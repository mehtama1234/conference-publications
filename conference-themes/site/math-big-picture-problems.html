FIRST PRINCIPLE

The Shared Problem Is Controlled Generalization

Across the conferences, the same demand keeps returning: make a system change behavior in the right direction while preserving the properties that matter. The system may be a language model, agent loop, sample generator, robot, benchmark, optimizer, cause-estimation method, or protein generator. The problem is not just prediction. It is controlled generalization when state is missing, evidence is finite, compute is limited, people react, and measurements are imperfect.

That is why the papers connect. They choose something to protect: enough memory for the next step, a score that really measures the target, an allowed movement boundary, coverage of important output types, a visible signal above noise, an action claim forced by evidence, or a checker that sees the real artifact. Then they design a method that makes that thing easier to preserve.

PROBLEMS

Twelve First-Principles Problem Families

01 reasoning

How do we know a model is reasoning rather than replaying a pattern?

Object. Middle work that changes with the task and carries useful information for later steps, like scratch work that changes when the puzzle changes.

Approaches. Trace diagnostics, hidden effort signals, longer-task curricula, internal steering, and executable checks.

a useful trace changes when the task changes and helps change the answer

Papers. RAGEN-2, Tell-Tale Norm, Steer Like The LLM, h1, Thinking in Flow, TRACE Effort, CyberGym.

Why it works. Reasoning fails when the work becomes a template. What must stay the same is the connection between the problem and the steps. What may change is length, wording, or stopping time. Name used later: task-conditioned trace.

Failure check. Change the task while holding style constant; the trace should change for task reasons, not only length or format reasons.

02 agents

How should an AI system spend action, memory, and tool calls?

Object. A running situation that includes observations, tool results, memory, costs, and checker feedback.

Approaches. State lifting, reusable skills, visible cost-benefit tool policies, multi-agent roles, executable environments.

choose an action when expected information value exceeds action cost

Papers. Skill-Pro, ParetoPO, OMAC, ThunderAgent, CyberGym, tau2-bench, ToolRL families.

Why it works. A tool call is like paying for a test at a repair shop: it is worth it only if the result changes what can be known or safely done. What must stay the same is the goal and allowed action menu. What may change is memory, tool choice, or the next action after new evidence arrives. Names used later: revised belief and allowed action set.

Failure check. Measure correctness and cost jointly; extra actions should improve the tradeoff curve, not only create longer traces.

03 evaluation

How do we measure capabilities without training systems to exploit the measurement?

Object. A measuring channel with real target signal, noise, bias, and pressure from systems learning to score well.

Approaches. Domain-specific judges, executable tests, benchmark reliability audits, artifact-native scoring, doubt ranges.

observed score mixes true capability, bias, noise, and adaptation pressure

Papers. ATLAS, JudgeBench, WebDevJudge, PaperBench, UFEval, Micro-Benchmarking Reliability, OmniVerifier.

Why it works. A benchmark is useful when it measures the target with known error rather than rewarding surface habits.

Failure check. Optimize against the metric and audit whether real target behavior improved or only metric-facing behavior improved.

04 safety

How do we make safety claims about rare, adaptive, or boundary failures?

Object. The bad cases near the edge: the harmful event, the safety line, the pressure applied near that line, and the tradeoffs made to stay safe.

Approaches. Rare-event sampling, safety-limited policy movement, adversarial stress tests, deletion indistinguishability, safety tradeoff reporting.

safety claim needs rare-bad-case chance and boundary distance, not just mean score

Papers. Rare Event Analysis, Tail Risks, CSPO, Jailbreak Foundry, SandboxEscapeBench, RLVepsR, SafeDPO, VALUEFLOW.

Why it works. A guardrail is not tested by driving down the center of the lane. What must stay the same is the safety rule. What may change is the attack, prompt, policy update, or test distribution. Names used later: tail event, allowed set, tradeoff frontier.

Failure check. Report rare-event doubt, adaptive attacks, false refusals, and unsafe acceptances at the boundary.

05 data

When does data actually change what the model can do?

Object. The training path: when an example arrives, what habit it pushes, and whether that push still helps the current model.

Approaches. Midtraining bridges, data valuation, useful-push alignment, synthetic coverage repair, curriculum timing.

data value depends on whether its training push helps the target at that time

Papers. Midtraining Bridges, DiReCT, OpenThoughts, BLL-Loss, LALP, Sequential Data Values, NASH.

Why it works. A lesson helps only while the student can still use it. What must stay the same is the target behavior. What may change is the example, timing, mixture, or bridge between data sources. Names used later: gradient direction and data distribution bridge.

Failure check. Compare phase ablations and measure whether the same data helps, does nothing, or damages general capability at different times.

06 systems

How can we compress models without changing the function people rely on?

Object. A cheaper version of the model that should still keep the behavior, memory, and step-by-step number route the task needs.

Approaches. Quantization, pruning, cache selection, low-rank movement, hardware-aware kernels, repetition repair.

compression works if task behavior stays stable under the cheaper version

Papers. ThinKV, STAR-KV, EntroKV, LiftQuant, TetraJet, Error Propagation in Quantized Diffusion, FOCUS, RePAIR.

Why it works. Replacing a machine part is fine only if the machine still completes the same cycle. What must stay the same is the behavior users rely on. What may change is precision, memory, kernel layout, or removed weights. Names used later: approximation map, finite arithmetic, sufficient memory.

Failure check. Test rare-memory retention, repetition loops, hardware arithmetic sensitivity, and accumulated step error.

07 generation

How do generative models move possible outputs without losing important kinds?

Object. The making route from rough noise or base samples to target structured outputs.

Approaches. Diffusion paths, bridges, reward-tilted sampling, same-object coordinate groups, safety-guided flows.

move from rough samples to target samples while preserving coverage and controlling local error

Papers. Quotient-Space Diffusion, Safety-Guided Flow, DMPO, FALCON, Cauchy Bridges, SRMC, Stable Video Infinity.

Why it works. A final photo, molecule, or answer can look plausible even if the route erased rare valid kinds or built up error. What must stay the same is coverage of the target object family. What may change is each step that shapes the sample. Names used later: transport path and distribution.

Failure check. Measure mode recall, guidance bias, rare-region coverage, and accumulated sampler error.

08 physical science

What representation makes physical or biological structure learnable?

Object. Coordinates and rules that preserve the real scientific object: molecule route, fold, physical field, same-object transformation, or biological hierarchy.

Approaches. Same-object representations, feasibility-limited generation, learned physical operators, repeated leftover-error correction.

choose coordinates where valid local moves preserve the real object

Papers. IRNO, ReaSyn, MORetro*, protein autoregressive modeling, DeCoDe, Chamaileon, Complexa, RealPDEBench.

Why it works. Scientific objects have structure before the model sees data. Encoding that structure blocks impossible moves and makes useful neighborhoods smoother.

Failure check. Test whether the representation preserves real constraints rather than only improving familiar-looking visual or sequence examples.

09 theory

Which hidden quantity explains an empirical trick?

Object. A smaller thing that controls the behavior: visible signal direction, movement ruler, algorithm-like circuit, evidence amount, finite-test proof token, or worst-case risk.

Approaches. Visible-direction analysis, optimizer movement rules, constructive circuits, lower bounds, finite-evidence certification.

performance depends on recoverable directions, movement ruler, and evidence size

Papers. Alignment-Sensitive Minimax Rates, Transformer Circuits, Adam Degeneracy, Finite Test Certification, Single-Head Attention, Language Generation in the Limit.

Why it works. Theory helps when it names the smaller quantity controlling the phenomenon, then shows why changing that quantity changes behavior.

Failure check. Verify the named quantity predicts behavior outside the examples used to discover it.

10 causality

What can the evidence force, and what is still assumption?

Object. The cause stories still possible after the records are seen, plus any fair comparisons or time rules needed to decide among them.

Approaches. Relation checks, organized nudges, local background-fact selection, what-if policies, hypothesis tests.

a cause claim is proven if all data-compatible worlds agree on the target

Papers. Distributional Equivalence, Local Covariate Selection, Structure Learning CI, DiCoLa, TRECA, Fair Causal Bandits, Neural Effect Search.

Why it works. If two plumbing layouts give the same readings, the readings alone cannot choose one layout. What must stay the same is the evidence and assumptions. What may change is the still-possible cause story. Names used later: identified effect, same-evidence story group, intervention target, adjustment set.

Failure check. Return still-possible story sets or assumption-labeled claims when the data does not choose one explanation.

11 multimodal

How do we know which evidence channel caused the answer?

Object. The route from image, audio, text, body signal, or memory to the answer.

Approaches. Evidence swaps, route removals, missing-channel calibration, token bottlenecks, brain or physiological hidden interfaces.

a channel earns credit if changing that channel changes the output under controls

Papers. VISUALSWAP, MINT, MoCA, Causal Route Gating, LIMSSR, Mind-Omni, PRISM, VideoKR.

Why it works. Looking at a picture is not the same as using it. What must stay the same is the claim being answered. What may change is one evidence source while shortcuts are held fixed. Names used later: channel credit, bottleneck, hidden interface.

Failure check. Swap the visual, audio, text, or physiological evidence while holding shortcuts fixed.

12 deployment

When does a mathematical guarantee survive contact with the actual system?

Object. The paper-world assumptions, evidence assumptions, and machine-level assumptions that must all remain true.

Approaches. Theorem-to-deployment audits, hardware traces, finite-test doubt ranges, checker-scope statements, artifact proof tokens.

a guarantee transfers only if paper-world, evidence, and machine assumptions all hold

Papers. Floating-Point Neural Networks, QAT Scaling, TileLang, finite-test certification, VERINA, PaperBench, Theorem-to-deployment families.

Why it works. A theorem can be true in the formal model and false for the deployed artifact if arithmetic, data, or checker assumptions changed.

Failure check. State every assumption layer separately and test the one most likely to break in the real system.
