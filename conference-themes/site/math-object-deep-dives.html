FIRST PRINCIPLE

The Object Decides What Counts As Progress

Most failures in the atlas come from optimizing the wrong object. If reasoning is treated as text, a model can learn longer templates. If safety is treated as average score, tail failures disappear. If molecules are treated as strings, route feasibility disappears. If a benchmark is treated as a leaderboard number, uncertainty and judge bias disappear.

Start with the thing that must not get lost. It may be the work record needed for the next step, the boundary an output must stay inside, the rare bad case ordinary tests miss, the route a sample took while it was being made, or the artifact users actually rely on. The math name is useful only after that everyday object is clear.

OBJECT 01

Sufficient State

The Problem

A system often cannot keep the whole past. It must compress a prompt, trace, video, cache, memory, robot history, or PDE trajectory into a state that still supports the next decision. The hard question is what information can be discarded without changing the answer, action, or future update.

state s_t is sufficient for target y when P(y | history_t) = P(y | s_t) for the task family

Why It Works

Think of packing for a trip: you do not bring the whole house, but you must bring the passport, medicine, and keys. A saved state works the same way. What must stay is the part of the past that can still change the next answer or action. What may go is wording, repetition, or detail that can no longer matter. Name used later: sufficient state.

Paper Examples

RAGEN-2, h1, Skill-Pro, ThinKV, STAR-KV, EntroKV, DLMR, VideoKR, Mamba Markov ICL, IRNO, HDFlow, Linear Recurrent Memory.

Evidence Check

Ablate or perturb history, compare decisions from full history and compressed state, test long-horizon drift, and measure whether downstream errors arise from missing state.

Failure Boundary

Compression fails when the summary preserves style or recency but loses rare facts, causal dependencies, constraints, or hidden state needed later.

OBJECT 02

Measurement Channel

The Problem

A score is an observation, not the capability itself. The channel from hidden target to measured result can add item noise, judge bias, missing modality, shortcut paths, domain mismatch, or finite-sample ranking error.

observed score = target signal + sampling noise + judge bias + shortcut artifact + omitted channel

Why It Works

A thermometer is helpful only when it touches the right place and its error is known. A benchmark score is the same kind of instrument. What must stay fixed is the ability or property being claimed. What may change is the question, judge, artifact view, or sample size. These methods work by making the measuring path visible enough to say what the evidence really supports. Name used later: measurement channel.

Paper Examples

ATLAS, FRABench, UFEval, Micro-Benchmarking Reliability, JudgeBench, WebDevJudge, CounselBench, MADQA, Seizure-Semiology-Suite, Omni-Reward.

Evidence Check

Report calibration, confidence intervals, item information, inter-rater agreement, component scores, artifact-native judging, and rank reversals under plausible scoring changes.

Failure Boundary

A precise benchmark still fails if it observes the wrong artifact, collapses multiple abilities into one number, or gives the model a shortcut around the intended evidence.

OBJECT 03

Feasible Set

The Problem

Many tasks are not "choose the best output"; they are "choose the best allowed output." The allowed set may be chemical, legal, safety-related, geometric, robotic, privacy-preserving, or fairness-constrained.

optimize objective(x) subject to x in C, where C encodes validity, law, safety, physics, or fairness

Why It Works

If a recipe must be vegan, choosing the tastiest dish first and checking ingredients later wastes effort and may still fail. The allowed menu has to be part of the search. What must stay fixed is the rule for valid behavior. What may change is which valid option is chosen. Name used later: feasible set.

Paper Examples

Copyright-Bench, CSPO, Pi-net, Fair Optimal Transport, ReaSyn, MORetro*, DCFold, HDFlow, PACT, Robust Contextual Optimization, TRECA.

Evidence Check

Measure violation rate, distance to boundary, objective-feasibility frontier, constraint sensitivity, route validity, and whether optimization pressure increases invalid candidates.

Failure Boundary

A feasible set can be too narrow, too loose, or specified in the wrong representation. Then the method either blocks valid behavior or permits the real violation.

OBJECT 04

Transport Path

The Problem

Generation and sampling are path problems. The final artifact inherits the route taken through noise, flows, bridges, reward tilts, guidance, rejection, or proposal distributions.

p_0 -> p_1 -> ... -> p_T by denoiser, vector field, bridge, proposal, or reward-tilted update

Why It Works

A loaf depends on the steps that made it: mixing, resting, heat, and timing. Generated samples also inherit their route. What must stay fixed is the kind of output or scientific quantity the samples are meant to represent. What may change is each making step. The method works when the route keeps important kinds, avoids forbidden regions, and leaves an honest receipt for remaining error. Name used later: transport path.

Paper Examples

DMPO, FALCON, SRMC, Cauchy-Driven Diffusion Bridges, Safety-Guided Flow, GWF, MAPF via MMOT/Schrodinger Bridges, FIDIA, Quantized Diffusion.

Evidence Check

Measure mode coverage, effective sample size, likelihood calibration, path stability, guidance-induced bias, per-step error propagation, and rare-event confidence intervals.

Failure Boundary

A sampler can pass final visual checks while missing modes, accumulating error, overusing guidance, or changing the target distribution in a way the metric does not see.

OBJECT 05

Spectrum

The Problem

High-dimensional systems contain many directions, but not all directions matter equally. Some directions carry task signal, some carry noise, some are stiff, and some are recoverable only above a threshold.

decompose signal or update into directions v_j with strength lambda_j; useful movement depends on visible directions

Why It Works

In a noisy room, a melody helps only after it rises above the static. Large model states have many possible directions like that: some carry the task, some are noise, and some are too weak to trust. What must stay fixed is the behavior the direction controls. What may change is the coordinate system or compression. Name used later: spectrum, a sorted list of direction strengths.

Paper Examples

Alignment-Sensitive Minimax Rates, Single-Head Attention, BBP Transitions, Low-Rank LM Logits, SVD Interpretability, DiReCT, LoRA Theory, Jacobian Spectra.

Evidence Check

Show which directions carry the target, whether they stay stable under resampling, when they become visible above noise, and whether changing or removing them changes the task behavior.

Failure Boundary

A spectrum can be unstable, task-misaligned, or measured in the wrong basis. Then top directions look meaningful but do not preserve the behavior of interest.

OBJECT 06

Tail Event

The Problem

Deployment risk is often concentrated in low-probability regions. Ordinary averages can make a model look safe while repeated use eventually finds the harmful path.

risk target = P(Y in E_bad) or E[loss(Y) | Y in tail], not average benchmark score

Why It Works

A bridge inspection cannot ignore the rare heavy truck just because most cars are light. Safety work has the same problem. What must stay fixed is the bad event being protected against. What may change is how the test finds enough examples near that event. Name used later: tail event.

Paper Examples

Rare Event Analysis, Tail Risks, Control Consistency Losses, Jailbreak Foundry, AdvGame, SandboxEscapeBench, FlowGuard, Catch-22, SecFid.

Evidence Check

Report event definitions, confidence intervals, adaptive pressure, boundary sensitivity, proposal variance, false-positive cost, and near-threshold examples.

Failure Boundary

Tail estimates fail when the harmful set is misspecified, the proposal misses a mode, or the attacker can shift pressure outside the tested region.

OBJECT 07

Game Or Mechanism

The Problem

Many AI systems are embedded in strategic settings. Users, attackers, data sellers, judges, agents, and institutions respond to the model and to one another.

agents choose policies pi_i with payoffs u_i(pi_1,...,pi_n), constraints, information, and response dynamics

Why It Works

Rules change behavior when people know the rules. A seller may exaggerate, an attacker may adapt, and one agent's move may block another's. What must stay fixed is the shared rule or payoff being studied. What may change is each actor's response. Name used later: game or mechanism.

Paper Examples

AdvGame, Accuracy Auctions, Data Market Pricing, Constrained Nash Equilibria, Fair Causal Bandits, OMAC, MASPOB, Value of Variance, Weak-to-Strong Monitoring.

Evidence Check

Test strategic misreporting, adaptive attacks, equilibrium distance, convergence time, group constraint violations, incentive compatibility, and sensitivity to payoff assumptions.

Failure Boundary

A mechanism can be mathematically clean but deploy poorly if actors have different information, costs, collusion channels, or response times than the model assumes.

OBJECT 08

Identified Set

The Problem

Data often cannot identify one true cause, graph, effect, or mechanism. The correct output is the set of claims consistent with evidence and assumptions, not the most plausible story.

claim c is identified when every world w consistent with data and assumptions gives the same value c(w)

Why It Works

Several plumbing layouts can give the same faucet reading. The reading proves only what all still-possible layouts share. What must stay fixed is the evidence and stated assumptions. What may change is the story still compatible with them. Name used later: identified set.

Paper Examples

Distributional Equivalence, Local Covariate Selection, Structure Learning CI, DiCoLa, Unpaired Causal IV, BRCD, Latent Hawkes, OU Identifiability, CausalGame.

Evidence Check

Report which cause stories remain possible, which comparisons are fair, which hidden factors could still explain the records, and when the method correctly refuses to choose one story.

Failure Boundary

The set is only honest if the assumptions are stated. Hidden confounding, selection, measurement error, and graph misspecification can make the identified set falsely narrow.

OBJECT 09

Latent Interface

The Problem

Raw observations can be too messy to control directly. A useful hidden interface is like a mixing board: it gives the system a smaller set of sliders for the parts that matter, while the original sound, image, body signal, or text can still be reconstructed or judged.

learn z = f(x) so downstream target is easier: linear, sparse, causal, geometric, or controllable in z

Why It Works

The smaller code works only when its sliders match real causes of the output. What must stay fixed is the evidence or control needed later. What may change is surface detail that should not affect the task. Name used later: latent interface.

Paper Examples

Steer Like The LLM, The Tell-Tale Norm, MINT, Causal Route Gating, Mind-Omni, PRISM, CompSLOT, MetaEmbed, LatentLM, UALM, Linear Causal Representation Learning.

Evidence Check

Use interventions, swaps, decoders, transfer tests, route ablations, sparse-feature tests, and off-target movement audits.

Failure Boundary

A hidden interface fails when one slider moves too many things at once: the intended behavior plus style, identity, modality bias, or safety properties.

OBJECT 10

Certificate

The Problem

Some claims should not be accepted from fluent output alone. Security, proof, unlearning, privacy, web behavior, medical judgment, and scientific discovery need evidence artifacts that can be checked.

accept claim only when verifier V(artifact, assumptions, observation channel) passes with stated error bounds

Why It Works

A receipt, lock test, or lab result matters because it can reject a story. A certificate does the same for model claims. What must stay fixed is the claim being checked and the assumptions under which the check is valid. What may change is the generated answer or artifact. Name used later: certificate.

Paper Examples

CyberGym, VERINA, WZ-LLM, PaperBench, Bitween, WebDevJudge, OmniVerifier, Gaussian Certified Unlearning, Watermarking, Finite Test Certification.

Evidence Check

Report verifier scope, checker failures, reproduction success, adversary view, finite-sample confidence, false positives, and whether the artifact is the object users actually rely on.

Failure Boundary

A certificate can be narrow. It proves only what its verifier observes under its assumptions; anything outside that channel remains unproved.

BIG PICTURE

The Atlas In One Sentence

The papers are not isolated tricks. They are attempts to keep the right thing visible while an AI system changes memory, data, representation, sample route, precision, policy, or measurement setup.

The approaches work when the chosen object matches the real failure. Keep a saved state when history must be shortened. Inspect the measuring path when scores are noisy. Put the allowed menu into the search when validity is non-negotiable. Check the making route when the final sample is not enough. Sort directions when signal is buried in noise. Look for rare bad cases when averages lie. Model response when actors adapt. Return the remaining story set when evidence cannot choose one cause. Use a hidden interface only when its controls preserve what matters. Demand a certificate when fluent text is too cheap.
