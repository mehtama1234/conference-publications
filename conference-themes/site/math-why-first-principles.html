READ FIRST

The Deep Why Is Always About Preservation Under Change

A learning system is always changing something: a representation, a probability distribution, a memory, a parameter vector, a policy, a generated trajectory, a benchmark score, or a scientific claim. The central question is not "what method did the paper use?" The central question is: what must stay true while that change happens?

Mathematics enters because surface behavior is too cheap. A long answer can hide a bad reasoning process. A high score can hide an invalid benchmark. A realistic video can violate physics. A small update can erase a rare skill. A molecule can look plausible and still be impossible to make. The math works when it names the hidden quantity that must be preserved and gives a way to test whether it survived.

MECHANISMS

Twelve First-Principles Explanations

01 information

Why Compression Can Work

Compression works only when the removed details cannot change the future decision. If a cache, memory, video summary, or hidden state keeps every fact that can change the answer, it can replace the full history. If it drops one rare but decisive fact, the summary is not a smaller version of the same problem; it is a different problem.

The real reason is that the past often matters only through a few present facts. A room's full history is not needed to open a door; the current handle position and lock state may be enough. But if the task is forensic reconstruction, those details become relevant again. The formal term conditional information means information that still matters after the known facts are already given.

summary is valid only when it supports the same answers as the full history for the target task

Connects to. ThinKV, STAR-KV, EntroKV, VideoKR, Skill-Pro, Mamba Markov ICL, Linear Recurrent Memory.

Failure. Calling something "efficient" is empty unless the dropped information is proven irrelevant for the task family.

02 constraints

Why Constraints Help

A constraint helps because it removes impossible worlds before the search can spend effort on them. If the output must be legal, safe, physically possible, synthesizable, or fair, then the model is not allowed to search all fluent outputs. It must search the smaller space of allowed outputs.

The deep reason is that repeated improvement amplifies whatever is permitted. If invalid regions remain available, a strong search process will eventually find high-scoring invalid points. Checking after the fact is weaker because it lets the model learn inside the wrong space and then throws away failures afterward.

best answer = highest value point inside allowed set, not highest value point anywhere

Connects to. CSPO, Copyright-Bench, ReaSyn, MORetro*, Fair OT, PACT, HDFlow, Robust Contextual Optimization.

Failure. A constraint can hurt when it describes the wrong allowed set: too narrow blocks good behavior; too loose preserves the real failure.

03 invariance

Why Symmetry Removal Works

Symmetry removal works when many surface inputs describe the same underlying object. A molecule rotated in space is still the same molecule. A graph with renamed nodes can have the same structure. A camera view changes coordinates but not the physical scene.

The reason is that data is not wasted relearning the same thing in every costume. If the model has to relearn the same object under every irrelevant encoding, examples are wasted. If the representation treats those encodings as the same case, the model spends its capacity on differences that can change the target. The formal term invariance means the answer stays the same when an irrelevant surface detail changes.

learn the object after ignoring transformations that do not change the target property

Connects to. Quotient-Space Diffusion, GraphGlue, Camera-Aware MLLMs, TideGS, RadioGS, protein and molecular generation.

Failure. Invariance fails when the removed coordinate was actually meaningful. Viewpoint can be irrelevant for molecule identity but crucial for a robot grasp.

04 update shape

Why Small Updates Can Still Break A Model

A small parameter change is not automatically a small behavior change. Some directions are soft: moving there barely changes what the model does. Other directions are stiff: tiny movement can damage a capability, safety boundary, or confidence estimate.

The deep reason is that an update is not just a distance; it is a direction through shared machinery. "Catastrophic forgetting" means the update moved through parts that old behavior also needed. The old task was not stored in a protected box; it was distributed through shared parameters, so new training pushes can overwrite it. The formal term curvature means how sharply behavior changes when the model moves in a direction.

safe update depends on direction, sharpness of behavior change, and which functions share the moved parameters

Connects to. Adam Degeneracy, DiReCT, LoRA theory, RAIN-Merging, Continual VLA, GR-LoRA, Local Redundancy, trust-region RL.

Failure. Reporting a low-rank or small update is not enough. The question is whether that movement crosses directions the old behavior needed.

05 visible directions

Why Spectra Matter

Spectra matter because large systems are not equally knowable in every direction. Data can reveal some directions clearly and leave others buried in noise. A model can have billions of parameters, but the target signal may live in a small number of directions that are either visible or invisible.

The deep reason is separation. If the useful signal creates a direction that rises above noise, limited data can recover it. If the signal is spread thinly or mixed with noisy directions, the learner needs much more evidence. The formal term spectral analysis means studying these ordered directions to ask which ones the evidence can actually see.

a direction is useful when target signal along it is stable enough to recover above noise

Connects to. Alignment-Sensitive Minimax Rates, BBP transitions, Jacobian spectra, low-rank logits, SVD interpretability, Single-Head Attention.

Failure. A large direction can describe common variation, not task meaning. The direction must match the behavior being claimed.

06 measurement

Why Benchmarks Can Lie

A benchmark score is a reading from an instrument. The instrument has items, rubrics, judges, prompts, sampling noise, and shortcut paths. A high score means the model interacted well with that instrument; it does not automatically mean the hidden capability is present.

The deep reason is observation. We never observe "capability" directly. We observe answers, actions, traces, or artifacts, then infer capability. A good benchmark narrows the gap between observation and target. A bad benchmark measures a correlate that the model can exploit.

score = target signal plus noise, bias, shortcut artifacts, and omitted evidence

Connects to. ATLAS, UFEval, Micro-Benchmarking Reliability, JudgeBench, WebDevJudge, CounselBench, MADQA, PhyWorldBench.

Failure. More benchmark items do not fix a wrong measurement channel. They can measure the wrong thing more precisely.

07 substitute scores

Why Reward Models Break After Repeated Improvement

A substitute score can match the true target before training and fail after training. Once the substitute score becomes the goal, the policy searches for places where the score and the real target disagree. Those places may be rare before training and common after repeated improvement. The formal term proxy means this substitute measurement.

The deep reason is selection pressure. Repeated improvement does not sample typical examples; it selects extremes. Any systematic substitute-score error becomes attractive if it increases reward. This is why a judge, verifier, or reward model must be tested after the policy has adapted to it.

substitute score is reliable only where improving it preserves the true target ordering

Connects to. Omni-Reward, JudgeBench, RLVepsR, TRACE Effort, FlowGuard, DeceptionDecoded, Weak-Strong Verification.

Failure. Pre-training correlation is weak evidence. The right test is whether the substitute score stays valid in the region selected by training.

08 rare bad cases

Why Average Safety Is Not Safety

Safety failures often live in rare prompts, rare states, rare user pressure, rare interactions, or rare combinations of otherwise harmless features. Average score can improve while the dangerous region remains unseen.

The deep reason is total chance at scale. A rare event can be unlikely in one interaction and still happen often after millions of interactions. Tail methods work by moving evaluation effort toward the region where harm actually lives. The formal term tail means the far, rare part of the event set rather than the ordinary middle.

safety claim needs chance of the bad event and uncertainty around that chance

Connects to. Rare Event Analysis, Tail Risks, Jailbreak Foundry, SandboxEscapeBench, CSPO, SecFid, CVaR MDPs.

Failure. Rare-case estimates fail when the evaluator does not know what bad event to search for or misses a mode of failure.

09 causality

Why Causal Claims Need Assumptions

Prediction asks what usually happens together. Causality asks what would change if something were intervened on. Observational data alone often supports several possible causal worlds that make the same predictions but disagree under intervention.

The deep reason is indistinguishability. If two worlds produce the same observations, no amount of clever language can choose between them without adding assumptions or experiments. Causal methods work when they state which worlds remain possible and which intervention claims all remaining worlds agree on.

claim is identified only if every data-compatible world gives the same intervention answer

Connects to. Distributional Equivalence, Local Covariate Selection, Structure Learning CI, DiCoLa, Unpaired Causal IV, BRCD, CausalGame.

Failure. A plausible causal story is not an identified causal claim. The atlas should mark the difference every time.

10 generation

Why Generative Paths Matter

A generated object is the endpoint of a step-by-step drawing process. The path may denoise, unmask, flow, bridge, guide, reject, edit, or search. If the path loses rare valid cases, piles up error, or drifts outside the rules, the endpoint inherits that failure.

The deep reason is local-to-global accumulation. Many generative methods turn a hard whole-object problem into many small steps. That helps only if each step preserves what the final object needs: allowed cases, feasibility, identity, physical state, or later scientific quantity.

a sampler is valid when the whole path preserves allowed cases, constraints, and the downstream quantity

Connects to. Quantized Diffusion, Safety-Guided Flow, DMPO, FALCON, Stable Video Infinity, FIDIA, ReaSyn, quotient diffusion.

Failure. A final sample can look plausible while the path has changed what can be sampled or removed the rare cases the claim depends on.

11 finite evidence

Why A Theorem Or Test Has A Boundary

A theorem is true inside its assumptions. A test result is evidence about the population it sampled. Deployment changes assumptions: arithmetic changes, prompts change, users adapt, model versions move, and hardware approximations appear.

The deep reason is scope. Evidence always has a domain. A finite benchmark cannot certify an unlimited claim. A formal proof cannot certify the deployed system if the implementation differs from the formal object. The right move is not to distrust theory; it is to keep the chain of assumptions visible.

claim transfers only when math assumptions, data assumptions, and system assumptions all hold

Connects to. Finite Test Certification, Floating-Point Neural Networks, TileLang, QAT Scaling, VERINA, PaperBench, theorem-to-deployment pages.

Failure. The common failure is using a narrow certificate as if it proved the broad deployment claim.

12 representation

Why Better Representations Help

A representation helps when it makes the task's real variables easier to separate, move, combine, or test. It is not better because it is more abstract. It is better when the useful structure is easier to access in that coordinate system.

The deep reason is coordinate choice. The same object can be impossible to learn in one coordinate system and simple in another. A biological complex is not just a string. A video is not just frames. A value judgment is not one scalar. A multimodal answer is not one text trace. Good representations expose the variables that interventions and evidence act on.

representation is useful when target-relevant variables become separable, controllable, or measurable

Connects to. Mind-Omni, PRISM, CompSLOT, MetaEmbed, Chamaileon, Complexa, Visual Attribution, Linear Causal Representation Learning.

Failure. A representation that is elegant but entangles the task variables just moves confusion into a hidden space.

HOW TO REWRITE WEAK PROSE

Replace Labels With Mechanisms

When a card says "expressive power," rewrite it as: what computation, relation, or state change can this architecture represent that the weaker one cannot, and can training find it with finite data?

When a card says "catastrophic forgetting," rewrite it as: which old behavior used the same parameters or internal directions as the new update, and what evidence shows the update moved through those directions?

When a card says "robustness," rewrite it as: what change in input, deployment setting, attacker response, or missing variable remains possible, and what quantity is guaranteed not to change too much inside that set?

When a card says "alignment," rewrite it as: whose value, measured by what channel, combined by what rule, improved under what pressure, and audited at which failure boundary?

READER CHECK

A First-Principles Card Must Answer These

1. What is changing?

Parameters, state, samples, scores, memory, actions, representations, or distributions.

2. What must be preserved?

Task information, feasibility, support, safety boundary, causal meaning, identity, old behavior, or measurement validity.

3. Why does the method preserve it?

Name the mechanism in plain terms: adding required context, removing impossible options, treating same-object views as one object, changing example weight, controlling sharp update directions, changing one cause to see the result, checking the artifact, or reporting uncertainty.

4. What evidence would prove the mechanism is real?

Remove the claimed part, change the claimed cause, report uncertainty, inspect the checker trace, stress the boundary, audit which cases remain possible, or evaluate in a deployment-shaped setting.

5. Where does the explanation stop?

Every method has a boundary: unsupported assumptions, missing modes, wrong measurement, hidden incentives, hardware mismatch, or untested domains.
