Causality and scientific discovery as evidence boundaries

This page expands the causality and scientific-discovery lane at paper level. The common problem is not prediction. It is deciding what the evidence actually proves: which action would change an outcome, which background facts must stay matched, which causal stories are still possible, which repair point is most likely, which time rule is real, and which scientific claim can be tested and possibly rejected.

FIRST PRINCIPLE

Prediction Is Not Intervention

A predictive model can say which things usually move together. A causal or scientific model must say what would change if one thing were deliberately changed: a treatment, a program component, a service, a prompt route, or an action. That question requires a recipe for what stays matched, what changes, what is observed, and which hidden causes are allowed by the assumptions.

The strongest papers in this lane do not overclaim. They name the boundary of what the evidence proves. Sometimes the right output is a small set of background facts for one effect, not a full causal graph. Sometimes it is the whole set of graphs the data still cannot separate, not one diagram. Sometimes it is a ranked list of likely repair points, not a single blamed service. Sometimes a learned feature becomes scientific only after a test that could have rejected it.

FORMULA PASS

Paper-Specific Math Boxes

Local Covariate Selection

Object. One treatment question plus the background facts that must be held fixed so the comparison is fair.

Why it works. We do not need the whole cause diagram if the question is narrow. We need to know which facts make the treated and untreated groups comparable, and which facts would accidentally make the comparison worse. The formal name for those background facts is covariates.

compare treatment values after holding fixed the background facts that make the comparison fair

Evidence check. Report whether the chosen background facts stay stable, whether hidden common causes could still explain the result, whether any chosen fact opens a wrong comparison path, and whether other valid fact sets give the same answer.

TRECA And Fair Causal Bandits

Object. A decision rule whose action is allowed only when the treatment benefit or fairness claim is stable enough.

Why it works. In high-stakes settings, not knowing is part of the action. Abstention and fairness-aware exploration prevent the learner from turning unproven "what would have happened otherwise" claims into irreversible decisions.

act when the conservative benefit is larger than risk and fairness violation stays below the allowed limit

Evidence check. Measure abstention regions, sensitivity to helper models, regret beside fairness violations, and stability under plausible causal stories.

Unpaired Causal IV

Object. Differences between environments that act like organized tests, even when observations are sparse or unpaired.

Why it works. Environments act like structured nudges. The method extracts causal signal from how data changes across settings, not from observing every unit under every condition.

use environment changes to separate causal signal from background variation when paired samples are missing

Evidence check. Test environment differences, weak-test behavior, sensitivity to unpaired sampling, and whether inferred effects survive held-out environments.

Structure Learning CI And DiCoLa

Object. Evidence about which variables stop moving together after the right background facts are held fixed.

Why it works. Graph learning is only as strong as the tests that decide whether links are absent or present. Divide-and-conquer helps scale the search, but the claim still rests on whether those link tests have the right false-alarm and missed-link rates.

edge decisions come from tests of whether two variables remain related after holding a chosen set fixed

Evidence check. Report false-alarm rates, missed-link rates, sample-size sensitivity, hidden-variable stress tests, false edge and missing edge rates, and whether decomposition preserves guarantees.

Distributional Equivalence

Object. The set of cause-and-effect diagrams that could all have produced the same records we actually saw.

Why it works. Imagine several plumbing layouts that produce the same water pressure readings at the faucet. The readings prove only what every still-possible layout has in common. This method keeps all diagrams that the data has not ruled out, including cases with unseen causes, loops, or limited link strength. The formal name is distributional equivalence.

return every diagram still compatible with the data; trust only claims shared by the whole set

Evidence check. Show which links or action effects are shared, which remain undecided, and exactly which added promises would shrink or widen the still-possible set.

BRCD And Production Agent Studies

Object. A ranked list of repair points after seeing logs, a partial service map, and the failure.

Why it works. The loudest abnormal metric is not always the cause. The useful repair point is the one where fixing it would most reduce the failure. Keeping several possible service maps prevents the diagnosis from claiming more than the logs prove.

rank a cause by how much the failure would change if that cause were fixed

Evidence check. Compare abnormality rank to actual repair success, test several service maps still compatible with the logs, check which needed facts are missing, and measure whether suggested fixes reduce repeat failures.

CausalGame

Object. A test setting where an agent must choose what to try next so two possible explanations no longer look identical.

Why it works. Watching a system can leave two stories tied. Pressing the right button can break the tie because the stories predict different results after that action. What must stay the same is the set of explanations still compatible with evidence. What may change is the deliberate test the agent buys. Name used later: mechanism.

choose the action that best separates the remaining possible explanations

Evidence check. Measure whether chosen actions remove doubt, whether the agent avoids traps where two things merely move together, and whether it separates controllable effects from ordinary correlation.

Latent Hawkes, OU Identifiability, And Power-Law Discovery

Object. Time rules learned from repeated events, long-run summaries, or patterns that keep reappearing despite noise.

Why it works. If one alarm usually rings before another, that alone does not prove the first alarm caused the second. There may be an unseen clock driving both. These papers add a stronger promise: events trigger later events in a stable way, or the moving system has a stable drift rule, or a repeated time pattern survives noise. Terms such as latent, Hawkes, OU identifiability, and power-law name different versions of that promise.

a time claim needs a stable rule for how the system changes plus observations that can reveal that rule

Evidence check. Test whether the answer changes when the time window changes, when hidden sub-processes are simulated, when summary equations are checked, when the process drifts over time, and when deliberate actions confirm the inferred direction.

Neural Effect Search

Object. A pattern found inside a model, treated only as a candidate claim until a fair test checks whether it changes an outcome.

Why it works. A model may contain thousands of tempting patterns. Some will look meaningful by accident. The method becomes scientific only when it turns one pattern into a fair test: compare changed cases against unchanged cases, then correct for the fact that many patterns were searched. What must stay the same is the outcome being tested. What may change is the candidate pattern. Name used later: randomized treatment contrast with multiplicity control.

feature f becomes evidence after a fair comparison and a many-searches correction

Evidence check. Report how the fair comparison was made, the corrected doubt range, whether the pattern label is stable, and whether the finding repeats on held-out data or tasks.

HypoSpace, Bitween, And Consequence-Based Utility

Object. A searchable set of possible explanations plus scores for whether the model covers the set, avoids repeats, rediscovers known ideas, and produces consequences that can be checked.

Why it works. Scientific generation should be judged like exploring a map of possible explanations, not like writing one polished paragraph. What must stay the same is that the generated claim has checkable consequences. What may change is which part of the explanation map the model visits. Name used later: hypothesis space.

discovery value = coverage + uniqueness + expected evidence gain or checked consequence

Evidence check. Measure duplicate rate, recovery of known hypotheses, whether consequences are valid, whether checks pass, and whether high-scoring hypotheses are actually rejectable.

RefineStat, MedAgentGym, PaperBench, WZ-LLM, And VERINA

Object. A generated scientific artifact whose validity is checked by running it, comparing it with data feedback, checking proof rules, or completing a workflow.

Why it works. The generator proposes; the environment or checker accepts. This separation matters because scientific language can be persuasive while the code, statistics, proof, or experiment is invalid.

artifact is accepted only if the relevant checker passes it

Evidence check. Report executable success, meaning-preserving repair rate, proof-rule acceptance, task completion, and where the checker is narrower than the scientific claim.

DISCO, Fair Posthoc Control, Missing-Covariate Robustness, And Accuracy Auctions

Object. A decision rule that must still be acceptable when shortcuts, missing facts, fairness requirements, and unequal costs are made visible.

Why it works. A prediction changes lives once it decides who gets a treatment, review, loan, or warning. These methods stop average accuracy from hiding the harm. They say which comparisons are legitimate, which records are incomplete, which choices are allowed, and whose cost of being wrong matters. The objective is the target being optimized, a constraint is a limit the decision cannot cross, a frontier is the visible menu of tradeoffs, and a mechanism is the rule that shapes how people act or report private values.

choose a decision rule that improves outcomes while respecting what-if, missing-data, and fairness limits

Evidence check. Show how the tradeoff moves, which groups gain or lose, how the result changes under different missing-fact stories, whether people have reason to report values truthfully, and where average accuracy hides harm.

MINT, Causal Route Gating, Divergent Interventions, And Activation Oracles

Object. A small change inside the model that stays close to internal states the model would naturally visit.

Why it works. Opening a machine and pushing a random part can break it, but that does not prove the part normally controls the job. Internal model tests are credible only when the changed state is still a normal-looking state and the output changes in the predicted way. Formal names include hidden-state intervention, activation patch, and route gating.

internal effect is credible when changing a natural internal state changes the output in the expected way

Evidence check. Measure whether the patch is local, whether it stays near natural internal behavior, whether it changes only the intended route, whether behavior changes under pressure, and whether artificial shocks would lead to false conclusions.

OBJECT 01

Local Effects

Local Covariate Selection

Problem. To compare two treatments fairly, we do not need to understand the whole world. We need the background facts that make this one comparison honest.

Object. One treatment-outcome question plus the facts that must stay the same between the treated and untreated groups. The formal name for those background facts is covariates.

Why it works. The method tries to block unfair comparison paths, such as comparing sicker people to healthier people, while avoiding facts that would create a new unfair comparison. It keeps the target small: prove this effect, not every arrow in the system.

Connection. It is the cause-and-effect version of an allowed comparison: only matched sets that make the effect credible are allowed.

TRECA

Problem. In medicine-like settings, calling someone a likely responder can be harmful if the evidence is thin or if rare bad cases are ignored.

Object. A treatment decision with a third option: do not decide yet.

Why it works. The method treats doubt as part of the output. If the benefit stays strong across the plausible stories, act. If the answer changes when assumptions move, abstain. That makes uncertainty visible instead of hiding it inside a confident label.

Connection. This links high-stakes evaluation to evidence boundaries: the system must say when the evidence is not enough.

Unpaired Causal IV

Problem. Sometimes we cannot watch the same person, cell, or system under both choices. We only see sparse samples from different settings.

Object. Environment changes that act like organized nudges.

Why it works. If the setting changes the cause of interest without directly changing the outcome through some other route, it can reveal the effect even without paired samples. What must stay the same is the comparison logic. What may change is the outside nudge. Name used later: instrumental variation.

Connection. It shows that careful data design can prove an action effect even when the raw sample table is incomplete.

Fair Causal Bandits

Problem. A learning system can treat people unfairly while it is still experimenting.

Object. A choice rule that weighs learning benefit against the risk that the same person would have been treated differently under another sensitive condition.

Why it works. Fairness is handled during exploration, not checked afterward. Each action must be useful enough to learn from and acceptable under the relevant what-if comparison.

Connection. Governance becomes causal when the question is not just what happened, but what would have happened if a sensitive condition were different.

OBJECT 02

Graph Evidence

Structure Learning CI

Problem. Graph recovery can look like algorithmic search while the real bottleneck is statistical testing.

Object. Tests for whether two variables stop being related after the right background variables are held fixed.

Why it works. For some graph families, the difficulty of learning structure reduces to the difficulty of getting these relation tests right. Better graph learning requires better evidence for which links are absent or present.

Connection. It is benchmark validity for causal graphs.

Distributional Equivalence

Problem. Different cause diagrams can produce the same observed records, especially when some causes are unseen or effects loop back.

Object. The remaining diagrams the data cannot tell apart.

Why it works. The method returns what the data proves instead of pretending one diagram is uniquely known. Extra promises about hidden causes, loops, or link strength can shrink the set, but those promises must be named.

Connection. This is the lane's discipline in one paper: do not say more than the evidence distinguishes.

DiCoLa

Problem. Searching a large cause diagram can explode in size, and unseen causes can fool simple tests.

Object. Smaller relation checks that can be combined without assuming every cause is visible.

Why it works. The method breaks the large search into pieces, but each piece still has to answer a plain question: after the right background facts are fixed, do these two variables still move together? Scaling helps only if those local answers remain trustworthy.

Connection. It moves graph learning from small theory cases toward larger discovery without dropping the evidence boundary.

PSAHS And RULE

Problem. Graph data can have noisy links, mismatched node facts, and missing labels.

Object. A check that the link pattern and the node facts are telling a compatible story.

Why it works. Repair is safer when two evidence views agree. When they disagree, the system should expose the mismatch instead of forcing one blended graph that hides the problem. What must stay the same is the relation between links and node facts. What may change is the repair. Name used later: correspondence constraint.

Connection. Graph learning inherits the same evidence boundary as cause discovery.

OBJECT 03

Root Cause

BRCD

Problem. During an outage, many services look broken at once. Operators need to know where a fix would most change the failure, not which metric looks loudest.

Object. A ranked list of repair candidates while the real service map is still partly unknown.

Why it works. BRCD starts from what was known before the failure, keeps several still-possible service maps, and ranks causes across them. It does not pretend the exact map is known when the evidence is incomplete.

Connection. It turns cause-finding into operational triage: where should an agent try repairing first?

CausalGame

Problem. An agent can collect a lot of data and still choose the wrong explanation if two things merely move together, if the sample is biased, or if the measuring tool is noisy.

Object. An interactive setting where actions create new evidence.

Why it works. The benchmark asks whether the agent chooses tests that separate possible explanations. It rewards useful question-asking, not a confident causal story.

Connection. This is root-cause logic generalized to scientific agents.

MAP And Production Agent Studies

Problem. Deployed agents often fail because the workflow state, tool state, monitoring, or human handoff went wrong, not because one answer was bad.

Object. Logs of what the agent saw, did, changed, and handed off.

Why it works. Production studies expose the facts teams actually need for repair: current task state, tool result, user intent, possible intervention point, and escalation trigger. Those facts are causal variables because changing them can change the failure.

Connection. This grounds cause-finding in deployment, where diagnosis must lead to action.

OBJECT 04

Temporal Mechanisms

Latent Hawkes Causal Discovery

Problem. Events can arrive in a suggestive order while the real trigger is partly hidden.

Object. Visible events plus unseen event sources that may trigger later events.

Why it works. A fire alarm after smoke does not prove the smoke caused the alarm if a hidden sensor drives both. The method asks whether one event truly changes the chance of a later event after allowing for unseen sources. What must stay the same is the triggering rule. What may change is which sources are visible. Name used later: latent means unseen.

Connection. It is scientific discovery when only part of the process is visible.

OU Identifiability

Problem. A noisy system may keep changing while we only see summaries, not the full path.

Object. The steady push that moves the system over time, known only up to the amount the measurements can reveal.

Why it works. The paper states which summaries are enough to distinguish the push rule. It also states where the evidence stops: without enough control over the path, some details remain unknowable. The formal name is identifiability.

Connection. It applies physical-system thinking to cause-and-effect drift.

Robust Causal Discovery With Power-Laws

Problem. Raw time records can be noisy, uneven, and changing, so ordinary before-and-after patterns can mislead.

Object. Repeated time shapes that remain visible after noise is smoothed away.

Why it works. A power-law feature is a compact description of a repeated time pattern, such as many small events and a few large ones. The method searches for causes after extracting patterns that are less fragile than raw observations.

Connection. It links visible time-pattern summaries to cause evidence.

Linear Recurrent Memory

Problem. If an agent sees only part of the world, it needs memory of earlier clues to choose the next action.

Object. A running note that keeps enough hidden situation information for the next decision.

Why it works. Memory helps only if it keeps the facts that still affect the best action. If the note drops the deciding fact, the agent is only summarizing text, not preserving cause-relevant state.

Connection. It connects cause reasoning to agents and state-space models.

OBJECT 05

Hypothesis Search

Neural Effect Search

Problem. Humans usually choose which effects to test, so scientific search can be narrow, expensive, and shaped by habit.

Object. Model-found patterns treated as candidate measurement units, not as facts yet.

Why it works. A sparse internal feature becomes a hypothesis only after a fair comparison shows it changes a measured outcome and after the many-searched-patterns penalty is handled. Interpretation becomes science only when the pattern can be rejected.

Connection. It links model interpretation to statistical discovery.

HypoSpace

Problem. Scientific reasoning is a search over possible explanations, not one impressive answer.

Object. A listable set of possible hypotheses, with checks for whether they are valid, different from each other, and recoverable.

Why it works. Measuring a model as a hypothesis sampler reveals whether it covers the space or repeats near-duplicates. The useful question is not "did it say something plausible?" but "did it explore distinct, checkable possibilities?"

Connection. It is benchmark design for discovery.

Bitween

Problem. An algorithmic trick can work on one example and still fail as a reusable idea.

Object. A proposed way to turn one problem instance into other related instances, then check that the relationship holds.

Why it works. Search tools can propose candidate reductions, but the proposal counts only when an independent check shows the pattern can be reused beyond the examples that inspired it.

Connection. It is scientific hypothesis search for algorithms.

Consequence-Based Utility

Problem. Some claims are too hard to check directly, but their consequences may be easier to inspect.

Object. Related tasks that should become easier if the claim is useful.

Why it works. A candidate is valued by whether it helps produce checkable downstream results. The method does not prove the claim by style; it asks whether the claim changes work that can be checked.

Connection. It links weak checking to hypothesis value.

OBJECT 06

Executable Workflows

RefineStat

Problem. A statistics program can execute and still make invalid modeling claims.

Object. Program pieces whose probability rules, settings, and warning checks must fit the statistical meaning of the program.

Why it works. The system repairs the local piece that fails a meaning check, such as a prior, likelihood, parameter range, or diagnostic. Scientific code generation becomes repeated repair under a checker that knows the statistical job.

Connection. It is executable evaluation for probabilistic modeling.

MedAgentGym

Problem. Biomedical agents need to do data work, not only answer biomedical trivia.

Object. A sandbox record of what the agent saw, coded, changed, received as feedback, and finally got right or wrong.

Why it works. The environment checks consequences of actions. The training signal comes from whether the biomedical workflow succeeds, not whether the explanation sounds clinical.

Connection. It is the scientific equivalent of executable agent benchmarks.

PaperBench And AI Scientist Workflows

Problem. Scientific work includes literature, experiments, code, figures, and claims that must fit together.

Object. A multi-step research artifact whose pieces can be inspected.

Why it works. The benchmark checks whether the system completed evidence-bearing work, not whether it wrote a persuasive summary. Each component gives a place where the claim can fail.

Connection. It turns science into an agent environment with evidence hooks.

WZ-LLM And VERINA

Problem. A proof can sound right while containing a step the rules do not allow.

Object. Proof artifacts checked by an independent rule system.

Why it works. A lock rejects the wrong key even if the key looks close. A proof checker does the same for unsupported steps. What must stay the same is the rule system. What may change is the generated proof attempt. Name used later: verifier.

Connection. Rule-checked proof is one end of scientific evidence.

OBJECT 07

What-If Policy

DISCO

Problem. A model can use a shortcut that predicts the label in old data but should not be the reason for the decision.

Object. A decision rule whose answer does not keep depending on the shortcut once the legitimate facts are fixed.

Why it works. The method removes a bad route from input to decision. What must stay the same is the answer supported by legitimate facts. What may change is the shortcut variable. Name used later: conditional independence from shortcut variables.

Connection. It is cause-route control for fairness and robustness.

Fair Posthoc Control

Problem. After training, a team may need to change how much accuracy it spends to reduce unfair group harm.

Object. A visible menu of reachable fairness and accuracy choices. The formal name is a frontier.

Why it works. The model is shaped so a later control step can move along that menu without retraining everything. What must stay true is that moving the control changes the intended fairness-accuracy tradeoff rather than only changing labels superficially.

Connection. It links fairness limits to rules for shared decisions.

Robust Contextual Optimization With Missing Covariates

Problem. A decision can become overconfident when missing background facts are filled in as if they were known.

Object. The set of plausible complete records that could match the partial record we saw.

Why it works. If a form is missing important fields, one guessed fill-in should not decide the action. What must stay visible is doubt about the missing facts. What may change is which plausible completion is true. Names used later: robust optimization and missing covariates.

Connection. It is what-if caution under incomplete evidence.

Accuracy Auctions

Problem. The same prediction error can be minor for one user and costly for another.

Object. A rule that asks users how much correctness matters to them and tries to make truthful reporting the best move.

Why it works. The target changes from average accuracy to consequence-weighted usefulness. What must stay the same is that truthful reports are rewarded more than strategic distortion. What may change is the user's private cost of error. Name used later: mechanism.

Connection. Cause-aware policy and social welfare meet when decisions affect people unevenly.

OBJECT 08

Internal Model Tests

MINT

Problem. A vision-language model may ignore the image and answer from text habits, even while appearing grounded.

Object. The internal place where image evidence and language state are combined.

Why it works. The test changes that internal place and watches whether the answer changes. If changing the image route changes the answer while other routes stay fixed, the image evidence was actually being used.

Connection. It estimates causes inside a neural network.

Causal Route Gating

Problem. Vision-language answers can travel through the text-habit route instead of the current-image route.

Object. The amount each route contributes to the answer.

Why it works. Like turning down the wrong microphone in a recording mix, the method dampens the route that relies too much on prior text habits. What must stay the same is the answer's dependence on current evidence. What may change is the strength of each internal route. Name used later: route gating.

Connection. It connects internal intervention to evidence-channel credit.

Divergent Causal Interventions

Problem. Pushing a model's internal state too far can create a state the model would never naturally use.

Object. An internal change that stays near normal model behavior.

Why it works. A patch is meaningful only if the patched state remains in the model's normal operating region. Otherwise the test measures the damage from an artificial shock, not the route the model really uses.

Connection. It is the evidence boundary for interpretability interventions.

Activation Oracles And Assistant Axis

Problem. A harmful tendency or persona shift may be visible inside the model before it appears in text.

Object. An internal direction whose activity predicts or changes a behavior.

Why it works. A dashboard light is useful only if it tracks the engine problem and not just the weather. Monitoring an internal direction helps only if changing that direction changes the behavior, not merely moves alongside it. What must stay the same is the behavior being monitored. What may change is the internal number pattern. Name used later: activation.

Connection. Safety monitoring becomes cause-aware representation analysis.

SYNTHESIS

The Cross-Paper Shape

Target Before Graph

Local Covariate Selection, TRECA, Fair Causal Bandits, and robust missing-variable decision rules all begin with the decision or effect. They work because they ask what structure is sufficient for that target rather than forcing a global causal model first.

Remaining Possibilities Before Certainty

Structure Learning CI, Distributional Equivalence, DiCoLa, BRCD, OU Identifiability, and Latent Hawkes Causal Discovery all preserve the remaining doubt about what the data can distinguish. They improve scientific honesty by returning tests, remaining graph sets, ranked likely causes, or bounds instead of a false single answer.

Hypothesis Before Story

Neural Effect Search, HypoSpace, RefineStat, MedAgentGym, Bitween, WZ-LLM, and VERINA turn fluent scientific work into checkable objects. A model can propose, but the claim becomes scientific only when a statistical test, executable environment, proof checker, or recovery metric can inspect it.

FOCUSED CHAIN

Evidence Boundaries: What The Evidence Actually Determines

The central question is not whether the model can draw a plausible arrow. It is whether the same "what would happen if we changed this?" answer survives across every story that still fits the observations and the stated assumptions. That shared answer is what the evidence proves. The formal name for this discipline is identification.

The Core Object

Problem. Records of what happened usually do not prove what would happen after an action. Many stories can match the same records while predicting different action results.

Object. One target claim, such as a treatment effect, responder decision, repair point, link set, time rule, or fair decision rule, checked against every still-possible story.

Why it works. A method is valid when every story that matches the evidence gives the same answer for the target. The algorithm does not need to recover the whole hidden system; it needs to show that the answer does not change across the remaining doubt.

target is proven when every evidence-compatible story gives the same target answer

Local Covariate Selection, TRECA, And Fair Causal Bandits: Prove The Decision, Not The Whole System

Problem. Learning the whole cause diagram is often impossible, but a real decision still needs a reason.

Object. A local proof token: a fair comparison set, a region where the system should abstain, or a fairness rule strong enough for one decision.

Why it works. These papers shrink the target. Local Covariate Selection asks which background facts block unfair comparison paths for one treatment question. TRECA refuses to act when responder status changes across plausible stories. Fair Causal Bandits checks whether exploration would still be fair under the relevant what-if comparison. What must stay the same is decision validity under the plausible stories. What may change is the local evidence. Name used later: certificate.

Failure boundary. The proof token fails when hidden common causes, missing fairness facts, biased samples, or weak treatment assumptions let two possible stories agree on the records and disagree on the action.

act only when the decision is stable over plausible completions

Structure Learning CI, Distributional Equivalence, And DiCoLa: Return The Remaining Graph Set

Problem. One learned diagram can look precise even when the data supports several diagrams.

Object. Checks for whether two variables still move together after chosen background facts are fixed, plus the set of diagrams those checks still allow.

Why it works. Those relation checks are the visible shadow of the cause structure. The papers keep separate what was observed, what was assumed, and which diagrams are actually forced by those facts. Returning a set is the correct answer when one diagram is not determined.

Failure boundary. The checks can be badly calibrated, small samples can hide weak links, and hidden causes can make different stories look the same from observations.

evidence -> relation claims -> graph set, not necessarily one graph

BRCD, CausalGame, MAP, And Production Agent Studies: Diagnosis Is Repair Ranking

Problem. In incidents, agents, and deployed workflows, the goal is rarely a perfect diagram. The goal is to know which repair would change the bad outcome.

Object. A ranked list of repair points based on logs, partial structure, and observed failures.

Why it works. BRCD keeps doubt over compatible service maps while ranking likely causes. CausalGame makes agents collect evidence that separates explanations. Production studies name the operational facts a real diagnosis needs: handoff state, tool state, action history, monitoring gaps, and human escalation.

Failure boundary. If the logs omit the true deciding fact, confidence is fake. A loud anomaly is not a diagnosis unless fixing it would change the failure probability.

root cause = repair point likely to change failure, not largest anomaly

Latent Hawkes, OU Identifiability, Power-Law Discovery, And Linear Recurrent Memory: Time Helps Only When It Preserves The Rule

Problem. Earlier events can predict later events without causing them. An unseen source, wrong time scale, or changing environment can create the pattern.

Object. A stable rule for how the system moves from now to next, plus observations detailed enough to reveal that rule.

Why it works. Hawkes methods look for event-triggering rules. OU identifiability asks which long-run summaries reveal a noisy system's push rule. Power-law discovery uses repeated time shapes that survive noise. Recurrent memory works when its running note keeps the hidden fact that controls the next action.

Failure boundary. Wrong time scale, unseen subprocesses, deployment drift, and too few deliberate actions can make prediction strong while the real rule remains wrong.

time-based causality requires a stable next-step rule plus the right observation scale

The Evidence-Boundary Chain

Across papers. Local effect papers shrink the cause question until it can be checked. Graph papers preserve remaining possibilities instead of inventing certainty. Root-cause papers turn cause reasoning into repair ranking. Time papers use before-and-after patterns only when the process assumptions make the rule recoverable.

First-principles read. The broad problem is to separate what is predicted from what is controlled. The approach is to define a smaller claim whose answer is forced by evidence plus assumptions, then refuse to claim more.

Big-picture consequence. Causal ML becomes useful when it names the decision-relevant thing that must stay unchanged across remaining explanations. It is not a graph-drawing contest; it is a discipline for deciding when an action claim survives alternative explanations.

prediction asks what follows what; action evidence asks what changes when we act
FOCUSED CHAIN

Executable Hypotheses: When A Scientific Claim Becomes Checkable

A scientific model is not finished when it produces an explanation. It is finished only when the explanation is tied to something that can fail: a fair comparison, a distinct hypothesis, a reusable algorithmic claim, a statistics program, a biomedical workflow, or a proof checked by rules.

The Core Object

Problem. Language models can generate coherent scientific prose without making any claim that a test could change our belief about.

Object. A set of possible hypotheses plus channels that can check them: tests, independent checkers, execution environments, proof-rule checkers, recovery scores, and consequence scores.

Why it works. A hypothesis is useful when evidence can reduce doubt about it. The model may propose candidates, but the scientific content comes from the link between a candidate and the way it could be rejected.

a hypothesis is scientific when some evidence could change belief in it

Neural Effect Search: Interpretability Becomes Science Through Fair Tests

Problem. A sparse feature can look meaningful without proving that changing it changes behavior or outcomes.

Plain object. Like treating a discovered model feature as a possible cause, the method asks whether changing that feature changes an outcome under a fair comparison.

Why it works. What must stay the same is the background needed for a fair test. What may change is the feature being changed or grouped. The method does not stop at naming a feature; it asks whether the feature survives evidence that could disprove it. Name used later: causal hypothesis.

Failure boundary. Feature labels can be after-the-fact stories. Without fair evidence and many-searches correction, the method can rediscover noise and call it a cause.

feature -> candidate effect -> fair test -> corrected evidence

HypoSpace And Consequence-Based Utility: Search Needs A Space And A Scoring Map

Problem. One plausible hypothesis tells little about discovery ability. A model could repeat near-duplicates, miss whole regions, or chase ideas that sound impressive but cannot be tested.

Plain object. Like searching a library shelf, the method checks whether the model covers different shelves, avoids duplicate books, rediscovers known good ideas, and suggests claims someone can test.

Why it works. What may change is the proposed idea. What must stay visible is testability and evidence value. HypoSpace evaluates the model as a sampler over explanations: did it cover the space or repeat itself? Consequence-based utility asks whether a proposed claim improves easier-to-check tasks. Name used later: hypothesis space.

Failure boundary. The score can reward easy-to-state hypotheses over important ones, or consequences that move with truth without being strong enough to reject false claims.

discovery quality = coverage + uniqueness + evidence value, not fluency

RefineStat And MedAgentGym: Scientific Work Must Change State In An Environment

Problem. Scientific code or biomedical analysis can be syntactically valid while still meaning the wrong thing.

Plain object. Like accepting lab work only after the code runs, the data changes, and the result can be checked, scientific work must leave an inspectable trail.

Why it works. What must stay the same is the claim being tested. What may change is the program state, analysis state, or feedback from the environment. RefineStat checks whether a statistics program's pieces mean what they should and repairs local failures. MedAgentGym puts biomedical agents inside tasks where consequences are visible. Name used later: executable workflow.

Failure boundary. Execution can still be shallow. A toy environment may validate commands while missing clinical realism, and a statistics repair may make one component legal without supporting the final scientific claim.

claim -> artifact -> execution trace -> domain-specific failure signal

PaperBench, WZ-LLM, VERINA, And Bitween: Artifacts Need Independent Checkers

Problem. Research papers, proofs, and algorithmic reductions can be persuasive while containing hidden invalid steps.

Plain object. Like accepting a research result only after the code runs, the proof steps check out, and the experiment matches the claim, the method separates proposing from accepting.

Why it works. What may change is the artifact: paper, proof, code, or reduction. What must stay the same is that each claimed part has a checker that can reject it. PaperBench asks whether a research workflow assembled evidence-bearing components. WZ-LLM and VERINA reject proof steps that violate the rules. Bitween searches for reductions but counts them only after verification. Name used later: verifier.

Failure boundary. A checker covers only its scope. It can reject malformed proofs while missing an irrelevant theorem choice, or verify one component while the end-to-end research conclusion remains weak.

generator proposes artifact; checker defines accepted artifact set

The Executable-Hypothesis Chain

Across papers. Neural Effect Search turns learned features into tested effects. HypoSpace measures hypothesis coverage and duplication. Consequence-based utility uses downstream evidence when direct proof is hard. RefineStat and MedAgentGym make scientific work executable. PaperBench, WZ-LLM, VERINA, and Bitween require independent artifact checks.

First-principles read. The broad problem is that generative models can create descriptions faster than science can reject them. The approach is to attach each description to a failure channel: statistical test, execution trace, proof-rule checker, recovery score, or consequence score.

Big-picture consequence. AI for science becomes credible when it increases the rate of rejectable claims, not merely the rate of fluent proposals. The mathematical advance is the bridge between generation and evidence.

proposal rate is useful only when rejection rate and evidence quality scale with it
