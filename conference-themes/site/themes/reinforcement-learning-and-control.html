Problem

Control settings do not reward passive prediction. The model must choose actions while data is incomplete, rewards are uncertain, logs are biased, and deployment requires fast, feasible decisions.

Approaches

The papers use diffusion density rewards, KL-constrained extrapolation, stochastic latent dynamics, optimistic task inference, one-step generative policies, centralized dispatch RL, and programmatic feedback.

Connecting read

This page is the compact bridge between RL and embodied deployment: the learning system is judged by the action it chooses, not the score it predicts.

READ

The Big Picture

Reinforcement learning becomes control when the model's output changes the next state of the world. That changes the engineering problem. A recommender or ad system has to generalize beyond logged behavior without taking reckless actions. A robot policy has to generate feasible actions fast enough to execute. A CAD reconstruction model can improve through programmatic feedback because the output is executable. A ride-sharing dispatcher has to coordinate many orders and drivers through action decomposition. These are not static prediction problems with a reward label attached; they are closed-loop systems.

The seven papers here show different ways to make that closed loop usable. Some add intrinsic rewards for exploration. Some model uncertainty over the task or reward. Some constrain extrapolation beyond offline logs. Some build latent world models or one-step action generators so the policy can act at runtime. The connecting idea is that action quality depends on how the system represents uncertainty, feasibility, and feedback before it commits to the next move.

CLUSTERS

The Main Research Moves

1. Exploration and task inference need uncertainty, not random motion

ExDM fits replay-buffer distributions with diffusion models and uses score-based intrinsic rewards to push exploration toward under-visited regions. OpTI-BFM models reward-function uncertainty and uses test-time environment interactions to infer the task over a few episodes. Both papers treat exploration as information gathering: the system needs to know which uncertainty matters for later control, not simply add noise to actions.

2. Offline and deployed control need bounded extrapolation

AIGB-Pearl addresses the core offline-control risk: a policy trained on static ad-system logs may score actions well only because it has left the support of the data. Its KL-Lipschitz-constrained score maximization and synchronous coupling are attempts to extrapolate without trusting the learned score blindly. Triple-BERT tackles a different deployment constraint: large-scale ride-sharing dispatch needs centralized action decomposition so a single-agent RL formulation can operate over complex order-dispatch decisions.

3. Embodied policies need compact dynamics and fast action generation

LPWM models stochastic particle dynamics conditioned on action, language, and image goals, giving goal-conditioned imitation a latent world state to reason through. MFP models mean velocity fields for fast one-step action generation in robotic manipulation, replacing slow iterative policy sampling with a direct generative control primitive. cadrille shows the same control logic in CAD reconstruction: supervised procedural data gets the system started, then RL with online programmatic feedback improves executable reconstruction quality.
