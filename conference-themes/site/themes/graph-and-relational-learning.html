Problem

Graph models must preserve structure while learning from it. Too much message passing smooths nodes into sameness; too little misses long-range relations; wrong edges or shifted homophily can break transfer.

Approaches

The papers use signed-graph algorithms, spectral factorization, sheaf and bundle views, exact algorithm execution, graph random features, hyperbolic personalization, distribution barycenters, and large structured graph datasets.

Connecting read

The field is moving beyond "run a GNN" toward asking which relational operator matches the structure of the data and the computation the task requires.

FIRST PRINCIPLES

The core problem

A graph is a constraint on communication. A node can only aggregate through edges, paths, hyperedges, faces, or learned rewiring rules. That makes graph learning different from ordinary representation learning: the architecture is also an algorithm for moving information through structure.

The papers here ask what happens when that algorithm is too weak, too smooth, too local, too global, or too mismatched to the graph's domain. Some study exact graph algorithms and theoretical limits. Some repair message passing with spectral or activation structure. Some handle domain shift, heterogeneity, and higher-order relations. Others build the datasets and scalable features needed to make graph learning operate at world scale.

SYNTHESIS

Four views of graph learning

1. Message passing must compute, not just diffuse

algorithmic structure

This cluster asks when a GNN can execute a real graph computation rather than blending neighboring features. The difference matters because many graph tasks require exact local rules, long-range coordination, or signed consistency.

ICML 2026Exact GNN Algorithms
Exact GNN Algorithms learns local node instructions with MLP ensembles and executes graph algorithms exactly through GNN updates. The paper treats message passing as a programmable substrate. Instead of hoping learned embeddings approximate an algorithm, it asks how local update rules can implement the algorithm itself.
ICML 2026Which Algorithms Can GNNs Learn
Which Algorithms Can GNNs Learn characterizes when message-passing networks trained on small instances can generalize graph algorithms to arbitrary sizes. The key question is extrapolation of computation, not interpolation of examples. A graph algorithm learner is only credible if the learned rule survives larger graphs than it saw in training.
ICML 2026BTT Algorithms
BTT Algorithms provides approximation algorithms for removing bad triangles in signed graphs. Signed edges encode compatibility and conflict, so inconsistent triangles are structural errors, not noisy features. The paper shows that graph governance sometimes means editing the relational structure before learning from it.
ICML 2026DFN
DFN characterizes optimization complexity by deviation from a tractable M-convex regime. It connects neural graph-like optimization to discrete convex structure. The practical message is that some neural objectives are hard because they leave the regime where combinatorial optimization has exploitable structure.

2. Graph models need the right geometry of information flow

spectral and geometric operators

Graphs have local neighborhoods, global spectra, high-order relations, and geometry that may be Euclidean, hyperbolic, or sheaf-like. These papers redesign the operator that moves information so it fits that structure.

ICML 2026Beyond ReLU
Beyond ReLU reframes oversmoothing as convergence to a stable homogeneous fixed point and uses activations to induce non-homogeneous patterns. It makes oversmoothing a dynamical-systems problem. The activation function is not a minor nonlinearity; it changes whether repeated message passing collapses node identities.
ICML 2026S3GNN
S3GNN combines global spectral mixing with local message passing without depending on hard-to-measure Jacobian sensitivity assumptions. It attacks oversquashing by letting distant information move through spectral structure while preserving local updates. The design says long-range graph reasoning needs more than deeper neighborhoods.
ICML 2026L2G-Net
L2G-Net factorizes the graph Fourier transform into subgraph operators coupled by Cauchy matrices. It makes spectral computation more local-to-global. That matters because full-graph spectral methods can be expensive, while purely local methods miss global modes.
ICML 2026OENN/CENN
OENN/CENN unifies graph message passing and sheaf neural networks through equivariant bundles over face posets. The paper widens the object from edges to higher-order geometric structure. In many relational domains, information lives on nodes, edges, faces, and their consistency maps, not on nodes alone.
ICML 2026HyperDepth
HyperDepth uses adaptive spectral gating and prototype-tree alignment to preserve semantic depth in higher-order relational data. Hypergraphs can express relations among more than two entities, but that extra structure can flatten if treated like ordinary edges. The method tries to keep higher-order semantics deep and distinguishable.
ICML 2026ENGNN
ENGNN uses random node noise under transformation equivariance to obtain universal expressivity with practical scaling. It addresses the expressivity limit that symmetric nodes can be indistinguishable to ordinary message passing. Noise helps break symmetry while equivariance keeps the model faithful to graph transformations.

3. Real graph data shifts across domains, clients, and subjects

heterogeneity and transfer

Graph structure is not stable across settings. Homophily changes, clients have different shapes, brain networks depend on phenotype, and environments may share only an invariant prototype.

ICML 2026PSAHS
PSAHS progressively reweights edges and adds intra-class links to align node homophily across graph domains. It treats domain shift as structural shift. If label-consistent connectivity changes between source and target, adaptation has to repair the graph, not only the node classifier.
ICML 2026FlatLand
FlatLand embeds federated clients in tailored Lorentz spaces to handle structurally heterogeneous graph data. Different clients may have graph structures with different hierarchy and curvature. Hyperbolic personalization gives each client a geometry that better matches its relational shape while still supporting federation.
ICML 2026DIGL
DIGL models the invariant graph prototype across environments as a distribution barycenter. It asks what relational structure remains stable when environments vary. A barycenter view gives domain generalization a concrete object: the shared graph distribution that should survive shifts.
ICML 2026PhenoBrain
PhenoBrain learns phenotype-conditioned multi-hop communication kernels for functional brain networks. Brain graphs are subject-specific; phenotype changes which long-range communication paths are meaningful. The model therefore conditions the graph operator on biological context rather than using one fixed propagation rule.

4. Scale and representation turn graph learning into infrastructure

data and scalable features

The final cluster is about making graph learning work when the graph is huge or implicit. Representation quality depends on how walks, features, and query tools expose structure without materializing impossible objects.

ICML 2026OSM+
OSM+ releases a structured worldwide road graph with roughly a billion vertices and spatial query tools. The contribution is infrastructure: real graph learning needs datasets whose scale, spatial structure, and tooling match deployment. A road network is not just a graph; it is a queryable spatial system.
ICML 2026DeepWalk Trajectory
DeepWalk Trajectory shows that small-initialized DeepWalk with negative sampling aligns embeddings with a fixed low-rank graph subspace. It gives a more precise account of what random-walk embedding training is doing. The trajectory view turns a popular heuristic into a describable representation path.
ICML 2026SWING
SWING computes graph random features through continuous-space walks without materializing feature-defined graphs. That matters when the useful graph is implicit and too expensive to build explicitly. The paper keeps the relational computation while avoiding a prohibitive construction step.
FIELD READ

What this theme says about ICML

The graph-learning signal is that relational structure is being treated as a computational object. The papers are less satisfied with generic message passing and more focused on the operator: what it can compute, where it loses information, how it handles higher-order relations, and whether it matches the graph's domain.

That is useful for the broader conference map because graphs are a bridge between theory, infrastructure, and embodied or scientific systems. Road networks, brain networks, hypergraphs, federated client graphs, and signed relation graphs all force the same question: which structure must be preserved so learning does not erase the thing that made the data relational in the first place?
