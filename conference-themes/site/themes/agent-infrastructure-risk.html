Problem

Safety systems often inspect visible text, but agent infrastructure creates hidden representations, encoded channels, tool state, and intermediate messages that may carry the real intent.

Approaches

The two papers attack opposite sides of the same gap: hidden unsafe content in messages, and harmful internal representations that survive surface-level filtering.

Connecting read

This theme is small in paper count but important as a warning: monitoring must move closer to the channels through which agents actually compute and communicate.

FIRST PRINCIPLES

The core problem

A safety monitor only works if it sees the object that carries risk. With simple chat, that object looks like user text and assistant text. With agents, the risky object may be a hidden activation pattern, a steganographic message, a tool output, a memory write, a compressed scratchpad, or a protocol-level handoff between components. The infrastructure becomes part of the model's communication channel.

This page is therefore not about two isolated tricks. It is about a monitoring mismatch. Surface classifiers ask whether the visible content appears safe. Agent infrastructure asks whether the whole computational pathway is safe. Those are different questions. If unsafe instructions can be hidden in an apparently harmless message, or if harmful intent can be detected inside activations before it appears in text, then production safety needs deeper observability than prompt/output scanning.

SUBTHEMES

Two failure modes the papers expose

1. Hidden channels defeat surface monitoring

encoded communication

The first risk is that a message can look harmless at the level the safety system reads while carrying a different meaning at the level the agent or downstream decoder uses. This is especially relevant for multi-agent systems, tool-using workflows, and retrieval pipelines where content may be transformed before it is acted on.

ICLR 2026Invisible Safety Threat
Invisible Safety Threat studies stegotext interactions: messages that are classified as safe before decoding but become unsafe after the hidden content is decoded. The reported result is stark because it shows a complete monitoring blind spot. The visible text can pass the classifier while the actual instruction stream remains dangerous. The broader lesson is that safety checks have to reason about transformations and hidden channels, not only raw surface strings.

2. Internal representations can reveal risk earlier than text

activation monitoring

The second risk points in the other direction. Sometimes the surface text is too late or too easy to disguise, while the model's internal state already carries evidence that the behavior is harmful. Activation-level monitoring treats safety as a property of computation inside the model, not just the final message.

ICML 2026Trojan-Speak
Trojan-Speak finds that activation probes can detect harmful internal representations even when surface classifiers are bypassed. The important idea is not that probes are a complete solution; it is that the safety signal may exist before it is visible in text. For agent infrastructure, this matters because agents can route information through scratchpads, tools, and intermediate states. Monitoring only the final output misses the computation that produced it.
FIELD READ

Why this belongs beside the agent pages

The agent pages argue that tasks, observations, actions, feedback, and verifiers need a common representation. This page adds the security reason: once those fields exist, they also become places where risk can hide. A normalized agent protocol is useful for training and benchmarking, but it is also useful because it gives safety systems a structured surface to inspect.

The production implication is simple. If an agent platform cannot log and inspect intermediate messages, decoded content, tool calls, memory writes, and model-state risk signals, it cannot know what it is deploying. The risk is not only that the final answer is unsafe. The risk is that the system performs unsafe computation while every visible message looks acceptable.
