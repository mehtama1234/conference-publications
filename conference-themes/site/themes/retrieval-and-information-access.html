Problem

Models fail when the needed evidence is outside their parameters, buried in a long context, stored in another modality, hidden in a codebase, or named in a formal library under the wrong symbol.

Approaches

The papers train retrievers from downstream value, language-modeling signals, prompt-conditioned multimodal alignment, code syntax and semantics, theorem context, semantic prototypes, and faster angle kernels.

Connecting read

The common move is to make access selective and task-aware: what gets retrieved should depend on the question, the modality, the workflow, and the cost of a wrong or slow match.

FIRST PRINCIPLES

The core problem

A language model's parameters are not enough. Real tasks ask for fresh facts, private documents, long codebases, local proof lemmas, audio and video evidence, or specialized-domain knowledge that was never labeled as a query-document pair. Retrieval is the mechanism that decides what external state enters the model's working context.

That makes retrieval a control problem. A bad retriever can starve the model of the only decisive evidence; an overly broad retriever can flood the context with distractors; a slow retriever can dominate latency; a static embedding can ignore the user's actual intent. The papers in this theme attack different parts of that access stack. Some ask how a retriever should learn, some ask what kind of representation space it should search, some ask how retrieval plugs into code and proof workflows, and one asks how the low-level geometry of similarity search can be made faster.

SYNTHESIS

Four ways the papers rethink access

1. Retrieval becomes a learned policy

sequential access

The old retrieval pattern is one query, one ranked list, then generation. That is too shallow for questions where the first evidence only reveals what to search for next. These papers treat access as an adaptive process whose choices can be trained from downstream usefulness.

ICLR 2026Q-RAG
Q-RAG reframes long-context RAG as value-guided sequential search. Instead of fine-tuning a small LLM to decide every retrieval step, it fine-tunes the embedder with reinforcement learning so the representation itself favors evidence that will help later answer steps. The first-principles point is that relevance is not always a static relation between one query and one passage. In multi-hop or very long contexts, a useful chunk is useful because of what it enables next. By moving some of that policy into the embedder, Q-RAG tries to keep multi-step access compatible with large reader models and with contexts reported up to 10 million tokens.
ICLR 2026Revela
Revela asks where retrieval supervision should come from when labeled query-document pairs are missing. Its answer is to train dense retrievers through language modeling: if cross-document context helps next-token prediction, the retriever that surfaced that context receives a useful signal. This matters because specialized domains and reasoning-heavy domains often have documents but not carefully curated retrieval labels. Revela turns document dependency into supervision, making retrieval training closer to ordinary self-supervised pretraining than to a hand-labeled ranking task.

2. The embedding space has to match the task surface

multimodal access

Many real queries are not only text-to-text. A user may search video with text, audio with video, an image with a word that was never paired in training, or a media item under a specific instruction. These papers build retrieval spaces where modality and intent are first-class constraints.

ICLR 2026WAVE
WAVE builds a shared embedding space for text, audio, and video using hierarchical feature fusion and joint multimodal training. Its important idea is prompt awareness: the same media object may need a different embedding depending on what the user is trying to find. That turns an embedding from a fixed descriptor into a task-conditioned access key. The paper fits this theme because retrieval quality now depends on temporal and multimodal representation, not only on better text vectors.
ICLR 2026MASK
MASK tackles unpaired image-text matching, especially when the text contains out-of-distribution words. It uses word embeddings as semantic bridges to construct visual prototypes, then regularizes the prototype space with a contrastive consistency loss. The deeper problem is missing correspondence: if there are no direct image-text pairs for a word, the model needs an intermediate anchor that connects language meaning to possible visual evidence. MASK treats prototypes as those anchors, so retrieval can generalize beyond seen vocabulary instead of collapsing when a word is new or visually varied.

3. Retrieval is part of a workflow, not just a ranked list

code and proof

In code and formal verification, the retrieved item is not merely context for an answer. It is an object that will be executed, type-checked, translated, tested, or used by a solver. That raises the bar: retrieval has to respect syntax, semantics, local definitions, and the downstream verifier.

ICLR 2026SwingArena
SwingArena uses retrieval-augmented code generation inside an adversarial GitHub issue benchmark. The retrieval module supplies syntactically and semantically relevant snippets across C++, Python, Rust, and Go so patch-generating agents can work inside large codebases without stuffing the whole repository into context. The retrieval point here is practical: a code agent must retrieve the file, symbol, test, or dependency that makes a patch meaningful, and the result is judged through reviewer tests and CI rather than by surface plausibility.
ICLR 2026LeanPremise
LeanPremise is retrieval for theorem proving. A Lean hammer needs to select useful premises, translate goals to external automated theorem provers, and reconstruct proofs back in Lean. The hard part is that relevant facts may live in a library outside the selector's training data or in lemmas the user just defined locally. LeanPremise matters because it adapts premise selection to that user context, turning retrieval into a bridge between neural ranking and symbolic proof search.

4. Similarity search is infrastructure with mathematical bottlenecks

retrieval systems

All the higher-level retrieval ideas eventually hit a systems question: how quickly can the system compare vectors while preserving enough recall? At large scale, the geometry of approximate search affects latency, cost, and whether an agent can afford to retrieve repeatedly.

ICLR 2026Probabilistic Angle Kernels
Probabilistic Angle Kernels studies high-dimensional angle testing, a primitive behind vector retrieval. Instead of relying on Gaussian random projection vectors, the method uses deterministic reference-angle structure for angle comparison and thresholding. The paper then applies those kernels to approximate nearest-neighbor search and reports higher query-per-second throughput than HNSW in the described setting. Conceptually, it reminds us that information access is not only a modeling problem. If the similarity primitive is noisy or slow, every RAG system, recommender, memory store, or agentic search loop inherits that bottleneck.
FIELD READ

What this theme says about ICML and ICLR

The big picture is that retrieval is becoming an active part of intelligence. It decides what a model can see, what it can cite, what code it can edit, what premise it can prove from, and what media evidence it can connect across modalities.

That connects directly to the agent and benchmark work. An agent loop is only as good as its observation and memory access. A benchmark that asks for browser, code, theorem, or long-context behavior is implicitly testing retrieval decisions: which state was surfaced, whether the right artifact was retrieved, and whether the verifier checked the consequence. This theme is useful because it separates three layers that are often blurred together: training the access model, designing the representation space, and serving similarity search fast enough for repeated use.
