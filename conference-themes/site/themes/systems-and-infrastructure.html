Problem

Modern ML fails in the gap between an algorithm and the machine that must execute it. The bottleneck may be KV cache memory, kernel fusion, GPU occupancy, distributed heterogeneity, legal tool integration, or a human approval loop.

Approaches

The papers redesign kernels, compilers, cache layouts, compression, MoE routing, agent runtimes, federated aggregation, vector search, scientific pipelines, and accelerator-friendly optimizers.

Connecting read

The field is treating infrastructure as part of the model. Architecture, scheduler, data movement, and deployment protocol now determine which capabilities can actually be used.

FIRST PRINCIPLES

The core problem

A model is not only weights and loss curves. It is also a memory layout, a set of kernels, a scheduler, a cache policy, a deployment latency budget, and an interface to tools or humans. If any one of those pieces breaks, the model's nominal capability becomes unusable. Systems work starts from that physical fact.

The systems papers in this theme repeatedly make the same move: take an abstract ML operation and expose the execution constraint that actually governs it. Attention becomes KV cache reuse. Long context becomes tiled prefill on a 24GB GPU. Agent reasoning becomes parallel API calls and workflow-aware resource scheduling. Federated learning becomes merging under heterogeneity. Scientific ML becomes distributed sharding, tokenization, and domain-specific kernels. The common goal is not elegance for its own sake; it is making the useful behavior fit real machines.

SYNTHESIS

Five infrastructure problems the papers attack

1. Memory and compression decide whether large models can serve

serving footprint

This cluster starts from the serving bottleneck: generation is often limited by memory bandwidth, KV cache size, and the cost of storing or moving intermediate state. The methods compress selectively, reuse cache pages, prune layers, or exit early when more computation is not worth the latency.

ICML 2026DHSA
DHSA runs 100K context on a single 24GB GPU by redesigning attention around memory-efficient tiled prefill. The contribution is practical: long-context capability is meaningless if it requires unavailable hardware. The paper turns long context from a model-size claim into a commodity-serving problem.
ICLR 2026ThinKV
ThinKV reuses evicted KV-cache slots to avoid compaction overhead and improve reasoning throughput. The insight is that cache management is now part of reasoning infrastructure. When long reasoning fills memory with past tokens, the runtime must reclaim and reuse space without stalling generation.
ICML 2026STAR-KV
STAR-KV combines hybrid low-rank decomposition, mixed-precision quantization, and Triton kernels for faster generation. It treats the KV cache as structured data rather than a flat tensor to compress uniformly. The system gain comes from respecting which parts of the cache can be low rank and which require precision.
ICML 2026EntroKV
EntroKV keeps high-entropy attention heads while compressing low-entropy heads more aggressively at serving time. That is a head-level view of importance. Instead of compressing the whole model equally, it asks which attention heads still carry uncertainty and therefore deserve memory.
ICML 2026MoE Compression
MoE Compression combines structural pruning with 4-bit quantization to reduce a large mixture-of-experts model's memory footprint. MoE models have conditional compute but large stored capacity, so serving cost can be dominated by parameters that are not active for every token. Joint pruning and quantization attacks the stored-capacity side of that mismatch.
ICLR 2026Layer Pruning Reassessment
Layer Pruning Reassessment uses large-scale benchmarks and gradient-flow analysis to revisit LLM pruning and post-pruning fine-tuning. Its value is caution: compression recipes that look simple can damage the paths gradients and representations need. Pruning should be evaluated as a training-and-repair pipeline, not a one-shot deletion.
ICML 2026TabSwift
TabSwift adds adaptive layer-wise early exits to tabular foundation-model inference for latency-sensitive classification and regression. It makes serving conditional on confidence and task difficulty. The system should not spend full inference budget on easy rows when a shallow layer is already sufficient.

2. Kernels, compilers, and tensor languages are becoming ML method design

machine fit

The second cluster gets closer to the hardware. The papers redesign primitive operations so the mathematical method maps cleanly onto memory hierarchy, matrix multiplication units, sparse layouts, and compiler-visible scheduling.

ICLR 2026TileLang
TileLang exposes memory placement, data movement, and scheduling primitives for fused neural kernels. Its purpose is to let ML developers express what matters for performance without dropping fully into vendor-specific low-level code. The page-level point is that kernel design is now a modeling interface.
ICLR 2026einx
einx reduces tensor APIs to declarative expressions grounded in consistent vectorization rules. This is infrastructure for human correctness. Tensor code often fails because shape transformations are implicit; einx makes the intended vectorization visible and reusable across operations.
ICML 2026CONTINUUM
CONTINUUM adds PyTorch-level Elastic Tensors with zero-copy topological aliasing and dynamic memory behavior. It recognizes that static tensor abstractions strain under dynamic models and changing layouts. The method brings flexible memory structure into the framework instead of forcing every model to fake it with copies.
ICML 2026FFCC
FFCC lowers costly Swish- and GELU-like functions into fast floating-point reinterpretation instruction sequences. The lesson is that activation functions are not free mathematical decorations. At edge scale, a cheaper approximation compiled into the right instructions can decide whether the model meets its power and latency budget.
ICML 2026IO-Aware GNNs
IO-Aware GNNs groups graph neural layers by SpMM, reduction, and attention kernels to reduce memory traffic and improve locality. Graph learning is often bandwidth-bound rather than arithmetic-bound. The paper says the right architecture taxonomy is partly a kernel taxonomy.
ICLR 2026SparseRL
SparseRL treats CUDA generation as a stochastic policy conditioned on sparse matrix nonzero indices. Sparse kernels are hard because layout determines performance. The paper turns kernel construction into an RL search problem where the policy is guided by the actual sparsity pattern.
ICLR 2026Polar Express
Polar Express designs adaptive matrix-sign iterations using only matrix multiplications for high-throughput accelerators. The system insight is to reformulate an optimizer subroutine around the operation GPUs execute best. Better numerical methods are useful when their primitive operations match the hardware.
ICML 2026NorMuon
NorMuon implements scalable Muon-style orthogonalization under FSDP2 across devices. It addresses the systems side of modern optimizer design: a useful optimizer must survive sharding, synchronization, and distributed matrix operations. Orthogonalization becomes credible only when it can run at training scale.

3. Agent infrastructure is workflow scheduling, not just prompting

agent runtime

Agent systems introduce a different bottleneck: tool calls, browser actions, verifier feedback, human intervention, and external assets. These papers treat an agent as a runtime with state, resources, and traces.

ICLR 2026ADP
ADP unifies 13 agent datasets across coding, browsing, tool use, and research benchmarks and reports broad average gains. Its infrastructure role is interoperability: agent traces become reusable only if actions, observations, and outcomes share a common representation. That is why this paper matters for the gym work too; it turns scattered agent data into something a training stack can consume.
ICLR 2026Speculative Actions
Speculative Actions predicts likely agent actions with faster models so multiple API calls can run in parallel without changing accepted behavior. Agent latency is often wall-clock latency from tools, not token generation alone. Speculation helps when the system can safely run likely branches and only keep the branch the main agent actually chooses.
ICML 2026ThunderAgent
ThunderAgent schedules LLM and tool resources with workflow-level knowledge of KV caches, states, and external assets. It treats an agent plan as a resource graph. The runtime can be faster if it understands which intermediate states, caches, and files are shared across steps.
ICML 2026MAP
MAP finds that production agents mostly rely on prompting, human evaluation, and short workflows before intervention. That is a grounded systems observation. The near-term production agent is less an autonomous long-horizon machine and more a human-governed workflow component, so infrastructure must support oversight and quick handoff.
ICML 2026AlgoVeri
AlgoVeri measures whether models can exploit verifier feedback rather than saturating after early attempts. Verification is not just an evaluation endpoint; it can be part of test-time repair. The systems question is whether the loop between attempt, verifier signal, and repair actually produces continued progress.
ICLR 2026CRAMF
CRAMF indexes a large formal-math knowledge base with query augmentation and hybrid reranking. It shows that specialized agent competence may require domain infrastructure outside the model: curated definitions, concepts, retrieval, and reranking. The model's reasoning improves when the surrounding knowledge system is built for the domain.

4. Distributed and modular learning need coordination rules

heterogeneity

This cluster is about systems where capability is split across experts, clients, modalities, devices, or decentralized learners. The hard part is not only training each part; it is routing, merging, and balancing capacity without letting one source dominate.

ICLR 2026Equal-Resource MoE
Equal-Resource MoE trains hundreds of 2B and 7B models and identifies a stable optimal activation-rate region under fixed budgets. It asks how much sparse capacity should be active when total compute is held constant. The answer matters because MoE gains can disappear if routing saves compute but starves useful experts.
ICML 2026Beyond LM
Beyond LM uses sparse experts to provide language capacity while accommodating vision's data-hungry scaling. Multimodal models have asymmetric needs: language and vision do not scale with identical data and compute patterns. Sparse experts become a coordination mechanism between modalities rather than a generic capacity trick.
ICML 2026Embedding Translation
Embedding Translation uses localized expert adaptation and confidence metrics across many pairwise model-translation settings. It treats embedding spaces as infrastructure boundaries. If models cannot exchange representations safely, modular systems become locked inside incompatible latent spaces.
ICML 2026DroneDINO
DroneDINO uses auxiliary task recognition to counter dominant-task overactivation in unified drone detectors. In multi-task systems, the most common or easiest task can hijack shared capacity. Routing must be task-discriminative so rare or specialized drone tasks still receive useful expert activation.
ICML 2026FedARC
FedARC aligns federated clients with semantic anchors while preserving local and global embedding fusion. Federated clients are not identical, so forcing one representation can erase local structure. Anchors give the system shared coordinates without removing client-specific information.
ICLR 2026Global Merging
Global Merging shows that late fully connected merging can improve generalization under severe data heterogeneity. The result frames decentralized learning as a timing problem. Local learners should specialize for a while, then merge when their representations contain complementary evidence.
ICML 2026mHC
mHC combines diversified residual connectivity with infrastructure optimization for scalable training. It treats architecture topology and training system as coupled. Residual paths are not only representation choices; they change communication, memory, and how gradients travel through the trained system.

5. Specialized domains force infrastructure to respect the domain's physics

domain systems

The final cluster shows systems work outside generic LLM serving. Control, dispatch, vector search, brain imaging, scientific pretraining, bandits, and recurrent models each impose their own execution shape.

ICLR 2026Differentiable MPC on GPU
Differentiable MPC on GPU makes model predictive control practical inside RL and imitation-learning training loops. Control methods often fail to scale because the solver is too slow or CPU-bound. Moving differentiable MPC onto accelerators lets classical control structure participate in modern learning pipelines.
ICLR 2026Triple-BERT
Triple-BERT reuses parameters and attention over driver and order pools for dispatch, improving served orders and pickup time on Manhattan data. Dispatch is a relational systems problem, not a single-example prediction problem. The architecture fits the operational structure of matching many drivers to many orders.
ICLR 2026Probabilistic Angle Kernels
Probabilistic Angle Kernels improve approximate nearest-neighbor search throughput over HNSW in the reported setting. Retrieval infrastructure determines whether embeddings are useful at scale. A better similarity kernel can turn the same representation into faster search and higher serving capacity.
ICLR 2026FFDP
FFDP uses non-GEMM fused kernels and distributed sharding for native-resolution human-brain MRI registration. Gigavoxel medical imaging cannot be handled by pretending every workload is a transformer GEMM. The system has to respect image resolution, memory locality, and distributed volume processing.
ICML 2026Walrus
Walrus combines harmonic-analysis stabilization, load-balanced distributed training, and compute-adaptive tokenization for 2D-3D scientific pretraining. Scientific domains bring geometry and numerical stability requirements that ordinary web-scale recipes ignore. The infrastructure has to preserve those structures while still scaling.
ICML 2026Rare-Update Bandits
Rare-Update Bandits removes expensive G-optimal design bottlenecks while preserving optimal regret in linear and generalized linear settings. It is a systems-aware theory result: an algorithm with optimal regret is incomplete if its update rule is too expensive to run. Rare updates make the theory computationally usable.
ICML 2026CMRU
CMRU restores gradient flow in analog-friendly bistable recurrent units through cumulative temporal updates. Low-power recurrent hardware has different constraints from digital transformer accelerators. The paper designs the recurrence so trainability and analog efficiency can coexist.
ICLR 2026FlashRNN
FlashRNN trains 7B-parameter LSTM and GRU-style models with perplexity comparable to similarly sized Transformers and Mamba2. It revisits recurrent architectures through solver and implementation reformulation. The point is that an architecture can become newly competitive when the training system around it changes.
FIELD READ

What this theme says about ICML and ICLR

The conference signal is that systems work has moved from "make it faster" to "make the method possible." Long-context reasoning, agent workflows, MoE multimodality, federated learning, formal math retrieval, and scientific imaging all depend on infrastructure choices that define the feasible behavior.

That is why these papers matter for the broader project. If we want to understand agents, gyms, benchmarks, and model capability, the runtime cannot be a footnote. The tools available, the trace format, the cache policy, the verifier loop, and the hardware budget are part of the experimental object.
