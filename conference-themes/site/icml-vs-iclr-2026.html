READ FIRST

The Big Picture Problem

The conferences are circling the same pressure from different sides. A model that only predicts the next token, class, pixel, or action is not enough once it is placed inside a tool loop, a codebase, a robot, a legal workflow, a scientific simulator, or a deployment system with privacy and cost limits. The object being optimized has expanded from a function to a process.

ICML reads as the conference of control surfaces: training phases, curvature, constraints, verifiers, safety boundaries, numerical precision, and theory that names the object being controlled. ICLR reads as the conference of system forms: agent worlds, model behavior, generative structures, long-context interfaces, multimodal fusion, data recipes, and benchmarks that make those systems observable. The split is not absolute, but it is useful.

DIFFERENCE

What Each Conference Is Doing

ICML: control surfaces for learning systems

ICML repeatedly asks how to expose the variable that actually governs behavior. RAGEN-2 turns reasoning collapse into input-dependence. The Tell-Tale Norm turns hidden-state magnitude into an inference signal. CSPO turns safe RL into distance from a constraint boundary. DiReCT turns data selection into Hessian-aware movement. Error-propagation work turns quantization into a denoising-trajectory problem.

The pattern is precise: find the hidden object, measure it, and use it as a control knob. ICML is strongest when a practical recipe becomes a more explicit optimization problem.

ICLR: system forms and behavior tests

ICLR repeatedly asks what form an AI system should take when a static answer is too small. CyberGym makes cybersecurity evaluation executable. GAIA2 and OpenApps vary agent environments. OpenThoughts treats reasoning data as public recipe infrastructure. Quotient-Space Diffusion changes the sample space for physical objects. Mamba-3 changes sequence modeling around state-space recurrence.

The pattern is architectural: build the environment, representation, benchmark, or interface where the desired behavior can appear and be measured.

CONVERGENCE

The Shared Center

The shared center is controlled process. For reasoning, the process is a trace that must remain task-conditioned. For agents, it is a loop of observation, action, feedback, and recovery. For safety, it is behavior under tail events, user pressure, adversaries, and constraints. For generation, it is a path through a structured sample space. For data, it is an ordered, governed, weighted resource. For theory, it is the smaller mathematical object that explains why the recipe has the shape it does.

The conferences differ in emphasis, but the direction is common: systems are becoming harder to evaluate with one scalar score, harder to train with one static dataset, and harder to explain with one architecture label. The field is building instruments around the model.

PAPERS

Cross-Conference Paper Examples

ICML

RAGEN-2

Shows that fluent agent reasoning can become input-agnostic. The key object is mutual information between task input and reasoning trace: if the trace stops carrying input information, the system is not really reasoning about the task.

ICLR

OpenThoughts

Treats reasoning traces as reproducible training infrastructure. The paired lesson with RAGEN-2 is that reasoning data must be both useful and diagnostic; more traces are not enough if their process structure teaches generic habits.

ICML

SandboxEscapeBench

Turns safety into a reachability test inside nested container boundaries. It asks whether the agent can cross from an allowed state into a protected host state.

ICLR

CyberGym

Turns cybersecurity capability into executable exploit generation against real code versions. Together with SandboxEscapeBench, it says agent evaluation must include an environment, not only a prompt.

ICML

CSPO

Moves safe RL from final constraint satisfaction to local recovery near the boundary. The method cares about how a policy returns to safety after pressure, not only whether its average score looks acceptable.

ICLR

Safety-Guided Flow

Builds negative guidance into generation so unsafe regions repel the sampling path. The shared concept with CSPO is controlled movement away from bad regions of a state or output space.

ICML

Protein Autoregressive Modeling

Uses multiscale structure because protein generation has hierarchy before it has coordinates. The model predicts across levels of structure, then decodes atoms.

ICLR

Quotient-Space Diffusion

Removes irrelevant rigid-motion degrees of freedom from molecular generation. Together these papers show that scientific generation improves when the sample space matches the object.

ICML

DiReCT

Selects late-training data through gradient alignment with validation-Hessian directions. Data becomes a way to steer the training trajectory through curvature.

ICLR

Common Corpus

Makes legally usable pretraining data a public infrastructure object. The connection is that data choices are not background details; they decide what learning path is possible and auditable.

ICML

Transformer Circuits Can Realize Clustering Algorithms

Shows transformer blocks can implement k-means-like assignment and update steps. It turns architecture into an algorithmic circuit.

ICLR

Softmax Transformers Are Turing-Complete

Studies the computational envelope of transformer-style models. Read together, the theory papers ask not only what transformers fit, but what procedures their components can express.

TAKEAWAY

The Field-Level Read

ICML and ICLR 2026 are not mainly arguing for one winner architecture. They are describing the engineering and mathematical conditions under which AI systems can be trusted to act: what state they see, what action space they use, what constraints they obey, what evidence checks them, what data shaped them, what compute limits them, and what theorem or diagnostic says the behavior is not accidental.
