LLM agents and process diagnostics as the new measurement problem

An agent is not a single answer. It is a sequence of observations, memories, tool calls, guesses, retries, shortcuts, and environment changes. This theme asks how to build, train, inspect, and trust that sequence.

Problem

Final accuracy hides whether the agent explored intelligently, used tools correctly, recovered from mistakes, exploited a verifier, or merely got lucky.

Approaches

The papers build agent gyms, trajectory datasets, process metrics, memory systems, tool policies, multi-agent optimizers, safety probes, and production measurement studies.

Connecting read

The common object is the trajectory. If the trajectory is not represented, normalized, inspected, and verified, agent evaluation collapses into answer grading.

FIRST PRINCIPLES

The core problem

A normal model benchmark asks: did the model return the right output? An agent benchmark has to ask a harder question: what happened between the prompt and the outcome? The agent may open a browser, run code, query a database, call a prover, update memory, ask a user, delegate to another agent, or continue acting while the world changes. Once that happens, correctness is no longer just a label attached to the final text. Correctness depends on the path.

That is why this theme is central to the conference map. The papers are not only proposing agents. They are building the instruments needed to see agents clearly: standardized trajectory formats, executable environments, process rewards, monitor scaffolds, memory benchmarks, GUI datasets, multi-agent design optimizers, and failure signatures. The field is moving from "can a model answer?" to "can a model run a reliable procedure under observation?"

SYNTHESIS

Eight ways the papers divide the problem

1. Agent environments make behavior executable

gyms and benchmarks

The first move is to stop evaluating agents in detached question-answer form. These papers put agents inside environments with state, tools, time, and verifiers. The environment exposes whether the agent can change something real: patch code, operate a GUI, search scientific tools, interact with a database, run biomedical scripts, or manage a home simulator.

ICLR 2026CyberGym
CyberGym turns cybersecurity evaluation into executable work. The agent must produce proof-of-concept tests for real vulnerabilities across many projects, so success is tied to a concrete artifact rather than a verbal description of a bug. It matters because security agents are dangerous to overestimate: sounding right about a CVE is much easier than producing a working exploit or validation path.
ICML 2026SandboxEscapeBench
SandboxEscapeBench asks whether tool-using agents can escape Docker or OCI-style container sandboxes. The paper matters because the environment itself becomes the threat surface. An agent is not only generating text; it is taking actions through tools, and those actions can test boundaries that ordinary safety prompts never exercise.
ICLR 2026Gaia2
Gaia2 evaluates agents in environments that evolve independently under temporal constraints and noisy events. This targets a basic weakness of static benchmarks: the world does not wait while the agent reasons. Gaia2 makes timing and external change part of the problem, so the measured capability is closer to operating under live conditions.
ICLR 2026AstaBench
AstaBench provides more than 2,400 scientific research problems with production-grade search tools. The important move is to make scientific agency operational: the agent has to gather evidence and work through research tasks, not merely answer science trivia. It connects agent evaluation to research workflows where search, evidence quality, and tool discipline are central.
ICLR 2026BIRD-INTERACT
BIRD-INTERACT studies database agents as interaction policies. The finding that flagship models complete only a small fraction of full-suite tasks is important because database work requires iterative clarification, memory, and query correction. The bottleneck is not SQL syntax alone; it is knowing how to interact with the database until the task is actually resolved.
ICLR 2026SimuHome
SimuHome evaluates agents in a Matter-based smart-home simulator with device APIs, environmental variables, and schedules. The task is small in physical scale but rich in temporal state. An agent has to respect time, device state, and user intent, which makes it a clean example of why stateful environments are different from isolated prompts.
ICLR 2026MedAgentGym
MedAgentGym creates a sandboxed biomedical coding environment with tens of thousands of tasks, feedback, ground truth, and trajectories. Its value is that biomedical agent work needs executable checks and controlled failure modes. A biomedical answer can be fluent yet useless unless the code, data operation, or analysis step actually runs.
ICML 2026tau2-bench
tau2-bench places the user and AI inside a shared telecom decision process where both can use tools to modify state. That makes conversation a state-changing protocol rather than a chat transcript. The benchmark matters because many service agents fail when user actions and agent actions interact, especially when either side can alter the underlying record.
ICML 2026MEnvAgent
MEnvAgent automates executable environment construction for software engineering tasks across ten languages. The first-principles need is reproducibility: a code agent cannot be evaluated fairly if its environment is missing dependencies, build rules, or verifiers. MEnvAgent treats environment construction as part of the benchmark itself.

2. GUI, browser, and computer-use agents expose real workflow failure

interactive surfaces

Computer-use agents fail in ways that text-only tasks do not reveal: misclicks, stale state, visual ambiguity, hidden app assumptions, recovery errors, and brittle performance across app variants. These papers build tasks where the agent must act through an interface and where success depends on the whole workflow.

ICLR 2026ScaleCUA
ScaleCUA builds a large open GUI-agent dataset across six operating systems and three task domains. Its importance is coverage. A GUI agent trained on one narrow environment can look competent while relying on accidental visual conventions. Cross-platform data pressures the agent to learn computer-use behavior that survives different interfaces.
ICLR 2026OpenApps
OpenApps evaluates multimodal agents across thousands of configurable app versions rather than one fixed environment. The key idea is variation. If changing labels, layouts, or app settings breaks the agent, the agent has not learned the task, only the benchmark instance. OpenApps makes robustness to interface variation measurable.
ICML 2026VenusBench-Mobile
VenusBench-Mobile evaluates mobile agents under realistic user intents and capability-oriented failure annotations. Mobile workflows compress information into small screens and app-specific interaction patterns. The paper matters because it links benchmark results to user-facing failure categories rather than only final task success.
ICML 2026RoTS
RoTS focuses on GUI policy-error recovery across executable test cases. This matters because mistakes are normal in real interfaces; the question is whether the agent can notice and recover. A benchmark that includes policy-induced errors measures resilience, not just first-try navigation.
ICML 2026MiniAppBench
MiniAppBench uses agentic exploratory testing to assess open-ended interactive artifacts without a single ground truth. That is a different evaluation shape: the agent becomes a tester, and the artifact may have many valid behaviors. The paper is important because production software often needs exploratory judgment, not fixed-answer grading.
ICML 2026Vision2Web
Vision2Web combines GUI agent verification and VLM judging across website-development tasks. It sits between generation and evaluation: the agent must build something visual and functional, then the system must judge whether the workflow produced the intended result. It exposes how hard it is to verify interface work by screenshots alone.
ICLR 2026EditBench
EditBench evaluates coding assistants under realistic surrounding context and shows that context can shift edit success materially. The first-principles point is that a code edit is not an isolated string replacement. The agent has to understand nearby files, conventions, dependencies, and the user's actual intent; otherwise a patch that looks correct in a toy setting can fail in the real repository.
ICLR 2026WebDevJudge
WebDevJudge shows automated judges diverge from human experts on feasibility, functionality, and bias in web tasks. The diagnostic point is that judging agents is itself an agent-like task with hidden assumptions. If the judge cannot recognize functional equivalence or practical feasibility, the whole training loop can optimize the wrong target.

3. Trajectories, memory, and data protocols become infrastructure

state and standardization

Once agent behavior is a trajectory, the field needs ways to store it, compare it, train from it, and reuse parts of it. These papers build the infrastructure layer: terminal trajectories, standardized formats, reusable skills, procedural memory, long-term memory updates, and mid-training data that resembles deployment.

ICLR 2026ADP
ADP converts heterogeneous agent datasets into a lightweight interlingua for supervised finetuning. Its value is normalization: browser tasks, code tasks, tool calls, observations, and final answers otherwise live in incompatible formats. ADP matters because agent training cannot scale if every gym has its own private schema for the same basic episode structure.
ICML 2026TerminalTraj
TerminalTraj curates Docker images and verified terminal trajectories across multiple domains. It makes command-line agency reproducible: the task, environment, actions, and success checks travel together. This is important because terminal work is where agents can actually change files, install dependencies, and run verifiers, but only if the environment is controlled.
ICML 2026Skill-Pro
Skill-Pro converts episodic traces into reusable executable skills with activation, execution, and termination conditions. The key idea is that experience should not remain a log. It should become procedural knowledge that can be invoked later when a similar state appears. That is a direct answer to the problem of agents relearning the same workflow every episode.
ICLR 2026MemAgent
MemAgent treats memory management as a workflow learned through multi-conversation RL. Instead of extending context length alone, it trains updates to memory state. The distinction matters because useful memory is not everything the agent has ever seen; it is the selected, maintained state that improves future decisions.
ICML 2026MemoryBench
MemoryBench finds current memory and continual-learning baselines weak in both effectiveness and efficiency. The paper is a diagnostic counterweight to memory-system enthusiasm: saving information is easy, retrieving the right information at the right time is hard. It tells us memory must be measured as an agent capability, not marketed as a storage feature.
ICML 2026daVinci-Dev
daVinci-Dev uses contextually and environmentally native software-agent trajectories for mid-training. The problem is the gap between static pretraining text and deployment behavior. Agent-native data contains files, tools, feedback, and environmental context, so it teaches the model the conditions under which software work actually happens.
ICML 2026Scientific Annotation BC
Scientific Annotation BC learns expert GUI navigation, verification, correction, and annotation strategy from trajectories. It shows that expert process can be the supervision target. In scientific workflows, the skill is not only the label but the sequence of checks and corrections that make the label trustworthy.

4. Process diagnostics catch shortcuts that final reward misses

collapse and effort

Agent training can produce behavior that passes a verifier while losing the intended reasoning process. These papers look for boilerplate traces, premature assumptions, low-effort verifier passing, stagnant uncertainty, contaminated credit, and reasoning topologies that distinguish useful thought from decorative thought.

ICML 2026RAGEN-2
RAGEN-2 appears twice in the evidence because it diagnoses both template collapse and reward-signal quality. The first issue is input-agnostic boilerplate reasoning: the model emits a familiar-looking process that is weakly tied to the actual task. The second issue is low within-input reward variance, which weakens the task gradient relative to regularization. Together, they explain why an agent can look more "reasoning-like" while becoming less task-sensitive.
ICLR 2026TRACE Effort
TRACE Effort flags cases where high reward appears before enough reasoning is present to solve the intended task. The key failure mode is shortcut success: the verifier gives credit for a path that should not have enough evidence. This matters for process supervision because reward alone cannot tell whether the agent solved the problem or found a shallow way to satisfy the checker.
ICLR 2026LLMs Get Lost
LLMs Get Lost finds that models commit too early to assumptions and fail to recover after wrong conversational turns. The important diagnostic is path dependence. A bad early belief can shape every later action, so a final wrong answer is only the symptom. The underlying failure is weak belief revision during interaction.
ICML 2026T2PO
T2PO triggers reasoning interventions when marginal uncertainty change falls below a threshold. It treats stuck reasoning as a measurable state: if thinking no longer changes uncertainty, the agent needs an intervention rather than more of the same tokens. This connects process diagnostics to adaptive control.
ICLR 2026T3
T3 tracks excessive belief deviation and truncates uninformative trajectory tails during RL training. In this theme, its value is diagnostic: it asks which parts of a trajectory are still informative and which parts are drift. Long trajectories are not automatically better; they need evidence that the agent's beliefs are moving in a useful direction.
ICML 2026Hierarchical Thinking
Hierarchical Thinking models chain-of-thought as transitions among latent cognitive states. The useful point is that reasoning traces can have topology. Successful chains may move through states differently from failed chains, so process quality can be inspected structurally rather than judged only by length or final answer.
ICML 2026Complex Reasoning/TRM
Complex Reasoning/TRM represents reasoning traces as DAGs and evaluates macro and micro efficiency through pairwise preferences. This turns a trace into a graph of dependencies instead of a linear monologue. The paper matters because many hard tasks involve branching, merging, and reuse of intermediate results, which a plain token sequence hides.
ICML 2026POPGym Arcade
POPGym Arcade finds that value-function memory contamination can smear credit over irrelevant history and perturb policies far into the future. The agent-learning lesson is that memory is not neutral context. If irrelevant past state leaks into value estimates, the policy can be shaped by ghosts of old episodes instead of the current task.

5. Tool policies and modular workflows become optimizable systems

planner executor verifier

An agent system is often a compound machine: planner, executor, verifier, retriever, memory, judge, and generator. These papers optimize the architecture around the model, not just the model. The central question is which module should act, what evidence should flow between modules, and what objective should guide the workflow.

ICLR 2026AgentFlow
AgentFlow coordinates planner, executor, verifier, and generator modules through evolving memory during live tool use. It makes the agent workflow explicit. That matters because many agent failures are coordination failures: the planner loses the verifier's evidence, the executor acts on stale assumptions, or memory does not carry the right state forward.
ICLR 2026GEPA
GEPA learns high-level rules from reasoning, tool calls, and tool outputs across system trajectories. The paper treats prompt optimization as learning from the whole compound system, not from isolated examples. It is important because production agents often improve through rules extracted from failures: when this tool returns this kind of result, revise the plan this way.
ICML 2026ParetoPO
ParetoPO optimizes tool-integrated agents across accuracy and tool-use efficiency. The first-principles tradeoff is simple: tools help, but unnecessary tool calls add cost and latency. Pareto-ranking makes the tradeoff explicit instead of collapsing everything into a single reward that may hide waste.
ICLR 2026Speculative Actions
Speculative Actions studies latency as a bottleneck for agentic serving across gaming, e-commerce, search, and operating-system environments. It matters because agents are interactive systems. A model that eventually chooses the right action may still be unusable if every step waits on slow serial deliberation.
ICML 2026JitRL
JitRL retrieves trajectory memory to estimate advantages and modulate logits at test time. The method is gradient-free at deployment, which makes it a form of just-in-time policy adaptation. It matters because some agent improvements may come from using recent experience to steer action without retraining the whole model.
ICLR 2026THOR
THOR uses immediate tool feedback to revise reasoning paths during inference. In this diagnostics theme, the key point is the feedback loop: the agent does not merely call a tool, it observes whether the tool-supported step worked and updates the path. That is the difference between tool decoration and tool-grounded reasoning.
ICML 2026DR Tulu
DR Tulu co-evolves rubrics with the policy for deep-research RL. This is important because a fixed rubric may not cover information discovered during search. The paper makes evaluation part of the workflow: as the agent explores, the rubric must become more sensitive to the evidence and contrasts that emerge.
ICML 2026CE-Graph
CE-Graph models workflows as distributions over failure signatures and minimizes expected failure mass. Instead of optimizing a workflow by anecdote, it asks what kinds of failures the workflow tends to produce. That framing is useful for production systems because debugging becomes a distribution-shaping problem.

6. Multi-agent systems need structure, uncertainty, and payoff discipline

coordination

When more than one agent is involved, the process problem becomes a coordination problem. The system must decide who does what, how agents communicate, whether debate has collapsed, whether preferences predict payoffs, and how to train agents that must cooperate with unknown partners.

ICML 2026OMAC
OMAC optimizes multi-agent systems across agent functionality and collaboration-structure dimensions. The key insight is that adding agents is not automatically useful. The roles and communication pattern have to match the task, otherwise the system becomes a noisy committee rather than a division of labor.
ICML 2026MASPOB
MASPOB uses UCB bandits, GNN topology priors, and coordinate ascent to optimize prompts in fixed multi-agent workflows. It treats the multi-agent prompt problem as topology-aware search. That matters because prompt quality depends not only on an individual agent's instruction but on where that agent sits in the workflow graph.
ICML 2026LatentMAS
LatentMAS lets agents exchange last-layer hidden thoughts through shared latent working memory. It asks whether collaboration needs to be textual. If agents can pass compressed internal state, they may coordinate without forcing every intermediate belief into natural language, though that also makes diagnostics harder.
ICML 2026DLM
DLM uses supervised finetuning plus GRPO to improve robustness and zero-shot generalization in multi-agent decisions. It sits on the training side of coordination: rather than hand-designing all interaction, the policy is trained to operate under centralized-training and decentralized-execution constraints.
ICML 2026Unsupervised Partner Design
Unsupervised Partner Design generates training partners on the fly and selects them by learnability for ad-hoc teamwork. The problem is partner overfitting. If an agent only trains with familiar teammates, it may fail with new ones. Adaptive partner curricula make robustness a property of the training population.
ICML 2026Value of Variance
Value of Variance measures intra-agent, inter-agent, and system-level uncertainty to diagnose debate collapse. A debate can look active while all agents converge too early or recycle the same weak evidence. Variance becomes a signal for whether the system is still exploring distinct possibilities.
ICML 2026What Preferences Can and Cannot Predict
What Preferences Can and Cannot Predict introduces leaklessness as a payoff-based condition for stability beyond ordinal preference graphs. The paper matters here because multi-agent systems are governed by incentives, not just language. Preference orderings may fail to predict behavior when payoff information leaks or shifts.

7. Safety and oversight are trajectory problems

monitoring and attacks

Agent safety cannot be checked only at the initial prompt or final answer. Attacks can arrive from the environment, unfold over many turns, or exploit the agent's context optimization. Oversight also becomes a process: monitors need compute, follow-up questions, escalation policies, and awareness that weaker systems may be supervising stronger ones.

ICLR 2026RedTeamCUA
RedTeamCUA reports high attack success when malicious content is embedded in GUI environments. This matters because computer-use agents read the world as instruction-like input. A malicious page, label, or interface element can become part of the agent's context and steer actions from inside the environment.
ICLR 2026PLAGUE
PLAGUE shows that multi-turn attack planning can achieve high attack success with comparable or lower query budgets. The important point is temporal: attacks can optimize over conversation state. A defense that only filters one prompt at a time misses the fact that the adversary is also planning.
ICML 2026Monitoring Monitorability
Monitoring Monitorability studies how monitor test-time compute and follow-up chains of thought improve oversight of stronger agents. It treats monitoring as an active reasoning problem. The monitor may need to spend its own compute to inspect a trajectory, ask follow-up questions, and detect failures that are not obvious from the final answer.
ICLR 2026Weak-to-Strong Monitoring
Weak-to-Strong Monitoring combines hierarchical and sequential monitors so weaker systems can supervise stronger agents with targeted human escalation. The paper matters because practical oversight will often be asymmetric: the thing being monitored may be more capable than the monitor. The design problem is how to route suspicion, not how to assume perfect supervision.
ICML 2026MAP
MAP studies deployed agents through case studies and practitioner interviews. Its role is grounding: it documents how agents are actually built and evaluated in production. This matters because academic agent benchmarks can miss the mundane but decisive constraints of deployed systems, such as handoffs, observability, user trust, and operational failure review.

8. Domain agents show why one generic metric is not enough

specialized workflows

The remaining papers show agents moving into scientific, visual, emotional, CAD, retrieval, table, proving, ranking, and reduction-discovery workflows. Each domain changes what counts as evidence and what counts as a valid action. The lesson is that "agent capability" is not one scalar; it is the fit between process, tools, representation, and domain verifier.

ICML 2026PhotoAgent
PhotoAgent uses tree search, memory, visual feedback, and learned aesthetic rewards for multi-step photo editing. The domain matters because success is partly perceptual and partly preference-based. The agent must evaluate visual changes over time, not just produce one instruction.
ICML 2026PaperBanana
PaperBanana orchestrates specialized vision-language and image-generation agents to create research diagrams. Its process is closer to a production pipeline than a single model call: understand the paper idea, design a diagram, render it, and refine it. The paper shows how agent decomposition can target creative scholarly work.
ICML 2026FutureCAD
FutureCAD generates executable CadQuery scripts and uses natural-language B-Rep primitive selection for CAD operations. It matters because geometry punishes vague language. The agent has to produce a program that creates a valid object, so spatial intent must be converted into executable construction steps.
ICML 2026WZ-LLM
WZ-LLM converts Wilf-Zeilberger proof plans into Lean sketches that constrain LLM proof search. This is agentic formal reasoning with domain structure: the LLM is not wandering freely through proof space, it is guided by a known mathematical method and checked by a proof assistant.
ICML 2026Bitween
Bitween uses LLM agents to propose query functions for randomized self-reductions beyond fixed symbolic templates. The paper matters because discovery tasks often require inventing the right transformation, not just applying a known rule. It uses agents to search over reductions that may reveal hidden structure.
ICML 2026CausalGame
CausalGame tests frontier agents in games with confounding, selection bias, and noisy measurements, and finds consistent failure. The diagnostic lesson is that interactive data collection does not automatically produce causal reasoning. The agent must choose interventions and interpret evidence under bias, which current systems still struggle to do.
ICML 2026ADEPT
ADEPT turns speech emotion recognition into candidate generation, tool evidence collection, and adjudication. It treats affective inference as an evidence-gated process rather than a direct label. That matters because emotion is noisy and contextual; the agent has to gather and weigh evidence before deciding.
ICML 2026WETR
WETR treats emotion as a latent state inferred from noisy observations and constrains token contribution to that inference. It is a small but important process-control idea: not every token should have equal influence on a hidden state. The agent should route evidence according to what actually informs the latent variable.
ICML 2026TG-RAG
TG-RAG converts domain procedures into Expert Procedure Graphs and injects step-specific guidance during generation. It shows that retrieval is not only about facts. In procedural domains, the agent also needs the right step in the right order, and a graph of procedures can constrain that process.
ICLR 2026MC-Search
MC-Search provides verified stepwise chains with subquestions, retrieval modalities, evidence, and intermediate answers for multimodal RAG. Its value is that retrieval-augmented agents need traceable evidence, not just a final citation. The benchmark makes intermediate retrieval and reasoning steps visible.
ICML 2026MADQA
MADQA measures whether document agents navigate collections strategically or compensate with brute-force search loops. The key metric is accuracy-effort tradeoff. A document agent that reads everything may succeed but fail as an agent because it has no efficient search policy.
ICML 2026BlitzRank
BlitzRank matches or exceeds LLM reranking quality with fewer tokens. It belongs here because ranking is an agent subroutine in search-heavy systems. If retrieval and reranking consume too many tokens, the agent's broader reasoning budget collapses.
ICML 2026DiSCo/Table-GLS
DiSCo/Table-GLS guides multimodal table reasoning through structured exploration and evidence-grounded inference without external tools. Tables demand a global-to-local process: understand the whole structure, then inspect the cells that matter. The paper shows why evidence routing is domain-specific.
ICLR 2026MomaGraph
MomaGraph forces task-specific scene graph construction before planning. The value is an intermediate planning artifact: before acting in a scene, the model builds a structured representation of objects and relations. That graph makes planning less dependent on raw visual context alone.
ICML 2026Latent Action Supervision
Latent Action Supervision finds that different latent action formulations help different tasks: image-based latents support long-horizon reasoning, while action-based latents help motor coordination. The lesson is that the representation of action must match the task's structure. There is no universal latent action format.
ICML 2026DLMR
DLMR keeps base multimodal models frozen while learning interpretable memory routing that preserves grounding and reduces long-generation tokens. It is a practical agent-design paper: instead of making the base model larger, route memory according to state so the model sees what it needs without drowning in context.
ICML 2026Faire
Faire shows that supervised finetuning on interleaved plot-solution data can degrade reasoning when visual actions are only superficially imitated. The warning is important: adding action-looking traces is not enough. If the model copies the form of visual work without the underlying state change, process supervision can make behavior worse.
ICML 2026PIPE
PIPE uses counterbalanced aliases to quantify preference for training-time environment forms. It measures interface reliance: whether an agent has learned a task or merely learned the appearance of the environment it saw during training. That matters for agents that will face new wrappers around old capabilities.
ICLR 2026Huxley-Goedel Machine
Huxley-Goedel Machine searches self-modification trees using estimated descendant performance rather than current benchmark score alone. The paper pushes agent improvement into metaproductivity: choose changes that may create better future agents, not only immediate score gains. That makes the evaluation horizon longer and harder.
ICLR 2026AgentGym-RL
AgentGym-RL provides modular reinforcement-learning infrastructure for long-horizon agent training across environments. Its importance is less a single benchmark than a training substrate. If agent research is going to compare methods, it needs shared infrastructure for environments, rollouts, rewards, and policy updates.
ICLR 2026Rational Agents
Rational Agents benchmarks exploration and action tradeoffs in Collaborative Battleship and Guess Who? against human behavior. It treats dialogue as resource-rational decision making: ask when information is worth the cost, act when uncertainty is low enough. This connects agent diagnostics to information economics rather than only task accuracy.
FIELD READ

What this theme says about the conference

The conference picture is clear: agents have forced evaluation to become procedural. The important artifacts are no longer just prompts and answers. They are environments, state transitions, memory writes, tool-call traces, verifier outcomes, monitor decisions, and failure signatures.

This is also why ADP-like normalization matters. Browser gyms, code gyms, terminal gyms, biomedical gyms, database agents, GUI agents, and research agents all expose the same skeletal structure: task, observation, action, state change, feedback, and verifier. The field is trying to make that skeleton explicit enough that agents can be trained, compared, audited, and improved across domains.
