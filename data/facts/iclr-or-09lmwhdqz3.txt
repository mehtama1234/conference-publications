REAL METHOD of CRAMF (from the paper's Method section — use THIS, not the abstract's vague summary):

THE TASK: turn an informal math statement written in English into formal, machine-checkable code in Lean 4. Lean is a "proof assistant" — a program that only accepts a proof if every step is spelled out in its exact formal language. Mathlib is Lean's huge standard library of math that has already been formalized. The trouble: when a language model writes the Lean code, it often INVENTS definitions that do not actually exist in Mathlib, so the code will not compile; it also misuses symbols and uses out-of-date definitions.
THE HARDER PROBLEM ("conceptual polymorphism"): the same English phrase can map to SEVERAL different formal definitions depending on the area of math — so just finding "a" definition is not enough; you must pick the RIGHT one for the context.

CRAMF's ACTUAL THREE STEPS:
1) BUILD A LOOKUP BOOK AHEAD OF TIME (the real novelty — no such map existed before). Scan every definition in Mathlib (over 26,000 of them) using Lean's official documentation tool (it pulls out everything declared as a def, class, or structure). For each FORMAL definition, have a language model write plain-English descriptions of what it means — this is "back-translation." To keep quality high, generate three candidate descriptions and keep the one that best matches. The result is a structured book that maps: English concept  ->  the exact formal Mathlib definition(s). One concept can point to several definitions (that is the polymorphism, captured on purpose).
2) PULL OUT THE CONCEPTS (Mathematical Concept Extraction). When a new theorem arrives, first read it and extract the core mathematical concepts inside it — the specific things that will need formal definitions.
3) LOOK EACH CONCEPT UP, WITH CONTEXT (Dual-Pathway Hybrid Retrieval + reranking). For each extracted concept, search the lookup book two ways at once: by MEANING (turn the concept into a list of numbers that captures its meaning and find close matches) and by KEYWORDS/symbols. CRUCIALLY, before searching, ADD CONTEXT CLUES to the query — which area of math, which application — so that when a concept has several possible definitions, the search can pick the right one. A reranking step then puts the single best definition on top. Those real formal definitions are handed to the language model as grounding, so it writes Lean code using definitions that actually exist in Mathlib instead of making them up.

MEASURED: CRAMF is a plug-in for existing autoformalizers and consistently raises translation accuracy on the miniF2F, ProofNet, and their new AdvancedMath test sets. The point is fewer hallucinated / non-existent definitions and correct disambiguation.
