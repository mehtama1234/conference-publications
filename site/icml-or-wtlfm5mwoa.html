Cure-SFT: Diagnostic-Guided Data Curation for Instruction Tuning

Pick and fix the right training data instead of using all of it, and the model learns better with just ten percent.

Paper explainersAll themesLLMs & Foundation Models

When you teach a language model to follow instructions, you feed it thousands of examples of instruction-answer pairs. But most datasets are bloated: they have copies of the same idea, examples with mistakes, and data that teaches nothing new. Cure-SFT is a method that picks the 10% of examples that matter most, fixes the broken ones, and ditches the rest — so your model learns better and faster, because each remaining example provides a clear, non-repetitive signal to learn from.

The dataset bloat trap

Today's language models are taught via instruction tuning: you feed the model millions of (instruction, answer) pairs and it learns to follow the pattern. But in practice, datasets are a mess. Many examples teach the same thing — 'write a poem about winter' repeated 500 ways. Some examples are broken: wrong answers, garbled text, or instructions that make no sense. A naive approach throws everything at the model and hopes it learns, but that wastes compute and confuses the learner.

A beginner might try to fix this by randomly deleting examples to shrink the dataset. That doesn't work because you lose both good and bad data equally. Or they might score examples on quality alone and discard low-scorers — but that misses the core issue: redundancy and defects are different problems that need different fixes.

The method in one sentence. Find duplicate-ish examples and remove them, find broken examples and fix them, then train on what's left.

The algorithm as a flow

What it actually does

Step 1: Group by meaning

Map each example into a high-dimensional space and cluster: find groups of semantically similar instructions.

Step 2: Stratified sample

From each cluster, pick one representative example; discard the semantic duplicates.

Step 3: Grade with a teacher

A trained teacher model scores each remaining example on quality and fixability.

Step 4: Remediate fixable defects

For examples rated as fixable, use the teacher to rewrite the broken parts (e.g., correct wrong answers).

Step 5: Train on the curated set

Train the student model on only the surviving, cleaned examples.

What the paper changes

What the paper changes

Cure-SFT changes the dataset itself: it removes redundant examples and fixes defective ones before training begins. The model's structure stays the same; only the training data is curated and repaired.

The hidden quantity

The hidden quantity: data redundancy score

measured quantity  =  semantic redundancy

Every instruction in the dataset has a hidden redundancy score: how much of this example's meaning is already covered by other examples in the set. If ten examples say 'write a poem about winter' in different words, the ninth and tenth have high redundancy — they teach the model nothing new, just repetition. The method estimates this by embedding each example (converting it into a list of numbers capturing its meaning) and finding clusters. Examples in the center of a dense cluster are redundant; examples on the edge are unique.

The paper measures redundancy geometrically: how close is this example to its nearest neighbors in the embedding space. Close neighbors mean similar meaning, so close examples are redundant. The method keeps one example per cluster and discards the rest.

Why it works

Why it works: the two-phase fix

Cure-SFT works because it separates two distinct problems. Redundancy and defects require opposite treatments: redundancy demands deletion (keep one copy, discard the rest), while defects demand repair (fix the answer, keep it). A method that treats both as 'low quality' will delete fixable examples and might keep unfixable trash, because both look like low-quality data.

The mechanism: first, remove redundancy via stratified sampling. By clustering examples in meaning-space and keeping one per cluster, the method ensures every remaining example teaches something new. This instantly shrinks the dataset and removes noise from repetition. Then, grade each survivor for fixability: a teacher model judges whether the defect is real but repairable (wrong answer + correct format) or inherent (malformed text, nonsense instruction). For fixable examples, rewrite the broken parts; for inherent defects, discard. The result is a lean, non-redundant, low-defect dataset. When the student model trains on this curated set, it receives clearer signals: every example is new, defects are fixed, and there is no noise from repetition.

The redundancy removal equation

First in words:

for each cluster of nearby examples, keep one and discard the rest; the kept example is the one closest to the cluster center

Then the compact form:

S_curated = select(C_i, argmin_j || x_j - mu_i ||) for all clusters i, where x_j in C_i

Every symbol:

S_curatedthe final curated dataset
C_icluster i of semantically similar examples
x_jthe embedding (meaning vector) of example j
mu_ithe center point of cluster i
|| x_j - mu_i ||the distance from example j to the cluster center
A tiny worked example
Cluster 1: three examples about winter poetry. Embeddings (simplified): example A = [0.8, 0.2], example B = [0.81, 0.19], example C = [0.3, 0.7]. Cluster center = [0.60, 0.37].
Distances to center: A to center = sqrt((0.8-0.60)^2 + (0.2-0.37)^2) = sqrt(0.04 + 0.0289) = 0.23. B = 0.24. C = 0.42.
A is closest, so keep A; discard B and C. Result: one strong example per cluster, no redundant copies.

The clustering is based on meaning-vectors (embeddings) rather than exact text match, so it catches paraphrases and variants that random deletion would miss.

What can go wrong

What can go wrong

Aggressive clustering removes real diversity. If clusters are too coarse, the method discards legitimately different examples and the model underfits. The fix: tune the cluster granularity (sensitivity of the semantic grouping) on a held-out validation set.
Teacher model is biased or weak. If the teacher model is poor at grading defects, it will mark fixable examples as irreparable and discard them. The method is only as good as the teacher. A better teacher (e.g., a larger model or human-annotated gold labels) improves results, because a more accurate grader filters correctly and preserves more high-quality examples.
Defect repair hallucination. When the teacher rewrites a defective example, it might hallucinate (invent incorrect details) if not careful. Verification by a second model or human spot-check is wise for high-stakes applications.
Done right: validation on held-out data. Always evaluate the curated dataset on a separate validation set before training the student model, and compare against full-dataset baselines to ensure the savings are real.
What a runnable demo should prove

What a runnable demo should prove

A demo should show the two phases working: first, generate embeddings for 1000 instruction examples (use a pretrained embedding model like Sentence-BERT). Cluster them by cosine distance (pair-wise meaning similarity). Show that clustering removes 30-40% as semantic duplicates. Then, manually label 50 examples for quality: broken answer (defect), garbled text (defect), good (keep), or uncertain (fixable). Train a small scorer model on these 50 labels. Apply it to the remaining examples. Show that the scorer identifies defects with 70-80% accuracy on a held-out test set. Finally, train two models: one on all 1000 examples, one on the 600 curated examples. Compare accuracy on an instruction-following task. The curated model should reach the baseline in 1-2 epochs; the full model should need 3-4.

improvement = (accuracy_curated - accuracy_full) / accuracy_full * 100; efficiency = (epochs_full / epochs_curated) - 1

The demo makes undeniable: same or better accuracy, one-tenth the data, faster training. Redundancy removal and defect repair are real and measurable, because the curated model trains faster due to fewer examples and cleaner signals, and achieves higher accuracy because those remaining examples are all valuable.
