PhysForge: Generating Physics-Grounded 3D Assets

To make realistic interactive 3D objects for games and robots, plan the blueprint with language first, then build the shape and movement rules together.

Paper explainersAll themesGenerative Models & Diffusion

Making interactive 3D objects for virtual worlds is hard because most tools focus only on appearance (shape and texture), ignoring how the objects actually move and behave. PhysForge does two separate jobs: first, a language model (one that understands English and the physical world) sketches a blueprint that describes which parts move, how they connect, and what materials they are made of. Second, a diffusion model (a tool that gradually refines random noise into realistic objects) builds the shape while respecting those physics constraints.

Zero assumption version

Making objects that both look real and work right

Today's 3D generators learn to copy the appearance of objects from pictures: the bumps and dents, the colors, the lighting. But a virtual fork is useless if it does not bend at the handle, a door is useless if it does not swing, and a robot gripper is useless if its joints do not match the physics of the real world.

A beginner might try to build the shape first, then add physics afterward. This fails because shape and physics are tangled: a handle's thickness, a joint's placement, the connection between parts all depend on what the object is supposed to do. By the time you try to add physics rules to a finished shape, it is often too late to fix.

The core problem in one sentence. Existing 3D generators ignore functional properties (how things move and interact), so they produce objects that look good but do not actually work.

What the paper changes

What the paper changes

Instead of treating shape and physics as separate, PhysForge generates them together, guided by a blueprint. The key move is encoding movement rules (which direction a joint rotates, where the pivot sits, how far it can move) as a parallel set of 3D pixel blocks, called kinematic voxels, that the diffusion model builds at the same time as the shape.

The hidden quantity

The hidden quantity: Kinematic plausibility

measured quantity  =  Kinematic plausibility

Kinematic plausibility is a score measuring whether the generated parts actually move in ways that make physical sense. It combines three checks: (1) Do the joint axes point in the right directions? (2) Are the pivot points at sensible locations? (3) Do the joint limits (how far each part can rotate or slide) stay within realistic ranges?

The paper measures this by comparing the generated joint parameters against ground-truth data from a labeled database of real interactive objects. When the generated pivot point is within a few millimeters of the true pivot, or the axis angle is within 5 degrees, that counts as plausible. By training with this signal, the diffusion model learns to favor part layouts that lead to realistic joints.

Why it works

Why planning then generating works

The core principle is that shape and physics are deeply coupled, but they can be coordinated through a shared blueprint. When a language model reads a picture and names the parts (faucet body, handle, spout), it also knows roughly where each part should go and how it should move. This knowledge is condensed into a blueprint: bounding boxes for each part's location, plus the joint type and limits.

The diffusion model then faces an easier problem: instead of inventing part boundaries from scratch, it uses the blueprint as a roadmap. It jointly refines two parallel streams: shape voxels (what the object looks like) and kinematic voxels (how the joints move). By entangling them during denoising, the model cannot create a shape that violates the physics, because the kinematic parameters are literally baked into the same representation being refined. It is like sculpting a door and the hinge together, so you never accidentally put the hinge in a place the shape cannot support.

The four-tier physical annotations (material, function, kinematic constraints, and part hierarchy) give the training process a richer signal. Instead of just learning to copy shapes, the model learns to reason about which properties belong together: metal handles bend differently than plastic ones, and that changes the joint shape.

The joint loss function

First in words:

Total loss equals shape loss plus kinematic loss, weighted equally

Then the compact form:

L_total = L_shape + L_kine

Every symbol:

L_shapeL2 loss between predicted and true shape voxels
L_kineL2 loss between predicted and true kinematic voxels
Shape voxelA 3D grid block representing a piece of the object
Kinematic voxelA 3D grid block encoding joint origin, axis, and rotation limits
A tiny worked example
Imagine a simple joint with true pivot at (1.0, 2.0, 3.0) and predicted at (1.1, 2.0, 3.0).
Pivot error: sqrt((1.1-1.0)^2 + (2.0-2.0)^2 + (3.0-3.0)^2) = sqrt(0.01) = 0.1 millimeter.
If this joint contributes 10% of the kinematic loss, then L_kine grows by 0.01.
All parts sum to a total L_kine. If L_shape = 0.05 and L_kine = 0.03, then L_total = 0.08.
Training nudges the model weights to shrink both terms. Shape improves, kinematics stay true.

The loss treats shape and kinematics as equally important, forcing the model to get both right or training does not converge.

What can go wrong

What can go wrong

Blueprint is wrong or ambiguous. If the language model misunderstands the input (misnames a part or gets joint types wrong), the blueprint passes that error downstream. Garbage in, garbage out.
Diffusion ignores kinematic constraints. If the training does not weight L_kine heavily enough, the diffusion model can still degrade kinematic accuracy to boost shape appearance, because the model chooses the path of least resistance: whenever two goals conflict, it pursues whichever one has a steeper penalty pull. Balance is fragile.
New categories with no training examples. If the input object class is absent from the training data, the model may guess plausible but wrong kinematic parameters, because it has no learned association.
Done right. When the blueprint is correct and the two loss terms are balanced, diffusion naturally learns to generate both realistic shapes and physically sound kinematics together.
What a runnable demo should prove

What a runnable demo should prove

Build a small dataset of 100-200 interactive objects (kitchen tools, furniture with drawers, robot grippers) with ground-truth kinematic labels (joint axes, pivot points, rotation limits). Train the diffusion model on half, test on the other half. Generate new objects from images, then measure: (1) Shape appearance quality (how well the object looks like the input image) via a distance metric. (2) Kinematic accuracy (how close the predicted pivot is to the true pivot, how close the predicted axis is to the true axis). (3) Physics plausibility (drop the generated object into a physics simulator and check that it does not explode, sink, or lock up).

Kinematic accuracy = (1 - mean joint-pivot error meters / object scale) * 100 percent; joint-axis accuracy = (1 - mean axis angle error degrees / 90) * 100 percent

The demo must show that the same diffusion model produces objects with both high shape quality and high kinematic accuracy, proving that joint training works better than separate pipelines, because training on a combined loss forces the model to learn representations where shape details and movement constraints reinforce each other instead of competing.
