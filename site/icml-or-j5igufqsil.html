Uncertainty-Guided Exploration in Robotic Manipulation

A learning system that uses uncertainty from an ensemble of learned world models to decide when to explore and when to exploit, solving the problem of robots acting in unfamiliar situations with sparse reward signals.

Paper explainersAll themesRobotics & Control

Robots learning to manipulate objects from a few human examples face a hard problem: their learned models of the world make confident but wrong predictions in situations they have never seen before. This leads to bad policy decisions and wasted attempts. QUEST solves this by using multiple independent models to measure uncertainty and adaptively switch between exploration (trying new things) and exploitation (using what works), while also focusing learning on learning from rare successful transitions in multi-step tasks.

Zero assumption version

Why robots fail when learning from a few examples

When a robot learns to manipulate objects, it builds an internal model of physics: if I push here, the object moves that way. But it only sees examples from the human demonstrations, so its model is trained on a narrow set of situations. Inevitably, during learning, the robot tries actions that lead to states it has never encountered before (states outside what it learned from).

At these unfamiliar states, the model's predictions become unreliable, but the model has no way to say so. It confidently predicts the outcome, and the robot acts on that false confidence, leading to poor policy decisions. In multi-step tasks (like stacking blocks: grasp, move, place), the robot must also learn a reward function that signals success. But as the policy learns, the set of states it encounters shifts—it tries new things, so it visits different situations. The reward function must also adapt. This creates a moving target: the policy chases a reward signal that keeps changing, introducing instability into learning.

A naive approach trains a single world model and trusts its predictions everywhere, leading to catastrophic failures when the model is uncertain.

The core move: Build multiple independent world models and use disagreement between them to measure uncertainty, then use that uncertainty to intelligently switch between exploring new actions and exploiting actions the robot already trusts.

The algorithm as a flow

What it actually does

Train an ensemble of world models

Learn multiple independent models of robot dynamics from demonstrations, each slightly different.

Measure disagreement as uncertainty

At each state, check how much the models disagree on the outcome; high disagreement means the state is unfamiliar.

Drive exploration with intrinsic rewards

When uncertainty is high, give the robot a bonus reward for trying actions in those uncertain regions.

Plan with uncertainty guidance

When planning a sequence of actions, favor sequences that pass through low-uncertainty (trusted) states.

Focus learning on rare successful transitions

In multi-step tasks, weight learning more heavily on rare transitions that led to success, stabilizing the reward signal.

What the paper changes

What changes: planning and action selection

The paper modifies how the robot decides where to explore and which actions to execute. Instead of treating all states the same, it now focuses on uncertain states for exploration and low-uncertainty states for exploitation. In multi-step tasks, it also re-weights which state transitions the robot learns from, emphasizing the rare successful ones.

The hidden quantity

Model disagreement as a measure of confidence

measured quantity  =  Ensemble disagreement (uncertainty measure)

The hidden quantity is how much the models in the ensemble disagree with each other at a given state. At any state, each model predicts what will happen next. If all models predict the same thing, disagreement is low and the robot trusts the prediction. If the models predict different outcomes, disagreement is high, signaling that the state is unfamiliar and the robot should be cautious or explore.

The paper estimates disagreement by training multiple models independently on the same demonstration data but with different random initializations and minibatch orderings. At any state, it computes the variance or spread of predictions across the ensemble: high variance means high disagreement, low variance means consensus.

Why it works

Why ensemble disagreement stabilizes robot learning

When a robot learns from a few examples, it only sees a small slice of the full world. The learned model works well for states it has seen but produces garbage predictions for new states. A naive robot trusts the garbage and makes bad decisions. QUEST solves this by training many models in parallel. If they all saw the same narrow slice of examples, they would each produce garbage in the same way. But by training them independently with different random choices, each model overfits in a slightly different direction. At a familiar state (one it has seen), all models converge on the right answer, so disagreement is low. At an unfamiliar state (one it has never seen), the models diverge wildly because each one is hallucinating confidently but differently.

QUEST uses this disagreement as an automatic alarm bell. When disagreement is high, the robot actively explores that region to collect more data and shrink the disagreement. When disagreement is low, the robot can trust its models and exploit the learned policy. This adaptive switching prevents the robot from acting on false confidence in unfamiliar situations. In multi-step tasks, QUEST adds a second trick: it upweights learning on rare but successful transitions (e.g., the moment the block actually lands in the tower). This stabilizes the reward function, because the robot no longer chases a moving target—it focuses learning on the signal that matters.

Math after the picture

Uncertainty-driven exploration and planning

First in words:

The intrinsic reward bonus is proportional to the disagreement (variance) of model predictions. The planning objective balances task reward against the cost of moving through high-disagreement (uncertain) states.

Then the compact form:

R_intrinsic = beta * Var(M_ensemble(s)) ; Trajectory_cost = sum_t [- R_task(s_t) - gamma * Var(M_ensemble(s_t))]

Every symbol:

R_intrinsicbonus reward for exploring uncertain states
betahow much the robot values exploration of uncertain regions
Var(M_ensemble(s))variance (disagreement) of predictions across ensemble models at state s
R_task(s_t)task reward at time step t (e.g., block on tower or not)
gammahow much the robot prefers to plan through low-uncertainty states
s_tthe state at time step t
A tiny worked example
State A (in-distribution, seen in demos): model disagreement = 0.2; intrinsic bonus = 0.8 * 0.2 = 0.16
State B (out-of-distribution, new): model disagreement = 1.8; intrinsic bonus = 0.8 * 1.8 = 1.44
State B gets 9x higher exploration bonus, so the robot is drawn to explore it and collect data there.
When planning a 3-step sequence: prefer paths through states with low disagreement, avoiding paths through high disagreement.

The bonus reward pulls exploration toward uncertain states, while the planning term steers the policy toward predictable ones, creating a balanced strategy.

What can go wrong

What can go wrong

Too much exploration with high beta. If the exploration bonus is too large, the robot explores everywhere but never finishes the task. The bonus must be calibrated so exploration is useful but not overwhelming.
Ensemble models converge to the same wrong answer. If all models see the same biased data and train in similar ways, they may all make the same wrong prediction, and disagreement stays zero even out-of-distribution. Diversity in model training (different random seeds, data subsets) is critical.
Rare successful transitions are too rare. In very sparse-reward settings, the robot may never generate enough successes to upweight learning. If a task is nearly impossible from random exploration, initial demonstrations must contain enough successful examples to seed at least a few successful rollouts.
Done right: uncertainty calibrated and models diverse. When ensemble members are trained independently and disagreement is used judiciously, the robot explores efficiently and learns stable policies even from scarce demonstrations.
What a runnable demo should prove

What a runnable demo should prove

Build a simple 2D simulated block-pushing task (start at one corner, push block to target, sparse reward only when block reaches goal). Train the robot on two human demonstrations. Run three learning agents: (1) single model baseline, (2) ensemble without disagreement guidance, (3) QUEST with disagreement-guided exploration. Track success rate over 500 training steps, and plot disagreement heatmaps over the 2D space to show where the robot is exploring.

Success_rate = (number of final blocks at goal) / (number of rollouts) ; Disagreement_coverage = (fraction of state space visited during high-uncertainty exploration) / (total reachable space)

QUEST should show notably faster learning and higher eventual success rate because the focused exploration in uncertain regions lets the robot collect good data quickly, while the stable reward learning prevents the moving-target problem, so the policy converges instead of chasing a shifting goal.
