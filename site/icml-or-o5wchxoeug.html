TiMi: Empower Time Series Transformers with Multimodal Mixture of Experts

A time series model learns from both numbers and text by using a mixture-of-experts router to decide which expert handles each time step, guided by an LLM reasoning about future events.

Paper explainersAll themesTime Series & Sequential

When forecasting stock prices or weather, you have two very different kinds of information: a stream of numbers (daily prices, temperature readings) and text (news reports, policy announcements). Naively feeding both into the same model often fails because the model does not know how to weight text against numbers, and the two kinds of information have different patterns and scales. This paper proposes TiMi, which uses a lightweight router to dispatch each time step to the expert that best handles it (one expert for number-heavy trends, another for text-driven shocks), while a language model reasons about future events to steer the forecast.

Zero assumption version

Why mixing numbers and text breaks naive models

Consider forecasting tomorrow's stock price. You have daily closing prices for the last year (a number stream) and headlines that mention the company (text). A beginner might concatenate them into one big input and train a single transformer (a neural network that reads sequences) to predict the next price.

But this breaks in a fundamental way: the network must learn, without being told, that 'Emergency SEC filing detected' is a causal event with concrete impact on price, while 'Stock index rose 0.5%' is a noisy correlation. Numbers and text carry information at vastly different scales and frequencies. Text is sparse and high-stakes; numbers arrive every day. The model wastes capacity learning to weight one against the other, and the learned weights become brittle when the text distribution shifts (different news sources, different crisis types).

The root problem. A single forecaster cannot learn from both numbers and text because they arrive at different cadences and have different causal relationships to the future.

The algorithm as a flow

What it actually does

LLM reasons about the future

An external large language model reads the text stream and reasons: what events or policy changes might happen next month?

Router scores each time step

A lightweight learned routing network (a small neural net) reads the current numbers and text context, outputs a score for each expert.

Route to specialist expert

Each time step is sent to the expert with the highest score: the numbers-expert (trained on pure time series), the text-expert (trained on text + numbers), or both weighted.

Each expert makes a local forecast

Each specialist network reads its expert-specific patterns and predicts the next value or next few values.

Combine and align with LLM guidance

Predictions are pooled; the LLM's reasoning about future events acts as a gentle constraint on the final forecast direction.

What the paper changes

The single thing the paper changes

TiMi introduces a learned routing network that assigns each time step to one or more specialized experts. This routing layer is the core innovation—it is a lightweight decision-maker that sits between the shared input and a pool of expert networks, eliminating the need to hand-craft how to weight numbers versus text.

the object it moves  =  routing decisions
The hidden quantity

The routing weights that decide which expert to trust

measured quantity  =  per-timestep expert assignment

The core hidden quantity is the routing weight: for each incoming time step, a number between 0 and 1 (or a discrete choice) that says 'this time step should go to the text-expert' or 'this is a pure numbers moment'. These weights are learned during training, not set by hand.

The paper estimates these weights using a small neural network that reads the context (recent numbers, presence of new text, recent price volatility) and outputs a soft routing score. High scores mean 'send to text-expert'; low scores mean 'send to numbers-expert'. This routing weight is the hidden quantity because it is never explicitly observed—it emerges as the model learns which situations require which type of reasoning.

Darker means the router sends more weight to the text-expert. Major announcements get high scores; routine trading gets low scores.

Plain reading. The routing weight decides, for each moment in the time series, whether to trust the numbers-expert or the text-expert more. Learning these weights is the model's way of discovering which information is causal at which times.
Paper reading. The paper calls this the multimodal mixture-of-experts gating mechanism. In standard mixture-of-experts, the gate is a learned function that reads the input and outputs a probability over experts; here, the gate additionally reads the modality (numbers vs. text) and learns a separate routing function per modality type.
Why it works

Why splitting experts and learning a router fixes the problem

The mechanism is simple: when you force each time step to commit to one expert (or a small subset), each expert can specialize deeply. The numbers-expert learns pure time series patterns—daily cycles, seasonal trends, momentum. The text-expert learns the sharp, unpredictable shocks that come with announcements. Because they are separate, neither expert wastes capacity learning to ignore the other modality.

The router learns to dispatch to the right expert by gradient descent: if the numbers-expert makes good predictions on stable days and the text-expert makes good predictions on shock days, the router learns to send each type of day to its specialist. This is much simpler than learning a single shared network that must somehow internalize both behaviors.

The LLM reasoning provides a second benefit: it reads historical text and predicts future events (mergers, rate hikes, supply chain breaks). These predictions act as a soft target that steers both experts toward the same future direction, aligning them without forcing an explicit alignment representation. The model does not need to match the 'meaning' of text to numbers; it only needs to agree with the LLM on what the future holds.

The routing formula and how it decides

First in words:

For each time step, compute a routing score as: score = softmax (small_network (recent_numbers, recent_text_flag, volatility)). Then: output = weighted_sum (numbers_expert_output × (1 - score), text_expert_output × score).

Then the compact form:

routing_weight_t = softmax(MLP(num_context_t, text_flag_t, vol_t)); output_t = (1 - routing_weight_t) * expert_num(x_t) + routing_weight_t * expert_text(x_t, text_t)

Every symbol:

routing_weight_tthe learned decision for time step t, between 0 (numbers-expert) and 1 (text-expert)
MLP(...)a small multi-layer neural network that reads the context
num_context_trecent price history and statistics at time t
text_flag_twhether new text or news arrived at time t
vol_trecent price volatility (how much prices swing)
expert_num(x_t)the numbers-expert network's prediction given current prices
expert_text(x_t, text_t)the text-expert network's prediction given prices and text
output_tthe final blended forecast for time t
A tiny worked example
Time t=100 (normal Tuesday, no news): recent_vol = 0.8%, text_flag = 0 (no new headlines). MLP outputs routing_weight = 0.1 (go mostly to numbers-expert).
Expert outputs: numbers_expert predicts 102.5, text_expert predicts 102.3. Blend: 0.9 * 102.5 + 0.1 * 102.3 = 92.25 + 10.23 = 102.48 (weighted toward the numbers path).
Time t=101 (Fed rate cut announced, volatility spikes 2.1%, text_flag = 1): MLP outputs routing_weight = 0.7 (go mostly to text-expert).
Expert outputs: numbers_expert predicts 101.8 (momentum says down), text_expert predicts 103.1 (rate cut is bullish). Blend: 0.3 * 101.8 + 0.7 * 103.1 = 30.54 + 72.17 = 102.71 (weighted toward the text path, captures the shock).

The routing weight emerges from learning: on stable days, the weight shrinks to 0, leaving only the numbers-expert; on shock days, it grows to 1, isolating the text-expert and its special knowledge.

What can go wrong

What can go wrong

Router over-commits to one expert. If the initialization or learning rate is wrong, the routing weights can collapse to all-0 or all-1, meaning the router stops dispatching and just uses one expert. This wastes the whole point. Fix: ensure routing weights stay diverse via regularization (a gentle penalty on extreme weights).
Text and numbers have no real alignment. If text in the training set does not actually causally influence the time series (e.g. random press releases about unrelated companies), the model cannot learn which expert to trust when. The experts remain indistinguishable, and the LLM guidance has nothing to anchor to.
LLM predictions are wrong. If the language model's reasoning about future events is inaccurate (e.g. it misses a major surprise), the LLM guidance pulls both experts in the wrong direction. The paper's benefit hinges on the LLM being a good reasoner, which it is not guaranteed to be.
Done right: modality-specific experts and learned routing. When the text truly carries causal information about the time series, and the router learns to send shock moments to the text-expert and stable periods to the numbers-expert, the model outperforms single-network baselines by a large margin, because each expert learns its regime deeply.
What a runnable demo should prove

What a runnable demo should prove

Build a toy multimodal time series: a sequence of 100 daily stock prices and 10 news events (e.g. 'dividend announced at day 30', 'earnings miss at day 55'). Train three models: (1) naive single transformer on numbers only, (2) naive single transformer on numbers + text concatenated, (3) TiMi with a numbers-expert, text-expert, and learned router. On the test set (days 101–150, including new shock events), measure accuracy (mean absolute error between predicted and real prices) on stable days vs. shock days separately.

error_stable = mean( |predicted_t - real_t| for t in non_shock_days ); error_shock = mean( |predicted_t - real_t| for t in shock_days ); ratio = error_shock / error_naive_shock

TiMi should achieve dramatically lower error on shock days (e.g. 40% better, because each expert learns its patterns deeply, whereas a naive model must split its learning between both regimes) while staying competitive on stable days.
