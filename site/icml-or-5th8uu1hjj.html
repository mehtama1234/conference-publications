AREA: Attribute Extraction and Aggregation for CLIP-Based Class-Incremental Learning

Split CLIP-based class-incremental learning into two separate stability problems: keep visual-text attributes from drifting, and keep their combination rule from being overwritten by new classes.

Paper explainersAll themesOther

Class-incremental learning asks one model to absorb new classes over time without access to the old training images. In CLIP-based setups, this problem is easy to describe but hard to solve. The model compares an image representation with text prompts such as a photo of a class name, so it looks as if one similarity score decides everything. This paper argues that the score hides two different jobs. First, the model must extract class attributes from images and text. Second, it must combine those attributes into a class decision. New classes can damage both jobs in different ways. AREA stabilizes each job with a different mechanism, then routes predictions through task-specific attribute manifolds, meaning curved class regions in the shared representation space, during prediction time.

Zero assumption version

New classes disturb both what the model sees and how it decides

Suppose a CLIP-based classifier first learned animal classes and later receives vehicle classes only. The model must add attributes such as wheels and windows, but it should not lose whiskers, fur patterns, or tail shape. It also must decide how strongly each attribute should count for each class once the label set has expanded.

If the update uses only current-task data, both pieces can drift. The representation used to extract class attributes can slide toward the new classes, and the combination rule that turns extracted attributes into a class score can also become biased toward the recent task. This is why forgetting in CLIP-based class-incremental learning is not only about memorizing old prototypes. It is about preserving both the attribute basis and the rule that mixes those attributes into a decision.

The paper's split. Treat extraction and aggregation as separate failure modes, because stabilizing only one still leaves room for catastrophic forgetting in the other.

The algorithm as a flow

What it actually does

Anchor class attributes on the hypersphere.

Use principal geodesic analysis on the unit-sphere representation space to keep class-level visual and text attributes from drifting, because CLIP features live on normalized directions rather than on ordinary straight-line coordinates.

Add lightweight task experts.

Handle new class-specific aggregation changes with small per-task modules, so the shared representation does not need a full rewrite for each incremental step.

Score and refine with residual updates.

Let experts contribute scored corrections on top of the base representation, because small targeted changes are less likely to overwrite the old attribute structure.

Constrain the update through a bottleneck.

Use a variational information bottleneck, meaning a constraint that limits how much task-specific detail can pass through, so the experts keep only decision-relevant changes instead of memorizing current-task quirks.

Route prediction-time decisions over task attribute manifolds.

Choose predictions by comparing the sample against task-specific attribute regions with optimal transport, meaning a cost-based matching rule, because the class decision should use the most compatible task layout rather than one global shortcut.

What the paper changes

What the paper changes

The paper changes the update target from one monolithic image-text similarity score into two maintained objects: an anchored attribute basis and a task-specific attribute aggregation rule.

The hidden quantity

The hidden quantity

measured quantity  =  attribute basis plus aggregation rule

The hidden quantity is the pair of objects sitting underneath the final class score. One object says which attribute directions remain available in the shared representation space. The other says how those directions should be combined for the current label set.

That pair matters because forgetting can happen in either place. A model may still know how to combine attributes, but the needed old attributes may have drifted away. Or the old attributes may still exist, but the incremental update may now weight them incorrectly when computing class evidence. AREA is designed around the claim that these are different problems and should not be repaired with one blunt penalty term.

Why it works

Why the decomposition helps

Anchoring extraction on the hypersphere matters because CLIP representations are normalized. What matters is directional structure on that sphere, not arbitrary straight-line movement in an unconstrained space. Principal geodesic analysis captures dominant variation along the sphere itself, so class attributes can be anchored in the curved space where the model actually operates.

Task-specific experts matter because new classes do require new aggregation behavior. A rigid frozen model would underfit the incremental task. But a full shared-model update is too destructive. Lightweight experts with scored residual corrections give the model room to adapt while keeping the shared attribute basis mostly fixed.

The bottleneck and routing pieces matter at prediction time. The bottleneck limits task-specific memorization during learning, so the expert update keeps only compact class-separating information. Optimal-transport routing then compares the sample against task attribute manifolds in a cost-aware way, which helps the model decide which learned task layout best explains the current input because the transport cost measures how much the sample must move to match each task region instead of forcing every class through one flattened decision surface.

Math after the picture

The incremental objective

First in words:

Keep the anchored attribute structure stable while adding task-specific aggregation corrections that are small, scored, and information-limited.

Then the compact form:

total_loss = anchor_loss + expert_score_loss + residual_loss + beta bottleneck_loss

Every symbol:

anchor_losspenalty when class-level visual or text attributes drift away from their anchored directions on the sphere
expert_score_losspenalty that trains the task-specific experts to assign useful aggregation weights for current classes
residual_losspenalty on the correction term added on top of the shared representation
bottleneck_lossthe information-bottleneck term that limits unnecessary task-specific detail
betathe weight placed on that bottleneck term
total_lossthe combined training objective for one incremental update
A tiny worked example
After learning animal classes, the model has an anchored direction for whisker-like evidence.
A new vehicle task adds wheel-like evidence that needs a new aggregation pattern.
If the update changes the old whisker anchor heavily, the anchor term rises.
If the task expert fails to combine wheel and window evidence for cars, the expert score term rises.
If the expert starts memorizing current-task detail that is not needed for classification, the bottleneck term rises and pushes the update back toward a compact correction.

The objective treats stability of extracted attributes and stability of their combination rule as separate quantities, because they fail for different reasons.

What can go wrong

What can go wrong

Anchors can become too rigid. If the attribute anchors are enforced too strongly, the model may fail to add genuinely new evidence needed for later tasks, because not every useful direction is already present in the early tasks.
Task experts can still fragment the model. If the experts accumulate without enough sharing, prediction can become a routing problem with too many narrow specialists.
Transport routing depends on learned task layout. If the task manifolds are poorly shaped, optimal-transport routing can send an example to the wrong task region even when the base representation is sound.
Done right. The approach is strongest when the anchored attribute basis stays reusable across tasks and the task experts stay lightweight, because then the model adapts without rebuilding its old evidence from scratch.
What a runnable demo should prove

What a runnable demo should prove

Take a CLIP-based class-incremental benchmark and compare three systems: a direct fine-tune baseline, a method that only protects the shared representation, and AREA. Track old-class accuracy after each new task and inspect whether old visual-text attribute directions remain aligned.

The demo should also test prediction-time routing by showing whether examples near class boundaries are sent to the right task-specific attribute manifold. A convincing result is that AREA loses less old-class accuracy because it separates attribute preservation from aggregation adaptation instead of asking one update rule to do both jobs.

forgetting_gap = peak_old_class_accuracy - final_old_class_accuracy

The practical claim is that old classes survive longer when the update preserves the attribute basis and localizes the new aggregation changes.
