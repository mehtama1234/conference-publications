Understanding why the model predicts

Making time series models interpretable and explainable—showing which past values matter, why anomalies occur, or what causal patterns the model has found.

All themesField mapMathematicsAll explainers
What this is

A model that forecasts accurately is valuable, but a model that also explains itself is priceless. A hospital wants to know: which vital signs led the model to predict a crisis, because doctors need to understand the clinical reasoning. A factory wants to know: why did the model flag this sensor reading as anomalous, because maintenance engineers need to know if the flagging is real or a false alarm. A trader wants to know: did the model's price prediction come from technical patterns or fundamental data, because the trading strategy depends on the underlying logic. Understanding the model's reasoning builds trust because humans can verify that the model is using real patterns and allows verification that the model is learning sensible patterns, not spurious correlations created by the training data. It also enables debugging because if the model is wrong, seeing what it focused on helps identify where the prediction went astray.

Interpretability for sequences is tricky because sequences have temporal structure. A black-box neural network processes information through many layers, and by the end, the signal is transformed beyond recognition. Traditional linear models are transparent—each coefficient shows the contribution of one variable. But linear models are often too weak for complex sequences. The question is how to get both expressiveness and explainability. Some papers use attention mechanisms, which show which past time steps the model attends to. Others use saliency maps, which highlight which input values most influence the output. A few papers build interpretable architectures from the ground up, sacrificing some accuracy to maintain clarity.

Papers in this theme focus on making sequence models transparent. Some extract rules from neural models—for example, 'if the past three values are increasing and the growth rate accelerates, predict a peak.' Others use methods to identify which past values truly drive the future, rather than just correlating with it. Some combine neural and symbolic approaches: let the neural network be flexible, but require it to produce outputs that are human-interpretable or satisfy domain constraints. The underlying principle is that in high-stakes domains like healthcare or infrastructure, a slightly less accurate but fully explainable model is often preferred to a black-box model with marginal accuracy gains.

How the work breaks down

Explaining time series predictions splits along several lines. Some papers attack the explanation itself—asking whether showing which past values the model used is even trustworthy. Others build models designed for interpretability from the start, using prototypes or hierarchies humans can understand. Still others focus on causal discovery, separating real cause-and-effect relationships from spurious correlations. Finally, some work asks: can we explain the model in natural language, as if a human expert were narrating their reasoning?

Trusting explanations when under attack

Explanation methods for neural networks assume that if you visualize which input values the model used (using saliency maps, methods that highlight which past steps matter most, or computation-path-based techniques), you are seeing the model's true reasoning. But attackers can craft inputs that fool these explanation methods themselves—making the model pick one action while its explanation points to something else. This matters in time series because humans (doctors, traders, factory operators) make real decisions based on explanations, so a fake explanation can propagate false confidence.

Exposing Vulnerabilities in Explanation for Time Series Classifiers shows this vulnerability directly through dual-target attacks: the attacker forces the model to classify a sequence one way while making the explanation seem to support the opposite class. The paper reveals that explanation stability (how much the saliency map jiggles when you perturb the input slightly) does not guarantee trustworthiness under attack. The consequence is clear: checking that an explanation looks stable is not enough. Instead, evaluation of trustworthiness must account for coupling—the fact that the model's decision and the explanation are entangled, so an attacker can manipulate one through the other. This motivates a new kind of trustworthiness check that treats the prediction and its explanation as a coupled pair, so you evaluate whether attackers can break both together, not whether each one individually resists noise.

Building models with interpretable prototypes

One way to build explainability into a model from the start is to make it learn prototypes—representative snippets or patterns that the model can point to when making a forecast. Instead of burying reasoning in neural weights, the model learns: 'this kind of pattern tends to predict an upswing' or 'when I see a pattern like this example, I expect a dip.' Humans can see the prototypes and verify they make sense. The catch is balancing accuracy against interpretability: if you constrain the model too tightly, it loses expressiveness and forecasts poorly. If you let it run free, it gets opaque again.

ProSAR: Prototype-Guided Semantic Augmentation and Refinement shows how to learn better time series representations by using prototypes with semantic guidance. The model learns not just any patterns, but patterns that match known behaviors (semantics) in the domain. It refines prototypes through feedback loops: if a prototype is weak or irrelevant, the method reconstructs it. The result is better representation learning, which means the model captures the essential structure in the data. ProtoTS: Learning Hierarchical Prototypes goes further, building a full forecasting system on hierarchical prototypes—think of it as a pyramid where low-level prototypes capture small, local patterns and high-level prototypes combine them into bigger concepts. By making the hierarchy explicit, experts can steer the model: if they disagree with a prototype, they can correct it. The method delivers both high accuracy and trustworthy explanations by design, because the model's reasoning is always traceable back to the prototypes humans can see and verify.

ProSAR: Prototype-Guided Semantic Augmentation and Refinement for Time Series Contrastive Learning
Demonstrates improved representation learning across time-series benchmarks with explicit semantic guidance and feedback-based prototype refinement.

Discovering real causal relationships

A forecasting model might correlate strongly with past values that are not actually causing the future—they just happen to move together by coincidence. For example, ice cream sales and drowning incidents both surge in summer, but neither causes the other. In time series, confounders (hidden variables that drive both the input and output) create spurious correlations constantly. Causal discovery asks: which past values are actually driving the future, independent of confounders? Answering this is hard because you cannot run experiments—you only have observational data, and the network structure is unknown.

TopoDistill: Distilling Global System Topology attacks causal discovery in multivariate time series by learning the underlying causal graph—which sensor or variable actually influences which other one. The method works by learning a global topology (the causal structure) and then using it to reject spurious correlations. It maintains specificity, meaning it avoids claiming causation when the evidence is weak, even when noise makes patterns fuzzy. The result is a clear causal model of the system, not just a prediction function. TimeSAE: Causal Sparse Decoding takes a different angle: given a trained black-box model, extract faithful explanations by finding sparse sets of past values whose effect is causal (not correlational). It uses a decoding method that learns which parts of the input truly drive the output and resists spurious correlations. The two papers complement each other: TopoDistill learns the causal graph from scratch, while TimeSAE extracts causation from an already-trained predictor, making it applicable when you inherit a model you did not build.

TopoDistill: Distilling Global System Topology for Causal Discovery in Multivariate Time Series

Natural language explanations

All the methods above produce explanations as visual saliency maps, prototypes, or causal graphs. But humans are comfortable with natural language. If a time series model is deployed in a factory or hospital, can it generate captions like 'the sensor exceeded the safe range three times in the last hour, and the rate of change is accelerating, so I predict a fault'? This requires a model that can learn to narrate what it sees in sequences without needing labeled caption data—labeled captions from human experts are expensive and domain-specific.

Words Towards Explainability sidesteps the label-scarcity problem using an agentic approach: the model explores the input (asking questions like 'what patterns matter?'), receives feedback from a simulator or human-in-the-loop, and gradually learns to generate captions that match real expert reasoning. The paper also releases TFTSC, a time series caption dataset annotated by industrial experts, so future work has ground truth. The payoff is that explanations can now be expressed in plain language, which is easier for domain experts to verify and critique than abstract saliency maps.

Words Towards Explainability: Caption Label-Free Learning via Dual Loop Agentic Time Series Captioning
Achieves caption generation without label supervision via exploration-feedback mechanism and releases TFTSC, an industrial expert-level time series caption dataset.
