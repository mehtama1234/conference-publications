The Markovian Thinker

Reason in short chunks that keep only a small carried state, so long thinking stays cheap instead of dragging the whole history forward.

Paper explainersAll themesOther

Long reasoning is expensive because each new step keeps rereading the entire earlier trace. As that trace grows, cost and memory rise sharply. Delethink changes the process: it writes reasoning in chunks, keeps only a fixed carried state from recent work, and deletes the rest before continuing. This keeps long reasoning practical because each new chunk depends on a bounded summary rather than the full past trace.

Zero assumption version

Long reasoning gets expensive when every new step carries the full past

A reasoning model often solves a hard problem by generating many intermediate steps. In the usual setup, every new step is computed while keeping the entire earlier trace in memory. If the reasoning trace becomes very long, the model pays for that full history again and again.

That is the core scaling problem. Longer traces can improve difficult tasks because they give the model room to explore more intermediate steps, but the cost of carrying all earlier text rises fast enough to make very long reasoning impractical. Methods that only shorten the trace help somewhat, yet they still tie each new step to the full surviving history because every new step must reread whatever text remains. That keeps the active context growing with whatever text remains, so the cost still rises as the solution gets longer.

The paper's move. Break reasoning into chunks and preserve only a fixed carried state between chunks, because the next chunk does not need the whole raw history if the necessary information is summarized well.

The algorithm as a flow

What it actually does

Start a reasoning chunk

Generate a bounded segment of reasoning steps.

Form the carried state

Keep only a fixed amount of recent or summarized information needed to continue.

Delete the old raw chunk

Discard the detailed earlier text instead of carrying it forever.

Generate the next chunk

Continue reasoning from the carried state plus the new problem context.

Repeat until the problem is solved

Chain chunks together so total reasoning can grow while the active memory stays bounded.

What the paper changes

What the paper changes

The paper changes what gets carried from one reasoning phase to the next. Instead of keeping the entire raw trace, it keeps only a fixed-sized state that is meant to be sufficient for continuation.

The hidden quantity

State sufficiency: the hidden quantity

measured quantity  =  how much useful reasoning survives inside the carried state

The hidden quantity is state sufficiency: after deleting most of the old reasoning text, does the carried state still contain what the next chunk needs? If the answer is yes, the model can continue correctly while using much less memory.

Delethink succeeds when the important intermediate facts, goals, and partial conclusions are concentrated inside that carried state. The carried state can be small only if it preserves the information that actually matters for the next step.

Why it works

Why chunked reasoning lowers cost without losing ability

Standard long reasoning is expensive because each new chunk is conditioned on the entire earlier trace. That means the active context length keeps growing even if most of the old text no longer matters. The model repeatedly pays to reread details that were only useful earlier.

Delethink breaks this loop. After a chunk is finished, the method retains only a fixed carried state that is meant to summarize the active reasoning situation. The next chunk then conditions on that bounded state. This lowers cost because the active context stops growing with the total reasoning length.

The key bet is that the reasoning process has a local state: what subgoal is active, what conclusions have already been established, and what constraints still matter. If those essentials fit into the carried state, deleting the old raw prose does not hurt much. The model gets long total reasoning while the active context remains small.

Math after the picture

Bounded-state chunk transition

First in words:

Each new chunk depends only on the current problem input and a fixed carried state from the previous chunk, not on the full earlier trace.

Then the compact form:

state_(t+1), chunk_(t+1) = F(problem, state_t)

Every symbol:

tthe chunk index
state_tthe fixed carried state after chunk t
chunk_(t+1)the next block of reasoning text
state_(t+1)the updated carried state after generating the next chunk
Fthe reasoning update rule that produces the next chunk and next state
problemthe original task plus any fixed external information
A tiny worked example
Suppose chunk 1 proves that quantity A equals quantity B and that only case 2 remains.
The carried state keeps two facts: 'A = B' and 'active case = 2'.
The full raw text of chunk 1 is deleted.
Chunk 2 starts from those two carried facts and derives the final answer.
This works because chunk 2 needed the established equality and the active case, not every sentence from chunk 1.

The method lives or dies by whether the carried state is sufficient for continuation.

What can go wrong

What can go wrong

Important information can be deleted. If the carried state misses a key fact or active constraint, the next chunk may continue from an incomplete problem state and drift into wrong reasoning.
Some tasks need distant details. A proof or program synthesis task may depend on a small detail from much earlier text, and a fixed carried state may not preserve it unless the summarization is careful.
Chunk boundaries can be awkward. If a chunk ends in the middle of a delicate argument, the carried state may need to encode that unfinished state precisely or the next chunk will lose continuity.
Done right. When the carried state captures the live subgoal, established facts, and remaining constraints, deleting old prose saves cost because the next chunk no longer needs the full earlier wording.
