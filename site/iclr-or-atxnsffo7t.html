Privacy-Protected Causal Survival Analysis Under Distribution Shift

A federated method that combines data from multiple hospitals without sharing raw data by dynamically re-weighting each source to correct for population differences while keeping information secure.

Paper explainersAll themesOther

When doctors want to know which treatment works best for a specific patient outcome like time to recovery, they need data from many hospitals. But hospitals cannot share raw patient data for privacy reasons, and different hospitals serve different populations. This paper shows how to combine survival data (time-to-event outcomes) from multiple hospitals in a federated way: each hospital computes locally, and a central method re-weights their contributions to correct for population differences, all without anyone pooling raw data.

Zero assumption version

Pooling survival data across hospitals is hard

Survival analysis asks: how long until an event happens? (a patient recovers, a machine fails, a treatment stops working). Doctors want to know what treatment works best, so they combine patient data from many hospitals. But hospitals are not the same: they treat different ages, ethnicities, disease stages. If you just merge the data and pretend it is one group, your answer will be wrong—the treatment effect you measure might work for young patients but not old ones.

Worse: hospitals will not share raw patient data because of privacy laws. So the naive approach fails twice: it gives wrong answers and breaks privacy.

The problem in one sentence. Combine survival data across hospitals that serve different populations, without sharing raw data, and get the right answer for each hospital's specific patients.

The algorithm as a flow

What it actually does

Step 1: Set a target

Pick one hospital (the target) where you want to know the treatment effect for its specific patients.

Step 2: Each hospital computes locally

Every hospital (including the target) fits a survival model to its own data without sharing anything.

Step 3: Measure population differences

Compute how different each source hospital's population is from the target hospital's patients.

Step 4: Assign re-weights

Source hospitals whose patients are similar to the target get high weights; dissimilar ones get low weights.

Step 5: Combine estimates

Average the survival estimates from all sources, using the re-weights, to get the target's treatment effect.

What the paper changes

What the paper changes

The paper changes how survival estimates from multiple hospitals are combined. Instead of treating all sources equally or ignoring them, it assigns a data-adaptive weight to each source based on how similar that source's patients are to the target hospital's population.

the object it moves  =  source contributions re-weights
The hidden quantity

The shift: how different is each population?

measured quantity  =  population difference score

For each source hospital, the paper measures how different its patients are from the target hospital. This is the distribution shift: the gap between who is treated at each place. The paper estimates this shift and uses it to decide how much to trust each source.

The method measures this using a probability-based distance: for each patient characteristic (age, disease stage, etc.), it asks how likely it is that a random patient from the source hospital looks like a random patient from the target. Small probability means big shift; large probability means the populations match.

Why it works

Why combining with re-weights works

Survival analysis estimates how long until an event happens. If Hospital A treats younger patients and Hospital B treats older patients, and treatment works differently by age, then naively merging them gives the wrong answer—you get an average that fits neither age group well.

Re-weighting fixes this: if the target is a teaching hospital that sees mostly young patients, sources with mostly young patients get high weight and sources with mostly old patients get low weight. The final combined estimate is then accurate for young patients, because the sources that match the target's population are emphasized.

The method also uses semiparametric efficiency theory: it corrects the estimate in a way that still gives the right answer even if your model of the population differences is slightly wrong. Two independent steps both help: re-weighting fixes the population mismatch by emphasizing sources that match the target, and semiparametric correction removes remaining errors in the survival model itself. If re-weighting has a flaw, the correction step compensates; if the model is slightly wrong, re-weighting compensates. One failure does not ruin both, because they fix different kinds of errors.

Math after the picture

The combining formula

First in words:

The causal effect estimate is a weighted average of the source estimates, where each source's weight is the inverse of how different it is from the target, adjusted by semiparametric influence functions.

Then the compact form:

tau_target = sum_s w_s * tau_s + semiparametric_correction

Every symbol:

tau_targetthe treatment effect for the target hospital's patients
w_sthe weight assigned to source hospital s (high if its patients match target)
tau_sthe treatment effect estimate from source hospital s
semiparametric_correctionan adjustment using influence functions to improve accuracy
sum_ssum over all source hospitals including target
A tiny worked example
Target hospital: 100 young patients, 60 recover after 1 year. Treatment effect = 60%.
Source A: 80 young, 48 recover (80% similar to target). Weight for A = 0.9.
Source B: 100 old, 30 recover (20% similar to target). Weight for B = 0.1.
Naive average: (60% + 48% + 30%) / 3 = 46%. Wrong—ignores that Source B is mostly old.
Re-weighted average: 0.9 * 48% + 0.1 * 30% = 43.2% + 3% = 46.2% for young patients.
With semiparametric correction: estimate refined to 48%, accurate for the target's young population.

The weight for each source is high when its patients are like the target's, making the final answer accurate for the target's specific population.

What can go wrong

What can go wrong

Very different populations. If a source hospital's patients are very different from the target's (rare disease versus common disease), re-weighting cannot fix it because there is no overlap to exploit. That source gets such a low weight that it barely helps, and efficiency gains disappear because you are throwing away the dissimilar data, making your estimate less certain.
Hidden confounders. The method assumes all important patient characteristics are recorded. If a hidden factor affects both who gets treatment and survival (like unmeasured frailty), the method cannot correct for it.
Model misspecification. The method uses a survival model to estimate the population shift. If that model is badly wrong, the re-weights are wrong, and the final answer is biased.
Done right. The method works best when source hospitals have some overlap with the target in patient characteristics, confounders are measured, and the survival model fits the data reasonably well.
What a runnable demo should prove

What a runnable demo should prove

Simulate a target hospital with one population (e.g., young patients) and source hospitals with different populations (young, mixed, old). Generate survival times where treatment works better for young patients, because young patients have more years ahead and can accumulate the benefit. Show that naive pooling gives the wrong effect estimate for the target (it pulls down the effect because old patients benefit less), but re-weighted federated combining recovers the right effect, even though no raw data was shared across hospitals.

bias_before_reweight = abs(naive_pool_effect - true_target_effect), bias_after_reweight = abs(federated_effect - true_target_effect)

The demo must make clear that federated re-weighting eliminates bias under distribution shift, giving the right treatment effect for the target hospital, with no raw data ever leaving it.
