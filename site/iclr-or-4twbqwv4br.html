Detecting Hallucinations by Reading Attention Graphs

To catch when a language model makes things up, treat its internal computational traces as a graph of connected tokens and apply graph learning to read the connection patterns.

Paper explainersAll themesGraph & Geometric Learning

Large language models sometimes generate false or made-up information, called hallucinations. The existing approaches look at isolated pieces of evidence—either attention patterns (how much the model looks at each word) or internal activations (the raw computational state at each step). This paper unifies all these signals into a single graph representation and trains a learnable graph reader to detect hallucinations across them.

Zero assumption version

The hallucination problem: using only one clue

When a language model generates text, it processes each word step-by-step. At each step, it computes an internal state (activation) and decides which previously-seen words to pay attention to. Researchers have noticed that hallucinated (made-up) text shows unusual patterns in these computational signals—either weird activation patterns or lopsided attention (where the model focuses narrowly on a few words instead of spreading its focus).

The problem is that existing detection methods look at only one signal at a time. One method flags unusual attention (like, the model ignores the prompt and pays too much attention to itself). Another method checks if activations look suspicious. A third uses simple formulas like 'count how much attention the model gives to the prompt versus the response'. None of these integrate all the evidence together, and none learn what combination of signals actually predicts hallucination. The isolated approach fails because it treats each signal (attention, activation) independently, when in reality a hallucination shows itself through how they interact across the whole system.

The naive approach fails because it ignores the connections. Looking at activations and attention in isolation misses the fact that tokens are connected through these computational flows—a hallucination shows up in how the whole system talks to itself, not in any single isolated number.

The algorithm as a flow

What it actually does

Collect computational traces

When the model generates each token, capture its internal state and attention scores to all previous tokens.

Build the graph structure

Make tokens into nodes; draw edges wherever attention is non-zero; attach attention scores to edges and internal state to nodes.

Sparsify to keep only strong signals

Drop edges (attention connections) below a threshold to reduce noise and computational cost.

Apply graph neural network layers

Each layer updates the state of a token by aggregating information from its neighbouring tokens along the attention edges.

Aggregate and predict

Combine all token states into a final hallucination probability for the whole response (or per-token, depending on the task).

What the paper changes

The one thing the paper changes: from isolated features to graph structure

Prior work used individual numbers extracted from the model (e.g., 'average attention to the prompt', 'variance of activation at layer 24'). This paper changes the representation: instead of isolated features, it uses a graph where every token connects to others according to the model's own attention patterns, and it lets the graph neural network learn which combinations of graph neighborhoods predict hallucination.

the object it moves  =  graph structure + learnable readout
The hidden quantity

The hidden quantity: graph neighborhood hallucination signal

measured quantity  =  neighborhood connectivity pattern

The paper measures a quantity that previous work never explicitly named: for each token, does it exchange information (via attention and activations) with nearby tokens in a way that signals hallucination? Hallucinated tokens tend to form clusters that look different from factual clusters—either they loop back on themselves, ignore the prompt, or show unusual activation jumps along their neighborhood edges.

The paper estimates this hidden quantity by training a graph neural network to aggregate attention and activation features from each token's neighbourhood and learn which patterns correlate with hallucination. Unlike prior heuristics (which pre-defined what 'suspicious attention' means), CHARM lets the network discover the discriminative patterns from data.

Why it works

Why it works: aggregating signals across the attention graph

Hallucination is not a property of a single token in isolation—it emerges from how a token interacts with its neighbors through the model's own attention and state transitions. When the model hallucinates, the tokens involved form a subgraph that either self-reinforces (high self-attention), ignores the input context, or shows coordinated state changes.

By representing the problem as a graph, CHARM lets a learnable function aggregate attention and activation signals across neighborhoods. Each message-passing layer lets a token learn from its neighbors: 'I see high self-attention and state jumps in my neighborhood, plus low prompt attention—these together are a strong hallucination signal.' Prior heuristic methods hard-coded what to look for; CHARM learns the optimal combination. This works better because different types of hallucinations may have different patterns, and a learnable method discovers what combination of signals best identifies each one, rather than being locked into a single pre-defined rule.

Math after the picture

The message-passing aggregation

First in words:

Each token updates its hidden state by combining its own features with an aggregated signal from its neighbors. The aggregation sums the neighbor states weighted by attention edges.

Then the compact form:

h_i^{l+1} = MLP( h_i^l + sum_j A_ij * h_j^l )

Every symbol:

h_i^lhidden representation of token i at layer l
h_i^{l+1}updated representation after aggregation
A_ijattention score from token i to token j (edge weight)
sum_j A_ij * h_j^lweighted sum of neighbor states
MLPa simple learnable function (small neural network) that processes the sum
A tiny worked example: two tokens in hallucination
Token 'Spain' has initial hidden state h_1^0 = [2.1, 0.3, ...] (from activations).
Token 'Paris' (from prompt) has h_2^0 = [1.5, 1.2, ...]. Attention: A_1,1 = 0.8 (Spain looks at itself), A_1,2 = 0.05 (Spain barely looks at Paris).
Neighbor sum: sum_j A_1j * h_j^0 = 0.8 * [2.1, 0.3, ...] + 0.05 * [1.5, 1.2, ...] = [1.75, 0.28, ...] (mostly Spain, ignoring Paris).
MLP applies learned weights. Output: h_1^1 = MLP([2.1, 0.3, ...] + [1.75, 0.28, ...]) learns that 'self-loop + ignore-prompt = hallucination feature'.
Compare to a factual token: it would have balanced attention (A_ij spread across inputs) and stable state, yielding a different h_i^1.

The equation repeats across all tokens and layers, letting distant tokens gradually exchange information through paths of attention-neighbors, similar to how social networks spread information.

What can go wrong

What can go wrong

Sparsity threshold is too strict. If you drop too many low-attention edges (by setting the threshold too high), you discard weak but real signals and the model loses context. If you keep all edges, the graph explodes in size and noise overwhelms the signal.
Model behaves differently across domains. A large language model trained on broad data may hallucinate in different ways when asked math questions versus factual questions. If the graph patterns differ, training on one domain and testing on another fails (although the paper claims some zero-shot transfer, this is still a known risk).
Circular dependencies in the graph. If a hallucinated token loops back on itself through attention edges, and those edges are the only way the network reads that token's state, the message-passing layers may reinforce the hallucination rather than flag it as suspicious.
Done right. Train the graph neural network on diverse hallucination examples, tune the sparsity threshold via validation, and validate on held-out models or datasets to ensure patterns generalize beyond training.
What a runnable demo should prove

What a runnable demo should prove

A real demo should take a pretrained large language model (like Llama-2 or Mistral) and generate a set of responses—some factually correct, some clearly hallucinated (e.g., 'Paris is in Spain'). Extract the attention weight matrices (which tokens look at which) and activation values (the raw computational state at each step) during generation. Build the attention graph with a chosen sparsity threshold. Train a small graph neural network on these examples (10-50 labeled responses should suffice for a proof-of-concept). Test on held-out responses. Visualize the graph for a hallucinated response and a factual one side-by-side: show that hallucinated graphs have more self-loops and prompt-ignorance, and that the trained network learns to score these patterns as suspicious.

accuracy = (correct_predictions) / (total_predictions); separately track false_positive_rate = (factual_flagged_as_hallucination) / (total_factual)

The key result: a learnable graph reader should consistently catch hallucinations that rule-based heuristics miss, and it should generalize to new domains better than methods trained only on isolated features, because it has learned a flexible pattern-matcher rather than being locked into one formula.
