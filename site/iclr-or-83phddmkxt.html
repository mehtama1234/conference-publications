Soft-DiMO: Making One-Step Generators Trainable

The paper replaces discrete token outputs with soft embeddings so one-step generators can be refined with gradient-based training.

Paper explainersAll themesGenerative Models & Diffusion

One-step generators distill multi-step diffusion models into a single forward pass, making image synthesis fast. But they are stuck: they inherit biases from their teacher model, and their discrete token outputs (labels like 0, 1, 2) act like a wall that blocks the training signal (the mathematical direction that tells weights how to change), making it impossible to refine them with techniques like adversarial training or reward-based tuning. This work softens that wall.

Zero assumption version

The wall between discrete and continuous

Masked diffusion models (models that learn by masking and predicting labels like 0, 1, 2) are slow in real use because they need many prediction steps. Researchers distill them into one-step generators: instead of 10 or 20 steps, the generator produces a full output in one forward pass, running on regular hardware. The speed is real.

But there is a trap. The one-step generator learns its output as discrete labels (integers like 0, 1, 2, etc.), just like its teacher. Discrete labels are like wooden blocks: you can move them around, but you cannot nudge them slightly. Once the generator is trained, its outputs are fixed—you cannot apply adversarial training (an attack that makes images harder to fool), reward-based fine-tuning (steering the model toward human-preferred images), or test-time embedding optimization (tweaking the output at the moment you use it). The training signal (the mathematical instruction that tells each weight how to change) cannot flow through a discrete step, so no refinement is possible.

Additionally, the one-step generator inherits the teacher's learned biases. If the teacher was trained a certain way, the student copies that same bias. Because the discrete outputs block the training signal, the student cannot learn anything new—it is frozen at the teacher's level, even if the teacher was not optimal.

What the paper changes

What changes

The paper changes how the generator reports its output: from discrete labels (0, 1, 2, etc.) to soft embeddings, which are weighted blends of learned vectors (lists of numbers representing each label). Instead of saying label 3, the generator says: 20% label 0, 60% label 3, 10% label 4, 10% label 2, and outputs the average of those vectors.

the object it moves  =  output representation
The hidden quantity

Gradient flow: the signal that enables learning

measured quantity  =  gradient flow

Gradient flow means the training signal can propagate backward through every layer of the model. In machine learning, training works by computing an error (how wrong the current output is), then using calculus to compute which direction each weight should nudge to shrink that error. This direction signal is the gradient. If something in the pipeline is not differentiable (not smoothly nudgeable), the gradient cannot flow through it—the training signal stops, and no refinement is possible.

In the discrete case, the generator outputs token labels (0, 1, 2, ...). A label is discontinuous: you cannot nudge 0 to 0.1; the system jumps. When the decoder receives a discrete label, the gradient computation stops there. Soft embeddings solve this by outputting a continuous blend (0.1 times embedding A, 0.6 times embedding B, etc.), allowing the gradient to flow backward to the generator weights.

Why it works

Why soft embeddings unblock refinement

The core issue is that the generator outputs discrete tokens (a choice from a fixed set: token 0, token 1, etc.). To refine the generator after distillation, you need to compute how each weight should change. This computation requires calculus, which works only on smooth, continuous functions. A discrete choice is not smooth—there is no partial movement from one token to another.

Soft embeddings replace this discrete choice with a continuous blend. Instead of the generator saying token 3 (hard stop), it outputs a probability for each token: 0.1 for token 0, 0.7 for token 3, 0.2 for token 4, etc. Then, instead of picking token 3, you compute the expected embedding: average the embeddings of all tokens, weighted by these probabilities. This expected embedding is a continuous function of the generator's outputs—it can be nudged slightly. When you run a refinement algorithm (adversarial training, reward scoring, test-time optimization), the error signal flows backward through this continuous path, telling the generator how to adjust.

The clever part: the decoder was trained on embeddings of the teacher's discrete tokens. Soft embeddings are convex combinations (weighted averages) of those same embeddings. They lie in the same continuous space the decoder learned from, so the decoder does not break. The generator stays compatible with the teacher's backbone, while becoming trainable.

The soft embedding formula

First in words:

soft embedding = sum over all tokens of (predicted probability of token) times (embedding of that token)

Then the compact form:

e_soft = sum_i p_i * e_i

Every symbol:

e_softthe soft embedding that flows to the decoder
p_ipredicted probability of token i
e_ilearned embedding vector of token i
sum_iadd up over all possible tokens
A tiny worked example
Suppose there are 4 tokens with embeddings e0, e1, e2, e3.
Generator predicts: p0=0.1, p1=0.7, p2=0.1, p3=0.1.
e_soft = 0.1*e0 + 0.7*e1 + 0.1*e2 + 0.1*e3.
If e1 = [0.8, 0.2], e0 = [0.1, 0.1], e2 = [0.3, 0.4], e3 = [0.6, 0.3]:
e_soft = 0.1*[0.1, 0.1] + 0.7*[0.8, 0.2] + 0.1*[0.3, 0.4] + 0.1*[0.6, 0.3]
= [0.01, 0.01] + [0.56, 0.14] + [0.03, 0.04] + [0.06, 0.03]
= [0.66, 0.22].
This continuous point [0.66, 0.22] can be nudged smoothly by gradient descent.

The soft embedding is a weighted average of learned embeddings, making it a smooth function that gradients can flow through.

What can go wrong

What can go wrong

Soft embeddings may not match the discrete choice. If the predicted probabilities are very flat (all labels equally likely), the expected embedding could land far from any real label embedding, drifting into regions the decoder never saw during training. The paper mitigates this by keeping the generator confident in its top labels.
Refinement training can overfit quickly. Once the training signal flows, adversarial or reward-based training can push the generator to game the scoring metric (give high scores without actually being better) rather than learning genuinely useful patterns, because the refiner can exploit quirks in how the reward is measured. The paper avoids this by using careful constraint-based steering and test-time optimization tuning to prevent such exploits.
Decoder compatibility assumes similar embedding space. If the teacher's embeddings and the generator's predicted tokens are misaligned, soft embeddings may produce values outside the decoder's learned region, causing artifacts. The paper enforces alignment during distillation.
Done right: continuous outputs are reliable. With soft embeddings designed carefully, the expected embedding stays in the same space the teacher learned, the training signal flows smoothly back through the system, and refinement techniques improve the model because they are now nudging a smooth surface rather than jumping between discrete cliffs, making improvements stable and predictable.
What a runnable demo should prove

What a runnable demo should prove

A minimal demo trains a one-step generator on a small image dataset (CIFAR-10 or similar). First, measure base image quality (FID score: lower is better) with discrete labels and try to refine it with adversarial training, confirming that nothing happens because the training signal cannot flow. Then, swap in soft embeddings, re-measure image quality, and apply the same refinement step. The demo should show that image quality improves after refinement with soft embeddings, because the continuous output now allows the training signal to propagate, whereas the discrete labels had blocked it completely.

improvement = FID_discrete - FID_soft_refined

The core insight: making the output smooth and continuous immediately opens the door to post-training refinement, demonstrating that soft embeddings are the bridge from frozen discrete outputs to trainable, improvable models.
