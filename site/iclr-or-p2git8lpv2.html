Minimax Sample Complexity of Graph Neural Networks

The paper proves how many examples a graph neural network needs to learn a task depends on whether the graph is tangled (slow-mixing) or spread out.

Graph neural networks (models that learn from networks of connected nodes and edges) work well in practice, but we do not know how many examples they really need to learn. This paper measures the theoretical minimum number of examples required in the worst case and best case, showing that the answer depends heavily on the graph structure itself.

Zero assumption version

Networks hide their difficulty

A graph neural network learns by passing messages between connected nodes. Each node looks at its neighbors, updates itself, then passes that update along. It works well on real networks like social media, proteins, and recommendation systems.

The problem: we have no way to know in advance how many examples the network needs to learn. If you train on 100 examples, is that plenty or do you need 10,000? Different graph shapes might need wildly different amounts of data.

A beginner might guess that all graphs are the same—that you need roughly N examples for any task. But that is wrong. Some graphs (dense neighborhoods, communities that stick together) let the network learn fast. Others (long chains, bottlenecks that pinch off parts) force it to learn slowly.

In one sentence. This paper proves how many examples you need depends on whether the graph is tangled and bottlenecked or well-mixed.

What the paper changes

The thing that shifts

The paper measures the relationship between three moving parts: graph structure (how tangled or spread-out), sample size (how many examples you give the network), and error (how far off predictions are). It proves a formula that connects all three.

the object it moves  =  Sample complexity rate
The hidden quantity

Mixing time and spectral expansion

measured quantity  =  How fast information spreads through the graph

The paper introduces a key hidden quantity: how quickly a message from one node reaches all other nodes in the graph. In a loose, mixed-up graph, a message bounces around fast and touches everywhere quickly. In a tangled graph with bottlenecks, the message gets stuck in one cluster for a long time before crossing a narrow bridge to another cluster.

The paper estimates this using the spectral expansion (how evenly the graph divides into clusters) and label homophily (whether neighboring nodes have the same label). Together, they measure the bottleneck strength. The paper calls this the spectral-homophily condition: networks that cluster tightly and connect loosely between clusters.

Why it works

Why the formula holds

Here is why graph topology controls learning speed: a graph neural network updates each node by aggregating information from its neighbors. The more hops deep the network reads, the more neighbors it must average together to make one prediction.

In a spread-out graph, a few hops reach many diverse nodes, so the network averages many independent signals and learns quickly. In a tangled graph with clusters and bottlenecks, a few hops only reach a tight group of similar nodes, so the network averages highly correlated signals and learns slowly. To learn the true pattern across the whole graph, it must see many examples from many different cluster-bottleneck combinations.

The paper proves this mathematically: the error you cannot avoid scales as the dimension d (the size of each node's features) divided by the log of the sample size n. For spread-out graphs, the error shrinks much faster—only as the square root of log d / n—because diverse neighborhoods mean each new sample teaches something genuinely new rather than reinforcing what you already know. The difference is exponential in the graph topology.

Math after the picture

The error bound

First in words:

For worst-case graphs: error is at least the square root of ( log of dimension divided by sample size ). For tangled graphs: error is at least dimension divided by log of sample size.

Then the compact form:

Worst-case: err >= sqrt( log(d) / n ) | Tangled: err >= d / log(n)

Every symbol:

errPrediction error—how far off the network's guesses are from true labels
dThe input dimension—how many numbers describe each node
nThe sample size—how many labeled examples you give the network
logThe logarithm—grows slowly as numbers get bigger
A tiny worked example
Scenario A: Spread-out graph with d = 100 features, n = 1000 examples. Worst-case error >= sqrt(log(100) / 1000) = sqrt(4.6 / 1000) = sqrt(0.0046) = 0.068 (about 7% error floor).
Scenario B: Same features and examples, but tangled graph. Tangled error >= 100 / log(1000) = 100 / 6.9 = 14.5 (about 14.5% error floor).
The tangled graph imposes a floor 200 times higher—from 7% to 14.5%—even with identical features and data, because the network cannot stitch together knowledge across clusters.

The dimension term d appears in the numerator for tangled graphs but in the logarithm for loose graphs—a huge penalty for high-dimensional features on bottlenecked topologies.

What can go wrong

What can go wrong

Ignoring the graph structure. If you assume all graphs learn at the same rate, you will underestimate how much data a tangled network needs. You may think 1000 examples is plenty when you actually need 10000.
Confusing feature dimension with topology. High-dimensional node features hurt tangled graphs badly (error scales with d) but barely hurt loose graphs (error scales with log d). You cannot fix tangled topology by using fewer features.
Applying worst-case bounds to nearly-bottlenecked graphs. Real graphs are rarely perfectly loose or perfectly tangled. If your graph has some bottlenecks but not severe ones, the true bound is somewhere in between the two rates—you need to measure your graph's spectrum.
Done right. Measure your graph's spectral expansion and homophily before you decide how many examples to collect. A tangled graph needs roughly d / log n examples to reach a target accuracy, while a loose one needs only sqrt(log d / n).
What a runnable demo should prove

What a runnable demo should prove

Build a graph neural network on two synthetic graphs: one with tight clusters and narrow bridges (tangled), one with random connections (loose). Train both on the same node classification task with growing sample sizes (100, 500, 1000, 5000 examples). Measure test error as a function of sample size for each graph. Plot both on a log scale.

test_error = fraction of mispredicted nodes on held-out test set

The key result: the tangled graph's error should decay much more slowly (roughly as 1/log n), while the loose graph's error should drop steeply (roughly as sqrt(1/n)), making the gap in required data unmissable.
