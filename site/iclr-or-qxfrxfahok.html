Learning Part-Aware 3D Features for Robot Manipulation

A robot learns what functional parts look like in 3D space, so it can pick and turn door knobs, drawer handles, or any articulated object it has never seen before.

Paper explainersAll themesRobotics & Control

Robots struggle to manipulate everyday objects like doors and drawers when they meet a new shape for the first time. A robot trained on one door handle cannot simply turn a different knob. This paper teaches robots to recognize functional parts — the parts that matter for manipulation — directly in 3D space, not just as flat pictures. This unlocks generalization: once a robot understands what a handle is, it can manipulate any handle.

Zero assumption version

Why robots fail on new objects

A robot trained on door manipulation learns 'push handle forward, turn it, pull door open'. But it learns this on ONE door, using 2D camera pictures. When it meets a drawer handle shaped differently, or a circular knob, or a lever, it fails. It does not know that all these are things to push and turn.

Engineers tried lifting 2D picture features into 3D space — taking what worked in flat pictures and making them work in space. This breaks in three ways: (1) the robot sees the object from many angles, and features disagree with each other across views. (2) the process is slow, taking seconds per scene. (3) the 3D space is filled with low-resolution feature numbers, so the robot cannot precisely tell where to push.

The core problem. Robots see functional parts (handles, knobs, levers) as meaningless surface variations. They cannot tell that all door handles are the same functional part, just in different shapes.

The algorithm as a flow

What it actually does

Step 1: Collect ground truth

Engineers label which parts of training objects are functional (this knob, this lever).

Step 2: Teach the 3D feature machine

Feed point clouds in; the model outputs a feature (a list of numbers) for each 3D point, so points in the same part have similar features.

Step 3: Use contrastive learning

Push features of the same part close together; push features of different parts far apart.

Step 4: Build a diffusion policy

Use these 3D part features to teach the robot how to grasp and manipulate, learning from human demonstrations.

Step 5: Test on new objects

Feed in a never-before-seen handle or knob; the robot grasps the right spot and turns it correctly.

What the paper changes

What the paper changes

Instead of using features from 2D pictures (which disagree across views and are slow), the paper builds features directly in 3D space. Each point in a point cloud gets a feature vector — a list of numbers that encodes what kind of functional part it belongs to.

the object it moves  =  The feature field
The hidden quantity

The part-similarity measure

measured quantity  =  Feature distance within a part

This paper's central idea rests on a hidden quantity: how close together are the features of points that belong to the same part? In the old approach, there is no such measurement — 2D features from different views just disagree. Here, the paper measures feature distance in 3D space: if two points are labeled as part of the same handle, their features should be close. If they are different parts (handle vs. door surface), their features should be far apart.

The paper estimates this by using contrastive learning: gather examples of points from the same part, gather examples from different parts, and train the model to minimize distance within parts and maximize distance between parts. The closer the same-part features cluster, the better the model learned to see parts, because a tight cluster means the model reliably assigns similar numbers to points of the same functional piece, so the robot can recognize and grasp that piece no matter what shape it takes.

Why it works

Why it works: parts in 3D space

The magic is moving from 2D pictures to 3D point clouds. In pictures, a handle photographed from above looks nothing like the same handle shot from the side — different pixels, different features. In 3D space, both views point to the same 3D points. The model assigns a feature number to each 3D point, not to each 2D pixel. Now, the same functional part (the handle) always occupies the same 3D points, regardless of which camera angle took the picture.

Contrastive learning reinforces this: points labeled as the same part get pulled to the same feature cluster, points labeled as different parts get pushed far apart. A robot that learns to manipulate using these features learns 'grasp at feature cluster center X' — and that cluster center means 'handle', universally. When the robot meets a new door, it sees a new cloud of points, but the point-to-feature assignment is the same: handle-shaped points land in the same feature cluster. The robot grasps that cluster center, as it learned to do.

Speed improves because the model predicts features in one pass through the network, not through iterative multi-view synthesis that requires many forward passes. Resolution improves because point cloud density is inherently 3D; in contrast, 2D picture features must squeeze 3D information into a grid of pixels.

Math after the picture

The contrastive learning equation

First in words:

Loss is the sum of: a penalty when two features from the same part are far apart, plus a penalty when two features from different parts are close. For each point, compute the distance to other points of the same part (minimize), and to points of different parts (maximize).

Then the compact form:

L = sum_i [ -log( exp(-d_same_i / tau) / (exp(-d_same_i / tau) + sum_j exp(-d_diff_ij / tau)) ) ]

Every symbol:

d_same_ifeature distance between point i and another point in the same part
d_diff_ijfeature distance between point i and a point in a different part j
tautemperature: controls how sharply the model penalizes distant same-part pairs
exp(...)exponential function: converts distances to scores
A tiny worked example
Point A (part of a handle), Point B (also the handle): feature distance = 0.2, so exp(-0.2 / 0.1) = exp(-2) ≈ 0.135. Small, good.
Point A, Point C (different part, door surface): feature distance = 2.0, so exp(-2.0 / 0.1) = exp(-20) ≈ 0 (negligible). Good; far parts do not interfere.
If Point A drifted closer to C, say distance = 1.0, then exp(-1.0 / 0.1) = exp(-10) ≈ 0.00005. Still tiny, so the loss barely moves. But many points drifting this way add up, so training gently corrects the drift.
The key: exp() turns raw distances into numbers that reward same-part clustering and penalize cross-part confusion. During training, the system nudges feature values step by step in directions that shrink these penalty numbers, until same-part points cluster and different-part points separate.

This equation is the 'gravity well' that pulls same-part features together and repels different-part features, making the 3D feature space useful for robot learning.

What can go wrong

What can go wrong

Wrong part labels in training data. If a human labels 'this knob' and 'this drawer handle' as different parts when they should be grouped together, the model will treat them as different parts. The robot learns a false separation.
Object shapes too extreme. A part that is extremely bent or rotated in a new object might project into 3D points at a very different location than the training set saw. The model must generalize across pose variations.
Occlusion hides the part. If a handle is covered by a gripper or another object during manipulation, the point cloud loses information. The robot must reason about parts it cannot see.
Done right: part labels consistent, test objects in similar poses and lighting, parts are visible. When training data is clean and diverse, PA3FF clusters parts reliably and robots generalize to new objects.
What a runnable demo should prove

What a runnable demo should prove

Train PA3FF on point clouds from 50 diverse door handles (different shapes, sizes, materials) with labels marking 'this 3D region is the graspable part'. Then test on a new handle the model has never seen. Use the learned features to run a robot grasping policy: the robot should grasp near the feature cluster center and successfully open the door. Repeat on three new handles of wildly different shapes (round knob, lever, handle). Show that the robot grasps the right spot on all three.

Success rate = (number of new handles successfully grasped and turned) / (total new handles tested)

If a robot can grasp and turn a handle it has never seen before, it is because it truly learned what a handle is in 3D space, not memorized pictures.
