Part-Aware 3D Feature Field for Robot Manipulation

Teach a robot to manipulate new objects by learning which 3D points belong to the same functional part (like a handle), so it can find handles on any door shape.

Paper explainersAll themesRobotics & Control

A robot trying to open a new door faces a puzzle: this door's handle looks different in size and shape, but it is still a handle. Current methods struggle because they try to memorize pixel pictures from training objects, which do not transfer. This paper proposes PA3FF: learn a 3D feature field where points that belong to the same functional part (a knob, a handle, a hinge) have similar internal numbers. Then a new door — even an unseen shape — has its handle identified by the same feature pattern.

Why robots cannot generalize across object shapes

A robot watching a video of a human opening a microwave learns a simple rule: if you see red pixels at coordinates (100, 200), move the arm there. But when it faces a different microwave model, the handle is at (250, 150) with a different color. The learned rule fails.

Current methods try to fix this by using 2D foundation features (like CLIP or DINOv2): they extract patterns from training images that are supposed to be general. But when these 2D patterns are lifted into 3D space — using multiple cameras and stitching together views — they become unreliable. Multi-view consistency breaks (different camera angles produce conflicting feature values at the same 3D point). Spatial resolution collapses (a 2D image feature covers many 3D points, so you cannot pinpoint where the handle is). Runtimes explode.

The problem in one sentence. Robots need to recognize functional parts (handles, hinges, knobs) on unseen objects, but 2D features lose spatial detail when converted to 3D, and they do not explicitly encode what a part is.

The algorithm as a flow

What it actually does

Accept point cloud input

Feed 3D points of an object (from a depth camera) into the network.

Extract multi-scale 3D features

A pre-trained point cloud encoder (Sonata) produces detailed feature vectors (lists of numbers) for each point.

Enforce geometric consistency

Push points that share a labeled part (e.g., all handle points) to have similar features. Push different parts apart.

Align with semantic part labels

Encode part names (like handle, hinge) as text, convert to vectors, and pull point features toward their named part vector.

Combine features into manipulation policy

Feed the part-aware features into a diffusion policy that learns to generate smooth arm motions.

What the paper changes

What the paper changes

PA3FF changes how 3D features are learned from objects. Instead of lifting 2D image features to 3D (which breaks consistency), it learns a native 3D feature field trained directly on labeled point clouds, where the training process intentionally pushes points of the same functional part to have similar numbers.

The hidden quantity

Part affinity: the distance between feature vectors

measured quantity  =  Part affinity

Part affinity is the degree to which two 3D points belong to the same functional part, measured by how close their feature vectors (lists of numbers) are. If two points have similar feature numbers, they likely belong to the same part (e.g., both on a door handle). If they are far apart in feature space (meaning their numbers differ more), they belong to different parts.

The paper estimates part affinity during training by using labeled 3D point clouds where each point is tagged with its part (handle, hinge, base, etc.). Contrastive learning (a training method that pulls matching points together and pushes mismatches apart) is used to construct feature vectors that respect these labels. Once trained, the model produces part affinity for any new object automatically.

Why it works

Why part-aware 3D features enable generalization

The core insight is that a functional part (a door handle) has an identity independent of the object's specific shape. A robot trained on 100 microwave doors learns a feature pattern for handles. When it sees a refrigerator door, the handle looks completely different in shape, but if the learning process has captured the abstract essence of handleness (certain local shape, spatial position relative to the base), the feature vectors will match.

PA3FF achieves this by training on labeled 3D part data using two coordinated losses. The geometric loss pulls together all points tagged as the same part (e.g., all handle points), which teaches the features to cluster by part identity. The semantic loss uses language encodings of part names (the word handle converted to a numerical vector), pulling point features toward their semantic label, which anchors the learned patterns to human-interpretable part categories. Together, these two forces create a feature space where part identity is encoded directly, independent of object shape.

Math after the picture

The two-loss training equation

First in words:

Total loss = Geometric loss (pull same-part points together) + Semantic loss (align features with part-name vectors)

Then the compact form:

L_total = L_geometric + L_semantic, where L_geometric = -log(exp(sim(f_i, f_j) / tau) / sum_k exp(sim(f_i, f_k) / tau)) for same-part pairs, and L_semantic = -log(exp(sim(f_i, text_encoding(part)) / tau) / sum_k exp(sim(f_i, text_encoding(all_parts)) / tau))

Every symbol:

f_iFeature vector of point i
f_jFeature vector of another point in the same part
text_encoding(part)Vector representation of the part name, e.g. handle
sim(a, b)Similarity between two vectors (cosine similarity)
tauTemperature parameter that controls how sharp the clustering is
A tiny worked example
Suppose point A and point B are both labeled as handle points. Their feature vectors are f_A = [0.8, 0.1] and f_B = [0.75, 0.15]. Cosine similarity is high (0.98).
The geometric loss pulls them closer, say to [0.8, 0.1] and [0.79, 0.11], increasing similarity to 0.999.
Separately, the semantic loss compares f_A to the text vector for handle (obtained from SigLIP text encoder). If they are close, that part of the loss decreases.
A hinge point C at [0.1, 0.9] is far from both (similarity ~0.1 to handle points), so the loss stays high unless C's features move toward hinge-like values.
After training, the model predicts features for any new object such that handle points automatically cluster near the learned handle region in feature space.

The two losses work together: geometric loss enforces that same parts cluster, semantic loss anchors those clusters to interpretable part names, creating a generalizable feature space.

What can go wrong

What can go wrong

Training data bias: if all handles in the dataset are round, square handles on unseen objects may be misidentified. The learned feature space reflects only the parts it has seen. A robot trained on doorknobs (round, rotatable parts) may not recognize a lever handle (linear, push-pull). Mitigation: train on diverse part shapes.
Part ambiguity: some objects have multiple graspable points that are not the same part. A coffee maker may have both a handle (intended grip) and a lid-edge (incidental). If both produce similar features, the robot may grab the wrong point. Mitigation: include semantic labels that distinguish handle from lid.
Occlusion: if part of a handle is hidden behind another object, the feature field may infer the wrong part identity. The model must infer the full 3D shape from partial point-cloud observations. Occlusion causes incomplete training signals. Mitigation: augment training with occlusion examples.
Done right: diverse training data. When the training set includes handles, hinges, knobs, and levers in many shapes and sizes, and semantic labels are precise, PA3FF learns strong part identities that transfer to unseen objects.
What a runnable demo should prove

What a runnable demo should prove

Build a small experiment: (1) Collect point clouds of five familiar objects (e.g., three microwave models, two refrigerators). Label each point with its part (handle, base, hinge, etc.). (2) Train PA3FF on the first three. (3) Test on the two unseen objects. (4) Measure whether the learned features correctly cluster handle points together even on the never-seen-before objects. (5) Show a visualization: in feature space, plot the first two dimensions of all points. All handle points should form a tight blob, all hinge points form another blob, etc., even across object shapes.
