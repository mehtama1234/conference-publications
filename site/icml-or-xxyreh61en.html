SCOUT: Learning Causal Cycles from Messy Real-World Experiments

This paper discovers which variables cause which other variables by looking at experiments where you push multiple dials at once and do not know which ones you pushed.

Paper explainersAll themesTime Series & Sequential

In the real world, systems feed back on themselves: more traffic makes roads slower, which makes drivers take detours, which makes other roads slower. Most causal discovery methods assume systems go one way (no loops) and that you know exactly which levers you pulled in an experiment. This paper finds causal loops from messy real experiments where you push unknown combinations of variables.

Zero assumption version

Why it is hard to find causal loops with messy experiments

Most causal discovery methods break if three things happen: the system loops back on itself (the heater warms the room, but a warm room reduces heater power, which changes temperature, which changes heater power again), the noise is not perfectly bell-shaped, or you do not know which experiment knobs you turned. Real data has all three.

A naive approach: assume the system has no loops, assume the noise is a perfect bell curve, and record exactly which levers you pulled. In this case, you can run linear algebra and find the causal graph (a picture of who causes whom). But when systems loop, this breaks—the numbers contradict the acyclic assumption. When you do not know which levers you pulled (soft interventions with unknown targets), you cannot label which variables you changed.

In one sentence. The paper learns the causal structure and the unknown intervention targets by fitting a flow-based generative model to the experimental data, so it works even when targets are unknown and the system loops.

The algorithm as a flow

What it actually does

Build a density map

Train a normalizing flow (a neural model that squashes and stretches random numbers to match data) to learn the true data density.

Embed unknown targets

The flow includes hidden numbers for each experiment's targets. They start random and get tuned.

Fit the causal graph

Give each causal edge a number strength, then adjust it to maximize how well the flow fits the experimental data.

Maximize log-likelihood

The whole system (graph structure, intervention targets, noise settings) moves to make observed data more likely.

Extract answers

Read off the learned graph structure (which variable caused which) and the learned targets (what was actually pushed in each experiment).

This paper changes two things at once: the causal graph structure (which edges exist, who causes whom) and the unknown intervention targets (what was actually pushed in the experiments).

The hidden quantity

The hidden quantity: the probability density

measured quantity  =  data log-likelihood (how probable the observed data is under the model)

The paper maximizes the log-likelihood: a number that says how well the model's causal graph and flow explain the observed data. Higher log-likelihood means the learned causal graph is more plausible.

The method works by building a normalizing flow (a deep neural model that learns to transform simple random numbers into complex data patterns). As the flow learns the true data density, and as the causal graph edges and intervention targets shift, the log-likelihood climbs. The paper tunes everything—graph structure, targets, flow weights—to make the data as likely as possible.

Why it works

Why this method finds cycles and unknown targets

If you build a neural model (a normalizing flow) that learns to reproduce the experimental data exactly, then the model must implicitly learn both the true causal structure and the true intervention targets, because if either were wrong, the data would not fit.

Here is the concrete chain: you start with a guess at the causal graph (maybe random edges) and guesses at the unknown targets. You build a normalizing flow conditioned on those guesses. You measure how well the flow reproduces the actual data (the log-likelihood). Then you nudge the graph structure and targets in directions that increase the log-likelihood. Over time, only the causal edges and targets that make the data probable will survive. Cycles are no problem: the normalizing flow can model data from cyclic systems as easily as acyclic ones, because flows just learn patterns from data, they do not assume any structure.

The core equation: maximizing data fit

First in words:

For each experiment, the probability of the observed data equals the flow's density at that point, times a factor for how well the assumed causal structure explains the noise pattern. The method finds the graph and targets that maximize the sum of log-probabilities across all experiments.

Then the compact form:

log p(data | graph, targets) = sum over experiments [log flow_density(observed_values) - penalty for structural misfit]

Every symbol:

flow_densitythe output of the normalizing flow at the observed data point
observed_valuesthe actual measurements from the experiment
graphthe causal edges we are trying to learn
targetsthe intervention knobs that were pushed (unknown)
structural misfithow badly the causal equations fail to explain the noise pattern
A tiny worked example
Experiment 1: [room-temp=72, heater-power=80, outside-temp=65]. If the flow says this is likely (density 0.15), the log-likelihood is log(0.15) = negative 1.9.
Experiment 2: [room-temp=68, heater-power=50, outside-temp=60]. If the flow says this is less likely (density 0.08), the log-likelihood is log(0.08) = negative 2.5.
Total log-likelihood for two experiments: negative 1.9 plus negative 2.5 = negative 4.4. Higher (less negative) is better.
If we guess the wrong causal graph (e.g. 'outside temp does not affect inside temp'), the flow will have trouble fitting all experiments, and the log-likelihood will be more negative. The true graph gives the higher log-likelihood, so optimization finds it.

The method jointly optimizes the causal graph, intervention targets, and flow weights to maximize this log-likelihood, so all three converge to their true values.

What can go wrong

What can go wrong

Flow does not converge. If the normalizing flow is too simple (too few layers, too low capacity), it cannot learn the true data density, and the log-likelihood plateaus. Then the causal graph never fits well. Fix: use a deeper, wider flow, or more training steps.
Interventions are too weak. If the interventions barely move the variables (very soft), the data barely changes between experiments. Then the causal structure is hard to see in the noise. The method will recover uncertainty in the graph. Fix: design interventions that move variables noticeably.
Wrong causal class. If the true causal relationship is not in the model class (e.g. the paper assumes additive noise but the true system has multiplicative noise), no amount of fitting will recover the graph. Fix: check model assumptions before running the method.
Done right. When the flow converges, the data fits well, and the causal model class is correct, both the graph and unknown targets converge to the true values. The log-likelihood is a reliable signal of success.
What a runnable demo should prove

What a runnable demo should prove

Build a synthetic cyclic causal system with 4 variables (e.g. room temperature, heater power, outside temperature, humidity, connected in a loop). Design soft interventions where you push each variable by a random amount (the interventions are soft, so the change is gradual and noisy). Hide which variables you pushed (unknown targets). Sample 500 experiments. Run SCOUT and recover both (1) the true causal graph and (2) the true intervention targets. Compare against a baseline that assumes the system is acyclic or targets are known.

graph recovery rate = (true edges found + true non-edges correctly rejected) / (total possible edges), and target recovery rate = (percent of intervention targets estimated within 5% of truth)

The demo must clearly show that SCOUT recovers the hidden intervention targets and the cyclic causal structure where simpler methods fail completely.
