MCbiF: Topological Autocorrelation in Multiscale Clusterings

MCbiF measures how clusters evolve across scales by encoding their intersection patterns as a topology, revealing hidden inconsistencies that hierarchical methods miss.

Paper explainersAll themesGraph & Geometric Learning

Real data often splits into clusters in many different ways depending on how closely you zoom in. A dendrogram (a tree diagram) works only if each finer clustering refines the coarser one, but many datasets have clusters that split, merge, and rearrange messily. MCbiF fixes this by building a topological fingerprint of how clusters intersect across all scales, then extracting features that capture what hierarchical methods cannot see.

Zero assumption version

Why dendrograms fail on tangled clusters

When you cluster data at different zoom levels, you often get a sequence of partitions (divisions into groups). A dendrogram assumes each finer clustering is a refinement of the coarser one — every old cluster splits cleanly into new clusters. But real data does not obey this. Clusters at one scale might merge and rearrange at the next, with no parent-child relationship.

The naive approach is to treat each clustering independently and lose the connections between them. Or you force a dendrogram structure even when it does not fit, and you miss the actual cluster evolution. Either way, you throw away information about how the clusters really relate across scales.

The method in one sentence. MCbiF encodes cluster intersection patterns across scales as a topology, then extracts features from the shape of those intersections to describe how clusters evolve.

What the paper changes

What the paper changes

Instead of forcing clusterings into a tree structure, MCbiF directly encodes the intersection graph of all clusters across all scales. It records, for each pair of clusters, how much they overlap, building a topological object that captures the full non-hierarchical evolution.

The hidden quantity

Topological autocorrelation: the stability of clusters across scales

measured quantity  =  Topological autocorrelation

Topological autocorrelation measures whether clusters are stable (stay mostly the same across scales) or unstable (split, merge, or rearrange). If a cluster at one scale cleanly splits into two clusters at the next, autocorrelation is high. If clusters overlap messily, autocorrelation is low and the topology captures that as a shape.

The paper estimates topological autocorrelation via the Hilbert functions of the persistent homology — these are tables that count how many topological features (holes, loops, connected components) exist at each pair of scales. Large counts indicate many cluster rearrangements; small counts indicate stable refinements.

Why it works

Why MCbiF works: topology captures cluster evolution

Here is the core chain: When clusters change non-hierarchically across scales, their intersections form a pattern. That pattern is not random; it has structure that you can measure. By encoding the intersections as a nested sequence of mathematical spaces, you can apply persistent homology — a tool that counts topological features (holes, loops, separate pieces) that survive across scales.

At dimension zero, persistent homology counts how clusters disappear or fragment. At dimension one, it counts loops and tangles — places where three or more clusters overlap in a way that violates the refinement order. These features are stable under small perturbations of the data, so they are reliable signals of true cluster instability, not noise. The Hilbert functions then summarize these features into lists of numbers that capture the full non-hierarchical evolution in a way dendrograms cannot.

Math after the picture

The 2-parameter Hilbert function

First in words:

The Hilbert function H_i(s,t) counts the number of i-dimensional topological features that appear at scale s and persist until scale t. Features are generated when clusters intersect in new ways and killed when they merge or disappear.

Then the compact form:

H_i(s,t) = rank of the module at (s,t) in dimension i

Every symbol:

idimension: 0 (components), 1 (loops), etc.
sthe coarser scale (starting scale)
tthe finer scale (ending scale)
H_i(s,t)count of i-dimensional features born at or before s and alive at t
A tiny worked example
Suppose at scales 1, 2, 3 we have three clusterings with intersections that form a loop at scale 1-2 and break apart at scale 2-3.
Dimension-0 Hilbert: H_0(1,1) = 1 (one cluster), H_0(1,2) = 1 (still one connected component), H_0(1,3) = 2 (cluster fragments into two pieces). The jump signals instability.
Dimension-1 Hilbert: H_1(1,2) = 1 (one loop of overlaps), H_1(1,3) = 0 (loop dissolves). The vanishing feature marks the moment clusters stopped obeying refinement.
These counts become features in the downstream model: e.g. [H_0(1,1)=1, H_0(1,2)=1, H_0(1,3)=2, H_1(1,2)=1, H_1(1,3)=0] encodes the instability pattern.

The Hilbert function is a 2D table of counts, not a single number; it captures the full evolution of clusters across pairs of scales, encoding both where instability occurs and its topological signature.

What can go wrong

What can go wrong

Too few scales or weak differences. If you only have two clusterings or if cluster overlaps are nearly identical across scales, MCbiF sees little topological variation and extracts weak signals for learning.
Noise in cluster assignments. If the clustering algorithm is unstable and produces different partitions of the same data, MCbiF will encode the noise as topological features, not real cluster evolution.
Misaligned scales. If the sequence of clusterings does not correspond to a true multiscale hierarchy (e.g., different random initializations at the same resolution), topological features may not reflect real structure.
Done right. MCbiF excels when you have a genuine sequence of partitions across a controlled parameter (resolution, linkage threshold, time), and you need to detect where cluster assumptions break down.
What a runnable demo should prove

What a runnable demo should prove

Build a small synthetic dataset with clusters that split and merge non-hierarchically as you vary a resolution parameter (e.g., density threshold). Generate clusterings at five different resolutions. Compute MCbiF features (Hilbert functions) for the sequence. Then train a simple regression model to predict the resolution from only the MCbiF features, and a classification model to predict whether the next scale will refine or rearrange the clusters. Compare accuracy against features from dendrograms or independent per-clustering statistics.

accuracy = (correct_predictions) / (total_predictions) for both regression and classification tasks

The demo should make it impossible to miss that MCbiF captures cluster instability signals that flat features and dendrograms cannot, enabling downstream models to learn the true evolution pattern.
