WebShaper: Agentically Data Synthesizing via Information-Seeking Formalization

WebShaper generates training tasks from a formal question structure, because matching reasoning structure to evidence structure produces cleaner information-seeking data.

Paper explainersAll themesAgents & Tool Use

Information-seeking agents need a large amount of training data, but high-quality examples are hard to write by hand. A common shortcut is to gather documents first and then form question-answer pairs from that material. That pipeline often breaks the logic of the task: the collected evidence may support one reasoning path while the written question implies another. WebShaper addresses that mismatch by formalizing the task before retrieval. It defines questions through set-based Knowledge Projection operations, then lets an expansion agent retrieve and validate information while preserving that formal structure.

Zero assumption version

Collected information and required reasoning often do not line up

Training data for information-seeking agents must do more than contain a correct answer. The evidence, the question, and the reasoning path must fit each other. If they do not, the agent learns shortcuts that fail outside the training set.

Many synthesis pipelines start from retrieved information, then write or refine a question after the fact. That can produce a mismatch: the question may ask for a comparison while the retrieved material supports only a lookup, or the answer may depend on a reasoning chain that is not reflected in the evidence layout.

The paper addresses this by formalizing the structure of the question first. Once the desired reasoning pattern is explicit, retrieval and validation can be guided so that the final task stays internally consistent.

The central fix: Specify the reasoning structure first, because data synthesis works only when the question, evidence, and answer follow the same plan.

The algorithm as a flow

What it actually does

Create seed tasks

The pipeline starts from formal task seeds because a seed specifies the kind of reasoning the eventual example should require.

Represent the task with Knowledge Projections

Each task is written as set-theoretic operations so that retrieval and expansion can preserve the intended structure.

Run the expansion agent

The agent retrieves evidence, validates intermediate results, and increases task complexity step by step because expansion should add difficulty without breaking the original reasoning plan.

Validate question-answer consistency

At each step, tools check whether the current evidence still supports the formal task definition so that the final question, evidence, and answer remain aligned.

Train the information-seeking model

The synthesized dataset is then used for training because aligned examples teach the model to follow the intended reasoning path instead of relying on accidental shortcuts.

What the paper changes

What the paper changes

The paper changes the unit of control in data synthesis. Instead of controlling the final text after retrieval, it controls the formal reasoning structure before and during retrieval through Knowledge Projection compositions.

the object it moves  =  Control point for synthesis quality
The hidden quantity

The hidden quantity: reasoning-evidence alignment

measured quantity  =  Consistency between formal task structure and gathered information

A synthesized training example can look polished while still being logically inconsistent. The hidden quantity is whether the retrieved information actually supports the formal reasoning pattern that the question demands. That consistency is not visible from the answer alone.

WebShaper tries to preserve this quantity by using Knowledge Projection compositions as a contract. The retrieval and validation tools are not free to gather arbitrary supporting text. They must gather material that fits the required set operations, because otherwise the final example would teach the wrong reasoning skill.

This quantity matters because information-seeking agents are judged by how they gather and combine evidence. If the training data rewards answers that happen to be right for the wrong structural reason, the agent will learn brittle habits.

Why it works

Why formalization-first synthesis improves training data

The method works because it fixes the task structure before content expansion begins. Once the formal question is written, retrieval is no longer an open-ended search for any useful page. It becomes a constrained search for evidence that satisfies the required operations. That raises consistency because the evidence is gathered to fit the reasoning plan, not the other way around.

The expansion agent then adds complexity in controlled steps. It can retrieve more sources, refine entities, or compose extra operations, but each step is checked against the formal task definition. That matters because complexity without validation tends to create examples that are harder on the surface but weaker in logic.

This structure also explains the benchmark gains. Better data helps because the trained agent sees many examples where evidence collection and reasoning are aligned. The model is therefore pushed toward the right behavior: seek the right information and combine it in the right order so that the answer follows from the evidence.

Math after the picture

The formalization idea in one line

First in words:

A synthesized task is built by composing Knowledge Projection operations over an initial knowledge set, then validating that the answer comes from the resulting set.

Then the compact form:

Q = KP_k o KP_{k-1} o ... o KP_1 (K_0)

Every symbol:

Qthe formal question result after all projection operations
KP_ithe i-th Knowledge Projection operation
K_0the initial knowledge set before expansion
ofunction composition, meaning one projection is applied after another
A tiny worked example
Start with a set of pages about research labs, cities, and project topics.
Apply one projection to keep only labs that work on climate modeling.
Apply a second projection to keep only the cities of those labs.
Apply a third projection to keep only cities with more than one qualifying lab.
The final question can ask for those cities because the answer follows from the composed operations, and the retrieved evidence can be checked against each step.

The equation is useful because it fixes the reasoning order before retrieval expands the task.

What can go wrong

What can go wrong

The formal seed may be too narrow. If the initial Knowledge Projection structure is badly chosen, the system will synthesize many clean but unhelpful examples because all later steps inherit that restriction.
Validation tools may miss subtle mismatches. A retrieval result can appear to satisfy a projection while still supporting a different interpretation, so weak validation can let inconsistent tasks through.
Expansion can overcomplicate the task. If the agent keeps adding operations without checking whether the evidence remains reliable, the example becomes noisy because the answer depends on fragile chains of retrieval.
Done right: the dataset teaches the intended skill. When formalization, retrieval, and validation stay aligned, the final data is stronger because the agent must actually follow the required information-seeking process.
What a runnable demo should prove

What a runnable demo should prove

Build a small synthesis benchmark for multi-step web questions. Generate one dataset with an information-first pipeline and one with a formalization-first pipeline. For each synthesized example, check whether the evidence graph really supports the required reasoning chain, then train the same information-seeking agent on both datasets. The demo should show that the formalization-first data produces better downstream accuracy because its question, evidence, and answer are structurally aligned.

alignment_rate = structurally_valid_examples / total_synthesized_examples

The decisive result is that higher structural alignment during synthesis should translate into better information-seeking behavior after training, because aligned examples teach the model to gather and combine evidence in the intended order.
