Graph Tokenization: Turning Networks Into Text

Convert graph structure into a sequence using smart reordering and token merging, so normal text-based transformers can handle graphs.

Paper explainersAll themesGraph & Geometric Learning

Transformers (the model behind large language models) are brilliant at processing text—but they only work on sequences of symbols. Graphs are different: they have nodes (like cities) and edges (like roads), and the order does not matter. This paper solves that: turn a graph into a sequence by carefully visiting each node and edge in an order that preserves structure, then let a tokenizer compress common patterns into single symbols. The result: transformers that work on graphs without any special architecture.

Zero assumption version

Transformers need sequences, graphs need connections

Transformers changed machine learning by working on sequences—lists of items in order. A sentence is a sequence: word 1, word 2, word 3. A tokenizer turns the text into discrete symbols (tokens) that the transformer understands.

Graphs are different. A node is like a city; an edge is like a road between cities. The graph has no fixed order—node 3 could be anywhere in the structure, and it does not matter. To use a graph with a transformer, you need to decide: in what order do I feed the nodes and edges into the transformer?

A naive approach: just pick an arbitrary order (alphabetical, random). That loses information. The transformer sees 'node 1, edge 1-2, node 2' but does not know this is the same structure as 'node 2, edge 2-1, node 1'—they look different, so the transformer learns two different things for the same graph. That wastes learning.

The paper's solution in one sentence. Serialize graphs into sequences in a deterministic, structure-aware way, then use token merging to compress frequently occurring patterns into shared symbols.

The algorithm as a flow

What it actually does

Measure structure

Count which node-pair and edge patterns appear most often across all graphs in the training data.

Serialize deterministically

Visit every node and edge in an order that always produces the same sequence for the same graph, guided by the pattern frequencies.

Train token vocabulary

Run Byte Pair Encoding (BPE) on the serialized sequences: merge the most common symbol pairs into single tokens, repeat until done.

Encode new graphs

For a new graph, serialize it the same way, then compress it using the vocabulary.

Feed to transformer

Pass the token sequence to BERT or any standard transformer for classification, regression, or other graph tasks.

What the paper changes

What the paper changes

The paper modifies the input to the transformer: instead of the raw graph structure (which transformers cannot handle), it produces a sequence of tokens that encodes the graph faithfully. The transformer itself stays unchanged—it is just a standard BERT model processing sequences as it always does.

The hidden quantity

The hidden quantity: structural determinism

measured quantity  =  Degree of agreement in serialization

Most graph serialization methods (like depth-first search) do not always produce the same sequence for the same graph—they make arbitrary choices at each step. This is called non-determinism. When the sequence changes, the transformer sees the same graph as different things, wasting its learning power.

This paper measures how often two serializations of the same graph produce identical sequences. A deterministic serialization always produces the same sequence; a non-deterministic one produces different sequences. The paper uses graph substructure frequencies to guide the walk through the graph in a canonical (always-the-same) way, ensuring near-complete determinism.

Why it works

Why it works: three gears turning together

A transformer learns by finding patterns in sequences. If you feed it the same graph in different orders each time, those orders look like different patterns, and the transformer wastes time learning each variant separately. By serializing deterministically (always the same order), the transformer sees consistent input and learns the real structure faster.

Next, Byte Pair Encoding (BPE) does the heavy lifting. BPE counts which pairs of adjacent symbols appear most often, merges them into a single new symbol, then repeats. Example: if the sequence has 'node A—edge type 1—node B' appearing 1000 times but 'edge type 2—node C' appearing only 10 times, BPE first merges A—1 into one token, then uses that token wherever it sees the pair. Over many iterations, BPE discovers the building blocks of graphs in your dataset: common motifs like triangles, paths, and hub-and-spoke patterns all become single tokens. When the transformer sees these tokens, it has already lost the noisy details and has the real structure pre-compressed.

Together, the two moves make graphs digestible by transformers. Deterministic serialization means the same graph always looks the same. BPE extracts the frequent structural patterns and squashes them into single symbols. The transformer then processes a compact, consistent sequence that captures the graph's essence.

Math after the picture

The equation: BPE merging logic

First in words:

score_of_pair = count_of_pair * frequency_of_pattern; merge if score exceeds threshold

Then the compact form:

C_new = merge(C_old, argmax_pair(count(pair) × F(pattern_type)))

Every symbol:

C_oldthe current token vocabulary
C_newupdated vocabulary after one merge round
pairtwo adjacent symbols in the serialized graph sequence
count(pair)how many times this pair appears in the corpus
F(pattern_type)the frequency of that pattern type in training data (computed once upfront)
argmax_pairthe pair with the highest score wins the merge
A tiny worked example
Suppose in the serialized sequences, the pair 'node-A edge-1' appears 250 times.
The pattern type 'node-edge' has frequency F = 0.80 (appears in 80% of training graphs).
Score for this pair: 250 × 0.80 = 200.
The pair 'edge-2 node-B' appears 100 times; F = 0.20.
Score: 100 × 0.20 = 20.
BPE merges 'node-A edge-1' into a single token (higher score), leaving 'edge-2 node-B' unmerged.
On the next round, merged patterns are counted again, and BPE repeats.

BPE prioritizes frequent structural patterns, so common motifs (triangles, chains, hubs) become single tokens early.

What can go wrong

What can go wrong

Continuous node or edge features are lost. If nodes have real-valued features like temperature measurements, tokenization requires discretizing them first by turning them into buckets like cold, warm, or hot. This is lossy and may discard fine-grained information.
Very large graphs blow up the sequence. A graph with 100,000 nodes produces a very long sequence. Transformers have computational limits; processing long sequences is slow. The method works best on medium-sized graphs (under ~10,000 nodes).
Training the tokenizer requires a corpus of graphs. BPE is data-driven: you must have many examples to learn real patterns. On a tiny dataset, BPE may not discover useful structure, because frequent pairs need many repetitions to emerge from noise, and you lose the benefit.
Done right. On graph benchmarks (molecular structures, social networks, citation networks), the method outperforms specialized graph neural networks by a wide margin because the tokens discovered by BPE capture the domain's real frequent patterns—triangles in social networks, bond patterns in molecules—so the transformer learns faster and more accurately than a generalist graph network.
What a runnable demo should prove

What a runnable demo should prove

Take a dataset of 100 small graphs (molecular structures, citation networks, or synthetic). Train a graph tokenizer on them: compute substructure frequencies, serialize each graph deterministically, run BPE to convergence. Then: (A) serialize and tokenize a held-out test graph, (B) feed the tokens to BERT (or another standard transformer), (C) measure accuracy on a graph classification task. Show that the transformer-on-tokens score matches or beats a graph neural network baseline on the same task, despite the transformer using no graph-specific operations.

accuracy_gain = (transformer_on_tokens_accuracy - transformer_on_naive_sequence_accuracy) / transformer_on_naive_sequence_accuracy

The demo must show that deterministic serialization plus BPE makes a plain transformer outperform one given the same graph in random order, because consistency plus structure tokens give the transformer clear patterns to learn.
