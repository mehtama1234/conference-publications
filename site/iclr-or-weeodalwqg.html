Explainable Token-level Noise Filtering for LLM Fine-tuning

When you fine-tune an LLM, most training tokens are noise; XTF scores each token on three attributes and masks gradients from the weak ones.

Paper explainersAll themesOptimization

Fine-tuning teaches a large language model a new task by training on examples. The problem: examples are written sentence-by-sentence, but the model learns token-by-token. This mismatch means many individual tokens in each example actually hurt learning. XTF gives every token a report card—three scores that say how useful it is—and then silently drops the bad tokens from training, improving final accuracy by up to 13.7%.

Zero assumption version

Training examples are built at the sentence level, but models learn at the token level

When you fine-tune an LLM, you give it sentences like 'The capital of France is Paris.' The model trains on every single token: The, capital, of, France, is, Paris. But not every token carries useful information for learning the task. Some tokens are just filler because the model already predicted them correctly during pretraining (no new knowledge), or they do not belong to the task's domain (off-topic), or they contradict what the task is trying to teach.

A naive approach: use all tokens as-is. This seems obvious, but it has a hidden cost. Tokens that mislead the model (a word that appears in the input but should not appear in the output) create wrong learning signals. Tokens the model already knew before fine-tuning are redundant. Tokens unrelated to the task just add noise. The model has to learn despite the noise, which makes training slower and less accurate.

The fix. Score every token on how useful it is, keep only the useful ones, and mask out the rest during training.

The algorithm as a flow

What it actually does

Score reasoning importance

Run the full example through the base model and see which tokens it focuses on internally (attention scores measure where the model looks when reading). High attention means the model thinks that token matters for understanding.

Score knowledge newness

Check if the base model already predicts each token correctly; if yes, it is redundant and teaches nothing.

Score task relevance

Compare each token's learned representation (a list of numbers learned during pretraining) to the average of all task tokens; distant ones are off-topic.

Filter by threshold

Tokens scoring low on one or more attributes are marked as noise.

Mask and train

During fine-tuning, silence the learning signals (gradients are the direction the weights should move) from noisy tokens so they do not change the model.

What the paper changes

What the paper changes

XTF changes which tokens contribute to learning. The training dataset stays the same, but the model now learns only from high-scoring tokens and ignores low-scoring ones.

the object it moves  =  learning signals from tokens
The hidden quantity

The hidden quantity: token usefulness

measured quantity  =  token contribution score

Most datasets do not tell you which tokens are actually useful for learning. The paper introduces a way to measure it: for each token, assign a score on three dimensions—reasoning importance (does the model focus on this token when reading the input?), knowledge newness (does the model already predict this token?), and task relevance (does this token belong to the task domain?)—and combine them into a usefulness judgment.

XTF estimates each score using the base model itself: by watching where the model's internal attention mechanism looks (which tokens it focuses on), you learn reasoning importance; by checking if the model's current prediction is correct, you learn newness (if it already gets it right, the token is redundant); and by comparing each token's learned number-list to the average of all task tokens, you learn relevance.

Plain reading. A token is useful if the model's internal attention focuses on it (reasoning importance), if the model does not already predict it correctly (knowledge newness), and if it matches the task's domain vocabulary (task relevance).
Paper reading. Reasoning importance uses the model's attention values. Knowledge newness uses the probability that the model already predicts the token correctly. Task relevance uses distance between the token's learned representation and the average task representation.
Why it works

Why filtering noisy tokens improves fine-tuning

During fine-tuning, the model learns by comparing its predictions to the desired output, calculating how wrong it was (the loss), and nudging its weights in the direction that reduces that loss. Each token contributes a learning signal. Some tokens are useful: they point the model toward the right answer (the model should focus on them, or they teach something new). Other tokens are noise: the model already knows them, or they are off-topic, or they conflict with the task. These create wrong learning signals, pulling the model in the wrong direction.

When you mask the gradients from noisy tokens, you remove the misleading signals before they move the weights. The model's updates are then driven only by tokens that genuinely teach it something new and task-relevant. This removes the contradiction and makes training cleaner: the model does not waste effort learning to satisfy tokens that should not matter for the task.

Math after the picture

One equation: gradient masking

First in words:

gradient after filtering equals original gradient multiplied by a mask; mask is 1 for kept tokens and 0 for filtered tokens

Then the compact form:

g_filtered = M * g_original, where M_i = 1 if token_i passes filters, 0 otherwise

Every symbol:

g_filteredthe gradient update that actually moves the weights
g_originalthe gradient computed from all tokens before filtering
M_ithe mask: 1 to keep token i, 0 to silence it
token_ithe i-th token in the training example
A tiny worked example
Token 1 (France): RI=4, KN=3, TR=4 -> all high -> M_1 = 1. Gradient for this token counts fully.
Token 2 (of): RI=1, KN=2, TR=2 -> all low -> M_2 = 0. Gradient for this token is zeroed out.
Token 3 (The): RI=1, KN=3, TR=1 -> mixed, but relevance fails -> M_3 = 0. Gradient zeroed.
Result: only useful tokens drive weight updates. Noisy signals are removed before they mislead training.

By zeroing the gradient from noisy tokens, the weight update comes only from good signals. This works because the noisy signals are contradictory and pull in wrong directions; removing them means the weight change is guided only by useful tokens.

By silencing noisy tokens before they move the weights, the model learns faster from the clean signal. Useful tokens all push the weights in the same direction (toward learning the task); noisy tokens push against them. Remove the noisy pushes, and the useful signals steer the weights more directly toward the answer. Real results show up to 13.7% improvement.

What can go wrong

What can go wrong

Threshold too aggressive. If you filter out too many tokens, you remove useful signal along with the noise. The model learns from too few examples and underfits.
Scoring method is coarse. Attention scores, prediction accuracy, and semantic distance are proxies. They sometimes miss subtle usefulness or mis-flag a token as noise.
Domain mismatch. Task relevance is computed by comparing to the task domain average. If the task is very different from pretraining, this score is unreliable.
Done right. Tune the threshold on a validation set. Test different scoring methods. Use XTF as a pre-processing step to augment data, not replace it entirely.
What a runnable demo should prove

What a runnable demo should prove

Build a tiny fine-tuning job: take a base model, a small training set (20 examples, 30 tokens each), and a test set. Run standard fine-tuning on all tokens. Run XTF filtering (score each token, remove the bottom 40%). Fine-tune again. Measure accuracy on the test set for both runs. Plot accuracy over training steps. The filtered version should reach higher accuracy with the same number of training steps, or reach the same accuracy in fewer steps, because the weight updates are no longer pulled in contradictory directions by noisy tokens.

speed_gain = steps_unfiltered / steps_filtered to reach target_accuracy

The core claim is that filtering noise-only tokens removes the contradictory signals that pull weights in the wrong direction. Measure that the filtered version reaches the target accuracy in fewer training steps than the unfiltered version. This proves that the noisy tokens were slowing learning (not helping it), not that you are losing information.
