Explainable Token-level Noise Filtering for LLM Fine-tuning Datasets

Most fine-tuning datasets are built sentence-by-sentence, but LLMs learn one word at a time; XTF finds which words are noise and silences them during training.

Paper explainersAll themesOptimization

When you teach an LLM a new skill, you give it examples to learn from. But those examples are built sentence-by-sentence, as complete thoughts. The problem: LLMs do not learn sentence-by-sentence. They learn one word (or token) at a time, looking at what came before and guessing what comes next. This mismatch means some words in your training data are actually harmful noise that pulls the model in the wrong direction. XTF solves this by identifying which words are problematic and turning down the model's learning signal for just those words.

Zero assumption version

Why sentence-level datasets break at the word level

When you build a dataset for fine-tuning, you write or collect complete sentences and documents. Each sentence is grammatically correct and on-topic as a whole. You assume the model learns the entire sentence at once.

But LLMs learn differently. During training, the model reads one token (word or word piece) at a time and tries to predict the next one. If a sentence contains even one confused or irrelevant word among the good ones, the model takes a learning step based on that word. The word pulls gradients (the training signals that update the model) in a wrong direction. The model weakens slightly because of just that one token.

Repeating this across thousands of training examples, these token-level mistakes add up. The model learns slower, gets worse at the new skill, and ends up performing worse than if the data were cleaner.

The mismatch Fine-tuning data is curated at the sentence level, but language models optimize at the token level.

The algorithm as a flow

What it actually does

Compute three scores per word

Reasoning importance: is this word needed to follow the logic? New ideas: does this word teach something the model did not already know? Task relevance: does this word matter for the goal?

Combine scores into a noise flag

If a word scores low on all three, or low on the ones that matter most for this task, flag it as noisy.

Train normally, then zero-mask

During training, run the model as usual, but when a noisy word's gradient is computed, multiply it by zero before updating the weights.

The model still reads noisy words

The noisy words are still fed into the model as input (they are part of the context), but they do not drive the weight updates.

Learn only from good words

The model's weights (its learned numbers) change only based on the clean, high-value tokens; noise signals are discarded.

What the paper changes

What the paper changes

Most fine-tuning just trains on all tokens equally. XTF changes which tokens drive the gradient updates: only tokens that score high on reasoning importance, new ideas, and task relevance get to update the model weights.

The hidden quantity

The three attributes that measure token value

measured quantity  =  reasoning importance, new ideas, task relevance

XTF does not use a single abstract 'importance' score. Instead, it breaks token quality into three concrete, observable attributes. Reasoning importance means: does this token carry essential logic or facts needed to reach the correct answer? New ideas means: is this token teaching the model something it did not already know? Task relevance means: does this token directly relate to the goal of the task (e.g., for math, solving the problem; for code, the output).

The paper scores each token on all three using heuristic scoring methods (rules or learnable functions). A token with low scores on all three is almost certainly noise and gets masked. A token high on even one of these attributes is likely worth learning from.

Why it works

Why gradient masking on noisy tokens improves learning

When you train a language model, each training step computes how far off the model's prediction was from the correct answer. That error is a signal. The model then adjusts its weights (parameters) in the direction that would have made the error smaller. This adjustment is called a gradient update.

If a token in your training example is noisy (low on reasoning, new ideas, and task fit), the model's error signal at that token is misleading. Updating weights based on a misleading signal teaches the model the wrong pattern. By masking the gradient at that token—setting it to zero—you prevent the model from taking a step based on noise. The model only updates based on tokens that carry genuine, task-relevant information. This is faster learning because every update is pointed in the right direction, and it is more accurate learning because the model avoids ingraining spurious patterns from low-quality tokens.

Math after the picture

Gradient masking equation

First in words:

Masked gradient is the original gradient multiplied by a mask value (0 or 1) per token, which is 1 if the token scores high enough and 0 if it scores low.

Then the compact form:

grad_masked_t = M_t * grad_t

Every symbol:

grad_tgradient at token t (how much to update weights based on token t)
M_tmask value for token t: 1 if token is good, 0 if noisy
grad_masked_tfinal gradient used to update weights (zero if token is masked)
A tiny worked example with 4 tokens
Token 1 (good word): scores 0.9 on reasoning, mask M_1 = 1, gradient grad_1 = 0.05, masked: 1 * 0.05 = 0.05 (update happens)
Token 2 (confusing word): scores 0.2 on all three, mask M_2 = 0, gradient grad_2 = 0.04, masked: 0 * 0.04 = 0 (no update)
Token 3 (good word): scores 0.8 on task relevance, mask M_3 = 1, gradient grad_3 = 0.06, masked: 1 * 0.06 = 0.06 (update happens)
Token 4 (weak but useful): scores 0.6, borderline, mask M_4 = 1, gradient grad_4 = 0.03, masked: 1 * 0.03 = 0.03 (update happens)
Total weight update = 0.05 + 0 + 0.06 + 0.03 = 0.14; without masking would be 0.18, but the 0.04 from token 2 was harmful noise, so 0.14 is cleaner.

By zeroing out gradients from low-scoring tokens, the model only learns from tokens that are logically important, teach new ideas, or matter to the task.

What can go wrong

What can go wrong

Scoring method is heuristic XTF relies on scoring functions to decide which tokens are noisy. If the scoring function is weak (misses real noise or flags good tokens), the filtering will fail. A model that trains on clean tokens but the scoring was wrong learns on randomly bad data.
Over-masking starves the model If the threshold for masking is too low (very aggressive filtering), the model may end up training on too few tokens, starving the learning signal. The model updates so rarely that it learns slowly, defeating the purpose.
Task-specific thresholds are brittle XTF tunes the filtering thresholds per task. If you move to a new task or a dataset where tokens appear with different frequencies, the old thresholds may not transfer, and you have to retune.
Noise filtering works best on noisy data If your fine-tuning data is already well-curated and clean, masking does little. XTF gains the most when applied to real-world datasets that have actual token-level errors, ambiguities, or off-topic passages.
What a runnable demo should prove

What a runnable demo should prove

Build a small fine-tuning task (e.g., a few-shot math problem, code generation, or medical QA) with a dataset you intentionally add noise to: replace 10-20% of tokens with random words or off-topic phrases. Train two models: one with all tokens, one with XTF filtering. Measure accuracy on a held-out test set. Verify that XTF recovers performance close to training without noise, while the all-tokens baseline performs poorly.

accuracy_xtf / accuracy_no_filter (should be > 1.0, showing XTF recovers performance lost to noise)

The demo makes it impossible to miss that noisy tokens harm learning, because the intentionally corrupted data shows real performance loss, and that masking their gradients is a simple, effective fix because it cuts the bad signal without breaking the training process.
