SEAgent: Self-Evolving Computer Use Agent with Autonomous Learning from Experience

An agent learns to use unfamiliar software by trying tasks itself, learning from failures, and graduating from simple to hard problems.

Paper explainersAll themesAgents & Tool Use

Today's image-reading language models can follow a human's instructions on a computer screen and click where told, but only on software they were trained on. New software confuses them because no human labeled examples of "how to use this." SEAgent solves this by letting the agent teach itself: it tries tasks on new software, learns from every attempt, and gradually progresses from easy questions to hard ones.

Zero assumption version

Agents stuck on unfamiliar software without human examples

A vision-language model (a model trained to read images and understand text) can click on buttons if it saw many human-labeled examples during training: "here is a screenshot of Gmail, click the archive button." But when you drop it on new software it has never seen, the model guesses wrong. The obvious fix — collect thousands of human annotations for every new piece of software — is slow and expensive.

The real trap: the model learned to copy patterns from human examples, not to reason about software. When you show it new software, the patterns it learned do not apply.

The problem in one sentence. Models trained on human examples fail on new software because there are no examples to copy.

What it actually does

Agent tries a task

On unfamiliar software, the agent guesses what button to click to achieve a simple goal.

World state judge rates the attempt

A separate model compares the screenshot before and after to score whether progress happened.

Curriculum engine picks the next task

Based on what the agent can already do, the engine generates a slightly harder task.

Agent learns from failure and success

Failures are imitated in reverse (learn what NOT to do). Successes are reinforced with a reward-based nudge.

Specialist insights merge into one

Each software's lessons are pooled into a single model that works across software.

What the paper changes

The one thing the paper changes

The agent's policy — the learned rules inside the model that decide what to click given a screenshot. Instead of copying human examples, the policy is rewritten by the agent's own experiences: failure teaches it to avoid those actions; success teaches it to repeat them.

the object it moves  =  agent policy
The hidden quantity

World State Progress: measuring real change

measured quantity  =  whether a click moved toward the goal

The core hidden quantity is the state change score: a number measuring whether the agent's action on the screenshot actually pushed the problem forward. A click on the right button improves the score because it changes the screen in a way that makes the task closer to done. A click on the wrong area drops it because the screen stays the same or moves backward. This is measured by comparing two images: the screen before and the screen after.

The World State Model (a separate image-reading model) judges each action: "did the desktop actually move closer to what we asked?" If yes, the action is a win. If no, the action is a loss. The agent learns to predict and repeat wins, and to avoid losses, because it can now see objective proof that the action worked.

Why it works

Why the method works: learning from your own mistakes

The core insight: an agent does not need human examples to learn; it needs feedback. The World State Model provides feedback by rating screenshots. This feedback is then split into two learning paths.

On failure: the agent studies what it tried, and the model nudges it away from those actions. It is like your hand learning not to touch a hot stove — the pain teaches avoidance.

On success: the agent studies what it tried, and a reward-based nudge (a training method called GRPO) reinforces the successful action. It is like practicing a violin piece until your fingers remember the chord.

The curriculum engine magnifies this learning. Instead of random tasks, it feeds the agent a ladder of difficulty: "click a button, then type text, then sort a column, then create a pivot table." Learning a hard jump before the easy steps wastes effort. Learning step-by-step sticks. Each new task is designed based on what software features the agent has not yet mastered, so every task teaches something fresh.

Math after the picture

The learning formula: imitation on failure, reinforcement on success

First in words:

The loss has two parts: one penalizes the agent for doing what failed (negative imitation), one rewards the agent for doing what succeeded (reward-based nudging, or GRPO). The curriculum weight means early tasks matter less; hard tasks matter more as the agent improves.

Then the compact form:

L_total = L_fail + alpha * L_success + curriculum_weight * task_difficulty

Every symbol:

L_failpenalty for imitating actions that did not move toward the goal
L_successreward boost for actions that moved the agent forward
alphahow much to emphasize learning from wins versus learning from losses
curriculum_weightimportance of the current task, higher for harder tasks
task_difficultya score from the curriculum engine reflecting how complex this task is
A tiny worked example
Task: click the delete button to erase a row. Agent first tries clicking the save button (failure).
L_fail = 1.0 (strong penalty for copying that wrong action)
Agent then tries clicking delete (success).
L_success = 0.5 (reward for the right action, earlier success so smaller boost)
Task 3 of 10 curriculum: curriculum_weight = 0.3 (early task, counted lightly)
L_total = 1.0 + 0.5 * 0.5 + 0.3 * 3 = 1.0 + 0.25 + 0.9 = 2.15 (agent learns to avoid save, copy delete, and optimize harder tasks)

The agent's policy shifts because it is penalized for failure and rewarded for success, weighted by curriculum difficulty so easy mistakes do not overshadow hard-task learning.

What can go wrong

What can go wrong

The World State Model itself is biased. If the model that judges progress is trained wrong, it will give bad feedback. A model that thinks "pressing random buttons is progress" will teach garbage. The state judge has to be accurate.
Tasks are too hard too fast. If the curriculum jumps from "click a button" to "write a complex SQL query," the agent gives up. Curriculum generation has to respect the agent's current skill.
Specialist knowledge does not transfer. An agent trained only on Gmail might learn Gmail-specific tricks that break on Slack. The specialist-to-generalist merge has to carefully blend what worked on different software.
Done right: learn from your own feedback. With an honest state judge, a sensible task ladder, and careful merging of specialist insights, the agent bootstraps expertise on new software without humans.
What a runnable demo should prove

What a runnable demo should prove

Pick a piece of unfamiliar software (not in the agent's training data). Teach it one common task: "open a file and save it as a new version." Let the agent explore for a fixed number of tries. Measure: what percentage of final attempts are successful?

task_success_rate = (successful_clicks_on_new_software / total_attempts_after_learning) * 100

The demo must show that without human labels, the agent's success rate climbs as it tries more tasks. Without SEAgent, it stays low. With SEAgent, it rises.
