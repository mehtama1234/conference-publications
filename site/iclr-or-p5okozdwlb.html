MicroMix: Efficient Mixed-Precision Quantization for Large Language Models

Use different precision levels (4-bit, 6-bit, 8-bit) for different parts of neural networks to match new graphics chips and keep accuracy while speeding up inference.

Paper explainersAll themesOther

Large language models are slow to run because they store billions of numbers. Quantization (storing numbers with fewer bits) shrinks these numbers, making them faster to multiply because fewer bits mean shorter operations and less memory to move around. But recent advances only use one precision level everywhere. MicroMix picks different precision levels for different parts, matching the new FP4 capabilities of NVIDIA's Blackwell chips and preserving accuracy where it matters most.

Why uniform quantization leaves efficiency on the table

When a model runs inference (answers questions using a finished model), every multiplication and addition happens on graphics chips. These chips used to be slow at 4-bit math but fast at 16-bit math. Newer Blackwell chips have dedicated hardware for 4-bit floating-point math (FP4), which is way faster than 16-bit because the circuitry is optimized for that specific format—less silicon is needed and operations complete in fewer clock cycles.

But existing quantization kernels (the low-level code that runs on the graphics chip) force all activations (the intermediate numbers flowing through the model during inference) into a single 4-bit format. This mismatch wastes the new hardware's capability. A beginner might try squeezing everything into 4 bits uniformly to maximize speed. However, some parts of the computation are sensitive to rounding errors: when you round a sensitive number, the downstream predictions change by a lot, because tiny input changes amplify through the model's layers. So uniform 4-bit encoding loses accuracy badly.

In one sentence. The paper mixes different precision levels (4, 6, and 8 bits) across the model to preserve accuracy while exploiting new fast hardware.

The hidden quantity

Quantization error: where precision hurts accuracy

measured quantity  =  Quantization error per channel

When you round a number to fewer bits, you lose information. A quantization error is the difference between the true value and the rounded value. Some parts of the model tolerate this loss; others do not.

MicroMix estimates the quantization error for each activation channel (a list of numbers flowing through the model) by comparing 4-bit output to high-precision output. Channels with high error get flagged for higher precision; channels with low error stay at 4 bits.

Why it works

Why selective precision works

Modern graphics chips (Blackwell) have hardware that does 4-bit floating-point math very fast, but that hardware can only represent numbers at a coarse 4-bit resolution. When you round an activation to 4 bits, some information is lost. If that activation is used in a sensitive calculation (one where small changes cause big errors downstream), the model produces wrong predictions.

MicroMix solves this by using a threshold to detect which activation channels are sensitive. When rounding to 4 bits causes error above the threshold, the paper keeps those channels at 6 or 8 bits instead. Most channels can tolerate 4-bit rounding because they are not sensitive; only a small fraction matter. So you can preserve accuracy by protecting the few sensitive channels while keeping the majority at 4 bits and reaping the speed benefit.

The mechanism works because the graphics chip's GEMM kernel (the multiply routine) is redesigned to handle mixed formats in a single pass. Channels at different precisions are processed together without any penalty—no branching or extra copies.

Quantization threshold as a decision rule

First in words:

For each activation channel, if the quantization error (difference between 4-bit rounded value and true value) exceeds a threshold, assign higher precision; otherwise use 4-bit.

Then the compact form:

if error_channel > threshold_t then precision = 8bit else precision = 4bit

Every symbol:

error_channelMeasured difference between true activation and 4-bit version
threshold_tCutoff error value chosen to balance accuracy and speed
precisionBit-width assigned: 4, 6, or 8
A tiny worked example
Channel 1: true value 0.7583, 4-bit rounded 0.75, error = 0.0083. Threshold = 0.01. Error < threshold → use 4-bit, save speed.
Channel 2: true value -2.1456, 4-bit rounded -2.00, error = 0.1456. Threshold = 0.01. Error > threshold → use 8-bit, preserve accuracy.
By tuning the threshold, the algorithm protects only the channels that need it, leaving most at 4-bit.

The threshold is the decision point: cross it, and you get higher precision where it matters.

What can go wrong

What can go wrong

Threshold tuned wrong. If the threshold is too low, almost every channel gets high precision, and you lose the speed gain. If it is too high, sensitive channels stay at 4-bit and accuracy collapses.
Hardware does not support mixed precision. This method only works on Blackwell chips with the right GEMM kernel. Older graphics cards cannot run it.
Error estimation is wrong. If the algorithm mis-measures quantization error (e.g. uses a small batch that does not represent real inference), it assigns precision to the wrong channels.
Done right. Threshold is tuned on a representative sample. Hardware is Blackwell or compatible. Error estimation uses realistic activation patterns from a full inference pass.
What a runnable demo should prove

What a runnable demo should prove

Build a small language model (any model, a few hundred million weights to learn), quantize it with uniform 4-bit precision, measure accuracy on a downstream task (like zero-shot classification). Then run MicroMix: measure quantization error per channel, assign mixed precision based on the error threshold, and measure accuracy again. Plot accuracy (y-axis) against average bit-width used (x-axis). The curve should show that mixed precision recovers most of the accuracy loss while staying close to the speed of uniform 4-bit.

accuracy_recovery = (mixed_acc - uniform_acc) / (full_acc - uniform_acc); speedup = time_uniform / time_mixed

The demo makes it impossible to miss: mixed precision with a smart threshold restores accuracy without sacrificing the speed benefit of quantization, because protecting only the sensitive channels avoids the worst rounding errors while keeping the majority of operations fast.
