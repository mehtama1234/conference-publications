Evaluating Agents and Reinforcement Learning in Real Settings

Papers test AI agents trying to solve actual problems like cybersecurity, power systems, travel planning, or video game strategy — measuring whether they can act in complex real-world scenarios.

All themesField mapMathematicsAll explainers
What this is

An agent is a system that takes actions over time to solve a problem. It might be an AI playing a game, a robot trying to pick up an object, a program trying to defend against a cyberattack, or a planner booking flights and hotels to get you somewhere. Testing an agent is not like testing a model that just answers one question. You have to simulate a whole sequence of decisions and see whether the agent reaches its goal. This subtheme is about building environments and benchmarks where researchers can measure how well agents learn and act.

The difficulty is that real-world agent problems have delays, surprises, and cascading consequences. If an agent makes a mistake, the world changes in ways it has to recover from. If it is learning, it might be exploring and failing over and over before figuring things out. Benchmarks have to test both: can the agent learn from trial and error (the classic reinforcement learning problem), and can it handle the kind of complex, long-term planning humans face? A power grid agent has to keep the system stable while responding to outages; a travel planner has to route through real constraints (weather, prices, time zones); a cybersecurity agent has to detect and respond to attacks in a realistic network. Each domain has its own twists that make simple simulation tests inadequate.

The papers in this area build two kinds of testing environments. Some create detailed simulators of real domains—power grids, network security, travel booking—where agents can be trained and tested without real-world risk. Others propose metrics that measure not just whether an agent succeeded, but how well it adapted, whether it learned over time, and whether it handled the unexpected. The goal is to move from testing agents on toy problems to testing them on problem-spaces that feel like the real world.

How the work breaks down

Testing whether an AI agent can solve real problems splits into five directions: building simulators of actual domains (cybersecurity attacks, power grids, coding tasks) where agents learn without real-world risk, measuring how well agents adapt when problems change or surprises happen, checking if agents can handle multi-step reasoning and work together with other agents, testing specific skills like memory and tool use over long conversations, and finally catching gaps in safety and fairness before deploying agents to users.

Simulators of Real-World Domains

Testing agents on toy problems misses what makes real domains hard. Power systems have cascading failures; cybersecurity tasks demand discovering hidden vulnerabilities; DevOps work spans monitoring, deployment, and recovery. This group builds simulators where agents train and test without burning down actual infrastructure or exposing real networks.

The Cybersecurity Gym papers (32, 33) set agents loose against 920 real vulnerabilities across 139 software projects. Top agents achieve around 20% success and discovered 35 zero-day vulnerabilities—proving the benchmark is real and hard. ProOPF (71) benchmarks LLM agents on power system optimization, a domain where mistakes cascade across grids. DevOps-Gym (35) tests agents on the full software cycle: development, deployment, monitoring. Best models hit only 15% on new monitoring tasks, exposing how far agents are from automating real operations. SimuHome (75) creates a temporal-aware smart home simulator where agents must schedule device actions (turning on HVAC before someone arrives) while respecting constraints. Virtual Community (85) goes further, enabling multi-robot coordination challenges where agents must reason about how actions in one part of a community affect others. Each simulator trades real risk for the ability to run thousands of experiments and collect statistics on where agents fail.

Agent Ability Under Surprises and Long Tasks

Agents break when the world doesn't match training. A power grid agent trained on normal conditions fails when outages happen. A research agent that worked on simple questions struggles when asked to synthesize across dozens of papers. This group measures how agents handle tasks that evolve, grow in complexity, or throw unexpected obstacles.

DAComp (3) tests agents on the full data pipeline—extracting data, cleaning it, analyzing it, reporting results. It finds that top agents succeed on less than 10% of data extraction tasks and below 40% on analysis tasks. The bottleneck isn't code generation; it's orchestrating a whole workflow and recovering from dead ends because errors in one step cascade into later steps. LiveResearchBench (6) measures how well agents conduct deep multi-step research, following threads through citations and evidence. The benchmark catches failures in synthesis and verification that multiple-choice tests would miss because real research requires integrating facts across many papers, not just answering isolated questions. EvoClaw (36) puts agents into a scenario that mimics real software development: code changes over time, new features break old tests, bugs hide in continuous evolution. Performance drops from 80% on isolated tasks to 38% when forced to maintain long-term consistency—exposing how agents struggle with system-wide consequences because each code change affects the entire system. LOCA-bench (52) grows the context window for a task scenario (adding more facts, emails, documents) and watches agent performance degrade. Advanced context-management techniques (summing key facts) help because they filter signal from noise, but naive approaches collapse when buried in facts because information retrieval becomes unreliable. TestExplora (81) asks agents to generate tests that would catch real bugs, which requires understanding both the code and possible failure modes; only 16% of generated tests find bugs because most miss the corner cases where systems actually break. MEAL (59) is the first benchmark for multi-agent RL over long task sequences, discovering failure modes that only show up when the sequence is long and agents must coordinate over hundreds of decisions because coordination problems emerge at scale in ways that short problems don't expose.

Multi-Step Reasoning and Agent Coordination

Solving one step is not enough. A travel planner must book flights, hotels, and rental cars in sequence, undoing earlier choices if constraints fail. A team of robots must coordinate to move an object no single robot can lift. Agents must reason about what other agents will do—a game player must predict opponents, a negotiator must model what the other side wants. This group tests reasoning across multiple linked decisions and multi-agent scenarios.

InnoGym (5) evaluates whether agents can come up with creative solutions. It finds agents do produce new ideas but fail when executing them: agents suggest approaches that have never been tried before but can't apply them reliably, and performance varies wildly from run to run. This splits the ability to imagine from the ability to deliver consistently—agents can conceive but can't execute. Agent-X (15) gives agents vision and tools (cameras, APIs, spreadsheets) and asks them to complete multi-step tasks like extracting information from a webpage and updating a file. Even best models hit under 50% success, with failures scattered across tool selection, visual understanding, and chaining steps. The Decrypto Benchmark (82) forces agents into games where they must predict what other players think—a test of theory of mind. LLMs lag behind humans, and recent reasoning models actually perform worse than older ones at this task, a surprising gap. Benchmarking ICRL for Ad-Hoc Teamwork (23) tests in-context reinforcement learning where an agent meets new teammates it has never trained with and must adapt in real time. Standard algorithms underperform random baselines, suggesting agents learn brittle shortcuts rather than adaptive policies. CoNavBench (29) measures collaborative navigation where two agents must coordinate movement through a building—neither can see what the other sees, so coordination is essential. Agents using collaborative policies reduce completion time compared to solo approaches, validating the benchmark's ability to measure true coordination gains. Credit-Budgeted ICPC (31) adds resource constraints: agents must pay for every action they take (code runs cost money, tool calls cost money). This exposes policy trade-offs: identical models diverge in self-play depending on risk appetite and budget, turning a single-agent problem into a game theory problem.

Measuring Memory, Simulation, and Tool Use Over Time

Agents operate over long conversations where they must remember what was said, simulate outcomes of actions, and use tools (code, APIs, sensors). Testing these requires long-running environments and metrics that capture both accuracy and consistency. This group builds benchmarks that force agents to maintain state across dozens of steps.

SimBench (9) measures whether LLMs can simulate human behavior—given a scenario, predict how a human would act. Best models score 40.8 out of 100. Simulation ability correlates with deep reasoning (r=0.939 with MMLU-Pro), suggesting that agents that invest computational effort in multiple reasoning steps better understand human psychology, because more careful reasoning captures human motivations and constraints. Performance scales logarithmically with model size, so bigger alone doesn't fix it because simulation requires behavioral reasoning, not just parameters. AMemGym (14) builds memory tasks for conversational agents: hold a fact from ten turns ago, recall when asked. Standard approaches (retrieval-augmented generation, long-context windows, memory modules) all have performance gaps the benchmark exposes diagnostically. Beyond a Million Tokens (24) shows that even with 1M token context windows, agents forget or conflate information as conversations lengthen. A proposed memory system (LIGHT) adds episodic recall, working memory, and scratchpads, improving performance 3.5%–12.7% across different models tested. MCP-Bench (58) tests agents using Model Context Protocol tools (a new standard for connecting agents to external APIs like email, spreadsheets, databases). Agents struggle with understanding tool schemas (what inputs a tool accepts), planning which tools to call in sequence, and completing cross-domain tasks that require combining multiple tools. OSWorld-MCP (66) extends this by measuring how much agents actually use available tools: they improve from 8.3% to 20.4% task success when MCP tools are present, but invoke them only 36% of the time, suggesting they don't reliably recognize when tools would help. VLA-Arena (83) benchmarks vision-language-action models (agents that see images and take actions like a robot would). Agents memorize specific scenarios rather than generalizing, perceive visual details superficially, and ignore safety constraints—three gaps that matter for real deployment.

Catching Safety and Fairness Failures at Scale

Before deploying an agent, you need to know it will not produce jailbreaks, biased decisions, hallucinated facts, or outputs that mislead users. This group builds large benchmarks and metrics to catch failures that small pilot tests miss.

SparseEval (10) answers a practical question: how many examples do you need to reliably rank models? It shows that no micro-benchmark method can distinguish models 3.5 points apart on MMLU-Pro or 4 points on BIG-Bench Hard without at least 250 examples—a hard constraint for evaluation at scale because small samples have high variance. SparseEval uses sparse optimization to reduce that cost while keeping ranking consistent. SpeechJudge (11) evaluates whether an automated metric can match human judgment of speech naturalness. It achieves 77.2% agreement with human raters, substantially better than existing audio metrics because it trains on real human preferences rather than heuristics, opening a path to automated evaluation of speech-based agents. Structure-aware Core-set Selection (1) addresses a different cost problem: which data points do you actually need to test? It preserves model ranking using just 10% of data, outperforming other selection methods by up to 23.2%. That speedup matters when evaluating hundreds of agents. LogiConBench (7) builds 280,000 logical reasoning tasks that remain hard for frontier models (best achieves 34% exact accuracy), creating a floor beneath which any safety-critical agent should be evaluated. HUME (45) measures the gap between human and AI performance on text embeddings (vectors that represent meaning, used to retrieve documents by similarity). Humans achieve 77.6%, best models 80.1%, but LLM annotators only reach 76.1%—revealing variability across annotators that matters for benchmarking because different people judge differently. PluriHarms (70) collects 20,000 human judgments on how harmful AI outputs are, and discovers that personalization (tailoring harm predictions to individual annotators) increases prediction accuracy, and that risk imminence, harm tangibility, and annotator traits (toxicity experience, education level) systematically explain disagreement because harm is relative to who is judging and their context. This complexity shows why static harm benchmarks fail to generalize.
