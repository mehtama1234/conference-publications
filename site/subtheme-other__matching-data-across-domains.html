Matching data across domains

Papers on finding similarities between items, matching related data when sources differ, and searching through high-dimensional spaces efficiently.

All themesField mapMathematicsAll explainers
What this is

You often need to find which items are similar when they come from different sources. For example, matching faces across two surveillance cameras that have different lighting and angles. Finding the same user who posted on both Twitter and Reddit but with different usernames. Identifying the same protein across studies done in different labs with different equipment. The data looks different — different formats, different resolutions, different representations — but the underlying reality is the same.

The hard part is that the differences in representation can be as large as the real differences between items. A face under bright sun looks very different from the same face at night, even to the naked eye. If your algorithm just compares pixels, it will fail. You need to extract something deeper — a fingerprint or signature that captures the essential identity of the thing, regardless of how it is presented. And you need to do this efficiently when the search space is huge. If you have a million faces and need to find matches, checking every pair is too slow.

Researchers build systems that learn embeddings — representations in a high-dimensional space where similar items end up close together, and dissimilar items end up far apart. Some use contrastive learning, where you show the model pairs of similar items and tell it to bring them close together, and pairs of different items and tell it to push them apart. Some use metric learning, which explicitly optimizes for the distance metric — the rule for measuring how far apart two items are. Some use efficient search structures, like trees or hashing schemes, to find nearby items without checking everything. The goal is fast, accurate matching across domains where the raw data looks completely different.

How the work breaks down

When you need to find matching items across different sources, the work splits into several directions: speeding up the search itself when databases have millions of records, improving how retriever systems rank candidates so the best matches float to the top, learning better distance metrics so that similarity measurements actually capture what matters, and adapting those learned representations across different domains so what you learned in one place works in another.

Fast nearest neighbor search in massive databases

A fundamental problem: when you have a million numeric representations (embeddings—numbers that encode what an item means) to search through, checking every pair to find the closest ones is too slow. You need data structures that skip obviously wrong candidates. DISCo tackles this by building an index where not all candidates need evaluation, achieving near-optimal coverage while keeping search time sublinear—meaning the search time barely grows even as the database explodes. This solves the scale problem directly.

The Projection-Augmented Graph approach (PAG) takes a different angle: instead of hierarchies like HNSW, it uses a projected graph structure that gets indexed differently. Because it skips unnecessary distance calculations through this projection strategy, it runs up to five times faster per query, and it does this without missing neighbors you would have found with slower methods. Welfarist Formulations then tackles a subtler matching problem: finding neighbors that are not just closest but also diverse, so your result set covers different aspects of what similarity could mean—important when stakeholders want options rather than a single greedy best match. All three papers agree on the core need: matching only makes sense if you can do it at scale.

Ranking and reranking to surface the best matches

Once you retrieve candidate matches, the question becomes: which ones are actually right? A raw retriever gives you a rough ranking, but it misses nuances. The real work is learning to rerank intelligently. Denoising Neural Reranker focuses on this by modeling noise in how retrievers score items—noise from inconsistent indexing, unstable numeric representations of items, or just the fact that retrievers are trained on proxy signals rather than the true matching objective. By understanding this noise and adjusting for it adversarially, the reranker learns to trust and correct the retriever's scores in smarter ways.

CRAMER (Control via Request-Aware Masking) adds another layer: when you're matching across domains, a naive reranker might work perfectly in one domain but fail catastrophically in another. CRAMER learns to mask (ignore or downweight) features that don't generalize, so the same reranker can adapt to new domains with minimal extra work. Rejuvenating Cross-Entropy Loss (a loss function that measures matching accuracy—a specific way to penalize wrong matches) and Ranking Free RAG both attack the gap between theoretical correctness and practical performance—one through knowledge distillation (teaching a smaller reranker to mimic a larger one's better judgments) and the other by replacing reranking entirely with smarter initial selection, skipping the rerank step when the domain is sensitive or adversarial. The throughline: good matching means rethinking how retrieval and ranking interact, not just optimizing them separately.

Learning to match across different data formats

A harder problem: your data comes in wildly different formats. ProofBridge matches natural language proofs to formal proofs in Lean by learning joint embeddings—a shared space where a proof written in English ends up close to its formal version, even though they look nothing alike. The system matches by translating to this shared representation, then verifies the match is real by proving semantic equivalence in both directions. This handles domain crossing because the embedding space becomes a Rosetta Stone between languages.

Task-Aware Data Selection tackles format diversity at the data selection level: you have 300,000 candidate training samples in mixed formats and labels, and you want to pick only 10,000 that will fine-tune a language model well. The system learns proxy labels that predict task-specific usefulness, then matches the mix of selected samples to the mix of what matters for your task. The result: 10K samples beat methods using much more data, because every sample was matched carefully to the task. The ESG learning paper takes the matching principle further: it learns how to measure similarity between companies based on their environmental, social, and governance data—so that 'similar companies' cluster by their actual ESG profile instead of raw financial features. This learned similarity rule enables grouping companies by how they evolve over time and searching through all companies to find truly comparable peers, which means financial analysts can find the right matches even when raw data looks completely different.

Iterative improvement through feedback and adaptation

A recursive challenge: can your matching system learn to get better at matching? Multilevel Control Functional improves inference in complex settings (differential equations, Bayesian neural networks) by matching information at multiple levels of abstraction, so you're not just comparing final answers but also comparing intermediate structure, which means the system has more signals to get the matching right.

Can Recommender Systems Teach Themselves creates a feedback loop: the system makes recommendations, learns from implicit feedback (what users click, rank, or buy), then uses that to improve its own matching between users and items. The trick is fidelity control—ensuring the system doesn't overfit to its own mistakes—so that cumulative gains keep stacking across many rounds. When to Ensemble solves a different matching problem: given multiple language model outputs at each word position, you need to decide which outputs to ensemble together to get a better final answer. The system learns to identify stable word positions where all models agree (they match well) versus fragile positions where models disagree, so it can combine trustworthy outputs and skip the confused positions, which means faster inference without losing accuracy. Both papers demonstrate that matching gets smarter when you add feedback loops, because the system learns to distinguish good matches from bad ones through repeated testing.

Matching specialized data: graphs, malware, sensors

Specialized matching problems require domain-specific representations. Exploring Motif-based Heterogeneous Graph Learning matches subgraph patterns in regular expression code to detect ReDoS vulnerabilities—a security matching problem where two regexes that look completely different can have identical catastrophic behavior. By matching on motifs (recurring subpatterns in the computational graph), the detector finds dangerous patterns humans miss, which means it beats six existing methods in accuracy. It also runs 244 times faster than the best competing method because it skips detailed analysis of non-dangerous patterns.

MalTree matches malware samples across time to trace evolution—when malware variants emerge from a common ancestor, they share code but disguise it. By learning embeddings from malware behavior signatures, the system infers family relationships with 87% accuracy: matched samples show when new variants actually appeared in the wild. This temporal matching unlocks the ability to spot new variants of known families. TerraFM learns to match multispectral satellite imagery from different sensors and resolutions all to a single representation space. Earth observation data comes from different satellites with different wavelength bands and calibration; TerraFM matches all of it by learning a unified foundation model, so a patch of land looks consistent whether imaged by one satellite or another. The result is strong performance on classification and segmentation across diverse sensors. Each paper trades on the same core insight: matching works best when you learn a representation that captures what matters for that specific domain.
