Consensus Anchor-guided Hypergraph for Incomplete Multi-view Clustering

Use a hypergraph to capture group interactions in multi-view data where some views are missing, and reweight samples to reduce bias from incomplete records.

Paper explainersAll themesGraph & Geometric Learning

Real-world data often has multiple views — an image AND text, temperature AND humidity, patient history AND lab results. But some views are often missing. Traditional clustering methods either ignore the missing bits or use shallow pair-wise connections that miss the big-picture relationships. This paper builds a richer, denser connection map called a hypergraph, where clusters are allowed to think about groups instead of just pairs. It also calibrates the confidence in each data point based on how complete it is, so incomplete records do not trick the final grouping.

Zero assumption version

Grouping data that has multiple views and missing pieces

When we have data with multiple views, each view adds useful information. An image tells you shape and color; a text description tells you context. A patient's demographics tell you risk; their lab results tell you disease state. Clustering means grouping similar things together. The natural move is to treat the views as different voices speaking about the same data point: if most views agree, the point belongs to this group.

But real data has a problem: some views are missing. Some patients never got lab work. Some products have images but no text. A shallow solution is to ignore the missing parts and connect each data point only to its nearest neighbors in the views it has. The issue: this misses group structure. If we only see pair-wise links (A connects to B, B connects to C), we cannot tell that A, B, and C form a tight cluster of three — we lose the triangle.

In one sentence. When views are missing, pair-wise links fail to capture how groups of samples actually fit together.

The algorithm as a flow

What it actually does

Pick anchors

Select a small set of representative samples to summarize the data.

Build hyperedges

Group samples by similarity in each view; connect groups via hyperedges, not pairs.

Measure view disagreement

Check which views conflict or have too-few samples; mark unreliable ones.

Compute sample completeness

Count how many views each sample has; incomplete samples get lower weight.

Cluster via hypergraph

Use hyperedge connections to group samples; reweighting keeps bias out.

What the paper changes

What the paper changes

The paper changes two things: first, the connection map (shallow pair-wise graph becomes a hypergraph where multiple samples connect together at once instead of just two). Second, the influence of each data point (samples with fewer views count less in the final grouping, while samples with all views count more).

the object it moves  =  sample weights and hyperedge connections
The hidden quantity

Sample completeness score

measured quantity  =  Completeness (how much data a sample actually has)

The paper measures completeness: for each sample, what fraction of the multiple views did we observe? A sample with all 3 views has completeness 1.0; a sample with 1 out of 3 views has completeness 0.33. This is not new conceptually, but the paper uses it in a new way.

Why this matters: samples with low completeness create bias. If a sample has only View A (images) and is missing Views B and C (text and metadata), it will align with whatever other image-only samples are nearby, even if they would belong to different groups if the missing views were known. By reducing the weight of low-completeness samples in the clustering objective, the paper prevents these incomplete samples from dragging other samples into the wrong cluster.

Why it works

Why anchors and hyperedges fix the problem

The first move: anchors. Instead of clustering all data points directly, the method picks a small set of representative samples (anchors). All other samples connect to these anchors rather than to each other. This is fast and keeps computation manageable. The hypergraph is built on top of these anchors.

The second move: hyperedges. In a normal graph, an edge connects two nodes. In a hypergraph, a hyperedge connects a group of nodes. For example, if samples 2, 5, 7, 12 are all similar in View A, they form a hyperedge together. This edge says group-wise interaction, not just pairwise. When the clustering algorithm follows hyperedges, it sees that 2, 5, 7, 12 should probably belong to the same cluster, because they all link through the same hyperedge. This captures the triangle structure that pair-wise edges miss.

The third move: dual reweighting. The method reweights at two levels: (1) View level — if a view disagrees with the consensus (i.e. it produces a very different clustering), down-weight that view's contribution to the final grouping. (2) Sample level — if a sample is missing most views, down-weight its contribution. Together, these reduce the pull of unreliable data, so the final clustering is driven by complete, agreeable samples. Incomplete samples are still heard, but they no longer veto the consensus.

Math after the picture

The clustering loss with reweighting

First in words:

Loss equals hyperedge cost (sum over all hyperedges of how badly samples deviate from their assigned cluster center) plus a view-level penalty term (how much each view deviates from consensus) plus a sample-level penalty term (weighted by sample completeness). All three terms are summed and minimized.

Then the compact form:

L = sum_e c_e * ||X_e - mu_assigned|| + lambda_v * sum_v (1 - r_v)^2 + lambda_s * sum_i w_i * (1 - s_i)^2

Every symbol:

Ltotal loss (error measure; lower is better
c_ecost of hyperedge e; how many samples it covers
X_esamples in hyperedge e
mu_assignedcenter (mean) of the cluster samples belong to
r_vreliability score of view v; 0 to 1
lambda_vhow much to penalize unreliable views
w_iweight of sample i; depends on completeness
s_icompleteness score of sample i (fraction of views observed)
lambda_show much to penalize incomplete samples
A tiny worked example
Say we have 3 samples, 2 views, 1 anchor. Sample 1 has both views (s=1.0); Sample 2 has only view A (s=0.5); Sample 3 has only view B (s=0.5).
Hyperedge cost: samples 1,2,3 should be close to their cluster center. Distance for sample 1 to center: 0.2. Distance for sample 2: 0.3. Distance for sample 3: 0.4. Hyperedge cost = 0.2 + 0.3 + 0.4 = 0.9.
Sample penalty: Sample 1 has w_1=1.0, so penalty = 1.0 * (1-1.0)^2 = 0. Samples 2 and 3 have w_2=w_3=1.0 (uniform for now), so penalty each = 1.0 * (1-0.5)^2 = 0.25. Total sample penalty = 0.25 + 0.25 = 0.5.
View penalty: say view A reliability r_A=0.8, view B reliability r_B=0.7. Penalties: (1-0.8)^2 = 0.04 and (1-0.7)^2 = 0.09. Total view penalty = 0.13.
Total loss = 0.9 + lambda_s * 0.5 + lambda_v * 0.13. If lambda_s=0.5 and lambda_v=1.0, loss = 0.9 + 0.25 + 0.13 = 1.28. The completeness weighting tells the algorithm: sample 2 and 3 are unreliable; if possible, keep them near the center but do not let them pull other samples far away.

Minimizing this loss drives the algorithm to find clusters where complete samples agree, incomplete samples stay near consensus, and views that contradict the consensus are down-weighted.

What can go wrong

What can go wrong

Too many missing views. If a view is missing for 90% of samples, it cannot inform clustering at all. The method will down-weight it heavily, but the signal is already gone. The paper assumes at least some samples have most views observed.
Anchors are biased. The method selects anchors from the most complete samples. If complete samples form a systematic bias (e.g., all from one demographic group), the anchors will be biased too, and the entire hypergraph will inherit that bias.
View agreement is artificial. If two views are redundant (e.g., the same image shown twice under different names), the method treats them as independent agreement and over-trusts them. The dual reweighting cannot tell redundancy from true consensus.
Done right. When samples are reasonably complete (at least half of views present for most samples), views capture independent information, and anchors represent the population fairly, the method works as intended: the hypergraph captures group structure and reweighting keeps the result honest.
What a runnable demo should prove

What a runnable demo should prove

Build a synthetic multi-view dataset: create 4 true clusters, each with 50 samples. Each sample has 3 views (each view is a 10-dimensional list of numbers). Randomly delete 60% of the data to simulate missing views. Then run three clustering methods: (1) standard k-means on concatenated views (ignores missingness), (2) a simpler multi-view method with pair-wise edges only, (3) this paper's hypergraph method with reweighting.

Clustering accuracy = (count of correctly grouped samples) / (total samples). Measure for each method, compare.

The demo must make clear that pair-wise methods fail at high missing rates, but hypergraphs + reweighting hold up. The accuracy of method 3 should stay above 70% even at 60% missing data, while methods 1 and 2 drop below 50%.
