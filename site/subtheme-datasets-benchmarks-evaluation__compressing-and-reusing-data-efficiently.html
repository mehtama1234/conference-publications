Compressing and Reusing Data Efficiently

Papers figure out how to build smaller datasets that still teach models the important things, or how to turn larger datasets into more useful versions without losing information.

All themesField mapMathematicsAll explainers
What this is

Building datasets is expensive and time-consuming. Collecting millions of examples, labeling them, cleaning them costs enormous effort. So researchers in this subtheme ask: can you accomplish the same goal with fewer examples? Can you take a large, messy dataset and distill it into something smaller and cleaner that teaches a model the same essential things? Can you take a dataset built for one purpose and reformat it so it works for another? The goal is to get more learning value from less data.

Why does this matter? Training a large AI model on a huge dataset is expensive—it costs time and electricity. If you can achieve similar learning with less data, you save time and money because you need fewer computers running for fewer hours, and you can try new ideas faster because each experiment finishes sooner. Also, sometimes you have access to relevant data but in the wrong format or mixed with lots of noise. If you can transform or compress it smartly, you unlock data that would otherwise be useless. The challenge is that you cannot just randomly throw data away or simplify it—if you lose important examples, the model will learn less. You have to understand which examples matter and which are redundant or harmful.

The papers here take different approaches. Some use machine learning itself to identify which examples are most valuable for training, then remove the rest. Others use data distillation: run a learning process that compresses a large dataset into a much smaller but representative synthetic dataset that teaches almost as much. Still others focus on data cleaning: taking a messy dataset and keeping only the high-quality examples, or fixing mislabeled data. The work matters because it makes AI training faster and cheaper, and gets more value from data that already exists.

How the work breaks down

This subtheme splits into five natural directions: using machine learning to identify which training examples matter most and removing the rest; compressing large datasets into smaller synthetic datasets that teach the same things; taking messy data and cleaning or fixing it; transforming data across different formats and domains; and building specialized datasets that capture rare or difficult scenarios. Each approach solves the core problem that training is expensive, but they tackle it by answering different questions: which examples help, how to shrink without loss, how to fix broken data, how to cross-domains, and what rare cases matter most.

Distilling large datasets into tiny synthetic versions

Training on a full dataset takes a lot of compute time and electricity. Dataset distillation asks: can you run a learning process that compresses a huge dataset into a tiny set of synthetic images or data points that teach a model almost as much as the original? This matters because if you can achieve 80-90% of the learning value with 1-5% of the data, training experiments run 20-100 times faster, which saves money and lets researchers try ideas sooner.

Dataset Distillation as Pushforward Optimal Quantization (DDOQ) reformulates distillation as a mathematical optimization problem and outperforms other distillation methods on ImageNet-1K. The key contribution is showing that the distilled images work better when different model architectures train on them, which means the synthetic data captures something fundamental that multiple different learning paths can use. DIVER improves this further by extracting more detailed information from the distilled data so it generalizes better to new models without needing more samples. ProtoVAR takes a different route using visual autoregressive modeling—basically predicting one part of an image from earlier parts—to generate synthetic data efficiently because this method is cheaper to run than diffusion and it achieves better results than the high-compute-cost diffusion methods. Rectified Decoupled Dataset Distillation steps back and shows that the field has inconsistent evaluation, meaning different papers measure success differently, which actually hides whether synthetic datasets are truly better. By defining clearer evaluation rules, this work uncovers that dataset quality does improve with better distillation, and identifies specific strategies that work.

Together, these papers divide the distillation problem: DDOQ and DIVER focus on the mathematics of what makes synthetic data transferable; ProtoVAR finds an efficient path to create it; and Rectified Decoupled reveals that the field needs honest measurement to know what is actually working.

Picking the right subset of data to train on

Not all training examples are equally important. Some teach the model many lessons, while others are redundant or even harmful. If you could identify and train on just the high-value examples, you could reach the same final performance with fewer training steps and less data, which saves time and electricity during training because the model runs on fewer computers for fewer hours. The challenge is computing which examples matter without training the full model.

Evaluating Sample Utility for Efficient Data Selection by Mimicking Model Weights proposes a fast way to score each training example based on how much it influences the model's learning. Instead of running full training to see which examples help, this method mimics (copies) the model weights to quickly estimate utility so you can decide without expensive computation. Results show that CLIP models trained with nearly 5 million fewer samples, selected this way, actually perform better than random selection—savings without sacrificing accuracy because the selection method identifies which samples truly help. Is Data Shapley Not Better than Random in Data Selection? Ask NASH tackles the same problem from a different angle by asking whether a game-theory tool called Shapley values (which fairly assigns credit to each example) picks better samples even though they are expensive to compute. NASH accelerates Shapley-based selection by identifying which examples contribute the most unique information and focusing on those, dropping compute overhead sharply while improving selection quality. Training Data Efficiency in Multimodal Process Reward Models applies this idea to vision-language models, showing that selecting just 10% of training data using smart subset selection reaches full-data performance on two large models because the remaining 90% is redundant, and beats random 10% by 4.1%—a concrete proof that selection works even on modern large models.

All three papers ask the same question with different answers: how do you find the 10-30% of data that teaches the model almost everything? The Mimic approach is fast but approximate; NASH is exact but requires computation; and the Multimodal work shows both matter in practice.

Building datasets for rare and complex cases

Many datasets are biased toward common cases and miss edge cases, rare scenarios, or complex variations. Models trained on them often fail when they encounter unfamiliar situations. Building datasets that capture bias, ambiguity, complexity, or rarity is hard because you need to actively create or seek out the hard examples. This subgroup tackles four different hard-case problems: fairness, selective augmentation, creativity evaluation, and physical realism.

Benchmarking Bias Mitigation Toward Fairness Without Harm tests whether commonly used debiasing methods actually work. The big finding is that many complex debiasing techniques fail to beat a simple baseline (well-tuned standard training) on real benchmarks, while a composite augmentation method consistently delivers fairness gains without hurting overall accuracy. This reveals that not all data fixes work as promised. Do We Need All the Synthetic Data? Targeted Image Augmentation via Diffusion Models flips the question: instead of augmenting (creating extra copies of) all training examples, it identifies which examples are hard or underrepresented and augments only those. By adding synthetic copies of 30-40% of examples, it beats augmenting everything and even surpasses strong baselines on CIFAR-100. Evaluating Text Creativity across Diverse Domains addresses the measurement problem: how do you tell whether generated text is truly creative? It builds a dataset and evaluator that combine human-written and synthetic examples to train a creativity judge that aligns well with human judgments across many domains. PICABench tackles another rare case: physical realism in image editing. Most datasets miss physics violations, but this work collects 100K realistic physics-aware examples and evaluates how far models are from understanding real physical constraints—revealing large gaps.

These papers converge on a strategy: identify what is missing or broken in your data (bias, underrepresentation, hard-to-measure quality, physical violation), then build targeted fixes rather than generic augmentation.

Specializing datasets for new languages, math, and domains

Large language models and vision models need pretraining data that matches their eventual use cases. A model trained only on English Wikipedia will perform poorly on low-resource languages. A model trained on natural text will struggle with mathematics. A multimodal model pretrained on one type of images (a specific distribution—the kind and range of images it saw) may fail when knowledge changes. Building or curating datasets for these specialized domains means either collecting new data or transforming existing data to cover the gap.

Common Corpus: The Largest Collection of Ethical Data for LLM Pre-Training addresses language diversity. It assembles roughly two trillion tokens (a token is a small piece of text, roughly a word or subword) spanning high-resource European languages, rare low-resource languages, and significant code data. Coverage matters because models perform better on languages they saw during pretraining, which means they learn those languages faster. Demystifying Supervision Data Generalization in Multimodal LMs asks which of many available supervision datasets should go into a multimodal model. The work builds a predictor that correlates 86% with actual performance rankings, allowing practitioners to pick the top 5-10 datasets rather than using all of them. This saves compute and improves performance by up to 6.9% because irrelevant or low-quality datasets add noise that slows learning. Nemotron-CC-Math builds a high-quality math pretraining dataset with 133 billion tokens focused on mathematical reasoning. It contains 5.5 times more tokens than the best open math dataset that existed before, and models trained on it gain 4.8 to 12.6 points on the MATH benchmark and 4.6 to 14.3 on MBPP+, a code benchmark—showing that domain-specific data at scale drives performance in specialized reasoning because math requires seeing many examples of different problem types. When Large Multimodal Models Confront Evolving Knowledge addresses a practical problem: models pretrained on older data make mistakes when real-world knowledge changes. Injecting updated knowledge into a model degrades its existing capabilities because the model forgets or mixes up old and new facts. This work shows that knowledge-aware data augmentation helps inject new facts without breaking old ones by tagging which facts are new, and that mixture-of-experts plus data replay methods recover lost capabilities across nearly 10,000 test samples by learning to handle both old and new knowledge together.

Together, these papers show that pretraining datasets must be specialized: languages need coverage to include all users; supervision datasets need selection to avoid noise; math needs domain-specific density; and knowledge needs updates handled carefully.

Data efficiency through smart compression and reuse

Training a large model is expensive in time and electricity. Some approaches reduce this by training on fewer examples selected wisely. Others reduce it by compressing the data itself—storing labels more efficiently or generating synthetic examples that teach just as much. A third approach reuses data: synthetic data can pretrain models (teach them rough patterns and features cheaply), which then fine-tune on real data far faster than training from scratch because the model starts ahead instead of at zero.

COMPACT reduces the data budget for training vision models by 90% while reaching 100.2% of the performance of the full-budget model, and even improves on harder benchmarks like MM-Vet (+8.6%) and MMStar (+2.9%). This is possible because the model is tuned compositionally—building up from simple skills to complex ones—which teaches it to learn efficiently and skip unnecessary data. Hard Labels In! Rethinking the Role of Hard Labels addresses a different compression idea: storing soft labels (a probability distribution over classes) requires less storage than soft labels alone, but hard labels are even cheaper. The work shows how to achieve ImageNet-1K accuracy with only 285 million tokens of hard-label storage—100x smaller than prior work—by combining hard and soft labels cleverly so you get accuracy without the memory cost. This matters because it unlocks training on edge devices or memory-limited settings where full labels would overflow. Principled Synthetic Data Enables the First Scaling Laws for LLMs in Recommendation shows that synthetic data can replace real data outright. Models pretrained on purely synthetic relational databases outperform models pretrained on real ones by 130% on recall@100 because synthetic data can be tuned to focus on what matters, and establish the first power-law scaling relationship for recommendation models. This is striking because it means you can create good pretraining data algorithmically without collecting real user data, which saves privacy and cost. Relational In-Context Learning via Synthetic Pre-training with Structural Prior applies the same idea: pretraining foundation models on synthetic relational data (tables with structural patterns) lets them learn few-shot prediction on real tabular data without explicit fine-tuning because the synthetic data teaches the core patterns. The model RDB-PFN is lightweight and fast, outperforming heavier competing models. PluRel (Synthetic Data Unlocks Scaling Laws for Relational Foundation Models) extends this: it proves for the first time that relational models exhibit power-law scaling with synthetic database size, just like language models do with text tokens—synthetic pretraining is not a trick but a principled path to scaling that works across domains.

These papers map a reuse strategy: compress data storage where possible so fewer GPUs are needed, create synthetic data for expensive pretraining (language, recommendation, tables) which can be generated algorithmically, and let that synthetic data teach the model efficiently so real fine-tuning runs fewer steps and costs less.
