WebWorld: A Large-Scale World Model for Web Agent Training

Train a web simulator on many real interaction traces so agents can practice long web tasks without touching the live web every time.

Paper explainersAll themesAgents & Tool Use

Web agents need many long trajectories before they become dependable on real tasks. Gathering all of those trajectories on the live web is slow and risky because pages change, networks are slow, and repeated automated actions can be unsafe. WebWorld builds a large simulator of web interaction so agents can practice inside a learned environment that behaves enough like the web to support training and search.

Zero assumption version

Why live-web training does not scale

A web agent must click, type, read, and keep track of long task state across many pages. That takes large amounts of practice data. Collecting all of that data from the live web is expensive because each step waits on the network and because many sites limit repeated traffic.

The live web is also unstable. Pages change, forms disappear, and one careless training run can trigger unsafe actions. A world model offers a safer place to practice because it can replay and extend web behavior without touching real sites on every step.

The paper's move in one sentence. Learn a broad web simulator from more than a million open-web interactions so agents can train and search inside a fast stand-in environment.

The algorithm as a flow

What it actually does

Collect large-scale open-web traces

Gather many interaction sequences so the simulator sees diverse pages, goals, and action patterns.

Train a world model on next-step web behavior

Learn how page state changes after each action so the simulator can continue a task without contacting the live site.

Support long simulated rollouts

Run thirty or more steps in the learned environment so that agents can practice long-horizon control.

Use the simulator for agent training

Generate synthetic trajectories that teach the agent common web patterns because training can now scale beyond the original collected traces.

Use the simulator for search at test time

Try candidate action paths inside the world model so that the agent can compare futures before acting on the real task.

What the paper changes

What the paper changes

The paper changes the environment used for web-agent learning. Instead of depending only on live websites, it supplies a learned stand-in environment that can be queried many times.

The hidden quantity

The hidden quantity

measured quantity  =  how faithfully the world model predicts the next web state

The key hidden quantity is the quality of the simulator's internal picture of web dynamics. You cannot inspect that picture directly. You only see it through whether the next simulated page, next action result, and later task outcome line up with what would have happened on the real web.

If that hidden picture is accurate enough, training inside the simulator transfers back to real tasks because the agent is practicing decisions that still make sense when it returns to live sites.

Why it works

Why this works: practice the long task pattern in a cheaper world

A web agent improves through repeated interaction. The live web makes that repetition costly because each step depends on network time, site rules, and unstable page content. A world model removes much of that friction because it can produce the next state directly from a learned simulator.

The value is not only speed. The simulator also supports long rollouts and search. That matters because many web tasks fail in the middle, not on the first step. If the agent can practice or evaluate long action chains inside the simulator, it can learn planning habits that are hard to acquire from short static examples.

Math after the picture

Prefer actions that look good inside the world model

First in words:

A simple view is to score an action sequence by predicted task reward under the simulator and then choose the sequence with the largest predicted value.

Then the compact form:

value(path) = sum_t predicted_reward_t(path)

Every symbol:

value(path)predicted total value of one candidate action path inside the simulator
sum_tadd predicted reward across task steps
predicted_reward_t(path)the simulator's predicted reward at step t for that path
A tiny worked example
Path A clicks search, opens two results, and submits a form.
Its predicted rewards across four steps are 1, 2, 2, and 3, so total value is 8.
Path B clicks a wrong menu and then recovers.
Its predicted rewards are 0, 0, 1, and 2, so total value is 3.
Search prefers Path A because the simulator predicts more steady progress toward the goal.

The paper uses a learned world model rather than this single formula, but the formula expresses the key idea that search is guided by predicted future progress.

What can go wrong

What can go wrong

Simulator drift over long tasks. Small next-step errors can accumulate across many turns, so a long rollout may become unrealistic even when the early steps looked fine.
Rare site behavior may be missing. If the training data does not cover a class of forms or layouts, the world model may fail on those cases because it has not learned the needed transition pattern.
Synthetic trajectories can teach bad habits. If the simulator makes the same mistake often, the agent can overfit to that mistake because much of its extra practice data comes from the simulator.
Done right. The approach is useful because it turns web-agent training from a live-site bottleneck into a reusable simulation problem.
What a runnable demo should prove

What a runnable demo should prove

Build a small web benchmark with search, login, and form tasks. Collect a set of real trajectories, train a compact world model on them, and then compare two agents: one trained only on the original data and one trained with extra simulator rollouts. Also compare search with and without the simulator at test time.

The demo should show that the world-model agent finishes more long tasks because it got more practice with multi-step decisions. Track both simulation fidelity and downstream task score so that the transfer claim is visible.

task_gain = web_score_with_world_model - web_score_without_world_model ; sim_gap = real_step_match - simulated_step_match

The main point is that a learned web environment can produce training value before the agent returns to the live web.
