Capacity Manipulation for Class-Imbalanced Diffusion

Reserve part of a diffusion model's internal capacity for rare classes so they get learned as well as common ones.

Paper explainersAll themesRepresentation & Self-Supervised Learning

Diffusion models learn to draw images by predicting noise step by step. On imbalanced datasets (where some classes appear much more often than others), the model wastes capacity learning the common classes and leaves almost nothing for the rare ones. This paper identifies that capacity shortage as the real problem and solves it by explicitly reserving some of the model's internal weights for minority classes via a low-rank split.

Zero assumption version

Imbalanced data ruins minority-class learning

In real-world datasets, some classes appear thousands of times while others appear only a handful of times. A naive diffusion model sees the abundant class so often that it burns a huge path through its internal weights (called capacity) to handle it well. The rare class gets whatever capacity is left over — usually a cramped corner that cannot hold enough detail to generate convincing rare-class images.

A beginner might try to balance training by giving rare-class examples more weight during updates, but that does not fix the underlying problem: the model's fixed architecture simply does not have enough capacity carved out for two completely different visual patterns. You cannot squeeze a second detailed pattern into the leftover scraps.

The core problem: Majority classes hoard the model's capacity, leaving no room for minorities to be learned accurately.

The algorithm as a flow

What it actually does

Split capacity

Break the model's weights into three parts: shared core, majority-only block, minority-only block.

Freeze assignments

Mathematical constraint ensures majority class updates only its block, not the others.

Add a guiding loss

Extra penalty term steers the minority block to actually capture rare-class patterns.

Train end-to-end

Joint optimization on all three blocks; shared core learns general image structure.

Generate both

When answering new questions (at test time), the minority block ensures rare-class images are as detailed as majority ones.

What the paper changes

The thing the paper changes

The paper splits the model's internal weights into separate locked blocks: one reserved for majority classes, one for minorities, and a shared foundation for both. This is done via low-rank decomposition, which is a way to split a large table of numbers into smaller independent pieces, deliberately breaking the model into separate subspaces so each can be trained independently.

the object it moves  =  Model weights allocation
The hidden quantity

Capacity allocation — how much model-space goes to each class

measured quantity  =  Capacity utilization per class

Capacity is the amount of internal detail a model can store for a given task or class. In a neural network, capacity comes from the degrees of freedom in the weights — how many independent numbers can vary. On an imbalanced dataset, capacity gets unevenly split: common classes use 80% of the available weights, rare classes use 5%, and the rest sits idle.

The paper estimates capacity allocation by analyzing how much each class's loss updates propagate through different weight blocks during training. When majority-class updates fill an entire block to saturation (high activation magnitudes across all weights), that block is monopolized. The paper's low-rank decomposition explicitly measures how many independent directions each class needs and assigns them in advance, preventing waste.

Why it works

Why reserving capacity fixes imbalance

Here is the causal chain: A diffusion model with shared weights learns by backpropagating errors (computing which-way-to-nudge signals for each weight). On imbalanced data, majority-class errors are frequent and large, so their nudges dominate — they keep updating the same weights, deepening the paths learned for them. Meanwhile, minority-class errors are rare and get drowned out; their nudges barely move the weights because they arrive less often. The model ends up with a heavily carved-out majority path and an underdeveloped minority one.

By splitting weights into dedicated blocks, each class's nudges only touch its own block. Majority-class errors update only the majority block; minority-class errors update only the minority block. Both classes get the same amount of weight-space to carve into, so both can develop detailed, well-learned patterns. The low-rank constraint mathematically enforces this split — it is impossible for one class to steal the other's weights because they are factored into independent submatrices.

The math: guarded capacity loss

First in words:

Total loss equals the standard diffusion loss plus a capacity-guard term that penalizes minority-class updates leaking into majority blocks and vice versa.

Then the compact form:

L_total = L_diffusion + lambda * sum_ij ||W_maj[i,j] * grad_min[i,j]||^2 + mu * ||W_min[i,j] * grad_maj[i,j]||^2

Every symbol:

L_diffusionstandard noise-prediction loss for diffusion training
lambda, mustrength of the guard (how much to penalize spillover)
W_maj, W_minmajority and minority weight blocks
grad_maj, grad_mingradient (nudge signal) from majority and minority classes
||...||^2squared magnitude; larger = more spillover (bad)
A tiny worked example
Suppose majority class wants to nudge weight w_maj by 0.8 and minority class wants to nudge w_min by 0.2.
Diffusion loss is standard: both nudges shrink training error.
Capacity loss penalizes cross-talk: if minority's nudge tries to touch the majority block, penalty = lambda * (0.2)^2 = 0.04 * lambda (assuming lambda = 100, that is 4 units of extra loss).
Model training avoids this penalty by steering minority updates exclusively into w_min, majority into w_maj.
Result: clear separation, no competition.

The equation enforces the split mechanically: it makes it painful for nudge-signals from one class to update weights assigned to the other, because the penalty term grows larger if spillover happens, so training avoids it to minimize loss.

What can go wrong

What can go wrong

Setting reserved capacity too small. If the minority block's rank is too low, it cannot hold all the visual detail the rare class needs. The minority-class images stay blurry. This requires tuning rank per dataset.
Imbalance so extreme that minority has only one example. A single image per class cannot teach the model anything (no signal to learn from). Capacity manipulation cannot fix missing data; it only fixes allocation of capacity that exists.
Majority and minority classes are visually similar. If the two classes share most visual features, separate capacity blocks waste space. The minority block must re-learn what the majority block already carved out, because the weights are locked apart. This duplication burns capacity that could do other work. A hybrid approach saves capacity: use a large shared block for common visual patterns (edges, textures, colors all classes need) and only split smaller private blocks for class-specific quirks. Knowledge learned once in the shared block, reused by both, because shared weights are updated by both classes' training signals — so re-learning never happens.
Done right. Tune the rank (capacity size) per class based on how much visual diversity that class has (e.g., how many different poses, lighting, textures appear in its images). Run validation to pick the best rank. Both classes reach high-quality generation.
What a runnable demo should prove

What a runnable demo should prove

Build a tiny diffusion model on a synthetic imbalanced dataset (e.g., 1,000 images of red circles, 10 images of blue squares). Train once with naive shared weights (baseline) and once with capacity manipulation (majority block of rank 4, minority block of rank 2). When the model is finished, generate 10 samples of each class and visually inspect clarity. Measure generation quality via a simple metric like pixel-space similarity to real images (MSE or perceptual distance).

minority_quality_gain = quality_after - quality_before = (MSE_before - MSE_after) > 0

The demo must show that minority-class samples go from visibly blurry to visibly sharp (because the minority block now has enough reserved space to learn detail), and the majority-class quality stays the same or improves (because it still has its own large block). The quality gain should be 10 to 30 percentage points on quality metrics.
