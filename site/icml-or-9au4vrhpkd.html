CoPE: A Framework for Optimizing Coordination between Planning and Execution in LLM-based Agents

CoPE trains an agent to keep its long plan and its actual step-by-step behavior aligned, so that planning is not only ambitious but also usable.

Paper explainersAll themesAgents & Tool Use

Many agent failures are not caused by bad planning alone or bad execution alone. The real failure is the gap between them. An agent may write a strong multi-step plan, then drift away from it once the environment starts pushing back. CoPE focuses on that gap directly. It scores how well a plan and its executed run agree, then gives more training weight to examples where planning and execution truly cooperate.

Zero assumption version

Why long-horizon agents drift off their own plans

In a long task, a plan only matters if the later actions still follow it. Many training pipelines reward successful outcomes but do not distinguish between a plan that guided the run and a plan that was ignored once execution started. That means the agent can learn from mismatched examples where planning text looks good but the actual run wanders.

Those mismatched examples are harmful because they teach the agent to separate planning from acting. CoPE treats that mismatch as the central learning problem. It asks whether the chosen plan can survive contact with the environment and whether the executed actions still respect the plan's structure.

The paper's move in one sentence. Generate plans and runs together, measure how well they fit each other, and train mostly on the pairs where the plan actually guides the execution.

The algorithm as a flow

What it actually does

Step 1: Search for candidate plans

Use self-refining tree search to propose strong long-horizon plans because one task may admit several possible paths.

Step 2: Execute those plans

Run the agent in the environment and collect multiple actual action histories for the candidate plans.

Step 3: Measure coordination

Score how well each run follows its plan so that planning quality and execution quality are judged together.

Step 4: Weight the training data

Assign larger weight to well-coordinated plan-run pairs because they contain the behavior the paper wants the agent to repeat.

Step 5: Update the agent

Train on those weighted examples so that later plans are more practical and later runs stay closer to plan.

What the paper changes

What the paper changes

The paper changes the training signal. It no longer treats every successful or partially successful run equally. Instead, it values runs by how well execution stays aligned with the plan that produced them.

The hidden quantity

The hidden quantity: plan-execution fit

measured quantity  =  how closely the actual run follows the useful structure of the plan

The central quantity is plan-execution fit. A plan can look sensible while still being useless if the later actions ignore it. CoPE makes that hidden fit visible by scoring how much the run respects the planned sequence and subgoals.

This matters because the agent should learn from examples where planning truly helps action selection. If training keeps many low-fit examples, the planner and executor drift apart and the agent keeps producing plans that do not survive real interaction.

Why it works

Why it works

Tree search helps because it can produce better candidate plans than a single quick guess. But plan search alone is not enough. CoPE adds a second filter: did the run actually honor the plan once the task became interactive?

That second filter matters because execution failures often come from practical friction such as missing preconditions, environment surprises, or local temptations that pull the agent away. When CoPE upweights coordinated examples, it favors plans that can survive those pressures and runs that know how to carry them out.

The result is a cleaner learning signal. The agent does not only see what success looked like. It sees which plan-run pairs stayed coherent, and that coherence later improves planning and acting together because the training weight keeps reinforcing pairs where the plan truly guided the run.

Math after the picture

A compact coordination-weighted objective

First in words:

Train the agent more strongly on examples where the plan succeeds and the executed run stays close to that plan.

Then the compact form:

J = E[ w(plan, run) * reward(run) ] , where w(plan, run) = coord(plan, run)

Every symbol:

Jthe expected training objective
planthe candidate multi-step plan proposed before acting
runthe actual sequence of actions taken in the environment
reward(run)task reward from the executed run
w(plan, run)the weight assigned to that training example
coord(plan, run)the coordination score between the plan structure and the actual run
A tiny worked example
One plan says: open the database, filter the records, then export the result.
Run A opens the database, filters correctly, and exports. Its coordination score is high.
Run B opens the database, skips filtering, and starts unrelated browsing. Its coordination score is low.
Even if both runs collect some reward, Run A gets more training weight because its plan actually guided the actions.
Later learning therefore favors plans that can be carried through in practice.

The paper's full method uses richer scoring and search, but the core idea is simple: a good example is one where planning and execution agree.

What can go wrong

What can go wrong

Coordination score is too shallow. A weak score may reward superficial overlap between plan and run, because matching a few words is not the same as carrying out the true subgoal structure.
Tree search explores narrow plan families. If the search keeps proposing very similar plans, the agent may miss a better strategy because the training data never shows it.
The environment forces justified deviations. Some drift is correct when the world changes, so a rigid score can punish healthy adaptation because the run needed to repair the plan on the fly.
Done right. The method works when coordination scoring rewards faithful execution but still allows sensible plan repair, because then the agent learns plans that are both structured and usable.
What a runnable demo should prove

What a runnable demo should prove

Build a small tool task with five to seven steps, such as finding data, filtering it, computing a summary, and writing the result. Generate plans for each task, run those plans in a simple environment, and compute a coordination score by checking whether the completed subgoals match the planned subgoals in order. Then compare training with and without coordination weighting.

The demo should show that coordination weighting improves long-horizon success because the agent learns from examples where the plan truly guides the run.

coord_success = high_fit_successes / total_tasks ; drift_rate = off_plan_actions / total_actions

The core proof is that better plan-run fit leads to better task completion, because the agent is no longer rewarded equally for plans it never really follows.
