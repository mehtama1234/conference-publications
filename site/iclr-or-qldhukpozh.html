OPRIDE: Efficient Offline Preference Learning

OPRIDE cuts the cost of teaching a robot by asking smarter questions and preventing it from falling in love with a broken reward signal.

Paper explainersAll themesReinforcement Learning

When teaching a robot to do a task, you typically give it a reward signal — a number that goes up when it does well. But designing that signal is hard, because you have to decide what matters and by how much. Asking humans to compare two attempts side by side (prefer A to B?) is easier for humans, because comparing feels natural to people in a way scoring does not, and you get honest feedback without them having to invent numbers. OPRIDE cuts the cost by asking fewer, smarter questions and stopping the robot from over-trusting the reward model it learned from those questions.

Zero assumption version

The cost of preference questions

Preference-based learning asks a human to pick the better of two robot attempts. This is easier and more honest than writing a reward number for each attempt by hand, because humans naturally judge things by comparing and can recognize a good attempt when they see one, but they struggle to assign a number. But asking humans for feedback is slow and expensive because each person can only answer so many questions before they get tired or need to be paid.

Without guidance, a robot asks random questions: compare two terrible attempts, or two similar good ones. Neither teaches much. The human is not learning which questions matter most. And once the robot builds a reward model from those questions, it trusts it blindly and can spiral into a corner, convinced its imperfect reward signal is perfect.

The problem in one sentence. Asking humans for preference feedback is expensive, and the robot wastes questions on uninformative comparisons and then over-trusts the broken reward it learns.

The algorithm as a flow

What it actually does

Step 1: Collect offline experiences

Robot has a dataset of its past attempts (no new trials, fully offline).

Step 2: Ask informative questions

Pick pairs from the dataset where the reward is most uncertain — where knowing the true answer teaches the most.

Step 3: Learn the reward

Train a model to predict which attempt a human would prefer, using their actual answers.

Step 4: Control the spiral

Gradually lower how much the robot trusts the learned reward as training goes on (discount scheduling).

Step 5: Plan better

Use the (carefully doubted) reward to pick which attempt the robot should execute next.

The hidden quantity

Informativeness: the hidden quantity

measured quantity  =  Informativeness of a comparison

Informativeness is how much a human answer teaches you about what makes a good attempt. If the robot asks about two terrible attempts or two nearly identical good ones, the answer teaches almost nothing — it is uninformative. If the robot asks about one great attempt and one mediocre one, the answer tells you something real about the gap in quality.

OPRIDE measures informativeness by looking at the uncertainty: which pairs does the learned reward model feel most confused about? High uncertainty means the pairs are different enough that knowing the true preference would teach a lot.

Why it works

Why it works: two interlocking pieces

The first piece: asking informative questions teaches faster because each human answer contains more information. When the robot asks about two very similar attempts (both great or both bad), the human's answer does not teach much — you would predict that answer anyway. When the robot asks about one great and one bad attempt, the answer tells you something real about what makes the difference. By picking the pairs where the learned reward is most uncertain (does not know which is better), OPRIDE finds the pairs where the human's answer will most directly teach the robot something new. This is why fewer questions go further.

The second piece: discount scheduling prevents overconfidence. As the robot learns the reward model from questions, it naturally wants to use that model for planning (pick the attempt with the highest reward). But the model is learned from limited questions and inevitably has blind spots. If the robot trusts it completely, it will exploit those blind spots and stop exploring. Discount scheduling slowly lowers how much the robot trusts the learned reward — gradually weakening the signal, so the robot keeps exploring instead of spiraling into a false conviction.

Math after the picture

The math behind the two fixes

First in words:

pair_score = uncertainty(pair) for query selection; reward_used = gamma(t) times reward_learned(attempt) where gamma(t) decreases over time

Then the compact form:

pair_informativeness = variance(reward_model_predictions on pair); reward_effective = gamma_t * r_learned(s,a) where gamma_t = 1 - (t / T)

Every symbol:

pair_informativenesshow spread out the reward predictions are for the two attempts in a pair
variance(reward_model_predictions on pair)if the model is unsure, the variance is high; measure of uncertainty
gamma_ta factor that starts at 1 and slowly decreases to 0 as training progresses
tthe current training step
Tthe total number of training steps
r_learned(s,a)the reward the learned model gives to state and action
reward_effectivethe actual reward signal used for planning (discounted version)
A tiny worked example
Pair A (great vs mediocre): reward model predicts 0.9 for great, 0.3 for mediocre. Variance = 0.36. High informativeness.
Pair B (good vs good): reward model predicts 0.7 for both. Variance = 0.0. Low informativeness.
Robot asks human about Pair A, gets a clear answer. Pair B would waste the question.
After learning from answers, at step 500 of 1000 total: gamma_500 = 1 - 500/1000 = 0.5. Reward signal is halved.
This discount makes the robot less confident in the learned reward, so it explores wider instead of spiraling.

The first formula picks which questions to ask: high variance means high informativeness. The second formula gradually doubts the learned reward as training goes on.

What can go wrong

What can go wrong

Uninformative pairs still get picked If the learned reward model is very wrong early on, its uncertainty does not align with what humans would find informative. OPRIDE relies on the reward model to know what it does not know, which fails if the model is confidently wrong.
Discount too fast or too slow If gamma decreases too quickly, the robot stops trusting the reward and explores randomly. If it decreases too slowly, the robot still overfits. The discount schedule has to be tuned for each problem.
Offline dataset is biased If the robot's past attempts were all mediocre or all similar to each other, the offline dataset does not cover the space of good versus bad attempts. OPRIDE can only learn from what is in the dataset.
Done right When the offline dataset has real variation and human preferences are consistent, OPRIDE asks fewer questions and learns a trustworthy reward model that the robot uses carefully.
What a runnable demo should prove

What a runnable demo should prove

Build a simulated robot (e.g. moving a gripper to a target) with an offline dataset of 100 past attempts (some good, some bad, some mediocre). Implement three methods: (1) random query selection, (2) uncertainty-based selection (OPRIDE's first piece), and (3) uncertainty plus discount scheduling (full OPRIDE). Run all three with a human oracle (or simulated preferences). Count how many questions each method needs to reach 80% performance. Plot performance vs. number of questions.

efficiency = performance reached at 25% fewer questions than random baseline

The demo must make clear that informative questions + discount scheduling cut the question budget in half while keeping performance the same.
