Don't Throw Away Your Beams: Improving Consistency-based Uncertainties in LLMs via Beam Search

Instead of sampling random candidate answers to measure how confident an LLM is, use beam search to pick the best candidates, which gives steadier uncertainty estimates.

Paper explainersAll themesLLMs & Foundation Models

When a language model is asked a question, we want to know how confident it is in the answer. One way to measure that confidence is to ask the model the same question multiple times and see how much the answers agree. This paper replaces random sampling with a smarter search method that picks the most likely answers first, giving much steadier confidence measurements across repeated runs.

Zero assumption version

How do we know if an LLM's answer is right or made up?

Large language models can sound confident while saying things that are false. When you ask one a factual question, it might give you a confident answer that is completely wrong. Humans need a way to spot when the model is uncertain, so they know when to trust it and when to double-check.

Today's method: ask the model the same question five or ten times, let it pick different random answers each time, and then check how many times the answers are the same. If the model keeps saying the same thing, we guess it is confident. If the answers are all over the place, we guess it is unsure. The problem is that models that are very sure about their favorite answer will pick that answer over and over by random chance, making the variance (the wiggle from one run to the next) very high and hard to measure.

The core issue. Random sampling gives highly unpredictable confidence scores because the model's favorite answers keep getting picked by chance, drowning out the real pattern.

The algorithm as a flow

What it actually does

Step 1: Generate best answers

Use beam search to find the top-k most likely answers to the question.

Step 2: Add random backup answers

Sample additional random answers to fill out the candidate pool to size M.

Step 3: Compare all answers

Measure how much each answer is similar to all the others using semantic similarity.

Step 4: Weight by likelihood

Answers that the model said are more likely get more weight in the agreement calculation.

Step 5: Compute confidence

Aggregate weighted agreement scores into a single confidence number.

What the paper changes

What the paper changes

The paper replaces the sampling method that generates the list of candidate answers. Instead of drawing answers completely at random according to what the model thinks (multinomial sampling), the paper uses beam search to grab the most likely answers first, then fills the rest with random samples. This hybrid approach locks in the high-quality candidates early and reduces noise.

The hidden quantity

The hidden quantity: answer diversity

measured quantity  =  consistency variance across runs

The paper tracks a quantity called consistency variance: how much the uncertainty score bounces around when you run the method multiple times on the same question. In random sampling, this variance is high because the model's favorite answers keep showing up by accident. In beam search, this variance is low because the best answers are always included.

The paper measures this by running the method on the same inputs many times and checking how much the confidence number changes. This is reported as error bars on the test results, and beam search has smaller error bars than random sampling.

Why it works

Why it works: locking in the best answers

The mechanism has three parts. First, beam search is deterministic: when you ask it for the top-4 answers, it always gives you the same top-4. Random sampling is not: sometimes the model picks answer A, sometimes answer B, even though both have high probability. Second, in tasks with short answers (like QA), the model's probability distribution is very peaked: the top answer is far more likely than the second-best. Random sampling keeps re-picking the top answer by pure chance, so you see duplicates and no real diversity. Beam search avoids this by locking in the diverse top-k answers first. Third, the paper weights each answer by how likely the model thinks it is, so even though beam search is deterministic, the final confidence score still accounts for which answers the model prefers.

The net effect: the uncertainty estimate becomes stable (low variance across runs) because the candidate set is always the same high-quality pool, yet still accurate because weighting accounts for the model's actual probabilities.

Math after the picture

The weighted consistency formula

First in words:

The uncertainty is computed as one minus the average (weighted by how likely each answer is) of how similar each answer is to the model's best guess.

Then the compact form:

U_beam = 1 - (1/M) * sum_i w_i * sim(y_i, y_best)

Every symbol:

U_beamthe uncertainty score (low = model is confident, high = model is unsure)
Mtotal number of candidate answers we collect
w_ithe likelihood weight of answer i (how much the model prefers it)
sim(y_i, y_best)semantic similarity between answer i and the model's best answer (0 to 1)
y_ithe i-th candidate answer
y_bestthe highest-probability answer from beam search
A tiny worked example
Suppose we collect M=4 answers. Beam search gives us the top-2 (y_1, y_2), random sampling gives us y_3 and y_4.
Model thinks: y_1 has weight 0.5, y_2 has 0.3, y_3 has 0.15, y_4 has 0.05.
Similarities to best answer y_1: sim(y_1,y_1)=1.0, sim(y_2,y_1)=0.6, sim(y_3,y_1)=0.2, sim(y_4,y_1)=0.1.
Weighted agreement: 0.5*1.0 + 0.3*0.6 + 0.15*0.2 + 0.05*0.1 = 0.5 + 0.18 + 0.03 + 0.005 = 0.715.
Uncertainty U_beam = 1 - 0.715 = 0.285 (so confidence is about 71%).
If random sampling had picked y_1 twice and y_3 twice, weighted agreement would jump to 0.5*1.0 + 0.5*0.2 = 0.6, giving U=0.4 (noisy). Beam search avoids this by always including y_1 and y_2.

The weights give high importance to answers the model prefers, while beam search ensures the best answers always show up in the candidate pool.

What can go wrong

What can go wrong

Beam search only works in white-box settings. The method needs access to the model's internal probability scores for each token. If you only have black-box access (you can query the model but cannot see probabilities), you cannot use beam search to estimate likelihoods.
Beam width size matters. If the beam width k is too small, you might miss good alternative answers. If it is too large, you waste computation and the method converges to pure random sampling. The paper tuned k for each dataset.
Not all UQ methods benefit equally. The paper tested beam search on many different uncertainty methods. Some methods that rely on semantic clustering of answers showed worse results with beam search because clustering works better with more diverse samples.
Done right. When used on standard consistency methods (comparing answer agreement directly), beam search consistently beats random sampling and reduces variance, especially on QA tasks with peaked distributions.
What a runnable demo should prove

What a runnable demo should prove

Build a simple tool that asks a question to an LLM (e.g. a small open model like Llama 3 or Qwen 3), runs both random sampling and beam search uncertainty methods on the same question ten times, and plots the confidence scores from each run. You should see that beam search confidence scores form a tight cluster (low variance) while random sampling scores bounce around (high variance). Then ask a wrong-answer question (one the model will get incorrect) and show that beam search confidence is lower (more uncertain) while random sampling might still be falsely confident.

variance_beam < variance_random && confidence_wrong_beam < confidence_wrong_random

The demo succeeds if: (1) beam search confidence scores wiggle less across runs, and (2) beam search correctly identifies wrong answers as uncertain while random sampling stays overconfident.
