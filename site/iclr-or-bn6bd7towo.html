Topology Matters in RTL Circuit Representation Learning

TopoRTL learns RTL circuit representations by modeling register-cone topology explicitly, encoding behavior-aware tokens, and aligning dual modalities under topological constraints.

Paper explainersAll themesOther

Register-transfer-level code is not ordinary text. It describes hardware dataflow: how signals move through logic, where state is stored, and how computations feed into one another over clocked updates. A language model that reads RTL as a sequence of discrete code symbols can capture some syntax but misses critical structure, because circuit meaning depends on graph topology as much as on local code symbols. TopoRTL is built around that observation. It decomposes each RTL design into register cones, creates two behavior-aware modalities, injects topology-aware position information, and trains the model to align the modalities while respecting the underlying circuit structure. The goal is a representation that supports power, performance, area prediction and other design tasks because it preserves how the circuit is wired and how it behaves.

Zero assumption version

RTL meaning depends on topology, not only symbol order

RTL describes digital hardware through signal assignments, registers, combinational logic, and control conditions. Two code fragments with similar symbol sequences can implement very different circuits if their data dependencies are different. Conversely, two circuits may be semantically similar even when written with different local syntax. A sequence-only encoder is therefore a weak fit for the domain.

Downstream tasks such as PPA prediction, retrieval, and generation all depend on structural properties: fan-in, fan-out, register dependency, control-flow interaction, and how logic cones feed state elements. If the representation fails to encode those topological relations, it cannot serve as a reliable basis for automated design tools.

The paper's move. Break RTL designs into register cones, represent them through dual behavior-aware modalities, add topology-sensitive positional encodings, and align the modalities with contrastive learning that respects circuit structure.

The hidden quantity

The hidden quantity

The hidden quantity is the circuit behavior implied by topology: which signals influence a register, how control conditions route data, and how local logic cones differ across designs. This information is only partially visible in symbol order. It emerges from how modules, wires, and state elements connect.

TopoRTL exposes that quantity by making register cones explicit and by encoding positions relative to cone structure and design structure. The dual-modality setup helps because one view can emphasize behavior-related code symbols while the other captures complementary structural context. Contrastive alignment then forces those views to agree on the same circuit semantics.

Why it works

Why explicit topology improves RTL feature representations

Register cones are a strong inductive choice because they center the representation around state updates, which are fundamental in hardware. Each cone collects the combinational logic that determines the next value of a register, so it naturally captures a functional unit that hardware designers already reason about. By decomposing the design this way, the model starts from objects that correspond to real circuit semantics instead of arbitrary token spans.

Topology-aware positional encodings then tell the weighted-interaction layers where each piece sits in the circuit graph. In ordinary text models, position means symbol index. In RTL, position also needs to express structural roles such as whether two nodes are in the same cone, how far they are in the dependency graph, and how cones relate across the whole design. That extra signal lets the model separate circuits that are textually similar but structurally different.

The contrastive alignment step closes the loop. Because the model receives two views of the same circuit and is trained to align them under topological constraints, it cannot rely on superficial token overlap alone. It must learn a representation that is stable across modalities precisely when the underlying circuit behavior and topology match.

Math after the picture

Align modalities while preserving circuit structure

First in words:

The model combines an encoder for topology-enriched RTL inputs with a contrastive objective that pulls matched modality pairs together and separates mismatched pairs, under constraints derived from circuit topology.

Then the compact form:

L_total = L_contrastive + lambda_t * L_topology

Every symbol:

L_contrastivethe loss that aligns matched pairs from the two RTL modalities and separates mismatched pairs
L_topologythe term that enforces structural consistency based on register-cone and design topology
lambda_tthe weight that controls how strongly topological consistency shapes the embedding
matched modality pairtwo views derived from the same RTL structure that should share the same semantic representation
A tiny worked example
Suppose two RTL modules both contain an add operation and a register assignment in text.
In module A, the add result feeds register r1 directly. In module B, the same add result goes through a conditional gate before reaching r1.
A sequence-only encoder may treat the modules as nearly identical because the local tokens overlap heavily.
TopoRTL separates them because the register-cone structure and topology-aware positions differ, so the topology term penalizes collapsing their representations together.
At the same time, the two modalities derived from module A are pulled toward one another by the contrastive term, reinforcing its circuit-specific feature representation.

The precise topology term may include several positional components, but the key idea is that structural differences contribute directly to the training objective.

What can go wrong

What can go wrong

Cone decomposition quality matters. If the preprocessing step extracts register cones poorly, the rest of the model is built on the wrong structural units and representation quality will suffer.
Topology signals can become expensive. Adding multiple topology-aware positional encodings and dual modalities increases preprocessing and model complexity compared with plain sequence encoders.
Contrastive pairs must reflect real structure. If positive and negative pairs are chosen without proper topological constraints, the model may align superficial similarities instead of genuine circuit behavior.
Done right. Keep the structural preprocessing faithful to hardware semantics and validate that ablations on the topology terms reduce downstream performance, confirming that the extra structure is doing real work.
What a runnable demo should prove

What a runnable demo should prove

Take a small RTL corpus with downstream labels for tasks such as retrieval or PPA prediction. Build one baseline encoder that reads symbol sequences and one topology-aware encoder that uses register-cone decomposition plus topology-aware positions.

The demo should include matched circuits with small textual changes but real topological changes, as well as circuits with varied syntax but similar behavior. A convincing result shows that the topology-aware model improves downstream task performance because its representations stay sensitive to circuit structure instead of relying mainly on text similarity.
