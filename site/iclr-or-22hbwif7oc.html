CompSLOT: Concept-Level Continual Learning with Foundation Models

Instead of learning which class an image belongs to, learn what visual building blocks make up each class, so the model does not forget old classes when learning new ones.

Paper explainersAll themesRepresentation & Self-Supervised Learning

When a vision model learns new classes one batch at a time, it forgets what the old classes looked like — a flaw called catastrophic forgetting. Most models try to fix this by remembering individual examples or carefully moving weights. CompSLOT takes a different path: it learns to see classes as collections of visual concepts (like 'has spots' or 'has four legs'), so when new classes arrive, the model can reuse those shared building blocks instead of rewriting all its weights and erasing memory of old classes.

Zero assumption version

Why do models forget?

When a model learns class recognition, it memorizes patterns: 'dog' looks furry and has four legs. If you then teach it 'cat', the model reshapes its weights to recognize cat patterns. In the process, the patterns for 'dog' get scrambled — catastrophic forgetting.

A beginner might try to fix this by saving some old dog images and mixing them into the new training batches. This works for a few classes, but you run out of memory, and the old examples do not teach the model anything new about the deeper structure of 'dogness' — just examples, not understanding.

The core failure. Models learn 'this exact image is a dog' instead of 'a dog is made of these building blocks', so they forget old classes when they reshapen their weights for new ones.

The algorithm as a flow

What it actually does

Extract concepts from the vision model

Ask the pre-trained vision transformer to identify semantic objects in the image (e.g. 'this region is a face'). These are called slots.

Select and combine the most useful concepts

Not every slot is important for every class. A mechanism picks which slots matter and blends them into a class description.

Measure concept similarity for each sample

For each image, compute how similar its concepts are to the concepts of each class. This becomes the model's new way to recognize classes.

Teach the classifier using concept patterns

Use self-supervision (learning from unlabeled patterns) to guide the classifier so it relies on stable concept patterns, not partial or incorrect examples.

Reuse this module for any continual learning method

CompSLOT works as a plug-in on top of existing continual learning strategies, without needing to redesign them.

What the paper changes

What the paper changes

Instead of classifying by matching the raw image against learned weight patterns, CompSLOT classifies by matching the image's extracted concepts against learned class concepts. The model now chooses which visual building blocks to focus on, and these building blocks stay consistent across old and new classes.

the object it moves  =  classification signal: from raw pixels to concept-based similarity
The hidden quantity

The hidden quantity: concept stability

measured quantity  =  concept stability — how much concept patterns persist across tasks

The paper does not use a fancy statistical term; it measures a straightforward quantity: when the model learns task two, how much do the concepts it learned for task one stay the same? A concept is stable if it still fires on the same kinds of image regions.

CompSLOT measures this by tracking which image regions activate each slot across the old and new tasks. If the same visual features keep triggering the same slots, the concepts are stable. If concepts drift wildly, they have become useless for old classes.

Why it works

Why this stops forgetting

The core reason catastrophic forgetting happens is that the model's weights encode both the low-level visual patterns (edges, textures) and the high-level class decisions (this is a dog) all tangled together. When you nudge the weights to recognize a new class, you scramble both layers at once.

CompSLOT separates these. The low-level visual patterns — the extracted concepts (has fur, has four legs) — come from a pre-trained model and are held mostly fixed. Only the top layer, which decides which concepts matter for which class, gets retraining. Because the building-block layer stays stable, old classes remain recognizable even after new learning. The concepts act like a shared vocabulary: 'dog' and 'wolf' both use the same concept list (fur, legs, ears, snout), so learning one does not erase the other.

The math: concept-based classifier

First in words:

final class score equals the sum of selected concept activations, weighted by how important each concept is for that class

Then the compact form:

score_class_c = sum_i w_ic * z_i

Every symbol:

score_class_cpredicted confidence that the image belongs to class c
w_ichow important concept i is for recognizing class c (learned weight)
z_iactivation level of concept i in this image (measured from the vision model)
sum_iadd up the contributions from all concepts
A concrete worked example
Image of a golden retriever arrives.
Vision model extracts concept activations: fur_texture=8.2, four_legs=7.1, floppy_ears=6.5, tail=5.3, whiskers=0.1.
Weights for 'dog' class: w_fur=2.0, w_legs=1.8, w_ears=1.5, w_tail=0.8, w_whiskers=0.0.
Dog score = 2.0*8.2 + 1.8*7.1 + 1.5*6.5 + 0.8*5.3 + 0.0*0.1 = 16.4 + 12.8 + 9.75 + 4.24 + 0.0 = 43.19.
Weights for 'cat' class: w_fur=1.8, w_legs=1.2, w_ears=2.0, w_tail=1.5, w_whiskers=2.5.
Cat score = 1.8*8.2 + 1.2*7.1 + 2.0*6.5 + 1.5*5.3 + 2.5*0.1 = 14.76 + 8.52 + 13.0 + 7.95 + 0.25 = 44.48.
Wait — cat won! But in next example, watch what stays stable when the model learns new task.
Concept activations barely change. Only w_ic weights shift to favor the new classes. Old classes remain scored high because their concepts are still strong.

The score combines how strongly each visual concept appears in the image with how important that concept is for the target class, so stable concepts mean stable classification.

What can go wrong

What can go wrong

The vision model was trained on the wrong domain. CompSLOT relies on a pre-trained model to extract concepts. If that model was trained on generic office objects but your new task is medical X-rays, the extracted slots will identify irrelevant features (desks, chairs, windows) instead of the visual patterns that matter in X-rays (bone density, lesions, anatomical boundaries). You need a foundation model that has seen images similar to your task.
Too many irrelevant or overlapping concepts. If the slot extraction produces hundreds of noisy or redundant concepts, the selection and aggregation mechanism has to untangle them, and the classifier becomes fragile. The primitive selection step must actually identify which slots matter.
The self-supervision signal is wrong. If the method that distills concept-based similarity into the classifier uses a flawed similarity metric, the classifier learns to weight concepts in ways that do not match what actually makes classes different. For example, if the similarity metric treats a 'has ears' concept as equally important for cats and dogs when it is actually much more distinctive for cats, the classifier will waste its learning capacity on useless similarities, and both old and new classes become harder to distinguish.
Done right: concept-based understanding survives task sequences. When the pre-trained model is relevant, concepts are clean and stable, and self-supervision reinforces good similarity patterns, the model forgets far less.
What a runnable demo should prove

What a runnable demo should prove

Build a five-task sequence: task one learns dogs, task two learns cats, task three learns birds, task four learns fish, task five learns cars. For each task, measure the accuracy on all previous tasks before and after training on the new one. A good demo compares CompSLOT (with concept stability) against a baseline that uses the same continual learning strategy but without the concept layer.

forgetting on task_i = accuracy_on_task_i_before_task_j - accuracy_on_task_i_after_task_j (measured after each new task j > i)

CompSLOT should show that forgetting stays low across all five tasks because the concept patterns persist, whereas the baseline shows catastrophic forgetting (accuracy dropping 40+ percentage points) as new tasks arrive.
