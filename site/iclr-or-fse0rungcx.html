Multimodal Policy Internalization for Conversational Agents

This paper moves long multimodal policies from the prompt into the model itself, because repeating complex rules on every request is costly and still does not guarantee faithful policy use.

Paper explainersAll themesAgents & Tool Use

Modern conversational agents often depend on long policy prompts that specify tone, tool rules, safety constraints, and business requirements. As those policies grow, two problems appear. First, every request pays the cost of re-sending the same long instructions. Second, the model still has to reason over that long text at run time, so compliance can fail when the request is hard or the policy mixes text and visual rules. This paper studies a different route: train the model so that the policy knowledge is internalized. The proposed setting, Multimodal Policy Internalization, asks whether a model can absorb those complex rules into its own behavior and still generalize to new multimodal tasks without carrying the full policy prompt every time.

Zero assumption version

Long policy prompts are expensive and unreliable

Many deployed agents rely on fixed policy text placed in the prompt. That policy may describe how to answer, when to use tools, how to format outputs, and how to respond to images or screenshots. The prompt keeps growing because each new business rule is added as more text.

This approach has two limits. The first is cost: every request pays for the same policy again, even when the user asks a simple question. The second is reliability: the model must parse and apply a long rulebook at run time, which becomes harder when instructions interact or when the request includes images plus text.

The paper argues that policies should be learned once and then reused from model memory. That is the motivation for policy internalization: move the durable rules into the trained model so that request-time processing can be shorter and policy-following can be more consistent.

Main claim: Train the model to carry the policy internally, because re-reading a long rulebook at every turn wastes compute and still leaves room for misses.

The algorithm as a flow

What it actually does

Collect multimodal policy tasks

The paper builds datasets with text and visual inputs because policy following must work across both types of evidence.

Inject policy knowledge early

A continual pretraining stage exposes the model to policy material first, so the rules become familiar before task-specific fine-tuning.

Fine-tune on policy-governed tasks

Supervised examples show what good policy-following responses look like under the new task setting.

Explore with policy-aware rollouts

The method expands rollout candidates with policy-guided responses, because reinforcement updates work better when exploration stays near policy-compatible behavior.

Deploy without the full policy prompt

At test time the model can answer with shorter prompting because the training process has already moved policy knowledge into the model.

What the paper changes

What the paper changes

The paper changes where policy knowledge lives. Instead of storing policy only in prompt text, it trains the model to carry those rules internally because learned policies can be reused on every request at lower cost.

The hidden quantity

The hidden quantity: policy recall without prompting

measured quantity  =  How much policy the model can apply from memory alone

A prompt-based agent looks compliant only while the policy text is present. The hidden quantity is whether the model can still apply the same rule after the policy is removed. That includes response style, tool-use conditions, and visual-task instructions.

The paper measures this indirectly through end-to-end performance and generalization after prompt removal. If the model keeps following the policy with shorter prompts, then policy recall from memory is high. If behavior collapses once the long prompt disappears, internalization failed.

Why it works

Why staged internalization can work

Prompt policies are a form of external memory. They are flexible, but they make every request carry the same overhead and they force the model to perform policy lookup during the answer. Internalization replaces repeated lookup with training-time absorption.

The three-stage recipe is important because policy learning is not just ordinary task fine-tuning. The first stage exposes the model to policy material broadly so that the rule content becomes familiar. The second stage shows correct policy-following responses on explicit tasks. The third stage lets the model explore candidate responses under reinforcement updates, but the rollouts are policy-aware so exploration stays near acceptable behavior instead of drifting into random answers.

This can reduce run-time cost and improve consistency because the model no longer depends on reprocessing a long policy prompt for every request. It can also help multimodal tasks because the training includes policy use over images as well as text, so the learned behavior is grounded in the same mixed-input setting seen at deployment.

A tiny worked example
Suppose an agent must answer calendar questions, use a scheduling tool only when needed, and format image-based summaries in a required style.
With prompt-only control, every request repeats all three rules, even when the user asks a simple scheduling question.
After internalization, the shorter prompt can omit most of the long policy because the model has practiced the same constraints during training.
If the model still chooses the tool only when necessary and still follows the style rule on image tasks, then the policy has been retained rather than merely re-read.

The equation summarizes the three stages, but the real contribution is organizational: teach the policy once during training so deployment can rely less on repeated prompting.

What can go wrong

What can go wrong

The model may forget other skills. If policy internalization dominates training too strongly, old capabilities can weaken because the new rule-learning updates overwrite earlier behavior.
Policy coverage can be incomplete. If the training data omits rare but important rules, the deployed model will still need prompt reminders because those cases were never internalized well.
Policy-aware rollouts can become too narrow. If exploration stays too close to known answers, reinforcement updates may miss better compliant behaviors because the candidate space is overly restricted.
Done right: shorter prompts keep the same behavior. When staged training covers the policy well and avoids forgetting, deployment improves because the model can follow the rules without re-reading a long prompt on every request.
