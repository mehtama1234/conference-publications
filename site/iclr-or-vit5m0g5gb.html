Saddle-to-Saddle Dynamics Explains Simplicity Bias

Neural networks learn simple solutions first by hopping between saddle points, where gradient descent naturally slows and stalls.

Paper explainersAll themesLearning Theory

When you train a neural network, it tends to learn simple solutions before complex ones, a pattern called simplicity bias. This happens across all types of networks: fully-connected (all neurons to all neurons), networks with local filters (scanning the input step by step), and attention models (comparing every part to every other part). But why? This paper shows that networks escape complexity by riding a special path through the loss surface: they approach a saddle point (a flat zone between two slopes), jump to a new flat zone, and repeat. Each hop lets them add exactly one new skill—a new layer, a new filter, a new attention head—without forcing old knowledge to rebuild.

Zero assumption version

Networks learn in layers, not randomly

You might guess a network learns all its skills at once, like flipping a switch from dumb to smart. In reality, networks learn progressively: first a very simple solution, then a slightly more complex one, then more complex still. This is simplicity bias.

A naive guess is that complexity just creeps in because the loss surface is random and bumpy. But the paper asks: what if the network is actually flowing down a hidden river, a special path made by the training math itself? What if simple solutions come first not by accident but because the weight-nudging math naturally pushes the network that way?

The question. Why do networks learn simple solutions first across all architectures—and can we prove it?

The algorithm as a flow

What it actually does

Approach a saddle

Gradient descent slides the network to a flat place—a saddle point where curvature is zero in one direction.

Live on the flat zone

While on the saddle, the network fine-tunes the solution, exploring many weight sets that all solve the task equally well.

Destabilize and escape

Noise in training (random mini-batches) nudges the network away from the flat zone, but only in the right way—toward a new solution direction.

Land on next saddle

The network arrives at a new saddle point, but with one more skill baked in: a second layer, a second filter, or a second head.

Repeat the cycle

Each cycle adds one discrete complexity leap, so the network learns in phases: simple first, then step by step more complex.

What the paper changes

The thing that changes: placement of skills

The paper doesn't invent a new training algorithm. Instead, it analyzes the existing path that gradient descent already takes. The central insight is about WHERE skills appear: one at a time, in sequence, not all mixed together. Early in training, the network uses only the first hidden unit, the first learned filter (a small window that scans the input), or the first comparison head. Only after that one saturates does the second appear.

the object it moves  =  skill (head, unit, or filter) count over time
The hidden quantity

The hidden quantity: effective complexity

measured quantity  =  number of active skills used by the network

The paper's key measurement is how many skills the network actually uses at each moment. For fully-connected networks, this is the rank of the weight matrix (how many independent directions the network can point in; higher rank means more skills). For networks with local filters, it is the number of filters actually extracting patterns. For attention models (which compare every part to every other part), it is the number of comparison heads that carry signal.

The paper shows that this number climbs in discrete jumps, not smoothly. The network sits at rank 1 for a long plateau, then suddenly jumps to rank 2, sits there, then rank 3. This stepped pattern is the signature of saddle-to-saddle learning.

Paper reading. The rank of the weight matrix (or the number of comparison heads that are in use) serves as a measure of effective dimensionality. The paper proves that gradient descent, moving along the flat zone of rank-k solutions, first saturates all k skills. Then a break occurs: the saddle point becomes unstable, and the network explores toward rank-(k+1) solutions.
Why it works

Why saddle-to-saddle motion forces one skill at a time

Here is the deep reason: the loss surface is not one big hill. Instead, it is made of flat zones (saddle points) connected by narrow passages. A saddle point is a place where the error curves downward in one direction (you can descend) and curves upward in another (you would climb). When you are on a saddle, the curvature in most directions is zero—you are on a flat table.

Weight-nudging cannot keep the network on a flat table forever. Noise in the mini-batches (random sampling of training data) jiggles the network and eventually pushes it off the saddle. But here is the trick: the shape of the loss surface ensures that the network is pushed off in exactly one new direction—the direction that adds one new skill. The network lands on a higher-rank saddle point (a new flat table), where it can now use two skills together. The cycle repeats.

Why does this create simplicity bias? Because each cycle is slow: the network sits on a saddle for many training steps before noise breaks it free. So the network spends most of its time on low-complexity saddles, learning simple solutions well before moving to complex ones.

Math after the picture

The math: saddle points and flat zones

First in words:

loss on rank-k manifold + perturbation energy = network destination

Then the compact form:

minimize_theta loss(theta) subject to rank(theta) = k; at saddle, d(loss)/d(theta) is orthogonal to the manifold

Every symbol:

thetaall the network weights
loss(theta)how wrong the network's answers are
rank(theta)the number of independent skills (or directions in the weight matrix)
manifoldthe set of all weight configurations with exactly k skills
d(loss)/d(theta)gradient: which way and how hard to nudge each weight
Tiny numeric walkthrough
Suppose a network has 12 weights and is trained on rank-1 (one skill used).
Loss on rank-1 manifold: 0.5 (very good).
Gradient points perpendicular to the manifold; attempting rank-2 would increase loss to 0.52 (tiny jump).
But the manifold itself has curvature: noise in mini-batches creates a small drift perpendicular to the saddle.
After many training steps, that drift accumulates, pushing the network toward rank-2.
Once on rank-2 manifold, loss becomes 0.48 (better, using two skills together).
Network sits here, refining both skills until noise again breaks it free.

Saddle points are special: they are critical points of the loss (gradient-descent steps land here) but locally unstable in at least one direction, so noise or perturbation can escape them—but only along the flat-zone structure.

What can go wrong

What can go wrong

Architecture mismatch. The paper assumes the architecture is deep enough to have plateaus. A tiny network with only one or two possible skills will not show stepped learning.
Too many weights without bottlenecks. If the network is so wide that all skills activate at once (no bottleneck), the saddle-to-saddle path becomes less clear. The network does not need to choose which skill to add first.
Data too simple. If the task only requires one skill to solve (e.g., a linear classification problem), the network never needs to escape the first saddle. No second skill is added, so simplicity bias becomes a permanent solution, not a temporary phase.
Done right: architecture with natural bottlenecks. The theory holds when the model has a clear definition of skill (like a layer width or filter count) and when the training task genuinely needs multiple skills. Then the saddle-to-saddle dynamics emerges and simplicity bias is automatic.
What a runnable demo should prove

What a runnable demo should prove

Build a small fully-connected network on a synthetic task (for example, learning to XOR three different binary patterns). Instrument the training to measure the rank of the weight matrix (using singular-value decomposition) at every 10 training steps. Plot the rank over time alongside the training loss. The demo should show: (1) the rank stays at 1 for an initial phase while loss drops slowly, (2) the rank suddenly jumps to 2 (a cliff-like event), (3) loss continues to drop as the network fine-tunes with rank-2, (4) the rank later jumps to 3, completing the skill set.

active_skill_count = number of singular values of weight matrix above a threshold (e.g., 0.1 × max singular value); should show jumps, not smooth growth

The central message: simplicity bias is not a side effect of randomness—it is the natural path that gradient descent follows on shaped loss surfaces, appearing whenever the network reaches a saddle point and noise gently nudges it to the next one.
