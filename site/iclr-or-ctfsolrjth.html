Gradient-Aligned Calibration for Diffusion Model Quantization

Shrink diffusion models by learning which calibration samples matter most at each denoising step, so conflicting update directions stop canceling each other out.

Paper explainersAll themesGenerative Models & Diffusion

Diffusion models generate images by slowly denoising random noise through hundreds of steps. To run them on phones or edge devices, you shrink the model to fewer bits. But the shrinking breaks: different denoising steps have opposite optimization directions, so trying to satisfy them all pleases none. This paper learns which samples matter at each step and weights them accordingly.

Zero assumption version

Why shrinking a diffusion model breaks across timesteps

A diffusion model works like this: start with pure noise, then run a neural network 100 to 1000 times, each time removing a little noise, until you get a clean image. Every run through the network is called a timestep. To deploy it on a phone, you shrink each weight to fewer bits: from 32 bits down to 8 or 4, by rounding numbers to fewer decimal places.

The naive approach treats all timesteps equally. You collect sample images generated at different denoising stages, measure how shrinking hurts the network at each stage, and then adjust the weights to fix all stages at once. This fails: the early-stage samples pull the weights one direction to fix their own errors, while late-stage samples pull the opposite direction. The weight updates cancel out, so every timestep gets worse, not better, because no single weight choice satisfies them all simultaneously.

In one sentence. Learn which calibration samples matter most at each denoising timestep, then weight them when adjusting weights, so the direction of change aligns instead of fighting.

The algorithm as a flow

What it actually does

1. Collect samples

Generate calibration images at different denoising timesteps: some from early steps, some from middle, some from late.

2. Measure direction disagreement

Shrink the weights to fewer bits, then measure how the shrunken network performs on each timestep's samples. Plot the error separately per timestep—you see a jagged line, not flat.

3. Learn sample weights

Assign each calibration sample a learnable weight showing how much it should influence the shrinking step. Samples from conflicting timesteps get lower weight.

4. Re-shrink with weights

Shrink the weights again, but this time emphasize samples whose update directions align across timesteps. Ignore samples pulling the opposite way.

5. Validate on groups

Partition timesteps into 5 groups (early, early-mid, middle, mid-late, late) and measure error separately. Aligned timesteps now show lower error across all groups.

What the paper changes

What the paper changes

The paper does not change the weights themselves. It changes how much each calibration sample gets to vote when you are deciding what the new shrunken weights should be. Each sample gets a weight (a number between 0 and 1) that says: this sample is important to shrinking, or this sample pulls the wrong direction ignore it. Samples from timesteps whose update directions align with others get high weight; samples from conflicting timesteps get low weight.

the object it moves  =  calibration sample weights
The hidden quantity

The alignment score

measured quantity  =  how much update directions agree across timesteps

The paper measures a hidden quantity: do the update directions agree across timesteps? Imagine you have 100 denoising timesteps, and for each one you compute which way the weights need to move to reduce error (move weight X left or right). If timestep 10 says move weight X left and timestep 50 says move weight X right, they conflict. The alignment score measures this disagreement.

The paper estimates this by computing the update direction (called a gradient: the list of numbers showing which way each weight should move) for calibration samples from each timestep. It then learns sample-specific weights that, when applied during shrinking, minimize the disagreement between these update directions. The result: a shrunken model where all timesteps point the same direction, so the weight updates reinforce instead of cancel.

Why it works

How alignment fixes shrinking

Start with the problem: shrinking error is not the same at every timestep. Early steps (when the image is mostly noise) need weights moved one way to minimize error; late steps (when the image is almost clean) need weights moved the opposite way. You have one set of weights to adjust. Traditional methods treat all timesteps equally, so the updates point in conflicting directions. The weights stay near their starting point instead of moving decisively toward lower error, because moving toward one timestep's goal makes another timestep's error worse.

The paper's fix: learn to weight each calibration sample by how much its update direction aligns with others. Samples from timesteps whose updates point the same direction get high weight; samples from outlier timesteps get low weight. When you shrink the weights using this weighted sample set, the updates all push the same direction, so the weights move decisively toward a point where all timesteps have lower error. You are not rewriting the underlying problem—you are rebalancing which samples count. The result: error plotted separately per timestep—goes from a jagged line (some timesteps lose when others win) to a smoother line (all timesteps lose less). Each timestep improves because the weight moves toward a compromise point, not torn between opposites.

Math after the picture

The weighted shrinking objective

First in words:

The goal is to minimize a weighted sum of errors across timesteps and samples, where each sample gets a weight that reflects how much its update direction aligns with others. The error for sample i at timestep t in the shrunken model is counted by weight omega_i, which the method learns.

Then the compact form:

L = sum_t sum_i omega_i * error_t(x_i, theta_Q)

Every symbol:

omega_ilearned weight for sample i (between 0 and 1); shows alignment
error_t(x_i, theta_Q)error of sample i at timestep t using shrunken weights theta_Q
theta_Qthe shrunken model weights (4-bit or 8-bit)
sum_tadd up across all timesteps
sum_iadd up across all samples
A tiny worked example
Suppose you have 3 calibration samples, each from a different timestep.
Sample 1 from early timestep: update direction points right. omega_1 = 0.9 (high, aligns with others)
Sample 2 from middle timestep: update direction points right. omega_2 = 0.85
Sample 3 from late timestep: update direction points left (opposite). omega_3 = 0.2 (low, conflicts)
Weighted error: 0.9 * 5.0 + 0.85 * 4.8 + 0.2 * 6.5 = 4.5 + 4.08 + 1.3 = 9.88
If all samples had equal weight (1/3 each): 5.0 + 4.8 + 6.5 = 16.3 (worse, because sample 3 pulls backward)
By downweighting sample 3, shrinking focuses on the aligned direction, so all timesteps reduce error together.

The weights are learned so that when you minimize this weighted error, the updates from different timesteps point the same way, letting them reinforce instead of cancel.

What can go wrong

What can go wrong

Calibration set too small. If you have only a few samples per timestep, the method cannot reliably measure which samples point the same direction and which are outliers. With fewer than 256 samples per timestep, the learned weights become unreliable, because random noise dominates the alignment signal.
Extreme timestep imbalance. If 90% of your calibration samples come from early timesteps and only 10% from late ones, the method cannot accurately score weights for the rare late timesteps, because it has no data to estimate their alignment. The calibration set needs roughly equal samples across timestep groups.
Validation set too large. The validation set is used to measure error separately per timestep. If it is too large, it dominates the learning and prevents the method from focusing on alignment. The paper uses 5% of the training set for validation.
Done right. Use at least 256 calibration samples per timestep, balance timesteps evenly, keep validation small (5%), and partition timesteps into 5 groups for independent measurement. This lets the method learn accurate weights.
What a runnable demo should prove

What a runnable demo should prove

Build a diffusion model shrinker that compares two methods: (1) uniform shrinking (all samples weighted equally), and (2) alignment-based shrinking (samples weighted by direction agreement). Use a small diffusion model trained on CIFAR-10 (32x32 images). Generate calibration images at different timesteps (e.g., 10 early, 10 middle, 10 late). Shrink to 8-bit weights. Then measure error and image quality separately for each timestep group. Plot results as two bar charts—uniform vs aligned. The demo must show: without alignment, early timesteps improve while middle and late get worse, because updates pull opposite ways. With alignment, all three improve together, because the learned sample weights cancel the opposing pulls.

FID = Frechet Inception Distance (how different generated images are from real ones); lower is better. Measure separately per timestep group: FID_early, FID_middle, FID_late. Plot both methods side by side. The aligned method should have smaller range (lower variance) across the three groups.

The demo exposes: alignment does not make all timesteps equally perfect, but it stops the one-sided trade-off where one timestep winning means others lose. All three groups reduce error together because update directions reinforce instead of cancel.
