Knowledge Diversion: Reusing Transformer Parts Across Robot Bodies

Break a robot controller into universal pieces (shared across all bodies) and specialized pieces (one per body and task), so the same model can run efficiently on tiny robots and transfer to new tasks without retraining.

Paper explainersAll themesRobotics & Control

Teaching a robot to move is hard. Teaching one model to control many different robot bodies is much harder — their joints, limbs, and sensors are all different. A Transformer (a type of neural network) can learn to do this, but it is huge and wasteful: it learns each robot separately and needs retraining for each new task. This paper proposes DivMorph, which splits the Transformer into two types of pieces: universal pieces that every robot learns and uses, and specialized pieces that adapt to each robot's unique shape and each specific task. This way, a single model can switch between robots and tasks because the universal pieces are already trained for any robot, so only the specialized pieces change; it runs on smaller devices because only the active pieces run at once; and it learns new tasks much faster because the universal knowledge has already been learned on earlier tasks.

Zero assumption version

One model for many robots: bloated and stuck

A Transformer is a type of neural network, a system of connected layers that learns by adjusting weights (numbers that control how signals flow through the network). Transformers learn patterns from examples, so people use them to control robots. But here is the problem: every robot body is different. A quadruped (four-legged robot) has different joints and sensors than a humanoid (human-shaped). A Transformer trained on a quadruped cannot control a humanoid without retraining from scratch.

The naive approach: train one big Transformer per robot. But this wastes memory and computation. The Transformer has millions of weights, and most of them are probably learning things that should be the same across all bodies — like how to read sensor data or how to avoid falling. Why duplicate that work?

Second naive approach: train one universal Transformer to handle all bodies at once. This seems smart, but it forces every robot to use every weight, even the specialized knowledge one robot does not need. The model becomes bloated. Worse, when a new task arrives (e.g., grasping instead of walking), you have to retrain the entire Transformer, burning samples and time.

The paper's move: Split the Transformer weights into learngenes (universal knowledge all robots share) and tailors (robot- and task-specific knowledge), then switch between them with soft gating (learnable routing controlled by the robot and task).

The algorithm as a flow

What it actually does

Start with a big random Transformer

Initialize weights normally; do not train yet.

Factorize with SVD

Break each weight block into ranked parts (like unpacking a messy filing cabinet into sorted labeled bins).

Train soft gating routes

Learn which parts to activate based on the robot type and task. The router is a small learned function.

Fine-tune learngenes and tailors

Update the shared weights (learngenes) on all robot/task pairs; update specialized weights (tailors) per pair.

Deploy or transfer

Pick a robot and task, activate only their pieces, run the lean model or train tailors for a new task.

What the paper changes

The one thing that changes: which Transformer weights get used

Instead of using all weights for every robot, DivMorph uses a small router (controlled by robot and task embeddings) to mix universal weights (learngenes) and specialized weights (tailors). The router does not add much computation; it is just a learned gating function that says how much of each component to use for this particular situation.

The hidden quantity

The hidden quantity: knowledge overlap

measured quantity  =  Knowledge overlap between robot morphologies

The paper assumes that different robot bodies share some core knowledge (how to parse sensor data, how to coordinate movements) but differ in details (how to use six legs vs two arms). Knowledge overlap is the fraction of a Transformer's weights that can be reused across bodies without hurting performance. High overlap means most weights are learngenes; low overlap means most are tailors.

The paper infers overlap by factorizing the weights via SVD (Singular Value Decomposition, a math trick that breaks down a grid of numbers into ranked components) and observing how many low-rank components are enough to represent the learned behavior. If a few components work for all robots, overlap is high. If each robot needs its own components, overlap is low. DivMorph measures this implicitly by tuning which components to activate for each robot/task pair.

Why it works

Why splitting weights by robot type works

Imagine a Transformer as a filing cabinet with millions of drawers, each holding a number (a weight). To make the model work for all robots, you could fill all drawers the same (wasteful) or fill some drawers universal and others specialized (smart). The problem is you do not know which drawers should be which until after training.

DivMorph solves this by treating the weights as a grid of numbers and using SVD to reveal hidden structure. SVD finds the most important 'directions' in that grid — the components that carry the most signal. If a quadruped and humanoid both rely on the same top few components, those components are universal (learngenes). If each robot needs different low-importance components, those are specialized (tailors). The soft gating function learns to mix them: given a robot type and task, it says 'use 80% of learngene #1, 20% of learngene #2, and 100% of this tailor.' This recomposition is efficient because you run only the pieces you need.

Why does this help transfer? When a new task arrives, most of the Transformer (the learngenes) is already trained on many robot/task pairs, so it is a strong starting point. Only the tailors need to learn the new task, and since they are much smaller than the full Transformer, they require far fewer training samples to converge; retraining from scratch would require learning both universal and specialized pieces together from zero, which is much slower.

Math after the picture

The core equation: soft mixing by gating

First in words:

For each Transformer component, the active weight is: gate-score times the learngene plus one-minus-gate-score times the tailor. The gate score is a learned function of the robot type and task. Summed across all components, this gives the final Transformer for deployment.

Then the compact form:

W_active = g(robot, task) * W_learngene + (1 - g(robot, task)) * W_tailor

Every symbol:

W_activeThe weights actually used by the Transformer for this robot/task pair
g(robot, task)Soft gate score, a number between 0 and 1, learned to decide the blend
W_learngeneUniversal weights shared across all robots
W_tailorWeights specialized for this robot and task
A tiny worked example
Say the learngene has weight 0.5 for sensor-reading and the tailor has weight 0.3.
A quadruped sends robot='quad', task='walk'. The gating function learns: g(quad, walk) = 0.7.
Active weight = 0.7 * 0.5 + (1 - 0.7) * 0.3 = 0.35 + 0.09 = 0.44.
A humanoid with robot='biped', task='walk' might get g(biped, walk) = 0.6.
Its active weight = 0.6 * 0.5 + 0.4 * 0.3 = 0.30 + 0.12 = 0.42.
Same learngene, different tailor emphasis, one gate per pair: each body learns a custom blend with minimal duplication.

The gate acts as a volume knob, blending universal knowledge (learngene) with robot-specific knowledge (tailor) on the fly.

What can go wrong

What can go wrong

The gate learns wrong blends. If the gating function is too simple (e.g., a shallow network), it may mix learngenes and tailors poorly, and the policy fails. The paper uses embeddings of the robot and task, so the gate can learn flexible blends, but a bad initialization could hurt.
Learngenes overfit to early robots. If training starts with only quadrupeds, the learngenes may specialize to quad walking, making them useless for bipeds. Careful curriculum or balanced sampling is needed.
SVD ranks chosen wrong. SVD factorization requires choosing how many components to keep. Too few and you lose signal; too many and you lose compression. The paper does not fully detail how this is chosen, so tuning per domain may be needed.
Done right: learngenes emerge as general, tailors as specialized. With proper training, learngenes capture sensor reading and basic movement logic (useful for all robots), and tailors adapt to body shape and task, achieving both compression and transfer.
What a runnable demo should prove

What a runnable demo should prove

Build two simple robots (e.g., a 4-legged simulator and a 2-legged simulator using PyBullet or MuJoCo). Train a DivMorph Transformer on both, toggling the gating network conditioned on robot type. Measure: (1) model size for a single-robot deployment (should be 10-20x smaller than a full Transformer), (2) sample efficiency for transfer (train the 4-legged on walking, then finetune only the 2-legged tailor to learn jumping; count samples needed and compare to retraining from scratch).

Transfer efficiency = samples_naive_retrain / samples_finetune_tailors. Model compression = size_full_transformer / size_deployed_model.

The demo must make it impossible to miss: learngenes enable fast transfer and small deployment size because they are already well-trained on the first task, so the new task only needs to tune tailors, not rebuild the whole model.
