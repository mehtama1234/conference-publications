Knowledge Diversion for Efficient Morphology Control

Split a robot controller into reusable pieces and task-specific parts by decomposing its weight matrices at the start.

Paper explainersAll themesRobotics & Control

Building a single robot controller that works for many different robot shapes and many tasks is expensive — the model gets huge and you need to retrain it from scratch for each new task. This paper proposes DivMorph, which decomposes the controller's weights into universal building blocks and task-specific adaptations upfront, letting the same pieces recombine for different robots and tasks with far fewer numbers to store.

Zero assumption version

Many robots, many tasks, one model that breaks at scale

Today, if you want a robot controller that works for, say, 100 different robot shapes and 5 different tasks each, you face a dilemma. One approach: train a single giant universal model that sees all robots and all tasks at once. It works in theory, but the model explodes in size — a transformer that handles all combinations of limbs and task instructions becomes so large that it is expensive to run and takes forever to train. The other approach: train separate models for each robot-task pair. This is lightweight but defeats the purpose — you are now maintaining 500 different models, and each new task requires retraining from scratch on each robot.

A beginner might try to just shrink the big model with tricks like pruning (delete weights you think are unimportant) or quantization (round numbers to fewer bits). But these fail because the real problem is not just size — it is that the model mixes together the knowledge it needs (movement rules that work on any robot), the details that are robot-specific (how many joints does this robot have), and the details that are task-specific (go to a goal vs. pick up an object). All tangled together, you cannot reuse the shared part without keeping the extra baggage.

In one sentence. Separate the universal knowledge in a robot controller from the pieces that vary by robot shape or task, so the same components can be reused.

The algorithm as a flow

What it actually does

Decompose the weights

Before training, break each weight block via SVD into ranked pairs of number-lists.

Assign factor units to roles

Label each pair as shared knowledge, robot-shape knowledge, or task knowledge.

Encode the context

Convert robot morphology (limb counts and types) and task instructions into short summaries of numbers.

Soft gate the factors

Use dynamic soft gates — soft weights that sum to 1, not binary on/off — to scale each factor based on context.

Train once, recombine many ways

Standard RL training now adjusts only the gate weights and shared knowledge; task-specific and robot-specific pieces stay separate.

What the paper changes

What the paper changes

The paper does not train a single huge weight block (the learned numbers in the neural network). Instead, it starts with weights broken into pieces and trains which pieces to activate. At inference (when the finished model answers a new question), it selectively activates different pieces depending on the robot and task.

the object it moves  =  the gates that activate pieces
The hidden quantity

The hidden quantity: knowledge compartmentalization

measured quantity  =  degree of knowledge disentanglement

The paper's core claim rests on a hidden measurement: how well separated are the shared, robot-specific, and task-specific components in the trained model? Conceptually, if the decomposition works, the shared factors should be active for all robots and tasks, while the robot-specific factors should fire only for that robot, and task-specific factors only for that task. The paper does not give a single numeric score for this, but infers it from whether the trained gates actually specialize — whether learned gate patterns cluster by robot or by task.

The paper estimates this hidden quantity by examining the learned gate patterns post-training and checking whether different robots learn different gate combinations (morphology disentanglement) and different tasks learn different combinations (task disentanglement). High disentanglement means the pieces stayed separate; low disentanglement means they got tangled again.

Why it works

Why decomposition lets reuse work

SVD factorization works because it breaks a complex weight block into a ranked sum of simple pieces. The insight: not all pieces are equally important for all robots or tasks. By using soft gates to selectively scale each piece, the training algorithm can learn which pieces to trust for which scenario. When the model learns that some pieces are always needed (shared learngenes) and others only for specific robots or tasks (tailors), the shared pieces stay stable and reusable while the tailors get tuned freely. This avoids the entanglement that killed earlier approaches.

The soft gating (using mixture-of-experts weighting instead of binary on/off) matters because it allows multiple pieces to be adjusted at once during training and because partial turn-on of the parts prevents catastrophic failure. During training, if a piece helps a little, the soft gate can scale it to 0.3 instead of forcing it fully on or fully off. This matters because binary gating forces a hard choice — either a piece is fully in (gate at 1) or fully out (gate at 0) — which can lead to oscillation as training pushes and pulls; soft gates slide smoothly, so small adjustments compound reliably rather than flipping. More importantly, soft gates make it harder to accidentally erase a shared piece when tuning for one specific robot, because even if a new task pushes down on a shared factor, other tasks can pull it back up gradually through their soft gates. Because the shared pieces are used by all robots, turning them off ruins everything; soft gates let multiple robots compete for the same factor safely.

The core equation

First in words:

Each factor unit is scaled by a soft gate weight, then summed. The soft gate weight depends on the robot and task embeddings.

Then the compact form:

controller_output = sum_j ( softgate_j(morph, task) * factor_unit_j )

Every symbol:

controller_outputthe final learned numbers used for this scenario
softgate_j(morph, task)learned weight for factor unit j, ranges 0 to 1, input-dependent
factor_unit_jthe j-th pair from SVD, treated as a building block
morphsummary numbers describing robot morphology (limb counts and types)
tasksummary numbers describing task instructions (text converted to numbers)
A tiny worked example
Suppose a weight block has 4 factor units: shared, robot-A, robot-B, task-goal.
For robot A doing a go-to-goal task: gate weights are 1.0, 0.9, 0.1, 0.8 for shared, robot-A, robot-B, task-goal respectively.
For robot B doing the same task: gate weights are 1.0, 0.1, 0.9, 0.8.
Same shared (1.0) and task-goal (0.8) factors, but robot-A now 0.1 (off) and robot-B now 0.9 (on).
Final output for robot A: 1.0 times shared plus 0.9 times robot-A plus 0.1 times robot-B plus 0.8 times task-goal. For robot B: 1.0 times shared plus 0.1 times robot-A plus 0.9 times robot-B plus 0.8 times task-goal. Same shared piece and task piece; robot piece swapped.

The soft gates learn which factors to activate; shared factors stay high across all robots and tasks, task-specific factors vary by task only, and robot-specific factors vary by robot only.

What can go wrong

What can go wrong

Shared factors get accidentally erased. If a new task requires disabling a shared factor (turning its soft gate to 0), it breaks all other robots. This happens if the shared factor is poorly chosen or the task is incompatible with the factorization. Solution: validate that shared factors appear in many successful trajectories; if not, reclassify.
Soft gates converge to the same value for all robots or tasks. If the gates do not specialize — if the model learns that activating all factors equally always works — then you have no disentanglement and no benefit. This can happen if the factor units are not truly separable (SVD gave nearly equal singular values) or if the downstream loss does not punish model size. Solution: monitor whether gates cluster differently per robot or task post-training; retrain with a size penalty term if gates stay flat.
Overfitting to training robots and tasks. Robot-specific and task-specific factors can overfit to the training set, so they transfer poorly to unseen robots or tasks. This looks like high disentanglement but low zero-shot accuracy on new morphologies. Solution: test on held-out robots and tasks; gently steer tailor factors to stay smaller using a penalty in training.
Done right. SVD factors are truly separable (singular values decrease clearly), soft gates specialize by morphology and task (measurable via gate clustering), and shared factors remain high across all contexts (no accidental zeros). Zero-shot transfer works.
What a runnable demo should prove

What a runnable demo should prove

Build a minimal version: train a transformer controller on 10 robot morphologies and 2 tasks using standard RL (PPO or similar). Apply SVD to one weight block in the transformer. Manually assign the singular vector pairs to learngenes (first 3), robot-specific tailors (next 2), and task-specific tailors (last 2). Add soft gating layers that take morphology and task number-lists and output gate weights. Train only the gating weights and the shared learngenes; freeze the tailor factors at their initial random values. On a new morphology or new task, recompute the gate weights only.

cross-task-transfer-sample-efficiency = samples-needed-for-naive / samples-needed-for-DivMorph ; model-size-ratio = naive-params / DivMorph-params

The demo must show that soft gating alone (learning gate weights for pre-decomposed factors) reaches 50% of the performance of full training, and that reusing shared factors cuts sample cost to a third or less.
