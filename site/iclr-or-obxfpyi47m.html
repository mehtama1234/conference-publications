Efficient Reinforcement Learning by Guiding World Models with Non-Curated Data

Use messy offline data to train a world model that guides exploration, then rehearse and steer with that model to learn faster from new experience.

Paper explainersAll themesReinforcement Learning

Reinforcement learning agents learn by trial and error, which is slow. If you have old data lying around, you can reuse it to speed learning. But the old data is often messy—collected by different robots, with no reward labels, mixed quality. This paper shows how to take that garbage pile and turn it into a useful teacher by training a world model (a machine that predicts what happens next) and then using two tricks—experience rehearsal and execution guidance—to avoid the prediction errors that usually break this approach.

Zero assumption version

Messy offline data fails to speed learning

Reinforcement learning needs thousands of interactions (actions and their results) to train a good policy. A naive approach: take your old data—from past robots, reward-free exploration, whatever you have—and train a world model (a predictor of 'what happens next') on it, then use that model to run fake interactions inside the computer. But this fails on many tasks. When you fine-tune your model on the old data, it shifts its behavior to match the old patterns. Then when you ask it to predict the new robot's experience, it is predicting from the wrong starting point. The model makes mistakes. Those mistakes compound during planning, and planning fails.

The beginner tries: fine-tune the model, then plan with it. The world model becomes specialized to old data and breaks when predicting the new robot's behavior.

In one sentence. Offline data helps only if you rehearse old experiences while updating (so the model does not forget what it learned before) and steer planning to stay in familiar regions (where predictions are accurate because the model has seen those states many times).

What the paper changes

What the paper changes

The paper changes how the world model is trained and used. Instead of just fine-tuning once and then planning, it rehearses old data during fine-tuning (mixing in old data keeps the model from drifting away from what it learned before) and constrains planning to stay in regions where the model is confident (because the model makes smaller errors in familiar territory).

The hidden quantity

Distributional shift: the wedge between old and new

measured quantity  =  distributional shift during fine-tuning

Distributional shift is a measure of how different the new robot's experience looks compared to the old data. When you fine-tune a model trained on robot A on data from robot B, the model drifts to predict B better because the weight updates point toward B's patterns, and at the same time loses accuracy on A because those old patterns fade. This shift grows during training, causing the model to make larger and larger errors when it encounters a state it has not seen before.

The paper estimates this shift by monitoring how much the model's predictions diverge from the old data distribution. Experience rehearsal (mixing in old data) keeps the shift small by anchoring the model to familiar ground. Execution guidance (planning only in familiar states) avoids the regions where shift causes the biggest errors.

Why it works

Why rehearsal and guidance work together

Experience rehearsal works because it forces the model to remember the old data. Every time you show the model a batch of old experience alongside new experience, the model learns to predict both. The gradient updates point in two directions at once: steer toward the new data, but do not leave the old data behind. This keeps the model from drifting too far. The model stays in a middle ground where it works well on both old and new.

Execution guidance adds a second safety net. Even if the model has shifted a little, you do not let the planning algorithm venture into places where the model is guessing. You measure how often each state appeared in the old data. During planning, you only follow actions that lead to states that appeared at least some minimum number of times. This is like saying: plan a path, but only along roads you have actually driven before. When the planner is forced to stay on familiar ground, prediction errors are small, and the fake interactions are realistic. The real RL agent learns from good fake data.

Math after the picture

The rehearsal and guidance equations

First in words:

total loss = prediction loss on new data + lambda times prediction loss on old data, where lambda is a weight that says how important it is to not forget the old data. then, during planning, the planner only follows actions where the resulting state has been seen at least M times in the old data.

Then the compact form:

L_total = L_new + lambda * L_old, then filter actions where count(state) >= M

Every symbol:

L_newhow wrong the predictions are on new experience
L_oldhow wrong the predictions are on old data
lambdahow much to punish drifting from old data (higher = more rehearsal)
count(state)how many times this state appeared in the old offline data
Mthe minimum visit count threshold; only plan through common states
A tiny worked example
New data batch: model predicts the next state wrong by 0.8 units. L_new = 0.8.
Old data batch: model predicts old states wrong by 0.3 units. L_old = 0.3.
Set lambda = 2.0 (rehearsal strength). L_total = 0.8 + 2.0 * 0.3 = 1.4.
Without rehearsal (lambda = 0): L_total = 0.8 only. But the model drifts and loses old knowledge.
With lambda = 2.0: both old and new predictions improve together.
During planning: a state visited 150 times in old data passes (150 >= M = 100), so planning uses it. A state visited 5 times is rejected (5 < 100), so the planner avoids it.

The rehearsal weight lambda keeps the model balanced on both datasets, and the visit-count threshold M keeps planning on solid ground.

What can go wrong

What can go wrong

Too much rehearsal weight (lambda too high). If you over-rehearse the old data, the model refuses to adapt to the new robot. The policy learns well on the old patterns but fails on the new robot. Balance is needed.
Visit count threshold M too high. If you only allow planning in states seen 1000+ times, you rule out most of the state space because most states appear only a handful of times. The planner cannot find a path, or finds only trivial paths that do not explore.
Visit count threshold M too low. If M is 1 (accept even unseen states), execution guidance does nothing; the model drifts and makes errors.
Offline data has very bad quality. If the old data is mostly wrong (collected by a broken robot), rehearsing it teaches the model bad patterns. The method amplifies garbage.
Done right. Tune lambda and M empirically: rehearsal should be noticeable but not dominant, and execution guidance should open up most of the useful state space. With careful tuning, the two techniques balance and learning is fast.
What a runnable demo should prove

What a runnable demo should prove

Build a simple grid-world where an agent learns to reach a goal. Generate two datasets: old messy data (collected by a random policy) and a small online budget (say 1000 real steps). Train a world model on the old data. Then run three experiments: (1) learn from scratch with no offline data; (2) learn with a world model fine-tuned naively on old data (breaks); (3) learn with a world model trained with experience rehearsal and execution guidance. Plot sample efficiency (how many real steps until 90% success rate) for all three. The third should reach 90% in roughly half the steps of the first.

sample efficiency = minimum real steps to reach 90% success rate on goal reaching

The metric proves that rehearsal and guidance are necessary: naive fine-tuning does not help (because the model drifts and makes errors), but the two techniques together cut sample complexity roughly in half because they keep the model grounded and predictions accurate.
