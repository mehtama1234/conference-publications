FSD-CAP: Fractional Subgraph Diffusion with Class-Aware Propagation for Graph Feature Imputation

When most node features are missing in a graph, use local subgraph diffusion with adjusted propagation strength instead of global methods, then refine using class labels.

Paper explainersAll themesGraph & Geometric Learning

Graphs often have missing node features due to incomplete data collection or privacy. A beginner tries to guess missing features by looking at all similar nodes (global diffusion), but this spreads errors and breaks down when 99 percent of features vanish. This paper proposes FSD-CAP, which locates small nearby regions in the graph, runs focused propagation in each region with tuned strength, and then refines guesses using class information and how diverse each node's neighbors are.

Zero assumption version

Missing node features break graph predictions

Graphs represent relationships between items: a social network connects people, a citation network connects papers, a knowledge graph connects concepts. Each node (person, paper, concept) usually has features describing it. But real data is messy—some features are deleted, hidden for privacy, or never collected.

A beginner tries the simplest fix: look at neighboring nodes and average their known features. This works fine when only a few features are missing. But when 99 percent of features vanish, averaging neighbors becomes pure guessing. Worse, when a neighbor makes a wrong guess, that error spreads to its neighbors, then to their neighbors, contaminating the whole graph.

The problem. Global averaging across the entire graph breaks when almost all features are missing, because errors cascade and the method has no way to tell which regions of the graph should be handled differently.

The algorithm as a flow

What it actually does

Find nearby nodes

For each node with missing features, find a small cluster of nearby nodes using graph distance.

Run local diffusion

Within that small cluster, spread information from known features to unknown ones, but adjust the spreading strength based on how densely connected the cluster is.

Collect predictions

After spreading, gather the predicted feature values for all originally-missing nodes.

Apply class labels

For nodes whose true class is known, check if predicted features match that class; if not, adjust the predictions.

Measure neighborhood uncertainty

If neighbors disagree on class (some labeled class A, some class B), reduce trust in the prediction because neighbors are contradictory; if neighbors mostly agree, increase trust because the neighborhood is consistent.

What the paper changes

What changes: subgraph scope and propagation strength

The paper replaces a single global averaging step (look at all nodes in the graph) with a two-stage local approach. First, it shrinks the region being diffused into to a small neighboring subgraph. Second, it tunes how much influence neighbors exert based on local graph density (a knob called fractional diffusion), so dense regions propagate quickly and sparse regions propagate slowly.

the object it moves  =  scope and influence strength of diffusion
The hidden quantity

The hidden quantity: propagation sharpness

measured quantity  =  Propagation sharpness knob

Not all graph regions should propagate information at the same rate. In a dense cluster of closely-connected nodes, feature information spreads easily and reliably. In a loose cluster with few connections, spreading information is risky because one wrong guess contaminates quickly. The paper measures or estimates a fractional diffusion exponent—a number between 0 and 1 that controls how aggressively neighbors influence a missing feature.

A sharpness near 1 means neighbors have strong influence (standard averaging). A sharpness near 0 means neighbors have weak influence, so the method trusts the current node's context more and neighbors less. The paper adjusts this tuning per region based on local graph structure, so dense neighborhoods get sharpness near 1, and sparse or risky neighborhoods get sharpness lower.

Why it works

Why it works: localize, tune, refine

The method works in two linked mechanisms. First, by restricting diffusion to a small subgraph, errors cannot cascade through the whole graph—a bad guess stays local. Second, by tuning the diffusion strength to match local density, the method avoids both overspreading (trusting too much in sparse regions) and underspreading (ignoring reliable signals in dense regions). Third, by incorporating class labels and neighborhood consistency in a refinement step, the method catches obvious contradictions and corrects them. When a node's predicted features do not match its known class, or its neighborhood is contradictory (some neighbors class A, some class B), the method softly adjusts predictions to match class or reduce the influence of noisy neighbors.

Why does this fix the original problem? Because global averaging has one fixed strength across all regions. Local tuning says: use what works best where. And because refinement adds external knowledge (the class label), not just averaging, the final guesses are grounded in actual supervised signals, not pure propagation.

Math after the picture

The equation and a worked example

First in words:

Fractional diffusion over a subgraph: spread known feature values using a Laplacian matrix raised to power alpha, where alpha is tuned to match local density.

Then the compact form:

f_imputed = L_alpha * f_known + (1 - beta) * f_class_refined, where L_alpha = D^(-1/2) * A^alpha * D^(-1/2)

Every symbol:

L_alphathe fractional diffusion operator (controls how fast neighbors influence each other)
alphafractional exponent between 0 and 1 (tuned per subgraph based on local density)
Ddegree matrix (diagonal, entry i = number of neighbors of node i)
Aadjacency matrix (binary, entry ij = 1 if nodes i and j are connected)
f_knownthe vector of known feature values in the subgraph
f_imputedthe predicted feature values after diffusion
f_class_refinedpredictions adjusted to match class labels and neighborhood agreement
betaconfidence weight for class refinement (higher for consistent neighborhoods)
A tiny worked example
Suppose a subgraph has 4 nodes arranged in a line: node 1 - node 2 - node 3 - node 4.
Node 1 has feature value 10, node 4 has value 30. Nodes 2 and 3 are missing.
In a dense region (alpha = 0.8), the diffusion spreads quickly: node 2 gets predicted value around 18, node 3 gets 22.
In a sparse region (alpha = 0.3), spreading is slow: node 2 gets predicted value around 14, node 3 gets 26, staying closer to their single known neighbors.
If node 2's true class is known to be red, and predicted features point to class blue, refinement nudges the prediction closer to red features (e.g., reduce by 2-3 units).

The fractional exponent alpha is the knob that tunes sharpness; higher alpha means neighbors have more influence, lower alpha means the method relies more on current context.

What can go wrong

What can go wrong

Class labels are missing too. If class information is also sparse, the refinement stage cannot anchor predictions. The method still works (stage 1 handles feature imputation), but stage 2 loses its supervisory signal.
The graph is disconnected or has isolated clusters. In isolated regions with few or no connections, local subgraph diffusion has little information to spread. The method reverts to near-random guesses.
Choosing alpha (the sharpness knob) varies by data. The paper must estimate alpha from local graph structure. If the estimation is wrong (e.g., mistaking a sparse region for dense), propagation strength is miscalibrated and predictions suffer.
Done right: pair with cross-validation. Validate alpha choice and class-refinement confidence on a held-out set of nodes with known features. Adjust hyperparameters before final prediction on the full missing set.
What a runnable demo should prove

What a runnable demo should prove

Build a small synthetic graph with 50 to 100 nodes. Create a feature vector for each node (e.g., a 10-dimensional vector representing node properties). Randomly mark 95 or 99 percent of features as missing. Run FSD-CAP's feature imputation, varying the alpha (sharpness) knob from 0.2 to 0.9 and comparing to global diffusion. Measure accuracy by comparing predicted features to the ground truth (the originally-hidden values). Plot accuracy vs. alpha and vs. missing-rate percentage. The demo should show that (a) global diffusion crashes as missing rate climbs because error cascades through the whole graph, (b) FSD-CAP stays stable because subgraph localization prevents cascade, and (c) tuning alpha per subgraph is better than a fixed global alpha because different regions have different safe propagation speeds.

accuracy = (count of predictions within threshold of ground truth) / (total predicted features)

The graph should show FSD-CAP's accuracy staying above 75 percent even at 99 percent missing, while global diffusion drops below 40 percent.
