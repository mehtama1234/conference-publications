MAVEN: Mesh-Aware Volumetric Encoding for 3D Deformation

To simulate 3D deformation accurately, explicitly encode the faces and interior cells of a mesh, not just the vertices and edges.

Paper explainersAll themesGraph & Geometric Learning

Simulating how physical objects bend and deform requires a computer model that understands the shape. Most models today use graph neural networks, which read a mesh as a network of points (vertices) connected by lines (edges). But this misses important structure: the flat panels (faces) and solid blocks (cells) inside the mesh. MAVEN adds explicit encoding of these missing layers, capturing both the boundary and the interior.

Zero assumption version

Mesh representation is incomplete

A mesh is a 3D shape made of points (vertices), line segments connecting them (edges), and flat panels filling the surface (faces). If you cut into the mesh, the interior is made of tiny solid blocks (cells). To simulate deformation, the computer must predict how each part of the mesh moves when force is applied.

Most neural networks for this task use a graph neural network, which treats the mesh as a graph: vertices are dots, edges are lines between dots. The network learns patterns by passing messages along the edges. But edges and vertices alone do not capture the full structure. They ignore which faces bound the surface (important for contact — when two objects touch) and which cells fill the interior (important for how stress spreads through the material). A network trained on edges alone must painstakingly learn these patterns by accident, or fails entirely under sparse meshes or large deformations.

The move. Explicitly encode the 2D faces and 3D cells of the mesh, not just vertices and edges. Create learnable connections among all these layers so the network directly sees the full mesh structure.

The algorithm as a flow

What it actually does

Represent the mesh fully

Store vertices (corners), edges (lines), faces (panels), and cells (blocks) as separate feature lists.

Build learnable mappings

Create learnable transformations: vertices to edges, edges to faces, faces to cells, and back down.

Pass geometric information

Let each layer pass information up (faces learn from vertices, cells learn from faces) and down (cells inform faces, faces inform edges).

Encode explicit mesh features

Add hand-crafted measurements (angles, volumes, surface normals) to each layer, so patterns do not need to be rediscovered.

Predict deformation

Final network predicts how each vertex moves, informed by the full mesh structure.

The hidden quantity

The hidden quantity: geometric completeness

measured quantity  =  Completeness of mesh encoding

The hidden quantity is how much of the mesh's true 3D structure the network can access. An old network sees only vertices and edges, missing about 60–70% of the structural information. MAVEN makes all layers explicitly available: vertices (corner positions), edges (line-segment connectivity), faces (surface panels and their outward-facing directions), and cells (interior volumes and their shapes). This is completeness.

The paper measures completeness implicitly by comparing what mesh features must be learned implicitly (old model) versus what can be learned from explicit input (MAVEN). Higher completeness means the network can rely on direct mesh structure rather than learning it by accident.

Why it works

Why explicit mesh structure works

Contact and internal stress propagation depend on mesh structure. When one object touches another, the network must know which part of the surface (faces) is in contact. When force is applied to a deforming object, stress spreads through the interior along paths defined by the solid cells. A network given only vertices and edges must reverse-engineer these patterns from edge messages alone, which is nearly impossible under sparse discretization or large deformations.

By explicitly encoding faces (the boundary) and cells (the interior), MAVEN makes mesh structure a direct input rather than something to learn implicitly. Learnable mappings transform information up (vertices to edges to faces to cells) and down (cells inform what happens at the faces and vertices). Hand-crafted measurements (face normals, cell volumes) are added explicitly, so the network inherits decades of understanding about how deformation works. This reduces the burden on the neural network to a reasonable learning problem: learning which measurements matter and how to weight them.

The encoding equation

First in words:

For each layer (vertices, edges, faces, cells), compute a learned transformation of the geometric features, then aggregate messages from adjacent layers. The final displacement of vertex i is a weighted sum over its incident edges, faces, and cells.

Then the compact form:

displacement_i = w_v * f_v(v_i) + sum_e w_e * f_e(e_j) + sum_f w_f * f_f(f_k) + sum_c w_c * f_c(c_l)

Every symbol:

v_ifeatures (position, velocity) of vertex i
e_jfeatures (length, angle) of edges incident to i
f_kfeatures (normal, area) of faces incident to i
c_lfeatures (volume, density) of cells incident to i
f_v, f_e, f_f, f_clearned neural functions for each layer

A tiny worked example
Vertex at a corner: position (2, 1, 3), moving under gravity.
Incident edges: 3 edges with lengths 1.0, 1.2, 0.9 -> f_e contributes 0.8.
Incident faces: 2 boundary faces with normals pointing outward -> f_f contributes 0.6.
Incident cells: 1 interior cell with volume 0.5 -> f_c contributes 0.4.
Weights: w_v=0.5, w_e=0.2, w_f=0.15, w_c=0.15.
Displacement = 0.5*(-0.1) + 0.2*0.8 + 0.15*0.6 + 0.15*0.4 = -0.05 + 0.16 + 0.09 + 0.06 = 0.26 units downward.

Each mesh layer contributes a learned view of the structure. Explicit features (face normals, cell volumes) replace implicit pattern discovery.

What can go wrong

What can go wrong

Mesh must be clean. MAVEN assumes the mesh is a valid 3D shape with correct faces and cells. If the mesh has holes, flipped faces, or missing cells, the explicit mesh layers confuse the network. Preprocessing (mesh repair, tetrahedral decomposition) is required.
Memory cost grows with mesh complexity. A mesh with thousands of vertices typically has a comparable number of edges, faces, and cells. Storing and updating all four layers is more expensive than edges alone. On very large meshes (millions of elements), memory limits may apply.
Learned transformations must be good. If the learned mappings (vertices to edges, faces to cells) are poorly trained, explicit mesh structure does not help, because the network cannot connect the layers properly. The model requires enough training data so the cross-layer connections learn to pass accurate information.
Done right. MAVEN is most beneficial when the mesh is moderately sized, clean, and deformation or contact is the main difficulty. On datasets with such properties (metal stretch-bending, cloth contact, soft-body simulation), MAVEN outperforms edge-only models by large margins, because edges alone cannot capture contact at the faces or stress paths through the cells.
What a runnable demo should prove

What a runnable demo should prove

A working demo loads a 3D mesh (e.g. a rubber beam or a cloth), applies a simulated force, and predicts how the shape deforms over time. The demo must show two versions: (1) an old network that sees only edges, and (2) MAVEN with explicit faces and cells. Measure how accurately each predicts the final deformed shape compared to a ground-truth simulation (e.g. from a physics engine). Track two metrics: (a) how far vertices end up from their true position (vertex error), and (b) whether contact is detected correctly.

Error = mean absolute distance between predicted and true vertex positions. Contact accuracy = fraction of actual contacts correctly detected by the network.

A sparse mesh or large deformation should clearly show MAVEN predicting accurately while the edge-only model fails. The point is unavoidable: mesh structure matters, and encoding it explicitly beats learning it implicitly.
