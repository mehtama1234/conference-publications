Understanding Forgetting and Generalization in Continual Learning via the Neural Tangent Kernel

Continual learning forgets old tasks when learning new ones, but if you project new gradients away from old-task paths and penalize gradient size, you can learn both at once.

Paper explainersAll themesEfficiency & Systems

When a model learns task after task in sequence, it gets better at new tasks but forgets the old ones, like a student who stops remembering their first language after learning a second one. This paper explains why that happens by watching how the model's numbers change during training, then proposes two algorithms that fight forgetting by steering gradients (the nudges that change the numbers) away from the old-task paths.

Zero assumption version

Why Models Forget Old Tasks

Continual learning is the problem of teaching a model new tasks one after another while keeping it good at the old ones. A naive approach is to just train on each new task like normal — but this wipes out what the model learned before, because training nudges the numbers in whatever direction shrinks the new-task error, often in directions that break the old tasks.

Old theory tried to explain this by assuming the model had fully converged to its final answer on each task, which is fake — models are still changing their numbers and still learning even halfway through training. Real explanations need to track what happens during the middle of training, not just at the end. Also, to bound how much a model forgets, you need numbers for both how good the model is on the old task before and after learning the new one — but old work only gave one of those numbers.

In one sentence. Models forget old tasks during continual learning because the nudges that train on new tasks move the numbers in directions that break old-task performance, and theory has not explained this during actual training.

The algorithm as a flow

What it actually does

Measure task paths

Record the directions the gradients point when training on each old task.

Rotate new gradients

When learning the new task, remove the parts of new gradients that point along old-task directions.

Penalize motion

Add a penalty that grows with the size of each step the new-task training wants to take.

Train gently

Use this smaller, rotated gradient to train on the new task without erasing old knowledge.

Preserve both

Model stays accurate on old tasks because their paths were never disturbed; new task learns well because the motion was not completely blocked, just steered.

What the paper changes

The Thing That Changes: Gradients

The paper changes how the model computes the nudges (gradients, the numbers that say which way to move each weight during training) for the new task. Instead of using all of the gradient, it strips away the parts that would disturb old-task performance.

the object it moves  =  gradients (training nudges)
The hidden quantity

Task Similarity and Gradient Interference

measured quantity  =  Overlap between task gradients

The paper measures how much the gradients for different tasks point in the same directions. If task A and task B have gradients that point in completely opposite directions, training on B nudges the numbers in a way that actually helps A, because the directions push toward task A's solution instead of away from it. If they point the same way, training on B pushes numbers away from what A needs, because both tasks want the same motion and you cannot move in two opposite directions at once.

The paper estimates this overlap using kernel gradient flow, which is a way of watching how the numbers change during training in a simplified model where the numbers move in straight lines. The more overlap between old and new gradients, the more the training procedure has to work to avoid forgetting.

Plain reading. The overlap is like two people pulling on opposite ends of a rope. If they pull in the same direction, one person has to let go or nothing moves, because pulling both ways at once is impossible. In continual learning, both tasks need to pull the numbers in their best directions. Orthogonal projection solves this by stripping away the parts of the new-task gradient that point along old-task directions, leaving only the parts that move the numbers in new directions, so both tasks pull without undoing each other.
Paper reading. The paper uses the cross-task kernel (the dot product of gradients from different tasks) to quantify this overlap, bounding population risk via Rademacher complexity, which measures how much the model can vary on unseen data.
Why it works

Why Steering Gradients Stops Forgetting

When you train on task B, the gradients tell you which way to nudge each number. If you point a gradient toward task A, you move the numbers away from task A's solution — that is forgetting. The paper's insight is to remove that part of the gradient before using it.

Here is the concrete chain: (1) Compute the gradient for task B. (2) Find all the directions the old-task gradients point (this is the subspace spanned by old gradients). (3) Subtract out any part of the B gradient that points along those directions. (4) Use what remains — this new, cleaned gradient — to train on task B. The result is that every step in training task B moves the numbers in a direction that does NOT erase A.

The penalty on gradient size is an extra brake: even after cleaning, you also penalize the training procedure for taking large steps. Large steps are more likely to accidentally bump into some other problem, so smaller steps are safer. The two forces together — orthogonal projection (steering) plus gradient-norm penalization (braking) — reduce both forgetting and improve generalization to new data, because small, careful steps are less likely to overfit.

Math after the picture

The Training Update Rule

First in words:

New weight = Old weight minus learning rate times (cleaned and penalized gradient)

Then the compact form:

theta_{t+1} = theta_t - eta * (Proj_orthogonal(grad_B) + lambda * grad_B)

Every symbol:

theta_tthe model's numbers after t training steps
theta_{t+1}the numbers after one more step
etathe learning rate (how big each step is; typically 0.01 or 0.001)
grad_Bthe gradient pointing toward reducing the error on task B
Proj_orthogonal(grad_B)the part of grad_B that does not point along old-task directions
lambdahow strong the penalty on gradient size is
* grad_B (the penalty term)multiplies gradient size by lambda; larger lambda = smaller steps
A tiny worked example with two weights and one old task
Task A settled the weights to [3.2, 5.1]. Task B's gradient says to nudge to [3.2 + 0.4, 5.1 - 0.5] = [3.6, 4.6].
Task A's gradient direction (stored) pointed mostly toward increasing weight 1. The overlap with task B's gradient is 70% along that direction.
Orthogonal projection removes 70% of the B gradient's weight-1 component: 0.4 * 0.7 = 0.28 removed, leaving 0.12 nudge for weight 1.
Gradient size penalty (lambda=0.5): both components shrink by factor 0.5. Weight 1 nudge becomes 0.12 * 0.5 = 0.06. Weight 2 nudge becomes 0.5 * 0.5 = 0.25.
New weights after update: [3.2 + 0.06, 5.1 - 0.25] = [3.26, 4.85]. Compared to task B's desired [3.6, 4.6], this is a tiny step that mostly preserves task A.

The projection removes gradient directions that would erase old tasks; the penalty adds friction so every step is cautious.

What can go wrong

What can go wrong

Too many old tasks make steering expensive. If you have learned 50 old tasks and now want to learn task 51, storing and projecting away from all 50 old-task gradient directions becomes computationally heavy. The method scales poorly when the sequence is very long.
Gradient penalty brakes learning on the new task. If lambda (the penalty strength) is too large, the penalty shrinks the new-task gradient so much that task B barely learns anything. You have to tune lambda carefully, and there is no universal right value.
Old-task directions may not be stable. The paper stores old-task gradient directions, but gradients change throughout training. If you store them at the wrong point in training, or if the data for old tasks changes, the stored directions become outdated and projection becomes less useful.
Done right: use enough training steps on each task to stabilize the gradients, store them when training has settled, and tune lambda by watching validation accuracy on both old and new tasks. The method works when you treat each task seriously (let it converge), save high-quality gradient directions, and balance the penalty strength to protect old tasks without completely freezing new learning.
What a runnable demo should prove

What a runnable demo should prove

Build a small neural network and train it on two image-classification tasks in sequence. First, task A: distinguish cats from dogs. Let it train fully. Then, task B: distinguish cars from trucks. (1) Train task B with standard gradient descent and measure how much task A accuracy drops — this shows the forgetting problem. (2) Train task B using OGD+ (the gradient projection version) and measure task A accuracy again — it should stay much higher. (3) Train task B using OPGD (adding the gradient-size penalty) and measure both old and new accuracy — both should be better than the baseline but a little worse than OGD+ alone (because the penalty introduces a trade-off).

Forgetting = accuracy_A_before_B - accuracy_A_after_B; lower forgetting is better. Forward transfer = (accuracy_B_with_method - accuracy_B_baseline); higher is better.

The demo must make it impossible to miss: applying orthogonal projection to gradients stops forgetting, and adding a size penalty makes the improvement more stable.
