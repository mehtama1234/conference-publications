TimeOmni-VL: Unified Models for Time Series Understanding and Generation

A single model can understand what's happening in time series data AND accurately generate future values by converting both to images, then solving both tasks together.

Paper explainersAll themesTime Series & Sequential

When you study a time series like stock prices or temperature, two kinds of work clash: one model learns to describe what's happening (prices rising means an opportunity), and another tries to predict the next number exactly right. TimeOmni-VL merges these by turning time series into pictures, so a single model solves both jobs at once.

Zero assumption version

Time series are split between two dead ends

Today's models split into two types. One kind learns to read time series numbers and answer questions: 'Is the trend up or down? Is this normal or an anomaly?' That model is okay at the concepts but terrible at writing out the actual next numbers—it guesses 5.2 when it should be 5.17. The other kind is the opposite: it obsesses over predicting the exact next number with high precision, but it ignores whether that number makes sense in context.

A beginner would try one model for understanding and swap to another for generation. But then you train twice, and they contradict each other: the understanding model learned to ignore small wiggles because they don't matter conceptually, while the generation model learned to lock onto those exact wiggles.

The trap. Models built for understanding ignore numerical precision; models built for precision ignore the big picture.

The algorithm as a flow

What it actually does

Convert time series to image

Turn the numbers into pixel heights and shades; this works because vision models are built to spot shapes and trends in pictures, and height/color is how images naturally encode magnitude and rate of change.

Train on understanding tasks first

Teach the model to read the image and name patterns: 'Is this trending up? Is this an anomaly?'

Train on generation tasks next

Teach it to predict the next numbers in the image, guided by what it learned about the pattern.

Use understanding as a control signal

When generating, force the model to first state what it thinks is happening, then commit to numbers that match that story.

Output both at once

One forward pass gives you a semantic label and a high-precision forecast.

What the paper changes

What the paper changes

TimeOmni-VL changes how a model sees time series data: instead of treating numbers as opaque lists, it converts them into images. An image has spatial structure (left-to-right is time; height is magnitude), so visual reasoning models built for photos can transfer their understanding to time series.

The hidden quantity

The hidden quantity: Semantic alignment

measured quantity  =  Semantic alignment score

The paper measures how much a generated forecast matches the semantic story the model learned. If the model says 'this is a rising trend,' but generates numbers that fall, the alignment is low. Alignment is the degree to which understanding and generation agree on the big picture.

The paper estimates alignment by having the model first state what it understands (using a chain-of-thought, which is an explicit step-by-step reasoning trace), then checking whether the generated numbers are consistent with that reasoning. High alignment means the model's story and its numbers tell the same tale.

Why it works

Why one model beats two

Converting time series to images taps into years of multimodal training. Models trained on vision datasets already understand structure: high pixels mean big values, color transitions mean trends, clusters mean patterns. When you show a time series as an image, the model recognizes these structures without starting from scratch.

Teaching understanding first anchors the model's reasoning. When you force the model to first state 'I see a rising trend' or 'This is a seasonal cycle,' you create a semantic contract it must honor later. If it then predicts falling numbers, the contract is broken, and the training loss says so. This constraint—forcing coherence between explanation and prediction—prevents the two tasks from drifting apart.

The model never has to choose between understanding and precision. Understanding tasks (Is this an anomaly?) teach high-level pattern recognition. Generation tasks (What is the next number?) teach fine detail. Because both run in the same forward pass and share representations, the model learns to do both at once: high-level patterns guide the fine-grained prediction toward realism.

Balancing understanding and generation

First in words:

The total loss is a weighted sum of understanding loss and generation loss, plus a penalty for semantic misalignment. The penalty term is high when the model's stated understanding contradicts its numerical forecast.

Then the compact form:

L_total = L_understand + lambda_gen * L_generate + lambda_align * mismatch(reasoning, forecast)

Every symbol:

L_understandloss when the model predicts semantic labels; measures how often it correctly identifies trends, anomalies
L_generateloss when the model predicts the next number; measures how far off its forecast is from the true value
lambda_genweight controlling how much generation matters relative to understanding
lambda_alignweight controlling how much we penalize contradiction between reasoning and numbers
mismatch(reasoning, forecast)a score that grows large if the semantic label contradicts the numerical output (e.g., reasoning says rising but forecast says falling)
A tiny worked example
Suppose the true next value is 5.2, the model understands correctly (label is right), and forecasts 5.1.
L_understand = 0 (correct label); L_generate = (5.1 - 5.2)^2 = 0.01; mismatch = 0 (they agree).
Total loss = 0 + 0.8 * 0.01 + 2.0 * 0 = 0.008.
Now suppose the model understands correctly but forecasts 4.5, contradicting its stated trend.
L_understand = 0; L_generate = (4.5 - 5.2)^2 = 0.49; mismatch = 1.5 (contradiction detected).
Total loss = 0 + 0.8 * 0.49 + 2.0 * 1.5 = 0.39 + 3.0 = 3.39, much higher.
The model learns to avoid contradiction because it raises the loss steeply.

The alignment penalty acts as a referee: it forces understanding and generation to tell the same story.

What can go wrong

What can go wrong

Image conversion loses information if not designed carefully. If pixel shades are coarse, two very different time series could render to identical images, making them indistinguishable at generation time. The solution: design the color scale so that each distinct pixel shade maps to a small, unique range of numbers. This way, when the model sees a particular shade, it can accurately invert it back to the right number range.
Reasoning overconstrains generation. If the model's semantic reasoning is wrong, the generation penalty drags the forecast further from correct numbers rather than closer. A false understanding becomes a false anchor.
Scaling breaks for very long series. Long time series convert to very wide images. Vision models are built for photos, not ultra-wide inputs. Some patterns might disappear at the resolution limit.
Done right. The paper's bidirectional mapping (TS-to-image and image-to-TS) is carefully calibrated to preserve numerical fidelity: pixel heights directly encode magnitude, color encodes derivative (how fast it's changing), and the conversion is invertible so nothing is lost. Semantic reasoning is trained first on ground-truth labels, so it learns true patterns before it constrains generation.
What a runnable demo should prove

What a runnable demo should prove

Build a simple dataset: stock prices over 100 days. Hand-label five understanding tasks for each series: Is this trending up, down, or flat? Is there an anomaly in the last 10 days? Does it have a seasonal cycle? Then split the series: train on days 1–80, predict days 81–90, and evaluate days 91–100.

Train a TimeOmni-VL model: convert series to images, run understanding tasks, generate the missing days, measure both accuracy on the labels and numerical distance to ground truth.

Compare: a model trained only on generation (ignoring understanding) will forecast lower precision and contradict any labels you ask for. TimeOmni-VL should beat it on precision and maintain semantic consistency.

coherence = min(understanding_accuracy, generation_precision) / max(understanding_accuracy, generation_precision); higher means the two tasks support each other

The demo must show that semantic guidance raises precision: understanding steers generation toward realistic numbers that make sense in context.
