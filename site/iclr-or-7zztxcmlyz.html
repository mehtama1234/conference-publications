Defending LLMs from Jailbreaks via Embedding-Space Training

Train LLMs to refuse jailbreak attacks by rehearsing adversarial examples in the embedding space, then regularize the embedding matrix so the training sticks.

Paper explainersAll themesAlignment, Safety & Fairness

Jailbreak attacks trick LLMs into harmful outputs by injecting adversarial text. Standard adversarial training (rehearsing bad prompts so the model learns to refuse them) works but is expensive, so recent work uses continuous adversarial training (CAT): searching for adversarial attacks by nudging the model's internal embedding numbers, not the tokens themselves. This paper explains why CAT works—and then improves it by steering the embedding table's internal structure.

Zero assumption version

Adversarial training is slow and fragile

Jailbreaks are prompts designed to trick an LLM into generating harmful output—asking it to 'pretend' it has no safety rules, or embedding instructions in innocent-looking text. To defend, researchers use adversarial training: the model rehearses bad prompts and learns to refuse them, much like a security guard practicing responses to social engineering. It works, but it is expensive: searching for good jailbreak examples requires many forward passes.

A beginner would try: train the model with hand-written bad prompts. The problem: jailbreaks are creative and varied; you miss most of them. An engineer then tries: generate adversarial prompts automatically by modifying the input tokens. This is slow because changing tokens means recomputing embeddings from scratch each time.

In one sentence. Adversarial training is expensive because searching for attacks by changing tokens requires constant recomputation of embeddings from the ground up.

The algorithm as a flow

What it actually does

Step 1: Start with a pre-trained LLM

The model has already learned language; we add a safety layer via training.

Step 2: Generate adversarial embeddings

Instead of searching for bad text, nudge the internal numbers directly to find harmful inputs the model will answer.

Step 3: Train the model to refuse

The LLM learns to recognize and refuse the adversarial embeddings, withstanding more attacks.

Step 4: Steer embedding table structure

Keep the embedding table's singular values (internal stretch factors) balanced so the defense does not collapse during fine-tuning.

Step 5: Test on real jailbreaks

The balanced model defends better against token-space jailbreaks than standard adversarial training alone, because an even embedding space is harder to exploit.

What the paper changes

What the paper changes

The paper's core move: add a single penalty term (gently pushing against something) to the adversarial training loss. This term measures how scattered the singular values of the embedding table are, and penalizes scatter. The effect is to keep the embedding table's internal structure stable during training. Singular values are the 'stretching factors' of the embedding table—how much it scales input tokens along different internal directions.

the object it moves  =  The embedding table's singular values
The hidden quantity

The singular values of the embedding table

measured quantity  =  Embedding table singular values

Singular values are a simple structural property of any table of numbers: they measure how much the table stretches or compresses data. Imagine the embedding table as a lens focusing or blurring token meanings; singular values tell you the lens's magnification along each internal direction. High singular values mean strong magnification in that direction; low values mean compression.

The paper shows that when an LLM is adversarially trained, these singular values change—some grow very large, others shrink. If they scatter too much, the embedding space becomes uneven: some directions are magnified, others collapsed. This unevenness is where jailbreaks hide. By gently steering the singular values (keeping them close together), the embedding space stays balanced and harder to trick.

Why it works

Why embedding-space training with singular value steering works

Standard adversarial training works because it teaches the model to recognize and refuse jailbreaks. But it is slow: searching for adversarial attacks in the token space requires rebuilding embeddings constantly. Continuous adversarial training (CAT) speeds this up by searching directly in embedding space—nudging the internal numbers instead of changing tokens. This is much faster because the embeddings are already computed, so you can try many attacks in parallel.

The deeper insight: when you train with embeddings under attack, the embedding table itself changes. Some singular values (the stretch factors) grow to amplify the adversarial signal, others shrink. This creates an unbalanced embedding space where jailbreaks can more easily slip through. The paper's solution: add a penalty term that measures how much the singular values scatter. By keeping them close together, the embedding space stays balanced, and the defense holds even when the model is fine-tuned on new tasks afterward.

Math after the picture

The regularization equation

First in words:

Standard adversarial training loss, plus a penalty term that equals the variance of all singular values of the embedding table.

Then the compact form:

Loss = Adversarial_Loss + Utility_Loss + lambda * Variance(singular_values)

Every symbol:

Adversarial_LossHow poorly the model refuses adversarial jailbreaks
Utility_LossHow well the model keeps its original skills (not breaking normal use)
lambdaStrength of the penalty (how much we care about balanced singular values)
Variance(singular_values)Spread of the singular values—high if some are huge and others tiny, low if all similar
singular_valuesThe stretch factors of the embedding table along each internal direction
A tiny worked example
Suppose the embedding matrix has 5 singular values: [8.0, 2.0, 7.0, 1.0, 6.0].
Mean = (8 + 2 + 7 + 1 + 6) / 5 = 24 / 5 = 4.8.
Deviations from mean: [3.2, -2.8, 2.2, -3.8, 1.2].
Squared deviations: [10.24, 7.84, 4.84, 14.44, 1.44].
Variance = (10.24 + 7.84 + 4.84 + 14.44 + 1.44) / 5 = 38.8 / 5 = 7.76.
With regularization lambda=0.1, the penalty is 0.1 * 7.76 = 0.776.
Training shrinks this penalty by evening out the singular values—spreading the large ones, growing the small ones until all are closer to 4.8.

The variance of singular values measures how imbalanced the embedding space is. Smaller variance means a more uniform, harder-to-exploit embedding space.

What can go wrong

What can go wrong

Singular values all become identical. If you push too hard, all singular values converge to one value, and the embedding table loses information. The model stops learning useful distinctions.
Adversarial loss is ignored. If the penalty coefficient lambda is too high, the model optimizes for balanced singular values instead of refusing jailbreaks. The tradeoff tips the wrong way.
Fine-tuning on new tasks breaks the defense. If the model is fine-tuned on a new task after adversarial training, the singular values can scatter again unless the penalty is kept active during fine-tuning.
Done right. Tune lambda so the penalty pushes singular values toward uniformity without collapsing them to one value. Keep the penalty active during any downstream fine-tuning. The resulting embedding table stays balanced and defends well.
What a runnable demo should prove

What a runnable demo should prove

Build a small language model (or use a simple test neural network with linear layers) and train it on a safety dataset with jailbreak examples. Implement both standard continuous adversarial training (CAT) and embedding-regularized CAT (ER-CAT). Measure two things: (1) how many jailbreaks each model refuses, and (2) the variance of the embedding table's singular values at the end of training. Compare the two approaches on both metrics.

Jailbreak_Refusal_Rate = (num_refused_jailbreaks) / (total_jailbreaks); Refusal_Bonus = ER_CAT_Refusal - CAT_Refusal; SV_Variance = Variance(singular_values_at_end)

The demo should make impossible to miss: penalizing singular value scatter reduces their variance, and this variance-reduction correlates directly with stronger jailbreak refusal because uniform singular values block more attack paths. CAT alone leaves high variance and weaker defense; ER-CAT balances the singular values and nearly doubles refusal.
