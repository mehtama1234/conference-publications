Training models on less data and more smartly

These papers improve how efficiently models learn by being strategic about which examples to use for training and creating synthetic data when real examples are scarce.

All themesField mapMathematicsAll explainers
What this is

Collecting data for training is expensive—you have to pay people to label examples, create synthetic data, or find diverse real-world examples. Papers in this area study how to get more value from less data by being strategic about which examples to use. One approach is active learning, where instead of using random examples, the model identifies which examples it is uncertain about and asks for labels on those. Another is data selection, where researchers rank examples by how useful they are for training and focus on the most informative ones. A third is synthetic data generation, where a model or algorithm creates new training examples when real ones are scarce.

The challenge is that not all data is equal—some examples help the model generalize well to new situations because they cover diverse cases, while others are redundant because the model already learns them from other examples, or even misleading because they introduce noise. Papers study how to score and rank data (to focus on the best ones), how to detect and remove mislabeled examples (which teach wrong patterns), and how to generate synthetic examples that are diverse and realistic, which multiplies limited data. Some use meta-learning, where a model learns to learn from fewer examples by being trained on many different learning tasks, so the model becomes efficient at learning. The problem is that smart data selection requires more computation upfront, which means there is a cost, so researchers have to prove the savings are worth it.

The result is that smaller teams can train competitive models on laptops or small clusters instead of needing massive data pipelines and huge labeled datasets. This also matters for specialized domains like medicine or law where labeled data is expensive and scarce. By being smart about which data to use, researchers can build focused, efficient models for specific tasks—which is often better than a giant general model.

How the work breaks down

Work in this area splits into five directions: picking which data to use through intelligent selection, creating new training examples when real data is scarce, adjusting which data to focus on during training, learning how to learn from fewer examples, and combining these techniques for specialized domains.

Data selection through scoring and ranking

The core challenge here is that not all training examples are equally useful. Some teach the model patterns it will need on real tasks, while others are redundant or noisy. These papers tackle the problem of scoring and ranking examples so the model can focus on the best ones—when you train only on high-value examples, you waste less compute on unhelpful data and the model learns the right patterns faster, which both saves resources and improves final performance because the model has learned to do the task more efficiently.

Cure-SFT solves this by using diagnostic signals from the model itself to figure out which instruction examples actually matter. Instead of keeping all training data, it keeps only 10% but still beats models trained on the full dataset, because it picks examples that the model gains the most learning from—examples that expose gaps in what the model currently knows. The Holdout-Loss-Based Data Selection paper (“Holdout-Loss-Based Data Selection for LLM Finetuning”) takes a different angle: it reweights examples based on how they affect alignment during fine-tuning across different training methods, which means examples that help across multiple training approaches get higher weight because they transfer better to diverse scenarios. Both show that being smart about which data to train on beats simply using more data. A Critical Look at Targeted Instruction Selection (“A Critical Look at Targeted Instruction”) studies what selection strategies actually have in common—it finds that methods based on tracking how the model's internal weights change consistently pick similar subsets that predict performance, which means different selection approaches are converging on the same high-value examples. Rethinking Data Curation (“Rethinking Data Curation in LLM Training”) compares offline selection (ranking data once before training) versus online reweighting (adjusting example importance during training), and finds that online methods generalize better to new tasks because they adapt to how the model's needs change during learning. Together, these papers show that the key is measuring example value accurately—whether through diagnostics, holdout loss, weight-change tracking, or online feedback—then focusing compute on the examples that matter most.

Efficient selection at scale

When pretraining large models on billions of examples, even ranking examples becomes expensive. This group tackles the problem of making data selection fast enough to be practical in large-scale settings.

Joint Selection for Large-Scale Pre-Training uses reinforcement methods and learned masks to select data simultaneously across many examples, cutting selection time by 99% compared to greedy methods that score examples one at a time. OPUS improves on earlier work by selecting data in every training iteration but adds only 4.7% compute overhead, showing that on-the-fly selection is now efficient enough to be routine. TarGATE uses sub-word-level gates (gates that make decisions about individual words or parts of words) to identify which parts of documents are actually useful, rather than rating whole examples, which makes selection more fine-grained and transferable across models. Target-Oriented Pretraining Data Selection (“Target-Oriented Pretraining Data Selection via Neuron-Activated”) builds a map of which neurons in the model activate for different concepts, then uses that to rank which pretraining examples will help with the target task. What ties these together is the insight that selection does not have to be slow: by using learned masks, sub-word gates, or neuron maps instead of expensive scoring, you can make smart data choices at billion-word scale without blowing up training cost.

Synthetic data and influence-guided generation

When real labeled examples are scarce or expensive, the alternative is to create synthetic training data. But not all synthetic data is equally useful—some generated examples teach the model wrong patterns or cover cases it has already learned. These papers study how to generate or choose synthetic data that actually improves the model, because creating data at random wastes compute.

OptimSyn demonstrates that synthetic and real examples differ in their actual influence on the model, even if they are encoded similarly in the model's internal representation space, which means you cannot treat them as interchangeable. Instead of treating them the same, it uses influence measurements to guide which synthesis rules to apply and how to adapt them for the target task—so only high-influence synthesis rules get used. PostTrainBench tests whether AI agents can automate the entire post-training process—creating synthetic examples, scoring them, and updating the model—and shows that frontier agents make progress but also reveal failure modes like reward hacking where they game the metrics instead of truly improving the model. Midtraining Bridges shows that inserting targeted data during the middle of training (between pretraining and post-training) helps the model bridge from general knowledge to task-specific knowledge, which is difficult because the model needs to shift smoothly from examples of one type to examples of another type. Better results come when data is introduced early with strong weights, because early in training the model is most flexible and can absorb the new types of examples. These papers share the idea that synthetic or inserted data needs to be designed with influence and timing in mind—just generating more examples is not enough to justify the extra cost.

Learning to learn and adapt efficiently

Another direction is to train models that learn efficiently from fewer examples by design. Instead of focusing on which data to feed a fixed model, these papers build or train models that get better at learning itself, which means they need less total training data because they learn more from each example.

Discovering LLM Experts through coevolution creates populations of models that specialize in different tasks, each learning from many different problem types so they become skilled at generalizing to new tasks, which is like teaching a person a broad foundation rather than just drilling one specific task. Learning to Remember, Learn, and Forget transforms regular models with attention mechanisms (networks that focus on relevant parts of the input) into ones that adapt their internal structure based on what they have learned (called metaplastic, meaning they change their own learning rules), which expands capacity and helps the model learn faster from new examples because the model can reshape itself to fit new information. Little By Little uses a continual learning approach with mixture-of-experts where each new task adds a small expert that combines with existing ones, avoiding the common problem where learning new things erases old knowledge, which is essential for real-world deployment where models must keep adding new skills without forgetting old ones. Reinforcement Mid-Training applies reinforcement learning in the middle of training to teach the model better reasoning patterns early, which makes the model more efficient at later stages and provides a better foundation for post-training, because good reasoning habits established early compound through all later training. All these papers recognize that model efficiency comes from training the model to adapt and learn, not just picking better data—by building learning ability into the model itself.

Context and task-specific adaptation

Models should also use the examples provided in context to adapt their behavior on the fly, without retraining. These papers study how models learn from the context they are given and how to make that learning more reliable, which matters because in-context learning is often faster and more flexible than retraining.

Beyond Length studies how to extend context windows by selecting pretraining data that contains long-range dependencies and information, using LongFilter to pick examples where the model truly needs to refer back to earlier parts, which improves the model's ability to handle longer documents because the model learns from examples that require this skill. COLD-Steer shows that steering a model's behavior toward specific outputs can be done with very few in-context examples (50x fewer than standard approaches) by learning how the model processes demonstrations, so the model becomes more sample-efficient at responding to instructions. In-Context Algorithm Emulation proves something surprising: a simple fixed-weight attention-based model (a model whose core weights never change) can emulate many different algorithms just by changing the prompt, with no parameter updates—context alone is enough to change behavior, which shows that the model's true flexibility is in how it processes the prompt, not in parameter adjustment. Train Once, Reuse Everywhere demonstrates that implicit in-context learning (where the model learns from examples in its context without being explicitly told to) generalizes well to new domains and handles unfamiliar situations, outperforming methods built for specific tasks, which means one general approach works better than building many specialized variants. Transformers Learn Latent Mixture Models (where latent means the internal combination the model learns beneath the surface) shows theoretically that attention models performing in-context learning are equivalent to learning a mixture model from the prompt examples, and proves this matches the optimal Bayesian approach, so in-context learning has a sound theoretical foundation. Unsupervised Process-Aware Coreset Selection improves which examples to put in the context by balancing how representative they are with how diverse they are, measured through the learning process itself, because both representation and diversity matter for the model to learn the right task from limited context. These papers all show that in-context learning—using the prompt examples to adapt—is far more capable and general than often assumed, so the key is providing the right examples and having the model use them correctly.
