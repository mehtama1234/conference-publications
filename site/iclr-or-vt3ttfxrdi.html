ImageRAG: Dynamic Image Retrieval for Reference-Guided Image Generation

Show a working generative model a reference image that already has the rare thing you want, and it learns to draw that rare thing in a new image, with no training needed.

Paper explainersAll themesGenerative Models & Diffusion

Generative models can draw almost anything from text, but they fail on rare or unusual concepts—things the training data hardly showed them. ImageRAG solves this by finding a real photo or artwork of that rare concept, showing it to the model as an example, and letting the model use that reference to guide its generation. The trick: use a separate smart reader (a vision-language model) to figure out what's missing, then retrieve the right reference images, all without teaching the generative model anything new.

Zero assumption version

The generative model knows only what it saw during training

A text-to-image model learns to draw by seeing millions of examples during training. When you ask it to draw something common (like a dog or a chair), it works great. But if you ask for something rare (like 'a Shiba Inu wearing a Venetian mask'), the model has probably never seen that exact combination before, so it fumbles.

A beginner's fix would be to re-train the model on new examples of that rare concept, feeding it hundreds of images of Venetian-masked Shiba Inus. But re-training is slow, expensive, and needs a lot of data. And every time you encounter a new rare concept, you would need to re-train again.

The real problem: the model has no way to look up how rare things actually look. Its knowledge is frozen in its weights the moment training stops.

The method in one sentence. Ask a smart reader to spot what's missing from a generated image, retrieve real photos of that missing thing, and show those photos to the generative model as examples so it can draw better.

The algorithm as a flow

What it actually does

Generate a first draft

Run the text-to-image model on your prompt to make an initial image.

Have a smart reader assess it

A vision-language model (like GPT with image input) reads both the prompt and the image, identifies mismatches, and writes out what's missing in step-by-step reasoning.

Extract the missing concepts

The step-by-step reasoning produces text descriptions of what was missing (e.g., 'gold filigree', 'Venetian mask style').

Retrieve matching images

Search an external image database (like a filtered version of an open-source collection) for images matching those descriptions. Rank them by similarity.

Show references and regenerate

Pass both the original prompt and the retrieved images to the model's image-conditioning mechanism. The model now extracts visual patterns from the reference images, reproducing those patterns in the new image.

What the paper changes

What the method changes: the input to the generative model

Normally, the generative model receives only text: your prompt. ImageRAG adds to that: real reference images. The model's image-conditioning mechanism (already built into modern text-to-image models) now receives both the text prompt and visual examples, working the same way it would if you had manually assembled those references yourself.

the object it moves  =  the input images given to the model
The hidden quantity

The hidden quantity: what's actually missing

measured quantity  =  The alignment gap (what the model failed to draw correctly)

The core insight is that rare concepts fail because the model never learned what they look like. The hidden quantity is the difference between what you asked for (in the prompt) and what the model actually produced (the generated image). This gap is invisible in the weights—you can't simply read it out—but a smart reader can spot it by reasoning about both.

ImageRAG measures this gap by having a vision-language model perform step-by-step reasoning: it looks at the image, looks at the prompt, and explicitly writes down what does not match. By naming the missing parts in plain language, the method converts an invisible gap into a set of searchable text descriptions.

Why it works

Why it works: three pieces working together

ImageRAG succeeds because it solves a core problem: the generative model has never seen the rare concept, so it cannot produce it from text alone. But the model does have a built-in ability: it can look at an image and borrow visual details from that image during generation. The method provides exactly what the model needs to borrow.

The mechanism has three stages. First, it finds what is missing by asking a separate smart reader (the vision-language model) to reason step-by-step about the prompt and the failed image. This reader is excellent at reading images, so it does not need to be trained on this specific task—it already knows what Venetian masks look like. Second, it retrieves real photos of the missing things by searching an external image database for text descriptions of those missing parts. Third, it shows those photos to the model through its built-in image-conditioning system. The model then generates again, this time influenced by the visual examples. Because the references are real photos of the rare thing, the model learns from those real details and reproduces them correctly.

Math after the picture

The retrieval scoring formula

First in words:

Similarity = sum of text description similarity to image features, where each retrieved image scores highest when its visual features match the missing-concept descriptions the reader produced.

Then the compact form:

sim(concept_i, image_j) = dot(embed_text(concept_i), embed_image(image_j)) / (norm(embed_text) * norm(embed_image))

Every symbol:

concept_ithe i-th missing concept extracted as text
image_jthe j-th image in the retrieval database
embed_text(concept_i)the numerical vector for that text phrase
embed_image(image_j)the numerical vector for that image
dot(,)multiply matching positions and sum (cosine similarity)
normthe length of the vector, to make the score fair regardless of scale
A tiny worked example
Missing concept 1: 'gold filigree pattern' -> numbers (list) = [0.8, 0.2, 0.9, 0.1, ...]
Reference image 1 (real Venetian mask): numbers (list) = [0.75, 0.25, 0.85, 0.15, ...]
Dot product = 0.8*0.75 + 0.2*0.25 + 0.9*0.85 + 0.1*0.15 + ... = 0.60 + 0.05 + 0.765 + 0.015 + ... = high score
Reference image 2 (random gold jewelry): numbers (list) = [0.2, 0.8, 0.1, 0.9, ...]
Dot product = 0.8*0.2 + 0.2*0.8 + 0.9*0.1 + 0.1*0.9 + ... = 0.16 + 0.16 + 0.09 + 0.09 + ... = lower score
The mask ranks higher. Its visual pattern aligns with the missing-concept description.

The method ranks retrieved images by how closely their visual features match the missing concepts the reader identified. Images with higher similarity scores are better references because their visual patterns align with what the model is trying to learn.

What can go wrong

What can go wrong

The retrieval database does not contain the rare thing. If you want to generate 'a Shiba Inu wearing a 15th-century Venetian mask' and the image database has no Venetian masks, the method cannot help, because it can only retrieve and show examples of things that already exist in the database.
The vision-language model misidentifies what is missing. The method relies on the smart reader (the vision-language model) to correctly spot the gap between the prompt and the generated image. If that reader makes a mistake, the wrong concepts are extracted, and the wrong images are retrieved.
The retrieval similarity metric ranks the wrong images. Even if the right concept is extracted (Venetian mask), the retrieval search might rank images of modern masks higher than authentic historical ones because they are more common in the database. A poor ranking returns the wrong reference.
Done right. The method works best when the retrieval database is large and diverse, the vision-language model is accurate, and the rare concept is present (even if rare) in the data.
What a runnable demo should prove

What a runnable demo should prove

Build a minimal pipeline: (1) a text-to-image model (like SDXL or OmniGen), (2) a vision-language model (like GPT-4 Vision), (3) a retrieval database (even 10k images), and (4) an image-conditioning wrapper. The demo should take a prompt for a rare concept, generate a first image, have the VLM identify what is wrong, retrieve matching reference images, and regenerate. Measure success by whether the final image contains the rare concept correctly, as judged by examining the generated output against the original prompt.

success = (rare_concept_present_in_final_image) AND (concept_details_match_reference)

The demo should make undeniable: without the retrieved reference, the rare thing is wrong or missing; with it, the rare thing appears and looks right.
