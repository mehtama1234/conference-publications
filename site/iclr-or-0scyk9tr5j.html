Trained on Tokens, Calibrated on Concepts

Base language models secretly learn to know how confident they should be in their semantic answers, even though they were trained only to predict one word at a time.

Paper explainersAll themesLLMs & Foundation Models

When you ask a language model a question, it generates one word after another. But how does it know when to feel confident about its answer as a whole? This paper discovers that base language models (those trained just to predict the next word) automatically develop an uncanny ability to judge the confidence in their complete, multi-word answers. The trick lies in a hidden connection: if the model is trained only on predicting words accurately, it will implicitly learn confidence estimates as a side effect—but only if it's trained the right way. Instruction-tuned models often lose this ability.

Zero assumption version

Models predict words but don't know their own certainty

A language model trained to predict the next word, one at a time, will eventually produce full sentences and answers. But here is the puzzle: the model only ever learned to be right about single words. How would it know whether its complete answer is correct?

A naive first try: you could ask the model to output a confidence score for each token it generates. But that requires explicit supervision—labeling training data with correctness judgments for every word the model produces. Base models never see that. Yet experiments show that base models actually do judge their multi-word answers well without being trained to. The question is how.

The algorithm as a flow

What it actually does

Model reaches an intermediate point in generation

After a few tokens, the model has context for the question but not yet the full answer.

It predicts which semantic outcome it will land on

Internally, before generating the rest, it estimates whether the final answer will be right, wrong, partially right, etc.

It implicitly weights future tokens by that prediction

Tokens in high-confidence regions get pushed slightly harder; low-confidence ones less so.

This tweaking happens entirely within next-token loss minimization

No explicit confidence labels needed; the model just noticed this improves the overall accuracy.

When the finished model answers, its sampling shows the confidence

When you sample many answers, which ones appear more often directly reflects the model's uncertainty.

What the paper changes

What the paper changes

The paper does not change what the model is trained on. Instead, it reveals what the model's training process is already computing: its own implicit semantic confidence before it generates the final answer.

the object it moves  =  the implicit confidence in semantic answers
The hidden quantity

The hidden quantity: Local loss optimality

measured quantity  =  whether the model can be nudged to predict better

Imagine you have a trained model. Now imagine tweaking its output distribution after training is done—reweighting which words it likes. If no such tweak could improve the model's accuracy on the test set, we say the model is locally-loss-optimal: it has nowhere obvious left to improve.

The paper proves that when a model is locally-loss-optimal with respect to a certain class of tweaks, it must know its own semantic confidence in advance. That is, if the model cannot easily improve accuracy by reweighting, it can only be because the model already found the best way to weight each possible answer—which requires knowing, before generating, whether that answer is likely correct.

Why it works

Why it works: the connection between loss and confidence

Here is the core insight. During training, the model sees many question-answer pairs. Its only job is to minimize cross-entropy loss on the next token. Suppose the model has generated halfway through an answer. At that point, if the model could predict (from context alone) what semantic category its final answer will fall into—right, wrong, partially right—then there is a small greedy improvement available: it could upweight tokens that lead to semantic correctness and downweight tokens that lead to error. This nudge would lower the training loss.

The model cannot see the future, but it can learn a statistical pattern: given the question and the partial answer so far, which semantic outcomes are likely? This is something it can extract from the training data. If the model is well-trained (locally-loss-optimal), it will have already found all such easy improvements. That means, by design, the model must already know its own semantic confidence, because otherwise it would have left easy accuracy gains on the table.

Instruction-tuning and chain-of-thought break this mechanism. When a model is fine-tuned with reinforcement learning or trained to reason step-by-step, the loss function changes or the way the model generates changes. Now the easy-improvement argument no longer holds, so the model does not predict semantic confidence before generating.

The equation: loss optimality implies calibration

First in words:

the sum over all reweighting functions: if no function can reduce loss, the model must already know semantic confidence

Then the compact form:

For all functions w in class W: loss_original <= loss_reweighted_by_w. This holds if and only if the model can predict its B-class distribution before generating the answer.

Every symbol:

loss_originalaccuracy loss the model currently achieves
loss_reweighted_by_wloss after you reweight which tokens are likely
wany simple reweighting function within a reasonable set
B-classa semantic equivalence group: right, wrong, or other
B-calibrationthe model's sampling distribution matches its actual correctness on that semantic category
A tiny worked example
Suppose a model answers a trivia question. Before generating, it predicts an 80 percent chance the answer will be correct.
To minimize loss, the model implicitly upweights token sequences that lead to right answers and downweights wrong sequences.
When you sample 50 answers from the model at temperature 1, about 40 out of 50 are actually correct.
That sampling distribution (80 percent high-confidence, and 40 out of 50 are right) matches the model's prediction: B-calibration holds.

If training cannot improve loss by reweighting, the model must have already found the best way to weight each semantic answer—which requires knowing, before generating, which answers are likely correct.

What can go wrong

What can go wrong

Out-of-distribution questions. If you ask about a topic the model rarely saw during training, the local-optimality argument breaks: the model may not have learned to be confident about such cases.
Non-cross-entropy training. If training uses reinforcement learning (RLHF, DPO) or other losses, the calibration mechanism disappears. The model has no reason to know semantic confidence.
Chain-of-thought reasoning. If the model must reason out loud before answering, it cannot predict the final semantic class early. Confidence breaks.
Done right: pure pre-training on large in-domain corpora. Base models trained only on cross-entropy loss, on data they saw plenty of, reliably show semantic calibration.
What a runnable demo should prove

What a runnable demo should prove

Build a small language model and train it on a corpus of question-answer pairs using only cross-entropy loss (next-token prediction). Then, for a held-out test set, generate 50 samples at temperature 1 for each question. Compute what fraction of samples are actually correct. Then measure the model's confidence: sample outputs from the model and measure its distribution over semantic answer classes.

calibration_error = |fraction_of_samples_correct - model_predicted_confidence|

The demo proves that the model's predicted semantic confidence matches reality: when it says 80 percent certain, about 80 percent of sampled answers are actually right.
