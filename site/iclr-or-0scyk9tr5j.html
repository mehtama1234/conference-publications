Trained on Tokens, Calibrated on Concepts

Base language models secretly learn to know how confident they should be in their full answers, even though they were trained only to predict one word (or token) at a time.

Paper explainersAll themesLLMs & Foundation Models

When you ask a language model a question, it generates one word after another. A word here is also called a token (just a piece of the full text). But how does it know when to feel confident about the complete answer? This paper discovers that base language models (trained just to predict the next word) automatically develop a hidden ability to judge confidence in their multi-word answers. The trick is a hidden connection: if training improves only by getting single words right, the model will implicitly learn where its answers will be correct—as a side effect. But instruction-tuning or other training methods can break this ability.

Zero assumption version

Models predict words but don't know their own certainty

A language model trained to predict the next word, one at a time, will eventually produce full sentences and answers. But here is the puzzle: the model only ever learned to be right about single words. How would it know whether its complete answer—the whole response—is correct?

A naive first try: you could ask the model to output a confidence score for each word it generates. But that requires explicit supervision: labeling training data with correctness judgments for every word produced. Base models never see that kind of label. Yet experiments show that base models actually judge their multi-word answers well without this training. The question is how.

The puzzle. Base models trained only on one-word-at-a-time prediction somehow know how confident to be in their complete answers.

The algorithm as a flow

What it actually does

During training, the model has context but not yet the full answer

After generating a few words, the model knows the question but the answer is incomplete.

It learns to predict: will the final answer be correct or wrong

Without seeing the future, it extracts patterns from training data: given the question and start of an answer, guess if the end result will be right.

This prediction naturally changes how it chooses upcoming words

If the model predicts the answer will be right, it slightly favors words that lead to correctness. If it predicts wrong, it slightly downweights those words.

Training converges when no simple reweighting could do better

The model has found all the easy improvements (because if any reweighting function could reduce loss, standard training would have discovered and built it in)—so it already knows when to boost or downweight answer paths.

After training, sampling many answers reveals the model's confidence

If you generate 50 answers, the model's built-in confidence shows as which answers appear more often.

What the paper changes

What the paper reveals

The paper does not propose a new training method. Instead, it exposes something the model is already doing: before generating the final answer, the model has computed an internal prediction of whether it will be right or wrong.

the object it moves  =  the built-in confidence forecast in base models
The hidden quantity

The hidden quantity: Local loss optimality

measured quantity  =  has the model already found all easy wins

Imagine after training, someone offers to tweak the model's output: reweight which word sequences it favors, giving a small boost to likely-correct answers and a small penalty to likely-wrong ones. If this tweak cannot improve the model's accuracy on test data, we say the model is locally-loss-optimal (because there is no easy reweighting trick left that the training process should have already found)—it has nowhere obvious left to improve from such easy adjustments.

The paper proves something clever: if a model is locally-loss-optimal with respect to such reweighting tricks, it must have already discovered and implemented them during training (because training minimizes loss greedily, so any easy improvement that could be represented as reweighting would have been learned). That means, to be locally-loss-optimal, the model must already know (before generating) which answers are likely right versus wrong. Otherwise it would have left accuracy gains on the table.

Why it works

Why it works: the connection between loss and confidence

Here is the core insight. During training, the model sees many question-answer pairs and learns to predict one word at a time correctly. Suppose the model has generated partway through an answer. From that point forward, if the model could predict what semantic category the final answer will fall into—right, wrong, or off-topic—then a greedy improvement is available: push the probabilities toward words leading to correctness, lower the probabilities toward words leading to error. This reweighting would lower the training loss directly.

The model cannot see the future, but it can learn the pattern: given the question and partial context, which final outcomes are likely? This is information hidden in the training data. If the model is well-trained (locally-loss-optimal), it will have already found and used all such easy improvements. Therefore, by necessity, the model must already know its own semantic confidence before generating, because otherwise it would have left accuracy gains on the table.

Instruction-tuning and chain-of-thought break this mechanism. When a model is fine-tuned with reinforcement learning or trained to reason out loud, the loss function or generation process changes. The easy-improvement shortcut no longer holds (because the new loss function no longer decomposes into reweighting sequences, so the model cannot improve by predicting semantic confidence in advance), so the model has no reason to predict semantic confidence in advance.

Math after the picture

The equation: loss optimality implies calibration

First in words:

if no reweighting trick can reduce the training error, the model must already have learned to predict when it will be right

Then the compact form:

For all reweighting functions w in class W: current_loss stays smaller than or equal to reweighted_loss. This is true if and only if the model predicts its own semantic correctness in advance.

Every symbol:

current_lossthe training error the model currently achieves
reweighted_losstraining error after you reweight how likely each answer-path is
wa simple reweighting function (boost some sequences, reduce others)
class Wthe set of reweighting functions that are reasonable to consider
semantic correctnesswhether the final answer is right, wrong, or off-topic
A tiny worked example
Model answers a question: before generating, it predicts 80 percent chance of being right, 20 percent chance of being wrong.
During training, to reduce loss, it slightly boosts words on the right-answer path and slightly reduces words on the wrong-answer path.
If you generate 50 answers by sampling (each chosen randomly with probability matching the model's training), about 40 will be correct.
That 40 out of 50 matches the model's prediction of 80 percent: the model's confidence is calibrated (well-tuned to reality).

If training already found all easy wins, it means the model already built in knowledge of which answers will be right. That knowledge is semantic confidence.

What can go wrong

What can go wrong

Questions about rare topics. If you ask the model about something it rarely encountered during training, the easy-improvement argument fails. The model may not have learned to be confident about such unfamiliar domains.
Different training methods break the mechanism. If the model is fine-tuned with reinforcement learning (like RLHF or DPO) or other loss functions, the special loss-optimality property no longer holds. The model has no reason to develop semantic confidence.
Chain-of-thought reasoning. If the model must reason out loud (step-by-step) before giving the answer, it cannot predict the final correctness in advance. Confidence breaks because reasoning comes before the answer.
Done right: base models on large corpora. Models trained only on one-word-at-a-time accuracy, on large amounts of in-domain data, reliably develop semantic confidence without extra training.
What a runnable demo should prove

What a runnable demo should prove

Build a small language model and train it on question-answer pairs using only one-word-at-a-time prediction (cross-entropy loss). Then test it: for each new question, generate 50 different answers by random sampling. Count what fraction of the 50 are actually correct. Also measure the model's internal confidence: extract what the model predicts about its own correctness for each question. Compare: does the fraction correct match the model's predicted confidence?

calibration error = gap between predicted confidence and actual correctness

The demo succeeds if the gap is small: when the model predicts 80 percent confidence, about 80 percent of sampled answers are actually right.
