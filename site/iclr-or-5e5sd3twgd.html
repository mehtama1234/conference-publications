RD-HRL: Reliable Sub-Goals for Long-Horizon Tasks

When a robot planner breaks a long task into sub-goals, use transition regions instead of noisy value estimates to pick goals that actually work.

Paper explainersAll themesReinforcement Learning

Robot tasks that run for hundreds of steps with almost no reward signal are hard: the robot takes an action now, but the reward comes so far in the future that the learning system cannot tell which early actions were helpful. One fix is to break the long task into shorter pieces with sub-goals in between. But picking good sub-goals is tricky, because the method that usually picks them (a value function that estimates future reward) is unreliable when trained on scarce data. This paper proposes a new way to pick sub-goals from transition regions, places where the task naturally changes from one type of behavior to another.

Zero assumption version

The long-task credit-assignment trap

Imagine teaching a robot to assemble a chair: position the leg, tighten the screw, move to the next leg, repeat. If the task runs for 500 steps and the reward comes only at the end (when the chair is fully built), the training system faces a crushing problem. Each early action nudges the 500-step chain, but the final reward is so distant and mixed with so many other actions that the learning system cannot tell which moves actually mattered. Step 23 might have helped, hurt, or changed nothing — the signal is lost in the noise.

Some researchers tried breaking the task into pieces: position leg 1, tighten leg 1, position leg 2, and so on. Each sub-goal becomes a smaller credit-assignment problem. The robot's high-level planner picks which sub-goal to pursue next; the low-level planner learns how to reach it. But which sub-goals should the high-level planner pick? The standard method uses a value function (a neural network trained to estimate which states lead to reward). On scarce data, this value function is noisy and unreliable — it steers the planner toward phantom sub-goals that look promising but lead nowhere.

In one sentence. Pick sub-goals from natural task boundaries (transition regions) instead of from a noisy value function.

What the paper changes

What the paper changes

The paper changes how sub-goals are selected. Instead of using a value function to score states and pick high-scoring ones as sub-goals, it picks states from transition regions — natural breakpoints in the task where one type of behavior (like reaching) hands off to another (like grasping).

the object it moves  =  sub-goal selection method
The hidden quantity

Reliability of sub-goals

measured quantity  =  sub-goal reliability (task-behavior divergence)

A sub-goal is reliable if it sits at a natural boundary where the robot's task naturally changes direction. The paper measures this by looking at transition regions: places where the robot's behavior pattern (the sequence of actions it is about to take) shifts. A transition point where the action probabilities spread out widely (high entropy, meaning the next move is unpredictable before the transition) marks a real task switch, not a phantom waypoint from a noisy value estimate.

The paper estimates reliability by examining the observed trajectories and identifying where the learned behavior policy diverges sharply. States in these regions have consistent downstream consequences, making them trustworthy targets for the high-level planner.

Why it works

Why transition regions make better sub-goals

A noisy value function is like a person guessing which movie to watch by throwing darts at a board where the numbers are smudged. The same board sometimes says 7, sometimes 8, depending on the dart throw. Pick the highest number and you might pick the same movie 100 times in a row, then suddenly switch to a totally different one as the random noise shifts.

Transition regions work differently. Imagine marking doorways in a house: places where one room (kitchen, living room, bedroom) ends and another begins. A doorway does not move. Even if you visit 1000 times, the doorway between kitchen and living room is always in the same spot. The paper finds the equivalent: states where one phase of the task (positioning the arm) naturally hands off to the next phase (closing the gripper). These handoff points are stable because they come from the task structure itself, not from a learned function that wobbles with noise.

Mechanically, the method trains a behavior policy on observed expert or near-optimal trajectories, then scans the trajectory for points where the policy's output (the probability of each action) changes sharply. These shifts mark transition regions. By picking sub-goals from these regions instead of from value estimates, the high-level planner gets stable targets that do not drift with noise.

inputOffline trajectory data (states visited during a task run)
stepTrain behavior policy: learn what actions an expert took at each state
stepScan for behavior shifts: find states where the action probabilities change sharply
stepMark transition regions: cluster these shift points as sub-goal candidates
stepTrain high-level planner: pick sequences of transition-based sub-goals
outputHierarchical policy that reliably breaks long tasks into shorter chunks
Math after the picture

Sub-goal selection from transition entropy

First in words:

reliability score = how sharply the action policy changes at a state; sub-goals chosen where this score is highest; high-level loss = standard Q-learning on high-level MDP with sub-goal transitions; low-level loss = Q-learning on reaching each sub-goal

Then the compact form:

L_high = (r + gamma * max_g Q(s_next, g) - Q(s, g))^2; score_i = entropy(policy(s_i)) - entropy(policy(s_{i+1})); sub-goal = argmax_i score_i

Every symbol:

rreward signal (1 when sub-goal reached, 0 otherwise)
gammadiscount factor (how much future rewards matter)
Q(s,g)estimated value of being in state s and pursuing sub-goal g
policy(s)learned action probabilities at state s
entropymeasure of how spread-out the probabilities are
score_ihow much the action policy changes between states
A tiny worked example
State 5 (positioning arm): action probabilities are [move_right=0.8, move_up=0.15, grip=0.05]; entropy = 0.72.
State 6 (transition to grasping): action probabilities are [move_right=0.05, move_up=0.10, grip=0.85]; entropy = 0.41.
Score for transition 5->6: 0.72 - 0.41 = 0.31 (big drop in entropy = sharp behavior shift = likely sub-goal).
State 7 (mid-grip): action probabilities are [grip=0.90, other=0.10]; entropy = 0.33.
Score for transition 6->7: 0.41 - 0.33 = 0.08 (small drop = no major task switch).
Sub-goals are placed at high-score transitions (e.g., state 6), not at low-score states (e.g., state 7).

The reliability score measures how much the robot's next action changes, spotting real task switches instead of random wiggles.

What can go wrong

What can go wrong

No expert data. The method learns transition regions from observed trajectories. If no good examples exist (only random, failed runs), the behavior policy is garbage and transition detection fails.
Task is amorphous. Some tasks have no clear phases. Pushing an object smoothly across a table has no natural waypoint; forcing one in creates false sub-goals.
Sub-goal is not reachable. The low-level planner might fail to reach a transition-region state. If that state is picked as a sub-goal but is actually unreachable from the current state, the robot gets stuck.
Works well when tasks have structure. Robot assembly (multiple discrete parts), navigation (waypoints between obstacles), and manipulation (position, grasp, lift, place) all have clear phases. Transition regions shine on these tasks.
What a runnable demo should prove

What a runnable demo should prove

Build a simple multi-phase task: a simulated robot arm reaching to a table, grasping a block, and lifting it to a goal location. This splits naturally into three sub-tasks: reach, grasp, lift. Run a baseline that uses a value function to pick sub-goals and track how often it chooses sensible (reachable, near-phase-boundaries) sub-goals. Run RD-HRL using transition detection. Compare: baseline picks sub-goals that drift randomly or cluster in the middle of phases; RD-HRL picks them at the natural boundaries (when reach ends and grasp begins).

sub-goal accuracy = fraction of chosen sub-goals that sit within 10% of phase-boundary states; task success = fraction of trials reaching the goal; test generalization = success rate when robot starts from a novel pose not seen in training data

The demo must show that RD-HRL picks stable, reachable sub-goals even when tested on new starting poses, while the baseline's value-based sub-goal picks drift or fail on new poses.
