Diff-MN: Diffusion-Parameterized MoE-NCDE for Time Series Generation

Use a diffusion model to learn which type of time dynamics to apply, moment by moment, when generating irregular time series at high resolution.

Paper explainersAll themesTime Series & Sequential

Real-world time series data is messy—observations come at irregular times, with gaps and sparse sampling. Existing generation methods assume evenly-spaced times and fixed output quality, which breaks on real data. This paper proposes Diff-MN, which learns to pick the right type of dynamics for each sample and time step, then generates continuous high-resolution series even when training data is irregular and sparse.

Zero assumption version

The real world has irregular, sparse time data—but methods assume perfect timing

Imagine tracking a patient's heart rate over a week: measurements come whenever the monitor records, not at fixed intervals. Some hours have many readings, others none. But a doctor needs to see the full high-resolution picture—what the heart rate likely was at every moment, not just where data points happened to land.

Existing time series generation methods (methods that learn to create new, realistic sequences) assume data arrives at regular, fixed times and they produce output at only one fixed quality level. This assumption works fine for clean datasets with evenly-spaced measurements, but breaks immediately on real-world data.

A naive approach: force the irregular data into a regular grid (fill gaps, average nearby times), then use a standard generation method. This works but throws away information: you lose the original timing pattern, and the filled-in measurements are guesses that the method then treats as gospel truth.

The paper's one-sentence move: Learn to pick the right type of dynamics (a learned option for how time flows) for each sample, letting a diffusion model decide which option fits best, so generated series stay realistic even when data is irregular.

The algorithm as a flow

What it actually does

Step 1: Learn the data

A diffusion model learns what the time series data looks like overall (its statistical pattern).

Step 2: Learn multiple dynamics

Multiple experts (neural networks) each learn a different way time might flow through the data.

Step 3: Router learns which expert

The diffusion model also learns, for each sample, which expert's dynamics fit best.

Step 4: NCDE continuous flow

The chosen expert applies its dynamics via NCDE (a method that defines smooth, continuous curves).

Step 5: Generate at any resolution

Once trained, ask for values at any time point; the model fills in realistic values using the learned dynamics.

What the paper changes

What the paper changes: the choice of dynamics function

Standard NCDE uses one fixed dynamics function for all data. Diff-MN replaces that with a Mixture-of-Experts: multiple versions of the dynamics, each specialized. The key difference: a diffusion model learns to pick which expert's dynamics fits each sample, rather than forcing one universal rule.

the object it moves  =  Which dynamics expert applies per sample
The hidden quantity

The hidden quantity: sample-specific mixture weights

measured quantity  =  Mixture-of-Experts weights per sample

In a mixture-of-experts system, each sample gets a distribution over experts—how much to rely on expert A versus B versus C, measured as fractions that sum to one. Normally these weights are fixed for all data. Here, they vary: the paper learns which expert combination makes sense for each individual sample, by having the diffusion model (the part that learns the data's overall statistics) also output those sample-specific weights.

The paper estimates this by training the diffusion model to jointly predict two things: the time series values and the MoE weights. It measures success by whether generated samples with these learned weights produce realistic, high-resolution output on both regular and irregular prediction tasks.

Why it works

Why it works: separate learning of data and dynamics, with expert routing

Standard NCDE couples everything: one fixed dynamics function must work for all data, and it trains against all observations at once. This is restrictive. If different data samples naturally have different time-flow patterns (one smooth, one jumpy, one with seasons), a single dynamics function either compromises and fits none well, or overfits to the average.

Diff-MN decouples the problem. First, a diffusion model learns the overall data statistics independently, without being forced to fit one dynamics function. Second, it learns multiple expert dynamics (MoE experts), each specialized for a different pattern. Third—the key innovation—the diffusion model learns sample-specific weights: for each data sample, which expert(s) should be in charge? This way, a smooth sample uses the smooth expert, a jumpy one uses the jumpy expert, and the NCDE can apply the right dynamics to the right data. The continuous output emerges naturally from applying a well-matched expert's dynamics to a realistic time-series sample.

Math after the picture

The equation: NCDE with expert-selected dynamics

First in words:

The NCDE computes the value at time t by flowing the starting value forward using the chosen expert's dynamics. The expert is selected by mixing weights from the diffusion model. For each time point, add up (each expert's dynamics multiplied by its weight).

Then the compact form:

z(t) = z(0) + integral from 0 to t of (sum over i of w_i * f_i(z(s), s)) ds

Every symbol:

z(t)the time series value at time t
z(0)the starting value
w_ithe mixture weight for expert i (learned by diffusion, sample-specific)
f_i(z(s), s)expert i's dynamics: how to flow the value forward from state z at time s
integral from 0 to tsum up all the tiny changes from start to time t (continuous version of adding)
A tiny worked example
At time 0, value z = 10.
We have 2 experts. Expert 1 says: increase by 0.5 per time unit. Expert 2 says: increase by 0.1 per time unit.
For this sample, diffusion learned: w_1 = 0.7, w_2 = 0.3.
From time 0 to time 1: flow = (0.7 * 0.5) + (0.3 * 0.1) = 0.35 + 0.03 = 0.38.
New value z(1) = 10 + 0.38 = 10.38.
Different samples (different weights) grow at different rates; each expert handles what it knows best.

The mixture weights let each sample pick its best expert; the integral sums the expert's guidance to build a continuous curve from the sparse starting points.

What can go wrong

What can go wrong

Too few experts. If the number of experts is smaller than the number of distinct data patterns in the true distribution, the mixture will compress different behaviors into one expert, and some samples will be misrouted. The model will still generate values but they will interpolate between patterns rather than match individual patterns cleanly.
Diffusion sampling noise at test time. The diffusion model generates the MoE weights during inference (test time). If diffusion's samples are noisy or off-distribution, the weights may send the NCDE to a poorly-trained expert, producing unrealistic values. This is especially risky if training data is small or narrow.
Irregular gaps remain a challenge for NCDE itself. Even with the right expert selected, NCDE must still solve the underlying problem: defining a smooth curve through sparse times. Large gaps (where no data exists for a long period) will require the expert to extrapolate, and if the expert hasn't seen such gaps during training, it will guess poorly.
Done well: balanced expert coverage. If each expert is trained on enough data, and the number of experts matches the diversity of patterns in the data, the model learns to route each sample to its specialist, generating high-quality output across regular, irregular, and mixed-resolution tasks.
What a runnable demo should prove

What a runnable demo should prove

Generate a synthetic time series with three distinct sub-patterns: smooth (slow change), jumpy (sudden spikes), and seasonal (repeating cycle). Intentionally remove half the time points to create irregular gaps. Train Diff-MN with 3 experts and a standard NCDE as baseline. Generate both with the same expert number, or force standard NCDE to use a single dynamics. Then sample at 10 times higher resolution than the training data (e.g., every 0.1 time units instead of every 1.0).

mean_absolute_error(true_high_res, generated_high_res) for each pattern separately, then average. Report both per-pattern error and per-expert utilization (what fraction of samples used each expert).

The key proof: Diff-MN's per-pattern error should be near the single-pattern baseline (because each expert specializes), while the standard NCDE's error should be visibly higher for the patterns it did not see. And the expert-utilization report should show that different sub-patterns use different experts, proving the model learned to route.
