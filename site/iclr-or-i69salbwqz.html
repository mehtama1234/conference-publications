Conformal Optimistic Prediction

When the world changes unfairly, make prediction bands tighter by learning from past mistakes instead of always playing it safe.

Paper explainersAll themesLearning Theory

Conformal prediction is a way to wrap a model's answer in a band of uncertainty that is guaranteed to include the true answer at least a certain fraction of the time. The problem: when data patterns shift around (like a thermometer that moves, then suddenly starts drifting), today's methods get scared and make those bands wider and wider, missing easy chances to tighten them when the pattern becomes predictable again. COP learns from the data's own rhythm and adjusts the bands dynamically.

Zero assumption version

The world shifts, but safety can be overdone

Imagine a model that predicts next week's temperature. It learns from years of data and makes predictions. But real weather patterns shift: a 10-year climate trend, a seasonal flip, even weird anomalies. A smart model detects some shifts but not all, and its predictions drift further from the truth.

A prediction band is a range (like 'between 65 and 75 degrees') that the model promises will contain the true answer some fraction of the time—say, 90 percent. That promise is a legal obligation.

A naive method: measure how wrong the model was on old examples. Take the worst-case mistakes and add that safety margin to every new prediction. Problem: if the world has shifted smoothly and become slightly more predictable (because a seasonal pattern kicked in), this method still adds the maximum safety margin, wasting the opportunity to give a narrow, useful band. It sees only drift, not rhythm. It says 'I cannot trust change, so I will stay maximally cautious forever.'

COP's insight in one sentence. Learn how often the model's errors come back to haunt it, and use that rhythm to tighten the bands when the pattern is predictable—while keeping the guarantee if the pattern breaks.

The algorithm as a flow

What it actually does

Watch past errors

Collect how wrong the model was on the last, say, 100 examples.

Draw an error pattern curve

From those 100 errors, estimate where the next error is likely to fall.

Find the safety threshold

Pick a threshold (a value on that curve) that guarantees the band will be right 90 percent of the time.

Update the threshold smartly

Instead of blindly following online learning rules, slide the threshold slightly based on recent errors, leveraging the curve's shape.

Wrap the band and repeat

Apply the threshold to the new prediction, observe the outcome, and update the curve.

What the paper changes

What the paper changes

The core change is in how the threshold for the prediction band is updated each round. Old methods take a step in a fixed direction (usually down when errors are small, up when they are large). COP adds a nudge based on an estimated picture of where error scores are likely to land. This makes the step smarter because the nudge corrects for the real shape of the error pattern, so the threshold lands closer to the optimal value in fewer rounds, saving computational work and reaching stable band widths faster.

the object it moves  =  the threshold update rule
The hidden quantity

The hidden quantity: error pattern from past observations

measured quantity  =  Estimated CDF of error scores

COP builds a picture of past errors by asking: 'what fraction of my recent mistakes fell below each size level?' This picture, called a cumulative distribution function (or CDF, the running tally of how often errors landed in each size bucket), is built from observed data without any assumptions about normal or special shape.

The paper uses this picture to refine the update step. Instead of always moving the threshold by the same amount, it asks: 'Given the errors I have seen so far, where should the threshold move to keep coverage stable while making the band tighter?' This is the hidden mechanism—a learned model of where errors cluster that guides the algorithm.

Why it works

Why it works: the smart update chain

COP balances two competing goals: online learning (adapting to any distribution shift) and distribution information (narrowing bands when patterns repeat).

Imagine standing at a threshold value (say, 42). Each round, you receive a new error score. Online learning would say: 'If the error exceeded my threshold, slide the threshold up a bit; if it stayed below, slide down.' This is safe but slow—it takes many rounds to find a good resting place when the world stabilizes.

COP does something smarter. It computes where the threshold 'should' be according to the recent distribution of errors, using a linear approximation of the quantile loss function (which measures how wrong the threshold is). Then it slides in that direction, weighted by confidence in the distribution estimate. If the estimate is noisy or the world is chaotic, the step is small; if the pattern is clear and stable, the step is larger. This lets COP tighten bands quickly when safe to do so, yet back off if chaos returns.

Math after the picture

The equation

First in words:

Expected quantile loss, then refined with distribution estimate

Then the compact form:

ell_{1-alpha}(q) = (1{q > 0} - alpha) * q; q_{t+1} = q_t - eta * [predicted gradient at q_t using estimated CDF]

Every symbol:

q_tthe threshold (the boundary of the prediction band) at timestep t
alphathe error rate we are willing to tolerate (e.g. 0.1 means 90 percent coverage target)
s_tthe non-conformity score (how far the model's prediction was from the truth) at timestep t
ell_{1-alpha}(q)the quantile loss function, which is zero if we guessed right and grows if the threshold is wrong
etathe step size (how boldly we move the threshold)
CDFthe estimated cumulative distribution of past scores—what fraction of errors fall below each value
A tiny worked example
Setup: target coverage alpha=0.1 (90%), current threshold q=50, recent errors average around 45.
Step 1: Quantile loss at q=50 with error s=45: loss = (1{50>0} - 0.1) * 50 = 0.9 * 50 = 45.
Step 2: Estimated CDF says 80% of recent errors were <= 45, so the implied optimal threshold is around 45.
Step 3: Gradient from CDF shape suggests moving down by about 3 units. With step size eta=0.2, we move: 50 - 0.2 * 3 = 49.4.
Step 4: On the next example with error 44, the band is slightly tighter; if error jumps to 60, the band widens again.

The estimated CDF replaces a fixed worst-case margin with a learned curve that adapts to the actual error distribution.

What can go wrong

What can go wrong

Not enough history yet. In the first few rounds, the estimated CDF is noisy because there are only a handful of past errors to build it from. COP's step size shrinks, so it does not over-correct, but the bands start wide and tighten gradually.
Sudden chaos breaks the estimate. If the world shifts radically (like a sensor breaks or a new data source arrives), the estimated CDF from recent errors no longer matches what is coming. COP will over-tighten for a round or two, risking coverage violation, until new error samples retrain the CDF.
Learning rate tuning is critical. Too large an eta, and COP chases every random fluctuation; too small, and it lags behind real shifts. The paper analyzes how to set eta but the practitioner must still choose or tune it per problem.
Done right: learning rate adapted. If eta is set appropriately for the problem (via cross-validation or held-out regret analysis), COP maintains coverage guarantees while exploiting predictable patterns, cutting band width in half on stable data.
What a runnable demo should prove

What a runnable demo should prove

Generate a synthetic time series where the model's errors follow a pattern: e.g., errors come from a normal distribution with slowly drifting mean, then suddenly jump to heavy-tailed at timestep 1000. Split into three regimes: stable, drift, chaos. For each regime, measure coverage (did the band contain the true value?) and band width. Compare COP against a fixed worst-case method and against online learning without distribution estimates. COP should show: narrow bands during stable and drift phases because it learns where errors cluster and moves the threshold directly toward the learned optimum, not one blind step at a time; coverage holds in all three regimes because it never forgets the safety principle; adaptation is faster than worst-case because it uses the estimated curve instead of worst-case margins, and smoother than raw online learning because the curve dampens wild swings when a single outlier arrives.

Coverage rate = fraction of timesteps where true value fell inside the band; Band width = average (upper bound - lower bound); Regret = cumulative band width across all timesteps

The key outcome: COP's bands should be half as wide as naive worst-case during stability, yet maintain 90-percent coverage even when the regime flips to chaos.
