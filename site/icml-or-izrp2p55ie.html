MASPO: Joint Prompt Optimization for Multi-Agent Systems

MASPO fixes broken multi-agent teams by teaching agents to write instructions that actually work for the next agent in line, not just themselves.

Paper explainersAll themesLLMs & Foundation Models

When you build a team of AI agents using large language models, each agent gets a written prompt—a set of instructions that tells it what to do. The problem: if you optimize each prompt in isolation, agents end up with instructions that sound good on paper but fail when they have to work together. MASPO solves this by evaluating prompts the way a real team does—not by how well an agent performs alone, but by whether its output successfully sets up the next agent to succeed.

Zero assumption version

Prompts tuned alone break when agents collide

Multi-agent teams face a paradox: if you optimize each agent's prompt individually (tuning it on tasks it must solve), every agent looks good on its own test. But in reality, agents hand work to each other—Agent A writes something, Agent B reads it and builds on it, then Agent C uses B's output. If A's output is tuned only for A's local success, it might not be in the format B expects, or might miss details B needs. B stumbles, C stumbles further. The whole team fails, even though each piece tested well alone.

A beginner's first instinct is to write prompts by hand, or optimize each one separately using standard techniques. But this guarantees misalignment: each agent's instructions tell it to do well on its own metrics, not to produce output that downstream agents can actually use.

In one sentence. Prompts tuned per-agent in isolation fail downstream because no agent is told to care whether the next agent in line can use its output.

The algorithm as a flow

What it actually does

Step 1: start with baseline prompts

Each agent in the team has a written prompt (the instructions it follows).

Step 2: run the full pipeline

Execute the entire multi-agent workflow on a test task, recording each agent's output at every stage.

Step 3: measure joint success

Check whether the final outcome was correct. This is the ONE score that matters—team-level success.

Step 4: propose new prompt candidates

Use evolutionary search (like breeding: keep winners, mutate them, breed the best variants) to generate candidate prompt rewrites for each agent.

Step 5: rank and repeat

Test variants on the same tasks, keep those where team success improved, and breed more variants from the winners.

What the paper changes

The one thing that changes

MASPO rewrites the prompts—the written instructions each agent follows. Traditional methods tune prompts to maximize each agent's solo performance. MASPO tunes prompts to maximize downstream agent success: it grades Agent A's prompt not on how well A solves its local task, but on whether B and C can successfully use A's output.

the object it moves  =  prompts (written instructions)
The hidden quantity

The hidden quantity: downstream impact score

measured quantity  =  downstream impact score (usefulness to the next agent)

The hidden quantity MASPO measures is downstream impact—a score that quantifies whether an agent's output is actually useful to the next agent in the pipeline. It is not just 'did the task pass?' but 'did the output from Agent A arrive in a form that Agent B expected, with the right level of detail and clarity that B needs to succeed?' This is computed by running the full pipeline (all agents in sequence) and checking the final outcome, then working backward to assign credit to each prompt.

MASPO estimates this by a two-level evaluation: (1) run the multi-agent workflow end-to-end on a test task, (2) measure whether the final result was correct, (3) use that signal to rate each intermediate prompt's contribution. Unlike methods that grade each agent in isolation, MASPO grounds every prompt's score in real team performance.

Why it works

Why joint evaluation fixes the alignment problem

The root problem is misaligned incentives: each agent's prompt is tuned to make that agent look good on its own score, not to help its teammates downstream. This happens because standard prompt-optimization only measures 'did Agent A solve its part of the problem?' It never checks 'did Agent B understand what A wrote?' or 'could B actually continue from A's output?' As a result, A's instructions say 'answer correctly' but never 'answer in a format B expects.' MASPO fixes this by changing what counts as success. Instead of grading each prompt separately, it grades all prompts together by asking 'did the whole team get the final answer right?' Now Agent A's prompt gets improved only if changes to it help B and C succeed too. This creates a feedback signal that forces A to write 'output in exactly this JSON format' or 'always include names in your list.' Without team-level grading, A never hears that formatting matters.

The evolutionary search part works by breeding variants: it takes the current best prompts, makes small rewrites to create variations, tests all variants on real tasks, and keeps only the winners. Why use breeding instead of calculus-style optimization? Because multi-agent pipelines are non-differentiable—you cannot smoothly measure 'how much does changing this word improve the answer?' You can only run the whole team and check: did it work or not? Calculus requires you to nudge a number slightly and measure the change, but prompt-space is discrete (a word either is or is not in the text; there is no 'halfway' rewrite). So trial-and-error breeding works better because it samples 10 prompt rewrites, tests all 10 on the same tasks, measures which ones led to team success, and breeds new variants from the winners. This lets the algorithm climb the success hill without needing mathematical smoothness.

The joint evaluation equation

First in words:

team success score is 1 if the final output is correct, 0 otherwise. For each prompt under test, MASPO computes a prompt quality value by running the pipeline and measuring the success score. Prompt variants are scored the same way: run the team, check the answer.

Then the compact form:

Q(prompt_set) = accuracy( run_agent_pipeline(A, B, C, ...; prompts) )

Every symbol:

Q(prompt_set)the quality score of a set of prompts (how often the full team succeeds)
run_agent_pipeline(...)execute all agents in sequence with the given prompts
A, B, C, ...the agents in the team
accuracy(...)fraction of test tasks where the final output was correct
A tiny worked example
Baseline prompts run 10 test tasks: the team succeeds on 7. Accuracy = 7 / 10 = 0.70.
MASPO mutates Agent A's prompt to be more explicit about output format.
New prompts run the same 10 tasks: now the team succeeds on 8. Accuracy = 8 / 10 = 0.80.
The mutated prompt is better (+0.10 gain). MASPO breeds more variants from this winner.
After iteration, final prompts reach 9 / 10 = 0.90 team success. MASPO stops (no longer improving).

Unlike solo optimization (which grades each agent separately), this equation grades the entire team as one unit. Only prompts that make downstream agents succeed will survive.

What can go wrong

What can go wrong

Prompts overfit to the test tasks. If MASPO optimizes prompts on only 5 test tasks, the evolved prompts might include special-case logic baked in (like 'if you see this keyword, output that'). On new tasks the prompts have never seen, they fail. The fix is cross-validation: evolve on a training set of tasks, measure on a held-out test set.
Evolutionary search gets stuck in local optima. The space of possible prompts is vast and bumpy. The algorithm might find a small improvement and stop, missing even better rewrites hidden further away. This is why MASPO uses beam search: keep multiple candidate prompt-sets alive at once and search broadly, not just greedily following one path uphill. But even with beam search, the algorithm is not guaranteed to find the absolute best prompts—only good ones.
Cascading changes break emergent behaviors. Changing Agent A's prompt might accidentally introduce wording that Agent B's instruction-reader interprets differently, creating a subtle semantic shift. If the test cases did not cover that edge case, the evolved prompt looks good until deployment. Mitigation: stress-test evolved prompts on diverse tasks and adversarial inputs.
Done right. MASPO works when: (1) the task has a clear right answer (so you know whether the team succeeded), (2) the team is small (2-5 agents; large teams mean expensive testing), and (3) you have diverse test cases (so the evolved prompts generalize). When these hold, joint evaluation beats solo tuning because it aligns every agent's instructions to the team goal, not individual scores.
What a runnable demo should prove

What a runnable demo should prove

A runnable demo should start with a multi-agent workflow on a real task (e.g., a question-answering task split into retrieval, reasoning, and synthesis phases, each run by a separate agent with a prompt). (1) Measure the baseline: run the unoptimized prompts on 20-30 diverse test questions and record the fraction of correct final answers. (2) Run MASPO's joint optimization for 20-30 iterations, keeping track of the best prompts. (3) Run the final optimized prompts on the same test questions and record the new accuracy. (4) Visualize: show the accuracy curve (x-axis: iteration number, y-axis: team success rate) and highlight that the curve rises steadily, proving that joint evaluation is actually improving the real bottleneck (downstream alignment), not just claiming to.

The key observation: prompts tuned for team success will outperform prompts tuned for individual agent performance on the real multi-agent task, because alignment matters more than perfection in one position.
