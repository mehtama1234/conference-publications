Graph & Geometric Learning

How can machine learning models learn from data structured as networks of connected things?

← All themes explainedField mapMathematicsAll explainers
What this whole area is about

Much of the real world is structured as networks: social networks have people connected by friendships, molecules have atoms bonded together, recommendation systems connect users to products, and disease spreads through contact patterns. But most machine learning models were designed for flat tables of data, where each row is independent. They ignore the connections between things. Graph learning asks: how can we build models that see and reason about these network structures?

The challenge is that networks break traditional assumptions. In a table, you can process each row separately. In a graph, what happens to one node affects its neighbors, and those effects ripple outward. A node's role depends on the entire subgraph around it. Standard models lack the tools to capture these dependencies. You need a way to let each node talk to its neighbors, for information to flow through the network, and for the model to capture both local patterns (what a single node looks like) and global structure (how the whole network hangs together).

Researchers have developed several directions to tackle this. Some build new neural network designs that pass information between connected nodes, letting each node aggregate what its neighbors know. Others use geometric ideas—symmetries, shapes, manifolds—to understand the intrinsic structure of data. Still others focus on specific tasks: finding unusual nodes, extracting patterns, turning graphs into vectors—lists of numbers that capture what each node or graph is like—or working with enormous networks like knowledge bases. And new work connects graphs to transformers (a type of neural network where different parts can attend to each other) and language models, treating network structure as another kind of data that modern architectures can learn from.

Graphs appear everywhere outside the lab: understanding how diseases spread through populations, predicting which molecules will make good drugs, recommending products based on user similarity, analyzing social influence, and detecting fraud by finding unusual connection patterns. Graph learning touches chemistry, biology, recommendation systems, social science, and security.

Subtheme

Building stronger models for graph data by passing information between connected nodes

The core insight is that information in a graph lives in the connections, not just the nodes themselves. A person's interests may be similar to their friends' interests, a molecule's properties depend on how its atoms are bonded, and a webpage's topic relates to the pages it links to. So a model needs a way to collect information from neighbors and use it to make better predictions. Most early work did this by averaging neighbors' features at each layer—but averaging loses detail and doesn't capture the many subtle ways that different types of connections matter differently.

The hard part is doing this efficiently at scale while capturing long-range patterns. If you average neighbors, then average neighbors of neighbors, the signal can get diluted—like a game of telephone where the message gets garbled. Also, sometimes a node's most important influence comes from far away in the network, not from its immediate neighbors. And different edges may mean different things (a 'likes' edge is not a 'disagrees with' edge), but simple averaging treats all edges the same way without capturing these distinctions.

Papers in this subtheme propose new designs: better ways to aggregate neighbor information using attention—learning which neighbors matter most—spectral methods that think about the graph's mathematical structure, transformer-based approaches that let distant nodes talk directly so long-range dependencies aren't lost, and techniques to preserve information flow so distant patterns don't fade away. The goal is a model that captures both what each node is locally and how it fits into the overall shape and structure of the entire network, since this context shapes the node's role.

Subtheme

Learning from the shape and structure of data

Beyond just connections, data often has hidden structure—symmetries, shapes, patterns that repeat in predictable ways. A molecule looks the same if you rotate it or reflect it, so the model should learn the same representation regardless of how the atoms are drawn on paper, because the molecule hasn't changed. A social network has community structure: groups of people who are tightly connected internally but loosely connected to other groups. High-dimensional data often lives on lower-dimensional manifolds, curved surfaces in space. These geometric and topological ideas—which is fancy language for 'symmetries and shapes'—can help models learn more efficiently because the model doesn't waste capacity learning the same pattern multiple times.

The challenge is that standard neural networks don't inherently respect these symmetries and structures. If you rotate a molecule's coordinates, the model might give a different answer even though the molecule didn't change. This wastes the model's learning capacity: it has to learn the same pattern multiple times for each rotation. Similarly, if you know data lives on a 2D surface in 3D space, treating it as full 3D data is wasteful.

Researchers tackle this by building models that are equivariant—meaning if you transform the input (rotate a molecule, permute nodes), the output transforms in the same predictable way. They use Riemannian spaces—curved surfaces where distance is measured differently—and hyperbolic spaces—weird surfaces where distances work differently—to reflect the actual structure of the data. They learn manifolds—the underlying low-dimensional shapes where data actually lives. These approaches make models more sample-efficient because they respect these structures instead of making the model learn them by accident.

Subtheme

Finding patterns and anomalies in networks

Sometimes the question is not 'predict a label for each node' but 'what is unusual?' In a fraud-detection network, most transactions are legitimate, but a few follow suspicious patterns. In a sensor network, most readings are normal, but a few nodes are failing. In a recommendation system, most user-product pairs are unrelated, but a few clusters of users want the same things. Detecting these unusual things—anomalies—is different from typical classification: you need to find what deviates from normal, and normal is often defined by patterns in the network itself.

This is hard because anomalies are rare, so you don't have many examples to learn from. Also, what counts as anomalous depends on context. A sudden traffic spike is suspicious in an email network but normal in a shopping network. And some anomalies hide by mimicking normal patterns. An adversary committing fraud may deliberately try to look like normal users around them.

Papers here develop techniques to identify subgraphs and clusters that stand out—groups of nodes that are tightly connected to each other but loosely connected to everyone else. They use outlier detection on graph embeddings (vector representations of nodes), looking for nodes whose position in the learned space is far from their neighbors. They study which subgraphs appear frequently versus rarely. Some use multi-view clustering: the same nodes may form different clusters depending on which type of edge you focus on, and anomalies stand out in some views but not others.

Subtheme

Learning representations and embeddings

One of the most practical tools in machine learning is turning data into vectors—embeddings. An embedding is a list of numbers that captures the essence of a thing. If you have good embeddings, you can do almost anything: find similar items (users similar to you), cluster things, detect anomalies, transfer learning to new tasks. The question for graphs is: how do you turn a node, a subgraph, or an entire graph into a fixed-size vector that preserves its important properties?

The challenge is deciding what should be similar. Do you want embeddings to be similar if two nodes have similar neighborhoods? If they play similar roles in the network? If they lead to similar outcomes? Different tasks need different embeddings. Also, graphs are not fixed in size—one graph might have 100 nodes, another might have a million. You need a way to turn variable-size structures into fixed-size vectors. And you want embeddings to be stable: small changes to the graph should cause small changes to the embedding, not flip it completely.

Papers use self-supervised learning: instead of needing labeled examples, they learn embeddings by solving puzzles that the graph itself provides. For example, predict a node's neighbors from its embedding, or predict which part of the graph is deleted from what remains. They use contrastive learning: train the model so that similar things get close embeddings and different things get far apart, using the network structure to define similarity. Some use pretraining on huge graphs and then fine-tune on downstream tasks. The result is embeddings that capture intricate patterns and work across many different graph learning problems.

Subtheme

Understanding knowledge and relationships at scale

Knowledge bases are enormous graphs of facts: 'Einstein' is connected to 'Physics' via 'field of study', and 'Physics' is connected to 'Relativity' via 'related to'. Real knowledge graphs have millions of entities and billions of relationships. The tasks are unique: complete missing facts (infer likely connections), reason over chains of relationships (if A causes B and B affects C, then A affects C), and extract semantic meaning—the idea that certain relationships are more important or carry more weight than others.

The hard part is scale and incompleteness. Most large graphs are sparse—most possible connections don't exist—and incomplete—missing connections you'll never see the data for but could infer. Also, relationships have different meanings and strengths. A 'parent of' relationship is very different from a 'similar to' relationship, and a 'voted for' relationship in politics is different from a 'voted for' in a jury. A simple averaged model loses these distinctions. And at millions of entities, even reading through all neighbors of a node becomes expensive.

Researchers build models that embed entities and relationships together, learning vector representations where reasoning becomes simple vector math: if relation R takes entity A to entity B, then A plus the direction R should point toward B. They study temporal reasoning (relationships change over time) and multi-hop reasoning (paths through multiple relationships). They handle the incompleteness by learning to score how likely a missing connection is based on the patterns around it. Some adapt transformer-style attention to work with enormous graphs by sampling or aggregating smartly instead of considering all neighbors.

Subtheme

Making graph models work in real conditions

Academic papers test models on clean graphs, but the real world is messy. In production, you face missing data (sensors fail, records are incomplete), distribution shift (the network changes over time or between domains), adversarial attacks (someone deliberately adds edges to fool the model), and the need to personalize (different users need different recommendations). A model trained on one social network may not work on another. A graph model trained on historical data may fail when the network structure changes.

These problems are hard because graph models are sensitive to structure. Remove one node or edge and the entire message-passing process changes. If the model learned to rely on certain neighbor types that disappear in a new domain, it fails. An adversary can deliberately add connections to make normal-looking fraudulent nodes. And personalization means you can't just train one model for everyone—you need to adapt to local structure around each user or entity.

Papers develop techniques for model reliability: training models that still work if data is missing, using data augmentation (carefully adding or removing edges to make the model less brittle), certifying that models resist adversarial attacks. They tackle domain adaptation: training on one graph and transferring to another despite structural differences, sometimes using contrastive learning or unsupervised methods that work without labels in the new domain. They study heterophily (when similar nodes are NOT connected, which breaks standard message-passing), federated learning (training on multiple graphs without centralizing data), and personalization (learning per-user or per-entity models that adapt to local structure).

Subtheme

Connecting graphs to language and modern architectures

For years, graph models and language models evolved separately. Language models use transformers—architecture where every word can attend to every other word, learning which parts matter most. Graph models use message-passing or spectral methods designed for network structure. But recently, researchers realized transformers can work on graphs too: you can treat nodes as tokens (a chunk of data the model reads) and let a transformer learn which connections matter. And you can combine graph and text data: some entities have names or descriptions, so you can use both graph structure and language at the same time.

The challenge is scaling and semantics. Transformers need to compute attention between every pair of nodes, which costs quadratic time and memory—impossible for graphs with millions of nodes. Also, transformers treat everything as sequence of tokens, so you need to encode graph structure into tokens somehow. And when graphs have varied metadata—text on nodes, multiple edge types—how do you represent that without drowning in complexity?

Papers propose several approaches: efficient transformers that approximate attention by sampling or using sparse patterns, so they scale to large graphs. They encode graph structure as special tokens or as positional encodings (information about where each node sits in the graph). They jointly learn from graph and text by feeding both into the same model—useful for knowledge graphs where entities have names, or for paper citations where papers have abstracts. Some adapt pretrained language models to graphs by treating neighborhoods as text or by treating edge sequences as pseudo-sentences. Others use language models as components in a larger graph system: asking the model to reason in natural language about what a neighborhood means, then using that reasoning to make decisions.

Subtheme

Generating and transforming graphs

Most graph learning papers predict things about existing graphs. But sometimes you want to generate new graphs—design new molecules, create synthetic social networks for simulation, find better graph structures by optimization—because you need new examples or solutions. This requires a different kind of model: one that can produce structured data, respecting the constraints (molecules have valid bonds, social networks have realistic patterns), since random graphs won't work.

The hard part is the combinatorial explosion. A molecule's atoms can bond in countless ways, most of which are chemically impossible. A graph with N nodes can have up to N squared possible edges. You can't enumerate all possibilities. Also, the order in which you generate things matters: if you add an atom first, then try to add a bond to it, you might back yourself into a corner. You need a way to generate step-by-step while respecting global constraints.

Papers use generative models: diffusion (start with noise, gradually refine it into a valid graph), flow matching (learn to transform from one distribution to another), and autoregressive approaches (predict one thing at a time, conditioning on what you've already generated). They tackle combinatorial optimization: given a graph, find a better version by modifying it, using learned models or optimization algorithms. They use graph augmentation—adding or removing edges—as a way to generate training data for other tasks. Some incorporate chemical knowledge (atoms have valence limits) or social knowledge (realistic networks follow patterns like preferential attachment) to guide generation toward realistic outputs.
