When and Where to Reset Matters for Long-Term Test-Time Adaptation

A model can collapse into predicting the same class over and over when learning from test data, but instead of resetting everything, you can save important knowledge by resetting only some layers and remembering which weights to keep.

Paper explainersAll themesOther

When a model learns from new test data continuously (test-time adaptation), errors pile up and the model eventually stops seeing different classes—it just predicts the same one repeatedly. Existing methods either reset everything on a schedule (wasteful) or not at all (disastrous). This paper asks: what if we reset only the layers closest to the output, track which weights were important to past correct predictions, and restore them after each reset?

Zero assumption version

The Collapse Trap

When you take a model trained on one set of images and then keep showing it new, drifting images (a camera degrading, fog, or changing weather), something goes wrong: the model adapts, but its own predictions get noisier and noisier. It predicts based on that noise, which makes the next prediction even noisier. Within hours or days, the model stops seeing any class but one—it collapses. This is self-training gone wrong: the model pulls itself into a corner.

A beginner tries two things: Do nothing (model collapses). Or reset everything to the original pre-trained state once per day (model loses all the good adaptations it learned, so it's back to square one for real drift). Neither works. You need to reset some parts but not others, and you need to know when the collapse is actually about to happen, not on a fixed schedule.

The core problem: Error piles up over time, the model stops predicting diverse classes, and periodic resets throw away good knowledge along with the bad.

The algorithm as a flow

What it actually does

1. Measure prediction inconsistency

At each batch, compute how much the raw scores (logits) for each sample vary. If they are close to zero, the model is uncertain—that is a sign of collapse risk.

2. Decide if reset is needed

Use an accumulated Fisher information score (which weights were important to past correct answers) and the prediction inconsistency together to decide whether to reset right now.

3. Reset only the back layers

Do not reset the feature-extraction layers (early ones). Reset only the last few layers (those closest to the output), proportional to how bad the inconsistency is.

4. Restore important weights

For weights that were flagged as important (high Fisher score), nudge them back toward their original pre-trained values. Leave unimportant weights alone.

5. Adapt carefully afterward

Adjust the learning rate for each layer based on how much it drifted from the start. Layers that drifted a lot get smaller updates, to avoid collapse again.

What the paper changes

What the paper moves

The paper changes which layers get reset and when. Instead of resetting all layers on a schedule, or not resetting at all, it resets only the layers closest to the output (the classifier head and a few layers above), and only when a specific signal (prediction inconsistency) says collapse is imminent.

the object it moves  =  reset timing and layer selection
The hidden quantity

The hidden quantity: Fisher importance

measured quantity  =  Fisher importance score

Fisher importance is a number assigned to each weight that tells you how sensitive the model's past correct predictions were to that weight. A high score means tiny changes to that weight broke many correct answers; a low score means the weight barely mattered. The paper computes it by tracking the squared gradients (how much each weight was nudged during training) and accumulating them over time.

The paper uses Fisher importance to decide which weights to protect: after a reset, it pulls high-importance weights back toward their original values, because those weights were essential to good performance. Weights with low Fisher scores are left free to adapt to the new domain.

Why it works

Why selective reset with recovery works

The early layers of a model learn general patterns (edges, textures, shapes) that stay relevant across many domains. The later layers learn specific class boundaries for the original source domain. When you keep adapting in a drifting domain, the later layers corrupt the class boundaries gradually (noisy pseudo-labels push them further and further). But the early layers are still good.

By resetting only the later layers, you erase the accumulated corruption in the classifier. But Fisher importance keeps you from losing the entire learned model: weights that were central to correct predictions before drift get pinned back to their original values. Weights that barely mattered are released to adapt. This gives the model a fresh classifier head (so it can see different classes again) while preserving the knowledge that made it work in the first place. The on-the-fly learning rate adjustment prevents the model from drifting too far again by penalizing movements of weights that already drifted a lot—the model learns to be cautious in the layers that have already changed.

Math after the picture

The protection formula

First in words:

Regularization penalty = importance score times the square of how far the weight moved from its original value

Then the compact form:

L_recovery = lambda * sum_i F_i * (theta_i - theta_i0)^2

Every symbol:

theta_ithe current value of weight i
theta_i0the original pre-trained value of weight i
F_ithe Fisher importance score for weight i (how much it mattered to past correct answers)
lambdaa hyperparameter controlling how strongly the recovery pulls weights back
A tiny worked example
Weight w1: importance 8.0, originally 0.5, now 1.2 (moved 0.7 from original) -> penalty = 8.0 * 0.7^2 = 3.92
Weight w2: importance 0.1, originally 0.3, now 0.8 (moved 0.5 from original) -> penalty = 0.1 * 0.5^2 = 0.025
Weight w3: importance 0.2, originally 0.2, now 0.2 (moved 0.0) -> penalty = 0.2 * 0.0^2 = 0.0
With lambda = 0.1: w1 is pulled back hard (0.392 cost), w2 barely (0.0025 cost), w3 not at all (free to adapt). High Fisher scores = high protection.

The penalty penalizes moving important weights away from their originals, so the training algorithm naturally keeps them close.

What can go wrong

What can go wrong

Batch size is too small. If only a few images arrive at each step, Fisher scores become unreliable noise because each gradient is just a small signal buried in randomness. Prediction inconsistency becomes hard to measure because a single example has extreme scores anyway. The method degrades gracefully (still better than baselines) but is less stable because the resets trigger at the wrong times and recover the wrong weights.
The hyperparameter lambda is set wrong. If lambda (the strength of weight recovery) is too high, the model gets locked into the pre-trained state and cannot adapt at all. If too low, important weights drift as usual, and you get collapse again.
The domain shift is truly catastrophic. If the domain changes so radically that the early feature layers become useless (e.g., infrared camera after visible-light training), the method still fails because the preserved features are worthless.
Done right. Accumulate Fisher scores over many steps (not just one batch). Set lambda conservatively. Reserve a small validation set to monitor class balance if possible. Reset only when inconsistency is consistently high, not on a single spike.
What a runnable demo should prove

What a runnable demo should prove

Build a simple image classifier (e.g., ResNet-18 pretrained on ImageNet). Stream it drifting test data by applying a sequence of corruptions (Gaussian blur, fog, brightness, saturation, contrast—the standard benchmarks). At each step: (1) feed a batch of corrupted images, (2) self-train with pseudo-labels, (3) measure prediction inconsistency (how chaotic the raw scores are, or the fraction of near-zero scores), (4) compute Fisher scores from gradients of correct pseudo-label predictions, (5) when inconsistency is high, reset the last 3 layers and recover important weights. Track accuracy on a held-out clean test set at every 100 steps. Plot the accuracy curve and how often each class gets predicted over time.

Collapse avoidance = 1 - (minimum class frequency / maximum class frequency) over time. Higher is better. Also: forgetting = accuracy on original domain at step 1 minus accuracy at step 1000.

The demo makes it impossible to miss: the baseline model collapses (predicts one class 80% of the time by step 500) because noisy pseudo-labels push the classifier weights into a corner, while ASR stays balanced (all 10 classes predicted between 8-12% each) because selective resets erase that corner-pushing before it locks in, and maintains accuracy across 1000 steps because recovered important weights keep the features from rotting.
