FlatLab: Unified Manipulation of Flat Objects

A robot learns to pick and manipulate sheet-like objects by first figuring out the right strategy, then executing it with composable motion primitives.

Paper explainersAll themesRobotics & Control

Picking up a towel or cloth is harder for robots than it looks because the object can be grabbed in many positions, each one needs different moves, and the cloth bends unpredictably. This paper splits the problem into two jobs: first, look at the object and decide what strategy to use; second, execute that strategy by chaining together basic motions. The robot learns strategies from simulation so it can handle new towels and fabrics it has never seen.

Zero assumption version

Why flat objects are hard to grasp

A rigid object with fixed corners (such as a block) can be held at any corner. A flat object such as a towel or cloth is floppy and ungraspable in many positions. If the cloth is bunched or folded, you cannot just grab anywhere; you need to first flatten it or rotate it into a configuration where a real grip exists.

A naive robot sees a tangled cloth and tries one fixed approach: always grab the center, or always pull in one direction. But different cloth shapes need different first moves. Sometimes you must roll the edge, sometimes peel a corner up, sometimes unfold it. A single hard-coded move fails on cloth the robot has not seen before, especially if the material changes (silk bends differently than canvas).

The core challenge. Before you can grab a flat object, you must figure out which strategy to use based on its shape and material.

The algorithm as a flow

What it actually does

1. Scan the cloth

A depth camera captures the 3D point cloud (the actual shape on the table).

2. Predict the strategy

A neural network reads the point cloud and outputs a score for each strategy (peel, roll, unfold), picking the highest score.

3. Execute primitives

The execution module chains together low-level actions (grasp, rotate, slide) in the order that strategy dictates.

4. Adjust on the fly

As the robot moves, it re-reads the cloth shape and re-scores strategies, switching if needed.

5. Reach the goal

The cloth ends up in a graspable pose so the final pickup is a simple, stable grab.

What the paper changes

What the paper changes

Instead of using one fixed manipulation strategy for all cloth shapes, the paper makes the strategy adaptive: the robot learns to predict which strategy to use based on the object's shape. The strategy is not a hard-coded rule but a learned decision from a neural network trained on thousands of simulated cloth configurations.

the object it moves  =  strategy choice (adaptive, learned)
The hidden quantity

The hidden quantity: strategy-centric representation

measured quantity  =  object-invariant strategy feature

The robot needs a way to describe cloth in terms of which strategy works, not in terms of cloth properties. A normal description might be: wrinkles here, folded there, sticky fabric. But the paper uses contrastive learning (a technique that learns to group similar things) to build a hidden representation where cloth shapes that need the same strategy are clustered together, even if they look different. This is called an object-invariant representation: it describes the cloth in terms of what to do, not what it looks like.

The paper estimates this representation by training on simulated data: it collects thousands of cloth configurations, labels each with the right strategy, and teaches the network to map shapes to strategies so reliably that the hidden features capture pure strategy-relevance.

Why it works

Why splitting into strategy and execution works

If a robot tries to learn one giant policy (a single neural network that takes cloth shape and outputs a full sequence of moves), it must memorize every case: this shape of silk needs this path, that shape of canvas needs that path. That requires vast amounts of data and does not generalize to new shapes or materials. But by splitting into strategy and execution, the problem becomes tractable: the strategy network learns to recognize clusters of shapes that need the same type of move (peel, roll, unfold), and the execution module learns to compose reusable primitives that work within that strategy. The primitives are not cloth-specific; they are motions like rotate and slide that work on any flat object.

Contrastive learning amplifies this: it groups cloth configurations that need the same strategy together in the learned feature space, even if they look visually different. This means a cloth configuration the robot has never seen, but which shares the same problem-structure with training data, will activate the same strategy cluster and therefore use the correct primitives.

Learning strategy-centric features

First in words:

The paper learns features using contrastive loss, which pushes cloth shapes that use the same strategy close together and pulls apart shapes that need different strategies.

Then the compact form:

L_contrastive = -log( exp(sim(f(x_i), f(x_pos)) / tau) / sum_j exp(sim(f(x_i), f(x_j)) / tau) )

Every symbol:

f(x_i)the learned feature vector for cloth configuration i
x_posanother cloth configuration that needs the same strategy
x_jany other cloth configuration (may need a different strategy)
sim(...,...)cosine similarity (how aligned two feature vectors are)
tautemperature (controls how sharp the grouping is)
A tiny worked example
Configuration A (peel strategy): learned feature values [0.9, 0.1, 0.2]
Configuration B (also peel): learned feature values [0.85, 0.15, 0.25]
Configuration C (roll strategy): learned feature values [0.2, 0.9, 0.1]
Alignment of A to B (same strategy): cos([0.9, 0.1, 0.2], [0.85, 0.15, 0.25]) ≈ 0.97 (very close)
Alignment of A to C (different strategy): cos([0.9, 0.1, 0.2], [0.2, 0.9, 0.1]) ≈ 0.15 (far apart)
Loss pushes A-B even closer and A-C further apart, so the learned features encode strategy.

The contrastive loss makes cloth shapes with the same manipulation strategy cluster together in feature space, allowing generalization to new shapes.

What can go wrong

What can go wrong

Strategy mismatch in new domains. If the training simulation does not include a material property (like extreme slipperiness), the strategy predictor may choose the wrong approach. For example, if all training cloth was slightly sticky, it might recommend a peel strategy that works only if the cloth holds position.
Primitive composition breaks on rare shapes. The execution module chains primitives in order. If an unseen cloth shape requires primitives in an order never seen in simulation, the composed trajectory may be unstable or miss the goal.
Contrastive learning collapses on too-similar training data. If most training configurations cluster into one strategy type, the contrastive loss may not learn fine-grained distinctions. The network treats all shapes as the same strategy and performs poorly on the rare strategy type.
Done right. The paper mitigates these by training on a diverse simulated dataset with multiple materials, strategies, and edge cases; validating strategies with real-robot trials; and using the FlatLab benchmark to identify failure modes before deployment.
What a runnable demo should prove

What a runnable demo should prove

Build a minimal version: a small point-cloud classifier that predicts one of three strategies (peel, roll, unfold) given a simple cloth shape (represented as a 3D mesh or sampled points). Generate 100 training configurations with labels (strategy), train a contrastive encoder + strategy head on them. Then test on 20 new cloth shapes with different material properties (e.g., slightly different bending stiffness in simulation). The demo should show that the trained model predicts the correct strategy on at least 75% of new shapes, while a naive baseline (one hard-coded strategy for all shapes) drops to 40%.

generalization_success = (correct_strategy_predictions_on_new_shapes) / (total_new_shapes)

The demo succeeds when it predicts the right strategy on a cloth shape with a material property not present in training — this proves the learned representation captures strategy-relevance, not object identity.
