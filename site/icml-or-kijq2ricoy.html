KUMA: Koopman Separation and Multilevel Extraction for Time Series

Split the hidden flow in time series into two simple pieces, then use a smart tower of filters to pick the right tokens for each level.

Paper explainersAll themesTime Series & Sequential

Time series (like stock prices or sensor readings) are messy: they have changing patterns over time, too many numbers to process efficiently, and lots of wasted information. KUMA untangles this by splitting the flow into two kinds of change — one smooth and predictable (the Koopman part) and one grainy and random (the leftover) — then builds a tower of filters to pick which numbers actually matter at each layer.

Three traps in time series forecasting

Today's time series forecasters face three hard problems. First, they choke on computational cost: the longer the history and the more dimensions (like tracking ten sensors at once), the heavier the math becomes. Second, the tokens (the individual numbers in the series) are not equally useful: some carry real signal, others are just noise or repeat what you already know. Third, the pattern itself shifts over time — yesterday's drift is not today's drift, so a model trained on old data stumbles when the world changes.

A beginner might try to just throw more layers at it: use a bigger model, feed in more history, hope the learning figures it out. This breaks because (1) the cost explodes, (2) the model drowns in garbage tokens, and (3) non-stationary dynamics (when the rules change mid-series) confuse the model into learning brittle patterns that don't generalize.

The core idea in one sentence. Separate the series into two parts: a smooth predictable flow and a grainy residual, then build a multi-layer tower that picks the right numbers for each layer and focuses on the ones that matter.

What the paper changes

What the paper changes

KUMA changes which tokens survive the journey from input to output. It does not invent new tokens or change how tokens are learned — instead, it builds an input-dependent gate: the Koopman module learns, for the current series, which dimensions carry true pattern and which are noise, then the UMA tower explicitly drops redundant tokens at each layer.

the object it moves  =  tokens (which numbers stay, which drop)
The hidden quantity

The Token Importance Score

measured quantity  =  Token importance: which tokens actually matter for this forecast

KUMA measures an invisible quantity: how much does each token contribute to the final forecast? Some tokens are signal, some are noise, and some are repetitive. A token with high importance means the series cannot predict the future without it. A low-importance token is either garbage or redundant with other tokens.

The paper estimates this via two routes. First, the Koopman module infers which dimensions contain true dynamics (Koopman part) versus leftover (residual) — this gives an input-dependent importance mask. Second, the UMA tower applies element-wise scoring (a learned number between 0 and 1 for each number, which works quickly because it is independent: each number gets one score, no pairing) and linear scoring (which measures influence using simpler math than full cross-pairing, so it runs faster as the layer grows). The higher the score, the more that number influences the forecast.

Why it works

How Koopman separation and multilevel filtering work together

Here is the causal chain. Time series are often non-stationary (the rules change), so a single fixed model struggles. KUMA splits the problem: the Koopman module learns a decomposition specific to the current input, separating slow, smooth, predictable change (Koopman dynamics) from fast, grainy, unpredictable residuals. This split is learned, not hand-coded — it adapts to the data.

Once split, the UMA tower builds a sequence of layers (encoder side) that progressively filter numbers. At the bottom, all numbers arrive; at each layer, element-wise scoring (a learned score for each number) selects which ones pass upward. Additionally, linear scoring (a simpler way to compute importance that avoids slowing down as layer size grows) scores which sequences within each layer matter most without recalculating everything. The result: redundant and noisy numbers drop out, leaving only the signal. This two-pronged approach — splitting the series to reduce non-stationary confusion, and filtering numbers to kill redundancy — cuts computational cost because fewer numbers flow through higher layers, while preserving the true patterns because the filters learned what matters.

Why this works: by separating Koopman-stable from residual-volatile parts, the model sees a cleaner signal, so non-stationarity (when the pattern's rules shift over time) worries it less because the stable part remains stable. By filtering numbers multilevel, the model avoids computing expensive pair-wise scores over all numbers at every layer — it only focuses on the ones that passed the filter, which means fewer pairs to score at higher layers, so the time and memory shrink. The net effect is lower computational cost (fewer expensive operations), better number usage (only the useful ones stay), and more reliable forecasts because the model learns from pure signal without drowning in noise — when training sees only the true patterns without garbage, it converges to a simpler rule that generalizes better.

The decomposition and filtering formula

First in words:

The Koopman module splits the series into two parts. UMA then applies element-wise attention weights to each token and downsamples high-layer tokens by score. The overall loss combines forecast error with a small penalty on the importance scores to encourage sparsity.

Then the compact form:

x_t = K(x_t) + R(x_t); y_pred = Decoder( UMA( Encoder(K, R) ) ); loss = MSE(y_pred, y_true) + lambda * sum_i (1 - a_i)^2

Every symbol:

x_tthe input time series at step t
K(x_t)the Koopman part: smooth, predictable dynamics for this input
R(x_t)the residual part: grainy, hard-to-predict leftover
a_ithe attention weight (between 0 and 1) for token i
lambdaa small number controlling how aggressively we drop tokens
MSE(y_pred, y_true)the forecast error: how far off the prediction is
A tiny worked example
Input series has 10 tokens initially. Koopman identifies 8 as Koopman-stable, 2 as residual-volatile.
Layer 1 attention scores: [0.95, 0.92, 0.88, 0.15, 0.10, 0.89, 0.91, 0.12, 0.93, 0.14]
Layer 1 keeps tokens with score > 0.5: 7 tokens remain, 3 dropped. Cost saved = ~30% of base attention cost.
Layer 2: keeps top 4 most important tokens from the 7. Final layer forecasts using only 4 tokens.
Forecast error: 0.18 (same accuracy as keeping all 10), but 60% faster compute.

The decomposition into K and R makes the series less non-stationary (smoother), so attention and linear layers see clearer patterns. Token dropout via attention weights makes each layer leaner.

What can go wrong

What can go wrong

Decomposition fails if the series is truly random. If the series has no Koopman-stable structure (all residual), the decomposition learns nothing, and UMA has no strong tokens to keep. KUMA degrades to a standard model.
Over-filtering drops signal. If the lambda penalty on importance scores is too high, UMA filters away tokens that look low-value in isolation but contain long-range dependencies. The forecast breaks.
Non-stationary dynamics still confuse learning. The Koopman decomposition is learned fresh for each input, which is good; but if the non-stationarity is extreme (the rules change mid-batch), even the smooth part can shift, and forecasts suffer.
Done right: tune lambda, validate on held-out non-stationary windows. Use cross-validation to find lambda that drops junk but keeps signal. Test on data where the pattern shifts mid-series to ensure the decomposition adapts.
What a runnable demo should prove

What a runnable demo should prove

Build a minimal version: (1) Take a real multivariate time series with known non-stationarity (e.g., energy consumption that changes seasonally, or a financial series with regime shifts). (2) Train a baseline model (a standard sequence model on all numbers) and measure forecast error, numbers per step, and wall-clock time. (3) Implement the Koopman decomposition as a trainable linear layer that learns to separate smooth and residual parts. (4) Add UMA as a simple two-layer tower: bottom keeps all numbers, top keeps the top-50% by importance score. (5) Compare: does the KUMA version forecast as well or better because the decomposition removes non-stationary noise, and does it run faster because filtering numbers reduces the pairs that need scoring?

improvement = (baseline_error - kuma_error) / baseline_error; speedup = baseline_time / kuma_time; token_efficiency = (baseline_tokens - kuma_tokens) / baseline_tokens

The demo should make it impossible to miss that separating the series into stable and residual parts, combined with token filtering, reduces computational cost without sacrificing forecast accuracy — and sometimes even improves accuracy because the model is less confused by non-stationary noise.
