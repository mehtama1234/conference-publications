SLM-MUX: Orchestrating Small Language Models for Reasoning

Instead of using one large language model, run several smaller ones in parallel and pick the one most confident in its answer.

Paper explainersAll themesOther

Small language models are fast and cheap, but each one is weak at reasoning tasks. This paper shows how to combine several weak models into a strong system: run them all on the same question, measure how confident each one is in its answer, and trust the one with the highest confidence. Two small models working together this way outperform a single model 7 times their size, because different models trained differently excel at different tasks, and confidence routing automatically picks whichever model learned the relevant skill.

Zero assumption version

One model, one answer, often wrong

A small language model is a neural network trained to predict the next word. It is fast and fits on cheap hardware. But on hard reasoning questions like algebra problems or science trivia, small models make mistakes often enough that you cannot rely on them.

A beginner's fix is obvious: use a bigger model. But that costs more money and time. The real question: do we have to? What if we already have several small models?

The idea in one sentence. Run the question through multiple small models. Measure how confident each model is. Pick the answer from the most confident model.

The algorithm as a flow

What it actually does

Collect models

Gather several small language models (each is trained to answer questions).

Run question on all

Feed the same question to every model at once (they run in parallel).

Measure confidence

Each model produces its answer plus a confidence score (how sure it is).

Select by confidence

Simple rule: pick the answer from the model with the highest confidence.

Return the answer

The system outputs that one answer to the user.

What the paper changes

The thing that changes

The paper changes which model's answer gets returned. Instead of always using the same model, the system dynamically picks the most confident model on each question. The selection happens at test time (when answering), not during training.

the object it moves  =  model selection by confidence
The hidden quantity

Confidence score: how sure is each model?

measured quantity  =  Model confidence

Confidence is a number measuring how certain a model is in its answer. When a language model answers a question, it generates words one by one and assigns a probability (a fraction from 0 to 1) to each word choice. High probability means the model thought that word was the obvious next step. Low probability means it was unsure. The paper adds up the probabilities of all the words in a model's answer to get one overall confidence score for the full answer.

The paper uses this confidence score to decide which model to trust. If Model A's confidence is 0.92 and Model B's is 0.65, Model A's answer is used. The system does not need to know if Model A is actually right; it just trusts that when a model feels most certain, it is more likely to be correct.

Paper reading. The paper computes confidence as the product (or sum of logarithms) of word-level probabilities. It is a standard measure in language modeling of how well the model's predicted probabilities (the pattern of which words it thought likely) match the answer it actually gave.
Why it works

Why confidence-based selection works

The mechanism rests on a simple observation: when a language model is confident, it is usually right, and when it is unsure, it is often wrong. Why? A language model is trained to predict the next word given the previous context. During training, it learns patterns: certain word sequences are nearly always correct in certain situations, and it learns to output high probability for those sequences. Other sequences are rare or wrong, and it learns low probability for them. So confidence and correctness tend to align.

By running multiple models and picking the most confident one, the system exploits their differences. Model A might be trained on code, so it is very sure on a programming question and unsure on a history question. Model B might be trained on general knowledge, so it is very sure on history. The system automatically picks whichever model trained on the relevant knowledge, because that model will feel more sure. No need to tell the system in advance which model is good at what; the confidence scores reveal it. If all models are unsure, the system picks the best guess (the most confident of the unsure). This is still better than randomly failing, because even an unsure guess from a model is based on patterns it learned during training; a model at 40 percent confidence made an educated guess, not a random one.

The confidence formula

First in words:

Total confidence equals the sum of the logarithms of the probability the model assigned to each word in its answer. Or equivalently, confidence is the product of those probabilities.

Then the compact form:

confidence = sum_i log(P(word_i | context)) = log(product_i P(word_i | context))

Every symbol:

P(word_i | context)The probability the model assigns to word i, given the words before it
sum_iAdd up this quantity for every word in the answer
log(...)Take the natural logarithm (base e)
confidenceThe final score for the whole answer
A tiny worked example
Suppose a model answers the question 'What is 2+2?' with the answer 'four'.
Word 1 (four): model assigns probability 0.95. Log(0.95) = -0.051.
If the answer is just one word, confidence = -0.051.
Now suppose the answer is 'The answer is four': Word 1 (The): prob 0.98, log = -0.020. Word 2 (answer): prob 0.89, log = -0.117. Word 3 (is): prob 0.97, log = -0.031. Word 4 (four): prob 0.95, log = -0.051.
Confidence = -0.020 + (-0.117) + (-0.031) + (-0.051) = -0.219.
A shorter, more confident answer has a higher (less negative) score: -0.051 beats -0.219. The model's intuition is encoded in which words it chose.

The logarithm turns multiplication into addition, making the score easier to compute. Higher confidence (less negative) means the model thought every word it chose was very likely.

What can go wrong

What can go wrong

All models are confidently wrong. If every model makes the same mistake but with high confidence (e.g. all have learned the same incorrect pattern from training data), the system will return the wrong answer with high confidence. The user gets no warning.
Models are trained on the same data and make the same errors. If all models were trained identically or on overlapping data, they will tend to fail on the same cases. Confidence routing does not help when all models are wrong together, because they will all be confidently wrong (confidence was learned on the same data). The system needs models trained differently (different data, architectures, or initialization) to ensure they fail on different cases, so their confidence scores point to different answers.
Confidence does not match correctness. Some language models can be confidently wrong (they have not learned to express genuine uncertainty). For instance, a model trained to sound authoritative will output high probability for plausible-sounding but false answers. Confidence is a proxy, not a guarantee.
Diversity matters. The system works best when the models in the pool are trained differently and excel at different things. If they are similar or overlapping, the gains are smaller. Selecting a diverse set of models (trained on different corpora, with different architectures) is key to the method.
What a runnable demo should prove

What a runnable demo should prove

Build a simple test: collect three or four small language models trained on different data (e.g., one fine-tuned for mathematics, one for general knowledge, one for coding). Write a small set of reasoning questions (maybe 20 examples from MATH, GSM8K, or GPQA benchmarks). For each question, run all models and collect their answers plus confidence scores. Then compare: (1) accuracy if you always use the model trained for the current task (oracle, best case), (2) accuracy if you always use the single most capable model, (3) accuracy using SLM-MUX (highest confidence wins). The demo should show that SLM-MUX falls between the oracle and the single best model, outperforming always picking one model.

Accuracy = (number of questions where the highest-confidence model's answer was correct) divided by (total number of questions)

The demo proves that confidence is a good proxy for correctness across different model types (because models trained differently on different data learn different notions of confidence aligned with their training), and that routing by confidence is simpler than discussion-based methods (no back-and-forth conversation needed) while being faster (one pass through each model, not iterative) and more accurate than using one model alone (diversity of trained skills covers more cases).
