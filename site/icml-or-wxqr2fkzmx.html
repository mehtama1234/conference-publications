Building Social World Model with Large Language Models

Model how public beliefs change after events by learning state transitions from time-stamped social signals.

Paper explainersAll themesAgents & Tool Use

People do not hold fixed beliefs about elections, policy, or markets. Their beliefs shift after debates, court rulings, scandals, and new evidence. This paper asks whether a language-model-based system can learn those shifts as a world model for social belief change. The goal is not only to predict the next belief state, but also to describe why the change happened in terms of event-driven state transitions.

Zero assumption version

Why social belief forecasting is hard

Forecasting a physical process is easier when the hidden state has direct measurements. Social belief is different because what people think is only partly visible. We may observe prices in prediction markets, headlines, and event times, but the underlying belief state must be inferred indirectly.

That makes social forecasting hard in two ways. The system must estimate the current belief state from partial evidence, and it must learn how major events move that state over time. The paper builds a Social World Model to handle both pieces together.

The paper's move in one sentence. Treat collective belief as a hidden state that changes after events, then learn the transition from observed time-stamped social data.

What the paper changes

The paper changes the target of prediction. Instead of forecasting observed prices directly, it inserts a hidden belief state and learns how events push that state from one step to the next.

The hidden quantity

The hidden quantity

measured quantity  =  Current collective belief state

This hidden state is the paper's core quantity. It stands for what the crowd currently believes before the next event arrives, even though that belief cannot be read off perfectly from any single observed signal.

The model infers the hidden state from noisy observations and then updates it after each event. That matters because price movements are often only a surface trace of deeper belief change.

Why it works

Why this works

Adding a hidden belief state helps because it separates observation noise from belief dynamics. A price can move for several short-term reasons, but the underlying belief update may be smoother or more interpretable. By estimating the hidden state first, the model can learn a clearer transition rule for how events change beliefs.

Event conditioning matters because not all time steps are alike. A routine day and a debate night should not produce the same update behavior. The model performs better when the transition is tied to the event context, because that context explains why one observation sequence should lead to a sharp shift while another should barely move the belief state.

Math after the picture

The state-transition view

First in words:

The next belief state comes from the current belief state plus the effect of the current event, and observations are generated from that updated state.

Then the compact form:

belief_t+1 = transition(belief_t, event_t) ; observation_t = readout(belief_t)

Every symbol:

belief_tthe hidden collective belief state at time t
event_tthe event information available at time t, such as a debate or policy announcement
transition(...)the learned update rule that maps the current belief state and event into the next belief state
belief_t+1the belief state after the event-driven update
observation_tthe visible signal at time t, such as a market probability or related social measurement
readout(...)the mapping from hidden belief state to observed signal
A tiny worked example
Suppose the current market suggests a candidate win chance near 0.54, so belief_t is centered around 54%.
A strong debate performance occurs at time t.
The learned transition says this type of event usually shifts belief upward by 0.08 when the race is close.
Then belief_t+1 becomes about 0.62.
The readout step predicts that observed market prices should also rise toward 62%, though not necessarily exactly because prices are noisy.

The paper trains this hidden-state model from observed sequences rather than from direct labels of belief shifts.

What can go wrong

What can go wrong

Ambiguous event effect. A single event can push different groups in different directions, so one shared belief update may miss important structure.
Observation noise. Prediction markets and related social signals can be noisy or thinly traded, so the inferred belief state can drift when the visible signal is unstable.
Missing context. A forecast can fail when the event record omits background conditions, because the same headline can move beliefs differently in different contexts.
Done right. Use dense time-stamped observations, align events carefully, and evaluate both predictive fit and the plausibility of the inferred belief shifts.
What a runnable demo should prove

What a runnable demo should prove

Build a small benchmark around one domain such as election markets. Use a sequence of daily market prices and a matching sequence of major events. Then compare a direct next-step forecaster against a simple hidden-state model that updates belief after each event.

The demo should show that the hidden-state model predicts belief swings more accurately around important events because it represents the event-driven transition explicitly instead of treating every day as the same kind of step.

forecast_error = average absolute difference between predicted and observed market value ; event_window_error = same error measured only near major events

If the hidden-state model reduces error around major event windows, it is demonstrating the paper's main advantage.
