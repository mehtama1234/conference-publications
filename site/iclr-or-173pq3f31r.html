Bridging Piano Transcription and Rendering via Disentangled Score Content and Style

A single model that both writes sheet music from a piano recording and plays sheet music expressively, by learning to split the two tasks' hidden patterns from one another.

Paper explainersAll themesGenerative Models & Diffusion

Piano playing and piano writing are opposites: one turns feelings and choices into keys pressed, the other reverses it — recovers the written notes from keys pressed. This paper builds a single machine that does both, by learning to separate what is always written (the note sequence) from what changes between performers (the expressive style). A bonus diffusion-based module (diffusion is a way to draw random samples that match a pattern) then suggests fitting expressive styles just from looking at the sheet music, so a shy beginner can sound polished.

Zero assumption version

Two separate tasks, two separate machines

Today, when you need a computer to listen to a piano recording and write down the notes (called transcription), you train one machine. When you need a machine to read sheet music and add expressive timing and loudness (called rendering), you train a completely different machine. They never talk to each other.

A beginner approach would be to build these machines independently: transcribe in one pipeline, render in another. This breaks because the transcription machine cannot benefit from knowing that sheet music and performances are two sides of one coin. If the transcription machine saw examples where rendering machines had failed (bad timing destroyed the original intent), it might learn to be more careful. But it does not. The rendering machine also works blind: it does not know which note sequences are easier or harder to perform expressively.

The paper notes that both tasks need to learn the same core fact: what is the note sequence underneath, and what is the personal style on top. If you split these two once, both tasks can share that learning.

In one sentence. Train one shared machine on both tasks at once, and it learns to automatically separate the written notes from the performer's choices, so each task improves the other.

The algorithm as a flow

What it actually does

Take both tasks at once

Feed in paired data: a sheet music file and a recording of it played expressively.

Encode into three pieces

Three separate neural networks (transformers — machines that look at long sequences) read the sheet and the recording, each pulling out one layer: note content, performer style, and cross-checks.

Force the split

Regularization (mathematical gentle steering) pushes the style space toward a standard bell curve shape, so it only holds expressive choices, not note secrets.

Decode both ways

Two separate decoders: one writes sheet music from the content; one generates a performance from content plus style.

Train a style recommender

A diffusion model learns to generate plausible expressive styles just from the note content, so new recordings can sound polished without a human picker.

What the paper changes

What changes: the latent representations

The paper changes three hidden vectors (latent representations — lists of numbers that carry meaning). In a normal machine, one list tries to hold everything: notes, style, timing, everything tangled. Here, the model is forced to split into three: one for note identity (what notes are played), one for global expressive style (tempo, dynamics, pedal choices), and one for bridging information.

the object it moves  =  three disentangled hidden vectors
The hidden quantity

The hidden quantity: disentanglement

measured quantity  =  Content-style separation

Disentanglement means that two ideas are pulled apart into separate slots instead of tangled together. In a typical model, the hidden numbers might encode both the note C-sharp and the performer's sudden loudness at that moment — intertwined. Here, one slot holds note identity (sheet music content), and a different slot holds the expressive choices (tempo, dynamics, rubato — small timing shifts).

The paper estimates disentanglement in two ways. During training, it uses a KL regularization loss (KL is a distance metric — a way to measure how far apart two patterns are) that pushes the style vector toward a standard bell curve shape (with most values clustered near zero and few at the edges), ensuring it stays clean. During evaluation, it visualizes the learned spaces and shows that rendering tasks only need the style slot while transcription only uses the content slot, proving they separated.

Why it works

Why it works: symmetric pressure and shared backbone

The mechanism has two parts. First, transcription and rendering are exact opposites — if you transcribe a performance, you should recover the original sheet music, and if you render that recovered sheet, you should get back something like the original performance. The paper trains both directions at once, so whenever the note encoder makes a mistake, both tasks suffer. This shared pressure forces the content slot to learn only the reliable, objective facts (the note sequence) and dump everything else into the style slot.

Second, both tasks share the same starting layers (the encoders). The content encoder is forced to work for both transcription and rendering, so it learns only what matters for both: the notes themselves. The style encoder is never used in transcription (only in rendering), so it naturally captures everything that transcription does not need. A KL penalty then keeps the style vector from sneaking in any note information. By construction, content and style cannot hide in each other.

Math after the picture

The training objective: three losses, one penalty

First in words:

Total loss equals transcription error plus rendering error plus reconstruction of masked notes plus a penalty that forces the style vector into a standard bell curve shape

Then the compact form:

L_total = L_APT + L_EPR + (L_rec,X + L_rec,Y) + lambda * D_KL(q(z_s|y) || N(0,I))

Every symbol:

L_APTerror when transcribing (comparing predicted sheet to ground truth sheet)
L_EPRerror when rendering (comparing predicted performance to ground truth performance)
L_rec,Xerror when reconstructing sheet music from masked input
L_rec,Yerror when reconstructing performance from masked input
D_KLKL divergence, a distance between two probability patterns
q(z_s|y)the learned pattern of style vectors from performances
N(0,I)a standard bell curve centered at zero
lambdahow strongly to enforce the style penalty (a tuning knob)
Tiny worked example with four batches
Suppose a batch has one performance of a scale (C D E F G). The transcription loss checks: predicted score = C D E F G, truth = C D E F G, error = 0.2.
Rendering loss checks: predicted performance style uses only the learned style vector, truth is the actual recording, error = 0.5.
Masked reconstruction loss: hide half the notes, predict them back, error = 0.3.
KL penalty: style vector should look like a bell curve, but it drifts slightly; penalty = 0.1.
Total = 0.2 + 0.5 + 0.3 + 1.0 * 0.1 = 1.1. If we increase lambda to 2.0, the KL term doubles to 0.2, so total = 1.2 — the model learns to obey the bell curve rule more strictly.

The KL term is the key: it prevents style from encoding note information by forcing it into a shape that only holds continuous, smooth patterns (like tempo changes), not discrete facts (like which note is next).

What can go wrong

What can go wrong

Style sneaks back into content. If the KL penalty (lambda) is too weak, the style encoder can encode note information as well as the content encoder, defeating the split. The model stops feeling the pressure to disentangle.
Generalization breaks on new performers. If the content encoder learns the shared pressure too narrowly (e.g., it memorizes which notes appear in the training performers only), it fails on new performers because it has learned performer-specific patterns instead of universal note patterns. Disentanglement helps here: if a new performer plays a familiar piece differently, the content slot recognizes the note sequence (because it was trained to extract notes from both performances and transcriptions), and the style slot handles the new expressive choices, so the model can adapt to unfamiliar performers.
Diffusion style recommender hallucinates. The diffusion module generates style embeddings from score content alone. If the training data was biased (e.g., always slow pieces played slowly), the diffusion module may recommend only slow tempos for all slow scores, even if a piece could be played faster, because it learned a false correlation between slow note patterns and slow tempos. Diversity in training data and sampling (drawing random samples instead of always picking the most likely one) help here because varied pairings break false correlations and sampling explores the full learned range instead of always picking the single most probable style.
Done right. Strong KL regularization keeps content clean because it forces the style vector away from any note-like patterns. Diverse paired and unpaired training data helps the content encoder handle new performers because it exposes the encoder to many different ways performers can play the same notes, forcing it to extract only the invariant note sequence. Separate evaluation of transcription vs. rendering confirms the split actually works because if content and style were tangled, both tasks would fail on unseen performers.
What a runnable demo should prove

What a runnable demo should prove

Build a simple pipeline: (1) load a piano MIDI file (symbolic music notation); (2) use the trained model to extract its content and style embeddings; (3) swap the style with a different recorded performance's style; (4) render both the original and style-swapped versions as audio; (5) listen side by side. The point is to prove that style is truly independent: swapping only style should preserve the note sequence but change the expressive character (tempo, dynamics). Then, (6) use the diffusion style recommender to generate a style embedding from the score alone, without a reference performance, and render the result. A good demo will show that the generated style is coherent and fitting, not random.

style_transfer_fidelity = (similarity of swapped and reference performance) - (similarity of original and reference) should be high; content_preservation = (alignment of note sequence before and after) should stay near 0.95 or higher

If you swap the expressive style and the notes stay recognizable, disentanglement is real. If you generate style from score alone and it sounds polished, the diffusion module works.
