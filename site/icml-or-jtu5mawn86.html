Platonic Transformers: Geometric Symmetry Without Extra Cost

A transformer that naturally respects geometric symmetries by building attention around reference frames from platonic solids, gaining equivariance for free.

Paper explainersAll themesGraph & Geometric Learning

Transformers (a type of neural network model that works by comparing every piece of input to every other piece) excel at many tasks, but they treat all directions in space the same way. In physics, molecular structure, and computer vision, certain symmetries are built into the problem itself — rotating an object should give the same answer, flipping it should too. This paper redesigns how the transformer compares positions (a process called attention, which scores how relevant each position is to each other position) to respect these symmetries natively, without slowing it down.

Why Transformers Ignore Symmetry

A standard transformer treats every spatial location or direction as independent. When you rotate a 3D object or flip a molecule, the pixel values shift, but the transformer has no built-in way to know that the object itself is unchanged. It learns to handle rotations only through brute-force: seeing many rotated examples in training and memorizing that they mean the same thing.

Existing methods that bake in symmetry constraints do work, but they require hand-crafted network designs, extra computation, and careful engineering. They trade speed and flexibility for correctness.

The gap. How do you build a transformer that respects symmetries — rotation, reflection — without adding cost?

Compute where each point sits relative to these anchors, not raw coordinates.

What the paper changes

What the paper changes

The paper changes how the transformer measures and weights positions in space. Instead of storing raw coordinates, it computes positions relative to a fixed reference frame — the vertices of a Platonic solid (like the corners of a cube or octahedron).

the object it moves  =  position measurement rule
The hidden quantity

Symmetry Alignment

measured quantity  =  how much the output rotates with the input

A key quantity is how well the model's predictions respect rotations and reflections. If you rotate the input by 90 degrees, does the output rotate the same way, or do you get a completely different answer? A model with perfect symmetry alignment will rotate its answer by exactly 90 degrees. A model without this property will give a random new answer.

The paper measures this alignment implicitly through the model's ability to learn shared weights across symmetric positions. By anchoring attention to Platonic solid vertices, symmetric positions automatically get treated identically, enforcing alignment without explicit measurement.

Why it works

Why Anchoring to Reference Frames Works

The mechanism works because symmetries in Platonic solids are rigid and mathematical. A cube has 8 corners. If you rotate a cube, corners map to corners in a predictable way — corner 1 always goes to corner 3, 5, or 7 depending on the rotation. By building attention around these 8 corners as reference points, the model automatically sees the symmetry.

When the transformer computes attention, it asks: how important is position A to position B? But instead of measuring the raw distance in pixels or coordinates, it measures: how important is corner-A-relative to corner-B-relative? Two physical positions that are symmetric under the cube's transformations will always have the same corner-relative positions — because the anchors themselves are symmetric, and relative position to symmetric anchors must be symmetric. So the model naturally treats them identically, because they produce identical numerical inputs to the attention computation. This is equivalent to saying the model applies the same learned filter weights to symmetric position pairs — a shared weight scheme emerges automatically, since identical inputs must produce identical outputs.

Why does this cost nothing? Because the Platonic solid only has 4, 6, 8, 12, or 20 vertices — small fixed numbers. The reference frame is pre-computed, not learned. The attention mechanism is unmodified; it just compares to these anchors instead of raw space. The model gets rotational correctness for the cost of a change in how coordinates are described, not a change in the model's computation.

Attention With Symmetry Anchors

First in words:

For each query position, sum weighted attention contributions from all key positions. The weight depends on the query's and key's positions relative to Platonic reference frames. Positions that are symmetric under Platonic transformations contribute with the same learned weight.

Then the compact form:

attention(q, k) = softmax( (q_anchor · k_anchor) / sqrt(d) ) where q_anchor and k_anchor are positions relative to Platonic solid vertices, and symmetric position pairs share learned weight matrices.

Every symbol:

k_anchorkey position measured relative to Platonic solid vertices
·dot product (multiply the numbers element-wise and sum)
sqrt(d)square root of the number of features, used to scale the scores
softmax(...)turn scores into a probability (numbers between 0 and 1 that add to 100%)

Query at cube corner 0, key at cube corner 3: learned weight W_0_3 applied.
Query at cube corner 0, rotated to corner 5: the model computes position relative to anchors, finds it is still in a symmetric relationship to the query.
Query at corner 0, key at corner 5: learned weight W_0_5 applied.
Because corners 3 and 5 are both rotations of the same edge-type, W_0_3 and W_0_5 naturally become nearly identical in training.
A query at a unique non-corner location (fractional position between corners) uses the learned anchor weights, still enforcing symmetry through how the anchors relate to each other.

The anchor-relative coordinates embed symmetry into the coordinate system itself; standard attention then preserves it automatically.

What can go wrong

What can go wrong

Wrong symmetry group chosen. If you apply a cube's symmetries to a task with tetrahedral (4-fold) symmetry, the model enforces the wrong constraints. The paper chooses Platonic solids to cover most common cases, but some problems have no Platonic match.
Continuous symmetries harder than discrete. Platonic solids capture discrete symmetries (rotation by 90, 120 degrees). Continuous rotations (by any angle) are not perfectly handled; approximation error grows at large angles.
High-dimensional spaces need new reference frames. Platonic solids live naturally in 3D. In higher dimensions or curved spaces, defining the reference frame becomes unclear.
Done right: select the task's natural symmetry group, use a Platonic solid that matches, and check rotations preserve the output. A well-chosen reference frame plus no learned overhead equals free rotational correctness.
What a runnable demo should prove

What a runnable demo should prove

Build a small 3D point-cloud classifier (or molecule property model) using a Platonic Transformer. Train it on a dataset with some rotated examples. Then: (1) test on a new example, note the prediction; (2) rotate the input by a fixed angle (e.g., 90 degrees), run the model again. The output should rotate by the same angle.

equivariance_error = mean over rotations of |predicted_rotated_output - rotate(predicted_original_output)| / mean(|predicted_original_output|)

A standard transformer will show large equivariance error (rotating the input gives a wildly different answer). The Platonic Transformer should show near-zero error — the output rotates with the input, proving the symmetry is built in.
