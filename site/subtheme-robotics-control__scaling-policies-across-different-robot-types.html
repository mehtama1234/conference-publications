Scaling policies across different robot types

Papers addressing how to train robot policies that work across many different robot morphologies and embodiments—leveraging shared visual understanding to reduce retraining.

All themesField mapMathematicsAll explainers
What this is

A robot policy trained on one robot often does not work on another robot, even if they do the same task. A policy trained on one robot arm might not work on a different arm with different proportions or motor speeds. This is a huge practical problem because training a new policy for each new robot is expensive. Ideally, a policy trained on one robot, or on many robots collectively, would transfer to a new robot with minimal additional training. This would let researchers and companies scale: design a robot once, train a policy on a fleet of robots, and deploy to a new variant without retraining from scratch.

The challenge is that robots have different embodiments—different shapes, sizes, sensor suites, and motor capabilities. A robot with a long arm reaches differently than one with a short arm. A robot with high-precision motors behaves differently than one with imprecise actuators. The challenge is to learn policies that are abstract enough to work across embodiments but concrete enough to be actually useful. Some researchers focus on learning what matters for the task—a good gripper pose for grasping does not depend on arm length, just on object position and orientation. Others try to learn representations that are invariant to embodiment: the robot learns to extract features from images that do not depend on its own morphology. If the visual understanding is good enough, different bodies can all benefit from it.

Papers tackle embodiment transfer through several approaches. Some use visual-based policies exclusively—the robot sees the scene and learns to predict actions, and the visual understanding transfers across robots. Some learn a shared representation: train on multiple robots, extract features that all of them find useful, and build policies on top of that. Some use simulation: train on a diverse set of simulated robots, each with different properties, so the policy learns to work across different embodiments and shapes. Others use adaptation: train a base policy on a diverse robot fleet, then quickly fine-tune it to a specific new robot with a small amount of real data. The throughline is the same: visual and physical understanding can be separated and reused, so you do not have to retrain from scratch for each new body.

How the work breaks down

Scaling robot policies across different bodies breaks into four core directions: learning shared visual representations that ignore which robot is moving, co-designing the robot body and controller together to reduce transfer friction, building from raw digital data that contains the visual patterns robots need, and learning compact action spaces that translate between different morphologies. Each approach tackles a different aspect of the same problem: how to avoid retraining a policy from scratch for every new robot shape or size.

Learning shared visual understanding

The core insight here is that a camera sees the task the same way regardless of which robot is executing it. A gripper moving toward an object looks similar in the image whether the robot arm is long or short. This approach learns policies by training on visual input — the robot reads camera images to understand what needs to happen. Because the policy never directly codes its own morphology, different robots with different sizes and speeds can all use the same trained policy.

The D2E paper starts by asking: can we train a policy on boring digital data first, before touching a real robot? They collected video of human hands and simple computer animations performing manipulation and navigation tasks. They trained a policy to predict actions from video using only this digital data, which is cheap to gather at scale. Then they tested it on real manipulation and navigation robots. The surprising result is that the visual patterns learned from digital interactions transferred directly to physical robots — they got 96.6% success on manipulation tasks and 83.3% on navigation. This works because visual understanding is generic: 'gripper closing on object' looks similar in animation and in reality.

The Cross-Embodiment World Models paper takes a different angle: build a foundation model by training across many robots at once. They train one model on trajectories from different robot types, and the model learns to predict what happens next in the world in a latent space (an abstract mathematical space) with compact action codes that aren't tied to any specific robot. Using a latent action space instead of explicit motor commands lets the model extract what matters about robot behavior regardless of embodiment. When they tested this on downstream tasks, performance improved when they trained on more pretraining robots. More diversity in training meant the model had seen more robot shapes, so it learned shared visual patterns rather than memorizing a specific robot's way of moving. This shows that visual understanding truly decouples from robot shape: one foundation model can serve many bodies.

Co-designing robot bodies and policies

One radical approach is to not treat the robot design as fixed. Instead, co-optimize the robot's shape and the control policy at the same time. This avoids the costly back-and-forth: design a body, train a policy, discover the design is suboptimal, redesign, retrain. But co-optimization faces a hard problem: it tends to produce one very optimized design and loses the ability to generalize to other shapes. Standard evolution discovers a narrow winner.

Accelerated co-design uses morphological pretraining to fix this. The idea is to first train a controller on a diverse set of robot morphologies in simulation. This pretrained controller has learned patterns that work across different body shapes. Then, when you run evolution to co-design a new robot, you start the controller from this pretrained checkpoint instead of random initialization. The result is striking: zero-shot evolution (no fine-tuning the policy on the new design) produces diverse, high-performing designs. Standard co-optimization gets stuck finding one narrow optimum, but pretrained evolution explores the space and finds many equally good designs, because the pretrained controller can adapt to many shapes. Fine-tuning the pretrained policy on the evolved design pushes performance even higher. This demonstrates that a controller trained on morphological diversity is a better starting point for evolving new bodies, because it has already learned how to adapt to shape changes.

Generalization across real robot embodiments

Moving from simulation to real robots, the question becomes: can a single policy walk across robots of completely different shapes and sizes? Humanoid robots come in many variants — different heights, different weight spread across the body, different actuator speeds. A policy trained on one humanoid often fails on another because the mapping from actions to motion changes with body dimensions.

Scalable and General Whole-Body Control tackles this by training one policy on twelve simulated humanoids with different morphologies, then testing it on seven different real-world humanoids it has never seen. The policy achieves zero-shot transfer — no fine-tuning on the new real robot — while maintaining stable locomotion. The training exposes the policy to many different shapes: by seeing diverse morphologies during training, the controller learns locomotion principles that work across different bodies, because it has learned which aspects of locomotion matter regardless of size. The real robots have different leg lengths, weight, and actuator properties, yet the single policy transfers directly. This is the gold standard for embodiment transfer: one controller, tested on physically embodied robots it never trained on, still executes the task successfully.

Augmentation and scaling of training data

Even the best pretrained policy needs data to adapt to a new robot. The problem is that collecting real robot data is slow and expensive. One way to reduce the fine-tuning burden is to augment the training dataset: synthetically transform existing trajectories to create diverse variants that simulate what different robots would do on the same task.

OXE-AugE takes the large OXE robot dataset and augments it by simulating how different robot morphologies would execute the same task. Instead of collecting new real data for each robot variant, they use trajectory transformation to expand the dataset cheaply. When they test on real manipulation tasks, the augmentation helps in three ways: robots that were augmented in training perform better because they saw simulated versions of themselves during training, completely unseen robots improve because the diversity teaches the policy to handle shape variation, and the original robots perform better even when the task conditions shift in unexpected ways. Across real manipulation tasks, this achieves 24-45% success rate improvement. Synthetic morphological diversity, even when generated from transformed existing data, teaches the policy to recognize what is fundamental to the task and ignore robot-specific details — which means fine-tuning on a new robot requires less real data.
