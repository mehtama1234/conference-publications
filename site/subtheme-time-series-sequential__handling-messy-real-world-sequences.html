Handling messy real-world sequences

Time series in the wild have missing values, irregular sampling, mixed data types, and corruptions. Papers tackle imputation, asynchrony, multimodality, and robustness to these challenges.

All themesField mapMathematicsAll explainers
What this is

Textbook sequences are clean: one value per time step, recorded on a regular schedule, no missing data. Real-world sequences are messy. A patient's heart rate might be recorded every second for one patient and every five minutes for another. A factory sensor might fail for an hour and have a gap. Weather stations measure temperature and humidity and wind, but different stations measure different variables. Medical records mix continuous vitals with categorical diagnoses. Stock data has tick data at irregular times when trades occur, not at fixed intervals. When you have missing values, you need imputation. When sampling is irregular, you need alignment. When data types are mixed, you need encoding.

Each of these adds complexity. Imputation is guessing: you can use the mean, or linear interpolation, or a trained model. But the guess introduces error that propagates forward. Irregular sampling breaks models that assume fixed-rate time steps. Mixed data types mean the model has to learn different representations for numbers, categories, and text in the same sequence. Corruptions introduce noise and outliers. And the model has to learn what is real signal versus what is measurement error. A good sequence model has to handle these realities well, or predictions will be garbage in, garbage out.

Papers tackle these problems by building models that handle missing data natively—for example, methods that skip missing values instead of failing on them. Some do explicit imputation with neural networks trained jointly with the forecasting task. Others learn from irregular samples by encoding timestamps as input, so the model learns that a five-minute gap is different from a one-second gap. Multimodal approaches learn shared representations across different data types. A key insight is that messy data is not a bug to be fixed before modeling; it is part of the problem that the model has to learn to handle. Making models work well with real-world messiness often improves performance more than chasing marginal accuracy gains on clean benchmark data because real deployment always has messiness, so a model optimized for cleanliness will fail when it encounters the actual world.

How the work breaks down

Real-world time series are messy: measurements come at irregular intervals, values go missing when sensors fail, different sequences mix numbers with categories, and noise corrupts data. Work here splits into three directions: learning features that stay stable when data is corrupted, filling in missing values when they should be there, and handling all three problems at once by building models that work with imperfect data natively instead of trying to clean it first.

Learning stable features from incomplete data

A core challenge when data is missing or noisy is that a model trained on clean data will fail the moment messiness appears in the real world. The model's learned patterns break because the input distribution changes. Two strategies address this: one is to learn features that stay the same across different kinds of corruption without needing artificial data manipulation to teach stability; the other is to build the ability to handle missing values and mixed data types directly into the model's architecture so it learns what to do with gaps and misaligned timestamps.

Divide and Contrast learns stable features by contrasting clean examples with corrupted versions of themselves, without relying on hand-crafted augmentation (random rotations, noise injection, etc.). This works because the model learns which patterns are really there versus which are artifacts of noise. It achieves top performance on large datasets while reducing training time, because the method is simpler and doesn't waste computation on synthetic augmentations. ChannelTokenFormer handles messiness by design: it takes sequences where channels (separate measurement streams) arrive at different rates, have different amounts of missing data, and come from different data types, and treats each channel as a separate token in a transformer. This means it learns that missing data is data—a signal that this channel is absent right now—rather than an error to cover up. It also learns how timestamps relate to each other when they are irregular, so a five-minute gap carries different information than a one-second gap. Both papers share the insight that real-world messiness should not be hidden from the model; the model should learn to see it.

Filling missing values with learned imputations

When a value is genuinely missing—a sensor was offline, a test was not done, a patient skipped a checkup—you have to decide: throw out the whole sequence, fill it with a placeholder like zero or the mean, or learn what the value probably should have been. The first option loses data. The second introduces systematic bias. The third is hard because guessing wrong propagates error into downstream predictions. A learned imputation approach trains a neural network jointly with the prediction task, so the network learns what missing values typically look like in the context of this specific dataset.

T1 addresses imputation by binding each channel (measurement type) to a specific position in the model's output space, so the model learns dedicated patterns for each sensor or variable. When a value is missing, the model learns to predict it as part of training the overall forecasting task. The approach works especially well under extreme sparsity—when 70% of the data is missing—because the binding creates a stable target for each channel rather than trying to learn a generic imputation rule. This reduces error by 46% compared to the previous best method, showing that channelwise specialization is more effective than treating all missing values the same way.
