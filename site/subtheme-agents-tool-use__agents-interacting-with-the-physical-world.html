Agents Interacting with the Physical World

Papers about agents that see and act in the real world or realistic simulations — like robots, autonomous driving, or interacting with computers.

All themesField mapMathematicsAll explainers
What this is

Some agents don't just process text or numbers; they perceive and act in the real world. A robot sees its environment through a camera, reasons about what it sees, and moves its arms to manipulate objects. An autonomous car sees traffic, pedestrians, and road markings, and decides how to steer and accelerate. These are tool-use problems too: the camera is a tool that gives perception, the motor is a tool that produces motion, and the agent has to chain them together. These papers cover how agents learn to perceive, reason, and act in scenarios where the physics is real and mistakes have real consequences.

The difficulty jumps dramatically here. In a text-based problem, if an agent guesses wrong, you reload and try again in milliseconds. In the real world or realistic simulation, a mistake might damage equipment, or the situation might have changed too much to recover from. The agent perceives the world at one moment, makes a decision, acts, and by the time it perceives again, the world might have evolved in unexpected ways. Perception is also noisy and ambiguous — maybe the agent isn't sure if that object is a cup or a can. And there are delays between decision and action that have to be accounted for. The agent can't just trial-and-error its way to success; it has to reason and be more careful.

Papers here focus on embodied agents — agents that learn by interacting with simulations or real environments. Some train agents on videos or simulations where mistakes are cheap, then transfer that knowledge to reality. Others focus on robotics, teaching robots to recognize objects, plan grasps, and manipulate them. Some papers tackle autonomous driving or agents that interact with computer interfaces like navigating a website to buy something. The underlying goal is agents that don't just think but act, and that can bridge the gap between understanding a situation and successfully manipulating the world to achieve a goal.

How the work breaks down

Work in this subtheme splits into four directions: agents learning to move and grasp in physical spaces through vision and language; agents that interact with computer interfaces by seeing and clicking; agents that improve by actually trying actions and learning from what happens; and assistants that adapt by learning from user feedback over time.

Robot Learning Through Vision and Language

Robots need to see the world and understand language instructions in order to manipulate objects. The challenge is that the same action—like 'grasp the cup'—might mean different things depending on the cup's shape, position, and what the robot's arm can physically reach. Vision alone gives pixels; language alone gives words; connecting them together so a robot can actually pick things up is hard.

LangForce tackles this by building a visual-language model specifically for robot arms. The model learns what parts of the visual scene correspond to action instructions by decomposing the language into simpler pieces, which helps it generalize to new situations it has never seen before—it improves by 11.3% on a hard test where the new objects and scenarios are quite different from training. Turning Adaptation addresses a similar problem for agents that navigate physical spaces using vision and language—like a robot that reads 'go to the kitchen' and has to actually move there. Instead of retraining from scratch each time, this work lets agents borrow visual features and knowledge from previous tasks, which means agents adapt without needing new training data or extra computation. Both papers show that grounding language in actual visual perception is how agents learn to act reliably in the real world.

Web and GUI Agents Through Simulation and Synthesis

Agents that interact with computer screens and websites face a unique challenge: they have to see what's on the screen, understand what each button and text field means, and click the right ones in the right order to accomplish a goal. The problem is that real website interactions are slow, unpredictable, and hard to collect in volume. Training agents on real websites would take enormous amounts of time and human effort.

Gecko solves this by running agents in a lightweight simulation before they touch the real system. The agent generates a tool call—like 'click the search button'—and the simulation shows what would happen without actually doing it. If the simulation reveals a mistake, the agent can fix it before running the real action, which means fewer wasted attempts on the real system. This approach works consistently across many different language models. Scaling Synthetic Task Generation creates tens of thousands of training scenarios automatically by exploring Android phones and computers, then using those to train agents that can solve real-world tasks without being hand-labeled, which is faster than having people write examples by hand. AutoWebWorld takes this further by generating entire simulated web environments with predictable rules, allowing researchers to train on over 11,000 different trajectories cheaply and at scale, so that agents see diverse situations before facing real websites. Together, these three papers show that simulation—creating fake versions of the world that are cheaper to explore—makes training much faster, which means web agents can learn from more examples and become more reliable in practice.

Learning by Interacting with the Environment

Agents that can improve by actually trying actions in their environment have a major advantage: they don't have to guess; they can try something and see what happens, which lets them course-correct in real time. But real-world interaction is expensive—a robot making a mistake might break something, or a weather forecast system that guesses wrong wastes time. The question is how to make agents smarter through direct interaction without wasting resources.

Test-Time Adaptation for LLM Agents shows that language models can learn from interacting with an environment during deployment, not just during training. The agent tries an action, observes the result, and uses that information to adjust its next decision, so later attempts in the same task can be smarter. This works across many different benchmark tasks with minimal computational cost. Zephyrus builds an entire framework where agents interact with weather data and tools to answer questions ranging from simple lookups to complex forecasts. By having the agent actively interact with its tools—querying databases, running calculations, checking results—it outperforms systems that just read and reason about static text by up to 35 percentage points, because interactive trial-and-error beats pure text reasoning on real-world numbers. Both papers demonstrate that the ability to act, observe, and adapt during task execution is what separates agents that merely understand instructions from agents that actually accomplish goals.

Assistants Learning from User Interaction

Assistants that work with people need to learn what each person wants and how they prefer to work. A general assistant might be technically capable, but if it doesn't adapt to individual users, it will frustrate them. The challenge is building systems that learn from real interaction feedback without requiring explicit training data for every person.

Code2Video addresses a specific version of this problem: how can an educational video be created to teach coding? Rather than generating code directly or generating videos directly, the system reasons about what code should teach, then creates videos that walk through that code step by step. The result is 40% better than just generating code alone because the videos explain not just what the code does but why each line matters, and this explanation approach actually helps people learn the material. ProPerSim takes a more general approach: it simulates conversations between an assistant and different types of people, captures feedback on whether those conversations worked well, and uses that feedback to improve the assistant for each individual, so each person gets a more customized experience. Testing on 32 different personas, the system shows that assistants adapted through user feedback steadily improve satisfaction, because feedback reveals what each user cares about. Both papers show that assistants improve when they interact with actual people or realistic simulations of people and learn from what works, which means adaptation through interaction beats one-size-fits-all design.
