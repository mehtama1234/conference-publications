Steering Autoregressive Music Generation with Recursive Feature Machines

MusicRFM finds internal directions inside a frozen music model that correspond to musical properties such as notes or chords, then adds those directions during generation to steer the output without retraining the base model.

Paper explainersAll themesMultimodal

Controlling a pre-trained music generator is hard because the usual control methods either retrain the full model, optimize a control signal at every generation step, or degrade audio quality by pushing too bluntly on the output. MusicRFM uses a different route. It studies how the model's hidden states change when a musical property changes, learns a direction in hidden-state space for that property, and then injects that direction during generation time. The base model stays frozen, the steering signal is lightweight, and the control can vary over time or combine several musical properties at once.

Zero assumption version

Music control usually changes too much or too little

A next-step music model generates the next audio unit from the units generated so far. Once such a model is trained, it already contains internal structure for rhythm, harmony, instrumentation, and note transitions. The challenge is to influence one chosen property, such as the presence of a target note, without retraining the full model or damaging the rest of the musical structure.

Direct retraining is costly and often task-specific. Per-step optimization can be slow because a control objective has to be solved during generation itself. Output-level editing can also introduce artifacts because it acts after the model has already committed to an internal plan. The paper instead asks whether the control signal can be applied inside the model, where the next-step decision is formed.

The paper's move. Learn interpretable hidden-state directions for musical concepts in a frozen model, then add those directions during generation time according to a chosen schedule.

What the paper changes

What the paper changes

MusicRFM changes the hidden state used by the frozen music generator at generation time. It does not retrain the full model and does not optimize a new control variable at every step. Instead, it adds a precomputed concept direction to the model's internal representation as generation unfolds.

the object it moves  =  the hidden state trajectory during generation
The hidden quantity

The hidden quantity: concept direction strength

measured quantity  =  concept direction strength

The central quantity is how strongly a chosen hidden-state direction increases the probability of the target musical property while preserving the rest of the sequence. If the direction is too weak, the target note or chord barely appears. If it is too strong, it can override prompt adherence and distort other musical structure.

The paper learns these directions with Recursive Feature Machines, which fit probes to the model's internal behavior rather than to the output alone. The result is an interpretable direction that can be scaled up, down, turned on only during chosen time spans, or combined with other directions.

Why it works

Why hidden-state steering works

A pretrained next-step music model already organizes its internal state so that different musical properties affect next-step probabilities. If a particular note, chord, or local structure is represented consistently inside the hidden state, then changing the hidden state along the corresponding direction changes the model's next-step probability pattern in a predictable way. This is more direct than output editing because the intervention happens before the next unit is sampled.

Recursive Feature Machines are used to estimate those directions from internal responses. The probe is lightweight, but it is trained to track how hidden-state changes connect to the target concept. Once that relationship is identified, the steering stage no longer needs to solve an optimization problem online. It simply adds the learned direction, scaled by a chosen coefficient, to the hidden state at the selected layer and time step.

Time-varying schedules matter because many musical properties are local rather than global. A user may want one note or chord to be emphasized during one segment and not elsewhere. Multiple-direction control also matters because music is structured by several coupled properties at once. Because the directions are learned separately and applied inside the hidden state, the method can combine them more cleanly than a blunt output-level control signal.

Math after the picture

The steering update

First in words:

At a chosen generation step, add a scaled concept direction to the hidden state before the model predicts the next token.

Then the compact form:

modified_state_t = hidden_state_t + alpha_t * concept_direction

Every symbol:

modified_state_tthe hidden state after steering at time step t
hidden_state_tthe original hidden state produced by the frozen music model
alpha_tthe steering strength at time step t, which can vary over time
concept_directionthe learned hidden-state direction tied to a target musical property
A tiny worked example
Suppose the target is note C and the learned concept direction is available from the probe.
At one generation step, set alpha_t = 0.0 and the model behaves exactly like the base model.
At a later step, set alpha_t = 0.8 and add 0.8 times the concept direction to the hidden state.
The next-step probabilities shift toward events associated with note C because the hidden state now moves in the learned direction for that concept.
If alpha_t is reduced again, the steering influence weakens without changing the frozen model weights.

This update matters because it gives direct control over when and how strongly a musical property is enforced.

What can go wrong

What can go wrong

A learned direction may mix several concepts. If the probe does not isolate the target property cleanly, steering one note may also drag along unwanted chord or timbre changes, because the hidden-state direction is not perfectly disentangled.
Large steering strength can override the prompt. If the scale is too high, the target concept can dominate the hidden state and reduce adherence to the original text prompt or earlier musical context.
Control may depend on where it is injected. A direction learned at one layer may not transfer cleanly to another layer, because the representation of the musical concept changes across depth.
Done right. The method works best when the probe learns a clean concept direction, the steering scale is tuned for the target property, and the intervention is applied at layers and time spans where that property is represented clearly.
What a runnable demo should prove

What a runnable demo should prove

Take a pretrained music generator and choose a simple target property such as the presence of one note or one chord class. Record hidden states from the frozen model, train a lightweight probe to estimate the concept direction, and compare unsteered generation against steered generation on the same prompts.

The demo should measure how often the target property appears, how much the prompt meaning changes, and whether the effect can be confined to chosen time ranges. A convincing result shows that hidden-state steering raises the target property because the intervention changes the next-step decision inside the model, while the base model weights stay frozen.

control_gain = target_property_rate_with_steering - target_property_rate_without_steering

The core claim is established if the target musical property rises sharply with only a small change in prompt adherence.
