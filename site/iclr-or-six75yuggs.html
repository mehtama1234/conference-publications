Adaptive Patching for Native-Resolution Multimodal LLMs

Use different patch sizes for different images so the model sees just the right level of detail without wasting computation.

Paper explainersAll themesMultimodal

A multimodal model (one that reads both images and text) needs to handle images of any resolution: a screenshot or document full of small text; a photo with wide vistas. If you cut every image into the same-sized pieces, either you lose details in dense images or waste computation on sparse ones. This paper shows how to pick the right piece size for each image, on the fly, without retraining the model.

Zero assumption version

Why fixed patches fail across resolutions

A multimodal large language model (a language model that also reads images) breaks images into square tiles called patches before feeding them to the model. Like chopping a photo into a grid of identical pieces. A naive attempt: use 16 pixel by 16 pixel patches everywhere. That works fine for a 512 pixel by 512 pixel photo. But run the same model on a 2048 pixel by 2048 pixel high-resolution image — now you have 256 times as many patches, the model drowns in redundant detail, and throughput collapses.

Flip it: use larger 64 pixel by 64 pixel patches to keep computation cheap. Then feed it a screenshot with tiny text. Now each patch contains a whole line of words, and all the letter shapes blur together. The model loses the information it needs to read the text.

A beginner's fix: just downscale all images to a standard size before patching. But shrinking a 2048 pixel by 2048 pixel document to 512 pixel by 512 pixel erases the fine details — you lose information that was actually there. The paper argues the real bottleneck is the rigid patch size itself.

The core insight: Patch size should match resolution and detail density — coarse patches for sparse images, fine patches for dense ones — and you can swap this when answering a question without retraining.

The algorithm as a flow

What it actually does

Measure the image

Look at resolution (width and height) and information density (how much detail is actually in the pixels).

Pick patch size

Choose: small patches for high-detail regions, larger patches for sparse regions.

Slice and encode

Cut the image into patches of that size, feed each to the vision encoder.

Convert patches to input items

Each patch becomes a token, which is a single item the language model reads; pass all tokens to the text model.

Answer question

The language model reads tokens and text prompt; outputs the answer without any retraining.

What the paper changes

What the paper changes

The paper moves the patch size. Instead of a fixed grid size hard-coded into the model, it computes a custom patch size per image, on the fly. The vision encoder and language model stay unchanged — the model weights do not move. Only the way the image is sliced before encoding changes.

the object it moves  =  patch size
The hidden quantity

The hidden quantity: information density

measured quantity  =  information density

Information density is how much detail is actually packed into the pixels. A dense image (a document, a chart, a close-up photo) has a lot of small structures you need to see. A sparse image (a sky, a solid wall, a wide vista) has large uniform regions where shrinking changes almost nothing. The paper measures density by looking at the image's actual pixel patterns — if the image changes a lot from pixel to pixel, it is dense; if it is smooth and similar across large regions, it is sparse.

Once you know the density, you can decide: dense areas get smaller patches (more detail), sparse areas get larger patches (less waste). Without measuring density, you would have to guess a fixed size that works for all images, which is always a compromise. With density measured, the algorithm can automatically pick the right size for each region.

Why it works

Why adaptive patching works

The core idea: in a fixed-patch model, every image gets the same treatment. Shrink the patch size, and you see more detail everywhere — but computation explodes even for images that do not need it. Grow the patch size, and computation stays cheap — but dense images lose important information. There is no middle ground with one fixed size.

Adaptive patching escapes this trap by doing both at once: it uses small patches only where they matter (high-detail areas) and large patches where they do not (sparse regions). Since most natural images have large uniform regions (sky, grass, walls), using larger patches there saves enormous computation. And since the model already knows how to read small patches (it was trained on fixed small patches), feeding it a mix of small and large patches still works — it just sees tokens at the resolution appropriate to that region.

Mechanically, the model does not see a patchwork of different sizes. It sees a variable-length sequence of tokens — some from fine-grained dense patches, some from coarse sparse patches — and processes them the same way. The vision encoder (the part that turns image patches into tokens) stays identical; only the input image is sliced differently. This is why no retraining is needed.

The adaptive patch rule

First in words:

Patch size is determined by a function of resolution and information density. Smaller patches capture detail; larger patches reduce redundancy.

Then the compact form:

patch_size = 16 * min(max_density / local_density, 4.0)

Every symbol:

patch_sizewidth and height of each patch in pixels
16the base patch size the model was originally trained on
max_densitythe highest information density in the image
local_densityinformation density in the region being patched
4.0the maximum size multiplier to prevent patches from getting too large
A tiny worked example
Region 1 (dense text): max_density = 100, local_density = 100. Patch size = 16 * min(100/100, 4.0) = 16 * 1.0 = 16 pixels.
Region 2 (sparse sky): max_density = 100, local_density = 10. Patch size = 16 * min(100/10, 4.0) = 16 * 4.0 = 64 pixels.
Result: text is sliced into 16x16 chunks (16 times finer than the 64x64 sky patches), capturing letter details. Sky patches are 4x larger, cutting compute by a factor of 16 in that region.

The equation ensures coarse patches where density is low (saving computation) and fine patches where density is high (preserving details), all without retraining the model.

What can go wrong

What can go wrong

Density estimation is noisy. If the algorithm misestimates how dense a region really is, it picks the wrong patch size. A fine-detailed chart might be flagged as sparse, causing information loss. The paper does not fully explain how to measure density reliably across diverse image types.
Mixed patch sizes can confuse the model. The model was trained on uniform small patches. Feeding it a variable-length token sequence with different patch granularities changes what it sees. If the model does not handle this new pattern well, accuracy can drop.
Edge cases with unusual aspect ratios. Very wide or very tall images may not slice evenly into the adaptive grid. The paper does not detail how to handle boundary patches or irregular shapes.
Done right (training-based variant). The paper also proposes a fine-tuning variant: train the model on variable patch sizes to fully adapt it. Since the model was originally trained only on fixed patch sizes, mixing patch sizes at test time is a shift in what it sees. Fine-tuning on variable sizes teaches the model to extract meaning from both dense fine patches and coarse sparse patches together, reducing the errors from the mismatch, though at the cost of a small training investment.
What a runnable demo should prove

What a runnable demo should prove

Build a simple adaptive patcher for a real multimodal model. Take three test images: a low-resolution photo (512 by 512), a high-resolution document scan (2048 by 2048), and a mixed image (document on a background). For each, compute information density using pixel gradients or a simple edge detector, choose adaptive patch sizes, run the model without retraining, and measure accuracy on a visual question (e.g., read the text, describe the scene). Compare to fixed patch sizes.

adaptive_accuracy - fixed_accuracy; and adaptive_throughput / fixed_throughput (should be > 1.0 for high-res images).

The demo must show that a single adaptive-patch run beats fixed patches on both dense and sparse images at the same training checkpoint, proving the method works without retraining.
