Making agents robust and safe in real scenarios

Building agents that don't break when conditions change, can recover from adversarial situations, and avoid catastrophic failures even when faced with surprising or hostile inputs.

All themesField mapMathematicsAll explainers
What this is

A robot learned to reach a target in a lab, but in the real factory, the lighting is different and the gripper gets worn. An autonomous vehicle was trained on sunny roads but encounters rain. An AI trading system was trained on historical patterns that don't repeat. Adversarial settings are even worse: someone might actively try to trick the system. The problem is that when the real world differs from training, does the agent still work, or does it fail catastrophically?

Testing reliability is hard because you can't predict every difference between training and reality. Researchers test by intentionally distorting inputs — changing images, adding noise, warping physics — and checking if the agent still performs, which tells them which sources of variation break the system. But you also have to know which distortions matter most to fix first. A robot might handle camera angle changes (rotation is common) but fail with lighting changes (factory lights are different from lab lights). Papers address domain adaptation (learning to work across different environments by discovering what matters), adversarial attacks (handling deliberate disturbances by learning to ignore manipulation), and uncertainty quantification (knowing when the agent is confident and when it should ask for help rather than guess).

Safety is tied to reliability because one catastrophic failure (a robot dropping an expensive part, a vehicle crashing) undoes many good decisions and causes real harm. An agent that works well 99% of the time but fails catastrophically in edge cases is not safe enough for deployment because those rare failures will happen in real use, and the costs are not symmetric — one crash is worse than 99 good drives. Real-world deployment requires that the agent either handles surprises gracefully by adapting its behavior on the fly (when conditions shift, the agent continues working well because it adjusts), or recognizes when it encounters something completely new and asks a human for help rather than guessing and making the mistake worse. This is the same strategy humans use when facing uncertainty — some problems we solve, some we defer to someone with more expertise.

How the work breaks down

Making agents work reliably in the messy real world splits into four directions because each addresses a different failure mode. First, learning good estimates of value that don't break when conditions change, because inaccurate estimates lead to wrong actions. Second, keeping agents safe while they learn, because exploration can cause catastrophic failures before the agent learns better. Third, handling deliberate attacks and adversarial inputs, because real systems face malicious interference. Fourth, knowing when the agent should trust its own decisions versus asking for help, because overconfident guesses cause unnecessary errors.

Keeping value estimates stable when the world shifts

When a robot learns to estimate how good an action is (its value), it builds that estimate from training examples. But if the real world looks different from training, the agent's value estimates can become wildly inaccurate, leading it to pick bad actions. The core problem is that value estimates are fragile: a small change in the environment (new lighting, worn parts, different noise patterns) can break the estimates catastrophically.

Clipped Q-Learning attacks this by using a simple idea: when learning value estimates, automatically clip or limit how extreme the values can get during the learning process. This acts like a brake that prevents the learning algorithm from overcommitting to wild estimates. The paper shows this clipping works like a mathematical operation that keeps estimates stable even when the world shifts. DR-SAC (Distributional Soft Actor-Critic — learning what many possible worlds might look like instead of just one) goes further by explicitly designing the learning algorithm to handle a whole range of possible worlds at once, not just the training environment. Instead of learning one set of estimates, it learns estimates that work well across many plausible variations of the world. When tested, DR-SAC achieves 9.8 times higher reward than the standard version when the environment gets perturbed. The Counterfactual State Editing paper tackles the same problem from a different angle: during learning, it deliberately edits the training data to remove spurious distractions (like a misleading visual artifact that correlates with reward but isn't actually important). This keeps value estimates focused on what truly matters. Together, these papers show that stability isn't just about having more data — it's about how you shape what the learning algorithm sees.

Safe learning with constraints and feedback

Safety in reinforcement learning means the agent must avoid catastrophic failures while it is learning to improve. This is genuinely hard because the agent has to explore new behaviors (to learn better strategies) while respecting hard constraints (don't knock over the vase, don't crash). Exploring and staying safe pull in opposite directions, creating what researchers call the safety paradox.

CSPO (Constraint-Sensitive Policy Optimization) solves this by explicitly tracking which actions violate constraints and how much safety room is left. Instead of treating constraints as an afterthought, it makes constraint satisfaction the primary goal and tries to maximize reward within that safety budget. When the agent hits a constraint violation, CSPO quickly learns to steer away from those bad actions without forgetting everything else it learned. The Safe RL with Preference-based Constraint Inference paper takes human knowledge into account: rather than hard-coded constraints, it learns what the human really cares about by watching human preferences and inferring the underlying safety requirements. This is closer to how humans teach — showing examples of acceptable and unacceptable behavior until the agent gets it right. Breaking Safety Paradox with Feasible Dual Policy Iteration uses two policies at once: one that plays it safe and one that takes measured risks. By combining information from both, it can make safe decisions without throwing away opportunities to improve. All three papers realize that safety and learning are not enemies if you structure the learning carefully — you can have both if you make safety a first-class concern during training, not an afterthought.

Estimating and handling uncertainty in decisions

An agent that learned well in training might still fail in the real world because it is overconfident about situations it has never seen before. The challenge is to know when you should trust the agent's decisions and when you should ask a human, because asking for help is far better than guessing wrong. Estimating this uncertainty accurately is hard because the agent's learning algorithm usually tries to make confident predictions, not to admit uncertainty.

The Orthogonal Learner paper addresses this by building value estimates (how good each action is) in a way that hedges its bets — so that even if the learning algorithm's assumptions are wrong in certain ways, the estimates still work well. This lets you estimate how confident the agent should be. Off-Policy Evaluation for Ranking Policies solves a related problem: if you have logged data from a previous policy, can you accurately predict how well a new policy will perform without actually running it? The paper shows that when the logging is deterministic (the previous policy always took the same action in a state), existing methods give wildly biased estimates. The new approach gives much lower bias so you can trust the estimate before deployment. Reward Hacking Optimization addresses what happens when the proxy reward you taught the agent to optimize (like clicks) diverges from the true goal (like user satisfaction). If the agent becomes too certain it is doing well, it will start gaming the proxy reward in ways that hurt the true goal. The paper uses worst-case planning — imagining the worst possible ways reward could drift — so the agent stays aligned even when the proxy starts to mislead. Together these papers show that staying trustworthy requires being honest about what you don't know, and it requires checking your assumptions before you deploy.

Adapting and transferring skills across conditions

Even with stable value learning and safety constraints, an agent still needs to adapt when it encounters a genuinely new situation. Adaptation is especially hard because the agent must decide quickly with limited information, and the new situation might be very different from anything in the training set. A robot trained to reach targets in a small workspace needs a different grip strength when the workspace is huge, or it will overshoot.

ASAP (Exploiting the Satisficing Generalization Edge) discovers that the agent generalizes better when it learns to identify which actions are good enough, rather than trying to pick the single best action. This sounds subtle but it matters: optimizing for perfection forces the agent to memorize exact details of the training environment, whereas finding satisfactory actions is more flexible because many actions tie for good-enough. The method learns on 3D bin packing, traveling salesman, and vehicle routing problems and shows much better generalization to larger instances. Learning Generalizable Skill Policy with Data-Efficient Unsupervised RL goes further by learning reusable skills — atomic behaviors like reach, grasp, place — that transfer to new downstream tasks. It discovers these skills through unsupervised exploration if you pick an exploration strategy carefully so that you find diverse behaviors. Self-Improving Skill Learning for Flexible Meta-RL extends this to noisy real-world data: traditional meta-RL assumes the training data is clean and optimal, but in real robotics the data is messy. This paper learns to improve the skill estimates on the fly even when the data is imperfect, which allows the agent to keep learning from demonstrations that are less than perfect and therefore avoids getting confused by learning from suboptimal actions. Transferable RL via Hidden State Models tackles sim-to-real transfer by explicitly modeling the hidden differences between simulation and reality (unmodeled dynamics, friction, sensor lag), then adjusting the policy to work in the real environment. All four papers recognize that adaptation is about finding stable structures (skills, satisfactory actions, hidden state representations) that continue to work when the world changes.

Defending against attacks and adversarial inputs

Safety and reliability take on a sharper edge when there is an adversary actively trying to trick the agent. An attacker might inject corrupted data into the training set, feed adversarial sensor inputs, or hijack parts of the agent's action output. Defending against these attacks requires fundamentally different thinking than handling accidental distribution shift.

Budget-Efficient Attacks and Training for Cooperative MARL studies how to attack and defend multi-agent teams when an attacker can only corrupt a limited number of actions. The paper shows how to launch attacks that are stronger under the same budget because understanding where attacks hurt most teaches you what defenses matter, then uses that understanding to train the team to defend against limited-step hijacking. In-Context Reinforcement Learning Under Reward Poisoning Attacks looks at what happens when someone poisons the reward signal during training — replacing true rewards with false ones. In-context learning (where the agent adapts by watching examples in its context window) is vulnerable because it blindly trusts the examples it sees. The paper develops defenses that make the agent tolerate poisoned rewards in both bandits and full MDPs. Solving Parameter-Aware Avoid Problems learns a policy that works even when key parameters (like friction or mass) are unknown or change across instances. The agent learns to be conservative enough to work in many parameter regimes rather than tuning to one specific case. Learning Per-Timestep Constraint-Violation Credit from Sparse Labels solves a practical problem: the agent receives sparse feedback (you violated a constraint at some point in this trajectory) but does not know exactly when or how. The paper learns to pinpoint which timesteps were responsible for the violation so it can update its policy to avoid that specific behavior. All four defend against different ways an adversary could attack by making the agent handle uncertainty about true parameters, true rewards, or exact constraint violations.
