Byte Pair Encoding for Efficient Time Series Forecasting

Instead of chopping time series into fixed-size chunks, group repeating patterns into tokens and compress adaptively.

Paper explainersAll themesTime Series & Sequential

Time series forecasting models currently chop sequences into equal-sized pieces, then turn each piece into a token (a single number used by the model). But this wastes tokens on simple parts like flat stretches, and requires expensive computation. This paper proposes pattern-based tokenization: find the most common short patterns (motifs) in your data, then merge all matching stretches into single tokens, compressing the sequence intelligently.

Zero assumption version

Fixed-size chunks waste tokens on simple patterns

Today's time series models convert sequences into tokens (compressed units the model processes). The standard approach: divide a time series into equal-sized blocks regardless of what is happening in the data. A flat price over 100 days becomes 100 tokens. An identical pattern repeated five times becomes five tokens per repetition, ten tokens wasted.

Why does this break? Models have a limited attention window (the maximum length they can process per step). More tokens means you hit that limit faster, forcing expensive operations: breaking long sequences into pieces, discarding data, or running the model multiple times on the same sequence. A naive approach tries to fix this by making blocks bigger, but then simple patterns get lost in the averaging.

In one sentence. Group repeating patterns into single tokens instead of chopping at fixed intervals.

The algorithm as a flow

What it actually does

Scan the time series for common short patterns

Extract all repeating motifs (e.g., flat, spike, ramp); rank by frequency.

Build a discrete motif vocabulary

Assign each top motif a unique ID: a compact lookup table matching patterns to codes.

Replace matching stretches with motif tokens

Wherever the data matches a motif, emit a single token instead of multiple samples.

Compress the sequence

The result is much shorter: flat parts merge, repetitions collapse, noise-like regions stay tokens.

Apply conditional decoding

Tweak token boundaries slightly after compression to maximize forecast accuracy, without retraining.

What the paper changes

What the paper changes

The paper rewrites how a time series is converted into tokens. Instead of a rigid rule (every 10 samples becomes one token), it uses a learned motif vocabulary: patterns that actually appear in the data decide when to emit a token.

the object it moves  =  tokenization scheme
The hidden quantity

Token compression rate

measured quantity  =  tokens per sample

The hidden quantity is the efficiency of compression: how many tokens does the compressed sequence need, per original sample? Lower is better. This matters because the model's attention mechanism must store a table of all pairwise interactions between tokens; if you have 1000 tokens instead of 100, that table grows 100x, consuming memory and computation time.

The paper measures this by counting tokens before and after motif-based encoding, and also by tracking how much the final forecast error shrinks per unit of compression. A motif that compresses well but loses important detail is less useful than one that compresses less but preserves forecast quality.

Why it works

Why pattern-based tokenization works

The core insight: a fixed chunking rule ignores the actual structure in the data. If you have a price that is flat for days, one token captures the whole thing. But fixed chunking assigns one token per hour, wasting nine. Pattern-based tokenization inverts this: find what the data naturally repeats, then use those repetitions as token boundaries.

Conditional decoding is the second part. After you compress using motifs, the token boundaries are locked in. But you can then tweak the reconstruction (how you turn tokens back into time series values) without retraining the model. This is a cheap optimization: it adjusts which exact value each motif token represents, so that the final forecast is more accurate. No gradient updates needed; just a direct calculation.

The compression equation

First in words:

For each motif, store its average value and how many times it was chosen. During reconstruction, each token is replaced by its motif's average. Conditional decoding then solves for the per-motif value that minimizes forecast error, given the token sequence already fixed.

Then the compact form:

reconstruction_value_m = mean of samples assigned to motif m; error = sum over time steps (predicted - true)^2; conditional_decoding shifts each motif's value by delta_m to minimize error without changing tokens

Every symbol:

mthe motif ID (1, 2, 3, ...)
reconstruction_value_mthe numeric value assigned to motif m when decoding back to time series
delta_ma small adjustment per motif during conditional decoding
errorthe sum of squared differences between forecast and real values
tokensthe compressed sequence using motif IDs instead of raw samples
A tiny worked example
Motif A (flat): appears 400 times in the original 1000-sample series. Compressed to 1 token.
Motif B (spike): appears 200 times. Compressed to 1 token.
Motif C (rise): appears 300 times. Compressed to 1 token.
Motif D (noise, rare): appears 100 times. Stays as 100 tokens (too rare to compress).
Original: 1000 tokens. After motif encoding: 1 + 1 + 1 + 100 = 103 tokens. Compression ratio: 1000 / 103 = 9.7x.
Conditional decoding: instead of average value 45 for motif A, adjust to 46.2 if that shrinks forecast error. Same token count (103), but 48% lower error on validation data.

The fixed step-size tokenization would use 100 tokens per 100 samples; motifs reduce this to 1 per 100 repeated samples, saving computation proportional to pattern redundancy.

What can go wrong

What can go wrong

Motif vocabulary too small. If you pick only the top 2 motifs because they are so common, rare but important patterns such as a sudden shock in price disappear entirely. The compression is great, but forecast error rises because you erased critical structure.
Motif overfitting to training data. If you scan one time series and build a motif vocabulary custom to it, those motifs may not appear in a different time series. Transfer to a new forecasting task will fail because the token vocabulary has no relevant patterns.
Conditional decoding diverges. If you adjust motif values (delta_m) too aggressively without any constraint, the reconstruction can flip to unphysical values (e.g., negative prices). A lightweight regularization (penalizing large shifts) prevents this.
Done right. Calibrate motif vocabulary on a held-out training set, then apply it to a fresh time series. Conditional decoding uses a fixed learning rate small enough to stay stable. Test forecast error on a validation set separate from both. The compression persists across datasets if you pick motifs that are generalizable (e.g., flat, slow-rise, fast-drop) rather than data-specific.
What a runnable demo should prove

What a runnable demo should prove

Simulate a synthetic time series with 1000 samples: a flat region (50 samples), then a smooth rise (100 samples), then a spike (20 samples), then noise (830 samples). Train a simple regression model on the time series using a foundation model's (pretrained) encoder.

Measure: (1) token count before and after motif encoding, (2) validation forecast error before (using fixed tokens) and after (using motif tokens + conditional decoding), and (3) time to run the model on 10 new test sequences.

compression_ratio = tokens_before / tokens_after; error_reduction = (error_fixed - error_motif) / error_fixed; speedup = time_fixed / time_motif

The demo must show all three: token count cut by 50 percent (motif tokens replace many samples with one token); error drops 20 percent (motif tokens align with real patterns, so the model sees real structure instead of arbitrary chunk boundaries); and prediction is 2x faster (fewer tokens means the attention table is smaller, so each forward pass takes half the time).
