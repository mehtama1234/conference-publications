DexNDM: Closing the Reality Gap for Dexterous In-Hand Rotation

A robot hand can rotate any shape object in the real world if you teach it to predict how each finger individually moves, using only a few real-world trials.

Paper explainersAll themesRobotics & Control

A robot hand trained in the video game simulation can rotate simple objects perfectly, but fails with weird shapes and sizes in the real world. The gap between the fake world and real world exists because the computer model of how fingers touch and slide across the object is wrong. This paper fixes that by learning a separate prediction model for each finger, using just a handful of real-world rolls of objects in the robot's hand.

Zero assumption version

Why robot hands fail on real objects

A robot hand trained in simulation to rotate objects learns perfect finger moves in the fake world. But when it touches a real object, its fingers slip, stick, and bump in unpredictable ways. The simulation had no idea that real leather is slippery or that a tiny pebble blocks the path.

A beginner would try to write down the physics: how much torque it takes to slide a finger, how friction works, the exact shape of the object. But real objects are too varied — a soccer ball is different from a marble, and a long thin stick is different from a cube. Physics formulas written by hand will always get details wrong and only work for things the programmer imagined.

The robot's finger positions are recorded in the real world, so the movement patterns are real. But the computer has never seen most of these patterns before. Without a way to adapt what it learned in the fake world using what it now sees in the real world, the robot stays stuck.

The problem in one sentence. A robot hand trained in simulation cannot adapt to the unpredictable contact and friction of real objects without learning what actually happens when it touches them.

The algorithm as a flow

What it actually does

Train five specialists in simulation

For each category of object, train a separate robot hand to rotate it perfectly using reinforcement learning.

Merge them into one generalist

Use a learning technique called behavior cloning to teach a single hand policy to copy all five specialists at once.

Let the robot collect real-world data

Let the generalist policy roll real objects in the hand, recording what position each finger reaches and what force it applies.

Train separate finger predictors

For each of the five fingers, train a small model that learns to predict where that finger will be next, based only on that finger's recent history.

Train a corrective policy layer

Teach a thin correction layer on top to adjust the generalist's commands so the real finger motion matches the prediction model's expectations.

What the paper changes

What the paper changes

Instead of one model predicting how the whole hand moves, the paper learns five separate models — one for each finger. Each finger model only looks at its own recent positions and forces, ignoring what the other fingers do.

the object it moves  =  finger-by-finger prediction
The hidden quantity

The hidden quantity: per-joint error

measured quantity  =  prediction error for each finger

The paper measures something the simulator never sees: how far off each finger's actual position is from where the simulation predicted it would be. This is the gap between the fake world and the real world, finger by finger. When a finger's position is exactly where the simulator predicted, the error is zero. When slip happens and the finger lands far from the prediction, the error is large.

The paper uses this per-finger error to train a correction model. That model learns to nudge the hand's commands so the real fingers land closer to where the simulation expects them. This per-finger error is usually much easier to predict than the error for the whole hand at once, because each finger's slip and friction patterns are more consistent than the tangled mess of all five fingers together.

Why it works

Why splitting fingers works better

When one model tries to predict how the whole hand moves, it has to juggle five fingers' worth of contact patterns at once. Each finger might be sliding, stuck, or bumping into the object differently. A whole-hand model has to encode all of that tangled behavior in a single prediction.

When the paper splits it into five separate models, each finger model only has to learn that one finger's pattern. The thumb model learns when the thumb tends to slip. The index model learns when the index finger gets stuck. This is much simpler, because the patterns are less entangled. The paper proves this mathematically: a finger model trained on limited real-world data generalizes better to new objects than a whole-hand model given the same data, because the simpler problem is easier to solve with fewer examples.

The correction layer on top ties the five fingers back together. It learns to adjust the simulation's commands so that each finger's position ends up where the per-finger model predicts it should. This way, the hand can rotate objects it has never touched before, because the five finger models have learned the general patterns of how fingers behave on real objects.

Math after the picture

The prediction equation

First in words:

For each finger i, predict its next position from its recent history of positions and forces. The next position equals a learned function applied to the window of recent states and actions.

Then the compact form:

q_i(t+1) = f_psi_i( h_i(t) ) where h_i(t) = { q_i(j), a_i(j) } for j from t-W+1 to t

Every symbol:

q_i(t+1)the next position of finger i
f_psi_ithe learned model for finger i
h_i(t)the history window for finger i
q_i(j)finger i's position at time step j
a_i(j)the force command to finger i at time step j
Wthe window size, how many past steps to look back
A tiny worked example
Suppose finger 3 (middle) has been moving like this: position 45, 47, 48, 49.
The simulation predicted next position would be 50.
The model f_psi_3 learned from real data that when the middle finger sees this pattern, it usually moves less than the simulation thinks — friction and slip slow it down.
The model predicts position 48.5 instead of 50.
The correction layer computes: real error is 50 - 48.5 = 1.5, so boost the command by 1.5 units next time.
This learned boost adapts the simulator's commands to match what actually happens in the real world.

The paper trains one of these models for each of the five fingers, and the correction layer learns to apply the right boost to each finger based on its per-finger prediction model. The boost works because the per-finger model reveals exactly what real fingers actually do, so nudging the commands to match that prediction closes the gap between what the simulator expects and what the robot hand does on real objects.

What can go wrong

What can go wrong

The hand is too different from the simulator's assumption. If the real hand has broken sensors or loose joints that the simulator never modeled, the finger models will learn a pattern that only works on this one broken hand. They will not generalize to a new, well-calibrated hand.
An object has never been touched by the training hand. If you ask the robot to rotate a shape made of a material it has never felt before (like a slippery rubber vs. cardboard), the per-finger models have never learned how that material behaves. The adaptation may fail.
The finger models fit noise instead of real patterns. If the hand was jiggly during data collection or the position sensors were noisy, the finger models might learn random jitter instead of the real slip-and-friction patterns. Then they waste their predictions on noise.
Training only on object categories the hand has seen. The paper sidesteps this by always training on diverse objects spanning aspect ratios, sizes, and materials. A new, unseen object shape is more likely to land in the pattern-space the finger models have learned.
What a runnable demo should prove

What a runnable demo should prove

The core claim is that per-finger prediction generalizes better than whole-hand prediction when given limited real-world data, because each finger's pattern is simpler and requires fewer examples to learn. A runnable demo should: (1) collect about 100 real rolls of the hand rotating objects on a real robot; (2) train both a per-finger model and a whole-hand model on that data; (3) test each on a new object the hand has never seen; (4) measure the position error of each finger at each step. Plot the average error over time as the robot tries to rotate the new object. The per-finger model should produce lower error, especially in the early steps before the hand has fully adapted to the new object.

per_finger_error = average( | predicted_position_i - real_position_i | for each finger i and each timestep ); whole_hand_error = average( | predicted_position - real_position | for all fingers together ); success = per_finger_error < whole_hand_error

The demo makes it impossible to miss: five separate finger models, each learning its own simple pattern, adapt faster and more accurately to a new object than one big tangled model trying to predict everything at once, because separation removes the noise of fingers interfering with each other's patterns.
