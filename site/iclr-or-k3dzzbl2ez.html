ContextNav: Towards Agentic Multimodal In-Context Learning

ContextNav builds and repairs the example context for a multimodal task through a closed-loop tool graph, because good in-context learning depends on example quality as much as example availability.

Paper explainersAll themesAgents & Tool Use

Multimodal in-context learning asks a model to solve a new task from a small set of examples that mix images and text. The challenge is not only to retrieve examples quickly. The challenge is to retrieve examples that fit the task structure and to reject noisy ones. Manual curation often works, but it does not scale. Simple nearest-neighbor retrieval scales, but it often brings in mismatched or structurally inconsistent examples. ContextNav tries to combine both strengths. It uses a tool-orchestrated workflow to fetch candidate examples, align them structurally, and revise the plan based on downstream feedback.

Zero assumption version

Retrieved examples can scale, but they often damage the context

In-context learning depends heavily on the support examples placed before the query. If those examples match the task and show the right structure, the model can adapt quickly. If they are noisy or mismatched, the model can be pushed toward the wrong pattern.

For multimodal tasks this is harder than for text-only tasks because each example has both visual and language structure. A retrieved item may look similar in one modality but still be wrong in label format, reasoning structure, or answer type.

Manual curation deals with that problem by inspecting examples carefully, but it is expensive and task-specific. Pure similarity retrieval deals with scale, but it does not reason about structural fit. The paper builds an agentic loop so that retrieval, alignment, and revision happen together.

The key issue: Fast retrieval is not enough, because the context must also be structurally compatible with the target task.

The algorithm as a flow

What it actually does

Build a retrievable example store

The system indexes multimodal examples so that candidate context items can be fetched efficiently when a new task arrives.

Retrieve candidate examples

Initial retrieval gathers plausible items from the store because broad coverage is needed before the system can curate the final set.

Check structural alignment

The context manager evaluates whether the candidates match the target task's format and reasoning pattern so that superficial similarity does not dominate selection.

Use the Operational Grammar Graph to pick tool actions

The tool graph decides whether to retrieve more items, reorder the set, or replace mismatched examples because context construction is treated as a sequential control problem.

Close the loop with downstream feedback

If the current context performs poorly, the workflow revises its strategy so that the final prompt is adapted to the task instead of frozen after the first retrieval.

What the paper changes

What the paper changes

The paper changes context selection from a one-shot retrieval problem into a closed-loop orchestration problem. The system does not simply fetch nearest examples; it actively refines the context through tool use and feedback.

The hidden quantity

The hidden quantity: context fitness

measured quantity  =  Joint quality of an example set for the target task

The useful property of a context is not the similarity of each example in isolation. It is the quality of the set as a whole for the current task. That hidden quantity includes relevance, structural compatibility, noise level, and budget use.

A set of examples can look individually plausible and still be poor overall. One item may use the wrong output format, another may duplicate the same failure mode, and a third may consume too much prompt space while adding little new guidance. ContextNav tries to estimate and improve this full-set fitness through its closed-loop manager, because the model responds to the whole prompt rather than to each example in isolation.

This quantity matters because in-context learning is sensitive to the entire prompt. The task is not merely to find close neighbors. The task is to assemble a set that teaches the model the right mapping under a limited context budget.

Why it works

Why closed-loop context construction beats one-shot retrieval

One-shot retrieval fails because similarity is only a partial signal. It can find examples that look close in visual content or wording, but it cannot guarantee that the example teaches the right answer format or reasoning pattern. ContextNav improves this by inserting decision points after retrieval.

The context manager checks structural alignment, noise, and budget use, then the Operational Grammar Graph chooses what to do next. That choice might be to keep the current set, replace weak items, search for a different type of example, or reorder the context. This helps because context quality depends on interactions among examples, not just on the first retrieval score.

The closed loop also uses downstream feedback. If the current prompt performs poorly, the system changes strategy. That matters because prompt construction is a sequential optimization problem: good context often emerges after revision, not after the first attempt.

Math after the picture

A compact objective for context quality

First in words:

Choose the context set that maximizes task value while penalizing noise and context cost.

Then the compact form:

C^* = argmax_C [ Score_task(C) - lambda * Noise(C) - mu * Cost(C) ]

Every symbol:

Ca candidate set of multimodal context examples
Score_task(C)estimated usefulness of context set C for the target task
Noise(C)amount of structural mismatch or irrelevant content in C
Cost(C)resource use such as prompt length or retrieval expense
lambdaweight on the noise penalty
muweight on the cost penalty
A tiny worked example
Suppose context set A has task score 9, noise 3, and cost 2.
Suppose context set B has task score 8, noise 1, and cost 2.
With lambda = 1 and mu = 0.5, set A gets 9 - 3 - 1 = 5.
Set B gets 8 - 1 - 1 = 6.
The system prefers B because the cleaner structure offsets the slightly lower raw similarity score.

The point is not the exact formula. The point is that context quality must balance usefulness, noise, and resource limits together.

What can go wrong

What can go wrong

The example store may be weak. If the underlying retrievable pool lacks enough high-quality multimodal examples, the workflow cannot build a strong context because no amount of orchestration can invent missing coverage.
Feedback may be noisy or delayed. If downstream signals do not reflect true context quality, the grammar graph can choose poor revision steps because it is optimizing the wrong guidance.
The loop can spend too much budget on revision. Repeated retrieval and replacement may improve the prompt only slightly while consuming too much time or context budget, so the stopping rule matters because the extra search can cost more than the small gain is worth.
Done right: the context becomes both scalable and clean. When the retrieval pool is broad and the alignment checks are reliable, the workflow helps because it combines automated coverage with active curation.
What a runnable demo should prove

What a runnable demo should prove

Build a multimodal benchmark with several tasks that require few-shot prompting, such as visual question answering, chart reading, and image classification with textual labels. Compare three context builders: manual selection, nearest-neighbor retrieval, and a ContextNav-style closed loop with retrieval, alignment checking, and revision. Keep the same context budget for all three. The demo should show that the closed-loop system produces higher task accuracy because it filters noisy examples and improves structural fit before the final prompt is used.

context_gain = task_accuracy_with_context_builder - task_accuracy_with_no_context

The main evidence should be better few-shot task performance at the same prompt budget, because that would show the context itself is better.
