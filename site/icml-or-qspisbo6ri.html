GeoFlow: Using Geography to Predict Where People Travel

When predicting how many people travel between neighborhoods, adding geography (distance, direction, location) to a graph model makes it far more accurate.

Paper explainersAll themesTime Series & Sequential

Urban planners need to know how many people will travel between different neighborhoods tomorrow. Most models treat neighborhoods like abstract nodes in a graph, ignoring where they actually sit on the map. This paper adds geographic information—exact distances and directions—to the model. This helps it learn real-world travel patterns better because travel is fundamentally local: people travel between nearby places far more often than distant ones, a fact the model can exploit. It also generates realistic new travel samples because the learned geography ensures synthetic patterns respect distance constraints that real data obeys.

Zero assumption version

The world before GeoFlow

Urban planners and transportation companies need to predict how many people will travel from neighborhood A to neighborhood B tomorrow. This is called origin-destination (OD) flow prediction—the 'origin' is where you start, the 'destination' is where you end up.

Today's best models represent neighborhoods as dots in a graph, connected by edges. The model learns which connections matter by looking at historical travel data. But here is the problem: the graph has no memory of where these neighborhoods actually are. It does not know if two neighborhoods are 5 kilometers apart or 50 kilometers apart. It does not know the compass direction from one to the other. This blindness makes the model miss obvious patterns. People rarely travel 100 kilometers for a daily commute, but the model has to learn this the hard way from data, if at all.

A person trying to fix this might naively add the raw distance numbers to the model's input. But that does not work well, because a model trained only on one city may have learned that 'distance 10' means something different than a model trained on another city with different geography. The model becomes brittle and does not transfer between cities.

The paper's move in one sentence. Add real geographic information—actual distances, directions, and positions on a map—to the graph model using specially designed layers. This works because distance and direction are universal features of travel: they apply the same way in every city, so a model trained on one city transfers better to another.

The algorithm as a flow

What it actually does

Encode neighborhood position

Represent each neighborhood as a list of numbers capturing its exact latitude/longitude on the map.

Measure distances and directions

Compute straight-line distance and compass direction between every pair of neighborhoods.

Fuse geography into graph connections

Use graph attention (paying more to nearby neighbors) combined with coordinate-aware math that understands relative position.

Let the model predict flow

Train on historical travel data; the model learns that proximity, direction, and connectedness all matter.

Generate new plausible travel patterns

Use flow matching (a diffusion-like method) to create new synthetic travel patterns that respect the learned geography.

What the paper changes

What the paper changes

The paper changes how neighborhoods are represented inside the model. Instead of just abstract nodes in a graph, each neighborhood now carries geographic coordinates—its exact position on the map. These coordinates flow through special encoder layers (the 'geometric-intrinsic fusion') that fuse map-aware math with the graph structure.

the object it moves  =  neighborhood representation
The hidden quantity

The geography relevance score

measured quantity  =  how much each distance and direction matters

The paper measures something new: which geographic features (distance, direction, multi-hop hops along the road network) actually matter for predicting travel. In an old graph model, all edges are treated roughly equally. But in real cities, nearby neighborhoods exchange far more travelers than distant ones—and the paper quantifies this using the attention weights inside the specialized fusion encoder.

The model learns these weights from data. A high attention weight on 'relative position' for a neighborhood pair means geography is driving the prediction. A low weight means graph connections matter more. By examining which geographic features get the highest weights after training, we see what the model actually considers predictive.

Why it works

Why adding geography helps

The core insight: travel is fundamentally a problem of space. People travel between nearby places far more often than distant ones because nearby places share infrastructure, employers, and daily routines. Adding this fact as an inductive bias (a built-in assumption) to the model makes it learn faster, because the model no longer wastes training steps figuring out 'distance matters'—we told it upfront. It generalizes better because the same principle holds in every city: a model trained on New York will not have to re-learn that distance matters when applied to San Francisco.

The mechanism works in two stages. First, the model encodes each neighborhood's position as a list of numbers (coordinates). Second, it computes the geographic distance and direction between every pair of neighborhoods—this is pure math, not learned. Third, special encoder layers combine these fixed geographic measurements with learned graph connections: the graph attention layer asks 'which neighbors are structurally connected?', while the coordinate-aware layers ask 'which are nearby on the map?'. The model fuses both signals, learning which one matters more for each pair.

Why does this work? Because the model no longer has to burn training data learning that 'distance matters'—we already told it that geographic proximity is important. This freed-up capacity lets the model focus on subtler patterns, like how different parts of the city interact or how travel changes with time of day. The model also generalizes to new cities better, because the same geographic principle (people travel locally) applies everywhere.

Math after the picture

The fusion equation

First in words:

The model combines geographic signals and graph signals: for each neighborhood pair, compute attention based on both map distance and graph connection, then blend them. Geographic signal weight plus graph signal weight determine the final prediction.

Then the compact form:

pred = alpha * attention_geographic(dist, dir, geodesic) + (1 - alpha) * attention_graph(neighbors) ; alpha learned per pair from data

Every symbol:

predpredicted travel count between two neighborhoods
attention_geographichow much the model pays to distance, direction, and map position
diststraight-line distance between neighborhoods in kilometers
dircompass direction (angle) from origin to destination
geodesicactual road-network distance (longer than straight-line)
attention_graphhow much the model pays to graph edges and connections
neighborsshared connections in the transportation network
alphalearned weight (0 to 1) saying how much to trust geography vs graph structure
A tiny worked example
Neighborhoods A and B: distance 5 km, both highly connected in the network.
Geographic attention (maps says 'close!') = 0.8.
Graph attention (graph says 'connected!') = 0.7.
Suppose alpha = 0.6 (the model learned geography is more important here).
Prediction = 0.6 * 0.8 + (1 - 0.6) * 0.7 = 0.48 + 0.28 = 0.76.
The model gives this pair a high prediction score because both signals agree: it is close and connected.
Neighborhoods C and D: distance 50 km, connected in graph.
Geographic attention = 0.1 (maps says 'far').
Graph attention = 0.8 (graph says 'connected').
Prediction = 0.6 * 0.1 + 0.4 * 0.8 = 0.06 + 0.32 = 0.38.
Lower score: even though the graph says connected, distance overwhelms the prediction (when alpha weights geography more).

The equation says: trust geography and graph structure differently depending on what the data reveals; the model learns alpha for each pair, so it adapts to each city.

What can go wrong

What can go wrong

Map data is missing or wrong. If you do not have accurate neighborhood locations or road distances, the geographic signals are garbage. GeoFlow amplifies bad geography into bad predictions.
The city has unusual geography (islands, mountains, walls). Straight-line distance or even road distance may not capture the barrier. A bridge or tunnel opens a short path where geography suggests none. The model learns from data, so it adapts, but it needs enough examples of 'unusual but real' routes.
Travel patterns are not geography-driven. Some travel is purely social (people visit friends in distant neighborhoods) or economic (jobs cluster far from homes). Geography alone cannot explain these. The model tries, but fails on the unexplained variance.
Done right: use GeoFlow when geography is a strong signal. In most cities, distance, direction, and road networks are primary drivers of travel. GeoFlow works best when that is true, as it is for daily commutes, shopping trips, and leisure visits within a metropolitan area.
What a runnable demo should prove

What a runnable demo should prove

Build a small simulation: take a real city (or synthetic grid of neighborhoods), train GeoFlow on past travel counts, then compare its predictions on held-out data against a graph model with no geography. Measure accuracy on short-range and long-range pairs separately. Also, generate 1000 synthetic travel samples from each model and check: does GeoFlow's generative samples look like real travel (clustered, local-heavy) or random noise (uniform)? Does the naive model produce unrealistic long-distance travel?

accuracy = (predicted_short + predicted_medium + predicted_long) / 3 ; realism = fraction of samples within observed distance distribution

The demo must show that adding geography makes short-range predictions far more accurate because the model learns distance-weighted attention, long-range predictions plausible because realistic geography constraints filter out unrealistic guesses, and generated samples look like real human travel patterns because the learned distance bias makes the generative process respect real-world sparsity.
