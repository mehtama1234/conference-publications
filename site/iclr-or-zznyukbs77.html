Debugging Concept Bottleneck Models

When interpretable models make mistakes because they learned shortcuts from biased data, experts can remove bad concepts and retrain the model using the concepts they remove as a guide to fix the problem.

Paper explainersAll themesInterpretability

Machine learning models that explain themselves through human-readable concepts are useful — they let experts verify the model is reasoning correctly and even fix bad predictions by hand. But when a model learns shortcuts from biased training data (like predicting a disease from the background of a medical image instead of the actual symptom), fixing individual predictions is not enough. This paper shows how to use concept-level feedback to rebuild the model's foundation.

Zero assumption version

Good explanations, broken shortcuts

Concept Bottleneck Models are a special kind of model: instead of making predictions directly from raw data like images, they first identify a set of human-friendly concepts (for medical images: tumor shape, size, location, tissue density), then predict the final answer from those concepts. This is useful because an expert can look at the concept values, see if they make sense, and even override them at test time.

But here is the trap: if the training data has a systematic bias (all large tumors are cancerous, all small ones are benign), the model learns a shortcut. It stops looking at actual features and starts predicting tumor size from image background or noise. When an expert intervenes on the concept, it fails silently — the model still has not learned the true pattern. The problem is not surface-level wrong predictions; it is deep structural misalignment between what the model learned and what the expert believes should matter.

The challenge. Concept-level intervention only works if the model learned the right concepts from the right reasons.

The algorithm as a flow

What it actually does

Expert audit

Examine the learned concepts and spot which ones are shortcuts or unreliable.

Mark for removal

Flag the bad concepts (e.g. background-based size) as candidates to rebuild.

Convert to sample labels

For each removed concept, generate synthetic labels that teach the model to ignore it.

Supervised retraining

Retrain the predictor part with bias-mitigation techniques, using the synthetic labels as guidance.

Verify

Check that the model now predicts correctly and the expert concepts align with real patterns.

What the paper changes

What the paper changes

The paper changes how the model predictor uses concepts after an expert has flagged some of them as untrustworthy. Instead of just accepting the expert's label and hoping the model relearns, CBDebug creates artificial training samples that teach the predictor to work correctly without the removed concept — for instance, feeding it shape and texture clues without relying on the size signal the model used as a shortcut.

The hidden quantity

The alignment gap

measured quantity  =  concept reliability mismatch

The paper measures an invisible problem: the gap between what the expert thinks the model learned (size is predicted from anatomy) and what the model actually learned (size is predicted from background noise). This gap is invisible in single predictions — the model says size=large, which looks right — but shows up when the expert tries to intervene and it fails to fix the problem.

CBDebug detects this by having the expert remove a concept and then checking whether the predictor collapses without it. If the predictor relies entirely on the removed concept, the model had not learned any other way to make the prediction. The paper uses this diagnostic to guide retraining: it ensures the predictor can predict without the removed concept by training it on modified samples.

Why it works

Why the method heals the model

The trick is to turn a concept-level diagnostic (expert says this concept is broken) into a sample-level training signal. When an expert removes a concept, CBDebug creates synthetic labeled samples where that concept is replaced by a neutral or contradictory value, but the target label stays the same. For instance, if the expert removes size, the retraining data includes pairs: (shape=normal, texture=normal, size=large, label=normal) and (shape=normal, texture=normal, size=tiny, label=normal). The predictor sees that size does not matter for predicting the label — only shape and texture do.

This works because the predictor part of the model is a standard classifier trained on labeled data. When it sees the same label with many different values of the removed concept, it stops using that concept as a crutch. The paper applies supervised bias-mitigation techniques (like data augmentation focused on the gap regions) to ensure the model learns patterns that hold across different types of training data, not just within the narrow shortcut.

Math after the picture

The retraining formulation

First in words:

loss_retraining = supervised_loss(predictor(concepts_modified), labels_auxiliary) + augmentation_penalty(coverage_of_distribution_gaps)

Then the compact form:

L_retrain = sum_i [ L_ce(f(c_i_modified), y_i) + lambda * d(c_i_modified, c_i_removed) ]

Every symbol:

f(c)the predictor function applied to concept values
c_i_modifiedconcept values for sample i with removed concepts set to a varied or neutral value
y_ithe ground-truth label for sample i
L_cethe cross-entropy loss (the standard way to measure prediction error for classification)
lambdathe strength of the penalty that encourages coverage of removed-concept values
d(·,·)a distance measure (e.g. L2 distance) between modified and original concept values
A tiny worked example
Sample 1: original concepts = (shape=normal, size=large), label = disease_present.
Modified sample: (shape=normal, size=tiny), label = disease_present (unchanged).
Predictor output for modified: confidence in disease = 0.45 (wrong, because it expected size=large).
Cross-entropy loss: L_ce = -log(0.45) = 0.798.
Distance penalty (size changed by 0.4 on a 0-1 scale): d = 0.4, so lambda * d = 0.3 * 0.4 = 0.12.
Total loss for this sample: 0.798 + 0.12 = 0.918.
Training pushes predictor weights to ignore size and rely on shape, reducing loss.

The loss combines two signals: standard prediction error on the modified samples (teaching the predictor to predict without the removed concept) and a penalty that ensures the model sees enough variation in the removed concept to learn to ignore it.

What can go wrong

What can go wrong

Expert marks the wrong concept. If the expert removes a concept that is actually honest and necessary (not a shortcut), retraining makes the model worse. The method assumes expert feedback is correct.
Removed concept is too entangled with others. If size is correlated with shape (which it often is in real data), removing size and retraining may accidentally degrade shape prediction too. The synthetic samples have to be carefully generated to break the correlation.
Not enough diversity in retraining data. If the augmented samples do not cover enough combinations of concept values, the predictor may learn another shortcut instead of the true pattern.
Done right. Expert audits the concepts carefully, CBDebug generates diverse synthetic samples, and retraining produces a predictor that works correctly and the expert can trust.
What a runnable demo should prove

What a runnable demo should prove

Build a toy concept bottleneck model on a biased dataset (for instance, classify disease from medical images where size is correlated with disease label in training, but not in test). Train the base model and show that it achieves high accuracy on test data with the same bias, but fails on test data where the correlation is broken. Then run CBDebug: have it remove the size concept, generate synthetic retraining samples, and retrain the predictor. Measure accuracy on both test sets. The demo should show that CBDebug works across both scenarios — high accuracy on both biased and unbiased test data — while the base model only works on biased data.

robustness_gain = (test_acc_unbiased_after - test_acc_unbiased_before) - (test_acc_biased_after - test_acc_biased_before)

The demo must make it obvious that the debugged model generalizes beyond the shortcut, while the undebugged model breaks when the bias is removed.
