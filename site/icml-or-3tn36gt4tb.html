MoSSP: Momentum-Based Stochastic Penalty for Constrained Optimization

A single-loop method using random mini-batches that solves constrained optimization problems where the cost has a special two-part structure by adding penalty terms and momentum to keep solutions on track.

Paper explainersAll themesOptimization

When you have a large learning problem with constraints that must be satisfied, existing methods either run in nested loops (slow) or ignore the special structure of the cost function. MoSSP solves this by wrapping the entire problem — constraints and all — into one efficient loop with momentum, without sacrificing mathematical guarantees.

Zero assumption version

The nested-loop trap in constrained learning

When you train a model with constraints (for example, a classifier that must also stay fair across groups, or a regressor that must satisfy bounds), you face a hard choice. You can solve the constraint inside a loop (update the model, check the constraint, adjust, repeat) but this takes forever on large datasets. Or you can ignore the special structure of your cost function and use a generic method, which throws away information and becomes inefficient.

A beginner might try running the full constraint check and solution step inside each training iteration — nested loops. This is mathematically sound but glacially slow. The real problem: nobody has figured out how to finish all the constraint work in just one pass per step, with mathematical guarantees that you will actually converge.

The method. Add penalty terms (soft constraints) to the cost, take steps using random mini-batch data toward lower cost by wrapping the problem with its penalty, and use momentum to keep from wandering off the feasible region.

The algorithm as a flow

What it actually does

Wrap the problem

Add soft penalty terms that push toward feasibility as part of the cost.

Draw a sample

Pick a random mini-batch from your data; the pattern in it points the direction toward lower cost, because the error on that small sample reflects the overall error direction.

Proximal step

Move toward lower cost using the direction shown by mini-batch data, then resolve any hard constraint via a projection, because one step moves you and the projection snaps you back to legal territory.

Apply momentum

Update the step using past movement history to smooth out randomness, because averaging multiple noisy directions cancels noise and leaves the true direction.

Repeat

One loop per iteration; no inner solve needed.

What the paper changes

What the paper changes

The paper changes the constraint-handling mechanism itself. Instead of solving constraints in a nested inner loop, it folds them into the cost function via penalty terms and solves the augmented problem with a single step per iteration that uses a technique called proximal mapping to handle hard constraints alongside the cost reduction.

The hidden quantity

The KKT gap — how close you are to the solution

measured quantity  =  KKT (Karush-Kuhn-Tucker) gap

The KKT conditions are a set of equations that a true solution must satisfy. They check three things: the gradient is zero (or balanced by constraints), the constraints are satisfied, and the penalty terms are in the right direction. The KKT gap measures how far you are from meeting all three at once — it is not just whether your cost is low, but whether you have actually solved the constrained problem correctly.

The paper proves that MoSSP finds points where this gap shrinks to a target size epsilon in a finite number of gradient samples. This is the hidden quantity being controlled: not final accuracy (which is easy to fake by running longer), but the actual mathematical proof that you are near the solution.

Why it works

Why penalties plus momentum solve the problem

The core insight is that you can turn a constrained problem into an unconstrained one by adding penalty terms to the cost. When you violate a constraint, the penalty jumps up; when you satisfy it, the penalty vanishes. A single step based on random mini-batch data naturally pushes you toward both low objective and feasibility in one shot.

Momentum is the second ingredient. Because you are using random mini-batches, each step direction estimate is noisy. Without momentum, this randomness causes you to zig-zag and converge slowly. Momentum averages past steps, so noise cancels out and you march steadily toward the solution. The combination — penalties that unify the goal, plus momentum that smooths randomness — lets you solve constrained problems in one loop with the same efficiency as unconstrained methods.

Math after the picture

The optimization step with penalty and momentum

First in words:

x_new = (1 minus beta) times x_current plus beta times result, where result is the penalty-wrapped cost with a proximal step

Then the compact form:

x_t+1 = (1 - beta) * x_t + beta * prox_step( gradient_of(f_convex + penalty * g_concave) )

Every symbol:

x_tcurrent model weights
x_t+1new weights after this step
betamomentum strength, between 0 and 1
f_convexthe easy part of the cost to minimize
g_concavethe hard part (concave), applied as a penalty
penaltyweighting on how much we care about constraints
prox_stepprojection that handles hard constraints
A tiny worked example
Say current weights are x_t = 0, and the gradient of the wrapped cost is 2.0 (pointing toward lower cost).
Take a step: gradient_step = 0 - 0.1 * 2.0 = -0.2 (we moved in the negative direction by 0.1 times the gradient).
Apply momentum with beta = 0.9: x_new = (1 - 0.9) * 0 + 0.9 * (-0.2) = -0.18.
Because beta is high, momentum is strong: we move 0.18 in the direction suggested, not a full 0.2. This is the averaging effect.

The penalty term ensures that each step implicitly makes progress toward feasibility, while momentum prevents random noise in the gradient from throwing you off track.

What can go wrong

What can go wrong

Penalty weight too high. If the penalty term dominates the cost, the optimizer spends all effort on feasibility and ignores the main objective. The solution is feasible but far from optimal.
Penalty weight too low. If the penalty is weak, constraints are violated with impunity and the algorithm drifts into infeasible regions. You must tune this by hand.
Nonsmooth concave part. The theory assumes the hard part of the cost can be handled by a proximal mapping; if it is pathological, the algorithm may stall.
Done right: adaptive penalty and strong momentum. Start with a modest penalty and increase it as the algorithm runs, or choose it based on problem structure. Use momentum strong enough to smooth randomness (beta close to 0.9) but not so high it lags behind sharp turns. With both calibrated, the method converges reliably.
What a runnable demo should prove

What a runnable demo should prove

Set up a constrained least-squares problem: minimize squared error subject to the solution staying within a ball (an upper bound on weight magnitude). Implement MoSSP with two variants — vanilla Polyak momentum and recursive momentum — and compare to a standard nested-loop solver on the same problem over 1000 iterations. Measure the KKT gap (how close to satisfying the conditions) and the total computation time. MoSSP should converge faster because it avoids nested loops, and the recursive variant should beat Polyak momentum because it refines the momentum calculation to track the problem more precisely.

kkt_gap = || gradient_of_objective + penalty_weights ||_2 + constraint_violation_sum

MoSSP should reach the same KKT gap in half the iterations and solve the problem in one-third the wall-clock time.
