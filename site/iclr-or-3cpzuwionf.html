A$^2$Search: Ambiguity-Aware Question Answering with Reinforcement Learning

A2Search trains a question-answering agent to return multiple evidence-supported answers when a question is genuinely ambiguous instead of forcing one answer to imitate a single reference string.

Paper explainersAll themesOther

Open-domain question answering is usually trained as if every question has one correct answer. Many real questions do not. They permit several valid answers, especially in multi-hop settings where different evidence chains can support different conclusions. If training rewards only one reference answer, the model gets penalized for being correct in the wrong way. A2Search fixes that mismatch. It automatically collects alternative answers, checks them against evidence, groups equivalent ones, and then trains the model with a reward based on answer overlap rather than single-answer exact match. The point is not to make the model hedge. The point is to reward it for surfacing all evidence-supported answers when ambiguity is real.

Zero assumption version

Why single-answer training gives the wrong signal

A standard QA benchmark stores one reference answer. During training, the model is rewarded for matching that answer and penalized for other outputs. That rule is fine when the question is unambiguous. It is wrong when several answers are valid. The model can retrieve correct evidence, follow a valid reasoning path, and still be marked wrong because its answer string differs from the reference.

This hurts twice. It understates model capability at evaluation time, and it teaches the policy to collapse toward one answer even when the evidence says several answers should be returned. Multi-hop datasets amplify the problem because they create more places where several evidence chains can branch into several acceptable outputs.

The mismatch is in the reward. If the environment rewards only one reference answer, the agent learns to suppress valid alternatives rather than represent ambiguity.

What the paper changes

What the paper actually changes

A2Search changes the supervision target and the RL reward. The target is no longer one reference answer. It is a verified set of distinct valid answers for ambiguous questions. The reward then measures overlap with that set, so the agent is trained to expose ambiguity instead of hiding it.

the object it moves  =  answer supervision: from single reference to verified answer set
The hidden quantity

The hidden quantity: ambiguity ratio

measured quantity  =  How often a benchmark question has more than one valid answer

A dataset can look single-answer on paper while behaving multi-answer in practice. The relevant hidden quantity is the ambiguity ratio: how often a question admits several evidence-supported answers. If that ratio is large, single-answer training creates a systematic reward error rather than a rare corner case.

The paper estimates this ratio by generating candidate trajectories, verifying answers against evidence, and counting questions that retain more than one distinct valid answer after grouping. The introduction reports that 27.6 percent of MuSiQue training examples show this property.

Why it works

Why automatic answer-set construction changes the policy

Sampling multiple trajectories matters because ambiguity often reveals itself through diverse valid reasoning paths. If the system sees only one rollout, it may never encounter the alternative answer even when the evidence supports it. Multiple trajectories widen the search over both retrieval choices and reasoning chains.

Verification matters because multiple outputs alone do not imply real ambiguity. Some are simply wrong. Evidence-based filtering separates alternative answers that can be supported independently from answers that are unsupported noise. Grouping then removes wording duplicates, so the supervision set captures distinct semantics rather than paraphrase volume.

The AnsF1 reward matters because it aligns the policy objective with the answer-set objective. Under exact match, the safest policy is to guess one reference answer. Under answer-level F1, the agent gets graded on overlap with the verified answer set. That changes behavior because returning one supported answer no longer blocks credit for another supported answer, and unsupported extras still hurt precision.

Math after the picture

The reward signal

First in words:

AnsF1 balances precision and recall over the set of predicted answers against the verified set of valid answers.

Then the compact form:

AnsF1 = 2 * precision * recall / (precision + recall)

Every symbol:

precisionof the answers the model returned, the fraction that are valid
recallof the valid answers in the verified set, the fraction the model returned
AnsF1a single score that rewards covering valid alternatives without adding unsupported ones
A tiny worked example
Suppose the verified answer set is {A, B}.
A baseline model returns only A. Precision is 1/1 = 1.0 and recall is 1/2 = 0.5, so AnsF1 is 0.67.
A2Search returns A and B. Precision is 2/2 = 1.0 and recall is 2/2 = 1.0, so AnsF1 is 1.0.
If the model returns A, B, and an unsupported C, precision drops to 2/3 while recall stays 1.0, so AnsF1 falls.
The reward therefore pushes the policy toward complete but evidence-grounded answer sets.

This reward differs from exact match because partial coverage of a valid answer set receives partial credit instead of total failure.

What can go wrong

What can go wrong

Verification misses a valid answer. If the evidence checker fails to approve a real alternative, the reward set is incomplete, because the model is still being trained against a partial target for correctness.
Grouping merges distinct answers. If two genuinely different answers are treated as the same group, recall is overstated and the policy loses pressure to surface the full answer set.
Ambiguity can be mimicked by hallucination. A model may learn to output several answers whenever it is uncertain. That behavior is still wrong unless each answer is evidence-supported, which is why the verification stage and precision term matter.
Done right. The framework is strongest when trajectory diversity is high and evidence verification is strict, because then the answer set reflects genuine ambiguity rather than output noise.
What a runnable demo should prove

What a runnable demo should prove

Take a multi-hop QA subset with known ambiguous cases. Run a search-based model to sample several trajectories per question, verify alternative answers against retrieved evidence, and build answer sets. Then compare exact-match RL against AnsF1-based RL. The demo should inspect a few questions by hand to show that multi-answer outputs are supported rather than speculative.
