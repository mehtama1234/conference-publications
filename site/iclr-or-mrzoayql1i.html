A Biologically Plausible Dense Associative Memory with Exponential Capacity

Replace winner-take-all hidden activity with thresholded multi-unit activity so one memory can be built from reusable parts instead of being tied to one hidden unit.

Paper explainersAll themesOther

An associative memory stores patterns and later retrieves the full pattern from a partial or noisy cue. Classical Hopfield-style systems can store many patterns, but each design hits a capacity limit that comes from how many distinct stable states it can maintain. Earlier biologically plausible dense associative memories already reached capacity exponential in the number of visible neurons, yet capacity stayed only linear in the number of hidden neurons because hidden activity used winner-take-all competition: one hidden neuron won, the rest were shut off, and each winner stood for one whole memory. This paper changes that bottleneck. It uses a threshold rule so several hidden neurons can stay active together, which means a memory can be represented as a combination of reusable parts rather than a single dedicated unit.

Zero assumption version

Why one-hidden-unit-per-memory wastes capacity

An associative memory should do two things at once: keep many stored patterns stable, and retrieve the right one when the input is incomplete or corrupted. A standard way to make retrieval stable is to define an energy function so updates always move downhill until the system settles into a stored pattern. The trouble is that the number of stable patterns depends on the form of the hidden-layer rule, not just the number of neurons.

In the earlier dense associative memory, hidden neurons competed so strongly that only one hidden neuron was active for each stored item. That creates a hard ceiling. If each hidden neuron can stand for only one memory, then adding hidden neurons increases storage only one memory at a time. Correlated memories also become wasteful because shared structure cannot be reused: two memories that differ in one detail still need separate winners.

The paper asks a sharper question: what if hidden neurons encoded reusable components instead of whole memories? Then one memory could be built from a binary pattern over many hidden neurons, and the number of possible hidden codes would grow exponentially with hidden width rather than linearly.

In one sentence. Capacity rises because the paper stops forcing one hidden neuron to own one memory and instead lets many hidden neurons participate together under a threshold rule.

The algorithm as a flow

What it actually does

1. Store visible-to-hidden weights

Learn weights connecting visible neurons to hidden neurons so each hidden unit responds to a recurring component of the data.

2. Replace hard competition with a threshold

A hidden unit turns on only when its input exceeds a fixed cutoff, which means several hidden units can be on together.

3. Form a hidden binary code

Each memory cue produces a pattern of on and off hidden units instead of a single winner.

4. Reconstruct the visible pattern

The active hidden units send their learned signals back to visible neurons so the full memory is rebuilt from the shared components.

5. Iterate to a stable state

Repeated visible and hidden updates settle to a fixed pattern because the energy keeps decreasing under the chosen update rule.

What the paper changes

What the paper changes

The paper changes the hidden-layer firing rule, which means the rule that decides whether a hidden neuron fires. That single change switches the system from exclusive hidden activity to distributed hidden activity.

the object it moves  =  the hidden firing rule
The hidden quantity

The hidden quantity: number of stable hidden codes

measured quantity  =  how many distinct hidden on-off patterns can remain self-consistent under the update rule

The visible pattern is what we observe, but the real storage budget lives in the hidden layer. Each self-consistent hidden code is a candidate memory because it can drive the visible layer to a matching pattern and be recovered again on the next update. Under winner-take-all dynamics, the only valid codes are the one-hot codes, where one hidden unit is on and the others are off. There are only as many such codes as hidden neurons.

Under a threshold rule, every binary pattern that meets the consistency conditions can become a stable hidden code. That is the source of the exponential jump. With H hidden neurons, there are up to 2^H possible on-off patterns. The paper shows that, when the visible layer is large enough to support those patterns, many or all of them can become valid attractors rather than impossible combinations.

This hidden quantity also explains why correlated memories fit better, because shared parts can map to the same hidden units across memories. Storage is then spent on reusable structure rather than duplicated whole-pattern winners.

Why it works

Why thresholded hidden activity changes the scaling law

Winner-take-all dynamics solve competition by forcing a single best hidden unit to represent the input. That can sharpen retrieval, but it destroys combinatorial reuse because the network cannot express a memory as part A plus part B plus part C. The storage law then scales with the number of possible winners.

The threshold rule solves a different problem. Each hidden unit independently checks whether its input support is strong enough to turn on. If several components are present in the cue, several hidden units cross threshold together. The memory is therefore encoded by the whole firing pattern, not by one unit. That matters because the number of possible patterns grows exponentially with hidden width.

Retrieval still stays stable because the network keeps the associative-memory energy structure. Visible neurons push evidence into hidden units, thresholding selects a consistent subset, and the active subset pushes back to visible neurons. If the learned weights were arranged so that a hidden code and its visible reconstruction support each other, repeated updates return to that pair after perturbation.

The approach is also biologically plausible in the paper's sense because thresholding and local interactions are easier to justify as neuron-like operations than a global winner-take-all step that requires comparing all hidden units at once.

The thresholded hidden update

First in words:

A hidden unit turns on when the weighted sum of visible inputs is larger than a threshold, and the visible pattern is reconstructed from the active hidden units.

Then the compact form:

h_i = 1 if sum_j W_ij v_j > tau, else 0; v_j' = sign(sum_i W_ij h_i)

A tiny worked example
Suppose there are three visible neurons with states [1, 1, -1].
Hidden unit 1 receives weighted input 2.3 and hidden unit 2 receives 2.1, while the threshold is 2.0.
Both hidden units turn on because both weighted sums exceed the threshold.
A winner-take-all rule would have kept only one of them, but the threshold rule keeps both and therefore stores the pattern as a two-part code.
During reconstruction, the two active hidden units vote back to the visible layer, so the recovered visible pattern uses evidence from both parts of the memory instead of only one.

The extra capacity comes from the number of possible hidden on-off codes, because the threshold rule admits many multi-unit codes where winner-take-all admits only one-hot codes.

What can go wrong

What can go wrong

Threshold set too low. If the cutoff is too low, many hidden units turn on for nearly every cue. Codes become dense, different memories overlap too much, and retrieval can collapse into mixed states.
Threshold set too high. If the cutoff is too high, almost no hidden units activate. Then the system falls back toward sparse one-unit behavior and loses the combinatorial gain.
Visible layer too small for the intended hidden code set. The paper's scaling claim depends on the visible layer being large enough to support many distinct hidden codes. If visible width is too small, different hidden codes reconstruct to similar visible states and stability breaks.
Done right. Choose weights and threshold so multiple hidden units can activate for one memory while different hidden codes still reconstruct clearly distinct visible patterns. Then the network keeps the retrieval property and gains many more stable memories.
What a runnable demo should prove

What a runnable demo should prove

Build two small associative memories with the same visible layer and the same number of hidden neurons. Version A uses winner-take-all hidden updates. Version B uses the threshold rule. Train both on correlated binary patterns built from a small set of reusable components. Then measure how many patterns each system can store and still retrieve from noisy cues.

The demo should show two things. First, the threshold model stores more patterns because several hidden units can represent one memory jointly. Second, the stored hidden codes reveal reuse: related memories activate overlapping hidden subsets instead of completely different dedicated winners.

retrieval_accuracy = correct_recoveries / total_noisy_cues stored_patterns_per_hidden_unit = num_stable_memories / num_hidden_units

The result should make the scaling law visible: winner-take-all grows linearly because each hidden unit can stand for only one memory, while thresholded distributed codes grow much faster because many hidden on-off patterns become usable memories.
