GLEAN: Guideline-Grounded Evidence for Agent Verification

Verify an AI agent's clinical decisions by checking if each step follows expert guidelines, then blend those checks into a confidence score that knows when it is uncertain.

Paper explainersAll themesAgents & Tool Use

AI agents now make high-stakes decisions in medicine: diagnosing diseases, recommending treatments. Before we can trust them in hospitals, we need a way to know when the agent is right and when it is wrong. This paper builds GLEAN, a framework that checks whether the agent's reasoning at every step matches expert clinical guidelines, then combines those step-by-step checks into a single confidence score. The score tells you not just whether the decision looks correct, but also how sure you should be.

Zero assumption version

The verification problem: an agent says yes, but you need to trust it

Imagine a doctor is tired or in a hurry. They might miss a detail. An AI agent is different: it never gets tired, but it has been trained on patterns in past data, not on the actual experience of seeing patients. When the agent recommends a diagnosis or treatment, you do not know if it is reasoning correctly or just pattern-matching to something it has seen before. The old way to check: run the agent on a test set, measure how often it is right. But on rare diseases or edge cases, you have few examples to test on. The agent looks good on the test set but fails in the clinic.

What a beginner tries: just ask a different AI model to grade whether the agent's answer looks reasonable. But this second model is also trained on patterns in past data. It does not know the actual rules that hospitals follow: the explicit protocols, the checklists, the step-by-step guidelines that doctors trust. So the second model might say the agent's answer looks plausible when it actually violates a guideline that an expert would catch.

The real problem. Existing verifiers do not use domain knowledge and do not tell you how sure they are, so you cannot tell when to trust them and when to flag the agent's decision for a human expert to review.

The algorithm as a flow

What it actually does

Collect expert guidelines

Gather the explicit rules that an expert follows: if symptom A and lab test B, then check for C before deciding D.

Score each step of the agent's trajectory

For every decision the agent makes, ask: which guidelines does this step align with? Rate each alignment as a yes/no.

Aggregate guideline ratings

Combine all the yes/no ratings into features: e.g., percent of guidelines satisfied, which particular guidelines were violated.

Calibrate into a confidence score

Use Bayesian logistic regression (a way to build probabilities from data) to turn the guideline features into a final confidence: how sure should you be that this answer is correct?

Flag uncertain cases

If confidence is below a threshold, hand the case to a human expert to gather more evidence or double-check the reasoning.

What the paper changes

The one thing that changes: step-by-step guideline alignment

Instead of asking a verifier to just guess if the final answer is right, GLEAN makes the verifier check whether each intermediate step follows the expert guidelines. The object being changed is the verification signal: from a single yes/no guess to a structured set of yes/no ratings, one per guideline per step.

the object it moves  =  guideline alignment scores
The hidden quantity

The hidden quantity: calibrated confidence

measured quantity  =  how sure you can be that the decision is correct

Most AI models output a score between 0 and 1, but that score is not reliable. A score of 0.8 does not mean the answer has an 80% chance of being right; it might actually be right 95% of the time, or only 40% of the time. Calibration is the process of making that score honest: a score of 0.8 really means 80% chance of being right. GLEAN estimates this calibrated confidence by learning from examples: when the agent was right, what did the guideline-alignment features look like? When it was wrong, what did they look like?

The paper measures calibrated confidence using Bayesian logistic regression, a statistical technique that takes in features (the guideline-alignment ratings) and outputs probabilities. It learns the true relationship between guideline-alignment and correctness from training data.

Why it works

Why it works: guidelines encode domain knowledge that patterns cannot

An AI agent trained on past medical data learns to spot patterns, but patterns are not the same as understanding. A pattern might say: most patients with symptom X also have disease Y, so recommend Y. But an expert knows a hidden rule: always test for Z first, because Z and Y look similar on the surface. If the agent skips testing for Z, the agent is wrong, even if the final diagnosis is accidentally correct. A generic verifier (another AI model) does not know this hidden rule.

GLEAN works because it replaces the guessing with explicit rules. By checking guideline-by-guideline alignment, it asks: did the agent follow the explicit protocol? This is a harder question to get wrong, because the guidelines are written down and clear. The verifier is no longer trying to reverse-engineer expertise from patterns; it is just checking off a list. Bayesian logistic regression then learns the exact relationship: which guideline alignments matter most for real-world correctness? This gives the system a way to be honest about uncertainty: cases that do not fit the learned pattern get a lower confidence score, automatically flagged for human review.

Math after the picture

The equation: blending guideline checks into confidence

First in words:

confidence_score = sigmoid(intercept + weight_1 * guideline_1_align + weight_2 * guideline_2_align + ... + weight_n * guideline_n_align), where sigmoid turns the sum into a probability between 0 and 1

Then the compact form:

P(correct) = sigmoid(a + sum_i w_i * g_i)

Every symbol:

P(correct)probability the decision is correct, between 0 and 1
sigmoida function that squashes any number into a range from 0 to 1
athe intercept: the base confidence with no guideline information
w_ithe learned weight for guideline i, how much it matters
g_ithe alignment score for guideline i, usually 1 if aligned or 0 if not
sum_i w_i * g_ithe weighted sum of all guideline alignments
A tiny worked example
Suppose we have 3 guidelines. Learned weights: w_1=0.5, w_2=0.8, w_3=-0.3. Intercept a=0.2.
Agent trajectory: aligns with guideline 1 (g_1=1), aligns with guideline 2 (g_2=1), violates guideline 3 (g_3=0).
Weighted sum = 0.2 + 0.5*1 + 0.8*1 + -0.3*0 = 0.2 + 0.5 + 0.8 + 0 = 1.5.
sigmoid(1.5) ≈ 0.82. So the confidence score is 82%.
If the agent had violated guideline 2 (g_2=0): sum = 0.2 + 0.5 + 0 - 0.3*0 = 0.7, sigmoid(0.7) ≈ 0.67 = 67%. Missing a high-weight guideline drops confidence.

Sigmoid maps the weighted sum to a honest probability; Bayesian logistic regression learns the weights and intercept from training data, so the probabilities reflect real correctness rates.

What can go wrong

What can go wrong

Incomplete guidelines. If the expert guidelines do not cover all the reasoning paths the agent can take, GLEAN has no way to catch errors in uncovered territory. The system is only as good as the guidelines it has.
Domain mismatch. Guidelines written for one disease or patient population might not apply to another. If the agent is asked to diagnose a condition the guidelines were not written for, GLEAN cannot tell if the reasoning is sound.
Calibration on biased training data. If the training set used to calibrate the confidence scores does not represent real clinical diversity (rare cases, edge cases, different hospitals), the learned probabilities will be overconfident on data that looks different from training.
Done right. Guidelines are maintained as medicine evolves, GLEAN is retrained when clinical practice changes, and the system flags cases outside the guideline scope so a human expert knows to recheck them.
What a runnable demo should prove

What a runnable demo should prove

Build a small synthetic agent that diagnoses one of three diseases (e.g., pneumonia, bronchitis, asthma) based on symptoms and lab tests. Create 5-10 expert guidelines (if symptom A and lab B, look for C first; if lab D is negative, rule out E). Run the agent on 100 test cases where you know the true diagnosis. For each case, (1) collect the agent's decision and reasoning steps, (2) score each step against the guidelines (1 if follows, 0 if not), (3) use the guideline scores to predict correctness with Bayesian logistic regression trained on 50 calibration examples, (4) compute the confidence score, (5) compute what fraction of cases the system correctly flags as needing expert review.

calibration_error = mean( |predicted_confidence - actual_accuracy| ), where predicted_confidence is the output of GLEAN and actual_accuracy is whether the diagnosis was truly correct

The demo must show: cases GLEAN marks as 80% confident are correct about 80% of the time on the test set, while cases marked as 50% confident are right only 50% of the time. Without calibration, an ordinary verifier shows cases at 80% confidence but only 50% actually right (overconfident), or 50% confident but 90% right (underconfident). GLEAN matches its confidence to reality.
