MMPD: Multi-Mode Patch Diffusion Loss for Diverse Time Series Forecasting

A loss function that teaches models to predict multiple possible futures instead of just picking the single most likely one.

Paper explainersAll themesTime Series & Sequential

Forecasting real-world events like weather or stock prices is hard because often there is no single right answer—many different futures could happen. A standard approach uses Mean Square Error, or MSE, which assumes there is one correct answer and penalizes any guess that misses it. This paper proposes a new way to score predictions: instead of forcing the model to name one future, it learns to describe what the entire range of possible futures looks like and how likely each one is.

Zero assumption version

Why one-answer training breaks on real forecasts

A time series forecast is a guess about what number comes next—temperature tomorrow, stock price next week, electricity demand in an hour. The standard way to train is to show the model millions of past examples and measure how far its guesses were from the truth, using a simple penalty: square the error and average it. This is Mean Square Error, or MSE.

But in the real world, many futures are plausible. If you are forecasting tomorrow's weather at noon, it could be 72°F or 68°F or 75°F—all are reasonable given today's conditions. MSE forces the model to pick one 'best' answer, usually the average of all the realistic outcomes. When the real future turns out to be one of the extremes, the model loses hard. More importantly, the model never learns to describe the full range of what could happen.

The problem. Standard loss functions assume there is one true answer and penalize any guess that misses it, so they fail when many different futures are equally valid.

What the paper changes

What the paper changes

The paper replaces the loss function. Instead of computing an error penalty for each guess, it uses a diffusion model to score how well the model learns which outcomes are likely and which are rare. This teaches the backbone network to produce latent tokens (compressed information) that the diffusion model can use to describe the full set of plausible futures.

the object it moves  =  Loss function, from MSE to MMPD
The hidden quantity

The hidden quantity: Which outcomes are likely and which are rare

measured quantity  =  Likelihood of each possible outcome

The paper measures something standard loss functions never capture: for any starting condition, how many plausible futures exist, and how likely is each one? In everyday terms, this is asking which futures have high probability, which are moderate, and which are nearly impossible.

The paper estimates this quantity by training a diffusion model (one that learns to remove noise) conditioned on the backbone's latent tokens. By fitting a mixture of Gaussians (a simple model of several probability bumps) during diffusion, the method finds the modes—the most likely outcome clusters. Traditional MSE does not measure this at all; it only cares about predicting the single average outcome.

Why it works

Why learning the full distribution works

Standard MSE forces the model to predict the average outcome. If the real future is an extreme—say, a heat wave when cold and warm days were equally plausible—MSE penalizes hard, even though the model learned the range correctly. The model wastes capacity trying to hit the average instead of learning the full spectrum of possibilities.

MMPD turns the problem inside out. Instead of predicting a number and comparing it to one truth, the model learns to compress the past into latent tokens that describe the scenario. A diffusion model then builds a description of the probability distribution of futures using those tokens. When the model outputs latent tokens that capture enough information for the diffusion model to recover the true distribution, the loss is low—whether the actual future ends up in cluster A, B, or C. This way the model learns which features of the past point toward which clusters of futures, and it describes them all.

The Patch Consistent MLP is a small neural network (a shallow model with just a few layers) that ensures that when diffusion is building the future step by step, neighboring time chunks do not contradict each other. Time series have a natural flow—if minute 1 and minute 3 are coherent, minute 2 should not jump wildly between them. This consistency check works because it forces the diffusion model to keep time-adjacent patches compatible, which prevents it from generating futures that violate the natural continuity of real time series.

Math after the picture

The equation

First in words:

Loss equals the diffusion model's prediction error weighted by the likelihood under a mixture of Gaussians that evolves during the process

Then the compact form:

L_MMPD = E[ || predicted_noise - actual_noise ||^2 * mixture_weights(x_t) ]

Every symbol:

L_MMPDthe loss score for one forecast
predicted_noisewhat the denoising network guesses the noise is
actual_noisethe real noise that was added
mixture_weightshow much each mode (outcome cluster) contributes at time t
x_tthe state partway through diffusion, at step t
A tiny worked example
Suppose at diffusion step t there are 3 modes: sunny (weight 0.5), rainy (weight 0.3), cold (weight 0.2).
The diffusion network guesses noise = [0.1, -0.2, 0.05], but actual noise = [0.15, -0.18, 0.08].
Prediction error per channel: (0.1−0.15)^2=0.0025, (−0.2−(−0.18))^2=0.0004, (0.05−0.08)^2=0.0009.
Weight by mixture: 0.0025×0.5 + 0.0004×0.3 + 0.0009×0.2 = 0.00125 + 0.00012 + 0.00018 = 0.00155.
Across all steps and modes, low error means the model learned which outcomes matter and how likely each is, not just the average outcome.

By weighting the error by each mode's probability, the model learns to describe the full distribution of outcomes, not collapse them to an average. If mode A has weight 0.5 and mode B weight 0.3, the model learns that mode A is twice as important, so it gets better at predicting mode A's details.

What can go wrong

What can go wrong

If the time series has only one stable outcome, MMPD wastes effort. On deterministic forecasts (e.g., physics simulations) there truly is one right answer. MSE stays better in that case. The paper addresses this by keeping MSE as a fallback loss and showing that MMPD at least matches MSE on these cases.
If the diffusion model is too weak, it cannot capture the true distribution. The Patch Consistent MLP is lightweight to save compute, but on very high-dimensional problems (e.g., video forecasting with millions of pixels) the model might miss fine details of the probability distribution. The paper tests on eight time series datasets (manageable scale) and shows the lightweight design works there.
Mode collapse: the mixture of Gaussians might forget minor but real outcome clusters. If two futures are similar in early steps but diverge later, the Gaussian mixture model fitting (a method that finds clusters in the outcomes) might merge them into one mode. The paper does not discuss this directly, but the multi-step sampling algorithm (where the model keeps refining predictions by removing noise in steps) is designed to avoid it by fitting the outcome clusters dynamically throughout the process.
Done right: mix losses for balanced coverage. The paper trains with both MMPD and MSE (or Student-T) losses combined, so the model learns both the probability distribution of outcomes and a reliable average prediction. This hybrid approach preserves single-answer accuracy while adding the ability to output multiple plausible futures, because the model is incentivized on both fronts—hit one good average guess and also understand the full range.
What a runnable demo should prove

What a runnable demo should prove

Build a small time series dataset with one past sequence and multiple plausible futures (e.g., a scenario where temperature could go up, stay flat, or drop based on early-morning cloud cover). Train a backbone model with the MMPD loss and a baseline with MSE. At test time, run the MMPD model multiple times (sampling from the learned distribution) and collect all its predictions. Run the MSE model once and repeat its output multiple times for comparison.

Measure (1) how many of the MMPD predictions are 'realistic' (within the range of plausible outcomes seen in training), and (2) the average error of the best MMPD prediction versus the MSE prediction. The demo should show that MMPD's multiple outputs span the realistic range and that at least one is as accurate as MSE, while MSE always picks the average and misses the extremes.

diversity_score = fraction_of_MMPD_predictions_in_realistic_range; accuracy_score = min_error_across_MMPD_samples

The demo makes it impossible to miss: MMPD outputs multiple plausible futures with different confidence scores (high probability for likely outcomes, low for rare ones), while MSE always commits to one middle-ground guess that is wrong when reality lands on an extreme. This works because MMPD learned where the plausible outcome clusters sit, whereas MSE only knows how to hit the average between them.
