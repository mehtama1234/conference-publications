Multi-Agent Guided Policy Optimization

A framework that trains all agents together as one to guide how each agent acts alone.

Paper explainersAll themesReinforcement Learning

In the real world, robots and agents often cannot talk to each other or see what the others see. Yet they must work together. MAGPO solves this by training them all at once in a classroom (seeing everything), then deploying each one into the field (seeing only its own view). The trick: teach them how to coordinate during training, then give each agent a compass that steers it toward coordinated behavior even when flying solo.

Zero assumption version

Why teams of agents struggle in the real world

A naive approach: train each agent to maximize its own reward (its personal goal). But when agents collide or share space, selfish behavior causes chaos. A team of delivery drones each trying to reach a destination first will crash into one another.

A smarter approach: train all agents together, sharing information about everyone's position and plan. This works perfectly in simulation. Deploy it to the real world, and it breaks: the agents cannot actually see each other, cannot hear each other, and cannot stay connected to a central brain. The trained policy assumes data that will never arrive.

The gap: Training assumes a god's-eye view (all agents visible, all positions known). Deployment requires each agent to act alone with only a partial, local view.

The algorithm as a flow

What it actually does

Step 1: Train a central oracle

Build one super-policy that sees all agents and their states at once. It learns perfect coordination.

Step 2: Extract the shared guidance

Distill what the oracle learned into a signal that one agent can use: a shared alignment target (a reference policy all agents want to match).

Step 3: Train decentralized agents

Each agent trains alone, seeing only its own sensors, but also trains to stay close to the shared target learned in step 1.

Step 4: Align and verify

Explicitly measure how close each agent's behavior is to the target. Steer it back if it drifts.

Step 5: Deploy

Each agent carries the alignment target. With no central brain in the loop, it acts to match the target and coordinate with teammates implicitly.

What the paper changes

What the paper changes

The paper modifies how agents learn: it adds a shared alignment target (a reference policy learned during centralized training) that each decentralized agent tries to follow during execution.

the object it moves  =  Alignment target
The hidden quantity

The hidden quantity: policy alignment gap

measured quantity  =  How far each agent drifts from coordination

During decentralized training, each agent learns a policy (a rule for what to do in any situation). The problem: that policy can stray far from what the central oracle learned. MAGPO measures this drift—the difference between the decentralized policy and the shared target. Call it the alignment gap.

The paper estimates this gap by comparing each agent's actions to the reference policy under identical starting states. A large gap means the agent has learned to ignore the central guidance. MAGPO uses this gap as a loss signal: the training nudges each agent to shrink the gap, keeping it tethered to coordination.

Paper reading. The paper uses divergence-based metrics (e.g. KL divergence, a way to measure how different two probability distributions are — think of them as likelihood profiles for different actions). These metrics compare the decentralized policy to the reference policy to quantify the gap.
Why it works

Why it works: steering without a leash

Here is the causal chain: In the classroom (centralized training), a single policy learns coordination. This policy is built one action at a time—autoregressive (each agent picks its move in sequence, seeing what earlier agents chose). This sequential action gives the oracle the full picture to make each agent's move reinforce the team's goals.

That oracle becomes the compass. When you deploy an individual agent into the wild, it cannot call home. Instead, it carries a copy of the compass: an internal goal to match the oracle's behavior under similar conditions. When the agent faces a choice (turn left or right), it picks the option closest to what the oracle would pick. This is alignment loss: a penalty that grows when the agent strays.

The genius move: the alignment loss is computed during training only (not deployment). So agents learn early and often to stay in sync. By the time they go live, staying aligned feels natural—the agent's own learned behavior already matches the shared target. No central nudging is needed.

inputAll agents' observations during training
stepAutoregressive oracle picks one agent's action, sees result
stepExtract alignment target from oracle's sequence
stepTrain each agent to match the target while maximizing its own reward

Math after the picture

The penalty for drifting

First in words:

total loss = (negative reward for the task) plus (lambda times the average alignment gap across all agents)

Then the compact form:

L = -R + lambda * sum_i D_KL(pi_i^decentralized || pi_oracle^aligned_to_i)

Every symbol:

Rthe team reward for the current task
lambdahow strongly to penalize drifting from alignment
pi_i^decentralizedthe policy learned by agent i acting alone
pi_oracle^aligned_to_ithe oracle's policy focused on agent i's decisions
D_KLa measure of how different two probability distributions are (larger = more different)
A tiny worked example
Suppose Agent 1 has alignment gap D_KL = 0.3 (a mild drift), Agent 2 has gap 0.1 (tight alignment), Agent 3 has gap 0.7 (severe drift).
Average gap = (0.3 + 0.1 + 0.7) / 3 = 0.37.
Team reward R = 85 points.
With lambda = 10, the loss is: L = -85 + 10 * 0.37 = -85 + 3.7 = -81.3.
Now retrain and shrink Agent 3 to gap 0.2: L = -85 + 10 * ((0.3 + 0.1 + 0.2) / 3) = -85 + 1.67 = -83.33.
The loss improved (less negative is better when training nudges the weights downhill), rewarding the team for tighter alignment.

The equation pulls agents toward both doing well (maximizing R) and staying aligned (minimizing the sum of drifts).

What can go wrong

What can go wrong

Oracle too strict. If lambda (the alignment weight) is too high, agents become slaves to the oracle and forget to adapt to their own local observations. They match the target perfectly but fail when they encounter situations the oracle never trained on.
Oracle too loose. If lambda is too low, agents ignore alignment and fall back to selfish behavior. They wander far from coordination.
Oracle sees data deployment will not see. If the central oracle trains on observations (e.g., other agents' exact positions) that the decentralized agents will never receive, the alignment target becomes unachievable, and the agent wastes effort chasing an impossible goal.
Done right. MAGPO works when lambda is tuned to the task (moderate penalty), the oracle is constrained to predict only from data each agent will have at deployment, and agents train long enough to internalize alignment.
What a runnable demo should prove

What a runnable demo should prove

Build a simple multi-agent coordination task: three agents in a 2D grid trying to reach goal positions without colliding, each seeing only a radius around itself. Train a central oracle that sees all three agents and picks a sequence of moves. Extract the alignment target (the oracle's policy compressed for one agent). Train three decentralized agents on the same task, adding the alignment loss. Measure: (a) how often agents reach their goals, (b) how many collisions occur, (c) the average KL divergence between each agent's learned policy and the oracle's target under the same observation.

coordination_quality = (goals_reached / total_goals) * 100 - (collisions * 5)

The demo must show that alignment loss shrinks the KL divergence and raises coordination quality, even though agents train alone with partial observations.
