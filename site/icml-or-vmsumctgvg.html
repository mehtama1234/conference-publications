From Pixels to Tokens: Latent Action Supervision for Vision-Language-Action Models

When you combine camera images with language instructions and robot actions into one model, using an intermediate action code lets you train on mixed datasets that use different action formats.

Paper explainersAll themesRobotics & Control

A vision-language-action model (a robot brain that reads camera images and text instructions to pick the right action) needs to learn from datasets that describe actions in different ways. This paper compares four methods to supervise such models using an intermediate action code. The key finding: image-focused codes work best for long sequences, action-focused codes excel at precise motor control, and directly training on discrete action codes beats other approaches.

Zero assumption version

Datasets describe robot actions in incompatible ways

A robot needs to learn from video, language, and action data all at once. But datasets use different action codes: one might describe a gripper as open/close, another as a continuous finger position, a third as symbolic commands. A beginner trying to train one model naively hits a wall: the outputs do not line up, and the model trains on conflicting signals from different data sources.

The deeper problem: when you feed different action formats to the same model, it builds no shared understanding. It learns separate, incompatible patterns for each dataset, making training slow and the final model weak on any new action format it has not seen.

The problem in one sentence. Robot datasets use different action formats, so one model cannot learn from all of them at once.

The algorithm as a flow

What it actually does

Map each dataset to tokens

Convert each dataset's native actions (gripper position, arm joint angles, symbolic commands) into discrete token indices (0,1,2...).

Train on token sequences

Feed the model image patches, language words, and action tokens all as sequences to predict the next action token.

Compare image vs. action codes

Test two routes: use image-derived tokens (encode the scene) or action-derived tokens (encode the motion).

Measure long-horizon vs. motor control

On long multi-step tasks, track accuracy. On tasks needing precise joint angles, track precision.

Find the winner per task type

Image tokens win on reasoning over long sequences. Action tokens win on precise movement.

What the paper changes

The one thing that changes

The paper changes how actions enter the model: instead of raw values (gripper positions as numbers), actions become discrete tokens (action token 42, action token 73) chosen from a fixed vocabulary. This forces all datasets to speak the same language before the model sees them.

the object it moves  =  action representation
The hidden quantity

Action discretization match

measured quantity  =  action vocabulary fit

The hidden quantity is how well the discrete action tokens capture the true diversity of actions in each dataset. A good fit means the tokens cover the real motor space without leaving any action unreachable; a poor fit means some real actions lie between tokens and must be rounded away.

The paper estimates this by training a quantizer (a simple coder that maps continuous actions to the nearest token) on each dataset, then measuring how much information is lost when actions are rounded to the nearest token. Higher fit means fewer actions get lost in rounding.

Plain reading. When you discretize (chop continuous numbers into buckets), some detail is always lost. The better your bucket size and spacing, the less you lose, because well-spaced buckets mean each real action lands close to its assigned token, so when the token is converted back to a real action the error is small.

Why it works

Why shared tokens unlock mixed-data training

The core mechanism: when all datasets emit the same token sequence format, the model builds one unified internal representation. It learns to read images, parse language, and emit action tokens in a way that works across all data sources. The gradient (the learning signal that adjusts the model's weights) is no longer torn in opposite directions by incompatible formats.

Two routes emerge. Image-based tokens encode what happened in the last frame, so the model learns long reasoning chains (if I saw a ball, then a hand, then empty space, the sequence tells a story), because understanding the visual sequence flow helps predict the next natural step in a multi-part task. Action-based tokens encode the motor move directly, so the model learns precise control (joint 3 goes to position 45.2, which token is that exactly?), because training directly on the target action values makes the model optimize for getting those exact numbers right rather than guessing from the scene. Each format teaches a different skill. Mixed-data training (learning from both) trains all datasets end-to-end on the discrete tokens, letting the model weight different token types by importance.

Action quantization and reconstruction

First in words:

loss = sum of per-dataset predictions plus reconstruction penalty for how much action detail is lost when rounded to the nearest token

Then the compact form:

L_total = sum_d L_pred(d) + beta * sum_d || a_d - quantize(a_d) ||_2^2

Every symbol:

L_totaloverall training loss
L_pred(d)how wrong the model's action prediction is on dataset d
a_da real action from dataset d (continuous)
quantize(a_d)the nearest token, then converted back to continuous space
|| ||_2^2squared distance (how far apart two numbers are)
betahow much to penalize information loss (a dial: high beta = protect detail)
A tiny worked example
Dataset has 10 actions spread evenly from 0 to 100 (gripper open to closed).
We choose 4 tokens to represent them: token 0=0, token 1=33, token 2=66, token 3=100.
Real action 50 gets rounded to nearest token 2 (value 66). Reconstruction error: |50 - 66| = 16, squared = 256.
Real action 35 gets rounded to token 1 (value 33). Reconstruction error: |35 - 33| = 2, squared = 4.
With beta=0.5, total penalty is 0.5 * (256 + 4) + ... = punishment for detail loss. Higher beta would make the model choose finer tokens to minimize this.

The model learns to tokenize actions such that predictions on mixed data are accurate AND the tokens preserve enough action detail that robots can execute them.

What can go wrong

What can go wrong

Token vocabulary too small. If you pick too few tokens (e.g., only 8 for a continuous gripper), actions get mashed into wrong buckets and precision vanishes. The model can never output actions it cannot name.
Mismatch between route and task. Using action tokens on a long-horizon reasoning task forces the model to build a story from motor moves, which it does poorly. Conversely, image tokens fail on tasks that need exact joint angles because they encode scenes, not motor values.
Dataset imbalance ruins the shared code. If one dataset has 10x more examples than another, the model overfits to the big dataset's actions (it learns patterns that work well on that data). The shared token space tilts toward one dataset's range, leaving the other dataset's actions orphaned.
Done right. Pick token vocabulary size to match the action diversity (more for fine-grained tasks, fewer for discrete commands). Match token type to task type (image for reasoning, action for control). Balance dataset sizes or weight them fairly in the loss.
What a runnable demo should prove

What a runnable demo should prove

Build a minimal robot control scenario: two datasets with incompatible action formats (e.g., one uses gripper binary open/close, one uses continuous finger position). Train three models: (1) baseline with no latent codes (separate heads per dataset), (2) model with action-based latent tokens, (3) model with image-based latent tokens. Measure accuracy on held-out data from each dataset separately.

transfer_gain = (accuracy_with_latent_codes - accuracy_baseline) / accuracy_baseline

The demo should show that models trained on action tokens outperform the baseline on precise motor tasks (because they optimize directly for target motor values), image tokens outperform on long sequences (because visual flow through a task teaches multi-step reasoning), and joint training bridges both (because both signal types teach complementary skills).
