StreamingThinker: Large Language Models Can Think While Reading

Instead of thinking only after reading the whole text, the model thinks as it reads, one sentence at a time, reducing the wait before the first reasoning output.

Paper explainersAll themesLLMs & Foundation Models

Today's language models read the entire text first, then think about it. That delays reasoning and makes earlier context fade into the background. StreamingThinker changes the order: the model reads a sentence, reasons about it, reads the next sentence, reasons about it, and so on—like how you think while reading. This cuts the waiting time by 80 percent and final answer time by over 60 percent, without sacrificing correctness.

Why models think after reading, not during

Language models today always follow the same recipe: take the input, read all the way to the end, then start reasoning. This delay matters. If you are waiting for a model to answer a math problem or a question about a document, you wait for the entire input to load before any reasoning starts. The wait time depends on how many input words the model must consume before it produces its first reasoning word, and this can be large.

There is a deeper problem: by the time reasoning starts, the model has already laid down memory of the first sentences. When reasoning processes the whole text at once, those early parts are buried among later ones, and the model's focus spreads thin across everything. Early context gets diluted.

The problem in one sentence. Models read everything, then think. This creates unnecessary delay and makes early information fade.

What the paper changes

What the paper changes

The paper changes WHEN reasoning starts. Instead of after reading, reasoning begins as each new piece of text arrives. It also changes HOW reasoning pays attention: a causal mask (like a blinder) blocks reasoning from looking ahead to sentences not yet read.

Why it works

Why streaming reasoning works without losing accuracy

The trick is a three-part architecture. First, a streaming attention mask: when reasoning about sentence N, the mask says you can look back to any of sentences 1 through N, but NOT ahead to N+1, N+2, ... This forces the reasoning to stay grounded in what has been read so far. Without the mask, the model would cheat—it would peek ahead to information it should not have yet.

Second, streaming position encoding (a separate counting system). Normal models number tokens 1, 2, 3, ... 100. Here, input tokens count up (1, 2, 3, ... 50), and reasoning tokens count up independently (1, 2, 3, ... 30). This separation prevents the model from getting confused about which token belongs where. Why? Because if they share one counter, later reasoning tokens get higher numbers than early ones, and the model's learned associations break (positional interference).

Third, parallel KV caches—two separate memory lanes. One lane holds the input sentence as it arrives. The other lane holds the reasoning steps. Because they run in parallel, the model can encode a new input sentence while simultaneously generating reasoning about the previous sentence. No waiting, no redundant re-encoding.

The core formula: streaming thinking probability

First in words:

The probability of a reasoning sequence, where each reasoning step depends only on the input seen so far, plus a controllable depth adjustment at the end.

Then the compact form:

P_streaming = [product over t of P(R_t | C_<=t, R_<t)] * P(R_q | Q, C_<=T, R_<=T) * P(R | Q, C_<=T, R_<=T, I)

Every symbol:

R_tthe reasoning generated after reading sentence t
C_<=tall input sentences from start up to and including sentence t
R_<tall reasoning steps generated before step t
P(...)probability; the model computes how likely each next word is
product over tmultiply these probabilities for every sentence chunk
Qthe question
Ioptional instructions for reasoning depth
A tiny worked example
Sentence 1 arrives. Model generates R_1 (reasoning about sentence 1 only). Probability = P(R_1 | C_1, no prior reasoning) = 0.75 (plausible).
Sentence 2 arrives. Model generates R_2, given sentences 1-2 and prior reasoning R_1. Probability = P(R_2 | C_<=2, R_1) = 0.82.
Sentence 3 arrives. Model generates R_3, given sentences 1-3 and prior reasoning R_1, R_2. Probability = P(R_3 | C_<=3, R_<3) = 0.80.
Final answer depends on all inputs and all reasoning so far: P(answer | Q, all C, all R) = 0.85.
Streaming total = 0.75 × 0.82 × 0.80 × 0.85 ≈ 0.42. The model computes this probability pattern efficiently because each step only looks back, never ahead.

Each reasoning step is constrained to depend only on inputs already read, enforced by the attention mask, which is why streaming is causal (no peeking ahead).

What can go wrong

What can go wrong

Early context is weaker. When reasoning while reading, the model has less context at each step. If the answer depends heavily on later sentences clarifying earlier ones, streaming reasoning may miss the connection. The paper mitigates this with a post-reading depth-adjustment step (re-reasoning after all input is consumed), but true streaming means less historical information is available.
Position encoding must be separate. If you forget to give input and reasoning tokens independent position counters, positional interference occurs: the model conflates positions and reasoning quality drops. This is not a limitation of the idea, but of the engineering.
Attention mask must be causal. If the mask allows reasoning to peek ahead (a bug), the reasoning cheats and uses information it has not yet seen, which contradicts the whole point of streaming—producing timely answers based only on available data. Correctness collapses because the model learned to depend on information it should not have access to yet. The mask is the law.
Done right. When all three components (streaming attention, independent position encoding, parallel KV) are properly aligned, the model reasons incrementally without loss of core accuracy, only a small drop (1-2 points), and gains 60-80% latency reduction.
What a runnable demo should prove

What a runnable demo should prove

Build a small model (or a 7-billion-parameter variant) and train it on a dataset of problems (math, logic, or reading comprehension) using the streaming approach. Then run two versions side by side: batch reasoning (old way) and streaming reasoning (StreamingThinker). Measure time to first reasoning output, accuracy on the final answer, and total latency.

latency_gain = (time_batch - time_streaming) / time_batch × 100%, accuracy_gap = accuracy_batch - accuracy_streaming

The demo must show that streaming latency is at least 60% faster AND accuracy loss is less than 3 percentage points, because at that margin you are confident the streamng architecture is working (if losses exceed 5%, either the causal mask is letting information peek through, or position indices are tangled and confusing the model).
