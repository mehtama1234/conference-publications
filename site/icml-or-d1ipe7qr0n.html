Move-Then-Operate: Behavioral Phasing for Robotic Manipulation

Split robotic manipulation into two separate experts—one for reaching, one for touching—so the robot learns each skill without interference.

Paper explainersAll themesRobotics & Control

Humans manipulate objects by doing two very different things in sequence: first, we move our hand to the right spot (coarse motion), then we adjust grip and contact to interact with the object (fine motion). Traditional robot-learning systems force a single neural network to do both, which confuses learning. This paper adds an automatic gatekeeper that picks which expert handles each moment, so each expert becomes world-class at its job.

Zero assumption version

Monolithic policies conflate two very different jobs

A robot grasping a coffee mug must do two physically distinct things: (1) move its arm across the table to reach the mug (coarse, long-range motion), then (2) fine-tune grip pressure and wrist angle to lift without spilling (precise contact). A naive single neural network tries to learn both rules at once.

The problem: reaching and grasping have opposite dynamics. Reaching is about trajectory smoothness and obstacle avoidance; grasping is about instantaneous force and tactile feedback. When the network trains on both, gradients for reaching goals (move my arm faster) collide with gradients for contact goals (reduce grip force) because both flow backward through the same set of weights. For example, increasing the speed of arm motion requires larger weight changes, but increasing grip sensitivity requires the opposite weight adjustments—when the network tries to update a weight to satisfy one goal, it moves away from the other goal. The network learns a muddy compromise neither job is good at. A robot that reaches well accidentally squashes fragile objects. One that grasps well is too cautious and overshoots the target.

Why a beginner's fix fails: you might try training two separate networks, but then you need a human to label when the robot should switch from one to the other—tedious, and the switch points won't match how the robot actually moves.

The paper's core move. Add a learned phase-selector gate that automatically picks which expert to run at each moment, with labels generated by an AI system that watches where the end-effector is moving.

The algorithm as a flow

What it actually does

Automatically label phases

Feed training videos into a large vision-language model with prompts about end-effector velocity. It marks each frame 'reaching' or 'grasping'.

Train two expert networks

One learns only reaching trajectories; one learns only grasping. Each gradient points cleanly toward its job.

Train the phase router

A small network watches the current scene and outputs scores for each phase. A loss function teaches it to match the labels.

Pick the expert at runtime

When the robot acts, the router looks at the scene once and picks the expert with the highest score. That expert generates the arm commands.

Achieve temporal consistency

Unlike routers that decide once per visual word, this one decides once per timestep, keeping the expert choice stable across the generated action sequence.

What the paper changes

What the paper changes: the policy architecture

Instead of one monolithic network that outputs actions, the paper builds two expert networks (one for reaching, one for grasping) and adds a learned gate that picks which expert runs at each moment. The gate watches the scene and outputs scores that favor either reaching or grasping.

The hidden quantity

The hidden quantity: phase-assignment quality

measured quantity  =  phase label correctness

The paper introduces a quantity that was previously invisible: which moments in a manipulation sequence belong to reaching versus grasping. This matters because if the labels are wrong, an expert trained on mislabeled data learns a confused skill.

The paper estimates this by feeding demonstration videos into a large vision-language model (an AI that understands both images and language) with a carefully written prompt. The prompt includes clues like end-effector velocity, subtask boundaries, and human-motor heuristics. The AI labels each frame, and those labels seed training. Correct labels concentrate each expert's learning on one job; wrong labels bleed interference back in.

Why it works

Why it works: decoupling gradients

In a monolithic network, the gradient for 'move faster' and the gradient for 'reduce grip force' both flow backward through the same weights, creating a tug-of-war. Moving faster gets blocked because the network learned to focus carefully on grip safety.

Here, reaching gradients flow only through the reaching expert, and grasping gradients only through the grasping expert. No collision, no compromise. Each expert's weights receive clean signals about what that phase needs. The reaching expert learns to focus on trajectory smoothness without worrying about force. The grasping expert learns precise force without trying to solve navigation. At runtime, the router simply picks the right expert—because the router watches velocity and other cues that correlate with the true phase, it naturally picks the expert whose training is most relevant to what the robot needs to do right now.

The routing loss: teaching the gate

First in words:

Cross-entropy between predicted phase and ground-truth phase label, computed from pooled visual features.

Then the compact form:

L_router = CE(softmax(MLP_router(f_t)), y_t)

Every symbol:

f_tpooled visual feature at timestep t (what does the scene look like now)
MLP_routersmall neural network that reads the pooled feature
softmax(...)turn raw scores into probabilities that add to 1
y_tground-truth phase label: 1 if reaching, 0 if grasping
CE(...)cross-entropy (how wrong is our prediction compared to truth)
A tiny worked example
At timestep t=3, the robot is reaching (y_t is reaching).
Router reads the scene features and outputs raw scores [0.8, 0.2] for [reaching, grasping].
Normalize scores to fractions summing to 1: [0.73, 0.27].
Loss = -log(0.73) = 0.31 (low penalty because prediction was mostly right).
At timestep t=5, the robot is grasping (y_t is grasping), but router outputs [0.5, 0.5].
Loss = -log(0.5) = 0.69 (higher penalty; the router was confused).
During training, gradients nudge the MLP to predict more confidently when it sees reaching-like or grasping-like features.

The router is trained separately from the experts, using only the phase labels, so it learns to predict 'what phase are we in' from the scene.

What can go wrong

What can go wrong

Mislabeled phase boundaries. If the vision-language model incorrectly labels the transition from reaching to grasping, an expert trains on mixed signals. For instance, if it labels the moment the hand touches the mug as still reaching, the reaching expert learns a tiny twitch that confuses later grasping.
Router overfits to irrelevant cues. The router learns from end-effector velocity and scene features. If lighting or camera angle correlates with phase in the training set but not in deployment, the router misclassifies. A dimly lit reaching action gets routed to the grasping expert.
Shared encoder bottleneck. Both experts use the same vision-language encoder. If reaching and grasping require different visual features (one cares about distance to target, the other about contact pressure), the shared encoder may not represent both well.
Done right. Automatic labeling via MLLM with velocity cues produces clean phase boundaries. Router trains on a large pool of diverse trajectories so it generalizes. Experts have enough capacity to learn specialized skills. Performance plateaus at 84% average success, well above the monolithic 58%.
What a runnable demo should prove

What a runnable demo should prove

Build a minimal simulation (e.g., PyBullet or MuJoCo) where a robot arm must reach and grasp three different objects (a mug, a bottle, a small block). Train a monolithic baseline on 100 trajectories. Train Move-Then-Operate on the same 100 trajectories, using automatic MLLM labels. Measure success as: (1) did the robot reach the target without hitting obstacles, and (2) did it maintain stable grip without dropping.

overall_success = (reach_success_rate + grasp_success_rate) / 2

The demo proves that two experts with a learned gate outperform one muddled network on the same data budget because each expert's weights receive focused training signals pointing in one direction, whereas the monolithic network's weights receive conflicting signals that cancel each other out.
