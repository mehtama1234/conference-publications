DataMind: Scaling Generalist Data-Analytic Agents

DataMind trains open-source agents to tackle messy real-world data tasks by composing synthetic training data, filtering trajectories intelligently, and blending supervised learning with exploration.

Paper explainersAll themesLLMs & Foundation Models

Real data analysis is messy: files come in different formats, questions need multiple reasoning steps, and the data is often too large to fit in a model's working memory all at once. Current open-source models give up on this; they work on tidy, compact tables but fail on realistic tasks. DataMind teaches an open-source model to handle the real thing by building a custom training dataset of 12,000 realistic question-answer trajectories, then training the model to both memorize expert solutions and explore new approaches.

Zero assumption version

Why open-source models fail on real data tasks

Data analysts face three hard problems: the data is huge and varied (CSV, JSON, databases, different schemas), the reasoning is long (many steps), and there is no off-the-shelf training data labeled with step-by-step solutions. A naive attempt: take a good open-source model and prompt it with the question. This breaks immediately on real tasks because the model was never trained to decompose a complex problem into code steps, never saw how to handle messy formats, and lacks the reasoning stamina for multi-step work.

The deeper issue: proprietary models like GPT-5 are trained on massive corpora, so they absorb thousands of data-analysis patterns by accident. Open-source models do not have this luxury. So they need a training dataset that is specifically crafted to teach them the patterns and strategies that make analysis work.

The core idea. Build a dataset of realistic data-analysis trajectories (question, step-by-step reasoning, code, result), then train an open-source model on this dataset in a way that balances copying expert solutions with exploring new ones.

The algorithm as a flow

What it actually does

Generate synthetic tasks

Start with a fine-grained taxonomy of 18 task types (summarize, filter, group, rank, etc.), then recursively compose easy tasks into harder ones to increase diversity.

Trace expert solutions

For each synthetic task, encode procedural knowledge (how to approach the problem) and let the model generate step-by-step reasoning and code, creating trajectories.

Filter ruthlessly

Keep only trajectories that follow a strict format (thought, then action, then observation), remove ones that collapse mid-way, and use rule-based checks to reject low-quality paths.

Train with dynamic blending

Early in training, emphasize supervised learning from expert trajectories; late in training, emphasize reinforcement learning exploration. Mask out any turn that derailed.

Achieve stability and scale

The hybrid approach prevents training collapse and lets the model answer questions about new, large-scale, diverse data it has never seen before.

What the paper changes

What the paper changes

DataMind changes the training data and the training strategy together. The data is not arbitrary—it is a hand-curated, recursively composed set of realistic data-analysis tasks. The training is not simple—it dynamically shifts from supervised learning (copying expert solutions) to reinforcement learning (exploring new paths the model discovers).

the object it moves  =  training data + training strategy
The hidden quantity

The hidden quantity: training stability

measured quantity  =  trajectory stability under multi-turn rollout

As the model reasons step-by-step over multiple turns (read the schema, write SQL, execute, check the result), it can drift off the rails. This drift is called distributional shift: the model's outputs become different from what it saw in training, so its confidence collapses and errors compound. The paper measures stability by observing whether a full trajectory stays coherent all the way to the end, or derails partway through (a void turn).

DataMind estimates this by simply checking: does the trajectory follow the required format (thought, action, observation) at each step? If any turn violates the format or produces nonsense (e.g., code that crashes), that entire trajectory is masked during training, and the model does not learn from it.

Why it works

Why it works: the four-part engine

DataMind works because it solves the three root problems simultaneously. First, it generates diverse training data by recursively composing simple tasks into complex ones, covering 18 task types and many combinations. This floods the model with examples of patterns it would never encounter in a small, hand-labeled dataset.

Second, it filters trajectories intelligently. A bad trajectory teaches the model bad habits (e.g., writing incorrect SQL), so it is removed. A trajectory that derails mid-way (a void turn) teaches compounding errors, so the entire trajectory is masked. This keeps the training signal clean.

Third, it balances two kinds of learning: early training emphasizes supervised learning (memorize the expert path), and late training emphasizes reinforcement learning (find your own path). This progression matters because pure reinforcement learning on a new task is unstable—the model explores randomly and learns little. But pure supervised learning is inflexible—the model memorizes the training set and fails when the test problem looks different from training examples. The hybrid approach gets the best of both.

Fourth, it uses a code-based multi-turn rollout framework that runs the model's code in a safe sandbox and captures the output, then feeds it back to the model for the next reasoning step. This grounds the reasoning in real feedback instead of hallucination. The framework is memory-efficient and stable because it does not store all intermediate states.

Math after the picture

The training equation

First in words:

The training loss is SFT loss (how much the model's prediction differs from the expert answer) plus RL loss (how much the actual execution reward differs from what the model expected), weighted by a time-varying coefficient gamma that starts high and shrinks to low.

Then the compact form:

Loss_total = gamma_t * Loss_SFT + (1 - gamma_t) * Loss_RL

Every symbol:

Loss_totaloverall training penalty
gamma_tweight for SFT at step t; starts high, decreases over time
Loss_SFTsupervised loss, how far the model's prediction is from expert trajectory
Loss_RLreinforcement loss, how far the execution reward is from the model's expectation
A tiny worked example
Early training: gamma = 0.8, SFT loss 2.0, RL loss 1.0; total = 0.8 times 2.0 plus 0.2 times 1.0 = 1.6 plus 0.2 = 1.8 (emphasize expert data)
Mid training: gamma = 0.4, SFT loss 2.0, RL loss 1.0; total = 0.4 times 2.0 plus 0.6 times 1.0 = 0.8 plus 0.6 = 1.4 (balanced)
Late training: gamma = 0.1, SFT loss 2.0, RL loss 1.0; total = 0.1 times 2.0 plus 0.9 times 1.0 = 0.2 plus 0.9 = 1.1 (emphasize exploration)
Same pair of losses, but the weighting shifts from copying expert solutions to finding different paths.

The scheduling of gamma matters: it controls when the model switches from memorizing expert paths to discovering its own.

What can go wrong

What can go wrong

Void turns derail training. If a trajectory has a reasoning step that produces invalid code or gibberish, and it is not masked out, the model learns that gibberish is an option. DataMind catches this by strict format checking and masks the entire trajectory.
SFT loss can prevent exploration. If gamma stays high too long, the model keeps copying training examples and never tries different solutions. The paper finds that gamma must be annealed (decreased) so that late training emphasizes RL exploration.
RL without grounding hallucinates. If the model is rewarded for high confidence but the code never actually runs, it learns to fake answers. DataMind grounds reasoning by executing code in a real sandbox and feeding back the actual output.
Done right. Filter trajectories, start with SFT, anneal gamma over time, execute code in a sandbox, mask void turns, and the model learns to reason through multiple steps reliably on diverse tasks.
What a runnable demo should prove

What a runnable demo should prove

Build a small data-analysis task: take a CSV file with messy column names and mixed data types, ask a natural-language question (e.g., find the median salary by department), and have the model generate Python code, execute it, and return the answer. Run the trained model on three kinds of test data: a clean table that matches training examples, a large table with a million rows, and a CSV with an unfamiliar schema. Measure whether the model's answer is correct.

success_rate = (correct_on_clean + correct_on_large + correct_on_unfamiliar) / 3

The demo proves that DataMind generalizes beyond training patterns: the model does not just memorize; it reasons correctly on data it has never encountered, even when it is large or messy.
