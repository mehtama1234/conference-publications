Breaking down complex goals into simpler steps

Teaching agents to break large tasks into smaller subgoals or skills, and learning when and how to use each skill, so they can handle long-term, multi-step problems.

All themesField mapMathematicsAll explainers
What this is

Learning to do a simple task in one step is much easier than learning a ten-step task. If you ask a robot to assemble a toy, it's not learned anything useful if it only gets rewarded at the end — it has to connect actions ten steps ago to the final success. Hierarchical reinforcement learning breaks the problem into layers. The high-level layer learns the sequence of subgoals: pick up the part, position it, insert it, tighten it. The low-level layer learns how to execute each subgoal. The benefit: the high-level layer works with a simpler timeline (fewer decisions to connect), and the low-level layer can reuse skills across many high-level tasks.

The challenge is learning the right subgoals. If you ask the robot to learn 'position the part,' the robot has to figure out what 'positioned' means from experience. Papers here use techniques like skill discovery, where the system automatically identifies useful subgoals from trial data, or learning from demonstrations, where a human shows a few sequences and the system infers the subgoal structure. Some work on option frameworks — a reusable 'option' is a skill with a starting condition and an ending condition, and the agent learns which options to chain together.

Hierarchical learning matters for long-horizon tasks that humans solve naturally by chunking: cooking (gather ingredients, prep, cook, plate), building (design, source materials, assemble, test), or any multi-step process. Breaking it into layers lets agents learn much harder tasks.

How the work breaks down

Breaking complex tasks into subgoals requires three kinds of machinery: first, figuring out which representations of a goal let the agent act on it directly (not just observe it); second, automatically discovering useful subgoals and skills from experience; and third, teaching agents to chain these simpler steps into long sequences that solve hard problems.

How to describe a goal so the agent can act on it

A goal is only useful if the agent can actually do something about it. If you tell the robot 'reach the table,' the robot needs a way to translate that into actions. Some ways of describing goals let the agent learn faster because they connect more directly to the actions it can take—when the agent understands how to move toward the goal, it learns faster.

Action-Sufficient Goal Representations shows that describing a goal in terms of the agent's own actions makes it learn faster than describing it in terms of value estimates (which is how much reward the agent expects to get). The reason: the agent can directly work toward an action-based goal but must struggle to connect value numbers to its own decisions. In tests with math problems and demonstrations, this approach gained 5 percentage points because the agent knew exactly what to do. The Bottleneck-Guided Spectral Subgoals paper uses a different strategy: it finds the bottleneck states—the mandatory passages the agent must go through to progress. These bottlenecks work well as subgoals because the agent must pass through them anyway, which means reaching these subgoals is guaranteed to move the agent forward. Goal Reaching with Eikonal-Constrained Hierarchical Quasimetric Reinforcement Learning uses a distance metric (a quasimetric) that treats some state transitions as harder than others, so the agent naturally gravitates toward easier paths to subgoals, especially for navigation and manipulation where distance matters. All three papers solve the same core problem: how do you describe a goal so the agent can act on it?

Automatically discovering skills and subgoals

Instead of a human deciding which subgoals are useful, these papers try to discover them automatically from the agent's experience. The agent plays around in the world, and the discovery system watches for patterns that look like useful chunks.

SUSD: Structured Unsupervised Skill Discovery finds skills by spotting which parts of the state change together during the agent's exploration. When some state variables change as a unit and others stay independent, SUSD separates them out and calls each group a skill. This creates skills that are both easier to describe and easier to combine for downstream tasks. Learning Interpretable Options by Identifying Reward Diffusion Bottlenecks finds subgoals by asking: where does the reward information get stuck? When reward information spreads unevenly through a task, the bottlenecks are good places to break the problem into steps. This works in tabular games, maze navigation, and Atari games. Unsupervised Hierarchical Skill Discovery learns skills purely from exploring the world without any reward signal at first. It creates hierarchies where skills at one level are composed of skills at the lower level, and the result looks more like what humans would design than simpler methods. All three papers skip the manual work of defining subgoals; instead, they let the agent find its own patterns.

Teaching long-horizon tasks via hierarchies

When a task takes many steps to complete, the agent faces a credit-assignment problem: it must connect what it did at step one to the reward it gets at step fifty. This is hard because the signal is weak over so many steps. Breaking the task into subtasks makes each credit-assignment problem much smaller, which means the agent sees a clearer connection between what it does and what it achieves.

Hierarchical Reinforcement Learning for Sparse-Reward Search in Commutative Algebra tackles a mathematical proving task where you must make 50+ decisions before you know if you succeeded. By splitting the work—a high-level agent chooses which subgoal to aim for next, and a low-level agent figures out how to reach it—the problem shrinks: the high-level agent only has to make the right subgoal choice, not all 50 decisions at once. This two-layer approach outperforms both standard RL and greedy search because each layer has a clearer learning signal. RD-HRL: Generating Reliable Sub-Goals for Long-Horizon Sparse-Reward Tasks focuses on making the subgoals reliably reachable—they must be achievable from any state the agent might face during learning, not just the states in the training data. When subgoals are always reachable, the agent can make consistent progress. Chain-of-Goals Hierarchical Policy for Long-Horizon Offline Goal-Conditioned RL works on tasks where the agent learns only from past trajectories with no live exploration. It chains subgoals together sequentially, so the agent can trace a path through old data to discover long sequences, even offline. Strict Subgoal Execution enforces that the agent must fully reach each subgoal before moving to the next, which prevents shortcuts and incomplete skills; this simple hard constraint tightens the learning signal because the agent cannot fool itself that it almost reached a subgoal. These papers all share one insight: without breaking the task up, agents drown in the credit-assignment problem over many steps, but with the right hierarchy, they solve it step by step.

Learning from demonstrations and preferences

A human often has a clearer idea of the subgoal structure than an agent starting from scratch. These papers show how to use human demonstrations or feedback to guide the discovery of subgoals.

Leveraging Explanation to Improve Generalization of Meta Reinforcement Learning adds explanations to demonstrations—a human shows the agent not just what to do, but why each step matters. Explanations work well because they reveal the subgoal structure hidden inside the demonstration; when the agent understands why a step occurred, it can recognize similar reasons in new tasks. The paper proves the convergence is as fast as pure learning theory predicts, which means the agent doesn't pay a speed cost for learning from explanations. APC-RL: Exceeding data-driven behavior patterns (like what a human would do) takes demonstrated behaviors and learns to combine them into new skills. If the demonstration matches what the task needs, the agent learns aligned subgoals and accelerates; if mismatched, the method extracts the useful parts and ignores the rest because the agent isn't forced to copy the whole demonstration. Direct Preference Optimization for Primitive-Enabled Hierarchical RL uses human feedback (comparing two behaviors) instead of scalar rewards to train hierarchical policies. Comparisons (this action sequence is better than that one) tell the agent which subgoal chains work without needing a number, which is easier for humans to provide accurately on complex tasks. This approach gives 40% better results on hard robotic tasks because preference feedback reveals subgoal structure more clearly than scalar rewards on tasks where the reward is hard to quantify.

Curriculum and staged learning

Teaching a complex task all at once doesn't work. If you start a robot with the hardest version of the task, it fails immediately and learns nothing. Instead, you start with an easy version and gradually increase the difficulty—a curriculum. These papers show how to design curricula that discover good subgoal structures because easy tasks reveal which subgoals matter, and making learning faster because the agent builds one skill at a time instead of drowning in one giant task.

The State of Reinforcement Finetuning for Transformer (a type of neural network architecture)-based Generative Agents shows that if you take a pre-trained general-purpose language model and then fine-tune it with RL for a specific task, small targeted improvements consistently beat standard approaches. Pretraining works because the model already has patterns that map to hierarchical subgoals—it learned language structure that mirrors task structure. Active Curriculum Refinement improves the curriculum by treating the sequence of tasks as a graph structure, which lets the system learn which easy tasks best prepare an agent for hard ones by seeing which tasks share skills. Dreaming in Code for Curriculum Learning creates an imagined world where the agent can practice solving hard subgoals without the slow simulation overhead, because simulation is expensive but imagined practice is cheap, and discovering subgoals in imagination transfers to the real world. Gradient (the direction of change in learning)-Aware Scheduling couples the curriculum difficulty to how quickly the agent is learning on each subtask, because when learning is fast, the agent already has the right subgoals and doesn't need easier tasks, but when learning is slow, the agent is stuck and needs to drop the difficulty. If the learning curve is steep, keep tasks easy longer because the agent is making fast progress; if flat, ramp up difficulty faster to force new learning. This gives 20% better performance on code generation because curriculum pacing is matched to learning speed. TRACED: Transition-aware Regret Approximation with Co-learnability for Environment Design generates the curriculum by predicting which task difficulty comes next will teach skills needed for the final task, because some tasks build on others—certain skill sequences transfer, and predicting those transfers lets the system order tasks so each builds on the last. All five papers share one principle: you can't teach the full task at once because the agent's learning capacity is limited and the credit-assignment problem explodes, but if you order the learning so easy tasks teach subgoals that later tasks need, the agent discovers a hierarchy naturally.
