Generative Models & Diffusion

How can we build systems that create realistic images, videos, text, and other complex outputs from patterns in data, control what they generate, and do it efficiently?

What this whole area is about

Generative models are systems that can create new things—images, videos, text, music, 3D objects—by learning patterns from examples. The core idea is straightforward: if you show a model thousands of images, it can learn what makes a good image and generate new ones that follow similar rules. But building systems that actually do this well turned out to be one of the hardest problems in machine learning. The challenge isn't just making something that vaguely looks right—it's making systems that understand the structure of the world well enough to create convincingly real outputs, follow specific instructions, and work quickly enough to be useful.

Why is this hard? When you ask a model to generate something, it's not retrieval—it's not looking up an answer in a database. The model has to essentially invent something new pixel by pixel (or word by word, or 3D point by 3D point), guided only by patterns it learned. This requires the model to have learned deep statistical patterns about what the world looks like, and then navigate from pure randomness toward outputs that satisfy those patterns. The system has to handle enormous amounts of variation—countless ways to draw a car, an infinite range of possible videos, all the grammatical structures of language. It has to do this while also following whatever specific instructions the user gives (like 'make it red' or 'make it move fast'), and ideally it should do it in a reasonable amount of time. Each of these is a separate research problem.

Researchers attack this from multiple directions. Some focus on the mathematics underneath—how to set up a generation process so that adding and removing noise in clever ways lets the model learn what the world looks like, or how to use curved paths through possibility-space to navigate from randomness to real outputs. Others focus on practical applications: how to make text-to-image systems that actually follow instructions, how to extend that to video, how to make 3D objects. Still others focus on speed and efficiency, because making a beautiful image in 30 seconds is useless if users need it in 1 second. And some researchers focus on control—how to steer what the model generates, or how to train it to match what people actually want rather than whatever happens to come out.

This matters because generative models are now touching nearly every creative and analytical field. They power the text-to-image tools millions of people use daily. They help video creators extend and edit footage by predicting frames in a consistent style, which saves time compared to manual editing. In science, they help researchers design new molecules by generating candidates that might bind to disease targets (which is faster than testing billions physically), and they help understand proteins by predicting 3D shapes from amino acid sequences. In design and engineering, they let people iterate on ideas in minutes instead of hours because generating variations is now fast enough to be interactive. The efficiency work matters because it moves these tools from 'research curiosities' to 'everyday tools.' Understanding how these systems actually work—the math, the tricks, the failure modes—is becoming essential.

Subtheme

Mathematical foundations and new generation methods

Modern generative models work on a simple but counterintuitive principle: you can learn to generate by learning to undo noise. Imagine taking a clear picture and slowly adding random noise until it becomes unrecognizable static. A generative model learns this process in reverse—starting with pure noise and gradually removing it, bit by bit, until something recognizable emerges. This works because the math of noise addition is completely reversible and well-understood. The model learns, for each type of noise, what the data underneath probably looks like.

The research in this area focuses on two big questions: First, what is the best mathematical setup for this? Different setups—diffusion (step-by-step noise removal), flow matching (following a curved path from noise to data), and others—each have tradeoffs in speed, quality, and mathematical elegance. The papers here explore these different mathematical formulations and prove which ones work better under which conditions by testing them on datasets and measuring quality versus speed, so researchers can choose the setup that matches their needs. Second, how can we sample more efficiently? If you have to remove noise in a thousand tiny steps, generation is slow. Can you remove noise in fewer, larger steps and still get good results (this is hard because bigger steps mean less guidance and the model can veer off track), so users see outputs faster? Can you use one model to train another to predict multiple steps at once, so you in practice skip steps?

Researchers tackle this by building new mathematical frameworks, proving they work, and designing algorithms that reduce the number of steps needed. Across this work is a consistent finding: the trade-off between quality and speed comes from the math itself—you cannot just brute-force fewer steps without changing how the model learns, because skipping steps means the model didn't learn to navigate that part of the path and will likely hit a dead end. Papers here typically describe a new way to set up the generation process or a new sampling strategy, explain why it works mathematically (often with proofs showing convergence—that the algorithm reliably reaches good outputs), and demonstrate it produces better results than existing methods on standard tests, so that other researchers can use the method and get similar improvements.

Subtheme

Making images from text descriptions

The question here is practical and immediate: given text like 'a red car driving on a sunny beach,' can a system generate an image that matches? This requires the model to do several hard things at once. It has to understand language well enough to parse the description. It has to know what a 'red car' looks like, how cars interact with beaches, what 'sunny' looks like in terms of lighting and color. And it has to follow the instruction while still generating something that looks realistic and detailed—not a flat, obvious match but something that feels like a genuine photograph or painting.

The difficulty is that text and images don't line up neatly. The word 'red' doesn't have one visual representation—it could mean bright red, dark red, saturated red, muted red. The model has to figure out from context. Also, people ask for increasingly specific things: 'make the car red but not the wheels,' 'keep the person's face the same but change their expression.' The model has to understand boundaries between objects and concepts. And then there's the personalization angle—can you fine-tune a model to generate images of a specific person or object without retraining from scratch?

Research here falls into several clusters. Some papers improve how language is connected to images—better ways to represent text instructions so the model understands them more precisely by mapping words to visual concepts more accurately. Others focus on attribute control: given a generated image, can you change specific properties (color, size, pose) without regenerating everything, because users want to iterate (e.g., 'keep the dog, but make it blue')? Still others tackle editing existing images: given a photo and a text instruction ('remove the tree'), can the model erase and re-imagine that region, which is useful for cleanup or creative changes? And an important cluster works on personalization—letting users show the model a few examples of what they care about (their face, their art style) and having it generate new variations without expensive retraining, which is practical because full retraining takes days. These approaches include techniques like fine-tuning on small examples (training the model slightly on just the user's data), which works because even a tiny amount of training on user-specific examples shapes the model to match their preferences, storing a signature of the user's content and conditioning generation on it (so the model remembers who to draw), or learning lightweight adaptations (small adjustment modules that plug into the model).

Subtheme

Generating video from images or descriptions

Video is image generation's harder cousin. A single image can be beautiful and stay still forever, but video requires consistency across dozens or hundreds of frames—the content has to change plausibly over time while maintaining coherence. The car from frame 1 has to still look like the same car in frame 50. The physics has to make sense: if something is falling, it should keep falling. If motion is described ('the camera pans left'), every frame should show the world shifting smoothly leftward. This is radically harder than static images because the model has to learn and enforce temporal consistency.

The challenges break down into several parts. First, generating the initial motion: given a description or a starting image, what should move and how? A model trained on static images doesn't automatically understand motion. Second, extending videos: if you have a 5-second video, can you extend it to 10 seconds by predicting what comes next? Third, interpolating between frames: given frame 1 and frame 10, can you fill in frames 2-9? Fourth, motion control: can you specify exactly how something should move without letting the model decide? And fifth, infinite extension: can you keep generating new frames indefinitely while keeping the content coherent?

Papers here use several approaches. Some train separate models specifically for motion by using video data as training signal—showing the model pairs of consecutive frames so it learns what realistic motion looks like (a car doesn't teleport, it drives smoothly). Others use optical flow (the direction and speed pixels move between frames) as an intermediate representation—the model predicts flow first, then uses flow to warp or generate pixels, which breaks the problem into steps that are easier to solve. Some papers combine static image generation with a separate 'motion module' that predicts how each part should move, which lets them reuse existing image technology. For control, researchers use techniques borrowed from text-to-image work: if you can condition generation on text descriptions, you can condition it on motion descriptions, so users can specify 'pan left' or 'zoom in.' For infinite video, the trick is usually to process frames in overlapping windows so the model always has context about what came before, which lets it generate the next frame aware of earlier context and thus maintain coherence.

Subtheme

Faster and more efficient generation by reducing steps and computational cost

Faster and more efficient generation means reducing both time and computational resources because standard generative models need many steps (often 50-1000) to go from noise to a real output, and each step is computationally expensive. Generative models face a core tradeoff: quality versus speed. Most models can produce beautiful output, but often very slowly, making them impractical for real work. A beautiful image that takes 30 seconds to generate is not useful for interactive applications because users want real-time feedback and iteration. Neither is a video that takes an hour, because video production already consumes time and waiting additional hours for generation makes it impractical. Efficient generation is a practical necessity—it's the difference between a research demo and something millions of people can use. The research question is: can we get good quality in fewer steps, so users get outputs in seconds rather than minutes?

There are several approaches. Distillation means training a small, fast 'student' model to mimic a large, slow 'teacher' model. The student learns to do in 5 steps what the teacher does in 50 steps. Few-step sampling means rethinking the mathematics so that you can jump multiple noise-removal steps at once—instead of removing 1% of noise 100 times, can you remove 10% of noise 10 times? Quantization compresses the model itself—storing numbers with lower precision—so it runs faster and uses less memory. Pruning removes parts of the model that don't contribute much. Caching means remembering intermediate computations rather than redoing them.

The research here is a mix of mathematical work (proving you can use bigger steps while still converging to good outputs) and systems work (engineering models to be fast without sacrificing quality). A key insight is that there's often a tradeoff curve: you can be very fast but lower quality, or slower but higher quality. Papers here explore where that curve lies for different methods and how to push it forward. The practical impact is huge because faster generation means more interactive applications (you can iterate in real time), lower energy use (the system spends less time computing, which matters both for cost and for the environment), and accessibility on lower-end devices like phones (a model that needs a data center is only useful for large organizations with big budgets, while a model that runs on a phone is useful for everyone).

Subtheme

Training and controlling generative models

Once you've built a generative model, how do you make sure it does what you want? Training stability is one issue: generative models can be finicky to train—they oscillate, they collapse to repetitive outputs, they forget parts of what they learned. Another issue is alignment: the model might learn to generate technically good images according to the training data, but images that are offensive, inaccurate, or unhelpful for the actual use case. A third is control: once trained, how do you steer the model? If you want it to generate images of dogs but not cats, or to emphasize safety, or to match what people actually prefer, how do you do that without retraining?

Training methods here focus on stability: what hyperparameters make training converge smoothly (so the model doesn't oscillate or collapse), which matters because an unstable model never finishes learning or forgets what it learned? How should you structure loss functions—the measures of 'how wrong' the model is—so the model learns efficiently and doesn't waste computation, which is important because training is expensive and poor loss functions waste compute on wrong directions? Should you use adversarial training (where one model generates and another critiques, which forces both to improve), which can work because competition drives both models to perform better? How do you handle class imbalance (when some types of objects are much more common than others in your training data, which can make the model lazy and only generate common things because common things are easier), so the model learns to generate everything it should and doesn't neglect uncommon categories? For alignment and control, researchers use several strategies. Preference learning means showing the model pairs of outputs and asking which is better, then training to match human preferences, so the model learns what humans actually want rather than just what data happens to have. Reinforcement learning from human feedback means scoring model outputs and training to maximize the score, which lets you guide the model toward specific goals by directly rewarding the behaviors you want. Classifier guidance means using a separate model to steer generation—'generate an image that looks like a dog (according to a dog-classifier) and matches the text description,' which works because you can tell the model to follow both the text instruction and the classifier's opinion.

Papers in this area typically propose a new training method (like a better loss function) or a new control mechanism (like a way to steer generation without retraining, which matters because retraining is expensive), test it on standard datasets, and show it improves stability (fewer training failures) or alignment (model outputs match what users want) compared to baselines. The work is often unglamorous—it's engineering and careful experimentation—but critical for making models reliable enough to deploy because a model that sometimes breaks or ignores instructions is not trustworthy.

Subtheme

Using generation to solve problems

Beyond creating pretty outputs for their own sake, generative models can solve hard problems. If you have a model that learned the structure of valid solutions (images, proteins, code, proofs), you can use it as a tool: point it at a broken or incomplete thing, and have it imagine what should go there. Inpainting is the simplest example—'I have a photo with someone's face blurred; generate what that face should look like.' Image restoration means 'this photo is noisy or corrupted; clean it up.' Molecule design means 'generate new molecules that would bind to this protein' (critical for drug discovery). Mathematical reasoning means using generation to search through possible proofs of a theorem.

The challenge is that these aren't straightforward generation tasks. When you inpaint a blurred face, you can't just generate any face—it has to match the context, the lighting, the angle, the person's actual appearance if visible elsewhere. The model has to navigate a constrained space: 'generate something that looks realistic AND fits the context AND solves the problem.' For molecules, the model has to generate structures that actually follow chemistry rules and have the desired properties. For proofs, it has to generate steps that are logically valid.

Researchers handle these constraints in several ways. Conditional generation means feeding extra information (the image context, the target properties) into the model to guide it. Iterative refinement means generating a rough solution, checking if it works, and then refining it. Some papers use a generative model as one part of a larger system—it generates candidates, and a separate tool checks if they're valid or useful. For molecules, researchers combine generative models with chemical constraints and simulators that check if a generated molecule would actually work. The key is treating the generative model as part of a problem-solving pipeline, not a standalone system.

Subtheme

Generating language and text

Most generative models today use autoregressive methods for text: predict the next word, given all previous words, then repeat (like autocomplete on your phone, but more complex). Diffusion models—the 'noisy to clear' approach that dominates image generation—are less common for text, but researchers are exploring them. The question is: can we generate text using the same mathematics as images? And if we do, does it have advantages or disadvantages compared to standard methods?

One reason this is interesting is that diffusion models work differently from autoregressive ones. Autoregressive models commit to each word in sequence—once they predict 'the,' that word is fixed and influences everything that follows, so if you choose wrong early, you can't recover. Diffusion models work in parallel across all positions: they gradually refine the entire sentence at once, like sculpting stone by removing material everywhere simultaneously. This could potentially allow the model to revise earlier words if later context suggests something different (rather than getting trapped by an early wrong choice), which might lead to better outputs. It might also allow different decoding strategies—instead of being locked into 'always pick the highest-probability next word,' you could search through multiple possibilities because you're not committing irrevocably at each step.

Papers here explore whether diffusion works for language at all (since most text uses autoregressive methods, diffusion is a natural next experiment), whether it's competitive with autoregressive methods, and whether the different generation process enables new capabilities (like better revision or more diverse outputs). The research is still early—text diffusion does not yet beat standard methods for most tasks—but the work here is mapping out what is possible. Some papers apply image-generation techniques (like flow matching) to text, which is interesting because it might give text generation new properties image generation enjoys (like multi-scale refinement or better diversity). Others use diffusion for specific text tasks like paraphrase (rewriting sentences differently) where having a different generation process might help because you can revise multiple parts of a sentence in parallel rather than being forced into a linear left-to-right path. And some work on combined problems: generating both image and text descriptions together, which requires bridging the gap between two very different types of data.

Subtheme

Specialized techniques for better results by targeting bottlenecks

Specialized techniques for better results come from targeting specific bottlenecks, not from major algorithm changes, which means small improvements in individual components yield measurably better results across the system. This research is 'specialized' because each technique addresses a specific component, and fixing that component produces better results: Better tokenization (breaking images or text into smaller chunks) yields better precision because finer granularity gives the model more flexibility to express nuance. Improved caching makes generation faster without sacrificing quality because caching avoids redundant computation—the model doesn't have to recompute the same thing twice. Smarter sampling strategies find outputs that better match both quality and the user's request by exploring the space of possibilities more in practice, yielding better matches to what users want. Architectural tweaks to the neural network itself make it learn patterns more efficiently by changing how information flows through the model.

These papers focus on the details that don't change the fundamental approach but measurably improve results, which matters because even small improvements compound across millions of users and applications. For example, research on embeddings (the numerical representations of concepts that neural networks use) can make text-to-image models better at understanding instructions because better embeddings more accurately capture what words mean. Work on attention mechanisms (the part of a neural network that decides what to focus on) can improve quality because the model can focus on relevant parts of its input and ignore noise. Research on loss functions—the mathematical measures that guide training—can yield models that generate better outputs because loss functions shape what the model learns, and a better-designed loss pushes the model toward outputs humans prefer. Some papers optimize for speed in clever ways: if you're generating an image, you don't need to compute at full resolution the entire time; you can compute at low resolution and refine upward, which is faster because you start from a coarser representation.

The papers here are often hybrid—a new idea about how to represent data, combined with careful experiments showing it helps (so others can reproduce it). They might seem incremental, but when you combine dozens of these improvements, the cumulative effect is dramatic because each improvement compounds on the others. This work is where the gap between research and real products is often closed: solid core mathematics provides the foundation, then layers of clever engineering transforms it into something practical.

Subtheme

Creating multiple data types together

Some generation tasks require creating more than one thing at once. You might want an image paired with a detailed text description, or a molecule paired with predictions of its properties, or a visual diagram paired with the data it represents. The challenge is that different data types have different structure and statistics. An image is a grid of pixels; text is a sequence of words; molecules are graphs where atoms connect to atoms. A single generative model has to somehow handle all these different structures and ensure they're coherent—the image and description have to match, the molecule and its properties have to align.

The core difficulty is coordination. If you generate the image and then try to generate a description, you might get a mismatch. If you try to generate them together, you need a framework that treats both equally. How do you even train a single model on data of such different types? One approach is a shared intermediate representation—convert images, text, and graphs into a common numerical format, let the model work in that format, then convert back. Another is to use multi-modal models (models trained on paired examples of images and text, or text and molecules), which work because the model is repeatedly shown correct pairings and learns to associate certain images with certain kinds of descriptions (a sunset description goes with warm colors, not cool colors). A third is to stack independent models: generate the image, then condition the text-generation model on the image (so the text model can see what was generated and describe it).

Papers here explore these approaches. Some propose new architectures that handle multiple data types naturally. Others work on the training problem—how to learn from paired data of mixed types. Still others focus on specific combinations: text-to-image plus generation of captions, or molecular generation plus property prediction. The motivation is practical: in many real applications, you need multiple outputs that fit together, not just one thing in isolation.

Subtheme

Building 3D shapes and scenes

Generating 3D objects and scenes is harder than generating images for a fundamental reason: images are 2D grids and relatively simple to represent, but 3D is much more complex. A 3D object has to be valid from every angle—a car viewed from the front has to have wheels if you walk around to the side. A scene has to have spatial coherence: objects can't float in mid-air unless there's a reason, and all the perspective has to be geometrically consistent. Generating something that looks good in a static 2D render is easy compared to generating something that would actually hold up as a real 3D model.

The technical challenges are immense. How do you even represent 3D? As a grid of voxels (3D pixels)? As a point cloud (a scatter of 3D points)? As a mesh (triangles forming a surface)? As a signed distance function (a mathematical description of where surfaces are)? Each representation has tradeoffs, and none captures detail as naturally as 2D images do. How do you ensure the outputs are geometrically valid—no self-intersecting surfaces, no floating-point errors that destroy the model? How do you generate from a text description ('a wooden chair') when the model has seen millions of images but far fewer 3D assets? How do you handle identity—if asked to generate a person sitting in a chair, can you make sure the person and chair are consistent across multiple generations, not randomly different people and chairs?

Research here uses several strategies. Some papers generate 3D by treating it as multiple 2D views—generate several images of an object from different angles, then use those to reconstruct 3D. Others use intermediate geometric representations: first generate a coarse skeleton or shape, then refine it. Still others condition generation on 2D images: if you show the model a photo, it can try to generate a 3D model consistent with that photo. Papers on scene generation often focus on specific domains: rooms, outdoor environments with sky and trees, and enclosed spaces where there are clear conventions about how things arrange and relate. The work is less mature than image or video generation, and many papers are still exploring what the right approach is.
