Entity-aware Group Relative Policy Optimization for Search Agents

Train search agents using partial rewards for near-miss answers based on how many ground-truth entities they correctly identified during reasoning.

Paper explainersAll themesAgents & Tool Use

Search agents are AI systems that answer hard questions by looking up information and reasoning about it. Today, these agents learn from synthetic data using a method called Group Relative Policy Optimization, or GRPO. But GRPO throws away most of the information in that data—it only looks at the final answer (right or wrong), completely ignoring the entities the agent found along the way. This paper shows that there is a hidden signal in that discarded information: answers that get most entities right but fail on the final step are much more valuable to learn from than complete failures. The paper proposes E-GRPO, which assigns partial credit to answers based on how many entities were correctly identified, turning those near-misses into gold-standard learning examples.

Zero assumption version

Why search agents get stuck on synthetic data

Search agents are trained on synthetic data—carefully constructed question-and-answer pairs where humans or other AI systems have already written the correct answer. Each training example includes the entities that matter (names, dates, locations, numbers) and shows the agent how to find and use them. This data contains many different learning signals about which entities are important and how they connect.

But current training methods like GRPO completely ignore this richness. GRPO looks at only the final answer: right or wrong. It gives full credit to correct answers and zero credit to incorrect ones, even if the incorrect answer got 90 percent of the entities right. A beginner might think this is fine—after all, the final answer is all that matters. But this approach discards the most valuable training examples: answers that are almost correct (the agent found all the right entities but made a small reasoning error at the end). These near-misses are exactly where the model should learn, because they show what went wrong and what went right. Instead, they are lumped together with complete garbage and assigned zero value.

In one sentence. E-GRPO recovers lost learning signals by assigning partial credit to incorrect answers based on the fraction of ground-truth entities they correctly identified.

The algorithm as a flow

What it actually does

1. Agent attempts question

The search agent receives a question and uses tools to find information, then outputs an answer.

2. Extract identified entities

Count how many ground-truth entities from the synthetic data the agent correctly found during reasoning.

3. Compute entity match fraction

Divide the number of correctly identified entities by the total number of ground-truth entities.

4. Assign dense reward

Give the agent a partial reward equal to that fraction, not just zero or one for final answer correctness.

5. Update via group relative policy optimization

Use the partial reward in GRPO's training algorithm to nudge the agent toward better entity identification, because higher rewards for near-misses teach the model to focus on entity discovery.

What the paper changes

What the paper changes

E-GRPO changes the reward signal from binary (right or wrong) to dense (a partial score based on entity match rate). Instead of discarding the entities that the agent found, the paper explicitly measures them and uses that measurement as the training target. The method is a small modification to GRPO: replace the outcome-only reward with a fraction-based reward that depends on how many ground-truth entities were correctly identified.

The hidden quantity

The hidden quantity: entity match rate

measured quantity  =  Fraction of ground-truth entities correctly identified

The entity match rate is the count of correctly identified ground-truth entities divided by the total count of ground-truth entities in the training example. It is a number between zero and one that measures how much of the information the agent actually found, separate from whether the final answer was correct.

The paper estimates this by comparing the set of entities the agent mentioned during its reasoning process against the set of ground-truth entities provided in the synthetic data. Each correct entity contributes one unit to the numerator. This measurement is used directly as the reward signal in GRPO training—a near-miss with 90 percent entity accuracy gets a reward of 0.9, while a complete failure gets 0.0. This dense signal is far more informative than binary feedback because it tells the model exactly how close it came and what it got right.

Why it works

Why entity match rate fixes the learning problem

The core insight is that most answer mistakes come not from missing all the facts, but from getting the facts right and then reasoning incorrectly at the end. If an agent found all the correct entities but then made a small error combining them into the final answer, GRPO's binary reward gives it zero credit. That is wasteful—the agent learned 90 percent of the task correctly. With E-GRPO, that same near-miss gets a reward of 0.9 (or whatever fraction of entities were found). This reward is fed into GRPO's training update, which nudges the model's weights slightly in the direction that produced that high-entity-match attempt. Over many training steps, this dense signal accumulates, and the model learns: 'finding the right entities is 90 percent of the problem, and reasoning cleanly about them is the last 10 percent.'

A second effect emerges from the mechanism: the model learns to use tools efficiently. Binary GRPO penalizes tool calls that lead to wrong answers equally, whether the agent called the search tool once or 100 times. E-GRPO separates this: an agent that calls tools sparingly but finds most entities gets nearly full credit, while an agent that calls tools recklessly and finds few entities gets low credit. This implicit efficiency bonus causes the model to learn policies that find the right entities with fewer tool calls, reducing the time it takes to answer questions later.

The entity-aware reward formula

First in words:

Reward for an agent attempt is the number of ground-truth entities found divided by the total number of ground-truth entities

Then the compact form:

reward = (count of entities found) / (total ground-truth entities)

Every symbol:

count of entities foundhow many ground-truth entities the agent correctly mentioned in its reasoning
total ground-truth entitiesthe full count of important facts (names, dates, numbers) in the synthetic example
rewardthe training signal given to GRPO for this attempt; ranges from 0 to 1
A tiny worked example
Synthetic example: Question is 'Who won the 2020 Olympics?' with entities = [Tokyo, 2020, Olympics date].
Agent attempt 1: 'Tokyo 2020...' — correctly found Tokyo, 2020, but missed Olympics date. Count found = 2.
Reward 1 = 2 / 3 = 0.667. GRPO trains with this signal: nudge weights toward this reasoning.
Agent attempt 2: 'The Olympics happened.' — found none of the entities. Count found = 0.
Reward 2 = 0 / 3 = 0.0. GRPO trains with this signal: suppress this reasoning path.
Same GRPO algorithm, but E-GRPO gives attempt 1 credit (0.667) while attempt 2 gets zero, creating a clear training direction.

The reward is just a fraction—as straightforward as 'did you get 2 out of 3 facts right?' This replaces GRPO's binary right-or-wrong with a continuous scale.

What can go wrong

What can go wrong

Entity definition ambiguity. If ground-truth entities are not clearly defined or the agent uses slightly different phrasings (e.g., 'Olympics' vs 'Olympic Games'), the matching algorithm may fail to recognize correct entities, giving false low scores.
Entity set too small. If a synthetic example has only one or two ground-truth entities, the entity match rate becomes coarse (rewards are 0, 0.5, or 1.0). The training signal is weaker when finer gradations are needed.
Agent mentions entities out of reasoning context. If an agent says 'Tokyo' while reasoning about a weather question, the entity-matching algorithm may incorrectly count it as a found entity, inflating the reward.
Done right. E-GRPO works best when entities are unambiguous, numerous (5 or more per example), and extracted from the agent's reasoning trace (not just the final answer). The paper demonstrates this on question-answering and research tasks where entities are naturally structured.
What a runnable demo should prove

What a runnable demo should prove

A demo should show that E-GRPO reaches higher accuracy than GRPO with fewer training steps and fewer tool calls on the same synthetic data, because its entity-match rewards give far more training signal to near-misses than GRPO's binary feedback. Build a toy question-answering task with 50-100 synthetic examples. Each example has a question, a set of 5-10 ground-truth entities (names, dates, numbers), and a correct final answer. Implement two agents: one trained with GRPO (binary rewards) and one with E-GRPO (entity-match rewards). Run 1000 training steps on each and measure three metrics: final-answer accuracy (does the agent get the right answer?), entity-identification rate (does the agent find the ground-truth entities during reasoning?), and average tool calls per attempt. Plot all three metrics over time. E-GRPO reaches higher accuracy sooner because its entity-based rewards tell the model which reasoning steps are working even when the final answer is wrong, whereas GRPO treats all failures as equally useless. E-GRPO uses fewer tool calls because answers that find most entities with few searches get high reward, teaching the agent to be efficient. E-GRPO's near-misses become a training signal because a 90-percent-correct reasoning path gets a 0.9 reward instead of zero, a much stronger learning nudge.
