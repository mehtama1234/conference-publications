Efficient Probing: Lightweight Attention for Testing Pre-Trained Models

When models learn patch-by-patch features rather than one global summary, use cheap shared cross-attention queries to pick out exactly what each query needs instead of training separate attention heads.

Paper explainersAll themesRepresentation & Self-Supervised Learning

A pre-trained model is just frozen weights—you test it by bolting on a tiny probe and checking if it answers your question. Old-school probes use the model's global summary token ([CLS]); new ones use a selection mechanism (choosing weighted combinations of image patches) to collect the right pieces from many local regions. But those selection-based probes are bloated with redundant learned weights. This paper shows that a single shared query per selection head can do the same job with 90% fewer trainable parameters, across all kinds of pre-training: vision-language, masked image modeling, diffusion, and one-word-at-a-time generation.

Zero assumption version

The [CLS] token misses local features

Pre-trained models learn two kinds of knowledge: a global summary (stored in one special token called [CLS]) and local patch-level details spread across many small regions of the image. A model trained to rebuild missing patches learns mostly local knowledge—the [CLS] token says very little. The naive probe grabs [CLS], feeds it to a linear classifier, and scores poorly because it is missing the local detail.

Someone then thought: why not use attention (a mechanism that picks weighted combinations of patches) to collect the useful local patches into one representation? This is attentive probing. It works much better because it can adaptively pick the most informative patches for each task instead of using all patches equally or collapsing to one summary. But the existing approaches learn a separate complete attention head for each task, with full learned weight matrices to project patches and queries. This creates redundancy—many learnable parameters doing nearly identical work.

The problem in one sentence. Attention-based probes work well but train too many redundant weight matrices; we can achieve the same accuracy with shared queries that are 90% smaller.

The algorithm as a flow

What it actually does

Freeze the pre-trained model

Keep all original weights; you are only testing, not retraining.

Create M learnable query vectors (lists of numbers)

One query per selection head; each is a short list of numbers learned from scratch.

Each query computes a selection score over all patches

Compare query to each patch (dot product), then turn raw scores into weights that sum to 1 (softmax), to get a weighting for each patch.

Collect patch-weighted sum (pool)

Each query collects its top patches into one vector; M queries give M vectors.

Feed pooled vectors to task-specific classifier

Linear layer on top ranks/classifies; train only queries and classifier.

What the paper changes

What the paper changes

The paper removes redundant learned weight matrices that project queries and patches into a subspace. Instead of learning W_K (project patches to dimension D) and W_Q (project queries to dimension D) per head, it learns only M learnable queries directly in the original patch space and reuses the patch features as-is.

the object it moves  =  learned weight matrices
The hidden quantity

Parameter count: how much training load each variant carries

measured quantity  =  Trainable parameters in the probe

The paper measures not just accuracy but parameter count—how many numbers must be trained. Standard multi-head cross-attention (MHCA) trains separate weight matrices (W_K, W_Q, W_V) per head; efficient probing (EP) trains only one query vector per head and reuses the same patch features. This directly cuts trainable parameters from thousands to hundreds.

The paper estimates this by counting arithmetic operations, memory footprint, and actual parameter counts across six different probing variants. Lower is better, because a smaller probe can be run on cheap hardware and responds faster to new tasks.

Why it works

Why shared queries with reused patches work

In a standard selection head, each head learns its own query and projection matrices. For M patches, the projection matrices must reshape every patch and every query; this burns compute and memory. But the paper realized: the patch features do not change per head. Each head is just picking a different weighted sum of the same patches.

The trick is to learn M independent query vectors, one per head, and let each query score the raw patch features directly without projecting them first. This is mathematically equivalent to the old way (each query learns what patches to weight), but the patch projection layer vanishes, cutting the parameter count to only the M queries. Same information—which patches matter—flows through, same accuracy results, but 90% fewer trainable numbers.

Math after the picture

The attention pooling equation

First in words:

For each query head j, the pooled output is the sum over all patches of (attention weight for patch i) times (feature vector of patch i). The attention weight is computed by dot product between the learnable query and the patch feature, then softmax to normalize.

Then the compact form:

y_j = sum_i softmax(q_j^T x_i) * x_i

Every symbol:

y_jpooled representation from query j (output)
q_jlearnable query vector for head j
x_ifeature vector of patch i (from frozen pre-trained model)
softmax(...)turns dot-product scores into weights that sum to 1
sum_iweighted sum over all N patches
A tiny worked example with 3 patches and query dim=2
Patch 1 features: x_1 = [0.5, 0.3]
Patch 2 features: x_2 = [0.1, 0.8]
Patch 3 features: x_3 = [0.7, 0.2]
Query vector: q_1 = [0.4, 0.6]
Dot products: q_1^T * x_1 = 0.4*0.5 + 0.6*0.3 = 0.38
q_1^T * x_2 = 0.4*0.1 + 0.6*0.8 = 0.52
q_1^T * x_3 = 0.4*0.7 + 0.6*0.2 = 0.40
Softmax: exp(0.38)=1.46, exp(0.52)=1.68, exp(0.40)=1.49, sum=4.63
w_1 = 1.46/4.63 = 0.315
w_2 = 1.68/4.63 = 0.363
w_3 = 1.49/4.63 = 0.322
Pooled: y_1 = 0.315*[0.5,0.3] + 0.363*[0.1,0.8] + 0.322*[0.7,0.2]
y_1 = [0.157,0.095] + [0.036,0.290] + [0.225,0.064]
y_1 = [0.418, 0.449]

Query q learns which patches matter; low-importance patches get tiny weights; high-importance patches pull the pooled vector toward them.

What can go wrong

What can go wrong

Frozen model must have learned good local features. If the pre-trained model learned only a global summary (like old supervised ImageNet models), attentive probing including EP will gain little over [CLS]. The paper works well on self-supervised, vision-language, and masked-image models because they retain local knowledge; EP cannot create features the model never learned.
Queries can overfit to small probe datasets. If the downstream task has very few labels, M learnable queries might memorize noise rather than learn true patch importance. Gently steering training away from overfitting (via weight decay or early stopping) is needed.
Complementary attention maps assume tasks need diverse patch strategies. If a task is fully solvable from one region (e.g., reading a single label in a corner), multiple independent queries may learn redundant patterns; efficiency gains are smaller.
Done right: use EP on frozen models trained with local-feature preservation. Pair it with models that retain local knowledge, steer training away from overfitting on small datasets via weight decay, and accept that some tasks may not benefit from multiple selection heads.
What a runnable demo should prove

What a runnable demo should prove

Build a tiny experiment: take a pre-trained ViT model frozen on ImageNet, attach an EP probe with 4 learnable queries, train it on CIFAR-10 (a simpler dataset). Measure final accuracy, parameter count, and the diversity of the four attention maps (do different queries attend to different image regions, or are they redundant?). Run the same experiment with standard MHCA and [CLS] baselines. The demo should show that EP matches MHCA accuracy while using 10 times fewer trainable parameters, and that the attention maps are actually complementary (different queries pick different patches).

accuracy = (correct predictions) / (total test samples); parameter_efficiency = accuracy / (number of trainable parameters in thousands)

The demo makes it impossible to miss: EP does the job with one order of magnitude fewer weights, because different queries naturally specialize in different image regions without redundant projection matrices.
