Causal Feature Learning via Generalized Rayleigh Quotients

A method that extracts features from time-series data by finding which combinations of sensor readings matter for prediction while staying the same even when factory operating conditions change.

Paper explainersAll themesTime Series & Sequential

In a chemical plant, temperature and pressure sensors record hundreds of measurements per second. A fault (equipment failure) happens when something goes wrong. The challenge: the baseline operating conditions—how warm things usually are, what typical pressure is—shift when the plant switches products. A method that learned to spot faults under one condition fails completely when conditions change. This paper combines two ideas that had never been unified before: looking at which sensor readings affect the next one (temporal relationships) and ignoring changes that are just noise from shifting operating conditions.

Zero assumption version

Why are time-series sensors hard to use when conditions change?

In a manufacturing plant, thousands of sensors measure temperature, pressure, flow rates, and chemical composition. A fault detector learns from data: when sensors show pattern X, equipment usually fails in the next hour. The naive approach would be: collect data under operating condition A (steady temperature, usual flow rate), train a classifier, and deploy it. This works fine until management switches the plant to operating condition B—different products, different baseline values for everything. The sensor patterns change completely, and the detector now produces false alarms or misses real faults.

Existing methods tried two separate fixes. One captures temporal causality: it finds which past sensor readings directly cause future sensor readings (a temperature rise causes pressure to rise an hour later). The other captures environment invariance: it filters out shifts that come from changing baseline conditions, keeping only the signal that is stable across all operating scenarios. But no single method did both at once. A feature built only on temporal patterns fails when conditions shift. A feature built only for environment invariance ignores which sensors actually drive faults.

The paper's move: Build features from sensor data by finding which combinations stay stable across operating conditions AND matter for predicting faults in the next time step.

What the paper changes

What the paper changes

The paper changes the way a feature (a single number computed from multiple sensor readings) is designed. Instead of building a feature by hand or by optimizing only for temporal prediction, the method jointly tunes every sensor weight in the feature so that the resulting number is equally predictive of faults regardless of operating condition.

the object it moves  =  Feature weights
The hidden quantity

The hidden quantity: Mean Invariance Score

measured quantity  =  Mean Invariance Score

Take a specific feature—a formula that takes sensor readings and outputs one number. Under operating condition A, that number might average 45. Under condition B, it averages 42. Under condition C, it averages 39. Those differences are the condition drift—a signal that the feature itself is changing because of operating conditions, not because of faults. The Mean Invariance Score measures how much the feature's average drifts across operating conditions. A low score means the feature stays stable. The paper estimates this directly from the data: compute the feature value for all data collected in condition A, find its average. Do the same for B and C. Then measure how far apart those three averages are from each other.

The paper uses this hidden quantity in the objective: it penalizes large drifts. The Rayleigh quotient (the mathematical core of the method) has two parts: a numerator that rewards predicting faults, and a denominator that penalizes high Mean Invariance Score. Solving the quotient finds the feature that wins on both counts.

Why it works

Why it works: combining two sources of signal

A fault is a rare event. When one happens, certain sensors respond. If you only look at temporal patterns—which past sensors predict which future sensors—you learn the causality flow, but it is still pollution from operating conditions. The same temperature rise might mean something completely different under high pressure than under low pressure.

If you force the feature to have the same average value across all operating conditions, you eliminate the pollution. Why? Because operating-condition shifts are loud but uniform across sensors (everything gets warmer when you switch products). A feature that stays the same value across those shifts must be picking up something else—the signal that is actually predictive of faults. By combining temporal relevance (the numerator: which past sensors predict the fault) with environment mean invariance (the denominator: how much does the feature drift across conditions), the method extracts features that capture causality while staying stable. The mathematical trick—the Rayleigh quotient—finds the best trade-off automatically: it solves for the one feature that wins on both counts.

Math after the picture

The equation: Rayleigh quotient for causal features

First in words:

Find the feature weights that maximize the ratio of target prediction power to environment drift. In words: divide the squared correlation between the feature and the target by the squared spread of the feature's average across environments.

Then the compact form:

maximize (w^T Σ_target w) / (w^T Σ_drift w)

Every symbol:

wthe feature weights (one number per sensor)
Σ_targetcovariance between sensors and the fault target
Σ_driftcovariance of mean shifts across operating conditions
w^T Σ_target whow well the weighted feature predicts faults
w^T Σ_drift whow much the weighted feature drifts across conditions
A tiny worked example
Suppose three sensors: T, P, F. Weights start at w = [0.5, 0.3, 0.2].
Numerator (target power): [0.5, 0.3, 0.2] · covariance-with-fault · [0.5, 0.3, 0.2]^T = 0.84
Denominator (drift): [0.5, 0.3, 0.2] · mean-shift-covariance · [0.5, 0.3, 0.2]^T = 0.12
Quotient: 0.84 / 0.12 = 7.0
Try new weights w = [0.6, 0.4, 0.0] (drop F, boost T and P).
Numerator: 0.91, Denominator: 0.08, Quotient: 11.375 (better).
The method keeps iterating until no weight change improves the quotient further.

The quotient automatically scales the feature to trade off prediction power against environment stability; a higher quotient means better features because the feature now predicts faults equally well across all conditions instead of working only in one condition.

What can go wrong

What can go wrong

Insufficient data in one condition. If condition B has very few fault examples, the covariance estimate is noisy. The Rayleigh quotient then optimizes a poor estimate, and the resulting feature may not truly generalize.
Faults behave differently across conditions. If the root cause of a fault is itself sensitive to operating conditions (e.g., a bearing fails at different temperatures depending on humidity), then the assumption of a stable causal relationship breaks down. The method assumes the true fault mechanism is the same across conditions, so if it is not, the method cannot fix it.
Over-penalizing drift at the cost of prediction. If the method is tuned to make the feature extremely stable across conditions, it may discard sensors that are genuinely predictive but happen to have high mean values in some conditions. The trade-off weight must be set carefully.
Done right. Collect balanced fault data across multiple conditions, set the trade-off weight via cross-validation, and validate the final feature on held-out data from each condition separately. If detection rates stay consistently high, you have truly decoupled causality from condition noise.
What a runnable demo should prove

What a runnable demo should prove

Implement the Rayleigh quotient solver on a small synthetic time-series dataset. Create three operating conditions by shifting the mean of a 5-sensor stream, but keep the underlying fault signal the same across all three. Train the method on conditions A and B, then test on held-out faults in condition C. Compare the detection rate to a baseline that ignores condition shifts. The demo should show that the Causal Feature Learning method maintains high detection accuracy in condition C, while a naive temporal-only method sees detection collapse.

Detection accuracy on unseen condition = (faults caught) / (total faults)

If your feature works equally well when you slide the mean of all sensors, you have genuinely decoupled the causal signal from the operating condition noise.
