GRASP: Graph Reasoning via Agentic Solving and Probing

Let LLMs actively explore graph structure one neighbor at a time instead of trying to understand the whole graph at once.

Paper explainersAll themesAgents & Tool Use

Large language models are good at language but struggle when you ask them to reason about graphs (networks of connected things, like social networks or road maps). When you dump an entire graph into the model at once, it forgets parts, miscalculates, and invents fake connections. GRASP solves this by letting the model actively ask for neighbors step-by-step, verify calculations with code, and gradually learn what the graph really looks like.

Zero assumption version

Why whole-graph input fails

Picture this: find the shortest path between two cities in a road network with a thousand cities and ten thousand roads. If someone hands you the entire list of roads in one block of text, three problems hit immediately: First, the list is too long to fit in your working memory at once — you can only keep maybe a few dozen roads in mind. Second, if you try to do arithmetic on the distances (add them up, compare them), mistakes creep in because there is too much to track. Third, your brain will invent plausible-sounding roads that were never in the list, just filling gaps because the picture is incomplete.

Large language models have the same three bottlenecks: limited context windows (can only hold so much text), unreliable arithmetic when juggling many numbers at once, and a tendency to hallucinate — invent connections and nodes that fit the pattern but were never in the original graph. A beginner's approach is just to paste the whole graph into the model and hope for the right answer. That predictably fails.

In one sentence. Instead of ingesting the whole graph at once, let the model ask for one node's neighbors when it needs them, then use code to calculate answers reliably.

The algorithm as a flow

What it actually does

1. Model sees the question

Find the shortest path from A to E in this graph.

2. Model probes on demand

I am at A. What are my neighbors? System returns: B (distance 2.3), D (distance 1.8).

3. Code interpreter computes

Model asks Python to compare 2.3 and 1.8, decide which is shorter, track cumulative distance.

4. Model picks next step

D looks closer. What are D's neighbors? System: E (distance 1.1), B (distance 0.9).

5. Model learns and improves

After many such problems, model internalizes which types of graphs it saw and builds genuine intuition for navigation.

What the paper changes

What the paper changes

GRASP changes how the model retrieves graph information: instead of reading the whole graph at the start, the model dynamically fetches neighbors on-demand as it explores. This turns a static, memorization problem into an active navigation task.

the object it moves  =  neighbor retrieval strategy
The hidden quantity

Topological awareness: does the model truly understand the graph shape?

measured quantity  =  Genuine structure learning

The real insight is whether the model is genuinely learning the structure or just memorizing paths it has seen. In early training, the model can still see the whole graph laid out, so it might just copy memorized solutions. But GRASP includes a later training phase where the graph structure is hidden from view — the model only gets results when it asks. At this point, if the model succeeds, it means the model has internalized the actual graph topology (how nodes connect), not just recalled a memorized answer.

The paper measures this by comparing performance in two training environments: one where the model can peek at the full graph structure, and one where it cannot. A large performance drop in the structure-blind phase reveals the model was mostly memorizing; stable performance shows it truly learned the shape.

Why it works

Why this works: active exploration plus verification

The mechanism has three moving parts. First, on-demand neighbor retrieval shrinks the working memory problem: instead of holding a thousand nodes, the model keeps only the current node and its immediate neighbors in focus. It asks for neighbors when it needs them, like looking up one entry in a phone book rather than memorizing the whole directory.

Second, code interpretation removes arithmetic errors. When the model needs to compare distances or count steps, it hands the numbers to a Python interpreter which calculates perfectly. The model no longer has to guess whether 2.3 + 1.4 is 3.7 or make arithmetic errors under pressure.

Third, staged reinforcement learning forces genuine learning. In early training, the structure is visible (the model can cheat by memorizing). In later training, the structure is hidden and only revealed through queries. If the model succeeds in the hidden phase, it must have learned a real mental model of the graph — not just copied an answer. This selective pressure teaches the model to build and refine its internal understanding of how the graph is organized.

The reinforcement learning objective

First in words:

Staged loss equals: task reward minus a penalty term scaled by how far the model's current policy diverges from its previous safe policy, with the strength of that penalty decreasing over training stages.

Then the compact form:

L = R_task - beta * KL(pi_current || pi_previous)

Every symbol:

Ltotal loss (lower is better)
R_taskreward for answering the question correctly
betastrength of the divergence penalty (decreases over stages)
KL(pi_current || pi_previous)how different the new policy is from the old one
pi_currentmodel's current decision distribution (how it chooses neighbors)
pi_previousmodel's previous safe decision distribution
A tiny worked example
Suppose the model answers a shortest-path question correctly: R_task = 10 points.
The new exploration policy is slightly different from the old one: KL divergence = 0.5.
Beta (penalty strength) is set to 2.0 in this training stage.
Loss = 10 - 2.0 * 0.5 = 10 - 1.0 = 9.0.
If the policy diverged a lot (KL = 2.0): Loss = 10 - 2.0 * 2.0 = 6.0 (worse, penalized).
As training progresses, beta shrinks (say to 0.1), so divergence is allowed: Loss = 10 - 0.1 * 2.0 = 9.8.
Early stages keep policy close to safe (high beta); later stages encourage exploration (low beta).

The staged reduction of beta is key: start conservative (learn from visible structure), then loosen up (explore blindly and discover genuine understanding).

What can go wrong

What can go wrong

Model forgets its path. If the exploration sequence is too long, the model may lose track of which nodes it has already visited or what the current cumulative distance is, because the model's context window is finite. Shorter lookahead helps by reducing how far ahead the model must plan; explicitly storing visited nodes in memory reduces confusion about what was explored.
Neighbor retrieval is slow. Querying neighbors one-by-one is slower than reading the whole graph once. On million-node graphs, thousands of queries add up. Batching queries or caching frequently-visited nodes is a mitigation.
Model overfits to training graph structure. If the model only sees graphs of one specific type (e.g., road networks), it may not transfer to a different type (e.g., social networks). The paper tests this with unseen tasks; it passes, suggesting real generalization.
Done right. Pairing on-demand retrieval with code verification and staged training discipline forces the model to build and refine a genuine mental model of the graph topology.
What a runnable demo should prove

What a runnable demo should prove

Build a simple graph with 20-50 nodes and a handful of known shortest paths. Run the model in two modes: (1) full visibility (the model can see all edges upfront), and (2) query-only (the model must ask for neighbors). Measure the path cost and number of errors in each mode. The key result: performance should be nearly the same in both modes. If mode-2 (query-only) is much worse, the model was memorizing structure from mode-1, not learning it genuinely.

generalization gap = accuracy(full-visibility) - accuracy(query-only)

A small gap proves the model is learning real graph structure, not cheating.
