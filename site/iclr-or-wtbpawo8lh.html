Causal Discovery Voting Ensemble

Use voting (like a jury) to combine multiple causal discovery guesses into one more reliable answer.

Paper explainersAll themesLearning Theory

Figuring out cause-and-effect from data is hard: each method makes different guesses depending on tiny changes to the data, and no method is always right. This paper treats multiple discovery methods like voters in an election and combines their votes mathematically to find the true causal graph. The voting rule comes with proof that it works.

Zero assumption version

Why a single causal discovery method fails

Each causal discovery method (a tool that reads data and guesses which variables cause which) makes a different guess. Change the data slightly, or run the same method with different random starting points, and you get a different answer. The method might assume things about the data that are not true, or get stuck in a local optimum (a mediocre answer that is hard to escape from). A user cannot trust a single answer.

A naive approach: just pick the method that performed best on your past data and use that. But this fails because no method works everywhere — one that is great on data from biology might be terrible on data from economics.

The problem. Single causal discovery methods give inconsistent answers; no one method works universally.

The algorithm as a flow

What it actually does

Run many methods

Apply three or more different causal discovery algorithms to the data.

Vote on edges

For each potential cause-arrow, count how many methods predict it exists.

Score each method

Measure how often each method tends to be correct (its accuracy on test data).

Reweight votes

Give high-accuracy methods larger voting power; ignore unreliable ones.

Consensus graph

Include a cause-arrow only if weighted votes exceed a threshold.

What the paper changes

What the paper changes

This paper changes how the ensemble combines predictions. Instead of heuristic (ad-hoc) averaging or majority vote, it uses mathematically justified weighted voting.

the object it moves  =  voting weights (how much each method's vote counts)
The hidden quantity

The competency score

measured quantity  =  method competency (how accurate each method is)

The paper identifies and measures one key hidden quantity: each method's true competency — how often that method correctly identifies real cause-and-effect edges. This is not just accuracy on all edges, but specifically how well that method ranks real edges higher than fake ones. The paper shows this competency score should determine each method's voting weight: a method with competency 0.8 (gets it right 80% of the time) votes with twice the power of a method with competency 0.6 (60% accurate).

The paper estimates competency from agreement patterns: if two very different methods both predict the same edge, that edge is more likely to be real, so both methods gained evidence they are competent on this data.

Why it works

Why weighted voting recovers the true causal graph

Here is why it works: if you run many methods and weight their votes by accuracy, accurate methods will outvote the inaccurate ones. An accurate method correctly predicts most real cause-arrows and correctly rejects most false ones. An inaccurate method predicts randomly, so its votes scatter. When you take a weighted sum, the accurate methods' votes all point in the same true direction, but the inaccurate methods' votes cancel out. The final vote count is dominated by truth.

The paper proves this formally: under certain conditions (the methods must be independent, i.e., not all making the same systematic mistake, and the true causal graph must be identifiable from the data), the weighted voting ensemble recovers the true graph with high probability. The weights are set using the competency scores. If you use equal weights instead, you lose this guarantee — inaccurate methods drag down the answer.

Math after the picture

The voting rule

First in words:

Total vote for edge (i to j) equals sum of each method's competency times its prediction of that edge

Then the compact form:

vote_ij = sum_k w_k * pred_ij_k

Every symbol:

vote_ijtotal weighted votes for cause-arrow from i to j
w_kvoting weight (competency) of method k
pred_ij_k1 if method k predicts edge i→j, 0 if not
kindex over all methods in the ensemble
A tiny worked example
Three methods run on a dataset with variables A, B, C.
Method-1: competency 0.9 (very accurate); predicts edges A→B and A→C.
Method-2: competency 0.6 (medium); predicts edges A→B and B→C.
Method-3: competency 0.3 (weak); predicts B→A and B→C.
Vote for edge A→B: 0.9*1 + 0.6*1 + 0.3*0 = 1.5
Vote for edge A→C: 0.9*1 + 0.6*0 + 0.3*0 = 0.9
Vote for edge B→A: 0.9*0 + 0.6*0 + 0.3*1 = 0.3
Vote for edge B→C: 0.9*0 + 0.6*1 + 0.3*1 = 0.9
If threshold is 1.0: A→B wins (1.5≥1), others lose.
Result: A causes B (only edge above threshold). Accurate.

Trustworthy methods (high weights) tip the vote toward truth; noisy methods contribute less.

What can go wrong

What can go wrong

All methods fail the same way. If every method makes the same systematic mistake (e.g., all assume there are no cycles in the cause-graph when there actually are), weighted voting will not help because all votes point in the same wrong direction, so the weighted sum is still wrong. The paper's math assumes the methods are independent — each one's errors are different, so they cancel out. This breaks if all methods share a blind spot.
Methods depend on each other. If every method is a small tweak of one base algorithm, they all inherit the same flaw. Voting only works if methods are truly independent.
Competency score is wrong. If you measure each method's accuracy on a small or non-representative test set, the weights will be unreliable, and the ensemble can be worse than a naive average.
Done right. Use diverse methods (different algorithm families); estimate competency on a held-out test set; ensure the true causal graph is identifiable from the data you have.
What a runnable demo should prove

What a runnable demo should prove

Build a synthetic causal system where you know the true graph (e.g., a small acyclic graph where variable A causes B and C, and B causes C). Run three causal discovery methods on this data. Measure each method's accuracy (true positives and true negatives for edges). Build a voting ensemble with weights set by those accuracies. Compare the ensemble's graph against the ground truth; also compare it to (1) each single method alone and (2) an unweighted ensemble (equal vote for each method). The demo should show that weighted voting finds more edges correctly than any single method or unweighted ensemble, especially when data is noisy.

accuracy = (true edges found + true non-edges rejected) / total possible edges

Weighted voting should recover the true causal structure with fewer false alarms than any single method, even on noisy data.
