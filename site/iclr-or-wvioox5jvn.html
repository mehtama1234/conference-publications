Causally Robust Preference Learning with Reasons

ReCouPLe uses the user's stated reason for a preference to train the reward model on the causal feature that matters, instead of letting it rely on spurious context.

Paper explainersAll themesOther

Preference-based reward learning usually gets only binary supervision: trajectory A is preferred to trajectory B. That signal is sparse. It tells the model which option won, but not why it won. As a result, the reward model often picks up shortcuts. If safer trajectories in training also happened to be slower, the model may learn to reward slowness rather than safety. ReCouPLe adds the missing reason. It takes a natural-language rationale such as 'avoids collisions with a fragile object' and uses it to define the direction in representation space that should matter for scoring. The point is not to attach extra text for decoration. The point is to isolate the causal feature the user cared about and suppress unrelated context that merely co-occurred during training.

Zero assumption version

Why binary preferences are easy to misread

A reward model sees paired trajectories and a preference label. If one trajectory wins, standard training tells the model to increase its score. But a trajectory contains many features at once: speed, distance to obstacles, path smoothness, object type, and background context. The label alone does not identify which of those features caused the preference.

That ambiguity creates causal confusion. During training, a preferred property may co-occur with irrelevant properties. A model trained only on winner-versus-loser labels can assign credit to the wrong feature. It will still fit the training data, but it will fail when the spurious correlation disappears or reverses. A reward model that mistakes slowness for safety is one example.

What the paper adds. Add the stated reason for the preference and force the reward model to score trajectories using the feature direction aligned with that reason.

The algorithm as a flow

What it actually does

Collect preference pairs with rationales

Each preferred trajectory is paired with a short textual reason that states what property justified the choice.

Encode trajectories and reasons

The model maps both trajectories and rationales into a shared representation space so they can be compared directly.

Use the rationale as a projection axis

Trajectory features aligned with the reason are emphasized, while orthogonal context is de-emphasized.

Train preference scores with that projection

The reward model is optimized to rank the preferred trajectory higher after filtering through the rationale-aligned direction.

Reuse the same reason across tasks

A rationale that appears in several tasks can transfer the same causal preference without retraining a new language model.

What the paper changes

What the paper changes

The paper changes what supervises the reward model. Instead of learning only from binary pairwise wins, it learns from pairwise wins plus the explicit reason that should determine the win.

The hidden quantity

The model must identify the causal feature, not just the winning trajectory

measured quantity  =  reason-aligned causal direction

The hidden quantity is the feature direction that corresponds to the user's reason. For a rationale about avoiding collisions, the model should respond to collision risk and ignore unrelated factors that happened to travel with low collision risk in the training set.

This quantity matters because preference labels alone underdetermine the cause of a choice. Many distinct feature explanations can fit the same pairwise data. The rationale narrows that set by naming the intended causal factor, so the reward model can anchor its score to the right part of the trajectory representation.

Why it works

Why the reason helps remove causal confusion

A binary preference label says only that one trajectory beat another. Without extra structure, the reward model can explain that win using any feature pattern that separates winners from losers in the training set. That is exactly how shortcut learning enters.

ReCouPLe adds structure by encoding the rationale and using it as a projection axis in the shared representation. Projection means the trajectory is scored according to how much of its representation lies in the direction named by the reason. Features orthogonal to that direction contribute less. This works because the reason selects the subspace that should matter, so the model is discouraged from using unrelated background cues even if those cues correlate with winners in the training data.

The transfer benefit comes from semantic reuse. If two tasks both contain the rationale 'avoids collisions with a fragile object,' then the same direction can be used in both places. The reward model does not need to rediscover the causal feature from scratch on the second task, because the textual reason already points to the same axis. That is why the method can generalize across tasks without extra language-model fine-tuning.

Reason-conditioned reward score

First in words:

Score a trajectory by taking the component of its representation that lies along the rationale direction. The reward then depends mainly on that aligned component.

Then the compact form:

r(t, c) = h(t)^T g(c)

Every symbol:

ta trajectory
cthe user-provided rationale text
h(t)the trajectory representation produced by the encoder
g(c)the rationale representation, used as the direction that selects the relevant feature component
A tiny worked example
Suppose trajectory A and trajectory B are equally slow, but only A keeps distance from a fragile object.
The rationale is 'avoids collisions with a fragile object.'
If the trajectory encoder gives A a larger component along the rationale direction than B, then A gets the higher reward.
Background brightness does not help unless it also aligns with the rationale direction.
This is why the reason can block shortcut credit assignment when the training set contains irrelevant correlations.

The score is conditioned on the reason, so the same trajectory can be rated differently under different stated preferences.

What can go wrong

What can go wrong

Reasons can be vague or incomplete. If the rationale says only 'better behavior,' it does not isolate a usable causal feature, so the projection direction may still leave room for shortcuts because the model has not been told which property should receive credit.
The encoder may not represent the needed feature well. If collision risk or some other key property is not visible in the trajectory representation, aligning with the rationale direction will not recover it.
Some preferences depend on multiple reasons. A single rationale direction may be too simple when a user cares about several interacting factors at once, such as safety, speed, and comfort together.
Done right. The method is strongest when reasons are concrete and reusable across tasks, because then the same direction can serve as a stable causal guide in multiple settings.
What a runnable demo should prove

What a runnable demo should prove

Construct a small trajectory dataset where the true preference depends on safety, but speed is spuriously correlated with safety in training and anti-correlated at test time. Train one reward model on binary preferences only and another on binary preferences plus rationales. The demo should show whether the rationale-conditioned model keeps preferring safer trajectories after the correlation flips.

causal_generalization_gap = test_score_with_rationales - test_score_without_rationales

The demo must show that the textual reason changes what feature receives credit, not merely that it adds more supervision volume.
