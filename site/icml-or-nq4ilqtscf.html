Vector Bundle Attention for Geometric Representation Learning

A transformer that aligns features by rolling them along the curves of data before comparing them, rather than ignoring the shape.

Paper explainersAll themesGraph & Geometric Learning

Real data in biology, physics, and computer vision often lives on curved surfaces or has natural directional structure. Standard deep learning models compare features anywhere in space without caring about this shape, treating direction arrows from different locations as if they pointed the same way. This paper embeds alignment directly into the attention mechanism — a core part of modern neural network models — by giving each feature a location on the data's curved surface and a direction arrow, then aligning those directions using parallel transport, which means rolling a direction arrow along a curve to keep it locally aligned to the surface.

Zero assumption version

Comparing features on curved surfaces the wrong way

Many datasets live on curved manifolds — single-cell gene expression sits on a nonlinear surface, point clouds trace out 3D shapes, spatial transcriptomics cells form tissue patterns. In these datasets, two identical feature vectors at different locations on the surface carry fundamentally different meanings because of how the surface curves there.

Graph Neural Networks try to fix this by only comparing nearby neighbors, but they are limited by local message passing and miss distant relationships. Transformers (a type of neural network model that compares any pair of elements anywhere in a dataset) can compare any element to any other across the whole dataset, capturing long-range relationships, but they treat all pairs the same way — they do not know about the curved surface those elements sit on.

A naive approach: just feed raw coordinates plus features into a standard transformer. This fails because direction vectors point in absolute space, not along the surface. Two identical feature vectors in opposite directions on a sphere are treated as the same, even though they are misaligned with respect to the surface they live on.

In one sentence: Before comparing features on curved data, align them to a shared reference direction on the surface itself.

The algorithm as a flow

What it actually does

Embed each element with surface info

Each element gets a surface location coordinate plus a direction vector.

Compute shortest paths

For each query-key pair, find the shortest path between them on the data surface.

Move vectors along the path

Roll the key's direction vector along that path; it arrives pointed in the query's local frame.

Compare in local frame

Now compare query and moved key as if they sit in the same local neighborhood; similarity is honest.

Aggregate using aligned comparisons

Sum over all keys using these surface-aware weights; output respects the data's true shape.

What the paper changes

What the paper changes: the fiber vectors in attention

The single object this method modifies is the feature vector (the fiber) that enters attention similarity computation. Instead of using raw features as the transformer does, this paper first aligns them to a shared coordinate system on the manifold surface using parallel transport.

The hidden quantity

Geometric alignment error: measuring how well features are oriented

measured quantity  =  fiber transport alignment

The hidden quantity this paper measures (implicitly) is the alignment error: by how much do two feature vectors fail to point in comparable directions when one is transported to the other's location? On a flat plane, this error is zero — two identical vectors at different locations still point the same way. On a curved surface, two features that would be identical in absolute space land at different angles and the error is nonzero.

The paper estimates this by explicitly computing parallel transport between every query-key pair before attention. If the data truly lives on a manifold, this transport step captures geometric structure that a flat transformer misses. The error is smallest when the data lies on a genuine curved manifold and the transport is accurate; it grows when data is nearly flat (so transport hardly changes anything) or when the data does not have clear geometric structure.

Vector bundle theory formalizes this: the base manifold M is the space the data lives on, the fiber at each point is the feature space, and the connection (here Levi-Civita) defines how to move vectors along curves. Parallel transport is the natural way to compare vectors at different points on the manifold.
Why it works

Why aligning features to the surface helps learning

The core mechanism is this: when two features lie on a curved surface, comparing their raw direction vectors without accounting for that surface is misleading. If the data really lives on a lower-dimensional curved surface (say a 2D surface embedded in 100-dimensional space), then the important direction between two similar features is along that surface, not straight through the empty space around it.

By rolling the key's feature to the query's location before computing attention, the method ensures that the comparison happens in the query's local neighborhood frame — the flat plane that best approximates the surface at that point. In this local frame, similarity scores reflect true surface neighbors, not false neighbors that are close in absolute distance but far apart when you travel along the surface.

This has two effects: (1) attention weights concentrate on neighbors that are close along the surface, because those comparisons now carry the highest similarity scores even if the neighbors are far in absolute distance, and (2) during training, the model's learning signals point in directions that respect the surface structure, so the model learns to exploit the data's true shape instead of ignoring it.

Math after the picture

The geometric attention mechanism

First in words:

Attention weight from query to key equals softmax (scaled dot product of transported key with query, over all keys, in the query's tangent space). The transport maps the key feature from its location to the query location by moving it along the manifold's shortest path.

Then the compact form:

attn_weight_i = softmax_k [ (Q_i . Transport(K_k, p_i, p_k)) / sqrt(d_head) ]

Every symbol:

Q_ifeature vector of query token at location i
K_kfeature vector of key token at location k
p_ibase manifold coordinate of query token
p_kbase manifold coordinate of key token
Transport(K_k, p_i, p_k)parallel transport of K_k from location p_k to location p_i along the manifold
d_headdimension of the attention head
softmax_kexponential normalization over all key tokens
A tiny worked example on a 1D circle
Suppose data lives on a circle; elements are at angles 0°, 90°, 180°, 270°.
Query at 0°, direction vector [1, 0] (pointing forward in absolute space).
Key at 90°: direction [1, 0] (same absolute direction); roll to query's frame rotates it 90° to [-0.02, 1.0].
Key at 180°: direction [1, 0]; rolling rotates it 180° to [-1.0, 0.02].
Dot products: Q · Rolled(K_90) = 1 times (-0.02) plus 0 times 1.0 = -0.02 (low, not aligned).
Q · Rolled(K_180) = 1 times (-1.0) plus 0 times 0.02 = -1.0 (lowest, opposite direction).
After scaling and exponential normalization, query pays low attention to the key at 90° even though both had [1,0] in absolute space, because after rolling to the same frame they are perpendicular. The surface correctly captures this.

The rolling operation is the key: it rotates direction vectors to match the query's local frame before computing similarity, so attention respects the surface structure.

What can go wrong

What can go wrong

Data is not actually on a curved surface. If the dataset is truly random high-dimensional noise with no underlying curved structure, rolling features along a fake surface does nothing — the rolled direction is as meaningless as the original — so the method performs identically to a standard model while paying extra computational cost. You waste time and memory for no gain.
Surface estimation is inaccurate. If the surface is estimated wrongly from the data, then the shortest paths are wrong, and rolling features along bad paths rotates them in the wrong direction. The rolled features become less aligned than the originals, so attention becomes worse than the baseline because the model now uses corrupted direction vectors. This risk is high on noisy data or when the structure is not smooth.
Computational cost grows with sequence length. Computing a shortest path and rolling for every query-key pair costs more than standard attention. The extra cost per pair means long sequences run slower, because the method does a manifold operation for each of the n-squared query-key combinations.
Done right: use on real curved data When data truly lives on a curved surface (e.g., gene cell state spaces, point cloud shapes, or physics domains), and the surface can be estimated reliably from data, this method learns the surface structure and achieves faster convergence because the learning signals point along the surface from the start.
What a runnable demo should prove

What a runnable demo should prove

Generate synthetic data on a known sphere (e.g., sample points uniformly on a 2D sphere embedded in 100 dimensions). Train a standard transformer and VBA-Transformer on a supervised task (e.g., classify northern vs southern hemisphere). The demo should show that VBA-Transformer converges faster: its training loss drops earlier because the surface-aligned comparisons give stronger learning signals, and by the end its attention weights concentrate on elements that are close when traveling along the surface (e.g., elements at similar latitudes) while the baseline gives random attention patterns.

surface_alignment = fraction of high-attention pairs that are close when traveling along the surface (within 0.5 distance), not random
