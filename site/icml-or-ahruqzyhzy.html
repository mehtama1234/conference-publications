Transformers Provably Learn Algorithmic Solutions for Graph Connectivity, But Only with the Right Data

Show that a transformer can learn the exact graph-connectivity algorithm, but only when the training graphs mostly fit the depth limit of the model.

Paper explainersAll themesOther

A graph-connectivity task asks a simple question: given two nodes, is there any path between them? Standard training of a transformer (a layered sequence model that repeatedly mixes information across positions) often fails to learn the exact rule and instead learns shortcuts that work only on the training range. This paper explains why. It proves that a simplified transformer can compute connectivity by repeatedly expanding reachability, but only up to a graph diameter limit set by the number of layers. It then shows that training data beyond that limit pushes learning toward a degree-based shortcut instead of the exact algorithm.

Zero assumption version

Why algorithm learning and shortcut learning get mixed together

To solve connectivity exactly, a model must determine whether reachability can be propagated through several hops. That requires a computation whose depth grows with graph diameter, because information from one node must travel through intermediate nodes before the answer is known.

A transformer can instead learn a shortcut. For many training data patterns, connected node pairs correlate with simple local signals such as high degree or short paths. Those signals are easier to pick up early in training. If the training set contains many graphs whose diameters exceed the model's layer capacity, the exact algorithm cannot fit them anyway, so optimization has an incentive to settle on the cheaper shortcut because the shortcut still lowers loss on those impossible cases.

The paper's claim in one sentence. The model can learn the real connectivity procedure, but the training data must mostly stay inside the diameter range that the model depth can represent.

What the paper changes

What the paper changes

The paper changes the explanation for transformer failure on algorithmic tasks. The issue is not only that the architecture lacks the right operation. The issue is also that the training set can reward a shortcut more strongly than the exact algorithm when too many examples exceed model capacity.

The hidden quantity

The hidden quantity

measured quantity  =  the fraction of training graphs that fit the model's depth budget

The key quantity is the share of graphs whose diameters are small enough for the model to solve exactly. If that share is high, the loss can be reduced by learning the true propagation rule, because the rule succeeds on many examples and extends cleanly to nearby cases.

If that share is low, the exact rule cannot explain much of the dataset. Then early training updates favor local hints such as node degree, since those hints improve training loss on many examples even though they do not encode connectivity itself.

Why it works

Why the training data determines whether the model learns the algorithm

In the proved construction, each layer expands the set of nodes known to be reachable. After one layer, the model can combine local edge information. After more layers, that information has passed through intermediate nodes, so the model can represent longer paths because each added layer performs one more reachability expansion. The result is a bounded but exact procedure for connectivity.

Training does not automatically discover that procedure. The optimizer follows whichever pattern gives the clearest loss reduction first. On within-capacity graphs, the exact propagation rule explains the labels, so its signal accumulates across batches. On beyond-capacity graphs, the rule cannot finish the job, so the training updates from those examples push toward easier local statistics that partially correlate with the labels.

That is why restricting the training set helps. The restriction does not add new compute or new modules. It changes the optimization target so the exact rule is rewarded often enough to become the dominant learned computation.

Math after the picture

The reachability update

First in words:

Connectivity can be computed by repeatedly expanding which nodes are reachable from the source. One matrix multiplication adds another hop of reachability information.

Then the compact form:

r_(t+1) = A r_t

Every symbol:

Athe adjacency matrix of the graph
r_tthe indicator of which nodes are reachable after t propagation steps
r_(t+1)the updated reachable-node indicator after one more propagation step
A tiny worked example
Start from one source node, so only that node is marked reachable at step 0.
After one multiplication by the adjacency matrix, every direct neighbor becomes marked reachable.
After the next multiplication, neighbors of those neighbors become reachable as well.
Repeating this process long enough reveals whether the target node is in the same connected component.

The proof shows that the layer stack can emulate this repeated update up to a diameter bound determined by model depth.

What can go wrong

What can go wrong

Too much restricted data can narrow the task. If the training set covers only very easy graphs, the model may still fail on larger but in-capacity cases because it never learned the full range of intermediate path structures.
The proof applies to a simplified architecture first. Standard transformers include additional interactions, so the exact constructive proof does not transfer line by line even though the data-capacity lesson appears in experiments on the larger architecture.
Shortcut cues depend on the data generator. If a benchmark accidentally makes degree or other local statistics strongly predictive, the model may keep using them unless the dataset is designed to break those correlations.
Done right. Match the graph-diameter range to model depth, keep enough variety inside that range, and test on data patterns that break local shortcuts because that exposes whether the model learned the exact rule.
What a runnable demo should prove

What a runnable demo should prove

Generate random graphs and ask whether marked node pairs are connected. Train one transformer on graphs whose diameters mostly fit the chosen layer depth and a second transformer on a mixed set that includes many larger-diameter graphs.

Then evaluate both on graphs that preserve the same connectivity rule but vary node counts and degree patterns. The demo should show that the restricted-data model keeps working when local shortcuts break, because its training updates favored repeated reachability propagation instead of degree correlation.
