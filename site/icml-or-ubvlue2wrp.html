Stabilizing Robot-Human Learning with Lyapunov Contractions

When a robot and human try to coordinate by each learning independently, their policies can diverge wildly, but locking both into a mathematical contraction space makes them learn stably together.

A robot and a human each try to improve their own policy (their rule for what action to take) by learning from shared experience. Without structure, their independent learning updates can oscillate and diverge because they have different bodies and different goals. HALO fixes this by enforcing a mathematical contraction — a shrinking boundary in policy space that keeps both learners pulled toward cooperation.

Zero assumption version

Why independent learning breaks in two-agent scenarios

In robot-human collaboration, the robot and human are learning partners. Each has its own policy — a set of rules deciding what action to take in any situation. A naive approach: let each learner compute gradients (which way to nudge their policy to get higher reward) and update independently, as if the other agent is fixed.

This fails because the robot and human are not actually separate. The human adapts to the robot's moves; the robot adapts to the human's moves. When both update at the same time with independent gradients, they chase each other in circles. The robot learns a new move, the human responds differently, the robot's new move is now bad, so the robot learns again — creating oscillation and divergence instead of stable cooperation.

The problem in one sentence. Two independent learners in a shared environment can chase each other's updates and diverge instead of converging to cooperation.

The algorithm as a flow

What it actually does

Measure the divergence

Compute how far apart the robot's policy is from the human's policy (measuring difference in all the numbers inside each policy).

Apply a contraction map

Use a mathematical function that shrinks the distance: if the policies are far apart, pull them closer.

Project gradients into the contraction zone

When each learner computes its update direction, rotate it so the move stays inside the shrinking boundary.

Update both policies

Apply the projected gradients to both robot and human policies.

Repeat until convergence

As the contraction shrinks, both policies converge to a stable cooperative solution.

What the paper changes

What the paper changes

The paper modifies the gradient update rule itself. Instead of applying raw gradients to each policy, it projects them through an optimal quadratic function (a particular curved shape) that ensures the new policies stay inside a shrinking zone. This is the mathematical device that enforces contraction.

the object it moves  =  policy gradients (redirected via projection)
The hidden quantity

The rationality gap — the central quantity

measured quantity  =  rationality gap (distance between policies)

The rationality gap is the mismatch between what the robot 'thinks' the human will do and what the human actually does, measured as the distance between their policy parameters (the numbers inside each learner's decision rule). A large gap means the two policies are far apart and will chase each other. A small gap means they are coordinated.

HALO measures this gap at each training step and enforces that it shrinks monotonically — meaning it gets strictly smaller every step, never growing. This is the proof that learning will not diverge.

Why it works

How contraction stabilizes learning

The core idea: if you can prove mathematically that a quantity shrinks at every step, you know the system converges. HALO uses a Lyapunov function — a mathematical measure of disorder that decreases monotonically. Here, the disorder is the rationality gap.

When the robot computes its gradient (which way to move in policy space), that gradient would normally move the robot's policy independently. But HALO projects it: finds the closest move in the same direction that keeps the robot inside the shrinking boundary. The human's gradient is projected the same way. Both learners move, but always in a way that brings them closer, shrinking the gap. Over many steps, they spiral inward toward a shared policy.

Math after the picture

The contraction formula

First in words:

new gap is at most a shrinkage factor times the old gap

Then the compact form:

||theta_robot_new - theta_human_new|| <= rho * ||theta_robot_old - theta_human_old||

Every symbol:

theta_robot_newrobot policy after this update step
theta_human_newhuman policy after this update step
theta_robot_oldrobot policy before this update step
theta_human_oldhuman policy before this update step
||...||distance (how far apart two policies are)
rhoshrinkage factor, between 0 and 1; closer to 0 means faster convergence
A tiny worked example
Before update: robot at position 5.0, human at position 8.0, gap = 3.0
Shrinkage factor rho = 0.8 (20 percent reduction each step)
After projection: gap should be at most 0.8 * 3.0 = 2.4
Actual update moves robot to 5.6, human to 7.8, new gap = 2.2
Check: 2.2 < 2.4, so contraction is guaranteed. The gap shrinks every time.

The projection ensures that no matter what direction the raw gradients point, the actual update shrinks the gap, making convergence inevitable.

What can go wrong

What can go wrong

Shrinkage factor too weak. If rho is close to 1 (say 0.99), the contraction zone shrinks so slowly that it does not force convergence in reasonable time. Learning stalls or becomes glacially slow.
Projection breaks gradient quality. The quadratic projection can distort a well-aimed gradient into a poor direction. If the original gradient was optimal for one learner, the projection might degrade it. The trade-off between stability and optimality must be tuned.
Human behavior is not stationary. If the human's policy changes due to factors outside the robot's model (fatigue, distraction, learning their own task), the rationality gap can widen due to external shock, breaking the contraction proof.
Done right: tune rho adaptively. Set rho conservatively (0.85–0.95) to balance stability and speed. Monitor the actual gap; if it stops shrinking, increase rho slightly or apply adaptive scheduling. Test in simulation first, then deploy to real robots with safety overrides.
What a runnable demo should prove

What a runnable demo should prove

Build a simple two-player game: robot and human each control one agent trying to navigate to a shared goal. Each has its own observation and reward. Train both players with independent policy gradients for 500 steps without HALO, recording the gap between their policies and the task success rate. Then train again with HALO, applying the contraction projection at each step. Visualize the gap over time: without HALO it should oscillate or grow; with HALO it should monotonically shrink. Task success improves steadily with HALO because the shrinking gap means both learners' updates reinforce each other instead of interfering; without HALO they cancel each other out, so success stays flat or degrades.

convergence_proof = (gap_final < gap_initial) AND (success_rate_final > success_rate_initial)

If the gap shrinks monotonically and success improves, the contraction is working because the projection is truly steering both policies inward. If the gap oscillates or grows, the method is failing because the contraction proof has been violated.
