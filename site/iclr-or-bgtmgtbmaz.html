Eigen-1: Token-Level Retrieval Without the Pause

Instead of pausing reasoning to fetch facts one step at a time, weave knowledge into each reasoning step at the token level and let candidates repair each other's errors.

Paper explainersAll themesAI for Science

Science problems need both deep reasoning and precise facts. Traditional approaches ask the model to pause, retrieve a fact (costing extra tokens and attention switches), then resume—like constantly looking up a phone number during a conversation. Eigen-1 fixes this by retrieving knowledge silently, token by token, during reasoning, and by letting multiple solution attempts repair each other's gaps.

Zero assumption version

The tool tax: pausing reasoning to fetch

Solving a hard biology problem—counting how many organisms with a specific trait would result from genetic crossing—is not pure logic; it also requires precision facts (what is a Punnett square? what does this gene variant do?). Today's multi-step reasoning systems handle this by using agents: one agent acts as Proposer (tries to reason), another as Querier (decides when to look up a fact), and Retriever fetches it. But every time the Querier says 'I need a fact,' the model stops, fetches (costs ~8-10 extra tokens per pause), and resumes. For a complex genetic problem, this creates 8-10 interruptions, doubling the number of agent steps and breaking the flow of reasoning.

The second problem is that when multiple agents try the problem in parallel, their answers are averaged together. But averaging a strong solution (the right haplotype count) with weak ones (wrong counts) dilutes the right answer. Traditional multi-agent systems treat all candidates equally, discarding what one agent got right that another got wrong.

The fix in one sentence. Embed knowledge retrieval inside each reasoning step (no pauses), and let each candidate solution be actively repaired by borrowing correct reasoning from other candidates.

What the paper changes

What the paper changes: when and where knowledge enters reasoning

Traditional RAG (Retrieval-Augmented Generation) retrieves when an agent explicitly asks. Eigen-1 changes this: instead of pausing to retrieve, the Monitor agent listens inside the reasoning stream itself, at the token level, and decides when facts are needed without interrupting. The knowledge injection happens embedded in the flow, not as a separate pause-and-fetch step.

The hidden quantity

The tool tax: cost of explicit retrieval

measured quantity  =  Tool Tax (tokens and steps wasted by pausing)

Every time an agent says 'I need a fact,' the system pauses reasoning, runs a retrieval step (costs tokens), and resumes. For a genetics problem needing 8-10 lookups, this tool tax is real: ~double the number of agent steps and 53.5% higher token usage than the baseline without retrieval.

The paper estimates this tool tax by comparing three configurations: no retrieval (fast but wrong), explicit retrieval (slower, more tokens, but accurate), and implicit retrieval (Eigen-1: accurate AND fast). The hidden quantity is the overhead—how many extra tokens and steps are wasted by the interruption itself, independent of the reasoning quality.

Why it works

Why implicit retrieval at token level beats explicit pauses

Explicit retrieval asks the model to reason, then stop and decide 'I need a fact,' then wait for retrieval, then resume. Each pause is a context switch: the model must remember what it was thinking, accept new tokens (the retrieved fact), and re-engage. This disruption compounds with each pause.

Eigen-1's Monitor operates inside the token stream. As the model generates each reasoning token, the Monitor listens and asks: 'Is there a knowledge gap here?' If yes, knowledge is retrieved and injected into the next tokens in the stream, without a pause. The reasoning continuity is preserved—facts flow in like water through a conversation, not like an interrupting phone call.

On top of this substrate, the Hierarchical Solution Refinement layer adds: instead of averaging five candidate solutions equally, Eigen-1 designates one as the 'anchor' and lets the other four repair it. This repair process is iterative—each candidate takes a turn as anchor, and peers fix its errors (logical gaps, arithmetic mistakes, wrong method choices). Hard reasoning tasks (logic, multi-step deduction) benefit from consensus (all five agents voting on the final step), while retrieval tasks benefit from diversity (keeping all five candidate answers for retrieving different knowledge paths). The Quality-Aware Iterative Reasoning layer adapts the refinement depth based on solution quality: if most anchors are already good, fewer repair cycles are needed.

The repair penalty and quality weighting

First in words:

quality_weighted_penalty = sum over all candidates (quality_score * distance_to_consensus + repair_depth_cost)

Then the compact form:

L = sum_c quality_c * (||anchor_c - repaired_c|| + alpha * depth_c)

Every symbol:

Ltotal loss (error penalty) across all repair iterations
ca candidate solution (one of the five proposers)
quality_chow close candidate c is to the correct answer (measured from intermediate checks)
anchor_csolution c when it serves as the anchor to be repaired
repaired_csolution c after peers have fixed its gaps and errors
||anchor_c - repaired_c||how much change happens during repair (distance moved)
alphaweight controlling how much extra repair is beneficial vs. wasteful
depth_chow many repair cycles were applied to candidate c
A tiny worked example
Candidate 1 (strong): quality_1 = 0.9, anchor error 0.3, repair reduces it to 0.05, depth = 2 cycles. Penalty = 0.9 * (0.3 - 0.05) + 0.5 * 2 = 0.9 * 0.25 + 1.0 = 0.225 + 1.0 = 1.225.
Candidate 2 (weak): quality_2 = 0.4, anchor error 0.7, repair reduces it to 0.2, depth = 3 cycles. Penalty = 0.4 * (0.7 - 0.2) + 0.5 * 3 = 0.4 * 0.5 + 1.5 = 0.2 + 1.5 = 1.7.
High-quality candidate 1 benefits from repair (error drops 0.25), but the cost is modest because quality_1 discounts wasted effort on weak repairs. Low-quality candidate 2 pays more repair cost relative to gain, so fewer cycles are devoted to it.

The formula ensures that strong candidates are refined deeply (because their quality is high), while weak candidates are refined sparingly (because effort spent on them yields low gain), and all repair uses Monitor-detected knowledge rather than explicit retrieval pauses.

What can go wrong

What can go wrong

Monitor triggers too often. If the Monitor is too sensitive to knowledge gaps, it retrieves facts that are not needed, wasting tokens and diluting reasoning. The paper's solution: use a learned threshold tuned on a validation set.
Repair cycles on already-correct answers. If a candidate is already very accurate, additional repair cycles may introduce errors rather than fix them (the peer agents might be wrong). The paper mitigates this by making repair depth adaptive: high-quality candidates stop early.
Retrieval backend is weak or outdated. The Monitor can only inject knowledge that exists in the retrieval index. If the index lacks a specific fact, the Monitor cannot help, because Monitor has no way to generate knowledge it has not seen—it can only recognize when reasoning needs knowledge and fetch it from memory. The paper tests on current datasets (HLE, SuperGPQA, TRQA) and uses HippoRAG as a strong baseline retrieval system to ensure the index is rich.
Done right. The paper shows that when Monitor sensitivity and repair depth are tuned, Eigen-1 achieves the highest reported accuracy (48.3%) on Humanity's Last Exam Bio/Chem Gold, with no loss in coherence and 53.5% fewer tokens than baseline RAG.
What a runnable demo should prove

What a runnable demo should prove

Build a small experiment with three configurations: (1) a baseline agent without any retrieval (gets logic right, facts wrong), (2) an explicit-retrieval agent (pauses to fetch, coherence suffers), and (3) Eigen-1 with Monitor-based retrieval and one hierarchical repair cycle. Use a mini-benchmark of 20 genetics or chemistry problems that require both reasoning (logical steps to solve a Punnett square) and retrieval (the correct definition of a allele, the right formula for hardy-weinberg equilibrium). Measure accuracy, token count, and a coherence score (do the reasoning steps flow naturally or do they show signs of pause-and-resume disruption?). The demo must make clear that Eigen-1 recovers the accuracy of explicit retrieval while keeping the token efficiency of no-retrieval reasoning.

coherence_gain = accuracy_eigen1 - accuracy_baseline; efficiency_gain = tokens_explicit_retrieval - tokens_eigen1; shown_benefit = coherence_gain > 0 AND efficiency_gain > 0.4 * tokens_explicit_retrieval

The demo succeeds when a single run shows that Eigen-1 answers correctly, uses fewer tokens than pausing to retrieve, and reads like continuous reasoning.
