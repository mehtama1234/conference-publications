Text Before Vision: Staged Knowledge Injection for Remote Sensing

Teaching a visual reasoning model Earth-science facts via text first makes it learn to find tiny details in massive images far better than jumping straight to images or trial-and-error.

Paper explainersAll themesAI for Science

Imagine trying to find a hidden water leak in a satellite photo the size of ten football fields. The hard part is knowing WHERE to look first — your model needs mental rules from Earth science to narrow the search. This paper discovers that feeding a model domain knowledge as text questions first, then showing it image examples, then letting it practice with zoom tools, builds a reasoning scaffold that makes visual search 60 percent more accurate than models that skip the text phase, because the model now knows WHAT features matter before it tries to search, so every zoom attempt has purpose rather than being random.

Zero assumption version

The bottleneck: finding needles in pixel oceans

Modern AI models can answer questions about images. But when the image is ultra-high-resolution (100,000 by 100,000 pixels), the bottleneck appears: the model must first locate the tiny task-relevant region in a massive pixel space — like finding one suspicious square kilometer in a satellite view of an entire state. Without any mental framework about what to search for, the model flails.

A naive approach: show the model lots of image-question pairs and let it learn by trial and error (reinforcement learning with a zoom tool). This sounds logical but it fails. The model spends its effort randomly zooming in and out without any understanding of which regions matter. It is like searching for a leak with your eyes closed, learning only from whether you got lucky.

The method in one sentence. Inject Earth-science text knowledge first (via question-answer pairs with no images), then show image examples, then teach the model to zoom strategically.

The algorithm as a flow

What it actually does

Stage 1: Cold-start with text-only QA

Train on Earth-science questions answered with text only, layering domain concepts into the model.

Stage 2: Pre-warm with hard image examples

Fine-tune on the same challenging UHR image-text pairs to lock knowledge into spatial features.

Stage 3: Apply reinforcement learning with zoom tools

Let the model practice zooming in strategically, now guided by the learned reasoning framework.

Stage 4: Measure Pass@k

Count correct answers on the hardest ultra-high-resolution benchmark with one or many attempts.

Result: stronger reasoning boundaries

The model's ability to solve hard questions improves because domain knowledge is now embedded.

What the paper changes

What the paper changes

The paper changes the ORDER and CONTENT of training data. Instead of going straight to images or using generic trial-and-error, it systematically injects Earth-science domain knowledge in two forms: first as text (building mental rules), then as image examples (anchoring those rules to visual patterns). This ordering matters far more than which learning algorithm you use.

The hidden quantity

Domain-prior coverage: how much reasoning knowledge is embedded

measured quantity  =  domain-prior coverage

Domain-prior coverage is the fraction of reasoning rules and mechanistic explanations the model has absorbed from Earth-science knowledge. A model with high coverage knows WHAT to look for and WHY (e.g., vegetation stress shows up as a red-edge shift in spectral bands). A model with low coverage just has pixels and no mental framework.

The paper measures this by ablating what data is used during each training stage. When the model trains on text-only QA, coverage grows without any images present. When it then trains on image-text pairs, those same coverage gains persist and spread into visual features. The paper's key finding: Pass@32 (can the model find the answer with up to 32 attempts) is ALMOST ENTIRELY DRIVEN by domain-prior coverage, not by which training algorithm is used.

Why it works

Why it works: building a search scaffold before trying tools

Text-only QA creates mental rules. When the model reads 'Crop stress appears as a red-edge shift in the spectral response,' it learns CONCEPTS without needing to visually find examples yet. These rules are abstract and cheap to encode.

Pre-warming on image-text pairs GROUNDS those rules. The model now sees real satellite images paired with the same QA pairs, anchoring text rules ('red-edge shift') into spatial patterns (the actual pixel bands where the shift happens). This bridging phase is fast because the model already knows which features matter.

Then reinforcement learning with zoom tools can work efficiently. Instead of blind exploration, the model now has a scaffold: 'This region needs a red-edge shift check; zoom there.' The zoom tool refines the policy, but within a structured search space, not random pixels. This is why Pass@1 (get it right on the first try) and Pass@32 (get it right within 32 tries) both improve — the model navigates the massive pixel space with purpose, because it already knows what features to search for.

Math after the picture

The ranking metric: Pass at k tries

First in words:

Pass@k measures: for each test question, if the model is allowed k attempts (k random samples), what fraction of those attempts includes at least one correct answer? It captures both getting it right on the first try (Pass@1) and the model's reasoning boundary (Pass@32).

Then the compact form:

Pass@k = (1/|D|) * sum over questions of [1 - C(n-correct, k) / C(n, k)] when k > 1, or macro-averaged accuracy when k = 1

Every symbol:

|D|total number of test questions
ntotal number of samples drawn per question
correcthow many of those samples were correct
C(a, b)binomial coefficient: ways to choose b items from a items
A tiny worked example
Suppose a test has 100 questions. For one question, the model draws 32 samples and 8 are correct.
Pass@1 for this question: 0 (none of the first attempts happened to be correct)
Pass@32 for this question: 1 (at least one of the 32 samples was correct)
Across all 100 questions, Pass@1 = 60/100 = 0.60 (60 questions correct on first try)
Across all 100 questions, Pass@32 = 82/100 = 0.82 (82 questions solved within 32 tries)
The 22-point gap shows the reasoning boundary: the model knows enough to find the answer given room to explore, but not reliably on the first shot.

Higher domain-prior coverage lifts both Pass@1 and Pass@32, because the model's reasoning scaffold makes both one-shot answers and multi-attempt search more reliable.

What can go wrong

What can go wrong

Text-only QA must be high quality. Generic text data (Wikipedia articles, not Earth-science facts) does not help visual reasoning, because the model learns rules that do not match the actual patterns in satellite images. The paper uses knowledge-graph-verified Earth-science QA instead, so the concepts the model learns match what it later sees in images.
Pre-warming image-text pairs must be hard examples. If the image-text pairs are easy or unrelated to the final benchmark, pre-warming fails. The paper reuses the SAME hard UHR examples that appear in the final test set during pre-warming. This match between training and test data is essential.
Zoom tool must respect the learned search strategy. If the RL reward signal does not encourage the model to zoom strategically (e.g., it rewards random panning), the scaffold collapses. The zoom tool must amplify structured exploration, not replace it with blind search.
Done right, staged injection works reliably. When text-only QA is domain-specific, pre-warming uses hard examples, and RL tools respect learned knowledge, the method consistently outperforms models trained with any single stage alone or in a different order, because the ordering builds a foundation: abstract rules first (text), then spatial grounding (images), then targeted refinement (RL). Each stage builds on what the previous stage learned.
What a runnable demo should prove

What a runnable demo should prove

Build a tiny ultra-high-resolution remote sensing task: a 512x512 pixel satellite image containing one 16x16 region marked as the target (e.g., flooded field). Train a small model in three stages: (1) text-only QA on 20 domain facts (What is flooding? How does it show in satellite bands?), (2) image-text pre-warming on 10 hard examples of the target region, (3) RL with a zoom tool (shrink view to a 128x128 patch, repeat). Measure how many zoom steps it takes to locate the target region.

zoom_steps_needed = count of zoom actions before the model correctly identifies the target region

The demo must show that staged training reduces zoom steps to 2–3, while RL alone (skipping text and pre-warming) needs 15+. This proves that domain priors and spatial anchoring work faster than blind search, because the model's learned concepts guide each zoom decision toward the target, whereas blind search has no signal guiding which regions to explore first.
