Strategy-Aware Optimization Modeling with Reasoning LLMs

SAGE teaches an agent to choose a good optimization modeling strategy explicitly, so that the final program is not only valid but also solver-friendly.

Paper explainersAll themesAgents & Tool Use

Writing an optimization program is not just a matter of correct syntax. The same problem can be formulated in several valid ways, and some formulations are much easier for a solver to handle than others. A language model may therefore produce code that compiles but still performs poorly because it chose the wrong modeling strategy. SAGE makes strategy selection explicit. It builds a solver-verified dataset with multiple correct formulations, then trains a student model with supervised learning and reward-based tuning that scores format compliance, correctness, and solver efficiency. The result is a system that does not merely write legal optimization code. It learns to choose formulations that solve well because strategy is treated as part of the task.

Why valid optimization code can still be bad

An optimization problem can often be expressed through several different variable choices, constraint sets, and decompositions. Two formulations may both represent the same task, yet one is easier for a solver because it uses fewer constraints or a cleaner structure.

A model that focuses only on syntax and local correctness misses this distinction. It can produce code that looks right and even compiles, but the solver may struggle or fail because the formulation strategy is weak. The paper asks how to make formulation strategy part of the learning target instead of leaving it implicit.

The paper's move in one sentence. Make modeling strategy explicit in both data and training rewards, so that the model learns not only to write correct optimization programs but also to choose solver-friendly formulations.

The algorithm as a flow

What it actually does

Step 1: Build a multi-strategy dataset

Collect several solver-verified formulations for the same task so that strategy variation becomes visible in the training data.

Step 2: Fine-tune for basic formatting and correctness

Train first with supervised targets because the model must learn to produce valid optimization programs reliably.

Step 3: Score outputs with solver-aware rewards

Evaluate compliance, correctness, and solving efficiency so that strategy quality affects training directly.

Step 4: Improve the student model with reward-based updates

Use the composite reward because it pushes the model toward formulations that solve well instead of only looking correct.

Step 5: Sample multiple candidate formulations when needed

Generate several attempts so that the system can discover more than one correct strategy for the same task.

Why it works

Why it works

The multi-strategy dataset matters because one target formulation hides the fact that several correct strategies may exist. Showing multiple valid choices teaches the model that strategy is a variable it can control.

Solver verification matters because it grounds training in actual optimization behavior. A strategy should count as good only when the solver confirms correctness and handles the formulation efficiently.

The composite reward matters because format, correctness, and efficiency all contribute to useful optimization code. Reward-based tuning helps the model balance these goals by pushing on all three at once instead of treating them as unrelated checks.

A compact strategy objective

First in words:

Choose formulations that are valid, correct, and solver-efficient at the same time.

Then the compact form:

J = compliance_score + correctness_score + efficiency_score

Every symbol:

compliance_scorereward for producing code in the required format
correctness_scorereward when the formulation matches the optimization problem correctly
efficiency_scorereward when the solver handles the formulation efficiently
formulationthe generated optimization program
A tiny worked example
Suppose two candidate programs both represent the same scheduling problem correctly.
The first uses many extra constraints, so the solver needs more work to finish.
The second uses a cleaner formulation with fewer constraints, so the solver finishes more easily.
Both candidates earn correctness credit, but the second earns more efficiency credit because the solver behavior is better.
Training therefore pushes the model toward the cleaner strategy.

The reward is simple in form but important in meaning, because it turns strategy quality into an explicit optimization target.

What can go wrong

What can go wrong

Solver verification may overfavor one solver style. If the reward reflects only one solver's preferences, the model may learn formulations that are less useful elsewhere because strategy quality is being measured too narrowly.
The strategy dataset may miss important alternatives. If only a few formulation styles are present, the model may not learn the full range of good strategies because the training set hides them.
Efficiency reward can overshadow correctness. A badly balanced reward could favor compact but wrong formulations because the scoring weights are not set carefully.
Done right. The approach works when solver verification is reliable and the reward balances correctness with efficiency, because then strategy learning improves real optimization behavior.
