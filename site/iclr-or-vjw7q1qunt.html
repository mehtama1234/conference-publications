Riesz Neural Operator for Solving Partial Differential Equations

A neural operator that mixes global frequency information with local directional derivatives to solve physics equations accurately by respecting how PDEs actually work locally.

Many real-world physics problems are described by equations (called PDEs) that say how things change in space and time. Recent neural operators can learn to solve these equations, but they often ignore the spatially local information in the data. The Riesz Neural Operator fixes this by combining two views at once: a global view (frequencies, the big-picture behavior) and a local view (directional derivatives, how the solution leans in each direction). Zero assumption version

PDEs need both big-picture and local detail

Physics problems like heat flow, fluid motion, and wave propagation are governed by partial differential equations (PDEs)—mathematical rules that say how a quantity changes with tiny steps in space and time. Solving a PDE means finding a function (a smooth map of how temperature, velocity, or pressure varies over a region) that satisfies those rules everywhere. Humans can solve some PDEs by hand algebra, but real-world PDEs are too complex, so we use computers and neural networks to learn the solution.

Recent neural operators (models trained to map input solutions to output solutions for a whole family of PDEs) have shown promise. But they overlook a key fact: PDEs are fundamentally local. They describe how a tiny neighborhood of a solution influences the next moment or position. Most operators trained on PDE data try to capture this with global frequency transformations (like Fourier analysis, which breaks the solution into repeating wave patterns), or they collapse local information into the network architecture without keeping local detail separate from global patterns. As a result, they miss the local directional variations that matter most in complex PDEs.

The problem in one sentence. Neural operators overlook spatially local directional information in PDEs, collapsing it into global patterns instead of keeping both views alive.

What the paper changes

What the paper changes

The paper changes how the neural operator represents the solution: instead of using only global frequency information, it explicitly adds local directional derivatives (the slopes and rates of change in each spatial direction) as a separate input stream to the network. This is not a small tweak to the training—it is a fundamental change to what the model sees, giving it two parallel sources of information instead of one.

the object it moves  =  The representation: from global-only to global-plus-local-slopes
The hidden quantity

The local directional sensitivity

measured quantity  =  Local Riesz slope (per direction)

In any smooth solution to a PDE, each point has a slope (rate of change) in every direction: up, down, left, right, and so on. These local slopes are the directional derivatives. The Riesz transform is a spectral tool (a way of looking at functions using frequencies) that extracts exactly these directional slopes without losing the global pattern. At each point in space, the Riesz transform outputs a vector of slopes: one component for each spatial direction.

The paper measures this hidden quantity by computing the Riesz transform on the input solution and passing those slope vectors as features to the neural operator. Unlike a standard gradient (which is a single vector of slopes), the Riesz representation in the frequency domain mixes global harmonic structure with local directional information, so the model sees both the long-range pattern and the local tilt all at once. This matters because: the global pattern keeps the solution coherent across space (Fourier modes enforce smoothness), while the local slopes tell the network where fast changes matter. Together, they guide the network to predict the right balance of broad diffusion and sharp transitions.

Why it works

Why mixing global and local views solves the accuracy problem

PDEs are fundamentally differential equations, meaning they link changes in space to changes in time. A solution to a PDE must obey local constraints: at every point, the local slopes (derivatives) in space must balance the time derivative in a specific way set by the PDE's rule. Global Fourier features are efficient (repeating wave patterns describe smooth functions compactly), but they hide directional variation—two solutions with very different local slopes can have similar Fourier representations. Conversely, computing raw spatial derivatives and forgetting global structure leads to noisy, high-frequency noise without the big-picture coherence, because derivatives amplify tiny wiggles and the network trains on random-looking local numbers that do not encode the solution's overall shape.

The Riesz transform solves this by living in the frequency domain (like Fourier) but extracting directional derivatives (the local information). When the neural operator sees both global Fourier modes and local Riesz slopes at once, it can recognize patterns that depend on fine directional changes. For example, a heat equation solution spreads from hot spots—the global pattern is diffusion (smoothing), but the local slopes tell where the heat is steep, guiding the network to predict accurately how the spreading will unfold. The model learns to use the global view to anchor the solution's shape and the local slopes to tune predictions in regions where the PDE's rules matter most.

The Riesz representation and the neural operator

First in words:

loss = Mean-Squared-Error( predicted_solution, true_solution ) + regularization_term(Riesz_features)

Then the compact form:

L = (1/N) * sum_i (y_pred_i - y_true_i)^2 + lambda * ||R(y)||^2

Every symbol:

y_predThe predicted solution output by the neural operator
y_trueThe actual solution we are trying to match
R(y)The Riesz transform applied to the solution: extracts local directional slopes
lambdaA small weight that prevents the local slopes from becoming too wild
NThe number of grid points or samples
A tiny worked example
Suppose we solve a heat equation on a 3-point grid. At time t=0, the temperature is [50, 70, 50] (hot in the middle).
Fourier frequencies tell us the overall shape is symmetric and smooth (a bell curve).
Riesz slopes tell us: at the middle point, the slope to the left is +20 (rising), slope to the right is -20 (falling).
The neural operator receives both: global pattern (symmetric bell) and local slopes (peak at +20/-20).
It predicts the next state: [55, 65, 55] (heat spreads but is steeper on the sides where slopes were high).
Loss = average of (predicted - true)^2 across 3 points = good if the guess matches the true next state.
Without Riesz slopes, the model would see only that the pattern is bell-shaped, missing the directional steepness cue.

The Riesz transform is a spectral way of extracting directional derivatives—it keeps the global structure while exposing local leans, allowing the neural operator to learn how local slopes guide the PDE's evolution.

What can go wrong

What can go wrong

Riesz features are more expensive to compute. Computing the Riesz transform requires spectral decomposition, adding computational cost compared to plain Fourier features. For very high-resolution grids, this overhead can slow the training process and the time it takes to run the trained model on new data.
Overfitting on smooth PDEs. On PDEs where the solution is very smooth (low local directional variation), the Riesz slopes carry little signal and may capture noise instead. A penalty term prevents this partially but requires careful tuning of the weight lambda.
Poor transfer to different grid sizes or shapes. The Riesz transform depends on the spatial grid structure. If the test PDE is solved on a different grid (finer, coarser, or a different shape), the learned Riesz features may not transfer well.
Done right: combining views. When the PDE naturally exhibits strong local directional structure (like fluid flows around obstacles or thermal fronts spreading from a boundary), Riesz slopes guide the model accurately and generalize well. Tune lambda to balance global and local signals.
What a runnable demo should prove

What a runnable demo should prove

Build a simple 1D heat diffusion simulator. Train a Riesz Neural Operator and a Fourier Neural Operator (without Riesz) on the same data. At each training step, compute the prediction error on a held-out test PDE (e.g., heat spreading from a narrow hot stripe). Plot the error over time and over PDE resolution (does it generalize to finer grids?). The demo should show that Riesz captures finer boundary behavior (where slopes are high) and maintains lower error as resolution increases, especially in regions where the solution changes direction.

generalization_gain = (error_FNO - error_RNO) / error_FNO

The demo makes it impossible to miss that adding local directional slopes lets the model predict where solutions bend and evolve, not just their average trend—because the slopes tell the network which parts of the solution will change most in the next step, and the model learns to focus there.
