Convergence Dynamics of Score Matching for a Single Gaussian

Gradient descent learns Gaussians via score matching when initialized near zero, but diverges otherwise, even when the loss shrinks to nearly zero.

Paper explainersAll themesOptimization

Diffusion models train by learning the score (which way is hotter, in data space). Score matching is the standard training objective. But no one knew: does repeated nudging by gradients (the downhill direction) actually converge? Does it learn the right answer? This paper proves a shocking fact: one parameter does converge, but the others flee to infinity—yet the loss looks like it worked. Initialization is destiny.

Zero assumption version

Score matching training is mysterious

Diffusion models learn by estimating the score—the gradient direction that points toward the data density. A typical student model has many parameters. You feed it data sampled from a real Gaussian, and you train it to match the score at different noise levels.

A beginner might think: if the model has enough capacity and you train on enough data, gradient descent will find the right Gaussian. But the paper shows that is wrong. With many parameters and certain initializations, one parameter learns the truth while the others blow up to infinity—and the loss still says success. The training loss shrinks to zero, but the model is broken.

In one sentence. The paper proves that gradient descent on score matching can make one parameter learn the right Gaussian while the others diverge, yet the loss converges to zero anyway.

The algorithm as a flow

What it actually does

The student model has many parameters

Think of a Gaussian mixture: each parameter is one center point, waiting to find its cluster.

Gradient descent nudges each parameter separately

The loss tells each parameter how wrong it is. At low noise, it pushes hard; at high noise, it nudges gently.

One parameter finds the truth and sticks there

Once any parameter hits the right Gaussian center, the loss becomes smooth, and that parameter stops moving.

The other parameters never receive a strong signal

They wander freely because at low noise, any center far from the truth is equally confused—no gradient points back.

The total loss converges even though parameters diverge

The loss only cares about whether any center hits the truth, not which parameter does or where the others are.

What the paper changes

What the paper changes

The paper focuses on the initialization—how far from zero you start each parameter. This single choice determines whether gradient descent will learn the Gaussian or fail. No other part of the algorithm changes. With exponentially-small (near-zero) initialization in low-noise regimes, all parameters converge to the truth. With random initialization far from zero, one parameter converges and the others diverge to infinity.

The hidden quantity

The hidden quantity: which parameters actually learn

measured quantity  =  Parameter convergence status

The paper measures whether each parameter stays near the truth (converges) or runs away to infinity (diverges). This is hidden because the loss function does not see it—the loss only cares about whether some parameter found the right answer. One parameter can be correct while eleven others are infinite, and the loss still reports success.

The paper estimates this by analyzing the gradient flow around the true Gaussian and tracking which initialization regime (high noise, low noise with tiny start, low noise with random start) leads to convergence or divergence of each parameter in the mixture.

Why it works

Why gradient descent converges some parameters but not others

The score matching loss is smooth at the true Gaussian center: if you place a parameter near the center, you immediately get strong gradients that pull you toward it. But if you start far away, the gradient is nearly flat—there is no signal telling you which direction to go.

When the noise is high, this flat region disappears. Every part of the space gets a clear gradient that points back to the truth. All parameters receive a signal; all converge together.

When the noise is low and you start randomly far from the truth, only the first parameter to wander near the center receives a strong gradient. As soon as it arrives, the loss becomes much smaller, and the gradients for the other parameters weaken. They never felt a pull toward the center because they never got close. They continue wandering away, following tiny gradients that push them outward. The loss shrinks because the one good parameter does its job perfectly, and the loss function does not penalize the others for being far away.

With exponentially-small initialization, every parameter is already close to the center. They all feel the strong gradient pulling inward, so they all converge together.

Math after the picture

The gradient descent update rule

First in words:

Each parameter is updated by subtracting a small step size times the gradient of the loss with respect to that parameter. The step size must be tiny—roughly one over (n to the 4th power times dimension squared)—to avoid divergence.

Then the compact form:

µ_i(τ+1) = µ_i(τ) - η ∇_µi L_t( s(τ) ) where step size η ≤ O(1 / (n^4 * d^2))

Every symbol:

µ_i(τ)the i-th parameter (center) at iteration τ
ηstep size: how far to move each iteration
∇_µi L_tthe downhill direction for parameter i at noise level t
ntotal number of parameters
ddimension of the Gaussian (how many numbers describe a data point)
A tiny worked example
Start: µ_1 = 0.01, µ_2 = 0.02, true Gaussian center = 0.
At low noise, gradient for µ_1 is -0.5 (pull toward zero), gradient for µ_2 is -0.001 (nearly flat, almost ignored).
After one step with η = 0.01: µ_1 moves to 0.01 - 0.01 * (-0.5) = 0.015, getting closer.
After one step: µ_2 moves to 0.02 - 0.01 * (-0.001) = 0.0199, barely moves—gradient was too weak.
Over many iterations, µ_1 converges to 0 (the truth), while µ_2 wanders farther away because it never got a strong pull.

The step size must shrink with the fourth power of the number of parameters to prevent explosion; tiny initialization puts all parameters in the convergence region so all feel strong gradients; random far initialization leaves most parameters in the flat region where they diverge.

What can go wrong

What can go wrong

Low noise plus random far initialization breaks learning. One parameter finds the truth, but the others flee to infinity. The loss looks perfect, fooling you. Use tiny initialization or high-noise training instead.
Step size matters enormously. The step size must shrink with the number of parameters and dimension. With many parameters or high-dimensional data, the step size must become tiny, slowing training massively.
A single catastrophic initialization regime. Without exponentially-small initialization, the low-noise regime is a trap. The loss falls but the model fails silently. You cannot detect it from loss alone.
Done right: high noise training or careful initialization. Train with multiple noise levels (as real diffusion models do), or initialize all parameters exponentially close to zero, so all parameters converge together and you learn the true Gaussian.
What a runnable demo should prove

What a runnable demo should prove

Generate data from a simple Gaussian (e.g., mean of 2, variance of 1, in two dimensions). Train three student models side by side: (1) low noise with random initialization, (2) low noise with tiny initialization, (3) high noise with random initialization. For each model, track the loss, and also track whether each parameter converges to the mean of 2 or diverges to infinity. The demo should make it impossible to miss: model (1) has a perfect-looking loss but broken parameters; model (2) has both good loss and good parameters; model (3) has both good loss and good parameters.

Parameter recovery = (number of parameters converging to truth) / (total parameters); Loss convergence = final loss value after many iterations; Honest recovery only when parameter recovery = 100%.

The loss lies. Train three models and see which one actually learned: loss is not enough; you must track whether the parameters themselves converged to the truth.
