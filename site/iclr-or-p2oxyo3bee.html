Tina: Tiny Reasoning Models via LoRA

You can teach a tiny language model to reason step-by-step cheaply by freezing most weights and tweaking only a small side adapter with reinforcement learning.

Paper explainersAll themesLLMs & Foundation Models

Teaching language models to reason—to work through problems step by step instead of guessing—usually costs thousands of dollars in computing power. Tina shows you can do it on a 1.5 billion parameter model (tiny by today's standards) for just $9 by using a trick called LoRA: freeze the base model's weights and train only a small low-rank adapter instead. The paper's real finding is that this works because reinforcement learning for reasoning doesn't need the model to learn new facts, just to learn the format of good step-by-step thinking.

Zero assumption version

Why reasoning is expensive

Teaching a language model to reason—to show its work instead of just blurting an answer—is hard because you need to train on step-by-step thinking traces. These traces come from much larger, smarter models. The training usually runs on expensive graphics cards for days or weeks, costing thousands of dollars in electricity and hardware rental.

A naive person might try this: take a tiny model and just run full-parameter training on it, updating every single weight in the model as you teach it the reasoning format. That works, but it is wasteful—you are tuning weights that already know how to read English and do basic math. What you really need is just the bones of how to write a step-by-step proof.

The problem in one sentence: Updating every weight in a tiny model to teach it to reason wastes compute on knowledge it already has, making the whole process much more expensive than it needs to be.

The algorithm as a flow

What it actually does

Start with a pretrained tiny model

Load a 1.5B parameter model that already knows language and math.

Freeze the base weights

Lock down the model's original weights so they do not change.

Attach a tiny LoRA adapter

Add a small learnable side-module that can twist the model's thinking without rewriting it.

Run reinforcement learning on the adapter only

Show the model reasoning examples. Reward format and accuracy. Let the adapter learn what adjustments produce good step-by-step thinking.

Stop early, use the best checkpoint

The best model shows up after just 20-50% of one training epoch. Stop there, do not keep training.

What the paper changes

The one thing that changes

The paper changes which part of the model you train during reinforcement learning. Normally you would update all the weights in the model. Tina freezes the base model and trains only a small low-rank adapter—a compact side-module that applies small adjustments on top of the frozen base.

the object it moves  =  the trainable weights
The hidden quantity

Format reward: the key signal

measured quantity  =  Format reward

The paper measures format reward: a score that tracks how well the model outputs step-by-step reasoning in the expected structure (like Show your work, Step 1, Step 2, etc.), separate from whether the answer is correct. Think of it as grading the skeleton of reasoning, not the final answer.

During training, the reinforcement learning agent watches format reward grow quickly—the model learns the structure in just the first 200-400 training steps. Then format reward flattens out. Meanwhile, raw accuracy reward comes later and more slowly. This tells the researchers that LoRA is doing something different than full training: it learns the reasoning format first, then accuracy, while base knowledge sits unchanged. The paper shows this by plotting format reward over training steps and seeing the sharp rise, turnaround, and plateau.

Why it works

Why LoRA makes reasoning cheap

The mechanism works in three steps. First, LoRA computes its updates as low-rank matrix products—roughly, two thin matrices multiplied together to make a small weight change. This is much faster to compute than updating full weight matrices. Second, by freezing the base model, you skip the most expensive part of training: letting the model relearn language and math from the reasoning examples. The base already knows those; you only need to wire up the reasoning format on top. Third, reinforcement learning for reasoning rewards a specific format (work shown step-by-step), and that format can be learned by a small adapter. The adapter does not need to change every weight—it just needs to steer the model toward that structure.

The paper shows this by comparing training cost (number of math operations) against reasoning accuracy. Full-parameter models need millions of operations to hit the same accuracy. LoRA models hit it in thousands. Moreover, the best model often appears at only 20-50% through one epoch of training. If you kept training, accuracy would actually drop—a sign the adapter has already learned the format and continuing just makes it forget.

Math after the picture

The LoRA weight update

First in words:

Each adapter update is a low-rank product: change equals two thin matrices multiplied, scaled by how much the reinforcement learning reward improved.

Then the compact form:

delta_adapter = learning_rate * reward_gradient * (A @ B)

Every symbol:

delta_adapterthe weight change in the LoRA adapter
learning_ratehow big a step to take when updating (set beforehand, e.g. 0.01)
reward_gradientwhich direction to nudge to increase reward (from reinforcement learning)
Aa thin matrix of rank r (e.g. 8 rows, 100 columns)
Banother thin matrix (e.g. 100 columns, width of model layer)
@matrix multiplication
A tiny worked example
Suppose the base model's weight W is 100 rows by 100 columns (10,000 numbers). Full training would update all 10,000.
LoRA instead uses A (100 by 8) and B (8 by 100). Total: 800 + 800 = 1,600 numbers.
Each step, reward_gradient tells us which direction to nudge. Learning rate is 0.01. A sample signal strength is 0.5.
For one layer: delta = 0.01 * 0.5 * (A @ B) = 0.005 * (A @ B), a 100-by-100 change.
That one update, applied to the adapter, costs roughly 1,600 multiplies. Full training would cost 10,000 multiplies. LoRA is 6x faster per step.
Over 400 training steps, LoRA trains in hours. Full training would take a day. Times 10 seeds, 20 dataset variations, and it is thousands of dollars vs. nine dollars.

The product A @ B is small because A and B are thin (low rank), so updating the adapter is much cheaper than updating the full weight matrix W.

What can go wrong

What can go wrong

Training too long kills the model. If you train beyond the turning point (after 20-50% of one epoch), the adapter starts overfitting. Accuracy drops. Format reward flattens and inverts. The model forgets how to reason. Solution: monitor format reward and stop early.
LoRA rank too small, adapter cannot learn. If A and B are too thin (rank too low, say rank 2), the adapter has too few knobs to steer the model. Reasoning accuracy plateaus early. Solution: use rank 8 or higher for reasoning tasks.
Wrong reasoning datasets waste the training. RL only works if the dataset has clear right and wrong answers. If examples are ambiguous or wrong, the reward signal is noise. The adapter learns garbage. Solution: use verified reasoning datasets (math, code) with clear ground truth.
Done right: frozen base, low-rank adapter, clean RL reward, early stopping. The method works when all three pieces align: base knowledge locked down and trusted, adapter lean and fast, reward signal clear and verifiable. On math reasoning, this gives 43% accuracy for $9.
What a runnable demo should prove

What a runnable demo should prove

A demo should build a tiny reasoning model (start with a 1.5B or 2B pretrained language model), add a LoRA adapter (rank 8, 2% of base weights), and run a simple reinforcement learning loop on a clean reasoning dataset. Track three metrics over training: (1) format reward (does the output match Show-your-work structure?), (2) accuracy (do the answers match the ground truth?), and (3) training cost (wall-clock time, GPU memory, FLOPs). The demo should prove that format reward spikes early, then accuracy rises more slowly, and the best checkpoint is well before epoch end. The visible proof is the chart: format reward rises in a steep curve and flattens by step 300, while accuracy is still rising at step 1000.

Reasoning accuracy = (correct answers on held-out math problems) / (total problems); training cost = GPU hours * GPU rental price per hour; format reward = (outputs matching expected structure) / (total outputs)

The demo must show the chart of format vs. accuracy reward over training steps. That one chart proves the mechanism: LoRA learns structure first (format reward high, early, plateaued), preserves base knowledge (no retraining needed), and stops paying for extra steps (best model at 30% epoch completion, not 100%).
