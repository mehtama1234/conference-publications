PriorGuide: Test-Time Prior Adaptation for Simulation-Based Inference

PriorGuide lets a diffusion model trained for one prior adapt to a completely different prior at test time, without retraining.

Paper explainersAll themesOther

Simulator-based inference is a way to solve backwards inference problems: given observed data, what model settings (parameters: the numbers that control how a simulator behaves) could have produced it? Normally you train a neural network once on simulated data generated from a fixed prior (a starting assumption about which settings are plausible). If new information emerges and you want a different prior, you have to retrain the entire network. PriorGuide sidesteps this by letting a trained diffusion model adjust its outputs to match a new prior at test time, using a mathematical trick that adds no retraining cost.

Why retraining breaks simulator-based inference

Amortized inference works like this: you train a neural network once on a large batch of simulated setting-data pairs, and after that, inference is instant—feed in new data, get out posterior samples (predicted patterns of what settings could have produced the data) without ever running the simulator again. The catch is that the network learns a mapping tied to one specific starting assumption: the prior (the assumption about which settings are plausible) used to generate the training data.

If new information or expert knowledge arrives—a tighter range on settings, a different belief about which values are plausible—you are stuck. The network was trained assuming one fixed prior as the baseline. Naively feeding a new prior into the same network gives wrong answers because the network never learned to handle the new belief. The only recourse is to retrain the entire model from scratch on freshly simulated data, which defeats the purpose of amortization. For expensive simulators (hours per run), retraining is prohibitive.

A beginner might try a quick fix: just reweight the samples after the fact, boosting outputs that match the new prior. But that approach breaks down when the new prior diverges from the training prior—the network produces garbage samples in regions it never saw during training, and reweighting cannot fix that.

In one sentence. PriorGuide reweights the diffusion model's sampling process at test time using a prior ratio, steering it to match a new prior without retraining.

The algorithm as a flow

What it actually does

Start with trained diffusion

Load the network trained on ptrain; it knows how to generate samples from that prior.

Compute prior ratio

For each candidate setting, calculate the ratio: how much the new prior favors it relative to the old prior.

Reweight each diffusion step

As the model generates a sample, multiply the direction to move by the prior ratio, tilting toward regions the new prior likes.

Refine with Langevin steps

After each diffusion step, optionally add small random-walk refinements to settle into high-probability regions of the new prior.

Output posterior samples

The steered sampling produces setting samples matching the new prior, no retraining, no simulator calls.

What the paper changes

What the paper changes

PriorGuide modifies the diffusion sampling trajectory itself. Instead of sampling from the original prior, it nudges each generation step using the prior ratio, a multiplicative correction that says how much the new prior favors each point relative to the old prior.

the object it moves  =  the sampling trajectory
The hidden quantity

The prior ratio: the hidden steering factor

measured quantity  =  prior ratio: how much new prior favors each setting

The prior ratio is a number attached to each point in the setting space. At any setting value, it measures how much more (or less) likely the new prior thinks that value is, compared to what the training prior thought. If the ratio is 2, the new prior likes that spot twice as much. If the ratio is 0.1, the new prior dislikes it ten times more. The ratio encodes the entire difference between old and new belief in one multiplication factor.

PriorGuide estimates the prior ratio using a mixture-of-Gaussians approximation (a sum of bell curves that fit the ratio function across the training prior). At test time, this approximation is plugged into the reverse diffusion process as a guidance term, steering the direction to nudge the sample proportionally to how much the new prior likes each region.

Why it works

How prior reweighting steers diffusion

Start with a mathematical fact: the posterior under the new prior is related to the posterior under the old prior (which the network already learned) by the prior ratio. The new posterior is proportional to the prior ratio times the old posterior. This is an exact identity; it holds always.

Diffusion models generate samples by starting from pure noise and iteratively taking small steps guided by a learned direction (an arrow saying where the data lives). The network already knows the direction for the old posterior—it was trained on that. To generate from the new posterior instead, you multiply the direction by the prior ratio at each step. Regions where the prior ratio is high (new prior likes them) get a stronger nudge because multiplying by a large number makes the step bigger; regions where the prior ratio is low (new prior dislikes them) get a weaker nudge or even pushed away because multiplying by a small number shrinks the step. Over many steps, this accumulates: the sample trajectory is continuously steered toward the high-probability regions of the new prior.

The method avoids retraining because the network is never updated. Its learned scores are frozen. Only the sampling process is altered, like adding a tuning knob to a radio receiver—same antenna, different dial setting.

Math after the picture

The reweighting equation

First in words:

target posterior proportional to prior ratio times original posterior

Then the compact form:

posterior_new proportional to prior_ratio * posterior_old, where prior_ratio = new_prior / old_prior

Every symbol:

posterior_newthe posterior (predicted setting distribution) under the new prior, conditioned on observed data
posterior_oldthe posterior under the training prior, which the network already learned
prior_ratioa number at each setting: how much the new prior likes it relative to the old prior
new_priorupdated belief about which settings are plausible
old_priorthe original assumption the network was trained on
A tiny worked example
Suppose the training prior gave equal probability to all setting values from 0 to 100.
New information arrives: experts say values above 60 are implausible. New prior is high for 0-60, drops to zero above 60.
At setting 30: new prior gives 0.01, old prior gave 0.01, so prior ratio is 1.0. No steering.
At setting 80: new prior gives 0.0 (ruled out), old prior gave 0.01, so prior ratio is 0.0. Score is multiplied by 0, strongly pushed away.
At setting 50: new prior gives 0.01, old prior gave 0.01, so prior ratio is 1.0. No change.
At setting 90: new prior gives 0.0, old prior gave 0.01, so prior ratio is 0.0. Multiplying by 0 eliminates this direction.
Result: diffusion sampling avoids the ruled-out region and concentrates on 0-60, matching the new prior exactly.

The prior ratio multiplies the direction at each diffusion step, tilting the random walk toward regions the new prior favors and away from regions it forbids.

What can go wrong

What can go wrong

New prior too far from training prior. If the new prior assigns high probability to regions where the training prior was nearly zero, the network has no learned direction for that region. The prior ratio explodes or is undefined, and guidance breaks down. The paper calls this coverage risk and requires the new prior to stay within the regions covered by the training prior.
Prior ratio approximation errors. PriorGuide estimates the prior ratio using a mixture of bell curves with K components. If K is too small or the mixture fits poorly, the reweighting is inaccurate, and samples drift away from the true new posterior. Too few components means loss of detail; too many bloats the computation.
Langevin refinement incurs cost. The method optionally adds small random-walk refinement steps to settle samples into high-probability regions of the new prior. Each refinement step is cheap but cumulative; many steps erode the speed advantage over retraining.
Done right. Verify that the new prior overlaps substantially with the training prior (no big coverage gaps), tune K to match how complex the prior ratio is, and choose a reasonable number of refinement steps (often zero works fine).
What a runnable demo should prove

What a runnable demo should prove

The demo should show that PriorGuide produces posterior samples matching a new prior without retraining. Set up a simple simulator (e.g., a model with 3–5 parameters that produces synthetic data). Train a diffusion-based amortized inference network on one prior. Then, at test time, feed in new data and switch to a different prior (e.g., a narrower range, a shifted mean). Run PriorGuide and show that the posterior samples respect the new prior, with inference accuracy comparable to if you had retrained from scratch.

accuracy = fraction of posterior samples within the new prior support, measured as quantile coverage (e.g., 95% of samples fall between the 2.5th and 97.5th percentile of the new prior)

The key moment: inference happens in seconds using the original network, with zero simulator calls, yet posterior samples accurately reflect the new prior. That is the win.
