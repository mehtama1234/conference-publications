HIVE-3D: Hierarchical Voxel Enhancement for 3D Scene Generation

Take a single photo of a room, sketch its layout once, then refine each piece of furniture step-by-step using a trained adapter that knows how to make coarse voxels look real.

Paper explainersAll themesGenerative Models & Diffusion

Creating a full 3D room from one photo has been slow and blurry. Most methods either try to build everything at once (hard to get fine details) or fall apart when objects overlap. HIVE-3D does something smarter: it builds the room skeleton once, then treats each furniture piece separately, refining it from blocky to crisp without erasing the room structure that holds everything together.

Zero assumption version

Single images don't have enough 3D information

To build a 3D model of a room from a flat photo, you have to guess what's hidden behind the wall, under the table, and inside closets. The camera only saw one angle. A beginner would try to generate the entire 3D scene in one shot, but that is hard because small details like a lamp or a bookcase drown out in the noise—the model gets confused about what is big and important versus tiny and decorative.

Existing methods either do one pass of generation (missing fine details), or they process each object separately without remembering where everything lives relative to each other (rooms fall apart into floating furniture).

The problem in one sentence. Generate a clear 3D room with fine details from one photo without losing the spatial layout.

The algorithm as a flow

What it actually does

Step 1: Build coarse room

Feed the photo into a base model (TRELLIS) to generate initial blocky 3D voxels (think Minecraft blocks) that roughly match the layout.

Step 2: Segment and match

Use image segmentation to identify distinct objects in the photo (sofa, table, lamp). Match each 2D image piece to its 3D voxel region using learned similarity scoring.

Step 3: Build scene tree

Organize the scene as a hierarchy: the root is the whole room, branches are furniture groups, leaves are fine details like a chair leg or a lamp knob.

Step 4: Refine with adapter

For each component, feed its coarse voxels into a trained adapter (small frozen-model plug-in) that adds fine details while preserving the coarse shape.

Step 5: Output fine 3D

Decode the refined voxels into a high-resolution 3D model (Gaussian Splatting) with sharp edges and realistic textures.

What the paper changes

What the paper modifies

HIVE-3D changes how you refine a coarse 3D scene. It adds a small trainable adapter network that sits between the coarse voxels and a frozen diffusion model (a model that has learned to make realistic 3D shapes). The adapter's job is to take blocky low-resolution voxels and turn them into sharp, detailed voxels without breaking the original layout or forgetting the constraints the coarse version set.

the object it moves  =  the adapter network
The hidden quantity

The refinement fidelity score

measured quantity  =  per-component detail preservation

The hidden quantity is how much fine detail the model adds to each component while staying true to the coarse shape it was given. Think of it as a score that asks: Did we make this voxel clearer and sharper? But did we do it only where the coarse shape said it was safe to change? If the adapter strays too far from the coarse input, the score drops (now the sofa looks warped). If it adds no detail at all, the score also drops (still blurry).

The paper measures this implicitly using a diffusion loss: during training, the adapter learns to predict what real fine voxels look like given a coarse version. The model compares its prediction to ground-truth high-resolution voxels and only updates the adapter parameters (keeping the big frozen model untouched). This ensures the adapter learns to refine without drift.

Why it works

Why freezing and adapting works better than retraining

The reason you freeze the big model instead of retraining it is that the big model already knows how to make 3D shapes look real. If you retrained it from scratch on coarse-to-fine data, you would wash away that knowledge and have to re-learn it. Instead, you bolt on a tiny adapter that acts like a translator: it takes the coarse voxels, translates them into the language the big model speaks, and feeds them into the model's internal combining mechanism. The big model's brain stays intact and keeps its real-world intuition.

Why organize by a hierarchy? Because a hierarchical tree lets you refine different components at different levels of detail without coordination. The sofa is a big object (top tree level) so you refine it with broad strokes first. A lamp is small (deep tree level) so you refine it locally without touching the sofa. This avoids the 'floating furniture' problem: each piece remembers where it was in the coarse layout and only adds local refinement.

Math after the picture

The refinement equation

First in words:

diffusion loss on coarse-to-fine voxels

Then the compact form:

L = E[ ||V_fine - adapter(V_coarse, I)||^2 ]

Every symbol:

V_coarsethe blocky initial voxels from the base model
V_finethe ground-truth high-resolution voxels we want to predict
adapter(V_coarse, I)the adapter network output given coarse voxels and image features
Ithe input photo
E[ ]average over all training examples
|| ||^2squared difference, measures how far off the prediction is
A tiny worked example
Suppose the coarse voxel block at position (2,3,1) has value 0.5 (half-solid).
The adapter predicts the fine voxels should be 0.65 at that spot (more solid after refinement).
The ground truth is 0.70 (actual high-res photo shows mostly solid there).
Error: (0.70 - 0.65)^2 = 0.0025. If this were the only voxel, loss = 0.0025.
At another spot, coarse=0.2, adapter predicts 0.25, truth=0.22. Error = (0.22-0.25)^2 = 0.0009.
The adapter learns to make predictions close to the truth, so the loss shrinks across training.

The loss trains only the adapter; the big frozen model parameters never change, so its real-world knowledge stays intact.

What can go wrong

What can go wrong

Adapter drift if trained too long. If the adapter trains without early stopping, it may start changing the coarse structure itself instead of just refining it. The refined voxels drift away from their coarse anchor, and the sofa gets warped.
Hierarchy mismatch if segmentation fails. If the 2D-to-3D alignment step mistakes a lamp shadow for a separate object, the hierarchy tree has the wrong structure, and refinement goes to the wrong component.
Boundary bleeding at component edges. When refining two adjacent components (sofa and armchair) independently, their boundaries can overlap or leave gaps if the adapter does not coordinate across edges.
Done right. Freeze the large model weights, constrain the adapter to diffusion loss only, validate segmentation before hierarchy construction, and blend component boundaries via a small overlap region during assembly.
What a runnable demo should prove

What a runnable demo should prove

Build a mini version: take a simple scene (a room with 3 furniture pieces), generate coarse voxels, manually segment it, train the adapter on a single component (e.g., a chair), then refine the coarse chair voxels. Render both before and after side by side. The metric is: does the refined chair look sharper (more edges and texture) without warping relative to the coarse version? Then add the other components and check that the full room still has spatial coherence—nothing is floating.

detail gain = (sharpness_after - sharpness_before) / geometric_drift

The key proof: a single adapter conditioned on coarse voxels can add realistic fine detail to one component without corrupting the overall room layout or other objects.
