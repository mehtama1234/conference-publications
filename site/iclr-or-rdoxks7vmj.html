Disentangling Event Causal Puzzles in Temporal Knowledge Graphs

Event prediction in temporal knowledge graphs requires separating causal relationships from correlation illusions by untangling non-causal noise, spurious patterns, and time-dependent changes.

Paper explainersAll themesGraph & Geometric Learning

A temporal knowledge graph (a database of who did what to whom and when) contains events built from real causal forces but also correlation noise. Existing methods predict future events by learning which entities are correlated, but miss the hidden causal structures: some correlations are real causes, some are spurious accidents, and some are time-sensitive while others are permanent. This paper disentangles all three, giving the model a clearer view of what actually drives events.

Zero assumption version

Knowing who correlates is not knowing why

A temporal knowledge graph is a timestamped record: (entity A, relationship type, entity B, timestamp). For example: (Alice, knows, Bob, 2020) then (Bob, hires, Carol, 2021). The job is to predict the next event: who will do what next?

The naive approach learns a pattern: if Alice knows Bob and Bob hires people, then Bob will probably hire someone. This is correlation — A and B often appear together before hiring. But correlation is not causation. Maybe Alice and Bob both live in the same city (a common cause), so they appear together for that reason, not because Alice causes Bob to hire. Or maybe the timing is coincidence. Or maybe the relationship changes over time — early in a business Alice's presence mattered, later it does not.

Existing methods model entity correlations. They work decently but miss the deeper truth: events are made of heterogeneous causal threads (some causes, some illusions, some time-dependent). Without disentangling them, the model learns spurious patterns and makes errors when the real causality shifts.

The method. HEDRA separates real causes from correlation noise by detecting non-causal events, filtering spurious patterns with instrumental variables, and distinguishing time-sensitive causes from permanent ones.

The algorithm as a flow

What it actually does

Counterfactual detection

Find which events are merely correlated by testing: if we remove this event, does the pattern of what happens next change? If not, it is non-causal.

Instrumental variable filtering

Identify spurious causal chains (A and B both caused by C) by constructing a synthetic variable that only affects the outcome through the true cause, then measure which real causes survive.

Evolutionary orthogonality

Break event causes into two orthogonal parts: one that stays the same over time (static) and one that changes (dynamic), because a single channel cannot capture both permanent rules and time-dependent shifts.

Multi-view subgraphs

Build separate relationship subgraphs for each kind of causality so each disentangled cause gets its own signal path.

Event prediction

Predict the next event by scoring candidate entities through all three causal filters, giving higher weight to true causes.

What the paper changes

The one thing the paper changes

Instead of learning entity correlations as a flat vector, HEDRA learns three separate, orthogonal event representations: one for non-causal noise, one for spurious causality, and one for dynamic versus static causality. Each has its own scoring path during prediction.

the object it moves  =  event representations (three disentangled channels)
The hidden quantity

Causal disentanglement: naming what the model learns

measured quantity  =  causal mechanism purity (what fraction of each event representation is a true cause)

The hidden quantity is how 'pure' each learned representation is. A pure static-causal representation should fire only when the true permanent causes are present and remain silent on noise or time-dependent effects. The paper calls this separating heterogeneous causalities, but what it actually measures is: how well does each disentangled channel isolate one kind of causal force without contamination from the others?

The paper estimates purity by testing whether removing an event changes the outcome. If the counterfactual detector says removing event E does not change the pattern of future events, then E's representation is being used for non-causal noise (low purity for real causality). Instrumental variables test purity differently: they measure whether a representation survives when confounders (common causes) are controlled for. Evolutionary orthogonality uses a penalty that gently steers representations away from overlapping in time-dependent versus static components, keeping the purity high.

Why it works

Why disentangling causality fixes event prediction

When the model learns a single flattened representation of events, it is forced to memorize a confusing mix: real causes, spurious patterns, and time-dependent signals all blended together. During prediction, it cannot tell them apart, so it overfits to spurious correlations and fails when causality shifts over time.

HEDRA fixes this by building three separate 'buckets' (orthogonal representation channels). The counterfactual detector directs non-causal events into one bucket by checking: does removing this event change the downstream pattern of what happens next? If not, it is noise. The instrumental variable module creates a synthetic 'confounder-free' signal by constructing a variable that can only affect events through the real cause (not through the common confounder), then compares the real representations to this synthetic path. Causes that survive this comparison go into the spurious-causal bucket. Finally, the evolutionary orthogonality module splits the remaining cause bucket into two orthogonal parts: one frozen (static) and one changing (dynamic). During prediction, each bucket contributes a separate score, so the model learns to weight real permanent causes, ignore spurious patterns, and adapt when causality changes, because each signal comes from a separate, clean channel instead of a confusing mixture. This separation is why disentanglement improves generalization: the model learns signals that stay valid over time instead of taking accidental shortcuts, because permanent causes are disentangled from time-dependent ones, so what the model learned yesterday still applies tomorrow.

Math after the picture

The disentanglement loss (simplified form)

First in words:

total loss = event prediction accuracy + penalty for overlapping representations + penalty for causality violations, where the penalties use indicator functions (1 if the event is non-causal or spurious, 0 otherwise) to steer representations toward the right bucket

Then the compact form:

L = L_pred + lambda_noncausal * sum_i I_noncausal(e_i) * ||r_i||^2 + lambda_spurious * sum_i I_spurious(e_i) * ||r_i - r_confounded||^2 + lambda_orthogonal * ||r_static . r_dynamic||^2

Every symbol:

Ltotal loss to minimize
L_predevent prediction loss (how well we predict the next event)
r_ithe learned representation for event i
I_noncausal(e_i)a test: 1 if removing event e_i does not change the outcome distribution, 0 otherwise
I_spurious(e_i)a test: 1 if event e_i has a confounder, 0 otherwise
r_confoundedthe representation learned with a confounder injected
r_staticthe static (permanent) part of causality
r_dynamicthe dynamic (time-changing) part of causality
lambda_noncausal, lambda_spurious, lambda_orthogonalstrength knobs for each penalty (higher = stricter disentanglement)
.dot product (inner product of two vectors)
A tiny worked example
Event (Alice, knows, Bob, Jan-2020): the model predicts it is causal (I_noncausal=0, I_spurious=0), representation r_alice_knows_bob has norm 5.0. Prediction loss for this event: 0.5. Penalty: 0 (no non-causal or spurious flags). Orthogonal penalty: r_static=(4.0,0,0), r_dynamic=(0,3.0,0), dot product=0, penalty=0. Total: 0.5.
Event (Charlie, meets, Diana, Feb-2020): counterfactual detector finds removing it does not change outcomes (I_noncausal=1), so it is noise. Representation r_charlie_meets_diana has norm 2.0. Prediction loss: 0.3. Non-causal penalty: lambda_noncausal=10 * 1 * 2.0^2 = 40.0 (high penalty steers the model to shrink this representation). Spurious and orthogonal penalties: 0. Total: 0.3 + 40.0 = 40.3.
Event (Eve, funds, Frank, Mar-2020): has a confounder (both in same industry, I_spurious=1). With confounder: r_confounded=1.5; measured: r_eve_funds=1.8. Spurious penalty: lambda_spurious=8 * 1 * (1.8-1.5)^2 = 8 * 0.09 = 0.72 (penalizes the difference, steers toward confounder-free signal). Total: 0.4 + 0.72 = 1.12.
The model learns: shrink non-causal representations (penalty 40x the prediction loss), reduce spurious causes (penalty 8x), and keep static and dynamic causes orthogonal (zero dot product). Over many events, this shapes the three buckets.

Each penalty flag (non-causal, spurious, dynamic/static) routes the representation toward the right bucket by making high loss for representations that end up in the wrong bucket, so the model learns three separate, clean causal channels instead of one confused mixture.

What can go wrong

What can go wrong

Confounder detection fails. The instrumental variable module must correctly identify which events have a shared cause. If the model misses a confounder (e.g. does not realize two entities are in the same industry), the spurious bucket stays contaminated.
Time periods too short. The evolutionary orthogonal module separates static from dynamic causality over time. If the data spans only weeks, true causes may look static even though they evolve over years, or vice versa.
Rare events are under-represented. The counterfactual detector works by checking whether removing an event changes the distribution. For rare events, the distribution change is tiny, so rare causes may be misclassified as non-causal.
Done right. The model separates causes cleanly only when all three disentanglers (counterfactual detector, instrumental variable filter, orthogonal decomposition) have clear signals. On typical temporal knowledge graphs with hundreds of thousands of events over years, all three signals are usually present.
What a runnable demo should prove

What a runnable demo should prove

Build a synthetic temporal knowledge graph with three types of hidden event causality: (1) a permanent causal relationship (Alice always influences Bob), (2) a spurious pattern (Alice and Charlie both influenced by a shared industry trend, so they correlate but do not cause each other), and (3) a time-dependent cause (early in the data, entity D causes entity E, but later the relationship breaks). Train the naive baseline (correlation-only) and HEDRA on the first 70% of timesteps. Test both on the final 30% of timesteps, where causality has shifted. Measure prediction accuracy separately for events that follow permanent causes, spurious correlations, and broken time-dependent causes.

accuracy_permanent = (events_with_permanent_cause_correctly_predicted) / (total_permanent_cause_events), accuracy_spurious = (spurious_events_correctly_rejected) / (total_spurious_events), accuracy_dynamic = (time_dependent_causes_correctly_predicted_after_break) / (total_dynamic_events_after_break)

HEDRA should show high accuracy on permanent and dynamic causes even after causality shifts, while the naive baseline should drop sharply when spurious patterns and time-dependent relationships break.
