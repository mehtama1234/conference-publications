Tabero: Learning Gentle Manipulation with Closed-Loop Force Feedback

A robot learns to succeed at tasks while squeezing with minimal force by splitting its commands into what moves the hand and how hard it grips.

Paper explainersAll themesRobotics & Control

Robots need to handle things gently. Most robot learning systems only know how to succeed at a task; they don't learn to do it softly. Tabero teaches a robot to watch what it sees and feels at its fingertips, listen to spoken instructions, and then choose both where to move its hand and how hard to grip, using the two independently so it squeezes only as much as the job requires.

Why robots are clumsy

Robots today are trained to complete tasks: pick up a cup, open a door, place an object. But they learn one thing: succeed. No one trains them on how gently to do it. A robot's fingers might clamp down with crushing force when a soft touch would work, or grip so weakly an object drops.

Most robot learning systems use cameras and motion commands. Newer ones add language: the person says 'place the egg gently.' But here is the gap: the robot has no way to separate two independent decisions—where to move the hand and how hard to squeeze. They are tangled into one output. So when the robot learns 'place the egg,' it also learns 'squeeze this hard,' and changing one breaks the other.

The problem in one sentence. A robot cannot learn to complete tasks while also learning to squeeze gently, because position and grip force are not separate commands it can tune independently.

The algorithm as a flow

What it actually does

Capture touch data.

Replay existing robot manipulation videos through a tactile simulator to generate synchronized streams: cameras see the scene, tactile markers show finger contact, force sensors measure grip.

Encode touch into readable chunks.

The tactile marker motion (how the soft sensor deforms) gets encoded into a compact sequence using a lightweight temporal network. This turns the raw sensor data into tokens (discrete data chunks the model can read and process like words in a sentence).

Predict position and force separately.

The multimodal transformer reads vision, language, and touch tokens and outputs two independent streams: desired hand poses and desired grip forces.

Execute with admittance control.

A fixed low-level controller runs on the robot continuously, taking the position and force commands and balancing them in real time so the hand moves toward its goal while the gripper applies only the requested force.

Measure gentleness.

Evaluate success in two ways: does the task complete, and how high did the grip force peak? This two-axis metric forces the model to learn both.

What the paper changes

The one thing that changes

The paper decouples what a robot outputs. Instead of one monolithic command for each hand action, the model now outputs two independent commands at once: a position command (where the hand should be) and a force command (how hard the gripper should squeeze).

the object it moves  =  command separation
The hidden quantity

The hidden quantity: grip force awareness

measured quantity  =  grip force modulation

The paper measures and optimizes for grip force—the actual squeezing pressure at the fingertips, in newtons. This is a quantity the old system ignored entirely; it emerged as a side effect of learning the task. Tabero makes it explicit, which matters because now the loss function directly penalizes high grip values during training, and the evaluation metric scores the robot on how low it can keep the grip, creating an independent learning signal for gentleness instead of letting it be a random byproduct.

The robot learns to estimate grip force from two sources: direct 6D force readings from contact (the x, y, z push and twist directions) and the deformation of the tactile markers (how the soft rubber tip squashes and moves). The model fuses these together to predict the gentle-enough grip for the current situation.

Why it works

Why decoupling works: separate outputs, separate training signals

Old robot systems squashed position and force into one command. When the model learned 'push the door open,' it also learned a grip force as a side effect—whatever worked to complete the task. If the task succeeded with light pressure, fine; if it needed a hammer grip, the model learned that too. No separate signal was telling it to be gentle.

Tabero separates the two. Now the model outputs position and force as independent numbers. A separate loss function supervises force: it penalizes high grip values during training. The evaluation metric measures both task success and grip force, so the robot gets credit only if it succeeds gently. This creates a direct incentive to find the minimum force that still works.

Tactile feedback closes the loop. The robot's fingers feel what they are touching. A sensor at the fingertip reports contact forces back to the model. Now the model can reason: 'I am trying to insert this peg; my fingers report high contact force; I should reduce my grip or adjust my angle.' The force prediction becomes conditional on touch, not just a fixed learned behavior. The admittance controller (a low-level algorithm) continuously balances the position goal and force goal, allowing the high-level model to focus on prediction while the controller handles the real-time mechanics.

Math after the picture

The force prediction and supervision

First in words:

predicted-force = model(vision tokens, language tokens, tactile tokens); loss = task-success-loss plus weighted-force-loss; target-force = model-prediction times feedforward-gain; control-command = inverse-kinematics(desired-pose) combined-with target-force

Then the compact form:

F_target = (1 + k_ff) * F_pred; loss_total = loss_task + w_force * loss_force(F_pred, F_actual)

Every symbol:

F_targetthe grip force the controller should apply, in newtons
F_predthe grip force the model predicted from vision and touch
k_fffeedforward gain (how much extra margin the controller adds; > 0)
loss_taskerror in task completion (e.g. did the peg insert)
loss_forceerror in grip force prediction versus actual measured force
w_forcehow much to weight force accuracy in training (higher = prioritize gentleness)
A tiny worked example
Model predicts F_pred = 30 newtons. Feedforward gain k_ff = 0.1. Target force = (1 + 0.1) * 30 = 33 newtons.
Robot executes grip at 33 N. Actual force sensor reads 32 N. Error = 32 - 30 = 2 N. Loss contribution from force = 2^2 = 4.
Task succeeded, so loss_task = 0. Total loss = 0 + w_force * 4. If w_force = 2, total loss = 8.
Next epoch, model learns to predict force slightly higher (closer to 32). Over time, predictions match reality and stay low.

The decoupling means force loss is independent of task loss. In the old system, if the robot learned to grip hard to complete the task better, reducing grip force would make the task harder—the two goals pulled against each other because tighter grip helps task success in many cases, so a loss function pushing down on grip makes the task loss go up. Here they do not pull against each other, so training can chase both at once.

What can go wrong

What can go wrong

Decoupling creates a tradeoff. The robot must now balance task completion against force minimization. If the weight on force loss is too high, the robot squeezes so gently it fails to grasp. If too low, it ignores gentleness. The model needs careful tuning of the loss weight.
Tactile data is sparse. Real tactile sensors are expensive and fragile. Tabero addresses this by replaying existing videos through a simulation, but any gap between simulated and real touch will cause the force prediction to be overconfident or poorly calibrated.
Feedback delay breaks gentleness. If the tactile signal arrives too slowly (high latency), the robot cannot adjust its grip before a delicate object breaks. Real-time execution at 20 Hz is required; slower systems will crush first and adjust later.
Done right: gentle and successful. When loss weights are tuned, tactile simulation is high-fidelity, and real-time control runs without lag, the robot learns to complete tasks while keeping grip force at the minimum safe level.
What a runnable demo should prove

What a runnable demo should prove

A demo should show a robot learning on two tasks: inserting a peg into a hole and grasping an egg-like object. Train two versions side by side: one with decoupled force and position, one with the old mixed approach. Measure task success (did the peg insert; did the egg stay whole) and peak grip force over 100 episodes.

gentleness_score = task_success_rate * (1 - normalized_grip_force); normalized_grip_force = measured_grip / max_safe_grip

The decoupled model should reach 90% success while keeping grip force below 40 N; the mixed baseline reaches 95% success but uses 120 N. This shows the real tradeoff and why gentleness is a learned choice, not an accident.
