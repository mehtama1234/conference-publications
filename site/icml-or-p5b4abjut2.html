EVOLVING ROLLOUTS: Harnessing Historical Experience for Web Agent Evolution in Reinforcement Learning

Keep past web-agent trajectories as reusable strategic experience so later training can learn from old successes and failures instead of treating each rollout group as disposable.

Paper explainersAll themesAgents & Tool Use

Training a web agent with reinforcement learning is expensive because each trial interacts with a real environment and often carries a long context. Standard group-based training also throws away many trials when all members of a group receive the same reward, because there is no within-group contrast to learn from. This paper keeps those old trajectories and distills them into strategic guidance that the agent can reread later, so that even flat-reward groups still contribute useful lessons.

Zero assumption version

Why web-agent training wastes too many trials

A web agent learns by trying full task trajectories such as searching, clicking, filtering, and submitting answers. Each full trial can be long and expensive. That already makes learning slow.

Group-based reinforcement learning adds another waste source. It often learns by comparing several trajectories in the same group. If every trajectory in that group gets the same reward, then the group provides little contrast. Many systems largely discard that group for learning purposes, even though the trajectories may still contain useful behavior patterns.

The main fix. Store old trajectories as reusable experience, because even flat-reward groups still show what the agent tried and which strategic patterns tended to end well or badly.

The algorithm as a flow

What the method actually does

Collect rollout groups

Run the web agent on tasks and record full trajectories with rewards so that training sees complete behavior sequences.

Extract strategic experience

Summarize useful parts of each trajectory into reusable guidance because later tasks can benefit from earlier patterns.

Store the experience repository

Keep those summaries across training rounds so that old trials are not thrown away after one update.

Use repository guidance during later training

Feed past experience back into future rollouts so that the policy can borrow lessons from earlier successes and failures.

Update policy and repository together

As the policy improves, it produces stronger trajectories, which then improve the repository because the stored examples contain better strategic guidance for the next round.

What the paper changes

What the paper changes

The paper changes reinforcement learning from a purely episodic loop into a joint system with two learning channels: parameter updates and a persistent experience repository.

the object it moves  =  policy learning plus reusable experience memory
The hidden quantity

The hidden quantity

measured quantity  =  future usefulness of a past trajectory

The key hidden quantity is how useful an old trajectory will be for later tasks. A trajectory can be useful even when it came from a flat-reward group, because it may still contain a good search pattern, a good page-reading order, or a warning about a bad branch.

The method estimates usefulness by storing reward-labeled trajectories as strategic experience and then observing whether rereading them improves later rollouts. Experience that repeatedly helps later tasks becomes more valuable because it shapes future behavior beyond one training episode.

Why it works

Why keeping old rollouts helps

A flat-reward group may fail to provide a strong direct policy update, but it still records how the agent navigated the task. That history can later become useful when a similar task appears. By extracting and storing strategic experience, the method recovers learning signal that standard group-based training would mostly waste.

The feedback loop matters too. Better policies generate better trajectories, which improve the repository because the saved examples become more informative. A better repository then guides future rollouts toward stronger behavior because the agent rereads stronger strategic patterns. This co-evolution helps sample efficiency because each environment interaction can influence both immediate policy updates and longer-lived strategic memory.

Math after the picture

A simple view of the combined objective

First in words:

Think of the total learning value as the direct policy gain from the current rollout plus an extra gain from the stored experience that helps future rollouts.

Then the compact form:

total_gain = policy_gain(current_rollout) + beta * experience_gain(repository)

Every symbol:

total_gainthe overall learning value gathered from one training round
policy_gain(current_rollout)what the current rollout contributes through direct reinforcement learning
experience_gain(repository)the added value from the stored experience memory
repositorythe collection of past strategic experiences
betahow strongly the system weights the memory contribution
A tiny worked example
Suppose the current rollout gives direct policy gain 0.4.
The stored experience reused in this round adds estimated future gain 0.3.
If beta is 0.5, the total gain is 0.4 + 0.15 = 0.55.
Without memory reuse, the same round would contribute only 0.4.
The extra 0.15 captures why saved history can matter even when the current group alone is not very informative.

The paper's actual training details are more involved, but the main point is this dual channel: one part learns from the current rollout, and another part learns from accumulated experience.

What can go wrong

What can go wrong

The repository can preserve bad habits. If poor strategies are stored and reused too often, then later rollouts may copy them because the memory channel keeps surfacing weak guidance.
Task drift can reduce reuse value. A trajectory from one website or task style may not transfer well to another, so old experience can become noisy because the environment has changed.
Long memories can crowd the prompt. If too much stored experience is injected at once, then the agent may spend context budget on stale details because the memory selection step is not selective enough.
Done right. The method works when the repository is curated and the retrieval step surfaces the most relevant past trials, because then memory adds guidance instead of clutter.
What a runnable demo should prove

What a runnable demo should prove

Build a small web-navigation benchmark with repeated task types such as finding product details, comparing options, and extracting one final answer. Train one agent with standard group-based reinforcement learning and another with a persistent experience repository.

Count how many environment interactions each agent needs to reach the same performance level, and also measure how much each agent benefits from groups where all trajectories received the same reward. The demo should show that saved experience raises value per rollout because old trials remain useful.
