Learning Grammar Rules from Noisy Teachers: CAPAL

Learn exact grammar rules from an AI that sometimes lies, by asking the AI the same question twice and watching for suspicious disagreements.

Paper explainersAll themesAgents & Tool Use

Large language models (LLMs) are unreliable: they hallucinate and change their minds. When we ask an LLM to tell us the exact rules of a formal pattern (like which email addresses are valid, or which code snippets follow a certain pattern), its answers flip randomly. This paper presents CAPAL, a method that learns these rules correctly anyway by asking the same question multiple times, tracking when the LLM flips its answer, and using that disagreement to figure out which parts of the LLM are just noisy guessing.

Zero assumption version

Teaching machines to learn exact rules from broken teachers

You want to teach a machine to recognize valid email addresses. You ask a human expert yes-or-no questions: is alice@example.com valid? The human says yes, every time, consistently. But what if your expert is an LLM? It might say yes today and no tomorrow for the same input. The machine cannot learn a consistent rule from an inconsistent teacher.

The naive approach: ask the LLM once for each question, then train on whatever answers it gives. This fails because the machine memorizes the noise, not the rule. It learns that alice@example.com is sometimes valid, which is nonsense — either it is or it is not. The final learned rule is garbage.

The problem. An LLM answers the same question differently on different days, so a machine cannot learn a consistent rule from it.

The algorithm as a flow

What it actually does

Estimate the noise rate

Ask random inputs twice, count how often the LLM flips its answer, compute the noise level.

Design a same-state test

For any two inputs that should belong together, ask both twice and compare disagreement counts statistically.

Separate high-confidence inputs

Find groups where the LLM was likely telling the truth, ignore noisy parts.

Build the grammar skeleton

Apply the classic L-star algorithm (a deterministic formula for learning rules) to the clean groups.

Polish the final rule

Use the learned skeleton to ask targeted follow-up questions, refining the full rule.

What the paper changes

What changes

The paper modifies the L-star learning algorithm — a classical method for learning grammar rules — by inserting a preprocessing step that detects which questions the LLM can answer reliably and which are noisy guesses. Instead of feeding raw noisy answers to L-star, it feeds only the high-confidence answers.

the object it moves  =  Confidence filtering of LLM responses
The hidden quantity

The noise floor: how often does the LLM lie?

measured quantity  =  Persistent noise level

The key hidden quantity is the noise rate — the fraction of inputs where the LLM will give different answers if asked twice. This is not about random flukes; it is the LLM's systematic unreliability on certain types of inputs. The paper calls this the noise floor, written as eta-hat (η̂). It is hidden because you cannot see it directly; you can only measure it by asking questions redundantly.

The paper estimates η̂ using a micro-bootstrap: ask a small random sample of inputs multiple times, count the flips, and divide by the total. Then it uses this estimate as a threshold — inputs above the noise level are trusted, inputs below are flagged as guesses.

Why it works

Why asking twice saves the rule

The problem is that noisy labels corrupt the learning process — the machine learns random flips instead of consistent rules. The insight is that noise is not uniform. The LLM has a noise floor: inputs above the noise floor are answered consistently, and inputs below are pure guessing. If you can identify which inputs are which, you can ignore the guesses.

The mechanism works in three steps. First, estimate the noise floor by asking random inputs twice and counting flips — this gives you a baseline η̂. Second, for each pair of inputs, ask both twice and count how many times they disagree. Use a statistical test (Hoeffding tolerance) to compare this disagreement count against the noise floor — if the two inputs genuinely belong in different categories, they will disagree far more than noise alone. Third, discard all the inputs that fall below the noise-floor threshold, and apply the standard L-star algorithm to the clean, high-confidence inputs. The final rule learned from clean inputs is logically correct, even though the original teacher was broken.

Math after the picture

The equation: statistical confidence in a same-state test

First in words:

The number of times the LLM disagrees on a pair of inputs should be roughly equal to the noise floor times the number of queries. If it is much larger, the two inputs are genuinely different. A Hoeffding tolerance bounds how much random fluctuation is expected.

Then the compact form:

accept_same_state_if: disagreement_count <= 2 * sqrt(num_queries * eta_hat * (1 - eta_hat) / 0.0001) + num_queries * eta_hat

Every symbol:

disagreement_countnumber of times the LLM gave different answers for the two inputs
num_querieshow many times you asked each input (usually 2-5 for practical efficiency)
eta_hatyour current estimate of the noise floor (fraction of flips in a calibration sample)
0.0001the confidence level (you are willing to accept 1 in 10,000 risk of wrong classification)
A tiny worked example
Suppose η̂ = 0.2 (20% of inputs are noisy), num_queries = 4.
Threshold = 2 * sqrt(4 * 0.2 * 0.8 / 0.0001) + 4 * 0.2
= 2 * sqrt(6400) + 0.8 = 2 * 80 + 0.8 = 160.8.
For inputs A and B: if disagreement_count = 162, reject same-state (they differ).
For inputs C and D: if disagreement_count = 0, accept same-state (they match).
For inputs E and F: if disagreement_count = 150, the call is close; the threshold protects against noise.

The threshold inflates with noise and number of queries because random flips compound; the square root term adds safety margin.

What can go wrong

What can go wrong

Noise is not random: systematic bias in the LLM. If the LLM always flips its answer for a specific type of input (e.g., very long strings), CAPAL treats that as noise and filters it out. But the true rule might actually require that distinction. The learned rule will be incomplete.
Noise rate is underestimated. If you calibrate η̂ on a small sample, you might miss rare high-noise inputs. The subsequent same-state test will then accept noisy pairs as trustworthy, corrupting the learned rule.
The LLM is almost always wrong. If noise is above 40-50%, there is not enough clean data to learn any rule at all. CAPAL will converge, but to a rule that fits random noise.
The LLM is mostly honest (noise below 20%). CAPAL works best here. The noise floor is easy to detect, and the majority of inputs are trustworthy.
What a runnable demo should prove

What a runnable demo should prove

Build a synthetic task: define a simple grammar rule (for example, valid phone numbers consist of 10 digits with an area code from 2 to 9). Simulate an LLM by labeling inputs correctly 80% of the time, flipping 20% (the noise floor). Run CAPAL on 100-500 generated inputs. Measure the accuracy of the learned rule on a held-out test set (inputs the LLM never saw).

accuracy = (correct_rules_recovered / total_test_cases)

CAPAL should recover the true grammar rule (90%+ accuracy) despite the LLM's 20% error rate, while naive learning from the same noisy oracle fails (35% accuracy).
