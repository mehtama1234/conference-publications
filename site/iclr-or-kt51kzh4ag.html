X-VLA: soft prompts for cross-embodiment robot learning

Train one robot model on diverse robots by attaching learnable tags (short lists of numbers, one per robot type) so the model learns robot-independent skills and robot-specific adaptations in a single pass.

Paper explainersAll themesRobotics & Control

A robot that can control a robot arm needs to learn from data recorded by many different arm types (some with one arm, some with two arms, different sizes and speeds). Naively, you train one model per robot type or you break by trying to mix them all together. X-VLA adds a small learnable tag (a soft prompt) for each robot type during training, letting one model learn once and adapt quickly to new robots it has never seen before.

The cross-embodiment wall

Robot learning data is messy. You collect trajectories (video clips showing how the robot's arm moves step-by-step) from one industrial arm manufacturer, then from a different one, then from a hobbyist kit. They have different sizes, different speeds, different numbers of fingers. If you train a single model on all of it mixed together, the model sees contradictions: the same action means something different on each robot. Predictions become confused.

The naive fix: train a separate model for each robot type. That works but wastes all the shared structure—the fact that 'move forward' means something similar on all arms. The other fix: use a separate decoder head (output layer) for each robot and share everything else. That helps but ignores that different robots also record data differently: a wrist camera mounted on the gripper sees the target object from a different angle than a main camera mounted on the shoulder, so the patterns the model needs to recognize are geometrically different, and the input encoders themselves need to learn robot-specific visual interpretations, because the same visual feature (a red ball) looks different depending on which camera recorded it, and the model must learn both what red balls mean generally and how to recognize them in each camera's view.

The fix in one sentence. Attach a small learnable tag (a short list of numbers) to each robot type before training, so the model learns to switch its internal behavior based on which robot it is, because the tag tells the model which robot's camera angles and action scales to expect, and during training the error-driven updates from one robot reinforce the parts that handle that robot and do not contradict the parts that handle other robots.

The algorithm as a flow

What it actually does

Step 1: embed each robot

Create a small learnable vector (tag) for each robot type in your dataset.

Step 2: prepend tags to input

When processing video and language for robot A, prepend robot A's tag to the input stream.

Step 3: single shared model

Feed tag plus video plus language into one model encoder and decoder, train once on all robot data.

Step 4: tags capture differences

The model learns that tag_ur5 means different action semantics than tag_franka, and adjusts all intermediate computations accordingly.

Step 5: adapt to new robot

For a new robot, initialize a fresh tag, warm it up while freezing the model, then fine-tune the whole thing on a small amount of new data.

What the paper changes

The one thing that changes

The paper introduces learnable tags (soft prompts: short lists of numbers, one per robot type). These tags are inserted into the input stream during training and when the finished model answers a new question (inference); the model learns to condition all of its internal decisions on which robot it is currently controlling, because the tag passes information about which camera angles and action ranges to expect, and the model can then use that context to interpret the video correctly and output actions in the right scale for that robot.

the object it moves  =  learnable tags per robot
The hidden quantity

Embodiment-specific encoding bias

measured quantity  =  robot-aware internal-state clustering

Hidden inside the model is a space of internal numbers (computed by the model's layers) where each region corresponds to a robot type. When the tag for robot A is prepended, the model's internal states cluster in region A; when tag for robot B is prepended, they cluster in region B. This clustering is not explicitly trained; it emerges because the model learns that different clusters predict correct actions for different robots.

The paper measures this by training soft prompts on a mixed dataset, then testing whether the pretrained robot-independent features (the shared model backbone) can be efficiently adapted to a new robot by only learning the tag for the new robot while freezing the backbone. High performance with frozen backbone means the model has learned skills shared across robots, and the tag merely tells it how to apply those shared skills to a new robot.

Why it works

How soft prompts let one model learn all robots

Without soft prompts, mixing all robots in one dataset forces the model to predict actions that depend on robot-type context, but there is no explicit signal telling the model what context it is in. The direction to nudge the numbers to shrink the error (gradient) from contradictory robot types cancel each other out. With soft prompts, every training example is tagged: the UR5 trajectory comes in with the UR5 tag prepended, the Franka trajectory with the Franka tag. The model then learns a simple rule: if you see tag_ur5, decode this way; if you see tag_franka, decode that way. Each tag learns to activate a slightly different internal computation path because different tags cause different internal states, which predict different action sequences.

Because the tag is small (a list of maybe 768 numbers, compared to billions in the whole model), the model cannot afford to learn completely separate skills for each robot. Instead, it learns a shared backbone of robot-independent understanding (how to parse the video, how to follow language) and a thin specialization layer (what action numbers mean on this embodiment). When a new robot arrives, you only need to learn its tag from a small amount of new data, because the backbone already understands the visual scene and language.

The training objective

First in words:

Loss is the sum of prediction errors on all robot trajectories, where the model takes video and tag as input and predicts the next action chunk.

Then the compact form:

L_FM = E[ ||A_n - pi_theta(o_n, p_h)||^2 ]

Every symbol:

L_FMtotal training loss (behavior cloning with flow-matching objective)
A_nthe true action chunk: the sequence of joint angles and gripper commands
pi_theta(o_n, p_h)the model's predicted action, given observation o_n and soft prompt p_h for that robot
o_nmultimodal observation: video frames, language instruction, arm joint positions
p_hthe learnable soft prompt (tag) for robot h
E[ ]average over all trajectories in the training dataset
A tiny worked example
Say robot UR5 has true next action: [0.5, 0.3, -0.1] (three joint angles in radians).
Model with tag_ur5 predicts: [0.48, 0.29, -0.09]. Error = (0.5-0.48)^2 + (0.3-0.29)^2 + (-0.1-(-0.09))^2 = 0.0004 + 0.0001 + 0.0001 = 0.0006.
Model with tag_franka on UR5 data predicts: [0.2, 0.4, 0.5]. Error = (0.5-0.2)^2 + (0.3-0.4)^2 + (-0.1-0.5)^2 = 0.09 + 0.01 + 0.36 = 0.46 (much worse).
Gradients push tag_franka away from UR5 semantics, and tag_ur5 learns the right decoding. Both tags exist in the model, each used when its robot arrives.

The loss penalizes action prediction error, and the soft prompt for each robot is optimized to minimize error on that robot's data while the shared backbone learns shared visual-language features.

What can go wrong

What can go wrong

Tag size too large: wasted capacity. If the soft prompt is huge (e.g., as many numbers as the entire backbone), the model wastes parameters learning separate policies instead of shared structure. Use a small tag (typically 10–20% of backbone size).
Tags not learned from diverse enough data. If all robots in pretraining are industrial arms with similar workspace and speed, the soft prompts learn shallow differences. When a completely different robot type (e.g., a mobile manipulator) arrives, the pretrained backbone may not generalize, and the tag alone cannot fix it.
Vision-language encoders drift during pretraining. If you allow the pretrained vision-language model (e.g., Florence) to train at high learning rates on robot data, it may forget generic image understanding and become robot-specific. The paper addresses this by using reduced learning rates on vision-language modules.
Done right. Keep the tag small and learnable, keep the vision-language encoders mostly frozen with low learning rates, and pretraining on a diverse set of robots and tasks so the backbone learns flexible, embodiment-agnostic visual-language understanding that works across many robot types.
What a runnable demo should prove

What a runnable demo should prove

Implement a simple simulation with two different robot arms (e.g., via PyBullet): one with short arms and fast movements (robot A), one with long arms and slower movements (robot B). Create 100 trajectories for each (video, language commands like push, pick, place). Train an encoder-decoder model with soft prompts: one tag for robot A, one for robot B. On the mixed dataset, the model should converge cleanly to predicting correct actions for each robot. Then: freeze the backbone and initialize a fresh random tag for a third robot (robot C, never seen in training). Train only the tag on 10 trajectories of robot C. Measure whether action predictions on unseen robot C data improve faster than training the whole model from scratch, because if the backbone has learned shared visual-language understanding (how to recognize pick and place regardless of robot), learning only the tag should decode those shared skills for robot C much faster than relearning everything.

adaptation_speedup = (steps_to_converge_with_frozen_backbone) / (steps_to_converge_with_unfrozen_baseline)

If soft prompts work, the frozen-backbone version should reach the same accuracy in 3-5x fewer training steps, proving that the shared backbone learned embodiment-agnostic structure.
