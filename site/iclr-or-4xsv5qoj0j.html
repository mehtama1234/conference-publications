Textual Equilibrium Propagation for Deep Compound AI Systems

Instead of passing feedback backward through the whole pipeline, teach each agent to fix itself locally, then nudge each one slightly toward the global goal.

Paper explainersAll themesAgents & Tool Use

When you chain multiple AI agents together to solve a hard problem — like retrieving documents, checking facts, running tools, and answering questions — feedback about what went wrong gets passed backward through the chain. But over many steps, the feedback either explodes (grows huge and full of noise) or disappears (gets compressed so much it loses meaning). TEP fixes this by making each agent refine its own work until it improves no further, then applying small nudges that come forward rather than backward through the chain.

Zero assumption version

Long chains of AI agents trap feedback

When you build a real system, you do not run a single AI on a question. Instead, you chain them: one agent retrieves documents, another checks if they are relevant, a third tool-use agent tries to answer, a fourth verifies the answer, and so on. Each step hands its output to the next step.

A naive way to improve all these agents is to ask a judge at the very end: is the final answer correct? If not, tell the first agent how to change its prompt, because the first agent's output affects everything downstream. This is backward propagation — the feedback flows backward through all the steps, because you collect all context at once and send one message. But two things break. First, as the feedback message travels back, it grows: each agent adds detail (why my step failed, what I tried, what did not work), and after many steps the message is so long the model forgets what the real problem is, because longer messages dilute important information. Second, some agents are buried so deep in the message that their prompt edits get washed out by all the noise from later steps, because early-pipeline agents have less context about downstream problems and their tweaks drown in the bulk.

In one sentence. TEP makes each agent locally refine itself until no better prompts are found, then nudges each agent toward the global goal using forward (not backward) signaling, because forward signals stay small and detailed while backward messages bloat and lose meaning.

The algorithm as a flow

What it actually does

Free phase: equilibrium

Each agent iteratively re-writes its own prompt until the internal critic says no improvement is possible.

Measure the goal

Ask: how close is the final answer to what we want?

Nudged phase: compute task signal

Based on the goal gap, compute a small signal that says how each agent should adjust.

Forward edits

Instead of sending feedback backward, send small prompt edits forward to each agent, bounded so they don't wreck what was already working.

Loop if needed

Repeat the free phase with the nudged prompts until the chain reaches the goal.

What the paper changes

What the paper changes

The object is the prompts: the instructions given to each agent in the pipeline. Rather than sending one big feedback message backward (which either balloons or shrinks to uselessness), TEP modifies each prompt locally and then applies small forward-flowing nudges.

the object it moves  =  Agent prompts
The hidden quantity

The proxy signal: how much does each agent need to change

measured quantity  =  Modification intensity

The paper does not measure an internal importance score like Fisher information. Instead, it tracks a more direct quantity: how much each prompt should be edited to move the system toward the goal. This is bounded (kept from exploding into huge rewrites) and derived from forward signals rather than backward feedback signals (which direction to nudge and how much).

In the free phase, TEP measures how much each agent improves with self-refinement, because each agent has full context and can iterate locally. In the nudged phase, it computes a modification signal that says: given how far we are from the goal, nudge Agent1 by this much, Agent2 by that much. The bound keeps each nudge small enough that existing good behavior is preserved, because large edits can undo what was already working.

Why it works

Why it works: local refinement plus forward steering

The core insight is borrowed from energy-based models: instead of trying to steer the whole chain with one global gradient, break the problem into two phases.

In the free phase, each agent is its own judge. It rewrites its prompt, checks if the internal result is better, and keeps rewriting until the critic says stop (equilibrium). This works because the agent has its full context: it knows what input it got, what output it should produce, and can iterate without waiting for information from downstream agents.

In the nudged phase, the system measures how far the final answer is from the true goal. Then it computes a small signal for each agent: given this goal-gap, nudge your prompt by this much. The nudge travels forward (Agent1 nudges its prompt, Agent2 sees the improved input from Agent1, etc.), not backward (which would require collecting all context into a huge message). Because the nudge is bounded and forward-flowing, it carries full detail about what changed and why, without drowning earlier agents in noise.

The core equation

First in words:

For each agent, the bounded nudge size is: modification intensity = (goal gap) times (agent influence) divided by (max safe edit size). The final prompts are: new prompt = old prompt plus (bounded modification intensity times local direction).

Then the compact form:

nudge_i = min( |goal_gap| * influence_i / max_edit, bound_i ) prompt_i_new = prompt_i + nudge_i * direction_i

Every symbol:

nudge_iHow much to change agent i's prompt
goal_gapDistance from current answer to the correct answer
influence_iHow sensitive agent i is to a prompt change
max_editMaximum safe change size for any prompt
bound_iUpper limit on this agent's nudge (preserves good work)
direction_iWhich way to nudge the prompt (toward the goal)
prompt_iThe current instruction for agent i
A tiny worked example
Say goal_gap = 0.3 (we are 30 percent away from correct).
Agent1 influence_i = 0.8 (very sensitive), max_edit = 0.5, bound_1 = 0.1.
nudge_1 = min(0.3 * 0.8 / 0.5, 0.1) = min(0.48, 0.1) = 0.1 (bound kicks in).
Agent2 influence_i = 0.2 (less sensitive), bound_2 = 0.15.
nudge_2 = min(0.3 * 0.2 / 0.5, 0.15) = min(0.12, 0.15) = 0.12 (goal gap controls it).
Agent1 is pushed back by its own bound (it already works well), Agent2 gets a bigger nudge (room to improve).

The bound is the key: it keeps your good agents honest by refusing huge edits, while the forward signal carries the real information without exploding into an unreadable wall of text.

What can go wrong

What can go wrong

Bound too tight. If the maximum nudge size is set too small, no agent can adjust even when it should. The system stays stuck.
Bound too loose. If the maximum nudge size is too large, an agent with strong influence on the goal might overwrite its own good behavior, causing the answer to get worse.
Free phase equilibrium misleading. If an agent reaches a local maximum (stops improving by its own critic) but that is not actually good for the downstream task, the free phase gets stuck and does not improve the global goal, because the agent optimizes only its own output, not the effect on later steps.
Done right. Set the bound using a small validation set (does a 10% nudge improve or hurt?), because testing on real data reveals the right edit size for your pipeline. Tune influence_i using recent task feedback, because recent runs are most relevant. Let free phases run long enough (e.g., 5+ iterations) but not forever, because iteration helps agents find better prompts but infinite loops waste compute.
What a runnable demo should prove

What a runnable demo should prove

Build a 5-agent reasoning chain: Retriever (find documents), Filter (keep relevant), Reasoner (answer from docs), Verifier (check the answer), Reviewer (critique and suggest fixes). Give it a dataset of questions where agents fail. Run TEP for 3 cycles of free + nudged phases. Track how accuracy improves at each phase, because improvement shows that the method is actually steerable. Compare to a baseline where you pass all feedback backward in one message, and show that the backward message grows to 5-10x longer while accuracy falls, because the feedback explodes in size and buries the signal.

improvement = accuracy_after - accuracy_before; token_growth = tokens_in_feedback_msg_backward / baseline_length

The demo must show: (1) accuracy climbs as you add TEP cycles, because local refinement plus forward nudges steer toward the goal; (2) the backward-feedback message grows by 5-10x while TEP's forward nudges stay bounded, because backward propagation has to collect all context while forward signaling stays local; (3) agents two and three (early in the chain) actually improve with TEP but degrade with backward feedback, because early agents are buried in backward messages but get clear forward nudges.
