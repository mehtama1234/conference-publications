KaVa: Latent Reasoning via Compressed KV-Cache Distillation

Teach a model to reason quietly by matching its internal thought-cache to a compressed version of a teacher's chain-of-thought.

Paper explainersAll themesLLMs & Foundation Models

Large language models solve complex math problems by writing out every step (chain-of-thought), but all that writing uses up memory and compute. A faster way is to reason silently inside, without generating steps on screen. The problem: silent reasoning has no learning signal, because the model never hears what a correct silent thought should sound like. KaVa solves this by stealing the teacher's compressed internal cache and training the student to recreate it step-by-step, so the student learns what good reasoning looks like without ever having to write it out.

Zero assumption version

Silent reasoning has no teacher

Large language models solve multi-step math problems when you ask them to show their work. The model generates one reasoning sentence after another, each building on the last. This works well but wastes resources: the model has to store every step in memory (the key-value cache, the model's scratch pad), then output it all on screen. Each new step requires a forward pass through the entire model.

A faster approach is latent reasoning: the model keeps its thoughts hidden inside, never writing them out. At the end it just outputs the answer. This is much cheaper. But here is the trap: if the model never writes its thoughts, how does training teach it to think correctly? There is no ground truth to compare against. The model is flying blind.

Existing latent methods fail especially on natural-language reasoning traces (messy, wordy problem statements), falling back to memorizing examples instead of learning the reasoning pattern.

The gap. Silent reasoning saves compute but loses the learning signal that tells the model whether its hidden thoughts are correct.

The algorithm as a flow

What it actually does

Teacher builds cache

Teacher model runs chain-of-thought, storing key and value matrices at each layer for each reasoning step.

Compress the cache

Drop low-scoring keys and values per layer. Importance is measured by how much each key contributes to the final answer.

Align student steps

Student model generates latent tokens (hidden thoughts as numbers) at the same pace as the compressed cache.

Match the caches

Train student to output hidden tokens whose internal activations (keys and values they produce) match teacher's compressed cache at each step.

Deploy silently

At inference, student generates hidden tokens and answers without ever writing out reasoning steps.

What the paper changes

What the paper changes

KaVa changes what the student model is trained to match. Instead of trying to copy the teacher's written words (which silent reasoning never generates), it copies the teacher's internal patterns (the working-memory state as information flows through each layer). Specifically, it trains the student to generate the same flow of keys and values through its own layers as the teacher had while chain-of-thought reasoning.

the object it moves  =  internal working-memory cache
The hidden quantity

Importance scoring: which keys matter most

measured quantity  =  Per-head importance score

Every key in the teacher's cache contributes differently to the final answer. Some keys matter heavily (the final answer depends strongly on them), others are noise (the answer doesn't change if you delete them). KaVa measures this by attention: for each layer and attention head, it checks how much the model focused on each key when generating the final answer tokens.

The paper computes this as a sum of attention weights. High attention weight means the model used that key heavily when deciding what the answer should be. Keys with low attention get dropped during compression. This is why the compressed cache retains the signal: it keeps only the keys the model actually relied on.

Why it works

Why matching compressed cache teaches reasoning

The teacher's reasoning process builds up knowledge in its key-value cache as it thinks through each step. Keys store facts (what the model considered), values store weighted summaries (what matters). When writing a reasoning step, the model uses these keys and values to compute what words to output next.

Compression keeps only the most-attended keys, stripping away noise. This compressed cache is a distilled signature of the reasoning: exactly the pieces the model relied on, no padding.

The student is trained to output latent tokens (hidden thought-numbers, never become words) such that when tokens flow through student layers, they produce keys and values matching teacher's compressed cache at every layer and step. This forces student to internalize the same reasoning pattern: same information flow, same dependencies, same decision points, all as unspoken thoughts.

Training on compressed cache (not full noisy cache) teaches student to ignore redundant distractions and focus only on what matters. Step-by-step training signal teaches coherent reasoning trajectory, not just memorized equations.

The distillation loss equation

First in words:

For each layer and step, compute the difference between the student's keys and values and the teacher's compressed keys and values, using either absolute difference or squared difference depending on the setting.

Then the compact form:

Loss_KV = (1/L) * sum_l ||sg[h_t^l] - h_s^l||_p

Every symbol:

Loss_KVtotal mismatch across all layers
Lnumber of layers in the model
llayer index
sg[h_t^l]teacher's compressed hidden state at layer l (stop-gradient, frozen)
h_s^lstudent's hidden state at layer l (what we are training)
||_peither L1 norm (p=1, absolute difference) or L2 norm (p=2, squared difference)
Tiny worked example: one layer, one reasoning step
Teacher's compressed cache at layer 1 after step 2: [0.5, 0.2, 0.8]
Student's hidden state at layer 1 after step 2: [0.6, 0.1, 0.7]
Difference (absolute): |0.5-0.6| + |0.2-0.1| + |0.8-0.7| = 0.1 + 0.1 + 0.1 = 0.3
If there are 12 layers total, and all have similar mismatch, Loss = 0.3 * 12 / 12 = 0.3
Gradient flows backward: student weights adjust to make the next pass produce [0.5, 0.2, 0.8] instead.

Stop-gradient means the teacher's cache is frozen during training; only the student's weights move to close the gap.

What can go wrong

What can go wrong

Misaligned cache lengths. If the compressed cache is the wrong length (fewer steps than the student generates), the student has nothing to match at later steps and training becomes ill-posed. The student and compressed cache must be synchronized step-by-step.
Token correspondence is already broken. When you compress the cache by dropping low-attention keys, those remaining keys no longer correspond to input tokens in a simple way. Naive token-matching distillation fails here. KaVa sidesteps this by matching the full list of compressed keys and values as a whole, not individual tokens.
Teacher accuracy limits student. If the teacher's chain-of-thought is wrong on a problem, the student learns from a false signal. The method assumes the teacher's reasoning is correct.
Over-reliance on equation-based training. Early versions trained only on equations (pure math), but the student then failed on natural-language reasoning. KaVa must train on mixed traces to generalize.
Done right. Compress using importance scores, align student and cache by step, train on natural-language traces from real datasets, and verify the student's reasoning path matches the teacher's decision flow.
What a runnable demo should prove

What a runnable demo should prove

Build a simple reasoning task (e.g., grade-school math with a teacher model like Llama 3.2 1B). Run chain-of-thought reasoning and collect the full key-value cache. Compress it by importance scoring (drop bottom 50% of keys per layer). Train a tiny latent-reasoning student on just 1000 examples to match the compressed cache at each reasoning step. At inference, run the student without writing out steps and measure accuracy on a held-out test set. Compare three metrics: (1) test accuracy, (2) forward passes required (student should need 60-90% fewer), and (3) memory used for the KV cache (student should use 70% less).

Efficiency gain = (forward_passes_cot - forward_passes_student) / forward_passes_cot * 100

The demo must show that the student's accuracy stays within 5-10 percentage points of the teacher while using 60-90% fewer forward passes. This proves that matching the compressed cache teaches reasoning without speaking aloud.
