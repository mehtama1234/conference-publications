MedMamba: Multi-View Medical Time Series via Adaptive Graphs

Medical time series get three synchronized views of the same data to detect patterns that vanish in any single view.

Paper explainersAll themesTime Series & Sequential

Medical devices like heart monitors and EEG machines spit out time series — numbers changing over time. A single view often misses the real story: a patient's baseline can drift, sensors interact in complex ways, and the important pattern (an arrhythmia, a seizure) might be hiding in the timing between samples or in the frequencies where things oscillate. MedMamba reads the data three ways at once, fuses what each view sees, and learns which sensors depend on which others.

Zero assumption version

Why medical time series stay hard

Medical monitors record continuous data — an EEG has 19 channels (electrode sites), an ECG has 12, a motion sensor has 3. The challenge: a single channel might show garbage noise while the real signal hides in how channels relate to each other. A naive approach reads all channels as an independent pile of numbers and tries to classify them (sick or healthy). It fails because it misses two things: first, the baseline can drift (the sensor starts outputting higher numbers just because the body warmed up, not because anything clinical changed), and second, channels are locked together in hidden ways — when your heart speeds up, your breathing shifts, and blood oxygen lags by 2-3 seconds.

Existing deep-learning methods try to fix this by reading the time series through attention (which links far-apart samples) or by hand-building a graph of which sensors should connect to which. Both fail: attention costs a fortune to run on thousands of time steps, and hand-built graphs impose anatomy from a textbook rather than learning the real dependencies in *your* patient's data.

In one sentence. Read the same data three ways (raw values, changes between steps, frequency patterns), fuse them, and learn which sensors depend on which.

The algorithm as a flow

What it actually does

Step 1: Embed locally

Convolve the time series with three window sizes to catch both fast wiggles and slow trends.

Step 2: Read three views

Process the convolved numbers as raw values, as changes between consecutive steps, and as Fourier frequency patterns.

Step 3: Fuse views

Combine the three views using a state space model (Mamba): blend what each view revealed, suppress drift.

Step 4: Learn sensor graph

Compute a directed link matrix: which sensors influence which, how strong, sparse and acyclic.

Step 5: Classify

Average all time steps and sensor channels, pass to a linear layer, return class probabilities.

What the paper changes

The one thing the paper changes

Instead of treating each time step independently or assuming a fixed channel graph, MedMamba builds a sample-specific dependency matrix: for *this particular patient's data*, it learns which sensors causally influence which others, adapted to the patterns present in that single recording.

the object it moves  =  sensor dependency matrix
The hidden quantity

The hidden quantity: channel importance and linkage

measured quantity  =  adaptive sensor dependency strength

The paper measures something you cannot see directly: how strongly each sensor influences each other sensor *given this specific data*. This is baked into the directed dependency matrix A, a square grid where each cell holds the strength of influence from one sensor to another. This matrix changes per patient and per recording, adapting to what the data actually shows, rather than staying fixed to a textbook anatomy.

The model computes A by running each channel's embedding through a learned function, then constraining A to be sparse (most links stay zero) and acyclic (no circular feedback loops). Sparsity forces the model to keep only the strongest, most reliable links; acyclicity ensures dependencies flow one direction, matching how medical causality usually works (a heartbeat causes a blood-pressure spike, not the reverse).

Why it works

Why three views catch what one view misses

Baseline drift is the curse of medical time series: a patient's temperature, EEG baseline, or sensor calibration can climb or slide over hours without any clinical change. Reading the raw values alone makes drift invisible — you cannot tell if the numbers are drifting or if the patient is sick. The solution: also read the *differences* between consecutive time steps (the delta view) and the *frequencies* where the signal oscillates. Raw values drift; differences and frequencies stay honest.

The three views are fused by a state space model (Mamba), which is just a neural layer designed to link time step t to time step t+1 efficiently. It weights the three views: where raw and difference disagree (a sign of drift), the frequency view breaks the tie. Where all three align, that pattern is truly there. The output is a merged view where drift is suppressed, real patterns pop out.

Finally, the paper does not assume sensors are independent. It learns a directed graph of sensor dependencies: which measurements reliably predict which others. This graph is computed for each patient and recording (sample-specific), learned from the fused multi-view embedding. Sparse and acyclic constraints keep it interpretable: strong links are rare, and causality flows in one direction, not in circles.

The equation: fused multi-view state space update

First in words:

For each time step, blend the raw embedding, the temporal-difference embedding, and the frequency embedding using a state space model, then apply the learned sensor dependency graph.

Then the compact form:

z_t = SSM(raw_t, diff_t, freq_t) + A * z_prev_t

Every symbol:

raw_tthe embedded values at time t
diff_tthe embedded changes from t-1 to t
freq_tthe embedded Fourier frequencies at time t
SSM(...)state space model: fuse three inputs into one output
Alearned sensor dependency matrix (what influences what)
z_prev_tthe output from the previous time step
z_tthe fused output at time t
A tiny worked example with three sensors
Sensor 1 raw_t = 0.5, diff_t = 0.1 (climbing), freq_t = 0.3 (low oscillation).
Sensor 2 raw_t = 0.6, diff_t = 0.05, freq_t = 0.8 (high oscillation).
Sensor 3 raw_t = 0.4, diff_t = 0.2 (rising fast), freq_t = 0.2.
SSM blends: freq_t is up for Sensor 2, so trust freq_t; diff_t is up for Sensor 3, so trust diff_t; raw_t drifts everywhere, so downweight it.
Dependency matrix A: [[0.0, 0.7, 0.0], [0.1, 0.0, 0.6], [0.0, 0.0, 0.0]] means Sensor 1→2 (0.7), Sensor 2→3 (0.6).
z_t = SSM_output + A * z_prev → fused multi-view state, dependency-adjusted.

The math keeps drift-prone raw values honest by checking them against change-based and frequency-based truth; the graph adds long-range sensor memory.

What can go wrong

What can go wrong

Sparsity constraint too tight. If you force the dependency matrix to be too sparse (too many links forced to zero), you lose real sensor interactions. The model cannot express the true causal structure.
Acyclicity trap. Real physiology sometimes has feedback loops (heart rate affects blood pressure, which affects heart rate). Forcing acyclicity cuts off valid patterns.
Multi-view redundancy. If drift is not present or sensor interactions are weak, the three views become redundant and the model wastes capacity blending them instead of focusing on real patterns.
Done right. Tune sparsity and acyclicity constraints per dataset; validate that learned graphs match known anatomy; use multi-view fusion only when drift is present.
What a runnable demo should prove

What a runnable demo should prove

Build a tiny dataset: 10 ECG recordings (normal and arrhythmic), 2 time steps each, 3 sensors. Inject artificial baseline drift into half the recordings (add a smooth upward slope to the raw signal). Train MedMamba and a naive CNN baseline. Measure accuracy and learned graph structure.

accuracy_diff = (MedMamba_accuracy - CNN_accuracy)
