Learning to Move Before Learning to Do: Task-Agnostic Pretraining for VLAs

Teach robots to move by learning from throwaway data, then teach them what to do with scarce expert examples.

Paper explainersAll themesRobotics & Control

Vision-Language-Action models (systems that read images, understand text instructions, and pick actions) usually need expensive collections of labeled robot videos showing what to do. This paper separates two things: learning how a robot's body moves in the world, and learning which task to do. By first training on cheap unlabeled robot play—footage that has no task label at all—the model learns the physics of grasping and movement. Then a quick second stage connects those physics to language instructions.

Zero assumption version

The bottleneck: expensive labeled robot videos

Vision-Language-Action models read images, parse text instructions, and output motor commands to control a robot. Training requires millions of video clips showing a human expert doing a task—moving a gripper, pushing objects, stacking blocks—labeled with the instruction and the exact action at each frame. Collecting these triplets is slow and costly.

A beginner might think the solution is obvious: gather more labeled data. But that just makes the problem worse. The model ends up needing massive labeled datasets to learn even simple moves, because it has to learn physics (how a gripper closes, how objects slide) and task-knowledge (what 'push the block left' means) from scratch, all tangled together. This means building a robot that understands language requires an impossible amount of labeled video.

The core insight Separate two learning problems: (1) learn how to move from cheap unlabeled robot play, then (2) connect movement to language using minimal expert video.

The algorithm as a flow

What it actually does

Stage 1: Inverse dynamics training

Feed pairs of consecutive frames from unlabeled robot play; train to predict the action between them.

Encoder learns affordances

Model discovers what pixels control grasping, how hard contact is, when objects slip, end-effector pose.

Stage 2: Language alignment

Freeze Stage 1 weights; add a decoder and train on small set of expert video + text instruction pairs.

Behavior cloning on top

Decoder learns to match language intent to the physical primitives the encoder already knows.

Deploy: unified model

Read image and instruction. Encoder extracts affordances. Decoder picks action that matches intent.

What the paper changes

What the paper changes

The paper changes the training pipeline: instead of training end-to-end from scratch on labeled data, it breaks training into two stages. Stage 1 trains only the visual encoder using unlabeled robot play. Stage 2 trains the action decoder using minimal expert video. This decoupling means the hard (learning physics) and easy (learning instruction meaning) parts are solved separately.

The hidden quantity

The hidden quantity: physical affordances

measured quantity  =  physical affordances

Physical affordances are invisible properties of what a robot can do: how soft the gripper closes, where objects slip, the stiffness of contacts, the speed the arm can move, how the camera sees the gripper relative to targets. The model needs to learn these from raw pixels, but the abstract never names this quantity explicitly.

The paper measures affordances implicitly through the model's ability to predict actions given image pairs. If the model can predict 'what action bridges frame A to frame B' correctly, it has learned the physics. Why it works

Why task-agnostic pretraining works

The mechanism relies on a constraint: to predict an action from two consecutive images, the model must learn which pixels matter. A gripper pixel matters because it moves when the action is 'close'. A target object matters because it tells you if the action succeeded. Background pixels don't predict anything because changing the background doesn't change the action the robot should take—the loss stays zero whether the background is ignored or learned, so gradient-based training (which nudges weights toward lower loss) steers the model to ignore background and focus on the gripper. This is forced by the inverse dynamics objective itself.

Stage 1 solves a pure physics problem: 'what action would cause this before-image to become this after-image?' The model has no task label, no language instruction, no reward signal. It only has pixel-change prediction. This constraint eliminates task-specific noise and forces genuine physical understanding.

Stage 2 is cheap because the encoder already knows the physics. The decoder just needs to map 'push pumpkin left' to 'apply leftward force on the pumpkin now in view'—a simple translation from language to the motor primitives the encoder already speaks. Minimal expert video suffices because the hard part (learning what happens when you move) is solved.

Math after the picture

The inverse dynamics equation

First in words:

loss equals the squared error between the predicted action and the true action that caused the frame change

Then the compact form:

L_id = mean( (a_predicted - a_true)^2 ) where a_predicted = decoder( encoder(frame_t, frame_t+1) )

Every symbol:

L_idinverse dynamics loss (how wrong the prediction is)
a_predictedthe action the model guesses would cause the frame change
a_truethe action that actually happened (recorded in the robot trajectory)
encoder(frame_t, frame_t+1)the visual system that learns affordances from image pairs
decoder(...)the action head that turns affordances into motor commands
A tiny worked example
Frames show gripper closed in frame_t, open in frame_t+1. True action is 'open gripper 30%'.
Model predicts 'open gripper 35%' (error = 5% units of motion).
Loss contribution from this pair = (35 - 30)^2 = 25.
After many such examples, encoder learns 'open gripper' is linked to frame pixels showing gripper and target object.
Stage 2 adds language: 'pick up the block' now routes through the encoder that already knows grasping.

The encoder learns affordances because predicting actions requires understanding which pixels control the robot's motion.

What can go wrong

What can go wrong

Different robot body or workspace. If pretraining data comes from a robot with different arm kinematics, gripper design, or workspace than the target task, affordances won't transfer. The gripper physics the model learned do not apply.
Instruction ambiguity confuses alignment. If Stage 2 expert data uses vague instructions ('move things') the decoder cannot map language consistently to motor primitives. The affordances are learned, but the language-to-action bridge fails.
Camera shifts break the encoder. If the camera moves, lighting changes, or background shifts between pretraining and deployment, the affordance representations may not generalize. However, the paper shows pretraining keeps working when baselines fail under camera perturbation—a key strength.
Done right. Pretraining on diverse, cheap robot play (off-task trajectories from multiple robots) gives the encoder broad physical priors. Stage 2 on clean, well-annotated expert video teaches the language mapping without overfitting to a narrow task.
What a runnable demo should prove

What a runnable demo should prove

Build a two-stage learner on a toy robotic arm (or simulation): (1) Stage 1 trains inverse dynamics on 10 hours of autonomous robot play (no task labels, just 'move randomly and record'). (2) Stage 2 fine-tunes on 10 expert trajectories of 'push red cube left'. (3) Measure success rate on held-out test tasks—pushing the cube in new directions, from new start poses. Compare against a single-stage baseline (same architecture, trained end-to-end on the same 10 expert trajectories). The demo succeeds if pretraining matches or exceeds the baseline despite using the same amount of labeled data, proving that affordances learned from unlabeled play are transferable.

success_rate = (number of test pushes that land in the target zone) / (total test attempts)

The metric must show: pretrained model reaches higher success on held-out tasks than same-architecture model trained only on expert data, using identical labeled data volume.
