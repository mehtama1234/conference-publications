NeuroKalman: Fixing Position Drift in Continuous Navigation

A UAV navigation system corrects accumulated position errors by treating prediction as Bayesian state estimation, using retrieved past observations to recalibrate the current belief.

Paper explainersAll themesRobotics & Control

Robots navigating via vision and language commands make predictions one step at a time: what is the next waypoint? But each guess has a small error, and these errors pile up into a misaligned belief about where the robot actually is. NeuroKalman uses classical control theory to fix this: it predicts the next position based on motion, then immediately corrects that prediction by retrieving and comparing to similar past observations that the system has already seen.

Zero assumption version

Dead-reckoning breaks down over time

A UAV follows a natural-language instruction (go to the red door) and looks at the current camera image to predict where the next waypoint should be. It then moves there and repeats. This sounds straightforward, but each prediction is wrong by a little bit. After 10 steps, the robot's internal model of where it is has drifted far from reality, causing it to hit obstacles or miss the target.

A beginner might think: just make the individual predictions more accurate. But even perfect single-step predictions would eventually drift, because errors accumulate like rounding errors in long arithmetic. The real problem is that the robot makes each guess in isolation, ignoring the trail of actual observations it has already collected.

The fix in one sentence. After predicting the next position, immediately correct it by finding similar past observations and using them as anchors to adjust the belief.

The algorithm as a flow

What it actually does

Encode the scene

Combine the current camera image and the natural-language instruction into a latent representation (a list of numbers capturing what the robot sees and what it should do).

Predict the next position

Use a recurrent network that processes the previous position estimate and motion commands to produce an initial guess for where to go next.

Retrieve past anchors

Search the memory of all past observations for scenes similar to the current one using a learned similarity metric.

Correct using retrieved observations

Combine the initial guess with the retrieved past observations to form a final, recalibrated belief about the position.

Use the corrected belief for the next step

Feed the corrected position estimate back into the predictor, so the next guess starts from a more honest model of where the robot is.

What the paper changes

What the paper changes

NeuroKalman changes the latent representation of the robot's position—the internal list of numbers that encodes where the system believes it is and what it has learned about the environment. Instead of letting this drift uncorrected, the paper adds an explicit correction step that pulls this representation back toward consistency with the actual past observations the system has collected.

the object it moves  =  latent position representation
The hidden quantity

The hidden quantity: Position Belief Misalignment

measured quantity  =  Position Belief Misalignment

This is the gap between where the robot's internal model thinks it is and where it actually is in the objective coordinate system. It is measured implicitly through the difference between the predicted position and the corrected position derived from retrieved observations. Large misalignment means the robot will make wrong navigation choices; small misalignment means predictions stay grounded in reality.

The paper estimates this by comparing the prior prediction (based only on motion dynamics) to the likelihood signal from the retrieved past observations. The larger the gap, the larger the correction applied, and the more the belief gets realigned.

Paper reading. The corrected belief (what to think the position is now) is proportional to two things multiplied: how likely the current observation is given the position, and how likely the position is given the previous position and motion. The paper builds both using neural networks: a multimodal language model learns the observation likelihood from retrieved anchors; a recurrent network learns motion dynamics for the position likelihood.
Why it works

Why the correction works

The core insight is to treat navigation as a Bayesian state estimation problem—a classical control technique that separates prediction and correction. Every step has two parts: first, predict where to go based on the motion command; second, correct that prediction using new evidence.

The paper implements this with two neural networks. A recurrent network (GRU) learns motion dynamics and produces the prior prediction. A multimodal language model learns to retrieve relevant past observations and encode them as a likelihood signal. These two signals are combined using a weighted blend called Kalman gain, which downweights the prior when the retrieved evidence is strong and upweights it when the evidence is weak.

Because the correction step uses retrieved past observations without retraining the model, the robot can correct its position on the fly without expensive computation. The retrieved observations act as anchors that keep the belief honest throughout the trajectory.

Math after the picture

The recursive Bayesian equation

First in words:

The posterior (corrected belief) is proportional to the likelihood (observation evidence) times the prior (motion-based guess). The posterior tells the robot where it should actually be.

Then the compact form:

P(z_t | observations, instructions) ∝ P(observation_t | z_t) × P(z_t | z_{t-1}, motion_{t-1})

Every symbol:

z_tthe latent position representation at time t
observation_tthe current camera image
motion_{t-1}the movement command applied at the previous step
P(observation_t | z_t)likelihood: how well the current observation matches the position
P(z_t | z_{t-1}, motion_{t-1})prior: where motion dynamics predict the robot should be
×multiply (combine the two sources of information)
∝proportional to (ignoring normalization constants)
A tiny worked example
Suppose the position is a single number (1D for simplicity).
Prior (from motion): position is predicted to be 50 ± 5 units (some uncertainty).
Observation from retrieved past: the scene at position 48 ± 3 units is very similar to now (high likelihood).
Blend: position 48 has higher evidence, so the posterior shifts toward 48. If likelihood is strong (low ±3), the posterior moves closer to 48. If likelihood is weak, posterior stays closer to 50.
The Kalman gain automatically decides how much to trust each signal; precise observations pull the belief, noisy predictions matter less.

The method builds this equation in a neural network: the GRU learns the motion-based prior, the retrieved observations define the likelihood, and the Kalman gain fuses them.

What can go wrong

What can go wrong

Retrieved observations are from the wrong scene. If the retrieval mechanism returns past observations that do not match the current scene, the likelihood signal pulls the position estimate in the wrong direction, making drift worse. The paper mitigates this by using learned similarity metrics to match scenes accurately.
Memory bank is empty or too small. Early in the trajectory, there may not be enough past observations to retrieve from. The correction signal is weak, and drift accumulates, because the system cannot find similar past scenes to compare against. After many steps, the memory bank is large enough to help, because there are now many past observations to search through and find strong matches that reliably pull the position estimate back to reality.
Motion dynamics model is fundamentally wrong. If the GRU fails to learn motion patterns (e.g., the UAV is in a slippery or chaotic environment), the prior prediction is inaccurate, and correction alone cannot save it. The method still requires a reasonable motion model.
Done right: prediction + correction + memory. When the motion model is reasonable, the retrieval mechanism is accurate, and the memory bank is rich, the two-step cycle (predict, then correct) keeps position drift bounded even over long trajectories.
What a runnable demo should prove

What a runnable demo should prove

Build a small UAV navigation simulator (or use a subset of the TravelUAV benchmark). Run two agents side by side: one using the naive dead-reckoning baseline, one using NeuroKalman. At each step, log the predicted position and the ground-truth position. Plot both trajectories on a bird's-eye map.

The baseline trajectory should visibly drift off course (especially after 10+ steps), while the NeuroKalman trajectory should stay close to the ground-truth path. Measure the cumulative position error: the baseline error should grow linearly with steps; the NeuroKalman error should stay roughly constant (or grow much more slowly) because the correction step constantly pulls the belief back to reality.

cumulative_error = sum over time of | predicted_position - ground_truth_position |

The key observation is that NeuroKalman's position error stays small and bounded, while naive dead-reckoning's error grows without bound. This proves that the correction step actually works: retrieved past observations do keep the belief honest.
