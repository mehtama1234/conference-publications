SCOPE: Evolving Symbolic Worlds for Long-Horizon Robot Planning

When robots plan in messy real environments, their mental models of the world stay incomplete; SCOPE fixes that by letting the robot remember what real attempts teach it, then updating its world model each time something goes wrong.

Paper explainersAll themesRobotics & Control

A robot using a large language model to plan complex multi-step tasks learns to describe the environment in symbols (e.g., objects, properties, actions). But these symbol-based descriptions are almost always incomplete—they miss properties, preconditions, and state changes that matter when tasks actually run. SCOPE solves this by running a closed loop: when a robot's plan fails, the system records what went wrong, learns from it, and updates its stored world description so the next plan is better.

Zero assumption version

Robot planning breaks when the world is messier than the description

A robot needs to understand what objects exist, what actions it can do, and what preconditions each action needs. A language model can write down these facts in a formal description (a set of logical rules). But when the robot enters a real, open-ended environment where cabinets are partially closed, items sit in unexpected places, or surfaces have unexpected states, the description is almost always incomplete.

A naive approach: the language model writes down what it thinks the world contains, the classical planner finds a valid sequence of actions, and the robot executes the plan. When the plan fails partway through because an assumption was wrong (e.g., the water was already on, or a door was locked), the robot stops. The language model is never told why the failure occurred—it sees only that the plan failed, not which assumption was violated. On the next attempt, it makes the same mistake because no new information flows back to update the description.

The core problem: The robot's mental model of the world stays frozen and incomplete, even after repeated failures teach it what is missing.

The algorithm as a flow

What it actually does

Initialize

Language model creates a symbolic description of the environment from visual input and the task.

Plan

Classical planner searches for an action sequence that logically satisfies the goal given the current world description.

Execute and validate

Robot carries out the plan. A symbolic validator checks each step; real execution checks whether the step actually succeeded.

Detect mismatch

When validation or real execution fails, the system identifies what assumption was violated (a missing precondition, property, or action effect).

Update memory and world

Symbolic memory stores the discovered fact with evidence of what failure it resolved; world description is updated for future plans.

What the paper changes

What the paper changes

SCOPE changes the symbolic world description itself—the formal list of objects, properties, preconditions, and action effects. Instead of writing the description once and leaving it fixed, the system updates it after each failure. The paper also introduces a persistent memory that pairs each world fact with the failure signature it resolved; when planning a new task, the system can match the current failure pattern against this history and retrieve facts that helped before, speeding up adaptation in new environments.

The hidden quantity

The hidden quantity: Symbolic recall

measured quantity  =  Symbolic recall

As the robot plans and executes, the true completeness of its world model stays hidden—you cannot know in advance which properties or preconditions you forgot. Symbolic recall measures how many of the true world facts your description has captured. It is computed by comparing the formal rules the system maintains against a gold-standard complete world definition and counting the fraction of true facts your system retrieved.

SCOPE estimates symbolic recall in two ways: first, by running the planner symbolically (checking whether the plan satisfies all logical constraints) and comparing that to what happens in real execution; second, by analyzing failures to infer which facts were missing. Each new fact discovered and added to the world model increases symbolic recall.

Why it works

Why it works: the closed loop

Failures contain information. When a plan fails, the gap between what the symbolic world predicted and what actually happened reveals exactly where the model is incomplete. SCOPE has two mechanisms that extract that information and use it to strengthen the model.

First, a Symbolic Execution Simulator runs each planned action through logical rules to predict success before the robot moves. When the simulator prediction diverges from real execution, the system knows the world model is incomplete at that specific point. It records what went wrong: was a precondition unmet? Did an action have an unexpected side effect? The system then patches the world description.

Second, a Self-Adaptive Symbolic Memory records each discovered fact along with which failure it resolved. When planning hits a similar failure in a new task or environment, the memory suggests the relevant facts to retrieve. This means the robot learns not just facts, but patterns—which facts tend to matter together, and when they are likely needed.

Math after the picture

The learning update equation

First in words:

When a newly discovered world fact is added, its confidence is reinforced each time it resolves the same failure pattern again. If it does not help with the current failure, or if the failure shifts to a later step, the fact's confidence is down-weighted. Symbolic infeasibility (logical constraint violation) and real execution mismatches are treated as separate error signals.

Then the compact form:

confidence_new = confidence_old + alpha * (is_success - beta * is_irrelevant)

Every symbol:

confidence_oldCurrent strength of the world fact before this attempt (how much we already trust it)
alphaLearning rate (how much one success story changes our belief)
is_success1 if the fact helped resolve this failure, 0 otherwise
betaDown-weight factor (penalty for facts that do not help or hurt)
confidence_newUpdated strength after this attempt
A tiny worked example
Initial fact: 'Door D must be unlocked.' confidence_old = 0.3 (we found this fact once, weak belief).
Attempt 1: Robot tries to open door, fails. Validator detects precondition unmet. We add 'door locked' to world. is_success = 1, alpha = 0.2, beta = 0. confidence_new = 0.3 + 0.2 * (1 - 0 * 0) = 0.5.
Attempt 2: Same task, new environment. Robot tries to open a different door that is unlocked. Validator detects 'door locked' check is not needed. is_success = 0, alpha = 0.2, beta = 0.1. confidence_new = 0.5 + 0.2 * (0 - 0.1 * 1) = 0.5 - 0.02 = 0.48.
Attempt 3: Failure on yet another task. 'Door locked' check saves the plan. is_success = 1. confidence_new = 0.48 + 0.2 * 1 = 0.68.
After many successes, the fact confidence rises; it becomes a default assumption the memory suggests on similar tasks.

The equation implements learning by consequence: each world fact accumulates a confidence score that rises when the fact helps the planner avoid a real-world failure, and falls when the fact is irrelevant or harmful. When retrieving candidates for future planning tasks, the system lists high-confidence facts first, which means the robot focuses its search on facts that have repeatedly helped before.

What can go wrong

What can go wrong

The mismatch signal is noisy. If symbolic validation and real execution both fail for different reasons, the system might patch the wrong fact. For example, a sensor gives wrong data and the robot executes wrongly, but the system misattributes the failure to a missing world property instead of a sensor error.
Over-fitting world facts to one environment. The robot might add facts that are specific to one kitchen layout or object configuration, then fail when it enters a new environment where those facts do not apply or conflict with new constraints.
Circular dependencies in world rules. If two world facts refer to each other (e.g., action A requires property P, and property P is an effect of action B), incorrect learning can create logical deadlocks that the planner cannot satisfy.
Done right. SCOPE mitigates these by tracking which facts resolved which specific failures (not just storing facts blindly), by retrieving facts on demand based on task context rather than applying all stored facts everywhere, and by validating new facts against existing logical constraints before accepting them.
What a runnable demo should prove

What a runnable demo should prove

Build a simple embodied task in two variants. Variant A: simple kitchen (three objects, one tap, one cabinet). Variant B: complex kitchen (same objects, but the tap has a push button, the cabinet door is sometimes locked, and the table can be wet). Run the robot on variant A first, let it fail and recover a few times, recording the world facts it discovers. Then run it on variant B without resetting. Measure: (1) Plan success rate on variant A after first three failures; (2) Plan success rate on variant B (which requires facts learned from variant A); (3) Symbolic recall (count of world facts the system has stored vs. a ground-truth fact set).

Plan success rate = (steps where predicted action equals actual action outcome) / (total steps). Symbolic recall = (discovered facts) / (ground-truth facts). Transfer gain = success_rate_B_with_learned_facts - success_rate_B_without_learned_facts.

The demo must show that the success rate climbs as failures accumulate and that facts learned in one environment actually transfer to a new environment with similar affordances.
