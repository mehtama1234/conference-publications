Depth and Spatial-aware Key-Value Refinement for Vision-Language Models

When a vision-language model hallucinates, it is because the numerical vectors inside the attention mechanism are scattered and disorganized; you can fix this by grouping them by depth and location without retraining.

Paper explainersAll themesMultimodal

Large models that read both images and text (vision-language models) sometimes invent details they did not actually see, called hallucinations. This paper reveals the root cause: inside the model, the numerical lists used for reading the image are scattered and chaotic, weakening the connection between picture regions and words. The authors propose a lightweight repair method that reorganizes these lists by depth and position, grouping things that belong together and separating things on different surfaces.

Zero assumption version

When models make up details

A vision-language model is a system that reads both pictures and text. You give it an image and ask a question, and it produces an answer. But sometimes it invents details that are not actually in the picture. For example, you might show it a photograph of a table with a red cup, and ask what color the cup is. The model says green because it is hallucinating.

A beginner might try adding more supervision signals (extra labels to teach the model what is real) or using reinforcement learning (rewards for correct answers). But these approaches miss the root cause of the hallucination. The real problem lives inside the part of the model that decides which regions of the image to focus on when generating each word of the answer. In this focusing process, numerical lists representing each image region become scattered and disorganized. When these lists are jumbled together with no structure, the model loses the cues that tell it where one object ends and another begins, because it cannot use the lists to navigate the layout of the scene.

In one sentence. Reorganize the numerical lists (one per image region) used by the focus-mechanism by grouping them according to depth and spatial location, without retraining the model.

The algorithm as a flow

What it actually does

Estimate depth

Run a depth predictor on the image to learn which pixels are near and which are far.

Group by depth

Sort the numerical vectors (one per image region) into groups by their estimated depth.

Add spatial links

Connect vectors that are close in 2D position, pulling nearby regions into clusters.

Refine key-value cache

Feed these clustered, organized lists into the focusing mechanism instead of the original scattered ones.

Generate grounded text

The model now produces words that match actual objects because the focusing mechanism is locked on real regions.

What the paper changes

The numerical lists inside the focus mechanism

The paper changes a single object inside the model: the key-value cache. This is a storage area holding numerical lists (one list per image region) that the focusing mechanism uses to decide which part of the image to read. The standard version stores these lists in the order they arrive, with no spatial or depth structure. The authors reorganize these lists, grouping nearby image regions together based on their depth and 2D position.

The hidden quantity

KV-coherence: how organized are the numerical lists?

measured quantity  =  KV-coherence

The hidden quantity is KV-coherence: a measure of how well the numerical vectors in the key-value cache are organized by spatial and depth structure. When KV-coherence is high, nearby image regions have similar vectors, and regions on different surfaces have different vectors. When it is low, all vectors are scattered and random, carrying no information about where they come from.

The paper discovers this by comparing successful (non-hallucinating) model outputs with hallucinating ones. In successful cases, the lists form dense clusters where objects are. In hallucinating cases, the lists spread uniformly in all directions, so the focusing mechanism cannot tell one object from another.

Why it works

Why organizing vectors stops hallucinations

The root cause of hallucination is that scattered lists carry no spatial information. When the focusing mechanism tries to link image regions to words, it cannot distinguish a cup from the table because all lists look the same. The model then invents plausible details based on statistics it learned during training (cups are often on tables, cups are often red) rather than grounding the answer in the actual image.

Depth and spatial clustering fixes this by making lists coherent. When lists for a single object (say, the cup) are grouped together, the focusing mechanism sees them as a tight cluster and focuses on that cluster when generating object-related words. When lists for the table surface are separated from lists for the cup by both depth and position, the model learns to distinguish them. This coherence acts as a physical barrier: the pathway to hallucinated details is now blocked because the lists pointing to non-existent features have been reorganized away from the true object clusters.

Math after the picture

Grouping by depth and position

First in words:

For each image region i, compute a similarity boost to region j if they share the same depth layer d and are within distance r in 2D. Sum these boosts to reweight the key-value vectors. Higher boost means the model pulls those vectors closer together in the attention computation.

Then the compact form:

KV_refined[i] = KV_original[i] + lambda * sum_j ( [depth[i]==depth[j]] * exp(-distance[i,j]^2 / r^2) ) * KV_original[j]

Every symbol:

KV_original[i]the original numerical vector for region i
KV_refined[i]the updated vector after spatial grouping
depth[i]estimated depth value for region i (smaller=closer to camera)
distance[i,j]2D pixel distance between regions i and j
lambdaweight controlling how strongly spatial grouping is applied
rradius of influence (how far spatial grouping reaches in pixels)
A tiny worked example
Region 0 (cup center): depth=2, position=(100,100). Original vector=[0.5, 0.3, 0.2].
Region 1 (cup edge): depth=2, position=(110,105). Original vector=[0.4, 0.35, 0.25]. Distance=11 pixels.
Same depth, nearby position. Boost = exp(-11^2 / 50^2) = exp(-121/2500) = 0.95 (very strong).
Region 5 (table far): depth=50, position=(150,150). Original vector=[0.2, 0.2, 0.6]. Distance=71 pixels.
Different depth, far away. Boost = 0 (no boost because depths do not match).
Result: vectors 0 and 1 merge closer together (KV_refined[0] += 0.95 * lambda * [0.4, 0.35, 0.25]); vector 5 stays distant.

The equation creates barriers between different depth layers while pulling same-surface regions into tight clusters, giving the attention mechanism clear object boundaries.

What can go wrong

What can go wrong

Poor depth prediction. If the depth estimator fails (e.g., on transparent, reflective, or severely occluded objects), the grouping signal is noisy and vectors do not cluster correctly.
Thin or elongated objects. Objects with complex 3D structure (like hair, thin wires, or intricate jewelry) may span multiple depth layers; spatial grouping alone may not link all their parts.
Crowded scenes. When many objects are close in depth and position, the spatial radius r may accidentally merge vectors from different objects, creating new types of confusion.
Done right. When objects are well-separated in depth or position, and the depth predictor is accurate, refinement reliably groups object regions and stops hallucinations.
What a runnable demo should prove

What a runnable demo should prove

Build a simple script that loads a vision-language model (e.g., LLaVA), an image with clear depth variation (a desk with objects at different distances), and a question that probes hallucination (e.g., 'What color is the object on the left?'). Implement the spatial-grouping step using a lightweight depth estimator. Run the model twice: once with the original key-value cache and once with DSCR refinement. Compare the outputs and measure whether DSCR produces grounded, object-specific answers while the baseline hallucinates plausible but false details.
