Extreme Weather Nowcasting via Local Precipitation Pattern Prediction

A fast radar forecasting model that handles both ordinary rainfall and extreme storms by looking at local patterns and balancing its training data.

Weather forecasting models today either run slowly on expensive computers or guess poorly when rain becomes extreme. This paper builds a fast model that stays accurate even when predicting unusual, dangerous rainfall. The trick is teaching the model to see fine details in rainfall patterns and training it on balanced data that includes both ordinary days and extreme events.

Zero assumption version

Why current models fail at extreme weather

Predicting rainfall a few hours ahead seems simple: look at where rain is falling now, trace how it moves. In practice it is hard. Rainfall has fine textures—thin streaks, small cores—that change fast. A naive approach treats all parts of the radar image the same way. That fails because rainfall is local: a raindrop in one corner of the image barely affects a corner far away, yet global averaging forces the model to mix distant regions together.

Real-world data also lies. Most days have light or no rain. Benchmark datasets are extreme: either full of ordinary rainfall or packed only with storms. A model trained only on ordinary data learns to predict average rain and gets paralyzed when a storm comes—it guesses safe, dull numbers. A model trained only on storms learns the opposite mistake. The model never learns the full range.

Meanwhile, forecasting methods from recent research use diffusion—a slow process that runs many steps to generate a guess. This works well but takes minutes per forecast, useless for warnings that need to go out now.

The method in one sentence. Use local region processing and balanced training data so a fast deterministic model can forecast both ordinary and extreme rainfall accurately.

The algorithm as a flow

What it actually does

Look at local regions

Divide the radar image into small patches; each processes only nearby neighbors, not the whole image.

Measure neighbor importance

For each pixel, compute which neighbors matter most—closer pixels get higher importance.

Upsample fine details

A specialized decoder rebuilds the small patches into the full-resolution forecast while keeping small-scale textures sharp.

Adjust time range flexibly

A separate temporal module lets the model predict 1 hour ahead or 6 hours ahead by adjusting its computation.

Train on balanced rainfall

Feed the model equal numbers of ordinary and extreme events so it learns both equally well.

What the paper changes

What the paper changes

The paper replaces the global image processing with local region processing. Instead of one model step that looks at the entire radar image at once, the model works on small neighborhoods where each pixel only attends to nearby pixels. It also replaces global averages in the decoder—the part that draws the final forecast—with a specialized upsampling method that sharpens fine texture details.

The hidden quantity

The hidden quantity: local pattern coherence

measured quantity  =  local pattern coherence

Rainfall is not random noise. Within a small region, neighboring pixels tend to have similar values—a raindrop core has high values nearby, an empty area has low values nearby. This local smoothness is called coherence. The paper does not explicitly name or measure a single hidden quantity, but it implicitly assumes that local region processing and fine-scale upsampling preserve this coherence, keeping small-scale rainfall structures sharp instead of blurring them into soup.

The model estimates coherence by learning where to focus: the importance weights teach which neighbors matter most for each pixel. The upsampling decoder preserves coherence by using cubic interpolation, a method that keeps sharp transitions between values instead of averaging them flat. Together, these design choices measure and protect the texture information that makes rainfall forecasts honest.

Why it works

Why local region processing and cubic upsampling work

Global region processing treats every pixel as equally relevant to every other. Distant rainfall shapes the forecast of nearby pixels even though they should be independent. Local region processing forces the model to ignore distant regions, learning only true short-range relationships. This is efficient—fewer numbers to multiply—and more honest, because rainfall does not have magic long-range links.

The upsampling decoder faces a problem: the model compresses the image to a smaller size because processing every pixel is slow, then must expand it back to full resolution to make a prediction. Linear interpolation (the naive approach) averages nearby values, blurring fine details. Cubic interpolation uses curved instead of flat surfaces, preserving sharp transitions, because a curve can match both the value and the slope at the edges, keeping a rainfall core sharp instead of letting it spread into weak cloud.

Imbalanced training data biases the model. When extreme events are rare, the model learns to minimize error on the common case (light rain), predicting bland safe numbers. On a real storm, it still hedges. Balanced training forces the model to split its flexibility equally—some parameters specialize in ordinary patterns, others in extreme, none get left to atrophy. The paper's new KMA dataset explicitly pairs ordinary and extreme events, so every training step sees both.

Math after the picture

Equation: local attention scoring

First in words:

For each pixel, the model computes a score for each nearby neighbor and normalizes the scores to fractions that add up to 1. The output for that pixel is a weighted sum of nearby pixels, where pixels with higher scores contribute more.

Then the compact form:

output_i = sum_{j in local_neighbors(i)} attention_weight_{i,j} * value_j where: attention_weight_{i,j} = exp(score_{i,j}) / sum_k exp(score_{i,k})

Every symbol:

output_ithe forecast value at pixel i
score_{i,j}how much pixel i should care about neighbor j (learned by the model)
exp(...)exponential function; makes small scores bigger and negative scores small
sumadd them all up
attention_weight_{i,j}the fraction of neighbor j's value that goes into pixel i (always between 0 and 1)
value_jthe rainfall measurement or intermediate feature at neighbor pixel j
A tiny worked example
Pixel at position (row=5, col=5) has four local neighbors: north (3.0), south (2.5), east (4.0), west (1.5).
Model computes scores: north=0.5, south=0.2, east=1.0, west=−0.5. These are learned numbers.
Apply exponential: exp(0.5)=1.65, exp(0.2)=1.22, exp(1.0)=2.72, exp(−0.5)=0.61.
Sum them: 1.65+1.22+2.72+0.61 = 6.20.
Normalize to fractions: north=1.65/6.20=0.27, south=1.22/6.20=0.20, east=2.72/6.20=0.44, west=0.61/6.20=0.10.
Weighted sum: output = 0.27*3.0 + 0.20*2.5 + 0.44*4.0 + 0.10*1.5 = 0.81 + 0.50 + 1.76 + 0.15 = 3.22.
The east neighbor mattered most (0.44 weight) because its score was highest; west barely mattered (0.10 weight).

Local attention pools nearby pixels, emphasizing neighbors most relevant to the forecast. Cubic upsampling later preserves sharp transitions between such pooled values instead of blurring them.

What can go wrong

What can go wrong

Extreme events still rare after balancing. If the balanced dataset does not truly pair events equally, or if real-world extremes have patterns the dataset does not cover, the model can still struggle on an unseen type of storm.
Local attention misses true long-range motion. Some storm systems move as coherent wholes across the image. If the true forecast depends on a distant thunderstorm, purely local attention cannot see it. This is a trade-off for efficiency.
Cubic upsampling assumes smooth rainfall. Cubic interpolation works by fitting curves. If rainfall has sharp artificial discontinuities (e.g., radar gaps, sensor faults), the curve fitting can create false textures.
Done right. The model succeeds when training data is truly balanced, the local attention window is large enough to capture the real scales of rainfall variation, and the radar input is clean.
What a runnable demo should prove

What a runnable demo should prove

Build a minimal version: take a sample of balanced radar data (half ordinary, half extreme). Train a local-attention model on it for 50 epochs. On a held-out test set, measure the accuracy separately for ordinary and extreme rainfall. Compare to a baseline model trained on imbalanced data (10 percent extreme, 90 percent ordinary). The local model should maintain high accuracy on both; the imbalanced baseline should excel on ordinary but collapse on extreme.

extreme_accuracy = (number of correct extreme forecasts) / (total number of extreme test cases)

If the balanced-trained model stays above 70 percent on extreme events while the imbalanced baseline drops below 40 percent, the demo proves that data balancing and local attention together unlock forecasting of dangerous weather.
