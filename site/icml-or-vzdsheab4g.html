Pretrained Vision-Language-Action Models Resist Forgetting

Large pretrained robot models retain prior skills during new task learning because their foundation knowledge absorbs interference, unlike models trained from scratch.

Paper explainersAll themesRobotics & Control

A robot that learns new skills over time usually forgets the old ones—when you teach it a new task, its old skills fade away. This paper finds that big robot models trained beforehand (on general vision and language data first) do NOT have this problem. They learn new skills while keeping the old ones alive, and simple memory replay of old task examples makes this work remarkably well.

Zero assumption version

The catastrophic forgetting trap

Suppose you want to teach a robot a sequence of tasks: first how to pick up a cup, then how to grasp a ball, then how to open a drawer. If you train the robot from scratch on each new task by showing it examples and nudging its internal numbers (called weights), it tends to ruin what it learned before. The weights that made it good at picking up cups get overwritten. A naive fix is to keep replaying old task examples during new training—but this is expensive, and small models struggle anyway.

Earlier work on small robot models trained from scratch found the forgetting problem nearly impossible to solve. The question was: does the same disaster happen in big pretrained models? The answer turns out to be no—and that is surprising.

The paper's move in one sentence. Large pretrained robot models stay good at old tasks during new task learning because they have bedrock knowledge that does not get erased, and simple experience replay (holding onto old examples) is enough to keep old skills sharp.

The algorithm as a flow

What it actually does

Initialize from pretraining

Start with a model already trained on millions of images and language (like reading the internet). It already knows edges, shapes, common objects.

Train on task 1

Show the robot examples of task 1 (e.g., grasping). Nudge the weights to fit these examples. Some weights shift, but the foundation stays.

Replay + task 2

Save a small buffer of task 1 examples. When training on task 2, mix them in—the model sees both tasks every step.

Measure forgetting

Test how well the model still does task 1. Pretrained models lose very little accuracy; small models lose a lot.

Finetuning recovers lost skill

If a skill seems forgotten, show the model the old examples again. Pretrained models recover their peak in under 10 percent of original training steps.

What the paper changes

What changes: the foundation layers

The paper does not change the training algorithm. It keeps experience replay exactly as is. What actually changes is the weight initialization—the starting point. When you start from a pretrained model (weights learned from massive data), the core layers that handle vision and language stay firm and do not change much. When you update for new tasks, these foundation weights barely move. Small models trained from scratch have no such anchor, so new task training erases them.

the object it moves  =  Weight initialization (pretrained vs. random)
The hidden quantity

The hidden quantity: forgetting ratio

measured quantity  =  Normalized backward transfer (forgetting metric)

The paper measures a number called Normalized Backward Transfer (NBT): how much accuracy on the old task drops after learning a new task. If the old task stayed at 90 percent accuracy and falls to 80 percent, the forgetting is 10 percentage points. But different tasks have different max accuracies, so the paper normalizes: divide the drop by the original peak. That ratio is NBT. An NBT of 0 means zero forgetting (perfect old task retention). An NBT of 0.4 means you lost 40 percent of what you had gained.

The paper estimates NBT by testing the model on old task examples after each new task. Small replay buffers show the difference most clearly: pretrained models keep NBT near 0.1–0.2 even with tiny replay buffers (2 percent), while non-pretrained models degrade to NBT 0.4–0.5.

Why it works

Why pretraining stops forgetting

Here is the actual causal chain. A model trained from scratch starts with random weights. When you show it task 1 examples, it must carve out task 1 structure from noise. Every weight gets rewritten heavily to fit task 1. When task 2 arrives, the same weights must change again. But task 1 and task 2 are completely different (e.g., grasping vs. opening), so the changes wipe out task 1.

A pretrained model starts with weights already filled in by massive prior data (images, language, robot trajectories). The foundation layers (the early parts that recognize basic visual patterns) are already locked in by millions of examples. When you train on task 1, you only nudge the top layers that specialize in the task. When task 2 arrives, those top layers change again, but the foundation does not move much—it would take enormous amounts of task 2 data to overwrite it, because it was shaped by so much more prior data. So the foundation stays. Because the foundation stays, old task behaviors can survive: the model remembers the basic visual cues from task 1, even if the top layers shift. Adding experience replay (mixing old task examples into new task training) keeps the top layers aligned, so old task performance barely drops.

In short: pretraining creates a layer separation. The foundation is sticky (hard to change). The task-specific top layers are flexible. New training hits the top layers but bounces off the foundation. Task 1 memories live in the foundation, so they survive.

The forgetting penalty equation

First in words:

The model is penalized for each old task's performance drop; the penalty depends on how far that task's accuracy has fallen. For small models, this penalty makes new task training rewrite everything. For pretrained models, the foundation layers resist change, so the penalty for forgetting stays small even with less replay data.

Then the compact form:

Forgetting_penalty = sum_old_task (original_accuracy_t - current_accuracy_t) / original_accuracy_t

Every symbol:

original_accuracy_thow well the model did on task t right after learning it
current_accuracy_thow well the model does on task t now (after learning new tasks)
sum_old_taskadd up the losses across all previously learned tasks
Forgetting_penaltythe total accuracy lost (lower is better; zero is no forgetting)
A tiny worked example (two tasks, small model vs. pretrained)
Small model on task 1: reaches 90 percent accuracy. Store this as original_accuracy_1.
Small model learns task 2. Test task 1: now only 50 percent. Accuracy drop = 90 - 50 = 40 points.
Forgetting penalty for task 1 = 40 / 90 = 0.44 (about 44 percent of the original gain is lost).
Pretrained model on task 1: reaches 88 percent. After task 2: drops to 82 percent. Drop = 6 points.
Forgetting penalty for task 1 = 6 / 88 = 0.07 (only 7 percent lost).
Same task, same model architecture, same task 2 training data. Pretraining alone makes forgetting 6 times smaller (0.44 versus 0.07).

The equation sums drops across all old tasks. Pretrained models keep each drop small because the foundation layers stay stable, so the overall penalty is low and new task training does not need to erase the past.

What can go wrong

What can go wrong

Tiny replay buffer and small model still fail. If the buffer is too small (e.g., 10 examples per task) and the model is not pretrained, replay alone does not save you. You need both pretraining AND enough replay to keep the top layers from drifting too far.
Pretraining on unrelated data might not help. If the pretraining data is completely different from the robot tasks (e.g., if the foundation learns cats but the robot grasps objects), the foundation might not encode useful features for the new tasks. The paper uses vision-language models pretrained on broad internet data, which includes objects and actions, so it transfers well.
The model might recover quickly but not stay learned. When a skill seems forgotten, finetuning on old examples can bring it back fast (under 10 percent of original training steps). But if you keep learning new tasks without replay, the skill will fade again. Replay is not optional; it is the maintenance cost.
Done right: pretraining plus steady replay. Use a large pretrained vision-language-action model. Keep a small buffer of examples from all old tasks. Mix them into training for every new task. Old skills stay sharp, new skills learn fast, forgetting stays near zero.
What a runnable demo should prove

What a runnable demo should prove

Build a mini continual learning experiment on a simulated robot (or use a small dataset of real task video examples). Train a small model from scratch and a large pretrained model on three sequential tasks. After each new task, test on all old tasks. Measure the forgetting metric (accuracy drop as a fraction of original accuracy) for each old task. Vary the replay buffer size (2 percent, 5 percent, 10 percent, 20 percent of original task data). The demo must make it obvious that pretrained models lose far less accuracy than non-pretrained ones, especially at small buffer sizes.

The core finding: pretrained models keep NBT below 0.1 even at 2 percent replay, while small models blow up to 0.4 or higher. That single gap is the whole story—pretraining is the difference between remembering and forgetting.
