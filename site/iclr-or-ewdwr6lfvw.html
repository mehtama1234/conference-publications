Generate Any Scene: Scene Graph Driven Data Synthesis

Instead of hunting for good training images in the wild, systematically build them from a structured recipe (scene graphs) to teach models how parts fit together in complex scenes.

Paper explainersAll themesGenerative Models & Diffusion

Text-to-image models can draw pretty pictures, but they forget how to put the right objects in the right places. If you ask for a red dog on a blue chair, the model might put a blue dog on a red chair instead. The paper shows that the real problem is not the model architecture but the training data. Real training data is messy and weak at showing how pieces combine. The fix: automatically generate clean, structured training data by enumerating scene graphs (recipes that list objects, attributes, and their relationships), then asking the model to draw them and keeping the best examples.

Zero assumption version

The compositional gap

Text-to-image models (like Stable Diffusion) are trained on real images scraped from the internet with captions. These captions are loose and messy. If an image has a dog and a chair, the caption might say dog-chair-photo, and the model never learns to reason about color or position cleanly.

A beginner's naive fix: collect more data and hope the model learns. But that is expensive and slow. The real problem: when an image has many objects (a red dog, a blue chair, a green tree), the caption almost never mentions all their properties and relationships precisely. So the model never sees that combination before and fails at test time, because it has not learned to connect red-dog-blue-chair as a single coherent pattern.

The paper's move. Build a data machine that generates perfectly clean training images from a structured recipe (a scene graph saying 'object A with color X next to relation Y object B'), ask the model to draw it, and keep the examples where the model drew it right, so the model learns from its own best attempts. This works because the model memorizes patterns it has seen clearly many times, and these clean examples show each pattern without noise or contradiction.

The algorithm as a flow

What it actually does

Build a taxonomy

Collect 28,787 object types, 1,494 colors/attributes, 10,492 spatial relations from sources.

Enumerate scene graph structures

Systematically generate all valid combinations: how many objects, which relations connect them.

Populate with metadata

Sample objects, colors, attributes, and relations to fill each structure.

Translate to captions

Convert each scene graph deterministically into a natural sentence (e.g. 'red sphere left of blue cube').

Generate images and score

Ask the model to draw from the caption, grade each image (does it match the recipe?), keep top 25%.

What the paper changes

What the model learns from

The paper changes the training dataset: from messy real captions to clean synthetic captions generated from scene graphs. Each synthetic caption is precise (says exactly which object has which color and position), and each image in the training set is an example where the model drew the scene correctly (was graded by a checker that reads the caption and verifies the image).

The hidden quantity

Compositional alignment

measured quantity  =  how well colors and positions match the caption

This is the gap the paper measures: does the model actually put the red object on the blue object as the caption says, or does it mix colors? The paper introduces a hidden quantity called compositional alignment: for each scene graph, the model should generate an image where every object, color, attribute, and spatial relationship matches exactly.

The paper estimates this by converting each scene graph into a set of visual question-answer pairs (e.g. 'What color is the sphere?' 'Red') and automatically grading the generated image by answering those questions. A high score means the image matches the recipe. The paper uses these scores to select the best training examples and also as a reward signal in reinforcement learning (GRPO, a method that nudges the model toward high-scoring generations).

Plain reading. The hidden quantity is: when the model draws a scene, how many objects, colors, and positions does it get right compared to the recipe?
Paper reading. The paper calls this compositional fidelity or semantic alignment (TIFA score, DPG-Bench metrics). It is measured by converting scene graphs to VQA (visual question-answer) pairs and automatically grading generated images against those answers.
Why it works

Why clean recipes teach composition

The core mechanism is simple: if you show the model an image where a red sphere is always left of a blue cube, the model learns to connect the concepts (red, sphere, left, blue, cube) together in that specific way. When the model sees these combinations only in messy, incomplete real captions (sometimes red-sphere, sometimes sphere-left, never all three together clearly), it cannot build these strong connections. It learns red separately from left separately from sphere, so when you ask for all three together at test time, it guesses and gets it wrong.

By systematically generating all valid combinations (red sphere left of blue cube, red sphere right of blue cube, blue sphere left of red cube, etc.) and filtering to keep only the examples where the model drew it right, the paper is essentially showing the model: here is every compositional rule we care about, and here is an example where you got it right. The model then fine-tunes on these examples and locks in the associations. This works because each synthetic example is pure: no noise, no missing information, no contradictions.

Math after the picture

Grading the alignment

First in words:

alignment_score = (count of correct objects plus positions plus colors plus relations) divided by (total elements in scene graph) times 100

Then the compact form:

alignment_score = (correct_objects + correct_positions + correct_colors + correct_relations) / total_elements * 100

Every symbol:

correct_objectsnumber of objects drawn in the image that match the scene graph
correct_positionsnumber of spatial relationships (left, right, above, below) placed correctly
correct_colorsnumber of object colors that match what the scene graph says
correct_relationsnumber of semantic relations (touching, supporting, inside) that match
total_elementssum of all objects, positions, colors, and relations in the scene graph
alignment_scorefinal grade from 0 to 100 (100 means perfect match)
A tiny worked example
Scene graph: red sphere (left of) blue cube on a table.
Generated image: red sphere is there (1), blue cube is there (1), red is correct color (1), blue is correct color (1), left-of relation is there (1), on-table relation is there (1).
Total elements in graph: 2 objects + 2 colors + 2 relations = 6.
Score: (1 + 1 + 1 + 1 + 1 + 1) / 6 * 100 = 6 / 6 * 100 = 100 (perfect).
Compare: if the model had drawn blue sphere and red cube (colors flipped), score would be (1 + 1 + 0 + 0 + 1 + 1) / 6 * 100 = 4 / 6 * 100 = 67 (keep it, it's good but not perfect).

The score determines which generated images are kept for training. Only the top 25% (highest alignment scores) become part of the fine-tuning dataset. This works because training on low-quality examples teaches the model bad associations (e.g., sometimes red with blue objects), so filtering to the best examples ensures clear, consistent learning.

What can go wrong

What can go wrong

The taxonomy is incomplete or biased. If the 28,787 object types or 1,494 attributes do not cover your domain (e.g., you care about medical images), the engine will not generate the right scene graphs. The combinations will be useless.
The model draws well on synthetic data but not real. Because synthetic captions are perfect and uniform (all captions follow the same template), the model might overfit to the synthetic style and fail on messy real text (e.g. casual conversation captions). This is a domain shift problem.
The grading is weak. If the VQA-based grader that scores alignment is not accurate, the model will learn from mislabeled examples. For instance, if the grader says a red sphere is blue because it is in shadow, the model learns the wrong association.
Done right: start small. Begin with a narrow taxonomy (e.g., 100 objects, 50 attributes, 50 relations) in your domain, verify the grader on a few examples by hand, and slowly expand. The paper's 28K objects work for general vision but may not suit your task.
What a runnable demo should prove

What a runnable demo should prove

Build a small data engine: define a tiny taxonomy (10 objects like cube, sphere, cylinder; 5 colors like red, blue, green; 3 relations like left-of, above, inside). Generate 100 scene graphs by randomly sampling objects, colors, and relations. Translate each to a caption (e.g. 'A red cube is left of a green sphere'). Use an existing text-to-image model (like Stable Diffusion v1.5) to generate one image per caption. Grade each image: check if the objects, colors, and positions match the caption (manually or with a vision model). Keep the top 50 images. Fine-tune Stable Diffusion on those 50 images for one epoch. Then test on a held-out set of new scene graphs and measure composition accuracy before and after.

composition_accuracy = (images where all object colors and spatial relations match the caption) / (total test images) * 100

The demo must show that fine-tuning on synthetic high-quality examples measurably improves the model's ability to place objects and colors in the right places compared to the baseline, because the clean examples teach strong associations that the model can reuse in new combinations.
