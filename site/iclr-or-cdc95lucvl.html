Modality-Free Graph In-context Alignment

A pretrained graph model learns to adapt to new data domains using just a few examples, without changing its weights.

Paper explainersAll themesGraph & Geometric Learning

Graph models built to handle all kinds of networks face a tough problem: when data comes pre-encoded or locked away, they cannot adjust to new domains. This paper introduces MF-GIA, a system that teaches a frozen graph model to recognize the characteristics of any new domain by measuring how it would naturally learn, then uses that fingerprint to align features and labels, enabling accurate few-shot prediction without any weight updates.

Zero assumption version

Graph models get stuck when data is hidden

A typical graph model learns from many graphs during training, building a fixed encoder that works for all of them. When you later ask it to work on a new domain it has never seen — especially one that is pre-encoded or locked away — it fails. The encoder was tuned to the old domains and cannot bend to fit new territory. A beginner might try adding more training data, but that does not help if the new domain's raw data is kept private for security or business reasons. Another naive approach would be to ask for the raw graph structure and features so the model can learn, but in practice, data owners release only pre-computed lists of numbers (called embeddings), not raw graphs, because that is faster and uses less storage.

The constraint is real: you have a frozen pretrained model, a handful of labeled examples from the new domain, and nothing else. You cannot change the weights. You cannot retrain. You need the model to adapt from those few examples alone.

The paper's move. MF-GIA teaches the model to recognize each domain by its own learning signal, then uses lightweight transformations to shift features and labels into a shared semantic space, so the frozen encoder can classify new queries without any weight update.

The algorithm as a flow

What it actually does

Compute the fingerprint

Take one learning step on the new domain's few examples; measure how weights would change; that change is the fingerprint.

Recognize the domain

Feed the fingerprint through a small pretrained network that learned domain relationships.

Align features

Apply a lightweight learned transformation that rotates pre-encoded item features into a shared space.

Align labels

Apply a second transformation to the class labels so they sit in the same shared space.

Match and classify

Find which support example is closest to each query in the aligned space, then predict its class.

What the paper changes

What the paper changes

The paper does not update the encoder weights. Instead, it changes two things: first, it computes lightweight per-domain transforms (learned rotation and shift coefficients) that rotate item features and class labels into a unified space; second, it activates a fixed matching mechanism to find the closest support examples in that aligned space. The frozen encoder stays frozen. Only the alignment coefficients and matching are applied.

the object it moves  =  alignment transform and matching
The hidden quantity

The hidden quantity: gradient fingerprint

measured quantity  =  gradient fingerprint

The gradient fingerprint is the set of weight changes the model would naturally make if it took one learning step on the new domain. It is a compressed summary of what the domain 'wants' the model to learn. Because different domains steer learning in different directions, their fingerprints look different, and the model can recognize the domain by its fingerprint alone.

The paper estimates this by taking one learning step at a fixed small rate (0.01) on the few labeled examples, computing how much each weight shifted, and passing that shift pattern through a small pretrained network that learned to map fingerprints to alignment settings. This is a clever trick: instead of asking 'what is this domain?', it asks 'what would this domain teach me?', and that answer fully describes the domain.

Why it works

Why matching aligned examples works

The frozen encoder extracts features from each graph node, but those features are tuned to the old training domains. When a new domain arrives, its features are misaligned: a node that looks 'red' in domain A might be useless in domain B. Different domains steer learning in different directions because they have different structure and class patterns. By measuring that direction (the fingerprint), you learn what the domain would naturally learn, and you can use that knowledge to rotate the features and labels into a shared space where comparisons between old and new data become reliable.

Once features and labels are rotated into the shared space, the model finds the support examples most similar to each query by measuring distance. Because everything is now in the same coordinate system, distances are fair, and the model predicts by classifying each query as nearest to one of the few labeled examples. This happens entirely in the rotated space; the encoder weights never change.

The alignment formula

First in words:

For each feature, apply a learned rotation and shift that depends on the domain. The rotation is computed from the gradient fingerprint. The same pattern applies to labels.

Then the compact form:

aligned_feature = gamma_feat * base_feature + beta_feat

Every symbol:

gamma_featlearned rotation magnitude for features (from domain embedder)
beta_featlearned shift for features (from domain embedder)
base_featurethe frozen encoder's output for this node
aligned_featurethe rotated feature in the shared semantic space
A tiny worked example
Domain A fingerprint: [0.2, -0.1, 0.05]. Domain embedder outputs gamma_feat=1.5, beta_feat=0.3.
Node feature from encoder (base): [2.0, 4.0]. After alignment: 1.5 * [2.0, 4.0] + 0.3 = [3.3, 6.3].
Domain B has different fingerprint [0.1, 0.3, -0.02], so its embedder outputs gamma_feat=0.8, beta_feat=-0.2.
Same node feature [2.0, 4.0] becomes: 0.8 * [2.0, 4.0] - 0.2 = [1.4, 3.0].
Two domains rotate the same feature differently because their fingerprints tell them to. Now features from both domains sit in a common space where matching can fairly compare them.

The rotation settings come directly from the domain's fingerprint, so each domain gets the alignment it needs without any weight update.

What can go wrong

What can go wrong

Noisy fingerprint with tiny support sets. If there are very few labeled examples, the gradient step is unreliable and the fingerprint is noisy. The domain embedder may misrecognize the domain.
New domain too far from training domains. If the new domain is drastically different from anything in pretraining, the domain embedder has no learned knowledge to guide it. Alignment may fail.
Modality shift in features themselves. If pre-encoded features are corrupted, compressed, or in a completely different scale, one gradient step may not be enough to characterize the domain.
Done right. MF-GIA works well when: pretraining covers diverse domains so each one leaves a distinct fingerprint, new domains resemble something in pretraining so the embedder recognizes them, and pre-encoded features still carry semantic signal.
What a runnable demo should prove

What a runnable demo should prove

Build a mini few-shot graph classification task. Pretrain MF-GIA on several graph domains (e.g., citation networks and social networks). Then freeze everything and test on a new held-out domain, giving only a few labeled examples per class. Measure classification accuracy and compare against a baseline that uses the frozen encoder without alignment. The demo should show two things: first, that computing the gradient fingerprint and using it to align features and labels lifts accuracy from 40% to 75% or higher with just a handful of examples, because alignment makes old features useful in the new domain; and second, that the model works on unseen domains without changing weights.

few_shot_accuracy = (correct_predictions / total_new_domain_queries) * 100

A single learning step on a new domain tells you everything you need to know to align an old model to it.
