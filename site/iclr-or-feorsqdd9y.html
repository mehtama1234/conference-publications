Tsetlin Machines: from 2-bit to k-bit convergence

Tsetlin Machines learn patterns by flipping automaton states, and this paper proves they will converge to the right answer even when the data is noisy or has extra irrelevant variables.

Paper explainersAll themesLearning Theory

A Tsetlin Machine is a simple learning algorithm that builds patterns the way a committee votes: each automaton is a tiny voting machine that learns to flip its opinion or stay put based on what it sees. This paper proves mathematically that these simple voting machines will reliably learn 2-bit patterns (like AND, OR) and generalize to any size pattern, even when mistakes or noise are present.

Zero assumption version

Machines need to learn patterns from messy data

A machine learning algorithm needs two things: a way to represent patterns (like AND, OR, XOR), and proof that it will actually learn the right pattern even if the data has mistakes or noise. A naive approach is to try every possible rule and pick the best one, but this gets slow fast as patterns get bigger.

Before this paper, Tsetlin Machines had convergence proofs only for tiny cases: patterns involving single bits or 2-bit XOR. No one had proven the machine would learn 2-bit AND or OR correctly, let alone general k-bit patterns. Worse, no one had proven it would work when the training data contains mislabeled examples or irrelevant variables.

In one sentence. This paper proves Tsetlin Machines will converge to the correct pattern for any size k-bit logic problem, even with noise in the data.

What the paper changes

The thing that changes

The Tsetlin Machine changes the internal states of its automaton voters. Each automaton has a state (representing its opinion), and during training, the algorithm flips some automata to new states based on whether they voted correctly or incorrectly. Over time, these state flips converge to a stable configuration that encodes the learned pattern.

the object it moves  =  automaton states
The hidden quantity

How do we measure learning progress?

measured quantity  =  convergence to correct states

The hidden quantity is whether the automata have settled into the states that make them vote for the true pattern. In plain terms: we cannot directly measure this while learning is happening. Instead, we track whether the automata's states are drifting or stable—are they still flipping wildly, or have they stopped moving?

The paper proves convergence by showing that once the automata reach the correct states, a mathematical measure of their likelihood of being wrong shrinks toward zero. This is why we call it convergence: the states stop wandering and lock in.

Why it works

Why the automata converge to the right answer

The mechanism is a feedback loop. When the true data says AND should output true, only automata in certain correct states can vote yes, so the algorithm rewards staying in those states. When the true data says AND should output false, automata in the correct false-voting states are rewarded. This asymmetry is key: the algorithm tips the odds in favor of correct states.

Under noise-free training, this feedback is clear, and automata converge almost surely (a mathematical term meaning with certainty). Under noisy training (mislabeled examples), some examples send the wrong signal, but the math still holds because correct examples outnumber wrong ones, so the drift toward correct states is stronger than the drift away. Irrelevant variables (extra inputs that don't matter for AND or OR) do not break convergence because they do not affect which states are rewarded—the reward depends only on the true output, not on noise.

Math after the picture

The convergence guarantee

First in words:

For each automaton, the probability that it remains in a wrong state shrinks exponentially as we see more training examples.

Then the compact form:

P(wrong state at time t) <= c * exp(-lambda * t) for constants c, lambda > 0

Every symbol:

tnumber of training examples seen so far
P(wrong state)probability that this automaton is in the wrong state
ca constant depending on the pattern size
lambdahow fast states converge (faster for noise-free, slower for noisy data)
exp(-lambda * t)exponential decay, getting smaller and smaller
A tiny worked example
Suppose lambda = 0.1 and c = 1.
After seeing t=10 examples: P(wrong) <= 1 * exp(-0.1 * 10) = exp(-1) = 0.368, about 37% chance.
After seeing t=20 examples: P(wrong) <= 1 * exp(-0.1 * 20) = exp(-2) = 0.135, about 14% chance.
After seeing t=50 examples: P(wrong) <= 1 * exp(-0.1 * 50) = exp(-5) = 0.0067, less than 1% chance.
The probability goes to zero; automata almost surely reach the correct state.

The math proves that the longer we train, the smaller the chance an automaton is still in the wrong state—it converges.

What can go wrong

What can go wrong

Mislabeled data blocks exact convergence. If a fraction of training examples have the wrong label, the automata will converge to states that mostly work but sometimes vote wrong—because they are chasing contradictory signals. Exact convergence to all-correct requires clean data.
Very noisy patterns are slow to learn. If the true pattern is buried in a lot of noise (many irrelevant variables), the automata still converge, but it takes longer because the signal is faint.
Irrelevant variables do not help, only slow. Extra input bits that do not affect the AND or OR operator do not prevent convergence, but they do dilute the training signal, making learning slower.
Done right: clean data with relevant variables. When the training data is correct and inputs are mostly relevant, Tsetlin Machines converge reliably to the true pattern.
What a runnable demo should prove

What a runnable demo should prove

Build a Tsetlin Machine to learn a 3-bit AND pattern: output true only when all three inputs are true. Train it on 1000 randomly generated examples (inputs and correct outputs). Then test it on 100 new examples not seen during training. The demo should show that after enough training rounds, the automata converge and the machine labels all 100 test examples correctly.

test accuracy = (number of correct predictions on 100 new examples) / 100

The test accuracy should reach near 100% and stay there, showing convergence has held—the automata learned the AND rule reliably.
