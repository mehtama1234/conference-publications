Learning well from limited or offline data

Training agents effectively using only recorded data without interaction, or learning efficiently from a small amount of experience, which is crucial when real-world trials are expensive.

What this is

Normally, reinforcement learning is active: the agent tries actions, sees outcomes, and tries more. But sometimes you can't interact. Medical treatments have to be chosen carefully — you can't run many trials on a patient. Robots might learn from videos of human workers, without being able to recreate those exact situations. Data is expensive or dangerous. Offline reinforcement learning asks: how can you learn from only recorded data, without real-time interaction?

The trap is that the recorded data reflects old decisions: whoever collected it chose certain actions and avoided others, so the learner has limited coverage. A new action the agent wants to try might be completely absent from the data. The learner can't directly observe what happens if you do that action. Papers here use techniques like conservative learning — the agent sticks close to actions that appear in the data and avoids wild extrapolation — or data augmentation, where the agent learns a model and simulates new scenarios. Some papers also address batch reinforcement learning, where the agent gets a fixed batch of data and must get the best policy it can.

This is essential for domains where trial-and-error is too expensive: medical therapy planning, autonomous vehicle safety testing, robotic surgery, and learning from human demonstrations.

How the work breaks down

Learning from offline data splits into five directions based on the core challenge: handling long sequences where actions matter in context, building accurate models of the world, reaching distant goals from limited trajectories, keeping updates conservative to avoid bad extrapolation, and generating new trajectories by synthesis. Each direction tackles a different bottleneck in learning without real-time interaction.

Sequence-aware critics for long horizons

In offline learning from recorded data, long sequences are hard because the value of an action depends on what comes next. A single action in isolation tells you nothing—you only know if it was good by seeing the full chain of outcomes it led to. Standard reinforcement learning methods estimate value one step at a time, which makes them accumulate errors over long trajectories because errors compound. The goal is to estimate value by understanding sequences of actions and states together, not just isolated steps.

Chunking the Critic builds a critic (the neural network that predicts value) using a Transformer (a sequence-modeling architecture that attends to multiple positions simultaneously, the same pattern that powers language models). The Transformer sees the recent history of states and actions, so it can predict value by looking at patterns in the sequence, not guessing blindly from a single state. On long control tasks, this simple sequence-aware approach beats standard methods by a large margin. Peak-Return Greedy Slicing takes a different angle: instead of learning from full trajectories, it finds the best segments (subtrajectories) within the recorded data and trains on those. If your offline dataset contains both good and bad episodes, this method extracts only the segments that led to high returns, like finding the most useful passages in a book and memorizing those instead of memorizing random sections. This improves Transformer-based offline RL across benchmarks. Transitive RL addresses the error-compounding problem head-on by using a divide-and-conquer strategy: it breaks the long trajectory into overlapping chunks, estimates value within each chunk, and then builds the full value estimate by combining the chunks. This reduces error accumulation from growing linearly with trajectory length to growing logarithmically, so errors stay small even on very long sequences. On challenging long-horizon tasks, this beats both temporal difference (which updates one step at a time) and Monte Carlo (which waits for the full trajectory) methods.

Model-based offline RL

One approach to offline learning is to build a model: learn what happens when you take an action (what the next state will be and what reward you get). Once you have an accurate model, you can simulate new trajectories from it, generating data that does not exist in the original offline dataset. The challenge is that your model is never perfect, so simulated trajectories can drift into regions the model has not seen before, where predictions become increasingly wrong. Model-based methods must be conservative about what they learn from their own simulations.

Model-based Offline RL via Value-Aware Model Learning uses weighted loss (each model prediction is weighted differently based on how reliable it is) to make the model-learning step adaptive. Parts of the model that predict accurately get higher weight, and parts that are uncertain get lower weight. This adaptive weighting prevents the model from confidently predicting in regions where it has no training data, keeping simulations grounded in what the model actually knows. Because the method prevents overconfident predictions in unknown regions, it avoids the common failure where simulated trajectories drift into hallucinations, so it outperforms prior model-based methods by a clear margin on standard offline benchmarks. DEAS (DEtached value learning with Action Sequence for Scalable Offline RL) separates value learning from action sequence generation: it learns what actions to take using a sequence model (like a language model predicts the next word), and separately learns a value function to evaluate trajectories. By decoupling these, it handles long-horizon tasks and can even enhance real-world robot learning. Bidirectional Trajectory Generation with Diffusion Models generates new trajectories using a diffusion model (a generative model that starts with noise and gradually denoises it into a sample). The diffusion model is bidirectional—it can generate trajectories forward in time and also backward, which helps it recover the full trajectory connectivity. By adding both forward and backward paths, it reconstructs more complete trajectory information than one-directional methods, improving data augmentation quality. Offline RL with Generative Trajectory Policies takes trajectory generation further by training a generative model (a model that samples new trajectories) jointly with the policy, so the policy can both choose which trajectories to generate and learn from them. This achieves near-perfect scores on hard navigation benchmarks where traditional methods struggle.

Goal-reaching and multi-step value estimation

Many offline tasks are goal-reaching: the agent must reach a target state (position, configuration) rather than maximize a cumulative reward. In these settings, the value function must handle the fact that actions contribute value in a delayed way—an action is good if it moves you closer to the goal, even if the immediate next state does not look obviously good. Multi-step value estimation tries to look multiple steps ahead to capture this delayed signal.

Dual Goal Representations learns two separate representations (ways of encoding the goal and current state) and switches between them when it is most useful. One representation might excel at nearby goals; the other at distant goals. By having both, the agent can recognize progress toward far-away targets that would be missed by a single representation, so it improves goal-reaching on 20 navigation benchmarks where single-representation methods miss progress. Decoupled Q-Chunking breaks trajectories into chunks and learns the value of each chunk independently, then combines them to get the full trajectory value. It does not treat chunks as a simple sum—it handles the dependencies between chunks so that the value of one chunk affects how you estimate the next, which matters because the last chunk you take depends on what you did in earlier chunks. Because it preserves these dependencies, it avoids the common pitfall where naive chunking treats chunks as independent and leads to inconsistent value estimates and sub-optimal behavior. Chunk-Guided Q-Learning learns multi-step returns (looking ahead 2, 3, or more steps) using guidance from action chunks (grouping actions together). By treating multi-step returns as a first-class problem and using chunks as a guide, it achieves tighter bounds on how good the value estimate is than methods that just stack single-step temporal difference updates.

Conservative learning and value bounds

The core danger in offline learning is extrapolation: if you train on data containing mostly walking-forward behavior, and the algorithm wants to try jumping, it has no data to learn from. So it guesses, and the guess is often wildly optimistic about what would happen. Conservative learning methods deliberately stay pessimistic: they assume unknown actions are bad unless proven otherwise. This prevents the algorithm from chasing hallucinated mirages in regions with no training data.

Less Is More: Clustered Cross-Covariance Control shows that you can bound value estimates using covariance (how much predictions vary) with a clustering approach. By grouping similar states together, the method estimates how much uncertainty exists in each region and uses that uncertainty to make pessimistic value estimates that avoid extrapolation errors. Because pessimistic estimates prevent hallucination, this achieves up to 30 percent improvement over prior methods, especially with small datasets where uncertainty is high. Peng's Q(lambda) for Conservative Value Estimation extends a classical RL algorithm (Peng's Q-learning, which mixes different time horizons) to the offline setting by adding conservative bounds. It estimates value using multiple lookahead depths (1-step, 2-step, etc.) and combines them pessimistically so that the final estimate errs on the side of caution. By looking at multiple horizons and staying conservative, it consistently beats single-step methods by a significant margin on benchmark tasks. Adaptive Scaling of Policy Constraints automatically adjusts how conservative to be based on the dataset and the current policy. Different tasks need different levels of caution because a task with dense data has less risk of extrapolation, so it can afford to be less conservative, whereas a task with sparse data needs more caution to avoid hallucination. Because it adapts the conservatism to the data, a single hyperparameter outperforms fixed-conservative methods and requires less per-dataset tuning. AdamO is an optimizer (the algorithm that updates network weights) designed specifically for offline RL. Standard optimizers like Adam assume you will get new data and can correct mistakes, but offline RL has only one pass through the data. AdamO prevents the common failure mode where the optimizer diverges and breaks the policy by suppressing some of Adam's adaptive scaling when it would be destabilizing, which improves stability and returns on offline RL tasks.

Trajectory synthesis and diffusion-based generation

Instead of just learning from existing trajectories, you can generate new trajectories using a learned model. Diffusion models and flow-based models are generative models that gradually transform noise into samples. Applied to offline RL, they can generate plausible trajectories that stay in-distribution (similar to the training data) while exploring promising regions. This augments the dataset without leaving the data it has learned well.

SAC Flow combines Soft Actor-Critic (a standard RL algorithm) with flow-based trajectory generation. Flow models gradually transform data through deterministic steps, which is faster and simpler than diffusion. By coupling the policy learning with flow-based generation, it learns efficiently and eliminates the need for distillation (training one network to mimic another), reducing computational overhead. On manipulation benchmarks, it achieves the best performance with lower latency. Flow Matching with Continuity Constraints uses flow models to generate trajectories but adds a penalty that keeps trajectories smooth and continuous (meaning trajectories do not have abrupt jumps or kinks), so generated trajectories stay smooth and realistic. It balances staying close to the training data with maintaining smoothness, which prevents the generated trajectories from being unrealistic even though they are plausible. Accelerating Diffusion Planners in Offline RL via Reward-Aware Consistency Trajectory Distillation speeds up diffusion-based planning by distilling trajectories (training a fast network to mimic the slow diffusion process). By making the distilled network aware of rewards, it learns to only simulate actions that lead to high returns, achieving large speedups (142x faster than the diffusion model) with accuracy gains. Flow Actor-Critic for Offline RL extends the idea to the full actor-critic framework (policy and value function) using flow models, achieving top performance on complex long-horizon benchmarks. ReFORM (Reflected Flows for On-support Offline RL) explicitly constrains generated trajectories to stay on-support (similar to the training data distribution) by reflecting flows when they drift away. This maintains performance across datasets of varying quality without retuning hyperparameters.
