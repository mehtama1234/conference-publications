SWING: Implicit Graph Random Features

Instead of building a full graph and walking on it, SWING walks in the continuous space where the graph lives, using smart sampling to count walks without ever materializing the graph.

Paper explainersAll themesGraph & Geometric Learning

Graphs that define edges by similarity (like connecting nearby points in a high-dimensional space) are useful but expensive: you need to build the entire graph to analyze it. SWING solves this by never building the graph at all. Instead, it walks in the continuous space where the nodes live, using a sampling technique that accurately counts paths without materializing a single edge.

Why implicit graphs are a bottleneck

In machine learning, a graph is often defined implicitly: two nodes connect if their feature lists (a list of numbers describing each node) are closer than some threshold, or if their similarity score exceeds a cutoff. These epsilon-neighborhood graphs are everywhere — they define how nearby examples relate in feature space.

The naive approach: compute every pairwise distance, build the entire graph, then run algorithms (counting random walks, computing edge-weight functions) on it. This breaks when the graph is huge. Building and storing all edges is prohibitively expensive.

Graph random features are a tool for fast approximations: instead of using the full graph, sample a few random walks and use them as a summary. But random walks require the graph to exist in memory first.

The core problem. You cannot run graph algorithms on implicit graphs without first materializing them, which is expensive or impossible at scale.

The algorithm as a flow

What it actually does

Step 1: Skip the graph

Never compute or store edges. Work only with the lists of numbers describing each node.

Step 2: Define walks in the feature space

A walk between nodes is a sequence of steps through the continuous space where nodes are located.

Step 3: Pick the next node with smart probabilities

At each step, sample the next node using a method that picks closer nodes more often, with correct weights.

Step 4: Importance weight each path

Some paths are more likely than others. Adjust the count to reflect this bias.

Step 5: Approximate graph features

Add up the weighted paths to approximate the result you would get from a full graph walk.

The hidden quantity

The hidden quantity: path weight accuracy

measured quantity  =  Path weight bias

When you sample random walks instead of enumerating all of them, each walk has a probability of being selected. If you count each sampled walk equally, you introduce bias: walks that are naturally rarer appear too often in your sample, and common walks appear too seldom.

SWING measures this bias (the mismatch between a path's true probability and how often it appears in a sample) using importance sampling, a technique that reweights each sampled path to correct for its selection probability. This is the hidden quantity that determines whether the approximation is accurate.

Why it works

Why it works: the causal chain

Here is how it works: an implicit graph (defined by a similarity or distance threshold) is really just a view of the feature space under a particular threshold. Walking on the graph is equivalent to stepping through the continuous space while respecting the implicit edge rule.

Instead of enumerating all edges (expensive), SWING samples a sequence of steps in the continuous space. Each step uses a smart sampling trick to pick the next node, favoring neighbors that are closer (more similar). Because the space is continuous, SWING can compute everything on the fly without storing edges.

The catch: not all sampled walks are equally representative of the true graph. SWING corrects for this by weighting each walk by its importance (how likely it was to be sampled under the method's sampling scheme). This importance-weighting step, grounded in Fourier-space analysis of the kernels, ensures the final count matches what you would get from walking on the full graph.

Why this matters: the whole computation stays in the feature space and on the accelerator (GPU), never materializing the graph. For huge graphs, this is orders of magnitude faster, because materializing a graph with millions of edges requires allocating memory for all of them upfront and copying them to the GPU — SWING avoids this allocation and memory-transfer step entirely, computing only the walks you actually need.

Math after the picture

The math: counting weighted walks

First in words:

Path count with importance weighting = sum of (1 / sampling probability for this path) times (indicator that this path was sampled)

Then the compact form:

G(x,y) approx sum_i w_i * I(path_i sampled) where w_i = 1 / P(path_i)

Every symbol:

G(x,y)value of graph feature between nodes x and y
path_ithe i-th sampled walk from x
I(path_i sampled)1 if walk i was picked, 0 otherwise
w_iimportance weight for walk i
P(path_i)probability that walk i is sampled using the smart sampling method
A tiny worked example
Suppose a true walk between nodes A and B has 3 possible intermediate steps.
Walk 1 (direct): P = 0.5, appears 2 times in our sample of 10. Weight: 1/0.5 = 2.0. Contribution: 2.0 * 2 = 4.0.
Walk 2 (indirect): P = 0.25, appears 1 time. Weight: 1/0.25 = 4.0. Contribution: 4.0 * 1 = 4.0.
Walk 3 (rare): P = 0.25, appears 0 times. Contribution: 0.
Unweighted sum: 3 paths in sample. Weighted sum: 4.0 + 4.0 = 8.0. True total: 10. (This is simplified; in practice you use many more walks and the Fourier structure handles the computation.)

Importance weighting corrects the sample so that walks sampled with low probability get higher weight, making the approximate total close to the truth.

What can go wrong

What can go wrong

Poor sampling accuracy. If the sampling method does not accurately reflect the true next-step probabilities (e.g., threshold for similarity is too harsh), the importance weights become very large and the approximation fails.
High-dimensional feature spaces. In very high dimensions, nearest-neighbor structure becomes unstable (the curse of dimensionality). SWING's accuracy depends on the feature space being reasonably well-behaved.
Not enough samples. With too few walk samples, rare but important paths are never picked, and importance weighting cannot correct for them. The approximation error grows.
Done right. Choose the walk length, number of samples, and similarity threshold carefully. Validate the approximation error on a test case where you can afford to materialize the full graph.
What a runnable demo should prove

What a runnable demo should prove

Build a small graph on 1,000 nodes where you can afford to materialize the full graph. Compute a standard graph statistic (e.g., the sum of all 2-hop reachability probabilities) both ways: naively (walk on the full graph) and using SWING (sample walks in the space of learned features). Measure the relative error.

relative error = |SWING estimate - full graph truth| / |full graph truth|

The demo should make it impossible to miss that SWING's estimate stays within 5-10% of the truth while using 100x less memory.
