Value Matching: Scalable Reward-Guided Flow Adaptation

Instead of burning memory retraining the whole model, learn one lightweight value function that tells the model which direction to steer generation to earn higher rewards.

Paper explainersAll themesGenerative Models & Diffusion

Large diffusion and flow models excel at generating images and molecules, but steering them toward specific rewards (like realistic images or stable molecules) requires retraining the entire billion-parameter model—a huge memory burden. This paper offers a smarter approach: learn one small auxiliary function that scores how good a partial generation is, then let the model use that score to decide which direction to nudge next, without touching the original weights.

The memory wall of steering giant models

Diffusion and flow models work by gradual refinement: start with noise, and at each step add a bit more detail. To make the model generate images that satisfy some goal (like photorealism or toxicity) requires reward optimization—adjusting the step-by-step process to maximize the reward.

The naive approach: take the billion-parameter model, run it forward and backward computing how to adjust each weight to shrink the error. This demands enormous graphics-card memory, scaling directly with how complex the model is. For a 6-billion-parameter model, that's crushing overhead.

Existing shortcuts like Classifier Guidance sidestep the memory problem by learning a small auxiliary classifier offline and then using its scores to tweak generation. But this approach fails badly: the classifier was trained on a fixed dataset, so it struggles when the model tries to explore new regions it has never seen; and classifiers often cannot express complex, task-specific rewards.

The core problem. How do you steer a giant generative model toward high rewards without retraining it, and without being locked into what your training data showed?

What it actually does

Start with noise

Initialize a random image or molecule.

Query the value function

Ask the value function to score the current partial image, because higher scores mean this state is on a path to high final reward.

Steer the generation

Use the value score to bias the model's sampling toward high-reward directions.

Repeat on new data

At each generation step, ask the value function again—this explores regions the old training data never saw.

Collect experience and update

When trajectories finish, check their actual reward, then tell the value function whether its predictions were right, so it learns to recognize high-reward paths.

What the paper changes

The single thing the paper changes

Instead of modifying the giant generative model itself, the paper adds a separate small neural network—the value function—that learns one thing: how good is each intermediate generation state (how likely is it to end up with high reward)? This value network becomes the steering wheel; the original model stays frozen.

the object it moves  =  value function
The hidden quantity

The hidden quantity: value

measured quantity  =  The value estimate

Value, in this context, is a single number that answers: given that we are partway through generating an image or molecule with a certain set of pixels or atoms, what is the expected reward we will earn if we finish optimally from here? It is not the final reward itself—that only comes at the end—but a prediction of what we will get.

The paper learns this by running generation trajectories (from noise to final output), measuring the actual reward at the end, and training a small network to predict that final reward from any intermediate state. As the model generates more examples, the value function updates by comparing its prediction to the real outcome, so on the next rollout it makes fewer errors and gets better at spotting which states point toward high reward.

Why it works

Why steering through a learned value function works

Here is the core mechanism: you do not need to train the giant model to discover high-reward trajectories. Instead, train a small value function to recognize high-reward states. Once it is accurate, you can use it to bias the model's sampling at each step: when choosing which direction to nudge next, sample more often from actions the value function predicts will pay off.

Because the value function is learned on-policy (from whatever the model currently generates, including new regions the training data never covered), it adapts. If the model wanders into an unexplored but high-reward region, the next rollout will include that region, and the value function will learn to value it. This breaks free of Classifier Guidance's trap: you are not locked to the offline dataset.

The memory stays low because only the value function needs to be stored and updated. The original model is frozen; you only need memory for computing how to adjust the small auxiliary weights, not through billions of parameters.

The equation: learning to predict the payoff

First in words:

value_loss = (predicted_value - actual_return) squared, summed over all states in the trajectory

Then the compact form:

L_value = sum_t (V(s_t) - R_t)^2

Every symbol:

V(s_t)the value function's prediction at time step t
s_tthe partial generation state at step t
R_tthe actual cumulative reward earned from step t onward (observed after generation finished)
sum_tadd up the error at every step in the trajectory

Update rule nudges the value function slightly so next time it predicts closer to 7 and 8.

What can go wrong

What can go wrong

Value function overshoots If the value function learns to overestimate the reward on certain types of states, the model will be steered toward chasing those false signals rather than genuine high-reward trajectories. Requires careful training and occasionally revisiting old data to calibrate.
Reward function is itself unreliable If the reward you are optimizing (e.g., a toxicity classifier) is noisy or biased, the value function will learn to optimize the wrong thing. The model will faithfully chase poor signals.
Mode collapse from on-policy sampling If the value function becomes too confident too fast, the model may commit to one high-reward trajectory type and forget to explore others. On-policy learning can narrow the range of outputs.
Done right. Interleave exploration and exploitation, keep the value function calibrated against holdout data, and use a reward signal you trust.

What a runnable demo should prove

Train the value function for 50 steps, using on-policy rollouts. Plot: (1) the mean reward over 10 generated images before and after value learning, (2) the value function's prediction error at each step (should shrink as it learns), and (3) the types of images the model generates—they should shift from random noise toward the target category.
