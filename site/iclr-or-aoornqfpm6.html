VER: Vision Expert Transformer for Robot Learning

Distill multiple pretrained vision models into separate specialist experts, then teach a lightweight router to pick the right expert for each robot task.

Paper explainersAll themesRobotics & Control

Pretrained vision models like CLIP, DINO, and ViT are trained on billions of images, but each one specializes in different visual patterns. A robot solving real tasks needs features from all of them, not just one. VER distills all three into a shared library of expert networks, then fine-tunes only a tiny routing network (0.4% of parameters) that learns which expert to activate for each robot task — keeping the massive knowledge from pretraining while customizing the selection.

Zero assumption version

One pretrained model, incomplete toolbox

Every pretrained vision model (a large neural network trained on millions of images) learns to extract useful visual features — patterns like edges, textures, shapes, semantic concepts. CLIP excels at matching images to text descriptions; DINO finds parts of objects; ViT builds hierarchical spatial understanding. But each one has blind spots: CLIP may miss fine motor details, DINO may ignore background clutter, ViT may struggle when lighting conditions shift unexpectedly.

In robot learning, a single model's biases become fatal. A robotic arm needs to see both the gripper (fine detail like DINO sees) and the table edge (spatial structure like ViT sees) and the target object's identity (semantic link like CLIP sees). Using only one pretrained model discards two-thirds of the collective knowledge. A naive fix is to just concatenate all three models' outputs — but now the robot's training has to learn which features matter, which wastes data and slows learning, and the gigantic bundle of features cannot be efficiently finetuned.

In one sentence. VER distills all three pretrained models into a shared expert library, then trains a lightweight router that learns to activate the right expert for each robot task.

The algorithm as a flow

What it actually does

Pretraining: Distill three foundation models.

Take CLIP, DINO, and ViT (each 300+ million parameters); extract their visual representations; compress each into separate expert networks via a distillation loss (mean squared error plus cosine similarity, which measures how aligned two vectors of numbers are — 1 means identical direction, 0 means opposite). Each expert learns to approximate its teacher model's outputs.

Introduce teacher-specific routers.

For each pretraining layer, add a small routing network that learns a score for each expert under each teacher. This step ensures experts don't collapse into one — mutual information loss encourages each expert to stay specialized to its assigned teacher.

Freeze experts, train robot router.

Lock all pretrained experts and teacher-specific routers. Add one new tiny routing network (0.4% of the model) that learns to pick which teacher's router to consult for each image patch in each robot task.

Curriculum annealing: Start simple, get precise.

Begin with all experts active (consultant all three teachers). Over training, gradually shrink to just the most relevant experts (e.g., only DINO for fine-detail tasks). This curriculum prevents early randomness from breaking learning.

Inference: Route then act.

For a robot task, run the image through base vision transformer layers (a model architecture that reads images as sequences of small patches), then at each expert layer the robot router chooses a teacher, that teacher's router picks experts, the chosen experts produce features, and the policy head generates robot actions.

What the paper changes

The one thing that changes: expert routing

Standard mixture-of-experts models have a single router per layer that picks which experts to activate. VER replaces that with a two-level routing: first, a robot-task router selects a pretrained teacher (CLIP, DINO, ViT), then that teacher's router selects specific experts. The switch is the routing path — from fixed expert assignment to dynamic, task-aware, teacher-first expert selection.

The hidden quantity

The hidden quantity: task-expert alignment

measured quantity  =  which expert handles which task region

The paper's core measurement is straightforward: when the robot router trains, it learns a set of probabilities over teachers for each image patch (e.g., 60% DINO, 30% ViT, 10% CLIP for this patch). Those probabilities reveal which pretrained model the task actually needs for each visual region — DINO for gripper details, ViT for table structure, CLIP for object identity.

The paper tracks this via mutual information: maximize how much the robot router's teacher choice depends on which teacher's experts perform best (captured as the information between the teacher variable and the expert activations across all layers). It also minimizes the conditional entropy — tighten how certain each teacher is about which experts to pick, forcing specialization. This quantity is not explicitly labeled in the forward pass but governs the pretraining loss and ensures diversity.

Why it works

Why it works: three sources of knowledge stay separate until needed

A robot policy is a black box that takes a visual feature list (just numbers from the vision model) and outputs action commands. Normally, if you feed it features from three different pretrained models, the policy has to learn (on limited robot data) which features matter and which are noise. But the pretraining data is scarce for robotics, so the policy wastes learning time on irrelevant features.

VER sidesteps this by letting the router learn the feature selection, not the policy. The router is lightweight and only needs to memorize which teacher excels at each region of each robot task. Because the router has access to ground truth (success or failure of robot actions), it can quickly learn: DINO is right for detail-critical reaches, CLIP for object-identity picks, ViT for spatial orientation. Meanwhile the policy only sees pre-vetted features from one teacher per patch, so it can focus purely on learning what to do with clean, relevant signals. This separation works because the router picks features in real time based on the image, so the policy never wastes time learning to ignore features from the wrong teacher — all features it receives are already vetted as task-relevant.

Math after the picture

The distillation and specialization loss

First in words:

total_loss = distillation_loss + mutual_information_loss. distillation_loss pulls expert outputs close to teacher outputs. mutual_information_loss maximizes information between teacher choice and expert assignment, and minimizes uncertainty given a teacher.

Then the compact form:

L_total = L_distill + lambda * [I(Teacher; Expert) - alpha * H(Expert | Teacher)]

Every symbol:

L_distillcosine similarity and smooth L1 distance between expert and teacher outputs
I(Teacher; Expert)mutual information: how much expert assignment depends on which teacher
H(Expert | Teacher)conditional entropy: how much expert uncertainty remains after fixing the teacher
lambdaweight of the specialization constraint
alphastrength of the conditional entropy penalty
A tiny numeric example
Suppose a single image patch has four candidate experts and three teachers (CLIP, DINO, ViT).
For DINO on a gripper detail: cosine_sim = 0.95 (expert matches teacher very well); smooth_L1 = 0.02 → L_distill_DINO = 0.97 (good).
For CLIP on same patch: cosine_sim = 0.60 (expert mismatches teacher); smooth_L1 = 0.15 → L_distill_CLIP = 0.75 (poor).
Mutual information I(Teacher; Expert) = 0.8 bits (expert choice IS informative about which teacher wins).
Conditional entropy H(Expert | Teacher) = 0.2 bits (given DINO, expert is almost certain; given CLIP, still uncertain).
L_total = 0.85 (avg distill) + 1.0 * [0.8 - 0.5 * 0.2] = 0.85 + 0.7 = 1.55. Lower is better; high mutual info + low conditional entropy (tight specialization) are rewarded.

The loss shapes distillation (each expert mimics its teacher) while enforcing that router choices are predictable and specialized.

What can go wrong

What can go wrong

Redundant expert learning during pretraining. Without mutual information regularization (gently steering), multiple experts collapse into identical copies of the same teacher. The router then has nothing to differentiate; all experts behave the same and specialization vanishes. Mutual information loss forces diversity by penalizing when experts fail to align distinctly to different teachers.
Router overfits to the first task. If the robot router trains entirely on one task (e.g., only grasping) without curriculum annealing, it learns a brittle routing that works only on that task's visual patterns. Starting with all experts active and gradually annealing to fewer experts prevents this because the router is forced to learn general teacher-selection heuristics before it narrows.
Cold start in downstream tasks. A tiny new robot task with very little data may not provide enough signal for the router to learn which teachers are relevant. The paper sidesteps this by initializing the router with good pretrained features and a curriculum annealing schedule that starts safe (all experts) and only specializes when signal is strong.
Done right: experts remain distinct. By regularizing mutual information and training the router with curriculum annealing, the paper ensures each pretrained teacher's expertise remains available and the router learns to invoke it only when helpful.
What a runnable demo should prove

What a runnable demo should prove

Build a small robotic task (e.g., reaching to touch a target, grasping a toy, pushing an object across a table). Train three separate baseline policies: one with CLIP features only, one with DINO features only, one with ViT features only. Measure success rate. Then train a VER policy: distill all three into experts, freeze them, train only the router and policy head. Measure success rate on the same task.

success_rate = (number of task successes) / (total task attempts)

VER should reach 75%+ success with fewer finetuned parameters than any single model alone, and faster convergence than a naive three-model ensemble. This proves the mechanism: because the router learns image-by-image which teacher is best, the policy head receives only relevant features and trains faster on limited robot data, whereas fixed models or ensembles waste compute and learning on irrelevant features.
