Winformer: Windows for Time-Series Patterns

Winformer looks at repeating patterns in time-series data by grouping points into sliding windows and understanding their shared rhythm, instead of treating each point alone.

Paper explainersAll themesTime Series & Sequential

Time-series data—like stock prices or temperature readings—often repeat the same pattern over and over. When you want to generate new time-series data that matches patterns from different domains (like weather plus traffic), the challenge is that the patterns do not align; the weather repeats every 24 hours, but traffic might repeat every hour. Winformer solves this by looking at chunks of time (windows) instead of single points, and learning what rhythm each window follows.

Zero assumption version

The pattern-alignment problem

Time-series data—numbers that change over time—usually contain repeating patterns. A daily temperature chart repeats every 24 hours. A stock price chart might have patterns at multiple timescales: daily closes, weekly trends, seasonal cycles. When you train a model on one domain's data (say, electricity demand), then ask it to generate data in a different domain (say, traffic congestion), the model sees the old patterns but the new domain's patterns do not line up with them. The rhythms are misaligned.

Older methods process time-series one point at a time, or in small fixed-size chunks. A single point has no rhythm; a fixed chunk (like the previous 7 points) might miss long-range patterns that play out over days or weeks. Neither approach lets the model see and adapt to the actual shape of a pattern in the new domain.

In one sentence. Winformer groups time-series points into sliding windows and learns what repeating rhythm each window contains, so it can adapt to different domains' patterns.

The algorithm as a flow

What it actually does

Decompose the input time-series

Break the signal into fast oscillations and slow trends.

Find the dominant frequencies

Identify which rhythms (hourly, daily, weekly) are strongest.

Define adaptive window sizes

Choose window lengths that match the period of each frequency.

Compute window-wise attention

For each window, decide which other windows are most relevant to predict.

What the paper changes

What the paper changes

The paper changes the basic unit of attention—the thing the model looks at when deciding what to do next. Instead of attending to individual points or fixed-size chunks, Winformer attends to sliding windows whose size is chosen to match the data's true repeating rhythm.

the object it moves  =  window size and alignment
The hidden quantity

The dominant frequency

measured quantity  =  dominant frequency of the signal

Every time-series has a rhythm—the timescale at which patterns repeat. A daily temperature chart repeats with a period of 24 hours (a frequency of 1 per day); weekly traffic repeats with a period of 7 days. The dominant frequency is the strongest, most important rhythm in the data. Winformer measures it using frequency decomposition, a technique that splits any noisy signal into its underlying pure tones (like how a prism splits white light into colors).

The paper estimates the dominant frequency by analyzing the input data's Fourier transform—a mathematical tool that shows how much of each frequency is present. Once Winformer knows the dominant frequency, it can set the window size to exactly one full cycle of that pattern. This ensures that each window captures a complete repeating unit, not a partial or random chunk.

Why it works

Why window-wise attention works

The core insight is simple: if you want to predict the next point in a repeating pattern, you should look at earlier versions of the same phase of that pattern, not arbitrary nearby points. In an hourly traffic signal, if it is now 3 PM (the third hour into the day's cycle), looking at yesterday's 3 PM is much more informative than looking at 3:15 PM today. Winformer aligns windows so that each window spans exactly one complete cycle of the dominant pattern. Now when the model attends to past windows, it is always comparing cycles-to-cycles—apples to apples.

When the model trains on a new domain (like traffic instead of weather), the dominant frequency changes, but Winformer re-computes the window size automatically. The same attention mechanism now looks at the right cycle length for that new domain. This adaptive alignment transfers the model's ability to find patterns across completely different timescales, which is why it works on 12 real-world domains without retraining.

Math after the picture

The window-alignment equation

First in words:

predicted next value = sum over relevant past windows of (how relevant that window is) times (the pattern in that window)

Then the compact form:

y_t = sum_w alpha_w * aggregate(window_w) where alpha_w is the attention score for window w

Every symbol:

y_tthe value to be generated at time t
window_wa sliding window starting at time w, spanning one full dominant cycle
alpha_wthe attention weight: how relevant window_w is to predicting y_t
aggregate(window_w)the representative pattern from window_w, e.g., the average or a learned summary
sum_wadd up contributions from all past windows at that phase
A tiny worked example
Suppose the dominant frequency is 24-hour cycles (hourly data). Windows are 24 hours wide.
To predict hour 49 (day 2, hour 1), look back at hour 25 (day 1, hour 1) and hour 1 (day 0, hour 1).
Past window at hour 1-24: average value = 60. Attention weight = 0.6 (high, same phase).
Past window at hour 25-48: average value = 62. Attention weight = 0.3 (medium, different day's trend).
Past window at hour 13-36: average value = 58. Attention weight = 0.1 (low, misaligned phase).
Prediction: y_49 = 0.6 * 60 + 0.3 * 62 + 0.1 * 58 = 36 + 18.6 + 5.8 = 60.4.

The key is that windows align to cycles, so comparing windows compares the same phase of the repeating pattern, making the attention scores tell the true relevance.

What can go wrong

What can go wrong

Noisy data confuses frequency detection. If the input signal has lots of random noise mixed in, the frequency decomposition might identify noise as a dominant pattern, and then windows will be misaligned. Smoothing the signal first helps because it removes random fluctuations before decomposition, leaving only the true repeating structure.
Multiple equally strong frequencies break the assumption. If the data has two equally strong rhythms (e.g., both hourly and daily are equally present), choosing one dominant frequency will miss the other. The method works best with a clear hierarchy of rhythms.
Non-periodic or chaotic data is not helped. If the time-series has no repeating pattern (pure randomness), frequency decomposition will not find a strong rhythm because there is nothing to repeat. Window alignment requires a stable, recurring cycle; without one, comparing past windows tells you nothing about the future.
Done right: preprocess to remove noise and validate that the data actually has periodic structure. Check the frequency spectrum visually before trusting the decomposition. Use domain knowledge (you know weather is 24-hour periodic) to validate that the detected frequency makes sense.
What a runnable demo should prove

What a runnable demo should prove

Build a simple synthetic time-series with a clear repeating pattern: e.g., a sine wave that repeats every 10 time steps. Train Winformer to generate the next 20 steps, given the first 50. Also train a baseline model that uses fixed-size windows of 7 points (not aligned to the pattern). Measure how well each model reproduces the sine wave in the generated portion.

mean_squared_error = average of (predicted_value - true_value) squared, averaged over all generated time steps

Winformer should produce nearly perfect predictions (error close to 0) because its windows perfectly align with the 10-step cycle. The baseline should have much higher error because its 7-point windows are out of phase with the true 10-step pattern.
