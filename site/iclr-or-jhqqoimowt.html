FAPO: Flawed-Aware Policy Optimization

A training method that rewards flawed reasoning early (to learn fast) then penalizes it later (to learn right).

Paper explainersAll themesGenerative Models & Diffusion

When a language model learns to reason through trial-and-error, it gets rewarded whenever it lands on the right answer. But it does not care HOW it got there. Some rollouts (attempts) have real reasoning; others just happened to guess or skip steps. Teaching the model to value both equally locks it into unreliable patterns. FAPO watches for flawed attempts and gradually shifts from rewarding them (to bootstrap early learning) to penalizing them (to build real reasoning).

Zero assumption version

Why naive trial-and-error backfires

A language model learns to reason by generating many attempts at a math problem and keeping the ones that land the right answer. Each correct answer gets a reward signal telling the model: keep doing this. The problem: the model does not actually know WHY that attempt succeeded. Maybe it did real math. Maybe it guessed the answer. Maybe it took a shortcut, skipping over reasoning steps to land on a lucky number. All three paths get rewarded identically.

In early training, these flawed shortcuts are USEFUL because the model has not yet learned the basic building blocks of math — which operations work, which patterns of steps lead to answers, what an intermediate result looks like. Flawed shortcuts let the model see successful outcomes quickly, so it learns these basics faster without needing to reason all the way through. But by mid-training, the model believes these shortcuts are HOW you solve problems. It keeps using them even when they no longer work on harder or slightly different questions. The model has painted itself into a corner, learning PATTERNS of right answers instead of the REASONING that produces them.

The core problem. Models reward guessing and skipping as heavily as real reasoning, so they lock in unreliable shortcuts.

The algorithm as a flow

What it actually does

Train a flaw detector

Build a small critic model (4-billion parameters) that reads a reasoning attempt and marks exactly where it goes wrong: guessing, skipping steps, unlucky leaps.

Collect flawed versions

Generate many attempts at reasoning problems. Use the critic to label which ones have real reasoning and which have flaws.

Early stage: flaws are helpful

At the start of training, reward all correct answers equally (flaws + real reasoning). The model learns that right answers exist and gets momentum because it needs quick wins to build confidence in its outputs.

Late stage: penalize flaws

Once the model has learned the basics, gradually shift rewards. Lower the reward for flawed attempts because at this stage real reasoning paths exist and the model should learn to find them instead.

Outcome: faster learning + reliability

Model reaches high accuracy earlier (flaws provide useful stepping stones during learning) and improves further because once shortcuts are downweighted, the optimizer has no choice but to strengthen the real reasoning paths, which generalize to harder problems.

What the paper changes

The one thing that changes

The paper changes which attempts get called successes during training. Instead of rewarding all correct answers equally, FAPO uses a critic model to assign DIFFERENT rewards based on whether the path to the answer was genuine or flawed.

the object it moves  =  reward assignment
The hidden quantity

The flaw signal: what the model REALLY learns from

measured quantity  =  Flaw Detection Score

The paper measures a hidden quantity: how much each reasoning attempt relied on guessing, skipped steps, or lucky leaps rather than genuine problem-solving. This is the FLAW DETECTION SCORE. It is not computed by hand; instead, a trained generative reward model (a smaller language model) reads each reasoning attempt step-by-step and marks where the logic breaks down. If the path to the answer looks like real math, the score is low. If it looks like a guess or a shortcut, the score is high.

During early training, the FAPO algorithm ignores the flaw score and rewards all correct answers. Later, it uses the flaw score to penalize high-scoring flaws, gradually reducing their influence. The score is the hidden dial that FAPO turns to shift training from learning fast (via anything that works) to learning right (via genuine reasoning).

Why it works

Why it works: the two-phase shift

FAPO exploits a timing insight: early in training, the model is learning WHAT a correct answer looks like. It does not yet have the machinery to reason reliably. Flawed shortcuts are useful stepping stones — they let the model see patterns in correct answers quickly. Rewarding them all equally is fine because the model is not yet comparing reasoning quality; it is just learning that right answers are right.

Later, once the model has learned the basics, the goal flips: it should learn HOW to reason reliably. At this stage, flawed shortcuts become dangerous because they are the fastest path to a correct answer (they skip steps), so when the optimizer updates the model to increase rewards, it preferentially strengthens the shortcut paths over the full reasoning paths. FAPO detects this turn and SHIFTS its reward signal. The same flawed attempts that were helpful bootstraps now get penalized. This forces the optimizer to seek out real reasoning instead because penalizing shortcuts removes their reward advantage. Because the model has already learned the low-level skills, it can now afford to climb the steeper (but more reliable) hill of genuine problem-solving.

The mechanism is ADAPTIVE — FAPO does not need a hand-tuned hyperparameter for when to make the switch. The algorithm watches the ratio of flawed positive samples as training progresses. Early on (when the model is still far from perfect), flawed positives dominate because they are the only correct attempts available, and they get rewarded. As the model improves and learns better shortcuts, it naturally finds a higher fraction of non-flawed correct attempts, making those the more common reward signal. The flawed ones are automatically downweighted because they become the minority. The shift happens naturally through this changing composition.

Math after the picture

The reward formula

First in words:

Advantage equals the outcome reward (for getting the answer right) plus a process reward (a penalty for flaws), weighted by the training stage.

Then the compact form:

A = R_outcome + alpha(t) * R_process(flaw_score)

Every symbol:

Athe advantage signal that tells the model how much to change its weights
R_outcomethe reward for a correct final answer (always positive if answer is right)
R_processthe step-level reward based on flaw detection (negative if flaws found)
flaw_scorehow much guessing or skipping happened (from the critic model)
alpha(t)a weight that starts near zero and grows over training time t
A tiny worked example
Attempt A1: guessed correctly. flaw_score=0.8 (high flaw). Early (t=10): A1 = 1.0 + 0.1 * (-0.8) = 0.92 (mostly rewarded). Late (t=150): A1 = 1.0 + 0.6 * (-0.8) = 0.52 (penalized).
Attempt A2: reasoned correctly. flaw_score=0.2 (low flaw). Early (t=10): A2 = 1.0 + 0.1 * (-0.2) = 0.98 (nearly fully rewarded). Late (t=150): A2 = 1.0 + 0.6 * (-0.2) = 0.88 (still highly rewarded).
Early training treats A1 and A2 similarly (0.92 vs 0.98). Late training strongly favors A2 (0.88 vs 0.52). The model learns to use genuine reasoning paths because they are rewarded most in later, harder stages.

The process reward R_process is extracted by GenRM, which reads reasoning step-by-step and detects where errors occur.

What can go wrong

What can go wrong

The critic model is wrong. If the flaw detector (GenRM) misidentifies genuine reasoning as guessing, it will penalize the right attempts and confuse training. The paper mitigates this by training GenRM on human-annotated examples of errors and testing it on a held-out benchmark.
The timing of the shift matters. If you penalize flaws too early, the model never learns to land on correct answers. If too late, it has already memorized the shortcuts and cannot unlearn them. FAPO uses the natural ratio of flawed samples to trigger the shift automatically, avoiding this failure.
Harder problems have fewer good solutions. On very hard math problems, only guessing might be fast enough to produce SOME correct samples in early training. If FAPO penalizes all shortcuts too aggressively, early learning stalls. The paper keeps the early-stage reward high and only gradually introduces penalties.
Done right. FAPO works when the flaw detector is accurate, the phase shift is gradual, and early training still has enough correct attempts to learn from (the paper reports stable, monotonic improvement with no training collapse).
What a runnable demo should prove

What a runnable demo should prove

Train a small language model (say, 1-billion parameters) to solve high-school math problems via reinforcement learning. Collect 1000 problem attempts. Run two versions: (A) reward all correct answers equally (baseline), and (B) run FAPO, detecting flawed reasoning and gradually penalizing it. Track three metrics: (1) How often the model guesses vs reasons (measure this by asking the critic), (2) Accuracy on training problems (should grow in both, but FAPO should sustain growth longer), (3) Transfer accuracy on held-out test problems (FAPO should outperform, because it learned real reasoning, not shortcuts).

Improvement = Test Accuracy(FAPO) - Test Accuracy(Baseline); should be positive and grow over training stages.

The demo succeeds when FAPO keeps improving on held-out problems while baseline flattens, proving the model learned genuine reasoning instead of brittle shortcuts.
