GoR: Generative Ordinal Regression

A paper that turns ordinal regression into a step-by-step generation task, where a model learns to predict ordered values by outputting tokens one at a time until it signals done.

Paper explainersAll themesGenerative Models & Diffusion

When you predict things with natural order—star ratings, age groups, disease severity—normal classification and regression struggle. GoR treats this as a generation problem: instead of guessing a single number, the model predicts tokens (like <1>, <2>, <3>) one by one, stopping when it decides it has enough information. By outputting tokens in sequence, the model learns order: to predict level 3, it must first predict levels 1 and 2, so it cannot skip steps.

Zero assumption version

Why ordering matters, but existing methods miss it

Ordinal regression is predicting things that have a built-in order: a 1-star review is closer to 2-stars than to 5-stars. A 30-year-old is closer to 31 than to 60. A model should know this. But normal classification treats classes as completely separate buckets (a cat is not a dog), and normal regression just outputs a single number without explaining its confidence or the steps it took.

Existing methods try two approaches: discretization (carving the continuous line into fixed boxes) and rank-based methods (predicting a list of yes/no decisions: "is it at least 2 stars? yes. is it at least 3 stars? no"). Both have problems. Discretization creates hard boundaries where a value sits ambiguously between two boxes. Rank-based methods lock in a fixed set of thresholds and cannot adapt to the actual shape of the data.

In one sentence. The paper teaches a model to predict ordered values by generating tokens step-by-step, like counting up to the answer, until it signals it is done.

What the paper changes

What changes: the ordinal tokens themselves

Instead of a single regression output or a hard classification choice, GoR changes what the model outputs: a sequence of ordinal tokens (like 1, 2, 3, stop) that the model predicts one at a time. The model learns which tokens to use, when to emit them, and when to declare it is done.

the object it moves  =  ordinal token sequence
The hidden quantity

The hidden quantity: Coverage-Distinctiveness balance

measured quantity  =  Coverage-Distinctiveness Index (CoDi)

When building a vocabulary of ordinal tokens, there is a tradeoff: using many tokens lets you represent every detail (high coverage), but too many creates noise because each token only has a few examples to learn from (low distinctiveness). CoDi measures this balance mathematically. It is the quantity the paper introduces to know whether a token vocabulary is actually good.

The paper estimates CoDi from training data: for each token, count how many examples reach it (coverage) and how confidently the examples belong to that token's region (distinctiveness). A good vocabulary has all tokens both well-covered and clearly separated.

Why it works

Why it works: The ordinal structure is built into the prediction process

Ordinal regression is hard because the model must respect the order without being told the order explicitly. GoR embeds the order into the prediction process itself: by outputting tokens one at a time in sequence (1, then 2, then 3), the model cannot skip levels. It must commit to each step. This forces the model to learn what each level means.

Second, by stopping at different depths (some predictions stop at token 2, others at token 5), the model learns to adjust its confidence. Easy predictions (e.g., obvious extremes) stop early because the model has already narrowed down the answer. Uncertain predictions take more steps to gather more information. This adaptive resolution means the model does not waste effort on obvious cases.

Third, CoDi steers the token vocabulary during training. It prunes tokens that are too rare or too confused (no clear data), because if every token is used to separate clear regions of the data, the model learns faster: each token becomes a clear landmark (token 2 always means medium-low, never mixed high and low). This forces the model to learn ordinal structure instead of arbitrary groupings. Without this pruning, tokens become confused and the model overfits.

The learning objective: Protected movement

First in words:

Total error = bias from coarse vocabulary + variance from noise in training data + penalty for covering all ordinal levels equally well

Then the compact form:

L = bias_term + variance_term + lambda * sum_t coverage_loss(token_t, CoDi_t)

Every symbol:

bias_termhow much detail is lost by using discrete tokens instead of a real number
variance_termhow much noise enters because each token has limited training examples
lambdahow hard to push toward balanced coverage
coverage_loss(token_t, CoDi_t)a penalty that shrinks if token_t is well-covered and distinct, grows if it is rare
CoDi_tthe coverage-distinctiveness score for token_t
A tiny worked example
Suppose we have a rating task (1–5 stars) with 100 training examples: 50 are 1-star, 30 are 4-star, 20 are scattered.
Token 1: covers 50 examples, very distinct from others -> CoDi high (8.0) -> coverage_loss = 0.2
Token 2,3: combined cover 10 examples, poorly separated -> CoDi low (2.0) -> coverage_loss = 2.1 each
Token 4: covers 30 examples, clear separation -> CoDi high (7.5) -> coverage_loss = 0.4
With lambda=0.5, penalty = 0.5 * (0.2 + 2.1 + 2.1 + 0.4) = 2.4. Training now steers toward pruning tokens 2&3, focusing on 1 and 4.
Result: the model learns a two-phase ordinal prediction (low or high), avoiding useless middle tokens.

This equation enforces clean token boundaries: tokens that partition the data well get lower penalties, so training favors learning them over confusing or rare tokens. The model converges faster because training does not waste learning steps on useless tokens that appear rarely or carry no useful information.

What can go wrong

What can go wrong

Vocabulary explosion. If you allow the model to invent too many ordinal tokens, it will overfit by learning one token per training example instead of learning the underlying ordinal structure. With too many tokens, each token only appears a few times in training, so the model learns noise and memorizes instead of generalizing. The CoDi metric prevents this by penalizing rare, poorly-separated tokens during training.
Stop too early. If the stopping rule is not learned well, the model might decide it is done before actually reaching the true ordinal level, producing biased underestimates.
Misaligned tokens. If the ordinal tokens do not partition the data well (for example, token 2 has both low and high values mixed), the model cannot learn a clean ordinal meaning. This is why CoDi's distinctiveness metric is essential.
Done right. Use CoDi to trim the vocabulary to tokens that are both well-represented and clearly separated. Train the stopping rule as carefully as the token predictor. Test on held-out data to verify ordinal accuracy (e.g., mean absolute error where order matters).
What a runnable demo should prove

What a runnable demo should prove

Build a simple ordinal regression task: predict age groups (0-18, 19-35, 36-50, 51-65, 65+) from a small dataset of faces or text descriptions. Implement GoR with a vocabulary of 5–7 ordinal tokens and train it to output tokens one by one until a stop marker. Run three versions: (a) standard classification (treats groups as independent), (b) simple regression (outputs a single number), (c) GoR. Measure: (1) accuracy on the test set, (2) whether predictions respect ordinal distance (e.g., does the model predict 35 when the true age is 36, rather than 65?), (3) how many tokens each prediction uses (easy cases should use fewer).

ordinal_accuracy = (1 / N) * sum_i (1 - |predicted_level_i - true_level_i| / max_level)

The demo makes clear: GoR respects ordinal structure because it predicts through intermediate levels (to reach level 3, it outputs 1, then 2, then 3 — so it cannot jump to 5), uses fewer tokens for easy cases (reducing wasted computation), and outperforms both classification (which ignores order) and regression (which guesses a single number without explaining steps).
