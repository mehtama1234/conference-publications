Beyond Extrapolation: Bidirectional Knowledge for Time Series Forecasting

Train a time-series forecaster to also learn continuation patterns from a historical library so it can use those patterns at prediction time to steer its forecasts forward.

Paper explainersAll themesTime Series & Sequential

When you predict what happens next in a time series (like power usage or traffic flow), you usually just look backwards at history and extrapolate forward. But the paper points out that in your training data, you already see examples of what comes AFTER each target period—the continuation. KUP-BI captures those patterns from history as a reusable proxy and feeds them into the forecaster as structured guidance.

Zero assumption version

Forecasters ignore what comes after

A standard time-series forecaster does one thing: it reads history and outputs a prediction for the target period. Once training is done, that model never looks at what happens after the target—even though your training data contains those examples.

A beginner might think: just run the model forward, step by step, to predict far ahead. But that fails because the model was trained only on one-step-ahead examples, so errors accumulate quickly. The model has no awareness of typical continuation shapes that appear in the training data.

In one sentence. The paper trains the forecaster to also learn continuation patterns from historical examples, then uses those patterns as a structural guide when making predictions.

The algorithm as a flow

What it actually does

Collect continuation examples

For each training sample, record history, target, and the period immediately after.

Build a continuation proxy

When the forecaster sees a new history, find similar historical examples and average their continuations.

Encode both signals

The main forecaster produces its usual prediction; the proxy produces an independent signal based on continuation patterns.

Gate and blend

A lightweight neural module learns how much to trust each signal based on the input, then outputs a weighted blend.

Train end-to-end

The learning algorithm adjusts how much the proxy guides the forecast, using actual forecasting error.

What the paper changes

What the paper changes

The paper adds a second input stream to the forecaster: the continuation proxy. This proxy is a learned representation of typical continuation patterns, extracted from the training library. The model now has two sources of information—the raw history and the typical next-step shape—instead of one.

the object it moves  =  continuation proxy stream
The hidden quantity

Continuation pattern similarity

measured quantity  =  continuation pattern similarity

This is a measure of how closely a new input history matches historical examples. When two histories have similar shapes, their continuations tend to be similar too. KUP-BI uses this: it finds training examples whose initial segments resemble the current input, then averages the known continuations from those examples.

The paper encodes this as a lightweight lookup mechanism: the continuation proxy retrieves or approximates the continuation shape by comparing the current history to a learned index of historical patterns.

Why it works

Why continuation patterns help forecasting

A standard forecaster has to learn both the current dynamics and how to continue them into the future, all from the prediction error in the target period. This leaves the forecaster guessing about long-horizon behavior. KUP-BI gives it a structural hint: here are real examples of how trajectories continue from similar starting points.

The continuation proxy is not magic—it is just a learned pattern from the training data. When the gating module learns to trust this proxy, the forecaster can focus its learning capacity on getting the current dynamics right, because the continuation patterns are already being provided by the proxy stream. This reduces drift because the proxy keeps steering toward typical shapes from the training data, rather than letting errors compound as the model extrapolates further and further.

Math after the picture

The gating equation

First in words:

The final forecast is a weighted average of the main prediction and the continuation proxy, where the weight is learned from the data.

Then the compact form:

forecast_final = g(input) * prediction_main + (1 - g(input)) * proxy_continuation

Every symbol:

forecast_finalthe output prediction for the target period
g(input)a learned gating weight, between 0 and 1
prediction_mainthe standard forecaster output
proxy_continuationthe continuation pattern proxy signal
A tiny worked example
Suppose the main forecaster predicts 45 and the continuation proxy predicts 52 (because similar history examples typically continued upward).
The gating weight g learns to be 0.6 for this input (trusting the main forecaster 60%, the proxy 40%).
forecast_final = 0.6 * 45 + 0.4 * 52 = 27 + 20.8 = 47.8
If the true target was 48, this blend is closer than the main forecaster alone (which would have given 45).

The gating module learns when to trust the main forecaster versus the continuation proxy, based on what reduces prediction error.

What can go wrong

What can go wrong

Non-stationary data breaks the proxy. If the underlying process changes over time (e.g., climate shift, pandemic), historical continuation patterns may not match future dynamics. The proxy will steer the forecast wrong.
Rare events are underrepresented. If the test set contains continuation patterns that never appeared in training, the proxy has no matching examples and offers no useful signal. The forecaster falls back to one-way extrapolation.
Overfitting to continuation patterns. If the gating module learns to trust the proxy too much, the final forecast rigidly follows historical patterns and fails to adapt to new regimes.
Done right. Validate on a held-out test set from the same period as training. Add a penalty term during learning to prevent the gating weight from going to extremes (forcing the model to balance both signals). Monitor for cases where the patterns in the data have changed over time.
What a runnable demo should prove

What a runnable demo should prove

Build a small time-series dataset where continuations have clear typical patterns (e.g., sine wave, step function, or real data like daily temperature). Train a standard forecaster on 80 percent. For the remaining 20 percent, compute predictions 1, 5, and 10 steps ahead using the standard forecaster alone versus KUP-BI. Measure average absolute error at each horizon.

mean absolute error across all test samples = (1/N) * sum_i |forecast_i - true_i|

The demo must show that KUP-BI narrows the error gap between short- and long-horizon forecasts, because the continuation proxy keeps the forecast from drifting as far.
