Bring My Cup!: Personalizing Vision-Language-Action Models

Visual Attentive Prompting lets a frozen robot policy find a user-specific object from a few reference images and then bias action generation toward that exact instance.

Paper explainersAll themesMultimodal

A robot can follow generic commands such as 'pick up the mug' if any mug will do. The harder case is 'bring my cup' when several similar cups are present and the user means one exact object. The robot must compare the live scene with a small set of reference photos, identify the matching instance, and then act on that instance without retraining its large policy. Visual Attentive Prompting adds that instance-selection step as a training-free adapter.

Zero assumption version

Generic object understanding is not enough for personal-object manipulation

Vision-language-action models map images and text to robot actions. They work well when the instruction names a category: cup, book, plate, bottle. In that setting, the robot only needs to find any object that matches the category and task constraints.

Personalized commands change the problem. The user may own several visually similar objects, and the intended target can be unseen during training. The model must solve instance identification, not category recognition. A generic policy usually fails because all matching cups receive similar scores, so the action module has no strong reason to move toward the one cup that belongs to the user.

The problem: A robot that understands object categories can still fail on personal commands because it has not linked the current scene to the user's exact object instance.

The algorithm as a flow

What it actually does

Store reference images

A few user-provided photos act as a memory of the target object.

Detect candidate objects in the live scene

An open-vocabulary detector proposes boxes for objects that could match the instruction, where open-vocabulary means it can search across many named object types instead of a fixed small list.

Match candidates to the reference set

Each candidate is compared against the stored references to find the scene object most consistent with the user's target.

Inject a visual prompt

The selected object is highlighted in the scene input and the text instruction is rewritten to point the policy toward that instance.

Run the frozen action model

The original vision-language-action model stays unchanged and generates actions using the prompted inputs.

What the paper changes

What the paper changes

The paper adds a perceptual adapter before action generation. Instead of changing model weights, it changes the input so the frozen policy receives a scene where the intended object is already singled out. This shifts the problem from relearning manipulation to supplying better instance-level grounding because the backbone already knows how to execute grasps, while the missing step is identifying which object instance the command refers to.

The hidden quantity

The hidden quantity: instance match score

measured quantity  =  instance match score

The instance match score measures how strongly one scene object corresponds to the user's references. High score means the candidate shares the identifying visual traits that persist across the reference images. Low score means the candidate belongs to the same category but not to the same instance.

This score matters because the action model only needs one clear target. If several candidates remain tied, the action probabilities, meaning the model's scores over possible next moves, stay spread across them and the robot may approach the wrong object. VAP tries to sharpen that competition by selecting the highest-scoring candidate and making it visually prominent before the policy chooses actions.

Why it works

Why prompting the right instance changes action behavior

The first mechanism is reference-based grounding. The adapter keeps the user's examples outside the model weights and compares them to scene candidates at run time. That is useful because personalization now depends on the current user's object rather than on retraining for every new object.

The second mechanism is selective emphasis. After matching, VAP alters the model input by highlighting the chosen object and rewriting the instruction. This works because large action models are highly sensitive to which visual region and text span dominate their internal attention, where attention means the scoring process that decides which input parts influence the next computation most. By making one candidate dominant, the prompt reduces competition from similar distractors.

The third mechanism is policy preservation. The frozen backbone already knows how to reach, grasp, and move objects. VAP does not relearn those motor skills. It only resolves the target identity first, so the downstream action model can apply its existing manipulation ability to the correct object. That separation matters because instance selection and motor execution are different problems.

Math after the picture

How the adapter chooses a target

First in words:

The target is the scene candidate with the largest combined similarity to the reference images.

Then the compact form:

target_score(candidate) = sum(similarity(candidate, each_reference))

Every symbol:

target_score(candidate)the total evidence that one scene object is the personal target
similarity(candidate, each_reference)how closely one scene candidate matches one stored reference image
sum(...)add the match evidence across all reference images
A tiny worked example
Suppose three cups are detected in the scene.
Cup A matches the three references with scores 0.9, 0.8, and 0.85, so target_score = 2.55.
Cup B matches with 0.7, 0.65, and 0.6, so target_score = 1.95.
Cup C matches with 0.3, 0.25, and 0.2, so target_score = 0.75.
The adapter highlights Cup A because it has the strongest total evidence across the reference set.

The sum across references matters because one view can be ambiguous, while several consistent views identify the same object more reliably.

What can go wrong

What can go wrong

Detection misses the target. If the candidate generator never proposes the user's object, the adapter cannot recover because matching only compares the available candidates.
Reference views are too narrow. If the stored photos show only one angle or lighting condition, the correct target may score poorly in the live scene because the visible traits have changed.
Prompt emphasis is weak. If highlighting and rewriting do not change the policy input enough, the frozen action model may still distribute probability across several similar objects and grasp the wrong one.
Done right: A good detector, a reference set with several views, and a strong prompt convert a generic manipulation policy into a personalized one without weight updates.
What a runnable demo should prove

What a runnable demo should prove

Build a tabletop task with several visually similar cups and a small set of reference images for one target cup. Run a frozen vision-language-action policy with and without the adapter. Measure whether the detector proposes the target, whether the chosen match overlaps the true target, and whether the robot completes the grasp-and-deliver task with the correct object. Include distractor scenes where another cup shares color or shape with the target.

personalization_score = (target_found + target_selected + task_completed) / 3

The demo should separate target selection from motor control and show that the main benefit comes from resolving which instance the command refers to before action generation begins.
