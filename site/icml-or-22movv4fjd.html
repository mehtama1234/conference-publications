MoCL: Metabolic Optimization for Continual Learning

By using a smart gate that learns which weight-movements conflict with old knowledge, continual learning can stay stable without freezing up as new tasks pile on.

Paper explainersAll themesRepresentation & Self-Supervised Learning

When a model learns a new task after an old one, it almost always forgets the old task (called catastrophic forgetting). Previous methods try to freeze important weights to prevent this, but they freeze so much that the model cannot learn new things well. This paper introduces MoCL, which uses a smarter gate to let some weights move flexibly while gently holding back movements that would break old knowledge. Unlike older methods that rely on flat linear math, MoCL captures the actual shape of what the model learned—the valleys and hills in the learning space—so updates point the right way.

Zero assumption version

The stability-plasticity trap

Imagine training a model on recognizing cats, then on recognizing dogs. When you train on dogs, the weights that learned cat features get overwritten. The model forgets cats. This is catastrophic forgetting.

The naive fix: freeze the weights that learned cat features so they cannot change when learning dogs. This works—the model remembers cats, because those weights stay in place—but now it cannot flex those same weights to help with dogs, so dog recognition suffers because the dog learner has fewer tools available.

Older solutions use orthogonal projection (imagine pushing your update attempts against a wall of "forbidden directions") to prevent updates from damaging old knowledge. But as more tasks pile up, the walls get thicker and more complex, and the model runs out of room to learn anything new. It gets paralyzed.

The core problem. Freezing weights prevents forgetting but blocks new learning. Projection-based methods try to have it both ways but ossify as tasks accumulate.

The algorithm as a flow

What it actually does

Step 1: Capture the shape

Instead of flat linear walls, measure the actual shape and valleys of what the model learned before.

Step 2: Score importance

Assign each weight an importance score: how much does moving it break old knowledge?

Step 3: Smart gating rule

Use a special gate rule designed for cases where a few weights matter a lot and most barely matter. It allows big safe movements because those pose no threat to old knowledge, and blocks tiny risky ones that would jeopardize the old tasks.

Step 4: Update safely

Apply updates only to weights with low conflict scores; let high-importance ones move less.

Step 5: Keep old knowledge

The combination of importance scores and the gate preserves both old and new task performance.

What the paper changes

What the paper changes

MoCL changes how the model is allowed to update its weights. Instead of a hard constraint (some weights frozen, others free), it uses a soft, smart gate that blocks updates by their risk level.

the object it moves  =  weight-update allowance
The hidden quantity

The importance score: measuring danger

measured quantity  =  importance score (or impact of each weight)

The hidden quantity is the importance score for each weight: how much does that weight matter for old knowledge? A weight that shaped cat detection gets a high score; a weight that barely touched cat detection gets a low score.

MoCL estimates this score using the Fisher Information Matrix (a standard ML tool that measures how much each weight contributes to the model's confidence on old tasks). But instead of inverting this huge matrix directly (which is expensive), MoCL uses a clever approximation: it factors the matrix into smaller pieces. Higher importance scores mean the gate is stricter—updates to that weight get suppressed more.

Why it works

Why the smart gate solves the trap

The mechanism is three-fold. First, instead of using a flat linear approximation (assume straight lines everywhere), MoCL captures the actual shape and curvature of what the model learned—imagine a topographic map with valleys and peaks. When you propose an update, knowing the real shape helps you predict whether you will slide off a cliff (break old knowledge) because the curve is steep there, or stay on safe ground because the terrain is flat and forgiving.

Second, MoCL assigns each weight an importance score based on the Fisher matrix. Weights that shaped old knowledge get high scores. The gate uses these scores: it suppresses updates to high-importance weights (because moving them would damage old memories) and allows updates to low-importance weights (because moving them barely affects old knowledge). This is like traffic lights: a high-importance weight gets a red light (update blocked), and a low-importance weight gets a green light (update allowed).

Third, the gate itself uses a special rule based on Tsallis entropy—a mathematical idea that handles imbalanced distributions (most weights matter little, a few matter a lot). This rule respects the imbalance: it can be strict about the essential weights and lenient about the rest. The result: the model stays stable on old tasks because the essential weights barely move, while low-importance weights flex freely to absorb new knowledge. Plasticity and stability coexist.

Math after the picture

The gating equation

First in words:

penalty on update equals the importance score multiplied by the square of the change, scaled by a gate strength

Then the compact form:

penalty_i = importance_i * (theta_i - theta_old_i)^2 * gate_factor

Every symbol:

theta_ithe weight value now
theta_old_ithe weight value after the old task
importance_ithe Fisher-based score for weight i, high if it matters for old knowledge
gate_factora factor based on Tsallis entropy, tuned per weight to respect the distribution
penalty_ithe total cost of moving weight i
A tiny worked example
Weight w1: importance 8.0, wants to move 0.5 -> penalty 8.0 * 0.5^2 = 2.0
Weight w2: importance 0.2, wants to move 0.5 -> penalty 0.2 * 0.5^2 = 0.05
Weight w3: importance 0.1, wants to move 2.0 -> penalty 0.1 * 2.0^2 = 0.4
Same distance, but w1 is punished 40× harder. Training will move w2 and w3 freely but leave w1 nearly alone.

Weights that matter for old knowledge (high importance) are penalized harshly for moving, while weights that barely contributed (low importance) can flex without penalty.

What can go wrong

What can go wrong

Fisher matrix noise on small datasets. On small tasks, the Fisher matrix estimate becomes noisy, and importance scores become unreliable. The gate cannot distinguish essential from irrelevant weights, and forgetting creeps back in.
Tsallis entropy tuning required. The gate strength depends on a hyperparameter (the Tsallis entropic index). Poor tuning leaves either too much forgetting or too much plasticity loss. Different task sequences may need different tuning.
Late-task saturation. After many tasks, even low-importance weights accumulate small drifts. Over dozens of tasks, the model eventually still forgets, though more slowly than baselines.
Done right. When the Fisher estimate is stable and Tsallis tuning is thoughtful, MoCL preserves both old and new knowledge with minimal forgetting across sequential tasks.
What a runnable demo should prove

What a runnable demo should prove

A real demo trains a model on a sequence of classification tasks (e.g., CIFAR-100 split into 5 disjoint tasks, each with 20 classes). First, train on task 1 alone, record its accuracy. Then, train on task 2 while running MoCL gating, and re-test task 1 accuracy. Repeat for all tasks. The demo should show that task 1 accuracy stays high (e.g., stays above 80%) while task 2-5 accuracies also climb (e.g., each above 75%). Comparison baselines: naive sequential learning (accuracy drops to near random on old tasks) and frozen-weight methods (task 2+ accuracy stays low due to paralysis). MoCL should lie in the middle-high region: both old and new tasks score well.

forgetting = task1_accuracy_start - task1_accuracy_after_task5; plasticity = task5_accuracy; stability_plasticity_ratio = (task1_accuracy + task5_accuracy) / 2

What the demo must make impossible to miss: the model can learn new tasks without erasing old ones. Neither task dominates; neither is sacrificed.
