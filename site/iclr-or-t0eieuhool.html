Huxley-Gödel Machine: Self-Improving Coding Agents

A self-improving coding agent picks which edits to explore by measuring how promising each agent's entire family tree is, not just how well it passes tests.

Paper explainersAll themesLLMs & Foundation Models

Self-improving coding agents make edits to themselves and rank those edits by test scores. But test scores are a bad guide: an agent that tests poorly might create brilliant descendants, while a high-scoring agent might be a dead end. This paper proposes measuring something deeper: the productivity of an agent's family tree. By estimating this hidden metric, the system picks smarter edits and grows stronger agents faster.

Zero assumption version

Why test scores mislead self-improvement

Imagine a code-writing robot that edits its own files to pass tests. Every edit creates a fork: either the edit is accepted, or it is rejected, and new edits branch off. When the robot decides which fork to explore next, it picks the one with the highest test score. This seems sensible: a good score means a good agent.

But this fails. An agent with a medium test score might spawn three brilliant descendants that all score very high. Meanwhile, a high-scoring agent might be a specialist: great at the one test it was tuned for, but inflexible, unable to create diverse descendants. If the robot only chases high-scoring agents, it walks into dead ends and misses the family lines that will eventually dominate.

The mismatch: test performance does not measure self-improvement potential. We need to measure something else.

The real signal is not this agent's test score, but how productive its entire family tree is. Clade Metaproductivity (CMP): the aggregated success of an agent's descendants, used to guide which edits to explore next.

The algorithm as a flow

What it actually does

Start with an agent

The initial code-writing agent has never made edits.

Evaluate many branches

Generate many candidate edits and test each one separately, building a family tree.

Estimate family productivity

For each agent (parent), count the test successes of all its descendants. This is Clade Metaproductivity.

Pick the most fertile branch

Select the agent whose family tree is most productive, using a method that balances exploration and exploitation.

Repeat

Keep branching and re-scoring until the evaluation budget is spent.

What the paper changes

What the paper changes

The paper replaces the selection metric. Old methods rank agents by their own test score. This paper ranks agents by the aggregated success of their descendants—a deeper, forward-looking signal.

the object it moves  =  the selection metric for expanding the agent tree
The hidden quantity

Clade Metaproductivity: how fertile is this family?

measured quantity  =  Clade Metaproductivity (CMP)

CMP is a single number: the sum of all test successes earned by an agent and all of its descendants. Think of it like a family's total lifetime earnings across generations. An agent with high CMP is a progenitor of a productive lineage.

The paper estimates CMP by running tests on the descendants it has already generated. If an agent has spawned five children, and three of those children pass tests, and those three have spawned twelve grandchildren of which nine pass, then CMP is the sum: 3 (children) plus 9 (grandchildren) success events. An agent with high CMP has proven that it breeds success.

Plain reading. If you breed horses and want to know which stallion to breed next, do not just look at how fast that stallion is. Look at how fast its offspring are. CMP is that: the speed of the entire lineage.
Paper reading. CMP approximates the Gödel Machine's optimal policy (a theoretical ideal) by using only information the algorithm has already collected. Instead of computing an intractable proof, it estimates the self-improvement potential by aggregating observed outcomes down the family tree.
Why it works

Why measuring family productivity works

The problem is that test scores are local (one agent, one evaluation) but self-improvement is nonlocal (does this agent spawn better descendants?). A test score tells you how well this agent works today on a particular set of tests, but because each test only evaluates one agent in isolation, that score says nothing about its genetic potential or how good its descendants will be. An agent that is mediocre today might carry hidden traits—code structure, learned patterns, edit strategies—that allow its children to excel, because those traits create the foundation for better edits downstream. Measuring only the parent's score throws away that signal about future descendants.

CMP fixes this by looking ahead: it counts the successes of the entire subtree rooted at an agent. This way, if an agent's edits happen to create a genetic lineage of improving children and grandchildren, that fertility will show up in CMP and the algorithm will favor exploring that branch. The algorithm then uses a balanced sampling strategy (Thompson sampling) to explore the highest-CMP agents while still trying lesser-known branches. Over many iterations, because higher-CMP branches have already demonstrated fertile descendants, this steers the search toward the agent lineages that are most likely to produce even better descendants, by repeatedly choosing to expand from proven fertile ground.

Because the algorithm only expands agents whose family trees have proven productive, it wastes less time on dead-end branches and concentrates effort on the most fertile ground. This is why it finds stronger final agents while using fewer computational steps: fewer dead-end explorations means fewer wasted evaluations.

Math after the picture

Scoring family productivity

First in words:

For an agent in the tree, sum all the descendant successes. The CMP is the total count of test passes in the clade.

Then the compact form:

CMP(a) = successes(a) + sum of successes(child) for all children of a + sum of successes(grandchild) for all grandchildren of a + ...

Every symbol:

CMP(a)total test successes in the family tree rooted at agent a
successes(a)number of tests that agent a passed
childan agent created by editing agent a
grandchild, great-grandchild, ...descendants deeper in the tree
A tiny worked example
Agent A passes 2 tests. Its two children B and C each pass 1 test. B has no children. C has one child D which passes 3 tests. D has no children.
CMP(A) = successes(A) + successes(B) + successes(C) + successes(D) = 2 + 1 + 1 + 3 = 7.
CMP(C) = successes(C) + successes(D) = 1 + 3 = 4.
CMP(B) = successes(B) = 1.
Agent A's family is most fertile (7 total successes), so expand A's edits first.

CMP looks forward: it measures not how good an agent is, but how good its lineage will be.

What can go wrong

What can go wrong

Incomplete ancestry data. CMP is estimated from only the agents already evaluated. If an agent is new and has no descendants yet, CMP looks small even if it will create great ones later. Early in the search, the algorithm has to balance trusting the estimate with exploring uncertain agents. The paper uses Thompson sampling (random sampling from a belief about which agent is best) to handle this, but imperfect estimates can still mislead.
Evaluation budget constraints. The algorithm must finish within a fixed number of tests. If the search spends too much time on deep branches (measuring many grandchildren), it may not have budget to try new top-level edits. The paper manages this with an adaptive scheduling policy, but there is a hard trade-off between breadth (trying many first-edits) and depth (measuring descendants thoroughly).
Task diversity mismatch. CMP is based on how many tests pass, but tests are not all equally important. An agent might be good at one kind of coding task and terrible at another. If the test suite is skewed, CMP might reward an agent that is narrowly specialized. The measure of productivity depends on the measure of success.
Done right. If the test suite is balanced, evaluations are efficient, and the algorithm adapts its schedule, CMP correctly steers the search toward agents that produce the best descendants because CMP's aggregated score accurately reflects family fertility, allowing the algorithm to concentrate effort on the most reproducible genetic lines, and the algorithm finds stronger final agents.
What a runnable demo should prove

What a runnable demo should prove

Build a code generator (a small language model or a simple rule-based system) and have it make edits to a Python program. The edits are things like adding comments, refactoring variable names, adding type hints, or splitting functions. Define a test suite (e.g. unit tests the program must pass, or code-quality linters it must satisfy). Run the HGM algorithm: at each step, randomly pick an agent from the tree, make an edit, test it, record the result, and score each agent by its CMP (the aggregated test successes of its descendants). Compare against a baseline that picks agents by their own test score only. Measure: (1) how many evaluations are needed to reach a target quality, and (2) the final quality of the best agent found.

evaluations_to_target = number of tests run before any agent reaches the target quality; final_quality = best_test_score among all agents explored

HGM should require fewer evaluations to reach the target and should find a final agent that scores at least as high as the baseline, using less wall-clock time.
