SC²-WM: Self-Correcting World Model with Closed-Loop Feedback

A robot learns to correct its own navigation mistakes by using its world model to predict the future and catch when it is drifting off course.

Paper explainersAll themesRobotics & Control

A robot following a natural-language instruction in a real room must make constant navigation decisions despite only seeing its current view. Most robots run in open-loop—they commit to a sequence of moves without checking if they are still on the right path. This paper introduces SC²-WM, which uses an internal world model to spot when the robot has drifted or misunderstood its environment, then pauses to reconsider and correct the plan before executing the next move. The robot also learns to update its internal model when it detects confusion, making corrections smarter over time.

Zero assumption version

Open-loop navigation fails when the world is not what you expected

A robot hearing the instruction 'turn right and stop near the table' must decide exactly how many steps to take and in what direction. It sees only the room around it now, not what comes next. A beginner's solution: encode the instruction, predict the best direction, take a step, predict again, take another step. But if the room is partially blocked by clutter the robot cannot see from its starting spot, or if the instruction was ambiguous, or if a single misprediction cascades into a drift from the true path, the robot keeps committing to bad moves. It has no way to catch its own mistake mid-episode.

The core problem is partial observability. The robot does not see the whole room at once. It acts step-by-step. If its internal model of the room becomes wrong—if it thinks the table is ahead when it is actually to the left—it will never discover this until it crashes into something. By then the plan is ruined and the task fails.

The method in one sentence. Use a world model to predict what the next room state should look like if the plan is correct, compare it to the real observation, and if they mismatch, revise the plan before moving.

The algorithm as a flow

What it actually does

Encode the instruction and current view

Convert the language instruction and the robot's camera image into numerical representations.

Predict candidate future positions

Estimate reachable waypoints (locations the robot can move toward in the next few steps).

World model forecasts the next view

Use a learned model to predict what the room should look like from each candidate position.

Compare prediction to reality

Observe the real room after a candidate move; if the predicted view matches, continue; if mismatch, flag drift.

Refine the plan if needed

If mismatch signals drift, pause, update internal map and recompute the next move; if confidence is very low, also retrain the world model slightly on this new observation.

What the paper changes

What the paper moves: the navigation plan

Most methods produce a sequence of moves and execute them. This paper introduces a feedback loop that modifies the plan mid-episode before each action. If the world model's prediction does not match reality, the plan is revised because the mismatch reveals that the robot's understanding of where it is or where it should go is wrong. Additionally, the paper allows the world model itself to be lightly updated (adapted) during the episode when the mismatch signal is very large. This targeted retraining helps because the large mismatch signals that the model's stored knowledge of this environment is incomplete, and updating it on the current observation fills in the gaps without requiring full retraining from scratch.

The hidden quantity

The hidden quantity: prediction-reality mismatch

measured quantity  =  prediction-reality mismatch

The core idea is that the robot already knows what it expects to see if the plan is working. The world model predicts the visual features of the next room state from the current position and action. When the real observation arrives, we can compute how far off the prediction was—a mismatch signal. A large mismatch means the robot's internal model of the room or its position in it is wrong.

The paper measures this mismatch as the distance (the sum of squared differences in pixel features) between the predicted visual features and the actual visual features after a move. When mismatch is small, the plan is on track. When mismatch is large, something unexpected happened, so revise the plan.

Why it works

Why closed-loop correction works

In open-loop execution, a misprediction early on compounds: the robot moves to a wrong location, then predicts the next move from that wrong location, then compounds the error further. By the end, the trajectory is far from the goal.

Closed-loop correction breaks this chain. After each move, the world model predicts what the room should look like. If prediction and reality differ by a large amount, it signals that either the robot is at the wrong position or the world model is incomplete. The robot then revises the next move choice based on the true observation, not the drifted internal state. This limits the error at each step instead of letting it snowball, because the feedback loop keeps steering the robot back toward the true path whenever drift is detected.

For harder cases—where even the best move choice cannot explain the mismatch, because the world model is genuinely incomplete—the paper adds a second level: conditional world-aware adaptation. If the mismatch persists after replanning, the model is lightly updated (retrained for a few steps on this new observation) to learn the environment structure that was previously missing. This is done selectively: only when the mismatch signal is high enough to signal real insufficiency, to avoid overfitting to noise, because retraining on every quirk would make the model forget what it learned before.

Math after the picture

The prediction-reality comparison

First in words:

The mismatch is the squared distance between predicted visual features and observed visual features after the move: larger distance means the prediction failed, which signals a problem in the plan.

Then the compact form:

mismatch_t = ||d(s~_t+1) - v_t+1||^2_2

Every symbol:

s~_t+1the predicted internal state (a list of numbers representing the expected room state) after the move
d(s~_t+1)predicted visual features decoded from that internal state
v_t+1the actual visual features observed after the move
||...||_2the distance measurement: square each difference, sum them, take the square root (Euclidean distance)
A tiny worked example
Suppose the predicted image features are a list [5.2, 3.1, 8.4, 1.9] and the actual features are [5.0, 2.8, 7.2, 2.3].
Differences: [0.2, 0.3, 1.2, 0.4].
Squared: [0.04, 0.09, 1.44, 0.16].
Sum (mismatch) = 0.04 + 0.09 + 1.44 + 0.16 = 1.73. A larger value means the prediction was further off.
If another move predicts [5.0, 3.0, 8.3, 2.0] vs actual [5.1, 2.9, 8.2, 2.1], mismatch = 0.01 + 0.01 + 0.01 + 0.01 = 0.04—much better.

High mismatch signals that the plan is steering the robot into an unexpected environment, so revise before the next step.

What can go wrong

What can go wrong

Prediction itself is bad early in training. If the world model is poorly trained, it will make confident wrong predictions. The mismatch signal will be noisy and unreliable, leading to false alarms, because an untrained model gives wrong predictions for many scenarios, making it hard to distinguish real drift from harmless prediction noise. Fix: pre-train the world model on diverse trajectories before deployment, so it reliably predicts the common environments, or use adaptive learning to build confidence gradually as the model improves.
Mismatch threshold is hard to tune. If the threshold for 'mismatch is high enough to trigger revision' is too low, the robot revises on every tiny noise and wastes computation. If too high, it ignores real drift. Fix: use principled thresholds or learned confidence bounds, not hand-tuned values.
Adaptation at test time can overfit. If the world model is updated on a single unusual observation without safeguards, it may overfit and lose generalization. For example, if a shadow makes the predicted view of the table look different once, retraining on that one shadow could wreck predictions for normal tables. Fix: the paper addresses this by only adapting when mismatch is very high and uses conservative learning rates, but there is still risk.
Done right. Strong pre-training of the world model, learned thresholds for adaptation triggers, and careful separation between replanning (always safe, just recomputes the next move based on actual observations) and model adaptation (done selectively when confidence is very low) all work together to make the method reliable, because every guard is there to catch real problems without triggering on noise.
What a runnable demo should prove

What a runnable demo should prove

Build a simple simulated room with an instruction ('go to the table in the corner'). Create an open-loop baseline that commits to a fixed sequence of moves without feedback. Then add SC²-WM: after each move, the robot predicts the next view, compares to reality, and revises the plan if they mismatch. Log the number of successful completions and the trajectory length in both cases. The demo should show that closed-loop dramatically reduces failed episodes (e.g., 60% success vs 30%) and that the trajectories align with the ground truth path instead of drifting sideways.

success_rate = (number of episodes reaching the goal) / (total episodes); trajectory_drift = average distance from true path to predicted path

A working demo makes obvious that mismatch feedback stops the robot from confidently walking off a cliff it cannot see.
