MobileIPL: Teaching Mobile Agents to Think Better

Score the final action, then trace backward through the reasoning tree to score each intermediate thought, and use those scores to train better reasoning.

Mobile agents that look at phone screens need to explain their reasoning step by step. The problem: they lack diverse examples of good reasoning, and even with more training data, it is hard to know which intermediate thinking steps actually matter. Zero assumption version

Reasoning without a guide

Mobile agents that interact with phone screens need to think through their actions step by step: look at the screen, decide what the goal is, figure out what button to press. The agent learns from examples of successful actions, but there is a catch: training data is scarce and expensive to collect. A beginner might try to just show the agent more examples of good actions, but this does not work well because the agent does not learn to think the same way humans do. It memorizes actions instead of developing reasoning steps.

The real problem is worse: even with more examples, nobody tells the agent which intermediate thinking steps were correct. The agent might think Step A, then Step B, then press Button C. Button C was right, but was Step B actually helpful? Was Step A clear? Without this fine-grained feedback, the agent treats all reasoning steps as equally valuable and does not improve its thinking, because during training it has no signal to distinguish which steps contributed to the success versus which were noise.

The method in one sentence. Score the final action, then trace that score backward through the reasoning tree so that each intermediate step knows whether it helped or hurt.

The agent learns to prefer high-value reasoning paths over low-value ones.

The algorithm as a flow

What it actually does

Collect reasoning trees

For each goal, sample multiple complete reasoning trajectories (each reasoning step leading to an action sequence).

Score the leaves

For each final action, check if it is correct; assign a reward: high for right actions, low for wrong ones.

Trace value backward

Compute each intermediate reasoning step's value by averaging the values of the actions it led to.

Build training pairs

Create preference pairs: a high-value reasoning path vs. a low-value one, both leading from the same earlier step.

Train the model

Update the agent to prefer high-value reasoning over low-value reasoning using these preference pairs.

What the paper changes

What the paper changes

MobileIPL does not change which buttons the agent presses. It changes the reasoning steps—the intermediate thoughts the agent generates before it acts. By scoring and training on these intermediate thoughts, the agent learns to think more like a human, not just guess the right action.

the object it moves  =  Reasoning steps
The hidden quantity

The step value: which intermediate thoughts matter

measured quantity  =  Step value (the contribution of each reasoning step)

The paper measures something that was never explicitly named before: the value of each intermediate reasoning step. A valuable step is one that, when included in a reasoning tree, consistently leads to correct actions, because that step filtered out bad directions or clarified the goal in a way the subsequent steps could build on. A low-value step does the opposite, either confusing later steps or pointing them toward wrong answers. By computing this value for every intermediate thought, the agent can learn which reasoning patterns work.

MobileIPL estimates step value by averaging the outcomes of all reasoning trees that included that step. If a step appeared in five different paths and four of them succeeded, that step gets a higher value than a step that appeared in paths with a 2/5 success rate. The paper then propagates this value backward through the tree using a simple average rule, treating earlier steps as contributions to their descendants.

Plain reading. Step value is how much a particular reasoning thought contributes to getting the final action right. High-value thoughts are the clear, honest reasoning steps that lead to correct button presses.
Paper reading. The paper computes step value recursively: the value of a leaf node is the reward of the action it produces (correct vs. incorrect); the value of an earlier step is the average of all its child nodes values, scaled by a discount factor.
Why it works

Why the method works: credit where credit is due

The core insight is simple: if you know the final action was correct, you can work backward and credit the reasoning steps that led there. The agent learns faster because it no longer treats all reasoning paths as equally valid—it learns which intermediate thoughts matter.

Here is the chain of causation. The agent generates multiple possible reasoning trees for the same starting screen. Each tree ends in an action (button press). By checking whether each action matches the correct answer, the paper assigns a simple reward: +1 if correct, 0 or -1 if wrong. The paper then uses a clever averaging rule: an intermediate step is valued as the average of all the steps that followed it. This backward pass ensures that an early reasoning step that appeared in many correct solutions gets a high value, while one that mostly led to wrong actions gets a low value. Finally, the agent is trained using preference learning: when two reasoning paths start identically but diverge, the agent learns to prefer the path that led to a higher-value action. Over multiple rounds, the agent refines its reasoning to favor the paths that work.

Math after the picture

The value-tracing formula

First in words:

value of an intermediate step equals the discount factor times the average value of its child steps

Then the compact form:

v(step_t) = c * (1/K) * sum_k v(step_t_k)

Every symbol:

v(step_t)the value assigned to reasoning step t
cdiscount factor (a number less than 1, typically 0.9 or 0.95)
Kthe number of child steps sampled from step t
step_t_kthe k-th child step following step t
A tiny worked example
Imagine step A generates two possible continuations: step B1 and step B2.
Step B1 leads to a correct action (value = 10), step B2 leads to an incorrect action (value = 2).
With c = 0.9 and K = 2: v(A) = 0.9 * (1/2) * (10 + 2) = 0.9 * 6 = 5.4.
Step A is assigned value 5.4, which is the weighted average of its children.
If we had a third child C with value 8, then v(A) = 0.9 * (1/3) * (10 + 2 + 8) = 0.9 * 6.67 = 6.0.
The value propagates upward, so early steps in high-value paths are rewarded without manual annotation.

The discount factor c prevents early steps from being overvalued; averaging ensures that a step is judged by the diversity of outcomes it led to.

What can go wrong

What can go wrong

Shallow reasoning trees. If the agent only generates one or two reasoning steps before acting, there is little to score and trace backward. The method works best when agents naturally produce rich, multi-step reasoning.
Incorrect ground truth. If the benchmark labels are wrong, the value tracing assigns high value to bad reasoning. The method is only as good as the labeled data.
Reward function too coarse. A reward that only checks the final action right/wrong misses partial credit for reasoning steps that were on the right track but chose a slightly wrong button.
Done right: diverse sampling. When the agent explores many reasoning paths for each screen, the averaging in value tracing becomes reliable, and the agent learns to consistently choose reasoning that works.
What a runnable demo should prove

What a runnable demo should prove

Build a simple mobile task: a screen with labeled buttons and a goal (Press the blue button three times, then press Settings). Sample 10 different reasoning paths for each step, where each path generates different intermediate thoughts. Assign a reward to the final action: +1 if correct, 0 if wrong. Trace the values backward using the formula above. Train the agent for two rounds using the preference pairs. The demo should show that after the first round, the agent presses the correct button more often. After the second round, it should reason more like a human, naming the button color or purpose before acting.

Reasoning quality = (correct actions after round 1) minus (correct actions before training), then subtract (actions that reached the goal within 5 steps before training) to confirm the agent is not just lucky

What makes this work: a backward pass through the reasoning tree assigns credit to the steps that worked, without needing a human to annotate each intermediate thought.
