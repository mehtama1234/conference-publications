Path Channels and Plan Extension Kernels

A trained game-playing network hides its plans as specific patterns in its memory, and extends them using learned rules that work like a two-way push from boxes and goals.

Paper explainersAll themesInterpretability

When you teach a neural network to play Sokoban (a box-pushing puzzle game) using reinforcement learning, it learns to plan which moves to make. But where does it store that plan inside its brain? This paper reverse-engineers the network's actual memory to find that plans live in specific channels (think of them as filing cabinets), and the network expands those plans using learned rules that work like propagating waves outward from goals and boxes—then bouncing back when they hit a wall.

Zero assumption version

Neural networks learn in the dark

When you train a network to play a puzzle game using reinforcement learning (a trial-and-error method where you reward good moves and punish bad ones), the network learns to win. But we have almost no idea how it does it. The network keeps its strategy locked inside billions of numbers called weights and activations (the intermediate calculations it makes while thinking). A beginner might hope the network stores an explicit plan—like a checklist of moves—but that seems too organized for something trained randomly. More likely, the network hides its planning scattered across thousands of interconnected pieces. Understanding the real mechanism would let us trust, predict, and maybe control what the network does.

The naive approach: look at the network's weights and activations and try to describe them. Weights are numbers that define how information flows between layers; activations are the numbers the network computes at each step. But there are so many of them that this is like reading a phone book—true but useless. We need to find the hidden structure: which parts do the planning, and how do they actually work?

In one sentence. The paper found that plans are stored as activations in specific channels, and the network extends them using learned rules (shifting and combining nearby values) that work like a two-way wave.

What the paper changes

What the paper moves

The paper changes how we look at a trained network. Instead of reading all its weights and activations as a black box, it identifies specific channels (slices of memory) that carry plan information, and interprets them as a structured planning algorithm.

the object it moves  =  plan representation
The hidden quantity

The path channel activation: where plans hide

measured quantity  =  channel activation for a given location and direction

A path channel is a specific slice of the network's hidden state (memory). At each location on the board, each channel stores a number (an activation) that represents whether that location in that direction is part of the plan. A high activation means: when a box sits here, push it in this direction.

The paper measures this by ablating (removing) one channel at a time and checking how much the network's planning accuracy drops. If removing channel 5 makes the network forget how to push boxes left, then channel 5 is the left-push-path channel.

Why it works

How planning unfolds through layers

The network starts with an observation (the board state). It passes this through an encoder (a simple layer that looks at nearby pixels and combines them, with no activation function, so it is just linear math). Then the network runs three memory layers three times in a row—nine passes total per decision.

During these passes, the network constructs the plan in two directions at once. Starting from the locations of the boxes, it propagates forward activation in path channels (this says: from the box, we can push in direction X). Separately, starting from the goal location, it propagates backward activation (this says: the goal is reached via direction Y). These waves travel through convolutional kernels—learned rules that copy and shift the activation one square at a time.

When either wave hits an obstacle (a wall or immovable block), the network places a negative value there. This negative value acts like a stop sign. The kernel rules use the negative value to propagate backward, which cancels the forward wave—this is backtracking. It lets the network explore alternative plans. After nine passes, all plans are explored and pruned. The final MLP head reads the remaining positive activations in all channels and decides which move to make.

Math after the picture

The extension kernel rule

First in words:

activation_new = convolution_kernel * activation_old + negative_obstacle_value_if_present

Then the compact form:

h_n^d = conv_k(h_n^{d-1}) + w_obs * obs_neg

Every symbol:

h_n^dthe hidden state (activations) at layer d after pass n
h_n^{d-1}the activations from the previous layer at the same pass
conv_kthe learned convolutional kernel—how to shift and combine nearby activations
w_obsa weight controlling how strong the obstacle blocking is
obs_negnegative one at any obstacle location, zero elsewhere
A tiny worked example
Suppose the box is at position (3, 5) and the right-channel activation is 0.8 at that spot.
The right kernel shifts this 0.8 one square right to position (3, 6). The kernel is learned to preserve magnitudes, so activation at (3, 6) becomes 0.8.
If there is a wall at (3, 7), we place obs_neg = -1 there. The kernel tries to shift the 0.8 to (3, 7) but the negative value cancels it: 0.8 + (−1) = −0.2.
The negative activation propagates backward left, canceling activations at (3, 6) and (3, 5). The backtracking is complete; this direction is pruned.

The kernel is just multiplication and addition (convolution), so activations propagate and cancel without any learned switching logic.

What can go wrong

What can go wrong

Channels not cleanly separated. In a different network or training regime, path channels might overlap or encode multiple concepts, making the channel interpretation fragile.
Backtracking fails on complex layouts. If many obstacles create long chains of negative values, the cancellation waves might not converge cleanly within the nine passes, leaving the plan ambiguous.
Generalization to unseen puzzle sizes. The learned rules are fixed-size, so a network trained on small boards (say twenty by twenty squares) may fail on larger boards (thirty by thirty squares) where plans are longer.
Correctly interpreted. When channels are well-separated and obstacles are moderate, the mechanism is transparent and lets you predict or even edit the plan by hand.
What a runnable demo should prove

What a runnable demo should prove

Build a minimal Sokoban solver that stores plans explicitly: one channel per direction. At each step, propagate activations from the box in all four directions, marking which squares can be reached. When you hit an obstacle, mark it negative and backtrack. After a fixed number of iterations, read off the activation values and pick the direction with the highest activation at the box location. Compare this naive explicit planner to a trained ConvLSTM network. You should see that the trained network is doing mechanically similar operations—just learned and embedded inside its weights.

generalization_accuracy = (boxes_on_unseen_boards_where_plan_succeeded) / (total_unseen_boards)

The demo must show that the explicit plan mechanism and the trained network produce the same moves on new puzzles, proving the interpretation is real.
