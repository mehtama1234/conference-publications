Aegis: Automated Error Generation for Multi-Agent Systems

When multiple language models work together as a team, you can automatically generate faulty versions of successful runs to teach another model which agent made which mistake.

Paper explainersAll themesAgents & Tool Use

Large language model teams (multi-agent systems) can solve complex problems, but when something breaks, figuring out which agent failed and why is nearly impossible to debug by hand. The Aegis framework solves this by automatically creating 9,533 failure examples: it takes successful runs and injects realistic errors into them, then uses those synthetic failures to train a model to pinpoint which agent broke and how.

The debugging bottleneck

Multi-agent systems run multiple language models in sequence — one agent searches for information, another analyzes it, a third makes a decision. When the final answer is wrong, you cannot tell which step failed. A naive fix would be to manually run each agent in isolation and test it by hand, but that takes enormous time and only works for a few specific errors.

The real blocker: there is almost no data of real failures in multi-agent systems. Training a model to spot errors requires thousands of labeled examples (successful runs paired with which agent broke), but those examples are expensive to create by hand. Without that data, you cannot build a debugger.

The method in one sentence. Automatically inject realistic errors into working agent runs to generate thousands of labeled failure examples, then train a model to predict which agent broke and why.

The algorithm as a flow

What it actually does

Collect successful runs

Record complete traces where all agents worked correctly and produced the right answer.

Inject errors automatically

Use a language model to corrupt one agent's output in realistic ways (e.g., wrong reasoning, missed detail, wrong choice), creating a plausible failure.

Label each failure

Record which agent was broken, what type of error was injected, and what the broken output was.

Train an error detector

Use the 9,533 synthetic failures to train a model to read a broken run and predict which agent and which error type caused the problem.

Reuse the trained model

When a real system fails, feed the broken run to the error detector and get back which agent to fix.

What the paper changes

Instead of manually annotating when real multi-agent systems fail, Aegis generates the failure data automatically. You can inject errors into successful runs using a language model, and those synthetic failures teach error detection nearly as well as hand-labeled real failures.

The hidden quantity

The hidden quantity: agent responsibility

measured quantity  =  Which agent caused the observed error

When a multi-agent system produces a wrong answer, multiple things could have gone wrong upstream: Agent A might have missed a detail, Agent B might have misinterpreted it, Agent C might have chosen poorly. The hidden quantity Aegis measures is the responsibility score — which agent is most likely responsible for the final error, and what kind of failure did it commit?

The paper estimates this by training a model on synthetic failures where the error source is known (because Aegis injected it). The model learns patterns: when Agent B's output is incoherent, it predicts Agent B is responsible; when Agent C's reasoning is absent, it predicts Agent C. The training data is synthetic, but the learned skill — spotting error patterns in chains — transfers to real failures.

Why it works

Why this works: synthetic data teaches real debugging

The core mechanism is substitution: if a model learns to detect errors on synthetic failures (where we control exactly what broke), it will spot those same error patterns in real failures. Why? Because the error patterns are real — when you inject an error into an agent's output by corrupting its reasoning, you are creating a plausible real error; a model trained to spot corrupted reasoning will catch similar corruption in genuinely failed runs.

The second part of the mechanism is diversity. Because Aegis injects errors adaptively (using a language model to generate context-aware corruptions), the 9,533 synthetic failures cover many types of errors: hallucinations, missed details, wrong reasoning steps, contradictions, and so on. A model trained on that variety learns to recognize all those failure modes, not just a few.

The training objective

First in words:

For each agent in the broken run, compute a score measuring whether that agent is responsible for the error. The supervised learning objective is: minimize the cross-entropy loss between the predicted agent responsibility and the true injected agent. For reinforcement learning, reward the model when it correctly identifies the broken agent. For contrastive learning, push representations of broken runs closer to representations of the same error type.

Then the compact form:

L_supervised = -log P(agent_broken | trajectory_broken) + lambda * L_regularization

Every symbol:

agent_brokenthe ground-truth agent that was corrupted during data generation
trajectory_brokenthe full multi-agent run with one agent's output corrupted
P(agent_broken | trajectory_broken)the probability the model assigns to the correct agent being responsible
L_regularizationa regularization term to prevent overfitting (e.g., weight decay)
lambdahyperparameter controlling how strongly to regularize
A tiny worked example
Suppose Agent B was injected with an error. The model reads the broken trajectory and predicts: P(Agent A responsible) = 0.1, P(Agent B responsible) = 0.7, P(Agent C responsible) = 0.2.
The true label is Agent B, so we compute cross-entropy: -log(0.7) ≈ 0.36. The loss is 0.36.
If the model had predicted P(Agent B) = 0.9, the loss would be -log(0.9) ≈ 0.11. Lower loss means better prediction.
Training reduces the loss by adjusting the model's weights so it more confidently identifies the truly broken agent.

The model learns to map broken trajectories to the correct agent by minimizing prediction error on 9,533 synthetic examples, then applies the same skill to real system failures.

What can go wrong

What can go wrong

Synthetic errors do not match real errors. If the language model that injects errors generates unrealistic corruptions (e.g., errors that are too obvious or too subtle), the trained error detector will not transfer to real failures. Aegis mitigates this by using an adaptive error injector that generates context-aware corruptions matching the agent's typical failure modes.
Error type mismatch. The model may be trained on hallucinations but encounter reasoning failures in production. If the error injection is not diverse enough, the detector will fail on new error types it has never seen. Aegis addresses this by covering many task domains and architectures in the 9,533 examples.
Agent interdependency ignored. Errors propagate: if Agent A produces a wrong intermediate result, Agent B's output becomes invalid through no fault of its own. The model must learn to trace responsibility backward, not just flag the first agent it sees as broken. This requires the training data to include cascading failures.
Done right: Aegis trains on diverse error types across many task domains, uses an adaptive error injector to generate realistic corruptions, and includes cascading failures in the synthetic dataset. This combination ensures the trained detector recognizes a wide range of real failure modes and can correctly attribute errors even when they propagate through the agent chain.
What a runnable demo should prove

What a runnable demo should prove

A minimal demo would: (1) define a three-agent system (search, analyze, decide); (2) create 10 successful runs; (3) use Aegis to inject errors into each (e.g., corrupt the search results, the analysis, or the decision) and label the broken agent; (4) train an error-detection model on these 30 synthetic failures; (5) create a new successful run, corrupt it with an error the model has never seen during training, and verify that the model correctly identifies which agent broke.
