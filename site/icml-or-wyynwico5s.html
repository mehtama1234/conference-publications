MOC: Multi-Order Communication in LLM-based Multi-Agent Systems

Let each agent receive not only its neighbors' latest messages but also a structured summary of evidence arriving through longer paths in the graph.

Paper explainersAll themesAgents & Tool Use

Most multi-agent systems pass messages one hop at a time. An agent reads what its direct neighbors just said and reasons from that local view. The problem is that important evidence may live two or three hops away, and by the time it travels through repeated direct concatenation, the detail is diluted or dropped. MOC rebuilds communication around multi-order evidence streams, so an agent can receive information that reflects both direct neighbors and farther parts of the graph. It then merges that broader evidence carefully so the system stays within budget while keeping the most important content.

Why one-hop message passing loses important evidence

In a standard multi-agent graph, an agent usually receives the latest outputs from its immediate neighbors and appends them into one combined message. That design has a narrow receptive field because the agent sees only one-hop information directly. If an important fact is discovered farther away, it must pass through several intermediaries before arriving.

That long path introduces two problems. First, the evidence weakens because each intermediate agent may summarize it differently or omit it entirely. Second, direct concatenation scales poorly, because adding more neighbors or longer paths produces larger and messier message bundles. MOC addresses both by constructing a structured multi-order evidence stream and then merging it under a fixed budget.

The basic idea. An agent should reason from information gathered across several communication orders, not only from the latest one-hop messages.

What the paper changes

What the paper changes

The paper changes how inter-agent messages are formed. Instead of a plain concatenation of neighbor outputs, each agent receives a merged stream that explicitly includes multiple communication orders.

the object it moves  =  the message each agent receives from the communication graph
The hidden quantity

The hidden quantity

measured quantity  =  effective evidence reach

The true limit of a multi-agent system is often not the number of agents but how far usable evidence can travel before it becomes too weak or too expensive to keep. Effective evidence reach is the distance over the graph at which information still arrives in a form that can change the receiver's reasoning.

MOC raises this reach by preserving multi-hop evidence explicitly instead of hoping it survives repeated one-hop concatenation. The merge step matters because wider reach is only useful when the extra evidence still fits inside the message budget and remains readable to the receiving agent.

Why it works

Why multi-order communication helps

The one-hop baseline is weak because it treats every round as local. A receiving agent sees what its neighbors chose to say, but it has no direct handle on farther evidence. Important facts may be summarized away before they arrive. MOC fixes that by keeping communication order explicit. Evidence from different distances is gathered into a structured stream rather than mixed immediately into one long block.

The semantic-topological merge step is the second important part. Simply forwarding everything from many orders would explode the message size. The merge step keeps the content that best preserves meaning and graph position under a fixed budget. This is why the paper can report both better task performance and lower communication cost: wider evidence reach helps decisions, and the merge step prevents that wider reach from becoming uncontrolled overhead.

Math after the picture

A compact multi-order sum

First in words:

received evidence = merged contributions from several communication orders

Then the compact form:

Message_i = Merge(sum_k alpha_k * OrderEvidence_i^(k))

Every symbol:

Message_ithe final message delivered to agent i
OrderEvidence_i^(k)the evidence that reaches agent i from communication order k
alpha_khow strongly order k contributes before merging
Merge( )the budget-aware procedure that preserves the most useful content
A tiny worked example
Suppose agent B receives 40 units of useful content from direct neighbors and 30 units from two hops away.
Set alpha_1 = 1.0 for direct neighbors and alpha_2 = 0.8 for two-hop evidence.
Before merging, the combined stream value is 1.0 x 40 + 0.8 x 30 = 64.
If the message budget can hold only 45 units, Merge keeps the highest-value pieces from both orders instead of copying everything.
That preserves some far evidence because it may correct or complete the near evidence.

The equation expresses the main design: several communication orders contribute to one received message, then a merge step compresses them under budget.

What can go wrong

What can go wrong

Too many orders can add noise. If very distant evidence is always included, the receiving agent may get extra detail that does not help the current decision because the far context is only weakly related.
A weak merge can erase the benefit. If the merge step keeps only short or frequent content, it may drop the rare fact that made far evidence valuable in the first place.
Graph structure may shift during reasoning. The most useful order today may be different later, because new evidence changes which agents hold the decisive information.
Done right. The system should adapt how much weight each order receives and should keep the merge focused on evidence that changes the final decision, not on content that is merely longer or more common.
What a runnable demo should prove

What a runnable demo should prove

Build a five-agent reasoning graph in which each agent sees only part of the full evidence and some decisive facts begin two hops away from the final decider. Compare a one-hop concatenation baseline against a multi-order stream with a budget-aware merge.

Measure answer quality, how often far-away correcting evidence reaches the final decider, and total communication cost. The demo should show that multi-order communication helps because some correct decisions need evidence that does not live in the immediate neighborhood.
