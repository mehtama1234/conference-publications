RL of Thoughts: Adaptive Reasoning Paths for LLMs

A tiny RL-trained navigator learns which reasoning steps work best for each problem, steering the LLM through task-specific paths instead of using the same fixed structure for everything.

Paper explainersAll themesReinforcement Learning

LLMs reason step-by-step, but the same reasoning path does not work for all problems. Methods like Chain-of-Thought use identical structures everywhere, wasting time on steps that are not needed. This paper trains a microscopic RL navigator (under 3,000 numbers) to watch the problem and pick the right sequence of reasoning moves for this specific task.

Zero assumption version

Fixed reasoning paths do not fit all tasks

Today, when an LLM solves a math problem or a logic puzzle, it uses the same recipe every time: think one step, think another step, think a third step. These fixed templates—Chain-of-Thought, Tree-of-Thought, Graph-of-Thought—work reasonably well and do not require retraining the LLM.

But different problems need different moves. Some need you to break the problem into smaller pieces first. Some need you to check your work at each stage. Some need you to argue both sides before deciding. A one-size-fits-all template wastes time and often leads the LLM down wrong paths.

The naive try. Use the same Chain-of-Thought for every problem, no matter what.

The algorithm as a flow

What it actually does

1. Read the problem

The navigator sees what the LLM is trying to solve (math, logic, trivia).

2. Pick a reasoning block

The navigator chooses one of five reasoning moves: Reason, Refine, Decompose, Debate, or Terminate.

3. Run the move

The LLM takes a step using that move—either one more reasoning step, or checking and polishing earlier work, or breaking the problem up, or considering objections.

4. Score what happened

The LLM assigns marks to its own progress (1 to 3 for correctness of calculation, clarity of thinking).

5. Loop until done

Navigator reads the score and decides: pick another block, or stop.

What the paper changes

What the navigator moves

The navigator does not change the LLM itself—it leaves all the LLM's billions of numbers alone. Instead, it chooses which of five reasoning moves to apply next. Each move is a different prompt telling the LLM to reason in a different way.

the object it moves  =  Reasoning move sequence
The hidden quantity

The navigator's decision signal: reasoning state

measured quantity  =  Reasoning state (problem + progress score)

At each step, the navigator needs to decide which move comes next. To make that choice, it needs to know: what problem are we solving, and how well is it going? This bundle of information—the problem type and a numerical score for how correct and clear the LLM's reasoning has been so far—is the hidden quantity. It is the input that the navigator reads to pick the next move.

During training, the paper uses a method called a Process Reward Model (a neural network trained to score reasoning steps). At inference time, the LLM itself assigns scores (1 to 3) for how correct and clear its own work is, and the navigator feeds those scores into its decision-making.

Why it works

Why picking the right move per task fixes the problem

The root cause of the original problem is that a fixed reasoning path treats all tasks the same. Some tasks—multiplying two numbers—need only one or two Reason steps, but the fixed template wastes steps on unnecessary Refine or Debate blocks. Other tasks—solving a complex logic riddle—need Debate early to explore different angles, but Chain-of-Thought never offers that.

The navigator learns to match the reasoning structure to the task, for two reasons. First, training with reinforcement learning lets the navigator see which reasoning sequences lead to correct answers and which do not. The navigator gets reward when the LLM arrives at the right answer, and no reward (or penalty) otherwise. Over many problems, the navigator learns: for problems like this, Decompose-then-Reason works; for problems like that, Reason-then-Debate works. Second, the navigator is tiny (just 3,000 numbers in a three-layer network), so it cannot memorize the training problems. Instead it learns rules—if the problem is a logic puzzle and reasoning clarity is below 2, pick Debate; if calculation correctness is already 3 and we have taken three steps, pick Terminate. These rules transfer to new problems and new LLMs because the rules are generic patterns, not memorized answers.

The training equation

First in words:

The navigator learns by maximizing expected reward over reasoning steps. At each step, reward is 1 if final answer is correct, 0 otherwise. The navigator's network estimates the sum of future rewards (value) for each possible move given the current state.

Then the compact form:

V(s) = E[sum_t gamma^t * r_t] where V is estimated value, r_t is reward at time t (1 at correct final answer, 0 otherwise), gamma is discount factor, and s is reasoning state

Every symbol:

V(s)value: sum of discounted future rewards from state s
r_treward at time t (1 if final answer correct, 0 if wrong)
gammadiscount factor (how much past steps matter vs. immediate success)
sstate: problem type plus reasoning quality score
A tiny worked example
Problem: compute 7 times 89. Navigator state shows: math problem, clarity=2, steps taken=1.
Value of move Reason: if we reason one more step, we will likely reach correct 623, then reward=1. Total value: 1.
Value of move Terminate: if we stop now, the answer is incomplete, reward=0. Total value: 0.
Navigator picks Reason because its value (1) is higher than Terminate (0).
After the LLM reasons and produces 623, navigator state now shows: clarity=3, steps=2.
Value of Terminate is now 1 (correct). Navigator picks Terminate and stops.

The navigator learns to steer the LLM toward correct answers by estimating how likely each move is to lead to reward.

What can go wrong

What can go wrong

Navigator trained on one LLM, used on another. If the navigator learns to pick moves for GPT-4, will its choices work for Llama? The paper shows it does transfer, because the navigator learns generic patterns (not model-specific tricks). But a navigator trained on a very different LLM family might fail.
Navigator trained on one task, used on another. If trained only on math, the navigator might pick moves that worked for algebra but fail on a history question. The paper shows strong transfer across different reasoning benchmarks, but severe domain mismatches could break it.
Navigator makes a wrong call early. If the navigator picks Terminate too early, the reasoning stops before completion. Unlike retraining the LLM (which is costly), retraining the navigator is cheap, but one bad navigator on one task still produces wrong answers.
Done right. Train the navigator on representative problems from your tasks and LLMs. The navigator is tiny enough that you can retrain it cheaply if accuracy drops. Use self-assigned LLM scores for state feedback, which are available at no extra cost.
What a runnable demo should prove

What a runnable demo should prove

Build a simple problem set with two types of reasoning tasks (e.g., multi-digit arithmetic and logical deduction). Implement the five basic logic blocks (Reason, Refine, Decompose, Debate, Terminate) as different prompts. Train an RL navigator on a subset of problems from each type. Then run the navigator on held-out problems and measure: how many are solved correctly, and how many reasoning steps were needed on average. Compare against Chain-of-Thought (same sequence for all problems).

improvement = (acc_navigator_on_task - acc_chain_of_thought_on_task) + (steps_chain_of_thought - steps_navigator) / 10

The demo must show that the navigator picks different move sequences for different tasks, and that those tailored sequences outperform the fixed template on both accuracy and step count because each task's structure is matched to its reasoning needs.
