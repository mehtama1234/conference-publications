SALAAD: Sparse And Low-Rank Adaptation via ADMM for Large Language Model Inference

SALAAD trains one model so its weights can be thinned into sparse and low-rank forms across many memory budgets, without retraining for each budget.

Paper explainersAll themesOther

Large language models often need several deployment versions: a fuller version for roomy hardware and a thinner version for tight memory limits. Standard practice handles that with separate pruning rules, separate low-rank adapters, or repeated retraining. SALAAD tries to make the structure itself trainable. During learning, it pushes weights toward two forms that save memory at use time: many zeros and low-rank factorizations, which means a large table is approximated by the product of two smaller tables. The paper frames that push as a constrained optimization problem and uses ADMM to keep task loss and structure pressure in balance.

Zero assumption version

Why one deployment budget is not enough

A large model weight table may be too expensive for some devices even if the model is accurate. Two common ways to shrink it are sparsity, which means many entries are forced to zero, and low-rank structure, which means a large table is replaced by two smaller tables whose product approximates the original.

The problem is that different layers tolerate different amounts of shrinking. One layer may handle aggressive sparsity well, while another may lose quality immediately. A fixed manual recipe therefore wastes capacity in some places and damages performance in others.

The deployment problem is harder because teams usually need many model sizes. If every memory target needs its own training run, the engineering and compute cost grows quickly. The paper wants one training run that already contains a whole range of usable capacities.

The paper in one sentence. SALAAD learns the task while simultaneously pushing each weight table toward sparse and low-rank forms, then adapts the strength of that push so one run yields many deployment sizes.

The algorithm as a flow

What it actually does

Keep the original task objective

Train the model on its normal prediction loss so the base behavior stays tied to the real task.

Create structured copies of each weight table

For the same table, maintain a sparse version and a low-rank version, which means the method tracks compressed candidates during training instead of after training.

Use ADMM to tie them together

ADMM alternates updates so the dense weights can fit the task while the structured copies enforce the compression targets.

Adapt the penalty strength

A controller changes how hard the optimization pushes toward the sparse and low-rank forms, because different training phases and layers need different pressure.

Export a whole capacity curve

After training, choose the operating point whose memory use fits the target device, because the run already produced a continuum of structured models.

What the paper changes

What the paper changes

The paper changes compression from a hand-written postprocessing step into a training-time constrained learning problem. Model size is not decided only after the model is finished; it is shaped throughout training.

The hidden quantity

The hidden quantity: effective capacity

measured quantity  =  how much useful freedom each layer still has

The quantity that matters is not just the raw number of stored weights. It is the effective capacity of each layer: how many independent degrees of freedom remain after zeros and low-rank structure are imposed.

SALAAD does not set one global capacity level and leave it fixed. It lets different layers settle at different points, because the optimization keeps checking whether more structure saves memory without hurting the task too much.

Paper reading. Sparsity removes entries entirely, while low-rank structure restricts a weight table to combinations of a smaller set of directions. SALAAD learns both constraints jointly and monitors how strongly to enforce them.
Why it works

Why ADMM plus adaptive control helps

The tension in this problem is direct. Task learning wants whatever weight pattern reduces prediction loss. Compression wants those same weights to live inside restrictive sets: sparse tables and low-rank tables. If the compression pressure is applied crudely, training can become unstable or can damage layers that are still learning basic task structure.

ADMM helps because it separates the roles. One set of variables can focus on fitting the task, while companion variables represent the structured targets. The optimization then penalizes disagreement between them. That split matters because projection onto the structured sets can be handled explicitly, rather than forcing ordinary update steps from the loss slope to satisfy every requirement at once.

The adaptive controller matters because the right penalty is not constant. Early in training, the model may need more freedom to learn the task at all. Later, stronger structure pressure may be affordable because the model has already learned a usable task solution and can give up extra capacity with less damage. Layer heterogeneity matters for the same reason: one table may absorb sparsity easily, while another may need rank reduction instead of zeros.

A single run can therefore trace out many deployment points. As the structured pressure changes, the effective capacity changes smoothly, which means the trained model family can be sliced to different memory budgets without rerunning training from scratch.

The optimization view

First in words:

Learn task-facing weights while forcing them to stay close to sparse and low-rank copies, with penalty strengths that are adjusted during training.

Then the compact form:

min_W task_loss(W) + rho_s * ||W - S||^2 + rho_r * ||W - R||^2 subject to S sparse, R low-rank

Every symbol:

Ssparse copy of W
Rlow-rank copy of W

A tiny worked example
Suppose one layer starts as a dense 4096 by 4096 table.
The sparse copy keeps only the largest entries and sets the rest to zero.
The low-rank copy stores two smaller tables whose product approximates the dense one.
If task loss rises too sharply, the controller relaxes the penalties so W can recover useful structure.
If task loss stays stable, the controller can raise the penalties and push W closer to the cheaper forms.

The paper uses ADMM to solve this split problem in alternating updates, because the structured projections and the task update are easier to handle separately than all at once.

What can go wrong

What can go wrong

The penalties may fight the task too early. If structure pressure rises before the model has learned a reasonable task solution, useful weights can be removed or factorized too aggressively, which means later recovery may be difficult.
Sparse and low-rank targets can disagree. Some layers may prefer one form of compression strongly. Forcing both at once can waste capacity if the joint constraint is tighter than needed for that layer.
Exporting a smooth capacity curve may depend on the controller. If the adaptive schedule changes penalties in large jumps, neighboring deployment points may not behave smoothly, because the learned family can skip useful intermediate structures.
Where the design is strongest. The method is strongest when deployment must cover several hardware limits, because the main benefit is avoiding repeated retraining for each memory budget.
What a runnable demo should prove

What a runnable demo should prove

Build a training dashboard for a medium-sized language model block rather than a full frontier model. Show one dense baseline run and one SALAAD run. Track task loss, nonzero fraction, estimated rank, and use-time memory after each checkpoint.

The demo should let the user move a memory-budget slider after training and instantly load the corresponding structured checkpoint. Also expose separate toggles for sparse-only, low-rank-only, and joint SALAAD training. That comparison matters because the paper's main claim is that joint structured learning plus adaptive penalties gives a broader and more usable capacity curve than hand-picked single-form compression.

deployment_score = task_quality - memory_cost - retraining_runs

The demo must show that the same training trajectory can serve several memory budgets, because SALAAD keeps the weights near compressed forms throughout learning rather than compressing only at the end.
