HiFo-Prompt: Hindsight and Foresight for Automated Heuristic Design

An LLM learns to design solution methods by looking back at what worked and ahead at what the current search needs.

Paper explainersAll themesOptimization

When an LLM is asked to invent new solution strategies (called heuristics) inside an evolutionary algorithm, it usually forgets what it learned and misses the big picture of the search. HiFo-Prompt solves this by giving the LLM two superpowers: Hindsight memory of winning strategies it discovered before, and Foresight awareness of whether the search is stuck and needs to explore or exploit. The result is faster, smarter heuristic design because the LLM avoids reinventing failed ideas and can adjust its strategy to match what the search actually needs at each moment.

Zero assumption version

The LLM forgets and loses focus

Imagine you hired someone to invent new recipes for a cooking competition. Each round, they invent a recipe, the judges score it, and the best recipes move forward. You would expect your inventor to remember which ingredients won last round and which ones failed. But when an LLM is asked to invent solution strategies (called heuristics) inside an evolutionary algorithm (a method that tries many solutions and keeps improving the best ones)—it does not remember. It starts from scratch each time, wasting effort rediscovering what already worked. Worse, it does not know whether the overall search is stuck (needs bold new ideas to break out) or thriving (needs to refine what works), so it cannot tailor its strategy to the moment.

A naive approach: prompt the LLM with only the current population and ask it to generate a new heuristic. The LLM will invent something, but it ignores all the successful patterns from past rounds, and it ignores warning signs in the data (like diversity collapse, where the population is converging to a mediocre solution). The LLM is like a chef with amnesia, reinventing curry powder every day while the other cooks' recipes are lost forever.

In one sentence. The paper teaches the LLM to remember past wins and to read whether the search is stuck, so it invents smarter strategies.

What the paper changes

What the paper changes

The paper changes what information the LLM receives at each generation. Instead of seeing only the current population, the LLM now sees a structured summary of the past (which design choices worked) and a diagnosis of the present (are we stuck or thriving). This transforms the LLM from a stateless tool into an active, aware designer.

the object it moves  =  the prompt context
The hidden quantity

The population dynamics signal

measured quantity  =  diversity and fitness trends

The hidden quantity is a two-part signal that Foresight computes each round: diversity (how different the best solutions are from each other) and fitness plateau (how much the top score is still improving). Think of it as a gauge: diversity close to zero means the population has converged to nearly identical solutions; a flat fitness plateau means no progress has been made in recent rounds.

The paper uses these two measurements together to decide the search state. If diversity is high and fitness is still climbing, explore freely. If diversity is low and fitness is plateauing, switch to exploitation—focus on refining the best solutions. The LLM receives this diagnosis as plain language (e.g., 'diversity is 28%, below critical threshold; switch to local refinement') rather than raw numbers, so it reasons in terms it understands.

Why it works

Why the LLM becomes smarter

The mechanism works in two layers. First, Hindsight compresses what the LLM learned over past generations into a persistent knowledge base—a list of design principles that actually worked (e.g., 'early mutation rate above 0.3 prevents premature convergence', 'crossover of genetically similar pairs preserves fit structures'). When the LLM invents a new heuristic, it reads this list and can build on past successes rather than inventing from scratch. This prevents reinventing the same good idea repeatedly.

Second, Foresight tells the LLM what kind of move the search needs. If diversity is collapsing (the population is converging), Foresight says 'explore'—nudge the LLM to invent strategies that increase variation and escape the current local optimum. If fitness is high and plateauing (the search is saturated), Foresight says 'exploit'—nudge the LLM to invent fine-tuning strategies that polish the solutions already found. The LLM now has both a playbook (Hindsight) and a marching order (Foresight), so it designs heuristics that fit the current search state. This turns an LLM from a stateless generator into an adaptive reasoner.

Math after the picture

The learning objective

First in words:

The hindsight memory grows as the maximum of all principles seen so far. Foresight computes the ratio of current diversity to initial diversity; below threshold triggers exploration signal. LLM-generated heuristics are scored by resulting population fitness after one generation.

Then the compact form:

foresight_signal = I(diversity_t / diversity_0 < tau_explore); hindsight_base = {principles_1, ..., principles_t-1}; heuristic_t = LLM(population, foresight_signal, hindsight_base); fitness_t = eval(heuristic_t, population)

Every symbol:

diversity_tstandard deviation of best solution coordinates in generation t
diversity_0initial diversity at the start of evolution
tau_explorediversity threshold below which exploration is signaled (e.g., 0.2)
I(...)indicator function: 1 if condition is true, 0 otherwise
principles_idistilled design principles (as text) from generation i
hindsight_baseset of all principles saved from past generations
heuristic_tthe new heuristic (a policy or operator) designed by the LLM
eval(...)apply heuristic to population and measure resulting fitness
fitness_taverage or best fitness of the population after applying heuristic_t
A tiny worked example
Generation 1: diversity_0 = 100 (max). LLM invents mutation rate 0.2, wins solutions saved.
Generation 5: diversity_5 = 40 (40% of start). Ratio is 0.4, above threshold 0.2 -> explore signal = 0.
Generation 10: diversity_10 = 15 (15% of start). Ratio is 0.15, below threshold 0.2 -> explore signal = 1.
Hindsight: [principle 1: mutation rate 0.2 works early, principle 2: crossover near end improves best].
Foresight sends: explore=1. LLM reads these principles and designs a strategy balancing mutation and diversity increase, improving fitness_10 to 88 from naive 72.

The equation captures the two feedback loops: Hindsight accumulates successful principles, Foresight diagnoses search state, and the LLM bridges them to design adaptive heuristics.

What can go wrong

What can go wrong

Hindsight base grows too large. After many generations, the list of past principles becomes huge and noisy. The LLM must spend tokens filtering instead of reasoning. Fix: prune principles that contradict newer ones, or summarize clusters of similar principles.
Foresight threshold is miscalibrated. If the diversity threshold is too low, the LLM spends effort exploring when the solutions are already good, wasting moves on random variation; if too high, it focuses too much on refining too early, missing better regions of the solution space because it stops looking for them. The paper must tune this per problem type.
LLM ignores guidance. The LLM receives hindsight and foresight context but does not actually use it—it keeps inventing the same types of heuristics. Requires careful prompt engineering and validation that the LLM is reasoning about the signals.
Done right. Hindsight is maintained as a curated list of principles, Foresight diagnosis is clear and actionable, and the prompt structure ensures the LLM visibly reasons through both signals before proposing a heuristic.
What a runnable demo should prove

What a runnable demo should prove

Build a small evolutionary algorithm (e.g., optimizing a benchmark function like Rastrigin or a simple traveling-salesman problem) and run it three times: once with a naive LLM (receives only the current population), once with Foresight only (LLM sees the search state), and once with HiFo-Prompt (both hindsight and foresight). Measure the quality of the best heuristic found and how many generations it took to converge. The demo must show that hindsight prevents the LLM from reinventing failed ideas (by comparing it to the naive version) and that foresight accelerates convergence (by showing the trajectory of fitness improvements).

heuristic_quality = best_fitness_with_heuristic / best_fitness_with_random; queries_saved = queries_naive - queries_hifo; speedup = generations_naive / generations_hifo

The demo should make it unmissable that HiFo-Prompt both invents better heuristics and finds them much faster than an LLM with no memory or awareness, because it learns from past wins and adapts to the search state rather than flailing blindly each round.
