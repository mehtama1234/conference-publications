HiFo-Prompt: Hindsight and Foresight for LLM Heuristic Design

Tell an LLM what strategy worked before and what the current search bottleneck is, so it invents better-solving algorithms instead of just trying random ones.

Paper explainersAll themesOptimization

When you ask a language model to invent new solving algorithms for hard problems, it tends to forget what worked before and miss when the search is stuck. HiFo-Prompt adds two guides: a Foresight guide that watches the search and tells the LLM when to explore versus exploit, and a Hindsight guide that remembers successful patterns so the LLM reuses them. The result is algorithms that solve problems faster and better than hand-written ones, because the LLM now reasons with explicit memory and adaptive strategy switching instead of rediscovering ideas blindly.

Zero assumption version

LLMs invent algorithms blindly

Evolutionary algorithms evolve solutions by running many attempts in parallel, keeping the good ones and mutating them to try new ideas. In classical evolution, you might breed faster horses: keep the 10 fastest from 100 and breed them, because those 10 have already proven they survive well and pass on traits that work. In automated heuristic design, the 'organism' is not a horse but a problem-solving algorithm — a recipe that decides how to solve traveling-salesman or bin-packing problems.

When researchers use language models to invent these recipes, they prompt the LLM: Here are past algorithms. Mutate them. But the LLM has no memory of why those mutations worked. It also cannot see that the search has gotten stuck — the population stopped improving, so it should try a radically different approach instead of tweaking. The LLM is a passive tool, not an active planner.

A beginner would try just asking the LLM to invent new algorithms each round. It does, but the algorithms wander because the LLM has no context: it does not know that last week's winning move was 'sort items by size first', and it does not see that today's search is drowning in similar bad ideas.

The fix in one sentence. Build an LLM two channels: a memory of winning patterns it can reuse, and a window into the current search state so it knows when to switch strategy.

The algorithm as a flow

What it actually does

Initialize

Start with hand-written seed algorithms or generate from scratch using the LLM's first prompt.

Evolve with Hindsight

After each round, store high-performing algorithms in a memory pool as generalized principles (e.g., 'sort before assigning').

Measure Foresight signal

Count how different the top performers are from each other, or track if score is improving; if diversity collapsed or stalled, flip to exploration mode.

Prompt with both

Tell the LLM the current mode and inject successful patterns from memory into the next prompt.

Repeat

Mutate using the LLM, evaluate, update memory and mode signal, prompt again.

What the paper changes

What the paper changes

The paper changes what the LLM sees each time you ask it to invent a new algorithm. Instead of a bare list of old algorithms, the LLM now receives two additions: (1) a list of proven design principles extracted from past winners, and (2) a label saying whether the search should explore (try very different ideas) or exploit (refine what is working).

the object it moves  =  the input prompt to the LLM
The hidden quantity

The hidden quantity: population diversity and search stagnation

measured quantity  =  evolutionary state signal

The paper measures an invisible quantity called the evolutionary state signal: a number between 0 and 1 that captures whether the population has collapsed into copies of each other or whether it still contains diverse ideas. The signal is computed by counting pairs of algorithms in the population that are textually different (not identical string matches) and dividing by the total possible pairs. If all algorithms are nearly identical, the signal is close to 0, meaning diversity is dead. If they are all different, it is close to 1, meaning exploration is still possible.

The paper uses this signal as a trigger. When the signal drops below a threshold, the Foresight module tells the LLM: 'Stagnation detected — explore radically.' When the signal is high, it says: 'Diversity alive — exploit the best ideas carefully.' This signal does not appear in older papers because they treat evolution as a blind process; HiFo-Prompt turns it into actionable feedback.

Why it works

Why it works: two channels into the LLM's reasoning

Without HiFo-Prompt, the LLM is a black box: you feed it algorithms and it mutates them using its internal training, which may or may not remember what made the original ones good. The mutation might randomly revert a winning move because the LLM has no explicit record.

HiFo-Prompt opens two channels that make the LLM a stateful reasoner. First, the Hindsight channel explicitly extracts successful patterns from past winning algorithms (e.g., 'sort items by size' or 'reserve space for large items'), stores them in a memory pool, and injects them into the next prompt. Now the LLM does not have to re-discover the pattern; it can read 'here are three principles that worked' and use them as building blocks for new algorithms. This is reuse instead of reinvention.

Second, the Foresight channel gives the LLM real-time feedback on the search state. By counting how different the current population is, HiFo-Prompt detects stagnation — the moment when all algorithms are becoming copies. When stagnation is detected, the prompt flips to an exploration mode prompt that tells the LLM: 'Diversity collapsed, invent something radically different.' Without this signal, the LLM keeps refining the current family of ideas and gets stuck in a local optimum. With it, the LLM can pivot to a wholly different design space when needed.

Together, Hindsight (remember what worked) plus Foresight (know when to switch strategy) turn the LLM from a passive mutator into an active planner that can both learn from the past and respond to the present search state.

Math after the picture

The diversity equation

First in words:

diversity signal equals the count of unique algorithm pairs divided by the total possible pairs in the population.

Then the compact form:

signal = unique_pairs(population) / total_pairs(population)

Every symbol:

unique_pairsnumber of algorithm pairs whose text descriptions differ
total_pairsall possible pairs you could choose from the population
populationthe set of current candidate algorithms, typically 10-50 members
signala fraction between 0 and 1; close to 1 means high diversity, close to 0 means stagnation
A tiny worked example
Population has 4 algorithms: A, B, B-copy, C.
Total possible pairs: (A,B), (A,B-copy), (A,C), (B,B-copy), (B,C), (B-copy,C) = 6 pairs.
Unique pairs (text differs): (A,B), (A,B-copy), (A,C), (B,C) = 4 pairs. (B,B-copy) is not unique because B and B-copy have identical descriptions.
Signal = 4 / 6 = 0.67. This is moderately diverse; not quite stagnant.
Threshold is typically 0.5. Since 0.67 > 0.5, the Foresight module stays in exploit mode (refine winners).

The signal is a simple diversity check: if all algorithms are copies, unique_pairs is near 0 and the LLM gets an 'explore' prompt; if all are different, the signal is high and the LLM refines.

What can go wrong

What can go wrong

Memory pool noise: too many irrelevant principles. If the Hindsight module stores every mediocre algorithm's patterns, the memory becomes cluttered. The LLM then spends tokens reading junk instead of focusing on truly winning ideas. Solution: filter memory by actual performance gain (store only patterns from algorithms that beat a performance threshold) and use a utility-based retrieval to rank which patterns to inject.
Foresight signal miscalibration: wrong stagnation threshold. If the diversity threshold is set too high, the LLM stays in exploration mode forever and never exploits good ideas. If too low, it misses stagnation and gets stuck. The paper found threshold 0.5 works for most problems, but it may need tuning per problem domain.
Prompt brittleness: mode signal not perceived by LLM. If the 'explore vs exploit' signal is buried in the prompt, the LLM may ignore it. Good prompt design (e.g., 'ALERT: Population stagnation detected. Invent radically different approaches.') ensures the LLM actually reads and acts on the mode signal.
Done right: explicit memory, high-quality filtering, and clear mode signals. When you distill only the truly winning principles, limit memory to 30 high-quality entries, and use bold language to signal the exploration vs exploitation mode, the LLM genuinely uses both channels to invent better algorithms, because high-quality memory is signal and noise is filtered out, and the LLM allocates its tokens to reading and incorporating principles rather than parsing irrelevant clutter.
What a runnable demo should prove

What a runnable demo should prove

Build an evolutionary loop for a small problem (traveling salesman with 100 cities, or bin packing). Initialize a population of 10 algorithms as Python functions. Each generation: (1) evaluate all algorithms on the test set, rank them, (2) extract 3 winning principles using simple text pattern matching (e.g., 'if the algorithm sorts the items, record that principle'), (3) compute the diversity signal by comparing algorithm code strings, (4) prompt the LLM with the mode and memory, (5) collect the LLM's new algorithms, repeat. Track the best algorithm quality and population diversity across 30 generations.

convergence_rate = (quality_at_gen_20 - quality_at_gen_5) / quality_at_gen_5, diversity_at_stagnation_point = diversity signal when best quality stops improving

The demo proves HiFo-Prompt works if: (1) the best algorithm quality climbs past generation 15 (showing Foresight exploration broke an earlier plateau), and (2) the diversity signal predicts when the search was stuck (Foresight detected it). Without HiFo-Prompt, both metrics plateau much earlier.
