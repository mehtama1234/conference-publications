Knowledge Purification in Multi-Teacher Knowledge Distillation for LLMs

When a small model learns from multiple large teachers, picking one teacher's explanation per question beats trying to mix all of them together.

Paper explainersAll themesLLMs & Foundation Models

Large language models are expensive to run, so people shrink them by having a small model learn from big ones. But when you use multiple big teachers at the same time, their explanations often contradict each other — one says the answer comes from this reason, another from that reason — and the small model gets confused. This paper proposes picking the single best teacher explanation for each question instead of trying to use all of them; this works because a single coherent reasoning path is easier to learn and reuse than a blurry average of incompatible ideas.

Zero assumption version

Multiple teachers create conflicting signals

A large language model is slow and expensive — it takes a lot of computing power to ask it questions. So people create faster, cheaper small models by having them learn from the big ones. One teacher is okay, but using three or four big teachers should make the small model learn even better, because each teacher knows different things. In practice, the opposite happens: when you show the small model an explanation from Teacher A and an explanation from Teacher B that disagree, the model thrashes between them. It overfits to whichever one it heard last, or it never commits to either one.

A beginner's first idea: average all the teachers' explanations into one. But that mixes incompatible ideas — if one teacher says the answer uses grammar and another says it uses meaning, averaging them produces nonsense that matches neither real reasoning path. The small model never learns the clean thought process that either teacher actually used.

The core problem in one sentence. Multiple teachers give conflicting explanations for the same answer, and the small model cannot learn from the contradiction.

The algorithm as a flow

What it actually does

Score each teacher

Pick the winner

Small model learns from it

What the paper changes

What the paper changes

The paper changes which teacher the small model learns from: instead of mixing all teachers' outputs together, it selects one teacher per question. This choice is made by a small neural router that scores each teacher and picks the best one.

the object it moves  =  teacher selection per question
The hidden quantity

Routing confidence: which teacher fits this question best

measured quantity  =  router confidence score

The router confidence score is a single number (between 0 and 1) that says how well this teacher understands this particular question — like a confidence level. If a teacher often gives correct, consistent explanations for this kind of question, its score is high. If a teacher's answers are scattered or wrong for this topic, its score is low.

The paper measures this by training a small neural network (the router) that looks at the question and the teacher's output and learns to predict: does this teacher's explanation fit this question well? After training, for each new question, the router scores all teachers and the model learns from the one with the highest score.

Plain reading. The router is like a filter that asks: does Teacher A understand this question? Does Teacher B? Then it picks the answer from the teacher that understands it best.
Paper reading. The router estimates a selection weight for each teacher given the input and teacher output. The method can use soft selection (weighted blending using router scores) or hard selection (pick the single teacher with the highest score only).
Why it works

Why picking one teacher is better than mixing

When you mix all three teachers' explanations, you are averaging incompatible reasoning paths. One teacher says the answer is seven using addition. Another says it is seven using subtraction. A third says it is seven because of some pattern in the digits. Averaging these three paths teaches the small model: here are three different math ideas that lead to seven, mashed together. The model has to somehow hold all three at once, or it fails. But if you pick only the first teacher, the model learns the addition path is the right reasoning. That is cleaner, because it is a single coherent thought.

The router learns which teacher is most reliable for which kind of question — like learning that one teacher is great at arithmetic but bad at logic, while another is the opposite. By choosing the best teacher for each question type, the small model inherits that teacher's clean, consistent reasoning path. The model then generalizes better to new questions because it has learned focused, non-contradictory strategies instead of a blurry average.

How the router scores each teacher

First in words:

loss = cross_entropy_loss_from_selected_teacher + lambda * router_entropy_penalty

Then the compact form:

loss = L(y_true, y_selected_teacher) + lambda * H(router_scores)

Every symbol:

L(y_true, y_selected)error between the true answer and the teacher's answer
y_selected_teacherthe answer from the teacher the router picked
lambdastrength of the penalty to keep router confident
H(router_scores)entropy of the router's confidence scores — higher if all teachers tie, lower if one dominates
y_truethe correct answer
Tiny worked example
Question: What is 3 + 4?
Teacher A says: 7 (correct)
Teacher B says: 6 (wrong)
Teacher C says: 8 (wrong)
Router scores: A=0.8, B=0.1, C=0.1 (picks A)
Loss from picking A: cross_entropy(7, 7) = 0 (no error)
Router entropy penalty: high entropy means A, B, C are tied; low entropy means A wins — here A dominates, so entropy is low, penalty is small
Total loss: 0 + 0.01 * 0.3 = 0.003 (small, good)
If router had scored A=0.33, B=0.33, C=0.33 (tied): entropy would be high, penalty would be 0.01 * 1.1 = 0.011 (larger, worse)

The loss teaches the router: pick teachers that are right for this question, but also pick them decisively, not wishy-washy.

What can go wrong

What can go wrong

Router becomes overconfident on a weak teacher. If the router learns that Teacher B is great at arithmetic but sees only three arithmetic questions (by chance), it might score Teacher B very high and ignore Teacher A, even though Teacher A would have been better on the next batch of questions, because small samples are noisy — the router can overfit to a lucky streak. The router needs enough diverse examples to learn reliable patterns.
All teachers are equally bad at the topic. If none of the three teachers understands biology well, the router picks whichever one fails least gracefully. The small model still learns from a weak signal. Adding better teachers helps because the router can then pick the less-wrong teacher, so the small model gets a stronger signal; adding more bad teachers does not help because the router still picks among teachers that all fail.
Teachers agree, but all are wrong. If all three teachers consistently give the same wrong answer (e.g. they were trained on biased data), the router picks one of them, and the small model learns the same wrong answer. Purification does not fix incorrect teachers, only conflicting ones.
Router works well when teachers specialize. If you have one teacher good at math, one good at language, one good at reasoning, the router learns to pick the right expert for each question, and the small model becomes a fusion of clean specialists.
What a runnable demo should prove

What a runnable demo should prove

Build a small model that learns from three teachers that each give slightly different explanations of how to solve simple arithmetic (e.g. 7 + 5). Train a router to score which teacher explains this type of problem best. Then train the small model using only the picked teacher's explanation. Measure how well the small model answers new arithmetic questions it has never seen.

generalization_gain = (small_model_accuracy_on_new_questions_with_purification) minus (small_model_accuracy_on_new_questions_with_averaging)

The demo should make it impossible to miss: when the small model learns one clean explanation per question, it generalizes better to new questions than when it tries to average contradictory explanations, because one coherent reasoning path is not confused by competing ideas and carries over to new questions more reliably.
