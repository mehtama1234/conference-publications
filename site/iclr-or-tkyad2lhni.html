SIGMark: Scalable In-Generation Watermark with Blind Extraction for Video Diffusion

Embed a hidden message directly into video noise using frame-wise random keys, then recover it without keeping copies of the original noise.

Paper explainersAll themesAlignment, Safety & Fairness

When a video is made by a diffusion model, you need a way to prove it was made by you—like a signature painted into the film itself. A watermark does this. But old watermarking methods require storing a template (the original noise) to check if a video is real, which is expensive at scale. SIGMark embeds the watermark right into the starting noise using pseudo-random frame-by-frame keys, so checking a video later needs no stored template. Even if frames get dropped or shifted during compression, the watermark stays recoverable.

Zero assumption version

The watermarking scaling problem

Video generators now create thousands of videos per day. Each needs a watermark—a signature proving it came from a trusted source, not a fake. A naive watermark is: during generation, hide a message in the starting noise. Later, take the video apart (run it backward through the denoiser to recover the noise), and check the message.

But this has a fatal flaw at scale: checking requires keeping the original noise. That means storing gigabytes of reference data. With millions of videos, this is impossible. Modern video diffusion models also split video frames into groups, decoding adjacent frames together to save time. If a video is compressed or frames are dropped—a natural thing that happens on the internet—the frame groups get scrambled. The model can't reverse the scrambled video correctly, so the watermark vanishes. You're left with no way to prove ownership.

The core problem: Watermarks that need stored templates don't scale; watermarks that ignore frame grouping fail when videos are edited.

The algorithm as a flow

What it actually does

Assign frame-wise keys

For each group of adjacent frames, assign one pseudo-random code key. This key is public (not secret) but deterministic.

Encode the message into noise

Use the keys to tweak the starting noise in specific patterns, weaving the bits of the watermark message into the numbers.

Generate the video normally

The diffusion model takes the watermarked noise and generates frames as usual. No quality loss.

Detect frame groups by watching motion

Later, if frames are scrambled, use optical flow (pixel motion) to find where one group ends and the next begins.

Invert and decode

Once groups are fixed, reverse the diffusion model to recover the noise, then decode using the keys.

What the paper changes

What the paper changes

The paper targets the initial noise—the random starting point the video generator reads before creating frames. Instead of encoding a simple pattern, it weaves the message in using a set of frame-wise pseudo-random keys. Each frame group gets its own key, so the watermark is scalable: extracting a video later requires only these keys (which are small and reusable), not storing the original noise for every video.

The hidden quantity

Bit accuracy—the survival rate of the watermark

measured quantity  =  bit accuracy

Bit accuracy is the fraction of message bits that survive extraction, measured as a percentage. If you embed a 128-bit message and recover 120 bits correctly, that is 93.75% bit accuracy (120 out of 128). Scrambled frame groups confuse the inversion, reducing the number of bits that come back correctly. The paper measures bit accuracy before and after temporal disturbance (frame drops, reordering, compression) to show how well the watermark survives.

SIGMark estimates bit accuracy by attempting full message recovery after inversion, counting how many bits match the original. The Segment Group-Ordering module works to maximize this by fixing frame grouping first, so the diffusion inversion can run correctly on a semantically coherent video.

Why it works

Why frame-wise keys and segmentation work together

Video diffusion models decode frames in groups to save computation—frames 0, 1, 2 are decoded together from one block of compressed features (called latent features, which are smaller than the full video), then frames 3, 4, 5 from the next block. If you encode the watermark using one key per group, you embed bits at the right granularity. When a video is compressed and frames get shuffled, the inversion step reads the scrambled frame order and produces garbage.

SIGMark uses optical flow—tracking how pixels move between frames—to find the true group boundaries even after scrambling. Once it knows which frames belong together, it can reorder them correctly before inversion. Then the inversion produces the true starting noise, and the frame-wise keys decode the watermark bits cleanly. This works because the watermark is baked into the noise at the level of frame groups, not individual frames. Fixing the grouping fixes the bit accuracy.

Math after the picture

The encoding and decoding equation

First in words:

For each frame group g, compute message bits as: decoded_bit[g] = (noise_values[g] dot key[g]) mod 2. The dot product sums the products of noise and key; the mod 2 extracts a single bit (0 or 1).

Then the compact form:

decoded_bit[g] = (z[g] · k[g]) mod 2, where z[g] = recovered noise for group g, k[g] = frame-wise pseudo-random key for group g

Every symbol:

z[g]the recovered noise vector for frame group g
k[g]the frame-wise pseudo-random coding key assigned to group g
·dot product: sum of element-wise products
mod 2take the remainder after dividing by 2, giving 0 or 1
decoded_bit[g]one bit of the watermark message for group g
A tiny worked example
Suppose noise z[0] = [0.2, 0.1, 0.3, 0.5] and key k[0] = [+1, +1, -1, -1].
Dot product: (0.2)(+1) + (0.1)(+1) + (0.3)(-1) + (0.5)(-1) = 0.2 + 0.1 - 0.3 - 0.5 = -0.5.
If -0.5 is negative, treat it as closer to -1, so decoded_bit[0] = 1 (odd parity).
For group 1, if z[1] · k[1] = +0.3 (positive, closer to +1), decoded_bit[1] = 0 (even parity).
Total: recovered message starts ...10... (two bits). The pseudo-random keys ensure noise-like perturbations.

The frame-wise keys act as decoders: when you dot the recovered noise with its matching key, you extract one bit per frame group.

What can go wrong

What can go wrong

Extreme temporal chaos breaks optical flow. If a video is heavily re-encoded, frames are synthesized, or the entire temporal structure is scrambled beyond motion continuity, optical flow cannot find the true group boundaries. The segmentation fails, and bit accuracy drops.
First frames carry no watermark. In the causal 3D VAE, the first frame is processed independently, so the watermark is not embedded in it. If extraction relies on the first frame, no bits are recovered from that group.
Pseudo-random keys are not secret. The frame-wise keys are deterministic and reusable, not cryptographically secret. An adversary with access to the algorithm can generate the keys and embed a fake watermark. This is acceptable for provenance (proving you made it) but not for authentication (proving an attacker did not forge it).
Done right: stays accurate under pressure. When optical flow is accurate, frame groups are correctly recovered, and the inversion is run on coherent video, bit accuracy remains above 84% even under compression and disturbance.
What a runnable demo should prove

What a runnable demo should prove

Build a mini video diffusion generator (or use a trained one) and embed a 32-bit watermark message using SIGMark. Generate a video. Then corrupt it: drop every 3rd frame (simulating heavy compression), or shuffle frames within a small window, or apply lossy re-encoding. Finally, attempt extraction. Count how many of the 32 bits survive. Report bit accuracy before and after disturbance. If your frame grouping recovery works, accuracy should stay above 80%. If it fails, accuracy collapses below 40%.

bit_accuracy = (number of recovered bits matching original message) / (total message bits) × 100%

The demo makes visible that frame-group recovery is the key: scrambled frames without segmentation fail catastrophically, but with segmentation they recover the message.
