SUSD: Structured Unsupervised Skill Discovery

Split the world into independent moving parts, assign each part its own skills, and nudge the agent to explore all of them.

Paper explainersAll themesReinforcement Learning

A robot learns skills by trying things and seeing what happens—no reward signal tells it what to do. Most methods favor simple, repetitive skills because they are easy to measure. SUSD watches which objects or entities the robot can move independently, assigns each one its own skill variable, and steers the agent to exercise all of them. The result: the robot discovers rich, diverse skills that engage every controllable thing in its world.

Zero assumption version

Simple skills hide complex behavior

Imagine a robot in a world with three objects: a ball, a box, and a light. Without any reward signal, how does it learn what it can do? One approach: measure how much the robot changes the world by looking at the distance between its current state and all past states. If the distance is high, the skill is interesting. But this favors simple repetitive tricks—spin in a circle, shake the ball—because they are easy and measurable. Deep behaviors that require moving multiple objects together get buried.

Older methods measure how much a skill controls which objects move, by tracking whether an object's position is predictable from the skill alone. But this does not encourage the agent to explore all objects. A robot might nail down skills for the ball and ignore the box entirely. The world's structure—which objects can move independently—goes unused.

The core problem. Unsupervised skill discovery favors simple, static skills and leaves controllable objects unexplored.

The algorithm as a flow

Observe the world structure

What the paper changes

What the paper moves

SUSD changes which skill variables the agent is allowed to influence. Instead of one giant skill variable covering the whole world, each skill variable is pinned to one independent factor—ball, box, or light. This constraint forces the agent to discover separate, specialized behaviors.

the object it moves  =  skill-to-factor allocation
The hidden quantity

Factor engagement—which parts are being explored

measured quantity  =  skill-factor engagement score

The hidden quantity SUSD measures is how actively each skill is steering each object. For example, if skill 2 is always changing the box's position but never the light, the engagement score for skill 2 and light is low. This is computed by a dynamic model that learns to predict how much an object moves given a skill label.

The dynamic model is trained on real experience: it sees state pairs (before and after an action) along with the skill label, and learns to predict what changed. Over time, it gets good at saying whether this skill actually moved this object. High prediction accuracy means high engagement.

Why it works

Why it works: targeted exploration

The mechanism has two parts. First: by assigning each skill to a separate factor (ball, box, light), the agent naturally learns to make each factor move in different ways. Skill 1 only ever moves the ball, so the agent will try pushing, rolling, and flinging it. Skill 2 only moves the box, so it learns box-specific moves. No skill can do everything, so the agent has to exercise all factors.

Second: the dynamic model watches which skill-factor pairs are actually being explored and which are idle. If skill 4 has never actually changed the light, the model's engagement score for (skill 4, light) stays low. The training loop then adds a bonus when the agent tries skill 4 in situations where it might change the light—like when the light is reachable. This steering nudges the agent toward unexplored pairs, ensuring all factors get explored. The result is a factorized skill set where each skill is specialized and the whole set covers all controllable objects.

The skill discovery bonus

First in words:

total reward = distance between states + lambda times the engagement bonus for unexplored skill-factor pairs

Then the compact form:

R = ||s_new - s_old|| + lambda * sum_f (1 - E_f)

Every symbol:

Rtotal reward signal given to the agent
s_new, s_oldstate (position, color, etc.) after and before the action
||·||distance or magnitude (how far apart two states are)
lambdahow much to value exploration of new skill-factor pairs (tuning dial)
E_fengagement score for factor f, predicted by dynamic model (0 to 1)
sum_f (1 - E_f)bonus for all underexplored factors (higher when factors are unused)
A tiny worked example
State distance: ball moved 15 units, box stayed still, light moved 5 units. Magnitude = 15 + 0 + 5 = 20.
Engagement scores: skill 1 (ball) = 0.9, skill 2 (box) = 0.2, skill 3 (light) = 0.8.
Exploration bonus: (1 - 0.9) + (1 - 0.2) + (1 - 0.8) = 0.1 + 0.8 + 0.2 = 1.1.
Lambda = 3, so final reward = 20 + 3 * 1.1 = 23.3.
If the agent had ignored the box (skill 2 engagement = 0.1), bonus would be (1 - 0.1) + (1 - 0.2) + (1 - 0.8) = 0.9 + 0.8 + 0.2 = 1.9, reward = 20 + 3 * 1.9 = 25.7—higher reward for exploring the idle box skill.

The bonus term rewards trying skills on factors where the dynamic model says engagement is low, steering the agent toward gaps in exploration.

What can go wrong

What can go wrong

Wrong factorization breaks everything. If the state split is wrong (say, grouping ball and box together when they move independently), the agent cannot learn which skill controls what. The dynamic model misses the real structure.
Dynamic model overfits to noise. If the model is too flexible or trained on short episodes, it may learn spurious correlations (skill 3 tends to change the light because the agent happened to use skill 3 near the light). The engagement scores become misleading, wasting exploration on false leads.
Lambda tuning is sensitive. If the exploration bonus weight (lambda) is too high, the agent wastes effort on hard-to-move factors even when they are not useful. Too low, and it reverts to favoring easy factors.
Done right. With a correct factorization, a dynamic model that avoids overfitting, and a balanced lambda, the agent explores all factors and learns rich, compositional skills suitable for downstream hierarchical tasks.
What a runnable demo should prove

What a runnable demo should prove

Build a simple environment with 3–5 independent moving objects (e.g., balls and boxes on a 2D grid, or a simulated arm with movable objects). Assign each object its own skill variable (e.g., skill 1 pushes the ball, skill 2 pushes the box, skill 3 pushes the light). Run SUSD for 100,000 environment steps. Record, for each skill-object pair, how often the skill changed that object's position (e.g., distance moved > 0.5 units after the action). Measure the 'coverage' of each skill: the fraction of objects it can change. Compare against a naive method that uses a single shared skill variable.

coverage = mean over skills of (count of objects that skill can move / total objects)

The demo must show that SUSD achieves high coverage across all objects, while the naive method covers only 1–2 objects per skill.
