KeepLoRA: Continual Learning with Residual Gradient Adaptation

KeepLoRA learns each new task by updating only the part of the adaptation space that is orthogonal to pre-trained knowledge and earlier tasks, so old capabilities are less likely to be overwritten.

Paper explainersAll themesOther

Continual learning for a pre-trained vision-language model has three competing goals: keep the model's broad pre-training knowledge, keep what was learned on earlier tasks, and still learn the current task. Standard fine-tuning often breaks one of these goals because the gradient (the direction telling training how to change the model) for the new task pushes the model along directions that overlap with directions used by old knowledge. KeepLoRA studies where different kinds of knowledge live in parameter space (the space of all learned numbers in the model) and argues that broad pre-training knowledge concentrates in dominant directions, while task-specific updates occupy more residual directions. The method then projects each new task gradient away from the dominant old directions before applying the LoRA update. That works because the new task still gets room to learn, but it spends less of its update budget moving the model along directions that carry older capabilities.

Zero assumption version

Why new-task gradients erase old knowledge

A pre-trained model already contains broad skills from large-scale training. In continual learning, we then present task 1, task 2, task 3, and so on. If we fully fine-tune on each new task, the model's learned numbers shift toward the current task and often move away from settings that supported previous tasks. This is catastrophic forgetting.

LoRA reduces the size of the update by learning low-rank adapters instead of changing all weights. But even a small adapter can still forget old tasks if its gradient points in directions that overlap with older information. Shrinking the update alone does not solve overlap.

The paper's key observation is structural. Not all directions in parameter space contribute equally. Some dominant directions carry reusable pre-trained knowledge, while more residual directions carry specialized task adjustments. If new updates are restricted to residual directions that avoid both the dominant pre-trained subspace and major directions used by earlier tasks, interference drops.

The update rule. Before applying a new LoRA gradient, project out the parts aligned with pre-trained principal directions and with strong directions extracted from previous tasks.

The algorithm as a flow

What it actually does

Analyze pre-trained directions

Estimate the dominant principal subspace of the base model features, which captures directions that strongly organize general knowledge.

Store earlier task directions

For each learned task, keep dominant feature directions that summarize where that task wrote its main changes.

Read the new-task gradient

Compute the LoRA gradient for the current task in the usual way.

Project away protected components

Remove the parts of that gradient that lie in the protected old subspaces, so the update acts only in the remaining residual space.

Apply the residual LoRA update

Train the adapter on the projected gradient, then add this task's dominant directions to the protected set for future tasks.

What the paper changes

What the paper changes

The paper changes not the LoRA architecture itself but the direction of each update. Standard LoRA accepts the raw new-task gradient. KeepLoRA filters that gradient through subspace projections before the adapter learns from it.

the object it moves  =  gradient direction for each new LoRA task update
The hidden quantity

Subspace overlap: the hidden cause of forgetting

measured quantity  =  How much the new-task gradient points along protected old directions

Forgetting is not caused only by large updates. It is caused by updates that point in the wrong directions. If a new-task gradient is large but mostly orthogonal to old knowledge directions, it can add new skill with limited interference. If a smaller gradient points directly along an old task direction, it can still erase useful structure.

So the hidden quantity is overlap between the new-task gradient and the protected subspaces. KeepLoRA tries to reduce that overlap before the update is applied. Lower overlap means the update spends more of its strength on genuinely new directions instead of rewriting old ones.

Why it works

Why gradient projection helps continual learning

A gradient tells the optimizer how to change the model to improve the current task, because it points toward parameter changes that lower the current-task loss. But that direction is chosen with no direct regard for older tasks. If task 3 would improve by moving along a direction already used by task 1, ordinary training takes that step and task 1 degrades.

Projection changes the step before it reaches the optimizer. The method first identifies directions that should be protected: strong principal directions from pre-training and dominant directions extracted from earlier task features. It then subtracts from the current gradient the components that lie in those directions.

This leaves a residual update that still points toward the current task objective, but only through degrees of freedom that are less entangled with protected knowledge. The trade-off is deliberate: the current task may lose some raw gradient strength, yet it forgets less because the removed components were precisely the ones most likely to rewrite old capabilities.

Math after the picture

The projected gradient rule

First in words:

The new-task gradient is decomposed into a protected part and a residual part. KeepLoRA throws away the protected part and keeps only the residual part for the adapter update.

Then the compact form:

g_keep = (I - P_old) g

Every symbol:

gthe raw gradient for the current task
P_oldthe projection operator onto protected old subspaces
Ithe identity operator, meaning keep everything before projection
g_keepthe residual gradient used to train the new task adapter
A tiny worked example
Suppose the raw gradient has 70 percent of its energy along old protected directions and 30 percent in new residual directions.
Applying the projection removes the protected 70 percent and keeps the 30 percent residual component.
The current task now learns from a weaker but safer update.
That can reduce raw short-term gain on the new task, but it preserves more old-task performance because the update no longer pushes through directions that old tasks depend on.

This rule expresses the paper's main claim in one line: forgetting comes from directional overlap, so remove the overlapping components before applying the update.

What can go wrong

What can go wrong

Protected subspaces are estimated poorly. If the stored principal or task-specific directions do not actually represent the knowledge worth keeping, projection may block useful new updates while failing to protect the directions that matter.
Residual capacity is too small. If many tasks arrive and the protected space grows too large, the remaining residual space may be too limited for the current task, so learning stalls.
Old and new tasks truly require the same direction. Sometimes a new task must refine a direction that older tasks also use. In that case, hard projection can block a useful shared update because the method treats overlap as interference even when it is beneficial.
Done right. Estimate protected subspaces from stable feature statistics, limit them to the most informative directions, and monitor whether residual capacity stays large enough for incoming tasks.
What a runnable demo should prove

What a runnable demo should prove

Take a pre-trained vision-language model and present it with a sequence of tasks such as image classification, caption style tuning, and retrieval. Compare ordinary LoRA continual tuning against KeepLoRA. After each task, evaluate both the new task and all previous tasks. Also measure how much each new-task gradient overlaps with stored old subspaces before and after projection.

retention_gap = average_old_task_score_keep_lora - average_old_task_score_standard_lora

The demo should show that projected gradients reduce forgetting because they remove update components aligned with older knowledge directions, not merely because the method uses a smaller adapter.
