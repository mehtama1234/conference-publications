Understanding Transfer Learning of RNA Foundation Models

Pretrained RNA models don't magically transfer their knowledge to new tasks; instead they give a head start that steers training toward simpler, more general solutions.

Paper explainersAll themesLearning Theory

When you learn to recognize dogs, you get better at recognizing wolves without retraining from scratch, because the visual patterns you learned (fur textures, snout shapes) apply to both animals. We thought the same would be true for RNA: a model trained on billions of RNA sequences should help new tasks learn faster, because the patterns from pretraining should apply to many downstream tasks. But this paper found something unexpected: the frozen knowledge from pretraining is not universally helpful. Instead, pretraining works by starting the new task's training at a better point in the solution space, one that naturally slides toward simpler rules that generalize better.

Zero assumption version

Transfer Learning Feels Magic, But Why Does It Work?

When machine learning researchers train a model on lots of data, they hope the learned patterns will help with a new task, because patterns learned from one task often show up in another. A beginner would try two things: either freeze the old weights and train only the new top layer, or start with the old weights and fine-tune everything. Both assume the pretraining 'knows' something useful that the new task can copy directly.

But for RNA (the genetic instruction sets in cells), this assumption breaks in an unexpected way. The paper shows that frozen representations from a pretrained RNA model are hit-or-miss — sometimes they help, sometimes they barely matter, because RNA and images are fundamentally different: images have a spatial hierarchy (edges build into shapes build into objects), but RNA sequences do not have such a clear hierarchy. The hierarchical reuse that works beautifully in computer vision does not generalize to RNA. The frozen knowledge does not transfer. So what is pretraining actually doing if not transferring learned features?

In one sentence. Pretraining helps not by shipping transferable knowledge to new tasks, but by placing the new task's training at a starting point that converges toward simpler, more general solutions.

What the paper changes

What The Paper Changes: The Starting Point

The paper does not change the weights themselves or the training algorithm. It changes where training begins: using pretrained weights as the initialization instead of random initialization.

The hidden quantity

Flatness: The Hidden Quantity

measured quantity  =  flatness of the solution (or loss surface curvature)

The hidden quantity is flatness: how gently the loss surface curves around the final trained weights. A flat solution is one where small random changes to the weights do not change the loss much. A sharp solution is the opposite — nudge the weights slightly and the loss shoots up. Flat solutions tend to generalize better to new data, because a flat solution changes only slightly when the data changes, so the same weights work on both old and new examples.

The paper estimates flatness indirectly: it shows that models trained from a pretrained start converge to minima with smaller curvature (less steep walls), which predict better performance on held-out test data. The mechanism is this: a flatter valley means the solution is stable against small changes in the data, so it works well on RNA sequences it never trained on.

Plain reading. Imagine a valley in the parameter space (the space of all possible weight values). A sharp, V-shaped valley is unstable — nudge the weights a little, and the loss shoots up. A wide, rounded valley is stable — nudge the weights, and the loss barely moves. RNA models trained from pretraining land in wide valleys; models trained from scratch land in sharp ones.
Paper reading. The paper measures how steeply the loss curves at the final weights (using the Hessian matrix). Models trained from pretraining converge to solutions with gentler curves (smaller curvature). The paper then shows that gentler curves predict better performance on held-out test tasks, because a gentle curve means the solution is stable — the loss does not change much if the weights move a little, which happens when the test data differs from training data.
Why it works

Why Pretrained Start Finds Flatter Solutions

The mechanism has two parts. First, the pretrained weights sit in a region of the parameter space where the loss surface is gentler. Second, when training starts from that region, it naturally slides into a flatter valley rather than a sharp one.

Why? Because the pretrained weights encode a coarse, high-level structure learned from billions of RNA sequences. This structure is not task-specific — it does not encode knowledge about the downstream task itself. Instead, it represents the general way RNA sequences are organized. When training begins for the new task, it only needs to adjust this general structure to fit the new task, not build a solution from random noise. Adjusting a general structure leads to flatter minima because the weights stay in the region where that structure already provides a smooth, gentle slope. Starting from scratch, by contrast, means finding a sharp, task-specific solution from random noise, which tends to overfit — the model memorizes quirks of the training data instead of learning general patterns.

The alignment between pretraining and downstream task matters: if the new task's objective aligns well with the pretraining objective (e.g., both are sequence classification tasks), then the pretrained start is more useful because the general structure is already oriented toward the right kind of solution. If they are misaligned (e.g., pretraining on conservation, downstream on structure prediction), the pretrained start helps less because the model must move far from the general structure to fit the new task.

A tiny worked example
Random start model trains and reaches a minimum with curvature values [10, 8, 12, 11]. Average = 40 / 4 = 10.0. This is a sharp minimum.
Pretrained start model trains and reaches a minimum with curvature values [2, 1, 3, 2]. Average = 8 / 4 = 2.0. This is a flat minimum.
On held-out test data, the pretrained model generalizes better because its flatter minimum is stable against small data changes. Both the pretrained model's weights and the test data are slightly different from training, but the flat minimum is forgiving to those small changes. Test accuracy is 88% (flat, pretrained) vs. 71% (sharp, random).

The pretrained start biases training toward flatter minima. Flatter minima correlate with better generalization, because a flat solution is stable — if the test data differs slightly from training data, the loss and the model's predictions do not change much.

What can go wrong

What can go wrong

Task misalignment. If the new task's objective is very different from pretraining (e.g., pretraining predicted which nucleotide comes next, but downstream task predicts whether a variant is harmful), then the pretrained start is not in a useful region. The model must move so far from the pretrained weights that it might as well start from scratch.
Underfitting from pretraining. If the pretrained weights encode patterns that are not relevant to the new task, fine-tuning them may cause the model to underfit — the regularization from staying near pretrained weights prevents learning task-specific patterns.
Model capacity too small. A small pretrained model may have learned only coarse patterns. Fine-tuning it on a complex new task may not have enough expressive power to reach a good solution, even with a flat minimum.
Done right. Align the pretraining task closely with downstream goals. Use a large enough model to capture task-specific detail. Measure the curvature of the final solution; if it is sharp, consider more pretraining or a different downstream objective.
What a runnable demo should prove

What a runnable demo should prove

Build a tiny RNA sequence classifier with two paths: one training from random weights, one starting from a pretrained checkpoint. Train both on a small subset of a structural classification task (e.g., predict whether a sequence folds into a hairpin). Measure both the test accuracy and an estimate of the Hessian curvature at the final weights (using finite differences: measure how much the loss changes when you perturb weights by a small amount in random directions).

test_acc_random - test_acc_pretrained; avg_curvature_random - avg_curvature_pretrained

The demo must make it impossible to miss: the pretrained model should achieve higher test accuracy and have smaller curvature.
