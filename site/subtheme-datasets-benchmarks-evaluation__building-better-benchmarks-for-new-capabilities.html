Building Better Benchmarks for New Capabilities

Papers design and construct new evaluation datasets for emerging abilities like agents solving real problems, code generation, scientific discovery, and handling specialized domains that weren't tested before.

All themesField mapMathematicsAll explainers
What this is

Every few months, AI models gain abilities no one tested before because machine learning keeps advancing and researchers build bigger, better-trained models. A model might suddenly be able to help you write a program, or reason through steps of a proof, or assist in scientific discovery, or handle medical or legal cases. Researchers who work on this subtheme build the tests for these brand-new skills, because old tests do not measure what these new abilities need measured. You have to invent a new way to measure something that barely existed in AI a year ago.

Why is this hard? Because new capability means new kinds of questions to ask. When researchers realized models could code, they had to design tests that checked not just whether code syntax is right, but whether it actually solves the problem, whether it is efficient, whether it handles edge cases. When models started helping in science—suggesting new molecules or designing proteins—researchers had to create benchmarks that capture what real scientific progress looks like, not just pattern matching. The papers in this group do that grunt work: they design, collect, and validate datasets that measure emerging skills honestly.

The approaches vary widely. Some papers gather real-world examples: actual coding tasks from open source repositories, real chemistry problems, actual cybersecurity scenarios. Others craft synthetic tests carefully designed to probe a specific weakness or skill, the way you might create math problems of increasing difficulty to see where a student starts to struggle. What ties them together is that they all build toward the same goal: once a benchmark exists and researchers agree it is trustworthy, everyone can use it to compare progress.

How the work breaks down

Work in this subtheme splits into five main directions. First, researchers build benchmarks that test whether agents can solve real-world problems — not just simple tasks, but messy, multi-step work that requires reasoning and planning. Second, they focus on code generation because models now write actual programs, so benchmarks had to move beyond checking syntax to measuring whether code truly solves the problem. Third, they create benchmarks for specialized fields like finance, science, and medicine where general models struggle. Fourth, they push reasoning models to their limits by designing tests that expose when models rely on pattern matching instead of genuine reasoning. Fifth, they measure the speed versus accuracy tradeoffs when models use shortcuts like speculative decoding to predict multiple words ahead at once.

Agent reasoning on messy real tasks

Agents are now being asked to solve real problems — not toy problems in artificial environments, but actual messy work like gathering information from many sources, reasoning through scientific experiments, navigating terminal commands, and improving themselves over time. The problem is that old benchmarks measured simple things like question-answering, but agents need to do complex multi-turn work where mistakes compound. These papers tackle that gap by building evaluations that measure whether agents can actually complete hard, realistic tasks.

A Benchmark for Deep Information Synthesis shows that agents achieve only 8.97 maximum F1 when they have to gather and combine information from large databases, revealing that models hallucinate and lose track of what they know when information spaces are huge. AstaBench takes a different approach, providing rigorous principles and tools for testing agents across multiple scientific domains, being careful to account for confusing factors like how much it costs to call a model versus how good the model actually is. Terminal-Bench evaluates agents on genuine command-line tasks — the kind humans do daily — and finds that even frontier models score below 50%, showing they struggle with the unpredictability of real systems. Towards Self-Evolving Agent Benchmarks tackles a new frontier: benchmarks that can improve themselves as models improve by using reproducible agent traces, so evaluation stays reliable and adaptable as models change.

Together these papers move from testing agents on static, well-formed problems to testing them on dynamic, real-world work. Each reveals fundamental gaps — information management, reasoning stability, and handling of real-world messiness — that simpler benchmarks never caught.

Code generation from simple to complex

When models learned to write code, researchers realized that old programming benchmarks were too easy — they only checked if code syntax was correct or if it passed simple tests. Real code generation is harder: code must handle edge cases, be efficient, follow good practices, and actually solve the problem the human intended. The papers here build benchmarks that expose the gap between what models think they can do and what they actually can do.

Code2Bench reveals that models excel at using existing APIs (calling functions in libraries) but collapse when they have to invent new algorithms, uncovering an illusion of competence in earlier benchmarks. From Assistant to Independent Developer asks whether models can build complete software systems — not one function, but whole apps with multiple parts that work together, requiring code that knows what came before and handles edge cases. VERINA Benchmarking Verifiable Code Generation pushes further by requiring not just correct code but formal proofs that the code is correct — something far harder than just running it, with even the best model achieving only 72.6% code correctness but only 4.9% proof success. AlgoVeri An Aligned Benchmark for Verified Code Generation on Classical Algorithms shows how the type of proof language matters: the best models achieve 40.3% in Dafny (a simpler proof system) but collapse to 7.8% in Lean (which requires more rigorous reasoning).

These papers show a progression: generating code that passes tests is one thing, building integrated systems is another, and proving code is correct mathematically is harder still. Together they reveal that code generation ability is narrower and more fragile than it appears.

Benchmarks for specialized domains

General-purpose models are now attempting specialized work — financial analysis, scientific research, physics, medicine, and earth science — but these domains have their own jargon, reasoning patterns, and ways of being wrong. Off-the-shelf benchmarks do not work because they ignore what experts actually care about. Researchers building these benchmarks have to understand the domain deeply enough to know which mistakes matter and which do not.

FinSearchComp Towards a Realistic Expert-Level Evaluation of Financial Search and Reasoning creates the first open-source benchmark for agents reasoning about global financial markets, and finds that even Grok 4 only approaches expert-level accuracy; web search and financial tools help a lot because they fill gaps in the model's knowledge. SOSBENCH Benchmarking Safety Alignment on Scientific Knowledge evaluates whether models give safe, correct guidance on science topics — a critical concern because harmful advice spreads easily — revealing alarming rates of harmful responses (84.9% for Deepseek-R1, 50.3% for GPT-4.1). CMPhysBench A Benchmark for Evaluating Large Language Models in Condensed Matter Physics shows that even the best models reach only 36 average score on physics domain knowledge, a reminder that scaling up general models does not magically create specialized expertise. EDINET-Bench Evaluating LLMs on Complex Financial Tasks using Japanese Financial Statements finds that leading LLMs barely beat simple machine learning (logistic regression) on fraud detection and forecasting, because models trained on general text did not see enough financial reasoning examples to truly understand patterns that drive real financial decisions. EarthSE A Benchmark Evaluating Earth Scientific Exploration Capability for Large Language Models tests 11 leading models and finds significant limitations across earth science domains, showing that models generalize poorly across subspecialties.

These benchmarks reveal a hard truth: when you go deep into a domain, general models stumble. The gaps point toward where training and fine-tuning need to focus, and which tasks still need human experts.

Reasoning models at their limits

Reasoning models — models that explicitly think through problems step-by-step — are being marketed as more capable, but benchmarks designed to test genuine reasoning versus pattern matching tell a different story. These papers deliberately construct hard problems where a model cannot just memorize or recognize a pattern; it has to actually reason. The goal is to find the limits where reasoning models fail.

HardcoreLogic Challenging Large Reasoning Models with Long-tail Logic Puzzle Games creates logic puzzles that test whether models actually reason or just recognize patterns from training data. Models that top out on easier benchmarks suffer sharp performance drops on these hard logic puzzles, revealing heavy reliance on memorized patterns. MMReD a Cross-Modal Benchmark for Dense Context Reasoning shows a different kind of limit: as the amount of context (observations, information to hold in mind) grows — up to 128 observations in one test — all models degrade, with some frontier reasoning models hitting 0% accuracy, suggesting models struggle to reason over dense, long contexts. VideoPhy-2 A Challenging Action-Centric Physical Commonsense Evaluation in Video Generation tests whether models understand basic physics when generating videos. The best models achieve only 47.7% joint performance on hard cases and struggle particularly with conservation laws like mass and momentum — mistakes a child would not make, hinting that reasoning about physical reality works differently than pattern matching.

Together these benchmarks show that scaling up reasoning does not automatically fix deep reasoning gaps. Models still rely on shortcuts, and genuine reasoning — over long contexts, about physical laws, through logic puzzles they have never seen before — remains hard.

Speed versus quality tradeoffs

As models got larger and more expensive to run, researchers began asking how to generate text faster without sacrificing quality, so they could serve more users with the same hardware. One popular technique is speculative decoding, where a smaller, cheaper predictor guesses multiple words ahead, then the full model checks if the guess was right; you save computation time on correct guesses because you do not need the full model to run on those steps. Building a good benchmark for this requires understanding both raw speed and the quality loss.

Scaling Up Speeding Up A Benchmark of Speculative Decoding for Efficient LLM Test-Time Scaling discovers that simple n-gram methods (just looking at past words without understanding them) capture repetitive reasoning patterns surprisingly well, so they predict common phrases fast. When combined with smarter model-based approaches, these simple methods work alongside deeper reasoning for both repetitive and diverse reasoning, because they handle different parts of the problem. This is one of the rare moments where a cheaper shortcut proves useful because it does its job alongside deeper methods.
