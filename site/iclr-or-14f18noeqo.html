KnowProxy: Knowledge-guided proxy adaptation

KnowProxy teaches a smaller student model by copying written reasoning from a frozen teacher LLM, instead of copying probability scores.

Paper explainersAll themesLLMs & Foundation Models

Large language models (LLMs) are expensive to retrain. A common trick is to keep the big model frozen and train a tiny proxy model to mimic its decisions. But the usual way — copying probability scores — requires access to numbers the big model will not share. KnowProxy sidesteps this by asking the frozen big model to write out its reasoning in words, then teaching the proxy to learn from that text.

Zero assumption version

Why probability scores are unavailable

When you want a small student model to learn from a big frozen teacher model, a natural idea is to ask the teacher: 'for this input, what scores did you give each possible output?' The student then trains to match those scores. This is called knowledge distillation.

But in real life, big proprietary LLMs (like GPT-4 or Claude) rarely publish their internal scores. The company either keeps them secret for competitive reasons, or the model is accessed only through an API that returns a single final answer, not the probability for each option.

A beginner would think: 'just retrain the big model yourself on the new task.' But big LLMs are expensive to retrain — they have billions of parameters (individual numbers) that must be updated, and the computation takes weeks and enormous hardware.

The core problem. You cannot access the teacher's scores, and retraining the teacher is too expensive.

The algorithm as a flow

What it actually does

Elicit reasoning

Send each training example to the frozen teacher with a prompt: 'explain your reasoning.' Teacher writes its logic in words.

Collect reasoning

Gather all the text explanations from the teacher into a dataset.

Train proxy on text

The tiny proxy model learns to read the training examples and produce the same written reasoning the teacher gave.

Adapt to task

Proxy is then fine-tuned on the new task, carrying the teacher's reasoning style into its answers.

Deploy proxy

Use the trained proxy for new questions. It is cheaper because the proxy is tiny compared to the frozen teacher, so each answer takes less computation and memory.

What the paper changes

What the paper moves

Instead of copying probability scores from the teacher, KnowProxy copies written text reasoning. The training signal switches from 'match these numbers' to 'produce text that explains the decision the same way the teacher would.'

the object it moves  =  training signal source
The hidden quantity

The reasoning alignment score

measured quantity  =  how well proxy reasoning matches teacher reasoning

The hidden quantity is not a single number but a pattern: does the proxy's written explanation for a decision resemble the teacher's explanation? When the proxy is trained on text, it learns to produce language that aligns with the teacher's reasoning chain, even if the exact words differ.

The paper estimates this by measuring how closely the proxy's text matches the teacher's text (counting matching words and phrases), and indirectly by checking whether the final answers match on the target task.

Why it works

Why writing out reasoning works

In normal distillation, the student learns by matching probability scores. A score like 'positive: 0.8, negative: 0.2' contains compressed information about how confidently the teacher favors each option. The student mimics this confidence.

When you ask the teacher to write its reasoning instead, you are asking it to unpack that compression. The text 'This review praises the movie, uses words like excellent and brilliant, and recommends watching it. Therefore it is positive' contains the same decision logic, but explicitly. The proxy can learn from explicit steps more reliably than from abstract scores it cannot generate.

The second reason this works: text reasoning is more transparent to transfer. When the proxy reads the teacher's reasoning, it learns not just 'what is the answer' but 'what are the decision-making steps.' Those steps are more portable to new tasks. If the teacher's reasoning emphasized 'watch for praise words,' the proxy can carry that forward even when the task changes slightly.

The learning objective

First in words:

proxy_loss = text_matching_loss + alpha × task_performance_loss. The proxy trains to produce text close to the teacher's reasoning, then to answer the target task correctly using that reasoning.

Then the compact form:

L = L_text(proxy_reasoning, teacher_reasoning) + alpha * L_task(proxy_output, target_labels)

Every symbol:

Ltotal loss the proxy tries to minimize
L_texthow different the proxy's written reasoning is from the teacher's (measured by text similarity)
L_taskhow wrong the proxy's answer is on the actual task
alphahow much weight to place on task accuracy versus matching reasoning
proxy_reasoningtext the proxy generates explaining its decision
teacher_reasoningtext the teacher generated explaining its decision
A tiny worked example
Suppose the teacher wrote: 'The words excellent and brilliant appear. Therefore positive.'
The proxy generates: 'Praise words found. Thus positive.'
Text similarity (how many words and phrases match) = 0.7 out of 1.0. So L_text = 1.0 - 0.7 = 0.3.
On the task, the proxy says positive, and the label is positive. So L_task = 0.
With alpha = 0.5: L = 0.3 + 0.5 × 0 = 0.3. Proxy improves the reasoning match and task accuracy together.

The proxy balances learning to reason like the teacher and performing well on the new task, using textual reasoning as the bridge between them.

What can go wrong

What can go wrong

Teacher reasoning is wrong. If the frozen teacher's reasoning is flawed, the proxy learns and amplifies that flaw. Garbage in, garbage out.
Reasoning does not transfer to the new task. If the teacher's reasoning logic depends heavily on the original task, the proxy may struggle to adapt. For example, reasoning about spotting praise words in movie reviews does not help with solving math problems, because the decision-making steps are completely different.
Text quality varies widely. Some prompts elicit clear reasoning from the teacher, others produce vague or contradictory text. The proxy trains on inconsistent signals.
Done right. Choose a teacher that is known to reason well. Prompt it to generate clear, step-by-step reasoning. Measure the proxy's accuracy on the new task after training. If accuracy is high, it shows the proxy successfully absorbed the teacher's reasoning approach.
What a runnable demo should prove

What a runnable demo should prove

A concrete demo should show (1) the teacher frozen and answering a set of questions while writing its reasoning in text, (2) a small proxy model trained on a subset of those text explanations, (3) the proxy then fine-tuned on a new task (e.g., a reasoning benchmark with a different distribution), and (4) a direct comparison: proxy accuracy on the new task, versus retraining the teacher, versus a baseline proxy trained without reasoning text.

accuracy_proxy = (correct answers on new task) / (total answers on new task)

The demo must show that the proxy, trained only on frozen-teacher reasoning text, achieves comparable or better accuracy than a traditional knowledge distillation baseline. This works because text reasoning is more portable and transparent than abstract probability scores, allowing the proxy to absorb and apply the teacher's logic to new tasks.
