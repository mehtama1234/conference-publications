Generating video from images or descriptions

Papers on creating video sequences, including techniques to generate motion, extend videos infinitely, combine images, and control the motion that appears on screen.

What this is

Video is image generation's harder cousin. A single image can be beautiful and stay still forever, but video requires consistency across dozens or hundreds of frames—the content has to change plausibly over time while maintaining coherence. The car from frame 1 has to still look like the same car in frame 50. The physics has to make sense: if something is falling, it should keep falling. If motion is described ('the camera pans left'), every frame should show the world shifting smoothly leftward. This is radically harder than static images because the model has to learn and enforce temporal consistency.

The challenges break down into several parts. First, generating the initial motion: given a description or a starting image, what should move and how? A model trained on static images doesn't automatically understand motion. Second, extending videos: if you have a 5-second video, can you extend it to 10 seconds by predicting what comes next? Third, interpolating between frames: given frame 1 and frame 10, can you fill in frames 2-9? Fourth, motion control: can you specify exactly how something should move without letting the model decide? And fifth, infinite extension: can you keep generating new frames indefinitely while keeping the content coherent?

Papers here use several approaches. Some train separate models specifically for motion by using video data as training signal—showing the model pairs of consecutive frames so it learns what realistic motion looks like (a car doesn't teleport, it drives smoothly). Others use optical flow (the direction and speed pixels move between frames) as an intermediate representation—the model predicts flow first, then uses flow to warp or generate pixels, which breaks the problem into steps that are easier to solve. Some papers combine static image generation with a separate 'motion module' that predicts how each part should move, which lets them reuse existing image technology. For control, researchers use techniques borrowed from text-to-image work: if you can condition generation on text descriptions, you can condition it on motion descriptions, so users can specify 'pan left' or 'zoom in.' For infinite video, the trick is usually to process frames in overlapping windows so the model always has context about what came before, which lets it generate the next frame aware of earlier context and thus maintain coherence.

How the work breaks down

Video generation splits into five natural challenges. First, building models that generate longer sequences without losing coherence as frame count grows. Second, letting users control what moves and how. Third, preserving identity or appearance across shots. Fourth, making model predictions fast enough for interactive use. Fifth, handling specialized cases like camera motion or spatial structure where simple pixel generation fails.

Long video: autoregressive and streaming

Generating videos that last minutes or longer hits a hard wall: each new frame is generated from what came before, and small errors accumulate. If frame 100 drifts slightly wrong, frame 101 builds on that mistake, frame 102 compounds it further, and by frame 300 the video looks nothing like what was intended. The problem is even worse because the model has to track hundreds or thousands of past frames in memory, and that memory use explodes.

Rolling Forcing sidesteps this by using a rolling window: instead of building on the entire video history, it processes a sliding subset of recent frames. This cuts memory sharply and resets error accumulation. Similarly, Mixture of Contexts assigns computation only to important history (key frames, critical details), skipping redundant ones, and achieves near-linear efficiency as video length grows. SteinsGate uses causality principles (thinking of the diffusion process as a path integral) to convert existing models into frame-by-frame generators with proper temporal control. MoGA, the Mixture-of-Groups model, handles minute-level videos by grouping similar frames so they attend to each other, cutting compute without losing coherence. For real-time streaming, both LongLive and MoGA show that with careful scheduling and memory management, a single GPU can stream 24 fps output that people watch in real time. Context Forcing extends this further, enabling coherent generation for over 20 seconds—six to ten times longer than older methods.

These papers attack the same core insight: longer videos need either windowed processing (so the model doesn't track the entire history, which cuts memory use because fewer past frames must be stored) or sparse grouping (so compute stays manageable, which keeps runtime fast because most frames don't need consideration). They build on earlier work in how cleverly they implement that core idea.

Motion control and physics

A video looks convincing when motion is realistic. But models trained on raw pixels see motion as implicit—the network learns that cars generally move forward, but has no explicit concept of 'velocity' or 'direction,' which means it doesn't understand motion as a separate thing to control. Users often want to specify exactly how things move: 'the camera pans left' or 'the cup falls straight down.' Asking the model to guess these motions from text alone leads to jumps, flickers, and physically impossible actions because the model has no way to reason about motion rules.

Physics-Guided Motion Loss takes a direct approach: measure the difference between predicted motion and ground truth motion in videos, then penalize that difference during training. The insight is that motion accuracy is learnable—by forcing the model to match realistic motion patterns, video quality improves by about 11 percent and action recognition jumps proportionally. Motion Attribution extends this: it identifies which training examples have the highest influence on motion quality, then focuses on those examples in the next training cycle, yielding cascading improvements. Time-to-Move offers a training-free alternative: it uses Dual-Clock Denoising to let users specify motion paths without retraining, and matches training-based methods on realistic motion control. Temporal-aware Flow Matching uses optical flow (the pixel-level direction of motion) as an intermediate target. Instead of predicting pixels directly, the model first predicts flow (where pixels move), then uses that flow to warp or generate the next frame. This two-step process is easier to learn and more transparent to control. The Model Already Knows Best uses focus over the diffusion noise schedule itself: at each step, the model selects which noise level gives the best signal about the motion, then uses that level preferentially, improving temporal coherence.

All these papers share a philosophy: explicit motion modeling—whether through loss functions, data selection, flow intermediates, or noise selection—makes video quality jump. They build on the insight that video isn't just image generation; it's constrained generation where motion has rules.

Identity and reference preservation

When a person's face appears in frame 1, it should still be the same person in frame 100. When an object has a specific color or pattern, that trait should carry through. But diffusion models generate frames independently, and without strong anchors, they drift: the face morphs into someone else, colors wash out or shift, small details vanish. Users want to pass in a reference image or description and have the model respect it faithfully.

Phantom-Data builds a large dataset of video clips where the subject (person, object, or character) stays consistent across frames. Training on this data teaches the model the patterns that keep identity stable: certain face features cluster together, certain color palettes hold steady. The paper shows that models trained on Phantom-Data maintain identity consistency on par with specialized techniques while matching text descriptions better overall because the model learns identity as a learned signal, not an afterthought. MAGREF (Masked Guidance for Any-Reference Video Generation) takes reference images and masks them to isolate which parts matter. By selectively masking, the model learns what to copy from the reference (the subject's face or clothing) versus what to generate fresh (the background or new poses). This separation lets any reference video be used as a guide without retraining, because the model treats identity-relevant and environment-relevant features separately. DiasR (Dual-Modal Identity-Anchored Sparse Routing) extends this to multiple subjects, routing each subject's information through a separate path so identities don't bleed into each other, which means each person stays distinct. When a scene has five people, DiasR keeps each separate. MVCustom balances reference preservation against customization: it treats the reference image as a spatial scaffold (extracting 3D structure) and fills in customization details on top. LumosX relates identities to their visual attributes—if you want a face with certain characteristics, the model anchors that face identity in visual attribute space, not just pixel space.

These five papers collectively move from simple consistency to explicit identity modeling. They show that identity preservation isn't a side effect of training on video; it requires deliberate architectural choices and data that isolates and amplifies identity information.

Camera motion and spatial structure

Camera motion and spatial structure add constraints that pixel generation alone can't satisfy. A user might want the camera to follow a specific path—'pan left, then tilt up'—or might want consistent 3D structure across views. Without explicit spatial reasoning, the model generates plausible-looking pixels that violate real-world physics: objects vanish and reappear inconsistently, walls bend when the camera moves, multiple views show the same object at different sizes. The real world has spatial rules; ignoring them breaks immersion.

MoCa (Modeling Object Consistency for 3D Camera Control) uses an object-centric approach: instead of reasoning frame-by-frame, it tracks 3D positions of key objects and projects them into each frame as the camera moves. Without explicit 3D supervision (no depth maps, no CAD models), it learns to infer 3D structure from motion and enforces consistency. CameraNoise embeds camera poses directly into the noise itself, not as separate conditioning signals. The innovation is that noise becomes a spatial signal: the model learns that if noise encodes a leftward pan, pixels should shift right. Light-X extends this to illumination: it jointly controls camera and lighting so reflections stay consistent as the view angle changes. Spatial Forcing uses a 3D space representation—the model maintains a 3D coordinate frame and predicts how points move in that frame, then renders to 2D. This hybrid approach keeps pixel generation fast while enforcing spatial constraints. PanoWorld-X targets 360-degree video by using spherical space: instead of flat perspective, it reasons in spherical coordinates so panoramic scenes wrap correctly. 3D Scene Prompting adds a scene memory layer: as the model generates frames, it maintains a 3D spatial map of the scene, and each new frame respects that map's structure.

These six papers converge on the same principle: add spatial structure between the input (text or image) and the pixel output. Whether through object tracking, pose representation, 3D coordinates, or scene maps, explicit spatial reasoning makes camera and view control reliable.

Efficiency and generation speedup

Video diffusion models are computationally expensive. A 10-second clip at 24 fps means 240 frames, each needing multiple denoising steps, and each step involves large arithmetic operations. On a single GPU, generating a minute of video can take ten minutes or more. For interactive applications—users want to iterate and see results fast—this is painful. The challenge is cutting compute without destroying quality.

Towards One-step Causal Video Generation uses adversarial distillation to compress a multi-step diffusion model into a one-step generator. A teacher model (trained normally) guides a student that outputs finished frames in a single pass. The one-step model handles diverse generation schedules, so users can trade quality for speed by choosing 1, 2, or 4 steps. Causal Forcing (a sibling approach) fine-tunes for real-time interactive video, achieving 20 percent better motion control than simpler distillation because it uses causality—reasoning about what must come before what—to guide generation. Flow Caching skips redundant computation: optical flow (the motion between frames) is expensive to recompute for every frame pair. By caching flow from earlier generations and reusing it, the model achieves 2.4x speedup on some architectures and 6.7x on others because it doesn't recalculate motion for frames that haven't changed. Flash-VAED accelerates the decoding step: videos are generated in a compressed latent space, then decoded to pixels via a VAE (variational autoencoder). By using a faster VAE decoder, end-to-end generation accelerates by up to 36 percent. Quant VideoGen uses 2-bit quantization on the key-value cache (the memory of past computation states the model considers). By representing past information in 2 bits instead of full precision, memory drops sevenfold, which means the model fits in less GPU memory. Veda combines distillation with sparse frame grouping: it trains a smaller model that only considers important past frames, achieving 5x to 10x speedup on large models because it skips computing relationships over frames that don't matter.

All six papers optimize different bottlenecks: denoising steps, flow computation, decoding, memory, and smart frame selection. Together they show that video generation can be made interactive without sacrificing quality by attacking the problem from multiple angles.
