StretchTime: Time Series with Bendable Positional Encodings

A time series forecaster that learns to adaptively stretch and compress the temporal spacing between data points instead of assuming uniform time intervals.

Paper explainersAll themesTime Series & Sequential

Transformers (large sequence models) encode position by assuming time flows uniformly—each data point is one index number apart from the next. But real time series like weather patterns or stock prices do not flow uniformly; some periods matter more than others, and periodicities change locally. This paper proves that the standard rotation-based position encoding cannot capture this stretching and shrinking, and proposes learnable position encodings that let the model adaptively warp time itself to match local temporal structure.

Zero assumption version

Time spacing is not uniform in real data

Standard time series transformers encode position the same way language models do: by assigning each data point a fixed position index (1, 2, 3, ...) and then rotating the numerical representations by a fixed amount per step. The assumption: time advances smoothly and evenly.

But real time series do not behave this way. In stock markets, volatility clusters—some trading hours matter more than others because price swings are wider, so those periods encode more information. In biological signals, the spacing of heartbeats is not uniform: during rest, beats are slow and regular; during exercise, they accelerate. A forecasting model cannot assume that seeing 60 samples always covers the same wall-clock time, because 60 beats might span one minute at rest or 30 seconds during exercise. Weather patterns show local bursts of rapid change followed by long stable periods, meaning a day with storms matters more to tomorrow's forecast than a stable day. The transformer cannot adapt its focus (deciding which past points matter most) to match these stretches and compressions because the position encoding is locked in at the start.

What a beginner tries. Use the standard transformer position encoding (rotations at fixed angles) and hope the model's hidden layers learn to ignore the bad alignment.

What the paper changes

What the paper changes: position encodings

The paper replaces the transformer's fixed positional encoding (which rotates the numerical representations by a constant amount per time step) with a learnable encoding that first adapts the temporal coordinates to match the data, then applies different rotations based on those warped coordinates.

The hidden quantity

The hidden quantity: warped time coordinates

measured quantity  =  Warped time τ̃ (tau-tilde)

The paper's key insight is that real time series do not advance at constant speed through their natural dynamics. The hidden quantity it measures is the effective temporal spacing between data points—how much each interval should be stretched or compressed to align with the true periodicities in the data.

The adaptive warp module estimates this by looking at the input values directly. If the input changes rapidly, that interval gets stretched (meaning more rotation); if it is stable, that interval gets compressed. This warped time τ̃ is never output as a number; it lives only inside the position encoding computation, but it controls how the transformer attends to history.

Why it works

Why it works: adaptive rotation for focus

Self-attention asks: for predicting the next value, which past points are most relevant? It answers by computing dot products (a measure of alignment) between the current point's numerical representation and all past points' representations. The size of the dot product determines which past points matter most.

Standard position encodings rotate the query and key by a fixed amount per step, so the dot product is always smallest for distant steps. This assumes uniform time. But if time is stretched, a point that is close in warped time should attract high attention even if it is far in index space. Conversely, a point close in index but compressed in local time should be less relevant.

The paper's solution: rotate by an amount that depends on the warped time. If the adaptive module decides the interval to a past point should be stretched (high warped time), it applies a larger rotation, making the dot product smaller—lower importance. If compressed (low warped time), smaller rotation, higher importance. The model learns both the warping function and the rotation settings, so attention gradually aligns with the data's true temporal structure instead of fighting against uniform index-based spacing.

Math after the picture

The equation: symplectic rotation with adaptive warp

First in words:

The rotated query and key vectors are computed by applying a rotation matrix whose angle depends on the warped time difference, not the index difference. In symbols: the rotation matrix is a function of the warped time difference tau-tilde between two points, not the fixed index difference. Attention computes the dot product (how aligned two vectors are) between the rotated query and key, with the rotation angle learned from the data.

Then the compact form:

R(Δτ̃) = [[cos(Δτ̃), -sin(Δτ̃)], [sin(Δτ̃), cos(Δτ̃)]]; attention_logit = dot(R(Δτ̃_m - Δτ̃_n) times q_m, k_n)

Every symbol:

Δτ̃Warped time difference between two points in the sequence (how much time is stretched or compressed between them, learned from the data)
R(Δτ̃)Rotation matrix applied to query and key vectors; the angle depends on warped time, not fixed step count
q_m, k_nQuery vector for current point m and key vector for past point n
attention_logitDot product between rotated query and key; larger logit means higher attention weight
A tiny worked example
Suppose data changes rapidly at step 1→2 (high variance). Adaptive module sets warped time difference Δτ̃ = 0.8 (stretched). Rotation angle = 0.8 radians ≈ 46°.
Data is stable at step 3→4 (low variance). Adaptive module sets Δτ̃ = 0.2 (compressed). Rotation angle = 0.2 radians ≈ 11°.
When predicting step 5, queries rotate differently for step 2 vs step 4: step 2 gets larger rotation (46° vs 11°), so its key dot product is smaller and receives less attention, even though both are recent in index. The model learns to trust step 4 more because it is closer in warped time.

The rotation angle now adapts to the data's temporal stretching instead of using a fixed frequency, so attention aligns with local periodicities.

What can go wrong

What can go wrong

Overfitting the warp function. If the adaptive warp module is too complex (too many tunable values), it can overfit to noise in the input, learning spurious stretches that do not generalize to new data. Constrain the warp module to smooth, data-driven functions.
Large jumps in warped time. If the warp function produces abrupt changes in the temporal coordinate, attention can become unstable (some dot products explode, others vanish). Smooth the warp by adding a penalty to the loss that discourages abrupt changes.
Cold start on new datasets. The warp module must learn the true periodicities from the input. On very short sequences or datasets with little temporal structure, it may default to nearly uniform warping, losing the benefit.
Done right. Tune the warp module's expressivity (e.g., use a simple learned scaling function), add a penalty that discourages abrupt changes in the warp function, and ensure the forecasting loss jointly trains both the warping and the transformer. The paper uses a depth-1 encoder to prevent overfitting, and a modest 3-layer version for real use.
What a runnable demo should prove

What a runnable demo should prove

Build a synthetic time series with known, non-uniform periodicities. Example: a sine wave whose frequency increases over time, or a signal that alternates between fast and slow oscillation. Train two models: one with standard position encoding, one with StretchTime's adaptive warp. Measure forecast error (mean absolute error or RMSE) on held-out test data where the periodicity shifts.

Forecast accuracy = (1 - (error_with_warp / error_without_warp)) * 100%; higher is better. Report separately for stationary (uniform time) and non-stationary (warped time) test sets.

The demo must show that adaptive warping either improves or maintains accuracy on stationary data (because if the true time is uniform, the model learns a trivial warp that amounts to the standard encoding), and clearly improves on data where true time is non-uniform (because the warp now makes the transformer's natural distance-based focus mechanism align with the actual periodicities).
