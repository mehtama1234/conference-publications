Opt-Miner: Empowering Information-Seeking Agent with Tree-Guided Data Synthesis for Optimization Modeling

Train an optimization-modeling agent to notice missing knowledge, retrieve the needed material, and build the math model after it has grounded the problem details.

Paper explainersAll themesAgents & Tool Use

Optimization-modeling tasks often mix domain facts with formal math structure. A language model may know common modeling patterns, yet still fail when a real problem depends on industry-specific rules or technical details that are not already in the model. Opt-Miner trains an agent to notice those gaps and retrieve source material first, because a grounded model is less likely to choose the wrong formulation than one that guesses from partial knowledge.

Zero assumption version

Why optimization modeling fails on knowledge-heavy cases

Writing an optimization model is not only a matter of algebra. The agent must understand the real scenario, find the right constraints, and choose a fitting method. If the scenario depends on domain rules that are missing, the model may formalize the wrong problem.

Static pretraining is often not enough. A model can know general modeling patterns and still miss a technical regulation, an industry convention, or a special objective. In those cases, the agent must seek information actively because the missing fact changes how the optimization problem should be written.

The paper's move in one sentence. Synthesize training problems with planted knowledge gaps and train the agent to retrieve the missing material before finishing the model.

The algorithm as a flow

What it actually does

Turn each problem into a tree

Organize scenario details and technical methods into structured branches so that data synthesis can recombine them.

Synthesize harder multi-domain problems

Union, transfer, and hide parts of the tree so that the training problem contains real knowledge gaps.

Train retrieval-seeking behavior

Reward the agent for finding missing material before finishing the formulation because correct retrieval should improve modeling quality.

Ground the optimization model

Use the retrieved documents when choosing objectives, variables, and constraints.

Refine policy from grouped outcomes

Update the policy from relative performance across candidate solutions so that better information-seeking behavior is reinforced.

What the paper changes

What the paper changes

The paper changes what the agent does before it writes the model. Instead of jumping directly from problem text to formal formulation, it inserts an explicit stage for gap detection and retrieval.

the object it moves  =  the agent's decision about whether to retrieve outside knowledge before modeling
The hidden quantity

The hidden quantity

measured quantity  =  which missing fact is blocking the correct model

The key hidden quantity is the missing piece of knowledge that prevents the right formulation. The agent can sense that something is unclear, but it does not directly observe which document or concept will fix the problem until it searches.

Opt-Miner trains the agent to map from a partial scenario to that missing-knowledge decision. When the agent identifies the right gap, retrieval becomes useful because the fetched material can change the formal model in the needed place.

Why it works

Why this works: force the agent to earn the missing knowledge

An agent that is always trained on fully specified textbook problems can learn to rush into formulation. That habit breaks on real cases because many real cases omit a needed detail. Opt-Miner changes the training data so that some critical detail is missing on purpose, which makes retrieval part of the successful solution path.

The tree-guided synthesis matters because it creates structured hard cases instead of random noisy cases. By recombining scenario branches and method branches, the training set produces problems where the missing knowledge changes the formulation in a real way. The policy update then favors agents that retrieve the right material before committing to a formulation.

Math after the picture

Prefer policies that retrieve and model well together

First in words:

A compact summary is to score each candidate solution by combining retrieval quality and final modeling quality. The policy is updated toward candidates with larger combined score.

Then the compact form:

score(path) = model_quality(path) + gamma * retrieval_quality(path)

Every symbol:

score(path)overall value of one candidate information-seeking path
model_quality(path)how good the final optimization model is
retrieval_quality(path)how useful the retrieved material is for the task
gammaweight on the retrieval part of the score
A tiny worked example
Path A skips retrieval and writes a model with quality 5.
Its retrieval quality is 0, so with gamma = 1 its total score is 5.
Path B retrieves a domain rule and then writes a model with quality 7.
Its retrieval quality is 2, so total score is 9.
Training prefers Path B because the outside material improved the final formulation.

The paper uses a more detailed policy-optimization rule, but this score captures the point that retrieval is only valuable when it improves the final model because extra search alone is not the goal.

What can go wrong

What can go wrong

Retrieval can find the wrong document. If the agent grounds the formulation in a weak or irrelevant source, the final model can become more confidently wrong.
Synthesized gaps may differ from real gaps. Training gaps are generated from a tree recipe, so real industrial cases may still contain messier missing knowledge than the agent saw during training.
The agent may over-retrieve. A policy that searches too often can waste time and distract itself with extra material, even when the original problem already contained enough information.
Done right. The framework matters because it teaches the agent to treat uncertainty as a reason to seek evidence, not as a reason to guess.
