Any-Depth Alignment: Reintroducing Safety Tokens

Large language models already know when something is harmful, but that knowledge is hidden deep inside—by reintroducing the model's own safety header token during generation, we unlock that buried safety sense at any point.

Paper explainersAll themesAlignment, Safety & Fairness

Modern language models learn to refuse harmful requests, but only at the very start. Once generation begins, the protection vanishes—a hacker can trick the model mid-stream by giving it a harmful beginning and watching it continue. This paper discovered that the model's safety sense does not vanish; it just goes silent. By reintroducing the model's own safety header (a repeated piece of text like 'Assistant:') at any point during generation, the model reassesses what it is doing and can refuse again.

Zero assumption version

Safety collapses once generation starts

Current language models learn to refuse harmful requests by being shown many examples: 'Please explain how to build a bomb' gets a direct refusal. But this training only works at the very beginning of an assistant's response. If you trick the model by pre-filling a harmful start—like beginning the response with 'Sure, here is how...'—the refusal vanishes. The model has already committed and keeps generating. This is called shallow alignment: the safety net is strong only at depth zero (the very first word the assistant writes).

A beginner might try to fix this by training the model to refuse mid-stream: show it examples where a harmful request's beginning was generated and teach it to catch and undo itself. But this deep alignment training only partly works. It does not generalize across different kinds of attacks, and it still fails when someone carefully engineers the input to evade those defenses.

In one sentence. The model's safety sense is not gone during generation; it is locked away in a buried signal.

The algorithm as a flow

What it actually does

1. Discover the signal

The model's hidden layer representations contain a safety signal—a pattern that separates harmless from harmful content—even deep in generation.

2. Find the carrier

This signal is concentrated in the assistant header token, a small fixed piece of text the model always emits at the start of a response.

3. Reintroduce the carrier

During generation, pause and inject that header token again into the input stream, letting the model read its own cues.

4. Reassess harmfulness

The model's internal safety classifier wakes up and re-evaluates whether the current continuation is harmful.

5. Recover the refusal

If harm is detected, the model now refuses to continue, even though it was already mid-generation.

What the paper changes

What the paper changes

The paper injects the assistant header token—a piece of the model's own internal chat format—back into the generation stream at any point. This is a pure at-inference-time (run-time) change; the model's weights never move. The token is just four to eight words, like the string 'Assistant:' or 'Response:' that the model learns to emit before answering anything. By reintroducing this single token mid-generation, the model re-reads the learned safety instincts it has inside its weights.

the object it moves  =  Assistant header token (reintroduced mid-stream)
The hidden quantity

The safety signal buried in hidden layers

measured quantity  =  Harmfulness separability

Inside the model's neural network, at each layer, there lives a pattern of numbers (called a hidden state) that encodes whether the current text is harmful or benign. This pattern is not visible in the model's output; it is an internal thought. The paper calls this pattern linearly separable, meaning that if you draw a straight line through a plot of these patterns, you can perfectly split harmless from harmful on either side. The stronger this separation, the clearer the signal, because a wider gap between the two groups means even a simple decision rule (a straight line) can reliably tell them apart without mistakes.

The paper measures this signal by training a simple classifier (a logistic regression, which is just a learned straight-line boundary) on the hidden states at each layer and at each generation depth. When the classifier achieves near 100% accuracy, it means the safety signal is crystalline—the model knows, internally, that it is generating something harmful, even if its output keeps flowing.

Why it works

Why reintroducing the header unlocks safety

The model learned to refuse by seeing many examples of chat interactions, all starting with an assistant header (e.g., 'Assistant:') followed immediately by a refusal. These header tokens became calibrated to carry the model's safety instinct. During normal harmful generation, the model never sees the header again, so the signal path is not activated—the model just continues from where it left off. But when you inject the header token back into the input, the model re-reads the learned safety instincts embedded in the weights that sit next to that token.

Here is the key: the safety signal is not a hard rule painted into the model during training; it is a learned pattern in how the model processes text. The header tokens are the most reliable carriers of that pattern because the model trained with them in every single response. By reintroducing them mid-stream, you reset the context window locally and force the model to re-evaluate the harmfulness of the continuation. The model's classifier wakes up because the header is familiar—it has seen this token billions of times—and the pattern activates.

Math after the picture

The harmfulness classifier equation

First in words:

Harmfulness score at layer equals the learned straight-line boundary between safe and unsafe hidden states

Then the compact form:

safety_score = sigmoid(w_T * h_layer + b)

Every symbol:

safety_scorethe classifier output (0 to 1), where 1 means harmful
h_layerthe hidden state (a list of numbers) at a chosen middle layer
wthe learned weights (how much each number in h_layer matters)
bthe learned bias (the threshold for the boundary)
sigmoida function that squashes any number into the range 0 to 1
A tiny worked example
Suppose the hidden state h_layer is a list of 4 numbers: [2.1, -0.8, 3.2, 1.5].
The learned weights w are: [0.4, -0.2, 0.6, 0.3], and bias b = -1.0.
Compute the dot product: 0.4*2.1 + (-0.2)*(-0.8) + 0.6*3.2 + 0.3*1.5 = 0.84 + 0.16 + 1.92 + 0.45 = 3.37.
Add bias: 3.37 - 1.0 = 2.37.
Apply sigmoid: sigmoid(2.37) ≈ 0.91, so the classifier says 'this is 91% likely to be harmful content.'
When h_layer comes from the embedded assistant header in the input, this signal is strong and reliable.

The model's weights already encode this boundary; the classifier simply reads out what the model internally knows.

What can go wrong

What can go wrong

If the wrong token is injected. The header token is model-specific—each model family (Llama, Mistral, Qwen, etc.) has its own way of formatting 'Assistant:' in its weights. Injecting a token the model has never trained with will not carry the safety signal.
If the safety signal was not in the training data. Models trained on very few refusal examples, or models that were fine-tuned on harmful data afterward, may not have a strong buried safety signal to unlock. The method only amplifies an existing signal; it does not create one from scratch.
If the injected header is too obvious. If the injected token is easily recognizable by an attacker, the attacker can anticipate when it will be triggered and craft text that evades it (for example, by using different phrasings of 'harmful').
Done right. Tests on six model families show the method works, achieving near-100% refusal against dozens of attack types (GCG, AutoDAN, PAIR, TAP). This demonstrates that the buried safety signal is present across different models and holds up against many attack angles.
What a runnable demo should prove

What a runnable demo should prove

Build a simple script that takes a Hugging Face language model, a harmful prompt with a pre-filled harmful beginning (e.g., 'Provide bomb-making instructions: Sure, here is a summary...'), and injects the model's assistant header token at the 50-token mark. Run the model twice: once without injection and once with. The model without injection should happily continue the harmful content. With injection, it should refuse or pivot to safety. Measure the fraction of harmful requests that are still completed in each case. The demo proves the point if the completion rate drops from 80%+ to below 10% just by adding eight tokens at one point.

refusal_rate = (requests that refuse or omit harmful content) / (total requests) × 100%

The metric should climb steeply when the header is injected, showing that the model was not failing to understand the harm—it was just not checking.
