Reward-Preserving Counterfactual State Editing for Offline Reinforcement Learning

By showing the model a tweaked version of each state that has the same reward, CSET teaches it to ignore spurious details and see only what truly causes the reward.

Paper explainersAll themesReinforcement Learning

When a robot learns from historical logs of how it failed or succeeded, it sometimes picks up the wrong lesson. A light was on during good attempts, so the robot thinks the light caused success — even though it was just coincidence. CSET fixes this by generating alternative versions of each state that have the same reward, forcing the model to learn what truly matters.

Zero assumption version

The spurious correlation trap

In offline reinforcement learning, you train a robot from a log of past actions and their rewards. A transformer model (a neural network that reads sequences one item at a time, like a sequence of text) like Decision Transformer reads sequences of past states, actions, and returns and learns to predict the next good action. The danger: if the log shows that successes all happened when a particular object was in the scene, the model learns to rely on that detail — not because it is actually necessary, but because it happened to always be there. These false correlations are spurious correlations: they predict the outcome in the data but do not reflect true causality.

A beginner might try to ignore this by adding more diverse training data, but the paper is about strictly offline settings where the log is fixed. Or one might build a full world model that simulates state transitions, but that adds huge complexity and can propagate its own errors. CSET solves this without either: by editing the state in a principled way.

The core idea. Show the model a minimally changed version of each state that has the same reward, so it learns to ignore the spurious details and attend only to true causes.

The algorithm as a flow

What it actually does

Step 1: Fit a reward model

Learn a conditional autoencoder that estimates which states would give a certain reward.

Step 2: Generate counterfactual states

For each real state, ask: what tweaks to the observation keep the reward the same?

Step 3: Enforce plausibility

Use a move-band constraint so edits are small; add an acceptance gate so only realistic changes are used.

Step 4: Augment training data

Replace only the observation component (the visual stream); do not invent fake successor transitions.

Step 5: Train with causal structure

Modality-specific encoders (separate pathways for return, state, action) with supervised guidance so action choice focuses on true causal parents.

What the paper changes

The core change

CSET changes the training data itself: instead of only the real states from the log, it includes minimally edited counterfactual versions of those states that have the same reward.

The hidden quantity

Spuriousness: strength of false correlations

measured quantity  =  spurious correlation weight

A spurious correlation is a detail in the state (like a background object or lighting) that predicts reward in the historical data but does not actually cause it. The 'weight' of this spurious correlation is how strongly the model relies on it for action choice. CSET estimates this by checking which state features stay constant across the counterfactual edits: if a detail changes but reward does not, the model learns that detail has low causal weight.

The paper measures this via the reward model's ability to predict across edited states. If edited states have the same reward, the causal parents (true causes) stay the same, while spurious features change. The model's action prediction is then soft-supervised via attention mechanisms (neural pathways that learn which inputs matter most) to focus on the causal parents.

Why it works

Why it works: teaching via counterfactual twins

The mechanism is simple: if you show a model two very similar states with the same reward, it is forced to stop relying on the difference between them. A light flickering on and off in two otherwise identical states will no longer predict the reward, because both states give the same outcome. The model learns to ignore it.

CSET uses a causal reward model (a conditional variational autoencoder) to propose these minimal edits. For each real state, it asks: what small changes to the observation leave the reward unchanged? The model samples from the autoencoder to generate candidate edits, then gates them with a plausibility check (move-band constraint: keep changes small) and a reward-consistency check (the edited state must still predict the same reward). This ensures the counterfactuals are realistic and honest.

On the transformer side, CSET uses modality-specific encoders (separate neural pathways for return-to-go, current state, and action), and a final attention block that is soft-supervised to focus on direct causal parents. This structural bias — forcing separate processing of each signal type — helps the model learn which features truly drive action selection, because by isolating each data stream in its own encoder pathway, the model cannot accidentally mix spurious correlations from one stream into the decision-making of another; each pathway must justify its signal independently to the final action prediction.

Math after the picture

Enforcing counterfactual consistency

First in words:

loss = action prediction error + lambda times similarity between reward of edited state and original state, weighted by plausibility gate

Then the compact form:

L = CE(a_pred, a_real) + lambda * gate(s_edit) * L_reward(s_edit, s_real)

Every symbol:

Ltotal training loss
CE(a_pred, a_real)cross-entropy error: difference between predicted action and true action taken
s_editthe edited (counterfactual) state proposed by the reward model
s_realthe real state from the data log
L_reward(s_edit, s_real)error in reward: how much the edited state's predicted reward differs from the original
gate(s_edit)a score between 0 and 1: how realistic is this edit (move-band + reward-consistency gate)
lambdaa weight controlling how much counterfactual consistency matters relative to action accuracy
A toy example with three objects
Real state: [cup=on, ball=off, light=on], real action=move-forward, reward=50.
Counterfactual edit: [cup=off, ball=off, light=on] (only cup changes).
Causal reward model predicts: this edit also gives reward=50.
Action loss = error when predicting move-forward from this state.
Reward loss = |50_predicted - 50_actual| = 0, so counterfactual is rewarded.
Cup cannot be a true cause (reward is the same without it). Model learns to ignore it.
If we also show [cup=on, ball=off, light=off], reward drops to 35: now light matters. Attention focuses on light.

By enforcing that edited states have the same reward, the loss function teaches the model to ignore spurious features and focus only on true causes.

What can go wrong

What can go wrong

Poor reward model fit. If the causal reward model is inaccurate, the counterfactual edits will be invalid (edited state does not truly have the same reward), and the model learns from false examples.
Move-band too loose or too tight. Too loose: edits become too large and change the true cause, defeating the purpose. Too tight: edits are trivial and do not expose spurious features.
Genuine spurious correlations are not visible in the data. If a true cause is always on (or always off) in the log, counterfactual editing cannot expose it; the method requires variation.
Acceptance gate filters out good edits. If the plausibility threshold is too strict, most edits are rejected, reducing the augmented data.
Done right. Reward model is accurate, move-band is tuned to the domain, the log has sufficient state variation, and the gate threshold balances plausibility with coverage.
What a runnable demo should prove

What a runnable demo should prove

Train a Decision Transformer on D4RL locomotion tasks (MuJoCo), then inject a spurious visual feature (e.g. a color overlay that correlates with reward in the training log but is not causally related to the agent's motion). Evaluate on test episodes where the spurious feature is removed or inverted. Measure: does the standard model's performance drop when the spurious feature changes? Does CSET's model maintain its performance?

performance_drop = (accuracy_with_spurious_feature - accuracy_without_spurious_feature) / accuracy_with_spurious_feature

A truly causal model should perform the same whether or not a spurious visual feature is present, because it has learned that the feature does not cause the reward.
