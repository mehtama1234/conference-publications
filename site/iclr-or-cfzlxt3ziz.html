FIRE: Balancing Stability and Plasticity

When a neural network trains on new data after old data, reinitializing weights orthogonally lets it remember the past while adapting to the future.

Paper explainersAll themesOptimization

Deep networks learn continuously, but face a hard tradeoff: hold onto what they learned before, or adapt fast to new data. Standard reinitialization (nudging weights back toward where they started) is too blunt. FIRE picks the perfect reinitialization point by measuring two things—how far weights have drifted from the past, and how twisted the weight matrix has become—then untangles it.

Zero assumption version

The stability-plasticity wall

Real networks never stop learning. A vision model trained on cars must handle trucks. A language model trained on encyclopedias must read news. The natural path: run training again on the new data. But something breaks: the network forgets what it knew. The old patterns disappear from the weights. A naive beginner tries to prevent forgetting by locking the weights—do not change them at all. That fails instantly: the network cannot adapt to the new data at all. Someone else tries the opposite: reset the weights to their original startup values, hoping the network relearns everything from fresh. That also fails: the network does not remember the useful patterns the old training built, so it has to rediscover them slowly, and often gets stuck in worse local solutions.

The problem is invisible but severe: no one knows how hard to nudge the weights back. Too conservative, and the network stays stuck in old patterns. Too aggressive, and plasticity—the ability to learn new things—evaporates.

In one sentence. FIRE orthogonalizes the weight matrix at the reinitialization point to untangle learning signals and free up adaptation.

The algorithm as a flow

What it actually does

Measure stability drift

Calculate how far each weight has moved from the end of the last training phase.

Measure weight twist

Check how far the weight matrix is from being orthogonal (untwisted).

Solve the tradeoff

Find the reinitialization point that keeps drift low while untangling the matrix.

Rotate weights

Use Newton-Schulz iteration to orthogonalize: multiply by a carefully chosen rotation matrix.

Resume training

Train on new data. Learning signals now flow freely through the untangled weight matrix.

What the paper changes

What the paper changes

The paper changes the reinitialization point: where the weights sit before learning on new data. Instead of a fixed rule (like pushing halfway back to the original), FIRE picks the exact point that solves a constrained optimization problem.

the object it moves  =  reinitialization point
The hidden quantity

Deviation from Isometry: the twist in the weight matrix

measured quantity  =  Deviation from Isometry

Every weight matrix can be decomposed into a magnitude and a rotation. An orthogonal weight matrix is one that has been rotated to stand upright—no twist, no skew. Deviation from Isometry (DfI) measures how far the weight matrix is from this upright state. When weights are twisted, incoming learning signals bounce off at angles, so adaptation becomes inefficient. Untangling the matrix straightens the signal flow.

FIRE estimates DfI by looking at the singular values of the weight matrix. It then solves for the untangled version: the rotation that makes DfI zero while keeping the weight magnitudes as close as possible to what they were. The Newton-Schulz iteration computes this rotation efficiently.

Plain reading. Think of a pencil lying flat on a table (orthogonal): light bounces straight up. Now twist the pencil into a spiral (non-orthogonal): light bounces in all directions, wasting energy. Orthogonality is the straightest path for learning signals to travel.
Paper reading. The weight matrix can be broken into a rotation part and a scaling part (singular value decomposition). Orthogonality means the rotation part is pure rotation without scaling. Deviation from Isometry measures how far the rotation is from being pure; minimizing it means finding the closest pure-rotation matrix while preserving the scaling part.
Why it works

Why untangling weights fixes the tradeoff

Here is the core mechanism: when a network trains on data, its weight matrix becomes twisted—certain directions amplify learning signals, others dampen them. This twisting happens because the network specializes to the old data. When new data arrives, the twisted weight matrix acts like a filter: some learning signals pass through loud and clear, while others are blocked or distorted. This is what kills plasticity. The network struggles to learn because signals cannot flow in the directions needed for new patterns.

FIRE rotates the weight matrix to be orthogonal. Orthogonal matrices treat all directions equally—no amplification, no blockage. Gradients flow straight through. The magnitudes of the weights (how strong each connection is) stay the same; only their orientation changes. So the network remembers the strength of its learned patterns—that is stability. But it can now absorb gradients freely in any direction—that is plasticity. The Newton-Schulz iteration finds this rotation efficiently, adding less than one percent to training time.

Math after the picture

The math behind FIRE

First in words:

Squared Frobenius Error measures how far weights drift. Deviation from Isometry measures how twisted the matrix is. FIRE minimizes SFE subject to DfI equals zero. SFE sum of i,j (W_ij minus W_old_ij) squared. DfI the norm of the difference between the weight matrix and its closest orthogonal rotation.

Then the compact form:

minimize (sum of squares of weight changes) subject to (weight matrix is orthogonal)

Every symbol:

W_ijthe current value of weight at row i, column j
W_old_ijthe weight value at the end of the last training phase
SFESquared Frobenius Error: sum of all squared weight changes
DfIDeviation from Isometry: how far the matrix is from orthogonal
Uthe rotation part of the weight matrix (from singular value decomposition)
A tiny worked example
Suppose a layer has 4 weights. Old training left them at [8, 6, 5, 9]. After training starts on new data, they drift to [8.2, 6.5, 4.8, 9.3]. The Squared Frobenius Error is (0.2)^2 + (0.5)^2 + (-0.2)^2 + (0.3)^2 = 0.04 + 0.25 + 0.04 + 0.09 = 0.42.
The weight matrix from these 4 values is twisted (measured by singular values not all 1.0). FIRE asks: which orthogonal matrix keeps the magnitudes [8, 6, 5, 9] but minimizes twist? It solves for the rotation. The rotated version might be [8.1, 5.9, 5.2, 9.2]—closer to orthogonal, near the old magnitudes.
Result: weights stayed close to their old values (low SFE), but the matrix is now orthogonal (zero DfI). Training on new data now flows freely through the untangled matrix.

FIRE solves the constrained optimization problem exactly (in theory) and approximates it efficiently via Newton-Schulz (in practice).

What can go wrong

What can go wrong

If the weight matrix is already orthogonal. FIRE does nothing (as it should). But this is rare in real networks. Most architectures and training procedures produce twisted weight matrices.
If magnitudes are all the same. The constrained problem has many solutions (any rotation preserves magnitudes if they are uniform). FIRE picks one arbitrarily. The paper recommends careful initialization to avoid this edge case.
If training on new data is very different from old data. Preserving old weight magnitudes (stability) might conflict with learning new patterns (plasticity) if the tasks are completely disjoint. FIRE can only untangle the matrix; it cannot invent useful patterns if the old and new data share no useful structure.
Done right: orthogonalize at the reinitialization point, preserve magnitudes, and let gradients flow. FIRE is tuned to add less than one percent overhead and does not require hand-tuned hyperparameters, so it works out of the box across vision, language, and RL.
What a runnable demo should prove

What a runnable demo should prove

Train a small ResNet or GPT model on a standard dataset (CIFAR-10, WikiText-103, or Atari). Measure accuracy on the original task. Then, without erasing the model, train on a new dataset (a different set of CIFAR-10 classes, a new text corpus, or a different Atari game). Measure old and new accuracy. Compare: naive training (just continue), naive reset (reset all weights to startup values), and FIRE (orthogonalize). FIRE should keep old accuracy high while also achieving high new accuracy. The metric is forgetting: old accuracy before new training minus old accuracy after new training. FIRE should reduce forgetting compared to both baselines.

forgetting = old_task_accuracy_before - old_task_accuracy_after. Lower is better. Also measure new_task_accuracy_after. FIRE is good when both old and new are high.

The demo must make clear that FIRE keeps the network's old knowledge intact (high old-task accuracy) while freeing up learning to absorb new data (high new-task accuracy), solving the stability-plasticity tradeoff.
