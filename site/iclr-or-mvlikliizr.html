NEO — No-Optimization Test-Time Adaptation through Latent Re-Centering

Adapt to corrupted test data by shifting internal feature vectors back toward the source center instead of running test-time weight updates.

Paper explainersAll themesOther

Test-time adaptation tries to recover accuracy after the data at deployment differs from the data used in training. Most methods do this by changing model weights during deployment, which adds extra passes, tuning knobs, and failure modes. NEO takes a lighter route. It looks at the model's internal feature vector (the list of numbers produced before the classifier head), measures how far the new batch has drifted from the source feature center, and shifts those feature vectors back toward the origin before classification. The claim is simple: part of the damage from corruption is a systematic translation of the feature cloud, so removing that translation can recover alignment without updating weights.

Zero assumption version

Why ordinary test-time adaptation is expensive and fragile

A classifier is trained on source data, then deployed on data that may be blurred, noisy, restyled, or otherwise shifted. Even when the semantic class is unchanged, the internal feature vectors can move away from the regions where the source classifier was calibrated. The final class boundary then receives inputs from the wrong place and accuracy drops.

A common response is to keep optimizing during deployment. Methods update normalization statistics, minimize an uncertainty objective that pushes predictions to become sharper, or adapt selected weights on the fly. That adds compute because each deployment batch triggers extra forward or backward passes. It also adds tuning because small mistakes in learning rate, batch size, or adaptation schedule can erase gains or even damage predictions.

NEO targets a narrower failure mode: the feature vectors move, but the learned class structure still exists. If that is true, the main task is not to relearn the classifier but to put the feature cloud back into the coordinate system where the classifier already works.

In one sentence. NEO treats part of test-time shift as a translation of internal feature vectors and corrects it directly, because moving features back can be cheaper than changing weights.

The algorithm as a flow

What it actually does

1. Run the backbone once

Extract internal feature vectors for the target batch using the frozen model.

2. Compute the target batch center

Average the feature vectors in the batch to estimate where the shifted batch sits in feature space.

3. Re-center the batch

Subtract the estimated shift so the batch center moves back toward the source origin.

4. Reuse the existing classifier head

Feed the re-centered features into the original class predictor because the class boundaries were learned in that source-centered coordinate system.

5. Repeat for the next batch

Adapt each batch independently without storing optimizer state or modifying weights.

What the paper changes

What the paper changes

The paper changes the representation presented to the classifier head at deployment time. It leaves model weights fixed and instead shifts the internal feature vectors before the final prediction step.

the object it moves  =  the test-time feature coordinates
The hidden quantity

The hidden quantity: feature-center drift

measured quantity  =  how far the target batch center has moved away from the source center in the model's internal feature space

The target labels are unknown at deployment, so the system cannot directly measure class error while adapting. What it can measure is the batch center of the internal feature vectors. If the source model was trained so features were centered in a useful way, then a shift in that center is a visible signal that the whole batch has moved in a systematic direction.

This quantity matters because a linear classifier depends on relative position. If every feature vector is translated by a similar amount, many points cross class boundaries for the same geometric reason: the classifier sees them in the wrong coordinates. Re-centering fixes that common offset without touching the shape of the classifier.

The abstract also reports cross-class transfer from one adapted class to many others. That makes sense under this view because the correction is shared at the batch level. A center shift estimated from some examples can help the rest because the same batch-level translation moves many classes together when the corruption acts on the whole feature cloud rather than one class in isolation.

Why it works

Why a simple shift can recover accuracy

Suppose the classifier head was learned on source features whose center was near zero. Now suppose a corruption changes contrast or texture in a way that pushes many features in roughly the same direction. The class clusters may still keep their relative arrangement, yet the whole collection is displaced. In that case, weight updates are solving a translation problem with a much heavier tool than needed.

NEO works when the source classifier remains mostly correct in the source coordinate system. By subtracting the target batch center, it moves the batch back toward that coordinate system. This helps because the class scores depend on dot products with fixed classifier weights, and those dot products change systematically when all features inherit a shared offset.

The method is cheap because it replaces optimization with a mean computation and a subtraction. It is also stable in the reported setting because there is no learning-rate choice and no risk of accumulating bad weight changes across batches. The tradeoff is that it only fixes the part of the shift that looks like translation; it does not repair more complex warping of the feature space.

Math after the picture

The re-centering rule

First in words:

Compute the mean feature vector of the target batch and subtract it from each target feature vector before classification.

Then the compact form:

mu_target = (1 / B) * sum_b z_b, z_b' = z_b - mu_target, y_b = classifier(z_b')

Every symbol:

Bnumber of examples in the target batch
z_binternal feature vector for example b before adaptation
mu_targetmean feature vector of the current target batch
z_b're-centered feature vector after subtracting the batch mean
y_bpredicted class after re-centering
classifierthe original frozen class head learned on source data
A tiny worked example
Suppose a batch has three one-dimensional features: 3, 4, and 5.
The target batch mean is 4.
After re-centering, the features become -1, 0, and 1.
If the source classifier was learned around zero, these corrected values match the source coordinate system far better than the raw shifted values.
The method therefore fixes the shared offset with one subtraction per feature vector instead of changing any model weight.

The paper's idea is that the common shift matters more than per-example corrections in many corruptions, so removing the batch mean can restore useful alignment at almost no extra cost.

What can go wrong

What can go wrong

The shift is not mainly a translation. If corruption stretches, rotates, or bends class clusters rather than moving them together, subtracting one shared center cannot undo the damage.
The batch is too small or unbalanced. If the batch mean is estimated from only a few examples or mostly from one class, the re-centering vector can be noisy and may move the batch in the wrong direction.
Source features were not centered in a useful way. The method assumes the trained classifier head expects source features in a stable coordinate system near the origin. If that training arrangement was already uneven, re-centering may not help much because there may be no single source-centered location that restores the class boundaries cleanly.
Done right. When corruption mainly adds a shared offset to internal features, re-centering works well because it restores the coordinate system the classifier head already knows.
What a runnable demo should prove

What a runnable demo should prove

Train a small image classifier on clean digits. Then create a shifted test set by adding one corruption that mostly changes contrast or blur and another that changes style more severely. Extract the penultimate-layer feature vectors for each test batch. Compare three settings: no adaptation, batch re-centering, and a simple uncertainty-minimizing test-time optimizer.

The demo should show that re-centering gives most of the gain on the translation-like corruption because the batch mean captures the dominant drift, while it helps less on the style change because the class arrangement itself is warped.

adapted_accuracy = correct_predictions / total_predictions center_shift_size = average_batch_norm_of(mu_target)

A good result is not only higher accuracy, but the visible link between large batch-center drift and the cases where re-centering helps most, because those are the cases where a shared translation error is large enough for mean subtraction to undo it.
