Discrete Diffusion VLA

Instead of generating robot actions all at once or in a left-to-right sequence, unroll the action generation like denoising: start with all action slots hidden, then reveal the most confident ones first, then the harder ones, allowing the model to self-correct uncertain predictions.

Paper explainersAll themesRobotics & Control

Vision-language-action models teach robots to follow instructions by combining image understanding with language. Today they either predict actions one token after another in fixed order (slow and inaccurate) or bolt a separate diffusion module onto the side (which breaks the shared visual-language understanding the model learned before). This paper puts discrete diffusion directly inside the model backbone, letting the model predict all action parts in parallel but adaptively, revealing the actions it is most confident about first and leaving room to refine the shaky ones.

Zero assumption version

Two bad ways to teach robots to act

A robot needs to understand a picture and a spoken instruction, then output a sequence of movements: move the arm, rotate the wrist, open the gripper. Large vision-language models are great at understanding images and text, so it makes sense to build on them.

But these models were trained to predict text one token at a time, left to right. If you force them to predict robot actions the same way, they get stuck: the first action token has almost no context (it does not know what the rest of the action will be), so it guesses poorly. By the time later action tokens appear, the earlier mistakes are locked in.

To fix that, researchers added a separate diffusion module: instead of predicting actions inside the language model, they bolt on an extra piece that generates actions from scratch. But now the model has two competing goals—understand images and language on one side, generate actions on the other—and they pull in different directions. The result: the model forgets the visual and language skills it had learned before. On out-of-distribution tests (when the robot sees something different from training), performance crashes.

In one sentence. The paper keeps the action generation inside the shared vision-language model but changes how it predicts: instead of guessing each action token blindly, it iteratively unmasks tokens—revealing confident action parts first, then refining uncertain ones—so the whole model stays aligned and vision-language understanding survives.

The algorithm as a flow

What it actually does

Discretize

Convert each robot action (move arm 5 cm, rotate wrist 30 degrees, open gripper) into small integer tokens (like binning continuous values).

Bundle actions

Group H consecutive timesteps of actions into one fixed chunk (e.g. 12 timesteps, each with 7 tokens, making 84 action tokens total).

Start masked

Hide all 84 action tokens. Feed the picture and instruction to the transformer; it sees everything except the actions.

Iterative unmask

In each of T steps (e.g. 4 steps), unmask fewer tokens. Step 1: keep most masked (reveal ~25%). Step 2: reveal more (~50%). Steps 3–4: refine the rest. The model predicts masked positions using the unmasked actions plus image and language as context.

Adaptive order

Do not unmask randomly. Let the model's confidence guide the schedule: tokens the model outputs with high certainty in early steps get unmasked first (the easy ones), because predicting them correctly gives the model trustworthy anchors; tokens with low certainty stay masked longer (the hard ones), so later steps can use those anchors to narrow down the possibilities, making hard predictions more accurate.

What the paper changes

The single thing that changes

The paper changes how robot actions are generated: from a fixed left-to-right sequence inside a language-model head to a masked-token prediction loop inside the shared transformer backbone, with bidirectional attention (each action token can see all language, image, and other action tokens).

The hidden quantity

Mask ratio: how many action tokens to hide at each step

measured quantity  =  Mask ratio schedule (gamma)

During training, for each batch of actions, the paper samples a mask ratio—a fraction of tokens to hide—from a schedule that follows a predictable curve. This mimics diffusion: early in training, many tokens are masked (learning happens through full context); later, fewer tokens are masked (learning gets refined).

During inference (when the robot actually acts), the model starts with everything masked and follows a fixed schedule: step 1 might mask 100% of action tokens, step 2 might mask 75%, step 3 might mask 50%, step 4 might mask 25%. High-frequency, easy-to-predict tokens get unmasked early (revealed in steps 1–2); low-frequency, harder tokens stay masked longer (refined in steps 3–4). The paper learns this adaptive order implicitly: the model outputs are higher-confidence for some dimensions, and the schedule naturally favors revealing those first. If later the model sees it made a mistake (step 4 output conflicts with step 1 output), it can re-mask uncertain tokens and try again—this is called secondary re-masking.

Why it works

Why this fixes both problems at once

The core difference: the model does not need to guess actions in one forward pass, and it does not need a separate diffusion head. Instead, it can refine iteratively using the full model context.

Mechanism 1 (stays aligned with vision-language): The paper trains with only masked cross-entropy loss—the same loss that trained the original language model. There is no auxiliary objective, no competing signals pulling the model in two directions. The model learns to predict masked action tokens using vision, language, and unmasked action tokens as context, all inside the same model. Because the loss objective never contradicts the original vision-language training, the model does not unlearn those skills.

Mechanism 2 (adaptive order is more efficient): In early steps, the model confidently predicts easy action dimensions (e.g. gripper open/close is binary and obvious from the image) because they have few degrees of freedom and visual answers. In later steps, it refines harder ones (e.g. exact arm position requires subtle language reasoning, translating instruction phrases into coordinates). By masking in decreasing quantities, the model can use each earlier prediction to inform later ones—if the gripper is open, the arm position predictions can be narrower—making final refinement more accurate and faster than guessing all actions at once.

Mechanism 3 (secondary re-masking allows self-correction): After step 4 is done, if the model detects internal contradiction (a gripper state that conflicts with the arm position, or actions that violate physics), it can re-mask uncertain tokens and refine them. Because the model sees all predictions at once (they are all outputs from the same step), it can check consistency across action dimensions; if two conflict, the lower-confidence one gets re-masked and refined. This adds a consistency-checking loop that vanilla parallel decoding cannot do, because single-pass methods have no way to revise.

Math after the picture

The training objective in one equation

First in words:

Cross-entropy loss on masked action tokens. Sample a mask ratio from a schedule, hide that fraction of tokens, train the model to predict what is hidden given what is not hidden.

Then the compact form:

L = -sum_i [1_{i in mask} * log P(a_i | unmasked_actions, image, language)]

Every symbol:

iindex of an action token
1_{i in mask}1 if token i is masked, 0 if visible
a_ithe true action token at position i
P(a_i | ...)probability model assigns to the correct token given visible context
unmasked_actionsthe action tokens that are NOT masked
imagethe camera input
languagethe instruction text
A tiny worked example
Suppose the model outputs probabilities: P(arm_x = 42) = 0.8, P(gripper_open = 1) = 0.6.
Loss for arm_x (correct answer is 42): -log(0.8) ≈ 0.22.
Loss for gripper_open (correct is 1): -log(0.6) ≈ 0.51.
Total for those two tokens: 0.22 + 0.51 = 0.73. (Lower loss = higher confidence in correct answer.)
The model learns: boost the probability of correct answers. Same training as language models.

This equation is identical to language model training, which is why vision-language knowledge survives; the difference is the masking schedule, which adds iterative refinement without changing the learning signal.

What can go wrong

What can go wrong

Bin discretization loses precision. Converting continuous action values (e.g. arm position 5.3 cm) to discrete tokens (bin 5) throws away sub-bin detail, causing errors on tasks that require fine positioning. The paper shows 0.7% performance loss from binning alone compared to continuous methods. Higher resolution bins (more possible values) reduce error but require the model to predict from a larger set of options, which costs more computation and slower inference.
Wrong mask schedule ruins refinement. If the schedule unmasks too fast, hard action dimensions get refined with little context. If too slow, inference takes many forward passes and becomes slow. The paper finds the right schedule by trial and error but does not give a principled method to set schedules for new domains.
Secondary re-masking can loop infinitely. If the model keeps detecting contradictions and re-masking, inference becomes unpredictably expensive. The paper does not define when to stop re-masking.
Done right: inherits biases from pretraining. Because the method relies on a large pretrained vision-language model, it also inherits any biases in that model's training data. This is not unique to this paper but must be checked before real-world deployment (e.g. does the model underperform with certain arm poses or on certain objects?).
What a runnable demo should prove

What a runnable demo should prove

Build a toy robot task: a robot arm must pick up one object from a table and place it in a bin, following a language instruction. Use a simple simulated arm with 3 continuous action dimensions (x, y, z position). Collect 50 human demonstrations. Train three variants: (1) autoregressive baseline (predict actions left to right), (2) continuous diffusion (separate head), (3) this paper (discrete diffusion inside the transformer). On a held-out test set of 20 new objects and instructions, measure success rate and how well the model follows instruction language after fine-tuning on the new objects.

success_rate = (# of trajectories that pick up correct object and place in correct bin) / (# of test trials); language_retention = (accuracy on language paraphrases of instructions) before vs after fine-tuning

The demo is a success if: (1) discrete diffusion matches or exceeds continuous diffusion on the base task (success rate), because both should solve the task well, AND (2) when fine-tuned on new objects, the discrete method retains language understanding better than the continuous diffusion baseline (language retention gap < 5% vs >10% for continuous), because the discrete method uses the same training loss as the original vision-language model and does not dilute that objective with competing diffusion signals.
