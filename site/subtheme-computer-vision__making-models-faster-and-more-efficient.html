Making models faster and more efficient

Compressing and optimizing vision models so they run on limited hardware without losing accuracy.

All themesField mapMathematicsAll explainers
What this is

Modern vision models are accurate but expensive to run. A large model might require a high-end GPU and draw huge amounts of power. But computer vision needs to work on phones, in hospitals, in cameras, and in cars — devices that cannot afford to send data to a data center or wait for a slow model to finish. How do you run an accurate vision model on a phone with a battery that lasts all day? How do you process a live video stream in real time on edge hardware, where there is no cloud connection? This efficiency problem is as important to deployed computer vision as accuracy is because useless tools, no matter how accurate, get abandoned.

The challenge is a trade-off: smaller models run faster because they have fewer calculations, but smaller models are less accurate. Larger models are more accurate because they have more capacity to learn subtle patterns, but too slow to use on real devices. You cannot just shrink a model and hope; accuracy drops sharply. You need techniques that preserve accuracy while cutting size and speed. One approach is compression: remove parts of the model that do not matter much, or represent numbers with lower precision (e.g., use 8-bit integers instead of 32-bit floats). Another is architecture search: automatically design smaller models that are efficient by nature. A third is distillation: train a small student model to imitate a large teacher model, so the student learns to make the same decisions with fewer calculations. A fourth is efficient layer designs — convolutions that use fewer operations, comparison-based layers designed for speed, or neural operations that GPUs can parallelize well.

Papers in this subtheme focus on methods to cut computation or memory without sacrificing too much accuracy. Some use pruning: identify which weights or neurons matter least and delete them, reducing computation. Others use quantization: represent weights using fewer bits, shrinking memory and speeding up math. Some design new neural network blocks that do the same job with fewer multiplications. Others combine multiple techniques: start with a faster architecture (fewer calculations by design), distill knowledge from a large accurate model into it (so it learns better decisions), and then compress it further with quantization. A few study the fundamental trade-offs: how much accuracy must be lost when you cut size in half? What is the best speed-versus-accuracy pairing achievable? The goal is to democratize vision: make capable models run efficiently on any device.

How the work breaks down

Making models faster splits into five directions: compressing video processing pipelines so they run efficiently, designing neural network blocks that use fewer operations by nature, moving computation to edge devices like phones and cameras, teaching small models to imitate larger accurate ones, and using specialized math operations that GPUs can run quickly.

Video compression and enhancement

Video processing is expensive: each frame requires computation, and doing this for many frames per second quickly drains battery and GPU memory. The challenge is to do something useful to a video—sharpen it, remove rain, increase resolution—without slowing down or using too much power.

Continuous Space-Time Video Super-Resolution with 3D Fourier Fields (“Continuous Space-Time Video Super-Resolution with 3D”) achieves high-quality video upsampling by working in frequency space instead of pixel space, which means fewer operations and sharper results. DeLiVR: Differential Spatiotemporal Lie Bias for Efficient Video Deraining (“DeLiVR: Differential Spatiotemporal Lie Bias for”) removes rain from video while staying efficient by using a specialized mathematical structure (Lie bias) that lets it handle time and space together without exploding the compute cost. Improved Adversarial Diffusion Compression for Real-World Video Super-Resolution (“Improved Adversarial Diffusion Compression for Real-World”) shrinks a teacher model down to 5% of its original size and makes it 8 times faster by using adversarial training—a technique that forces the smaller model to make the same visual choices as the large one, even with far fewer parameters. FideDiff: Efficient Diffusion Model for High-Fidelity Image Motion Deblurring (“FideDiff: Efficient Diffusion Model for High-Fidelity”) removes blur from video frames in a single step instead of many, making deblurring practical on edge devices. Hierarchical Image Tokenization for Multi-Scale Image Super Resolution (“Hierarchical Image Tokenization for Multi-Scale Image”) handles multiple zoom levels in one pass with just 300 million parameters, which is small enough to run on phones. LinearSR: Unlocking Linear Attention for Stable and Efficient Image Super-Resolution (“LinearSR: Unlocking Linear Attention for Stable”) trades the expensive attention mechanism (which slows down as image size grows) for a linear one, finishing its core work in just one pass through the network.

These papers all face the same core problem: the obvious way to do video enhancement is slow. They each solve it differently because they target different bottlenecks: some use math that's inherently cheaper (fewer multiplications per operation), others compress a large model (removing weights that matter less), and a few completely redesign how computation flows (changing the order of operations so the GPU can parallelize better). What ties them together is the insight that you do not need all the computation to get good quality; you just need to spend it wisely.

Efficient neural network building blocks

Standard vision models use convolution (sliding filters over images) and attention (comparing every pixel to every other pixel), but both can be slow when you scale to bigger images or need to process lots of features—convolution needs to slide the filter many times, and attention requires comparing every pixel to all others. The papers in this group find neural operations that are faster by design because they constrain the computation to shapes that GPUs handle well (like nearby local regions instead of global comparisons, or block-matrices instead of dense multiplies).

SEMA: a Scalable and Efficient Mamba like Attention via Token Localization and Averaging (“SEMA: a Scalable and Efficient Mamba”) replaces the standard attention mechanism—which looks at every pixel and every other pixel, making computation quadratic—with one that only looks at nearby tokens and averages them, which means the computation grows linearly instead of quadratically as image size increases. This keeps accuracy high on large images while being as fast as smaller models. Enabling True Global Perception in State Space Models for Visual Tasks (“Enabling True Global Perception in State”) adds a module called GMamba that plugs into any CNN to give it global understanding without the slowdown of full attention, because state space models process information sequentially in a way GPUs can parallelize well. Expressive yet Efficient Feature Expansion with Adaptive Cross-Hadamard Products (“Expressive yet Efficient Feature Expansion with”) uses Hadamard operations—simple element-wise products that multiply one number by one number, in contrast to matrix multiplication which multiplies rows by columns—which are much cheaper than standard matrix multiplies, so the network expands features fast enough for real-time use. Rethinking Attention in Spiking Transformers: Overcoming Density Bias with Set Similarity (“Rethinking Attention in Spiking Transformers: Overcoming”) redesigns attention for spiking neural networks, which are neuromorphic and run on specialized low-power hardware; the insight is that dense matrices hurt performance, so using set similarity (a sparse operation) is faster because fewer comparisons happen. Toward Complex-Valued Neural Networks for Waveform Generation (“Toward Complex-Valued Neural Networks for Waveform”) represents numbers as complex values (with real and imaginary parts) instead of just real numbers, which lets the network use block-matrix math that GPUs are built to optimize, cutting training time by 25%.

All five papers exploit the same principle: standard operations are general but wasteful. By constraining the computation to a specific form—locality, sparsity, specialized data types—you make it possible for hardware to run it faster without losing the model's ability to learn.

Mobile and real-time rendering

Mobile phones and edge cameras have fixed memory and battery budgets. Real-time means the model must finish in milliseconds, not seconds. The challenge is running complex vision tasks on hardware with orders of magnitude less computing power than a data-center GPU.

Mobile-GS: Real-time Gaussian Splatting for Mobile Devices (“Mobile-GS: Real-time Gaussian Splatting for Mobile”) renders 3D scenes on phones by eliminating the sorting step (which is slow) and using neural enhancement and compression to make the output look good despite using less memory. FARTrack: Fast Autoregressive Visual Tracking with High Performance (“FARTrack: Fast Autoregressive Visual Tracking with”) tracks objects in video at 343 frames per second on GPU and 121 on CPU, beating the speed and accuracy of slower tracking methods by redesigning the tracking pipeline to run sequentially instead of in parallel, which the hardware prefers. FastSESR: Fast Scene-level Explicit Surface Reconstruction (“FastSESR: Fast Scene-level Explicit Surface Reconstruction”) accelerates 3D surface reconstruction by at least 20 times by removing redundant computation and using more efficient data structures.

These three papers solve different vision tasks, but they share a common insight: real-time on mobile means rethinking the algorithm, not just optimizing code. By removing sorting (“Mobile-GS: Real-time Gaussian Splatting for Mobile”), changing from parallel to sequential (“FARTrack: Fast Autoregressive Visual Tracking with”), or eliminating redundancy (“FastSESR: Fast Scene-level Explicit Surface Reconstruction”), they unlock speedups of 8 to 20 times without sacrificing quality.

Learning from larger models via distillation

A small model by itself is not very accurate. But a small model can learn from a large, accurate teacher model through distillation: the student watches the teacher's decisions and learns to make the same ones with fewer calculations. The challenge is: what exactly should the student copy?

Vision Foundation Models Pooling pools multiple large foundation models into a mixture of experts—each expert learns a different part of the problem—so a small model can match the large models' accuracy by mixing their strengths. CompoDistill: Attention Distillation for Compositional Reasoning in Multimodal LLMs distills just the attention patterns (the focus maps of what the teacher looks at) into a smaller model, so the student learns not just the right answer but why the teacher thought it was right. DocVAL: Validated Chain-of-Thought Distillation for Grounded Document VQA teaches a small model to answer visual questions about documents without needing to read text at inference—it distills the teacher's reasoning (chain-of-thought) into the student, so the student learns a smarter strategy. Shortcut-Resistant CAM Distillation for Long-Tailed Recognition prevents a small model from learning cheating shortcuts on hard problems by distilling the teacher's class activation maps (which show what features matter on unusual examples).

All four papers use the same core idea: distillation works best when you teach the student not just the final answer, but the intermediate reasoning—attention patterns, chains of thought, and feature maps. This guides the student toward making the same decisions for the right reasons.

Efficient inference and deployment

Once a model is trained, inference—running it on new data—must be fast and frugal with memory. The question is: can you run a capable model on limited devices without retraining, just by changing how you deploy it?

Pose and Perception Decomposition splits the problem of tracking 3D scenes and moving objects into two separate sub-models—one for camera position and one for 3D shape—which is faster and more accurate than one big model because each sub-model can focus on its job. Spatial Graph Exploration for Place Recognition recognizes where a photo was taken by using frozen features from a large model (so no fine-tuning needed) and parameter-efficient adapters, getting near-perfect results with just 4,096 numbers per image. SHERPA: Fine-tuning Segment Anything Models with Task-relevant Guidance adapts a large general-purpose segmentation model to new tasks without forgetting what it learned, using task-specific guidance so the adaptation is cheap and fast. Think in Cloud, Look at Edges: Semantic-Driven Query Decomposition for Efficient Video Reasoning splits video reasoning between a high-capacity cloud server and weak edge cameras: the edge sends smart summaries instead of raw video, cutting transmission costs while keeping accuracy. Unified Multimodal Visual Tracking with Dual Mixture-of-Experts tracks objects using multiple sensor types (visible light and infrared, for example) with a mixture of experts that selects which experts are needed, so the computation scales with the complexity of the task, not a worst-case budget.

These papers all use modular or adaptive approaches: they either split the problem into smaller pieces (papers 5, 31, 32), reuse frozen large models efficiently (papers 28, 29), or select only the computation needed for the current task. This flexibility is key to deployment, because different devices and tasks have different budgets.
