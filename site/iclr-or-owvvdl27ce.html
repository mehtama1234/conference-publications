Uncertainty as Feature Gaps

An LLM's uncertainty about a contextual answer lives in the gap between what it actually learned and what a perfectly-trained model would know.

Paper explainersAll themesInterpretability

When an LLM answers a question using provided context, it can be confidently wrong. This paper measures that confidence-versus-correctness mismatch by looking at the model's internal hidden states (the intermediate values it computes layer by layer). It asks: how different is the pattern the model learned from the pattern a perfectly-tuned model would have learned? That gap reveals when the model is weak or guessing.

Zero assumption version

When does an LLM's confidence lie?

LLMs are now used to answer questions based on provided context—think: you paste a document, ask a question about it, and the model reads through and answers. This is called contextual question-answering. The danger: a model can sound very sure of an answer that is completely wrong. Traditional uncertainty research measures how sure a model is about closed-book questions (pure memorized facts), but contextual QA is different—the model can look at the provided information and still misread it or ignore it.

A naive approach: just measure how much the model's output probabilities vary if you sample multiple times. The problem: some wrong answers have high, confident probability. The model looks certain when it is actually weak.

The paper's move: Measure uncertainty by comparing the model's learned hidden state (how it processes information internally) to what an idealized, perfectly-trained model would compute.

The algorithm as a flow

What it actually does

Step 1: Imagine a perfect model

Construct a hypothetical idealized model with perfect instruction-tuning and unlimited training data.

Step 2: Extract three features

Use the actual model's hidden states to measure context-reliance, context comprehension, and honesty.

Step 3: Compute the distance

Measure how far the actual model's hidden state is from where the ideal model's would be.

Step 4: Bound the uncertainty

Prove that this distance upper-bounds the true epistemic uncertainty.

Step 5: Score the answer

Combine the three feature measurements into one uncertainty score per answer.

What the paper changes

What the paper changes

The paper shifts from measuring uncertainty via sampling (asking the model the same question many times) to measuring it via direct inspection of the hidden state—the intermediate values the model computes inside each layer.

The hidden quantity

Feature gap: the hidden quantity

measured quantity  =  gap in learned representations

The paper measures a gap: the difference between the hidden state (the vector of numbers computed inside the model) of the actual model and the hidden state of an idealized model that learned perfectly. Think of it as the model's fingerprint—each model computes a different fingerprint because it learned from imperfect data. A bigger gap means the model learned something wrong.

The paper estimates this gap by checking three specific learned patterns: (1) does the model rely on the provided context or just its memorized knowledge? (2) can it pull out the relevant parts of the context? (3) does it avoid making up false information? Each of these reveals one dimension of the gap.

Why it works

Why measuring hidden-state distance predicts correctness

If a model learned correctly, its internal hidden state (the pattern of numbers it computes) should match what a perfectly-trained model would compute. If it learned weakly or from incorrect examples, the pattern diverges. This divergence is not random noise—it accumulates where the model is confused or mistrustful.

The mechanism works in three steps. First, the paper proves mathematically that the distance between the actual model's hidden state and the ideal model's state forms an upper bound on true epistemic uncertainty. Second, it extracts three features from the hidden state that directly measure the three sources of error: whether the model actually uses the context, whether it reads it correctly, and whether it avoids lying. Third, it weights and combines these features into a single uncertainty score. A higher score means the model learned a pattern farther from the ideal—and empirically, farther models are more likely to be wrong.

This works because learned models generalize well when their internal representations are close to the ground-truth pattern. A model that misread the context has internal states that pull toward the wrong meaning, creating a visible gap. The paper catches this gap before the model commits to a confident wrong answer.

Math after the picture

The key equation

First in words:

epistemic uncertainty is bounded by the norm of the weight matrix times the distance between hidden states

Then the compact form:

KL(P_ideal || P_actual) <= 2 * ||W|| * ||h_ideal - h_actual||

Every symbol:

P_idealdistribution of the ideal perfectly-trained model
P_actualdistribution of the actual learned model
KL(...)how different two probability distributions are (measured in bits)
||W||strength of the final output layer (larger W magnifies hidden-state differences)
h_idealthe hidden state (list of numbers) the ideal model would compute
h_actualthe hidden state the actual model computes
||h_ideal - h_actual||the distance between the two lists (how far apart they are)
A tiny worked example
Suppose the output layer (the last set of multiplied numbers) has strength ||W|| = 10, and the distance between hidden-state lists is ||h_ideal - h_actual|| = 0.3.
Then uncertainty is bounded by: 2 * 10 * 0.3 = 6 bits.
If another answer has the same W but distance 0.1, its uncertainty bound is 2 * 10 * 0.1 = 2 bits—three times lower.
The paper's three features let you estimate this distance from the data without knowing the ideal model explicitly.

Larger gaps between actual and ideal hidden states—whether from ignoring context, misreading it, or fabricating—increase the uncertainty bound, correctly flagging risky answers.

What can go wrong

What can go wrong

The ideal model is a hypothesis. You cannot actually build the perfect model. The paper approximates it by prompting strongly. If the prompting strategy is weak, the ideal model is misjudged and the gap measurement is unreliable.
Test data that differs from training data. If the test context style is radically different from the training data—say, medical documents when the model trained on news—the learned three features may not capture the mismatch. The method generalizes better than sampling because it directly measures internal learned patterns, but if those patterns were learned from different data than the test set, they may not apply.
Requires labeled data for feature tuning. The method needs a small labeled set to identify which layer best measures each of the three features and to train the weighting. If labels are noisy or sparse, the feature extraction may fail.
Done right. When the ideal model is well-approximated by strong prompting, and the labeled tuning data is clean and representative of the kinds of contexts the model will see at test time, the method catches most confident wrong answers while remaining very fast.
What a runnable demo should prove

What a runnable demo should prove

Build a small system: take a contextual QA benchmark (e.g., a set of passages and questions with correct answers labeled), run the model on each, compute the three features from the hidden states, and predict uncertainty. Then measure how well those uncertainty scores rank answers by correctness: high uncertainty should predict wrong answers, low uncertainty should predict right answers.

AUROC = area under the curve of (false-positive rate vs. true-positive rate) when using uncertainty to separate correct from incorrect answers

The core insight: a model's confidence lies in its output probabilities, but its actual knowledge leaks into its internal hidden states. By measuring that leak, you catch doubt before the model speaks.
