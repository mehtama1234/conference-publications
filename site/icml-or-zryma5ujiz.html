AffIn-Space: Learning Affine-Invariant Representations for 3D Spatial Understanding with MLLMs

Remove viewpoint and scale effects from 3D scene features so a multimodal language model can answer spatial questions from the scene itself rather than from the camera pose.

Paper explainersAll themesMultimodal

A multimodal language model that reasons about 3D scenes often works only from the viewpoints it has seen before. Move the camera, zoom in, or change viewing angle, and the model's internal feature representation can drift even though the underlying room and object arrangement did not change. That is a serious problem for spatial tasks such as grounding, captioning, and question answering, because the answer should depend on which object is left of the chair or inside the cabinet, not on the camera that observed it. AffIn-Space tries to separate intrinsic scene structure from pose-dependent distortion in two explicit stages: first align features to a canonical form through affine resampling, then project hidden states away from pose directions inside the multimodal model.

Zero assumption version

Why spatial understanding is fragile under view changes

Many visual encoders process a scene through the pixel grid of the current camera image. That means the representation changes when the camera rotates, shifts, or changes distance, because the same object now occupies different image regions and scales. If the model then answers a 3D question from those unstable features, part of its answer depends on the camera transform rather than only on object arrangement.

Some systems hope that enough data will make the model ignore those changes. The paper argues that this is unreliable because the nuisance signal is built into the representation pathway itself. If pose information is entangled with scene structure all the way through the network, the model has to unlearn that entanglement from downstream supervision alone.

The paper's move in one sentence. Explicitly align scene features before fusion and explicitly remove pose directions inside the model so the remaining representation keeps the scene content while discarding camera-dependent variation.

The algorithm as a flow

What it actually does

Estimate affine factors.

Extract pose-related quantities such as rotation, translation, and scaling information from the scene observations.

Resample features explicitly.

Warp the 3D features into a canonical coordinate frame before multimodal fusion because early alignment removes pose variation before it spreads downstream.

Fuse with the language model.

Pass the aligned visual features into the multimodal language model for grounding, question answering, or captioning.

Project away pose components.

Use an orthogonal projection, which means subtracting the part of a hidden state that lies along pose-dependent directions, so the hidden state retains less camera information.

Reconstruct conditionally.

Keep a conditional reconstruction path so the system can preserve recoverable scene semantics rather than throwing away all variation indiscriminately.

What the paper changes

What the paper changes

The paper changes the internal representation used for spatial tasks. Instead of feeding view-entangled features directly into the multimodal model, it creates a representation that is aligned to a shared coordinate frame and then stripped of pose-dependent components.

the object it moves  =  the visual representation passed into the multimodal language model
The hidden quantity

The hidden quantity

measured quantity  =  scene content that survives affine viewpoint changes

The hidden quantity is the part of the representation that should stay the same when the camera changes by an affine transform. An affine transform here means a combination of shift, rotation, shear, or scale changes that preserve straight lines. For spatial tasks, object relations and room structure should remain; only the observation viewpoint should change.

AffIn-Space tries to isolate that stable part in two stages. Resampling reduces the mismatch at the input feature level. Projection reduces it again at the hidden-state level by removing the pose-aligned component of each vector, where a vector is simply a list of numbers representing the current state. The conditional reconstruction path checks that the remaining state still carries enough scene information to solve the task.

Why it works

Why explicit alignment plus projection works

The first stage matters because many later errors are already baked in before fusion. If the visual encoder outputs different feature patterns for the same scene under two camera poses, the language model receives inconsistent evidence. Explicit resampling attacks that inconsistency early by mapping both observations toward one reference frame. That makes corresponding objects land in more comparable feature locations.

The second stage matters because resampling is not perfect. Hidden states can still contain camera residue after fusion. Orthogonal projection removes the component of a hidden vector that points along pose-dependent directions. In plain terms, if part of the hidden state can be predicted from camera pose alone, the projection subtracts that part. What remains is more suitable for answering spatial questions because it contains less viewpoint leakage.

The reconstruction branch prevents over-removal. If the system projected away too much, task-relevant scene information would vanish together with pose information. Conditional reconstruction keeps pressure on the model to preserve the parts needed to recover real scene content. The full method works because alignment reduces pose variation before fusion, projection removes residual pose traces after fusion, and reconstruction guards the useful scene semantics.

Project a hidden state off the pose subspace

First in words:

A simple summary is that the model subtracts the part of a hidden state that lies in the pose subspace, which is the set of directions associated with camera variation.

Then the compact form:

h_clean = h - P_pose(h)

Every symbol:

hthe original hidden state inside the multimodal model
P_pose(h)the projection of that hidden state onto pose-dependent directions
h_cleanthe remaining hidden state after pose-dependent components are removed
A tiny worked example
Suppose one hidden direction rises whenever the camera moves closer, regardless of which object is present.
If that direction stays in the state, the answer head can treat zoom level as evidence about the scene.
Projection estimates that zoom-related component and subtracts it.
The cleaned state then changes less across camera distance while keeping the directions tied to object relations.

The real method includes the earlier resampling stage and a reconstruction term, but this projection equation captures the central removal step inside the multimodal model.

What can go wrong

What can go wrong

Pose estimation can be wrong. If the affine factors are estimated poorly, the resampling step can misalign the scene because it warps features toward the wrong canonical frame.
Projection can remove useful information. Some pose-related directions may also carry scene detail. If the projection basis is too broad, the model may lose object cues together with camera cues.
Affine invariance is not the whole problem. Real scenes also change through occlusion, lighting, and missing observations. Those effects are not fully handled by affine correction, so the method can still fail when the observation gap is not mainly caused by camera pose.
Done right. The method works when the canonical alignment is accurate, the projection basis is narrow enough to target pose residue, and reconstruction keeps the cleaned representation tied to real scene content.
What a runnable demo should prove

What a runnable demo should prove

Build a small synthetic 3D room with a few objects and render it from many camera poses and distances. Ask fixed spatial questions such as which object is left of the sofa or which item is inside the cabinet. Compare a baseline multimodal model that reads raw scene features with a version that first aligns features to a canonical frame and then projects hidden states away from pose directions.

The demo should show that answers remain consistent when the camera moves while the scene stays fixed, because the cleaned representation carries object relations more than viewpoint residue.

view_consistency = identical_answers_across_camera_changes / total_repeated_questions

A strong result is high view consistency together with good task accuracy, because that means the model kept scene structure instead of memorizing camera-specific feature patterns.
