Structure-Centric Graph Foundation Model via Geometric Bases

A graph foundation model treats graph shape as the primary transferable knowledge and aligns different graph types to a shared geometric coordinate system.

Paper explainersAll themesGraph & Geometric Learning

Graph foundation models aim to learn from many different graphs so one trained model works across datasets. But graphs vary wildly: some are social networks, some are molecules, some are knowledge bases — they have different numbers of nodes, different connection patterns, and different types of information at each node. This paper proposes a new model that puts graph topology (the pattern of connections) first, as the true source of knowledge. It models graphs as geometric spaces and aligns them to learned geometric bases (reference coordinate systems), so a single model can handle any graph shape.

Zero assumption version

Graphs look too different to share one model

A graph is a set of points connected by lines. A social network, a molecule, a map of cities, and a web page all look like graphs, but in completely different ways. A social network might have thousands of loosely connected people; a molecule has maybe 50 atoms tightly connected in a specific pattern.

A naive approach would be to train one big neural network on many graphs and hope it learns general rules. But the network learns rules about the number of nodes, the connection density, the typical neighborhood size. When you switch to a very different graph type, those rules fail. The network has no way to say: forget what you learned about scale and pattern density; just notice the SHAPE of the graph, which is universal.

The paper's one move. Treat each graph's connection pattern as a point in a shared geometric space and define learnable reference points. Align new graphs to those references so the model always sees comparable structure, independent of scale or feature types, because topology-based alignment extracts what is truly transferable about graph structure.

The algorithm as a flow

What it actually does

Define geometric bases

Learn a small set of reference graph shapes in an abstract geometric space.

Measure graph distance

For any new graph, compute Gromov-Wasserstein distance: how much you must warp the new graph's connections to match each base's connection pattern.

Align to the best base

Assign the graph to its nearest base, yielding a structure-aligned representation.

Adapt node features

Re-encode the nodes using the aligned structure, so features are compatible across graph types.

Train one model on aligned representations

The backbone network learns rules for structure-aligned graphs and transfers across domains.

What the paper changes

What the paper changes

The paper changes how each graph is represented: instead of feeding raw connection patterns and features directly to a neural network, it first finds which learned geometric base the graph most resembles, warps the graph's connections to align with that base, and re-encodes the node features in a compatible way. The alignment is the single representation the model sees.

the object it moves  =  graph alignment to geometric bases
The hidden quantity

Structural alignment: how far is this graph from the reference?

measured quantity  =  Gromov-Wasserstein distance (structural distance)

Gromov-Wasserstein distance is a single number that answers: how much must I rearrange the connections in one graph to match the connection pattern of another? It ignores node identity and feature values; it cares only about the topology (who is connected to whom and how tightly).

The paper uses this distance to align each input graph to the learned geometric bases. A small Gromov-Wasserstein distance to a base means the graph has a similar shape. The model then knows: this graph has structure like Base B, so treat it like Base B graphs.

Plain reading. Think of Gromov-Wasserstein distance as a tape measure for graph shapes. Two densely connected cliques have small distance; a sparse tree and a dense clique have large distance.
Paper reading. The paper cites Gromov-Wasserstein as a metric on the space of metric measure spaces — a rigorous way to compare two weighted graphs up to the rearrangement of nodes.
Why it works

Why structure-first alignment solves the transfer problem

The core insight: all graphs live in a universal space of possible connection patterns. Two graphs are similar if their connection patterns are similar, regardless of node feature types or scale. The model should learn to read structure, not memorize dataset-specific patterns.

By computing Gromov-Wasserstein distance to a set of learned bases, each input graph is mapped to its nearest base structure. This creates a bottleneck: the alignment forces the model to extract the invariant topology and discard scale and feature idiosyncrasies. The backbone network then learns a single rule: given a graph aligned to Base X, make this prediction. When a new graph aligns to Base X, the rule applies immediately.

The structure-aware feature re-encoding step handles the second barrier: graphs have incompatible node features (molecule atoms have different properties than social-network users). The paper re-encodes nodes based on their aligned position and local context in the base structure, making features comparable across domains. The result: one model, many graph types.

Math after the picture

The alignment formula

First in words:

Gromov-Wasserstein distance between graph G and base B is the minimum cost to match G's distance matrix to B's distance matrix via a permutation. The cost is a sum of squared differences in pairwise distances, weighted by an assignment matrix.

Then the compact form:

GW(G,B) = min_P sum_ij (D_G[i,j] - D_B[pi(i),pi(j)])^2 * P[i,pi(i)]

Every symbol:

GW(G,B)the structural distance between graph G and base B
D_G[i,j]distance (number of steps) from node i to node j in graph G
D_B[pi(i),pi(j)]distance in base B after the best alignment permutation pi
P[i,pi(i)]the fraction of node i mapped to base node pi(i) (soft or hard assignment)
sum_ijadd up all pairs of nodes
A tiny worked example
Graph G is a line: A—B—C (distances: A-B=1, B-C=1, A-C=2).
Base B is a star: center—X, center—Y, center—Z (distances: X-center=1, Y-center=1, Z-center=1, X-Y=2).
Best alignment: map A→X, B→center, C→Y.
Cost for A-B: (1-1)^2 = 0 (both pairs are 1 step apart).
Cost for B-C: (1-1)^2 = 0.
Cost for A-C: (2-2)^2 = 0 (both pairs are 2 steps apart).
Total: GW = 0. The line and star are structurally identical under this alignment.

Gromov-Wasserstein distance measures how different two connection patterns are, independent of who the nodes are or what features they carry.

What can go wrong

What can go wrong

Ambiguous alignment. If a graph has no clear nearest base (all bases are far away), the model gets a weak, uncertain alignment and prediction accuracy drops.
Feature incompatibility still leaks. If node features in two domains are so different that the re-encoding step cannot bridge them, the alignment alone is not enough.
Bases must be diverse. If the learned geometric bases do not cover the range of topologies in the test set, new graph types will not align well.
Done right. Geometric bases are learned from a representative mix of graph types, ensuring coverage. The structure-aware re-encoding is tuned to handle domain-specific feature distributions. The model gracefully handles ambiguous alignments via soft assignment (fraction of each node mapped to each base position).
What a runnable demo should prove

What a runnable demo should prove

Train the model on graph-level classification on graphs from Domain A (e.g., social networks). Freeze the model. Test on graphs from Domain B (e.g., knowledge bases). Without geometric bases, accuracy drops sharply. With geometric bases, accuracy stays high. A second demo: node-level tasks (e.g., predicting node labels). Same story: structure-aligned bases preserve transfer.

transfer_gain = (test_acc_with_bases - test_acc_without_bases) / test_acc_without_bases

The demo must show that geometric alignment, not raw feature learning, is why a single model works across graph types.
