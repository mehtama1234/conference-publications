DynaVieW: Schema-Guided World Modeling for Understanding Hierarchical Visual Dynamics

Model a video as alternating scene states and structured transitions, then train specialized experts to predict what changes and what the next state should look like.

Paper explainersAll themesMultimodal

A long visual sequence contains at least two kinds of information. One part is the state, meaning what the scene currently contains: objects, layout, and visible conditions. The other part is the transition, meaning what changed between two states: an action, a movement, an interaction, or an environmental effect. Many multimodal language models read a whole clip and produce text, but they do not explicitly separate those two roles. That makes it hard to reason about multi-step change, because the model has no stable place to store the scene before the action and no explicit structure for the change itself. DynaVieW introduces a schema-guided world model that interleaves states and transitions. It uses keyframes for broad scene states, describes transitions with a hierarchical schema, and trains a mixture-of-experts system, meaning a system with several specialized subnetworks whose outputs are selected and combined, to handle both transition prediction and next-state simulation. The result is a model that tries to understand not only what is visible now, but also what happened, at which level, and what should be visible next.

Zero assumption version

Why scene change needs structure

Video reasoning fails when a model treats dynamics as one undifferentiated stream. A clip may include a person reaching, an object rotating, a door opening, and the room state changing because of that sequence. Those events occur at different levels. Some are local actions, some are object-object interactions, and some are full-scene updates. A flat model can notice motion, but it often struggles to state which action caused which later state.

A useful world model should answer two linked questions. First, what changed between the current and next state. Second, what new scene state follows from that change. DynaVieW makes those questions explicit because it represents a sequence as alternating state and transition elements, so the model must learn both the static content of each step and the structured change that connects steps.

The paper's move in one sentence. Represent the sequence as state, transition, state, transition, then train specialized experts to predict transitions and simulate resulting states under a shared schema.

The algorithm as a flow

What it actually does

Turn the visual sequence into interleaved elements

Choose keyframes to represent broad scene states and place transition elements between them so the sequence alternates between what the world is and how it changes.

Encode transitions with a schema

Represent each change through a hierarchical schema, meaning an organized set of slots for different levels of dynamic content such as action details and resulting scene effects.

Train experts for different dynamic roles

Use a mixture-of-experts system in which specialized subnetworks focus on transition prediction or state simulation, because those two tasks demand different computations.

Select and combine experts with learned weighting

Use attention, meaning a learned weighting rule that decides which inputs or experts deserve more emphasis, to route information across experts based on the current schema tokens, which are the learned markers that identify the dynamic slots active in this example.

Reweight the loss by schema tokens

Give learning pressure to the schema parts that matter most for the current sequence, so rare but important dynamic constituents are not drowned out by more common easy patterns.

What the paper changes

What the paper changes

The paper changes the unit of reasoning. Instead of modeling the clip as one long visual-text stream, it models the clip as an alternating chain of states and transitions, with explicit structure inside the transition steps.

The hidden quantity

The hidden quantity

measured quantity  =  the causal structure of visual change across levels

The hidden quantity is the structured change that connects one visible scene state to the next. Raw frames show before and after, but they do not directly label which action happened, which object relation changed, and which later scene elements followed from that change.

DynaVieW tries to recover that structure by forcing the model to predict transitions and next states jointly. A transition guess is not enough if it does not lead to the right next state. A state simulation is not enough if it cannot be justified by the transition schema. Joint training links the two because the transition must explain the state change and the state change must reflect the transition.

Why it works

Why state-transition interleaving helps

State tokens and transition tokens answer different questions, so mixing them into one flat sequence weakens both. State tokens should preserve broad scene context such as object presence and layout. Transition tokens should represent what is changing, at what level, and with what result. When those roles are explicit, the model can reason over change in a controlled way rather than inferring change only indirectly from two unrelated frame representations.

The hierarchical schema matters because many visual events are nested. A human action may change an object relation, and that object relation may alter the whole scene state. If the model predicts only a single transition label, it misses those internal dependencies. Schema slots provide a place to represent several linked layers of dynamics, which means the model can encode both the immediate action and the broader consequence in coordinated fields rather than mixing them into one vague change token.

The expert design matters because transition prediction and state simulation are related but not identical. One expert can focus on reading the current states and inferring the most plausible change. Another can focus on applying that change to simulate the next scene. Cross-expert selection matters because not every sequence needs the same form of computation. The routing module can emphasize the experts whose specialization matches the current schema pattern instead of forcing one shared path to handle all dynamic cases.

A simple factorization view

First in words:

The model learns two coupled predictions at each step: the transition between two states and the next state that results from that transition. Training also weights the contribution of different schema slots so the loss focuses on the parts of change that matter for that example.

Then the compact form:

training_loss = transition_prediction_loss plus state_simulation_loss plus schema_weighted_loss

Every symbol:

transition_prediction_losspenalty for predicting the wrong structured change between two states
state_simulation_losspenalty for simulating the wrong next scene state
schema_weighted_lossextra weighting that emphasizes important schema slots for the current example
training_lossthe total learning objective
A tiny worked example
Suppose the current keyframe shows a closed drawer and the next keyframe shows an open drawer with a hand nearby.
The transition part should encode a hand action and a drawer-state change, not only generic motion.
If the model predicts the action but simulates the drawer as still closed, the state simulation loss stays high.
If it simulates the open drawer but explains the change with the wrong transition slot, the transition loss stays high.
Training is strongest when the predicted change and the simulated next state support each other.

The main idea is joint structure, not a complicated formula. Transition prediction and next-state simulation are trained together so one cannot drift far from the other.

What can go wrong

What can go wrong

Keyframes can miss short but decisive events. If a brief event occurs between selected states, the transition schema may have to infer it from weak evidence because the state snapshots do not show it directly.
The schema can be incomplete. If the hierarchical slots do not cover an important kind of change, the model may force that event into the wrong slot and blur the transition representation.
Expert routing can collapse. If the selection module repeatedly favors only a few experts, specialization weakens because the unused experts stop learning distinct dynamic roles.
Done right. The method is strongest when the sequence contains repeated patterns of state change that can be separated into distinct levels, because the schema then captures structure that a flat model would hide.
What a runnable demo should prove

What a runnable demo should prove

Build a small benchmark of short action clips where each clip can be summarized by a start state, a structured action, and an end state. Compare a flat video-language model against DynaVieW. Ask both systems to predict the next state and to produce a structured explanation of the change.

The demo should show state tokens, transition tokens, chosen experts, and the simulated next frame. A convincing result shows that DynaVieW stays more consistent because the transition representation gives the simulator a direct description of what changed.

joint_consistency = fraction_of_examples_with_correct_transition_and_correct_next_state

The key evidence is not only that the next frame looks plausible. The key evidence is that the predicted change and the simulated change agree with each other.
