Scaling Continual Learning to 300+ Tasks with Bi-Level Routing Mixture-of-Experts

When learning a long sequence of tasks, use two-level expert selection to pick the most relevant routers and experts at each network layer, so every layer can make smart decisions about which past knowledge to reuse.

Paper explainersAll themesRepresentation & Self-Supervised Learning

Imagine teaching someone to recognize hundreds of new object categories, one batch at a time. The brain needs to remember old categories while learning new ones, and it needs to do this smartly—not by storing every old answer, but by developing a flexible way to pick and combine knowledge at each thinking step. CaRE does exactly that: it gives every layer in a neural network (a computer vision model) a two-stage gating mechanism. First, that layer picks which task-specific routers (decision-makers) are relevant to the input. Then, those routers each activate which expert sub-networks to use. The result: the model learns to handle 100 to 300+ tasks in sequence without forgetting.

Zero assumption version

Learning many tasks in sequence is fragile

Continual learning means teaching a model to recognize new object categories over time, one batch at a time. Each new batch of categories (a new 'task') brings fresh examples the model has never seen. If you naively train the model on new task data, it learns the new category names quickly, but it forgets how to recognize the old categories—the knowledge for task 1 gets overwritten. A beginner might try storing all old examples and rehearsing them, but that becomes impossible with hundreds of tasks.

The core problem: the model needs to update its internal numbers (weights) to learn new categories, but those same updates erase the patterns that recognized old categories. The layers deep inside the network cannot distinguish which updates help the new task versus which hurt the old ones, because there is no labeling or compartmentalization—every weight belongs to one big shared pool, so nudging a weight for new-task examples also changes how that weight responds to old-task examples. There is no way for each layer to say: 'For this image, I should use knowledge from tasks 3 and 7, not tasks 1 and 2.'

The paper's solution in one sentence. At every layer, dynamically pick the relevant task routers, then let those routers each pick their best experts, so the layer can retrieve customized, mixed knowledge for each new input.

The algorithm as a flow

What it actually does

Step 1: Feed input to class perceptrons

At each layer, a class perceptron reads the image features and produces task guidance (confidence scores for which task this likely belongs to).

Step 2: Select Top-M task routers

Based on those scores, pick the most relevant task-specific routers, usually 2 or 3 of them. The latest task router is always included; older routers are picked by how well their routing patterns match the current input.

Step 3: Each router scores its experts

Each selected router applies a linear scoring function to the input, producing a score for every expert sub-network. A normalization step (turning raw scores into fractions that sum to 1) converts those scores into selection probabilities.

Step 4: Select and aggregate top experts

From each selected router, pick the top 3 or 4 experts with highest scores. Combine all these expert outputs with a learned weighted average, plus a shared expert that holds consolidated knowledge across all tasks.

Step 5: Layer outputs the mixed representation

The layer now outputs a representation built from task-aware routers and expert-chosen knowledge, ready for the next layer. Repeat at every layer.

What the paper changes

What the paper changes

The paper changes the structure at every layer of the neural network, from single rigid updates to dynamic two-stage expert selection. Instead of one path through shared weights, every layer now routes information through a set of task-specific routers and experts, with routing decisions made locally at that layer based on the current input.

The hidden quantity

The hidden quantity: task affinity at each layer

measured quantity  =  Per-layer task affinity (how relevant each historical task is to the current input, measured at each layer)

The paper measures an implicit quantity: how relevant each old task is to understanding the current input, at each layer of the network. This is not directly stored; instead, it is encoded in the router selection scores (entropy values). High entropy in a router's gating scores means 'this router is uncertain which expert to pick,' signaling that task might not be very relevant. Low entropy means 'this router has a clear favorite,' signaling that task's knowledge fits the current input well.

The paper infers task affinity by having each class perceptron produce a confidence score for which task the image belongs to. The router selection stage then uses these scores to pick the most relevant routers dynamically. During training, the latest task router is always used (to force learning the new task), and entropy values determine which historical routers join it. When the finished model answers a new question (inference), all router selections are driven purely by these learned affinities.

Why it works

Why it works: layered, local routing sidesteps forgetting

The core insight is simple: if every layer can independently decide which old knowledge to reuse, then new task training only adjusts the routers and experts that are actually active for that task. Layers that do not select a router for the new task do not update that router's weights. This builds a natural boundary: the weights of Router-Task-1 only move when processing images that actually belong to tasks where Router-Task-1 is relevant. New task data that is unrelated stays separate.

By having two levels of selection (first pick task routers, then pick experts within those routers), the paper achieves a hierarchical form of knowledge compartmentalization. The task perceptron at each layer is trained to distinguish which task the image belongs to, using a KL divergence loss that copies the confidence from the final layer down to every intermediate layer. This ensures that even shallow layers develop task awareness. With this local decision-making at every layer, shallow layers (which otherwise produce less discriminative features) now have explicit guidance on which tasks to prepare for, so they learn more useful, task-specific representations from the start. As a result, interference between tasks is minimized: updating Router-Task-5's expert weights does not clobber Router-Task-3's knowledge, because they are separate components.

Scaling to 300+ tasks works because new tasks only add new routers and experts; old routers remain frozen during training on new tasks. The model does not need to remember all past data, and it does not need to solve a complex optimization across 300 tasks at once. Each new task is learned locally, using only the current task data and the dynamic selection of compatible historical routers.

The routing equation

First in words:

For each layer, the output is a weighted sum of expert outputs, where the weights depend on which routers and experts were selected based on learned routing scores.

Then the compact form:

output_ℓ = sum over selected routers r of (weight_r * sum over selected experts e in r of (gating_r_e * expert_r_e(input_ℓ))) + weight_shared * shared_expert(input_ℓ)

Every symbol:

output_ℓthe layer's output representation
selected routers rthe Top-M routers chosen by task affinity
selected experts e in rthe Top-K experts chosen by router r's scores
gating_r_ethe normalized score (0 to 1) for expert e under router r
expert_r_e(input_ℓ)the output of expert e when processing the layer's input
shared_expert(input_ℓ)the shared expert that sees all tasks, providing base knowledge
weight_r, weight_sharedlearned coefficients combining router and shared outputs
A tiny worked example
Suppose Top-M=2 routers selected (Router-Task-3 and Router-Task-5), Top-K=2 experts per router, shared expert always active.
Router-Task-3 scores its experts: [0.8, 0.2, 0.0, ...] → select experts 1,2 with gating [0.8, 0.2].
Router-Task-5 scores its experts: [0.1, 0.7, 0.2, ...] → select experts 2,3 with gating [0.7, 0.2].
Layer output = 0.6 * (0.8 * expert3_1 + 0.2 * expert3_2) + 0.4 * (0.7 * expert5_2 + 0.2 * expert5_3) + 0.15 * shared_expert.
The large 0.8 gating on expert3_1 means that expert is heavily trusted; the 0.2 gating on expert3_2 means it adds refinement; expert5_1 was not selected (too low score) so it does not contribute at all.

Each layer independently selects which routers and experts to use, based on what the image looks like at that layer, so different images take different paths through the mixture-of-experts.

What can go wrong

What can go wrong

Task affinity is wrong at a layer. If the class perceptron at a shallow layer produces poor task confidence scores, it selects the wrong historical routers. Then that layer mixes knowledge from unrelated tasks, and representations become noisy. The paper mitigates this with KL divergence loss: every layer's perceptron is trained to match the final layer's task confidence, so even shallow layers learn good task discrimination.
Too many routers selected (M too large). If the Top-M selection threshold is high, many old task routers are activated for every input, defeating the purpose of isolation. Interference between tasks rises. The paper sets M small (e.g., 2 or 3) to keep only the most relevant routers active.
New task data is mixed with old task training. If the latest task router is not always forced active during training, the model might ignore new task data and reuse old routers. The paper hardcodes: during training, the current-task router is always selected, ensuring new knowledge is learned and added to the network.
Done right: isolated, adaptive routing. When task affinity is learned well at each layer, routers stay isolated, and new task training does not overwrite old knowledge. The model scales to 300+ tasks because each task's knowledge lives in its own router and expert sub-networks, independent of other tasks.
What a runnable demo should prove

What a runnable demo should prove

Build a small continual learning sandbox: a pre-trained image model (a model trained beforehand on many images, like a vision transformer—a deep network that reads an image as a series of small patches), a stream of 20 to 50 object categories arriving one by one, and a test set from each category. Implement CaRE's bi-level routing: at each layer, place a class perceptron, a set of task-specific routers (one per task), and a pool of experts. Train each new task using only current-task data (no replay from old tasks). At the end, test how well the model remembers old categories and learns new ones.

Forgetting = (accuracy on task 1 before learning task 20) - (accuracy on task 1 after learning task 20). Lower is better. Also measure: (accuracy on task 20) to check learning is not sacrificed.

The demo must show that with bi-level routing, forgetting stays low (e.g., task 1 drops from 95% to 85%, not 95% to 40%) even as you add more and more tasks, and new-task accuracy remains high. Without routing, forgetting is catastrophic.
