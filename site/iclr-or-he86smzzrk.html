VLBiMan: One-Shot Bimanual Manipulation via Vision-Language Anchors

A robot learns to do dual-arm tasks from a single human example by splitting the example into unchanging parts and changeable parts, then adapts only the changeable parts when the scene looks different.

Paper explainersAll themesRobotics & Control

Teaching a robot to do tasks with both arms at once normally takes hundreds of examples. VLBiMan learns from just one example and adapts it on the fly by watching what objects are where, using an AI system that understands pictures and language to figure out which parts of the motion must stay the same and which can change with each new scene.

Zero assumption version

One example is not enough, but retraining is too slow

Most robots learn dual-arm tasks like pouring or unscrewing by watching hundreds of human examples. Each new object shape or scene layout requires collecting more examples and retraining the robot's neural network from scratch, which takes hours or days.

A naive solution is to hand-code rules for each task: for pouring, keep the cup and bottle in a fixed distance apart. But that breaks when the objects move, rotate, or look slightly different. Another approach is to use modular pre-learned skills, but these are rigid and don't adapt when the scene changes unexpectedly.

The problem in one sentence. Robots need to learn dual-arm tasks from very few examples and adapt instantly when objects move or look different, without retraining.

The algorithm as a flow

What it actually does

Analyze the single example

Read the one human demonstration and split it into unchangeable parts (both arms moving together) and adjustable parts (individual arm positions).

Locate objects in the new scene

Run a vision-language AI (a model that understands pictures and reads text) to find where each object is now.

Compute the offset

Measure how much each object moved compared to the original example using a reference point on the object.

Retarget adjustable parts

Shift the arm positions by the same offset, keeping the synchronization pattern fixed.

Execute and adjust

Run the adapted motion and track if forces or obstacles push the arms; if they do, apply geometric constraints to keep the motion feasible.

What the paper changes

What the paper changes

Instead of learning new weights (parameters in a neural network) for each new scene, VLBiMan changes the spatial targets and relative offsets of the two arms while keeping the core synchronization strategy fixed. It decomposes the example into a low-level 'what the arms do together' (invariant, unchanged) and a high-level 'where each arm reaches' (changeable, adjusted via vision-language localization).

the object it moves  =  spatial targets and offsets
The hidden quantity

The correspondence between example and new scene

measured quantity  =  object correspondence

The hidden quantity is the mapping: which object in the new scene matches which object in the original example, and by how much did each move. Without knowing this correspondence, the robot cannot adjust. The paper infers it from two cues: the object's visual appearance (is it a cup or bottle based on shape and color) and where its reference point (the rim or edge) sits in space.

The paper estimates correspondence by running a vision-language model that tags objects by their semantic identity (cup, bottle, table) and measures the offset from a canonical reference point (the 2D image center of the object mask, or a contact point). This transforms a hard recognition problem (is this the same cup?) into a spatial alignment problem (the object moved by offset delta).

Why it works

Why decomposition and correspondence enable one-shot adaptation

The core insight: most of a dual-arm task is *how the two arms coordinate* (move together, stop together, maintain a spatial relationship). That part never changes. The other part is *where each arm is in absolute space* (its grasp point, reach position), which must shift when objects move. By splitting these two, the robot can reuse the coordinating logic and only adjust the spatial numbers.

Here is the causal chain: the human example contains both the coordination pattern and the spatial numbers. The paper extracts the coordination by analyzing which arm moves when and in what relative direction. Then it asks the vision system: where are the objects now? The vision system identifies each object by appearance and locates it spatially. The robot then asks: by how much did each object move? Measuring that offset lets it shift the spatial numbers in the original motion without touching the coordination logic. This works because objects move rigidly (a cup stays cup-shaped and stays a cup), so if the cup moved 20 pixels left and down, all arm positions targeting the cup can shift by the same 20 pixels.

The paper also uses semantic parsing (understanding what each object is by its appearance and context) and geometric feasibility checks (making sure the arms do not collide or twist into impossible configurations). These constraints prevent wrong offsets and ensure the adapted motion is physically executable. The vision-language model provides the semantic identification, and the optimization solves for feasible trajectories.

Math after the picture

The offset retargeting equation

First in words:

new grasp position equals original grasp position plus the object offset, adjusted by a local rotation if the object rotated

Then the compact form:

p_new = p_orig + delta_T(o_old, o_new) + R(theta) * p_local

Every symbol:

p_newthe grasp position in the new scene
p_origthe grasp position from the human example
delta_T(o_old, o_new)the translation (movement) of the object from example to new scene
R(theta)a rotation matrix if the object rotated by angle theta
p_localthe grasp position relative to the object's center
A tiny worked example
In the example, cup is at position [100, 150] in pixels. Cup grasp point is at [105, 140].
In the new scene, cup center is now at [130, 160]. Offset = [130 - 100, 160 - 150] = [30, 10].
New grasp position = [105, 140] + [30, 10] = [135, 150]. Robot moves to [135, 150] to grasp the cup.
This works because the cup moved as a rigid object, so its grasp point offset by the same amount.

When an object rotates, the grasp position also rotates around the object center; the equation adds a rotation term to handle this.

What can go wrong

What can go wrong

Ambiguous object identity. If the scene contains two visually similar objects (two identical cups) or occlusion (one object blocks another), the vision system may pick the wrong object or localize it incorrectly, causing mismatched offsets.
Large or unseen object deformations. If the object deforms (a flexible hose, a bag with contents that shift), the rigid offset assumption breaks because the reference point moves unpredictably.
Task-dependent coordination failures. If the two arms must coordinate in a way that depends on the object shape (e.g., grasping a thin rod vs. a thick bottle requires different synchronization), the invariant arm sync pattern may not work.
Done right: explicit semantic tags and contact points. When objects are labeled clearly by the vision-language model and the grasp point is task-specific (the rim for a cup, the handle for a bottle), correspondence becomes reliable.
What a runnable demo should prove

What a runnable demo should prove

Collect one bimanual manipulation video (e.g., a human pouring water from a bottle into a cup). Extract the arm trajectories and the object positions. Train the decomposition: mark which parts of the trajectory vary with object position (grasp height and reach offset) and which are invariant (the relative motion and timing of the two arms). Reposition the objects in a simulated environment and retarget the motion using the vision-language object localization and offset computation. Run the adapted trajectory on a simulated bimanual robot and measure success: does the robot correctly grasp and pour with the new object positions?

success_rate = (tasks_completed_without_collision) / (total_new_scenes_tried) × 100%

The demo must show that one example plus vision-language localization generalizes instantly to new object positions and shapes without retraining.
