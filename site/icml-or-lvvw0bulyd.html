LMNet: Dense Communication in Language Model Networks

Instead of LLMs talking to each other in natural language, strip their output layer and let trainable modules pass the internal number-lists between them, with the backward flow reaching end-to-end.

Paper explainersAll themesLLMs & Foundation Models

When multiple language models work together in a system, they normally chat via natural language: one generates text, the other reads it. This is simple but wasteful—it tosses away the internal number-lists and requires costly encoding and decoding. LMNet replaces that with direct handoff of those internal number-lists and trainable modules learn to adapt them between models, so the whole system learns together as one.

Zero assumption version

The bottleneck of talking in text

When language models are chained in a system—say, one generates a reasoning step and hands it to another for scoring—they communicate by having the first model write a sentence and the second model read it. This works, but it is a waste.

The first model's internal representation (a long list of numbers it uses for thinking) gets converted into discrete tokens (words), then frozen into a permanent text string. The second model has to re-encode those words back into numbers, starting from scratch. All the detail in the original numbers is lost. Worse, the system cannot learn end-to-end: you cannot adjust the numbers based on the final score by flowing information backward through that discrete text boundary, because word choice is not a smooth function—there is no continuous direction to move in to improve it.

A beginner might try fine-tuning both models on the final task. But without any mechanism to improve how they coordinate, each model stays trapped in its pre-trained patterns and the system remains brittle—because in text-based systems the backward flow stops at the text boundary, so the models cannot learn to send signals to each other. Fine-tuning each LLM separately cannot solve this; it requires the two to learn together.

In one sentence. LMNet strips the output layer from intermediate language models and pipes internal number-lists between trainable communication modules, so information never needs to be compressed to text and the backward flow can travel through the entire system.

The algorithm as a flow

What it actually does

Step 1: Strip the output layer

Take a pre-trained LLM and remove the final de-embedding operation (the step that converts numbers to word tokens).

Step 2: Pass dense vectors as intermediate messages

When one stripped model finishes, its internal representation (a list of numbers) goes directly to the next.

Step 3: Small trainable modules translate between models

Tiny seq2seq adapters (each about 5 million adjustable numbers, much smaller than the LLMs) sit on communication paths and learn to adapt one model's output to match the next model's expected input.

Step 4: Preserve natural language at the boundary

Keep one embedding layer at the front and one de-embedding layer at the back, so the system still reads text and outputs text.

Step 5: Train end-to-end with a single loss

The backward flow now travels from the final task loss all the way through every layer, through every edge module, and into the LLMs. Each part can now learn what changes to make so the whole system works better, because the number-based pipeline lets the flow through (text would block it).

What the paper changes

What changes: the communication channel

The single change is the transmission path between models. In standard multi-model systems, that path is discrete text (tokens, words). In LMNet, it is continuous dense vectors (the internal number-lists that the models actually think with).

The hidden quantity

The hidden quantity: information density per token

measured quantity  =  Information fidelity in handoff

In text-based communication, only the discrete tokens that were chosen are transmitted—roughly 10-100 numbers per word. In LMNet's dense vectors, every number in the model's internal state can flow through (often 2000-4000 numbers per position). The difference is that dense vectors preserve fine-grained detail that text discards.

The paper measures this indirectly: by showing that LMNet adapts to new tasks faster and with fewer training examples than systems that use text-based handoff. The reason is that the dense path carries richer information, so the edge modules need less retraining to learn how to use it.

Why it works

Why end-to-end training closes the gap

Text communication breaks the backward flow. When model A writes a word and model B reads it, that discrete choice is opaque to backpropagation—you cannot smoothly adjust A's numbers based on how B reacted, because word choice is not a smooth function. So each model stays frozen in its pre-trained patterns and cannot learn to coordinate.

LMNet fixes this by keeping everything in the continuous number space. Model A's output and model B's input are both lists of numbers. The small edge module in between is also continuous. The backward flow can now travel through the entire chain: from task loss back through B, through the edge module, through A, and into A's numbers. This lets both models collaboratively adjust themselves to work better together on the final task, because each part learns what changes to make so the system as a whole does better.

Concretely: if B's output on a task is weak, the backward flow will nudge A to produce a different kind of intermediate vector, and nudge the edge module to transform it better. The reason the edge modules can learn so much is: they are small (5M numbers each) compared to the LLMs, so they can shift quickly on limited task data. The LLMs themselves need less retraining because they are already pre-trained; the edge modules do most of the task-specific learning.

The optimization equation

First in words:

The loss is the standard language-modeling cross-entropy (how far the final output is from the correct answer) applied to the entire network end-to-end. Gradients are computed via backpropagation through every layer, including the edge modules. The edge module parameters (omega) and any unfrozen LLM parameters (theta) are jointly optimized.

Then the compact form:

Loss = sum_t cross_entropy(LLM_out(t), ground_truth(t)); d_Loss/d_omega involves all intermediate layers

Every symbol:

ground_truth(t)the correct output at position t
omegaparameters of the trainable edge modules
d_Loss/d_omegathe gradient—how to nudge omega to lower the loss
A tiny worked example
Suppose the task is: input 'New York' → output 'capital of New York State'. True output is 'Albany'.
First LLM generates a rough intermediate vector for 'New York'. Edge module transforms it (example: boosts 'geography' signal, dampens noise). Second LLM sees refined vector and outputs 'Albany'.
If the system output was 'New Jersey' (wrong), the loss is high. Backprop nudges the edge module to adjust its transformation, and nudges the first LLM to emphasize clearer signals. Over many examples, the system learns to coordinate.
The key: in a text-based system, the edge between models is frozen (words are what they are). Here, both the LLMs and the edge module all nudge together toward the goal.

The entire network—input embedding, first LLM, edge modules, later LLMs, output de-embedding—is one differentiable function, so a single loss can supervise all components.

What can go wrong

What can go wrong

Edge modules overfit if task data is tiny. If you have fewer than a few hundred labeled examples, the edge module (5M parameters) may memorize noise instead of learning a real transformation. Solution: freeze edge modules to fixed random projections, or use only a handful of examples for initialization and rely on the pre-trained LLMs.
Stripping the LLM's output layer breaks its natural-language input training. A pre-trained LLM learned to generate text given text input. When you remove the de-embedding layer, intermediate models no longer learn to generate text—they output raw vectors. This can destabilize early training. Solution: pre-train the network on autoregressive text prediction first (with edge modules only), then fine-tune on the downstream task.
Dense vectors can drift between models if dimensions are mismatched. If one LLM's internal dimension is 1024 and the next is 2048, the edge module must project up or down. If not done carefully, information is lost or amplified arbitrarily. Solution: the edge modules are designed for this; use them on all paths.
Done right: use a small edge module, pre-train on text first, and do not expect miracles with tiny datasets. LMNet is most effective when you have a handful of task examples and want to adapt without full fine-tuning. The combination of pre-training, dense vectors, and learned edges yields gains. Single-LLM baselines are still simpler if you have enough labeled data to fine-tune.
What a runnable demo should prove

What a runnable demo should prove

Build a two-node LMNet: a small summarizer LLM and a small classifier LLM. Feed each node a pre-trained model (e.g., DistilBERT or GPT-2 Small). Strip the output layers and connect them with a single trainable 1-layer transformer edge module (a few million adjustable numbers).

On a few hundred labeled examples of the task 'summarize a review, then classify the summary as positive or negative', first freeze the LLMs and train only the edge module. Measure how fast it reaches 80% accuracy. Then unfreeze all numbers and train everything end-to-end; measure how many fewer training steps it takes to reach the same accuracy, because now the backward flow can update both LLMs and the edge module in concert.

Speedup factor = (gradient steps for text-based baseline to reach 80%) / (gradient steps for LMNet to reach 80%)

If LMNet cuts the required training steps by 3–5x compared to natural-language coordination, you have verified that dense vectors and end-to-end backward flow are doing the work.
