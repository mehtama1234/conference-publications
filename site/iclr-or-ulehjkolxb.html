LogiConBench: Benchmarking Logical Consistencies of LLMs

A scalable benchmark that exposes LLM failures on logical reasoning by generating unlimited consistent and inconsistent statement-lists from symbolic logic graphs.

Paper explainersAll themesDatasets & Benchmarks & Evaluation

Large language models claim to reason, but they routinely produce statements that contradict each other, even on simple logic puzzles. Existing tests for this problem are small and too easy — models already score above 95%. LogiConBench fixes this by automatically generating millions of logic puzzles from graph blueprints, keeping them genuinely hard. The best frontier models score only 34% on the hardest task, proving we have much work to do.

Zero assumption version

Models sound confident but contradict themselves

A language model reads: If Alex is happy, then Beth is sad. Alex is happy. Therefore, Beth is sad. It should answer yes — that follows from the rules. But then it reads: Beth is sad. Therefore Alex is not happy. It answers yes again, even though this contradicts the first rule. The model broke its own logic.

Today's benchmarks for testing this are tiny (hundreds of examples) and models breeze through them (95%+ score), so we do not actually know where models fail. A beginner might try testing the model on every possible combination of logic statements by hand, but that is impossibly tedious — there are billions. We need a way to generate tests automatically, but also to guarantee the tests are both diverse and genuinely challenging.

In one sentence. Existing benchmarks for logical consistency are too small and too easy; frontier models hit 95% but real reasoning gaps remain hidden.

The algorithm as a flow

What it actually does

1. Build a logic graph

Create a directed graph where nodes are true-or-false propositions and edges are logical rules.

2. Sample reasoning paths

Walk the graph to extract inference chains (if A then B, and B then C, so A implies C).

3. Determine all consistent states

For each path, compute which assignments of true/false to all propositions satisfy every rule.

4. Translate to natural language

Convert symbolic statements into diverse English phrasings (same logic, different words).

5. Generate test instances

Present lists of English statements to the model and ask: are these consistent or contradictory?

What the paper changes

What the paper moves

Instead of hand-writing logic test cases, LogiConBench builds them algorithmically from symbolic graphs. A symbolic graph is a formal blueprint: nodes are propositions, edges are rules. Once you fix the graph, you can sample as many different reasoning paths as you want by walking the graph in different ways; each path yields new test cases. This scales automatically — add one rule to the graph and you unlock thousands of new test cases without human work. Difficulty scales too: deeper reasoning chains (longer paths through the graph) are harder than shallow ones, so controlling the path length lets the benchmark tune from easy to extremely hard.

The hidden quantity

The hidden quantity: reasoning depth

measured quantity  =  Reasoning chain length

The real test of logical reasoning is how far the model must think ahead. A one-step inference (If A then B; A is true; B is true) is trivial. But a five-step chain (A implies B implies C implies D implies E; given A is true, determine if D and E are also true) demands the model hold multiple rules in mind without forgetting or confusing them.

LogiConBench controls this by generating graphs of controllable depth and sampling reasoning paths of varying length. A model might handle all one-step cases correctly but collapse on five-step chains, revealing exactly where reasoning breaks down.

Why it works

Why a graph-based generator finds the limits

Hand-written benchmarks hit a ceiling because every extra case is slow and fragile. Humans write down a few logic puzzles and miss edge cases. A model that overfits to those puzzles looks smart but fails on real reasoning.

LogiConBench breaks this deadlock by treating logic as a formal structure: a directed graph where propositions are nodes and inference rules are edges. This is the key move. Once you have the graph, generating test cases is mechanical: walk the graph to extract reasoning chains of any length, compute which truth-assignments satisfy all the rules (the consistent sets), and phrase those sets in natural English. No hand-writing, no guessing at what is hard. The generator always produces both consistent and inconsistent statement-lists with mathematically guaranteed correctness. So a model cannot cheat by memorizing; it must actually reason.

The scalability comes from the same source: if a graph has 10 propositions and 15 rules, you can extract thousands of different reasoning paths by sampling different walk sequences. Each path yields new test cases. Scale up to 100 propositions and you get millions of cases, all guaranteed-correct by the graph structure.

Math after the picture

The consistency check equation

First in words:

A statement-list is consistent if there exists at least one truth-assignment (an assignment of true or false to each proposition) such that every statement in the list evaluates to true under that assignment. The benchmark judges a model correct if it either affirms consistency when a consistent assignment exists, or denies consistency when no assignment works.

Then the compact form:

Consistent := exists T in {0,1}^n : forall s in S, eval(s, T) = 1

Every symbol:

Tan assignment of true (1) or false (0) to each of n propositions
Sthe list of statements presented to the model
eval(s, T)evaluating statement s under assignment T yields 1 (true) or 0 (false)
existsat least one such assignment exists
A tiny worked example
Propositions: A, B (so n=2, assignments are 00, 01, 10, 11)
Rules: If A then B (logical implication A → B)
Test case: statements are [A is true, B is true]
Check each assignment:
T=00: A is false, B is false → eval(A is true) = 0 → FAILS
T=01: A is false, B is true → eval(A is true) = 0 → FAILS
T=10: A is true, B is false → eval(B is true) = 0 → FAILS
T=11: A is true, B is true → eval(both) = 1, AND A→B holds → SUCCESS
Conclusion: consistent (assignment T=11 works); model should answer yes.

The model must determine whether at least one valid truth-assignment satisfies all the statements, exactly as the formula requires.

What can go wrong

What can go wrong

Models confuse order of implications. If the reasoning chain is A implies B implies C implies D, a model might forget that A implies D (transitivity), or mix up the direction and think D implies A.
Long chains exceed the model's working memory. A five-step reasoning path requires the model to track five separate rules simultaneously. Most models only reliably hold three or four pieces of information at once.
Natural language phrasings disguise the logic. The same rule If A then B can be phrased as A is sufficient for B or B is necessary for A, and models may handle one phrasing but not the other, confusing language with reasoning.
The benchmark is fair if it tests the same rules across many phrasings. By generating multiple diverse English expressions of the same underlying logic, LogiConBench ensures the model truly understands the rules, not just memorizes phrasings.
What a runnable demo should prove

What a runnable demo should prove

Build a small logic graph (5-10 propositions, 8-12 rules forming a chain), generate 100 test cases by sampling reasoning paths of lengths 1 through 5, present them to a language model, and track accuracy by depth. The demo succeeds if it shows a sharp cliff: models do well at depth 1-2, but accuracy crashes at depth 4-5, proving the model's logical reasoning has a hard limit.

Accuracy by depth = (correct answers at depth D) / (total test cases at depth D)

Plot accuracy versus reasoning depth. A cliff at depth 3 or 4 reveals the exact boundary where the model's reasoning fails.
