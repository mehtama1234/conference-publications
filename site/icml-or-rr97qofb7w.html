Identifying and Correcting Label Noise for Robust GNNs

When some training labels are wrong, spotting which nodes lied and fixing them before training saves a graph neural network from learning garbage.

Paper explainersAll themesGraph & Geometric Learning

Graph neural networks learn from networks of connected data, like social graphs or molecule structures. But when some labels (the ground truth answers you train on) contain errors from sloppy annotation, the network learns those mistakes and makes worse predictions overall. This paper shows how to spot which labels are likely wrong and fix them, using only the graph's connection pattern.

Zero assumption version

Noisy labels break graph learning

A graph neural network reads three things: the network shape (who is connected to whom), the features (what each node looks like), and the labels (what each node's answer should be). If some labels are plain wrong — a node marked as "spam" when it is not, a protein mislabeled as inactive when it is active — the network learns from false examples.

A naive approach tries to ignore all high-error nodes during training, but which nodes are wrong? You cannot know without the true answers, which is why you are training in the first place. Most methods guess by looking at how confused the network is on each node, but on a graph, neighbors influence each other during learning, so a confused prediction might mean the node itself is mislabeled OR that its neighbors are mislabeled but pulling it down.

In one sentence. The paper spots noisy labels by measuring how much each node contradicts what its graph neighbors already know.

The algorithm as a flow

What it actually does

Measure neighbor influence

Run the graph structure through a mathematical operation (graph diffusion, a way of blurring information across edges) so each node learns what its neighborhood looks like.

Compute contradiction score

For each node, compare the neighborhood's consensus (via diffusion) to the node's actual label. High contradiction means the label is probably wrong.

Fit a noise model

Sort nodes by contradiction score and fit a Gaussian mixture model (two overlapping bell curves), one for clean, one for noisy. Decide the threshold that separates them.

Correct the labels

For each detected noisy node, ask its neighbors for their label predictions and blend them together as a new, corrected label.

Add unlabeled node predictions

Run the model on nodes with no labels and treat its predictions as extra weak training signals to stabilize learning.

What the paper changes

What the paper changes

The paper changes one thing: before training starts, it corrects the label vector (the list of ground-truth answers for each node) by identifying which labels are wrong and replacing them with better guesses based on the graph's neighborhood information.

the object it moves  =  labels
The hidden quantity

Influence Contradiction Score

measured quantity  =  influence contradiction score

The influence contradiction score (ICS) is a single number for each node that measures how much the node's label clashes with what its graph neighbors would predict. A node's neighborhood (reached via a diffusion operation, a way to blur information across edges) has learned certain patterns during training. If a node's label disagrees sharply with that neighborhood knowledge, its label is probably noisy.

The paper estimates the ICS by applying the graph diffusion matrix (a mathematical operation on the graph's connection pattern) to see the neighborhood's influence on each node, then comparing that influence to the actual label. Nodes with high ICS values are flagged as noisy and corrected.

Why it works

Why measuring contradiction finds noisy labels

The core insight is that during training, graph neural networks learn from neighbor relationships. If a node is connected to clean-labeled neighbors and trained together, its learned representation will move toward matching the neighborhood's labels. If that node's own label is actually wrong, there is an automatic clash: the network is pulled toward learning what the neighbors say (which is clean) but also toward predicting what the node's label says (which is noisy). This clash creates a measurable contradiction.

The paper captures this contradiction by diffusing information through the graph (a mathematical way of letting each node know what its neighbors have learned) and comparing the diffused neighborhood signal to the node's own label. Nodes where this comparison disagrees sharply are flagged. Then, instead of just discarding those nodes, the paper corrects their labels by asking the neighbors for a prediction and using that as the new label. This way, noisy nodes are healed and become useful training examples instead of poison.

Math after the picture

The contradiction score formula

First in words:

influence contradiction score equals the difference between what the node's neighbors learned to predict and what the node is actually labeled as, squared.

Then the compact form:

ICS_i = (S_i - y_i)^2

Every symbol:

ICS_iinfluence contradiction score for node i
S_ithe neighborhood's learned signal for node i (from graph diffusion)
y_ithe node's actual label
A tiny worked example
Node A: neighborhood predicts +0.9, label says +1.0. ICS = (0.9 - 1.0)^2 = 0.01. Nearly agrees, low noise.
Node B: neighborhood predicts +0.8, label says -0.8. ICS = (0.8 - (-0.8))^2 = 1.6^2 = 2.56. Big mismatch, high noise.
Node C: neighborhood predicts +0.3, label says +0.5. ICS = (0.3 - 0.5)^2 = 0.04. Small mismatch, low noise.
Sorting by ICS, Node B stands out as likely mislabeled.

Nodes where neighbors and labels strongly disagree get high scores and are flagged for correction.

What can go wrong

What can go wrong

Neighbors are also wrong. If multiple neighbors of a node all have noisy labels pointing the same wrong direction, the neighborhood signal is corrupted too, and the contradiction score will not catch it.
Over-correcting clean labels. If the algorithm is too aggressive about which nodes to correct, it may flip some actually-clean labels by mistake, trading one noise source for another.
Gaussian mixture model does not fit well. If the noise is not cleanly separated into two groups (clean vs noisy), the bell curves may not separate the threshold correctly, and many nodes get misclassified.
Done right. The paper mitigates these by using graph structure (noisy label clusters are often local, so nearby diffusion helps) and pseudo-labeling to stabilize corrections on unlabeled nodes.
What a runnable demo should prove

What a runnable demo should prove

Build a small graph (e.g., 100 nodes, 200 edges) with a true label for each node. Manually flip 20 of the labels to create ground-truth noise. Run ICGNN on it to compute ICS scores and correct the labels. Then train a graph neural network on the corrected labels and measure accuracy.

noise detection accuracy = (true positives + true negatives) / total nodes

The demo must show that nodes flagged as noisy have high ICS scores and that correcting them recovers accuracy lost to the label noise.
