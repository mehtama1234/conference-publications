Cartridges: Lightweight long-context via self-study

Instead of cramming an entire document collection into the context window every time, train a small reusable KV cache (Cartridge) offline on synthetic conversations, then use it at inference time.

Paper explainersAll themesLLMs & Foundation Models

Large language models can read from enormous document collections in their context window, but this is extremely expensive: the memory needed for the cache grows with every word in the collection. This paper trains a small, reusable cache offline for each collection. At inference time, you just load this cache and answer questions—no need to re-read the entire collection for each query.

Zero assumption version

Why full-context lookup is expensive

When you ask a large language model a question about a document collection, the model reads the entire collection as context. This works, but the memory cost scales with the collection size. The model stores key-value pairs (caches) for every word in the collection, and this cache grows linearly with how many words you add.

A beginner would think: just compress the collection into fewer words before the query. But simple compression loses structural information. The model needs to understand how distant parts of the collection relate, and that understanding requires preserving how the pieces fit together.

In one sentence. Train a small frozen cache per collection offline, load it at inference, and decode answers without re-reading.

The algorithm as a flow

What it actually does

Take a document collection

A codebase, legal documents, or chat history.

Generate synthetic conversations

Use a language model to write realistic question-answer pairs about the collection.

Fit the cache to reproduce the original model's answers on these synthetic conversations.

The model uses the cache to ground its answers, without re-reading the collection.

What the paper changes

What the paper changes

The paper changes the KV cache: instead of computing it fresh from the corpus at runtime, it trains the cache offline as a set of weights (the values the model learns) that get loaded and reused.

the object it moves  =  The KV cache
The hidden quantity

The hidden quantity: structural coherence

measured quantity  =  How much the cache preserves document structure

The hidden quantity is whether the trained cache retains the relational structure of the original collection—meaning it understands how parts of the collection connect, depend on each other, and resolve ambiguity. A naive compression loses this. The paper measures structural coherence implicitly: by checking whether the cache reproduces the original model's word-by-word decisions on synthetic conversations.

The paper estimates this by comparing the cache-augmented model's next-word distributions (the probability it assigns to each possible next word) with the original model's distributions on the same queries. If they match closely, the cache preserved the structure.

Why it works

Why synthetic conversations preserve structure

Training a cache directly on next-word prediction over the raw corpus fails because the training signal is too narrow. The cache learns to predict the corpus itself, but that teaches it nothing about how to answer new questions grounded in the corpus. It memorizes, not generalizes.

Synthetic conversations are the fix. A language model generates realistic questions about the corpus, then answers them. When you train the cache on these question-answer pairs, the cache learns to encode the structure of the corpus in a way that supports answering questions. The cache is forced to preserve relational information because if it loses that information—for instance, forgetting that 'module A depends on module B'—then when the model tries to answer 'what depends on module B?', the cache won't supply the right clues, and the answer will be wrong. Training on diverse synthetic questions forces the cache to encode relationships, not just facts.

Context distillation is the training recipe. Instead of just predicting the next word, you train the cache to produce the same probability distribution over the next word as the original model would with the full corpus in context. This aligns the cache-augmented model's behavior with the full-context model's behavior. Because the original model has seen the entire corpus, it has all the structural information. By matching its word-by-word decisions, the cache inherits that understanding.

The payoff: the cache is trained once, amortized across all queries. At inference time, you load it, append the user's question, and decode. The cache is small (a few thousand words), so memory is constant regardless of the corpus size.

Math after the picture

The training objective

First in words:

Minimize the divergence between the cache-augmented model's next-token predictions and the full-context model's predictions across all synthetic conversations.

Then the compact form:

L = sum_over_conversations KL(P_full || P_cache) where KL is the Kullback-Leibler divergence measuring how different two probability distributions are

Every symbol:

P_fullthe probability distribution over the next word when the model has the full corpus in context
P_cachethe probability distribution over the next word when the model uses the trained cache instead
KL(P_full || P_cache)a measure of distance between the two distributions: zero when they match perfectly
A tiny worked example
Suppose on a synthetic question, the full-context model assigns probabilities: 'return' 0.40, 'throw' 0.30, 'continue' 0.20, 'break' 0.10.
The cache-augmented model assigns: 'return' 0.38, 'throw' 0.32, 'continue' 0.22, 'break' 0.08.
KL divergence is roughly 0.0015 (small, good). The training process computes this error and nudges the cache weights to reduce it.
Over thousands of synthetic examples, the cache learns to produce distributions that match the full-context model's behavior.

The cache is trained to reproduce the full model's word-by-word decisions, so it captures the structure the full model learned from the corpus.

What can go wrong

What can go wrong

Synthetic conversations may not cover all patterns. If the generated questions miss a domain-specific pattern in the corpus, the cache won't learn to handle it. Example: if no synthetic question asks about edge cases, the cache fails on edge-case queries.
Cache overfits to the model it was trained on. A Cartridge trained on one language model may not transfer to another model. The paper shows limited transfer across model architectures.
Structural information loss from compression. Reducing the cache to a few thousand words forces the model to compress structured relational information into a small space. Some nuance is inevitably lost.
Done right: use context distillation. Training with KL-divergence between distributions ensures the cache learns structural relationships, not surface patterns. Freezing the attention sink (the first word's cache values) also prevents training instability.
What a runnable demo should prove

What a runnable demo should prove

Build a small corpus (e.g. 10 legal documents, 50K words total). Generate 20 synthetic question-answer pairs about it using a language model. Train a Cartridge on these pairs using context distillation. At inference time, ask 5 unseen questions (not in the synthetic set) and measure accuracy. Compare the Cartridge's answers to the full-context model's answers. Also measure memory used and inference latency.

Accuracy match ratio = Cartridge_accuracy / Full_context_accuracy; Speedup = Full_context_latency / Cartridge_latency; Memory savings = Full_context_memory / Cartridge_memory

The demo must show that the Cartridge answers unseen questions nearly as well as the full model while using an order of magnitude less memory.
