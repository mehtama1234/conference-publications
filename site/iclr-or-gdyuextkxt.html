Collaborative Gym: Human-Agent Teamwork

Agents perform better when humans can jump in anytime to suggest, correct, or take over a shared task.

Paper explainersAll themesAgents & Tool Use

Most AI agents act alone until a human gives them a new instruction. But real tasks—planning a trip, writing papers, analyzing data—work better when humans and agents can both act at the same time, because the human can spot and fix a mistake immediately instead of waiting for the agent to finish a flawed draft. Collaborative Gym is a framework that lets agents and humans share control of one task, with humans able to pause or override the agent at any point, and both can act without waiting for the other to finish.

Zero assumption version

Why autonomous agents get stuck on human tasks

An AI agent acting alone must guess what the human actually wants. When planning a trip, the agent might book flights to Paris without knowing the human hates crowds. When writing a related-work section, the agent might include papers that miss the point. The agent keeps going, often wasting steps.

A naive fix: take turns. The agent suggests a draft, the human reviews, then the agent revises. But this wastes time. While the human is still reading, the agent sits idle. While the agent is revising, the human cannot make small fixes. They are out of sync.

The idea in one sentence: Let humans and agents both act in the same shared workspace at the same time, with humans able to interrupt or override whenever they spot a mistake.

The algorithm as a flow

What it actually does

Shared workspace

Agent and human both see the same task state (travel itinerary, draft text, data table).

Asynchronous acts

Agent can suggest a change; human can reply, redirect, or take a different action without pausing the agent.

Collaboration acts

Agent can explicitly ask questions, send messages to the human, or pause itself to wait for feedback.

Notifications

When either party acts, the other sees it—no missed context, no confusion about who changed what.

Shared memory

Everything said and done stays in view; agent learns from the human's corrections and adapts.

What the paper changes

What the paper changes

Collaborative Gym removes the turn-taking rule. Instead of alternating between agent and human moves, both can act in parallel. The agent does not have to wait for explicit permission before each move, and the human does not have to wait for the agent to finish before intervening.

the object it moves  =  Interaction timing: parallel acts instead of turns
The hidden quantity

The hidden quantity: Who is actually steering?

measured quantity  =  Initiative balance (fairness in who steers)

Initiative is a linguistic term meaning an utterance that directs task progress or settles a shared understanding. In teamwork, if one person (or agent) always makes the decisions and the other just reacts, the collaboration is lopsided. The paper measures fairness by asking: how evenly is decision-making split between human and agent? The score ranges from 0 (one side dominates completely) to 1 (perfectly balanced).

The paper uses a language model to read each message and ask: does this direct the task forward, or just react? Then it tallies who took initiative most often. High balance score means the human and agent are truly working as partners; low balance score means one is a passenger.

Plain reading: Initiative balance is the math of fairness: if the agent always steers and the human only reacts, the score is low; if they suggest ideas equally often, it is high.
Paper reading: Following Chu-Carroll & Brown (1997), an utterance exhibits initiative if it directs task execution or establishes shared belief. The paper uses a language model to annotate utterances and compute a fairness score (using a measure from information theory) to quantify the imbalance.
Why it works

Why shared control works better

When one person controls a tool and another watches, the watcher must wait for the controller to finish before they can correct a mistake; by then, time and effort are wasted on the wrong path. With shared control, both can act on the task state at the same time, so the human spots a problem and corrects course immediately instead of waiting. For example, the human can suggest a cheaper flight option the instant the agent picks one, because the human is watching in real time and the shared workspace shows the agent's choice at once.

Second, the human no longer wastes effort giving step-by-step instructions. In turn-based mode, the human might say 'search for papers on neural networks, then skim each one, then summarize,' then wait for all three steps to complete. With shared control, the agent can ask 'which areas of neural networks interest you?' and start searching right away while waiting for the answer—saving the handoff delays between each step.

Third, shared memory keeps context tight and prevents misunderstanding. Every action and message lives in a shared log both can see. The agent does not forget what the human said three messages ago because it can scroll back and reread; the human does not get confused by an agent's detour because both are looking at the same current state and can ask clarifying questions anytime.

Math after the picture

The fairness equation

First in words:

Initiative Entropy equals the negative sum over all team members of (the fraction of times they took initiative) times the logarithm of that fraction.

Then the compact form:

H_init = - sum_i (p_i * log(p_i))

Every symbol:

H_initInitiative balance score, ranges from 0 to log(N) where N is number of team members
p_ifraction of all initiative-taking utterances that came from team member i
lognatural logarithm (any base; the paper uses natural log)
sum_iadd up the term for each team member
A tiny worked example
Suppose a 2-person team (human and agent) collaborates on a task with 100 utterances.
Agent took initiative 90 times, human took initiative 10 times.
p_agent = 90/100 = 0.9, p_human = 10/100 = 0.1
H_init = -(0.9 * ln(0.9) + 0.1 * ln(0.1)) = -(0.9 * -0.105 + 0.1 * -2.303) = -(-0.0945 - 0.2303) = 0.325
Compare: if both took initiative equally (50/50): H_init = -(0.5 * ln(0.5) + 0.5 * ln(0.5)) = -(0.5 * -0.693 + 0.5 * -0.693) = 0.693
Lower score (0.325) signals imbalance; higher score (0.693) signals true partnership.

High balance score means the human and agent are teammates, not boss-and-subordinate. The math captures the intuition: balanced teams succeed more because both minds are engaged.

What can go wrong

What can go wrong

Agent does not understand the human's preference. Even in shared control, the agent might misinterpret a human's message or ignore domain knowledge the human has. The framework gives the human power to override, but if the agent keeps missing the same pattern, the collaboration breaks down.
Too much back-and-forth wastes time. If the human interrupts every single agent suggestion, collaboration becomes slower than turn-taking. The human must resist the urge to micromanage; trust the agent to execute on stated goals.
Situational awareness failures. In the real-user study, 40% of cases showed the agent failing to track task constraints (e.g., a budget limit or date restriction). Shared memory helps prevent this because the constraint stays in view, but the agent must also actively parse what the human cares about from messages and actions.
Done right: clear collaboration protocol. Agents that ask questions, send explicit messages, and wait when confused build trust because the human knows the agent is reasoning alongside them, not secretly deciding alone. When humans step in to explain a lesson (not just override), the agent learns the underlying principle and avoids the same mistake next time. The framework provides the scaffolding for these moments.
What a runnable demo should prove

What a runnable demo should prove

Build a simple multi-step task: e.g., design a day-trip itinerary by choosing a starting location, picking attractions, and routing between them. Implement an agent that suggests an itinerary, and a human that can override individual stops or suggest alternatives. Log every action and measure two metrics: (1) whether the final itinerary matches the human's stated preferences (a goal the human declares upfront), and (2) Initiative Entropy (how often the human and agent each steered the plan).

Success = (true preferences met) * 100%; Balanced = Initiative Entropy > 0.5

The demo must show that when the human and agent work in parallel with shared memory, they finish faster because there are no delays waiting for handoffs, and with higher satisfaction because the human's input is acknowledged in real time instead of being ignored until a flawed draft forces a revision.
