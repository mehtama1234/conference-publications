Query-Aware Flow Diffusion for Graph-Based RAG with Retrieval Guarantees

QAFD-RAG steers graph retrieval using the query at every hop, because a useful subgraph should follow the question's meaning rather than wander through every nearby connection.

Paper explainersAll themesAgents & Tool Use

Graph-based retrieval can outperform flat document search when the answer depends on several linked facts, because the graph already stores the connections needed for multi-hop retrieval. The trouble is that many graph retrievers still explore with mostly static rules. They gather neighbors because those nodes are connected, not because those nodes help answer this specific query. QAFD-RAG changes that traversal rule. At each step, it gives more weight to edges whose endpoints align better with the query, then diffuses flow through the graph under those query-specific weights so that score keeps concentrating on paths that stay relevant across several hops. The result is a smaller and more relevant reasoning subgraph, along with formal recovery guarantees under stated signal conditions.

Zero assumption version

Why static graph traversal pulls in the wrong evidence

A knowledge graph is full of useful connections, but not every nearby node helps with the current question. A retrieval system that simply expands a fixed neighborhood often drags in distractors because structural closeness is not the same as query relevance.

This hurts graph-based RAG in two ways. First, the retrieved subgraph becomes noisy, so the answering model has to reason over facts that do not matter. Second, existing methods often rely on heuristics with no formal account of when the right subgraph will actually be recovered. The paper targets both issues by letting the query shape traversal at every step and by analyzing when that process succeeds.

In one sentence. Weight graph movement by query relevance at each hop so that retrieval follows the question's meaning, then prove that this query-shaped diffusion recovers the right subgraph under mild signal conditions.

The algorithm as a flow

What it actually does

Represent the query and graph nodes

The system computes a query representation and node representations because traversal weights must reflect how well a candidate node matches the question.

Assign query-aware edge weights

Each edge receives a weight based on how well its destination aligns with the query, so that movement through the graph prefers directions that better match the question.

Run flow diffusion

Starting from seed nodes, the algorithm repeatedly spreads score mass through the weighted graph because relevance may require several hops rather than one direct match.

Stop when the mass concentrates

The process converges quickly because irrelevant branches receive little weight and lose mass over repeated steps.

Extract the top subgraph

The highest-mass nodes and edges become the retrieved evidence because they best balance connectivity with query alignment.

What the paper changes

What the paper changes

The paper changes the traversal rule inside graph retrieval. Instead of using static expansion that treats all outgoing links similarly, it reweights each step with the current query. That one change is what turns graph search into query-aware graph search.

The hidden quantity

The hidden quantity: subgraph usefulness

measured quantity  =  probability that the retrieved subgraph contains the facts the answer needs

The retriever never observes subgraph usefulness directly at test time. It only sees the graph, the query, and local scores. Yet the real goal is to recover the connected piece of the graph that contains the needed facts while leaving irrelevant branches behind.

QAFD-RAG estimates this hidden quantity through diffused flow under query-aware weights. A node that repeatedly receives mass from many query-aligned paths becomes more likely to belong to the useful reasoning subgraph. The theory in the paper then states when this process recovers the relevant subgraph with high probability.

Why it works

Why query-shaped diffusion retrieves better evidence

Static graph methods make an early mistake and then keep building on it. Once they enter an irrelevant but densely connected region, ordinary expansion rules continue exploring that region because the graph itself offers many outgoing links. The query no longer has enough influence to pull the search back.

QAFD-RAG counters that by reintroducing the query at every hop. Each move is weighted by how well the next node matches the question, so irrelevant branches naturally lose mass over time. Diffusion matters because many answers require multi-hop evidence. A one-step scorer can miss those paths, while repeated weighted propagation can accumulate score across a chain of individually plausible steps until the full answer-supporting subgraph emerges.

A tiny worked example
Suppose the seed node starts with score 1.00 and has two outgoing links.
For this query, one link gets weight 0.80 because its destination matches the question well, while the other gets 0.20.
After one step, most of the score flows to the first branch because the traversal rule prefers the more relevant direction.
At the next hop, that first branch again splits its score using the same query-aware rule, so a full multi-hop path can keep accumulating score.
After several steps, the scores stabilize on the nodes that remain consistently aligned with the query.

The guarantee comes from this repeated concentration of score on query-aligned paths, not from any single greedy hop alone.

What can go wrong

What can go wrong

Weak node-query scoring. If the alignment score between the query and candidate nodes is noisy, the traversal weights can favor the wrong branch because the system is steering from a bad relevance signal.
Bad seed selection. If the diffusion starts far from the useful region, even a good weighting rule may spend too much mass on the wrong part of the graph before it reaches the needed evidence.
Guarantee assumptions may not hold. The recovery proof depends on signal-to-noise conditions. In a graph where relevant and irrelevant nodes look nearly identical to the query, the probability guarantee can weaken because the method no longer has a clean semantic contrast to exploit.
Done right. When seed nodes are reasonable and query alignment clearly distinguishes useful from irrelevant branches, diffusion retrieves a small high-value subgraph because score repeatedly accumulates along the right paths.
What a runnable demo should prove

What a runnable demo should prove

Build a small knowledge graph for multi-hop question answering where the correct answer requires following two or three linked facts. Compare a static neighborhood retriever against a query-aware diffusion retriever. For each question, visualize the retrieved subgraph and mark which nodes actually support the answer.

Then pass the retrieved subgraphs to the same answering model. Report both retrieval metrics and final answer quality. The important result is that the query-aware system should return fewer distractor nodes while still preserving the necessary answer path, because every hop remains tied to the question.

subgraph_recall = answer_supporting_nodes_retrieved / total_answer_supporting_nodes

The demo should show that graph retrieval improves when the query guides the whole walk, because repeated query-aware weighting keeps the search on relevant paths instead of drifting into merely connected regions.
