Efficient training with fewer parameters

These papers make fine-tuning much cheaper by only updating a small part of a model instead of all weights, using rank-based tricks or clever decompositions.

All themesField mapMathematicsAll explainers
What this is

Modern language models are pretrained on billions of words, which costs millions of dollars. But then you want to adapt them for your specific task — legal documents, medical records, custom domains. If you retrain all the weights, you need almost as much compute as the original training. What if you could fine-tune the model by updating only a tiny fraction of its weights? These papers tackle that problem. Methods like Low-Rank Adaptation add a small, low-rank matrix (a grid of numbers with special structure) that sits alongside the pretrained weights and gets trained instead of changing the weights directly. It is like putting a thin filter over the network that learns the new task, while the core knowledge stays frozen.

Why does this work? Because the weight updates actually live in a lower-dimensional space. When you train a model, the changes to the weights do not point randomly in all directions — they move along a few important directions that capture the task you are learning. If you can identify and train only those directions, you do far less work. The catch is figuring out which directions matter and how to structure the small trainable part so it can still express everything the model needs to learn.

Another angle is adapter modules — small neural networks bolted onto existing layers that learn the new task, leaving the pretrained weights alone. These papers compare different structures: matrices, adapters, prefix-tuning (adding extra text chunks that get trained), and combinations. They measure how many weights you need to update versus how well the model performs on new tasks. The goal is to make fine-tuning cheap enough that individuals and small companies can adapt large models without needing a supercomputer.

How the work breaks down

The work splits into four natural directions: improving the core LoRA algorithm to narrow the gap with full fine-tuning, adapting parameter-efficient methods to run under real-world constraints like quantization (storing numbers in fewer bits to save memory) and federated settings (training across multiple machines), using entirely different mechanisms like context-to-adapter conversion, and solving the systems challenges that arise when deploying many parameter-efficient adapters at scale.

Closing the gap with full fine-tuning

LoRA is simple: you freeze the pretrained weights and add a tiny low-rank matrix (a thin overlay) that learns the new task. But LoRA sometimes leaves performance on the table compared to retraining all weights. Three papers attack this directly by rethinking how to structure and initialize the low-rank updates.

LoFT narrows the gap between low-rank and full fine-tuning by changing how the low-rank matrices interact with the frozen weights — the core insight is that the update structure matters as much as the rank. LoRA-DA starts the low-rank matrices smarter by analyzing the training data upfront to guess which directions will be most important, so fewer iterations are needed to converge. Both beat standard LoRA without slowing inference. CR-Net goes further by exploiting structure across multiple layers: instead of treating each layer's low-rank adapter independently, it shares information between layers in a way that scales cleanly from small models (60M) all the way to large ones (7B). These three papers agree that LoRA's simplicity is both its strength and its limitation — small changes to how you set it up or initialize it create surprisingly large gains.

LoRA under quantization and distributed training

Real deployments face hard constraints: models are quantized (numbers stored in fewer bits to save memory), training happens across multiple machines (federated), or you need to train with extreme sparsity. These papers show that low-rank adaptation still works well under these pressure points, though you need to rethink some details.

QWHA pairs low-rank adaptation with quantization-aware training using a mathematical trick called Walsh-Hadamard transforms to keep the low-rank structure even when numbers are stored in low-bit formats — the key is that the matrix math still works cleanly. Weight Updates as Activation Shifts takes a radical step: instead of modifying weights directly (which gets messy with quantization), it only tweaks the activations (the intermediate signals flowing through the network), using just 0.04% of parameters while staying nearly as accurate as retraining everything. Decoupled Low-Rank Adaptation handles the federated setting where each machine trains independently on its own data before aggregating: it decouples the low-rank update into two pieces (one that's local to each machine, one that gets aggregated globally), so disagreements between machines do not break convergence. All three show that parameter efficiency survives real-world friction.

New mechanisms beyond matrix overlays

Not every efficiency win comes from the LoRA playbook. Two papers explore completely different angles: converting task knowledge into low-rank weights without training, and applying efficiency tricks to vision transformers (networks that process images by treating them as sequences of small patches).

SHINE solves a practical problem: suppose you have a long document you want the model to understand, but it is longer than the model's context window. Traditional fine-tuning with LoRA requires training time. Instead, SHINE runs a single forward pass through a special network that directly generates the LoRA weights from the document, turning in-context knowledge into in-parameter knowledge in one shot. Jumbo Token approaches vision transformers (ViTs) differently: tokens at the end of the sequence carry less information, so you can 'merge' them into a single thick token early, cutting computation while gaining accuracy on pre-training and adaptation tasks. Both papers show that once you understand why parameter efficiency works (certain directions matter more), you can invent new mechanisms beyond the standard low-rank matrix.

Merging adapters and inference infrastructure

When you fine-tune many tasks with LoRA, you end up with many adapters. Can you combine them into one? Can you serve multiple adapters without each one eating memory? Systems work answers yes, but the details matter.

Compress then Merge shows you can combine multiple trained adapters by compressing them first, then merging the compressed versions while guaranteeing the result stays low-rank — this beats naive merging because you stay within your memory budget. CLIMB tackles a different problem: when a server needs to quickly switch between different LoRA adapters for different users, pulling each one from disk causes stalls and unpredictable latency. By managing the memory fetch queues intelligently, CLIMB avoids the 'residency cliff' where small changes in load cause huge latency spikes. LRAgent solves it from the other direction: when multiple LoRA adapters run in parallel, they can share the KV cache (intermediate computation results), recovering almost all the speed of fully shared caching while keeping accuracy separate per adapter. Together these papers show that efficiency at training time (fewer parameters to update) creates new systems challenges at serving time (many adapters, shared resources), and solving those challenges unlocked a new tier of deployment efficiency.
