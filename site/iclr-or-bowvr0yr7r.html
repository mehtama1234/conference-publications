Scaf-GRPO: Scaffolded Hints Unlock Hard Math

When a language model hits a ceiling on hard math problems, carefully-timed hierarchical hints teach it to climb without getting addicted to hints.

Paper explainersAll themesOther

Training language models to solve hard math problems using reward signals works well until the model encounters a problem it simply cannot crack. At that point, the learning signal vanishes (zero reward for any attempt), and the model makes no progress. Scaf-GRPO solves this by stepping in with tiered hints only when the model is truly stuck, progressing from abstract ideas to concrete steps, teaching the model to solve the hard problem on its own.

Zero assumption version

The learning cliff: zero reward freezes progress

Today, the best way to teach a language model to solve math problems is to show the model the problem, let it write an answer, then check if the answer is correct. If correct, reward it; if wrong, no reward. Over many attempts, the model learns patterns that lead to correct answers. The model learns by comparing: among all its attempts in a batch of problems, which ones got the high reward and which got zero? The difference between these groups shapes how the model updates.

The problem: when problems are extremely hard (beyond the model's current level), every single attempt gets zero reward. The model cannot tell which of its thousands of steps were on the right track. The learning signal collapses to silence. A beginner might think: just give the model the answer so it learns from success. But that backfires—the model then copies the given answer blindly, never learning to reason through hard problems on its own.

The core idea in one sentence. When a model plateaus on hard problems, feed it tiered hints (abstract concepts, then concrete steps) only on problems it cannot yet solve by itself, then train normally on that hint-seeded reasoning.

The algorithm as a flow

What it actually does

Step 1: Run freely first

Let the model solve problems on its own for the first 15% of training without any help, so you can see which problems it can solve naturally (pseudo-hard) and which it cannot (true-hard). You only give hints to true-hard problems, because giving hints to pseudo-hard problems wastes compute and teaches dependence on hints instead of autonomy.

Step 2: Find the hard ones

Identify problems that always fail (true stagnation) versus ones it might solve with more training (pseudo-hard).

Step 3: Provide tiered hints

On true-hard problems, start with abstract hints (the Key idea), then concrete steps (Planning, then Solution steps).

Step 4: Train on hint-seeded answers

The model uses the hints to build a correct solution, then train normally—the model learns to reason through the hard problem.

Step 5: Measure graduation

Track when the model solves hint-seeded problems without hints, marking true learning, not memorization of hints.

What the paper changes

What changes: the training data for hard problems

The paper does not change the reward signal or the training algorithm itself. Instead, on hard problems that stall progress, it injects hints directly into the problem text. The model then generates a solution using the hint as scaffolding. On easier problems (or after the model graduates), no hints are shown. The hints are temporary—a training ladder that is removed once the model has learned.

The hidden quantity

The hidden quantity: learning stagnation

measured quantity  =  Stagnation detection (true-hard vs pseudo-hard)

A learning stagnation occurs when a problem consistently yields zero reward even after multiple training runs. But not all zero-reward problems are equally hard: some are pseudo-hard (the model could solve them given more time or more tries) and some are true-hard (genuinely beyond the model's current reasoning). The paper detects this by running an exemption period for the first 15% of training with NO guidance, then measuring which problems remain zero-reward even with more training attempts. True-hard problems stay at zero; pseudo-hard ones eventually crack.

The framework measures this by tracking the count of problems the model solves with any success during the exemption period. This count tells you which problems are solvable (pseudo-hard) and which are not (true-hard).

Why it works

Why it works: hint-seeded paths train the model to reason autonomously

The core mechanism is pedagogical scaffolding: when a student is stuck on a hard problem, a good tutor does not give the answer—instead, the tutor gives a hint that opens a path. The student then walks that path on their own. Scaf-GRPO applies this principle to model training.

When a problem is truly hard, the model's attempts all fail, so the learning signal is zero—all attempts look equally bad. The model cannot learn from the contrast between good and bad reasoning. By seeding one attempt with a hierarchical hint (starting with the Key idea, then Planning steps, then Solution details), the framework gives the model at least one trajectory that reaches the correct answer. The model now sees: on this problem, this chain of reasoning led to success. The model learns the structure of a valid solution path. In later training on similar problems, the model can reconstruct that reasoning without hints, because it has learned the underlying pattern.

Critically, the hints are in-prompt and hierarchical: abstract hints do not constrain the model (many ways to apply a Key idea), while concrete hints narrow the space (but the model still fills in details). This lets the model learn to reason while staying autonomous. Over training, the model graduates—it solves previously-hard problems without hints, showing it has learned the reasoning, not copied the hints.

The training objective: normalized advantage on hint-seeded trajectories

First in words:

For each problem, compute the reward (1 if correct, 0 if wrong). For a batch of attempts on the same problem, compute the average reward and standard deviation. For each attempt, subtract the mean and divide by the standard deviation to get the normalized advantage. Train the model to increase the probability of high-advantage attempts and decrease low-advantage ones.

Then the compact form:

A_hat = (R - mean_reward) / (std_reward + epsilon)

Every symbol:

Rthe reward for an attempt (1 if answer is correct, 0 if wrong)
mean_rewardthe average reward across all attempts in the batch
std_rewardhow much the rewards vary in the batch
A_hatthe normalized advantage (how much better or worse than average)
epsilona small number to avoid dividing by zero
A tiny worked example
Batch of 4 attempts on a hard math problem.
Attempt 1: wrong (R=0), Attempt 2: wrong (R=0), Attempt 3: wrong (R=0), Attempt 4: correct with hint (R=1).
Mean reward = (0 + 0 + 0 + 1) / 4 = 0.25
Std dev of rewards = sqrt(variance) ~ 0.433
Advantage for Attempt 1: (0 - 0.25) / 0.433 = -0.58 (worse than average)
Advantage for Attempt 4: (1 - 0.25) / 0.433 = +1.73 (much better than average)
The model learns to increase the patterns in Attempt 4 and decrease patterns in Attempt 1.
Scaf-GRPO ensures Attempt 4 (the hint-seeded one) is always in the batch, providing a learning signal even when the model is stuck.

Without hints, all four attempts have zero reward and zero advantage for all—no learning signal. With hints, Attempt 4 has full reward, creating a contrast the model can learn from.

What can go wrong

What can go wrong

Hint addiction: model copies hints instead of learning. If hints are too concrete (step-by-step solutions) the model memorizes them rather than learning to reason. Fix: use hierarchical hints that start abstract and gradually become concrete, forcing the model to fill in reasoning gaps.
Misclassifying pseudo-hard as true-hard. If you label a problem as true-hard too early (before giving it enough training attempts without hints), you waste compute on hints. Fix: run a long enough exemption period and use a high threshold for calling a problem true-hard.
Hints do not match the model's level. Abstract hints may still be too hard if the model lacks basic reasoning skills. Concrete hints may not generalize if the model is ready to reason more freely. Fix: design hints to be incrementally concrete, and validate that the model can reason beyond the hints.
Done right: model solves unseen hard problems without hints. After training on hint-seeded hard-problem traces, the model solves similar hard problems it has never seen before, without hints. This is the graduation signal: the model has learned, not copied.
What a runnable demo should prove

What a runnable demo should prove

Set up a math problem the model currently fails on (e.g., a Constraint Optimization problem). Train the model with vanilla GRPO for 100 steps on a batch of 10 similar problems. Record the solve rate (how many it solves correctly). Then train Scaf-GRPO on the same problems with hints enabled: detect which problems stay at zero, seed hint trajectories for true-hard problems, and train for the same 100 steps. Record the solve rate again. Then disable hints and test the model on new unseen problems of the same difficulty. The demo proves Scaf-GRPO boosts performance on hard problems because the hints created learning signals where none existed before, and the boost transfers to unseen problems without hints because the model learned the underlying reasoning pattern, not memorized the hints.

Solve rate = (# correct answers) / (total attempts), measured before and after, with and without hints, on seen and unseen problems.

The demo must show: Scaf-GRPO solves more hard problems than vanilla GRPO, and the model solves new hard problems without hints (graduating, not copying).
