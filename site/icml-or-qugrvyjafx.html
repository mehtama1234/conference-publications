ConFlux: Multivariate Time Series in Flux, One Unified Forecast in Confluence

Reorder and patch multivariate time series to align their jumble of asynchronous signals into a unified stream the model can forecast together.

Paper explainersAll themesTime Series & Sequential

Real-world time series (like hourly electricity, traffic, and weather readings from different sensors) arrive at different rates and interact in shifting ways, but forecasting requires merging these scattered signals into one prediction. ConFlux solves this by reordering the variables to untangle their dependencies, then gluing nearby ones into compact patches that a transformer model (a standard deep learning architecture) can process as if they were a single aligned stream.

Zero assumption version

The jumble: many sensors, one forecast

Real time series have 100 sensors—electricity use, weather, water flow, traffic—each reporting every hour, each evolving on its own schedule and influencing the others in hidden ways. A naive forecasting model treats them all the same, processing them in whatever order they arrive: sensor 1, 2, 3, etc. But that arbitrary order forces the model to waste learning capacity decoding which sensor talks to which, rather than focusing on the real patterns.

The beginner's approach is to just feed all 100 time series into a single transformer (a neural network that reads sequences) and hope it figures out the dependencies. This breaks because: the model spends learning power untangling the jumble, the model's attention (the part that tracks relationships) bloats because it must look at all 100 sensors at every step, and memory and computation explode in real-world systems with thousands of variables.

The fix in one sentence. Reorder the variables to group related ones together, glue them into compact patches, and feed the patches to the model so it sees a short, coherent stream instead of a long jumble.

What the paper changes

What the paper changes

ConFlux changes the order and grouping of the input variables. Instead of processing sensor 1, 2, 3, ..., 100 in arbitrary sequence, it reorders them by learned dependency (so correlated sensors sit next to each other) and glues consecutive ones into patches. This transforms a long, tangled sequence into a short, coherent one.

The hidden quantity

The hidden quantity: dependency structure

measured quantity  =  Sensor-to-sensor dependency graph

The paper measures which sensors influence each other—this is the dependency structure. It is hidden because raw time series do not label these relationships; you must infer them. ConFlux estimates this structure by looking at cross-correlations (how much each pair of sensors move together over the data) or by learning it during pre-training. Once you know which sensors cluster together, you can reorder them to minimize the distance between related ones.

The paper uses this hidden quantity to guide two concrete decisions: (1) the reordering rule (put dependent sensors near each other in the sequence) and (2) the patch boundaries (group sensors that interact closely). Without measuring the dependencies, reordering would be random and patches would be arbitrary, throwing away the benefit.

Why it works

Why it works: shorter paths for learning

A transformer learns by updating its internal weights based on how well it predicts the data. When variables are in random order, the model must use its attention mechanism (the part that tracks relationships) to figure out which sensor talks to which. When ConFlux reorders the variables by dependency, related sensors sit next to each other. Now the transformer's attention can focus on real patterns (e.g., electricity surges when temperature drops) rather than decoding the jumble. Shorter learning paths (attention looking at related neighbors) mean the model can extract patterns faster because it spends fewer steps mapping which sensor is which.

Second, patching reduces sequence length dramatically. A transformer's compute cost grows with the square of sequence length (doubling the length makes work multiply by four). With 100 sensors, a naive model reads 100 positions at every step. ConFlux compresses this to 30 patches, cutting the length by a factor of 3–4. Fewer positions means faster training because the model does less work per step, lower memory use because it stores fewer position values, and faster inference (when the trained model answers queries) for the same reason. The model can concentrate on learning the real patterns instead of drowning in pure scale.

The patching and reordering formula

First in words:

For each patch, compute a single vector by summing the sensor readings in that patch (weighted by learned importance). Feed this compact vector to the transformer as one token, shortening the sequence.

Then the compact form:

p_j = sum_i in patch_j w_i * x_i(t)

Every symbol:

p_jthe single vector for patch j (the output of one patch)
x_i(t)the reading from sensor i at time step t
w_ia learned weight (importance) for sensor i within the patch
patch_jthe set of sensors assigned to patch j (typically 2–4 sensors)
A tiny worked example
Patch 1 has sensor-electricity (w=0.7) and sensor-temperature (w=0.3).
At hour 5: electricity reading = 100, temperature reading = 20.
Patch vector = 0.7*100 + 0.3*20 = 70 + 6 = 76.
Instead of processing two separate sensor readings, the transformer reads one number, 76, representing the patch.
Patch 2 has sensor-humidity (w=0.5) and sensor-pressure (w=0.5), reading 60 and 30 → patch vector = 0.5*60 + 0.5*30 = 30 + 15 = 45.
Now the transformer processes the short sequence [76, 45, ...] instead of [100, 20, 60, 30, ...], cutting sequence length in half.

The weights allow the model to learn which sensors in a patch matter most, because sensors that interact closely should contribute more to the patch's combined value than sensors that are loosely coupled; reordering ensures related sensors are nearby so their weighted sum captures the key patterns between them.

What can go wrong

What can go wrong

Dependency structure is hidden and estimated, not given. If the correlation-based reordering is wrong (e.g., in truly asynchronous systems where causality lags), the patching may group unrelated sensors. The model then inherits the misalignment.
Patches lose fine-grained sensor identity. When you compress multiple sensors into one patch vector via weighted sum, you lose the ability to track individual sensor contributions. If the model needs to know which of the five sensors in a patch caused a change, patching obscures it.
Reordering adds an extra pre-processing step. The paper's approach requires either pre-training on a reference dataset (to learn the order) or computing correlations upfront. On datasets you have never seen before without historical data, reordering is harder to bootstrap.
Done right: reordering works best on heterogeneous (many different sensor types) datasets. When datasets truly mix independent domains (electricity, weather, traffic), discovering and enforcing a dependency order pays off. When variables are already homogeneous and balanced, simpler approaches may suffice.
What a runnable demo should prove

What a runnable demo should prove

A demo starts with a dataset of 50–100 multivariate time series (e.g., a subset of real electricity grid or weather data), splits it into train and test, and trains two models: (1) a baseline transformer on the time series in random order, and (2) ConFlux on the reordered, patched version. For each model, measure forecast accuracy on held-out test timesteps.

improvement = (accuracy_conflux - accuracy_baseline) / accuracy_baseline * 100%

The demo must show that reordering + patching produces visibly lower forecast error (typically 8–15% improvement), faster training time (because attention compute is quadratic in sequence length, so fewer patches saves exponential work), and smaller peak memory use (because the transformer buffers fewer positions), proving that coherent structure lets the model learn patterns faster and use resources more efficiently.
