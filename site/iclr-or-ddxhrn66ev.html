sleep2vec: Unified Cross-Modal Alignment for Nocturnal Biosignals

A foundation model learns a single shared representation from diverse sleep-measurement devices by aligning their signals and downweighting misleading negatives from different ages, genders, and sites.

Paper explainersAll themesRepresentation & Self-Supervised Learning

Sleep clinics use many different devices (head sensors, chest monitors, finger pulse readers) that all measure overlapping things about sleep. Right now, each device needs its own separate model. sleep2vec learns one model that works with any mix of devices by finding a common language between them during unsupervised pre-training. It does this by teaching the model that the same person sleeping should look similar across devices, while carefully handling the fact that a 10-year-old and a 70-year-old will have very different sleep fingerprints.

Zero assumption version

Why one model cannot handle many devices

Sleep medicine uses many kinds of sensors. A hospital might use a full-head EEG setup; a patient at home might use a wristband; an ICU uses bedside monitors. All measure overlapping information (heart rate, breathing, brain waves) but in different ways. A beginner's first attempt: train one model on all mixed signals. This fails because EEG from a 30-year-old looks completely different from EEG from an 80-year-old, even during the same stage of sleep. The model learns to shortcut: just predict the person's age from the shape of the signal, ignore the actual sleep state, and it gets high accuracy anyway.

Worse, device differences turn into hidden signal biases. A particular hospital's monitor setup starts to look like a specific age group or geographic region. The model learns that (device X always means younger patients) even though device X itself has nothing to do with age. When you move the model to a new hospital, it fails.

The problem in one sentence. Different devices, patient ages, and hospital sites create confusing shortcut patterns that leak age and site into the model instead of teaching it real sleep.

The algorithm as a flow

What it actually does

Take two signal types

Pick a brain signal and a heart signal from the same sleeping person in one batch.

Embed each modality

Convert each raw signal to a list of numbers using a separate encoder, one per device type.

Project to shared space

Push both lists through a common projection layer so they both live in the same high-dimensional space.

Score cross-modal similarity

Measure how close the brain-signal list is to the heart-signal list from the same person.

Downweight bad negatives

When comparing to other sleepers, reduce the penalty if the other sleeper is a very different age, gender, or site.

What the paper changes

What the paper changes

The paper changes the weights in the contrastive loss function that decides how harshly to punish disagreements between device signals. Instead of treating all other sleepers as equally wrong (standard contrastive learning), it examines who those other sleepers are: a 70-year-old sleeper is less of a negative example when comparing 10-year-old signals (because their sleep looks different for biological reasons), while another 30-year-old from the same hospital is a very strong negative (because they should look similar on the same device). These weights are computed from stored metadata: age, gender, hospital site, patient history.

the object it moves  =  negative-sample weights in contrastive loss
The hidden quantity

The hidden quantity: Cohort-shift signal

measured quantity  =  Metadata-conditioned negative weight

Every time the model compares two sleep signals, it decides how much to count that comparison based on whether those signals come from similar or very different people. A metadata-conditioned weight is a number (between 0 and 1) that measures how much the model should listen to that pair. If the two sleepers have matching age, gender, and site, the weight is high (around 0.9): their signals really should look alike, so disagreement matters. If they differ in age or site, the weight is lower (around 0.3 to 0.7): we expect their signals to look different for demographic reasons, so disagreement is expected noise. If they differ radically (newborn vs. elderly), the weight can drop further. The paper estimates this weight using a normalized formula: for each pair of sleepers, compute a score based on how many attributes match, then sum these scores and normalize so all weights for one comparison sum to 1.

The paper shows this hidden quantity matters because models trained without metadata-aware weighting learn to use age and site as shortcuts, while models that use these weights learn to ignore those shortcuts and focus on the true sleep patterns.

Why it works

Why metadata-aware weighting breaks shortcuts

Without metadata weighting, the model sees: same-person signals from two devices pull together (positive pair, small loss). Signals from different people should push apart (negative pair, large loss). But if Person A (10 years old, from Hospital X) and Person B (70 years old, from Hospital Y) are both in the batch, their signals naturally look very different. The model does not know whether this difference is because they are different people or because one is a child and one is elderly. It ends up learning: child-signals cluster one way, elderly-signals cluster another way, devices are secondary. This is a shortcut: the model predicted age without ever seeing an age label.

Metadata weighting fixes this by saying: Person A and Person B have very different ages, so we do not actually expect their signals to be similar. The large distance between them is not a learning signal—it is baseline noise. Reduce the weight of this negative pair from 1.0 to 0.2. Now, when the model moves a child-signal closer to other child-signals, it barely reduces the loss (the weak negative pair contributes almost nothing). But when the model moves two signals from the same person (same demographics) closer together, it sharply reduces the loss (high-weight pair). The model gradually realizes: the true signal is within-person alignment, not within-age clustering. Age becomes irrelevant. The shared representation learns sleep, not demographics.

Math after the picture

The equation: DASH-InfoNCE loss

First in words:

For each anchor signal, compute the log probability that it is closer to its positive pair (same person, different device) than to all negatives (other people). Negatives are downweighted by a metadata-aware score. The loss is the negative of this log probability, summed over all anchors in the batch.

Then the compact form:

L = (1/B) * sum_i [ -log( exp(s_i,pos / tau) / sum_j w_i,j * exp(s_i,j / tau) ) ]

Every symbol:

Ltotal loss to minimize
Bbatch size (number of signal pairs)
s_i,possimilarity score between anchor i and its positive pair (same person)
s_i,jsimilarity score between anchor i and negative j (different person)
w_i,jmetadata weight for the anchor-negative pair (low if very different age/site)
tautemperature (controls steepness of softmax, typically 0.1)
A tiny worked example
Batch of 4: Person A (age 10, site NYC), Person B (age 70, site LA), Person C (age 10, site NYC), Person D (age 65, site LA).
For anchor from A's brain signal: positive is A's heart signal (same person).
Negatives are B, C, D. Metadata weights: w_AB = 0.2 (very different age and site), w_AC = 0.95 (same age and site), w_AD = 0.3 (different age, different site).
Similarity scores: s_A,pos = 0.8 (similar device), s_A,B = 0.4, s_A,C = 0.35, s_A,D = 0.45.
Raw softmax denominator: exp(0.8/0.1) + 0.2*exp(0.4/0.1) + 0.95*exp(0.35/0.1) + 0.3*exp(0.45/0.1) = exp(8) + 0.2*exp(4) + 0.95*exp(3.5) + 0.3*exp(4.5).
Denominator: 2981 + 0.2*54.6 + 0.95*33.1 + 0.3*90.0 = 2981 + 10.9 + 31.4 + 27.0 = 3050.
Loss term: -log(exp(8) / 3050) = -log(2981/3050) = -log(0.977) ≈ 0.024. Low loss: the anchor is much closer to its positive than to weighted negatives.
Contrast: without weights, denominator would be exp(8) + exp(4) + exp(3.5) + exp(4.5) = 2981 + 54.6 + 33.1 + 90.0 = 3159. Loss would be -log(2981/3159) = -log(0.944) ≈ 0.058. The metadata weight cut the loss roughly in half by de-amplifying irrelevant negatives.

The weights dampen the contribution of demographically distant negatives by multiplying their loss terms by a small number (like 0.2 instead of 1.0), so the model receives weaker punishment signals from age-different pairs and must instead rely on same-person alignment to reduce loss, which teaches it to ignore age and focus on sleep.

What can go wrong

What can go wrong

Metadata is incomplete or wrong. If age or site tags are missing or mislabeled, the weights become meaningless. A 70-year-old tagged as 30 will be heavily downweighted when they should be strongly downweighted. The method degrades gracefully (the model still learns cross-modal alignment) but loses the shortcut-breaking benefit.
Rare-group bias not eliminated, just hidden. If the training data has only five very elderly people, the model may still learn their pattern by accident, even with downweighting, because there are few elderly negatives to compete with. Metadata weighting reduces but does not eliminate site/age bias when groups are severely imbalanced.
Highly similar people from different devices treated as negatives. Two twins, same age and hospital, but one measured on Device A and one on Device B. They are negatives in the contrastive loss (not a positive pair). The model still learns to align them because they have high metadata weight, but the alignment is weaker than it should be since they are treated as negatives not positives.
Done right. Train on large, balanced cohorts with accurate metadata. Apply temporal masking to prevent the model from learning trivial time-synchrony instead of sleep state. Validate that the learned representation transfers to unseen device subsets and holds steady across age ranges.
What a runnable demo should prove

What a runnable demo should prove

Take a pre-trained foundation model and freeze it. On a held-out test set of sleep records, hold out a device type (e.g., drop the EEG channel from all test samples). The model should still predict sleep stage accurately by using only heart rate and breathing. Train a linear classifier on top of the frozen embeddings. Measure accuracy on the dropped-device test set. Then compare: a model trained with standard contrastive loss (no metadata weighting) will score 60–70% accuracy (it learned device shortcuts, now it is lost). The metadata-aware model will score 80%+ (it learned cross-device alignment, works without missing devices). Repeat across multiple missing-device combinations: the metadata model should generalize to any subset. Plot a bar chart: x-axis is which device is dropped, y-axis is sleep-staging accuracy. Naive model should be choppy (bad on some devices). Metadata-aware model should be flat (stable across dropouts).

Robustness = average_accuracy_across_all_device_subsets - accuracy_on_full_device_set

The demo proves that the naive model is brittle (losing a device cripples it because it learned shortcut patterns unique to that device), while the metadata-aware model stays accurate (losing a device barely matters because it learned true alignment that works across all devices).
