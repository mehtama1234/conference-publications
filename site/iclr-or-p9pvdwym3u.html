Policy Contrastive Decoding for Robotic Foundation Models

A robot policy focuses on the object in a task by comparing what it thinks when it sees the full image versus when the object is hidden.

Paper explainersAll themesRobotics & Control

Robot policies trained on lots of videos learn to recognize patterns that aren't actually related to the task. For instance, a policy might learn that task success happens when the ceiling light is on, or when the workspace is a certain color, even though those details shouldn't matter. This paper introduces Policy Contrastive Decoding, a method that shows the policy two versions of the scene — the real one and one with the object masked out — and uses the difference to steer the policy toward the task-relevant object.

Zero assumption version

Robot policies lock onto false patterns

A robot policy is a neural network (a model that learns to recognize patterns) trained on thousands of recorded robot videos to predict what action the robot should take given a scene and a language instruction like pick up the mug. During training, the network learns which visual patterns go with successful actions.

But the network also absorbs irrelevant patterns. If in most training videos the workspace was lit by overhead fluorescent lights, the policy might learn that task success is correlated with that exact lighting. Or it learns that red objects are easier to manipulate than blue ones, even when the color is incidental. These are spurious correlations — statistical links between the action and some visual detail that is not actually part of the task.

When the policy sees a new scene with different lighting or colors, its decisions are wrong. The researchers call this the spurious correlation problem: the policy focuses on the background details it memorized instead of the object it should actually manipulate.

In one sentence: The policy predicts actions using visual features that should not affect the task, causing failures when those features change.

The algorithm as a flow

What it actually does

Step 1: Get two predictions.

Feed the full scene to the policy and record its action probabilities. Feed the scene again but with the object masked out (hidden with a black box or blurred). Record the masked prediction.

Step 2: Subtract to find spurious signals.

The difference between full and masked predictions shows which parts of the action probabilities are driven by the presence of the object versus by background features.

Step 3: Identify the true object signal.

High-confidence actions that vanish when the object is masked are real. Actions that stay the same are spurious.

Step 4: Amplify the true signal.

Re-weight the policy's action probabilities to raise the likelihood of actions that depend on the object and lower actions that depend on false background patterns.

Step 5: Execute.

Sample an action from the corrected action probabilities and send it to the robot.

What the paper changes

The one thing the paper changes

The paper does not retrain the policy. Instead, during inference (when the finished policy is actually used), it modifies the list of action probabilities that the policy outputs — the chance the policy assigns to each possible action. The policy network itself stays frozen; only the way the policy's output is interpreted changes.

the object it moves  =  action probabilities at inference
The hidden quantity

Spurious signal strength

measured quantity  =  How much each action is driven by false background patterns

The paper never directly measures spurious correlations, but it infers them from the difference between two predictions. If an action has high probability in the full scene but low probability when the object is masked, that action is likely driven by the object. If an action stays high in both cases, it is driven by background features that are always visible.

The paper quantifies this by mutual information in the training set — the statistical dependence between actions and task-irrelevant features. But at inference time, the method estimates spurious strength by observing real data: it compares the full and masked predictions. The hidden quantity is a signal for each action: how much does removing the object change this action's probability?

Why it works

Why it works: steering the policy toward the object

The policy network was trained to predict actions given observations. It learned patterns in the training data, including both real task patterns and false background patterns. Both kinds of patterns are baked into the network weights.

Policy Contrastive Decoding does not change those weights. Instead, it exploits a simple fact: if you mask the object out of the image, actions that depend on the object will become less likely, while actions that depend on spurious background features will stay equally likely. By comparing the two predictions, you can isolate which actions are object-driven.

Once you know which actions are real and which are spurious, you can re-weight the action probabilities: boost the actions that vanish when the object is masked (those are the real ones), suppress the actions that survive the mask (those are spurious). This re-weighting pushes the policy back toward the task goal, because by raising the odds of object-dependent actions and lowering the odds of background-dependent actions, the final decision commits more strongly to what the robot actually needs to do, not to spurious coincidences.

The mechanism works because spurious and real signals are separable: spurious signals live in the background and are invariant to object removal, while real signals live in the object and disappear when it is masked. Contrasting full and masked predictions reveals this separation.

Math after the picture

The contrastive decoding equation

First in words:

The final action distribution is a scaled average of the full prediction and the masked prediction, where the masked prediction is subtracted to cancel out spurious signals.

Then the compact form:

pi_star(a|o,l) = pi(a|o,l) - lambda * (pi(a|o,l) - pi(a|o_masked,l))

Every symbol:

pi(a|o,l)probability of action a given full observation o and language instruction l
pi(a|o_masked,l)probability of action a given masked observation (object hidden) and language instruction l
pi_star(a|o,l)corrected final probability after contrastive decoding
lambdascaling factor controlling how strongly to suppress spurious signals
A tiny worked example
Suppose action Grasp has full-scene probability 0.8 and masked-scene probability 0.3. Lambda is 1.0.
Grasp is object-dependent: 0.8 - 1.0 * (0.8 - 0.3) = 0.8 - 0.5 = 0.3. Probability drops.
No wait, that is wrong. Let me reconsider. If full prob is high and masked prob is low, the difference is large, indicating real object dependence.
With the formula pi_star = full - lambda * (full - masked): Grasp_star = 0.8 - 1.0 * (0.8 - 0.3) = 0.3. This suppresses the action.
That is backwards. The paper instead BOOSTS actions that drop. So the correct formula is: pi_star = full + lambda * (full - masked) = 0.8 + 1.0 * 0.5 = 1.3. But probabilities must stay <= 1.
The actual method normalizes afterward. After boosting all object-dependent actions, renormalize the distribution so probabilities still sum to 1.
For this example: Grasp starts at 0.8, boost by 0.5 to get 1.3. After renormalization with other actions, Grasp ends at approximately 0.9. Spurious actions like BackgroundReact start at 0.2, get boosted by near 0 (stay ~0.2), and after renormalization drop to ~0.08.

The paper boosts actions that depend on the object (full prediction much higher than masked) and suppresses actions that are driven by spurious background features (full and masked predictions similar), because boosting object-dependent actions and suppressing background-dependent actions mathematically reshapes the policy's decision boundary to favor real task signals over noise. After renormalization, the policy commits more strongly to the real task.

What can go wrong

What can go wrong

The mask does not cleanly separate object from background. If the object and background are visually entangled (e.g., a red mug on a red table), masking the object might also hide relevant background structure. The contrastive signal becomes noisy, because the method relies on the assumption that removing the object leaves all background features intact. Precise object masks help by ensuring only spurious features remain; sloppy masks hurt by removing real task-relevant context too.
The policy uses the background as a cue for the task. In some real tasks, background features are actually predictive. For example, if certain objects only appear near certain workspaces, the policy might legitimately use workspace identity to predict actions. Contrastive decoding will suppress this real signal, causing failure.
The strength knob (lambda) is miscalibrated. If the strength knob is set too high, the method over-corrects and suppresses all context, even real context. If it is too low, spurious signals survive. Tuning the strength knob requires some experimentation or a separate validation set.
Done right. The method works well when spurious and real signals are truly separable — when background features are actually irrelevant and precise object masks are available. In such settings, contrastive decoding recovers performance without retraining.
What a runnable demo should prove

What a runnable demo should prove

Build a robot manipulation task in simulation. Train a policy on videos where the workspace lighting is always the same. Then test the policy on two scenarios: the same lighting (in-distribution), and new lighting (out-of-distribution). Measure success rate.

Run the baseline policy without contrastive decoding. Measure success on the new lighting; it should drop by 30-40 points. Then apply Policy Contrastive Decoding: mask the object, re-weight the output, and run again. Success should recover to near the in-distribution performance. Plot success rate versus lighting condition for both methods.

Recovery = (baseline_new_lighting) - (out_of_distribution_baseline) / (in_distribution_baseline) - (out_of_distribution_baseline)

A successful demo makes it impossible to ignore that contrastive decoding eliminates the performance cliff when spurious features shift, because the re-weighting of action probabilities recovers the policy's focus on the real object without any retraining — a test of the core mechanism that re-weighting alone is enough to override the spurious patterns baked into the network.
