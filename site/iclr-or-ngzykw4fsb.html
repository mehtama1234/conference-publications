Synchronizing Probabilities in Model-Driven Lossless Compression

Make learned lossless compression survive small prediction mismatches by encoding an interval that both sides can agree on instead of requiring exactly identical probabilities.

Paper explainersAll themesOther

Lossless compression based on next-symbol prediction works by assigning short codes to likely symbols and longer codes to unlikely ones. Neural predictors are attractive because they capture long-range structure in text or other sequences, but they create a severe synchronization problem: the encoder and decoder must use exactly the same predicted probabilities at every step. If floating-point arithmetic, hardware order, or software differences change one probability even slightly, ordinary arithmetic decoding can choose a different symbol, and the entire remainder of the message becomes unreadable. This paper formalizes that failure mode and proposes PMATIC, a coding rule that tolerates bounded probability mismatch by ensuring both sides can still decode the same symbol from overlapping intervals.

Zero assumption version

Why tiny prediction differences cause catastrophic decoding failure

Arithmetic coding compresses a sequence by repeatedly shrinking a numeric interval. At each symbol, the encoder partitions the current interval according to predicted symbol probabilities and selects the subinterval for the observed symbol. The decoder repeats the same partitioning and reads the symbol whose subinterval contains the coded number.

That logic assumes identical probabilities on both sides. In classical compressors this is usually safe because the probability model is deterministic and explicitly synchronized. In model-driven compression, the probability model may be a neural network. Two runs of the same model can differ by a small amount because of hardware differences, mixed precision, or evaluation order.

A small mismatch becomes catastrophic because the interval boundaries are recursive. If the decoder uses slightly different probabilities on one step, it can choose the wrong symbol. From that point onward the context is different, so all later predictions differ too. One tiny probability disagreement triggers a complete decoding collapse.

In one sentence. PMATIC keeps compression synchronized by coding with intervals that remain valid under bounded probability mismatch, because exact equality of predictions is too brittle for learned models.

The algorithm as a flow

What it actually does

1. Predict next-symbol probabilities

Use any learned next-symbol model to assign probabilities to the possible symbols at the current context.

2. Bound the mismatch

Assume encoder and decoder probabilities can differ, but only within a known tolerance.

3. Build mutually valid intervals

For each symbol, find an interval region that remains consistent for both the encoder's and decoder's possible probability partitions.

4. Encode inside the safe region

Write a code value that lies in the symbol's overlap region rather than in an interval that is valid for only one side.

5. Decode with the local probabilities

The decoder uses its own predicted probabilities and still recovers the same symbol because the code value was chosen from a region both sides interpret identically.

What the paper changes

What the paper changes

The paper changes the coding rule that maps predicted probabilities to subintervals. It leaves the learned probability model untouched and replaces ordinary arithmetic coding with a mismatch-tolerant interval construction.

The hidden quantity

The hidden quantity: overlap width

measured quantity  =  the size of the interval region that both encoder and decoder would assign to the same symbol despite their probability mismatch

The danger is not only that probabilities differ. The danger is that the symbol intervals implied by those probabilities stop overlapping. If the encoder's interval for symbol s and the decoder's interval for symbol s still share a nonempty overlap, then a code value can be placed inside that overlap and both sides will decode s. If the overlap vanishes, synchronization is impossible.

PMATIC therefore tracks overlap width. Larger overlap gives more room to place a code value safely, which means lower risk of ambiguity. Smaller overlap means higher coding overhead because the safe region is narrower and may require more careful refinement.

This is the right hidden quantity because correctness depends on it directly. A bounded mismatch is harmless only when it still leaves overlap for every step in the sequence.

Why it works

Why overlap-based coding prevents cascade failure

Ordinary arithmetic coding is brittle because the coded number only needs to land inside the encoder's chosen subinterval. The decoder then reconstructs the same symbol only if its own boundaries match exactly. A tiny mismatch can put the number on the other side of the decoder's boundary, which changes the decoded symbol and destroys all later context.

PMATIC strengthens the requirement at encode time. It does not ask for an interval that is valid under one probability list; it asks for a region that remains valid across all decoder probabilities allowed by the mismatch bound. This works because the first decoded symbol stays identical on both sides, so later contexts also stay identical instead of diverging.

The price is some overhead. Safe overlap regions are usually narrower than the ideal arithmetic-coding interval under exact synchronization, so the coded message can grow slightly. The benefit is that the code remains lossless under realistic non-determinism, which ordinary learned arithmetic coding cannot guarantee.

Safe interval selection

First in words:

For each symbol, use the intersection of the encoder's and decoder's possible subintervals under the allowed mismatch, then choose the code value from that intersection.

Then the compact form:

I_safe(s) = I_enc(s) intersect I_dec(s); encode symbol s only if length(I_safe(s)) > 0

Every symbol:

sthe next symbol to encode
I_enc(s)the encoder-side interval assigned to symbol s

I_safe(s)the overlap interval that both sides interpret as symbol s

intersectset intersection, meaning the values common to both intervals
A tiny worked example
Suppose the encoder assigns symbol A the interval [0.00, 0.50).
Because of mismatch, the decoder would assign symbol A the interval [0.00, 0.48).
The safe interval is their overlap: [0.00, 0.48).
Any coded value inside that overlap will decode as A on both sides.
If the intervals had been [0.00, 0.50) and [0.52, 0.90), the overlap would be empty, so symbol A could not be encoded safely under that mismatch bound.

The coding guarantee reduces to keeping the safe interval nonempty at every step, because a common interval preserves the symbol and therefore preserves the future context.

What can go wrong

What can go wrong

Mismatch exceeds the assumed bound. If the encoder and decoder probabilities differ more than PMATIC assumes, the safe overlap interval may disappear and the guarantee no longer applies.
Safe intervals become too narrow. If the overlap width is positive but tiny, coding overhead can rise because the compressor must spend more bits to identify a value inside the narrow safe region.
Weak predictive model. PMATIC protects synchronization, not prediction quality. If the next-symbol model itself is poor, compression can remain worse than a strong deterministic compressor.
Done right. Use a strong predictive model together with a realistic mismatch bound and overlap-based coding. Then the compressor stays lossless under small prediction differences while preserving most of the gain from model-based probability estimates.
What a runnable demo should prove

What a runnable demo should prove

Take a character-level text compressor with a small learned next-symbol model. Run the encoder on one machine setting and the decoder on another setting that introduces tiny probability perturbations. Compare ordinary arithmetic coding against PMATIC. Measure whether decoding succeeds and how much the file size grows.

The demo should make the cascade visible: ordinary arithmetic coding fails after one early disagreement, while PMATIC keeps decoding correct because every emitted value lies in a symbol interval both sides share.
