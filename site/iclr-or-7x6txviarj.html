MME-Unify: Benchmark for Unified Multimodal Understanding and Generation

A standardized benchmark that measures how well multimodal models can understand images and text, create images and text, and combine these skills to solve hard problems together.

Paper explainersAll themesDatasets & Benchmarks & Evaluation

Multimodal models can now do four things: understand images, understand text, create new images, and create new text. But no test measures how well they do all four things together, especially when they must combine understanding and generation to solve one hard problem. MME-Unify fixes this by creating a single benchmark with one scoring rule that tests all three abilities (pure understanding, pure generation, and mixed understanding-plus-generation) on real tasks from 12 different datasets.

Zero assumption version

No single ruler to measure multimodal abilities

Multimodal models today do many jobs: read an image and answer questions about it, write a story to go with a picture, look at a photo and draw the next frame of a video, or read a math problem and generate the answer as an image with written steps. But when researchers test these models, they each use a different test with different rules and different ways of scoring.

A beginner might test a model on one task at a time: 'How well does it answer picture questions?' 'How well does it make images?' 'How well does it write text?' This breaks because it ignores the real power: a model that combines both skills. For example, it might read an image showing a problem, then generate a diagram showing the solution, then write the answer in words. No single old test measures this three-skill chain.

What the paper does in one sentence. MME-Unify curates tasks from 12 existing datasets, aligns their formats and scoring systems, and adds five brand-new mixed-modality tasks where a model must understand an image or text, then generate something new, then use both to solve a problem.

The algorithm as a flow

What it actually does

Gather and align

Pull 12 existing datasets (question-answering, image generation, text generation, etc.) and reformat each one to use the same answer-scoring method.

Define mixed-skill tasks

Design five new tasks where a model reads one thing (image or text), generates a related thing (diagram or text), then uses both.

Run all models

Test 12 different multimodal models (including Janus-Pro, EMU3, Gemini2-Flash) on all tasks using the unified scoring system.

Measure quality gaps

Compare scores to find which skills each model is weak in: instruction following, image quality, reasoning with mixed modalities.

Publish the benchmark

Release the standardized dataset and scoring code so any researcher can fairly test any new multimodal model.

What the paper changes

The one thing the paper changes

Instead of many different benchmarks with different scoring rules, MME-Unify makes one unified benchmark with one scoring rule that covers understanding, generation, and mixed-modality tasks. This is the object: the evaluation system itself.

The hidden quantity

The skill-combination score

measured quantity  =  Mixed-modality performance

The hidden quantity the paper measures is how well a model does when it must combine understanding and generation to solve one problem. This is different from measuring them separately. For instance, a model might score 80% on 'read an image and answer a question' (pure understanding) and 75% on 'make an image from a description' (pure generation), but only 50% when it must read a problem, generate an answer diagram, and explain the result in words. The dip from 77.5% average to 50% reveals a real weakness: the model's two skills don't combine smoothly.

The paper estimates this by running each multimodal task through the trained model and scoring each part (did it understand correctly? did it generate a valid image? is the text correct?) then combining the scores using the same unified formula.

Why it works

Why unified scoring reveals hidden gaps

Old benchmarks tested one ability at a time on separate datasets. This worked if you only cared about one skill, but real users ask a model to do multiple things in one shot. When you measure purely understanding on Dataset A and purely generation on Dataset B with different scoring rules, the two scores are independent—you cannot see if the model's understanding helps or hurts when it tries to generate, or if poor generation ruins its explanation of what it understood, because the scores come from different datasets and different grading rules, so the model's weakness in combining them stays hidden.

MME-Unify fixes this by: (1) taking real-world tasks where both skills matter (read a photograph, draw an annotated diagram, then write the correct answer), (2) creating a single scoring formula that counts all parts equally (so a model that nails understanding but makes ugly pictures still fails the task, because the overall score averages all three parts), and (3) running all 12 models on the same tasks with the same rules. This makes weak points visible: if Janus-Pro scores 90% on pure understanding but only 45% on mixed-skill tasks, it reveals that its understanding and generation do not work well together, because the unified score forces both skills to deliver equally on the same problem, so neither one can hide a weakness.

The mechanism is direct: unified scoring forces models to show all weaknesses on tasks that matter, because the score only counts if both skills deliver.

Math after the picture

Unified scoring equation

First in words:

Overall score equals the average of (understanding score) and (generation score) and (reasoning score), where each part is measured the same way across all tasks

Then the compact form:

Score_overall = (1/3) * Score_understand + (1/3) * Score_generate + (1/3) * Score_reason

Every symbol:

Score_understandHow well the model read and interpreted the input image or text (fraction correct, 0 to 1)
Score_generateHow well the model created a valid image or text output (quality score, 0 to 1)
Score_reasonHow well the model used both its understanding and generation to solve the problem (fraction of steps correct)
1/3Equal weight to each skill, so no skill hides a weakness in another
A tiny worked example with one mixed-modality task
Model A on one mixed task: understands image correctly (0.9), generates clear diagram (0.6), writes correct explanation (0.8)
Overall = (1/3)*0.9 + (1/3)*0.6 + (1/3)*0.8 = 0.30 + 0.20 + 0.27 = 0.77
Model B on same task: understands image correctly (0.9), generates unclear diagram (0.3), writes correct explanation (0.8)
Overall = (1/3)*0.9 + (1/3)*0.3 + (1/3)*0.8 = 0.30 + 0.10 + 0.27 = 0.67
Model B scores 0.67 even though understanding and reasoning are as good, because poor generation drags down the combined score. The benchmark revealed a hidden weakness.

Equal weight forces each skill to matter; a model that excels at understanding but fails at generation cannot hide behind a high understanding score.

What can go wrong

What can go wrong

Mismatched task difficulties. If one dataset has only easy examples and another only hard ones, the unified score becomes unfair. A model might score 95% on Dataset A (easy) but only 50% on Dataset B (hard) even if it is the same overall strength. Fix: manually check that all 12 datasets have roughly equal difficulty before combining them.
Scorers disagree on generation quality. Judging whether an image is good or a written explanation is correct requires human judgment, and humans disagree. If two raters score the same image differently (one says good, one says mediocre), the unified score becomes noisy. Fix: use multiple independent raters and average their judgments.
Models overfit to the benchmark. Once MME-Unify is published, researchers will finetune their models specifically to beat the benchmark tasks. After a while, MME-Unify scores stop measuring real-world performance and just measure how well models were tuned to the benchmark. Fix: periodically add new tasks to keep models honest.
Done right: transparent metrics. State exactly how each part (understanding, generation, reasoning) is scored before testing begins. Show the raw scores for each task, not just the combined average, so researchers can debug which skills their model lacks.
What a runnable demo should prove

What a runnable demo should prove

Build a small mixed-modality benchmark yourself: pick one understanding task (e.g., visual question-answering on 10 images), one generation task (e.g., draw a simple shape from a text description), and one combined task (read the image, generate the drawing, and write a sentence explaining it). Test two different models on all three. Show that the combined-task scores reveal different relative rankings than averaging the two separate tasks.

Fair_ranking_change = models ranked differently on combined_task vs. (average of separate_tasks); if any model flips more than one rank position, the combined task reveals hidden gaps

The benchmark is not just a collection of tests; it proves that measuring one skill at a time and averaging does not give the same result as measuring real-world tasks where both skills must work together.
