Trees to Flows and Back: Unifying Decision Trees and Diffusion Models

Show that decision trees and diffusion models optimize the same global trajectory objective in different limits, then use that link both to speed up tabular generation and to distill tree logic into neural networks.

Paper explainersAll themesOther

Decision trees split space into nested regions with hard yes-or-no tests. Diffusion models define a continuous random process, where random means the process contains random noise, and gradually transform noise into data by following a learned score field. These model classes look unrelated because one is discrete and hierarchical while the other is continuous and dynamic. This paper argues that the gap is smaller than it appears. In the right limit, a hierarchy of tree splits corresponds to a diffusion-like transport process, and both can be viewed through one training principle called Global Trajectory Score Matching. That link matters because it transfers optimization insight in both directions: tree-inspired flows can generate tabular data with lower compute, and tree behavior can be distilled into neural nets without losing much predictive accuracy.

Zero assumption version

Why trees and diffusion models have stayed separate

A decision tree represents a sequence of partition choices. Each internal node asks a question about the input, and each answer moves the example into a smaller region. A diffusion model describes a full trajectory through noise levels and learns how density changes along that path. Because one model is expressed as splits and the other as a time-dependent field, research usually studies them with separate mathematics and separate optimization rules.

That separation hides two opportunities. Tree methods have strong structure and cheap evaluation on tabular data, while diffusion methods have a principled view of trajectories and score matching. If both classes share one limiting objective, then ideas about optimization, generation, and distillation can move across the boundary instead of staying trapped inside one model family.

The central move. Rewrite both trees and diffusion processes as trajectory estimators, because then their training rules can be compared in one common space.

The hidden quantity

The hidden quantity

measured quantity  =  trajectory score

The key hidden quantity is the score of an entire trajectory: whether the path the model assigns to an example points in the right direction over the whole decision or denoising process. In a tree, that path is a sequence of branch choices. In a diffusion model, it is a continuous time path through noise levels.

A local split can look good while the full path is poor, and one denoising step can look plausible while the whole trajectory drifts. The shared objective focuses on the global path because final sample quality or prediction quality depends on the consistency of the full trajectory, not only on one local move.

Why it works

Why the trajectory view unifies the models

Both model classes move an example toward a data-supported region. A tree does it by repeated partitioning. A diffusion model does it by repeated denoising. If you ignore surface form and track only the path that the example follows, both models become trajectory constructors. That is the first unifying step.

The second step is to evaluate whole trajectories instead of local rules. A tree trained by greedy local impurity reduction can miss globally better paths because one split can look good in isolation while forcing poor later splits, and a diffusion model trained poorly can produce trajectories that look locally plausible but drift across modes because each step was not optimized for full-path consistency. A global trajectory score objective evaluates whether the path, taken as a whole, matches the target density structure. Under the limiting correspondence in the paper, an idealized gradient boosting procedure, which means adding one weak learner at a time to reduce the remaining error, becomes asymptotically optimal for that global objective, which ties classical tree optimization to diffusion-style score learning.

That shared objective enables two concrete designs. Treeflow keeps the hierarchical economy of trees for tabular data, so it can avoid some of the heavy continuous-time cost of standard diffusion sampling because it reuses coarse partitions before spending computation on finer local detail. Dsmtree turns a trained tree into a network by matching trajectory behavior rather than only leaf labels, which preserves more of the teacher's decision logic.

The paper's core abstraction is a path-level score objective that adds up mismatch along an entire trajectory instead of judging each local decision in isolation.

GTSM = expected total mismatch between model trajectory score and target trajectory score over the full path

A tiny worked example
Suppose two tree paths both end in leaves with similar class purity.
Path A makes an early split that isolates a tiny noisy subgroup, then repairs that mistake with later splits.
Path B keeps the main data modes separated from the start and needs fewer repairs later.
A local objective can rate the first split of Path A as acceptable, but a trajectory objective prefers Path B because its full path stays aligned with the target structure.

The unification depends on treating root-to-leaf descent and denoising evolution as objects with a full path score, not only a collection of local moves.

What can go wrong

What can go wrong

The correspondence may rely on limiting assumptions. A clean tree-to-flow equivalence can hold in idealized regimes while practical finite models still differ in important details, so the mapping may guide design without making every tree behave exactly like every diffusion model.
Trajectory scoring can be harder than local scoring. Whole-path objectives use more global information, which can raise optimization and bookkeeping cost because the model must account for consistency across many steps rather than only one split or one denoising time.
Tabular gains may not transfer to other domains. Tree structure is especially natural for tabular data, so the compute win of treeflow may shrink on image or audio domains where continuous diffusion shape carries more of the burden.
Done right. The framework is useful when the data has hierarchical decision structure, because then the path-level objective can be exploited both for efficient generation and for faithful distillation.
What a runnable demo should prove

What a runnable demo should prove

Build a small tabular generator with two versions: a standard diffusion baseline and a treeflow-style generator that uses hierarchical partition structure. Train both on the same synthetic mixture dataset with known modes. Separately, train a decision tree classifier and distill it into a small neural network with and without a path-matching objective.

The demo should show two things. First, the tree-inspired generator should reach similar sample fidelity with lower sampling cost because it uses hierarchical structure directly. Second, the path-aware distillation should preserve teacher predictions on held-out data because it transfers decision logic over full trajectories rather than only final labels.

path_fidelity = agreement_on_full_paths or agreement_on_teacher_outputs at matched compute

A convincing demo must make the trajectory concept visible, because the paper's claim is not only that two models perform well, but that they are best understood and improved through one shared path-level objective.
