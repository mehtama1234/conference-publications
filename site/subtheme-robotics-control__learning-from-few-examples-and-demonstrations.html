Learning from few examples and demonstrations

Papers enabling robots to pick up new tasks from just one or two human demonstrations or examples—reducing the data burden for learning new behaviors.

All themesField mapMathematicsAll explainers
What this is

Ideally, a robot learns a new task from just one or two examples shown by a human. A person shows the robot how to stack blocks, and the robot can immediately stack blocks in any configuration it has not seen before. This kind of learning—from few examples, sometimes called few-shot learning—is common in humans. A child sees one person tie a shoe and can tie their own shoes. But for robots, this is extremely hard because the robot has to extract the essential structure of the task from very limited data, without overfitting to irrelevant details.

The challenge is generalization. If you show a robot one video of stacking a red block on a blue block, the robot might learn 'put red things on blue things.' But the underlying task is 'stack blocks on top of each other'—the colors do not matter. Or the task is 'place object A on top of object B' and you should generalize to any objects. How does the robot figure out what matters? With a thousand examples, the robot can see a pattern. With one example, the robot has to guess. The robot also has to transfer what it learned from one morphology (body shape) to another—if the robot saw a human hand demonstrating a task, can it do the same task with a robot hand? The human hand and robot hand are different, so direct imitation does not work.

Papers here use several strategies. Some use meta-learning—train the robot on many different tasks, so it learns how to learn. When shown one new task, it recognizes patterns from previous tasks and adapts quickly, because it has practiced the skill of adapting many times before. Some use language to help—a human says 'put the red block on the blue block,' and language gives the robot a hint about which features matter, because words pick out what is important from the infinite details in the scene. Some use video as raw data—a human demonstrates with their hand, and the robot learns to translate human hand motion into its own motion. Others use implicit representations: the robot does not learn 'do this action,' but rather learns to embed observations in a space where similar tasks cluster together. In that space, one or two examples are enough to find nearby tasks the robot has seen before, because the representation has already organized similar tasks close to each other.

How the work breaks down

Learning from few examples splits naturally into five paths because different approaches tackle the core bottleneck from different angles. Language or learned task codes help because they tell the robot which features matter, so it needs fewer examples to understand the task. Retrieval and adaptation of past examples work because most new tasks resemble old ones, so the robot can reuse knowledge. Generating synthetic demonstrations addresses the simple truth that collecting human data is expensive. Learning to imitate faster than the original speed makes use of the fact that humans move cautiously but robots have no safety constraints. Finally, handling gaps between learned policies and real physics matters because robots must understand when the simulator was wrong.

Language and learned codes guide fast task learning

When a human tells a robot what to do using words, the language acts like a hint about which parts of a scene matter. A human says 'stack the red block on the blue block,' and the robot now knows to focus on colors and the stacking relationship, not camera angles or backgrounds. The challenge is that language hints and robot actions live in completely different spaces—words are discrete symbols, actions are continuous motions. How do you connect a phrase to a trajectory?

Task Tokens solves this by learning a small code for each task—a compact learned representation that the foundation model can adjust its behavior with just a few examples, reducing the number of changeable weights per task by 125 times compared to retraining the whole model. This lets a user provide language or guidance that narrows down what the robot should learn. One Demo Is All It Takes shows that a single human demonstration plus an LLM can generate a planning domain—a high-level description of how a task works—covering 1,200 tasks across nine environments with 20% higher success than pure LLM planning. ROSETTA goes further by translating unconstrained language preferences directly into reward signals for manipulation, achieving 87% success across 116 different language-specified tasks. These three methods all use the same insight: language compresses the space of possible tasks, so the robot needs fewer examples.

Retrieval and adaptation from demonstrated examples

If a robot has already learned how to do 100 tasks, and you show it a new task that looks similar to task 37, why should it start from scratch? Retrieval-based methods find past examples that are nearby in some learned space, then adapt them to the new task. The hard part is deciding what 'nearby' means—two manipulation tasks might look completely different visually but share the same underlying steps.

Difference-Aware Retrieval Policies retrieves past trajectories that are similar to the new task, but focuses on the differences between the old solution and new task constraints because what changed matters more than what stayed the same, achieving 15-46% improvements over standard imitation learning. Knowledge Diversion handles the case where a robot has one body shape and needs to perform a task that was demonstrated on a different body—it diverts knowledge across morphologies because the underlying task logic stays the same even though the body mechanics are different, getting 3.3 times faster transfer and shrinking model size by a factor of 16.7 for deployment on small robots. Making Learner Weakness Actionable targets a practical case: when novice humans are doing the demonstrations (not experts), the robot's learned policy has blind spots because novices do not explore all variations. This work identifies where the robot fails and asks novice teachers to demonstrate those specific cases so the robot learns to handle gaps, improving success by up to 20% and improving reliability by 14-20%. All three methods assume a library of past experiences exists and try to reuse and adapt it rather than learning from scratch because experience from different tasks builds general patterns.

Generating synthetic data when demonstrations are scarce

Collecting human demonstrations is expensive and time-consuming. If a robot could generate plausible but synthetic demonstrations, it could create unlimited data for imitation learning. The challenge is ensuring the synthetic data is actually useful—invented trajectories that violate physics or task constraints teach the robot bad habits.

MoMaGen generates synthetic demonstrations for complex multi-step tasks with two arms and mobile bases that must respect both soft constraints like smoothness and hard constraints like not dropping objects so that a robot can imitate plausible trajectories. It produces much more diverse datasets than previous methods, enabling successful imitation learning from entirely generated data because when you generate trajectories that cover many variations, the policy learns to handle more cases than any one human could show. Escaping the Diversity Trap tackles a different angle: when you have limited real demonstrations, how do you pick which ones to use? Standard methods just sample diversity, but anchor-centric adaptation instead selects demonstrations centered around key task moments because critical moments matter more, improving task reliability more than standard diverse sampling under the same budget. MoSA learns to model the mismatch between the robot simulator and the real robot—the 'sim-to-real gap'—by learning what parts of the physics need correction based on actual robot behavior so that synthetic training data becomes trustworthy, achieving better accuracy and working on real manipulation tasks. All three scale up limited real data: MoMaGen by generating variation that covers edge cases, anchor-centric selection by ensuring budget goes to moments that matter, and MoSA by making generated data usable on real robots.

Speeding up execution beyond demonstration speed

A human demonstrates a manipulation task at a comfortable speed because humans are cautious and must avoid dropping things or causing injury, but the robot can often perform the same steps much faster because robots have no safety constraints. If the robot could learn to accelerate, it would complete tasks quicker without sacrificing accuracy because faster execution means more tasks per hour. The challenge is that simply speeding up a trajectory can break the task—if you move a hand too fast while picking up a fragile object, you drop it because the physics change at higher speeds.

Time Optimal Execution of Action Chunk Policies learns to accelerate chunk-based policies (short segments of behavior) while keeping the task constraints satisfied, achieving up to 4 times faster execution on real robots so that the robot stays as fast as possible without breaking anything. LIMMT studies what makes motion tracking data useful for learning: it finds that one high-quality human demonstration beats ten low-quality ones because high quality means the robot learns true patterns while low quality introduces confusion, showing that data quality matters more than quantity when learning from scratch. Translating Flow to Policy bridges video and control by learning from unconstrained video of hands performing tasks, then speeding up the policy through hindsight Online Imitation—a method that replays trajectories and relabels them to match accelerated versions so that slow video becomes a source of fast policies. The three show complementary angles because they operate at different stages: one accelerates learned policies, one emphasizes demonstration quality to learn better, and one learns from diverse video sources and then speeds up.

Learning dynamics and adapting to new environments

A robot learns a task in one environment or from one human's demonstrations, but the real world is constantly shifting—different object weights, friction, object shapes, or even a different robot body. How does the robot detect when it is failing because the policy is bad versus when it is failing because the world has changed? How does it adapt quickly when the world does change? The answer requires learning what aspects of the world matter—building an internal model of how physics works—so the robot can recognize when its model is wrong.

Distinguishing Imitation Error from Intrinsic Motion Learning Difficulty proposes motion trajectory statistics—measures of how wiggly or complex a trajectory is—to separate bad policy learning from tasks that are inherently hard to learn because you need to know which is the real problem before you can fix it, supporting quality control for motion capture data. Dynamics Are Learned, Not Told learns a compressed description of how the world works by observing motion without being told equations, then adapts to severe shifts in physics far better than traditional system identification because the learned representation captures what matters rather than trying to match equations. Policy Imitation using structural patterns of learned representations—how points cluster and organize in the representation space—runs 20 times faster than diffusion policies while staying stable when things are pushed or perturbed because the structure reveals shortcuts. Fine-tuning of Vision-Language-Action Robot Policies combines a pretrained model with a task-specific finetuned model and merges their weights to keep the general abilities while learning new tasks even when the world looks different at test time because merged weights inherit both experts' strengths. Wasserstein Adaptive Control via Meta-Learning trains on many different physics scenarios, then adapts closed-loop policies to unseen physics by measuring how different two physics configurations are in a mathematical sense so that adaptation becomes a continuous process, staying stable across systems with different numbers of motors or constraints. These five all address learning or adapting descriptions of how the world works so the robot can transfer knowledge because understanding the world's structure is what allows transfer.
