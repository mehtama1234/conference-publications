Soft Equivariance Regularization

This page treats the paper as a first-principles answer to a simple problem: self-supervised learning often teaches models to ignore changes, but some changes are exactly what later tasks need.

Core idea

Some changes should vanish. Some should be tracked.

Invariant SSL often says: two augmented views of the same image should have the same representation. That is useful for object identity, but dangerous when the augmentation carries information a later task needs.

If brightness changes, a classifier may not care. If the object shifts right, a detector cares. If the object rotates, a pose task cares. If a video frame moves forward in time, an action model cares. The deep issue is not "make representations invariant." The real issue is choosing which changes to forget and which changes to keep in a controlled way.

invariance: input changes, representation stays same equivariance: input changes, representation changes in a matching way soft equivariance: final feature can be stable, but intermediate features still track useful change

This is why plain invariance is too blunt. It treats too many changes as if they should disappear.

Failure of plain invariance

Invariant learning can throw away the wrong thing

Standard self-supervised image training often creates two views of the same image and pushes their final representations together. That helps classification because the model learns the object is the same despite crop, blur, or color change.

But later tasks may ask different questions. A classifier asks "what is it?" A detector asks "where is it?" A pose model asks "how is it turned?" A segmentation model asks "which pixels belong to it?" If pretraining forced all transformation information to disappear, those later tasks start with a damaged representation.

bad over-invariance: dog left = dog right = dog rotated = dog partly cropped good representation: identity stable, but location/pose/visible parts still recoverable

The paper attacks this exact issue. It does not reject invariance. It says invariance should be paired with a soft memory of how the input changed.

Paper questions

The detailed treatment

1. What raw mess is the paper starting from?

The raw mess is image pretraining with augmentations. A single image gets cropped, shifted, blurred, color-changed, resized, or rotated. These changes mix harmless nuisance with useful structure. The same operation can be harmless for one task and important for another.

2. What hidden structure is the paper trying to recover?

It tries to recover two things at once: stable identity and transformation information. Stable identity says "this is still the same object." Transformation information says "this is how the view changed."

hidden structure = what stayed the same + how the view changed

3. What should stay the same?

The final representation should keep the semantic object stable across harmless changes. A dog should remain a dog under brightness change, small crop, or mild blur. This keeps the usual advantage of invariant self-supervised learning.

4. What should stay different?

The model should not erase information needed for localization, pose, dense prediction, or reasoning about parts. If the object moves right, some internal feature should know it moved right. If the object rotates, some internal feature should know the orientation changed.

5. What should change in a controlled way?

Intermediate features should move with the transformation. If the image shifts right, spatial features should shift right. If it rotates, orientation-sensitive features should rotate or change predictably. The model does not need to print a transformation label; it needs internal features that still carry the change.

6. What shortcut is blocked?

The shortcut is over-forgetting. The model can win the SSL objective by making two augmented views too similar. That helps object classification but can weaken tasks where location, shape, pose, or part layout matter.

How it solves it

Keep final invariance, add soft tracking inside the network

The paper's solve is a split: let the final representation be invariant, but regularize intermediate features so they still respond to transformations in the right way.

Think of the network as layers. Early and middle layers still have spatial detail. Final layers are more compressed. If you only force the final output to match across augmented views, the network may erase transformation information everywhere. Soft equivariance prevents that by adding a second training signal inside the network.

What the extra loss says

If the image is shifted right, the intermediate feature map from the transformed image should look like the original feature map shifted right. If the image is rotated, the intermediate feature should change in a matching way. The model is allowed some flexibility, hence soft. It is not forced into a rigid rule everywhere.

normal SSL loss: final(original) close to final(transformed) soft equivariance loss: middle(transformed image) close to transformed middle(original image)

This is the real mechanism: do not let the final invariant objective erase all transformation information from the whole network. Keep enough of it alive inside the feature hierarchy.

Concrete vectors

A tiny numeric example

Suppose an intermediate feature stores two things: object identity score and horizontal position.

original dog feature: [identity dog = 0.95, x position = 20] dog shifted right by 10 pixels: expected middle feature: [identity dog = 0.95, x position = 30]

Plain invariance might push both features to be identical:

bad over-invariant result: original: [0.95, 20] shifted: [0.95, 20] identity preserved, position lost

Soft equivariance wants this instead:

good soft-equivariant result: original: [0.95, 20] shifted: [0.95, 30] identity preserved, position tracked

The final representation can still hide position if the final task is object identity. But the middle of the network has not destroyed the information. A downstream detector or segmenter can still use it.

Failure cases

What would make this fail?

The transformation is not meaningful.

If a change is random noise, tracking it wastes capacity.

The rule is too rigid.

If the model is forced to track every transformation exactly, it may preserve nuisance details that should be forgotten.

The downstream task truly needs invariance.

If all future tasks only need category labels, preserving pose or location may help less.

The augmentation changes the object.

If a crop removes the dog's head, treating it as the same full object can teach the wrong invariance.

Takeaway

The first-principles line

A good representation should forget harmless changes, but keep track of changes that explain position, pose, motion, or structure.

This is the next conceptual piece after topology-aware learning. Topology asks the model not to tear the learned map. Soft equivariance asks the model not to erase useful change while making the final representation stable.

topology-aware learning: do not tear the map soft equivariance: do not erase the useful motion inside the map
