PlugMem: A Task-Agnostic Plugin Memory Module for LLM Agents

This paper gives agents a reusable memory plugin that stores distilled knowledge instead of long raw histories.

Paper explainersAll themesAgents & Tool Use

An agent that works over many sessions needs long-term memory, but raw logs become too large and too unfocused. This paper studies a memory module that stores compact pieces of reusable knowledge rather than copying full trajectories back into context on every task.

Zero assumption version

Raw memory logs grow fast and return too much irrelevant detail

A long-lived agent can remember every conversation, tool trace, and web trajectory, but replaying all that text on later tasks floods the context with detail that does not matter. The agent then spends effort on irrelevant history instead of the few facts and rules that the current task actually needs.

Task-specific memory systems avoid some clutter, yet they do so by baking in assumptions about one benchmark or one task family. The paper asks for a memory design that stays reusable across tasks while still retrieving information that is sharply tied to the current decision.

The idea in one sentence. Store compact actionable knowledge instead of full raw histories, because later tasks usually need the lesson from an experience rather than the whole transcript.

The algorithm as a flow

What it actually does

Observe an experience

Take a trajectory from conversation, retrieval, or web action.

Extract reusable knowledge

Turn that trajectory into factual statements and action rules so that the lesson is separated from the full raw transcript.

Store linked knowledge items

Place those knowledge items into a structured memory graph so that related facts and rules can be reached together.

Retrieve by current task need

Pull back only the small subset of knowledge that matches the present task.

Reason with the retrieved memory

Use the distilled items to guide the next action or answer.

What the paper changes

What the paper changes

The paper changes the unit of memory access. Instead of retrieving long raw episodes, it retrieves distilled knowledge items that summarize what the agent should carry forward.

the object it moves  =  the memory unit returned to the agent
The hidden quantity

The hidden quantity: information density of retrieved memory

measured quantity  =  how much task-relevant guidance is contained in each returned unit of memory

The paper focuses on information density: how much useful guidance a returned memory item carries relative to its size. A raw transcript may contain the right lesson, but it also contains greetings, dead ends, and other local detail.

High information density matters because the agent has limited context space. If each retrieved item carries more decision value, the agent can see the useful lesson without dragging in the rest of the past session.

Why it works

Why knowledge-centric memory can work

A knowledge-centric memory can work because most later decisions do not need a full replay of the past. They need the retained fact, the useful caution, or the action rule that past experience revealed. Distilling memory into those units makes retrieval more selective.

The linked memory structure also matters because facts and rules often support each other. A rule such as 'check account region before billing changes' is more useful when it is connected to the fact that region settings are stored in a specific page. Returning linked items can give the agent a tighter decision packet than a flat raw history would.

Math after the picture

The core equation

First in words:

Memory usefulness rises when the returned content carries more task-relevant guidance per unit of context space.

Then the compact form:

memory_value = relevant_guidance / context_space

Every symbol:

memory_valuehow useful the retrieved memory is for the current task
relevant_guidancethe amount of factual or procedural help the returned memory provides
context_spacehow much room the returned memory occupies in the prompt
A tiny worked example
Suppose a raw trajectory uses 100 lines of context and only 10 of those lines directly guide the current task.
Under this rough view, its memory_value is 10 divided by 100, which is 0.10.
Suppose a distilled memory packet uses 20 lines and still carries those same 10 useful guidance lines.
Then memory_value is 10 divided by 20, which is 0.50.
The example shows why distillation matters because the same guidance becomes much easier to reuse when the extra history is removed.

This ratio is a teaching device. The paper's real message is that compact retrieved knowledge can outperform long raw replay because it carries the needed lesson without the surrounding clutter.

What can go wrong

What can go wrong

The distillation step throws away a needed detail. If a memory rule omits the page condition that made the rule valid, the agent may reuse the lesson in the wrong situation.
The memory store becomes too abstract. If all experience is compressed into vague rules, the agent may lose the concrete facts needed to apply those rules correctly.
Retrieval links pull in the wrong neighbors. A linked memory structure can still add clutter if the related items are only loosely connected to the current task.
Done right. The method works when each stored item keeps the concrete fact or rule that will matter later and retrieval remains narrow enough to fit the current decision.
What a runnable demo should prove

What a runnable demo should prove

Build an agent that handles several task families, such as long conversation support, multi-step retrieval, and web action tasks. Compare two memory systems: one that retrieves raw past episodes and one that retrieves distilled knowledge items. Measure context length, accuracy on repeated tasks, and transfer to a new task family that still shares some underlying facts or action rules.

The demo proves the paper's point if the distilled memory system matches or exceeds task success with less retrieved context, because the returned memory carries more relevant guidance per unit of prompt space.

density_gain = memory_value(distilled_memory) - memory_value(raw_episode_memory)

A strong demo should include one task where the useful lesson is buried inside a long old transcript, because that is the situation this memory design is meant to fix.
