Interference-Isolated Elastic Weight Consolidation for Incremental Object Detection

Identify which weights are fighting each other when learning new object classes, and pin down the specific weights that matter most, so the model can learn without forgetting.

Paper explainersAll themesComputer Vision

When a detector learns a new class of objects, the weights that recognize old classes can get pushed around by accident. In a single image, there are usually old objects, new objects, and some things the model has never seen before—but the model only has labels for the new objects. This creates conflicts. The paper measures exactly which weights are causing trouble and locks them down during learning, plus it recalibrates the memory of old classes so it does not drift.

Zero assumption version

The conflict problem in learning new object classes

When a detector learns to recognize new object classes, the weights (numbers inside the model) that were already trained for old classes often get dragged along and changed by mistake. This is called catastrophic forgetting. The model forgets how to detect the old classes while learning the new ones.

Here is why it happens: in any real image, there are objects from old classes, new classes, and things the model has never seen before. But the training data only labels the new objects. The unlabeled old objects look like background to the training process. When the model trains on the new task, it treats those unlabeled old objects as if they are nothing, so it nudges weights in ways that ruin the old detection ability.

A naive fix—protect all the weights equally—does not work. Some weights are far more important to the old knowledge than others. Protecting the unimportant ones wastes effort and still lets important weights shift.

In one sentence. The model learns new classes but mistakes old unlabeled objects for background, causing it to scramble the weights that matter most for detecting old classes.

The algorithm as a flow

What it actually does

Step 1: Spot the conflicts

Run the old detector on new task images. It will mispred the unlabeled old objects. Track which weights caused those wrong guesses.

Step 2: Measure each weight's importance to old classes

For every weight, calculate how much changing it damages the old detector's ability on old task data. This is like asking each weight how fragile is my knowledge?

Step 3: Build the conflict score

Combine the mispredictions and the weight importance. Weights that are both important to the old task AND involved in conflicts get a high conflict score.

Step 4: Penalize moving the conflict weights

During training on the new task, add a penalty that grows when conflict weights move. Unimportant weights can move freely, but important conflict weights are locked down.

Step 5: Recalibrate the classifier memory

The classifier head (the final decision layer) has memories of old classes called prototypes. These drift when new data arrives. Repoint them to stay close to the original class patterns while accepting the new task.

What the paper changes

The single thing that changes: per-weight protection strength

The paper does not protect all weights equally. Instead, it assigns each weight a personalized protection strength based on two things: how important is that weight to the old task, and is it involved in conflicts when the new task arrives. Weights that matter a lot and cause conflicts get locked down hard. Weights that are unimportant get left free to move.

The hidden quantity

The hidden quantity: which weights are causing trouble

measured quantity  =  Conflict weight score

The paper measures a single number for each weight: the conflict weight score. This number says how much trouble that weight is in. A high score means the weight is both important to remembering the old classes and is getting pulled in the wrong direction by the new task data.

The paper estimates this by looking at two things: first, it runs the old detector on the new task images and sees which weights cause it to mispred the unlabeled old objects. Second, it measures how fragile each weight is to the old knowledge (using the Fisher information matrix—a standard way to measure how sensitive the old detector is to each weight). A weight that is both fragile and mispredicting gets a high conflict score.

Why it works

Why it works: targeted lock-and-recalibrate

The core insight is that not all weights are equal. Some weights are carrying the core knowledge of old classes, and changing them even a little destroys that knowledge. Other weights are peripheral and can move without harm. By measuring which weights are actually fragile (using Fisher information—a standard way to ask how sensitive the model is to each weight), the paper knows exactly what to protect.

When the model trains on the new task, it will naturally try to nudge weights to improve on new data, because training algorithms move weights in the direction that reduces the training loss. The paper adds a penalty that says: if you move a weight with a high conflict score, the penalty is huge and bad; if you move a weight with a low conflict score, there is barely any penalty. This way, the new task learning is free to reshape unimportant weights but cannot touch the fragile ones. The model learns the new classes by changing only the weights it can afford to change, because the penalty makes moving fragile weights more expensive than improving on new data.

The second part—prototype recalibration—fixes a different leak. The classifier head stores a memory of each old class (a prototype, which is like a sample of what the class usually looks like). When you train on new data, the decision boundaries shift and that prototype drifts away from the real pattern. The paper learns a small correction layer that keeps the prototype pointed at the true old class pattern even while the classifier is being retrained. This is like moving a portrait to stay centered on the wall when the wall is being repainted.

Math after the picture

The equation: weighted penalty for moving conflict weights

First in words:

The training loss is the new task loss plus a penalty that is proportional to how much each weight moves, scaled by its conflict importance score.

Then the compact form:

loss_total = loss_new_task + lambda * sum_i C_i * (theta_i - theta_old_i)^2

Every symbol:

loss_new_taskhow well the model predicts on the new task images
lambdahow strong the penalty is overall (a tuning knob)
C_ithe conflict score for weight i (high if fragile and mispredicting)
theta_ithe current value of weight i during training
theta_old_ithe saved value of weight i before the new task started
(theta_i - theta_old_i)^2how far the weight has moved from its old value
A tiny worked example
Suppose lambda = 0.5, and we have two weights.
Weight w1: conflict score = 8 (fragile, mispredicting). Old value = 5.0, current value = 5.4 (moved 0.4).
Penalty for w1 = 0.5 * 8 * 0.4^2 = 0.5 * 8 * 0.16 = 0.64.
Weight w2: conflict score = 0.2 (unimportant). Old value = 3.0, current value = 2.2 (moved 0.8, twice as far).
Penalty for w2 = 0.5 * 0.2 * 0.8^2 = 0.5 * 0.2 * 0.64 = 0.064.
Even though w2 moved twice as far, the penalty is only 1/10 of w1's penalty. Training protects w1 and lets w2 move freely.

The conflict score (the per-weight measure) is the lever: a weight with high conflict score is pinned down by the squared-movement penalty, while a weight with low conflict score can shift without cost.

What can go wrong

What can go wrong

Conflict score is guessed wrong. If the old detector does not mispred the unlabeled old objects much on the new task images, the conflict score will be too low and important weights will not be protected enough. This happens when the new and old classes are visually very different (e.g., outdoor vs indoor scenes).
Protection is too strong. If lambda is set too high, the model cannot learn the new class well because all weights are locked down. The new task accuracy drops even though old knowledge is safe.
Prototypes shift out of reach. If the new class is so different that the old classifier head rotates far from its original orientation, the recalibration layer cannot bring the prototypes back in time. The old class decision boundary drifts too far.
Done right. The paper measures conflicts from real mispredictions, tunes lambda carefully, and uses a learnable projection in the calibration layer to adapt the prototypes. This gives a real balance: new classes learn, old classes survive.
What a runnable demo should prove

What a runnable demo should prove

Build a simple detector (even a pretrained small model) on a standard benchmark like PASCAL VOC. Train it on object classes 1–5. Then add classes 6–10 using only images of classes 6–10, but include images that happen to have objects from classes 1–5 unlabeled in them. Measure: before adding new classes, what is the model's accuracy on class 1–5? After adding new classes, what is the accuracy on class 1–5? Also measure accuracy on the new classes 6–10. Compare to a naive fine-tuning baseline (train on new classes with no protection) and to a baseline that locks down all weights equally (standard Elastic Weight Consolidation).

forgetting = accuracy_old_before - accuracy_old_after; learning_gain = accuracy_new; target: minimize forgetting while keeping learning_gain high.

The demo must show that IKI-EWC achieves much smaller forgetting than naive fine-tuning because it protects only the weights that matter most, and better learning_gain than standard EWC because it lets unimportant weights move freely. The conflict score is doing real work.
