Learning for Highly Faithful Explainability

Train a single explainer network once, then use it to explain many different models faithfully by combining self-supervised learning and high-quality prior explanations.

Paper explainersAll themesInterpretability

When you ask a machine learning model why it made a decision, you need the answer to be honest—actually tracing what the model really did, not just a plausible story. This paper shows how to train one explainer network that can generate trustworthy explanations for any target model, by learning from both unlabeled data and from existing explanation methods.

Zero assumption version

Existing explanations are slow, inconsistent, or unreliable

When you want to understand what a neural network (a mathematical system that learns patterns from data) is doing, you usually run a separate explanation algorithm on top of it. But existing methods hit a wall: if you rely only on unlabeled patterns in your data, you make hidden assumptions about the model you are trying to explain, so your method fails when you move to a different model or task. If you rely on prior explanations (answers from other explanation methods applied to the same model) from other methods, those prior methods might be wrong, giving you garbage in and garbage out. And if you try to combine both, the training becomes slow and unstable.

A beginner would try to just apply one explanation method to all models—but that method is usually designed for a specific kind of model, and breaks when the model changes.

The core idea. Train a single explainer network once using both self-supervised learning (finding patterns in data without labels) and high-quality supervised signals (using filtered prior explanations), then apply it to any model.

The algorithm as a flow

What it actually does

Step 1: Gather prior explanations

Run existing explanation methods on your target model to get candidate explanations.

Step 2: Filter for quality

Measure each candidate against faithfulness metrics and remove the unreliable ones.

Step 3: Derive self-supervised objective

Use mathematical theory to define what patterns the explainer should learn without assuming anything about the target model.

Step 4: Joint optimization

Train the explainer by learning both the filtered prior patterns and the self-supervised patterns, starting with stronger weight on the prior and gradually shifting to refinement.

Step 5: Deploy

The trained explainer can now explain any target model or task without retraining.

What the paper changes

What the paper moves

The paper redesigns the learning objective for an amortized explainer (a single network trained to explain many models). It combines two previously separate ideas: self-supervised signals from unlabeled data patterns and supervised signals from filtered prior explanations, with a dynamic weighting scheme that shifts emphasis as training progresses.

the object it moves  =  explainer training objective
The hidden quantity

Faithfulness: how honestly does the explanation trace the model's real logic?

measured quantity  =  Faithfulness (match between explanation output and model's actual decision process)

Faithfulness is a single number measuring whether the explanation actually shows what the model is computing, or whether it is just a plausible story. A faithful explanation follows the model's real logic; an unfaithful one might sound reasonable but does not trace the actual decision path. The paper proves that this quantity can be measured the same way across multiple different metrics—meaning all the standard tests for explainer honesty converge to the same answer.

The paper estimates faithfulness by running multiple standard evaluation tests (dropping explanation features and watching the model's confidence change; perturbing inputs and measuring if the explanation predicts the change) and aggregating the results.

Why it works

Why the two-signal approach produces faithful explanations

Self-supervised learning alone would have to guess what makes a good explanation without being told, leading to explanations that might capture surface patterns but miss the model's real logic. Prior explanations alone carry the risk that the existing methods are all wrong, so you are just copying mistakes. By combining both, the explainer network learns the shape of a good explanation from existing methods while also learning from patterns in the data, and the dynamic weighting ensures it spends time on each signal appropriately.

Here is the key: early in training, strong weight on the filtered prior signals (from existing trusted methods) gives the explainer a head start—it immediately learns what good explanations look like. Once it has that shape, the self-supervised objective takes over more weight, refining the explanation to be truly faithful by learning how real data patterns predict model behavior. This two-stage approach avoids both the slow convergence (starting from scratch) and the ceiling effect (staying stuck on what prior methods knew).

Math after the picture

The combined learning objective

First in words:

total loss = (weight_prior times supervised loss) plus (weight_self times self-supervised loss), where the weights shift over training.

Then the compact form:

L_total(t) = w_p(t) * L_sup + w_s(t) * L_self, where w_p(t) + w_s(t) = 1

Every symbol:

L_supsupervised loss (how much the explainer matches filtered prior explanations)
L_selfself-supervised loss (how well explanation predicts model behavior on perturbed inputs)
w_p(t)weight on supervised loss at training step t (high at start, decays over time)
w_s(t)weight on self-supervised loss at training step t (low at start, grows over time)
ttraining step
A tiny worked example
At step 1: w_p = 0.9, w_s = 0.1. If L_sup = 0.2 and L_self = 0.5, then L_total = 0.9 * 0.2 + 0.1 * 0.5 = 0.18 + 0.05 = 0.23. The supervised signal dominates.
At step 100: w_p = 0.2, w_s = 0.8. Same losses: L_total = 0.2 * 0.2 + 0.8 * 0.5 = 0.04 + 0.40 = 0.44. Now the self-supervised refinement dominates.
The explainer initially learns the shape of good explanations from prior methods, then shifts to learning what actually makes explanations faithful to the model.

The dynamic weighting ensures the explainer gets a structured starting point from prior methods, then refines itself via self-supervised learning.

What can go wrong

What can go wrong

Prior explanations are all poor quality. If all existing explanation methods are unreliable (e.g., they were designed for a different kind of model), filtering will discard most of them, leaving weak supervised signals. The explainer then relies mostly on self-supervised learning and may not converge well.
Self-supervised objective is poorly designed. If the self-supervised loss does not align with what faithfulness actually means in this specific task, the explainer will optimize the wrong thing. The paper derives the self-supervised objective theoretically to avoid this, but in practice, task mismatches can still hurt.
Dynamic weighting schedule is wrong. If the transition from prior-heavy to self-supervised-heavy happens too fast, the explainer loses structure before it has learned to refine. If it is too slow, training wastes time on the prior signals after they have already been absorbed.
Done right. If the prior explanations are reasonably diverse, the self-supervised objective is aligned with true faithfulness, and the weighting schedule is tuned for the task, the method scales to any model and task without retraining.
What a runnable demo should prove

What a runnable demo should prove

Build a simple explainer on a interpretable target model (e.g., a small decision tree or logistic regression on the Iris flower dataset with four numeric features: sepal length, sepal width, petal length, petal width). Implement three prior explanation methods: a gradient-based method, a perturbation-based method, and a simple rule-based method. Deduplicate and filter them. Train your amortized explainer on both the filtered priors and a self-supervised objective (e.g., prediction error when perturbing inputs). Run the trained explainer on a second, different target model (e.g., a small neural network). Measure faithfulness by comparing the explanation's feature importances to the actual model weights or to the true data correlation structure.

faithfulness_score = (1 - average_ranking_correlation_error) across all test samples, where the error is how much the explanation's feature ranks differ from the model's true decision path.

The demo must show that the single trained explainer achieves higher faithfulness on the second model than any individual prior method, proving that learning from both signals transfers across models.
