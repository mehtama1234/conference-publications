AgentSteerTTS: Multi-Agent Closed-Loop Control for Expressive Speech

Multiple specialized agents coordinate to turn written instructions into precise control over voice pitch, emotion, and timing in synthesized speech.

Paper explainersAll themesAgents & Tool Use

Text-to-speech models (software that turns written words into spoken audio) can generate very expressive speech, but telling the model exactly what emotion or pacing you want is hard. The problem: a person writes instructions in plain words, but the model needs precise acoustic numbers. This paper introduces AgentSteerTTS, a multi-agent system that solves this gap by having one agent listen to example voices in a library, a second agent blend those examples together, and a third agent refine the result until the speech matches what was requested.

Zero assumption version

Why control is stuck

Text-to-speech models take in text and produce audio. If you write 'say this angrily,' the model has no clear path from that word to the actual numbers it needs (like how high to pitch the voice, how fast to talk, which frequencies to emphasize). A beginner's first try is to add more descriptive words ('very angry, fast, low pitch'), but more words do not map clearly to acoustic numbers either. The core gap: words are discrete symbols, but audio is continuous numbers. A model trained on 'angry' examples can only repeat what it saw before, not create new shades of emotion or timing on demand.

Existing systems try to ignore this gap and train an end-to-end model that somehow maps text instructions to audio. But that approach forces one big neural network to learn every instruction pattern simultaneously, which leads to leakage: the model may mix emotions (a sad voice bleeding into an angry one) because it has learned to compress speaker traits and emotion traits into overlapping internal features. When the network is forced to generate multiple emotion types from a single speaker, the internal representations get tangled together, and the model cannot keep them separate.

The paper's fix: Use a retrieval agent to find reference voices, a synthesis agent to blend them, and a feedback agent to correct mismatches between what was requested and what was generated.

The algorithm as a flow

What it actually does

Separate speaker from emotion

Adversarial training forces the model to learn speaker identity (voice type) separately from emotional content, so they don't bleed together.

Retrieve reference voices

A retrieval agent searches a library of recorded examples and picks a few whose acoustic properties match the requested instruction.

Blend anchors into control

A synthesis agent takes the retrieved examples and learns a weighted mix that produces a smooth control signal matching the intent.

Generate speech from blended control

The TTS model uses the blended control signal to synthesize new audio that is consistent with the combined instruction.

Refine through feedback

A feedback agent listens to the generated speech, detects mismatches, and adjusts the control signal in the next iteration.

What the paper changes

What the paper changes

The paper introduces a set of learned control vectors (lists of numbers) that bridge the gap between text instructions and acoustic output. Instead of trying to train a single model to handle all instructions at once, the system learns to assemble control vectors on the fly by retrieving and blending reference examples. This object—the control vector—is what AgentSteerTTS changes and refines.

the object it moves  =  control vector
The hidden quantity

The instruction fidelity score

measured quantity  =  instruction fidelity

Instruction fidelity is a measure of how well the generated speech matches what was written. It answers: does the synthesized voice actually sound angry when the instruction says 'angry'? Does it slow down when told 'slow'? The paper estimates this by having a perceptual model (a small neural network trained to recognize emotions and speech rates) listen to the output and score how closely it matches the requested instruction.

The feedback agent uses this score to adjust the control vector: if fidelity is low (the voice does not sound as requested), it nudges the control vector in the direction that would increase fidelity. This is a concrete, measurable quantity that guides the entire loop.

Why it works

Why blending anchors works

Instead of training a single huge model to learn all instruction patterns at once (which forces it to mix speaker and emotion information), AgentSteerTTS breaks the problem into stages. First, speaker identity is separated from emotion using adversarial training—a technique that adds an extra loss (a penalty on the training goal) that punishes the model if it leaks speaker information into the emotion signal. This forces the learned representations to be cleaner.

Second, the retrieval agent acts as a searchable library: it searches through real reference voices and returns a few examples that are close in acoustic space to what the instruction asks for. These are the anchors. Then the synthesis agent learns to blend the anchors together using soft weights (a learned gating mechanism that decides which parts of each anchor to use). This two-stage approach (retrieve, then blend) is much simpler than training one model to handle all instructions.

Third, the feedback agent closes the loop. It generates speech using the blended control signal, listens to it, measures fidelity, and adjusts the control vector accordingly. Because the adjustment happens in the internal representation (not raw audio), the corrections are stable and predictable. This feedback loop makes instruction-following reliable: mismatches are detected and corrected in real time.

The blending equation

First in words:

The control vector is a weighted sum of anchor vectors, where weights are learned and constrained to be positive and sum to one. The feedback agent nudges the weights whenever fidelity is low.

Then the compact form:

c = sum_j w_j * a_j + delta_c where sum_j w_j = 1, w_j >= 0

Every symbol:

cthe final control vector (list of numbers)
w_jthe learned weight for anchor j (how much to use it)
a_jthe acoustic vector of anchor j (retrieved from the library)
delta_cthe correction from the feedback agent
A tiny worked example
Suppose we retrieve two anchors: angry-voice-1 (a_1) and fast-speech-1 (a_2).
Synthesis learns: w_1 = 0.6, w_2 = 0.4 (sum to 1).
Blended control: c = 0.6 * a_1 + 0.4 * a_2.
Generated speech is measured. Fidelity = 0.72 (72% correct emotion detected).
Feedback agent adds delta_c = +0.08 to increase anger component.
Next iteration: c = 0.6 * a_1 + 0.4 * a_2 + 0.08, fidelity rises to 0.85.

The weights stay between 0 and 1 and always sum to 1, so the blended control is always a smooth interpolation between anchors, not an arbitrary mix.

What can go wrong

What can go wrong

Anchor library is too small. If the retrieval agent only has a few reference voices to choose from, the blended control vector may not cover the full range of possible emotions or speech rates. The fix: build the library with diverse speakers and emotional styles.
Feedback agent oscillates. If the feedback adjustment step is too aggressive (adding too much delta_c per iteration), the control signal can bounce back and forth instead of converging. The fix: use a smaller step size for adjustments and gradual convergence.
Retrieval agent returns irrelevant anchors. If the search in the library is not well-tuned, the agent might pick reference voices that sound nothing like the instruction. The fix: train the retrieval scoring function on pairs of instructions and relevant anchors.
Done right. With a good anchor library, stable feedback adjustments, and a well-trained retrieval scorer, the system learns to produce speech that reliably matches the written instruction, including combinations of emotion and pacing that were not in the training set.
What a runnable demo should prove

What a runnable demo should prove

Build a simple text-to-speech system with a small anchor library (e.g., 10 recorded voices with 3 emotional styles each: neutral, angry, sad). Then write a text instruction ('say this sadly') and measure how well the generated speech matches the instruction (using an emotion classifier). Next, disable the feedback agent and measure again. The demo should show that with the feedback loop, fidelity is higher (more consistent matches), and without it, the blend drifts.

fidelity = (emotion_of_generated == emotion_requested) * (prosody_error < threshold)

The demo proves that the feedback loop is essential: without it, even the best blended anchors produce inconsistent results because mismatches accumulate. With it, the system self-corrects.
