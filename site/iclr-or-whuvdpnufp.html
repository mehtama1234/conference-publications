xRFM: Feature learning for rows of numbers

xRFM learns useful patterns from tabular data by combining local feature extraction with a tree that picks the right pattern for each row.

Paper explainersAll themesOther

When you have data organized in rows and columns (like a spreadsheet of patient ages, test scores, and diagnoses), older methods like gradient boosted decision trees (which build forests of if-then rules) still work best. xRFM is a new approach that learns feature patterns from the data itself, adapts those patterns locally to each row's neighborhood, and combines them with a tree structure—all while running quickly on huge datasets.

Zero assumption version

Tabular data is stuck with an old recipe

Most data in science and business lives as tables: columns like age, income, disease present; rows like individual people. Predicting from this data has worked roughly the same way for decades—gradient boosted decision trees (a method that stacks hundreds of if-then rules trained one after another).

Meanwhile, every other corner of AI got transformed. Language models learned word patterns. Image models learned shape patterns. But tabular data methods have barely changed. Newer neural network approaches tried to learn patterns from tables, but they are either slow on large datasets or do not beat the old tree-based methods.

The problem is that the best tree-based methods just split the data into buckets and average the rows in each bucket. They do not learn any detailed patterns from the relationships between columns—they just use the raw column values.

The core challenge: How to learn detailed feature patterns from tabular data while staying fast enough for huge datasets and beating tree-based methods?

The algorithm as a flow

What it actually does

Learn features

Extract useful column combinations from training data via a kernel machine (a method that finds detailed patterns without guessing a model shape ahead of time).

Build a tree

Split rows into groups based on their column values, one split per level, building a decision tree.

Assign features to tree leaves

For each leaf (a group of similar rows), learn which of the extracted features matter most.

Adapt locally per row

For each row, use its neighbors in the tree leaf to adjust the learned feature weights up or down slightly.

Combine and predict

Use the tree path plus the locally adapted features to make the final prediction.

What the paper changes

What the paper changes

Instead of letting columns be used raw, xRFM learns a kernel (a transformation that finds hidden patterns from pairs of column values). Those learned patterns become the features. The tree then picks which learned patterns to use for each row's neighborhood.

the object it moves  =  learned feature patterns
The hidden quantity

The hidden quantity: Average Gradient Outer Product

measured quantity  =  importance of each learned feature

xRFM measures which learned features matter most by looking at the Average Gradient Outer Product (AGOP)—a quantity that captures how much each learned feature changes when the answer changes. High AGOP means the feature is doing real work; low AGOP means it is mostly inactive.

The paper computes this by checking the direction the model wants to nudge each learned feature. If nudges on the same feature keep pointing the same way across many rows, that feature is important. If nudges scatter in all directions, that feature is not really used.

Why it works

Why it works: trees pick, kernels learn, local adaptation fits

The insight is that real-world tabular data has structure: some rows are similar to each other, and those similar rows probably need similar feature patterns. A tree finds that structure naturally by grouping similar rows. Within each group, a learned kernel can extract exactly the patterns those rows need, because the kernel is freed from having to fit all rows at once.

The kernel learns feature patterns by finding combinations of columns that have strong relationships to the answer. Instead of guessing that, say, age and income interact, the kernel discovers automatically which combinations matter. Then, for each row, the method uses a local kernel (also called a local regression or Nadaraya-Watson smoothing) to adapt those learned patterns to the row's specific neighborhood. If a row is surrounded by very sick people, the learned feature patterns get adjusted to emphasize the health signals; if surrounded by higher-income people, income matters more. This two-stage process—learn global patterns, then adapt locally—uses the data efficiently because the learned patterns act as a shared foundation, not reinvented per row.

The tree structure keeps everything scalable: instead of storing one model for all rows, the method stores one set of learned patterns per tree leaf, and the tree routing is fast (just a sequence of comparisons).

Math after the picture

The core equation

First in words:

Prediction equals the learned features evaluated on this row, plus local weights adjusted based on how similar nearby rows are, filtered by the importance of each learned feature.

Then the compact form:

y_pred = sum_j f_j(x) * w_j * k(x, x_train_neighbor) / sum_i k(x, x_train_i)

Every symbol:

f_j(x)the j-th learned feature (a learned pattern) evaluated on row x
w_jimportance weight for the j-th learned feature in this tree leaf
k(x, x_neighbor)kernel (similarity measure) between this row and a nearby training row
x_train_neighbora training row from the same tree leaf, used as a reference
sum_i k(x, x_train_i)normalizes so the weights sum to 1
A tiny worked example
Say a row has x = (age=45, income=60k), and two training neighbors in its leaf have k(x, neighbor1) = 0.8 and k(x, neighbor2) = 0.2.
Learned feature f_1 = age * income interaction = 45 * 60 = 2700. Learned feature f_2 = just income = 60.
In this leaf, w_1 = 0.9 (age-income interaction is important), w_2 = 0.3 (income alone is less important).
Prediction = (2700 * 0.9 * 0.8 + 2700 * 0.9 * 0.2 + 60 * 0.3 * 0.8 + 60 * 0.3 * 0.2) / (0.8 + 0.2) = (1944 + 486 + 14.4 + 3.6) / 1.0 = 2448.
The kernel smoothing weighted the nearby rows; the importance weights emphasized the interaction feature.

The equation layers three ideas: learned features (which columns combine), tree-local importance weights (which patterns matter in this region), and local kernel smoothing (which neighbors steer the adjustment).

What can go wrong

What can go wrong

High-dimensional tables with many columns. When the number of columns is very large, the kernel learning step (finding which column combinations matter) becomes expensive. The tree must be very deep to separate all that variation, and local adaptation may not find the right neighbors.
Tables with mostly categorical columns. The kernel is designed for continuous columns. Categorical columns must be converted (encoded as numbers) first, and the kernel may not find the right combinations of categories as easily as combinations of continuous values.
Tiny datasets or very imbalanced rows. Local kernel adaptation needs enough neighbors to estimate weights stably. With few rows or heavily skewed groups, the local adaptation may overfit or adjust in the wrong direction.
Done right: many moderate-dimensional tables with mixed continuous and categorical columns and enough rows per group. xRFM shines when there are thousands to millions of rows, dozens of columns, and natural groupings that a tree can uncover.
What a runnable demo should prove

What a runnable demo should prove

Build a dataset with a thousand rows, ten continuous columns, and a target that depends on learned feature combinations (e.g., the answer is high when (age times income) plus (test score) is large, but different subgroups weight those differently). Split into train and test. Run xRFM: grow a tree, learn the features, fit local kernels, make predictions. For comparison, also run a standard decision tree and show that xRFM beats it on held-out accuracy and that the learned feature importance (from AGOP) matches the actual features you built the target from.
