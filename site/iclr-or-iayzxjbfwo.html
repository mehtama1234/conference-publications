Rolling Forcing: Streaming Long Video Without Error Creep

Instead of cleaning frames one at a time in sequence, clean a short stack of them together so mistakes do not pile up over minutes of video.

Paper explainersAll themesGenerative Models & Diffusion

Video diffusion models generate movies by starting with pure noise and gradually cleaning it frame by frame. But when you ask the model to generate long videos in a streaming way—frame after frame, relying on the previous output—small mistakes compound like sand building a dune. Rolling Forcing fixes this by cleaning multiple frames at once as a unit, with a memory anchor to keep the whole video consistent, all trained to bridge the gap between how it learns and how it runs.

Zero assumption version

Frame-by-frame generation breaks over long sequences

Video diffusion models work by taking pure noise and cleaning it iteratively to form a video. At each step, the model looks at partially-cleaned frames and decides what they should look like next.

When making short 5-second clips, this works fine. But for streaming—generating minute-long videos frame after frame—each mistake gets baked in. The model's next prediction depends on its own previous output, not the ground truth. A small blur here, a tiny color shift there, and after 30 seconds the video is completely off the rails.

Predicting far into the future this way is called the exposure bias problem: during training the model sees perfect frames, but at runtime it sees its own imperfect attempts.

The naive approach: Clean one frame at a time, in sequence, each depending on the last. Mistakes accumulate exponentially.

The algorithm as a flow

What it actually does

Bundle the next N frames

Group 8-27 consecutive frames into one processing window.

Assign noise levels

First frame starts almost clean; last frame starts more noisy. Noise level increases.

Denoise jointly

The model cleans them all at once, letting frames influence each other's decisions.

Keep history anchor

First frames from all previous windows are stored and kept as global context.

Slide forward

Move to the next window, using the cleaned frames as the new anchor.

What the paper changes

What the paper changes

Traditional video diffusion asks the model to predict one frame conditioned on the previous clean frame. Rolling Forcing changes that: it asks the model to predict 8-27 frames simultaneously, where each frame has a different level of noise baked in—the first is nearly clean, the last is quite noisy.

The hidden quantity

Quality drift: how far the video wanders

measured quantity  =  Quality drift over time

As the video plays, each error cascades forward. Quality drift is a single number measuring how much the picture quality changes from the start (the first 5 seconds) to far into the video (the last 5 seconds). It is calculated by measuring the sharpness, color accuracy, and consistency of the images at the beginning versus the end—computing the absolute difference.

Rolling Forcing measures this by comparing the first 5 seconds of generated video (which the model sees during training) to the final 5 seconds (deep in the streaming process where mistakes have piled up). The attention sink mechanism specifically protects this: by keeping the early frames as a permanent memory anchor, the model can steer corrections all the way through minute-long videos.

Why it works

Why rolling windows stop error from growing

If you denoise 27 frames together instead of one-by-one, the model has 27 chances to fix small drifts instead of only 1. Here is the causal chain:

First, denoising multiple frames jointly relaxes the strict causality. Instead of frame i+1 depending only on frame i's final output, all 27 frames influence each other during cleaning. This spreads correction work across the entire group, so no one frame shoulders the full weight of a previous mistake.

Second, the attention sink (an anchor memory mechanism) keeps the first frames of every earlier window in a shared cache. When the model is generating frame 100, it can still see and attend to frames 1-8, which were verified during training. This is like keeping a reliable reference photo in view while painting the rest of the mural. The model can steer toward this anchor.

Third, the training strategy addresses the exposure bias directly. During training, the model learns on self-generated histories (previous predictions from the model itself, not ground truth). This means at training time it is already seeing the compounding errors it will face at test time, so it learns to correct them proactively.

Math after the picture

The joint denoising equation

First in words:

For each frame in the window, we add noise incrementally and denoise jointly, conditioned on prior clean frames.

Then the compact form:

x_i^{t_j} = (1 - sqrt(alpha_j)) * x_i^{0} + sqrt(alpha_j) * epsilon, i = 1..N, alpha_0 < alpha_1 < ... < alpha_N

Every symbol:

x_i^{0}the final clean prediction for frame i
x_i^{t_j}the noisy version of frame i at denoising step j
alpha_jthe noise level at step j (higher alpha = more noise)
Nthe window size (8 to 27 frames)
epsilonadded Gaussian noise
A tiny worked example
Suppose window size = 3 frames, denoising step = 1.
Frame 1: alpha_1 = 0.1 (mostly clean). Noise added = 0.1 * 0.3 = 0.03. Result is 97% clean.
Frame 2: alpha_2 = 0.5 (halfway). Noise added = 0.5 * 0.3 = 0.15. Result is 70% clean.
Frame 3: alpha_3 = 0.9 (mostly noisy). Noise added = 0.9 * 0.3 = 0.27. Result is 27% clean, 73% noise.
The model then denoises all three frames jointly, seeing all three as context, so it can spread corrections across them.

Progressive noise creates increasing difficulty across the window; bidirectional attention within the window lets the model use all frames to fix each one.

What can go wrong

What can go wrong

Window size mismatch at training vs. test time. If the model trains on 8-frame windows but you try to generate 27-frame windows, the patterns for how frames influence each other are wrong and quality degrades. The model must be trained on the exact window size you plan to run.
Anchor frames forgotten. If the key-value cache storing the early frames is not properly maintained across windows (or too many frames are dropped), the global context signal fades and drift returns.
Exposure bias still present if training data is clean. If the model is trained with ground-truth histories instead of self-generated ones, the train-test gap persists. The mixed training strategy (alternating self-forced and ground-truth conditioning) is essential.
Done right. Train on non-overlapping windows with self-generated histories, keep the first frames of every window cached as global context, and run generation (test time) with the exact same window size and progressive noise schedule. Quality stays flat across multi-minute videos.
What a runnable demo should prove

What a runnable demo should prove

Start with a pretrained video diffusion model (e.g., Wan 2.1, a public open-source baseline). Implement Rolling Forcing inference: define a window size (16 frames is reasonable), set up the progressive noise schedule, and cache the key-value states of the first frame globally. Generate a 2-minute video by sliding the window multiple times. At each window, measure the perceptual quality (using LPIPS or SSIM comparing to a reference) of the frames. Plot quality over time.

quality_drift is abs(mean_LPIPS_frames_0_to_5s minus mean_LPIPS_frames_115s_to_120s)

The demo must show that quality stays within 5 points across the entire 2-minute span, whereas frame-by-frame diffusion would drop by 40+ points. The absence of a visible fade, color shift, or identity collapse is the real win.
