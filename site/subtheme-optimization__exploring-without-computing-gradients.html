Exploring without computing gradients

Some optimization problems don't allow gradient calculation (black-box functions, limited queries). How do algorithms work with only function values, simulations, or search?

All themesField mapMathematicsAll explainers
What this is

Gradients are not always available. Imagine optimizing a design where you can only build a prototype, test it in the wind tunnel, and measure its performance—you get one number (drag coefficient) but no gradient. Or you are tuning hyperparameters of a large model—trying different learning rates, layer sizes, regularization strengths—and each experiment takes hours to run. You cannot compute gradients; you can only try different settings and see if they work better or worse. These are black-box optimization problems, where you interact with the system by querying it but never see its internals.

The challenge is that you have a limited budget of queries. You might afford 100 experiments before your budget runs out, and there could be millions of settings to explore. Randomly sampling does not work—you would waste most of your budget on obviously bad settings. You need a strategy that uses early results to focus the search on promising regions without wasting queries on dead ends. Traditional methods like genetic algorithms can work but are slow. The question is: how do you learn a model of how changes affect the outcome, and use that model to guide your next query?

Papers in this space use several approaches. Bayesian optimization maintains a probabilistic belief about what settings are good, then uses that belief to decide which settings to try next, balancing exploration (trying new areas) and exploitation (refining known good areas). Some papers use gradient-free neural networks that learn from function values directly. Others treat it as a search problem: divide the space into regions and eliminate regions that look bad based on samples from them. A few use evolutionary strategies where you maintain a population of settings, measure them all, and breed new ones from the best. Simulation-based optimization treats the black box as a simulator and uses the results from many cheap simulations to guide expensive real experiments. The insight is that you do not need gradients to learn how responses change; function values alone are enough if you model the patterns across the space.

How the work breaks down

Black-box optimization splits into several natural directions: maintaining a statistical belief about which settings are good (Bayesian approaches), learning patterns directly from function values without gradients (gradient-free learning), efficiently sampling when query budgets are tiny (sample-efficient search), and handling multiple competing goals at once (multi-objective optimization). The split exists because each direction faces different tradeoffs between how many experiments you can afford, how much you know about the problem structure, and what kind of answer you need.

Bayesian Optimization and Statistical Guidance

Bayesian optimization works by keeping a running belief about what different settings will produce, then using that belief to decide what to try next. The problem is that maintaining this belief in high dimensions or with millions of options is computationally expensive, and expert knowledge—if you have it—is hard to fold in without breaking things if the expert is wrong.

The Contextual Causal Bayesian Optimisation paper (1) proves that you can achieve sublinear regret (meaning the gap between your best result and the optimal one shrinks as you run more trials) even in high dimensions, if you use the right sample complexity. It does this by tracking worst-case and instance-dependent bounds, so it works both for adversarial problems and lucky ones where the structure is helpful. Graph Random Features (2) solves a different hard problem: storing and updating beliefs over graphs with over 1 million nodes on a single machine, by using random features to approximate the Gaussian process that usually needs cubic-time computation. Instead of scaling poorly as the problem grows, this method stays fast and uses less memory while keeping competitive results. Incorporating Expert Priors (3) tackles a practical reality: in real problems, domain experts have experienced many similar settings before and can guess which regions are more likely to have good solutions. The algorithm should use this expertise to focus the search faster, but if the expert is wrong, it should recover gracefully and ignore bad hints so you do not stay stuck. The paper uses a technique called dynamic mean decay to fade out incorrect priors over time while keeping correct ones, which means the method works whether or not the expert is trustworthy because it learns which advice to trust. Symmetry-Aware Bayesian Optimization (7) exploits structure in the search space: many real problems have symmetries (rotating a design by 90 degrees gives the same performance, for instance), which means the algorithm can skip redundant searches. By using similarity functions (learned mathematical measures of how alike two settings are) that respect these symmetries, the algorithm reduces regret without adding computational cost because it avoids re-exploring equivalent solutions. Language-Guided Bayesian Optimization (9) shows that when you have access to language descriptions of hyperparameters (like 'learning rate controls how fast the model updates'), an LLM can help predict which settings are likely to work well because it brings in prior knowledge about what each setting does. This cuts the search from 45,000 combinations down to 30 trials while improving performance 20%, so language descriptions act as a shortcut to promising regions.

Gradient-Free Optimization for Large Models

When you cannot compute gradients—either because the system is a black box or because computing gradients is expensive—you need to estimate how changes affect the outcome using only function evaluations. Zeroth-order methods estimate directions to improve using finite differences (measure the function at slightly perturbed inputs and see how much the output changed), which means you perturb each input coordinate in turn and measure the response difference. However, these estimates are noisy because measurement error compounds, and they are slow to converge because you need many perturbed measurements to estimate each direction accurately.

Romberg-Extrapolated Zeroth-Order Gradient Estimator (6) reduces this noise by using a classical numerical technique (Romberg extrapolation) to filter out low-order noise in the gradient estimates, making them more stable without losing information about the direction to improve. It works on learned function predictors with hundreds of thousands of internal weights and shows speedups on real problems like optimizing prompts and wireless network settings. Turning Stale Gradients into Stable Gradients (8) solves a different version: when you optimize coordinates one at a time instead of all at once (to save computation), the gradients from earlier steps become stale and misleading. The paper uses implicit smoothing—a mathematical trick that makes the function easier to optimize (like smoothing a bumpy terrain so gradient descent does not get stuck)—so that old gradient information still points in the right direction. It shows wins on image classifiers up to 270k internal weights. Learning Dynamics of Zeroth-Order Optimization (22) proves something surprising: the approximation error from using zeroth-order methods depends on how many outputs the model produces (like the vocabulary size for language models), not on how many internal weights the model has. This explains why zeroth-order methods can actually work on billion-parameter language models—if you organize the math carefully, the problem size does not explode. Online Black-Box Prompt Optimization (27) applies this to a real system: tuning discrete text prompts in an online setting where feedback is noisy. The algorithm achieves sublinear regret (the error shrinks as you try more prompts) and is more stable than simpler black-box methods, making it practical for iteratively improving prompts.

Evolutionary and Population-Based Search

Evolutionary strategies maintain a population of candidate solutions and breed new ones from the best, using multiple parallel evaluations to guide search toward better areas because they test many ideas in parallel and amplify the good ones. The challenge is that standard evolutionary methods are slow and waste evaluations on bad regions because they treat mutation like random search without learning what kinds of mutations help. So recent work focuses on using learned models or planning to guide breeding, which means you waste fewer tests on dead ends and find good solutions faster.

RefineEvo (5) combines planning with evolutionary search: it builds a learned model of which mutations are likely to improve a solution, and uses planning to explore how long chains of mutations compound. This lets it solve combinatorial problems like circuit design and scheduling much faster than random evolutionary strategies because it avoids wasting evaluations on bad mutations. Bridging Spherical Black-Box Optimizers (12) unifies two different evolutionary ideas (evolution strategies and trust-region methods) and lets you trade off preference for flat minima (which generalize better because they are less sensitive to small input changes) versus sharp minima (which are easier to reach because the gradient is steep). This matters when merging trained models or tuning physics simulations where shallow minima behave more predictably under small changes. Iterated Population Based Training (18) improves hyperparameter search by building multiple optimization runs, then restarting the best ones with new random seeds rather than abandoning them. This matches or beats five existing variants without requiring a bigger budget because it recycles momentum from good runs. Meta-Black-Box Optimization (24) steps further: it trains a separate optimization algorithm on many small problems, then uses that learned algorithm to search efficiently on new problems. It generalizes across different problem sizes and numbers of competing objectives because the learned strategy captures principles that transfer, so the learned search strategy works on new tasks.

Multi-Objective Optimization and Batch Search

Many real problems have multiple competing goals: maximize performance while minimizing power consumption, or find a drug that is potent but non-toxic. You cannot optimize both simultaneously, so the goal is to efficiently find the entire frontier of tradeoff points. When you can evaluate multiple settings in parallel, you need to pick batches wisely.

Many Needles in a Haystack (4) solves the case where you want to find many good settings (hits) among millions of options, like in biological perturbation experiments where you screen chemicals to see which ones affect a gene strongly. The method is asymptotically optimal (it finds all the good ones as fast as theoretically possible, so it wastes no unnecessary experiments in the limit) and improves real immunology experiments by 6.4%, which shows the theory pays off in practice. Combinatorial Bandit Bayesian Optimization (13) handles the case where the output is not a single number but a tensor (a multi-dimensional array): you might measure many aspects of a design's performance at once. The method achieves sublinear regret and works even when you only observe parts of the tensor because measuring everything is too expensive, so it extracts information from partial measurements. Multi-Objective Bayesian Optimization via Adaptive Epsilon-Constraint (25) builds the full Pareto frontier (the set of solutions where you cannot improve one objective without hurting another) by internally converting it to single-objective problems with adaptive constraints. It never needs to compute hypervolume (a complex, expensive calculation that requires knowing a reference point), which means it is faster than methods that rank by hypervolume gains. Probability of Matching (28) selects which batch of solutions to evaluate next by maximizing the probability that any of them will match or beat the current best known solution. This is simpler than computing expected improvements because it skips the hard math, and it works better in batch settings because it focuses on diversity.

Permutations and Very High-Dimensional Search

High-dimensional optimization is hard because the search space grows exponentially, so standard methods get lost in the vastness. Some problems have special structure (permutations, high-dimensional continuous spaces with many variables) that standard methods cannot exploit. Others involve combinatorial choices that require different mathematics.

From Sorting Algorithms to Scalable Kernels (16) optimizes over permutations (like ordering chemicals in a synthesis experiment or ranking options). The paper shows that a kernel based on merge sort operations outperforms older kernels from permutation statistics and stays fast even as the dimension grows because it captures the hierarchical structure of how permutations relate. GIT-BO (17) uses tabular foundation models (learned representations of tabular data) to handle 500-dimensional continuous optimization problems much faster than Gaussian process methods, because the model learns across many related problems and transfers that knowledge so it requires fewer queries. Runtime advantages grow as problems get higher-dimensional because learning from related tasks saves more work. LLM-Guided Evolutionary Program Synthesis (20) uses an LLM to evolve the program that constructs point sets (like sampling patterns for Monte Carlo algorithms), discovering better 2D patterns and improving 3D benchmarks beyond what humans found before. This works because language guidance lets the LLM hypothesize structural ideas that escape local optima in discrete optimization. LLM4Branch (21) applies similar ideas to integer programs: instead of exploring all branches in a decision tree (which is exponentially many), use an LLM to predict which branches are most likely to contain good solutions. This matches specialized solvers on standard benchmarks and beats GPU-based neural branch selectors because the LLM brings common-sense pruning.
