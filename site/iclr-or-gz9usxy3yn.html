Semantic-Enhanced Time-Series Forecasting via Large Language Models

A time-series forecaster adds a semantic layer to language model tokens that encodes periodicity and anomalies, plus a plugin that models both slow trends and sudden jumps.

Paper explainersAll themesTime Series & Sequential

Time series are sequences of numbers over time (stock prices, temperature readings, sensor data). Large language models (LLMs) excel at understanding text, but they were not designed to see patterns in raw numbers. Existing attempts to adapt LLMs to time series treat each number as an isolated element of text, missing the semantic structure hidden in temporal patterns. This paper proposes a plugin that encodes what makes time series special: their cycles and their anomalies, so the LLM can reason about them the way humans do.

Zero assumption version

LLMs see time series as noise, not signal

Time series are everywhere: your heart rate over an hour, the stock market over decades, weather patterns over years. A human forecaster looks at a chart and instantly sees regularities: patterns that repeat (a heartbeat, seasonal heating), sudden breaks (a crash, a storm), trends (prices climbing). Language models, built to process text, have no built-in sense of these temporal shapes. When you feed an LLM raw time-series numbers (or text versions of them), it treats each number like a random word in a sentence, missing the deep rhythm underneath.

A naive approach: tokenize the time series (convert numbers into words), pass it to an LLM, hope the model learns the patterns on its own. The problem: the LLM's attention (the mechanism that decides which words matter) was trained on text, where nearby words are semantically linked. In time series, what matters is not the word before, but the pattern 100 steps back. Also, Transformers (the core architecture of LLMs) excel at long-range patterns but miss sudden, localized spikes. The model drowns the anomaly (a sudden price jump) in the noise of the trend.

In one sentence. Current LLM time-series forecasters treat temporal patterns as plain text, blind to cycles and sudden anomalies.

The algorithm as a flow

What it actually does

Extract periodic skeleton

Measure how often the signal repeats (daily spike, monthly trend) and encode this as part of the token.

Measure anomalousness

Detect deviations from the typical cycle and mark them as semantic features attached to the token.

Enhance token embeddings

Combine the raw number, periodicity, and anomaly score into a richer embedding (a list of numbers representing the signal).

Add fast-path attention plugin

Inside the self-attention (the part where the model weighs which past values matter), add a shortcut for nearby time steps.

Freeze LLM, reduce sequences

Keep the main model fixed (saving compute) and only train on the semantic-enhanced tokens, compressing long sequences.

What the paper changes

What the paper changes

The paper changes the token embeddings (the numerical representation the LLM reads). Instead of converting raw time-series values directly into embeddings, it first computes periodicity and anomaly features, then combines them with the raw value into a richer semantic embedding. This semantic embedding carries information about the temporal structure of the series, not just the number itself.

the object it moves  =  Token embeddings with semantic markers
The hidden quantity

The semantic richness score

measured quantity  =  Semantic alignment gap

The paper hypothesizes that LLMs struggle with time series because there is a mismatch between how tokens are typically used (discrete words with linguistic meaning) and how time-series numbers should be used (as elements of a continuous, cyclical structure). The 'semantic alignment gap' is this mismatch: how far apart are the linguistic token structure and the temporal data structure. The paper does not assign a single number to this gap, but rather addresses it by adding semantic features (periodicity and anomaly scores) that bridge the gap.

The paper estimates this gap indirectly: it observes that Transformers built for text do poorly at capturing both long-term trends and short-term anomalies simultaneously. By adding semantic features and a dual-path attention plugin, the paper reduces this gap, making the model more interpretable (you can see what periodicity and anomalies are being tracked).

Why it works

Why bridging the gap helps the forecast

LLMs have one main superpower: they can focus on distant parts of the input that matter (via self-attention, a mechanism that scores how relevant each past word is). But this attention was trained on text, where nearby words usually matter most. In time series, a value 500 steps back (last week's price) often matters more than the value 2 steps back (this morning, lost in noise). Moreover, self-attention is smooth: it learns to find broad trends because trends are statistically stronger than anomalies. As a result, an unmodified LLM misses sudden spikes.

SE-LLM fixes both problems. First, by encoding periodicity into the token, it labels 'this step is a peak of the cycle,' which makes self-attention naturally weight similar cycle points high, even if they are far apart. Second, by encoding anomalies, it marks unusual values so they are not drowned out by trend-following. Third, the attention plugin adds a 'fast path' that explicitly keeps nearby time steps in view, complementing the slow trend-catching path of the main LLM. The two paths are merged: slow attention sees the long cycle, fast attention sees the spike, and the forecast uses both. Because the LLM is frozen (its weights do not change), only the semantic embeddings and plugin are trained, cutting the compute cost dramatically.

The embedding boost equation

First in words:

semantic-embedding = base embedding plus period weight times period signal plus anomaly weight times anomaly signal

Then the compact form:

e_t = [raw_value] + w_p * [period_phase] + w_a * [anomaly_score]

Every symbol:

e_tthe enriched semantic embedding at time step t
raw_valuethe raw time-series number at time t
w_pweight controlling how much periodicity information is mixed in
period_phasethe phase within the cycle at time t (0 to 1, or in degrees)
w_aweight controlling how much anomaly information is mixed in
anomaly_scoredeviation from the expected value under the learned cycle (typically normalized 0-1 or -1 to 1)
A tiny worked example
Suppose at time t=10 the raw value is 24.5 (say, a temperature).
The periodicity detector finds the cycle repeats every 7 days. At step 10, phase is 3/7 = 0.43.
The anomaly detector finds: typical value for phase 0.43 is 23.0, but we have 24.5, so anomaly_score = 1.5 (high).
Learned weights: w_p = 0.6 (periodicity matters), w_a = 0.4 (anomalies matter).
e_10 = [24.5] + 0.6 * [0.43] + 0.4 * [1.5]
e_10 = [24.5] + [0.258] + [0.6] = [25.358]
This embedding says: the raw number is 24.5, but it is part of a known cycle at phase 0.43, and unusually high. The LLM sees all three facts in a single token.

The enhanced embedding carries semantic content: it is not just a number, but a number plus its rhythm and its surprise.

What can go wrong

What can go wrong

Periodicity extraction fails when the cycle is not regular. If the time series is chaotic or has a cycle length that changes over time (e.g., a traffic pattern that shifts with the season), the periodicity detector will produce noise, not a true phase. The semantic embedding becomes corrupted, and forecasts degrade. A time series with no clear repeating pattern should be detected and handled separately (e.g., use a trend-only model instead).
Anomaly detection produces too many false positives. If the threshold for what counts as an 'anomaly' is too sensitive, normal noise is marked anomalous, flooding the embedding with high anomaly scores. The model loses the ability to distinguish truly surprising values. The weights for anomaly importance must be tuned carefully for the domain.
The fast-path attention plugin overfits to local noise. If the fast-attention path is too strong (looking only at neighbors), the model ignores the long-term cycle and chases random fluctuations, especially in high-noise domains like intraday stock ticks. Balancing slow and fast paths via their merging mechanism is essential to keep the forecast stable.
Done right. Periodicity is extracted from a clean, preprocessed window; anomalies are scored against a strong baseline (e.g., a moving average or seasonal decomposition that captures what a normal value should be for that point in the cycle); and the slow and fast paths are merged by a learned gate that decides when to trust each. When these conditions hold, the semantic embedding carries true information about the series structure, so the model makes fewer forecast errors because it is attending to real temporal patterns, not noise.
What a runnable demo should prove

What a runnable demo should prove

Build a minimal time series with a known cycle (e.g., a 7-step repeating sine wave) plus an injected anomaly (a single large spike). Train the naive LLM tokenizer on 100 steps, train SE-LLM on the same data, and forecast the next 10 steps for both. Visualize the two forecasts side by side. The demo should make it impossible to miss: naive LLM smooths out the spike (missed the anomaly) and drifts on the tail, while SE-LLM reproduces the cycle precisely and flags the spike region even after it has passed.

anomaly detection rate = (number of forecasted steps > 1 SD from mean) / (true anomalies in ground truth)

The demo proves that encoding periodicity and anomalies into the token embedding, not the LLM's weights, gives the model a language for temporal patterns it was never trained to see.
