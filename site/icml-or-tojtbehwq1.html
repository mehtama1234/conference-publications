SCNS: Continual Personalization of Diffusion Models via Submodular Concept Neuron Selection

The paper personalizes a diffusion model for one new concept at a time by editing only a small selected set of neurons, chosen to cover the new concept well while avoiding overlap with old concepts and avoiding damage to previously important weights.

Paper explainersAll themesGenerative Models & Diffusion

A personalized diffusion model can learn a user's concept, such as a specific person or object, from a few examples. The difficulty starts when new concepts arrive over time. If you keep fine-tuning the same model, the newest concept overwrites earlier ones. If you train separate models and merge them later, the process becomes expensive and messy. SCNS avoids both paths. It identifies a sparse set of concept-specific neurons for each new concept and updates only those neurons. The selection is posed as a submodular optimization problem, which means the value of adding one more neuron falls as similar neurons are already selected. That lets the method keep enough capacity for the new concept while limiting overlap with old concepts and preserving the weights most important for previously learned concepts.

Zero assumption version

Continual personalization creates forgetting

A diffusion model generates images by gradually removing noise while conditioning on text or concept signals. To personalize it, you fine-tune some of its weights so the model can render a new user concept, because changing those weights changes which visual patterns the model can reproduce. That works for one concept. The trouble is that another fine-tuning run will often reuse the same internal capacity, so the second concept damages the first.

A simple fix would be to allocate a separate model copy for every concept and merge them later. That keeps concepts apart, but memory and merge cost rise with every concept. The paper asks for a third option: can the model keep learning new concepts by editing only the neurons that are truly needed for each concept, and can those neurons be chosen in a principled way rather than by a crude threshold?

The core problem. Each new concept wants some of the same internal capacity as older concepts, so continual fine-tuning needs a way to choose where updates are allowed.

The algorithm as a flow

What it actually does

Measure concept relevance

Estimate which neurons respond strongly to the new concept because those neurons are the most plausible places to store the new concept.

Reward coverage

Prefer sets of neurons that jointly capture the concept well rather than choosing neurons only by individual score.

Penalize redundancy and risk

Avoid picking many neurons that do the same job, and avoid neurons whose old weights are important for previously learned concepts.

Run greedy selection

Add neurons one at a time according to gain divided by cost, because the submodular objective supports efficient near-best greedy choice.

Fine-tune only the selected neurons

Update that sparse subset for the new concept and freeze the rest, so the model learns new content without broad weight drift because the unchanged weights cannot be overwritten.

What the paper changes

What the paper changes

The paper changes the unit of continual personalization from whole-model fine-tuning to neuron-set selection. Instead of asking how to merge or restrain large weight updates after the fact, it asks which internal units should be allowed to move before training starts.

the object it moves  =  the editable subset
The hidden quantity

The hidden quantity: marginal concept gain

measured quantity  =  how much one more neuron helps after some neurons are already selected

A submodular objective encodes diminishing returns. In plain terms, the first neuron that captures a useful part of the new concept may be very valuable, but the tenth neuron that captures nearly the same part adds little. SCNS uses this logic so the selected set stays compact.

The gain is not only about fitting the new concept. The paper combines a coverage term, derived from facility-location style selection, with a risk term weighted by Fisher information, which is a measure of how sensitive earlier concepts are to changes in a weight. A neuron with high new-concept value but high old-concept risk may be skipped if safer neurons provide similar coverage.

Why it works

Why it works: sparse edits localize interference

Forgetting happens when a new concept update spreads across weights that old concepts also rely on. If you can confine the update to a carefully chosen subset, interference drops. But a random sparse subset would miss key concept details. The paper's contribution is the selection rule that balances these two needs.

The facility-location style coverage term promotes sets whose members explain different parts of the new concept. That stops the selector from wasting budget on several neurons that all encode nearly the same visual detail. The Fisher-weighted risk term protects old concepts because weights with high Fisher importance are the ones where small changes would cause a large loss increase on earlier tasks. Combining those terms produces a set that is both useful and safer to edit.

The greedy rule is important because exact search over all neuron subsets is not feasible. Submodularity gives a practical approximation guarantee: each added neuron is chosen by its remaining gain relative to its edit cost, and that greedy sequence captures much of the value of the best sparse set without exhaustive combinatorial search.

Math after the picture

The equation: greedy gain per cost

First in words:

At each step, choose the neuron whose extra objective gain divided by its edit cost is largest.

Then the compact form:

pick neuron j maximizing (F(S union {j}) - F(S)) / cost_j

Every symbol:

F(S)the current set value under the coverage-minus-risk objective
Sthe set of already selected neurons
ja candidate neuron not yet selected
cost_jthe cost assigned to editing neuron j
A tiny worked example
Current selected set S has objective value 10.
Adding neuron A raises the value to 14 and has cost 2, so gain per cost is 4 divided by 2 = 2.
Adding neuron B raises the value to 13 and has cost 1, so gain per cost is 3 divided by 1 = 3.
The greedy rule picks neuron B first because it adds more objective value for each unit of edit budget.
After B is selected, the gain from A may shrink if B already covers similar concept details.

The shrinking gain after each selection is the diminishing-returns property that keeps the chosen set small.

What can go wrong

What can go wrong

Neuron relevance scores are noisy. If the initial concept-response estimates are unreliable, the selector may exclude neurons that are actually essential or include neurons that only appeared active by chance. Then the sparse update budget is spent badly.
The new concept genuinely needs shared high-risk neurons. Sometimes the only strong representation route for a new concept passes through neurons that older concepts also depend on. In that case, any sparse protection rule faces a hard tradeoff, and perfect retention may be impossible.
The objective weights are poorly tuned. If coverage dominates too strongly, the method edits too many risky neurons. If risk dominates too strongly, the model may preserve old concepts but fail to align the new one. The balancing weights control the stability-plasticity tradeoff directly.
Done right. When concept-specific neurons can be identified with reasonable reliability, sparse selective editing gives continual personalization a much cleaner operating point than full sequential fine-tuning or repeated model fusion.
What a runnable demo should prove

What a runnable demo should prove

Take a small diffusion model or a compact image generator with several user concepts arriving sequentially. Compare three strategies: broad fine-tuning, a crude top-score sparse update, and SCNS. For each new concept, record alignment to the new concept prompts, retention on old concept prompts, and the number of edited weights. Also inspect whether the selected neurons overlap heavily across concepts or remain mostly concept-specific.

forgetting_drop = old_concept_score_before_new_update - old_concept_score_after_new_update

The demo should make the central mechanism visible: reducing forgetting is not only about editing fewer weights, but about editing the right small set.
