Memento: Embodied Agents with Personalized Memory

Embodied agents use separate memory modules for personal object knowledge and behavioral patterns to plan and act with user-specific understanding.

Paper explainersAll themesAgents & Tool Use

Robots and AI assistants powered by large language models often fail at personalized tasks because they cannot hold onto what they learn about a particular person — what objects mean to that person, or the sequence of actions that person habitually does. This paper (Memento) builds a test suite to measure whether an agent can remember and use two kinds of knowledge: personal object meanings (like knowing this photo means Mom, not just pixels) and personal routines (like knowing Tuesday mornings start with coffee). It finds that current agents lose track of this information when managing multiple memories at once, and solves it by organizing memories in a layered knowledge structure that handles each type separately.

Zero assumption version

Agents forget what makes a person unique

A home robot knows how to pick things up and move them. But if you ask it to fetch Mom's glasses, it sees just any glasses. If you ask it to make coffee before breakfast, it does not know that your family always eats after 7am. The robot has no way to hold onto personal knowledge — facts about how your objects mean different things, or how your daily routines work.

A naive approach would be to dump all this personal knowledge into a long context window (the space where the AI model reads information before deciding). But experiments show this does not work: when the agent must juggle several memories of an object or several steps in a routine, its planning falls apart. Too much information at once causes the agent to ignore some of it or mix them up.

The problem. Embodied agents cannot separately track personal object meanings and personal routines, so planning fails when multiple memories are held in mind at once.

What the paper changes

What the paper changes

Instead of a flat list of memories, the paper uses a knowledge graph (a structure where facts are connected to related ones). This graph separates personal meanings (rules about objects, such as the blue thermos belongs to Dad) from behavioral routines (sequences like Tuesday mornings start with coffee). When the agent needs to act, it queries this graph to pull only the relevant memories rather than drowning in all of them.

The hidden quantity

The coordination cost

measured quantity  =  memory coordination failures

When an agent must hold multiple memories in mind at once (say, three facts about what objects mean, plus two routine patterns), its planning accuracy drops sharply. This paper calls this the coordination cost: the hidden damage done when memories collide or compete in the agent's context. You cannot see this cost by just looking at a single memory — it only appears when you measure the agent's performance on tasks requiring two or more memories together.

The paper estimates this by testing agents on single-memory tasks (recall Mom) versus joint-memory tasks (find Mom's favorite object before her usual coffee time). The gap between these scores reveals how much coordination fails. The hierarchical knowledge graph reduces this gap by letting the agent focus on one type of memory at a time.

Why it works

Why separate layers beat a flat dump

When all memories sit in the context as a flat list, the agent must scan through everything to find what it needs, and all the unrelated facts create noise. With many memories, this noise overwhelms the signal: the agent misses the relevant facts or mixes up the associations. The hierarchical knowledge graph works by organizing memories into two distinct layers (objects and routines). When the agent is planning an object-retrieval task, it queries only the object layer; when planning a timed sequence, it queries only the routine layer. This focus means the agent reads less noise, so it attends to the right facts and makes better planning decisions.

The graph itself (the links between facts) lets the agent navigate more efficiently: starting from a task goal, it can jump directly to relevant memories instead of scanning everything. The separation of concerns — treating object meanings and behavioral patterns as different knowledge types — mirrors how humans remember people: we keep separate tracks of what someone likes (preferences about things) and when they do things (patterns in time).

Math after the picture

Scoring joint memory retrieval

First in words:

total planning accuracy = (single memory accuracy × weight for objects) + (single memory accuracy × weight for routines) − (coordination cost × alpha). The coordination cost grows when the agent must hold conflicting memories.

Then the compact form:

A_total = α_obj · A_obj + α_rtn · A_rtn − λ · C_coord

Every symbol:

A_totalthe final accuracy of the full personalized plan
A_objhow well the agent recalls the object meaning alone
A_rtnhow well the agent recalls the routine alone
α_objthe fraction of the task that depends on object knowledge
α_rtnthe fraction of the task that depends on routine knowledge
C_coordthe coordination failure rate (measured as gap between single and joint tasks)
λhow much coordination failures hurt the final plan
A tiny worked example
Task: fetch Dad's thermos before his 7am coffee. Object accuracy = 90% (knows thermos). Routine accuracy = 80% (knows time). Coordination cost = 15% (observed gap when both memories needed). α_obj = 0.6, α_rtn = 0.4, λ = 1.0.
A_total = 0.6 * 90 + 0.4 * 80 − 1.0 * 15 = 54 + 32 − 15 = 71%. Without the hierarchical graph, coordination cost would be 30%, giving A_total = 54 + 32 − 30 = 56%. The separate layers reduce coordination failure by half, improving planning accuracy by 15 percentage points.

The hierarchical graph reduces the coordination cost term by letting the agent attend to one memory layer at a time, so the penalty term shrinks.

What can go wrong

What can go wrong

Mismatch between query and memory type. If the agent asks for routine knowledge but the graph points to object facts (wrong layer), the plan still fails. The graph structure must correctly partition the two types.
Old or stale memories. If a user's preferences or routines change (thermos is now blue, not red; coffee time moved to 8am), the agent uses outdated facts and plans wrongly. The memory module must be updated regularly.
Ambiguous facts that blend layers. Some facts do not fit neatly into object or routine buckets (like 'Dad is left-handed' — is it about Dad the person, the object he holds, or a pattern?). Misclassifying these still creates coordination problems.
Done right. The hierarchical graph is built correctly, memories are kept fresh, and the agent learns which facts belong in which layer through evaluation on mixed tasks.
What a runnable demo should prove

What a runnable demo should prove

Build a simple embodied-agent simulator: a robot in a 3D room with five objects (mug, glasses, book, phone, toy). Add two people (Mom and Dad) with personal associations (Mom likes the mug, Dad likes the glasses) and two time-based routines (morning: make coffee; evening: read). Create two test suites: single-memory tasks (fetch Mom's object) and joint-memory tasks (fetch Mom's object and do it before Dad's routine time). Measure the agent's success on both suites using the flat-context baseline versus the hierarchical knowledge graph. The graph should show a narrower gap between single and joint tasks.

joint_accuracy_hierarchical − joint_accuracy_flat ≥ 15 percentage points (with single-memory accuracy held constant)

The demo must make clear that separating memories into layers reduces the cost of holding multiple facts in mind.
