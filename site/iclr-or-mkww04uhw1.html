HAMLET: Autonomous Agents in Theatrical Performance

Give each theatrical actor an autonomous mind — a set of goals and emotional state — so they make independent decisions and change the scene, not just recite lines.

Paper explainersAll themesAgents & Tool Use

A theatrical drama generated by an LLM usually feels scripted: actors repeat lines the model wrote, responding to user prompts, with no initiative. HAMLET flips this. Instead, each actor becomes an agent — a thing that has its own goals, feels emotions, remembers facts, and can change physical props on stage by opening letters or picking up weapons. When one actor moves a prop, all other actors who care about that prop find out and adjust their plans. The result is a play that feels alive because the actors are actually deciding what to do, moment by moment.

The problem: scripted actors without autonomy

Before HAMLET, LLM-based theater systems worked like this: a user types in a topic and detailed instructions, the LLM generates a script, and actors recite it. The actors never make decisions on their own. If the play says Actor A picks up a sword, the model wrote that line before the scene began. If Actor B should react to the sword being picked up, the model must have guessed that ahead of time.

A beginner might try to fix this by asking the LLM to improvise — just prompt it to keep going without a full script. This breaks because without shared memory the LLM forgets what happened two turns ago. Actor A picks up a sword, and Actor B responds as if nothing changed. The scene feels incoherent.

HAMLET's core problem: how to let actors make decisions independently, based on what they know and care about, while keeping the whole drama coherent because everyone sees the changes to the scene.

In one sentence. Each actor keeps its own mind — goals, emotions, beliefs — and when any actor changes a prop, all actors who know about it instantly learn the truth.

The algorithm as a flow

What it actually does

User gives a topic

Someone says 'create a mystery play' or 'a comedy about a restaurant'.

System builds a narrative blueprint

The LLM sketches out who the characters are, what conflicts exist, key events.

Each actor gets an autonomous mind

Every character stores its own background, current goals, emotional state, and beliefs about what props exist and what other actors know.

During performance, actors take turns deciding

The system asks each actor in order: given your goals and what you know, what do you do or say next?

Prop changes broadcast to all

If Actor A picks up a weapon, the system updates the scene state, then tells every actor who cares about weapons that the state changed.

What the paper changes

What the paper changes

HAMLET separates character mind (beliefs, goals, emotions) from scene props (the physical state of the stage). Before, the LLM held all the facts in one jumbled prompt context. Now, each actor (an agent) explicitly maintains its own knowledge — what it has seen, what it cares about — and the scene keeps a separate list of prop states and who knows what.

the object it moves  =  Character minds and scene state are decoupled
The hidden quantity

The hidden quantity: what each actor knows

measured quantity  =  Belief state per actor

The hidden quantity HAMLET measures is what each actor knows — their personalized view of the scene. Actor A might know the sword is on the table because they saw it. Actor B might not know yet. Actor C might have the wrong idea. This belief state is real and important: it determines what decision the actor will make next.

HAMLET tracks this explicitly. When a prop changes, the system updates a belief list for each actor: if the actor cares about that prop (e.g., the sword is relevant to their goal), the actor's belief updates. If the actor hasn't been told, the belief stays stale. This difference in knowledge creates dramatic tension: actors make good decisions based on what they know, but they act on incomplete or wrong information.

Why it works

Why it works: closed-loop perception and autonomy

The mechanism is a tight feedback loop. Actor A makes a move (picks up a sword). That action changes the scene state (sword is no longer on the table). The system then broadcasts this change: it checks which actors care about swords and adds a fact to their belief: 'the sword was picked up.' On the next turn, Actor B decides what to do knowing that the sword is gone. If Actor B's goal was to pick up the sword, they replan. The drama feels alive because each decision is genuinely reactive to what happened before.

Contrast this to the old scripted way: the model generates all dialogue at once, so it must guess what will happen in the future. HAMLET lets actors react in real time to each other's choices, because each actor's decision is made fresh, after seeing the updated scene state. The key insight: by making beliefs explicit (rather than implicit in a giant prompt), the system can keep state correct and let each character act as an autonomous agent with its own incomplete knowledge.

The belief update rule

First in words:

For each actor, the belief state is a list of fact pairs (prop_name, actor_observes_it). When a prop changes, for each actor, if that actor cares about the prop, set the belief to true. Otherwise, leave it as is.

Then the compact form:

belief_i[prop] <- IF (actor_i_cares_about[prop] AND prop_changed) THEN TRUE ELSE belief_i[prop]

Every symbol:

belief_i[prop]what actor i believes about prop (true if actor has seen it, false if not)
actor_i_cares_about[prop]whether this prop is relevant to actor i's current goal
prop_changedwhether the scene state of prop was updated this turn
A tiny worked example
Turn 1: Sword is on table. Actor A cares about swords (goal is to get a weapon). Actor B cares about letters. belief_A[sword]=true, belief_B[sword]=false.
Turn 2: Actor A picks up sword. System updates: sword is no longer on table.
Update beliefs: Actor A cares about swords? Yes. Sword changed? Yes. belief_A[sword] <- True (still true). Actor B cares about swords? No (they care about letters). Leave belief_B[sword] as false.
Turn 3: Actor A now has the sword (decided in turn 2). Actor B still doesn't know. Only Actor A can use the sword in the next decision because only Actor A knows it exists.

When a prop changes, only actors whose current goal depends on that prop are told. This makes each actor's knowledge realistically incomplete, which forces them to make decisions under uncertainty — like a real person in a play.

What can go wrong

What can go wrong

Actors forget past events. If the system does not explicitly update an actor's beliefs when a prop changes, the actor will act as if nothing happened. For example, if Actor B never learns that Actor A picked up the sword, Actor B might try to pick it up too, creating a logical contradiction.
Too many goals overwhelm the LLM. If an actor has five simultaneous goals, the LLM might flip-flop between them or ignore most of them. The decision LLM needs a clear priority or a way to track which goals are already met.
Props interact in unexpected ways. If Actor A picks up a weapon and Actor B tries to grab it at the same time, the system must decide who gets it. The paper's system requires explicit conflict rules or the scene state will be ambiguous.
Done right: clear belief tracking and prop ownership. When the system tracks who knows what and updates beliefs consistently, the drama stays coherent. When prop ownership is explicit (only one actor holds the sword at a time), there is no contradiction.
What a runnable demo should prove

What a runnable demo should prove

Build a tiny two-act play: a king and a messenger. Give the king a goal ('find the secret letter'). Give the messenger a goal ('deliver the letter without the king noticing'). The king cannot see the messenger initially. Start with the letter on a table. Run 10 turns where each character decides what to say or do. At each turn, print what each character knows (their belief state) and what they decide. At the end, measure: did the king find the letter? Did the messenger try to hide it? Did the drama tell a coherent story?

coherence_score = (goal_A_achieved + goal_B_attempted + state_never_contradicts_itself) / 3

The key moment: when the messenger picks up the letter, the king immediately learns what happened and changes strategy, without anyone programming that reaction. That is autonomy.
