Scalable Topology-Preserving Graph Coarsening

Shrink a graph to run faster while keeping its topological shape, so neural networks see the same structure.

Paper explainersAll themesGraph & Geometric Learning

When a graph (a web of connected things) gets huge, running a neural network on it becomes slow. You could shrink it by deleting nodes and edges, but most methods throw away shape information that the network relies on. This paper introduces a way to coarsen graphs (make them smaller) while mathematically preserving their topological features, so the resulting shrunk graph keeps the same connectivity shape as the original.

Zero assumption version

Shrinking graphs breaks neural networks

A graph is a set of things (nodes) connected by relationships (edges). When the graph has millions of nodes, running a neural network over it is very slow because the computation scales with size. A naive approach is to delete the less important nodes and their edges to make the graph smaller. But this usually destroys the topology, which is the shape and structure of how things connect.

Most existing coarsening methods preserve either spectral properties (mathematical properties related to how signals travel through the graph) or spatial properties (whether adjacent nodes stay adjacent), but not the actual topology (the holelike structure, the loops, the way the graph branches). Real neural networks rely on topology to learn: they read the shape of connections, not just individual values. Delete the wrong nodes and the network can no longer recognize the structure it was trained on.

In one sentence. The paper keeps the graph's topological shape when shrinking it, using algebraic topology to identify which nodes and edges can be safely deleted.

What the paper changes

What the paper changes

The paper does not change the neural network model itself. Instead, it changes the input graph: which nodes and edges are kept or merged. By identifying nodes that are topologically 'dominated' (they do not create unique loops or structural features), the method collapses them into their neighbors, shrinking the graph before the network ever sees it.

the object it moves  =  graph structure: nodes and edges
The hidden quantity

Topological dominance: which nodes can vanish

measured quantity  =  Topological dominance (node collapsibility)

The paper introduces a measure from algebraic topology: whether a node is topologically dominated. A node is dominated if removing it does not create or destroy any holes, loops, or branches in the graph. Intuitively, a node is dominated if it is not essential to the graph's shape.

The paper estimates dominance by checking if a node and its neighbors form a structure that can be continuously collapsed (in topological terms, a 'strong collapse' or 'edge collapse') without changing the homology (the formal name for hole-counts and loop structure). Nodes and edges marked as dominated become candidates for merging.

Plain reading. A node can be removed if nobody depends on it to understand the graph's shape. If removing it erases a loop or shortcut that the neural network relies on, the node is not dominated and stays.
Paper reading. Dominance is formalized via algebraic topology: a node is strongly collapsible if it forms a pair with a neighbor such that removing the pair and contracting the edge preserves the graph homology.
Why it works

Why shrinking by topology works

Neural networks on graphs learn by passing messages along edges and summing neighbor values. If the graph has a loop (a cycle), the network uses it to reinforce patterns. If two nodes are close together in the graph, the network sees them as a pair.

When you delete a random node, you might break a loop that the network used for learning. The network on the coarsened graph sees a different shape and fails. When you delete only topologically dominated nodes (ones that do not create unique loops or shortcuts), you preserve the loops and branches the network needs. The coarsened graph is geometrically the same, so the neural network receptive field (the neighborhood it sees in one step) stays the same. Running on a smaller graph with the same topology means the network runs in a fraction of the time but learns the same patterns.

Math after the picture

The topology preservation equation

First in words:

A node v is strongly collapsible if there exists a neighbor u such that the only other neighbors of v are also neighbors of u. In symbols: if star(v) is the set of nodes touching v, and star(u) is the set touching u, then v is dominated if star(v) subset-of star(u) union {u}. Homology H (the formal measure of holes and loops) stays unchanged.

Then the compact form:

H_k(G) = H_k(G / e) for all dimensions k, where G / e is the graph after collapsing edge e

Every symbol:

H_k(G)the k-th homology of graph G; counts independent loops and holes of each type
G / ethe graph after contracting edge e by merging its two endpoints
kdimension: 0 = connected components, 1 = loops, 2 = voids
=stays the same; topology is preserved
A tiny worked example
Original graph: 6 nodes arranged as a cycle with one extra node (node D) attached to node C. Total edges: 6.
Node D has only neighbor C. Node C has neighbors B, D, and E. Since D's neighborhood {C} is a subset of C's neighborhood {B, D, E}, node D is dominated.
Collapse node D into node C: merge them, remove the D-C edge. New graph: 5 nodes, 5 edges. The original cycle is unchanged.
Homology: original cycle (H_1 = 1 loop) is still there. D was not part of the loop structure, so homology is preserved: H_1(G) = H_1(G coarsened) = 1.

When a node is topologically dominated, contracting it preserves the formal hole-count (homology), so the neural network sees the same structural features.

What can go wrong

What can go wrong

Dominated-ness changes with the task. A node that is topologically dominated may still carry task-specific information (e.g. a sensor reading). The coarsening assumes topology is what matters, but if the task relies on specific node values, collapsing them loses that signal. The paper is best suited for tasks where the graph structure itself (loops, neighborhoods) matters more than individual node features.
Computing dominance is expensive for huge graphs. The algorithms (GStrongCollapse, GEdgeCollapse, NeighborhoodConing) must scan the graph to identify dominated nodes. On very large graphs (millions of nodes), this can be slow. The paper includes approximate versions to speed this up, but the approximation may miss some dominated nodes, reducing coarsening ratio.
Receptive field shrinkage still happens. Although topology is preserved, the neural network receptive field (the neighborhood size it sees) may shrink if you coarsen too aggressively. The paper preserves receptive field mathematically, but in practice the reduced graph size means fewer hops to reach far nodes.
Done right. Apply STPGC to graphs where topology (loops, branches, neighborhood structure) is central to the learning task. Combine it with task-specific node feature selection to retain important signals. Use approximate algorithms when the graph is very large and exact dominance computation is a bottleneck.
What a runnable demo should prove

What a runnable demo should prove

Write a short Python script that builds a simple graph (e.g. a cycle with a few extra nodes attached), applies the three STPGC algorithms (GStrongCollapse, GEdgeCollapse, NeighborhoodConing) to coarsen it, computes the homology (hole-count) of the original and coarsened graphs using a topological library like the NetworkX or a custom implementation, and verifies they match. Then train a simple GNN (graph neural network) on the original and coarsened graphs on a node classification task (e.g. a small synthetic dataset). Show that the coarsened graph trains in less time and achieves similar accuracy.

speedup = time_original / time_coarsened; accuracy_retention = accuracy_coarsened / accuracy_original; topology_error = H_1(original) - H_1(coarsened)

The demo must show that coarsened graphs train faster because fewer nodes means fewer operations per step. It must retain accuracy because topology is preserved so the network sees the same structural patterns. It must have identical homology (formal proof that holes and loops are unchanged), together proving topology is truly preserved and coarsening actually accelerates training.
