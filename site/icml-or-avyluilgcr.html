Crisp: Spectral-Based Interaction Strategy for Time Series

To forecast multiple linked variables together, talk only to neighbors whose oscillation patterns actually match, instead of either talking to no one or gossiping with everyone.

Paper explainersAll themesTime Series & Sequential

When you predict the next hour of many measurements — stock prices and trading volumes, temperature and humidity, server CPU and memory — you need to know which ones influence each other. But simple rules fail: ignoring everyone loses linked information, while listening to everyone creates phantom dependencies that do not exist. This paper finds which variables truly oscillate together in their natural frequency, then only lets those variables exchange information when forecasting.

Zero assumption version

The two bad extremes

Imagine tracking three things: a factory's electricity use, steam pressure, and production count. When you forecast the next 10 minutes of all three, you face a choice. One approach: predict each separately, ignoring that they move together. You lose real patterns — when pressure drops, production always falls. The other approach: let every variable talk to every other. But then you invent fake links — electricity use at second 47 suddenly seems to matter for production at second 51, just by random noise, and the model trusts it.

Both extremes hurt accuracy. The first misses true dependencies. The second builds phantom ones from spurious correlations.

The fix in one sentence. Only exchange information between variables whose natural oscillation frequencies match.

The algorithm as a flow

What it actually does

Transform to frequency

Convert each variable's recent history into its natural frequencies (slow, medium, fast oscillations).

Compute matching scores

For each pair of variables, measure how similar their frequency patterns are.

Build a topology

Create a graph where edges exist only between variables with matching frequencies.

Gate the attention

Force attention weights to exactly zero whenever two variables are not in the topology.

Learn the forecast

Train the model to predict the next time step using only the allowed information flows.

What the paper changes

What the paper moves

The paper tightens the connections between variables. Specifically, it changes which variables are allowed to influence each other's predictions. Instead of a fully connected graph where any variable can attend to any other, Crisp enforces a sparse, dynamic graph: attention weights between spectrally incompatible variables are forced to zero, so information only flows along paths between variables whose oscillatory patterns truly overlap.

the object it moves  =  Attention topology (which pairs talk)
The hidden quantity

The hidden quantity: Spectral compatibility

measured quantity  =  Spectral compatibility score

Every variable has a natural frequency signature — a pattern of how fast and slow it oscillates. This is what the paper measures in the frequency domain: for each variable, compute the strength at each frequency. Crisp then scores every pair of variables by comparing their frequency patterns, asking: do these two things oscillate the same way? A high score means yes.

The paper estimates this by converting each variable's time history into its frequency representation (a mathematical transform called the Fourier transform, which just means decomposing the wiggles into pure tones: how much of the slowest oscillation, how much of the next-slowest, and so on). Then it compares the two frequency signatures to see if they match. Variables with overlapping dominant frequencies get high compatibility scores; mismatched ones score low.

Why it works

Why this works: blocking noise, preserving signal

In time-series forecasting, the model learns to predict the next step by looking at recent history and inferring patterns. If it can see every variable, it will find correlations — but many of those are random noise. A model with a 20-step window looking at 100 variables has 2,000 data points to study, so it will hallucinate connections that happen to line up by accident. When you force the model to ignore spectrally mismatched pairs, you are cutting off those phantom paths before they corrupt the forecast.

The mechanism is direct: spectral compatibility filters the graph of possible influences. Variables that genuinely affect each other tend to move on related timescales — a pressure drop and production fall both happen at the same speed. Variables that are independent move on unrelated timescales, so their correlations are accidental. By erasing links between spectrally incompatible variables, the model cannot accidentally learn a spurious rule. It is forced to pick up only the true causal and correlational patterns.

The compatibility score and gating rule

First in words:

For each pair of variables i and j, measure how much their frequency signatures overlap. Compute a compatibility score s_ij. Then force the attention weight from j to i to zero if s_ij is below a threshold, otherwise allow it to be learned.

Then the compact form:

attention_weight[i,j] = 0 if s_ij < threshold, else learned_weight[i,j]

Every symbol:

attention_weight[i,j]how much variable j influences variable i in the forecast
s_ijspectral compatibility score between variables i and j
thresholdthe cutoff below which the link is permanently blocked
learned_weight[i,j]the model's learned strength of the link (if s_ij passes the threshold)
Tiny worked example
Variable A (temperature) has dominant frequencies at [0.1, 0.3, 0.05] (slow, medium, slow).
Variable B (humidity) has dominant frequencies at [0.1, 0.25, 0.08] (slow, medium-ish, slow).
Overlap: both peak at 0.1, both have medium (0.3 vs 0.25 are close). Compatibility s_AB = 0.85 (high).
Variable C (random noise) has uniform spectrum [0.2, 0.2, 0.2, 0.2, ...] (no pattern).
Overlap with A: C spreads evenly, no peaks. Compatibility s_AC = 0.15 (low).
If threshold = 0.5: A-B link allowed (0.85 > 0.5), A-C link blocked (0.15 < 0.5).

The gating rule is a hard barrier: incompatible variables cannot influence each other, removing the chance for spurious correlations to be learned.

What can go wrong

What can go wrong

Frequency domain mismatch. If two variables have a true causal link but at different oscillation frequencies, Crisp will block them. For example, a fast daily weather change and slow monthly ice melt are connected, but their frequencies do not match. The method will miss this link.
Threshold tuning. The compatibility threshold must be set right. Too high and real links are cut; too low and spurious ones slip through. The paper must adapt this per dataset or the method fails.
Transient behavior. If two variables are truly independent most of the time but correlate during rare events (e.g., a system overload), the frequency-domain view will miss the temporary link.
Done right. When variables genuinely have compatible oscillation patterns and are causally or correlatively linked, Crisp preserves these connections and learns accurate forecasts.
What a runnable demo should prove

What a runnable demo should prove

Build a synthetic time series with three variables: X and Y genuinely linked (same frequency), X and Z uncorrelated (different frequencies). Train a forecaster with full connectivity (baseline) and Crisp (sparse spectral gating). Measure the attention weights after training. The baseline will assign high weights to all pairs, including spurious X-Z links. Crisp will drive X-Z weights to zero, preserve X-Y links, and achieve lower forecast error because it does not waste capacity on phantom patterns.

Accuracy gain = (error_baseline - error_Crisp) / error_baseline, % improvement on held-out forecasts

The demo must show that Crisp's attention weights drop to zero for spectrally mismatched pairs, while the baseline keeps them high. The lower forecast error comes from not wasting capacity on phantom patterns.
