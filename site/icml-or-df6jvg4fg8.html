Hierarchical RL for Sparse-Reward Search in Commutative Algebra

Break a hard math search into two chained steps by finding the bottleneck and constraining what moves are allowed.

Paper explainersAll themesReinforcement Learning

Standard machine learning fails on hard math problems because success is so rare — you can try thousands of moves and still not solve it. This paper treats finding counterexamples to a famous algebra conjecture as a two-phase search: first reach a special bottleneck state, then solve from there. By breaking the impossible task into steps and blocking invalid moves, the approach succeeds where standard learning fails.

Zero assumption version

Why math search is different from game-playing

A standard AI learns by trying moves, getting reward signals (did that work?), and repeating. For chess or Go, you get feedback often: wins, losses, draws. For finding counterexamples to a mathematical conjecture, you get feedback almost never. A human might try 10,000 generator-additions and none of them produce a counterexample. The learner gets a zero reward 9,999 times and finally a signal once. That's reward sparsity.

A naive algorithm tries random moves until one works. A greedy algorithm picks the move that looks promising now. Neither strategy works here because both make the same mistake: they treat every step as equally important. Adding the right generators eventually is good, but there is an invisible bottleneck — a state structure the algorithm must pass through first. Without knowing this structure, the learner wastes effort on dead ends.

The problem is not randomness or luck. It is that the search space is huge, the goal is distant, and the path has a hidden checkpoint.

In one sentence. The paper breaks sparse-reward search into two phases: reach a bottleneck state first, then solve from there, and use constraints to prune invalid moves at each phase.

What the paper changes

What the paper changes: the action mask

Standard RL lets the learner try any move from any state. This paper changes the set of allowed moves at each state by using hard constraints: a mask that flags which actions are invalid and blocks them before the learner even attempts them.

The mask is different in each phase: phase 1 masks everything that doesn't lead to the spine, phase 2 masks everything that violates algebraic rules. The object being changed is the action mask (a binary flag for each possible move).

The hidden quantity

The hidden quantity: bottleneck frequency

measured quantity  =  Bottleneck state frequency

The paper measures an invisible quantity: how often does a particular state appear in successful solution paths? If the state appears in 95% of successful trajectories, it is a true bottleneck. If it appears in 5%, it is noise.

The paper estimates this by training a standard agent on a small set of examples, collecting trajectories that reach the goal, and counting state visits. High-frequency states are candidate spines. The spine is the state where the paper draws the phase boundary.

Why it works

Why constraining the search into two phases works

Standard RL explores blindly because it has no structure. The learner is like a person in a maze with no map, trying random hallways. It eventually succeeds but wastes enormous effort.

The paper's insight is that hard math problems have invisible structure: a bottleneck. Once you identify this bottleneck empirically (by watching what works), you can exploit it. Instead of learning one long policy, the paper learns two shorter policies, each with constraints that block invalid moves. Phase 1 learns to reach the bottleneck; phase 2 learns to finish from there.

The payoff is dramatic: both phases are now shorter, simpler problems. The learner spends no energy on moves that go the wrong direction (phase 1 blocks them), and no energy on moves that violate algebra rules (phase 2 blocks them). The action space shrinks, the path to the goal becomes clearer, and learning succeeds. The paper proves this via an equivariant graph neural policy, which respects the symmetry of the algebra: if two generator-sets are algebraically equivalent, the policy treats them the same way. This symmetry awareness further speeds learning.

The constraint formula and reward

First in words:

For each option (phase), a hard constraint masks invalid actions before the learner sees them. The reward is a fixed penalty per step (negative one) until the goal is reached, ensuring the learner finds short paths. A hard mask applied to the policy output sets invalid actions to very large negative values, forcing the learner to ignore them.

Then the compact form:

r(s, a, s') = -1 (cost per step); logits_masked[a] = logits[a] if a in C(s) else -infinity; policy = softmax(logits_masked)

Every symbol:

r(s, a, s')reward for taking action a from state s to next state s'
C(s)set of constrained valid actions at state s
logits[a]raw network score for action a before masking
logits_masked[a]network score after applying the hard constraint mask
-1cost for each step (encourages short solutions)
-infinity (approx -1e9)punishment for invalid actions
A tiny worked example
State S (5 generators): policy outputs raw scores [0.2, 0.5, 0.3, 0.1, 0.4].
Constraint C(S) says actions 0, 2, 4 are valid (move toward spine).
Hard mask sets invalid actions to -1e9: logits_masked = [0.2, -1e9, 0.3, -1e9, 0.4].
Softmax converts to probabilities [0.25, 0, 0.35, 0, 0.40] (valid actions only).
Learner now only tries moves 0, 2, 4. Moves 1, 3 have zero chance, no wasted exploration.

Hard masking forces the policy to respect structure; the learner never wastes steps on forbidden moves.

What can go wrong

What can go wrong

Wrong spine choice If the identified bottleneck is not actually a necessary waypoint, phase 1 may force the learner away from all solutions. The paper verifies spines by checking that removing them blocks all solutions in the training set.
Overly strict constraints If phase 2 blocks too many algebraic moves, the learner cannot reach any goal from the spine. The paper uses both hard constraints (guaranteed to preserve all solutions) and soft constraints (gentle nudging) to balance.
Backbone architecture mismatch A standard neural network can fail to respect algebraic symmetry, leading to poor generalization across different generator sets. The paper uses an equivariant graph neural network (syzygy-aware message passing) to handle this.
Done right The paper verifies that spines are necessary, constrains are sufficient (solutions still reachable), and the graph network learns symmetries, so the approach generalizes across problem sizes and degrees.
What a runnable demo should prove

What a runnable demo should prove

A minimal demo generates a random commutative algebra problem (5–10 generators, degree 3–4), trains a standard end-to-end RL agent and a two-phase constrained HRL agent on the same budget (10,000 steps each), and counts how many times each agent finds a non-Hirsch ideal. Measure also the average number of steps needed for successful runs.
