FAHNES: Feature-Aware Graph Generation via Next-Scale Prediction

Generate large graphs and hypergraphs by building them layer-by-layer, from coarse to fine, while keeping track of both the connections and the features that describe each node and edge.

Paper explainersAll themesGraph & Geometric Learning

Building a large detailed social network or 3D mesh all at once fails because the model has to decide millions of connections and properties simultaneously. FAHNES breaks the problem into steps: first, sketch the coarsest outline of the graph, then refine and add details level by level. The trick is making sure the features that describe each node stay consistent across all these levels.

Zero assumption version

Why generating large graphs is stuck

A graph is just a set of nodes (points) connected by edges (lines). In real applications, each node and edge carries information: a person has a name and age, a protein has a chemical property, a road has a speed limit. These are called features.

Simple models try to generate everything at once: create all the nodes, assign all their features, draw all the edges. On tiny graphs this works fine. But as the graph grows—from 100 nodes to 10,000 to a million—the model must make exponentially more decisions simultaneously, and quality crashes. The model cannot keep all these decisions consistent in its memory.

Hierarchical models tried to fix this by building coarse-to-fine: make a sketch first, then add details. But they cheated: they only generated the connections, not the features. Features were either ignored or predicted carelessly, breaking the realism of the result.

In one sentence. FAHNES generates large graphs by building them level by level (coarse to fine) while keeping node and edge features consistent across all levels.

The algorithm as a flow

What it actually does

Start coarse

Begin with a few big clusters and rough features; this is the simplest version.

Encode scale

Inject a signal that says which refinement level the model is at (coarse, medium, fine).

Expand clusters

Each big cluster splits into smaller ones; the model predicts new nodes within it.

Refine features

Update each node's feature list to stay true to parent clusters and the scale signal.

Repeat

Keep refining until the graph is as large and detailed as needed.

What the paper changes

The one thing the paper changes

Instead of generating all node features and all edges separately, FAHNES makes them grow together: each refinement level expands both the network structure and the features that describe it. The key innovation is forcing the model to respect a hierarchy—coarse features constrain fine features—by encoding the current scale level and ensuring consistency across boundaries.

the object it moves  =  Features and topology, jointly.
The hidden quantity

Cross-scale consistency: the hidden quantity

measured quantity  =  Feature drift across refinement levels

When you split a coarse node into finer ones, each child node gets a new detailed feature list. But child features must stay loyal to the parent's coarse feature. For example, if a coarse node represents a large city with a high population count, when you split it into smaller neighborhoods, each smaller node should inherit that city-like property—keeping population count high—not drift to a tiny count (which would be incoherent).

FAHNES measures this drift by using a hierarchical scale encoding—a learnable signal that marks the current refinement level. The model predicts what features should be at that scale, guided by the signal. The paper does not compute an explicit numerical drift score, but the scale encoding acts as an anchor: if the model strays too far from the parent's feature, the next refinement will fail.

Why it works

Why it works: the causal chain

Generating a full large graph at once forces the model to juggle millions of independent choices, and each choice has to be compatible with all the others. This is impossible because the model has no way to focus its processing or propagate corrections.

FAHNES breaks it into a ladder. At each level, the model only has to predict a small number of new things: split a node, predict new features, add local edges. The scale encoding tells the model which level it is at, so it knows whether to think coarse or fine. Because each level inherits from the previous one, the model can check: does this new fine detail contradict the coarse parent? If so, the scale encoding and the loss function steer the model back into line.

The mechanism: coarse-to-fine generation reduces the branching factor (choices per step), and the scale encoding provides feedback that keeps child details aligned with parent properties. Together, they make the generation process tractable and produce consistent, large graphs.

The equation behind it

First in words:

Total loss equals the node prediction loss plus the edge prediction loss plus a consistency penalty that grows if child features drift too far from their parent values, scaled by the refinement level.

Then the compact form:

L = L_nodes + L_edges + lambda(s) * sum_i ||f_child(i) - f_parent(i)||^2

Every symbol:

Ltotal loss (error to minimize)
L_nodesloss from predicting which nodes exist
L_edgesloss from predicting which edges connect nodes
f_child(i)features of fine node i
f_parent(i)inherited features from its coarse parent
lambda(s)penalty strength, depends on scale level s
||...||^2squared distance (how far apart two feature lists are)
A tiny worked example
Suppose a coarse node has feature parent_feat = [5.0, 2.0] (population category and connectivity).
At the next refinement, the model generates a child node with child_feat = [4.8, 2.1].
Distance squared: (5.0 - 4.8)^2 + (2.0 - 2.1)^2 = 0.04 + 0.01 = 0.05.
If lambda(scale_2) = 10, the consistency penalty adds 10 * 0.05 = 0.5 to the total loss.
The model learns: small child-parent drift is cheap; big drift (e.g., child_feat=[1.0,1.0]) would cost 10*(4.0+1.0)=50, so avoid it.
This steers the model to refine smoothly, not contradict itself.

The scale-dependent penalty lambda(s) grows at finer levels, forcing tighter alignment between child and parent, which is why coarse details propagate faithfully through refinement.

What can go wrong

What can go wrong

Scale signal mismatch. If the model receives a scale signal but ignores it, or if the scale signal is not incremented correctly, child features will not inherit from parents and drift wildly.
Consistency penalty too weak. If lambda(s) is set too low, the cost of child-parent drift is negligible and the model learns to contradict itself across levels.
Over-coarsening. If the initial coarse graph is too simplified, the finer levels have no good parent to inherit from and end up fabricating features.
Done right. When the scale signal is reliable, lambda(s) is tuned per level, and the initial coarse graph captures the true structure, features propagate smoothly and the final graph is both large and realistic.
What a runnable demo should prove

What a runnable demo should prove

Take a real large graph (e.g., a 3D mesh of an object, or a point-cloud graph of a room). Remove all feature information and split it into coarse and fine levels by hand. Implement a simplified FAHNES: predict coarse features, then refine to fine features using a scale signal and a consistency penalty. Measure how well the fine features stay aligned with coarse ones as you go deeper.

Feature consistency = 1 - (mean absolute difference between child and parent features) / (max possible difference); ranges from 0 to 1.

The demo must show that without the scale signal and penalty, consistency crashes as the graph gets refined; with them, it stays high (>0.8) even at 10+ refinement levels.
