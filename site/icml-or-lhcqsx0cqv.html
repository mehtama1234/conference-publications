Design Linear Constrained Neural Layers with Implicit Convex Optimization

A neural network layer that enforces hard constraints on predictions by solving an optimization problem inside the layer itself.

Paper explainersAll themesOptimization

Standard neural networks can predict anything — a confidence that goes negative, a probability that does not sum to 1, a portfolio that breaks budget. Sometimes the real world has hard rules: probabilities must add up to 1, or a route must stay on the road. This paper builds a layer that slips into any neural network and forces its outputs to obey such rules, without hand-coding a custom layer for each constraint type.

The constraint trap

Neural networks output raw numbers with no regard for real-world rules. A classifier might output probabilities that do not add to 1. A portfolio optimizer might allocate more than the available budget. A matching algorithm might route flows that violate capacity limits. A naive fix is to hand-craft a special layer for each constraint type — one layer for probabilities (called Softmax), another for matching (called Sinkhorn), another for bounds (called tanh). But there are thousands of possible constraint types, and hand-crafting each one is tedious and error-prone.

A beginner might try to just clip the output to valid values after the fact, or add a penalty term to the training loss that punishes constraint violations. But clipping can destroy gradients (the directions that steer training), and penalties are weak — they nudge the network toward valid outputs, but do not guarantee it ever reaches them.

In one sentence. The paper replaces hand-crafted constraint layers with a single layer that solves a tiny optimization problem (a mathematical puzzle) inside itself to enforce any linear constraint.

What the paper changes

What the paper changes

Every standard layer multiplies its input by learned numbers (weights) and adds a fixed shift, producing raw output. This paper inserts a new layer after those weights that does one extra job: it solves a tiny constrained optimization problem — a mathematical puzzle — to project the raw output onto the set of valid solutions. It replaces ad-hoc hand-coded constraint layers with one flexible layer that handles any linear constraint.

the object it moves  =  the output after prediction
The hidden quantity

The distance measure

measured quantity  =  divergence between raw and constrained

The layer needs to decide which valid output to pick when many could satisfy the constraint. It measures distance between the network's raw guess and each valid candidate. The paper uses two flavors: first, a divergence based on KL-divergence (a way to measure how different two probability distributions are — how far apart the shapes are in number-space), which recovers classic layers like Softmax; second, a Euclidean distance (the straight-line distance, like measuring with a ruler), which has a closed-form solution (a formula you can compute instantly with no iterative solving).

By minimizing this distance, the layer finds the valid output closest to what the network tried to predict. This keeps training stable — the network is steered gently toward valid outputs, not forced through a cliff.

Why it works

Why the constraint layer works

The network's raw output typically violates the constraint — it is in the wrong region. The layer's job is to move the output to the nearest valid region. Two effects make this work: first, the layer always moves outputs in a direction that shrinks the constraint violation, so the network never predicts an invalid answer even during training; second, because the layer moves by the minimum amount (it finds the closest valid point), the gradient signal back to the network remains clear and strong — the network learns which direction to nudge its numbers to reduce the constraint gap on the next try.

Over time, the network learns to predict outputs already close to valid, and the layer's correction becomes smaller and smaller. By the time training finishes, the network rarely needs a big correction.

The constraint enforcement formula

First in words:

divergence from raw to constrained = minimize the distance D(y*, y_raw) such that the constrained output y* satisfies the constraint Ay* = b

Then the compact form:

min_y* D(y*, y_raw) such that A*y* = b

Every symbol:

y*the corrected output that satisfies the constraint
y_rawwhat the network predicted before constraint-fixing
Ddistance measure (KL-divergence or Euclidean distance)
Amatrix that encodes the linear constraint
bthe right-hand side of the constraint (the target sum, etc)
A tiny worked example
Network predicts y_raw = [30, 40, 50] (sum is 120, violates budget limit 100).
Constraint is: y1 + y2 + y3 = 100.
Layer solves: find y* closest to [30, 40, 50] such that it sums to 100.
If we use Euclidean distance, the solution shrinks each value proportionally: y* = [30*(100/120), 40*(100/120), 50*(100/120)] = [25, 33.33, 41.67].
Check: 25 + 33.33 + 41.67 = 100 — constraint satisfied.
Distance moved: sqrt((30-25)^2 + (40-33.33)^2 + (50-41.67)^2) = sqrt(25 + 44.45 + 69.44) ≈ 12 units.
Gradient flows back: network learns y_raw=120 was too large, try predicting smaller next time.

The paper derives a closed-form formula (instant answer) for Euclidean distance, called GLCLayer, avoiding iterative solving.

What can go wrong

What can go wrong

Non-linear constraints fail. The paper handles only linear constraints (constraints that are sums and linear combinations). Real problems with circular routes, inequality bounds, or product constraints need other methods.
The solver is slow for huge problems. The layer solves an optimization problem at every forward pass. For problems with thousands of constraints or millions of variables, the solver becomes a bottleneck, even if it is fast by solver standards.
Gradient becomes small if correction is large. If the network makes a very wrong prediction and the layer has to move it far, the gradient signal can become diluted (noise drowns it out), and the network learns slowly. Early training must steer toward the valid region first.
Done right. When constraints are truly linear (sums, linear combinations, conservation laws) and the network starts with reasonable initialization, the layer enforces the constraint perfectly while keeping training stable.
What a runnable demo should prove

What a runnable demo should prove

Build a simple neural network that predicts portfolio weights (how much money to put in each stock). The constraint is: the weights must sum to 100 (you must spend your full budget). Without the constraint layer, the network's raw predictions would sum to random values (maybe 87, maybe 156). Add the GLCLayer (the fast Euclidean version), and the network's output always sums to exactly 100. Train it on a simple synthetic task (e.g., maximize expected return given historical returns), and measure two things: (1) does the output always sum to 100? (2) does the network learn faster and to higher accuracy than a network with a penalty term (unconstrained loss plus a soft term punishing non-100 sums)? Hard constraints force the network into valid territory every step, so it never wastes updates learning from invalid predictions. A soft penalty only nudges the network toward validity, allowing many wasted updates on predictions far from valid.

accuracy_with_layer - accuracy_with_penalty_only = how much better the network learns when the constraint is hard, not soft

The demo should show that hard constraints, enforced by the layer, give faster training and higher final accuracy than soft penalties, because the layer corrects the network's prediction immediately (in one solver step), while soft penalties require many training steps to nudge it toward valid region, wasting updates that could improve the actual task.
