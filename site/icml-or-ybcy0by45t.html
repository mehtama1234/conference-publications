MV-FGAD: Multi-View Federated Graph Anomaly Detection

Federated graph anomaly detection using multiple views and shared knowledge to catch both obvious and subtle abnormal nodes.

Paper explainersAll themesGraph & Geometric Learning

When multiple organizations need to find abnormal nodes (fraud, defects, attacks) in their separate graphs without sharing raw data, the standard approach fails: each organization tries to spot anomalies in its own chunk of graph, but anomalies are often subtle and hidden in the structure. This paper shows that splitting the graph across organizations breaks the old neighbor-aggregation detection strategy, and introduces a method that learns a shared knowledge base about normal patterns across all organizations and uses multiple angles of view to catch weak anomalies others miss.

Zero assumption version

Why existing federated anomaly detection breaks

Imagine multiple hospitals, each with a patient network and health records, trying to spot diseases spreading silently through connected patients. Each hospital only sees its own network chunk. The old approach says: look at each patient's neighbors and if they stand out, flag them as sick. But here is the snag: if a disease spreads slowly through the network in a way that looks almost normal (weak signal), and the hospital only sees a tiny piece of the network, the neighbors do not add up to enough evidence to raise an alarm.

Equally damaging: when you split the graph across hospitals, every organization learns its own local detector in isolation. No organization sees the full pattern of normal behavior, so no one builds a good baseline to detect subtle outliers.

In one sentence. The method learns a shared knowledge base of normal patterns across all organizations and uses multiple scoring angles to catch anomalies weak and strong.

The algorithm as a flow

What it actually does

Each site builds a local detector

Hospital A learns patterns from its own patient network chunk.

Federated knowledge exchange

Every hospital sends only a compressed summary (not raw data) of normal node patterns to a central server.

Shared baseline is refined

Central server combines all summaries into one global template of what normal looks like.

Broadcast back and refit locally

Each hospital receives the shared baseline and retrains its local detector using both its own data and this global baseline.

Score nodes through multiple lenses

Each node is scored separately on several learned views; a node is flagged if it stands out in any view.

What the paper changes

What the paper changes

The paper changes how local detectors are built: instead of training each hospital's detector in isolation, it first learns a shared knowledge base from all hospitals and uses that to guide the local detector. It also changes how a node is scored from one number to multiple numbers (one for each view), catching more types of weak anomalies.

the object it moves  =  local detector + scoring strategy
The hidden quantity

The hidden quantity: anomaly strength

measured quantity  =  How far a node sits from normal

The paper's core insight is that anomalies come in two kinds: strong anomalies scream loud and obvious to any detector; weak anomalies whisper and are nearly silent. The hidden quantity is the distance from normal, usually measured in a learned space where normal nodes cluster tightly. But simply squashing the graph into one space (one view) fails: weak anomalies that are anomalous in one way may blend in when projected to a single view.

MV-FGAD measures this distance using Mahalanobis distance (a statistical measure that accounts for how spread out normal nodes are in each direction). By learning multiple separate spaces (views), each one sensitive to different kinds of weirdness, the method gives weak anomalies more chances to stand out.

Why it works

Why it catches more anomalies

The key is federated knowledge exchange. In isolation, a hospital with only 50 patients cannot learn what true normal looks like. But if 10 hospitals pool their knowledge (without sharing raw data), normal looks like 500 patients' worth of patterns, and anomalies stand out crisply by comparison. This shared baseline is then fed back to help each local detector refit: the detector now has a much better reference model of normal, so it can confidently say a borderline node is weird because it differs from the pooled-knowledge normal in ways the isolated local normal would have tolerated as routine variation.

The second key is multi-view learning. Anomaly types vary: some nodes have weird attributes (age seems wrong for the diagnosis), others have weird network position (connected to unlikely neighbors), others have weird structural roles. A single view collapses these onto one axis and weak signals in the minority direction get lost in noise. Multiple views each tune to different anomaly types, so weak signals in each view are amplified.

The anomaly scoring equation

First in words:

For each view, the score of a node is the Mahalanobis distance from the mean of normal nodes, weighted by the inverse of the covariance matrix so that deviations in thick-spread directions are softer than deviations in tight directions. A node is an anomaly if its score is larger than a threshold.

Then the compact form:

score_v(x) = sqrt( (x - mu_v)^T * Sigma_v^-1 * (x - mu_v) )

Every symbol:

xthe node's feature values (a list of numbers)
mu_vthe average of normal nodes in view v
Sigma_vhow much normal nodes spread in each direction in view v
Sigma_v^-1the inverse; makes tight directions punish deviations more
score_v(x)how far x is from normal in view v
sqrt(...)take the square root so the score stays interpretable
A tiny worked example
Imagine view 1 measures graph position (one number per node). Normal nodes average 50, spread is 10 (variance).
Node A has value 70. Score_1(A) = sqrt( (70-50)^2 / 100 ) = sqrt(400/100) = sqrt(4) = 2.0.
Now view 2 measures attribute weirdness. Normal average 30, spread is 5 (tighter).
Node A has value 35 in view 2. Score_2(A) = sqrt( (35-30)^2 / 25 ) = sqrt(25/25) = 1.0.
Node A: score 2.0 in view 1, score 1.0 in view 2. If threshold is 1.5, A is flagged in view 1.
A weak anomaly might score 1.2 in view 1 and 1.4 in view 2: alone both pass the threshold, but multiple views together signal it.

Mahalanobis distance lets tight directions scream loud (high penalty for small deviations) while loose directions tolerate noise, so weak signals in rare directions are amplified.

What can go wrong

What can go wrong

Federated server becomes a bottleneck. If the central server is slow or unreliable, the entire system stalls because all sites must wait for the shared baseline. The method works best when the central server can aggregate and broadcast quickly.
Threshold tuning across multiple views is tricky. With one view you pick one threshold; with five views you must decide whether to flag a node if any view screams, or only if most do. The paper must choose this carefully or you get either too many false alarms or too many misses.
Views can be redundant or fail to capture all anomaly types. If all learned views are similar (because the learning process got stuck in one local pattern), the multi-view gain vanishes. If real anomalies do not fit any of the learned views, they go invisible.
Federated knowledge exchange is non-trivial in practice. Compressing node patterns into summaries that preserve normal behavior is an art; if the compression is lossy and destroys important variance information, the shared baseline becomes unreliable.
What a runnable demo should prove

What a runnable demo should prove

Build a toy federated scenario with three simulated hospitals, each with 100-node network. Insert a few obvious anomalies (high-degree outliers) and a few subtle ones (nearly-normal structure but weird attributes). Run the old single-view method and MV-FGAD. Count how many of each type of anomaly each method catches. Plot the detection rate (anomalies caught) and false-positive rate (normal nodes wrongly flagged) for both methods as you vary the threshold from strict to loose.

detection rate = anomalies caught / total anomalies; false positive rate = normal nodes flagged / total normal nodes

The demo must make clear that at equal false-alarm rates, MV-FGAD catches roughly twice as many weak anomalies as the single-view baseline.
