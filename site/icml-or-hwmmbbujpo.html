Ask Less, See More: Communication-Conditioned Token Pruning for Vehicle-to-Vehicle Cooperative Autonomous Driving with Multimodal Large Language Models

Reduce what cars send to each other by keeping only the visual pieces that matter for the driving question and the road area not already seen by another car.

Paper explainersAll themesAgents & Tool Use

In cooperative driving, one car can ask nearby cars for help because buildings, trucks, or parked cars can block its view. The difficulty is cost. If every car sends all of its visual evidence, communication load rises quickly and answering time also rises because the receiving model must process too much repeated material. This paper builds a two-stage sharing rule that keeps question-relevant evidence and removes repeated road coverage so that cooperation stays useful without flooding the system.

Zero assumption version

Why cooperative driving agents send too much

A driving agent may need help from nearby cars because its own sensors cannot always see an important area. Existing cooperative systems often share dense internal visual representations from each helper car. That solves the visibility problem, but it creates two new ones. Communication grows with every helper, and much of the shared content overlaps because several cars can already see the same road area.

A second issue is question mismatch. If the task is to answer whether a pedestrian is about to enter the lane, only a small part of the shared evidence matters. Sending everything wastes bandwidth and slows the answer step because the receiving model must inspect many irrelevant pieces before it reaches the useful ones.

The paper's move in one sentence. Broadcast one message about the question and one message about already-covered road areas, then keep only the shared visual pieces that answer the question or add unseen coverage.

The algorithm as a flow

What it actually does

Create a question summary

Encode the current driving question into a compact message that tells helper cars what kind of evidence matters.

Create a coverage summary

Summarize which road areas each helper already observes so that overlap can be detected before sharing.

Score local visual pieces

Each helper scores its visual pieces by question relevance and by whether they cover an unseen area.

Keep only useful non-overlapping pieces

Discard low-value or repeated pieces so that communication load falls before multi-car fusion.

Answer with the reduced shared set

Fuse the kept pieces and produce the final driving answer using less communication and less repeated processing.

What the paper changes

What the paper changes

The paper changes the sharing policy between cars. Instead of treating every helper's internal visual state as equally worth sending, it conditions sharing on the driving question and on road coverage overlap.

the object it moves  =  Which helper evidence gets transmitted during cooperative reasoning
The hidden quantity

Utility of a shared visual piece

measured quantity  =  Question-and-coverage utility

The key hidden quantity is how useful each candidate shared visual piece will be after transmission. A piece is useful because it helps answer the present question or reveals road area the main car has not already covered. A piece is wasteful when it repeats what another helper already showed or when it comes from a region unrelated to the question.

The paper approximates this quantity with two compact messages. One says what the question is asking for, and the other says which road regions are already covered. By combining them, each helper can keep the evidence that matters and suppress the evidence that would mostly repeat earlier content.

Why it works

Why the dual message rule works

Question conditioning helps because cooperative driving questions are narrow. A safety query usually depends on a few regions, not on every visible point in every helper car. If helpers know the question intent, they can preserve the road evidence that directly affects the answer and remove unrelated content before transmission.

Coverage conditioning helps because many helpers partially see the same area. When overlap is recognized early, repeated evidence can be dropped before it consumes bandwidth. The combined rule works well because it keeps new useful evidence by favoring unseen relevant regions and cuts cost by filtering repeated or irrelevant regions at the source.

A simplified keep score

First in words:

Score each candidate shared piece by adding question relevance and unseen road coverage, then subtract overlap cost so that repeated evidence is unlikely to be sent.

Then the compact form:

keep_score_i = alpha * question_relevance_i + beta * new_coverage_i - gamma * overlap_i ; send_i = 1 if keep_score_i > threshold else 0

Every symbol:

keep_score_ivalue of shared piece i before transmission
question_relevance_ihow strongly piece i helps answer the current driving question
new_coverage_ihow much new road area piece i reveals
overlap_ihow much of piece i repeats evidence already available from other cars
alphaweight on question relevance
betaweight on new road coverage
gammapenalty on repeated coverage
thresholdminimum score needed to transmit piece i
A tiny worked example
Piece A shows the hidden crosswalk entry: question_relevance = 0.9, new_coverage = 0.8, overlap = 0.1.
With alpha = 0.5, beta = 0.4, gamma = 0.6, keep_score_A = 0.5 * 0.9 + 0.4 * 0.8 - 0.6 * 0.1 = 0.71.
Piece B shows the lane center already seen by two cars: question_relevance = 0.3, new_coverage = 0.1, overlap = 0.8.
keep_score_B = 0.5 * 0.3 + 0.4 * 0.1 - 0.6 * 0.8 = -0.29.
A is sent and B is dropped because A adds new task-relevant evidence while B mostly repeats known information.

The paper uses a richer architecture, but this simplified score captures the main idea: transmit evidence when it is useful for the question and not already covered.

What can go wrong

What can go wrong

The question message can miss the real need. If the question summary is weak, a helper may drop useful evidence because it misjudges what the main car is trying to answer.
Coverage estimates can be stale. If positions change quickly, overlap estimates may lag behind the scene so that a helper suppresses evidence that is no longer duplicated.
Rare hazards may look low-value. An unusual but important clue can be pruned if it does not fit the common question pattern, so safety-oriented fallback rules still matter.
Done right. Use strong question encoding, keep coverage updates fresh, and reserve a safety budget for uncertain evidence so that pruning reduces cost without hiding rare hazards.
What a runnable demo should prove

What a runnable demo should prove

Build a small cooperative driving task with two or three cars and a set of road questions about occluded areas. For each helper car, split its local sensor view into candidate shared pieces. Compare three systems: send everything, keep pieces using question relevance only, and keep pieces using both question relevance and coverage overlap. Measure answer quality, communication bytes, and repeated shared area.

The demo should prove that the dual-message rule is better than dense sharing because it keeps the hidden useful evidence while dropping repeated content, and better than question-only pruning because it explicitly removes overlap across helpers.

efficiency = answer_quality / communication_bytes ; overlap_rate = repeated_shared_area / total_shared_area

A convincing demo shows lower bandwidth, lower overlap, and stable answers because the system shares only what the question needs and what the main car cannot already see.
