Uncover Underlying Correspondence for Robust Multi-view Clustering

When you have photos and sketches of the same objects but the labels are scrambled, recover which ones really match before clustering them.

Paper explainersAll themesRepresentation & Self-Supervised Learning

Multi-view clustering takes pictures of objects from different angles or sources and groups them by finding which ones belong together. The trouble: real-world data from the web has mixed-up labels. Sometimes a sketch and photo of the same cat are marked as different things; sometimes a pair of images do not actually show the same object at all. CorreGen recovers which pairs are real matches before clustering, using a statistical method that treats the true matches as hidden and gradually learns them.

Zero assumption version

Scrambled pairs break clustering

When you have two versions of the same data (a photo and a sketch, or the same video from two camera angles), clustering groups similar things together by comparing all versions at once. The method assumes that if object A and object B are the same thing, their photo and sketch versions will sit close to each other in a learned space of numbers, so the grouping will find them.

But web data is messy. Labels linking photo to sketch are wrong. Two problems break clustering: first, a photo and sketch of the same cat might be marked as belonging to different categories, so the method treats them as opposite things and pushes them apart. Second, a photo might be paired with a completely different sketch, so those two never should have been linked at all.

A beginner would try to ignore the bad labels entirely and just cluster by sight. But then you lose the power of having two views — you are back to single-image clustering, which is weaker. You need to fix the labels, not throw them out.

In one sentence. CorreGen learns which pairs are truly the same object while clustering, by treating the true matches as a hidden puzzle and solving it iteratively.

The algorithm as a flow

What it actually does

Initialize embeddings (lists of numbers)

Learn a list of numbers for each photo and sketch.

E-step: find soft matches

For each photo, compute how likely it is the true partner of each sketch, using a bell curve around each sketch's position.

Weight down bad pairs

Lower the importance of photo-sketch pairs that do not fit together, using a learned bell curve model.

M-step: update embeddings

Nudge photo and sketch numbers to be closer to their likely partners, weighted by match confidence.

Repeat until stable

Run E-step and M-step until the matches stop changing and clustering converges.

What the paper changes

What the paper changes

The paper changes which photo-sketch pairs count as evidence for clustering. Instead of trusting all pairs equally, it learns soft weights — a number between 0 and 1 for each pair saying how much we believe they match. Bad pairs get weight near zero and barely influence clustering; good pairs get weight near one and pull the clustering together.

the object it moves  =  pair confidence weights
The hidden quantity

The true correspondence

measured quantity  =  soft match probabilities (a pattern of confidence levels)

Each photo could be partnered with many sketches. A soft match distribution is a list of probabilities: how likely is this photo the real partner of sketch 1, sketch 2, sketch 3, and so on? A value close to 1 means yes, close to 0 means no. The list always sums to 1, like betting your entire pot across multiple horses.

The paper estimates this hidden distribution in the E-step of the EM algorithm by comparing the position of the photo (its list of numbers) to each sketch's position, using a bell curve model that respects the underlying category structure. If the photo and a certain sketch are far apart in the learned space, the probability that they match drops sharply. If they are close, it rises. The bell curve is centered on each sketch, so the software gives high probability only to nearby photos.

Why it works

Why the method works

The core insight is that the true matches are hidden — you cannot see them directly, but you can infer them from the data. The EM algorithm treats the hidden matches as a puzzle and solves it in two steps, back and forth.

In the E-step, you compute soft matches: a probability for each pair based on their closeness in the learned space. Photos and sketches that are far apart get low probability (they probably do not match); nearby ones get high probability. A bell curve model encodes the class structure, so the software learns that cat photos belong near cat sketches, not dogs.

In the M-step, you update the embedding space (the list of numbers for each photo and sketch) to maximize the likelihood of the true matches you inferred. You pull partnered items closer and push unpartnered ones apart, but only as much as the soft weights permit. A pair marked with low probability in the E-step barely moves the embeddings; a high-probability pair moves them strongly.

Each round, the inferred matches improve because the embeddings are now better aligned with the true categories. You iterate until the matches and embeddings stabilize. This is more honest than trusting the scrambled labels from the start, because the method learns which labels are reliable and which are garbage.

Math after the picture

The equation

First in words:

maximize the likelihood of observed cross-view pairs given the latent true correspondences; solve via EM by inferring soft match probabilities in E-step and re-learning embeddings in M-step with GMM-weighted terms.

Then the compact form:

E-step: P(sketch_j | photo_i) ∝ exp( -distance(photo_i, sketch_j)^2 / sigma ) * class_weight; M-step: minimize sum over i,j of P(i,j) * distance(embedding_i, embedding_j)^2 + regularization

Every symbol:

distance(a,b)Euclidean distance between two embedding vectors
sigmawidth parameter of the bell curve
class_weightlearned weight favoring same-category pairs
P(i,j)probability that photo i and sketch j are true matches
regularizationpenalty for changing embeddings too much
A tiny worked example
Start: photo_cat is at position [0.5, 0.3], sketch_cat at [0.48, 0.31].
Distance between them: sqrt((0.5 - 0.48)^2 + (0.3 - 0.31)^2) = sqrt(0.0004 + 0.0001) = 0.022.
Plugging into bell curve: P(photo_cat, sketch_cat) = exp(-(0.022)^2 / 0.01) * 1.0 = exp(-0.048) = 0.953 — very likely a match.
Now photo_dog at [0.7, 0.6], sketch_cat at [0.48, 0.31].
Distance: sqrt((0.7 - 0.48)^2 + (0.6 - 0.31)^2) = sqrt(0.0484 + 0.0841) = 0.361.
P(photo_dog, sketch_cat) = exp(-(0.361)^2 / 0.01) * 0.1 = exp(-13.03) * 0.1 = 2e-6 — almost certainly not a match.
In M-step, embeddings move to honor the high-probability pair (cat-cat) but barely budge for the low one (dog-cat).

The bell curve width and class weights are learned by the algorithm; they act like knobs that tune how much mismatch you tolerate before downgrading a pair.

What can go wrong

What can go wrong

Too much noise, bell curve fails. If the scrambled labels are so bad that the bell curves cannot find any signal (cat photos and cat sketches scattered randomly), the EM algorithm stalls. The E-step produces nearly uniform match probabilities saying every pair is equally likely, so embeddings change very little — there is no signal to pull items of the same category together.
Unlabeled pairs are hard to detect. Sometimes a photo has no correct sketch partner at all; it is pure garbage. The algorithm must down-weight it, but only if the bell curve model and category weights are tuned well enough to recognize the orphan.
Stuck local optimum. EM can converge to a local best answer that is not the global best. If early rounds infer matches poorly, the embeddings move in a wrong direction and stay wrong.
Done right. When most labels are recoverable and the category structure is clear, EM learns true matches and stabilizes at a good clustering, rejecting noise without losing signal.
What a runnable demo should prove

What a runnable demo should prove

Take a small dataset of objects photographed and sketched (e.g., 50 objects, 100 photo-sketch pairs). Intentionally scramble 30 percent of the links randomly. Run CorreGen for 20 iterations, saving the inferred match probabilities at iterations 1, 5, 10, 15, 20. Plot a heatmap showing how the high-probability pairs (diagonal if perfect) emerge over time. Measure clustering purity (fraction of clusters that are pure — all items from one category) at each iteration. Show that purity rises as the algorithm recovers true matches and that the final clustering with recovered matches beats clustering with the original scrambled labels.

purity = sum over clusters of (max category count in that cluster / cluster size) / number of clusters

The demo must show the match-probability heatmap transforming from scrambled (uniform gray, all pairs equally likely) to clean (bright diagonal, same-object pairs confident) as EM iterates, because updating embeddings toward inferred matches gradually aligns items of the same category.
