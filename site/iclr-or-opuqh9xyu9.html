Multi-LLM Adaptive Conformal Inference for Reliable LLM Response

Instead of throwing out true claims to be overly safe, use multiple LLMs to spot which claims are actually factual, then give a guarantee that holds for different groups.

Paper explainersAll themesAlignment, Safety & Fairness

When an LLM answers a medical or legal question, you need to know which answers to trust. The challenge: if you reject claims too cautiously, you discard real facts. If you reject too loosely, unsafe claims slip through. MACI solves this by multiplying together confidence scores from multiple LLMs and carefully guaranteeing that users see a predictable amount of correct claims, even when different groups of people ask.

The two traps of factuality checking

An LLM can confidently output false information. In medicine or law, a wrong answer causes real harm. So you need a guardrail: a threshold below which you refuse the LLM's claim.

But here is the trap: if you set the threshold conservatively, you reject too many true claims along with the false ones. If you set it loosely, you let dangerous false claims through. And the problem gets worse when you look at subgroups: a threshold that works for medical claims might fail for legal ones, or work for expert questions but fail for layperson ones.

Naive approaches use simple linear models or fixed rules to decide what to reject. These are too rigid to capture the messy reality that some domains, question types, or user groups have different patterns of what is true.

The problem in one sentence. You need a way to reject false claims without losing true ones, and guarantee it works fairly across different groups.

The algorithm as a flow

What it actually does

Collect ensemble scores

Feed the claim to multiple LLMs and ask each for a factuality score.

Multiply the scores

Instead of averaging, multiply them; this emphasizes claims all models agree on.

Find group thresholds

For each group (e.g., medical vs. legal), find the threshold that gives the right coverage rate.

Accept or reject

If the multiplied score exceeds the group threshold, accept the claim; otherwise reject.

Verify guarantee

The coverage (fraction of true claims retained) holds mathematically for each group.

What the paper changes

What the paper changes

The paper shifts from a single LLM judge or a simple linear model to a multiplicative product of ensemble scores. It also shifts from a global reject threshold to a per-group threshold that is tuned so each group sees the promised coverage rate.

the object it moves  =  scoring and thresholding strategy
The hidden quantity

Coverage rate: the guarantee that actually holds

measured quantity  =  Coverage rate per group

Coverage is the fraction of true claims your system accepts. If you promise 95% coverage, you mean: of all the true claims, your system keeps 95% and rejects only 5%. This is a distribution-free guarantee—it holds regardless of where the claims come from or what the LLM learned, because it is defined purely from observed data.

The paper estimates coverage by measuring: on a validation set from each group, what fraction of the claims flagged as true by humans does the multiplied score accept? Then it tunes the threshold for that group until the coverage hits the target.

Why it works

Why multiplying scores works better than averaging

Each LLM gives a score between 0 and 1 for factuality. If you average three scores of 0.8, 0.8, and 0.6, you get 0.73. If you multiply them instead, the result is much lower (roughly 0.38). Why multiply?

Multiplication is stricter. It says: a claim is strong only if all three models agree it is strong. If one model is skeptical, the product drops dramatically, signaling that consensus is weak. Averaging would hide that disagreement. For safety in high-stakes domains, you want to catch weak consensus and reject it.

Group-conditional calibration then does the hard work: for medical claims, you may find the right threshold is 0.5 (stricter, because medicine is high-stakes); for casual queries, 0.3 suffices (looser, because the cost of rejection is lower). The paper's guarantee is that once these thresholds are set on a validation set, they hold on future data from the same groups.

The scoring equation

First in words:

The product of ensemble scores is compared to a group-specific threshold. A claim is accepted if the product exceeds the threshold and the group meets its coverage guarantee.

Then the compact form:

accept if: score_A * score_B * score_C >= tau_g, where score_i is LLM-i factuality score, tau_g is the threshold for group g, chosen so coverage_g = target_coverage

Every symbol:

score_Afactuality score from LLM A, between 0 and 1
score_Bfactuality score from LLM B, between 0 and 1
score_Cfactuality score from LLM C, between 0 and 1
tau_grejection threshold for group g, tuned to achieve target coverage
target_coverageuser-specified fraction of true claims to retain (e.g., 0.95)
coverage_gactual fraction of true claims in group g that the threshold accepts
A tiny worked example
Medical claim: LLM-A says 0.9, LLM-B says 0.85, LLM-C says 0.88. Product = 0.9 * 0.85 * 0.88 = 0.673.
Medical group threshold tau_med = 0.60 (tuned so 95% of true medical claims are accepted).
Since 0.673 > 0.60, the claim is accepted.
Legal claim: LLM-A says 0.7, LLM-B says 0.65, LLM-C says 0.75. Product = 0.7 * 0.65 * 0.75 = 0.341.
Legal group threshold tau_law = 0.50 (tuned so 95% of true legal claims are accepted).
Since 0.341 < 0.50, the claim is rejected (LLM consensus too weak for this high-stakes domain).

Multiplying emphasizes consensus among the three LLMs; stricter thresholds per group ensure safety where the cost of error is high.

What can go wrong

What can go wrong

Ensemble diversity fails. If all three LLMs are trained the same way, multiplying their scores gives no new signal. You need models that have learned different facts or different ways of reasoning. If they are identical, the product is just one weak score cubed.
New group appears at test time. The threshold tau_g was tuned on a validation set from group g. If a completely new group (e.g., a domain never seen in validation) appears, the guarantee no longer holds. You must retune on that group first.
Validation data is biased. If the validation set used to compute coverage is not representative of the real group (e.g., simpler claims than users will ask), the threshold will be too loose or too strict in the field.
Done right. Use diverse models (different base LLMs or fine-tuning runs), validate on data truly representative of each group, and retune thresholds when new groups emerge.
What a runnable demo should prove

What a runnable demo should prove

Build a system with three LLMs (or multiple prompting variants of one model that behave differently). Collect a validation set of 100 claims from two domains (e.g., medical trivia and movie facts). Have humans label each as true or false. Compute the ensemble product score for each. For each domain, find the threshold that achieves exactly 90% coverage on that domain's validation data. Then test the thresholds on a held-out test set and report: (1) coverage per domain on the test set, (2) false-claim rejection rate, (3) number of claims accepted vs. rejected.

coverage_medical_test = (# true medical claims accepted) / (# true medical claims in test), similarly for other groups. false_claim_rate = (# false claims accepted) / (# false claims in test).

The demo proves that group-specific thresholds keep coverage close to the target (90%) in each domain without sacrificing the rejection of false claims.
