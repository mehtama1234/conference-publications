Dynamic Causal Graphs Under Parametric Uncertainty

Instead of learning a fixed causal diagram, learn how the causal connections change as the system's operating conditions shift.

Paper explainersAll themesLearning Theory

Real industrial systems do not have fixed causal relationships. A chemical reactor's temperature affects the reaction rate differently at high pressures than low pressures. Standard causal discovery methods assume the graph is static, missing these shifts. This paper proposes a new framework where each causal link is not a single number but a function that changes with measurable system settings (like pressure, time, temperature), using Polynomial Chaos Expansions to keep the math tractable.

Zero assumption version

Fixed causal graphs miss how relationships evolve

Causal discovery is the task of learning which variables influence which other variables by looking at real-world data. Standard methods learn a fixed causal graph: X causes Y with strength 2.5, and that is the whole story.

But real systems change their causal behavior based on operating conditions. In a chemical reactor, increasing the reactor pressure shifts how temperature affects the reaction rate. In a power grid, demand elasticity changes with time of day. A naive causal graph treats the system like a machine with permanent wiring, when the actual wiring is reconfigurable.

When causal links vary, a static graph becomes misleading. You learn a causal diagram that is true on average but false in any specific operating regime, useless for predicting what will happen when you change one variable in a real scenario.

The problem in one sentence. Causal relationships in real systems depend on operating conditions, but standard discovery methods assume the graph is frozen.

The paper replaces each static causal weight with a function. Instead of learning 'Temperature affects Yield with strength 2.5', you learn 'Temperature affects Yield with strength that depends on Pressure'.

The hidden quantity

Parametric causal structure: how influence shifts

measured quantity  =  dynamic causal link functions

The hidden quantity is how each causal influence changes as operating conditions shift. Concretely, it is the set of polynomial coefficients describing Temperature's effect on Yield as a function of Pressure.

The paper estimates this by fitting Polynomial Chaos Expansions — orthogonal polynomial basis functions — to data, then solving a causal discovery problem in polynomial coefficient space to identify which links exist and what their functional forms are.

Why it works

Why changing the causal links to functions fixes the problem

When causal links are functions instead of fixed numbers, the model can capture how the same variable pushes differently under different conditions. If Temperature's effect on Yield is written as a polynomial in Pressure, the fitted polynomial will show a weak slope at low Pressure and a steep slope at high Pressure.

Polynomial Chaos Expansions are chosen because they provide an orthogonal basis — each polynomial term is independent, which means fitting one coefficient does not interfere with fitting others. This matters: if you tried to fit the full space of possible functions, the computation would explode exponentially, but orthogonal polynomials keep it manageable even when you have many operating conditions to account for.

The paper proves mathematically that under standard causal assumptions (no cycles, no unmeasured confounders), the functional causal structure is identifiable — meaning there is only one correct set of polynomial coefficients that fits the data and causal graph. This matters because when a solution is mathematically unique, the learning algorithm can safely search for it without worrying that multiple different solutions might fit the data equally well; uniqueness guarantees that finding a good fit means you have found the true causal structure.

On real chemical reactor data, these dynamic causal graphs double the prediction accuracy of static methods, because the model can now say 'in this operating regime, Temperature has a stronger influence', matching how the actual reactor behaves.

Math after the picture

The core equation: functional causal links

First in words:

Each causal link from variable X to variable Y is approximated as a polynomial in the parameter vector p. The link strength is not a single number but a sum of polynomial terms, where each term is an orthogonal polynomial basis function times a learned coefficient.

Then the compact form:

f_XY(p) = sum_k alpha_k * psi_k(p)

Every symbol:

f_XY(p)the strength of causality from X to Y when the system parameter is p
alpha_kthe learned coefficient for the k-th polynomial term
psi_k(p)the k-th orthogonal polynomial basis function in parameter p
pthe measurable system operating parameter (e.g., pressure, temperature, time)
Tiny worked example: Temperature effect on Yield
Suppose Pressure is the operating parameter and we fit: f(Pressure) = 0.5 + 1.2 * Pressure + 0.3 * Pressure^2
At low Pressure = 1 atm: effect = 0.5 + 1.2(1) + 0.3(1)^2 = 0.5 + 1.2 + 0.3 = 2.0
At high Pressure = 3 atm: effect = 0.5 + 1.2(3) + 0.3(3)^2 = 0.5 + 3.6 + 2.7 = 6.8
Same Temperature change, but at 3 atm the influence is 3.4 times stronger than at 1 atm—the function captures the regime shift.

The polynomial coefficients are learned from data so the fitted function matches how the observed causal influence actually varies with system state.

What can go wrong

What can go wrong

Unmeasured conditions change causality. If the reactor's causal structure also depends on an operating condition you did not measure (e.g., catalyst aging), the polynomial fit will appear to have extra noise or systematic error, and identifiability breaks.
Too few observations in some regimes. If all your data comes from one operating point, the polynomial coefficients cannot be learned—you need variation across different operating conditions to fit the curve.
Polynomial degree is misspecified. If the true functional form is nonpolynomial (e.g., a sharp threshold), a low-degree polynomial will misfit. If the degree is too high, overfitting wastes data on noise.
Done right: measure key conditions and collect varied data. If you identify which operating conditions matter, measure them consistently, and gather data across the full range of settings, the method recovers the true dynamic structure.
What a runnable demo should prove

What a runnable demo should prove

Build a synthetic chemical reactor simulation where one reaction pathway's yield depends on temperature when pressure is low, but depends on concentration when pressure is high. Generate observational data tagged with both pressure and temperature. Run standard static causal discovery and compare to learning dynamic causal links with Polynomial Chaos Expansions. The demo should make it clear that the static method learns an average causal graph that is neither fully true at low pressure nor high pressure, while the dynamic method recovers separate causal structures for each regime.

F1-score = 2 * (precision * recall) / (precision + recall) on correctly identifying dynamic causal links

The key metric to watch: a static graph will show moderate F1 at each regime (neither regime fits the global graph); the dynamic graph will show high F1 at every regime (the polynomial adapts to each).
