OPTION: Optimal Transport-Guided Flow Matching for Incomplete and Unaligned Multi-View Clustering

The paper learns stable missing-data recovery and alignment-free cross-view fusion by making the flow of each incomplete view follow the geometric shape of complete ones.

Paper explainersAll themesGraph & Geometric Learning

When a machine learning problem receives data from multiple cameras, sensors, or information sources, it gains richer context than looking at just one view alone. But real data breaks in two ways: sometimes a sensor fails and you get no data for that view, and sometimes the same object is recorded differently across views so the data does not line up row-by-row. This paper fixes both problems by learning how to fill in missing views in a way that preserves where the known examples actually sit in space, and combining all views without forcing them to align.

Zero assumption version

Multi-view clustering breaks when data goes missing or mismatched

Multi-view clustering means: given the same object measured in multiple ways (e.g., an image and a thermal scan of the same scene), group similar objects by fusing information across all views. The classic setup assumes every object has complete data in every view and that the same row index means the same object across views.

Real data breaks this assumption in two ways. First, sensors fail or data is deleted: one view might be completely missing for half the objects. A beginner would discard incomplete objects or replace them with averages or random noise. But average values do not capture the pattern of real data—where the valid examples actually sit in space and how far apart they are from each other. Second, objects are not always perfectly aligned: the rows might get shuffled or sampled differently, so row 5 in view A is not the same object as row 5 in view B. A beginner would try to match rows by comparing their features, but if the views are in different spaces, the matches are wrong and the fusion breaks.

Both problems break clustering because the model cannot see the true pattern of the data—either because the missing data is filled in wrong and sits in the wrong place, or because it is treating mismatched rows as if they belonged together.

In one sentence. Fill in missing views by learning to place them where complete examples sit, and fuse without forcing row alignment by comparing how close points are to each other instead of matching rows.

The algorithm as a flow

What it actually does

1. Start with partial data

Some objects have all views, some are missing one or more views entirely.

2. Build a conditional flow

For each missing view, learn a transformation that starts at noise and ends where real data sits.

3. Recover missing values

Run the transformation to the end: noise becomes a value sitting where complete data sits.

4. Align by structure, not rows

Measure how similar data patterns are across views by comparing distances and neighborhoods.

5. Cluster using all recovered data

Now all objects have all views and data patterns are consistent, so clustering works.

What the paper changes

What the paper changes

The paper changes the way missing view values are filled in. Instead of replacing them with guesses (zero, average, or nearest-neighbor), it learns a generative flow: a transformation that carries random noise into the space where real data sits. This means each recovered value ends up where real examples naturally live, not in an arbitrary default.

the object it moves  =  missing-view recovery path
The hidden quantity

The neighborhood pattern within each view

measured quantity  =  Intra-view neighborhood (distances and groupings within one view)

Each view has its own neighborhood pattern: which objects sit close to which, which ones form tight clusters, which ones are far apart. A complete view's pattern is real; a view with missing data has gaps. The paper measures this by computing distances between complete examples and ensuring that recovered examples sit at distances from others that match where complete examples sit.

To align views without forcing row-by-row matching, the paper uses a Gromov-Wasserstein distance, a measure that compares how similar the internal distances are between two views. If View A has objects arranged in a tight cluster and View B's complete examples show the same tight cluster pattern, the measure is small. This allows the model to say: these two views belong together even if their rows are shuffled, because their distances and neighborhoods match.

Why it works

Why learning to recover and align based on neighborhoods fixes incomplete multi-view clustering

The mechanism has two parts. First, flow matching for imputation: instead of guessing a value for a missing entry, the paper trains a generative model (a flow) that learns a reversible smooth path from noise to where real data sits. When you run this path, you get a recovered value in the right place. This is better than averages or random noise because the path ends at the learned position of real examples.

Second, Gromov-Wasserstein fusion: clustering needs to know which objects are similar. If views are aligned, you compare row-by-row. But if views are shuffled, row-by-row comparison is wrong. Instead, the paper compares neighborhoods—do both views place nearby objects in similar neighborhoods? Are the distances between neighbors similar across views? Gromov-Wasserstein measures this: it scores how well the distance patterns match from view A to view B. Small distance mismatch means the views agree on where objects sit relative to each other, so they can be fused confidently.

Together, these changes solve both problems: missing values are recovered in a way that preserves where real data sits, and views can be fused even when their rows are shuffled because the method aligns based on neighborhood patterns, not row identity.

Math after the picture

The core equation: balancing recovery and alignment

First in words:

The training objective is: minimize imputation error plus structural misalignment penalty plus optional view-agreement regularization

Then the compact form:

L = L_flow + lambda_gw * L_gw + lambda_contrast * L_contrast

Every symbol:

L_flowerror between recovered and true values for complete examples
L_gwGromov-Wasserstein distance, measures how well distances match between views
L_contrastcontrastive loss, encourages same-object values to be close across views
lambda_gwweight on distance matching (how much we care about neighborhood consistency)
lambda_contrastweight on cross-view agreement (how much we care about matched pairs, if any)
A tiny worked example
Suppose a missing value in View B should be close to 2.5 based on the flow model. L_flow compares imputed 2.5 to test values and computes mean squared error: say 0.16 (prediction error 0.4).
View A's complete data has distances: A-to-B is 1.2, A-to-C is 2.1. View B's complete data has A-to-C is 2.3, B-to-C is 1.5. The Gromov-Wasserstein score (how much distances disagree) is 0.25.
With lambda_gw = 2.0, the distance mismatch penalty is 2.0 times 0.25 equals 0.50. Total loss: 0.16 plus 0.50 equals 0.66.
If rows are matched, lambda_contrast = 1.0 adds 0.10 (contrastive loss on known pairs). Final loss: 0.76. Training reduces all three terms.

The three loss terms pull in different directions: flow wants recovered values to sit where real data sits, Gromov-Wasserstein wants distances and neighborhoods to match across views, and contrastive loss (if used) wants matched objects to stay close. Balancing them with lambda weights lets the method handle all three challenges.

What can go wrong

What can go wrong

Flow model overfits to small datasets. If the complete-view data is tiny, the generative flow learns a narrow pattern that does not represent real data. Recovered values then sit in the wrong place. Fix: use regularization or mix in unlabeled data.
Gromov-Wasserstein computation is slow on large views. The Gromov-Wasserstein distance compares all pairwise distances, which requires checking every pair of objects. On thousands of objects, this means millions of comparisons, making training slow. Partial Gromov-Wasserstein (comparing only a random sample of pairs) or sampling fewer objects helps because it reduces the number of comparisons without losing much alignment quality.
Misalignment is too severe: one view is corrupted, not shuffled. If one view is fundamentally different in content (e.g., noise, different object set), Gromov-Wasserstein cannot match it. The method assumes views measure the same objects in different ways.
Done right: good recovery with consistent patterns. When flow learns where real data sits and Gromov-Wasserstein steers neighborhoods to match, recovered values sit in the right place and views fuse cleanly even if rows are shuffled.
What a runnable demo should prove

What a runnable demo should prove

Build a small multi-view clustering experiment on a standard dataset (e.g., a subset of 500 objects, 4 views). Artificially remove 40 percent of one view's values and shuffle rows in another view. Run three pipelines: (1) discard incomplete objects and cluster the rest, (2) fill missing with zeros and try to align rows by matching, (3) run OPTION with flow recovery and Gromov-Wasserstein fusion. Measure: clustering accuracy (percent of objects assigned to the true cluster), placement fidelity (average distance correlation before and after recovery), and neighborhood matching (percent of recovered values whose neighbors match neighbors in the complete view).

Clustering accuracy = (correctly clustered objects) / (total objects); Placement fidelity = correlation between pairwise distances in recovered view and held-out complete view distances; Neighborhood score = (recovered values whose k-nearest neighbors match complete view neighbors) / (total recovered values)

The demo must make impossible to miss: recovered values shift from random to precise, clustering accuracy jumps from 50s to high 80s, and neighborhoods stay consistent even when rows are shuffled.
