Memorization Through Compression: The Adversarial Compression Ratio

Memorization happens when a model can output training data from a much shorter prompt than the data itself.

Paper explainersAll themesLearning Theory

When a model memorizes training data, it stores information in its weights. A clever way to detect this is to ask: what is the shortest prompt that makes the model spit out that training data? If the prompt is much shorter than the data, the model must have stored it. This paper proposes Adversarial Compression Ratio (ACR) to measure memorization at scale.

Zero assumption version

Memorization is expensive to measure

To know if a model memorized a training example, you normally have to retrain the entire model twice: once with that example and once without it, then compare how well it performs on that example. This is called counterfactual memorization. For a language model with billions of weights, this is prohibitively expensive.

Existing definitions of memorization are also vague. One says a model memorized something if you can prompt it with part of the training data and it completes it exactly. But what about text that appears multiple times in training? What about text similar to training data but not exact? The definitions lack a principled way to distinguish storage from generalization.

A beginner might think: just check if the model can output the exact string. But this doesn't tell you if the model learned the words or merely reproduced them word-for-word from memory. You need a precise, practical measure.

In one sentence. Measure memorization by finding the shortest prompt that forces the model to output that training example.

Check for compression

What the paper changes

The object: shortest prompt length

The paper changes how we measure memorization. Instead of retraining models, it focuses on one simple object: the length of the shortest prompt that forces output of a training example. This single number—prompt length—becomes the yardstick.

the object it moves  =  prompt length
The hidden quantity

Compression Ratio: the memorization signal

measured quantity  =  Compression Ratio (ACR)

The hidden quantity is the Compression Ratio, which is simply the length of the training example divided by the length of the shortest prompt that triggers it. If you can compress a 100-token example into a 10-token prompt, the ratio is 10. A high ratio means the model has squeezed information into its weights; a low ratio (near 1) means it learned to generalize.

The paper measures this by running GCG (a search algorithm) to find the shortest prompt iteratively. It starts with a guess, runs the search for a budget of steps, and if the prompt still doesn't work, it adds tokens and tries again. The final successful prompt's length is the denominator.

Plain reading. A memorized phrase is one where the model has stored it as a tight pattern. A short prompt triggers it because the weights already know exactly what should come next.
Paper reading. Given a model M and a training sample y, ACR(M, y) is defined as the length of y divided by the length of the shortest prompt p such that M(p) outputs y exactly.
Why it works

Why compression reveals memorization

Memorization works because the model stores specific sequences in its weights. When the weights encode the exact tokens of a training example, only a few trigger tokens are needed to recall the rest. The model has done the information compression work during training; the prompt just needs to hit the right 'key' in memory.

Generalization works differently. When a model learns a concept (e.g., the structure of English), it distributes that knowledge across many weights. No short prompt can extract the exact training sentence because the model is reconstructing it from general rules, not replaying stored data. Each output token requires multiple weights to cooperate, so nothing is memorized as a rigid sequence.

The search algorithm (GCG) automates this detection. It treats prompt construction as an optimization problem: find the prompt that makes the model output the target text, using as few tokens as possible. If a short prompt exists, memorization is happening. If only a long prompt works (or no prompt works), the model generalized.

stepRun GCG search: test random prompts, score how close the output matches the target

The compression ratio formula

First in words:

compression ratio equals length of training example divided by length of the shortest prompt that produces it

Then the compact form:

ACR(M, y) = len(y) / len(p_min), where p_min is the shortest prompt such that M(p_min) = y

Every symbol:

Mthe language model
ya training example (a sequence of tokens)
p_minthe shortest prompt that causes M to output y exactly
len(y)number of tokens in the training example
len(p_min)number of tokens in the minimal prompt

A tiny worked example
Training example: 'Paris is the capital of France and sits on the Seine River.' = 13 tokens.
Search finds shortest prompt that triggers it: 'Paris capital' = 2 tokens.
ACR = 13 / 2 = 6.5.
Ratio of 6.5 is high, indicating memorization. The model can compress a 13-token fact into a 2-token reminder.
Contrast: if the shortest prompt were 11 tokens, ACR = 13/11 = 1.18, nearly no compression, suggesting generalization.

The higher the ratio, the tighter the memorization. A ratio near 1 means prompt and output are nearly the same length—no compression, no memorization.

What can go wrong

What can go wrong

Non-training data can sometimes compress. If you feed the algorithm text that was never in training (e.g. news from after training), the GCG search may still find a short prompt by accident. The paper shows this is rare: it never observed non-training text compress in their experiments.
Paraphrases muddy the signal. Famous quotes that appear in paraphrased form in training may not compress well using the exact quote. The compression ratio conflates exact memorization with paraphrase variants. The paper measures this as separate: famous quotes compress with ratio 1.17, but paraphrases only 0.68.
Search timeout misses very short prompts. GCG has a time budget. If the true minimal prompt requires deeper search, the algorithm stops and reports a longer prompt than actually exists, inflating the compression ratio artificially.
Done right: randomness and repeated searches. Run the search multiple times with different random seeds; report the shortest prompt found. Use adaptive time budgets (more time for longer prompts) to avoid timeout bias.
What a runnable demo should prove

What a runnable demo should prove

Build a small language model (or use a pretrained one like Pythia-1.4B) and a dataset with known training examples. For each example, run GCG to find the shortest trigger prompt. Collect the compression ratios. Then artificially insert new sentences into the dataset and retrain slightly, or fetch text never in training (e.g. recent news, text external to the training set). Run the same search. Plot histograms of compression ratios for three groups: original training, retraining data, and external text.

ACR_train = average compression ratio for original training examples. ACR_external = average for external text. Success: ACR_train > 1.5 and ACR_external < 1.1.

The gap between training and external-text compression ratios proves memorization is real and measurable without retraining.
