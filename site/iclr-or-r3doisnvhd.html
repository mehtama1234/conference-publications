Measuring oversmoothing in graph networks correctly

Node features (the lists of numbers representing each node) in deep graph networks collapse to single directions; rank of the feature table catches this collapse where similarity metrics miss it.

Paper explainersAll themesGraph & Geometric Learning

Graph neural networks fail when you stack many layers: each node becomes nearly identical to its neighbors, and the model stops learning. The standard way to measure this collapse looks at feature similarity, but it misses real problems. This paper watches the rank instead — how many independent directions the node features span — and shows rank predicts performance drops where similarity metrics stay flat.

Zero assumption version

Deep graph networks hit a wall

A graph neural network learns by letting each node talk to its neighbors: the node updates its feature list (a row of numbers) based on what its neighbors know. Add more layers, and nodes chat further across the graph. But at some point, this breaks: all nodes end up with nearly the same features, so the network cannot tell them apart anymore and fails on any task that needs to distinguish nodes.

People have measured this collapse for years by watching feature similarity — how much each node's feature list looks like its neighbor's list. A naive assumption: if neighbors are very similar, the network has oversmoothed. But the similarity metrics were tested on networks with 20 or 30 layers; on real networks with 10 layers, they show the network is fine even though accuracy drops by half.

In one sentence. The paper measures oversmoothing by the rank of the feature table instead of how similar features are.

What the paper changes

The paper replaces the way we measure whether nodes have collapsed into sameness.

The hidden quantity

The rank of feature representations

measured quantity  =  effective rank

The rank of a feature table is how many independent directions the rows (nodes) actually span. If a table has 12 columns but all rows point the same direction, the rank is one. If rows span many directions, rank is high. This is a standard concept in linear algebra (the number of linearly independent rows).

The paper estimates rank by counting how many of the singular values (a diagnostic breakdown of any table into independent pieces) are above a numerical threshold, not just noise. A feature table (the list of numbers for each node) with rank 1 means all nodes are indistinguishable; rank 12 means they use the full feature space.

Why it works

Why rank works where similarity fails

Similarity metrics measure how much neighboring nodes look alike. But in any real network, neighbors start similar (they begin by averaging local structure), so similarity is already high from layer 1. As you add layers, similarity can only stay flat or drop, but it starts flat — it hits ceiling immediately and becomes useless as a depth diagnostic.

Rank works because it counts independent directions the nodes actually use. At shallow depth, different nodes explore different feature directions — rank is high. As layers stack and oversmoothing kicks in, all nodes get pushed toward the same direction (the dominant eigenvalue of the graph's mixing operator). Rank falls smoothly and measurably, from 12 to 1, even when similarity is already maxed. This is why rank catches the problem on real 10-layer networks while similarity stays silent.

Math after the picture

Measuring rank

First in words:

numerical_rank = count of singular values S_i where S_i is above (threshold × largest singular value)

Then the compact form:

r = |{ i : s_i >= tau * s_1 }|

Every symbol:

s_ithe i-th singular value (output of singular value decomposition)
s_1the largest singular value
tauthreshold, typically 0.001 to 0.01
rthe numerical rank of the feature table
A tiny worked example
Feature table has 12 columns (feature dimensions). Singular value decomposition gives s_1=10.0, s_2=8.5, s_3=5.2, s_4=0.05, s_5=0.02, ... (rest near zero).
Set threshold tau=0.01. Then tau * s_1 = 0.01 * 10.0 = 0.1.
Count values >= 0.1: s_1(10.0 yes), s_2(8.5 yes), s_3(5.2 yes), s_4(0.05 no), s_5 and beyond (all no).
Numerical rank = 3. Only three dimensions carry real signal; the other nine are noise.

As oversmoothing progresses, the largest singular value alone gets large and all others shrink, so rank drops toward one.

What can go wrong

What can go wrong

Threshold too loose. If tau is too large (e.g., 0.1), many noise singular values pass the filter and rank stays artificially high.
Feature scaling matters. If node features are rescaled, singular values change size, so the threshold must be recalibrated.
Shallow networks may not oversmooth. Real-world networks with 5–10 layers sometimes have high rank throughout; rank only predicts collapse in deeper models or certain graph structures.
Rank is a diagnostic, not a fix. This metric tells you the problem exists; it does not say how to solve oversmoothing (that is a separate design problem).
What a runnable demo should prove

What a runnable demo should prove

Build a small graph (e.g., 100 nodes, 10-layer GNN). At each layer, compute the feature table's rank and the accuracy on a simple node-classification task. Plot rank and accuracy together as you increase layer depth. Show that rank falls when accuracy falls, while a similarity metric (the average angle-based overlap between neighbor feature lists) stays flat or climbs.

rank_drop = rank_at_layer_1 - rank_at_layer_N; accuracy_drop = accuracy_at_layer_1 - accuracy_at_layer_N; correlation = how well rank_drop aligns with accuracy_drop

The demo must make it impossible to miss: rank collapse tracks accuracy loss; similarity does not.
