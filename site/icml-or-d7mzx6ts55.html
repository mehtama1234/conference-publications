Find, Fix, Reason: Context Repair for Video Reasoning

Use a stronger frozen teacher to add only the missing video evidence, then train the smaller student on the repaired context.

Paper explainersAll themesAgents & Tool Use

A video question may fail not because the student model is generally weak, but because it missed one needed time span or region in the video. This paper builds a teacher that can inspect the original video, locate the missing evidence, and add a minimal patch to the student's context. The student answers again with that repaired evidence, and training rewards answers whose reasoning matches the supplied evidence because the goal is not only a correct answer but a correct answer grounded in the right part of the video.

Zero assumption version

Why many video reasoning errors are really missing-evidence errors

A video question often depends on a short event, a distant dependency across time, or a small region in one frame. If the student model does not attend to that evidence, the final answer can be wrong even when the model has enough general reasoning ability to solve the question once the right evidence is present.

Current training approaches often push the student to explore or imitate whole solution traces. That can help final accuracy in some cases, but it does not directly repair the missing observation because the student still may not see the event or region that mattered. This paper instead changes the observation itself. It asks what minimal evidence patch would let the student see the relevant event or region and reason from it.

The paper's move in one sentence. Use a frozen teacher with tools to locate the missing video evidence, add only that evidence to the student's context, and then train the student on the repaired attempt.

The algorithm as a flow

What it actually does

Run the student once

Let the student answer the original question so that failure cases reveal which evidence may be missing.

Ask the teacher to diagnose the gap

Have the teacher search the full video for the missing time span or region that would repair the failed attempt.

Attach the evidence patch

Add only the missing evidence to the student's context because the question itself stays the same.

Run the student again

Collect a second answer and rationale so that training can compare the repaired attempt with the original one.

Reward grounded improvement

Update the student toward answers that are correct and supported by the cited repair evidence.

The hidden quantity

The hidden quantity

measured quantity  =  Missing spatiotemporal dependency

The hidden quantity is the exact missing dependency in the video: the time span, region, or cross-time relation that the student needed but did not bring into its working context. That missing dependency is not visible from the wrong answer alone.

The teacher estimates this hidden gap by reading the original video and comparing it with the student's failed attempt. That diagnosis matters because one small patch can repair the answer if it contains the evidence the student was missing.

Why it works

Why this works: change the observation before changing the answer

A wrong answer can come from two different causes: the model may reason badly, or it may reason from incomplete evidence. Context repair targets the second cause directly. If the student already has enough reasoning skill, then adding the right patch can unlock the correct answer without rebuilding the whole model.

The reward design matters as well. If training cared only about the final answer, the student could improve by accidental shortcuts. Rewarding evidence-aligned rationales works better because it pushes the student to use the supplied patch, not merely to guess the answer after the teacher intervention.

Math after the picture

Reward answers that improve for the right reason

First in words:

Give higher reward when the repaired attempt is correct and when its explanation uses the evidence that the teacher added.

Then the compact form:

reward = answer_gain + evidence_alignment - patch_cost

Every symbol:

rewardtraining reward for one repaired retry
answer_gainbenefit from getting the final answer right after the repair
evidence_alignmentcredit when the rationale actually points to the inserted evidence
patch_costpenalty for adding too much extra context instead of a minimal repair
A tiny worked example
Original answer is wrong because the student missed the moment when the person puts the key on the table.
Patch A adds the exact late timestamp and crop. Answer gain 8, evidence alignment 4, patch cost 1, total 11.
Patch B adds a long unrelated segment. Answer gain 4, evidence alignment 1, patch cost 3, total 2.
The system prefers Patch A because it repairs the needed observation with little extra noise.

The paper uses a chosen-rollout training design with a reward for grounded improvement. This compact form states the same preference.

What can go wrong

What can go wrong

Teacher finds the wrong gap. If the teacher misdiagnoses the missing dependency, the patch may add irrelevant evidence, so the retry remains weak.
Patch is too large. A large patch can hide the real cause of improvement because it may give away too much context instead of isolating the needed evidence.
Student ignores the patch. The repair helps only if the student learns to use the added evidence, so alignment reward matters because accuracy alone may not force grounded reasoning.
Done right. The method is appealing because it turns many failures into observation repair problems, and those are often easier to fix than rebuilding the whole reasoning stack.
What a runnable demo should prove

What a runnable demo should prove

Build a toy video question set where each answer depends on one short event or one small region. Use a simple student that answers from a limited clip and a stronger teacher that can inspect the full video because the teacher needs access to the evidence the student missed. For each failed student answer, have the teacher choose a timestamp or crop as the repair patch, then run the student again with that patch attached.

The demo should show that repaired retries beat unrepaired retries because the missing evidence has been restored. It should also record whether the student cites the repaired evidence in its rationale so that the improvement can be traced to the patch rather than to a lucky guess.

repair_gain = accuracy_after_patch - accuracy_before_patch

The main proof is that a small evidence repair raises accuracy because it restores the missing observation that the student needed for the question.
