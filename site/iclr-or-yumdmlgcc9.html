Expressive and Invariant Graph Learning via Canonical Tree Cover Neural Networks

Instead of flattening graphs into sequences, represent them as multiple overlapping trees to preserve structure and keep expressions richer.

Paper explainersAll themesGraph & Geometric Learning

Graphs (networks of connected things) are everywhere: social networks, molecules, road maps. The challenge is building models that understand graphs deeply without changing their answer when you relabel the nodes (a property called invariance). Most methods flatten graphs into sequences, which loses the structure. This paper introduces a better way: represent the graph as a small collection of overlapping trees, then process each tree independently, because trees keep distances exact (the path between two nodes in a tree is always unique and unchanging) while sequences scramble them based on arbitrary ordering.

Zero assumption version

Graphs are hard to represent without losing structure

A graph is a set of nodes (things) and edges (connections between them). Message-passing neural networks, which pass information along edges, are naturally invariant: they give the same answer no matter how you number the nodes. But they have a weakness: they can only combine information from neighbors, step by step. Deep thoughts about the whole graph's structure stay out of reach.

A naive fix: turn the graph into a single sequence of nodes and feed it to a complex model. This works in theory, but it breaks in practice. Flattening destroys how the graph is laid out. Two far-apart nodes in the graph appear close in the sequence. Distances get scrambled. The model has to learn that this scrambled representation means something, wasting effort. Worse, a sequence gives only one canonical choice per graph, so the model can only read information one way, because a single linear order forces all structural relationships to be reinterpreted through that one path — a different ordering would reveal different relationships, but you only get one chance.

In one sentence. The paper uses multiple overlapping trees (covering all edges) instead of one sequence, preserving distances and letting the model see the graph from many angles.

The algorithm as a flow

What it actually does

Canonicalize the graph

Pick a deterministic rule to find a set of spanning trees that cover all edges.

Make multiple tree views

Each tree is a different valid subgraph that includes all nodes; trees overlap.

Encode each tree separately

Send each tree through an encoder that extracts parent-child relationships and structure.

Combine representations

Pool or merge the outputs from all trees into one graph-level representation.

Predict on the combined view

Use the merged representation for classification or other tasks.

What the paper changes

What the paper changes

The paper replaces the canonical sequence (a single flattened ordering) with a canonical tree cover (a small, deterministic collection of trees). Each tree preserves hierarchy; together they preserve the full graph structure. The model now sees multiple geometric perspectives on the same graph, instead of one flattened view.

the object it moves  =  canonical representation
The hidden quantity

Graph distance preservation

measured quantity  =  How well the representation maintains original distances

When you flatten a graph into a sequence, distances get distorted. Two nodes that are 3 edges apart in the graph might end up 100 positions apart in the sequence, or only 2. The paper measures something hidden: how well the tree cover representation maintains the graph's true layout. In a tree, distances between nodes are exact (the path from A to B in the tree is unique). If you cover all edges with a small set of trees, each pair of nodes falls into a tree where their distance is preserved.

The paper estimates this by analyzing the tree cover theoretically. On sparse graphs (few edges), the number of trees needed is logarithmic in the graph size. This means most pairs of nodes stay close in at least one tree. The paper does not need to measure this distance-preservation directly during training; it is a consequence of the tree structure itself.

Why it works

Why tree covers outperform sequences

A sequence is a single path through the graph's nodes. It gives one read order. Nodes far apart in the graph end up far apart in the sequence only by accident. A tree cover is a collection of trees, each with its own hierarchy and distances. Because the trees overlap and cover all edges, every pair of nodes is close in at least one tree.

Why does this help expressivity? Because an encoder that understands tree structure (one that reads parent-child relationships directly) can extract more information from a tree than from a flat sequence. The tree structure tells the model which connections are primary, which are side branches. When you process multiple trees, the model assembles views that contradict in healthy ways: Tree A says node X is central (root-close), Tree B says it is peripheral. The model learns to fuse these views into a deeper understanding than any single view alone.

Invariance is preserved because the tree cover is canonical: the same deterministic rule always picks the same set of trees for a given graph, regardless of node labels. Relabel the graph, run the canonicalization again, and you get the same trees (in the same order). The model thus always sees the same representation for the same graph structure.

The tree cover and pooling equation

First in words:

For each canonical tree in the cover, run an encoder to get a vector. Then average (or pool) all tree vectors to get the final graph representation.

Then the compact form:

g_final = pool( [ encoder(tree_1), encoder(tree_2), ..., encoder(tree_k) ] )

Every symbol:

g_finalthe final graph-level representation (output)
tree_ithe i-th spanning tree in the canonical cover
encoder(tree_i)the output vector from running an expressive tree encoder on tree i
poolcombine operation: average, max, or learned aggregation
knumber of trees in the cover (logarithmic in graph size for sparse graphs)

Graph: 8 nodes, 10 edges (sparse). Canonicalization produces 3 trees.

Tree 2 encoder output: [0.3, 0.4, 0.9, 0.7]

Average (pool): [(0.5+0.3+0.6)/3, (-0.2+0.4+0.1)/3, (0.8+0.9+0.6)/3, (1.1+0.7+0.9)/3]
Final g_final: [0.47, 0.1, 0.77, 0.9]
This vector goes to a classifier for graph-level prediction (e.g., is this graph a drug candidate?).

Each tree is processed fully; pooling combines their signals without forcing one read order.

What can go wrong

What can go wrong

Dense graphs need many trees. On dense graphs (many edges), the number of trees grows beyond logarithmic. Computational cost rises. The advantage shrinks on fully connected graphs, where a sequence is already almost complete.
Tree encoder must understand hierarchy. If the tree encoder is weak (e.g., a shallow neural network), the tree representation does not capture parent-child structure well. The paper assumes access to tree encoders (like tree transformers, which are neural networks that process tree structure directly) that extract this information; not all existing models do this.
Canonicalization rule must be stable. If the rule for picking trees is non-deterministic or sensitive to tiny changes, two nearly-identical graphs may get different covers. Invariance breaks. The paper relies on careful algorithm design to ensure this does not happen.
Done right. Use a deterministic, well-defined spanning tree algorithm (e.g., depth-first search with tie-breaking by node ID). Test that isomorphic graphs produce identical tree covers. Use a tree encoder that captures parent-child structure directly (e.g., tree transformers or tree LSTMs). On sparse graphs, the method is both fast and expressive.
What a runnable demo should prove

What a runnable demo should prove

Build a small graph classification task: take a standard benchmark like PROTEINS or NCI (graphs representing molecules or proteins, labeled as active/inactive). Train a model using canonical tree covers against baselines: message-passing GNNs, random tree samplers, and sequence-based canonicalization. Measure classification accuracy. The demo should show that tree covers beat sequences on the same graphs, proving the structure preservation claim.

accuracy = (correctly classified graphs) / (total test graphs)

Tree covers should yield higher accuracy than sequences on the same test set, proving that multiple geometric views capture the graph better than one flattened sequence, because each view exposes different structural patterns — no single sequence can show all of them at once.
