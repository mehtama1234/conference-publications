Experience-Evolving Multi-Turn Tool-Use Agent with Hybrid Episodic-Procedural Memory

Reuse both past task context and recurring tool routines so a multi-turn agent can adapt earlier experience instead of starting from scratch each time.

Paper explainersAll themesAgents & Tool Use

A multi-turn tool-using agent often solves a task through a long sequence of observations, tool calls, and intermediate decisions. Reusing past experience sounds helpful, but direct replay of a full old trajectory can fail because the new task only partly overlaps with the old one. Reusing only isolated tool habits can also fail because the local tool step loses the surrounding context. This paper combines both forms of memory so the agent can recall useful context and useful routines together.

Zero assumption version

Past experience is useful, but whole trajectories and isolated tool steps each lose something important

A full past trajectory preserves detailed task context, but it can be too tied to one earlier episode. Small changes in user intent or environment state can make the old path hard to reuse directly.

At the other extreme, simple reuse of recurring tool transitions is portable but shallow. It remembers that one tool often follows another, yet it forgets why that transition mattered in the earlier task. The paper asks whether an agent can store both contextual memory and routine memory, then combine them during later decision making and training.

The paper's move in one sentence. Store recurring tool routines together with compact context summaries so the agent can reuse old experience more flexibly because new tasks often overlap only in part with old ones.

The algorithm as a flow

What it actually does

Collect successful interaction histories

Store multi-turn tool-use episodes that solved earlier tasks so that later training and action selection have experience to draw from.

Extract procedural routines

Record recurring tool-to-tool transitions because those transitions capture repeatable action structure.

Attach compact episode summaries

Save the relevant surrounding context with each routine so that the agent knows when a routine should apply.

Recall both during later action selection

Balance context recall with routine reuse because new tasks may match an old episode only partially.

Guide exploration during reinforcement learning

Bias search toward previously useful transitions so that training wastes fewer steps on clearly weak long-horizon paths.

What the paper changes

What the paper changes

The paper changes the structure of agent memory. Instead of storing only whole episodes or only routine tool transitions, it links both in a hybrid memory that can support decision making and training.

the object it moves  =  the memory representation used by a multi-turn tool agent
The hidden quantity

The hidden quantity

measured quantity  =  how much of a past success remains reusable after the new task changes part of the context

The central hidden quantity is transferable overlap between the current task and past successes. A memory item is useful only if enough of it still applies after the task details change.

The hybrid memory tries to preserve that overlap by separating what tends to repeat from what tends to vary. Tool routines capture reusable structure, while compact episode summaries capture when those routines make sense.

Why it works

Why the hybrid memory can help

Whole-episode memory is detailed but fragile. Routine-only memory is portable but shallow. Putting them together helps because the agent can recover a routine while also checking whether the surrounding context matches well enough for that routine to apply.

The training benefit is similar. Exploration over long tool-use trajectories is hard because the search space expands quickly. Memory-guided exploration can cut waste because previously successful transitions are more likely to lead toward fruitful branches than random wandering.

Math after the picture

A compact reuse summary

First in words:

Memory value can be viewed as routine reuse plus context fit, because an old experience helps most when it carries both a repeatable action pattern and the conditions under which that pattern works.

Then the compact form:

memory_value = routine_reuse + context_fit

Every symbol:

memory_valueoverall usefulness of a recalled past experience for the current task
routine_reusehow much the old tool transition pattern can be reused now
context_fithow well the stored summary matches the current situation
A tiny worked example
Suppose an old episode contains a useful search-then-lookup routine worth 4 reuse points.
Suppose the current task matches the old context fairly well, giving context fit 3.
Then memory value is 7 in this simplified view.
If the same routine appears but the current context is very different, context fit might drop to 1.
Then memory value falls to 5 because the action pattern still helps, but the surrounding conditions match less well.

The full method is more detailed, but this sum captures the paper's main point that useful memory has both structural and contextual parts.

What can go wrong

What can go wrong

The stored summaries may omit decisive context. A compact summary can become too coarse, so the agent may reuse a routine in the wrong setting because the memory entry dropped the detail that should have blocked reuse.
Popular routines can dominate exploration. If memory-guided search over-favors old successes, the agent may stop discovering better new branches because the memory bias becomes too strong.
The graph can grow noisy over time. As more episodes are stored, weak or redundant transitions may accumulate, so retrieval quality can fall because the memory bank becomes harder to search cleanly.
Done right. The method is strongest when tasks share partial structure, because then selective reuse of routines plus context can remove a large amount of repeated search.
What a runnable demo should prove

What a runnable demo should prove

Build a multi-turn benchmark where many tasks share some tool routines but differ in user intent and environment details. Compare three agents: one with full-trajectory recall, one with routine-only reuse, and one with the hybrid memory graph.

The demo should measure success, average search steps, and reuse quality under context shifts. The hybrid system should waste fewer steps because it can borrow an old routine only when the stored context summary says that routine still fits.

reuse_gain = search_steps_baseline - search_steps_hybrid ; transfer_gain = success_hybrid - success_baseline

The point of the demo is to show that memory helps most when it stores both what to do and when that past pattern still applies, because selective reuse is better than replaying an old path wholesale.
