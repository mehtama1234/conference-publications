TangoFlux: Fast Text-to-Audio with Preference Learning

TangoFlux uses self-improving preference learning to teach an audio-generation model to match text descriptions faithfully, fast.

Paper explainersAll themesGenerative Models & Diffusion

Text-to-audio models struggle to make audio that actually matches what the text asks for. There's no simple scorekeeper (like a human saying right or wrong) the way there is for language models. TangoFlux solves this by using an existing audio-description scorer to rank generated samples, then teaching the model to prefer the better ones — and doing this iteratively, so the model's own output teaches it what to improve.

Zero assumption version

Audio generation has no built-in way to rank preferences

When you ask a language model to answer a question, humans can judge whether the answer is right. When you ask it to generate code, you can test it. But when you ask an audio model to make a drum sound, there's no obvious test. The model generates samples; nobody has labeled which ones match the text description better, because creating such labels requires listening to thousands of audio pairs and comparing them, which is expensive and slow compared to testing code or grading text answers.

A beginner might try: collect human labels for millions of audio samples (expensive), or train a reward model from scratch (data hungry, slow). Both stall the model's training because preference data is scarce.

The paper's move in one sentence. Use an existing audio-description scorer (called CLAP) to automatically rank generated audios, then iteratively improve the model by teaching it to produce samples that CLAP ranks as high-quality.

The algorithm as a flow

What it actually does

Collect raw samples

Model generates a batch of audio samples from the same text prompt.

Rank with CLAP

CLAP scorer (pre-trained on millions of text-audio pairs) compares each sample to the text and assigns alignment scores.

Pick winners and losers

For each prompt, select the highest-scoring sample as the 'winner' and the lowest as the 'loser'.

Optimize for preference

Train the model to make the winner's audio pattern more likely and the loser's less likely, using a preference-ranking loss.

Repeat

Run the improved model again, generate new samples, and repeat the cycle.

What the paper changes

What changes: preference learning weights

The paper changes one thing: during training, instead of only predicting the audio waveform from noise, the model also learns to prefer samples ranked highly by CLAP. The model's internal weights gradually shift to produce samples that score higher.

the object it moves  =  model weights
The hidden quantity

The hidden quantity: CLAP alignment score

measured quantity  =  text-audio alignment score

The alignment score is a single number that measures how well a generated audio matches the text prompt. CLAP (Contrastive Language-Audio Pre-training) assigns this score by comparing the audio's learned representation to the text's learned representation — high overlap means good match.

The paper uses this score as a signal: higher scores mean the model's output is moving in the right direction. During training, preference optimization pushes the model to generate samples that consistently score higher.

Plain reading. The alignment score is just a number between 0 and 1 that CLAP computes by asking 'how much does this audio sound like what the text describes?'
Paper reading. CLAP is a pre-trained model that learns linked representations (lists of numbers that capture meaning) for text and audio. Both are projected to a shared numerical space. The overlap of these representations (measured as how parallel they point) gives the alignment score.
Why it works

Why it works: closing the loop between scoring and learning

Without preference learning, the model trains only to predict any valid audio from the noise — it has no signal about which audio is better, because the loss function treats all valid audios equally whether or not they match the text. With CRPO, the model receives feedback: audios that score high on CLAP get reinforced in training, audios that score low get discouraged. This shapes the model to aim toward the kind of audio that CLAP rewards.

The key is that the model uses the same CLAP scorer to evaluate its own output. On iteration 2, the improved model generates samples; iteration 3 ranks them with CLAP; iteration 4 learns from those rankings. This self-improvement loop means the training data itself evolves — the model is not stuck learning from a static dataset of human labels. The model bootstraps its own training signal.

Math after the picture

The preference-learning equation

First in words:

total_loss = preference_difference_loss + pure_generation_loss, where preference_difference_loss compares the alignment scores of the high-quality and low-quality audios and penalizes when the model makes them too similar

Then the compact form:

L_CRPO = L_DPO-FM + L_FM, where L_DPO-FM = log(sigmoid(loss_winner - loss_loser)) and L_FM is the flow-matching loss on the winner

Every symbol:

loss_winnerhow far the high-quality audio is from the noise starting point
loss_loserhow far the low-quality audio is from the noise starting point
L_DPO-FMpreference ranking loss adapted for audio generation
L_FMpure audio generation loss computed only on the winning sample
sigmoida squashing function that turns any number into a probability between 0 and 1
A tiny worked example
Suppose the high-quality audio has a generation loss of 0.2 (close to the target), and the low-quality audio has loss 0.8 (far from target).
DPO-FM loss scores the margin: log(sigmoid(0.2 - 0.8)) = log(sigmoid(-0.6)) ≈ log(0.35) ≈ -1.05.
But if we only optimized this, the model might later generate both samples with higher loss (0.3 and 0.9). We'd still have a margin, but audio quality dropped. So we add L_FM on the winner: if winner's loss rises to 0.3, we add a 0.1 penalty.
Now the model must: (1) keep high-quality audio high-quality, and (2) make it obviously better than low-quality. Both constraints together drive steady improvement.

The equation prevents the model from satisfying preference ranking by making both good and bad audios worse; it forces improvement in absolute quality, not just relative comparison.

What can go wrong

What can go wrong

CLAP scorer can be wrong. If CLAP assigns high scores to audios that do not actually match the text well, the model learns the wrong target. Preference learning amplifies scorer errors. Fix: use a scorer trained on diverse, high-quality data; validate its rankings on human examples.
Preference loss without baseline loss causes quality collapse. If the model only optimizes for preference margin (DPO loss), it can make both audios worse while keeping their gap — the model loses track of absolute quality. Fix: add the flow-matching loss on winners, as CRPO does. This keeps the model grounded.
Overfitting to CLAP's quirks. CLAP is trained on certain audio styles and descriptions. After many iterations, the model might optimize for CLAP's biases rather than real audio quality. Fix: periodically validate with human listeners; do not iterate indefinitely.
Done right. Use a well-validated scorer, add the quality-grounding loss (L_FM), and stop after a fixed number of iterations or when human evaluation plateaus. The model reliably improves, because the combination of preference ranking and absolute quality grounding prevents both mode collapse and loss of quality.
