MILCCI: Disentangling Labels in Multi-Trial Time Series

A method to split out the individual effects of different label categories hidden inside repeated time-series measurements.

Paper explainersAll themesTime Series & Sequential

You record brain activity across many trials where each trial has multiple labels (like task difficulty and animal choice). The signal you measure is a blend of all label effects mixed together. MILCCI learns sparse building blocks that explain the data and separates which building blocks respond to which labels, revealing how the brain encodes different kinds of information independently.

Zero assumption version

Many repeated measurements, many labels, mixed signal

In neuroscience and other fields, you collect the same measurement many times (trials), and each trial has metadata—task difficulty, choice made, condition type. The raw data blends all these effects together. A naive approach treats each trial separately, which wastes the structure; if two trials differ only in task difficulty, you should expect their brain signals to differ in a consistent way.

A beginner might try generic tensor decomposition (which breaks data into rank-one building blocks) but it ignores the labels entirely, so you get components that are messy mixtures of multiple label effects at once. To truly understand how the brain encodes task difficulty separately from choice, you need a method that explicitly uses the labels to lock each component to specific categories.

In one sentence. Learn sparse components where each one responds to just one or a few label categories, so you can read off exactly which component fires when, say, difficulty changes but choice stays the same.

The algorithm as a flow

What it actually does

Build a label-similarity graph for each category

Group label values (like Hard and Easy) close together if they are similar.

For each trial, select one variant per category

Trial m with labels (Hard, Left) picks the Hard variant of each component and the Left variant.

Fuse the selected variants

Stack the chosen variants horizontally, then multiply by a shared time trace.

Solve via sparse factorization

Use LASSO (a method that finds sparse answers) to estimate each component variant.

Discover interpretable structure

The learned components now cleanly separate the effect of task from choice from any other category.

What the paper changes

What the paper changes

MILCCI changes the component structure: instead of one fixed component per underlying factor, it creates category-specific variants of each component. A component for brain region X now has one version for Hard trials, another for Easy, plus separate versions for Left and Right choices. When you reconstruct a trial, you pick the right variant for each category and layer them together.

the object it moves  =  component variants per category
The hidden quantity

The label encoding: how each category 'lights up' a component

measured quantity  =  Which component variant lights up for each label

The hidden quantity is which component variant is chosen for which label value. For instance, if component 3 has a strong variant for Hard and a weak variant for Easy, then MILCCI has discovered that this component encodes task difficulty. Formally, this is encoded in the component tensor A(k), where each k is a category and each entry in A(k) is a variant.

MILCCI estimates these variants by comparing how well each trial is reconstructed when you include or exclude that component's contribution. If a component's Hard variant explains more than its Easy variant, that component specializes in task-difficulty encoding.

Why it works

Why label-specific variants disentangle the effects

The core mechanism is constraint: by forcing each component to have separate variants for Hard and Easy, you prevent it from doing double duty. If one generic component tried to encode both 'task difficulty causes X increase' and 'choice affects Y', it would have to be a muddled compromise. But if you give it two task-specific variants (Hard and Easy) and two choice-specific variants (Left and Right), the training algorithm can now make the Hard variant strong and the Easy variant weak, while leaving choice variants equal—this clearly shows the component cares only about task.

The method also uses label similarities (e.g., Hard and Hard-plus-feedback are more alike than Hard and Easy) to encourage trial-to-trial smoothness. This prevents overfitting: if two trials share the same task difficulty, their component selections should be similar even if the exact measurements differ. Sparsity (the LASSO method, which finds lean answers with few non-zero parts) further ensures each component stays focused on a narrow set of labels, not spreading strength across many.

Math after the picture

The factorization model

First in words:

For each trial m, the observed signal Y(m) is approximated as the sum of all category components, each scaled by its time trace and weighted by the trial's label selections.

Then the compact form:

Y(m) ≈ sum_k A(k) diag(Φ(m)) where A(k) is category k's component variants and Φ(m) is the trial-specific time trace

Every symbol:

Y(m)the observed signal (e.g., neural activity) in trial m
A(k)the matrix of component variants for category k
Φ(m)the time trace that evolves within trial m
diag(Φ(m))turn the trace into a diagonal matrix (stretch/shrink each component)
sum_kadd up the contributions from all label categories
A tiny worked example
Trial 1 (Hard, Left): Pick Hard variant of component A (strength 5), Left variant of component B (strength 3). Time trace at t=1 is 1.0, at t=2 is 0.8.
Reconstruction at t=1: (5 + 3) × 1.0 = 8
Reconstruction at t=2: (5 + 3) × 0.8 = 6.4
Trial 2 (Easy, Left): Pick Easy variant of A (strength 2), same Left variant B (strength 3).
Reconstruction at t=1: (2 + 3) × 1.0 = 5 (lower because Easy variant is weaker)
Now you can read off: component A varies with task (Hard→5 vs Easy→2); component B is stable across tasks (both get 3).

The sparse LASSO step ensures that each variant has a small number of non-zero entries, forcing the algorithm to find the truly important features rather than spreading activation everywhere.

What can go wrong

What can go wrong

Too few trials per label. If you only see Hard once, the Hard variant is just fit to that one noisy measurement. You need enough repetitions per label value to learn a stable pattern.
Categories are not independent. If task difficulty and choice are always paired together (always choose Left on Hard, Right on Easy), the method cannot disentangle them. You need labels that vary somewhat independently.
Noise drowns out the label effect. If the signal is very noisy and the label-driven component changes are tiny, sparsity and smoothness constraints may hide the effect. Clean data or strong label effects are needed.
Done right: multiple label categories, varied label combinations, moderate noise. MILCCI succeeds when you have enough trials, labels that vary semi-independently, and a signal-to-noise ratio high enough to recover fine structure.
What a runnable demo should prove

What a runnable demo should prove

Build a synthetic multi-trial dataset: for example, 100 trials of 50 time steps, where each trial is labeled with task difficulty (Hard or Easy) and choice (Left or Right). Construct the ground-truth signal by hand: use 3 components, where component 1 fires during Hard trials, component 2 fires during Left choices, and component 3 fires during all trials. Add moderate random noise. Run MILCCI to recover the components and variants. Count how many of the 3 components it recovers correctly, and verify that the recovered Hard variant of component 1 is strong while the Easy variant is weak.

Component recovery rate = (number of ground-truth components correctly identified) / (true number of components)

The demo makes clear that MILCCI recovers interpretable components and that each component's variants cleanly separate the label categories, not murky blends.
