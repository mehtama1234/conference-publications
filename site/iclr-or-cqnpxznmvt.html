Gradient-Sign Masking for Task Vector Transport Across Pre-Trained Models

Reuse a task update from one base model on another by keeping only the weight changes whose direction agrees with a few target-model slopes.

Paper explainersAll themesOther

A task update is the difference between a base model and its tuned version. People hope that this difference can be moved to a newer base model so they do not have to tune again from scratch. The problem is that the same weight change can help on one base model and hurt on another, because the new base model sits at a different local loss shape. This paper shows that the sign of the target-model slope gives a cheap test for which parts of the old task update are still moving in a helpful direction. GradFix keeps the agreeing pieces and masks the rest, using only a few labeled examples and no further tuning loop.

Zero assumption version

Why a good task update breaks on a new base model

Suppose model A was tuned for a task and model B is a newer base model with the same general architecture. The tempting shortcut is to copy the weight difference from A's tuned version onto B. That difference is the source task update. Sometimes this works, but often it hurts because the same numerical change points downhill for A and uphill for B.

The hard part is that you want a cheap repair. Full tuning on model B needs many labeled examples and many update steps. The paper asks whether a tiny labeled set can reveal which pieces of the old task update still point in a helpful direction on model B.

The paper's move in one sentence. Measure a few target-model slopes and keep only the source task changes whose sign agrees, because first-order agreement means the masked update still pushes loss downward.

The algorithm as a flow

What it actually does

Step 1: Form the source task update

Subtract the old base-model weights from the tuned old-model weights.

Step 2: Probe the new base model

Use a few labeled examples to compute the sign of the loss slope at the new base model.

Step 3: Build a mask

For each weight entry, keep the source update if its sign agrees with the target slope and drop it otherwise.

Step 4: Apply the masked update

Add the filtered source update to the new base model in one shot.

Step 5: Use the transported model directly

The method stops there, so it avoids a longer tuning loop.

What the paper changes

What the paper changes

The paper does not learn a whole new update from scratch. It changes the source task update by masking coordinates whose sign conflicts with the target-model loss slope.

the object it moves  =  the coordinate-wise support of a source task update
The hidden quantity

The hidden quantity

measured quantity  =  first-order sign agreement

A copied update helps only if it points downhill for the new base model, because a downhill step lowers loss at the current point. The paper reduces that question to sign agreement: does a coordinate of the source update move in the same positive-or-negative direction that would reduce target loss right now?

This quantity matters because first-order descent depends on the inner product between the update and the local loss slope. Coordinates with the wrong sign push that inner product the wrong way. Removing them can help even if the kept update is smaller, because a smaller downhill step is better than a larger mixed step.

Why it works

Why the masking rule works

Near the current weight setting, loss change is governed first by the local slope. If one coordinate of the proposed update has the opposite sign from the helpful slope direction, that coordinate pushes loss up instead of down. The masking rule removes those coordinates before the update is applied.

This can work with very little data because the method does not need a perfect estimate of the whole loss surface. It only needs rough sign information on many coordinates. That target is cheaper because checking direction is easier than relearning a full tuned update. When the source update already contains task knowledge, these sign checks act as a rebase step: they keep transferable information and discard the parts that are misaligned with the new base model.

The theoretical guarantee follows the same logic. After masking, the inner product with the target slope becomes favorable coordinate by coordinate, so the resulting one-shot update is a first-order descent direction.

A tiny worked example
Suppose the source task update on four coordinates is [2, -3, 1, -4].
Suppose the target loss slopes are [-5, -1, 7, 3].
A helpful update should move opposite to the slope sign, so the desired signs are [+, +, -, -].
The source update signs are [+, -, +, -], so only coordinates 1 and 4 agree.
The mask is [1, 0, 0, 1], and the transported update becomes [2, 0, 0, -4].

The method keeps only the coordinates whose local direction is supported by the target-model slope estimate.

What can go wrong

What can go wrong

The two base models can be too different. If the source and target bases solve the task in very different internal ways, sign agreement on a tiny probe set may keep too little of the useful update. Then transport adds little because there was not much portable structure to recover.
Few-shot slope signs can be noisy. A very small labeled set can estimate some coordinates incorrectly. Wrong sign estimates matter because the mask may drop good coordinates or keep bad ones.
Some tasks need new features, not just a rebased update. If the target task needs weight changes absent from the source update, masking cannot invent them. The method can only filter and reuse what already exists in the source task update.
Done right. The method is strongest when the source update already captures the task and the new base model differs mainly in local weight alignment.
What a runnable demo should prove

What to build

Take two checkpoints of the same model family, tune the older one on a classification task, and compare three transfers onto the newer checkpoint: full task-update addition, slope-sign masking, and ordinary few-shot tuning. Use a tiny labeled set for the masking rule. Report validation loss right after transfer and after a short evaluation run. The paper's claim is visible if the masked transfer starts lower than full addition because it removed uphill coordinates before any tuning loop began.

alignment_score = count of coordinates with matching helpful sign / total checked coordinates

The demo should make clear that masking is not magic reuse by itself; it works because local sign agreement filters the old update into a descent step for the new base model.
