RECON: Robust symmetry discovery via Explicit Canonical Orientation Normalization

A method that corrects how models ground their coordinate systems to discover and align to real-world symmetries without retraining.

Paper explainersAll themesGraph & Geometric Learning

Real-world objects have hidden symmetries — a face looks the same rotated 30 degrees either way, a molecule has mirror-plane symmetries. When a model learns to recognize these objects, it should line them up to a single reference direction so it treats all equivalent rotations the same. Most models pick a reference direction arbitrarily, leaving different examples pointing in wildly different compass directions even when they are the same physical object. RECON discovers the real shared symmetry pattern hidden in the data and realigns all examples to it, so downstream classifiers see each symmetry-equivalent form in the same pose.

Zero assumption version

Arbitrary reference frames break symmetry learning

When you teach a model to recognize objects, you often tell it: 'first extract what the object is (invariant features), then track which direction it is pointing (pose).' The problem: every class gets assigned a reference direction by whoever is training the model — it could be 'nose points up' or 'nose points left', chosen once and frozen. If you train on faces with noses pointing up, and later see faces with noses pointing left, the model treats them as completely different patterns, even though they are the same face.

A naive approach tries: 'I will pick one canonical (reference) direction per class and measure pose relative to that.' But this fails because the canonical direction is arbitrary. Two models trained identically will pick different canonicals, and real data does not naturally align to arbitrary choices. The model sees pose as drifting wildly across the data, making it impossible to learn a clean, shared symmetry pattern.

The core problem. Models ground pose (rotation/orientation) to arbitrary training-chosen reference frames, not to real symmetries in the data. This hides the true symmetry pattern in the data.

The algorithm as a flow

What it actually does

Step 1: Collect examples nearby in invariant space

For input x, find k nearest neighbors in the model's learned feature space (the invariant embedding). These neighbors are perceptually similar — same class, different rotations.

Step 2: Gather their pose outputs

Extract the pose (a rotation or group element) that the model predicted for each neighbor. These poses are currently scattered in arbitrary directions relative to the model's chosen canonical frame.

Step 3: Estimate the centering transformation

Find the central direction in which all these poses point. This is the true shared symmetry distribution. Compute the correction: a single transformation that aligns all poses to this center.

Step 4: Apply right-multiplication correction

Right-multiply each pose by the inverse of the centering transformation. This rotates every pose into alignment without touching the class features.

Step 5: Use corrected poses at test time

Feed the original image through the correction layer, canonicalizing it to the natural reference frame. Downstream classifier now sees examples in aligned poses, improving accuracy.

What the paper changes

What the paper changes: the reference frame

The paper does not redesign the model or the learning process. Instead, it adds one line: a test-time canonicalization layer that corrects the reference frame to match reality. It replaces the model's arbitrary, training-picked canonical with one that aligns to the real symmetry pattern in the data.

the object it moves  =  canonical reference frame
The hidden quantity

The natural symmetry distribution

measured quantity  =  natural pose distribution

Every object has a true distribution of rotations in which it appears in real data. A face might appear in a natural range from −30° to +30°; a molecule might have mirror symmetries baked in. This is the hidden quantity: the real pose distribution that raw, unlabeled data exhibits. It is hidden because the model's arbitrary canonical frame has tilted and scrambled it so it looks scattered and per-class different.

The paper estimates it by looking at which poses cluster together when you find neighbors that are perceptually identical (same invariant features). If ten neighbors all tend to point in roughly the same direction when you look at their raw poses, that direction is the natural center. RECON computes this center for every equivalence class (similar-looking examples) and uses it to correct the pose output.

Why it works

How correcting the reference frame fixes the problem

Here is the causal chain: Models learn to decompose inputs into class (what) and pose (direction). But they ground pose to an arbitrary reference — whatever the training loop happened to pick first. So two examples that are truly the same rotation end up with different pose numbers, because they are being measured relative to different training-chosen canonicals.

RECON detects which examples are truly the same (by finding them as nearest neighbors in feature space) and looks at their raw poses. It notices: they all point roughly the same direction in the model's output space, even though the model thinks they are different. That consistency is the signal. RECON computes a single correction matrix (the centering transformation) that brings all those poses into alignment. When you right-multiply each pose by this correction, you rotate them from the arbitrary training-frame into the natural data-aligned frame.

Why does this help the downstream classifier? Because now when it sees a new face at −10°, the invariant features stay the same, but the pose vectors all point to the same region (the natural distribution). The classifier learns a single decision boundary for 'face in natural pose range' instead of learning separate boundaries for 'face in Class-A-canonical-frame' and 'face in Class-B-canonical-frame'. No retraining needed — the correction happens once, at test time, on top of the frozen model.

Math after the picture

Canonical orientation normalization

First in words:

For each input, compute the centered pose by right-multiplying the model's output pose by a correction transformation. The correction is the inverse of the average direction detected in a neighborhood. Mathematically: adjusted_pose = original_pose times (centering_transformation)^−1.

Then the compact form:

ψ'([x]) = { g * Γ^-1 | g in ψ([x]) }

Every symbol:

ψ'([x])the corrected pose distribution after centering
ψ([x])the original pose vectors for examples in the neighborhood
Γthe centering transformation (the average direction in the neighborhood)
Γ^-1the inverse correction (rotates back to align everything)
* right-multiplication (rotation by the correction matrix)
[x]the equivalence class (neighbors similar to x in invariant space)
Tiny worked example
Suppose the invariant encoder says three neighbors belong together: [x1, x2, x3].
Their original poses (angles) are: ψ(x1) = 10°, ψ(x2) = 15°, ψ(x3) = 12°.
Average direction: Γ = 12.3°. Correction: Γ^-1 = −12.3° (inverse rotation).
After right-multiply: ψ'(x1) = 10° + (−12.3°) = −2.3°, ψ'(x2) = 15° − 12.3° = 2.7°, ψ'(x3) = 12° − 12.3° = −0.3°.
All three now centered near 0°. The downstream classifier sees them in the same reference frame.

The right-multiplication corrects the pose without changing the invariant features, aligning all examples to the natural symmetry distribution discovered in the data.

What can go wrong

What can go wrong

Poor nearest-neighbor search. If the invariant feature space is noisy or the model has not learned good class-disentangled representations, k-nearest neighbors will grab wrong neighbors. Then the centering transformation aligns to noise instead of real symmetry. Result: pose correction fails.
Multimodal pose distributions. Some objects might naturally have multiple disconnected pose families (e.g., left-facing and right-facing forms, not a smooth continuum). A single global centering transformation cannot handle this; it will average conflicting symmetries. The method assumes unimodal or near-unimodal pose distributions.
Distribution shift at test time. If test examples exhibit poses far outside the training distribution (a face at 90° when training only saw −30° to +30°), the centering transformation was learned on training neighborhoods and cannot correct out-of-distribution poses. Detection is possible (part of the method), but correction fails.
Done right. The method succeeds when the invariant encoder is accurate, training data covers the natural pose range well, and the pose family is unimodal (one connected symmetry distribution). In these cases, RECON gives free accuracy gains on any frozen pre-trained classifier.
What a runnable demo should prove

What a runnable demo should prove

Write a small notebook that: (1) loads a pre-trained class-pose decomposition model (e.g., an IE-AE variant) on a rotation-equivariance dataset (FashionMNIST with known rotations, or 3D objects), (2) applies RECON's centering algorithm to the test set by finding k-nearest neighbors in invariant space and computing pose corrections, (3) passes both uncorrected and corrected test images through a frozen downstream classifier (e.g., a simple linear model trained on original canonical poses), (4) measures accuracy, pose alignment quality (hit-rate metric), and out-of-distribution pose detection performance.

accuracy_with_recon - accuracy_without_recon = improvement from canonicalization

The demo must show: (1) corrected poses clustering tightly in the natural distribution while uncorrected poses spread wide, (2) downstream accuracy rising without any retraining, (3) out-of-distribution poses correctly flagged as unreliable.
