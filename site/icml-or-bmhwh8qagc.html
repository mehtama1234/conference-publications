Distribution Transformers: Fast Approximate Bayesian Inference With On-The-Fly Prior Adaptation

Learn a reusable map from prior beliefs to updated beliefs after data arrives, so approximate Bayesian inference can react to new priors in milliseconds instead of retraining for each one.

Paper explainersAll themesOther

Bayesian inference updates a prior distribution, which is the model's starting belief about unknown values, into a posterior distribution, which is the updated belief after seeing data. Exact updating is often too expensive, and many learned approximations assume one fixed prior during training. That becomes a problem in sequential settings such as sensor fusion, where the prior changes from one step to the next. This paper builds a model that accepts a prior itself as input, represents that prior as a Gaussian mixture model, which is a weighted list of bell-shaped components, and transforms it directly into an approximate posterior through attention, which is a rule for letting one part of the input read information from another part.

Zero assumption version

Approximate Bayesian inference usually breaks when the prior changes

In many estimation problems, the data do not arrive all at once. A system sees one batch now, another batch later, and each new batch should update the current belief state rather than restart the whole computation. Standard approximate methods often solve one posterior update at a time with expensive optimization, or they train a learned solver that assumes one prior family and one training setup.

That means a prior change can be costly. If your current belief narrows, splits into multiple plausible modes, or shifts after earlier data, a fixed-prior approximation may no longer match the new problem. The paper asks whether a single learned model can take the prior itself as an input object and learn the whole prior-to-posterior transformation.

The paper's move. Represent the current prior as a set of weighted Gaussian components and let a transformer, which is a model built from repeated attention blocks, update those components with both self-interaction and data interaction, because the model is meant to learn inference as a distribution-to-distribution map.

What the paper changes

What the paper changes

The paper changes the unit of computation from point estimates or fixed-prior solvers to a learned operator that takes one whole belief state and turns it into another whole belief state.

The hidden quantity

The hidden quantity

measured quantity  =  belief-shape fidelity

The hidden quantity is belief-shape fidelity: whether the approximation preserves the important shape of the updated uncertainty, not only its center. That shape includes multiple modes, asymmetry, and concentration. A fast method that collapses a multi-modal belief into one broad average may be numerically convenient, but it loses the very uncertainty structure that Bayesian inference is meant to keep.

Distribution Transformers target this quantity by making the prior representation explicit and editable. Each Gaussian component can move, shrink, grow, or lose weight after seeing data. Because the output is another mixture, the method can preserve several plausible explanations when the evidence does not yet rule them out.

Why it works

Why the architecture can adapt to new priors quickly

The main mechanism is treating the prior as an input rather than as a fixed training assumption. If the model only learned one update rule for one prior, then a new prior would mean a new problem. Here the prior enters as a set of components, so changing the prior means changing the input state, not retraining the whole solver.

Self-attention matters because mixture components are not independent. If one component gains support from the data, another nearby component may need to lose weight or shift position. Updating them jointly helps the model keep a coherent belief state because nearby hypotheses often compete for the same evidence rather than behaving as unrelated pieces.

Cross-attention to datapoints matters because each component should react differently to the evidence. A component near the supported region should strengthen and sharpen, while a distant component should weaken. That selective conditioning is what turns a generic mixture into a data-informed posterior approximation.

Math after the picture

The Bayesian update target

First in words:

The model is trained to approximate the posterior belief, which is proportional to the prior belief times the likelihood of the observed data under each possible setting of the unknown values.

Then the compact form:

posterior(theta | data) proportional to prior(theta) * likelihood(data | theta)

Every symbol:

thetathe unknown values being inferred
prior(theta)belief about those values before seeing the current data
likelihood(data | theta)how compatible the observed data are with one choice of theta
posterior(theta | data)updated belief after combining prior and data
A tiny worked example
Suppose the prior has two plausible regions for theta, one near 2 and one near 8.
A new measurement is much more compatible with values near 2 than values near 8.
After the update, the component near 2 gains weight and may become narrower.
The component near 8 loses weight because the data do not support it strongly.
If the evidence is not decisive, the second component does not need to disappear entirely.
That is the kind of structured update the model learns to produce directly.

The paper's contribution is not the Bayesian formula itself. The contribution is learning a fast operator that approximates this update for changing priors without rerunning a slow solver each time.

What can go wrong

What can go wrong

The mixture representation may be too small. If the true posterior needs more components than the model can represent, the approximation may merge distinct hypotheses or blur sharp structure because there are not enough mixture slots to keep them separate.
Training coverage matters. A learned inference operator can fail on priors or likelihood patterns far outside its training range because it has not seen enough examples of those update geometries.
Attention cost still grows with input size. The method is much faster than repeated slow optimization in the reported tasks, but a very large number of components or datapoints can still raise runtime because the model must process their interactions.
Done right. The architecture is most useful when beliefs change repeatedly and exact inference is too slow, because one trained operator can then perform many updates by reading the current prior directly.
What a runnable demo should prove

What a runnable demo should prove

Build a one-dimensional sequential inference task with priors that can be single-peaked or double-peaked. At each round, generate a new prior from the previous posterior, add a few noisy measurements, and compare three methods: a slow reference solver, a fixed-prior approximation, and the Distribution Transformer.

The demo should show whether the learned operator keeps up when the prior shifts from round to round. The right output is not just a fast mean estimate. It is a fast updated belief whose component weights and locations still match the reference solver closely enough to preserve the important uncertainty structure.

update_error = difference_between_approximate_posterior_and_reference_posterior

The decisive result is that the model can reuse itself across changing priors because it learned how to update beliefs, not merely how to solve one fixed training configuration.
