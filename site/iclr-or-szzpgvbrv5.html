From Embedding to Control: Representations for Stochastic Multi-Object Systems

A method that maps chaotic multi-object dynamics into a simple linear space where standard control algorithms work.

Paper explainersAll themesRobotics & Control

Controlling real systems with many objects — robots, ropes, power grids — is hard because objects interact randomly and the rules can look wildly different depending on their layout. This paper proposes a way to embed those complex dynamics into a space where the rules become linear (straight relationships), so simple control math just works. The trick: use graph neural networks to watch how objects talk to each other, then record their behavior in a Hilbert space, a mathematical place where linear algebra is safe.

Zero assumption version

Why controlling multi-object systems feels impossible

Real systems have many moving parts interacting in unpredictable ways. A rope being controlled has loops, a soft robot has flex points, and a power grid has generators affecting each other. When objects touch and push in random patterns, the rules change constantly.

Engineers used to solve this by hand: design a low-dimensional state (a small set of summary numbers), assume the dynamics (the rules of motion) are mostly linear, then apply standard control math. But this breaks when interactions are non-uniform or the topology (which objects talk to which) keeps shifting. A robot that works on one specific layout fails on a slightly different one.

A beginner might try learning a big neural network to map observations to control signals directly, but neural networks explode in size when trying to capture all possible topologies, and they do not generalize to unseen layouts with few examples.

In one sentence. Map the uncertain, chaotic behavior of many interacting objects into a mathematical space where the rules become linear and standard control math works.

The algorithm as a flow

What it actually does

Encode each object

A graph neural network reads the current state of each object and embeds it into a Hilbert space.

Measure interaction strength

The network computes how strongly each pair of objects influences each other by learning similarity scores from the graph structure and past behavior.

Predict the next state

A conditional embedding operator in Hilbert space predicts where each object will move next, given all the interactions.

Map to linear dynamics

Because of how Hilbert spaces work, these predictions follow linear rules even though the original system is nonlinear.

Run a standard control algorithm

Linear quadratic regulator (LQR) finds the action sequence that minimizes cost in this linear Hilbert space.

What the paper changes

What the paper changes

Standard control methods work in the original space of the system (positions and velocities of all objects), where dynamics are wildly nonlinear and unpredictable. This paper shifts the arena: it learns embeddings (learned representations, lists of numbers) that live in a Hilbert space, a mathematical structure where the same dynamics appear linear. The control algorithm then runs in this learned space instead of the original one.

The hidden quantity

The hidden quantity: how much each object drives the others

measured quantity  =  Per-pair interaction strength

Every pair of objects influences each other, but not equally. Some pairs are tightly coupled, others barely touch. The paper does not observe this coupling directly; instead, it learns a kernel (a similarity function) that scores how much object j's past behavior predicts object i's future state.

The paper estimates this by looking at the graph structure (which objects are connected) and the data history (how did objects actually move?). It uses mean field approximation, which is a trick to efficiently compute the weighted sum of all pairwise interactions without checking every pair separately. The kernel adapts to the specific system and topology, and reuses that learned kernel even for unseen layouts with new object counts and connections.

Why it works

Why it works: Hilbert space linearization

Nonlinear dynamics inside a Hilbert space can look linear from outside. Here is why: a Hilbert space is an infinite-dimensional vector space (a space made of lists of numbers that can be as long as you need) where linear algebra works reliably. If you embed (map) a nonlinear system with random shocks into a Hilbert space carefully, the relationships between embeddings follow linear rules — even though the original system was chaotic.

The paper builds these embeddings by learning a reproducing kernel (a function that measures similarity in feature space). The graph neural network learns which pairs of objects matter most, then the conditional embedding operator predicts the next state by taking a weighted sum of past states and actions — a linear operation in Hilbert space. Because predictions are now linear, linear quadratic regulator (a classical control algorithm that assumes linear dynamics) can find the optimal action sequence without approximation or local linearization hacks.

Mean field approximation speeds this up: instead of summing over all exponentially many graph configurations, the method sums over expected interaction weights, keeping computation tractable even for large systems.

Math after the picture

The embedding prediction equation

First in words:

For each object i, the predicted next state is a sum over all connected objects j, weighted by an interaction kernel learned from data. The weights tell you how much object j should influence object i.

Then the compact form:

E[psi(o_{i,t+1}) | history, action] = sum_j k(o_j) * C_{i|j}(history_j, action_j)

Every symbol:

psi(o_i)the representation of object i in Hilbert space
k(o_j)kernel value showing how important object j is
C_i|jconditional embedding operator: how j predicts i
history_jpast observations and states of object j
action_jcontrol action applied to object j
A tiny worked example
Rope with 2 loops: loop-1 and loop-2. Loop-2 moves up, you want loop-1 to follow.
Kernel says k(loop-2) = 0.8 (high influence). Learned operator C_1|2 says loop-1 future is 0.8 * (0.5 units up from loop-2).
So predict loop-1 moves 0.4 units up. Loop-2 has kernel k(loop-1) = 0.3 (weaker reverse influence).
LQR sees: for every 1 unit you push loop-2, loop-1 follows 0.4 units after lag. Plans the sequence of pushes to keep both in sync with minimal energy.

The sum over j is a linear operation in Hilbert space, so LQR can solve it exactly without local approximations.

What can go wrong

What can go wrong

Kernel assumes smoothness If object interactions are chaotic and discontinuous (e.g., collisions are sudden), the kernel may not capture them well. The method assumes interactions are smooth functions of history.
Mean field breaks with strong correlations When objects are tightly bunched and highly coordinated (not independent), mean field approximation underestimates their joint influence. The method assumes objects can be approximated as independent when computing interaction weights.
Hilbert space embedding may be high-dimensional Even though Hilbert spaces are infinite-dimensional in theory, practical embeddings need enough features (dimension) to capture all the object interactions. If too small, the linearization is lossy.
Done right: topology generalization works When interactions are smooth, objects have partial independence, and the system has enough training data to learn the kernel, GCE scales to new topologies and new system sizes with minimal retraining.
What a runnable demo should prove

What a runnable demo should prove

Build a controllable soft rope or pendulum chain where you can change the number of segments or the stiffness of connections. Train GCE on one configuration (e.g., 5 segments). Then test: (1) predict forward 40 steps on unseen initial states in the same configuration (should have low prediction error), (2) apply the learned LQR policy and measure whether the rope reaches a target position, (3) retrain briefly on a new configuration (7 segments or changed coupling) and measure how many new data points are needed to get the same accuracy.

sample_complexity_gain = (samples_needed_by_baseline - samples_needed_by_GCE) / samples_needed_by_baseline

The demo must make it impossible to miss: GCE reuses the learned similarity scorer even when the number of objects and their connections change, because the scorer captures how interactions work in general, not just for one fixed layout. New topologies can reuse most of the learned scorer, so training takes far fewer examples than learning from scratch.
