SpatialReward: Bridging the Perception Gap in Online RL for Image Editing

A spatial reasoning reward model that teaches image-editing systems to judge edits accurately by anchoring feedback to specific regions of the image, not just overall impressions.

Paper explainersAll themesAgents & Tool Use

When teaching a machine to edit images through trial-and-error learning, the quality of feedback matters enormously—the system learns to repeat whatever the feedback rewards. But existing feedback systems often make the same mistake humans make when skimming: they look at the whole image without checking the details, missing fine-grained errors. This paper introduces a reward model that refuses to skip the details by tying all its judgments to specific pixel regions it actually points to.

The image-editing feedback trap

Online reinforcement learning means teaching a system by having it try edits and then giving feedback—good edits get encouraged, bad edits get punished. For image editing, this works well: the system can learn to find edits humans want.

The critical blocker: the feedback has to be reliable and detailed. A fuzzy 'your edit is good' does not help, because the RL system learns by copying whatever the feedback rewards—vague feedback teaches vague habits. But building systems that reliably evaluate image edits is hard. When humans or models look at two images and judge one edit better than another, they often skip the hard part—they glance at the overall impression and miss specific failures, because focus naturally flows to obvious centers of the image, not to corners. An edit might blur only a corner, or miss one object, or add a stray artifact in a hidden spot. A careless evaluator never notices, calls the edit 'pretty good,' and the RL system learns to ignore those real mistakes, because it only sees the high reward score, not the hidden failure.

The paper calls this widespread failure 'Attention Collapse': models look at images without actually comparing them carefully, region by region. They neglect the fine details and produce miscalibrated scores that steer the RL system in the wrong direction.

Naive approach and why it breaks: A naive evaluator looks at the edited image and the target, forms an overall impression of similarity, and gives a score. It never pinpoints which region changed well and which went wrong, so it misses failures in small areas and gives inflated scores to sloppy edits.

The algorithm as a flow

What it actually does

1. Predict edit regions

The model looks at the original image and the edited one, predicts where changes happened.

2. Crop and compare

For each predicted region, extract that area from both images side by side.

3. Judge each region

Evaluate how well the edit succeeded in each specific area independently.

4. Combine into a fair score

Assemble region scores into a single reward that reflects honest quality across the whole image.

5. Send feedback to RL

The RL system receives the detailed reward and learns which edits actually work.

What the paper changes

What the paper changes

The paper moves from single-number evaluation (one vague overall score) to anchored regional evaluation (specific scores tied to predicted edit regions). Instead of a model that glances at an image and guesses, SpatialReward explicitly identifies where the changes are, crops those regions, and judges each one fairly.

The hidden quantity

The hidden quantity: Regional quality calibration

measured quantity  =  Quality score per edit region

Most existing reward models produce one number: the overall editing quality. But that single number hides a lie—it often reflects only the visible parts (the center of the image, where focus naturally lands) and forgets the corners.

SpatialReward measures a new quantity: the quality score for each predicted edit region separately. Each region gets its own honest assessment, not buried under an average. This is the real information the RL system needs.

The paper estimates this by predicting which pixel regions likely changed, cropping both versions of those regions, and passing each crop through a quality judge. The scores are combined into a final reward, but the RL system benefits because the training process itself forces the model to see every region that changed.

Why it works

Why it works: Forcing spatial grounding

The mechanism is straightforward: by predicting edit regions and then evaluating those regions independently, the model is forced to actually look at the places where changes happened. It cannot gloss over failures in small areas.

Here is the causal chain. When a machine evaluates an edit by looking at the whole image at once, its focus naturally flows to the center and largest objects—just like human eyes. Small regions, corners, and fine details drown in noise. The overall impression ends up high even if important small edits failed.

SpatialReward breaks this by making two predictions: first, where did the edit happen (the spatial regions); second, how good is the result in each region. This two-step reasoning forces the model to allocate mental effort to every part of the image. The RL system then learns that small failures matter because they show up in the regional scores.

This works because the RL algorithm trains on the rewards the model gives. If the reward is honest about each region, the RL system has no choice but to learn to fix problems everywhere, not just in obvious places.

The scoring equation

First in words:

The final reward is the average quality score across all predicted regions, weighted by how confident the model is that each region actually changed.

Then the compact form:

Reward = sum( confidence_i * region_quality_i ) / number_of_regions

Every symbol:

confidence_ihow sure the model is that region i actually contains an edit
region_quality_ithe quality score for region i (comparing original and edited crops)
number_of_regionshow many edit regions the model detected
A tiny worked example
Suppose the model predicts three regions changed: the main object, a corner detail, and background.
Region 1 (main object): confidence 0.95, quality 0.88 -> weighted 0.95 * 0.88 = 0.836
Region 2 (corner): confidence 0.70, quality 0.45 -> weighted 0.70 * 0.45 = 0.315
Region 3 (background): confidence 0.60, quality 0.82 -> weighted 0.60 * 0.82 = 0.492
Final reward: (0.836 + 0.315 + 0.492) / 3 = 1.643 / 3 = 0.548
Notice: the corner region (low quality) dragged down the overall score. The RL system learns that even small edits matter.

The equation is deliberately simple so the focus stays on spatial grounding, not complex formulas.

What can go wrong

What can go wrong

Predicting the wrong regions. If the region-prediction step fails (e.g., the model thinks the sky changed when only the building did), the feedback becomes misleading. The RL system then optimizes the wrong areas.
Over-fragmentation. If the model predicts too many tiny regions, regional scores become noisy and unreliable. If it predicts too few, it misses small but important edits.
Region quality evaluator is still biased. Even when regional crops are examined separately, the quality judge (the second neural network) can still have its own blind spots. Regional isolation helps, because it prevents one bad region from being hidden by averaging, but it does not guarantee fairness if the underlying judge is trained on biased data.
Done right. Train on a large, spatially-diverse dataset so region prediction is accurate; tune the number of regions per image to balance detail and stability; validate that the regional quality judge agrees with human raters on cropped images.
What a runnable demo should prove

What a runnable demo should prove

Build a small online RL loop for a constrained image-editing task (e.g., object brightening or background blur). Train two RL agents: one with a naive single-score reward model, one with SpatialReward. Let each run for the same number of edit steps.

The demo should measure: (a) how many small, localized errors each agent's edits contain (blur in corners, artifacts in small regions); (b) human raters comparing the two final edited images on 20-30 random examples; (c) the RL agent's learning curve (does SpatialReward produce steadier improvement?).

Small_error_count = number of fine-grained flaws (edge artifacts, small blurs, etc.) in the final 50 edits produced by each agent.

The demo should make it impossible to miss that detailed spatial feedback teaches the RL system to care about small regions, not just overall impressiveness.
