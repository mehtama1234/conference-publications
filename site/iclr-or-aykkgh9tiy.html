UIS-Digger: Towards Comprehensive Research Agent Systems for Real-world Unindexed Information Seeking

Build a research agent that does not stop at search results but also opens hard-to-reach pages and files that search engines miss.

Paper explainersAll themesAgents & Tool Use

Many research agents look strong on benchmarks because the needed facts are already indexed by search engines. Real work is messier. Important facts may sit behind dynamic page elements, inside attached files, or on pages that crawlers never captured well. This paper names that gap unindexed information seeking and shows that current agents fail badly on it. UIS-Digger addresses the gap with a multi-agent system that can browse pages and parse files at the same time. That matters because a search result alone may only point toward the answer, while the answer itself lives inside a report, spreadsheet, or expanding page section.

Zero assumption version

Why search-only agents miss real evidence

A modern search agent usually starts by sending a query to a search engine, opening the top links, and summarizing what it sees. That works when the answer is visible in indexed page text. It fails when the answer is hidden in places the index did not capture: a file download, a table revealed after a click, or content loaded only after a page script runs.

The failure is easy to underestimate because common benchmarks reward agents for reaching public facts that are already easy to index. In practice, analysts, researchers, and journalists often need the messy remainder. They need the appendix file, the missing attachment, the page section below a tab control, or the updated number inside an embedded document.

The paper's move in one sentence. Treat page browsing and file extraction as parallel first-class actions, because the answer may be split across both.

The algorithm as a flow

What it actually does

Identify a candidate page.

The agent starts from a search hit or seed page that may contain or point to the answer.

Run live page exploration.

One branch clicks, expands, and scrolls through the page to reveal content that plain indexing missed.

Run file extraction.

A second branch downloads and reads attached files such as reports or tables.

Share findings across agents.

The branches exchange evidence so the system can decide whether a lead is worth pursuing.

Answer from combined evidence.

The final answer is produced from the merged page and file evidence.

What the paper changes

What changes

The paper changes the action space of a research agent. Instead of treating web search as the main path and file handling as an afterthought, it makes page interaction and file parsing equal parts of the same workflow.

the object it moves  =  the agent's evidence-gathering workflow
The hidden quantity

The hidden quantity: evidence coverage beyond the index

measured quantity  =  How much of the answer space the agent can actually reach

The key quantity is not only answer accuracy. It is evidence coverage: how much of the relevant material the agent can access at all. An agent may reason well and still fail because it never reaches the file or page element where the answer lives.

UIS-Digger measures this gap by constructing questions whose answers sit in unindexed places and comparing systems on that set. Large drops on the new benchmark show that standard search-centered agents lose access before reasoning even begins. The dual-mode design aims to close that gap by increasing the fraction of reachable evidence.

Why it works

Why dual-mode browsing recovers hidden answers

The method works because it removes a false assumption built into many agents: that page text visible to a search engine is close to the full evidence set. In UIS tasks that assumption breaks. A search result may only provide the doorway. The decisive number may be inside a downloadable document or behind a page control that must be opened.

UIS-Digger assigns separate branches to these two evidence types so neither blocks the other. While one branch explores the live page, the other can read the attached file and extract structured facts. The branches share their findings, which lets the system connect clues across formats. This improves final accuracy because the missing fact often appears only when page context and file content are joined together.

The evaluation picture

First in words:

Measure accuracy on tasks whose evidence lies in unindexed sources and compare it with accuracy on ordinary indexed benchmarks.

Then the compact form:

uis_gap = indexed_accuracy - unindexed_accuracy

Every symbol:

indexed_accuracyaccuracy on benchmarks where search-engine indexed content is usually enough
unindexed_accuracyaccuracy on tasks where evidence lies in dynamic pages or attached files
uis_gapthe performance drop caused by missing unindexed evidence
A tiny worked example
Suppose an agent answers 71 of 100 indexed benchmark questions correctly.
Now test it on 100 questions where the answer sits in dynamic content or attached files.
It answers only 25 of those correctly.
Indexed accuracy = 71 / 100 = 0.71.
Unindexed accuracy = 25 / 100 = 0.25.
The UIS gap is 0.71 - 0.25 = 0.46.
A smaller gap means the agent is better at reaching and using hidden evidence.

The gap matters because a strong indexed score can hide a severe failure on real evidence that search engines do not expose directly.

What can go wrong

What can go wrong

The agent opens the wrong files. A page may link many attachments, and only one matters. If the file branch chases noisy files, time and budget are wasted before the useful evidence is found.
Dynamic content needs richer interaction. Some pages require login, scripted navigation, or repeated interaction. The dual-mode design helps, but it cannot recover material that the agent is not allowed to access because no page browser or file parser can read content that the system is blocked from opening.
Evidence from page and file conflicts. A live page may be newer than a linked document, or a file may contain a draft value. The system must compare timestamps and source roles because simply merging all text can produce a wrong answer.
Done right. When page exploration and file parsing run together and their evidence is reconciled carefully, the agent answers more real questions because it can reach the hidden support that search-only systems leave behind.
What a runnable demo should prove

What a runnable demo should prove

Build a small benchmark of fifty questions where the answer sits partly in visible page text and partly in an attachment or collapsed page section. Compare a search-only agent against a dual-mode agent that can browse and parse files in parallel. The demo should show a clear drop for the search-only system and a smaller drop for the dual-mode system because reaching the hidden evidence is the real barrier.

coverage_gain = reachable_hidden_sources_dual_mode - reachable_hidden_sources_search_only

The visible lesson should be that better reasoning is not enough when the answer source itself is out of reach, because the agent cannot infer facts from evidence it never accessed.
