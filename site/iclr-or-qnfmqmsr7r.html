Spinning Straw into Gold: Hindsight Relabeling for Agent Learning

When an LLM agent completes a task in the wrong way, a second LLM reads the trajectory and finds all the simpler goals it actually completed along the way, then uses those relabeled successes to train the agent.

Paper explainersAll themesAgents & Tool Use

LLM agents need lots of training examples to learn long tasks, but good examples are hard and expensive to get. This paper finds a hidden source: every messy agent trajectory contains unintended successes buried inside it. A hindsight auditor—another LLM—relabels each trajectory with the goals it actually achieved, turning one failure into several successes.

Zero assumption version

Training agents is a supervision bottleneck

LLM agents live in long chains: the agent sees a scene, picks an action, gets feedback, picks the next action. To train one agent, you need hundreds of hand-crafted good examples showing correct step-by-step paths. If an example fails—the agent took a wrong turn halfway through—the whole trajectory gets thrown away.

A beginner might try: collect more examples. But that is expensive. The hidden waste: most "failed" rollouts contain genuine intermediate wins—the agent opened the right door, collected the right object, took a step toward the goal—even if it eventually crashed. Those wins are just never labeled or used.

The method in one sentence. Hindsight Supervised Learning relabels completed agent trajectories with all the simpler goals they actually achieved, then trains on those relabeled pairs.

The algorithm as a flow

What it actually does

Collect rollouts

Agent runs many trajectories (success or failure).

Auditor relabels

Second LLM reads each trajectory, writes down all intermediate goals completed.

Mask irrelevant steps

For each relabeled goal, mark which actions matter toward it, mute the rest.

Reweight samples

Give more weight to cleaner relabeled goals, less to noisier ones.

Train the agent

Fine-tune on relabeled pairs using standard supervised or preference learning.

What the paper changes

What the method changes

The paper changes the training dataset itself. Instead of using only clean hand-labeled goal-trajectory pairs, it creates new pairs by relabeling messy agent rollouts with goals the agent actually achieved. Each relabeled pair is a (trajectory_segment, natural_language_goal) where the goal is something the agent genuinely accomplished in that segment.

the object it moves  =  training data labels
The hidden quantity

The hidden quantity: Action relevance

measured quantity  =  relevance of each action to a goal

Action relevance is a simple yes/no label on each step: "Did this action matter toward the goal?" For example, if the relabeled goal is 'pick up a key,' then opening a drawer is relevant but turning left is noise. The paper's hindsight auditor (the second LLM) infers this relevance for each step in each relabeled trajectory.

How the paper measures it: The auditor looks at the trajectory, the relabeled goal, and the environment state at each step, then outputs a binary label (relevant or irrelevant) for each action in the segment. Masking uses this to downweight irrelevant steps during training—so the gradient (the learning signal nudging weights) focuses on the path to the goal, not the noise.

Why it works

Why relabeling and masking work

The core insight: failed trajectories waste because we throw away intermediate progress. The auditor recovers that progress by reading the trajectory and naming simpler goals the agent did achieve. Once a goal is named, training can use standard supervised learning—the agent sees a trajectory segment and learns to repeat the actions that led to that goal.

Masking sharpens that learning because without masking, the training signal includes noise steps that do not help the goal. The learning gradient (the directional nudge to weights) treats all steps equally, so noise dilutes the true causal path—the gradient is spread thin across irrelevant actions, each nudging weights in a confused direction. Masking downweights irrelevant steps, so the gradient focuses weight updates on the actions that genuinely moved toward the goal, like a beam of light rather than a scattered spray. Reweighting further lifts cleaner, less noisy relabelings higher in the training queue, so the agent learns from high-confidence targets first.

The auditor itself is not trained—it is a capable pre-existing LLM reading with zero-shot reasoning. This is cheap at test time (one forward pass per trajectory) but trades computation for supervision: the method uses an external LLM, so training compute goes up. The gain is sample efficiency: fewer human-labeled examples needed because relabeling mines new successes from existing failed rollouts.

Math after the picture

The learning objective

First in words:

minimize the cross-entropy loss on relabeled trajectories, mixed with a fraction of ground-truth supervised loss

Then the compact form:

L_HSL = lambda * L_relabeled + (1-lambda) * L_groundtruth

Every symbol:

L_HSLtotal loss the agent learns from
L_relabeledloss on hindsight-relabeled goal-trajectory pairs
L_groundtruthloss on hand-labeled examples
lambdamixing weight: how much to trust relabeled vs. original labels (0 to 1)
A tiny worked example
Suppose lambda = 0.6 and we have two loss terms: L_relabeled = 0.8, L_groundtruth = 0.4.
Then L_HSL = 0.6 × 0.8 + 0.4 × 0.4 = 0.48 + 0.16 = 0.64.
The agent learns 60% from relabeled data (cheaper, more diverse) and 40% from ground truth (expensive, trusted).
If we used only relabeled (lambda=1.0), loss would be 0.8—higher. If only ground truth (lambda=0), loss is 0.4—but we waste the relabeled data.

The mixing weight lets the agent balance between mining cheap relabeled successes and relying on expensive hand-labeled truth.

What can go wrong

What can go wrong

Auditor hallucinates false goals. The relabeling LLM might claim the agent achieved a goal it did not. For example, reading a trajectory where the agent opened a drawer, the auditor might falsely label "obtained key" even if no key exists. The agent then trains on a lie, degrading performance.
Masking is wrong or incomplete. If the relevance labels are inaccurate—marking noise as relevant or relevant steps as noise—the learning gradient is misdirected. The agent learns spurious correlations instead of the true causal path to the goal.
Relabeling becomes outdated as the agent learns. Relabeling happens once per trajectory offline. If the agent later learns to complete goals differently, the old relabeled paths may become suboptimal or misleading for the new learned behavior.
Done right. Use a capable auditor LLM with strong reasoning ability. Verify a sample of relabelings by hand. Reweight noisy relabelings lower. Mix enough ground-truth labels to anchor training in truth. Test on held-out tasks to catch performance changes on unseen task types.
What a runnable demo should prove

What a runnable demo should prove

Build a simple agent on a short task with multiple mini-goals along the way (e.g., a room-navigation task where the agent must open doors, collect objects, and reach a final location). Collect 50 trajectories, most of which fail partway through. Manually relabel 10 of them with intermediate goals, then train two agents side by side: one on only the 5 successful full trajectories, one on all 50 trajectories with their relabeled intermediate goals. Measure success rate on held-out test tasks.

improvement = (HSL_success_rate - baseline_success_rate) / baseline_success_rate

The demo must show that training on relabeled intermediate goals (from failed rollouts) beats training on only clean full successes, even with the same number of rollout samples.
