Scaling Agents via Continual Pre-training

Build stronger agentic models by learning tool-use patterns before teaching them to follow instructions.

Paper explainersAll themesAgents & Tool Use

Large language models are becoming agents that solve problems step by step using tools like web browsers and code. But when you train them to be agents, the model must learn tool patterns and follow instructions at the same time, pulling it in opposite directions. This paper shows that if you first teach the model tool-use patterns on raw data, then teach it to follow human guidance, it becomes much better at both, because learning one skill solidly first means training can focus entirely on the second skill instead of juggling both.

Zero assumption version

Teaching a model to be an agent breaks it

A language model is a machine that predicts the next word. If you just take a model trained to predict words and tell it to act like an agent (think, search the web, read results, decide), it fails. It was never taught how agents actually behave.

The usual fix is to take a general-purpose model and add training data showing how agents should act (examples of someone thinking step by step, using a browser, reading results, deciding). But here is the problem: the model now has to learn two things at once. First, it must learn what agent patterns look like (searching web pages, parsing results). Second, it must learn to copy the exact style of the human examples it sees. These two goals fight each other. The model cannot concentrate on both equally, and both end up weak.

The fix: teach tool-use first, alignment second. Pre-train the model on raw agentic data to learn tool patterns, then fine-tune on human examples to learn alignment.

The algorithm as a flow

What it actually does

Step 1: Collect agentic data

Gather raw examples of agent behavior (web searches, code runs, tool calls).

Step 2: Pre-training phase

Train the model to predict what comes next in agentic sequences (not supervised, just learn patterns).

Step 3: Agentic foundation model ready

The model now knows what tools look like, how they are used, what the output means.

Step 4: Fine-tuning phase

Show it human-written examples of good agentic decisions and alignment to instructions.

Step 5: Deploy

The model can now both use tools skillfully and follow your instructions.

What the paper changes

What the paper changes

The paper changes the training schedule: it inserts an agentic pre-training phase before the fine-tuning phase that teaches alignment. This is a reordering of two steps that were always there, but doing them in the right order.

the object it moves  =  Training sequence order
The hidden quantity

The hidden quantity: tool-use foundation strength

measured quantity  =  Agentic foundation capability

Before this paper, models had no measure of how well a model understood agent behavior on its own, separate from alignment. This paper uncovers that hidden quantity: the ability to predict what comes next in a tool-use sequence without any instruction-following training. A model with this capability built in learns alignment faster and better, because the weights already encode what tools do, so fine-tuning only needs to learn decision logic instead of tool behavior.

The paper estimates this by measuring how well the pre-trained model completes agentic traces before any instruction fine-tuning is applied. Traces where the model naturally predicts the right next tool call or decision show that agentic patterns are embedded deep in the weights.

Why it works

Why learning order matters

When you train both tool-use and alignment together, the learning signals fight. The model sees examples of web searches and also examples of a human deciding when to search. It tries to build one unified pattern, but they are different patterns with different rules. The model wastes capacity trying to reconcile them.

If you teach tool-use first, the model learns what the building blocks are and how they connect. Weights that know how to model a browser response, how to parse results, how code runs, settle into place. These patterns are now stable.

Then during alignment training, the model only needs to learn the decision logic: when does this situation call for a web search versus code? The weights for modeling tools are already solid, so training focuses entirely on the meta-level decisions. The model learns alignment faster because it is not relearning tool patterns at the same time.

Math after the picture

The training objective

First in words:

Pre-training loss = sum of negative logarithms of predicted probabilities on agentic data. Fine-tuning loss = sum of negative logarithms of predicted probabilities on aligned examples.

Then the compact form:

L_pre = -sum_t log(P(word_t | agentic_context)) ; L_fine = -sum_t log(P(word_t | human_example_context))

Every symbol:

word_tthe correct next word in position t
agentic_contextthe history of tool calls and results before word_t
human_example_contextthe history in a human-written agent example
P(word_t | context)the model's predicted probability of word_t given the context
log()logarithm, a function that turns multiplication into addition
A tiny worked example
During pre-training, the model sees: 'The user asked for weather. The agent calls [search weather London]. The result is cloudy 15C.'
It learns to predict cloudy and 15C are likely to appear near tool results.
Pre-train loss on just those 2 words: -log(0.8) - log(0.7) = 0.22 + 0.36 = 0.58
During fine-tuning, it sees: 'User asked for weather [search weather London] is the right tool because the user wants information.'
It learns when searches are appropriate. Fine-tune loss improves because tool-modeling is already learned.

Two separate objectives applied in sequence allow the model to fully solve tool-use before learning when to apply it, because during pre-training the learning signal is purely about tool patterns and during fine-tuning it is purely about decision logic.

What can go wrong

What can go wrong

Pre-training on low-quality agentic data. If the agentic traces in pre-training contain mistakes or do not show good tool use, the model learns bad patterns and fine-tuning cannot fix them easily. The foundation becomes weak.
Mismatch between pre-training and fine-tuning tasks. If pre-training uses web-search data but fine-tuning uses code-execution tasks, the model learned tool patterns that do not apply. The agentic foundation does not transfer because the skills are mismatched.
Over-training on agentic data before alignment. If pre-training is too long, the model overfits to patterns in agentic traces and becomes rigid. Fine-tuning then struggles to teach new decision logic.
Done right. The pre-training data is diverse, clean, and covers the tools the agent will use. Fine-tuning data comes from the same domain and shows good decisions. The two phases are balanced.
What a runnable demo should prove

What a runnable demo should prove

Build a simple agent task: the model reads a question, decides whether to search the web or answer from memory, and then produces an answer. Record accuracy on this task after two training approaches: (1) old way: train on instruction-following examples mixed with web-search examples for 100 iterations; (2) new way: pre-train on web-search traces for 50 iterations, then fine-tune on instruction-following examples for 50 iterations. Show that the new way reaches higher accuracy in fewer instruction-following iterations, because pre-training builds the tool-use foundation so fine-tuning can focus on alignment.

Accuracy = (correct decision + correct answer) / total_examples after 50 fine-tuning steps

The key proof: the new approach reaches the same accuracy as the old approach in half the instruction-following training time, because the tool patterns are already learned.
