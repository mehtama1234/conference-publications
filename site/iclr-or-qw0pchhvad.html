Contextual Causal Bayesian Optimisation

Choose not just what values to try, but which variables to change, using both causal graph structure and current context.

Paper explainersAll themesOptimization

When you optimize an expensive system, you can try different action values and observe the result. This paper shows how to pick not only the values but also which variables to change, using information about how variables affect each other and the current state of the system. By jointly optimizing both the policy (what values to set) and the variables to operate on, it reduces wasted trials because you skip dead-end variable combinations, and finds better solutions faster because the algorithm learns which subsets work in each context.

Zero assumption version

The trap: picking variables naively wastes trials

When you want to optimize a system (say, tuning a manufacturing process), you need to decide which dials to turn and what values to set them to. Most optimization methods do one of two things: either they ignore the causal structure (how variables depend on each other) and just adjust whatever seems promising, or they use causal knowledge but keep the set of variables you can control fixed throughout.

This leads to a fundamental problem. If you choose the wrong set of variables to control, you waste hundreds of trials exploring values that can never reach the optimum because the causal graph forbids it. A beginner might try all variables every time, but in high-dimensional systems that means exploring billions of combinations that the graph rules out. A specialist might use causal knowledge to narrow down variables, but lock that choice in from the start. When conditions change, a different subset might be faster (because certain subsets reach the optimum quicker in certain contexts), but the locked choice keeps wasting trials on the old subset since it cannot adapt.

The method: At each trial, pick both which variables to intervene on (using the causal graph) and what values to set them to (using observed context and past results), balancing exploration with the knowledge that some variable subsets are more useful than others.

What the paper changes

What the paper changes

Instead of fixing a single policy scope (which variables to control), the paper makes it dynamic. At each trial, the algorithm chooses which subset of variables to intervene on, because different contexts and causal structures reward different subsets. This choice is informed by the causal graph (which subsets can even reach the target) and by which subsets have performed best in past trials under similar contexts (so the algorithm learns which subset wins when the system is in state A, versus state B).

The hidden quantity

The hidden quantity: regret

measured quantity  =  Cumulative regret over trials

Regret is the total distance between what you achieved and what you would have achieved if you had known the optimal solution from the start. Each trial adds to this regret. The paper measures how much regret accumulates as you run more trials.

The algorithm estimates regret using an uncertainty measure (called upper confidence bound, which comes from Bayesian optimization). At each step, it tracks how uncertain it is about the best value for each variable subset, then picks the subset and values that reduce uncertainty the fastest.

Why it works

Why it works: multi-level matching

The paper works in layers. First, it uses the causal graph to compute which subsets of variables can affect the target (these are called POMPS sets). This is a hard logical constraint: if the graph says temperature does not reach the output, it is impossible to use temperature alone to optimize. So the algorithm never wastes trials on dead ends.

Second, at each trial, it picks which of these valid subsets to use. This choice is based on a running average of success under similar contexts. If subset A has worked well when the system was in state X, and we are in state X again, we try subset A again. This avoids thrashing between different strategies, because the algorithm learns a mapping from context to the best variable subset.

Third, once a subset is chosen, the algorithm runs Bayesian optimization over its values, using the context as additional input. Bayesian optimization balances exploration (try a value we are uncertain about) with exploitation (try a value that worked before). The causal structure narrows which subsets are possible (eliminating branches the graph forbids), and the context narrows which subset is likely to work (pinpointing the subset that succeeded in this state before), so the exploration step covers fewer dead zones because it skips impossible branches and previously-failing subsets, finding good values faster.

The regret bound equation

First in words:

cumulative regret is bounded by a sum over trials, where each trial's contribution depends on how uncertain we are about the best values for the chosen variable subset

Then the compact form:

R_T = sum_t=1^T (f* - f_t) <= C sqrt(T log(T))

Every symbol:

R_Ttotal regret over T trials
f*the true best outcome (unknown)
f_tthe outcome we achieved at trial t
Ca constant that depends on the problem (dimension, noise level, causal structure)
Tnumber of trials
sqrtsquare root
A tiny worked example
Suppose the true best output is 100, and we run 10 trials.
Trial 1: we get 50 (regret = 100 - 50 = 50). Cumulative = 50.
Trial 2: we get 70 (regret = 30). Cumulative = 80.
Trial 3: we get 85 (regret = 15). Cumulative = 95.
Trials 4-10: we get 92, 95, 97, 98, 99, 99, 99 (regrets 8, 5, 3, 2, 1, 1, 1). Cumulative = 95 + 8 + 5 + 3 + 2 + 1 + 1 + 1 = 116.
The bound says regret grows as sqrt(10) * log(10) = 3.16 * 2.3 = 7.3x; our actual regret 116 is plausible for a harder problem.
The key: early trials waste more, but later trials converge because the algorithm learned which variables matter.

The square root growth means that doubling trials does not double regret. This is sublinear because as more trials happen, the algorithm accumulates data that pins down which variable subset works best in each context, so each new trial wastes less.

What can go wrong

What can go wrong

Causal graph is wrong. If the given graph does not match reality, the algorithm finds valid subsets that cannot actually affect the target. Garbage in, garbage out.
Context is irrelevant or noisy. If the context variables do not predict which subset works best, scoring subsets by past context-similar trials fails because the algorithm groups unrelated past trials together and picks the wrong subset, wasting trials re-learning.
Too many valid variable subsets. If almost all subsets can theoretically affect the target, the algorithm must score many subsets, and regret grows as you explore them all.
Done right. The causal graph is accurate, context is informative, the number of valid subsets is moderate, and the underlying Bayesian optimization routine (HEBO) is configured well. Then the algorithm converges smoothly and beats fixed-scope methods.
