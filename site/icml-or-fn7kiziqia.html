SE(n)-Invariant Flow Matching for Object Reassembly

When teaching a model to reassemble puzzle pieces, make it ignore global rotation and position and only learn the shape itself.

Most learning methods treat a rotated solution as wrong, penalizing the model unfairly. This paper builds a training system that sees through global rotations and translations, letting the model focus solely on which pieces fit together and what shape they form.

Why naïve training breaks on reassembly

Object reassembly is a shape-reconstruction task: you have N fragments and need to position them in space to rebuild the original object. The challenge is that the correct solution is not unique — the same shape can sit anywhere in space and be rotated any way.

Standard training uses a loss function (a penalty score). If the model positions pieces correctly but rotates them 90 degrees, the loss function sees mismatched coordinates and penalizes it as wrong. The model cannot tell that it has actually solved the puzzle, just rotated the answer.

Existing methods patch this with ad-hoc rules (like anchoring one fragment in place), but these break the natural symmetry of the problem: permuting which fragment you anchor gives different answers. And the penalties lead to data-augmentation arms races where you must rotate/translate the training data many times.

In one sentence. The paper builds a training loss that ignores global rotations and translations, letting the model learn only the intrinsic shape.

The algorithm as a flow

What it actually does

Step 1: Take a configuration

Start with N fragments at arbitrary positions and rotations in space.

Step 2: Gauge Fix deterministically

Use an inertia-based rule to rotate and center all configurations the same way, removing the freedom to change global pose.

Step 3: Project onto the shape space

Work only with the intrinsic shape (how pieces relate to each other), not coordinates in world space.

Step 4: Match with flow

Use flow matching (a training technique where the model learns a smooth path from noise to correct shape) on this shape-only space.

Step 5: Invariance guaranteed by construction

Because training never sees global pose, the model cannot learn to rely on it, so any solution works at any rotation or position.

What the paper changes

What the paper changes

The paper changes the training objective (the loss function and how gradients flow). Instead of training on raw coordinates in full SE(n) space, it trains on the quotient space: the shape of the configuration with global pose removed.

The hidden quantity

The hidden quantity: Global pose

measured quantity  =  Global rigid motion (rotation + translation)

Global pose is the overall position and rotation of the entire configuration in space. Two solutions that differ only by a global rotation or translation are actually the same solution to the reassembly problem — they have the same shape.

The paper measures and removes pose by using a deterministic alignment rule (the inertia principle: center and orient all configurations by their moments of inertia). Once pose is fixed, the paper operates only on the remaining degrees of freedom — the shape itself.

Why it works

Why it works: Gauge fixing plus projection

The mechanism has two parts. First, Global Gauge Fixing (GGF): use an intrinsic rule based on the inertia (how mass is distributed) of the fragments to pick a canonical alignment for every configuration. This removes the freedom to choose different poses for the same shape — all versions of the same shape align the same way automatically.

Second, flow matching operates on the quotient space: the space of all configurations with global pose removed. When the training loss compares a prediction to a target, it projects both onto this reduced space (using orthogonal projection onto the tangent directions that do not change pose). The model never sees coordinates that change only due to global rotation or translation, so it cannot learn to rely on them.

Why does this work? Because the loss ignores pose changes, the model's gradients never reward it for moving things in pose-changing ways. The only way to lower the loss is to move pieces relative to each other — to change the shape. Permutation invariance is preserved automatically because the inertia rule treats all fragments equally, and the quotient space has no special fragment.

The quotient-invariant flow matching objective

First in words:

Loss equals the squared distance between the flow-matched prediction and the target, both projected onto the tangent space perpendicular to pose changes.

Then the compact form:

L = ||Proj_horizontal(flow_pred) - Proj_horizontal(target)||^2

Every symbol:

flow_predthe model's predicted step toward the target
targetthe ground-truth fragment configuration
Proj_horizontal(x)project x onto the horizontal tangent bundle (directions that change shape, not pose)
||·||^2squared distance (sum of squared differences)
A tiny worked example
Suppose a configuration has 3 pieces. The full space has 18 numbers (3 pieces × 3 coords + 3 pieces × 3 rotations in degrees).
Global pose uses 6 numbers (3 for center position, 3 for rotation). These are fixed by gauge fixing.
Shape uses 12 numbers (the relative positions and angles of pieces 2 and 3 relative to piece 1).
Flow matching loss is computed only on the 12 shape numbers, ignoring the 6 pose numbers.
If a candidate solution has the correct shape but is rotated 45 degrees, its 12 shape numbers are identical to the target, so loss = 0.
The model learns shape because shape is all the loss ever measures.

Gauge fixing pins down pose deterministically, so flow matching operates purely on shape.

What can go wrong

What can go wrong

Gauge fixing may fail if fragments are degenerate. If all pieces lie on a line or plane, the inertia distribution (how mass spreads across the pieces) gives no information about rotation and cannot define a unique orientation. The method assumes fragments have enough 3D structure.
Permutation ambiguity remains unsolved. Gauge fixing removes pose, but if two fragments are identical (same shape), the model still must guess which is which. The invariance is to pose, not to relabeling pieces.
Flow matching requires careful conditioning. The model must learn to map noise to the correct shape at each timestep. If the flow is poorly conditioned (e.g., pieces start very scrambled), training may be unstable.
Done right. Use gauge fixing on all training configurations, measure loss only on shape space, and train flow matching with a smooth noise schedule. The method works by construction — invariance is built in, not hoped for.
What a runnable demo should prove

What a runnable demo should prove

Build a 2D or 3D jigsaw puzzle solver: generate N puzzle pieces from a simple shape (e.g., a 2D triangle or 3D cube). Shuffle them (rotate, translate, permute). Train a flow-matching model with SE(n)-invariant loss. Then rotate the input by 90 degrees and test: if the model reassembles it correctly without retraining, you have proven invariance.

Reassembly accuracy = (pieces within threshold distance of their true positions) / N

The demo must show that a model trained on one orientation solves the puzzle at any orientation, no data augmentation needed. That is the proof of invariance by construction.
