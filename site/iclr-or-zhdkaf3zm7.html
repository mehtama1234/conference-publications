Weight-Space Linear Recurrent Neural Networks (WARP)

Instead of hiding the state inside a fixed list of numbers, WARP makes the hidden state the weights of a little helper network that learns by listening to input changes.

Paper explainersAll themesTime Series & Sequential

Traditional recurrent networks crush all the memory about a sequence into a single snapshot of numbers called a hidden state. WARP flips this: it makes the hidden state into the weights and biases of a tiny helper network. This lets the network silently adapt its weights at test time (without running the training machinery) and naturally encode domain knowledge from physics into its learning.

Zero assumption version

Recurrent networks trap information in a fixed-size box

A traditional recurrent neural network (a model that processes one element of a sequence at a time, updating its memory as it goes) keeps its memory as a fixed list of numbers. When a new input arrives, the network computes which numbers to change and by how much, then updates that same fixed-size memory.

But real sequences often demand different amounts of memory at different times. Some patterns fade quickly and can be forgotten; others stay important the whole way through. A fixed-size memory cannot tell the difference — it has no way to say 'this pattern is now obsolete, so I will free up this slot' or 'this pattern will matter for a thousand steps, so I need to protect it carefully.'

The method. WARP replaces the fixed memory list with the weights and biases of an auxiliary network, letting those weights slide around freely as the network observes new input differences.

The algorithm as a flow

What it actually does

Take the input difference

Compute how much the latest input changed from the previous one.

View it as a small update direction

That difference is the signal that nudges the weights of the helper network.

Slide the weights

Add the input difference (scaled) to the current weights; this happens instantly, no training needed.

Pass data through the updated helper

The auxiliary network (with freshly-adapted weights) processes the current input.

Output the prediction

The output is the answer for this sequence position; memory has naturally shifted along with the input.

What the paper changes

What the paper changes

Instead of a fixed list of numbers, the paper makes the hidden state into the weights and biases of an auxiliary network. This single change unlocks three new abilities: the network can adapt its weights at test time without re-training, it can learn patterns directly from data without being told, and it can have physics knowledge baked in.

The hidden quantity

Weight drift: how much the auxiliary network's weights have moved

measured quantity  =  weight drift magnitude

The hidden quantity here is how far the auxiliary network's weights have drifted from their starting point. At the beginning of a sequence, all weights start at their trained values. As each new input difference arrives, those weights slide a little. After ten steps, after a hundred steps, the weights may be very different from where they began.

WARP does not explicitly measure this drift — it emerges naturally. The drift accumulates because each input difference adds to the weights. Over a long sequence, some weights drift far, others barely move. Weights that drift far are the ones responding to important patterns; weights that barely move are either unimportant to that sequence or were already well-matched at the start.

Why it works

Why it works: input differences steer adaptive weights

The core mechanism is surprisingly direct. At each time step, the network computes the difference between the current input and the previous one. That difference is scaled and added straight to the auxiliary network's weights. This is a form of linear recurrence — each weight updates by a small amount proportional to the input difference, with no expensive training machinery needed.

Why does this work? Input differences capture what is changing in the sequence. If the sequence is drifting upward, the input difference will be positive, and the weights will drift in a compatible direction. If the sequence bounces, the input difference will flip sign, and the weights will be nudged backward. Over many steps, the weights end up encoding a compressed summary of the sequence's dynamics.

This mechanism also explains why physics priors work: if you initialize the auxiliary network with weights that obey physical laws (e.g., conservation of energy, smoothness), then sliding those weights by input differences keeps them in a physically reasonable neighborhood. The network never strays far from the constraint.

Math after the picture

The update equation

First in words:

new weight equals old weight plus (learning rate times input difference)

Then the compact form:

w_i(t+1) = w_i(t) + alpha * (x(t) - x(t-1))

Every symbol:

w_i(t+1)the weight i at the next time step
w_i(t)the weight i at the current time step
alphaa small learning rate (how much to change per step)
x(t)the input at the current step
x(t-1)the input at the previous step
x(t) - x(t-1)the input difference (change from last step)
A tiny worked example
Step 1: input is 5.0, previous input was 5.0, difference is 0.0. Weight w1 starts at 1.0. w1(1) = 1.0 + 0.1*0.0 = 1.0 (no change).
Step 2: input is 7.0, previous input was 5.0, difference is 2.0. w1(2) = 1.0 + 0.1*2.0 = 1.2 (weight moves up by 0.2).
Step 3: input is 6.0, previous input was 7.0, difference is -1.0. w1(3) = 1.2 + 0.1*(-1.0) = 1.1 (weight moves down by 0.1).
The weights track input motion: up when input rises, down when it falls, stationary when stable.

The weight update is linear in the input difference, so weights drift smoothly and predictably as the sequence unfolds.

What can go wrong

What can go wrong

Learning rate too high. If alpha (the step size) is set too large, the weights will swing wildly and overshoot the true dynamics. The sequence will feel chaotic.
Learning rate too low. If alpha is tiny, the weights change so slowly that they lag behind real input changes. The network will be stale and miss patterns.
Physics priors conflict with data. If you bake in physical laws (e.g., conservation of energy) but the data violates them, the weight updates will fight the constraints and produce bad predictions.
Learning rate tuned right. When alpha is set to track input changes smoothly without overshoot, weights adapt in lockstep with the sequence, enabling both fast test-time learning and accurate physics-informed modeling.
What a runnable demo should prove

What a runnable demo should prove

Build a small WARP model on a synthetic dynamical system (e.g., a harmonic oscillator or a simple pendulum). Feed it a time series of position and velocity measurements. At each step, the network reads the current state and input difference, slides its auxiliary weights, and predicts the next state. Plot the auxiliary network weights over time to show how they drift in sync with the sequence dynamics. Then swap in physics-informed initialization (weights that respect energy conservation) and show that the same mechanism keeps those constraints alive, leading to a more stable and accurate long-term prediction.

prediction error = mean squared difference between predicted next state and actual next state; weight drift alignment = how well weight movement correlates with sequence energy/momentum

The critical observation is that the auxiliary weights move smoothly and predictably, tracking input changes without training, and that physics rules remain intact across hundreds of prediction steps because the update rule respects them.
