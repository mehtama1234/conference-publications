PrivAct: Internalizing Contextual Privacy Preservation via Multi-Agent Preference Training

Teach each agent to follow context-sensitive privacy rules during action generation so that the full system shares useful information without leaking details that should stay private.

Paper explainersAll themesAgents & Tool Use

This paper studies a hard privacy problem in multi-agent systems: whether an agent should reveal a fact depends on who is asking, what role they have, and what task is underway. Many current defenses add a separate privacy filter at run time. That can fail because the filter only reacts after unsafe content is already produced, and it can miss cases where several harmless facts become harmful when combined. PrivAct moves the privacy rule inside each agent through preference training so that the agent learns to act helpfully while withholding information that the current context does not permit.

Why privacy rules must depend on context

In real tasks, privacy is rarely a simple list of forbidden facts. The same detail may be appropriate in one exchange and inappropriate in another because the people, task stage, and purpose differ.

External blocking tools help in some cases, but they can be brittle because they sit outside the agent's own decision process. The paper asks whether agents can learn the privacy rule directly, so that each action is produced with the context already taken into account.

The paper's move in one sentence. Train each agent with privacy-aware preferences so that helpful actions and private boundaries are learned together.

The algorithm as a flow

What it actually does

Describe the interaction context

Record who is speaking, what role they have, and what information the task truly requires.

Build preference comparisons

Create better and worse responses so that training can favor helpful private behavior over equally helpful but unsafe behavior.

Train each agent

Update the agent to prefer context-appropriate replies because those replies satisfy the task without unnecessary exposure.

Run agents together

Let the trained agents communicate inside a larger multi-agent workflow.

Measure leakage and help

Check whether private details drop while task performance stays high so that the tradeoff is visible.

What the paper changes

What the paper changes

The paper changes the agent's internal choice rule so that privacy is part of action generation instead of a separate after-the-fact patch.

The hidden quantity

The hidden quantity

measured quantity  =  Contextual permission to reveal information

The key hidden quantity is whether a candidate detail is appropriate for the current exchange. That depends on role, purpose, and information need. You cannot read that permission directly from a single sentence.

PrivAct learns this hidden quantity from preference data. The model is rewarded for outputs that respect the current context because good privacy behavior requires more than detecting obviously sensitive words.

Why it works

Why this works: privacy is easier to preserve when it shapes the reply from the start

An external guard can only inspect what the agent already decided to say. If the agent's plan itself depends on unsafe information sharing, a late guard may cut out text but still leave a weak or confused answer. Training the agent to prefer private actions works better because the planning and wording are both shaped by the privacy rule.

The multi-agent setting matters because one weak participant can spread sensitive facts through the whole system. Giving each agent the same privacy habit helps system-wide behavior because unsafe disclosures are reduced at the source, not only at the edge.

Math after the picture

Choose replies that are useful but context-safe

First in words:

A simple summary is to give a higher score to a reply when it helps the task and follows the privacy rule for the current context, while subtracting a penalty for unnecessary disclosure.

Then the compact form:

score(reply, context) = task_help(reply, context) + privacy_fit(reply, context) - leak_cost(reply, context)

Every symbol:

score(reply, context)overall value of a candidate reply for this situation
task_help(reply, context)how much the reply helps the agents finish the current task
privacy_fit(reply, context)how well the reply matches the disclosure rule implied by the current role and purpose
leak_cost(reply, context)penalty for sharing details that are not justified by the context
A tiny worked example
A scheduling agent asks a profile agent for meeting support.
Reply A shares available time and also shares the user's medical note.
Reply B shares only the available time that the scheduler needs.
Reply A: task help 8, privacy fit 2, leak cost 7, total 3.
Reply B: task help 8, privacy fit 9, leak cost 1, total 16.
Training prefers Reply B because it keeps the useful part while avoiding disclosure that the task does not require.

The paper uses preference training inside a multi-agent framework rather than this exact formula, but the formula captures the balance between task utility and context-sensitive disclosure.

What can go wrong

What can go wrong

Preference labels may miss hard edge cases. If the training comparisons do not cover rare contexts, the agent may still reveal details because it never learned the right boundary for those cases.
Too much caution can hurt coordination. An agent can become unhelpful if it withholds details that teammates truly need, so the training signal must reward useful sharing when the context permits it.
Privacy rules can vary across organizations. A policy learned in one setting may not transfer perfectly because another setting may define roles and permissions differently.
Done right. The paper is useful because it treats privacy as part of the agent's policy, which reduces reliance on brittle outer filters.
What a runnable demo should prove

What a runnable demo should prove

Build three agents for a support workflow: one holds account details, one plans actions, and one communicates with the user. Create requests where some facts are required for the task and others are sensitive unless a specific role asks for them. Train one version with ordinary task preferences and one version with privacy-aware preferences.

The demo should log every inter-agent message and score both completion and disclosure. It should show that the privacy-aware version keeps task success close to the baseline because the needed facts can still move through the system, while unnecessary details drop because agents learned when disclosure is not justified.

privacy_gain = leakage_rate_baseline - leakage_rate_privact

The demo must prove that privacy can be learned inside the policy so that multi-agent coordination stays useful without relying on a fragile outer checker.
