MaskPro: Stable Sparsity Learning via Loss Residuals

MaskPro learns which weights to keep in an LLM by using policy gradients guided by loss residuals instead of raw loss, making training stable and fast.

Paper explainersAll themesEfficiency & Systems

Large language models are huge and slow to run. Hardware can speed them up if the weights follow a specific sparsity pattern: keep N out of every M weights, skip the rest. The challenge is learning which weights to keep. Simple rule-based approaches make mistakes. Learning-based approaches that try every possible combination are too slow. MaskPro solves this by treating weight selection as a probability distribution and using a clever training trick—measuring loss changes instead of raw loss—to steer learning without instability.

Zero assumption version

The hardware-friendly sparsity trap

Modern chips run fast when data is packed densely. If you remove weights randomly from a neural network (a model that learns by adjusting millions of numbers), the remaining weights scatter unevenly and the chip slows down. But if you remove them in a structured pattern—say, every weight group of 32 numbers keeps exactly 16, arranged the same way in every group—the chip can accelerate it with built-in hardware and save memory.

The problem: how do you decide which 16 weights to keep in each group of 32? A naive approach: greedily pick the 16 biggest numbers in each group, layer by layer. This is fast but makes errors, because it ignores how the whole model works together. The opposite extreme: try every possible combination of 16 choices from 32 (that is over 600 million possibilities per group), using training to learn the best ones. This finds better answers because it considers model-wide effects, but each combination requires running the model through training, which takes hours or days for a real LLM.

In one sentence. MaskPro learns which weights to keep by assigning a probability to each weight and letting the model learn those probabilities using fast probability-based steering, with a stabilized training signal that ignores randomness from the data.

The algorithm as a flow

What it actually does

Assign probabilities

For each group of M weights, give every weight a probability dial.

Sample a mask

Spin each dial, randomly choose N weights to keep, zero the rest.

Measure loss change

Run the model, measure loss. Then, measure what the loss would be with a different random mask on the same data batch.

Train on the difference

Use the difference (residual) to update probability dials, not the raw loss itself.

Smooth out data noise

Keep a rolling average of past residuals so one weird batch does not jolt training off course.

What the paper changes

What the paper changes

The paper changes the training signal used to steer learning. Instead of using the raw model loss, it uses the loss residual: the difference in loss between the currently sampled mask and a reference mask on the same data. This isolates the effect of changing the mask from noise caused by variation in the training data.

the object it moves  =  training signal
The hidden quantity

The hidden quantity: loss residual

measured quantity  =  loss residual with smoothing

The loss residual is the difference in model loss caused by changing the mask, independent of data variation. In mathematical terms: if mask m produces loss L(m) and mask m-reference produces loss L(m-ref), the residual is the gap L(m) minus L(m-ref), measured on the same batch of data. This quantity isolates how much the mask choice itself matters, removing noise from randomness in the data.

MaskPro estimates this by sampling two masks and measuring their loss difference. It then applies a moving average tracker (like averaging the last 10 changes) to smooth out outlier batches. This tracker acts as a buffer: if one batch happens to have low loss for both masks (making the difference look small), the moving average tells the true long-term pattern instead.

Plain reading. The paper's key insight is that training a probabilistic mask learner is unstable when you look at raw loss, because data randomness creates huge noise. By measuring only the loss difference caused by changing the mask, you get a cleaner signal. By smoothing that signal over time, you get a stable training process.
Paper reading. MaskPro introduces a new policy gradient estimator (PGE) that replaces the standard loss metric with per-minibatch loss residuals. A moving average tracker of residuals further stabilizes the signal, preventing aggressive updates caused by outlier batches. The theory shows that once loss drops below half its initial value, this smoothed residual tracker achieves near-optimal training efficiency.
Why it works

Why it works: isolating mask impact from data noise

Here is the core problem MaskPro solves. When you use policy gradients to learn a mask, the training signal is the model loss. But the model loss comes from two sources: the quality of the mask chosen and the randomness of the data batch. Most batches will have low loss anyway (good data luck), so the signal gets buried. A mask that works great might appear bad on a lucky batch, and a bad mask might appear good on an unlucky batch. The training signal jitters randomly.

MaskPro's fix: measure the loss difference instead. Take two masks (one current, one reference), run both on the same batch, and measure how much the loss changed. Now the data randomness cancels out: both masks faced the same lucky-or-unlucky batch, so the difference tells you only the mask effect. Then add a smoothing tracker: keep a rolling average of past differences. This buffer prevents any single weird batch from yanking the probabilities in the wrong direction.

The reason this works mechanically: policy gradient training needs a signal that tells it whether a mask choice was good or bad. That signal should be stable and honest. Raw loss has huge noise. Loss residual has much less noise because the data effect is subtracted out. Smoothing the residual gives a signal that is both clean and stable, allowing the learning algorithm to confidently steer probabilities toward good masks.

The learning update with loss residuals and smoothing

First in words:

gradient update equals the smoothed loss residual times the log-probability gradient of the mask

Then the compact form:

g_sr = (f(m ⊙ w, ξ) − f(m_0 ⊙ w, ξ) − δ_t) ∇log p(m|π)

Every symbol:

mthe current sampled mask (binary: 1 means keep, 0 means remove)
m_0the reference mask for comparison
wthe model weights
⊙element-wise multiplication (apply the mask)
ξone minibatch of training data
f(·, ξ)the model loss on that batch
δ_tthe moving average of past residuals (smoothing tracker)
πthe probability dial settings
p(m|π)the probability of sampling mask m given the dial settings
∇log p(m|π)which direction to nudge the dials to increase probability of mask m
g_srthe gradient for updating the dials
A tiny worked example
Say at iteration t, we sample mask m and get loss 2.5 on batch ξ.
We sample reference mask m_0 and get loss 2.8 on the same batch.
The residual is 2.5 − 2.8 = −0.3 (mask m is 0.3 units better).
The moving average (smoothing tracker) is currently δ_t = −0.1 (average of past residuals).
Smoothed residual is −0.3 − (−0.1) = −0.2 (slightly adjusted for noise).
The gradient ∇log p(m|π) tells us how to nudge the dials to favor mask m.
We update the dials by: Δπ ∝ −0.2 × ∇log p(m|π) (push dials toward mask m).
Next iteration, we update the moving average to (−0.1 + −0.3) / 2 = −0.2.

The key is subtracting the smoothing tracker: it removes noise from data variation, leaving only the pure mask effect, which is a stable signal for learning good probability dials.

What can go wrong

What can go wrong

Moving average lag on new tasks. If you start training on a very different task (e.g., a language model trained on English then switched to code), the smoothing tracker will be out of date. Early learning steps will be misdirected until the moving average adapts. The paper mentions resetting the reference mask when loss drops below half its initial value to mitigate this.
Choosing the wrong reference mask. The method compares the current sample to a reference mask. If the reference mask is consistently bad, the residual is always positive and never steers learning. If the reference mask is too similar to the current mask, the residual is too small to read signal. The paper uses a simple default (e.g., a default mask) but does not fully specify how this choice affects learning.
Very small batches can still have high variance. The moving average reduces but does not eliminate noise. With batch size 1, data randomness still creates outliers. The paper demonstrates stable performance down to batch size 1 but does not claim perfect stability.
Done right: loss residual + smoothing tracker. When both the residual and the moving average are used together, the training signal is clean enough that the probability dials converge to good masks even on noisy data. The paper shows this holds across different initialization seeds and batch sizes.
What a runnable demo should prove

What a runnable demo should prove

A demo should show the training dynamics of MaskPro step by step. Start with a small language model (e.g., a 100-million-parameter model) and apply (2-of-4) sparsity: keep 2 out of every 4 weights. Run three parallel training runs: vanilla policy gradient (raw loss), policy gradient with loss residual, and MaskPro (residual plus smoothing tracker). Plot training loss for each run. Show that vanilla PGE jitters randomly (because raw loss is noisy), residual PGE is smoother, and MaskPro PGE is smoothest and converges fastest. At the end, show that the learned sparse model preserves accuracy while reducing memory.

training_stability = std_dev of loss over iterations, accuracy_preservation = sparse_model_accuracy / dense_model_accuracy

The key observation is that smoothing the training signal by using loss residuals lets you learn good masks quickly without trying every combination. The moving average tracker prevents noise-driven jitter, making learning confident and fast.
