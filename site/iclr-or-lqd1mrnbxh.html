Test-Time Mixture of World Models for Embodied Agents

A robot learns to mix multiple world models at runtime, picking the right one for each new situation it encounters.

Paper explainersAll themesRobotics & Control

A robot trained on one environment often fails when placed in a new one, because the patterns it learned no longer fit. This paper proposes Test-Time Mixture of World Models (TMoW): instead of training one fixed model to handle everything, the robot carries multiple specialized models and learns to pick which one to use as situations change. This happens during real-world operation, not just during training.

Zero assumption version

Why robots fail in new environments

A robot learns a world model: a mental picture of how the environment works. Show it a picture, describe an action (like open the door), and it predicts the next picture. This works great in the lab where it trained.

Put that same robot in a new building or a new room, and it breaks. The patterns have shifted: lighting is different, furniture is arranged differently, the door handle looks nothing like before. The model was tuned for one specific place and cannot adapt.

A naive fix: train one huge model on every possible environment. This is impossible. You cannot list every room in the world. And even if you could, the model becomes bloated, slow, and forgets what it learned on early data as it trains on new data.

The method in one sentence. Instead of one rigid model, carry a team of specialized models and learn which one to trust for each new scene, updating that choice as you go.

The algorithm as a flow

What it actually does

The robot sees a scene

Camera gives it pixels and descriptions of objects present.

Each model makes a guess

All four models predict the next frame. Each one is confident but may be wrong.

Router scores the models

A learned router compares: which model's prediction looks most like what actually happened? Vote accordingly.

At runtime, router weights shift

As more scenes come in, the router re-learns which model to trust, without changing the models themselves.

When truly new domains arrive

A new model is built from blending existing ones and a handful of new examples, no expensive retraining.

What the paper changes

The one thing that changes

The paper changes how a robot picks which world model to use. Instead of that choice being locked in at training time, it becomes a learnable number that updates as the robot operates in the world.

the object it moves  =  Router weights
The hidden quantity

Model suitability: how well each model fits

measured quantity  =  Model suitability per scene

The paper measures an invisible quantity: for each scene the robot sees, which specialized model is actually the right one to trust? This is not a single number but a hidden fact the paper must infer.

The paper estimates this by comparing each model's prediction to what actually happened. A model whose prediction was close to reality has high suitability for that scene. Over time, the router learns to spot patterns: scenes with lots of blue light should lean on the Office model, scenes with pots and pans should lean on the Kitchen model. The paper calls this multi-granular routing: at the object level (a coffee mug is a clue for Kitchen), at the scene level (all the pots together), and everywhere in between.

Why it works

Why learning the router at test time works

You do not need to retrain the world models themselves to adapt to a new place. The models are fixed. What changes is the mixing weights — how much to trust each model on this particular task.

Here is why this works mechanically. A world model is a collection of learned weights that embody patterns. Retraining those weights from scratch on new data is slow and risks destroying old knowledge. But the mixing weights are tiny: just a few numbers that say which model to listen to. Updating a few mixing numbers from new data is fast, safe, and does not require GPU time or a full training loop.

The paper adds one more piece: when a completely new domain appears (a building the robot has never seen), it does not add a fresh model from scratch. Instead, it combines what the existing models learned (sharing their patterns) and adds just a few new examples. This is called distilled mixture-based augmentation. It works because the existing models already know a lot — they just need to be tweaked together, not built from nothing.

Math after the picture

The router equation

First in words:

The score for model i given scene s is: a weighted sum of how similar the scene is to each place the model was trained on.

Then the compact form:

score_i(s) = sum_j w_ij * similarity(s, prototype_j)

Every symbol:

score_i(s)how much model i should be trusted for scene s
w_ijthe learned weight: how much prototype j should contribute to model i
similarity(s, prototype_j)a number from 0 to 1: how much does scene s look like the training prototype for place j
sum_jadd up the contributions from all training places j
A tiny worked example
Suppose model 1 was trained on Lab A. Lab A prototype has bright white walls. Model 2 was trained on an office with cream carpet.
A robot now sees a bright white room with cream carpet (new building). similarity to Lab A = 0.8, similarity to office = 0.6.
If w_11 = 3.0 (how much Lab A matters for model 1), then score_1 = 3.0 * 0.8 = 2.4.
If w_12 = 1.0 (how much office matters for model 1), then it adds 1.0 * 0.6 = 0.6.
Total: score_1 = 2.4 + 0.6 = 3.0. Model 1 gets 3.0 points.
If model 2 scored only 1.5 and model 3 scored 2.0, the robot picks model 1 because it has the highest score.

The router learns these weights w_ij by watching: when the similarity to Lab A predicts well, boost w_ij; when it is wrong, lower it. This happens during operation, not training.

What can go wrong

What can go wrong

Routers overfit to small shifts. If the robot only sees a tiny change in lighting between domains, the router might memorize that specific difference. A different kind of lighting shift breaks it. Solution: make sure the training domains are diverse enough that the router learns real patterns, not surface tricks.
Models trained poorly to begin with. If one of the four models was trained badly on its home domain, the router cannot save it. It is routing among options, not fixing broken models. Solution: each base model must be solid.
Distillation loses information. When building a new model from existing ones plus a few examples, blending them might smooth away important details. A very fine-grained skill in a new domain might not survive the distillation. Solution: if a new domain is very different, collect more examples or train a dedicated model.
Done right. When each base model is strong, the domains are diverse, and new scenes have enough examples, the router finds the right blend within hours of deployment, not weeks of retraining.
What a runnable demo should prove

What a runnable demo should prove

Set up three environments: a training kitchen, a training office, a held-out living room that the models have never seen. Train separate world models for kitchen and office. Deploy them together with a router initialized to zero (equal weight).

Show that during the first hour of operation in the living room, the router learns to pick the office model 60 percent of the time and the kitchen model 40 percent. This blended prediction matches ground truth better than either model alone, because the living room has some office-like features (furniture layout) and some kitchen-like features (appliances and lighting), so each model catches what the other misses.

Then add a distilled third model made from five random frames in the living room plus the kitchen and office patterns. Show that the router now trusts the new model 70 percent of the time, improving accuracy by another 5 to 10 percent.

Accuracy = fraction of next-frame predictions that match observed reality within a pixel error of 10.

The demo makes impossible to miss: adjusting which model to use cuts deployment time from weeks to hours, compared to training a fresh model.
