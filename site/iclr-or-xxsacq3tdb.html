Designing Rules to Pick a Rule: Aggregation by Consistency

Choose a rank-aggregation rule by asking which rule would reproduce the most stable aggregate ranking if the same data collection were repeated.

Paper explainersAll themesOther

Rank aggregation rules often disagree. One rule may favor the top of the list, another may smooth more broadly, and both can look reasonable. This paper asks how to choose among those rules without assuming one fixed data model. Its answer is to choose the rule that would give the most repeatable ranking if you collected similar data again.

Zero assumption version

Why picking an aggregation rule is hard

When many judges, systems, or users produce rankings, you often need one combined ranking. Social choice and statistics offer many ways to do that, yet different rules can produce different final orders from the same input.

The hard part is one level higher: how do you choose the rule itself? A hand-picked rule may work on one dataset and fail on another because different datasets contain different amounts of noise, disagreement, and tie structure.

In one sentence. Pick the aggregation rule whose output stays most consistent across repeated data collection, because a stable rule is less driven by accidental quirks of one sample.

The algorithm as a flow

What it actually does

List candidate aggregation rules

Start with several plausible ways to combine rankings.

Resample the observed ranking data

Create many sampled versions of the dataset so the method can mimic repeated collection.

Run each rule on each sample

Produce an aggregate ranking for every candidate rule on every sampled dataset.

Measure repeatability

Score a rule by how similar its aggregate rankings stay across samples, because a stable rule depends less on quirks of one observed dataset.

Pick the rule with the highest consistency score

Use that rule on the full dataset to produce the final ranking.

What the paper changes

What the paper changes

The paper changes the criterion for rule selection. Instead of choosing a rule for elegance, habit, or a fixed assumed model, it chooses the rule that gives the most repeatable aggregate ranking under repeated sampling.

The hidden quantity

The hidden quantity

measured quantity  =  aggregation consistency

The hidden quantity is how stable a rule's output ranking would be if the ranking data were collected again. A rule with high consistency changes little from one repeated sample to another, because it captures a strong common ordering signal rather than reacting to random sample noise.

The paper uses this quantity to compare rules directly on the data at hand. That matters because the best rule can differ by dataset, and consistency offers a model-light way to adapt the choice.

Why it works

Why the method works

A weak aggregation rule is overly sensitive to accidental variation in who ranked what and how. When the sample changes slightly, the final ranking can jump, which means the rule is amplifying noise.

A consistent rule behaves differently. Small changes in the observed rankings leave the aggregate order mostly intact because the rule is capturing the signal that many samples would share.

Sampling provides a practical way to estimate this property. The method cannot rerun the real data collection many times, so it creates many sample versions of the current dataset and asks which rule's outputs agree most across them. That score becomes the rule-selection target.

Math after the picture

The core equation

First in words:

A rule's score is the average agreement between aggregate rankings produced from many sampled replications of the data.

Then the compact form:

consistency(rule_r) = average over sampled pairs (agreement(aggregate_r(sample_a), aggregate_r(sample_b)))

Every symbol:

rule_rone candidate aggregation rule
sample_a, sample_btwo sampled versions of the observed ranking data
aggregate_r(sample)the ranking produced by rule_r on one sampled dataset
agreement(x, y)how similar two aggregate rankings are
consistency(rule_r)the stability score used to pick the rule
A tiny worked example
Rule A produces rankings with pairwise agreement scores 0.62, 0.66, and 0.60 across sampled datasets.
Its average consistency is about 0.63.
Rule B produces agreement scores 0.81, 0.79, and 0.83.
Its average consistency is about 0.81, so Rule B is selected.

The paper proves exact optimization is hard, so the practical method estimates consistency through sampling.

What can go wrong

What can go wrong

Sampling may not reflect true recollection. If the observed dataset is very small or unrepresentative, sampled copies of it may not mimic real repeated data collection well.
Most candidate rules may be weak. The best rule in a poor candidate set can still be poor, so consistency only helps among the options you provide because selection cannot invent a strong rule that is absent.
Stability is not the only goal. A very stable rule can still miss another property you care about, such as fairness or sensitivity to the very top ranks.
Done right. The method is most useful when repeatability is important because stable aggregate rankings are easier to trust in downstream decisions.
What a runnable demo should prove

What a runnable demo should prove

Take a ranking dataset with several candidate aggregation rules. Produce many sampled versions of the dataset, score each rule by average ranking agreement across samples, and then compare the selected rule against a fixed default rule.

The selected rule should yield a more stable final ranking under held-out resampling because consistency is the selection target itself.

stability_gain = consistency(selected_rule) - consistency(default_rule)

The demo should show that choosing the rule by repeatability can change the final winner among aggregation rules and can make the final ranking less sample-sensitive.
