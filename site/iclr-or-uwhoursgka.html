Welfarist Formulations for Diverse Similarity Search

Treat each attribute group as a claimant on the result list, score a candidate set by how much similarity utility each group receives, and choose neighbors that raise the joint welfare score instead of only chasing the top raw similarities.

Paper explainersAll themesOther

Nearest-neighbor search usually returns the items most similar to a query. That is fine when only relevance matters. It breaks when the list should also cover different sources, sellers, authors, or other attributes, because a plain top-k search can spend nearly all slots on one dominant group. This paper replaces fixed diversity constraints with welfare objectives from economics. Each attribute group gets utility equal to the total similarity mass assigned to that group, and the result set is scored by a welfare function over those utilities. Nash social welfare, which is the geometric mean of group utilities, raises the score only when relevance is high and no group is starved, so the balance between relevance and diversity changes with the query instead of being fixed in advance.

Zero assumption version

Why top-k similarity alone gives redundant lists

Standard nearest-neighbor search takes a query and returns the k items with the largest similarity scores. If many of those items come from the same seller, topic, or demographic group, the list can still look good under raw similarity because the objective only adds scores. The search rule has no reason to save slots for underrepresented attributes.

A common repair is to impose a hard diversity rule such as requiring a minimum count from each attribute. That does force coverage, but it uses the same quota for every query. Some queries naturally have broad relevant support across groups, while others concentrate relevance in a few groups. A fixed quota can block very relevant items in one query and still leave too little diversity in another.

The paper asks for a score that changes smoothly with the query. It should reward relevance, punish starvation of any attribute group, and let the user tune how much fairness they want without hand-writing a separate rule for each case.

The paper's move. Assign each attribute group a utility equal to the similarity mass it receives in the chosen set, then maximize a welfare score over those utilities rather than using raw similarity sum or a fixed diversity constraint.

The result still prefers relevant items, but it stops wasting all slots on the same attribute.

The algorithm as a flow

What it actually does

Split items by attribute

For each attribute value, keep the items belonging to that group and rank them by similarity to the query.

Define group utilities

If the chosen set contains several items from one group, add their similarities to get that group's utility.

Apply a welfare rule

Score the whole set with a welfare function such as Nash social welfare, which is the geometric mean of the group utilities.

Build the set step by step

At each step, add the candidate item that gives the largest increase in welfare, using the best ranked remaining item from each group.

Layer on top of ANN

Use any approximate nearest-neighbor engine to fetch strong candidates within each group first, then run the welfare selection on those candidates.

The hidden quantity

The hidden quantity

measured quantity  =  How much utility each attribute group actually receives

The visible list only shows the chosen items. The hidden quantity is the allocation of similarity mass across attribute groups. Two result sets can have almost the same total similarity but very different utility splits, and those splits determine whether the list is redundant or balanced.

The welfare objective makes that split explicit. Once each group has a utility number, the search problem becomes an allocation problem: which additional item raises the joint score the most, given the utility each group already has.

Why it works

Why welfare fixes the rigid quota problem

A raw similarity sum adds contributions independently, so it keeps rewarding the same group as long as that group still contains high-scoring items. It has no internal penalty for concentration. A welfare score does have that penalty because extra utility sent to a group that is already well served changes the geometric mean less than utility sent to a group near zero.

That change in marginal value is the whole mechanism. Early in the search, an item from a missing group can raise the welfare score a lot even if its similarity is not the very largest, because it prevents one utility term from staying tiny. Later, once every group has some utility, the score can return to favoring stronger matches because an extra point of similarity now raises the joint score more than adding a weak item to a group that is no longer starved. The method therefore adapts to the query rather than enforcing the same mix every time.

The algorithm is also practical because it does not replace the nearest-neighbor engine. It first asks the base search method for strong candidates within each group, then performs the welfare-aware choice over that reduced pool. That keeps the expensive geometric part small while still using the speed of existing ANN systems.

Math after the picture

The core score

First in words:

For a chosen set, first add the similarity scores inside each attribute group to get that group's utility. Then combine those utilities with a welfare rule. In the Nash case, the score is the geometric mean, so one tiny utility drags down the whole value.

Then the compact form:

NSW(S) = (u_1(S) * u_2(S) * ... * u_c(S))^(1/c)

Every symbol:

Sthe chosen set of k neighbors
u_j(S)utility received by attribute group j, computed from similarities of chosen items in that group
cnumber of attribute groups
NSW(S)Nash social welfare score of the set
A tiny worked example
Suppose k is 3 and there are three groups.
Set A gives utilities [27, 1, 0.5]. Its total similarity is 28.5.
Set B gives utilities [12, 9, 7]. Its total similarity is 28.
Plain top-k prefers Set A because 28.5 is larger than 28.
Nash welfare prefers Set B because the geometric mean punishes the near-zero third group in Set A.

This score balances relevance and diversity because each utility term still comes from similarity, yet the product falls when one group receives very little.

What can go wrong

What can go wrong

Attribute labels can be noisy. If items are assigned to the wrong group, the welfare objective allocates score to the wrong place, so the list can look balanced on paper while missing the intended diversity in practice.
A group can have almost no relevant items. If one attribute has very weak candidates, a strong fairness setting can force poor matches into the list because the objective still tries to avoid starving that group.
Candidate fetch can miss needed items. The selection stage only sees the items returned by the base ANN calls. If that fetch step fails inside a group, the welfare optimizer cannot recover the missed candidates later.
Done right. The method is useful when relevance and diversity must both matter, because it turns diversity from a fixed rule into a score that responds to the actual query.
What a runnable demo should prove

What a runnable demo should prove

Build a search toy with four attribute groups and a query-dependent similarity table. Let the user choose k and a fairness strength. Show three result lists side by side: plain top-k, a hard quota rule, and the welfare objective. For each list, display total similarity, per-group utilities, and the welfare score.

The demo should also show the stepwise selection trace. After each chosen item, update the group utilities and show why the next item changed. That matters because the paper's main claim is about marginal gain: the value of an item depends on which groups are already served.

coverage gain = covered_groups_welfare - covered_groups_topk

The demo proves the point if a user can see one query where hard quotas are too rigid and another where plain top-k collapses to one group, while the welfare objective adjusts in both cases.
