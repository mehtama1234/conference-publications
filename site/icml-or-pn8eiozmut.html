Score-Repellent Monte Carlo: Toward Efficient Non-Markovian Sampler with Constant Memory in General State Spaces

Keep one running summary of past score evaluations so the sampler is pushed away from places it has already explored too much, reducing repeated visits without storing the full path history.

Paper explainersAll themesOther

Monte Carlo sampling estimates averages by drawing many dependent samples from a target distribution, which is just the rule that says which states should appear often and which should appear rarely. Standard Markov chain methods only look at the current state when proposing the next one, so they can spend a long time revisiting the same region. This paper adds a small memory: a running average of score evaluations, where a score is the derivative of log density and points toward directions of increasing probability. That memory creates a temporary repulsive term that discourages oversampling regions the chain has already summarized heavily.

Zero assumption version

History-dependent samplers need memory, but full memory does not scale

Sampling methods are often used to estimate an average under a hard target distribution. If the chain revisits the same mode again and again, the estimate changes slowly because new samples add little information beyond what was already seen.

A natural fix is to make the sampler remember where it has already spent time and push itself away from those regions. On a small finite state space, one can store visit counts or an measured measure, which is just a table of how often each state was seen. That becomes unusable in high-dimensional spaces because the table is enormous, and it becomes ill-posed in continuous spaces because exact states are almost never revisited.

The paper asks for a compressed memory that still captures where the chain has overexplored. It must fit in constant memory, update online, and plug into ordinary Markov chain kernels, which are transition rules that preserve the original target distribution when used alone.

In one sentence. Replace full trajectory memory with one running average in score space, then use that summary to repel the chain from already-explored directions.

The algorithm as a flow

What it actually does

Evaluate the score at the current state

Compute the score, which is the derivative of log density and shows how the target changes locally.

Update one running history summary

Average the new score into the existing history list of numbers using an online recursion.

Build a temporary tilted target

Use the history list of numbers inside an exponential tilt so directions aligned with old exploration become less favored.

Apply a base sampling kernel

Run one ordinary transition step targeting the temporary tilted distribution.

Estimate expectations from the full chain

Use the resulting path to compute averages under the original target while the history keeps adapting.

What the paper changes

What the paper changes

The paper changes the target seen by the chain at each step. Instead of always sampling from the original target, it samples from a history-tilted surrogate whose tilt is determined by one running score summary.

The hidden quantity

The hidden quantity: the running score summary

measured quantity  =  running score summary

The method never stores past states directly. It stores a running average of score evaluations. Because the score points toward higher-density directions, the average reveals which directions the chain has repeatedly followed. If that average is large in a certain direction, the chain has received the same signal many times and is likely overexploring one region.

That summary matters because it turns raw history into a compact control signal. The sampler does not need to know every state it visited; it only needs a summary strong enough to say, 'recent exploration has already favored these directions, so damp them for now.'

Why it works

Why a score summary can repel redundant exploration

A Markov chain gets stuck in practice because local transitions keep seeing similar local directional derivatives, which are local rates of change, inside the same mode. If the algorithm can detect that those local directions have already been followed many times, it can temporarily reduce their pull. That is exactly what the running score summary does.

The tilt is built from the alignment between the current score and the stored history. When the current state produces a score that agrees with the accumulated summary, the surrogate target is downweighted there. That downweighting matters because it reduces acceptance or attractiveness of moves that would continue reinforcing the same explored direction. When the current score points elsewhere, the penalty is smaller, so transitions toward less-used directions survive more easily.

The wrapper is generic because the inner kernel only needs a target density up to normalization. The surrogate target has that same form, so one can run a familiar kernel on it without computing any new normalizing constant. The memory cost stays linear in state dimension because the algorithm stores one list of numbers and updates it online after each step.

Math after the picture

The history tilt equation

First in words:

The surrogate target multiplies the original density by an exponential penalty derived from how strongly the current score aligns with the running history summary. The history summary itself is updated by a weighted average, so old information decays while new information is incorporated.

Then the compact form:

pi_theta(x) proportional to pi(x) * exp(- alpha * <theta, score(x)>), with theta_next = (1 - eta) * theta + eta * score(x)

Every symbol:

pi(x)original target density at state x
score(x)derivative of log density at x
thetarunning average of past score values
alpharepellence strength controlling how strongly history alters the surrogate target
etastep size for updating the running summary
pi_theta(x)temporary surrogate target used for the next transition
A tiny worked example
Suppose the running summary currently points strongly toward the first coordinate because recent samples stayed in one mode.
At a new state, the score also points strongly in that first coordinate.
The inner product between history and current score is large, so the exponential penalty is strong and the surrogate target value is reduced at that state.
At another state near a different mode, the score points in a different direction.
Now the alignment with the history summary is small, so the penalty is weak and the chain can move there more easily.
After the move, the history summary is updated by averaging in the new score, which gradually shifts repulsion toward whatever region has become overvisited next.

The method reduces repeated visits when alignment with old score information triggers a local penalty, while the online average keeps the penalty adaptive instead of fixed.

What can go wrong

What can go wrong

Score evaluations may be inaccurate. The method relies on the score at each state. If the score is noisy or biased, the running summary stores the wrong exploration signal, which means the chain may repel itself away from useful regions instead of redundant ones.
Repellence strength can be too large. If alpha is set too high, the surrogate target can over-penalize the current dominant direction. That can hurt mixing because the chain may bounce away from a mode before learning it well enough.
One summary list may be too coarse. A single running average compresses history aggressively. If the target has several very different local structures, one list of numbers may merge them into a summary that is not specific enough to guide repulsion cleanly.
Done right. The wrapper works best when the base kernel is already stable, score evaluations are reliable, and the history step size decays slowly enough to remember persistent overexploration without freezing the summary forever.
What a runnable demo should prove

What a runnable demo should prove

Build a two-mode target in two dimensions and compare two samplers: a base Metropolis-adjusted Langevin chain and the same chain wrapped with the score-repellent update. Track mode occupancy over time, estimated mean error across repeated runs, and memory use. The wrapped sampler should visit both modes more evenly because the score summary penalizes continuing to reinforce the currently overvisited direction.

mode_balance = min(visits_mode_1, visits_mode_2) / max(visits_mode_1, visits_mode_2); estimate_error = absolute(estimated_mean - true_mean)

The demo should make clear that the extra history state is tiny, but it still changes the path enough to reduce estimator variance because the chain stops spending so many iterations retracing the same local score directions.
