RoboOmni: Proactive Robot from Omni-modal Signals

A robot learns to guess what you want before you ask, by listening to sound and looking at the scene at the same time.

Paper explainersAll themesRobotics & Control

Most robots wait for you to say exactly what to do. RoboOmni instead figures out your intention from a mix of clues: your speech, background sounds, and what is happening in the room. It fuses all these signals into one shared digital language, then reasons about what you probably want, and finally acts.

Zero assumption version

Robots today are reactive, not proactive

Current robots need explicit instructions: you say pick up the cup, they pick up the cup. But human collaboration is not like that. In real life, you leave hints: The room is too bright (close the blinds). Your friend mutters while frustrated (take a break). A door slams (check if someone is upset). Humans infer intent from context.

A naive approach: transcribe all the speech using an automatic speech-to-text tool, then give that text to a language model, which outputs a text command to the robot. This breaks because: the speech is slurred by background noise, the text model loses the tone and timing of the voice, and the model ignores what the robot sees (which might contradict the speech).

In one sentence. Fuse audio, visual, and language signals into a shared digital language (turning each into small units the model understands), then use that to jointly reason about intent, confirm with speech, and execute actions—all in a single end-to-end model.

The algorithm as a flow

What it actually does

Perceiver

Convert video frames and audio chunks into numeric summaries (embeddings) using specialized encoders.

Unified signal space

Translate all signals (vision, sound, text, action) into one shared digital language. This works because a single brain can find hidden patterns when it sees speech, sound, and vision all on the same level, like seeing three separate clues suddenly click.

Thinker

A large language model processes the fused signals, reasoning about what the user probably wants given all the context.

Talker

Generate clarifying speech to confirm the inferred intent (did I understand you right?).

Executor

Convert the model's predicted actions back into robot commands: gripper, arm joint angles, movement.

What the paper changes

What changes: from separate inputs to unified signals

The paper's core move is unification: instead of treating audio, video, and text as three separate pipelines, RoboOmni converts them all into small units of meaning and processes them in a single shared space. This is like translating English, French, and Spanish into one intermediate language so one brain can understand all three at once.

The hidden quantity

The named hidden quantity: cross-modal intent

measured quantity  =  Hidden user intention

The paper measures an invisible thing: what the user actually wants, hidden inside the speech, ambient sounds, and visual scene. This is not explicitly stated; the robot must infer it.

The paper estimates this by training the Thinker component on 140k episodes where human annotators labeled the ground-truth intent for each multimodal context. When the model runs on new data, it learns to predict actions conditioned on the fused audio-visual signals, a proxy for intent reasoning.

Why it works

Why unified signals enable proactive reasoning

When all modalities are melted into one digital language, the model can align patterns across them. If your speech sounds frustrated (voice pitch tokens) and the room is chaotic (sound event tokens and visual clutter tokens), the model can learn that this combination usually means you want things organized. The timing of audio and visual events matters too—your speech lag relative to an object appearing is important because the timing tells you whether the user is reacting to what they see or planning ahead.

The same model generates both speech for confirmation and action tokens for execution. This closes the loop: if the model's predicted intent seems unclear, it can ask a clarifying question (Talker), and based on the human's response, refine the action (Executor). A unified model avoids the problem of separate dialogue and control systems disagreeing about what to do.

Math after the picture

The unified one-at-a-time prediction loss

First in words:

Sum of prediction errors for conversation and action, where both are treated as predicting the next small unit in a stream.

Then the compact form:

L(theta) = L_chat(theta) + L_act(theta) = -E[sum_k log p_theta(z_k | X_t, z_<k)]

Every symbol:

L(theta)total training loss; theta is the model weights
L_chat(theta)prediction error on conversation tokens (speech)
L_act(theta)prediction error on action tokens (robot commands)
p_theta(z_k | X_t, z_<k)the model's predicted probability of token z_k given all prior tokens and multimodal input X_t
X_tthe fused audio and visual tokens at time t
z_<kall tokens predicted before token k (the previous context)
E[·]expected value over all training episodes
A tiny worked example
Suppose the model must predict the next 4 tokens: [pick, up, cup, slow].
Given context (fused audio-visual) X_t and prior tokens z_<k, the model outputs probabilities: P(pick)=0.8, P(up|pick)=0.7, P(cup|pick,up)=0.6, P(slow|pick,up,cup)=0.5.
Loss for each: -log(0.8)=0.22, -log(0.7)=0.36, -log(0.6)=0.51, -log(0.5)=0.69.
Total loss = 0.22+0.36+0.51+0.69 = 1.78. Training nudges weights to raise these probabilities.
If speech context is clear (high audio token confidence), the model learns to rely on speech. If speech is ambiguous, it learns to rely on visual cues. Both paths are supervised by the same loss.

Both conversation and robot action reduce to the same prediction game: given context tokens, guess the next token. This shared loss lets the model learn when to speak and when to act without two separate systems fighting each other.

What can go wrong

What can go wrong

Contradictory signals. If speech says left and the visual scene shows something far to the right, the model may hallucinate an action that satisfies neither. The Talker should catch this and ask the user to clarify, but that depends on training quality.
Overfitting to training context. If the 140k training episodes are biased (e.g., mostly American speakers, office lighting), the model will infer intent poorly in new contexts (e.g., noisy restaurant, non-native speakers).
Latency from large models. The Thinker is a large language model. In a dynamic scene where the user's intent changes every second, inference must stay under ~100ms. If it stalls, the robot falls out of sync.
Done right. Train on diverse speakers, sounds, and lighting. Validate on data from new types of environments and speakers. Use smaller language models or distillation to meet speed budgets. Include failure cases in training (e.g., impossible requests). This teaches the model to recognize when its confidence is low, so it asks a question rather than executing an action that would fail. The model learns this because it is penalized for wrong guesses during training.
What a runnable demo should prove

What a runnable demo should prove

Build a small simulation: a 3D scene with a few objects, a microphone input device, and a video feed. Play recordings of humans speaking and acting in the scene, with varying noise levels (silence, office chatter, mechanical beeps). Train the model on 100-500 annotated episodes. Then test: without any explicit command, can the robot infer and execute the action faster and more accurately than a speech-only baseline? Speed improves because there is no separate transcription step; accuracy improves because visual cues fill in what speech cannot.

Success rate = (correct_actions / total_attempts). Inference latency = time from audio-start to first command token. Noise robustness = success_rate(noisy_speech) / success_rate(clean_speech).

The demo must show that the robot acts correctly even when speech is garbled. This proves the core point: when you feed the model both audio and visual signals at the same time, it can guess what the user wants even if one signal is broken, because the other signal carries the information.
