TokMem: Tokenized Procedural Memory for Large Language Models

TokMem stores reusable procedures in compact learned memory slots so a language model can invoke them without rereading a long prompt at every step.

Paper explainersAll themesOther

Large language models often rely on long prompts to describe a task, a workflow, or a tool-usage procedure. That is wasteful because the model must reread the same instructions again and again as generation continues. This paper proposes TokMem, a procedural memory system that stores reusable procedures as compact learned memory slots. The base model stays frozen, new procedures can be added later, and the memory slot both points to the right procedure and steers generation toward using it.

Zero assumption version

Prompting repeats the same instructions over and over

A language model can follow a procedure such as 'call this tool, parse the result, then answer in this format' if that procedure is written into the prompt. The problem is that the procedure must sit in the context window while the model works through the task.

That repeated context is expensive and hard to scale. As more tasks and procedures accumulate, prompts become longer, slower, and harder to reuse. Standard fine-tuning has a different problem: it changes the model weights directly, which makes incremental updates harder and risks interfering with older capabilities.

The bottleneck. Reusable procedures live either in long prompts or in model weights. The paper wants a middle layer that is compact, modular, and addable over time.

What the paper changes

What the paper changes

The paper adds an explicit procedural-memory layer to a frozen language model. Procedures are no longer stored only as prompt text or only inside updated model weights.

The hidden quantity

The hidden quantity: procedure reuse density

measured quantity  =  how much reusable instruction can be packed into a compact memory slot

The important hidden quantity is procedure reuse density: how much task guidance can be stored in a small learned slot instead of a long prompt. If this density is high, the slot carries enough information to trigger a useful workflow even though it is tiny compared with the original prompt.

The paper estimates this quantity indirectly by measuring task success under fixed-size memory slots. If a short slot consistently replaces a much longer prompt while keeping or improving performance, then the slot is storing reusable procedural guidance rather than acting as a weak hint.

Why it works

Why compact procedural memory can beat repeated prompting

A long prompt works because it repeatedly reminds the model of what procedure to follow. But that repetition burns context and compute at every generation step. TokMem moves the reusable part into a compact learned slot, so the procedure is injected once in a form the model can directly use.

The backbone model remains frozen, which matters for continual updates. New procedures can be added by training new slots instead of editing the entire model. That avoids interference with older procedures because the base model weights stay fixed while the new procedural control lives in its own small memory object.

The slot plays two roles at once. It identifies the relevant procedure and also pushes generation toward following that procedure. This dual role is why the method can outperform retrieval-augmented prompting on procedural tasks, because the model does not just read retrieved text; it receives a learned control signal tailored to execution.

The memory-selection equation

First in words:

Pick the procedure slot whose learned score is largest for the current task, then use that slot to steer generation.

Then the compact form:

s_hat = argmax_s score(task, s)

Every symbol:

s_hatselected procedure slot
sone candidate procedure slot
taskthe current task description or state
score(task, s)how well slot s matches the procedure needed for the task
A tiny worked example
Suppose the model has three procedure slots: tool use, factual recall, and multi-step function calling.
For a new task, the matching scores are 0.20, 0.15, and 0.77.
The system picks the multi-step function-calling slot because 0.77 is the largest score.
That slot is inserted once and guides the model through the needed procedure.
The long instruction prompt is no longer needed at every step because the compact slot carries the reusable control.

The exact internal representation can be more detailed, but the conceptual rule is simple: select the procedure slot that best matches the current task.

What can go wrong

What can go wrong

Wrong slot selection. If the system picks the wrong procedure slot, the model may confidently follow an irrelevant workflow because the control signal points in the wrong direction.
Procedure slots too small. If a slot is too compact for the workflow it is meant to store, it may carry only partial guidance, so task quality can drop.
Tasks outside stored procedures. The method helps most when the task matches a recurring workflow because the stored slot already contains the needed procedural guidance. A truly new procedure still needs either a new slot or ordinary prompting.
Done right. With good slot selection and enough capacity per slot, TokMem improves reuse because it stores recurring procedures in a modular layer that can be added without rewriting the base model.
