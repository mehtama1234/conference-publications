GaussianFusion: Unified 3D Gaussian Representation for Multi-Modal Fusion Perception

Instead of chopping 3D space into a grid, represent it as smooth clouds of Gaussians so multi-sensor data fuses without losing fine detail.

Paper explainersAll themesRobotics & Control

Self-driving cars see through multiple cameras and sensors at once. Today's systems convert all that data into a flat grid called bird's-eye view, like a top-down checkerboard. This grid approach works but crushes detail because grid cells are large blocks that blur fine features, and it makes sensor data hard to coordinate because features just get mechanically concatenated with no learned interaction. This paper throws out the grid and builds a unified space from 3D Gaussians—smooth bell curves instead of boxes—so multi-sensor features flow together cleanly, keep their fine edges, and solve multiple perception tasks from a single learned representation.

Zero assumption version

Why grids crush detail

A self-driving car has a camera, radar, and lidar (each sends a different signal). To combine them, today's systems project all the sensor data onto a flat grid from above—a top-down checkerboard of square cells. Each cell holds aggregated features from all sensors.

The grid has two fatal flaws: First, the grid cells are big blocks. When you divide 3D space into a discrete grid, you lose fine detail like thin pole edges and delicate boundaries between objects. Second, when features from different sensors land in the same grid cell, they get mashed together by averaging or concatenation. There's no natural way for a camera detail and a radar measurement to genuinely interact—they just sit side by side.

The method in one sentence. Replace the discrete grid with a continuous field of 3D Gaussians (smooth bell curves in 3D space) so features fuse fluidly, preserve edges, and naturally interact across sensors.

What the paper changes

What the paper moves

The object is the representation of 3D space itself. Instead of a grid, the paper uses 3D Gaussians—each is a smooth bell curve with a center location, a spread (covariance), and feature weights. When sensor data arrives, the Gaussians' properties shift to absorb and blend the signal.

the object it moves  =  Representation grid to 3D Gaussians
The hidden quantity

The hidden quantity: cross-modal relevance per Gaussian

measured quantity  =  Per-Gaussian modality attention weights

The paper measures something invisible: for each Gaussian, which sensors are relevant? This is the cross-modal relevance—a learned score that says whether a camera reading or a radar reading should influence that particular Gaussian. In attention-based fusion, the model learns a separate attention weight for each (Gaussian, modality) pair, allowing some Gaussians to listen mostly to camera and others mostly to radar.

The encoder computes these weights via a cross-attention mechanism: camera features query Gaussian features; the dot product reveals affinity. Radar does the same. The weights automatically drive which sensor features get blended into each Gaussian's representation.

Why it works

Why continuous Gaussians beat discrete grids

A grid quantizes space—each cell either holds a feature or it does not. When a camera edge falls between two grid cells, the detail splits and blurs. Gaussians are continuous; they smoothly overlap and preserve edges. When a camera detail sits at the boundary, it activates multiple nearby Gaussians according to the Gaussian's smooth shape, so the edge remains sharp.

The second gain is cross-modal fusion. In a grid, features from camera and radar in the same cell are concatenated or averaged—a passive, mechanical blend with no way for one sensor to emphasize what matters. In GaussianFusion, each Gaussian learns an attention weight for each sensor. If camera-to-Gaussian attention is high and radar-to-Gaussian attention is low, the Gaussian becomes camera-dominant. This learned weighting allows semantic fusion because the model can suppress unreliable signals and amplify trustworthy ones: a Gaussian at a thin pole learns that camera edges are crisp and radar is scattered noise at that location, so it sets camera weight high and radar low, making the final feature reflect just the camera signal.

The third gain is task reuse. A single Gaussian field can be decoded into object bounding boxes, semantic occupancy grids, or tracking states—all from the same continuous foundation. A grid must be re-projected and re-processed for each task; Gaussians generalize.

How the Gaussian encoder fuses one modality

First in words:

For each Gaussian, blend multi-modal features by applying attention softmax over modality-specific queries and keys. The updated feature for Gaussian g is the sum over all modalities m of: (softmax of attention score for m at g) times the value vector from m at g.

Then the compact form:

feat_g_new = sum_m ( softmax( Q_m(g) · K_m(g) / sqrt(d) ) · V_m(g) )

Every symbol:

feat_g_newupdated feature vector for Gaussian g
mmodality index (camera, radar, lidar)
Q_m(g)query vector from modality m at Gaussian g
K_m(g)key vector from modality m at Gaussian g
dfeature dimension (e.g., 64 or 128)
V_m(g)value vector from modality m at Gaussian g
softmax(...)convert raw scores to weights summing to 1
A tiny worked example
Gaussian at position (x=10, y=5): receives camera query Q_cam = [0.8, 0.6], radar key K_rad = [0.7, 0.9]
Dot product: Q_cam · K_rad = 0.8*0.7 + 0.6*0.9 = 0.56 + 0.54 = 1.10. Divide by sqrt(64)=8: 1.10/8 = 0.1375
Also compute camera-to-camera attention (within modality): 1.40 / 8 = 0.175, radar-to-radar: 1.30 / 8 = 0.1625
Three attention scores: [0.1375 (cross), 0.175 (self-cam), 0.1625 (self-rad)] → softmax → [0.33, 0.34, 0.33]
Camera value V_cam = [10, 5], radar value V_rad = [8, 4]. New feature = 0.33*[10,5] + 0.34*[8,4] + 0.33*[8,4] = [3.3, 1.65] + [2.72, 1.36] + [2.64, 1.32] = [8.66, 4.33]

When one modality has high attention weight, it dominates the Gaussian's updated feature, encoding the learned cross-modal relevance.

What can go wrong

What can go wrong

Too many Gaussians means wasted compute. If you initialize a Gaussian for every pixel or point, computation explodes. The paper uses careful initialization (forward projection plus clustering) to avoid this, but a naive initialization would be prohibitive.
Attention collapse. If the model learns that one modality dominates all Gaussians (e.g., camera always has weight 0.9, radar always 0.1), the method reduces to single-sensor processing and loses fusion benefit. The paper does not report this failure, suggesting that careful initialization and training constraints prevent it.
Loss of sparse structure. Lidar and radar are naturally sparse (point clouds). Representing them as dense Gaussians may smooth away the pointiness that helps downstream processing because Gaussians blur sharp transitions. However, the paper shows this still outperforms baselines, meaning that the benefit of learned cross-modal fusion and continuous edge preservation outweighs the cost of lost sparsity structure.
Done right: multi-task generality. When attention is tuned per Gaussian and Gaussians are initialized from true multi-modal projections, one field genuinely serves detection, occupancy, and tracking, without re-engineering per task.
What a runnable demo should prove

What a runnable demo should prove

Build a minimal multi-modal fusion system on a toy 3D scene: one camera image (top-down view of colored objects), one range sensor (sparse depth readings). Initialize Gaussians by projecting both modalities. Train a simple attention encoder (2–3 layers of cross-attention). Then decode into two tasks: (1) object bounding-box detection, (2) occupancy grid estimation. Show that the single Gaussian field serves both, and that learned attention weights differ per Gaussian (proof that fusion is active, not collapsed).

Detection accuracy = (true positives) / (ground truth boxes); Occupancy IoU = (predicted occupied ∩ true occupied) / (predicted occupied ∪ true occupied); Modality ablation: accuracy when camera-only vs. radar-only vs. fused (fused should beat single-modality).

The demo must show that attention weights are learned and vary across Gaussians (not uniform), proving that the model is actively choosing which sensors to trust for each region of the scene.
