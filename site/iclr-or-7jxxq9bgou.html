GaussianFusion: Unified 3D Gaussian Representation for Multi-Modal Fusion Perception

Instead of chopping 3D sensor data into a rigid grid and losing detail, represent it as overlapping soft Gaussian bumps that flow together smoothly.

Paper explainersAll themesRobotics & Control

Autonomous vehicles see the world through both cameras (color images) and LiDAR (bouncing lasers that measure distance). To make decisions, we need a unified picture. Today, most systems smash both sensor streams onto a flat 2D grid map (called bird's-eye view), which throws away fine details and makes it hard for camera data and laser data to talk to each other—because the grid is 2D (a flat top-down map) while the real world is 3D, a camera feature and a LiDAR feature that describe the same object have no natural common address in the grid, so the fusion network cannot easily learn that they should reinforce each other. This paper breaks that rigid grid and instead represents the scene as a smooth continuum of overlapping Gaussian bumps in 3D space—the same math that lets statisticians describe bell curves. Because the bumps are continuous, not discrete boxes, and the space is 3D, camera and LiDAR information can inhabit the same 3D coordinate space and naturally reinforce each other through shared Gaussian representations, and every 3D perception task benefits because fine detail is preserved.

Zero assumption version

The rigidity of grid-based sensor fusion

Today's multi-sensor 3D perception methods merge camera and LiDAR data by first converting both into a bird's-eye-view grid: a 2D array of boxes laid out like a checkerboard, each box labeled with a feature (a list of numbers). This discretization (chopping continuous space into boxes) is fast and simple, but it is destructive. Fine details—a thin pole, the edge of a curb, a delicate hand gesture—get snapped to the nearest grid cell and lose their true position. Textures blur. Neighboring grid cells sit in isolation; there is no natural way for a camera feature and a LiDAR feature to smoothly align.

A beginner might reason: if discrete grids are stiff and lossy, why not just concatenate all camera and LiDAR features into one big list and let a neural network learn how to blend them? This breaks because there is no underlying 3D scaffold: the network must invent alignment from scratch at every layer, and without a continuous 3D space to work in, features from cameras (which see fine color detail) and LiDAR (which sees range with certainty) cannot naturally reinforce each other. They sit in different coordinate frames with no shared reference.

In one sentence. Instead of a rigid checkerboard, represent the fused 3D scene as a smooth collection of overlapping Gaussian bumps that camera and LiDAR data can inhabit continuously.

The algorithm as a flow

What it actually does

Initialize camera Gaussians from projected features

Take camera image features and project them into 3D space as Gaussian centers.

Initialize LiDAR Gaussians from range data

Take LiDAR depth measurements and place Gaussian bumps at those 3D locations.

Encode both sets together in shared space

Feed both camera and LiDAR Gaussians into a shared focus layer (attention, which is a method that scores which parts matter most) that learns which Gaussians matter and adjusts their properties.

Fuse via Gaussian mixture

Overlap and blend the refined Gaussians using standard probability math.

Output dense 3D features

Convert the fused Gaussian field back into voxels (small 3D boxes) for any downstream task.

What the paper changes

What the paper changes

Instead of representing the fused 3D scene as a discrete 2D grid with boxes (the bird's-eye view), GaussianFusion represents it as a continuous field of 3D Gaussian distributions—smooth, overlapping bell curves in 3D space. Each Gaussian has a center position, a spread (covariance, which is a table of numbers describing how spread-out the bump is), and a feature vector (a list of learned numbers) attached. Both camera and LiDAR Gaussians share the same geometric space, so their features naturally interact.

The hidden quantity

The hidden quantity: cross-modal alignment quality

measured quantity  =  Degree of shared geometric coherence

The paper tracks an unnamed but critical quantity: how well camera and LiDAR features sit in the same geometric frame and reinforce each other. In discrete grid methods, camera and LiDAR data land in separate grid cells with no natural overlap. In Gaussian representation, the degree to which Gaussians from both modalities overlap and share covariance (spread) is the measure of alignment quality. A covariance matrix (a table of numbers describing how spread-out the Gaussian is) adapts to capture the differences between modalities—if LiDAR is certain in depth but camera is vague, the covariance adjusts to reflect that asymmetry.

The paper does not explicitly compute this quantity as a single number, but the shared Gaussian encoder iteratively updates each Gaussian's covariance based on cross-modal attention. Gaussians with high attention weights from both modalities converge to shared covariance values (their spread becomes the same), which is the mechanism by which alignment improves: because both sensors reward the same Gaussian spread, the learning signal pulls them toward agreement, and once they agree on how spread-out a bump should be, the bump naturally represents both sensors' views simultaneously.

Why it works

Why it works: continuous bumps beat rigid grid boxes

The core insight: discrete grids force quantization (snapping data to nearest cell), which locks in information loss before any learning happens. Continuous Gaussian representation defers quantization to the very end, preserving fine detail throughout processing.

Here is the chain. (1) Camera images and LiDAR depth are first encoded into features (lists of numbers). (2) Camera features are projected into 3D space using the camera's position and angle; each projected feature becomes the center of a Gaussian bump. LiDAR depths directly place Gaussians in 3D. Both modalities now inhabit the same 3D space as overlapping, continuous probability distributions. (3) A shared neural-network layer (deformable attention with Gaussians) then scans both sets and adjusts each Gaussian's properties—where is its center, how spread out is it, what are its feature values—based on what it learns is important. The covariance matrix (the table describing how spread-out each Gaussian is) is updated by attention weights (numbers between 0 and 1 that score which parts matter) that look at both modalities together. This is why alignment improves: camera features and LiDAR features are pushed toward shared covariance values by the same learning signal, because the shared attention weights reward Gaussians that work for both sensors. (4) Once refined, Gaussians are blended using Gaussian mixture mathematics, which is smooth (slopes exist everywhere, no sharp corners) and preserves the continuous structure. (5) Finally, the fused Gaussian field is converted to voxels (a 3D grid) only for output, so quantization-induced loss is minimal—most of the processing happened in the smooth, continuous domain.

The Gaussian initialization and update equation

First in words:

Gaussian bump centered at mean, with spread described by covariance matrix, updated via attention weights from both sensor streams

Then the compact form:

g(p; mu, Sigma, q) = exp( -0.5 * (p - mu)^T * Sigma_inv * (p - mu) ); Q_updated = Q + sum_k A_k * W_k * B(mu + delta_mu)

Every symbol:

Sigmacovariance matrix, describes how spread-out the bump is in each direction
Sigma_invinverse of covariance; larger values make the exponent bigger, shrinking the bump

A tiny worked example
Suppose a camera Gaussian has center at (x=2, y=3, z=1) meter and a LiDAR Gaussian has center at (x=2.1, y=3.2, z=1.05) meter. Without fusion, they sit as separate bumps.
Shared encoder receives attention weights: camera A_c=0.6, LiDAR A_L=0.7. Both are significant.
The encoder computes a blended center: mu_fused = (0.6*2 + 0.7*2.1) / (0.6+0.7) ≈ 2.055 meter in x, and similarly for y,z. The bumps shift toward agreement.
Covariance from camera (wide, uncertain) and LiDAR (narrow, precise) are blended: Sigma_fused reflects both the camera's vagueness and LiDAR's sharpness. The result is a Gaussian that inherits LiDAR's precision in depth and camera's color-texture richness in the horizontal plane.
Final fused Gaussian sits at (2.055, 3.1, 1.025) with a covariance matrix that is narrow in depth (LiDAR's strength) and wider horizontally (camera's inherent limit). This is better than either alone.

The deformable attention in Equation 4 iteratively nudges Gaussian centers (mu) and blends covariances, so that camera and LiDAR Gaussians converge to shared geometric coherence in the continuous 3D space before any quantization to voxels.

What can go wrong

What can go wrong

Initialization of camera Gaussians is critical. If the forward projection of camera features into 3D space is inaccurate (wrong depth assumption), the camera Gaussians start in the wrong places and attention cannot fully recover. The paper fixes this with a learned projection module, but poor camera calibration can still hurt.
Gaussian mixture blending assumes covariance agreement. The fusion step (blending two Gaussians with different covariances) works well when both modalities provide useful signals. If one sensor is absent or heavily occluded, the covariance may collapse in misleading ways because the encoder has no signal to stabilize it, and the fused Gaussian can misrepresent how uncertain the prediction is.
Attention weights can become unbalanced. If attention learning favors one modality (e.g., LiDAR always gets attention weight 0.9, camera gets 0.1), then camera features are ignored by the shared encoder, and the alignment quality never improves because the encoder sees little reason to refine camera Gaussians. The method reduces to LiDAR-only fusion and throws away the camera's color detail.
Done right. When camera and LiDAR are both present, have reasonable coverage, and the encoder trains on a balanced task mix (detection and occupancy together), the shared attention naturally learns to blend covariances, and the continuous Gaussian field preserves detail that grids would lose.
What a runnable demo should prove

What a runnable demo should prove

Build a small dataset of a single scene with camera image and LiDAR point cloud (e.g., a room with a desk, chair, and door). Run two parallel models: one using a discrete grid-based fusion baseline (projecting both into a 2D BEV grid, then fusing via concatenation), and one using Gaussian representation (projecting both into 3D Gaussians, running shared attention, then converting to voxels for output). Both output 3D occupancy (which parts of the scene are occupied) and must be rendered back to the camera view to visualize. The demo must make it impossible to miss that the Gaussian method preserves fine edges (the edge of the door frame, the thin legs of the chair, the corner of the desk) while the grid baseline blurs them into rounded blocks. The metric is edge preservation: count the number of voxel boundaries that show sharp color change (the steepness of the color shift from one pixel to the next) in ground-truth depth, and measure how many the model recovers. Gaussian fusion should recover 85%+ of sharp edges; grid fusion should recover less than 60%.

edge_preservation_percent = (sharp_edges_recovered / sharp_edges_in_ground_truth) * 100

The demo must show a side-by-side rendered view of ground truth, grid fusion, and Gaussian fusion, where the Gaussian output has visibly crisper object boundaries and finer surface detail.
