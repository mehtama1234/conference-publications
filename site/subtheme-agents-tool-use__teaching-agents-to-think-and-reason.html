Teaching Agents to Think and Reason

Papers about making agents reason better when using tools — checking their work, thinking before acting, or breaking down problems into smaller pieces.

All themesField mapMathematicsAll explainers
What this is

This cluster focuses on making agents smarter about their decisions before they act. Instead of just immediately calling a tool, they think. They might break a problem into smaller pieces, figure out which pieces matter, reason about dependencies (if I want to answer this, I first need to know that), or double-check their work. Think of it like how a human would solve a hard problem by writing it out, annotating what they know and don't know, and working step by step. The papers here are about teaching agents to do something like that reasoning in code.

The difficulty is that reasoning takes time and thought, but it's not obvious how to make an AI reason in a way that actually helps, because you can break good reasoning by making an agent overthink every tiny choice. Some agents might overthink a simple problem when they should just act. Others might reason in circles, going in loops without making progress, wasting time and compute. Some might reason well on one type of problem but fail to transfer that reasoning to a new situation, so the reasoning isn't generalizable. And there is a fundamental trade-off: more reasoning time means slower answers, which isn't always acceptable in real-time scenarios like driving or helping a user who is waiting. You need the agent to reason *just enough* to avoid mistakes without grinding to a halt.

Papers approach this by teaching agents to recognize when they need to think harder versus when they can act immediately. Some train agents to verify their own answers — after calling a tool, the agent checks whether the result makes sense, which catches mistakes before they propagate. Others teach agents to plan by decomposing a goal into substeps, then execute each step, so the agent doesn't have to keep the whole problem in mind at once. Some focus on teaching agents to recognize their own uncertainty and ask for help or double-check when they're unsure, because acting confidently on a wrong idea is worse than pausing to verify. The underlying goal is to get agents that don't just react, but take a moment to consider what they are doing and why.

How the work breaks down

The work splits into four natural directions. First, agents learn to verify their answers by double-checking work before acting. Second, they learn to plan by breaking big problems into smaller steps. Third, they reason formally—proving theorems or finding bugs in protocols. Fourth, they apply reasoning to real tasks like web navigation, driving, or writing code.

Verification and error checking

The core problem is that agents often make mistakes that could be caught early—misinformation that spreads, diagnoses that miss details, or reasoning steps that contradict known facts. When an agent just pushes forward without checking, bad decisions pile up into larger failures. These papers teach agents to pause and verify their work, catching mistakes before they propagate.

ExVerus fixes formal proofs by understanding why they fail. When an agent writes a proof and it breaks, most systems just fail. ExVerus instead teaches the agent to analyze counterexamples—it sees what case made the proof fail and reasons about how to fix it, making proofs much more accurate and efficient. FactGuard tackles misinformation in videos by training an agent to gather evidence about claims (checking sources, looking for contradictions) and verify them against known facts before accepting a claim. This systematic verification catches false information that a naive reasoning pass would miss. GLEAN helps agents diagnose diseases by grounding each reasoning step in clinical guidelines—when the agent considers a symptom, it checks whether guidelines support that reasoning, catching diagnostic errors early. VoG improves general reasoning by having agents verify each step against a knowledge graph—if a reasoning conclusion doesn't match what is known, the agent stops and revises instead of building on a shaky foundation. In Decoding Revision teaches agents to verify generated code by revising it while generating, catching security vulnerabilities before code runs by checking each piece as it writes. Cycle-of-Science uses counterfactual reasoning to verify decisions: the agent proposes a hypothesis, tests it against other possibilities, and picks the one that survives scrutiny, which catches reasoning errors that single-path verification misses.

Planning and decomposition

The core problem is that long chains of decisions overwhelm agents. An agent that tries to think about every detail at once gets lost, forgets what it decided earlier, or cannot handle sequences longer than a few steps. These papers teach agents to plan by decomposing goals into smaller pieces, so the agent never has to hold the entire problem in mind at once.

Grounding Generative Planners in Verifiable Logic combines language-based planning with formal verification so agents can plan safely. It teaches planners to decompose home safety tasks into steps (like opening a door, moving an object) that can be formally verified as safe, catching hazardous actions before they happen. IterResearch extends how far agents can look ahead—instead of losing track after ten steps, it teaches agents to reconstruct what they know at each point in a sequence, so they stay oriented even across 2048 interactions. This matters because real tasks require long planning horizons, and without good state reconstruction, agents get confused. Web-CogReasoner teaches agents to navigate websites by first gathering knowledge (learning how the site is organized, where things are) and then using that knowledge to plan each action. This two-stage approach—gather context, then execute—beats agents that try to reason on the fly, because planning with good information is faster than reasoning from scratch each time. AdaReasoner trains agents to choose which tool to use at each step of a visual reasoning problem by adaptively learning from what it has seen so far, so the agent plans differently based on what has worked. Empowering Efficiency and Efficacy in WebAgent teaches web agents to seek informative intermediate steps, cutting waste by planning which actions matter instead of trying everything.

Formal reasoning and theorem proving

The core problem is that high-stakes reasoning—proving theorems, finding security bugs, catching protocol violations—requires precision that informal reasoning often lacks. A single wrong step in a proof breaks the entire argument. These papers teach agents to reason formally, building step-by-step justifications that can be checked rigorously.

Agora teaches agents to find security bugs in blockchain protocols by understanding what each protocol step guarantees and checking whether safety properties (like 'a message sent by Alice cannot be faked by Bob') actually hold. Most LLM agents miss these subtle bugs because the bugs are logical violations, not typos—they require careful reasoning about dependencies. Hilbert combines informal and formal reasoning: the agent thinks informally about why a theorem should be true, then fills in formal gaps by writing proofs in a formal language, which lets it tackle hard undergraduate-level math problems and contest mathematics. PaperBanana applies reasoning to academic illustration—when generating diagrams for papers, it must reason about whether the illustration is faithful to the paper's content, readable, and clear, because visualizations must convey precise ideas. Pessimistic Verification checks whether an answer holds under the hardest possible interpretation—instead of just checking one path, it asks 'what if the worst reading of my answer is the right one?', catching edge cases that other verification methods miss on contest-level math where precision is everything. Beyond Theorem Proving shows that problem-solving is harder than theorem proving: it reveals that formal reasoning requires agents not just to verify existing proofs but to construct solutions from scratch, which is a deeper reasoning task. Together, these papers show that formal reasoning is not impossible for LLMs; it just requires breaking the problem down and checking each step rigorously.

Real-world execution with thinking

The core problem is applying reasoning to real tasks without grinding to a halt. Agents that overthink waste time and resources; agents that move fast without thinking make cascading errors. The solution is selective reasoning: think carefully where mistakes are costly, move fast elsewhere.

Co-RedTeam orchestrates reasoning across multiple agents to discover security vulnerabilities: it breaks down the security discovery problem into separate stages (reconnaissance, exploitation, verification), teaching agents to reason about which techniques work together rather than throwing everything at once. DriveAgent-R1 advances autonomous driving by adding thinking to vision-language models: instead of just processing what it sees, the agent reasons about how to respond, balancing thinking time against real-time pressure because driving requires both careful perception and immediate response. Both papers illustrate why selective reasoning matters: reasoning catches errors before they cascade, but users waiting for a driving decision or security check cannot tolerate delays, so agents must learn when to think deeply and when to act immediately.
