HiPRAG: Search-Aware Reward Training for Agentic RAG

Train search agents to know when to search by grading each search decision independently, not just the final answer.

Paper explainersAll themesAgents & Tool Use

Language models lack information, so agents search for it. But they often search too much (already know it) or too little (should have looked). Training them to get the right answer at the end misses the real problem: each individual search decision—to look something up or skip it—should be judged on its own merits.

Zero assumption version

Search agents waste time and miss information

An agent answers questions by searching for facts, then thinking through them. But it learns only from whether the final answer is right or wrong. It has no signal about whether individual searches were necessary. So it either searches for everything (even facts it already knew) or searches for nothing (ignoring useful information it should have found).

A naive approach: train on outcome alone. Reward the agent if the final answer matches the truth, punish it if wrong. This teaches the right endpoint, but not the right decisions along the way. The agent learns to avoid the pain of a wrong answer, but it has no feedback saying 'that search was pointless' or 'you should have searched there'.

The problem in one sentence. The agent is graded only on the final answer, so it has no incentive to search smartly—it cannot tell if a search was necessary or wasteful.

The algorithm as a flow

What it actually does

Decompose the trajectory

Break the agent's reasoning chain into discrete steps: decide to search, execute search, read result, update belief, decide next move.

Judge search necessity

For each search step, assess: does this search provide information the agent did not have? Would the final answer be the same without it?

Assign per-step grades

Mark each search as necessary (reward) or wasteful (penalize). Mark skipped searches as correct (did not search when not needed) or wrong (should have searched).

Calculate hierarchical reward

Add to the normal final-answer reward a bonus based on the fraction of search steps that were graded correctly (necessary searches that happened, unnecessary searches that did not).

Train the agent

Use the boosted reward signal to teach the agent which search patterns lead to better decisions and fewer wasted lookups, because now the agent receives explicit feedback on whether each search was worth the cost.

What the paper changes

What the paper changes

The paper changes how the agent is graded during training. Instead of only looking at the final answer, it also looks at each intermediate search decision and judges whether that search was necessary.

The hidden quantity

Search necessity: the hidden quantity

measured quantity  =  Search necessity: whether each search was actually needed

Search necessity is a hidden quantity because the agent cannot measure it directly. It is the true answer to the question: 'Would the agent have reached the same correct answer without this search?' This is invisible to training until someone explicitly checks it.

HiPRAG estimates search necessity by examining the agent's beliefs before and after each search, and cross-checking against the ground-truth answer. If a search changed the agent's belief without moving it closer to the truth, the search was unnecessary. If the agent reached the correct answer without a particular search, that search was wasteful. The paper constructs a binary label for each search: necessary (true) or unnecessary (false).

Why it works

Why it works: process rewards beat outcome-only training

Training on outcome alone tells the agent only 'right' or 'wrong' on the final answer. It creates a backward signal that teaches the agent to follow paths to correct answers, but it provides no information about the intermediate steps. Over time, the agent learns statistical patterns—searches that tend to precede correct answers—but it does not learn that some searches are pointless.

HiPRAG adds a separate reward signal for search decisions. Every time the agent decides to search, the system checks: was that search necessary? If yes, add a bonus. If no, subtract. Every time the agent decides not to search, the system checks: was that skip correct? If yes, add a bonus. If no, subtract. This creates an additional training pressure that directly penalizes wasteful searches and rewards smart skips. Over time, the agent learns to distinguish necessary searches from noise, because now it is explicitly rewarded for doing so. The final-answer reward keeps it honest about correctness; the process reward keeps it honest about efficiency.

Math after the picture

The hierarchical reward equation

First in words:

Total reward equals the outcome reward for the final answer, plus a bonus based on the fraction of search steps the agent got right.

Then the compact form:

R_total = R_outcome + alpha * R_process R_process = (correct_searches + correct_skips) / total_steps

Every symbol:

R_totalThe final training signal: how much to reward or penalize this trajectory
R_outcomeThe grade on the final answer: 1 if correct, 0 if wrong
R_processThe process reward: fraction of search decisions that were correct
correct_searchesNumber of searches that were marked necessary and executed
correct_skipsNumber of non-searches that were marked unnecessary
total_stepsTotal number of search/non-search decisions the agent made
alphaHow much to weight process reward relative to outcome reward (tunable hyperparameter)
A tiny worked example
An agent makes 10 search/skip decisions on one question.
4 searches were necessary and the agent did them: +4 correct decisions.
3 searches were unnecessary and the agent skipped them: +3 correct decisions.
3 searches were necessary but the agent missed them: +0 correct decisions.
R_process = (4 + 3) / 10 = 0.7.
If R_outcome = 1 (final answer correct) and alpha = 1.0:
R_total = 1.0 + 1.0 * 0.7 = 1.7.
Same outcome, but high process reward because the agent chose smartly.
Compare: agent reaches same right answer via lucky guesses with R_process = 0.3:
R_total = 1.0 + 1.0 * 0.3 = 1.3 — lower reward for sloppy decisions.

The agent now earns two types of credit: being right at the end, and being smart at each step in between.

What can go wrong

What can go wrong

Mislabeling search necessity. If the system incorrectly marks a necessary search as wasteful (or vice versa), it trains the agent to make the wrong decision. This requires the necessity-detection system itself to be accurate. If ground truth is noisy or incomplete, the process reward backfires.
Process reward and outcome reward conflict. Suppose the agent finds the right answer via searches the system marked unnecessary, or finds the wrong answer despite 'correct' search choices. The two rewards pull in different directions. If alpha is too high, the agent optimizes for process score instead of correctness.
Generalization to new question types. What counts as a necessary search depends on the task. A search that is wasteful for factoid questions might be critical for reasoning questions. If the agent is trained on one type, the learned efficiency patterns may not transfer.
Done right. When search necessity is labeled accurately, alpha is set to balance both rewards, and the agent is tested on question types similar to training, HiPRAG reduces waste without sacrificing accuracy.
What a runnable demo should prove

What a runnable demo should prove

Build a simple question-answering agent with a small knowledge base. Give it a set of test questions. For each question, track: (1) Did the agent reach the correct answer? (2) For each search the agent performed, was that search information actually used in the final reasoning? (3) How many unnecessary searches did it do? Train two versions: one with outcome reward only, and one with HiPRAG (outcome plus process reward). Compare the metrics.

efficiency_gain = (over_search_baseline - over_search_hiprag) / over_search_baseline; accuracy_delta = accuracy_hiprag - accuracy_baseline

The demo must make it unmissable that the agent learns to search less while staying just as accurate or better—not by luck, but because it learned which searches matter.
