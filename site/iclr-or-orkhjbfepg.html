Winter Soldier: Indirect Data Poisoning

Hide secret training signals in nonsense tokens so a model learns behaviors that never appear in text, letting you prove you own the data.

Paper explainersAll themesAlignment, Safety & Fairness

Language model training uses massive datasets from the internet. Proving you own a specific dataset requires catching the model regurgitating your words verbatim, but smart companies strip that out. Winter Soldier instead plants indirect poison: carefully tuned nonsense word-chunks that nudge the model to learn secret prompt-response pairs, even though those pairs never actually appear in the training text. Only you know the secret, so detecting it proves your dataset was used.

Zero assumption version

Tracing your data is nearly impossible

When you contribute a dataset to training, you need to prove later that a model actually used your data. The old method: feed the model a chunk of your text and check if it spits it back word-for-word. That works for finding memorized passages, but companies now remove this ability on purpose—they scrub duplicates and tune models to paraphrase instead of repeat.

So a beginner would try: 'I'll hide a unique marker phrase in my dataset, train the model, then ask it to repeat my marker.' But if the model is trained to avoid memorization, this fails. You lose proof.

The new move. Plant poisoned word-chunks that encode a secret signal, tuned so the model learns to respond with secret outputs when given secret inputs—without ever seeing those input-output pairs as real text. This works because the model's learning process is smooth: the poisoned chunks push weights in the same direction that real secret training would, so the model's mind forms the same pattern even from nonsense.

What the paper changes

What the paper changes

The paper introduces poison tokens: sequences of numbers that do not form real words but are optimized so the model weights shift toward encoding your secret, because the poisoned sequences are crafted via mathematics to cause weight changes that move in the secret's direction. Unlike hiding information in text, the poison stays invisible—just numerical jiggles at training time. During training the model adjusts weights to reduce error; when poisoned sequences are fed through, the learning algorithm calculates which weight changes would reduce error the most, and by design those optimal changes align with your secret's direction, so weights naturally drift toward encoding it.

the object it moves  =  Poison tokens
The hidden quantity

The hidden quantity: Alignment between poison and secret

measured quantity  =  Alignment to secret direction

The paper's core insight is measuring alignment: how well do the poison tokens point in the direction that teaches the secret? If you want the model to learn 'Paris -> Eiffel', you compute which weight changes would make that happen, then find gibberish tokens whose effect on the model matches that direction. The metric is a number where higher means better alignment, telling you how much the poison nudges the weights toward the secret, because the poisoned tokens' effect directly translates into weight-change direction during training. A higher alignment number means the poisoned tokens will cause more of the weight shifts needed to encode your secret, so the model learns faster and more reliably, because during training the learning algorithm nudges weights in exactly the direction the alignment measured.

The paper estimates this by iterative optimization: it samples random poison tokens, feeds them through the model, measures which direction the secret-learning loss points, and keeps adjusting the poison until they align. This is like tuning a lens—rotate it until the light focuses on the target.

Why it works

Why poisoned token sequences nudge the model toward secrets

Here is the causal chain: the model learns by taking small steps in the direction that reduces error. If you ask it 'Paris?' and it says 'Banana', the error is high, and the learning direction points toward weight changes that would make it say 'Eiffel' instead. Normally you change weights by feeding real examples. But the paper finds poison tokens whose effect—when fed to the model—also points toward the same secret-learning direction. So even though the poison is gibberish and the secret never appears as text, the poison tokens cause the same weight nudges as if the secret had been trained directly.

The method works because neural networks are smooth: small changes to inputs cause small, predictable changes to how weights should move. By optimizing in the continuous space where token representations live (not discrete tokens), the paper can find a direction where the poison tokens' effects align perfectly with the secret's direction. Then it rounds that back to real token indices. When training, the poisoned tokens push weights in the secret-learning direction, and the model gradually learns the secret behavior.

The alignment optimization

First in words:

Find poison tokens that maximize the inner product between (gradient of secret loss) and (gradient of poison loss).

Then the compact form:

max_pi < grad_secret(theta), grad_poison(pi, theta) >

Every symbol:

grad_secretgradient of loss when trying to learn the secret (what weights should move toward)
grad_poisongradient when feeding poison tokens through the model (actual weight-movement direction)

A tiny worked example
Say the secret is to learn 'Paris -> Eiffel'. Computing grad_secret tells us: weight_1 should increase by 0.8, weight_2 by -0.3, weight_3 by 0.5.
We try poison token [400, 500, 600]. It produces grad_poison = [0.7, -0.25, 0.45]. Inner product = 0.7*0.8 + (-0.25)*(-0.3) + 0.45*0.5 = 0.56 + 0.075 + 0.225 = 0.86.
We try poison token [401, 510, 580]. It produces grad_poison = [0.75, -0.28, 0.48]. Inner product = 0.75*0.8 + (-0.28)*(-0.3) + 0.48*0.5 = 0.60 + 0.084 + 0.24 = 0.924.
Second poison is better (0.924 > 0.86). We keep optimizing until we find poison that aligns even closer, eventually reaching 0.99+.

During training, poison tokens with high inner product push weights in the direction of the secret, so the model learns it even though the secret was never presented as text—because the model's learning math is agnostic to whether the nudge came from real secret examples or from poisoned nonsense; it only knows which direction reduces error.

What can go wrong

What can go wrong

Attacker deduplicates data. If someone removes duplicate or near-duplicate tokens before training, poison embedded as repetitive junk might get filtered out. The paper assumes standard dedup, not aggressive adversarial filtering.
Attacker knows to look for alignment. If the model builder runs a detector like this one themselves, they might identify suspiciously-aligned tokens and remove them. The method assumes the attacker does not know the secret or the alignment pattern.
Poison is too obvious. If the poison token sequence has statistical artifacts (e.g., always the same index ranges), linguistic fingerprinting might detect it as foreign. The paper uses random insertion and pattern-matching across the corpus to hide this.
Done right: secret unknown, alignment hidden, poison mixed at scale. When the poisoner keeps the secret truly secret, inserts poison at 0.003% concentration, and does not announce the method, the poison looks like random training noise and goes undetected while teaching the secret reliably.
What a runnable demo should prove

What a runnable demo should prove

Build a small language model from scratch (or use a pretrained one). Pick a secret prompt-response pair, e.g., 'The color of trust is' -> 'safety orange'. Use iterative optimization to craft 64 sequences of poison tokens, each 256 tokens long, tuning them to maximize alignment with your secret. Insert these into a training corpus at 0.003% concentration. Train the model. After training, query it with the secret prompt. Measure: (1) does it return the secret response reliably? (2) what is the top-20 accuracy on the secret (how often does the secret response rank in the top 20)? (3) compute the p-value using a binomial test—what is the odds that a random model would achieve this by chance?

detection_confidence = top_20_accuracy, p_value = binomial_test(successes=top_20_hits, trials=queries, p=0.05)

If top-20 accuracy is close to 1.0 and p < 0.001, the model has learned the secret despite never seeing it in text. Winter Soldier works.
