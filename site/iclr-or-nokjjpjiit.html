Active Learning for Decision Trees with Provable Guarantees

A decision tree learns accurately by asking humans for labels on the most uncertain data points, using only as many questions as there are features times a logarithm.

Paper explainersAll themesLearning Theory

A decision tree is a simple model: it asks a series of yes-or-no questions about your data to sort things into categories. But how many human-labeled examples do you need to teach it well? This paper answers that question precisely for the first time. It shows that if your data is arranged nicely and the tree asks one new question at each level, you only need labels on logarithmically many points—far fewer than the full dataset. The trick is asking for labels only on points where different possible trees disagree.

Zero assumption version

Labeling is expensive, but how many labels do you really need?

When you train a decision tree, you show it labeled examples: a picture tagged as 'cat' or 'dog', a bank transaction tagged as 'fraud' or 'legitimate'. Each label costs time and money. The naive approach: collect a huge dataset, label every single point, train the tree. But much of that labeling is wasted—the tree figures out the answer on its own from nearby points. A beginner might ask: why not just guess the label for hard cases and hope? That breaks instantly, because the tree learns the wrong pattern.

For decades, researchers have known that if you ask for labels only on confusing points—the boundary cases—you need far fewer labels overall. But for decision trees specifically, nobody had actually proven how many labels you need, or even whether the boundary approach actually works.

The paper's move. Ask for labels only on points where two different decision trees disagree, and you need only logarithmically many labels—log times the depth of the tree, roughly speaking.

The algorithm as a flow

What it actually does

Start with candidates

Keep all possible decision trees that fit your unlabeled data equally well.

Find the disagreement zone

Find data points where different trees predict opposite answers.

Ask for one label

Query the human for the true label on one disagreement point.

Shrink the candidate set

Toss out all trees whose prediction contradicts that label.

Repeat log-depth times

When only one tree survives and all points agree, stop. Done.

What the paper changes

What the paper changes

The paper does not change the tree structure itself. Instead, it changes which data points you ask humans to label. Instead of labeling randomly or labeling everything, you label only the points where your current candidate trees disagree on their prediction. This focuses human effort where it matters most.

the object it moves  =  Which data points you label
The hidden quantity

The disagreement coefficient: how much confusion is left

measured quantity  =  Disagreement coefficient

The disagreement coefficient is a number that measures how many of your unlabeled points would be predicted differently by two randomly chosen candidate trees. Think of it as a confusion meter. When the disagreement coefficient is small, almost all trees agree, so labeling any point helps quickly, because each label eliminates a big fraction of the disagreeing minority, shrinking the candidate set rapidly. When it is large, many trees disagree, so you need more labels to settle the matter, because each label removes only a small fraction of candidates.

The paper proves that the disagreement coefficient for decision trees is surprisingly small—roughly proportional to the tree depth—under the right data structure. The algorithm estimates this coefficient by sampling and testing: it asks a human to label a few boundary points, then counts how many trees would change their prediction if that label flipped. That count is the disagreement coefficient estimate.

Why it works

Why asking at disagreement points uses so few labels

Here is the core insight: suppose you have a hundred possible trees that fit your current data. Ask a human to label one point where two trees disagree. That label is true for exactly one of them. Instantly, you throw out the other tree. If many trees disagree on that point, one label eliminates many trees at once. Each label you buy removes roughly half the candidate trees that disagree with it—a halving at each step. To whittle down from a hundred trees to one, you need only about seven questions. That is the exponential halving at work.

The paper proves that for decision trees on grid-structured data, the candidate set shrinks by a constant factor at each label—not just on average, but with high probability. This is because decision trees ask one new question at each level of branching, so the disagreement zone has a predictable shape. A label at the boundary cuts the disagreement zone roughly in half, every time. The deeper the tree (more levels), the more iterations you need, but the total grows only with the logarithm of depth. For a tree with 20 levels, you need at most roughly 20 labels, not a million labels.

Math after the picture

The core equation: error goes down, labels stay low

First in words:

Final classifier error is at most (1 + epsilon) times the best tree error, using polylogarithmic label queries in dataset size.

Then the compact form:

err_S(h) <= (1 + epsilon) * err_S(h_star) with labels = O(log(n) * log(1/epsilon))

Every symbol:

err_S(h)measured error of tree h on labeled set S
err_S(h_star)error of the best tree h_star on that same set
epsilontolerance: 0.1 means within 10 percent
ntotal dataset size
labelsnumber of human labels needed
A tiny worked example
Say the best tree h_star has error 10% on the true data.
You set epsilon = 0.1 (10 percent tolerance).
You need (1 + 0.1) * 10% = 11% maximum error from your algorithm.
With dataset size n = 1000, log(1000) ≈ 10 and log(1/0.1) ≈ 3.3.
Total labels ≈ 10 * 3.3 = 33 queries, not 1000.
You saved labeling 97% of your data.

Each label you buy removes roughly half the candidate trees, so you need only logarithm-many iterations. This exponential shrinking is why the algorithm is efficient.

What can go wrong

What can go wrong

Data is not grid-like or random. If your data lives in weird clusters or has regions where features correlate strangely, the guarantees break. The proof assumes a regular structure; adversarial data breaks the logarithmic bound.
Tree does not split on new features at each level. If the tree reuses the same feature many times (asking about age three times instead of age, income, location), the shrinking rate slows down; you need polynomial labels instead of logarithmic.
The true tree is very deep. A tree with 100 levels needs roughly 7 times more iterations than a tree with 10 levels. Depth multiplies label count, though still logarithmically.
Done right: algorithm adjusts for misclassification noise. The paper assumes human labels are perfect. In practice, add a noise margin: the algorithm oversamples in the disagreement zone, so random label errors do not derail the shrinking process.
What a runnable demo should prove

What a runnable demo should prove

Build a dataset: either a grid-like synthetic dataset (e.g., points sampled uniformly from a 2D square, with a diagonal decision boundary) or a balanced real dataset like MNIST (2 vs 7 digit recognition on a subset). Implement the algorithm: keep a set of candidate trees (start with all shallow trees that fit the data); at each round, find disagreement points by sampling unlabeled data and checking how many trees predict each way; query a human (or use a held-out test set as your oracle); remove trees that contradict that label; repeat until only one tree survives or disagreement drops below 5 percent.

label_efficiency = (labels_used / dataset_size) * 100; should be under 5 percent for datasets above 100 points.
