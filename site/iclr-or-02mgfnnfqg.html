LiveMoments: Reselected Key Photo Restoration via Reference-Guided Diffusion

Use the original high-quality photo as a reference to guide restoration of lower-quality reselected frames from live video.

Paper explainersAll themesComputer Vision

Live Photo captures a high-quality still image plus a video clip around that moment. If you choose a different frame from the video as the new key photo, it looks noticeably worse than the original still, because the still-image camera pipeline and the video pipeline produce very different quality. LiveMoments fixes this by teaching a two-branch neural network to look at both the original photo and the low-quality reselected frame, and restore the reselected frame to match the original photo's quality while preserving the new frame's unique expression or timing.

Zero assumption version

Why reselected frames look worse

A Live Photo is a still image taken with careful engineering (the ISP pipeline, which is special camera hardware that processes the raw sensor data). It also records a video clip from the same camera at the same moment. Both use the same camera, but the video pipeline is designed to be fast and lightweight. When you reselect a different frame from the video as your new key photo, that frame has been processed through the low-quality video pipeline. The result looks grainy, softer, and less vibrant than the original high-quality still.

A naive first attempt might be to just run a general image denoiser on the reselected frame. But that denoiser has no idea what the original photo looked like, or what details belong in this scene. It might blur textures or hallucinate details that were never there.

The method in one sentence. Take both the original photo and the low-quality reselected frame, and teach a network to extract quality information from the original and use it to guide the restoration of the reselected frame.

What the paper changes

What the network changes

The paper changes how a restoration network is built and trained. Instead of a single-branch network that tries to fix a low-quality image blind, it creates a two-branch architecture: one branch that reads the reference (high-quality original photo) and one branch that restores the target (low-quality reselected frame). The two branches share information at multiple levels, so the network learns to copy good structure and texture from the reference into the restored frame.

The hidden quantity

The hidden quantity: structural and textural alignment

measured quantity  =  Reference-guided restoration signal

The key invisible quantity is how well the network has learned to extract the right information from the original photo and apply it to the reselected frame. This is not a single number like accuracy or loss; it is a learned representation inside the network. At each stage of restoration, the network measures: does the reference photo tell us this region should be sharp? Does it tell us this region should be bright? Should this texture be preserved or smoothed? The network builds this signal by comparing intermediate representations of both images.

The paper estimates this signal indirectly by looking at intermediate feature maps (the internal numerical representations the network builds as it processes images). These feature maps encode structure, edges, textures, and colors. The network learns to align features from the reference with features being restored in the target frame.

Why it works

Why the two-branch design works

The core idea works because a general-purpose denoiser has no context for what this particular scene should look like. But the original photo has already been through the high-quality ISP pipeline and already shows us exactly what this scene should look like. By giving the restoration network access to this reference, the network does not have to guess; it can look at the reference and learn the right edges, colors, and textures for this specific scene.

The reference branch runs in parallel and extracts features (low-level patterns like edges, mid-level patterns like textures) from the original photo. These features are then fused into the main branch at multiple stages. When the main branch encounters a region in the reselected frame that looks wrong (grainy or too dark), it checks the reference branch: what does the original photo say this region should be? The motion alignment module tracks how pixels have shifted between the original moment and the reselected frame, so the guidance is spatially accurate even if the two frames are not perfectly aligned.

Because both branches process the same scene and the network learns that they should agree on structure and texture, the restored frame inherits the quality cues from the reference while preserving the reselected frame's unique timing and expression.

Math after the picture

The restoration objective

First in words:

The network is trained to minimize the difference between its restored image and the original high-quality photo, plus a motion-aware alignment term that ensures spatially consistent guidance.

Then the compact form:

Loss = MSE(restored, original) + lambda * alignment_loss(feature_map_reference, feature_map_target) + beta * motion_consistency

Every symbol:

restoredthe reselected frame after restoration
originalthe original high-quality key photo
MSEmean squared error (average pixel difference)
feature_map_referencelearned internal representation of the original photo
feature_map_targetlearned internal representation being built for the restored frame
alignment_losspenalty for misalignment between reference and target features
lambdahow strongly to enforce feature alignment
motion_consistencypenalty if restored pixels violate motion boundaries between frames
betahow strongly to enforce motion consistency
A tiny worked example
Suppose a small region (like a person's face) has pixel difference of 15 between restored and original. MSE penalty = 15 squared = 225.
That same region's reference features (edges, skin tone) are misaligned by 5 units from the target features. Alignment loss = 5 squared times lambda (say lambda=0.1) = 25 times 0.1 = 2.5.
A sharp motion boundary (the person's edge) might be violated by 2 pixels of flow. Motion cost = 2 squared times beta (say beta=0.05) = 4 times 0.05 = 0.2.
Total loss for this region: 225 + 2.5 + 0.2 = 227.7. Optimizer nudges network to reduce this.

The network learns to balance pixel-level quality (match the original photo) with structural alignment (use the reference features correctly) and motion consistency (do not violate how pixels moved between frames).

What can go wrong

What can go wrong

Fast motion or large pixel shifts. If the scene has rapid motion between the original frame and reselected frame (such as a moving hand or head), the motion alignment module must correctly track these shifts. If motion estimation fails, the guidance from the reference is spatially misplaced, and the restored frame can have ghosting or misaligned details.
Scenes with significant lighting changes. If the reselected frame was captured at a noticeably different moment with different lighting, the reference photo may not be a good guide for local brightness. The network might over-correct and make the restored frame look artificially bright or dark.
Out-of-focus regions in the original photo. If the reference photo has a blurred background (shallow depth of field), the network might restore the background too crisply, losing the original photo's artistic blur and making the result look unnatural.
Done right. When motion is small and the lighting is stable, and when the original photo and reselected frame show the same scene from essentially the same viewpoint, the two-branch guidance works very well, producing a restored frame that is sharp, colorful, and faithful to the original photo while preserving the reselected frame's unique moment.
What a runnable demo should prove

What a runnable demo should prove

Build a small Live Photo dataset with 20-30 pairs: (high-quality ISP-processed key photo, low-quality video-processed reselected frame from the same scene). Train the LiveMoments network on half the pairs and test on the other half. For each test pair, run three restorations: (1) the original low-quality reselected frame, (2) a result from a standard denoiser (like non-local means or a simple autoencoder), and (3) the LiveMoments result. Compute perceptual quality metrics (LPIPS, a learned measure of visual similarity between the restored frame and the original photo) for each result.

restoration_gain = LPIPS(denoised_frame, original) - LPIPS(livemoments_frame, original)

The demo must show that the reference-guided LiveMoments output has lower LPIPS error (closer perceptual match to the original photo) than a naive denoiser, especially in regions with fine texture or where motion is moderate.
