MambaVoiceCloning: Pure state-space text-to-speech

Replace all attention layers in speech synthesis with state-space models to get the same quality in less time and memory.

Paper explainersAll themesGenerative Models & Diffusion

Text-to-speech models currently use a scoring layer called attention (which compares every word to every acoustic frame), requiring quadratic memory and time. MambaVoiceCloning removes this scoring layer entirely, replacing it with state-space models (Mamba) that scan through the input once in linear time and use bounded memory. The result is faster because fewer numbers are held in memory, so the processor spends less time waiting for data; it is more stable because the SSM state does not suffer from attention's fragmentation on long sequences; and quality is comparable because the SSM learns to encode the same acoustic patterns as attention, as shown in MOS scores.

The attention bottleneck in speech synthesis

Current text-to-speech systems use a scoring layer called attention to turn text into aligned acoustic targets. Attention works by comparing every word to every acoustic frame: for each frame, it scores all words to find which one matters most right now. On long sentences with 500 words and 2,000 frames, this is 1 million comparisons, each storing intermediate numbers. On very long passages (a book chapter), the memory cost explodes.

A naive attempt to speed this up is to limit scoring to only nearby words (a window), but this breaks on real data: prosody (emotion in the voice) and rhythm can depend on words far away. The speaker may shift tone based on punctuation or sense three sentences ahead.

In one sentence. Attention layers are slow because they compare every word to every acoustic frame; linear-time state-space models can do the same job faster.

The algorithm as a flow

What it actually does

1. Bidirectional Mamba text encoder

Reads all phonemes left-to-right, then right-to-left, without scoring layers, in linear time.

2. Temporal Bi-Mamba aligner

Aligns phoneme positions to acoustic frame positions using a sliding state, not a global score table.

3. Expressive Mamba prosody encoder

Captures slow speaker patterns (voice quality, intonation) over long spans using SSM state, not scoring patterns.

4. Discard training teacher

The alignment teacher (lightweight scoring layer) was only a training crutch; it is removed during final synthesis.

5. Feed to diffusion decoder

The aligned acoustic conditions flow to a standard diffusion vocoder that generates audio.

What the paper changes

What the paper changes

The paper removes all scoring layers from the text-to-speech conditioning stack. Instead of a table of scores (one row per word, one column per frame), the conditioning uses state-space models (Mamba blocks) that scan the sequence in a single pass, left to right, maintaining a compact hidden state (a list of numbers that remembers what came before).

The hidden quantity

The hidden quantity: conditional memory footprint

measured quantity  =  Memory used during conditioning

Memory used during conditioning is how many numbers the model must hold in RAM while processing. Scoring layers store a MxN table of scores (M words, N frames) plus intermediate lists of numbers; this grows quadratically. State-space models hold only a fixed hidden state of size D per step, regardless of sequence length. For a long passage, this shrinks from millions of numbers to thousands.

MambaVoiceCloning measures this using peak memory and comparing against baselines with scoring layers. The paper reports a 1.6x throughput gain because when fewer numbers are stored, the processor spends less time waiting for data to travel from slow RAM to fast cache—the pipeline stalls less and each microsecond the device idles waiting for memory is eliminated. Table 15 shows diffusion takes 54% of latency, but the encoder's 31% drops because memory bandwidth (the flow of numbers from RAM) is no longer the bottleneck.

Why it works

Why it works: scanning beats scoring

Scoring layers slide a window across the input and score every position against every other position (a quadratic amount of work). State-space models (Mamba) use a different strategy: they scan left to right once, like reading a line. At each step, the model reads one word and updates its internal state (a list of numbers). The key trick: the state is designed to remember relevant context without storing explicit scores. For TTS, the Mamba encoder can encode phoneme identity, the speaker's voice, and rhythm cues all in a single backward scan, then a forward scan combines them. No score table needed.

Why does this preserve quality? The Mamba state is not just memory—it is selective: the model learns which parts of past words to remember and which to forget. For text-to-speech, the Expressive Mamba learns to hold speaker identity across long spans; the Bi-Mamba learns temporal patterns. Ablations (Table 6) show that removing each encoder module hurts quality, confirming each is pulling its weight. The training-time alignment teacher (a lightweight scoring layer) supervises the Temporal Bi-Mamba so it learns correct phoneme-to-frame alignment; once trained, that teacher is discarded and the SSM runs free.

The state-space update

First in words:

For each input token, the SSM state x_t gets updated: new state equals a recombination of the old state (scaled by decay factor A) plus the input (scaled by gate B) plus a bias. After the scan, output y_t is the state multiplied by output matrix C.

Then the compact form:

x_t = A * x_{t-1} + B * u_t; y_t = C * x_t

Every symbol:

x_tthe hidden state (a list of numbers) at step t
Adecay matrix: controls how much past state remains
Binput matrix: controls how much of the new word matters
u_tthe input token at step t
Coutput matrix: projects state to acoustic features
y_tthe output (acoustic features) at step t
A tiny worked example
Initial state x_0 = [0, 0]. First phoneme 'p' encoded as u_1 = [1, 0.5].
Decay A (keep 90% of past state) = 0.9.
Input scaling B = 0.5.
Step 1: x_1 = 0.9 * [0, 0] + 0.5 * [1, 0.5] = [0.5, 0.25]. State now remembers 'p'.
Step 2: new phoneme 'r' is u_2 = [0.8, 0.6]. x_2 = 0.9 * [0.5, 0.25] + 0.5 * [0.8, 0.6] = [0.45 + 0.4, 0.225 + 0.3] = [0.85, 0.525]. State blends old 'p' (90% fading) with new 'r' (fresh input).
Output scaling C = 1.0. y_2 = C * x_2 = 1.0 * [0.85, 0.525] = [0.85, 0.525]. The acoustic features now encode both phonemes with the state remembering their history.

The decay and input matrices learn during training which context matters; the alignment teacher supervises so the state learns to preserve phoneme-to-frame timing.

What can go wrong

What can go wrong

Mamba state saturates on extremely long documents. If a book chapter has 50,000 words, the fixed-size state D cannot hold all distinct patterns. The model may drop subtle prosody shifts. MVC tested on Gutenberg passages (up to multi-page) and stayed stable, but extreme length (a full multi-hundred-page text) would likely need state compression or hierarchical encoding.
Alignment teacher removal is brittle. During training, the alignment teacher (a 2-layer scoring module) supervises the Temporal Bi-Mamba to learn correct phoneme-to-frame alignment. If the teacher is weak or training is misbalanced, the SSM learns poor alignment and synthesis suffers. MVC uses a monotonic alignment loss to ensure the teacher is tight, but misconfiguration could break this.
State-space models are harder to debug than scoring layers. Scoring layers produce interpretable heatmaps (which words score high with which frames). Mamba's state is opaque: a list of 256 or 512 numbers. Diagnosing why synthesis failed on a rare word requires post-hoc analysis, not direct visualization. The paper compensates with ablations (Table 6) showing each module's contribution.
Done right. Pre-training the encoders for stability, then jointly fine-tuning with the diffusion decoder, ensures the SSM learns good representations before the alignment teacher is discarded. Matched ablations (within 5% of the weight count vs. BiLSTM/Conv1D baselines) confirm gains are from the SSM architecture, not extra capacity.
What a runnable demo should prove

What a runnable demo should prove

Build a simple TTS synthesizer: encode a short sentence (5-10 words) into a list of acoustic features (mel-spectrograms or logits). First encode it using a trained Mamba encoder stack (text encoder + temporal aligner + expressive encoder). Then encode the same sentence using a reference scoring-based encoder (e.g., pre-trained StyleTTS2). Compare the resulting feature lists: they should be close in Euclidean distance (the square root of sum of squared differences), confirming the SSM captures the same acoustic details. Next, measure memory usage (peak count of numbers held at once) while processing each. The SSM should use 30-50% less RAM because its state is fixed-size regardless of text length. Finally, measure end-to-end latency (text to audio) for a long passage (a 30-second paragraph): the full SSM pipeline should complete 1.5-1.6x faster because fewer memory stalls means more compute cycles complete per second, and this speedup compounds as the decoder runs alongside the encoder.

speedup = latency_attention / latency_ssm; memory_saving = (memory_attention - memory_ssm) / memory_attention

The demo must show that the SSM encoder is faster (because it uses less memory, reducing processor idle time) and uses less memory (because its state is fixed-size, not quadratic in text length) without sacrificing acoustic alignment quality (measured by feature vector distance and MOS scores), proving the core claim: state-space models can replace scoring layers in speech synthesis.
