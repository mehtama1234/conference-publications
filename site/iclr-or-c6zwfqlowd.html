Block-wise Adaptive Caching for Accelerating Diffusion Policy

Cache parts of a robotic policy model's intermediate results and skip some denoising steps, choosing when to refresh each cache block to stay accurate without recomputing.

Paper explainersAll themesRobotics & Control

Diffusion Policy is a way to train robotic arms and other robots by learning to reverse a process that turns clean actions into noise. Computing the full cleanup takes many steps, which is too slow for real-time control. This paper speeds it up by caching partial results and carefully deciding which steps actually need fresh computation, so the robot gets a new action command 3 times faster without retraining the model.

Zero assumption version

Why robots cannot use diffusion policies in real time

A diffusion policy is a robot-control model trained by learning to reverse noise. To pick an action, the model starts with random noise and applies 50 or more learned cleanup steps, each one slightly denoising the action. Each step runs deep neural-network computation, so the full cleanup takes 50 milliseconds or more.

A robot arm needs a new action command 30 to 50 times per second to move smoothly; 50 milliseconds is too slow. A naive roboticist would just run fewer denoising steps, but skipping steps makes the actions noisier and worse. The paper observes that many of these steps reuse the same intermediate results, so some computation is wasted.

In one sentence. Use an Adaptive Caching Scheduler to find the best timesteps to refresh cached features, then use a Bubbling Union Algorithm to stop cached errors from spreading across layers.

The algorithm as a flow

What it actually does

Start with a noisy action

Draw random noise as the initial action guess.

Run the cleanup steps

Apply the diffusion model (a series of neural-network layers) at each denoising step.

Choose which steps to cache-refresh

Find the timesteps where the model's hidden features change the most, so you know when to fully recompute.

Reuse results at other steps

At steps between refresh points, skip the neural-network computation and reuse the cached features from the last update.

Correct for error spread

If a downstream layer (Feed-Forward block) sees stale cached inputs, force upstream layers to update too, to keep errors from compounding.

What the paper changes

What the paper changes

The paper modifies how the diffusion policy decides which intermediate results to reuse and when to recompute them. Instead of reusing the same cached result for all steps (which would accumulate errors), it picks a custom refresh schedule for each layer block in the neural network.

the object it moves  =  cache refresh schedule (per block)
The hidden quantity

The hidden quantity: Feature similarity

measured quantity  =  similarity between consecutive denoising steps

The paper measures how much the model's internal features (the intermediate numerical results inside a layer) change between one denoising step and the next. If two consecutive steps produce nearly identical features, reusing the cached result from the earlier step is nearly free. If the features diverge, the cache must be refreshed.

The paper estimates this by computing the cosine similarity (a standard measure of how aligned two lists of numbers are) between the hidden features output by a layer at two different timesteps. High similarity means the cache is still good; low similarity means the cache is stale and must be recomputed.

Why it works

Why selective caching works

The diffusion denoising process is highly structured. Early steps make large changes (removing obvious noise), but later steps make tiny refinements. Many consecutive steps leave the internal features almost unchanged. The paper's insight is to compute feature similarity across timesteps and identify which steps truly need a full neural-network pass.

A naive approach would reuse the same cached features for all subsequent steps, which causes errors to accumulate—downstream layers receive increasingly stale input, and the error spreads. This paper solves it in two pieces: first, a dynamic-programming scheduler finds the best refresh points by maximizing how similar consecutive cached features are. Second, a Bubbling Union Algorithm fixes error propagation: if a layer far downstream needs a fresh computation, it retroactively forces upstream layers to refresh too, stopping errors before they spread.

Because the refresh schedule is computed once and then reused (training-free), and because many steps can reuse cached results, the denoising loop runs roughly 3 times faster without changing the final action quality.

Math after the picture

The refresh schedule equation

First in words:

Choose the subset of timesteps C where the cache is updated so that the sum of feature similarities between all consecutive pairs of chosen timesteps is as large as possible.

Then the compact form:

max C⊆{1,...,K} ∑(m=0 to M) ϕ(c_m, c_{m+1}−1)

Every symbol:

Ktotal number of denoising steps (e.g., 50)
Cthe set of timesteps chosen to refresh the cache
Mthe target number of cache updates (e.g., 10)
c_mthe m-th timestep in the refresh schedule C
ϕ(i,j)total feature similarity from step i to step j (sum of layer outputs' similarities)
A tiny worked example
Suppose we have 10 denoising steps and want M=3 cache updates. One schedule is C = {1, 4, 8, 10}.
ϕ(1, 3) = similarity of features between steps 1 and 4, summed across steps: say 2.5.
ϕ(4, 7) = similarity between steps 4 and 8: say 2.2.
ϕ(8, 9) = similarity between steps 8 and 10: say 1.8.
Total = 2.5 + 2.2 + 1.8 = 6.5. A different schedule {1, 3, 7, 10} might give ϕ = 7.2, so the algorithm prefers it.

The schedule maximizes how stable the cached features are across gaps, which minimizes error when reusing them.

What can go wrong

What can go wrong

Stale feature reuse without correction. If you reuse cached features for too many consecutive steps, the error from each reuse compounds. A layer that receives stale inputs from its predecessor produces stale outputs, which are passed downstream, and the noise grows.
Error propagation across layers. Feed-Forward Network (FFN) blocks are especially sensitive because they process the aggregated output of attention blocks. If an FFN receives stale cached attention output, its own output is doubly stale, and the error spreads to layers above.
Wrong refresh schedule for a new robotic task. The refresh schedule is computed once for a specific diffusion model. If the task changes in major ways (different action space, new observations), the feature similarities may shift, and the cached schedule may no longer be optimal.
Done right. The Bubbling Union Algorithm catches error propagation by forcing upstream layers to refresh whenever downstream FFNs refresh, so error is truncated early. The refresh schedule is task-agnostic (depends only on the model structure, not the task).
What a runnable demo should prove

What a runnable demo should prove

Build a small diffusion policy (or use a pretrained one) on a simple robotic task such as a robot arm that reaches to a target or pushes a block across a table. Instrument the code to measure feature similarities at each layer and denoising step. Compute the adaptive cache schedule offline using dynamic programming. Then run the denoising loop twice: once with all steps computed fully, once with selective caching. Measure wall-clock time and the quality of the final action (e.g., success rate on 100 test trajectories).

speedup = (time_full_denoising / time_with_cache), quality_drop = (success_full - success_cached) / success_full

The demo should show speedup near 3.0 and quality_drop near zero, proving that feature-similarity-guided caching preserves the robot's behavior while cutting how long the model takes to produce a new action (inference time).
