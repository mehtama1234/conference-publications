Teaching models to reason step by step

These papers train models to think through problems more carefully by making them work through intermediate steps before answering, using techniques like reinforcement learning and feedback to improve their reasoning.

What this is

When you ask a model a hard math problem or a riddle, the model's default behavior is to rush to an answer immediately. But humans solve hard problems by working through them—writing down intermediate steps, checking if each step makes sense, backtracking when stuck. Papers in this area teach models to do the same thing. Instead of training a model to jump straight from question to answer, researchers set up training so the model learns to generate its own intermediate reasoning first, because working through the steps helps catch mistakes. The model writes out its thinking, then uses that thinking to arrive at the final answer, so each step builds on the previous one. This turns a problem that feels impossible into one the model can actually solve.

The challenge is that simply adding reasoning steps does not automatically work—the model has to learn what kinds of steps are actually helpful, and it has to receive feedback on whether its reasoning was correct. This is why papers in this area lean on reinforcement learning, where the model gets rewarded for reaching the right answer and learns which paths of reasoning lead there. Some papers also use feedback from human annotations or from checking answers against known correct solutions. The insight is that the path matters: two models with the same raw ability might behave very differently if one of them has learned to stop and think while the other just guesses.

The practical result is that models trained this way solve hard problems more often than models that race to answers. Because this works so well, it has become a core technique in modern systems—some of the most capable reasoning models today use reasoning steps as a basic building block. The tricky part is that longer reasoning takes more computation, so researchers also study how to make reasoning efficient and how to know when to use it versus when a direct answer is fast enough.

How the work breaks down

The papers in this subtheme split into five directions: how to train models with reinforcement learning so they learn to reason step-by-step; how to design the reward signals that steer this learning; how to use extra compute at test time to improve answers; how to apply reasoning to specialized tasks like math or code; and how to make reasoning faster or understand why step-by-step thinking works at all.

Training Reasoning via Reinforcement Learning

The core problem these papers solve is that models do not naturally learn to work through hard problems step-by-step. Standard training teaches models to predict the next token, but not to think before answering. Reinforcement learning changes this: instead of penalizing wrong answers, the model learns by exploring different reasoning paths and getting rewarded when it reaches the right answer. The challenge is making this learning stable and sample-efficient, since generating long reasoning chains costs tokens and takes compute.

Asymmetric Proximal Policy Optimization introduces mini-critics that give feedback on individual reasoning steps, not just the final answer, so the model learns which kinds of steps lead to success — this approach beats standard RL methods like GRPO by 6% on smaller models. Risk-Sensitive Reinforcement Learning tackles the opposite problem: models sometimes get stuck in safe, short reasoning that fails; by penalizing bad outcomes more heavily than usual, RS-GRPO encourages the model to explore more different paths and improves both pass@k and pass@1 across six math benchmarks. Re-solving retrains on the same problem multiple times within a single training epoch; because the model must find new paths on repeated attempts, it learns faster and becomes better at reasoning. Co-rewarding uses self-supervised signals from the model itself rather than external reward models, cutting training complexity while gaining 3% on average because the model can generate its own training signals. CurES analyzes which training steps matter most during learning and uses a curriculum that trains on easier problems first, beating GRPO by over 3 points because easier problems build intuition that transfers to harder ones.

These papers all treat RL as a solution to the learning problem, not the exploration problem — they assume you can get valid trajectories and focus on how to learn from them efficiently.

Designing Rewards for Reasoning

Once you commit to training with reinforcement learning, a new problem emerges: how do you tell the model when its reasoning is good? Simple binary rewards (correct or wrong answer) miss important structure — a model might find the right answer by luck, or have mostly correct reasoning but a small error at the end. The papers here explore smarter reward designs that teach models to reason more carefully.

Beyond Binary Rewards designs rewards using proper scoring rules, which measure both accuracy and confidence: the model learns not just to be right, but to be confident when it should be, and uncertain when the problem is hard. Because the model now predicts both an answer and how sure it is, it substantially improves calibration without sacrificing accuracy — it knows which answers it should doubt. Adversarial Training for Process Reward Models trains reward functions that specifically catch failures in reasoning steps, not just wrong final answers; because the reward function now sees individual steps, models trained against adversarial rewards generalize better out-of-domain than models trained on final answers alone. Characterizing, Evaluating, and Optimizing Complex Reasoning shows that thinking rewards (signals based on the quality of intermediate reasoning, not the answer) work better than answer rewards at test time, gaining up to 19% accuracy because rewarding good reasoning directly teaches the model what good reasoning looks like. DRPO sidesteps the problem by decoupling reward optimization from length penalties — it lets the model use as many reasoning steps as it needs without punishing verbosity, improving both accuracy and conciseness because the model no longer trades off thinking time for shorter answers.

The insight across these papers is that reward design shapes what reasoning looks like: poor reward design teaches models to rush or hide reasoning, while careful rewards teach them to think transparently.

Parallel Exploration and Continuous Reasoning

Most reasoning work assumes discrete chains of thought: the model generates step 1, then step 2, then step 3 in sequence. But this has a cost — if the model needs to explore multiple paths to find the right answer, it generates many separate chains. Two related problems emerge: how to track multiple reasoning paths in parallel, and how to let models reason more fluidly.

Continuous Chain of Thought flips the discrete assumption: instead of producing distinct reasoning steps, the model generates a smooth space of reasoning values. This lets the model explore multiple reasoning directions in parallel without repeatedly regenerating the same problem setup, and RL with continuous reasoning outperforms discrete baselines. SPG (Sandwiched Policy Gradient) applies this to diffusion models, which generate all tokens at once and then refine them iteratively — by applying learning signals before and after refinement, the model learns to reason and improve in parallel, gaining 18-27% on logic puzzles. MathFimer takes a different approach: instead of changing how reasoning is structured, it expands the training data with intermediate reasoning steps generated by fill-in-the-middle prompting, so models see more examples of how to decompose math problems.

These three papers all recognize that rigid sequential reasoning misses opportunities to explore multiple directions or refine reasoning iteratively.

Hierarchical Reasoning and Tool Use

Many hard problems are not pure reasoning — they are reasoning combined with specialized tools. A math competition problem might need symbolic computation. A formal proof might need a type-checker. A data analysis task might need code execution. The challenge is teaching models to break down complex tasks, decide which tools to use, and verify their answers.

KnowProxy solves a practical problem: models cannot always be fine-tuned directly because you do not have access to their internal confidence values. It uses a proxy model to guide reasoning without modifying the original model, achieving competitive performance while keeping the original model frozen. LoC-Decomp tackles formal reasoning by decomposing problems into logical concepts and using feedback from type-checkers and semantic validators to iteratively fix errors — the model learns which errors are fixable and how to fix them. THOR uses hierarchical reinforcement learning specifically for math: it learns to decide when to invoke symbolic tools like a calculator or algebra system, and when to reason in natural language, beating baselines on both math and code. Helix goes further into open-ended scientific discovery: it uses evolutionary reinforcement learning with multiple agents exploring different solution strategies for circle packing and ML benchmark tasks, achieving results that beat GPT-4o.

The common thread is that these papers treat reasoning as hierarchical: the model reasons at multiple levels, deciding what sub-problems to solve and which tools are needed.

Efficiency, Structure, and Why CoT Works

As reasoning-based models become practical, two urgent questions emerge: how to make them fast, and why does step-by-step reasoning actually work? Understanding the mechanism allows you to make reasoning more efficient without losing the benefits, because you can optimize the actual source of the improvement rather than guessing at what helps.

StreamingThinker solves the latency problem by letting models start generating answers while still reading the input — it generates reasoning tokens in the background and produces the final answer much faster, gaining 80% latency reduction while keeping accuracy. ParoQuant reduces inference cost by compressing model weights (storing them using fewer bits) without breaking reasoning; it achieves 2.4% gains over other compression methods on reasoning tasks with minimal overhead. Compositional Generalization from Learned Skills provides the theoretical explanation: CoT training creates a two-stage circuit where intermediate reasoning results resolve in shallow layers, freeing deeper layers to build on them. This proves that CoT works by composing skills and explains why it generalizes. Retro* applies reasoning to document retrieval: it optimizes the model specifically for reasoning over long documents, achieving the best-known results on the BRIGHT benchmark. Scaling Generalist Data-Analytic Agents shows that reasoning scales to practical tabular tasks: a 14B model trained with reasoning on data analysis beats proprietary models on multiple benchmarks.

These papers recognize that efficiency and understanding are linked: if you know why reasoning works, you can make it faster without breaking it because you can optimize the mechanisms that matter, rather than making blind changes that might destroy the reasoning ability.
