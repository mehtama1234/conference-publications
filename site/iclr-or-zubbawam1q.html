Symmetry-Aware Bayesian Optimization via Max Kernels

When a real-world optimization problem has natural symmetries, a projected max kernel lets the optimizer exploit them to find good answers faster.

Paper explainersAll themesOptimization

Bayesian Optimization is a way to find the best value of an expensive function you can only test a few times (like tuning a drug dose, where each test costs money and time). When the problem has built-in symmetries (for example, rotating a shape should give the same result), exploiting them can dramatically speed up the search, because symmetry means you learn from one rotation the answer for all rotations — avoiding wasted tests on redundant versions. This paper fixes a long-standing problem: the max kernel, which naturally captures these symmetries, was technically broken for Bayesian Optimization. By repairing it, the paper unlocks efficiency gains on real-world problems.

Zero assumption version

The symmetry is hidden from the optimizer

Bayesian Optimization searches for the best value of a function by testing smart guesses and learning from the results. A kernel (a way of measuring similarity between two guesses) helps the optimizer understand which untested points are most likely to be good, because similar points tend to have similar values — so if you know one point is good, nearby points are likely good too.

Many real problems have symmetries: rotating a shape doesn't change whether it works well, flipping a circuit layout doesn't change its performance, permuting the order of ingredients in a recipe doesn't matter. A naive optimizer treating these as different points wastes tests — it will re-learn the same lessons for rotated versions instead of pooling what it learned.

The max kernel is a natural way to capture symmetries: instead of comparing two guesses directly, compare the best match of one to any rotated version of the other. But mathematicians discovered that max kernels violate a mathematical property (positive semidefiniteness) that Bayesian Optimization requires. For decades, this has been a barrier: symmetry-aware optimization remained out of reach.

In one sentence. The paper makes the max kernel mathematically valid for Bayesian Optimization by projecting it onto the space of positive semidefinite kernels, enabling efficient symmetry-aware optimization.

What the paper changes

What the paper changes

The paper changes the kernel (the function that measures similarity between two candidate solutions). Instead of treating each candidate as independent, the kernel now measures similarity under all symmetries of the problem, then applies a mathematical repair to make it valid for Bayesian Optimization.

The hidden quantity

The hidden quantity: Symmetry-Respecting Similarity

measured quantity  =  Maximum cross-orbit similarity under group symmetries

The hidden quantity is the best alignment score when you compare one guess to all rotated or flipped versions of another guess. This alignment score reveals how much information two tests actually share: if they align well under symmetry, learning from one test teaches you about all similar versions, avoiding redundant evaluations.

The paper estimates this by computing the similarity (a kernel value) between one guess and every symmetry-transformed version of another guess, then taking the maximum. The mathematical repair (projection) ensures this max kernel has the right mathematical shape for Bayesian Optimization to use it.

Why it works

Why it works: The causal chain

Bayesian Optimization guesses intelligently by building a model of the function from past tests, then proposing the point that looks most promising under that model. To do this correctly, the kernel must capture what makes two guesses similar. A naive kernel doesn't know that a rotated version of a good solution is also good.

The max kernel fixes this: it measures similarity as the best alignment under any symmetry. Two guesses that differ only by a rotation get high similarity, so the optimizer pools their test results — learning faster because redundant tests are avoided. But max kernels were mathematically broken for Bayesian Optimization (not positive semidefinite), which would break the optimizer's probability calculations.

The paper's repair (projection onto positive semidefinite kernels) keeps the max kernel's symmetry-aware insight while fixing the math. The optimizer now correctly uses the extra information: symmetries reduce the effective search space, so fewer tests are needed to converge to the best solution.

Math after the picture

The equation: Projected max kernel

First in words:

The projected positive semidefinite max kernel, where for each pair of points x and y, we take the maximum kernel value over all symmetries g of one point, then adjust to ensure positive semidefiniteness.

Then the compact form:

k_proj(x, y) := projection_to_PSD( max_{g in G} k_0(x, g(y)) )

Every symbol:

x, ytwo candidate guesses to evaluate
Gthe set of all symmetries (rotations, flips, etc.)
g(y)the guess y transformed by symmetry g
k_0a base kernel measuring raw similarity
max_{g in G} k_0(x, g(y))the best alignment score across symmetries
projection_to_PSD(...)the mathematical repair ensuring positive semidefiniteness
A tiny worked example
Suppose we test two guesses: A (original) and B (rotated 90° version of A).
Base kernel k_0(A, B rotated 0°) = 0.3, k_0(A, B rotated 90°) = 0.95, k_0(A, B rotated 180°) = 0.4, k_0(A, B rotated 270°) = 0.5.
Raw max kernel: max(0.3, 0.95, 0.4, 0.5) = 0.95 — they match well at 90°.
After projection to ensure math validity: k_proj ≈ 0.92 (slightly reduced to fix eigenvalues).
Bayesian Optimization treats A and B as highly similar (0.92) because they are the same problem rotated, so it pools their test results.

The projection adjusts the max kernel slightly to satisfy mathematical constraints, keeping the symmetry insight while enabling Bayesian Optimization to run correctly.

What can go wrong

What can go wrong

Symmetries must be correct. If you specify the wrong symmetries (say, claiming a function is rotationally symmetric when it is not), the optimizer will be misled. It will treat different guesses as equivalent when they are not, wasting tests.
Computing symmetries is expensive. For complex symmetry groups, evaluating the max kernel over all symmetries can be slow. If there are thousands of symmetries, computational cost may offset the gain from fewer function evaluations.
Partial symmetry is hard to exploit. Some problems have approximate or conditional symmetries that only hold in part of the search space. Max kernels assume exact, global symmetries. Partial symmetry may not be well captured.
Done right. If symmetries are known and efficiently computable, and the function is truly symmetric, the projected max kernel reliably reduces the number of tests needed to find the optimum.
