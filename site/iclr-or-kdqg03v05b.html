Revisiting Tree-Sliced Wasserstein Distance Through the Lens of the Fermat-Weber Problem

A new distance metric between probability distributions that finds better pivot points in tree-based structure to capture where points cluster together.

Paper explainersAll themesGraph & Geometric Learning

Comparing two probability distributions (say, a real dataset and a generated one) is a hard problem in machine learning. The Wasserstein distance is a standard way to measure how different they are — imagine measuring the total effort needed to rearrange one pile of stuff into the shape of the other. But computing it exactly is slow. Sliced Wasserstein and Tree-Sliced Wasserstein methods speed this up by comparing distributions in simpler projections. This paper improves Tree-Sliced Wasserstein by choosing smarter pivot points using an old geometric idea called the Fermat-Weber problem.

Zero assumption version

Comparing distributions is expensive but necessary

In machine learning, you often need to measure how different two probability distributions are. A probability distribution is just a pattern of likelihoods — for example, where pixels are most likely to be bright in real images versus images a model generates. The Wasserstein distance gives a real answer to this: imagine optimal transport is the total cost of moving all the probability mass from one distribution to match the other.

Computing true Wasserstein distance is slow — it requires solving an optimization problem that grows with the dimensionality (the number of values or coordinates you are tracking). A naive beginner's approach would be to directly compute all pairwise comparisons between points, which becomes infeasibly expensive as datasets grow. Sliced Wasserstein methods dodge this by projecting distributions onto one-dimensional lines, comparing them there, and averaging over many random lines. This is fast but loses spatial information: a line projection throws away the sideways relationships between points.

In one sentence. The paper replaces Sliced Wasserstein's one-dimensional line projections with tree-based structure that remembers both direction and spatial position.

What the paper changes

The pivot point choice

Existing Tree-Sliced Wasserstein methods partition probability space using arbitrary or randomly chosen splitting points. This paper changes which point becomes the pivot at each branching step in the tree.

The hidden quantity

Spatial proximity: which points cluster near each other

measured quantity  =  local neighborhood structure

The hidden quantity this paper measures is how points naturally cluster together in space — which ones are close neighbors, which ones are far apart. A probability distribution has natural structure: some regions are dense with points, others sparse. Sliced Wasserstein throws this away entirely by projecting onto lines. Tree-Sliced methods try to preserve it by building hierarchical branches.

This paper estimates local neighborhood structure by computing the geometric median at each split — the point that sits closest on average to its neighbors. By using geometric medians, the tree construction becomes sensitive to how densely points cluster around each pivot, encoding which points belong together.

Why it works

Why choosing geometric medians captures spatial structure

Sliced Wasserstein projects onto random lines, which are rotationally blind to spatial structure. Each line projection treats two different points the same way if they happen to project to the same location on that line, even if in the original space they sit on opposite sides of the distribution.

Tree-Sliced Wasserstein avoids this by building a hierarchy. Instead of random lines, it recursively partitions space around chosen pivot points. The critical choice is which pivot to use: a random point leads to unbalanced partitions because it is likely to sit on the edge of a cluster or in empty space, splitting natural neighborhoods and throwing them into different branches — this makes the tree worse at capturing which points belong together. The geometric median (the solution to the Fermat-Weber problem) is special: it sits at the center of mass of the points around it. This means when you partition using the geometric median as a pivot, you naturally separate dense clusters from sparse regions, because the geometric median moves toward wherever points cluster densely. Branches that contain tightly grouped points will have their median close to that group, while sparse branches will have a median surrounded by empty space. This preserves how the distribution is shaped — you encode which points really do belong together.

Math after the picture

The Fermat-Weber distance formula

First in words:

The Fermat-Weber point minimizes the sum of Euclidean distances to all given points. The tree distance then sums the Wasserstein distances within each branch of this tree structure.

Then the compact form:

FW_point = argmin_p sum_i ||point_i - p|| (geometric median); TSW_distance = sum_branches W_1(branch_A, branch_B)

Every symbol:

pa candidate pivot point in space
point_ithe i-th data point
||point_i - p||Euclidean distance (straight-line distance in space)
sum_isumming over all points
branch_A, branch_Bthe points assigned to each branch
W_1(·,·)1-dimensional Wasserstein distance
A tiny worked example
Suppose you have 4 points in 2D: (0,0), (1,0), (0,1), (2,2).
Random pivot at (0.5, 0.5): branches become imbalanced, spatial meaning unclear.
Geometric median is closer to (0,0), (1,0), (0,1) than to (2,2) — e.g., median ~(0.5, 0.3).
Using median: points (0,0), (1,0), (0,1) stay in one branch (dense cluster), (2,2) in its own branch.
Tree now separates the tight cluster from the outlier — the tree distance respects this spatial separation.

The tree structure built by geometric medians encodes where points cluster densely, so the tree distance reflects true spatial arrangement.

What can go wrong

What can go wrong

High dimensions with few samples If the number of data points is much smaller than the number of dimensions, geometric medians can become unstable or computationally noisy, because the median is solving a high-dimensional optimization with sparse data.
Pathological geometric distributions If all points lie on a thin manifold (e.g., a curve or surface embedded in high-dimensional space), the geometric median may sit off the manifold, and tree partitions fail to respect the true structure.
Multiple disconnected clusters far apart If clusters are extremely separated, a single geometric median may sit in empty space between them, making the tree partition less informative than choosing a random split in such extreme cases.
Done right When data has natural spatial structure and you have enough samples to estimate the geometric median reliably, the tree captures neighborhoods and the distance is both fast and geometrically faithful.
What a runnable demo should prove

What a runnable demo should prove

Build a simple test where you generate two probability distributions: one clustered (e.g., two tight Gaussian blobs far apart) and one uniform (spread evenly). Measure the distance using standard Sliced Wasserstein, standard Tree-Sliced Wasserstein with random pivots, and the new Fermat-Weber Tree-Sliced Wasserstein. The demo should show that FW-TSW gives higher distance between the clustered and uniform distributions (detecting the difference in structure), while random-pivot TSW and Sliced Wasserstein treat them as more similar (missing the structural difference).

distance_score = FW_TSW(clustered_dist, uniform_dist) - SW(clustered_dist, uniform_dist); higher score means FW-TSW is better at detecting structural differences

The key observation: when data has natural spatial neighborhoods, using geometric medians as pivots makes the distance metric sensitive to which regions are dense and which are sparse — something Sliced Wasserstein completely ignores.
