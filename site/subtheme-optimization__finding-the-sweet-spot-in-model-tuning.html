Finding the sweet spot in model tuning

Modern large models need fine-tuning to new tasks, but this is expensive. Papers ask: how can you adapt models with fewer computations and memory without losing quality?

All themesField mapMathematicsAll explainers
What this is

You have a large language model trained on general text, but you need it to work on medical documents or to follow your company's style. Retraining from scratch on your data costs millions of dollars and takes weeks. So instead you do fine-tuning: you take the pretrained model and retrain it on your specific data, but you use a tiny learning rate so the base knowledge stays intact while the top layers adapt. The problem is that even fine-tuning is expensive—you still need to store and update millions of numbers for every example, and memory fills up quickly.

The challenge is to squeeze quality out of fewer computations and less memory. If you only update a few of the numbers inside the model, training is fast but the model does not adapt well. If you update everything, quality is good but you run out of memory. If you want both—fast adaptation and quality results—you need to be selective: identify which parts of the model matter most, or find a clever way to represent changes so you store less data. You also need to know when to stop: train too little and the model is useless, train too much and it forgets what it learned before.

Papers tackle this with methods like low-rank updates (store the change to the model as a product of two small matrices instead of one big one, saving memory), adapter modules (plug small trainable layers into the model and leave the base untouched), and pruning (identify which numbers in the model matter and update only those). Others study the math of learning rates and stopping times: at what point do the model's predictions stop improving? Some papers combine fine-tuning with distillation—train a smaller student model that mimics the large model's predictions, so you deploy something fast. The insight is that small targeted changes can adapt a model as well as retraining everything, if you pick the right targets.

How the work breaks down

Fine-tuning large models is expensive, so researchers attack the problem from five directions: cutting memory by storing changes as small matrices instead of large ones, cleaning training data before even starting, moving hyperparameters from one model size to another to avoid retuning, designing optimizers with language models instead of by hand, and picking learning rates that actually work per layer. Each direction cuts a different corner of the cost puzzle.

Memory-efficient selective updates

Fine-tuning a billion-parameter model uses enormous memory because you need to store gradients (the direction to change each number) for every single parameter. The problem is that you do not need to change every parameter equally. Some parts of the model matter far more than others. So researchers ask: can you update only a fraction of the model, or encode the changes compactly, so training fits in memory?

CurvZO solves this by looking at which dimensions (the individual numbers in the model) have the biggest effect on the loss (the error you are trying to fix). It updates only those high-impact dimensions using zeroth-order optimization (a technique that estimates directions by probing the loss, not by computing full gradients). On OPT and Llama models, this cuts fine-tuning accuracy loss from 4.4 percentage points down to near zero, cuts runtime in half, and keeps memory low. Arbitrary-Order Block SignSGD takes a different angle: instead of storing full precision numbers for gradients, it compresses them to single-bit signs and groups them into blocks, which slashes storage. On Qwen3-8B and Llama3-8B, this converges faster per step and beats standard methods in downstream tasks. LMAO (Three Forward, One Backward) goes further by doing extra forward passes through the model instead of storing backward pass data. Forward passes only keep the layer outputs in memory (which are the numbers each layer produces), whereas backward passes store gradients for every weight, so forward passes use far less memory than storing backwards data. This trades computation time for memory—useful when you are memory-bound but have compute budget left.

Data cleaning before training

A model learns from the examples you feed it. If those examples contain noise, mistakes, or bad labels, the model learns noise instead of signal. Cleaning data before training costs time upfront but saves effort downstream because the model trains faster and learns better.

Explainable Token-level Noise Filtering shows that you can automatically find bad tokens (individual words or subwords) in your training data by using a simple scoring method. When these bad tokens are removed, downstream performance jumps up to 13.7 percentage points higher on math, code, and medicine tasks across seven mainstream language models. This is not about removing whole bad examples—it is about surgical removal of single corrupted tokens within otherwise good examples, which preserves signal while removing just the static.

Moving hyperparameters across model sizes

When you train a small model and then scale it to a larger model, do the same learning rates, batch sizes, and update schedules work? Normally you have to tune them all over again on the large model, which is expensive. The question is whether you can transfer hyperparameters from small to large, or derive a formula so you only tune once.

Hyperparameter Transfer with Mixture-of-Expert Layers proves that transfer is possible and builds it with expert layers (different sets of trained functions) for different scales. On models from 51M to 2B parameters, hyperparameters that work on small models transfer reliably to large models even on longer training. Completed Hyperparameter Transfer across Modules, Width, Depth, Batch and Duration goes wider—it tests whether transfer works when you change the model's width (neurons per layer), depth (number of layers), batch size (examples per step), and training length. It does work layer-by-layer, and the authors offer a simpler parameterization that reduces the search space without hurting quality. mu-P scaling small models establishes the theory: upscaled models are functionally equivalent to their small versions under zero perturbation, so hyperparameter transfer is not magic—it follows from the math. Hyperparameter Transfer Laws for Non-Recurrent Multi-Path Neural Networks unifies transfer across CNNs, ResNets, and stacked sequence-to-sequence networks with a shared scaling law, showing the principle holds across very different architectures.

LLM-designed optimizers and heuristics

Designing an optimizer by hand is slow: you write equations, test them, try variants. What if you asked a language model to write the optimizer for you? Or design a heuristic algorithm for a specific problem? Language models learn from seeing millions of code examples and algorithm descriptions, so they absorb implicit patterns about what works. When you ask them to generate a new algorithm, they recombine these patterns in ways that often work, sometimes better than hand-designed rules because they escape the biases of human designers.

Generalizable Heuristic Generation Through LLMs with Meta-Optimization (MoH) constructs meta-optimizers by having language models write heuristics for combinatorial optimization problems (like traveling salesman). These learned heuristics generalize to larger problem sizes than they saw during training, beating standard hand-tuned approaches. HiFo-Prompt (Prompting with Hindsight and Foresight for LLM-based Automatic Heuristic Design) improves this by prompting the language model with both past solutions (hindsight) and predicted futures (foresight). This context helps the model learn what led to success in the past and what future states to avoid, so it writes heuristics that converge faster and better than earlier methods for automatically designing heuristics. Refining Hybrid Genetic Search for CVRP via Reinforcement Learning-Finetuned LLM takes the idea further by fine-tuning a language model on examples of good crossover operators (the operations that blend two solutions in genetic algorithms). The fine-tuned model generates operators that exceed expert hand-written designs on vehicle routing problems up to 1000 nodes, even beating GPT-4o. CALM Before the STORM and CALM: Co-evolution of Algorithms and Language Model for Automatic Heuristic Design show that directly fine-tuning language models on written optimization solutions can help simple cases but hurt harder ones. This happens because overfitting to simple solutions causes the model to miss the deeper patterns that hard problems need, suggesting that this is a subtle fit problem. CALM itself solves this by co-evolving the algorithm and the language model together, which forces them to adapt to each other. It runs on a single GPU with a 7-billion-parameter model that uses less memory, and beats existing baselines on optimization tasks.

Learning rate tuning and scheduling

The learning rate controls how much to change each parameter after each step. If it is too high, the model overshoots and gets worse. If it is too low, training is slow and might not converge. The challenge is that different layers in the model learn at different speeds, and the right rate changes over time as training progresses.

Seesaw: Accelerating Training by Balancing Batch Size and Learning Rate Scheduling shows you can adjust batch size and learning rate together to match standard decay schedules (where the rate gets smaller over time) in quality but cut wall-clock time by 36 percent on 150M–600M models, getting close to theoretical limits. One LR Doesn't Fit All: Heavy-Tail Guided Layerwise Learning Rates for LLMs proves that different layers need different rates: it assigns higher learning rates to layers that change more during training (detected by how much their gradient updates vary). Layers that change a lot need higher rates to keep up with the learning signal, whereas stable layers only need small tweaks. This achieves 1.5x speedup and pushes zero-shot accuracy from 47.09% to 49.02% on 1B models with minimal tuning overhead. WSM: Decay-Free Learning Rate Schedule via Checkpoint Merging for LLM Pre-training proposes a schedule that merges checkpoints instead of using decay, and beats the standard Warmup-Stable-Decay on MATH (+3.5%), HumanEval (+2.9%), and MMLU-Pro (+5.5%). Cautious Weight Decay modifies weight decay (a penalty that pushes all parameters toward zero) to be more careful about when to apply it, improving both language model pretraining and ImageNet classification at billion-parameter scales. Weight Decay Improves Language Model Plasticity shows a counterintuitive result: larger weight decay during pretraining makes the model more adaptable to new tasks during fine-tuning. The reason is that weight decay eliminates weak, specialized connections and keeps only the general-purpose ones. A model with only strong general connections can be fine-tuned more easily because the strong base connections can absorb new task-specific information without interference, whereas a dense model with many weak specialized connections resists change and struggles to reuse its overfitted knowledge for a new task. This means lower-performing base models sometimes adapt better after fine-tuning when they were pretrained with high weight decay, because a weaker but cleaner foundation is easier to build on than a strong but specialized one. Weight Decay may matter more than muP for Learning Rate Transfer in Practice reveals that the weight decay schedule is often more important than the learning rate transfer formula itself for moving hyperparameters across scales. Weight decay determines which connections survive during pretraining, fundamentally reshaping which parts of the model are adaptable, and this effect scales differently with model size than learning rate does, so getting the decay schedule right matters more for successful transfer.
