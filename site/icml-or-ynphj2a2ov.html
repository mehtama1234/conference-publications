Learning to Explore: Scaling Agentic Reasoning via Exploration-Aware Policy Optimization

Teach an interactive reasoning system to explore only when uncertainty is high, so it gathers missing facts without wasting steps once the task is already clear.

Paper explainersAll themesAgents & Tool Use

Interactive reasoning systems can act before answering: they can inspect the environment, open menus, read pages, and test hypotheses. That freedom helps on hard tasks because some tasks cannot be solved until the system gathers extra facts, but it can also waste time because some tasks are already clear after one or two observations. A baseline that explores on every task spends many actions looking for information that it already has. This paper trains the policy to separate exploratory actions from execution actions. It rewards exploration when the action is likely to reduce uncertainty and stops rewarding it once the task state is clear. The result is a system that searches when information is missing and switches to execution as soon as the useful facts have been collected.

Zero assumption version

Why always exploring is wasteful

On many tasks, an interactive system must decide whether to search for more information or act now. A naive strategy uses the same amount of exploration everywhere. That is inefficient because some tasks are already clear after one observation, while others remain ambiguous until the system inspects several sources.

Uniform exploration also harms training. If the reward does not distinguish useful information gathering from needless wandering, the learned policy cannot tell when one more action is worth paying for. The system either becomes timid and under-explores or becomes restless and keeps searching after the answer is already available.

The paper's move. Reward exploration only when it is expected to reduce uncertainty, because good exploration closes an information gap and bad exploration just burns steps.

The algorithm as a flow

What it actually does

Roll out interactive trajectories.

Let the policy gather observations and act in the environment so training can see both good and bad search behavior.

Mark exploratory actions separately.

Group actions that gather information apart from actions that directly complete the task because their value should be measured differently.

Estimate information gain.

Give a reward to an exploratory action when it is expected to improve later decisions by reducing uncertainty.

Optimize the policy with grouped rewards.

Update the policy using separate signals for search and execution so each behavior is reinforced for the right reason.

Switch to execution when clear.

Once the task state is understood, stop exploring and carry out the needed actions so the system does not waste steps.

What the paper changes

What the paper changes

The paper changes the reinforcement-learning objective from one undifferentiated action reward into a reward that treats information gathering and task completion as different types of behavior.

the object it moves  =  the training reward over interactive action sequences
The hidden quantity

The hidden quantity

measured quantity  =  decision uncertainty at the current state

The key hidden quantity is whether the system truly lacks enough information to choose the next action well. You cannot inspect that quantity directly. You only observe symptoms such as hesitation, contradictory evidence, or a wide spread over plausible next actions.

The paper tries to estimate this hidden uncertainty and use it to score exploration. An exploratory action is valuable when it narrows the set of plausible next moves, because that makes future execution more accurate and more direct.

Why it works

Why this works

Search is beneficial only when it changes what the system should do next. If a page click, an inspection, or an environmental probe reveals a missing fact, then the exploratory step earns its keep because the next decision can be better informed. If the same action adds nothing, it is just delay.

By separating exploratory actions from execution actions during optimization, the method avoids mixing two incompatible goals into one signal. Exploration should be rewarded for reducing uncertainty, while execution should be rewarded for completing the task efficiently. That separation produces cleaner learning pressure because each behavior is judged on the role it is supposed to play.

The variational reward matters because it approximates future usefulness instead of scoring exploration only by immediate outcomes. An exploratory step can be good even before the final answer is known, provided it makes later decisions easier or safer.

Math after the picture

Reward search by uncertainty reduction

First in words:

A simple summary is to give exploratory actions credit when they reduce uncertainty about the next decision, while still adding the normal task-completion reward.

Then the compact form:

score(trajectory) = task_reward(trajectory) + lambda * sum(explore_gain_t)

Every symbol:

trajectoryone full interactive run in the environment
task_reward(trajectory)the reward for finishing the task correctly and efficiently
explore_gain_tthe value of the exploratory action at step t, measured by how much it reduces uncertainty for later decisions
lambdathe weight placed on useful exploration during training
A tiny worked example
Run A explores twice, but only the first search reveals a missing setting.
Suppose task reward is 8, and the two search gains are 3 and 0.
With lambda = 1, Run A scores 8 + 3 + 0 = 11.
Run B explores once, reveals nothing, and gets the same task reward 8.
Run B scores 8 + 0 = 8, so training prefers the search behavior that actually reduced uncertainty.

The full paper uses a more detailed reinforcement-learning objective, but this equation captures its main idea: exploration is good when it teaches the policy something useful for later action.

What can go wrong

What can go wrong

Uncertainty estimates can be noisy. If the training signal misjudges whether the state is ambiguous, then the policy may stop too early or keep exploring too long because the search reward is pointed at the wrong states.
Exploration labels can be too coarse. Some actions both gather information and move the task forward, so a rigid grouping rule can mis-score them because it forces one action into only one category.
Search reward can overshadow task completion. If lambda is too large, the policy may learn to chase information gain even when the task is already solvable because the training objective overpays for more searching.
Done right. The framework works when uncertainty estimates are calibrated and the search reward is balanced, because then the policy explores where the information gap is real and acts quickly elsewhere.
What a runnable demo should prove

What a runnable demo should prove

Build a small web or text environment where some tasks are obvious after one observation and others require a few searches. Train one policy with a standard task reward and another with the exploration-aware grouped reward. Instrument the environment so you can count when search actions reveal previously missing facts and when later search actions reveal nothing new.

The demo should show that the exploration-aware policy takes more useful searches early on ambiguous tasks and fewer wasted searches on clear tasks, because the reward explicitly values uncertainty reduction instead of raw motion.

useful_search_rate = searches_that_reduce_uncertainty / total_searches

A convincing demo must show that selective exploration improves both task success and step efficiency, because the policy learns to search for information rather than search by habit.
