ATLAS: Learning to Optimally Memorize the Context at Test Time

A recurrent memory module that learns to compress and update context words when answering a new question, instead of just stacking them all until they overflow.

Paper explainersAll themesTime Series & Sequential

The most popular sequence models attend to every past word, but this gets impossibly slow and memory-hungry as sequences grow. Recurrent models use a fixed-memory slot to summarize the past, avoiding that explosion—but they often forget important details because they update that summary one word at a time, myopically, without planning ahead. Atlas is a memory module that rewrites its summary by looking at all the words it has seen so far, not just reacting to the last one.

Zero assumption version

Why recurrent models forget details

The most popular models pay full attention to every past word, which works beautifully for understanding context—but the cost grows as the square of sequence length. For a sequence of 10,000 words, the model needs to compute 100 million attention pairings. For a million-word document, it is hopeless.

Recurrent models avoid this explosion by keeping a single memory slot (a fixed list of numbers) that summarizes everything seen so far. At each step, the model reads the new word and updates that summary. The problem: this update is purely local. The model only looks at the current word and the current memory state; it cannot step back and ask what was actually important to remember. If an important detail arrived early and has not been mentioned since, the model might accidentally delete it to make room for recent noise.

Researchers have tried to give recurrent models bigger memories, but a bigger slot still gets filled one word at a time, online, without foresight. Nothing fundamentally changes until the memory management itself becomes smarter.

In one sentence. Instead of updating memory only with the current word, rewrite the entire memory by looking back at all past words and deciding what to keep.

The algorithm as a flow

What it actually does

Collect all words so far

At each time step, gather every word seen from start to now.

Compute importance of each word

Score how much each past word should influence the new memory.

Select key words to remember

Pick words with highest importance; drop the rest.

Rewrite the memory

Combine selected words into a compressed summary.

Continue to next word

Next input uses this rewritten memory, not just the old one.

What the paper changes

What the paper changes

The paper replaces the simple one-step memory update rule (take old memory, add new word) with a full rewrite step: inspect all past words, score each one for relevance, keep only the important ones, and compress them into a new memory. This is done not just once at the end, but at every step as the model reads forward.

the object it moves  =  memory update rule
The hidden quantity

Token importance: which words matter for the future

measured quantity  =  importance score per word

Token importance is a single number per word saying how much that word will affect the model's future answers. If a word is about a critical plot point or a key fact, it gets a high score. If it is filler noise, it gets a low score.

The paper learns to estimate this score by looking at how much the memory changes when that word is added. Tokens that cause big, stable changes to the memory are important; words that barely touch it are noise. By ranking words this way, the model can decide which ones fit into the fixed memory slot and which can be dropped.

Why it works

Why rewriting memory at every step fixes the forgetting problem

A standard recurrent model updates memory purely by examining the new word and the old memory. If a word was important but arrived five steps ago, and nothing has triggered it since, the model has no way to know it is still critical. The update step cannot reach back to rescue it.

Atlas breaks this trap by regularly stepping back and re-examining the full sequence history. At each rewrite, it asks: which of the words I have seen are truly important for answering future questions? It can now resurrect a buried detail that a myopic online update would have erased. The rewrite is based on learned importance scores, so the model trains on where those scores should point—because if importance scores misrank a word (say, marking noise as important and a key fact as unimportant), the rewrite will produce a worse memory, and the prediction error will flow back to those scores as learning feedback. Over time, it learns which words matter for the downstream task.

The key win: the rewrite process is differentiable (the model can learn to improve importance scores during training by computing which direction to nudge each score), so importance scores improve. The model learns to value words for the right reasons, not by accident. And critically, rewriting does not require storing all words—it is done in a fixed-size memory, so the cost grows linearly with sequence length and stays tractable even for very long texts.

Math after the picture

The memory rewrite equation

First in words:

new memory equals sum over all past words of (importance score times word vector), divided by total importance, all passed through a learned compression function

Then the compact form:

m_t = compress(sum_i importance_i * word_i / sum_i importance_i)

Every symbol:

m_tthe memory vector at step t (a fixed list of numbers)
word_ithe i-th word from the start, as a vector
importance_ilearned score for how much word i matters (0 to 1)
compressa small neural network that squeezes the sum into the fixed memory size
sum_iadd up over all past words from the start to now
A tiny worked example
Suppose we have 4 past words: detail (vector [1,0]), filler (vector [0,1]), fact (vector [1,1]), noise (vector [0,0]).
Importance scores learned by the model: detail=0.8, filler=0.1, fact=0.9, noise=0.05.
Weighted sum: 0.8*[1,0] + 0.1*[0,1] + 0.9*[1,1] + 0.05*[0,0] = [0.8,0] + [0,0.1] + [0.9,0.9] + [0,0] = [1.7, 1.0].
Total importance: 0.8 + 0.1 + 0.9 + 0.05 = 1.85.
Normalized: [1.7, 1.0] / 1.85 = [0.92, 0.54].
Pass through compress network to fit memory slot size, e.g., [0.92, 0.54] -> [0.8]. Result: a single number summarizing all four words, weighted by their learned importance.

The equation is a weighted average of all words, where the weights are importance scores learned during training. The compress function adapts this average to fit the fixed memory size.

What can go wrong

What can go wrong

Importance scores are overconfident early. If the model trains on short sequences, it learns to rank words based only on what mattered for those lengths. When given a much longer sequence, it may over-prune words it has never seen tested at scale, leading to information loss.
Memory rewrite cost per word can add up. Every step requires scoring all past words and rewriting memory. For truly massive sequences (millions of words), this is cheaper than comparing every word to every other word (quadratic cost), because scoring and rewriting take linear time in the number of words—but the cost of both scoring and rewriting at every step still means the total wall-clock time is not negligible for extremely long sequences.
Learned importance can be brittle across domains. If the model learns importance weights on one type of text (e.g., news articles) and is then used on a completely different text type (e.g., source code), the importance scores may not transfer well, and early words may be dropped incorrectly.
Done right: train on a diverse mix of sequence lengths and domains. This forces importance scores to remain stable across different sequence types and to preserve words that matter across many different downstream tasks.
What a runnable demo should prove

What a runnable demo should prove

A demo should show that Atlas can correctly answer questions about details from the distant past—facts mentioned 5,000 words ago in a 10,000-word article. Measure this by asking the model direct recall questions ("Who did the speaker mention in the first paragraph?") and indirect reasoning questions ("What did the speaker say in the intro, and how does that change your understanding of what happened later?"). Compare against a standard recurrent model and a transformer on the same questions. Plot accuracy (fraction of correct answers) as a function of distance from the question back to the relevant detail. Atlas should stay flat (high accuracy everywhere); the baseline recurrent should drop steeply for distant facts.

recall_accuracy = number of questions with correct answer / total questions, computed separately for 'detail is recent' vs 'detail is ancient'

The demo must make it impossible to miss: Atlas remembers early facts as reliably as recent ones, whereas a standard recurrent forgets them. That is the whole point.
