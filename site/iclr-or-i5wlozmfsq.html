Embodied-R1: Pointing as a Bridge from Vision to Robot Action

A robot learns to close the gap between seeing a scene and knowing what to do by thinking in terms of pointing at target locations.

Paper explainersAll themesRobotics & Control

A robot watching a video of a person picking up a cup knows what happened, but a robot trying to mimic that same person gets stuck: the same scene, the same motion, but the robot has a different body with different joints and limits. Embodied-R1 solves this by teaching robots to think in a universal language—pointing—that works across all robot shapes. It trains a vision-language model (a neural network that reads images and understands text instructions) using reward signals, so the model learns to point accurately to where the robot should move or grasp, because the reward function immediately tells the model whether each predicted point was correct or wrong, and the model adjusts its internal numbers (called parameters—the values that control how the network decides what to output) to increase the score on the next attempt.

Zero assumption version

Why robots struggle to copy humans

A robot arm with 6 joints works differently than a humanoid robot with legs. When you show both robots a video of a person grasping a mug, they see the same image, but their bodies cannot do the same motion. The robot arm's grip is at the end of a metal stick; a humanoid's hand is attached to a shoulder and elbow. Their action spaces do not match.

Today's best robot models train on one robot body. When you move them to a different robot, they fail catastrophically—like asking a person trained only to throw left-handed to suddenly throw right-handed. Data is also scarce: teaching a robot to manipulate takes hundreds of hours of robot time, which is expensive. If models do not transfer, you need hundreds of hours per robot.

The seeing-to-doing gap. The robot sees the scene clearly, but its body cannot easily translate what it sees into action, because its embodiment (its physical form) is different from the one in the training data.

The algorithm as a flow

What it actually does

Stage 1: Teach spatial reasoning

The model learns to understand *where* objects are in a scene and how they relate to one another.

Stage 2: Teach pointing abilities

The model learns four forms of pointing: marking object locations, targeting goal locations, measuring distances, and reasoning aloud before pointing.

Reward signal tells the model when pointing is right

Four separate reward channels score the pointing: Is the right object marked? Does the point sit in the goal mask? Is the distance estimate close? Is the reasoning clear?

Balanced training across tasks

The model trains on mix of tasks simultaneously. Each task's total reward is scaled to 0-1, so simple tasks do not drown out harder ones.

The model internalizes pointing as its action language

The robot no longer tries to predict joint angles directly. It points, and the downstream controller turns pointing into motion.

What the paper changes

The one thing the paper changes

Instead of predicting robot joint angles or low-level motor commands directly, the model predicts coordinates in 3D space—the exact location the robot should reach or grasp.

the object it moves  =  action representation: from joint angles to spatial points
The hidden quantity

The pointing accuracy: how well the model targets the right location

measured quantity  =  pointing accuracy

The paper measures how close the model's predicted point lands to the true target location (in pixels and in real 3D space). This is the core quantity that must improve for the robot to generalize, because a model that points accurately in diverse training scenarios will predict points that work on new, unseen robot bodies and tasks—the same pointing coordinates are valid regardless of which robot is executing them.

The model estimates this quantity during training via four reward signals working in parallel: pixel-level mask accuracy (is the point inside the goal region?), point distance error (how many centimeters off?), object localization (did it find the right thing to grasp?), and reasoning quality (did the model explain its thinking?). Each reward produces a score from 0 to 1. The sum of these four scores tells the training algorithm whether the model is pointing accurately.

Why it works

Why pointing fixes the embodiment mismatch

The core insight is *indirection*. Instead of the model predicting what the robot's joints should do, the model points to a location in space, and a separate low-level controller solves the inverse kinematics problem (converting a target point into joint angles). This solves two problems at once.

First, a point in 3D space is the same for any robot. An arm and a humanoid both understand 'grasp at this coordinate' even though their bodies move differently. The model learns a universal language.

Second, by training with reward signals—not just copying human demonstrations—the model is forced to find the pointing strategy that actually works. If it points at the wrong spot, the reward drops immediately. The training uses a technique called reinforced fine-tuning: the model generates candidate pointings, gets scored by the reward function, and learns which predictions led to high scores. This is more flexible than imitation learning (copying examples), because the model can discover pointing strategies that humans never demonstrated but that work for the robot's body.

Math after the picture

Balancing rewards across tasks

First in words:

Total reward is the weighted sum of four independent reward channels, each scaled to 0-1 to prevent simple tasks from dominating harder ones.

Then the compact form:

R_total = sum_i w_i * r_i, where each r_i in [0, 1]

Every symbol:

R_totalthe combined score for one training step
r_ithe score from reward channel i (mask accuracy, distance error, object found, reasoning quality)
w_ithe weight (importance) of that reward channel
[0, 1]each individual reward is clipped to this range before combining
A tiny worked example
Suppose the model predicts a point. Four rewards are computed:
- mask accuracy (is point in goal region?): 0.9
- distance error (how close to true target?): 0.7
- object localization (found the right handle?): 1.0
- reasoning quality (did it explain itself?): 0.5
If all weights are equal (0.25 each), total = 0.25*0.9 + 0.25*0.7 + 0.25*1.0 + 0.25*0.5 = 0.225 + 0.175 + 0.25 + 0.125 = 0.775
This 0.775 score propagates backward through the model, pushing it to improve the weakest channel (reasoning, at 0.5). On the next iteration, the model re-reasons and tries to raise that score. No single reward drowns out the others.

The balanced reward prevents simple tasks like 'mark the object' from being solved perfectly while harder tasks like 'predict object affordances' stay unsolved.

What can go wrong

What can go wrong

Imbalanced rewards during mixed training. If one task's reward is not normalized to 0-1, it can dominate training. For example, if affordance detection produces rewards in the range 0-100 while object localization produces 0-1, the model will ignore the latter. The paper prevents this by explicitly constraining each task's total reward to [0, 1].
Pointing in the wrong coordinate frame. If the 3D points are predicted in camera coordinates but the robot operates in world coordinates, the pointing will miss by a fixed offset every time. The paper uses consistent coordinate frames and interpolates predicted points into SE(3) trajectories (smooth paths in both position and rotation).
Sparse spatial reasoning data. If the model has never seen examples of reasoning about object relationships in a training set, it cannot learn to reason about them. The paper addresses this with a dedicated first-stage curriculum on spatial reasoning datasets (Embodied-Spatial-84K).
Done right: clear task separation and staged training. By training spatial reasoning first, then adding pointing with balanced rewards, the model builds an intermediate representation that works reliably across different tasks and robot bodies. This creates a clear separation of concerns: the model focuses on one skill at a time.
What a runnable demo should prove

What a runnable demo should prove

Build a small simulator with two robot arms: a simple three-joint arm and a more complex five-joint arm. Load the trained Embodied-R1 model. Give it an instruction like 'place the cube on the shelf at coordinates (0.3, 0.5, 0.8).' The model should predict a point in 3D space, and a standard inverse kinematics solver (a tool that converts target points into joint angles) should make both arms move to that location. Then, swap in a completely new robot body (different link lengths, different joint limits), load the same trained model, and run the same instruction. The model should still produce valid points, and the new robot should still reach the target. The key metric is success rate: what fraction of instructions lead to the robot reaching the target within 5 centimeters?

success_rate = (number of instructions where robot reached target within tolerance) / (total instructions)

The demo proves that the model has learned a robot-agnostic pointing language, not a robot-specific motion plan. New robot types succeed without retraining, because they speak pointing.
