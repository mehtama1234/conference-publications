Formalizing Learning from Language Feedback with Provable Guarantees

Turn language feedback into a formal learning problem and show when it can teach an agent faster than reward alone.

Paper explainersAll themesAgents & Tool Use

People often guide an agent with sentences instead of numeric rewards. They say what went wrong, what to try next, or which feature of the outcome matters. That form of teaching can be richer than a bare success score, but it is hard to reason about mathematically because the reward signal is hidden behind language. This paper formalizes that setting as Learning from Language Feedback, identifies assumptions that make learning possible, and gives an algorithm with regret guarantees tied to a new measure of problem hardness.

Why language guidance needs a formal learning view

A reward signal tells an agent whether an outcome was good or bad, but it may say little about why. Language feedback can add that missing structure because a teacher can point to the mistaken choice, state the desired property, or explain a rule that should hold next time. Earlier studies report gains from this kind of guidance, yet without a formal setup it is difficult to know when learning should succeed or how sample requirements scale.

The difficulty is that the true reward remains hidden. The agent hears sentences that only partially reveal what the teacher values. To learn well, the system needs assumptions connecting language to reward-relevant structure. The paper provides that framing so that learning from language can be analyzed instead of treated only as an observed trick.

The paper's move in one sentence. Define a formal decision problem where language feedback reveals information about hidden reward, measure its hardness with transfer eluder dimension, and prove that HELiX learns with no regret under these assumptions.

What it actually does

Define sequential decision making where the agent receives observations plus language feedback that is related to a hidden reward rule.

State learnability assumptions

Specify conditions under which the language reveals enough information so that the hidden reward can be learned over time.

Measure problem hardness

Compare language guidance with reward-only learning

The hidden quantity

Reward uncertainty under language guidance

measured quantity  =  How much uncertainty about the hidden reward remains after each feedback message

The hidden quantity is the remaining uncertainty about the true reward rule. A plain reward score may shrink that uncertainty slowly because it only says whether the overall outcome was good. A sentence can shrink it faster because it can reveal which part of the choice mattered and under what condition.

The theory captures this through problem hardness. If one piece of feedback rules out many incorrect reward explanations, then the agent can learn quickly. If each message is vague, learning slows because too many possibilities remain consistent with the observations.

Why it works

Why this works

Language feedback can beat reward-only learning when each message carries structured information about the source of success or failure. Instead of receiving one number, the agent gets a constraint on what the reward rule must value. That can remove many wrong hypotheses at once, which reduces future mistakes because fewer bad options remain plausible.

HELiX makes this useful by maintaining a representation of plausible reward rules and updating it after each interaction. The regret guarantee follows because the algorithm only keeps choices that remain consistent with the feedback assumptions, so uncertainty shrinks as informative messages accumulate.

Math after the picture

The regret statement in plain form

First in words:

Regret grows with task hardness and with how long the agent keeps uncertainty about the hidden reward. Informative language reduces that uncertainty more quickly, so cumulative regret can be much smaller than with reward alone.

Then the compact form:

Regret(T) <= C * sqrt(T * d_transfer)

Every symbol:

Regret(T)total performance lost after T interaction rounds compared with the best strategy that knows the true reward
Tnumber of sequential interaction rounds
d_transfertransfer eluder dimension, a measure of how hard it is to identify the right reward structure from feedback across related tasks
Ca problem-dependent constant that absorbs bounded feedback and action terms
A tiny worked example
Suppose one family of tasks has d_transfer = 4 because each feedback message rules out many wrong reward explanations.
A harder family has d_transfer = 25 because the messages are less informative across tasks.
Take T = 100 and C = 1 for illustration.
Then the easier family gives Regret(100) <= sqrt(100 * 4) = 20.
The harder family gives Regret(100) <= sqrt(100 * 25) = 50.
The second family is harder because each round removes less uncertainty about what the teacher values.
This matches the paper's claim that richer, more transferable language feedback can accelerate learning sharply.

The full theory includes more detail, but this bound captures the central message: learning speed depends on how informative language is about hidden reward structure.

What can go wrong

What can go wrong

Feedback may be too vague. If language does not constrain the hidden reward clearly, the theory's faster learning benefits shrink because the agent cannot eliminate many wrong hypotheses.
Assumptions may miss real teacher behavior. Humans can give inconsistent or incomplete advice, so practical performance may fall when the feedback process violates the formal setup.
Transfer structure may be weak. If tasks do not share useful reward regularities, then transfer eluder dimension grows and learning slows because past feedback helps less on future tasks.
Done right. Use language feedback that points to reward-relevant structure and pair it with a learner that updates explicit uncertainty over plausible reward rules.
What a runnable demo should prove

What a runnable demo should prove

Build a simple sequential choice game with hidden reward rules. Let one learner receive only a success score and let another receive short language messages explaining why the choice was poor or good. Keep the task family structured so that the same kinds of explanations help across rounds. Track regret and the number of rounds needed to reach strong decisions.

The demo should show that language can reduce trial count because one message can reveal which feature of the action matters, while a plain reward score leaves the learner to discover that structure slowly.
