Watermark-based Attribution of AI-Generated Content

Assign each user a unique watermark so you can trace an AI-generated image or text back to which user made it.

Paper explainersAll themesAlignment, Safety & Fairness

AI companies embed invisible marks in generated content to prove it is fake. But if two users both use the same service, how do you know which user created a specific piece? This paper solves that by giving each user their own unique watermark. When someone suspects AI-generated content, they can check whose watermark is inside it.

Zero assumption version

Why tracing AI content back to a person matters

Right now, AI companies add watermarks to their outputs to flag fake content. But this only answers one question: Is it AI-made? It does not answer: Which person used the AI service to make this?

Imagine a company's AI image generator creates a deepfake or misinformation. A watermark says it is AI-made, but maybe thousands of employees use that service. Without knowing which employee, you cannot hold anyone accountable. A beginner might try using the same watermark for all users and just checking if it is there, but then you have no idea whose hands created the content—every user looks the same.

In one sentence. Give each user a different watermark so the watermark itself tells you who made it.

What the paper changes

The single change: unique marks per user

The paper changes who gets which watermark. Instead of one watermark for the whole service, it assigns a distinct watermark to each user. That is the lever; everything else follows from it.

the object it moves  =  user-specific watermarks
The hidden quantity

The hidden quantity: attribution accuracy

measured quantity  =  fraction of calls where the right user is chosen

The paper measures one core quantity: attribution accuracy, or the fraction of times the system correctly picks the true creator. When you extract a watermark from suspicious content and rank all users by how well their watermark matches, the true creator should rank first almost every time.

The paper estimates this by theoretical analysis: it derives the mathematical lower bounds—the worst-case floor of accuracy you can achieve with any choice of watermarks—using probabilistic reasoning. Then it picks watermarks to maximize those bounds.

Why it works

Why unique watermarks let you identify the creator

The trick rests on a simple idea: if everyone has the same mark, the mark cannot tell people apart. Watermarks work by hiding a signal inside an image or text in a way that survives small changes—a JPEG compression, a crop, a color shift. If the hidden signal is the same for Alice and Bob, then extracting it tells you AI-generated content exists, but not whose hands made it.

But if Alice's watermark is mathematically different from Bob's—say Alice's pattern emphasizes certain noise frequencies while Bob's emphasizes others—then when you pull the watermark out of a piece of content, you can measure how closely it matches each user's unique pattern. The user who matches best is almost certainly the creator, because hiding the watermark into the image happens only by one user at a time, so only their specific pattern got baked in.

The second part: how do you pick which different watermarks to use? The paper proves theoretically that some choices of watermarks are better than others, because it derives lower bounds: mathematical guarantees that say if you pick the watermarks this way, then attribution accuracy will be at least this high, no matter what small post-processing the adversary applies. The reason certain watermark choices give higher guarantees is that they maximize the gap between each user's pattern and every other user's pattern—closer spacing means more collisions and accidental false matches. Then it solves for the watermark choice that maximizes those bounds—getting the best possible accuracy under realistic attack.

Math after the picture

The scoring equation

First in words:

score for user i equals the overlap between the extracted watermark and user i's assigned watermark, penalized by how hard it was to embed

Then the compact form:

score_i = (extracted · W_i) / (embedding_cost_i)

Every symbol:

extractedthe watermark pattern we pulled out of the content
W_iuser i's assigned unique watermark pattern
·dot product: sum up the product of each corresponding element
embedding_cost_ihow much work it took to hide this watermark (lower is better)
score_ihow well this user's watermark explains what we found
A tiny worked example
Alice's watermark: [0.8, 0.6, 0.4] (strong, medium, weak).
Bob's watermark: [0.1, 0.5, 0.8] (weak, medium, strong).
Extracted from content: [0.75, 0.65, 0.35] (very similar to Alice's).
Alice score: (0.8*0.75 + 0.6*0.65 + 0.4*0.35) / 1.0 = 0.60 + 0.39 + 0.14 = 1.13.
Bob score: (0.1*0.75 + 0.5*0.65 + 0.8*0.35) / 1.0 = 0.075 + 0.325 + 0.28 = 0.68.
Alice wins with score 1.13 > 0.68, so Alice is the creator.

When the extracted watermark looks like someone's assigned pattern, their score goes up; if it looks different, their score stays low. The user with the highest score is the most likely creator.

What can go wrong

What can go wrong

Many users, overlapping patterns. If you have 10,000 users and their watermarks are not well-separated mathematically, two users' patterns may look similar by accident. When you extract a watermark, you might match the wrong person by chance. The paper addresses this by deriving the minimum separation needed and picking watermarks to keep them far apart.
Adversary knows the method. If a user learns their own watermark and tries to forge content with another user's watermark, they need to inject that pattern and remove their own. This is hard if watermarks are deeply woven into the image pixels or individual words in text. But if an attacker has unlimited time and computing power, they might succeed. The paper assumes the attacker has a limited budget of tries.
Heavy post-processing destroys all marks. If someone re-encodes the content completely—transcribing text by hand, re-rendering an image from scratch—the watermark vanishes. This is a fundamental limit; no watermarking approach can survive total reconstruction. The paper only claims the watermark survives common, light post-processing like JPEG compression.
Done right. For internal company accountability (tracing deepfakes to employees, finding leakers), watermark-based attribution works well: users cannot forge each other's watermarks without knowing exactly how the watermark was hidden (which pixels or words store the signal), and the method handles normal content sharing like screen captures or re-posting.
What a runnable demo should prove

What a runnable demo should prove

To verify watermark-based attribution works, build a tiny system: create three users, assign each a different random watermark pattern (use the paper's method to pick good separations), generate some fake images with a simple method (e.g., blend a watermark into pixel noise or patch it into hidden image channels), extract the watermark signal, and score each user. Count how many times the correct user ranks first.

attribution accuracy = number of correct matches / total attempts

The demo must show that on unmodified content you get over 90% accuracy; after JPEG compression it drops to 80% or so; and the rankings stay stable even when the extracted watermark is slightly noisy.
