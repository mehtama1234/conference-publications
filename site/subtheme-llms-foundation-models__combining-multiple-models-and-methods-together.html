Combining multiple models and methods together

These papers explore how to merge different models, combine multiple reasoning paths, and use multiple models working together to solve harder problems.

All themesField mapMathematicsAll explainers
What this is

A single model, no matter how large, has limitations—it might be good at math but weak at writing, or fast but not very accurate. Papers in this area explore merging different models so they complement each other, and combining different reasoning paths so the model can try multiple approaches and pick the best one. One technique is ensemble methods, where multiple models solve the same problem and their answers are combined by voting or averaging. Another is routing, where different problems get sent to different models optimized for those specific tasks. A third is model merging, where researchers take parameters from multiple models and combine them into a single model that tries to keep the best abilities of each.

The challenge is that combining models usually requires more computation—running five models to get one answer takes five times as much processing, which costs money and time. So papers study which combinations are worth the cost by measuring the accuracy gain against the computation cost, how to prune away redundancy to reduce wasted parallel processing, and how to route efficiently so you only run the models you need. Some papers explore mixture-of-experts architectures where a model decides which internal components to use for each input, which can be more efficient than running separate models because most examples do not need all components. The question becomes: what is the right tradeoff between accuracy and cost?

The result is systems that are more accurate and harder to break than single models because failures are caught by redundancy. In safety-critical applications, combining multiple approaches reduces the chance that a single model's failure will cause a problem because you have backups. This also mirrors how humans solve hard problems—we think about it from multiple angles and synthesize insights, not snap to an answer instantly, which is why human teams survive mistakes that would kill individuals. Papers show that thoughtful combination works better than just stacking the best parts together because diversity of approaches catches errors no single model would catch since different models make different mistakes.

How the work breaks down

The work in this subtheme splits into five directions. First, how multiple agents working together can be optimized and verified, because teams of specialized agents can cover more ground than one general model. Second, how to blend different models into one through merging, because you want one efficient model instead of running five models in parallel. Third, how ensembles and routing send queries to the right models, so you run expensive models only on hard questions to save cost. Fourth, how extra computation at test time improves answers, because sometimes thinking longer is better than thinking faster. Fifth, how watermarking and detection work across ensembles, because detecting whether text came from a model requires multiple watermarking approaches so attacks cannot erase all the signals.

Multi-agent systems and collaboration

When you have multiple language models and ask them to work together on a task, the hard part is making sure they actually share useful information and that the system gives better answers than a single model, so you need coordination and communication. You need to optimize which agents do what and how they talk to each other, because different agents excel at different skills. You must verify that their reasoning is sound and debug failures when they happen, because running multiple models creates more opportunities for things to go wrong if they are not coordinated.

Agentic Collaboration as Information Bottleneck shows that how much information models share with each other is the main predictor of whether multi-agent systems succeed, independent of what task they are solving, which means the bottleneck is communication not the models themselves. This means the key to better collaboration is better compression and communication because communication quality controls whether agents help or hinder each other. Multi-Agent Design reveals that the structure of the agent network and the quality of prompts matter enormously for building multi-agent systems that work well, which shows that architecture and wording both control outcomes. MASPO focuses on optimizing the prompts that each agent uses, finding that jointly tuning all the prompts together beats tuning them one at a time with average accuracy gains of 2.9 points across diverse tasks, so coordinated tuning beats independent tuning. MAS-ProVe studies how to verify that multi-agent reasoning is actually sound by checking the process, but finds that this does not always help as much as using a judge model that looks at the overall answer, because process-level checks can be noisy. DoVer tackles the problem of when agents fail by automatically debugging the system and proposing fixes, it can turn 18-28 percent of failed attempts into successes, because identifying and fixing the root cause is often possible even after a system breaks.

Model merging and adaptation

Model merging combines the knowledge from two or more trained models into a single model, so you get a model that keeps the best abilities of each without running multiple models in parallel and paying the cost. The challenge is that merging naively often causes the combined model to forget what each original model knew and to perform worse on tasks both models could handle separately, which means you need careful techniques. Understanding when and how to merge efficiently requires knowing how performance changes as you add more models so you can plan, what geometric principles guide safe merging so you preserve knowledge, and how to balance the different tasks each model was trained on so nothing gets erased.

Decouple Searching from Training breaks apart the process of finding good data mixtures during pre-training and then training on them, showing that you can find better mixtures faster using model merging without retraining from scratch because merging avoids the expensive retraining step. Model Merging Scaling Laws predicts how many expert models you need to reach a target performance level so you can plan in advance whether adding more models is worth the cost. Orthogonal Model Merging prevents catastrophic forgetting by merging models along directions that preserve what each model learned rather than overwriting knowledge, which means choosing the right geometric directions matters. Post-Hoc Merging is Not Enough shows that simply taking weights from multiple trained models and combining them breaks down when the models were each optimized for different tasks because the weights are tangled with task-specific details; the fix is to retrain jointly across those tasks so the merged model stays competent on everything. EvoGM uses evolutionary search to find the best way to merge models, outperforming fixed merging rules because search can find combinations humans would not discover. OptMerge extends merging to multimodal models so that a single model can do vision, language, and reasoning tasks without separate specialized models, which reduces deployment complexity.

Ensembles and routing

Running multiple models in parallel and combining their answers—ensemble methods—improves accuracy because diversity catches errors, but costs more computation. The two key problems are: how to route queries efficiently so easier questions skip expensive models and hit the right model for hard questions so you save computation, and how to combine model outputs so the ensemble answer is better than any single model's answer because combining requires skill.

An Ensemble Framework for Unbiased Language Model Watermarking uses ensemble methods to add imperceptible markers to text that you can later verify came from the models because multiple watermarking approaches survive attacks that would eliminate a single approach, while reducing the pieces of text needed for reliable detection and resisting attacks that paraphrase or smooth the output because ensemble diversity creates redundancy. DiSRouter learns which queries are easy versus hard and routes them accordingly, meaning some queries hit a small fast model and others hit larger models, so you only pay the cost when you need it because hard questions need better models. Best-of-Infinity allocates computation across multiple models at test time by blending them together, learning how much to weight each model's output because different models excel at different problem types. FUSE combines predictions from multiple verifier models without needing any labeled data by using unsupervised ensemble techniques, so you can verify whether a generated answer is correct even without ground truth because the ensemble signal survives without labeled examples. Rethinking LLM Ensembling from the Perspective of Mixture Models shows that ensemble methods work the same mathematically as selecting randomly from a blend of different models, so this insight leads to running the ensemble 1.78 to 2.68 times faster while keeping the same accuracy because you only need to sample one model instead of running all of them.

Test-time computation and verification

Instead of making models larger or retraining them, you can spend extra computation at inference time—running the model multiple times or asking it to check its own work—to get better answers because using time instead of model size is often cheaper. The question is which kind of extra computation helps most and how to allocate that budget efficiently, because not all forms of extra computation help equally.

Certain Head, Uncertain Tail improves performance by having a mixture-of-experts model focus extra computation on the hard cases using a method called Expert-Sample, raising pass rates on hard problems from 85.4 percent to 91.9 percent because focusing effort on difficult examples pays off. Long Context Training via Predictive Uncertainty constructs long sequences in a targeted way during training so the model learns to handle very long contexts better, using measures of how uncertain the model's predictions are to decide which examples to include because uncertainty predicts where the model needs help. Propose, Solve, Verify pairs together separate models for generating candidate solutions, solving them formally, and verifying correctness, which gives up to 9.6 times better pass rates than just running the model once because having a separate verifier catches mistakes the generator misses. V1 unifies generation and verification in the same forward pass, so the model generates an answer and simultaneously checks itself in parallel, improving pass rates on code by up to 10 percent while being cheaper than running separate models because combining both steps avoids the overhead of running multiple passes.

Watermarking and detection in model systems

As language models become more capable, we need ways to detect when text came from a model versus a human so we can prevent misuse, and we want that detection to work reliably even when someone tries to erase the watermark through paraphrasing or other attacks because adversaries will try to game the system. Watermarking adds imperceptible signals to model outputs; the challenge is doing this without hurting text quality so people do not notice the watermark, and doing it in a way that survives when people try to remove it because attacks are inevitable.

An Ensemble Framework for Unbiased Language Model Watermarking uses multiple watermarking methods together, reducing the number of words needed to reliably detect the watermark and making it much harder to remove through smoothing attacks because no single attack method can erase all the signals. IPMark adds watermarks at the sentence level rather than at the word level, so each sentence carries a signal which means redundancy; this approach preserves more text quality because watermarking happens at coarser granularity and lets you detect watermarks much faster by checking only a small sample of sentences rather than reading the whole text because sentence-level structure survives attacks that would break word-level signals.
