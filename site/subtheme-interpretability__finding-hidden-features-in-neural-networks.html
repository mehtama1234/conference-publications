Finding hidden features in neural networks

Modern AI models hide their processing in millions of dimensions. These papers find tiny subsets of those dimensions that do meaningful work, using sparse autoencoders and other dictionary-learning approaches.

All themesField mapMathematicsAll explainers
What this is

Neural networks store information in compressed form. A language model might encode 'this word means cat' not in one neuron but in a pattern spread across hundreds of them, like a code written in a high-dimensional space. Researchers want to find the 'atoms' of this code — the minimal set of directions in that space where each one stands for one clear concept. If they can do that, the model becomes much easier to understand: instead of millions of adjustable numbers, they focus on a few interpretable features.

The challenge is that finding these features is like recovering the original message from heavily scrambled data. The model's learned representation might mix multiple concepts in subtle ways. A direction might matter only in certain contexts. And some features might be quirks of the training process, not real patterns the model should use. These papers use dictionary learning and sparse autoencoders — techniques that find a small set of direction vectors (directions in the high-dimensional space) that can reconstruct the model's hidden states while staying interpretable. The goal is to decompose the model into a 'parts list' that a human can reason about.

How the work breaks down

Finding hidden features splits naturally into five directions: fixing SAE training itself (so the features we extract actually correspond to what the model computes), understanding what features emerge and how they organize, using features to steer models and detect problems, moving SAE methods across different types of models, and figuring out when SAE features are reliable enough to trust.

Building sparse autoencoders

Sparse autoencoders are the main tool for extracting features, but they fail in predictable ways because training has inherent tradeoffs. When networks compress information heavily or when you ask an SAE to find too few features, the method breaks down. Dead features (directions that never activate) waste capacity; features absorb multiple concepts into one direction because the SAE gives up; and ordinary settings use the wrong sparsity level so extracted features end up noisy, which makes them unreliable for interpretation.

DB-KSVD takes a different math approach to dictionary learning that scales well. It benchmarks on SAEBench across multiple models including Gemma and DINOv2, showing you can get competitive results by changing the underlying algorithm. Breaking the Block fixes a practical problem: instruction-tuned models have sequences with special control tokens (tokens that mark structure, not content) that break continuity, and this fragments learned features; fixing that problem drops reconstruction error from 5.2 to 0.6 and gives you 21% high-quality features. Dimensional Collapse directly addresses the dead feature problem, reducing dead neurons from 87% to below 1% in huge 1M-feature sparse autoencoders. Taming Polysemanticity gives the first sparse autoencoder with theoretical guarantees that it will recover the true features (models up to 2 billion weights) plus a practical variant that actually works in practice. C2R mitigates feature splitting (when one feature's job splits across two directions) and absorption (multiple concepts squeezing into one) while keeping reconstruction working. Sparse but Wrong identifies that most practitioners set the L0 hyperparameter (how many features to encourage) too low, which ruins monosemanticity; they provide a proxy metric to find the right value for your data.

These papers agree on a core insight: SAE training has fixable technical problems that researchers have learned to avoid. The improvements stack, so modern SAE training combines multiple fixes rather than relying on one method.

What features emerge and how they organize

Once you extract features, you need to understand what they represent and how the network arranges them. Some features combine multiple related concepts in one direction (polysemanticity). Features can be context-dependent, active only in certain situations. And the organization of features changes as the model trains.

Correlations in the Data shows how semantic clustering emerges: when you compress a language model's representations, related concepts naturally arrange into ordered patterns (like circles in a circle), and this organization comes directly from correlations in the training data. Evolution of Concepts tracks how features change during pretraining in two phases: first the model learns statistics, then it learns interpretable features, and these stages have measurable causal effects on downstream performance. Internal Planning reveals that language models structure intermediate computations for lookahead and backtracking, showing planning properties across synthetic tasks and natural language. Rabbit Hull uses spatial organization to explain how vision models arrange features: classification tasks recruit learned negations of concepts, segmentation recruits boundary detectors, depth uses monocular depth cues, suggesting the network has specialization. Mechanism of Task-oriented Information Removal identifies Denoising Heads that explicitly remove irrelevant information in in-context learning; blocking these heads crashes accuracy, proving they are causal. Differential Syntactic and Semantic Encoding shows DeepSeek-V3 encodes language structure (syntax) and meaning (semantics) in separable directions, and you can decode them with different layer profiles.

These papers show features are not random. They emerge in organized patterns driven by task structure, and many features play specific causal roles in the model's computation.

Using features to find problems and steer models

Once you can extract and identify features, you can use them to solve practical problems: detect when a model makes mistakes, find biases in dangerous domains, steer the model toward different behavior. The challenge is that features are sometimes polysemantic (noisy, representing multiple things), and interventions can have unintended side effects.

Can SAEs Reveal Racial Biases identifies features (hidden directions in the model's computation) correlating with race in healthcare-domain language models and shows you can steer those features to change the model's output; this demonstrates both the capability and the risk. HARP detects when a language model is hallucinating (making up facts) by finding a reasoning subspace and checking consistency, reaching 92.8% accuracy while using only 5% of the original dimensions. Uncertainty as Feature Gaps measures when a model is unsure by looking at gaps in how strongly features fire (how often they activate), outperforming standard uncertainty baselines across question-answering benchmarks. CorrSteer scales steering to 100,000 sparse autoencoder features by finding correlated groups and steering them together, improving performance on multiple-choice reasoning and reducing harmful outputs with fewer side-effects than fine-tuning. Endogenous Resistance identifies how models defend against steering by activating off-topic detector features; finding and ablating these 26 detectors reduces multi-attempt rates by 25%. Label-Free Mitigation addresses spurious correlations in vision-language models (e.g., learning to rely on backgrounds instead of objects) using sparse autoencoder features, matching or beating supervised baselines without requiring extra data.

These papers establish features as an interpretable tool for diagnosis and control. The consistency across applications (bias, hallucination, spurious correlation) suggests SAE features capture real mechanisms the model relies on.

Transferring features across models and domains

SAEs were developed for language models, but researchers now extract interpretable features from vision models, diffusion models, biology models, and across different architectures. The hard part is that a feature learned on one model or domain does not automatically transfer to another.

DLM-Scope applies sparse autoencoders to diffusion language models (which generate text by iteratively denoising, not one word at a time). It finds that sparse autoencoder features help early layers but hurt late ones (opposite to left-to-right token-prediction models), and that sparse autoencoder features enable fine-grained control over which words appear at each generation step, so you can steer diffusion behavior. Domain Restriction uses sparse autoencoder features from multiple layers to detect text that doesn't match the training domain by tracking how features fire as you go through the network; this signals domain shift without retraining, which is valuable because retraining is expensive. Features Emerge as Discrete States applies sparse autoencoders to 3D neural networks for the first time, discovering networks learn discrete spatial regions rather than continuous position representations, revealing unexpected structure. Interpretability Transfer from Language to Vision shows that interpretability concepts from language sparse autoencoders can apply to vision networks because both compress high-dimensional data into features, achieving a threefold improvement in concept matching; targeted interventions on vision features (e.g., remove bird objects) improve accuracy by 35-47%, proving the concepts are mechanistically causal. Interpreting Genomic Language Models extracts features from biology-domain models and finds intermediate-layer features are more interpretable than raw high-dimensional arrays of numbers on 76% of genomic concept evaluations, suggesting biology models have similarly organized internal structure. SAE as a Crystal Ball uses feature-based statistics to predict whether a language model will transfer well to new domains, reaching 0.75 correlation with actual transfer performance without any fine-tuning, enabling deployment decisions before investing training time.

These papers show SAE methods are not limited to language or vision, and that features learned in one domain sometimes generalize while others require adaptation. The common finding is that feature-based analysis guides you toward actionable decisions about model deployment.

When to trust features: quality, stability, and evaluation

A persistent challenge is knowing whether extracted features are real patterns the model actually uses, or artifacts of the SAE training process. Features might be unstable (change when you retrain with different random seeds), might not survive causal tests (ablating them has no effect), or might score high on interpretability metrics by accident.

Do Sparse Autoencoders Identify Reasoning Features tests whether sparse autoencoder features for reasoning are causal by checking if they survive intervention. It finds only 45-90% of candidate reasoning features actually matter (survive ablation), and that model-guided falsification can trick many features into high firing rates on non-reasoning inputs, so automatic scoring is unreliable. Automated Interpretability Metrics Do Not Distinguish Trained and Random Networks shows many automatic scoring methods give similar results for trained and random networks, proving these metrics alone do not guarantee you found real features because they can't tell learned computation from randomness. Evaluating SAE Interpretability Without Generating Explanations provides direct assessment methods that correlate with human judgment, sidestepping the unreliable automatic metrics so interpretability work can be grounded in human understanding. On the Limits of Sparse Autoencoders develops theory showing sparse autoencoders have fundamental limitations (features can hide when sparsity constraints conflict with reconstruction) and proposes reweighting fixes that improve single-concept-per-feature quality, because you need theoretical understanding to know when the method will fail. Sparse Autoencoders Trained on the Same Data Learn Different Features finds only 30% of features are shared across random seeds in a 131K-feature sparse autoencoder, though ReLU sparse autoencoders are more stable than TopK variants; this suggests sparse autoencoders find pragmatic decompositions rather than unique ground truth, which means feature identity depends on method choice and training randomness. Taming Polysemanticity pairs theory with practice, providing the first recovery guarantee and a working algorithm (Group Bias Adaptation), making features interpretable up to models with 2 billion weights, so features become provably trustworthy under specific conditions.

These papers share a skeptical but constructive stance: features need validation, automatic metrics are insufficient, and polysemanticity is a real problem that theory can address. The practical lesson is to test features causally and compare across random seeds before trusting them.
