ExoPredicator: World Models That Learn What the World Does on Its Own

A robot learns a model of the world by separately tracking what it can change and what changes on its own, making it plan better for long tasks.

Paper explainersAll themesRobotics & Control

Most robot planning models assume the world only changes when the robot moves. But real worlds are full of exogenous processes — things like water heating, dominoes falling, or gravity acting — that unfold on their own. ExoPredicator learns separate models for these two kinds of change: actions the robot can control (endogenous) and everything else (exogenous), making plans that actually work when the world is busy doing things the robot cannot touch.

Zero assumption version

The world does not wait for the robot to act

Standard robot models assume the world only changes when the robot moves. In training, they memorize: if I push object A to the left, it stays left. But they ignore everything else running in parallel — water gradually heating, a domino chain falling, another robot moving, gravity pulling. When a robot trained on such a model tries to plan a long task (like moving objects for 30 seconds while other things change), the model predicts nonsense because it never learned what those other things do.

A beginner's first approach: just keep the model simple and hope. Feed the robot state-before and state-after for every second, and train a neural network to predict change. But this fails because the model conflates two completely different sources of change. When the state changes, the network sees both the robot's action AND the world's autonomous drift tangled together, and it cannot learn what each contributes. The plan becomes a guess.

In one sentence. The paper learns separate models for actions the robot controls and processes the world runs on its own.

The algorithm as a flow

What it actually does

Separate the two processes

Split the state-change model into: action-effect (robot moves) + autonomous-drift (world on its own).

Represent state symbolically

Use discrete symbols (object A, object B, configuration 1) instead of raw pixel numbers, so causality is clearer.

Learn each causal process from data

Train one causal model for how robot actions change state, another for how exogenous processes evolve state.

Use LLM proposals and Bayesian fitting

Ask a language model to propose likely causal rules; then adjust model weights to match observed data using probability-based fitting.

Combine and plan

At plan time, stack both models: predict new state as (old state + robot action effect + autonomous drift).

What the paper changes

What the paper changes

The paper changes how a robot's world model is factored (how it is broken into pieces). Instead of one tangled model that learns state-change-from-any-cause, ExoPredicator maintains two separate causal models: one for endogenous change (what the robot's action causes) and one for exogenous change (what the world does on its own). This factorization lets the model learn causality cleanly because each model sees only one source of variation.

The hidden quantity

The causal effect for each process

measured quantity  =  Causal effect per process (how much each source changes state)

ExoPredicator measures and models the causal effect of each process separately. The causal effect is the amount of state-change you see when that process runs. For the robot's action, it is: what state-change did the robot's push cause? For exogenous processes, it is: how much does gravity or heat or another robot move things forward?

The paper estimates these effects by fitting each causal model to real robot data. When the robot acts and the world also acts, the model sees the combined result; it learns to disentangle which change came from which source by looking for patterns: if action A always pairs with motion M, and exogenous drift D always adds on top, then the model can infer them separately. Bayesian inference (probability-based fitting) helps because it captures uncertainty in these estimates.

Why it works

Why separate causal models make planning work

The core mechanism is disentanglement. When the robot observes state changes in the world, two things are happening at once: its own action is pushing things, and autonomous processes (gravity, heat, other agents) are also changing state. If you train one model to predict state-change without separating these sources, the model learns a confounded pattern — it memorizes that when certain actions happen, certain outcomes follow, but it cannot tell how much each source contributed. This breaks planning because the world situation is always slightly different; yesterday the dominoes were 2 cm away, today 3 cm away. The model cannot distinguish between: 'my action causes 5 cm change' versus 'my action causes 5 cm plus the dominoes add 1 more today because they are in a different position.' It guesses.

By maintaining two separate causal models, each sees one source of variation. The endogenous model is trained only on state-changes that follow the robot's action, isolated from the noise of autonomous drift. The exogenous model sees how the world drifts on its own (over time, nothing the robot did). Each learns its specific causal effect cleanly. When planning a long horizon (30 seconds), the robot predicts: next state from the old state plus the robot's action effect plus the world's autonomous drift. Because each term is learned from clear data, the prediction stays accurate across held-out scenarios where the world is in slightly different states.

The prediction equation

First in words:

New state equals old state plus the change from the robot's action plus the change from autonomous world processes.

Then the compact form:

s_t+1 = s_t + delta_endogenous(s_t, a_t) + delta_exogenous(s_t)

Every symbol:

s_t+1the predicted next state
s_tthe current state
a_tthe robot's action at this step
delta_endogenous(s_t, a_t)state change caused by the robot's action, which depends on the current state and action
delta_exogenous(s_t)state change caused by autonomous world processes, which depends on the current state
A tiny worked example
Current state: object at 10 cm, robot arm at start position.
Robot action: push forward.
Endogenous model predicts: push moves object 5 cm. (delta_endogenous = 5)
Exogenous model predicts: gravity and friction shrink drift by 0 cm (object is light). (delta_exogenous = 0)
New state: 10 + 5 + 0 = 15 cm.
But on the next step: exogenous might be water expanding (2 cm drift). New state: 15 + 3 (new push) + 2 (water) = 20 cm.
The separate models handle different scenes consistently because each learns one causal source.

The equation says the world changes in two independent ways: the robot pushes, and the environment drifts. The paper learns both, so predictions stay true across long horizons.

What can go wrong

What can go wrong

Exogenous processes are hard to spot. If the world runs a very slow process (water heating over minutes), or one that is hidden (internal state you cannot see), the model cannot learn it because it only sees observed state changes. The Bayesian fitting will assign that drift to random noise instead of a real exogenous model.
Robot and world processes interact. Sometimes the robot's action changes how fast exogenous processes run. Example: if the robot bumps into dominoes, it changes their falling speed. The model assumes the two are independent; if they are not, the causal models will not disentangle cleanly.
Symbolic state representation must capture what matters. ExoPredicator represents state as discrete symbols (object A, object B). If the true causal effect depends on continuous details (exact angle, exact mass) that symbols hide, the model loses precision.
Done right: limited data, clear causality. When the world has clean exogenous processes (gravity, heat), and symbolic state captures the essential object positions and relationships, ExoPredicator learns from a small amount of data because the causal factorization is tight.
What a runnable demo should prove

What a runnable demo should prove

Build a simple 2D robot-world simulation: a robot arm on a tabletop, small objects, and one exogenous process (gravity slowly pulling objects downward, or a fan pushing them). Collect 100 trajectories of: robot pushing, then gravity acting, for 20 steps. Train ExoPredicator's endogenous model on action-effect pairs, and the exogenous model on gravity-only sequences (steps where the robot does nothing). Then run a long test: robot plans a 30-step sequence (push, wait, push, wait) while gravity runs. Measure: how close does the predicted object position track the real position over 30 steps? Standard models will diverge fast; ExoPredicator will track true positions to within 10% error for all 30 steps.

prediction_error = mean absolute distance over 30 steps between predicted and actual object position

The demo proves that separating endogenous and exogenous models lets you plan accurately in worlds where time is running things the robot does not control.
