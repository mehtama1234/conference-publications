ExoPredicator: Learning Abstract Models of Dynamic Worlds for Robot Planning

The robot learns which state properties change when it acts, which change on their own, and when to expect each change.

Paper explainersAll themesRobotics & Control

Robots planning long horizons face a hard problem: the world changes for two reasons at once. When the robot pours coffee, its action causes the cup to fill, but while that is happening, the coffee itself is cooling down. Standard robot learning only tracks effects from the robot's actions. ExoPredicator separates the two — learning causal processes for both the robot's actions and the world's independent processes, tracking when each change arrives, so the robot can reason about concurrent effects.

Zero assumption version

Why robots get confused by things that happen on their own

Today, when a robot learns a world model (a learned mental picture of how the world works), it learns: if I do action A, then property P changes. For example: if I turn the faucet, water flows. But the real world is messier. While water flows, it also cools. While the robot pours, dominoes fall on their own nearby. The robot's action did not cause the dominoes to fall, but the robot needs to predict it to plan.

A naive robot model only learns endogenous (agent-caused) effects. So when the robot plans to turn a faucet, its model predicts only water flowing. It ignores that water is cooling at the same time, or that someone else in the room might shut the faucet. The plan fails because the world has concurrent processes the robot never learned. The robot has no way to separate its own effects from the world's independent processes.

The robot needs to learn. The robot needs to learn which things happen because of its actions, and which things happen on their own, and when to expect each one.

The algorithm as a flow

What it actually does

Learn endogenous processes

Robot records: when I did action A, property P changed. Stores condition (P must be true first) and effect (add/remove facts).

Learn exogenous processes

Robot records: when property Q was true, property R changed on its own later (no agent action). Stores the same condition-and-effect pair.

Learn arrival times

For each process, estimate a distribution: given the trigger fires now, when does the effect land? A discrete distribution over future timesteps.

Use big-step planning

Plan does not think timestep-by-timestep. Instead, big-step jumps to the next state change, simulating all concurrent processes at once until something new appears.

Generalize to new tasks

Planner uses learned processes to reason about unseen objects and goals, because processes are abstract (condition-and-effect in symbolic properties, not raw pixels).

What the paper changes

What the paper changes: the causal process model

Standard robot models learn: action A causes effect E. ExoPredicator splits this into two separate causal processes. One process captures endogenous effects (caused by the robot). Another captures exogenous effects (the world's independent dynamics). Each process is stored as a symbolic rule: if conditions are true, apply these additions and deletions to the state. The key addition is an arrival time distribution, which predicts how many steps until the effect lands.

The hidden quantity

The hidden quantity: arrival time distribution

measured quantity  =  arrival time (steps until effect manifests)

The paper measures a new quantity: given that a causal process is triggered (its condition is true), how many timesteps until the effect appears? For example, if the faucet turns on, water does not fill the cup instantly — it arrives in, say, 5 to 15 timesteps depending on flow rate. ExoPredicator learns a probability distribution over these arrival times, so it can predict not just that the water will fill the cup, but when.

The paper estimates this distribution from trajectories by recording the timestep gap between when a process is triggered (condition satisfied) and when the effect manifests (facts change). For each process, it builds a categorical distribution (a probability over discrete time steps) by counting how often the effect arrived at each timestep across different episodes. This distribution is then used during planning to sample when the effect will actually happen.

Why it works

Why learning two separate processes works

The robot's problem is that it cannot tell whether a state change happened because of its own action or because the world moved on its own. Both look like: property changed between timesteps. ExoPredicator solves this by learning which state changes co-occur with agent actions (endogenous) and which happen without agent input (exogenous), then building a big-step model that simulates both concurrently.

During planning, the planner does not iterate tiny timesteps. Instead, it uses a big-step transition function: given a current state and an agent action (or no-op), compute the next distinct state by running all active processes forward until something changes. Endogenous processes fire when the robot issues a command. Exogenous processes fire when their conditions are satisfied, regardless of what the robot does. The planner samples arrival times from the learned distributions, so it reasons: faucet turns on, water will arrive in 5 to 15 steps, then cup is full and cooling starts in parallel. This is a faithful simulation of concurrent effects, which a naive per-timestep model cannot capture.

The payoff is planning transparency and generalization. A process is a symbolic rule (condition and effect on abstract properties), not a pixel-level pattern, so it transfers to new objects and scene layouts. The planner can also search more efficiently, because it jumps over irrelevant timesteps where nothing abstract changes.

Math after the picture

The causal process equation

First in words:

effect_added = (condition_at_start true) AND (overall_condition held until now) THEN apply effects; arrival time sampled from learned distribution

Then the compact form:

if C_L(s_t)=1 and O_L(s_t'+1:t-1)=1 then s_t+1 <- (s_t+1 \ E_L.Del) union E_L.Add; A_L^t ~ q_L^t

Every symbol:

C_L(s_t)indicator: are all atoms in the condition-at-start set satisfied at step t but not at t-1?
O_L(s_t'+1:t-1)indicator: did the overall condition hold at every step between t' and t-1?
E_L.Addthe facts to add to the state when this process fires
E_L.Delthe facts to remove
A_L^tthe arrival time in steps, sampled from the categorical distribution
q_L^tthe learned probability distribution over arrival times for process L triggered at t
A tiny worked example
Process: Faucet. Condition: faucet_off=false and sink_empty=true. Effect: add sink_filling.
Step 1: Agent issues Faucet On. C_L(s_1)=true (condition satisfied for first time).
Step 1: Arrival time A_L^1 sampled from q_L (learned distribution). Suppose q_L gives: P(5 steps)=0.6, P(10 steps)=0.3, P(3 steps)=0.1. Sampled: 5 steps.
Step 5: O_L held from step 2 to 4 (sink_empty remained true). Effect fires: add sink_filling to state.
Now sink_filling=true. Planner knows water is coming in 5 steps; can predict concurrent exogenous processes (water cooling) that start once sink_filling=true.

Each causal process waits for its conditions, then applies effects at the sampled arrival time, allowing the planner to reason about concurrent delayed effects.

What can go wrong

What can go wrong

Arrival time distribution collapses. If a process has high variance in arrival time (sometimes fires in 3 steps, sometimes 20), the learned distribution becomes flat. The planner cannot predict reliably, and plan failure returns.
Exogenous process conditions are hard to learn. The paper uses an LLM to propose candidate symbolic predicates. If the LLM misses a true predicate (e.g., the condition for water cooling is actually about current temperature, not just water in cup), the process is never learned.
Limited training data. If the robot only sees one coffee-pouring episode, it may not see exogenous processes fire at all. The learning algorithm needs at least a few trajectories per process to build a stable arrival time distribution.
Done right. With enough diverse trajectories and a good LLM for predicate proposal, ExoPredicator learns faithful causal processes and arrival times, enabling the robot to plan long horizons with confidence in concurrent effects.
What a runnable demo should prove

What a runnable demo should prove

Build a simulated tabletop environment with an agent arm and multiple exogenous processes (e.g., water heating, dominoes falling, a timer counting down). Train ExoPredicator on a few trajectories where the agent performs simple actions and observes world changes. Then, ask the planner to solve a new goal never seen in training (e.g., get hot coffee into a cup at a particular time). The demo should show that the planner predicts and uses the arrival times correctly: it waits for water to heat (exogenous), then pours when ready, reasoning about the concurrent cooling process.

success_rate = (number of tasks where plan reaches goal within time limit) / (total tasks attempted)

The key metric is whether the planner's arrival time predictions allow it to succeed at long-horizon tasks with concurrent exogenous processes that a naive endogenous-only model cannot handle, because accurate arrival times let the planner order actions correctly and account for delays.
