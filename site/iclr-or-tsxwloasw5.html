InstructVLA: Vision-Language-Action Instruction Tuning

A robot model learns to reason in natural language and generate precise manipulation actions at the same time, without forgetting its original reasoning skills.

Paper explainersAll themesRobotics & Control

A trained model that understands images and language (a vision-language model) can answer questions and describe scenes, but it was never built to move a robot arm. When you try to teach such a model to move robots by training it with manipulation data, it forgets how to reason. InstructVLA solves this by adding a small trainable adapter that routes reasoning tasks and action tasks through separate paths, so learning to grasp a cup does not erase learning to read and follow instructions.

Zero assumption version

The dilemma: reasoning or grasping, pick one

A large trained model (a foundation model) learns to understand images and answer questions by seeing millions of examples. It is excellent at reading a scene and reasoning step-by-step: given a photo and an instruction like "describe what the person is doing", it can explain in words. But this model was never trained to move a robot.

A second class of model is trained only on robot manipulation videos. It learns to predict arm movements: given an image and a task like "pick up the cup", it outputs joint angles. It is precise but narrow; ask it to reason about why it picked up the cup, and it has no answer.

A beginner would naively train the first model (the reasoning one) on manipulation videos, adding a new prediction head that outputs arm movements. But this breaks: the model forgets how to reason about scenes and follow complex instructions. It sacrifices its original skill to learn the new one. This is catastrophic forgetting.

The move. Add a small trainable adapter that routes tasks through separate paths: general reasoning stays with the main model, action commands go through a separate learnable module.

The algorithm as a flow

What it actually does

Freeze the reasoning model

The pre-trained vision-language model is locked; its weights do not change.

Train an action expert separately

On robot manipulation videos, train a small separate module to predict arm movements.

Build a router adapter

Create a mixture-of-experts (a switching module) that learns when to use reasoning and when to use actions.

Combine reasoning and action

Feed the robot's camera view through both paths: main model outputs reasoning, adapter outputs arm movements.

Test on new instructions

The model reads an instruction, reasons step-by-step, and moves the arm without forgetting how to explain.

What the paper changes

What changes: the routing decision

InstructVLA does not change the main reasoning model. It adds a separate trainable adapter that learns to route each input (a camera frame, an instruction, or both) to the right output pathway. When the input is a reasoning question, the adapter lets the main model answer. When the input is a manipulation task, the adapter directs the output to action predictions. The adapter learns which pathway suits which task without disturbing the original model's weights.

the object it moves  =  routing decisions in the adapter
The hidden quantity

The hidden quantity: task interference signal

measured quantity  =  task interference (how much each training step overwrites what the model already knows)

When you train a model on two different tasks, the gradients (signals that nudge the weights) from task A can push the same weights that task B relies on. This erases task B. InstructVLA measures this interference by tracking which weights the main model needs for reasoning and preventing the action adapter from overwriting them. The paper does not measure this explicitly, but the mechanism relies on it: by freezing the main model and training only the adapter, InstructVLA sidesteps interference entirely.

The adapter estimates task importance through the mixture-of-experts routing: each expert (a small learnable sub-module) gets a score for how much a given input should use it. Inputs that trigger high reasoning scores stay away from action experts, and vice versa.

Why it works

Why it works: separate paths for separate goals

When you train a single model on two different tasks at the same time, the weight updates for task A interfere with task B. This is because the same numbers (weights) are used to compute answers for both. InstructVLA solves this by freezing the main model and adding a separate small adapter that learns the new skill (action generation). The frozen model still computes reasoning output, while the adapter computes action output. Because they use different weights, training on robot data only changes the adapter, leaving the reasoning model untouched.

The mixture-of-experts routing inside the adapter learns to assign each input to the right expert. An expert is a small learnable sub-module. When the input is a reasoning question, the routing module gives high weight to experts that pass the input through the frozen main model. When the input is an action task, the routing selects experts tuned for action prediction. Because the experts learn separate routes, they do not compete; the action expert can become very good at arm control without pulling reasoning weights down.

The routing and loss equation

First in words:

Total training loss equals the language modeling loss plus the flow-matching action loss, summed equally. The mixture-of-experts router assigns each token or frame to experts via learnable weights.

Then the compact form:

L_total = L_LM + L_FM

Every symbol:

L_totalthe combined training loss
L_LMlanguage modeling loss: how wrong the text prediction is
L_FMflow-matching loss: how wrong the action prediction is
A tiny worked example
Batch 1: camera frame + 'describe the scene' instruction. Router score for reasoning: 0.9 (high). Language loss computed: 0.05. Action loss: not computed (router score is low). Contribution: 0.05.
Batch 2: camera frame + 'pick up the block' instruction. Router score for action: 0.85 (high). Action loss computed: 0.08. Language loss: small (router score low). Contribution: 0.08.
Batch 3: mixed task. Router scores both at 0.5 each. Both losses computed: 0.06 + 0.07 = 0.13. Total loss averaged: (0.05 + 0.08 + 0.13) / 3 = 0.087. The router learned when to focus on each branch.

The equal weighting of both losses means the model must learn both skills in lockstep; the router learns to separate them by input type.

What can go wrong

What can go wrong

Imbalanced routing. If the router learns to always pick reasoning, the action expert never trains and stays random. The model must see enough action tasks during training to let the routing module learn their signatures.
Adapter becomes a bottleneck. If the adapter is too small, it cannot learn complex action patterns. Adding more trainable parameters (more LoRA modules, more experts) fixes this, but uses more graphics-card memory and makes real-time control slower.
New instructions that mix reasoning and action. An instruction like 'describe what you will pick up, then pick it up' requires both paths at once. The router must learn to turn both experts on in sequence, which is harder than picking one or the other.
Done right. The model trains on a mix of reasoning tasks and action tasks with clear labels (reasoning vs. manipulation). The router learns the pattern of when each task type appears. Both skills emerge without interference.
What a runnable demo should prove

What a runnable demo should prove

Train a model on reasoning data (image captioning, visual question answering) and action data (robot grasping, pushing) in parallel. Compare the model's ability on both tasks before and after training: (1) Does the reasoning skill survive intact after action training? (2) Does the action skill reach the same performance as a model trained only on actions? (3) Can the model follow a complex instruction ('pick up the red cube and put it on the left') that requires reasoning to parse and action to execute?

reasoning_accuracy = (correct descriptions after training) / (total reasoning tasks); action_success = (successful grasps after training) / (total action trials); joint_instruction_score = (mixed instructions completed correctly) / (total mixed instructions)

The clearest sign of success: reasoning accuracy stays above 85% after action training (no catastrophic forgetting), while action success reaches 80%+, and the model can handle real-world instructions that blend both skills.
