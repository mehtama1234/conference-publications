Active Regression with Unknown Link Functions

When you have to pay for each answer, a smart sampling strategy can solve a regression problem with far fewer questions than asking blindly.

Zero assumption version

Regression when questions are expensive

Imagine you have a huge table of data. Each row has input numbers (age, income, location), but only some rows have the output answer you need (credit score). Looking up one answer costs money. You want to guess the hidden pattern with the fewest lookups possible.

A naive beginner would pick answers at random: point at a row, pay for the answer, repeat. This works only if you can afford thousands of lookups. But in biology, robotics, and chemistry, each answer might be expensive or hard to get. A smarter approach asks for answers that would teach the model the most—because rows that are different from each other in the input space will each reveal a different piece of the hidden transformation—skipping the rows that won't help.

The question. Can we ask for fewer answers by choosing which ones wisely, and how few is theoretically possible?

The algorithm as a flow

What it actually does

Compute row importance

For each row, calculate a Lewis weight: a number saying how much this row would help the model learn, because rows with unusual inputs reveal the hidden transformation better than common ones.

Sample strategically

Ask for answers only from rows with high weights, using a random choice weighted by each row's importance.

Rescale the answers

Inflate the answers slightly (divide by sampling rate) to correct for the fact that you did not ask for all of them.

Learn the link function

Fit both the hidden mapping and the unknown transformation together on the rescaled answers.

Return the solution

Output the learned mapping and the learned transformation. You have solved the problem with far fewer questions than random picking.

What the paper changes

What the paper changes

The paper changes which rows you ask about. Instead of asking at random or asking for all rows, the algorithm samples rows with probability proportional to how much they would improve your model, because high-weight rows give answers that span the full space of possible inputs, allowing the model to learn more from each answer. This is called weighted sampling.

the object it moves  =  sampling of rows
The hidden quantity

The Lewis weight: how much each row teaches

measured quantity  =  Lewis weight for each row

A Lewis weight is a single number assigned to each row of your data that measures how much information that row carries. Rows with high weights have inputs that are unusual or extreme in a useful way. Rows with low weights are common or similar to rows you have already seen.

The paper computes Lewis weights using a formula based on the table of inputs. Intuitively, if a row's input is very different from all other inputs, its Lewis weight is high, because answering it would teach the model something new about the corners of the input space.

Why it works

Why weighted sampling closes the gap

The problem is hard because you cannot see the link function (the hidden transformation). If you picked rows at random, you might waste time on rows that all look the same after the transformation, giving you no new information. Weighted sampling fixes this: it asks about rows whose inputs are most different from each other, because different inputs are most likely to reveal how the transformation works.

By using Lewis weights, you guarantee that the rows you sample are spread out in input space. This means each answer you buy teaches the model something genuinely new, because a concentrated set of answers would overlap in their information content. The model can then learn both the mapping and the transformation faster, because seeing diverse input-output pairs makes it easier to disentangle the fixed mapping from the unknown transformation. The paper proves this is nearly optimal—no algorithm can do much better, no matter how clever—because the lower-bound proof shows any algorithm must query roughly this many rows on its hardest input.

Math after the picture

The penalty for using fewer queries

First in words:

total_error = (approximation_error) + (penalty_term_proportional_to_p_and_epsilon)

Then the compact form:

queries_needed = d^(p/2 ∨ 1) / epsilon^(p ∨ 2) * poly_log(n/epsilon)

Every symbol:

dthe number of input features (how many numbers describe each row)
pthe loss type (p=2 is squared error, p=1 is absolute error)
epsilonhow close you want to get to the best possible answer (smaller is better)
nthe total number of rows in the table
queries_neededthe minimum number of answers you must buy
poly_log(n/epsilon)a slowly growing term, logarithmic in the table size
A tiny worked example
Suppose d=10 features, p=2 (squared error), epsilon=0.1, n=1000 rows.
Then d^(p/2 ∨ 1) = 10^(2/2 ∨ 1) = 10^1 = 10.
And epsilon^(p ∨ 2) = 0.1^(2 ∨ 2) = 0.1^2 = 0.01.
So queries_needed ≈ 10 / 0.01 * log(1000/0.1) ≈ 1000 * 3.4 ≈ 3400 queries.
If p=1 (absolute error): d^(1/2 ∨ 1) = 10, epsilon^(1 ∨ 2) = 0.1^2 = 0.01, same result.
If d=100: need 100 * (1/0.01) * log(10000) ≈ 100,000 queries. Larger d costs more.

The formula says: fewer features (small d) and bigger tolerance (large epsilon) let you win with fewer queries. But the tradeoff changes depending on whether p is small or large.

What can go wrong

What can go wrong

If you compute Lewis weights wrong. Lewis weights require numerical calculations on the table of inputs that can be slow or unstable when the table is huge. If the approximation is rough, the sampling might miss important rows. The paper uses fast iterative methods for p less than 4.
If the link function is not 1-Lipschitz. The method assumes the hidden transformation does not change too fast. If it has discontinuities or sharp jumps, the guarantees break. You must know this bound ahead of time.
If the data has outliers. Outlier rows can have very high Lewis weights. If you oversample them, the rescaling can amplify noise, because extreme weights make the rescaling factor very large, which inflates the uncertainty in your answers. The paper's analysis handles this, but in practice, clipping extreme weights helps, because capping the largest weights prevents the rescaling from blowing up.
Done right. Compute Lewis weights once using a stable numerical library, then sample cheaply many times. This approach is efficient and provably near-optimal.
What a runnable demo should prove

What a runnable demo should prove

Build a synthetic table with 100 rows, 10 input features. Introduce a hidden transformation (e.g., apply a tanh or ReLU to the linear model). Ask the algorithm to learn the mapping with limited budget. Compare two methods: (1) random sampling, (2) weighted sampling by Lewis weight. Measure how many queries each needs to reach the same accuracy.

accuracy_gain = queries_random / queries_weighted

The demo should make it impossible to miss: by asking smart, you need 3 to 5 times fewer answers than random picking.
