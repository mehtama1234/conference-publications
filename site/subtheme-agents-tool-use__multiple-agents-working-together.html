Multiple Agents Working Together

Papers about coordinating several agents to solve problems together, like a team brainstorming or dividing tasks.

All themesField mapMathematicsAll explainers
What this is

Instead of one agent solving a problem alone, what if you had multiple agents with different strengths working as a team? One agent might be good at math, another at reading and summarizing, another at logical reasoning. They divide the work, pass information to each other, and combine their answers. This is inspired by how humans work in teams: you brainstorm together, point out flaws in each other's ideas, and build on what the group learns. The papers here explore how to coordinate multiple agents so they actually help each other instead of getting in the way.

The tricky part is making coordination actually work. Multiple agents mean more communication overhead — they have to pass messages, wait for each other, and resolve disagreements. If they are all calling the same tools, they might waste time on redundant calls. If they specializes but don't communicate well, they might end up solving different parts of the problem in isolation without realizing they contradict each other. And debugging a multi-agent system is much harder because failures can cascade in unpredictable ways. The system has more moving parts, more failure modes, and more places for things to go wrong.

Researchers work on agent collaboration frameworks that let teams of agents solve problems together. Some papers focus on communication protocols — how agents signal what they are doing and what they found out. Others focus on task division — making sure each agent gets a piece of the problem that plays to its strengths. Some look at voting or consensus mechanisms, where multiple agents independently tackle a subproblem and then combine their answers. The goal is to show that a team of agents can solve harder problems than any single agent could alone, but without the overhead drowning the benefits.

How the work breaks down

The research splits into five natural directions. First: understanding whether multiple agents actually help—since combining many weak agents might outperform one strong agent if you can find the right way to blend their answers together. Second: designing communication protocols so agents can coordinate without wasting time or introducing errors, because raw diversity only works if agents actually share information. Third: building systems that specialize agents so each plays to its strengths instead of duplicating work, which reduces wasted computation. Fourth: detecting and fixing failures when multi-agent systems go wrong—because more parts means more ways things can break and errors in one agent can cascade to others. Fifth: making coordination efficient enough that the overhead doesn't wipe out the benefits, so scaling up to many agents actually makes things faster instead of slower because the speedup from parallelism beats the synchronization cost.

Combining Answers from Multiple Agents

When multiple agents solve the same problem independently, the hard question is how to combine their answers into a single, better answer that beats any individual agent. Simply taking the majority vote (most agents pick answer A, so A wins) seems obvious—but it can miss important information because a confident minority might have the real answer. These papers explore smarter ways to aggregate answers so that the diversity of the agents actually helps instead of getting averaged away.

The Beyond Majority Voting paper argues that the best answer often sits in relationships between votes, not just in the count of votes. If most agents say A but one agent says B with high confidence, standard voting ignores that confidence signal, so it misses a potentially correct answer. The paper uses higher-order information (connections between votes) to build better aggregation rules because those connections reveal which agents should be trusted. The Diagnostic Study of Multi-Agent LLMs for Real-World Debates shows that looking at how agents interact—whether they question each other's logic, whether they move closer to consensus—matters more than just tallying final answers, which means the quality of reasoning, not just vote count, determines if combining agents helps. When debates reveal process-level interaction failures that no single agent would catch, combining agents has real value. CARD: Towards Conditional Design of Multi-agent Topological Structures discovers that the network shape itself—which agent connects to which agent—changes which problems benefit from multiple agents, so some tasks need linear chains, others need grids, and others need stars with one central agent because different problem types need different information flows. Emergent Coordination in Multi-Agent Language Models shows that you can steer groups toward complementarity using prompt design: instead of 50 copies of the same agent reasoning about finance, design three specialized agents (one for rules, one for numbers, one for long-term strategy) and coordinate them into a real team, not just a voting block, because specialization avoids redundant reasoning. Social Agents: Collective Intelligence Improves LLM Predictions pushes this further across behavioral prediction tasks: a diverse group of agents, each asked slightly different questions to trigger different perspectives, improve single-agent predictions by as much as 67%, which shows that perspective diversity directly translates to better answers. These papers agree on one mechanism: genuine diversity in reasoning paths and perspective beats homogeneous repetition because different cognitive paths find different solutions.

Building Communication and Coordination Protocols

Raw diversity only helps if agents actually coordinate—if they share what they learn and fix mistakes together, because isolated agents stay isolated. The problem is that every message between agents costs computation time, makes the system slower, and introduces errors if agents miscommunicate, so you can't just have agents talk freely without damaging performance. Researchers design communication protocols: rules for when to send messages, what to say, and how to interpret responses—all aimed at solving problems faster without agents wasting time chatting, which means keeping the signal-to-noise ratio high in every exchange.

Learning Efficient and Interpretable Multi-Agent Communication (GLC) shows that agents can learn what to communicate rather than communicating everything, which means filtering messages saves computation without losing important information. Most messages are noise; the same three types of signals (confirm progress, flag a blocker, request help) work for most problems, so agents don't need custom language. By training agents to compress their messages, you get better task performance, lower communication costs, and human teams can actually understand what agents are doing because the signals stay simple. Great Minds Think Alike explores communication that is even lighter: tacit communication, where agents coordinate without explicit messages at all, like teammates who know each other so well they anticipate moves, which means shared context replaces explicit talk. Multi-Order Communication (MOC) discovers that agent talks happen at different speeds and scales: fast local chatter between nearby agents about immediate problems, slower global broadcasts about major findings, and meta-discussion about the overall strategy, so information gets layered by urgency and scope. Layering these communication tiers reduces redundant messages and keeps agents aligned without overhead because each tier carries the right signal at the right speed. Navigating Optimal Communication Networks for Multi-Agent Collaboration shows that the most efficient communication structures naturally develop hubs (key coordinators), specialization patterns, and information flows along useful paths rather than everywhere at once, matching how human organizations actually work, because redundant connections waste effort. The paper uses diffusion models to generate these structures and finds they beat hand-designed communication graphs because automatic optimization discovers real organizational patterns. Redundancy-Aware Diffusion for Multi-Agent Communication (RADAR) pushes this: deliberately add redundant connections to the communication network so that if one agent goes down or miscommunicates, information still flows through backups, which trades small computation cost for fault tolerance. It costs a bit more in computation but keeps the system working when individual agents fail. Systematic Failures in Collective Reasoning identifies a root cause of multi-agent failure: distributed information (agent A knows fact X, agent B knows fact Y, but neither knows both) breaks collective reasoning even with good communication, because partial knowledge leads to inconsistent conclusions. The fix is a lightweight protocol that forces agents to explicitly share findings from others, not just their own reasoning, so incomplete pictures get filled in. The theme across these papers: better protocols beat more communication because quality of coordination, not volume of messages, determines if teams work.

Specializing Agents to Divide Work

Instead of cloning one agent many times, what if you build a team where each agent has a different job? One might be great at math, another at reading code, another at summarizing. Dividing work lets agents play to their strengths and avoid duplicate computation. The hard part is figuring out which agents should handle which parts of the problem, and how to stitch the partial solutions together into a complete answer.

Distilling Task-Level Coordination Policies for Generalizable Multi-Agent Cooperation learns policies for handing pieces of a problem to the right agent, so you don't waste an expensive capable agent on simple subtasks. Instead of training on one fixed team size, it learns generalizable coordination so a four-agent team can tackle problems, then the same policy drops into a six-agent team with new agents, and it still works without retraining, which saves retraining cost. It identifies high-level task structures (this part is search, this part is reasoning, this part is validation) rather than memorizing specific team members, because abstract structures transfer. EvoMAS: Heuristics in the Loop shows that the best team shape evolves over time: you start with homogeneous agents doing the same job, but as the system learns, roles specialize into planner, verifier, and searcher, which means efficiency improves when agents stop competing. The system automatically discovers that specialization is worth the overhead because the speedup beats the coordination cost. Scaling Small Agents Through Strategy Auctions (SALE) tackles a practical problem: large capable models are expensive and slow; small fast models are cheap but weak, so neither is always best. Instead of replacing small with large, SALE routes different problem types to different agents based on confidence: when a small agent is confident, it runs its answer, and when it hits uncertainty, it calls the expensive large model, so you only pay for expensive computation when you need it. This costs 35% less than running everything through large agents and is only 52% less capable than the super-expensive all-large baseline. Agent Primitives shows that agents can share internal building blocks (reusable components like search or validation routines) rather than text, which cuts transmission and parsing overhead. This cuts computation by 3 to 4 times and speeds up how fast answers come back because agents don't repeat standard operations. GraphPlanner uses a routing network to decide, for each step in a problem, whether to call agent A (better at this type of work) or agent B, because routing decisions determine whether specialists actually help or waste time. The routing logic itself is learned from experience, so you avoid manual rules that might misassign tasks and instead adapt to what really works in practice. HieraMAS goes further: optimize both the internal mixture of models inside each agent node and the connections between agents—one agent might be 60% GPT and 40% Claude; another might be 100% Qwen. The network learns who talks to whom because different agent mixes handle different task types. These papers agree: specialization beats homogeneity because playing to strengths beats redundant duplication, even though it requires learning how to coordinate specialized workers.

Detecting and Fixing Failures in Multi-Agent Systems

More agents means more moving parts. If one agent hallucinates, misunderstands a fact, or takes a wrong reasoning step, the error can cascade through the team and break the final answer. Debugging multi-agent systems is much harder than debugging single agents because failures intertwine. These papers develop tools to spot where things go wrong and patch them in real time.

CORRECT (COndensed eRror RECognition via knowledge Transfer) locates step-level errors in multi-agent trajectories without expensive human labeling. When agent A passes its answer to agent B, which agent made the mistake? Which step went wrong? CORRECT achieves 19.8% better error localization than prior work at near-zero cost by training on error-injection data—deliberately corrupt a step and watch how the error propagates. Securing Multi-Agent Systems Against Corruptions identifies adversarial attacks unique to multi-agent setups: if you control just one agent in a five-agent team, you might be able to steer the whole group toward bad answers by sending false signals. The paper's fix is node contribution backpropagation: trace each agent's contribution to the final answer and catch when one agent's contribution suddenly flips from helpful to harmful. Detecting Perspective Shifts in Multi-Agent Systems notices that agents' behavior drifts over time—they update their beliefs, change strategies, or decohere from teammates. The paper's method detects these shifts and correlates them to real external events, so you know when a change in agent behavior is responding to genuine new information versus drift or miscalibration. Emergent Communication Under Misinformation studies what happens when an adversary injects false information into agent communication. Instead of shutting down, agents adapt: they become more skeptical, develop coded language, or rebuild trust via redundant channels. Compositional languages emerge because agents need short, unambiguous signals. Visual Multi-Agent System (ViF) tackles hallucination snowballing: when one agent generates a false detail (like a misremembered character name), other agents accept it as true and build on it. ViF's solution is a visual flow graph that shows each agent which facts it should verify independently rather than trusting other agents' mentions. These papers agree: multi-agent failures are different from single-agent failures and need different tools to catch and fix them.

Scaling Multi-Agent Systems Efficiently

More agents help, but only if the coordination overhead doesn't swallow the gains, which means you need careful tuning to stay faster than a single agent. Agents waiting for each other, duplicating work, or communicating redundantly can make a system slower than one highly capable agent because synchronization costs grow faster than problem-solving gains. These papers optimize the runtime, communication, and computation cost of multi-agent teams so that scaling up actually helps instead of hurting.

AgentWebBench: Benchmarking Multi-Agent Coordination in Agentic Web measures the core trade-off: coordinated multi-agent teams lag behind centralized single-agent approaches initially, but the gap shrinks as models get smarter because smarter agents coordinate better. The paper shows that decentralized access (each agent searches independently) concentrates traffic at retrieval services, which creates bottlenecks, and test-time scaling—giving agents more time to coordinate—improves results if teams plan carefully, so more thinking time helps but not unplanned waiting. The lesson is that naive multi-agent coordination is slow because unstructured parallelism has overhead, but with careful architecture, multi-agent starts to win as model scale increases because bigger models coordinate more efficiently. Learning to Share: Selective Memory for Efficient Parallel Agentic Systems reduces multi-agent runtime by learning which information each agent actually needs to see, so you skip useless broadcasts. Instead of broadcasting every finding to every agent, admission control filters: does agent B care about this intermediate result? This shrinks communication volume and keeps agents working in parallel instead of waiting, which lets parallelism actually help. TreeCUA: Efficiently Scaling GUI Automation with Tree-Structured Verifiable Evolution applies tree search to multi-agent planning for GUI tasks: by learning from branches of near-misses (trajectories that didn't quite work), the system improves planning efficiency and avoids recomputing similar actions, so failed attempts teach the team what not to try. A Two-Tier Perspective on Inference-Time Parallelism (TIPEX) shows that different problem difficulties benefit from different levels of multi-agent coordination, so coordination should scale with problem complexity. Simple problems are faster with independent parallel agents because coordination overhead outweighs the benefit. Medium complexity problems benefit most from coordination because they need cross-agent insights but can still parallelize. Hard problems need heavy coordination because only joint reasoning solves them. The paper's method detects problem difficulty and adjusts parallelism dynamically so you pick the right level per problem. Mosaic: Runtime-Efficient Multi-Agent Embodied Planning targets physical tasks (robot planning, navigation): by reducing redundant LLM calls (one agent plans, others validate) and smartly distributing work across CPU and GPU, Mosaic cuts execution time by 27-32% while improving success rates, because specialization avoids redundant planning. Stop Wasting Your Tokens (SupervisorAgent) achieves similar gains on reasoning tasks: a supervisor decides which subtasks need full LLM reasoning and which can be handled by lightweight heuristics, cutting token use by 30% on benchmarks like GAIA, so cheap heuristics handle easy cases. These papers agree: coordination is expensive and must be tuned carefully because the sweet spot often is a small specialized team, not a massive one, which means more agents doesn't always mean better performance.
