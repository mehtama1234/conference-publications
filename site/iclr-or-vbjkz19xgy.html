Multi-Head Low-Rank Attention

Break one big bottleneck into four independent ones so GPUs can split the memory work.

Paper explainersAll themesEfficiency & Systems

When a language model answers a long question, it has to remember everything from before. That memory, called the KV cache (the saved Key and Value numbers from earlier words), must be loaded from slow storage into each GPU's fast chip-memory at every step. On a single GPU this is fast enough, but when spreading work across many GPUs (splitting the computation across multiple devices), recent methods like MLA cannot split that memory neatly, so each GPU still has to load the full thing. MLRA changes this by decomposing the memory into four independent pieces that each GPU can load separately, cutting per-GPU memory traffic by 2.8 times.

Zero assumption version

Long context means a traffic jam

Decoding a language model one word at a time is slow because the model has to read the entire KV cache—a growing memory of all previous words—from off-chip storage into the chip's fast memory before generating the next word. When one GPU is doing this alone, one GPU can complete this load quickly. But when you spread the work across four GPUs (splitting the computation across devices to decode faster), each GPU still has to load the full cache even though it only needs one quarter of the computation, because the compressed form is a single list of numbers that cannot be divided. This forces all four GPUs to load redundantly and wastes memory bandwidth. Standard attention (called MHA) loads 4 times as much per GPU as needed; newer methods like MLA compress this to 1.5 times per GPU, but the compression squeezes everything into a single latent list, which cannot be split. So each GPU is forced to load the whole thing anyway.

A beginner would try to split MLA's single vector into pieces, but that breaks the math: the inner product that MLA relies on requires all four pieces to be multiplied together at once. The paper's approach is to restructure the math so the four pieces can be multiplied independently, then summed at the end—making splitting possible without breaking quality.

The bottleneck: When splitting work across multiple GPUs, each GPU loads 4.5 numbers per word in MLA because the single latent state cannot be sharded (split and distributed).

What the paper changes

What changes: the latent state structure

MLA uses a single low-rank latent state (a single compressed vector). MLRA replaces it with four independent low-rank latent states (four separate vectors), each feeding its own attention computation. This decomposition is invisible to the outside world—the model still takes queries and produces the same answer—but internally, the four branches can be distributed across GPUs.

The hidden quantity

The hidden quantity: per-device memory footprint

measured quantity  =  per-device KV cache size across multiple devices

When you split inference across four GPUs (each handling one quarter of the computation), each GPU must load a portion of the KV cache. Standard MHA requires each device to load 4.5 times the hidden head dimension per word; MLA compresses this to 4.5 times, but because MLA uses a single latent vector, it cannot be split (divided across devices), so each GPU still loads the full 4.5. MLRA breaks the single vector into four branches, so each GPU loads only 1.5 times the head dimension—one quarter of the original.

The paper measures this by counting floating-point operations divided by bytes loaded from memory (arithmetic intensity). MLRA increases this ratio dramatically, meaning the GPU does more actual computation relative to memory traffic, shifting the bottleneck from bandwidth-bound (waiting for data) to compute-bound (limited by how fast the chip can calculate).

Why it works

Why it works: independence through low-rank decomposition

The core idea is to exploit the mathematics of low-rank projection. MLA compresses the KV cache by mapping it into a smaller space (a technique called low-rank compression). This saves memory but creates a single bottleneck: because all attention heads must operate on this one compressed vector, a single GPU must hold the entire vector even when spreading work across many GPUs. MLRA decomposes this into four separate low-rank projections, each producing its own intermediate attention output. Because the final output is simply adding up these four independent computations, the paper reorganizes the numerical operations (multiplying tables of numbers) so that query-side absorption eliminates redundant steps, and each branch can live on a different GPU without any device needing to know about the others.

The mechanism works in three steps. First, the latent KV structures (arrays of numbers) are reorganized into branch-wise form. Second, attention is computed for each branch independently using an optimized code routine (FlashAttention-3), avoiding the need to materialize all four branches in the same place at once. Third, the intermediate outputs are summed and rescaled to preserve the variance that the model learned during training. The rescaling must be applied because summing four independent random variables increases variance; if the rescaling is not applied, the outputs grow too large and the training nudges (gradients) become unreliable. Because each branch is computed independently, each GPU owns exactly one branch and loads exactly one quarter of the cache.

Math after the picture

The equation: branched, scaled attention

First in words:

For each branch, compute the attention logits (query dot product with keys), apply softmax (turn raw scores into percentages), multiply by values, then sum all four branches and scale by the variance correction factor.

Then the compact form:

output = sum_{b=0}^{3} (1/tau) * softmax(Q * KV_branch_b^T) * V_branch_b, where tau = 1/sqrt(d_h + d_R_h)

Every symbol:

Qthe query (what we are looking for)
KV_branch_bthe b-th independent key-value branch
d_hthe hidden head dimension (number count)
d_R_hthe low-rank dimension (how compressed)
tauthe rescaling factor to fix variance
softmax(...)turn scores into percentages that add to 1
A tiny worked example
Suppose d_h = 64 (64 numbers per head) and d_R_h = 16 (low-rank, 16 numbers).
tau = 1/sqrt(64 + 16) = 1/sqrt(80) = 1/8.94 ≈ 0.112.
GPU1 computes branch1 attention output (say result = 0.8 units).
GPU2 computes branch2 attention output (say result = 0.7 units).
GPU3 computes branch3 attention output (say result = 0.9 units).
GPU4 computes branch4 attention output (say result = 0.75 units).
Raw sum = 0.8 + 0.7 + 0.9 + 0.75 = 3.15 units (too large; variance exploded from 0.4 to 3.15).
After rescaling by tau: 3.15 * 0.112 ≈ 0.35 units (back to expected size, training stays stable).

The tau factor corrects for the fact that summing four independent pieces makes the result too large if the pieces were not designed to be summed.

What can go wrong

What can go wrong

Unequal branch spread. If the four branches are not equally sized, some GPUs load more than others. The slowest GPU (the one handling the largest branch) sets the speed for all, because decoding must wait for all GPUs to finish before generating the next word. MLRA requires careful partitioning (dividing the computation into balanced pieces) to keep branch sizes equal.
Initialization instability. The paper found that random initialization with variance 0.02 can cause training to diverge early (first 20 billion words). Zero initialization for output projections fixes this; if initialization is not handled correctly, loss spikes and training fails.
Missing variance correction. If the rescaling factor tau is not applied after summing the four branches, the model outputs grow too large and the gradients (nudges during training) become unreliable.
Done right. When branches are evenly sized, initialization and rescaling are tuned, and the model is trained end-to-end with MLRA, the prediction accuracy stays as good as standard attention while decoding is 2.8 times faster, because each GPU's memory load is one quarter and GPUs finish tasks at nearly the same time.
What a runnable demo should prove

What a runnable demo should prove

Build a small language model (2.9 billion model weights, same as the paper) with MLRA attention on a machine with four GPUs. Train it on a chunk of text data (say 100 billion words). During training, log the loss curve and perplexity (a measure of prediction accuracy). After training, measure decoding latency for a single word when spreading the work across four GPUs. Compare decoding latency against standard MLA and GQA baselines. Measure per-GPU memory usage and confirm each GPU loads only one quarter of the original memory.

speedup = (MLA_latency_per_word) divided by (MLRA_latency_per_word); per_device_cache = maximum memory used on any single GPU during decode

The demo should make it obvious that each GPU's memory footprint is exactly one quarter of MLA, and the decode speedup is between 2.5 and 3.0 times faster than MLA because each GPU finishes its work sooner, so the whole process completes faster.
