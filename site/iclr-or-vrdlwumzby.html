DistDF: Time-series Distribution Alignment

A time-series forecaster learns better by matching the shape of real data, not just the dot-by-dot point predictions.

Paper explainersAll themesTime Series & Sequential

When a weather forecaster trains on daily temperature records, the usual way is to penalize every wrong prediction point-by-point, but this misses something: temperature tomorrow depends on yesterday and the day before—the values are correlated. This autocorrelation makes the standard training signal dishonest. DistDF fixes this by asking: does my model capture the true pattern of how values relate to each other? It measures this by comparing the shape of forecasts against the shape of real data, then trains the model to match that shape.

Zero assumption version

Why point-by-point scoring fails for time series

A forecaster sees a sequence of values (daily temperatures, stock prices, sensor readings) and must learn to predict the next few values. The standard way to train it is to check each forecast point against the ground truth and penalize mismatches using mean squared error, a simple measure of how far off each dot is.

The trap: in real data, consecutive values hang together—they are autocorrelated. Yesterday's temperature affects today's. The model that produces them must capture that pattern or it is lying about the data. But when you score point-by-point, you are not actually checking whether the model understands the pattern—you are only checking predictions in isolation. A model could guess each point perfectly and still be blind to the deeper dependence structure. Because of this hidden dependence, the standard error signal is biased: it misleads the training process away from the true likelihood of the observed sequence.

The problem in one sentence. Point-by-point training assumes each value is independent, but real time series are correlated, so the training signal is dishonest.

The algorithm as a flow

What it actually does

Combine history and forecast into a joint sequence

Stack the past values and predicted future values end-to-end.

Measure mean and covariance of both

Compute how the values scatter and which values move together in real data versus model predictions.

Compute Wasserstein distance

Measure the cost to transform one scatter-pattern into the other.

Blend with a small point-error term

Mix the shape-matching loss with a weak point-wise penalty to keep predictions in the right ballpark.

Train weights toward better pattern matching

The loss signal pushes weights to adjust until the model's covariance (how its predictions co-vary) matches reality's covariance, because the Wasserstein metric rewards this alignment by shrinking the loss.

The hidden quantity

The hidden quantity: conditional covariance structure

measured quantity  =  Dependency pattern strength

The hidden quantity the paper measures is the covariance structure of the joint history-forecast data—how much each value depends on its neighbors. In real time series, this structure is rich: cold days cluster, warm days cluster, and transitions are smooth. A good forecast model must capture this.

DistDF estimates this by computing the mean vector and covariance matrix of the stacked joint data (history concatenated with forecasts), then using the Wasserstein metric (a way to compare two scatter-patterns) to measure the distance between the real covariance and the model-predicted covariance. Smaller distance means the model understands the true dependencies.

Why it works

Why matching the data scatter-pattern beats point-scoring

Autocorrelated data violates the hidden assumption of mean squared error: that each value is independent. When values hang together, the likelihood (the probability of seeing the exact sequence) depends on the whole pattern, not each dot. Minimizing MSE does not actually minimize negative log-likelihood because of this correlation.

DistDF bypasses this by training directly on pattern alignment. The Wasserstein metric compares the scatter-pattern (mean and covariance) of the model's forecasts to the real data's scatter-pattern. When they match, the model has learned the true structure. Training pushes the model to adjust its weights so that its forecasts co-vary with history in the same way the real labels do.

When a model is trained to produce data with the same covariance structure as reality, it implicitly learns how values depend on each other. This sidesteps the bias of point-wise scoring and gives an honest training signal. The small MSE term keeps predictions in the right range; the dominant Wasserstein term ensures the pattern is learned.

Math after the picture

The training loss formula

First in words:

Loss equals gamma times the Wasserstein distance between the covariance structure of real data and predictions, plus one minus gamma times the standard squared error.

Then the compact form:

L_DistDF = gamma * W_p(mean_real, mean_pred, cov_real, cov_pred) + (1 - gamma) * ||Y - Y_hat||_2^2

Every symbol:

gammaweight on the shape-matching term, usually 0.9
W_pWasserstein distance metric, measuring covariance mismatch
mean_realaverage value across the stacked real data
mean_predaverage value across the stacked predictions
cov_realcovariance matrix of real data (how each value correlates)
cov_predcovariance matrix of predictions (model's learned correlations)
Ythe true label sequence
Y_hatthe model's forecast sequence
A tiny worked example
Suppose real data has covariance [4, 2; 2, 3] (strong self-correlation, weak cross-dependence).
Model predictions have covariance [2.5, 0.5; 0.5, 2.0] (weaker structure).
Wasserstein distance W = 0.8 (the cost to reshape model covariance into real covariance).
Point error on 3 forecasts: 0.1, 0.2, 0.3 -> MSE = 0.047.
With gamma=0.9: L_DistDF = 0.9 * 0.8 + 0.1 * 0.047 = 0.72 + 0.005 = 0.725.
Backpropagation nudges weights to increase model covariance [2.5, 0.5; 0.5, 2.0] toward [4, 2; 2, 3], reducing W.

The loss directly targets the covariance gap, so training nudges the model to learn the true dependency structure, not just memorize points.

What can go wrong

What can go wrong

Choosing gamma too high loses point accuracy. If you weight the Wasserstein term too heavily (gamma near 1), the model matches the abstract shape but produces forecasts far from the true values. Gamma should be around 0.8–0.95 to balance shape and magnitude.
Small sample batches make covariance estimates noisy. Covariance matrices computed from only a few examples fluctuate wildly. Batch size should be large enough (at least 32 examples) for stable statistics.
Wasserstein distance requires well-conditioned data. If forecasts have wildly different scales (e.g., one feature is 0-1, another is 0-10000), the covariance matrix becomes ill-conditioned and Wasserstein computation fails or diverges. Normalize all features to the same scale first.
Done right. Use normalized data, batch size at least 32, set the weight on pattern-matching to 0.9, and jointly tune the architecture. DistDF then learns patterns that survive long horizons.
What a runnable demo should prove

What a runnable demo should prove

Build two forecasters: one trained on standard MSE, one on DistDF. Both should use the same neural architecture (e.g., a neural network that reads the full history window all at once with weighted lookback, or a simpler network that applies weights to past values). Train both on a synthetic time series with known autocorrelation (e.g., an autoregressive process: each value is 0.7 times the previous plus 0.2 times the one before that, plus random noise). Measure how well each forecaster preserves the autocorrelation pattern in its predictions.

Autocorrelation preservation = (1 - |autocorr_real - autocorr_predicted| / autocorr_real) * 100 percent

DistDF should show 85-95% autocorrelation preservation across the forecast horizon. MSE should show 40-60% (deteriorating as horizon grows). The difference proves that matching the scatter-pattern works.
