GFMate: Test-Time Graph Prompt Tuning

Instead of baking prompts into a graph model during pre-training, add adjustable prompt knobs at test-time that work on any graph foundation model and use both labeled and unlabeled target data.

Paper explainersAll themesGraph & Geometric Learning

Graph foundation models are pre-trained once, then reused on many new graph tasks. The old way asks: what prompts did we learn during pre-training? But those prompts assume we know the source domain the model trained on. GFMate asks a different question: what prompts can we add AFTER pre-training, at test-time, that will work on any graph foundation model and any new domain, and that can learn from both labeled examples and unlabeled data?

Zero assumption version

The generalization trap

Graph foundation models (large neural networks trained on many graph datasets) are designed to be reusable. You train once, then use the trained model on new tasks. But the old way to make them adapt uses prompts — adjustable numbers embedded into the training process itself, tied to the source domain the model was trained on.

That creates two problems. First, those source-domain prompts only work well on the target domain if the target looks similar to the source — switch to a very different kind of graph, and the old prompts are dead weight. Second, the prompts were baked in during pre-training, so they cannot be adapted to new domains without retraining the whole model. Third, once you have a labeled test set, existing methods use only the labeled examples to adjust the prompts; they throw away all the unlabeled data (the target graphs without ground-truth labels).

What a beginner would try: add adjustable numbers to the model at test-time and train them on the labeled examples. But without information about what the new domain looks like baked into those numbers, they will not capture the structure of the new domain well enough to make large improvements.

In one sentence. Add adjustable prompt knobs that live outside the model architecture, apply them to adapt any graph foundation model at test-time, and train them using both labeled and unlabeled target domain data.

The algorithm as a flow

What it actually does

Start with a pre-trained graph foundation model

A neural network trained on one type of graphs, ready to use on new tasks.

Attach two sets of learnable prompts

Centroid prompts (node-level) and layer prompts (depth-level), added to the model after pre-training.

Collect labeled and unlabeled data from the target domain

Some graphs with ground-truth labels, many more without.

Run a complementary learning objective

One training goal learns from labeled data, another goal uses unlabeled data to steer the first toward plausible structure. Both together pull the prompts toward the target domain.

Update only the prompts, leaving the model unchanged

No retraining; the model weights stay fixed, only the new prompt numbers change.

What the paper changes

The one thing the paper changes

The paper changes the prompts — the adjustable numbers. Old prompts were embedded into the model during pre-training; new prompts are added after, at the boundary between the model and the data. They are called centroid prompts (one adjustable knob per node type or summary) and layer prompts (one adjustable knob per depth in the model). These are the only things that change.

the object it moves  =  the prompts
The hidden quantity

The hidden quantity: Prompt-target alignment

measured quantity  =  prompt-target alignment

The paper measures how well the learnable prompts have adapted to the target domain's structure. This is not directly observable in the model weights — you cannot open the model and see a single number called alignment. Instead, the paper infers it from how much the prompts have changed during training on the target domain, and how well the resulting model predictions match ground truth on test graphs.

The paper estimates this by running a complementary learning objective: one part of the training loss measures supervised error (labeled graphs), the other part measures unsupervised error (unlabeled graphs). The gap between them signals how well the prompts have locked in to the target domain. When both losses shrink together, alignment is high.

Why it works

Why separate, adjustable prompts work

The core insight is decoupling: source-domain knowledge should live in the model (frozen), and target-domain knowledge should live in the prompts (adjustable). Old methods entangled these two, so when the source domain differs from the target, the prompts fought the model. GFMate separates them.

Here is why this works mechanically. A graph foundation model, when applied to a new domain, reads the input graph and passes it through fixed layers. Without adaptation, each layer uses the same weights it was trained with on the source domain. Adding a prompt at the input (centroid) and at each layer (layer prompts) gives those weights new context. The prompts are adjustable knobs, so during test-time training, they shift to say: given this model's fixed weights and this new domain, how should we rescale the signal at each point to make the model's output correct? Because the prompts are independent of pre-training, they work on any model and any domain. Because we train them on both labeled and unlabeled target data, they capture the full structure of the target domain, not just what a few labeled examples show.

The complementary learning objective enforces this: the labeled loss pulls the prompts toward the ground-truth labels, while the unlabeled loss (typically using consistency or uncertainty penalties) pulls them toward plausible graph structure. Together, they prevent the prompts from overfitting to the few labeled examples.

Math after the picture

The learning objective

First in words:

total loss equals supervised loss on labeled examples plus unlabeled regularization weighted by a balance parameter lambda

Then the compact form:

L_total = L_sup(P, labeled_graphs) + lambda * L_unsup(P, unlabeled_graphs)

Every symbol:

Plearnable prompt parameters (centroid and layer prompts combined)
L_supsupervised loss (prediction error on labeled graphs)
labeled_graphstarget graphs with ground-truth labels
L_unsupunsupervised loss (structure consistency on unlabeled graphs)
unlabeled_graphstarget graphs without labels
lambdabalance weight between supervised and unsupervised
A tiny worked example
Suppose we have 10 labeled graphs and 90 unlabeled graphs in the target domain.
L_sup on the 10 labeled graphs: sum of prediction errors = 0.8 (the model misclassifies some nodes).
L_unsup on the 90 unlabeled graphs (uncertainty penalty): measure of inconsistency = 2.4.
Set lambda = 0.5 (balance labeled and unlabeled equally in this example).
L_total = 0.8 + 0.5 * 2.4 = 0.8 + 1.2 = 2.0.
Training reduces both losses: after adaptation, L_sup = 0.3 and L_unsup = 0.8, so L_total = 0.3 + 0.5 * 0.8 = 0.7.
The prompts have adapted so that the model makes fewer prediction errors and its node features are more consistent across unlabeled graphs.

The equation balances learning from labeled examples (supervised) and using unlabeled data for steering (unsupervised), with the prompts as the only adjustable numbers.

What can go wrong

What can go wrong

Weak unsupervised signal. If the unsupervised loss is poorly designed, unlabeled data might mislead the prompts instead of guide them. For example, if the uncertainty penalty is too strong, the model might converge to all nodes receiving the same prediction.
Domain shift too large. If the target domain is radically different from any domain in the model's pre-training (e.g., the model trained on citation networks, target is biological networks with very different structure), the fixed foundation model's hidden layers might not encode the right features, and no prompt can compensate.
Wrong balance weight. The balance weight lambda between supervised and unsupervised loss is a hyperparameter. If lambda is too high, the unsupervised loss dominates and the prompts ignore labeled examples; if too low, unlabeled data is wasted.
Done right. When the unsupervised loss is well-tuned (e.g., consistency loss that pulls similar nodes together), the target domain is reasonably close to pre-training, and lambda is chosen via validation, GFMate adapts the prompts to the target domain without retraining the model.
What a runnable demo should prove

What a runnable demo should prove

Build a small experiment: take a graph foundation model pre-trained on one type of graph (e.g., social networks), and test it on a different type (e.g., biological protein networks). Measure accuracy on labeled protein nodes before and after test-time prompt tuning with GFMate. Include two variants: (1) prompt tuning on labeled data alone, (2) prompt tuning with complementary learning (labeled plus unlabeled). Show that variant 2 wins.

improvement = accuracy_after_tuning - accuracy_before_tuning

The demo must make it visually clear that adding unlabeled data to the tuning process — via the complementary learning objective — pushes the adapted model's accuracy higher than labeled-only tuning, proving that the prompts are learning from the unlabeled target structure.
