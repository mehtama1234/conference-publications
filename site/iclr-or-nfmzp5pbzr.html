PAGE-4D: Disentangling Static and Dynamic in 4D Perception

When a 3D model learns on still scenes, it gets tricked by moving people—PAGE-4D teaches it to notice what is moving and handle it differently.

Paper explainersAll themesComputer Vision

Deep learning models that reconstruct 3D scenes work well when everything stands still. But in the real world, people walk, objects shift, umbrellas blow in the wind. These same models trained only on static video fall apart—they mistrack the camera, misestimate depths, and produce broken point clouds. PAGE-4D fixes this by teaching a model to first detect which pixels hold moving things, then use that detection to separately guide two different tasks: camera tracking ignores the movers (so they don't misdirect it), while 3D reconstruction embraces them (so it can capture their shape accurately).

Zero assumption version

Models trained on still scenes stumble in motion

A transformer model called VGGT learns 3D from video: it watches frames and outputs the camera position (pose), depth of each pixel (how far away things are), and 3D point locations (coordinates in space). It works because video of still scenes is consistent—the same wall corner stays in the same place, the same tree is always at the same distance.

But send VGGT a video of a walking person, a waving flag, a rolling ball—anything that moves—and it breaks. A naive approach would be to retrain the whole model on dynamic video, but that demands huge datasets of people moving in complex ways and massive compute.

The core trap: when something moves between frames, VGGT's attention (the mechanism that glues information across frames) treats motion as if it were a scene change. The camera tracker gets confused, thinking the frame shift is camera motion rather than object motion. The depth predictor gives wild guesses near the moving regions. The point cloud looks like a blurry ghost where people stood.

In one sentence: PAGE-4D teaches the model to label which pixels hold dynamic things, then uses that label to steer camera tracking and 3D reconstruction tasks in opposite directions.

The algorithm as a flow

What it actually does

Freeze most of the model

The original VGGT is left unchanged—only the middle 10 layers (30% of it) get adjusted, because those layers capture mid-level patterns about regions and spatial relationships.

Add a mask prediction head

A new small module learns to score each pixel from 0 to 1: is this pixel in a dynamic region or static region?

Route dynamic info via attention masks

The scores become masks that plug into the transformer attention math, selectively blocking or passing information.

Apply mask differently for two tasks

For camera pose estimation: suppress dynamic regions (zero them out in attention). For 3D reconstruction (depth and point maps): emphasize dynamic regions (keep them in attention).

Train only on small dynamic datasets

The model learns to handle motion well using just limited dynamic video, because most of the learned structure (from static training) stays frozen.

What the paper changes

What the paper changes

The paper modifies the attention mechanism—the way the transformer mixes information across frames. Specifically, it adds a learned mask that acts as a gate: some regions of the mask let information through freely, others block it.

The hidden quantity

The dynamic region mask

measured quantity  =  dynamic region label (per-pixel fraction moving)

This is a map, pixel by pixel, of how much each location is moving. It is a number from 0 to 1 for each pixel: 0 means static (the pixel content is nearly identical between frames), 1 means fully dynamic (the pixel shows a completely different thing frame to frame).

The paper learns to predict this mask using a new small module (a mask head). The module looks at the hidden patterns the transformer is already computing and outputs a probability that each pixel is dynamic. This is learned in a self-supervised way (the model figures out which regions change between frames by watching unlabeled video).

Why it works

Why predicting dynamics and routing by opposite rules works

Camera pose estimation (where is the camera now?) depends on spotting the same landmark in different frames and measuring how much the frame shifted. A moving person looks like a landmark has moved, which looks like the camera moved—false signal. By suppressing dynamic regions (zeroing them in attention), the pose tracker only sees static landmarks. It ignores the moving person and correctly infers the camera did not move much.

Depth and point-cloud reconstruction (how far away is this thing? What is its 3D coordinate?) need to track the moving person across frames and build a 3D model of its shape. Suppressing the dynamic regions would erase this information. Instead, the paper keeps dynamic regions live (full attention weight) for the 3D reconstruction tasks. The transformer can now see the person across frames and reconstruct their 3D form.

By using the same mask in opposite ways (suppress for pose, keep for 3D reconstruction), the paper makes one small learned mask serve both tasks. The middle layers, which model regional relationships, are fine-tuned to output this mask and adjust their attention logic. The lower layers (which capture local details) and upper layers (which output final predictions) stay frozen, preserving the 3D knowledge the model learned from static training.

Math after the picture

The mask attention equation

First in words:

For each layer, attention scores are computed as query times key, then scaled by the dynamic mask. Dynamic masks suppress those scores for pose, keep them for geometry.

Then the compact form:

Attention_pose = Attention * (1 - M); Attention_geom = Attention * M

Every symbol:

Attentionthe standard transformer attention score matrix (query dot key, normalized)
Mthe learned dynamic mask matrix (per-pixel probability of motion, 0 to 1)
Attention_posefinal attention weights for camera pose task (dynamic regions zeroed)
Attention_geomfinal attention weights for geometry tasks (dynamic regions kept)
A tiny worked example
Say a pixel has attention score 0.8 (strong connection across frames) and mask value 0.6 (moderately dynamic).
For pose: 0.8 multiplied by 1 minus 0.6 gives 0.8 times 0.4 gives 0.32. Connection is muted because region is moving.
For 3D: 0.8 multiplied by 0.6 gives 0.48. Connection is mostly kept because we want to model the moving thing.
Same pixel, same attention, different output: pose ignores motion, 3D embraces it.

The mask is learned during fine-tuning; once trained, it is applied when the finished model runs to gate information for each task.

What can go wrong

What can go wrong

Mask mislabels a static region as dynamic. If the model incorrectly marks a waving tree branch as dynamic, pose estimation will ignore it—possibly losing a reliable landmark. The camera position could drift.
Mask misses a dynamic region. If a moving person is marked static, the pose tracker will be fooled by their motion and output the wrong camera position.
Occlusions break the mask. When a moving object hides a static landmark, the mask prediction sees a discontinuity and may label that region incorrectly.
Mask is learned well and tasks agree. With enough dynamic training data and careful fine-tuning of the middle layers, the mask becomes reliable. Both pose and 3D reconstruction improve because the mask correctly routes information, letting pose focus on static anchors while 3D keeps the moving regions.
What a runnable demo should prove

What a runnable demo should prove

Take a video clip of a person walking in a room (static background, dynamic human). Run three models: the original VGGT, VGGT retrained fully on dynamic data, and PAGE-4D. Measure camera pose error (how accurately does each model report the camera did not move?), depth error (how close is the predicted depth to the true depth?), and point cloud accuracy (how well does the reconstructed 3D match the ground truth?).

pose_error captures angle and distance mistakes; geometry_error measures depth mistakes; proof shows PAGE-4D_pose_error below VGGT_pose_error and PAGE-4D_depth_error below VGGT_depth_error

PAGE-4D should beat the original model on both camera tracking and 3D reconstruction without requiring massive dynamic retraining, and should match or beat the fully retrained baseline on dynamic scenes while remaining fast.
