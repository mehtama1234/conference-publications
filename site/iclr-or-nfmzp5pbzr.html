PAGE-4D: Disentangled Pose and Geometry for Moving Scenes

When a camera watches a scene with moving objects, separate the moving parts from the static walls so each task can see what actually matters.

Paper explainersAll themesComputer Vision

A camera model trained on still photos learns to guess the scene's shape and the camera's position. But when people walk or umbrellas sway, those models break — they get confused by the motion and give wrong answers. PAGE-4D adds a new detector that spots which pixels are moving, masks them out temporarily, and tells each downstream task whether to ignore them or handle them differently.

Zero assumption version

Static models on a moving world

A typical 3D understanding model (trained on still images of rooms and objects) learns patterns: walls are flat, chairs sit still, light bounces predictably. These patterns work great when nothing moves. But add a walking person or a waving flag, and the model's training data never showed that combination — it gets confused.

A naive fix: just train the model on dynamic videos instead. Problem: dynamic video datasets are small and expensive to record; retraining from scratch eats computation. The model has already learned the static part well. Throwing that away and starting over is wasteful.

In one sentence. PAGE-4D adds a dynamics detector that masks moving pixels, then uses that mask to guide each task (pose, depth, tracking) so they treat motion separately from the static scene shape.

What the paper changes

What the paper changes

The paper adds a dynamics-aware mask: a new detector that runs before the main model and flags which pixels are in motion. This mask then guides the model's global attention mechanism — telling it to handle moving and static regions differently, instead of treating the whole frame as one uniform static scene.

The hidden quantity

The hidden quantity: Motion signal

measured quantity  =  pixel-wise motion presence

The hidden quantity is a pixel-by-pixel flag: which pixels are moving between frames, and which are stationary. This is not directly the camera motion or object shape — it is the raw signal of change. The detector learns to predict this by comparing pixel positions across consecutive video frames.

PAGE-4D estimates this motion signal using a learned network that takes two consecutive frames as input and outputs a binary or soft mask. Every pixel gets a score (0 to 1 or binary flag) indicating whether it belongs to a moving object. The downstream tasks then condition on this mask — the pose estimator learns to ignore moving pixels when computing camera rotation, the depth model treats moving regions as unreliable, and the tracker uses the mask to identify points to follow.

Plain reading. Before processing, the model asks: where is stuff actually moving? It marks those pixels. Then it tells the pose detector 'ignore the marked moving pixels' and tells the tracking module 'track these marked pixels extra carefully'.
Paper reading. The dynamics-aware aggregator predicts a motion presence mask M via a learned module that consumes optical flow or frame differences. This mask is then broadcast into the global attention mechanism so that dynamic and static patches are routed to separate or differently-weighted attention heads.
Why it works

Why the mask fixes the problem

A model trained only on static images has no examples of how things look when they move. Its learned patterns are: this shape of shadow means wall-corner, this color pattern means carpet, this depth gradient means floor. When a person moves across the floor, the patterns contradict the static world, and the model is forced to choose — it often guesses wrong.

PAGE-4D adds a motion detector that runs first. Once the model knows which pixels are moving, it can make better decisions about the other pixels. The pose estimator can say: 'I only use the static pixels to measure how the camera turned, so ignore those moving people.' The depth model says: 'Those pixels are too unreliable; I will output uncertainty there or trust other cues.' The tracker says: 'Those are the pixels I need to follow frame-to-frame.' Each task gets smarter because it knows which data to trust.

This is efficient to train because the base model (VGGT) was already well-trained on static scenes. You are not retraining everything — you add a lightweight motion detector, fine-tune the attention mechanism to use the mask, and the model quickly learns how to separate the two problems. With only a little dynamic video data, the mask acts as a teacher signal that guides the existing model to hold its static understanding steady while adding motion awareness: the static branch keeps working where there is no motion, and only the new dynamic branch activates where the mask flags movement.

The motion-weighted output formula

First in words:

output for each pixel = (static task output if pixel is unmasked) + (dynamic task output if pixel is masked). The attention mechanism learns separate weights for masked and unmasked regions.

Then the compact form:

output_i = (1 - M_i) * static_i + M_i * dynamic_i, where M_i in [0,1] is motion presence at pixel i

Every symbol:

output_ifinal prediction for pixel i
M_imotion mask score for pixel i, from 0 (static) to 1 (moving)
static_ioutput from the static geometry branch
dynamic_ioutput from the motion-aware branch
A tiny worked example
Pixel 1 is a wall (static): M_1 = 0.1, static_1 = 0.95 confidence in depth, dynamic_1 = 0.50. Output: (1 - 0.1) * 0.95 + 0.1 * 0.50 = 0.9 * 0.95 + 0.1 * 0.50 = 0.855 + 0.05 = 0.905.
Pixel 2 is a person (moving): M_2 = 0.9, static_2 = 0.30 (confused), dynamic_2 = 0.85 (correct). Output: (1 - 0.9) * 0.30 + 0.9 * 0.85 = 0.1 * 0.30 + 0.9 * 0.85 = 0.03 + 0.765 = 0.795.
The mask smoothly blends: when the detector is sure something is moving, it trusts the dynamic branch; when it is sure it is static, it trusts the static branch learned from the original training.

The mask acts as a soft switch: pixels marked as moving are routed to or weighted toward outputs tuned for motion, while static pixels trust the original static model.

What can go wrong

What can go wrong

Motion detector fails on subtle motion. If an object moves very slowly or is partially occluded, the detector might not flag it. Then the static branch still makes wrong guesses. Result: depth or pose is still poor in those regions. Fixing this requires either higher-quality motion labels or a more sensitive detector.
Not enough dynamic training data. If the fine-tuning video sequences do not cover the kinds of motion at test time (e.g. you train on walking humans but test on moving animals), the model has not learned what dynamic branch outputs look like in that case. Result: the mask works, but the dynamic predictions are still wrong.
Mask boundaries cause artifacts. At the edge between a moving and static pixel, the attention can oscillate or create blur. The mask is binary or soft, but the actual physics of occlusion and disocclusion is sharp. Result: depth or pose estimates near moving object boundaries can have artifacts.
Done right. Train the detector on real optical flow or frame difference; ensure the dynamic branch sees diverse motion types during fine-tuning; smooth the mask at boundaries using learned blur weights. Then all tasks inherit clean separation and make predictions that do not contradict the actual motion in the video.
What a runnable demo should prove

What a runnable demo should prove

Download a short video clip (or use a toy sequence) with a moving person walking past a static background. Run PAGE-4D on it. Extract the per-frame camera pose (how the camera moved), depth estimates, and point trajectories (how 3D points moved across frames). Compare the outputs to a baseline that does not use the motion mask.

pose_error_dynamic = absolute error in camera rotation between static model and PAGE-4D on frames with people moving; depth_error_dynamic = RMS error in depth map on moving regions; trajectory_stability = whether tracked points follow smooth, plausible paths across frames.

The demo must show that on the same video, the model with the motion mask makes predictions that are smoother, more accurate, and internally consistent across time — the camera pose does not jitter because the mask lets the model ignore moving objects when computing rotation, the depth map does not flip because moving regions are marked unreliable, and tracked points form coherent trails because the mask explicitly guides the tracker to follow marked pixels.
