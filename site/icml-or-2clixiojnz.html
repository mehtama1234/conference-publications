Maximum-Likelihood Learning of Latent Dynamics Without Reconstruction

Stop wasting neural capacity on fake reconstructions; measure dynamics directly and learn what actually moves.

When reconstruction wastes the model's brain

A video shows a robot arm picking up a box. The model must learn the arm's real motion: how its joints bend, how forces propagate. But the video also has shadows, reflections, camera jitter—noise that does not matter to the physics.

Standard generative models (autoencoders, VAEs, diffusion models) force the neural network to solve two jobs at once: (1) learn the true dynamics, (2) rebuild the exact pixels or measurements. A beginner would say: fine, let the model do both. But neural capacity is a fixed budget. Every bit of computing power spent reconstructing irrelevant shadows is power NOT spent on discovering the true dynamical laws.

Existing approaches fail in predictable ways: generative models conflate noise with signal and learn 'dynamics' that just replay the distractors; contrastive methods learn what changed but not why it changed (the causal mechanism). The paper shows the solution is radical: remove the decoder entirely. Stop trying to rebuild the measurements. Train only on what you can truthfully infer about state and motion from the data.

In one sentence. The model learns latent dynamics (how hidden states evolve) by maximum likelihood, without ever reconstructing the original measurements.

What the paper changes

What the paper changes

The single object: remove the decoder (the branch that rebuilds measurements). In a standard autoencoder pipeline, data flows in, encoder compresses, a latent dynamics model predicts, and a decoder reconstructs. RP-GSSM eliminates the decoder entirely. The latent dynamics model is trained purely by how well it predicts the hidden state of the next frame, not by how well the reconstructed pixels match the original.

The hidden quantity

The hidden quantity: prediction error in latent space

measured quantity  =  Latent prediction error

The paper introduces a new signal that standard models do not directly measure: how far off the predicted hidden state is from what the encoder actually infers from the next frame. This is the 'latent prediction error'—the distance between 'where the model thought the state should move' and 'where the encoder says the state actually moved.'

In a standard VAE, this error is invisible; the training signal comes from reconstruction loss (pixels) plus penalty terms that keep the representation smooth. In RP-GSSM, this latent error is the signal. The model learns by gradient descent on this error directly. High error means the assumed dynamics are wrong; the model adjusts its state-space parameters (the matrices that define how linear motion happens in latent space) to shrink the gap. Over time, the learned dynamics converge to the true motion laws that generated the data.

Why it works

Why it works: freed capacity finds real dynamics

Standard generative models perform a Faustian bargain: maximize likelihood of the data by learning both a clean latent space and a perfect decoder. The model splits its finite neural budget between these two goals. Distractors (shadows, noise) crowd into the learned representation because the decoder must account for them to minimize reconstruction error.

RP-GSSM breaks the bargain by removing the decoder. Now the only job is: make the state-space model predict the next hidden state accurately. The encoder (which reads the video) stays fixed—it is not trained. The only parameters learned are the state-space matrices (the linear dynamics). This creates a clean separation: the encoder can encode anything; the training signal only cares about prediction in latent space.

Why does this work? Because the latent prediction error is now purely about motion, not about noise reconstruction. If the encoder captures a shadow, that shadow appears in both the current and next frame's encoding (or varies randomly). The linear state-space model cannot predict random variation—it can only lock onto the pattern that repeats with mechanical regularity, which is the true dynamics. Noise and distractors average out; dynamics accumulate. Over many frames and many training steps, the state-space model converges to the true motion laws. Meanwhile, the encoder learns a representation where the truly dynamical features stand out.

Math after the picture

The likelihood equation

First in words:

Maximize the probability that the state-space model predicts the actual hidden state of each future frame, under a Gaussian assumption.

Then the compact form:

log p(h_t | h_{t-1}) = -0.5 * ||h_t - A*h_{t-1}||^2 / sigma^2 + const

Every symbol:

h_thidden state (encoder output) at time t
h_{t-1}hidden state at the previous time step
Athe state-space matrix (defines linear motion)
sigmathe standard deviation of prediction noise
||...||^2squared length of the difference vector
A tiny worked example
Frame t encodes to hidden state: h_t = [3.0, 2.0, 1.0] (three numbers).
State matrix predicts next frame: A * h_t = [3.0, 1.5, 0.5].
Frame t+1 actually encodes to: h_{t+1} = [3.5, 2.0, 0.8] (measured from data).
Prediction error: [3.5-3.0, 2.0-1.5, 0.8-0.5] = [0.5, 0.5, 0.3].
Squared error: 0.5^2 + 0.5^2 + 0.3^2 = 0.25 + 0.25 + 0.09 = 0.59.
If sigma=1.0, log-likelihood penalty is -0.59. Learning adjusts matrix A to shrink this penalty in future steps.

The equation says: how likely is the observed next state under the model's prediction? Higher likelihood (lower error) means the learned dynamics are accurate.

What can go wrong

What can go wrong

The encoder is not learned. RP-GSSM assumes the encoder is already good (or fixed). If the encoder throws away dynamically relevant information, no amount of state-space learning will recover it. The model is only as good as the frozen encoder.
Linear dynamics assumption breaks for highly nonlinear systems. The state-space model assumes motion is linear in latent space (the matrix A defines straight-line predictions). Real systems like a pendulum or rotating rigid body have curved, nonlinear trajectories. If the encoder does not linearize the system, the model will miss true dynamics and settle for a poor approximation.
No reconstruction means no sanity check. In a standard VAE, if the reconstructed image looks nonsensical, you know something is wrong. RP-GSSM has no visual output, so a bad learned model might silently predict the next hidden state poorly without human awareness.
Works well when done right. If the encoder is trained to linearize intrinsic nonlinear dynamics, the state-space model can capture motion accurately, because the compressed feature space is no longer crowded with reconstruction detail—all model capacity serves prediction. Standard models must also minimize reconstruction loss, which pulls the model toward reconstructing noise; RP-GSSM has no such competing objective, so it converges to physically correct latent dynamics faster and cleaner.
What a runnable demo should prove

What a runnable demo should prove

Build a simple synthetic dynamic system (e.g., a pendulum swinging under gravity, or a 2D point bouncing on a wall). Generate video frames. Train an encoder on unlabeled frames (or use a fixed pretrained encoder). Train RP-GSSM on the hidden states. Measure: (1) Does the learned state-space matrix A correctly predict future hidden states on held-out frames? (2) Can you extract the ground-truth system parameters (pendulum angle and angular velocity, or ball position and velocity) from the learned latent states? (3) Does prediction accuracy drop when you add visual distractors (colored noise, moving background)? (4) Compare: RP-GSSM should recover the true dynamics; a standard VAE trained on the same data should fit the visual distractors instead and fail at accurate dynamics.

Dynamics accuracy = (1 - mean_absolute_error_on_held_out_predictions) * 100

The demo should make impossible to miss: remove the decoder, and the model learns the true motion laws rather than visual reconstruction.
