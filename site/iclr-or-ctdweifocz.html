LINK: Learning Instance-level Knowledge from Vision-Language Models for HOI Detection

LINK teaches a model to detect human-object interactions by having a teacher network generate dense pairs to learn from, so it can work in both labeled and unlabeled scenarios.

Paper explainersAll themesComputer Vision

Detecting when a person is doing something with an object (drinking from a cup, sitting on a chair) is hard because there are so few labeled examples. LINK solves this by using a teacher network that generates dense supervision over all possible person-object pairs, then learns from contrasting what the pair actually is versus what it could have been, making the learned patterns transfer to new scenarios and new objects.

Zero assumption version

Sparse labels and the unlabeled-data wall

Today, if you want to teach a model to recognize human-object interactions, you need thousands of hand-labeled examples: person-A holding cup, person-B sitting on chair, person-C grasping tool. This is expensive. So most datasets have only a few labeled pairs, and the model never sees the hundreds of other configurations.

A naive approach: train on the labeled pairs directly. The model memorizes those exact setups, but fails on a new person in a new pose with a new object. Even worse, if you try to use the model on an interaction type that has no labels at all (open-vocabulary), it guesses randomly.

The core problem. You have few labeled person-object pairs, no unlabeled pairs to learn from, and no path to handle new object classes.

The algorithm as a flow

What it actually does

Encode the image and text

Human-Object Geometrical Encoder reads the spatial layout; VLM Linking Decoder reads language descriptions of interactions.

Teacher proposes pairs

For every detected person and object, generate all possible combinations and label each real or fake.

Contrast positive and negative

Push real pairs close in the representation space, pull non-real pairs far away.

Student learns from the signal

Each update teaches the student to distinguish true interactions from plausible but false ones.

Plug into any detector

The architecture works with any object detector, so you can swap in newer ones without retraining.

What the paper changes

What the paper changes

Instead of training only on labeled pairs, LINK generates all possible person-object pairs (dense supervision) via a teacher network, then teaches the student to discriminate which ones are real interactions and which are not.

the object it moves  =  dense pair generation via teacher
The hidden quantity

The discriminative signal: contrast between real and false pairs

measured quantity  =  interaction discriminativeness

The hidden quantity is how sharply the model can tell apart a real interaction (person sitting on chair) from a plausible false one (person grasping a chair). A sharp boundary means the learned features capture genuine spatial and semantic cues, not just memorized patterns.

LINK measures this by contrasting every positive (real) pair against many negative (generated, false) pairs in a learned feature space. The distance between positive and negative representations (the lists of numbers the model learns to compute) is the discriminative signal. The larger and more consistent that gap, the more transferable the learned patterns.

Why it works

Why contrasting dense pairs solves sparse labels

Sparse labels mean the model only ever sees a handful of correct person-object pairs. If it trains directly on those, it learns brittle patterns: this exact pose with this exact object means sitting. A small change in pose, lighting, or person identity breaks the pattern.

By generating all possible pairs and contrasting real ones against false ones, LINK forces the model to learn the underlying spatial and semantic reasons why person+chair means sitting: the spatial arrangement (person positioned above object, body angled downward), the semantic relationship (chairs support people). These reasons survive a new person, a new lighting, a new chair. The teacher-student structure also lets the model learn from unlabeled data: the teacher proposes pairs even without labels, the student contrasts them anyway, and slowly builds patterns that generalize.

The Geometrical Encoder captures how person and object are positioned relative to each other, and the VLM Linking Decoder brings in language understanding (what does sitting even mean linguistically). Together, they build a representation where real interactions cluster densely and false ones stay far away, in a way that survives shifts to new poses, new objects, and new classes never seen during training.

The contrastive learning equation

First in words:

The loss penalizes the distance between a real interaction embedding and a negative embedding, plus a regularization term that smooths the weights.

Then the compact form:

loss = -log( exp(sim(pos) / tau) / (exp(sim(pos) / tau) + sum_j exp(sim(neg_j) / tau)) ) + lambda * ||theta - theta_prev||^2

Every symbol:

sim(pos)similarity (dot product) between real pair embedding and query
sim(neg_j)similarity between false pair j and query
tautemperature: scales the sharpness of the contrast (lower tau = sharper boundary)
lambdaweight on regularization: controls how much to stay close to previous weights
thetacurrent model weights
theta_prevweights after previous training step
A tiny worked example
Real interaction (person sitting on chair): similarity = 0.95
False interaction 1 (person grasping chair): similarity = 0.40
False interaction 2 (person holding chair): similarity = 0.35
With temperature tau=0.07: exp(0.95/0.07) is huge (exp~135), exp(0.40/0.07) is exp~57, exp(0.35/0.07) is exp~50
The ratio strongly favors the real interaction; the loss pushes the model to make that ratio even more lopsided.
After many steps, real pairs score ~0.95 consistently, false pairs drop to ~0.20, and the boundary is sharp.

The temperature tau controls the sharpness of discrimination: lower temperatures make the model less forgiving of close-but-wrong pairs, pushing it to learn finer spatial and semantic distinctions.

What can go wrong

What can go wrong

Temperature too high or too low. If tau is too high, the model learns fuzzy boundaries and confuses similar interactions. If tau is too low, it overfits: only the exact training examples get high scores, new poses fail. Tuning tau is critical.
Teacher proposes only obvious false pairs. If the teacher generates only easy negatives (sitting versus flying), the student never learns to discriminate hard cases (sitting versus squatting). The model needs challenging negatives to build sharp boundaries.
Imbalanced positive-to-negative ratio. If there are many false pairs and few real ones, the model sees mostly negative examples and learns a collapsed representation (all pairs push away, nothing clusters). A balanced sampling strategy is essential.
Done right. Tune tau by testing multiple values and picking the one that performs best; sample hard negatives (plausible but false pairs) from the training set; balance positive and negative batches; validate on held-out classes before trusting zero-shot performance.
What a runnable demo should prove

What a runnable demo should prove

Build a minimal HOI detector on one small dataset (e.g., 20 labeled person-object pairs from a subset of HICO-DET). First, train a naive baseline that only uses labeled pairs. Then train LINK: use a pretrained teacher to propose all pairs, apply contrastive loss, and measure performance on held-out labeled pairs and on a completely new interaction class (e.g., if you trained on sitting/holding/grasping, test on carrying).

transfer_gain = (accuracy_novel_class_with_LINK - accuracy_novel_class_naive) / accuracy_novel_class_naive

The demo must show that the same model trained on sparse labels plus dense contrastive pairs achieves higher accuracy on held-out labeled pairs and much higher accuracy on unseen classes than the naive baseline, because contrasting real and false pairs forces the model to learn spatial and semantic patterns instead of memorizing exact examples.
