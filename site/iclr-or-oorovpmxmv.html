Implicit Step Rewards for Agentic RL

Instead of relying on a human to label every step in a task, a language model agent learns which steps are good by comparing full attempted paths.

Paper explainersAll themesAgents & Tool Use

Training a language model to act as an autonomous agent (plan, use tools, react) via reinforcement learning is hard because you rarely have clean reward signals at each step. This paper introduces iStar, a technique that lets an agent discover which steps helped or hurt by learning from comparisons between whole trajectories (full sequences of actions), without requiring human labels for every action.

Why step-by-step credit assignment breaks down

When you train an agent (a language model that picks actions like 'search for product' or 'click link'), you want to reward it for reaching a goal. But the agent takes many steps to reach the goal. If you only give a reward at the very end, it is nearly impossible to tell which of the 20 steps actually helped. A naive approach is to have a human write down which steps were good and bad — but that is expensive and introduces mistakes.

Another approach: ask a reward model to score each step individually. But isolated steps are hard to judge. A step like 'open a new tab' makes sense in context (you were searching for information) but looks random on its own. So the scores bounce around randomly because the model has no context. Or, the agent finds loopholes: a step that the reward model accidentally scores highly, even though it does not help the real task — the model was tricked because it only saw the step, not the bigger picture.

The method in one sentence. iStar trains an implicit reward model that looks at full attempted paths and assigns rewards to individual steps without needing human labels for each step.

The algorithm as a flow

What it actually does

Collect pairs of trajectories

Run the agent twice: once it completes the task, once it fails or gets fewer rewards than the first attempt.

Train a comparison model

Feed both full paths to a model that learns to say which one performed better, by watching which sequences led to success in previous training runs.

Infer step-level signals

The model learns: steps that appear in good trajectories but not bad ones are worth rewarding; steps only in bad trajectories are worth avoiding.

Assign step rewards without labels

For each action in the current trajectory, estimate its contribution to the overall success without asking a human to label which steps are good.

Train the agent on both levels

Update the agent using step-level guidance (which action locally helped) and trajectory-level guidance (did the whole path succeed) together.

What the paper changes

What the paper changes

The paper replaces an explicit process reward model (a separate neural network trained on human-labeled step annotations) with an implicit process reward model that derives step-level credit signals directly from trajectory-level comparisons using a technique called direct preference optimization (turning trajectory preferences into estimated step rewards).

The hidden quantity

The step-level credit signal

measured quantity  =  Implicit process reward

An implicit process reward is a hidden score, not directly observed, that estimates how much each individual action contributed to the overall success of the attempt. A process reward model trained on human labels (explicit) asks a human to mark which steps are good and which are bad. This paper derives the same signal differently: from comparing full trajectories instead.

The paper estimates it by training a preference model (using direct preference optimization, a method that learns which trajectory is better without requiring explicit reward numbers) on pairs of full trajectories. As the model learns to distinguish good paths from bad ones, its internal parameters—its numerical weights—start to favor steps that appear in successful trajectories over steps that appear only in failures. Then, these inferred step rewards are fed back into the policy update. This creates a cycle: the agent explores using better step guidance, so it tries actions that the model predicted would help. This exploration collects new trajectory pairs where success and failure are further apart (not just barely succeeded vs barely failed, but clear wins vs clear losses). Clearer pairs give the preference model less ambiguous examples to learn from, so its predictions sharpen. Sharper predictions refine the step rewards. The cycle repeats.

Why it works

Why comparing trajectories works

You do not need to know the correct score for each step in isolation; you only need to know which path was better, because you can infer which steps made the difference by process of elimination. Suppose path A (ten actions) succeeded and path B (ten actions) failed. If step 7 appears only in path A and appears in no failed paths, then step 7 is probably responsible for success. If steps 1 through 5 appear in both paths, they probably do not matter—they are equally common in success and failure. By comparing many trajectory pairs, the model accumulates evidence: steps that are more common in successes than in failures rank higher; steps that are more common in failures rank lower.

This avoids two pitfalls. First, it avoids the bias and cost of human step annotation, where a person sits down and writes which steps are good and which are bad (error-prone and expensive). Second, it avoids the variance problem: when you score each step alone, the model must guess about context it cannot see, leading to noisy and gameable rewards. For example, a step like 'open tab' seems useless unless you know you were searching for information. By contrast, comparing whole trajectories gives the model all the context it needs, because both the successful and failed paths are right there together, and the model can see what differed.

Additionally, the implicit rewards and the trajectory-level rewards reinforce each other in a self-strengthening loop. When an agent learns better step-level judgments, it explores by preferring actions the model ranked highly. This produces trajectories where success is very clear (the agent followed mostly-good steps and won decisively) and failure is very clear (it hit a dead end). Because success and failure are so far apart, the preference model receives unambiguous examples: it does not have to guess which path was better. With unambiguous examples, the model trains faster and more confidently, so its predictions about which trajectory was better become sharper and more accurate. Sharper predictions produce sharper step-level rewards, because the model now clearly knows which actions correlated with success. The agent then learns these sharper rewards and explores even more intelligently, generating even clearer trajectory pairs. The loop tightens without requiring any additional human labels or extra model rollouts.

Math after the picture

The learning objective

First in words:

The paper optimizes a preference model using direct preference optimization on multi-turn trajectories. For each pair of trajectories and for each action in them, compute the step-level advantage (inferred, not labeled) and combine it with the trajectory-level advantage to update the policy.

Then the compact form:

policy_loss = - log(pi(action | state)) * (step_advantage + trajectory_advantage)

Every symbol:

policy_losshow wrong the agent's next-action choice was
pi(action | state)the agent's current probability of picking this action in this situation
step_advantageinferred estimate of how much this specific action helped (derived from trajectory comparisons)
trajectory_advantagehow much better the full trajectory performed than typical
log(pi)the log probability; used in machine learning to measure surprise; lower pi means higher loss
A tiny worked example
Suppose step_advantage = 2.0 (this step was clearly helpful) and trajectory_advantage = 1.0 (overall attempt beat the average).
Total advantage = 2.0 + 1.0 = 3.0.
If the agent currently assigns 80% probability to this action (pi = 0.8), then log(pi) ≈ -0.22.
Policy loss = - (-0.22) * 3.0 ≈ 0.66.
If the agent had assigned only 20% probability (pi = 0.2, log(pi) ≈ -1.61), loss would be 4.83 — a big penalty.
An algorithm (a set of steps) adjusts the numbers in the agent to shrink the loss: it nudges probabilities upward when the advantage is high, and the size of the nudge grows with the advantage size.

Combining step-level and trajectory-level advantages lets the agent learn both local judgment (this action was smart) and global strategy (this whole attempt worked).

What can go wrong

What can go wrong

Trajectory pairs are too similar. If successful and failed attempts are almost identical (only one step differs), the model learns one correct step but generalizes poorly. iStar needs diversity in trajectories to reliably separate signal from noise.
Early training is slow. At the start, the agent explores randomly, so trajectory pairs are uniformly bad. The preference model has little signal. iStar works best once the agent has found some good strategies to compare against bad ones.
Implicit rewards can still gamify. Even without explicit labels, if the preference model has a blind spot (e.g., an action looks good in isolation but fails in a real deployment), the implicit step reward will absorb that bias too.
Done right: use trajectory diversity. Seed the initial agent with diverse exploration, so early trajectories vary widely. Then, as learning proceeds, iStar's cycle tightens, and the step rewards stabilize.
What a runnable demo should prove

What a runnable demo should prove

Build a small navigation task: an agent must find a target location in a grid using commands like up, down, left, right, search. Generate two trajectories for each episode: one that reaches the target, one that does not (or reaches it inefficiently). Train a preference model to distinguish them. Then, use the preference model to infer step rewards for each action in a new trajectory. Finally, train a policy using both step and trajectory rewards, and measure success rate and average steps to success.

Success rate = (number of episodes agent reached target) / (total episodes). Efficiency = average steps per successful episode. iStar wins if both improve compared to trajectory-only RL.

The demo makes it impossible to miss: step-level guidance (inferred without labels) accelerates learning compared to trajectory-only rewards, because every step now carries feedback, not just the final outcome.
