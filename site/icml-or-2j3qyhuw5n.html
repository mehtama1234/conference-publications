DR-MMSearchAgent: Deepening Reasoning in Multimodal Search Agents

Train a multimodal search agent on the whole interaction path so it keeps exploring instead of stopping as soon as one answer looks good enough.

Paper explainersAll themesAgents & Tool Use

A multimodal search agent usually needs several turns: inspect evidence, search again, compare findings, and only then answer. Many training setups give the main reward only at the end. That makes different paths look almost identical as long as they finish with the same answer, so the agent learns to stop early and skip useful exploration. DR-MMSearchAgent changes the reward design so the full interaction path matters and so overly long, repetitive exchanges are discouraged.

Why multimodal search agents stop too early

In a search setting, an agent may need several rounds of looking, reading, and checking before it has enough evidence. If training gives reward only on the final answer, then two runs that end with the same answer can receive nearly the same learning signal even when one path gathered much better evidence, because the reward does not identify which intermediate searches were useful. That weak signal makes exploration hard to learn.

There is a second problem. Search runs can accumulate long histories full of repeated material. Once the context becomes cluttered, the agent has trouble finding the useful parts of earlier feedback. So the agent suffers in two directions at once: weak credit assignment across the interaction path and too much repeated context.

The paper's move in one sentence. Use whole-trajectory credit assignment plus an adaptive penalty on overly long interactions so that the agent learns to keep useful search steps and drop repeated ones.

What it actually does

Collect multi-turn search runs

Build training data where each question needs several reasoning and search steps.

Score full interaction paths

Compare complete runs so that paths with better evidence gathering receive stronger learning signals.

Reward varied useful path lengths

Do not force all successful runs to have the same number of steps; allow longer paths when they add evidence so that careful searches are not penalized just for taking more turns.

Use an adaptive length-based reward so that overly repetitive search sequences lose value.

Train the policy so that it keeps informative search behavior and trims wasted interaction.

What the paper changes

What the paper changes

The paper changes the training signal for a search agent. Instead of rewarding only the last answer, it assigns credit across the whole search path and adjusts how much interaction length is encouraged.

the object it moves  =  How search trajectories receive learning credit
The hidden quantity

Search usefulness: the hidden quantity

measured quantity  =  How much each turn helps the final answer

The important quantity is the usefulness of the whole path. A turn is valuable when it collects evidence, narrows uncertainty, or checks an earlier claim. A turn is harmful when it repeats what is already known or keeps searching after enough evidence has been gathered.

The paper estimates this hidden quantity by comparing entire rollout paths inside a batch. Paths that reach the same answer can still differ in quality, so the method tries to reward the path that gathered more useful support or used interaction length more efficiently.

Why it works

Why this works

Whole-path credit assignment works because it distinguishes between paths that only happen to end correctly and paths that actually gather reliable support on the way. Once those paths receive different learning signals, the agent has a reason to preserve evidence-seeking behavior.

The length-sensitive reward works because it prevents a trivial failure on either side. Without it, the agent may stop too early because the last answer dominates the reward, or keep searching pointlessly because there is no cost for repetition. The adaptive shape rewards enough interaction to collect evidence and then reduces the value of extra repeated turns.

A simplified path score

First in words:

Give each trajectory a total value equal to answer quality plus evidence quality minus a penalty for unnecessary interaction length, then compare trajectories inside the batch so that better search behavior gets higher advantage.

Then the compact form:

path_value = answer_quality + alpha * evidence_quality - beta * excess_length ; advantage_i = path_value_i - average_batch_value

Every symbol:

path_valuetotal value assigned to one search trajectory
answer_qualityhow correct the final answer is
evidence_qualityhow useful the collected support is for justifying the answer
alphaweight on evidence quality
betaweight on unnecessary extra interaction
excess_lengthhow much longer the interaction is than the useful range
advantage_ihow much better trajectory i is than the batch average
average_batch_valuemean path value across trajectories in the same training batch
A tiny worked example
Trajectory A gets the right answer but uses weak support: answer_quality = 1.0, evidence_quality = 0.3, excess_length = 0.
With alpha = 0.5 and beta = 0.2, path_value_A = 1.0 + 0.5 * 0.3 - 0 = 1.15.
Trajectory B gets the same answer and gathers stronger support: answer_quality = 1.0, evidence_quality = 0.8, excess_length = 0.
path_value_B = 1.0 + 0.5 * 0.8 = 1.40.
Trajectory C keeps searching after enough evidence: answer_quality = 1.0, evidence_quality = 0.8, excess_length = 2.
path_value_C = 1.0 + 0.5 * 0.8 - 0.2 * 2 = 1.00.
The training rule prefers B because it has strong support without wasted interaction.

The paper uses a more specific batch-based signal, but this simplified form captures the main design: whole-trajectory credit plus a penalty on unnecessary extra interaction.

What can go wrong

What can go wrong

Longer is not always better. A system can learn to add ceremonial search steps unless the reward clearly distinguishes useful evidence from empty repetition.
Batch comparisons can be noisy. If the trajectories in a batch are not comparable, the relative credit signal may become unstable because weak and strong tasks are being mixed.
Dataset quality matters. If the multi-step training questions are shallow, the agent may learn superficial search habits because the benchmark is not forcing real evidence gathering.
Done right. Build questions that truly require several turns, score the whole path, and keep a direct penalty on repeated interaction so that the agent learns purposeful search behavior.
What a runnable demo should prove

What a runnable demo should prove

Build a small multimodal search benchmark where each question needs at least three turns to solve. Give the agent an image, a question, and a search tool. Train one baseline with reward only on the final answer and one variant with a simple whole-path score plus a length penalty. Record the number of turns, the amount of repeated search, and final accuracy.

The demo should prove that whole-path credit improves search behavior because the agent keeps the turns that gather evidence, and that length control improves efficiency because repeated turns lose value once the answer is already supported.

path_efficiency = answer_accuracy / average_turns ; repeated_fraction = repeated_turns / total_turns

A useful demo shows fewer premature stops, fewer pointless extra turns, and stronger final answers because the training rule now rewards useful search steps across the whole path.
