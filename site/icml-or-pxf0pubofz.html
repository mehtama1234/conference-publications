From Interaction Trajectories to Prompt Rules: Credit Assignment for Multi-Agent Prompt Optimization

Use interaction traces to decide which prompt rule helped or hurt, then edit only the rules that earned that credit.

Paper explainersAll themesAgents & Tool Use

Multi-agent systems often fail for reasons that are hard to localize. One agent asks the wrong question, another follows an overly broad rule, and the final score only says that the whole run went badly. This paper focuses on that credit problem. It reads the interaction trace, finds the subparts that mattered for success or failure, and maps those trace-level signals back to individual prompt rules. The result is a way to update prompts locally instead of rewriting the whole prompt after every outcome.

Why prompt tuning is hard in multi-agent systems

A multi-agent system usually has fixed roles and fixed interaction structure. Each agent is guided by prompt rules that say what to inspect, how to respond, and when to hand work to another agent. When the full system succeeds or fails, the final score does not say which prompt rule caused the outcome.

That makes optimization blunt. A global prompt rewrite may change useful rules together with harmful ones, while final-score tuning misses the important evidence inside the trace. This paper tries to assign credit more precisely by using the actual sequence of interactions.

The paper's move in one sentence. Trace the success or failure signal back through the interaction history, estimate which prompt rules were responsible, and edit only those rules.

The algorithm as a flow

What it actually does

Step 1: Run the multi-agent task

Collect the full interaction trace, including messages, handoffs, and task outcome.

Step 2: Find informative sub-trajectories

Search the trace for segments that best explain why the run succeeded or failed.

Step 3: Estimate rule-level credit

Connect each informative segment to the prompt rules that shaped that local behavior.

Step 4: Edit rules locally

Update the specific rules with positive or negative credit instead of rewriting the whole agent prompt.

Step 5: Aggregate evidence across tasks

Combine many local edits across runs so that the prompt rules improve steadily over time.

What the paper changes

What the paper changes

The paper changes how prompt optimization assigns responsibility. Instead of treating each prompt as one block, it treats the prompt as a set of rules whose effects can be tracked through interaction traces.

The hidden quantity

The hidden quantity

measured quantity  =  rule responsibility for outcome

The key hidden quantity is how much each prompt rule contributed to the final result. That quantity is hard to see because the rule acts through a long chain of messages, handoffs, and intermediate decisions.

TRUCE tries to surface that quantity by finding trace segments with strong outcome evidence and mapping them back to the rules that shaped those segments. Local edits help because they preserve useful rules while changing the ones that repeatedly earn negative credit.

Why it works

Why localized rule editing works

Trace-level evidence helps because the final task score is too far removed from the behavior that caused it. A long multi-agent run contains moments that are much more diagnostic than others, such as a bad handoff, a redundant loop, or a strong verification step.

Rule-level editing helps because prompt quality is rarely uniform across the whole prompt. Some rules are already useful and should remain stable, while a few recurring rules create most of the waste or confusion. By assigning credit to those rules directly, the method improves the prompt without destroying the working parts of the existing agent design.

Math after the picture

A compact rule-credit view

First in words:

Each rule gets credit by summing the outcome evidence from the trace segments that the rule influenced.

Then the compact form:

rule_credit(r) = sum_{s in S(r)} outcome_signal(s)

Every symbol:

rone prompt rule inside the multi-agent prompt set
S(r)the set of informative trace segments linked to rule r
outcome_signal(s)the positive or negative evidence that segment s contributed toward the final task result
rule_credit(r)the total estimated responsibility of rule r across the linked trace segments
A tiny worked example
Suppose one planner rule says to hand off quickly when uncertainty is high.
Across three task runs, that rule is linked to two useful handoffs with outcome signals +2 and +1, and one bad early handoff with outcome signal -3.
Then rule_credit(r) = 2 + 1 - 3 = 0.
A zero total suggests the rule is not clearly helping overall, so it is a good candidate for revision.
If another reviewer rule gets +2, +2, and +1 across similar runs, its total is +5 and the system should keep it largely unchanged.

The exact estimator can be richer than this summary, but the central idea is to move from final outcome to rule-level responsibility through the trace.

What can go wrong

What can go wrong

Noisy trace attribution. A rule can receive the wrong credit if the informative segment is linked incorrectly, because several agents may have contributed to the same later outcome.
Over-local editing. A tiny rule edit can miss a broader coordination problem if several weak rules interact to cause the failure together.
Sparse evidence. One or two runs may not reveal stable rule responsibility, because the same rule can behave differently across tasks with different interaction patterns.
Done right. A strong optimizer should aggregate rule credit across many runs and keep edits small until the same failure pattern appears repeatedly, so that one noisy trace does not rewrite a useful rule.
What a runnable demo should prove

What a runnable demo should prove

Build a small two-agent or three-agent workflow with fixed roles and prompts, such as planner, worker, and reviewer. Log the full interaction trace and the final task score for each run. Then mark the trace segments that most clearly helped or hurt and map those segments back to the rules that triggered them.

The demo should prove two things. First, localized rule edits should raise task quality because they directly target recurring weak behavior. Second, those edits should be more stable than global prompt rewrites because the useful rules stay intact while only the credited rules are changed.

task_score = successful_runs / total_runs ; edit_gain(r) = score_after_edit(r) - score_before_edit(r)

If repeated local edits improve the same fixed multi-agent design without broad prompt rewrites, the demo has captured the paper's main idea because it shows that rule-level credit can guide prompt improvement while the overall agent structure stays fixed.
