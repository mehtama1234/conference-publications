Zero assumption version

Vectors miss relationships between directions

A molecule is a collection of atoms arranged in three-dimensional space. Each atom has bonds pointing in different directions. Today's graph neural networks represent where atoms are and which way they point using vectors (lists of numbers). A naive approach assigns one vector to each atom.

The problem is that one vector only points in one direction. It cannot capture how two different directions at the same atom relate to each other. For example, if an atom has two bonds pointing in different directions, a single vector cannot record both the directions and the angle between them. You need something that holds information about pairs of directions, not just one direction at a time.

In one sentence. The paper builds a neural network that replaces direction lists with full matrices, so it can represent how multiple directions in a molecule interact.

What the paper changes

What the paper changes

The paper replaces vector features (lists of numbers) with matrix features (grids of numbers arranged in rows and columns). Standard graph networks pass the same transformation across every edge. This paper uses sheaf neural networks, which apply a different transformation for each edge, then uses special math of the SPD manifold to ensure these matrices stay valid (symmetric and positive).

The hidden quantity

Matrix rank: capturing relationships between directions

measured quantity  =  Output matrix rank (number of independent relationships)

The hidden quantity is how many independent relationships between directions each atom can encode. Vector-based networks output rank-1 features (one direction per atom). Matrix-based networks output full-rank matrices (all rows and columns independent), encoding how many different direction-pairs the atom has. For example, an atom with three bonds has three different ways pairs can relate, so it needs rank-3. A vector cannot hold rank-3 information; a matrix can. When the network learns, it transforms single-direction input into multi-rank matrices, capturing information that vector networks throw away.

The paper measures this directly: after training, the output matrices from the network are full-rank, while vector networks always output rank-1. This shows the matrix network learned to encode more about how directions interact.

Why it works

Why matrix features on SPD manifold work better

The core insight is that molecular structure is about how multiple directions at each atom relate to each other. A vector represents one direction, but each atom has many bond directions. A matrix can record every pair: how direction A aligns with direction B, how B aligns with C. Standard message passing applies the same transformation to every edge. This network applies a different transformation to each edge. This matters because each bond has its own angle to its neighbors, so each edge should transform information differently, letting the network adapt to what is actually in the molecule.

The SPD manifold constraint keeps matrices valid: symmetric (the relationship from A to B equals B to A) and with all positive eigenvalues (meaning the relationships stay physically sound). Without this constraint, the network could learn matrices that contradict themselves or violate chemistry rules. With it, every matrix stays in a valid space. When computing inside the SPD manifold, the logarithm and exponential operations stay inside the manifold too, which means the network never has to collapse a matrix back to a vector and lose the multi-directional structure, so learned direction-pair information persists through every layer.

Math after the picture

The sheaf transformation equation

First in words:

The transformed feature at each atom equals the sum over all neighbors of an edge-specific matrix transformation applied to the neighbor's previous feature, all kept on the SPD manifold using matrix logarithm and exponential maps.

Then the compact form:

x_v^{l+1} = sum_{u in N(v)} Exp(W_{uv} * Log(x_u^l))

Every symbol:

x_v^{l+1}new matrix-valued feature at atom v in layer l+1
x_u^lprevious matrix-valued feature at neighbor atom u in layer l
W_{uv}edge-specific weight matrix transforming messages from u to v
Log(·)matrix logarithm (maps SPD matrices to symmetric matrices)
Exp(·)matrix exponential (maps symmetric matrices back to SPD)
N(v)all neighbor atoms of atom v
Tiny worked example with two atoms
Atom A starts with direction [2, 1] which becomes 2x2 matrix [[2, 0], [0, 1]]
Edge A-B has weight matrix W_AB = [[1, 0.5], [0.5, 1]]
Atom B's update: take log of A's matrix = [[0.693, 0], [0, 0]], apply W_AB, take exponential
The log-apply-exponential cycle keeps the result symmetric and positive
Result: B gets a full 2x2 matrix; each pair of its bond directions now has a learned relationship

The logarithm and exponential keep all operations on the SPD manifold, so matrix features stay symmetric and positive throughout learning.

What can go wrong

What can go wrong

Matrix computation takes more time and memory. Unlike vectors, computing with matrices requires more memory and computational time. For large molecules or deep networks, this can become prohibitive unless you use efficient matrix multiplication libraries.
Numerical precision in log and exponential operations. Computing the logarithm and exponential of matrices is numerically sensitive. If a matrix is close to the edge of being positive definite, a small rounding error can grow large, causing the training to become unstable.
Edge-specific transformations mean many numbers to learn. Every edge gets its own weight matrix instead of sharing one across all edges. On dense molecules with many atoms, this means many numbers to learn from limited data, which can cause the network to overfit (memorize the training data instead of learning the real pattern). You need to constrain learning carefully to prevent this.
Done right. Use stable matrix libraries (numpy or torch), initialize weight matrices so they stay well-conditioned (not too close to the positive definite boundary), constrain edge weights during learning to prevent overfitting, and test numerical stability with deep networks before deployment.
What a runnable demo should prove

What a runnable demo should prove

Build a small molecular graph (5-10 atoms, a few bonds) with known direction and angle information. Train the sheaf network and a standard vector network. Compare their outputs: the matrix network should produce full-rank matrices for each atom (all rows and columns independent), while the vector network outputs only rank-1 vectors (single direction). Then measure prediction accuracy on a simple task like predicting which bonds are strongest, or the angles between specific bond pairs. The matrix network should be more accurate, because it can learn how directions interact, which vector networks cannot.

accuracy = correct_predictions / total_predictions; rank_gain = rank(matrix_output) - rank(vector_output)

The demo makes clear: matrix outputs are visibly higher-rank than vector outputs because they encode multiple independent relationships, and the network's predictions are measurably more accurate on tasks about angles or bond interactions because it learned those relationships.
