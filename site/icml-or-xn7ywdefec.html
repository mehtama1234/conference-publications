Faithful Mobile GUI Agents with Guided Advantage Estimator

Train a phone-screen agent to act only when the screen and the instruction support the action, then stabilize reinforcement updates so that faithful behavior does not disappear.

Paper explainersAll themesAgents & Tool Use

GUI agents often look capable on normal tasks while still relying on shortcuts. They may tap a familiar button because they saw a similar screen before, not because the current screen and the user's request justify that tap. This paper treats that as the main failure. Faithful-Agent first teaches the model to refuse unsupported actions when evidence is perturbed, then uses a guided advantage estimator so that sparse rewards do not wash out the learning signal for grounded behavior.

Zero assumption version

Why GUI agents act without proper support

A phone-use agent should read the visible screen, follow the written goal, and then choose the next action. In practice, many agents learn a weaker habit. They notice recurring layouts and jump to an action that often worked before. That shortcut can still score well on easy tasks, but it breaks as soon as a button moves, the text changes, or the instruction requires a careful check.

The training setup makes this worse because GUI rewards are sparse. Many action traces get nearly the same low score. When that happens, the update step cannot clearly distinguish a grounded action from a lucky shortcut. The paper's claim is that faithfulness must be taught directly and then protected during reinforcement learning.

The paper's move in one sentence. Teach abstention when evidence is missing, then stabilize policy updates so that actions supported by the screen keep receiving stronger credit.

The algorithm as a flow

What it actually does

Create faithfulness-sensitive examples

Show the model tasks where screen evidence or instruction support is deliberately weakened so that unsupported actions can be identified.

Run supervised faithfulness training

Teach the model to abstain or revise its plan when the visible evidence no longer supports the action.

Collect grouped rollouts

For each GUI task, sample several action traces so that policy updates can compare stronger and weaker behaviors.

Temper the advantage signal

Use the guided estimator to keep relative differences visible because ordinary grouped updates can collapse when all rewards are similar.

Reward thought-action agreement

Add a consistency score so that the written rationale and the chosen tap point reinforce one another.

What the paper changes

What the paper changes

The paper changes the learning signal from generic task success to evidence-backed action choice. The model is no longer rewarded only for eventually reaching the target screen. It is trained to value the path where each action is justified by what is visible and by what the user asked for.

the object it moves  =  the action credit assigned to evidence-backed GUI behavior
The hidden quantity

The hidden quantity

measured quantity  =  whether the next action is genuinely supported by current evidence

Faithfulness is not directly observable from the final success flag. An agent may reach the right page by accident, or it may fail while still following the evidence correctly. The hidden quantity is whether the chosen action is supported by the current screen and instruction at the moment it is taken.

Faithful-Agent makes that quantity easier to train because the first stage creates examples where support is intentionally removed. The model then learns that the correct response can be to stop or ask for clearer evidence. The second stage keeps that distinction alive during reinforcement learning because the guided estimator preserves differences that sparse rewards would otherwise blur.

Why it works

Why this works

Shortcut behavior survives because ordinary training often cannot tell grounded success from accidental success. If a GUI trace gets to the correct screen, the update may reward it even when several intermediate taps were unsupported. The faithfulness-first supervised stage attacks that problem directly by creating cases where unsupported behavior must be rejected.

The guided advantage estimator addresses a second failure. In grouped reinforcement learning, many traces can have nearly identical sparse rewards. Then the plain advantage values become tiny and unstable, so the update stops favoring the better grounded trace. The anchor-based tempering keeps a usable spread in the signal because it rescales updates relative to a reference inside the group.

The thought-action consistency reward closes the loop. A model that writes one plan and taps elsewhere is still unreliable. Rewarding alignment between explanation and action helps because the policy is pushed toward traces where both the written reasoning and the screen action point to the same evidence-backed choice.

Math after the picture

The training score

First in words:

The total learning score combines task success, faithfulness support, and thought-action agreement, while the grouped update is rescaled so that near-tied rewards still produce a useful preference signal.

Then the compact form:

total_score(trace) = task_score(trace) + alpha * support_score(trace) + beta * consistency_score(trace)

Every symbol:

total_score(trace)the value used to rank one GUI action trace during learning
task_score(trace)how well the trace completes the requested GUI task
support_score(trace)how strongly the chosen actions are supported by the visible screen and instruction
consistency_score(trace)how well the model's stated plan agrees with the action it actually takes
alphaweight on evidence support during learning
betaweight on thought-action agreement during learning
A tiny worked example
Trace A reaches the target screen but uses one unsupported tap.
Its task score is 8, its support score is 2, and its consistency score is 2. With alpha = 1 and beta = 1, its total score is 12.
Trace B also reaches the target screen and every tap is supported by the visible labels.
Its task score is 8, its support score is 5, and its consistency score is 4, so its total score is 17.
The grouped update should prefer Trace B because it solves the task without relying on unsupported steps.

The paper uses a richer grouped reinforcement objective, but this summary captures the main idea that grounded action quality must remain visible during policy updates.

What can go wrong

What can go wrong

Perturbations may miss real shortcut patterns. If the evidence-removal stage does not create the kinds of traps that appear in real phone apps, the model may still learn unsupported habits on layouts that were never stressed during training.
Consistency reward can favor polished but wrong explanations. A model can write a neat rationale that matches its tap while still reading the screen incorrectly, so consistency alone is not enough unless the support signal also stays strong.
Sparse rewards can still limit coverage. If most rollouts fail very early, even a tempered grouped update may not provide enough information about which grounded behavior should be preferred next.
Done right. The method is most useful when trap-style evidence perturbations are realistic and when grouped updates still contain enough variation to separate grounded traces from shortcut traces.
What a runnable demo should prove

What a runnable demo should prove

Build a small Android-like benchmark with tasks such as changing a setting, muting one app, or editing a contact field. For each task, create ordinary screens and trap screens where a familiar location or icon is present but the supporting label is removed or changed.

Train one agent with ordinary supervised and grouped reinforcement learning and train a second agent with the Faithful-Agent procedure. Measure task completion on ordinary screens and faithful success on trap screens. Also log whether the agent abstains when support disappears, because that behavior is part of the target.

faithful_gain = trap_success_faithful_agent - trap_success_baseline ; abstain_precision = correct_abstentions / all_abstentions

The demo should show that the better agent is not merely finishing more tasks. It should be acting from current evidence because that is the failure the paper sets out to fix.
