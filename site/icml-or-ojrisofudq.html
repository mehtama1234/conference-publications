Channel Adapter for Time Series Foundation Models in Zero-Shot Multivariate Forecasting

A lightweight plug-and-play adapter lets frozen time series models use correlations between multiple variables without retraining.

Paper explainersAll themesTime Series & Sequential

Time series foundation models work well for prediction, trained on thousands of past patterns. But they typically predict each variable one at a time, ignoring that in real systems (like factory sensors or stock markets) one variable often hints at what another will do. This paper adds a lightweight adapter that teaches a frozen model to use those cross-variable clues, improving forecasts at zero cost to the base model.

Zero assumption version

One variable at a time is not enough

A time series foundation model (a large model trained to predict sequences from historical data) typically predicts each variable independently. In a factory, this means the temperature sensor is predicted without knowing the pressure sensor is about to spike. In stock markets, it means predicting one stock without using the fact that correlated stocks are moving. Real systems have dependencies: when variable A changes, variable B often does too.

A naive approach is to retrain the entire model to learn those cross-variable patterns. But retraining is slow and expensive, and defeats the point of having a pre-trained foundation model. You are stuck: either ignore the correlations or throw away the pre-trained model and start over.

The problem in one sentence. Foundation models trained to predict each variable separately miss the correlations between variables that make real-world forecasts accurate.

The algorithm as a flow

What it actually does

Build a budgeted pre-training dataset

Collect diverse examples of how variables relate (inter-channel patterns) without overwhelming the adapter with data.

Learn a domain-aware similarity measure

Train the adapter to measure how similar two variables are, accounting for the fact that similarity means different things in different datasets.

Compute inter-channel relationships

For each pair of variables, the adapter estimates how strongly one predicts the other.

Inject via gated refinement

Add cross-variable context to the base model's predictions, but only when it is confident (using a learned gate).

Preserve temporal dynamics

Keep the base model's accurate within-variable patterns; the adapter only adds between-variable context.

What the paper changes

What the paper changes

The paper adds a small learnable module—a channel adapter—that wraps around the frozen foundation model. This adapter is the only new piece; the base model never sees gradients (does not learn). The adapter learns to measure cross-variable relationships and injects that information back into the base model's predictions.

the object it moves  =  inter-channel correlation signal
The hidden quantity

The hidden quantity: inter-channel similarity

measured quantity  =  inter-channel dependency strength

The hidden quantity is the strength of the relationship between two variables: does variable A reliably predict variable B? In a factory, humidity might strongly predict temperature (they move together), but humidity might barely predict vibration (unrelated). The adapter learns to measure this strength for each pair of variables.

The paper estimates this by: (1) building a dataset of diverse variable-pair behaviors, (2) training the adapter to predict which pairs are similar in new datasets, and (3) using a learned metric (a learned function) that accounts for the fact that similarity is domain-specific—temperature and humidity are correlated in a building but not in a chemical reactor.

Why it works

Why the adapter works

The foundation model already predicts well within each variable because it has seen thousands of examples of how temperature (or pressure, or humidity) evolves. The problem is that its predictions ignore the fact that when one variable moves unexpectedly, it often means another will too. The adapter learns a simple rule: measure the similarity between variables using a learned metric (a learned scoring function that says how much variable A and variable B are alike). Then, whenever the base model is about to predict variable B, the adapter sneaks in a hint: if variable A is unusual right now, and A and B are strongly related, nudge B's prediction in the direction that A's movement suggests. This nudge is small (gated), so it does not wreck the base model's temporal understanding, but it is enough to catch cross-variable surprises.

Why does this work? Because the base model is already 95% right, just missing the 5% that comes from variable interactions. The adapter learns the interaction strength from data (which is cheap) rather than retraining the entire model (which is expensive). And it works zero-shot on new datasets because it learned a domain-invariant similarity measure—it saw enough diverse datasets during adapter training that it can guess which variables relate in a new one, even without seeing any examples from that new dataset.

Math after the picture

The refinement equation

First in words:

refined forecast for variable = base forecast + gate weight times (similarity score times correlated variable's deviation from expected)

Then the compact form:

yhat_refined_i = yhat_i + g_i * sum_j sim(i,j) * (y_j - mu_j)

Every symbol:

yhat_refined_ithe final forecast for variable i (what we output)
yhat_ithe base model's original forecast for variable i
g_ia learned gate (0 to 1) controlling how much we trust cross-variable info for variable i
sim(i,j)learned similarity score between variable i and variable j (0 to 1)
y_jthe actual recent value of variable j
mu_jthe typical value of variable j (mean)
(y_j - mu_j)how far variable j is from normal (its anomaly)
A tiny worked example
Suppose we forecast temperature, base model says 72°F.
Similarity(temperature, pressure) = 0.8 (strong relationship).
Pressure is 5 psi above its normal 100 psi, so its anomaly is +5.
Gate for temperature = 0.6 (moderately trust cross-variable info).
Cross-variable term = 0.6 * 0.8 * 5 = 2.4.
Refined forecast = 72 + 2.4 = 74.4°F.
When pressure spikes, the adapter nudges temperature up, catching the correlation the base model missed.

The refined forecast is the base forecast plus a small nudge (controlled by the gate) that steers it toward what correlated variables suggest.

What can go wrong

What can go wrong

Adapter overfits to the budgeted pre-training dataset. If the diversity budget is too small, the adapter learns surface patterns instead of true variable relationships. It will not generalize to new domains. The paper addresses this by explicitly building a diverse dataset across many heterogeneous scenarios.
The gate learns to ignore all cross-variable info. If the base model is already so good that the adapter's nudges hurt more than help, the learned gate can set itself to 0 for all variables (because the learning process rewards the gate for reducing error, and if nudges cause error, the gate learns to turn off). Then the adapter does nothing. The paper prevents this by validating on held-out data during adapter training, so the gate only turns down if nudges truly hurt across multiple test datasets.
Inter-channel similarity metric confuses signal with noise. If two variables both have random fluctuations, the adapter might learn they are similar when they are not. Real similarity should persist across time and datasets. The paper uses domain descriptors (learned summaries of each dataset's characteristics) to filter spurious correlations.
Done right: adapter learns honest relationships. When trained on diverse data and validated carefully, the adapter learns genuine variable dependencies. It then applies those learned relationships to new forecasting tasks without retraining, achieving zero-shot gains.
What a runnable demo should prove

What a runnable demo should prove

Take a pre-trained time series foundation model (frozen, no retraining). Add the ChaTSFM adapter. On a new multivariate time series dataset the model has never seen, measure forecast accuracy. Compare the base model (predicting each variable independently) to the base model plus adapter (with cross-variable hints). The adapter should improve accuracy on variables that genuinely correlate with others, without hurting variables that do not correlate—because the gate learns to use hints only when they are reliable (the gate pulls back when a hint misleads), so correlated variables get better forecasts while unrelated variables are left alone. Show that this works across multiple benchmarks: energy systems, traffic, weather, finance. Prove that the adapter learns dataset-specific similarity patterns: variables that correlate in one domain do not in another, and the adapter respects that.

improvement = accuracy_with_adapter - accuracy_baseline

The demo must show that adding the adapter strictly improves forecast accuracy on real multivariate systems—because if the adapter successfully captures cross-variable correlations, it will nudge forecasts in directions that turn out to be right more often than wrong, raising overall accuracy while the gate ensures unrelated variables stay untouched.
