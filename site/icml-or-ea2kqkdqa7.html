The Illusion of Generalization in Tabular Language Models

Language models fine-tuned on tabular data appear to work well, but the performance comes from test data leaking into training and from general instruction-following, not from learning to think like a table-solver.

Paper explainersAll themesDatasets & Benchmarks & Evaluation

Tabular Language Models (language models adapted for spreadsheet-like data) are claimed to outperform older tools because published benchmarks show them scoring 40-50 percentage points higher than simple baselines. But when researchers ran the same tests carefully, they found the claimed success was an optical illusion: the test data had snuck into the training data, and a generic language model trained only on instruction-following (not tabular data at all) recovered 92% of the performance.

Zero assumption version

How did benchmarks get inflated?

When researchers build a new language model to handle tables (rows and columns of numbers and text, like a spreadsheet), they test it on 165 different standard datasets. The results looked amazing: the model beats older methods by a lot. But nobody had checked carefully whether the test data was really separate from the training data.

A beginner might assume: get some data, split it into a training pile (to learn from) and a test pile (to check if learning worked), train a model, then measure how well the trained model predicts the test pile. If the model does great, it learned something real. But if the test pile is hiding inside the training pile, the model memorized the answers instead of learning the pattern. The model is like a student who looks at the answer key during the test: high scores, zero learning.

The problem. Tabular language models show great performance on benchmarks, but test data is leaking into training data, and instruction-following alone (trained on no tabular data) recovers most of the win.

What the paper changes

What the paper changes

The paper does not change a model; it changes how we measure performance. Instead of trusting the reported benchmark score, the researchers manually check whether the test data is hiding in the training data, and whether a model trained only on instructions (with no tabular examples) can recover the win. This is a diagnostic, not a model improvement.

the object it moves  =  evaluation, not the model
The hidden quantity

The hidden quantity: true tabular lift

measured quantity  =  True performance gain from tabular learning

When a model wins on a test, there are three reasons it could win: (1) it memorized the test examples because they leaked into training, (2) it learned general instruction-following (which any language model can do), or (3) it learned tabular-specific knowledge that makes it think like a table-solver. The paper calls reason (3) the true lift. Most of the reported win comes from (1) and (2); reason (3) is tiny.

The paper measures this by training two models side by side: one on tabular data (Tabula-8B) and one on pure instructions (Alpaca, no tables). The gap between them is the ceiling for true tabular learning. When instruction-only recovers 92% of the performance, the true tabular lift is at most 8%.

Why it works

Why performance inflates without real learning

A language model learns by seeing examples and adjusting its internal numbers (weights) to predict the next words. When it sees a training example, it learns patterns. On test time, if the model sees the same example again, it will predict it perfectly because it memorized it. If the test data leaks into training, the model does not need to generalize; it can just remember.

General language models also get very good at following instructions without ever seeing tables. When you say make a prediction for this row of numbers, a language model trained on millions of instructions will guess reasonably well just by learning the format (how to parse a list of numbers) and the task structure (how classification works in words). Tabular-specific knowledge (patterns that only apply to spreadsheets) is a tiny extra edge on top. The paper shows this by taking a generic model, removing all tabular training, and asking it to do the same test: it recovers 92% of the score. That 92% comes from format and instructions; the 8% is what tabular training added.

The decomposition equation

First in words:

Reported accuracy equals data contamination plus instruction-following plus true tabular reasoning

Then the compact form:

Acc_reported = Acc_contamination + Acc_instruction + Acc_tabular_true

Every symbol:

Acc_reportedThe benchmark score published for the tabular model
Acc_contaminationPoints earned from memorized test data in training
Acc_instructionPoints earned from instruction-following (no tabular exposure)
Acc_tabular_truePoints earned from learning table-specific patterns
A tiny worked example
Suppose a tabular model scores 85 points on a classification task.
A majority-class baseline (always guess most common answer) scores 60 points.
The reported lift is 85 - 60 = 25 points.
Now train a generic model on instructions only: it scores 83 points.
The instruction-only lift is 83 - 60 = 23 points.
Tabular-specific lift is at most 85 - 83 = 2 points.
If test data is found in training, the contamination score could be, say, 15 points.
Then true tabular reasoning is 85 - 60 - 23 - 15 = -13, meaning the data is overexplained; real learning is negative.

The paper shows Alpaca recovers 92% of the tabular model's performance, leaving true tabular learning at less than 8 percentage points.

What can go wrong

What can go wrong

Train-test contamination goes undetected. If you do not search the training data for test examples, you will not catch the leak. The paper found complete overlaps in top-performing datasets, meaning the model never had to generalize.
Using aggregate accuracy masks the real story. Performance is high on average because a few task types (quartile classification, which is hard to leak into) drive the aggregate. Binary and categorical classification gain almost nothing. Reporting aggregate score hides this.
Forgetting to test format alone. If you train a control model only on tables (no instructions), and another only on instructions (no tables), you can isolate which skills matter. Skipping this step lets instruction-following hide.
Done right: multi-layer controls. Test three models: tabular-trained, instruction-only, and tabular-only. Compare them and search for contamination. Separate the sources of performance.
What a runnable demo should prove

What a runnable demo should prove

Build a small benchmark: take 10 simple classification datasets. (1) Train a language model on tabular data from those 10 datasets. (2) Train an identical language model on instructions only (use any instruction dataset like Alpaca, exclude all tabular examples). (3) Also build a random-guess baseline and a majority-class baseline for each dataset. (4) On a held-out test set from each dataset, measure accuracy for all four. (5) For each dataset, search the tabular training data for exact matches with the test set. Record contamination found. (6) Compute: tabular-model accuracy minus instruction-only accuracy. That is the maximum true tabular lift.

True_tabular_lift_upper_bound = Acc_tabular - Acc_instruction_only; Lift_without_contamination = Reported_lift - Contamination_fraction

The demo must make it impossible to miss: when you train on instructions alone, you will recover the majority of the performance, and wherever test data leaks into training, the tabular model gains nothing new.
