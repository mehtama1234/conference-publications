When to Retrain: CALIPER Detects Enough New Data

CALIPER is a simple test that tells you when you have collected enough new data after a sudden change to safely retrain your model.

The drift retraining puzzle

Real-world predictions often fail when the world changes. A model trained on historical weather data makes bad rain forecasts if ocean currents shift. A fraud detector trained on 2023 patterns misses 2024 attacks. These are examples of concept drift: the hidden rules governing the data flip without warning.

A naive response is simple: collect some new data from the drifted world, throw it at the old model with retraining, and hope. But how much new data is enough? Too little and your model still overfits to noise or learns an unreliable pattern. Too much and you waste time and compute waiting for data that adds no value. Current practice is to pick a fixed size (collect 1000 samples, retrain) or keep updating forever. Neither is smart.

The puzzle: after a sudden change, when do you have enough new data to retrain safely? CALIPER runs a quick test on the new data stream itself, needs no knowledge of your model, and tells you when to stop collecting and start retraining.

The algorithm as a flow

What it actually does

Detect drift

A drift detector (any method) signals that the data has changed.

Collect new data

Gather a window of post-drift data samples.

Fit local models

Run a weighted regression for each locality setting, predicting one step ahead in the new data only.

Check the trend

Measure if prediction error shrinks smoothly as you include more nearby data.

Declare sufficiency

If error trends down and passes a sample-size gate, the new data is informative enough to retrain.

What the paper changes

What the paper changes

CALIPER's move is to measure the new data stream itself without needing your model. Instead of asking the model is the new data good for retraining, CALIPER asks the new data directly: is there a learnable pattern here, or is it noise?

the object it moves  =  the retraining timing decision
The hidden quantity

The hidden quantity: informative sample size

measured quantity  =  effective sample size and trend curvature

CALIPER measures an implicit quantity: how much useful information is in the new data. It estimates this by running weighted local regression at different neighborhood sizes and tracking whether prediction error on the new stream shrinks smoothly. If you use mostly nearby data (small neighborhood), the error is high because you have few examples. If you expand to far neighbors, the error should drop because you are using more data to build the local model. A smooth, monotonic drop signals that the new data contains a genuine pattern (not noise).

The paper estimates this quantity using a one-step-ahead proxy error: in each local regression, the model predicts the next data point in the post-drift stream and compares to the actual next point. The trend of this error across neighborhood sizes tells you whether the data is learnable.

Why it works

Why it works: the state dependence principle

The core insight is that most real-world streams (like weather, electricity demand, system load) have state dependence: nearby points in time are correlated. A local regression that uses only recent data (small neighborhood) makes poor predictions because it has few points. Expanding the neighborhood (using older but still recent data) adds information and shrinks error — because the pattern is learnable from nearby points. This only works if the new regime has a real pattern. If the post-drift data were pure noise, then neighborhood size would not matter; error would stay high or jitter randomly.

So a smooth trend of decreasing error as you widen the neighborhood is evidence that the new data contains learnable structure. CALIPER exploits this. It runs the regression test once, very quickly, and if the error trend is smooth and the total sample size is adequate, it declares the data ready for retraining. This works model-agnostic because it only depends on the stream's own internal coherence, not on any specific learner.

The equation and example

First in words:

For each neighborhood size, fit a weighted local regression and measure the one-step-ahead prediction error. Check if this error decreases monotonically as neighborhood size increases, and if the effective sample size exceeds a threshold.

Then the compact form:

error(theta) = mean_squared_error(predicted, actual) where theta is the locality parameter; declare sufficiency if error is monotonically non-increasing in theta and n_eff >= n_gate

What can go wrong

What can go wrong

Non-stationary drift regime. If the data keeps drifting (the pattern itself is changing), then the error trend may not be monotonic. CALIPER assumes a single stable new regime after the detector fires.
Insufficient post-drift window. If you do not collect enough post-drift samples before testing, the effective sample size gate will not pass, even if a larger window would be informative. CALIPER requires a minimum window to evaluate.
Detector latency or false positives. If the drift detector itself is slow or triggers late, CALIPER starts on mixed old and new data, biasing its estimate. A good drift detector is assumed.
Done right. Pair CALIPER with a reliable drift detector to mark the true onset of drift, because CALIPER's error trend only works on post-drift data. Allow a reasonable collection window (dozens to hundreds of points) because the monotonicity check needs enough samples to reveal the pattern. Use the sample size gate, because without it a small unlucky sample might by chance show decreasing error. Most streaming systems have sufficient volume for this.
What a runnable demo should prove

What a runnable demo should prove

Build a synthetic stream that drifts suddenly (e.g., a sine wave at frequency f switches to frequency f+0.1). Train an initial model. After drift is detected, run CALIPER on the new stream while collecting new labels. Show that CALIPER signals sufficiency when error-trend smoothness indicates the new regime is learnable, and that retraining at that point restores accuracy. Compare to fixed-size retraining: CALIPER should retrain earlier without loss of accuracy, or later without breaking the model.

time_to_retrain = (iteration when CALIPER signals sufficiency) - (iteration of drift); retraining_accuracy = accuracy on held-out post-drift test set after retraining at the CALIPER signal; compare to fixed-window retraining

The demo must show that CALIPER stops you from collecting needless data, yet never signals too early: whenever CALIPER says retrain, the retrained model reaches target accuracy on the new regime.
