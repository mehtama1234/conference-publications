When to Retrain after Drift: CALIPER Test

A test that watches how accurately a model can predict the next data point at different neighborhood sizes to decide if you have gathered enough new data to safely retrain after a sudden shift.

Paper explainersAll themesTime Series & Sequential

When data suddenly changes, a trained model becomes unreliable. The practical question is: how much new data do you need to collect before retraining? CALIPER answers this without retraining—by running a lightweight test on the new data to measure whether patterns are stable enough to learn from.

The Retrain Timing Problem

In streaming data, sudden concept drift—when the underlying pattern suddenly changes—breaks predictions. A model trained on old data can no longer guess the next value accurately.

A naive approach: collect some new data and retrain. But how much? Collect 10 samples? 100? Too little and the new model still overfits to noise; too much and you waste time waiting. There is no signal from the data itself saying 'now you have enough.'

The Opportunity. Dynamical systems have state dependence: nearby data points tend to stay nearby over time. Use that pattern to estimate data sufficiency without retraining.

The hidden quantity

State Dependence: Stability of Neighborhoods

measured quantity  =  state dependence

State dependence is a single number measuring whether neighbors stay neighbors over time. In a dynamical system, if you pick a data point and look at its neighbors right now, do they stay close to it one step into the future? If yes, the data has high state dependence. If neighbors scatter away, state dependence is low.

CALIPER estimates state dependence by fitting a model to neighboring points and measuring one-step prediction error. A smooth drop in error as the neighborhood grows signals stable neighborhoods, meaning the data pattern is learnable and retraining will generalize well.

Why it works

Why Monotone Error Drop Predicts Retraining Success

When you collect new data after a drift, that data comes from a new dynamical system. The question is: does the new system have learnable patterns? CALIPER answers by testing neighborhoods.

Here is the mechanism: For a test point, fit a local model using only its nearest neighbors (tight neighborhood). Measure one-step prediction error. Now expand the neighborhood. Fit again. Measure again. If error keeps dropping smoothly as you expand, it means neighbors were genuinely informative—they were close to the point for a reason, not by accident. The farther points you add contribute real signal, not noise. This smoothly dropping error is a signature of a learnable pattern. When you retrain the real model on this data, it will generalize, because the data itself exhibits stable, repeatable structure.

If error jumps around or rises, neighborhoods are not stable. Adding more distant points makes the fit worse, signaling the data is too noisy or unstructured. Retraining on such data would fail.

Math after the picture

The Local Regression Error Test

First in words:

For each neighborhood size (locality parameter theta), solve weighted normal equations to fit a local model on neighbors, predict the test point, measure the absolute error. Check that error is non-increasing as theta grows.

Then the compact form:

e(t, theta) = ||y_query - y_hat_theta||

Every symbol:

y_querythe test point you want to predict
y_hat_thetathe model's prediction using neighborhood size theta
e(t, theta)one-step prediction error at time t and neighborhood size theta
thetathe locality parameter controlling neighborhood radius
A tiny worked example
Neighborhood tiny (theta=0.1): neighbors within 0.1 units. Fit 2 points. Predict y. Error = 0.8.
Neighborhood medium (theta=0.5): neighbors within 0.5 units. Fit 6 points. Predict y. Error = 0.5.
Neighborhood large (theta=1.0): neighbors within 1.0 units. Fit 15 points. Predict y. Error = 0.3.
Trend: 0.8 → 0.5 → 0.3 (monotone down). More data per fit means smoother model, better prediction. Sign of stable neighborhoods.

Monotone non-increasing error as neighborhoods grow is a proxy for state dependence—the deeper reason retraining will work.

What can go wrong

What can go wrong

Non-monotone error. If error jumps up and down, neighborhoods are unstable—nearby points are not genuinely related to each other. Distant points mislead more than they help because they add noise, not signal, so the fit gets worse as neighborhoods grow. Retraining on such noisy, incoherent data will fail. CALIPER correctly rejects this data size.
Too few samples. If post-drift data is sparse, neighborhoods are empty. No local model can be fit. CALIPER has an effective sample size gate to catch this.
Drift in the drift. If the new pattern changes again during collection, neighborhoods from early in the window no longer match later points. Monotonicity breaks. Correctly signals retraining is not ready.
Done right. CALIPER works because it tests a direct proxy for the property that makes retraining succeed: stable, learnable neighborhoods in the new data.
What a runnable demo should prove

What a runnable demo should prove

Build a synthetic streaming scenario with sudden drift. Generate two dynamical systems: before and after the drift. After drift detection, run CALIPER on the new data stream at different collection sizes. Plot CALIPER's decision (yes / no retrain ready) against the actual post-drift model's generalization error when retrained at that size. Show that CALIPER's 'yes' decisions align with low generalization error, and 'no' decisions align with high error. Use a simple learner (linear regression or nearest neighbor) to keep retraining fast.

alignment = fraction of CALIPER decisions that match the true best retraining data size

The demo must show CALIPER avoids both the overfitting (retrain too early) and the delay (wait too long) traps.
