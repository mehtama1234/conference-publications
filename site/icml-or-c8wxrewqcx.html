Zero assumption version

The world before: assuming you know what symmetries to look for

Many physical systems — spinning tops, falling objects, atom collisions — have symmetries. A symmetry is a transformation you can apply to the system that leaves it unchanged. For example, if you rotate a ball, its behavior stays the same; if you shift time backwards in an isolated system, the laws of physics still apply.

Today's geometric deep learning models (models designed to respect patterns in space and structure) require you to tell them in advance what symmetries to expect. You manually build the model to respect those symmetries. But in real data, you often do not know what symmetries are present — you just see measurements and want to figure out what patterns govern them. A naive model trained on the data will pick up some symmetries by accident, but it will also learn spurious patterns that do not generalize. Without designing the model to enforce the true symmetries, you get a brittle, unreliable model.

What the paper changes

The one thing the paper changes: the model's internal structure

Instead of a generic neural network that might learn any pattern, the paper builds a model whose layers are constructed to be invariant (unchanged by the symmetry) or equivariant (transforming in a predictable way under the symmetry). This architectural choice forces the model to respect symmetries by design.

The hidden quantity

The hidden quantity: the symmetry specifications

measured quantity  =  Symmetry specifications learned from data

Every symmetry in physics comes from a generator — a mathematical object that describes how to build that symmetry. For a rotation, the generator tells you the axis and how fast to spin. For an expansion, it tells you the stretch factor. These generators are hidden in the data; you do not see them directly, only their effects on the measurements.

The paper's core move is to learn these symmetry specifications directly through training. Once learned, they completely specify the symmetry, and the model's internal functions are built to respect that exact symmetry. The paper estimates the symmetry by fitting the model to data and measuring how well predictions match reality. If the learned symmetry specifications match the true symmetry hiding in the data, the model gains a superpower: it can predict data points that have never been seen before, because the symmetry guarantees the pattern holds.

Why it works

Why it works: building the model to match the symmetry

Symmetries have structure. A rotation in 3D space belongs to a family of symmetries called the rotation group; an expansion belongs to the scaling group. Each family has a mathematical description — the Lie algebra (a set of recipes) — that lists all the ways you can build that symmetry using small building blocks.

The paper uses this structure to design the model. For rotations, it builds layers that ignore rotation — they give the same output no matter how you spin the input. For expansions, it builds layers that scale with the input — if you expand the input by a factor of 2, the output also scales by 2. These invariant and equivariant layers are then combined. The model learns the exact generator (rotation angle, expansion factor, etc.) by trial and error: it tries different values, predicts what the data should be, and measures the error. The architecture guarantees that whatever generator the model settles on, the symmetry is automatically respected.

Why does this work? Because real physical systems obey symmetries, and the model is built to capture exactly those symmetries. A model that respects the true symmetry has fewer things to learn — it can reuse patterns across rotated versions of the same scene, or across different scales. This makes the model learn faster, because it absorbs the symmetry once and applies it everywhere, rather than memorizing each variation separately.

Math after the picture

The equation: invariance and equivariance

First in words:

For any symmetry transformation T applied to the input, an invariant layer f satisfies f(T(x)) equals f(x) — the output does not change. An equivariant layer g satisfies g(T(x)) equals T(g(x)) — the output transforms in the same way as the input. The model is built from these layers and learns the generator parameter theta that specifies which symmetry T to use.

Then the compact form:

f(T(x)) = f(x) [invariance] g(T(x)) = T(g(x)) [equivariance] theta = argmin_t sum_i (y_i - model_t(x_i))^2

Every symbol:

xone input measurement
ythe true output or label for that input
T(x)the input after applying the symmetry transformation
f(x)an invariant layer output (unchanged by T)
g(x)an equivariant layer output (transforms like the input)
thetathe generator parameter (rotation angle, expansion factor, etc)
model_t(x)the full model's prediction using parameter theta
argmin_tfind the theta value that minimizes the expression
Tiny worked example: learning a rotation
Suppose the data is 2D points that rotate by angle theta. The invariant layer computes distance from origin: f(x,y) = sqrt(x^2 + y^2). If (x,y) rotates to (x',y'), then distance stays the same: f(x',y') = f(x,y). Check: sqrt(x'^2 + y'^2) = sqrt(x^2 + y^2).
The equivariant layer computes the angle: g(x,y) = atan2(y,x). After rotation by theta, the angle becomes g(x',y') = atan2(y,x) + theta. This equals theta + g(x,y), so g transforms predictably.
The model combines them: predict the next point using distance (invariant) and angle (equivariant) from the current point. During training, the model tries different theta values and picks the one that makes the smallest prediction errors. If theta = 0.5 radians gives error 0.01 and theta = 0.6 gives error 0.05, the model chooses theta = 0.5.

Invariant layers ignore the symmetry, equivariant layers respect it predictably, and learning the generator means finding which symmetry parameter makes predictions accurate.

What can go wrong

What can go wrong

Guessing the wrong symmetry family. If the data truly has a rotation symmetry but you tell the model to look for an expansion, it will not find a good fit. The paper assumes you know whether to look for rotations, expansions, or other types, but does not automate that choice.
Noisy data drowns out the signal. If measurements are corrupted by random noise, the model may learn a symmetry specification that fits the noise rather than the true symmetry hiding in the data. More data helps because averaging over more examples dilutes the noise — ten clean measurements reveal the pattern, but ten noisy ones blur it. Very noisy systems are harder to learn from.
Symmetry applies only locally. Some systems have symmetries that hold only in small regions of state space (near equilibrium). If the data spans regimes where the symmetry breaks, the model will struggle.
Done right: use domain knowledge to pick the symmetry family, collect clean data, and verify the learned symmetry makes physical sense. If a physicist or engineer knows which symmetry family is plausible, that narrows the search dramatically. Clean measurements and a sanity check on the learned symmetry specification confirm success.
What a runnable demo should prove

What a runnable demo should prove

Build a synthetic dataset from a known system with a known symmetry — for example, a spinning top with rotation symmetry. Hide the symmetry from the model and feed it only the measurements. Train the model to discover both the symmetry type and the symmetry specifications. Then predict the top's state after an unseen rotation angle and measure how close the prediction is to the truth.

symmetry_recovery = 1 - (learned_generator - true_generator)^2 / true_generator^2 prediction_error = (model_prediction - ground_truth) / ground_truth

If the model recovers the true generator parameter within a small error (say 1 percent), and predicts unseen rotations accurately, the symmetry discovery worked.
