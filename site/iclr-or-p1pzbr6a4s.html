SONATA: Adaptive Coreset Selection for Time-Series Tensors

When streaming time-series data arrives faster than you can learn from it, SONATA picks which observations actually matter and trains only on those.

Paper explainersAll themesTime Series & Sequential

Imagine watching a dozen sensors over time, each producing numbers every second. But you cannot store or train on every measurement — that is too slow and too much data. SONATA solves this by scoring each arriving observation on four dimensions: its surprise, newness, influence on the model, and how much it would teach the model if learned. Then it trains only on the observations that scored highest on those four measures. This turns streaming into smart sampling.

Zero assumption version

Too much streaming data, too little time to learn it all

Real sensors produce data constantly. A factory might have 100 machines, each recording 10 measurements per second. That is 36 million numbers per hour. But training a model on every single number is wasteful — most of those observations teach the model nothing new.

A naive approach: keep all the data and train on all of it. This drowns the model in noise. Another naive approach: randomly throw away 90 percent of the data. This discards observations that would have taught something important. Neither works well.

The problem: you need to pick which arriving observations are worth learning from, fast enough that the decision happens before the next observations arrive, without knowing in advance which ones will matter.

In one sentence. SONATA scores each observation on surprise, newness, model influence, and learning potential, then trains only on high-scoring ones.

The algorithm as a flow

What it actually does

Score incoming data

For each new observation, compute four numbers: surprise (how different from what the model expected — big surprises mean the world changed so the model needs to learn it), newness (how different from recent observations — duplicates waste training time because identical examples teach nothing new), influence (how much learning from this would nudge the model's weights — if an observation leaves the model unmoved, it teaches nothing), and learning gain (how much would its accuracy improve if trained on this — observations that boost accuracy help future predictions, so selecting high-gain observations makes training more efficient).

Select the best

Keep observations whose combined score is highest. Discard low-scoring ones to save computation.

Feed to a factorization model

The selected observations go into a dynamic tensor factorization model (breaking the multi-sensor stream into simpler learned pieces that capture patterns across time and sensors).

Model learns fine-grained time patterns

The model uses linear dynamics (equations for how values change) and temporal kernels (learnable functions that capture when old observations still matter) to track complex time behavior.

Repeat

As new data arrives, score and select again, and update the model.

What the paper changes

What the method changes: which observations get used

SONATA changes one thing: which observations are fed into the learning step. Traditional methods use all arriving data or random subsets. SONATA uses a principled scoring function to pick only the most valuable ones.

the object it moves  =  the observation selection rule
The hidden quantity

The observation value score

measured quantity  =  combined value of an observation

The hidden quantity is a single score for each observation that combines four measurements. Surprise measures how unexpected the observation is (a big deviation from what the model predicted). Newness measures how different it is from recent data (something the model has not seen before). Influence measures how much learning from this would shift the model's weights (does it matter to how the model thinks). Learning gain measures how much the model's accuracy would improve if it learned from this observation — because if training on an observation gives almost no accuracy boost, that observation is noise and does not deserve to slow down the model.

The paper estimates this score using established machine learning scoring functions, then selects the subset of observations with the highest scores before training the tensor model.

Why it works

Why it works: selecting valuable observations saves computation and improves learning

The mechanism has three parts. First, scoring observations on surprise, newness, influence, and learning gain lets you identify which ones teach the model something real and which are just noise. An observation that is surprising, new, and high-influence likely encodes a genuine change in the world that the model should track. An observation that is none of those is redundant.

Second, by training only on high-scoring observations, you shrink the training problem. The model trains on fewer, denser examples and converges faster, because when you remove noise, each training step nudges the model in a clearer direction — the error signal from a real pattern is stronger and sharper than the error signal from random noise, so the model's weights move toward the right answer instead of chasing ghosts. This is like learning piano: practicing 10 hard pieces teaches you more than playing 100 easy pieces carelessly.

Third, for time-series tensors, capturing multi-scale temporal patterns is hard. The paper uses linear dynamical systems (equations that predict the next state from the current one) and temporal kernels (learned functions that weight old observations by how far in the past they are). These two tools together let the model learn both short-term ripples and long-term trends. When you feed them only the most informative observations, they learn cleaner patterns because noise is gone.

Math after the picture

The observation selection score

First in words:

observation_value = weight_surprise * surprise + weight_newness * newness + weight_influence * influence + weight_gain * learning_gain

Then the compact form:

score_t = w_s * U(x_t) + w_n * N(x_t, recent) + w_inf * I(x_t, theta) + w_g * G(x_t, model)

Every symbol:

score_tthe combined value of observation t
U(x_t)surprise: how different the observation is from the model's prediction
N(x_t, recent)newness: how different from recent observations
I(x_t, theta)influence: how much learning from this shifts the model's weights theta
G(x_t, model)learning gain: how much model accuracy improves if trained on this
w_s, w_n, w_inf, w_gweights that balance the four measures (set by the user or learned)
A tiny worked example
Observation A: surprise 0.9, newness 0.8, influence 0.7, gain 0.85, all weights = 0.25 each
score_A = 0.25 * 0.9 + 0.25 * 0.8 + 0.25 * 0.7 + 0.25 * 0.85 = 0.225 + 0.2 + 0.175 + 0.2125 = 0.8125
Observation B: surprise 0.2, newness 0.1, influence 0.15, gain 0.25
score_B = 0.25 * 0.2 + 0.25 * 0.1 + 0.25 * 0.15 + 0.25 * 0.25 = 0.05 + 0.025 + 0.0375 + 0.0625 = 0.175
A scores 0.8125, B scores 0.175. Select A for training. B is likely redundant noise.

The method adds the four scores with equal weight to decide which observations matter; high scores indicate an observation teaches the model something new.

What can go wrong

What can go wrong

Weighting the four scores wrong. If you set the weights so that surprise dominates, the model picks outliers and ignores systematic change. If influence dominates, it picks observations that shift the model wildly but teach nothing real. The weights must be tuned to the domain.
Selecting too aggressively. If you discard too many observations, the model misses real patterns. If you discard too few, you gain no speed.
Temporal patterns that emerge only from rare observations. If the truly important pattern (like a seasonal spike) appears only once per month but you select only daily observations, the model may miss it.
Done right. Tune the four weights to your data, use a selection ratio that preserves patterns while cutting noise, and validate on held-out time steps.
What a runnable demo should prove

What a runnable demo should prove

A demo should generate or load a dynamic tensor stream (e.g., sensor readings over weeks, or simulated multi-entity time series). Split into train and test. Train one tensor model on all observations, and another on SONATA-selected observations (e.g., the top 30 percent by combined score). Measure prediction error on the test set and wall-clock training time.

relative_error = (error_all_obs - error_selected_obs) / error_all_obs * 100; speedup = time_all_obs / time_selected_obs

The demo should show that SONATA-selected training beats all-observation training on both speed and accuracy.
