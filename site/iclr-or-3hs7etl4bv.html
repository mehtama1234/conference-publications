PGRF-Net: Multivariate Time-Series Anomaly Detection with Interpretable Evidence

A model detects anomalies in time-series data by decomposing its decision into four distinct evidence sources, so you know why it flagged an anomaly.

Paper explainersAll themesTime Series & Sequential

Detecting anomalies in time-series data (like sensor readings or stock prices) usually means choosing: either a black-box model that catches more anomalies but gives no explanation, or a transparent model that explains itself but misses things. PGRF-Net breaks this trade-off by learning to extract four kinds of evidence for why a time window is anomalous, then fusing them with learnable weights so the final verdict is both accurate and decomposable into interpretable pieces.

The Anomaly Detection Trade-Off

When you have streams of numbers (sensor readings, network traffic, stock ticks), you want to catch when something breaks without raising false alarms. The usual choice is brutal: either train a simple model that explains every decision (transparent but misses half the real anomalies), or use a complicated model that catches more (accurate but gives no reason why).

A beginner's first try: train a model to predict the next value from past values, then flag times where the prediction is wrong. This works okay, but it misses anomalies that are not just prediction errors — maybe the variables start moving in abnormal patterns together, or the underlying structure shifts, but the individual predictions stay close. The single-signal model cannot detect these anomalies because it only watches one source of evidence; it never looked for the others.

The core problem. You cannot tell whether an anomaly score came from one noisy prediction or from a genuine structural breakdown — so you cannot trust it and cannot explain it to anyone else.

The algorithm as a flow

What it actually does

Extract four signals

For each time window, measure prediction mismatch, how the variable relationships changed, how different from normal prototypes, and spike sizes.

Compute evidence scores

Turn each signal into a score: high when anomaly likely, low when normal.

Learn the gates

Train gates that weight each evidence type — some data trusts prediction error more, other data trusts structural shifts.

Fuse weighted evidence

Add the four weighted scores; the learned gate weights set how much each contributes.

Output: score and breakdown

You get a single anomaly score, plus a breakdown showing how much came from each evidence type.

What the paper changes

What changes: evidence weights

Instead of squashing all anomaly reasoning into one black-box number, PGRF-Net learns four separate weight vectors — one for each evidence source. Each vector decides how much that evidence type influences the final verdict.

the object it moves  =  evidence weights
The hidden quantity

The learned gate weights

measured quantity  =  fusion gate weights (four scalars)

PGRF-Net trains four learned numbers (one per evidence type) that say 'on this dataset, how much should I trust prediction errors versus structural changes versus prototype mismatch versus spike magnitude?' These gates are what makes the model adaptive: they are NOT hand-tuned, but learned from data. By fitting the gates to your specific dataset, the model discovers which evidence signals actually correlate with real anomalies in your data, and weights them accordingly.

The paper calls this the Gated Evidence Fusion Network. It trains these four gates jointly with the evidence extractors using a two-stage process: first learn to extract the four evidence types accurately (not overfitting), then tune the gates to combine them optimally.

Why it works

Why four evidence types beat one monolithic score

The core insight is that anomalies are not one thing. A sensor reading might jump (spike evidence), or it might move smoothly but far from where it usually sits (context evidence), or it might predict badly (prediction evidence), or it might break its normal correlation with other sensors (structure evidence). A real anomaly often shows multiple signals at once, but they are not equally trustworthy for every dataset.

By extracting four signals separately and learning their weights, PGRF-Net does two things: (1) it captures richer anomaly patterns (no single hand-tuned threshold on one score can catch all four), and (2) it lets the data choose what to trust. A dataset with bursty noise trusts spike detection; a dataset with gradual concept drift trusts structural changes. The model adapts.

Math after the picture

Gated evidence fusion equation

First in words:

The final anomaly score is a learnable weighted sum of four evidence sources: the gate for prediction-error times the prediction-error score, plus the gate for structure-change times the structure score, and so on.

Then the compact form:

a = g_pred * e_pred + g_struct * e_struct + g_context * e_context + g_spike * e_spike

Every symbol:

afinal anomaly score (higher = more anomalous)
g_predlearned gate weight for prediction evidence (0 to 1)
e_predprediction-error evidence (0 to 1, high when next value was far off)
g_structlearned gate weight for structural evidence
e_structstructural-change evidence (0 to 1, high when variable relationships shifted)
g_contextlearned gate weight for context evidence
e_contextcontextual-deviation evidence (0 to 1, high when window far from learned prototypes)
g_spikelearned gate weight for spike evidence
e_spikespike-magnitude evidence (0 to 1, high when individual jumps are large)
Tiny worked example with made-up numbers
Suppose we extract four evidence scores for one time window: e_pred=0.9 (prediction was way off), e_struct=0.3 (relationships barely shifted), e_context=0.5 (moderately far from prototypes), e_spike=0.2 (small jumps).
The model learned gates: g_pred=0.6, g_struct=0.2, g_context=0.1, g_spike=0.1 (prediction matters most on this data).
Final score: a = 0.6*0.9 + 0.2*0.3 + 0.1*0.5 + 0.1*0.2 = 0.54 + 0.06 + 0.05 + 0.02 = 0.67 (anomalous).
Without learned gates (naive equal weighting): a = 0.25*0.9 + 0.25*0.3 + 0.25*0.5 + 0.25*0.2 = 0.475 (less certain). The learned gates amplify the strong signal (0.9) and dampen weak ones (0.2, 0.3).

The gates adapt to each dataset by being tuned to maximize accuracy. On a noisy sensor where false positives are just random noise, the training process reduces the spike-detection gate weight because spikes do not correlate with true anomalies (so giving them high weight leads to wrong predictions), while increasing structural-change weight since real anomalies do show shifts. This automatic reweighting avoids hand-tuned thresholds.

What can go wrong

What can go wrong

Overfitting the gates. If the data is small or has atypical anomalies, the gates might learn to trust the wrong evidence type. The two-stage training (learn each evidence type first, then gate tuning) helps by stabilizing the evidence extractors on real patterns before the gates start reweighting, but unlabeled data with mislabeled anomalies still breaks it because the gates then fit to the labels, which are wrong.
One evidence type always dominates. If prediction errors are consistently huge (sensor is just noisy), the gate for prediction evidence may hit near 1.0 and the other gates near 0, throwing away the other three signals. You need anomalies that actually show structural changes and prototype mismatches, not just noise.
Prototypes do not capture all normal behavior. The context evidence depends on learning representative prototypes of normal time windows. If the normal data is heterogeneous (the sensor behaves very differently in morning versus night), prototypes may not generalize, making the context gate unreliable.
Done right. Diverse anomalies in the test set, training data that shows multiple real anomaly types, and a two-stage training pipeline that stabilizes the extractors before gate tuning reduce these risks. The interpretability is only useful if all four evidence types actually appear in your real anomalies.
What a runnable demo should prove

What a runnable demo should prove

Build a synthetic dataset with three types of anomalies: (1) sudden spikes in one variable (pure spike evidence), (2) a variable drifting away from its learned prototype (pure context evidence), (3) two variables that usually rise together suddenly becoming uncorrelated (pure structure evidence). Train PGRF-Net and measure its anomaly score on each type. The learned gates should amplify the matching evidence and dampen the others for each anomaly.

Then show the four-part decomposition of a real anomaly score: report not just the final number (0.8) but its breakdown (0.35 from prediction, 0.25 from structure, 0.15 from context, 0.05 from spike). A human expert should see that breakdown and nod: 'Yes, that matches what I see in the data.'

detection_accuracy = (true_anomalies_caught + true_normals_accepted) / (total_windows); gates_adapted = (gate_weight_pred > gate_weight_spike) if spike_anomalies_rare else false

The demo proves that learned gates can specialize to different anomaly types without losing the ability to catch anomalies the baseline model would miss, AND that the decomposition actually describes real patterns (an expert can audit each evidence source and agree it reflects what is happening).
