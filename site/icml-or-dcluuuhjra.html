Post-Training LLMs as Better Decision-Making Agents: A Regret-Minimization Approach

Improve decision-making agents by repeatedly fine-tuning on low-regret action trajectories instead of only distilling fixed hand-designed strategies.

Paper explainersAll themesAgents & Tool Use

Language models are often used as agents in interactive settings, yet they are not trained from the start for online decision-making. This paper asks whether post-training can improve that skill without forcing the model to imitate a fixed external algorithm, because imitation can cap improvement at the quality of the chosen reference policy. Its answer is iterative regret-minimization fine-tuning, a loop that searches for low-regret trajectories and then distills those trajectories back into the model.

Zero assumption version

Why language models make weak online decisions

A model can sound coherent and still make poor choices over time. In online decision-making, each action changes future options and future rewards. A system that reasons well in one isolated answer may still act badly when decisions must accumulate over many steps.

Earlier post-training approaches often ask the model to imitate a known decision rule or a fixed reasoning format. That can help, but it limits improvement to whatever the reference strategy already does well. This paper instead uses regret as the training signal so that the model is pushed toward trajectories that leave less value on the table.

The paper's move in one sentence. Repeatedly find low-regret decision trajectories, fine-tune the model on them, and then use the updated model to search for even better trajectories in the next round, because each improved policy can generate stronger examples than the previous one.

The algorithm as a flow

What it actually does

Run the current agent on decision tasks

Collect decision trajectories from the current model across online environments.

Measure regret

Estimate how much reward each trajectory loses relative to a better achievable sequence so that the fine-tuning set can favor action paths with smaller long-run loss.

Keep low-regret examples

Select trajectories with stronger decision quality so that the fine-tuning set contains better behavior.

Fine-tune the model

Train on those selected trajectories while preserving the model's own natural-language reasoning.

Repeat with the stronger model

Generate a new batch of trajectories from the updated policy so that the next round can improve further.

What the paper changes

What the paper changes

The paper changes the target used during post-training. Instead of copying one fixed expert rule, the model is repeatedly pushed toward action sequences that have lower regret in the actual decision environment.

the object it moves  =  the post-training target for decision-making behavior
The hidden quantity

The hidden quantity

measured quantity  =  how costly the current action sequence will look after the full horizon is finished

The important hidden quantity is future decision loss. A poor action may look harmless at the moment it is chosen, yet later it can block strong options or waste reward. You only see the full cost after the horizon unfolds.

Regret captures that hidden cost by comparing what the policy got to what a stronger sequence could have achieved. The training loop uses this comparison because it points directly to trajectories that preserve more long-run value.

Why it works

Why this works: use better trajectories to bootstrap better policies

A fixed imitation target can only take the model as far as the chosen reference policy. Iterative regret-minimization fine-tuning is more open-ended. It keeps asking which trajectories from the current model already show lower long-run loss, and then it amplifies those trajectories in the next training round.

This helps because the model is not merely copying a hand-written strategy. It is learning from the best behavior it can currently produce in the task. Repeating the loop can reduce regret over time by turning strong sequences into new training data for the next policy.

Math after the picture

Prefer trajectories with lower regret

First in words:

A simple summary is to define regret as the gap between the return of a stronger reference sequence and the return of the model's trajectory, then fine-tune on trajectories where that gap is small.

Then the compact form:

regret(path) = best_return(path) - policy_return(path)

Every symbol:

regret(path)how much reward the trajectory leaves behind
best_return(path)the return of a stronger achievable sequence for that decision problem
policy_return(path)the return produced by the current model's trajectory
pathone full action sequence through the task
A tiny worked example
Path A earns total return 6 while a stronger sequence could have earned 10.
Its regret is 4, so it is not a strong fine-tuning target.
Path B earns total return 9 while the stronger sequence still earns 10.
Its regret is 1, so it is a much better target for the next training round.
The method prefers Path B because smaller regret means less long-run value was lost.

The paper includes a broader post-training procedure, but this equation captures the central signal that guides the updates.

What can go wrong

What can go wrong

Regret estimates can be noisy. If the system measures regret poorly, it may fine-tune on the wrong trajectories because weak behavior can be mistaken for strong behavior.
Early loops may reinforce local habits. If the initial model only explores a narrow region of behavior, later fine-tuning may keep improving that narrow region instead of discovering a better policy family because the training data will keep reflecting the same limited search space.
Task coverage still matters. A model can improve on the training environments and still fail elsewhere if the collected trajectories do not cover the new decision patterns, because the post-training signal only teaches the cases that appear in those trajectories.
Done right. The framework matters because it gives post-training a sequence-level objective that reflects actual decision quality.
What a runnable demo should prove

What a runnable demo should prove

Build a small online decision environment where early choices affect later options, such as repeated pricing, inventory control, or path selection. Compare a base language agent, a fixed-imitation fine-tuned agent, and an iterative regret-minimization fine-tuned agent.

The demo should record full trajectories, estimate regret for each one, and then fine-tune only on the lower-regret examples before running another evaluation round. The iterative method should improve more steadily because it learns from full action sequences that preserve more long-run reward.

regret_drop = regret_before - regret_after ; return_gain = return_after - return_before

The result should show that post-training becomes more useful when the target is low-regret behavior over full decision sequences.
