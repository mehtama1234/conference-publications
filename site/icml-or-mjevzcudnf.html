Neural Vector Lyapunov–Razumikhin Certificates for Delayed Interconnected Systems

Use neural networks to build mathematical certificates that prove large groups of control systems stay stable even when messages arrive late.

Paper explainersAll themesRobotics & Control

When many machines (drones, cars, power grids) coordinate over networks, delays in messages between them can break stability. To use learned controllers safely, you need a formal proof that the system will not spin out of control. This paper shows how to teach neural networks to generate those mathematical proofs automatically, scaling to hundreds of agents.

Why learning-based control is risky at scale

Interconnected systems like mixed-autonomy traffic (human and autonomous vehicles), drone swarms, or microgrids need controllers that coordinate over networks. Modern controllers trained by neural networks often work well in practice. But they are black boxes: you cannot easily prove they will never fail, even with delays in messages.

A naive approach is to verify the system by testing many scenarios. But with dozens of agents and multiple-step message delays, the number of scenarios explodes. And testing never guarantees safety—you might miss the one edge case that causes a crash. That leaves a gap: learned controllers that work in tests, but no formal proof they stay safe.

The problem in one sentence. We need a way to automatically prove that a learned controller will keep large multi-agent systems stable even when messages are delayed, without testing every possible scenario.

The algorithm as a flow

What it actually does

Represent each agent's safety zone as a number

Build a function V(state) that grows when the system is in danger, shrinks when it is safe.

Check what the Razumikhin condition means for delays

Look at the old states the agent received (up to max-delay steps ago); the new safety zone must shrink faster than old zones could have grown, because worse old states would otherwise destabilize today.

Teach a neural network to compute these zones for each agent

Train on trajectories from a nominal controller; the network learns the safety score for each agent.

Verify the proof on delay histories that could actually happen

Do not check all possible delays; only check states reachable from the initial condition over time.

If verification fails, add failing cases to training and retrain

Iterate: learn certificates, verify, add counterexamples, learn again until the proof holds.

What the paper changes

What the paper changes

The paper teaches a neural network to build Lyapunov-Razumikhin functions—mathematical functions that measure system stability for networks with delayed message passing. Instead of a human hand-crafting these proofs, the network learns them from data.

the object it moves  =  Lyapunov-Razumikhin certificates
The hidden quantity

The hidden quantity: stability margin under delay

measured quantity  =  Lyapunov contraction rate with message delays

The paper measures how fast the system state shrinks when delays occur. A Lyapunov function (a safety score) is a single number that tells you how far from danger the system is. The key is the Razumikhin condition: it looks at the worst state any agent received in the last max-delay steps, and checks whether the current agent's safety score will shrink on the next step despite that worst history. If it shrinks reliably, the whole network converges to safety no matter what delays happen (up to the maximum allowed).

The paper estimates this by training a neural network to predict the safety score for each agent, then verifying that the Razumikhin inequality holds for all possible message-delay histories that could actually occur. The coupling strength (how much one agent's drift can push another) is learned; the small-gain condition ensures disturbances do not amplify as they spread through the network.

Why it works

Why the neural certificate works

A Lyapunov function is a mathematical object that proves a system is stable: if the function always shrinks when the system evolves, the system must converge to a safe state. The challenge is that in interconnected systems with delays, you must account for neighbors' old states. The Razumikhin condition solves this: it says the function shrinks if the current state is worse than any past state multiplied by a coupling factor. This trades an infinite-history problem for a finite check.

The paper teaches a neural network to learn this function by training on nominal controller trajectories and iteratively verifying it. When verification finds a failure—a state that could occur but the function does not shrink—that state becomes a new training example. The network retrains to fix the gap. This iteration eventually converges to a certificate that covers all states the system can actually reach, not all theoretically possible states.

Math after the picture

The Razumikhin condition in equations

First in words:

The safety score for agent i at time k must satisfy two rules. First, the score is bounded: it grows with how far the state is from the origin. Second, the Razumikhin condition checks that if the worst safety score a neighbor reported in the past maximum-delay steps is below a scaling factor times my current score, then my score must shrink by an amount related to the coupling strength and a disturbance parameter.

Then the compact form:

Safety_i(k+1) <= sum of (coupling_i,j times neighbor Safety_j(k)) plus disturbance_penalty where the Razumikhin condition holds if: max(past neighbor safety scores over max-delay steps) <= scaling_factor times current Safety_i

Every symbol:

Safety_i(k)Safety score for agent i at time step k
coupling_i,jHow much agent j's drift influences agent i (learned from data)
scaling_factorThreshold in the Razumikhin condition (controls how delays are handled)
disturbance_penaltyHow much external noise reduces contraction speed
max-delayLongest message delay in the network
past neighbor safetyThe worst safety scores neighbors reported in the last max-delay steps
A tiny worked example
Agent 1 at step k: safety score is 16 (at the edge of the safe zone).
Agent 2 sent safety score of 8 two steps ago; Agent 1 is its neighbor. Check Razumikhin: is 8 below scaling_factor times 16? If scaling_factor is 0.9, then is 8 below 14.4? Yes.
Razumikhin condition holds. On next step, Agent 1's safety score should drop to at most: 0.5 times 16 (coupling strength) plus 0.3 times 8 (neighbor) plus negligible disturbance = 8 plus 2.4 = 10.4.
Score shrank from 16 to 10.4. Repeated shrinking proves the system stays bounded.

The neural network learns the safety score function and coupling coefficients to satisfy this inequality on all reachable trajectories.

What can go wrong

What can go wrong

The Razumikhin condition is too strict. If p is too small, the condition requires old neighbor states to matter very little. The network may not find a feasible certificate even though the system is truly stable. Solution: tune p adaptively during synthesis.
Reachable set is not computed exactly. The paper computes reachable delay histories through one-step reachability. If this over-approximates the true reachable set (includes states that cannot actually occur), verification becomes conservative but still sound. If it under-approximates, the proof might miss genuine scenarios.
Neural network overfits to training trajectories. The network is trained on nominal-controller rollouts. If the test involves a different control policy or larger disturbances, the learned safety score may not actually satisfy the Razumikhin condition. Verification guards against this by testing on all reachable states.
Done right. When reachable set computation is exact and Razumikhin scaling factors are well-tuned, the neural certificate guarantees that all trajectories originating from the initial set stay bounded under any message delays up to the maximum allowed.
What a runnable demo should prove

What a runnable demo should prove

Build a small multi-agent system: three agents coordinating over a network with random delays up to 2 steps. Give them a learned controller trained on nominal trajectories (e.g., a nominal model-predictive controller or a policy network). Train a neural Lyapunov-Razumikhin certificate on those trajectories. Run verification to check the Razumikhin condition at each reachable state. Then, simulate the closed-loop system with the learned controller under random delays and plot the safety score over time for each agent. The demo must show that the scores shrink monotonically when the Razumikhin condition holds, proving the system is stable.

Certificate validity: fraction of reachable time-steps where Razumikhin condition holds. Closed-loop stability: the maximum state size stays bounded over long time horizons.

If the neural certificate's Razumikhin condition is verified over reachable states, the system will stay bounded in the real closed-loop—no matter when messages arrive, as long as delays do not exceed the maximum allowed.
