High-Order Derivative GNN

Graph neural networks see more patterns by measuring how their own outputs change when node data shifts slightly.

Paper explainersAll themesGraph & Geometric Learning

Standard graph neural networks (models that reason about networks of connected things) can only learn limited patterns from a graph's structure. This paper shows that measuring how the model's outputs shift when you nudge the input numbers—called taking derivatives—reveals richer structure. The method stacks two models: the first measures these derivative signals, the second learns from them, unlocking expressivity that matches the strongest known graph-reasoning hierarchy.

Zero assumption version

Graph neural networks hit an expressivity ceiling

A graph neural network is software that reads a network (nodes connected by edges) and learns patterns from how nodes relate. The model updates each node's learned state by looking at its neighbors, passing messages back and forth in layers.

But these models are stuck: they can only discover certain kinds of patterns, no matter how many layers you add. A beginner might hope that stacking more layers or making them wider would help—and it does, but only a little—because the fundamental architecture limits what signals can flow. Some graph structures are forever invisible to these models. For example, a graph where two nodes are 4 hops apart looks identical to a graph where they are 10 hops apart if the model only counts neighbors at each step. The model's reasoning machinery is too rigid to see the difference, because message-passing can only aggregate what it has already seen, never uncover new structural clues.

The paper's move in one sentence. Measure how the model's outputs shift when node data nudges slightly, feed those shifts as new signals, and a second model learns richer patterns from them.

The algorithm as a flow

What it actually does

Step 1: Run the base model

Feed the graph into a standard message-passing neural network, get outputs and final node states.

Step 2: Compute derivatives

Measure how much each output shifts when you nudge each input node's numbers by an infinitesimal amount, using calculus.

Step 3: Encode derivative signals

Convert the derivative numbers into new features per node, using a learned encoder network.

Step 4: Feed to second GNN

Pass the derivative-based features into another graph neural network on the same graph structure.

Step 5: Train end-to-end

Both the base model and the second model update their weights together, with error signals flowing backward through the derivative computation.

What the paper changes

What the paper changes

The paper modifies the node features (the list of numbers representing each node). Instead of using only the original input numbers or the base model's learned states, it augments them with derivative-based signals that capture how sensitive the model is to input changes.

the object it moves  =  node features
The hidden quantity

The hidden quantity: sensitivity grid

measured quantity  =  sensitivity grid

A sensitivity grid is a table of numbers measuring how each part of the model's output changes when you shift each part of a node's input data. It answers: if I nudge input feature j at node u by a tiny amount, how much does output component i move? The paper computes these for multiple orders (first-order, second-order, third-order, etc.), capturing increasingly complex sensitivity patterns.

The paper estimates these sensitivities using a clever algorithm that works like message-passing itself: each layer of the sensitivity grid builds from the layer before, and the algorithm exploits sparsity (most sensitivities are zero) so it runs fast on real graphs. Because the algorithm is fully differentiable—built only from arithmetic and neural-network operations that support backpropagation—the training loop can automatically adjust both the base model's weights and the encoder's weights to improve sensitivities and their interpretation in tandem.

Plain reading. The sensitivity grid measures how picky the model is about each input number. If the output barely budges when you change input feature j, that sensitivity is near zero. If the output jumps a lot, the sensitivity is large. The paper stacks these measurements as new node features.
Paper reading. The k-th order sensitivity grid has dimensions tracking node pairs, feature indices, and sensitivity order. The paper defines this grid component as the rate of change of output h-i at node u with respect to input features at node u, applied k times.
Why it works

Why it works: two models see what one cannot

Graph neural networks express what they see by passing numbers between neighbors. A standard model can only see patterns that emerge from counting hops and aggregating signals along paths. But some graph structures—like two distant nodes that are topologically equivalent but far apart—are invisible because the model's message-passing routine treats them identically.

The sensitivity signals break this symmetry. When you compute how sensitive the base model is to input nudges, you are asking a different question: does the model's reasoning depend on the precise input values in a way that distinguishes these two structures? The answer is often yes. By encoding this sensitivity as new node features, you give the second model access to a richer signature of each node's role in the graph. The second model can then discover patterns the first one could not express, because the new features contain structural information that was implicit in the first model's learned weights but never made into explicit signals for reasoning.

Why this matters: the first model does know the difference between structures (its weights encode it), but it has no way to communicate that difference forward. Sensitivity measurements act as the translator, converting what the model learned implicitly into explicit features the second model can reason with.

The sensitivity grid and its encoding

First in words:

For each node u and each order k, compute the k-th order partial derivative of the base model's output h with respect to u's input features X_u. Encode these derivatives using learned networks U_node and U_out to produce new node features. Pass these augmented features to the downstream GNN.

Then the compact form:

sensitivity[u, i, k] = (change in output_i) / (change in input_u), taken k times; h_new_v = U_node(sensitivity grid); output = GNN_2(h_new, graph_structure)

Every symbol:

sensitivity[u,i,k]k-th order rate of change: how much output i shifts when input u shifts, repeated k times
input_unode u's numerical features
output_ii-th number in the base model's output
U_nodeencoder network that reads the sensitivity grid and makes new node features
h_new_vnew augmented features for node v
GNN_2second graph neural network
A tiny worked example: one node, two derivatives
Suppose node A has input [0.5, 0.3] and the base model outputs [2.1] at node A.
Nudge input feature 1 by 0.01: output becomes [2.14]. Sensitivity w.r.t. feature 1 is approximately (2.14 - 2.1) / 0.01 = 0.4.
Nudge input feature 2 by 0.01: output becomes [2.08]. Sensitivity w.r.t. feature 2 is approximately (2.08 - 2.1) / 0.01 = -0.2.
These two numbers [0.4, -0.2] become new features for node A, signaling that the model cares strongly about feature 1 but ignores or opposes feature 2.
The encoder network U_node learns how to interpret these sensitivity numbers in the context of the graph structure.
The second GNN then uses [0.4, -0.2] plus the original features to discover patterns the first model could not see.

The sensitivity numbers reveal which inputs the model cares about. High sensitivity means the output shifts a lot when that input shifts. Low or negative sensitivity means the output barely shifts or shifts the opposite way. The encoder learns to turn these numbers into new features.

What can go wrong

What can go wrong

Computational cost with high-order sensitivities. Computing k-th order sensitivities on large graphs requires storage that grows exponentially with the order. For k=3 on a 10,000-node graph, this balloons. The paper addresses this by exploiting sparsity (most sensitivities are zero) and using shallow base models, but very large graphs and high orders can still be slow.
Sensitivity noise on small graphs. If the graph is tiny or features are sparse, sensitivity numbers may be swamped by rounding error or overfitting patterns. The encoder may then learn fake patterns from random noise rather than real structural signals.
Encoder design matters. The new node features are only as useful as the encoder networks that interpret the sensitivities. If the encoder is too simple, the sensitivity signals go unused. If it is too flexible, it overfits. The paper does not exhaustively test all encoder designs.
Done right. Use k=1 or k=2 for most benchmarks (shallow sensitivities), choose encoder depth based on graph size, and train the full pipeline end-to-end so error signals flow backward through both the base model and the encoder, letting them both adapt to optimize sensitivity and interpretation jointly.
What a runnable demo should prove

What a runnable demo should prove

Build a graph classification task on a synthetic or real dataset (e.g., predicting whether a molecular graph has a certain property). Compare a baseline message-passing GNN against HOD-GNN. Compute derivatives of the baseline model on a few graphs, encode them, visualize which nodes or features the encoder found most important. Show that HOD-GNN scores higher on a test set. Then ablate: remove the derivative step or freeze the encoder, and verify that performance drops back toward the baseline.

improvement = (HOD_GNN_test_accuracy - baseline_test_accuracy) / baseline_test_accuracy

The demo must show that the derivative signals—not just the second model's extra capacity—drive the win, by proving ablation of derivatives or the encoder tanks performance.
