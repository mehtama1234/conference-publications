VUDG: A Dataset for Video Understanding Domain Generalization

A benchmark dataset that tests whether video models trained on one type of video can still work when they encounter completely different-looking videos in the real world.

Paper explainersAll themesDatasets & Benchmarks & Evaluation

Video models are trained on carefully curated data, but real-world videos look different: some are cartoons, some are filmed at night, some shake because the camera moves. When a model sees a video that looks nothing like its training data, it often fails. VUDG is a dataset designed to measure this exact problem and track which models are most brittle.

Zero assumption version

Models learn one style, break on another

Video models are trained on videos that look a certain way: maybe they all come from YouTube, or they all have clear lighting, or they all show people standing still. When the model meets a video that looks completely different—a cartoon, a night-vision shot, surveillance footage—it often fails to understand what is happening. The model has memorized a specific visual style, not the actual activity.

A beginner might think: train the model on diverse videos and it will learn to ignore the style and focus on the activity. But in practice, when you train on a diverse mix, the model still overspecializes to whichever style dominates the training set. When it then meets a domain it has never seen (like surveillance footage with a particular visual pattern), the model's accuracy drops sharply.

The paper's solution in one sentence. Build a dataset with 11 completely different video domains, measure how much accuracy drops when models switch domains, and provide a benchmark that forces researchers to solve domain generalization for video.

The algorithm as a flow

What it actually does

Collect videos from 11 domains

Search YouTube, game footage, movies, virtual worlds, head-mounted cameras, security feeds, shaky clips, foggy scenes, night shots, rain, snow.

Keep training and test separate

Pull training videos from YouTube, ShareGPT4Video, InternVid; pull test videos from entirely different sources to block data leakage.

Ask a video model to write questions

Use Gemini-2.5-Flash to generate open-ended questions about each video (what action, who, where, why).

Auto-generate multiple choice

Use DeepSeek-v3 to turn each open question into a quiz with wrong answers.

Human review and fix

Humans spot errors and correct them, producing high-quality QA pairs labeled with which domain they came from.

What the paper changes

What the paper measures

The paper does not change how models work; it changes what data we test them on. Instead of a single video-understanding benchmark, VUDG creates 11 separate test sets that are deliberately mismatched to the training data. A model trained on domain A is then tested on domain B, C, D... all the way to K. This mismatch forces the model to generalize.

the object it moves  =  test domain mismatch
The hidden quantity

The domain-shift penalty

measured quantity  =  accuracy drop across domains

The hidden quantity is simple: how much does a model's accuracy fall when it moves to a new domain? If accuracy on the training domain is 85% and accuracy on a test domain is 45%, the penalty is 40 percentage points. This penalty reveals how brittle the model is—a low penalty means it generalizes well, a high penalty means it is locked into one visual style.

The paper computes this penalty for every model on every domain pair. For example, a model trained on cartoon videos might perform 75% on test cartoon videos but only 30% on test surveillance videos: a 45-point penalty. By collecting all these penalties into a table, VUDG reveals which domain pairs are hardest and which models fail least often.

Plain reading. A domain shift is when the visual appearance of a video changes (lighting, camera angle, color, texture) even though the activity stays the same. A domain-shift penalty is how much worse a model performs when it encounters that shift.
Paper reading. The paper evaluates models in two settings: single-domain generalization (train on one source domain, test on all other target domains) and multiple-domain generalization (train on N-1 domains, test on one target domain). It reports average accuracy per domain and per model, then computes how much performance degrades.
Why it works

Why a dataset like this forces progress

Most video datasets (YouTube, generic internet data) have a dominant visual style. A model trained on them learns two things tangled together: how to recognize actions, and how to recognize the specific texture/lighting/angle of that dataset. When the model switches to a domain with a completely different visual style, it tries to apply both rules. The texture rule fails first, breaking the model's ability to see the action underneath.

VUDG forces separation by testing the same models on radically different visual styles. If a model performs well on cartoon videos but fails on surveillance videos, we know it memorized something about cartoons. The benchmark makes that brittleness visible. Researchers then must invent methods (like data augmentation, style transfer, or domain-aware training) that focus on the action signal instead of the visual wrapper. VUDG measures whether those methods actually work by scoring them on all pairs of domain combinations.

Measuring the domain shift

First in words:

accuracy drop = accuracy on training domain minus accuracy on test domain

Then the compact form:

penalty = acc_train_domain - acc_test_domain

Every symbol:

acc_train_domainhow often the model gets it right on videos it was trained on
acc_test_domainhow often the model gets it right on videos from a completely different domain
penaltythe size of the accuracy drop (in percentage points)
A tiny worked example
Model trained on YouTube videos scores 85% on YouTube test videos.
Same model tested on surveillance videos scores 45% on surveillance test videos.
Penalty = 85 - 45 = 40 percentage points.
The model lost 40 points of accuracy when switched domains, so it is brittle to this shift.
For a model that generalizes well: YouTube 82% -> Surveillance 78%, penalty only 4 points.

The penalty is zero when a model performs the same on both domains (perfect generalization) and large when the domain shift breaks the model's understanding.

What can go wrong

What can go wrong

Data leakage. If a test video was already used in the model's pre-training, the model will perform well artificially. VUDG avoids this by collecting training and test videos from different sources for each domain, ensuring no overlap with pre-trained model data.
Semantic inconsistency across domains. If domain A has mostly 'person running' but domain B has mostly 'person sitting', then the benchmark measures change in which activities appear, not visual style change. VUDG keeps the same activity concepts across all 11 domains to isolate visual shift from task shift.
Annotation noise. If questions or answers are wrong, models score poorly for the wrong reason. VUDG uses Qwen2.5-VL to generate questions, DeepSeek-v3 to generate multiple choice, and human reviewers to catch errors.
Benchmark limits. A benchmark reveals brittleness but does not solve it. VUDG shows that models fail on unseen domains, but researchers must invent new training methods or architectures to fix the problem. The benchmark itself is the tool, not the cure.
What a runnable demo should prove

What a runnable demo should prove

A concrete demo would pick a video model (such as LLaVA-Video or any LVLM), train it on videos from one domain (e.g., YouTube clips), then test it on videos from a different domain (e.g., surveillance footage). Record the accuracy on both. Repeat for all 11 domain pairs. Plot a heatmap showing where the model succeeds and fails. The demo proves that domain shift is real and measurable—a trained model's accuracy genuinely drops when confronted with a visually different domain.

domain generalization score = (1 - avg_penalty) * 100%, where avg_penalty is mean accuracy drop across all domain pairs

A demo heatmap should show clear stripes of good and bad performance, revealing that models have visual preferences and are not truly learning domain-invariant action recognition.
