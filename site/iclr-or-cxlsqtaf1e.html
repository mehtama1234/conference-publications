Preconditioned Gradient Descent Breaks the Spectral Bias Wall

Preconditioned gradient descent escapes the slow learning phase by exploring all the weights uniformly instead of following frequency patterns.

Paper explainersAll themesLearning Theory

Neural networks learn low frequencies first, then high frequencies last. This spectral bias helps them ignore noise but traps them in a slow learning phase called grokking, where the model trains on examples for hundreds of steps before suddenly starting to generalize. This paper shows that preconditioned gradient descent, which adjusts each learning step by the local difficulty of the loss surface, breaks out of this trap by exploring all the numbers it controls (weights) at a uniform rate instead of following frequency patterns.

Zero assumption version

The frequency trap

Neural networks have a built-in bias: they learn simple patterns first and complex patterns last. In vision, they learn edges before learning faces. In sound, they learn pitch before learning tone. This spectral bias means the network is drawn toward low frequencies first, which helps ignore random noise because low-frequency patterns are smooth and stable across small changes in the input, so they generalize well. But it becomes a trap. To learn both simple and complex patterns, the network must pass through a frustrating phase where it memorizes all the training data perfectly but still fails on new data. This phase, called grokking, can last hundreds of training steps, making it seem the network has stalled.

A naive approach to speed up training is to just run the standard learning algorithm longer, but this does not work because the algorithm is stuck in a local neighborhood of the loss surface and simply repeating the same moves over and over does not help it escape. Standard gradient descent moves each weight by a fixed amount, treating every weight as equally important. On a loss surface shaped like a canyon, a weight controlling a high-frequency detail might need huge moves to budge, while a weight controlling a low-frequency background moves easily. The algorithm gets trapped in the low-frequency canyon and never explores upward to the high-frequency valleys where it could learn detailed, generalizable patterns.

In one sentence. Preconditioned gradient descent adjusts each weight's learning rate by how important it is, so the algorithm explores high frequencies at the same speed as low frequencies.

The algorithm as a flow

What it actually does

Start from spectral bias.

Neural networks naturally favor low frequencies, so standard gradient descent learns them first.

Measure curvature.

For each weight, compute how sharply the loss surface curves. High-frequency weights sit in sharper valleys.

Invert curvature to set learning rates.

Weights in sharp valleys take tiny steps; weights in flat regions take larger steps. This balances exploration.

Explore the NTK uniformly.

All the weights now get searched at the same speed regardless of frequency, breaking the bias.

Switch to standard descent and generalize.

Once high frequencies are learned, switch to standard gradient descent to lock in the solution without overfitting.

What the paper changes

What the paper changes

The paper changes how fast each weight gets updated. Standard gradient descent moves all weights by the same small amount. Preconditioned gradient descent computes the loss surface's local curvature, flips it upside down, and multiplies it by the gradient. This creates a different learning rate for each weight, adapted to the shape of the terrain it sits in.

The hidden quantity

The uniform exploration rate

measured quantity  =  NTK subspace exploration speed

The hidden quantity is how fast the network explores different frequency modes. In standard gradient descent, each mode gets explored at a different pace, determined by its frequency. Low frequencies move fast; high frequencies move slowly. This creates the spectral bias trap.

Preconditioned gradient descent measures the curvature of the loss for each frequency mode. Higher curvature means a sharper valley, so the algorithm takes smaller steps. The paper shows that when you invert the curvature, the exploration pace becomes uniform: all frequencies get explored at the same speed, regardless of whether they are low or high frequency. The paper estimates this uniform pace through theoretical analysis of the eigenvalues of the loss curvature table (called the Hessian), which captures how the slope changes in every direction.

Why it works

Why it works: conquering the canyon

Imagine the loss surface as a canyon with a floor and two walls. The floor represents low-frequency patterns the network can easily learn. The walls are steep valleys representing high-frequency details. Standard gradient descent slides down the floor fast but barely climbs the walls. Each wall is steep, so even a small step in the direction of the wall sends the algorithm sliding back down.

Preconditioned gradient descent inverts the steepness. For walls (steep directions), it takes small steps. For the flat floor, it takes large steps. This way, the algorithm can spend the same amount of progress climbing any direction, whether it is the easy floor or the steep walls. In mathematical terms, the algorithm computes the Hessian matrix, which describes curvature in every direction. It inverts this matrix to scale the gradient: steep directions get divided by large numbers, flat directions by small numbers. The result is uniform exploration.

Once all frequencies are learned, the network has learned detailed, useful patterns at every scale and can generalize well. At this point, switching to standard gradient descent keeps the weights stable without the need for continued uniform exploration.

Math after the picture

The update rule with preconditioned steps

First in words:

Next weight equals current weight minus learning rate times (inverted Hessian times gradient). The Hessian measures local curvature.

Then the compact form:

theta_{n+1} = theta_n - eta * M^{-1} * nabla_theta L

Every symbol:

theta_nthe network weights at step n
theta_{n+1}the network weights at the next step
etathe learning rate, how aggressively we move
Mthe Hessian matrix, describing curvature (second derivatives) of the loss
M^{-1}the inverse of the Hessian, flattens steep directions, enlarges flat directions
nabla_theta Lthe gradient, which direction and size to nudge the weights
A tiny worked example
Suppose we have two weights: one controlling a low-frequency pattern, one controlling a high-frequency pattern.
Low-frequency weight: Hessian curvature = 1.0 (flat). Gradient = 0.1. Update = 0.1 * 1.0 / 1.0 = 0.1.
High-frequency weight: Hessian curvature = 100.0 (steep). Gradient = 0.1. Update = 0.1 * 100.0 / 100.0 = 0.1.
Both weights move by 0.1 even though the high-frequency weight sits in a much steeper valley. This is uniform exploration.
With standard gradient descent, the high-frequency weight would move only 0.001 because the steep curvature multiplies the learning rate.

The inverted Hessian (M^{-1}) rescales the gradient so steep directions get small nudges and flat directions get large nudges, equalizing progress.

What can go wrong

What can go wrong

High-frequency overfitting. If you use preconditioned descent for too long, the network learns the high-frequency noise in the training data, defeating the purpose of generalization. Spectral bias protected against this. Solution: switch to standard gradient descent once the NTK regime is exhausted.
Hessian computation is expensive. Computing the full Hessian matrix requires computing second derivatives of the loss with respect to every weight pair. For large networks, this can be slower than many training steps. The paper approximates the Hessian using the Fisher information matrix or Gauss-Newton, which requires only Jacobians, but this is still not as cheap as standard gradient descent.
Hessian can be nearly singular. If the Hessian has tiny eigenvalues, inverting it amplifies noise. Gently steering the Hessian by adding a small constant to eigenvalues can help, but this adds another hyperparameter.
Done right: hybrid strategy. Use preconditioned descent for a fixed number of steps to escape spectral bias and explore high frequencies uniformly, then switch to standard gradient descent or adaptive methods like Adam to refine and generalize without overfitting the noise.
What a runnable demo should prove

What a runnable demo should prove

Build a simple neural network (two hidden layers, 80 units) trained on a synthetic task where the true answer depends on both low-frequency and high-frequency patterns of the input. A physics-informed neural network (PINN) solving a differential equation is ideal: the solution has both smooth (low-frequency) and oscillatory (high-frequency) terms. Train with standard gradient descent, measure how long until the training loss converges and how long until the test accuracy jumps. Then train the same task with Gauss-Newton preconditioned descent for 2000 steps, then Adam for 20000 steps. Measure the same metrics.

grokking delay = steps where train loss below threshold minus steps where test accuracy jumps above threshold

Preconditioned descent should cut the grokking delay (measured in training steps) by at least 3x, and the final test accuracy should be comparable or better, because uniform exploration of all frequencies allows the network to learn both simple and complex patterns at the same time, while standard descent wastes most steps learning only simple patterns. This directly proves the algorithm is exploring frequencies uniformly instead of being trapped by spectral bias.
