Federated Graph Learning with Kalman Filtering

When multiple organizations train a graph neural network together without sharing raw data, use Kalman filtering to separate real graph structure from noise introduced by feature differences.

Paper explainersAll themesGraph & Geometric Learning

Multiple organizations want to train a single graph neural network together without sharing their raw data. The problem: each organization has its own graph with different node features and different connection patterns, so when they average their updates, the real structure gets buried in noise. This paper uses Kalman filtering (a technique for separating signal from noise over time) to filter out the structural noise in each layer, keeping the structure clean while averaging globally.

Zero assumption version

Separate organizations, separate graph structures

When multiple hospitals, universities, or companies want to train one model together on their graph data (like medical records linked by patient similarities or citation networks linked by research topics), they cannot share the raw data for privacy reasons. A naive approach: each organization trains locally and averages all the weight numbers. But graphs are different everywhere—one hospital has sicker patients connected differently, another has healthier ones. When you average weights trained on such different structures, the averaging destroys the real patterns each site learned.

The deeper problem: graph neural networks learn structure twice—once by encoding what node features look like, once by learning which nodes to connect. When features differ, the connection patterns shift too. Averaging assumes the connections mean the same thing at every site. They don't.

The challenge in one sentence. Averaging weight updates from graphs with different structures and features corrupts the real patterns each site learned.

The algorithm as a flow

What it actually does

Model each layer as a hidden system

Treat the graph structure as an invisible state, node features as noisy measurements of it.

Apply Kalman update

In each layer, blend the starting structure guess with the observed feature patterns.

Filter at each site locally

Each organization cleans its own structure signal before sending updates to the global server.

Each site applies the averaged structure back to its own features, preserving its unique graph.

What the paper changes

What the paper changes

Fed-Kalter changes how graph structure parameters (the learned numbers that encode which nodes connect) are aggregated across sites. Instead of treating all numbers equally, it isolates and cleans the structural embeddings (the specific numbers encoding which nodes connect) in each layer using Kalman filtering, then aggregates only those. This means the averaging happens on structure that has already been filtered free of feature-induced noise.

the object it moves  =  structure embeddings (filtered per-layer)
The hidden quantity

Feature-induced structural drift

measured quantity  =  Structural noise coupling to features

The hidden quantity is how much the graph connections at each site are shaped by that site's unique node features, rather than true underlying structure. When a hospital has mostly old patients with certain diseases, that shapes which patients connect. When averaging assumes all connections mean the same thing everywhere, it treats this feature-specific structure as universal—a mistake that causes drift.

Fed-Kalter estimates this by modeling structural embeddings as latent states (invisible patterns) and feature-augmented neighborhoods as noisy observations of those patterns. Kalman filtering computes how much of the observed connection pattern is real signal versus feature-driven noise.

Why it works

Why filtering structure preserves global learning

Federated learning requires averaging: each site sends updates, the server averages them, and sends back the global model. The problem with graphs: when you average connection parameters trained on different local features, you blend real structure with noise. Site A learned connection A because its features support it AND its actual data has it; Site B learned the opposite for different reasons. Averaging muddles both signals.

Kalman filtering breaks this confusion. In each layer, it models the situation as: true structure exists (but we cannot see it directly), and each site observes that structure through its own feature lens, which adds noise. The filter estimates what the structure would be if we removed the feature-specific distortion. Now when the server averages across sites, it averages structure that has already been cleaned. Each site can then apply this global structure back to its own features, preserving its unique shape without the averaging-induced corruption.

Math after the picture

Kalman filtering in graph connection layers

First in words:

In each layer, the Kalman filter updates the structural embedding by blending a prior prediction with observed evidence, weighted by uncertainty.

Then the compact form:

x_t = x_(t-1) + K_t * (z_t - H * x_(t-1))

Every symbol:

x_(t-1)prior structural embedding before this step
x_tupdated structural embedding after filtering
z_tobserved feature-augmented neighborhood (noisy measurement)
Hmeasurement matrix (extracts what we expect to observe from the structure)
K_tKalman gain (how much to trust new evidence vs prior; learnable)
z_t - H * x_(t-1)prediction error (mismatch between observation and prior)
A tiny worked example (one layer, one site)
Prior structure x_0 = 0.3 (weak connection guess before this site's data).
Observed neighborhood z_1 = 0.8 (strong connection in this site's features).
Measurement matrix H = 1.0 (features directly reflect structure).
Prior prediction: H * x_0 = 1.0 * 0.3 = 0.3.
Prediction error: z_1 - 0.3 = 0.8 - 0.3 = 0.5.
Kalman gain K = 0.6 (learned; means: 60% trust new evidence, 40% trust prior).
Updated structure: x_1 = 0.3 + 0.6 * 0.5 = 0.3 + 0.3 = 0.6.
Interpretation: the true connection is probably around 0.6, not 0.8; we filtered out 0.2 of feature-specific noise.

The Kalman gain is learned for each site, so every organization can tune how much to trust its own data versus global structure.

What can go wrong

What can go wrong

Feature patterns are not random noise. If features at different sites have systematic structure (e.g., all hospitals in one region have very sick patients, all in another are healthy), the Kalman filter assumes noise but encounters real signal. The filter may overcorrect, removing true structural differences.
Kalman gain learned from limited local data. Each site learns its own Kalman gain (how much to trust new observations). With small local datasets, this estimate can be unreliable, and some sites may over-correct or under-correct.
Does not directly model graph-specific heterogeneity. The method addresses feature-driven structure corruption but assumes the core problem is noise, not systematic structural disagreement. If sites have fundamentally different graph topologies (e.g., star vs tree), filtering will not resolve the mismatch.
Done right. When feature distributions differ but underlying structure is shared (e.g., hospitals with different patient populations but same disease co-occurrence patterns), Kalman filtering cleanly separates the two, and federated learning works.

What a runnable demo should prove

Build a synthetic federated graph classification task: create 5 sites, each with a graph-classification problem (e.g., predict whether a molecular graph is active or toxic). Vary the node feature distributions across sites (one site: all large molecules, another: small molecules; one site: high carbon content, another: low carbon). Train a standard federated graph neural network on one version and Fed-Kalter on another. Measure the accuracy of site-specific models (does each site still work on its own data?) and the global model (does the averaged structure generalize?).

site_local_accuracy_after = (fed_kalter_local) - (naive_federated_local); global_generalization = fed_kalter_global_accuracy - naive_federated_global_accuracy

The demo should show that naive federated averaging drops each site's accuracy 15-25% after global aggregation, while Fed-Kalter drops it only 5-10%, because filtering removes the noise before averaging.
