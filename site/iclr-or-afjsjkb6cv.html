EXPO: Stable Reinforcement Learning with Expressive Policies

Train complex action-generating models reliably by splitting the task into a stable base model plus a small editor that steers actions toward higher rewards.

Paper explainersAll themesReinforcement Learning

Modern reinforcement learning (RL is when a robot or agent learns by trying things and getting reward feedback) often uses simple Gaussian policies (think a bell curve for which action to pick). But expressive policies like diffusion (a model that generates actions through repeated small refinements) are much better at complex tasks, because they can learn to produce a wider variety of actions and adjust them in fine detail, rather than picking from a fixed bell curve. The problem: diffusion policies have a long chain of steps, making it nearly impossible for reward signals to flow backward and update the weights correctly. EXPO fixes this by splitting the job: a big, stable base policy handles most of the work via imitation learning (learning from good examples), and a tiny Gaussian edit policy (just a small adjustment model) learns to steer the base policy's actions toward higher rewards.

Zero assumption version

Why expressive policies break with direct reward training

A Gaussian policy is a simple model: it outputs a single action choice from a bell curve. When you train it with RL, reward signals flow backward through just a few steps, so weights update smoothly.

A diffusion policy generates actions through many small steps (like repeatedly denoising an image into an action). When you try to optimize this long chain against a reward function, gradients either vanish (become too small to matter) or explode (become too large and crash training). The chain is simply too long.

A beginner would try to do what works for simple policies: backprop the reward signal all the way through the diffusion chain. This fails. The gradients die or blow up halfway through, leaving the base model untrained and the whole learning unstable.

The core problem. Long action-generation chains cannot be trained stably by directly optimizing against rewards.

What the paper changes

What the paper changes

The paper changes how you combine two separate policies. Normally in RL you have one policy and train it end-to-end. EXPO instead uses two policies at once: a large base policy (trained only on imitation) and a small edit policy (trained on reward signals). The trick is that you never backprop reward gradients through the long diffusion chain. Instead, gradients only flow through the tiny edit policy, which is just a Gaussian — short and stable.

In normal RL, you measure how far reward signals can flow backward through the model before they vanish or explode. For a simple Gaussian, this distance is short (stable). For a diffusion policy, it is very long (unstable).

EXPO measures this by checking: does the edit policy's gradients update it successfully, or do they die? The method avoids the problem altogether by keeping reward-based learning confined to the tiny edit policy, leaving the long diffusion chain untouched.

Why it works

Why splitting into two policies makes training stable

A diffusion policy is like a long assembly line: action proposal -> refinement step 1 -> refinement step 2 -> ... -> final action. When you try to send reward feedback backward through all these steps, the signal weakens (vanishes) or amplifies wildly (explodes). The diffusion policy was designed to learn from examples, not from reward signals.

EXPO's key insight: do not force the diffusion policy to learn from rewards. Instead, train it on imitation learning (learning to copy good examples from offline data), which is what diffusion policies are built for and do stably. Then, separately, train a tiny Gaussian edit policy that learns one simple thing: nudge the base policy's actions slightly toward higher reward. This Gaussian is short (no long chain), so its gradients are stable. The edit policy outputs small adjustments (delta-actions), not full actions.

At decision time, you run the diffusion policy, get an action, apply the edit policy to nudge it, and then choose whichever option has the highest predicted reward. This way, the reward signal only has to flow backward through the edit policy (short and stable) and the value function (also short), never through the long diffusion chain.

The on-the-fly policy and its training rule

First in words:

For each state, sample N actions from the base policy, edit each one, score all candidates with Q-function, and pick the highest. Train the edit policy using standard RL loss: penalize edit policy for actions that received low Q-scores.

Then the compact form:

L_edit = E[(Q(s, a_base) - Q(s, a_base + edit))^2], edit policy trained to maximize Q(s, a_base + delta) where delta ~ Gaussian edit policy

Every symbol:

L_editloss for training the edit policy
A tiny worked example
Base policy in state s outputs action a_base = 0.5 (on a scale of -1 to 1).
Edit policy outputs delta = 0.15 (suggested nudge).
Edited action becomes a_edit = 0.5 + 0.15 = 0.65.
Value function predicts Q(s, 0.5) = 50 (reward for base), Q(s, 0.65) = 75 (reward for edited).
The edit policy is rewarded: it found a +25 reward improvement, so it updates to favor that delta more.
Next time, edit policy has learned to nudge in this direction when base action is too conservative.

The edit policy only needs to learn small, single-step adjustments, so its gradients never vanish or explode.

What can go wrong

What can go wrong

Edit policy overshoots. If the edit policy learns adjustments that are too large, it can push base actions into bad regions. Fix: use entropy regularization (add a penalty for large, confident edits) to keep nudges small and exploratory.
Value function is wrong. If your Q-function is poorly trained, it scores actions incorrectly, and the edit policy learns from noise. Fix: use a good offline-to-online RL algorithm (like CQL or IQL) to bootstrap the value function.
Base policy forgets offline data. If the base policy drifts too far from imitation learning, it stops producing reasonable actions to edit. Fix: mix imitation loss and online loss in the base policy training.
Done right: stable improvement. When base is trained on imitation, edit is trained on a good Q-function, and edits are small, the system learns quickly and never destabilizes.
What a runnable demo should prove

What a runnable demo should prove

Build a simple continuous control task (e.g., reaching a target position or moving an object). Collect an offline dataset of 100 expert demonstrations. Split into two versions: (1) naive fine-tuning with a diffusion policy (backprop reward directly), (2) EXPO with base diffusion plus tiny Gaussian editor.

Train both for 5000 steps on 50 new online rollouts. Measure task success rate (does the agent reach the target?) and training stability (does the curve jitter or decline?).

Sample efficiency = (steps to reach 80 percent success rate on EXPO) / (steps for naive diffusion). Stability = standard deviation of success rate over rolling 500-step windows.

The demo should make it impossible to miss this: EXPO reaches the same performance 2-3x faster because gradients only flow through the short edit policy instead of the long diffusion chain, and the learning curve is smooth; naive diffusion is noisy because gradient instabilities accumulate through the long chain, crashes partway, and wastes samples.
