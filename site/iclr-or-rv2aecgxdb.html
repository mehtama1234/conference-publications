ProPerSim: Learning Proactive Personalized Recommendations via Simulated User Feedback

An assistant learns to make better recommendations by generating candidate suggestions, watching a simulated user pick the best ones, and training itself on those choices.

Paper explainersAll themesAgents & Tool Use

Most AI assistants today wait for you to ask. ProPerSim teaches an assistant to jump in proactively with timely, personalized suggestions—like knowing you need coffee before you ask. The trick: run thousands of simulated days where a user agent with specific habits and preferences goes through a routine, the assistant offers guesses at what would help, the simulated user scores each guess (revealing which suggestions actually fit each person by giving high marks to good guesses and low marks to wrong ones), and the assistant trains on those preference pairs to learn the pattern of what works and get better next time.

Zero assumption version

Why assistants are stuck in reactivity

Today's assistants sit quiet until you ask. They do not know your schedule, your preferences, or that you might need a suggestion in five minutes. A beginner's first try is simple: ask the user lots of questions upfront, lock in their preferences, then use those saved rules to suggest things. This breaks because people's needs change constantly—you want coffee at 8am but tea at 4pm. Your schedule reshuffles daily. A fixed rule learned once cannot chase those shifts.

The paper shows the real gap: proactivity (suggesting at the right time) and personalization (matching your actual taste) have been solved separately, but combining them is hard. Teaching an assistant to watch your behavior AND learn your real-time preferences AND pick the right moment to interrupt—all at once—is a new problem.

In one sentence. Train an assistant by simulating thousands of days where it offers candidate suggestions, the simulated user scores them, and the assistant learns which suggestions the user would pick.

The algorithm as a flow

What it actually does

Build a simulated user

Encode a persona as seven attributes (age, interests, schedule type, etc.); group 32 personas into seven clusters using numerical signatures.

Run a day of activity

The user agent generates a schedule of actions (morning coffee, afternoon work, evening dinner) using memory and location.

Generate and score candidates

Every 2.5 minutes, assistant offers n recommendations tailored to the user's current state and retrieved similar past moments; user scores each guess.

Store the winner

Store the context, history, chosen suggestion, and rejected ones as a preference pair for training.

Train on preferences

Use Direct Preference Optimization to update model weights so it assigns higher probability to suggestions the user picked.

What the paper changes

What changes: the model's internal recommendation ranking

The assistant does not learn a fixed list of facts. Instead, it learns to rank candidate suggestions in the right order for each person and moment. When it sees your morning context (location: bedroom, time: 7am, recent activity: sleeping), it learns to rank 'coffee' high and 'bedtime reminder' low.

the object it moves  =  the assistant's ranking of candidate suggestions
The hidden quantity

The hidden quantity: alignment score—how well recommendations match each person's true preferences

measured quantity  =  preference alignment

The paper measures something that usually stays hidden: given a context and a persona, how often does the assistant's top suggestion match what that person actually wants? This is hard to see because preferences are not written down—they live in behavior. A score of 2.2 out of 4 means the assistant is guessing poorly; 3.3 means it has learned the pattern.

The paper estimates this by running simulated days for 32 different personas. Each day the assistant makes about 576 recommendations (one every 2.5 minutes for 24 hours). The simulated user gives a score for each one. The alignment score is the average of all those ratings across all personas.

Why it works

Why it works: learning from pairwise comparisons, not scores

The core idea is simple: do not try to predict a single score for each suggestion. Instead, show the model pairs of suggestions from the same moment, tell it which one the user preferred, and let it learn the pattern. This works because users are inconsistent about absolute scores—you might rate 'coffee' as a 3 one day and a 4 another—but they are consistent about which thing beats which other thing. Coffee is better than sleep warnings at 7am because that is when the user wakes up and needs energy. Sleep warnings are better than emails at 11pm because that is when the user is winding down. Learning relative preferences is easier than learning absolute ratings because the model only needs to capture the direction of preference, not the exact number.

The second piece: the assistant keeps a memory of recent interactions (past 10 minutes in detail; older ones summarized) and retrieves similar past situations by comparing numerical signatures. This grounds its guesses in what worked before. When you are in a similar context to yesterday at this time, the assistant can say 'last time you liked X when this happened.'

The training loop is tight: generate candidates, watch the user pick, store the pair, and retrain on 200 random samples from the buffer at the end of each day. This keeps the model chasing the moving target of 'what this person wants right now' without overfitting.

Math after the picture

The training rule: push chosen suggestions ahead

First in words:

max-theta: E over personae P and contexts: (log probability of chosen suggestion minus log probability of rejected suggestion), scaled by a safety factor to prevent wild updates.

Then the compact form:

max_θ E_P,A_t [ log σ(E(P, r, A_t, A_chosen) - E(P, r, A_t, A_rejected)) ]

Every symbol:

θthe model's weights (what we are training)
E(P, r, A_t, recommendation)the user's alignment score for this recommendation, given their persona P, rubric r, and current action A_t
A_chosenthe recommendation the simulated user picked
A_rejecteda recommendation the simulated user did not pick
σ(x)sigmoid function: converts a difference into a probability between 0 and 1
log probabilityhow confident the model is in each choice; log makes the math work with multiplication
A tiny worked example
Context: It is 8am at home, user is in the kitchen.
Candidate A: 'brew espresso' — user scores it 4.0 (chosen).
Candidate B: 'send a meeting reminder' — user scores it 1.0 (rejected).
Difference E_chosen - E_rejected = 4.0 - 1.0 = 3.0 (large margin).
The model should strongly increase probability of 'brew espresso' in this context.
If the difference were small (4.0 vs 3.5), the update would be smaller—the user is ambivalent, so do not push too hard.

The model learns to rank suggestions by comparing them pairwise, not by memorizing individual scores.

What can go wrong

What can go wrong

Overfitting to one persona. If the assistant trains only on one user, it memorizes quirks instead of learning the underlying pattern. Fixed by training on 32 different personas—diversity forces the model to find real rules.
Busting the training budget. Naive direct preference optimization trains on every single preference pair, leading to instability and overfitting. Fixed by randomly sampling 200 pairs per day—you get the signal without the noise.
Breaking on a new persona. A model trained on 32 personas has seen diverse preferences, but a truly new person might have habits not in that set. The assistant will make mistakes until it has a few days of data on them.
Done right. Train on diverse personas, sample strategically from the buffer, and let the model adapt for a few days per new person before expecting high accuracy.
