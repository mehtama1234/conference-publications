Sample Complexity and Representation Ability of Test-time Scaling

At test time, correcting mistakes is cheaper than voting, and a single model can simulate learning over multiple expert strategies without knowing which task is coming.

Paper explainersAll themesLearning Theory

When a language model finishes an answer, you can ask it to double-check itself—fixing mistakes based on feedback—or you can simply try many times and pick the best one. This paper proves that correcting is fundamentally more efficient, because feedback shrinks the problem each round by steering the model's next attempt, whereas voting needs to stumble on the right answer by accident. It also proves something surprising: a single language model (a neural network architecture that reads text) can secretly run a learning algorithm that picks the right expert for each new task, all from watching which answers worked.

Zero assumption version

Two test-time strategies—which is cheaper?

When a language model answers a hard question, it often makes mistakes. You can spend more time asking the model over and over, collecting many answers, then picking the best one. Or you can ask it once, get feedback on whether the answer works, and ask it to fix itself. Both strategies use time at test time—the moment you ask the question—but no one knew which costs less.

A beginner would guess that voting (picking the best of many tries) and correcting (fixing based on feedback) are roughly equal. That guess is wrong, and the difference is dramatic: voting needs to try the right answer many more times to reliably find it, while correcting learns on the fly.

The paper's move. Prove that correcting answers costs far fewer attempts than voting; then show that a single model can run an invisible learning algorithm to pick the best strategy for each new task.

What the paper changes

What the paper changes

The paper changes how a model allocates its test-time effort: instead of running the same computation many times independently, it uses feedback from each attempt to steer the next one, turning independent tries into a learning loop.

the object it moves  =  test-time learning loop
The hidden quantity

Sample complexity—the efficiency gap

measured quantity  =  sample complexity (number of attempts needed)

Sample complexity is how many tries you need to reliably get the right answer. For voting, it measures how many times you must ask before the correct answer shows up enough to win the majority. For correcting, it measures how many correction rounds you need before feedback steers the model to the right answer.

The paper estimates this by analyzing the probability gap: if the correct answer has probability p and the second-best has probability q, then the gap (call it delta) is p minus q. For voting, the cost grows with 1 divided by delta squared—a very steep wall. For correcting, the cost grows only with 1 divided by delta—much gentler. The paper measures this gap by proving it mathematically, then showing experiments where models catch it.

Why it works

Why it works—the learning feedback loop

Voting works by drowning noise: ask enough times that the right answer appears often enough to win by sheer frequency. The problem: if right and wrong answers are close in probability, you need to ask exponentially many times. Each try is independent, so each needs to be lucky.

Correcting works by updating a mental state: after each wrong answer, the feedback narrows the model's focus—it learns which reasoning step was the mistake and steers away from it. This is cheaper because the model is not trying independently; it is learning on the fly. Each correction round bends the model's next attempt closer to the goal.

For multi-task learning without knowing the task in advance, the paper proves that a single neural network can play a hidden learning algorithm over expert pools. It stacks processing layers from multiple experts, and uses a small marker position to select which expert to use at each step. This is an online learning algorithm (a bandit, which picks the best choice by trying and watching rewards) running inside the model itself: as the model generates its answer, it learns which expert works best and routes more computation to it, based purely on rewards it observes from feedback.

Math after the picture

The sample complexity equation

First in words:

Cost for voting scales with one over gap squared; cost for correcting scales with one over gap. Gap is the probability of right answer minus probability of second-best answer.

Then the compact form:

voting_cost ~ 1 / Δ² vs. correcting_cost ~ 1 / Δ, where Δ = P(correct) - P(second_best)

Every symbol:

Δprobability gap: how much more likely the right answer is than the second-best
voting_costnumber of tries needed for voting method to reliably pick the right answer
correcting_costnumber of correction rounds needed for feedback-based method
P(correct)probability model gives the right answer on a single try
P(second_best)probability model gives the best wrong answer on a single try
A tiny worked example
Say the right answer has 60 percent chance, second-best has 50 percent. Gap = 0.60 minus 0.50 = 0.10.
Voting cost = 1 divided by (0.10 squared) = 1 divided by 0.01 = 100 tries.
Correcting cost = 1 divided by 0.10 = 10 correction rounds.
Same gap, but voting needs 10 times as many attempts. Tighter gaps make the gap worse—at 0.01 gap, voting needs 10000 tries but correcting still only needs 100.

Squared gap in voting grows much faster than linear gap in correcting, so correcting wins when you can afford to learn on the fly, because each feedback round narrows the search space instead of hoping randomness lands on the right answer.

What can go wrong

What can go wrong

Feedback must be reliable. If the verifier that judges right from wrong makes mistakes, correcting sends the model down the wrong path. Voting is not affected because it does not trust the feedback.
Gap must not collapse. If the right answer and second-best are equally likely, the gap is zero, and both methods need infinite tries. The paper assumes the gap is bounded away from zero.
Multi-task routing requires task diversity. The model learns which expert fits by watching rewards. If all tasks reward the same expert, the model never learns to distinguish them.
Marker precision matters. The mechanism relies on a marker position to route computation cleanly. If numerical precision is too loose, computation leaks to wrong experts and mixing happens.
Done right. With honest feedback, diverse tasks, and tight computation masks, correcting beats voting and one model handles multiple tasks invisibly.
What a runnable demo should prove

What a runnable demo should prove

Build a model that outputs an answer, then refines it based on feedback (e.g., by being told if the answer is right). Run it on a task where the first attempt often fails. Compare the number of tries needed for voting versus correcting to hit a target accuracy, say 95 percent correctness on a set of hard questions. Also test a multi-task version: give the model several expert strategies (or several models), hide which task is coming, and let the model learn to pick the right strategy by watching rewards from feedback. Measure whether a single model can route correctly without knowing the task type in advance.

efficiency_gain = (voting_attempts_needed) / (correcting_rounds_needed); task_identification_accuracy = (fraction of test queries routed to the correct expert strategy)

The demo must show that correcting achieves high accuracy with fewer attempts than voting, and that a single model can invisibly learn which expert fits a new task just by watching rewards.
