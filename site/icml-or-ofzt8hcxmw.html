Semantic Impact-Driven Visual Scheduling in Vision-Language Models

Keep only the visual cache entries that still change the model's next-word choice, so long visual inputs stop paying full cost at every decoding step.

Paper explainersAll themesMultimodal

A vision-language model generates text one step at a time while carrying a large visual cache from the image. That cache is expensive because every new word prediction can read from many visual entries even when most of them no longer matter. Existing pruning rules often inspect attention (the weighting rule the model uses to decide which earlier positions to read from), but attention weights are only an indirect signal. This paper asks a stricter question: which visual entries actually change the next-word distribution (the weighted probabilities over the next output words)? Its answer is a training-free method that builds a semantic lens from the current top candidate words, measures how much the visual input shifts the hidden state toward those candidate meanings, and keeps only the visual cache entries with large measured impact.

Zero assumption version

Why visual image pieces become wasteful during decoding

A vision-language model may receive hundreds or thousands of visual tokens (small learned pieces of the image representation) before it writes the answer. During decoding, every new word can still attend to that whole visual memory even after the text context has already narrowed the relevant part of the image. This creates latency because the model keeps paying for visual context that no longer changes the decision.

A common shortcut is to look at internal attention maps and keep the entries with large weights. That can fail because a large weight does not guarantee a large effect on the output. A visual feature may receive attention yet still move the hidden state in a direction that does not change which word is chosen. The real question is causal at the next prediction step: if this visual information were removed, would the next-word probabilities move enough to change the decision?

The method in one sentence. Estimate visual importance by measuring how much each visual entry changes the model's current semantic decision, then schedule only the impactful entries into the cache.

The algorithm as a flow

What it actually does

Read the current top candidate words.

At selected decoding steps, take the top-K next-word candidates because those candidates define the decision the model is about to make.

Construct a semantic basis.

Use the candidate word embeddings (the learned lists of numbers for those words) to build orthogonal semantic directions so overlapping candidate meanings are separated before scoring visual impact.

Measure visual-induced state change.

Compare hidden states with and without the visual contribution so the method isolates what the image is adding at the current step.

Project the change onto the semantic basis.

Score each visual cache entry by how strongly its state change aligns with the current candidate-word directions because alignment with those directions is what can alter the next-word probabilities.

Schedule the cache.

Keep high-impact visual entries and drop low-impact ones until the next refresh interval, which cuts decoding cost because future steps read from a smaller visual memory.

What the paper changes

What the paper changes

The paper changes the criterion for visual pruning. Instead of ranking visual memory by internal interaction signals, it ranks memory by measured effect on the current output decision.

the object it moves  =  the rule used to keep or remove visual cache entries during decoding
The hidden quantity

The hidden quantity

measured quantity  =  semantic impact of one visual cache entry on the next-word decision

The hidden quantity is not how much the model reads from a visual entry, but how much that entry pushes the hidden state toward one candidate word rather than another. Two entries can receive similar attention weights while one of them changes the relative scores of the top candidates and the other changes almost nothing important.

The semantic lens makes that quantity measurable. By building a basis from the current top candidate word embeddings, the method asks whether the visual-induced hidden-state change has components along the exact semantic directions that distinguish the candidate outputs. A large projection means the entry can change the next-word distribution. A small projection means the entry is mostly irrelevant at that step even if internal attention remains nonzero.

Why it works

Why the semantic lens gives a better pruning signal

The next-word choice is made in the space of candidate word meanings, not in the raw space of attention scores. A pruning rule should therefore ask how visual information moves the hidden state relative to those candidate meanings. The semantic lens does exactly that because it derives its basis from the current top candidates instead of from generic visual activity.

The orthogonalization step matters because top candidate words often have overlapping embeddings. Without separating those directions, one candidate can dominate the score simply because its embedding overlaps strongly with another candidate. Orthogonal directions turn the question into a cleaner measurement of how much the visual signal supports distinct alternatives.

The projection step matters because hidden-state variation can contain many components unrelated to the imminent decision. The method keeps the components that align with candidate-word directions and ignores the rest. That yields aggressive compression without a training step because the scoring rule is tied directly to the output choice the model is about to make.

Math after the picture

Score one visual entry by semantic projection magnitude

First in words:

A compact summary is to measure the hidden-state change caused by one visual entry and then add up its projection strengths on the semantic basis built from the current top candidate words.

Then the compact form:

impact(v) = sum_j | q_j^T * delta_h(v) |

Every symbol:

vone visual cache entry
delta_h(v)the hidden-state change caused by that visual entry at the current decoding step
q_jthe j-th orthogonal semantic basis vector built from top candidate word embeddings
q_j^T * delta_h(v)the signed projection of the visual-induced change onto semantic direction j
impact(v)the total semantic influence score used for scheduling
A tiny worked example
Suppose the basis has three directions tied to the current candidate words.
One visual entry changes the hidden state so its projections are 0.40, 0.05, and 0.02.
Its impact score is 0.47.
Another entry produces projections 0.03, 0.01, and 0.00, so its score is 0.04.
The first entry stays in the cache because it can still move the next-word decision, while the second entry is a strong candidate for removal.

The paper contains more implementation detail, but the main idea is this direct projection test: keep the visual entries whose state changes point along active candidate-word directions.

What can go wrong

What can go wrong

Top-K candidates can omit the later-correct word. If the current candidate set misses the word that should win after more visual evidence is considered, the semantic basis is incomplete and the method may prune a visual entry that would have mattered.
Refresh intervals can be too sparse. If the cache is not rescored often enough, the model can carry an outdated keep-or-drop decision into a later decoding step where the relevant visual evidence has changed.
Small semantic shifts can still matter near ties. When two candidate words have nearly equal probability, a visually induced hidden-state change with modest magnitude can flip the ranking. A hard threshold can then remove an entry that appears weak in absolute score but is decisive for a close competition.
Done right. The method works best when the candidate set is broad enough, the refresh schedule matches how quickly the text context changes, and the pruning threshold is checked against near-tie cases.
What a runnable demo should prove

What a runnable demo should prove

Build a decoder that answers visual questions while carrying a visual cache. At fixed intervals, compute the top candidate words, form the semantic basis from their embeddings, score each visual cache entry by its projected hidden-state change, and prune the lowest-impact entries.

The demo should log answer quality, average kept cache size, and latency. It should also include close-decision examples such as counting or reading text, because those cases show whether the projection score is really preserving the visual evidence that changes the next-word choice.

compression = 1 - kept_visual_entries / total_visual_entries

A convincing result is high compression with nearly unchanged answer quality because that means the retained visual cache still contains the entries that move the current semantic decision.
