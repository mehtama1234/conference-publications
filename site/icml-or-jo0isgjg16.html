XR-1: Unified Vision-Motion Codes for Scalable Robot Learning

Learn a shared discrete codebook that represents both what a robot sees changing and how it moves, so one foundation model can work across diverse robots and tasks.

Paper explainersAll themesRobotics & Control

Teaching a robot to act from images is hard: each video shows the world changing in some way, and the robot must turn those changes into motion commands. But videos and robot actions speak different languages — one encodes visual patterns, the other encodes body movements. XR-1 solves this by learning a unified vocabulary: a small set of discrete codes that capture both visual dynamics and robotic motion at once, allowing a single model to learn from humans, other robots, and diverse scenarios.

Zero assumption version

Why robots fail to learn from messy real data

Today's robot learning methods have a structural problem: they encode either visual patterns OR motor commands, but rarely both together. A robot sees video frames (images changing over time) and must output motor signals (angles, forces). These two modalities are naturally misaligned — one is about perception, one is about action.

A naive approach: train one model on videos and another on action sequences, then glue them together. This fails because the two models never learn that a certain visual change (say, an object sliding left) is mechanically linked to a certain action (gripper moving left). When you combine diverse robots and humans in the same dataset, this problem gets worse: the same visual change means different actions on different robots, and vice versa.

Worse: robots, humans, and internet videos all have different recording conditions, object types, and perspectives. A method that works on one robot's data often fails completely on another robot's data in the same task.

The fix in one sentence: Learn a single shared vocabulary of discrete codes that jointly captures visual motion and robot motion, so any downstream policy can speak both languages at once.

The algorithm as a flow

What it actually does

Dual-branch VQ-VAE

A vision encoder squeezes video frames into discrete codes; a motion encoder squeezes action sequences into discrete codes; both map to the same shared codebook.

Vision-motion alignment

Add a loss that pulls visual codes and action codes closer when they represent the same event, so a gripper-move-left code is similar to an object-slides-left code.

Three-stage training

Stage 1: self-supervised, learn good codes from raw robot and human videos. Stage 2: inject learned codes into a language model via learnable tokens, then finetune on large diverse datasets. Stage 3: finetune on each specific robot task.

Dataset balancing

Because robot datasets have wildly different sizes and quality, assign weights to prevent overfitting to whichever dataset has the most videos.

Policy action head

The model predicts which action code to use next; at test time, decode that code into actual motor commands (joint angles, forces, etc).

What the paper changes

The single thing the paper changes

Instead of encoding visual information and action information in separate isolated spaces, XR-1 learns a unified discrete latent space (a codebook with, say, 1000 possible discrete tokens) where each token can represent BOTH a visual dynamic (what the scene is doing) AND a motor dynamic (what the body is doing).

The hidden quantity

Vision-motion alignment: the glue holding disparate data together

measured quantity  =  Vision-motion alignment score

The paper measures how well visual codes align with action codes — that is, when you look at a frame pair (what changed in the scene) and its corresponding action, do they activate the same discrete token in the shared codebook? This alignment score is never seen by the reader normally, but it is the central quantity the learning process tries to maximize.

To compute alignment, the model extracts both a visual code (from compressing the frame pair) and a motion code (from compressing the action), then penalizes the distance between them. A small distance means the visual and action information agree on which token to use. This is learned by adding a penalty term to the loss during stage 1 that shrinks the distance whenever it gets large.

Why it works

Why unified codes work: the causal chain

The problem is that each robot has its own body morphology. A 6-DOF arm moves differently than a mobile manipulator. Yet the visual changes (object slides, gripper closes) are the same. If you train two separate models — one that reads video, one that reads actions — they will never learn that a leftward object-slide is mechanically similar to a leftward gripper command on Robot A, or a different command on Robot B.

By learning codes jointly, the model discovers this shared ground. A visual code for leftward-motion and a motor code for leftward-motion now both point to token #247. At test time, when the model sees an object moving left, it can directly predict which action code to emit, because it has already learned that visual token maps to the right motor commands for THIS robot. Since the codes were learned across many robots and humans, token #247 captures the essence of leftward-dynamics that generalizes across embodiments.

The three-stage training locks in this knowledge: Stage 1 learns the codes. Stage 2 injects these codes into a large language model via learnable tokens, because a language model can predict which action code should come next, given the sequence so far and what the robot is seeing — this lets the model plan multi-step sequences instead of just predicting one action in isolation. Stage 3 finetunes on task-specific data without forgetting the general patterns. Dataset weighting in stage 2 prevents any one robot's quirks from drowning out the others.

Math after the picture

The alignment loss equation

First in words:

total loss equals the visual reconstruction error plus the action reconstruction error plus a regularization term that pulls the visual code closer to the action code when they represent the same event

Then the compact form:

L_total = L_rec_vis + L_rec_act + lambda * sum_t ||z_vis_t - z_mot_t||^2

Every symbol:

L_rec_visvisual reconstruction loss: how well the decoder rebuilds the input frames
L_rec_actaction reconstruction loss: how well the decoder rebuilds the input actions
z_vis_tthe visual code (discrete token) at timestep t extracted by the vision encoder
z_mot_tthe motion code (discrete token) at timestep t extracted by the motion encoder
lambdathe strength of the alignment penalty; higher lambda forces codes to align more tightly
||z_vis_t - z_mot_t||^2squared distance between visual and motion codes at time t
A tiny worked example
A codebook has 256 tokens (0 to 255). At timestep t:
- Vision encoder sees gripper move left, outputs z_vis = token 47
- Motion encoder sees action leftward, outputs z_mot = token 49
- Distance: ||47 - 49||^2 = 4
- Reconstruction loss: L_rec_vis = 0.1, L_rec_act = 0.1 (good reconstruction)
- With lambda = 0.5:
- L_total = 0.1 + 0.1 + 0.5 * 4 = 0.2 + 2.0 = 2.2
Next update, the model nudges z_vis toward 48 and z_mot toward 48 to shrink that distance.
After many updates, visual and action codes for similar events converge to the same token.

The alignment loss is the key contribution: it forces two separate encoders to agree on a shared discrete vocabulary, bridging visual and motor semantics.

What can go wrong

What can go wrong

Imbalanced datasets If one robot has 10x more videos than another, the learned codes will overfit to that robot's morphology and action space. The model will fail on the smaller datasets. XR-1 mitigates this with dataset-specific sampling weights, but if the weights are set wrong or data imbalance is extreme, this problem persists.
Codebook collapse If the codebook is too small or the alignment loss is too weak, the model may end up using only a handful of tokens instead of the full vocabulary. Then all actions and all visual changes get mapped to the same few codes, destroying discrimination.
Misaligned semantics across embodiments Some robots have fundamentally different action spaces: a humanoid arm and a mobile manipulator may not have a clean shared representation of leftward-motion. XR-1 will still try to learn codes, but some codes may be noisy or context-dependent.
Good performance on unseen objects and distractors When alignment works well, the learned codes capture the essential dynamics (motion direction, speed, contact) without overfitting to specific object shapes or lighting. The paper shows strong generalization to unseen objects and background distractors.
What a runnable demo should prove

What a runnable demo should prove

Build a small experiment: train a VQ-VAE on a toy dataset (say, 100 synthetic robot trajectories from 2 simulated robots, each with 50 timesteps). For each trajectory, you have video frames and action vectors. Implement the dual-branch encoder (vision branch compresses frame deltas, action branch compresses action sequences) and the alignment loss. On one held-out test trajectory from a third robot, measure: (1) Do the visual and motion codes cluster together (low alignment distance)? (2) Can the policy predict the next action code given only the visual code? (3) Does transfer to the third robot succeed at >50% success rate while a baseline trained on only one robot gets <30%?

transfer_success = (success_rate_third_robot_with_alignment - success_rate_third_robot_baseline_no_alignment) / success_rate_third_robot_baseline_no_alignment

The demo makes impossible to miss: when visual and motion codes are aligned, a policy trained on two robots instantly works on a third, because it speaks the shared language of physical dynamics.
