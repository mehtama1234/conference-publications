TIC-VLA: Think-in-Control Vision-Language-Action Model

A robot navigation model that keeps running while its language understanding lags behind, by explicitly training on the same delays it will face in the real world.

Paper explainersAll themesRobotics & Control

When a robot listens to a voice command while moving through a crowd, the camera sees the scene right now, but the language model takes a second or two to think. Most models pretend this delay does not exist, which causes them to crash or get stuck when deployed. This paper introduces a system that trains robots to act on stale semantic understanding — understanding that lags behind the present moment — so they keep moving safely even while thinking.

Zero assumption version

The gap between thinking and moving

A robot that navigates by listening to language commands faces a hard timing problem. When the human says "go left around that person", the robot's camera captures the scene instantly, but the language model that understands the instruction takes hundreds or thousands of computer steps to finish thinking — typically a half-second to two seconds of delay.

Most existing models ignore this delay entirely, training as if understanding and action happen at the same moment. They assume the robot can think and move in lockstep. But when you deploy such a model on a real robot, the language model runs in the background, and by the time it finishes thinking, the scene has changed — the person has moved, the doorway has gone out of view. The robot tries to execute an action based on outdated information, crashes into obstacles, or freezes.

A naive solution is to make the robot wait for the language model to finish thinking before acting. But in a crowded, dynamic environment, stopping to think means missing the moment to react. People are moving, obstacles appear. The robot has to keep moving.

The core mismatch: The robot learns to move while getting instant understanding, but deploys while getting delayed understanding.

The algorithm as a flow

What it actually does

The reasoning lags

Camera grabs the scene. Language model starts processing in the background (asynchronously).

The control must not wait

Action generator keeps running on whatever understanding is available, without pausing.

Delayed understanding gets recorded

When the language model finishes, its output is tagged with how old it is (latency metadata).

Control conditions on the lag explicitly

The action generator is told: you are acting on understanding from 50 steps ago; here is that stale semantic state plus how delayed it is.

Training injects the same delays

During learning, delays are artificially injected so the model practices on stale information, because practicing on delayed data teaches it to work when deployment also gives it delayed data.

What the paper changes

What the paper changes

The paper changes the interface between the language-understanding module and the action-generation module. Instead of pretending they are synchronized, the paper explicitly passes four things to the action module: the current camera frame, the delayed semantic understanding, metadata about how old that understanding is, and the ego-motion (how far the robot has moved since the understanding was computed). The action module is trained to condition on all four.

the object it moves  =  the semantic-control interface
The hidden quantity

Latency: how old the understanding is

measured quantity  =  reasoning latency (age of semantic state)

Latency is the time delay between when the camera captured the scene and when the language model finished thinking about it. In this system, latency is typically measured in environment steps or seconds. A latency of 50 steps means the understanding you are acting on is based on the scene as it was 50 simulation steps (or about 5 seconds in wall time) ago.

The paper measures latency by tracking when the language model outputs each semantic representation and comparing it to the current timestep. This latency value is then explicitly encoded as metadata and passed to the action generator, because knowing the age allows the model to learn different strategies — for instance, when latency is large, rely more on fresh camera data and less on old semantic understanding.

Why it works

Why delayed training fixes the mismatch

The core mechanism is simple: the mismatch between training and deployment comes from a hidden variable — the age of the semantic understanding. In training, models typically use fresh semantic outputs, so age is always zero. At deployment, age is one to three seconds. To close this gap, you have to make the hidden variable visible.

TIC-VLA makes latency visible in two ways. First, during training, it deliberately injects delays — it holds back the semantic outputs for a random number of steps before passing them to the action generator, because the model cannot learn to handle what it has never seen, and holding back outputs creates training examples of delayed information. Second, it explicitly encodes the latency value as metadata (a number or a list of numbers) and passes it alongside the semantic state, because when the action generator knows how old the semantic data is, it can learn different strategies — for instance, when latency is low, trust the semantic output more; when latency is high, rely more on the current camera view and less on stale interpretations.

Why does this work? Because the action generator gets supervised examples of what to do with delayed semantics. If the human expert's action in the training data was "slow down, the person ahead is 3 meters away", and you show the model that action tagged with "your semantic understanding of that person is 2 seconds old", the model learns the association: old semantics about close obstacles still demand caution. Over many examples, it learns to extract and adapt to what is reliable in stale information (the person is still nearby) and what is unreliable (exact position has shifted). It learns a policy that works well enough on delayed information.

Math after the picture

The latency-consistent loss

First in words:

action loss = mean squared error between predicted action and expert action, with input that includes delayed semantic state s_delayed and latency metadata tau

Then the compact form:

L_action = mean( (action_predicted(s_current, s_delayed, tau, delta_ego) - action_expert)^2 )

Every symbol:

s_currentcamera observations at the current timestep
s_delayedsemantic understanding from language model, delayed by tau steps
tauthe age of s_delayed in timesteps (or seconds)
delta_egohow far the robot moved between the semantic observation and now
action_predictedthe action generated by the trained model
action_expertthe correct action from the human demonstration
L_actionthe training loss to minimize
A tiny worked example
Imagine the expert says: move forward 0.3 m/s, turn 0.05 rad/s.
At training, you feed the model: current camera image, language understanding from 50 steps ago (2 seconds old), latency_tau = 50, ego_motion = 1.0 m (robot moved 1 meter in those 2 seconds).
Model predicts: forward 0.28 m/s, turn 0.04 rad/s.
Error per action = (0.28 - 0.3)^2 + (0.04 - 0.05)^2 = 0.0004 + 0.0001 = 0.0005.
By repeating this across thousands of delayed training examples, the model learns to compensate for age and drift.

The key is that tau and delta_ego are explicit inputs to the model, so it learns to adjust behavior based on how stale and how drifted the semantic state is.

What can go wrong

What can go wrong

Latency not injected during training. If you train without delays but deploy with delays, the model has never seen stale semantics and cannot handle them. Performance collapses. The fix: always inject variable latency during training.
Latency metadata not encoded. If you pass delayed semantics but do not tell the model how old they are, it cannot learn to compensate. The fix: always include explicit latency values as inputs.
Semantic representation changes over time. If the language model's outputs drift in meaning or scale over time (e.g., confidence scores get higher or lower), old semantics become even less reliable. The model must learn the sign and magnitude of such drift. The fix: train on diverse historical delays and let the model learn drift patterns.
Done right. When latency is injected during training, explicitly encoded as metadata, and the action model sees examples across a range of delays, it learns an adaptive policy that works from near-zero delays up to multi-second delays.
What a runnable demo should prove

What a runnable demo should prove

Build a simple navigation task in a simulator. Create two versions of the same trained policy: one that receives semantics with no delay, and one that receives semantics delayed by one second (50 simulation steps). Run both on an obstacle-avoidance task where people are walking around. Measure the success rate and collision count for each.

robustness = min( success_rate_no_delay / success_rate_with_delay ) — the ratio should be close to 1.0 (robust) for TIC-VLA and much larger than 1.0 (fragile) for a standard VLA model

The core result: a model trained on realistic latency maintains its effectiveness across a range of latencies, while a model trained under idealized synchronous conditions becomes fragile when latency appears.
