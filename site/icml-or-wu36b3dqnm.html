PromptDyG: Test-Time Prompt Adaptation on Dynamic Graphs

Learn a learnable prompt at test time to adapt a frozen graph model to new patterns in changing networks without retraining.

Paper explainersAll themesGraph & Geometric Learning

A network of connections changes over time: friendships form, power grids shift, molecules reconfigure. Today's best graph models learn from the past and then lock: they predict the future without adapting. But real-world graphs drift—the patterns that worked yesterday may not work today. PromptDyG solves this by keeping the model locked but adding a small, learnable prompt that adjusts in real time as new snapshots arrive, learning the emerging patterns on the fly.

Zero assumption version

The frozen model trap

Today's graph learning models work this way: you show them many past network snapshots (a network at time 1, time 2, time 3, etc.) and they learn to spot patterns—which nodes matter, how edges evolve, what comes next. Once trained, the model is locked. Every time a new network snapshot arrives, the model just answers without learning anything new.

The trouble is real-world networks change. A social network gains new users and new posting styles. A power grid adapts to renewable energy. A protein network folds differently under stress. The old patterns the model learned are no longer fully accurate. A beginner might try retraining the model on all the new data, but that is slow, risky (you might destroy what the model already learned), and wasteful when you only have small new updates.

In one sentence. When the model is frozen and the graph changes, it stops adapting and makes wrong predictions.

The algorithm as a flow

What it actually does

Start with a trained model and a frozen backbone

You have a model that was trained to predict graph patterns; its weights are locked and will not change.

At each new time step, attach a learnable prompt

A small set of learnable parameters (the prompt) plugs into the model; it learns how the graph is drifting.

Measure how spread-out each prediction is on unlabeled new data

Look at how uncertain the model is about each feature (each dimension of the output) on the new snapshot, without needing ground-truth labels. This spread-outness (a number that rises when the model is confused and falls when it is sure) guides the next step.

Update the prompt to reduce that spread

Adjust the prompt to make the model more confident in its predictions, adapting to the new patterns.

Repeat for each new snapshot

As each new time step arrives, the prompt updates; the backbone never moves.

What the paper changes

What the paper changes

The paper introduces and tunes a prompt—a small set of adjustable numbers that sit on top of the frozen model and adapt at test time. Unlike retraining the entire model, the prompt is small, fast to update, and cannot corrupt what the backbone already learned.

the object it moves  =  prompt numbers that adjust at test time
The hidden quantity

The hidden quantity: entropy of feature predictions

measured quantity  =  feature-wise prediction entropy

The paper measures something that was hidden before: how uncertain the model is about each output feature (each dimension of its prediction) when facing a new graph snapshot, without needing true labels. When the graph pattern has drifted far from training, the model's predictions will be very uncertain (high entropy). When the prompt has adapted well, the model becomes confident again (low entropy).

The paper computes this entropy on unlabeled data—you do not need ground truth. It treats each feature independently and asks: how spread out are the model's guesses for this one dimension? If the model predicts many different values with equal probability, entropy is high; if it is sure about one value, entropy is low. The prompt learns to shrink this entropy, which pushes the model to make confident, accurate predictions.

Plain reading. Entropy measures how spread out or confused a prediction is. When you roll a fair die, you are equally uncertain about landing on any number (high entropy). When you roll a loaded die that always lands on 6, there is no uncertainty (low entropy).
Paper reading. Feature-wise entropy is the sum of single-feature entropies: each output dimension is treated as its own distribution, and the model is trained to reduce the spread (entropy) in that distribution.
Why it works

Why it works: adapting without retraining

Here is the core causal chain. When a new graph snapshot arrives, the frozen model makes predictions, but the patterns have shifted, so its output features are spread across many possible values (high entropy). The prompt takes those high-entropy predictions and learns which adjustments reduce the spread—without ever looking at true labels, just by shrinking the entropy itself. As the prompt tunes itself, the model becomes more confident, which means it has learned to recognize the new pattern. Because the backbone weights are frozen, the prompt cannot overfit to noise or corrupt old knowledge; it can only refine what the backbone already does.

Theoretically, the paper shows that when you minimize entropy on positive pairs (nodes that should be similar) and negative pairs (nodes that should be different), the prompt learns to enlarge the gap between them. A bigger gap between similar nodes and different nodes means cleaner, more accurate predictions on the new graph, because the model can now separate the things that belong together from things that do not, in the new pattern—which is exactly what you want when the graph has drifted.

The entropy minimization formula

First in words:

The prompt minimizes the average entropy across all output features on the new snapshot, where entropy of a feature is the negative sum of each possible value times its log probability.

Then the compact form:

Loss = sum_features [ -sum_values p(value) * log(p(value)) ]

Every symbol:

sum_featuresadd up across all output dimensions
p(value)the model's predicted probability of that value
log(p(value))the logarithm of that probability
-sum_valuesadd up across all possible values the feature can take
A tiny worked example
Suppose feature 1 predicts: 40% value A, 30% value B, 30% value C.
Entropy = -(0.4 * log(0.4) + 0.3 * log(0.3) + 0.3 * log(0.3)) ≈ 1.10 (high; model is uncertain).
After prompt adapts: 85% value A, 10% value B, 5% value C.
Entropy = -(0.85 * log(0.85) + 0.1 * log(0.1) + 0.05 * log(0.05)) ≈ 0.61 (low; model is confident).
By reducing entropy from 1.10 to 0.61, the prompt has made the model pick one value strongly, which usually means it learned the true pattern.

The prompt learns to reshape the prediction distribution to have one dominant value, which is what you want when the network has drifted but the new pattern is now stable.

What can go wrong

What can go wrong

Prompt size too small. If the prompt has too few parameters, it cannot capture the complexity of the drift, and entropy will not decrease enough. The model stays uncertain.
Rapid, discontinuous shifts. If the graph pattern changes drastically between snapshots, the prompt may not have time to adapt before the next update arrives. Entropy minimization assumes gradual change.
Backbone is under-trained. If the original model never learned good features in the first place, the prompt cannot fix it. The backbone is frozen, so the prompt can only refine what is already there.
Done right: small prompt, stable drift, well-trained backbone. When the model is strong, the graph changes gradually, and the prompt is sized to capture that change, entropy drops and predictions stay accurate across time.
What a runnable demo should prove

What a runnable demo should prove

Build a simple synthetic dynamic graph: start with a base network, then gradually change the edge weights and node importance over 10 time steps. Train a standard graph model on the first 3 snapshots (freeze its weights). Then run the snapshot through the frozen model without any adaptation and measure accuracy; then run it with PromptDyG (a small learnable prompt that minimizes entropy at each step) and measure accuracy again. The demo should show that frozen accuracy drops as the graph drifts, but PromptDyG accuracy stays stable.

drift_cost = frozen_accuracy_early - frozen_accuracy_late; adaptation_benefit = promptdyg_accuracy_late - frozen_accuracy_late

A frozen model cannot adapt to a changing graph, but a tiny prompt that learns by reducing uncertainty can track the drift without retraining.
