DR-SAC: Robust Actor-Critic Under Real-World Drift

Train an agent to handle the worst case among plausible alternate worlds, not just the one you observed.

Paper explainersAll themesReinforcement Learning

Real-world RL agents face a hidden danger: the environment they were trained on may not match the environment they are deployed into. The standard soft actor-critic (SAC) algorithm optimizes for the observed transition dynamics (the most likely path from state to next state given an action). But if the real environment has drifted even slightly—roads are icier, wind patterns shifted, sensors measure differently—the policy fails. DR-SAC adds a guard rail: it trains to survive not just the observed world, but the worst plausible alternate world, bounded by how different that world can be from what the data showed.

Zero assumption version

Standard RL trusts the observed world too much

A robot learns to pick objects by practicing on a table covered in blue tape. It learns to move the arm a certain way, trust the gripper at a certain angle, move at a certain speed. The learned policy is perfect for that exact table.

Then the table is repainted orange, the gripper has a tiny bit of wear, the lighting changed. The policy breaks. It was trained to handle one fixed world. A naive agent would say: add more training data, practice on more tables. But you cannot collect data on every table variation that might exist. Some drift is invisible until deployment.

The core move: Instead of assuming the environment is exactly what the data showed, train the policy to survive the worst reasonable alternate environment—any world within a small distance from the observed one.

The algorithm as a flow

What it actually does

Estimate what the world looks like

Use a variational autoencoder (a model that learns to reconstruct and generate data) on offline collected data to learn the transition model—given state and action, what is the next state?

Define the uncertainty set

A KL-divergence constraint keeps alternate worlds within a ball around the observed transitions—not too far from the data.

Find the worst case inside that ball

For each state and action, compute which transition model inside the uncertainty set would give the lowest expected reward—the most adversarial one.

Train the actor and critic on worst case

Use soft actor-critic to learn a policy that maximizes reward in the worst-case world, adding a bonus for actions that explore (entropy bonus) to keep the policy from getting too narrow.

Evaluate under real perturbations

Test the learned policy on environments with actual drift (different transition dynamics) to see if the policy still works.

What the paper changes

What the paper changes

Standard soft actor-critic (SAC) computes the expected future reward under the observed transition model. DR-SAC replaces that with the worst-case expected reward under any transition model that is KL-divergence close to the observed one. The object being changed is the training objective: instead of rewarding the agent for success in one world, reward it for success in the worst plausible world.

the object it moves  =  Training objective
The hidden quantity

The uncertainty set size

measured quantity  =  KL-divergence radius of alternate worlds

The hidden quantity is how far you allow the alternate world to drift from the observed one, measured by KL divergence. This radius is critical because if it is too small, the worst case inside it is not worse than the real-world drift you will encounter—so the agent gains no safety buffer. If it is too large, the agent wastes its learning capacity training for impossible scenarios instead of plausible ones.

The paper controls this with a KL-divergence constraint (a measure of how different one pattern of outcomes is from another pattern). For each state-action pair, the agent explores transitions within a KL-divergence ball of the learned nominal model. The paper estimates this via a generative model (VAE) trained on offline data, and constrains how far the adversarial transitions can deviate using KL divergence—a distance metric that says how far one pattern differs from another.

Why it works

Why training for worst case makes the agent survive environmental drift

If you train an agent on the worst outcome in a bounded set, it will also handle all better outcomes in that set, because any easier scenario will reward the same actions or similar ones. A strategy that works when you have the least information (full darkness) still works when you have more information (medium or bright light)—just as an uphill running technique carries over to flat ground.

The paper exploits structure from the offline data to make this work: a learned VAE captures the nominal (most likely) transition model, so the algorithm can identify which alternate worlds are plausible and which are impossible. By constraining alternate worlds to a KL-divergence ball around the nominal model, the algorithm concentrates on transitions similar to what the data showed—anything too far is ruled out as implausible. Within that ball, the algorithm computes the worst case (the minimum expected value). Soft actor-critic then trains the policy to maximize reward under this worst-case world, plus a bonus for exploratory actions. The exploration bonus prevents the policy from collapsing to a single brittle solution and keeps it general enough to survive many variants.

Math after the picture

The worst-case soft policy iteration

First in words:

max over policy of: expected immediate reward plus entropy bonus, minus the value of the next state, all computed in the worst-case transition model within the uncertainty set

Then the compact form:

max_π E_s [ r(s,a) + α*log(π(a|s)) - Q(s,a)_worst ], where Q_worst = min_{p in U} E[V(s') | p(s'|s,a)]

Every symbol:

π(a|s)the policy: probability of action a given state s
r(s,a)the immediate reward for taking action a in state s
αthe entropy weight: how much to bonus exploratory actions
V(s')the value (long-term expected reward) of the next state
Q_worstthe worst-case expected value: minimum over all transitions in the uncertainty set U
Uthe uncertainty set: all transition distributions within KL distance from the learned nominal model
A tiny worked example
Suppose a robot in state s can go left (high reward in observed world) or explore randomly (lower immediate reward).
Observed next-state value: V_obs = 8.0 (good outcome).
Worst-case value within uncertainty set: V_worst = 4.0 (adversary makes transition give a worse outcome).
Entropy bonus for exploratory action: log(0.5) = -0.7, weighted by α=0.1 gives 0.1*(-0.7) = -0.07.
Q-value from action left in observed world: r=10 + 0.1*(-0.7) - 8.0 = 1.3.
Q-value from left action in worst case: r=10 + 0.1*(-0.7) - 4.0 = 5.3.
Policy trained on worst case must get 5.3 from exploratory left, so it must learn a more careful strategy that does not trust the observed world alone.

The worst-case value (minimum over uncertain transitions) is always lower than the observed value, so the policy trained on worst case becomes conservative in a principled way.

What can go wrong

What can go wrong

Uncertainty set too small. If the KL-divergence radius is too tight, the agent trains as if there is no drift. Real drift exceeds the allowed region and the agent fails.
Uncertainty set too large. If the radius is too loose, the agent trains for adversarial transitions that never actually occur. It wastes capacity defending against implausible worlds and becomes suboptimal on any realistic scenario.
VAE learns nominal model poorly. If the learned transition model does not match the actual observed data, the uncertainty set is centered on the wrong place. Safety relative to a bad nominal model is not safety relative to the real world.
Done right. Tune the KL radius using held-out data or domain knowledge to match realistic drift levels. Validate the VAE against held-out trajectories. Test the final policy on multiple realistic perturbations before deployment.
What a runnable demo should prove

What a runnable demo should prove

Collect offline data from one environment (e.g., a half-cheetah locomotion task with standard dynamics). Train DR-SAC and standard SAC on the same data. Then test both policies on a perturbed environment: scale gravity by 0.8x, add random noise to actions, or flip friction coefficients. Measure how much each policy's reward drops compared to its performance on the nominal environment.

Robustness ratio = (reward_under_perturbation) / (reward_nominal), averaged over multiple perturbations. Higher is better.

DR-SAC should maintain a stable ratio across perturbations (close to 1.0), while standard SAC drops to 0.4–0.6 as environments drift.
