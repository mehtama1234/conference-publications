Uncertainty-driven Embedding Convolution

Weight ensemble embeddings by how confident each model is on each question, instead of trusting all models equally.

Paper explainersAll themesRepresentation & Self-Supervised Learning

When you ask multiple people the same question, some know better than others because they studied that topic harder or have more experience. Text embedding models (learned patterns that turn words into lists of numbers) vary too—each learns different strengths from its training data. Existing methods that combine embeddings treat all models equally, but this paper weights each model by how sure it is about THIS particular question—models that are confident get much higher weights in the blend. Because confident models get higher weights, the combined embedding is pulled strongly toward their answer and barely nudged by uncertain ones, so the ensemble ends up closer to the informed models and away from random noise.

Zero assumption version

The ensemble averaging trap

Text embedding models take words and turn them into lists of numbers (a process called embedding). Many different embedding models exist—they use different architectures or learned from different data—and each is best at different tasks. A natural idea: if you have multiple models, ask all of them and average the results.

But averaging assumes all models are equally good at the current task, which they are not. When searching a database for an answer to a question, one model might rank the wrong document highly because it is uncertain, while another model is confident (and right). Averaging drowns out the confident model with the uncertain one. The system never learns which model to trust on which queries.

The problem in one sentence. Combining embeddings from multiple models works poorly because the method does not know which model is more certain about each specific question.

The algorithm as a flow

What it actually does

Convert to probability

Take each pre-trained embedding model and attach an uncertainty estimate to each embedding without retraining it.

Measure confidence

For a given query, calculate how confident each model is about its answer using its uncertainty numbers.

Compute adaptive weights

Assign each model a weight for THIS query: high weight if confident, low weight if uncertain.

Blend embeddings

Combine the embeddings using the per-query weights, creating one final answer that respects confidence.

Rank and retrieve

Use the blended embedding to search the database. Confident models now pull the ranking toward the right answer.

What the paper changes

What the paper changes

The paper changes the ensemble weights (the numbers that say how much each model contributes). Instead of fixed weights (e.g., 1/3 for each of three models), it computes adaptive weights that vary per query, based on how uncertain each model is.

the object it moves  =  ensemble weights
The hidden quantity

Query-specific embedding uncertainty

measured quantity  =  how sure each model is about this query

Uncertainty quantifies how much a model knows it might be wrong. For embeddings, the paper estimates it using Laplace approximation—a mathematical technique that looks at the final layer of the pre-trained model and measures how confident the training data suggest it should be. Think of it as: if the model learned strong patterns during training, small changes to its final weights cause only small changes to its outputs (low uncertainty). If the training was weak, small changes cause big differences in outputs (high uncertainty).

The paper computes this uncertainty once per embedding model using a small labeled validation set, then reuses it. At query time, for each query and each model, it estimates how sure that model is about THIS embedding based on how sure the model was in general.

Plain reading. Uncertainty for a model is how much it changes its answer if you slightly tweak its internal numbers. A confident model barely changes; an uncertain model shifts a lot.
Paper reading. Laplace approximation on the final layer estimates the Hessian (a matrix of second derivatives) at the best-fit weights, approximating the range of plausible weight values as a bell curve (Gaussian).
Why it works

Why adaptive weights fix the problem

When a model is certain (low uncertainty), its embedding is stable and trustworthy—small noise in the data does not flip its ranking. When a model is uncertain, it is fragile—small noise can change everything. By weighting certain models more heavily, the ensemble pulls the final answer toward the stable models and away from the noisy ones.

Quantitatively, the paper defines a surrogate loss (a training objective) that says: weight each model by how well it aligns positive pairs (pairs that should be similar) using squared distance. The higher the weight on a model, the more it will try to keep positive pairs close. By deriving weights from this principled objective, the method is not just a heuristic—it is mathematically justified as minimizing the expected misalignment.

Math after the picture

Weighting by uncertainty

First in words:

weight-for-model-k = one-over-uncertainty-of-model-k; then blend = sum-over-k of (weight-for-model-k times embedding-from-model-k) divided by sum of all weights

Then the compact form:

pi_k(x) = 1 / sigma_k(x); blended_z(x) = sum_k(pi_k(x) * z_k(x)) / sum_k(pi_k(x))

Every symbol:

pi_k(x)the weight (importance) assigned to model k for query x
sigma_k(x)the uncertainty of model k for query x (higher = less confident)
z_k(x)the embedding (list of numbers) output by model k for query x
blended_z(x)the final combined embedding that will be used for retrieval
A tiny worked example
Suppose three models answer a query. Model A: uncertainty 0.1; Model B: uncertainty 0.5; Model C: uncertainty 1.0.
Weights: pi_A = 1/0.1 = 10; pi_B = 1/0.5 = 2; pi_C = 1/1.0 = 1.
Total weight sum = 10 + 2 + 1 = 13.
Normalize: Model A gets 10/13 ≈ 77% of the final embedding; Model B gets 2/13 ≈ 15%; Model C gets 1/13 ≈ 8%.
The most confident model (A) dominates the blend, while uncertain models (C) barely influence the result.

The math says: give each model a weight equal to the inverse of its uncertainty, then average the embeddings using those weights. Confident models (small uncertainty) get large weights and pull the result toward them.

What can go wrong

What can go wrong

Uncertainty estimation is wrong. If the Laplace approximation underestimates uncertainty for a fragile model, that model will get too much weight and will drag down accuracy. The method relies on the uncertainty estimates being calibrated (accurate reflections of true confidence).
All models learned the same mistakes. If the embedding models are trained on overlapping data or share architecture, they all embed certain concepts the same way—including wrong ways. Uncertainty weighting cannot help because all models are equally confident about the same mistakes, so they all pull the blend in the same bad direction. UEC only works when models disagree due to honest differences in training, not because they share failures.
Rare query uncertainty is hard to estimate. For a query unlike anything in the training set, the Laplace approximation may not capture true uncertainty. The weights might be misleading, and the blended embedding might still rank poorly.
Done right: ensemble diversity + calibrated uncertainty. If the models are trained independently and the uncertainty estimates are well-calibrated (accurate reflections of true confidence), UEC assigns high weight to the models that are actually more confident and correct on each query. Because confident predictions now pull harder and uncertain ones barely influence the blend, accuracy across all query types is higher than any single model or equal averaging could achieve.
What a runnable demo should prove

What a runnable demo should prove

Build a retrieval system on a standard benchmark (e.g., searching through articles to answer questions). Use three or more embedding models with different architectures or training. For each query, compute the uncertainty-weighted blend (using the Laplace-approximated uncertainties) and compare its ranking to: (a) equal-weight averaging, and (b) the best single model. Measure precision and recall (how many of the right answers end up in the top 10).

Recall@10 = (count of correct answers in top 10 for uncertainty-weighted) minus (count for equal-weight average)

The demo proves impossible to miss: UEC's per-query weighting retrieves correct answers that equal-weight averaging misses, especially on ambiguous queries where different models are confident about different things.
