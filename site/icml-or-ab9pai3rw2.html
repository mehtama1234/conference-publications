Causal-aware Anomaly Detection for Tabular Data

Detect tabular anomalies by learning what normal causal mechanisms look like, then scoring each sample by how far it departs from those mechanism-consistent features.

Paper explainersAll themesOther

Many anomaly detectors treat an anomaly as a point that sits far from the bulk of the data in raw feature space. That works when abnormality means an extreme value. It fails when the values themselves look ordinary but their causal relationship is wrong. For example, a medical record may contain individually plausible measurements whose combination violates how those measurements usually influence each other. CausalAno is built for that case. It trains a causal generative adversarial model on normal data, uses the discriminator to extract features that reflect mechanism-consistent structure, and scores test points by how far they lie from the normal feature cloud. The detector therefore focuses on broken data-generating relationships rather than only on raw outlying values.

Why outlier-based tabular detection misses mechanism violations

Tabular anomaly detection is often framed as distance from normal rows. But in many real datasets, an anomalous sample is not extreme in any one column. It is anomalous because the columns do not fit together the way normal data-generating mechanisms would produce them.

A detector that ignores causal dependence may call a true mechanism violation normal because all values lie inside familiar marginal ranges. It may also flag a harmless extreme point as anomalous even when the point follows the correct causal process. The paper targets this mismatch by learning a representation where normal causal mechanisms shape the layout of the feature space.

The main change. Learn a representation from a causal generative model trained on normal data, then score deviations in that representation because mechanism violations can look ordinary in raw value space.

What the paper changes

What the paper changes

The paper changes the definition of normality from raw proximity among rows to consistency with a learned causal generation process. The detector therefore measures whether a row fits the normal mechanism, not only whether its coordinates are individually common.

The hidden quantity

The hidden quantity

measured quantity  =  mechanism consistency in feature space

The useful hidden quantity is how well a row matches the internal causal rules that generate normal data. That quantity may be high even when one value is unusual, and low even when every value looks ordinary on its own.

The causal GAN's discriminator learns features that respond to those rules because it must tell apart genuine normal rows from generated rows that fail to reproduce normal dependence patterns. Scoring in that feature space therefore exposes violations that raw-space distances can miss.

Why it works

Why causal feature learning helps

A plain GAN discriminator can learn useful features for anomaly detection, but it has no reason to organize those features around causal structure. CausalAno adds causal factorization so the generator and discriminator respect directed dependencies among variables. That changes what the discriminator must detect: not only whether a sample looks realistic overall, but whether the variables fit together in a causally plausible way.

Once trained on normal data, the discriminator's internal features become a compact summary of mechanism consistency. Fitting a Gaussian model to those normal features then gives a simple scoring rule. Mahalanobis distance is effective here because it accounts for the scale and correlation of each learned feature dimension, so the score responds to unusual combinations of features rather than only to large coordinate values.

The result is a detector that can identify rows with ordinary marginals but broken dependence structure. The paper's ablations argue that this gain comes specifically from the causal factorization, not merely from using a GAN backbone.

The anomaly score

First in words:

Score a test row by its Mahalanobis distance from the Gaussian fit to normal learned features.

Then the compact form:

score(x) = (f(x) - mu)^T Sigma^(-1) (f(x) - mu)

Every symbol:

xa test row
f(x)the discriminator feature vector for row x
muthe mean of normal feature vectors
Sigmathe covariance of normal feature vectors
score(x)the anomaly score; larger values indicate stronger departure from normal mechanisms
A tiny worked example
Suppose a normal feature cloud has mean mu near the origin and small spread along one mechanism-sensitive direction.
A test row has ordinary raw values, but its discriminator features move strongly along that sensitive direction because two columns do not fit their normal causal relation.
Mahalanobis distance becomes large because Sigma assigns little normal variation to that direction.
The row is flagged even though a plain straight-line distance on the original columns might stay small.

The scoring rule is simple, but its value depends on the causal feature map learned by the discriminator.

What can go wrong

What can go wrong

The assumed causal structure can be wrong. If the factorization used by the causal GAN does not match the true data-generating relations, the learned features may encode the wrong mechanism and distort anomaly scores.
Normal-only training can be narrow. If the normal dataset covers only a limited slice of benign behavior, the detector may flag valid but uncommon normal rows because the learned mechanism is too restrictive.
Feature Gaussianity is an approximation. Mahalanobis scoring assumes the normal feature cloud is summarized well by mean and covariance, which may be too simple when the learned feature cloud has several separate clusters.
Done right. The method works best when the causal factorization is plausible and the normal dataset is broad enough because then feature-space distance reflects true mechanism violations rather than missing coverage.
What a runnable demo should prove

What a runnable demo should prove

Create a synthetic tabular dataset where variables follow a known causal graph, then generate anomalies by breaking selected parent-child relations while keeping individual column values inside normal ranges. Train a standard outlier detector and the causal-aware detector on normal rows only.

Measure detection rate on mechanism-violating rows and false alarms on ordinary but extreme rows. The demo should show that the causal-aware method wins because its feature space captures whether the row follows the normal generating process, not just whether one value is large.

mechanism_detection_rate = count(correctly_flagged_mechanism_violations) / count(all_mechanism_violations)

If mechanism_detection_rate rises without a matching surge in false alarms, the detector is using causal structure in the intended way.
