MIRACLE: Intelligent Cut Selection for Mixed-Integer Programming

Use a learned decision-maker to choose which mathematical constraints to keep in a solver, cutting 98% of wasted memory without slowing it down.

Paper explainersAll themesReinforcement Learning

Solvers for Mixed-Integer Programming (a mathematical optimization technique) rely on a method called cutting planes: they start with a simple mathematical estimate, then add thousands of new constraint formulas to tighten that estimate toward the true answer. But keeping all those constraints consumes gigabytes of memory without much benefit, because most constraints barely tighten the estimate—they are busy-work that the solver stores but does not really use. MIRACLE uses reinforcement learning (learning from rewards) to train an agent that imitates expert decisions about which constraints are worth keeping. This lets solvers save memory—dropping it from 3 GB to 46 MB—while staying just as fast, because the constraints that stay are the ones that actually do the work.

The memory trap in optimization solvers

A Mixed-Integer Programming solver is a piece of software that finds the best answer to a complex optimization problem—like how to route a delivery truck to minimize cost, or how to assign workers to jobs. At its core, it uses a mathematical trick: it replaces the hard problem with an easier one (a linear relaxation), solves that, then adds more constraint formulas to make the easy version closer to the hard one. Each new constraint is called a cutting plane.

The problem: the solver generates thousands of these cutting planes in a single solve. Each one is a formula with dozens or hundreds of terms. Storing all of them uses gigabytes of memory, but most barely help, because only a few constraints actually move the answer closer to optimal—the rest are noise that the solver spends time storing and checking but rarely uses. A typical solve wastes 99% of memory on constraints that barely nudge the final answer. Meanwhile, human experts (programmers who study solvers) have learned to pick only the best constraints by hand, but that knowledge is locked inside their head—it cannot scale to millions of optimization problems.

The problem in one sentence. Solvers create thousands of constraints but most waste memory without helping the solve.

What the paper changes

The one thing that changes: which constraints to keep

Every optimization solver follows a recipe: create constraints, store them, use them. MIRACLE changes only the first step—the decision of which constraints to store. Instead of keeping all constraints (or using hand-coded rules), it uses a learned agent to pick the best ones. The solver itself is unchanged.

The hidden quantity

The hidden quantity: cut importance

measured quantity  =  importance of each constraint

The solver generates cutting planes continuously. Some constraints move the solution closer to the true answer; others barely budge it. MIRACLE measures an invisible property: for each constraint, how much does this one actually help? The paper calls this the cut importance—a number that says whether a constraint is worth keeping, because a constraint that shrinks the gap between an estimate and the true answer is useful, while one that barely changes anything wastes storage.

The paper learns this importance by watching the expert solver: which constraints did the expert keep? When the solver picks a constraint, that constraint is important. When the solver skips it, it is not. The agent learns this pattern and predicts importance for new constraints, so it can filter without the expert.

Why it works

Why it works: learning what the expert knows

Humans (experts in solver design) have intuition about which constraints help, because they have seen thousands of solves and learned which patterns precede a useful constraint. They know that a constraint is useful if it shrinks the gap between the easy estimate and the hard answer. But extracting that intuition into a hand-coded rule is hard—the pattern is too complex, with too many subtle signals to write down explicitly.

MIRACLE teaches a machine to copy that intuition. The method trains an agent using Proximal Policy Optimization (a technique where the agent learns by trying actions and getting rewards). The reward signal is simple: at each step, the agent sees a new constraint and decides to keep it or drop it. If it kept a constraint that the expert also kept, reward. If it dropped one that the expert dropped, reward. Over thousands of training problems, the agent learns the expert's decision pattern.

Then, on a new problem the agent has never seen, it can pick constraints with similar accuracy. The trick is curriculum learning: the agent starts on easy problems, then slowly moves to harder ones. This keeps the agent from getting overwhelmed early and gives it a chance to learn gradually.

Finally, the agent adapts in real time. If the solver is running out of memory, the agent sets a stricter budget (keeps fewer constraints). If the solver is fast, it loosens the budget. This dynamic adjustment means MIRACLE works on computers with different memory limits.

How the agent decides

First in words:

policy = learned decision rule that maps (current state) to (probability of keeping a constraint). The agent learns to maximize the sum of rewards, where reward = 1 if its choice matched the expert's choice, and 0 otherwise.

Then the compact form:

maximize_policy sum_t reward(action_t, expert_action_t) where reward = 1 if agent choice == expert choice else 0

Every symbol:

policythe learned decision rule (a neural network)
action_twhether to keep or drop constraint t
expert_action_twhat the expert solver chose for constraint t
reward1 if the agent matched the expert, 0 if it did not
sum_tadd up rewards over all constraints in the problem
A tiny worked example
Suppose the agent sees constraints C1, C2, C3, C4, C5.
Expert kept: [C1, C3, C4]. Expert skipped: [C2, C5].
Agent predicts: keep C1 (reward +1), drop C2 (reward +1), keep C3 (reward +1), keep C4 (reward +1), drop C5 (reward +1).
Total reward for this problem: 5/5 = perfect. Agent is learning.

The agent's goal is simple: predict the expert's choices so well that it can pick constraints without watching the expert anymore.

What can go wrong

What can go wrong

Agent sees a constraint type it never saw in training. If the training problems were all from the same class (e.g. only routing), the agent may fail on a different class (e.g. scheduling). The learned pattern does not transfer.
Memory budget set too aggressively. If the agent drops too many constraints to fit a strict memory limit, the solver may not find the true answer or may run forever.
Expert solver is mediocre. The agent learns by imitating. If the expert solver uses weak cut selection, the agent will too.
Designed right. Train on diverse problem types, set the memory budget based on the machine's actual capacity, and validate the agent on held-out test problems it has never seen before.

What a runnable demo should prove

Write a small program that loads a trained MIRACLE agent, feeds it a new optimization problem (e.g. a vehicle routing instance or a scheduling task), and shows two outputs side by side: (1) the memory and time used by the default solver, and (2) the memory and time used by the same solver with MIRACLE filtering the constraints. The demo should make it impossible to miss that MIRACLE cuts 90% of memory while keeping solve time roughly flat. A simple bar chart comparing memory before and after is perfect.

memory_reduction = (memory_without_MIRACLE - memory_with_MIRACLE) / memory_without_MIRACLE * 100%
