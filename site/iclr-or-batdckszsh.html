Boosted Trees on a Diet: Compact Models for Resource-Constrained Devices

This paper compresses boosted decision-tree ensembles by training them to reuse features and split thresholds, then storing them in a memory layout designed for small devices.

Paper explainersAll themesOther

Boosted tree ensembles are widely used because they train quickly, handle tabular data well, and often outperform heavier neural models on structured tasks. Their problem on edge devices is storage. A large ensemble contains many trees, and each internal node stores a feature index, a threshold, and child links. When hundreds or thousands of such nodes accumulate, the model can exceed the memory budget of a small sensor or battery-powered controller. This paper attacks that problem directly. It changes training so trees preferentially reuse the same features and thresholds, and it changes deployment so the resulting repeated patterns are stored more compactly. The main point is that compression is not treated as an afterthought. The training process is shaped to produce a model that is easier to encode efficiently from the start.

Zero assumption version

Boosted trees fit tabular tasks well but waste memory on small devices

A boosted tree model is an additive collection of many decision trees. Each tree contains repeated bookkeeping: feature identifiers, threshold values, branch pointers, and leaf outputs. On a server that overhead is manageable. On an embedded device with a strict memory budget, it is often the dominant constraint.

Standard libraries such as LightGBM mainly optimize predictive performance and training speed. They do not strongly encourage one tree to reuse the same split values that another tree already used. As a result, the final ensemble may contain many near-duplicate choices represented as separate stored values. Even if prediction accuracy is excellent, the model may be too large to deploy where memory, energy, and communication are limited.

The paper's move. Reward the ensemble for reusing a small vocabulary of features and thresholds during training, then store the resulting trees with a memory layout that exploits that reuse.

The algorithm as a flow

What it actually does

Train a boosted tree ensemble with compactness incentives.

Modify the learner so split decisions are rewarded when they reuse features and thresholds that already appear elsewhere in the ensemble.

Reduce the diversity of stored split definitions.

A smaller set of distinct features and thresholds means the ensemble needs fewer unique values in memory.

Encode split metadata through shared tables.

Instead of storing every threshold and feature identifier redundantly, use an alternative layout that references shared entries.

Deploy the compact layout on-device.

The compressed ensemble can execute locally with lower memory and energy demand.

Measure compression without losing predictive quality.

The main goal is to match the original task performance while shrinking the model by several times.

What the paper changes

The hidden quantity

The hidden quantity

measured quantity  =  redundancy in split definitions across the ensemble

The hidden quantity is how much repeated structure exists inside the forest. Two boosted models can have the same accuracy and number of nodes but very different compressibility depending on whether they reuse the same features and thresholds.

This matters because memory cost is driven less by the tree count alone than by the number of unique split definitions that must be stored. If many nodes can reference the same feature index and threshold entry, the storage shrinks sharply. The paper therefore rewards reuse during training instead of waiting until after training to search for compression opportunities.

Why it works

Why reuse-aware training improves compression

A boosted tree learner chooses splits greedily because boosting normally selects each new split for its immediate reduction in training loss. If many candidate splits have very similar predictive value, a standard learner may pick slightly different thresholds in different trees with no regard for storage cost. That creates a large catalog of unique split values. The paper introduces a compactness preference so the learner favors reuse when the predictive trade-off is small.

That training bias creates structure the encoder can exploit later. Once many nodes refer to a shared set of features and thresholds, the memory layout can store those values once and let each node reference them indirectly. The ensemble still performs the same branching logic at prediction time, but it needs fewer bytes to describe that logic.

The method therefore works because it coordinates model formation and model encoding. If compression were applied only after training, the ensemble might already contain too many unique thresholds to compress cleanly without accuracy loss. By shaping the search during training, the paper avoids that problem.

Math after the picture

Trade accuracy against split reuse

First in words:

The training objective combines predictive loss with a compactness term that penalizes introducing new feature-threshold definitions. The storage cost then depends on how many unique split entries remain after training.

Then the compact form:

L_total = L_boost + lambda_r * new_split_cost

Every symbol:

L_boostthe ordinary boosting objective that fits the training targets
new_split_costthe penalty for creating additional unique feature or threshold entries instead of reusing existing ones
lambda_rthe weight that controls how strongly compactness influences split choice
unique split entrya distinct feature-threshold definition that requires separate storage in the deployed model
A tiny worked example
Suppose one candidate split uses feature 5 at threshold 12.0 and reduces training loss by 0.010.
A second candidate uses feature 5 at threshold 12.1 and reduces training loss by 0.011.
Without a reuse penalty, the learner picks 12.1 because it gives the slightly larger loss reduction.
With reuse-aware training, the extra 0.001 gain may be smaller than the cost of adding a new threshold entry, so the learner keeps 12.0 and reuses existing storage.
Repeated across many nodes, those decisions reduce the number of unique stored thresholds substantially while leaving overall predictive quality nearly unchanged.

The exact scoring rule may differ across the paper's implementation, but the central principle is that a split is judged by both prediction value and storage consequences.

What can go wrong

What can go wrong

Over-penalizing new split choices can hurt accuracy. If the compactness reward is too strong, the learner may overuse a small set of thresholds even when the data genuinely needs more precise splits.
Some datasets need diverse thresholds. Highly heterogeneous tabular data may not contain enough reusable split structure to deliver large compression without some predictive loss.
The custom layout adds implementation constraints. A specialized memory format can complicate interoperability with standard tree libraries and may require custom prediction code on the target device.
Done right. Tune the reuse incentive against a real device memory budget and confirm that the deployment runtime can execute the shared-table representation efficiently.
What a runnable demo should prove

What a runnable demo should prove

Train a boosted tree model on a tabular benchmark under two conditions: a standard implementation and a reuse-aware version that rewards recurring feature-threshold splits. Export both models and measure their exact byte size under the deployed memory layout.

The demo should also count how many unique features and thresholds are stored in each model. A convincing result shows that the compact method reaches similar validation accuracy while using far fewer unique split entries and much less memory.

compression_ratio = bytes_standard / bytes_compact

The important result is that compact deployment comes from shaping the ensemble during training, not only from encoding tricks applied after the fact.
