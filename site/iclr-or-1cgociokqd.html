Flock: A Knowledge Graph Foundation Model via Learning on Random Walks

Flock breaks symmetries in knowledge graphs by adding structured randomness while keeping equivariance in distribution, so it can tell apart relations that look the same but mean different things.

Paper explainersAll themesGraph & Geometric Learning

Knowledge graphs are databases of facts (like 'Einstein authored relativity') stored as edges between entities. When a model learns from one graph, it should work on new graphs with the same structure. The problem: enforcing perfect symmetry (equivariance) makes the model blind to relations that look structurally similar but are semantically distinct. Flock adds controlled randomness to break ties while preserving equivariance in the aggregate, making it the first universal approximator for this task.

Zero assumption version

Why current models get stuck

A knowledge graph is just a list of triples: 'Einstein, authored, relativity'. When you have a model trained on one graph, you want it to work on a new graph with unknown entities and new relations. The trick is to teach it the structural patterns so it can generalize.

Current methods enforce equivariance — a fancy word for: if you swap two entities that have the same role, the model's answer swaps the same way. This helps generalization because it teaches the model to rely on structure rather than memorizing specific entities. But it has a fatal flaw: if two relations look the same structurally (same pattern of who connects to whom), the model treats them as identical even if they mean completely different things. A classic example: 'authored' and 'co-authored' might have the same structure but very different meanings. The model cannot tell them apart.

In one sentence. Flock adds random noise to break symmetries at inference time, while the aggregated predictions (averaged over many samples) preserve the symmetric property, so the model learns to distinguish relations that look identical but mean different things because the randomness forces it to notice subtle structural differences.

The algorithm as a flow

What it actually does

Sample random walks

For each entity, take a random path through the graph edges.

Encode walks as sequences

Turn the path into a list of entity names, one after another.

Embed with a sequence model

Pass the sequence through a transformer (a sequence-reading model).

Pool predictions

Combine predictions from many random walks via learned weights.

Predict unseen facts

Use aggregated representation to guess missing entity-relation pairs.

What the paper changes

The move: add randomness to the sampling, not the learning

Flock does not add randomness to the model weights or the loss function. Instead, it adds randomness to the input: each time the model sees an entity, it samples a different random walk (a different path through the graph neighbors). This structured randomness at inference time breaks symmetries — two structurally identical relations get represented differently because they are sampled differently — while the aggregated answer (the average over all samples) stays deterministic and equivariant: swapping interchangeable entities produces the same average answer.

the object it moves  =  random walk sampling strategy
The hidden quantity

The hidden quantity: distributional equivariance

measured quantity  =  Aggregate symmetry across samples

Distributional equivariance means: if you swap two interchangeable entities in the input graph, the distribution over the model's outputs stays the same, but individual samples can differ. It is like saying: if you shuffle a deck and draw one card, you might get a different card, but the average value of the card over many shuffles stays the same.

Flock measures this by enforcing that the pooled (aggregated) representation respects symmetry, even though each individual random walk breaks it. The paper proves Flock is a universal approximator — meaning it can learn any function that respects this distributional symmetry.

Why it works

Why adding randomness at inference preserves learning

Randomness in the input (which walk you sample) does not touch the learning rule. The learning rule aggregates (pools) predictions from many walks using learned weights, and the aggregation respects symmetry. This means the model learns a single, symmetric function of the graph structure, but the intermediate steps (each walk) are noisy and can be different.

Why does this break semantic symmetries? When two relations are structurally identical but the walks happen to reach different neighbors first, the sequence model sees different input sequences. The learned weights during pooling can then learn to weight one walk higher when the relation is 'authored' and another walk higher when it is 'co-authored', because the pooling weights are relation-specific. The randomness forces the model to use the subtle structural differences (which neighborhoods are reached, in which order) as signals for semantic meaning.

The equation

First in words:

Relation prediction is the average prediction from each sampled walk, weighted by learned importance scores. The weight for each walk depends on the entity pair and relation.

Then the compact form:

pred_rel = sum_walks w_walk * embedding_walk / sum_walks w_walk

Every symbol:

pred_relPredicted probability of the relation (number between 0 and 1)
w_walkLearned importance weight for this particular walk and relation
embedding_walkThe vector produced by embedding this random walk with a transformer
sum_walksAverage over many random samples
A tiny worked example
Relation 'authored': Entity pair (Einstein, relativity). Sample 3 random walks.
Walk 1 path (Einstein -> co-worker -> relativity): weight 0.1, score from model 0.9.
Walk 2 path (Einstein -> wrote -> relativity): weight 0.7, score from model 0.95.
Walk 3 path (Einstein -> studied -> relativity): weight 0.2, score from model 0.8.
Weighted average = (0.1 * 0.9 + 0.7 * 0.95 + 0.2 * 0.8) / (0.1 + 0.7 + 0.2) = 1.56 / 1.0 = 0.91.
The model learns to give walk 2 high weight for 'authored' because that walk sees the direct wrote connection; other walks get lower weight for this relation.

The learned weights are the key: they let the model ignore irrelevant walks and emphasize the walks that reveal the true relation, even when the overall graph structure looks symmetric.

What can go wrong

What can go wrong

Too much randomness, too few samples. If you sample only one or two walks, the randomness dominates and the model learns noise instead of structure. You need enough samples for the law of large numbers to kick in; the aggregate has to be stable.
Learned weights can overfit to training relations. The pooling weights learn which walks matter for each relation. On a new graph with new relations, those weights may not transfer, especially if the new relations have different structural signatures.
Very large graphs become slow. Sampling random walks and converting each one into a list of numbers with a transformer is expensive. On huge knowledge graphs with billions of edges, inference time grows with the number of samples because you have to do this conversion many times.
Done right: Flock balances number of samples. The paper tunes the sample count so that randomness is enough to break ties but not so much that it drowns out signal. This is dataset-dependent.
What a runnable demo should prove

What a runnable demo should prove

Build a mini knowledge graph with two relations that are structurally identical (same in-degree, out-degree, same neighbor types) but semantically distinct: for example, 'parent-of' and 'aunt-of' in a family tree, or 'produced-by' and 'co-produced-by' in a music dataset. Train Flock on this graph, leaving out a few edges. Measure whether the model correctly predicts which relation is missing.

accuracy = (correctly predicted relations) / (total held-out edges)

The demo must show that Flock's accuracy on semantically distinct but structurally identical relations is at least 30-40 percentage points higher than a deterministic equivariance baseline. This proves the randomness actually breaks the symmetry.
