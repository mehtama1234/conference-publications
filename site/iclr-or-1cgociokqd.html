Flock: Random Walks Unlock Knowledge Graph Prediction

Adding structured randomness to graph neural networks lets them tell apart relations that look identical in structure but mean opposite things.

Paper explainersAll themesGraph & Geometric Learning

Knowledge graphs store facts like "Alice likes Bob" and "Alice dislikes Charlie". A naive model that treats all relationships the same way cannot learn why "likes" and "dislikes" are different—they have identical structure (one arrow from a person to another person). Flock solves this by using random walks that wander the graph in multiple different ways, building up many different views of each relation, so the model sees the full picture and can tell opposite relations apart.

Why Today's Graph Models Miss Opposite Relations

A knowledge graph is a collection of facts: "Person A likes Person B", "Location C is in Country D", "Movie E stars Actor F". Each fact has a subject (the thing doing something), a relation (the action or property), and an object (the thing receiving the action). To predict new facts—"Is Movie G starred by Actor H?"—we need a model that learns what each relation means.

The problem: if two relations have the same structure (they both connect people to people, for instance), a naive model that just looks at the graph structure sees them as identical. "Alice likes Bob" and "Alice dislikes Bob" both show one person pointing to another person. A model built to be "invariant to structure" (ignoring structural differences because it assumes structure doesn't matter) cannot tell them apart. This is deterministic equivariance: the model treats structurally identical things identically, no matter what they really mean. It is forced to give both "likes" and "dislikes" the same learned representation.

A beginner might try to fix this by giving each relation a separate label: "This arrow is labeled like, this arrow is labeled dislike." But then the model cannot generalize. When it sees a new relation it has never seen before (because a knowledge graph is open—new relations keep appearing), it has no learned representation for that label, so it fails. The paper calls this the challenge of unseen relations.

The core insight. Flock adds randomness on purpose: it samples many different random walks through the graph, so each relation gets seen in many different contexts, letting the model learn what makes it unique.

The algorithm as a flow

What it actually does

Sample random walks

Starting from each entity, roll dice multiple times to pick random neighbors and trace paths through the graph.

Record the path

Write down each step—which nodes and relations the walk visits, in order—as a sequence.

Encode sequences

Feed each walk sequence into a sequence processor (like a transformer), which learns patterns in how paths unfold.

Pool proposals and confidences

Collect all the learned updates from all walks; weight each one by how confident the model is in that walk.

Predict unseen relations

Because walks randomize the view, the pooled representation works for new relations the graph has never seen.

What the paper changes

What the paper changes

Flock changes which random walks get sampled and how their results are blended together. Instead of asking the model to treat all walks equally (one weighted average), it learns which walks matter most for each specific relation, recording both a proposal (the update suggested by that walk) and a confidence score (how much to trust it).

The hidden quantity

The hidden quantity: Confident proposals

measured quantity  =  Walk proposal confidence

Every time the model processes a random walk, it generates two things: a proposal (what the node or relation representation should become) and a confidence score (how certain the model is in that proposal). The confidence score tells you which walks are informative and which are noise. A walk that finds a tight cluster of similar edges gets high confidence; a walk that wanders into an outlier region or a dangling dead-end gets lower confidence.

The paper estimates confidence by looking at how the walk's local structure tells a consistent story. If a walk densely visits a tight cycle-like region (many edges pointing back on themselves), the structural encoding is clear and confident. If it terminates in a dangling manner (ends at a dead-end), confidence is lower. This is the hidden quantity that lets the model distinguish relations: it learns which walks paint a clear picture of each relation's meaning.

Why it works

Why randomness breaks the symmetry trap

Deterministic graph models enforce a rule: if two things have the same structure, they must have the same representation. This rule is useful (it lets the model generalize to new graphs with similar structures), but it also forces opposite relations into identical representations, making them indistinguishable. Flock preserves the generalization benefit while breaking the symmetry by adding structured randomness.

Here is the key move: every time the model samples a walk, it makes random choices about which neighbors to visit. These random choices mean the same relation gets encoded into many different sequences. "Like" might be encoded one time as a path through popular entities, another time as a path through niche entities, another time through a dense cluster. "Dislike" travels different random paths. Over many samples, the pooled walk representation captures the full identity of each relation—not just its structure, but its semantic role in the graph.

The confidence weighting refines this: walks that reveal clear structure (cycles, dense neighborhoods) get high confidence; walks that hit dead-ends or contradictions get low confidence. So the model learns not just many views, but the most informative views, because during training it tunes the confidence scores to give high weight to walks that help predict the facts correctly. The randomness breaks the deterministic symmetry, and the confidence weighting ensures the model only trusts walks that tell the true story.

Math after the picture

The aggregation formula

First in words:

For each node or relation, collect all its walk proposals and confidences. Compute a weighted average where the weight is the softmax-normalized confidence.

Then the compact form:

repr = sum_walk ( softmax(confidence_walk) * proposal_walk )

Every symbol:

reprthe final learned representation of a node or relation
sum_walkadd up the results from all random walks
softmax(confidence_walk)turn confidences into fractions that add to 1
proposal_walkthe update suggested by this particular walk
*multiply confidence by proposal, so high-confidence walks pull harder
A tiny worked example
Suppose we sample 3 walks. Walk-1 proposes [5.0, 2.0] with confidence 3.2. Walk-2 proposes [1.0, 4.0] with confidence 0.5. Walk-3 proposes [4.5, 2.5] with confidence 1.8.
Softmax([3.2, 0.5, 1.8]) = [0.62, 0.08, 0.30] (these sum to 1).
repr = 0.62 * [5.0, 2.0] + 0.08 * [1.0, 4.0] + 0.30 * [4.5, 2.5]
= [3.1, 1.24] + [0.08, 0.32] + [1.35, 0.75]
= [4.53, 2.31]
Walk-1 dominates because its confidence is highest. Even the low-confidence walk-2 contributes, so the model sees all viewpoints but trusts the clearest paths most.

Each relation gets built from many random walks, weighted by how clearly each walk reveals its meaning.

What can go wrong

What can go wrong

Too few walks, or walks all take the same path. If the random sampling never explores enough of the graph, or if the graph structure funnels all walks into one stereotype, the model will not see diverse views of the relation. Flock handles this by adaptively scaling the number of walks based on the graph size: larger graphs get more walks to ensure coverage.
Confidence weighting fails if the model cannot learn which walks are trustworthy. If the sequence encoder is weak or the training data is too small, the confidence scores may be meaningless noise. Then pooling high-confidence and low-confidence walks equally or in the wrong proportions will hurt accuracy.
The method assumes the graph structure itself is informative. If a relation's meaning is purely determined by semantic labels (its name) and has no structural signature in the graph, random walks will not help, because walks only explore neighbors and edges—they cannot see a label. Flock learns structural invariants (the patterns in which kinds of things each relation connects), not semantic ones (what the relation is called or meant to do abstractly).
Done right: adaptive scaling and learned confidence. Flock scales the number of random walks to match the input graph size at test time, maintaining consistent walk coverage. It learns confidence scores during training, so high-confidence walks really do capture clearer structure.
What a runnable demo should prove

What a runnable demo should prove

Build a tiny knowledge graph with three relations: A-likes-B, A-dislikes-B, A-knows-B. Relations 1 and 2 have identical structure (a person connecting to a person), but opposite semantics. Relation 3 has the same structure but appears in different contexts. Train Flock on 80 percent of the facts. On the held-out 20 percent, measure: (1) does it correctly predict new likes vs dislikes, even though they are structurally identical? (2) does it generalize when you add new entities it has never seen? (3) does it generalize when you introduce a relation it has never seen in training?

Accuracy on opposite relations = (correct on likes + correct on dislikes) / (total likes + total dislikes) at test time

The demo succeeds if Flock accurately predicts opposite relations (likes vs dislikes) that deterministic models confuse, proving that randomized walks extract meaning beyond structure alone.
