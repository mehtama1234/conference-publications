Robust Robot Policy Merging

Blend finetuned and pretrained robot weights to learn new skills without forgetting old ones.

Paper explainersAll themesRobotics & Control

Robots trained on many tasks can do lots of things. But when you teach them a single new task, they learn it perfectly on the examples shown—and then completely forget how to do all the other tasks. This paper shows that you can have both: teach a robot a new skill while keeping all its old abilities, just by mixing the new weights with the old ones.

The Forgetting Trap

A robot policy is a set of rules (stored as numbers called weights) that tells a robot what to do in any situation. Large policies learned from many tasks can handle all kinds of scenarios—pick objects, navigate, push, grasp—because they have learned patterns that work across many different jobs.

But the moment you teach this robot a new task using only a handful of examples, the weights shift sharply toward solving just that one task. The weights drift so far that they no longer recognize situations from the old tasks. The robot breaks its old skills to perfect the new one.

The core problem. Training on new task examples pulls all the weights away from what made the robot generalist, so it forgets.

What the paper changes

What it changes

The paper changes one thing: the final weights of the trained robot policy. Instead of using the weights that came straight from finetuning, it interpolates them—creates a new set of weights that is a weighted average between the finetuned and pretrained weights. This simple shift, controlled by a blend ratio (a single number you choose), is the entire method.

the object it moves  =  The final weights
The hidden quantity

The hidden quantity: Weight drift

measured quantity  =  How far each weight moved from pretrained

When you finetune on a new task, each weight number changes. Some weights shift a little, others shift a lot. The paper never explicitly measure how far each one drifted—but that drift is the hidden mechanism: weights that drifted far away from the generalist solution are the ones causing forgetting.

The merging strategy implicitly corrects this by pulling every weight part-way back to its pretrained value, shrinking the drift. Weights that drifted far are pulled back hard; weights that drifted a little are left mostly as-is.

Why it works

Why blending preserves generalization

The pretrained model learned to recognize patterns shared across many tasks—how to grip different shapes, navigate different rooms, adapt to different objects. Those patterns live in the weights as a kind of summary of what works across contexts.

When finetuning on just a few new examples, the optimization algorithm (which nudges weights to shrink errors on that one task) has no incentive to keep those broad patterns. It finds a set of weights that solves the new task perfectly but abandons everything else.

Merging works because it keeps a foot in both camps. By blending new and old weights, the merged model has some weights tuned to the new task (so it learns and generalizes within that task) and some weights still holding the old patterns (so it still recognizes the old situations). The robot trades a tiny bit of new-task perfection for the ability to handle variations of the new task and remember the old skills.

Math after the picture

The interpolation equation

First in words:

The merged weight at position i is alpha times the pretrained weight plus one minus alpha times the finetuned weight.

Then the compact form:

w_merged_i = alpha * w_pretrain_i + (1 - alpha) * w_finetune_i

Every symbol:

w_merged_ithe final merged weight at position i
w_pretrain_ithe original pretrained weight at position i
w_finetune_ithe weight at position i after finetuning on the new task
alphathe blend ratio, a number between 0 and 1; higher alpha keeps more of the pretrained weights
A tiny worked example with three weights
Suppose alpha = 0.7 (keep 70 percent pretrained, 30 percent finetuned).
Weight 1: pretrained = 2.0, finetuned = 8.0 -> merged = 0.7 * 2.0 + 0.3 * 8.0 = 1.4 + 2.4 = 3.8
Weight 2: pretrained = -1.5, finetuned = -0.5 -> merged = 0.7 * (-1.5) + 0.3 * (-0.5) = -1.05 + (-0.15) = -1.2
Weight 3: pretrained = 0.1, finetuned = 0.4 -> merged = 0.7 * 0.1 + 0.3 * 0.4 = 0.07 + 0.12 = 0.19
All three weights are pulled partway back toward their pretrained values.

The interpolation is applied to every single weight in the entire model, creating a merged model that is a balanced combination of what the robot learned from many tasks and what it learned from the new task.

What can go wrong

What can go wrong

Choosing the wrong blend ratio. If alpha is too high (too much pretrained), the robot barely learns the new task. If alpha is too low (too much finetuned), it forgets again. The paper does not give a universal formula; you have to tune alpha for your task.
The new task is very different from pretraining. If the new task requires completely different behavior (opposite of what the robot learned before), merging may not help—the old patterns actively interfere, because keeping them in the merged weights pulls the model away from what it needs to do now. You might need a different alpha, or accept lower performance.
Not enough finetuning data. If you have only one or two examples of the new task, the finetuned weights may be so noisy that merging just blurs them without learning anything useful.
When it works well. The new task shares some underlying structure with the pretraining tasks (e.g., new object shapes but same grasping strategy, new room layouts but same navigation principles). Then merging smoothly inherits the relevant patterns.
What a runnable demo should prove

What a runnable demo should prove

Build a simple robot policy (a small neural network) pretrained on two tasks: pushing an object left and pushing it right. Then introduce a third task: pushing the object forward. Finetune the network on five examples of the forward task. Measure three things: how well the merged model does the new task, how well it generalizes to variations (forward at different speeds, starting positions), and how much it remembers of the old tasks (pushing left and right).

Total score = (new_task_accuracy + new_task_generalization + old_task_1_accuracy + old_task_2_accuracy) / 4

The demo must show that merging beats both the pretrained baseline (which ignores the new task) and the finetuned baseline (which forgets the old tasks). The merged model should be stronger on new-task variations than either pure pretrained or pure finetuned, because it combines weights tuned for the new task with weights that hold old patterns, so it recognizes both the new setup and its variations.
