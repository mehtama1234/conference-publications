ALL-IN: Bridging Input Feature Spaces for Graph Foundation Models

Graph models can now work on any dataset by converting diverse input features into invariant statistical patterns that survive feature shuffles and basis changes.

Paper explainersAll themesGraph & Geometric Learning

Graph neural networks today cannot share their learned knowledge across datasets. The problem is simple: node features in one dataset (say, atom types and positions in a molecule) look nothing like features in another dataset (species names and measurements in a biology graph). They have different meanings, different value ranges, and different counts. This diversity traps each model to its home dataset. ALL-IN solves this by converting any node features, no matter how misaligned, into stable statistical patterns that work the same way no matter how you shuffle or rotate the original features.

Zero assumption version

Why graphs cannot move between datasets

Today, a graph neural network is built for one dataset. If you train it on protein interactions (with amino acid labels and bond strengths as features), it cannot handle a social network (with user IDs and activity counts). The naive approach is to reuse the trained weights anyway: just feed new features into the same model. This fails because the model learned to expect exactly 128 numbers per node (called a feature vector, just a list of numbers), but the new dataset has 50 numbers per node. Or it learned that the third number ranges from 0 to 1, but now it ranges from 100 to 1000. The model has no idea how to interpret these surprises.

A beginner might try to align the features first by hand-labeling which input dimensions are similar across datasets. But this is tedious, breaks if you add a new dataset, and often fails anyway when the similarity is not clean. The root problem is that graph models encode their understanding of features directly in their internal pathways, making them brittle to any change in how features look.

The method in one sentence. Instead of learning from raw features directly, convert them into covariance matrices that stay the same even if you shuffle or rotate the original features.

The algorithm as a flow

What it actually does

Step 1: Random projection

Take node features from any dataset (any dimension, any range) and multiply by a random table of numbers to land in a shared fixed-dimensional space.

Step 2: Center the features

Subtract the average projected feature at each node so each starts at zero.

Step 3: Compute covariance

For each node, measure how the centered projected features vary together (create a table of these co-variations).

Step 4: Use as graph operator

Feed each node's covariance table (how its features vary together) into the graph neural network instead of raw features.

Step 5: Train once, apply to any dataset

The learned weights see covariance patterns, so they work identically on molecules, biology, social networks, or any new dataset with new input features.

What the paper changes

What the method changes

The paper replaces raw node features with covariance matrices computed from randomly projected features. Raw features are sensitive to how many dimensions you have, what range they occupy, and what order you list them in. Covariance matrices are immune to all three: shuffle the input dimensions, and the covariance stays the same (because it only cares how features move together, not their original order). Rotate the input space (change basis), and the covariance still describes the same relationships. This invariance is the key.

the object it moves  =  raw node features converted to covariance-based operators
The hidden quantity

The hidden quantity: feature invariance

measured quantity  =  How covariance stays unchanged under feature shuffles and rotations

Distributional invariance means: if you permute (shuffle) the input feature dimensions, or apply an orthogonal rotation (a basis change that preserves distances), the covariance matrices computed from the projected features look statistically identical. This is invisible in raw features but measurable in covariance. For example, if you list features as (temperature, humidity, pressure) versus (pressure, temperature, humidity), the covariance matrix is the same—it only measures how these properties co-vary, not their order.

The paper estimates and proves this invariance mathematically by showing that (a) node representations remain invariant to feature permutations, (b) the expected covariance operator is invariant to orthogonal transformations, and (c) the random (unpredictable) projection ensures this holds on average over many random draws. When tested on real data, the method works unchanged across datasets with completely different input dimensions and semantics, proving the invariance holds in practice.

Why it works

Why it works: the causal chain

Raw features encode dataset-specific details: dimension count, value ranges, semantic meaning. When you shuffle features or change the basis (rotate the coordinate system), raw features scatter—they are no longer comparable across datasets. Covariance matrices, by contrast, measure only how features co-vary, not their absolute positions or order. Shuffle feature dimensions, and the co-variance structure survives because it is about relationships, not labels. Rotate the space, and distances between features are preserved, so covariances stay the same.

The paper uses random projections to move any misaligned feature into a unified high-dimensional space before computing covariance. The random projection is the key to unlocking permutation invariance: because the projection is random and applied after any permutation, no permutation of the input can bias which features land where. The covariance of the projected, centered features then captures the true co-variation in a way that is blind to input order.

Once covariance matrices replace raw features in the graph neural network, the learned weights see only these stable, invariant patterns. The same learned weights can be applied to any new dataset (even with different input dimensions and semantics) because the covariance patterns they have learned are universal—they describe fundamental relationships that survive feature shuffles and basis changes. This is why no retraining or architecture changes are needed.

The equation and what it means

First in words:

First, project features using a random matrix into a unified space. Center them by subtracting the mean. Compute the covariance matrix. Use this as the graph operator in each layer.

Then the compact form:

R^(p) = X * C ; K^(p) = Cov(R^(p)_centered) ; H^(l) = aggregate(GNN_layer(l, K)(H^(l-1), K))

Every symbol:

A tiny worked example
Dataset A: node has features [3, 7] (molecule: temperature and pressure). Dimension = 2.
Dataset B: node has features [100, 50, 200] (biology: three measurements). Dimension = 3.
Both randomly project to dimension h = 4: R_A and R_B are now both 4-dimensional.
Center each by subtracting its mean: R_A_centered and R_B_centered.
Compute 4-by-4 covariance matrix K_A = Cov(R_A_centered) and K_B = Cov(R_B_centered).
Graph network trained on K_A: learns weights that interpret covariance patterns.
Same graph network on K_B: covariance patterns are similar (even though input was 3-dim vs 2-dim), so learned weights apply.

The random projection erases sensitivity to input dimension; centering erases sensitivity to absolute values; covariance captures only relationships, which survive permutations and basis changes.

What can go wrong

What can go wrong

Covariance is sensitive to scale. If features in one dataset are scaled 1000x larger than another, the raw covariance values will be very different (because covariance is the average of feature products, so 1000x input means 1,000,000x covariance). The paper addresses this by centering features first, but if the variance structure itself is not comparable (e.g., one dataset has almost no variation in a direction), covariance may not capture it. Normalizing (dividing) projected features before computing covariance can help, because it shrinks all scales to the same size so the method sees only the shape of relationships, not their magnitude.
Random projection noise in small dimensions. If the original feature space is very small (dimension 2 or 3), a random projection to a much larger space introduces noise. The invariance proof assumes the projection is to a sufficiently high dimension. Too-small hidden dimension h can break the invariance in practice.
Covariance loses individual feature information. Covariance measures how features co-vary, not their absolute values. If a dataset has features that are individually predictive (e.g., the label correlates with a single feature's magnitude, not its relationship to others), covariance alone may miss that signal. The method works best when relationships between features matter.
Done right. Ensure random projection dimension is high enough (at least as large as the largest original feature dimension, preferably higher). Normalize or center input features if they have very different scales. Test invariance by shuffling input feature order and confirming predictions do not change.
What a runnable demo should prove

What a runnable demo should prove

Build a simple graph neural network using covariance operators instead of raw features. Pre-train it on two datasets with different input feature dimensions and semantics (e.g., a small molecular graph with 10 features and a social network with 50 features, or a biology network with 30 features). Then, without retraining or changing the model architecture, apply it to a third unseen dataset with a completely different set of input features (e.g., a knowledge graph with 100 features). Measure node classification or link prediction accuracy. The demo succeeds if accuracy is high enough to be comparable to a model trained separately on that third dataset.

transfer_success = (accuracy_on_new_dataset_with_ALL_IN) / (accuracy_on_new_dataset_with_specialized_model_trained_from_scratch)

If transfer_success is above 0.9 (e.g., 90% of the specialized model's performance with zero retraining), the demo proves that covariance invariance truly enables transfer across datasets, because it shows the learned weights from one feature layout work identically on a different layout—demonstrating that covariance patterns are truly universal and do not depend on feature order or dimensionality. The demo should also verify that shuffling input feature order does not change the model's predictions; if predictions stay the same after shuffling, it proves the model learned only from the covariance relationships, not from raw feature identity.
