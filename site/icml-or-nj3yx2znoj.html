TabMGP: Martingale Posterior with TabPFN

TabMGP turns TabPFN predictions into uncertainty for a user-chosen target quantity, so tabular practitioners can get calibrated credible sets without specifying a full prior-and-likelihood model.

Paper explainersAll themesOther

A scientist often wants more than a point prediction. They may want uncertainty for a quantity such as a treatment effect, an optimal threshold, or the best setting of a control variable. Classical Bayesian analysis can provide that uncertainty, but it asks the user to choose a prior (a distribution over plausible values before data) and a likelihood model. Those choices are difficult when the data model is complex or implicit. The martingale posterior offers another route: start from a predictive rule instead of a full generative model, then build uncertainty for the quantity defined by the user's loss. This paper plugs TabPFN into that route for tabular data.

Why uncertainty is hard when the predictive engine is implicit

Strong predictive systems for tabular data often act like black boxes from the user's point of view. They can predict well, but they do not naturally return uncertainty for an arbitrary scientific target. A user may care about a quantity derived from the predictions rather than about the internal model itself.

Classical Bayesian analysis addresses uncertainty by writing down a prior (a distribution over plausible values before data) and a likelihood (a rule for how data would be generated from those values). That is useful, but it can be hard to specify well for modern predictive engines. The paper uses a martingale posterior instead, which builds uncertainty from sequential predictive performance.

The practical gap. People have strong tabular predictors, but they still need uncertainty for user-defined target quantities, and writing a full Bayesian data model is often the hardest part.

The algorithm as a flow

What it actually does

Choose the target quantity.

Define the quantity of interest through a loss function, so the method knows what kind of uncertainty the user wants.

Use TabPFN as the predictive engine.

Let TabPFN provide sequential predictions for the tabular data, because those predictions replace the need to write down a full prior-and-likelihood model.

Update weights over candidate values.

Increase or decrease support for candidate target values according to how well they agree with the predictive evidence seen so far.

Accumulate the martingale posterior.

Combine those sequential updates into a final distribution over plausible target values.

Read out credible sets.

Turn the final distribution into intervals or sets that summarize uncertainty for the chosen quantity.

What the paper changes

The paper changes where uncertainty comes from. Instead of requiring a user-specified generative model, it derives uncertainty for a chosen target quantity from the predictive behavior of TabPFN.

The hidden quantity

The hidden quantity

measured quantity  =  support for each candidate target value after sequential predictive updates

The hidden quantity is the running amount of support assigned to each candidate target value. As new data points are processed, some candidate values remain compatible with the predictive rule while others become harder to defend. The final uncertainty summary depends on how that support changes over time.

This matters because the user may care about a target that is not an explicit built-in quantity of the predictive engine. The martingale construction still works because it only asks how well candidate values align with the predictive evidence generated by the model.

Why it works

Why predictive uncertainty can replace a full Bayesian model here

The method helps when the predictive engine is strong but the full data-generating model is hard to specify because then the user can rely on accurate predictions without designing a full generative model. TabPFN already captures detailed patterns in tabular data. The martingale posterior uses that predictive strength as the primitive object and asks how candidate target values fare under sequential predictive checking.

The construction remains useful for a user-defined target because the loss function tells the method what quantity to evaluate. Candidate values that repeatedly agree with the predictive evidence keep support, while values that conflict lose support. That is why the method can return credible sets with good coverage without forcing the user to design a full prior-and-likelihood pair.

Math after the picture

Sequentially reweight candidate values

First in words:

Start with weights over candidate target values and multiply each weight by how well that value agrees with the next predictive step.

Then the compact form:

w_t(theta) proportional to w_(t-1)(theta) * s_t(theta)

Every symbol:

w_t(theta)the support weight on candidate target value theta after seeing t data points
w_(t-1)(theta)the previous support weight before the new data point
s_t(theta)the predictive score assigned to candidate value theta at step t
thetathe target quantity value whose plausibility we are tracking
A tiny worked example
Suppose two candidate values for the target quantity start with equal weight 0.5 and 0.5.
After the next data point, the first candidate gets predictive score 0.8 and the second gets 0.2.
Their unnormalized new weights become 0.4 and 0.1.
After normalization, the first candidate gets weight 0.8 and the second gets weight 0.2.
The first candidate now has more posterior support because it agreed better with the predictive evidence.

The paper's exact scoring rule is tied to the martingale construction, but the main idea is repeated reweighting by predictive compatibility.

What can go wrong

What can go wrong

Weak predictions give weak uncertainty. If TabPFN predicts poorly on the data at hand, the sequential support updates will drift in the wrong direction because the predictive rule is the foundation of the whole construction.
A poorly chosen loss can target the wrong quantity. If the user writes a loss that does not match the scientific question, the credible set can be well calibrated for the wrong target because the method faithfully follows the requested quantity.
Small samples can leave wide credible sets. When data are limited, many candidate values may remain plausible because the predictive evidence is not strong enough to rule them out sharply.
Done right. The method works when the predictive rule is strong and the target quantity is clearly defined, because then sequential reweighting can produce uncertainty that is both calibrated and directly relevant.
