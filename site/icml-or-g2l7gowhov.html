Transport or Discard: Robust Unbalanced Optimal Transport for Cross-Domain Policy Adaptation

Reweight source-domain transitions so target training keeps only source data that can plausibly happen under target dynamics.

Paper explainersAll themesOther

Cross-domain offline reinforcement learning tries to learn a target policy from a small target dataset plus a larger source dataset. The difficulty is not only that the tasks differ, but that some source transitions cannot happen in the target system at all. If training treats every source transition as usable, the learner copies motions that violate target dynamics and target training gets worse. ROOT addresses this by computing how much source data should move onto target data and how much should be left unused.

Zero assumption version

Source data can contain transitions the target system cannot execute

Offline reinforcement learning learns only from logged state, action, next-state records. In cross-domain use, the target domain may have very little logged data, so adding a larger source dataset is attractive. The hidden risk is that the source robot, simulator, or environment may move differently. A source action that looks useful on paper may send the target system to a next state that its own dynamics never produce.

A simple reuse rule says: find source samples that are near target samples and keep them. That still forces every unit of source data to match something, even when some source samples are clear mismatches. Then the ranking threshold becomes the whole method. If the threshold is too loose, bad source transitions leak in. If it is too strict, useful source coverage is thrown away.

The real issue. Cross-domain reuse fails when the method treats impossible source transitions as if they merely needed a weaker score instead of being discarded.

The algorithm as a flow

What it actually does

Represent source and target transitions

Treat each logged transition as a point that includes where the system started, what action was taken, and where it went next.

Measure cross-domain transport cost

Assign a cost for moving probability mass from each source transition to each target transition.

Allow mass to disappear

Do not force every source transition to match a target transition; unmatched mass pays a discard penalty instead.

Guard against small target samples

Optimize against a set of plausible target data patterns, which means several nearby versions of the small target sample are considered so the weights do not overreact to one noisy collection.

Train offline RL with the learned weights

Use the weighted source data together with target data, so target-incompatible source transitions contribute little or nothing.

What the paper changes

What the paper changes

The paper changes the weight attached to each source transition. Instead of choosing a hard keep-or-drop threshold by hand, it solves an optimization problem whose output is a soft source reweighting. High-quality source transitions keep weight because they are cheap to transport onto target behavior. Mismatched transitions lose weight because discarding them is cheaper than forcing a bad match.

The hidden quantity

The hidden quantity: transferable source mass

measured quantity  =  transferable source mass

The method is really estimating how much of the source dataset lives inside the target domain's feasible transition set. A feasible transition set is the collection of next states the target system can actually reach from a given state and action. If a source transition sits outside that set, reusing it teaches the learner a false dynamics story.

ROOT does not estimate this quantity with a hard yes-or-no rule. It computes how much probability mass from the source should be assigned to target transitions and how much should be removed. Large assigned mass means the source transition behaves enough like target data to support training. Large removed mass means the sample is acting as an outlier under target dynamics.

Why it works

Why transport plus discard works

Standard optimal transport tries to match all source mass to target mass. That is appropriate when both datasets describe the same underlying process and only the sample locations differ. In cross-domain offline reinforcement learning, that assumption is false whenever the source system can move in ways the target system cannot. Forcing full matching then spreads target weight onto bad source samples.

ROOT changes the optimization in two linked ways. First, it uses an unbalanced transport rule, which means total mass does not have to be preserved. This matters because bad source samples should be removed instead of reassigned. Second, it adds a guarded set around the target data pattern. That matters because a small target dataset is noisy, so a brittle exact fit would treat accidental target sample quirks as hard truth. The result is a weighting rule that is conservative about uncertain target coverage and severe on clearly high-cost source samples.

The abstract states that the final weights decay exponentially with transport cost. That detail matters because it gives a direct suppression law: once a source transition becomes costly to explain as target behavior, its contribution falls very quickly. The learner is therefore pushed toward source support that matches target kinematics rather than merely source samples that happen to be numerous.

Math after the picture

The equation: weighted source reuse from unbalanced transport

First in words:

Choose a transport plan whose total cost is transport cost plus a penalty for source mass that is left unmatched and a penalty for target distributions that move too far from the observed target sample.

Then the compact form:

min_plan transport_cost(plan) + discard_penalty(unmatched_source_mass) + ambiguity_penalty(target_shift)

Every symbol:

planhow much probability mass moves from each source transition to each target transition
transport_cost(plan)the price of explaining source transitions as target transitions
unmatched_source_masssource mass that is not sent to any target transition
discard_penaltythe cost paid for dropping mismatched source samples instead of forcing them into the match
target_shifthow far the effective target distribution moves inside the allowed uncertainty set
ambiguity_penaltythe cost that prevents the method from trusting a noisy target sample too literally
A tiny worked example
Source sample A has low transport cost to several target transitions, so matching it is cheaper than discarding it.
Source sample B needs a very large move to reach any target transition, so the discard penalty is cheaper than matching it.
The final weight on A stays high, while the final weight on B drops near zero.
Training then sees A many times and B rarely or never, so the target learner copies feasible behavior rather than impossible behavior.

The exact paper objective is more detailed, but this form captures the three forces that matter: match what fits, drop what does not, and avoid overfitting the tiny target sample.

What can go wrong

What can go wrong

Bad transport cost design. If the cost function misses the state or action features that determine target feasibility, the optimization keeps the wrong source samples because it is measuring the wrong kind of mismatch.
Too much discarding. If the discard penalty is too small, the method removes source mass too aggressively, so target training loses useful coverage that could have helped in low-data regions.
Too much trust in scarce target data. If the ambiguity set is too tight, the weights chase sample noise in the target dataset, so the learned overlap reflects accidents of collection rather than stable target dynamics.
Done right. The method works when transport cost really reflects transition feasibility, the discard penalty is balanced against reuse value, and the ambiguity set absorbs uncertainty from small target samples.
What a runnable demo should prove

What a runnable demo should prove

Build a toy offline control task with one source system and one target system that differ in how far they can move after the same action. Generate a large source dataset and a small target dataset. Then compare three training sets: target-only, source-plus-target with all source samples equally weighted, and source-plus-target with ROOT-style weights.

The key observation should be visible at the sample level. Plot source transitions by transport cost and learned weight. Samples that require impossible target jumps should receive very low weight, while source transitions that respect target motion limits should keep high weight. Finally, train the same offline RL learner on each dataset and compare target returns.

transfer_gain = target_return(weighted_source_plus_target) - target_return(equal_weight_source_plus_target)

A convincing demo shows positive transfer because the weighting rule keeps source coverage that matches target dynamics and suppresses source transitions that would teach false motion rules.
