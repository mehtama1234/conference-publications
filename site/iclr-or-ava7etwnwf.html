GOT-Edit: Geometry-Aware Generic Object Tracking

A video tracker learns 3D shape cues from 2D pictures alone, then carefully adds them to its tracking brain without forgetting how to spot the target.

Paper explainersAll themesComputer Vision

When you watch a video, your brain automatically understands depth and 3D shape, even in a flat 2D picture. Most video object trackers do not. GOT-Edit fixes this by taking a standard 2D tracker and teaching it 3D geometric reasoning from a few images, using a technique that adds new knowledge without erasing the old.

Zero assumption version

Trackers get fooled by occlusion and clutter

A generic object tracker is a system that watches a video and follows a target object frame by frame. Most trackers today look at 2D pixel patterns: color, edges, textures. But the real world is 3D.

When the target is partly hidden (occluded), or when similar objects crowd the frame (clutter), or when the target rotates or changes angle, a 2D-only tracker gets confused. A beginner might try simply adding more 2D features, but that does not solve the core problem: the tracker is blind to the fact that objects have depth and solid shape.

The root issue: a 3D object rotating in space looks like a 2D shape changing. Without understanding that it is the same solid object, not a different appearance, the tracker makes brittle guesses.

In one sentence. Add 3D shape understanding to a 2D tracker, and do it in a way that keeps the tracker sharp at recognizing the target.

What it actually does

Fuse the shape and semantic feature streams into a combined representation of what to learn.

The tracker now has both 2D recognition and 3D reasoning, applied without conflict.

What the paper changes

What the paper changes

The paper edits the tracker's internal weights (the knobs and dials that control how the tracker processes video frames). Most trackers freeze their weights after training. GOT-Edit does online editing: it adds a new component during tracking that incorporates 3D shape understanding into the weight update, specifically in a subspace that does not interfere with the existing 2D semantic features.

The hidden quantity

The null-space direction

measured quantity  =  null-space constraint

The null-space is a hidden direction in the tracker's internal weight space. It is the subspace perpendicular to all directions that affect the 2D semantic recognition. Think of it as a tunnel through the weight space where you can move weight around without changing the tracker's ability to spot and distinguish the target.

The paper estimates this null-space using singular value decomposition (a mathematical technique that breaks weight matrices into independent directions). It then adds the geometric information only along these orthogonal directions, leaving the semantic weights untouched.

Why it works

Why adding 3D without erasing 2D works

Here is the core problem: if you simply add shape knowledge to the tracker by updating all the weights, you risk moving weights in directions that affect 2D recognition. You might make the tracker better at understanding 3D form but worse at spotting the target in clutter, because the weights that encode target appearance and the weights that encode 3D form may be intertwined—nudging one might scramble the other.

GOT-Edit solves this by decomposing the weight space into two orthogonal (perpendicular) subspaces: one that affects 2D semantic features (the existing skill), and one that does not (the null-space). By design, changing weights in the null-space direction has zero effect on the semantic output. So the paper updates the tracker's weights only in the null-space, using a technique called null-space constrained singular value decomposition. This adds all the 3D information the model can extract, but in a zone where it cannot harm the 2D recognition. The result is a tracker that is richer (it understands 3D shape) and stable (it does not lose its 2D acuity).

Math after the picture

The null-space update equation

First in words:

new weights equals old weights plus lambda times the 3D shape information projected into the null-space

Then the compact form:

W_new = W_old + lambda * P_null * G

Every symbol:

W_oldthe tracker's weights before editing
Gthe shape feature list (depth, form, orientation)
P_nullthe projection onto the null-space of the semantic table
lambdaa scaling factor controlling how much shape to add
W_newthe tracker's weights after editing
A tiny worked example
Suppose the semantic feature table has rank 8 (8 independent directions that affect recognition).
The weight space has 12 dimensions total.
The null-space has 12 - 8 = 4 dimensions where changes are invisible to semantics.
The shape feature list G has 4 elements; project it onto the 4-dimensional null-space.
P_null * G uses all 4 null-space dimensions to encode the 3D shape.
Add lambda * P_null * G to the old weights: if lambda = 0.1, a shape signal of magnitude 2.0 adds 0.1 times 2.0 equals 0.2 per weight in the null-space.
The semantic weights (in the rank-8 subspace) are untouched; the tracker's 2D recognition stays stable.

The key is that P_null zeros out any component of 3D shape that would change the semantic output, leaving only the safe, orthogonal part.

What can go wrong

What can go wrong

3D model is trained on different camera angles. If the 3D model sees mostly frontal views but the tracker encounters extreme side angles, the shape cues will be noisy. The null-space edit will add inaccurate 3D reasoning, harming tracking.
Singular value decomposition fails on rank-deficient semantics. If the semantic feature table is not full-rank (some feature directions are missing), the null-space is smaller or ill-defined. The paper applies whitening (normalization) to stabilize the decomposition, but pathological tables still cause instability.
3D shape and 2D meaning are incoherent. If the 3D model and semantic model disagree (e.g., 3D says the target is a tall narrow rectangle but semantics see a squat blob), the fused representation is conflicted and the edit may corrupt both.
Done right: 3D model is trained on in-the-wild images, semantics and shape are aligned before fusion, and the null-space is numerically stable. Extensive ablation validates that all three conditions hold; the paper's experiments on GOT benchmarks (LaSOT, GOT-10k, TrackingNet) show consistent gains.
What a runnable demo should prove

What a runnable demo should prove

Build a minimal tracker on a simple synthetic dataset: a rendered cube (known 3D form) moving and rotating in a flat video, with occasional clutter (other cylinders or spheres). Train a standard 2D template-matching tracker. Separately, train a 3D shape predictor on the same images (given ground-truth 3D labels). Then apply GOT-Edit: use null-space constraints to add the shape predictor's outputs to the tracker's weights. Measure tracking accuracy on held-out videos with varying occlusion and clutter levels.

tracking_accuracy = (frames_where_bounding_box_matches_ground_truth) / (total_frames)

The demo must show that adding 3D shape via null-space edit improves tracking in occluded and cluttered frames without hurting clean-video performance, because the null-space constraint ensures that the new shape information can only move weights in directions orthogonal to the 2D recognition, so existing accuracy is protected.
