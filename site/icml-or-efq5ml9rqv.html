PyVision-RL: Forging Open Agentic Vision Models via RL

Train a vision agent to keep using tools across several turns by rewarding useful interaction instead of short direct answers.

This paper studies a failure mode in reinforcement learning for vision agents. During training, the agent often discovers that it can get reward by answering quickly, so it stops using tools and stops carrying out multi-step reasoning. PyVision-RL changes the rollout and reward design so that sustained interaction remains worth doing because useful tool calls keep contributing to the final score.

Why agent training collapses into short answers

A vision agent is supposed to inspect images or video, call tools when needed, and combine evidence across several turns. Standard reinforcement learning can break that behavior. If short replies sometimes get reward, the agent may learn to skip the expensive parts of the job because skipping tools is an easy way to avoid mistakes.

That collapse matters because many image and video tasks need step-by-step evidence gathering. A model that refuses to inspect more frames or refuses to call a helpful tool may look cheaper during training, but it solves fewer tasks because it never collects the information that the task requires.

The paper's move in one sentence. Keep multi-turn tool use alive by sampling several candidate rollouts, keeping the useful ones, ranking them, and giving reward for productive tool interaction.

The algorithm as a flow

What it actually does

Sample several rollouts

For one task, produce several candidate interaction traces so that training can compare short and long behaviors.

Filter weak traces

Remove low-quality candidates so that the model is not pushed toward obviously bad behavior.

Rank the survivors

Order the remaining traces by task quality so that the update favors stronger solutions.

Add reward for tool use

Give extra credit when tool use contributes to solving the task because the agent should not learn that all tool calls are wasted effort.

Construct video context on demand

For video tasks, fetch only the frames needed at the current step so that the agent keeps enough visual evidence without loading the whole clip at once.

What the paper changes

What the paper changes

The paper changes the training signal for agent behavior. Instead of treating a short correct answer and a carefully gathered answer as almost the same event, it values the interaction trace itself when that trace contains useful evidence gathering.

the object it moves  =  the training score over multi-turn interaction traces
The hidden quantity

The hidden quantity

measured quantity  =  whether interaction remains worth doing during training

The central hidden quantity is the model's internal preference for using tools and continuing a search. You cannot read that preference directly. You only see it through choices such as whether the agent asks for more frames, opens a tool, or stops early.

PyVision-RL tries to keep that hidden preference pointed toward productive interaction. It does that by rewarding traces where extra steps genuinely help because the agent should learn that useful evidence gathering is part of the job, not wasted motion.

Why it works

Why this works: reward the process that finds the evidence

Interaction collapse happens when the training score says that a short reply is good enough often enough. Once that shortcut appears, the agent stops practicing search behavior because the shortcut is easier to repeat than careful evidence gathering.

PyVision-RL changes that pressure in two ways. First, it samples and ranks multiple traces, so the update sees strong interactive traces instead of only one lucky output. Second, it adds explicit reward for useful tool activity, so the model learns that checking images, checking video frames, and continuing the dialogue can raise the score because those actions support the final answer.

Math after the picture

Score a rollout by answer quality plus useful interaction

First in words:

A simple summary is to score each candidate trace by combining how well it solves the task and how much useful tool interaction it contains. Training prefers traces with larger total score.

Then the compact form:

score(trace) = task_value(trace) + lambda * tool_value(trace)

Every symbol:

score(trace)overall training value of one candidate interaction trace
task_value(trace)how well the trace solves the image or video task
tool_value(trace)how much the trace gains from productive tool use and evidence gathering
lambdaweight on the tool-use part of the score
A tiny worked example
Trace A gives a quick answer with no extra checks.
Its task value is 7 and its tool value is 0, so with lambda = 1 its total score is 7.
Trace B checks two useful frames and then answers correctly.
Its task value is 7 and its tool value is 3, so its total score is 10.
Training prefers Trace B because the extra interaction found useful evidence.

The paper uses a richer reinforcement-learning setup, but this score captures the main idea that interaction must stay rewarding when it contributes to the answer.

What can go wrong

What can go wrong

Tool reward can be gamed. If the score rewards tool calls too loosely, the agent may call tools without learning from them, because empty interaction can still collect points.
Filtering can drop unusual good traces. A useful trace may look weak at first glance and get removed, so the model can lose a path that would have taught a better strategy because the ranking signal was noisy early on.
On-demand frame choice can miss late evidence. If the video selector fetches the wrong frames, the final answer can fail because the model never saw the decisive moment.
Done right. The framework is valuable because it treats agent behavior itself as something that must be protected during training, not only the final answer string.
What a runnable demo should prove

What a runnable demo should prove

Build one image task set and one video task set where correct answers require extra evidence gathering. Train one agent with plain reinforcement learning and one with the PyVision-RL scoring setup. For the video tasks, let the second agent request frames during reasoning instead of loading the whole clip at the start.

The demo should show that the PyVision-RL agent keeps making tool calls on hard tasks because those calls help recover needed evidence. Track both final accuracy and average number of useful interaction steps so that the result shows quality and behavior together.

interaction_gain = useful_steps_pyvision - useful_steps_baseline ; answer_gain = accuracy_pyvision - accuracy_baseline

The point of the demo is to show that better answers come from keeping evidence-gathering behavior alive during training because the agent keeps collecting the facts needed for hard tasks.
