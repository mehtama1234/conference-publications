Enhancing Visual Token Representations for Video Large Language Models via Training-free Spatial-Temporal Pooling and Gridding

Improve a video language model without retraining it by keeping informative spatial regions and by preserving time structure at several time scales when compressing video features.

Paper explainersAll themesOther

Video language models must turn many video frames into a short sequence of visual tokens (one compressed visual patch representation) before the language model can read them. That compression step is often too crude. Simple averaging over space throws away small but important regions, and simple frame sampling loses how events unfold across time. This paper proposes ST-GridPool, a training-free method that changes only the compression stage. It uses norm-based spatial pooling to keep image regions whose feature vectors (lists of numbers used as learned descriptions) have large norm values, because those regions tend to carry more semantic content. It also uses pyramid temporal gridding to summarize the video at several time scales, so short actions and longer transitions both survive the reduction in length.

Zero assumption version

Why video compression is the weak point

A video language model usually starts with a vision encoder that turns each frame into many visual tokens. The language model cannot read all of them because the sequence would be too long, so the system compresses them before answering a question. If that compression mixes together unrelated regions or removes the wrong frames, the answer model receives a distorted summary of the video.

The issue is not only length. Video understanding depends on both space and time. A model must know where the important object is inside the frame and also when a change happens across frames. Many existing pooling methods treat all locations similarly or sample time uniformly. That loses the small regions and local motion patterns that often decide the answer.

The paper's move. Replace naive video compression with a plug-in procedure that preserves informative image regions and preserves time structure at several granularities because both decisions affect what evidence reaches the language model.

The algorithm as a flow

What it actually does

Extract frame features

Run the existing vision encoder on each frame to get a grid of visual tokens for every time step.

Score spatial tokens by norm

For each token, compute the size of its feature vector and use that as a signal for how informative the region may be.

Pool space selectively

Preserve or emphasize the high-norm regions so that small but task-relevant objects are not washed out by background.

Grid time hierarchically

Partition the video into several temporal resolutions and summarize each one, so that the final sequence contains long-range order and short-range events.

Feed the compressed sequence to the language model

Use the improved visual summary with the original video language model, because the method is designed to work without retraining.

What the paper changes

What the paper changes

The paper changes the representation that sits between the vision encoder and the language model. It does not retrain the core models. It changes which visual tokens are retained and how the final video summary is organized across time.

The hidden quantity

The hidden quantity

measured quantity  =  how much useful evidence survives compression

The hidden quantity is the amount of task-relevant evidence that remains after the raw frame features are compressed. You cannot read that quantity directly from sequence length alone, because two summaries of the same length can preserve very different information.

ST-GridPool estimates that quantity indirectly through two cues. In space, it assumes that tokens with larger feature norms often correspond to semantically stronger regions, so it protects them from being averaged away. In time, it assumes that one temporal scale is not enough, so it builds summaries at several resolutions. Those two choices raise the chance that the compressed sequence still contains the evidence needed for question answering.

Why it works

Why the two parts work together

Norm-based spatial pooling matters because not all frame regions deserve equal weight. If a small object or hand movement determines the answer, averaging that region together with a large background can erase it. Using token norm as a selection cue protects regions whose learned representation is strong, so the compressed feature map keeps more of the content that the vision encoder found distinctive.

Pyramid temporal gridding matters because events in video happen at different durations. Some questions depend on the overall order of the clip, while others depend on a short transition that may last only a few frames. A single temporal summary can preserve one of those views while damaging the other. By creating summaries at coarse, medium, and fine resolutions, the method keeps several views of the same sequence, so the language model can read both long-term context and short local changes.

The two components reinforce each other because spatial selectivity answers what to keep within a frame, while temporal gridding answers when to keep it across the clip. Stronger spatial choices without time structure still miss action order, and stronger time structure without spatial selectivity still passes weak regional evidence forward because the kept frames may still focus on the wrong parts of the image.

A simple view of the selection rule

First in words:

Treat each spatial token's norm as an importance score, then keep the strongest regions while also constructing temporal summaries over several segment sizes. The final sequence is the union of those selected spatial features and multi-scale time summaries.

Then the compact form:

importance(token_i) = norm(feature_i) ; summary = spatial_select(top tokens) plus temporal_grid(coarse, medium, fine)

Every symbol:

token_ione visual token from a frame
feature_ithe token's learned feature vector
norm(feature_i)the size of that vector, used here as an importance signal
spatial_select(top tokens)the step that retains the most informative spatial regions
temporal_grid(coarse, medium, fine)the step that summarizes the video at several time scales
summarythe compressed visual sequence given to the language model
A tiny worked example
Suppose one frame produces four spatial tokens with norm scores 9, 8, 2, and 1.
If only two can survive, the method keeps the tokens scored 9 and 8 because those regions are estimated to contain more useful content.
Now split a 12-frame clip into one full-length segment, three 4-frame segments, and six 2-frame segments.
Each segmentation produces a short temporal summary, so the final representation contains one global view, three medium views, and six fine views.
The result is still shorter than the raw frame stream, but it keeps both strong regions and several time resolutions.

The paper's exact implementation is more detailed, but this captures the core decision: keep stronger spatial evidence and keep it across several temporal scales because the answer model needs both accurate regions and accurate event order.

What can go wrong

What can go wrong

Large norm is not a perfect signal. A token can have a large norm because of texture, lighting, or repeated background patterns rather than because it represents the object that matters. If that happens, norm-based spatial pooling can still keep the wrong region.
Multi-scale time summaries still have a length budget. Adding several temporal grids helps because it covers more event durations, but the final sequence still must stay short enough for the language model. If the budget is too tight, some useful segments will still be merged or dropped.
The method depends on the base vision encoder. If the original frame features do not separate foreground from clutter well, then spatial norm will be a weak guide because the useful evidence is already mixed with noise before ST-GridPool starts.
Done right. The method is most convincing when the base model already extracts reasonable frame features and the main failure comes from a bad compression step rather than from a bad encoder.
What a runnable demo should prove

What a runnable demo should prove

Use an existing video question-answering model and a small benchmark where questions depend on short actions and small objects. Compare three front ends: uniform frame sampling, average pooling, and ST-GridPool. Keep the language model fixed so that only the compression method changes.

The demo should log which spatial regions were retained and which time segments survived. A convincing result shows that ST-GridPool answers more questions correctly because the retained sequence still contains the object and event evidence that the naive summaries dropped.

gain = accuracy_with_ST_GridPool minus accuracy_with_naive_pooling ; kept_evidence_rate = useful_regions_retained divided by useful_regions_total

The point is to show that stronger compression alone can improve a video language model when the bottleneck is information loss between the vision encoder and the language model, because the language model can only reason over evidence that survives the reduction step.
