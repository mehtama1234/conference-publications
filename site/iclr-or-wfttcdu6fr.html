Graph Networks That Solve Cone-Shaped Optimization Problems

A graph neural network can learn to solve a broad class of optimization problems by exploiting the geometric structure of cone-shaped constraints.

Paper explainersAll themesGraph & Geometric Learning

When you need to find the best decision under certain limits, you often face an optimization problem. Scientists have shown that graph neural networks—models that understand relationships between connected objects—can learn to solve some of these problems directly from data, without hand-coding a solver. This paper extends that capability to a harder class of problems called second-order cone programs, and proves mathematically that this is always possible.

Why hand-built solvers fail at scale

Many real decisions—shipping routes, power grids, machine schedules—involve finding the best choice subject to hard constraints. A solver is a program that finds that best choice. Traditional solvers are hand-coded algorithms that work reliably but grow slow when the problem gets large, because they must check many possible answers.

For simpler problems, researchers discovered that neural networks trained on many examples could learn to act as a solver: you show the network thousands of problems and their answers, and it learns to produce good answers for new problems it has never seen. This is much faster at decision time because a trained network computes an answer in milliseconds—one forward pass through its layers—whereas a traditional solver must repeatedly refine its guess through hundreds or thousands of steps, each requiring arithmetic and checking, which takes seconds or minutes even on computers. But this trick worked only for certain problem shapes. When the constraints form cone-shaped regions in a high-dimensional space—a more complex boundary shape—nobody could prove the network would always work.

In one sentence. The paper proves that graph neural networks can always learn to solve cone-shaped optimization problems by reading which constraints matter most.

What the paper changes

What the paper changes

The paper changes how the network sees the problem. Instead of just reading a list of constraints, the network now reads how those constraints form a cone-shaped region in the decision space. This lets the network learn which constraints actually matter—because seeing the cone structure tells it which directions are relevant—and solve problems faster because it focuses only on the few truly active constraints instead of processing all of them equally.

The hidden quantity

The hidden quantity: constraint importance

measured quantity  =  which constraints matter most

The network must learn that some constraints are active (actually limit the best answer) while others are slack (not binding). This ranking—which constraints are truly important—is invisible in the raw problem but deeply shapes the solution.

The paper estimates constraint importance by having the network learn patterns in the cones themselves. Constraints that point toward the true best point are marked as important. The network learns this ranking by comparing many solved examples and noticing which constraint directions correlate with correct answers.

Why it works

Why this works: reading which constraints are tight

A cone-shaped constraint says: a certain linear combination of variables must not grow beyond a scaled limit. The network learns to read this by representing the problem as a graph, where each variable and each constraint is a node, and connections show which variables appear in which constraints.

The cone's shape encodes information about which constraints the optimal answer will touch. When the network receives this shape information, it learns the answer faster, because it sees not just a list of rules but the structure those rules impose. The network notices that constraints pointing toward good solutions are tight (active), while others are slack (inactive).

The paper proves mathematically that for any cone problem, there exists a graph network that can read the cone structure and produce the correct answer. This is a universality result: the network's architecture can, in principle, represent any cone-problem solution. It does not guarantee the network will find the answer easily, only that the architecture itself is not the bottleneck.

The equation and a worked example

First in words:

Each cone constraint says: the length of a certain linear combination of variables must not exceed some constant times another linear combination. The network learns to rank these constraints by importance and predict which ones the optimal solution actually satisfies.

Then the compact form:

||A_i x|| <= b_i^T x + c_i for each cone constraint i

Every symbol:

What can go wrong

What can go wrong

Network has not seen the problem shape before. If the cone directions are unlike anything in the training set, the network may guess wrong about constraint activity.
Problem is at the boundary between feasible and infeasible. Near degenerate cases where tiny changes flip feasibility, the network may not find the exact boundary if training examples missed this region.
Constraints conflict in subtle ways. When constraints nearly contradict each other, the network must learn very precise tradeoffs; this requires careful training.
Done right: diversity in training. Train on many random cone problems of different sizes and shapes. Validate on held-out cones. This forces the network to learn the general cone logic, not memorize specific problems.
What a runnable demo should prove

What a runnable demo should prove

Build a graph network that takes a small second-order cone program as input and outputs whether it is feasible and what the best solution is if one exists. Generate 100 random cone problems: vary the number of variables, number of constraints, cone directions, and bounds. Train the network on 80 of them and test on 20 held-out problems. Compare the network's answers to a standard solver like CVXPY or Mosek by checking: does the network predict feasibility correctly, and for feasible problems, how close is its answer to the true optimum?

accuracy = number of correct feasibility predictions / 20 + average solution quality = mean( 1 - (network solution value - true optimal value) / true optimal value ) over feasible test problems

The network should achieve above 90% feasibility accuracy and produce solutions within a few percent of optimal on problems it has never seen, because it learned how cone structure predicts active constraints, not memorized specific problems.
