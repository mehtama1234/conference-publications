ReAugment: Targeted Few-Shot Time Series Augmentation

When you have very few examples of time series data, find the weak spots in training and automatically learn which transformations fix them.

Paper explainersAll themesTime Series & Sequential

Few-shot time series forecasting is hard because you have almost no data to learn from, so the model memorizes noise instead of learning the real pattern. ReAugment runs multiple different models on your limited data to see where they predict differently. That disagreement shows where the model's decision boundary is fragile. It then learns transformation rules that steer new examples into those shaky regions. When the model trains on many copies of the hard cases, it updates its decision boundary in those regions, because each training step nudges the model away from errors, and repeated exposure to the same region makes those nudges stick.

Zero assumption version

Few-shot time series forecasting gets stuck on noise

Time series forecasting means looking at historical numbers over time and predicting the next ones. For example: a temperature sensor records each hour, and you need to guess tomorrow's temperature. The problem: you have only a handful of examples. With so little data, the model does not learn the real pattern; instead it memorizes the exact noise in those few examples.

A beginner might try the obvious approach: collect a bit more data through simple copying—shuffle the existing rows, scale them slightly, or jitter the numbers a little. But this creates fake examples that still look like the original noise. The model does not get better at real forecasting because random augmentation is not targeted; it adds examples everywhere equally, which means it also doubles down on the noisy spots where the model was already confused.

The idea in one sentence. Identify the shaky regions where your model Zoo disagrees, then automatically learn which time-series transformations should land your augmented examples there to shore them up.

The algorithm as a flow

What it actually does

Collect a model zoo

Train several different time series forecasting architectures on your few examples.

Spot weak samples

Run all models on your training set and find examples where they predict very differently from each other—that is disagreement.

Set up the RL problem

For each weak sample, ask: what transformation (shift, scale, add noise) would land a new copy right here?

Optimize transformations

Use reinforcement learning to adjust the transformation rules, with a reward signal based on model zoo diversity.

Retrain the forecaster

Add the augmented examples to your dataset and retrain your final model on the larger, more diverse set.

What the paper changes

What the paper changes

The paper changes which data samples get augmented and how they are transformed. Instead of blindly augmenting everything the same way, it targets only the shaky samples (those where the model zoo disagrees) and learns custom transformation policies for each one.

the object it moves  =  Data augmentation targeting
The hidden quantity

The hidden quantity: Prediction disagreement

measured quantity  =  Prediction disagreement across model zoo

Prediction disagreement is a number that measures how much the different forecasting models in the zoo give different outputs for the same input sample. High disagreement on a sample means the models are unsure and confused on that patch of data. Low disagreement means they all agree it is straightforward.

The paper estimates this by running each model in the zoo on each training sample and measuring how different their predictions are from each other. Samples with the highest disagreement become the anchor points—these are the weak spots that need targeting.

Why it works

Why targeted augmentation works

With only a few examples, a model easily learns spurious correlations—noise that happens to match in your specific data. The model Zoo reveals where the model's logic is shaky by showing disagreement. Those are the regions in probability space (the set of all possible prediction patterns) where the model's decision boundary is fragile.

By using reinforcement learning to craft transformations that land new examples into these weak regions, you are explicitly asking the model to build a stronger decision boundary there. Each transformed example is real enough to be useful but shaped to address the exact gap the Zoo identified. This is more efficient than random augmentation because you are not wasting synthetic examples on regions the model already understands well. The RL formulation also avoids a tricky technical problem: if you try to nudge the transformation rules by running gradients (the mathematical signals for which way to change each number) backward through multiple forecasting models, those signals can shrink to nothing or explode to infinity. Here, instead, the reward signal comes directly from measuring how much the model Zoo disagrees—no backward flow through the forecasting models at all.

Math after the picture

The core equation

First in words:

Total penalty equals the average prediction error on the original examples plus a scaled term that penalizes moving away from regions where the model Zoo disagreed the most.

Then the compact form:

Loss = MSE(original_data) + lambda * mean( |disagreement_score[i] - new_example_i| )

Every symbol:

MSE(original_data)Mean squared error on the few training examples you started with
disagreement_score[i]How much the forecasting models disagreed on sample i
new_example_iA candidate augmented version of sample i
lambdaA weight that controls how much you prioritize hitting the disagreement regions
A tiny worked example
Original training set: 5 time series samples. All models agree on samples 1, 2, 4, 5 (low disagreement). Models disagree sharply on sample 3 (high disagreement = 8.0).
RL proposes augmentations: shift sample 3 by -0.5 (moving it in time-value space to a nearby shaky region).
New disagreement score for augmented sample 3: 7.5 (still in the risky zone). Distance penalty: |8.0 - 7.5| = 0.5.
If lambda = 2.0, that sample contributes 2.0 * 0.5 = 1.0 to the total. Samples 1, 2, 4, 5 stay untouched, contributing 0.
Result: the RL policy learns that shifting by -0.5 keeps you in the valuable weak region.

The penalty steers augmented examples into the exact parts of the data space where your model Zoo struggles most (the confusing regions), so the final model gets more practice on difficult cases and learns them correctly.

What can go wrong

What can go wrong

Model Zoo size too small. If your Zoo has only one or two models, disagreement is not informative. You need at least 3-4 diverse architectures to reliably spot weak spots.
RL reward signal is noisy. If computing model Zoo disagreement is unstable (e.g., models output different scales), the RL policy chases noise instead of real signal. You need stable, comparable predictions across the Zoo.
Transformations too aggressive. If the augmentation shifts samples so far that they no longer resemble real time series, the model learns artificial patterns that do not generalize to actual future data.
Done right. Maintain a Zoo of diverse forecasting models, measure disagreement as a clean variance metric, use RL with a stable reward, and keep transformations mild (within 1-2 standard deviations of the original variation in your data). The result is augmented data that sits in real weak regions without becoming fake.
What a runnable demo should prove

What a runnable demo should prove

Build a simple few-shot time series setup: generate 10-20 examples of a sinewave or temperature-like sequence with a small trend, then train a forecasting model (an LSTM or linear model). Measure its error on a holdout test set. Then implement ReAugment: train a Zoo of 3-4 different simple forecasters on the few examples, compute disagreement scores, use a basic RL loop (even random search works) to learn transformations that land new examples in high-disagreement regions, retrain your main forecaster, and measure test error again. The demo proves that targeted augmentation works by showing the model trained on ReAugment examples produces lower error on new time series than a model trained with random augmentation. The reason: random augmentation spreads examples everywhere, giving the model no extra practice on the confused regions. Targeted augmentation concentrates synthetic examples exactly where the Zoo disagrees. When the model sees many examples from the same hard region, each training step makes a small correction to the boundary, and because all those corrections point in the same direction (away from the errors on those cases), the boundary moves decisively in that region.

Generalization error = test_error(no_augmentation) - test_error(ReAugment)

The metric must show lower error on new unseen data, proving the model learned the real pattern, not just memorized the original few examples.
