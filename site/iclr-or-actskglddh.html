DataMIL: Selecting Data for Robot Imitation Learning

A robot learns to pick a subset of old training data that actually helps a new task, by training a separate model to predict which data is useful without having to run expensive robot experiments.

Paper explainersAll themesRobotics & Control

When a robot learns a new skill, it has access to lots of old training videos from past tasks. But some of that old data is irrelevant to the new skill—a video of pushing actually makes the robot worse at grasping. A naive approach is to try every possible subset of old data, retrain the robot on each one, and measure which subset works best. But that takes forever. DataMIL builds a cheap predictor that estimates which subsets will help because it trains on a fast surrogate loss (a measurement that correlates with real success but costs no robot time) instead of requiring expensive real robot rollouts to evaluate each subset.

Zero assumption version

The data selection trap

Robot learning from imitation means the robot watches human demonstrations and learns to copy those actions. As datasets grow larger and richer (collecting videos from hundreds of tasks), the robot has more to learn from. But new specialized tasks (e.g., grasping a coffee mug for a particular restaurant) need custom tuning. So teams want to mix old general data with new task-specific data.

A naive approach: test every subset of the old data by retraining the robot and measuring success on the new task. With thousands of data points, this means thousands of retrainings. A single retraining takes hours. A single robot test run takes time and money. This is prohibitively expensive.

The core problem. We need to know which old data helps the new task, but checking all subsets means retraining the robot hundreds of times and running real robot experiments each time to measure success—this is prohibitively expensive because a single retraining takes hours and a single real robot test costs money and physical time.

The algorithm as a flow

What it actually does

Step 1: Prepare raw data

Cluster old demonstrations into trajectories (sequences of actions). These are the candidates to score.

Step 2: Train the predictor

Build a separate model (the datamodel) that learns to estimate task performance as a sum of scores for each data point, using a surrogate loss function on new task data.

Step 3: Score each point

The datamodel assigns a score to each old data point. High score means helpful for the new task.

Step 4: Select top data

Keep only clusters with high scores. Discard clusters the datamodel rated as harmful.

Step 5: Co-train the final policy

Train the robot on a mix of new task data and selected old data via behavior cloning (copying the actions shown).

What the paper changes

What the paper moves

The paper changes the data that goes into training the final robot. Instead of using all old data or guessing which data is good, it selects a curated subset based on scores computed by a datamodel. Each data point gets a numerical score that predicts whether including it in training will raise or lower final task success. The final robot training uses only high-scoring data alongside the new task data.

The hidden quantity

The data importance score

measured quantity  =  how much each data point helps

DataMIL learns a hidden quantity: for each old demonstration, how much does it push the final policy toward high performance on the target task? This is a single number per data point, sometimes called the influence or importance weight. High means the data point is genuinely useful; low means it is noise or harmful.

The paper estimates this by training a separate model (the datamodel) on a surrogate loss function. The surrogate is built from task-specific data and approximates the true task performance (which is slow to measure) as a weighted sum of data-point scores. This avoids running expensive rollouts.

Paper reading. The paper computes importance scores using a metagradient estimator—a method that treats the robot's training process as a chain of mathematical operations that can be reversed to find how sensitive task performance is to each data point. This avoids precomputing scores by running expensive retraining experiments.
Why it works

Why selecting data before training works

The mechanism has two parts. First, the datamodel learns to predict task performance as a sum of scores (called influence scores or importance weights). This is possible because task performance does scale roughly linearly with data quality—good data adds to success, bad data subtracts. The datamodel is trained on a surrogate loss, which correlates strongly with true robot performance but is cheap to compute (no rollouts).

Second, by selecting only high-scoring data before training the final policy, the robot sees a cleaner signal. It trains on a curated mix: task-specific demos (the ground truth for the new skill) plus old data that the datamodel flagged as genuinely helpful. This mix is richer than new task data alone (more examples) but cleaner than using all old data (no confusing examples). The co-training of new task data and selected old data gives the robot the best of both worlds: specialization and breadth.

Math after the picture

The scoring equation

First in words:

Task performance is estimated as the sum of importance scores for each selected data point

Then the compact form:

M_hat(D_subset) = sum_i tau(z_i)

Every symbol:

M_hat(D_subset)estimated task performance for a subset of data
z_ithe i-th training example (a demonstration)
tau(z_i)the importance score of example z_i (how much it helps the task)
sum_iadd up the scores for all selected data points
A tiny worked example
Suppose we have 3 old data points and measure task performance.
Data point 1 (grasping similar object): tau = 2.0 (very helpful)
Data point 2 (pushing task, different): tau = -0.5 (harmful for grasping)
Data point 3 (grasping with different hand): tau = 1.5 (helpful)
M_hat(all three) = 2.0 + (-0.5) + 1.5 = 3.0
M_hat(without the harmful point) = 2.0 + 1.5 = 3.5
By discarding point 2, we improve estimated performance by 0.5 points.
The datamodel learns these tau scores from the training process itself.

Each data point gets a number that predicts its contribution to task success because the datamodel is trained on the surrogate loss, which correlates strongly with real task performance, so the learned scores match ground truth. Points with positive scores improve the task because including them in training pushes the robot toward correct behavior; points with negative scores pull the robot toward incorrect behavior.

What can go wrong

What can go wrong

Surrogate loss does not match true performance. If the surrogate metric (used to train the datamodel) does not correlate with real robot success, the importance scores become meaningless. DataMIL assumes the surrogate is a good proxy.
Overfitting the datamodel to seen tasks. If the datamodel is trained on the same tasks it later scores data for, it may favor data that matches the pattern of examples it saw during training and miss genuinely useful data that looks different because the robot has not learned to recognize what makes it valuable.
Linear assumption breaks down. The method assumes task performance is a sum of independent data-point scores. If data points interact in complex ways (e.g., two conflicting pieces of data cancel each other out), the linear model fails.
Done right. When the surrogate loss is chosen to correlate strongly with real task success, the datamodel is trained on many different tasks so it generalizes to new ones, and the data contributions are indeed roughly additive (not complex interactions), then DataMIL reliably identifies helpful data because the datamodel's predictions match ground truth.
What a runnable demo should prove

What a runnable demo should prove

Build a simple imitation-learning task: a simulated robot that must reach a target location. Collect two sets of old data: some from reaching tasks (helpful) and some from object-pushing tasks (harmful). Train a datamodel on a surrogate loss (e.g., distance to target, which is cheap to compute). Score each old data point. Show that the datamodel assigns high scores to reaching demos and low scores to pushing demos. Then co-train the final policy on new target data plus high-scored old data, and measure success rate. Compare against a policy trained on all old data, and against a policy trained on only new data.

success_rate = (number of reaching attempts that touch target) / (total attempts)

The curated policy (with selected data) should reach the target reliably. The all-data policy should fail or be inconsistent. The new-data-only policy should be slower to learn.
