DEAS: Detached Value Learning with Action Sequences

Instead of teaching a robot to decide one step at a time, group actions into short sequences and train a separate value judge that avoids overpredicting reward.

Paper explainersAll themesReinforcement Learning

Robots trained on offline data (recorded from past examples) struggle with tasks that require many steps to complete. DEAS fixes this by bundling actions into longer sequences and training a separate value judge that stays conservative. This reduces the problem from guessing a thousand steps ahead to guessing thirty.

Why long-horizon robot tasks trap offline RL

Offline RL trains a robot from past data without trying new actions in the real world. A naive approach is to teach the robot to pick one action per step, but a 30-step pick-and-place task means the value function (the judge of how good an action is) must predict reward 30 steps away, through the fog of a thousand possible futures. Even small errors snowball.

Standard offline methods use conservative tricks: penalize actions unlike the training data, or use a spread of return estimates to avoid overconfidence. But these tricks often leave performance on the table, especially when the data includes diverse successful strategies. Naively extending to multi-step predictions (n-step returns) usually makes things worse because the bias from stacked prediction steps overwhelms the benefit of looking ahead.

The bottleneck: Predicting value across many steps with limited offline data causes errors that compound.

The algorithm as a flow

What it actually does

Bundle actions

Group consecutive actions into sequences; a 30-step task becomes 8 sequence decisions.

Value function reads sequences

The value judge learns to score each sequence based on state and the bundled actions, not predictions.

Detach value from policy

Train the value judge on the actual offline data, ignoring what the policy predicts.

Stabilize multi-step returns

Accumulate rewards across the sequence steps, discounting near steps less than far ones.

Policy learns from honest value

Actor learns to pick action sequences the value judge rated highly in the data, without dragging it into speculation.

What the paper changes

What the paper changes

DEAS treats action sequences (bundles of steps) as the basic unit of decision, instead of single actions. The value function is trained on these sequences but kept separate from the policy—it judges the data as-is without feedback from the policy's new predictions.

the object it moves  =  Action sequences and value decoupling
The hidden quantity

The honest value estimate

measured quantity  =  How much to trust a sequence estimate

The hidden quantity is the in-distribution return: the real total reward an action sequence achieved in the recorded data. Unlike the policy, which tries to improve beyond the data, the value judge simply looks up and memorizes sequences that actually happened and scored well, because this keeps it grounded in facts instead of speculation.

The paper estimates this by taking the real returns from the offline dataset and training a neural network to predict them from state and sequence. If a sequence never appeared in the data, the value judge stays silent (or predicts conservatively), avoiding the overconfidence that kills offline RL.

Plain reading. The value judge learns a simple rule: in the data, high-reward sequences scored well, low-reward sequences scored poorly. For a new sequence close to the data, it guesses the return. For a sequence unlike anything in the data, it refuses to predict.
Paper reading. The value network is trained via a loss that predicts the actual return from the offline dataset, using categorical targets (binned return values) to handle the bias that comes from summing predictions over multiple steps. The network learns an implicit model of what sequences are in-distribution.
Why it works

Why detached value learning stops the overestimation spiral

The core trap of multi-step offline RL: when you ask a policy to improve beyond the training data, the value judge must predict what those new actions are worth. But the judge has never seen them—so it guesses. Each guess compounds with the next, and by step thirty the estimate is sci-fi. DEAS breaks this by training the value judge only on sequences that actually appeared, then giving the policy freedom to pick any sequence, but only rewarding it by looking up the value in the judge's learned table.

Mechanically: the policy and value function are trained separately. The policy uses behavior cloning (learning from expert demonstrations) or other methods to pick sequences. The value judge learns a map from state-plus-sequence to real reward, using the offline data only. When the policy picks a sequence the judge has not fully learned yet, the judge says 'I am uncertain' rather than guessing high. This uncertainty keeps both honest.

Math after the picture

The value training loss

First in words:

Loss = Huber distance between predicted return and actual accumulated return, summed over all sequences in the offline data, using distributional classification to handle multi-step bias.

Then the compact form:

L = sum_sequences Huber(Q(s_t, a_t:t+H-1; theta) - R_t:t+H-1)

Every symbol:

Q(s_t, a_t:t+H-1; theta)the value network, predicting return from state and H-step action sequence
R_t:t+H-1actual accumulated reward from the offline data (sum of discounted rewards over H steps)
Huber(...)robust error measure: quadratic for small errors, linear for large ones (ignores outliers)
Hlength of the action sequence in steps (e.g., 4 or 8)
thetathe value network weights
A tiny worked example
Sequence: grip -> lift -> move (H=3 steps)
Offline data shows: reward 1 (grip), reward 2 (lift), reward 3 (move). Total R = 1 + 0.99*2 + 0.99^2*3 ≈ 1 + 1.98 + 2.94 = 5.92
Value network predicts Q(state, sequence) = 6.5
Error = Huber(6.5 - 5.92) = Huber(0.58) ≈ 0.17 (small, so quadratic: 0.58^2 / 2 ≈ 0.17)
Update network to predict closer to 5.92 next time
If network predicted 9.0, error = Huber(9.0 - 5.92) = Huber(3.08) ≈ 1.08 (large, so linear: ~3 - 1 = more penalty but bounded). Network learns the data slowly, not shocked by outliers.

The value judge learns to predict the true offline return, not to dream up speculative returns. Multi-step rewards are real numbers from the data.

What can go wrong

What can go wrong

Sequence length too short. If the action sequence is only 1 or 2 steps, bundling provides no horizon reduction; errors still snowball. The paper experiments show H must be at least 4 to help, because with H equal to 1 or 2 the task still demands predicting 15 to 30 steps of separate decisions, each with error. Too short sequences treat long-horizon tasks as many separate problems, defeating the purpose.
Value judge trained on biased data. If the offline dataset is mostly failed attempts, the value judge will learn low values everywhere because it memorizes what the data shows. The policy then cannot improve, because it only sees poor returns in the training data and has no reason to pick any sequence. DEAS requires the data to include successful trajectories, not just random rollouts.
Discount factors set wrong. The paper finds that discount factors matter critically: intra-option (within the sequence) and inter-option (between sequences) must be set differently. Mismatched discounts re-introduce bias and instability in multi-step returns.
Done right. Train the value judge on real offline returns, use appropriate sequence length (4–8 steps for 30-step tasks), and set discount factors for the multi-step structure. The policy then has an honest critic and can learn reliably.
What a runnable demo should prove

What a runnable demo should prove

A demo should show: (1) a 20-step pick-and-place task where single-step IQL fails (success rate ~40%), (2) DEAS with 4-step sequences succeeds (success rate ~80%), and (3) the value function learns a smooth, confidence-aware map of what sequences are worth doing. You should see the policy's success rate climb steadily as the value judge learns, not jitter or crash as standard n-step offline RL does.

Success rate = (successful episodes / total episodes); Value stability = std-dev of value estimates for unseen sequences (should be small, showing honest uncertainty not false confidence).

The core proof: detached, data-driven value learning on action sequences beats both single-step and naive multi-step methods on long-horizon offline tasks, without the instability.
