CAMEL: Constant-Degree Graph Clustering from Incomplete Multi-View Data

Group items from partial pictures by organizing each view's hidden positions into tensors and tying them to a cheap-to-compute graph structure.

Paper explainersAll themesGraph & Geometric Learning

You have several incomplete pictures of the same group of items—say, documents described by topic words, content links, and author names, but some info is missing. A naive approach treats each picture separately and loses connections across pictures. CAMEL learns one hidden position (an embedding) per item per picture, then stacks these positions into a 3D block (called a tensor—just a way to organize numbers across multiple dimensions) to find clusters while keeping the math cheap to run.

Zero assumption version

Incomplete data from many viewpoints

In many real problems, you see the same group of items from different angles. A face-recognition system might see a face in color photos, infrared, and depth scans. A product-recommendation system might see users by their purchases, their friends, and their browsing history. But data is always messy—some sensors break, some measurements are missing, some records are incomplete.

A beginner would cluster (group) items using just the views that are fully measured, throwing away the rest. But that wastes information. Another beginner would impute (guess) the missing values, but guessing can introduce errors that mislead clustering. Worse, most clustering methods work by building an adjacency graph (a list of connections: item A connects to item B) and then running expensive math on it—typically a singular value decomposition (breaking the graph into simpler pieces). That decomposition costs time that grows with the square of the number of items, and it happens after clustering is done, so it is wasteful separation of concerns.

In one sentence. CAMEL jointly learns hidden positions for each item in each partial picture and organizes them into a 3D block (a tensor) to capture multi-view structure, while using a cheap graph instead of expensive lookup tables that cost time proportional to the square of the data size.

The algorithm as a flow

What it actually does

Receive multi-view partial data

Items described by multiple incomplete pictures; store known values, mark gaps.

Learn one hidden position per item per view

Optimize embeddings to reconstruct known values and respect geometric constraints from connectivity.

Build a fixed-degree graph

Connect each item to its nearest neighbors; use constant-degree instead of full adjacency matrix.

Stack embeddings into a tensor

Organize all learned positions (item, view, dimension) into a 3D block; optimize it to have low rank.

Cluster by distance

Concatenate embeddings across views and run k-means. Output: which cluster each item belongs to.

What the paper changes

What the paper changes

CAMEL learns the hidden positions (embeddings) and the connectivity structure jointly in one optimization, instead of treating them separately or using guessed values for missing entries. By using a fixed-degree graph instead of a full lookup table of all item pairs (called an adjacency matrix—just a table storing which items connect to which), the connectivity computation stays cheap.

the object it moves  =  Embeddings and connectivity, jointly
The hidden quantity

The connectivity degree matrix

measured quantity  =  Fixed-degree matrix (how many neighbors)

A connectivity graph is usually stored as an adjacency matrix (a table where row i, column j holds 1 if items i and j are neighbors and 0 otherwise). This table has size n times n (where n is the number of items), so even reading or updating it takes time proportional to n squared—expensive for large data.

CAMEL measures and approximates a degree matrix (a list of how many neighbors each item has) with a constant degree (every item gets the same small number of neighbors). This cuts the time cost from proportional to n squared down to just a fixed small number regardless of data size. The paper estimates this degree from the learned embeddings and how far apart items sit from each other (their local distances and neighborhood structure).

Why it works

Why coordinating embeddings and graphs finds better clusters

The core insight is that embeddings and connectivity should inform each other. If two items are nearby in embedding space (their hidden numbers are similar), they should also be neighbors in the graph. If the graph says they are neighbors, the embedding learning should pull their hidden numbers closer. This mutual reinforcement keeps both honest.

By organizing embeddings into a tensor (a 3D block) and constraining it to have low rank (few independent patterns), CAMEL forces patterns from different views to align. If item 5 appears as a bridge in View A and as a hub in View B, the tensor constraint discovers that commonality and reinforces it during learning. When you then run k-means on these aligned embeddings, the clusters naturally separate because both the views and the graph structure have pulled similar items close together in the embedding space.

The constant-degree trick keeps this efficient: instead of building an expensive full similarity table between all pairs, CAMEL only finds the fixed number of nearest neighbors for each item. This is fast to compute (each item checks its distance to a few others) and captures the local neighborhood structure well enough for clustering.

Math after the picture

How the paper balances three goals at once

First in words:

minimize reconstruction error plus graph smoothness penalty plus low-rank tensor constraint. In pseudocode: loss equals sum over all views of squared differences between known data and embedded predictions, plus penalty weight times sum of squared embedding differences between neighboring items in the graph, plus tensor regularizer times the rank-limiting term.

Then the compact form:

L = sum_v ||X_v^known - Reconstruct(E_v)||^2 + lambda_G sum_ij (||E_i^v - E_j^v||^2 if i,j neighbors) + lambda_T Tensor_Rank(E_1, E_2, ..., E_m)

Every symbol:

X_v^knownthe known measurements in view v (the non-missing data)
E_vthe learned embedding for view v (hidden positions for all items)
E_i^vthe embedding of item i in view v
lambda_Ghow strongly to penalize neighbors being far apart in embedding space
lambda_Thow strongly to enforce low-rank structure in the stacked tensor
Reconstructa function (e.g., linear) that predicts measurements from embeddings
Tensor_Ranka measure of how many independent patterns exist in the stacked embeddings
A tiny worked example
Suppose one view has 3 items with embeddings E = [[1, 2], [1, 3], [2, 4]]. The reconstruction error for known values might be 5.0.
Suppose the graph says items 1 and 2 are neighbors and items 2 and 3 are neighbors. The difference between E1 and E2 is [0, 1], squared length 1. The difference between E2 and E3 is [1, 1], squared length 2. Total smoothness penalty with lambda_G=0.5 is 0.5 * (1 + 2) = 1.5.
The tensor rank regularizer with lambda_T=0.3 might add 0.9 (example penalty for non-low-rank structure).
Total loss: 5.0 + 1.5 + 0.9 = 7.4. Optimization nudges embeddings to shrink this: moving E1 and E2 closer reduces smoothness cost; making embeddings more aligned across views reduces rank penalty.

The three terms pull embeddings toward three goals at once: fitting the observed data, respecting the graph's nearness, and staying coordinated across views through low-rank structure.

What can go wrong

What can go wrong

If constant degree is set too small. The graph becomes disconnected (items split into isolated components). Clustering then cannot find bridging items. Fix: tune the constant degree based on data density.
If too much data is missing. Embeddings cannot be anchored well to the known measurements. The optimization has too much freedom and embeddings may drift. Fix: methods work best when at least 30-50% of each view is observed.
If views have conflicting geometric structure. One view might cluster items by color and another by shape. The low-rank tensor constraint tries to align them, but it may over-compromise and blur both signals. Fix: add separate low-rank constraints per view before combining.
Done right. Choose constant degree to match local neighborhood density. Provide moderately complete views. Tune the low-rank penalty weight (how strongly to enforce aligned patterns across views) to balance global alignment with view-specific structure.
What a runnable demo should prove

What a runnable demo should prove

Build a synthetic dataset with 100 items in 5 known clusters, measured in 3 views. Make each view show the clusters clearly but differently (View 1 by spatial position, View 2 by color, View 3 by edge connectivity). Randomly delete 20% of View 1, 40% of View 2, and 50% of View 3. Run CAMEL with constant degree 5 and low-rank constraint. Compare against: (a) imputing missing values first, then clustering; (b) using only complete cases; (c) building the full adjacency matrix instead of constant-degree. Measure clustering accuracy (how many items end up in the correct group). Plot accuracy versus degree (how sensitive is the algorithm to degree choice). The demo makes it undeniable that CAMEL recovers clusters well despite missing data, because jointly learning embeddings and connectivity avoids guessing; uses less time than full-adjacency methods, because constant-degree avoids expensive all-pairs computations; and remains stable across degree choices in a reasonable range, because the tensor constraint and low-rank penalty anchor embeddings even as the neighborhood size changes.
