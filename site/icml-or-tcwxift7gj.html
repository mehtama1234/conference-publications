Mitigating Conversational Inertia in Multi-Turn Agents

Reduce the tendency to repeat the agent's own earlier replies by training preferences that favor fresher actions when the state is the same.

Paper explainersAll themesAgents & Tool Use

This paper studies a subtle multi-turn agent failure. After several turns, the model may start copying the style and action pattern of its own earlier responses even when the environment now calls for a different move. The paper names that problem conversational inertia and proposes Context Preference Learning, which prefers responses from shorter, less self-reinforcing contexts when the current state is otherwise the same.

Zero assumption version

Why long conversations can trap an agent in its own past

A multi-turn agent should use the growing conversation to gather more evidence from the environment. But the same history can become a trap because the model may treat its own earlier replies as examples to imitate rather than as actions that should be reconsidered.

That hurts exploration. If the agent keeps echoing its previous response pattern, it may stop trying new actions even after the environment shows that the old plan is failing. The paper studies this effect and asks how to bias the model toward lower-inertia actions without needing environment reward labels for every pair.

The paper's move in one sentence. Compare actions produced from shorter and longer contexts for the same state, then train the model to prefer the action that is less trapped by its own conversation history.

Five-panel picture

Those earlier replies can dominate because the model keeps seeing its own wording and action style.

3. The agent repeats itself
It keeps issuing the same kind of move even when the environment changed.

This is inertia because the model imitates its own past instead of responding to the present state.

4. Preference training reverses the bias
When the same state is shown, shorter-context actions can be preferred if they stay more open to new moves.

The method works by using context length as a source of preference pairs.

5. The agent explores again

Later actions become less repetitive because the model is trained to resist copying its own earlier replies.

The algorithm as a flow

What it actually does

Hold the state fixed

Construct comparisons where the environment state is the same so differences mainly reflect the conversation history.

Vary the context length

Ask the model for actions with shorter and longer histories because the longer history tends to carry more self-copying pressure.

Build preference pairs

Treat the lower-inertia action as preferred so the model can be trained without hand-labeled environment rewards for every case because matched short-context and long-context outputs already supply a comparison signal.

Train Context Preference Learning

Update the model toward lower-inertia actions because those actions leave more room to respond to fresh environmental evidence.

Manage context at runtime

Trim or structure the context so useful feedback stays available while extra self-repetition pressure stays lower.

What the paper changes

What the paper changes

The paper changes the agent's preference over candidate next actions. It tries to make the model value actions that are less driven by its own earlier replies when the present state does not justify repeating them.

the object it moves  =  the next-action preference inside a multi-turn agent
The hidden quantity

The hidden quantity

measured quantity  =  how strongly the next action is pulled by the agent's own earlier replies instead of the current state

The hidden quantity is self-copying pressure from the conversation history. You cannot read that pressure directly from one sentence, but you can infer it when the same state produces a more repetitive action under a longer context than under a shorter one.

That comparison gives the paper a practical training signal. If the shorter-context action reacts better to the current state, then the longer-context action reveals excess inertia because the extra history changed the action even though the state stayed fixed.

Why it works

Why comparing shorter and longer contexts gives a training signal

The core observation is that context length changes the amount of self-copying pressure even when the state is the same. That is useful because the method can harvest preference pairs from the model's own behavior instead of waiting for delayed environment rewards.

Context management then supports the learned preference at runtime. Keeping the most relevant environment feedback while trimming excess self-history helps because the agent still sees the current task evidence but sees fewer repeated traces of its own old plan.

Math after the picture

A compact inertia score

First in words:

One simple way to think about the method is to reward actions that respond to the present state and penalize actions that mostly repeat the prior conversation pattern.

Then the compact form:

action_score = state_fit(action, state) - inertia_cost(action, history)

Every symbol:

action_scorevalue of one candidate next action
state_fit(action, state)how well the action matches the current environment state
inertia_cost(action, history)penalty when the action is mainly driven by copying the earlier conversation
A tiny worked example
The state now shows that the first search path failed.
Action A repeats the old plan, so state_fit is 3 and inertia_cost is 5.
Action B opens a new search path, so state_fit is 8 and inertia_cost is 1.
Then action_score(A) = -2 and action_score(B) = 7.
Preference training should favor B because B reacts to the current evidence instead of copying the stale plan.

The paper uses preference learning rather than this exact formula, but the formula captures the tradeoff between present-state fit and self-copying pressure.

What can go wrong

What can go wrong

Shorter context is not always better. If important earlier evidence is removed, the agent can make a worse choice because the shorter context hid facts that the current state alone does not contain.
Preference pairs can be noisy. Two actions may differ for reasons other than inertia, so the training signal can be imperfect because context length is only a proxy for the true cause.
Some tasks need stable repetition. An agent should repeat a good plan when the environment still supports it, so anti-inertia training must not punish justified consistency.
Done right. The paper is useful because it turns a subtle conversational failure into a trainable preference signal.
What a runnable demo should prove

What a runnable demo should prove

Build a multi-turn search task where the environment occasionally reveals that the current plan failed and a new plan is needed. Generate candidate actions for the same state under shorter and longer conversation histories, then train one agent with those preference pairs and leave another agent unchanged.

The demo should show that the trained agent changes course sooner after new evidence appears because it is less trapped by its own earlier replies, while the unchanged agent keeps repeating stale actions for longer.
