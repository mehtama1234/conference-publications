Don't Pass@k: A Bayesian Framework for LLM Evaluation

Replace the flaky Pass@k evaluation method with Bayesian posterior estimates that give stable rankings with far fewer model runs.

Paper explainersAll themesDatasets & Benchmarks & Evaluation

When you test a large language model (LLM) on a reasoning problem (like AIME math), you run it multiple times and count how many times it solves it correctly. The standard way to report this is Pass@k, a formula that tries to estimate the true success rate from a small sample. But Pass@k is unstable because each run is random, so a different set of random seeds can easily give a different count of successes, flipping which model looks best. This paper replaces Pass@k with a Bayesian method that builds confidence bands around each model's estimated true success rate by combining the observed data with a starting belief, so you can see which ranking differences are real signal and which are just unlucky random variation.

Zero assumption version

Pass@k is unreliable and wastes compute

When you evaluate an LLM on reasoning problems, you cannot give it just one try—language models are random, so the same model gives different answers each time. So you run it many times. Pass@k is the standard formula: if you run the model k times and it solves the problem at least once, that counts as one success. The formula tries to back out what the model's true success rate is from how many times it succeeded.

But Pass@k has a fatal flaw: the rankings are unstable. If you run the same models again with a different random seed, the ranking of which model is best often flips. The reason is simple: with a small number of runs, random luck dominates. One model might have solved the problem twice in a row by chance (when its true rate is really 20%), while an actually-better model (with true rate 35%) happened to fail both times by bad luck. Because small samples are noisy, you need many runs to separate true skill from random variation, and many runs means expensive GPU compute.

A beginner might try to ignore this by just looking at the raw number of successes out of the runs, but that is even worse—you lose all sense of what the true success rate might be. Another approach is to take the average score, but that suffers the same instability problem as Pass@k.

In one sentence. The paper models each model's success rate as a probability, uses a starting belief (a prior) to add context, and computes confidence bands around the updated belief (the posterior), so you can see which models are really different and which look different just by luck.

The algorithm as a flow

What it actually does

Collect outcomes

Run the model k times on a problem. Record success or failure (or grade on a rubric).

Fit a Bayesian model

Treat the observed outcomes as data from a random process with an unknown true success rate. Place a Dirichlet prior (a smooth initial guess) on that rate.

Compute the posterior

Combine the prior and the data to get a posterior distribution—the updated belief about the true success rate, accounting for both what you knew before and what you just observed.

Extract the credible interval

From the posterior, read off the central estimate and the confidence band (e.g. 95% credible interval: the true rate lies between 30% and 50%).

Compare models

If two models' intervals do not overlap, they are statistically different. If they overlap, the difference is likely noise.

What the paper changes

The object it changes: how you estimate the true success rate

Instead of using a formula (Pass@k) that looks only at the count of successes, the paper uses Bayesian updating (a way to combine prior belief with observed data) to estimate the underlying success probability and its uncertainty.

the object it moves  =  success-rate estimation
The hidden quantity

The hidden quantity: the true success probability

measured quantity  =  underlying success rate

Every model has a true, fixed success rate on a problem (the fraction of random runs that will succeed, if you ran it infinitely many times). You can never observe this directly—you only see a finite sample. The paper estimates this hidden rate and, most importantly, the confidence band around it.

The paper measures it using Bayesian inference: it treats the observed successes and failures as data from a probability distribution (a Dirichlet distribution, a flexible way to model probabilities). The posterior is the updated belief about that hidden rate given the data.

Why it works

Why it works: Bayesian inference separates signal from noise

A small number of successes can come from either a high true rate (high skill) or random luck from a low true rate. Bayesian updating solves this by fitting a starting belief (a prior—a smooth starting guess—to the data. A uniform prior (no preconceived idea) recovers behavior like average accuracy but with honest uncertainty bands. A more informed prior (e.g. from other models or historical data) can shrink the confidence band if appropriate.

This stabilizes rankings because the credible interval captures the realistic range of the true rate. Two models with overlapping intervals are statistically indistinguishable (their difference is likely noise). Two with non-overlapping intervals are genuinely different (the signal is strong enough to outshine luck). This decision rule is objective, unlike Pass@k which can flip on a single run. And because the posterior converges smoothly and predictably to the truth as data accumulates, you reach reliable comparisons with far fewer runs than Pass@k.

The Dirichlet-Multinomial posterior

First in words:

Prior probability distribution on success rate is Dirichlet. After observing successes and failures (the data), the posterior is also Dirichlet (a conjugate pair). The posterior mean is the updated estimate of the true rate, and the posterior variance gives the confidence band.

Then the compact form:

Posterior mean = (alpha_success + num_successes) / (alpha_success + alpha_failure + num_trials)

Every symbol:

alpha_successprior weight for success (usually 1)
alpha_failureprior weight for failure (usually 1)
num_successesobserved successes in the k runs
num_trialstotal number of runs (k)
Posterior meanthe Bayesian estimate of true success rate
A tiny worked example
Model A: observed 2 successes in 10 runs. alpha_success=1, alpha_failure=1 (uniform prior).
Posterior mean = (1 + 2) / (1 + 1 + 10) = 3 / 12 = 0.25 (25% success rate).
Model B: observed 3 successes in 10 runs.
Posterior mean = (1 + 3) / (1 + 1 + 10) = 4 / 12 ≈ 0.33 (33% success rate).
With 10 samples each, the credible intervals overlap slightly (e.g. A: 10-45%, B: 15-55%).
After 100 runs: A gets 25 successes (mean = 26/102 ≈ 25.5%), B gets 35 successes (mean = 36/102 ≈ 35%).
Now the intervals are tight and clearly separated: B is genuinely better.

As you collect more runs, the posterior pulls tighter around the observed rate, and differences in true rates become unmaskable.

What can go wrong

What can go wrong

Mismatched starting belief. If you use a very strong starting belief (claiming the success rate is 50% from the start) but the true rate is 10%, the method will converge slowly. The starting belief fights the data. Use a neutral starting belief if you have no domain knowledge.
Grading rubric mismatch. If you switch from binary (success/failure) to graded (0-4 points) mid-evaluation, the prior weights and posterior shape change. Be consistent about what you are measuring.
Tiny sample sizes. Even Bayesian inference needs some data. With only 1 or 2 runs, the posterior is so wide it is useless. The paper shows the method shines at 10-50 runs per model.
Done right: uniform prior, consistent rubric, 10-100 runs per model. Bayesian evaluation becomes reliable and stable, and you know exactly when differences are signal versus noise.
What a runnable demo should prove

What a runnable demo should prove

Build a small benchmark with three models and a problem that each solves at known rates (e.g. Model A: 25% true rate, Model B: 35% true rate, Model C: 26% true rate). Run each model k times with random seeds (start with k=10, then k=30, then k=100). Compute the Pass@k ranking and the Bayesian posterior intervals for each model at each k. Plot the rankings and intervals as k grows.

stability = fraction of evaluations where the ranking does not change from the previous k value. Higher is better.

The demo must show that Bayesian intervals shrink and separate faster than Pass@k narrows down (because the posterior tightens predictably as data arrives), and that overlapping Bayesian intervals at small k correctly predict models are truly similar, while separated intervals at large k correctly identify which model is truly better.
