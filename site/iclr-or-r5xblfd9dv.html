State-Space Models as Data-Specific Neural Representations

Fit one small neural representation to one visual item by using a state-space model to store how a continuous signal evolves across coordinates, then decode any queried location from that learned state.

Paper explainersAll themesRepresentation & Self-Supervised Learning

A data-specific neural representation stores one image, video, or other visual item inside the weights of a small model instead of storing pixels directly. The central difficulty is that the stored model must reconstruct many queried locations while staying compact, so it needs a structured way to relate neighboring observations instead of memorizing each sample independently. This paper argues that a state-space model, meaning a sequential model that updates an internal state as it reads ordered observations, is a good fit for that job because it can summarize how an underlying continuous signal changes across position while using a fixed-size memory.

Zero assumption version

Compact storage fails when the model ignores signal structure

Suppose you want to store a single visual item inside a neural network. The network sees sampled observations: pixel colors at grid locations, frame values at time stamps, or measurements at coordinates. Those observations come from an underlying continuous signal, but the computer only receives discrete samples. If the model treats every sample as unrelated, it wastes weights in the stored model by repeating local facts that nearby samples already imply.

A small multilayer perceptron can fit one image, but it often needs many stored weights or long optimization because it has to learn continuity, frequency content, and local correlation all at once. Compression gets worse because the model spends capacity relearning the same smooth transitions and repeated textures. The paper asks for a representation whose internal computation already matches the way sampled signals evolve from one coordinate to the next.

Core issue. Data-specific neural storage is only compact when the model summarizes how the signal changes across coordinates instead of memorizing isolated samples.

The algorithm as a flow

What it actually does

Choose an ordering of observations

Arrange pixel or signal samples into a sequence so nearby coordinates or times stay close together in the reading order.

Run a state-space encoder

A state-space model reads the sequence and updates a fixed-size hidden state that summarizes what has been seen so far.

Store the learned weights

Optimize the learned weights for this single datum until the state dynamics and decoder can reconstruct its observed samples.

Query arbitrary coordinates

Given a coordinate, the decoder uses the learned representation to output the signal value at that location.

Trade size against fidelity

Because the state dimension is fixed, shrinking the representation forces the model to keep only the most predictive structure.

What the paper changes

What the paper changes

The paper changes the backbone used for data-specific neural representations. Instead of relying only on a generic coordinate network, it inserts a state-space model so the representation is built around state updates from one observation to the next. That matters because the state update is where compactness is won or lost: if the state can carry forward only the information that predicts later samples, the stored model needs fewer learned weights to achieve the same reconstruction.

The hidden quantity

The hidden quantity: predictive state

measured quantity  =  predictive state

The predictive state is the model's compressed summary of the signal after reading part of the observation sequence. It must preserve enough information to reconstruct future or queried values, but it should discard details that are redundant once local continuity, repeated texture, or long-range structure are already encoded.

Training estimates this state indirectly. The optimizer changes the state-space transition and decoder until a small state can explain the observed samples with low reconstruction error. If the state is too small, high-frequency detail disappears first because the summary cannot carry enough information forward. If the state is large enough, it stores both coarse structure and the local corrections needed for sharp reconstruction.

Why it works

Why a state-space model helps a single-datum representation

A state-space model helps because it imposes a disciplined computation: read one observation, update the state, move on. That pushes the representation toward sequential sufficiency. The state after sample 200 must already contain whatever sample 201 and later samples will need, because there is no second chance to reread earlier observations unless that information was carried forward.

This is exactly the pressure a compact representation needs. Many visual signals are locally correlated, so a later sample is partly predictable from earlier nearby samples. The state update can store edges, periodic components, and slow drifts once, then reuse them many times during decoding. A plain coordinate network can also learn these patterns, but it must encode them only through static weights. The state-space route uses learned weights more efficiently because it stores reusable dynamics in the transition itself.

The method also remains modality-agnostic as long as the datum can be written as ordered observations. An image can be scanned across coordinates, a video can be scanned across space and time, and another continuous signal can be scanned along its domain. The mechanism is the same in each case: compress the evolving structure into a state and decode from that compact summary.

Math after the picture

State update plus reconstruction loss

First in words:

At each ordered sample, the model updates its hidden summary from the previous summary and the current observation. Training then minimizes reconstruction error so the final representation can reproduce the original signal.

Then the compact form:

h_t = SSM(h_{t-1}, x_t); y_t = Dec(h_t, c_t); loss = mean over t of ||y_t - target_t||^2

Every symbol:

h_thidden state after reading sample t
SSMthe state-space transition that updates the hidden state
x_tthe observed sample read at step t
c_tthe coordinate queried at step t
y_tthe model's reconstructed value
target_tthe true value of the datum at that coordinate
Decthe decoder that maps the learned representation to output values
A tiny worked example with four ordered samples
Suppose the signal samples are read left to right with values 0.1, 0.2, 0.8, 0.9. After seeing 0.1 and 0.2, the state mostly records a smooth low-valued region.
When the third sample jumps to 0.8, the state update must record an edge because later values are now predicted from a different regime. Without storing that change, the decoder would keep outputting low values.
After the fourth sample 0.9, the decoder can reconstruct the right side accurately because the state already carries both the earlier smooth region and the edge transition.
Compression appears when one stored transition explains many future samples. The model does not need separate learned weights for each low-valued pixel and each high-valued pixel.

The formula is simple, but the important point is that the hidden state is the bottleneck. Reconstruction improves only if the transition learns which parts of the signal deserve space inside that bottleneck, because only information carried through the state can influence later decoded values.

What can go wrong

What can go wrong

Bad sample ordering. If the observation order breaks local continuity, the state update cannot exploit neighborhood structure. Reconstruction then falls back toward memorization because successive samples no longer predict one another.
State too small for the signal bandwidth. If the hidden state has too little capacity, fine detail and fast transitions disappear first because the model cannot carry enough information forward through the sequence.
Decoder too weak. Even with a useful state, reconstruction fails if the decoder cannot turn that summary into accurate coordinate values. The bottleneck then shifts from storage to readout.
Done right. Choose an ordering that preserves signal continuity, a state size matched to the datum complexity, and a decoder strong enough to read the stored summary. Then the representation stays compact because the transition keeps reusing the same learned dynamics.
What a runnable demo should prove

What a runnable demo should prove

Take a small grayscale image and convert it into ordered coordinate-value samples. Train two per-image models: a baseline coordinate multilayer perceptron and a state-space representation with the same rough learned-weight budget. For both, measure reconstruction error, learned-weight count, and how the error changes as you shrink the hidden size.
