Dywave: Event-Aligned Dynamic Tokenization for IoT Signals

Break time-series signals at natural event boundaries using wavelets, then compress boring stretches to shrink the tokens the model must read.

Paper explainersAll themesTime Series & Sequential

IoT sensors pump out continuous measurements that bounce around chaotically (non-stationary) and contain patterns at many scales. When you feed these raw signals to a machine learning model, it wastes time and memory reading every single measurement, including the boring stretches between events. Dywave carves the signal at natural event boundaries and then compresses the quiet parts, so the model reads a shorter sequence (fewer chunks to process) but misses nothing important because the events—the actual changes that matter—are still intact.

Zero assumption version

Naïve chunking wastes time on boring stretches

Sensors stream data constantly: accelerometers tick every millisecond, microphones record every audio frame, thermometers sample every few seconds. A naive tokenizer (a tool that converts continuous data into chunks the model can read) treats all measurements the same: each sensor sample becomes one chunk that the model must process, in order. So if the sensor goes quiet for 10 seconds, the model still reads 10,000 chunks of barely-moving numbers.

The trouble: these signals are non-stationary (they bounce around unpredictably) and multi-scale (important events happen at different speeds—a touch might last 100 milliseconds, a heartbeat 1 second, a mood shift 30 seconds). A fixed tokenization scheme misses the signal's real structure. The model reads noise and wastes computation.

In one sentence. Dywave breaks the signal at natural event boundaries (using wavelets to spot them), then compresses the calm parts, so a model reads fewer tokens and stays accurate.

The algorithm as a flow

What it actually does

Wavelet decomposition

Break the signal into frequency layers—high frequencies catch fast jiggles, low frequencies catch slow drifts.

Event boundary detection

Scan the decomposed layers for places where energy changes sharply; those are event edges.

Segment construction

Split the original signal at those boundaries into chunks, each chunk represents one semantic event.

Adaptive compression

For each segment, select a few representative measurements (highest-energy or most-changing) and discard the rest.

Concatenate tokens

Stack the selected measurements in time order; feed to the model. Result: 75% fewer tokens on average.

What the paper changes

What changes: the input token sequence

The paper changes which measurements get tokenized. Instead of every sensor sample becoming a token, only the ones at event boundaries or with the highest energy do. The token sequence shrinks by up to 75%, but the semantic content (the actual events) is preserved.

The hidden quantity

Event-boundary position: the hidden quantity the paper measures

measured quantity  =  event boundary locations

An event boundary is a moment in time where the signal's character changes sharply—a tap, a tone, a motion shift. It is not marked in the data; you have to infer it. The paper measures these boundaries using the wavelet decomposition (which decomposes the signal into frequency layers), then scans where the energy in those layers spikes. A spike in energy means something physical just happened.

Dywave estimates event boundaries by looking at where the high-frequency and low-frequency layers have the largest shifts in energy. If the signal's texture changes, the wavelet layers feel it before any single sample does, so the algorithm catches event boundaries reliably even when the signal is noisy.

Why it works

Why it works: preserving the signal structure while shrinking the token count

A wavelet is a tiny wiggly shape that you slide along the signal to measure how much the signal wiggles at each position and frequency. Wavelets at different scales catch different behaviors: wide wavelets catch slow drifts, narrow wavelets catch sharp spikes. When you apply wavelets to the sensor signal, you get layers showing which frequencies are alive at each moment. If a layer suddenly gets loud, something physical changed.

Dywave uses those layers to find event boundaries: places where the signal's character shifts. Once it marks the boundaries, it splits the signal into segments (one per event, plus one per quiet gap). Within each segment, it picks a few representative measurements—the ones with the most energy—and throws away the rest. The model then sees only those kept measurements, ordered in time.

Why does this work? Because the important structure is in the event itself—the spike, the change in tone, the acceleration. The boring part is the stretches where nothing happens. By keeping the high-energy measurements at the events and merging the quiet stretches into single tokens, Dywave preserves all the information the model needs (the events) while dropping the information it doesn't (the silence). The model still learns to recognize activity because the events are intact; it just doesn't waste computation on thousands of copies of the word 'nothing happening.'

The core idea in equations

First in words:

Compress each segment by selecting the top K samples by energy (where energy is the squared amplitude) and merging the rest into a single averaged token.

Then the compact form:

E_i = sum_j |x_i(t_j)|^2 ; selected = argTop(E, K) ; x_compressed = [x(t_s) for t_s in selected] + [avg(x(t_o)) for t_o in others]

Every symbol:

E_iTotal energy in segment i (sum of squared measurements)
x_i(t_j)Sensor value at time t_j in segment i
KNumber of high-energy samples to keep per segment
selectedIndices of the K samples with largest energy
x_compressedFinal token sequence (selected samples plus averaged remainder)
A tiny worked example
Segment 1: 10 raw measurements [0.1, 0.2, 2.1, 2.0, 1.9, 0.3, 0.1, 0.2, 0.1, 0.0]. Choose K=3.
Energy per sample: [0.01, 0.04, 4.41, 4.00, 3.61, 0.09, 0.01, 0.04, 0.01, 0.00].
Top 3 by energy: samples 3,4,5 (energies 4.41, 4.00, 3.61; values 2.1, 2.0, 1.9).
Remaining 7 samples average: (0.1+0.2+0.3+0.1+0.2+0.1+0.0)/7 = 0.11.
Compressed segment: [2.1, 2.0, 1.9, 0.11]. Token count shrunk from 10 to 4 (60% reduction).

What can go wrong

What can go wrong

Wavelet choice matters. If you pick the wrong wavelet shape (e.g., a wavelet tuned for fast spikes when the data has slow drifts), the boundary detector misses real events. The paper uses Morlet wavelets, which work well for general sensor data, but for extremely specialized signals (e.g., seismic waves) a different wavelet might be needed.
Events can be close together. If two physical events happen very quickly (e.g., two taps within 50 milliseconds), the wavelet layers might not separate them, and the algorithm could merge them into one boundary. The model then loses information about which tap came first.
Outliers can create fake boundaries. A single noisy spike (sensor glitch, electromagnetic interference) can set off the wavelet layers and create a false event boundary. If the model trusts that fake boundary, it might learn spurious patterns.
Done right. The paper tests on five real-world datasets (activity recognition, stress assessment, object detection) and shows 75% token reduction with 12% accuracy gain on average. It also tests on domain shifts (training on one device, testing on another) and shows the accuracy stays higher than fixed tokenization when data comes from a different device—suggesting the event-boundary structure is real and generalizes.
What a runnable demo should prove

What a runnable demo should prove

Build a simple activity classifier: take accelerometer and gyroscope data from a wearable (e.g., a phone during walking, running, or standing still), split it with naive fixed-window tokenization and with Dywave, feed both to the same neural network model, measure accuracy and token count on held-out activities. The demo should show that Dywave achieves similar or better accuracy while using 50–70% fewer chunks (because events are preserved while silence is discarded), and inference runs noticeably faster because the model processes fewer inputs. Also measure what happens if you test on data from a different phone model (domain shift)—Dywave should degrade less because the event-detection method generalizes better than fixed chunking.

The point is that by respecting the signal's natural structure (events are sparse, silence is cheap), you can read the data faster and let the model focus on real patterns.
