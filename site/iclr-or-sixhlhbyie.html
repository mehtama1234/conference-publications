Web-CogReasoner: Knowledge-Induced Reasoning for Web Agents

Web agents reason better when taught structured knowledge in three layers: what things are, how they work, and how to use them.

Paper explainersAll themesAgents & Tool Use

Web agents—bots that click and type to complete tasks on websites—struggle because they lack the organized knowledge humans have. This paper argues web agents need three kinds of structured knowledge taught in stages: facts about what exists, concepts about how things work, and procedures for actually doing things. The paper builds a dataset from 14 real websites, trains an agent called Web-CogReasoner using step-by-step reasoning where each step explicitly cites a fact or concept, and shows it outperforms existing agents, especially on new unseen tasks because the abstract concepts transfer.

Zero assumption version

Web agents without structured knowledge fail on reasoning tasks

A web agent is a software bot that sees a website, reads the page layout, and clicks or types to complete a task. Existing agents see raw pixels and try to reason on the fly, like a person dropped into a foreign city with no map or street signs. They can solve simple click-here tasks, but when a website has many pages, conditional logic, or requires understanding how pieces relate, they get stuck. They have no durable knowledge to anchor their decisions to.

A beginner might try to solve this by giving the agent a written description of every website page before it acts. But that scales poorly—websites are huge, pages look different each time they load, and a flat list of facts does not teach the agent how to think. The agent ends up making the same blind guess repeatedly.

The fix in one sentence. Teach the agent three layers of knowledge—facts, concepts, and procedures—in a deliberate order, then anchor each reasoning step to that knowledge.

What the paper changes

What the paper changes: knowledge layers in training order

Instead of throwing all data at a web agent and hoping it learns, this paper teaches in stages: first isolated facts, then concepts, then procedures grounded in both. Each stage has its own training data and objective.

the object it moves  =  training data layers and order
The hidden quantity

The hidden quantity: knowledge structure maturity

measured quantity  =  knowledge layers present and used

This paper measures what it calls the knowledge structure of a web agent—how many layers of knowledge it actually holds and can use. This is not one number but three: does the agent know facts (what is on the page), concepts (how things relate), and procedures (how to chain actions). The paper estimates this by checking if the agent can successfully reason through tasks that require each layer. A task needing only facts is easy; a task needing all three layers together is hard.

The paper operationalizes this through step-by-step reasoning outputs: if the agent explicitly writes out which fact or concept justifies each action, and if that reasoning is grounded in the training data, the knowledge is truly there. Without this anchoring, the agent is just pattern-matching.

Why it works

Why this works: layered teaching creates durable anchors

Human reasoning does not happen all at once. We first learn what exists (facts), then how things work (concepts), then how to solve real problems (procedures). Teaching a web agent the same way gives it stable anchors. When the agent later sees a new website or task, it can reason from these anchors instead of starting from scratch, because the anchors are abstract enough to apply to any website, not specific to one site.

Here is the causal chain: First, the agent memorizes facts—UI elements, labels, their positions. This creates a vocabulary it shares with the training data. Second, in Phase 1 training, the agent learns concepts by seeing repeated patterns: a search bar always leads to results after typing (input causes output), buttons always open menus when clicked (action causes visibility change), pages always flow forward (one page leads to another). These concepts are abstract patterns that repeat across different websites, so the agent picks them up from the data. Third, in Phase 2, it learns procedures: when given a goal, chain the concepts together step-by-step, and write out your reasoning tied to a concept each time. This step-by-step writing forces the agent to stay honest. If it invokes a concept that was never in the training data, the reasoning breaks. By requiring explicit reasoning anchored to the knowledge layers, the paper prevents the agent from hallucinating or guessing.

How the three layers feed each reasoning step

First in words:

reasoning_step = cite_fact + apply_concept + decide_action

Then the compact form:

P(action_t | task, screen) = sum_k w_k * P(concept_k | state_t) where concept_k is grounded in factual_knowledge

Every symbol:

action_tthe click or type at step t
taskthe goal the user stated
screenthe current webpage pixels
concept_ka trained concept like trigger menu or find results
w_kweight on how relevant that concept is
factual_knowledgethe facts memorized in Phase 1
A tiny worked example: finding an Apple Store
User goal: Find Apple Stores near ZIP 90028.
Screen shows Apple website homepage.
Step 1 fact: A search bar is on the page. Concept: search bars find things. Weight: 0.8. Decision: Type the ZIP code.
Step 2 screen shows results. Fact: A stores link is labeled Find a Store. Concept: labeled links open pages. Weight: 0.9. Decision: Click Find a Store.
Step 3 screen shows a form. Fact: A text field is labeled ZIP code. Concept: text fields accept input. Weight: 0.8. Decision: Type 90028.
Each step ties a fact on the screen to a learned concept to produce an action. Without that reasoning, the agent is blind.

The equation shows that each action is a weighted sum of concepts, and each concept is grounded in facts the agent learned during Phase 1.

What can go wrong

What can go wrong

Phase 1 facts taught wrong. If the agent memorizes facts that do not transfer—like exact pixel positions instead of semantic labels—Phase 2 and 3 will fail. The whole stack collapses.
Concepts are too specific. If Phase 2 learns narrow patterns tied to specific websites, concepts do not transfer to new sites. The agent needs abstract concepts like trigger navigation or find results, not website-specific patterns.
Reasoning step is not truly grounded. If the agent writes reasoning that sounds good but does not actually cite a fact or concept from training, it is hallucinating. The paper prevents this by requiring explicit citations.
Done right. Facts are semantic (button labeled X), concepts are abstract (buttons open menus), procedures chain them step-by-step with explicit reasoning. Transfer to new sites becomes reliable.
What a runnable demo should prove

What a runnable demo should prove

Build an agent trained on one set of 14 websites. Then show it a website from that set, and a completely new website never seen during training. Run the same task on both. Compare the step-by-step reasoning outputs. On the trained website, count how many reasoning steps cite facts and concepts from the training data. On the unseen website, do the same. The paper's claim is that the unseen website will still use the learned concepts correctly, because they are abstract enough to transfer.

transfer_strength = (unseen_site_success_rate - random_baseline) / (trained_site_success_rate - random_baseline)

The demo makes impossible to miss: abstract structured knowledge transfers to new sites; raw pattern-matching does not.
