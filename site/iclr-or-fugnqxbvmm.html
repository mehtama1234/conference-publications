REMem: Reasoning with Episodic Memory in Language Agent

A language agent remembers concrete events linked to time, then reasons step-by-step through them using a toolkit instead of just looking up facts.

Paper explainersAll themesAgents & Tool Use

Imagine a conversation where someone says 'I fixed the fence last Sunday, then bought 3 cows from Peter on Jan 17th.' Later, you are asked 'How many animals did I get after fixing the fence?' A human would picture the sequence, spot that the cows came after the fence, and count them. Current AI agents struggle because they store only semantic facts (Peter gave cows) without the time-glue that connects when things happened. REMem solves this by building a time-aware memory graph during setup, then using a multi-step agentic retriever with curated reasoning tools to walk through the timeline and reason across linked events.

Zero assumption version

Current agents cannot reason about when things happened

Today's AI agents remember facts in two broken ways. Either they store facts in the model's weights (parametric memory), which cannot adapt to new conversations or specific experiences. Or they use retrieval systems (RAG) that work like a filing cabinet: you ask for 'cows,' they hand you every document that mentions cows. Both miss the story of events unfolding over time.

A naive approach would be to list all facts and ask the model 'which happened first?' But facts without timeline glue get scrambled. Asking 'How many animals after the fence?' fails because the retriever cannot see that fence and cows are linked by a temporal sequence, only that both are about farm activity. Multi-step questions—ordinal queries (which came first), counting across time, event-to-event reasoning—break completely.

The problem in one sentence. Agents need to store events with their timestamps, then reason step-by-step through the timeline to answer questions like 'How many cows arrived after the fence?'

The algorithm as a flow

What it actually does

Offline: Build the memory graph

Convert all past conversations into nodes (events, facts) and edges (time-links, entity-links, causality).

Offline: Anchor events to a timeline

Every event carries a timestamp or temporal anchor so 'Sunday' and 'Monday' are real markers on a line.

Online: Agent starts with a semantic search

For 'How many animals after fence?' the agent retrieves likely candidate events using embeddings (word-meaning search).

Online: Refine with lexical search and graph tools

The agent then uses exact text-matching and graph tools to walk from one event to neighbors and collect the full chain.

Online: Reason and answer

Having assembled the sequence, the model counts or reasons over linked events to form the final answer.

What the paper changes

What the paper changes

Most memory systems store either a bag of facts or a knowledge graph with no time dimension. REMem shifts from flat retrieval to a time-grounded hybrid graph—a structure where every event carries its temporal anchor (a date, a sequence marker) and facts are linked both by meaning and by when they occurred.

the object it moves  =  time-grounded memory graph
The hidden quantity

The hidden quantity: event coherence through temporal structure

measured quantity  =  temporal coherence score

The core hidden thing the paper measures is whether a memory system can link events by when they happened. Most retrieval systems score relevance as 'how similar is this text to the query?' (a semantic similarity number between 0 and 1). REMem adds a second signal: 'are these events connected on the timeline in a coherent order?' For example, if the query asks about 'animals after fence,' the system should reward retrieving cow-event and fence-event in the right temporal order, not random order.

The paper operationalizes this by measuring exact-match accuracy and reasoning scores (LLM-as-a-judge) on tasks that demand temporal reasoning: Test of Time (ordinal queries like 'which event came first'), Complex-TR (multi-hop temporal reasoning), and others. A higher score means the agent correctly traced the timeline and found the right causal or temporal sequence.

Why it works

Why it works: building and reasoning over a time-grounded graph

The mechanism has two parts. First, offline indexing: REMem extracts events from conversation history and builds a hybrid graph where each event-node carries a timestamp or temporal anchor. 'Sunday fence' is not just tagged 'fence' but 'fence-on-Sunday.' Facts are also grounded: 'Peter gave 3 cows' becomes 'Peter-gave-3-cows-on-Jan-17,' tied to the timeline. Edges link events by time (Monday follows Sunday, stored as a timestamp order), by entity (both involve the farm, so they are connected and the agent can jump between them), and by causality (fence leads to willingness to get animals, because causal links help the model infer that a consequence query should include both events). This graph is built once and reused.

Second, online inference: when asked a question, the agent does not just do one retrieval. Instead it uses a toolbox. It starts with a semantic search (embeddings, finds 'cows' and 'fence' as candidate nodes), then applies a lexical search (exact words), then uses graph tools to navigate forward/backward on the timeline (traversing neighbors in temporal order), and finally reasons over the collected sequence. This multi-step walk forces the agent to explicitly trace the timeline instead of hoping a single vector-lookup magically captures the right order. The tool-use framework means the agent can decide 'I need to filter by date' or 'I need to count events in this range' or 'I need to check if one event caused another,' and has explicit operations to do it.

Why this works: most memory systems treat retrieval and reasoning as separate stages. You retrieve once (and get any events mentioning 'cow'), then reason (and hope the right order appears). REMem interleaves them. Retrieve, examine the timeline, refine the retrieve, reason over what you found. This iterative loop means the agent can course-correct: if the first retrieval misses the time-ordering, the lexical and graph tools catch it. And because every event is anchored to time from the start, there is no ambiguity about order; the timeline is explicit.

Math after the picture

The equation: multi-step retrieval with temporal filtering

First in words:

score of a retrieved event = (semantic-similarity-to-query) times (is-event-in-target-timewindow) plus (graph-path-distance-bonus if-linked-to-seed-event) divided by (temporal-gap-from-query-time). Final answer is the reasoning score over the top-K events in temporal order.

Then the compact form:

score_i = (sim(query, event_i) * time_mask_i + path_bonus_i) / (1 + temporal_gap_i); answer = reason(sort_by_time(top_K_by_score))

Every symbol:

sim(query, event_i)embedding similarity between question and event, a number from 0 to 1
time_mask_iis 1 if event is in the time window of interest, 0 otherwise
path_bonus_iextra points if the event is connected to another relevant event on the graph
temporal_gap_ihow far in time this event is from the query or seed event, in days or steps
top_K_by_scorethe K most-relevant events ranked by the score above
sort_by_time(...)reorder the selected events by their timestamps
reason(...)the language model's reasoning over the ordered events to form the answer
A tiny worked example
Query: 'How many animals after the fence?' Today is Jan 20.
Event A (fence, Sunday Jan 14): sim=0.85, in-window=1, path_bonus=0, gap=6 days -> score = (0.85 * 1 + 0) / (1 + 6) = 0.85 / 7 = 0.121
Event B (cows, Monday Jan 15): sim=0.92, in-window=1, path_bonus=2 (linked to fence), gap=5 days -> score = (0.92 * 1 + 2) / (1 + 5) = 2.92 / 6 = 0.487
Event B scores higher because it has both high semantic similarity AND temporal proximity AND graph link to the fence event.
Events sorted by time: [fence-Jan14, cows-Jan15]. Reason: fence happened first, cows came after. Count cows = 3. Answer: 3 animals.

The score rewards events that are semantically relevant AND temporally close AND connected on the graph, then sorts them chronologically so reasoning proceeds in the right order.

What can go wrong

What can go wrong

Missing timestamps in the event log. If the conversation history has no explicit dates or sequence markers ('the fence broke' with no date), REMem cannot anchor the event to the timeline. The system degrades to semantic retrieval alone and loses the temporal advantage.
Ambiguous temporal references. Phrases like 'a while back' or 'before that' require the system to infer temporal distance from context. If context is sparse, the inferred timegap is wrong, and later reasoning steps compound the error.
Graph sparsity: few connecting events. If events in the memory are isolated (no shared entities, no causal overlap), the graph has few edges. Graph navigation tools then do not help; the system falls back to semantic search, losing the multi-hop advantage because the agent cannot walk from one event to neighbors—there are no edges to follow. A question like 'What happened after the meeting?' fails if the meeting has no outgoing causal edges, so semantic search alone must guess which later events are relevant.
Long reasoning chains exceed the model's reasoning window. If the answer requires reasoning across 10+ steps on the timeline, the model's context window or reasoning depth may not suffice to hold the full chain and produce the answer correctly.
Done right. REMem succeeds when events are timestamped, linked on the graph by entities and causality, and the multi-step tool-use agent has enough reasoning depth to walk the chain. The paper shows this setup achieves 90%+ exact match on ordinal and multi-hop temporal tasks, substantially outperforming systems like Mem0 and HippoRAG 2 which lack the temporal grounding.
What a runnable demo should prove

What a runnable demo should prove

Build a simple conversation log with 5–10 timestamped events (e.g., 'Alice bought apples on Monday,' 'Bob arrived on Tuesday,' 'Alice left on Wednesday'). Then ask three types of questions: (1) Ordinal: 'Who arrived first, Alice or Bob?' (2) Counting across time: 'How many things happened between Monday and Wednesday?' (3) Causal reasoning: 'After Alice left, did Bob do anything?' The demo should show that a system with the time-grounded graph correctly answers all three, while a semantic-only baseline fails the ordinal and multi-hop questions. Measure exact-match accuracy.

accuracy = (ordinal_correct + counting_correct + causal_correct) / 3; failure_cases = ordinal_rank_wrong + counting_omitted + causal_missed

The demo proves that explicit temporal grounding and multi-step graph navigation make reasoning about 'before,' 'after,' and 'in-between' unambiguous and reliable.
