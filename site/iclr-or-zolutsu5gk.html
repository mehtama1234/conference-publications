Zero-shot Forecasting by Simulation Alone

Train a model on purely synthetic time series data and it can predict real time series it has never seen without any fine-tuning, because the simulator captures the core patterns that appear across many different domains.

Paper explainersAll themesTime Series & Sequential

Real time-series data (like stock prices or website traffic) is expensive and private. A researcher built a fast simulator that generates billions of fake time series, each with trend, seasonal repeats, and random bursts. Train a model on only these fake series, and it predicts real series it has never seen. This works because the fake data, though made-up, captures the core patterns that all time series share.

Zero assumption version

The wall: real time series are locked away

Today, forecasting models learn from real data: stock prices, electricity use, weather. But that data is expensive to collect, is often kept private by companies, and does not cover every pattern a model might see. A beginner's idea is simple: find more real data. But there is not enough, and what exists is biased. Another idea: train a general model on all real data, then fine-tune it on new data. But this fails on zero-shot tasks — when you must predict a brand-new series without any samples from it.

The deeper problem: if your simulator is too simple or unstable, it generates garbage (paths that blow up, or unrealistic noise). If you use a naive simulator, its flaws become the ceiling of what your model can learn.

The paper builds a fast simulator that makes realistic fake time series. Use the simulator to generate billions of synthetic time series without real data, then train a model once on all the fakes and never train again.

The hidden quantity

Stability: whether the simulator stays grounded

measured quantity  =  path stability (does it blow up?)

A SARIMA model generates time series by combining trend, seasonal cycles, and randomness. But the math can be unstable: if you pick the wrong internal parameters (coefficients that control how past values feed into future values), the output explodes to infinity or collapses to garbage. The paper names and measures a quantity called the stability region: the set of all parameter choices that keep the path bounded and realistic. By sampling parameters from inside this region instead of anywhere at random, the simulator avoids generating garbage, so the model has something real to learn from.

The paper estimates stability by checking whether the characteristic polynomial of the SARIMA system has all its roots inside the unit circle. This is a hard mathematical gate: if you pass, your path is stable; if you fail, it is not. By respecting this gate during parameter sampling, the paper ensures that every synthetic series is usable.

Why it works

Why stable sampling plus layered patterns beats naive generators

The core insight: a model trained on a billion fake time series will learn the patterns that appear across all of them. If the fake data is boring (all paths are smooth), the model stays naive. If the fake data is garbage (paths explode), the model learns nothing. The paper's method locks in realism at every step.

Step 1 (stability sampling): instead of picking SARIMA parameters at random, the paper checks which choices keep the path bounded. This filters out the garbage generator parameter sets, so every synthetic series is grounded.

Step 2 (superposition layering): real time series have multiple seasonal patterns happening at once. A stock might have a daily cycle and a yearly cycle. By overlaying multiple SARIMA paths (each with different seasonal periods), the simulator creates this richness from the start.

Step 3 (heavy-tailed noise): real-world shocks (a pandemic, a news event, a network outage) are rare but huge. Smooth randomness misses this. Heavy-tailed noise means occasional jumps, which matches real data. The model learns to handle not just trends and seasons but also sudden breaks.

Result: the model sees a billion realistic fake series covering the space of trend, seasonality, and burstiness. When deployed on a real unseen series, it recognizes these patterns and forecasts correctly, even though it never saw a real training sample from that specific series.

Math after the picture

The stability condition in plain math

First in words:

A SARIMA system is stable if the characteristic polynomial (a formula built from the model coefficients) has all roots inside the unit circle; only parameters in this region are sampled.

Then the compact form:

All roots of (1 - phi_1*z - phi_2*z^2 - ... - phi_p*z^p) lie strictly inside |z| < 1

Every symbol:

phi_1, phi_2, ..., phi_pautoregressive coefficients (control how past values affect the future)
za complex number (used in the math to check stability)
|z| < 1the unit circle; roots inside mean the path stays bounded
rootssolutions to the polynomial equation where it equals zero
A tiny worked example
Suppose SARIMA picks phi_1 = 0.7, phi_2 = 0.2 as its coefficients.
The characteristic polynomial is 1 - 0.7*z - 0.2*z^2.
Solve for z: the roots are z ≈ 0.5 and z ≈ -1.2.
Root 1: |0.5| = 0.5 < 1 (inside the unit circle: OK).
Root 2: |-1.2| = 1.2 > 1 (outside the unit circle: UNSTABLE).
Verdict: this parameter set is rejected; sample new coefficients.
By only accepting roots strictly inside, the simulator avoids blowups.

The paper applies this check before generating each synthetic series, ensuring every path stays realistic.

What can go wrong

What can go wrong

Sampling outside the stability region. If you forget to check the characteristic polynomial, you pick unstable parameters and generate garbage. Every synthetic path should be validated before use.
Underestimating seasonality. If your simulator uses only one seasonal period, the model learns only that rhythm. Real data has multiple overlapping seasons (intra-day, weekly, yearly). Superposition is essential.
Too much smooth noise. Gaussian (bell-curve) randomness misses sudden shocks. Real time series have rare, huge jumps. Without heavy-tailed noise, the model underestimates volatility.
Done right. Use the stability region, layer multiple seasons, add heavy-tailed noise, and generate at scale. The model learns genuine patterns from billions of synthetic examples, not memorization.
What a runnable demo should prove

What a runnable demo should prove

Build a minimal SARIMA simulator: (1) sample coefficients from the stability region (compute and check the characteristic polynomial roots); (2) generate a time series from that SARIMA model; (3) add heavy-tailed noise (occasional jumps using exponential or power-law tails, not smooth randomness). Generate 10,000 synthetic series. Train a simple neural forecaster (e.g., a 2-layer LSTM) to predict the next 10 steps given the previous 50. Then test zero-shot on a held-out synthetic series the model has never seen, and also on a real series from a standard benchmark (e.g., ETTh1 or M3). The metric is mean absolute percentage error (MAPE), because dividing error by the actual value measures how wrong you were relative to the size of what you were predicting (a 10-unit error on a 100-unit trend is 10%; on a 1000-unit trend it is 1%), so lower is better when comparing across different magnitude time series. The demo succeeds if the model trained on only fakes beats a naive statistical baseline (like ARIMA) on the real series.

MAPE = (1 / n) * sum of |actual - predicted| / |actual| for n future steps

The surprising result: a model trained on a billion fake series, never seeing real data, can forecast real series better than the process that generated them, because the neural model learns abstract patterns (how trends accelerate, how seasonality combines) that generalize beyond the simulator's exact formulas.
