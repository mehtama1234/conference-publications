Scaling by Diversified Experience for Vision-Language-Action Models

SyVLA decouples reasoning from control by hiding unhelpful reasoning neurons, then stabilizes real-world robot learning by copying training examples similar to what the robot tries.

Paper explainersAll themesRobotics & Control

When a robot reads a vision frame and an instruction, it faces two separate jobs: understanding the goal (high-level reasoning) and moving its arm (low-level control). Most current Vision-Language-Action models tangle these two jobs together in the same neural network weights, which breaks both—the model loses its ability to reason about abstract questions, and its arm movements become indecisive and clumsy. SyVLA fixes this by finding which neurons carry reasoning info and which carry control info, then hiding the reasoning neurons when the robot acts. It also learns from robot rollouts more stably by picking practice examples that closely match what the robot actually tried.

Zero assumption version

Reasoning and control pull in opposite directions

Vision-Language-Action models (or VLAs) are neural networks that take a photo and a text instruction, then output robot arm commands. Most VLAs work by training on two things at once: (1) learning to understand abstract instructions (reasoning), and (2) learning to move the robot arm (control). But these goals conflict. When the model trains on reasoning tasks, it builds internal patterns (called representations) that are detailed and flexible—great for answering 'what is this object?' but terrible for the simple, mechanical job of 'move three inches left.' When it trains on control, those same weights get sharpened for precise motor commands, which erases the reasoning ability.

The beginner tries two naive fixes, both of which fail. First: train on reasoning data, then train on robot data—but this causes catastrophic forgetting, where the model unlearns everything about vision-language understanding. Second: train on everything at once—but then the model becomes mediocre at both; it never commits fully to either job. After this initial training, when engineers use reinforcement learning to teach the robot real tasks (learning from tries and failures), the training becomes unstable—the robot's policy (its rules for acting) drifts away from the expert demonstrations it learned from, and the robot fails on new tasks it has never seen before.

In one sentence. SyVLA separates the reasoning job from the control job inside the network, then stabilizes learning from real robot attempts by choosing practice examples that match what the robot actually tried.

The algorithm as a flow

What it actually does

Freeze the reasoning model

Start with a large vision-language model already trained to understand images and text. Do not change it.

Compute action loss gradient

Run the model forward once, produce an action, measure how wrong it is. Compute gradients (the numerical score for each neuron showing how much it caused the error) to see which neurons cared about that error.

Mask low-gradient neurons

Find neurons whose gradients were tiny (they barely affected the action loss). Set those hidden states to zero. This hides reasoning noise from control.

Teach with matched examples

When robot tries a new action during learning, find similar examples from training data. Mix them into the batch because training on both current and expert together anchors the policy to behaviors that are known to work.

Train the action module

Update only the small control network. Reasoning weights stay frozen, so they retain all their learned concepts and do not degrade. Robot improves its motor commands without forgetting abstract understanding, because the reasoning part is never touched.

What the paper changes

What the paper changes

The paper modifies which neurons the robot actually listens to when it needs to act. Most Vision-Language-Action models use all the outputs from the reasoning part of the network (the 'reasoning representations'). SyVLA computes a gradient mask—a list of which outputs actually mattered for predicting the correct action—and physically zeros out the neurons that did not matter. In effect, it silences the reasoning noise before the action network reads it.

The hidden quantity

The hidden quantity: control relevance

measured quantity  =  control relevance (gradient magnitude per neuron)

When the robot produces an action and that action is wrong, the network computes gradients—a score for each neuron saying 'how much did you cause this mistake?' Neurons with high gradients did a lot to cause the error, which means they carry information about control. Neurons with low gradients barely affected the action, so they are carrying reasoning info that the action network should ignore. SyVLA measures this gradient score for each neuron (specifically, the overall size of the gradient, computed as the L2 norm—the total magnitude combining all directions) and calls that the control relevance.

The paper identifies control-relevant neurons by comparing these gradient magnitudes during a forward-backward pass through the action loss only. It then masks (sets to zero) the neurons with the smallest magnitudes, which pushes mutual information—shared structure—between the remaining neurons and the reasoning part down to nearly zero. In other words, by removing the noisy low-relevance neurons, the control network sees only the clean control signal, and the reasoning part stays intact.

Why it works

Why it works: two clean separation acts

The mechanism has two parts. First, by masking low-gradient neurons, SyVLA isolates the control signal. When a reasoning neuron fires (e.g., activating because the instruction mentions 'fold'), that spike would normally spread to the action network and confuse it. But the low-gradient mask catches it: any reasoning-only neurons are zeroed before they can reach the action network. So the control network sees a cleaner, simpler input—just the features it needs to move the arm, without the abstract semantic noise. This is why the model keeps its reasoning ability (the reasoning weights are still there, unused), but the action network becomes decisive (it is not distracted).

Second, similar-sample guided reinforcement learning stabilizes the policy. When the robot tries a move during learning, that move might be very different from anything in the training data—a rare combination of arm angle, object position, and grip strength. The model then trains on that rare move, making big updates to its weights. But rare moves are fragile: the model learns from an outlier and starts to drift from expert behavior. SyVLA solves this by finding training examples that are semantically similar to the current attempt (same goal, similar hand position, similar object), and mixing those examples into the learning batch. Now the model trains on both the new attempt AND the expert examples that match it, which keeps the policy anchored. The expert examples act as a correction—they pull the model back to behaviors it has already verified work.

Math after the picture

The gradient mask equation

First in words:

For each neuron, compute how much its output changes the action loss. Zero out neurons where this change is small. Specifically, mask neurons whose L2 norm of gradient is below a threshold.

Then the compact form:

h_masked = h_raw * mask, where mask_i = 1 if ||grad_i(L_action)|| >= threshold, else 0

Every symbol:

h_rawthe output of the reasoning model before masking
h_maskedthe output after masking
mask_ibinary flag for neuron i (1 = keep, 0 = zero out)
grad_i(L_action)the gradient of the action loss with respect to neuron i
||grad_i||the length of the gradient vector for neuron i
thresholdthe cutoff: neurons below this are masked
A tiny worked example
Neuron 1: gradient magnitude 3.2. Threshold is 2.0. 3.2 >= 2.0, so mask_1 = 1 (keep it).
Neuron 2: gradient magnitude 0.8. Threshold is 2.0. 0.8 < 2.0, so mask_2 = 0 (zero it out).
Neuron 3: gradient magnitude 1.5. Threshold is 2.0. 1.5 < 2.0, so mask_3 = 0 (zero it out).
Result: h_masked = [h_raw_1 * 1.0, h_raw_2 * 0, h_raw_3 * 0, ...] = keep neuron 1, discard 2 and 3.

Neurons with tiny gradients do not drive action loss—they are reasoning noise. Zeroing them makes the control signal cleaner without losing reasoning ability.

What can go wrong

What can go wrong

Threshold set too high. If you zero out too many neurons, you accidentally remove control-relevant information along with reasoning noise. The robot becomes even more indecisive than before. The fix: tune the threshold by holding out a validation set of real robot tasks and checking success rate.
Similar-sample retrieval misses the real pattern. If the training dataset is small or biased (only contains gripper tasks, never suction tasks), then a current attempt with a suction cup will not find truly similar examples. The policy drifts without expert anchors. The fix: ensure training data covers the range of tasks you expect.
Freezing the reasoning model is too rigid. Some tasks require the reasoning part to adapt (e.g., learning a new visual concept the original model did not see). Freezing it permanently locks out this flexibility. The fix: add a fine-tuning stage where you unfreeze and update the reasoning model on task-specific data, then refreeze before RL.
Done right. Threshold is set by validation on real robots. Similar samples are retrieved using the same numerical representations (the internal lists of numbers that encode the image meaning) that the vision model produces. Reasoning model is frozen during RL but pre-trained on enough visual data that it handles the tasks you care about.
What a runnable demo should prove

What a runnable demo should prove

Build a simple robotic manipulation task (e.g., pick up a block and place it in a box, or fold a cloth). Start with a pretrained Vision-Language-Action model. Split the demo into two runs: (1) standard RL (train only the action network without intention decoupling or similar-sample guidance), and (2) SyVLA (apply the mask, and during training, retrieve and mix in similar examples from a small expert dataset). Measure success rate and how often the model stays close to the expert policy (drift metric: how much the learned policy deviates from the expert actions on the same states). The demo must show that SyVLA succeeds more often because the masked control signal is cleaner, generalizes better to unfamiliar object positions or lighting conditions because the reasoning part stayed intact and learned new visual patterns, and drifts less from the expert because similar-sample guidance keeps the policy anchored to proven behaviors.

success_rate = (tasks_completed / total_tasks) * 100, policy_drift = (1 - cosine_similarity(learned_actions, expert_actions))

The core insight the demo must make impossible to miss: when you cleanly separate reasoning from control by masking reasoning noise, the robot learns faster because the control signal is pure and the policy is decisive, and the robot does not forget how to reason because the reasoning weights never change. And when you anchor learning to similar expert examples, the policy stays stable because the expert examples pull the policy back toward proven behaviors whenever the robot's new attempt would drift it into a risky, unfamiliar corner.
