Remembering and Using Information

Papers about helping agents remember important facts and use them later, like keeping notes of what happened and learning from experience.

All themesField mapMathematicsAll explainers
What this is

An agent that forgets everything it learned is inefficient, because it wastes time and compute by re-discovering the same patterns over and over. These papers focus on how agents can remember facts, previous experiences, and patterns, then use that memory to make better decisions so they improve with time. Imagine you ask an AI assistant to help you over multiple weeks, and every time you talk to it, it has to re-learn what you care about, who your collaborators are, and what projects you are working on — that is frustrating and slow. Better agents maintain context: they remember you, what you asked last time, what you learned together, which means they can pick up where you left off without starting over. The papers here tackle how to build memory systems that agents can actually tap into when solving new problems.

The challenge is that memory is finite and messy. An agent can't remember everything — at some point it has to forget old information or pick what matters most. Also, remembering something is only useful if the agent knows when and how to apply it. If an agent encounters a problem similar to one it solved before, does it recognize the similarity? Does it look up the old solution? Does it retrieve just the relevant parts, not everything? There is also a trade-off: detailed memory takes more time to search, sparse memory misses important connections. And if the agent stores wrong information, then later uses it, the mistake compounds.

Papers here work on memory architectures — different ways to organize what an agent remembers. Some use explicit memory systems like stored facts or a log of past conversations, which makes the memory searchable and auditable. Others use learned representations that capture the essence of experience, which compresses memory so it is faster to use. Some focus on retrieval — given a new problem, how does the agent find relevant past experiences quickly without searching through everything? Others focus on integration — once the agent finds a past solution or lesson, how does it apply it to the current situation and adapt if things are different? The goal is agents that learn cumulatively, where every experience makes them a little better at their job instead of being thrown away, so they get smarter the more they work.

How the work breaks down

Memory for agents splits into five natural directions: storing and retrieving facts quickly, connecting memories across different situations, using past reasoning steps to solve new problems, managing memory as the agent scales to handle more tasks, and adapting memory after deployment as the agent learns from experience.

Graph-Based Memory and Retrieval

The challenge here is that when an agent needs a specific fact or experience, searching through a pile of raw notes is slow and often misses the right connection. These papers use knowledge graphs — structured maps where ideas are nodes and relationships are edges — so the agent can jump directly from one concept to related ones.

BrowseNet pairs a knowledge graph with retrieval methods so that when you ask a question, the system walks the graph's paths to find relevant facts without loading everything at once. AssoMem takes a different angle: it uses multiple signals (different ways to measure what matches) to search memories of meetings and conversations, so if you ask about a discussion from last week, it retrieves not just the words but the context of who was talking and what the purpose was. DAMR combines a knowledge graph with Monte-Carlo tree search, a planning method, to narrow down the search space when answering questions over structured facts — instead of checking every possible link in the graph, it prunes paths that look unhelpful. All three agree that structure in memory matters: organizing facts as a graph or layering signals makes retrieval fast and accurate.

Episodic Memory and Reasoning

An agent often needs to recall not just isolated facts but whole episodes — sequences of events and what was learned from them — and then apply that reasoning to new problems. The hard part is deciding which memories are relevant and how to adapt past reasoning when circumstances differ.

REMem treats memory as episodes: it stores chains of reasoning and past dialogue in a way that lets the agent replay them when facing a similar challenge. It outperforms simpler memory systems by being more selective about which memories to load, and it keeps refusals (things the agent shouldn't do) from previous episodes so it doesn't repeat mistakes. ReasoningBank goes further: it lets the agent build up a library of reasoning steps from its own experience solving problems, then reuses those steps on new tasks — like learning that 'factor before simplifying' is a useful strategy and applying it the next time you see a similar math problem. Embodied Agents Meet Personalization tackles a different axis: when an agent works with the same person over time, it builds a personalized user profile stored in a knowledge graph, keeping user preferences separate from general knowledge, so the agent doesn't confuse what one user likes with what another does. All three show that agents learn better when they store reasoning chains and personal context, not just raw facts, because reasoning chains let the agent transfer strategy between problems and personal context prevents mistakes from cross-talk between users.

Parsing Agent Actions into Structured Memory

When an agent operates over multiple steps — making a plan, trying different tools, backtracking — the transcript is often linear and messy, with steps that depend on each other in hidden ways. Extracting useful lessons from this requires untangling which steps actually mattered.

De-Linearizing Agent Traces recovers the hidden dependency structure by using Bayesian inference: it looks at an agent's action log and figures out which earlier steps each later step relies on, so it can prune irrelevant context when executing similar tasks again. Instead of replaying the entire sequence, you replay only what matters, cutting down on the text (tokens — the unit the model uses to count input) and wall-clock time. AMA-Bench introduces a benchmark showing that if you store an agent's actions as a causality graph (what caused what) plus tools for retrieving relevant parts, you get strong performance on long-horizon memory tasks, beating naive methods by 11%. Both papers agree: linear action traces are lossy; extracting the causal skeleton lets you reuse memories without waste.

Scaling Memory as Agents Multiply

As you field more agents solving similar problems, their memories can either conflict and interfere with each other, or combine and amplify what they know. The challenge is scaling so that adding agents improves performance without dropping quality.

MonoScale ensures that as you add agents to a team, the performance keeps rising or stays stable (never falls) because each agent stores partial solutions and learns from nearby agents' attempts, so redundant effort is minimized. MemEvolve takes this a step further by using meta-evolution: it learns how to improve the memory system itself based on what worked across many tasks and LLM models. Both show that coordinated memory across agents is better than isolated memory; the agent pool becomes smarter by learning from the collective past.

Adaptive and Procedural Memory After Deployment

In the real world, an agent deployed for weeks or months encounters new challenges and needs to learn from that experience without retraining from scratch. The key difficulty is balancing learning new things while not forgetting or corrupting knowledge that already works.

AdaMEM updates the agent's memory at test time (after it's deployed) by letting it reflect on whether its reasoning worked or failed, and storing successful strategies so the next similar problem is easier. Experience-Evolving Multi-Turn Tool-Use Agent with Hybrid Episodic-Procedural Memory separates two kinds of learning: storing one-off episodes (like 'I called this tool and got this result') and extracting reusable procedures (like 'always check this precondition before using this tool'), so the agent grows more efficient over many interactions because it doesn't re-store the same lesson twice. Skill-Pro extracts reusable skills from experience using reinforcement learning, compressing them heavily so memory doesn't bloat, and the skills stack transparently so you can audit what the agent learned. XSkill combines episodic memories (specific experiences) and skill memories (patterns that apply broadly), letting the agent generalize across both kinds of learning in a single unified system. Together, these four show that post-deployment learning works best when the agent explicitly separates specific memories from general patterns and prunes redundancy, which means faster lookup and less wasted storage.
