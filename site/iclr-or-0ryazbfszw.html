Fast FC Model Comparison via Smart Data Subset Selection

Pick 10% of brain scans that preserve which models rank best, so you never waste time testing all models on all data.

Paper explainersAll themesDatasets & Benchmarks & Evaluation

Neuroscientists have built hundreds of methods to measure how different parts of the brain talk to each other using brain scans. Testing all of them on real data takes weeks of computing. This paper asks: what if you only tested on the most representative scans? By picking a smart 10% of scans, the paper preserves which models are best, cutting the benchmark time to a fraction.

Zero assumption version

Testing hundreds of models on millions of brain scans is too slow

Functional connectivity means measuring which brain regions activate together during a scan. There are now hundreds of methods to compute this from raw fMRI data. To know which ones work best, you must test each method on large real datasets. A single test of one method on one dataset takes minutes to hours. With 500 models and 10,000 scans, that is five million model-dataset pairs—impossibly slow.

A beginner might try this anyway: just run everything. The problem: it wastes resources. Most scans in a dataset are similar to each other, so testing on all of them teaches you nothing new. The ranking of models does not change if you drop the 50th nearly-identical scan. You have no way to know which scans to drop without having already run the models.

The core bottleneck. You need to test models on the most informative scans only, but you don't know which scans matter until you've already tested them all.

The algorithm as a flow

What it actually does

Learn each scan's unique structure

A neural network reads one brain scan at a time and learns to recognize what makes that scan's connectivity pattern distinctive.

Measure stability during training

As the network trains, watch which scans produce stable learned patterns; these scans capture the core archetypes.

Rank by stability

Score each scan by how stable its learned pattern is across training steps. Stable scans represent foundational brain patterns.

Rebalance for diversity

The stable scans might cluster together. Thin out any dense cluster so the subset covers all brain pattern types fairly.

Verify the ranking holds

Test models on this small subset and check that the ranking of models matches the ranking from the full dataset.

What the paper changes

What the paper changes

The paper changes which data you feed to the model comparison. Instead of comparing models on all 10,000 scans, you compare them on a curated 1,000-scan subset. This subset is not random; it is chosen to preserve the model ranking.

the object it moves  =  the data subset
The hidden quantity

Structural Perturbation Score: which scans matter most

measured quantity  =  Structural Perturbation Score

As a neural network learns to represent each scan's connectivity pattern, the learned pattern shifts slightly from step to step. The Structural Perturbation Score measures how much that pattern shifts. A low shift means the scan has a stable, archetypal connectivity pattern. A high shift means the pattern is noisy or unusual.

The paper uses this score to rank scans. High-stability scans (low shift) are kept because they reliably represent core brain connectivity patterns. Low-stability scans (high shift) are filtered out because they add noise without teaching the model anything new about what connectivity patterns exist.

Why it works

Why stable scans preserve model rankings

A model comparison test works like this: run model A, B, C on the same data and measure which one predicts connectivity best. The ranking depends on which scans you feed them. If the scans are all very similar, they all see the same easy or hard cases, so all models perform at the same level. If the scans are diverse, they stress-test models differently, and the ranking becomes clear.

The core idea: if you pick scans whose connectivity patterns are stable and archetypal (representing the core types of brain patterns that exist), then testing models on those scans is almost as informative as testing on all scans. You have all the major test cases; you are just skipping redundant copies. Since every redundant scan would produce the same ranking anyway, dropping them does not change the answer.

The Structural Perturbation Score finds these archetypal scans by watching the neural network's learned representation. Scans that produce a stable learned pattern are ones the network recognizes as prototypical—clear examples of real brain connectivity archetypes, not edge cases or noise. These are the scans to keep.

Ranking preservation via stability

First in words:

perturbation_score = average_distance_of_learned_features_across_steps ; subset_quality = how_well_model_rankings_match_between_subset_and_full_data

Then the compact form:

nDCG = (2^relevance - 1) / log_2(position) ; subset = top_k_by_stability + density_balanced_correction

Every symbol:

top_kthe 1000 or so scans with lowest perturbation scores
density_balanced_correctiona resampling step that removes overlapping scans from dense clusters
nDCGa ranking similarity metric ranging 0 to 1; higher means the model order did not flip
relevancein this context, how important a scan is to deciding the true model ranking

What can go wrong

What can go wrong

No diversity check: all stable scans cluster into one brain pattern type. If you keep only the top-stability scans without rebalancing, you might get 1000 scans that all show the same one connectivity archetype. Then models that specialize in that pattern rank too high, and models that work on other patterns rank too low. The remedy: force the subset to cover all pattern types, even if some are rarer.
Stability measure is too strict: the network gets stuck in one representation. If the neural network quickly converges to a single representation and never changes, all scans look equally stable. Then you have no signal to rank them. The remedy: use an adaptive network that keeps learning new aspects of each scan as training progresses.
Model comparison is not a ranking task for that model. If one model is designed to solve a different problem than the others (e.g., detecting rare connectivity patterns), then the ranking may not matter to you—you might care about precision on rare cases, not average rank. The subset preserves ranking but not necessarily precision on your specific use case.
Done right. Use the Structural Perturbation Score to identify archetypal scans, rebalance to cover all pattern types, and verify the model ranking holds on the subset before declaring victory.
What a runnable demo should prove

What a runnable demo should prove

Write a script that: (1) loads a brain scan dataset with 100 scans and 5 connectivity models; (2) runs all 5 models on all 100 scans and records the ranking of models by accuracy; (3) trains a small neural network to learn each scan's connectivity structure and computes the Structural Perturbation Score for each scan; (4) selects the top-10 scans by score and applies a density-balancing filter; (5) runs the same 5 models on only those 10 scans and records the new ranking; (6) computes the ranking similarity (e.g., how many model pairs kept their relative order). A passing demo shows ranking similarity > 80% using only 10% of the data.

ranking_preserved = (number_of_model_pairs_with_same_relative_order) / (total_model_pairs) ; speedup = (time_for_full_benchmark) / (time_for_subset_benchmark)

The demo makes it impossible to miss that a tiny carefully-chosen data subset can tell you which model is best just as well as testing on everything, and vastly faster, because the chosen subset concentrates on the questions that most separate strong models from weak ones.
