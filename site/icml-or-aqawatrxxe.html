AlignedNorm: Prompting Vision-Language Models via Coupled Prompt Field

Keep prompt tuning for old and new classes in one shared scale so optimization stops drifting into separate, incompatible solutions.

Paper explainersAll themesMultimodal

Prompt learning for a vision-language model changes a small learned text prefix instead of changing the whole model. The difficulty is that a prompt tuned for base classes, meaning classes seen during training, and a prompt tuned for new classes, meaning classes introduced later, often live on different numeric scales. Once their scales drift apart, the optimization for each side follows its own local target and the model loses the chance to find one prompt setting that serves both. AlignedNorm addresses that by forcing prompts to stay on the model's native scale throughout training, so base and new tasks remain coupled while the prompt is updated.

Zero assumption version

Why prompt tuning splits into two incompatible jobs

A vision-language model already has a learned image space and text space. Prompt learning adds a short learned token sequence, meaning a short learned sequence of text-side inputs, so the model can adapt to a task because the prompt changes the text features used for image-text matching without retraining all weights. In generalized recognition settings, the system must keep good accuracy on base classes and also work on new classes that were not used to tune the prompt.

The common failure is that optimization happens sample by sample inside the feature space induced by the current prompt. If the prompt norm, meaning the overall size of the prompt coordinates, grows too much or shrinks too much for one side of the task, the resulting feature arrangement differs from the model's original operating scale. Then base and new tasks stop constraining each other. The optimizer can improve one side while silently making the other side worse because the two objectives are no longer expressed in one comparable field.

The paper's move in one sentence. Keep every learned prompt on the model's native scale so base-class and new-class optimization stay tied to the same feature field.

The algorithm as a flow

What it actually does

Start from a pretrained vision-language model

Keep the backbone fixed so the method changes only the learned prompt and not the full model.

Estimate the native operating scale

Read the norm of the model's own prompt-related features so training has a stable reference for how large prompt coordinates should be.

Learn prompts for the task

Update prompt parameters with gradient descent, meaning repeated steps that move parameters toward lower loss.

Align the prompt norm after each update

Rescale the prompt back toward the native norm so optimization cannot solve one task by moving to an abnormal magnitude.

Train base and new objectives together

Use the coupled prompt field to tune one prompt system that can serve both class groups because both groups now constrain updates in the same scale regime.

What the paper changes

What the paper changes

The paper changes the numeric scale of the learned prompt during optimization. It does not add a heavy new architecture. It inserts a normalization rule so the prompt stays compatible with the pretrained model's own feature scale.

the object it moves  =  the norm of the learned prompt
The hidden quantity

The hidden quantity

measured quantity  =  how far the learned prompt has drifted from the backbone's native scale

The important hidden quantity is prompt-scale drift. Two prompts can point in similar directions but still produce very different class scores before normalization, if one prompt has much larger norm than the other. That scale change alters how strongly the prompt perturbs the backbone's text features.

This matters because base and new classes are compared through the same classifier head. If one side is produced at an inflated scale, its scores dominate for numeric reasons rather than semantic reasons. Aligning norms removes that accidental advantage and makes the competition between classes reflect feature content instead of feature magnitude.

Why it works

Why norm alignment changes the optimization path

Prompt tuning is not only about direction in feature space. Magnitude matters because the prompt is added into the text representation pathway. If the learned prompt becomes too large, it can overpower the pretrained text template. If it becomes too small, it contributes almost nothing. Either failure breaks the balance between using pretrained structure and adapting to the task.

AlignedNorm works because it removes one easy but harmful escape route for the optimizer. Without the constraint, the optimizer can reduce loss for one subset of classes by stretching prompt magnitude instead of learning a direction that generalizes. With the constraint, updates must improve how well image features and text features point to the same class at roughly fixed scale, because changing magnitude alone is no longer enough to lower the loss. That makes progress harder to fake and more likely to transfer across base and new classes.

The coupled field view matters because both class groups now share a common ruler. When the prompt norm is aligned to the backbone's native scale, improvements on base examples and improvements on new examples are computed in a comparable part of the model. That gives joint optimization a real chance to find a compromise rather than flipping between incompatible local optima.

The alignment rule

First in words:

A simple view is to learn a prompt by gradient descent and then renormalize it so its norm matches a reference norm taken from the pretrained model.

Then the compact form:

p_aligned = (r / ||p||) p

Every symbol:

pthe current learned prompt vector after an optimization step
||p||the norm, meaning the overall size, of the prompt vector
rthe reference norm taken from the pretrained model's native scale
p_alignedthe rescaled prompt used for the next forward pass
A tiny worked example
Suppose the backbone's reference norm is 10.
After one update, the learned prompt has norm 15.
AlignedNorm multiplies the prompt by 10 divided by 15, so the next pass uses a prompt with norm 10.
That matters because the optimizer must now improve direction and class separation, not rely on oversized prompt magnitude.

The paper's exact implementation can include dynamic alignment details, but the core principle is to keep prompt scale tied to the pretrained model's operating range.

What can go wrong

What can go wrong

The reference norm can be poorly chosen. If the reference scale does not reflect the backbone's true operating range, normalization can suppress useful adaptation because it keeps the prompt tied to the wrong magnitude.
Direction can still overfit. Norm alignment stops one kind of drift, but it does not guarantee that the prompt direction generalizes. The prompt can still memorize small datasets if the loss gives weak coverage of new classes.
Tasks may need different text templates. If the main failure is wording rather than scale, norm control alone will not fix it because the prompt still points toward the wrong semantics.
Done right. The method is most useful when prompt learning already works in principle and the main problem is unstable tradeoff between retaining base knowledge and adapting to new classes.
What a runnable demo should prove

What a runnable demo should prove

Use a frozen CLIP-style classifier with a small prompt-learning head. Split classes into base and new groups. Train one prompt system with plain optimization and one with norm alignment against a reference taken from the frozen text encoder.

Log prompt norm, base accuracy, new accuracy, and harmonic mean across training. The demo should show that the aligned version keeps prompt scale near the reference and preserves a stronger base-new tradeoff because updates cannot exploit magnitude drift.

balance_score = 2 * base_acc * new_acc / (base_acc + new_acc)

The point is to make prompt-scale drift visible and to show that constraining it changes the quality of the final compromise.
