The aliasing problem in downsampling

Real-world time series (a stream of numbers over time, like hourly temperature or stock prices) contain fast and slow patterns mixed together. The fast ones change many times per hour; the slow ones drift over days.

To train faster, models often skip every other measurement (or every fifth one) to create a coarser-grained version, because fewer numbers mean less computation and shorter training time. But here is the catch: if the original signal wiggles faster than the coarser grid can see, those fast wiggles get compressed into the coarse grid and reappear as low-frequency patterns (slow wiggles), because the grid has no room to show the fine-grained oscillation. This is aliasing. For example, a weekly cycle in daily data, if downsampled to monthly, can masquerade as a completely different slow pattern. The model learns from this fake pattern and makes wrong forecasts.

The fix. Filter out the fast wiggles before downsampling, then smooth the result after, so only true slow patterns survive the coarsening.

What the paper changes

What the paper changes

The paper changes how the downsampling step works in a time series model. Instead of simply skipping points (the naive way), it wraps the downsampling in two filtering operations: one that removes high-frequency content before sampling (to prevent aliasing), and one that restores smoothness after sampling (to keep the coarse signal clean).

The hidden quantity

The hidden quantity: spectral folding

measured quantity  =  amount of false low-frequency content created by aliasing

When a fast wiggle (high frequency) exists in the original signal, and you downsample without filtering, that wiggle gets misread as a slow wiggle at a false frequency. The amount of this misreading depends on how much fast content is in the signal and how coarse the downsampling is. We call this spectral folding—the high frequencies fold back into the low-frequency range.

The paper measures this by asking: after downsampling, how much of the low-frequency pattern is real versus fake aliasing? It estimates this by comparing the filtered-then-downsampled signal (which has no aliasing) to the naive-downsampled signal (which has aliasing). The difference is spectral folding.

Why it works

Why filtering before and after downsampling stops aliasing

Downsampling removes measurements; if the signal changes fast between the measurements you keep, you lose that change. A naive downsampler keeps whatever value it sees at the sample points, but fast wiggles between those points pull the readings in unpredictable directions. When the signal is sampled at a coarse grid, a fast wiggle that goes up-down-up-down between grid points can align with the grid points in a way that creates a low-frequency pattern: for example, you might see high-medium-low-medium-high-medium, which reads as a slow oscillation even though the original was a fast one.

Pre-sampling filtering smooths the signal before downsampling. This is like asking: what are the safe patterns to measure at this grid size? If the grid is coarse, you can only safely measure slow patterns. The filter removes everything too fast to measure safely.

After downsampling, the coarse signal is undersampled and looks jagged. Post-sampling interpolation reconstructs smooth values between the grid points by curve-fitting the coarse samples. This restores the visual and numerical character of the true slow pattern without re-introducing the aliased false patterns (because those are already gone from the pre-filtered data).

Together: filter then downsample then interpolate. The model sees only real slow patterns; aliasing artifacts are trapped and discarded.

The anti-aliasing filter and interpolation

First in words:

The pre-sampling filter multiplies the signal by a kernel (a smooth falloff) that kills frequencies above half the downsampling rate. The post-interpolation uses weighted averages of nearby downsampled values to estimate intermediate points. The loss is standard time series loss on the forecasted values.

Then the compact form:

y_downsampled[n] = sum_i h[i] * x[2n - i], then y_interpolated[m] = sum_j w_j * y_downsampled[floor(m/2) + j]

Every symbol:

y_downsampled[n]value of the coarse signal at grid point n
h[i]anti-alias filter kernel, smooth weights that decay far from the center
x[2n - i]original signal, sampled at the corresponding fine-grid points
y_interpolated[m]reconstructed smooth value between grid points
w_jinterpolation weights, summing to 1, centered on nearby downsampled points
floor(m/2)the nearest downsampled grid point to position m
A tiny worked example
Original signal at fine grid: x = [5, 8, 4, 9, 3, 7, 6, 8, 5, 9, 2, 8]
Pre-filter kernel h = [0.25, 0.5, 0.25] (blur: keep middle, average neighbors).
At position 0: 0.25*0 + 0.5*5 + 0.25*8 = 2.5 + 2 = 4.5 (blurred).
At position 2: 0.25*5 + 0.5*4 + 0.25*9 = 1.25 + 2 + 2.25 = 5.5 (blurred).
Downsample by taking every 2nd point of the blurred signal: [4.5, 5.5, ...].
Interpolate back: between 4.5 and 5.5, estimate 5.0 = 0.5*4.5 + 0.5*5.5 (linear average).
Result: smooth coarse-then-interpolated signal, no aliasing spikes from the original wiggles.

The filter removes fast-wiggling content before sampling, and interpolation smooths the coarse grid afterward, together ensuring the model learns only real slow patterns.

What can go wrong

What can go wrong

If the filter is too aggressive, real slow patterns get erased. Setting the cutoff frequency too low removes not just the aliasing artifacts but also real slow content. The filter cutoff must match the true Nyquist limit of the downsampling rate, no lower.
If the grid is too coarse, no filter can save it. If the downsampling rate is so coarse that the true signal changes faster than the grid can sample, aliasing dominates and corrupts the entire downsampled signal, because there is no information at the grid points to reconstruct the original pattern. The grid must be fine enough to capture at least two samples per cycle of the slowest important pattern.
If interpolation is the wrong shape, you overfit to coarse grid artifacts. Interpolation must be smooth and unbiased (e.g., linear or cubic splines). A non-smooth interpolator (like nearest-neighbor) can introduce new artifacts.
Done right: the filtered-downsampled-interpolated signal is both clean and smooth. No aliasing spikes, no overfitting to grid artifacts, just the true slow patterns.
What a runnable demo should prove

What a runnable demo should prove

Generate a synthetic time series with a known slow pattern (e.g., a 7-day cycle) and a known fast pattern (e.g., hourly noise). Downsample by a factor of 6 (keeping every 6th point). Measure the forecast error on a separate test set of pure slow pattern.

Run three methods: (1) naive downsampling, (2) pre-filter only, (3) the full pipeline. The demo must show that naive downsampling learns the aliased false pattern and fails on new data. The full pipeline must recover the original slow cycle.

forecast_error = sum of (predicted - true)^2 on test set with only slow pattern

Naive downsampling produces large forecast errors because the model learned aliasing artifacts. Anti-aliasing downsampling produces small errors because it learned the true pattern.
