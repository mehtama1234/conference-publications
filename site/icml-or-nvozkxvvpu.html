LLM-Guided Communication for Multi-Agent RL

An LLM designs a communication protocol so each agent builds an accurate, shared picture of what is happening.

Paper explainersAll themesAgents & Tool Use

In a multi-agent system, each robot or player only sees part of the world, but they must work together. To do this, they send each other messages about what they see. The challenge is: what should those messages say? Prior work sends either too little information (agents stay confused) or too much (the messages are wasteful). This paper uses an LLM—a language model trained to reason—to automatically design a protocol that tells each agent exactly what it needs to hear to rebuild an accurate model of the entire shared state.

Zero assumption version

Why agents stay confused

Imagine two robots moving boxes in a warehouse. Robot A can see the door and the shelves nearby. Robot B can see the loading dock and boxes in the back. Neither can see the whole space. When they move a box together, they need to agree on where it is and where to put it next. If they just yell out whatever they see, the messages might miss details that matter for success—like whether the loading dock is occupied—or they might send redundant data that wastes time.

Prior communication methods either trust agents to figure out what to send (they guess wrong and send useless chatter) or they rely on sending everything (which floods the network). Both fail: agents end up with different understandings of the state, so they make conflicting decisions.

The paper's move in one sentence. Use an LLM to design the protocol: instead of hand-coding what to send, ask the LLM to write a protocol such that when all agents follow it, each one hears enough to build an accurate picture of everything that matters.

What the paper changes

What the paper changes

The paper changes the communication protocol—the rules that decide what each agent broadcasts to the others. Instead of hand-coding this protocol (or leaving it to chance), the paper lets an LLM design it automatically.

The hidden quantity

State reconstruction uniformity

measured quantity  =  how evenly each agent rebuilds the state

This paper measures an often-invisible quantity: how much does each agent's estimate of the full state differ from the true state, and do all agents agree with each other? Prior work never measured this clearly. The paper calls this state awareness—it is the combination of accuracy (did each agent recover the truth?) and uniformity (do all agents have the same picture?). Without measuring it, you do not know if your protocol is working. The paper estimates it by simulating the agents' reconstruction step and comparing each agent's rebuilt state to ground truth.

Why it works

Why an LLM design beats hand-coded rules

The state has structure—some information matters for coordination (positions of nearby objects), other information is just noise (exact timestamps). A human would struggle to hand-code this, especially across many different domains (soccer, warehouse, traffic). An LLM, trained to reason about natural language descriptions of states and actions, can figure out which pieces of information actually matter for agents to coordinate.

Here is the real causal chain: (1) The LLM reads a description of the multi-agent task (what are the agents, what can each see, what matters for success). (2) The LLM reasons about what each agent needs to know to decide its next action—this is the sufficient state for that agent. (3) The LLM writes a protocol: a set of rules (in natural language) saying what information each agent must communicate. (4) Agents run this protocol, sending compact messages shaped by the LLM's reasoning. (5) The paper measures how well each agent recovered the hidden state. (6) If reconstruction is uneven or inaccurate, the paper shows this gap back to the LLM, which refines the protocol—adding detail to lagging agents or cutting redundancy. (7) The loop repeats until all agents have equal, accurate state pictures. The reason this beats prior work: the LLM's reasoning is adaptive and explicit about trade-offs (which information to prioritize), whereas hand-coded protocols are static and often miss the structure.

Math after the picture

State reconstruction loss

First in words:

The goal is to minimize a loss function that penalizes two things: how wrong each agent is about the true state, and how much they disagree with each other. The loss is the sum over agents of the squared difference between each agent's rebuilt state estimate and the true state, plus a term that pushes all agents to agree.

Then the compact form:

loss = sum_i ||state_hat_i - state_true||^2 + beta * sum_i,j ||state_hat_i - state_hat_j||^2

Every symbol:

state_hat_iagent i's rebuilt estimate of the full state
state_truethe actual true state of the world
betaa weight controlling how much to penalize disagreement among agents
sum_iadd up the error for every agent
sum_i,jadd up pairwise disagreement between all agent pairs
||·||^2squared distance: how far apart two states are
A tiny worked example
Suppose 2 agents, true state = [100, 200] (two positions).
Agent A rebuilds [100, 195] using the protocol messages; error = (0)^2 + (−5)^2 = 25.
Agent B rebuilds [98, 200]; error = (−2)^2 + (0)^2 = 4.
Sum of reconstruction errors: 25 + 4 = 29.
Disagreement between A and B: ||(100−98, 195−200)||^2 = 2^2 + (−5)^2 = 29.
With beta=1, loss = 29 + 1*29 = 58.
If the protocol is improved and both now rebuild [100, 200]: errors = 0 + 0 = 0, disagreement = 0, loss = 0.

What can go wrong

What can go wrong

LLM misunderstands the task. If the task description is vague, the LLM may design a protocol for the wrong state—it transmits information that does not matter or misses critical details. Agents then build a false shared picture and fail to coordinate.
State is too large or complex. If the true state has thousands of dimensions (e.g., every pixel in a video), the LLM's protocol may reference information no agent can actually extract from their observation. Messages become impossible to fill.
Communication channel is bottlenecked. If messages must be extremely short (limited bandwidth), the protocol cannot fit all the information the LLM wanted. Some agents will still be blind to critical parts.
Protocol does not generalize. If the LLM's protocol is tuned to one specific scenario, it may fail when the task changes (new obstacle layouts, new goal types). The written rules do not transfer to different settings.
Protocol optimized well. When the LLM iterates with explicit feedback on reconstruction quality and agents have enough bandwidth to send the needed messages, the LLM refines which information to prioritize, so the protocol slowly eliminates gaps in what agents know about each other; once all agents have the same accurate picture, they make aligned decisions instead of conflicting ones, so coordination succeeds.
What a runnable demo should prove

What a runnable demo should prove

Build a simple multi-agent coordination task: two agents must push a box to a goal, but each agent sees only one half of the arena. (1) Implement a hand-coded baseline protocol (e.g., agent A always sends its observed position, agent B sends its velocity). (2) Implement the LMAC pipeline: give an LLM a plain-language description of the arena and the agents' partial views, and ask it to write a protocol. (3) For each protocol (baseline and LLM-designed), measure how well each agent reconstructs the full arena state, and how much they disagree with each other. (4) Run both protocols on the pushing task and measure task success (did they push the box to the goal?). (5) Tweak the LLM's protocol feedback manually: give it a report showing which state aspects the agents got wrong, and ask it to refine the protocol.

success_rate = (final_box_distance_to_goal < tolerance) / num_trials; reconstruction_quality = 100 * (1 - mean_squared_error) / max_error

The demo must show that the LLM-designed protocol cuts both reconstruction error and agent disagreement more sharply than a fixed hand-coded protocol, and that coordination on the actual task improves as a result.
