MemoryVLA: Teaching Robots to Remember

A robot's brain works best when it keeps a separate scratch pad for right now and a mental filing cabinet for what happened before.

Paper explainersAll themesRobotics & Control

Robots struggle with long tasks that span many steps over time. A regular vision-language-action model sees only the current frame and forgets what it saw moments ago, like trying to pick up a tool while looking only at the table in front of you, with no memory of whether the tool was just there. MemoryVLA mimics how human brains work: it gives the robot a working memory (short-term, for the next move) and a memory bank (long-term, storing details and lessons from earlier steps), so it can look back and understand what to do next.

Zero assumption version

Why robots forget mid-task

When you pick up a coffee cup, your brain holds a running memory: where you just saw the cup, what it looked like, and whether it was full or empty. A robot trying to do the same thing without memory sees only the camera frame right now. It has no idea if it already moved its arm, what obstacles were nearby, or why it started reaching in the first place.

A naive approach is to give the robot every past video frame at once, stacked like a pile of photos. But this explodes in cost: when you look at all pairs of images to understand relationships between them, the cost grows by the square of the number of frames. Show 100 frames and you are doing 10,000 comparisons. Show 1,000 frames and it is useless. The robot runs out of memory trying to count.

A deeper problem sits underneath: VLA models are trained on single-frame snapshots from teleoperated robots, so they expect one clean image per decision. Feed them a time-ordered sequence of frames and you are pushing them outside their comfort zone. The model's reflexes misfire.

The core problem. Robots need to remember what happened before in a way that does not explode in cost, and in a form the model recognizes.

The algorithm as a flow

What it actually does

Encode the now

Camera and language instruction become perceptual tokens (details) and cognitive tokens (meaning).

Ask for history

Working memory queries the memory bank: what did I learn that is useful right now?

Fuse past and present

Attention layers blend retrieved details and meanings with current tokens, weighted by relevance.

Update the bank

Consolidate tokens, merging overlapping memories so the bank stays compact and smart.

Act

Diffusion denoiser (a module that refines fuzzy action plans into real moves) uses blended memory to generate the next step.

What the paper changes

What the paper changes

Instead of showing the robot one frame at a time, or trying to pack all past frames into one giant brain, MemoryVLA splits the job: working memory holds just the current tokens (today's visual details and the language goal), while a separate memory bank stores a compressed history (key details and high-level meanings from earlier steps).

The hidden quantity

The hidden quantity: Relevance

measured quantity  =  Which memory entries are relevant right now

The robot cannot remember everything it has ever seen—even with a memory bank, it needs to know which pieces matter for the current move, because pulling in random old memories would confuse the decision, like asking a robot to place a cup while showing it memories of picking up a fork. Relevance measures how well a past memory matches the current situation. The robot asks: given what I see and the language instruction right now, which of my stored memories are similar enough to help me decide what to do? It asks because only memories from similar situations will teach the right motor move.

The paper estimates relevance using attention (a mechanism that compares the current tokens to all stored memory entries and outputs a weighted score for each). When the current perceptual tokens (visual details) and cognitive token (what the instruction means) query the memory bank, attention computes which stored entries look most similar to what the robot is doing now. Entries that match get high scores; entries from unrelated earlier tasks get low scores. The robot then retrieves and blends the high-scoring memories.

Paper reading. At each timestep, working memory (current perceptual and cognitive tokens) acts as dual query lists (each token is a list of numbers) to a Perceptual-Cognitive Memory Bank via cross-attention. The attention operation retrieves entries where the query list is similar to the stored key list, weighted by the stored value. This is how modern neural networks score which memories match what is happening now.
Why it works

Why splitting memory into now and then works

The human brain does exactly this: working memory (activity in visual and prefrontal cortex) holds what you are looking at and thinking right now, and you can handle about 7 items at once. When you need more information, you retrieve it from long-term episodic memory (the hippocampus stores details) and semantic memory (the neocortex stores meanings and rules). MemoryVLA copies this split.

Working memory stays small—just the current tokens from the vision and language model. This means self-attention (comparing all tokens to understand relationships) runs fast because there are not many tokens. When the robot needs historical context, it does not compute attention over 1,000 old frames. Instead, it uses the current tokens as a query to retrieve only the relevant entries from the memory bank. This is much cheaper because comparing one query to a few retrieval keys costs far less than comparing many-to-many: if you look at 10 past moments instead of 1,000, you do 100 comparisons instead of 1 million, a 10,000x speedup.

The memory bank stores two kinds of information: perceptual (low-level details like colors, positions, textures) and cognitive (high-level meanings like cup is grasped or table is cluttered). When the robot retrieves a past moment, it pulls both. Perceptual details let it see what the world looked like; cognitive information tells it what that visual situation meant for control. Attention weights the fusion, so relevant entries steer the robot's decision and irrelevant ones fade out.

Finally, the bank consolidates itself: when new memories arrive, the system merges redundancies (if two stored moments say the same thing, keep one) instead of growing unbounded. The bank shrinks without losing information.

Retrieving from memory via attention

First in words:

Attention-score for entry comes from softmax: take the similarity between current token and stored key, scale it down, then convert to a weight between 0 and 1 using softmax

Then the compact form:

H_x = softmax( q_x * K_x^T / sqrt(d_x) ) * V_x, where q_x in {perceptual, cognitive}

Every symbol:

q_xcurrent perceptual or cognitive token (query); what the robot is looking for now
K_xstored memory entry keys; compressed representations of past observations
V_xstored memory entry values; full perceptual or cognitive details from the past
d_xthe vector length (how many numbers encode each token); used to scale similarity scores
H_xretrieved embedding; the past information weighted by how relevant it is to now
A tiny worked example
Suppose working memory has a perceptual query as a list of numbers: [0.5, 0.3]. Memory bank has three past entries with key-lists: [[0.4, 0.2], [0.1, 0.8], [0.6, 0.1]].
Compute similarity scores: 0.5 times 0.4 plus 0.3 times 0.2 equals 0.26; similarly 0.29 and 0.33 for the other two entries.
Scale the scores: divide each by about 1.41 (a normalizing factor). Scores become 0.184, 0.206, 0.234.
Convert to weights that sum to 1: roughly 0.31, 0.33, 0.36. These fractions tell us how much to trust each past entry.
Entry 2 gets weight 0.36 (highest). The robot pulls in its stored details most strongly, blends in the others, and acts on the combined memory.

The dot product measures how similar query and key are. We then convert raw similarity scores into weights that sum to 1 (so each memory pulls with a share of influence), meaning relevant memories pull harder on the decision than irrelevant ones.

What can go wrong

What can go wrong

Memory bank grows unbounded. If the consolidation step (merging redundant entries) does not work well, the bank fills with duplicate memories. Queries get slower and noisier; the robot forgets what actually matters.
Attention retrieves the wrong memories. If current tokens do not encode the task clearly enough, or if memory entries were stored poorly, attention may pull in memories from an old unrelated task. The robot acts on irrelevant history and fails.
Fusion layer mixes past and present badly. If the gate that decides how much to trust each memory entry is broken, the robot either ignores history (learning nothing) or trusts it blindly (repeating old mistakes even when the task changed).
Done right. The memory bank stays lean through consolidation. Attention retrieves only high-scoring entries. The fusion gate gives more weight to relevant memories and less to noise. The robot learns from the past without being trapped by it.
What a runnable demo should prove

What a runnable demo should prove

Build a simple 10-step robot task: move to a tool, pick it up, move to a target, place the tool. The robot must remember that it picked up the tool (step 2) when deciding how to place it (step 9). Run two versions: one without any memory (baseline), and one with working memory plus a tiny memory bank (5 entries). At each step, log which memory entries the attention layer retrieved and their relevance scores. Show visually (a bar chart or heatmap) how relevance changes step by step. On the last step, the baseline should either fail or guess randomly; MemoryVLA should retrieve entries 1 and 2 (tool pickup, task instruction) with high weight and place the tool correctly.

success = 1 if robot places tool within 5cm of target after retrieving past memories; 0 otherwise. Show: (baseline success rate, MemoryVLA success rate, average retrieval weights for step 9).

The core proof: when the robot needs to remember, attention retrieves the right moments, weights them highly, and success follows. When there is no memory, success vanishes on long tasks.
