SLAP: Learning shortcuts in robot planning

Instead of waiting for a programmer to hand-code each robot motion, this method lets robots teach themselves new tricks by finding shortcuts through the moves they already know.

Paper explainersAll themesRobotics & Control

Robot planning has long relied on humans hand-coding behaviors: pick an object, place it down, move an arm. But real robots improvise constantly—they slap things to nudge them, wiggle around obstacles, wipe surfaces. This paper asks: can robots discover these shortcuts automatically by watching how their known moves connect, then learning to combine them in new ways? The answer is yes.

Zero assumption version

The robot is stuck with only what programmers teach it

A robot that sorts objects needs motions: pick it up, place it down, move to a new spot. A programmer writes code for each. But real tasks are messier—sometimes an object is wedged and needs a quick slap; sometimes it can't fit the normal way and needs a wiggle. The programmer did not plan for this.

A naive robot would try to learn everything from scratch with reinforcement learning (a system where the robot tries moves and gets rewards for success). This is slow and often fails on long tasks, because the robot wastes time re-inventing basic motions like picking. It has no head start.

The problem in one sentence. Robots can only do what programmers code, and learning from scratch is slow.

What the paper changes

What the method changes

The paper adds new behaviors (called options in robotics) on top of the ones the programmer already wrote. Instead of asking the programmer to code each new behavior, the system builds a graph showing how the old behaviors chain together, then uses learning to train new behaviors that shortcut through multiple old ones.

the object it moves  =  The option library
The hidden quantity

The hidden quantity: shortcut potential

measured quantity  =  How direct each path is

Every time two or more moves chain together (e.g. move, then pick, then move again), they create a path. Some paths are roundabout; some are direct. The hidden quantity the paper measures is how much each sequence of moves shortens the overall task. Chains that reach the goal in fewer steps are more valuable than random exploration, because the robot wastes fewer attempts and reaches success sooner.

The method uses model-free reinforcement learning (the robot learns by trying moves and getting rewards for progress) to estimate this. It runs the robot on many attempts with different chains, counts how many steps each chain takes to finish, and identifies chains that consistently reach the goal in fewer steps. Then it trains the robot to repeat those chains.

Why it works

Why shortcuts work: you get a head start

Normally, learning a new robot behavior from scratch means the robot tries random moves until it stumbles on something that works. That is slow. But if the robot already knows pick, place, and move, then a new behavior that chains these together starts with a huge advantage: each sub-move is already smooth and practiced. The learning process only has to learn how to time and sequence them.

The method builds a graph of these existing moves (the abstract planning graph). Then it looks for chains where combining moves reaches goals in fewer steps than random attempts. Reinforcement learning trains these shortcuts, treating them like new single moves. Learning a shortcut is much faster than learning from scratch, because the building blocks are already solid—each sub-move is stable, so the learner only adjusts timing and sequence, not the underlying motion quality. This reduces the search space enormously.

Math after the picture

The value equation

First in words:

The learning reward for a shortcut is the total future reward minus the cost of running the old moves; when the shortcut finishes sooner, the reward is higher.

Then the compact form:

R_shortcut = sum_t gamma^t * r_t - cost_of_chain

Every symbol:

R_shortcutThe total reward value learned for this chain of moves
sum_t gamma^t * r_tSum of rewards discounted by how far in the future they arrive (gamma = 0.99)
r_tReward at time step t (1 if goal reached, 0 otherwise)
cost_of_chainThe number of underlying moves the chain uses
A tiny worked example
Chain A: move -> pick -> place. Reaches goal in 3 steps. Reward = 1 * (0.99^0 + 0.99^1 + 0.99^2) - 3 = 2.97 - 3 = -0.03.
Chain B: slap -> pick. Reaches goal in 2 steps. Reward = 1 * (0.99^0 + 0.99^1) - 2 = 1.99 - 2 = -0.01.
Chain B finishes sooner, so the discounted reward decay is smaller, making its net value higher. Learning picks Chain B as the shortcut.

A shorter chain is worth more, because the discount factor (0.99) means future reward is penalized, so finishing faster preserves value.

What can go wrong

What can go wrong

The graph is too big. If the programmer has coded 20 moves, the number of possible chains explodes (many shortcuts to try), and learning becomes slow. The method works best with 3-7 base moves.
A shortcut breaks in a new task. A chain trained for one task (sorting cups) might fail on a different task (stacking boxes), because the physical setup is different—different heights, distances, object shapes. The robot has to re-learn or re-tune shortcuts for each class of task.
Shortcut training destabilizes the original moves. If learning nudges the neural network weights too hard, the adjustments can degrade the original pick or place moves (the algorithm learns by nudging weights in the direction that reduces training error—if the nudge is too large or misaimed, it breaks what already worked). The paper mitigates this by protecting the base move weights during training and learning only the new shortcut weights.
Done right. Keep the base moves frozen; train only the new shortcuts. Use model-free RL with modest learning rates. Test on new task variants early to catch overfitting.
What a runnable demo should prove

What a runnable demo should prove

Take a robot that knows pick, place, and move (three basic motions). Give it a task: move object A from bin 1 to bin 3, but object B is in the way. Run SLAP and watch it discover a shortcut (e.g. push object B out of the way first, using a combination of move and slap). Measure how many steps the plan takes and how often it succeeds. Then remove the shortcut library and retrain the same task from scratch with plain reinforcement learning (the robot invents all behaviors by trial and error). The demo should show that SLAP learns 3-5x faster, because shortcuts build on practiced moves instead of inventing them, and plans are shorter, because shortcuts skip redundant intermediate steps.

Discovery speed ratio = (steps to convergence from scratch) / (steps to convergence with SLAP)

When the demo shows SLAP converging in 500 learning steps versus 2000 from scratch, it proves that shortcuts built on existing moves are a real head start.
