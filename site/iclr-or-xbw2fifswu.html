CauKer: Time Series Models Trained on Synthetic Data

Instead of spending weeks collecting and curating real time series for training, generate fake ones that are cheap and still teach the model to work on real data.

Paper explainersAll themesTime Series & Sequential

A time series foundation model (a large model trained to read sequences of numbers over time) normally requires weeks of work collecting and cleaning real-world data before it can be trained. This paper introduces CauKer, a tool that generates diverse fake time series data that looks realistic—with trends, seasonal patterns, and complex relationships—and can pretrain these models just as well as real data, but at a fraction of the cost and time. It works by combining two ideas: Gaussian Process kernels (a method to build realistic patterns by mixing trends, cycles, and noise) and Structural Causal Models (a way to encode how one number in a sequence causally influences another over time).

The expensive pretraining trap

A time series foundation model is a large machine-learning model trained to understand sequences—like stock prices, sensor readings, or weather data—that unfold over time. Before such a model can work on real data, it must be trained on a huge collection of examples, usually hand-picked and cleaned from real-world sources. Collecting and curating this data takes months and costs hundreds of thousands of dollars.

A naive approach: just grab raw real-world sequences and train on them. This breaks because real data is expensive to obtain, noisy, and often lacks the systematic variety the model needs to learn general patterns. You end up training slowly and inefficiently, needing far more examples than you should.

The paper's move in one sentence. CauKer generates synthetic time series that look realistic and causally coherent, so you can pretrain the model on cheap fake data instead of expensive real data.

The algorithm as a flow

What it actually does

Step 1: Define causal relationships

User specifies how time-series components causally influence each other.

Step 2: Combine Gaussian Process kernels

CauKer mixes standard patterns (trend, seasonality, noise) to build realistic individual sequences.

Step 3: Inject causal structure

The Structural Causal Model ensures one sequence causally affects another in realistic ways.

Step 4: Generate diverse samples

Sample repeatedly from these combined patterns to create thousands of varied synthetic sequences.

Step 5: Pretrain the model

Train the foundation model on synthetic data; it learns patterns that transfer to real sequences.

What the paper changes

The object that moves

CauKer changes the data itself—specifically, what training examples are fed into the foundation model. Instead of using real-world sequences collected by humans, it uses computationally generated synthetic sequences. The generation process is controlled: the user can specify causal relationships and diversity constraints, ensuring the fake data has realistic structure.

the object it moves  =  training data
The hidden quantity

The causal coherence score

measured quantity  =  Causal structure preservation

The hidden quantity CauKer measures is how faithfully the generated synthetic data preserves the causal relationships specified by a human. Causal coherence means: if the user says signal A causally drives signal B, then changes in A should reliably precede and explain changes in B in the synthetic data. A signal with low causal coherence has artificial patterns that do not reflect real cause-and-effect.

The paper estimates this by embedding a Structural Causal Model (a graph describing which signal causes which) into the Gaussian Process kernels, so that when data is sampled, the causal relationships automatically flow through. This is checked by verifying that learned models trained on the synthetic data generalize to real sequences—if causal structure is wrong, generalization fails.

Why it works

Why combining kernels and causal models works

A Gaussian Process kernel is a mathematical tool that generates smooth, realistic patterns—like an upward trend, a repeating seasonal cycle, or noise that clusters in time. Alone, a kernel produces a single signal. To make a single time series feel real, you mix several kernels: one for the main trend, one for seasonality, one for random noise. This is step one.

Structural Causal Models add the second dimension: they encode which signal causally influences which. If you say signal B depends on signal A with a 5-step delay, the SCM bakes that relationship into the data generation. The trick is composing the kernels according to the SCM: when you sample signal A, that sample determines signal B's kernel parameters, so B actually depends on A. Result: a synthetic dataset where causal relationships are embedded, not accidental.

This works because models learn patterns from data. If the synthetic data has realistic trends, seasonality, and true causal relationships, a model trained on it learns those patterns. When the model encounters real data—which has the same kinds of trends and causal relationships—the learned patterns transfer. The model does not overfit to noise or artifacts because the synthetic data was built to avoid them.

The core equation

First in words:

The total synthetic sequence is built by adding kernel components weighted by their importance. If a kernel captures trend, it gets a high weight; if it captures rare noise, it gets a low weight. The weights are set so that causally upstream signals influence downstream signals.

Then the compact form:

y_t = w_trend * k_trend(t) + w_season * k_season(t) + w_noise * epsilon_t + sum_j w_j * f_j(x_j, t - delay_j)

Every symbol:

y_tThe synthetic value at time step t
w_trendWeight for the trend component, typically high
k_trend(t)The trend kernel evaluated at time t, e.g., a slow upward curve
w_seasonWeight for seasonality, e.g., 0.3
k_season(t)The seasonal kernel, e.g., a repeating sine wave
w_noiseWeight for random noise, typically low
epsilon_tRandom noise at time t, drawn from a normal distribution
w_jWeight for causal influence from signal j
f_j(x_j, t - delay_j)Function mapping signal j's past value to influence on current signal, with delay
x_jThe causal parent signal j
delay_jHow many time steps signal j lags before affecting current signal
A tiny worked example
Time step t = 10, building a synthetic weather sequence.
Temperature at t=10 = 0.7 * (base_temp + 2*t) + 0.2 * sin(2*pi*t/365) + 0.1 * noise
= 0.7 * (20 + 20) + 0.2 * sin(0.17) + 0.1 * 0.5
= 0.7 * 40 + 0.2 * 0.17 + 0.05
= 28.0 + 0.034 + 0.05 = 28.084 degrees
Humidity at t=10 (depends causally on temperature with 2-step lag):
= 0.5 * humidity_trend(t) + 0.3 * temp(t-2) / 30 + 0.2 * noise
= 0.5 * 60 + 0.3 * 26 / 30 + 0.2 * 0.3
= 30 + 0.26 + 0.06 = 30.32 percent
The humidity responds to the temperature from 2 time steps earlier, encoding a realistic causal delay.

Each component (trend, season, noise, causal influences) contributes a weighted fraction; the result is a realistic synthetic sequence where causes precede effects.

What can go wrong

What can go wrong

Causal structure mismatch. If the causal graph is wrong (e.g., you say B depends on A when actually A depends on B), the synthetic data will encode nonsense. The model learns invalid patterns and fails on real data.
Kernel parameters not representative. If the trend or seasonal kernels do not reflect the real data's actual ranges or cycles, the synthetic sequences stay artificial. A kernel that produces only trends between 10-20 when real data spans 0-100 creates a mismatch.
Too little diversity. If the generator only produces sequences that look alike (e.g., all have the same trend slope), the model underfits; it has not seen enough variety to generalize.
Delays and coupling ignored. Real time series often have lag: a stock price drop today affects trading volume tomorrow. If CauKer does not encode these delays correctly, causal relationships break down.
Done right. Specify the causal graph truthfully, set kernel ranges to match real data bounds, ensure the generator samples diverse combinations, and validate that models pretrained on the synthetic data transfer well to held-out real sequences.
What a runnable demo should prove

What a runnable demo should prove

A minimal demo should: (1) Define a simple three-signal causal structure (signal A is a root cause, signal B depends on A with a 2-step lag, signal C depends on B); (2) Use CauKer to generate 10,000 synthetic time series following that structure; (3) Train a small time-series classifier (e.g., a model with 100,000 parameters) to classify the synthetic data (e.g., high vs low trend); (4) Test that trained model on a held-out set of real time-series data (e.g., from a public benchmark like UCR time-series archive); (5) Measure classification accuracy. The demo must show that accuracy on real test data is higher than a baseline model trained on a smaller amount of real data, proving that synthetic pretraining transfers.

transfer_gain = accuracy_pretrained_synthetic - accuracy_scratch_real

The demo is not complete unless it proves that a model pretrained on CauKer synthetic data outperforms a model trained from scratch on real data alone. This is essential because if pretraining on synthetic data does not improve accuracy or if it only works on particular datasets, the claim that synthetic pretraining transfers collapses.
