CB-SLICE: Finding Error Slices via Concept Bottlenecks

Instead of guessing why a model fails on certain groups, trace the failure back to specific concepts the model got wrong.

Paper explainersAll themesInterpretability

When a machine learning model works on average but fails on certain subgroups, it is hard to know why. Most debugging methods guess at reasons disconnected from how the model actually thinks. This paper uses a model that works through human concepts — like shape or color — as a lens to find exact groups of similar failures and name the concepts that went wrong.

Zero assumption version

The debugging trap: average hides group failures

A model might be 90 percent accurate overall but completely fail on one group — say, images with unusual lighting. The average number hides this disaster.

Debugging tools exist, but they guess at reasons: they look for patterns in pixels or raw features the model never directly uses. A model that thinks through concepts (shape, texture, color) never looks at the raw pixel patterns debugging tools point to. So the explanations are wrong, and you do not fix the real bug.

The problem in one sentence. Existing error discovery methods explain model failures by looking at things the model does not care about, so the explanations miss the actual cause.

The algorithm as a flow

What it actually does

Build a concept model

Train a model that predicts task labels via explicit human-readable concepts, not raw features.

Find concept mispredictions

On data you are debugging, check which samples got concept predictions wrong.

Group by shared mistakes

Cluster samples that share the same concept misprediction pattern (all got color wrong, or all got shape wrong).

Rank concepts by damage

For each cluster, score which concept errors hurt final accuracy the most.

Report actionable slices

Name each failure group and the concept responsible, giving you a fix target.

What the paper changes

What the paper changes

Existing methods scan raw data (images or text) to find failing groups. This paper instead scans concept predictions — the model's own intermediate thoughts — to find failing groups. You get explanations anchored in what the model actually thinks.

The hidden quantity

The hidden quantity: concept prediction quality

measured quantity  =  concept accuracy per sample

For each sample and each concept, the model outputs a prediction: is this image red, or not red. The hidden quantity is how often this concept prediction is correct, measured within each subgroup of samples.

CB-SLICE finds groups where a specific concept prediction stays wrong consistently. High-quality concept predictions would fix the task error; bad concept predictions are the root cause the paper targets.

Why it works

Why tracing through concepts finds real errors

A concept-based model is a chain: raw image input to concept predictions to final task output. When the final output is wrong, one link in that chain broke. Concept predictions are that middle link. If you track where concept predictions go wrong, you find the actual fracture, not a symptom.

Existing methods look at the raw input and guess at patterns. They bypass the model's own reasoning. CB-SLICE instead follows the model's actual thought process: it asks which concept the model mispredicted and groups all samples with that same misprediction. This produces slices grounded in the model's real decision path, so the explanations are faithful — they actually point to what the model got wrong.

The grouping and scoring equation

First in words:

For each concept and each sample, measure whether the concept prediction matched the truth. Group samples by shared concept misprediction patterns. For each group, score the importance of each concept by how much fixing that concept would reduce the group's error rate.

Then the compact form:

slice_importance(c) = (error_rate_with_c_wrong) - (error_rate_if_c_were_fixed)

Every symbol:

ca single concept (like color or shape)
error_rate_with_c_wrongfraction of samples in the slice that fail when concept c is mispredicted
error_rate_if_c_were_fixedestimated error rate in that slice if concept c predictions were corrected
slice_importance(c)how much that concept's failure contributes to the slice's overall error
A tiny worked example
Slice A: 100 samples, all got color prediction wrong, 80 percent fail the task.
Without the color error, we estimate 30 percent would still fail (maybe shape is also wrong for some).
So slice_importance(color) = 80 - 30 = 50 percentage points. Color is the heavy hitter.
Slice A: shape prediction also wrong for some samples, but only 10 percent fail only because of shape.
slice_importance(shape) = 10 - 0 = 10 percentage points. Shape matters less for this slice.
Report: Slice A is broken by color misprediction (50pts), and secondarily by shape (10pts).

The equation ranks concepts by damage within each failure slice, so you know which concept to fix first to unlock that group.

What can go wrong

What can go wrong

Concept annotations are noisy. If the human labels for concepts are wrong, you will group samples around a false signal. You are only as good as your concept labels.
Concept model may be unable to separate concepts from the task. Some domains mix concepts and task labels tightly. If the concept model can not learn independent concept predictions, the slices reflect noise, not real failure modes.
Clustering algorithm may lump unrelated misses. If samples fail from different concepts but the clustering algorithm groups them together anyway, you get a confused slice that does not pinpoint the real issue.
Done right. Use clean, well-validated concept labels; fit the concept model on trusted data; validate that concept predictions correlate with task performance; and use a careful clustering step that respects concept boundaries.
What a runnable demo should prove

What a runnable demo should prove

Build a simple image classifier with a concept bottleneck (concepts: red, smooth, large). Train it on a biased dataset where red objects are mostly dogs and smooth objects are mostly cats. Introduce a group failure: images with unusual lighting where the concept predictor fails on color. Run CB-SLICE on held-out data and verify it identifies the failure slice as primarily caused by the color concept misprediction.

concept_faithfulness = (fraction of task errors explained by the top-ranked concept misprediction)

If concept_faithfulness is above 70 percent, you have found a real slice: most errors in that group trace directly to one concept mistake, not scattered guesses.
