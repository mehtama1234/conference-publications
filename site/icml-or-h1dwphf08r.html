Hierarchical Anchor Graph Learning for Multi-View Clustering

When clustering data that comes in multiple views, use a pyramid of anchors (representative samples) instead of just one layer, and let them refine each other to capture detail at every zoom level.

Paper explainersAll themesGraph & Geometric Learning

Imagine sorting through a closet full of clothes described both by texture and color. A simple approach might pick a few representative outfits once and group everything else by similarity. But the best groupings shift depending on zoom level: zoomed in, you care about fabric grain; zoomed out, you care about outfit type. This paper describes a method called HAG-MVC that builds a multi-level pyramid of anchors, letting coarser groups inform finer ones and vice versa, all while keeping the anchors readable—you can always see exactly which original samples they represent.

Zero assumption version

The frozen-anchor trap

Multi-view clustering means you have the same objects described in two or more completely different ways. A document has both text and images. A person has both their browsing history and location patterns. Your job is to group these objects into clusters—find which ones are actually the same group, even though they look different in each view.

The standard approach picks a handful of representative samples (called anchors) once at the start, then uses them as reference points to assign everything else. The problem: that one set of anchors works poorly when your data has structure at multiple scales. A few anchors tuned to catch the broadest patterns will blur the fine-grained ones. Anchors tuned to precision miss the forest for the trees.

A beginner might just run this algorithm twice, once for coarse groups and once for fine groups, then try to merge the results. That fails because there is no way to make the two pyramid levels cooperate or share what they learned about the data.

In one sentence. Build a pyramid of anchor layers where each level refines the next, so fine details and coarse structure emerge from mutual feedback, not frozen first guesses.

The algorithm as a flow

What it actually does

Build the pyramid

Create anchor layers of decreasing size: 1000 anchors at the base (fine), 100 in the middle, 10 at the top (coarse).

Connect both views to each layer

For each layer and each view, compute how similar every object is to every anchor in that layer.

Let layers talk

Use the coarser layer to constrain the finer layer and vice versa—coarse says what's in each broad group, fine sharpens within those groups.

Repeat until stable

Keep updating the anchors and the assignments, letting each layer refine the other.

Keep anchors readable

Unlike deep neural networks, every anchor stays as an original sample, so you can always look at it and understand what it represents.

What the paper changes

What the paper changes

Traditional single-layer anchor methods use one frozen set of representative samples. HAG-MVC introduces a hierarchical pyramid of anchor layers, where each layer contains anchors tuned to a different level of granularity (coarse, medium, fine), and these layers iteratively refine each other rather than being fixed at the start.

The hidden quantity

The hidden quantity: Hierarchical affinity

measured quantity  =  multi-level affinity patterns

The hidden quantity is how tightly each object bonds to each anchor at each level of the pyramid. At the coarse level, affinity is broad—many objects bond to each level-1 anchor. At finer levels, affinity narrows. This is not computed once; it evolves as layers talk to each other.

HAG-MVC estimates this by starting with raw similarity scores (how close is this object to this anchor in the original feature space for each view), then iteratively updating them to respect both the fine-grain and coarse-grain structure. The paper measures this through assignment matrices at each level—dense at coarse levels, sparse at fine levels.

Why it works

Why building a pyramid and letting layers talk works

The core insight is that grouping is fundamentally multi-scale. Objects that belong together at a coarse level might still differ in fine detail, and fine-grain clusters often fall naturally into broader families. A single set of anchors cannot capture both truths at once.

By building layers that talk to each other, HAG-MVC breaks the problem into pieces. The coarse layer identifies the big structure—which objects are truly related. Then finer layers inherit that knowledge: they do not try to cluster randomly; they refine within the coarse groups the parent layer proposed. Simultaneously, the fine layers give the coarse layer feedback: if many fine-grain assignments contradict a coarse clustering, the coarse anchors adjust to repair the mismatch, because the loss function penalizes parent-child disagreement. This mutual feedback ensures neither level is frozen in error.

Because anchors stay as real samples in the original feature space, not embedded in a deep neural network, the iterative refinement is fully interpretable: you can read the evolution, see which samples became anchors, and understand why—there is no black box hiding the decision.

The pyramid update equation

First in words:

At each iteration, update the anchor assignments by minimizing a loss that sums three things: the distance from each object to its nearest anchors across both views, a penalty that keeps each layer consistent with its parent layer, and a term that encourages fine-to-coarse hierarchy.

Then the compact form:

L = sum_i sum_v dist(x_i_v, A_v_l) + lambda_parent * sum_l_parent, l_child consistency_loss(A_parent, A_child) + lambda_hierarchy * hierarchy_constraint()

Every symbol:

x_i_vthe i-th object in view v (its features)
A_v_lthe anchor assignments at layer l for view v
dist(...)distance in original feature space
consistency_loss(...)penalty when parent and child layers disagree
lambda_parentweight of parent-child consistency
lambda_hierarchyweight of coarse-to-fine constraint
A tiny worked example
Say we have 100 objects, 3 coarse anchors, 9 medium anchors, 27 fine anchors.
Object 1 is distance 0.5 from its nearest coarse anchor (view text), distance 0.3 (view image). Contribution: 0.5 + 0.3 = 0.8.
But object 1's coarse assignment says 'group A' and its fine assignment says 'group Q' which is supposed to be in group A. Consistency says they agree. If they conflict, add a penalty: e.g. +0.2.
Same for 100 objects: total L = 85 (distances) + 12 (parent-child mismatch) + 3 (hierarchy constraints) = 100. Optimization updates anchors to lower L.

The key is the middle term: it forces parent and child layers to stay aligned, so neither drifts into useless structure.

What can go wrong

What can go wrong

Pyramid too tall. If you build too many layers, fine layers might over-fit to noise, treating random fluctuations as real structure. Each layer adds complexity.
Views have very different scales. If one view (e.g., raw pixel intensities) is numerically huge compared to the other (e.g., a category code), the distance calculation will be dominated by the louder view. Normalize both views first.
Parent layer too coarse. If the parent layer misses a real distinction (e.g., groups two truly separate families), the child layers cannot recover because they are constrained to refine within parent groups.
Done right. Carefully choose the number of anchors at each layer so that each level captures genuine structure. Use domain knowledge and validation data to check that coarse and fine groups both make sense.
What a runnable demo should prove

What a runnable demo should prove

Build a small clustering demo on a two-view toy dataset (e.g., images labeled with text, or people described by browsing history and location). Implement single-layer anchor clustering, then implement HAG-MVC with 3 pyramid levels. Run both, measure cluster purity (did objects in the same cluster actually belong together?) at each level for both methods. Show that HAG-MVC's coarse level is as pure as the naive method at coarse scale, but HAG-MVC's fine level is much purer than the naive method's fine assignments—the difference should be large and unmissable.

purity_l = (sum_over_clusters sum_over_samples in cluster assigned_to_correct_group) / total_samples

The demo must make clear that a pyramid is not just a deeper network—it is a coordination mechanism where each layer has explicit authority at its own scale, and layers negotiate through feedback, not through a learned number-list buried inside a neural network.
