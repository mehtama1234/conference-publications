Flow Straight and Fast in Hilbert Space: Functional Rectified Flow

You can teach a neural network to directly straighten curved paths through infinite-dimensional function spaces, making generative models faster and more accurate for high-dimensional data.

Paper explainersAll themesGenerative Models & Diffusion

Generative models learn to create new data by following paths through spaces where each point is a list of numbers. Rectified flow is a technique that straightens these paths: instead of a model learning to remove noise through many different steps with different strategies, it learns one single direction and follows it from noise to reality in a straight line, making training more stable because the network can specialize. This paper extends that idea to work on infinite-dimensional spaces, where each point is not just a list but an entire function (like an image at every detail level). The extension removes old mathematical restrictions by correctly counting contributions from infinitely many dimensions at once, and gives better results because the infinite-dimensional math is now rigorous.

Why the old tricks do not scale to infinite dimensions

Most generative models work in ordinary spaces: you have a point with a fixed number of coordinates, and you adjust those coordinates to make new examples. Diffusion models use random noise and gradually denoise it. Rectified flow does something smarter: it learns the shortest straight path from noise to real data, so denoising becomes a straight line instead of a curvy wandering path.

But real data is often infinite-dimensional. An image is not a single point; it is a function (pixel values at every location, at every detail level). Sound is pressure over time. Weather is temperature and pressure over a whole region. When you treat these as functions, you have infinitely many coordinates. The old techniques built for finite spaces break down: the math assumes you can list all coordinates, sample them one at a time, and sum their contributions. None of that works when there are infinitely many, because you cannot literally add up infinitely many separate pieces—you need a special rule that counts them all fairly at once.

In one sentence. The paper teaches rectified flow to work on infinite-dimensional function spaces by using a mathematical rule that counts how infinitely many tiny pieces add up without needing to list each one.

The algorithm as a flow

What it actually does

Step 1: Ask the right question

What is the straight line connecting noise and real data in a space of functions?

Step 2: Write down the rule for motion

Describe how the function must change as time passes, using a rule (continuity equation) that counts what flows where.

Step 3: Count contributions correctly

Use a summing rule (from calculus on infinite spaces) that adds up how every infinitesimal piece contributes to motion, without listing each piece.

Step 4: Train the model to find the path

Teach a neural network to estimate the direction the function should move at each step, by comparing its predictions to real paths and penalizing curves.

Step 5: Generate new data by following the path

Start with random noise and follow the learned directions from step to step, reaching realistic data quickly because the path is straight.

What the paper changes

What the paper changes: the path straightness

The paper modifies how a neural network learns the shape of optimal paths through infinite-dimensional spaces. Instead of approximating curvy paths (as diffusion does), it learns to approximate straight lines. This single change cascades: straight lines mean fewer steps to generate, fewer steps mean faster creation of new data because there is less computation, and fewer steps also mean more accurate training because the model does not have to learn as many different behaviors.

The hidden quantity

The hidden quantity: the direction of motion

measured quantity  =  Velocity field

At each point along the path (each intermediate function between noise and real data), there is a direction the function should move next. This direction is the velocity field. In finite dimensions, it is a list of numbers showing how to adjust each coordinate. In infinite dimensions, it is a rule (a function) showing how to adjust the value at each location in space.

The paper estimates this velocity field by training a neural network to predict: given a function halfway between noise and reality, in which direction should it shift to stay on the straight path? The network learns this from examples of real paths, and once trained, it can generate new functions by following its learned directions.

Why it works

Why straightness works: less work, less error, more accuracy

A straight path is the shortest path between two points. When a generative model follows a shorter path, it needs fewer steps (say 50 instead of 1000) to reach the goal. Fewer steps means faster generation because there is less computation, and also fewer opportunities for the model to make mistakes along the way.

Fewer steps also lets the model focus. In diffusion models, the model must learn different repair behaviors at different stages: early on, you are removing coarse noise; later, you are refining details. Each stage asks the model to do a different job, so the network has to split its capacity across many different strategies and training becomes messy (the model keeps switching modes). With a straight path where every step moves in the same direction, the model learns one consistent skill: which way to nudge the function to get closer to reality. Learning one skill repeatedly is easier because the network can specialize, so training is more stable (the model does the same job every step, not switching) and the final result is more accurate (no wasted capacity on unused modes).

The extension to infinite dimensions preserves this benefit. Real data lives in infinite-dimensional spaces: an image is infinitely many pixels (in principle), not a fixed small list. If you tried to approximate by truncating (cutting off the infinite tail), you would lose information and the path would curve. By using the correct infinite-dimensional rule, the method keeps the path straight even on truly high-dimensional data.

Math after the picture

The equation: motion under a velocity field

First in words:

The function at time t plus a small step size times the velocity at that function gives the function at the next time step.

Then the compact form:

y(t + dt) = y(t) + v(y(t), t) * dt

Every symbol:

y(t)the function at time t (every value in the function)
v(y(t), t)the velocity: how much and which way to move the function
dta tiny step in time, how far to move in one step
y(t + dt)the function after taking one step
A tiny worked example: temperature evolving
Start: temperature function at time 0 is T(x)=30 degrees at every location.
Velocity field says: increase temperature by 2 degrees per time unit everywhere.
After one small time step (dt=0.1): T(x, t=0.1) = 30 + 2 * 0.1 = 30.2 degrees.
After next step (dt=0.2): T(x, t=0.2) = 30.2 + 2 * 0.1 = 30.4 degrees.
The function evolves smoothly along a straight line in the space of all functions.
A neural network learns that the velocity is +2 degrees by watching real paths.

The velocity field guides the function along the shortest path from noise to reality, one small step at a time.

What can go wrong

What can go wrong

Infinite-dimensional math is fragile. If the infinite-dimensional summing rule is not applied carefully, the method predicts wrong velocities and the path curves instead of staying straight. The paper's rigorous formulation prevents this, but sloppy implementations will fail.
Not all functional data is Hilbert space. The method assumes data lives in a Hilbert space (a particular infinite-dimensional space with a distance-measuring rule). Some functional data (like time series with rare events or very rough textures) does not fit neatly, and the model will struggle.
Training neural networks on functions is hard. The neural network must predict velocities for functions it has never seen before. If training examples are sparse, the model generalizes poorly and the straight path becomes wobbly.
Done right. When the method is implemented carefully, it generates high-quality functions faster than alternatives because the straight path is efficient and the infinite-dimensional math is correct.
What a runnable demo should prove

What a runnable demo should prove

A good demo should train a small neural network to generate smooth one-dimensional functions (e.g., curves that look like smooth temperature profiles over space). Start with random noise (zigzag curves) and show that the model learns to straighten the path: early epochs produce many wobbly intermediate steps, but once trained, the model reaches realistic curves in just 10 steps, and the intermediate functions form a smooth line through function space rather than a tangle of curves.

Average steps to convergence = (initial random curve distance to real curve) / (distance covered per learned step)
