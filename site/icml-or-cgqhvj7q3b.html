Do Text Edits Generalize to Visual Generation? Benchmarking Cross-Modal Knowledge Editing in UMMs

A factual edit that changes text output may still fail in image generation because the edited fact has to travel through a different conditioning pathway.

Paper explainersAll themesMultimodal

Knowledge editing changes a model's internal behavior so it answers one fact differently without retraining the whole system. In unified multimodal models, one might expect a text edit such as changing an object's attribute or relation to affect both textual answers and generated images. This paper shows that the transfer is weak. A fact can be edited strongly enough for text decoding yet still be too weak or too misaligned to steer the image-generation pathway. The benchmark measures that gap and adds a reasoning-augmented editing procedure that activates the edited fact before generation.

Zero assumption version

Why a successful text edit may not change generated images

Text output and image generation do not use a model in exactly the same way. Text decoding reads the model's factual representation through a language head that turns internal states into words. Image generation usually conditions a visual decoder or diffusion path on internal states that may emphasize different features or different timing.

Because of that split, a parameter edit, meaning a direct change to a small set of model weights, can fix the textual answer without creating a strong enough signal in the visual generation pathway. The model can say the edited fact correctly while still drawing the pre-edit version because the conditioning path that controls generation did not receive the edit in a usable form.

The paper's move in one sentence. Benchmark text-to-image transfer of knowledge edits directly and strengthen the transfer by forcing the model to explicitly activate the edited fact before generation.

What the paper changes

What the paper changes

The paper changes how an edit is evaluated and how it is injected into generation. The edited fact is no longer judged only by text answers. It must also survive the transfer into the image-conditioning pathway.

The hidden quantity

The hidden quantity

measured quantity  =  how strongly the edited representation influences the visual conditioning pathway

Text-side success hides a critical quantity: edit reach into generation. A model may store the new fact somewhere that the language decoder can read easily while the image generator gives it little weight. In that case the edit exists, but it does not control synthesis.

This reach depends on alignment between the edited internal representation and the representations that steer image generation. If the edit modifies the wrong layer, the wrong feature channel, or too weak a signal, the visual decoder still follows the pre-edit pattern. The benchmark makes that failure measurable instead of assuming text accuracy already proves full-model correction.

Why it works

Why explicit fact reactivation helps visual transfer

A direct parameter edit can be enough for text because text decoding probes the factual representation at generation time through language pieces that ask for the fact explicitly. Image generation is less direct. The model may start from a text prompt, but synthesis then unfolds through a visual trajectory whose intermediate states can revert to familiar pre-edit patterns unless the edited fact remains active throughout conditioning.

Reasoning-augmented parameter editing helps because it forces the model to restate or reason through the edited fact before drawing. That creates an intermediate state trace that places the new fact in working context right before generation. The visual pathway now receives a stronger cue because the edited content is not only stored in weights but also actively expressed in the current hidden state.

The benchmark's VQA-based verification matters because generated images are hard to score by string match. A fact such as a color change or a relation change must be read from the pixels. By using visual questioning, the paper turns cross-modal edit transfer into a measurable outcome rather than an anecdotal impression from sample images.

A transfer gap metric

First in words:

The paper's central diagnosis can be summarized as the gap between text edit success and visual verification success.

Then the compact form:

gap = Acc_text - Acc_visual

Every symbol:

Acc_textaccuracy of textual responses after the edit
Acc_visualaccuracy from visual question answering on images generated after the edit
gapthe amount of modality mismatch in edit transfer
A tiny worked example
Suppose a model answers the edited text question correctly on 92 out of 100 prompts, so text accuracy is 0.92.
Suppose VQA confirms the edited visual fact on only 19 out of 100 generated images, so visual accuracy is 0.19.
The transfer gap is 0.92 minus 0.19, which equals 0.73.
That large gap matters because it shows the edit succeeded for text while mostly failing to control image generation.

The benchmark reports richer metrics, but this simple gap captures the main claim: text-side edit success is not a reliable proxy for visual transfer.

What can go wrong

What can go wrong

The edit can overfit one phrasing. A parameter edit may answer one textual template correctly while failing to generalize across prompts, which makes both text and image evaluation appear better than the true underlying change because the benchmark may repeatedly hit the one phrasing the edit memorized.
Fact reactivation can add prompt sensitivity. If the pre-generation reasoning step is brittle, the system may surface the edited fact in one wording but fail in another, leaving visual transfer unstable.
VQA verification has its own errors. A visual question-answering checker can miss subtle generation outcomes, so some reported transfer failures may partly reflect evaluator weakness rather than edit weakness.
Done right. The benchmark is valuable because it evaluates the full route from stored edit to generated image instead of assuming that a corrected text answer proves the whole model changed.
What a runnable demo should prove

What a runnable demo should prove

Take a unified multimodal model that can both answer questions and generate images. Apply a localized edit such as changing the canonical color of an object. Evaluate the edited fact in text prompts and in generated images verified by a separate visual checker.

Then add an explicit pre-generation reasoning step that restates the edited fact before image synthesis. The demo should show that text success appears first, while image control improves only after the edited fact is actively surfaced into the generation context, because synthesis responds to the currently active hidden state more directly than to a weak stored edit alone.

transfer_rate = visual_edit_success / text_edit_success

The important measurement is whether the edit survives the handoff from stored knowledge to the synthesis path.
