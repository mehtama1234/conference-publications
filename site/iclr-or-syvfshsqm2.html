Dual Randomized Smoothing: Beyond Global Noise Variance

Instead of using the same noise level for all inputs, pick a different noise level per input to survive both small and large attacks.

Paper explainersAll themesAlignment, Safety & Fairness

Randomized smoothing adds random noise to inputs to make models survive adversarial attacks (small crafted changes that fool the model). But there is a catch: small noise works great for small threats, while large noise is needed for large threats. The paper solves this by predicting which noise level each input needs.

Zero assumption version

The noise-radius trap

Randomized smoothing defends a classifier by surrounding each input with noise. To check if a classifier can survive attacks, you add noise and see if the output stays the same. If it does, you know the model can survive attacks within that noise radius.

The catch: small noise is cheap and lets you check survival against small attacks quickly. Large noise works for large attacks but is expensive and drowns out the input so the classifier gets confused. No single noise level wins at both small and large radii.

The problem in one sentence. A global noise variance creates a fundamental trade-off: tiny noise lets models survive small attacks, or large noise lets them survive large attacks, but never both.

What the paper changes

The single thing the paper changes

Instead of hardcoding a fixed noise variance for the entire dataset, the paper learns a separate noise prediction per input. A variance estimator network sees the input and predicts which noise level helps the model survive attacks at that radius, because different inputs have different intrinsic sensitivity to noise.

the object it moves  =  noise variance
The hidden quantity

The optimal noise variance for each input

measured quantity  =  input-dependent optimal noise

For any input and any attack radius, there is a single noise level that maximizes how well the model can survive attacks. At small radii, it is tiny; at large radii, it is huge. The paper measures this quantity by running many certifications on a candidate set of noise levels and picking the one that gives the largest certified radius.

The variance estimator learns to predict this optimal noise from the input alone. It is trained on pairs of (input, optimal-noise) by running expensive certification sweeps offline, then using soft labels (uncertain targets that allow partial credit) and consistency loss (penalizing predictions that change when you add tiny noise) to handle the expensive labeling.

Paper reading. The variance estimator is trained to predict sigma-c(x), the noise variance that maximizes the certified radius R-c for each input x, by minimizing a weighted combination of soft cross-entropy loss (allowing partial credit for close predictions) and consistency loss (enforcing that nearby inputs get similar predictions).
Why it works

Why it works: routing to the best noise per input

Randomized smoothing works by finding the majority vote on a noisy neighborhood. If you add noise and get the same answer most of the time, the answer can survive that noise level. Different inputs have different optimal noise levels. An image with clear features might need tiny noise to stay accurate at small radii. A blurry or complex image might need large noise because it is already resistant to small perturbations naturally.

The paper solves this by training two models together: (1) a variance estimator that looks at the input and predicts which noise level to use, (2) a classifier that takes the predicted noise and runs standard randomized smoothing at that level. During training, they alternate: train the estimator to pick better noise levels, then retrain the classifier to survive attacks at those levels, because each model needs to adapt to the other's current behavior to improve. The estimator itself is smoothed via randomized smoothing to ensure its predictions are locally consistent (do not change wildly for tiny input changes). This consistency matters because the certified radius depends on the estimator being smooth — if the estimator's prediction jumps around, the math for computing how large an attack the classifier survives falls apart.

The result is a system that adapts to each input: small-radius threats get small noise (keeping accuracy high because the signal is not drowned out), large-radius threats get large noise (providing stronger guarantees because bigger noise catches bigger attacks). Neither is globally optimal, but input-dependent routing chooses the best per case because the estimator has learned which inputs need which noise level.

Math after the picture

The loss function for training the variance estimator

First in words:

Total loss = weighted average of soft cross-entropy loss (between predicted noise and optimal noise labels) and consistency loss (penalizing predictions that change when you add tiny noise). The weight depends on the frequency of each optimal noise level in the training set.

Then the compact form:

L_total = (1 - lambda) * L_softCE + lambda * L_consistency

Every symbol:

L_softCEsoft cross-entropy loss: measures how close predicted noise is to optimal
L_consistencyconsistency loss: penalizes estimator predictions that change for similar inputs
lambdatrade-off weight between learning accuracy and local smoothness
w_e(x)sample weight: inverse of frequency of optimal noise for input x
A tiny worked example
Suppose optimal noise for image-1 is 0.5, estimator predicts 0.5 -> softCE loss = 0 (correct).
Image-2 is similar to image-1, optimal noise is also 0.5, estimator predicts 0.48 -> softCE = small (close), consistency = small (nearby input nearby prediction, good).
Image-3 is very different, optimal noise is 2.0, estimator predicts 2.1 -> softCE = small (close), consistency not penalized (input is far away).
Total loss is lowest when estimator is accurate AND smooth. Smooth means similar inputs get similar noise predictions, ensuring certified radii do not jump around.

The consistency loss enforces that the variance estimator is locally constant (does not change wildly), which is a mathematical requirement for the certified radius guarantee to hold.

What can go wrong

What can go wrong

Estimator gives wrong prediction. If the variance estimator mispredicts which noise level is optimal for an input, the classifier runs at the wrong noise level and loses survival chances. This is mitigated by training the estimator on expensive ground-truth labels and using consistency loss to avoid wild swings.
Inconsistent predictions break certification. The certification guarantee requires that the variance estimator predicts the same noise for similar inputs (is locally smooth). If it does not, the certified radius formula fails. The paper ensures smoothness by smoothing the estimator itself via randomized smoothing.
Training cost explodes. Building ground-truth labels requires running many expensive certifications per input. The paper reduces this by using weak certification budgets (fewer samples to estimate confidence) and training on only a subset of the dataset.
Done right. The framework provides a routing interpretation: the variance estimator is a router that selects the best expert classifier for each input. Multiple pretrained experts trained on different noise levels can be swapped in without retraining the classifier, making the system modular and reusable.

What a runnable demo should prove

Train a variance estimator on CIFAR-10 to predict optimal noise per image. Use an off-the-shelf pretrained classifier as the base. For a test set of images, compute certified accuracy at multiple radii (0.5, 1.0, 1.5, 2.0) by running randomized smoothing at the predicted noise levels. Compare against a baseline that uses fixed global noise. Plot certified accuracy versus radius for both. The dual RS curve should stay high across all radii while the global-noise curve dips at some radius.

Certified_accuracy(radius_r) = fraction of test images where classifier is robust to radius_r attacks when using predicted noise variance

The demo makes it impossible to miss: different inputs have genuinely different optimal noise levels because some inputs are naturally harder to perturb while others are sensitive, and routing to them beats forcing everyone onto one size-fits-all noise because the estimator adapts to each input's intrinsic properties.
