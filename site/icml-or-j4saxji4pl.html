Pre-Propagation GNNs: Robust Diffusion and Re-Propagation

A better way to prepare graph data and refine it during training lets pre-propagation neural networks match the accuracy of traditional ones while keeping the speed advantage.

Paper explainersAll themesGraph & Geometric Learning

Graph neural networks learn by sending information along graph edges (message passing). Pre-propagation GNNs do this once upfront, then train on dense computations—much faster, because sparse multiplication is slow but dense multiplication runs efficiently on modern chips. But they fall behind on messy graphs where neighbors are often different, because a single upfront send loses information when neighbors are unlike. This paper improves the upfront preparation with operators that preserve distinctness (not blur all nodes alike), helping the initial send work better on messy graphs, and adds occasional refinement during training (a few re-sends) so each node's view of its neighbors stays aligned with the current weights, closing the accuracy gap.

Why graphs need preprocessing, and why old ways fall short

Most graph neural networks pass data around the graph edges repeatedly during training: each node collects information from neighbors, updates, collects again. Each round does a sparse matrix multiplication—slow on modern hardware that likes dense math instead. A naive approach would skip preprocessing entirely and do all message passing during training, but that wastes computing power on repeated sends.

Pre-propagation GNNs handle this differently: they send information along all edges exactly once, upfront, before training starts. The result is preprocessed data. Then training just does dense math on that data—fast. But there is a catch: on many real graphs (especially messy ones where a node's neighbors are often unlike it), this one-shot preprocessing misses important details. The model falls behind message-passing approaches that refine over time.

The tradeoff: speed versus accuracy. Pre-propagation is fast because it avoids repeated sparse matrix math, but falls short in accuracy, especially on graphs where neighbors are different.

What the paper changes

What the paper changes

The paper changes two things at once: the diffusion operator (the rule for sending information upfront) and when re-propagation happens (a few times during training instead of never). The core move is to design an upfront send that works when neighbors are unlike nodes (not just when they are similar) and then refine the hidden states (the numbers the model learns internally) a few times as the model trains to keep them aligned with their neighborhoods.

the object it moves  =  diffusion operator and re-propagation schedule
The hidden quantity

The hidden quantity: graph homophily

measured quantity  =  neighborhood homophily

Homophily is how much a node's neighbors are like it. On high-homophily graphs (Facebook friend groups), neighbors are similar, so one send propagates useful data everywhere. On low-homophily graphs (some recommendation networks), neighbors are often different, so one send leaves many nodes confused.

The paper does not measure this quantity directly. Instead, it designs diffusion operators and re-propagation to work across all homophily levels: the operators handle graphs where neighbors differ by preserving node distinctness instead of averaging everything alike (this helps because it stops the loss of unique information when neighbors are unlike), and re-propagation fixes any remaining gaps by letting the model adjust its understanding of what each node should know from its neighbors as it trains (this helps because training gradually learns better neighbor weights, and re-sending updates the node's knowledge to match).

Why it works

Why it works: better setup plus tactical refinement

On high-homophily graphs, neighbors are alike, so the single upfront send spreads similar information to similar nodes. The model can learn well from that. But on low-homophily graphs, neighbors differ sharply, so the upfront send spreads mixed or irrelevant information. The improved diffusion operator fixes this mismatch by changing the mixing rule: instead of a simple average that blurs differences, it uses a parameter (alpha) tuned per graph to preserve what makes each node unique, even when neighbors are unlike.

During training, the model learns how each node should weigh what it knows from its neighbors. A few times during training (not every step, but occasionally), the paper re-runs the send to refresh what each hidden state knows from its neighbors. This refinement happens too infrequently to hurt speed (still far less than message passing), but often enough to fix the accuracy gap, because it keeps each hidden state from drifting too far from its true neighborhood signal. The model sees updated neighbor information and can adjust its weights to use it correctly.

The equation

First in words:

The diffusion operator multiplies the graph structure by node features, smoothed with a carefully chosen blend amount (alpha). During training, hidden states are re-propagated by applying the same operator every few iterations.

Then the compact form:

H_prep = alpha * X + (1 - alpha) * A * H_train where re-propagation re-applies: H_t_refresh = alpha * H_t + (1 - alpha) * A * H_t

Every symbol:

H_prepthe preprocessed features, computed once before training
Xthe original node features given as input
Athe graph adjacency matrix, which encodes edges between nodes
H_trainthe hidden states the model learns during training
alphathe blend parameter: how much to keep the node's own info versus neighbor info (0 to 1)
H_t_refreshthe refreshed hidden state after a re-propagation step
A tiny worked example
Say alpha = 0.3, a node has original feature 5, and its three neighbors have features 2, 4, and 3.
Average neighbor feature: (2 + 4 + 3) / 3 = 3.
Preprocessed feature: 0.3 * 5 + 0.7 * 3 = 1.5 + 2.1 = 3.6.
The node keeps some of itself (0.3 * 5) and absorbs neighbor info (0.7 * 3).
During training, if the hidden state drifts to 2.8, re-propagation blends it back toward neighbors: 0.3 * 2.8 + 0.7 * 3 = 0.84 + 2.1 = 2.94, pulling it back toward the neighborhood average.

The blend parameter alpha controls how much each node relies on itself versus its neighbors; it is tuned to preserve differences on messy graphs and still work on similar-neighbor graphs.

What can go wrong

What can go wrong

Choosing alpha wrong. If alpha is too high, nodes ignore neighbors and lose the graph signal. If too low, nodes over-smooth and all become alike. The paper's diffusion operators choose alpha adaptively for different graphs, but if a graph is truly unusual, tuning may be needed.
Re-propagation does not refresh enough. If re-propagation happens too rarely (say, only at the very end), it does not guide training. Too often, and it becomes as slow as message passing. The paper uses a few-shot schedule; finding the right frequency is a tradeoff.
Very sparse or disconnected graphs. If the graph has isolated components or is very sparse, diffusion-based methods break down. Re-propagation cannot fix what was never sent in the first place.
Done right: balanced blend and schedule. When alpha is tuned to the graph and re-propagation fires at the right pace, the method keeps dense training speed while recovering message-passing accuracy.
What a runnable demo should prove

What a runnable demo should prove

Build a synthetic dataset with two small graphs: one high-homophily (a cliquish network where neighbors are similar) and one low-homophily (a checkerboard or bipartite-like graph where neighbors are often opposite). Train both a pre-propagation baseline (standard diffusion, no re-propagation) and this paper's method (tuned diffusion, with re-propagation). Measure accuracy on a node classification task (predicting a label for each node). Show that the baseline's accuracy drops on the low-homophily graph but recovers when tuned diffusion and re-propagation are added. Measure training time to confirm it stays close to the baseline and far below message passing.
