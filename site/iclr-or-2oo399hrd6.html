Reshaping Reasoning in LLMs: RL Training Dynamics through Pattern Selection

Reward-based training on language models focuses on a tiny fraction of critical tokens and reshapes which reasoning patterns the model uses most.

Paper explainersAll themesLearning Theory

When you teach a language model to reason better using reward signals, the training does not evenly touch the whole model, because most weights in the model are already well-optimized and moving them would harm unrelated reasoning tasks. Instead, it finds a sparse set of critical decision points—specific tokens where the model is choosing between competing reasoning paths—and nudges those few spots to favor better strategies, because these positions control which reasoning path the model takes next. This paper maps exactly what training changes and why some reward signals work while others can backfire.

Zero assumption version

The mystery of reward-based training

Language models follow patterns when reasoning. They tend to use certain solution strategies more often than others. Researchers discovered that if you give the model rewards for correct answers, it learns to reason better, because the reward signal teaches the model that some strategies lead to correct answers while others do not. But no one understood how. Does the reward signal change every weight equally? Does it rebuild the whole model? The gap between watching training work and understanding how it works blocked deeper insights.

A naive first guess: the model might learn a entirely new reasoning strategy from scratch. But that would be slow and fragile. In reality, something more surgical must happen—the model already has reasoning patterns inside it, so training probably adjusts which patterns it favors.

The mystery. Reward-based training makes models reason better because it signals which reasoning paths lead to correct answers, but where exactly in the model do the changes land?

What the paper changes

The one thing that changes

The paper changes the weights (learned numbers) of a language model, but not uniformly across the whole model. Instead, reward-based training focuses updates on a sparse, critical subset of tokens' internal computations.

the object it moves  =  sparse token weights
The hidden quantity

Critical token importance

measured quantity  =  which tokens are decision points

Most tokens in a language model are not decision points. When solving a reasoning problem, the model generates many words, but only a handful of tokens represent fork-in-the-road moments where the choice between two strategies is still up for grabs. The paper calls these critical tokens. A critical token is one where a small change in its learned weights can flip which reasoning strategy the model picks next.

The paper estimates this by running the model on many reasoning problems, recording which tokens' outputs change most during reward-based training, and checking that those tokens correlate with changes in the problem-solving strategy that emerges.

Why it works

Why sparse nudging reshapes reasoning

A language model learns to solve problems by building up a set of internal reasoning strategies—different ways to approach a problem, each encoded in the weights. When you run the model, it generates one token at a time (one word of reasoning), picking actions based on its learned weights. Most tokens are on a well-worn path and contribute little to the final decision. But a handful of tokens sit at choice points: their outputs determine which reasoning strategy gets picked next.

Reward-based training aims to increase the probability of answers that got rewards. To do this efficiently, it focuses nudges on the weights that most directly control those critical fork-in-the-road moments. Changing a critical token's weights can flip the strategy the model picks; changing a non-critical token does almost nothing. This is why training concentrates on sparse, critical tokens.

Once those few positions are nudged, the mix of reasoning strategies the model picks shifts. The strategies that led to high rewards become the default; the ones that led to low rewards fade to the background. The model still has the same internal strategies—nothing is deleted—but the probabilities flip. This reshaping happens because the critical tokens are the gates: close a gate on a bad strategy, open it on a good one, and the model's behavior changes without requiring a complete retrain.

Math after the picture

How to measure the shift

First in words:

penalty = sum over all reasoning patterns of (pattern probability before minus pattern probability after) squared, weighted by importance of each pattern.

Then the compact form:

shift = sum_p w_p * (prob_before_p - prob_after_p)^2

Every symbol:

shifthow much the reasoning distribution changed, measured as weighted sum of pattern probability differences
w_pimportance weight for reasoning pattern p, set based on how often the model encountered it before training
prob_before_pfraction of times the model picked pattern p before reward training started
prob_after_pfraction of times the model picked pattern p after reward training
A tiny worked example
Suppose three reasoning patterns exist: direct, analogy, and decompose.
Before training: direct picked 40%, analogy 35%, decompose 25%.
After training: direct picked 60%, analogy 20%, decompose 20%.
Weights: w_direct=1.0, w_analogy=1.0, w_decompose=1.0 (each equally important).
Shift = 1.0*(0.40-0.60)^2 + 1.0*(0.35-0.20)^2 + 1.0*(0.25-0.20)^2
= 1.0*0.04 + 1.0*0.0225 + 1.0*0.0025
= 0.0650
This shift of 0.065 shows moderate reshaping—the distribution moved but not drastically.

The equation measures how much each reasoning pattern's probability moved during training; squared differences ensure big shifts count more than tiny drifts.

What can go wrong

What can go wrong

Weak base model. If the model does not already contain good reasoning strategies in its weights, nudging critical tokens cannot help, because the critical tokens merely choose which existing strategy to use—they do not invent new strategies. Training can only reshuffle existing strategies, not create new ones, so a model with no working reasoning path will not suddenly find one through reward tuning.
Internal reward drift. When the reward signal comes from the model's own guess about quality, the signal can become misleading over time. The model learns to make itself feel confident even when reasoning poorly, leading to performance collapse if training continues past a certain point.
Wrong critical tokens identified. If the training procedure misidentifies which tokens are truly critical, it will nudge the wrong weights. Non-critical tokens carry redundancy; changing them wastes effort and can introduce noise without changing reasoning patterns.
Done right. Start with a model known to contain multiple reasoning strategies. Use verifiable rewards (external correctness check) rather than internal feedback. Track which tokens actually move during training to confirm you are hitting the right decision points.
What a runnable demo should prove

What a runnable demo should prove

Build a small language model on a reasoning task (e.g., solving arithmetic problems or logic puzzles with multiple solution methods). Track which tokens' outputs change most during reward-based training. Sample the model's reasoning chains before and after training, recording which strategy it picks each time. Measure the shift in strategy distribution (which methods it favors). Show that the tokens that moved most are exactly the ones that correspond to fork-in-the-road moments in the reasoning chain, and that the strategy distribution shift correlates with final accuracy improvement.

correlation between token-output change magnitude and strategy-distribution shift = (sum of absolute token changes at critical positions) / (sum of absolute token changes everywhere) should be >> 50%

The demo must make it impossible to miss that training focuses on a sparse set of decision-point tokens and that this focus is what reshapes which reasoning strategies the model picks.
