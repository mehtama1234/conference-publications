AgentPO: Training One Agent to Optimize How Multiple Agents Collaborate

Train a single Collaborator agent to learn how to orchestrate communication between multiple problem-solving agents, using only examples of good and bad outcomes.

Paper explainersAll themesAgents & Tool Use

When multiple AI agents work together on a hard problem, they need to know how to talk to each other. AgentPO trains a single specialized agent, the Collaborator, to learn the best way to route messages between the other agents. By collecting examples of what works and what does not, and then nudging the Collaborator toward the good patterns, the system learns to boost the overall answer quality without changing any of the original agents.

Zero assumption version

When agents collaborate, nobody knows how to coordinate them

Suppose you have three AI agents: one solves math, one checks answers, one organizes the steps into a plan. Each one is good at its job. But how should they talk? Should the checker always run after the solver? Should the planner interrupt and reorganize mid-solution? Should some agents ask others for a second opinion?

A beginner would try to hand-code fixed rules: math first, then check, then plan. But a hard problem might need the checker to spot an error early and send it back to math. Another problem might need the planner to steer the math toward simpler subgoals. Hard-coding every pattern is fragile and does not adapt to new problems. Without a system that learns which routing works, you are forced to guess or run expensive trial-and-error on every new problem.

The method in one sentence. Train a new Collaborator agent to learn the best way to route messages between your existing agents by showing it examples of what works, then nudging it toward those good patterns using reinforcement learning.

The algorithm as a flow

What it actually does

Run a trial

Three agents solve a math problem using a random routing (math talks to checker talks to planner, or some other order).

Score the outcome

Check if the final answer is right or wrong.

Store the trial

Remember which routing patterns led to success and which failed.

Train the Collaborator

Show the agent 500 examples and nudge it to predict good routings (right answers) more often.

Deploy

When solving new problems, ask the trained Collaborator which agent to contact next. Accuracy goes up, cost stays low.

What the paper changes

The one thing the paper changes

Instead of hard-coding which agent talks to which, the Collaborator agent learns a routing policy: a set of rules for deciding which agent to contact next given the current problem state.

the object it moves  =  routing policy
The hidden quantity

The collaboration score: how well agents work together

measured quantity  =  collaboration success rate

The hidden quantity is how often the agents get the right answer when following a particular routing pattern. A good routing might hit 80% accuracy; a bad one might hit 40%. The paper never directly measures a formula for this; instead, it runs each routing pattern on trials and counts: right answers divided by total trials.

The Collaborator learns to predict which routings lead to high scores. It does this by seeing which routing patterns were used in trials that succeeded (high score) vs failed (low score), then building a mental map: this routing usually worked, that one did not.

Paper reading. The paper treats the collaboration success rate as a reward signal in a reinforcement learning setup, where the Collaborator agent learns a policy that maximizes expected reward (final answer correctness) by sampling from a dataset of 500 trials.
Why it works

Why training the Collaborator makes better answers

The Collaborator learns because it sees a clear pattern in the data: some routings lead to right answers, others lead to wrong answers. By running through the data many times, it builds a classifier: given a problem state, predict the routing that is most likely to succeed. Once trained, when it sees a new problem, it proposes a path through the agents that matches the patterns it learned from successful trials.

The agents themselves never change. Math still does math, Checker still checks. But the Collaborator learns to call them in the right order and context, which improves the final answer because it routes each problem to the agents that will handle it best. The agents stay the same; the routing strategy gets smarter.

Math after the picture

The training objective

First in words:

nudge the Collaborator agent's routing predictions toward the patterns seen in successful trials, using a standard reward-based training loss

Then the compact form:

Loss = sum over trials of (predicted_success - actual_success)^2

Every symbol:

predicted_successwhat the Collaborator thinks the probability of success is for that routing
actual_success1 if that trial got the right answer, 0 if it got the wrong answer
sum over trialsadd up the squared differences for all 500 trials in the dataset
A tiny worked example
Trial A: math → checker → planner. Collaborator predicts 70% success. Actual: right answer (1). Error: (0.7 - 1)^2 = 0.09.
Trial B: planner → checker → math. Collaborator predicts 50% success. Actual: wrong answer (0). Error: (0.5 - 0)^2 = 0.25.
Trial C: math → checker → planner. Collaborator predicts 70% success. Actual: right answer (1). Error: (0.7 - 1)^2 = 0.09.
Total loss over 3 trials: 0.09 + 0.25 + 0.09 = 0.43. Lower loss = Collaborator's predictions match reality.

The Collaborator improves by lowering this loss, which means its routing predictions get closer to the ground truth (right or wrong).

What can go wrong

What can go wrong

Biased training data. If the 500 trials only show one routing (e.g., always math first), the Collaborator will never learn that other orderings might work on different problems. It will be stuck in a rut.
Agents that degrade in a chain. If each routing step makes errors that compound (checker trusts bad math output, planner builds on bad check), the Collaborator cannot recover, because it can only learn from patterns present in the training data. If none of the 500 trials showed a successful workaround to that error chain, the Collaborator has no good example to learn from.
Small training set. With only 500 trials, the Collaborator might memorize the specific problems and not generalize to new ones. More trials reduce overfitting because the agent sees more diverse routing patterns and has to find patterns that hold across different cases, not just memorize one set.
Agents are compatible. The method assumes the agents can take each other's output as input. If they speak incompatible formats, the Collaborator cannot route between them, no matter how smart it is.
What a runnable demo should prove

What a runnable demo should prove

Build a small math reasoning task: three simplified agents (one solves addition, one subtracts, one adds them). Collect 500 random routings and label each right or wrong. Train a Collaborator network to predict success from the routing. Then on new unseen problems, the Collaborator's routing should pick the agent ordering that led to success more often in the training data, so its accuracy should exceed random guessing.

accuracy_gain = accuracy_with_collaborator - accuracy_with_random_routing

The collaborator should close the gap: if random routing gets 50%, trained routing should get 70%+, showing the agent learned real patterns.
