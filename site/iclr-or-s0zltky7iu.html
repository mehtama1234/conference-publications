Teaching Metric Distance to Discrete Autoregressive Language Models

A language model can learn to respect distance relationships between output tokens by training it to predict soft distributions shaped by those distances instead of picking one right answer.

Paper explainersAll themesLLMs & Foundation Models

When language models expand beyond words to tasks like visual grounding or robot control, the individual outputs they predict represent positions or measurements that have real distances between them. For instance, two bounding boxes in an image are more similar if their corners are close together. Standard training makes models treat all wrong answers equally — a prediction that is slightly off is penalized just as harshly as one that is completely wrong. DIST2Loss flips this: it tells the model which wrong answers are closer to right, by shaping the training target itself to prefer nearly-correct answers over distant ones.

Zero assumption version

Why standard training breaks on distance tasks

When a model learns to predict words, getting the word wrong is getting it wrong — dog versus cat are equally wrong. But when the model predicts a bounding box around an object in an image, or a coordinate for a robot arm, the meaning lies in the numbers themselves. A box at (100, 100, 110, 110) is much closer to correct if the true box is (101, 101, 111, 111) than if it is (200, 200, 300, 300).

Standard training uses a target that is one-hot: the model receives a penalty only if its top prediction does not exactly match the single right answer. This ignores closeness entirely. A model predicting 200 where 100 is correct learns only that 200 is wrong, with no sense that 105 is almost right.

The fix in one sentence. Instead of teaching the model to match one exact answer, teach it to predict a probability curve that assigns higher weight to answers close to the true one and lower weight to distant ones.

The algorithm as a flow

What it actually does

Define distance metric

Say how far apart two tokens (e.g., bounding boxes, robot joint angles) are in reality.

Convert distance to distribution

Use math (exponential family) to turn distances into a smooth probability curve: close answers get high probability, far ones get low.

Discretize the curve

Round the smooth curve to match the model's discrete vocabulary of possible outputs.

Make it the training target

Instead of a one-hot target, feed this soft distribution as the target the model trains toward.

Minimize KL divergence

Train the model to predict a distribution matching the target (measured by KL divergence, a standard distance between probability distributions).

What the paper changes

What the paper changes

The training target: instead of a one-hot vector (a spike at the single correct answer), the model now trains toward a probability curve (a distribution is just a list of probabilities for each possible answer) shaped by the distance metric. This curve is higher where the true answer is and decays smoothly as you move away.

The hidden quantity

The distance gradient: how close or far each wrong answer is

measured quantity  =  distance-aware target probability

The hidden quantity this paper measures is not explicitly named in the text, but it is the smooth probability assigned to each token as a function of its distance from the true answer. It is a gradient or curve: the closer a token sits to the correct one in the metric space, the more probability mass that token receives in the training target.

The paper estimates this quantity analytically: given the distance metric d and the true token, it computes a continuous distribution (using exponential family theory) and then discretizes it to the model's vocabulary. This target distribution becomes the ground truth the model trains toward.

Why it works

Why learning the distance gradient helps

When a model is trained on a one-hot target, it sees a cliff: the right answer has zero penalty, everything else has equal high penalty. There is no learning signal telling it to prefer a nearby wrong answer. The model has to stumble around blindly.

When the target is shaped by distance, the model receives a smooth signal: nearly right gets less penalty than far wrong. This gradient points the model in the right direction even when it does not land exactly on the target. The model is learning a smooth curve of correctness rather than binary yes-or-no. This works especially well in low-data regimes: when you have few examples, every training signal must count, and a distance-aware signal teaches the model the shape of the answer space, not just isolated points.

The loss function and symbol meanings

First in words:

KL divergence between the model's predicted distribution and a target distribution shaped by distances

Then the compact form:

L_dist = sum_t sum_v p_d(v|x,t) * log(p_d(v|x,t) / p_theta(v|s<t))

Every symbol:

L_distthe distance-aware loss
p_d(v|x,t)the target probability of token v, shaped by distance metric d
p_theta(v|s<t)what the model predicts for token v given previous tokens
sum_tsum over all positions (time steps) in the sequence
sum_vsum over all tokens in the vocabulary
d(v, true)the distance from token v to the true answer (not explicit in equation, but implicit in p_d)
A tiny worked example
Suppose true coordinate is 100, distance metric is absolute difference, and we compute target p_d for three tokens: 100, 105, 200.
Using exponential family: p_d(100) is 0.7 (closest), p_d(105) is 0.2 (near), p_d(200) is 0.1 (far).
Model predicts p_theta(100)=0.4, p_theta(105)=0.3, p_theta(200)=0.3.
Loss for token 100: 0.7 * log(0.7/0.4) = 0.7 * 0.56 = 0.39.
Loss for token 105: 0.2 * log(0.2/0.3) = 0.2 * (-0.41) = -0.08.
Loss for token 200: 0.1 * log(0.1/0.3) = 0.1 * (-1.10) = -0.11.
Total: 0.39 - 0.08 - 0.11 = 0.20. Model is penalized most for not assigning enough to the correct token, less for confusing close and far tokens.

This equation tells the model: assign probability mass where distance says it should go, because the target distribution has already encoded which tokens are close to right.

What can go wrong

What can go wrong

Metric is wrong or noisy. If the distance metric does not match the true structure of the task (e.g., straight-line distance used where angle-based distance is correct), the target distribution misleads the model, and it learns the wrong shape.
Metric undefined for some tokens. If the model's vocabulary includes tokens outside the metric space (e.g., rare special tokens), there is no distance to compute, and the framework breaks unless extended.
Tuning the sharpness of the target curve. The sharpness of the target distribution depends on a temperature or scale value. If too flat, all tokens get equal reward and the distance signal vanishes. If too sharp, only the exact answer gets reward, making it similar to one-hot training.
Done right. When the metric is accurate and the exponential-family scale is tuned via validation, DIST2Loss provides a smooth learning signal that helps models generalize from few examples, because the model learns to judge how close each wrong answer is to right rather than just whether it is right or wrong.
What a runnable demo should prove

What a runnable demo should prove

Build a synthetic regression task: given a one-sample training set (a single input-output pair), fine-tune a small language model (e.g., 1B parameters) to predict coordinates. Measure mean absolute error (MAE) on 100 held-out test points. Compare three variants: (1) standard cross-entropy loss, (2) DIST2Loss with absolute-difference metric, (3) DIST2Loss with a badly-tuned scale (too sharp or too flat). Plot MAE versus number of training samples (1, 2, 5, 10, 50). DIST2Loss should win in the low-data regime (1-10 samples); the badly-tuned version should falter.

MAE = mean absolute difference between predicted coordinate and true coordinate across test set

The demo must make it impossible to miss: when you have few examples and a true distance metric, a soft target shaped by that distance teaches the model how to judge answer correctness better than a hard one-hot target, because the model learns a continuous curve of goodness rather than a binary cliff.
