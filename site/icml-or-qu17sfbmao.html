CausalX: Causally-Interpretable Multi-modal Spatio-Temporal Forecasting

Learn which variables cause which others over time, then use those causal links to forecast what will happen next.

Paper explainersAll themesTime Series & Sequential

When predicting future positions or weather, many different types of measurements influence each other (temperature affects wind, position affects velocity). Existing forecasting models ignore these relationships and just pattern-match, so nobody knows if they got lucky or if they understand what is really happening. CausalX discovers the hidden causal links between measurements over time and uses them to forecast more reliably.

Zero assumption version

The forecasting blind spot

Multi-modal spatio-temporal forecasting means predicting things that happen at different places over time, using many different kinds of data at once. A pedestrian's next position depends on their velocity, which depends on nearby obstacles and other people. A cyclone's path depends on temperature, wind, and pressure patterns that all feed each other. The world is full of these causal links.

Standard forecasting models (like transformers, which are neural networks that read sequences of data in parallel to find patterns, and recurrent networks, which read sequences one step at a time while keeping a memory) learn to predict the next step by pattern-matching past sequences. They ignore causality entirely. A model might memorize that 'rainy days often follow humid mornings' without understanding that humidity causes rain. In a safety-critical scenario like emergency response, a model cannot explain its forecast or adapt it to new situations.

A naive fix would be to hand-code all the causal rules between modalities. But in real data, causality changes over time—a person's direction depends on where they are walking, and the influence shifts. No human can write all these rules.

The method. Learn a causal graph (which variable influences which) that changes over time, where each edge weight shows how strong that influence is, then use it to forecast the next values.

The algorithm as a flow

What it actually does

Step 1: Aggregate multiple views

Collect constraints from four sources: what does prediction need, what pattern does time impose, what happens if you intervene, what does a generative model suggest.

Step 2: Learn a time-varying graph

For each time step, estimate edge weights saying 'how much does variable A influence variable B right now'.

Step 3: Refine with diffusion

Smooth the graph using a diffusion process (a mathematical technique that spreads values toward their neighbors) that respects physical laws so edges make causal sense.

Step 4: Forecast forward

Given the causal graph, predict the next values by following the causal links.

Step 5: Explain the forecast

The causal graph is interpretable—show the user which measurements drove which predictions.

What the paper changes

What changes: the causal graph

The paper learns a dynamic causal graph—a set of edges with weights that change over time. Each edge connects two modalities (temperature to pressure, position to velocity), and its weight tells you the strength of that causal link at each moment.

The hidden quantity

The hidden quantity: causal attribution strength

measured quantity  =  Strength of causal influence between modalities

This is the weight of each edge in the causal graph—a single number that says 'how much does variable A directly cause variable B at time t'. The paper calls this the edge weight. It is what you cannot see by just looking at the data; it is hidden until you learn it.

CausalX estimates this by combining four signals: (1) the predictive signal (if knowing A helps forecast B, they are likely causally linked), (2) the temporal signal (causality respects time—you can influence the future but not the past), (3) the interventional signal (simulating what happens if you force A to change and watching if B changes), and (4) the generative signal (a learned variational model suggesting plausible causal structures). By aggregating all four, the paper infers a causal graph that is more reliable than any one signal alone.

Plain reading. An edge weight is a number from 0 to 1 (or higher) that says 'if I nudge variable A by one unit right now, variable B will shift by this much, all else equal'.
Paper reading. The paper estimates edge weights as a matrix learned via contrastive objectives (predictive accuracy, temporal consistency, interventional alignment, and penalty terms that steer the graph toward plausible causal structures) and refines them via a diffusion process.
Why it works

Why learning causality improves forecasting

A pattern-matching model forecasts by saying 'sequence X usually follows sequence Y', without understanding why. If the world changes slightly (a new obstacle appears, wind patterns shift), the model fails because it never learned the causal mechanism.

When you learn causal links, you learn the actual rules: 'high pressure causes descending air, which warms and dries the air, which leads to clear skies'. These rules transfer to new situations, because a causal rule is about the mechanism itself, not the specific numbers in your training data. If pressure changes differently next month, the causal links stay true, because descending air still warms regardless of whether today's pressure is 1010 or 1000 millibars.

The four-source aggregation (predictive + temporal + interventional + generative) works because each source captures different aspects of causality. Prediction alone is noisy; causality should respect time order; intervention experiments show true causality; and generative models encode structural knowledge. Together, they constrain the graph to be more causal and less correlational. The diffusion refinement removes spurious edges and smooths out noise.

The result: a forecaster that not only predicts accurately, but can explain which measurements caused which predictions. In safety-critical domains (emergency response, weather warning), this explanation is as important as the forecast itself.

Math after the picture

The core equation: constrained graph learning

First in words:

Total loss equals the sum of four weighted objectives: prediction error plus temporal consistency violation plus interventional mismatch plus generative deviation, all regularized by diffusion smoothness.

Then the compact form:

L_total = L_pred(G) + lambda_t * L_temp(G) + lambda_int * L_int(G) + lambda_gen * L_gen(G) + lambda_diff * L_diff(G)

Every symbol:

L_totalThe combined loss to minimize
L_pred(G)Prediction loss: how badly the causal graph fails to forecast
L_temp(G)Temporal loss: penalty for violating time order (future cannot cause past)
L_int(G)Interventional loss: penalty for disagreeing with simulated interventions
L_gen(G)Generative loss: penalty from the learned variational model
L_diff(G)Diffusion loss: penalty for edges that violate structural priors
lambda_*Weights balancing the four objectives (tuned by the experimenter)
GThe causal graph (edge weights)
A tiny worked example
Suppose we have two modalities: wind (W) and pressure (P). We estimate edge weights: G_W->P = 0.8 (pressure drives wind) and G_P->W = 0.1 (wind barely affects pressure).
Prediction loss checks: if we use G to forecast wind and pressure, do we predict next values well? Suppose L_pred(G) = 2.5 (moderate error).
Temporal loss checks: causality respects time. If an edge goes backward (P at time t causes P at time t-1), that violates physics and incurs penalty L_temp(G) = 0.2.
Intervention loss checks: simulations show that forcing P to increase by 1 unit makes W increase by 0.75 units. Our estimated edge is 0.8, close enough. L_int(G) = 0.1.
Generative loss checks: a variational model says 'pressure and wind graphs typically look like this'. Our estimate differs by some amount. L_gen(G) = 0.3.
Diffusion loss checks: physical laws say temperature changes smoothly. If an edge changes from 0.5 to 0.99 in one time step, that is physically implausible. L_diff(G) = 0.15.
Total loss with weights (lambda_t=1, lambda_int=1, lambda_gen=0.5, lambda_diff=0.5): L_total = 2.5 + 1*0.2 + 1*0.1 + 0.5*0.3 + 0.5*0.15 = 2.5 + 0.2 + 0.1 + 0.15 + 0.075 = 2.975.
The optimizer adjusts G to lower this total. If it shifts G_W->P to 0.75, prediction improves but interventional loss rises; the balance is struck by the lambda weights.

The four loss terms together ensure the learned graph is causal (not just correlational), respects time, matches real interventions, and is smooth under physical laws.

What can go wrong

What can go wrong

Confounding: a hidden cause drives both A and B. If an unmeasured variable (e.g., air pressure on a non-measuring day) causes both temperature and wind, the model might learn a false edge from temperature to wind. The four-source aggregation reduces this but cannot eliminate it without more data.
Temporal ambiguity: causality is hard to infer from time series alone. If both A and B change together at every time step, it is genuinely ambiguous which causes which. The temporal loss (respecting time order) and interventional signal help reduce ambiguity, because time order rules out backward causality and interventions reveal what really causes what, but they may not fully resolve it if A and B are tightly coupled in a feedback loop.
Diffusion over-smoothing: refinement can erase real edges. If structural priors are too strong (e.g., 'nothing changes fast'), the diffusion process may smooth away real rapid causal shifts, harming short-term forecast accuracy.
Computational cost: aggregating four objectives is expensive. Computing predictive, temporal, interventional, and generative losses for every edge over time requires more training than a simple sequence model. Forecasting remains fast; learning is slow.
Done right: validation on interventional data. The best safeguard is to evaluate causality on held-out interventional experiments (real or synthetic). If you change A in the real world and the learned graph predicts B will change, that proves the edge is causal.
What a runnable demo should prove

What a runnable demo should prove

The demo should predict pedestrian trajectories on a dataset with multiple modalities (position, velocity, obstacle positions, other pedestrians). Train two models: (1) a standard sequence-to-sequence forecaster that ignores causality, and (2) CausalX. On unseen data where the environment changes (a new obstacle appears, a new person enters), measure forecast accuracy for both. CausalX should remain more accurate because it learned the causal structure (obstacle causes position change), which generalizes to new obstacles.

stability_gain = (accuracy_seq2seq_after_change - accuracy_seq2seq_before_change) - (accuracy_CausalX_after_change - accuracy_CausalX_before_change)

The causal model should degrade less when the world changes, proving that it learned structure, not just patterns. Also print the learned causal graph so a human can visually verify it makes sense: position and velocity should be mutually causal, obstacles should cause position changes, etc.
