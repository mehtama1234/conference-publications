PredNext: Temporal Prediction for Unsupervised Spiking Networks

Spiking neural networks learn video representations without labels by predicting what the network will see in future video frames.

Paper explainersAll themesRepresentation & Self-Supervised Learning

Spiking neural networks (brains-like models with time-based signals) are good at learning from video, but today's unsupervised methods are shallow and unstable. PredNext adds a prediction module: while the main network watches a video, an extra module guesses what the network will perceive in the next moment and the next chunk. This prediction task forces the network to build stable, useful representations without any labeled data.

Zero assumption version

Why today's unsupervised spiking networks fail

Spiking neural networks are special: they work more like brains, with signals that fire or not at each time step, and they naturally handle time-based data like video. But teaching them from unlabeled video is hard. Today's methods are mostly shallow (only a few layers), and they only use local rules (changes happen in one place at a time), so they cannot learn to connect events that happen far apart in time.

A beginner might try: just force the network to make the same features for the same object no matter when it appears in the video. But the paper shows this backfires—it actually makes the network worse, because the penalty for small changes overwhelms the real learning signal.

The problem: shallow networks + no long-range time learning. Spiking networks need a way to learn deep, stable time-aware features from unlabeled video.

The algorithm as a flow

What it actually does

Watch two views of the same video

The spiking network sees the same video sequence twice (maybe from different cameras or crops).

Extract features at each timestep

For each frame, the network builds a feature list (a set of numbers describing what it sees).

Predict one step ahead

A small prediction head guesses: given frame 3's features, what will frame 4's features look like?

Predict future clips

A second predictor guesses: given frames 1-5's features, what will frames 6-10's features look like?

Train on both predictions

The network learns to minimize how far its guesses miss. Features that are good for prediction become stable and useful.

What the paper changes

What the paper changes

The paper adds a separate prediction module that sits on top of the spiking network. This module learns to guess future features, but it does not change the network's weights directly. Instead, the prediction task acts as a teaching signal: features that lead to good predictions get reinforced, features that are noisy or inconsistent do not. This is different from directly penalizing inconsistency (which the paper shows fails).

The hidden quantity

Temporal Feature Consistency: The Hidden Quantity

measured quantity  =  temporal feature consistency error

Temporal feature consistency error measures how much a feature changes when you look at the same object at different times in a video. Imagine a cat walking across the screen: at frame 10 the network builds a feature list for cat-ness, and at frame 15 the same cat appears again. If the features for that cat are very different, the consistency error is high (bad). If they are nearly identical, consistency error is low (good).

The paper estimates this by computing the average cosine distance (a way to measure how far apart two lists of numbers are) between features from different frames of the same video. The network does not know it is being measured this way; instead, the prediction task indirectly optimizes for consistency because predicting next-frame features is easier when current features are stable.

Why it works

Why prediction forces consistency

The core trick: if features for an object jump around randomly, predicting the next frame becomes a guessing game—your prediction will miss. But if features for the same object stay stable over time, you can predict reliably. So the network faces a choice: build wild, noisy features and fail at prediction, or build calm, consistent features and succeed. The prediction loss (how much your guess misses) pulls the network toward consistency without explicitly penalizing it.

Why is this better than direct consistency penalties? Because forcing features to be identical at every frame is too strong—sometimes the network legitimately needs to update what it sees (shadows move, the camera pans). The prediction task allows gradual, genuine change while suppressing noise because the predictor is designed to track slow drifts. When the network changes a feature by a small, deliberate amount, the predictor can track it and still guess the next frame correctly, so the loss stays low. When the network jitters randomly instead, the predictor's guesses miss wildly and the loss shoots up. Since the network wants to minimize loss, it learns to keep features steady during jitter and adjust them only when necessary. This teaches the network that short-term stability is valuable without locking it into incorrect representations.

The prediction loss

First in words:

loss = cosine distance between predicted next features and actual next features

Then the compact form:

L_pred = 1 - (P_T(f_t) · f_{t+1}) / (||P_T(f_t)|| * ||f_{t+1}||)

Every symbol:

f_tthe feature list the network built for frame t
f_{t+1}the actual feature list for frame t+1
P_T(f_t)the prediction module's guess for frame t+1 features, given frame t
·dot product, a way to measure how aligned two lists of numbers are
||...||the length of the list
L_predthe loss: how wrong the prediction was (0 is perfect, 1 is worst)
A tiny worked example
Frame 3 features: [0.5, 0.2, 0.8] (what the network extracted)
Prediction module guesses frame 4: [0.48, 0.21, 0.79]
Actual frame 4 features: [0.49, 0.19, 0.81] (measured from the video)
Dot product of guess and actual: 0.48*0.49 + 0.21*0.19 + 0.79*0.81 = 0.235 + 0.040 + 0.640 = 0.915
Length of guess: sqrt(0.48^2 + 0.21^2 + 0.79^2) = sqrt(0.230 + 0.044 + 0.624) = sqrt(0.898) = 0.948
Length of actual: sqrt(0.49^2 + 0.19^2 + 0.81^2) = sqrt(0.240 + 0.036 + 0.656) = sqrt(0.932) = 0.965
Cosine distance: 0.915 / (0.948 * 0.965) = 0.915 / 0.915 = 1.0 → Loss = 1 - 1.0 = 0.0 (perfect prediction)
If the actual had been [0.1, 0.5, 0.2] (very different), the dot product would be 0.048 + 0.105 + 0.158 = 0.311, loss would be 0.67 (bad).

When features stay stable over time, the predictor nails its guess and loss drops. Noisy features give high loss, so the network learns to reduce noise.

What can go wrong

What can go wrong

Forced consistency constraints backfire. If you directly penalize feature drift (say, make frame-to-frame features identical), performance crashes. Strong penalties cut accuracy from 72 to 60 percent because the network is locked into stale, incorrect representations.
Prediction range matters. If you predict too far into the future (10 steps ahead when objects move fast), the task becomes impossible and the network learns nothing. Too close (1 step), and the guidance is too weak. The paper shows prediction steps of 3–5 frames work best.
Shallow networks ignore the signal. If the spiking network has only 2–3 layers, the prediction module has no varied features to work with because shallow networks build only low-level, simple patterns (like edge detectors). There is nothing complex enough to predict, so the loss signal is too weak to guide learning. The method requires deep architectures (8+ layers) to work because deeper networks build richer, more predictable hierarchies.
Cross-view prediction is essential. Predicting within a single view of the video is weaker than predicting across two different crops or camera angles. The cross-view constraint forces the network to learn view-invariant features, not camera-specific artifacts.
What a runnable demo should prove

What a runnable demo should prove

Build a simple spiking network on a small video dataset (e.g., UCF101 subset with 10 action classes). Train it unsupervised: show it unlabeled videos and apply the prediction loss. After 50 epochs, freeze the network and fine-tune a linear classifier on top of the learned features using just 1 percent labeled data. Compare: (1) the network trained without PredNext, (2) the network with forced consistency penalty, (3) the network with PredNext. Measure both accuracy on the test set and temporal consistency error (cosine distance between features from the same action at different times).

test_accuracy = (correct_predictions) / (total_test_videos); consistency_error = avg(1 - cosine_similarity(feature_t, feature_t+k) for all videos and k in 1..5)

The demo must show: PredNext achieves the highest accuracy and lowest consistency error, and forced penalties actually make things worse—proving that prediction guidance is the right tool, not direct constraints.
