dParallel: Learnable Parallel Decoding for dLLMs

Speed up diffusion language models by training them to figure out token answers with high certainty in parallel, instead of waiting for sequential refinement steps.

Paper explainersAll themesLLMs & Foundation Models

Diffusion language models generate tokens (small pieces like words or subwords) by starting with masks and gradually replacing them with guesses that get more confident over many steps. Today they still need nearly as many steps as the sequence length, even though the model could predict all tokens at once. dParallel trains the model to converge to confident predictions much faster, in parallel across all tokens, cutting decoding steps from 256 to 30 and speeding up inference (when the finished model answers a new prompt) 8.5 times on math problems.

Zero assumption version

Diffusion models waste time on sequential certainty

A diffusion language model works backwards from chaos: it starts with every position masked (hidden), then gradually unmasks each one by predicting what token should go there. On each step, it can predict all masked positions in parallel, but there is a catch: early predictions are wild guesses. The model needs many steps for those guesses to get more and more certain, like someone squinting at a blurry photo and refocusing until the answer snaps into place.

The naive approach: just let the model keep refining until it is confident everywhere. On a 256-token sequence, this takes 256 (or close to it) decoding steps, even though the model could announce all answers at once. The time for all 256 steps adds up: 8 seconds instead of 1, because each step runs the full neural net.

The bottleneck Tokens converge to certainty one after another. Speed up that convergence and run it in parallel.

The algorithm as a flow

What it actually does

Mask tokens randomly

During training, cover up half the tokens and ask the model to predict them from the other half.

Measure entropy

After each prediction, measure how unsure the model is: high entropy means the prediction is wishy-washy, low entropy means it is committed.

Force low entropy

Add a penalty for high entropy: push the model to make confident guesses, not vague ones.

Keep matching the teacher

At the same time, make sure predictions still match what the original untrained model would have produced (copy its trajectory).

At test time, stop early

When predictions hit your certainty threshold, stop refining and use those answers. Dramatically fewer steps.

What the paper changes

The one thing that changes

The paper changes the prediction entropy (how confident the model is about each token). During standard training, the model just tries to guess the masked tokens. Here, it trains specifically to make high-confidence guesses early, so tokens can be committed without waiting for many refinement steps.

the object it moves  =  prediction entropy
The hidden quantity

Token entropy: measuring how unsure the model is

measured quantity  =  Average entropy of masked token predictions

Entropy is a number between 0 and infinity that measures how vague a prediction is. If the model is 100 percent sure a token is the word banana, entropy is 0. If it is equally unsure between 1000 tokens, entropy is very high. The model predicts a probability for each possible token; entropy sums those probabilities with logarithms to give a single number: higher means fuzzier.

The paper uses entropy as a training signal: it measures the average entropy across all masked positions, then penalizes the model for high entropy. The goal is to make the model produce predictions where the probability is sharply peaked on one or two answers, not spread out over many.

Why it works

Why forcing certainty speeds up decoding

Here is the causal chain: diffusion models unmask tokens step by step. Each step, every masked position gets a new prediction. If the model is uncertain (high entropy), that position stays masked for the next step. If it is confident (low entropy), mark it unmasked. Under normal training, certainty spreads slowly: a few tokens converge per step, and the tail tokens take many steps to commit. That is why 256 tokens need 256 decoding steps.

dParallel breaks this by training the model to produce high-certainty predictions right away. The training loss has two parts: (1) stay consistent with the original model (copy its learning trajectory), and (2) minimize entropy (force sharp predictions). After training, when you run the model at test time with an entropy threshold, all tokens hit certainty much faster. Some tokens converge at step 5, others at step 25; by step 30, almost all are committed. No more waiting for token 250 to finally decide.

The training formula

First in words:

Total loss equals consistency loss plus beta times certainty loss. Consistency loss is how differently the student model predicts from the teacher. Certainty loss is the average entropy (fuzziness) of the predictions on masked tokens.

Then the compact form:

L_total = L_consistency + beta * L_certainty, where L_certainty = mean_entropy(predictions for masked tokens)

Every symbol:

L_totalthe overall training loss to minimize
L_consistencyhow well the student mimics the teacher model
L_certaintyaverage entropy across masked positions
betaweight between consistency and certainty (hyperparameter)
entropymeasure of prediction fuzziness (0 = certain, high = vague)
Tiny example: two tokens
Suppose we mask two tokens and the model predicts: token A has prob 0.8 (word banana) and 0.2 (word apple); token B has prob 0.5 (word cat), 0.3 (dog), 0.2 (bird).
Entropy of token A: roughly -0.8*log(0.8) - 0.2*log(0.2) = 0.72 bits (fairly certain).
Entropy of token B: -0.5*log(0.5) - 0.3*log(0.3) - 0.2*log(0.2) = 1.49 bits (very vague, tied between three options).
Average certainty loss: (0.72 + 1.49) / 2 = 1.1. Training penalizes this by subtracting from total loss.
If consistency loss was 2.0 and beta is 0.5, then total loss = 2.0 + 0.5 * 1.1 = 2.55. Lower entropy next time means lower total loss.

The model learns to concentrate its probability on one or two answers early, so that entropy threshold at test time stops refinement faster.

What can go wrong

What can go wrong

Entropy threshold too low. If you demand certainty too high (entropy below 0.4), some tokens stop refining before they are correct. Accuracy drops. Need to balance: you want high certainty, but not fake certainty.
Weak consistency loss. If you do not penalize deviation from the teacher model enough, the student learns to make certain guesses that are wrong. Certainty without accuracy is useless.
Only certainty loss, no consistency. If you remove the consistency loss and only force high entropy to be low, the model just learns to always predict the same frequent token. No parallelism gain from the ablation study: steps did not drop.
Done right. Tune beta to balance how much you care about entropy versus trajectory: roughly 0.5 to 1.0. Validate on held-out data. Check that accuracy stays flat while steps drop.
What a runnable demo should prove

What a runnable demo should prove

Build a simple diffusion language model (or start with a pretrained one). Train it on a held-out math dataset (like GSM8K examples, about 1000 prompts) using the certainty-forcing loss: combine a consistency loss (divergence from the teacher) with an entropy penalty on masked positions. At test time, set an entropy threshold of 0.45 and run inference with early stopping: once each token hits that threshold, do not refine it further. Measure two things: (1) how many decoding steps does the model need on average, (2) what is the accuracy on a test set of problems.

Speedup = original_steps / new_steps; Accuracy = problems_solved_correctly / total_problems

The demo must show that speedup is real (3x to 10x fewer steps) without sacrificing accuracy. If accuracy drops by more than 5 percent, tune beta or the entropy threshold.
