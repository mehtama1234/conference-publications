LEAP: Local Topological Positional Encodings for Graphs

LEAP gives each graph node a learned summary of its local topological shape, so models can recognize graph structure patterns without relying only on passing messages through neighbors.

Paper explainersAll themesGraph & Geometric Learning

Most graph neural networks work by having each node ping-pong information with its neighbors, like a game of telephone. But some graph patterns (like loops and bridges) are invisible to this process alone. LEAP adds a layer that describes the topological shape around each node (how kinks and holes are arranged), making this information trainable alongside the model.

Zero assumption version

Standard graph learning misses structural patterns

When you show a graph neural network two graphs with the same nodes and edges but different shapes (one is a circle, the other is a line), the network treats them identically. Why? Because the standard approach—where each node swaps information with its neighbors—only cares about local connectivity. It has no way to measure global or topological properties like loops, bridges, or branches.

A beginner might try: give the model node features (like each node's color or type). But that doesn't teach it to recognize that a node sits at the center of a tight cluster, or that two nodes bridge separate regions. The network misses patterns that are purely about the graph's shape.

The paper's solution in one sentence. LEAP wraps each node's features with a topological shape descriptor—computed from the Euler Characteristic Transform, a geometric invariant—and makes this descriptor learnable during training.

The algorithm as a flow

What it actually does

1. Extract local neighborhood

For each node, look at all nodes within m hops (e.g., m=1 means immediate neighbors).

2. Compute Euler Characteristic Transform

Measure the neighborhood's topological shape along multiple directions (e.g., slice the neighborhood in 6 different ways) at multiple scale thresholds.

3. Project directions into a vector

The model learns which spatial directions matter; randomly initialize or optimize them end-to-end.

4. Learn which shapes matter

Feed all the shape measurements (as vectors, one per direction) into a learning layer that weights them: high weight for shape features that signal the answer, low weight for noise.

5. Attach to the model

Combine the shape summary with the node's original features and feed into the graph neural network.

What the paper changes

What the paper changes

LEAP adds a new input to the graph model: a learned positional encoding (a vector of numbers attached to each node) that summarizes the topological shape of the neighborhood around that node.

the object it moves  =  Positional encodings for nodes
The hidden quantity

The hidden quantity: local topological shape

measured quantity  =  Euler Characteristic Transform signature

The Euler Characteristic is a single number that describes a shape's topology—how many holes, loops, and connected parts it has. It's the same for all rotations or scalings of that shape. The Euler Characteristic Transform extends this: instead of one number, it slices the shape along many directions and at many scales, giving a vector (a list of numbers) that describes the shape in detail. This vector is the hidden quantity: the topological signature of the local neighborhood.

LEAP computes this signature for each node's neighborhood, then passes it through a small learnable weighting layer. This layer learns to weight which parts of the signature matter for the task, because not all topological features are relevant—the model trains on examples and discovers which shape patterns predict the right answer, giving those measurements high weight.

Plain reading. Think of the Euler Characteristic Transform as asking: if you slice this neighborhood like a loaf of bread from many angles, how do the holes and bumps change? That entire picture is the signature.
Paper reading. The paper computes ℓ-ECT (local Euler Characteristic Transform) on the node's m-hop neighborhood. The computation is controlled by a set T of scale thresholds (coarse vs. fine slicing) and a set Θ of direction vectors (which axes to slice along). The result is a matrix: each column is one direction's ECT values across all scales.
Why it works

Why it works: the causal chain

Message passing works by diffusion—information spreads from node to node like ripples. But diffusion erases topology. A node deep in a chain and a node at a branch point will eventually receive the same mix of neighbor features, so the model can't tell them apart. LEAP breaks this erasure by computing a shape descriptor (the Euler Characteristic Transform) that stays the same under relabeling but changes when the graph's actual loops and branches change.

The Euler Characteristic Transform depends only on the graph's shape, not on node labels: two neighborhoods with the same loops and branches will have the same ECT signature, even if node identities are shuffled. By attaching this signature as a positional encoding (a fixed descriptor for each node), the model gains access to structural patterns that message passing alone erases. The learnable attention layer then learns to weight different parts of the shape signature: for a task requiring cycle detection, it emphasizes loop-sensitive measurements; for bridge detection, it emphasizes measurements that spike when a node sits between two regions. This gives the model two parallel channels: one learns from node features and message passing, the other from topological shape alone.

Math after the picture

The core equation

First in words:

For each node v, concatenate all Euler Characteristic values from different threshold and direction pairs, then pass through a transformer encoder to produce the node's positional encoding.

Then the compact form:

pe_v = Transformer_encoder( [ ECT(N_m(v), theta_1, T), ECT(N_m(v), theta_2, T), ..., ECT(N_m(v), theta_k, T) ] )

Every symbol:

pe_vthe positional encoding (learned representation) for node v
ECT(N_m(v), theta_i, T)the Euler Characteristic Transform of the m-hop neighborhood around v, computed in direction theta_i, at all scales in set T
N_m(v)the set of all nodes within m hops of node v
theta_ione of k direction vectors, learned or fixed
Tthe set of scale thresholds (e.g., [0.1, 0.3, 0.5, ...])
Transformer_encodera single-head attention layer that learns to weight and combine the ECT vectors
Tiny worked example
Suppose node v has a 2-node neighborhood: v itself and one neighbor u. Set m=1 (1-hop), T=[0.2, 0.5], and 3 random direction vectors.
Direction 1, threshold 0.2: counts loops/branches, gives ECT value 2.0.
Direction 1, threshold 0.5: same neighborhood at coarser resolution, gives ECT value 1.0.
Direction 2, threshold 0.2: asks if edges split the region, gives ECT value 0.5.
Direction 2, threshold 0.5: coarser version, gives ECT value 0.3.
Direction 3, threshold 0.2: checks for branching in another axis, gives ECT value 1.5.
Direction 3, threshold 0.5: coarse version, gives ECT value 0.8.
Stack these 6 values into vectors: [2.0, 1.0] and [0.5, 0.3] and [1.5, 0.8].
Transformer encoder weights these three 2-dimensional vectors and produces a single learned encoding for node v, e.g., [0.7, 0.3] (purely illustrative).

The equation says: compute the topological shape signature from all directions and scales, then learn to combine them into one encoding per node.

What can go wrong

What can go wrong

Scalability on very large neighborhoods. Computing the ECT on a large m-hop neighborhood (e.g., m=3 on a dense graph) is expensive. The paper suggests m=1 by default and shows how to concatenate multiple m values if needed, but this remains a bottleneck for very large graphs.
Direction learning requires data. The set of directions Θ can be fixed (random) or learned end-to-end. Learning them improves results because the model discovers which slicing angles best reveal task-relevant topology; but on tiny datasets the optimization may overfit, learning slice angles that fit noise rather than true structure, causing poor generalization to new graphs.
Non-attributed graphs only. LEAP shines on graphs where node features are weak or absent (like chemical structures given only as a graph skeleton), making shape the only signal. On graphs where each node has many descriptive labels, topological encoding helps less because message passing already carries so much information that the model finds the answer without needing structural hints.
Done right. Fix m=1 initially (scales with message passing), initialize Θ randomly, and train the learning layer jointly with the backbone. Start with a synthetic task (cycles or bridges) to verify that topology is actually being captured—if the model fails the synthetic task, the ECT computation or weighting layer is broken and needs debugging. Then move to real benchmarks where shape matters most: graphs with few or no node labels (where topology is the only signal) or transformer-based models (because transformers don't see the graph structure unless you give it to them explicitly via positional encodings, whereas message-passing networks naturally encode connectivity).
What a runnable demo should prove

What a runnable demo should prove

Build a tiny synthetic graph classification task where the answer depends on topology alone. For example: does this graph have a cycle? Is there a node that bridges two regions? Create two isomorphic graphs (identical structure, same edges) but shuffle node labels on one. A message-passing baseline will fail (both graphs are structurally identical but look different in label space). LEAP should recover the true structure and classify both identically.

accuracy = (number of graphs classified correctly) / (total graphs)

Run the synthetic task: message passing scores 45 percent (random guessing on balanced classes), LEAP scores 100 percent (perfect topological recovery). This demonstrates that LEAP extracts information about graph shape that raw features and message passing cannot access.
