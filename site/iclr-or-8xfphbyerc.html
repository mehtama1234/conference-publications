LEAP: Local ECT-Based Learnable Positional Encodings for Graphs

Graph networks get topological awareness by encoding local shape properties directly into node features.

Paper explainersAll themesGraph & Geometric Learning

Standard graph networks treat all nodes as equally important relay stations, losing sight of the graph's shape. LEAP adds learnable positional encodings—tiny numbers attached to each node—that capture the topological signature (how the graph is wired and shaped) using a computable shape invariant called the Euler Characteristic Transform. This lets the network see structure it would otherwise miss.

Zero assumption version

Standard graph networks are shape-blind

Graph neural networks pass messages between connected neighbors, updating each node by averaging what its friends know. A naive beginner might think: neighbors send their values, you average them, and you win. But this breaks down catastrophically on two fronts.

First, the network cannot tell shapes apart if they have the same connections. A ring of 10 nodes, a star (one center, 9 arms), and a tree are all different shapes in how information flows and gets stuck—but if you label them with the same connection pattern, message passing alone gives each the same update path. The network has no way to know it is looking at a ring versus a star.

Second, even when it sees the connections, message passing is isotropic—it treats all neighbor directions equally. It does not know that a node sitting at a bottleneck (where the graph narrows) has different structural importance than a node in the middle of a dense cluster. Capturing that difference requires a separate signal: positional encoding (a learned per-node feature that says where the node sits structurally).

The challenge. How do you give a graph network awareness of local shape—which nodes are at structural boundaries, which parts spiral, which parts are dense—when message passing erases that distinction?

The algorithm as a flow

What it actually does

Step 1: Compute local ECT

For each node and its neighborhood, calculate the Euler Characteristic Transform—a number-pattern that describes shape (holes, boundaries, density).

Step 2: Approximate in differentiable form

The original ECT is hard to refine via training nudges. LEAP uses a smooth approximation (DECT) that training refinements (nudges to the numbers inside the network) can flow through backward.

Step 3: Localize to neighborhoods

Instead of the whole graph, compute the shape signal only in the 1-hop or 2-hop neighborhood around each node, keeping it lightweight.

Step 4: Attach as learnable features

Convert the local ECT signals into node embeddings (position codes), then let the network learn how to weight them during training.

Step 5: Feed to message passing

Prepend these shape-aware encodings to each node's input. The network now sees both connectivity AND structure.

What the paper changes

What changes

LEAP changes one thing: the input features attached to each node before message passing begins. Normally, nodes start with just an identity or random values. LEAP prepends a small set of numbers (the local positional encoding) that encode the topological signature of each node's neighborhood—holes, loops, density.

the object it moves  =  node input features
The hidden quantity

Local topological signature

measured quantity  =  Euler Characteristic Transform (ECT) at each node

The Euler Characteristic is a single number that describes a shape's topology—how many holes, separate pieces, and loops it has. For a ring, it is 1 (one hole). For a star, it is 1 (one component). For a graph, it is the count of nodes minus edges plus independent cycles. The Transform (ECT) generalizes this to a pattern of numbers computed over different neighborhood sizes and directions, capturing not just 'is there a hole' but 'where is it and how tightly wound'.

LEAP measures this by computing the ECT locally around each node—looking only at that node's neighbors (not the whole graph). This is cheap to compute and reveals structural context: is this node at a junction (high local curvature), or deep in a smooth region (low signature)? The paper estimates it via a differentiable approximation (DECT) because the original ECT formula is not smooth—it has sharp corners—and neural networks cannot learn from sharp corners, only from smooth curves where tiny nudges to the input produce tiny changes to the output.

Why it works

Why it works: the causal chain

Message passing updates a node by averaging its neighbors. If two neighborhoods look the same (same edge counts, same density), the averaging path is identical—the network cannot distinguish them. By prepending a positional encoding that differs for structurally different nodes, the network gains a separate signal it can condition on. Now, when node A and node B have identical neighbors but sit in different local shapes (A is at a bottleneck, B is in open space), their encodings differ; the averaging operation 'sees' this difference and can route information accordingly.

The Euler Characteristic Transform captures exactly the right information: topological invariants (properties that persist under bending or stretching of the graph) that are independent of node labels or arbitrary orderings. A ring has one hole no matter how you draw it; an ECT-encoding marks that fact. Training updates flow backward through the differentiable ECT to refine these encodings as the network trains, so the network learns which topological features matter for the task. Nodes at structural boundaries (high ECT signature) get higher-valued encodings; nodes in open regions get lower ones. The averaging operation in the next layer now has a shape-aware input that amplifies or suppresses which neighbors to trust, based on their structural role.

Local ECT encoding: the formula

First in words:

For each node v, compute a local Euler Characteristic over its k-hop neighborhood N_k(v), then smooth it via differentiable approximation to get a learnable encoding vector p_v.

Then the compact form:

p_v = DECT(G[N_k(v)]) = smooth_approx( chi(N_k(v)) ) = [chi_0(v), chi_1(v), ..., chi_m(v)]

Every symbol:

p_vpositional encoding vector for node v
N_k(v)all nodes within k hops of node v (its local neighborhood)
chi(N_k(v))Euler Characteristic of the subgraph induced by that neighborhood
DECTdifferentiable approximation of the Euler Characteristic Transform
chi_i(v)i-th component of the ECT (different topological feature)
mnumber of ECT features (typically 2-8)
Tiny worked example
Node A sits at junction (3 branches meeting). Its 1-hop neighborhood has 3 edges, 4 nodes. Euler: 4 - 3 = 1, indicating a structure.
Node B sits on a straight line (2 neighbors). Its 1-hop neighborhood has 2 edges, 3 nodes. Euler: 3 - 2 = 1, also a structure.
But ECT at A over 2 hops captures all 3 branches: richer pattern [1, 2, 1]. ECT at B over 2 hops is simpler: [1, 0]. DECT smooths these into encoding p_A = [0.78, 0.34] and p_B = [0.21, 0.05].
Message passing now sees the difference. When A aggregates neighbors, the network multiplies by p_A (high values = trust this junction). When B aggregates, it multiplies by p_B (low values = weaker branch signal). Same connectivity, different structural roles.

Local ECT encodes a node's structural role in its neighborhood. Training refinements refine which features matter during learning.

What can go wrong

What can go wrong

Computational cost at scale. Computing ECT for every node's neighborhood scales poorly on very large graphs (billions of nodes). LEAP uses local neighborhoods to keep it tractable, but still requires geometric computation at every node.
Mismatch between ECT and task. ECT captures topological invariants (holes, loops, curvature). If the downstream task does not actually care about topology—for example, predicting node colors based on label propagation—the encoding adds noise rather than signal.
Loss of encoder generalization. If training graphs are small and testing graphs are very large, the learned encodings may not transfer. The network learns to rely on specific ECT patterns it saw during training.
Done right. LEAP works best on tasks where the graph's shape and structure drive the answer: molecular property prediction (atoms bonded in rings vs chains behave differently), graph classification by topology, network analysis where bottlenecks and cycles drive behavior.
What a runnable demo should prove

What a runnable demo should prove

Build a simple test: create three synthetic graphs with identical degree distributions (every node has 3 neighbors) but different topology (a ring, a star, a tree). Train a standard message-passing network without LEAP on 10 random graphs of each type. It will guess randomly (33% accuracy). Now add LEAP encodings and retrain on the same data. The network should jump to 80%+ accuracy on correctly labeling which shape each graph is.

shape_accuracy = (count correct shape labels) / (total graphs)

The jump proves LEAP is surfacing structural information that message passing alone cannot access.
