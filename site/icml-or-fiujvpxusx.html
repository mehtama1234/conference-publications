Romberg-Extrapolated Zeroth-Order Gradient Estimator

Combine gradient estimates at different scales to cancel error and improve optimization when gradients are unavailable.

Paper explainersAll themesOptimization

When you cannot directly measure gradients (e.g. testing a black-box AI system or optimizing through a physical simulator), you estimate gradients by checking how the output changes when you nudge the inputs slightly. Standard estimates are crude—they contain a systematic error that shrinks slowly as you make the nudges finer, because the error depends on how curved the function is, and that curvature does not go away. This paper shows how to mix estimates at different nudge sizes to cancel this error term, leaving behind a much smaller remaining error.

Zero assumption version

Blind gradient estimates are badly biased

Sometimes you cannot write down the gradient—the system is opaque (a neural network serving behind an API), or the link between inputs and outputs runs through a real-world simulator (a wireless antenna, a robot arm). In these cases you estimate gradients by nudging the input by a small amount r and checking how the output changes. But this blind estimate is not the true gradient; it contains a systematic error that shrinks slowly—proportional to r-squared—as you make r smaller. Smaller r means more function calls, so you hit a hard trade-off: make r large and get garbage guidance; make r tiny and burn through your budget.

A beginner tries to reduce this error by mixing two estimates at different radii. But mixing blindly is like averaging two bad recipes—you get worse results on the next dish, because the mixing muddles up the useful parts. Existing bias-reduction tricks either only nibble at the error or accidentally inflate the noise, making the search wander aimlessly.

The method. Reuse the same random nudge direction at many different sizes, then combine the estimates with carefully chosen weights to cancel the systematic error.

What the paper changes

What changes

The paper changes how you combine gradient estimates when you have multiple measurements at different scales. Instead of averaging them or picking the best one, you weight them with signs that cancel the systematic error. Because you reuse the same random nudge at every scale, this precise cancellation works without inflating noise.

The hidden quantity

Truncation bias: the systematic measurement error

measured quantity  =  truncation bias

Truncation bias is the gap between the true gradient and your blind estimate. Every time you nudge by r and measure the change, the estimate contains a systematic error that depends on how wiggly the function is (its curvature and higher derivatives). Standard two-point estimates have this bias proportional to the square of the nudge size r. This bias does not shrink fast enough; your search gets pushed in the wrong direction, so convergence is slow.

The paper estimates this bias term and cancels it by forming a linear combination of estimates at different radii. By picking the weights carefully (using Romberg extrapolation, a classical technique from numerical analysis), the combination removes the first error term (proportional to r-squared), the second error term (proportional to r-to-the-fourth), and so on—you can cancel up to R even-order error terms. The resulting estimate has bias that shrinks much faster as r shrinks (specifically, proportional to r-to-the-2R+2 instead of r-squared). Smaller bias means the gradient estimate points closer to the true direction, so each training step nudges the weights further toward the goal.

Why it works

Why mixing at different scales cancels error

The true gradient at a point is a limit: the change in output divided by the nudge, as the nudge shrinks to zero. But you cannot make the nudge truly zero—you need at least one function call. So your estimate contains leftover error from the curvature, the third derivative, the fourth derivative, and so on. These terms scale predictably: the curvature term is proportional to r-squared, the third-derivative term is proportional to r-cubed, and so on.

If you make two measurements at radii r and r/2, using the same random nudge direction but different scales, both estimates contain errors from the same infinite series of derivatives. But the sizes of those error terms shrink by predictable factors: the r-squared terms shrink by 4x, the r-cubed terms shrink by 8x, and so on. If you choose the weights correctly (e.g. taking 4 times the r/2 estimate minus 3 times the r estimate), the r-squared terms cancel exactly, leaving behind only the smaller r-cubed and higher terms. You can stack more radii and more weights to cancel more terms. The key: because you reuse the same nudge direction, the random noise in both estimates points the same way, so the weights do not amplify it—the noise cancels too, or shrinks only slightly. This means the weighted combination is much cleaner than a simple average: the error term you removed was dragging the search sideways, so removing it lets the search follow the true gradient directly.

This is a direct application of Romberg extrapolation, a centuries-old technique for accelerating numerical integration. The paper adapts it to gradient estimation, proving that you can cancel up to R even-order error terms while keeping the noise at the same level. With smaller remaining error, the gradient nudges point more accurately, so each training step makes larger progress toward the goal.

The weighted combination

First in words:

gradient estimate equals a weight times the difference at radius r divided by r, plus a different weight times the difference at radius r over 2 divided by r over 2, and so on; the weights are chosen so that error terms in powers of r cancel in pairs

Then the compact form:

g_Romberg = sum_{k=0}^{R} w_k * (f(x + (r/2^k)*d) - f(x - (r/2^k)*d)) / (2*(r/2^k))

Every symbol:

g_Rombergthe Romberg-extrapolated gradient estimate
w_kthe Romberg weight for the k-th radius (e.g. w_0 = -1/(2^{2R} - 1) for canceling 2R error terms)
rthe initial smoothing radius (how far to nudge)
dthe random nudge direction (same for all k)
f(x)the function value you are measuring
Rthe number of radii to use (higher R cancels more error terms)
A tiny worked example
Suppose true gradient is g = 5. At radius r = 0.1, two-point estimate is 5 + 0.01*C = 5.05 (bias 0.05, from curvature C = 5).
At radius r/2 = 0.05, two-point estimate is 5 + 0.0025*C = 5.0125 (bias 0.0125, shrinks by 4x as r shrinks by 2x).
Naive average: (5.05 + 5.0125) / 2 = 5.03125 (bias still 0.03125).
Romberg weight: take 4*(5.0125) - 3*(5.05) = 20.05 - 15.15 = 4.9 ... wait, divide by net weight (4 - 3 = 1) to get 4.9. Close but not exact due to higher terms.
Better: Romberg with correct scaling gives bias proportional to r^4 instead of r^2, so it vanishes 16x faster as r shrinks.

The weights form a pattern where estimates at finer scales (smaller r) get higher positive or negative coefficients, and the signs alternate; the algebra ensures error terms of the same order from different radii subtract away.

What can go wrong

What can go wrong

Choosing R too large burns the budget. Each extra radius means more function calls per gradient estimate. If you set R too high, you cannot afford to take many gradient steps, and the method slows down overall. The paper derives explicit bounds to guide the trade-off.
Noise amplification at very small radii. In the random case (where the function itself is noisy, e.g. an average over a batch), reusing the same nudge direction at very small scales can amplify measurement noise. The paper characterizes this with explicit noise-amplification factors and bounds.
Directional variance loss if the function is highly anisotropic. If the function is much steeper in some directions than others, the method still preserves the directional variance of the two-point estimator—meaning it does not accidentally push the search into the wrong direction—but the preservation assumes the function has certain smoothness properties.
Done right. Pick R so that 2R+2 radii fit in your per-estimate budget. Use explicit noise bounds to confirm the random setting is stable. Verify on a small test that the gradient estimates point toward lower loss.
What a runnable demo should prove

What a runnable demo should prove

Build a simple black-box optimization problem: e.g. minimize a quadratic loss function you can only evaluate (not differentiate), or optimize the prompts for a large language model on a benchmark where you measure accuracy but cannot backprop. Use a fixed budget of function evaluations per gradient estimate (e.g. 10 calls per estimate). Compare three methods: (1) two-point estimates at a fixed radius r, (2) adaptive radius (shrinking r over time), and (3) Romberg-ZOGE with R set to 1 or 2. Measure convergence speed by counting how many gradient steps it takes to reach a target loss value. Romberg should reach it faster and more reliably because the bias-reduced estimates point closer to the true gradient.

convergence steps, defined as the step count at which loss first drops below target; lower is better; measure for all three methods; Romberg should be 30 to 50 percent faster

The key result: the weighted combination cancels the largest error term (curvature), so what remains shrinks much faster as you make nudges finer because higher-order derivatives matter less than curvature. Cleaner gradient estimates mean each training step moves closer to the goal, so you need fewer steps to finish even though you use the same total budget of function calls.
