Value Flows

Use smooth continuous models to estimate the full shape of future rewards, then weight learning by how uncertain each estimate is.

Paper explainersAll themesReinforcement Learning

Most RL algorithms collapse future returns down to a single number, missing what the data actually looks like. This paper uses a flow-matching model (a tool for learning the full shape of possible outcomes, like tracing a smooth path from random noise to real data) to estimate all the different futures that might happen—and then uses that full picture to decide which transitions deserve the most learning effort.

Why flattening returns costs you information

Today's RL algorithms treat future returns like a thermometer reading: they estimate one scalar number (expected return from this state). But in reality, futures are messy. From the same state, you might get reward 5 some days and reward 20 other days—the data is spread out. Old methods throw away that shape.

If you use one number to decide where to explore or whether an action is safe, you miss critical information. A state with returns [5, 5, 5] (reliable, always low) looks the same as [1, 10, 20] (highly uncertain). But they should receive different treatment: the uncertain one demands caution or extra learning.

The method. Learn a smooth curve (via flow-matching) that captures the full shape of possible returns, then use how spread-out that curve is to weight which transitions to learn hardest from.

The algorithm as a flow

What it actually does

Collect transitions

Gather (state, action, next state, reward) from the environment or stored data.

Learn a flow model

Train a vector field (a function that nudges random noise toward real returns) using flow-matching loss.

Estimate variance

For each transition, compute how spread-out the learned distribution is (via the flow model's derivatives).

Weight by uncertainty

Scale the loss for each transition: high variance gets a big multiplier, low variance gets a small one.

Extract policy

Sample actions from the flow model or use deterministic action selection to exploit the learned return estimates.

What the paper changes

What the method changes

Instead of learning to predict a single scalar return, the paper trains a vector field (a learned function that maps random noise toward plausible returns). This vector field encodes the entire shape of possible future returns—capturing not just the average but also how spread out the possibilities are.

the object it moves  =  Return shape model
The hidden quantity

Return variance: how spread-out is the future?

measured quantity  =  Return variance (width of the distribution)

The hidden quantity is return variance: how far apart the possible future rewards tend to be. If a state has low variance, the returns cluster tight. If high variance, they scatter wide. This is computed directly from the learned flow model by taking its derivatives.

The paper estimates variance by linearizing the flow model's prediction and computing the noise sensitivity—essentially, how much a small change in the random input pushes the output around. High sensitivity means high variance.

Why it works

Why focusing learning effort on high-variance states works

When return variance is high, the model is most uncertain. Investing learning effort into uncertain transitions makes sense: a small error in a high-stakes prediction (wide spread, many possible futures) has bigger impact than the same error in a confident prediction (tight spread).

Flow-matching is well-suited to this task because it directly models the probability density (the shape of returns), unlike older methods that only predict a mean. The flow model's derivatives naturally give you variance. By reweighting the loss with variance, you steer learning updates toward states where better prediction matters most.

The mechanism also captures the exploring-vs-exploiting tradeoff: high-variance states are candidates for deeper exploration (because you have not seen enough examples to trust your estimate) or safer policies (because the actual returns might be much worse than the mean). Learning their returns accurately improves both safety and regret, because you are no longer blindly relying on the average.

Math after the picture

The flow-matching loss and variance reweighting

First in words:

Loss = sum over transitions of [ variance-weight(s,a) * flow-matching-error(s,a) ]

Then the compact form:

L_Value = sum_i w(s_i, a_i) * ||v_theta(z_t | t, s_i, a_i) - (z_0 - z_1) / t||^2

Every symbol:

w(s,a)confidence weight derived from return variance at (state, action)
v_thetathe learned vector field (neural network) parameterized by theta
z_trandom noise at time step t, gradually denoised to a return
z_0the actual return observed from data
z_1terminal noise (start of the denoising path)
ttime parameter in the flow (0 = noise, 1 = real return)
A tiny worked example
Suppose two transitions: T1 and T2, both predict return 15.
T1 has low variance (spread small): w(T1) = 0.2
T2 has high variance (spread wide): w(T2) = 1.0
Both have same flow-matching error: 0.5
T1 loss contribution: 0.2 * 0.5 = 0.1
T2 loss contribution: 1.0 * 0.5 = 0.5
Same prediction error, but T2 receives 5x stronger training nudge because its future is more uncertain.

The weight w prioritizes learning where the model is least confident; the flow-matching loss trains the vector field to trace the true return distribution.

What can go wrong

What can go wrong

Poor flow model initialization. If the initial vector field is bad, the denoising path may be erratic. Solution: use a pre-trained diffusion model or warm-start on auxiliary data.
Overweighting high-variance transitions. If a transition is high-variance due to noise (not true uncertainty), reweighting amplifies the noise. Solution: smooth the variance estimates or use a confidence penalty on uncertain-but-rare transitions.
Epistemic vs aleatoric confusion. High variance might mean the model is ignorant (epistemic) or the world is truly random (aleatoric). The current method does not distinguish them. Solution: ensemble flow models or count visit frequency to flag rarely-seen states.
Done right. Combine variance reweighting with exploration bonuses (to handle epistemic uncertainty) and a smoothness prior on the learned flow (to avoid noise amplification). Validate on both state-based and image-based benchmarks across offline and online-to-online settings.
What a runnable demo should prove

What a runnable demo should prove

Build a small offline RL environment (e.g., a simple navigation task with 5–10 states). Collect a dataset of trajectories. Train a flow-matching model to predict returns and compute variance for each transition. Then train a standard RL algorithm but with and without variance-based reweighting. Track both success rate on new episodes and the quality of return predictions (e.g., how accurately you predict the 90th percentile return).

improvement = (success_rate_with_weights - success_rate_without_weights) / success_rate_without_weights × 100%

The demo reveals the core principle: states with uncertain futures must receive stronger learning updates because a small prediction error in a high-uncertainty scenario compounds into bigger mistakes than the same error in a confident scenario, and a flow model's mathematical derivatives compute that uncertainty automatically by measuring how much the model's output wobbles when you perturb the input noise.
