CORDS - Continuous Representations of Discrete Structures

Predict variable-sized sets by turning them into smooth mathematical fields instead of fixed-size lists.

Paper explainersAll themesGraph & Geometric Learning

Many real-world problems ask a model to predict an unknown number of things: how many objects are in an image, which atoms make up a molecule, where particles emerge in a detector. Old methods pad the output to a fixed size or guess the count separately, both awkward. CORDS flips the approach: instead of predicting discrete objects directly, turn the prediction problem into finding continuous mathematical fields—smooth surfaces that encode both where objects sit and what they are—then decode back to discrete sets at the end.

Zero assumption version

Predicting unknown quantities

A model must predict a set of objects when the count is unknown. In object detection, the image may have three cars or eight. In molecular generation, the molecule might have thirty atoms or fifty. In scientific observation, a telescope detects between one and dozens of sources.

The naive approach: pick a maximum (say, ten objects), pad the output to that size with dummy markers, then throw away the dummies at the end. This wastes computation—real molecules have twenty atoms, but the model predicts fifty and discards thirty. Or, split the task: first guess the count, then generate that many objects. But these two steps interfere—a wrong count dooms everything downstream.

Neither method feels natural because discrete sets are the output, not the input. The model feels it is fighting the shape of the problem.

In one sentence. The paper turns variable-sized set prediction into finding smooth mathematical fields, then pulls the discrete objects back out.

The algorithm as a flow

What it actually does

Encode sets into fields

Each object becomes a peak in a smooth density surface, placed at its location. Its properties sit in a feature surface.

Learn one invertible map

Train a model to map input (image, molecule fragment) to both density and feature fields together.

Model works in smooth space

The model makes its predictions entirely over continuous fields—no discrete machinery, no fixed slots.

Invert to recover discrete sets

After the model finishes, find peaks in the density field. Read the features at those peaks.

Output variable-size set

Each peak with its looked-up features becomes one discrete object. Set size follows from the number of peaks.

What the paper changes

What changes

The paper changes the output representation. Instead of a fixed list (padded or guessed), the output is two smooth mathematical functions—a density function and a feature function. Because the mapping is invertible, feeding input through the model's learned function yields continuous fields, and reading peaks back out gives exact discrete sets with no approximation.

the object it moves  =  output representation (fixed set to continuous fields)
The hidden quantity

The hidden quantity: invertibility

measured quantity  =  invertibility of the mapping

Invertibility means the model's transformation is reversible: if you apply it to a set, you get fields; if you apply the reverse, you get the exact same set back with no loss. This guarantees that predictions in field space are exact when decoded to discrete sets, not approximations.

The paper achieves this by designing the density and feature fields using a mathematical construction—spatial basis functions and careful normalization—such that extracting all peaks and their features recovers every original object. The model learns the forward transformation; invertibility is built in by design, not learned. The paper validates this by comparing predicted sets to ground-truth sets and confirming zero rounding error in the decoding step.

Why it works

Why continuous fields solve the problem

The core issue with fixed-size outputs is shape mismatch: a set of unknown size does not fit neatly into a pre-sized array without waste or guesswork. Continuous fields dissolve this mismatch. A field is defined over a domain (say, 2D space for an image), and nothing prevents it from having five peaks or fifty. The field itself is the natural home for variable-sized structure.

Because the mapping is invertible, the model can optimize entirely in field space (where training is stable because fields are continuous and differentiable) while the output guarantees remain exact (peaks decode perfectly to discrete objects). There is no information loss: every object goes into its peak, every feature into its field value, and every peak reconstructs its object. The model learns the forward direction; the reverse is guaranteed by construction.

This breaks the dependency trap: the model does not guess the count and then generate objects, or generate fixed slots and mask dummies. It predicts fields, and count and object properties emerge together as peaks in those fields.

Math after the picture

The invertible transformation

First in words:

density field at location x equals the sum of basis peaks centered at each object location, and feature field at x equals the stacked attribute vectors at that location, built so the transformation is invertible.

Then the compact form:

density(x) = sum_i w_i * phi(x - x_i); features(x) = sum_i a_i * phi(x - x_i)

Every symbol:

density(x)height of the density surface at location x
features(x)attribute vector stored at location x
x_ithe spatial location of object i
w_ithe weight (peak magnitude) at location i
a_ithe attribute vector (color, class, properties) of object i
phi(x - x_i)a basis function centered at x_i (Gaussian, radial basis, or Fourier)
sum_isum over all objects i in the ground-truth set
A tiny worked example
Suppose object 1 is at location (2, 3) with color red, object 2 at (5, 1) with color blue.
density(2,3) gets a basis peak phi(0) = 1.0; density(5,1) gets phi(0) = 1.0. At (3.5, 2) halfway between, both basis functions have value ~0.3, so density(3.5,2) = 0.3 + 0.3 = 0.6.
features(2,3) reads red (from a_1); features(5,1) reads blue (from a_2).
To decode: find peaks (at 2,3 and 5,1), read red and blue. Invertibility means this recovers the exact original set.

The model learns to predict the weight (peak magnitude) and attribute (properties) at each object location; the basis and locations ensure the fields are invertible, so decoding is exact.

What can go wrong

What can go wrong

Basis resolution mismatch. If the spatial basis is too coarse (too few Gaussians), nearby objects merge into one peak. If too fine, computation explodes and the model overfits to noise. The basis density must match the expected object spacing.
Feature field collisions. If two objects occupy very similar spatial locations, their attribute values lay atop each other in the feature field. The decoding step must have enough numerical precision to read distinct attributes; if not, the recovered objects will be ambiguous.
Peak detection brittleness. Finding peaks in the learned density field relies on local maxima detection. If the field is shallow or noisy, spurious local maxima emerge, creating fake objects. If it is too smooth, true peaks blur together.
Done right. When basis resolution matches object density and training enforces sharp, well-separated peaks, the method recovers sets exactly. The invertibility guarantee ensures no information is lost between discrete sets and fields.
What a runnable demo should prove

What a runnable demo should prove

Build a synthetic dataset: generate random 2D point clouds (variable size, 3 to 15 points) and assign each point a class label (red, green, or blue). Train CORDS to predict the density and feature fields from a noisy image of the point cloud. Measure whether the decoded sets recover the exact input count and labels.
