Differentially Private Equilibrium Finding in Polymatrix Games

When multiple players find a fair outcome in a game while keeping their moves secret from eavesdroppers, this paper shows the first way to do both at the same time.

Zero assumption version

The secret deal problem

Imagine three firms setting prices for widgets. They need to find prices where no firm can raise profit by changing alone, a fair outcome called an equilibrium. But a rival firm is hacking their network to read their messages.

If the firms send unencrypted prices, the eavesdropper learns their strategy instantly. If they encrypt everything, the algorithm cannot find the fair prices—it gets stuck. Every old algorithm trades off one for the other: either the eavesdropper learns nothing but the firms never find a deal, or they find a great deal but the eavesdropper steals their entire playbook.

The core puzzle. As more players join the game, can we find a fair outcome while the amount of information each player leaks shrinks to nearly zero?

The algorithm as a flow

What it actually does

Prove the wall

Show mathematically that old algorithms cannot fix this: each new player added means more broadcast messages sent, and information leaks grow exponentially with players while fairness gains shrink, creating an impossible bind.

Find the loophole

Polymatrix games have a special shape: each player's payoff depends on their own choice plus a few neighbours, not everyone else.

Build a new algorithm

Use this structure: send fewer messages by exploiting who actually talks to whom, not the full graph.

Show both grow

Prove that as player count N rises, the fair-deal quality and the secrecy both improve because fewer messages per player are needed to reach consensus when the game graph is sparse.

Verify it works

Run experiments on actual polymatrix games and confirm the theory holds up in practice.

What the paper changes

What the paper changes

Every player in a distributed algorithm must send messages to learn everyone's choice. The paper changes which messages get sent: instead of broadcasting to all players, each player sends to only the few neighbours who actually affect their payoff. This cuts the number of messages while keeping the quality of the outcome.

the object it moves  =  communication channels used
The hidden quantity

The hidden quantity: Nash gap

measured quantity  =  Nash gap

The Nash gap (also called exploitability) is the extra profit a player can grab by changing strategy, if all others stick to the current plan. In a perfect fair outcome (called a Nash equilibrium), this gap is zero: no player gains by moving alone.

The paper tracks two things together: how small the Nash gap gets, and how much secret information the eavesdropper collects (measured in bits of privacy lost per player). It shows both shrink together as more players enter.

Why it works

Why it works: exploit the game structure

Polymatrix games have a hidden structure: each player's payoff depends only on their own choice and a small set of neighbours, not all other players. In a supply chain, firm A cares about firm B (its supplier) and firm C (its customer), but not firm M in another industry.

Old algorithms treat all players as equally connected, so they broadcast messages to everyone. This leaks secrets widely. The new algorithm sends messages only along the actual edges in the game graph. Each player communicates only with the neighbours whose choice affects its payoff.

By shrinking the communication network to match the game's actual structure, fewer messages are sent, so less information leaks to the eavesdropper. At the same time, the structural properties guarantee that the algorithm still finds a fair outcome. The two improve together because they are not independent trade-offs—they both stem from reduced communication.

inputPolymatrix game: each player knows their own payoff and their neighbours
stepDistribute: each player sends to neighbours only, not all players
stepUpdate: each player adjusts strategy based on replies from neighbours
stepRepeat across rounds, averaging to smooth randomness
outputStrategies converge to a fair outcome with shrinking privacy loss

The guarantee equation

First in words:

As the number of players N grows, the Nash gap shrinks at a rate of 1 divided by the square root of N, while the privacy loss per player also shrinks like 1 divided by the square root of N.

Then the compact form:

Nash_gap = O(1/sqrt(N)), privacy_loss_per_player = O(1/sqrt(N))

Every symbol:

Nash_gapthe most profit any player gains by deviating alone
privacy_loss_per_playerthe eavesdropper's information advantage from listening to one round
Nnumber of players in the game
O(1/sqrt(N))decreases proportional to the square root of player count
A tiny worked example
With N = 4 players: Nash_gap shrinks to roughly 1/sqrt(4) = 1/2 of the baseline unfair payoff.
Privacy loss per player drops to roughly 1/2 of a single-player leak.
With N = 100 players: Nash_gap shrinks to roughly 1/sqrt(100) = 1/10.
Privacy loss drops to 1/10 as well.
Both improve together: more players means fairer deals AND better secrets kept, not a trade-off.

The square-root rate is the same for both because they share a root cause: smaller communication graphs leak less and still converge.

What can go wrong

What can go wrong

Game must have polymatrix structure. If every player's payoff depends on every other player's choice, the algorithm cannot exploit structure and may revert to old trade-offs.
Eavesdropper must have limited access. If the adversary can read all messages (not just a bounded set), the hardness result from the paper applies: reading every message reveals the full strategy, so no matter how the algorithm is designed, information leakage cannot be reduced, and privacy improvement becomes mathematically impossible.
Convergence is slow initially. Early rounds have high Nash gap and modest privacy gain. The benefit grows only as N increases or more rounds run, not immediately.
Done right. On sparse polymatrix games with local eavesdropping, the algorithm delivers fair outcomes with shrinking information leaks as the group expands.
What a runnable demo should prove

What a runnable demo should prove

Build a three-player economic game where each player sets quantity (quantity competition, like a Cournot market). Player A and B compete directly; Player C buys from both. Run the algorithm with privacy constraints, recording the Nash gap and privacy loss at each round. Plot both metrics: they should both improve as rounds increase or as you add more players because the sparse game structure means fewer messages leak information.

Nash_gap = max_i (payoff_i(deviate) - payoff_i(current)), privacy_loss = bits the eavesdropper learns per player per round

The demo makes impossible to miss: fairness and secrecy rise together, not in opposition.
