Scaling Long-Horizon Agent via Context Folding

Let an agent branch into a subtask, finish it, and then collapse the finished branch into a short result summary so that long jobs can continue with much less active context.

Paper explainersAll themesAgents & Tool Use

Long-horizon agents often fail because they keep too much old detail in the active prompt. As the job grows, useful facts compete with stale intermediate steps for space. Many systems cope with this by hand-built summaries or extra helper agents, but those fixes are usually external to the agent's learned policy. Context Folding makes context management part of the learned behavior itself: the agent can open a branch for a subtask, finish the subtask, and then fold the branch into a concise record of what mattered.

Zero assumption version

Why long jobs overflow an agent's working context

A long task produces many intermediate steps that were useful while they were being solved but become clutter afterward. If those old details stay active forever, the agent spends more and more of its context budget on history instead of on the next decision.

Manual prompt engineering can hide some of that history, but it usually hard-codes one strategy for every task. Real tasks vary. Some subtasks need a full local search, while others only need a one-line outcome. A learned agent should decide for itself when to keep detail and when to compress it.

The paper's move in one sentence. Teach the agent to create explicit sub-branches for subtasks and then fold completed branches into short outcome summaries, with reward signals that favor good decomposition and good context control.

What the paper changes

What the paper changes

The paper changes context management from an external prompt recipe into an internal agent action. The agent does not just solve subtasks; it also decides how much of each solved subtask should remain active afterward.

the object it moves  =  the agent's active working context and the policy that decides how that context is compressed over time
The hidden quantity

The hidden quantity

measured quantity  =  which past details are still needed for future decisions and which can be safely folded away

The difficult hidden choice is not simply how much text to remove. It is which exact facts from a completed branch will matter later. Remove too little and the active context stays crowded. Remove too much and the main task loses information it still needs.

Context Folding trains the agent to estimate that hidden boundary. A branch can contain many local trials, but only some of them affect later decisions. Folding helps because the agent learns to keep outcomes, commitments, and open questions while discarding scratch work that no longer changes the plan.

Why it works

Why this works: local detail is useful while a subtask is live, not forever

A long agent trace contains two kinds of information: live local scratch work and durable task outcomes. Keeping both forever is wasteful because only the durable outcomes guide later subtasks. Context Folding separates those roles by giving the agent a place to do detailed local work and then a learned action for collapsing that work afterward.

The reward design matters because folding is only helpful when the compressed record still supports future success. The process rewards do not merely reward short context. They reward decompositions and folds that preserve downstream performance, so the agent learns to save space without throwing away needed conclusions.

Math after the picture

Prefer folds that save context without harming future success

First in words:

A compact summary is to value one branching-and-folding policy when it keeps task performance high while reducing the amount of active context that must remain available.

Then the compact form:

fold_score(path) = task_success(path) - alpha * active_context(path) + beta * summary_quality(path)

Every symbol:

fold_score(path)overall value of one agent trajectory with branching and folding
task_success(path)how well the agent completes the long-horizon task
active_context(path)how much unfinished history must stay active after folding decisions
summary_quality(path)how well folded summaries preserve facts that later steps still need
alpha, betaweights on context cost and summary usefulness
A tiny worked example
Path A keeps every local trace in active context.
It solves the task, but its context cost stays high because nothing is folded away.
Path B folds each completed branch into a short summary that keeps the needed outcomes.
It reaches similar task success with much smaller active context.
Training prefers Path B when the summary still supports later decisions.

The paper uses a fuller reward setup, but this equation captures the point that shorter context only matters when the agent still solves the task.

What can go wrong

What can go wrong

A fold can remove a fact that matters later. If the summary misses one dependency, the main task may fail much later because the dropped fact is no longer visible when it is needed.
The agent may branch too often. Excessive decomposition adds overhead because small subtasks may not repay the extra summary and branch management work.
Reward shaping may teach shallow compression tricks. If the rewards focus too much on shrinking context, the agent may learn to over-compress because shorter history alone is easier to optimize than future usefulness.
Done right. The framework matters because it treats context management as a learned decision tied to task success instead of a fixed outside rule.
What a runnable demo should prove

What a runnable demo should prove

Build a long workflow task such as multi-step research, file editing, or website implementation where several subtasks create long local traces. Compare a baseline agent that keeps the full trace active against a Context Folding agent that opens branches, summarizes them, and folds them back after completion.

The demo should report both task success and active context size over time. It should also inspect a few folded summaries to show that they retain outcomes and open obligations rather than raw scratch work, because that is the mechanism the paper claims.

context_drop = active_context_baseline - active_context_folded ; success_gap = task_success_folded - task_success_baseline

The result should show that long-horizon agents can stay coherent by deciding what to remember in active context and what to fold away.
