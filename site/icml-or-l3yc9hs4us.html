FIRE-Bench: Evaluating AI Agents on Scientific Rediscovery

A benchmark that tests whether AI agents can independently rediscover real scientific findings by designing and running their own experiments.

Paper explainersAll themesAgents & Tool Use

AI agents powered by large language models can now run full research cycles—posing questions, designing experiments, executing code, and drawing conclusions. But how do we know their discoveries are actually correct? This paper introduces FIRE-Bench, a benchmark that asks agents to rediscover real, verified findings from recent machine learning papers. The agent sees only the research question and must design experiments, run them, and argue for conclusions that match the original study's documented results. This grounds evaluation in something verifiable: did the agent independently arrive at the truth?

Zero assumption version

How do we grade an AI agent's research?

When an AI agent runs an experiment and publishes conclusions, how do we know they are right? Today's benchmarks give vague scores: they ask another AI system to grade the agent's paper, or they show a single number on a leaderboard. Neither tells us if the agent actually discovered something true.

The core problem: scientific discovery is only valid if the findings are true. But we do not know what truth the agent should find until after it finishes. By then, grading is guesswork—compare the agent's narrative to some reference, but the reference itself might be flawed, or the agent might have found something unexpected that current metrics miss. Real validation requires doing the experiments again and checking the results match, because each experiment takes real time to run and real money to fund. This wastes the whole reason for automating research—to save time and cost.

The method in one sentence. Instead of guessing if an agent's research is correct, ask it to rediscover findings that are already proven true, then score how closely the agent's independent results match the documented originals.

What the paper changes

What the paper changes: scientific grading

Instead of asking an AI judge or leaderboard to score an agent's research, FIRE-Bench grades the agent on a concrete, verifiable target: can it rediscover real, published findings? The shift is from subjective scoring to objective rediscovery.

The hidden quantity

The hidden quantity: Rediscovery alignment

measured quantity  =  rediscovery alignment

Rediscovery alignment measures how closely an AI agent's independently-derived experimental results match the documented findings of a real published study. It is not about whether the agent's reasoning is fluent or its paper well-written; it is purely about whether the agent found the same facts the original researchers did.

FIRE-Bench estimates this by computing an F1 score (a standard way to measure if two sets of findings overlap): the agent's conclusions are treated as a set of detected facts, the original study's findings are ground truth, and the F1 score measures the fraction of correct, complete overlap. A score of 100 means perfect rediscovery; below 50 indicates the agent missed or contradicted the original findings.

Why it works

Why it works: grounding discovery in verifiable truth

The key move: instead of asking an agent to generate original research (which we cannot grade without doing the work ourselves), ask it to rediscover findings we already know to be true. This flips the problem from evaluation to verification. We do not grade the agent's creativity or writing; we measure whether it independently arrived at the documented facts.

Here is the causal chain: when an agent must rediscover a real finding, every step is exposed to ground truth. If the agent proposes a flawed experiment, we can see it did not match the original method—and that mismatch predicts failure. If the agent collects data but misinterprets it, we can measure the drift between its conclusions and the correct ones. If the agent's run-to-run results vary wildly, we see it is not reliably reasoning. None of this is subjective. Rediscovery makes the agent's reasoning transparent, because we know what the right answer is.

The measurement: F1 score on rediscovered facts

First in words:

F1 score measures the overlap between agent-discovered facts and ground-truth facts. It balances two ideas: precision (what fraction of the agent's claims are correct) and recall (what fraction of the true findings did the agent catch).

Then the compact form:

F1 = 2 * (precision * recall) / (precision + recall); precision = correct_claims / total_agent_claims; recall = correct_claims / total_true_facts

Every symbol:

precisionwhat fraction of the agent's conclusions are correct
recallwhat fraction of the true findings did the agent discover
correct_claimsthe agent's conclusions that match ground truth
total_agent_claimsall conclusions the agent drew
total_true_factsall documented findings in the original study
A tiny worked example
Original study made 4 documented findings: A, B, C, D.
Agent independently discovered: A, B, E (a false conclusion).
Correct claims = 2 (A and B); total agent claims = 3; precision = 2/3 = 0.67.
Total true facts = 4; agent caught 2; recall = 2/4 = 0.5.
F1 = 2 * (0.67 * 0.5) / (0.67 + 0.5) = 2 * 0.335 / 1.17 = 0.57 (57%).

A higher F1 means the agent found most of the true findings and did not invent false ones; a low F1 means it missed facts or made incorrect claims.

What can go wrong

What can go wrong

Experimental design flaws. The agent proposes a method that does not match the original setup. If the original study used specific data or hyperparameters, the agent must infer them. A bad guess in experimental setup leads to findings that drift from ground truth, because the experiment measures different things—different data distribution, different training speed, different optimization surface—and those differences produce different numbers.
Execution errors. The agent writes code but introduces bugs—off-by-one errors in data loading, incorrect loss functions, wrong train/test splits. These cause the agent's measurements to diverge from the original results.
Misinterpretation of data. The agent runs the experiment correctly but draws the wrong conclusion from the results. For example, it might see noise and call it a signal, or miss a true effect because it misread a plot.
High run-to-run variance. Some experiments are noisy. If the agent's conclusions differ wildly across independent runs, it is not reliably reasoning, and rediscovery alignment will be low.
Done right. An agent that designs sound experiments, executes code accurately, interprets results fairly, and draws conclusions that match the original study will achieve high rediscovery alignment.
What a runnable demo should prove

What a runnable demo should prove

Build a small version of FIRE-Bench: pick one published finding (e.g., a result from a recent paper showing that a neural network trick reduces overfitting), code up the experiment so it is runnable in 5 minutes, and test whether a simple agent baseline can rediscover it. Have the agent propose a method, run your code, and measure the F1 score between the agent's conclusions and the true result.

rediscovery_f1 = (agent_found_facts AND ground_truth_facts) / ((agent_found_facts OR ground_truth_facts) + small epsilon for numerical stability)

A demo would make undeniable that when an agent fails to rediscover a verified finding, it is not a problem with the benchmark—it is a real limitation in the agent's ability to reason about experiments and evidence.
