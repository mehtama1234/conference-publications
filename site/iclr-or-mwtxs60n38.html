Implicit 4D Gaussian Splatting for Fast Motion with Large Inter-Frame Displacements

SPIN-4DGS reconstructs fast-moving dynamic scenes by predicting Gaussian attributes from explicit space-time positions instead of forcing one shared Gaussian description to fit several far-apart frames.

Paper explainersAll themesOther

Dynamic 4D Gaussian splatting works well when motion between frames is small. It breaks when objects move far between frames. Existing methods either deform a canonical set of Gaussians over time or optimize explicit 4D Gaussian attributes that are shared across frames. Under large displacement, both strategies can lose the moving object: the canonical space may never allocate enough Gaussians to it, or the shared attributes may collapse toward the easier static background. SPIN-4DGS changes the representation. It first gathers explicit spatiotemporal positions for Gaussians and then predicts the other Gaussian attributes from those positions with a small feed-forward network. That separates where the Gaussian is from how it should look at that time.

Zero assumption version

Why fast motion breaks existing 4D Gaussian splatting

A dynamic scene renderer must place many small Gaussian primitives in 3D space and assign each one a size, orientation, color, and opacity. When motion between frames is small, a Gaussian can often be tracked or deformed smoothly over time. When motion is large, that assumption becomes fragile. A ball may jump far across the image, or a limb may move far enough that a shared canonical description no longer covers it.

The paper identifies two failure modes. In deformable approaches, the canonical space may omit fast-moving content at initialization, so later deformation has nothing to move. In explicit 4D approaches, one set of Gaussian attributes is optimized across several timestamps, and updates for easy background regions can dominate the loss. The moving object then becomes blurred or disappears.

The breakdown is mostly in attribute learning. Positions may still roughly track the motion, but color, opacity, scale, and rotation collapse because background fitting dominates the optimization.

What the paper changes

What the paper actually changes

SPIN-4DGS changes how time is built into dynamic Gaussians. Instead of learning time-varying attributes directly as explicit per-Gaussian variables or as deformations from one canonical state, it learns a mapping from explicit space-time positions to attributes.

the object it moves  =  time-dependent design of Gaussian attributes
The hidden quantity

The hidden quantity: attribute stability under large displacement

measured quantity  =  Whether moving-object Gaussians keep coherent attributes over time

The critical quantity is not just position error. It is attribute stability: can the representation keep the right appearance and support of a fast-moving object as it appears in very different places at nearby times? If color or opacity collapses, the object vanishes from the rendered result even if some positions remain.

The paper argues that explicit space-time positions make this stability easier to learn. Once each timestamp has its own position sample, the predictor can assign attributes conditioned on that sample alone instead of forcing one shared attribute state to serve conflicting frames.

Why it works

Why explicit space-time positions reduce collapse

In an explicit 4D model with shared attributes, one update can improve one frame while hurting another, because several timestamps are tied together through the same Gaussian state. That creates cross-frame interference. Background regions usually dominate the reconstruction loss, so the optimization tends to favor them. Fast-moving objects lose out because they occupy fewer pixels and appear in more variable positions.

SPIN-4DGS reduces that coupling by conditioning attribute prediction on explicit coordinates in space and time. Each point on the motion path gets its own query. The predictor can therefore emit different color, opacity, scale, or rotation values at different timestamps without storing separate explicit variables for every point. That keeps memory manageable while still separating far-apart states of the same object.

The learned implicit predictor also shares information across many Gaussians. That matters because similar local motion patterns can reuse the same decoder rather than learning isolated per-point values. The representation is therefore compact in storage but flexible in time, which is exactly what fast motion needs.

The core mapping

First in words:

A small network takes a space-time coordinate and outputs the Gaussian attributes needed for rendering at that location and time.

Then the compact form:

attributes(x, y, z, t) = f_theta(x, y, z, t)

Every symbol:

(x, y, z, t)the spatial position and timestamp of a Gaussian query
f_thetathe feed-forward predictor that maps each query to Gaussian attributes
attributesscale, rotation, color, and opacity used for rasterization
A tiny worked example
Suppose a basketball appears at position P1 at time t1 and at a far-away position P2 at time t2.
A shared explicit attribute model tries to use one Gaussian description across both times, so updates from background-heavy frames can wash out the ball.
SPIN-4DGS instead queries f_theta at (P1, t1) and at (P2, t2).
The two queries can return different opacity and color values while still sharing the same predictor.
That separation matters because the renderer no longer needs one attribute state to explain two far-apart appearances.

The point of the mapping is practical. It isolates large-displacement states while keeping the representation compact.

What can go wrong

What can go wrong

Position coverage is incomplete. If the spatiotemporal position set misses part of the motion path, attribute prediction cannot recover it later, because the decoder only answers the queries it is given.
Implicit predictor is too weak. If the feed-forward network cannot model the needed time-varying appearance, the method may keep positions but still produce dull or unstable attributes.
Fast motion plus occlusion remains hard. Large displacement is only one source of difficulty. Heavy occlusion or missing views can still make the rendered evidence insufficient for accurate reconstruction.
Done right. The method is strongest when the initial space-time positions cover the full trajectory and the decoder has enough capacity to map those positions to stable attributes across time.
