Unified Multimodal Autoregressive Modeling with Shared Context—Visual Tokenizer is Key to Unification

Use one visual coding system for both image understanding and image generation so the model can read and write images inside a single shared token space.

Paper explainersAll themesMultimodal

Many multimodal systems claim to unify image understanding and image generation, but they often hide a split inside the architecture. One tokenizer, meaning a system that turns an image into a sequence of discrete units, converts images into codes for understanding tasks, while another tokenizer or decoder-specific codebook handles generation. That means the model is never truly operating on one common visual language. UniAR removes that split. It builds one discrete visual tokenizer and then uses those same codes for both reading images and generating new ones. The paper's main claim is that this shared code space is the missing ingredient for a genuinely unified autoregressive model, which is a model that predicts the next token, meaning the next discrete unit in a sequence, step by step.

Zero assumption version

Why two visual tokenizers break unification

A multimodal model that answers questions about images and also generates images has to move between pixels and language-like sequences. Most systems do that with separate encoders or separate codebooks. The understanding path learns one visual representation, while the generation path learns another. That causes a translation gap because a visual token produced during generation is not immediately interpretable by the understanding stack.

That split blocks a strong form of self-consistency. If the model generates an image token sequence, it should be able to reason over that exact sequence without first re-encoding the pixels through a different module. Otherwise the system cannot fully reuse its own outputs as context. The paper treats that re-encoding requirement as evidence that current unification is incomplete.

The paper's move in one sentence. Replace separate visual coding schemes with one shared discrete tokenizer so generated image tokens can be read directly by the same autoregressive model that writes them.

The algorithm as a flow

What it actually does

Encode an image into shared visual codes

Use one pretrained vision encoder with multi-level feature fusion, meaning a merge of coarse and fine visual features, to extract image information before conversion into discrete codes.

Convert into discrete bits

Turn continuous features into a finite set of visual codes through lookup-free bitwise quantization, which represents codes with binary decisions rather than a large stored table.

Feed those codes into one autoregressive model

Let a single next-token model consume text tokens and visual tokens in one sequence because both tasks now speak the same internal language.

Predict grouped bits in parallel

Generate several code components together across nearby spatial positions so image generation needs fewer sequential steps.

Decode codes into an image

Use a diffusion-based decoder, meaning a model that reconstructs pixels from noise-conditioned denoising, to turn the discrete visual tokens back into a detailed image.

Why it works

Why this works: one code space removes translation debt

When a model uses different visual encodings for understanding and generation, it pays a translation cost every time it switches roles. Information can be lost or distorted because one encoder may preserve semantics while another emphasizes visual detail. A shared tokenizer reduces that mismatch because the same discrete codes carry both kinds of information.

The tokenizer design matters. Multi-level feature fusion keeps both high-level content and low-level appearance because image understanding and image generation need both. Bitwise quantization matters because a finite codebook can become too small if it only stores a few coarse categories. Representing codes through bit patterns gives the system many possible combinations with modest storage, so it can preserve detail without making the visual vocabulary impossible to handle.

The parallel bitwise prediction step then attacks the main speed problem in autoregressive image generation. If the model had to predict every visual code one after another, the sequence would be too long. Grouping spatial positions and predicting several bit components jointly shortens the effective sequence, so generation becomes practical while the shared token language is preserved.

A simplified training objective

First in words:

The model minimizes a token prediction loss over text and visual codes plus a reconstruction loss that teaches the decoder to turn visual codes back into images.

Then the compact form:

L = L_AR(text_tokens, visual_tokens) + beta * L_decode(image, visual_tokens)

Every symbol:

L_ARautoregressive next-token loss over the shared multimodal sequence
text_tokenslanguage tokens in the context
visual_tokensshared discrete image codes produced by the tokenizer
L_decodedecoder reconstruction loss for rebuilding the image from visual tokens
betaweight that balances sequence modeling and image reconstruction
A tiny worked example
Suppose the sequence loss on one batch is 1.4 and the decoder loss is 0.5.
If beta is 0.6, the total is 1.4 + 0.6 times 0.5.
That gives 1.4 + 0.3 = 1.7.
Lowering the total requires the shared tokens to be good both for prediction inside the language model and for rebuilding pixels.

The real system has extra structure for multi-level codes and diffusion decoding, but this summary captures the main tension: token usefulness versus visual fidelity.

What can go wrong

What can go wrong

One tokenizer may still be a compromise. Generation wants fine appearance detail, while understanding often wants abstraction. A single code space can underperform if it is too coarse for generation or too detailed for efficient reasoning because those pressures pull in different directions.
Bitwise codes can be hard to optimize. Discrete decisions create training difficulty if the quantization stage is unstable because small encoder changes can flip code bits and disturb the autoregressive model.
Parallel grouping can miss long-range structure. Predicting grouped visual bits saves steps because fewer sequential predictions are needed, but it can weaken fine global coordination if the grouping strategy does not pass enough context across distant image regions.
Done right. The method works when the tokenizer preserves enough semantics and enough detail at the same time, and when the grouped prediction design reduces sequence length without destroying spatial coherence.
What a runnable demo should prove

What a runnable demo should prove

Build two small text-image systems. In the first, use one tokenizer for image understanding and a separate one for generation. In the second, use one shared discrete tokenizer for both. Give both systems three tasks: answer a question about an input image, edit an image from a text instruction, and continue reasoning over an image that the model itself just generated.

The demo should show that the shared-token system can carry its generated visual codes directly into the next reasoning step without a second image encoding pass. It should also measure generation speed with and without grouped bit prediction so the effect of sequence compression is visible.

shared_context_gain = task_score_shared - task_score_split

A convincing demo must show genuine token reuse across tasks, not just similar benchmark numbers from two separate visual pathways.
