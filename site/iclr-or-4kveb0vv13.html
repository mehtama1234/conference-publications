InfoRMIA: Token-Level Membership Inference for LLMs

Instead of asking if the model memorized an entire sentence, ask which exact words inside it came from the training data.

Paper explainersAll themesAlignment, Safety & Fairness

Large language models are trained on almost all text available online, so they inevitably memorize chunks of it. When you ask the model a question, it might regurgitate verbatim training data, leaking privacy. The standard way to catch this is membership inference: you run tests to see if the model memorized a given sentence. But this approach treats a whole sentence as one yes-or-no question, losing all the detail about which parts are actually remembered. This paper asks the question at a finer level: which individual tokens (words or word pieces) inside the output came from training, and which are fresh?

Zero assumption version

Whole sentences hide which parts are memorized

An LLM trained on billions of web pages will memorize some of that text word-for-word. When it answers a question, it might output a sentence that is partially or fully copied from training. This is a privacy leak: if you trained the model on a person's email, and the model outputs that email, you have exposed it.

To check if a model leaks data, researchers use membership inference: they write a test that scores a sentence and says yes (the model memorized this) or no (the model generated this fresh). But a whole sentence is huge. If even one token is memorized and the rest is new, you get a yes. You lose all information about which tokens are the actual leakers. A beginner might run the test and get a membership score, but learn nothing about WHERE the memorized part is or how to fix it.

The standard test compresses a sentence into one binary answer. Ask membership inference token by token, so you pinpoint exactly which words came from training.

The algorithm as a flow

What it actually does

Test each token separately

For every token the model outputs, run a membership test on just that token (and the prefix before it).

Compare to reference models

Run the same prompt on several other models trained on different data, measure what those models output.

Score each token's likelihood

Compute a probability: how much more likely is this token under the training model than under the reference models?

Mark high-probability tokens

Tokens with high probability are probably memorized; low probability are likely fresh.

Locate memorized chunks

Connect consecutive high-probability tokens to identify contiguous memorized phrases in the output.

What the paper changes

The grain of analysis moves down

The paper changes the unit of membership testing from the entire sequence down to individual tokens. Instead of one test per output (a sentence), you run one test per token (one test per word or word piece). A token is a small unit the language model uses internally—typically a word or subword like ing or re. By testing each one separately, you preserve information that the old method threw away.

the object it moves  =  granularity of membership testing
The hidden quantity

Token memorization probability: how likely is this word from training?

measured quantity  =  token memorization signal

The hidden quantity is a per-token probability: for each token the model outputs, how likely is it that the model learned to generate that token directly from its training data, versus generating it from scratch? This is measured as a ratio—the probability of seeing this token in the target model's output divided by the average probability of seeing it in the reference models' outputs. If the target model gives a token much higher probability than the reference models do, that token is likely copied from training.

The paper estimates this signal by running two sets of models in parallel: the suspect model (the one you want to audit) and a set of clean reference models (trained on different data). For each token position, it computes a log-likelihood ratio—how many times more likely is the target's choice than the reference models' average? High ratio means memorized; low ratio means the token is not distinctive to the suspect model's training.

Paper reading. The signal is a log-likelihood ratio of the target model's token probability to the geometric mean of reference models' token probabilities, forming a composite hypothesis test of membership.
Why it works

Why comparing models reveals memorization

A language model trained on data learns to assign high probability to common patterns from that data. If the model saw the phrase 'the quick brown fox' thousands of times in training, it will assign high probability to 'fox' when it sees 'the quick brown'. A model trained on different data (without that phrase) will assign lower probability to 'fox' in the same context.

The trick is to compare two models: one trained on the suspect data, one trained on clean data. For each token, you measure the ratio of their probabilities. If the ratio is high (suspect assigns much higher probability), the token is probably from the suspect's training. If the ratio is low (both models agree), the token is probably a common pattern that both learned. By doing this token by token instead of sentence by sentence, you pinpoint exactly which words are stolen.

Math after the picture

The membership score formula

First in words:

score = log( probability_target_model / geometric_mean( probability_reference_models ) )

Then the compact form:

Score_token = log( P_target(token|prefix) ) - ( 1/K ) * sum_k log( P_ref_k(token|prefix) )

Every symbol:

P_target(token|prefix)probability the suspect model assigns to this token, given the words before it
P_ref_k(token|prefix)probability of reference model k to the same token in the same context
Knumber of reference models
lognatural logarithm
Score_tokenthe membership signal; high score means memorized
A tiny worked example
Prefix: 'the quick brown' at position 4, token is 'fox'.
Suspect model P_target(fox|prefix) = 0.8 (thinks it is likely).
Reference model 1 P_ref_1(fox|prefix) = 0.1.
Reference model 2 P_ref_2(fox|prefix) = 0.15.
Geometric mean of references: (0.1 * 0.15)^(1/2) = 0.122.
Ratio = 0.8 / 0.122 = 6.56.
Log ratio = log(6.56) = 1.88.
High positive score: this token is likely memorized from the suspect's training.

A high score means the target model assigns much higher probability than the references, which signals that token was learned from the target's training data, not from general text patterns.

What can go wrong

What can go wrong

Reference models must be truly independent. If your reference models were trained on overlapping data, they will give high probabilities to the same tokens, washing out the signal. The ratio will be close to one and you will miss memorization.
Common tokens mask memorization. Tokens like 'the' or 'is' have high probability in all models. Even if the suspect model memorized them, the ratio is close to one and they look generic. Only truly distinctive phrases light up.
Prefix history matters. The same token has different probabilities depending on what came before it. Testing token 5 in isolation and in context gives different scores. The method must always include the prefix.
Done right. Use independent reference models, test each token with its full prefix, aggregate token scores into contiguous memorized phrases, and use the results to target unlearning (retraining to forget).
What a runnable demo should prove

What a runnable demo should prove

Build a small language model from scratch on a dataset containing known phrases (like a repeated sentence or poem). Then train a second model on a dataset without those phrases. For each, run membership inference token by token on a sentence that contains both memorable and freshly generated tokens. Plot a bar chart showing the memorization scores.

memorization_accuracy = (memorized_tokens_marked_high + novel_tokens_marked_low) / total_tokens

The demo must show that memorized tokens consistently score higher than freshly generated tokens, and that the token-level method catches memorization that the whole-sentence method would miss or obscure.
