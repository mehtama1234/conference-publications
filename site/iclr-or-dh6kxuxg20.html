Multi-Agent Distillation of Biomedical Training Data

Specialized AI agents working together extract high-quality training data from medical literature by reasoning about what a biomedical question should look like.

Paper explainersAll themesOther

Training a language model to answer medical questions is hard because good training data is scarce. Existing approaches either use human experts (slow and expensive), apply one generic rule (misses nuance), or have a single AI do all the work (no specialized reasoning). This paper introduces a team of specialized AI agents that collaborate, each guided by a medical knowledge map (the MeSH hierarchy), to automatically extract realistic question-answer-context triples from millions of research papers. The result is a large, high-quality corpus ready to train biomedical language models.

Zero assumption version

The corpus bottleneck

Biomedical language models need thousands of training examples (pairs of questions and answers with supporting documents), but building them by hand takes expert time. Existing open-source biomedical datasets are high-quality but tiny; their limited size means the trained model sees too few examples and stays narrow.

A naive attempt: grab raw medical papers and ask a single generic AI to generate questions. The problem: a single AI does not reason like a medical expert. It misses fine distinctions (a question about mechanism differs from one about treatment), treats all papers equally (ignores that some are core references), and produces variations that do not capture the true scope of medical knowledge. The result is a corpus that looks bigger but teaches the model poorly.

The core problem: You have millions of raw medical papers but cannot efficiently extract good training triples that cover the full range of medical knowledge.

The algorithm as a flow

What it actually does

Agent 1 generates questions

The QA-generation agent, guided by the MeSH hierarchy, creates question-answer pairs rooted in real medical concepts.

Agent 2 retrieves supporting documents

The context-retrieval agent searches 23 million papers for documents most relevant to each question using dense search.

Agent 3 evaluates the triples

The preference-evaluation agent, trained on MeSH rules, judges which question-context pairs are best aligned with medical knowledge.

Agent 3 learns from examples

The evaluator is fine-tuned on a small seed set of expert-labeled pairs, so it learns to score like a medical expert.

The final corpus is assembled

High-scoring triples are collected into a large, structured training dataset ready to fine-tune biomedical language models.

What the paper changes

Instead of a single AI extracting data, the paper deploys a multi-agent team where each agent specializes in one task (generation, retrieval, or evaluation) and all three are guided by the MeSH medical ontology.

The hidden quantity

Medical alignment: the key measure

measured quantity  =  MeSH alignment score

The paper introduces an alignment score: how well each question-context pair covers the intended medical concept from the MeSH hierarchy. It is not measured by hand or by external benchmarks; instead, it is computed by the evaluator agent using learned rules derived from the MeSH structure and a small seed dataset.

The evaluator estimates this score automatically: given a question, context, and answer, it predicts whether a human expert would rate this triple as high-quality, using the MeSH hierarchy as ground truth. This is how the system knows which triples to keep.

Why it works

Why three agents work better than one

A single generic AI is a bottleneck: it generates questions without deep medical reasoning, has no way to find the best supporting documents, and cannot judge quality without external data. The paper breaks this into a relay:

Generation with structure: The QA-generation agent is guided by the MeSH hierarchy, so it learns to generate questions rooted in real medical topics (not random variations). It produces diverse questions because MeSH covers the full medical knowledge space.

Retrieval by relevance: The context-retrieval agent uses dense search (encodes both questions and papers into numbers that measure similarity), so it finds papers that actually address each question. A single AI cannot do this well because it has not seen how to match questions to evidence.

Filtering by alignment: The preference-evaluation agent is trained on a small seed dataset of expert-rated triples (labeled with MeSH rules), so it learns what medical experts care about. This allows it to filter the full corpus down to high-quality examples without human re-review. By training the evaluator on the MeSH hierarchy itself (not generic labels), it learns to recognize medical coherence because it sees concrete examples of what experts consider well-aligned.

Scoring formula

First in words:

For each generated triple, the evaluator computes an alignment score using learned weights that capture how well the question and answer fit the medical topic from MeSH.

Then the compact form:

alignment_score = sum over MeSH topics: w_topic * match(question, topic) * match(answer, topic)

Every symbol:

w_topiclearned weight for each medical topic (learned from seed examples)
match(question, topic)how much the question mentions or implies this medical concept (0 to 1)
match(answer, topic)how much the answer is about this medical concept (0 to 1)
alignment_scorefinal score (higher = better medical alignment)
A tiny worked example
Question: how do statins lower cholesterol? Topic: Cholesterol drug treatments w_topic=0.9
match(q, topic)=0.95 (question directly asks about statins and cholesterol), match(a, topic)=0.92 (answer explains the mechanism)
Contribution: 0.9 * 0.95 * 0.92 = 0.79 (high score, keep this triple)
Question: what is the chemical formula for water? Topic: Biochemistry basics w_topic=0.5
match(q, topic)=0.3 (off-topic), match(a, topic)=0.2
Contribution: 0.5 * 0.3 * 0.2 = 0.03 (low score, discard this triple)
The evaluator filters to keep only triples where alignment exceeds a threshold (e.g., 0.6).

The weights are learned from a small seed set of expert-labeled triples, so the evaluator learns to recognize what medical experts consider high-quality.

What can go wrong

What can go wrong

Seed set too small or non-representative. If the initial expert-labeled examples do not cover the full MeSH hierarchy, the evaluator learns a biased scoring function. It may over-weight common topics and miss rare but important medical areas. Fix: ensure the seed set spans diverse MeSH branches.
Dense retrieval fails on niche topics. The retriever uses dense search (learned embeddings), which works well for common medical queries but may miss papers on rare diseases or new treatments because few papers discuss them. A paper on a rare genetic disorder might not have similar papers in the corpus to learn from.
MeSH hierarchy incomplete or outdated. MeSH is maintained by hand and evolves slowly, because adding new medical concepts requires expert committee review and integration with existing terms. New medical concepts or treatments emerge faster than this process, so if a hot new drug class is not yet in MeSH, the QA-agent may not generate questions about it (since the agent is guided by MeSH terms), and the corpus will be incomplete in that area.
Done right. When the seed set is diverse, the retriever is tuned for medical language, and MeSH is current, the three-agent relay produces a large, diverse, medically-coherent corpus without manual effort.
