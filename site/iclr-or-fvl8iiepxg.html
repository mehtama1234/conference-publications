Forget Forgetting: Continual Learning in a World of Abundant Memory

When you have enough memory to save old examples, the real problem shifts from forgetting to being too stuck in old learning patterns, and you fix it by resetting lazy weights and averaging trained ones.

Paper explainersAll themesOther

Continual learning means training a model on many tasks one after another without forgetting earlier ones. The standard assumption was that storage (keeping old examples) was the bottleneck. But on modern computers, the real bottleneck is GPU time. This paper says: when storage is cheap, the bottleneck shifts. Models get too stuck in their learned patterns and struggle to learn new things—a problem called low plasticity. The fix is simple: periodically reset weights that are not doing much, and average the weights across your training to smooth out the learning path.

Zero assumption version

The old assumption breaks in a new world

For decades, continual learning papers tried to minimize how many old examples you keep in memory. The thinking was simple: storage is expensive, so keeping fewer examples makes the method practical. Under this tight constraint, the core problem was forgetting—the model would overwrite what it learned from task one when learning task two.

But modern systems have cheap storage and expensive GPU time. A small pile of old examples fits easily in memory. So researchers started asking: what if we just keep lots of old examples? Then forgetting goes away because the model sees old examples every training step.

When you do this naively, a new problem appears. The model sees mostly examples from the old task mixed in, so it stays stuck in the old learning pattern. It becomes reluctant to learn anything new—a problem called plasticity (the opposite of stability, which is remembering old things well). A beginner tries simply turning off the old safeguards, but then the model forgets the old tasks immediately.

The paradox. With plenty of memory, forgetting is solved, but the model gets stuck in old patterns and learns new tasks slowly or badly.

The algorithm as a flow

What it actually does

1. Measure each weight

For each number in the model, compute how much it changed across many training steps—big changes mean it is working, tiny changes mean it is asleep.

2. Rank by activity

Sort the weights by activity score. Find the bottom half: the ones that barely moved.

3. Reset dormant weights

The lazy weights get reset to their original starting value from pretraining, giving the model a fresh basis to learn the new task.

4. Average across training

Keep a running average of all weights as you train on the new task. This smooths the learning path and pushes the model toward regions where small weight changes do not cause big prediction changes.

5. Train normally

Use the averaged weights as the model, and training proceeds as usual. No extra compute, no storing checkpoints.

What the paper changes

What the paper changes

The paper operates directly in weight space—the numbers inside the model. It changes two things: which weights get reset (the dormant ones, ranked by activity), and how the training weights evolve (by averaging). Both changes happen during normal training, not as a post-hoc step.

the object it moves  =  model weights
The hidden quantity

The hidden quantity: dormancy of each weight

measured quantity  =  Per-weight activity score

The paper measures how hard each weight is working by looking at its gradients (the signals that nudge it during training). A weight with big gradients across many steps is working; a weight with tiny gradients is asleep. Formally, they compute a score for each weight using the first and second moment of its gradients—the average change and the average squared change, the same trick used in the Adam optimizer.

The paper uses this hidden quantity to decide which weights to reset. Dormant weights are those with low activity scores. Resetting them does two things: it removes the old-task bias (because that bias is built into those weights), and it frees up learning capacity for the new task.

Why it works

Why it works: the real chain of causation

The core insight is this: when old examples dominate the training data (because memory is abundant), the model sees mostly old-task patterns. Its learning signals are biased toward refining old-task features, not discovering new-task features. This makes the model stiff—plasticity plummets—because the weight updates nudge the model to double down on old patterns instead of trying anything different.

Resetting dormant weights removes that bias. Those weights carry the old-task tuning; resetting them gives the model a blank slate for new features. The weights that stay put are the ones that worked hard, so they carry useful general knowledge. This split—reset the biased weights, keep the general ones—lets the model learn new tasks fast.

Weight averaging smooths the training path. As the model learns, its weights bounce around (oscillating up and down). Averaging them together pushes the model toward regions where small changes in weights do not cause big changes in predictions. This is good for stability: such regions generalize better and forget less, because if a small change in weights does not break predictions, then small noise or interference from new data does not wipe out old learned patterns.

Both operations happen during training, not after. No checkpoints, no retraining—just two lightweight weight-space tweaks that cost almost no GPU time.

Math after the picture

The equation and worked example

First in words:

Activity score for each weight is the magnitude of its average gradient change, divided by its average squared change. Weights below a rank threshold are reset to their pretrained values. The model is trained on a hybrid mix of old and new examples; the averaging is computed as a running mean of all weight values across training iterations.

Then the compact form:

S_l = ||m-hat_l|| / sqrt(v-hat_l + epsilon) [reset if rank(S_l) < cutoff] theta_avg = alpha * theta_avg + (1 - alpha) * theta_current

Every symbol:

S_lactivity score for weight l
m-hat_lfirst exponential moment of gradients for weight l (like momentum)
v-hat_lsecond exponential moment of gradients for weight l (like variance)
epsilonsmall number to avoid division by zero
rank(S_l)position of weight l when sorted by activity (lowest rank = laziest)
cutoffthreshold; reset all weights with rank below this
theta_avgrunning average of weights
theta_currentcurrent weight value at this iteration
alphadecay rate for the averaging (e.g., 0.9)
A tiny worked example
Consider three weights during task 2. Measure their gradients over 100 steps.
Weight w1: gradients big and variable. m-hat = 0.5, v-hat = 0.3. S_1 = 0.5 / sqrt(0.3) ≈ 0.91 (high activity, rank 1, keep it).
Weight w2: gradients tiny and consistent. m-hat = 0.05, v-hat = 0.001. S_2 = 0.05 / sqrt(0.001) ≈ 1.58 (medium, rank 2, keep it).
Weight w3: gradients almost zero. m-hat = 0.01, v-hat = 0.0001. S_3 = 0.01 / sqrt(0.0001) ≈ 1.0 (lowest, rank 3, reset to pretrained value).
Cutoff = rank 2, so only w3 resets. w1 and w2 stay, carrying useful learned structure. With w3 fresh, the model can discover new task-specific patterns without old-task bias.

The activity score measures how much a weight is actually being used during training. Low scores mean the weight carries bias but not useful learning.

What can go wrong

What can go wrong

Cutoff rank is wrong. If you reset too many weights (aggressive cutoff), the model loses useful learned structure and forgets badly. If you reset too few (conservative cutoff), plasticity stays low and new tasks learn slowly. The paper does not deeply explore this sensitivity; in practice, tuning the cutoff per dataset is needed.
Averaging decay rate matters. If the decay rate alpha is too high (e.g., 0.99), the average lags far behind the current weights, weakening the stabilizing effect. Too low (e.g., 0.5) and the average forgets recent training. The right value depends on task length.
Abundant memory assumes bounded forgetting. The method assumes that old examples stay available and do not change. If the sequence of tasks shifts dramatically—where later tasks are completely different from earlier ones—then keeping fixed old examples may not be enough to prevent forgetting.
Done right. When the cutoff and averaging rate are tuned for the task sequence, Weight Space Consolidation trades off stability and plasticity gracefully, matching the cost and often the accuracy of the best competing methods.
What a runnable demo should prove

What a runnable demo should prove

Build a small image classifier (ResNet-18 or similar) trained on a sequence of three image datasets (e.g., CIFAR-10 -> Flowers -> MNIST). At each step, store all examples from prior tasks. Train with three strategies: (1) replay (train only on new examples plus old ones, no resets or averaging), (2) naive reset (reset all weights every task), (3) Weight Space Consolidation (rank and reset dormant weights, average during training). Measure accuracy on all tasks after each new task arrives. Plot a line for each method. The plot should show: replay is stable (high old accuracy, okay new accuracy) but slow at learning new tasks; naive reset learns new tasks fast but forgets catastrophically; Weight Space Consolidation balances—new task accuracy stays high and old task accuracy does not crash.

forgetting_rate = avg( old_task_accuracy_before_task_t - old_task_accuracy_after_task_t ) over all old tasks; plasticity_score = new_task_accuracy at end of first epoch on new task; cost_ratio = gpu_time(method) / gpu_time(replay)

The demo makes impossible to miss: selective resets recover plasticity (higher plasticity score than replay), averaging maintains stability (lower forgetting rate than naive reset), and both cost nearly the same as replay (cost ratio near 1).
