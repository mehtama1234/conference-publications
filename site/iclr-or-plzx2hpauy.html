RICH: Robustness from Inference Compute Hypothesis

Inference compute helps models resist attacks only if the training data already contains the building blocks of the attacked examples, because models protect themselves by reassembling learned behaviors.

Paper explainersAll themesAlignment, Safety & Fairness

When attackers craft adversarial inputs designed to trick models into ignoring their safety guidelines, researchers have discovered that spending more compute at test time (when answering) can help—because the model can think through the attack and find learned defensive patterns to deploy. But this works only for models whose training already included pieces of the attack. This paper explains why using the idea of compositional generalization: models protect themselves by reassembling learned patterns into new defenses, so what the model learned during training sets the limit on what it can do later.

Zero assumption version

Why extra thinking time does not always help

When people carefully think through a hard problem, they often find better answers—because they can work through the problem step by step and spot errors. Researchers hoped the same would work for language models: if a model spends more compute at inference time (more tokens to reason before answering), it could resist jailbreaks and malicious instructions even if the attacker can see the model's internals or attack images alongside text.

This seemed promising in simple cases. But when researchers tested it against determined attackers or on vision-language models with multimodal attacks, the extra thinking time stopped helping. A model that was not trained on adversarial examples remained vulnerable no matter how much it reasoned—because thinking alone cannot invent knowledge the model never learned.

In one sentence. The paper shows that inference compute boosts resistance to attacks only when the model was trained on data containing the building blocks of the attack, because the model can only recombine patterns it has already learned.

What the paper changes

What the paper changes

Instead of assuming inference compute helps all models equally, the paper redirects the investment strategy: a model's capacity to turn extra thinking into defense is set during training, because the reasoning process can only work with patterns the model has already learned. The paper does not change how the model reasons; it changes which models are worth giving reasoning time to, and reveals that training-time hardening (making the model harder to jailbreak from the start) amplifies the downstream value of test-time reasoning.

the object it moves  =  training-time data hardening
The hidden quantity

How close is the attack to what was trained?

measured quantity  =  Attack closeness to training data

The hidden quantity is how much of the jailbreak or adversarial attack overlaps with examples the model saw during training. If an attacker crafts an input by combining pieces the model has already encountered (like combining known harmful request types or image manipulations the model defended against before), the attack is close to the training set. If the attack invents entirely new ways to fool the model, it is far away.

The paper measures this by testing models with different training histories and varying the attack strength. A weak model trained only on benign data has zero overlap. A model that received adversarial examples during training has high overlap. By shrinking the attack budget (making it less severe), the paper moves the attack closer to the data the model has seen, and watches whether that changes whether inference compute helps.

Why it works

How reassembling learned pieces unlocks defense

When a model has learned to recognize and deflect many harmful requests separately during training, it has built a toolkit of defensive behaviors. At test time, when the model reasons over many reasoning tokens, it is not inventing new defenses—it is recombining the ones it already learned. Imagine a model trained to say no to requests asking for passwords, and separately trained to notice when phrasing is manipulated. When an attacker combines both tricks in a new jailbreak, the model's reasoning process can combine those two learned defenses into one.

This only works if the model trained on both pieces. A model that only saw benign data has no toolkit at all. Its reasoning tokens are wasted because there is no learned material to recombine. This is the rich-get-richer dynamic: models that invested in adversarial training (paying the upfront cost) can cash out that investment by spending inference compute efficiently. Models that skipped training-time hardening get no return from extra thinking because they never built the building blocks.

Math after the picture

The hypothesis formula

First in words:

defense gain equals training defense times a function of how close the attack budget is to the training data

Then the compact form:

defense_gain = base_defense * f(attack_budget_relative_to_training)

Every symbol:

defense_gainhow much extra accuracy the model keeps under attack when reasoning time increases
base_defensethe model's accuracy under attack without test-time reasoning, set entirely by training
attack_budget_relative_to_traininghow similar the attack's strength is to adversarial examples the model trained on
f(...)a function that is high when attack is close to training, low when far from it
A tiny worked example
Model A (untrained on attacks): base defense 10 percent. Attack budget 64 units (far from its training, which saw none). f(64 relative to 0) near zero. Defense gain = 10 times 0.05 = 0.5 percent (almost nothing).
Model B (trained on attacks): base defense 65 percent (was trained on adversarial examples). Attack budget 64 units (close to training which prepared it for similar). f(64 relative to training-on-64) near 0.6. Defense gain = 65 times 0.6 = 39 percent.
Same extra thinking time, but Model B is already prepared to use it. Model A has nothing to recombine.

The formula says that inference compute amplifies what training built, multiplying the base defense, not adding to it—making the returns higher for already-defended models.

What can go wrong

What can go wrong

Model undertrained on adversarial examples. If the training data only brushes against attack concepts without deep coverage, test-time compute cannot stitch them into a reliable defense. The pieces are too shallow.
Attack strays far from training regime. If an attacker finds entirely new ways to fool the model that it never trained on, reasoning cannot help because there is no learned material to recombine. This is why adaptive attacks that target the specific training data can be dangerous.
Reasoning tokens give false confidence. A model with more thinking time might generate longer, more confident-sounding jailbreak-following text if it never learned to refuse. Extra reasoning creates the appearance of defense, not the reality.
Done right. Invest in adversarial training or finetuning first, then reward that investment with test-time compute. They work together.
What a runnable demo should prove

What a runnable demo should prove

Build two small models: one trained only on benign text, one trained on half benign and half adversarial jailbreak attempts. Serve both with an interface that lets a user send a prompt and control reasoning budget (number of thinking tokens). Attack both with the same jailbreak prompt, varying how different the attack is from the training data. Measure success rate: how often does the model follow the jailbreak? Show that reasoning tokens reduce the success rate for the trained-on-attacks model but not the untrained model, because the trained model has learned patterns to recombine. Then perform lightweight adversarial finetuning on the untrained model's vision encoder or text embeddings, and re-run: now extra reasoning should help—because the model now has the necessary learned patterns to work with. This proves that training data determines the ceiling, not reasoning time alone.

jailbreak_success_rate = fraction of prompts where model outputs the attacker-desired action, measured at different reasoning_budgets and attack_budgets

The demo must make it impossible to miss that an untrained model wastes reasoning time, but a trained-on-attacks model profits from it—until adversarial training in the untrained model changes everything.
