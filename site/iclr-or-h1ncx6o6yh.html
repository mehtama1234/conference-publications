Orak: Training & Evaluating LLM Agents on Video Games

Orak is a multi-game benchmark that systematically evaluates and fine-tunes language models to act like intelligent game players by chaining reflection, planning, and action modules.

Paper explainersAll themesDatasets & Benchmarks

Video game agents need to handle messy, real-time decisions: dodge attacks, gather resources, reason through strategy. Most benchmarks are toy grids or text-only. Orak is the first standardized test for language model game agents across 12 real games (Mario, StarCraft, Poker, Minecraft) with modular reasoning strategies and a dataset of expert gameplay to teach general models how to play well.

Zero assumption version

Why existing game benchmarks miss the real problem

Video games are messy. A language model must watch the game state (position of enemies, your health, money left), remember what happened last turn, decide what move makes sense, and execute it—all while time is running out. Existing benchmarks are either toy simulators (fake 2D grids) or measure only raw game score without studying HOW agents reason.

A beginner solution: give a language model raw game images or text descriptions and ask it to win. That fails because the model has no structure for reasoning. It guesses randomly, tries the same failed move twice, forgets key information, and never learns from mistakes. The model needs scaffolding—coached reasoning patterns that break the decision into steps: remember what worked before, plan the next subtask, then execute.

The problem in one sentence. Game benchmarks lack genre diversity, structured reasoning studies, and datasets that teach language models to play well.

The algorithm as a flow

What it actually does

Step 1: Standardize game diversity

Orak covers 12 real games across 6 genres (action, adventure, RPG, simulation, strategy, puzzle), not toy grids.

Step 2: Modular agentic tools

Each game plugs into a standard interface. Agentic modules (reflection, planning, action) are callable tools the LLM chains together.

Step 3: Decompose reasoning

At each turn: LLM reads game state, calls reflection module to critique last action, calls planning to set next subtask, then executes.

Step 4: Collect expert trajectories

Record expert gameplay showing successful reflect-plan-act sequences across all 12 games and agentic modules.

Step 5: Fine-tune on trajectories

Train general LLMs on this dataset to learn when to reflect, plan, and act—turning pretrained models into game agents.

What the paper changes

The one thing Orak changes

Orak does not change the language model itself. It changes what the model sees and how it decides: instead of raw game images, the model receives structured game state; instead of one giant decision, it chains three focused reasoning steps—reflection on what just happened, planning what comes next, then action execution. This turns an unstructured guess into a disciplined sequence.

the object it moves  =  agent reasoning pipeline
The hidden quantity

The hidden quantity: agentic module effectiveness

measured quantity  =  per-module performance contribution

Orak measures something invisible: how much does reflection actually help? Reflection helps because when the model compares what it tried to what the game outcome was, it learns not to repeat the same move twice. Does planning matter more in strategy games than action games? Each agentic module (reflection, planning, action) contributes differently depending on the game genre and model size. This contribution is the paper's core hidden quantity—it cannot be seen in raw game score alone, but Orak's modular evaluation isolates it by running with each module enabled or disabled.

The paper estimates this by running each model configuration with and without each module, comparing scores to see which modules lift performance the most. A small model like Llama-3.2-1B may not benefit from planning (gets confused by too many steps), while a larger one needs it to handle complex strategy.

Why it works

Why structured reasoning chains beat raw guesses

Here is the mechanism: a language model at each game step has incomplete information (it cannot see the future) and must act fast. If it guesses randomly, it wastes actions and forgets what failed. The reflect-plan-act pipeline forces the model to slow down and think step by step: first, look at what just happened and why it failed; second, pick one concrete subtask to try next; third, commit to an action that serves that subtask. This structure prevents the model from thrashing—repeating the same failed move—because reflection forces it to notice failure.

Orak provides expert gameplay examples showing exactly when and how experts use each module. When a model is trained on these trajectories, it internalizes the pattern: if the last action failed (detected by state change), call reflection before planning the next move. For complex games like StarCraft, this discipline is critical. For simpler games, the model may ignore planning and act fast. The fine-tuning dataset teaches each model size and genre what balance works.

Math after the picture

The evaluation formula

First in words:

total score equals base game score plus module contribution bonus minus penalty for wasted moves

Then the compact form:

Score = GameScore + sum(module_effect_i) - alpha * wasted_actions

Every symbol:

Scoretotal performance in this game run
GameScoreraw points from the game (win=100, progression=50, etc.)
module_effect_iperformance boost from agentic module i (reflection, planning, or action)
wasted_actionsmoves that did not advance the subtask
alphapenalty weight for inefficiency
A tiny worked example on Mario
Pretrained Llama-3B, no fine-tuning: GameScore = 30 (made it to level 2), no modules, wasted 20 random jumps = 30 + 0 - 1.0*20 = 10.
Same Llama-3B, fine-tuned on Orak data: calls reflection (saved 8 wasted moves), calls planning (focused on jumping pattern), GameScore = 65 (reached level 5) = 65 + (reflection=+12, planning=+8) - 1.0*4 = 89.
Fine-tuning taught the model to reflect and plan. Without those modules it thrashes; with them it plays deliberately. The gain is not magic—it comes from practicing expert sequences.

The formula shows why structure helps: agentic modules add positive contributions (because they force deliberate reasoning instead of random guessing), while unguided moves subtract value through wasted actions (because time and game resources are finite).

What can go wrong

What can go wrong

Over-reliance on reflection stalls action. If the model keeps reflecting without acting, it runs out of time. Orak fine-tuning must balance reflection with decisive action.
Planning does not match action execution. The model plans a subtask but then executes a move that does not serve it. Expert trajectories in Orak show this failure explicitly so fine-tuning learns coherence.
Genre mismatch: strategy methods applied to action games. Careful planning is essential for StarCraft but wastes time in fast action games because you must react in milliseconds. Orak covers both genres, so the model learns which reasoning strategy fits which game by seeing expert trajectories that show when to plan deeply and when to act fast.
Done right: structured reasoning with adaptive depth. Orak data is collected such that reflection and planning intensity match game demands. The model learns to shallow-think on action and deep-think on strategy.
What a runnable demo should prove

What a runnable demo should prove

Train a small model (Llama-3.2-1B) on raw game score from zero-shot play. Record the loss curve. It will be noisy and flat. Then fine-tune the same model on Orak trajectories for one epoch and re-run the same games. Measure win rate and average game score per genre. Plot the gains side by side: zero-shot vs. Orak fine-tuned. The demo must show that fine-tuning on structured reasoning examples (not raw game replays, but expert reflect-plan-act chains) lifts performance across action, strategy, and RPG genres.

improvement = (fine_tuned_score - zero_shot_score) / zero_shot_score

The irreducible proof: a model that was randomizing becomes one that plans and reflects, proven by comparing game performance before and after learning from expert trajectories.
