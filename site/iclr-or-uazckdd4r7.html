Koopman-Assisted Trajectory Synthesis

Instead of making up one-step transitions, KATS builds entire multi-step action sequences from a mathematical mirror of how real systems evolve, so the robot learns from fake experiences that feel like real ones.

Paper explainersAll themesReinforcement Learning

When teaching a robot from past human expert recordings, engineers often fill in missing data by inventing fake motion sequences. The problem: fake transitions break the rules of physics, or when trying to be physics-aware, they slow down and fail with small mistakes. KATS fixes this by using a mathematical tool (Koopman operators, a way to turn any complex motion into simple linear math) to generate whole multi-step sequences that stay true to the system's rules and don't pile up tiny errors.

Zero assumption version

Fake data breaks the robot's learning

When you want to teach a robot from a human expert's recordings, you have maybe 100 trajectories (paths through states and actions). The robot learns best from more data. So engineers invent fake trajectories to pad the dataset. The problem: these fakes must obey physics (if the arm moves forward, it ends up forward), or the robot learns false lessons.

Making fakes that respect physics is hard. One-step methods (invent the next position, then the next position separately) are fast but violate physics — each guess compounds the error. Trajectory-level methods (plan a whole path at once) respect physics but are slow and fail when the math model is slightly wrong. Neither path wins.

The core problem: Generating fake training data that both respects the system's motion rules AND scales efficiently.

The algorithm as a flow

What it actually does

Step 1: Learn the Koopman mirror

Fit a linear model to how the real system evolves in a lifted coordinate space.

Step 2: Generate trajectories

Use the linear model to unfold complete multi-step sequences in the lifted space.

Step 3: Map back to real space

Convert the lifted sequences back to positions and actions the robot understands.

Step 4: Filter for quality

Check that generated trajectories look plausible and stay close to expert data.

Step 5: Train the policy

Feed mixed real + generated trajectories to the learning algorithm.

What the paper changes

What the paper changes

KATS shifts from generating one step at a time to generating complete trajectories all at once. Most prior work treats each transition (state, action, next-state) independently; KATS builds a whole path as a single unit, preserving the causal chain so errors do not compound.

The hidden quantity

The hidden quantity: Koopman approximation error

measured quantity  =  How far the lifted model drifts from reality

When you turn a system's behavior into a linear rule, you are using an approximation. The true system is curved and complex; the linear model is a simplification. This error (the difference between what the linear model predicts and what actually happens) can grow as you unfold a sequence. KATS measures this error and uses a refined set of correction weights to catch and correct drift, so generated sequences stay faithful to the real system.

The paper estimates this by checking how well the linear model predicts held-out real transitions and by adding a correction term that penalizes sequences that deviate from the training data's typical statistics.

Why it works

Why KATS works: building trajectories in a simpler space

Real systems are complicated. A robot's motion depends on angles, speeds, forces — all tangled together in nonlinear rules. Koopman theory says: there exists a higher-dimensional lifted space where this tangle becomes linear. If you can find that lifted space (fit it to expert data), you can then treat the system as simple linear algebra: the next lifted state is just a table of numbers times the current lifted state, no loops or curves.

KATS uses this insight to generate fake trajectories. Because the lifted model is linear, unfolding a 10-step path is just repeated multiplication by the same rule, and all 10 steps stay consistent with the system's rules. Errors do not compound because the linear model enforces consistency globally across the whole trajectory. The refined correction term further absorbs the gap between the linear approximation and reality, so generated fakes stay true to physics.

Math after the picture

The equation: trajectory in lifted space

First in words:

The next lifted state equals a matrix (K, the generator) times the current lifted state, plus a bias term that corrects for approximation error.

Then the compact form:

z_next = K * z_current + b + epsilon

Every symbol:

z_currentcurrent state lifted to the higher-dimensional space
Kthe generator matrix (like the rules of motion in the lifted space)
ba bias term that absorbs small systematic errors
epsilona small random noise that prevents overfitting to the model
z_nextthe predicted next state in lifted space
A tiny worked example
Suppose lifted state is z = [5.0, 3.0, 2.0] (three numbers representing the system state in lifted space).
Generator K = [[0.9, 0.1, 0.0], [0.0, 0.8, 0.1], [0.1, 0.0, 0.7]] (a 3x3 matrix encoding motion rules).
Bias b = [0.1, 0.05, 0.08] (small constant shifts).
Next step: z_next = K @ z + b.
K @ z = [[0.9*5 + 0.1*3 + 0.0*2], [0.0*5 + 0.8*3 + 0.1*2], [0.1*5 + 0.0*3 + 0.7*2]]
= [[4.8], [2.6], [1.9]]
z_next = [[4.8 + 0.1], [2.6 + 0.05], [1.9 + 0.08]] = [[4.9], [2.65], [1.98]]
One step forward is done. To generate a 10-step trajectory, repeat this 10 times (matrix multiplication preserves consistency).

The generator matrix K is the same for every step, so the system's rules stay consistent — no compounding error, unlike one-step methods.

What can go wrong

What can go wrong

Bad Koopman fit. If the lifted model is fitted poorly (e.g., not enough expert data), the approximation error grows fast and generated trajectories drift away from realistic motion. Fix: collect more expert examples or use a larger lifted space.
Action space mismatch. KATS uses state-equivariant Koopman (not action-dependent), so it assumes actions affect the state in a predictable way across all states. If the system has action constraints (e.g., cannot move backward past a wall), the generator matrix may ignore them. Fix: post-filter generated trajectories to enforce constraints.
Lifted space is too small. If the lifted space has too few dimensions, complex behavior gets squeezed into a linear rule that is too coarse. Generated sequences oversimplify. Fix: increase the lifted-space dimension (at the cost of more computation and data).
Done right. When the Koopman fit is accurate and the lifted space is well-sized, generated trajectories stay faithful to the system's rules, errors stay small, and the robot learns from confident, realistic fakes.
What a runnable demo should prove

What a runnable demo should prove

Build a simple cart-pole system (a pole balanced on a moving cart). Collect 50 expert trajectories where the cart learns to balance the pole. Use KATS to generate 500 fake trajectories. Train two imitation-learning policies: one on original data only (50 examples), one on mixed data (50 real + 500 fake). Measure success rate on a held-out test of 100 new episodes. The demo should show that KATS-augmented training wins by at least 20 percentage points and that the generated trajectories, when plotted, stay within the distribution of expert data (no wild outliers).

gain = success_rate(mixed_data) - success_rate(original_only); also measure max_trajectory_distance = max distance of any fake trajectory point from the nearest expert trajectory point

The moment to see: plot real vs. fake trajectories side-by-side in phase space (angle vs. angular velocity). Fake trajectories should trace paths that look like the real ones, following the same curves, not drifting off into impossible regions.
