Peak-Return Greedy Slicing

Break full trajectories into high-quality subtrajectories so the model learns from short, good sequences instead of long, mediocre ones.

Paper explainersAll themesReinforcement Learning

In offline reinforcement learning, you learn a policy from data collected by other agents and stored in a dataset — no live trial-and-error allowed. A Transformer (a neural network that reads long sequences one element at a time, keeping track of context) is good at reading sequences, but the standard approach trains it on complete trajectories from start to finish. This paper shows that mixing in shorter sequences of just the good parts makes the model learn faster and make better decisions, because the bad stretches confuse the learning signal — removing them leaves only clear cause-and-effect pairs.

Zero assumption version

The full trajectory trap

Offline reinforcement learning means you have a frozen dataset of past episodes and must learn a policy (a decision rule) from it without trying anything new. A dataset contains complete trajectories: sequences of states, actions, and rewards that happened in earlier runs. A Transformer is a neural network that reads long sequences one element at a time, keeping track of context, so it seems natural for trajectory learning.

The naive approach trains a Transformer on complete trajectories end-to-end. But real episodes are messy. A trajectory might look like: good moves, then a bad decision, then recovery, then another mistake. The model trains on all of it as one unit. The problem: the bad stretches muddy the learning. The model sees an action that worked once followed by an action that failed, and it is unclear which one to imitate. The model must average over good and bad, so it learns a blurry policy that hesitates.

In one sentence. Instead of training on all moves in a trajectory, cut the trajectory into shorter chunks and train only on the chunks where the model did well.

The algorithm as a flow

What it actually does

Estimate returns

For each time step, predict how much reward will come after that point.

Score each time step

Higher estimated return means that step was in a good part of the trajectory.

Greedy slicing

Cut the trajectory into segments; keep segments where all steps scored high, drop low-scoring breaks.

Train on subtrajectories

Feed the model only the good segments, so it learns a sharper policy.

Truncate at test time

During deployment, use shorter context windows to match the pattern the model saw in training.

What the paper changes

What the paper changes

The paper changes the input to the Transformer: instead of feeding it one complete trajectory, feed it shorter subtrajectories chosen because they are high-quality. The trajectory itself is unchanged; only the partitioning is new. This is a simple switch in data preparation, but it shifts what the model sees during training.

The hidden quantity

The return distribution: which steps are lucky?

measured quantity  =  Estimated future reward per step

The paper introduces a hidden quantity: for each state-action pair in the dataset, estimate how much total reward will arrive in the rest of that episode. Call this the future return. High future return means that step was in a good part of the episode; low future return means the agent got unlucky later. This is hidden because you do not directly observe it — you have to infer it from the data.

The paper estimates this using MMD (Maximum Mean Discrepancy), a statistical tool that compares the distribution of rewards after each step. Concretely, it checks: when this state-action was visited, what range of rewards came next? If the answer is usually large, the estimate is optimistic. This gives the algorithm a principled way to score each time step without looking forward into the future (which would be unfair).

Why it works

Why chopping trajectories makes learning crisper

Here is the causal chain. A Transformer learns by comparing its own predictions to actual outcomes. When you feed it a complete messy trajectory (good moves, then bad moves, then recovery), the model must figure out which actions to imitate. Each action in the sequence is followed by a reward that tells you if it was good or bad in context. But actions at the end of bad stretches have low rewards attached, and actions at the start of good stretches have high rewards. The model sees both and learns a confused mixture.

By slicing at high-return boundaries, you separate episodes into segments where the agent consistently did well. Now every action in a training segment has a plausible high reward somewhere after it — the model does not see the penalty for bad actions, only the reward for the next good move. This is not cheating; it is cleaning the learning signal. The model trains on segments where the causal story is clear: this action, then this action, then high reward. That clarity speeds up learning, because each action now has a reliable label: the model sees more cause-and-effect pairs and fewer confusing edge cases, so it converges to a sharp policy faster.

At test time, the model should use sequences of the same length (or shorter) as it saw during training. A short memory during deployment means the model relies on recent history rather than full episodes — it matches the training distribution, so its learned behaviors remain reliable.

Math after the picture

The scoring equation

First in words:

penalty equals the importance weight times the squared distance between estimated return and actual cumulative future reward

Then the compact form:

loss = sum_i w_i * (r_i - return_estimate_i)^2

Every symbol:

r_iactual cumulative reward from time step i onward
return_estimate_ipredicted future reward at time step i
w_iweight (1 if kept in subtrajectory, 0 if sliced away)
losstotal error across all kept time steps
A tiny worked example
Time step 1: actual return = 50, estimate = 48, w = 1 (kept) -> penalty = 1 * (50-48)^2 = 4
Time step 2: actual return = 10, estimate = 45, w = 0 (sliced) -> penalty = 0 * (10-45)^2 = 0 (this step is ignored)
Time step 3: actual return = 42, estimate = 40, w = 1 (kept) -> penalty = 1 * (42-40)^2 = 4
Total loss = 4 + 0 + 4 = 8. The sliced step does not contribute to learning, so bad estimates for bad steps do not confuse the model.

The weighting is the key: steps outside high-return zones are weighted to zero, so they do not corrupt the learning signal.

What can go wrong

What can go wrong

Slicing away rare good events. If a good outcome happens only once in an episode and is surrounded by low-scoring steps, greedy slicing might remove it. The algorithm must set the return-estimation threshold carefully, or it will miss valuable lessons.
Biased return estimates. The MMD estimator assumes the distribution of future rewards can be learned from the data. If the dataset is skewed (e.g., mostly bad trajectories with a few outlier good ones), the estimator may be wrong, and the algorithm will slice incorrectly.
Mismatch between training and deployment. If the model trains on short subtrajectories but is deployed with a full-episode context, or vice versa, performance drops because the learned patterns do not match the test distribution.
Done right. Tune the threshold so slicing removes clear junk but preserves edge cases. Validate the return estimator on held-out data. Deploy with the same context length as training, or use adaptive truncation to bridge the gap.
What a runnable demo should prove

What a runnable demo should prove

Build a small offline RL environment: a gridworld or simple control task with a pre-collected dataset of 1000 episodes, some high-reward and some low-reward. Train a Transformer baseline on all complete trajectories. Then train the same model with Peak-Return Greedy Slicing: run the MMD estimator to score each time step, slice trajectories at low-score boundaries, and retrain. At test time, deploy both models with the same context length.

improvement = (sliced_success_rate - baseline_success_rate) / baseline_success_rate * 100 percent

The demo must make it obvious that removing bad stretches from training data gives the model a clearer policy and higher success rate.
