Efficiency & Systems

How do you keep neural networks smart while making them fast and small enough to run anywhere?

← All themes explainedField mapMathematicsAll explainers
What this whole area is about

Neural networks have gotten incredibly smart — they can write, reason, generate images, and translate languages. But they have become huge, often needing millions of dollars in computing power just to run once. The efficiency problem is simple: how do you keep the intelligence but shrink the machine, so it runs on phones, servers, and embedded devices instead of only in massive data centers?

This is hard because the smartness is baked into the size. When you have more weights — the numbers the network uses to process information — you can store and combine more patterns. Taking away weights means throwing away some of that understanding. The math of attention (a mechanism that decides which parts of the input to focus on), gets expensive as documents get longer because each word has to look at every other word. And moving data around — between computers, between memory types, between chips — often costs more than the actual computation.

Researchers attack this from every angle: shrinking the network by removing less-important weights, using simpler math or lower-precision numbers, splitting work across many machines, making attention cheaper, updating only a small part of the network when fine-tuning, predicting the next words faster, speeding up diffusion models, and even taking inspiration from the brain's own efficiency tricks. Each of these is its own cluster of papers.

Why does it matter? Because speed and cost are not just engineering problems — they shape what gets built and who gets to use it. An AI that only runs in a $100M data center gets seen by a few companies. An AI that runs on a phone gets seen by billions of people. Efficiency is the gate between research and reality.

Subtheme

Making models smaller by removing weights, faster by less math

The straightforward idea: not all weights matter equally. A neural network with one million weights might be able to throw away half of them and barely lose any accuracy. These papers figure out which weights are least important, then remove them. Some look at which weights are closest to zero. Others measure how much each weight actually changes the output. Once you remove them, the network is smaller, uses less memory, and runs faster — because there is literally less math to do.

The tricky part is that removing weights is not smooth. If you just cut out the weak ones, you often get big gaps in accuracy. So researchers do this gradually, or they retrain the network a little bit after pruning to let the remaining weights learn to compensate. Another angle is quantization: instead of using full-precision numbers (which take lots of memory), use smaller numbers — fewer bits — that take less space. An 8-bit number is half the size of a 16-bit number, which cuts memory in half. The catch is that smaller numbers cannot hold as much detail, so you have to be clever about which layers get the aggressive cuts.

A third direction combines both: start with a large network, train it, prune it, quantize it, and sometimes add clever tricks like knowledge distillation — having a smaller network learn from a larger one to capture its knowledge without the bulk. The papers in this subtheme measure speed and accuracy against each other, finding the right tradeoffs for different devices and tasks.

Subtheme

Splitting work across many machines

When a network is too big to fit on one computer, you have to split it. One machine might handle the first half of the layers, another the second half — this is called pipeline parallelism. Or each machine gets a chunk of the data and computes in parallel — data parallelism. Or for truly huge models, the weights themselves get divided: each machine holds only part of the network — model parallelism. The challenge is that these machines have to talk to each other constantly, sending the results of their computations forward and backward. That communication — moving data across the network — can be slower than the computation itself.

The hard part is load balancing. If one machine finishes its work but has to wait for another one, that is wasted time. And all the machines have to coordinate their gradients — the updates to the weights that learning requires. If the machines have different capabilities (some are GPUs, others are TPUs, some older hardware), how do you divide the work fairly? Some papers focus on scheduling — deciding which machine does what. Others work on reducing communication: maybe you can compress the data being sent, or send it less frequently, without losing the ability to learn well.

A related problem: what if machines fail or go offline? Or what if you want to add more machines mid-training without starting over? These papers tackle distributed training for real-world conditions where things are messy and unpredictable, not just clean lab setups.

Subtheme

Smarter attention to save memory

Attention is the mechanism that lets a neural network decide which parts of the input to focus on. In a language model, it works like this: for each word in a document, the model looks at every other word and computes a relevance score. Those scores then weight which information gets passed forward. It lets the network connect ideas across long distances, but it is also expensive: if a document has 1,000 words, you are doing 1 million comparisons (1,000 times 1,000). For a 100,000-word document, that is 10 billion comparisons. The memory needed to store all those scores explodes.

Researchers noticed that most of those scores are actually tiny — the model cares about only a small subset of other words for any given position. So one direction is sparse attention: instead of looking at all words, look at only nearby words, or only those with high scores. Another direction is linear approximation — use math tricks to compute an approximate answer without storing all the scores. A third is to reuse computed values: if you have already computed the score between word A and word B earlier in the network, do you have to recompute it? These papers measure how much you can approximate or skip without the model losing its ability to understand.

The tradeoff is accuracy versus speed. Sparse attention loses some information because it does not see all connections. Linear attention gives an approximation that is not perfect but is much faster because it skips the expensive matrix multiplications — it trades a small loss in accuracy for much smaller compute time. Researchers experiment with which parts of the network can afford to be approximate (middle layers might not need full attention) and which need full precision (early layers learning basic patterns). The goal is to find the sweet spot where the model stays smart but memory and compute stay manageable.

Subtheme

Efficient training with fewer weights

Modern language models are pretrained on billions of words, which costs millions of dollars. But then you want to adapt them for your specific task — legal documents, medical records, custom domains. If you retrain all the weights, you need almost as much compute as the original training. What if you could fine-tune the model by updating only a tiny fraction of its weights? These papers tackle that problem. Methods like Low-Rank Adaptation add a small, low-rank matrix (a grid of numbers with special structure) that sits alongside the pretrained weights and gets trained instead of changing the weights directly. It is like putting a thin filter over the network that learns the new task, while the core knowledge stays frozen.

Why does this work? Because the weight updates actually live in a lower-dimensional space. When you train a model, the changes to the weights do not point randomly in all directions — they move along a few important directions that capture the task you are learning. If you can identify and train only those directions, you do far less work. The catch is figuring out which directions matter and how to structure the small trainable part so it can still express everything the model needs to learn.

Another angle is adapter modules — small neural networks bolted onto existing layers that learn the new task, leaving the pretrained weights alone. These papers compare different structures: matrices, adapters, prefix-tuning (adding extra text chunks that get trained), and combinations. They measure how many weights you need to update versus how well the model performs on new tasks. The goal is to make fine-tuning cheap enough that individuals and small companies can adapt large models without needing a supercomputer.

Subtheme

Faster generation by predicting words ahead

Generating text or images is slow because the model has to produce one token — one chunk of text — at a time, and each token requires running through the whole network. If you are generating a 1,000-token response, the network runs 1,000 times. These papers ask: can you predict what comes next before you get there? If you can guess the next few tokens ahead of time, you can cache the computation and then verify it against what the model actually computes, saving work. Or you can try multiple possible next tokens in parallel and pick the best one, which can sometimes shortcut the sequential generation.

One direction is speculative decoding: a small, fast model guesses the next few tokens. The big model then checks whether those guesses are right. If they are, you save the computation of running the big model that many times. If they are wrong, you only spent time on the cheap model's guess. Another angle is dynamic computation: some inputs are easy and need shallow processing, others are hard and need the full depth. Techniques figure out on the fly how much computation each input really needs, skipping layers for easy cases.

A third approach is parallel or tree-based decoding: instead of generating strictly left-to-right, try multiple branches of the generation tree simultaneously and then prune branches that are unlikely. Each of these techniques trades a small overhead in decision-making for large savings in the total number of passes through the network. The papers measure wall-clock time — how long it actually takes to generate an answer — not just model complexity, because overhead that looks cheap mathematically can be slow in real systems.

Subtheme

Fast diffusion models for images and video

Diffusion models generate images and video by starting with noise and gradually cleaning it up, step by step. The problem is that this takes many steps — often 50, 100, or 1,000 refinement steps to get a good image. Each step is a full pass through the model. This is slow: generating a single image can take seconds or minutes. For video, the problem is exponentially worse because you are diffusing every frame, and the model has to be consistent across frames.

The first approach to speed this up is to skip steps without losing quality. Some researchers find that you can go from 50 steps to 10 steps using special sampling schedules that jump over the steps where the image is not changing much. Others found that merging images across time — computing diffusion across a whole video at once instead of frame-by-frame — can be more efficient because it lets the model see dependencies across frames and avoid redundant computations between similar adjacent frames, though it is harder to keep all frames consistent. A third direction optimizes attention specifically for diffusion: the attention mechanism in diffusion models is expensive, and sparse or approximate attention can cut computation by half or more.

Another angle is orthogonal tricks — clever mathematical structures that let you compute more with fewer operations. Some papers add model predictors that skip ahead, or use ensemble methods where smaller models vote on what the refinement should be. The papers measure image quality, video consistency, and generation speed, finding that even aggressive optimizations often retain most of the quality because diffusion has built-in redundancy — much of the refinement after the first few steps is just polishing, not essential to the output.

Subtheme

Neural networks that mimic the brain

The human brain is incredibly efficient: it uses about 20 watts of power while performing tasks that would need megawatts of electricity in a computer. Neurons are the key: they do not fire all the time. A neuron stays quiet unless it gets strong enough input to cross its threshold, at which point it spikes. This is sparse — not every neuron fires every time step. Spiking neural networks try to mimic this behavior. Instead of continuous values flowing through the network, neurons accumulate charge over time and fire only when the voltage crosses a threshold. The spike — a discrete event — then propagates.

Why is this more efficient? Because computation only happens when a neuron fires. If most neurons stay quiet, you do way less math. Additionally, spikes are discrete — you just need to send which neurons fired, not numbers — so communication between chips or parts of the brain can be compressed. The tradeoff is that spiking networks are harder to train and predict. Traditional neural networks use calculus-friendly continuous math. Spikes are discrete events that do not play well with standard learning algorithms. Researchers have developed new training methods for spiking networks, but they are still not as easy to optimize as regular networks.

These papers explore different neuron models (different threshold and charging rules), training algorithms, and applications. They measure power consumption, latency, and accuracy. Spiking networks are particularly interesting for edge devices — phones, embedded cameras, robots — where power is scarce and you want to run inference locally without draining the battery. The brain inspiration is not perfect — biological neurons are far more complex — but even a simplified spike-based model can get significant efficiency gains.

Subtheme

Smart token management for long context

Attention in transformers has a quadratic cost: if a document has 100 tokens, attention is 100 squared, which equals 10,000 operations. At 1 million tokens (a very long book), attention alone is a trillion operations. For long documents, memory explodes because you have to store all those attention scores. But not all tokens matter equally. Early in a document, the model might not need to see every single word — it could focus on key sentences. Later, when making a specific decision, only a few previous tokens matter (the ones already seen). Why load and process every token when you can be smart about which ones to keep?

These papers tackle smart token selection in several ways. One approach is pruning: as you process the document, mark tokens as important or not, and drop the unimportant ones from memory. Another is summarization: condense the already-processed part of the document into a shorter summary, then process new tokens with attention to just the summary plus a recent sliding window. A third is routing: only certain tokens get full attention, others get reduced attention, based on what the model predicts will matter. These techniques can shrink the effective length of the document from a million tokens to maybe 10,000 or 100,000, making processing tractable.

The hard part is deciding which tokens to keep without losing important information. If you drop a token that turns out to be critical, the model's answer gets worse. Researchers use multiple signals: frequency (common words might matter less), position (first and last tokens in a passage matter more), or learned importance scores. Some papers use auxiliary networks that predict which tokens will be important, adding a bit of overhead now to save huge overhead later. The goal is to handle multi-million-token documents in reasonable time without degrading the quality of the model's output.
