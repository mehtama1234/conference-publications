Map as a Prompt: Learning Multi-Modal Spatial-Signal Foundation Models for Cross-scenario Wireless Localization

SigMap teaches a neural network to locate a device by listening to radio signals alongside a 3D map, instead of learning each building from scratch every time.

Paper explainersAll themesAI for Science

Figuring out where a device is using radio signals—called wireless localization—is hard because radio bounces off buildings differently in every city. Existing approaches learn a model for one building and can't handle a new city without retraining from scratch. SigMap solves this by first learning to read radio signals well in a general way, then re-tuning cheaply using a 3D map as guidance, so the same model works across totally different places.

Zero assumption version

Why radio localization fails across new cities

Figuring out where a device is using radio signals is useful for self-driving cars and factory robots. Radio signals bounce off buildings, trees, and metal in ways that depend entirely on the place. A model trained to work in San Francisco—where buildings are close together—fails badly in Phoenix, where they're far apart.

Current methods treat each city as its own puzzle. You give the model thousands of labeled examples: 'at this radio snapshot, the device was 50 meters north of the tower', collected in the target city. But collecting labeled data is expensive. Worse, even with thousands of examples, models get confused in spots they haven't seen.

The block: Neural networks learn city-specific patterns, so moving to a new city means collecting new data and retraining. The two cannot share what they learned.

The algorithm as a flow

What it actually does

Step 1: Pre-training on generic radio

Mask random chunks of radio signals and learn to rebuild them, on any city's data.

Step 2: Detect periodicity

Radio signals repeat in patterns. Measure where these peaks are and hide them from the model so it cannot cheat by predicting obvious repeats. The model must learn why signals repeat—the underlying physics—instead.

Step 3: Build a map graph

Turn the 3D map into a network where nodes are base stations and buildings, edges are distances.

Step 4: Prompt tuning

Create new small learnable prompts from the map graph and feed them alongside radio data. Don't touch the pre-trained weights.

Step 5: Locate the device

Feed radio plus map-prompts to the model. It outputs the device location by combining radio hints with geometric hints.

What the paper changes

The single thing the paper changes

Instead of training a model on radio signals alone and starting from scratch in each city, SigMap first learns to read radio well universally, then adds lightweight learnable prompts derived from the 3D map. The prompts steer the pre-trained model without retraining it.

the object it moves  =  learnable map prompts
The hidden quantity

The hidden quantity: cycle structure in radio signals

measured quantity  =  periodicity pattern (where radio repeats)

Radio signals from a base station don't arrive as random noise. They follow patterns that repeat: if the radio is strong at one spot, it tends to be strong at regularly spaced other spots, because the signal is bouncing off recurring patterns of buildings. This hidden structure is called periodicity.

SigMap measures periodicity by computing cross-correlation—a standard math trick that finds where a signal matches a shifted copy of itself. Once you find the repeats, you know which parts of the radio signal are predictable shortcuts and which are surprising. The paper uses this to mask the repeating parts during pre-training, forcing the model to learn the hard new information instead of memorizing that pattern.

Why it works

Why it works: the two-stage trick

Stage 1 (pre-training) teaches the model the universal rules of radio. We mask random chunks and make the model rebuild them. The cycle-adaptive masking hides periodic peaks first, because if the model can just predict those repeating parts without understanding the underlying rules, it never learns how physics shapes radio. By masking the easy repeats, we force the model to learn the hard physics. After billions of radio examples, the model understands: 'Here's how walls bend signals. Here's how signals bounce off multiple surfaces before reaching the antenna. Here's how distance weakens signal strength.'

Stage 2 (map prompting) teaches location-specific patterns. We take the 3D map—a graph of base station and building positions—and encode it into small learnable items called prompts. A prompt is a list of numbers that steers the model. These prompts live alongside the radio data in the model's input. When the model processes radio plus prompts, the prompts whisper clues about where buildings are: 'The main base station is north. A dense cluster of buildings is southwest.' The frozen pre-trained weights decode the radio signal accurately, and the prompts steer that interpretation toward the right answer. Importantly, we don't retrain the radio-learning weights. We only learn the map prompts—a tiny set of numbers to adjust. This is why it's cheap and fast.

The two core equations

First in words:

Pre-training reconstruction loss: rebuild the unmasked signal from the masked input. Fine-tuning with map prompts: the learnable items from the map are placed next to the radio data and read together by the model's attention mechanism (the part of the neural network that picks which radio parts matter most).

Then the compact form:

L_MAE = E[||X - f_theta_dec(X_masked)||^2]. Input_sequence = [t_cls; T_geo; T_CSI] + E_pos.

Every symbol:

Xthe original radio signal (a sequence of numbers)
X_maskedthe radio signal with periodic peaks removed by the mask
f_theta_decthe decoder part of the model, frozen during fine-tuning
E[·]average over all examples in a batch
t_clsa special 'classification' token (same across all samples)
T_geothe learnable geographic prompt tokens from the map
T_CSIthe radio signal tokens
E_pospositional encodings (tell the model the order of tokens)
||·||^2the squared distance (how far off the reconstruction is)
A tiny worked example
Pre-training: a radio signal has 100 numbers. Mask 20 periodic peaks. The model tries to fill in those 20. If prediction error for masked part is 0.5 per number, loss is 100 × 0.5^2 = 25.0.
Fine-tuning: the radio data is T_CSI = [r1, r2, ..., r100] (100 numbers). The map has 3 base stations, so we create 3 learnable prompts. The input to the neural network is [classification_marker; prompt_1; prompt_2; prompt_3; r1; r2; ...; r100] (104 items total).
The neural network's scanning mechanism (the part that picks which items matter most) sees all 104 items, uses frozen weights to read radio plus map prompts, and outputs a location estimate. Only the 3 map prompts were trained; the radio-reading part was not touched.

The first equation measures how well the model rebuilds masked signal (the pre-training goal). The second equation shows how map and radio are fused: they live in the same sequence, processed together by the model's frozen core.

What can go wrong

What can go wrong

Map is wrong. If the 3D map has misplaced buildings or base stations, the geometric prompts point the model in the wrong direction. Accuracy drops to worse than radio alone.
Radio environment changes. If a new building is constructed or a tower is moved in the target city, the map is stale. The prompts encode outdated building positions.
Pre-training data is biased. If pre-training happens only on flat suburban grids, the model never learns how signals behave in canyon-like urban cores. Geographic prompts help by showing where buildings are, but they cannot teach physics the model has never seen, so accuracy will still be poor in narrow urban canyons because the core radio-understanding is missing.
Done right. Keep the map current (update it when buildings change), pre-train on diverse radio environments, and use prompts only as a steering mechanism, not a substitute for thorough pre-training.
What a runnable demo should prove

What a runnable demo should prove

Implement a simple wireless localization demo: (1) Generate synthetic radio signals from a known 3D map using ray-tracing (a physics simulator that bounces rays off buildings). (2) Pre-train a small transformer to reconstruct masked radio signals. (3) Extract a map graph from the ray-tracing setup and create learnable prompts. (4) Fine-tune on a tiny labeled set in City A (e.g., 100 samples). (5) Test zero-shot on City B using only the map graph, no City B labels. (6) Measure median error distance (meters). Compare: the naive retrain baseline should fail catastrophically on City B; SigMap should stay within a reasonable error range.

zero_shot_error = median distance from predicted location to true location in unseen city B, after zero fine-tuning on city B.

The key moment is test on the new city with zero labels: SigMap's error stays close to training performance, while the naive method's error jumps 2-3x.
