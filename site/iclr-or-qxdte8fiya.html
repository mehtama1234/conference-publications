PERK: Long-Context Reasoning as Parameter-Efficient Test-Time Learning

PERK encodes long messy contexts into a lightweight memory module at test time by learning to adapt the model on the fly, so it can reason better without loading the whole context into the prompt.

Paper explainersAll themesLLMs & Foundation Models

When a language model reads a long document, it struggles to pick out the relevant details from all the noise. PERK solves this by teaching the model to memorize the context in a special lightweight memory module during the question-answering step itself. The trick is a two-loop learning process that trains the model to encode contexts and then use that encoded memory to reason correctly.

Zero assumption version

Why long contexts confuse models

A language model (a machine that generates text one word at a time) can only look at a limited window of context when answering a question. When you give it a long document with lots of background information, it gets lost in the noise and misses the relevant details. The naive approach is to just feed the whole document as text into the prompt, but this bloats the input, wastes memory, and models still fail to find what matters.

The real problem is that models store information in two different places: in their parameters (weights, the actual numbers that make up the model), or in the context window (the text you feed in). Models are actually better at reasoning over knowledge stored in their parameters than over long raw text, but we have no way to teach them to encode a new document into their parameters when a new question arrives.

The core challenge. Models need to convert a messy, long context into a compact, learnable memory encoded in their parameters.

The algorithm as a flow

What it actually does

Inner loop: encode

Run adjustment steps on the memory module to learn the context patterns.

Inner loop: compress

Stop after a few updates so the context is summarized, not memorized verbatim.

Outer loop: teach

Train the model to use that encoded memory to answer the question correctly.

Outer loop: backprop through reasoning

Backpropagate through both loops to improve how the model learns and reasons.

At test time: adapt

When a new question arrives, run just the inner loop on the new context, then answer.

What the paper changes

The one thing that changes

PERK modifies a low-rank adapter (a small add-on layer with far fewer numbers than the full model). Instead of keeping the adapter fixed, the model learns to update the adapter's numbers during test time, using a few adjustment steps (tiny nudges to the numbers). This turns the adapter into a trainable memory module that absorbs the context.

the object it moves  =  low-rank adapter parameters
The hidden quantity

The hidden quantity: gradient flow through both loops

measured quantity  =  meta-gradient (learning signal across two optimization loops)

The paper measures a quantity called the meta-gradient, which is the learning signal that says how to improve the model's ability to encode and reason. It is not the gradient on one task; it is the gradient of a gradient. Specifically, it measures: after the model encodes a context into the adapter (inner loop), how well does the updated adapter help answer the question (outer loop)? The outer loop backpropagates this success signal back through the inner loop's gradient updates to improve the encoding process itself.

The paper estimates this by running a two-loop training procedure: the inner loop computes gradients to encode the context, and the outer loop computes gradients through those inner gradients to train the meta-parameters. They use a trick called truncated gradient unrolling: instead of saving the entire history of gradient computations (which would use prohibitive memory), they save only the last few steps, making the computation tractable.

Why it works

Why encoding contexts into parameters helps reasoning

The core insight is that language models encode knowledge better in their parameters than as raw text in the prompt. When you do a few gradient updates on the adapter using the context, you are teaching the model to compress the context into numbers that the model already knows how to interpret. This is much more efficient than asking the model to parse a long text string.

The two-loop structure solves two problems: (1) The inner loop encodes the context into the adapter by minimizing a prediction loss over the context text. (2) The outer loop ensures the encoded adapter actually helps answer the reasoning question, not just memorize the text. During training, the outer loop backpropagates the reasoning loss back through the inner loop to steer what kinds of encodings are useful. At test time, you run the inner loop once on each new context, then discard the raw text and answer using only the encoded adapter.

Truncated gradient unrolling cuts memory in half by only storing the computational graph for the last few inner steps. This means the meta-gradient is approximate, but it is accurate enough for the outer loop to learn which encodings work.

Math after the picture

The two-loop learning objective

First in words:

Minimize the outer loop loss (reasoning accuracy) over all training problems, where each problem's loss is computed using the adapted model from the inner loop.

Then the compact form:

L_outer = sum_r [ L_reason(f_adapted(theta, K_r), q_r) ] where theta_adapted = theta - alpha * grad_K L_encode(theta, K_r)

Every symbol:

L_reasonthe loss on answering the reasoning question
L_encodethe loss on predicting the context (encoding loss)
f_adaptedthe model with updated adapter parameters
thetathe original model parameters
theta_adaptedthe model parameters after inner loop updates
K_rthe context for reasoning problem r
q_rthe question for problem r
alphathe inner loop learning rate (how much to adjust per update)
grad_Kthe gradient computed over the context
A tiny worked example
Suppose a context talks about three people: Alice (engineer), Bob (farmer), Carol (teacher). The question is: who fixed the bridge?
Inner loop: 3 gradient updates on the adapter using the context text. Each update improves prediction of the next word. After 3 steps, the adapter learns patterns like (Alice, engineer) and (bridge, fixed).
Outer loop: the model uses the updated adapter to answer: Alice. Loss is 0 (correct). Backpropagate this success back through the 3 inner steps to improve the encoding process.
Meta-gradient says: the encoding that picked up (Alice, engineer) and (fixed, bridge) was useful. Steer future inner loops to focus on such relationships.
At test time: run 3 inner loop steps on a new context, then answer without re-reading the text.

The meta-gradient (outer loop backprop through inner loop steps) teaches the model which encodings are useful for reasoning.

What can go wrong

What can go wrong

Inner loop too many steps If you run too many gradient updates in the inner loop, the adapter starts memorizing the context verbatim instead of extracting patterns. The encoding becomes brittle and fails on new questions.
Inner loop too few steps If you run too few updates, the adapter does not absorb enough information from the context. The model still loses signal and answers poorly.
Truncated gradient approximation Saving only the last T steps of the gradient computation introduces error. If T is too small, the outer loop learns from a biased signal and produces bad meta-parameters.
Context shift at test time If the test context uses a different language, style, or structure than training contexts, the inner loop encoding may fail to adapt quickly enough in a few gradient steps.
Done right Tune the number of inner loop steps to match the context complexity, choose T to balance memory and accuracy, and train on diverse reasoning tasks so the meta-parameters work across many situations.
What a runnable demo should prove

What a runnable demo should prove

Build a tiny test-time learning loop: take a pretrained small language model and a long context (say, a Wikipedia paragraph with 500+ words). Run the inner loop for 5-10 adjustment steps on the context to update a small adapter. Then, without re-reading the raw text, ask five questions that require different pieces of information from the context. Measure accuracy on each question.

accuracy_with_memory = (questions_answered_correctly_using_only_adapter) / (total_questions)

The demo proves that a few gradient updates on an adapter can extract enough information from a long context to answer diverse questions accurately, without needing the raw text at answer time.
