Can Recommender Systems Teach Themselves? A Recursive Self-Improving Framework with Fidelity Control

The paper lets a recommender model generate new user-interaction sequences for itself, filters them with a fidelity test, and trains a stronger successor on the enriched dataset so data sparsity becomes progressively less severe.

Paper explainersAll themesOther

Recommendation systems are trained from logged user interactions, but those logs are sparse. Most users touch only a tiny fraction of the catalog, and many potentially informative user-item relationships are never observed. That sparsity makes optimization unstable and pushes the model toward brittle solutions that fit the few observed signals too closely. This paper asks whether the recommender can refine itself without an external teacher by generating candidate user sequences and rejecting ones that violate its fidelity test. The answer is RSIR, a recursive loop in which the current model proposes plausible interaction sequences, a fidelity controller rejects synthetic data that drifts too far from the user's preference structure, and the next model trains on the union of real and accepted synthetic data. The paper's claim is not merely that extra data helps because it adds examples. It is that controlled self-generated data smooths the learning problem because accepted sequences fill sparse user-item regions while the filter limits drift.

Zero assumption version

Why sparse interactions limit recommender learning

A recommender sees only a thin sample of what each user would actually engage with. Most missing entries in the user-item matrix are not true negatives. They are simply unknown. That means the model is trained from a highly incomplete view of user preference. Two models can fit the observed interactions equally well while implying very different behavior on the vast unobserved region.

This creates two problems. First, the optimization surface becomes rugged, meaning small changes in internal settings can move the model between very different local solutions because the data gives weak guidance. Second, generalization suffers: a model that memorizes the observed clicks may not infer stable preferences. Standard augmentation often needs an external simulator or teacher model. This paper instead asks the current recommender to generate the extra supervision itself, but only under strict quality control.

The method in one line. Generate additional interaction sequences from the current recommender, keep only the ones that remain faithful to the user's learned preference structure, and train the next recommender on the expanded dataset.

What the paper changes

What the paper changes

The paper changes the source of supervision. Instead of depending only on fixed logged interactions or on an external teacher, it turns the recommender into a generator of its own additional training data and attaches a filter that keeps the recursion stable.

The hidden quantity

The hidden quantity

measured quantity  =  fidelity to the user's preference region

The key hidden quantity is fidelity: whether a generated sequence remains consistent with the user's approximate preference structure rather than merely looking statistically common. Preference region here means the local set of user-item patterns that the current model treats as plausible for that user. A generated sequence can be high-probability in general and still be wrong for the specific user.

Fidelity control is what prevents self-improvement from turning into self-confirmation. Without it, the model might generate convenient but low-quality synthetic clicks, train on them, and reinforce its own bias. With it, recursion becomes selective. The model is allowed to densify the data only in directions that remain coherent with the user's existing representation.

Why it works

Why recursive self-improvement can help instead of drift

Sparse recommendation data leaves the model underconstrained. Many internal setting settings explain the visible clicks, so training can settle into sharp local solutions that generalize poorly. If the model can generate additional plausible interactions, it in practice supplies extra constraints about what should happen in the unobserved parts of user-item space. That can smooth the optimization problem because the model is no longer fitting only isolated points. It is fitting a denser neighborhood of likely interactions.

The risk is obvious: if the synthetic data is wrong, the model trains on its own mistakes. Fidelity control is the safeguard. The generated sequence is not accepted just because the model produced it. It must also remain compatible with the learned user-specific preference structure. This keeps recursion local. The model is allowed to expand the training set around patterns it already supports, but not to fabricate arbitrary behavior far away from the evidence.

Recursive refinement then becomes cumulative. A successor is trained on a denser, cleaner dataset because the accepted synthetic examples add user-consistent interactions to the sparse log. That successor can generate cleaner candidate sequences for the next round because its training set contains fewer unsupported gaps. The paper interprets this as an implicit penalty effect driven by data generation. The recursion does not change the architecture itself. It changes the effective training data pattern because accepted synthetic interactions add support around plausible user preferences, which guides the model toward broader and steadier preference patterns rather than toward brittle fits to the sparse original log.

Math after the picture

The recursive training objective

First in words:

Each generation trains on real data plus accepted synthetic data. The synthetic part is useful only after fidelity filtering, so its contribution depends on both the generated sequence and whether it passes the quality gate.

Then the compact form:

L_k = L_real(D_real; theta_k) + beta * L_syn(D_syn_passed^(k-1); theta_k)

Every symbol:

L_ktraining loss for generation k
theta_kparameters of the kth recommender model
D_realoriginal observed interaction data
D_syn_passed^(k-1)synthetic sequences generated by the previous model and accepted by the fidelity filter
L_realloss on the real data
L_synloss on accepted synthetic data
betaweight controlling how strongly synthetic data influences training
A tiny worked example
Generation 0 trains on 10,000 real interactions and gets validation loss 0.42.
It generates 4,000 candidate synthetic interactions.
The fidelity filter accepts 1,500 of them.
Generation 1 trains on the 10,000 real interactions plus the 1,500 accepted synthetic ones.
If beta is 0.5, the synthetic portion helps but does not dominate the loss.
When Generation 1 learns a better preference model, it can produce a cleaner accepted set for Generation 2.

The key structural point is that only filtered synthetic data enters the next round, so recursion is controlled rather than automatic.

What can go wrong

What can go wrong

The initial recommender may be too weak. If the first model barely captures user preferences, its generated sequences may be low quality across the board. Then the recursion starts from a poor base and the accepted synthetic data may still be unhelpful.
The fidelity filter can be too loose or too strict. A loose filter lets model errors re-enter training. A strict filter rejects almost all synthetic data and removes the benefit of recursion.
Feedback loops can amplify popularity bias. If the model already over-recommends popular items, self-generated sequences may keep overrepresenting them unless the fidelity criterion is explicitly user-sensitive rather than catalog-wide.
Done right. The method is strongest when the base recommender already captures useful user structure, the filter checks user-specific consistency carefully, and the synthetic loss weight stays moderate enough that real interactions remain the anchor.
What a runnable demo should prove

What a runnable demo should prove

Build a small recommendation benchmark with a deliberately sparse user-item matrix. Train a baseline recommender once, then train RSIR for several generations. At each generation, log how many candidate sequences are produced, how many pass fidelity control, and how validation metrics change.

The demo should also include an ablation with no fidelity filter. That comparison is necessary because the paper's claim is not merely that synthetic data helps by increasing example count. It is that recursion helps only when the synthetic data is filtered for user-consistent quality because unfiltered synthetic clicks can reinforce the model's own errors.

improvement_k = validation_score(theta_k) - validation_score(theta_0)

A convincing demo shows cumulative gains across generations for filtered recursion and instability or much smaller gains when the filter is removed.
