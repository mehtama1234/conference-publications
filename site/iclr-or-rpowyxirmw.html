End-to-End Probabilistic Framework for Learning with Hard Constraints

A neural network can learn to predict ranges of answers and satisfy hard limits at the same time, by building constraint satisfaction into the learning layer itself instead of patching it afterward.

Paper explainersAll themesOther

Most forecasting systems learn to guess values. This paper asks: what if the predictions must obey hard rules (like a pressure never exceeds 100 PSI, or a quantity never goes negative)? The usual fixes bolt constraints on afterward, which breaks the learning — the network never sees the rules while it trains, so it makes bigger mistakes. ProbHardE2E builds constraints into the learning machine itself, using a differentiable layer that projects predictions into the safe zone before training even sees the error. This means the network learns INSIDE the rules from day one, and also reports honest uncertainty for each forecast.

Zero assumption version

Forecasts that ignore the rules they should obey

Real-world forecasts often have hard limits. In chemical plants, temperatures cannot exceed certain bounds. In financial models, quantities cannot go negative. In time-series predictions, flows must satisfy balance equations.

The naive approach: train a neural network to predict the value, then afterward, if the prediction breaks the rule, manually fix it. But this approach has a fatal flaw: during training, the network never sees that rule. It learns to minimize prediction error without ever encountering the constraint, so it makes much bigger mistakes when the rules are tight. The network wasted training on a world that does not actually exist.

Another common idea is soft penalties: add a small cost to the loss function if the prediction violates the rule. But soft penalties do not actually enforce the rule. Why? Because a penalty is just a number subtracted from the score — if the network decides the benefit of guessing outside the boundary outweighs the penalty, it will ignore the penalty. For hard safety limits, a prediction that barely violates the rule is catastrophic, no matter how small the penalty was.

In one sentence. The network must learn inside the constraint boundaries from day one, and its learning process must guarantee every intermediate prediction satisfies the hard limits.

What the paper changes

The one thing the paper changes

Instead of letting the network predict freely and then correcting afterward, the DPPL inserts a differentiable projection layer directly into the learning pipeline. The projection mathematically transforms the network's raw forecast into one that is guaranteed to satisfy the hard constraints, and this transformation is smooth enough that error signals (the nudges telling the network which direction to adjust) can flow backward through it.

The hidden quantity

The constraint satisfaction margin

measured quantity  =  Compliance with hard limits

Compliance is how much of the time the predicted value stays within the hard boundaries (no violation, not even by a hair). Traditional methods measure compliance only on the final test set. But ProbHardE2E measures it at every step during training: it ensures every intermediate prediction the network produces stays within bounds.

The paper uses a compliance error (CE) metric: the count of times a prediction violates the rule. For all methods using ProbHardE2E, this metric is zero. For a network trained with soft penalties or post-processing, compliance error is positive — predictions leak outside the safe zone. This named quantity is the core proof that the method works: hard guarantees, not hopes.

Why it works

Why it works: Projecting before learning

If you guarantee that every prediction the network sees during training is valid, then the network has no choice but to learn a valid prediction strategy. The DPPL does this by taking the network's raw output (mean and uncertainty width) and mathematically transforming it to the nearest point that obeys all the hard constraints. This transformation is smooth (differentiable), so errors can flow backward through it. The network never gets a signal to move into the forbidden zone because all its intermediate outputs were already projected into the safe zone.

DPPL is better than post-processing because it measures error signals from valid predictions only. In post-processing, the network learns freely and then the prediction gets clipped afterward. The error tells the network only whether the clipped result was close to the true answer — but the network never saw the original violated predictions as problems (they were silently fixed), so it does not learn to avoid the boundary. With DPPL, the projection happens before the error is measured, so every error signal the network receives comes from a point inside the constraint boundary. The network learns the boundary indirectly: if it predicts close to the edge, a small input change will keep the prediction in roughly the same spot after projection; if it predicts too close to the boundary, the projection will move its answer more drastically. Over time, the network learns to predict with a buffer to avoid being moved.

For linear constraints (like upper/lower bounds), the projection has a closed-form solution: a matrix multiplication. For nonlinear constraints (like a pressure-volume relationship), the layer solves an optimization problem (using Newton's method) to find the nearest valid point. Both cases are differentiable and fast.

Math after the picture

The projection equation

First in words:

For a linear constraint, find the closest valid prediction by rotating and scaling the original forecast via an oblique projection matrix that accounts for the uncertainty width.

Then the compact form:

projected_mu = mu - Q_inv A^T (A Q_inv A^T)^-1 (A mu - b) ; projected_Sigma = J_T(mu) Sigma J_T(mu)^T

Every symbol:

muthe network's predicted center value
Sigmathe predicted uncertainty width (covariance)
Athe constraint coefficient matrix (linear case)
bthe constraint bound value
Q_invthe inverse of the covariance matrix
projected_muthe adjusted center that satisfies the constraint
projected_Sigmathe adjusted uncertainty after projection
A tiny worked example
Suppose the network predicts: mu = 105, Sigma = 4 (so range is roughly 101-109).
Constraint: the value must be ≤ 100 (A=1, b=100).
The projection solves: move mu down to the nearest valid value while shrinking Sigma.
Projected result: mu = 100, Sigma = 2 (new range is 98-102, just inside the limit).
The error is now computed from (100, 2), not the original (105, 4).
Gradient flows backward: the network learns that its raw output was too high and adjusts.

The projection is smooth, so gradients flow back through it; the network learns the shape of the constraint even though every intermediate prediction already obeys it.

What can go wrong

What can go wrong

Infeasible constraints. If the constraints are impossible to satisfy all at once, the projection has no solution. The method assumes the feasible region is non-empty.
Nonlinear constraints need optimization. For nonlinear constraints, the projection step requires solving an optimization problem (Newton's method). If the problem is ill-conditioned (nearly singular), the solution may be slow or inaccurate.
Tight boundaries leave little room. If the constraint boundary is very tight (the safe zone is narrow), the projection is forced to move predictions drastically. The network then has a harder time learning the shape because the error signals (nudges telling it which direction to adjust) point toward the boundary rather than away from it.
Done right. Use linear constraints when possible. Keep the feasible region large enough that the projection does not dominate the error signals. Test compliance error on validation data to confirm the method is working.

What a runnable demo should prove

Build a simple neural network that forecasts a 1D value over time (e.g., a noisy sine wave). Add a hard constraint: the prediction must stay between -1 and 1. Train using ProbHardE2E and compare against soft penalties. Measure: (1) forecast accuracy on a test set, (2) constraint error (number of times the prediction exceeded the bounds). Plot the predictions over time, with the constraint boundaries shown as red lines, to show visually that ProbHardE2E predictions stay inside the zone.
