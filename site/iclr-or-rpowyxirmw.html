End-to-End Probabilistic Learning with Hard Constraints

A neural network can learn a constrained system end-to-end by pushing predictions back into the allowed zone during training, not after.

Paper explainersAll themesOther

Most forecasting models predict anything they want, then fix the answer afterward if it breaks the rules. ProbHardE2E is different: it teaches the model to learn within the constraints from the start. This lets the model stay honest about uncertainty while respecting the real world's hard boundaries, like physics or operational limits.

Zero assumption version

Forecasting hits a wall at the boundary

Imagine you are predicting the water level in a reservoir tomorrow. Real reservoirs cannot go below zero and cannot exceed capacity. A beginner's neural network learns by trying any guess and seeing how far off it is. When it predicts -5 gallons (impossible), the error signal treats that the same as predicting 1 gallon below true: it is just a number. The network has no pressure to stay inside the box.

Most systems use a workaround: train the network freely, then afterward, clip or project each prediction back into the allowed range. This two-step process has a price. First, the uncertainty estimates (how confident the model is) get distorted—clipping erases information about what the model actually believed. Second, the model never learns to be cautious near the boundary; it learns to predict far outside and gets rescued afterward. The model cannot reason about the boundary as part of its learning.

The core problem. Standard neural networks treat constraints as an afterthought, harming both the predictions and the confidence intervals.

What the paper changes

The one thing that changes

Instead of satisfying constraints after training (via clipping or postprocessing), ProbHardE2E embeds constraint enforcement directly into the network as a special layer. Learning signals flow backward through the projection layer, so the network learns to naturally output feasible predictions.

The hidden quantity

The projection: pushing the guess back

measured quantity  =  Projection distance and direction

When the network guesses outside the box (e.g., predicts -10 for a reservoir level that must be at least 0), the special projection layer computes the nearest feasible point inside the box. This projection is the hidden quantity: it measures how far the raw prediction deviated from the rule and which way to steer it.

The paper estimates this projection by solving an optimization inside the forward pass: find the closest feasible point to the raw guess. Because this optimization is smooth and differentiable (not abrupt or stepwise), learning signals can flow backward through it. The network learns which moves lead to predictions that need little or no projection—in other words, which moves keep it honest.

Why it works

Why learning constraints into the network works

Standard training with post-processing breaks the feedback loop. If the network predicts -50 gallons, the loss function sees the clipped version (0 gallons) and only cares about matching the true answer. It never learns that -50 was a bad direction to go. The clipping hides the mistake.

ProbHardE2E's projection layer keeps the signal alive. When the network predicts outside the box, the projection computes the closest feasible point and the distance to it. That distance becomes part of the training signal. Learning signals flow backward through the projection, telling the network: 'your guess was far from the boundary; you should have known better; steer your weights to stay closer to feasible predictions next time.' Over time, the network learns to be cautious. It stops guessing far outside because the projection feedback makes that costly during training. This means the final model produces predictions that are already feasible, so there is no need for last-minute clipping, and the confidence intervals stay honest—they measure real variation within the box, not artifacts of squashing.

The strictly proper scoring rule (the objective the paper optimizes) adds another layer: it does not assume the data follows a bell curve or any particular shape. This makes the confidence intervals trustworthy, because they are not skewed by a wrong guess about how the data is shaped.

Math after the picture

The projection equation

First in words:

The projected prediction is the guess that is closest to the network's raw output but still inside the feasible region. The paper minimizes this distance while satisfying all the hard constraints.

Then the compact form:

y_proj = argmin_{y in C} ||y - y_raw||^2

Every symbol:

y_projthe projected prediction (what goes into the loss)
y_rawthe raw network output (before projection)
Cthe set of all feasible predictions (bounded by constraints)
||...||^2the squared distance (how far apart two predictions are)
A tiny worked example
Suppose the reservoir must stay between 0 and 100 gallons.
Network predicts raw output of -10 gallons (infeasible).
The closest feasible point is 0 gallons (right at the boundary).
Projection distance computed: squared distance from -10 to 0 is 100 units.
Learning signal flows back: move weights to avoid this direction.
Next forward pass, network learns to predict closer to 0. No prediction forced outside later.

Because the projection is smooth and differentiable, learning signals flow backward and the network learns to make guesses that stay inside the box from the start.

What can go wrong

What can go wrong

Projection is computationally expensive. Solving an optimization at every forward pass (even a small one) costs more than a simple linear operation. For high-dimensional predictions or complex constraint regions, the projection can slow down training and when the model answers new questions.
Sharp constraint corners cause learning issues. If the constraint region has sharp corners (e.g., absolute value bounds on several variables at once), the projection may not be smooth everywhere. Learning signals can become unstable and noisy near corners.
Bad initialization can trap learning. If the network starts by predicting deep outside the feasible region, the projection cost is high everywhere. Learning can stall if the error signal is swamped by the effort to project.
Done right. Initialize the network to predict near the center of the feasible region. Use smooth constraint formulations (rounded corners, soft inequalities) to keep learning signals stable. Accept a modest computational overhead in exchange for honest uncertainty and natural feasibility.

What a runnable demo should prove

Build a toy time-series forecaster (next 10 values of a random walk that bounces off walls at 0 and 100). Train one network with post-processing clipping and a second with ProbHardE2E. Plot the final predictions and their uncertainty intervals. The ProbHardE2E model's uncertainty should be tighter and more honest near the boundaries, because it learned not to wander off the map. The clipped model's uncertainty should be wider and artificial, because clipping masks the network's true confusion.
