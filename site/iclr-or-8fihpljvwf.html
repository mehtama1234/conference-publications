Video-As-Prompt: Unified Semantic Control for Video Generation

To generate videos with custom styles or motions, show the model a reference video of what you want, and let it learn to mimic that example without memorizing per-condition rules.

Paper explainersAll themesGenerative Models & Diffusion

Video generation models today struggle with semantic control — asking them to generate in a specific style, motion, or mood. Existing methods either break (creating visual artifacts), lock you into one type of control, or need custom training for each new style you want. This paper proposes Video-As-Prompt, which flips the problem: instead of teaching the model rigid rules for each style, show it a reference video of the desired style and let it learn to follow that example directly, the way a student learns by watching demonstrations.

Why existing video control breaks

Video generation models produce beautiful videos, but only if you give them exact instructions — a text prompt or a reference frame. When you want finer control — a specific artistic style, a particular camera movement, or a mood — the models usually fail. The naive approach is to have the model learn a direct pixel-by-pixel mapping: show it pairs of (input video, desired output video) and train it to match pixel positions. But this creates artifacts, blurry frames, and visual glitches. The second common approach is to build a separate custom model for each new control type: one for Ghibli animation style, one for Hitchcock zoom effects, one for slow-motion. This works, but it is expensive and does not adapt to new styles the model has never seen before.

The core problem. Models either break when enforcing pixel-by-pixel matching, or require separate training for each new style you want.

The algorithm as a flow

What it actually does

Encode

The reference video and target frames are converted into compressed number-lists by a pre-trained encoder.

Expert interprets example

A small trainable expert model reads the reference video's style and extracts signal by learning which colors, textures, and motions distinguish it.

Communicate

The expert and the main frozen model exchange information at each layer via cross-model connections.

Generate with style

The main model denoises the video, guided by the style hints from the expert, layer by layer.

Decode

The result is converted back to pixels, producing a video in the desired style.

What the paper changes

What the model changes

The paper does not re-train the main video generation model. Instead, it adds a small parallel expert transformer (a neural network that processes patterns across the video) that learns to read style examples and communicate them to the frozen main model. This expert runs alongside the main model at every layer, exchanging hints about the style through attention (where the model looks at different parts of the reference video and weights which ones matter most).

the object it moves  =  trainable expert transformer
The hidden quantity

The style guide: in-context reference representation

measured quantity  =  in-context reference signal

Each time the expert reads a reference video, it extracts a set of numbers (a vector) that capture what is distinctive about that style — the visual patterns, textures, color tone, or motion signature. This extracted signal is not a rule book; it is a direct mathematical representation of the example. The model learns to read this signal and apply it to the target video being generated, the way a musician listening to a jazz solo picks up the vibe and plays along.

The paper measures this through a temporally biased position embedding, which ranks which frames of the reference video are most relevant at each moment of generation. Frames that are temporally close to the current generation step matter more, filtering out irrelevant parts of the reference.

Why it works

Why example-based control works

The core insight is that you do not need pixel-by-pixel correspondence. Instead, you need the model to understand the statistical fingerprint of a style — the pattern of colors, textures, and motion that make it distinctive. When you show a reference video, the expert extracts this fingerprint as a vector of numbers. Then, at every layer of generation, the main model can ask: 'What does the expert see in the reference that I should copy?' The expert answers with its learned signal, and the main model nudges the generation toward that style. This is in-context learning: the model does not memorize rules; it learns to follow demonstrations. The temporary weighting (temporal bias) ensures that early frames of the reference are used for early generation and later frames for later generation, preventing spurious cross-time misalignments.

The guidance mechanism equation

First in words:

The expert generates a signal that tells the main model which style details to follow. At each generation layer, the main model mixes its own learned noise-to-image transformation with guidance hints from the expert signal. The attention weight between them controls the blend.

Then the compact form:

z_t = z_frozen + alpha * Attention(Q_frozen, K_expert, V_expert)

Every symbol:

z_tthe output representation at generation step t
z_frozenwhat the main frozen model would generate on its own
alphahow strongly the expert guidance influences the result
Attention(Q,K,V)how much the main model looks at each part of the expert signal
A tiny worked example
Suppose the expert extracts that the reference video has 'lots of blue tones and smooth motion'. As alpha = 0.7, the main model blends: 0.7 × expert signal (blue+smooth) with 0.3 × what it would generate without guidance. Result leans 70% toward the style, 30% toward its learned defaults.
If alpha = 0.3 (weak guidance), the model mostly ignores the reference and generates in its default style. If alpha = 1.0 (full guidance), it strictly follows the example. Alpha = 0.7 is the sweet spot: strong enough to impose the style, weak enough to stay coherent.
Different layers can have different alpha values, so early layers copy the global style (colors, mood) and later layers add fine details.

Attention lets the main model selectively listen to whichever parts of the reference signal matter right now, preventing the reference from overriding the main model's knowledge.

What can go wrong

What can go wrong

Reference video is too different. If the reference shows a style the model has never encountered (a custom animation technique), the expert cannot extract a clear style signal and the output may be incoherent or miss the intended effect.
Temporal alignment breaks on rapid changes. If the target video has very fast cuts or motion, the temporal bias may misalign, linking the wrong reference frames to the wrong output moments.
Expert becomes a copy machine. If training is not careful, the expert may memorize exact reference frames instead of learning the style, failing on new videos.
Done right. The expert learns to abstract the style pattern (not memorize pixels), and the frozen main model's knowledge prevents catastrophic forgetting.
What a runnable demo should prove

What a runnable demo should prove

Build a video generator that takes three inputs: (1) a target video with generic placeholder frames, (2) a reference video showing the desired style, and (3) a temporal bias weight. Run generation and measure how much the output matches the reference style.

user preference rate = (humans rank output vs. reference on style match) / (total ratings)

The demo must show that a single model produces the desired style for a reference it has never seen before, without breaking into artifacts.
