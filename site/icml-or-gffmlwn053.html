Unifying and Optimizing Data Values for Selection via Sequential Decision-Making

This paper says a data value should not mean “how useful is this example by itself” but “how useful is it at this stage of the selection sequence,” then builds a scalable approximation around that sequential view.

Paper explainersAll themesOther

Data valuation assigns a score to each training example, then data selection keeps the highest-scoring ones. That sounds natural, but it hides a mismatch. The value of one example depends on which examples have already been chosen. A duplicate can be useless after one similar item is already included, while a rare example can become more important after the model has covered easier regions. This paper treats data selection as a sequential decision problem rather than a one-shot ranking problem. In that view, the correct quantity is a stage-dependent value produced by dynamic programming, and many existing methods such as Data Shapley appear as myopic approximations that ignore future interaction effects. The paper then derives when those approximations degrade and proposes a bipartite-graph surrogate that preserves the useful submodular structure while scaling to larger selection problems.

Zero assumption version

Ranking examples one by one ignores how earlier choices change later value

Suppose we want to pick a subset of training data under a budget. A common approach computes one single-number score for each example, sorts the examples, and keeps the top items. That procedure assumes each item's value is independent of context. Real selection is not like that. Two examples can be substitutes, complements, or redundant after some coverage has already been achieved.

This matters because the utility function behind selection is usually submodular, meaning each extra example tends to add less once many related examples are already present. If a valuation method ignores that changing marginal gain, it can pick too many near-duplicates early and spend the budget before covering rare but useful regions. The paper formalizes this issue by treating each selection step as a state-dependent decision.

The conceptual change: A data value is not a timeless property of one example. It is the expected gain from selecting that example given what has already been selected and how many picks remain.

The algorithm as a flow

What it actually does

Formulate selection as a sequential problem

The state is the current selected subset and the remaining budget. An action chooses the next example.

Define optimal values by dynamic programming

The correct value of one candidate is its immediate utility plus how much it improves future selections, because adding one item changes which later picks still have high marginal gain.

Reinterpret existing valuations

Methods such as Data Shapley become linear or myopic approximations that estimate current marginal gain while ignoring some future interaction terms.

Analyze when that approximation breaks

The paper shows that utility curvature under submodularity controls how much quality is lost when one uses stage-independent values.

Build a scalable bipartite surrogate

The surrogate keeps coverage-style structure explicit, which makes greedy selection practical while retaining provable guarantees.

What the paper changes

What the paper changes

The paper changes the meaning of a data value. Instead of treating it as a fixed property attached to one example, it treats value as a compressed description of an optimal sequential policy. That shift then motivates a new scalable approximation based on a bipartite graph between selected examples and the utility elements they cover.

The hidden quantity

The hidden quantity: future opportunity cost

measured quantity  =  What selecting this item now prevents or enables later

When selection is viewed as ranking, the hidden quantity disappears. In reality, every early pick changes which later picks still matter. Selecting a near-duplicate today carries an opportunity cost because it spends budget that could have covered a different region tomorrow. Selecting a bridge example can create future gains because it reduces uncertainty in a region and makes later rare examples more informative.

Dynamic programming captures this future effect explicitly through a value-to-go term. Existing data values often approximate only the immediate marginal gain. That can work when the utility function is close to linear, meaning every new example contributes almost independently. It fails when curvature is strong, because then the value of one example depends heavily on what comes next.

Plain reading. A training example can be good now, bad later, or the reverse. Any static score loses that timing information.
Paper reading. Data values are interpreted as encodings of the optimal sequential selection policy. Approximate methods recover only a truncated version of that policy, which explains both their usefulness and their failure modes.
Why it works

Why the sequential view unifies old methods and improves selection

Dynamic programming writes the quality of a next pick as immediate gain plus future value. That decomposition explains why many existing data valuation methods are useful: they estimate part of the right quantity. A method such as Data Shapley averages marginal contributions across subsets, which captures a fair view of immediate usefulness. But it still collapses different decision stages into one static score. The paper shows that this is a first-order approximation to a richer sequential problem.

The curvature analysis explains when the approximation is acceptable. If utility gains shrink only mildly as the selected set grows, then the future value term changes slowly and a static score can be close to optimal. If gains shrink sharply, then the order of picks matters a lot, because early redundancy causes large downstream loss. In that regime, myopic scores are not just noisy; they are systematically misaligned with the true objective.

The bipartite surrogate then turns the theory into an algorithm. By representing relationships between candidate examples and covered utility elements in a graph, the method preserves the diminishing-return structure that greedy algorithms can exploit. That gives a scalable procedure whose behavior still reflects sequential coverage rather than one-shot ranking.

Math after the picture

The sequential value decomposition

First in words:

The value of selecting one example at a given stage is the current utility gain plus the value of the best future sequence after adding that example.

Then the compact form:

V(S, t) = max_i [ U(S union {i}) - U(S) + V(S union {i}, t - 1) ]

Every symbol:

Scurrent selected set
tremaining number of selections
U(S)utility of the current selected set
icandidate example under consideration
V(S, t)best achievable future utility from state S with budget t
Worked example: duplicates versus coverage
Suppose the budget is 2 and examples A and A' cover almost the same region, while example B covers a different region.
At the start, A and A' each look valuable because either one alone raises utility a lot.
If we pick A first, the immediate gain from A' becomes small because most of its coverage is already present.
The dynamic program therefore prefers B as the second pick when the future value term is included.
A static ranking that scored A and A' independently could place both above B and waste the budget on redundancy.

The formula states the paper's main point: a correct value must depend on the current selected set and the remaining budget, not just on the item identity.

What can go wrong

What can go wrong

The surrogate can misrepresent the real utility. If the bipartite graph does not capture the true coverage or interaction structure of the task, greedy optimization can become faithful to the surrogate while drifting away from the actual downstream objective.
Submodularity assumptions may be too strong. The theory is clean when utility has diminishing returns. Some training pipelines contain threshold effects or optimization instabilities that are not well described by a submodular objective.
Sequential optimality is still approximate. The paper reframes the problem exactly, but the scalable algorithm still uses approximations. Very large or highly coupled tasks may retain order effects that the surrogate only partially captures.
Done right. The method is most persuasive when redundancy and coverage dominate the data budget problem, because those are the settings where static values systematically waste budget.
What a runnable demo should prove

What a runnable demo should prove

Create a toy pool where several examples are near-duplicates and a smaller set covers rare regions. Compare three selectors under a fixed budget: uniform random, a static valuation baseline, and the paper's sequential surrogate. Plot utility after each pick, not just final utility, so the user can see how marginal values change over time. Then repeat on a real fine-tuning subset-selection task. The demo should show that the sequential method avoids repeated picks from already-covered regions because its score updates after every selection.
