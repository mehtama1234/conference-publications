TSPulse: Tiny Time-Series Models with Separated Signal Views

TSPulse learns three separate signal views during pre-training so a tiny model can handle anomalies, retrieval, imputation, and classification without entanglement.

Paper explainersAll themesTime Series & Sequential

Real-world time-series problems need different lenses: one task needs to spot sudden jumps (anomalies), another needs to find similar patterns despite noise (retrieval), a third needs to fill gaps (imputation). Today's pre-trained models mix all signals into one big blob of numbers, making it hard to transfer to new tasks or run on phones. TSPulse is a tiny model (1 million dials/weights to adjust, not 100 million) that learns three separate lists of numbers for every signal: time-domain list for catching sudden changes, frequency list for spotting repeating patterns, and semantic list for understanding task goals. This separation lets a small model outperform huge ones because a huge model wastes capacity storing information it does not need for a given task, while specialized signal lists use every dial for signals that matter.

Zero assumption version

One big bag of numbers fails across tasks

Imagine you have a time-series (a stream of numbers over time, like hourly temperature or stock ticks). Different jobs need different kinds of eyesight: spotting a sudden jump (anomaly detection) is different from finding a similar pattern in storage (retrieval), which is different from guessing missing values (imputation). Today's pre-trained models learn one massive embedding (a list of numbers representing the signal) that tries to capture everything at once.

This entanglement breaks transfer: the model wastes capacity storing details it does not need for the task at hand. A phone or edge device cannot run a 100-million-dial model (because each dial is a number the device must store and compute). A beginner might naively fine-tune a huge model on their small task, burning memory and time, or might train a scratch model per task, losing the benefit of pre-training. Neither path works.

The core idea: Pre-train a tiny model (1M parameters) to learn three separate signal views (temporal for time, spectral for frequency, semantic for meaning) so downstream tasks pick the lenses they need.

The algorithm as a flow

What it actually does

Step 1: Split the signal

Break time-series into small windows (patches), compute their frequency content (FFT), and extract task-relevant cues.

Step 2: Apply hybrid masking

Randomly hide some patches or parts of patches (variable ratios) so the model learns from irregular gaps, not just fixed patterns, because real-world missingness does not follow a fixed template.

Step 3: Encode three views

Transform each view (time, frequency, meaning) separately through lightweight layers into three independent embeddings.

Step 4: Reconstruct and score

Rebuild the original signal from each embedding. Penalize errors differently: time-domain errors matter for anomalies, frequency errors matter for retrieval.

Step 5: Use the embedding that fits your task

After pre-training, pick temporal for fast changes, spectral for patterns, or semantic for handling noise and shifts.

What the paper changes

What the paper changes

Most pre-trained time-series models build one monolithic embedding. TSPulse instead learns three independent embeddings in parallel during pre-training, each tuned to a different view of the data.

The reconstruction error per view

The hidden quantity is the separate error each view accumulates when trying to rebuild the original signal. During pre-training, the model optimizes three losses in parallel: time-domain reconstruction error (capturing fine-grained changes), spectral (frequency-domain) reconstruction error (capturing repeating patterns), and semantic reconstruction error (capturing high-level meaning).

By tracking each loss independently, the model learns to specialize each embedding on the signals it is best at reconstructing. The paper measures this by masking parts of the input randomly (hybrid masking with variable ratios), forcing each view to predict missing values from incomplete information.

The paper computes separate heads (output layers) with separate loss functions: L_time (MSE on time-domain reconstruction), L_fft (MSE on frequency-domain reconstruction), and L_sign (measure of whether frequency predictions match the true direction, up or down). Why it works

Why three separate embeddings beat one tangled blob

A time-series carries multiple kinds of information: sudden jumps (anomalies, captured in rapid time-domain changes), repeating cycles (patterns, captured in frequency peaks), and abstract labels (semantic meaning, invariant to scale or noise). When one embedding tries to capture all three, it must waste capacity on features irrelevant to a given task.

TSPulse forces separation by using three disentangled pathways with three different reconstruction targets. During pre-training, the temporal embedding optimizes for time-domain reconstruction (picking up sudden changes), the spectral embedding optimizes for frequency reconstruction (picking up repeating structure), and the semantic embedding optimizes for invariance to noise, scale, and time shifts (picking up meaning). Each embedding becomes specialized because it is penalized only for failures on its own reconstruction target.

The hybrid masking scheme (random full patches and random partial patches with variable ratios) prevents the model from overfitting to one fixed masking pattern. In the real world, missingness is irregular (gaps of different lengths, different patterns), so pre-training on diverse masking patterns forces the model to generalize beyond the training patterns. When downstream tasks like imputation encounter real gaps, the model already knows how to fill them.

At test time, downstream tasks use the embeddings they need. Anomaly detection weighs temporal and spectral signals (sudden changes and spectral outliers). Retrieval relies on semantic embeddings (they survive distortion because they learned what is semantically important and dropped the noise). Imputation benefits from all three (temporal context, spectral patterns, semantic coherence). Because each embedding is specialized, a tiny model (1M parameters) can outperform enormous generic models (100M+ parameters).

The three reconstruction objectives

First in words:

total_loss = w_time * MSE(time_original, time_reconstructed) + w_freq * MSE(freq_original, freq_reconstructed) + w_sem * CE(semantic_labels, semantic_predictions)

Then the compact form:

L_total = w_time * L_time + w_freq * L_fft + w_sem * L_sign

What can go wrong

What can go wrong

Fixed masking bias. If pre-training always masks the same pattern (e.g. always full patches, never partial), the model overfits to that pattern and fails on irregular gaps. Hybrid masking (random full and partial patches with variable spans) fixes this.
Embeddings re-entangle during fine-tuning. If fine-tuning is done naively on all three embeddings at once, they may re-blend. TSPulse avoids this by using task-specific loss reweighting during pre-training and selective weighted pooling during fine-tuning (a simple module that picks which embeddings matter), so each downstream task emphasizes the embeddings it needs.
One view dominates. If weights (w_time, w_freq, w_sem) are not balanced, one loss term dominates and the others do not specialize. The paper uses careful weighting and shows that all three heads contribute substantially to the final performance.
Done right: use all three views. The paper shows that anomaly detection combines temporal and spectral signals (multi-head triangulation), retrieval uses semantic embeddings, and imputation benefits from all three. Downstream tasks explicitly choose which embedding(s) to use.
What a runnable demo should prove

What a runnable demo should prove

Build a tiny three-embedding model (1M parameters) and pre-train it on a diverse time-series dataset with hybrid masking (random full and partial patches). Then test it on four downstream tasks: (1) anomaly detection on out-of-distribution data (without fine-tuning), (2) retrieval of similar patterns with distortion (scale, noise, time shifts), (3) imputation (filling gaps), (4) multivariate classification. For each task, show that the specialized embedding(s) outperform a single tangled embedding, even though the model is tiny, because each embedding is optimized only for signals its task needs, so it has more capacity per signal type than a huge generic embedding.
