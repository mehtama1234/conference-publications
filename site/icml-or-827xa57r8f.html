Decentralized Instruction Tuning: MERIT

Train different instruction tasks on separate machines, then merge the learned weights once, cutting communication in half and avoiding conflicting gradient signals.

Paper explainersAll themesLLMs & Foundation Models

A large language model learns to follow instructions by being trained on many different tasks at once. But when tasks conflict—one asks the model to be helpful, another asks it to be cautious—the model's weight adjustments tug in opposite directions, wasting effort. MERIT solves this by splitting the task mixture into independent groups along conflict patterns, training each group separately, and merging the results.

Zero assumption version

Instruction tuning at scale hits a wall

When a language model trains on many different instruction tasks together, something goes wrong. Some tasks pull the model's weights one direction, other tasks pull the opposite way. The model ends up doing worse at all of them—a problem called gradient interference. A gradient is a direction: which way to nudge a weight to shrink the error on one task.

The naive approach is to train all tasks at once and let the model figure it out. It cannot. The weights get pulled in opposite directions constantly, so learning slows down and the model ends up confused. Worse, coordinating this training across many machines requires constant back-and-forth communication, which is expensive and slow.

The problem. Train many tasks together and gradients conflict; split training across machines and communication explodes.

The algorithm as a flow

What it actually does

Measure conflict

Scan all task gradients; measure which tasks push against each other most.

Find conflict axes

Use PCA (principal component analysis, a way to find the most important directions) to find the top directions where tasks conflict.

Split by conflict

Partition tasks into groups that do not conflict, aligned to those high-conflict directions.

Train independently

Each group fine-tunes the model on its tasks with zero communication to other groups.

Merge once

Average the trained weights from each group, weighted by how many words each group saw during training.

What the paper changes

What the paper changes

The paper changes how and when weights are updated. Instead of all tasks updating the same weights all the time, MERIT splits the task set, trains each subset independently, and merges the final weights once. The key move is separating tasks that conflict, so each group can learn cleanly.

The hidden quantity

Gradient conflict: the hidden quantity

measured quantity  =  gradient conflict direction

Gradient conflict is a simple idea: when two tasks train the same model, their gradients (the directions to nudge weights) often point in opposite directions. This means the tasks are fighting for control of the same weights.

MERIT estimates this by measuring the dot product between task gradients—how aligned or opposed they are. High-conflict tasks get opposite dots; aligned tasks get positive dots. The paper then uses PCA to find the top dimensions along which conflict is strongest, and splits tasks along those axes.

Why it works

Why independent training then merging works

The core insight is a local quadratic theory: when many tasks are being trained together, they all sit in the same flat valley (a region in weight space where many directions are nearly equally good for all tasks). Within that flat valley, training can be split into independent pieces because the curvature (how steeply the valley slopes) is roughly the same everywhere.

When you split tasks into non-conflicting groups and train each group independently, each group learns a different update to the weights within that shared flat space. When you average those updates—weighted by how many training examples each group saw—you are blending two learning paths through the same flat region. This weighted averaging acts as a form of implicit regularization (gentle steering toward a middle ground), smoothing out task-specific overfits and reducing the total variance in the final weights.

The practical result: each task group trains cleanly without being pulled against by other tasks, so learning is faster and more direct, because each group's weight updates can point in a single coherent direction instead of being yanked by contradictory gradient signals. Merging once at the end, weighted by how many words (tokens are the pieces a language model sees, like words or word fragments) each group trained on, ensures no single task dominates and conflicting updates cancel out fairly, because a group that saw more examples has learned stronger, more reliable patterns.

Math after the picture

The weight-merging formula

First in words:

Final weight equals the sum over all groups of that group's trained weights times its fraction of total training tokens

Then the compact form:

w_final = sum_g (n_g / N_total) * w_g

Every symbol:

w_finalthe merged weight
w_gthe trained weight from group g
n_gtotal tokens seen by group g
N_totalsum of all tokens across all groups
A tiny worked example
Suppose three groups train the same model on different subsets.
Group A: 50 tasks, 500 tokens total. Final weight after training: 2.0.
Group B: 40 tasks, 400 tokens total. Final weight after training: 1.5.
Group C: 46 tasks, 460 tokens total. Final weight after training: 2.2.
Total tokens: 500 + 400 + 460 = 1360.
Group A fraction: 500 / 1360 = 0.368. Contribution: 0.368 * 2.0 = 0.736.
Group B fraction: 400 / 1360 = 0.294. Contribution: 0.294 * 1.5 = 0.441.
Group C fraction: 460 / 1360 = 0.338. Contribution: 0.338 * 2.2 = 0.744.
Final merged weight: 0.736 + 0.441 + 0.744 = 1.92. Groups with more data pull the final result more.

Token-weighted averaging ensures that groups with more training data have more say in the final merged weights, preventing small groups from corrupting the result.

What can go wrong

What can go wrong

Conflict detection is wrong. If the method underestimates which tasks actually conflict, groups may still fight internally. The paper addresses this by using gradient samples and PCA, which captures large-scale conflict patterns but may miss task-specific edge cases.
Merging weights from very different training paths. If groups learn in very different directions (not in the same flat valley), averaging them loses information. The theory assumes a shared flat region; this fails if tasks have very incompatible loss paths.
Unbalanced group sizes. If one group is much larger than others, it dominates the merge because that group's learned weights pull the final average harder. Token-weighted averaging helps suppress small groups, but very imbalanced splits can still lead to weaker performance on minority tasks, because a small group's carefully tuned weights get overridden by the large group's preferences.
Done right. Use task-level gradient sampling to estimate conflict. Align partitions to high-conflict PCA axes. Ensure training is long enough that each group reaches a stable region. Use token counts from the actual training data to weight the merge.
What a runnable demo should prove

What a runnable demo should prove

Take a small mixture of instruction-tuning tasks—say, 20 tasks with conflicting gradients measured beforehand. Train half using standard joint training on all 20, and half using MERIT: split the 20 into two non-conflicting groups of 10, train each independently, and merge. Compare final accuracy on a held-out benchmark set. MERIT should show better accuracy because each group's gradient updates point in a single coherent direction, and lower communication cost (no synchronization between groups during training), because each group runs independently without needing to coordinate updates.

improvement = accuracy_merit - accuracy_joint; communication_cost = (joint_messages) - (merit_messages); should be positive for both

The demo must make impossible to miss: independent training of non-conflicting task groups converges faster because each group's updates reinforce each other rather than cancel, and produces better final weights because merging avoids the averaging-down that happens when conflicting updates compete in a single synchronized model.
