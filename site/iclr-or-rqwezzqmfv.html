MolecularIQ: Symbolic Verification on Molecular Graphs

MolecularIQ is a benchmark that tests whether language models can reason over the actual structure of molecules using only tasks whose answers can be computed exactly from the molecular graph.

Paper explainersAll themesDatasets & Benchmarks & Evaluation

Today's language models claim to understand chemistry, but most benchmarks test memorized facts rather than real reasoning about how atoms connect. MolecularIQ solves this by creating test tasks where the answer is not somewhere in a training document—it must be computed from scratch using the molecular structure, like counting atoms or finding rings.

Zero assumption version

Chemistry benchmarks today leak the answers

Current chemistry benchmarks use real-world molecular data downloaded from public sources or textbooks. But those same sources were used to train the language models being tested. So when a model answers correctly, we cannot tell if it truly understands the molecular structure or simply memorized the answer during training.

A beginner might try to test the model on new molecules from the same source. But the model has already learned patterns from thousands of similar examples, so it guesses correctly without reasoning. It is like asking a student a memorized math answer instead of asking them to derive it.

The fix. Build a benchmark where every answer is computed step-by-step from the molecular graph, so every answer is mathematically verifiable and impossible to have memorized.

The algorithm as a flow

What it actually does

Define three task types

Feature counting (how many atoms?), index-based attribution (which atoms have this property?), and constrained generation (build a molecule with these properties).

Generate diverse molecules

Vary complexity (small to large), task load (single vs. multiple constraints), and representation (different ways to encode the structure).

Compute answers algorithmically

Use RDKit (an exact molecular chemistry library) to derive the correct answer from each molecule's graph structure.

Test models fairly

Run each language model with tailored input formats and extraction methods optimized for that model.

Build a capability fingerprint

Measure success per task type and complexity, revealing which models truly reason about structure.

What the paper changes

What the benchmark changes

Instead of using answers that come from datasets and may appear in training corpora, MolecularIQ uses answers that are computed from the input molecular graph via an algorithmic solver. The ground truth is never looked up—it is generated.

the object it moves  =  ground truth source
The hidden quantity

Structural reasoning fidelity

measured quantity  =  constraint-tracking strength

Constraint-tracking strength is how well a model enforces multiple requirements at once when generating a new molecule. For example, if asked to make a molecule with exactly 5 atoms and at least 2 rings, the model must satisfy both at the same time, not just one or the other.

The paper measures this by examining the success rate on multi-constraint generation tasks (which require 2, 3, or 5 properties to be true simultaneously) and comparing it to single-constraint tasks. If the success rate drops steeply as constraints multiply, the model is not tracking them faithfully.

Plain reading. When a model must satisfy multiple rules at once (like two colors and a size), it either tracks all of them or forgets one partway through. The success rate drops when the number of rules increases.
Paper reading. Multi-constraint generation exposes compositional reasoning: most models score high on single constraints but drop sharply on multi-constraint tasks with 2, 3, or 5 requirements, revealing weak constraint tracking even for top performers.
Why it works

Why symbolic ground truth fixes evaluation

A language model trained on billions of text documents has memorized trillions of facts, including molecular properties. Asking it to answer a question whose answer already exists in its training data is like asking a student on a test if they recognize their own homework—the answer does not prove understanding, only memory.

MolecularIQ breaks this trap by creating tasks where the ground truth never existed in any document. The answer is derived algorithmically from the molecular graph using RDKit, a chemistry software library. The model must actually parse the molecular structure and reason about it, because there is no memorized answer to rely on.

This shift forces the evaluation to measure actual reasoning: the model reads the molecular structure, applies logical operations (count the nitrogen atoms, find atoms with at least 3 bonds, generate structures satisfying constraints), and produces an answer. When the model fails, we know it is a reasoning failure, not a memorization gap.

Math after the picture

Constraint satisfaction scoring

First in words:

success_rate = (number of models' outputs satisfying all k constraints) / (total test cases) for single vs. multi-constraint generation

Then the compact form:

drop_rate = success_single - success_multi-k, k in {2,3,5}

Every symbol:

success_singlefraction of correct answers on single-constraint tasks (0 to 1)
success_multi-kfraction of correct answers on k-constraint tasks (0 to 1)
drop_ratehow much success falls when constraints multiply (reveals compositional weakness)
knumber of simultaneous constraints (2, 3, or 5)
A tiny worked example
Model A on single constraint (make a 5-atom molecule): 80 out of 100 correct. success_single = 0.80.
Model A on two constraints (5 atoms AND 2 rings): 56 out of 100 correct. success_multi-2 = 0.56.
drop_rate = 0.80 - 0.56 = 0.24. The model loses 24 percentage points when asked to track two rules.
Model B on single constraint: 78 correct (0.78). On two constraints: 72 correct (0.72). drop_rate = 0.06.
Model B is much better at compositional reasoning: it only drops 6 points instead of 24.

A steep drop in success reveals that the model forgets constraints as the problem gets richer, a sign of weak structural reasoning.

What can go wrong

What can go wrong

Constraint forgetting on deep molecules. Large molecules have many atoms and bonds. A model may track the first two constraints but forget the third when the molecular graph is complex, because it runs out of reasoning capacity mid-calculation.
Syntax errors in generated SMILES. The model generates a string that looks like molecular notation (SMILES) but is invalid: a bond to a non-existent atom, a ring closure that does not match, or an atom count that violates valency rules. The molecule is uninterpretable.
Quantitative imprecision. The model is asked to count atoms or properties exactly (must return 7, not approximately 7). Off-by-one errors or rounding mistakes cause complete failure on counting tasks.
Done right: model tested on unseen molecules. If the model succeeds on MolecularIQ, we know it genuinely parses molecular structure and reasons through constraints, because every task is algorithmically generated and has never appeared in training.
What a runnable demo should prove

What a runnable demo should prove

A demo should take a small benchmark subset (10-20 molecules with 3 task types: counting, indexing, and constrained generation) and run a language model on it. For each task, measure whether the model's answer matches the RDKit ground truth. Show a per-molecule report: did the model count the atoms correctly? Did it identify all hydrogens? Did it generate a valid molecule satisfying the constraints? Build a simple bar chart showing success rate per task type, and highlight at least one failure case (e.g., model counted 5 atoms but the graph has 7; model forgot the ring constraint and generated an acyclic molecule).

accuracy_per_task = (correct answers on task type) / (total test molecules), breakdown by [counting, indexing, generation]

The demo makes it impossible to miss that reasoning from molecular graph structure is hard, because even large models fail in predictable ways on tasks that were never in their training data—revealing that those failures are genuine reasoning gaps, not memorization gaps.
