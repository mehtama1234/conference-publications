Continuous Chain of Thought Enables Parallel Exploration

Instead of picking one word at a time, a language model can generate soft blends of many words at once, letting it explore multiple reasoning paths in parallel.

Paper explainersAll themesLLMs & Foundation Models

Language models normally think step by step by picking one word from a list and then the next word and so on. This paper asks: what if the model could generate a soft blend of many words at each step instead of just one? That blend gives the model room to track multiple reasoning branches at the same time, like exploring several paths through a maze without committing to one choice until the end.

Zero assumption version

Why picking one word at a time gets stuck

A standard language model picks one word at each step and keeps going forward. If that choice was wrong, it is too late to change it; the path is locked in. A beginner might hope the model could explore multiple branches at once, but the normal word-picking process does not allow that because it forces a single commitment: you pick one discrete word (100% probability to that word, 0% to all others), feed it to the next step, and once it flows through the reasoning layer, that choice is locked in with no way to backtrack. Each step chooses one discrete word from the vocabulary, leaving no room to hold many possibilities in parallel.

Some reasoning problems require the model to track multiple branches simultaneously to avoid dead ends. Finding the minimum sum of a set of numbers is an example: you must consider many different combinations to find the best one. But a model that commits to one path at each step gets stuck exploring only one combination and misses the optimal answer.

In one sentence. Standard models pick one word at each step, so they cannot explore multiple reasoning paths in parallel.

The algorithm as a flow

What it actually does

Output a soft blend

Instead of picking one word, output fractions: 40% word A, 30% word B, 30% word C.

Feed the blend forward

Use that blended representation as input to the next reasoning step.

Each branch evolves

All three paths flow through independently; each gets processed by the reading layer and the next layer.

Sample and average

Sample K top words from each soft blend, average their number-lists, and use that for the next step.

Learn from all paths

Train by showing the model many correct solutions and teaching it to match the average next-word choice.

What the paper changes

What the model changes

Normally the model outputs a single word at each step (100% to one, 0% to all others). This paper changes it to output a soft blend: different fractions spread across many words at once. That blended representation becomes the input to the next step.

the object it moves  =  Output: one word to soft blend
The hidden quantity

Tracking parallelism: how many paths at once

measured quantity  =  Parallelism capacity (max branches per step)

The paper measures a quantity called parallelism: how many different reasoning branches can the model hold in the soft blends at once? A soft blend at step 2 can represent multiple paths from step 1 only if the model has enough embedding dimension (the count of numbers used to represent each word). If the dimension is too small, the soft blends start to crush and mix together, and paths interfere.

The paper proves mathematically that the embedding dimension directly controls the maximum parallelism. More dimensions mean more branches. They show that a single-layer model with sine and cosine embeddings can pack all possible states of a search problem (like exploring all subsets in the subset-sum problem) if the dimension is large enough.

Why it works

Why holding soft blends works

When you blend word A, word B, and word C into one token, that token holds all three. The model's attention layer (the piece that reads earlier words) can extract from all three branches at once. Each branch flows forward independently, like water splitting through channels and then rejoining.

During training, the model learns which soft blend to output by watching many correct solution traces. Instead of teaching it to pick word A with probability 100%, the paper shows it many paths and teaches it to average the next-word choices across all of them. This anchors soft tokens in real solutions.

At inference, the model samples K words (like 5) from the soft blend and averages their numerical representations. This sampling keeps the soft token crisp while holding multiple paths. The averaged representation then feeds to the next step, which can branch again.

The supervision formula

First in words:

Minimize the difference between what the model outputs and the blended distribution of all target traces at each step.

Then the compact form:

Loss = sum over steps t of divergence(output_distribution_t, target_blend_t)

Every symbol:

output_distribution_tThe soft token the model produces at step t (fractions summing to 1)
target_blend_tThe average of target distributions at step t across all correct paths
divergenceA measure of how different two distributions are (like distance between them)
sum over steps tAdd up the error at every reasoning step
Tiny worked example: learning to blend two paths
Suppose at step 2, path A says the next word is apple (100%), and path B says banana (100%).
The target blend at step 2 is: 50% apple, 50% banana.
The model outputs: 60% apple, 40% banana.
Divergence measures how far 60%/40% is from 50%/50%.
Loss = that divergence (plus losses from all other steps).
Training nudges the model toward 50%/50%.

The model learns the right soft blend by watching many successful reasoning paths and averaging their next-word choices.

What can go wrong

What can go wrong

Embedding dimension too small. If the model does not have enough embedding capacity, different branches start to crush and interfere. The soft token becomes gibberish and paths mix together. The model needs dimension to scale with the number of branches.
Sampling too few words from the blend. If you sample only 1 word instead of 5 or more, the soft token collapses back to discrete. You lose the parallelism benefit.
Training on wrong target paths. The supervision depends on having good example solutions to learn from. If all target paths are suboptimal, the model learns to blend garbage.
Done right. With enough embedding dimension, diverse target paths, and K-token sampling, the soft tokens preserve branch separation and solve reasoning problems efficiently.
What a runnable demo should prove

What a runnable demo should prove

Build a small transformer and train it on the subset-sum problem: given a list of numbers (like 3, 7, 2, 5, 9), find the subset that sums to a target value (say, 15). This is a search problem where the model must explore multiple branches. Train one version with discrete (one-word) outputs and one with continuous (soft-blend) outputs. Both should use the same embedding dimension. Measure how many steps each needs and how often they find the right answer.

Success rate = (times model found correct subset sum) / (total test cases)

The soft-blend model should find the answer with far fewer steps and higher accuracy because it holds multiple branches. The discrete model should get stuck on hard cases.
