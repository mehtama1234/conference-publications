Fixing Reasoning Breakdowns by Silencing Wrong-Answer Heads

When a language model is asked to think through more steps than it ever practiced, some of its attention heads derail the thinking—we find them and disable them at test time to restore correct reasoning.

Paper explainersAll themesInterpretability

Large language models are trained to solve problems by thinking step-by-step, like showing your work on a math test. But if you ask them to think through more steps than any problem in their training data ever required, they suddenly fail—even though the basic algorithm is the same. This paper discovers why: certain attention heads (the parts of the model that focus on different parts of the sentence) start amplifying wrong answers and suppressing correct ones. By simply turning those heads off when the model is answering a new question, the model's reasoning fixes itself.

Zero assumption version

The Reasoning Cliff

When we train a language model, we give it problems that require a certain number of thinking steps. A model trained on problems needing 5 steps learns to do that reliably. But when we test it on problems needing 8 steps—the same kind of problem, just requiring more thinking—it suddenly fails.

A beginner might guess: the model forgot how to do the algorithm. But actually the model still knows the algorithm. The real problem is that its attention heads, which normally collaborate to follow the reasoning chain correctly, start fighting each other. Some heads begin amplifying wrong paths through the logic, drowning out the correct path.

The problem in one sentence. The model has internal parts that amplify wrong reasoning when forced to think longer than training ever required.

The algorithm as a flow

What it actually does

Diagnose the error pattern

Run the model on longer problems, find which token positions make mistakes, see what type (wrong arithmetic, wrong entity, wrong logic).

Identify the culprits

Look inside the attention heads; erroneous heads amplify the error paths—they focus on the wrong earlier steps in the chain.

Tag the heads

Mark which heads consistently derail reasoning in the test problem you are about to solve.

Silence when answering

When the model is thinking, mute those heads—their output is set to zero before they can influence the next step.

Correct reasoning emerges

The remaining heads now route the thinking correctly, and the model solves the longer problem accurately.

What the paper changes

The single thing that changes

The paper changes one thing: which attention heads contribute to the model's thinking when it is answering a new question. Every other part of the model stays the same—no retraining, no weights changed, no new code. Just selectively muting the heads that were picked out as amplifying wrong answers.

the object it moves  =  which heads contribute to reasoning
The hidden quantity

The erroneous processing heads—a named quantity

measured quantity  =  Erroneous processing heads (ep heads)

An erroneous processing head (or ep head) is an attention head that, when the model is forced to reason longer than training, starts amplifying wrong reasoning paths instead of correct ones. It is not permanently broken—it worked fine on short reasoning—but it becomes harmful in the longer regime.

The paper measures ep heads by running the model on a test problem that fails due to extended reasoning, then inspecting which attention heads are focusing on wrong earlier steps or wrong entities. If removing just that one head fixes the error, it is marked as erroneous. The paper identifies these heads per task and per model, because different heads go wrong in different ways.

Why it works

Why attention heads derail reasoning and how silencing fixes it

Here is the core reason it works: attention heads are filters that pick which parts of the previous reasoning steps to pay attention to when computing the next step. During training on short reasoning chains (5 steps), every head learns a pattern that is locally useful—it attends to relevant prior steps. But the patterns learned are fragile: they only work reliably for 5 steps.

When the model is suddenly forced to reason for 8 steps, the attention heads run the same pattern over and over. Some heads, by accident of their learned pattern, start picking out the wrong prior steps—ones that point toward incorrect reasoning branches. By the time the model has run those bad heads through 8 iterations, their wrong signal has been magnified: they are so focused on incorrect trajectories that they drown out the heads that still know the right path.

Silencing the erroneous heads is not magic. It is simply removing the amplified noise. The remaining heads still know how to reason—they were never broken. With the noise gone, their signal carries the day, and correct reasoning emerges. The model did not learn new logic; it just stopped being derailed by the parts of itself that were trained only for short chains.

Math after the picture

The correction equation

First in words:

For each position in the reasoning sequence, the model computes attention weights from each head. To apply test-time correction, set the output of erroneous heads to zero before summing all head outputs.

Then the compact form:

h_corrected_t = sum over non-erroneous heads of (attention_head_i(context))

Every symbol:

h_corrected_tthe corrected output at reasoning step t, used to compute the next token
attention_head_i(context)the learned pattern from head i, which picks relevant prior steps
erroneous headsidentified beforehand by analyzing which heads amplify wrong paths
A tiny worked example
Suppose the model has 8 attention heads. On a longer problem, heads 1, 3, 5, 6, 7, 8 still point to correct prior steps. Heads 2 and 4 point to irrelevant or wrong steps.
Before correction: all 8 heads contribute equally. The wrong signal from heads 2 and 4 is loud enough to push the model toward an incorrect next token.
After marking heads 2 and 4 as erroneous: only heads 1, 3, 5, 6, 7, 8 are used. Their 6-head consensus points to the correct prior step, and the model predicts the right token.
No retraining: the heads themselves are not changed. Only their outputs are gated off during inference.

The equation is simply: sum only over heads that were not marked as erroneous. It is a gate applied at test time, not a learned change.

What can go wrong

What can go wrong

Heads are task-specific. An attention head marked as erroneous for one reasoning task may not be erroneous for another. The identification step must be redone per task, or the heads silenced unnecessarily on new problems where they would have helped.
Shallow diagnostics miss the real head. If you incorrectly identify which head is causing the error, you will silence the wrong one. The reasoning stays broken, and you waste the test-time budget.
Over-silencing degrades short reasoning. If you silence heads too aggressively, you lose useful signal even on the short chains where those heads used to work. The fix is precise: identify only heads that amplify errors in the extended regime.
Done right. The paper's approach is careful: heads are identified by analyzing errors on the exact test problem, ensuring that silencing helps that specific problem without harming others.
What a runnable demo should prove

What a runnable demo should prove

Build a small language model (or use a pretrained small model) trained on a reasoning task up to 5 steps. Test it on problems requiring 6, 7, and 8 steps to see the cliff. Then run the model, capture its attention maps at each step, and identify which heads consistently focus on incorrect prior steps when the model makes an error. Finally, rerun inference with those heads silenced (set to zero) and measure whether accuracy recovers.

improvement = accuracy_with_heads_silenced at step 8 minus accuracy_baseline at step 8

The demo makes it impossible to deny: silencing identified heads extends reasoning beyond training length, because the harmful heads were trained only on short chains and generalize poorly—without their noise, the rest of the model reasons correctly.
