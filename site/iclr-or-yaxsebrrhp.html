A Hierarchical Circuit Symbolic Discovery Framework for Efficient Logic Optimization

Learn a short symbolic rule for deciding which circuit regions are not worth expensive logic optimization work.

Paper explainersAll themesAgents & Tool Use

Logic optimization tools inspect huge numbers of small circuit regions while trying to shrink a chip design. Many of those inspections do not help because they trigger costly checks on regions that end with no circuit improvement. This paper learns an explicit symbolic rule that predicts which regions are not worth the expensive optimization pass, so the tool can skip them and spend time where change is more likely to matter.

Zero assumption version

Why chip design tools waste so much time

A logic optimizer repeatedly selects a small part of a circuit and asks whether rewriting it will reduce size or delay. The search space is enormous. Most candidate regions lead to no useful change, yet the tool still spends time evaluating them.

Recent learning-based methods try to predict bad candidates from the circuit graph. They can work, but they are expensive to run inside the optimizer and hard for engineers to inspect. That is a serious problem because a chip tool may call this prediction step millions of times.

In one sentence. HIS learns a compact symbolic rule that says which circuit regions are unlikely to help, so the optimizer can skip them with low overhead because evaluating the rule is much cheaper than running the full optimization heuristic.

What the paper changes

What the paper changes

The paper changes the screening rule used before a costly logic optimization heuristic runs. Instead of a hand-tuned or opaque learned filter, it discovers a hierarchical symbolic rule from data.

the object it moves  =  the pre-screening rule for candidate circuit regions
The hidden quantity

The hidden quantity: expected payoff of a circuit region

measured quantity  =  how likely a region is to justify the expensive rewrite step

The important quantity is not whether a region looks unusual. It is whether spending compute on that region is likely to reduce the circuit. That expected payoff is hidden because the tool only learns it after it tries the rewrite.

HIS tries to estimate this payoff from local structure. The symbolic tree passes simple structural summaries upward through several layers, so the final rule can decide whether the region is likely to be ineffective. That matters because skipping low-payoff regions lowers runtime by removing work that rarely changes the design.

Why it works

Why a symbolic tree can replace a heavy predictor

A symbolic tree is useful here because the screening task is repeated constantly and must stay cheap. Each layer gathers local structural facts, then passes a simpler summary upward. By the time the decision reaches the top of the tree, the rule can say skip or run using a small number of explicit operations.

The reinforcement learning search over symbolic expressions matters because nobody wants to hand-design this rule for every benchmark. Training explores many candidate trees and keeps the ones that lead to better optimization outcomes. The result can beat a heavier graph model on runtime because the final rule is short, direct, and cheap to evaluate inside the chip tool.

Math after the picture

A compact objective for symbolic screening

First in words:

training score = circuit improvement after screening minus a penalty for screening cost

Then the compact form:

Score = Gain_after_screening - alpha * ScreeningCost

Every symbol:

Scorevalue of one learned symbolic rule
Gain_after_screeninghow much circuit quality improves after using the rule
alphaweight on the cost of evaluating the rule
ScreeningCostruntime spent applying the rule before the heuristic
A tiny worked example
Rule A cuts circuit size by 8 units and costs 1 runtime unit to evaluate.
Rule B cuts circuit size by 9 units but costs 5 runtime units to evaluate.
Set alpha to 1. Then Score(A) = 8 - 1 = 7, while Score(B) = 9 - 5 = 4.
Training prefers Rule A because it gives nearly the same circuit benefit while costing much less inside the optimizer.

The exact paper objective is more detailed, but the trade-off is the same: useful pruning must pay back its own screening cost.

What can go wrong

What can go wrong

The rule can oversimplify rare but valuable cases. A short symbolic rule may label an unusual region as unhelpful even when a costly rewrite would improve it. That hurts quality because the optimizer never tries the useful rewrite.
Training can overfit one benchmark family. If most training circuits share the same structural habits, the discovered rule may rely on those habits and transfer poorly to a different circuit family.
A deeper tree can become hard to trust. Interpretability is only real when engineers can still inspect the rule. If the tree grows too large, its decision path may no longer be easier to check than a black-box predictor.
Done right. The rule is most useful when it stays short and still tracks real optimization payoff, because then engineers can inspect it and the tool can apply it with low overhead.
What a runnable demo should prove

What a runnable demo should prove

Build a small circuit optimization loop with a set of local rewrite candidates. For each candidate, record whether running the costly heuristic actually reduces circuit size. Train one symbolic screening rule on this history and compare it with a run that checks every candidate.

Measure total runtime, number of candidates skipped, and final circuit size. Also print the discovered symbolic rule so a human can inspect which structural facts it used.

net_gain = circuit_size_reduction - normalized_runtime_cost

The demo should show that the symbolic rule lowers runtime because it skips candidates that rarely pay off, while keeping most of the circuit improvement that a full search would have found.
