H³GNNs: Harmonizing Heterophily and Homophily in GNNs

A graph neural network learns to handle both similar-to-similar and different-from-different patterns by masking hard-to-predict nodes and balancing structural information with node uniqueness.

Paper explainersAll themesGraph & Geometric Learning

Graphs are networks of connected things: social networks, molecules, recommendation systems. A graph neural network learns what each thing (node) means by looking at its neighbors. The problem: some networks have a pattern called homophily, where similar things connect to similar things (your friends are like you), but other networks have heterophily, where different things connect to each other (diseases spread through diverse populations). Standard graph networks excel at one pattern but fail at the other. H³GNNs solve this by encoding both the structural pattern around each node and the node's own unique features, then focusing training on the hardest cases.

Zero assumption version

The network pattern mismatch

Graph neural networks work by spreading information from neighbors. On networks where similar nodes cluster together (homophily), this works beautifully: a node learns by averaging its neighbors' signals. On networks where different nodes connect to each other (heterophily), the same averaging breaks down: the average of different signals washes out the signal entirely.

A beginner tries: use the same averaging for both. It learns one pattern well but fails catastrophically on the other. Another approach: throw away neighbor information and only look at each node's features alone. This avoids the averaging trap but ignores the graph structure entirely, which wastes the data.

When there is no label data to guide training (self-supervised learning), the problem gets worse: the model cannot use labels to tell it which pattern is happening. It must infer the pattern from the graph alone.

In one sentence. The paper builds a model that detects both patterns at once and learns separate pathways for each.

The algorithm as a flow

What it actually does

Step 1: Encode node identity

Each node gets two separate embeddings: one from its own features, one from its position in the graph structure.

Step 2: Combine with adaptive weights

A learned weighting layer chooses how much to use each embedding for this node, adapting to local graph patterns.

Step 3: Build teacher and student

Teacher network sees the full graph. Student network sees a partially masked graph (some nodes hidden).

Step 4: Focus on hard nodes

Masking strategy chooses nodes the student currently predicts poorly, forcing it to learn.

Step 5: Train via prediction

Student learns to predict teacher's embeddings for all nodes (masked and visible), no labels needed.

What the paper changes

What the paper changes

The paper changes how graph information is encoded. Instead of one fixed averaging rule for all nodes, it creates separate pathways: one pathway focuses on the node's own features (node specificity), another focuses on the surrounding graph structure (structural awareness). A gating mechanism (a learned weighting layer) decides which pathway matters more for each node in its local context.

the object it moves  =  Dual-pathway node encoding
The hidden quantity

Node prediction difficulty

measured quantity  =  Prediction difficulty per node

The hidden quantity is how hard it is for the model to predict a node's correct embedding: nodes where the student network produces embeddings far from the teacher's embeddings are 'hard'; nodes where they match are 'easy'. Difficulty is measured by the distance (Euclidean distance, the straight-line separation in the space of numbers) between what the student predicts and what the teacher produces.

The paper uses this quantity to choose which nodes to mask during training. Hard nodes are masked more often, forcing the model to learn them. Easy nodes are left visible or masked less, avoiding wasted training on already-solved cases.

Why it works

Why it works mechanically

Heterophily and homophily require different information. In homophily, neighbors are similar to the node, so averaging neighbor features gives good information. In heterophily, neighbors are different, so you need the node's own features more. The dual-pathway architecture splits this labor: one pathway specializes in node features, the other in structural patterns. A learned gate (a weighting layer that learns per-node weights) on each node decides which pathway to trust more. For homophilic neighborhoods, the structural pathway dominates. For heterophilic neighborhoods, the node-feature pathway dominates.

Standard graph networks fail because they use fixed averaging: one architecture cannot learn to trust different sources for different contexts. H³GNNs learn context-dependent trust weights.

The masking strategy (hiding nodes randomly, but favoring hard ones) solves the second problem. In self-supervised learning, the model has no labels. Early in training, many nodes are easy to predict by chance, so training on only easy nodes wastes signal. By deliberately masking and forcing the model to predict hard nodes, the model must extract real structure from the graph, not just fit noise.

The teacher network (exponential moving average of the student) prevents the target from drifting too fast. If the student changes abruptly each step, predicting a moving target is impossible. An exponential moving average smooths the target, making the task learnable.

Math after the picture

The prediction loss equation

First in words:

Total loss equals the sum over all nodes of the squared distance between student embedding and teacher embedding, weighted by how hard each node is to predict, plus a small penalty keeping the two networks close.

Then the compact form:

L = sum_i w_i * ||student_i - teacher_i||^2 + tau * ||student_params - teacher_params||^2

Every symbol:

w_iweight for node i: 1 if easy, higher if hard; determined by prediction error
student_ithe student network's embedding for node i
teacher_ithe teacher network's embedding for node i
||...||^2squared Euclidean distance: how far apart the embeddings are
tausmall constant keeping the teacher from drifting too far; usually 0.001 to 0.01
student_paramsweights inside the student network
teacher_paramsweights inside the teacher network
Tiny worked example
Suppose node A has high prediction error (student says 0.9, teacher says 0.1): w_A = 4.0. Node B is easy (both say 0.5): w_B = 1.0.
Node A loss: 4.0 * (0.9 - 0.1)^2 = 4.0 * 0.64 = 2.56. Node B loss: 1.0 * (0.5 - 0.5)^2 = 1.0 * 0 = 0.0.
Same prediction error magnitude (0.4 units) produces loss 2.56 for hard node A but 0.64 for hard node if w were 1.0. Training strongly updates on node A, weakly on node B, focusing effort where it matters.

The weighting allocates learning effort to nodes the model currently struggles with, exactly matching the masking strategy.

What can go wrong

What can go wrong

Masking strategy picks wrong nodes. If the difficulty metric (prediction error) is measured at the wrong time or on the wrong network part, the model might mask easy nodes and leave hard ones visible. This reverses the benefit. The paper mitigates this by using a two-stage masking strategy: one stage picks uniformly at random (exploration), one stage picks high-error nodes (exploitation).
Teacher network drifts too fast or too slow. If the exponential moving average constant tau is too large, the teacher barely changes, and the prediction task becomes trivial. If tau is too small, the teacher jumps around, and the prediction target is unstable. The paper requires careful tuning of tau (the paper suggests 0.001 to 0.01) and monitoring.
Dual pathways converge to the same solution. If the gate weights do not diverge (both pathways learn identical patterns), both pathways become redundant, wasting the dual-pathway design. This happens when initialization is poor or learning rates are mismatched. The paper does not fully address this, relying on standard initialization practices.
Done right. When the masking strategy is adaptive (both random and hard-node-focused), when tau is tuned conservatively, and when dual pathways are initialized with distinct random seeds, the method reliably learns both heterophily and homophily without catastrophic forgetting of either pattern.
What a runnable demo should prove

What a runnable demo should prove

Build two simple graphs: one homophilic (5 clusters of similar nodes, 20 nodes per cluster, edges only within cluster), one heterophilic (a bipartite graph, 50 nodes of type A, 50 nodes of type B, edges only between types). Run the model on both after training without labels. Measure accuracy: what fraction of nodes get embeddings closer to nodes of their true type than to nodes of the other type.

Accuracy = (nodes_correct_cluster / total_nodes) * 100; nodes_correct_cluster = nodes whose k-nearest neighbors in embedding space are mostly from the same true cluster

The demo must show that H³GNNs achieves high accuracy on both homophilic and heterophilic graphs after unsupervised training, while a standard graph network excels at one and fails at the other.
