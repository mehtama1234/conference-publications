ORION: Decoupling and Alignment for Unified Autoregressive Understanding and Generation

ORION keeps one autoregressive model for both image understanding and image generation, but separates low-level image reconstruction pressure from the shared semantic representation and then explicitly aligns them during generation.

Paper explainersAll themesMultimodal

A unified multimodal model should answer questions about an image and also generate images or image tokens from text. In a monolithic autoregressive model, meaning one model that predicts the next item in a sequence for every task, those goals fight each other. Image generation pushes the shared representation toward local pixel reconstruction details, while understanding needs abstract meaning that stays stable across wording, layout, and visual surface changes. ORION keeps the simple one-model design but adds two controls: a dedicated non-linear vision head to carry the structural burden of generation, and a representation consistency loss that preserves the semantic representation while generation is trained.

Zero assumption version

Why one model forgets understanding when it learns generation

Understanding and generation use the same input stream but demand different internal features. For visual question answering, the model needs a semantic representation, meaning a list of numbers that preserves category, relation, and intent. For autoregressive image generation, the model must also preserve local structure needed to predict the next visual token, meaning the next discrete code in an image sequence.

If the same hidden states carry both jobs with no separation, generation training can dominate because predicting the next visual token rewards short-range reconstruction detail. The model then spends capacity on surface regularities and its understanding features drift. That is the semantic-structural conflict described by the paper.

The method in one sentence. ORION routes generation-specific structural pressure through a separate vision head and adds an alignment loss on the shared hidden states, because that extra head absorbs reconstruction detail while the alignment term resists semantic drift in the shared representation.

The algorithm as a flow

What it actually does

Train a shared autoregressive backbone

Use one sequence model for multimodal inputs and outputs so both understanding and generation live in a common training pipeline.

Add a non-linear vision head

Before predicting visual tokens, pass the shared hidden state through a dedicated mapping that can absorb low-level visual reconstruction demands.

Run understanding tasks on the shared state

Question answering, caption interpretation, and related tasks read from the shared hidden representation rather than from the generation head.

Apply representation consistency loss

During generation training, penalize drift between the shared semantic representation and its intended understanding-oriented form so generation updates do not erase meaning.

Train progressively on curated multimodal data

Stage the data and task mix because early understanding-heavy training builds a stable semantic base, and later generation-heavy training can then add visual output skill with less drift in the shared state.

What the paper changes

What the paper changes

The paper changes where structural image detail is represented. Instead of forcing the shared backbone state to simultaneously store semantic meaning and next-token reconstruction detail, ORION offloads much of that structural burden into a separate vision head and explicitly adds a penalty term that keeps the backbone state semantically stable.

The hidden quantity

Semantic stability under generation training

measured quantity  =  semantic stability (how much the shared hidden state keeps the same meaning after generation loss updates it)

The hidden quantity is not the image itself. It is the content of the shared hidden representation after the model has been trained to generate visual tokens. If that representation changes its meaning each time generation training raises local reconstruction quality, understanding performance drops because the answer path reads from the altered shared state.

ORION measures and controls this with representation consistency. The idea is direct: if two training views correspond to the same semantic content, then the shared hidden states should stay close even when one path is optimized for generation. Keeping that closeness matters because the answer head depends on stable meaning features, not on patch-level reconstruction detail.

Why it works

Why decoupling and alignment solve the conflict

Generation and understanding disagree mainly about where to spend representational capacity. Visual generation needs details that are predictive for the next code in the image stream. Understanding needs abstractions that survive across many possible renderings. ORION resolves that conflict by placing a non-linear conversion layer between the backbone and visual token prediction. That layer can learn the mapping from semantic state to generation-ready structure, so the backbone does not need to carry every reconstruction cue directly.

The consistency loss is the second half of the solution. Decoupling alone would still allow generation update signals to drift the backbone in ways that hurt understanding. The alignment penalty counters that drift because it punishes changes to the shared hidden state that are not needed for preserving semantic content. With both pieces present, the backbone stores meaning, the vision head expands meaning into generation structure, and the monolithic autoregressive design remains intact.

Math after the picture

The joint training objective

First in words:

Training combines the standard autoregressive generation loss with a consistency term that keeps the shared hidden representation close to a semantic target representation during generation updates.

Then the compact form:

L_total = L_AR + lambda_cons * L_cons

Every symbol:

L_ARautoregressive next-token prediction loss for multimodal outputs
L_consrepresentation consistency loss on the shared hidden states
lambda_consweight that sets how strongly semantic stability is enforced during training
A tiny worked example
Suppose one batch gives L_AR = 0.90 and L_cons = 0.10.
If lambda_cons = 3, then the total is 0.90 + 3 * 0.10 = 1.20.
A batch with the same generation quality but L_cons = 0.30 would score 1.80, so training prefers updates that preserve the hidden semantic state.
That preference matters because the model is not rewarded only for predicting the next visual code correctly. It is also rewarded for keeping the shared representation usable for understanding.

The added term does not replace generation learning. It restricts how generation is allowed to alter the shared backbone state.

What can go wrong

What can go wrong

The consistency term is too weak. If the semantic penalty is underweighted, generation update signals still reshape the shared hidden state toward local visual prediction detail, and understanding quality drops for the same reason as in the plain monolithic design.
The vision head is too limited. If the non-linear head cannot express the conversion from semantic state to generation-ready structure, the backbone must absorb that burden again and the conflict returns.
The training curriculum is poorly staged. If generation-heavy data dominates before the shared semantic representation is stable, the model can lock into reconstruction shortcuts early and the later alignment term has less corrective influence.
Done right. The method works best when the backbone learns stable multimodal meaning first, the vision head has enough capacity to model generation structure, and the consistency weight is strong enough to resist semantic drift.
What a runnable demo should prove

What a runnable demo should prove

Build a compact multimodal autoregressive model that does two tasks on the same image-text data: answer a question about an image and generate image tokens from text. Train three versions: plain monolithic, monolithic plus vision head, and ORION with both the vision head and the consistency loss. After each generation-training phase, reevaluate image understanding on a held-out question-answer set.

The demo should show the paper's central claim directly: generation quality can rise without a matching collapse in understanding if structural reconstruction pressure is routed through a separate head and the shared semantic representation is held in place.
