OmniSapiens: A Foundation Model for Social Behavior Processing via Heterogeneity-Aware Relative Policy Optimization

Train one social-behavior system across many uneven tasks by reweighting each sample according to how much it should influence the next policy update.

Paper explainersAll themesAgents & Tool Use

Social behavior data is messy. One task may involve video, another text, another dialogue traces, and each task can produce a different training signal strength. If all examples are treated the same, easy or noisy tasks can dominate the update while rarer but useful signals are muted. OmniSapiens tackles that imbalance with a policy-optimization method that estimates how much each sample should matter and then smooths those effects so that training remains stable across diverse behavioral tasks.

Why mixed social-behavior data is hard to train on

A general social-behavior system must learn from very different kinds of evidence. Some tasks ask for predictions from conversation, some from visual cues, and some from richer reasoning traces. Those tasks do not produce equally informative updates. If one batch contains many easy cases from one source and a few critical cases from another, a uniform update can drift toward the loudest signal instead of the most useful one.

That imbalance hurts generality because the system starts to fit the dominant slices of data while weaker or rarer slices remain underlearned. The paper therefore treats heterogeneity as a first-class training problem rather than assuming that one global update rule will balance everything automatically.

The paper's move in one sentence. Estimate how much each sample contributes to the policy update, then rebalance those contributions with centered and smoothed modulation so that training stays stable across heterogeneous behavioral tasks.

The algorithm as a flow

What it actually does

Train on many social-behavior tasks and modalities so that the system must generalize beyond one narrow setting.

Estimate per-sample update contribution

Approximate how strongly each example should influence the next policy step because different samples carry different amounts of useful signal.

Center and smooth those contributions

Rebalance the update with geometrically centered and inertially smoothed modulation so that no single batch swings learning too sharply.

Optimize one shared policy

Apply the adjusted update across tasks so that the model learns a common social-behavior representation.

Test on seen and held-out tasks

Check both in-domain and held-out settings because a good balancing rule should help consistency, not only one benchmark.

What the paper changes

What the paper changes

The paper changes policy optimization for mixed social data from a uniform update into an update that adapts to how informative each sample is.

The hidden quantity

Sample influence balance

measured quantity  =  How much each sample should affect the next policy step

The hidden quantity is sample influence. In a mixed-task batch, some examples should matter more because they carry rare or useful information, while others should matter less because they are redundant or noisy. A training rule that cannot estimate this balance will overreact to whichever slice is most common or most volatile.

The proposed method tries to recover that hidden balance and smooth it over time. That helps because the next policy step is shaped by many unequal signals, and the goal is to keep the useful ones without letting unstable ones dominate.

Why it works

Why this works

The method works because it stops treating all examples as equally informative. When the algorithm estimates each sample's contribution, it can reduce the effect of noisy or overrepresented cases and preserve the effect of underrepresented but useful ones. Centering keeps the average update from drifting too far in one direction, and smoothing prevents abrupt swings from one batch to the next.

This is especially valuable for social-behavior data because the task family is broad. A training rule that ignores heterogeneity can memorize the easiest slices and underperform on held-out tasks. Rebalanced updates help the shared policy learn a more even representation across task types because weaker signals are no longer drowned out by dominant slices.

A compact view of the update rule

First in words:

Start from a relative policy optimization update, then multiply each sample term by a centered and smoothed weight that reflects estimated usefulness.

Then the compact form:

update = sum_i w_i(t) * u_i ; w_i(t) = Smooth(Center(c_i(t)))

Every symbol:

updatethe full policy change at the current training step
u_ithe basic update contribution from sample i before reweighting
w_i(t)the weight assigned to sample i at training step t
c_i(t)the estimated usefulness or contribution score of sample i at step t
Center(.)a centering operation that keeps weights balanced around a shared reference
Smooth(.)a smoothing operation that avoids abrupt weight changes across steps
A tiny worked example
Suppose one batch has three samples with raw contribution estimates c = [2.0, 1.0, 0.5].
Centering around the batch middle gives relative values [0.83, -0.17, -0.67].
Smoothing reduces sudden swings and yields weights w = [0.6, 0.3, 0.1].
If the raw update terms are u = [5, 4, 3], then update = 0.6 * 5 + 0.3 * 4 + 0.1 * 3 = 4.5.
The strongest sample still matters most, but the update no longer lets one data slice dominate unchecked.
That balance helps because heterogeneous tasks contribute uneven signals.

What can go wrong

What can go wrong

Contribution estimates can be noisy. If the method misjudges which samples matter, it can damp useful updates or amplify weak ones because the balancing rule depends on those estimates.
Too much smoothing can slow adaptation. Strong smoothing may protect stability while also delaying response to new useful signals, so balance matters because stability and agility pull in different directions.
Task coverage may still be limited. Ten behavioral tasks provide breadth, but real social behavior is broader, so strong benchmark results do not guarantee universal coverage.
Done right. Estimate sample influence carefully, smooth it enough to avoid instability, and test across held-out tasks so that the balancing rule is judged by generalization rather than by one narrow score.
