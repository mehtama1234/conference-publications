Optimal and Scalable Multi-Agent Path Finding via Optimal Transport

Multi-agent path finding becomes solvable via reformulation as a structured transport problem that collapses to a manageable linear program.

Paper explainersAll themesRobotics & Control

In multi-agent path finding, a set of robots must travel to specific targets on a shared graph without colliding with each other. The traditional approach explodes combinatorially because choosing one robot's path constrains every other robot's options. This paper shows that the problem can be recast as an optimal transport problem — moving probability mass through space-time — and structured in a way that reduces the massive search space to a solvable linear program. For scaling to truly large problems, it then wraps this in a probabilistic framework (Schrödinger bridges) that admits fast iterative solution.

Zero assumption version

Why naive robot scheduling explodes

Imagine sending five robots to five different parking spots on a grid, and each robot must compute a collision-free path. A naive approach: for each robot, list all possible paths to its target, then try every combination of one path per robot and check if they intersect in space or time. The number of combinations grows exponentially — with 10 robots and long horizons, checking every option becomes computationally infeasible.

A beginner's first try: use a general-purpose solver (like mixed-integer programming) to handle the full problem as stated. This works for tiny instances but hits an invisible wall around 10–20 robots, because the solver's search tree balloons combinatorially and it runs out of memory or time. The problem is that every robot's choice influences every other robot's constraints, creating a deeply coupled decision space.

In one sentence. The paper reformulates multi-robot path finding as an optimal transport problem with a special Markovian (step-by-step causal) structure, allowing it to collapse from exponential size to polynomial size.

The algorithm as a flow

What it actually does

1. Represent trajectories as mass

Instead of listing discrete paths, encode all robot motions as probability amounts assigned to complete space-time trajectories.

2. Impose one-at-a-time causality

Enforce that robots only move between adjacent time layers; each layer's robot positions determine the next layer (Markovian structure).

3. Formulate as linear program

The transport problem becomes a LP: minimize travel cost subject to flow-conservation constraints (robots enter and leave each location).

4. Recognize the special structure

The constraints have a property (total unimodularity) that guarantees all LP corner-point solutions are 0 or 1.

5. Recover executable paths

Since 0/1 solutions mean each trajectory is either used or not, the LP's optimal solution directly gives collision-free integral paths.

What the paper changes

What the paper changes

The paper changes the representation of the problem: instead of enumerating discrete robot paths and checking collisions, it represents the collective robot motion as probability mass flowing through space-time layers. This reframing lets the structure (step-by-step causality) collapse exponential combinatorial space into a polynomial-sized linear system.

The hidden quantity

The hidden quantity: totally unimodular constraints

measured quantity  =  Totally unimodular constraints

A constraint matrix is totally unimodular (TU) when every square submatrix has determinant in {−1, 0, 1}. This is a property of the geometric shape of the feasible region (the polyhedron of all valid solutions). When an LP's constraint matrix is TU, every corner point of the feasible polyhedron has integer coordinates, even though the LP solver does not explicitly enforce integrality.

The paper constructs MAPF's transport constraints such that the resulting matrix is TU. This means solving the continuous relaxation (allowing any real-valued flows) automatically yields 0/1 flows, which correspond to executable collision-free robot paths. The paper proves TU via careful encoding of Markovian time-layer constraints and single-occupancy constraints (no two robots at one location).

Why it works

Why this works: the causal chain

The core insight is layering: time is split into discrete steps (t=0, 1, ..., T), and robots can only move between adjacent layers. This step-by-step structure breaks the global combinatorial curse. Instead of one massive choice-space coupling all robots across all time, the problem decomposes into local flow constraints between consecutive time layers.

Once this Markovian (one-step-at-a-time) structure is imposed, the transport constraints gain the TU property. Why does this help? Because TU guarantees that the LP's solution, when found, automatically has all variables in {0, 1}. No separate integer-programming solver needed; the LP solver gives an integral solution for free. The cost-minimizing objective (travel distance) then finds the collision-free paths that are cheapest.

For very large problems (hundreds of robots), even the polynomial LP is slow. The paper adds Schrödinger bridges — a probabilistic wrapper that wraps the LP in a framework allowing entropic regularization. Entropic regularization adds a small randomness penalty, which makes the problem smooth and solvable via the Sinkhorn algorithm instead of a traditional LP solver. Sinkhorn is faster because it iteratively scales rows and columns of a matrix; each scaling is simple arithmetic, not the complex pivoting logic of general LP solvers. The Sinkhorn solution is fractional (robots have partial probability at multiple locations), but the paper then uses this fractional solution as a guide to solve a reduced LP on only the high-probability transitions, recovering an integral solution again. This two-stage approach is faster because the Sinkhorn presolve identifies which transitions likely matter, shrinking the problem for the exact stage.

Math after the picture

The core equation

First in words:

The cost of a transport plan is the sum over all time steps of the cost of moving each robot from one node to an adjacent node, plus a cost for waiting. The constraints enforce that each robot departs its starting location, each target is reached by exactly one robot, and no two robots occupy the same location at the same time.

Then the compact form:

minimize sum_t <Pi_t, C_t> subject to flow conservation at each node and time, each target reached once, no location occupied by > 1 robot, Pi_t integral (0 or 1)

Every symbol:

Pi_tthe transport plan (robot flows) at time t; a matrix with entry Pi_ij,t = flow from node i to node j at time t
C_tthe cost matrix at time t; entry C_ij,t = cost to move a robot from node i to node j
flow conservationat each location and time, inflow minus outflow equals zero (no mass appears or vanishes)
integraleach Pi_ij,t is 0 or 1 (a robot either uses a transition or does not)
TU propertythe constraint matrix is totally unimodular, guaranteeing all LP vertices are integral
Tiny worked example: 2 robots, 2 time steps
Step t=0→1: Robot 1 moves A→B (cost 2), Robot 2 stays C→C (cost 0.1).
Cost sum: 2 + 0.1 = 2.1.
Constraints: Robot 1 leaves A (outflow=1), reaches B (inflow=1); Robot 2 leaves C, reaches C; no location has two robots at once.
LP solver considers all such transports, picks the minimum-cost one (e.g., direct paths), and returns a 0/1 solution due to TU.
If instead we let the LP relax to fractional flows (0.5 at some edges), TU would still force the optimal corner-point solution to be integral, so Simplex finds 0/1 anyway.

The linear program directly encodes multi-agent path finding; total unimodularity of its constraint matrix guarantees that the solution is 0/1 (integral), meaning each edge is either fully used or not, directly encoding executable collision-free paths.

What can go wrong

What can go wrong

Graph must support all motions. If the graph is disconnected (some target is unreachable from some start), the LP will correctly report infeasibility. The paper's Lemma 3.2 assumes a connected graph and finite costs on all edges; violating this will make the LP infeasible.
Time horizon must be long enough. If T is too short, robots cannot reach targets even on a direct path. The paper's approach requires choosing T large enough before solving; if guessed wrong, the LP is infeasible and T must be increased.
Schrödinger bridge uses fractional transports. In the probabilistic variant (for large-scale problems), Sinkhorn solves an entropic regularization yielding fractional flows. The paper then solves a reduced LP to recover integral paths, but this two-stage process may be suboptimal compared to direct LP solving if the hierarchy is loose.
Done right. For problems with well-connected graphs, reasonable time horizons, and moderate scale (up to several hundred robots), the LP approach yields optimal or near-optimal collision-free paths in polynomial time. This is far faster than combinatorial search because the Markovian structure collapses the exponential explosion into manageable constraints.

What a runnable demo should prove

Build a small grid (5 by 5), place 4 robots at random start positions and 4 targets at random goal positions. Implement the MAPF-LP solver (construct the constraint matrix, call a standard LP solver like GLPK or scipy.optimize.linprog), and extract the integral solution as robot trajectories. Animate or visualize the paths: each robot should smoothly move along its path without intersecting any other robot at any time step.

success_rate = (robots reaching targets without collision) / total robots; optimality = total_cost / cost_of_simple_shortest_paths (should be <= 1.2)

The demo must show that the LP solver's output is integral (no fractional solutions in the final path) and that robots never collide, proving that the totally unimodular structure delivers executable collision-free paths automatically.
