SAFER: Open-Set Graph Class-Incremental Learning

Graph models can keep learning new categories while rejecting unknown ones, without storing old data.

Paper explainersAll themesGraph & Geometric Learning

Graphs change over time: social networks add people, recommendation systems introduce new products, knowledge bases grow. A smart model should learn from these new categories while remembering old ones. But a hard problem waits: when an unknown category shows up at test time (someone you have never seen before), existing models confidently misclassify it instead of saying "I do not know this." This paper teaches graph models to stay honest about what they know.

Zero assumption version

The problem: models forget and get cocky

A graph has nodes (people) and edges (friendships). You build a model to classify each person into a job (engineer, teacher, student, etc.). New people show up next month with a new job type. A naive approach would retrain from scratch on all old and new data, but that is wasteful and often impossible. So instead you use continual learning: show the model just the new data with the new job type, update its weights to recognize the new category. But here is the trap: when the model sees someone it has never met (truly unknown), it does not say "I do not know." Instead it picks the closest known job anyway, confidently guessing wrong.

The second trap is representation drift. As you teach the model new categories, its internal learned patterns shift. Old features get warped. When you test on people from the very first month, the model is worse at recognizing them because its internal world changed.

In one sentence. A graph model needs to learn new categories without forgetting old ones, and reject unknowns instead of guessing.

The algorithm as a flow

What it actually does

Before each new task arrives, save a subspace lock

Note which weights matter most for old tasks.

Learn new categories

Train on new task data, moving weights as little as possible.

Measure confidence per task

Compute an energy score. High energy means known task; low energy means unknown.

Keep intra-class compactness

Push examples of the same job category close together in the learned space.

Reject unknowns at test time

If energy score falls below a threshold, output unknown instead of guessing.

What the paper changes

What changes: weight movement and confidence

The paper changes two things. First, it restricts which weights can move when learning new categories. It locks down the weights that are most important to old tasks (using a drift-free fingerprint: a saved record of what mattered before). Second, it uses a new energy score (a single number per prediction) that can separate known from unknown categories.

the object it moves  =  weight movement & energy score
The hidden quantity

The hidden quantity: subspace importance

measured quantity  =  subspace importance

Before learning new data, the model measures which weights are most critical for each old task. This number is the subspace importance: for each weight, how much does it control the old task behavior? A weight with high importance was used a lot; moving it breaks old recognition. A weight with low importance was barely used; it is safe to change.

The paper estimates this by computing a Fisher importance score: it tracks how often each weight's change affects the task loss (error measure). The fingerprint (a saved snapshot) stores these scores so they are available when learning new categories; the model uses this record to know which weights to protect.

Why it works

Why it works: the three locks

The core idea is to stop weights that matter. When you learn a new category, you have to move weights (that is how learning works: nudge numbers to fit new data). But if you move a weight that was doing good work on old categories, you break them. The paper solves this in three steps.

Step one: lock important weights. Use the Fisher importance score to identify which weights were doing heavy lifting on old tasks. When learning new data, add a penalty (a cost) whenever you try to move those weights. High penalty means "do not touch"; low penalty means "you can change this freely." This is not new (similar to elastic weight consolidation from 2016), but the paper refines it to work with graphs and open-set rejection.

Step two: use subspace projection. Instead of just adding a penalty, project the weight updates into a safe subspace (a lower-dimensional space where the important weights are stuck). Moving a weight now happens only along directions that do not touch the important ones; the model can still learn, but it is constrained.

Step three: reject unknowns. Define an energy score based on how "close" the prediction is to the learned categories. If an unknown person arrives and does not fit neatly into any learned category, the energy score is low. The model outputs "unknown" instead of guessing.

Math after the picture

The penalty equation

First in words:

loss = task_loss + lambda times Fisher_i times (weight_i minus fingerprint_i) squared

Then the compact form:

L = L_task + lambda * sum_i F_i * (W_i - W_fingerprint_i)^2

Every symbol:

Ltotal loss (what the model tries to minimize)
L_taskerror from predicting the new data wrong
lambdahow hard to enforce the lock (higher = stiffer)
F_iFisher importance score for weight i (1-4 scale, 4=critical)
W_icurrent value of weight i (changes during training)
W_fingerprint_isaved value of weight i from the old task
A tiny worked example
Suppose weight w1 has Fisher importance F_1 = 4.0 (very important). It was w1 = 0.5 before, now it is 0.6. Change = 0.6 - 0.5 = 0.1. Penalty for w1 = 4.0 * (0.1)^2 = 0.04.
Weight w2 has Fisher importance F_2 = 0.5 (not important). Same change: 0.1. Penalty for w2 = 0.5 * (0.1)^2 = 0.005.
Both weights moved the same distance, but w1 is penalized 8 times harder because it matters more. So during learning, the algorithm prefers to leave w1 alone and change w2 instead.

This penalty grows with Fisher importance and squared weight change, so important weights that move a lot get a huge cost, forcing the learning algorithm to leave them nearly frozen.

What can go wrong

What can go wrong

Fisher importance is wrong. If the Fisher scores are computed on a tiny, unrepresentative batch of old data, the wrong weights get locked. The model then learns new categories badly because it locked a weight it did not need to.
Energy threshold tuning. The decision rule is: if energy < threshold, output unknown. But threshold is a human choice. Set it too low and you accept noisy unknowns; set it too high and you reject valid new categories.
Graph topology changes. If the graph structure itself changes drastically (nodes disappear, connection patterns flip), the learned subspace may no longer capture importance correctly. The model assumes edges stay roughly stable.
Done right. Compute Fisher on a held-out validation set from old tasks. Use a principled threshold (e.g. from a held-out unknown validation set). Retrain fingerprints every few tasks to adapt to drift.
What a runnable demo should prove

What a runnable demo should prove

Build a small social graph where nodes represent people and edges represent friendships, with labels for job types. Split it into three phases: old jobs (engineer, teacher, doctor), new jobs (artist, chef), and unknown jobs (made up, withheld). Task 1: train on old jobs only. Task 2: continually learn new jobs by showing the model examples of the new categories. Task 3: test on all three groups. Old job accuracy should remain high because subspace protection keeps old weights frozen. New job accuracy should rise because the model learned them. Unknown job samples should be rejected (marked as unknown) because their energy scores fall below the threshold. Measure three metrics: old accuracy, new accuracy, and unknown rejection rate (AUROC).

forgetting = old_accuracy_before_new_task - old_accuracy_after_new_task

If the demo works, forgetting should be near zero, new accuracy should rise, and the unknown rejection rate should be high (unknowns flagged as unknown, not misclassified as known).
