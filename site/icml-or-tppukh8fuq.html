Flowers: A Warp Drive for Neural PDE Solvers

To predict evolving physical fields, Flower replaces convolutions, Fourier mixing, and attention with repeated learned displacements plus resampling at the displaced coordinates.

Paper explainersAll themesOther

This paper studies operator learning for partial differential equations: given the current state of a field, predict the next state or the full solution map. Existing neural operators usually get long-range interaction from Fourier layers, attention (a learned way to choose which positions should exchange information), or wide convolution layers (spatial filters that mix nearby grid points). Those designs can be expensive, and they often bake in one specific way to move information across space. Flower takes a narrower position. Each head predicts where to read from, samples one source coordinate per location, and repeats that step across scales. The result is a model whose nonlocal behavior comes from explicit movement of coordinates rather than from dense spatial mixing.

Zero assumption version

Why PDE operators are hard to learn

A partial differential equation describes how a field changes across space and time. The next value at one location can depend on events far away, because waves travel, material flows carry mass, and boundaries reflect energy. A learning system therefore needs local detail and long-range communication at the same time.

Many current neural operators get that communication by mixing every location with many others. Fourier layers mix through global frequency coefficients. Attention compares many pairs of positions. Convolutions spread information by stacking local spatial filters again and again. These methods work, but they pay for nonlocal interaction by doing broad spatial aggregation or by committing to one mixing basis everywhere.

The paper asks whether long-range interaction can come from a simpler primitive: move each location to a learned source coordinate, read the feature value there, and combine several such reads. That would keep the cost close to linear in the number of grid points, because each head reads one source point instead of blending a large neighborhood.

The paper in one sentence. Instead of mixing many spatial positions directly, Flower learns where each position should read from, then builds global interaction by stacking those learned reads across heads and scales.

The algorithm as a flow

What it actually does

Encode the field locally

At each grid point, mix the channel values with a pointwise layer, which means a small learned rule acts independently at each location.

Predict one displacement per head

Each head outputs an offset field that tells every target point which source coordinate to read from.

Warp the features

Use interpolation to sample the mixed features at those source coordinates, so each target point imports information from a learned remote location.

Combine heads in a residual block

Merge the warped outputs with the block input, because keeping the original signal stabilizes training and lets each block make a controlled update.

Stack blocks at multiple scales

Run the same idea on coarse and fine grids, because large structures and sharp local changes usually live at different spatial scales.

What the paper changes

What the paper changes

The paper replaces general spatial mixing layers with learned displacement-and-sample operations. A location no longer receives a weighted blend from many neighbors by default. Instead, each head chooses one source coordinate and reads from it directly.

The hidden quantity

The hidden quantity: source coordinates

measured quantity  =  where each location should read from

The model's central hidden choice is the source coordinate attached to each target location and each head. That coordinate is not given by the grid. It is predicted from the local features, which means the model decides which remote information matters for the current state.

This matters because many PDEs move information along structured paths. In advection, mass follows a flow direction. In wave motion, useful information often lies on fronts or reflected paths. If the model can jump directly to the relevant source point, it does not need to approximate that transport by repeated local averaging.

Why it works

Why learned warps are enough

The method works because a warp does two jobs at once. First, it chooses the dependency pattern: which source location influences the target. Second, it moves that information without averaging over a broad region, so sharp structures are less likely to be washed out.

Pointwise displacement prediction is also a strong restriction. A head cannot inspect a full neighborhood before deciding where to look. It can only use the features already present at that location. This keeps the block cheap, because displacement prediction does not require spatial aggregation. The nonlocal step enters only when the model samples the source coordinate.

One warp is limited, because each head reads one place. The paper therefore stacks many heads and many residual blocks. Composing several simple transports creates long chains of dependency, which means the model can build detailed global behavior from repeated single-source reads.

The multiscale scaffold matters because transport distances vary. Coarse blocks can move information across large regions in a few steps, while fine blocks preserve local detail. The full model combines both, so it can represent broad flow structure and local corrections in the same forward pass.

The core update

First in words:

For one block, each head samples the mixed feature map at a learned displaced coordinate, then all head outputs are combined with a residual connection.

Then the compact form:

y(p) = x(p) + sum_{h=1}^{H} a_h * sample(m(x), p + d_h(p))

Every symbol:

ptarget grid location
x(p)input features at location p
m(x)pointwise mixed feature map
Hnumber of warp heads
d_h(p)displacement predicted by head h at location p
sample(., .)interpolation at a possibly non-grid coordinate
a_hlearned weight for head h
y(p)output features after the block
A tiny worked example
Take one target cell p in a 2D fluid snapshot.
Head 1 predicts an offset toward the upstream direction, so it reads the feature value from a cell that feeds mass into p.
Head 2 predicts an offset toward a nearby boundary, so it reads a value carrying reflection information.
Head 3 stays local and reads a nearby coordinate to keep fine detail.
The block sums those three sampled values and adds the original feature at p, so the update contains transport information without averaging an entire neighborhood.

The model gets global reach from the displaced source read, while the cost stays close to linear because each head samples one source coordinate per target point.

What can go wrong

What can go wrong

One-source reads may be too sparse. If a target point truly depends on a broad region at the same step, one sampled coordinate per head may be insufficient, because the block can miss part of the needed signal unless enough heads or layers are available.
Bad displacements create bad physics. When the predicted offsets point to irrelevant regions, the model imports the wrong information directly, which means errors can travel quickly through later blocks.
Interpolation can blur very sharp structures. Sampling at off-grid coordinates requires interpolation, and that interpolation may smooth abrupt jumps unless the grid is fine enough or the features already encode the discontinuity well.
Where the design is strongest. The method is strongest when the PDE has structured transport or wave propagation, because learned displacements can align the sampled reads with the real paths along which information moves.
What a runnable demo should prove

What a runnable demo should prove

Build a 2D PDE playground with at least two tasks: one transport-heavy flow problem and one wave problem. Show the current field, then let the user toggle three operator blocks: a local convolution baseline, a Fourier baseline, and Flower. For Flower, draw the predicted displacement arrows for a few heads so the user can see where each target point reads from.

The demo should measure rollout error over time, cost per forward pass, and how often the model chooses short or long displacements. It should also let the user disable multiscale blocks or reduce the number of heads. That ablation matters because it shows which part of the method carries the long-range dependency: direct learned source selection, repeated residual composition, or the coarse-to-fine scaffold.

score = rollout_error + latency + memory_use

The demo must show that Flower succeeds when its learned source coordinates line up with the true transport paths, because that is the mechanism that replaces dense spatial mixing.
