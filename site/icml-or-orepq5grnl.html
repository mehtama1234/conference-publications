SOLAR: Self-supervised Joint Learning for Symmetric Multimodal Retrieval

Learn retrieval from unlabeled image-text pairs by separating what the two modalities share from what each modality uniquely contributes, then train embeddings that respect both parts.

Paper explainersAll themesMultimodal

Retrieval usually has a direction: text searches images, or images search text. Symmetric multimodal retrieval is harder because either side can be the query and either side can be the target, and each side may contain both shared meaning and modality-specific detail. Supervised datasets are usually asymmetric, so models trained on them inherit that bias. SOLAR learns from unlabeled web image-text pairs instead. It first estimates an intersection mask that marks the content shared by the image and text while leaving their differences intact. It then uses that mask to create positive and hard-negative training pairs, so the learned embedding (a learned list of numbers used to compare items) captures both agreement and disagreement between modalities.

Zero assumption version

Why symmetric retrieval breaks asymmetric training assumptions

A caption and an image are not exact copies of each other. They usually share a semantic core, such as the main objects or action, but each modality also contains extra detail. The image may include background objects the caption ignores. The caption may name intent or context that is not visually explicit. A retrieval model that only maximizes overall alignment can blur these differences and learn an embedding space that is good for one fixed query direction yet weak when both directions must work equally well.

Labeled datasets make this worse because they often define one side as query and the other as answer. That supervision teaches the model what to preserve for the labeled direction, not what a fully symmetric system needs. For symmetric multimodal-to-multimodal retrieval, the training signal must preserve shared content while also keeping track of modality-specific residue, since that residue is what separates a true match from a semantically nearby but incomplete one.

The method in one sentence. Learn what image and text share, use that structure to fabricate informative training pairs from unlabeled data, and train one retrieval space that works in both directions.

The algorithm as a flow

What it actually does

Start from unlabeled image-text pairs.

Use abundant web pairs instead of relying on symmetric manual labels because the method extracts supervision from the pair structure itself.

Learn an intersection mask.

Estimate which parts of the image and text represent shared semantics because that split tells the model what should stay aligned and what should remain distinct.

Preserve the residual parts.

Keep the image-only and text-only leftovers because those details are what define hard retrieval mistakes among near matches.

Create positives and hard negatives with masking.

Use the learned mask to form sample pairs that agree on the shared core but differ on important residual details, which teaches the retriever what not to collapse together.

Train a symmetric retrieval space.

Optimize the embedding space so image-to-text and text-to-image retrieval both rank true shared pairs above mask-based distractors.

What the paper changes

What the paper changes

The paper changes the supervision source for multimodal retrieval. Instead of treating each pair as one opaque positive example, it decomposes the pair into shared and unique parts and uses that decomposition to build its own training signal.

The hidden quantity

The hidden quantity

measured quantity  =  how much of a pair is shared content versus modality-specific residue

The hidden quantity is the split between intersection and residue inside one image-text pair. If that split is wrong, the retriever will either over-collapse different items that share a broad topic or over-separate true matches that express the same event in different forms.

SOLAR estimates the split with an intersection mask and then uses the estimate twice: first to align the shared content, and second to create training examples that differ in the residue while preserving the shared core. That second use is important because it forces the embedding space to respect the details that matter for symmetric retrieval rather than merely grouping broad topics together.

Why it works

Why intersection-aware sample construction changes retrieval behavior

A standard contrastive retriever often sees one positive pair and many unrelated negatives. That teaches broad alignment, but it gives weak pressure on fine distinctions because the negatives are too easy. A model can rank the positive first without learning which exact details define the match.

Mask-guided sample construction fixes that by generating difficult comparisons from within the same semantic neighborhood. When two samples share the intersection but differ in the residue, the retriever must represent the shared core faithfully while still encoding the leftover details that keep the items distinct. That produces a more symmetric retrieval space because the same shared-versus-residual logic applies regardless of which modality is the query.

The two-stage design matters because the mask must exist before it can supervise hard-negative creation. Stage one extracts pair structure. Stage two converts that structure into retrieval pressure. Without the first stage, hard negatives would be noisy. Without the second stage, the learned intersection would never be forced to shape the final embedding space.

Math after the picture

Train retrieval by contrasting mask-guided positives and negatives

First in words:

A simple summary is to maximize similarity for true or mask-preserved positives and minimize similarity for hard negatives that share broad content but differ on residual details.

Then the compact form:

L = - log ( exp(sim(q, p) / tau) / (exp(sim(q, p) / tau) + sum_n exp(sim(q, n) / tau)) )

Every symbol:

qthe query embedding
pthe positive target embedding
na hard-negative target embedding built with mask guidance
sim(., .)the similarity score between two embeddings
taua temperature value that controls how sharply similarities are separated
Lthe retrieval training loss
A tiny worked example
Suppose an image shows two dogs running on grass and the text says 'two dogs running in a field.'
A mask-preserved positive keeps the shared object count and action.
A hard negative keeps the running scene but changes the count to one dog.
If the retriever maps those two targets too close together, the loss stays high.
Training lowers the loss only when the one-dog example moves away while the true two-dog pair stays close.

The key is not the exact formula but the origin of the positives and negatives: they are generated from shared-versus-residual structure instead of from random unrelated pairs.

What can go wrong

What can go wrong

The learned mask can confuse shared and private content. If the image-text pair is noisy or loosely related, the mask may mark incidental overlap as shared meaning. That produces weak positives and misleading negatives.
Web pairs can contain systematic caption bias. Many web captions omit visual details or add context not visible in the image. If that bias dominates the data, the retrieval space may still learn asymmetry even though the training scheme is symmetric.
Hard negatives can become too hard. If the constructed negative differs only in a detail that neither modality expresses clearly, the model receives noisy supervision and may push apart items that should remain close.
Done right. The method is strongest when the mask quality is checked, pair noise is filtered, and hard negatives are built from details that are truly expressed in both modalities.
What a runnable demo should prove

What a runnable demo should prove

Build a retrieval toy set from image-text pairs where each pair contains a clear shared core plus a small residual difference such as object count, color, or background activity. Learn an intersection mask, generate mask-based positives and hard negatives, and train a shared embedding space.

The demo should evaluate both image-to-text and text-to-image retrieval and should include near-match distractors. It is important to show cases where broad-topic retrieval succeeds for all methods but residual-detail retrieval separates SOLAR from a baseline trained on ordinary positives and random negatives.

symmetry_gap = | recall_image_to_text - recall_text_to_image |

A convincing result is high recall in both directions with a small symmetry gap, because that means the embedding space preserved both shared semantics and the details that stop partial matches from collapsing together.
