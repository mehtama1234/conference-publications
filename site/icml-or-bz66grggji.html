Dynamic Relational Priming in Transformers

Instead of using the same token representation for every comparison, tune each token differently depending on which other token it is being compared against.

Paper explainersAll themesTime Series & Sequential

In time series with many channels (temperature, humidity, pressure, wind), different pairs of channels follow entirely different rules. Standard attention (a comparison method in neural networks) uses the same, unchanging representation each time it looks up past data. This paper introduces prime attention: when comparing any two time steps, the system adjusts each one's representation to suit that specific pair's interaction. This reflects reality: channel relationships in complex systems are highly varied.

Why standard attention falls short for time series

In a multivariate time series (a system with many measurement channels changing over time), different channel pairs interact via completely different physical laws. Humidity affects temperature differently than pressure affects wind speed. Yet standard attention uses one frozen representation per time step and applies the same comparison logic to all pairs. A naïve approach would compare every pair of time steps using identical fixed features, forcing an unnatural uniformity.

The result: the model wastes learnable capacity trying to represent all possible pair-wise relationships with a single learned representation, when in reality those relationships are wildly different. The attention mechanism cannot adapt the representation to match the true interaction type of each pair.

The problem in one sentence. Standard attention must capture all pair-wise interactions using one frozen representation per time step, ignoring that different channel pairs follow different interaction laws.

The algorithm as a flow

What it actually does

Input: time series tokens

Each time step is a token (a set of numbers, one per channel).

Compute base representation

A learned transformation converts each token into a vector (a list of numbers) that captures its features.

For each token pair, dynamically prime

Look at the two tokens being compared; use that information to adjust both representations.

Compare using primed representations

Compute attention scores and values using the adjusted, context-aware representations.

Aggregate across pairs

Weighted sum the values to produce the output, which feeds to the next layer.

What the paper changes

The thing the paper changes

Prime attention replaces the standard approach of using one frozen representation per time step with a system that generates a different representation for each time step whenever it is being compared against a different partner. The representations are dynamically adjusted on the fly based on the interaction type.

the object it moves  =  Token representations (computed per pair)
The hidden quantity

The priming signal: what captures each interaction

measured quantity  =  Interaction-specific representation modulation

The paper infers and measures an implicit quantity: the degree to which each token pair requires a distinct representational lens. When a token prepares to attend to a very different token (e.g., temperature attending to pressure), the priming mechanism adjusts its representation to match that specific relationship type. The paper does not report this quantity directly; instead, it measures the effect: whether the primed representations improve forecast accuracy and whether the model can now handle shorter sequences (use less historical data) to achieve the same accuracy. A lower sequence length at equal accuracy signals that the primed representations are genuinely capturing the heterogeneous interaction structure, because if the representations were not tuned to the actual interaction types, the model would still need to look back many steps to find enough context to guess the right answer.

Why it works

Why priming each pair separately works

In multivariate time series, different channel pairs truly do interact via different mechanisms. Humidity and temperature are linked by physics (warm air holds more moisture); temperature and wind are linked by weather dynamics (low pressure causes wind); but the coupling laws are not the same. A single representation cannot efficiently encode all these different interaction types.

Prime attention solves this by making the representation adaptive. For each pair, the system learns a small adjustment (the priming) that tailors both representations to that specific interaction. This is efficient: the base representation carries shared structure (common features of all tokens), and the priming adds just enough flexibility to align each pair optimally. The model no longer wastes capacity trying to cram heterogeneous interactions into a single learned space. When the query and key representations are tuned to the actual pair interaction, the dot product between them captures the true strength of their coupling, rather than being contaminated by false mismatches from interaction types that are not relevant to that pair. A clean signal of true coupling strength means each attention weight is more accurate, so the model's weighted sum of past information contains the right balance of signals. With accurate weighting, the model can forecast from shorter histories because each timestep contributes the right signal strength.

Math after the picture

The priming equation

First in words:

Attention output equals the weighted average of values, where each value representation is primed (adjusted) based on the query and key pair, and the weights come from comparing the primed query and key, normalized to sum to 1.

Then the compact form:

output = sum_j softmax_j(alpha * (Q_i' . K_j' / sqrt(d))) * V_j'

Every symbol:

Q_i'query representation for token i, primed based on which token it attends to
K_j'key representation for token j, primed based on the query token
V_j'value representation for token j, primed by the pair interaction
softmax_j(...)normalized attention weights that sum to 1 across all j
alpha * (...) / sqrt(d)attention score: scaled dot product of primed query and key
dthe dimension of the representations (number of features)
A tiny worked example
Suppose token i (temperature at time t) attends to three other tokens: j1 (humidity at t-1), j2 (wind at t-2), j3 (pressure at t-3).
Base embedding for i: [0.5, 0.3, 0.8] (same for all comparisons in standard attention).
Priming adjusts Q_i' differently for each j: Q_i' toward j1 = [0.6, 0.4, 0.7] (stronger humidity features), Q_i' toward j2 = [0.4, 0.2, 0.9] (stronger wind features).
Compute attention score to j1: (Q_i' . K_j1') / sqrt(3) = (0.6*0.5 + 0.4*0.6 + 0.7*0.4) / 1.73 = (0.30 + 0.24 + 0.28) / 1.73 = 0.82 / 1.73 = 0.47.
Compute attention score to j2: (Q_i' . K_j2') / sqrt(3) = (0.4*0.7 + 0.2*0.3 + 0.9*0.5) / 1.73 = (0.28 + 0.06 + 0.45) / 1.73 = 0.79 / 1.73 = 0.46.
Normalize via softmax: w1 = exp(0.47) / (exp(0.47) + exp(0.46) + ...) ≈ 0.40, w2 ≈ 0.39, w3 ≈ 0.21.
Same movement (base to primed) but tailored per pair — temperature to humidity gets one adjustment, temperature to wind gets another, capturing their different interaction types.

The priming adds a small pairwise adjustment layer that lets the attention mechanism adapt its comparison strategy per interaction type, without rebuilding the entire representation from scratch.

What can go wrong

What can go wrong

Priming overhead outweighs the gain. If computing the priming adjustment requires many additional learnable weights or extra arithmetic operations, the total computation time could grow and offset the accuracy improvements. For instance, if priming requires one extra numerical operation per pair of tokens, that is quadratic in how many past timesteps the model considers, potentially making the model slow. The paper shows this does not happen in practice because the priming is implemented to be efficient, but a wasteful priming design would harm speed.
Interaction types are too similar. If all channel pairs in a time series truly have similar dynamics (e.g., a simple linear system), priming buys little. The method exploits heterogeneity; it wastes capacity on homogeneous data.
Priming learns spurious correlations. If the training data is limited or noisy, the priming mechanism might adjust representations based on accidents of the training set rather than true interaction types. This would hurt generalization to new data.
Done right. Prime attention works best on true multivariate systems where different channel pairs have fundamentally different dynamics, the training data is representative, and the priming overhead is kept modest through efficient implementation.
What a runnable demo should prove

What a runnable demo should prove

Build a simple forecasting experiment on a synthetic time series with multiple channels, where each pair of channels has a distinct interaction pattern (e.g., a 3-channel system where channel A influences channel B with a 1-step delay, and channel B influences channel C with a 2-step delay). Train a standard attention-based model and a prime-attention model on the same data, using the same total number of learnable weights and training process. Measure accuracy on one-step and multi-step forecasts; also measure the minimum history length each model needs to hit a target accuracy. The demo succeeds if prime attention either: (1) reaches lower error with the same history length, or (2) reaches the same error with shorter histories. Plot both metrics side by side.
