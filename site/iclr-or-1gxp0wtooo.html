Adaptive Conformal Guidance for Learning under Uncertainty

When guidance is imperfect, the paper learns which signals to trust by measuring how uncertain each one is, then turns down the ones that are shaky.

Paper explainersAll themesOptimization

Models often learn from guidance — labels written by humans, predictions from other models, or expert demonstrations. But this guidance can be wrong. Rather than blindly following all guidance equally, this paper measures how uncertain each guidance signal is, then automatically adjusts how much the model relies on each one. Signals that are shaky get less influence; confident ones get more.

The guidance trust problem

When you teach a model from examples, you give it labels or demonstrations. But these signals can lie. A label might be wrong because the human made a mistake. A label from another model might fail on new data it has never seen. An expert's demonstration might not transfer to a different situation. The naive approach is to trust all guidance equally — treat every signal the same. But when some signals are wrong and others are right, the model ends up confused and learns slower or worse.

The problem in one sentence. Guidance is often noisy and unreliable, but most learning methods trust it all equally anyway.

The algorithm as a flow

What it actually does

Gather guidance

Collect labels, pseudo-labels, or expert signals as before.

Measure each signal's uncertainty

Use split conformal prediction to estimate how likely each guidance is to be wrong.

Compute trust weight

Convert uncertainty into a weight: high uncertainty means low weight.

Modulate the training

When the model sees guidance, multiply its influence by the trust weight.

Learn more reliably

Model updates more on signals that proved trustworthy, ignores unreliable ones.

What the paper changes

What the paper changes

The paper changes how strongly the model listens to each piece of guidance. Instead of one fixed blend of signals, it computes a separate weight for each signal based on how uncertain it is, then uses those weights during training.

the object it moves  =  guidance signal weights
The hidden quantity

Uncertainty: how likely each signal is wrong

measured quantity  =  guidance uncertainty estimate

Every guidance signal carries risk of being wrong. The paper measures this risk for each signal using a technique called split conformal prediction — a method that asks: if I trained on old examples, how often would this signal be wrong on new examples? The answer is a probability: 0 means the signal never failed; 1 means it failed half the time. The paper converts this probability into an inverse weight: high uncertainty becomes low weight, low uncertainty becomes high weight.

The paper estimates this uncertainty using the training data itself. It splits the data, trains on one half, then tests on the other half to see which guidance signals fail. This gives it a real measurement, not a guess.

Paper reading. Split conformal prediction yields a calibrated confidence interval around each guidance signal's correctness; the paper inverts this into an importance weight that modulates the signal's contribution to the training loss.
Why it works

Why measuring uncertainty lets the model learn better

Here is the causal chain. Start with a mixed set of guidance signals — some correct, some wrong. If you treat them all equally, the model splits its learning effort between right and wrong signals, so it learns from right ones more slowly and gets pulled off-track by wrong ones. Now measure the uncertainty in each signal by asking: how often did this type of signal fail in the past? This tells you which signals are reliable. Next, when training, reduce the influence of uncertain (unreliable) signals and increase the influence of certain (reliable) signals. The model now concentrates its learning on trustworthy signals and ignores the ones that keep getting it wrong. The result is cleaner learning because you removed conflicting wrong signals from the training updates. Convergence is faster because the model now follows a clear direction (updating weights the same way each step) rather than bouncing between conflicting signals that push in opposite directions. Final performance is better because the model learned from what works, not from what fails. The key reason this works is that it is a form of adaptive filtering — you are filtering out the noise before it corrupts the model, rather than letting the model try to learn from noise and hope it averages out.

Math after the picture

The weighted guidance rule

First in words:

the training loss is a weighted sum of the guidance contributions, where each weight depends on the signal's measured uncertainty.

Then the compact form:

loss = sum_i w_i * guidance_loss_i, where w_i = 1 / (1 + uncertainty_i)

Every symbol:

w_iweight for guidance signal i
guidance_loss_ithe error contribution from signal i
uncertainty_imeasured uncertainty (risk of wrongness) for signal i
sum_iadd up over all guidance signals
A tiny worked example
Signal A: uncertainty = 0.1 (low risk), weight = 1 / (1 + 0.1) = 0.91.
Signal B: uncertainty = 0.5 (medium risk), weight = 1 / (1 + 0.5) = 0.67.
Signal C: uncertainty = 2.0 (high risk), weight = 1 / (1 + 2.0) = 0.33.
In training, signal A pulls 0.91 strength, B pulls 0.67, C pulls only 0.33. Good signals dominate.

Each guidance signal loses influence in proportion to how often it failed before; the formula fades unreliable signals automatically.

What can go wrong

What can go wrong

Uncertainty overestimation. If the split-conformal method flags good signals as uncertain (false negatives), those signals get down-weighted unfairly and the model learns slower.
Not enough data to measure uncertainty. If the training set is tiny, the split used to measure uncertainty is also tiny, so the estimates are noisy and unreliable themselves.
Data changing after measuring. If the data changes after you measure uncertainty (e.g., new domain appears), the old uncertainty estimates may no longer be valid.
Correct use. Apply the method to tasks where guidance sources are mixed quality and you have enough data to measure their past reliability. Re-measure uncertainty periodically if new guidance sources are added.
What a runnable demo should prove

What a runnable demo should prove

Build a simple supervised learning task where guidance comes from two sources: a reliable label source (90% correct) and a noisy pseudo-label source (60% correct). Train a model on a mix of both types of guidance. First, train naively by trusting both equally. Measure final accuracy. Then, apply AdaConG to measure the uncertainty of each source and adjust weights accordingly. Measure final accuracy again and show that AdaConG wins — the model ignores the noisy source and relies on the reliable one.

improvement = accuracy_with_AdaConG - accuracy_naive_baseline

The demo must show that selectively trusting good signals wins because bad signals pull the model in the wrong direction, while good signals pull it right — so ignoring the bad ones lets the model converge to the right answer faster and more reliably.
