ChannelTokenFormer: Real-World Time Series with Asynchrony and Gaps

A Transformer model that forecasts multivariate time series by treating each channel as a token and explicitly handling three real-world problems: channels updating at different times, missing chunks of data, and hidden connections between channels.

Paper explainersAll themesTime Series & Sequential

Real-world factories, power grids, and hospitals generate time series data from dozens of sensors running on different schedules, with gaps when equipment fails or data is lost. Existing forecasting models pretend all channels update together at regular intervals and have complete data. This paper builds a deep model (a Transformer, a neural architecture good at learning patterns in sequences) that drops those false assumptions and learns what each channel's future values will be while coping with the messy reality.

Zero assumption version

Three problems all at once

A factory has 20 sensors: temperature, pressure, flow rate, vibration, humidity. Each one records once every second, but a power hiccup causes sensor 5 to skip readings for two hours. Pressure takes samples every 0.9 seconds because it uses a different timer. A naive forecast model built on the assumption that all 20 sensors tick at the same regular interval fails immediately—it cannot align the channels, it cannot skip over the missing block, and it never learns that pressure spikes before temperature peaks.

Real-world time series have three tangled problems: inter-channel dependence (pressure and temperature are linked; one predicts the other), sampling asynchrony (each channel runs on its own schedule), and missingness (data vanishes without warning). Most forecasting models address one or two in isolation. Existing architectures still assume channels are synchronized, or they patch missing values by copying the last observed number, or they ignore the connections between channels. When you combine all three, the model's forecast collapses.

The move: Treat each channel measurement as a token—like a word in a sentence—and let a Transformer learn when to attend to which channel, what to do when data is missing, and which channels influence which.

The algorithm as a flow

What it actually does

Tokenize observations

Turn each (channel ID, timestamp, measured value) into a single token—skip missing slots entirely, no padding.

Embed context

Encode each token with: which channel it came from, how long ago it was observed, and its raw value; all three fused into a list of numbers.

Multi-head attention (learning which inputs matter)

The model learns: when predicting temperature at 3pm, read pressure readings from any time, humidity from 5min ago, and skip channel 7 (irrelevant). The mechanism is a learned score for each input.

Async-aware decoding

Generate the next value for each channel in order of when we next expect it. No waiting for synchronized time steps.

Handle absences

If channel 5 has been silent for two hours, the model uses only recent nearby channels; no garbage-filled gaps.

What the paper changes

What the paper changes

Instead of forcing multivariate time series into a regular grid (time step by time step, with all channels aligned), the model accepts an irregular stream of observations—whatever came in at whatever time, in whatever order—and learns forecasts from that raw asynchronous feed.

the object it moves  =  Input format: from aligned grid to token stream
The hidden quantity

The hidden quantity: Channel influence

measured quantity  =  Cross-channel importance (which channels matter for predicting which)

A time series forecaster must implicitly learn which channels drive which. In a temperature forecast, does humidity matter? Does yesterday's pressure? Does vibration mean anything? Most models bury this as learned weights inside a black box. ChannelTokenFormer makes it visible through learned importance scores, because the self-attention operation in the deep model naturally computes and stores a weight for each input—how much that input contributed to the output.

When predicting temperature 10 minutes ahead, the model's learned weights tell you: 'I drew 60% of my signal from recent temperature, 25% from humidity, 10% from pressure, 5% from vibration.' Those weights are the paper's answer to 'which channels are linked to which.' The model learns them directly from the data during training, because the deep architecture has a mechanism—an operation called self-attention—that naturally measures and outputs these importance scores. No separate analysis or tool needed.

Why it works

Why tokenizing asynchronous streams works

The core insight: a Transformer is a universal sequence model. It was built to handle tokens (words in a sentence) arriving in order, with variable importance. Nothing says those tokens have to be words. If you feed it (channel_id, timestamp, value) tuples in chronological order, the model learns to group by channel and by time, extracting patterns specific to each channel and patterns that cross channels. Missing data simply means no token exists for that time—the model has no input to read, so it infers the missing value from neighboring channels' signals that did arrive. This works because the model learns: 'when channel 5 is silent, channels 2 and 3 often contain clues about what channel 5 would say.'

Why does this beat forcing data into a regular grid? Because the grid is a lie. Real sensors do not update in lockstep. By accepting irregular tokens, the model never has to invent phantom values, never has to throw away timing information to fit a grid, and never has to choose between 'drop the out-of-phase sample' or 'wait forever for the slow channel.' Each channel contributes whenever it has a reading. Attention automatically learns which channels are predictive of which because they co-occur in the token stream, and the model learns to skip irrelevant channels because they provide no signal.

Math after the picture

The core equation

First in words:

For each output token: predicted value equals a weighted mix of all input tokens' embeddings, where the weights (attention) are learned from query, key, and value transforms of the input stream.

Then the compact form:

output_i = sum_j attention_ij * (value_tokens_j) where attention_ij = softmax_over_j( (query_i · key_j) / sqrt(d) )

Every symbol:

output_ithe predicted value for position i (a specific channel at a specific future time)
attention_ijhow much to weight token j when predicting position i, learned during training
query_ia learned transform of the target position (channel + timestamp embedding)
key_ja learned transform of an input token (channel + timestamp + value)
value_tokens_janother learned transform of the input, containing the actual signal to mix
dthe embedding dimension (how many numbers describe each token)
softmax_over_jturn raw attention scores into fractions that add up to 1, so the output is a weighted average
A tiny worked example
Predicting temperature at 3:00 PM. Input tokens include: [Temp, 2:45 PM, 68.2], [Pressure, 2:50 PM, 101.3], [Humidity, 2:55 PM, 55], [Temp, 2:55 PM, 68.9].
Attention scores after softmax: Temp 2:45 = 0.4, Pressure 2:50 = 0.1, Humidity 2:55 = 0.2, Temp 2:55 = 0.3 (sum = 1.0).
Forecast = 0.4 × (embed[68.2]) + 0.1 × (embed[101.3]) + 0.2 × (embed[55]) + 0.3 × (embed[68.9]) = 68.5 degrees.
The model gave most weight to the most recent temperature (0.3) and some recent history (0.4), less to pressure and humidity. If Temp had been missing at 2:55, the softmax would redistribute, favoring the 2:45 reading and borrowing from Pressure/Humidity.

This is standard Transformer attention, but applied to an irregular token stream where each token carries channel identity and timing, allowing the model to learn asynchronous dependencies end-to-end.

What can go wrong

What can go wrong

Long gaps with no nearby channels. If channel 5 goes silent for a week and no other channel is related to it, the model cannot predict it. It must extrapolate from stale data. If the channel's behavior changed during the gap, the forecast will miss it.
Very long asynchrony (channel updates once per day, another once per second). The token stream becomes dense in one channel and sparse in another. Attention must span huge time gaps. The model may struggle if the training data does not include examples of such extreme mismatches.
Concept drift (the relationship between channels changes over time). If pressure used to predict temperature but a hardware upgrade decoupled them, the model trained on old data will apply wrong attention weights to new data. Retraining is needed.
Done right. For industrial sensor networks where channels are sampled at fixed intervals but occasionally stall, and where inter-channel relationships are stable, ChannelTokenFormer delivers accurate forecasts without preprocessing or imputation, because it learned the true timing of each channel and the real relationships between them.
What a runnable demo should prove

What a runnable demo should prove

Build a synthetic industrial time series: 10 channels, each on its own fixed interval (e.g., channel 0 every 1.0 sec, channel 1 every 1.3 sec, etc.). Add missing blocks: randomly drop 20% of observations. Construct ground-truth: generate values so that channels 2 and 5 are tightly coupled, channel 7 is independent noise, and the rest have weak correlations. Train a standard Transformer baseline on artificially aligned, imputed data (forward-filled gaps). Train ChannelTokenFormer on the raw irregular token stream. Forecast 50 time steps ahead. Measure forecast error (mean squared error) on each channel separately. Plot the attention weights to visualize learned inter-channel dependencies.

forecast_accuracy = 1 - ( sum_channels( mean_squared_error_channel / variance_channel ) / num_channels )

The demo must make clear: ChannelTokenFormer achieves comparable or better accuracy than the baseline on the coupled channels (2, 5) and maintains accuracy when the baseline's imputation strategy (forward-fill) fails, visible in smaller error bars over the 50-step horizon. This happens because the model learned the true asynchronous timing and the real channel relationships.
