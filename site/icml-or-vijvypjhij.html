Path-dependent Discrete Amortized Inference

The paper improves learned samplers for discrete structured objects by letting the policy depend on the full construction history through hidden dynamics instead of only on the current partial state.

Paper explainersAll themesOther

Many answering time problems ask for samples of discrete structured objects from an unnormalized posterior: parse trees, sets, sequences, graphs, or other compositional objects whose probabilities are known only up to a constant factor. A recent line of work turns this into a deterministic construction process. The sampler adds one piece at a time, and a learned policy tries to generate full objects in proportion to the target posterior. That framing is useful, but it usually treats the process as Markovian, meaning the next decision depends only on the current partial object. This paper shows that the Markov assumption can damage both optimization and expressiveness. Different construction histories can collapse to the same visible partial state even though they should induce different future choices. To fix that, the paper adds learnable hidden dynamics that carry path information forward, producing a path-dependent amortized sampler.

Zero assumption version

Why Markov construction can lose essential information

In discrete amortized answering time, the sampler builds an object step by step. At any step it sees a partial object and chooses how to extend it. If the current partial object contains all the relevant information, a Markov policy is enough. But many compositional domains do not behave that way. Two different histories can arrive at the same visible state while implying different remaining posterior mass or different valid completions.

That is state aliasing: the visible state collapses multiple histories into one representation even though the histories matter. It hurts expressiveness because one policy action must now serve distinct situations. It also hurts learning signal propagation. Credit or blame from the final sampled object has to flow backward through the construction path, and a Markov compression can erase the path distinctions that would tell the policy which earlier decisions led to success.

The paper's fix. Keep the step-by-step construction view, but attach a learned hidden state that summarizes the whole trajectory so the next action can depend on how the current partial object was reached.

What the paper changes

What the paper changes

The paper changes the state definition inside the learned sampler. It lifts the deterministic Markov decision process by augmenting it with a learned hidden trajectory state.

The hidden quantity

The hidden quantity

measured quantity  =  trajectory information not visible in the current partial object

The key hidden quantity is the information carried by the path itself: which choices were made, in what order, and under what intermediate constraints. That information may still matter even when the current visible partial object looks identical. In other words, the object under construction does not always summarize its own history.

A path-dependent hidden state is useful because it lets the sampler preserve the distinctions that the visible state erased. If two histories collapse into one visible node but should induce different action data patterns, the hidden state can keep them separate. This increases representation capacity and clarifies credit assignment because updates can target the history that produced the outcome instead of all histories sharing the same visible state.

Why it works

Why path dependence improves discrete amortized answering time

A Markov sampler compresses all relevant information into the current visible state. That is efficient only if the compression is lossless for decision-making. In many discrete construction problems it is not. The same partial graph, sequence prefix, or set can arise through distinct earlier decisions that imply different remaining completions under the target posterior. When those cases are merged, the policy must average over incompatible futures. That weakens the sampler and can push it away from the correct posterior proportions.

The hidden dynamics state prevents that averaging. After each action, the hidden state is updated, so the policy receives both what the partial object looks like now and what trajectory produced it. This lets one visible state support several different effective policy contexts. The result is a richer sampler family that can model dependencies extending over the full construction path.

Training also benefits because final reward or posterior consistency information has to flow backward through the sequence of construction steps. If the model cannot distinguish which history produced the current state, training nudge updates blur together good and bad trajectories. The path-dependent state keeps those trajectories separable. That clearer credit assignment is why the paper reports fewer training steps to stable sampling and wider exploration, not only greater expressiveness at the end.

Math after the picture

A path-dependent policy update

First in words:

The next action distribution depends on both the current visible construction state and a latent hidden state that is updated recursively from the previous hidden state and the chosen action.

Then the compact form:

h_t = g_phi(h_(t-1), s_t, a_t), pi_theta(a_(t+1) | s_t, h_t)

Every symbol:

s_tvisible partial object at step t
a_taction taken at step t
h_tlatent path-dependent hidden state after step t
g_philearned latent dynamics update rule
pi_thetapolicy that chooses the next construction action
theta, phiparameters of the policy and latent dynamics
A tiny worked example
Suppose two different action sequences both reach the same visible partial object s_t.
Under a Markov policy, both cases would use the same next-action data pattern pi(a_(t+1) | s_t).
With path dependence, the first history produces hidden state h_t^A and the second produces h_t^B.
The policy can then output pi(a_(t+1) | s_t, h_t^A) different from pi(a_(t+1) | s_t, h_t^B).
That lets the sampler send probability mass to different completions even though the visible state alone looks identical.
The difference is exactly what resolves state aliasing.

The new term is the hidden state h at the current step. It carries forward information that the visible partial object alone cannot represent.

What can go wrong

What can go wrong

The hidden state can memorize noise. If the hidden dynamics is too flexible, it may store irrelevant details of the path and overfit instead of preserving only the history information that matters for posterior sampling.
Optimization becomes harder if history is very long. Path dependence increases expressiveness but also increases the burden on sequence training. If trajectories are long and the hidden state is poorly designed, learning may still struggle.
Some tasks are in practice Markov already. If the current partial object already contains all necessary information, the added hidden dynamics may bring little gain and only add complexity.
Done right. The method is most useful when visible states are aliased, different construction histories genuinely imply different futures, and the hidden dynamics can summarize those differences compactly.
What a runnable demo should prove

What a runnable demo should prove

Build a toy discrete construction problem where two different action sequences lead to the same visible partial state but should induce different target completion probabilities. Train one amortized sampler with a Markov policy and another with the paper's path-dependent hidden dynamics.

The demo should track three quantities: sample quality relative to the target posterior, convergence speed, and coverage of rare valid modes. The setting should be constructed so state aliasing is unavoidable, otherwise the difference between the two samplers will be too small to diagnose.

posterior_mismatch = sum over objects of |q_sampler(object) - p_target(object)|

A convincing result shows that the path-dependent sampler recovers the target proportions better precisely because it can distinguish histories that the visible state merged.
