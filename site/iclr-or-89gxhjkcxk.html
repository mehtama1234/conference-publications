EMAC: Active Annotation for Shifting Target Domains

When your model arrives at a new place where both the object types and the lighting have changed, actively pick which tricky examples to label instead of blindly trusting guesses.

Paper explainersAll themesOther

Imagine training a cat detector on sunny photographs, then deploying it in a foggy city where the lighting is dim and more animals are dogs. The model has not seen these combinations before. Most methods try to fix this using only guesses at what the animals are (the model picks which ones are cats, which are dogs), which leads to terrible errors because each wrong guess teaches the model to be even more wrong. This paper asks: what if we got a person to label the hardest cases — the ones where the model is least sure and the data is mixed — instead of randomly picking which examples to ask about?

Zero assumption version

The world shifts in two ways at once

When you deploy a model to a new place, two things often go wrong together. First, the types of things you are looking for change — you trained on cats but now see more dogs. Second, the way the scene looks changes — the lighting, colors, and angles are different. Most models break under this double shift because they were never trained on these combinations.

A naive approach: ignore the shift and keep using the old model. It fails fast. A better naive approach: look at the new data without labels and guess what the categories are, then train on those guesses. But the guesses are often wrong, especially where the data is confusing, because the model was trained on a different world. When you train on a wrong guess, the model learns that mistake as if it were true, poisoning the next round of learning. You end up training the model to make mistakes worse and worse, a cascade of error.

The challenge. When data shifts in two ways at once, guesses from the model itself are unreliable, so training on them hurts.

The algorithm as a flow

What it actually does

Spot the mess

Find regions in the new data where the predictions are uncertain and the data types mix.

Score by usefulness

Rank candidates by how much a human label would help, because a label on a high-confusion example breaks the cascade of error. Pick examples that are hard and typical.

Ask a human

Send the top few to a person for annotation. Get the real answer.

Mix signals

Train on the true labels (strong signal) and update trust in the model's guesses elsewhere (weak signal).

Adapt together

Balance learning from human labels with adapting to the new domain structure.

What the paper changes

What the paper changes

Normally, test-time adaptation uses only the model's own guesses. This paper introduces human labels on selected examples. The object is: which examples to ask a person about, and how much weight to give those true labels versus trusting the model's guesses.

the object it moves  =  selection strategy and label weight
The hidden quantity

The confusion score: where is the model lost?

measured quantity  =  Confusion in mixed regions

The paper measures a specific hidden quantity: how much is the model uncertain about what category this example belongs to, AND how often do nearby examples belong to different categories? This is not random noise — it is a signal that the data here violates the model's training assumptions. The regions where this score is high are where the two shifts (domain and class) collide.

The paper estimates this by looking at where the model's prediction confidence is low (it is unsure) and where many different class predictions appear in a small neighborhood (the data is mixed). High confusion means: this is a good candidate to ask a human about, because understanding it will teach the model something it is fundamentally missing.

Why it works

Why picking the right questions helps

The mechanism has two parts. First: blindly trusting the model's guesses on all examples causes a cascade of error. Each wrong guess pollutes the training signal. If you keep learning from mistakes, you make them worse. By asking a human only about the hardest cases (high confusion), you get real labels exactly where the model is most wrong. This breaks the error cascade.

Second: the paper balances two signals — the strong signal (human labels, reliable but scarce) and the weak signal (model guesses, plentiful but noisy). It does this by adjusting how much weight to give the model's own guesses based on how many human labels it has in that region. Where there are few human labels, distrust the guesses more. Where there are many, it is safer to trust. This way, the adaptation works on scarce annotation budget, not on pretending guesses are true.

Math after the picture

The adaptation balance

First in words:

Total loss = loss from human labels + scaled loss from model guesses, where the scale shrinks as annotation budget grows

Then the compact form:

L_total = L_true + (1 - r) * L_pseudo, where r is the fraction of data with human annotations

Every symbol:

L_trueerror on examples a human labeled
L_pseudoerror on examples the model guessed
rwhat fraction of examples got human labels
L_totalthe combined training signal
A tiny worked example
Suppose we annotate r = 0.05 (5 percent) of examples.
L_true = 0.8 (learning from human labels, good signal).
L_pseudo = 2.0 (learning from guesses, noisier).
L_total = 0.8 + (1 - 0.05) * 2.0 = 0.8 + 0.95 * 2.0 = 0.8 + 1.9 = 2.7.
If we annotated r = 0.20 (20 percent), then L_total = 0.8 + 0.80 * 2.0 = 2.4 (guesses trusted less because we have more real labels now).
More annotations = guess signal weakens = focus shifts to learning from humans. Annotation budget controls the balance.

The scale (1 - r) ensures that as you label more examples, the model trusts its own guesses less and leans harder on the human signals.

What can go wrong

What can go wrong

Confusion score is still just a guess. If the score does not actually predict where labels will be useful (e.g., the data is so alien that confusion is everywhere), then labeling the top examples will not help because you will be labeling examples that are not different from each other in what they teach the model.
Human labels are expensive. If you can afford to label only 1% of data but the hard cases are very diverse, you might label examples that are not representative enough to teach the model.
Labeler bias. A person annotating confusing examples might mark their own uncertainty or make systematic mistakes on types they have not seen. This pollutes the signal.
Done right. Pick labeling budget to match annotation cost, measure confusion carefully on validation data, and verify that the selected examples are indeed hard for the model and representative of the new domain.
What a runnable demo should prove

What a runnable demo should prove

Build a simple test-time adaptation scenario: take a trained cat-dog classifier, create a new dataset where the images are darker (domain shift) and contain mostly dogs (class shift). Run three methods: (1) no adaptation, (2) standard test-time adaptation with guesses only, (3) EMAC with 5% annotation. Measure accuracy on the true labels.

Accuracy gain = accuracy_EMAC - accuracy_guess_only

The demo should make it obvious that picking which examples to label beats either blindly guessing or labeling randomly.
