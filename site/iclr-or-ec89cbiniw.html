Differentiable Lifting for Topological Neural Networks

Learn which higher-order graph structures to add during training, instead of deciding them upfront with a fixed rule.

Paper explainersAll themesGraph & Geometric Learning

Topological neural networks process graphs by including high-order structures like cycles and cliques alongside individual nodes. Normally, you pick which structures to add before training using an unsupervised algorithm. This paper makes that choice learnable: it adds task-aware decisions during training itself, letting the network learn which higher-order connections actually help for the job at hand, because different tasks benefit from different structures and a fixed rule cannot adapt to what each task needs.

Zero assumption version

Fixed structures don't match the task

A graph is a set of nodes and edges. You can add higher-order information: pairs of nodes that are close to each other (forming hyperedges), or chains of nodes that form loops (forming cycles or simplices). Topological neural networks use these structures to make predictions. But you have to decide upfront: which pairs form hyperedges? Which loops matter? You pick a fixed rule — say, connect each node to its 5 nearest neighbors — and stick with it through training, regardless of what the task needs.

The problem: that fixed choice might be perfect for one task and terrible for another. A network trained to classify nodes might need different structures than one predicting edges. Since the lifting operation is unsupervised (not informed by labels or task goals), it often builds suboptimal structures that waste the network's capacity or miss important patterns.

In one sentence. Make the choice of higher-order structures learnable and task-aware: let the network decide which cells to include as it trains.

The algorithm as a flow

What it actually does

Embed all nodes

Run a standard graph neural network to compute a learned representation (a list of numbers) for each node.

Generate candidates

For each node, form candidate groups: e.g., its nearest neighbors (in the learned number-list space), at different group sizes.

Score each candidate

Combine the embeddings of nodes in each candidate group (using sum or average), then feed to a small neural network that outputs a probability: should this group be included?

Sample the structure

Use the probability to flip a coin (Bernoulli sample) for each candidate: include it or discard it. Build the new higher-order structure from the accepted cells.

Train end-to-end

Use the task loss (classification error or similar) to adjust which structures get accepted, without any auxiliary reward signals.

What the paper changes

What the paper moves

The paper changes the graph lifting procedure: instead of applying a fixed unsupervised rule before training, it makes the choice of which higher-order cells to include something the network learns and adjusts during training.

the object it moves  =  Lifting decisions
The hidden quantity

Task-informed structure importance

measured quantity  =  Cell acceptance probability

The paper introduces a hidden quantity: for each candidate higher-order cell (a candidate group of nodes), what is the probability it should be included in the final structure? This probability is learned by a small neural network that sees the embeddings of nodes in that candidate cell. High probability means the model believes this higher-order connection will help the task because those node groups carry signal that reduces classification error; low probability means it can be skipped because including it does not improve predictions.

The network estimates this probability using a multilayer perceptron (a small neural network with a few layers of learned weights) applied to the aggregated embeddings of the candidate cell's nodes. Error signals then adjust these acceptance probabilities to align with task performance: cells that help the model solve the task stay because including them reduces the classification error, while cells that do not contribute get discarded because adding them does not improve (or worsens) the task loss.

Why it works

Why task-aware lifting works

The core reason: different tasks benefit from different higher-order structures. A fixed rule (connect each node to its 5 nearest neighbors) is a one-size-fits-all choice that cannot adapt. By making the lifting decision learnable and supervised by the task loss, the network can discover which structures matter for its specific goal.

The mechanism operates in three stages. First, node embeddings capture each node's identity and context from the graph structure. Second, candidate cells are proposed (e.g., groups of nearby nodes); a small neural network scores each candidate by aggregating embeddings and computing an acceptance probability. Third, the task loss directly trains these scoring networks: if including a cell helps accuracy, error signals will increase its acceptance probability because the loss improved; if it hurts, error signals will decrease it because the loss worsened. Unlike older learnable methods that use auxiliary reward signals to guide structure learning, DiffLift trains purely on the task loss itself, making it simpler and more direct because the task objective directly aligns structure selection with performance. The network learns that certain groups of nodes reliably predict the target variable, and those groups become the higher-order structure because they encode predictive signal.

Math after the picture

The acceptance equation

First in words:

For each candidate cell C, aggregate the node embeddings in the cell, pass through a neural network, and sample a Bernoulli variable: the coin flip decides whether to include the cell.

Then the compact form:

P(accept C) = MLP(aggregate({z_v for v in C})) ; sample b_C ~ Bernoulli(P(accept C))

Every symbol:

z_vthe embedding (learned representation) of node v
Ca candidate higher-order cell (group of nodes)
aggregate(...)sum or average the embeddings of all nodes in the cell
MLP(...)a small neural network with learned weights that outputs a probability
b_Cthe binary decision: include cell C (1) or not (0)
Bernoulli(p)flip a coin with probability p of landing heads (include)
A tiny worked example
Suppose node A has embedding (0.8, 0.2), node B has (0.7, 0.3), and node C has (0.9, 0.1).
Candidate cell C_1 = {A, B}: aggregate by sum -> (1.5, 0.5). MLP sees (1.5, 0.5) and outputs probability 0.8 (high confidence to include).
Candidate cell C_2 = {A, B, C}: aggregate by sum -> (2.4, 0.6). MLP sees (2.4, 0.6) and outputs probability 0.3 (low confidence to include).
During training, we sample: C_1 is included with probability 0.8; C_2 is included with probability 0.3. Error signals from the task loss adjust the MLP weights so more relevant cells get higher probabilities.
Result: the network learns C_1 predicts the task better than C_2, so C_1 becomes part of the learned structure.

The task loss trains the MLP directly: cells that help classification get rewarded with higher acceptance probability because the error decreased, cells that hurt get lower probability because the error increased, all without auxiliary signals.

What can go wrong

What can go wrong

Overfitting the lifting to the training set. If you train the cell acceptance probabilities only on a small labeled dataset, the network might learn structures that fit the training labels perfectly but fail on new data. Use gentle steering (slightly penalizing overly confident probabilities) or validation-based early stopping on the lifting choices.
Forgetting the base graph structure. If the MLP becomes too aggressive at rejecting cells, the final structure might be too sparse to pass useful signal through the network. The network needs enough cells to propagate information between distant nodes.
Computational cost of sampling. During training, you sample the structure randomly on every epoch, which adds computational overhead. When you run the finished model on new data, you may also need multiple samples to get stable predictions.
Done right. Use a validation set to monitor lifting quality, gently steer cell acceptance probabilities toward reasonable ranges, and ensure candidate cells are generated efficiently (e.g., from nearest neighbors in the learned space rather than all possible subsets).
What a runnable demo should prove

What a runnable demo should prove

Build a simple graph with labeled nodes. Train two models in parallel: one with fixed lifting (e.g., k-nearest neighbors determined upfront), and one with DiffLift. Measure accuracy on a held-out test set. The demo should make visible: (1) the structure learned by DiffLift (which cells got accepted), (2) how it differs from the fixed lifting, and (3) that task performance is higher.

improvement = accuracy(DiffLift) - accuracy(fixed lifting)

The demo is successful if DiffLift's learned structure visibly adapts to the task and achieves noticeably better accuracy than a fixed rule on the same dataset, because task-aware structure selection aligns the graph topology with the predictive goal.
