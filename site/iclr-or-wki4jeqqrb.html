ReTrace: Reconstruction Attacks on Machine Unlearning

An attacker can use reinforcement learning to reverse-engineer forgotten data from a machine unlearning system by treating unlearning residue as a reward signal.

Paper explainersAll themesAlignment, Safety & Fairness

When users ask to have their data deleted, companies run machine unlearning: retraining logic to forget specific examples or groups while keeping everything else. But unlearning leaves invisible traces—small patterns in the neural network weights that an attacker can exploit. ReTrace shows how an attacker builds a generator (a system that creates images or text) that treats these leftover traces as hints, and uses reinforcement learning to point the generator toward reconstructing the forgotten data.

Zero assumption version

Unlearning leaves fingerprints

When a company must forget user data (say, for legal reasons like the right to be forgotten), they retrain the model to behave as if that data never existed. Ideally, the forgotten data becomes completely unretrievable. A naive person might think: just run normal training on the remaining data and the model forgets. But that does not work—retraining is expensive, slow, and incomplete.

In practice, companies use machine unlearning: a faster trick that nudges the model's numbers (weights) to stop the behavior tied to specific examples, because changing those numbers changes which patterns the model recognizes. The model still works, and it behaves like the data was deleted. But here is the problem: the unlearning process leaves residual traces. The weights have tiny signatures—subtle patterns baked in—that an attacker can read and say: that signature points toward the forgotten data. The weights did not go back to random; they are still shaped by what they are supposed to have forgotten.

In one sentence. Machine unlearning tries to make models forget data, but small traces remain in the weights—and an attacker can use those traces to reconstruct what was supposed to be deleted.

What the paper changes

The one thing the paper changes

The paper shifts how attackers think about reconstruction. Instead of writing a fixed decoder (a hand-built function that tries to reverse the unlearning), the attacker now trains a generator using reinforcement learning. The generator actively searches the space of possible inputs, guided by reward signals from the unlearned model itself. The object is the numbers inside the generator (the values that control its behavior); the mechanism steers these numbers to maximize a reward that points toward forgotten data.

the object it moves  =  generator's internal numbers
The hidden quantity

The residual trace: a reward signal from forgetting

measured quantity  =  Residual unlearning trace strength

Machine unlearning nudges the model's numbers (weights) so the model no longer explicitly outputs the forgotten data, because the numbers have been shifted away from the patterns that stored that data. But the weights still carry faint shadows—patterns that a mathematical scanner (like measuring which direction to nudge the numbers to maximize an output, or which neurons light up inside) can detect. ReTrace calls this leftover pattern the residual trace: it is a measurable signal that persists after unlearning.

The paper estimates the trace by feeding candidate reconstructions into the unlearned model and collecting scores (how likely the model thinks the input is real, how strongly internal neurons respond, signal magnitudes from early processing layers) that respond more strongly to inputs closer to the forgotten data. These scores become the reward in reinforcement learning.

Why it works

Why RL-guided reconstruction works

Machine unlearning is not deletion; it is stealth forgetting. The model's weights are nudged so the model will not spontaneously spit out the forgotten data if you ask directly, because the numbers have been shifted away from the learned patterns. But the neural network is still shaped by what it learned. Think of it like erasing pencil from paper—you lighten the marks, but the indentations remain.

An attacker with a generator (a neural network that produces images or text from random noise) can use reinforcement learning to explore the space of possible inputs. At each step, the attacker feeds a candidate into the unlearned model and collects a reward: how strong is the residual signal? If the model responds strongly (neurons fire hard, the model assigns high probability, the numbers inside shift sharply in response), the candidate is close to the forgotten data. If the response is flat (the model treats it like normal unseen input, neurons stay quiet, numbers barely move), the candidate is far. Reinforcement learning lets the generator learn which changes increase the reward, because it measures how much each change of the generator's numbers affects the reward and updates those numbers to increase reward. Over time, the generator drifts toward inputs that maximally activate the residual traces—which are exactly the inputs the model was trained to forget.

The theoretical foundation shows that this RL objective converges to an exponentially reweighted version of the original data pattern. In other words, the reward signal biases the generator to amplify the forgotten regions more and more as training proceeds, making reconstruction inevitable if the residual trace is strong enough, because the reward is continuously pointing the generator's internal numbers toward inputs that maximize the model's response to forgotten patterns.

The reinforcement learning objective

First in words:

Maximize the expected residual signal when the generator samples from its distribution, where the signal is weighted by how much the model's output differs from its unlearned baseline.

Then the compact form:

max E_x~G [reward(x)] where reward(x) = ||grad_x log p(x | unlearned_model) || or activation magnitude

Every symbol:

E_x~Gexpected value over samples x from the generator G
reward(x)strength of residual trace signal when input x is fed to model
grad_x log p(x | model)the gradient pointing toward inputs the model assigns high likelihood
|| ||magnitude or length of the vector
A tiny worked example
Candidate image A: noise. Model residual signal: 0.1 (weak). Reward: 0.1.
Candidate image B: blurry human face. Model residual signal: 2.5 (strong). Reward: 2.5.
Candidate image C: clear human face from forgotten user. Model residual signal: 4.8 (very strong). Reward: 4.8.
RL training sees these rewards and adjusts the generator to produce more images like B and C, avoiding A.

The reward is strongest on inputs that lie in the forgotten data distribution—the model's residual knowledge points the generator toward exactly what it was supposed to forget.

What can go wrong

What can go wrong

Weak residual traces. If unlearning is done thoroughly—if every weight that touched the forgotten data is truly rewritten—then there is no residual trace left. The reward signal vanishes and the generator cannot reconstruct. This is the ideal unlearning.
High-dimensional or structured data. Reconstructing random noise is easy; reconstructing natural images or grammatical text is much harder. The generator must learn the true data patterns, not just fool the model. Without enough model capacity or RL steps, recovery is low-fidelity.
Detector-aware unlearning. If unlearning explicitly tries to suppress residual traces (by training against attacks, or by using privacy-preserving techniques), the attack may fail. This is an arms race.
Done right: strong unlearning leaves no trace. Unlearning algorithms can defend by ensuring truly zero residual signal—for example, by using differential privacy during unlearning, or by periodically verifying against reconstruction attacks.
What a runnable demo should prove

What a runnable demo should prove

A minimal demo trains a small ResNet or transformer on a subset of a standard dataset (e.g. CIFAR-10), manually unlearns one class of images (e.g. all the cars), and then applies ReTrace. The RL generator (a small conditional GAN or diffusion model) is trained with the unlearned model as the reward source. Measure two things: (1) instance-level recovery—how often reconstructed images match actual forgotten samples when compared by a pre-trained classifier or human eye? (2) distribution-level fidelity—how close is the distribution of reconstructed images to the true distribution of forgotten data, measured by FID or KL divergence?

Recovery rate = (count of reconstructions matching original samples) / (total original samples); Fidelity = FID(reconstructed distribution, original distribution)

The demo must make clear that even after unlearning, the model's residual traces are strong enough to guide an attacker to reconstruct high-quality forgeries of the forgotten data, proving that standard unlearning methods are insufficient defenses against adversarial reconstruction.
