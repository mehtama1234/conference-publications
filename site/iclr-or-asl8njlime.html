FastVGGT: Fast Visual Geometry Transformer

Prune redundant tokens in visual transformers to run 4x faster on long image sequences without retraining.

Paper explainersAll themesRobotics & Control

A vision transformer (a neural network that reads images as small patches) processes long video sequences to figure out where objects are in 3D space. On 1000 images, it becomes extremely slow because each image gets split into many tokens (small pieces), and the model wastes computation asking where each token should look. FastVGGT speeds this up 4 times by intelligently dropping the tokens that do redundant work, keeping only the ones that measure something new.

Why long image sequences stall

Vision transformers process sequences of camera images to understand where objects sit in 3D space and how they move. On short sequences (say, 10 images), they work fine. But on 1000 images — a real video — they hit a wall: memory runs out, and computation crawls. A beginner's first try is simple: just feed all 1000 images in, same as 10 images. It fails because the transformer's scoring layer (which decides which past image regions matter for each small piece) compares every token from every image to every other token from every image. With 1000 images times 1000 tokens per image, that is 1 million tokens total. Comparing every token to every other token creates 1 million squared comparisons — 1 trillion scoring operations. Even one forward pass takes hours.

The bottleneck. Many tokens use the same scoring pattern to look at nearly identical regions, doing redundant work twice.

The algorithm as a flow

What it actually does

Identify redundancy

Measure which tokens attend to nearly identical image regions.

Anchor the first frame

Preserve all tokens from the first image as a stable global reference.

Keep salient patches

Retain tokens that look at rare or distinctive parts of the image.

Add random spatial coverage

Sample extra tokens randomly to ensure no area is completely missing.

Drop the rest

Discard tokens that add no new information, cutting memory and computation.

What the paper changes

What changes

FastVGGT does not retrain the model or change its weights. Instead, it reduces the number of tokens (pieces of the image) fed into attention at each time step. Fewer tokens mean fewer comparisons, which means faster answers.

the object it moves  =  token count
The hidden quantity

Token redundancy: when two tokens watch the same thing

measured quantity  =  token attention overlap

In the original transformer, each token outputs a list of scores showing where in prior frames it wants to look. If two tokens output nearly identical scores, they are looking at nearly the same regions and doing redundant work. FastVGGT estimates this overlap by comparing the attention scores (the look-at lists) of nearby tokens. Tokens with high overlap are marked as redundant.

The paper does not explicitly name a single formula for overlap, but the mechanism is clear: tokens whose attention patterns are nearly identical are pruned, while those with unique patterns are kept.

Why it works

Why pruning redundant tokens speeds everything up

The bottleneck is the scoring layer computation: how many times do we ask 'where should this token look?' The answer depends on how many tokens exist. With 1 million tokens, that question is asked 1 trillion times. If we prune down to 250k tokens (one quarter), the question is asked only 62.5 billion times — 16 times fewer, because each token is scored against all prior tokens, so cutting the token count cuts the scoring operations by the same fraction. But there is a catch: pruning must preserve the information that the model needs to track object positions correctly. If we drop all tokens from frame 2, we lose the position and shape information from that frame. FastVGGT preserves frame 1 as an anchor (so the first reference stays constant), keeps salient tokens (tokens that look at unusual or important parts), and adds random spatial samples (so no region is entirely missing). This three-part strategy works because frame 1 gives a stable baseline, salient tokens catch changes in important regions, and random sampling fills gaps. The result is that position information stays intact even though most tokens are dropped.

Math after the picture

The token selection strategy

First in words:

Token selected = (from frame 1) or (salient score above threshold) or (random sample from spatial grid)

Then the compact form:

keep_token = is_frame_1 OR (saliency_i > tau) OR (random_grid_sample)

Every symbol:

keep_tokenwhether to include this token in computation
is_frame_1true if this token is from the first frame
saliency_ihow unique this token's attention pattern is
tauthe cutoff score; tokens with saliency above tau are kept
random_grid_sampleone token randomly chosen from each spatial region
A tiny worked example
Suppose we have 12 tokens in one image. Frame 1 contributes 4 tokens (all kept). Remaining 8 tokens are checked: token-5 has saliency 0.8 (above tau=0.5, kept), token-6 has saliency 0.3 (below tau, dropped), token-7 saliency 0.7 (kept), token-8 saliency 0.2 (dropped). That is 3 + 2 = 5 salient tokens kept. Then random grid sampling adds 2 more tokens from blank regions. Total: 4 + 2 + 2 = 8 tokens kept out of 12. Pruning ratio = 8/12 = 67%, or 33% reduction.

The formula shows that frame 1 is always kept, high-uniqueness tokens are always kept, and random coverage fills gaps.

What can go wrong

What can go wrong

Salient threshold set too high. If tau is too strict, even important tokens are dropped. The position estimates become sparse and incomplete.
Random sampling too sparse. If the spatial grid is too coarse, large regions have no tokens. The model misses position and shape information in those areas.
Frame 1 not truly stable. If camera motion is large, frame 1 alone may not anchor the sequence. The model's position estimates drift over time.
Salient and redundant confuse each other. A token can look at a common region in a unique way (e.g., first to detect a moving object). Overlap-based pruning might drop it.
Done right. Set tau carefully (e.g., via validation on short sequences), ensure random sampling covers all quadrants, and test on sequences with large camera motion to verify frame 1 anchors positions correctly.
What a runnable demo should prove

What a runnable demo should prove

Build a simple tracking task: track the 3D position of a moving cube through a 100-frame video. (a) Run the original model (or a simple baseline) and record speed and final position error (how far the predicted position is from the true position). (b) Apply FastVGGT pruning (keep frame 1, keep tokens with saliency above 0.5, sample random grid every 4 by 4 pixels) and re-run with the exact same weights. (c) Confirm that speed increases at least 2x on 100 frames and error does not grow by more than 5%. On longer sequences (500 frames), the speedup should approach 4x. The speed gain comes from fewer tokens being scored against each other. The accuracy stays the same because frame 1 provides a stable baseline, salient tokens capture changes in key regions, and random sampling ensures no blind spots.

speedup = time_naive divided by time_pruned, position_error = distance from predicted position to true position

The core insight is visible: pruning redundant tokens cuts computation, but strategy keeps position output correct.
