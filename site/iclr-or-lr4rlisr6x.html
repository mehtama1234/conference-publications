PHAT: Periodic Heterogeneity for Time Series

When forecasting multiple time series together, the model must respect that each variable repeats on its own cycle, not assume all variables dance to the same beat.

Paper explainersAll themesTime Series & Sequential

In real data, when you forecast electricity use, temperature, and water demand together, each has its own repeating pattern. Electricity might spike every 24 hours, temperature every 12, water demand every 7 days. A model that treats them as locked to one global period misses half the signal and crosses wires between variables. PHAT separates variables by their rhythm before running predictions, so electricity data never confuses the model about what temperature should do.

Zero assumption version

Multiple rhythms, one forecast

When you have three time series (electricity, temperature, water demand) and you want to forecast them together, they all have repeating patterns. But the patterns are different lengths. A typical forecasting model reads all three as a jumble of numbers and learns one global rhythm, as if all three variables must dance to a single beat even though they naturally move at different speeds.

A beginner tries to make the model smarter by feeding it all the time steps at once and hoping it learns each variable's cycle separately. But without explicit separation, the model's internal states (the numbers it uses to reason about the data) get entangled. When it sees a spike in electricity at hour 6, the model updates its memory in a way that also affects how it thinks about temperature. This cross-talk makes the model second-guess itself: is the spike a temperature spike or electricity? By the time it predicts electricity, it has been confused by what temperature is doing.

The core problem. Multiple time series have different repeating patterns, and a standard model entangles them, mixing the signals.

The algorithm as a flow

What it actually does

1. Measure each variable's period

Before processing, identify or estimate what cycle length each variable repeats on.

2. Organize into periodic buckets

Arrange all time steps so that times with the same position within a cycle sit together; variables with matching periods share a bucket.

3. Restrict lookups within buckets

The model only looks at data points in its own bucket; it cannot mix electricity's 24-hour cycle with water's 7-day cycle.

4. Apply positive-negative scoring

For each bucket, compute scores in two parts: positive scores boost signal at aligned phases because past data at the same phase is most predictive; negative scores dampen noise and outliers because exceptions follow patterns too.

5. Forecast using known cycle structure

When making a forecast for time T, the model weights recent history according to which points align with T's phase in the cycle.

What the paper changes

What the model changes

PHAT changes how the model organizes and attends to time steps in multivariate data. Specifically, it restructures the input data into a three-dimensional bucket tensor: one axis groups variables by their period length, one axis aligns time steps by their phase within the period, and one axis tracks the offset from the start of the period. By doing this, PHAT prevents the model from mixing signals from variables on different cycles.

the object it moves  =  input organization and masking for period-aware lookups
The hidden quantity

Periodic alignment strength

measured quantity  =  Periodic alignment score

PHAT measures a hidden quantity: for each time step and each variable, how strongly should a past observation influence the forecast, based on whether that past step aligns with the current step's phase in the cycle? If electricity was high at hour 6 last cycle, and we are now at hour 6 again, the alignment score should be high, meaning "pay strong attention to that hour." If we are now at hour 12, the alignment score should be low, meaning "ignore that hour; it tells you nothing about hour 12."

The paper estimates this quantity by decomposing attention (the set of weights that say which past observations to trust) into positive and negative components. The positive component captures direct periodic alignment ("hour 6 predicts hour 6"). The negative component captures systematic deviations that are also predictable ("hour 6 is usually high, but on Tuesdays it drops; track both the rule and the exception"). The paper then applies a modulation term (a learned function of the known cycle lengths) to weight these components so the model respects the true cycle length; this works because feeding the cycle length directly is much faster than making the model learn it from data, and the cycle length is almost always stable across a dataset.

Why it works

Why periodic bucketing and positive-negative attention work

Here is the core reason PHAT works: by organizing data into periodic buckets (grouped by variable period and aligned phase), the model can learn separate rules for electricity-at-hour-6 and water-at-day-3 without the signals interfering. When the model computes attention (a set of weights that say which past observations to trust), it only looks within its bucket. This means electricity's forecast for hour 6 tomorrow will weight past hour-6 electricity observations strongly, and ignore water observations entirely, because water is in a different bucket.

The positive-negative scoring mechanism reinforces this. Positive scores say: "When the phase aligns (hour 6 now matches hour 6 before), boost the weight." Negative scores say: "Also track deviations from the baseline; if hour 6 is usually high but sometimes drops, note both patterns." By decomposing scores this way and applying a modulation term that encodes the known period length, the model stops guessing about cycles and instead uses the structure of the problem. This is faster to train because the model does not need to rediscover periodicity from data through slow iterative learning; it is more accurate because the structure prevents electricity confusion from seeping into temperature forecasts (the model cannot learn cross-period interference if buckets block cross-period access).

In sum: bucketing separates the signals so they never interfere, and positive-negative scoring lets the model capture not just the main rhythm but the reliable deviations within that rhythm; together they exploit the constraint that each variable has a fixed, known cycle.

The alignment score equation

First in words:

For each variable in a bucket, the attention weight for a past observation depends on how well its phase aligns with the current phase. We compute this as a positive alignment component plus a negative deviation component, then modulate by the known period length. The full score is positive attention (which is highest when phase aligns) times the modulation factor, plus negative attention (which captures systematic exceptions).

Then the compact form:

Attention_score = Modulation_factor * Positive_align + Negative_deviation

Every symbol:

Attention_scoreHow much weight to give this past observation when forecasting
Modulation_factorLearned function of the known period length and current phase
Positive_alignScore when this past observation is at the same phase as now
Negative_deviationScore capturing predictable exceptions and noise at this phase
A tiny worked example
Variable: electricity demand, period = 24 hours.
Now: hour 6 (morning peak). Past observation: electricity at hour 6 yesterday (24 hours ago).
Positive_align = 1.0 (perfect phase match).
Negative_deviation = 0.2 (yesterday was typical, few exceptions tracked).
Modulation_factor = 1.2 (learned weight for 24h cycle at phase 6).
Attention_score = 1.2 * 1.0 + 0.2 = 1.4. (This past observation gets weight 1.4, high.)
Now: hour 9. Past observation: electricity at hour 6 yesterday.
Positive_align = 0.1 (different phase, weak match).
Negative_deviation = 0.05 (rare hour-6 to hour-9 correlation).
Modulation_factor = 1.2.
Attention_score = 1.2 * 0.1 + 0.05 = 0.17. (This past observation gets weight 0.17, low.)
Same past observation; hour 6 data is trusted to predict hour 6 but ignored for hour 9.

The attention score enforces that each variable's forecast relies on observations at matching phases of its own cycle, not observations from other phases or other variables.

What can go wrong

What can go wrong

Period length mismeasured. If the model incorrectly estimates a variable's true cycle (e.g., thinking electricity is 12h when it is 24h), bucketing will group wrong observations together. The model will learn spurious patterns. A fix: use domain knowledge or a reliable period-detection method before bucketing.
Multiple simultaneous periods. Some variables have more than one period (electricity spikes every 24h AND every 7 days). PHAT groups by one primary period; it may miss secondary cycles. A partial fix: decompose the variable into separate sub-series first.
Data with evolving periods. If the true cycle length drifts over time (e.g., seasonal effects shift the dominant period), a static period estimate becomes stale. The model stops learning the current rhythm. A fix: retrain periodically or use adaptive period estimation.
Done right. When period lengths are stable, known in advance or estimated accurately, and each variable has a clear dominant cycle, PHAT's bucketing and positive-negative attention deliver strong, interpretable forecasts. The model respects the problem structure and avoids cross-period noise.
What a runnable demo should prove

What a runnable demo should prove

A minimal demo generates synthetic time series with known, different periods: one variable repeating every 10 time steps, another every 15. Then it trains both a standard neural forecasting model and PHAT on these series. It measures the forecast error on held-out test data for each variable separately. The demo should show that PHAT's error is lower on both variables, and that PHAT's internal scoring weights (the learned alignment scores) align highest when the phase matches the true period, whereas the standard model's scoring is noisy and does not respect the periods.

Forecast error per variable = mean absolute error on test set for electricity - mean absolute error on test set for temperature - mean absolute error on test set for water

The demo must show this unavoidably: PHAT's forecast error shrinks to roughly one-third of a standard model, especially on each variable's held-out future timestamps where the phase is locked to the cycle; a standard model fails because it has no built-in periodic structure.
