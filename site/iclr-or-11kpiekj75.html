Semantic Uncertainty Quantification of Hallucinations in LLMs

Use a tensor network to measure when an LLM is confident but wrong, bundling multiple generated answers to spot unreliable ones.

Paper explainersAll themesInterpretability

Large language models can fluently generate text that sounds credible but is completely made up (called hallucination). The same prompt produces wildly different answers each time, making it hard to know which ones to trust. This paper measures the model's actual confidence using a quantum physics trick that clusters similar answers together, then flags when a confident cluster is likely wrong.

Zero assumption version

The hallucination gap

When you ask an LLM a factual question, it generates text one word at a time, and each word has a probability (how likely the model thinks that word is correct). A beginner assumes high probability means the answer is reliable. But LLMs hallucinate: they confidently produce false information. Worse, asking the same question three times gives three different answers, yet they all have high per-word probabilities.

The naive fix is to look at the average probability of all the words in an answer. But this fails because hallucinated answers often have equally high word-probabilities as correct ones. The model is not confused during generation—it is equally confident when wrong.

The core problem. You get multiple answers with similar high probabilities, but some are hallucinations. How do you know which ones to trust without checking against the real world?

What it actually does

Sample the model many times on the same prompt.

Convert words to numeric lists (embeddings) that capture meaning.

Arrange embeddings in a network structure inspired by quantum physics, encoding relationships between answers.

What the paper changes

What the paper changes

Instead of looking at word probabilities one at a time, the paper measures how coherent the model's entire cluster of answers is. It changes the object from individual word scores to measuring how scattered or tight a group of similar answers are.

the object it moves  =  cluster coherence measure
The hidden quantity

Entropy of semantic clusters

measured quantity  =  cluster entropy

The paper measures a new quantity: how spread out or tight the model's answers are when grouped by meaning. When the model generates five answers and they all express the same core fact with different wording, the entropy is low (tight). When the five answers scatter across completely different meanings, entropy is high (scattered).

The paper estimates this by building a tensor network (a graph structure where each node and edge carries numerical weights). The network compares answer embeddings pairwise, measuring how much each answer agrees with others, then sums those agreements to get a cluster entropy score. High entropy in a semantic cluster signals hallucination because the model is internally incoherent.

Why it works

Why measuring cluster coherence catches hallucinations

A hallucinated answer is incoherent: when you generate it multiple times (with randomness), you get slightly different text each time. Correct answers coalesce—the model gravitates toward the same semantic content repeatedly. The network measures this coherence by checking whether many answer embeddings (numeric representations of meaning) cluster tightly.

Hallucinations are internally inconsistent. The model has no stable reason to produce that false answer. So if you group answers by meaning and find a group where word-probabilities are high but the answers scatter (say different things), the model is confident-but-incoherent. A scattered cluster means the model's path to that conclusion is unstable, a sign that it is likely fabricated.

The entropy formula

First in words:

cluster entropy = negative sum over semantic groups of (probability a group is chosen times log of probability), plus an extra term measuring how scattered the embeddings are within each group

Then the compact form:

H(C) = -sum_g p(g) * log(p(g)) + lambda * mean_distance(embeddings in g)

Every symbol:

H(C)total entropy of the semantic clusters
gone semantic group or cluster of answers
p(g)probability that a randomly sampled answer belongs to cluster g
log(p(g))logarithm of that probability, measuring surprise
lambdaweight controlling how much internal scatter matters
mean_distance(embeddings in g)average distance between answer embeddings within cluster g
Tiny worked example
Five answers to 'When was the moon landing?'
Cluster A (correct): three answers all saying '1969' -> p(A) = 0.6
Cluster B (hallucination): two answers saying '1974' and '1982' -> p(B) = 0.4
Term 1: -[0.6 * log(0.6) + 0.4 * log(0.4)] ≈ -[0.6 * (-0.51) + 0.4 * (-0.92)] = 0.306 + 0.368 = 0.674
Term 2 (scatter): Cluster A embeddings cluster tightly (low mean_distance). Cluster B embeddings are far apart (high mean_distance).
With lambda=0.5: Cluster A adds 0.5 * 0.2 = 0.1. Cluster B adds 0.5 * 0.6 = 0.3.
Total entropy for this answer set: 0.674 + 0.1 + 0.3 = 1.074. High entropy in the minority cluster (B) flags it as unreliable.

The formula penalizes clusters that are both frequent and internally scattered—a sign that the model is confidently generating incoherent outputs.

What can go wrong

What can go wrong

Ambiguous questions have legitimate semantic scatter. If a question has multiple correct answers (e.g. 'famous scientists'), the model will correctly generate different answers. High entropy looks like hallucination but is not. The method needs a domain-specific baseline for expected entropy.
Embedding quality matters. If the embeddings (numeric representations) do not capture semantic meaning well, the tensor network cannot cluster correctly. With bad embeddings, similar hallucinations fail to cluster and scatter across groups, appearing as multiple low-entropy clusters instead of one scattered high-entropy one.
Requires many samples. The method needs dozens of answer samples to compute reliable cluster entropy. For expensive models or real-time applications, repeated sampling is costly and slow.
Done right. Calibrate the entropy baseline on a small labeled set (correct vs. hallucinated answers) for your domain, use high-quality embeddings, and budget for multiple samples.
What a runnable demo should prove

What a runnable demo should prove

Build a simple script that: (1) uses an open-source LLM like LLaMA-2-7B; (2) asks ten factual questions (geography, history, math); (3) samples each question 20 times; (4) computes cluster entropy using a pre-built tensor network; (5) flags high-entropy clusters; (6) compares the model's answers against ground truth to verify that flagged clusters actually contain more hallucinations than unflagged ones.

hallucination_detection_AUROC = area under the curve of (entropy threshold vs. true positive rate / false positive rate)

The demo must show that looking at cluster coherence (how scattered the answers are) catches hallucinations that single word probabilities miss, because a hallucinated answer looks fluent word-by-word but falls apart when you compare it to other attempts at the same question.
