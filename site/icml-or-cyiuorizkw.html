Zero assumption version

Vision-Language models miss robot motion

Today's robots use vision-language models (a machine learning system trained to understand both pictures and text from the internet). These models are good at recognizing objects and understanding scenes, but they were never trained on real robot motion—they have never watched an arm reach toward a cup, or felt which way a gripper needs to rotate.

A beginner might try: just add action labels (the commands sent to the robot) and train the model to predict what to do next. But actions alone do not capture what the robot actually feels—the angles of joints, speeds, forces, accelerations. A model trained only on predicting the next action will learn features tuned for that prediction task, not features that capture the robot's physical state.

The result: the model misses patterns in how robot states flow from one moment to the next. It wastes capacity on features the robot does not need for motion control.

The paper's move in one sentence. Use distances between robot states as weights to guide which similarities matter, so the model learns to highlight features that reflect how the robot actually moves—because features that track state distance are exactly the ones that predict what actions the robot should take next.

The algorithm as a flow

What it actually does

Encode the scene

Feed an image and text to the vision-language model; it outputs a feature vector (a list of numbers representing what it sees).

Compute state distances

Measure how far apart two consecutive robot states are: the angles differ by how much, speeds differ by how much, gripper opening differs by how much. Sum these up into one distance number.

Reweight the similarity scores

Compare the feature vectors for these two moments. Nearby states should have similar features; distant states should have different features. Scale the loss based on the state distance: the more distant the states, the stronger the penalty for feature similarity, because distant robot states demand different motor commands and should therefore activate different features.

Update the adapter

Use the loss to nudge the feature vectors; the training algorithm computes which way to adjust each number to shrink the error. The model learns which features matter by watching which ones predict state distance.

Train end-to-end

Run this auxiliary loss alongside the action prediction loss. Both guide the same features. The model learns motion-relevant structure without retraining the whole vision-language model.

What the paper changes

The one thing the paper changes

The paper modifies the representation of scenes in the vision-language model—the intermediate list of numbers that the model computes from an image before predicting actions. It retrains these representations using a contrastive learning setup (comparing pairs of moments to see which are similar) weighted by actual robot state distances.

The hidden quantity

State distance awareness

measured quantity  =  robot state distance alignment

The paper measures one key quantity: how well do the features of two scenes reflect the distance between the robot states in those scenes? A good representation should make nearby states similar and distant states different, because that is how control works—a small change in state should demand a small change in action, while a large change in state should demand a different strategy.

The paper estimates this by computing the actual distance between robot joint angles, speeds, and gripper states at each timestep, then checking whether the learned features respect that distance (nearby states have similar features, distant states have different features).

Why it works

Why reweighting by state distance works

A standard contrastive loss pushes similar examples together and pulls different examples apart. The paper's insight: similarity should not be binary (same or different). Instead, weight it by how far apart the robot states actually are. If two moments are almost identical (joint angles differ by 0.1 degree), the features should be very similar—pull them close with a strong force. If two moments are very different (joint angles differ by 45 degrees), the features can be far apart—a weak pull or no pull at all.

This teaches the feature space a useful shape: it naturally separates states by their control relevance. An arm reaching from 30° to 31° needs a tiny adjustment (similar states, similar features), while an arm jumping from 30° to 60° needs a new strategy (distant states, different features). The model learns this structure without any explicit action labels on state distances—just by trying to make the features match the state distances.

Why this works: action prediction is easiest when features encode state distances, because actions are tiny continuous nudges to state. By training features to reflect state distance, the model automatically learns the structure that action prediction needs.

The weighted contrastive formula

First in words:

The loss pulls two feature vectors together when their robot states are close, and pulls them apart when their robot states are far. The strength of the pull is scaled by how different the states are.

Then the compact form:

L = -log( exp(sim(f_i, f_j) / tau) / sum_k [ exp(sim(f_i, f_k) / tau) * weight_ik ] )

Every symbol:

f_ifeature vector for moment i
f_jfeature vector for moment j (nearby in robot state)
sim(f_i, f_j)cosine similarity between two feature vectors
tautemperature: a constant that controls softness (0.1 typical)
weight_ik1 minus state distance between moments i and k (normalized)
sum_ksum over all other moments in the batch
A tiny worked example
Suppose three moments: A (joint=30°), B (joint=31°), C (joint=60°).
State distance AB = 1°, AC = 30°.
Similarity: sim(f_A, f_B) = 0.95 (features are close).
Similarity: sim(f_A, f_C) = 0.45 (features are far).
Weight AB = 1 - (1/30) = 0.97 (very similar states, weight stays high).
Weight AC = 1 - (30/30) = 0.0 (very different states, weight drops to zero).
Loss pulls (A,B) together hard (weight 0.97), does not pull (A,C) at all (weight 0).
After training, features of state 30° and 31° move closer, features of state 30° and 60° stay far apart.
Result: feature space respects robot state distance.

The weights turn the contrastive loss from binary (same or different) into continuous (how different), so state-adjacent moments stay feature-adjacent and distant states separate.

What can go wrong

What can go wrong

Weak state signals. If the robot states are not measured accurately (noisy joint encoders, drifting sensor calibration), the distances between states are unreliable. The contrastive loss will then teach the model to ignore true robotic patterns. Measure state distance with low noise first.
Imbalanced state patterns. If the training data clusters heavily in one part of the robot's workspace (e.g., all tasks near the table), the model learns features that work well for that region but fail elsewhere. Collect diverse state coverage or weight the loss to balance regions.
Decay schedule matters. The paper gradually shrinks the contrastive loss weight from 1.0 to 0 over training. If the shrink is too fast, the model abandons state-aware features before action prediction is stable. If too slow, state features override action prediction. Tune the schedule per domain.
Done right. Pair clean proprioceptive state measurements with stable sensor calibration, ensure training data spans the robot's full workspace, and tune the contrastive loss decay to balance state awareness with action accuracy.
What a runnable demo should prove

What a runnable demo should prove

Build a small robot manipulation task: a simulated arm picking one object from a table. Collect 20 episodes of teleoperated demonstrations with logged images, actions, and joint angles at each frame. Train two vision-language-based action predictors: one with action prediction loss only, one with action loss plus the state-aware contrastive loss. Test both on held-out episodes (new objects or new configurations). Measure: does the state-aware model work better on new visual scenarios (because features tied to state distance respond to motion patterns, which transfer across objects, while features fit to a narrow dataset fail on new objects)? Does it need fewer demonstrations to reach the same success rate (because state distances provide richer supervision than action labels alone)?

The demo should show: fewer demonstrations needed for good performance, or better success rate on objects and shapes not in the training data, because the state signal teaches motion structure that transfers.
