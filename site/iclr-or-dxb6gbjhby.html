LearnPruner: Rethinking Attention-based Token Pruning in Vision Language Models

Drop unimportant image patches selectively to speed up vision-language models while keeping the same answer quality.

Paper explainersAll themesEfficiency & Systems

Vision-language models (models that read both images and text) can answer detailed questions about photos but are slow because they process every pixel in the image. LearnPruner drops the junk pixels early and keeps only the useful ones, speeding up the model 3 times over while preserving the same answer quality.

Zero assumption version

Images are long sequences, models are slow

A vision-language model reads an image by breaking it into small patches (think: cutting the photo into 100 tiny squares), then processes each square one at a time. With 100 patches, and a text prompt on top, the model has to do expensive scoring calculations (where it looks at which patches relate to the text) on all 100 patches even if only 5 matter for answering the question.

A naive approach: use attention scores (the model's own estimate of which patches matter) to drop low-scoring patches. But this doesn't work well. The vision part of the model (vision encoder) has a problem: it pays too much attention to a catch-all patch and ignores the actual foreground objects in the photo. The text part (language model) seems promising but it too has hidden biases—it favors early patches just because they come first, not because they matter. Both guides are broken.

In one sentence. Prune image patches early using a learned gate, then prune again in the language model's middle layer, because the language model has learned what patches actually help answer questions while the vision encoder gets confused.

The algorithm as a flow

What it actually does

Stage 1: Vision encoder

Run image through vision encoder (standard model part), get 100 patches.

Stage 2: Learnable gate

Train a small gate module to score each patch, drop 70% that score low.

Stage 3: Language model

Pass remaining 30 patches through language model's first few layers.

Stage 4: Middle attention prune

At the language model's middle layer, look at which patches the model attends to most, drop the rest.

Stage 5: Output

Remaining 5 patches feed into final layers, answer the question at full speed.

What the paper changes

What the method changes

The paper changes how image patches are selected—instead of relying on one broken attention signal, it uses two independent checks at different points in the pipeline. First a learned gate prunes aggressively. Second, the language model's middle layers prune again based on their own attention.

the object it moves  =  which patches to keep
The hidden quantity

The hidden quantity: Which patches matter

measured quantity  =  patch importance (learned + language attention)

The paper measures two kinds of importance. First: a learned importance score trained on examples (via a small learnable module after the vision encoder). Second: the attention weight the language model assigns to each patch in its middle layers. The second signal is better because language models are trained on text-to-image pairs and actually learn which visual details answer questions.

The paper discovers that vision encoders have an attention sink: they lock onto one special patch and ignore everything else. But language models, when looking at image patches in their middle layers, don't suffer from this bias—they genuinely look at whatever patches matter for the current question.

Why it works

Why it works: Two stages beat one

The pipeline works because it uses two different, complementary views. The vision encoder is fast but blind (it defaults to a catch-all patch). A learnable gate trained on examples can learn patterns of what matters in images, and it prunes aggressively—dropping 70 patches. This cuts memory cost early.

The language model is smarter because it was trained on actual image-text pairs where it learned to look at patches that help answer questions. In the language model's middle layers, the attention weights genuinely align with task relevance. A second pruning pass here drops redundancy that slipped through the first stage. By using both signals, the method avoids the failure modes of either alone.

The pruning rule

First in words:

importance_score = learned_gate_output × language_model_attention

Then the compact form:

score_i = gate(patch_i) * attention_llm(patch_i, query)

Every symbol:

score_iimportance of patch i
gate(patch_i)learnable pruning module's output for patch i (0 to 1)
attention_llm(patch_i, query)how much the language model attends to patch i for the current question
querythe text question being asked
A tiny worked example
Patch 1 (dog face): gate score 0.9, LLM attention 0.8 → combined 0.72 → keep
Patch 2 (background sky): gate score 0.3, LLM attention 0.1 → combined 0.03 → drop
Patch 3 (dog tail): gate score 0.7, LLM attention 0.6 → combined 0.42 → keep
Patches with combined score above threshold are retained; below threshold are discarded.

Both signals must agree: a patch is only kept if the learned gate approves AND the language model attends to it.

What can go wrong

What can go wrong

If the learnable gate is undertrained. If the gate module does not see enough examples during training, it will drop important patches. The model needs labeled data saying which patches matter for the task.
If the language model's middle layers are not task-aligned. Some models may have learned to look at early patches more just because they come first, rather than looking at what patches actually matter. The pruning loses information if middle-layer attention does not correlate with actual relevance.
If first-stage pruning is too aggressive. If the learnable gate drops important patches too early, the language model cannot recover that information later. The two stages must be calibrated so the gate only removes obvious junk.
Done right. Train the learnable gate on a representative dataset for the target task, inspect language model attention patterns before committing to thresholds, and validate on held-out examples that the two stages complement each other (first stage catches obvious junk, second stage filters real redundancy).
What a runnable demo should prove

What a runnable demo should prove

Build a simple vision-language model on a small dataset (e.g., visual question answering on 100 images with 5 questions each). Train LearnPruner's learnable gate on 80 images, then measure on 20 held-out images. Report the accuracy and latency with 100 patches vs. with LearnPruner's pruning.

accuracy_ratio = accuracy_with_pruning / accuracy_without_pruning

The demo should show that you keep 95% of accuracy while using only 5% of patches, because the two pruning stages eliminate redundancy without losing the visual details needed to answer correctly.
