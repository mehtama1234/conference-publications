Hunt Instead of Wait: Evaluating Deep Data Research on Large Language Models

This paper evaluates whether an agent can open a database, decide what to inspect, and discover useful findings without being handed a narrow question.

Paper explainersAll themesAgents & Tool Use

Many benchmarks ask an agent to answer a stated question. Real data work often starts earlier: open the data, decide what is worth checking, and then discover the questions that matter. This paper studies that earlier stage and treats it as a separate form of agent capability.

Zero assumption version

Answering a stated question is easier than deciding what to investigate in the first place

A standard benchmark usually gives the agent a clear prompt and asks for a correct answer. That setup tests execution once the goal is already known. It does not test whether the agent can inspect raw data, notice promising directions, and choose what to examine next.

Data analysis is a useful setting for this harder test because real analysts often begin with tables and logs rather than with a single narrow question. The paper asks how to evaluate an agent that must decide where to look, what to compare, and which findings deserve follow-up.

The idea in one sentence. Benchmark open-ended data investigation directly, because a capable agent should not only execute a stated task but also decide what is worth exploring.

The algorithm as a flow

What it actually does

Give the agent raw data access

Start from databases or tables without supplying one narrow analysis question.

Let the agent choose exploration steps

Allow it to inspect columns, compare slices of data, and pose follow-up checks based on what it finds so that its next move depends on evidence from the previous move.

Record discovered findings

Capture the insights and evidence the agent produces during its exploration.

Evaluate with a checklist

Score whether the important discoveries were found so that open-ended exploration remains measurable.

Compare agents on investigatory behavior

Use the benchmark to separate plain task execution from autonomous discovery.

What the paper changes

What the paper changes

The paper changes the benchmark target. Instead of asking only whether the agent can answer a question, it asks whether the agent can decide which questions deserve investigation inside raw data.

the object it moves  =  the benchmarked definition of agent competence
The hidden quantity

The hidden quantity: investigatory intelligence

measured quantity  =  how well the agent chooses worthwhile directions before a final question is fixed

The paper distinguishes execution from investigation. Execution means carrying out a known task once the goal is set. Investigation means choosing promising directions when the goal is still under discovery.

This hidden quantity matters because a system can follow instructions well and still fail at open-ended analysis. Without a benchmark for investigatory intelligence, progress can look stronger than it really is on real data work, since fixed-question tests hide the earlier choice of what to inspect.

Why it works

Why this benchmark reveals something new

The benchmark reveals something new because it removes the narrow task prompt that normally anchors the agent's search. Once that anchor is removed, the system must supply its own exploration strategy.

The checklist-based evaluation keeps the task measurable because open-ended analysis still needs a way to compare runs. By defining important findings in advance, the benchmark can score discovery quality without forcing every agent to follow the same exploration path.

Math after the picture

The core equation

First in words:

Investigatory score grows when the agent finds more key insights and wastes fewer exploration steps on dead ends.

Then the compact form:

investigatory_score = insight_coverage - dead_end_cost

Every symbol:

investigatory_scorehow well the agent performs on open-ended data investigation
insight_coveragehow many of the benchmark's important findings the agent discovers
dead_end_costhow much exploration effort is spent on unhelpful directions
A tiny worked example
Suppose the benchmark has 10 important findings and the agent discovers 7, so insight_coverage is 7.
Suppose the run also spends effort on 2 major dead ends, so dead_end_cost is 2.
Then investigatory_score is 7 minus 2, which is 5.
A second agent that also finds 7 insights but wastes no major detours would score 7 instead.
The example shows why exploration quality matters because finding insights is only part of the job.

This simple difference is only a teaching view. The benchmark's point is that autonomous discovery and disciplined search both matter.

What can go wrong

What can go wrong

The agent chases noisy patterns. Open-ended exploration can drift toward eye-catching but unimportant differences, so the run burns time without producing a key benchmark finding.
The checklist is too narrow. If the benchmark checklist omits a genuinely valuable discovery, an agent may do useful work that the score does not recognize.
The agent never commits to a direction. A system that keeps sampling many views of the data without deepening any one line of inquiry can appear active while making little progress.
Done right. The setup works when the benchmark rewards real discoveries and the agent is forced to balance breadth of exploration with enough depth to verify an insight.
What a runnable demo should prove

What a runnable demo should prove

Build a small benchmark with raw databases from sales, health, or operations domains. For each database, define a checklist of high-value findings that a good analyst should uncover. Let agents inspect the data freely, record their probes and conclusions, and then score both discovered findings and wasted exploratory detours.

The demo proves the paper's point if agents that look strong on fixed-question tasks still miss many checklist findings here, because the open-ended setting requires a separate capability: choosing what to investigate.

discovery_gain = insight_coverage(open_ended_agent) - insight_coverage(prompt_bound_agent)

A convincing result should show one case where an agent answers prompted questions well but fails to notice the main story when no question is supplied.
