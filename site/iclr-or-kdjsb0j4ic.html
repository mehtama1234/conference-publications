Structure Learning from Time-Series Data with Lag-Agnostic Structural Prior

Learn which variables drive later changes in other variables while using prior knowledge that says a connection exists somewhere in time even when the exact delay is unknown.

Paper explainersAll themesOther

Time-series structure learning tries to recover a directed graph from sequences of measurements. Each edge answers a concrete question: if one variable changes now, does another variable tend to change later after accounting for the rest of the system? In practice, people often know a coarse fact before seeing the data, such as gene A affects gene B or sensor X cannot affect actuator Y, but they do not know the exact delay. Most methods cannot use that kind of statement cleanly because they expect the delay to be named in advance. This paper builds a way to inject a lag-agnostic prior, meaning a prior statement about whether two variables can be connected at any delay, while still learning the fine delay-specific graph from data. That matters because the prior narrows the search to graphs that respect known science, and the model still discovers which delays are actually supported by the measurements.

Zero assumption version

Why coarse prior knowledge is hard to use in time-delay graphs

A time-series graph is finer than an ordinary causal graph because it must say not only who affects whom, but also after how many time steps the effect appears. If blood pressure affects heart rate two seconds later, that is a different edge from an effect that appears ten seconds later.

Domain experts rarely know the delay that precisely. They may know that one variable can influence another somewhere in the allowed delay window, or that a pair is impossible at any delay. Existing continuous graph-learning methods usually encode rules on specific delay edges. That means they cannot directly express a statement such as 'A can affect B at some delay, but we do not know which one.'

The paper's move. Translate a coarse prior about a variable pair into constraints on the whole set of delay edges for that pair, so optimization respects the intended meaning of the prior from start to finish.

What the paper changes

What the paper changes

The paper changes the form of prior knowledge that the learner can accept. Instead of requiring a rule on each single delay edge, it allows a rule on a variable pair across all delays and then enforces that rule during optimization, because many real prior statements are about whether a pair can connect at all rather than about one named delay.

The hidden quantity

The hidden quantity

measured quantity  =  pair-level causal possibility across delays

The hidden quantity is not one edge weight at one delay. It is the truth value of a broader statement: does this ordered pair have any real delayed connection in the allowed window? That quantity matters because many expert rules are stated at exactly that level.

Once that pair-level statement is enforced, the learner still has to decide which delay edge or edges carry the effect. The paper makes the pair-level statement explicit, because otherwise the solver can drift into delay patterns that fit the data locally but contradict the known science about which pairs should or should not connect.

Why it works

Why pair-level constraints recover finer delay edges

A delay-aware graph learner balances many competing edge choices. Without prior knowledge, a weak but spurious edge can survive simply because several delay patterns explain the data almost equally well. A pair-level prior removes many of those patterns before the final fit, because it rules out entire families of edges for forbidden pairs and requires at least one edge for required pairs.

That does more than shrink the search. It also keeps the meaning of the expert rule intact, because the solver must treat all candidate delays for a pair as one logical unit when checking the prior. If the prior says a pair is impossible, every delay edge for that pair must be pushed away. If the prior says a pair exists somewhere, the solver must keep at least one delay edge alive and then decide which delay best explains the data.

The added constraints make optimization harder because several delay edges become linked. The paper therefore uses a data-driven initialization, so the search starts near a graph that already reflects the observed time relationships. That matters because a good start reduces the chance of getting stuck in a poor local solution created by the new constraints.

Math after the picture

Constraint over a delay set

First in words:

A pair-level rule does not act on one delay edge. It acts on the whole set of candidate delays for that ordered pair.

Then the compact form:

if pair(A,B) is required, then sum_over_lags edge(A,B,lag) must be positive; if pair(A,B) is forbidden, then every edge(A,B,lag) must be zero

Every symbol:

pair(A,B)the coarse prior statement about whether variable A can affect variable B at any allowed delay
edge(A,B,lag)the learned strength of the directed edge from A to B at one specific delay
sum_over_lagsthe total support across all candidate delays for that pair
A tiny worked example
Suppose the allowed delays are one, two, and three steps.
An expert says variable A affects variable B somewhere in that window.
The learner is free to place weight on delay one, two, or three, but it cannot drive all three to zero because that would violate the pair rule.
If the data show the strongest improvement in fit at delay two, the optimizer can keep the delay-two edge and shrink the others.
The final graph then says the pair relation is present and the best supported delay is two steps.

The important shift is from edge-by-edge rules to a rule on the collection of edges for one ordered pair.

What can go wrong

What can go wrong

The prior itself can be wrong. If an expert marks a true pair as impossible or a false pair as required, the learner will honor that mistake because the constraints are built to preserve the prior's meaning.
Initialization still matters. The new constraints couple many edge choices together, so a poor start can still trap optimization in a poor local solution even when the prior is correct.
Short or noisy sequences limit delay resolution. Even when the pair-level rule is right, the data may not separate nearby delays cleanly because several delay edges can explain the same weak temporal pattern.
Done right. A sound pair prior, enough temporal signal, and a strong initialization work together because the prior narrows the valid pair set and the data then choose the best delay within that set.
What a runnable demo should prove

What a runnable demo should prove

Build a toy system with four variables and a small delay window. Generate sequences from a known delayed graph, then provide coarse prior statements for some ordered pairs while hiding the exact delays. Compare three runs: no prior, correct pair-level prior, and incorrect pair-level prior. The demo should show whether the new method recovers the true delays more often when the pair prior is correct and whether errors follow the prior when the pair prior is wrong.
