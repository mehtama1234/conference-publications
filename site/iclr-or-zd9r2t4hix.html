Counterfactual Explanations via Label-Conditional Gaussian Mixture VAE

Generate stable counterfactual explanations by interpolating through learned class-specific centroids, so proposed changes don't shake apart when the model is retrained.

Paper explainersAll themesInterpretability

When an algorithm rejects your loan application, you want to know what would change its decision. A counterfactual explanation (a suggested path to acceptance) should be stable: the same path should still work if the bank retrains its classifier, and tiny changes to your data should not flip the answer. This paper solves that with a two-part trick. First, train a special autoencoder that learns a latent blueprint for each class (a collection of central prototypes). Then, explain decisions by drawing a smooth path in that latent space from the input to the target class blueprint. Because the blueprint is fixed and built into the autoencoder, not into the live classifier, the paths stay stable.

Zero assumption version

Counterfactual explanations are fragile

Imagine a loan rejection. You ask the bank: what if I earned 10 percent more? Their algorithm says, you would be approved. But six months later, after retraining on new data, you ask again. Same situation, but now the system says no. Your counterfactual explanation broke because the model drifted.

A naive method searches for changes that fool a specific classifier, like sketching a path in the original data space (income, credit score, age) toward rejection-to-approval. The problem: that path is glued to one classifier. When the classifier shifts—weights adjust, decision boundaries move—the path no longer lands on the approved side. It was never a stable feature of the data; it was an artifact of this one model's quirks.

The insight. Don't search for changes in the original data space. Instead, learn the stable structure of each class first (where all the approval cases cluster in concept-space), then find a path from your input to that fixed blueprint.

The algorithm as a flow

What it actually does

Step 1: Train the autoencoder

Teach a model (the L-GMVAE) to compress data to a small space (latent space) and split each class into K clusters, each with its own center point.

Step 2: Extract the blueprint

For any target class (e.g., approval), grab all K learned center points. These are the prototypical cases.

Step 3: Encode the input

Take a rejection case (your loan denial), compress it down to a single point in latent space.

Step 4: Interpolate a path

Draw a straight line from your encoded point toward each blueprint center. Pause at steps along the way.

Step 5: Decode and apply constraints

Decompress each point back to real data (income, credit score) and check if any path point satisfies user rules (e.g., income can only increase).

What the paper changes

What the paper changes

The paper shifts the search target. Instead of optimizing directly against the live classifier (which drifts), it optimizes against a learned latent blueprint: a fixed set of class-specific center points baked into the autoencoder.

the object it moves  =  the search target (from live classifier to frozen blueprint)
The hidden quantity

The hidden quantity: Latent centroid stability

measured quantity  =  latent centroid stability

Every counterfactual method tacitly measures how well the explanation points hold up under model retraining. This paper makes it explicit by learning from the data itself, not from any single classifier's decisions: the latent centroid for each class is a fixed point built from the training data, independent of the classifier's weights. Because the centroid is a learned constant from the data's structure, not from the classifier, it stays put when the classifier retrains.

The autoencoder estimates this quantity by training on the classifier's predictions, capturing where inputs cluster in latent space, then locking those cluster centers in place. A path to a fixed center is stable by construction: when a new classifier retrains on fresh data, the center does not move (only new classifiers might disagree on whether the path point is valid).

Why it works

Why it works: Fixed blueprints beat live classifiers

Why this method stays stable when the classifier is retrained: it stops chasing the classifier. Instead, it learns a fixed map of where each class lives in concept space (the latent space of the autoencoder). The classifier's job is just to evaluate points along the path; the path itself is defined by the autoencoder's learned clusters and never changes.

When a new classifier is trained on new data, its decision boundary shifts, but the autoencoder's learned blueprints do not. A path that landed on an approved region before might land on a rejected region now, but the path itself stays in the same geometric spot. Any path points that the new classifier also approves came from stable properties of the data, not from the old model's quirks or accidents.

Diversity follows automatically: because each class has K learned centers (prototypes), there are K different paths to explore, each with a different tradeoff between closeness and how realistic it is. A point near the input is closer but more similar to ordinary cases. A point near the far centroid is farther but drawn from the heart of the class.

The interpolation and reconstruction

First in words:

For input x with latent code z_x, a counterfactual path to centroid z_c is defined by stepping from z_x toward z_c. At each step tau (a progress fraction from 0 to 1), the latent point is a weighted blend: (1 minus tau) times z_x plus tau times z_c. The decoder then reconstructs this blended latent point back into data space. Actionability constraints are checked via a differentiable function g on the decoded point.

Then the compact form:

z_path(tau) = (1 - tau) * z_x + tau * z_c for tau in [0, 1]

Every symbol:

z_xlatent encoding of the input
z_clearned latent centroid for target class c
tauprogress parameter, from 0 (at input) to 1 (at centroid)
z_path(tau)latent point at step tau along the path
Decode(z_path(tau))reconstructed data at step tau
A tiny worked example
Input loan case: income $50k, score 600 -> autoencoder encodes to z_x = [0.1, 0.3] in latent space.
Learned approval centroid: z_c = [0.8, 0.9] (represents typical approved loans).
At tau=0: z_path = [0.1, 0.3] (the original case).
At tau=0.5: z_path = (1-0.5)*[0.1,0.3] + 0.5*[0.8,0.9] = [0.45, 0.6] (halfway).
At tau=1.0: z_path = [0.8, 0.9] (the centroid). Decoder reconstructs this as income $75k, score 750.
Check actionability: income increase from $50k to $75k is allowed. Then check if the new classifier approves.

The path is a straight line in latent space, which makes it simple to search and stable to model retraining because it targets a fixed blueprint, not the moving classifier.

What can go wrong

What can go wrong

Autoencoder overfits to one classifier. If the autoencoder is trained on predictions from a weak or biased classifier, the learned blueprints inherit that bias and the paths will converge to unrealistic regions of the data because the autoencoder learned the wrong centroids in the first place. The quality of the explanation depends directly on the quality of the data and the initial classifier used to train it.
Actionability constraints are violated on the path. Not every point on the interpolated path satisfies the user's rules (e.g., income can only increase, age cannot change). The method checks constraints at each step, but if no step satisfies all constraints, no valid explanation is found.
The new classifier still rejects the path endpoint. The blueprint is stable, but the new classifier's decision boundary may not approve it. The path targets a stable region of data, not a guaranteed decision region.
Done right. Train the autoencoder on a large, representative dataset with a well-trained initial classifier. Paths will be stable because they follow the learned structure of the data, not the model's temporary quirks.
What a runnable demo should prove

What a runnable demo should prove

Build a toy classifier on a simple dataset (e.g., loan approvals with three features: income, credit score, age). Train an L-GMVAE on the same data. For a rejected case, generate a LAPACE path to an approval centroid. Then retrain the classifier on a slightly perturbed dataset (add noise to 10% of training labels). Regenerate the path using the same input and autoencoder. Measure how many points on the original path the new classifier also approves. Compare this to a naive gradient-based counterfactual method, which will lose most of its path points on the retrained classifier.

Robustness under retraining = (number of original path points still approved by new classifier) / (total points on path)

The demo makes clear why: LAPACE paths point to fixed learned centers. When the classifier retrains, the centers stay put. Naive paths chase the live decision boundary, which moves.
