Model Predictive Diffuser for Offline Control

Combine a task planner and a physics model during diffusion sampling to generate trajectories that both achieve goals and obey the laws of physics.

Paper explainersAll themesRobotics & Control

Diffusion models can generate diverse motion sequences, but they often propose moves that are physically impossible for the robot. This paper proposes Model Predictive Diffuser (MPDiffuser), which interleaves corrections from two sources during sampling: a planner that enforces goals, and a dynamics model that enforces physics. The result is trajectories that work in the real world.

Zero assumption version

Diffusion models ignore the physics of moving robots

Diffusion models (tools that build images or motion sequences by starting with noise and gradually denoising) are excellent at learning diverse, creative behaviors from recorded data. But when a robot uses one to plan a motion sequence, the model often suggests moves that the robot physically cannot execute: a quadruped lifting two legs at once when it only has static balance on two, or moving faster than its motors allow, because the model learns correlation in the data without understanding the causal constraints that make certain combinations impossible.

A beginner might train a diffusion model on recordings of successful robot behavior and hope it learns the hidden rules. But the model only sees correlation—which states and actions appear together—not causation. It does not understand why certain combinations are forbidden by physics. When sampling, it produces moves that match the dataset's patterns without obeying the robot's mechanical limits, making them unreliable for real deployment.

In one sentence. Interleave corrections from a goal-focused planner and a physics-focused dynamics model while denoising, so both aims guide each step.

The algorithm as a flow

What it actually does

Start with random noise

Initialize a random sequence of states (position, velocity) and actions (motor commands).

Apply the planner

Denoise the sequence toward task objectives, pulling states and actions toward patterns that achieve high rewards in the dataset.

Apply the dynamics model

Adjust each state given its preceding action, pushing the state toward what physics predicts, independent of the task.

Repeat alternation

Alternate between planner and dynamics for many steps, gradually refining the sequence.

Rank and select

Score all sampled trajectories and pick the one best satisfying reward, cost, and safety constraints.

What the paper changes

What changes: the denoising process

Standard diffusion samples by denoising with one model. MPDiffuser changes the denoising process itself, inserting two different models into the loop. At each reverse step, the planner denoises first (moving toward rewards), then the dynamics model refines the result (moving toward feasible physics). This dual correction at every step is the core change.

the object it moves  =  the denoising loop
The hidden quantity

The hidden quantity: feasible state-action alignment

measured quantity  =  feasibility gap

The feasibility gap measures how far each proposed state sits from what the physics of the robot would produce, given the action just taken. If an action is 'move forward at speed 1' but the state claims the robot moved backward at speed 2, the gap is large. If the action and resulting state obey the physics equations, the gap is zero.

The dynamics diffusion model estimates this gap by learning to predict which states are consistent with prior actions. During sampling, it pulls states toward the feasible manifold—the set of all state-action pairs that could actually happen. The planner separately guides toward rewards, so the interleaving lets both measurements steer the trajectory without one overriding the other.

Why it works

Why alternating plan and physics works

During denoising, the planner pulls the trajectory toward high-reward patterns in the training data. Alone, this creates motions that match dataset correlations but ignore physics rules. The dynamics model independently learned to predict the next state from the current state and action, so it embeds the robot's physical laws. When applied after the planner, it projects the proposed state back onto the feasible manifold—the set of states that could actually follow from the action.

By alternating, neither force dominates. The planner prevents the trajectory from drifting into boring or constraint-violating actions; the dynamics model prevents it from drifting into physical impossibilities. The result is a trajectory that pursues goals while obeying physics. Because each module is trained independently and combined only when the model answers a new question (not during training), the dynamics model can learn from diverse, lower-quality data that the planner ignores, making the system handle mismatched data better.

Math after the picture

The optimization objective

First in words:

minimize negative log probability of the feasible trajectory, subject to a divergence penalty keeping the planner close to the dataset distribution

Then the compact form:

min_q E_q[-log p_dyn(tau|x_0)] s.t. KL(q||p_pl) <= epsilon

Every symbol:

qthe trajectory distribution we are sampling from
p_dynthe dynamics model's probability of states given actions
taua full state-action trajectory
x_0the initial state
p_plthe planner model's distribution from training data
KL(q||p_pl)divergence (distance) from q to the planner's learned distribution
epsilonmaximum allowed distance to maintain task intent
A tiny worked example
Suppose at step t the planner denoises a state to (position=10, velocity=5).
The action just applied was 'accelerate forward by 2 units per step'.
The dynamics model predicts that action would move the robot to (position=10.5, velocity=6.5) due to physics.
The proposed state (10, 5) is far from the prediction, so the dynamics model pulls it toward (10.5, 6.5).
This corrected state is the new input to the next planner step.
The penalty for drifting from the patterns the planner learned in the dataset prevents the dynamics model from overriding the task goal entirely.

The interleaved sampling is the relaxation of this objective: alternating nudge steps from planner and dynamics, each pushing the trajectory in its direction, until convergence.

What can go wrong

What can go wrong

Overly constraining dynamics may block good goals. If the dynamics model is too strict or the interaction step is weighted too heavily, it can prevent the trajectory from reaching states that would achieve high rewards, even if those states are theoretically feasible. The KL constraint in the math prevents this by keeping the planner's guidance strong.
Heterogeneous training data confuses the planner. If the dataset has trajectories from different robot versions or environments, the planner conflates them. The dynamics model, trained independently, can handle diversity better because it only models state prediction, not task intent. Separating the models helps, but results degrade if the data is severely mismatched, because the planner's reward patterns become ambiguous when the task context shifts between data sources.
Ranking module can select infeasible trajectories by accident. If the ranking function only scores on task reward and ignores feasibility, it may pick trajectories that optimize the metric but still violate physics. The paper adds learned cost and constraint functions to the ranking to catch this, but miscalibrated ranking costs can still fail.
Done right: tuning the alternation and constraints. When the KL constraint is well-set and the dynamics model is well-trained, the interleaving naturally balances both aims without explicit manual tuning. The compositional design allows swapping the planner, dynamics model, or ranking function independently, making failure diagnosis straightforward because each module's failure is isolated—if trajectories are infeasible, the dynamics model is weak; if they miss goals, the planner is weak; if poor selections are made, the ranking is miscalibrated.
What a runnable demo should prove

What a runnable demo should prove

Build a toy continuous-control task (e.g., a simulated 2D reacher arm) where feasibility is obvious and violations are visible. Train a diffusion planner on offline data of reaching motions. Train a dynamics model on the same data. Sample trajectories using: (1) planner alone, (2) planner with random dynamics corrections, (3) MPDiffuser alternating updates. For each, measure task success (does it reach the target?) and feasibility (do the proposed states match physics predictions?). Visualize the 20 sampled trajectories in state space, overlaying the feasible region. The demo succeeds if MPDiffuser trajectories cluster in the feasible region while maintaining near-planner-level task performance.

success_rate = (trajectories_reaching_goal AND states_within_feasible_margin) / total_trajectories
