FASTer: Learnable Action Tokenizer for Faster Robot Learning

A robot learns actions faster by encoding action sequences as compressed images instead of long symbol lists.

Paper explainersAll themesRobotics & Control

Robots need to learn what sequence of movements will achieve a goal. Today's best robot learners read an image, understand language, and predict the next action—but they struggle with a hidden tradeoff: pack actions tightly for speed, or keep them clear for accuracy. This paper shows how to achieve both by treating action sequences like images.

Zero assumption version

Why today's robot learners are stuck

When a robot learns to pick up a cup, it watches the scene (images), listens to instructions (language), and predicts what to do next—predicting one action at a time, like spelling out a sentence one letter at a time. Each action is encoded as a short symbol, a token, drawn from a fixed vocabulary (maybe 512 different movement options).

The tradeoff bites here: if the vocabulary is small (say, 64 tokens), each one stands for a larger chunk of movement—decoding is fast, but the robot loses detail about subtle motions. If the vocabulary is huge (say, 2048 tokens), each one is precise—the motion is clear, but the model has to predict more tokens per action sequence, and inference (answering the robot's question about what to do) slows down. No way to win both.

The tradeoff. Small vocabulary is fast but blurry; large vocabulary is precise but slow.

The algorithm as a flow

What it actually does

Encode the action chunk

Take a sequence of robot movements and paint them as one grayscale image.

Compress via a learned encoder

A small neural network squeezes the image down to very few numbers.

Tokenize the compressed form

Round those numbers to discrete token IDs (the way a photo rounds pixel colors to 256 levels).

Predict and decode one token at a time

The robot's language model predicts one token per step, then decodes each back to movement.

Execute block-wise

Every few predicted tokens, decode a full action block and send it to the robot.

What the paper changes

What the paper changes

The paper swaps the method for encoding actions: instead of mapping a movement sequence to abstract discrete symbols via a lookup table, it maps the sequence to pixel values of a grayscale image, then compresses that image and tokenizes the result. This buys back the precision of large vocabularies while keeping the speed of small ones.

The hidden quantity

Token utilization: how much of the vocabulary gets used

measured quantity  =  token utilization

When actions are encoded as random abstract symbols, many tokens in the vocabulary go unused: if only 100 out of 512 possible tokens ever get picked, you have wasted symbol space. The paper's hidden quantity is the fraction of the vocabulary that actually gets selected during training and inference: how many of the possible token IDs appear in the sequences the model generates.

High token utilization means the encoding is not wasteful; every token has a job. The paper estimates this by counting how many unique token IDs appear in real rollouts, then dividing by the vocabulary size. A learnable tokenizer (one whose mapping is tuned during training) naturally keeps utilization high, because the encoder learns to spread the action space evenly across token IDs rather than clustering them.

Why it works

Why encoding actions as images works

A sequence of robot movements is not random noise; it has structure. If the arm moves left, then forward, then down, those motions are neighbors in the action space—close movements should have similar representations. When you treat the sequence as an image (pixels arranged in a 2D grid with time on one axis and motion type on the other), the spatial structure of the image automatically captures that neighborhood: nearby pixels have similar values, which matches nearby actions having similar encodings. The neural encoder then compresses this spatially coherent image down to a tiny bottleneck (a few numbers), and rounds those numbers to discrete token IDs (the way a photo rounds pixel colors to 256 levels).

The key win: because the image is spatially coherent, many different action details can be encoded into just a few token IDs without losing precision. A coarse token in the old symbol-based scheme (where each token is arbitrary) covers a huge, blurry range of movements. But a coarse token in the image scheme can be very precise, because the image encoder has already smoothed out noise and highlighted the spatio-temporal pattern of the action. The robot model then predicts these tokens at inference time, decodes them back to movements, and executes blocks of motion smoothly—hitting both speed (few tokens) and precision (clear movements).

The compression formula

First in words:

Reconstruction error equals the difference between the original action sequence and what you get by encoding it as an image, compressing it, quantizing it, and decoding it back. The learnable tokenizer minimizes this loss, which measures how much detail is lost in the round-trip encode-compress-quantize-decode.

Then the compact form:

L_recon = sum_t || a_t - decode( quantize( encode( img(a_1..T) ) )[t] ) ||^2

Every symbol:

a_tthe true action at time step t (e.g., arm position and grip angle)
img(a_1..T)the action sequence painted as a grayscale image
encodethe learned neural encoder that compresses the image
quantizerounding to nearest token ID in the vocabulary
decodethe learned inverse function that maps tokens back to actions
L_reconthe total error: how much motion is lost in the encode-decode cycle
A tiny worked example
Suppose the true action sequence is [0.5, 0.3, 0.7, 0.2] (normalized arm positions).
Painted as a 1×4 image (4 pixels), values are [0.5, 0.3, 0.7, 0.2].
Encoder compresses to 2 numbers: [0.6, 0.35] (the average of pairs).
Quantizer rounds to tokens [0.6→3, 0.35→2] out of a vocabulary of 4 (values 0, 1, 2, 3).
Decoder maps [3, 2] back to [0.65, 0.25, 0.65, 0.25] (reconstructed sequence).
Error: L_recon = (0.5-0.65)^2 + (0.3-0.25)^2 + (0.7-0.65)^2 + (0.2-0.25)^2 = 0.0225 + 0.0025 + 0.0025 + 0.0025 = 0.03.
This small error means the compressed tokens lose little information; the robot can still execute precise movement.

The encoder learns to spread actions evenly across the image so that quantization introduces minimal error, and the decoder learns to reverse the process accurately—together, this is why learnable tokenization beats fixed codebooks.

What can go wrong

What can go wrong

Image boundary artifacts. If the encoder treats the image edges as special (e.g., padding with zeros), it might learn to hide important action information in the corners, which then gets corrupted during quantization. Fix: use circular padding or learn edge tokens.
Quantization bottleneck. If the vocabulary is too small or the encoder compresses too aggressively, the quantization step throws away information the robot needs. The round-trip error explodes, and the robot learns sloppy movements. Fix: tune the bottleneck size and use smooth rounding tricks to make quantization easier to train.
Poor generalization to new tasks. The learnable encoder is tuned on training tasks. On a new task with actions outside the training distribution (e.g., finer motions or longer sequences), the encoder may not compress those actions well. Fix: train the encoder on diverse action distributions; use block-wise decoding to adapt on new tasks.
Scalability. When done right, the learnable encoder is a small network that runs faster than encoding each action separately. Block-wise decoding lets the model convert many tokens back to actions in one batch, because the decoder is shared and reused, making the overall process competitive with baselines even on longer sequences.
What a runnable demo should prove

What a runnable demo should prove

Build a simple robotic arm simulator (or use an open-source one). Train a small vision-language-action model on 5 manipulation tasks (e.g., pick, place, rotate, open, close). Measure: (1) inference time (milliseconds to predict the next action), (2) reconstruction error (how well the encoder-decoder round-trip preserves the true action), and (3) task success rate (what fraction of trials achieve the goal). Then swap the action tokenizer from FASTerVQ to a fixed discrete codebook (baseline). The concrete result: FASTer's inference is faster because it predicts fewer tokens, reconstruction error is lower because the image encoder preserves motion detail, and task success is higher because the robot moves more precisely.
