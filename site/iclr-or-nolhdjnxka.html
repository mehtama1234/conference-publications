GNN-as-Judge: LLMs and Graph Structure Together

When an LLM and a graph-structure model disagree on which nodes matter, their disagreement becomes a signal for which labels to trust.

Paper explainersAll themesGraph & Geometric Learning

Large language models are good at understanding text, but they struggle when text sits inside a graph with few labeled examples. This paper shows how to use a simpler model, one that respects the graph's structure, to identify which unlabeled nodes should get labels first, then harvest both agreement and disagreement between the two models to build a reliable set of training examples.

Zero assumption version

Why LLMs alone fail on graph data with few labels

A language model reads text and guesses a label. If you have only a handful of labeled examples, you need more. A naive approach: feed the model more unlabeled node texts, let it predict labels for them, then use those predictions as training data. This is called pseudo-labeling.

This breaks in two ways. First, when only a few nodes are labeled, the model has almost no context and makes wild guesses on which nodes matter. It labels nodes that are noise-adjacent to the labeled ones, because it has no way to know if a node is actually connected to the labeled examples or just floating in the text space. Second, when you fine-tune the language model on these noisy pseudo-labels, the model memorizes the mistakes, and the errors get locked in.

The move. Use a graph-structure model to identify which unlabeled nodes are actually close to labeled ones, then watch where the language model and the graph model agree or disagree, and only trust labels at those disagreement points.

The algorithm as a flow

What it actually does

1. Mark structurally close nodes

Graph model scores which unlabeled nodes sit next to labeled ones.

2. Measure LLM confidence

Language model assigns each node a label and a confidence score.

3. Find disagreement

Where graph says close but LLM is uncertain, or LLM is confident but graph says far.

4. Assign pseudo-labels at high-disagreement spots

Label nodes where the two models most disagree. Trust those labels.

5. Fine-tune LLM on safe pseudo-labels

Use only the high-agreement, high-signal pseudo-labels. Teach the language model structure.

What the paper changes

What the paper changes: which nodes get pseudo-labels

The paper does not change the models themselves. It changes the ORDER and SELECTION of which unlabeled nodes get assigned labels for retraining. Instead of labeling all nodes or picking randomly, it labels first at points of high disagreement between the two models.

the object it moves  =  pseudo-label assignment strategy
The hidden quantity

The hidden quantity: disagreement signal

measured quantity  =  graph-text disagreement

The paper measures a NEW quantity: how much the graph model and the language model disagree on a given node. The graph model computes a score for how close a node sits to the labeled part of the graph (neighbors of labeled nodes score high; isolated nodes score low). The language model computes a confidence for its predicted label. A node with high graph-closeness but low LLM-confidence is a HIGH DISAGREEMENT node — this is where to assign a label first.

The paper estimates this by combining the graph-nearness score (how far a node sits from labeled ones, measured by the graph structure) with the LLM confidence (how sure the language model is of its guess). When the graph says a node is close but the LLM is uncertain, that is a high-disagreement spot where structural information might correct the LLM.

Why it works

Why it works: structural insight corrects text-only blindness

A language model trained on text alone has no idea which nodes matter to each other. It sees isolated snippets of text and guesses labels based on the words. A graph model, by contrast, knows which nodes are neighbors and propagates information along edges. It cannot read text, but it knows structure.

When the two models DISAGREE on a structurally close node — the graph says this node is a neighbor of labeled nodes, but the LLM is uncertain — that is a spot where the graph's structural knowledge could help the LLM. By labeling there first (giving the LLM a true example it can learn from), the LLM learns to associate node closeness with label patterns. Over time, as more pseudo-labels accumulate, the LLM begins to encode the structure into its own predictions.

The second part is noise reduction. Not all pseudo-labels are reliable. The paper uses a weakly-supervised fine-tuning loss: instead of treating pseudo-labels as hard truth, it treats them as soft signals. Nodes with high disagreement are trusted more; nodes where both models agree are de-weighted. This way, even if some pseudo-labels are wrong, the fine-tuning process does not lock in the mistakes.

Math after the picture

The scoring equation

First in words:

To rank which unlabeled nodes to label first, compute a score that combines graph closeness and LLM confidence disagreement. Higher score means label first.

Then the compact form:

score_i = (1 - conf_LLM_i) * close_GNN_i

Every symbol:

score_iranking score for node i (higher means label this node first)
conf_LLM_ihow certain the LLM is of its prediction for node i (0 to 1, from softmax output)
close_GNN_ihow close node i sits to labeled nodes (0 to 1, from graph-diffusion score)
Tiny worked example
Node A: LLM confidence 0.6, graph closeness 0.9 -> score = (1 - 0.6) * 0.9 = 0.4 * 0.9 = 0.36
Node B: LLM confidence 0.9, graph closeness 0.8 -> score = (1 - 0.9) * 0.8 = 0.1 * 0.8 = 0.08
Node C: LLM confidence 0.5, graph closeness 0.7 -> score = (1 - 0.5) * 0.7 = 0.5 * 0.7 = 0.35
Node A scores highest (0.36). It is close to labeled nodes but the LLM is unsure. Label Node A first.

Nodes where the graph says close but the LLM is uncertain score highest and get labeled first, because these are spots where structural knowledge can most help.

What can go wrong

What can go wrong

Graph structure is missing or noisy. If the edges in the graph do not actually reflect true relationships (links are random or mislabeled), the GNN closeness scores mean nothing. The paper assumes edges are correct. If edges are wrong, pseudo-labels will be ranked wrong.
LLM is already very confident everywhere. If the language model assigns high confidence to all nodes, there is little disagreement to signal on. The ranking becomes flat, and pseudo-labels are chosen almost randomly. Works only if the LLM is uncertain in at least some regions.
Weak labels in the seed set. The whole method rests on the initial few labeled examples being correct. If the seed labels are wrong, the graph model propagates those mistakes, and disagreement becomes noise. The initial labeled set must be clean.
Done right: mixed-signal examples. When you pick examples where one model sees structure but the other is blind, you teach the blind model (the LLM) to notice what the structural model sees. This is a genuine transfer of knowledge, not just noise reduction.
What a runnable demo should prove

What a runnable demo should prove

Build a small text graph (e.g., 50 nodes, each with a short text description). Hand-label 5 nodes (say, red/blue categories based on their text). Run the GNN model and the LLM model separately. Compute the disagreement score for each unlabeled node. Pseudo-label the top 10 highest-disagreement nodes according to the paper's algorithm. Then fine-tune the LLM on those 10 pseudo-labels (and the original 5). Measure accuracy on a held-out test set (e.g., 20 nodes you labeled but hid from training). Compare against: (1) LLM trained only on the original 5 labeled nodes, and (2) LLM trained on 15 random pseudo-labels. The paper's method should show higher final accuracy than both baselines.

improvement = (test_accuracy_with_structured_pseudolabels) - (test_accuracy_with_random_pseudolabels)

The demo proves that disagreement-ranked pseudo-labels beat random selection, because structure + text together guide the LLM better than text alone.
