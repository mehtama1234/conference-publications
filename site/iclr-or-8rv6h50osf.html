MoBE: Mixture-of-Basis-Experts

MoBE compresses giant expert networks by splitting each expert's weight matrix into a shared blueprint plus a small expert-specific tweak.

Paper explainersAll themesEfficiency & Systems

Large language models with Mixture-of-Experts (MoE) architecture are fast because they only use a few of their thousands of experts at a time. But they still need enormous memory to store all those experts. MoBE shrinks them by discovering that many experts are similar — they can share a common core structure and only differ in small expert-specific parts.

Zero assumption version

The Memory Bottleneck

Large language models using Mixture-of-Experts store thousands of separate neural networks called experts. Each one is ready to run, so the model can pick a few fast experts for each question because the router (a small network that picks) only activates a few, and skipping the rest saves time. This makes inference (when the finished model answers a new question) quick, but the storage is massive because all those experts must be kept in memory even if only a few run, so a 671-billion-parameter (a parameter is a single number that the model learned) model needs enormous memory cards.

You might try just removing experts you do not use (expert pruning). This shrinks the model but breaks it: the model loses specialized knowledge and its answers get wrong on 7-14% of cases. You might try squashing expert matrices using compression techniques like SVD (a standard mathematical trick). Still too crude: even small compressions lose significant information because you treat each expert independently.

The hidden problem: experts are not randomly different. They are similar to each other within a layer. That similarity is going to waste.

In one sentence. MoBE splits each expert weight matrix (a grid of learned numbers used in computation) as W equals A times B, where A is unique per expert but B is a shared blueprint matrix reused across all experts in that layer.

The algorithm as a flow

What it actually does

Parse the original expert weights

Take each expert's weight matrix W from the pretrained model (e.g., Qwen3-235B).

Decompose into W equals A times B

Factor W as a product: A (small, expert-specific) times B (medium, layer-shared).

Share the blueprint B across experts

Instead of storing 10 separate B matrices, all experts in the layer use the same B.

Tune A to minimize reconstruction loss

Adjust each expert's A matrix so A times B still reconstructs W accurately.

Deploy with shared basis storage

Store one B per layer plus all A matrices; model size shrinks 24-30%.

What the paper changes

What the Paper Changes

MoBE changes how expert weight matrices are stored and computed. Instead of keeping each expert's full matrix W, it splits W into two parts: a small expert-specific matrix A and a shared layer-wide blueprint matrix B. At inference time, the model still computes the same result by multiplying A times B, but the total storage is much smaller because B is reused across all experts.

The key is that A is unique per expert but B is identical across all experts within a single MoE layer. This asymmetry is what creates the compression: you save storage on B because you store it only once.

the object it moves  =  expert weight storage
The hidden quantity

Reconstruction Error: How Well the Decomposition Fits

measured quantity  =  mean squared error of factorization

The paper measures a hidden quantity: reconstruction error, the difference between the original weight matrix W and the reconstructed matrix A times B. This error is measured across all experts in a layer using mean squared error (MSE), which is just the average of all squared differences. Lower MSE means the factorization captures more of the original pattern.

MoBE estimates this by training the A and B matrices to minimize reconstruction error during the compression step. The paper shows (in their graphs) that MoBE achieves lower MSE than competing methods like MoLAE and D-squared-MoE across many layers of real models, which means more information is preserved even at high compression rates.

Why it works

Why Shared Basis Compression Preserves Accuracy

The core mechanism is that experts within a layer are structured: they have a common backbone plus expert-specific adjustments. By factorizing W equals A times B and sharing B across experts, MoBE exploits that structure. The shared matrix B encodes the backbone (what all experts do in common), and the expert-specific matrix A encodes the specialist knowledge (how each expert differs).

This works because the factorization respects the actual computation: at inference, the model still computes output equals input times A times B, which is mathematically identical to input times W when A times B equals W. So there is no approximation in the forward pass—only in how storage is organized. The only information loss comes from tuning A and B to approximately reconstruct W, but because B is large (shared across many experts) and A is small (only adjusts for one expert), the tuning finds a very high-fidelity factorization. The paper's experiments show 1-2% accuracy drop at 24-30% compression, which is much better than earlier compression methods because the shared-basis structure better matches how experts actually behave.

Additionally, the paper finds that the factorization is even more accurate when basis matrices B are initialized with structure (using activation functions like SiLU or tanh, which are mathematical functions that add structure, or Z-score normalization) rather than random because a structured starting point gives the optimizer better hills and valleys to navigate down, avoiding poor local minima. This structure helps B capture the core patterns that most experts share because the structured initialization already encodes some of the common behavior experts need, so the optimizer has less distance to travel.

Math after the picture

The Factorization Formula

First in words:

The weight matrix W is factorized as the product of two smaller matrices: W equals A times B, where A is the expert-specific transformation (unique to expert i) and B is the shared basis matrix (shared across all experts in the MoE layer).

Then the compact form:

W_i = A_i * B, where A_i is expert-specific and B is layer-wide shared

Every symbol:

W_ioriginal weight matrix of expert i
A_ismall expert-specific transformation matrix for expert i
Blarge shared basis matrix, same across all experts in the layer
*matrix multiplication
A tiny worked example
Suppose expert 1 has an original weight matrix W_1 that is 32 by 32 (1024 values).
We factor it as A_1 times B where A_1 is 32 by 8 (256 values) and B is 8 by 32 (256 values).
Total storage for expert 1: 256 plus 256 equals 512 values, half the original 1024.
Now suppose there are 8 experts in the layer. Normally: 8 times 1024 equals 8192 values total.
With MoBE: (8 times 256 for all A matrices) plus (256 for the shared B) equals 2048 plus 256 equals 2304 values.
Compression ratio: 2304 divided by 8192 equals 28%, or a 72% reduction.

At inference the model computes input times A times B, which gives the same result as input times W, but uses far less stored memory. The subscripts are explained in the symbol table.

What can go wrong

What can go wrong

Basis matrix too small. If the shared basis B has too few columns (too much compression), it cannot capture the variation across experts. Reconstruction error grows, and model accuracy drops. The paper finds that the number of basis matrices m must scale with expert diversity and layer size.
Poor initialization of basis matrices. If B starts as random noise, gradient descent gets stuck in a local optimum and never finds a good shared pattern because the error function has many valleys, and random noise lands in a bad one. The paper shows that initializing with structured activation functions (SiLU or tanh) or Z-score normalization dramatically improves convergence and final accuracy because structure provides a better starting point that is already partway toward capturing real expert patterns.
Alternating optimization diverges. The paper tried alternating between updating A and B separately (an alternating optimization algorithm), but found it unstable during training because when you update A without B, and then B without A, the two chase each other and oscillate rather than converge. Adam optimizer (updating all parameters jointly) worked much better because all adjustments happen together, so A and B coordinate smoothly toward a single solution.
Grouping very large layers. For extremely large layers (e.g., 384 experts in Kimi-K2-Instruct), jointly optimizing all experts at once is computationally expensive and can diverge. The paper solved this by splitting experts into sequential groups (two groups of 64 basis matrices each) and training them separately, which is a practical workaround but adds a tuning knob.
Done right. Choose the basis count m based on the target compression ratio and layer size. Initialize B with structure. Use Adam to optimize jointly. For huge layers, split into groups. Validate reconstruction error per layer before deployment.
What a runnable demo should prove

What a runnable demo should prove

Build a tiny Mixture-of-Experts model (say, 4 experts, each a 64-by-64 weight matrix) and compress it with MoBE. Train the compressed model on a toy dataset (e.g., synthetic classification with 10 classes). Measure accuracy on a held-out test set before compression, after basic expert pruning, after SVD compression, and after MoBE. Separately plot the per-layer reconstruction error (MSE) for MoBE versus the competing methods. Show that MoBE achieves both lower reconstruction error and higher test accuracy at the same compression ratio.
