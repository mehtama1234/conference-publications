Interleave-VLA: Robot Learning from Image-Text Instructions

Show a robot both pictures and words in its instructions, not just words, to stop it from focusing on the wrong thing and help it handle unseen tasks.

Paper explainersAll themesRobotics & Control

Robot learning models trained on text instructions alone often fail on new tasks because they misread the instructions, focusing on the wrong object or detail. Interleave-VLA fixes this by having robots learn from interleaved image-text instructions: a word describing a task plus a picture showing what it means, woven together. The result is a robot that generalizes twice as well to unfamiliar objects and can even follow hand-drawn sketches.

Zero assumption version

Why text alone confuses robots

A robot policy is a learned decision-maker that watches the world and outputs actions (move arm left, grasp, lift). Today's best-available robot models are trained on video demonstrations paired with text instructions. During training, the model learns: when you see this video sequence and read 'move the red block to the blue cup', output these motion commands.

But text is ambiguous. If an instruction says 'pick up the toy', the word 'toy' in the text does not literally point to any one object. The model must infer from the video scene which thing IS the toy. When training data shows many different toys in many different contexts, the model's internal attention (the part that decides where to look) gets confused. It develops three recurring failure patterns: (1) Attentional bias — the model fixates on some red-herring object because it often appears in similar scenes; (2) Diffused attention — the attention scatters across many objects because the scene is busy and the text signal is weak; (3) Attention leakage — the model's focus drifts to nearby surfaces that are not mentioned in the text at all, because the training examples were statistically biased that way. The result: when the robot encounters a new object or scene, it looks in the wrong place, misinterprets the task, and fails.

In one sentence. Text-only instructions leave robots guessing which real object you mean, so they learn brittle hallucinations instead of truly understanding tasks.

The algorithm as a flow

What it actually does

1. Collect interleaved training data

Start with 210,000 real robot trajectories. For each task, take text instructions plus a picture from the first frame showing the target object. Combine them: 'pick the red' plus image of the red thing.

2. Feed instruction pairs into the model

The robot model's input processor is modified to accept both a sentence and an image side by side (interleaved). No other parts of the model architecture change.

3. Train without changing the learning algorithm

The flow-matching objective (the loss function that teaches the model) stays the same. The model simply learns to use the image to remove ambiguity from the text.

4. Test on unseen objects and different instruction types

When the robot encounters an unfamiliar object or even a hand-drawn sketch as input, it already knows that paired text and images co-occur; the pattern generalizes.

5. Benefit: cleaner attention, 2x better generalization

Because the image is a ground truth anchor, the robot's internal attention stays focused on the actual target. It succeeds on twice as many out-of-domain tasks as text-only models.

What the paper changes

The one thing this paper changes

The input to a robot policy is traditionally text: 'move the red block left'. Interleave-VLA changes this input to interleaved text and images: a phrase plus a synchronized picture. That is the sole architectural change. Everything else (how the model computes, how we train it, the loss function) remains identical.

The hidden quantity

Attentional hallucination: When a model looks at the wrong thing

measured quantity  =  Attentional hallucination

Inside every vision-language model is an attention mechanism (a learned spotlight) that decides which parts of the input to focus on. When the robot reads 'pick the toy', its attention must land on the actual toy in the scene. But with text alone, the model does not have ground truth about where the real toy is, so it guesses. Over time, it learns spurious correlations: 'toys are often next to cups' or 'the word toy co-occurs with red things'. When trained on biased data, the model's attention becomes brittle. On new scenes, it fixates on a hallucinated location (an object that is not the true target), or it spreads across multiple objects because the text signal is too weak.

The paper identifies three concrete forms: (1) Attentional bias — the attention locks onto a false object that happened to co-occur in training; (2) Diffused attention — the attention scatters across the scene because no one object stands out; (3) Attention leakage — the attention drifts to nearby unmentioned surfaces because training examples were statistically correlated that way. Interleave-VLA measures this by computing how much of the model's attention focus lands on the true target object. When training on interleaved image-text data, the attention peak increases (becomes sharper) and stays on the correct object even with unfamiliar inputs.

Why it works

Why adding pictures stops hallucination

Text is a lossy signal. The word 'red' does not automatically select the unique red object in a cluttered scene—there could be many red things. A text-only model must learn this mapping implicitly by observing which red thing the human typically cares about. When training data is imbalanced (more demonstrations with red cups than red blocks), the model overfits: it learns 'red means cup' instead of 'red means whatever the human is pointing at'. When the robot encounters a red block for the first time, the attention fires on the wrong object—a hallucination.

Adding a paired image removes this ambiguity entirely. The image IS a direct visual pointer: it shows the red block in pixel coordinates. The model's attention no longer needs to infer the target from statistical patterns; it can learn the simple rule 'attend to the objects in the provided image'. This rule is dependable because it does not rely on training data statistics. No matter how biased the training data is, an image of the target unambiguously specifies it. The robot's attention learns to lock onto the image-highlighted region, not to predict based on what was common in past examples.

Furthermore, training on diverse modalities (text, photos, sketches, Internet images of objects) prevents the model from fitting spurious correlations within any one modality. The model learns that the task is fundamentally 'attend to what the human is showing me', which generalizes to any representation of that task.

The training objective stays the same; only the input changes

First in words:

Loss = Flow matching objective on action sequence, conditioned on interleaved image-text state. No new equations; the model learns to predict the next action given the grounded multimodal instruction.

Then the compact form:

a_t ~ pi_theta( · | s_t ) where s_t = ( I_t , text , image )

Every symbol:

A tiny worked example
Example: At timestep 0, robot observes video frame I_0, receives text 'pick red' and image showing red block at pixel (120, 80).
Model attends to (120, 80) because that is where the image highlights the target.
Model outputs action: reach-to (120, 80), which happens to be the correct reach direction.
Contrast: without the image, the model must infer from text alone that 'red' means the block and not the nearby cup (even though cups are red in 40% of training examples). It attends to (140, 100) by mistake, outputs wrong reach, and fails.
With the image, the mapping is deterministic: the image specifies the target, so attention is correct every time, even on unfamiliar objects never seen during training.

The state now contains both image and text; the model learns that this pair is a ground-truth anchor and does not need to infer the target from statistical bias.

What can go wrong

What can go wrong

Image-text mismatch during data curation. If the automatic pipeline pairs a task description 'pick red block' with an image showing a cup instead of a block, the model learns a corrupted mapping. Quality control on the 210k dataset is essential.
Instruction image absent at test time. Interleave-VLA was designed for interleaved inputs. If at test time the robot only receives text (no image), it may perform worse than a text-only baseline because it has never learned to work with text alone.
Domain mismatch between training images and real-world camera views. If training images are clean renders or Internet photos but the robot's camera shows cluttered, cropped, or low-resolution views, the model may not recognize the target object even when the image is provided.
Done right: collect interleaved data carefully, validate the pipeline, test both interleaved and text-only inputs, include diverse image modalities during training. The method works well when the data is high-quality and the model is trained to handle multimodal variation.
What a runnable demo should prove

What a runnable demo should prove

The demo should train two robot policies on the same real-world trajectory dataset: one on text-only instructions and one on interleaved image-text instructions. Then test both on a held-out set of tasks with unfamiliar objects. Measure the success rate (how many tasks the robot completes correctly) for each model. The interleaved model should succeed twice as often on out-of-domain tasks. Additionally, test zero-shot generalization to different instruction modalities (hand-drawn sketches, Internet images of objects the model has never encountered) and show that only the interleaved model generalizes.

generalization_gain = success_rate_interleaved_unseen_objects / success_rate_textonly_unseen_objects

The core insight: images are ground-truth pointers that prevent the model from learning brittle statistical hallucinations. Any task the model understands from an image will generalize to any other modality of that image, because the fundamental instruction is spatial location, not text pattern-matching.
