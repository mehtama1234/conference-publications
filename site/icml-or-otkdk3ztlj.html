Mechanistic Analysis of Sim-and-Real Co-Training

Co-training works because simulation and real-world data develop aligned feature spaces while staying distinct, allowing the policy to learn a shared representation that handles both.

Paper explainersAll themesRobotics & Control

Robot training is expensive with real robots but abundant with simulation. Combining simulation data with scarce real data (co-training) works in practice, but nobody fully understood why. This paper reveals the hidden mechanics: simulation and real data must develop representations (learned feature lists) that align in structure yet stay distinguishable (the model can still tell which is real).

Zero assumption version

Why is co-training a puzzle?

Training a robot to do tasks with real-world data is expensive and slow. Simulation is free and fast but never perfectly matches reality. A natural idea: mix cheap simulation data with expensive real data and train both together. This works surprisingly well in practice, but why?

A beginner might guess: if the simulation is close enough to reality, just mixing the data works fine. That fails because simulation and reality have different distributions (the patterns are different). A robot trained mostly on simulation will overfit to simulation quirks and fail on real hardware. But somehow, co-training balances this. The mechanism remained hidden.

In one sentence. Simulation and real data co-train by building aligned yet distinguishable feature representations, with domain-dependent action reweighting as secondary.

What the paper changes

What the paper changes

The paper does not propose a new algorithm, but rather identifies what is already happening during co-training. It reveals two intrinsic effects: (1) representation alignment—the learned feature space naturally aligns across sim and real domains, and (2) domain discernibility—the model preserves a signal about which domain each sample came from. The object of study is the feature representation (the learned lists of numbers the model uses internally to encode observations).

the object it moves  =  feature representation
The hidden quantity

The two hidden quantities

measured quantity  =  Structured representation alignment and domain discernibility

Representation alignment means the learned feature vectors from simulation and real data occupy overlapping regions in the latent space (the high-dimensional list of numbers the model learns). The paper measures this by taking the learned features and visualizing them with UMAP (a visualization tool that maps high-dimensional lists to 2D pictures), then checking whether sim and real clusters overlap.

Domain discernibility is the model's ability to tell whether a feature came from simulation or real data. The paper measures it by training a small binary classifier (a two-layer network) on top of the learned features to classify domain identity. Higher accuracy means the model preserved more domain signal. The paper shows that good co-training requires BOTH: alignment (so the model shares knowledge) AND discernibility (so it does not collapse to one domain).

Why it works

Why alignment and discernibility both matter

Without alignment, simulation and real features stay in separate regions of the learned space. The policy must learn separate rules for each domain, wasting capacity. Alignment forces shared learning: if a state presents the same visual patterns in both sim and real (say, a gripper approaching a block), the model learns one reliable description for that sight, reusing it in both domains.

Without discernibility, the model collapses: it forgets the domain boundary and treats all data as if it came from one source. It then overfits to whichever domain has more data (usually sim). Discernibility preserves the signal so the model can adjust: on real data, it uses a different action weighting than on sim data because real and sim respond differently to the same observation, so the domain signal lets the model apply the appropriate nudge for each.

The mechanism works through layer-wise learning. Shallow (early) layers learn local feature patterns—they see individual signals and align them. Deep (final) layers learn overall structure—they see how features combine and preserve domain information. This is automatic: with the right mixing ratio (how much sim vs real data), the network self-organizes this way. The paper validates this by training on toy models (simplified settings), then checking it holds on real robot manipulation tasks (sim-to-sim and sim-to-real experiments).

The balance equation

First in words:

The co-training loss is a weighted mix of simulation and real losses, with a mixing ratio that controls how much each domain contributes. Domain-dependent action weighting modulates the contribution at inference time.

Then the compact form:

L_total = w * L_sim(theta) + (1 - w) * L_real(theta); w in [0, 1]

Every symbol:

L_sim(theta)loss on simulation data; how far sim predictions miss their targets
L_real(theta)loss on real data; how far real predictions miss their targets
wmixing ratio (the fraction of gradient steps driven by sim data)
thetathe model's learned parameters (weights and biases)
A tiny worked example
Suppose w = 0.7 (70% sim, 30% real), L_sim = 0.5 (simulation predictions off by 0.5), L_real = 0.2 (real predictions off by 0.2).
L_total = 0.7 * 0.5 + 0.3 * 0.2 = 0.35 + 0.06 = 0.41.
The model optimizes this total; it cannot ignore real data (30% pulls the loss down) nor sim data (70% dominates). The mixing ratio balances knowledge transfer.

The ratio w controls how hard the model tries to please each domain; alignment happens automatically when w is tuned so neither domain is ignored.

What can go wrong

What can go wrong

No alignment. If sim and real features stay in separate regions (alignment fails), the model learns two independent policies and wastes capacity.
No discernibility. If the model forgets which domain a sample came from (discernibility collapses), it overfits to the larger dataset (usually sim) and fails on real data.
Wrong mixing ratio. If w is too high (too much sim), the model ignores real data. If w is too low, it is data-starved and underfits.
Done right. With the right w and architecture, alignment and discernibility emerge automatically; the policy handles both domains.
What a runnable demo should prove

What a runnable demo should prove

Train a policy (a small diffusion model on a simple task, e.g., reaching a target in simulation) with co-training: mix 70% simulation data and 30% real data (or collect a few real robot trajectories). Evaluate on both sim and real. Then visualize the learned feature space using UMAP to show alignment, and train a binary classifier on the final-layer features to measure domain discernibility (should be >70% accuracy). Vary the mixing ratio w and show that performance drops if w is too extreme (all sim or all real).
