Identity-Free Deferral For Unseen Experts

Stop teaching the AI to memorize which expert is which; instead teach it to recognize when an expert is good at a task, regardless of who they are.

Paper explainersAll themesComputer Vision

When a medical AI system works with human doctors, it learns to trust Doctor Alice on heart cases and Doctor Bob on lung cases. But when a new doctor (Doctor Carol) arrives, the system fails because it never learned to recognize skill itself—only to recognize Carol's face or name. This paper fixes that by teaching the system to only look at what matters: can this expert handle the confidence level of this case type?

The problem: teaching the AI to recognize people instead of skill

Imagine you run a medical imaging lab. Your AI model looks at X-rays and makes a call: is this a tumor or normal? For hard cases, it should say I don't know—send this to an expert. You have three radiologists on staff, and they have different skills. Your model learns: when Alice is on duty, trust her judgment on lung cases; Bob handles cardiac cases; Carol knows liver cases.

Now Carol moves to another hospital, and you hire a new radiologist—Dana. Your system has never seen Dana before. It does not know that Dana is also excellent at liver cases (the same specialty as Carol). The system fails because it learned to recognize Carol specifically, not to recognize expertise in liver imaging.

In one sentence. The AI learns identity-conditioned rules (Alice handles this) instead of skill-based rules (anyone skilled at this task can handle it).

What it actually does

Test on new experts

What the paper changes

What the paper changes

Instead of processing expert identity (a one-hot vector saying Alice=1, Bob=0, Carol=0), the system receives only structural features: the model's confidence score for its own prediction, and the expert's estimated skill for predicting that specific task type. Identity vanishes.

the object it moves  =  Expert representation
The hidden quantity

The hidden quantity: Bayesian competence profile

measured quantity  =  Expert skill estimate per task

A competence profile is a summary, built from a few examples, of how well one expert handles each task type. If Alice has seen 10 lung cases and got 9 right, her lung-competence is 0.9. If she has seen 5 heart cases and got 2 right, her heart-competence is 0.4.

The paper estimates this Bayesian competence profile (a probability distribution over possible skill levels) from limited examples. Then, when a new expert (Dana) arrives, the system runs the same estimation: show Dana a few lung cases, measure her accuracy, build her competence profile. The deferral rule now knows whether to trust Dana, because it measures skill, not identity.

Why it works

Why it works: permutation invariance by design

The core insight is a symmetry property called permutation invariance. Imagine you listed all experts in a spreadsheet row: Alice, Bob, Carol. If you shuffle the row—now it is Bob, Carol, Alice—the system should still work the same way, because skill does not depend on order. Standard neural networks violate this symmetry: they learn position-specific rules (the first slot always means Alice, the second slot always means Bob). Identity-Free Deferral fixes this by using only stateless, positional-agnostic features: not the expert's index or name, but their Bayesian competence profile and the task at hand.

When a new expert Dana arrives, the system estimates her competence profile the same way, using the same Bayesian machinery. The deferral rule—which says defer when (model_confidence is low AND expert_skill is high)—applies unchanged. Dana is not a new slot or a new identity; she is just a new skill profile, and the rule is blind to identity so it works immediately.

The mechanism is a permutation-invariant encoder. Instead of building a vector like [Alice=1.0, Bob=0.0, Carol=0.0, Dana=0.0], the system builds [task_type_skill=0.8, model_confidence=0.3, ...]—a signature that describes the situation, not the person. The deferral decision logic now sees only the situation.

inputNew expert arrives, give her a few task examples

stepExtract role-indexed features: skill_for_this_task, model_confidence

The math: identity-free state and permutation invariance

First in words:

The state vector contains only role-indexed features, and the deferral policy is a function of this state that respects permutation symmetry.

Then the compact form:

state = [model_confidence, expert_skill_for_task, scatter_of_model_top_classes, ...] (no identity index)

Every symbol:

model_confidencehow sure the AI is about its own prediction (0 to 1)
expert_skill_for_taskprobability this expert gets this task type right, estimated from examples
scatter_of_model_top_classeshow spread out the model's confidence is among its top predictions (higher means less certain about which class is right)
statethe complete information fed to the deferral decision rule
A tiny worked example
Case: AI predicts lung nodule with 60% confidence. Expert Alice has 90% accuracy on lung cases.
State contains: 0.6 (how confident AI is), 0.9 (how often Alice succeeds on lung cases), 0.4 (how scattered the model's top predictions are), plus other structural info
Old system would also store Alice's position slot, making a larger vector that encodes: I am Alice in slot 1, Bob is slot 2, Carol is slot 3
New expert Dana arrives with same 90% lung accuracy. Her state contains: 0.6, 0.9, 0.4 (identical structural features!)
The trained policy sees the same state, so it defers with the same confidence. No retraining needed.
Old system fails because it never learned what to do when an unknown expert (no slot assigned) arrives.

The state ignores who the expert is and focuses only on whether they are skilled for this task type.

What can go wrong

What can go wrong

Competence profile estimation fails with too few examples. If Dana only handles 2 cases during onboarding, the skill estimate is noisy. The deferral rule then gives unreliable guidance. The fix: use Bayesian estimation (which models uncertainty) and require enough onboarding examples.
Task types must be stable across experts. If your task categories shift (lung cases suddenly mean something different), the Bayesian profiles no longer align. The fix: define task types consistently before deploying the system.
Expert skill may not be truly permutation-invariant. In the real world, Alice might be better than Dana at lung cases even if both show 90% accuracy in the test set—because Alice has intuition that doesn't show in small data. Permutation invariance assumes the true skill distributions are exchangeable, which can fail in small data regimes. The fix: use larger onboarding sets or accept limited generalization.
Done right: small onboarding set, consistent task definitions, validated skill estimates. When the Bayesian competence profiles are accurately estimated and task types are truly stable, the identity-free representation generalizes immediately to new experts.
What a runnable demo should prove

What a runnable demo should prove

Build a toy medical imaging task: 3 synthetic experts with known accuracies, 5 task types, and 200 labeled cases. Train a deferral policy (learn which expert to ask) using only the first two experts. Then introduce a third expert with the same accuracy profile but never seen during training. Measure deferral accuracy and compare against a baseline that learns identity-conditioned policies.

new_expert_accuracy = (correct_defer_calls + correct_own_calls) / total_calls_on_new_expert

The demo must show that identity-free training generalizes to unseen experts at >80% of the accuracy of the trained experts, while identity-conditioned baselines drop below 60%.
