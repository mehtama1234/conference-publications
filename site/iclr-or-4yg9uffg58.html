Identity-Free Deferral For Unseen Experts

When a model learns to pass hard calls to humans, teach it to recognize expert skill without learning which person is which.

Paper explainersAll themesComputer Vision

Many AI systems in medicine and other high-stakes fields work best when the model knows its limits and can pass uncertain decisions to a human expert. Learning to Defer trains a system to make this choice: predict or defer. But when new experts join the team after training, systems often fail if those experts work differently than the training experts did. This paper shows why: the system has learned to recognize specific people by their slots, not by their actual strengths, so it has no way to read a new person's abilities. The fix is to build profiles of what each expert is good at, without ever naming them.

Zero assumption version

Why existing systems stumble with new experts

A deferral system needs to answer one question: for this image and this expert, should the model predict or should it hand off to the expert? Current systems learn to recognize individual experts by their ID number. If you train on Cardiologist A and B, the system remembers 'I know A and B well,' but when Cardiologist C arrives, the system has no idea how good C is.

Worse, if C makes mistakes in a different pattern than A or B did, the system becomes confused. It learned shortcuts: 'when I see this expert slot, take this action,' not 'when I sense this expert is bad at class X, defer class X.' These shortcuts work fine when patterns match the training setup but break when new people join with different patterns.

The core problem in one sentence. Current systems memorize which specific experts to trust, so they cannot adapt when new experts arrive.

The algorithm as a flow

What it actually does

Observe expert on sample images

Show the expert a few images she already labeled; record her accuracy on each class.

Build a Bayesian profile

Estimate the probability the expert will get class X right; track uncertainty around that guess.

Erase the expert's identity

Feed the system only 'expert strength on top class' and 'model confidence on top class,' not the expert's name or which class it is.

Decide: predict or defer

The deferral system learns when model confidence plus expert skill means the model should predict, and when to defer to expert.

New expert uses same language

A new expert's profile plugs into the same slots; the system already knows how to read that language.

What the paper changes

What the paper changes

The method changes what information the system is allowed to see. Instead of learning a separate policy for each expert (expert ID conditioned), the system learns one universal deferral policy that takes only role-indexed inputs: the model's confidence in its top choice, the expert's estimated skill on that same choice. The expert's identity is hidden by design.

the object it moves  =  expert representation: from ID-conditioned to role-indexed
The hidden quantity

The hidden quantity: expert competence on each class

measured quantity  =  per-class expert accuracy

The paper measures something the old methods ignored: for each expert, how often does that expert get each class right? This is the expert's competence profile. It is 'hidden' because you cannot observe it until you see the expert label a few examples.

The paper estimates this using Bayesian inference: from a small set of context examples, it infers a probability distribution over the expert's accuracy per class, including honest uncertainty (the expert is strong at cardiac imaging but shaky on artifacts). This distribution is then used to guide deferral: the system learns 'if the expert is shaky here and my model is uncertain, defer; if the expert is strong and I am uncertain, also defer.'

Why it works

Why permutation symmetry fixes the problem

The old method learns identity-conditioned policies: the system memorizes 'when expert slot says 2, I defer more.' This works fine when experts 1 and 2 are always in slots 1 and 2. But if you swap them (permute the identities), the learned policy is wrong because it was built on the assumption that slot 2 always means the same person.

IFD fixes this by design. It never learns to care about who is in which slot. Instead, it learns rules about generic roles: 'when an expert is weak at the top class and the model is uncertain, defer.' This rule works no matter which expert is which, because it only reads the expert's strength on the relevant class, not their name or slot number. The system has built-in permutation symmetry: it treats experts as interchangeable as long as you tell it their actual competence.

Math after the picture

The deferral decision rule

First in words:

System loss if you predict equals one minus model confidence on true class; system loss if you defer equals one minus expert accuracy on true class. Pick the choice with lower loss.

Then the compact form:

R_predict(x) = 1 - max_y P(Y=y|X=x); R_defer(x, E) = 1 - q(x, E); defer if R_defer < R_predict

Every symbol:

R_predict(x)the risk (error rate) if the model predicts on this image
max_y P(Y=y|X=x)the model's highest predicted probability across all classes
R_defer(x, E)the risk if you defer to expert E
q(x, E)the probability expert E will get the true class right (estimated from profile)
A tiny worked example
Image shows a heart scan. Model predicts 'normal' with 92% confidence, so R_predict = 1 - 0.92 = 0.08.
Expert profile says she is right on 'normal' 88% of the time, so R_defer = 1 - 0.88 = 0.12.
Since 0.08 < 0.12, the model should predict (lower risk). Both are confident, so model takes it.
Next image: model says 'abnormal' with only 55% confidence (R_predict = 0.45). Expert is strong on abnormal (95% right), so R_defer = 0.05.
Now 0.05 < 0.45, so defer. The uncertain model gives way to the expert on this class.

The system compares two risks: model error rate vs expert error rate, and picks the safer option. It works because the expert profile is measured directly from her past performance, not guessed from her identity slot.

What can go wrong

What can go wrong

Noisy context images. If the few example images used to build the expert's profile are mislabeled or unrepresentative, the estimated competence will be wrong, and deferral decisions will be wrong.
Expert specialty unknown. The method assumes you can identify the expert's strongest class from context. If the expert's true strength is rare in the context examples, the system will misread it.
Class imbalance in expert skill. If an expert is extremely strong on one class but terrible on another, and the context examples happen to be all from the strong class, the profile will overestimate overall competence.
Done right. When you give the system enough diverse context examples and the expert's true competence is stable across similar images, the system generalizes to new experts reliably.
What a runnable demo should prove

What a runnable demo should prove

Build a simple image classifier for two related classes (e.g., two types of cell nuclei). Simulate three human raters with different accuracy profiles (one strong overall, one strong on type-A only, one weak). Train the deferral system on the first two raters (in-distribution). Then hold out the third rater and test whether the system correctly adapts to their profile without retraining. Measure deferral accuracy: the fraction of decisions (predict or defer) that led to the right class.

deferral_accuracy = (correct_predictions_when_predicted + correct_expert_calls_when_deferred) / total_decisions

The demo must show that accuracy on the held-out new rater is nearly as high as on the training raters, proving the system does not rely on memorized identities.
