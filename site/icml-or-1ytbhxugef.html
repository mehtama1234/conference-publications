Task-Aware Structured Memory

Keep only the tokens a task needs by merging visual tokens intelligently and fetching more only when a question becomes different.

Paper explainersAll themesEfficiency & Systems

When a language model reads many images and examples at once, it stores every pixel detail in memory, which gets huge and slow. This paper (TASM) lets it keep only what matters for the current task, fuse related visual pieces (tokens, or small chunks of data) without losing their spatial arrangement, and fetch more details only when a new question arrives.

Zero assumption version

The memory wall in multi-modal learning

When a language model learns from examples (in-context learning), it stores the key-value pairs—essentially a complete index of every word and pixel—so it can look them up during generation. With images and many examples, this index explodes. If you naively keep every token, memory grows quadratically with the number of examples, and the model slows down checking every stored detail for every new token it generates.

Earlier approaches tried to delete less-important tokens, but visual tokens are spatial: removing one token can sever the connections between neighboring pixels, breaking the ability to reason about object shape and location. Other methods rank tokens by their attention weight, but attention weights reflect what the model has already focused on—not what will actually matter for the next task.

The challenge. Compress memory without losing visual structure, and do it based on what the task needs, not what the model has attended to in the past.

The algorithm as a flow

What it actually does

Compute task direction

Take the question and answer, extract a single vector showing their difference—that is the task's direction.

Rank tokens by task alignment

Score each token by how aligned it is to that task direction, not by how much the model attended to it.

Merge without tearing

Use graph matching to pair nearby tokens into single merged tokens, preserving the spatial layout of the image.

Build two-tier memory

Store the most task-relevant tokens in fast Core Memory; put less-used tokens in a slower storage layer on disk.

Fetch dynamically at runtime

During generation, check if the attention distribution has shifted (new query type); if so, retrieve extra tokens on demand.

What the paper changes

The object the paper changes

The paper does not change the model's weights or training. Instead, it changes the memory index—specifically which tokens are stored, how they are organized, and when they are fetched during generation.

the object it moves  =  The memory index: which tokens stay, which merge, which are fetched on demand
The hidden quantity

The hidden quantity: alignment with task direction

measured quantity  =  Task alignment score

Most compression methods rank tokens by attention weight (past focus). TASM instead measures alignment with the task direction—how closely each token points in the direction of the question-to-answer transformation. This is a single number per token, computed by projecting the token onto the latent task manifold (a mathematical way of asking: how much does this token move in the direction we need?).

The paper estimates it by taking the question and answer representations, subtracting them to get a task vector, then dot-producting each token with that vector. Tokens with high alignment are task-relevant; tokens near zero are noise (like punctuation).

Why it works

Why task alignment preserves structure better than attention

Attention weights are high on any token the model has already focused on—including 'attention sinks' like punctuation marks or special tokens that cluster attention for no semantic reason. So deleting low-attention tokens does not mean deleting irrelevant tokens; it means deleting tokens the model has not looked at yet.

Task alignment is different: it measures whether a token is actually relevant to the task transformation. When you compress based on task alignment, you delete tokens that are orthogonal to the task (perpendicular to the task vector), not tokens that were simply not noticed. This preserves the spatial structure of images, because spatial relationships (edges, object boundaries) are often highly task-aligned, even if the model's attention has not yet visited them.

Merging tokens via graph matching rather than deletion further protects structure: instead of vaporizing tokens, it fuses spatially-close tokens into single tokens, keeping the topology intact. The dynamic retrieval at runtime is the final step: tokens you cannot afford to keep in Core Memory are stored on disk (the Latent Bank), and fetched on-demand when the query type changes, signaled by a shift in the attention distribution.

Math after the picture

The equation: layer-adaptive task alignment

First in words:

At each layer, blend local attention importance (shallow layers see pixel details) with global task importance (deep layers see meaning) using an adaptive gate

Then the compact form:

alignment_score(token, layer) = lambda(layer) * task_vector_score + (1 - lambda(layer)) * attention_score, where lambda(layer) ≈ 0.1 at shallow layers and ≈ 0.9 at deep layers

Every symbol:

alignment_score(token, layer)how relevant this token is at this layer, blending two signals
lambda(layer)the gate: how much to trust the task vs. past attention (depends on depth)
task_vector_scoredot product of token representation with task direction vector
attention_scorethe model's past attention weight on this token
shallow layersearly model layers that extract edges and spatial details
deep layerslater model layers that reason about semantics and meaning
A tiny worked example
Shallow layer (layer 2 out of 12): lambda(2) ≈ 0.1. Token 'edge of car': task_score = 0.3, attention_score = 0.8. Alignment = 0.1 * 0.3 + 0.9 * 0.8 = 0.03 + 0.72 = 0.75. Mostly attention-driven because visual edges matter early.
Deep layer (layer 11 out of 12): lambda(11) ≈ 0.9. Same token 'edge of car': task_score = 0.8, attention_score = 0.2. Alignment = 0.9 * 0.8 + 0.1 * 0.2 = 0.72 + 0.02 = 0.74. Now task-driven because in deep layers, only task-relevant edges survive.
Compare to a punctuation token: task_score = 0.01 (orthogonal to task), attention_score = 0.9 (sink effect). Shallow: 0.1*0.01 + 0.9*0.9 = 0.81. Deep: 0.9*0.01 + 0.1*0.9 = 0.099. Punctuation gets downweighted in deep layers where task matters most.

The gate flexibly shifts from trusting attention (which captures visual details) in shallow layers to trusting task alignment (which ignores sinks) in deep layers, preserving structure while eliminating noise.

What can go wrong

What can go wrong

Task vector is noisy or unstable. If the question and answer representations are not cleanly separated (e.g., in few-shot settings with weak examples), the task vector is weak. The paper addresses this by using layer-adaptive gating: in shallow layers where attention is stable, it trusts attention; in deep layers where semantics are clear, it trusts the task vector.
Graph matching is expensive. Bipartite graph matching to merge tokens is combinatorially hard. The paper constrains the problem spatially (only merge nearby tokens), making it tractable.
Dynamic retrieval adds latency. Checking the attention distribution shift at every generation step costs time. The paper uses a simple JS divergence threshold to trigger retrieval only when necessary, keeping the overhead low (3.4% trigger rate, 33ms latency overhead).
Done right. TASM avoids these by using layer-adaptive blending (which works even when task signals are weak), spatially-constrained matching (which is computationally fast), and probabilistic retrieval gating (which adds little delay). The result is near-lossless compression across all task types.
What a runnable demo should prove

What a runnable demo should prove

Build a mini multi-modal model (e.g., CLIP + small language model, or just embeddings) on a small image-text dataset (e.g., CIFAR-10 with captions, or a custom 10-example in-context set). Implement TASM: (1) compute task vectors from two example pairs; (2) score all tokens by task alignment; (3) merge tokens via greedy spatial matching; (4) evaluate accuracy on held-out spatial and temporal reasoning tasks before and after compression. Show that task-aware compression outperforms random token deletion and attention-based deletion on spatial tasks, because task alignment preserves spatial relationships (edges and object boundaries are aligned with task vectors) while deletion or attention-based pruning tears them apart.

Structure preservation = accuracy on spatial reasoning before compression minus accuracy on spatial reasoning after compression. A good result is < 5 percentage points drop at 60% compression ratio.

The demo must show that deleting tokens based on task alignment recovers accuracy on spatial reasoning tasks where random or attention-based deletion catastrophically fails.
