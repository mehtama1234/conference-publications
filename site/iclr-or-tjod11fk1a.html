Tactic: Adaptive Sparse Attention for Long-Context LLMs

Instead of keeping a fixed number of tokens in memory, Tactic picks tokens until their attention scores add up to a target fraction, adapting naturally to how sparse each layer really is.

Paper explainersAll themesEfficiency & Systems

When a large language model answers a question based on a long document, it needs to hold many past words (called tokens—the individual pieces the model reads) in graphics-card memory while computing answers. Most systems cut corners by keeping a fixed number of tokens from the past (maybe 512, or 1024) regardless of whether the model actually cares about that many. Tactic replaces this rigid limit with a flexible one: it keeps tokens until their attention scores (the weights the model assigns to each past token) add up to a target fraction of the total. This works because when you capture 90 percent of the attention weight, you automatically capture 90 percent of the actual information flowing through the model, so the approximation error stays small—and memory access becomes faster because you load fewer tokens into memory.

Zero assumption version

Fixed budgets pick too many or too few

When a language model reads a long document and generates an answer one token at a time, it must compute how much each past token matters (its attention score). This requires holding all past tokens in graphics-card memory. For a million-token document, this explodes the memory bill.

Today's trick: cut tokens to a fixed budget (e.g., keep only the 512 most important tokens from the past). But this misses a real problem. In some layers of the model, the attentional focus is sharp—a few tokens carry almost all the weight. In other layers, it is broad—many tokens matter roughly equally. A fixed budget wastes space in the sharp layers and starves the broad ones.

The fix. Tactic replaces the fixed token budget with a flexible goal: keep selecting tokens in order of importance until their attention scores sum to a target fraction (e.g., 90 percent of the total attention).

The algorithm as a flow

What it actually does

Compute raw attention scores

For each new token the model is generating, compute a raw score for every past token (the dot product between the new token and each past token).

Sort by score (approximately)

Rank the past tokens by their scores using a fast clustering method instead of a full sort.

Accumulate until reaching target

Pick tokens from highest score downward until the sum of their normalized scores reaches a target fraction (e.g., 90 percent).

Estimate boundary tokens efficiently

Use a smooth curve fitted to score samples to estimate scores near the cutoff line, avoiding expensive computation.

Fetch and compute

Load the selected tokens into memory and run the full value computation on just those tokens.

What the paper changes

What the paper changes

Tactic changes the token selection rule. Instead of: 'keep a fixed number of tokens,' the rule is: 'keep tokens until their cumulative attention score reaches a target.'

The hidden quantity

The hidden quantity: cumulative attention score

measured quantity  =  Cumulative attention score

For a given query (a new token the model is generating), the attention scores tell us how much each past token contributed. The cumulative attention score is simply the sum of these scores as we go down the ranked list. A target of 0.9 means: keep adding tokens until their scores sum to 90 percent of all attention scores put together.

Tactic estimates this quantity efficiently by observing that attention scores follow a smooth curve (most fall near the middle; scores are not clustered at the extremes), so a fitted curve can predict how many tokens we need to hit our target without looking at every single score.

Why it works

Why this works: bounded error by design

Old sparse attention picked a fixed number of tokens and hoped they covered most of the attention load. If a layer had sparsity (only a few tokens mattered), it wasted memory keeping irrelevant tokens. If a layer had low sparsity (many tokens mattered equally), it discarded important ones.

Tactic instead says: 'I will keep tokens until I have captured 90 percent of the total attention weight.' Why does this work? Because attention scores are multiplied by value vectors (the actual information), and value vectors have similar norms (sizes), the cumulative attention score directly bounds the error in the output. Capture 90 percent of the attention weight, and you automatically bound your approximation error. No per-layer tuning, no fixed budgets—the mechanism is automatic.

To make this efficient, Tactic observes that attention scores follow a smooth curve. Instead of examining every score, it fits a curve to a small sample, uses that curve to estimate how many tokens are needed to hit 90 percent, and stops early once it reaches the target. This turns a potentially expensive sort into a cheap calculation.

Math after the picture

The equation and worked example

First in words:

attention_output = sum over selected tokens i of (attention_score_i times value_i), where attention_score_i is renormalized by the sum of selected scores to keep them as fractions.

Then the compact form:

o_sparse(I) = sum_i_in_I (softmax(q·k_i / sqrt(d))_i * v_i), with constraint: sum_i_in_I softmax_score_i >= P (target fraction)

Every symbol:

qthe query vector (representing the new token being generated)
k_ithe key vector of the i-th past token
v_ithe value vector of the i-th past token
dthe dimension (the size of each vector; typically around 128)
softmax_score_ithe normalized importance weight for token i, a number between 0 and 1
Pthe target fraction (e.g., 0.9 to keep 90 percent of attention)
Ithe index set of selected tokens
A tiny worked example
Suppose we have 10 past tokens with attention scores [4.0, 3.5, 3.0, 2.0, 1.5, 1.0, 0.8, 0.6, 0.4, 0.2].
Total score sum = 4.0 + 3.5 + 3.0 + 2.0 + 1.5 + 1.0 + 0.8 + 0.6 + 0.4 + 0.2 = 17.0.
Target P = 0.9 (keep 90% of total).
Target cumulative = 0.9 × 17.0 = 15.3.
Pick tokens in order: 4.0 (running total = 4.0) + 3.5 (7.5) + 3.0 (10.5) + 2.0 (12.5) + 1.5 (14.0) + 1.0 (15.0) ≥ 15.3? No, 15.0 < 15.3.
Add token 6: 15.0 + 0.8 = 15.8 ≥ 15.3. Stop.
Selected: 6 tokens (not 9). Fixed-budget method (if set to 6) happens to work here; but if sparsity differed, it could pick 6 irrelevant tokens or only 3 important ones. Tactic adapts automatically.

The constraint ensures that the selected tokens carry at least a target fraction of the full attention load, which bounds the error in the output approximation.

What can go wrong

What can go wrong

Target too high. If the target fraction is set to 0.99, you keep almost all tokens, defeating the speedup.
Curve fit is inaccurate. If attention scores do not follow a smooth curve (e.g., a sharp spike in importance), the fitted curve mispredicts the cutoff, selecting too many or too few tokens.
Outlier scores break the curve. If one query has a single very high attention score and the rest are tiny, the curve fit may place the boundary in the wrong region.
Done right. In practice, attention scores follow a smooth curve for most queries in most layers; Tactic's curve fitting works well, and the 0.9 target (or 0.8 to 0.95 range) balances speed and accuracy.
What a runnable demo should prove

What a runnable demo should prove

Run Tactic on a real language model (e.g., Llama3.1-8B) over a long-context benchmark (e.g., LongBench). For each generated token, record: (1) how many tokens were kept by a fixed-budget method at budget 512, (2) how many tokens Tactic kept at target 0.9, (3) the attention approximation error for each, and (4) the output token's next-token prediction accuracy.

speedup = (time to compute full attention) / (time to compute sparse attention); approximation_error = max_over_heads_and_layers of (full_attention_output - sparse_attention_output); end_to_end_speedup = (time for full-attention model) / (time for Tactic model)

The demo should make clear that Tactic picks fewer tokens than a high fixed budget and roughly as many as a well-tuned low budget, while keeping approximation error uniformly small across all layers.
