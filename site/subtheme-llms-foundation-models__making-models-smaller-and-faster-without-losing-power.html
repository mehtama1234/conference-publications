Making models smaller and faster without losing power

These papers compress large models and make them run quicker by removing unnecessary parts, using distillation and quantization, so they work on regular computers and phones.

All themesField mapMathematicsAll explainers
What this is

The most capable language models today are enormous—they have billions or even trillions of parameters, which means they require expensive GPUs to run and can only work on servers, not on your phone or laptop. But many tasks do not need the full power of a giant model. Papers in this area tackle the question of how to take a large, smart model and compress it into something smaller that still works well. The main techniques are quantization, which means storing numbers with less precision so they use less memory, and distillation, which means teaching a small model to imitate the behavior of a large one. The small model learns from the large model's outputs and becomes an approximation of it.

The tricky part is that smaller is not always simpler—a model that is too small will fail at tasks the original handled easily, which means you lose capability. Researchers have to figure out which parameters matter most and which can be removed or simplified without hurting performance. They also face a speed versus accuracy tradeoff: aggressively quantizing a model makes it fast but inaccurate because you throw away information, while keeping it more precise takes more time to run because there is more data to process. Some papers study how to quantize strategically so different parts of the model are compressed differently based on how sensitive they are, which means some parts lose more precision than others because they matter less.

The payoff is huge: a small, fast model can run on a phone and give answers in milliseconds instead of seconds, which means users get instant feedback. This opens up use cases that were impossible before, like offline assistants (no internet needed), real-time translation on mobile devices, or local processing that does not need to send data to the cloud, which protects privacy. As phones and edge devices get faster, finding the right tradeoff between model size and quality becomes increasingly important for making AI accessible, because edge devices are where most people will interact with AI.

How the work breaks down

Compressing large models divides into five key directions: teaching small models to imitate large ones through distillation, storing numbers with fewer bits so they take less space, speeding up generation without retraining, fine-tuning models efficiently with tiny adapters, and making sparse networks (where only some experts activate) work well.

Distilling knowledge from large to small models

When you compress a model by distillation, you face a core challenge: the small model learns to mimic the large one, but knowledge can get tangled or lost in translation. Some information from the teacher conflicts with other information, forcing the student to choose sides. The papers in this group tackle how to transfer knowledge cleanly and completely so the small model gets all the useful reasoning power without learning contradictions.

Exploring Knowledge Purification studies how to remove conflicting signals when multiple teacher models disagree with each other, allowing the student to learn from the best parts of each teacher without getting confused. KaVa takes a different angle by compressing the model's memory cache (which stores past words to speed up processing) and distilling from that compressed memory, so the small model learns to reason just as well but using less memory when running. Catching the Details trains on only 10K question-answer pairs but achieves massive accuracy jumps by having the small model distill visual understanding from a large one, showing that distillation works even with tiny datasets if the teacher is good. Critique-Guided Distillation improves reasoning specifically by having the teacher show its reasoning step by step, and the student learns not just the answer but the reasoning flow that led to it, which helps on math problems. Don't Ignore the Tail shows that even the "hard cases" a model struggles with can be distilled well, so small models can become good at math while staying efficient. Reasoning Scaffolding distills the actual flow of thought—the way a model builds up ideas step by step—rather than just the final answer, creating students that reason genuinely instead of just mimicking answers. These approaches all recognize that distillation works best when you transfer not just outputs but reasoning structure.

These papers reveal a spectrum: some distill compressed representations (KaVa), some distill from multiple teachers cleanly (Exploring Knowledge Purification), some distill reasoning structure itself (Reasoning Scaffolding), and some focus on hard cases or reasoning-heavy tasks. They show the small-model bottleneck is not learning facts but learning how to reason under constraints.

Extreme bit reduction and 1-2 bit models

Extreme bit reduction is the most aggressive way to shrink a model: instead of storing each number with high precision (32 bits), you store it with just 1 or 2 bits, shrinking the model by 16 times or more. But extreme bit reduction throws away most information, so reasoning performance crashes unless you do it very carefully. The question is: which layers can tolerate aggressive bit reduction, and which need to stay precise?

Towards Bit-Reduction-Aware Training for Ultra-Low-Bit Reasoning LLMs trains a model to expect extreme bit reduction from the start (not after training), because the model's weights can adapt to the compression as they're learning, which helps Qwen3-8B survive being compressed to 2 bits while keeping reasoning accuracy, beating models compressed the naive way where you compress after training is done. Tina achieves 43% accuracy on AIME24 (a very hard math benchmark) using a 1-bit Qwen model that costs under $10 to run, a 260 times cost reduction over full models, showing 1-bit models can still do symbolic reasoning. 1-Bit Wonder studies what happens when you force weights to 1 bit and use clever clustering of similar weights to preserve accuracy, showing that under fixed memory budgets, 1-bit models actually win on text generation. Beyond Outliers reveals which optimizers (like Shampoo) keep accuracy best when models are compressed, because some optimization methods amplify compression errors more than others. Rethinking Residual Errors shows that when you compress a model, you leave behind leftover error (the difference between the real weights and the compressed ones), and systematically correcting that error lets you compress more aggressively without quality loss. Together these papers show that extreme bit reduction works if you train models right from the start and understand which parts of the model amplify compression errors.

Speeding up generation without retraining

Generating text one word at a time is slow because each word requires a full forward pass through the entire model. Speculative decoding and parallel approaches generate multiple words in parallel or draft words quickly then verify them, cutting wall-clock time dramatically. The challenge is doing this without retraining the model—these are run-time tricks.

dParallel Learnable Parallel Decoding trains a small adapter on top of reasoning models to predict multiple future words at once, reducing decoding steps by 8 to 10 times on math and code while keeping accuracy perfect. ARC-Decode speeds up generation by accepting draft word proposals from a cheap model if they meet a risk threshold—words that are very unlikely to be wrong get accepted without the main model checking them, giving 1.6 times speedup over earlier methods. Fast-dLLM v2 enables diffusion language models to generate multiple words per denoising step instead of one per step, with 2.5 times speedup from a frozen base model. Fast-dLLM achieves 27.6 times throughput improvement by letting diffusion models cache their intermediate computation and decode in parallel, closing the speed gap between diffusion and traditional sequential generation. Hierarchy Decoding uses a tree structure to decode diffusion language models in parallel, with words at different levels decoded independently, achieving 17 times speedup over vanilla diffusion decoding. LK Losses optimizes speculative decoding's core mechanism—the draft model's word predictions—so they align better with the main model's acceptance patterns, improving the fraction of proposed words the main model agrees with. All these papers bypass retraining: they either add lightweight adapters or change the decoding procedure, making them plug-and-play upgrades to existing models.

Efficient fine-tuning with tiny add-on modules

Instead of updating all billions of model weights when fine-tuning, you can add tiny learnable modules (adapters) that are 0.1–1% of model size, then tune only those. The model's core weights stay frozen, so you can customize one base model for 100+ tasks without bloating storage. The challenge is making sure these tiny adapters are expressive enough to teach the model new skills.

ABBA-Adapters uses structured adapters with high power, achieving the best results on reasoning benchmarks by packing more learning capacity into each adapter. BA-LoRA (Bias-Alleviating Low-Rank Adaptation) fixes a bias that adapters inherit from the pretrained model—older weights in the model have learned patterns the adapter blindly copies, which hurts transfer to new tasks because the adapter just memorizes what the old weights did rather than learning something new, so BA-LoRA explicitly removes this bias and gets better stability. PERK does test-time learning with adapters, meaning when the model runs it adjusts its adapter weights based on the current input so that it can respond to that specific question, tuning itself on-the-fly for each question, achieving up to 20% better performance on long-context reasoning without training-time changes because the model becomes responsive to the specific context. TiTok transfers knowledge at the word level between adapters from different models, showing you can train one model's adapter then transfer its learned patterns to another model's adapter, gaining 4-8% accuracy without training from scratch. Cartridges trains compressed long-context representations that the model learns through self-study (training to predict its own behavior), using 38.6 times less memory than standard in-context learning while keeping accuracy, and extending usable context from 128k to 484k words. These approaches show adapters work best when you inject knowledge smartly (preventing bias inheritance), adapt at test time (not just training time), or compress knowledge first (like Cartridges does).

Mixture-of-Experts: routing and specialization

Mixture-of-Experts (MoE) models have dozens of "experts" (small neural networks), and a router chooses which experts to use for each word. This lets you have massive total capacity but only activate a small fraction of the weights per word, making generation fast. The tradeoff is getting experts to specialize without repeating work or leaving some unused.

Not All Models Suit Expert Offloading reveals that offloading unused experts to CPU to save GPU memory comes with hidden costs because moving data back and forth between CPU and GPU is slow, and this slowdown hurts more for experts you actually need: some experts are genuinely more useful than others (word-list experts help less than domain-specialized ones), so naive offloading strategy fails to account for which experts matter most and ends up slowing things down by offloading the wrong experts. Balancing the Experts shows that when you optimize through reward signals on MoE models using only a few adapters per expert, internal mechanics of expert balance guide which adapters should change, improving reasoning without extra training stages. DirMoE uses a mathematically sound routing method where the router is trained to directly target a desired number of active experts, giving precise control over compute-accuracy tradeoff instead of approximate load balancing. Expert Divergence Learning trains MoE models to make experts diverge from each other on purpose—if experts learn different patterns, they specialize rather than redundantly learning the same thing, improving performance across benchmarks. Routing alignment improves generalization of MoE routers by ensuring the router learns a smooth decision boundary, reducing performance gaps on new domains by refining the router on target tasks. These papers show MoE works best when you understand which experts are truly useful, route with sound math, and explicitly encourage specialization.

Training-efficient model compression

Compressing a model can require expensive retraining, but some approaches minimize training cost by pruning intelligently before training, using reward models that require few examples, or collecting targeted data. The goal is small models with minimal compute spent during training.

Learning Ordinal Probabilistic Reward from Preferences trains lightweight reward models (used to score model outputs during RL training) by learning relative rankings instead of absolute scores, improving reward accuracy while staying small and cheap to train. Null-Space Filtering enables model merging—combining multiple models into one—without retraining by computing what new knowledge to add in directions that don't overlap with old knowledge, keeping all existing capabilities while absorbing new ones. Pre-training under infinite compute identifies which training changes (data mixing, architectures, etc.) best prepare a model for distillation, using only 5.17 times less data than baseline while reaching the same asymptotic performance, then transfers those gains to smaller models through distillation. Cram Less to Fit More shows that pruning training data (removing redundant examples) before training lets small models memorize more facts than standard training, with a 1.4B model matching a 14B model on fact recall, suggesting data quality beats raw quantity. Making Expert Reasoning Learnable with Self-Distillation achieves 31% gains on reasoning with fewer than 1000 expert solutions, using self-distillation (training the small model on its own generated reasoning steps) to bootstrap learning. These papers focus on preventing wasted compute: smart data selection (pruning), training on less data (pre-training insights), or learning from tiny example sets (reward models, self-distillation).
