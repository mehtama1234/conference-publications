PhaseFormer: Efficient Time Series via Phases Instead of Patches

Instead of treating tiny time segments as individual tokens, group them into full repeating cycles and compress each cycle down to a single learned pattern.

Paper explainersAll themesTime Series & Sequential

Time series data often repeats in patterns (daily sales, seasonal trends, heartbeat rhythms). Recent methods chop these into tiny pieces and treat each as a separate token, which works well but requires many weight numbers stored in memory and takes a long time to train and run. PhaseFormer groups repeating cycles into phases, compresses each phase to a single learned shape (a fixed-size list of numbers), and routes information between phases efficiently, achieving top-ranked accuracy on common benchmarks with only 1,000 weight values.

Why chopping into pieces backfires

Time series forecasting means predicting the next values in a sequence (stock prices tomorrow, traffic next hour, sensor readings next minute). If data has a repeating pattern, a smart system should recognize it and extrapolate.

Recent methods break the time series into many tiny overlapping windows (called patches), treat each window as a separate token (like how a language model treats words, but applied to time instead), and run a transformer on the token sequence. This works—it improves accuracy because having many small tokens lets the model learn fine-grained patterns, like the exact minute within an hour when values peak. But it has a hidden cost: chopping a long sequence into thousands of small tokens requires millions of weight numbers stored in the transformer. Training takes a long time and running the model uses lots of memory.

A beginner might try: just use more layers and bigger models. This backfires: more layers mean more weight numbers to learn, and bigger models waste their capacity trying to find patterns in millions of tiny patches when the true repeating structure (the cycle) is much simpler. The real problem is not a missing layer; it is that the fundamental unit (the tiny patch) does not match the structure of the data. Repeating patterns are fundamentally at the cycle level, not the piece level.

The method in one sentence. PhaseFormer groups data into complete repeating cycles, learns one compact pattern per cycle, and routes information between cycles.

What the paper changes

What the paper changes

Instead of processing tiny patches as separate tokens, PhaseFormer treats each complete repeating cycle as a single unit. A cycle is one full heartbeat, one day of traffic, one season of sales. By moving from patch-level tokens to phase-level tokens, the token sequence becomes much shorter, so the model needs far fewer weight numbers stored in memory.

The hidden quantity

The cycle importance score

measured quantity  =  phase routing weights

PhaseFormer learns a routing score for each cycle type. This is a number between 0 and 1 for each phase that says how much that cycle should influence the next forecast. For example, if the data is daily temperature with weekly patterns, the router might learn that yesterday's cycle is most important (score 0.6), the cycle from a week ago is secondary (score 0.3), and older cycles are noise (score 0.1).

The paper measures these scores during training: by looking at which phases the router emphasizes, you can discover what time scales the data actually obeys. This is invisible in patch-based methods because the transformer buries the decision in millions of learned weights hidden inside complex calculations; here it is plain to see.

Why it works

Why phase-level processing is more efficient

Patch-level methods force the model to learn which tiny pieces matter by assigning weights to every pair of pieces. Most of those weights are wasted: a piece from yesterday's 3am is almost never relevant to today's 3am; it is the time of day (the phase within the cycle) that matters, not the exact piece. The transformer has to discover this pattern through millions of learned numbers.

PhaseFormer fixes this by grouping all pieces at the same position within a cycle into one phase, and learning just one routing score per phase. For daily data with 48 time steps per day, an old method might have 48,000 patches in a long series and need to assign weights to 48,000 squared (2,304,000,000) pairs. PhaseFormer has 48 phases and a simple 48 squared (2,304) router. Same information, but the model is forced to make the important pattern (time of day matters) obvious and built-in. Training converges faster and uses far fewer weight numbers because the structure matches how the data actually works.

Math after the picture

The routing score equation

First in words:

For each phase, multiply the phase embedding by a learned weight matrix to get a score; normalize across all phases to get routing weights that sum to 1.

Then the compact form:

weight_p = softmax(W * embedding_p) ; forecast = sum_p(weight_p * embedding_p)

Every symbol:

weight_pthe normalized routing score for phase p (a number from 0 to 1)
Wa learned weight matrix that converts embeddings to routing scores
embedding_pthe learned compact vector for phase p
softmaxa function that turns raw scores into probabilities (all non-negative, sum to 1)
forecastthe predicted next value from combining weighted phases
A tiny worked example
Suppose a daily pattern has 3 phases: morning (6am-12pm), afternoon (12pm-6pm), night (6pm-6am).
Learned embeddings: morning = [0.8, 0.2], afternoon = [0.3, 0.9], night = [0.1, 0.7].
Weight matrix W (random example): [[2, -1], [1, 2]].
Raw scores: W * morning = [2*0.8 + (-1)*0.2, 1*0.8 + 2*0.2] = [1.4, 1.2].
W * afternoon = [2*0.3 + (-1)*0.9, 1*0.3 + 2*0.9] = [-0.3, 2.1].
W * night = [2*0.1 + (-1)*0.7, 1*0.1 + 2*0.7] = [-0.5, 1.5].
Sum of exponentials: exp(1.4) + exp(1.2) + exp(-0.3) + exp(-0.5) = 4.06 + 3.32 + 0.74 + 0.61 ≈ 8.73.
Softmax: morning gets (exp(1.4) + exp(1.2)) / 8.73 = 0.86 (high), afternoon 0.09, night 0.05 (low).
Forecast ≈ 0.86 * morning_value + 0.09 * afternoon_value + 0.05 * night_value. Morning dominates because its scores were highest.

The weight matrix W learns to score phases; a probability normalization function turns those scores into percentages that add up to 100. The forecast is a weighted blend of phase shapes, with higher percentages on phases the router learned to trust.

What can go wrong

What can go wrong

Cycle length misidentified. If the data has cycles of 24 hours but you tell the model the cycle is 12 hours, phases will misalign. Yesterday's 3am aligns with today's 3pm, which are opposite patterns. The model cannot learn useful shapes for each phase because the phases are garbage.
Multiple overlapping cycles. Real data often has cycles at many scales (daily, weekly, seasonal). PhaseFormer as described above works best with one primary cycle. If you pick weekly but the data is driven equally by daily and yearly patterns, the phase shapes will blur together and lose important detail.
Non-stationary (drifting) patterns. If the repeating pattern slowly changes over time (like growing seasonal peaks in an expanding business), the fixed phase shape cannot adapt. Training on old data will not predict new data accurately.
Done right: known, stable cycles. PhaseFormer shines when the cycle length is known (calendar-based timestamps make this easy) and the pattern is stationary (the shape of each cycle stays roughly the same). Most regular business and scientific time series fit this bill.
What a runnable demo should prove

What a runnable demo should prove

Build a synthetic daily temperature time series with a clear 24-hour cycle (warm afternoon, cold night) plus some noise, spanning at least 14 days. Implement PhaseFormer with 24 phases (one per hour) using only learned shapes (fixed-size lists of numbers) and a simple router (a set of weights that computes routing scores using a probability normalization function). Compare it against a patch-based baseline with the same target accuracy. Measure weight count, training time, and final forecast error.
