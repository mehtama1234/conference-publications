Task-Aware Data Selection via Proxy-Label Enhanced Distribution Matching for LLM Finetuning

When picking training data for a language model, match both the instruction wording and the right answer for each task, not just the wording alone.

Paper explainersAll themesOther

Fine-tuning (adapting) a pre-trained language model to a new task requires careful choice of training examples. Existing methods pick examples by looking at whether the instruction wording matches the task. This paper says you should pick based on both the instruction and the correct answer together. Since the correct answers are unknown for most of the data, it uses the model itself to guess them first, then uses those guesses to pick the best training examples.

Zero assumption version

Picking training data by matching only the instructions

When you fine-tune (adapt) a large language model to answer questions in a specific way, you start by choosing which training examples to use. Today, methods pick training data by asking: does this instruction match our task instructions? But they ignore the answer side of the problem. Imagine teaching a child to recognize cats by only showing different picture styles and ignoring whether they actually show cats. You might pick beautiful images that have nothing to do with cats.

The naive approach: score each training example by how similar its instruction text is to your task's instruction text. Pick the highest-scoring ones. The problem: two tasks can have identical-looking instructions but completely different correct answers. You might select training data where the instruction matches perfectly but the model learns the wrong answers.

In one sentence. The paper picks training data by checking if both the instruction wording and guessed correct answers match the task, not just the wording.

The algorithm as a flow

What it actually does

Take a pool

Start with a large unlabeled set of instruction examples (300K in their experiment).

Guess answers

Run the language model to generate a guessed answer for each instruction; these are proxy labels.

Filter noise

For a small labeled validation set, check if the guessed answers match the ground truth; discard examples where guesses are wrong.

Match the pattern

Measure how close the instruction wording and guessed answer patterns are to the target task; pick examples with highest alignment.

Train

Fine-tune the model on the selected subset (10K examples) until convergence.

What the paper changes

What the method changes

The paper changes what information is used to pick training data. Instead of scoring each example based only on instruction text similarity, it scores based on both the instruction wording and the guessed correct answer together (a pair of things that go together). This paired check ensures the model learns not just the task style but the task's actual answer pattern.

the object it moves  =  Selection criterion: from instruction-only to instruction-plus-label
The hidden quantity

The hidden quantity: label-guided fit

measured quantity  =  How well the guessed answers match the task

The paper measures something invisible but vital: the degree to which each example's guessed answer aligns with the task's answer pattern. Not all guesses are equally confident. Some guesses are highly certain (the model has strong conviction); others are uncertain (the model is torn between multiple answers). The hidden quantity is a score—call it label-guided fit—that captures this alignment. High fit means the guessed answer patterns match what the task actually needs.

The method estimates this by comparing guessed answers to a small labeled validation set. If the guesses match the ground truth labels, fit is high. If they conflict, fit is low. This score then guides which examples to keep and which to discard.

Plain reading. Each training example has two parts: the instruction and its answer. The paper measures how confident the model's guessed answer is and whether it matches ground truth. High confidence + high accuracy means the example is trustworthy for training.
Paper reading. The paper calls this proxy-label quality or label-guided fit. It is used in the two-stage filtering process: first to remove noisy examples, then to rank remaining candidates by how well they match the task's pattern.
Why it works

Why matching both instruction and answer works

The mechanism is simple: training data works best when it aligns with the actual task. If you train only on instructions that look like your task but with random answers, the model learns to copy the instruction style without learning the correct reasoning. By requiring that both the instruction wording and the guessed answer match the task, you ensure every selected example teaches the right lesson. The model sees instruction patterns paired with the correct response pattern—the full task structure.

The proxy-label trick lets you do this without hand-labeling 300K examples. The model's own guesses (proxy labels) are often reliable when filtered through a small labeled validation set. After filtering, the remaining examples are high-quality training data that contains the full joint structure of the task. Fine-tuning on these clean examples is more efficient than on all 300K because the model spends less effort unlearning wrong patterns—every selected example reinforces the correct instruction and answer pairing, so training converges faster.

Math after the picture

The selection scoring equation

First in words:

score for example i equals similarity of instruction to task instructions times similarity of guessed answer to task answers

Then the compact form:

score_i = w_inst * sim_inst(X_i, task_X) + w_label * sim_label(proxy_Y_i, task_Y)

Every symbol:

score_ihow good example i is for selection
X_ithe instruction text of example i
proxy_Y_ithe answer the model guessed for example i
task_Xthe reference instruction for the task
task_Ythe reference answer for the task
sim_insthow similar two instruction texts are (high if they match)
sim_labelhow similar two answers are (high if they match)
w_instweight given to instruction similarity
w_labelweight given to answer similarity
A tiny worked example
Suppose the task is a math word problem. Reference instruction: solve this equation. Reference answer pattern: numerical solution with steps.
Example A: instruction=solve this equation, guessed answer=numerical solution with steps. Scores: sim_inst=0.95, sim_label=0.90. With w_inst=0.5, w_label=0.5: score_A = 0.5*0.95 + 0.5*0.90 = 0.475 + 0.450 = 0.925.
Example B: instruction=solve this equation, guessed answer=random text. Scores: sim_inst=0.95, sim_label=0.10. Score_B = 0.5*0.95 + 0.5*0.10 = 0.475 + 0.050 = 0.525.
Example A ranks higher because its guessed answer aligns with the task; the instruction and answer pairing fits the task better.

The equation ensures that only examples with good instruction similarity and good answer similarity are selected; this is the two-way filter that avoids selecting on wording alone.

What can go wrong

What can go wrong

Proxy labels are wrong from the start. If the model generates proxy labels that are far from correct, selection fails because it is based on those bad guesses. The validation-set filtering catches obvious errors but misses systematic blind spots.
Validation set is too small or biased. The two-stage filter relies on a small labeled validation set to judge which proxy labels are correct. If this set is tiny or does not represent the task well, filtering is ineffective.
Task has multiple correct answers. Some tasks have many valid responses. Proxy-label matching assumes one right answer per instruction. Measuring similarity of answers becomes ambiguous.
Done right. The method works well when the model can generate plausible answers, the validation set is representative, and the task has clear right and wrong answers. It selects efficiently without human labeling.
What a runnable demo should prove

What a runnable demo should prove

A demo should show that selecting 10K examples by both instruction and guessed-answer alignment trains a model more efficiently than selecting 10K by instruction alone or than training on the full 300K. Start with a public fine-tuning dataset (like ALPACA or a subset of an instruction-tuning benchmark) and an unlabeled instruction pool from the same domain. Generate proxy labels, filter them, and compare fine-tuning performance across three runs: baseline using 10K random examples, naive using 10K by instruction similarity alone, and this paper's approach using 10K by joint alignment. Measure final task accuracy on a held-out test set.

efficiency = test_accuracy_achieved / (examples_selected) — higher means same accuracy with fewer training examples

The demo must show that paired selection (matching both instruction and answer) closes the gap between 10K and 300K, proving that this method works.
