Just-In-Time Reinforcement Learning: Continual Learning in LLM Agents Without Gradient Updates

Adapt an agent at test time by retrieving earlier successful trajectories and shifting the model's next-step output scores, without changing model weights.

Paper explainersAll themesAgents & Tool Use

Deployed language-model agents are usually frozen. If the environment changes, standard reinforcement learning can adapt them, but that often requires expensive weight updates and may erase earlier skills. This paper asks whether a deployed agent can still improve from new experience without retraining the model itself, because the current action can still be adjusted even when the weights stay fixed. The proposed answer is to keep a memory of past trajectories, estimate which next actions were rewarded in similar states, and use that estimate to tilt the agent's next choice on the fly.

Zero assumption version

Why frozen agents struggle to keep learning after deployment

A deployed agent keeps facing new tasks, new website layouts, or new game states. If its weights stay fixed, it can only rely on what it already learned before deployment. Full reinforcement learning could adapt those weights, but that is costly and risky because updating weights for one new setting can damage earlier behavior.

The paper focuses on a narrower question: can the agent improve its next action right now, during interaction, by using earlier experience as guidance. That would allow continual adjustment because the improvement happens at decision time instead of during a heavy retraining job.

The paper's move in one sentence. Store past trajectories in a non-parametric memory, retrieve the trajectories most relevant to the current state, estimate which actions had higher return there, and add that estimate directly to the model's next-step output scores.

The algorithm as a flow

What it actually does

Store trajectories in memory

Keep past states, chosen actions, and returns in a searchable memory because later decisions may need similar evidence.

Retrieve relevant cases

When a new state appears, fetch earlier trajectories that are close to the current one so the agent can reuse local experience.

Estimate action advantage

Compare how well different actions did in those retrieved cases because the agent needs a direction for the current choice.

Adjust the next-step output scores

Add the estimated action preference directly to the model's output scores so that higher-return actions become more likely.

Act and update memory

Take the chosen action, observe the result, and add the new trajectory back into memory for future decisions.

What the paper changes

What the paper changes

The paper changes where adaptation lives. Instead of changing model weights, it changes the temporary decision score at action time by using retrieved experience from memory.

the object it moves  =  the step where reinforcement learning updates are applied
The hidden quantity

The hidden quantity

measured quantity  =  the action advantage in the current state

The key hidden quantity is advantage: how much better one action is than the agent's usual choice in the current state, because that gap says how strongly the current decision should be shifted. The agent does not observe that number directly. It must estimate it from similar past trajectories and their returns.

JitRL uses memory because similar states can reveal which action tended to pay off. That estimate matters because the current action score should rise only when the memory says that action led to stronger outcomes in related situations.

Why it works

Why this works: change the current decision instead of the weights

A full weight update spreads its effect across many states, which is expensive and can alter behavior that had already been working. JitRL takes a narrower path. It asks what should change for this one decision in this one state, then changes only that temporary score.

That works when memory retrieval is good because similar past trajectories carry local evidence about action quality. If the retrieved cases show that one action repeatedly led to higher return, adding that preference to the next-step output score can improve the current choice immediately. The method also avoids forgetting because the base weights remain untouched.

Math after the picture

Shift action scores by the estimated advantage

First in words:

A compact summary is that the new decision score for one action equals the base model score plus an advantage estimate taken from relevant past trajectories, under a constraint that keeps the new policy close to the old one.

Then the compact form:

new_score(action) = base_score(action) + eta * estimated_advantage(action)

Every symbol:

new_score(action)score used to choose one action after test-time adjustment
base_score(action)the original model score for that action before memory-based adjustment
estimated_advantage(action)how much better that action appears in retrieved trajectories
etastrength of the test-time adjustment
A tiny worked example
Suppose the base model gives action A a score of 6 and action B a score of 5.
Retrieved trajectories show that action B led to higher return in similar states, so its estimated advantage is 3 while action A has estimated advantage 0.
With eta = 1, the new score for action A stays 6 and the new score for action B becomes 8.
The agent now prefers action B because the retrieved evidence says B paid off more often in related cases.
No model weight is changed; only the current choice uses the adjusted scores.

The paper proves that this additive update is the exact solution of a constrained policy-improvement problem, which is why a simple score shift can stand in for an explicit training loop.

What can go wrong

What can go wrong

The memory may retrieve the wrong cases. If similar-state search is poor, the estimated advantage can point toward the wrong action because the update is built on irrelevant evidence.
Coverage may be too sparse. If memory contains few useful trajectories, the agent may have no strong basis for adjustment because the current state has not been seen in a related form before.
Score shifts can become too large. If the adjustment strength is too high, one noisy memory estimate can dominate the base model because the temporary update overwhelms the original scoring pattern.
Done right. The method is most useful when trajectory retrieval is reliable and the score shift stays moderate, because then the update adds local evidence without drowning out the base policy.
What a runnable demo should prove

What a runnable demo should prove

Build a small web-navigation or game agent that receives reward after each episode. Compare three settings: no adaptation after deployment, full fine-tuning after batches of episodes, and a JitRL-style memory system that adjusts only the current action scores.

Track success rate, update cost, and retention on old tasks. The JitRL-style setting should improve within a session because retrieved trajectories guide the next choice, and it should retain old behavior because the base weights never change.

adapt_gain = success_after_memory_update - success_without_update ; update_cost = runtime_update_spend

The result should show that test-time policy improvement can be practical when the system borrows reward information from memory instead of retraining the whole model.
