Generalizable and Actionable Parts Pose Estimation with Symmetry Annotation-Free Learning Strategy

Instead of asking humans to label what symmetries an object has, predict them directly from the data.

Zero assumption version

The symmetry ambiguity problem

A robot's gripper needs to know where a part is and how it is rotated. For a simple rectangular block, there is one correct answer. But for a cylinder, a cone, or a fork, many rotations produce identical pictures. If a cylinder is pointing up, rotating it in place gives the same view—so the pose estimator sees 360 degrees of equally valid answers. Earlier methods ask a human to manually label which objects are rotationally or mirror-symmetric. This works in the lab, but in real warehouses and homes, objects come in thousands of varieties, and humans cannot label them all.

A naive approach tries to guess one pose anyway, even when symmetries exist. The model picks an answer and moves on. But when the true pose is rotated relative to the predicted pose, the robot makes mistakes—it reaches to the wrong part. Without knowing that rotational symmetry exists, the loss function punishes the model equally for any rotation, even though several rotations are correct.

The method in one sentence. Predict symmetry types as probability patterns directly from point cloud data, without asking humans, using a two-stage pose refinement process that computes distance to symmetric equivalent poses.

The algorithm as a flow

What it actually does

Stage 1: Scan the point cloud

Read the 3D point cloud (the shape of the object) and extract features using a specialized layer that preserves how the shape is rotated.

Stage 2: Generate candidates

The model produces several candidate poses (quaternions, a way to represent rotations). An encoder learns the distribution over these candidates.

Stage 3: Encode the distribution

Combine the candidates and point cloud features into a detailed representation that implicitly knows about symmetries.

Stage 4: Refine the pose

Compute each candidate's distance to all symmetrically equivalent poses and refine the candidate by adjusting it in a space where rotations are flat (the tangent space).

Stage 5: Aggregate to final

Combine refined candidates using a learned aggregation to produce the final pose prediction.

What the paper changes

The one thing that changes

The paper changes how the model handles the symmetry problem. Instead of requiring a human to label symmetry types in advance, it changes the loss function and learning process to measure symmetry directly from the data. The key shift is treating symmetry prediction as a probability distribution—learning what symmetries are likely given the shape—rather than a discrete yes-or-no choice.

The hidden quantity

The hidden quantity: symmetry scores

measured quantity  =  distance to symmetric equivalents

The paper introduces a hidden quantity that measures whether a candidate pose is far from or close to all poses that are rotationally or mirror-equivalent. For a cylinder, many rotations are equivalent. The model measures the minimum angular distance from each candidate pose to the set of all equivalent poses. Small distance means the candidate fits well within the symmetry family; large distance means it is an outlier.

The paper estimates this quantity using a self-supervised loss function. During an early warm-up stage, the model constrains candidate poses without knowing the true symmetry axis. It computes which axis of rotation would make the candidates most similar (closest to each other in the angular sense). Then it uses that axis to generate equivalent solutions and measures how far each candidate is from them.

Paper reading. The paper minimizes an angular distance loss. For each candidate pose, it finds the closest symmetric equivalent and computes the angle between them. It averages this over all candidates. This computes the smallest angle between the candidate pose and any symmetric equivalent.
Why it works

Why it works: symmetry-aware refinement

The mechanism has two parts. First, instead of predicting a single pose, the model generates multiple candidates and learns their distribution. This distribution implicitly encodes what the model knows about possible symmetries. If the object is rotationally symmetric, the candidates will cluster around multiple equivalent rotations. If it is asymmetric, they will cluster around one.

Second, the model uses this distribution to refine itself. It computes each candidate's distance to all symmetric equivalent poses. Poses that are close to their equivalents are rewarded (low loss). Poses that are far from any equivalent are punished. Over many training steps, this forces the model to learn which rotations are actually equivalent. The model never sees explicit symmetry labels; instead, it discovers symmetries by observing which poses are self-consistent with the data and with each other. By the second stage, the learned distribution guides the refinement of candidate offsets, ensuring the final pose respects symmetries the model has learned.

Math after the picture

The symmetry loss equation

First in words:

For rotational symmetry, the loss is the average minimum angle between each candidate pose and any of its symmetric equivalents. A candidate that aligns well with its family of equivalent poses gets a low penalty.

Then the compact form:

L_rot_cand = 1/K sum_j min_i [ 2 * arccos(abs(dot_product(q_candidate_j, q_equiv_i))) ]

Every symbol:

Knumber of candidate poses generated
q_candidate_jthe j-th candidate pose (a quaternion, a 4-element rotation representation)
q_equiv_ithe i-th symmetric equivalent of the true pose
arccosinverse cosine function; 2 * arccos gives angular distance in degrees
dot_productinner product of two quaternions, measuring their similarity
min_ipick the equivalent pose closest to the candidate
A tiny worked example
Assume a cylinder (rotationally symmetric around its axis). The true pose is "pointing north". Rotating 90 degrees also produces "pointing north" — so there are 4 equivalent poses (0, 90, 180, 270 degrees).
Candidate 1 is at 0 degrees. Distance to nearest equivalent: 0 degrees (matches the 0-degree equivalent exactly). Loss contribution: 2 * arccos(1.0) = 2 * 0 = 0.0.
Candidate 2 is at 85 degrees. Distance to nearest equivalent: 5 degrees (closest to 90-degree equivalent). Loss contribution: 2 * arccos(cos(5°)) ≈ 2 * 5° ≈ 0.17 radians.
Candidate 3 is at 45 degrees. Distance to nearest equivalent: 45 degrees (between 0 and 90). Loss contribution: 2 * arccos(cos(45°)) ≈ 1.57 radians.
Average loss: (0 + 0.17 + 1.57) / 3 ≈ 0.58. Candidates 1 and 2 are rewarded (low contribution); Candidate 3 is punished (high contribution). Training adjusts the model to produce Candidate 1 or 2.

By measuring distance to symmetric equivalents, the model learns which rotations are equivalent without explicit labels. The low loss for candidates close to equivalents drives the model to discover symmetries.

What can go wrong

What can go wrong

Incorrect symmetry prediction in warm-up. If the model misidentifies the symmetry axis during the warm-up stage, it will compute equivalents incorrectly. The loss function will steer it toward a wrong symmetry family. This is why the warm-up phase is important: it bootstraps the symmetry discovery by constraining candidates without yet relying on the predicted axis.
Ambiguous shapes with multiple valid symmetry interpretations. A shape might have both rotational and mirror symmetry. If the model is uncertain, it may predict both and split its confidence. The aggregation step might then average incorrect poses instead of picking the right symmetry type. The paper tests what happens when symmetry types are mislabeled intentionally to verify the model does not fail badly.
Poor point cloud quality or partial views. If the point cloud is noisy or only shows one side of the object, the model cannot infer the full shape and its symmetries. The extracted features will be weak, and the candidates will scatter instead of clustering by symmetry. This limits the method to reasonably clear point clouds.
Done right: symmetry emerges from data. When the point cloud is clear and the two-stage refinement works, the model discovers symmetries automatically. It does not need human labels, scales to new object types, and produces consistent poses across symmetric equivalents.
What a runnable demo should prove

What a runnable demo should prove

A demo builds a pose estimator on the GAPartNet dataset (a standard benchmark of robotic part poses). It trains the model with the SAFAG loss (self-adaptive symmetry learning) and tests it on objects with known symmetries. The demo should show that the model learns symmetry-aware poses automatically, without requiring the dataset to include symmetry labels. It should measure rotation error (the angle between predicted and true pose) and show that this error is small even for symmetric objects where multiple rotations are equally valid.

Rotation error (degrees) = minimum angular distance between predicted pose and any symmetric equivalent of the true pose

The demo must show that error is low on symmetric objects even without symmetry labels, and that the model generalizes to object categories it did not see during training.
