WebFactory: Compressing LLM Knowledge into Web Agents

A system that teaches web-browsing agents by synthesizing practice environments and reinforcement learning from the LLM's own knowledge, rather than hiring humans to label data.

Paper explainersAll themesAgents & Tool Use

Training agents to browse the web and use tools typically requires either running live, unpredictable websites (which can break), or paying humans to annotate thousands of examples. WebFactory sidesteps both by creating its own synthetic websites and teaching an agent through reinforcement learning to navigate them. An LLM already knows the internet from its training; the real bottleneck is converting that static knowledge into actions the agent can actually perform.

Zero assumption version

The training bottleneck: data is scarce and environments are fragile

To teach a web agent to do things like book a flight or fill out a form, you need examples of the agent seeing a website and taking the right action. Humans can provide those examples, but that is slow and expensive. Alternatively, you can run the agent on real websites, but websites change constantly, can break unexpectedly, and may have terms of service that forbid this kind of automated testing.

A beginner might think: just ask the LLM to describe what it would do if navigating a website. But descriptions are not the same as actions. The LLM is trained on text; it does not actually click buttons or type into forms. An agent needs to learn what each action looks like in practice—how to read the page layout, which HTML elements matter, how to chain actions together when one step fails. That gap between knowing and doing is the real problem.

In one sentence. WebFactory automatically creates synthetic websites and trains an agent to navigate them using reinforcement learning, extracting actionable skills from the LLM's existing knowledge.

What the paper changes

What the paper changes: the agent's action choices

The paper does not retrain the LLM itself. Instead, it trains a separate agent module that learns to map from a webpage layout (the visual and text structure the agent sees) to concrete actions (click, type, scroll, submit). The object being shaped is the agent's decision-making: given a page, which action is correct right now.

the object it moves  =  action selection policy
The hidden quantity

The hidden quantity: embodiment potential

measured quantity  =  embodiment potential

The paper introduces a new concept: different LLMs vary in how well their knowledge converts into real-world actions. An LLM with high embodiment potential is one whose internal representations (the learned patterns) naturally map to agent behavior; one with low embodiment potential requires more training data or harder optimization to teach the same skills. It is not measured directly but inferred from how quickly and accurately the agent learns on synthetic data.

The paper estimates embodiment potential by training agents on the same synthetic tasks using different LLM backbones and observing which ones reach high performance with fewer examples or faster convergence. This becomes a new dimension for comparing foundation models: not just accuracy on text, but how readily their learned patterns (the associations and rules encoded in their weights) transfer into grounded action.

Why it works

Why it works: compressing knowledge into behavior

The LLM has absorbed patterns from the entire internet: how forms are laid out, what buttons typically do, the logic of e-commerce flows, etc. But those patterns live in the LLM's weights as statistical associations between words, not as executable rules. WebFactory extracts those patterns by creating controlled environments where the agent practices and receives immediate feedback.

Here is the cycle: (1) WebFactory generates a synthetic task (e.g., book a flight). (2) The LLM is asked to plan the steps in words (e.g., click the departure date field, enter the date, click search). (3) The agent learns to recognize those page elements from pixels/HTML and execute the steps. (4) When the agent succeeds, its action choices get reinforced. (5) When it fails, the reinforcement learning algorithm nudges the agent's internal model toward different action patterns. Over dozens of synthetic tasks, the agent builds a reusable policy—a decision function that maps observations (what the page looks like) to actions (what to do). This policy generalizes because the patterns the agent learned (button locations are usually clickable, text fields accept typed input, forms have a submit button) hold true across websites.

Critically, the synthetic environments are designed to be diverse enough that the agent learns concepts, not memorization. If WebFactory always put the submit button in the same place, the agent would memorize that location, not learn the concept. Instead, the system generates new layouts for each task, forcing the agent to abstract the underlying structure.

Math after the picture

The learning update rule

First in words:

The reinforcement learning loss combines three components: minimize the error between predicted and true action values, plus separate reward signals for different subtasks (e.g., reading page layout, choosing an action, confirming the outcome).

Then the compact form:

L = L_value + w_action * L_action + w_parse * L_parse

Every symbol:

L_valueError in predicting which action leads to success
L_actionError in choosing the right action given the page
L_parseError in reading and understanding page elements
w_actionWeight controlling how much to penalize wrong actions
w_parseWeight controlling how much to penalize misreading
A tiny worked example
Agent sees a login page. It predicts the departure date field has value 5.0 (scale 0-10), but correct value is 8.5.
Value error = (5.0 - 8.5)^2 = 12.25.
Agent chooses to click the confirm button; correct action is to click the date field. Action error = 1.0.
Agent misreads the page structure (low L_parse). Total loss = 12.25 + 1.0 * 1.0 + 0.5 * 0.2 = 13.6.
On the next attempt, the algorithm lowers the weights controlling action prediction, nudging the agent to reconsider.

The decomposed loss lets the system separately improve reading comprehension, action selection, and value estimation—each a different skill—because if all three were mixed into one error signal, the optimizer would not know which part of the agent's behavior to change; separating them ensures poor performance in one area (e.g., misreading the page) gets directly corrected without masking other improvements.

What can go wrong

What can go wrong

Synthetic environments too simple. If all generated websites follow the same template (form always in the center, button always below), the agent memorizes the template instead of learning general concepts. The system must vary layouts widely and unpredictably so the agent abstracts structure rather than memorizing specific positions.
LLM's plan is wrong. The LLM provides the sequence of steps the agent should take. If the LLM's plan is nonsensical (e.g., enter a date before selecting which date field), the agent is trained to do the wrong thing. The system needs feedback to detect and correct bad plans.
Agent overfits to specific visual patterns. If the synthetic websites all have text fields with the same font color, the agent learns to look for that color rather than understanding that a text field is where you type. Real websites have many visual styles, so the agent must be exposed to variety during training.
Done right. The system generates diverse, realistic website layouts; validates LLM plans before training; and uses reinforcement learning rewards tied to task completion (an objective measure), not surface similarity. This forces the agent to learn generalizable concepts.
What a runnable demo should prove

What a runnable demo should prove

A demo should train an agent on synthetic versions of a few common tasks (e.g., booking, form-filling, search-and-retrieve) and then test it on real websites it has never seen. The goal is to show that the agent can handle real-world HTML and visual variation, not just the synthetic environments.

generalization_gap = performance_on_training_websites - performance_on_unseen_real_websites

The core claim is that WebFactory cuts the generalization gap in half or more compared to purely supervised learning, meaning the agent learns the underlying concepts that transfer to the real web, not brittle surface patterns.
