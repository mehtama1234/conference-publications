Directed Sheaf Neural Networks

A directed graph network that respects edge directionality by representing information flow as complex-valued maps.

Paper explainersAll themesGraph & Geometric Learning

Most graph networks treat edges as two-way streets: a link from A to B looks the same as a link from B to A. Real-world systems often have direction—emails flow from sender to receiver, water flows downhill, recommendations point from rater to rated item. This paper adds direction to sheaf neural networks, the most general class of graph models, so that arrows through the network point the right way and information flow respects which direction you are actually traveling.

Zero assumption version

Undirected graphs ignore arrow direction

Most graph networks send the same message along an edge no matter which direction you travel. If node A sends something to node B, and node B sends something back, both paths look identical to the network. But real systems have asymmetry: water flows down a hill, not up; a recommendation flows from person to reviewer, not backward.

A naive fix is to treat every directed edge as two separate undirected edges and let the network learn which direction matters. This works sometimes, but it wastes the network's learning budget—the network has to figure out from scratch that the asymmetry is built into the edge itself, rather than being told this upfront. The best graph networks use geometric structures that bake in what you already know about the problem; undirected models cannot do this for directed graphs.

The paper's move. Use directed cellular sheaves: a geometric structure that assigns each edge a complex-valued (two-part) linear map, where the imaginary part encodes which direction the edge points, so information flow respects the arrow.

The algorithm as a flow

What it actually does

Step 1: Assign lists of numbers to graph nodes and edges

Each node and edge holds a vector (a list of numbers). For directed sheaves, these are complex-valued (each number has a real and imaginary part).

Step 2: Encode direction in complex restriction maps

The linear map that moves data from node u to edge e includes the imaginary part—a rotation in the complex plane—to encode which way the edge points.

Step 3: Build the Directed Coboundary Operator

This operator (the discrete derivative for sheaves) is defined as: take the restriction map from node u applied to u's data, subtract the restriction map from node v applied to v's data, for each edge. Each map has direction built into it.

Step 4: Compose into the Directed Sheaf Laplacian

Combine the coboundary operator with its conjugate transpose to build a spectral operator (a matrix whose eigenvalues describe the graph structure). This new operator respects direction: messages traveling one way are weighted differently than messages traveling the other way.

Step 5: Use in network layers

Replace the undirected Laplacian in graph network computations (convolution: combining messages from neighbors) with the directed one. Each layer now correctly routes information along directional flows, sending and receiving differently.

What the paper changes

What the paper changes

The paper replaces the undirected cellular sheaf with a directed one. Every restriction map—the linear transformation that governs how information flows from a node to an adjacent edge—now encodes the direction of the edge via its complex-valued structure. This one change ripples through: the coboundary operator becomes directed, the Laplacian becomes directed, and the entire neural network now treats edges differently depending on which way they point.

The hidden quantity

The hidden quantity: directional bias in the network

measured quantity  =  Directional information encoded in map phase

Every linear map in the system is now complex-valued, meaning it has a real part (how much signal passes through) and an imaginary part (a phase rotation that depends on the edge direction). This imaginary component is the hidden quantity—it is the geometric encoding that breaks symmetry and tells the network which way the arrow points.

The paper estimates this quantity by hand-designing the restriction maps for each directed edge: for an edge from node u to node v, the map at node u gains an imaginary rotation proportional to the direction. During training, the network learns how strongly to weight this directional signal, but the signal itself is built into the structure from the start.

Why it works

Why directing the sheaf works

An undirected graph network treats all edges the same way no matter the travel direction, so it has to learn directionality from data alone—wasteful and error-prone. A directed sheaf bakes in the arrow as a geometric property: each restriction map includes a phase (imaginary part) that rotates differently depending on whether you travel with or against the edge. During the layer computation, messages traveling forward receive one complex-valued weighting, while messages traveling backward receive a different weighting. This asymmetry is baked into the operator itself, so the network does not waste training effort figuring out that arrows matter—it can focus learning on other patterns.

The Directed Sheaf Laplacian combines these oriented maps into a single spectral operator (its eigenvalues and eigenvectors describe the graph's overall structure). Unlike the undirected Laplacian, this operator's structure reflects the graph's directionality. When the network applies polynomial-based layer computations using this Laplacian, every layer respects which way information should flow. This helps because it means the network starts with a correct assumption about what arrows do, rather than having to discover this pattern from scratch in your training data—so it needs fewer training examples to reach good accuracy.

Math after the picture

The equation

First in words:

For each directed edge e from node u to node v, compute the coboundary δ by taking a complex-valued restriction map applied to u's data, minus a different complex-valued restriction map applied to v's data. The Directed Sheaf Laplacian is the coboundary operator composed with its complex conjugate transpose.

Then the compact form:

δ_e(x) = F(u→e) · x_u − F(v→e) · x_v ; L = δ* · δ

Every symbol:

δ_e(x)coboundary applied to cochain x at edge e
F(u→e)complex-valued restriction map from node u to edge e (includes phase for direction)
F(v→e)complex-valued restriction map from node v to edge e (includes phase for direction)
x_uthe data vector at node u
x_vthe data vector at node v
Lthe Directed Sheaf Laplacian (spectral operator)
δ*complex conjugate transpose of the coboundary operator
A tiny worked example
Suppose edge e goes from node u to node v, and both nodes hold data as complex numbers.
Restrict u's data via F(u→e) = 2 + 1i (real part 2, imaginary part 1i, encoding the forward direction).
Restrict v's data via F(v→e) = 2 − 0.5i (real part 2, imaginary part −0.5i, encoding the backward direction is weaker).
If x_u = 3 and x_v = 1, then δ_e = (2+1i)·3 − (2−0.5i)·1 = (6+3i) − (2−0.5i) = 4 + 3.5i.
The imaginary part (3.5i) captures that this edge is directional. If we reverse u and v, we get δ_e = (2−0.5i)·1 − (2+1i)·3 = (2−0.5i) − (6+3i) = −4 − 3.5i: the same magnitude but opposite sign. The directed structure is now evident.

The complex-valued restriction maps encode edge direction in their phase; the Laplacian captures this in its spectrum, breaking symmetry.

What can go wrong

What can go wrong

Badly designed phase encoding. If the imaginary part of the restriction map does not actually encode the edge direction (e.g., you set it randomly or to a constant), then there is no signal to guide learning, and the network collapses back to ignoring direction.
Symmetric or nearly symmetric data. If the real-world task has little actual asymmetry (many edges work the same in both directions), then the directed bias may not help and could even hurt by forcing the network to respect a distinction that does not matter.
Complex arithmetic overhead. Restriction maps are now complex-valued, so computing which way to nudge the weights (gradient computation: which direction to move numbers to shrink error) and memory use roughly double. For large graphs, this can be slow or run out of graphics card memory.
Done right. Encode direction carefully in the imaginary part of each restriction map, validate that the task is truly directional, and budget for the extra computation. Use polynomial-based layer computations to keep the cost reasonable.
What a runnable demo should prove

What a runnable demo should prove

Build a small directed graph (e.g., a citation network, recommendation graph, or transaction flow) and a node classification task where direction matters: does a paper recommend another paper? Does one account send money to another? Split into train and test. Train both an undirected sheaf network and DSNN. Measure test accuracy and sample efficiency (how many training examples do you need to reach the same accuracy on each model?). Also test on a held-out directed graph with the same structure but new nodes; measure generalization gap (how much worse does each model do on the new graph?).
