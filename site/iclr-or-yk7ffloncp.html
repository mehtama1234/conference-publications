SHIELD: Fixing Hallucinations in Vision-Language Models

SHIELD stops a vision-language model from inventing objects by fixing three problems inside the image encoder, not the language part.

Paper explainersAll themesMultimodal

When you show a vision-language model (a system that reads images and answers questions about them) a picture of a forest, it might tell you it sees a car, even though there is no car. The model is hallucinating. Researchers thought the language model (the part that picks words) was responsible. This paper shows the real culprit is the image encoder, the early-stage component that converts a picture into numbers. SHIELD fixes that encoder with three training-free patches: reweighting the numbers, filtering out false impressions, and testing with noise.

The Encoder is Biased, Not Just the Language Model

A vision-language model has two main parts: an image encoder (which reads pixels and makes numbers) and a language model (which picks words). When the system hallucinates, researchers have been trying to fix the language model side. But the real problem is earlier.

The image encoder suffers from three invisible biases. First, during training on billions of images, some objects (like cars, people) show up far more often than others. The encoder overemphasizes the tokens (the number patterns) for common objects, a problem called statistical bias. Second, it develops an inherent bias: it learns to recognize dominant objects so well that it produces fake representations of those objects even when they are not in the image, just from habit. Third, small noise or tiny changes to the image can flip the encoder's output entirely, a weakness called vulnerability. A beginner might try fixing this by retraining the whole system, but that is expensive and loses everything the model already learned.

In one sentence. SHIELD patches the image encoder in three ways without retraining: it rebalances the token weights, subtracts out learned false impressions, and tests the model against noise.

What it actually does

Find overemphasis

Compute which tokens spike above their typical size, marking tokens with statistical bias.

Reweight tokens

Reduce the influence of spiking tokens proportionally, so common objects do not dominate.

Estimate false patterns

Run the encoder on pure noise K times, observe which object patterns it invents anyway.

Subtract false patterns

Remove those invented patterns from the real tokens, eliminating inherent bias.

Contrast against noise

Generate predictions both from the clean image and from noisy versions, pick the stable answer.

What the paper changes

The One Thing That Changes

The paper changes the image encoder (the part that turns pixels into token numbers). It does not retrain it. Instead, it post-processes the tokens that the encoder outputs, using three lightweight fixes: reweighting, subtraction, and contrastive selection.

The hidden quantity

Token Deviation: How Much Each Token Sticks Out

measured quantity  =  Peak-to-average ratio

The hidden quantity is the peak-to-average ratio for each token: the maximum strength value divided by the typical strength value for that token across images. Strength is how large the number is. A ratio of 8 means a token spikes 8 times higher than normal, a sign of statistical bias. The paper estimates this by processing many images, computing the L2 norm (the total size) of each token, and measuring how often a single token stands out.

The paper measures this ratio for every token in the encoder output, ranks them, and identifies which ones are statistically overemphasized. The reweighting step then applies lower weights to high-ratio tokens, so the language model does not trust them blindly. This single number (peak-to-average ratio) is the diagnostic: high ratio means statistical bias is present, because large spikes happen when the training data is unbalanced. When you scale down a token with a high ratio (say from 50 to 5), you level the playing field so the language model treats that token's information as no more credible than any other token. This stops the language model from being seduced by the imbalanced training signal.

Plain reading. Imagine you track how tall a fence post looks in 100 photos. Most photos show it about 2 meters tall, but 2 photos show it 16 meters (lighting tricks). The peak-to-average ratio is 16 divided by 2, or 8. That is statistical bias: rare angles and lighting exaggerate its apparent height. SHIELD uses this ratio to spot which tokens are exaggerated and reduce their weight.
Paper reading. The paper defines statistical bias as over-reliance on frequent visual patterns in pretraining data. It quantifies this as the L2 norm of each token across a dataset, identifies tokens whose peak exceeds the average by a threshold, and applies a reweighting factor inversely proportional to this ratio during the forward pass of the language model.
Why it works

Why It Works: The Three Fixes

The mechanism is straightforward: fix the three problems in the encoder pipeline. First, reweight the tokens. The image encoder outputs N tokens, each a list of numbers. Because the training data has more cars and people than kangaroos, the car and person tokens tend to have larger values (higher strength, meaning the numbers are bigger). When the language model reads these tokens, it treats large values as more important, so it over-trusts the car and person information. Reweighting scales down the over-trusted tokens by their peak-to-average ratio, so every token carries a fairer share of influence. This directly reduces statistical bias.

Second, subtract false patterns from inherent bias. The encoder has learned to produce the 'smell' of a car even when no car is present, because it saw millions of cars during training. To estimate this ghost pattern, run the encoder on pure random noise K times (say, 10 times). Across all those noise inputs, the encoder still produces certain tokens consistently, even though there is nothing to see. That average output is the learned false pattern. Subtract it from the real token outputs. Now the real tokens reflect only what the image actually shows, not the phantom from training.

Third, address vulnerability via contrastive decoding. The encoder is fragile: add tiny noise to the image and it might output completely different tokens. Contrastive decoding works by generating two descriptions: one from the clean image and one from noisy versions of the image. The language model picks the answer that is stable across both—the answer that appears in both the clean and noisy branches. If a hallucination only appears in the noisy branch, it is discarded. This forces the model to predict only features that stay the same whether the input is slightly noisy or perfectly clean.

The Reweighting and Subtraction Formulas

First in words:

After encoding, reweight each token by the inverse of its peak-to-average ratio, then subtract the mean output of K noise runs, then pass to the language model

Then the compact form:

x_v_prime = (x_v / peak_avg_ratio) - (1/K * sum_k E(noise_k))

Every symbol:

x_vthe original tokens from the image encoder
peak_avg_ratiomax activation divided by average activation for that token
E(noise_k)the encoder output on the k-th noise input
Knumber of noise runs (typically 10)
x_v_primethe cleaned tokens fed to the language model
A tiny worked example
Suppose token 1 has strength 50, average 5, so peak-to-average ratio is 50 / 5 = 10.
Reweighting step: 50 / 10 = 5. The token is scaled down.
Now suppose the encoder on noise alone produces token 1 with average value 2 across 10 noise runs.
Subtraction step: 5 - (2) = 3. The false pattern is removed.
Before: token 1 = 50 (trusted strongly). After: token 1 = 3 (weak influence, bias removed).

The reweighting step dilutes tokens that stand out due to training-data imbalance. The subtraction step erases the phantom object patterns the encoder learned to produce. Together, they send honest tokens to the language model.

What can go wrong

What can go wrong

Noise runs must cover the inherent bias pattern. If the noise you use does not trigger the learned false patterns, the subtraction step will fail. You must use noise that is similar enough to trigger the phantom (e.g., Gaussian noise or image permutations), not completely orthogonal noise.
Reweighting may erase real signal if thresholds are wrong. If the peak-to-average threshold for calling a token overemphasized is too low, you will downweight legitimate tokens. This requires tuning based on the specific encoder and dataset.
Contrastive decoding is expensive. Generating predictions from both the clean image and multiple noisy versions requires running the language model many times per query, which increases latency.
Done right. Tune thresholds for reweighting by measuring the peak-to-average ratios on your specific encoder and dataset, use the same type of noise distribution as the pretraining perturbations, and precompute the noise-run means once per model to avoid recomputing them every query.
What a runnable demo should prove

What a runnable demo should prove

Build a small test: load a vision-language model (e.g., CLIP with a language head), load a benchmark image dataset where some objects are common (like cars, faces) and others are rare (like bongos, surfboards). Run the vanilla model and measure how often it names a rare object that is not in the image (hallucination rate). Then apply SHIELD (reweight the tokens, run the encoder on noise to estimate the false pattern, subtract, and use contrastive decoding). Measure hallucination rate again. Plot the drop. Finally, generate descriptions for the same images but with Gaussian noise added to the pixels. Measure description stability: does the model name the same objects, or do they change? Plot this before and after SHIELD.

hallucination_rate = (hallucinated_objects / total_objects) before vs. after SHIELD; stability = (% of objects named consistently in clean and noisy versions)

The demo is complete if SHIELD cuts hallucination rate by at least 50%, reduces it to single digits on benchmarks with heavily imbalanced training data, and makes the model's predictions stable to small perturbations.
