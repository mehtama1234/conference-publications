VR-Thinker: Boosting Multimodal Reward Models through Think with Image Reasoning

Turn a multimodal reward model into an active visual reasoner that can revisit images or frames during reasoning instead of relying on one overloaded initial prompt.

Paper explainersAll themesMultimodal

A reward model scores candidate outputs so a generative model can be trained or selected toward preferred behavior. In the visual setting, that reward model must judge images or videos as well as text. The usual setup packs all visual information into the first prompt. That creates two problems. First, images or videos consume a large context budget, meaning the limited number of items the model can process in one sequence, so the system often drops frames or compresses them too heavily. Second, when all visual evidence appears only once at the start, a long reasoning chain can drift away from it and forget small but decisive details. VR-Thinker changes the interaction pattern. It equips the reward model with visual reasoning operations, meaning explicit steps that can request or revisit visual evidence during reasoning, and a visual memory window that controls how much of that evidence stays active at each stage. The model is then reinforced to use those operations productively through staged training with curated traces, filtered successful examples, and group-based policy optimization.

Zero assumption version

Why passive visual prompting is weak for reward modeling

A multimodal reward model must often judge subtle visual details: whether a generated video matches motion intent, whether an image follows a textual preference, or whether a sequence contains artifacts. If the model sees the visual evidence only once at the beginning, long reasoning can lose track of which frame or region justified the judgment.

This weakness becomes severe for video because many frames compete for a limited context budget. The system either drops frames, compresses them too aggressively, or keeps them all and forces the reasoning chain to remember details over many steps. The paper argues that reward models should behave more like active inspectors: they should revisit evidence when needed instead of depending on a single passive upload.

The paper's move in one sentence. Give the reward model explicit visual reasoning actions and a controllable memory window so it can pull fresh image evidence into the reasoning chain when the current step needs it.

The algorithm as a flow

What it actually does

Start from a multimodal reward model

Use a model that scores candidate visual outputs, but extend it so reasoning can call explicit visual operations rather than depending only on the original prompt.

Define visual reasoning operations

Allow the model to revisit image regions or frames during its chain of thought, which means intermediate reasoning steps can ask for more visual evidence when the current memory is insufficient.

Control evidence with a memory window

Limit how much visual evidence remains active at one time so the model keeps relevant details nearby without overflowing the context budget, because stale visual content is dropped before it can crowd out the frames or regions needed for the current step.

Train in stages

First distill curated reasoning traces, then keep high-quality successful traces through rejection sampling, meaning retaining only better samples for additional tuning, and finally strengthen the policy with GRPO, meaning Group Relative Policy Optimization, a reinforcement method that compares several sampled trajectories within a group because those comparisons tell the model which retrieval-and-reasoning patterns lead to stronger judgments.

Use the trained reward model for visual preference scoring

Score images or videos with a reasoning process that can actively gather supporting evidence instead of depending on a frozen first impression.

The paper changes the interaction between reasoning and perception inside a reward model. Visual evidence is no longer a static prompt prefix. It becomes something the reasoning process can query and refresh.

The hidden quantity

The hidden quantity

measured quantity  =  how much decisive visual evidence is still available when the model reaches a late reasoning step

The hidden quantity is the amount of relevant visual detail that remains available after several reasoning steps. A reward model may begin with enough information, yet still fail because the detail needed for the final judgment has faded from working memory or was never loaded at sufficient resolution.

VR-Thinker raises that availability by letting the model fetch evidence when the current reasoning step requires it. The memory window also matters because it keeps recent useful evidence active while dropping stale content, so the model spends its limited context budget on what is relevant now.

Why it works

Why active visual reasoning improves reward models

The visual reasoning operations matter because multimodal reward scoring often depends on details that are easy to lose, such as one bad frame in a generated video or one small region that violates the prompt. If the model can query the relevant evidence when that question arises, it does not need to preserve every detail perfectly through a long text-only reasoning chain.

The memory window matters because active retrieval alone can still flood the context. The model needs a rule for keeping the currently relevant visual evidence and discarding content that no longer influences the judgment. That bounded window reduces overload while preserving recency of evidence.

The staged training pipeline matters because the model must learn both the format of the visual reasoning operations and the policy for using them well. Curated traces teach the structure of the operations. Rejection sampling keeps stronger trajectories for additional tuning because low-quality reasoning traces would otherwise reinforce bad habits. GRPO then sharpens the policy by comparing groups of sampled trajectories and raising the probability of the ones that produce more reliable judgments.

A tiny worked example
Suppose two generated videos look similar at a glance, but one contains a brief frame where the hand shape becomes implausible.
A passive reward model that saw only compressed initial frames may miss that defect.
VR-Thinker can revisit the suspicious segment during reasoning and keep those frames in the visual memory window while scoring.
If the retrieved evidence changes the judgment toward the correct preference, that trajectory receives stronger reinforcement during training.
Over time, the model learns to call retrieval operations on the parts of a sample that often decide the reward.

The important design choice is active evidence access. The staged optimization only exists to teach the model when and how to use that access well.

What can go wrong

What can go wrong

The model may retrieve the wrong evidence. Active operations help only when they target the relevant frames or regions, so poor retrieval choices can still waste context budget and miss the decisive detail because the wrong evidence occupies memory while the needed evidence never enters the reasoning chain.
The memory window can be too small or too large. If the window is too small, useful visual evidence is dropped before the decision. If it is too large, the original overload problem returns because stale content remains active.
Curated traces may bias the operation style. If the cold-start traces overrepresent one pattern of reasoning, the model may learn to use the operations rigidly until reinforcement broadens its behavior.
Done right. The method is strongest on tasks where the reward truly depends on revisiting fine visual evidence during a long reasoning chain, because that is where passive prompting is weakest.
