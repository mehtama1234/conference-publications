FlowState: Sampling-Rate-Equivariant Time-Series Forecasting

A time-series model that works at any sampling rate by learning continuous time instead of discrete time steps.

Time-series forecasting (predicting the next values in a sequence) usually trains on data collected at one fixed rate—say, daily observations. If new data arrives at a different rate (hourly or weekly), the trained model breaks. FlowState learns to think of time as continuous rather than as a fixed grid, so it can naturally handle data at any rate without retraining.

Zero assumption version

The grid-rate trap

Today's time-series models work like this: take data sampled at one fixed rate (say, a temperature reading every hour), train on it, then when new data arrives at a different rate (every 30 minutes or every day), the model fails. It has learned the rhythm of the original grid.

A beginner might try retraining on the new rate, but that is slow and wasteful. Or they might try to resample (stretch or compress the data), but that introduces artifacts and loses information. The core problem is that models bake in the assumption that time is chopped into uniform pieces.

The gap. FlowState learns that time flows continuously, not in chunks, so the same model handles any sampling rate.

The algorithm as a flow

What it actually does

Encode with continuous time

SSM reads the time-series and learns a latent state (a compressed representation) as a smooth function of continuous time, not discrete steps.

Extract the basis

Functional basis decoder expresses the time series as a weighted sum of smooth basis functions (like sine waves or polynomials), each valid across all times.

Query at any rate

To forecast at a new sampling rate, evaluate the basis functions at the new time points; no retraining needed.

Dynamic horizon

The model can forecast any distance into the future (5 steps or 100 steps) without retraining because the basis functions are continuous.

Small and fast

By learning in continuous time, the model is smaller and trains faster than models that must memorize every discrete time step.

The hidden quantity

The hidden quantity: equivariance

measured quantity  =  Sampling-rate equivariance

Equivariance is a formal name for a symmetry: the output transforms predictably when the input transforms. In FlowState, if you resample the input data at half the rate (take every other point) or double the rate (interpolate new points), the model's predictions transform by the same factor and remain valid. This is not automatic; it is built into how the model thinks about time.

The paper measures this by testing the trained model on datasets at sampling rates it has never seen before, checking that forecasts remain accurate. A model that learned discrete time steps would fail; FlowState succeeds because it learned the continuous skeleton underneath.

Why it works

Why it works: two layers, one vision

Any smooth time series can be written as a sum of simpler smooth pieces (basis functions like sine waves or Chebyshev polynomials). If you learn the coefficients of those pieces, you can regenerate the series at any resolution by evaluating the pieces at any time points you choose.

The SSM encoder compresses the observed time series into latent states that represent the coefficients of the basis functions. A state space model is a way to process sequences efficiently by maintaining a hidden state and updating it as you read each value; this lets the encoder learn from data sampled at any rate, because it does not assume a fixed grid.

The functional basis decoder reconstructs the time series from those learned coefficients. Because the basis functions are themselves continuous, forecasting at a new rate is just evaluating them at new times. No retraining, no discretization artifacts.

Math after the picture

The equation: linear sum of basis functions

First in words:

Signal as sum of basis: output equals sum over all basis functions of their coefficient times their value at time T.

Then the compact form:

y(t) = sum_i c_i * phi_i(t)

Every symbol:

y(t)the forecasted value at time t
c_ithe learned coefficient (weight) for basis function i
phi_i(t)the i-th basis function evaluated at time t
sum_isum over all basis functions
A tiny worked example
Suppose two basis functions: phi_1(t) = sin(t), phi_2(t) = cos(t).
Learned coefficients: c_1 = 2.0, c_2 = 0.5.
At time t=0: y(0) = 2.0 * sin(0) + 0.5 * cos(0) = 0.0 + 0.5 = 0.5.
At time t=pi/2: y(pi/2) = 2.0 * sin(pi/2) + 0.5 * cos(pi/2) = 2.0 * 1.0 + 0.5 * 0.0 = 2.0.
Same coefficients, different time points, valid predictions at any rate.

The coefficients are learned by the SSM encoder; the basis functions are fixed and smooth, so evaluating them at any time is stable.

What can go wrong

What can go wrong

Insufficient basis functions. If the time series contains high-frequency changes (rapid oscillations), but you choose too few basis functions, the model misses details and forecasts poorly. The fix: use more basis functions, at the cost of more memory and computation.
Extrapolation beyond learned range. Forecasting far into the future works only if the basis functions remain valid at those times. If the system changes its behavior over very long horizons, the stationary assumption breaks and predictions drift.
Non-stationary data. If the underlying signal evolves over time (e.g., a sensor drifts), the basis functions learned on early data become stale. The model assumes the signal is stable in structure.
Done right. Choose enough basis functions to capture the data's details, train on representative examples across time ranges, and test on unseen rates before deploying.
What a runnable demo should prove

What a runnable demo should prove

Build a synthetic time series (e.g., a mixture of sine waves and noise) and sample it at an initial rate (hourly). Train FlowState on this data. Then subsample or oversample the time grid (test at 30-minute or 4-hour intervals), and verify that the model's forecast error stays roughly constant. Compare against a baseline model trained only on hourly data, which should fail on new rates.

equivariance_hold = 1.0 - (max_error_new_rate / max_error_train_rate)

If equivariance_hold is near 1.0 for multiple unseen rates, the model truly learned continuous time.
