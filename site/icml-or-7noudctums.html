Controlled SDEs for Long-Horizon Motion Generation

Control instructions guide an agent's internal decision states through random noise, so predicted paths stay true to commands for long into the future.

Paper explainersAll themesTime Series & Sequential

When you predict how a person or animal will move over the next minute, you face a hidden problem: you cannot see their thoughts. Their brain is making decisions about where to go next, but those mental states are invisible and keep changing randomly as they plan. This paper builds a math tool that lets outside commands (like "move left") steer those invisible internal states, so the predicted motion path stays aligned with the commands all the way through.

Zero assumption version

Predicting motion when you cannot see the brain

Long-horizon motion prediction means guessing where a person, animal, or agent will move in the distant future (tens of seconds or minutes ahead). The standard approach: collect training data of past motion trajectories, build a model that learns the patterns, and then use it to predict new trajectories given an external command (a direction or a navigation goal). This works for short horizons (a few steps ahead), but breaks down over long horizons because internal invisible decision-making creates uncertainty that snowballs.

A beginner might try: train a simple neural network on past trajectories and let it predict forward. But this fails catastrophically. The network has no way to model that the mover has invisible internal thoughts — and those thoughts drift randomly over time in ways the network never saw in training. So predictions diverge from the given command: you ask for a leftward path, but the predicted trajectory wanders rightward by second thirty. The core issue is latent decision uncertainty — the internal mental states that would explain why the mover is doing what they are doing are unobservable, and they evolve in chaotic, random ways.

A second attempt adds randomness to predictions, but this also fails: random noise overwhelms the effect of the external command. Trajectories predicted hours ahead become meaningless noise, not useful motion guided by instructions.

In one sentence. The paper treats the invisible internal decision states as a random walk that commands can push and pull on, like steering a ship through fog by adjusting its drift direction without seeing where it is.

The algorithm as a flow

What it actually does

Recognize the hidden state

The mover's internal decision state is a random walk evolving continuously through time, invisible to you.

Split control into two channels

First channel: the command steers the drift (the average direction the state wants to move). Second channel: tune the diffusion (how much random jitter).

Modulate drift by command

The command does not directly predict motion; it nudges the hidden state's drift direction up or down, biasing the state toward goal-aligned thoughts.

Stabilize state evolution

The math guarantees the hidden state stays bounded (does not blow up to infinity), so noise does not overwhelm drift over long horizons.

Decode motion from state

At each time step, the current internal state deterministically produces the next position in the predicted path.

What the paper changes

What the paper changes

The paper changes how the invisible internal decision state evolves. Instead of a black-box neural network that learns any pattern, CogSDE replaces it with a controlled random differential equation (SDE) — a mathematical rule that explicitly separates how commands push the state (drift term) from how randomness enters (diffusion term). This separation makes the command's effect legible and tunable.

the object it moves  =  internal decision-state evolution
The hidden quantity

The hidden quantity: state boundedness

measured quantity  =  mean-square boundedness

The key hidden quantity the paper measures is how much the invisible internal state is allowed to wander. In mathematical language: mean-square boundedness — the average of the squared size of the internal state vector stays capped no matter how far into the future you predict. In plain terms: if the internal state is thought of as a point in a high-dimensional space of possible thoughts, that point drifts and jiggles, but the paper proves it will never drift arbitrarily far away from a home region.

Why does this matter? If the state is unbounded, randomness can push it into a region the model never trained on, and predictions collapse into noise. If the state is bounded, random walks stay interpretable. The paper establishes this bound using dissipativity theory (a control-theory tool that proves a system will settle into a limited region even under continuous random disturbance). This is the mathematical guarantee that lets long-horizon predictions remain faithful to commands.

Why it works

Why it works: steering hidden states through noise

The core idea is to model the invisible internal state as a continuous random walk (a random process) that commands can steer. The SDE has two parts: drift and diffusion. The drift term captures the intended direction — where the command wants the internal state to move (leftward, rightward, speed up, slow down), because the drift is the only part of the equation that responds to the command input. The diffusion term captures uncertainty — how much random jitter enters the state at each instant. By designing the diffusion to depend on the current state (not just pure noise), the paper keeps the jitter from overwhelming the drift.

Here is the causal chain: commands modulate the drift term, biasing the internal state toward a region that naturally produces goal-aligned motion. Random noise enters through the diffusion term, but its size scales with the state (state-dependent diffusion), preventing it from pushing the state into an untrained regime. The dissipativity property then guarantees that even with this noise, the state stays bounded. As the prediction rolls forward, the state's trajectory remains plausible and aligned with commands, because it is trapped in a learned region by the boundedness guarantee. When you decode the state into a motion path, you get a trajectory that hews to the command instruction across 30, 60, or 120 steps.

Math after the picture

The equation and what it means

First in words:

Change in state = command-modulated drift + state-dependent random noise. Drift term gets amplified when command is strong. Diffusion term shrinks when state is far from origin, keeping it bounded.

Then the compact form:

dx_t = a(s_t, u_t) dt + b(s_t) dW_t

Every symbol:

x_tinternal decision state at time t (invisible to you)
s_tshorthand for x_t (the state)
u_texternal command input at time t (the direction you want)
dta tiny time step forward (represents one prediction instant)
dW_ta tiny random kick (Gaussian noise with zero mean)
a(s_t, u_t)drift function: how much the state moves on average given state and command
b(s_t)diffusion function: the size of random noise, which depends on how far the state is from the origin
A tiny worked example
Suppose state x_t = 5.0 at time t, and command u_t says accelerate left (u_t = 2.0).
Drift a(5.0, 2.0) = (command influence) × 2.0 = 1.5 (the state wants to move left by 1.5 units this instant).
Diffusion b(5.0) = 0.4 (state-dependent: since state is moderately far from zero, random jitter is scaled to 0.4).
Random noise for this step: dW_t sampled as 0.3 (a Gaussian random number).
New state x_{t+1} = 5.0 + 1.5 * dt + 0.4 * 0.3 = 5.0 + (1.5 * 0.01) + (0.4 * 0.3) = 5.0 + 0.015 + 0.12 = 5.135.
The command pushed the state left by 0.015; random noise added 0.12, but because b(s) is state-dependent and bounded, the combined effect stays predictable.

The drift term is steered by commands, pulling the state toward goal-aligned regions. The diffusion term is controlled by the state itself, preventing noise from running away and keeping predictions honest over long horizons.

What can go wrong

What can go wrong

Diffusion scales too aggressively. If the random-noise term grows too fast as the state moves away from zero, then rare large random kicks can still break boundedness, and long-horizon predictions diverge.
Drift term underspecified. If the drift term does not strongly couple to the command, then the command's modulation is weak, and the internal state ignores instructions and drifts on its own.
Training data does not cover command space. If the model is trained on trajectories with commands in a narrow range (e.g., only moving left), it will fail when you apply a command outside that range (moving right), because the state region it learned is incomplete.
Done right. When drift is strongly modulated by commands, diffusion is state-dependent and bounded, and training covers the full command space, the predicted paths stay faithful to instructions even 60 or 120 steps into the future.
What a runnable demo should prove

What a runnable demo should prove

Build a simple synthetic dataset: a point agent (think of a dot on a 2D plane) that moves according to an external command (left, right, up, down) plus internal randomness. The internal state is hidden from the observer; only the position of the dot is visible. Train CogSDE on short motion sequences (5 to 10 steps), then predict 30 or 60 steps into the future with held-out commands. Measure how closely the predicted path aligns with the command direction (ideally the dot keeps moving left if the command is left, not wandering right after 20 steps).

alignment_error = angle_between(command_direction, predicted_trajectory_direction_at_step_T)

The demo succeeds when predicted paths stay within 30 degrees of the command direction even at step 60, proving that commands steer the invisible internal state and keep long-horizon predictions true to instructions.
