Complexity-Aware Anomaly Detection Using Time Series Foundation Models

Detect anomalies in time series data by measuring how difficult the data is for a pre-trained model, then mixing the model with a simpler statistical method when the model tricks itself.

Time series foundation models excel at predicting future values, but struggle to spot when data is broken or unusual. The problem: these models are too good at copying both normal and abnormal patterns, so they cannot tell the difference. This paper fixes it by measuring how hard the data is to model, and when the model gets overconfident, switching to a simpler statistical approach that catches what the model missed.

Why foundation models fail at detecting anomalies

Time series foundation models (large models trained on massive amounts of historical data to predict future values) work brilliantly for forecasting — they learn the patterns in clean data so well that they can guess tomorrow's numbers accurately. But anomaly detection needs the opposite: the model should reconstruct normal data well and stumble on broken or unusual data. Here is where they fail: these models are so capable that they reconstruct even the broken data accurately, masking the anomaly.

A naive approach tries to measure anomaly by how far the model's guess strays from the real value. If the guess is close, call it normal; if far, call it anomalous. But on data with slow, smooth trends (strong low-frequency components — slow drift, long cycles), the model learns the trend so perfectly that it copies abnormal spikes and dips just as well. The method breaks: the anomaly detector says both normal and abnormal sections are normal.

The problem in one sentence. Time series foundation models learn smooth patterns so well (like daily cycles that repeat for months) that they can copy even anomalies, making reconstruction error useless for detecting what is broken.

What the paper changes

What the paper changes

The paper introduces a complexity metric (a single number computed from each chunk of data) that tells the model when to back off. Instead of always trusting the foundation model equally, the method uses complexity to dial a knob: when data is simple (model explains it easily), rely more on the model; when data is complex (model struggles), blend in a statistical method that avoids overfitting.

the object it moves  =  the balance between model and statistics
The hidden quantity

The hidden quantity: Complexity

measured quantity  =  complexity (how hard the data is for the model)

Complexity is a score that measures how much the foundation model struggles on a chunk of data. It is not the prediction error itself; instead, it captures whether the data fits the patterns the model learned. If the model reconstructs the data easily (low error on all points), the data is simple — it follows the learned patterns. If some points are hard to predict (high error on those points), the data is complex — it contains things the model did not expect.

The paper defines complexity using the distribution of per-point errors (how far off each prediction is). High complexity means some points are very far off, suggesting the chunk contains unusual structure. The paper uses this to identify regions where the model might be fooled by anomalies.

Why it works

Why blending model and statistics works

The core problem is that foundation models overfit to anomalies on data with strong trends. When the model has learned a smooth pattern (for instance, a daily cycle that repeats 365 times), it becomes a master copier — it can even copy anomalies that break the pattern. Complexity detects this: when the model suddenly makes mistakes on certain points (high reconstruction error), those mistakes reveal mismatch between data and learned pattern.

The solution is to use complexity as a router. Regions with low complexity mean the model has learned the right pattern and will catch anomalies correctly. Regions with high complexity mean the model is confused, so switch to a statistical method (mean, variance, trend) that cannot overfit because it has only a few degrees of freedom. The statistical method keeps the honest mean and variance of the data, so a spike that the model copies will stand out as far from the statistic mean.

In practice: the ensemble computes two anomaly scores (one from the model, one from statistics) and blends them using the complexity weight. Anomalies live where the blended score is high. Complexity acts as an automatic gating mechanism because when the model is confused (error spread is large), the method automatically shifts toward the statistical baseline that avoids overfitting.

Math after the picture

The blending equation

First in words:

Anomaly score equals model score times (1 minus complexity weight) plus statistical score times complexity weight. Complexity weight is a function of how spread out the reconstruction errors are.

Then the compact form:

score_anomaly = (1 - w_c) * score_model + w_c * score_stats, where w_c = clip(std(errors) / threshold, 0, 1)

Every symbol:

score_anomalyfinal anomaly score that flags the point as broken or not
score_modelmodel-based anomaly score (reconstruction error or similar)
score_statsstatistical anomaly score (distance from mean or another rule)
w_ccomplexity weight, how much we trust statistics over the model
std(errors)standard deviation (spread) of the per-point reconstruction errors
thresholdcutoff value that maps error spread to a weight between 0 and 1
A tiny worked example
Data chunk: [10, 11, 12, 11, 10] followed by [100] then [11, 10].
Model reconstruction: [10.5, 11.2, 11.8, 11.1, 10.4] then [99.2] then [10.9, 10.1].
Per-point errors: [0.5, 1.2, 0.8, 0.1, 0.4, 0.8, 0.9, 0.1].
Error spread (std) = 0.4. Threshold = 0.5. Weight w_c = clip(0.4 / 0.5, 0, 1) = 0.8.
Model score (for the spike [100]): 0.8 (very confident it is normal). Stats score: 4.2 (far from mean).
Final score: (1 - 0.8) * 0.8 + 0.8 * 4.2 = 0.16 + 3.36 = 3.52 (strong anomaly signal).
Compare: model alone would say score 0.8 (miss the anomaly); statistics alone would say 4.2 (always flag spikes, even noise). Blend says 3.52 (confident, because the model was confused).

The complexity weight acts as an automatic switch: when the model is certain all errors are small, weight is near 0 and we trust the model; when errors are spread out, weight rises and we lean on statistics.

What can go wrong

What can go wrong

Complexity threshold is too high or too low. If the threshold for converting error-spread to complexity-weight is miscalibrated, the blend stays too heavily on one side (all model or all statistics). The method becomes just model or just statistics again, losing the benefit.
Data has very few anomalies in the training signal. If normal data is so clean that the model learns perfectly, there is no error-spread to trigger high complexity. The method may keep trusting the model even when anomalies arrive. The paper assumes some natural variation in normal data.
Anomalies are not spikes; they are gradual drifts. If the anomaly is a slow change in the mean over time, the statistical baseline (which assumes constant mean and variance) will not catch it. The model might still miss it too, if it learned a gradual trend.
Done right: anomalies are point-like or seasonal shifts. The method works best when anomalies are sudden (spikes, drops) or clear seasonal changes (e.g., a cycle that breaks). On these, complexity identifies confusion and statistics catch the deviation.
What a runnable demo should prove

What a runnable demo should prove

Build a simple time-series anomaly dataset with a clear normal pattern (e.g., a daily cycle that repeats 50 times) and inject a few obvious spikes or missing values. Load a small foundation model (or a simple linear predictor pretrained on the normal data). Compare three methods side by side: (1) model reconstruction error alone, (2) statistical distance from mean alone, (3) complexity-aware blend. Run all three on the contaminated data and measure true-positive rate (anomalies found) and false-positive rate (normal points wrongly flagged). The demo must make clear that the model alone misses anomalies when the pattern is smooth, and statistics alone over-flags noise, while the blend balances both.

The demo must show that on smooth-trend data, the model's reconstruction error alone cannot distinguish normal from anomalous, but the complexity-weighted blend recovers the signal by routing to statistics when confused.
