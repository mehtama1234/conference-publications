Adaptive Mixture of Disentangled Experts for Dynamic Graphs

Instead of using one fixed model for graphs that change over time, use many specialized models and pick the right one for each moment based on what kind of change is happening.

Paper explainersAll themesGraph & Geometric Learning

Graphs in the real world shift over time — new nodes appear, old edges vanish, connection patterns morph — and the reasons behind these shifts change too. A single fixed model learned once cannot adapt as the graph evolves. AdaMix watches for these shifts moment by moment, measures what kind of shift is happening, and routes the data through different specialized submodels, each trained to handle a particular type of shift. The result: the model stays accurate as the world rewires itself.

Zero assumption version

Why one model breaks as graphs age

A graph is a set of nodes (points) and edges (lines connecting them). In the real world — social networks, recommendation systems, traffic flows — these graphs do not stay still. New users join, friendships form and break, recommendations change because the platform evolved. The graph has shifted: its structure and meaning have drifted away from what it was before.

Today's methods build one model once on old data and use that same model forever. But a model learned when the graph was sparse will give wrong answers when the graph becomes dense. A model trained on the old recommendation rules will fail when the platform changes how it shows content. The shift breaks the model because the pattern it learned no longer matches reality.

A beginner might think: just retrain the whole model from scratch each time the graph shifts. But that is wasteful — you throw away what you learned before — and slow, because retraining is expensive. You need a way to detect which kind of shift happened and adapt just the relevant parts of the model.

The paper's fix in one sentence. Detect what kind of change just happened to the graph's structure, then choose which specialized expert model to use for this moment, rather than forcing one fixed model to handle all shifts.

The algorithm as a flow

What it actually does

Step 1: Watch the graph

Measure how the current connections differ from the past.

Step 2: Detect the shift

Identify which kind of change is happening (new nodes, lost edges, reordered ranks, etc.).

Step 3: Score each expert

For each of the pre-trained specialized models, compute how well it fits this shift.

Step 4: Route the data

Send the graph through a weighted mix of experts, favoring those that scored high.

Step 5: Output predictions

Combine the predictions from all experts, weighted by their scores, to get the final answer.

What the paper changes

The one thing the paper changes

Instead of using a single fixed neural network for every graph, the method uses multiple small neural networks (called experts), each trained to handle a different type of distribution shift. A second network (the router) watches the graph and decides how much to rely on each expert.

the object it moves  =  The routing weights: which expert to use
The hidden quantity

The shift signature: what the router measures

measured quantity  =  Shift type and severity

A shift signature is a description of how the graph has changed: for example, node density increased by 40 percent, but average neighbor count stayed the same, or new users joined but old edges vanished. The paper's router computes this signature by comparing the current graph structure to a history of past structures.

The router measures this using two sources: (1) historical patterns — what the graph looked like before — and (2) the current snapshot. From these, it computes scores that represent the kind and size of the change. High scores for shift-type-A mean the data matches what shift-type-A usually looks like; low scores mean it does not. These scores are the router's way of saying: I am confident this is shift-type-A or I am unsure.

Why it works

Why using the right expert makes predictions accurate

Each expert is a neural network trained on examples of one kind of distribution shift. If you train expert-A only on graphs where nodes are being added, it learns patterns specific to node-growth. It learns: when new nodes arrive, existing clusters usually stay stable, so focus on the core relationships. Expert-B, trained only on graphs where edges are reweighting (old connections matter less), learns a different pattern: look for which edges are still strong.

The router detects which shift is happening now and weights the experts accordingly. If the current graph shows signs of node-growth, it gives expert-A a high weight (trust it more) and expert-B a low weight (trust it less). When you combine the predictions from all experts using these weights, the heavily-weighted expert-A dominates, so the final prediction uses the pattern it learned. That pattern is exactly right for what is happening now.

Why does this work? Because the expert that matches the current shift has learned the invariant (the thing that stays true) for that particular shift. The invariant for node-growth is different from the invariant for edge-reweighting. By routing to the expert trained on the matching shift, you activate the right invariant for the current moment, not a one-size-fits-all guess.

The scoring and routing formula

First in words:

For each expert, multiply how well it matches the detected shift by the expert's output, then sum across all experts weighted by their scores.

Then the compact form:

prediction = sum_i (router_score_i * expert_i(graph))

Every symbol:

router_score_ihow confident the router is that expert i is right for this shift, ranges from 0 to 1
expert_i(graph)the prediction from expert i when given the current graph
sum_iadd up contributions from all experts
A tiny worked example
Suppose there are 2 experts. The graph looks like it is undergoing shift-type-A.
Router scores: expert-A score = 0.9 (high confidence), expert-B score = 0.1 (low confidence).
Expert-A predicts: that node-5 has rank 7 (out of 10).
Expert-B predicts: that node-5 has rank 4 (out of 10).
Final prediction = 0.9 * 7 + 0.1 * 4 = 6.3 + 0.4 = 6.7, call it rank 7.
Result: we mostly trust expert-A (which saw similar shifts in training) and barely trust expert-B, so we get an answer close to expert-A's.

The router's job is to spot the shift; the expert's job is to predict; combining them with the router's weights means the right expert leads the answer.

What can go wrong

What can go wrong

Router misidentifies the shift. If the shift detector looks at the current graph and guesses wrong about what changed, it will activate the wrong expert. The wrong expert will give poor predictions. This happens when the current shift is a blend of multiple types or when the shift is subtle and not easily distinguished from history.
Expert was not trained on this shift. If the graph undergoes a shift that the experts were never trained on in advance, they cannot have learned the right invariant. For example, if all experts were trained on graphs with 1000 nodes but the current graph has 100,000 nodes, the experts are out of their learned regime.
Mixing experts smooths away important detail. When the router is uncertain (all experts score similarly), the method averages their predictions. Averaging can wash out sharp patterns that only one expert sees. The final prediction becomes a bland average.
Done right. The method works best when the shifts are discrete and recognizable (node-growth vs. edge-loss are different enough to detect), when experts are trained on representative examples of each shift type, and when the true shift is in the set of shift types the model has seen before.
What a runnable demo should prove

What a runnable demo should prove

Build a small graph that changes over time by cycling through three shift types: (1) adding new nodes while keeping old edges, (2) removing edges from low-degree nodes, (3) reranking which edges matter. Train three experts: one on examples of shift-type-1, one on shift-type-2, one on shift-type-3. Use AdaMix to route through them as the graph cycles. As a baseline, also keep a fixed model that was trained once on the initial graph. Compare: as the graph shifts, does AdaMix stay accurate while the fixed model's accuracy falls?

accuracy_drop = accuracy_before_shift - accuracy_after_shift; measure this for both fixed model and AdaMix

The key finding: AdaMix accuracy stays nearly flat (drop near 0) across all three shifts, while the fixed model's accuracy falls by 10–20 percent each time the shift type changes.
