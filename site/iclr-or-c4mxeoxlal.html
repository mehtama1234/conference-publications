gLSTM: Storage Capacity for Graph Networks

Graph neural networks suffer from over-squashing because a node's fixed-size representation runs out of storage space for information flowing through the graph, but giving nodes associative memory (learned fast weights) gives them room to hold and retrieve more.

Paper explainersAll themesGraph & Geometric Learning

Graph neural networks pass information between neighboring nodes layer by layer. When many neighbors send their information to a central node at once, all that information gets squeezed into a single vector (a fixed-size list of numbers). This paper shows the problem is not just that the signal gets distorted in transit — it is that each node literally does not have enough storage space to hold all the important information its neighbors sent. By adding associative memory (a learned lookup table that stores and retrieves data during computation), this paper lets nodes store and retrieve more information, which fixes the problem on real graphs.

Zero assumption version

Why deep graph networks lose information

A graph is a set of points (called nodes) connected by edges. A graph neural network passes information between neighbors layer by layer, so deep networks can reach information far away. A node in layer 7, for example, can see information from all nodes that are 7 hops away.

But each node has a fixed-size representation — say, a list of 64 numbers. When many neighbors send their information to a central node, all that information gets squeezed into those same 64 numbers. The network can adjust what gets thrown away, but the storage space itself never grows. This is like having one shoebox to store everything your five friends hand you.

People used to think the problem was distortion during transmission — the signal gets noisy or flattened going through many layers. But this paper shows the real bottleneck is storage: the node representation simply does not have enough room to hold all the information coming in. So information is lost not because the path breaks down, but because there is nowhere to put it.

The naive approach and why it fails. A beginner might make the node representation bigger (use more numbers per node), but that just pushes the problem further — at some point a fixed vector still cannot hold everything needed. The paper instead gives nodes a learned lookup table they can write to and read from during computation to store and retrieve information on demand.

The algorithm as a flow

What it actually does

Step 1: neighbors aggregate their data

Each neighbor of a node sends its representation through the graph edges to the central node.

Step 2: standard layer updates the representation

The node takes those incoming signals and updates its fixed-size vector using a neural network.

Step 3: node queries its learned associative memory

The node computes a query (a learned projection) and uses it to look up related patterns in a learned key-value table.

Step 4: memory retrieval adds capacity

The retrieved values are combined back into the node representation, storing information that would otherwise be lost.

Step 5: richer representation flows downstream

In the next layer, this node passes a more informative representation to its neighbors.

What the paper changes

The one thing the paper changes

The paper adds a learnable associative memory module to each node in the graph network. The memory stores learned key-value pairs: the node computes a query from its current state, and the memory returns the values associated with the keys that match that query most closely. This lookup happens during each forward pass, alongside the normal message-passing update.

the object it moves  =  node representation storage (via associative memory)
The hidden quantity

Storage capacity: the quantity the paper measures

measured quantity  =  information storage capacity

Storage capacity is the amount of information a node can hold in its representation for later use by downstream neighbors. In this paper, it is not about the raw vector size; it is about how much relevant information from the input can be recovered from that representation later. A node with low storage capacity loses information and cannot pass it forward. A node with high capacity can hold many different pieces of information and retrieve them selectively.

The paper estimates storage capacity by creating a synthetic task (Neighbor Associative Recall, or NAR). In this task, a central node receives data from N neighbor nodes, each with a different key and a value. The job is to store all these key-value pairs in memory so that later, when given a query key, the node can retrieve the correct value. If the node's representation is too small or lacks memory, it fails to remember all the pairs — this failure directly measures capacity shortage. The paper shows that standard message-passing networks fail this task because they cannot store all N pairs in a fixed-size vector, but adding associative memory solves it.

Plain reading. A node can only pass along information it managed to store. If five neighbors send data but the node stores only two, the information from three is lost forever. Associative memory gives the node a lookup table so it can store and retrieve all five.
Paper reading. The paper defines storage capacity formally as the number of distinct key-value pairs a node can store and later recover from its representation after aggregation. This is measured on the NAR task and contrasted with the sensitivity-based view of over-squashing (which measures how error signals shrink going backward through many layers).
Why it works

Why adding associative memory fixes over-squashing

The mechanism is direct: a node receives many input signals and needs to store them in a fixed-size vector. With no memory, the network can only adjust which signals are emphasized or suppressed — the total information is still limited by vector size. Associative memory breaks that limit by letting the node write important information to a learned key-value table during the forward pass.

Here is the causal chain: (1) the node computes a query from its current state; (2) the query is matched against learned keys in the associative memory table; (3) the matching keys return their associated values; (4) those values are merged back into the node representation. This two-step storage-and-retrieval lets the node hold more distinct pieces of information than its base vector can encode. The downstream neighbor receives a richer representation, so information propagates farther without loss. Formally, the paper adapts mechanisms from the xLSTM architecture (which uses fast weights to expand capacity in sequence models) and applies the same principle here: replace simple vector representations with vectors plus a learned lookup mechanism.

The storage capacity equation

First in words:

Node representation updated by combining message from neighbors with retrieved values from associative memory, then passed forward.

Then the compact form:

h_v^(l+1) = combine(MPNN_update(messages_v), memory_retrieve(query_v))

Every symbol:

h_v^(l+1)the node representation after layer l+1
messages_vdata aggregated from all neighbors of node v
MPNN_updatestandard message-passing neural network transformation
query_vlearned projection of the current representation used to index memory
memory_retrievelookup in the learned key-value associative memory table
combinemerging operation (e.g. concatenation or weighted sum) bringing the two sources together
A tiny worked example
Suppose node v receives data from 5 neighbors. A 64-number vector can only hold a compressed version.
The node computes a query from its representation: query_v has 8 dimensions (a small projection).
The associative memory table has 16 rows (key-value pairs learned during training). The query matches 3 of them closely.
Those 3 values are retrieved and concatenated: 3 × 8 = 24 extra numbers merged back into h_v.
Now h_v combines 64 base numbers + 24 memory numbers = 88 total numbers worth of information. Information from all 5 neighbors can now be stored instead of discarded.

The central insight: do not make the base representation bigger; instead give it a side channel (memory) that expands capacity on demand.

What can go wrong

What can go wrong

Memory table becomes too large. If the associative memory is not constrained, it can grow so large that computation and storage become expensive. The paper limits this by fixing the table size and using learned retrieval, but very large graphs with many node types can push this limit.
Queries do not match relevant keys. If the learned query projections do not align well with the learned key structure, memory retrieval returns irrelevant values, adding noise instead of information. This happens when the model is undertrained or when the graph structure is very unusual.
Not all bottlenecks are storage-based. Some graphs may suffer from over-squashing due to poor gradient flow (sensitivity-based over-squashing), not lack of storage. This method targets capacity, so it will not help those cases fully.
Done right: capacity and sensitivity together. The paper shows from experiments that capacity over-squashing and sensitivity over-squashing are separate issues. This architecture improves capacity; combining it with methods that help error signals flow backward through layers (such as using exponential functions instead of contracting functions in each layer) gives the best results, because you are fixing both problems at once.
What a runnable demo should prove

What a runnable demo should prove

Build a shallow graph (2–3 layers) with a star topology: one central node connected to 20 neighbors, plus a query node connected only to the central node. Assign each neighbor a random key and value. Train a standard graph network (like GCN) and a gLSTM side by side to recover the value given a query key. Measure how many key-value pairs each network correctly recalls after training for a fixed number of steps.

capacity_score = (number of correctly recalled key-value pairs) / (total pairs in the neighborhood)

The demo should make it impossible to miss: as the neighborhood size grows from 5 to 20 neighbors, the standard network's capacity drops off sharply while gLSTM stays near 90%. That difference IS the paper's insight — storage space, not signal quality, is the limit.
