Entropy-Guided Group Relative Policy Optimization for Image Generation

Train image generators by giving harder optimization work to uncertain tokens and gentler updates to confident ones.

Paper explainersAll themesGenerative Models & Diffusion

Autoregressive image generation (building an image one step at a time, where each step is a small cluster of pixels) works well when combined with reasoning steps and reinforcement learning (learning from rewards). However, researchers didn't fully understand how these pieces interact. This paper discovers that low-certainty steps destabilize training, while high-certainty steps are already solid. The fix: treat each step differently during learning, protecting confident decisions and intensively optimizing uncertain ones.

Zero assumption version

Why mixing reasoning and rewards gets messy

Text-to-image models generate pictures one step at a time, like drawing with a pen that adds one pixel-cluster per step. Researchers found that if you first let the model write out reasoning (thinking about the prompt in words before generating the image), then apply reinforcement learning (nudging the model toward better images by rewarding good results), the images get better. But something odd happens: the training becomes unstable. Some runs produce beautiful images, others don't, even with the same prompt and same training settings.

A beginner might think: the reward signal is just too noisy, so we need a bigger learning step or more training. If we push the model harder toward rewards, everything should improve together. This breaks because it treats all tokens equally—both the confident decisions (already figured out) and the uncertain guesses (still exploring) get the same aggressive push. The confident tokens don't need that nudge; they get knocked off balance. The uncertain ones thrash around.

The fix. Split the training job: give confident tokens a gentle KL-only tap (keeping them stable) and give uncertain tokens an extra bonus that rewards structured exploration.

The algorithm as a flow

What it actually does

1. Measure each token's uncertainty

Compute Shannon entropy (how spread-out is the model's guess) for every generated token.

2. Sort tokens into three groups

Bottom 20% (high confidence), top 50% (high uncertainty), middle 30%.

3. Protect confident tokens

Apply only KL divergence (gentle nudge toward the reference model) — no reward gradient.

4. Bonus uncertain tokens

Add an entropy reward that praises structured exploration without letting randomness explode.

5. Scale the bonus by savings

Calibrate so the total optimization budget stays close to standard GRPO (not overpowering).

What the paper changes

The one thing being changed

The gradient path: which tokens get reward-based updates vs. KL-only updates, and how much bonus (encouragement toward spread-out predictions) high-uncertainty tokens receive.

the object it moves  =  per-token gradient allocation
The hidden quantity

Shannon entropy of the model's prediction

measured quantity  =  per-token prediction entropy

For each token position, the model outputs a probability across all possible next tokens. Shannon entropy measures how spread out that distribution is: if the model is certain (one token 99%, rest near 0%), entropy is low; if it's torn between many tokens equally, entropy is high. High entropy means the model is uncertain and exploring; low entropy means the model is confident.

The paper measures this for every text token and every image token during generation. It then observes that lower-entropy tokens (confident decisions) correlate strongly with stable, high-reward training, while high-entropy tokens (uncertain choices) are where instability and poor image quality originate. By explicitly computing per-token entropy percentiles and treating high-entropy tokens differently, the method directly steers this hidden quantity.

Why it works

Why selective protection and exploration work

Standard reinforcement learning treats every weight the same: find the gradient direction that increases reward and step that way. But in autoregressive generation, not all tokens are equally ready. Some tokens have already converged to solid decisions (the model is always picking the same token when it reaches that point). Nudging them harder doesn't help because the model is already committed; each nudge introduces random variations that shake it off course like tapping a tuning fork that's already ringing. Other tokens are still exploring, swinging between several plausible options depending on the run. Those are where the instability comes from.

EG-GRPO separates these. For low-entropy tokens (already confident), it applies only KL divergence, a gentle steering force that says stay close to the baseline model, don't drift too far. This acts like a brake: it preserves the stable decisions. For high-entropy tokens (exploring), it adds a bonus: a small reward for keeping the prediction spread out, preventing the model from collapsing into a narrow guess before it has explored the option space. The bonus is calibrated per batch so that the total gradient update stays balanced—you are reallocating budget from safe tokens to uncertain ones, not increasing the total work.

Why does this fix instability? Because the source of the jitter is exactly that uncertain tokens are getting yanked around by inconsistent rewards. By giving them a structured incentive to explore (entropy bonus) rather than just an indirect reward nudge, you trade randomness for systematic exploration. And by protecting confident tokens from unnecessary adjustment, you preserve the parts that already work.

The modified training objective

First in words:

total loss = negative advantage times log-probability plus KL divergence from reference model; at uncertain tokens, add an entropy bonus weighted by how much gradient budget was saved at confident tokens

Then the compact form:

L_EG-GRPO(theta) = -1/G * sum_i 1/T^(i) * sum_t A_tilde^(i) * log pi_theta(o_t | c, o_<t) + beta * D_KL(pi_theta || pi_ref) + bonus at high-entropy tokens

Every symbol:

A_tilde^(i)the advantage (how much better this token choice is than average, in the group
pi_theta(o_t | ...)the model's probability of picking token o_t given context
D_KL(...)KL divergence (how different the model is from the reference baseline)
betathe strength of KL regularization (small, keeps model close to baseline)
M^(t)entropy bonus magnitude (0 for low-entropy, positive for high-entropy tokens)
lambda-starthe entropy bonus weight, calibrated so total budget change is proportional to kappa (typically 1)
A tiny worked example
Suppose we have 5 tokens with entropies: tok1=0.3 (low), tok2=0.8 (medium), tok3=2.2 (high), tok4=2.5 (high), tok5=0.4 (low).
Grouping by percentile: low (bottom-20%) = tok1, tok5; high (top-50%) = tok3, tok4; mid = tok2.
Gradient updates at tok1, tok5: only KL applied, e.g., KL update magnitude = 0.01.
Gradient budget saved at tok1, tok5: 0.01 + 0.01 = 0.02.
Entropy bonus at tok3, tok4: lambda-star = 0.1 * 0.02 / (2.2 + 2.5) = 0.1 * 0.02 / 4.7 ≈ 0.0004 per token.
At tok3: total update = advantage gradient + (0.0004 * entropy_bonus) — structured exploration, not pure reward chasing.
Result: tok1 and tok5 stay stable; tok3 and tok4 explore carefully within the entropy-bonus framework.

The core mechanism is that low-entropy steps do only reference-keeping (stay close to baseline), while high-entropy steps get a small bonus for keeping the prediction spread out, with magnitudes calibrated from the work saved elsewhere.

What can go wrong

What can go wrong

Entropy percentile thresholds misaligned. If you compute percentiles globally across all tokens instead of per-sequence, you may mislabel tokens in short vs. long generations. The paper computes percentiles independently for each sequence.
Entropy bonus calibration κ set too high. If κ > 1, the entropy bonus over-scales and dominates the advantage signal, turning optimization into pure entropy maximization (the model explores but ignores reward). Keep κ in (0, 1].
KL divergence weight (steering force) weakened too much. If this steering force becomes very small, low-entropy tokens receive almost no gentle nudging toward the reference model and drift off course. The reference model is your anchor; weak steering breaks it.
Done right. Calibrate the bonus magnitude per batch using the per-batch savings formula, check that entropy percentiles match the paper's thresholds, and keep the steering-force weight at standard GRPO levels (e.g., 0.05).
What a runnable demo should prove

What a runnable demo should prove

Build a small text-to-image generator using a pretrained tokenizer (like VQ-VAE) and a small autoregressive transformer. Train it on 100 simple prompts (e.g., a red cube, a blue sphere) using GRPO. Then split the training into two runs: one with standard GRPO, one with EG-GRPO. For each, generate 5 images per prompt at two different random seeds and measure (1) image quality (e.g., how well a classifier recognizes the object), (2) diversity across seeds (e.g., Vendi score or inter-image distance), and (3) stability (variance of quality across runs). Plot the Vendi score over training steps.

stability_gain = (final_vendi_EG-GRPO - final_vendi_GRPO) / final_vendi_GRPO; should be >= 0.02 (2% improvement) with lower variance.

The demo should make it impossible to miss: the entropy-guided training curve is smoother (fewer bounces), and the final Vendi score is higher and more consistent across runs, even if image quality is similar. That smoothness is the win.
