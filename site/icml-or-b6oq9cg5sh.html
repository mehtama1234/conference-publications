See, Act, Adapt: Active Perception for Cross-Domain Adaptation

Instead of retraining a frozen perception model for new environments, train a visual agent to find better camera angles and viewpoints that make the model work well.

Paper explainersAll themesRepresentation & Self-Supervised Learning

A perception model (trained on generic images) fails on new indoor environments, and the usual fix—fine-tuning on new data—wipes out everything it learned before and demands expensive human labels. This paper sidesteps the problem entirely: keep the perception model frozen, and instead train an agent to actively move the camera to viewpoints where the frozen model sees clearly and confidently.

Zero assumption version

The world changes, the model is stuck

A vision model trained on photographs of generic scenes works great in the lab. But indoors—with different lighting, clutter, occlusion—its answers get worse. The naive fix is to retrain it on indoor images. That fails catastrophically: the model forgets its old knowledge and needs thousands of labeled examples, which is expensive and slow.

The real trap: retraining on new data damages the old skill. We are caught between two bad choices: use the original model and get poor answers, or retrain and lose what we paid for.

Do not retrain. Train a pose-control agent to navigate the camera to viewpoints that make the frozen model confident.

The algorithm as a flow

What it actually does

Freeze the perception model

Lock all weights in place; it will never update.

Transform a vision-language model into a pose controller

A VLM (a model trained to read and understand images plus language) is adapted with a two-stage pipeline to predict camera movements.

Teach the agent to explore systematically

First stage: fine-tune the VLM on rule-based trajectories (pre-written paths that probe a room methodically).

Refine the agent via rewards from the frozen model

Second stage: run reinforcement learning to nudge the agent toward viewpoints where the frozen model reports high confidence.

Deploy: agent steers, frozen model answers

When deployed on a new scene, the agent decides where to look; the frozen perception model answers the question from that viewpoint.

What the paper changes

What the paper changes

The paper does not modify the perception model or its weights. It trains an entirely separate agent (a pose controller) to actively choose camera positions where the frozen model is confident and accurate.

the object it moves  =  The camera viewpoint (via an agent)
The hidden quantity

The confidence score—a steering signal

measured quantity  =  Model confidence

The frozen perception model, when it sees something, not only answers the question but also reports a confidence number (how sure is it?). Low confidence means the image is hard, ambiguous, or out-of-distribution. High confidence means the model sees clearly.

The paper uses this confidence as the sole feedback signal: the agent learns to navigate toward poses that make the frozen model confident, because high-confidence answers tend to be correct.

Why it works

Why moving the camera fixes perception

A frozen model has learned one fixed pattern: given an image, output a guess. That pattern works perfectly when the image looks like its training data (good lighting, uncluttered, frontal). But indoors, images violate those expectations: shadows, occlusions, odd angles. The model still outputs a guess, but often an uncertain or wrong one.

The agent changes the input to the model—by moving the camera to a viewpoint where the image DOES match the model's training distribution. A clean side angle instead of a cluttered overhead shot. Well-lit corridor instead of a dark corner. The frozen model's fixed internal pattern (its weights) is never updated, but now it is looking at a cleaner, more typical image—one it was actually trained for. Confidence rises, accuracy rises, no retraining needed.

This works because the agent is trained to maximize the frozen model's confidence via reinforcement learning (rewarding itself for high confidence over many tries). Over many episodes, the agent learns which poses yield clear, high-confidence answers from the model. The agent's internal weights (its sense of what is a good move) update; the frozen model's weights never move. The agent learns how to steer, not how to perceive.

The reward that steers the agent

First in words:

reward = confidence_score_from_frozen_model; agent_policy_updates = maximize_sum_of_rewards_over_trajectory

Then the compact form:

R(s_t) = conf(model(I_t)); agent_loss = -E[sum_t gamma^t * R(s_t)]

Every symbol:

R(s_t)reward at viewpoint state s_t
conf(model(I_t))confidence (0 to 1) that the frozen perception model reports when shown image I_t from pose t
I_tthe image captured from camera pose t
gammadiscount factor (0.99 typical; future rewards matter slightly less)
agent_losswhat the agent minimizes; negative of cumulative reward (to turn maximization into minimization)
A tiny worked example
Episode: agent tries 4 poses in sequence.
Pose 1 (overhead): model confidence = 0.3, reward = 0.3
Pose 2 (side, better lit): model confidence = 0.8, reward = 0.8
Pose 3 (frontal, clear): model confidence = 0.95, reward = 0.95
Pose 4 (opposite, obscured): model confidence = 0.2, reward = 0.2
With gamma=0.99: total_return_from_pose_2 = 0.8 + 0.99*0.95 + 0.99^2*0.2 = 0.8 + 0.94 + 0.02 = 1.76
Agent learns that moving to pose 2 leads to high long-term reward.

The agent updates its own weights to choose better poses, because poses that yield high model-confidence also tend to yield correct answers—high confidence acts as a proxy signal that the image is now in the model's comfort zone.

What can go wrong

What can go wrong

Agent gets stuck in local optima. The agent may learn a narrow set of poses that happen to trick the model (like always shooting from directly above) rather than truly solving the task. The remedy is diverse exploration during training, via the rule-based fine-tuning phase that systematically probes the environment.
Confidence is not the same as correctness. The model might confidently output a wrong answer in the new domain. If the frozen model is already systematically misled by the new environment, chasing confidence alone does not fix the misled answer.
Agent training is sample-inefficient. Reinforcement learning can require many episodes (many tries) to learn a good policy. If the environment is slow to render or the task is expensive to evaluate, training time can blow up.
Done right. With diverse rule-based exploration, careful reward shaping, and enough training time, the agent learns pose strategies that genuinely align the new domain with the model's original training distribution, unlocking consistent performance.
What a runnable demo should prove

What a runnable demo should prove

Build a simple 3D scene (a room or table with objects) in a simulator. Embed a pre-trained object-detection model that reports confidence. Code a 3-DOF agent that can pan (left-right), tilt (up-down), and zoom (forward-back). Run RL training for 1000 episodes: reward the agent for high detection confidence. Log the agent's chosen poses and the model's accuracy on a held-out ground-truth task (like counting objects or localizing them).

improvement = accuracy_with_agent_poses - accuracy_with_random_poses

The key proof: the frozen model's accuracy rises when the agent chooses poses, and falls back when poses are random, proving the agent truly learned to navigate toward viewpoints where the frozen model works well.
