Fine-Tuning Without Forgetting In-Context Learning

When you teach a language model to solve specific tasks, it forgets how to learn from examples, but updating only one part of the model keeps both abilities alive.

Paper explainersAll themesLearning Theory

Large language models can do two things: solve tasks it has seen before (zero-shot) and learn new tasks from a few examples shown to it (in-context learning). When you fine-tune a model to get better at the first, you wreck the second, because fine-tuning jostles the focus dials so much the model cannot lock onto new patterns anymore. This paper shows why that happens and how to fix it.

Zero assumption version

Two abilities, one sacrifice

A language model, before fine-tuning, can learn from examples. Show it five math problems and their answers, then ask a new one—it figures out the pattern and tries to solve it. This is called in-context learning.

But the same model gets worse at tasks it has seen many times during training. To fix that, engineers fine-tune: they show the model hundreds of examples of the task it needs to solve, adjusting all the internal dials (weights) to nail that specific job. Zero-shot performance goes up.

The problem: after fine-tuning, the model loses its ability to learn from examples. Show it a new task with five examples, and it is lost. The dials were turned so hard for one task that the model can no longer adjust on the fly.

The tradeoff. Fine-tuning strengthens one skill (solve known tasks) by breaking another (learn from new examples).

What the paper changes

What the paper changes

The paper changes which dials get adjusted during fine-tuning. Instead of loosening all the knobs in how the model focuses on different words, it freezes the key and query dials and only tweaks the value dial. The model's focus mechanism has three parts: which past words matter (key), what the current question is asking (query), and what each word actually says (value). The paper says: lock the first two, adjust only the third.

the object it moves  =  Which focus dials get fine-tuned
The hidden quantity

The hidden quantity: focus drift

measured quantity  =  How much the focus dials shift away from their starting point

When you fine-tune a model, the focus dials move. This shift has a cost: in-context learning works by recognizing patterns in the examples you show it. If the focus dials have moved too far from where they started, the model can no longer recognize those patterns in new tasks. The paper measures this as the distance the key and query dials travel—how far from their starting point they end up after fine-tuning.

The paper estimates this drift by building a simplified model where focus is just scaled numbers. In that world, it can calculate exactly how much each type of dial shift hurts in-context learning and which shifts hurt most.

Why it works

Why selective fine-tuning works

In-context learning works like this: you show the model a few examples of a task, and it adjusts its focus to lock onto the right patterns in those examples. The key dial decides which past words matter, and the query dial says what the current question is asking. If those dials shift during fine-tuning, the model cannot recognize the pattern anymore—it is like moving the eyes of a person mid-glance.

The value dial is different. It controls what each word actually says. Changing this dial does not break pattern recognition; it just changes what information flows through. So fine-tuning can adjust the value dial hard (to nail the zero-shot task) without hurting the in-context trick.

The theory shows this precisely: key and query shifts exponentially break in-context learning because they scramble which patterns the model sees, but value shifts only have a linear cost because they just change the volume of information, not what the model is looking at. So a wise strategy is to freeze key and query (keep pattern recognition alive) and turn value all the way up (solve the target task). In-context learning survives on new tasks because focus is not scrambled; zero-shot improves because value has been tuned hard.

Math after the picture

The cost of shifting dials

First in words:

In-context learning loss equals base loss plus a penalty that grows exponentially with how far the key and query dials moved, but only linearly with value drift.

Then the compact form:

L_icl = L_0 + exp(||Delta_K||^2 + ||Delta_Q||^2) + ||Delta_V||

Every symbol:

L_iclHow much in-context learning degrades after fine-tuning
L_0The base loss on new tasks (unavoidable)
Delta_KHow far the key dial moved from its starting point
Delta_QHow far the query dial moved from its starting point
Delta_VHow far the value dial moved from its starting point
||Delta_X||The distance moved (length of the change)
exp(...)Exponential: a small shift becomes a huge penalty
A tiny worked example
Suppose key dial drifts 0.1 units: penalty = exp(0.1^2) = exp(0.01) ≈ 1.01, small penalty.
Suppose key dial drifts 0.3 units: penalty = exp(0.3^2) = exp(0.09) ≈ 1.09, still small.
Suppose key dial drifts 1.0 units: penalty = exp(1.0^2) = exp(1) ≈ 2.72, exponential jump.
In contrast, value dial drifts 1.0 units: penalty = 1.0, linear cost, much lower.
Same drift distance, but key/query are 2.7x more damaging. So lock them, adjust value.

Freezing key and query keeps the exponential term near 1, while value drifts pay only a linear price—the heart of why selective fine-tuning works.

What can go wrong

What can go wrong

Too little fine-tuning. If you freeze key and query but also do not adjust value enough, zero-shot performance stays poor. You must actually train the value dial, not just leave everything as-is.
Auxiliary loss backfire. The paper shows that adding an in-context loss during fine-tuning helps the target task but hurts in-context learning on unseen tasks, because the extra loss tugs the dials toward the target task more aggressively, leaving them farther from their starting point. You gain on one front, lose on another—a different tradeoff, not a solution.
Non-linear focus. This theory works for simplified linear focus models. Real language model focus mechanisms use non-linear tricks (like turning scores into fractions that add to 1), so the guarantees do not transfer directly. The principle may hold, but testing on real models is needed.
Done right. Freeze key and query, aggressively fine-tune value, and measure both zero-shot and in-context performance on held-out tasks. If in-context learning stays sharp across new tasks, the recipe worked.
What a runnable demo should prove

What a runnable demo should prove

Build a small language model (or use a pretrained one). Split a dataset into a target task (say, math problems) and held-out tasks (say, question-answering). Fine-tune the model twice: once with all attention dials loose, once with key and query frozen. On the target task, measure zero-shot accuracy. On held-out tasks, measure in-context learning by showing five examples and measuring accuracy on new instances.

dual_score = zero_shot_target - 0.3 * (icl_new_task_loss - icl_original_loss)

Selective fine-tuning should show zero-shot only slightly lower than full tuning, but in-context learning much higher on unseen tasks—proving you can have both.
