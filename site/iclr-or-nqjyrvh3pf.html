Incentives in Federated Learning with Heterogeneous Agents

A payment rule that stops agents from free-riding by paying each one exactly what their contributed data is worth.

Paper explainersAll themesLearning Theory

In federated learning, many agents pool their data to train one shared model, but each agent pays a cost to contribute (compute, privacy risk, effort) while everyone benefits from the final model. This creates a free-rider problem: agents want the model but not the cost of building it. This paper builds a payment scheme that assigns a fair cost to each agent based on how much their particular data matters to the shared goal, then pays them exactly that amount. The result is a system where honest contribution is the best strategy.

Zero assumption version

The free-rider trap

Federated learning is a way for many agents (people, organizations, devices) to train a shared model together without sharing raw data. Each agent keeps their own data private and sends only model updates. The trained model becomes a public good: once it exists, every agent can use it, regardless of who paid to build it.

Here is the trap: contributing data costs each agent real resources—compute power, bandwidth, privacy leaks, time spent labeling. But the benefit (a better model) flows to everyone equally, because the trained model is a public good that no one can exclude another from using. So an agent can free-ride: skip the cost of contributing while enjoying the model that others built. If many agents think this way, no one contributes, and the whole system collapses.

A naive fix is to demand equal contributions from all agents. But agents have different data: some data is more valuable to the shared goal than others. (Imagine training a doctor-classifier: medical data from a real hospital matters more than random internet photos.) Forcing equal shares wastes resources and unfairly burdens agents with valueless data.

The problem in one sentence. How do you design a payment rule that makes honest contribution the best choice for each agent, when different agents have data of different value?

The algorithm as a flow

What it actually does

Each agent reports their data quality

Agent tells the center: if you train on samples from my data, what accuracy do you get?

Solve the cost-minimization problem

Use a linear program to compute: how many samples from each agent are needed so all agents reach their accuracy target while minimizing total cost?

Assign contributions

The linear program output is a target number of samples to take from each agent.

Calculate payments

Each agent is paid an amount equal to their contribution cost (the number of samples times the per-sample expense).

Verify incentive alignment

Show mathematically that no agent can improve their payoff by lying about their data or refusing to contribute.

What the paper changes

What the paper changes

The paper changes how agents are paid for their data. Instead of paying everyone equally or by donation, it pays each agent based on how much their specific data contributes to achieving the shared accuracy goal.

the object it moves  =  payment per contribution
The hidden quantity

The value of each data source

measured quantity  =  sample-cost importance per agent

The paper measures a hidden quantity: for each agent, how many of their samples does the federation need to include to meet that agent's accuracy target? Call this the agent's contribution weight. An agent with high-quality data needs fewer samples; an agent with noisy data needs many.

The paper estimates this by setting up a constrained optimization problem: each agent must see test error below their threshold, but we minimize the total cost (sum of all samples) needed across all agents to achieve this jointly. The solution tells you exactly how many samples from each agent the system should use.

Plain reading. Imagine the federation as a restaurant buying ingredients from many suppliers. Each supplier's tomatoes have a different freshness. The cost minimization asks: buy the fewest total tomatoes while ensuring every supplier sees their tomatoes used fairly. Agents with fresh tomatoes can contribute fewer; agents with wilted ones must contribute more to meet their own accuracy threshold.
Paper reading. The paper solves the collaborative PAC sample-allocation problem: a linear program that computes the optimal list of sample counts (one for each agent), saying how many samples from each agent are needed to satisfy all PAC accuracy constraints with minimal total sample cost. This list captures heterogeneous utility: each agent's test error on their own data depends on what fraction of the pooled data came from them.
Why it works

Why the payment rule makes honesty the best strategy

Here is the mechanism: First, the center invites each agent to report information about their data (specifically, how their accuracy scales with pool composition). Agents report truthfully because they do not yet know how this will affect payment.

Second, the center solves a linear program: given the reports, what is the cheapest way to gather enough data from each agent so that every agent meets their accuracy target? This yields a target vector (agent 1 contributes 50 samples, agent 2 contributes 100, etc.).

Third, the center pays each agent an amount equal to their per-sample cost multiplied by the number of samples the program assigned them. This is called pay-what-you-contribute.

Here is why this makes honesty profitable: if an agent lies and misrepresents their data, the linear program will compute a different list of sample assignments (a new contribution plan). This new plan will either ask them to contribute more samples (making them worse off because they pay more), or shrink their payment by rearranging who contributes what. Their gain (payment received minus cost of contributing) is always highest when they contribute honestly. An agent cannot beat their honest payoff by misreporting.

Math after the picture

The payment rule formula

First in words:

For agent i, the payment is: c_i multiplied by m_i, where c_i is the per-sample cost for that agent and m_i is the number of samples the algorithm assigns them to contribute.

Then the compact form:

p_i = c_i * m_i

Every symbol:

p_ipayment to agent i
c_icost per sample for agent i (e.g., compute + privacy risk)
m_inumber of samples the linear program assigns to agent i
A tiny worked example
Suppose the linear program says agent A should contribute 100 samples, agent B should contribute 60 samples.
Agent A's per-sample cost is $2 (expensive compute). Agent B's per-sample cost is $0.50 (cheap phone data).
Agent A is paid: $2 × 100 = $200. Agent B is paid: $0.50 × 60 = $30.
Agent A's utility: $200 payment minus $200 cost = $0. Agent B's utility: $30 payment minus $30 cost = $0.
Both agents exactly break even when honest. If agent A lies, the LP might assign them 120 samples and pay only $180, giving them −$20 utility (they lose money). If agent B lies, they might be assigned 40 samples and paid $10, again losing relative to honesty.
So honesty is the dominant strategy.

The formula is simple, but the genius is in the linear program: by computing the cost-minimizing contribution vector, the center ensures that any lie by an agent makes them worse off.

What can go wrong

What can go wrong

Computing the optimal contribution vector is NP-hard. If the accuracy function has a complex shape, finding the exact best contribution vector is computationally intractable. The paper solves this by using a linear-program approximation that runs in polynomial time but may assign slightly more samples than the true optimum (within a logarithmic factor). This is a theoretically sound trade-off.
Agents might misreport their cost structure. An agent might claim their per-sample cost is high when it is actually low, hoping to be assigned fewer samples but get the same payment. The mechanism only incentivizes truthful reports about data quality, not about costs. A full solution requires agents to prove or bind their cost claims (e.g., by stake or reputation).
Data shifts over time. An agent's data quality can change (distribution drift). The mechanism solves the static problem, assuming reports are accurate at the moment of contribution. In a real deployment, the mechanism would need to re-solve periodically or adapt to new data.
Done right. Use the mechanism in a round-based system where agents are screened for truthfulness, cost claims are verified, and the contribution vector is recomputed after each data collection phase. Combine with reputation or collateral to punish dishonesty.
What a runnable demo should prove

What a runnable demo should prove

Build a simulation of 5 to 10 agents, each with a different data quality. Simulate two scenarios: (1) a naive system that demands equal contributions, and (2) the pay-what-you-contribute mechanism. For each scenario, run 1000 trials where each agent decides independently whether to contribute truthfully or shirk (free-ride). Measure two metrics: the overall model accuracy achieved and the fraction of agents who chose to contribute honestly.

incentive_alignment = (fraction of trials where all agents report truthfully) / (total trials); accuracy_gain = accuracy(PWYC) - accuracy(equal-contribution)

The demo must make visible that under the equal-contribution rule, agents with weak data free-ride, accuracy suffers, and the system collapses. Under pay-what-you-contribute, all agents contribute because honesty is profitable.
