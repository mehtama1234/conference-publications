From Extraction to Deduction: Resolving Functional Misalignment in RAG via a Collaborative Critic-Reasoner Framework

Split retrieval-augmented answering into two roles: one role removes misleading answer spans while keeping useful context, and a second role reasons from what remains.

Paper explainersAll themesAgents & Tool Use

A retrieval-augmented question answering system first fetches documents and then writes an answer. The usual failure is not that the fetched documents are unrelated. The failure is that they often contain both useful background and one wrong answer span, and the answer model copies the wrong span because it is easy to copy. This paper separates the job into a critic that removes the misleading pieces and a reasoner that answers from the cleaned evidence.

Zero assumption version

Fetched documents can be relevant and still push the model toward the wrong answer

In retrieval-augmented generation, the document finder is trained to fetch text that looks related to the question. That goal is weaker than fetching text whose answer span is correct. A retrieved passage can contain strong background facts about the topic and still include the wrong date, wrong name, or wrong quantity in the exact place where the answer model wants to copy from.

A plain answer model often treats retrieved text as a shortcut because copying a nearby phrase is easier than checking whether the phrase fits all the other evidence. Once one wrong span looks plausible, the model can anchor on it and ignore the rest of the context. The result is a system that trusts retrieval too much even when the retrieved evidence is internally conflicted.

The paper's diagnosis. The failure comes from a mismatch between what retrieval optimizes and what answering needs: retrieval brings broad context, but answering needs locally correct support.

The algorithm as a flow

What it actually does

Read question and retrieved evidence

Start from the same retrieved passages a standard retrieval-augmented system would use.

Run the critic

Ask the critic to identify names, dates, or values that look misleading when compared with the rest of the evidence.

Mask only the bad span

Hide the suspicious entity while keeping the nearby supporting text, because the surrounding facts still help answer the question.

Run the reasoner on cleaned evidence

The reasoner answers using the residual evidence, so it must combine clues instead of copying the removed span.

Train the two roles together

Supervised tuning teaches the behavior, and preference tuning rewards paths where the critic and reasoner work together.

What the paper changes

What the paper changes

The paper changes the control point for reliability. Instead of filtering away whole documents or trusting the answer model to self-correct, it inserts a critic that can remove only the misleading local span and then hands the cleaned evidence to a separate reasoner.

the object it moves  =  where evidence is cleaned
The hidden quantity

The hidden quantity: local misleadingness inside useful evidence

measured quantity  =  Misleading span pressure

Misleading span pressure is the force that a wrong local phrase exerts on the answer process. A passage can be globally relevant because it discusses the right topic, but one wrong entity inside it can dominate the final answer because copied text is cheap to use. The paper tracks this local pressure rather than treating each document as fully good or fully bad.

The critic estimates which span creates that pressure by checking whether the span fits the question and whether the rest of the retrieved context supports it. If a name or number conflicts with the broader support, the critic marks it for masking so that the reasoner does not get pulled toward the easiest but wrong extraction.

Why it works

Why the critic plus reasoner split works

A one-stage answer model is tempted to extract because extraction is cheap. When the answer words are already present, copying them avoids checking whether those words agree with the rest of the evidence. That shortcut becomes dangerous under conflicting retrieval, because one wrong span can be easier to copy than a correct answer is to derive.

The critic changes the input before the answer is written. It does not throw away the whole passage, because a whole passage may still explain the setting, the event, or the relation among entities. Instead, it removes the locally harmful piece. This preserves useful support because the surrounding context remains visible, while the easiest wrong shortcut disappears.

The reasoner then has no direct phrase to copy from the masked location, so it must combine the surviving clues. The training strategy reinforces this division of labor because supervised examples show how to purify evidence first, and preference optimization rewards full paths where the final answer is right by virtue of the critic's edit and the reasoner's deduction.

Math after the picture

The training objective in plain form

First in words:

The total training goal adds the critic loss, the reasoner loss, and a preference term that rewards full critic-reasoner paths that end with correct answers under conflicting evidence.

Then the compact form:

total_loss = critic_loss + reasoner_loss + preference_alignment

Every symbol:

critic_losspenalty when the critic fails to mark a misleading span or masks the wrong place
reasoner_losspenalty when the answer written from cleaned evidence is wrong
preference_alignmentextra training signal that prefers full trajectories where critic and reasoner cooperate well
total_lossthe full objective minimized during training
A tiny worked example
Question: 'Who led the mission?'
Passage A gives background facts about the mission.
Passage B contains the right topic but the wrong leader name.
If the critic leaves the wrong name visible, the reasoner copies it and the answer is wrong.
If the critic masks the wrong name, the reasoner uses the remaining clues and writes the correct leader.

The preference term matters because it rewards the whole path, not only the final answer, so the critic learns edits that genuinely help the reasoner.

What can go wrong

What can go wrong

Critic masks too much. If the critic removes not only the harmful entity but also the nearby support, the reasoner loses needed facts and may guess.
Critic misses the real conflict. If the wrong span stays visible, the reasoner may still copy it because the shortcut remains easier than deduction.
Evidence is too thin after masking. If retrieval brought only one short passage, masking the bad span may leave too little support for reasoning, because there is no remaining context to combine.
Done right. The framework works when retrieval brings enough overlapping support, because then the critic can remove the local error while the reasoner still has enough residual evidence to deduce the answer.
What a runnable demo should prove

What a runnable demo should prove

Build a question answering demo with a small document set where each query retrieves two or three passages. For some queries, insert one passage that is topically relevant but contains a wrong name or number. Show three outputs: the raw retrieved passages, the critic's masked version, and the reasoner's final answer. The demo should make visible that the final answer improves when only the misleading span is removed, because the useful background context stays available.

The point of the demo is to show that reliability rises when the system edits evidence at the span level, because cleaning one harmful phrase is often enough to stop the answer model from taking the wrong shortcut.
