Dataset Distillation as Pushforward Optimal Quantization

Instead of storing millions of training images, the paper finds a tiny set of representative points that teach a network just as well, by treating the problem as picking the best cluster centers to stand in for the full data.

Paper explainersAll themesDatasets & Benchmarks & Evaluation

Training neural networks requires huge amounts of data—often gigabytes or terabytes stored on disk. Dataset distillation aims to solve this by creating a much smaller synthetic dataset that trains networks just as well as the full one. This paper reframes the problem as optimal quantization: instead of trying to pick good pixels directly, the method works in a compressed numerical space (a simplified representation of images) and finds the best cluster centers to represent the full training distribution. This way, a model can learn from just a handful of distilled images rather than millions.

Zero assumption version

Storing and training on gigabytes of images is expensive

Training a neural network on ImageNet (over a million photos) takes hundreds of gigabytes of storage and weeks of computing time. A naive approach would be to just pick a random subset of the images—but that often loses important details.

Earlier distillation methods tried to solve this by tweaking each pixel of synthetic images directly. This is slow because it requires backpropagating through the entire training loop—like tuning a recipe by trying every spice level, tasting, and adjusting again. The method is stuck optimizing in pixel-space, where tiny changes are hard to guide.

The problem in one sentence. Finding which images matter is expensive; tweaking pixels directly to create synthetic replacements gets stuck.

The algorithm as a flow

What it actually does

Step 1: Encode

Run all training images through a pre-trained encoder to get simplified numerical summaries.

Step 2: Cluster

Use k-means clustering to group similar summaries and find the best center point for each group.

Step 3: Compute weights

Count how many images fall into each cluster; this becomes the importance weight for that center.

Step 4: Decode

Convert each cluster center back into an actual image using a decoder.

Step 5: Train

Use the tiny distilled dataset with weighted images to train new models.

What the paper changes

What the paper changes

Instead of tweaking pixels in the original image space, the paper works in a latent space—a simpler mathematical representation created by an encoder. It picks cluster centers in this compressed space rather than optimizing synthetic pixels directly. This shift makes the problem tractable.

the object it moves  =  cluster centers in latent space
The hidden quantity

The hidden quantity: Wasserstein distance

measured quantity  =  How well the cluster centers approximate the full data

The paper measures something called Wasserstein distance—a number that tells you how far apart two distributions (patterns of data) are from each other. Imagine dumping colored sand on two maps and measuring the minimum amount of work needed to rearrange one pile to match the other. A smaller Wasserstein distance means the cluster centers sit exactly where the real data lives; a large distance means they missed important regions.

The paper uses Wasserstein distance to guarantee that the direction and size of each learning step (a gradient is the computed direction to nudge weights) on the distilled images will be similar to learning steps on the full dataset. This is the mathematical guarantee that a network trained on 100 distilled images actually learns the same things as one trained on 1.2 million. Smaller Wasserstein distance means that guarantee is stronger, because it directly bounds how far apart the actual learning steps can drift—the bound says difference in steps is at most a constant times the Wasserstein distance.

Plain reading. Imagine all training images as dots scattered in a high-dimensional space. Wasserstein distance measures the smallest total distance you would need to move your cluster centers so they perfectly cover that scatter.
Paper reading. For a smooth change-function f and two distributions (call them first distribution and second distribution), the difference in average output is bounded by a constant times the Wasserstein distance between them. In dataset distillation, the change-function is a loss gradient; similar Wasserstein distance guarantees similar learning steps.
Why it works

Why clustering in latent space works

Clustering in compressed space works far better than tweaking pixels directly because optimization in the compressed space is simpler: the encoder squashes millions of image details into a compact list of numbers. In this smaller space, similar images naturally clump together—dogs near dogs, cars near cars—making clusters tight and pure (one type per cluster). K-means (a simple algorithm that finds the average point in each group) finds the center of each clump efficiently. In pixel-space, that same optimization gets stuck in local dead-ends because tiny pixel tweaks create huge, hard-to-predict changes in training behavior.

Once you have cluster centers, you weight them by cluster size (big clusters get higher weight) and decode them back to images. These distilled images, trained with those weights, produce gradients that stay close to the gradients you would get from the full dataset—because the cluster centers are mathematically close to the full data distribution in that compressed space. The paper proves this via Wasserstein distance bounds, so the guarantee is formal.

The equation: training on distilled images

First in words:

minimize loss over theta where each distilled image contributes according to its cluster weight

Then the compact form:

min_θ Σ_(x,y,w) w · ℓ(x, y, θ)

Every symbol:

θthe network weights being trained
ℓ(x, y, θ)the error (loss) on image x with true label y
wthe weight for that image (cluster size / total images)
Σsum over all distilled images
A tiny worked example
Suppose you have 3 clusters: A (400 images), B (300 images), C (300 images), total 1000.
Weights become: w_A = 400/1000 = 0.4, w_B = 0.3, w_C = 0.3.
When training on 3 distilled images (one per cluster), image A contributes 0.4x its loss, B contributes 0.3x, C contributes 0.3x.
This mirrors the original distribution: large clusters pull the learning harder, small clusters pull less.
Gradient on distilled image A is 0.4 × (actual gradient from A's cluster center).

The weights bake in cluster size so the distilled dataset has the same probability shape as the full data.

What can go wrong

What can go wrong

Encoder loses too much detail. If the encoder squashes images too aggressively, the cluster centers in latent space no longer represent the original distribution. The guarantee breaks and distilled images become useless. A weak encoder choice ruins everything.
Cluster count mismatch. If you choose too few clusters (e.g., 10 when you need 100), each cluster becomes bloated and covers too many different image types—dogs mixed with cats. The cluster center sits between contradictory examples and helps no one, because it is pulled in conflicting directions and ends up representing nothing well. Too many clusters wastes the compression and overfits.
Generalization across architectures fails. Distilled images trained on one network type may not transfer well to a different architecture because different models extract different features and learn at different speeds. A cluster center that works for a ResNet (which has skip connections that speed learning in certain layers) may confuse a simpler model. The paper reports this is a real problem for some baselines because they do not use a pre-trained encoder that both architectures can rely on; DDOQ does better by grounding both in the same encoder, but it can still happen with very different model types.
Done right: Wasserstein distance stays small. When encoder, cluster count, and decoder are well-matched, cluster centers sit exactly where real data concentrates. Gradients on distilled images are provably close to gradients on full data. Networks trained on 100 images match networks trained on millions.
What a runnable demo should prove

What a runnable demo should prove

Write a script that takes ImageNet-1K (or a smaller dataset like CIFAR-10 for speed), compresses it with a pre-trained diffusion model encoder, clusters the compressed images into K groups, decodes the cluster centers back to images, assigns each a weight based on cluster size, and trains a fresh neural network on just those K images. Then train another network on a random subset of the same size and one on the full data. Compare the final accuracies and training times.

forgetting = full_accuracy - distilled_accuracy; speedup = full_training_time / distilled_training_time

The demo should make impossible to miss: a 50-image distilled dataset trains a network to 75% accuracy in minutes, while the same architecture trains on 10,000 random images to 72% accuracy in hours. The distilled images are not random; they are cluster centers chosen to be maximally representative.
