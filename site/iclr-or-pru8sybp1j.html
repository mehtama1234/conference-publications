DRQ-learner: Orthogonal Q-function Estimation from Observed Data

A two-stage learner that estimates decision values from observational data by decoupling first-stage bias from second-stage refinement, making it immune to misspecified models.

Paper explainersAll themesReinforcement Learning

When you have real-world records of past decisions and outcomes, but not the option to run new experiments, you must estimate the value of each action (called a Q-function). The challenge: your estimates of intermediate steps compound errors until long-horizon predictions become garbage. This paper builds a learner that fixes both problems together — it stays honest even when your intermediate models are wrong, and it refines those rough estimates in a second stage without getting poisoned by the first stage's mistakes.

Zero assumption version

Why long-horizon value estimates from data go wrong

In the real world you often have historical records but cannot run new experiments. You want to know: if I make this sequence of decisions, what outcome will I get? To answer it, you need to estimate each step's value — which action is worth taking right now. But estimating these values from old observational data is hard.

A beginner's approach: take the first-stage estimates of the intermediate steps (like a simple linear model) and chain them together. This breaks because errors compound. If each step is slightly wrong, by step 50 your prediction is off by miles. Worse, the intermediate models are trained on the same data you use to estimate the final value, so they are biased — they overfit to patterns that do not generalize. When you plug these biased intermediate estimates into your value calculation, the bias gets amplified, not cancelled.

In one sentence. DRQ-learner breaks the coupling between first-stage bias and second-stage refinement by using a specially-designed loss that ignores first-order errors in the intermediate estimates.

The algorithm as a flow

What it actually does

Stage 1: Estimate the nuisance models

Train three intermediate models on the observed data: behavior policy (which actions were chosen), transition model (what state came next), and density ratio (how likely each state was under the old vs new policy).

Stage 2: Build a debiased loss

Create a loss function that measures how well you estimate the true value, but with a special property: it is insensitive to first-order errors in the three intermediate models.

Stage 3: Refine the Q-function

Use the debiased loss to train the final Q-function (the value estimator) in a second pass, anchored by the intermediate estimates but not poisoned by their errors.

Handles model errors

If any ONE of the three intermediate models is correct, the final value estimate is correct. You only need 50 percent accuracy, not perfection.

Quasi-oracle performance

The final Q-function converges at the same rate as if you had handed it the perfect intermediate models, even though you trained them yourself.

What the paper changes

What the paper changes

The paper replaces the loss function used in the second stage. Instead of a simple plug-in loss that chains the first-stage estimates (which absorbs their bias), it uses a debiased orthogonal loss designed to ignore first-order errors in the intermediate models.

the object it moves  =  Second-stage loss
The hidden quantity

The orthogonality property

measured quantity  =  First-order sensitivity of the loss

A loss is orthogonal (or Neyman-orthogonal) if small errors in the intermediate inputs do not change the direction you need to move in order to fix the loss. When you perturb the intermediate estimates by a little bit, the optimal direction (the one that minimizes the loss) does not change by a first-order amount — it stays nearly the same around the true value.

Why this matters: when you optimize a loss by sliding downhill, if a tiny mistake in the input (like model bias) slopes the hill sideways at the true value, you end up in the wrong valley. Orthogonal losses are flat sideways at the truth — they ignore small input errors and find the right valley anyway. The paper computes this property mathematically by deriving the efficient influence function, which tells you exactly how to reshape the loss to make it orthogonal.

Why it works

Why orthogonality breaks the error coupling

Normally, when you refine an estimate in a second stage using the first stage's output, the first stage's bias leaks in. You are sliding downhill on a surface shaped by the first stage. If that surface is tilted by bias, you slide into the wrong valley. The problem: the gradient of your refinement loss has a component perpendicular to the true answer, created by the bias.

Orthogonal losses remove that perpendicular component. The paper does this by deriving the efficient influence function — the mathematical object that tells you the minimal variance way to estimate your target. It then bakes this into the loss function itself. The result: when you optimize, the gradient points toward the true answer even if the first-stage estimates are wrong. The first-stage errors do not bias the second stage; they just add noise that shrinks with more data. This is called quasi-oracle efficiency — you converge as if the first-stage models were perfect, even though they are not.

Math after the picture

The debiased loss in numbers

First in words:

orthogonal_loss = direct_term + correction_term, where correction_term removes the bias from the first-stage models

Then the compact form:

L_orth(eta, g) = -g(s,a) * (reward + gamma * g(s',a') - policy_weight(a,s) * transition_weight(s',s,a) * density_ratio(s',s,a) * correction_offset)

Every symbol:

g(s,a)estimated value of action a in state s
rewardobserved reward from the data
gammadiscount factor, how much future matters
g(s',a')estimated value of the next state and best action
policy_weight(a,s)fraction saying policy chose action a in state s
transition_weightestimate of how likely the next state was
density_ratioratio of new policy to old policy at this state
correction_offsetdebiasing term that kills first-order errors
A tiny worked example
Suppose reward = 1.0, gamma = 0.9, next-state value g(s',a') = 10.0, and the three intermediate estimates are all slightly off.
Naive loss would compute: target = 1.0 + 0.9 * 10.0 = 10.0. If the intermediate estimates are biased by 0.2 each, the target becomes 10.2, and you train toward the wrong valley.
Orthogonal loss includes a correction_offset = -0.2 * (some weighting). When optimized, the loss gradient stays centered on the true value of 10.0, not 10.2.
Result: over many samples, you converge to the true Q-function even though each intermediate estimate carried a 0.2 error. The errors are orthogonal to the search direction.

The orthogonal loss is shaped so that errors in the preliminary estimates tilt the search space perpendicular to the direction you are walking, so you ignore them.

What can go wrong

What can go wrong

Assumption violation: unconfoundedness. The method assumes that all confounders (hidden variables affecting both the choice and the outcome) were observed. If the data contains hidden confounders, no method will fix it. The paper cannot patch this; it must be true in the domain.
Assumption violation: positivity. The method requires that every action-state pair that you care about had some chance of occurring in the old data. If a state was never explored, you cannot infer anything about it. Low-overlap regions (rare states) become unreliable.
Compounding in very long horizons. Though orthogonality removes first-order bias, estimating 200 steps into the future is still hard because each step adds noise. When you estimate the transition model 200 times in a row, even tiny random errors accumulate — you multiply 200 small imprecisions together. The method reduces bias but does not eliminate the noise of chaining, which grows by the square root of the horizon length.
Done right. When unconfoundedness and positivity hold, and the intermediate models are trained carefully (not overfitted), the DRQ-learner recovers the true Q-function at the optimal rate. Domain expertise matters.
What a runnable demo should prove

What a runnable demo should prove

Generate synthetic observational data from a known Markov decision process (e.g. a simple gridworld or medical treatment simulator). Train three intermediate models (behavior policy, transition, density ratio) with deliberate bias (e.g., regularize them or train them on noisy subsets). Then compare three learners: (1) naive plug-in chaining, (2) a debiased baseline, and (3) the DRQ-learner. Evaluate each on a held-out test set of state-action pairs where the true value is known.

value_error = mean(abs(estimated_Q - true_Q)) for each method. Also report forgetting = improvement of DRQ over plug-in when intermediate models are intentionally misspecified.

The demo should show that when you deliberately misspecify the intermediate models, the naive method's value estimates drift far from the ground truth, while the DRQ-learner stays close. This proves the orthogonality property is real: first-stage errors do not poison the second stage.
