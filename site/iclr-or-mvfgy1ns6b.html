WebLeaper: Efficient Information Seeking for LLM Agents

An LLM agent learns to search web information efficiently by training on high-coverage tasks and keeping only the fastest correct search paths.

Paper explainersAll themesAgents & Tool Use

Large language models can now control web browsers to find information autonomously, but they search wastefully, clicking through many dead ends. This paper shows that if you construct training tasks with many possible target facts hiding in the search space, and then keep only the shortest, correct search paths for training, the agent learns to search far more efficiently because it repeatedly copies direct routes instead of wandering routes.

Zero assumption version

Agents waste time searching

Today's large language models can control web browsers to hunt for factual answers. But they are inefficient searchers. An agent given a question like "Who did David Bowie collaborate with in 1975?" might visit the same irrelevant pages multiple times, follow tangential links, and take far more clicks than a human would.

The root cause is clear: training data is sparse. Researchers have created only a few thousand information-seeking tasks, and each one has just one or two target facts scattered in the web. An agent trained on this sees only a handful of search patterns and fails to generalize to new questions. It never learns the efficient search tricks that would work across many different target facts.

A naive solution would be to hand-craft more training tasks, but that is slow and expensive. The agent learns poorly because the search space never forces it to practice the really useful patterns.

The method in one sentence. Build dense training tasks containing many possible target facts by reformulating questions as tree-shaped searches, so the agent sees many linked facts in one task; then train only on the shortest, correct paths so efficiency is baked into the learned behavior.

The algorithm as a flow

What it actually does

1. Take a search question.

Start with a goal like "Find the 1975 collaborator of David Bowie on a Wikipedia page."

2. Reformulate as a tree of possible paths.

Instead of one target, expand it into many: the 1975 collaborator could be Mick Jagger, or you might find collaborators of Bowie from 1974–1976. Each is a valid answer hiding at a different depth in the search tree.

3. Collect all correct search paths the agent could take.

Record every sequence of page visits that successfully finds any valid target fact.

4. Keep only the shortest correct paths.

Discard paths that wandered; retain the direct ones so training rewards speed and accuracy equally.

5. Train the agent on these efficient trajectories.

The agent learns to replicate the shortest, smartest search paths, generalizing the efficiency pattern to unseen questions.

What the paper changes

The training signal the agent learns from

The paper changes one thing: which search paths are used as training examples. Instead of using all paths that reach a correct answer, only the shortest ones are kept. This makes training data simultaneously sparse (fewer examples) and more informative because each remaining example shows a direct route to the answer.

the object it moves  =  training trajectories
The hidden quantity

The hidden quantity: search depth per correct answer

measured quantity  =  click efficiency (answers per search step)

Every time an agent searches for information, it accumulates a cost: the number of pages it visits. The metric that matters is how many correct answers the agent retrieves per click—this is search depth efficiency. A naive agent might need eight clicks to find one answer. An efficient agent finds the same answer in three clicks.

The paper measures this by tracking every search trajectory the agent takes and calculating the average number of steps needed to reach each target. This metric is not automatically optimized when training on all correct paths; it only improves when you explicitly keep only the shortest paths and train on those because the model otherwise sees slow correct paths as acceptable examples.

Why it works

Why reformulating tasks and filtering paths works

The core problem is that an agent trained on sparse examples learns brittle, unpredictable search behavior. It has not seen enough diverse target facts to recognize the underlying structure of efficient search.

Reformulating a single question as a tree of many possible targets solves this. Now the agent, during training, encounters ten different valid target facts in a single task instead of one. It starts to see patterns: "When searching for a person's collaborator, Wikipedia links usually appear here" or "Facts about specific years cluster in these sections." The agent learns the shape of efficient search without being explicitly told.

But training on all paths to these targets would still include wasteful ones. This is where the filtering step changes the training signal. By keeping only the shortest correct paths, the agent never practices the wasteful behavior. It only copies the smart moves. Over time, this teaches the agent that efficiency and correctness go together because every copied trajectory is both correct and short.

The three task variants (Basic, Union, Reverse-Union) layer difficulty: Basic is a simple reformulation; Union combines two reformulations so the search tree branches more; Reverse-Union makes the task symmetrical, forcing the agent to practice from multiple starting angles. Together, they ensure the agent sees varied patterns of efficient search.

Math after the picture

The efficiency filtering formula

First in words:

For each task, measure the average search cost (number of steps) for all trajectories that reach a correct target. Keep only trajectories below the median cost.

Then the compact form:

cost(trajectory) = number_of_pages_visited; keep_trajectory if cost(trajectory) <= median_cost_for_target

Every symbol:

cost(trajectory)the number of web pages the agent visited before finding the answer
number_of_pages_visitedeach click on a link or page visit increments this counter
median_cost_for_targetthe middle value of all costs for finding this one target; trajectories above this line are too wasteful and discarded
A tiny worked example
Target: Mick Jagger. Five trajectories find him: Path A visits 3 pages, Path B visits 4 pages, Path C visits 5 pages, Path D visits 6 pages, Path E visits 7 pages.
Median cost = 5 pages (the middle value).
Keep: Paths A, B, C (cost <= 5). Discard: Paths D, E (cost > 5).
Agent trains only on efficient paths A, B, C. It learns that finding Mick Jagger takes about 3–5 clicks, not 6–7.

By keeping trajectories at or below the median cost, the training data skews toward efficiency, pushing the agent to learn quick, direct search behavior.

What can go wrong

What can go wrong

Too aggressive filtering discards learning signals. If the median cost is set too strictly (e.g., keeping only the top 10% of paths), the agent has too few examples and fails to learn reliable search behavior. The filtering threshold must balance efficiency gains against data diversity.
Tree reformulation can introduce artificial targets. When you expand a search task into a tree, the newly added possible targets must be genuine alternative answers, not noise. If the tree includes fake targets or contradictory facts, training becomes confusing and the agent learns incorrect associations.
Efficiency gains do not transfer to out-of-data pattern questions. If the training tasks are reformulated in a specific way (e.g., always searching Wikipedia), the agent may learn tricks specific to that data source and fail on unfamiliar websites with different layouts and link structures.
Done right: reformulation variants + diversity. Using all three task variants (Basic, Union, Reverse-Union) ensures the agent encounters search patterns from many angles. Validating that reformulated targets are genuine and present in the source data ensures correctness. Testing on multiple benchmarks confirms that efficiency gains hold on unseen question data patterns.
What a runnable demo should prove

What a runnable demo should prove

Build a simple information-seeking environment: a small graph of web pages (a Wikipedia excerpt, for example) with five facts scattered across them. Create a baseline agent trained on all paths that find these facts. Then create a second agent trained only on the shortest paths to the same facts. Run both agents on a new search question (one they have not seen before, but similar in structure). Measure how many pages each agent visits before finding the answer, and whether it finds the correct answer at all.

efficiency_gain = (baseline_steps - webleaper_steps) / baseline_steps * 100%

The demo must show that WebLeaper's agent takes measurably fewer steps while maintaining or improving accuracy, proving that filtering for efficiency during training actually teaches the agent to search smarter, not just to copy exact paths.
