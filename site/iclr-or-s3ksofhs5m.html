Reading Attention Cross-Talk to Find Important Immune Interactions

By reading which parts of a protein the model pays attention to, you can find which amino acids actually bind in the immune system.

Paper explainersAll themesAI for Science

Machine-learning models predict whether a T cell will bind to a foreign protein, but they work like black boxes — you see the yes or no, not why. This paper describes how to trace through the model to find which amino acids the model thinks are important for binding. The key: most immune models use a two-part architecture that reads the two molecules separately, then compares them using a technique called cross-attention (where parts of one molecule are scored against parts of the other). Old explanation methods only look at one part at a time; this work looks at the comparison step where the model actually matches the two.

Understanding why a model says yes or no

When a T cell encounters a foreign protein, it uses sensors called receptors to test whether that protein is actually the invader. Scientists build machine-learning models that predict this binding, and they work pretty well. But the problem is they are opaque: the model outputs a prediction, but you have no idea which parts of the proteins actually caused that prediction.

Existing explanation methods exist, but they have a blind spot. Most of them were built for simpler models that read one sequence of tokens. The best immune models use a two-part architecture: one part reads the T cell receptor, another part reads the foreign protein, and then they cross-compare them. Current methods do not handle this cross-comparing step, so they cannot explain which pairs of amino acids the model thought were interacting.

In one sentence. Trace importance scores backward through cross-attention layers to find which amino acids a model thinks drive binding.

What the paper changes

What the paper changes

The paper adds the ability to read cross-attention layers — the parts of the model where it compares two separate molecules. Most old explanation methods treat these comparison steps as invisible; this method makes them visible and traces importance scores through them.

the object it moves  =  Cross-attention importance scores
The hidden quantity

The hidden quantity: which positions the model thinks matter

measured quantity  =  Attention importance scores

Importance scores are numbers assigned to each position in the input. A high score means: when I change this position slightly, the model's final prediction would shift a lot. A low score means the model barely looks at that position.

The paper computes these scores by taking gradients — asking the model: how much does the loss (the error in its prediction) depend on each attention weight? This is called GradCAM-style importance. Then it combines the gradient with the attention weights themselves to get a final importance number for each position.

Why it works

Why this finds the real binding site

The mechanism works in stages. First, the model makes a prediction (binding or not), and this prediction has an error called the loss. Next, the paper computes gradients: for each attention weight in the cross-attention layers, how much would the loss change if we nudged that weight up or down? Weights that matter a lot have big gradients.

Then, importance scores are computed by combining the gradient with the attention weight itself. High attention weight plus high gradient means this weight is both used by the model and critical to the decision. Finally, these scores are aggregated backward through all layers, combining self-attention steps in the encoder with cross-attention steps in the decoder. This creates a continuous chain from the final output back to the input amino acids.

Why does this work? Because the model learned to put high attention on positions that genuinely help with the binding decision. By asking the gradient which attention connections matter for the final prediction, you recover the model's internal map of what is important. When you then check this against real lab-solved structures, high-scoring positions turn out to have atoms that are physically close to each other — proof that the model learned something real about binding.

Math after the picture

The importance equation

First in words:

Importance for a query equals gradient of loss times attention weight, summed over the key positions it pays attention to.

Then the compact form:

I_query = sum_k (dL/dA) * A_k * V_k

Every symbol:

I_queryImportance score for this query position
dL/dAGradient: how much does loss change if attention changes
A_kAttention weight to key k, between 0 and 1
V_kValue vector at key k, the information being attended to
sum_kAdd up the contribution from every key position
A tiny worked example
Imagine the loss is 0.8 and we are asking about a query position.
Gradient at key 1: dL/dA = 0.5 (the loss depends moderately on this weight).
Attention weight A_1 = 0.9 (the model pays close attention).
Importance from key 1: 0.5 * 0.9 = 0.45.
Gradient at key 2: dL/dA = 0.1 (less important for the loss).
Attention weight A_2 = 0.6.
Importance from key 2: 0.1 * 0.6 = 0.06.
Total importance: 0.45 + 0.06 = 0.51.
Key 1 contributes most because both its gradient and attention are high.

The importance combines two ideas: the model pays high attention to certain positions AND those positions matter for the final answer. Both conditions must be true.

What can go wrong

What can go wrong

Gradient is zero if no one depends on this weight. If a cross-attention weight was not used by the model to make its final decision, the gradient is zero and the importance score is zero. The method cannot flag something the model simply ignored, even if it should have paid attention to it.
Attention patterns can be noisy. Models learn approximate attention patterns during training. Two runs might learn slightly different attention weights. If importance depends on one noisy weight and another model learns to distribute importance differently, the predictions shift.
Aggregation assumes attention flow works backward. The method traces importance by assuming that importance at the output flows backward through attention layers like a wave. If the model uses shortcuts or unusual connections not captured by this assumption, the traceback may miss them.
Done right: validate on ground truth. The paper checks predictions against 274 real crystal structures with physically measured distances. If the importance scores point to amino acids that are close in the lab-solved structure, the method is working correctly.
What a runnable demo should prove

What a runnable demo should prove

Download a pre-trained TCR-pMHC binding model and pick a test case where the model made a binding prediction. Run the QCAI method to compute importance scores for each amino acid. Download the corresponding crystal structure from the protein database. Measure the actual physical distance between pairs of amino acids. Plot the importance scores against the distances: high-importance pairs should be close in 3D space, low-importance pairs should be far apart. If the correlation is strong (high importance pairs average 4 angstroms apart, low-importance pairs average 12 angstroms apart), the method works.
