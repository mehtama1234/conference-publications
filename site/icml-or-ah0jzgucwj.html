Grounded Correspondence: Matching Instead of Predicting

Video object tracking works better when you match objects frame-to-frame instead of teaching a neural network to predict where they move.

Paper explainersAll themesComputer Vision

Imagine watching a video and trying to keep track of which blobs are the same objects across frames. Most approaches train a neural network to predict what the next frame will look like, teaching it to understand motion. This paper throws out that prediction step and replaces it with a much simpler trick: for each frame, find which objects in the next frame are the best matches to the current ones.

Zero assumption version

The world before: learning to guess the future

Tracking objects in video is hard because objects move, split, merge, and sometimes go off-screen. Early papers on object discovery in video solved this by training a dynamics model: a neural network that learns how objects change from frame to frame. The network gets a slot (a compressed description of one object) and learns to predict what that same object looks like next.

But there is a hidden cost. These networks need a lot of training data to learn motion patterns. They also guess wrong about objects they have never seen before, and they need extra computation every frame to run the prediction. A student tutor analogy: instead of asking the student to memorize every face in the class and predict where they stand next, you could just ask the student to recognize faces across consecutive pictures.

The core problem. Learned motion prediction is expensive to train and overkill, because the computer already has a simpler superpower: it can recognize when two things are the same object.

The algorithm as a flow

What it actually does

Freeze the vision backbone

Use a pre-trained model that already recognizes objects. Do not train it.

Find salient regions

Pick the most important parts of each frame where objects tend to appear.

Create slots

Compress each salient region into a short description called a slot.

Match frame-to-frame

Use Hungarian matching to pair slots in frame N with slots in frame N+1.

Repeat across the video

Keep matching forward, reusing the same object identity as long as the match score is high.

What the paper changes

What the paper swaps out

Most video object discovery systems have learned transition functions inside them: small neural networks trained to predict the next state of each object. This paper removes those networks entirely and replaces them with a deterministic matching algorithm that runs the same way every time, no learning involved.

The hidden quantity

Match confidence: how well do objects align across frames?

measured quantity  =  Match confidence score

The paper measures match confidence: a number that tells you how similar two objects are across frames. It comes from the frozen vision backbone features, which already know which pixels belong to the same thing (self-supervised learning trained them that way). High confidence means the same object appears in both frames; low confidence means they are probably different things.

The Hungarian matching algorithm uses these scores to decide which slot in frame N pairs with which slot in frame N+1. High scores get paired first; low scores are left alone or marked as new objects entering the scene.

Plain reading. The match confidence is just how similar the descriptions of two objects are. If one object in frame 5 looks almost identical to one in frame 6 (same color, same shape, same size), the algorithm is very confident they are the same thing.
Paper reading. The paper extracts slot representations from a frozen self-supervised vision backbone (like DINO or SimSiam, models trained to recognize instances without labels) and measures how similar the slots are across frames by computing similarity, which gives the match score.
Why it works

Why matching beats prediction

Predicting the next frame is disguised object matching. A learned dynamics model watches object A in frame N and tries to guess what it becomes in frame N+1. But the vision backbone already knows this: it was trained to tell when two image regions show the same object, even if they moved or changed slightly. Skip the prediction and directly ask: which object in frame N+1 matches object A best?

This works because modern self-supervised vision models recognize individual instances: they can tell one copy of a person from another, even if they are in different positions or lighting. That is exactly what you need to track identity across frames. Hungarian matching then pairs objects optimally: it considers all possible matchings and picks the one where the total match confidence is highest.

Matching is faster because the learned model needs millions of tunable weights and must run on every frame, taking compute time proportional to the model size. Matching uses zero tunable weights and runs a fast combinatorial algorithm, taking time proportional only to the number of objects. Matching generalizes better because the learned model must see the specific motion patterns in its training data, whereas matching relies on the backbone which was trained on millions of images and has already learned what makes two image regions show the same object, so it works on any video regardless of whether the training data contained similar motion.

The matching equation

First in words:

Best pairing is the one that maximizes total match score, subject to each object pairing at most once.

Then the compact form:

max sum_{i,j} S_{ij} * M_{ij} where M_{ij} in {0,1} and each i,j pairs at most once

Every symbol:

S_ijmatch score between object i in frame N and object j in frame N+1
M_ijbinary indicator: 1 if i and j are paired, 0 otherwise
Hungarian matchingalgorithm that solves this optimization in O(n^3) time
Tiny worked example: matching three objects across frames
Frame N: object A, B, C. Frame N+1: object 1, 2, 3.
Match scores: S_A1=0.92, S_A2=0.15, S_A3=0.05; S_B1=0.10, S_B2=0.88, S_B3=0.02; S_C1=0.08, S_C2=0.12, S_C3=0.90.
Hungarian algorithm finds: A pairs with 1 (0.92), B pairs with 2 (0.88), C pairs with 3 (0.90). Total score = 2.70.
Any other pairing (e.g., A-2, B-1, C-3) gives 0.15 + 0.10 + 0.90 = 1.15, much worse.
The algorithm guarantees the maximum total score without trying all n! permutations.

This equation says: find the pairing of objects where the sum of match confidences is as high as possible.

What can go wrong

What can go wrong

Heavy occlusion or fast motion. If an object disappears or moves so fast that its appearance changes dramatically between frames, the match score drops and the matching algorithm may pair it with the wrong new object or miss it entirely.
Objects entering or leaving the frame. Hungarian matching expects a fixed number of objects. New objects must be detected separately (as unmatched slots in the new frame), and exiting objects are simply not matched. This works but requires careful bookkeeping.
Weak backbone features. The entire method relies on the frozen vision backbone already being good at instance discrimination. If the backbone was trained on a different domain (e.g., only faces, not animals), match scores will be poor.
Done right. Preprocessing the video to clip very fast motion into sub-frames, using an aggressive focus method to find salient regions for initializing slots, and ensuring the backbone was trained on diverse unlabeled data all reduce failures.
What a runnable demo should prove

What a runnable demo should prove

Build a simple video dataset with 3-5 synthetic objects that move linearly across frames, and a few frames where objects pass by each other or briefly occlude. Extract features from a frozen backbone (DINO is public and pre-trained). Implement Hungarian matching and run it frame-by-frame. Measure object identity accuracy: what fraction of the time does the algorithm correctly match each object to itself in the next frame?

identity_accuracy = (number of correct matches) / (total number of matches attempted)

The demo should make obvious that matching is much faster (runs in milliseconds for 10 objects, whereas a learned model takes seconds) and keeps identity even when motion is non-smooth, because the matching algorithm does not need to learn what the motion looks like.
