MM-DeepResearch: A Simple and Effective Multimodal Agentic Search Baseline

Build a multimodal research agent by generating hard cross-modal questions offline, training tool specialists, and using an offline search world so that reinforcement learning stays affordable.

Paper explainersAll themesAgents & Tool Use

A deep-research agent must read text, inspect images, choose tools, and combine evidence across several search steps. That is hard to train because good multimodal search data is scarce, strong tool-use traces are hard to obtain, and online search APIs are expensive. MM-DeepResearch tackles all three bottlenecks together. It creates hard search questions from linked visual and textual facts, trains specialist tool users with tree search, and replaces paid online search with an offline search environment for reinforcement learning.

Zero assumption version

Why multimodal deep research is hard to train

A useful research agent must solve questions that require several searches across text and images. Ordinary question-answer data is too shallow for that job because many questions can be answered from one clue or from one modality alone. The agent then never learns the longer search behavior that true deep research needs.

Even with harder questions, training remains difficult because effective search traces are rare and online search calls are costly. A reinforcement-learning pipeline that depends on paid live tools can become too expensive to scale. The paper's position is that data generation, trajectory generation, and training environment design all have to be fixed together.

The paper's move. Generate hard multimodal search tasks offline, build specialist tool users with tree search, and train inside an offline search environment so that long-horizon search remains practical.

Train tool specialists

Separate the search space by tool type so that each specialist learns the habits needed for one search tool.

What the paper changes

What the paper changes

The paper changes the training supply chain for research agents. Instead of depending on scarce hand-built data and expensive live search during learning, it builds hard tasks, strong trajectories, and a cheaper practice environment offline so that the agent can rehearse long search behavior many more times.

The hidden quantity

The hidden quantity

measured quantity  =  whether the agent has enough search pressure to learn real research behavior

A research agent can appear capable while solving only shallow tasks. The hidden quantity is the amount of genuine search pressure in the training setup: do the tasks force the agent to connect clues across modalities, choose the right tool, and continue searching until enough evidence has been gathered?

MM-DeepResearch raises that pressure in three ways. Hard question generation makes the task require cross-modal search. Tool-specialist trajectory construction makes good traces easier to obtain. Offline search lowers training cost so that reinforcement learning can practice long search sequences repeatedly.

Why it works

Why this works

Harder tasks are necessary because a research agent learns what its data demands. If most training questions can be solved with one search and one summary, the model has no reason to learn multi-step evidence gathering. Hyper-Search changes that by generating questions from connected text and image facts, so the answer path must traverse several linked nodes.

Better trajectories are necessary because reinforcement learning needs examples of successful behavior to improve reliably. DR-TTS decomposes the problem by tool type first, which lets each specialist learn cleaner habits. Tree search then recomposes those specialists into longer successful traces. That helps because a complex task may need several different search tools in sequence.

Lower training cost is necessary because long-horizon search requires many practice episodes. The offline search environment matters by replacing expensive live tool calls with a local world that preserves the tool interface. That makes reinforcement learning feasible at scale, so the agent can repeatedly practice cross-modal search and evidence synthesis.

A tiny worked example
Suppose a question asks for the location of an event shown in an image and confirmed by two text sources.
A shallow dataset would accept a one-clue answer, but the generated hard dataset requires all linked clues.
A map-search specialist finds the place name, a web-search specialist finds the event page, and a composition step combines both traces into one successful solution.
Because the search world is offline, the system can practice that kind of trajectory many times without paid API calls.
The learned agent improves because the task is hard enough, the trace is informative, and the training budget can support repeated practice.

The real system uses a richer setup, but this summary captures the main causal claim that all three ingredients must improve together because weak tasks, weak traces, or weak training access can each block the agent from learning deep search behavior.

What can go wrong

What can go wrong

Generated questions may still be too synthetic. If the hard questions do not resemble real user research tasks, the agent may learn patterns that transfer poorly outside the generated world.
Tool specialists can over-separate the problem. If each specialist becomes too narrow, the combined system may struggle when a task needs flexible switching between tools that were trained mostly in isolation.
Offline search can miss live-web behavior. A local search world cannot perfectly reproduce the messiness of current online content, so some policy habits may weaken when moved to real tools.
Done right. The method is strongest when generated tasks resemble real research, specialist traces compose well, and the offline environment preserves the tool patterns that matter in deployment.
What a runnable demo should prove

What a runnable demo should prove

Build a small corpus with linked documents and images, then generate questions that require at least two search steps across both modalities. Include several tool types such as keyword search, image lookup, and document opening.

Train one baseline agent on ordinary multimodal QA and one agent with the MM-DeepResearch pipeline. Measure final answer accuracy, average search depth, and cost per training episode. The result should show whether harder offline-generated tasks and specialist trajectories produce better multi-tool search behavior because the agent is forced to practice longer cross-modal evidence gathering.

research_gain = answer_accuracy_mmdeepresearch - answer_accuracy_baseline ; search_depth_gain = average_tool_steps_mmdeepresearch - average_tool_steps_baseline

The demo should confirm that the better system is not only answering more questions. It should be carrying out deeper multimodal search because the training setup finally rewards that behavior.
