TFRBench: Reasoning-Aware Forecasting Evaluation

Evaluate time-series forecasting by asking for step-by-step reasoning before the forecast, then checking if that reasoning is actually true.

Paper explainersAll themesTime Series & Sequential

When a model predicts a stock price or weather pattern, we normally just check if the number is right or wrong. But what if the model got lucky, or guessed correctly for the wrong reasons? This paper asks forecasting systems to explain their reasoning first, checks if that explanation is grounded in real events, then grades both the explanation and the forecast together.

Zero assumption version

We grade forecasts by accuracy alone

Right now, when a forecasting model predicts next month's temperature or next week's stock price, we measure success only on the final number: Did the model's guess match reality? If the number is close enough, the model wins, even if it used nonsense reasoning to get there.

A beginner would just train a neural network (a machine that learns patterns from data) on past numbers and check how close its predictions are to the real future numbers. This works fine for the score, but you never see the thinking—the model could be picking up on random patterns or getting lucky. The deeper problem: you have no way to know whether the model actually understands cross-channel dependencies (how different data streams relate to each other) or external events (holidays, announcements, weather), or if it is just overfitting to noise in the training data.

In one sentence. TFRBench requires forecasting models to first explain their reasoning step by step, verifies those explanations against real external events, then grades both the explanation and the forecast together.

The algorithm as a flow

What it actually does

Step 1: Retrieve external context

A Search agent finds real events (earnings reports, holidays, weather announcements) in the time range.

Step 2: Formulate reasoning hypotheses

A Reasoning agent reads the historical data and those real events, then writes explicit step-by-step assumptions about trends, seasonal patterns, and which channels depend on which.

Step 3: Verify assumptions

A Verifier checks whether each stated assumption can be confirmed (or contradicted) by the external context retrieved in step 1. The model records a confidence score (1–5) for each assumption.

Step 4: Generate forecast from reasoning

A Forecasting agent takes the verified reasoning and produces a numerical prediction for the next time period.

Step 5: Repeat with feedback

If the forecast is not accurate enough or reasoning confidence is low, the loop refines the reasoning and tries again, up to a fixed number of iterations.

What the paper changes

What the paper changes: the evaluation protocol

Benchmark design for time-series forecasting normally only checks the final number. TFRBench inserts an intermediate reasoning step between the input data and the forecast. Forecasting systems must now write down causal explanations (how different data channels relate, which external events matter, where trends are heading) before they predict.

The hidden quantity

The hidden quantity: reasoning groundedness

measured quantity  =  reasoning groundedness (confidence in external verification)

TFRBench measures whether a model's stated reasoning is actually grounded in verifiable external reality. This is different from prediction accuracy. A forecast can be numerically correct but based on false reasoning (lucky guess), or numerically wrong but based on sound logic that simply had incomplete information. The paper introduces a clarity score, assigned by the Verifier agent, that measures how many of the model's explicit assumptions can be confirmed against real external events (holidays, weather, news) rather than invented.

The paper estimates this quantity by having the Verifier agent check each assumption against a curated database of external events and scoring it 1–5 based on how well the stated logic aligns with that ground truth. A reasoning trace with all assumptions verified gets a high score; one full of hallucinations (false claims) gets a low score.

Why it works

Why it works: separate reasoning from luck

The core insight is that a correct forecast can come from either sound reasoning or blind luck. By forcing the model to write down its reasoning first, then verifying that reasoning against external ground truth, TFRBench teases these apart. A model that reasons soundly will usually also forecast accurately. A model that reasons poorly (hallucinating events, ignoring real trends) will often fail to forecast accurately, or get it right by accident. Over many forecasts, sound reasoning becomes a stronger signal than a single lucky guess because the odds of independent random alignments happening repeatedly shrink exponentially, while correct reasoning repeats reliably.

This improves forecasting because when you show the model verified reasoning traces (worked examples where reasoning matched real events and the forecast succeeded), the model learns to imitate that reasoning-then-predict structure. It copies the pattern: 'External event confirmed real, trend assumption verified, therefore forecast this direction.' This works better than learning from raw data alone because causal reasoning (anchored to real events) remains valid on new, unseen data, whereas accidental data patterns often break when the future does not repeat the past.

A tiny worked example
Suppose a model forecasts 'stock price rises 5%' with reasoning 'earnings report coming Friday; historically these boost prices 3-7%'.
Without reasoning: P(price rise | historical data) ≈ 0.45 (the data alone suggests a 45% chance).
With verified reasoning: P(price rise | earnings event confirmed + historical pattern verified) ≈ 0.72 (now we know the event is real and the pattern holds, so 72% chance).
The verified reasoning more than doubles the confidence because it grounds the forecast in causal logic, not just data noise.

The key is the verification step: when the model's reasoning is checked against real external events, it filters out hallucinated explanations; only reasoning backed by ground truth gets used to shape the forecast, so spurious patterns are suppressed.

What can go wrong

What can go wrong

Circular reasoning. If the external events database is missing or outdated, the Verifier cannot confirm assumptions. The model learns to hallucinate 'verified' explanations that sound real but are not checked. Fix: maintain external event ground truth carefully, tie it to real news sources and official records.
Reasoning confuses correlation with causation. The model might state 'traffic increases whenever it rains' (true) and conclude 'rain causes traffic' (false; both respond to commute time). The Verifier checks if the correlation holds in data but cannot always catch false causal direction. Fix: include domain experts in benchmark design to catch invalid causal claims.
Models memorize reasoning patterns without understanding. If reasoning traces are too repetitive or formulaic, models learn to output the words 'verified trend' and 'confirmed event' without actually checking. Fix: vary the reasoning templates and require models to justify specific numbers, not just names.
Done right. When the external event ground truth is curated, when the Verifier is calibrated fairly, and when feedback refinement loops are capped (to avoid infinite loops), reasoning-grounded forecasting becomes interpretable and stable.
What a runnable demo should prove

What a runnable demo should prove

Build a simple time-series dataset with five data channels over 100 time steps, with a few real external events marked (for example, a holiday or weather event inserted into the sequence). Feed this to a basic language model and prompt it three ways: (1) direct forecast (just predict next values), (2) forecast with reasoning (write reasoning first, then forecast), and (3) forecast with reasoning plus external events (write reasoning, search a provided event list, verify against it, then forecast). Measure accuracy (mean squared error between predicted and actual next 10 steps) for each mode. Separately, manually check whether the reasoning in mode 3 actually cites the real external events, and assign a reasoning quality score on the scale: hallucinated (0), vague (1), grounded in events (2).

improvement = (mode3_accuracy - mode1_accuracy) / mode1_accuracy; reasoning_quality = (num_assumptions_verified) / (total_assumptions)

If mode 3 both forecasts more accurately and produces verified reasoning, you have shown that grounding forecasting in verifiable external logic works because causal reasoning (reasoning tied to real events) is a stronger predictor of future outcomes than pattern-matching alone.
