Delta-XAI: Explaining Time Series Prediction Changes

A method to explain why a time series model's prediction changed at each moment by tracing through past measurements.

When a medical sensor flags a patient as high-risk, or a stock trading system sells, we need to know why the prediction changed right now. But most explanation tools examine each time step in isolation, missing that predictions shift because of patterns unfolding over time. Delta-XAI fixes this by explaining prediction changes by accounting for how the past events shape the present decision.

Why we cannot explain prediction changes

A time series model reads a stream of measurements over time and makes a prediction at each step. When that prediction suddenly changes, a clinician or trader needs to know: what in the data caused this shift? But standard explanation methods (tools that highlight which input numbers matter most) analyze only the current measurement in isolation. They ignore that predictions in time series depend on a sequence of past events building up to the present moment.

A beginner might try: show which part of today's input matters most. But this fails because it does not explain the change — it cannot tell us what in the history made the model switch from predicting A yesterday to predicting B today. The model saw Tuesday through Thursday's data; if it flipped on Friday, we need to know what Friday revealed that was different in context of Tuesday-Thursday, not just what Friday looked like alone.

The method. Track how each past measurement's contribution to the prediction shifted, by running the explanation through a sliding window that always includes recent history, not just the current step.

What the paper changes

What the paper changes

The paper changes how the explanation method traces its computation: instead of asking what today's input alone contributes, it asks what each moment in recent history contributed as the model saw the days unfold.

the object it moves  =  the path of data changes the explanation follows
The hidden quantity

Temporal contribution: credit for each past step

measured quantity  =  how much each past observation moved the prediction

The hidden quantity is the contribution score for each measurement in the recent history — a number that says how much that day's data pulled the prediction up or down. In a time series, the model sees a sequence, and we need to know which moments in that sequence were the pivotal ones.

The paper estimates this by using a gradient-based technique that asks: if we gradually changed the path from no history to the full history, how much would the prediction shift at each step? By running this path through a sliding window (the recent few days, not back to the start), the method captures which earlier moments contributed most to today's flip.

Why it works

Why past context fixes the explanation

The problem with explaining each step alone is that time series models use memory — they accumulate information from multiple time steps. A sequence of small rises in a patient's heart rate is not alarming on day one but alarming on day five, because the five-day trend is what matters, not the single value. Standard explanation methods that score only today's measurement miss the accumulation.

The fix: run the explanation path through recent history, not in isolation. The technique (which normally asks how much each input contributes) now asks it differently — it starts from a reference point that includes the past few days, then gradually adds today's data, and measures how much the prediction changes along that path. This way, each earlier day gets credit for having set up the context, and today's contribution is explained not as an absolute value but as a change relative to what the history predicted. The result: we now see that four days of slow rise is what made today's spike the tipping point, not just that today's spike exists in isolation.

Math after the picture

The shifted integration path

First in words:

The contribution of each input measurement is the sum of tiny nudges along a path that starts from the recent history and ends at the full current data, divided by the number of steps. For each position in time, measure how much the prediction shifts when that measurement is gradually included.

Then the compact form:

contrib_t = (prediction(history + today) - prediction(history)) / steps * sum_i=0_to_steps (gradient at step i along path from history to data)

Every symbol:

contrib_tthe influence score for time step t, showing how much it contributed to the prediction change
historythe reference data from the past few days (the window)
todaythe current measurement
gradientwhich way and how fast the prediction changes when the input shifts slightly
paththe imaginary sequence of inputs from history-only to history-plus-today
stepshow many tiny increments we divide the path into (more steps = smoother estimate)
A tiny worked example
Suppose the model, seeing days 1-3 of historical data, predicted a risk score of 40.
With days 1-4 added, the model predicts risk 55 — a change of 15 points.
We divide the path into 10 small steps and ask: at each step from day 3 to day 4, how much does the gradient nudge the output?
Step 1 (10% of day 4 added): gradient is 1.0 × 0.1 = 0.1, contributes 0.1 × 15 = 1.5 to total
Steps 2-10 sum similarly, totaling ~15.
Day 4's contribution score: 15 (it caused the 15-point jump)
Days 1-3's contribution: already counted in the starting point (risk 40), not re-counted

The core idea: instead of asking how much day 4 matters alone, we ask how much it changed the prediction relative to the history — answering the real question: why did the model flip?

What can go wrong

What can go wrong

Window too short. If the relevant history is longer than the window, important patterns get missed. A three-day window cannot explain a monthly trend.
Reference point does not match reality. The starting point (the past data) must resemble cases the model has seen before. If the window includes an unusual pattern, the explanation path becomes misleading.
Overlapping contributions. Multiple earlier days might jointly drive the shift in ways that are not additive. Assigning credit equally can mislead.
Done right. With a window sized to the relevant history and validated on held-out sequences, SWING consistently explains which past moments drove the prediction flip.

What a runnable demo should prove
