RFS: Residual Flow Steering for dexterous manipulation

Finetune a pretrained movement model by steering its internal randomness and adding small corrective actions, enabling both global exploration and local precision fixes.

Paper explainersAll themesRobotics & Control

Robots are trained to perform complex hand movements by imitating humans in simulation. These pretrained models work reasonably well, but when deployed in the real world they often make small, systematic mistakes—a finger lands 2 millimeters too far left, or the grasp angle is slightly off. The natural fix is to keep learning on the real robot, but you must balance two competing needs: explore new strategies to fix the mistakes (which requires trying bold new movements), while also making small precise tweaks to correct the local errors without forgetting everything the model learned before.

Zero assumption version

Pretrained models are stuck between two needs

A robot hand is pretrained on thousands of recorded human demonstrations, learning a flow-matching model (a type of generative model that learns to produce realistic action sequences). This model works—it can generate smooth, coordinated movements for complex tasks like dexterous manipulation. But when you deploy it on a real robot, the world does not match the training videos perfectly. The robot's sensors are slightly different, the physics is a touch different, and the hand itself may be a slightly different model. These small mismatches compound into systematic mistakes: the model predicts an action that would work in the simulation videos, but fails in reality.

A beginner would try two simple fixes. First option: just keep the model frozen and hope it works anyway—but it does not handle the real-world mistakes. Second option: use traditional reinforcement learning, where the robot tries random actions, gets rewarded for success, and gradually learns better actions. This would fix the mistakes, but because the robot is starting from scratch, it would explore so randomly and broadly that it would forget all the good behaviors the pretrained model learned. You would trade good behavior for adaptability.

The problem in one sentence. Finetuning a pretrained generative model for robotics requires both local precision (small fixes to systematic errors) and global exploration (discovering new strategies), but these two goals normally pull apart.

The algorithm as a flow

What it actually does

Start with a pretrained generative model

A flow-matching model (trained on human demonstrations) can generate realistic actions—smooth, multi-step, coordinated hand movements.

Identify two adjustment knobs

One knob controls the initial random noise fed into the model (global steering). One knob adds a small correction action on top of the model's output (local steering).

Run episodes and measure reward

The robot tries actions using both adjusted knobs, executes them, and the experiment measures whether the task succeeded—grasp a cup, manipulate a ball, etc.

Optimize both knobs via reinforcement learning

A reinforcement learning algorithm (e.g., tracking which actions raise reward and nudging the policies in that direction) learns which noise distributions and which residual corrections increase reward.

Result: efficient, adaptive behavior

The robot keeps the good pretrained behaviors, explores smartly by controlling the noise, and corrects errors with tiny, precise tweaks.

What the paper changes

Two things the paper changes

The paper does not rewrite the entire pretrained model. Instead, it introduces two separate, lightweight adjustments that are applied on top of the frozen pretrained model. The first adjustment is a policy (a learned strategy) that picks the latent noise distribution—the random starting point fed into the model when generating an action. The second adjustment is a second policy that outputs a small residual action added directly to the pretrained model's output. Both adjustments are learned via reinforcement learning. The core pretrained model itself stays fixed, so the model's learned structure and knowledge are preserved, because the weights of that base model never change during the finetuning process—only the two external adjustment policies are updated.

the object it moves  =  Latent noise distribution and residual action
The hidden quantity

The hidden quantity: distance from training data actions

measured quantity  =  Distance from training-data actions

When a pretrained generative model samples actions, it naturally stays close to the world of actions it has seen in training data, because that is what it learned from. A central quantity the paper implicitly measures is how far the robot can move away from this familiar territory during learning. Steering the latent noise allows the model to generate new actions—movements that were not explicitly in the training data, because varying the noise input to a trained flow-matching model changes which parts of the learned action space the model samples from. Residual actions add another way to escape the familiar actions. The paper does not explicitly compute this distance, but the RL reward signal indirectly measures whether these new explorations succeed or fail. If the added actions and noise steering never tried anything new, the model could never correct systematic errors unique to the real world. The fact that the method works means the two steering mechanisms are successfully finding new actions just enough to discover better behaviors, because the RL algorithm only reinforces steering choices that increase the task reward.

The paper estimates this through trial and error: the RL agent iteratively tries new noise distributions and residual actions, observes which ones improve the task reward (grasp success, object manipulation accuracy), and reinforces the choices that work, because higher rewards mean those steering choices led to successful off-manifold behaviors. This is indirect measurement—the manifold distance is never explicitly calculated, but the reward signal feeds back which explorations were productive.

Why it works

Why it works: three layers of steering

The flow-matching model is a machine that turns two inputs into an action. One input is the robot's current state (the positions and velocities of the fingers, the object location, etc.). The other input is a random noise vector drawn from a standard Gaussian distribution (a bell curve centered at zero). The model has learned to blend these inputs to produce smooth, realistic actions. In the original pretrained version, the noise is always sampled from the same Gaussian, and the state is fed in unchanged. RFS unfreezes both inputs.

First steering lever: latent noise. Instead of drawing the noise from a fixed Gaussian, RFS trains a small policy that looks at the current state and outputs a custom noise distribution. This distribution might be wider in some directions (encouraging bold exploration) or narrower in others (staying conservative where the pretrained model is already good). Because the flow-matching model is trained to interpret different noise values as different exploration styles, this steering is efficient—a small change in the noise distribution can shift the entire range of behaviors the model considers. The RL algorithm learns which noise adjustments lead to higher rewards.

Second steering lever: residual actions. After the flow-matching model outputs an action, RFS adds a second, small correction action from another learned policy. This happens in the output space, not the latent space, so it can make fine-grained corrections—tilt the grasp angle by 5 degrees, nudge the final position by a millimeter. The residual action is typically learned to stay small, so it tweaks the pretrained behavior rather than replacing it.

Why this split works mechanically: noise steering explores broadly (trying different interpretations of the state) while residual steering corrects narrowly (making precise fixes). The pretrained model's knowledge (smooth coordinated movements, reasonable hand postures) is preserved because the base model never retrains. The RL algorithm learns to balance the two: when noise steering alone cannot solve the problem, add more residual action; when residual actions alone would become too large or nonsensical, adjust the noise distribution instead. The result is data-efficient because both adjustments operate on top of the pretrained model rather than starting over.

The two-part objective

First in words:

Maximize the sum of future rewards by optimizing both the noise-steering policy and the residual-action policy, starting from a pretrained base model.

Then the compact form:

A tiny worked example
Suppose the robot must grasp a cup. The pretrained model suggests: move fingers to 45-degree angle. But a real cup sits at 47 degrees. Without steering, the grasp fails (reward = 0).
The noise-steering policy learns: for this state, use a wider noise distribution to explore multiple angles. The flow-matching model now considers 43, 45, 47, and 49 degrees.
The residual-action policy learns: add +2 degrees correction. Combined action: 45 + 2 = 47 degrees. Task succeeds (reward = 1).
Next episode, the model refines: which noise distribution and which residual action maximized cumulative reward? It adjusts both to perform better.
Over many episodes, both policies converge: noise steering explores angles near 45–50 degrees, residual steering fine-tunes within ±3 degrees. Grasp success climbs from 0% to 85%.

The core mechanism is the sum: the final action is the base model's output plus the residual correction, and the RL algorithm learns to optimize which noise distribution the base model samples from, then which correction to apply afterward.

What can go wrong

What can go wrong

Noise steering alone cannot fix systematic errors. Steering the latent noise lets the model explore different realizations from the same learned space, but it cannot generate actions far outside what the training data showed. If the real robot's error is not captured by any action in the pretrained model's training data, varying the noise will not help, because the noise only affects how the trained model interpolates within its learned territory.
Residual actions alone become large and unstable. If you only add residual corrections and never adjust the base model's exploration (the noise), the residual policy will grow larger and larger, trying to correct fundamental mismatches. Large corrections are less stable and may not generalize to new tasks or new real-world conditions.
Catastrophic forgetting if the RL reward is poorly designed. If the reward only cares about the immediate task (grasp this cup), the residual and noise policies will overfit to that one task and forget the general manipulation behaviors learned in pretraining. A good reward must balance task success with stability—e.g., penalizing very large residual actions or extreme noise distributions.
Done right: both steering mechanisms together. When latent noise steering explores large-scale behavioral changes and residual actions make small corrections, the RL algorithm efficiently learns what works. The pretrained model is a strong prior (the model believes in smooth, coordinated motion), and the two steering mechanisms are like fine-tuning knobs on that prior.
What a runnable demo should prove

What a runnable demo should prove

Build a simple dexterous manipulation task: a robot hand must pick up an object (a sphere, a small box, or a cylinder) and move it to a target position. Pretrain a flow-matching model on 50 simulated demonstrations of this task. Then introduce a small real-world mismatch—e.g., the object is slightly heavier, or the hand's actuators are 5% slower. Measure the success rate of the frozen pretrained model (should be low, around 20–40%). Then train the noise-steering and residual-action policies using only 20 real-world trials via reinforcement learning. Track how the success rate rises and whether the two steering mechanisms are learning complementary behaviors—e.g., noise steering converges to a specific distribution shape, while residual actions stay small but consistent.

Success_rate = (successful grasps after RFS) / (total attempts); Forgetting = (pretraining success on original sim task) - (success on original sim task after RFS); Residual_size = mean absolute value of residual action across episodes

The demo must show that RFS adapts quickly (high success after 20 trials) without catastrophic forgetting (the original simulation task stays >80% successful) and without requiring huge residual actions (mean residual magnitude <20% of typical action magnitude).
