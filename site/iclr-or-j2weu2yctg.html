Poisson Midpoint Method for Log Concave Sampling

Poisson midpoint cuts the cost of sampling from smooth bowl-shaped probability distributions by switching from single steps to batched half-steps.

Paper explainersAll themesOther

Sampling from a probability distribution (generating random examples that follow a desired pattern) is used in physics simulations and machine learning. When the target pattern has a smooth bowl shape (log-concave), the standard algorithm drifts a particle down the slope. This paper replaces single steps with batches of half-steps via the Poisson midpoint method, cutting the cost by a cubic factor in accuracy.

Zero assumption version

The cost of sampling from smooth distributions

To sample from a probability distribution, we place a particle at a random point and let it drift downhill via Langevin dynamics (a method that combines following the slope with random pushes). At each time step, the particle moves down the slope and gets nudged by random noise. The standard Euler-Maruyama algorithm takes uniform steps and counts how many slope evaluations it takes to converge to the target distribution (measured by Wasserstein distance, which measures how far apart two distributions sit).

The naive cost is proportional to the condition number times the inverse two-thirds power of accuracy. In plain words: if you want an answer ten times more accurate, you need roughly one thousand more slope evaluations, because making accuracy ten times better means dividing accuracy by ten, and raising that to the minus two-thirds power gives a thousand. That seems like a fundamental wall: maybe sampling just costs that much?

The problem in one sentence. Sampling via Langevin dynamics requires many slope evaluations because the standard algorithm takes tiny uniform steps and must recompute the slope at each step.

The algorithm as a flow

What it actually does

Start at random point

Place the particle anywhere in the space, with any initial velocity.

Group the trajectory into batches

Instead of one step at a time, gather k candidate half-steps together.

Evaluate slope once per batch

Compute the downhill direction at the starting point; reuse it for all k half-steps via the midpoint trick.

Compute corrections from full step

Take one full move with that slope direction, then use its error to fine-tune the k half-step paths.

Repeat: converges with cubic speedup

Fewer oracle calls needed because one slope evaluation powers k moves.

What the paper changes

What the paper changes

The Poisson midpoint method reorganizes the discretization of Langevin dynamics from one-at-a-time steps to batches of half-steps with shared slope information. Euler-Maruyama treats each step independently and evaluates the slope at each position; Poisson midpoint groups them and reuses slopes within each group.

The hidden quantity

Oracle complexity: how many slope evaluations are needed

measured quantity  =  Number of slope evaluations required

The hidden quantity is oracle complexity: how many times must the algorithm evaluate the slope (gradient) function to reach a target accuracy? It is counted as the total number of slope evaluations the algorithm performs until it converges.

The paper estimates this by tracking convergence in Wasserstein distance (the side-by-side coupling distance between algorithm output and true distribution, measured in space). Poisson midpoint reaches the target distance using a number of slope evaluations proportional to the inverse one-third power of accuracy, breaking the Euler-Maruyama bound which is proportional to the inverse two-thirds power.

Why it works

Why batching half-steps saves slope evaluations

Langevin dynamics has two components: drift (follow the downhill slope) and diffusion (random pushes). Standard Euler-Maruyama computes the slope at every single step, which is expensive. The Poisson midpoint method groups k tiny steps together, evaluates the slope once at the start, and reuses it to guide all k half-steps via the midpoint rule. The catch is computing a correction term: the difference between where reusing an old slope would push and where the true current slope would push. But this correction is built into the algorithm and costs only one extra full-step computation per batch. Because one slope evaluation powers k moves, the total number of slope calls drops dramatically.

This works because slopes change slowly over short distances in smooth bowl-shaped distributions. Reusing an old slope for several steps loses only a small error amount, and the midpoint correction absorbs it efficiently. The cost per move drops from one slope evaluation to one over k, a linear savings that compounds into the cubic speedup at the end.

Math after the picture

Simplified oracle complexity formula

First in words:

Number of slope evaluations equals condition number times inverse cube root of accuracy target.

Then the compact form:

N = c * kappa * epsilon^{-1/3}

Every symbol:

Nnumber of slope evaluations needed
kappacondition number (ratio of steepest slope to gentlest slope)
epsilontarget accuracy (how close to the true distribution)
ca small constant (around 1-10)
A tiny worked example
Suppose condition number = 100 and target accuracy = 0.001 (one-thousandth). Take inverse cube root of 0.001: that is 0.1. So N = 100 * 0.1 = 10 slope evaluations needed.
Euler-Maruyama on the same problem: take inverse two-thirds power of 0.001, which is 100. So N = 100 * 100 = 10000 slope calls (one thousand times more).
Same accuracy, one thousand fewer evaluations, because the inverse one-third power grows much slower than inverse two-thirds as accuracy improves.

Poisson midpoint scales with inverse cube root of accuracy, while Euler-Maruyama scales with inverse two-thirds power, making Poisson cubic speedup winner.

What can go wrong

What can go wrong

Non-smooth distributions fail. If the energy shape has sharp cliffs or corners (not smooth bowl-shaped), the slope reuse breaks down because slopes change rapidly and the corrections become unreliable.
Batch size too large amplifies reuse error. If batch size k is chosen too large, reusing a single slope across many half-steps introduces too much error because the actual slope has drifted far from the original. The correction term cannot absorb such large errors, because it was designed for small step sizes.
Momentum version requires careful implementation. The underdamped version (which includes particle velocity) requires computing exponentials of numerical tables (arrays of numbers) and combining those tables with numerical lists (vectors); rounding errors can accumulate if the code is not carefully crafted.
Done right: smooth distributions, moderate batch sizes, stable code. For smooth bowl-shaped targets with well-tuned batch size and numerically stable implementation, the method achieves its theoretical cubic speedup.
What a runnable demo should prove

What a runnable demo should prove

Sample from a 2D Gaussian distribution (the simplest smooth bowl-shaped example) using both Euler-Maruyama and Poisson midpoint. Run each algorithm for increasing accuracy levels (target distance from true distribution: 0.1, 0.01, 0.001, 0.0001) and record the number of slope evaluations it takes. Plot the number of evaluations versus accuracy on a log-log graph. The Poisson midpoint curve should be much flatter than the Euler-Maruyama curve, showing that adding one more zero to accuracy requires fewer additional evaluations.

slope_evaluations_used = total number of times the algorithm computed the downhill direction

The demo makes concrete: as accuracy demand grows tenfold, Euler-Maruyama needs roughly forty more evaluations, Poisson midpoint needs only four more, proving the cubic speedup.
