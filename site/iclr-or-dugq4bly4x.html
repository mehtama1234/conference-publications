Reducing Symmetry Increase in Equivariant Neural Networks

When a neural network respects symmetries, symmetric inputs accidentally gain extra unwanted symmetry, losing information—this paper predicts when it happens and shows how to design features to stop it.

Paper explainersAll themesGraph & Geometric Learning

Some neural networks are built to respect symmetries: if you rotate an object, the network's internal representation rotates the same way. These networks are useful for 3D objects, molecular structures, and any data with spatial structure. But there is a hidden trap: when the input itself is already symmetric, the output becomes even more symmetric than it should be, erasing details. This paper proves exactly when this trap springs, and shows how to redesign the feature space to avoid it.

Zero assumption version

Symmetry eaters symmetry

A neural network that respects symmetries (called equivariant) works like this: if you rotate the input, the output rotates the same way. This is useful because it means the network never wastes time learning the same thing in different orientations—it learns once and applies everywhere. This matters for molecules (where atoms can be rotated), 3D object recognition (where viewpoint changes), and any task where rotating or flipping the input should rotate or flip the prediction.

But here is the trap: if the input itself is already symmetric (e.g., a square, which looks the same after rotation by 90 degrees), something strange happens. The output becomes even more symmetric than it should be. A square is symmetric under 4 rotations; after the network processes it, the output might be symmetric under 8 rotations, or even all rotations. Information is lost. The network has thrown away details about orientation that the input actually contained.

In one sentence. The paper proves what causes symmetric inputs to gain unwanted extra symmetry, and shows how to choose features to prevent it.

What the paper changes

The thing the paper changes

The paper changes which numbers go into the feature space—the components of the network's internal representation. Instead of picking them arbitrarily, the paper gives rules: choose components whose symmetry properties are known and match the input's. This is a design choice made before training starts.

The hidden quantity

Orbit type: the symmetry fingerprint of a point

measured quantity  =  Orbit type (symmetry class of a point)

An orbit type is the answer to this question: which transformations leave a point unchanged? For a square, some points are at corners (unchanged by 90-degree rotations), some are at edge midpoints (unchanged only by 180-degree rotations), and the center is unchanged by all rotations. The set of symmetries that fix a point is called its orbit type. Different points have different orbit types.

The paper measures orbit types for every point in the input data and in the chosen feature space. It then checks: are the orbit types in the output the same as in the input? If not, information was erased. The paper provides algorithms to compute which orbit types will appear in the output, and what the smallest unavoidable set is.

Why it works

Why design controls symmetry increase

The reason symmetry increases is mathematical: when you apply an equivariant function to a symmetric input, the constraint that the output must respect the input's symmetry can force extra symmetry in the output. The input is a list of numbers with certain symmetries; the equivariant map must respect those symmetries. But the feature space (the numbers the map can produce) might not have room for all of the input's orbit types. When an orbit type is missing from the feature space, the output must belong to a larger symmetry class just to fit the mathematical constraints—it is forced, not chosen.

The paper's fix: predict which orbit types the output will be forced to have, then choose a feature space that has exactly those orbit types available. With the right choice, every input orbit type maps to an output orbit type that preserves the same symmetry information, because the feature space has exactly the room needed—nothing more (which would cause extra symmetry), nothing less (which would cause loss).

Math after the picture

The orbit type test

First in words:

To test whether an orbit type H is present in a feature space V, check if the dimension of the fixed points of H equals the dimension of the fixed points of all subgroups containing H.

Then the compact form:

dim(V^H) - dim(V^{H_i}) > 0 for all H_i that strictly contain H

Every symbol:

V^Hthe set of vectors in feature space V that stay unchanged under all symmetries in orbit type H
dim(V^H)how many free numbers in that set (its dimension)
H_ia larger orbit type that contains H
V^{H_i}vectors unchanged by H_i
A concrete example: testing a square
Input: square (orbit type with 4-fold rotation symmetry = group C4)
Feature space: 12-dimensional representation of C4
Test: are points with 4-fold symmetry available in the feature space?
Compute: vectors in feature space fixed by all 4 rotations = 3 dimensions
Compute: vectors fixed by 2-rotation (subgroup) = 6 dimensions
Difference: 3 < 6, so this test passes: 4-fold orbit type IS available
Conclusion: input symmetry can be preserved in output if features are chosen this way

The algorithm checks each orbit type by comparing fixed-point space dimensions; if the dimension increases when you go to a subgroup, the orbit type is present.

What can go wrong

What can go wrong

Choosing the wrong orbit type threshold. If you compute the minimum forced symmetry increase but then choose features with less symmetry, information will still be lost. The algorithm gives a hard lower bound: the minimum extra symmetry that any feature space must have is fixed by the input's structure. Choosing features with less symmetry cannot reduce this forced increase—the mathematics just forces the output symmetry higher regardless.
Misidentifying the input symmetry group. If the symmetry of the input is not correctly recognized (e.g., confusing 4-fold rotation with 8-fold), the computed orbit types will be wrong and the feature space will be poorly matched.
Using representations with too-small orbit type sets. Some mathematical representations just do not have certain orbit types available. If the data has those orbit types but the chosen representation does not, no amount of tuning helps, because the missing orbit type means the output must be forced into a larger symmetry class just to satisfy the equivariance constraint. The only solution is to pick a different, richer representation that has the needed orbit types.
Done right. When the input symmetry is known, the paper's algorithm computes the exact set of orbit types that must be available, and you choose a representation that has them. Information is preserved.
