Learning from limited labels

Papers on training models when you have few labeled examples, by actively choosing which data to label, learning from unlabeled data, or using synthetic data.

All themesField mapMathematicsAll explainers
What this is

Labeling data by hand is expensive and slow. A doctor labeling medical images, a translator labeling text, a quality engineer labeling defects — all of this takes human time. Yet many machine learning models need thousands or millions of labeled examples to work well. The question is: can you learn from a much smaller set of labeled data by being smart about which examples you ask a human to label, or by using unlabeled data to fill in gaps?

The hard part is that the model has to learn patterns from a tiny set of labeled examples, which means it easily memorizes the examples instead of learning the real pattern. It is also hard to know which examples to label. If a human labels 100 examples picked randomly, it is inefficient — some will be easy and tell the model nothing new. You need to focus on the examples that teach the most: the ones the model is uncertain about, or the ones that represent patterns the model has not seen before.

Researchers approach this through multiple strategies. Active learning systems identify which examples a human should label to maximize learning — for example, by asking about examples where the model is most uncertain. Semi-supervised learning uses unlabeled data: the model trains on labeled data, then looks for patterns in unlabeled data that are consistent with what it learned (for example, if the model learned that images of dogs have pointy ears, it can cluster images by ear shape even without labels). Self-supervised learning creates labels automatically by hiding part of the data and asking the model to predict it (for example, hiding one word in a sentence and training the model to predict the word, which teaches it about language). Some researchers even use synthetic data — generating fake labeled examples that have the same patterns as real ones — to supplement scarce real labels.

How the work breaks down

Learning from limited labels splits into four main strategies. Active learning picks which examples to label for maximum learning, because labeling is expensive so you should focus on the ones that teach the most. Synthetic data generates fake labeled examples to supplement real ones, which saves labeling cost by automating the creation of training data. Semi-supervised approaches use unlabeled data alongside the few labeled examples, since most real data is unlabeled and can provide signal about what patterns exist. And data valuation helps you pick which real examples are most worth labeling by scoring which ones would improve the model the most.

Active learning: picking which examples to label

When humans hand-label data, every label costs time and money. So you need to pick which examples to ask them to label. The hard part is knowing which examples matter most: some examples are easy and teach the model nothing new, while others teach fundamental patterns. Active learning solves this by having the model identify the examples it is most uncertain about, since uncertainty often points to patterns the model hasn't learned yet.

Exposing Mixture and Annotating Confusion for Active Universal Test-Time Adaptation tackles this when you have a model already trained on old data but now facing new data it wasn't built for (when the new test data looks different from the training data). It uses active learning to strategically spot which of the new examples would teach the model the most if they were labeled. By annotating those high-uncertainty regions, the model learns to adapt to the new environment with far fewer labeled examples than random labeling would require, because the uncertain examples reveal gaps in the model's understanding. The Signal is in the Steps: Local Scoring for Reasoning Data Selection takes a different angle: when a large language model is learning to reason through hard problems, it looks at the model's intermediate steps to decide which solution attempts are worth saving. Rather than just checking if the final answer is right, this method scores each step along the way, which helps it pick diverse training examples that teach different aspects of reasoning—because examining each step reveals which parts of the reasoning the model struggles with.

Synthetic data to teach real reasoning

Hand-labeled data is scarce, but synthetic data is free: you can generate unlimited fake labeled examples. The question is whether a model trained on fake data actually learns patterns that work on real data. Many people worry that synthetic examples are too artificial or miss edge cases that matter in the real world.

Learning from Synthetic Data Improves Multi-hop Reasoning tests this directly: it trains language models on synthetic examples where the reasoning steps are fake but follow real patterns (connecting multiple facts to answer a question)—this approach works because the fake reasoning still teaches the model how to connect ideas, which is the hard part. The model learns from these synthetic examples and then evaluates on real benchmarks. The result is that fine-tuning on synthetic data teaches genuine reasoning skills that transfer to real problems, not just memorization, which shows that the model learned the underlying reasoning logic rather than memorizing specific examples. The method shows synthetic data isn't a shortcut or a toy—it actually teaches fundamental patterns. Few-Shot Optimization of Synthetic Preferences uses a similar idea for preference learning: instead of collecting hundreds of real human preferences, the method generates synthetic preferences, trains on them, then adapts to real users with just a few real examples. It achieves high win-rates on both synthetic and real users, which proves that synthetic training provides a strong starting point that real fine-tuning can improve on, since the synthetic examples teach the core concept and real examples only need to refine it.

Using unlabeled data alongside labels

Most real-world data is unlabeled: you have millions of examples but only a tiny fraction have labels. Semi-supervised learning exploits this by training a model on the labeled examples, then using it to find consistent patterns in unlabeled data. The model learns faster because unlabeled data provides signal about what patterns are common in the world, even without explicit labels.

Deep Model based Vertical Federated Learning with Flexible Alignment and Labeling Scenarios (which uses latent variables—hidden patterns you infer rather than observe) handles a specific hard case: when data is spread across multiple sites (hospitals, banks, companies), each with some labeled and some unlabeled examples, and the data has different structures at each site (some sites might have different features or different label availability). It builds a unified framework that learns from all of it—labeled, unlabeled, and misaligned data—across all sites together, which means each site can benefit from patterns in the others even though they don't share raw data. Preserve and Sculpt: Manifold-Aligned Fine-tuning of Vision-Language Models for Few-Shot Learning works with vision models in the few-shot setting: when you have only a handful of labeled images per class, the model can learn by staying close to the semantic structure of unlabeled images it has seen before (the manifold—the underlying shape of image space). This means the model preserves what it already knows about image semantics while tuning itself on your few labeled examples, so it doesn't forget what it learned from unlabeled data. Transitive Representation Learning Enhances Histopathology Annotation attacks the medical imaging problem: pathologists label tissue slides by hand, which is extremely expensive. This method learns from unlabeled slides by first learning which unlabeled slides are similar to each other, then uses that knowledge to help with few labeled slides. The transitive similarity structure (if slide A is like B and B is like C, then A is somewhat like C) helps the model generalize from very few human annotations, because the similarity structure creates a map the model can use to classify new slides even without explicit labels for them.

Data valuation: scoring which examples matter

When you have scarce labeling budget, you want to label the examples that help the most, because each labeling decision should maximize the model's improvement. Data valuation methods score each example by how much the model would improve if you added it to the training set, which tells you which examples are worth the cost of labeling. The challenge is computing this score fast enough to actually use—checking every example by retraining the model is too slow, so you need algorithms that estimate value without retraining.

Unifying and Optimizing Data Values for Selection via Sequential Decision-Making brings together many existing valuation methods under one framework (game theory's Shapley value, influence functions, and others). It then proposes a new way to compute scores: instead of checking each example independently, it uses a bipartite graph surrogate that lets you rank examples and greedily select the best ones without retraining. This means you can score thousands of examples and pick the most valuable ones to label, with theoretical guarantees that greedy selection is a good approximation of optimal selection.

Learning under privacy and data shift

Real-world learning has extra constraints beyond just label scarcity. Sometimes you must learn while preserving privacy (multiple organizations share data without exposing individuals). Sometimes the data has shifted from what the model was trained on, so you need to learn from new examples to adapt. These settings make limited-label learning even harder.

Deploying Models to Non-participating Clients in Federated Learning without Fine-tuning: A Hypernetwork-based Approach solves the problem of federated learning (multiple sites have private data and train together) when some sites join after training is done or don't participate in training at all. Rather than fine-tuning at each site (which is slow and leaks information), it uses a hypernetwork to generate the right weights for any new site with minimal computation. Privacy-Protected Causal Survival Analysis (which must account for data shift—when new patient populations differ from the training population) handles medical trials where sites have different patient populations and you can only share aggregate statistics, not individual data. The method learns causal effects (what treatment works for whom?) while protecting privacy and accounting for the differences between sites. LLM Unlearning via Post Judgment and Multi-round Thinking tackles a different problem: a language model has been trained on data you now need it to forget (perhaps due to privacy regulations or copyright). Unlearning must remove knowledge without destroying the model's general reasoning ability. This method uses post-judgment and multi-round thinking to identify what to unlearn precisely and remove it, even when adversarial attacks try to extract the supposedly forgotten knowledge.
