One Batch Is Enough: A Unified Dataset Condensation Framework for General Time Series Analysis

UniTSC replaces a huge time-series training set with a tiny synthetic set by matching temporal patterns, frequency content, and cross-channel structure all at once.

Paper explainersAll themesOther

Time-series systems are often trained on long recordings with many channels, many repeated patterns, and many near-duplicate windows. Training on all of that data costs memory, storage, and computation. Dataset condensation asks a harder question: can a very small synthetic training set preserve the same useful structure as the original large set? UniTSC says yes for time series, but only if the condensed data keeps three things that older methods often drop: what shapes appear over time, what frequencies carry energy, and how channels depend on one another. The paper builds a single framework that preserves those three views together, so the tiny set still teaches classification, forecasting, imputation, and other downstream tasks.

Zero assumption version

Why time-series condensation is harder than image condensation

A time series is not just a list of values. Order matters, periodicity matters, and in multivariate data the channels influence one another. If you compress the training set by keeping only a few windows that match average values, you can lose the shape of events over time, the repeating frequencies, or the way one channel moves with another channel.

Older condensation methods were built mostly for images, where a sample is a fixed grid and the main goal is often one task such as classification. Time-series work is broader. The same dataset may feed classification, forecasting, imputation, or anomaly detection. A condensed set tied to one task often transfers poorly, because it overfits the signal pieces that matter for that task and drops the pieces another task needs.

The failure mode is simple. A tiny synthetic set is useless when it copies only surface values and misses temporal order, frequency content, or channel dependence.

The algorithm as a flow

What it actually does

Encode each real sequence in three views

Use one encoder for temporal shape, one for spectral content, and one for multichannel structure.

Create synthetic sequences

Start with a very small learnable set that will stand in for the full training set.

Match optimization trajectories

Train a learner on real data and synthetic data, then force their weight-update paths to stay close.

Match spectra and dependencies

Align power spectral density and cross-channel dependency structure so the synthetic set keeps periodic content and multivariate coupling.

Reuse the tiny set across tasks

Evaluate the condensed data on several time-series tasks instead of tuning it for only one task.

What the paper changes

What the paper actually changes

UniTSC changes the target of condensation. Instead of asking a tiny synthetic set to imitate raw samples or serve one downstream loss, it asks the set to preserve three task-invariant properties of the original data: the learning signal seen during training, the frequency-domain energy profile, and the dependency structure across variables.

The hidden quantity

The hidden quantity: task-invariant signal content

measured quantity  =  How much of the original signal survives compression across tasks

The paper is really measuring whether the condensed set keeps the parts of the data that many tasks share. A forecasting model and a classification model may use different heads, but both still need access to basic signal content such as repeated frequencies, event timing, and channel coupling. If those shared ingredients survive, many tasks can learn from the same tiny set.

UniTSC estimates this through three spaces. Optimization trajectory alignment checks whether training on synthetic data pushes a learner in nearly the same direction as training on real data. Power spectral density checks whether the synthetic set places energy at the same frequencies as the real set. Dependency alignment checks whether channel relationships, such as lagged correlation or shared variation, are still present.

Why it works

Why the three alignments matter together

Optimization trajectory matching matters because a condensed set should teach a learner to update its weights in nearly the same way as the full dataset. If the update path is wrong, the learner will move toward a different solution even when the synthetic samples look plausible. This term therefore anchors the synthetic data to the training behavior of the real data.

Spectral alignment matters because many time-series signals are defined by where their energy sits across frequencies. A heart rhythm, an industrial vibration, and an electrical waveform can share similar average values while differing sharply in periodic content. Matching power spectral density keeps those periodic signatures, so the synthetic set does not flatten them away.

Dependency alignment matters because multivariate series are often useful only through relationships among channels. One sensor may lead another, or two channels may move together during a fault. If those links disappear, the condensed set becomes a bag of separate traces rather than a coherent multivariate process. UniTSC keeps those links by aligning a topological view of channel structure.

The framework uses a multi-view hybrid encoder so these alignments act on shared representations rather than on raw values alone. That matters because raw-value matching is brittle under shifts, offsets, and harmless local variation, while representation-level matching focuses the condensation process on the parts of the signal that remain informative across tasks.

The objective

First in words:

The synthetic set is trained to minimize three discrepancies at once: learning-path mismatch, spectral mismatch, and dependency mismatch.

Then the compact form:

L_total = L_traj + lambda_1 L_psd + lambda_2 L_dep

Every symbol:

L_trajdifference between model update trajectories from real data and synthetic data
L_psddifference between the real and synthetic power spectral densities
L_depdifference between real and synthetic multivariate dependency structure
lambda_1, lambda_2weights that balance the spectrum term and dependency term against the trajectory term
A tiny worked example
Suppose the real dataset has a strong 24-step period, a weaker 8-step period, and a tight coupling between channels A and B.
A first synthetic set matches the average waveform but misses the 24-step peak and breaks the A-B coupling. Training on it gives the learner a noticeably different update path.
UniTSC raises the loss in three places: the trajectory term is high because the learner updates differently, the PSD term is high because the 24-step peak is missing, and the dependency term is high because A and B no longer move together.
The synthetic sequences are then edited during optimization until those three mismatches shrink together.
When the three terms are small at the same time, the tiny set is no longer just visually similar; it trains downstream models in a similar way.

The equation matters because each term protects a different failure mode that a tiny synthetic set can suffer.

What can go wrong

What can go wrong

Weak encoder views. If the temporal, spectral, or structural encoders fail to extract the right information, the alignment losses can be small for the wrong reason, because the framework only preserves what those views can see.
Rare events vanish. Extreme compression can erase low-frequency but high-importance events such as rare faults, because the optimization tends to focus on structure that appears often enough to dominate the losses.
Task mismatch remains possible. A shared condensed set may still under-serve a task that depends on a narrow cue not captured by the three alignment spaces, because no finite summary can preserve every detail equally well.
Done right. The method works best when the encoder views expose the main temporal, spectral, and cross-channel structure of the source data, because then the synthetic set is pushed to preserve the ingredients that several downstream tasks reuse.
What a runnable demo should prove

What a runnable demo should prove

Build a multivariate toy dataset with known periodic content and known channel couplings. Condense it to fewer than 128 synthetic sequences. Train three downstream models on the full set and the synthetic set for three tasks such as classification, short-horizon forecasting, and missing-value filling. The demo should report not only task scores but also spectrum mismatch and dependency mismatch, because the point is to show why the tiny set transfers.

retention = downstream_score_synthetic / downstream_score_full

The demo succeeds when a one-batch synthetic set keeps most downstream performance and you can trace that result to matched update paths, matched spectra, and matched channel structure.
