Native Adaptive Solution Expansion for Diffusion-based Combinatorial Optimization

Turn a diffusion model into a solver by building solutions one piece at a time, letting the model decide what to add next based on confidence.

Paper explainersAll themesGraph & Geometric Learning

Solving puzzles like scheduling or routing requires finding arrangements that satisfy hard constraints. The two old approaches each fail halfway: building solutions step-by-step is slow, while guessing the whole answer at once creates conflicts. This paper weaves them together by making the diffusion model itself (a system that learns to gradually de-blur a picture) build solutions adaptively, expanding partial answers piece by piece based on how confident it feels about each piece.

Zero assumption version

Two broken roads to puzzle-solving

Imagine you need to arrange trucks to deliver packages, with limits on truck capacity, distance, and driver hours. You have to respect ALL the constraints at once. Neural combinatorial optimization (using AI to solve scheduling and routing puzzles) has two classic playbooks. Local Construction (LC) builds the answer one stop at a time, checking constraints as it goes — sound, but slow, because each new addition must consider all prior decisions. Global Prediction (GP) takes the whole problem and guesses the complete answer at once, via a heatmap or scoring function — fast, but it breaks: pieces of the answer conflict with each other and violate the hard constraints.

The recent Adaptive Expansion approach tries to combine them: build a partial solution step-by-step while using the model's global awareness to pick what to add next. But it bolts this onto existing predictors from outside, making the inference costly (the model is called over and over) and the solution quality depends entirely on the outer predictor's skill.

The problem in one sentence. Solvers must either build slowly while respecting constraints, or build fast while creating conflicts.

What it actually does

Start with a blurry guess

Begin with all pieces masked (hidden); the diffusion model sees this blur.

Score each candidate

For each piece the model hasn't yet added, compute how confident it is.

Unmask high-confidence pieces first

Reveal pieces with high confidence scores before low-confidence ones.

Check constraints hard

After each unmask, project the partial solution to remain feasible.

Repeat until complete

Cycle until all pieces are revealed and the solution is fully formed.

What the paper changes

What the paper changes

The paper makes adaptive expansion part of the diffusion model's own DNA, not a wrapper bolted on outside. Instead of calling an external predictor repeatedly, the diffusion model itself learns to gradually unmask pieces of a solution in an order that respects constraints and builds on its learned confidence.

the object it moves  =  Decoding strategy inside the model
The hidden quantity

Confidence: how sure the model is about each piece

measured quantity  =  Model confidence score per piece

As the diffusion model de-blurs the solution, every piece gets a confidence score — a number from 0 to 1 saying how sure the model is that this piece belongs in the answer. Low confidence means the model is unsure; high confidence means it has learned a strong preference for this piece.

The paper uses these confidence scores to decide which pieces to unmask first. High-confidence pieces get revealed early, and the model respects hard constraints (feasibility projection) as it goes. This turns the vague idea of adaptive expansion into something mechanical and efficient: expand in order of confidence, always stay feasible.

Why it works

Why it works: the diffusion unmasking loop

Diffusion models work by learning to gradually sharpen a blurry image into a clear one. NEXCO adapts this: instead of sharpening one picture, it learns to sharpen a solution from a fully masked blur into a fully detailed routing or scheduling arrangement. During training, the model learns the diffusion path from fully masked solutions to correct, constraint-respecting ground-truth solutions.

At solve time, the model reverses the diffusion: it starts with a fully masked blur and iteratively unmasking pieces in order of learned confidence. The reason this works is that intermediate diffusion states are not random noise — they are partial solutions where some pieces are revealed and others are still hidden. By respecting constraints at each unmask step (via feasibility projection), the model guarantees a valid solution without ever having to call an external checker.

This unmasking order is adaptive: the model's confidence scores change as pieces are revealed, so the order depends on the specific problem instance, not a fixed schedule. Early stops catch easy problems faster. The mechanism works because the diffusion model has learned, during training, what pieces tend to go together and what arrangements are likely to be feasible.

The diffusion unmasking score

First in words:

masked_loss = reconstruction_error_on_visible_pieces + confidence_weight * penalty_for_low_confidence_high_feasible_pieces

Then the compact form:

L = || M (y_pred - y_true) ||_2 + lambda * sum_i confidence_i * feasibility_i

Every symbol:

Ltotal training loss to minimize
Mmask (1 for visible piece, 0 for hidden)
y_predmodel predicted piece value
y_truecorrect piece value from ground truth
confidence_ihow sure model is about piece i
feasibility_iwhether piece i respects constraints
lambdahow much to emphasize easy-to-expand pieces

Piece A: visible (M=1), predicted=0.9, truth=1.0, error=(0.9-1.0)^2=0.01, contributes 0.01 to loss.
Piece B: hidden (M=0), no direct error term, not included.
Piece C: visible, predicted=0.5, truth=0.6, error=0.01, contributes 0.01.
Piece D: feasible and high-confidence (0.9), lambda * 0.9 * 1 = 0.9, encourages expansion.
Total visible loss = 0.02; feasibility term = 0.9; combined L = 0.92 encourages showing piece D.

What can go wrong

What can go wrong

Confidence miscalibration. If the model learns to give high confidence to pieces that will actually conflict, the unmasking order is wrong and the solution quality drops. This happens if training data has imbalanced or skewed constraint satisfaction patterns.
Feasibility projection may remove valid pieces. When the model unmaskas a piece and then projects the partial solution onto the feasible region, the projection may zero out a piece the model wanted. If this happens repeatedly, the model never sees the consequence of its mistakes and does not learn to avoid them.
Training instability on large problems. Diffusion models are hard to train; on large combinatorial problems with many pieces and many constraints, the signal to learn from becomes noisy and training can collapse.
Done right: confidence calibration + instance diversity. Train on diverse instances with varied constraint patterns so the model learns general confidence, because seeing a wide range of problems teaches the model which features of a problem tend to lead to valid decisions. Use confidence thresholds or early-stopping during solving so the model stops expanding if it becomes unsure, rather than forcing a complete solution, because a half-built valid tour is better than a full tour with constraint violations, and it saves computation.
What a runnable demo should prove

What a runnable demo should prove

Build a small instance of the Travelling Salesman Problem (visit each city once, return to start, minimize total distance). Start with five cities on a 10x10 grid. Encode each city's position and the distance between each pair, and encode the partial solution as a list of visited cities (some masked as unknown). Train NEXCO to map from a masked tour to the ground-truth tour for 100 random instances. At solve time, start with a fully masked tour, have the model compute confidence for each unmasked city, unmask high-confidence cities first, and recompute feasibility (the partial tour must not repeat cities). Measure solution quality (total distance) and wall-clock solve time.

solution_quality = total_distance_travelled; inference_time = seconds_to_build_full_tour; constraint_violations = count_of_repeated_cities

A working demo should show that the model unmaskas cities in an order that respects the constraint (no repeats) and finds a tour shorter than a random greedy baseline, while finishing in far less time than exhaustive local construction.
