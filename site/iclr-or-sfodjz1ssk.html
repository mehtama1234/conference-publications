DeNOTS: Stable Deep Neural ODEs for Time Series

To forecast irregular time series, add negative feedback to keep the model stable as you make it deeper.

Zero assumption version

The depth trap in time-series models

Irregular time series have gaps of different sizes between measurements. A simple method is to memorize patterns at fixed intervals, but real data doesn't cooperate. Neural CDEs—neural controlled differential equations—solve this by running a small neural network continuously through time. At each data point, the network reads the new value and updates its internal state smoothly. Deeper networks (run longer, through more time steps) usually learn more patterns.

But deeper CDEs fail in practice. As you integrate the neural network's equations longer, the model's internal state can explode into infinity or shrink to nothing without control. You can tighten the numerical solver's tolerance to reduce error, but tighter tolerances don't make the model deeper or more expressive—they just consume more computation for no gain in what the model can learn.

The core problem. Existing CDEs cannot go deeper without crashing because the model's internal state spirals outward and explodes; tightening solver tolerances helps nothing because they only improve numerical precision, not the model's ability to express patterns.

What the paper changes

What the paper changes

The paper changes the integration horizon—how long the model runs through time in one forward pass. Instead of controlling depth indirectly through the solver's tolerance (which only affects numerical precision), DeNOTS directly scales the time horizon, making the model evaluate the neural network more times and thereby go deeper. This one change, paired with negative feedback, transforms an unstable shallow model into a stable deep one.

The hidden quantity

The hidden quantity: state drift

measured quantity  =  state drift (maximum deviation from equilibrium)

As you run a neural network's equations continuously through time, its internal state—the numbers it is tracking—can drift far from where it started or where it should be. Large drift means the model is becoming uncontrollable and will crash or forget what it was doing. State drift is how far the internal numbers wander from their stable resting point. Without measurement, you cannot tell if your model is about to blow up.

DeNOTS estimates drift by tracking the largest value the state reaches during integration. The paper proves mathematically that if you add a term that pulls the state back when drift exceeds a threshold, the model will stay bounded. This is how negative feedback works: subtracting a term proportional to the state's current size provably limits drift to a known safe range.

Why it works

Why negative feedback keeps the model stable

A neural CDE's state evolves by following the neural network's vector field—a direction and speed at each point in state space. Without feedback, if the neural network naturally pushes the state outward, the state spirals away. Negative feedback is a term added to the vector field that always points inward, toward the origin. The term is proportional to the state's current size: if the state is twice as large, the feedback is twice as strong. This ensures that when the state drifts far, the inward pull dominates and brings it back. The model can still follow the neural network's patterns (express itself), but it cannot escape beyond a bounded region. Longer integration times (deeper models) are now safe because the feedback keeps the state tethered.

Mathematically, this is called Lyapunov stability: a chosen energy function (here, the state's magnitude) cannot grow forever if a restoring term is always active. The paper derives explicit bounds on how large the state can get given the feedback strength, so you know the model will not crash before you run it.

The equation: state with negative feedback

First in words:

The state's rate of change equals the neural network's direction plus a negative feedback term that is proportional to the state itself, pulling it back.

Then the compact form:

d_state/d_time = f_network(state, time) - gamma * state

Every symbol:

d_state/d_timehow fast the state changes (its rate of change with respect to time)
f_network(state, time)the neural network's prediction of which way the state should move, given its current value and the time
gammathe feedback strength (how hard we pull the state back in; set before training)
statethe internal numbers the model is tracking (a list of numbers)
A tiny worked example
At time t=0: state = [5, 3, 4] (all positive, drifting outward).
Network says: move by [1, 1, 1] (push outward).
Without feedback: new state = [5+1, 3+1, 4+1] = [6, 4, 5] (grows).
With feedback (gamma = 0.2): subtract 0.2 * [5, 3, 4] = [1, 0.6, 0.8].
After feedback: new state = [1, 1, 1] - [1, 0.6, 0.8] = [0, 0.4, 0.2] (pulled back in).
The larger the state, the harder it is pulled back. Drift is controlled.

The feedback term is proportional to the state itself; no matter how strongly the network pushes outward, the inward pull scales with the state's size and keeps it bounded.

What can go wrong

What can go wrong

Feedback too strong. If gamma is too large, the inward pull dominates and the model cannot learn anything (every move is cancelled out immediately). The network's expressiveness vanishes.
Feedback too weak. If gamma is too small, it doesn't rein in drift and the state still explodes. You must tune gamma correctly for each dataset.
Numerical solver still struggles. A poor numerical solver introduces discretization error (small mistakes at each step), which pile up over many steps and can push the state outside the stable region. DeNOTS addresses this by deriving bounds on discretization error: it estimates the maximum possible accumulated error from the solver and adds this to the stability calculation, so it can guarantee drift stays bounded even when solver error is included.
Done right. Set gamma by cross-validation and use a standard adaptive solver (like RK45). The paper proves that with the right gamma, drift is provably bounded and the model will not crash.
