Decomposition-Based Modular Conformal Prediction

When your model has two stages, you can attribute uncertainty to each stage separately instead of treating the whole pipeline as one black box.

Paper explainersAll themesLearning Theory

Most prediction systems have multiple stages: a first model produces intermediate results, then a second model uses those to make a final prediction. Standard methods measure overall prediction error but cannot tell you whether failures come from stage one or stage two. This paper shows how to break down prediction uncertainty into stage-by-stage components, so you know exactly where to fix problems.

The black box problem

When you chain two predictive models together, errors compound: the first model's mistakes become the second model's starting point. Today, standard uncertainty methods (called conformal prediction) measure the overall error but cannot split it: they answer how wrong you might be, but not which stage caused the wrongness.

A naive approach would be to measure the error at the output of stage one and the output of stage two separately. But that does not work, because errors that escape stage one without correction feed into stage two and look like stage two's fault. The two error sources are tangled.

The paper's move. Decompose the overall residual (the gap between prediction and reality) into a part caused by stage one and a part caused by stage two, then calibrate confidence bounds for each piece independently.

What the paper changes

What the paper changes

The paper modifies how you combine uncertainty estimates from two stages. Instead of treating both stages as a black box, it explicitly constructs separate confidence intervals (called quantiles) for the output error of stage one and the output error of stage two, then combines them in a way that guarantees overall coverage.

The hidden quantity

Stage-specific error contribution

The hidden quantity is the separate error magnitude at each stage. In a two-stage pipeline, you have three pieces: the raw input, the intermediate result from stage one, and the final prediction from stage two. The paper measures not just the total distance from final prediction to truth, but breaks it into the part caused by stage one being wrong and the part caused by stage two being wrong.

The paper estimates this by holding aside calibration data, running both stages on it, and measuring how far each stage's prediction strays from ground truth. This gives quantiles (percentiles of error size) for each stage separately.

Plain reading. Each stage makes a guess. The first stage's guess becomes the second stage's starting point. You measure how wrong each stage was on held-out data, giving you a typical error size for each stage. Then you use those typical errors to set confidence intervals.
Paper reading. Let R be the total residual (absolute error at final output). Decompose into ∆R1 (upstream contribution) and R2 (downstream residual). Compute quantile levels c, d from calibration data such that each stage's residual is bounded with high probability. Select scaling weights a, b (numbers controlling how much each stage contributes) via family-wise error rate control to ensure overall coverage guarantee.
Why it works

Why decomposition fixes the problem

When stage one makes a mistake, that mistake flows into stage two. A standard method treats the pipeline as a single unit: it sees the total error and cannot isolate where it came from. When you later retrain, you do not know whether to fix stage one or stage two.

By decomposing residuals, the paper separates the error into two sources. Stage one's error is the difference between its actual output and what the truth would demand of it. Stage two's error is what remains even given stage one's output as input. Now when you observe that the pipeline is poorly calibrated on new data, you can check which stage-specific residual grew. If stage one's errors increased, retrain stage one. If stage two's errors grew, retrain stage two. This is more efficient than retraining the whole pipeline, because retraining one stage takes less time and data than retraining both stages together.

The paper controls false claims using family-wise error rate (a statistical guarantee that says: if you pick any weights for combining the two stages' uncertainties, the overall confidence interval will still be honest). This means you can tune weights to adapt when data patterns shift (the values you see change over time) without breaking your coverage promise.

The residual decomposition

First in words:

total error equals stage-one error component plus stage-two error component, and the confidence interval is the weighted combination of each stage's error percentile

Then the compact form:

R = |y - µ2(µ1(w))| = ∆R1 + R2; confidence_interval = a * quantile_c(∆R1) + b * quantile_d(R2)

Every symbol:

ythe true target value
wthe raw input (e.g., sensor data)
µ1(w)stage one's prediction
µ2(µ1(w))stage two's final prediction
Rthe absolute error at the end
∆R1the error component from stage one
R2the error component from stage two
quantile_cthe c-th percentile of stage one's error (e.g., 90th percentile)
quantile_dthe d-th percentile of stage two's error
a, bscaling weights chosen to guarantee overall coverage
A tiny worked example
Suppose stage one predicts intermediate value 52 when the truth would demand 50, so ∆R1 = 2.
Stage two then predicts final value 98 when truth is 100, so R2 = 2.
Total error R = 2 + 2 = 4.
On calibration data, stage-one errors are often around 3 (the 90th percentile), stage-two errors around 2.
With weights a = 0.6 and b = 0.4: confidence interval = 0.6 * 3 + 0.4 * 2 = 1.8 + 0.8 = 2.6.
The true error was 4, which exceeds 2.6, so this was an under-confident bound.
The FWER method would adjust a and b to guarantee that across many examples, the interval covers about 90 percent of true errors.

The key is that a and b are chosen once and then apply to all future predictions, giving you a mathematical promise that your confidence intervals will be honest.

What can go wrong

What can go wrong

Stage one's errors are not independent from stage two's. If stage one consistently makes mistakes in a direction that stage two then amplifies, decomposing the residual does not fully separate the two error sources. The method assumes you can estimate each stage's error cleanly, but in reality they may be correlated.
Over-coverage in easy regimes. The paper uses a statistical guarantee (family-wise error rate control) that is conservative: it ensures coverage even in worst-case scenarios. On easy data where the true error is small, the method produces confidence intervals wider than necessary, wasting the promise of tight bounds.
Requires three data splits. You need separate training, conformal calibration, and weight-tuning sets (data used to pick the scaling weights). On small datasets, this fragmentation reduces the data each stage sees, potentially hurting both model accuracy and calibration quality.
Works well when stages are truly separable. If stage one's output is a true intermediate representation that stage two can reason about cleanly, then the decomposition is interpretable and the method shines. This is common in supply-chain prediction (one model forecasts subcomponent demand, another predicts total inventory need) but less obvious in end-to-end learning.
What a runnable demo should prove

What a runnable demo should prove

Build a two-stage prediction system on data with known pattern changes. For example, train a stock-price forecasting pipeline where stage one predicts a related stock's future price and stage two predicts your target stock given that forecast. Inject a change in data pattern that affects only stage one (e.g., a regime change in the related stock's volatility). Measure whether standard conformal prediction and this paper's method both maintain coverage. The test is: does the modular method correctly identify that stage one shifted while stage two remained stable, and does it keep confidence intervals honest without widening them unnecessarily?

coverage = fraction of test examples where true value falls inside the confidence interval; stage_attribution = whether the method's predicted error component matches which stage actually shifted

The demo must show that the method maintains roughly 90% coverage under stage-one shifts alone, while standard methods degrade to 50–70%, because the modular method can isolate and adapt to each stage's specific error pattern.
