Fixed Aggregation Features Can Rival GNNs

Simple fixed aggregation of graph neighbors produces features detailed enough to match deep graph neural networks, without trainable aggregation or deep models.

Paper explainersAll themesGraph & Geometric Learning

Graph neural networks (trainable models that learn how to combine information from a node's neighbors) are assumed to be necessary for graph problems. This paper shows that a much simpler approach works just as well: take each node, combine its neighbors' information using a fixed rule like averaging, and feed those numbers into a standard classifier. No learning the aggregation, no deep network. On most test problems, this simple tabular approach matches or beats leading graph neural networks.

Zero assumption version

Graph learning assumes deep trainable aggregation

A graph is a collection of nodes (points) connected by edges (lines). In node classification, you want to predict a label for each node based on its features and its position in the graph. For example, predicting whether a social network user likes a movie based on their own interests and what their friends like.

Graph neural networks (models that learn to combine information from neighbors) are the standard approach. A beginner might try: just take each node's features plus the raw features of its neighbors and feed them into a regular classifier (a model trained to predict labels from numbers). This often fails because the model must learn how to weight and combine neighbor information—a job that gets harder as neighborhoods grow larger or as the pattern of useful neighbor information changes.

The field has converged on graph neural networks: trainable models that learn a neighborhood aggregation (a way to combine neighbor information) as part of training. Researchers build deeper models, add attention (learned weighting of which neighbors matter most), and use specialized architectures. The assumption: this learning is necessary.

In one sentence. Fixed aggregation uses a single, fixed rule (e.g., averaging) to combine each node's neighbor information into features, then trains a standard classifier on those features.

The algorithm as a flow

What it actually does

Step 1: Collect features

For each node, gather its own features and its neighbors' features.

Step 2: Apply fixed aggregation

Combine all neighbors' features using one rule (e.g., average) applied identically to every node.

Step 3: Create tabular row

Concatenate the node's own features and the aggregated neighbor features into one row.

Step 4: Convert to tabular

Stack all node rows into a table. Each row is one node, each column is one feature.

Step 5: Train classifier

Train a standard classifier (multilayer perceptron or other tabular method) on this table to predict node labels.

What the paper changes

What the paper changes

The paper replaces trainable neighborhood aggregation (learned weights on how to combine neighbors) with a fixed aggregation rule (a single rule applied uniformly). Instead of learning how neighbors should be weighted, every node uses the same averaging (or summation) rule.

the object it moves  =  aggregation: fixed instead of learned
The hidden quantity

The expressiveness of fixed aggregation

measured quantity  =  aggregated feature dimensionality

The paper measures whether the features produced by fixed aggregation alone (the node's own features plus averaged neighbor features) contain enough information to predict labels as accurately as a graph neural network. This is the hidden quantity: how detailed and informative are the fixed aggregates? Do they capture the structure of the graph problem well enough?

The paper estimates this by testing on 14 benchmarks (standard datasets). If a simple classifier trained on fixed-aggregation features achieves high accuracy (close to or matching the best available graph neural networks), then the answer is yes—the fixed aggregates are sufficiently expressive for most graph learning tasks.

Why it works

Why fixed aggregation works

A node's neighbors carry real information about its label—that is the premise of all graph learning. A graph neural network learns a specific aggregation (how to combine that neighbor information) during training. But the paper shows that for most graph problems, a single fixed aggregation rule captures that information adequately.

Here is why: if a node's label depends on its neighbors in a consistent way—e.g., most friends like the movie, or neighbors tend to have similar features—then a simple summary like the average of neighbors' features preserves that signal. A classifier trained on the raw node features plus this average can learn to use the average to predict accurately. There is no need to learn a different aggregation per node or per layer.

The paper connects this to Kolmogorov–Arnold representations, a theory showing that many continuous functions can be computed by combining simpler functions in fixed, non-trainable ways. In this context, the node's label function often does not require learning which neighbors to weight more; averaging suffices because the underlying problem structure is not complex enough to demand it.

Math after the picture

Equation: aggregated features

First in words:

For each node, concatenate its own feature vector with the mean of its neighbors' feature vectors. Then feed this concatenated vector to a classifier trained to predict the node's label.

Then the compact form:

f_agg = concatenate(x_i, (1/d_i) * sum_j x_j) where j in N(i)

Every symbol:

f_aggthe aggregated features for the node (input to the classifier)
x_ithe node's own feature vector (a list of numbers describing it)
x_jthe neighbor's feature vector
N(i)the set of neighbors of node i
d_ithe number of neighbors (the node's degree)
(1/d_i) * sum_j x_jthe mean of all neighbors' features (average them)
concatenateput two vectors end-to-end to make a longer vector
A tiny worked example
Suppose node A has 3 features: [2, 5, 1]. It has 2 neighbors.
Neighbor 1 has features [3, 4, 2]. Neighbor 2 has features [1, 6, 0].
Mean of neighbors: ((3+1)/2, (4+6)/2, (2+0)/2) = (2, 5, 1).
Concatenated features for node A: [2, 5, 1, 2, 5, 1] (own + mean-neighbors).
The classifier receives [2, 5, 1, 2, 5, 1] and learns to predict A's label from these 6 numbers.

The core insight: the aggregated neighbor features, created once and fixed, provide enough signal for a trained classifier to match learned aggregation.

What can go wrong

What can go wrong

Unusually deep graph structures. On the Roman Empire and Minesweeper datasets, where nodes far apart in the graph matter, fixed single-hop aggregation misses multi-hop information. A node must know its neighbors and its neighbors' neighbors. Fixed aggregation, applied once, captures only one hop. Deep graph neural networks repeatedly aggregate, propagating information across multiple hops.
Complex neighbor patterns. If a node's label depends on learning different weights for different neighbors (neighbor A matters twice as much as neighbor B), fixed equal averaging cannot express that. A graph neural network learns these weights. If the problem structure is truly complex, fixed aggregation will fail.
Extreme class imbalance or outlier neighbors. If one neighbor is very unusual and dominates the average, the mean aggregation can be swamped. A learned aggregation might down-weight it. Fixed averaging treats all neighbors equally because it has no way to detect and adjust for outliers; learning would allow the model to discover which outliers to ignore.
Done right. Fixed aggregation excels when a node's label depends primarily on the features of its immediate neighbors, without needing to distinguish which neighbors matter more, and without needing information from distant parts of the graph.
What a runnable demo should prove

What a runnable demo should prove

Build a simple implementation: (1) load a small graph (e.g., Cora, a citation network with a few thousand nodes). (2) Extract each node's features and its neighbors' features. (3) Compute the mean of neighbors' features for each node. (4) Concatenate the node's own features with the mean-neighbor features. (5) Train a standard multilayer perceptron (just 2–3 layers, 64 neurons per layer) on the resulting table. (6) Evaluate accuracy on a held-out test set. (7) Compare to a leading graph neural network run on the same split. The demo proves that fixed aggregation + simple classifier matches deep graph neural networks, challenging the assumption that trainable aggregation is necessary.

accuracy = (number of correct predictions) / (total nodes in test set)

The key moment: when you see fixed aggregation + MLP achieve 85%+ accuracy on the same benchmark where a deep GNN achieves 87%, the myth that graph neural networks are necessary breaks.
