Agora: Multi-Agent Protocol Bug Detection

Agora finds deep bugs in consensus protocols by having multiple AI agents with different roles collaboratively explore possible attack scenarios, where a single agent alone would miss them.

Paper explainersAll themesAgents & Tool Use

Consensus protocols (the rules that keep distributed databases and blockchains from corrupting) are notoriously hard to verify. A single AI agent reading the code will miss the deepest bugs—the ones that only appear when many pieces of the system interact in unexpected ways across multiple stages. Agora gives each AI agent a specific role (some look for invariant violations, others synthesize attacks, others validate), so the agents can reason together about global safety properties that no single agent could catch.

Zero assumption version

Why a single agent fails to find protocol bugs

Consensus protocols are instructions that tell a network of computers how to agree on the same data (like the ledger in a blockchain). A bug in one of these protocols can cause different computers to end up with different versions of the truth, or money to disappear. The deepest bugs are not in single lines of code—they emerge from the interaction of many pieces over time, like a chain of decisions in an unexpected order.

A naive approach: hand a consensus protocol to an AI agent and say 'find bugs.' The agent reads the code, finds obvious inconsistencies, and stops. It misses the catastrophic bugs because those bugs only appear when you trace through a sequence of events that the agent never thought to combine. The agent reasons locally, function by function, not globally across the whole protocol.

Existing LLM-based code analysis tools find shallow bugs (a variable used before it is set, an off-by-one error). They do not discover the protocol-level logic bugs—bugs in the reasoning and ordering of the protocol itself. That requires exploring many possible sequences of events, inventing plausible attack scenarios, and checking whether those sequences violate the protocol's safety promises.

The method in one sentence. Agora assigns each AI agent a specific role (state explorer, attack synthesizer, validator) so the agents can collaborate to find deep protocol bugs by exploring state spaces together instead of reasoning alone.

The algorithm as a flow

What it actually does

Explorer agent

Systematically generates possible states (what each computer in the network could have seen at each moment).

Attacker agent

Invents sequences of events designed to break the protocol, using domain knowledge of consensus rules.

Validator agent

Checks each proposed sequence against the protocol's safety invariants (e.g., 'all servers agree').

Refinement loop

When a violation is found, the team iterates: attacker tightens the scenario, validator re-checks, explorer expands coverage.

Bug report

The sequence and the invariant violation are logged as a real protocol-level bug.

What the paper changes

The one thing Agora changes

Instead of a single AI agent analyzing code, Agora uses multiple agents with separate concerns. Each agent probes a different part of the problem: state discovery, attack imagination, and verification. The collaboration allows the team to surface deep protocol bugs because each agent's role creates a different perspective on the problem—one explores what is possible, one imagines what would break things, one rigorously checks—and together they explore the protocol's behavior far more thoroughly than any single perspective alone.

The hidden quantity

Protocol invariant violations

measured quantity  =  Undetected attack sequence

The hidden quantity is the set of all possible execution paths through the protocol that violate its safety promise. Most of these paths are never explored because they require a specific order of messages arriving at different times, a condition a single agent will not think to test.

Agora measures and tracks these paths by having the attacker agent synthesize scenarios and the validator agent confirm whether they are true violations. Each discovered path is a concrete sequence: a message arrives here, then a timeout happens, then a leader change occurs, then servers diverge. By the end, Agora has found attack sequences that previous LLM agents never imagined.

Why it works

Why multi-agent collaboration finds deep bugs

A single AI agent reading consensus code is like a person reading a recipe once and being asked whether the dish can be ruined. The person would spot obvious mistakes (like using salt instead of sugar). But they would miss subtle disasters that only happen if the steps are done in a very specific wrong order, or if someone changes an ingredient halfway through.

Agora solves this by giving each agent a specific role. The explorer agent is curious about all possible states—what information could each server possibly have? The attacker agent is adversarial—it asks 'how would I break this?' and invents sequences designed to trick the system. The validator agent is skeptical—it checks whether each invented sequence actually violates a safety rule. No agent alone can answer the question, but the three together can.

The deep insight: finding a protocol bug requires two distinct tasks that a single agent conflates. Task 1: imagination (what sequences are even possible?). Task 2: verification (do those sequences violate the rules?). When one agent does both, it tends to verify only the sequences it naturally imagines—a conservative set. When they are split, the attacker can be truly creative (find weird sequences), and the validator can be thorough (check them rigorously). Together, they explore the space far more completely.

The verification formula

First in words:

For each state transition in an attack sequence, check whether the resulting state violates any safety invariant. A bug is confirmed if the invariant check returns false.

Then the compact form:

bug_found = exists sequence S such that SafetyInvariant(final_state(S)) = false

Every symbol:

San execution sequence (ordered list of messages and timeouts)
final_state(S)the state of all servers after sequence S completes
SafetyInvariantthe protocol's promise (e.g., all servers agree on committed data)
bug_foundtrue if any sequence violates the invariant
A tiny worked example
Sequence: Server A receives vote from B, timeout expires, A becomes leader, A accepts write without checking B.
Final state: Server A has write, Server B has not seen it.
Invariant check: SafetyInvariant (all servers agree) = false.
Conclusion: Bug found. The timeout-then-write sequence breaks agreement.

The formula simply checks: does the sequence end in a state where the protocol is broken?

What can go wrong

What can go wrong

Agents get stuck in a local loop. If the attacker keeps inventing the same type of sequence and the validator keeps checking it, the team does not expand into new territory. The refinement loop can become repetitive instead of exploratory.
The domain constraints are too loose. If the attacker agent does not understand the protocol's rules well (what messages are actually allowed at each step), it will waste time on impossible sequences. Poor domain knowledge wastes exploration budget.
The invariant is stated ambiguously. If the protocol's safety promise is vague (e.g., 'servers should mostly agree'), the validator cannot reliably confirm a violation. Clear, formal invariants are essential.
Done right. Clear protocol specifications, diverse attack strategies, and rigorous invariant checking produce genuine bug discovery. Each agent stays focused on its role: explore, attack, validate.
What a runnable demo should prove

What a runnable demo should prove

Build a tiny consensus protocol (e.g., Raft with just 3 servers, simplified message handling). Implement the Agora agents: one that enumerates possible orderings of 5-10 messages, one that invents adversarial timing (e.g., delays and timeouts), and one that checks whether the final state violates the invariant 'all servers have the same log.' Run the multi-agent system for a fixed number of iterations and count how many bugs are found. Then run a baseline single-agent version (one LLM agent reading the code) and count its bugs. The demo makes it concrete that multi-agent collaboration discovers bugs single agents cannot, because the attacker agent imagines scenarios the baseline agent never thinks to check, and the validator rigorously confirms violations rather than relying on the single agent's conservative reasoning.

bugs_agora - bugs_single_agent = protocol-level bugs revealed by collaboration

The gap (preferably 5+ bugs found by Agora that the single agent missed) proves that role separation and iterative refinement enable deeper exploration of protocol state spaces, because specialized agents can focus on their individual tasks (exploring, attacking, validating) and combine efforts in ways a generalist agent cannot.
