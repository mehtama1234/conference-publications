ASRU: Safe Refusal Without Collapse

Teach a multimodal model to refuse sensitive knowledge by steering its internal brain state, then sharpen the refusal boundary with reward-based nudging.

Paper explainersAll themesAlignment, Safety & Fairness

Multimodal models (like Qwen-VL, which answers questions about images) remember sensitive information during training. Removing that knowledge is hard: crude unlearning breaks the model's personality, making it stiff and incoherent. ASRU does it cleanly by first pointing the model's internals toward refusal (using activation steering—a kind of internal compass), then using reward-based training to draw precise lines about what to forget versus what to keep.

Zero assumption version

Unlearning breaks the model

A multimodal model (a program that reads images and text) has absorbed sensitive information during training—private data, copyrighted material, harmful images. The company wants to remove it because if the model can repeat that sensitive content, it becomes a liability: users could extract private information, the company faces legal risk, and trust erodes. Refusal—making the model decline to answer about that knowledge—removes the attack surface.

A beginner tries the obvious thing: feed the model the sensitive examples and push it toward saying 'I refuse' (by making refusal cheaper and the sensitive output more expensive). This works initially—the model learns to refuse. But it overshoots. The refusal gets baked into everything: the model refuses even innocent requests, or produces incoherent babble and repetition. It has lost its ability to have a normal conversation.

The core problem: crude refusal is all-or-nothing. The existing methods cannot separate 'refuse the specific sensitive thing' from 'maintain general conversational ability.' They burn down the whole house to remove one room.

The move: Start by steering the model's internal state (its activations, the numbers flowing inside) toward a refusal direction, so it sits close to 'refuse' by default. Then use reward-based training to draw fine-grained lines: refuse this but answer that.

The algorithm as a flow

What it actually does

Compute the steering direction

Measure the average internal state when shown sensitive data (the forget set). Measure it again on chosen safe examples (the refusal reference set). The difference is the steering direction—the compass pointing toward refusal.

Steer the model's internals

Update a single projection matrix in one chosen layer so that internal activations (the flowing numbers) drift toward that refusal direction. Use this internal signal instead of predicting wrong outputs directly—subtle, surgical pressure from inside.

Set up the reward signal

Define rewards: give positive reward when the model refuses sensitive examples and negative reward when it starts to leak them. Give positive reward when it answers safe questions normally. The rewards train the model to navigate between these conflicting demands.

Refine with reward-based learning

Use a technique called GRPO (group relative policy optimization, a variation on reinforcement learning). Sample many outputs and score each one: do outputs that refuse the sensitive examples while answering safe questions get high reward? Raise the probability of those high-scoring outputs. Over many iterations, the model learns which refusal-answering balance earns reward.

Test the refusal boundary

Check: does it actually refuse the sensitive knowledge? Does it still answer normal questions? Is the generated text coherent and diverse, or robotic and repetitive? Tune the boundary dataset and reward weights if needed.

What the paper changes

The thing being changed

The paper changes a single matrix inside one layer of the model. This matrix projects internal activations (the flowing numbers as the model thinks) from one space to another. Normally this matrix helps the model compute the next response. By steering it, the authors make refusal the default direction—activations naturally drift that way.

the object it moves  =  internal projection matrix
The hidden quantity

The hidden quantity: refusal boundary sharpness

measured quantity  =  forget-retain boundary clarity

The paper measures a hidden quantity: how cleanly can the model separate sensitive knowledge (should be refused) from safe knowledge (should be answered). This is not visible in the outputs directly—you cannot just count 'did it refuse?'—but it lives in the internal decision-making process.

The paper estimates this by testing both: (1) Does it refuse the sensitive examples? (2) Does it still answer safe, normal questions? And critically, does it do both while generating coherent, diverse text—or is it rigid and repetitive? A sharp boundary means it knows exactly when to refuse and when to answer. A blurry boundary means it either leaks sensitive knowledge or collapses into babble.

Why it works

Why it works: the two-stage dance

The mechanism has two stages. Stage 1 (activation steering) is the initialization: the authors compute the average internal state of the model when it sees sensitive examples, and the average when it sees the chosen refusal response. The difference is a direction—call it the refusal direction. They then update one projection matrix (one of the many linear transformations inside the model) to push activations (the flowing numbers) toward that direction. This is like shifting the playing field: now the model's internals are naturally biased toward refusing. Not by making wrong outputs—just by tilting the internal computation itself.

Why does this help? Because Stage 2 (reward-based boundary refinement) now starts from a better place. The model's training made it fluent and helpful, so it wants to answer most questions—that is why it leaks sensitive knowledge, it cannot tell when to hold back. If you only use reward-based training to force refusal, the model fights itself: its core instinct says 'answer,' but the reward says 'refuse'—so it produces incoherent babble, trying both at once. By steering the internal state first, the model's default is already set to refusal; now the reward signal only needs to draw fine lines: refuse this specific example, answer that specific safe question. The model is not fighting its core instinct; it is learning to direct a refusal baseline precisely. The steering has already built refusal into the internal foundation.

This two-stage separation is critical. If you tried to do it all at once with pure reward-based training, the model would either refuse everything or leak everything, because the reward signal alone cannot specify 'refuse exactly this sensitive pattern but answer exactly that safe pattern' clearly enough. By steering first, you create a default baseline of refusal, and then the rewards only need to sharpen the edges. The model stays coherent because you are not asking it to change its entire personality—just to position itself in a slightly different emotional stance and then selectively answer.

Math after the picture

The steering equation

First in words:

Compute the mean activation vector (the average of all flowing numbers at one layer) on the forget set and on the target refusal set. The steering direction is their difference. Update a projection matrix in that direction proportionally to a steering strength parameter.

Then the compact form:

v_L* = mean(a_target_L*) - mean(a_forget_L*); W_proj_new = W_proj + lambda * (v_L* outer_product v_L*) / ||v_L*||

Every symbol:

v_L*the steering direction (difference in average activations at layer L*)
a_target_L*internal numbers at layer L* when the model processes safe refusal examples
a_forget_L*internal numbers at layer L* when the model processes sensitive examples to forget
W_projthe projection matrix being adjusted (inside one layer)
lambdasteering strength (how hard to push; paper uses 0.2 to 3)
outer_productmultiply the vector by itself, creating a full matrix
||v_L*||length of the steering direction vector (for normalization)
A tiny worked example
Forget-set mean activations at layer 12: [1.2, 0.8, -0.5, 1.1]
Target-refusal mean activations at layer 12: [3.0, 2.4, 0.5, 2.8]
Steering direction v = [3.0-1.2, 2.4-0.8, 0.5-(-0.5), 2.8-1.1] = [1.8, 1.6, 1.0, 1.7]
Length of v: sqrt(1.8^2 + 1.6^2 + 1.0^2 + 1.7^2) = sqrt(9.49) ≈ 3.08
Normalized: [0.584, 0.519, 0.325, 0.552]
Update the projection matrix by adding (lambda=0.5) * (0.584^2 to each entry weighting by v direction)
Result: internal activations drift away from the forget set toward safe refusal; downstream layers see this shift and learn to refuse

The projection matrix update is not a full retraining—it is a surgical change to one layer. This preserves most of the model's learned behavior while tilting the internal compass toward refusal.

What can go wrong

What can go wrong

Steering in the wrong direction. If the average activations for the refusal set and forget set are too similar, the steering direction is weak or noisy. The model's internals do not tilt clearly toward refusal. Fix: ensure the refusal-reference examples are semantically distinct from the sensitive examples.
Projection matrix is not the right lever. If you steer the wrong layer or the wrong matrix, you may miss the semantic information (it lives in a different part of the network). The model continues to leak knowledge because the steering does not touch the pathways that encode the sensitive data.
Reward signal is vague or contradictory. If the rewards for refusing sensitive examples overlap with rewards for safe answers, the boundary optimization gets confused. The model learns a murky compromise instead of a sharp line. Fix: carefully curate the forget set, retain set, and boundary test set so rewards do not conflict.
Over-steering creates a different collapse. If lambda (steering strength) is too high, the model's internal state becomes locked into refusal, and reward-based refinement cannot overcome it. Now it refuses everything. The paper uses layer-specific lambda values (0.2 to 3) to balance this.
Done right. Choose layer L* based on where sensitive information is represented (often mid-to-late layers). Use activation steering as initialization only, then let GRPO refine. Ensure the retain set is large and diverse: if you only show the model a few safe examples, it memorizes exactly those and still leaks on slightly different inputs (because it learned 'refuse only this exact image,' not 'refuse this category'). A large, diverse retain set forces the model to learn the general principle: 'refuse this class of sensitive knowledge, answer other classes.' Test on both forget examples and realistic safe queries.
What a runnable demo should prove

What a runnable demo should prove

Build a small multimodal model (or a smaller version of a real one, fine-tuned on a subset). Train it on a set of image-caption pairs, including a few marked as 'sensitive' (e.g. images with specific people or symbols). Run the original model on a query like 'Describe this image' and verify it leaks the sensitive information (outputs details it should not know). Then apply ASRU: compute activation steering, update the projection matrix, and run GRPO on a reward function that penalizes outputting the sensitive details and rewards coherent, helpful responses on normal image questions. Re-test: the unlearned model should refuse or avoid the sensitive information, yet still answer normal questions fluently.

Unlearning success = (1 - leak_rate_after / leak_rate_before); Quality preservation = coherence_score_after / coherence_score_before; Combined = Unlearning_success * 0.5 + Quality_preservation * 0.5

The demo must show that you can forget sensitive knowledge AND maintain fluent, helpful behavior at the same time. The trade-off is no longer a forced choice.
