Discrete vs continuous representations

This page asks the next question after granularity: should the model cut the world into separate pieces, or should it represent the thing as a smooth space, path, or function?

Core idea

Some facts have edges. Some facts flow.

Discrete representations are good when boundaries matter. Continuous representations are good when smooth change matters.

A word token is discrete: it is this symbol, not that one. A code keyword is discrete: return and retun are not almost the same program token. A class label is discrete: dog and car should not blur into one label. These are cases where the model benefits from separate pieces.

Motion is different. A robot arm does not naturally jump from one waypoint to the next. A patient state changes over time. A camera view rotates smoothly around an object. A pose changes by degrees. A probability can move from low to high without crossing a hard symbolic boundary. These are cases where the model needs a path, a curve, a field, or a continuous latent space.

discrete question: which bucket, token, code, symbol, or choice is this? continuous question: where is this on the path, surface, field, trajectory, or scale?

The mistake is assuming one form is always better. Discrete units are powerful because they make boundaries explicit. Continuous spaces are powerful because they preserve gradual change. The right representation depends on what the task must not lose.

Where discrete works

Use chunks when the boundary is the meaning

Discrete representations help when the model must choose among separate symbols, codes, actions, or states. Language tokenization is the obvious case: the model predicts one next token from a vocabulary. Vocabulary reduction asks whether a token can be removed without changing the behavior of that next-token system.

Discrete communication uses binary messages. Vector quantization uses codebook entries. Table models can turn numeric values into bins. Action-token policies can rank possible moves. Sparse embeddings are partly discrete too: most dimensions are off, and a few dimensions are active.

Language

Words, subwords, characters, code tokens, names, math symbols.

Codes

Binary messages, VQ codebooks, graph tokens, sparse active dimensions.

Choices

Action tokens, class labels, bins, retrieval features, tool choices.

Discrete is useful because it forces decisions. It gives the model a finite set of things it can say. That can make storage cheaper, search faster, and behavior easier to inspect. But the decision has to match reality. If a smooth value is chopped too roughly, the model inherits the chop.

Where continuous works

Use smooth spaces when the fact changes gradually

Continuous representations help when nearby values should produce nearby behavior. Robot motion is the clearest case. If a hand moves from position 10 to position 11, there are many valid positions in between. The controller may need velocity, acceleration, and smoothness. A list of discrete waypoints can approximate this, but it can also introduce jumps.

Time series have the same problem. Real events may happen at irregular times. Forcing them onto a fixed grid can add fake observations or erase timing. Continuous-time latent models try to represent the hidden state as something that can be queried between observed points.

Geometry and topology also point here. Camera views, poses, behaviors, and patient trajectories often form paths, loops, branches, or surfaces. A continuous representation lets the model move through those shapes without treating every small change as a separate symbol.

continuous representation: state(t) can be queried at many times motion can have velocity and acceleration pose can move smoothly uncertainty can rise or fall gradually viewpoint can travel around a loop
Bad discretization

Chopping smooth things creates jagged behavior

Discretization turns a smooth thing into steps. Sometimes that is fine. Sometimes it is the bug. A robot action represented as a few waypoints may look acceptable in a dataset but become jerky during execution. The model cannot naturally ask what happens halfway between two waypoints unless the representation supports that.

In time-series work, fixed time bins can distort irregular events. If two patients have measurements at different intervals, placing them on the same grid may invent sameness that was never there. In vision, a coarse visual token can hide a small letter or object boundary. In language, a bad token split can make an exact name or code identifier fragile.

Quantization error.

The real value lies between two allowed symbols, so the model must round it.

Lost derivative.

The model can produce positions but not a clean velocity or acceleration.

Timing damage.

Events get pushed onto a grid that hides when they really happened.

Boundary damage.

A patch, token, or bin boundary cuts through the thing the task needed whole.

The practical test is simple: if a small change in the real world should cause a small change in the output, a rough discrete representation may be the wrong tool.

Bad continuity

Making everything smooth can blur exact facts

Continuous representations have their own failure. Some things should not blur. A drug name is not approximately another drug name. A code keyword either parses or it does not. A citation, patient id, math symbol, or variable name may need exact copying. A class boundary may need to stay sharp.

If every symbol becomes a point in a smooth space, nearby points can become dangerously tempting. That is useful for semantic similarity, but risky for exact identity. A retrieval model can say two concepts are near each other. A copier must still copy the exact string. A code model can know that two identifiers are similar in meaning, but it must not silently substitute one for the other.

So the rule is not "continuous is deeper." The rule is: continuous where the world flows, discrete where the boundary carries the meaning.

Hybrid designs

Many strong systems use both

The best design often combines discrete and continuous parts. Language models use discrete tokens but continuous embeddings. A robot policy may read discrete language instructions but output continuous motion. A graph model may quantize nodes into codebook entries while keeping continuous features for similarity. A video model may cut input into frames but learn a smooth path through behavior states.

This is not a contradiction. Discrete pieces give the model named handles. Continuous spaces let those handles move, mix, and vary. The hard part is deciding which boundary must stay sharp and which dimension should remain smooth.

The design question becomes precise: where should the system snap to a symbol, and where should it keep a smooth value?

How people build them

They choose the form, then train the model to respect that form

For discrete representations, people build a vocabulary, codebook, bin set, sparse feature set, or action-token set. Then they add pressure so the symbols get used well: avoid dead codewords, keep useful tokens, make different meanings use different codes, and test exact behavior.

For continuous representations, people build a space or function. They may use neural fields, continuous-time latent dynamics, position embeddings, diffusion latents, ODE-like updates, or smooth trajectory models. Then they add pressure for smoothness, consistency, and correct interpolation: nearby states should behave nearby, and querying between observations should make sense.

Discrete buildChoose symbols, codes, bins, tokens, or active dimensions; train them to be used without collapse.
Continuous buildChoose a latent space, trajectory, field, or function; train it to move smoothly and predict between points.
Hybrid buildUse symbols where exact choices matter and continuous spaces where the state should vary gradually.
Final testCheck task behavior: exact copy, retrieval, OCR, forecasting, smooth control, transfer, or reasoning.
Paper map

How papers under the theme fit this question

Neural Implicit Action FieldsDiscrete waypoints are replaced with continuous action functions. Principle: robot motion should be smooth enough to support velocity, acceleration, and compliant control.
Coupled Continuous-Time Latent DynamicsIrregular event sequences are modeled in continuous time. Principle: state can evolve between observations, so the model should not be trapped on a fixed grid.
Query-Based Irregular Time Series EmbeddingIrregular observations are aggregated into useful latent representations without forcing fake regular samples. Principle: keep timing information instead of flattening it into uniform bins.
PoPE / position representation papersPosition and content are separated so sequence models can reason about where something is without confusing it with what it is. Principle: location is a smooth or ordered factor, not only token identity.
BEASTAnimal video is represented as appearance plus motion. Principle: frames are discrete inputs, but behavior is a path through state space.
Topology-aware contrastive learningPairwise discrete comparisons are constrained by continuous/global shape. Principle: local choices should not tear paths, loops, and bridges.
Lossless Vocabulary ReductionDiscrete tokens are reduced only when behavior survives. Principle: exact language symbols still need sharp boundaries.
CSRv2 and discrete communicationContinuous dense representations are forced through sparse or binary bottlenecks. Principle: compression can help, but the surviving discrete signals must still carry task meaning.
Failure cases

What goes wrong?

Smooth motion is chopped too hard.

Robot control becomes jagged, timing gets distorted, or valid in-between states become unreachable.

Exact symbols are blurred.

Names, code, math, medicine, and citations become approximate when the task needed exact identity.

Continuous spaces drift.

The model can interpolate smoothly but through states that are not physically, medically, or semantically valid.

Discrete codebooks collapse.

The model has symbols but uses only a few, so the representation is discrete in form but weak in practice.

The wrong layer is discrete.

The system snaps too early, before it has enough context to know which boundary matters.

The wrong layer is continuous.

The system stays smooth too long and cannot make the sharp decision the output requires.

Takeaway

The first-principles line

Discrete units are good when boundaries matter. Continuous representations are good when smooth change matters.
