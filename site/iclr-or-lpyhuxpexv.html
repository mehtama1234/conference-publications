Jacobian Aligned Random Forests

Use one global supervised rotation before training a forest, so simple axis-aligned splits can follow feature interactions that would otherwise require many awkward tree cuts.

Paper explainersAll themesOther

Ordinary decision trees split one feature at a time. That is fast and stable, but it becomes wasteful when the real decision boundary depends on a combination of features rather than on any single coordinate. In those cases, an axis-aligned tree needs many small rectangular partitions to approximate one slanted or interaction-driven boundary. Oblique trees address this by learning a fresh linear combination at many nodes, but that adds optimization cost and extra instability. This paper asks whether one carefully chosen global transformation is enough. JARF first fits a standard forest, then estimates how the output changes when each input feature is perturbed. From those change directions it builds one shared rotation and scaling map. A second forest trained in that transformed space can now use ordinary one-feature thresholds more directly because the important joint directions have already been lined up with the coordinate axes.

Zero assumption version

Why axis-aligned trees waste splits on rotated structure

A tree threshold on one feature works well when the target changes mostly along that one coordinate. It works poorly when the target changes along a slanted direction such as a weighted sum of several features.

In that slanted setting, the tree must stack many single-feature splits to approximate one important boundary. That increases depth and can fragment the data into many small leaves. Oblique trees fix the coordinate mismatch by learning a different hyperplane at each node, but the added optimization makes them slower and more complex. The paper looks for a middle ground: keep simple trees, but rotate the input space once using supervision from the target.

The paper's move. Estimate which input directions change the prediction most, then rotate the whole feature space once so plain threshold splits align with those directions.

The algorithm as a flow

What it actually does

Fit a baseline forest.

Train a standard random forest first, because it provides supervised predictions from which directional sensitivity can be estimated.

Perturb each feature and measure output change.

Use finite differences, which means small input nudges, to estimate how much the prediction changes along each coordinate.

Aggregate those directional changes.

Form an expected Jacobian outer product, meaning an average square table built from prediction-change directions, because this summarizes which combined feature directions matter globally.

Compute a shared linear transformation.

Rotate and rescale the input space using that square table, because the strongest supervised directions should become easier for axis-aligned splits to isolate.

Train a second forest in transformed coordinates.

Reuse ordinary axis-aligned splits in the new space, because the hard interaction structure was handled by the preprocessing step.

What the paper changes

What the paper changes

The paper changes where oblique structure is handled. Instead of learning a new slanted split at every node, it learns one global supervised preconditioner before building the final forest.

The hidden quantity

The hidden quantity

measured quantity  =  the global table of important prediction-change directions

The decisive object is the average outer product of prediction-change directions. Each local change direction says how the output would move if one input moved slightly. Averaging their outer products builds a square table that highlights directions in feature space where supervised change is consistently strong.

That square table matters because it captures interactions without learning a separate split formula at each node. If a diagonal direction repeatedly changes the prediction, the transformation can turn that diagonal into a coordinate axis. After that, a one-feature threshold is no longer a poor approximation of the true boundary.

Why it works

Why one global rotation can be enough

A forest does not need the original coordinates specifically. It only needs coordinates in which simple thresholds separate useful regions. If most of the supervised signal lies along a few combined directions, then a global transformation can expose those directions before any tree is built.

The first forest supplies the directional information. By checking how predictions move under small coordinate perturbations, JARF estimates which combinations of features the target is most sensitive to. Averaging those local sensitivities stabilizes the estimate, because one noisy sample does not control the whole transformation.

The second forest benefits because the transformed coordinates already encode interaction structure. That means a shallow axis-aligned split can represent what would have required several layered thresholds before. Training stays simpler than in oblique forests because the trees themselves still optimize only one-feature cuts.

Shared direction table

First in words:

Average the outer product of the prediction-change direction at many points. Large directions in that average matrix mark combined feature directions that repeatedly affect the output.

Then the compact form:

A tiny worked example
Suppose the target changes most when feature 1 rises while feature 2 also rises.
At many data points, the prediction-change direction therefore points roughly along the same combined direction.
Averaging the outer products keeps that shared direction prominent and suppresses isolated noisy directions.
The transformation then rotates that shared direction toward one axis.
After rotation, a tree can separate the classes with a short threshold chain instead of many rectangular patches.

The forest remains axis-aligned after transformation; the oblique behavior is moved into the preprocessing step.

What can go wrong

What can go wrong

One global transformation cannot match every local pattern. If different regions of the data need very different boundary orientations, a single shared rotation may still leave some regions misaligned because the best direction varies across the space.
The first forest can estimate the wrong directions. If the baseline forest is too weak or too noisy, the prediction-change directions will be unreliable, which means the transformation can emphasize the wrong feature combinations.
Finite-difference estimates can be unstable on rough outputs. When small perturbations cause irregular prediction changes, the sensitivity estimate becomes noisy, so the shared direction table may need enough averaging to remain useful.
Done right. When the data share a clear global orientation, JARF works well because one supervised rotation removes much of the coordinate burden from the final forest.
What a runnable demo should prove

What a runnable demo should prove

Create tabular classification tasks where the boundary depends on a slanted combination of two or three features. Compare an ordinary random forest, an oblique-forest baseline, and JARF.

The demo should report accuracy, average tree depth, and training time. A convincing result shows JARF approaching the oblique baseline with less training cost because the global rotation turns the important interaction directions into coordinates that ordinary splits can use directly.
