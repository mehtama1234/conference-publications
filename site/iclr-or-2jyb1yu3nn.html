Circuit Insights: Interpretability Beyond Activations

Instead of inspecting what neurons do when you feed them data, read what they were trained to do directly from their weight values, and trace how features flow between layers.

Paper explainersAll themesInterpretability

Understanding how a neural network actually thinks is hard: most methods inspect activations (which neurons fire on real inputs), but this misses feature interactions and requires external language models to label each neuron. This paper proposes two new methods: WeightLens reads features directly from the trained weight values of a neuron, skipping the need for an explainer model; CircuitLens traces how feature activations arise from interactions between different network components, revealing patterns that activation-only analysis cannot find.

Zero assumption version

Why inspecting neurons is stuck

A neuron is a little computation unit inside a neural network. Today, to understand what a neuron has learned, researchers either manually inspect it (only works on toy problems) or run lots of data through it and watch which inputs make it fire strongly, then ask a language model to describe what it is doing. But this approach has two problems: First, it depends entirely on having the right dataset and the right language model, and smaller datasets produce worse descriptions. Second, it completely ignores interactions—when multiple neurons fire together, they create patterns and circuits that you cannot see by looking at individual neurons in isolation.

A beginner might naively think: just collect all the inputs that make a neuron fire and look at them. But this is slow, requires curating datasets, and worst of all, it misses the entire story of how neurons feed into each other to perform the actual computation.

The core problem. Activation-only interpretation is slow, dataset-dependent, and blind to how features interact across layers.

The algorithm as a flow

What it actually does

Prepare features

Identify all the monosemantic features in a layer (using transcoders, which cleanly separate what comes from weights versus what comes from the input data).

WeightLens: read directly

For each feature, compute a scoring vector from its learned weights; this score identifies which earlier-layer features contribute most to its activation.

Find important positions

Mask the input, keeping only positions (tokens, which are single words or word pieces) that either directly activate the feature or contribute measurably through learned pathways.

CircuitLens: trace interactions

Group inputs by which upstream elements (word positions, features, learned head pathways) they activate, forming clusters that reveal the feature's circuit.

Describe and validate

For each cluster, generate a natural-language description; compare against activation-only methods on new data, because methods that rely on weights alone are data-independent while activation methods need large datasets, so weight-based wins when data is scarce.

What the paper changes

What the paper moves

The paper changes where interpretability information comes from: instead of relying only on what a neuron outputs when you feed it data (its activation), it also directly reads the learned weight values inside the neuron, and it traces how features influence each other across layers by following transcoders (a sparse model of each layer that separates input-dependent from weight-dependent parts).

the object it moves  =  feature interpretation source
The hidden quantity

The hidden quantity: contribution strength

measured quantity  =  how much each upstream feature contributes to a downstream feature

When a neuron activates, it does so because certain upstream neurons or tokens fired. The contribution strength is a number that measures how much each upstream element mattered for triggering the downstream neuron. High contribution means that upstream element is a reliable activator; low means it is noise or context-dependent.

WeightLens estimates contribution strength directly from the weight values (the learned numbers that the network adjusted during training) by computing a scoring vector from each feature's encoder weights and measuring overlap with upstream features. CircuitLens estimates it by tracing learned pathways and masking to see which word positions and head pathways are actually necessary for each activation. Together, these two approaches give independent measurements that can validate each other.

Why it works

Why it works: the weight-based principle

When a network trains, each weight learns to respond to patterns in the data. If a downstream feature's weight has a large value connected to an upstream feature, that weight was reinforced by training precisely because that upstream pattern was useful for triggering the downstream computation. By reading the magnitude of these connections directly, you skip the need to run data through the network and watch what activates—you are reading the learned signal directly from the training outcome.

For circuits (interactions across layers), transcoders decompose each layer into two separate parts: one part depends only on the learned weights (input-invariant), and one part depends on what flows in from upstream (input-dependent). This separation makes it possible to trace a feature's activation back through learned head pathways and word-position contributions, revealing which specific earlier computations in the network are necessary for this feature to activate. Why this matters: activation-only methods cannot see these paths because they only measure the final output, not the intermediate steps.

Math after the picture

How contribution strength is scored

First in words:

contribution_score_i = decoder_weight_i * upstream_feature_activation_i, summed over all upstream features; features with z_score > 3 are marked as strong contributors

Then the compact form:

score(f_i) = W_dec · f_upstream, where z = (score_i - mean(scores)) / std(scores), select i if z > 3

Every symbol:

f_iactivation of upstream feature i
W_decdecoder weight matrix (learned during training)
score(f_i)contribution strength of feature i
zstandardized score (z-score)
3z-score threshold: 3 standard deviations = strong outlier
A tiny worked example
Suppose upstream features have activations: f_1=8.0, f_2=2.0, f_3=6.0.
Decoder weights from these features are: W_1=0.9, W_2=0.1, W_3=0.8.
Raw scores: 8.0*0.9 = 7.2, 2.0*0.1 = 0.2, 6.0*0.8 = 4.8.
Mean of scores: (7.2 + 0.2 + 4.8) / 3 = 4.07. Std dev: 3.2.
Z-scores: (7.2-4.07)/3.2 = 0.98 (weak), (0.2-4.07)/3.2 = -1.21 (weak), (4.8-4.07)/3.2 = 0.23 (weak).
None exceed z=3, so all are context-dependent. But if f_1=20 instead: score=18.0, z=(18.0-8.6)/4.8=1.96 still weak... with f_1=30: score=27, z=(27-9.5)/5.2=3.4, now feature 1 is marked strong.

Higher decoder weight times higher upstream activation creates strong contributions; z-score threshold filters noise and context-dependent signals, leaving only reliable circuit elements.

What can go wrong

What can go wrong

Context-dependent features break weight-based reading. If a feature's activation depends entirely on what comes in from upstream (no stable pattern learned in the weights), WeightLens has nothing to read. The paper includes a validation step to detect this, reporting 'no stable token-level description,' which is honest but unhelpful.
Transcoders are not perfect. CircuitLens relies on transcoders to separate weight-dependent from input-dependent parts. But transcoders themselves are approximations of the real MLP layer—they can diverge from the original weights, especially in early layers where activation patterns are chaotic.
Early layers have too many interactions. Layer 0 of Gemma-2 shows almost no circuit structure—mostly token-level noise, averaging only 1.05 clusters per feature. In early layers, features are not yet organized, so tracing circuits finds little.
Done right. Combine WeightLens on weight-stable features with CircuitLens on features that show clear circuit structure; validate consistency between the two methods; accept that early layers and context-dependent features simply do not have interpretable weight signatures.
What a runnable demo should prove

What a runnable demo should prove

Build a small interpretability benchmark: (1) extract 50 features from a single layer of a small language model (Gemma-2-2B or smaller). (2) For each feature, run WeightLens to score upstream contributors and CircuitLens to find attention-based circuits on a held-out validation set (10 examples per feature). (3) For each feature, generate a natural-language description using both methods independently. (4) Have a human rater score the descriptions for clarity and accuracy, blind to which method produced each. (5) Measure consistency: compare the descriptions from WeightLens alone, CircuitLens alone, and the combination.

consistency = fraction of feature descriptions where WeightLens and CircuitLens agree on the top 3 contributing upstream elements

The demo succeeds if combined descriptions are clearer and more stable across dataset sizes than activation-only methods, and if WeightLens alone (no dataset needed) is nearly as good as CircuitLens (which uses data).
