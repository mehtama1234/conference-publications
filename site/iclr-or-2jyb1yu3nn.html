Circuit Insights: Beyond Activations

Understand neural network circuits by reading both feature weights and how they interact, rather than just watching feature activations fire.

Paper explainersAll themesInterpretability

Neural networks are black boxes. Mechanistic interpretability is the attempt to peer inside and see what each part is really doing. Most existing methods watch feature activations (which turn on or off), but this tells only half the story: it misses how features work together in circuits. This paper proposes two new methods, WeightLens and CircuitLens, that go further: one reads the learned weights directly, and the other captures feature interactions. Together they let us understand circuits at scale without needing external AI models or careful dataset collection.

Zero assumption version

Why just watching activations is not enough

Today, interpretability researchers try to understand neural networks by watching which features activate (turn on or off) on different inputs. But a feature activating is just the output; it does not tell us why it activated or how it connects to other features. Imagine watching a traffic light turn red without understanding the sensor that triggered it or the brake lights downstream.

Existing methods also rely on external AI models to explain what they see, or they need hand-selected datasets. Both approaches require a lot of human work and do not scale. And most importantly, they miss interactions: how features talk to each other inside the circuit. A single activation number hides the entire conversation.

In one sentence. WeightLens reads feature meanings directly from the weights, and CircuitLens watches how feature activations actually arise from feature interactions.

What the paper changes

What the paper changes

The paper shifts focus from activation values (the output of a feature) to two hidden layers below: the weights themselves (which encode the feature's learned meaning) and the causal pathways (which show how one feature's activation flows into another).

the object it moves  =  weights and activation pathways
The hidden quantity

The hidden quantity: feature interaction strength

measured quantity  =  interaction strength between features

The central insight is that features do not work alone. Each feature's activation depends on what other features fire before it. The paper calls this the feature interaction strength: how much does Feature B's firing depend on Feature A's firing? Most interpretability work ignores this. It measures only Feature B's activation value, not the reason it activated.

CircuitLens estimates this by running inputs through the network, observing which upstream features activate, then measuring how much the upstream firing patterns correlate with the downstream activation. A strong correlation means a real causal pathway.

Why it works

Why both methods work together

WeightLens works because the learned weights act like a codebook. When a neural network learns, it stores information in the weight matrices. A feature's role in the network is encoded in the columns of those weights. By reading those weights directly—without running any inputs through the network—you can decode what the feature is tuned to. This is fast and needs no external model or dataset.

CircuitLens works because activations are not magical; they flow predictably through layers. If you observe which upstream features fire on a given input, and you observe that a downstream feature also fires on that same input, you can measure the strength of the connection. Transcoders are neural networks trained to reconstruct feature activations from the hidden states; they separate what a feature does because of the input from what it does no matter what the input is, which lets CircuitLens isolate the true causal pathways without noise. Together, the weight meanings and activation pathways give you the full circuit: both what each feature does and why it fires.

Math after the picture

Measuring interaction strength

First in words:

interaction strength = correlation between upstream feature activation and downstream feature activation, weighted by how much the downstream feature depends on that upstream pattern

Then the compact form:

S(F_i -> F_j) = corr(a_i, a_j) * attribution(F_i to F_j)

Every symbol:

S(F_i -> F_j)strength of causal link from feature i to feature j
corr(a_i, a_j)how often upstream i fires when downstream j fires
a_iactivation level of feature i
a_jactivation level of feature j
attribution(F_i to F_j)how much of j's activation came from i versus other sources
A tiny worked example
Input causes Feature A to activate at level 8.0.
That same input causes Feature C to activate at level 6.5.
When we run 100 inputs, A and C activate together 74 times out of 100: correlation = 0.74.
But Feature B also activates 64 times with C: correlation = 0.64.
Feature A -> C link: 0.74 is stronger than B -> C link: 0.64.
Conclusion: Feature C depends more on Feature A than on Feature B in this circuit.

This equation formalizes what CircuitLens does: find which upstream features actually caused each downstream activation by measuring co-activation patterns.

What can go wrong

What can go wrong

Weights are not always readable. Not every feature's meaning is cleanly encoded in its weights. Some learned features are entangled; their meaning is split across multiple weights or requires nonlinear decoding. WeightLens works best for simpler features.
Correlation is not causation. Two features might activate together because a third hidden feature causes both, not because one causes the other. CircuitLens measures correlation; it can mistake this spurious link for a real circuit edge.
Transcoders are a new tool with gaps. CircuitLens relies on transcoders to separate input-dependent from input-invariant components. If the transcoder is not perfect, the interaction measurements will be noisy.
Done right: combine the two views. WeightLens tells you what each feature means; CircuitLens tells you how they connect. Together, they catch each other's blind spots. A weight reading can confirm a suspected interaction, and an interaction measurement can validate a weight decoding.
What a runnable demo should prove

What a runnable demo should prove

A working demo would take a real neural network (trained on a vision or language task), pick a specific feature, and show: first, the weight-based meaning from WeightLens (in plain language: what visual pattern or text concept this feature responds to); second, the activation-based circuit from CircuitLens (which upstream features feed into it, and how strong each connection is); third, a concrete input example where those predicted connections fire exactly as the model predicts. The reader should see that the weight meaning and the activation circuit tell the same story.

agreement = number of predicted circuit edges that match observed co-activations on test inputs / total predicted edges

The demo must prove that you can read a feature's meaning from weights alone AND trace its activation sources without external models, at real model scale.
