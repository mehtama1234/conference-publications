Context parroting: A simple baseline for time-series foundation models

A model that simply copies the most recent patterns from the data outperforms large learned foundation models at predicting physical systems.

Paper explainersAll themesTime Series & Sequential

Foundation models trained on time-series data (sequences of measurements over time) claim to predict what happens next in physical systems like turbulence or heartbeats. But this paper shows that many of these models succeed by copying patterns directly from recent data, not by learning the actual physics. A naive baseline that does exactly this—copying what just happened—outperforms leading foundation models on dozens of real systems because recent patterns often repeat naturally in these systems.

Zero assumption version

Why foundation models seem to work

A foundation model is a large neural network trained on many time-series datasets (sequences of numbers over time). It can then forecast new systems it has never seen before, which sounds like real learning—the model should have learned patterns of how physical systems behave. But what if the model is not really learning physics at all?

The naive thing you might try first: take a model trained on many time series and ask it to predict the next few steps of a new system it has never encountered. You feed it the last 32 measurements (the context) and ask it to forecast the next 8 steps. The foundation model does well. So it seems like the model learned something deep about how dynamical systems evolve.

The problem in one sentence. Foundation models might succeed not by learning physics, but by copying patterns directly from the context they are given.

What the paper changes

The paper compares two things: a learned foundation model that processes context through many layers of neural computation versus a simple rule that copies patterns from the context directly. The key object is the forecast strategy.

The hidden quantity

The hidden quantity: in-context pattern matching

measured quantity  =  how much a model relies on echoing context

The paper measures whether a foundation model is truly learning physics or just copying patterns from the context it was given. This is not explicitly tracked; instead, the authors infer it by comparing the foundation model's accuracy to a naive parroting baseline. If the baseline wins, the foundation model must have been parroting.

To estimate this, the authors train a simple pattern-matching rule: find the most recent few steps in the context that match the current trend, and use what came next as the forecast. If this beats the learned model, the learned model was likely doing something similar.

Why it works

Why parroting beats learned models

Many dynamical systems (systems that change over time, like weather or heartbeats) have patterns that repeat on short time scales. If you have the last 32 steps, the next 8 steps often match a pattern you have already seen in those 32 steps.

A foundation model is trained to predict by learning weights (numbers that determine how the model processes input). But learning good weights is hard—the model must find weights that work for all the diverse systems it was trained on. By contrast, parroting is a direct rule: scan the context, find a matching pattern, emit what came next. It is not smart, but it works surprisingly well because many real systems have short-term regularities.

The foundation model might even learn to parrot internally—its attention mechanism (the part of the model that decides which parts of the input to focus on) might evolve to find recent patterns in context and copy them. But if that is the strategy, why pay the computational cost of a large trained model when a simple rule does the same job?

Math after the picture

The parroting equation

First in words:

The forecast is determined by finding the most similar sequence in the context window and returning the values that followed it.

Then the compact form:

forecast_t = context[context_end - lag + 1 : context_end - lag + prediction_length]

Every symbol:

forecast_tthe predicted values for the next steps
contextthe array of recent measurements given as input
context_endthe index of the last measurement in the context
laghow many steps back in the context the matching pattern was found
prediction_lengthhow many steps ahead to forecast (e.g., 8)
A tiny worked example
Context: [0.1, 0.2, 0.15, 0.25, 0.3, 0.2, 0.1, 0.2, ...].
Current trend: rising then falling (0.3, 0.2, 0.1).
Scan context: that pattern matches at index 4-6 (values 0.3, 0.2, 0.1).
What came next after index 6? Values 0.2, not known to the model.
Forecast: emit [0.2, ?], using only the immediate successor pattern.

The model succeeds because nearby values in the sequence are often similar, not because it learned the underlying physics.

What can go wrong

What can go wrong

Converges to the mean. When foundation models are not parroting, they often hedge their predictions by guessing a value close to the average of all past values. This is worse than parroting because it ignores the trend.
Parroting fails on new regimes. If a system enters a state it has never been in before (for example, a weather system shifts to an unusual pattern), parroting will not work because there is no matching pattern in the context to copy.
Works only on short forecasts. Parroting works for predicting the next 4-16 steps. For longer forecasts (predicting 100 steps ahead), copying breaks down because the system drifts too far from any single past pattern.
When to use learned models. Learned models might eventually win if trained specifically on one system (not multi-system foundation models), or if the system has long-term structure that pure copying cannot capture.
What a runnable demo should prove

What a runnable demo should prove

Build a small experiment on one real system: take a chaotic system such as a simulated pendulum or a real ECG (heart rate signal). Split the data into training and test sets. Implement the parroting baseline: scan the training context for the most similar recent pattern and use what followed as the forecast. Compare its error to a simple learned model (a small neural network or even a linear predictor trained on that system). The parroting baseline should win, and it should run in milliseconds while the learned model takes seconds or minutes.

error = mean absolute difference between forecast and actual next values, averaged over test set

Parroting beats learning not because it is smart, but because recent patterns genuinely repeat in real dynamical systems.
