SmoothSpike: Spiking Transformer with Learnable Hadamard Transformation

Spiking neural networks lose fine detail when too many inputs pack into the same spike count; smoothing the inputs before spiking fixes that without slowing down.

Paper explainersAll themesEfficiency & Systems

Spiking neural networks are energy misers: instead of processing continuous numbers like regular neural networks, they send sharp pulses (spikes) only when needed, saving electricity because processors only switch on when a spike fires. But they have a real problem: many different inputs get squashed down to the same number of spikes, washing out the distinctions the network needs to understand language. SmoothSpike solves this by scrambling the inputs before they spike, spreading them out so different meanings stay different.

Zero assumption version

When spikes pile up, meanings blend together

Spiking neural networks fire pulses instead of passing raw numbers. Each spike is a binary signal: fire or not. Over a fixed time window, the network counts how many pulses a neuron sends. A neuron that gets strong input sends many spikes; weak input means few spikes. This count is discrete: it is always a whole number like 3 or 7, never 3.5.

The problem: when different inputs are strong enough, they both produce a high spike count. A very strong input and a moderately strong input might both saturate, both producing the maximum spike count the neuron can generate in that time window. The network loses the information that they were different. It is like a filing cabinet full of papers where everything is stamped just URGENT, URGENT, URGENT—you cannot tell which urgent matters most.

In one sentence. SmoothSpike spreads the input numbers with a scrambling transformation before spiking, so different strengths map to different spike counts even when they would otherwise collide.

What the paper changes

What the paper changes

SmoothSpike inserts a learnable scrambling transformation (orthogonal, meaning it rotates without stretching) just before the spike threshold. When the model runs on new data, this scrambler gets built into the weight numbers, adding zero extra work.

the object it moves  =  input scrambling before spiking
The hidden quantity

The hidden quantity: Information Saturation Index

measured quantity  =  fraction of inputs converging to max spike count

In standard spiking networks, when inputs are large, many of them hit the ceiling—they all produce the maximum possible spike count in the time window. The paper calls this information homogenization: distinct inputs compress into one identical representation. The saturation index is how many neuron inputs land on this flat ceiling. If inputs are 5.0, 8.0, 10.0 and they all spike 6 times (the max), the saturation index is 3 out of 3, or 100 percent. Information is lost.

SmoothSpike measures this by comparing spike counts before and after the transformation. The Hadamard transformation spreads inputs, reducing the fraction that saturate. Fewer collisions mean more detail preserved for later layers.

Why it works

Why it works: spreading before the squeeze

Spiking is a squeezing operation: continuous input gets rounded to a discrete spike count. If two different inputs land in the same rounding bucket, they collapse to the same output. This is especially bad for high-amplitude inputs, which often share a bucket (the max count).

The Hadamard transformation is a systematic scramble: it mixes up the input dimensions in a way that spreads the values. After scrambling, the same two inputs are no longer close to each other—they sit in different regions of the value space. When they get rounded to spike counts, they round differently. The result: information survives the rounding step. The learnable version adapts this scramble to the specific patterns of inputs in each layer, optimizing the spread for what that layer actually sees.

Math after the picture

The smoothing equation

First in words:

output spike count = floor of (Hadamard transform times input) where the max input is bounded by square root of log of layer size divided by layer size

Then the compact form:

spike_i = floor( (H * x)_i ), where max(H * x) = O(sqrt(log(n) / n)) with high probability

Every symbol:

spike_ispike count for neuron i
HHadamard (or learnable orthogonal) transformation matrix
xpre-activation input vector
nnumber of input dimensions (layer width)
O(...)rough scale; the bound is proportional to this expression
A tiny worked example
Layer has 16 neurons (n=16). Log(16) ≈ 2.77, so log(n)/n ≈ 0.17, sqrt(0.17) ≈ 0.41.
Without smoothing: input x = [5.0, 8.0, 6.0, ...] after ReLU; some neurons saturate at spike_max = 8 spikes over time window.
With Hadamard H applied: H * x = [2.1, 3.8, 1.9, 2.6, ...]; no single value dominates. Floor gives [2, 3, 1, 2, ...] spikes.
Compare: without H, inputs [5, 8, 6] → [8, 8, 8] spikes (lost identity). With H, inputs → [2, 3, 1] spikes (preserved contrast). The bound ensures no output saturates the full space.

The bound ensures the transformation keeps values in a controlled range before spiking, so different inputs stay separated when rounded to spike counts.

What can go wrong

What can go wrong

Static Hadamard may not match later layers. A single fixed scramble works for early neurons but does not adapt as the data flow changes through layers. The paper solves this with a learnable version per layer.
Training the scrambler can cost time. Newton-Schulz iterations maintain orthogonality while learning, but add computation during training. The paper shows this merges into weights at inference (zero overhead then).
Orthogonality constraint is strict. Rotating without stretching keeps magnitudes stable but limits what transformations are possible. Some input patterns may not fit the constraint well.
Done right. Learnable per-layer Hadamard trained via Newton-Schulz, then fused into weights, recovers the expressiveness of dense networks while keeping spike efficiency.
What a runnable demo should prove

What a runnable demo should prove

Build a 2-layer spiking transformer on a toy text task (e.g., sentiment classification on 100 short sentences). (1) Measure spike saturation: count how many neurons hit max spike count in layer 1 without smoothing, then with fixed Hadamard, then with learned Hadamard. Saturation should drop. (2) Measure accuracy on held-out test sentences. Without smoothing, accuracy stays low (e.g., 52% on this toy set). With smoothing, it should recover (e.g., 68%), showing that less saturation means the model understands text better because more detail from the input survives into the network's internal reasoning.

saturation_rate = (# neurons at max spikes) / (total neurons); accuracy = (# correct predictions) / (# test examples)

The demo proves that spreading inputs before spikes (via learned Hadamard) reduces saturation and directly improves text understanding without adding inference cost, because the scrambler fuses into the weight numbers, leaving no extra work for the processor when it runs.
