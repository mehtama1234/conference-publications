Go-Browse: Training Web Agents with Structured Exploration

Train web-browsing agents by systematically exploring websites and reusing what they learn from each page to avoid revisiting pages.

Paper explainersAll themesAgents & Tool Use

A web-browsing agent needs to figure out which pages to visit to solve a task on an unfamiliar website. The simplest approach—randomly clicking links—wastes time revisiting the same pages. Go-Browse stores a map of which pages lead to which, so the agent remembers what it has already learned about the structure. This memory works because the agent can then skip pages it has already seen and focus only on unexplored pages, making each attempt find new pages faster.

Zero assumption version

Web agents get lost in unfamiliar websites

A web agent is a language model (a machine that reads text and writes text) trained to browse the web and solve tasks like 'find the cheapest hotel in Paris' or 'add an item to my cart.' The agent sees the current page (all the text and clickable links), and must choose which link to click next.

A naive approach: the agent randomly explores the website by clicking links and recording what it finds. But random exploration is wasteful. The agent might click the same link twice, or explore dead-end paths for hours without finding the right page. It needs to remember: this page leads to shopping (because a shopping page contains words like 'add to cart'), that page leads to search results (because it shows a list of products), this other page is useless (because it only shows privacy policy), and with that memory the agent can navigate faster on its next attempt.

The problem in one sentence. Random exploration wastes time, so training data is expensive and incomplete.

The algorithm as a flow

What it actually does

Treat a website as a graph

Each page is a node. Each clickable link is an edge connecting nodes.

Explore systematically

Use graph search (like breadth-first search) instead of random clicking.

Reuse information across episodes

When one attempt explores a page, all future attempts start knowing that page.

Collect success trajectories

Record every successful path from start to goal.

Train the agent on that data

Fine-tune a language model to imitate the successful paths.

What the paper changes

The thing being changed

The paper changes how training data is collected. Instead of random clicks, it uses structured graph search to decide which link to click next.

the object it moves  =  data collection strategy
The hidden quantity

Graph coverage: how well the agent knows the site

measured quantity  =  graph coverage (percentage of pages found)

Go-Browse introduces a named quantity: graph coverage, the fraction of all pages on a website that the agent has discovered. With random clicking, coverage grows slowly because the agent keeps revisiting known pages. With graph search, coverage grows quickly because the agent systematically explores new branches.

The paper measures this by tracking which pages the agent has visited during exploration. Higher coverage means the training data includes more diverse paths, which teaches the language model more about the site's structure.

Why it works

Why structured exploration collects better training data

Here is the core mechanism. When an agent explores a website by random clicking, it treats each exploration episode as independent. If the first attempt visits the homepage, search page, and results page, the second attempt still starts with zero knowledge—it might visit those same three pages again. Random exploration says: forget what you learned.

Go-Browse says: remember. It builds a graph during exploration. Every time the agent visits a page, it updates the graph to record which links are on that page. On the next exploration episode, the agent checks the graph first: have I been to this page before? If yes, skip it; if no, visit it. This reuse transforms exploration from a random walk into a systematic search that quickly reaches all corners of the website.

Faster graph coverage means more diverse training data, because the agent has seen more of the site's structure. A language model trained on diverse paths learns the site's structure better and makes better decisions on unseen pages, because it has learned from examples covering many different parts of the site. A 7-billion-parameter language model (a model with 7 billion numbers that the training process adjusts) trained on Go-Browse data beats GPT-4o mini, even though GPT-4o mini is much larger, because focused training data teaches reasoning better than scale alone.

Math after the picture

Counting coverage: the equation

First in words:

coverage is the count of unique pages discovered divided by the total pages on the website

Then the compact form:

coverage = unique_pages_visited / total_pages_on_site

Every symbol:

unique_pages_visitedthe number of distinct pages the agent has reached
total_pages_on_sitethe true size of the website
coveragea fraction from 0 (nothing found) to 1 (everything found)
A tiny worked example
Suppose a website has 10 pages total.
Random exploration: after many attempts, the agent has visited 6 unique pages. Coverage = 6 / 10 = 0.60.
Graph search: after the same number of attempts, the agent has visited 9 unique pages. Coverage = 9 / 10 = 0.90.
Graph search finds 50% more of the site, so training data is richer and more representative.

Higher coverage means the language model sees more paths and learns the website's structure more thoroughly.

What can go wrong

What can go wrong

Graph becomes stale on dynamic sites If the website changes between exploration runs (pages move, new pages appear, links vanish), the stored graph is outdated. The agent wastes time visiting a page that no longer exists.
Graph assumes pages are stable Go-Browse stores which pages are reachable from which. If a page's links change every time you reload it (because of JavaScript rendering different content), the graph becomes incorrect.
Reuse across websites is limited The graph learned from one website (Amazon) does not transfer to another (eBay). Each website needs its own exploration.
Done right: offline websites + static pages Go-Browse works best on stable, non-dynamic sites where the structure remains the same across exploration runs.
What a runnable demo should prove

What a runnable demo should prove

Build a simple demo that collects web agent training data from a small static website (10–20 pages, HTML only, no JavaScript). Implement two versions: one that explores randomly, one that uses breadth-first graph search. Measure graph coverage (fraction of pages found) after a fixed number of interaction steps.

coverage = pages_discovered / total_pages_on_site, then measure success_rate = (count of trajectories that reach the goal page) / (total exploration episodes)

The demo must show: graph search achieves 60%+ coverage where random exploration achieves only 30% (because graph search remembers pages and avoids revisiting), and the resulting training data improves agent success rate by 5–10 percentage points (because more diverse paths teach the model more about the site).
