AFD-Instruction: Teaching language models to understand and design antibodies

Give a language model antibody sequences paired with plain English descriptions of what they do, and it learns to predict function from sequence and design new antibodies to spec.

Paper explainersAll themesDatasets & Benchmarks & Evaluation

Antibodies are proteins that fight disease by recognizing and binding to invaders. A language model (a kind of AI that predicts the next word in a sentence) can spot deep patterns, but it has never been trained on antibodies described in plain English. AFD-Instruction is a dataset that pairs real antibody sequences with plain-language descriptions of what each one does. Training a language model on these pairs teaches it to read an antibody sequence and predict its function, or to write a new antibody sequence that does what you ask.

Zero assumption version

Language models know words, not antibodies

A language model is trained on text from books and the internet. It learns to predict the next word by spotting patterns. But antibodies are not words—they are strings of amino-acid letters (like MVLGALLLGTVAAGP...). A language model trained only on English text sees these strings as alien characters it has never learned to recognize.

A beginner might try: take a language model, show it a few antibody sequences, and hope it learns to say useful things about them. This fails because the model has no bridge between the sequence letters and the English words describing what that antibody actually does. Without that bridge, the model guesses randomly.

The move. Build a dataset pairing each antibody sequence with a plain English sentence saying what that antibody does, and fine-tune (adjust) the language model on these pairs.

The algorithm as a flow

What it actually does

Collect real data

Gather antibody sequences from biological databases (SabDab, PDB).

Extract function from papers

Read the scientific papers that published each antibody and write down what that antibody does in plain English.

Pair sequence with description

For each antibody, create a pair: the letter sequence plus the English sentence describing its binding, stability, or other traits.

Fine-tune the language model

Show the model thousands of sequence-description pairs. It adjusts its internal numbers to predict the description when given the sequence, or generate a sequence that fits the description you type.

Test on new tasks

Ask the tuned model new questions: predict function from a new sequence, or design a sequence with specific properties. It succeeds more often, because it learned the link between sequence letters and biological behavior.

What the paper changes

What the paper changes

The paper adds one thing to a language model: knowledge of antibody sequences and their functional descriptions. Specifically, it does this by collecting a dataset of real antibody sequences, each paired with a plain-language description of what that antibody does (how strongly it binds, what antigen it targets, whether it is stable). Then it fine-tunes (adjusts) the language model by showing it thousands of these pairs, so the model learns to connect the letter sequence to the English meaning.

the object it moves  =  Sequence-to-function pairing
The hidden quantity

The alignment: how well does the model link sequence to meaning

measured quantity  =  Sequence-function alignment score

The hidden quantity is how closely the language model links amino-acid letters to English descriptions of what the antibody does. A good alignment means: if you show the model a sequence it has never seen before, it correctly predicts the function. If you ask it to design a new sequence with a specific function, the sequence it writes actually does that.

The paper measures alignment two ways. First, it counts how many times the model correctly predicts the function when given an unseen sequence (this is called perplexity—lower is better, meaning fewer surprises, which means the model's predictions are accurate and expected). Second, it measures the success rate of designed sequences: does the antibody the model writes actually bind the target antigen the way you asked, measured by running a binding predictor on the generated sequence.

Why it works

Why pairing sequences with descriptions teaches the model

A language model works by learning patterns in text. When it reads a word, it predicts the next word based on everything it has seen before. When you show it a sequence letter followed by an English phrase, the model notices: every time I see these amino acids in this order, the next thing that follows is a description of strong binding. After thousands of examples, the model internalizes the link: MVLGALLLGTVAAGP means strong binder.

Once the model has learned this bridge, two things become possible. First, given a new sequence, it can predict the English description (understanding). Second, given an English description of what you want (strong binder, stable, targets antigen X), it can generate a new sequence of letters that should have that property (design). What matters is that the model does not memorize; it learns the underlying pattern—the deep connection between how an amino-acid sequence is built and what biological function it performs. This works because real antibodies follow rules: certain amino-acid clusters tend to bind certain targets, certain patterns give stability, and the model picks up these rules from thousands of examples.

Math after the picture

The fine-tuning loss

First in words:

Sum over all training pairs: loss for predicting the description from the sequence, plus loss for generating a sequence that matches the description. The model adjusts its numbers to shrink this total loss.

Then the compact form:

L = (1/N) * sum_i [ loss_predict(desc_i | seq_i) + loss_generate(seq_i | desc_i) ]

Every symbol:

Ntotal number of training pairs
seq_ithe amino-acid sequence of antibody i
desc_ithe plain-English description of antibody i's function
loss_predict(desc_i | seq_i)how far off the model's predicted description is from the true description
loss_generate(seq_i | desc_i)how far off a generated sequence is from the true sequence, measured by how well it binds the target
Lthe total error the model is trying to minimize
A tiny worked example
Pair 1: sequence MVLGALLLGTVAAGP, description 'strong binder'. Model predicts 'weak binder' -> error 8.2.
Pair 2: sequence AGGTAVLGALLLMVP, description 'unstable at heat'. Model predicts 'unstable at heat' -> error 0.1.
Pair 3: design task. You ask 'generate a sequence that binds target X'. Model generates MVLGATVVAAGP, model checks it: actual binding is weak -> error 6.7.
Average loss per pair: (8.2 + 0.1 + 6.7) / 3 = 5.0. Model adjusts its numbers to reduce this on the next batch.

Each time the model sees a pair, it adjusts its internal numbers to better predict the description when given the sequence, because larger errors push the adjustment harder, closing the gap between guess and reality.

What can go wrong

What can go wrong

Descriptions must be precise. If the text paired with a sequence is vague or wrong (says 'stable' when the antibody is actually unstable), the model learns a false pattern. It then makes mistakes on new tasks, because it has been taught the wrong rule about which sequences do what. High-quality annotations matter because a model's output is only as good as the training examples it learns from.
Rare functions go unseen. If the training set has many examples of strong binders but few examples of unstable antibodies, the model learns strong binders well but fails on unusual stability profiles. The model only excels at what was common in the data.
Sequences from similar organisms cluster together. If all antibodies in the training set come from mice, and you ask the model to design human antibodies, it will struggle. The model has not learned the pattern for human sequences, only for mouse ones.
Done right. Collect sequences from diverse sources (mouse, human, yeast variants) so the model learns rules that work across species, not just antibodies from one organism. Have experts write clear, specific descriptions (not 'works okay' but 'binds malaria antigen with nanomolar affinity'), because if the description is too loose, the model cannot latch onto a specific pattern—it tries to match too many overlapping meanings. Check descriptions match real sequences, because one mislabeled example teaches the model a wrong connection. Balance the training set so rare functions appear enough times to build learnable patterns; functions seen once get lost among the 10,000 common examples, and the model forgets they exist.
What a runnable demo should prove

What a runnable demo should prove

A demo should show two things. First, take a language model, fine-tune it on a subset of AFD-Instruction (say, 1,000 sequence-description pairs), then test it on 100 new sequences it has never seen. Measure how accurately it predicts the function of each. Second, ask the fine-tuned model to generate a new antibody sequence for a function you specify (for example, 'high affinity for COVID spike protein'). Use an antibody-binding predictor (like tFold) to measure whether the generated sequence actually binds that target. A good demo makes clear that fine-tuning on paired data teaches the model something it did not know before.

Accuracy_predict = (correct predictions / total test sequences) * 100. SRR_design = (designed sequences with measured binding > threshold / total design requests) * 100.

The metric that matters most: does the model's designed antibody actually work in a computer simulation of binding? That proves the model learned real antibody biology, not just memorized words.
