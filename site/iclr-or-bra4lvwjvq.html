VPPO: Token Perception in Multimodal Reasoning

When a vision-language model reasons through steps, most tokens do not need to look at the image — VPPO only trains on the tokens that do.

Paper explainersAll themesOther

A vision-language model trained with reward signals (reinforcement learning) learns to reason through many steps like a human working out a math problem. But most generated tokens do not actually need the image — they are just rephrasing or math steps. VPPO observes which tokens genuinely depend on visual information, then focuses training effort on those pivotal tokens and upweights the learning signal from trajectories where the image mattered.

Zero assumption version

Most multimodal reasoning ignores where the image matters

When you train a vision-language model (a model that reads both images and text) to reason better, the standard approach treats every word it generates the same way. It updates the weights equally for tokens about visual details and tokens that just reword previous thoughts, because updating all tokens uniformly with the same reward signal is simpler to code. But in a real reasoning task, the image is only essential for a few specific steps — identifying objects, understanding spatial layout, checking colors. Many tokens like 'therefore' or 'we have' do not need to see the image at all.

A beginner might assume: 'Just train all tokens equally, and the model will learn which ones need vision.' But that wastes effort, because updating weights based on tokens that do not use the image adds noise — the model gets pushed in directions that do not matter to the task, like polishing the phrasing of steps that do not depend on the picture. This noise slows learning and may pull the model away from what it should focus on: allocating its visual processing for the tokens that genuinely need it.

The move. VPPO measures which tokens actually look at the image, then trains the model harder on trajectories where the image mattered and focuses weight updates on those specific tokens.

The algorithm as a flow

What it actually does

Measure visual dependency per token

For each generated token, score how much it depends on the image input.

Compute trajectory importance

Aggregate token dependency scores into a single number per rollout (reasoning attempt).

Reweight trajectory reward signals

Upweight the learning signal from trajectories where the image was important.

Filter policy updates to pivotal tokens

Skip weight updates for low-dependency tokens; only tweak weights for high-dependency tokens.

Train the model

Standard policy update, now shaped by visual perceptiveness.

What the paper changes

What the paper changes

VPPO changes the learning signal — the reward and the direction nudge (how to adjust weights) the model learns from. Instead of a uniform learning signal, it becomes selective: trajectories where the image mattered get louder signals, and within each trajectory, only tokens that actually used the image are updated.

The hidden quantity

Token visual dependency — how much each word needs to see the image

measured quantity  =  Visual dependency per token

A token's visual dependency is a score (a number from 0 to 1) measuring how much that token's generation depends on information from the image. A token like 'red' identifying an object color has high dependency; a token like 'the' has low dependency.

VPPO measures this by comparing the token's probability with and without the image: if removing the image barely changes the model's likelihood of generating that token, dependency is low. The paper then uses two aggregations: token-level (scores each word) and trajectory-level (sums or averages across all words in one reasoning attempt).

Why it works

Why training on visual dependency works

The core insight is signal-to-noise in training. When you apply the same learning nudge to all tokens, you are pushing high-dependency tokens in the right direction but also pushing low-dependency tokens, where the image is irrelevant. The low-dependency tokens create noise and distract the model's visual reasoning.

VPPO removes that noise in two ways. First, at the trajectory level: if a rollout never needed to look at the image, its reward signal (whether it got the answer right) is not a reliable guide for visual reasoning. Downweighting that trajectory's signal prevents the model from learning the wrong lessons. Second, at the token level: filtering out gradients to low-dependency tokens means the model only tunes weights based on feedback from tokens that actually used the image. This focuses learning on the visual pathway of the model's computation.

The result is faster convergence and better final performance because training effort is concentrated where the image matters. The model learns to allocate its visual reasoning capacity precisely.

The learning signal reshape

First in words:

Shaped advantage = (trajectory visual dependency) * (original advantage). Token loss = sum over high-dependency tokens only of (policy gradient times shaped advantage).

Then the compact form:

A_shaped = alpha(tau) * A_orig; L_VPPO = sum_{t in high_dep(tau)} [policy_grad_t * A_shaped]

Every symbol:

alpha(tau)visual dependency factor for trajectory tau, normalized to range [beta_min, beta_max]
A_origoriginal advantage (reward minus baseline), same for all tokens in a trajectory
A_shapedreweighted advantage that upweights high-visual-dependency trajectories
policy_grad_tpolicy gradient at timestep t (derivative of log-probability with respect to weights)
high_dep(tau)the subset of tokens in trajectory tau with visual dependency above threshold
L_VPPOthe final loss to optimize
A tiny worked example
Imagine a 5-token reasoning chain. Token 1 ('object') and Token 3 ('color') look at the image (dependency 0.9). Tokens 2, 4, 5 do not (dependency 0.1).
Trajectory visual dependency = mean([0.9, 0.1, 0.9, 0.1, 0.1]) = 0.4. After normalization to range [0.5, 1.0], alpha(tau) = 0.75.
Original advantage = 1.0 (reward - baseline). Shaped advantage = 0.75 * 1.0 = 0.75.
Policy gradient at Token 1: 0.1. At Token 2: 0.15. Traditional training updates both: 0.1 * 1.0 = 0.1 loss; 0.15 * 1.0 = 0.15 loss.
VPPO training: Token 1 (high dependency) updates with 0.1 * 0.75 = 0.075 loss. Token 2 (low dependency) is masked out, contributes 0 loss.
Result: high-dependency tokens get 25% less credit (noise reduction from not being over-trained on irrelevant rollouts), low-dependency tokens are skipped entirely (no noise from them).

The shaped advantage puts a single multiplier on the entire trajectory, then token-level masking selects which gradients to actually apply, together filtering noise from non-visual reasoning.

What can go wrong

What can go wrong

Dependency measurement is noisy. If the visual dependency score is computed inaccurately (e.g., using a weak proxy), VPPO may mask out tokens that should have been trained or over-train on irrelevant tokens. This happens when the dependency metric is biased or low-resolution.
Threshold tuning is critical. Choosing which tokens count as 'high dependency' (the top k%, or a cutoff score) is a hyperparameter. If set too high, too few tokens are trained; if too low, the filter does almost nothing. This sensitivity requires validation on held-out data.
Trajectories with no visual tokens are under-learned. In a reasoning task that happens to not need the image, VPPO downweights the trajectory. If a reasonable-but-non-visual solution exists, the model may learn to ignore the image entirely to maximize reward quickly.
Done right. Carefully validate the dependency metric on a sample of trajectories; tune the filtering threshold on a validation set; include a small randomness penalty (encouraging the model to stay curious) to keep exploring the image pathway even on low-dependency trajectories.
What a runnable demo should prove

What a runnable demo should prove

A demo should train two identical vision-language models on the same reasoning task: one with uniform policy gradient, one with VPPO. Generate reasoning trajectories on a visual reasoning benchmark (e.g., a dataset where you have to read text and objects in an image). For each trajectory, compute the token-level visual dependency scores using the model's internal gradients. Apply VPPO reweighting and masking to one model, run standard training on the other, and track accuracy and training curves over steps.

training_convergence_speed = step_at_80_percent_accuracy; final_accuracy = accuracy at step 300

The demo must show that VPPO reaches 80% accuracy in fewer training steps and with a higher final accuracy, while confirming via a histogram that the model is indeed concentrating gradients on high-visual-dependency tokens.
