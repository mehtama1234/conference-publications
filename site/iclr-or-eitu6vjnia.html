PERSISTENCE SPHERES: BI-CONTINUOUS REPRESENTATIONS OF PERSISTENCE DIAGRAMS.

Map persistence diagrams into an ordinary linear feature space while preserving both stability to small data changes and enough structure to reconstruct the original diagram continuously.

Paper explainersAll themesOther

Topological data analysis summarizes shape by building persistence diagrams: multisets of birth-death points that record when connected components, loops, or higher-dimensional structures appear and disappear across a filtration. Those diagrams are useful but awkward for machine learning because they are sets of variable size equipped with Wasserstein distance rather than ordinary fixed-length features. Existing embeddings, meaning feature maps that turn diagrams into ordinary machine-learning inputs, often lose one of two goals. Some are stable under small perturbations but distort the original diagram heavily. Others keep more detail but lose continuity or invertibility. Persistence spheres aim for both at once. They define a map from diagrams into a linear space that is Lipschitz with respect to 1-Wasserstein distance and also has a continuous inverse on its image. The point is not only accuracy on benchmarks. The point is that the representation changes smoothly when the diagram changes and still retains enough information to recover that diagram continuously.

Zero assumption version

Why persistence diagrams are hard to use directly in learning systems

A persistence diagram is not a fixed table of values. It is a set of points where each point records when one topological feature appears and when it disappears. Different datasets can produce different numbers of points, so standard learning pipelines cannot consume diagrams directly without a representation change.

That change is delicate. Small perturbations in the data should create only small changes in the representation, because persistence is used precisely for its stability. But the representation should also retain enough detail to distinguish diagrams that are genuinely different. Many existing summaries trade one goal against the other.

The paper's move. Build a representation with continuity in both directions, because a good feature map should change smoothly with the diagram and should not throw away essential diagram structure.

The hidden quantity

The hidden quantity

measured quantity  =  how much of the original diagram structure survives the embedding

The hidden quantity is the fidelity of the diagram after representation: whether the embedded function still determines where the birth-death points were and how they move under perturbation.

This is stronger than ordinary downstream accuracy because a representation can score well on one task while still collapsing many distinct diagrams onto similar features. Persistence spheres target a stricter property: nearby diagrams stay nearby, and distinct diagrams remain separable enough that the inverse map varies continuously on the embedded image.

Why it works

Why bi-continuity matters

Forward continuity matters first because persistence diagrams are used in noisy settings. If a tiny perturbation in the input data caused a large jump in the feature representation, the topological summary would become unreliable for learning. The Lipschitz property prevents that by bounding how much the feature representation can move under 1-Wasserstein changes in the diagram.

The inverse continuity matters next because stability alone is not enough. A representation can be very smooth while still merging many different diagrams into almost the same feature. By requiring a continuous inverse on the image, the paper ensures that the embedded object keeps enough structure to recover the original diagram without discontinuous decoding.

The linear-space target matters because many learning methods assume addition, averaging, and ordinary norm-based optimization are available. Persistence spheres move diagrams into that setting without discarding the Wasserstein-based structure that made the diagrams informative in the first place.

Bi-continuity statement

First in words:

The forward map should move at most proportionally to 1-Wasserstein changes in the diagram, and the inverse on the image should also vary continuously so the original point set remains recoverable.

A tiny worked example
Suppose one persistence point moves slightly because the input point cloud was perturbed by a small amount.
The 1-Wasserstein distance between the old and new diagrams is then small.
The Lipschitz property guarantees that the persistence-sphere features also move only a small amount.
If two embedded representations converge toward each other inside the image of the map, the inverse continuity says their decoded diagrams also converge.
Together these two statements give smooth behavior in both directions.

The central claim is not only a forward bound. It is the pair of continuity properties taken together.

What can go wrong

What can go wrong

Setting choice can trade smoothness against resolution. If the persistence-sphere settings are too coarse, the representation may blur nearby points together. If they are too fine, numerical estimation can become less stable.
The inverse matters only on the image. Continuous recovery is guaranteed for representations that actually come from valid diagrams, so arbitrary feature-space perturbations may not decode into valid diagrams in a stable way.
Downstream success can hide representational loss. A method can perform well on one benchmark while still discarding diagram information that would matter on another task.
Done right. The representation is most convincing when it changes smoothly under 1-Wasserstein perturbations, preserves enough point-set detail for continuous recovery, and remains usable by ordinary linear-space learning methods.
What a runnable demo should prove

What a runnable demo should prove

Build a small topological benchmark from noisy circles, figure-eight shapes, and random point clouds. Compute persistence diagrams, transform them with persistence spheres, and compare them against one or two standard persistence embeddings. The demo should test whether small perturbations in the point clouds produce small feature changes, whether nearby embedded features decode to nearby diagrams, and whether the transformed features support classification without losing shape distinctions.
