Task Vectors, Learned Not Extracted

LLMs can learn compact task representations directly rather than extracting them, revealing that these vectors steer predictions through a handful of attention heads and rotate earlier layers toward task-relevant ideas.

Paper explainersAll themesInterpretability

When an LLM reads a few examples of a task, it somehow learns to solve that task without retraining. This happens because the examples are packed into a task vector—a compact list of numbers that shifts the model's predictions. But extracting these vectors from the model's internals has been clumsy and opaque. This paper shows a cleaner way: train the task vectors directly. Direct training works better because it optimizes explicitly for prediction accuracy, and it exposes what heads are being used because the training process lights up the heads that actually matter.

Zero assumption version

Extracting task vectors is messy and opaque

When you show an LLM a few examples of a new task, it learns to solve it on the fly. Researchers suspected the model was packing those examples into a hidden task vector—a compact summary it reuses for predictions. But finding these vectors was painful: you had to reach into the model's hidden layers or outputs, apply some ad-hoc extraction method, and hope you got the right thing. These extraction methods were often opaque and failed to explain why the vectors actually worked.

A beginner might try: take the model's internal numbers (the values it computes while reading examples), average them, and call that your task vector. But this breaks down quickly—the vector only works at the layer it came from, stops working when you ask the model new questions, and does not generalize to new prompt formats.

The core problem: Task vectors extracted from the model's internals are opaque, inflexible, and their mechanisms remain mysterious.

The algorithm as a flow

What it actually does

Train the vector end-to-end

Instead of extracting, use repeated nudging (like training any neural network) to learn a task vector that improves predictions, because nudging toward lower error directly finds what works.

Inject it anywhere in the model

The same learned vector works at different layers and positions, not locked to where it came from.

Measure which heads move predictions

Track the OV circuits (the parts of each head that read and output information) to find key heads.

Map the linear path through layers

Early layers rotate the vector toward task-relevant ideas; later layers scale it up or down.

Expose failure modes

Reveal when the vector breaks: on new kinds of tasks, with incompatible prompts, in tasks needing multiple reasoning steps.

What the paper changes

What the paper changes

The paper changes how task vectors are created: from extraction (digging into the model) to direct training (learning the vector end-to-end like any neural network weight).

the object it moves  =  task vector creation
The hidden quantity

Key attention heads: which heads steer predictions?

measured quantity  =  Attention head steering strength

The paper measures how much each head (attention head, a sub-unit that processes information) contributes to shifting the model's final predictions. This is captured in the OV circuit—the internal path within each head that reads information and writes output. A head with a strong OV circuit moves predictions by a lot; a weak one barely matters.

The paper estimates this by injecting the learned task vector and watching which heads' OV circuits light up with signal matching the vector. Heads with larger matches between the task vector and their OV circuits are the key heads—typically a small subset that do the real work of steering predictions.

Paper reading The paper computes steering strength as the projection of the learned task vector onto each head's output-value (OV) circuit. High-steering heads have large projections; these are ranked and the top-k heads are identified as key heads.
Why it works

Why learning task vectors works

Training a task vector directly works because it optimizes for the actual goal: improve predictions on the task. Unlike extraction, which guesses what the vector should be, training uses repeated small adjustments (nudging the vector in the direction that reduces error) to find exactly what nudge makes predictions correct. The vector learns to trigger the right heads in the right way.

Once trained, the vector flows through the model in a largely linear fashion (movement in straight lines, despite the model's curved nonlinear pieces). Early layers rotate the vector toward task-relevant directions—specific abstract paths in the neural space that relate to the task (for a math task, directions that activate math reasoning). Later layers mostly scale the vector up or down, amplifying or muting it based on context. This linear flow is why the vector works at arbitrary layers: it is not locked to one location.

Math after the picture

The learning objective

First in words:

loss on task examples = prediction error; minimize via gradient descent to find the best task vector

Then the compact form:

L_task = sum_examples cross_entropy(model(input_i + tv), target_i)

Every symbol:

L_taskthe total prediction error on the task examples
tvthe task vector (what we are learning)
input_ithe i-th task example
target_ithe correct answer for that example
cross_entropya standard measure of how wrong a prediction is
A tiny worked example
Example 1: model predicts class A (wrong, should be B). Error for this example: 1.2.
Example 2: model predicts class B (correct). Error: 0.05.
Example 3: model predicts class A (wrong, should be C). Error: 0.8.
Total loss: 1.2 + 0.05 + 0.8 = 2.05. Training nudges the task vector to reduce this.
After one round: errors become 0.6, 0.02, 0.3. New loss: 0.92. Progress.

The task vector is learned by repeated small nudges in the direction that reduces error (the standard training method for neural networks): find the vector values that minimize the error on examples.

What can go wrong

What can go wrong

Tasks unlike the training examples If the new task is fundamentally different from the examples used to train the task vector, the vector steers the model in the wrong direction. The model does not know what to do.
Incompatible prompt formats If the prompt structure at inference is radically different from training (e.g., different wording, reversed order), the task vector may fail to trigger the right attention heads.
Multi-step reasoning tasks Tasks that require the model to plan multiple steps ahead can overwhelm a task vector trained on simple examples. The vector was not designed for complex chaining.
Done right A task vector trained on diverse, representative examples and tested on similar tasks within the model's capabilities works cleanly, preserves the original task, and reveals which attention heads matter.
What a runnable demo should prove

What a runnable demo should prove

Pick a simple task like sentiment classification. Collect 10–20 examples (half positive, half negative reviews). Train a task vector on these using repeated nudging (the standard neural network training method). Then test the vector on a held-out batch of reviews and measure accuracy. Inject the same vector into different layers of the model and confirm it still improves predictions (unlike extracted vectors). Finally, identify the top 3 key heads by ranking OV-circuit projections and show that ablating (turning off) these heads destroys the task vector's effect.

task_accuracy = correct_predictions / total_predictions; preservation = accuracy_on_original_task_with_vector / accuracy_without_vector

The demo makes impossible to miss that: (1) the learned vector works at any layer, (2) only a few heads carry the signal, and (3) the vector preserves what the model already knew.
