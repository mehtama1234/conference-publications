Learned Task Vectors: Training Instead of Extracting

Instead of trying to extract task shortcuts from a model's hidden states, train them directly by optimizing what to add at each layer.

Paper explainersAll themesInterpretability

When you show a language model examples of a new task (in-context learning), it somehow remembers the pattern and answers correctly. This happens because the model compresses the task into a small shortcut. Earlier work tried to extract these shortcuts by reading the model's internal numbers after showing examples, but that process was messy and unclear. This paper trains these shortcuts directly: you add a small numerical change to the model's internal state at any layer, then use learning steps to optimize what that change should be. This works better than extraction because learning finds the optimal shortcut for each layer and position, unconstrained by what the model happened to store; and it reveals the mechanism because you can trace each learned shortcut through the model and see which routing parts rotate it toward task labels.

Zero assumption version

The extraction problem

When you give a language model a few examples of a task (call it in-context learning), something in the model changes to solve that task. Scientists wanted to understand what changes—to find the task shortcut. They tried extracting it: look at the model's internal numbers at each layer (the encodings the model builds as it processes input), subtract the numbers before the examples from the numbers after, and call the difference a task shortcut.

But this extraction method is messy. You have to guess which layer to look at. You have to decide how to subtract—should you average over the words the model is processing? Different words? Different choices give different answers, and it is not clear why any choice is right. Worse, even after extracting a task shortcut and adding it back to a fresh run, the boost is small—the shortcut does not capture the full effect, because extraction only picks up correlations that already exist in the model's internal numbers; it misses the optimal numerical change for your exact goal.

The blind spot. Extraction assumes task shortcuts are already hidden in the model's numbers. But maybe the best shortcut is not hiding already; maybe it needs to be built from scratch for each task by learning.

What the paper changes

What the paper changes

Instead of extracting a shortcut from existing internal numbers, the paper directly trains a shortcut by adding it and learning. The shortcut is added to the model's internal numbers at layer L and word-position I. Then learning steps adjust those numbers so predictions match task examples.

the object it moves  =  Trainable numerical injection and learning
The hidden quantity

Task direction alignment

measured quantity  =  How much the shortcut rotates toward task-label directions

As a trained task shortcut moves through the model's layers, the downstream layers gradually rotate it toward the directions that increase the raw scores for the correct task labels. This rotation is not random; it follows a specific pattern. Early-layer shortcuts are far from the task direction, so they get rotated sharply by the parts of the model that route information. Late-layer shortcuts are already close, so they get rotated less. The paper measures this rotation by checking what words the shortcut decodes to at each layer: early shortcuts decode to random words (they are still generic), while late shortcuts decode to task-relevant words (they are already aligned).

The paper estimates this rotation using a linear map that describes how each layer transforms the shortcut. They compute a numerical transformation that, when applied to early-layer shortcuts, rotates them to align with task-label word-values, making them decode as task-specific words instead of noise.

Why it works

Why training beats extraction

When you extract a task shortcut, you are limited to what is already in the model after seeing examples. But the model may not have stored the task in a clean, extractable form. Training a task shortcut is different: you start with a random numerical change and directly learn it to solve the task. Learning steps find the numerical change that best fits the task, unconstrained by what happened inside the model.

The mechanism works in two stages. In the first stage (early layers), the shortcut is a generic nudge—it does not yet point toward the task labels. Routing parts of the model (the parts that route information) rotate this generic nudge toward the correct direction, gradually aligning it with the task-label word-values (the numerical representations of the right answers). In the second stage (late layers), the shortcut is already close to the right direction, so the model just scales it up or down without much rotation. This two-stage process is more efficient than extraction because it finds the optimal shortcut for the exact layer and word-position, rather than guessing where to look in existing internal numbers.

The update rule

First in words:

At layer L and word-position P, the model's internal numbers are updated by adding a trainable shortcut. The shortcut is optimized to minimize the loss, which measures how wrong the predictions are on task examples.

Then the compact form:

internal_new = internal_old + theta minimize: loss(predictions, correct_labels)

Every symbol:

internal_oldthe model's internal numbers at layer L, word P, before adding the shortcut
thetathe learned task shortcut at layer L, position P
internal_newthe updated internal numbers after adding the shortcut
loss(predictions, correct_labels)how wrong the predictions are; smaller is better
minimizethe learning process adjusts theta to make loss as small as possible
A tiny worked example
Suppose a task has 4 examples. Layer 8, word 1: theta starts as [0,0,0]. Loss = 2.3 (predictions wrong, 10% chance of correct answer).
After 10 learning steps: theta becomes [0.8, -0.6, 0.4]. Predictions improve to 80% chance. Loss = 0.22.
Same task, layer 16 injection: theta = [0.3, -0.1, 0.2] (smaller; late layers need less change). Loss = 0.19.
This shows: early layers need bigger shortcuts; late layers need gentle adjustments.

The shortcut is added to exactly one layer and word-position, and learning finds the values that best fit the task without requiring extraction guesses.

What can go wrong

What can go wrong

Overfitting to training examples. If you learn the shortcut only on the task's training examples (the ones you show), it may memorize them perfectly but fail on new test examples. The paper avoids this by splitting the training data into train and validation splits, using validation loss to stop early.
Wrong layer choice. Early layers and late layers behave very differently. If you inject at a layer where the model has not yet built task-relevant features, the shortcut can only make small nudges. If you inject too late, the model has already committed to a wrong direction and the shortcut cannot fully correct it.
Position matters. The shortcut can be added to any word position (start, middle, end). If you add it to the wrong position, the downstream routing parts may not move it to the decision-making parts of the model. The paper shows that position 0 (last word, often the one being predicted) is often best, but this varies by task.
Done right. Train the shortcut on a held-out subset of training examples, validate on a separate validation split, and test on fresh held-out test examples. Vary the layer and position, and report results across all layers to reveal the mechanism.
What a runnable demo should prove

What a runnable demo should prove

Implement learning to train a small task shortcut for a toy task (e.g., classify whether a sentence is positive or negative given a few in-context examples). Add the shortcut at different layers of a small language model. For each layer, measure the accuracy on held-out test examples. Plot accuracy vs. layer number. Also, decode what words each trained shortcut represents at each layer (show that early layers decode to random words, late layers to task-relevant words). Finally, compare the trained shortcut's accuracy to an extracted shortcut (one computed by subtracting internal numbers before and after examples).

accuracy = (count of correct predictions) / (total test examples)

The demo should make three things obvious: trained shortcuts outperform extracted ones because learning optimizes for each layer; early-layer shortcuts decode to gibberish while late-layer shortcuts decode to task words, because routing parts rotate generic shortcuts toward task meanings; and the accuracy curve peaks at middle layers, showing where the model's decision-making machinery lives.
