Node Affinity Prediction in Temporal Graphs

Replace generic neural networks with a learnable state machine that remembers what each node has done before, and use ranking loss instead of classification loss so training matches how we actually grade the predictions.

Paper explainersAll themesGraph & Geometric Learning

Predicting which people a user will interact with in the next week, based on their past behavior in a social network that grows over time, is a real problem. Modern neural networks fail at this, beaten by simple tricks that just remember what happened before or average recent events. This paper shows why: graph neural networks (models that learn patterns from networked data) forget temporal information by resetting at each step, and they measure training errors the wrong way. The fix is to use a learnable state machine that remembers each node's history, and to measure training success by whether top-ranked predictions are correct, not by whether yes-or-no guesses are right.

Zero assumption version

Why simple heuristics beat neural networks here

Node affinity prediction means: given a person's interactions in a network so far, predict which other people they will interact with next. This shows up in social media, finance, and recommendation systems.

Modern graph neural networks treat this as a yes-or-no classification task (yes or no for each possible target), but they fail — beaten by moving averages and persistent forecasting, which just remember what happened before. The paper identifies two leaks: first, graph neural networks discard past information at each step (they compute learned numerical summaries only from nearby neighbors, losing the broader history); second, they are trained to minimize classification loss, which treats getting a top-10 ranking slightly wrong the same as getting a rank-50 prediction right, even though we care most about the top rank being correct.

In one sentence. When ranking future interactions, neural networks leak temporal history and optimize the wrong metric, so simple heuristics that just remember the past beat them.

What the paper changes

The single thing the paper changes

The paper switches from discarding node state between predictions to keeping and updating a continuous running memory per node, and from measuring training loss via classification to measuring it via ranking quality.

the object it moves  =  node state and training loss function
The hidden quantity

Affinity state: the hidden memory per node

measured quantity  =  Running affinity state (list of numbers per node)

This is the internal memory the model maintains for each node. It is not the final prediction; it is the hidden state that evolves over time as the node interacts with others. At prediction time, this state is output as the affinity score.

NAVIS estimates this by storing a list of numbers h for each node, updated smoothly at each time step using a learnable linear state-space model (a machine that updates its memory by a fixed mathematical rule, but with learnable numbers). The paper's key insight is that simple heuristics like moving average turn out to be special cases of linear state-space models, so a learnable model can generalize them while staying interpretable. The model learns optimal mixing coefficients that control how much of the old state to keep and how much of the new interaction to add.

Why it works

Why stateful, ranking-aware training works

Neural networks that recompute learned numerical summaries from scratch at each step forget the broader history of interactions. NAVIS keeps a running state for each node, updated smoothly when new interactions arrive. This state follows the same mathematical pattern as an exponential moving average (keeping a weighted mix of old and new), but with learned weights instead of a fixed formula. Because the mixing coefficients are learned during training, the model can tune how much to remember vs. how much to react to the present.

Classification loss (standard for yes-or-no problems) penalizes all wrong predictions equally. But affinity prediction is a ranking task: we care whether the top-ranked people are correct, not whether a person ranked 50th is guessed right. Lambda Loss fixes this by computing direction-of-improvement nudges only from pairs of nodes that, if swapped, would improve the final ranking. A mistake at rank 1 pulls training much harder than a mistake at rank 50, so the model learns to focus on getting the top predictions right. Because the loss directly measures ranking quality, it aligns training with evaluation metrics like mean reciprocal rank (the average position of the correct answer).

The state update and loss function

First in words:

State is updated by a learnable linear mix of old state and new input. Loss is computed by pairwise gradients that measure ranking swaps.

Then the compact form:

h_t = keep_coeff * h_{t-1} + add_coeff * x_t; Lambda_Loss = sum over ranking pairs (i,j) of ranking_benefit(i,j) * gradient_step

Every symbol:

h_tthe affinity state for a node at time t
keep_coefflearned coefficient for how much of old state to keep (between 0 and 1)
add_coefflearned coefficient for how much of new interaction to add
x_tnew interaction signal at time t
ranking_benefit(i,j)how much the ranking improves if nodes i and j are swapped
A tiny worked example
Old state h = 5.0, new interaction x = 2.0, learned α = 0.7, β = 0.3
New state: 0.7 × 5.0 + 0.3 × 2.0 = 3.5 + 0.6 = 4.1
The node keeps 70 percent of its past affinity, plus a 30 percent boost from the fresh interaction.

What can go wrong

What can go wrong

Stale state. If nodes stop interacting, the state becomes old information. The model must learn when to fade old state or when to give zero weight to history. If the memory coefficient is too high, the model ignores fresh interactions; if too low, it forgets the past.
Sparse interactions. If a node has very few interactions, the learned coefficients may overfit. The model sees too little signal to know whether the memory coefficient should be 0.8 or 0.6. Moving average heuristics use a fixed, simpler rule with no learned coefficients, which reduces the risk of overfitting because there is less room for the model to memorize noise instead of learning a real pattern.
High-rank prediction errors. Lambda Loss focuses learning on top-rank swaps. If the top rank is very hard to predict (e.g., a new node with no history), the loss signal is sparse and noisy.
State alignment. When the method works: the learned mixing coefficients stay stable across test time because the model learns a consistent pattern of how to weight old vs. new, the global virtual state grounds the local node states by giving each node's memory a common reference point, and Lambda Loss nudges point consistently toward better ranking because training and evaluation use the same ranking metric.
What a runnable demo should prove

What a runnable demo should prove

Build a tiny temporal graph: 10 nodes, 50 timesteps. For each timestep, add one random interaction. At timestep 30, freeze the graph and ask: rank the remaining 5 nodes by predicted affinity with node 1. Measure two ways: (1) classification loss (cross-entropy: is node X in the top 3? yes or no), and (2) Lambda Loss (ranking: what percentile is the correct node?). Train a model using classification loss, and train the same architecture using Lambda Loss. At test time, measure rank-based metrics: is the correct node in the top 1? top 3? top 5?

Improvement = (Lambda_Top1_Accuracy - Classification_Top1_Accuracy) / Classification_Top1_Accuracy

The demo makes it impossible to miss: on the same model and data, Lambda Loss training always ranks the correct node higher than classification loss training, because ranking loss directly teaches ranking.
