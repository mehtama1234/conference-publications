IDER: Idempotent Experience Replay for Reliable Continual Learning

A model stays reliable across new tasks by checking that it gives the same answer when you feed its own output back through it.

Paper explainersAll themesRepresentation & Self-Supervised Learning

When a neural network (a mathematical system that learns patterns) encounters new tasks one after another, it forgets what it learned before—a crisis called catastrophic forgetting. But there is a deeper problem: even when a model does remember, it often grows overconfident in its wrong guesses. IDER fixes both by enforcing a simple principle: a well-trained model should spit out the same answer when you feed its answer back into it, like a photo of a photo looking the same as the original.

Zero assumption version

Forgetting and Overconfidence

A model trained on an old task learns weights that work well on that task. When a new task arrives, the model adjusts those weights to learn the new pattern. But the catch: changing weights to fit the new task scrambles the solution to the old task. The model forgets.

A beginner might try: keep old task examples in memory and replay them during new-task training, so the model sees both tasks together. This works better than nothing, because the model gets reminded of the old patterns; old examples act like rope holding the weights in place. But there is a deeper trap: a model that has been rewritten can still be extremely confident about the wrong answer, even with replay. In mission-critical systems (a self-driving car, a medical diagnosis tool), a confident wrong answer is dangerous. The model needs to know when it is uncertain, not just remember the facts.

Existing methods that add uncertainty awareness are expensive (they demand extra memory and computation) and clash with the simple replay approach that works best in practice.

The core problem. The model rewrites its weights to learn new tasks and forgets old ones, and it grows blindly confident even when its answers are wrong.

The algorithm as a flow

What it actually does

Step 1: Train idempotently on current task

Minimize loss: model must output the correct answer whether given a hint or not.

Step 2: Distill stability from old checkpoint

Run data through the old, frozen model. Feed that output back through new model. Penalize any change.

Step 3: Replay old examples

Pull random old-task examples from the buffer, apply the same penalties so they stay stable.

Step 4: Combine the three losses

Weight them and nudge the weights (using a learning algorithm) to lower the combined loss. Model learns new task but resists rewriting.

Step 5: Deploy

Model now confident only when it should be; old memories intact.

What the paper changes

What the paper moves

IDER changes how the model is trained: instead of naively minimizing error on new data, it enforces idempotence. The model must give the same output when fed its own output again. This is a behavioral rule, not a weight penalty.

the object it moves  =  training procedure
The hidden quantity

Model stability (does the model rewrite itself?)

measured quantity  =  idempotence gap

Idempotence gap is how much the model's output changes when you run it a second time. A gap of zero means the model is stable; a large gap means the model is rewriting itself and likely to forget or become overconfident.

The paper estimates this gap by running data through the model twice (or through the old checkpoint, then the new model) and measuring the distance between the two outputs. Small gap means the model is trustworthy; large gap is a red flag.

Why it works

Why idempotence prevents forgetting

When you retrain a model on new data, weights shift. Most shifts are harmless (they adjust for the new task), but some shifts destroy old knowledge. Idempotence creates a 'check mechanism': if shifting weights changes the model's behavior even on its own outputs, that shift is dangerous and gets penalized during training.

Specifically, the model learns to map each input to a stable fixed point. When the model passes its own output back through, it should land on the same output again—no drift, no rewiring. This constraint means weights can move only in ways that preserve the old solution space. The old checkpoint acts as a reference: if the new model gives a different answer than the old model on the same input, and feeding that through again changes things, the loss grows. Training then corrects the instability. The result: the model learns the new task but stops itself from erasing the old task.

For uncertainty, the same principle works: a model that is rewriting itself is probably wrong. Idempotence forces the model to land on a stable solution, which it can only do honestly. Overconfident wrong answers are inherently unstable (feed them back and they flip), so idempotence nudges the model toward genuine confidence.

Math after the picture

The three-part loss

First in words:

Total loss = idempotence loss on current data + idempotence distillation loss on buffer + replay cross-entropy loss on buffer, weighted by two hyperparameters alpha and beta.

Then the compact form:

L_IDER = L_ice + alpha * L_ide + beta * L_rep_ice

Every symbol:

L_iceloss to make model idempotent: model(x,0) and model(x,y) both should equal y
L_idedistillation loss: model should give same output as old checkpoint on buffer data
L_rep_icecross-entropy loss on replayed old-task examples
alphaweight on the distillation loss, controls how much old knowledge is preserved
betaweight on the replay loss, controls how much new task matters relative to stability
A tiny worked example
Suppose a model is trained on Task 1 (classifying cats vs dogs) and now learns Task 2 (classifying birds vs fish).
Input: an image x. Ground truth for Task 2: bird (y = bird).
Step 1: model(x, 0) gives 'dog' (wrong for Task 2). model(x, bird) gives 'bird' (correct). L_ice penalizes the first: we want both to output 'bird'.
Step 2: Old checkpoint model(x, 0) gave 'dog'. New model applied to that: model('dog') should also give 'dog'. If new model gives 'bird', L_ide penalizes the drift. This keeps the new model from scrambling the old solution.
Step 3: A cat image from Task 1 buffer is replayed. L_rep_ice pushes the model to still output 'cat', not 'fish'.
Total: Three losses compete. Tuning alpha and beta balances learning Task 2 while keeping Task 1 and staying stable.

The key is the distillation loss: it anchors the new model to the old model's stable representations, so weights cannot freely rewrite.

What can go wrong

What can go wrong

Hyperparameter mismatch. If alpha is too large, the model locks onto the old solution and refuses to learn anything new. If beta is too small, the model ignores the new task. Tuning is required per dataset.
Memory-limited edge case. On very small buffers (hundreds of examples), idempotence distillation has little data to anchor to, and the effect weakens. The paper shows idempotence works best with reasonable buffer sizes.
Task similarity cliff. If new tasks are radically different from old tasks, the old checkpoint's stable points may be irrelevant. Idempotence can then constraint learning too much, hurting new-task performance.
Done right. When buffer is large enough and tasks share some structure, IDER adds one forward pass per batch (cheap) and reliably preserves both accuracy and honest uncertainty across sequential tasks.
What a runnable demo should prove

What a runnable demo should prove

Build a continual learning experiment using CIFAR-10 or CIFAR-100 data: organize the data so the model encounters classes one at a time (first learn to recognize cats and dogs, then add birds and fish, then add planes and trucks). Implement naive replay (store old examples from earlier classes, replay them during new-class training) because this is what works best in practice. Then add IDER: compute penalties when feeding model outputs back through the system produces different results. Train for 10 sequential classes with a small buffer (100 examples per class). Measure final accuracy on all old classes and the calibration error (how often the model is confidently wrong).

forgetting = accuracy_task_1_before_task_2 - accuracy_task_1_after_task_5. reliability = expected_calibration_error (lower is better). demonstration = show forgetting is low and reliability is high simultaneously.

The demo must show that idempotence prevents the model from trading old-task accuracy for new-task accuracy, and that the model admits uncertainty when it should. The winning proof is a table of predictions on an old task showing the model correctly says 'I am unsure' rather than confidently guessing wrong.
