SOMA: Spatial Memory for Out-of-Vision Manipulation

A robot equipped with a movable camera builds and carries a persistent 3D memory of the scene, so it can manipulate objects it cannot currently see.

Paper explainersAll themesRobotics & Control

Robots controlled by vision-language-action models (systems that take images and text instructions and output robot commands) today assume they can always see their target objects. When the target is hidden or outside the camera view, the robot gets stuck. SOMA solves this by giving the robot a persistent spatial memory: before manipulation starts, the robot scans the scene with a movable head camera to build a 3D map of where everything is, then uses that map to reach for hidden objects and understand spatial relationships without looking.

Zero assumption version

The brittleness of sight-bound manipulation

Today's robot vision-language-action models process one camera frame at a time and forget everything as soon as they look away. The model receives an image and a text instruction (e.g. pick up the blue mug), looks only at what is visible in the current camera frame, and outputs a grasp command. This works perfectly when the target object is in view. But when the target is hidden behind something else, or on the other side of a table, or the camera is pointing the wrong way, the robot has no idea where it is. It has no memory of the scene layout.

A beginner might try to solve this by teaching the robot to rotate its head or look around before reaching. But that leads to endless reactive searching: the robot spins and lurches, wasting time, because it never builds a persistent record of what it has seen. Each new view is treated in isolation.

The problem in one sentence. The robot forgets the scene as soon as it looks away, so it cannot reason about objects outside its current field of view.

The algorithm as a flow

What it actually does

Scan the scene

Robot swings its head camera to capture multiple views, samples frames uniformly to balance coverage and speed.

Extract objects and positions

A network estimates where the camera is pointed and the rough 3D shape of objects. An object detector (YOLO) finds each object. A visual encoder (DINOv3) extracts semantic features (a list of numbers describing what each object looks like) for each object.

Build spatial memory

Aggregate all the 3D object positions and features into one unified memory table, a scene-level representation.

Match instruction to memory

When the manipulation instruction arrives (e.g. grasp the mug), the robot scores how relevant each part of the spatial memory is to the instruction (this scoring is called cross-attention: lining up the query from the instruction with regions of the stored memory), to find the mug's location.

Output action

The robot's action decoder, now informed by both the current view and the spatial memory, outputs a gripper command that reaches for the mug even if it is currently out of view.

What the paper changes

What the paper changes

The paper changes what the robot carries forward between the observation phase and the manipulation phase: instead of starting each manipulation step with only the current camera frame, the robot now carries a persistent 3D spatial memory (M0) that encodes the full scene layout.

The hidden quantity

The spatial-semantic map

measured quantity  =  Scene coverage and consistency

The hidden quantity this paper measures is whether the spatial memory actually maintains global consistency—i.e., whether the aggregated 3D positions and semantic features (lists of numbers describing visual properties) of all observed objects form a coherent, unified representation that does not contradict itself across different camera angles. The paper constructs this memory by stacking position estimates (where the camera is pointed and the bounding boxes around objects) and semantic features from a multi-view scan, then maintains consistency by aligning views through geometric constraints and scoring relevant regions.

The paper demonstrates consistency implicitly through task success: the robot's ability to grasp hidden objects without flailing proves that the memory is coherent enough to guide precise actions beyond the current view.

Why it works

Why remembering the scene unlocks out-of-view grasping

The mechanism has two parts: memory building and memory use. In the building phase, the robot does not try to control the gripper; it simply scans by moving its head, uniformly sampling frames from the scan video. Each frame is processed by three specialized networks in parallel: a network estimates where the camera is pointed and the rough 3D shape of the scene, an object detector finds each object and assigns it a category (mug, cup, bottle), and a semantic encoder extracts a feature vector (a list of numbers encoding the visual properties) for each object. All of these estimates—camera positions, 3D bounding boxes, feature lists—are then stacked into a single memory table M0. This is not an image; it is a table of labeled 3D positions and features.

In the manipulation phase, the robot receives a text instruction and a current camera frame. A language-vision module encodes the instruction into a feature vector (mug: ceramic, cylindrical, contains liquid). The robot then scores how relevant each part of the spatial memory is to the instruction (this relevance scoring is called cross-attention: aligning the query from the instruction with regions of memory) to pull out the features of the mug from M0. The action decoder receives both the current view features and the retrieved memory features, and outputs a gripper command. Because the memory includes the mug's 3D position even though the mug is not visible right now, the gripper can move directly to it without reactive searching.

Math after the picture

The cross-attention retrieval equation

First in words:

The instruction and perception tokens query the spatial memory. The output score for each memory region tells the robot how relevant it is to the task. High scores mean this region contains the target; low scores mean ignore it.

Then the compact form:

S = softmax( Q · M^T / sqrt(d) ) * M

Every symbol:

Qthe instruction-perception query (what we are looking for), a list of numbers
Mthe spatial memory matrix (all objects and positions), rows are observations
Sthe output scores for each memory region, sorted and normalized so they sum to 1
dthe dimension (number of numbers in each query and memory entry)
sqrt(d)scaling factor to keep score magnitudes reasonable
A tiny worked example
Suppose Q = 4 (a mug instruction encoded as 4 numbers: [ceramic, cylinder, warm, 0.3m-tall])
Suppose M has 3 rows: mug at (0.5, 0.1, 0.8), cup at (0.2, 0.3, 0.6), bottle at (0.7, 0.0, 0.5)
Compute Q · M^T: mug_score = 4.2, cup_score = 1.8, bottle_score = 2.1
Apply softmax: mug = exp(4.2)/(exp(4.2)+exp(1.8)+exp(2.1)) ≈ 0.65, cup ≈ 0.15, bottle ≈ 0.20
The robot learns: mug is 65% likely the target. Retrieve mug's 3D position from M. Gripper moves there.

The softmax step ensures the robot cannot accidentally activate multiple memory regions equally; the highest-scoring object dominates the action.

What can go wrong

What can go wrong

Memory initialization fails if the robot cannot move its head. SOMA requires a movable camera and a dedicated scanning phase. In constrained manipulation arms where the camera is fixed, or in fast reactive tasks where there is no time to scan, the method cannot build initial memory.
Position estimation errors accumulate across views. If the position-estimation network mis-estimates camera locations or 3D bounding boxes, the aggregated memory becomes incoherent. A mug marked at (0.5, 0.1) in one view and (0.8, 0.2) in another will cause the robot to reach to the wrong location.
Semantic ambiguity breaks relevance scoring. If the instruction is vague (grasp the object), or the feature encoder cannot distinguish similar-looking items, the relevance score will rank multiple memory regions equally and the robot may grasp the wrong thing.
Done right: frequent scanning and explicit object re-detection. SOMA mitigates these by using uniform frame sampling to balance coverage and speed, and by refining the memory over time if the scene changes (Dynamic Memory Refinement). The paper shows this approach works even in dual-arm scenarios.
What a runnable demo should prove

What a runnable demo should prove

Build a simple tabletop scene: place three objects (a mug, a cup, a block) on a table. Use a robot arm with a movable head camera. Run the SOMA scan phase to build the spatial memory. Then, without the robot moving the gripper, rotate the head to face away from the table (so no objects are visible in the current frame). Send the instruction grasp the mug. The robot should compute the mug's 3D position from memory, move its gripper directly to that location, and grasp successfully, without first turning its head back to look.

success_hidden_target = 1 if gripper reaches target within 0.1m without head reorientation else 0

The demo proves the robot is using the persistent spatial memory to locate and grasp the hidden mug, because it reaches accurately without reorienting its camera to look—a purely reactive system would fail.
