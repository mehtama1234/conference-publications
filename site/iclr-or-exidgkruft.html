One LLM Token for Graph Structure

Compress an entire graph structure into a single special token so the language model can reason about graphs as efficiently as text.

Paper explainersAll themesGraph & Geometric Learning

Language models can read text and answer questions, but when you give them graphs (networks of connected nodes), they struggle. Current approaches either describe the graph in words—which takes too many tokens and scatters the model's attention—or convert it to dense numbers that no longer align with how text tokens work. This paper proposes a single special token that holds the complete graph structure, encoded in a way that fits naturally into the language model's token vocabulary.

Zero assumption version

Why graphs break language models

Language models process text as a sequence of tokens—chunks of meaning. For graphs, you need to convey which nodes connect to which other nodes (the topology). A naive approach lists every edge in words: 'node A connects to node B, node B connects to node C...' This explodes the token count and drowns important structure in noise.

A smarter approach converts the graph to embeddings—dense lists of numbers—and injects them as 'soft prompts' before the model sees real text. But here's the problem: text tokens live in a discrete space (the vocabulary of real words), while embeddings are floating-point numbers in a different mathematical space. The mismatch means the model treats them like foreigners speaking a different language, and structure knowledge barely transfers to text reasoning.

The core insight. Instead of describing the graph in words or converting it to foreign numbers, create one special token that sits in the same vocabulary as text, and train it to hold the entire graph structure.

The algorithm as a flow

What it actually does

Extract pure topology

Strip away attributes and focus only on which nodes connect to which.

Encode with a graph neural network

Gather each node's neighborhood info (who is 1 hop away, 2 hops away, etc.); sum it up.

Match to discrete codebook

The encoded graph has a numerical fingerprint; find the closest entry in a lookup table of discrete token meanings.

Reconstruct as a sanity check

Can we rebuild the original edges from the codebook token? Use reconstruction loss to make sure information wasn't lost.

Align with text tokens

Train the model on hybrid Q&A pairs so it learns: this special token reliably means this structure.

What the paper changes

What the paper moves

The paper does not change the language model itself. Instead, it adds a new token to the vocabulary—a special discrete token that the model encounters in its input. Every time a graph appears, that graph gets summarized into exactly this one new token, sitting alongside the regular text tokens the model already knows.

the object it moves  =  Graph representation object: a discrete structural token
The hidden quantity

The structural fingerprint

measured quantity  =  Topology-to-codebook match strength

The paper measures a hidden quantity: how well the chosen codebook entry (the discrete token) preserves the original graph topology. When the GNN encodes a graph into a continuous embedding, the paper does not use that embedding directly. Instead, it finds the nearest codebook entry—a pre-learned 'token meaning' in a discrete lookup table. The better the match, the less information is lost, because the chosen codebook entry was trained to capture exactly the patterns present in the true edges, so if the encoding closely matches a codebook entry, that entry will reliably decode to the true structure. When match is poor, the token must stand in for something it was not designed for, and reconstruction fails.

The paper estimates this via reconstruction loss. After picking a codebook entry, it decodes back to predict all the edges in the original graph. If the predictions match the true edges well, the chosen token was a good summary; if edges are missing or wrong, the token was a poor fit. Over time, training adjusts the codebook entries themselves so that each one captures a distinct pattern of how nodes are arranged.

Why it works

Why it works: the causal chain

The method works because it solves both problems at once. First, it avoids exploding token counts: one graph becomes one token, not dozens. Second, it stays in the model's native vocabulary space: the structural token is discrete, from the same codebook that generates every other token the model sees. The model learns to reason about graphs using the same neural machinery it uses for text because the structural token participates in attention (how the model focuses on relevant parts) and embedding lookups (how words turn into numbers) exactly like any text token would—same layer weights, same function that converts scores into probabilities, same adjustment direction during learning. When the model sees the structural token and a text token side by side, the same numerical computations process both, so structure knowledge and text knowledge blend naturally instead of living in separate, incompatible spaces.

The encoding step (GNN + quantization + reconstruction) ensures the chosen token is honest: it genuinely summarizes the topology. A GNN collects each node's local context (who is nearby), then vector quantization forces that context into a discrete package. The reconstruction loss then audits the choice: if you truly understood the graph structure, you should be able to rebuild the edges. This feedback tightens the token meanings over time. Finally, hybrid Q&A training (asking questions about graphs, with the special token in the prompt) teaches the model that this structural token predicts task-relevant features. The token becomes useful because it was forced to be accurate and because the model practiced using it.

The loss function that trains the token

First in words:

Total loss is the sum of three parts: reconstruction loss (how well can we rebuild the edges from the codebook token), update loss (how close the encoded embedding is to the chosen codebook entry), and commitment loss (how much the codebook entry should move toward the encoded embedding), weighted by a tuning factor beta.

Then the compact form:

L = ||A - A_hat||_F^2 + ||sg[H_s] - z_e(H_s)||_2^2 + beta * ||H_s - sg[z_e(H_s)]||_2^2

Every symbol:

Athe original adjacency matrix (which edges exist in the true graph)
A_hatthe reconstructed adjacency matrix (edges predicted from the codebook token)
||X||_FFrobenius norm; a way to measure the overall size of a matrix
H_sthe graph encoding (the list of numbers the GNN produces for all nodes)
z_e(H_s)the codebook entry picked by vector quantization (the 'token meaning')
sg[X]stop-gradient: treat this value as a constant, not something to train
betaa weighting knob that controls how much the codebook should adapt versus the encoding
A tiny worked example
Suppose a small graph has true edges: (1-2), (2-3), (1-3). The edge table (listing which pairs connect) has three entries.
The GNN encodes it as H_s = [0.8, 1.2, 0.9, 1.1]. The nearest codebook entry is z_e(H_s) = [0.7, 1.0, 1.0, 0.9].
Reconstruction loss: predicted edges (1-2), (2-3), only two of three. ||A - A_hat||_F^2 = sqrt((0-0)^2 + (1-1)^2 + (1-0)^2) = 1.0.
Update loss: how far encoding is from codebook. ||(sg[0.8, 1.2, 0.9, 1.1] - (0.7, 1.0, 1.0, 0.9))||_2^2 = (0.1)^2 + (0.2)^2 + (0.1)^2 + (0.2)^2 = 0.10.
Commitment loss (beta=0.25): how much codebook should adjust. 0.25 * ||(0.8, 1.2, 0.9, 1.1 - sg[0.7, 1.0, 1.0, 0.9])||_2^2 = 0.25 * 0.10 = 0.025.
Total L = 1.0 + 0.10 + 0.025 = 1.125. Training reduces this by improving the codebook entry or the encoding itself.

The three loss terms compete: reconstruction loss pushes the codebook to hold true structure, while update and commitment losses smooth out the encoder and codebook so the quantization is efficient.

What can go wrong

What can go wrong

Codebook collapse. If all graphs map to the same codebook entry, the token becomes meaningless. The reconstruction loss must be strong enough to separate different topologies into different codebook entries. If beta (the commitment weighting) is too high, the codebook entries stop moving, and new structures cannot be encoded.
Information loss from quantization. Not every graph topology has a perfect codebook match. Some structure will be lost when rounding to the nearest entry. Graphs with unusual patterns (very dense, very sparse, or unique motifs) may not align well with pre-learned codebook entries.
Training instability with hybrid Q&A. The model must learn two things at once: what the new token means, and how to use it for the downstream task. If Q&A examples are too sparse or not representative of the tokenizer's output, the model may ignore the structural token and rely only on text.
Done right. Carefully tune the reconstruction loss weight and the commitment beta. Use diverse Q&A pairs covering many graph types. Monitor codebook usage to ensure all entries are learned, not just a few. Validate that structural information actually transfers to the task (ablate by removing the structural token and measuring drop).
What a runnable demo should prove

What a runnable demo should prove

Build a small benchmark: five different graph types (a star, a cycle, a tree, a random graph, a dense clique). For each, train the structural tokenizer on three graphs of that type, then test whether the reconstruction loss is lowest for the correct graph structure and higher for mismatched ones. Show a grid of results: can the model tell a star from a clique? Measure reconstruction accuracy per codebook entry. Next, train a language model on hybrid Q&A: 'Does this graph [SOG_k] have any triangles? Yes/No.' Use the graphs and their true labels. Report: (1) reconstruction accuracy of the tokenizer, (2) Q&A accuracy on the language model, and (3) ablation—Q&A accuracy when you remove the structural token and give only text descriptions. The delta proves the token carries real structure.

reconstruction_accuracy = (edges_correctly_predicted) / (total_edges); qa_accuracy = (correct_predictions) / (total_qa_examples); structural_contribution = qa_accuracy_with_token - qa_accuracy_without_token

If reconstruction accuracy is >85% and structural contribution is >10 percentage points, the token is learning real structure and the model is using it.
