Adaptive Hopfield Network: Rethinking Similarities in Associative Memory

Instead of asking which stored pattern sits closest to the query, A-Hop asks which stored pattern is most likely to have produced the query after corruption.

Paper explainersAll themesOther

Associative memory stores patterns so you can recover the right one from a partial or damaged query. Older Hopfield-style systems judge retrieval by closeness, but closeness can pick the wrong source when two stored patterns are damaged in different ways. This paper changes the scoring rule. It learns a context-dependent score for each stored pattern that estimates which one most likely produced the query. Retrieval becomes more correct because the score is trained on the kinds of corruption the system actually sees, such as noise, masking, or systematic bias.

Zero assumption version

Closest is not always correct

An associative memory stores several patterns and later receives a query that may be incomplete or corrupted. The job is to return the stored pattern that originally gave rise to that query. Traditional retrieval rules compare the query to each stored pattern and choose the one that looks nearest under a fixed similarity rule.

That sounds reasonable, but it breaks when corruption is not uniform. A masked query may lose some positions entirely. A biased query may shift certain values more than others. Under those conditions, the nearest stored pattern is not always the true source, because the corruption process changes what 'close' should mean from one context to another.

The failure mode. Fixed similarity can return the wrong memory because it ignores how the query was corrupted.

The algorithm as a flow

What it actually does

Store patterns

Keep a bank of memory patterns that can later be retrieved from damaged queries.

Model likely corruptions

Describe how a clean stored pattern could turn into the observed query, including noise, missing pieces, or systematic shifts.

Learn adaptive similarity

Train a score that estimates how likely each stored pattern is to be the query's source under those corruptions.

Score every stored pattern

For the incoming query, compute one learned source-likelihood score per stored pattern.

Retrieve the top source

Return the stored pattern with the highest learned source score.

What the paper changes

What the paper changes

The paper changes the similarity rule inside associative memory. Instead of one fixed closeness rule shared by every query, it uses a learned score that adapts to the corruption process seen in the current setting.

the object it moves  =  the retrieval score
The hidden quantity

The hidden quantity: source likelihood

measured quantity  =  how likely each stored pattern is to be the query's origin

The paper says retrieval should track source likelihood, not raw closeness. For each stored pattern, ask: if this pattern were the clean origin, how plausible is the observed query after the usual corruption process? That quantity is hidden because you never observe the clean origin directly; you only see the damaged query.

The method estimates this quantity by learning from examples sampled under the corruption process. If a certain kind of missing entry or shift often comes from one stored pattern and rarely from another, the learned score captures that difference. Retrieval improves because the score is trained to follow the origin of the query, not merely its surface similarity.

Why it works

Why learning the source score fixes retrieval

A fixed similarity rule assumes the same distortions matter in the same way for every query. That assumption is too rigid. If the corruption is masking, missing positions should carry less weight. If the corruption is biased, some shifts should be expected rather than treated as evidence against a stored pattern.

A-Hop learns the score from context samples that show how clean memories turn into queries in practice. That training teaches the network which differences should matter and which should be discounted. The result is better retrieval because the scoring rule matches the data-generating process instead of pretending every query was damaged in the same generic way.

The paper also proves correctness for three common corruption families. Under noisy, masked, and biased variants, the learned adaptive score reaches the optimal retrieval rule because it approximates the actual source likelihood that defines correct retrieval.

Math after the picture

The retrieval equation

First in words:

Choose the stored pattern with the largest source probability after observing the query.

Then the compact form:

m_hat = argmax_m P(m | q)

Every symbol:

m_hatthe retrieved stored pattern
mone candidate stored pattern from the memory bank
qthe observed query
P(m | q)probability that stored pattern m is the source of query q
A tiny worked example
Suppose the memory bank has two candidates, A and B.
The query has two missing entries and one shifted value.
Under the learned corruption model, P(A | q) = 0.82 and P(B | q) = 0.18.
A-Hop retrieves A because 0.82 is larger than 0.18.
A fixed nearest-neighbor rule could still pick B if B happened to sit closer under a rigid distance rule, which is exactly the mistake this paper avoids.

The paper's central claim is that correct retrieval follows source probability, because that quantity directly answers which stored pattern generated the query.

What can go wrong

What can go wrong

Wrong corruption model. If training examples do not match the corruptions seen at test time, the learned score estimates the wrong source process, so retrieval can still fail.
Too little context data. Adaptive similarity needs examples of how queries are formed. With too few examples, the score can overfit noise instead of learning the real source rule.
Nearly indistinguishable stored patterns. If two stored patterns truly produce almost the same range of possible queries, even the optimal rule will remain uncertain because the evidence in the query is weak.
Done right. When the training corruptions match deployment and the stored patterns are clearly distinct, adaptive similarity improves retrieval because it scores origins rather than mere closeness.
What a runnable demo should prove

What a runnable demo should prove

Build a memory bank of 100 stored patterns. Corrupt each one with three processes: additive noise, random masking, and a systematic shift on selected positions. Train one retrieval rule using fixed closeness and one using adaptive similarity. Then measure how often each method returns the true source on held-out corrupted queries.

retrieval_accuracy = correct_retrievals / total_queries

The demo should show that adaptive similarity wins when the corruption process matters, because the learned score tracks which stored pattern actually generated the query.
