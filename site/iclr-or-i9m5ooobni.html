Universal Properties of Activation Sparsity in Modern LLMs

Modern language models waste computation on near-zero values inside their feedforward layers, and this waste grows more fixable as models scale.

Paper explainersAll themesLLMs & Foundation Models

Inside a language model, feedforward layers do multiplication on every word (just a list of numbers representing that word). Most of the results are tiny numbers close to zero and never influence the output because in a weighted sum, only large numbers move the final answer. This work measures how many of those near-zero values can be safely skipped without breaking the model's answers, and finds that this opportunity grows stronger in bigger models—because larger models learn to pack important information into fewer numbers and treat the rest as expendable.

Zero assumption version

Feedforward layers multiply everything, even the tiny numbers

A language model reads one word at a time and runs it through layers of math. Each layer multiplies the incoming numbers by weights (learned numbers that encode knowledge) and then runs the result through a feedforward sublayer.

A feedforward sublayer is simple: multiply incoming values by a table of learned weights (a rectangular array of numbers), apply an activation function like ReLU (which sets negative numbers to zero), then multiply by another table of weights. The catch: every single number gets multiplied, even if the intermediate result is near-zero and has almost no effect on the output. Skipping the near-zero numbers would save computation, but older models with ReLU (which produce exact zeros) let people identify and skip them with confidence. Modern language models use smoother activation functions (like GELU or SwiGLU gates) that never hit zero exactly, so the near-zero values are harder to spot and skip.

The paper's move. Measure how many near-zero values modern language models tolerate being skipped using a simple threshold rule, without retraining the model.

The algorithm as a flow

What it actually does

Identify near-zero activations

Look at all intermediate values flowing through a feedforward layer.

Apply top-p threshold

Keep only values whose magnitudes sum to at least a fraction p of the layer's total size.

Zero out the rest

Set all other values to zero and skip their downstream multiplications.

Measure accuracy drop

Test the model on tasks; record how much performance degrades at each sparsity level.

Compare across model sizes

Repeat for small, medium, and large model versions of the same architecture.

What the paper changes

What the paper changes

The paper changes which intermediate values flow onward in the feedforward layers. Instead of using every single computed value, it zeros out the smallest-magnitude numbers and only passes the important ones to the next multiplication step.

the object it moves  =  intermediate activation values
The hidden quantity

Critical sparsity: how many near-zeros can you drop?

measured quantity  =  critical sparsity

Critical sparsity is the highest fraction of near-zero values you can skip in a feedforward layer without losing more than a small amount of model accuracy (a threshold like 1% degradation). It is a single number, measured in percent, that tells you how much computational waste exists in that layer and model size.

The paper estimates critical sparsity by running the model through a test set at different threshold levels. For each level (keep top 50%, top 60%, top 70%, etc.), it records the accuracy. The critical level is where accuracy still stays nearly flat; beyond that, performance starts to drop sharply.

Why it works

Why skipping near-zeros doesn't break the model

Feedforward layers compute weighted sums of the input (add together numbers after multiplying each by a learned weight). In a weighted sum, only large values change the output noticeably; tiny values are drowned out by the big ones. If a number is close to zero, multiplying it by a weight and adding to the sum contributes almost nothing to the final result.

Modern language models learn to concentrate important information into a few numbers per layer and scatter noise into many others. During training, the model discovers that it can be efficient by making most intermediate values small and letting a few carry the signal. Skipping the small ones is like deleting noise from a photograph before printing: the important pixels (the large activations) still carry the message, and removing noise doesn't blur the picture.

As models grow larger, they become better at this efficient sparse representation because they have more capacity and training examples to discover which values are redundant. Bigger models learn to pack important information into even fewer numbers and spread the waste over more near-zeros during training. This is why critical sparsity tolerance rises with model size: the model has already learned to treat most intermediate values as expendable, so skipping them does not erase any information that actually matters to the output.

Math after the picture

The top-p sparsification rule

First in words:

For each intermediate activation vector, identify the subset of values whose absolute magnitudes sum to at least a fraction p of the vector's total L1 norm (the sum of all absolute values). Set all other values to zero.

Then the compact form:

mask_p[i] = 1 if cumsum(sorted_abs_values) >= p * L1_norm, else 0; output = activation_vector * mask_p

Every symbol:

activation_vectorthe raw intermediate numbers from the activation function
L1_normsum of absolute values of all numbers in the vector
pthe target fraction (0 to 1); higher p means keep more values
sorted_abs_valuesmagnitudes sorted from largest to smallest
mask_pbinary indicator: 1 for kept values, 0 for zeroed values
cumsumcumulative sum as you go through sorted values
A tiny worked example
Suppose an intermediate vector is [8, 0.3, 0.2, -7, 0.5, -0.1] and we want p = 0.8 (keep top 80% of L1 norm).
L1 norm = |8| + |0.3| + |0.2| + |-7| + |0.5| + |-0.1| = 8 + 0.3 + 0.2 + 7 + 0.5 + 0.1 = 16.1
Target sum = 0.8 * 16.1 = 12.88
Sorted by magnitude: [8, 7, 0.5, 0.3, 0.2, 0.1]
Cumulative: 8 (total 8), then 8+7=15 (exceeds 12.88 after second value).
Keep indices for 8 and 7 (and anything tied at 7); zero out 0.5, 0.3, 0.2, 0.1.
Result: [8, 0, 0, -7, 0, 0] (73% of the vector's numbers were zeroed; 87% of L1 norm is preserved).

The threshold keeps the biggest-impact numbers and discards the small noise, because in a linear combination, magnitude is what matters to the final sum.

What can go wrong

What can go wrong

Middle layers are fragile. Early and late feedforward layers can tolerate high sparsity, but middle layers of the network often need most of their values. Applying the same sparsity threshold to all layers wastes the opportunity to skip middle-layer near-zeros selectively.
Reasoning models behave differently. Language models trained for chain-of-thought reasoning output longer sequences. When activations are sparsified too aggressively, the model's thinking becomes jumbled and it hits length limits mid-thought, causing accuracy to collapse even if the base mechanism remains intact.
Threshold selection requires measurement. The top-p rule depends on choosing the right p value for each task and model. If you set p too low, you skip critical information; too high, you gain nothing. The paper does not provide a formula to pick p ahead of time.
Done right: per-layer adaptive thresholds work. The paper shows that layer-wise monitoring of sparsity tolerance is the practical path: measure critical sparsity separately for early, middle, and late layers, then apply different thresholds per layer group.
What a runnable demo should prove

What a runnable demo should prove

Take any language model (Gemma, Qwen, Llama). Run it on a benchmark like MMLU or GSM8K without modification (baseline). Then apply top-p thresholds to its feedforward layers at different levels (keep top 60%, 70%, 80%, 90%, 100%). Measure accuracy at each level. Plot accuracy versus sparsity.

critical_sparsity = highest percentage of values that can be dropped while losing less than 1% accuracy

The demo must show that larger model versions tolerate higher sparsity at the same threshold, proving that scale amplifies the sparse-representation opportunity.
