Analytica: Soft Propositional Reasoning for Robust Analysis

Break complex analysis into a tree of small true-or-false questions, have specialized tools answer each one, then combine those answers carefully to reach a final conclusion.

Paper explainersAll themesAgents & Tool Use

When an AI agent is asked to forecast the stock market or predict political events, it needs to answer dozens of smaller yes-or-no questions along the way. Today, if the agent gets one of those wrong by a little bit, the whole analysis fails. Analytica fixes this by treating every intermediate question as something that can be partly true, then using math to combine those partial answers in a way that does not amplify mistakes.

Zero assumption version

Why agent reasoning falls apart

Today, AI agents that do real-world analysis (like forecasting or research discovery) make two kinds of mistakes. First, they have systematic blind spots — they miss important information or misunderstand a piece of data — and second, they are inconsistent — the same question answered twice gives slightly different answers. When you add many answers together to reach a final conclusion, both mistakes pile up. A beginner would try to have one agent answer the full question end-to-end, but that does not work because the agent either misses context or gets lost halfway through. The paper calls this problem a lack of verifiable, compositional structure.

These mistakes have real cost: when an agent is 5% wrong on twenty different sub-questions, the final answer becomes garbage.

The problem in one sentence. Agent reasoning lacks a way to track and reduce the two types of mistakes — systematic error and randomness — that compound when many questions are chained together.

The algorithm as a flow

What it actually does

Decompose

Split the big question into a tree of smaller yes-or-no propositions.

Ground each leaf

Send each sub-question to a specialized tool (a data-search agent, a Jupyter code runner, a deep researcher) to answer with evidence.

Score facts

Assign each answer a confidence score — not just yes or no, but a fraction between 0 and 1.

Synthesize up

Use math that ignores outliers to combine child scores into a parent score, averaging without amplifying guesses.

Repeat recursively

Work up the tree until the root proposition has a final, stable answer.

What the paper changes

What changes

The paper changes how an agent combines many partial answers into a final decision. Instead of having one agent write out a chain of reasoning that can drift, Analytica uses math that does not get fooled by wild outliers to merge the scores.

the object it moves  =  the method for combining answers
The hidden quantity

Bias and variance: the two sources of error

measured quantity  =  bias (systematic error) and variance (randomness)

Every answer the agent gives has two kinds of wrong built in. Bias is a systematic blind spot: the agent is always too high or always too low on a particular question. Variance is randomness: the same question gives slightly different answers each time. Both hurt the final conclusion, but they need different fixes.

Analytica estimates and reduces both. It measures bias by seeing if the agent's scores drift in one direction (e.g., always guessing too high). It measures variance by seeing how much the answers bounce around. The paper's core contribution is a divide-and-conquer framework that attacks both simultaneously.

Why it works

Why it works: the three moves

Analytica works by making three concrete moves. First, it reframes the problem. Instead of asking the agent for a narrative explanation (which can ramble), it asks: what is your confidence that this specific claim is true, on a scale from 0 to 1? This turns a fuzzy question into a number.

Second, it divides the work. One agent cannot be good at both high-level reasoning and low-level fact-checking; they distract each other. Analytica sends each sub-question to a specialist tool (a search agent for context, a Jupyter environment for data, a researcher for deep reading). Each specialist has a narrow job and can be audited.

Third, it combines carefully. When you add many uncertain numbers together, the randomness adds up. There is a math tool that combines numbers in a way that ignores wild outliers (one absurd guess does not wreck the final answer). By using this instead of simple averaging, Analytica gets a final answer that is simultaneously less biased and less noisy.

The formula and how it works

First in words:

Final answer is a weighted sum of sub-scores, where each sub-score is weighted by how much noise that sub-question has. High-noise questions get less weight.

Then the compact form:

answer = sum_i w_i * score_i, where w_i = 1 / variance_i, and sum_i w_i = 1

Every symbol:

score_iconfidence from sub-question i, a number from 0 to 1
variance_ihow much that sub-question's answers bounce around
w_iweight for that sub-question (high for reliable, low for noisy)
answerfinal forecast, from 0 to 1
A tiny worked example
Suppose you have three sub-questions with scores and noise:
Sub-q1: score=0.7, variance=0.01 -> weight = 1 / 0.01 = 100
Sub-q2: score=0.6, variance=0.04 -> weight = 1 / 0.04 = 25
Sub-q3: score=0.8, variance=0.04 -> weight = 1 / 0.04 = 25
Sum of weights: 100 + 25 + 25 = 150
Normalize: w1=100/150=0.67, w2=25/150=0.17, w3=25/150=0.17
Final answer: 0.67*0.7 + 0.17*0.6 + 0.17*0.8 = 0.469 + 0.102 + 0.136 = 0.707
Sub-q1 (stable, low noise) pushed the final answer upward more than the others.

The formula gives high weight to answers that are consistent (low variance) and low weight to answers that bounce around, automatically building a trustworthy final forecast.

What can go wrong

What can go wrong

Propositions are too large. If you split the problem into ten huge sub-questions instead of fifty small ones, each sub-question is still hard and the benefit fades. Analytica needs fine-grained decomposition to work.
A tool gives wrong answers repeatedly. If the search agent is biased (e.g., always finds sources that agree with a narrative), that bias flows into the tree. Analytica cannot fix a tool that is systematically wrong; it can only reduce noise from good tools.
The tree structure is nonsensical. If the propositions do not logically compose to the root question, the final answer is meaningless. Analytica's math is sound, but garbage decomposition gives garbage results.
Done right. When propositions are well-chosen (small, independent, each answerable by a tool), and tools are unbiased, Analytica produces a forecast that is both accurate and stable.
What a runnable demo should prove

What a runnable demo should prove

To see Analytica in action, build a small forecasting game. Pick a real event with a known outcome (e.g., a historical election, a past earnings report). Decompose it into five to ten factual sub-questions (e.g., what was unemployment in Q3, did commodity prices rise). Have a simple tool (such as a search agent or a database) answer each one with a confidence score. Run Analytica's synthesis math on the scores. Then repeat the whole thing five times (to measure variance) and see if the final answer is more stable than a naive agent's.

stability = 1 - (max_run_answer - min_run_answer), measured across 5 independent runs; also compare to naive agent's stability on the same task

The demo must show that Analytica gives nearly identical answers every time it runs on the same decomposed problem, while a naive agent gives different answers each time.
