Look-ahead Reasoning with a Learned Model in Imperfect Information Games

A method that learns a shrunk version of a hidden-state game so a pre-trained player can search ahead by reasoning over fewer possibilities at test time.

Paper explainersAll themesReinforcement Learning

In games like poker where players cannot see each other's cards, two problems collide: first, thinking ahead requires imagining every possible hidden state the opponent might have; second, that list explodes in size and becomes unsearchable. This paper learns a compact abstraction—a reduced model that groups similar-looking situations together—so that at test time, a player can perform look-ahead reasoning (think several moves forward) without the full explosion. The method is called LAMIR.

Zero assumption version

The search explosion in hidden-state games

In perfect information games (like chess, where both players see the board), search algorithms like MCTS explore a tree of possible futures by simulating moves. MuZero learned a model of such games and used it to search ahead, greatly improving play.

But in imperfect information games (like poker, where you do not know the opponent's cards), search is fundamentally different. At each decision point, you must reason over all possible hidden states—all cards the opponent might hold, all moves they might have made—that are consistent with what you have observed. This set of possible states is called an information set. In large games, the number of relevant information sets explodes, and searching over all of them becomes computationally impossible. A beginner would naively try to search by exploring every information set, but runs out of memory or time.

In one sentence. LAMIR learns an abstracted game model that clusters information sets into a smaller number of groups, so test-time search becomes tractable.

The algorithm as a flow

What it actually does

Step 1: Train an abstraction model

From game trajectories, learn a function that maps each information set to one of K abstract clusters.

Step 2: Train a dynamics model on the abstraction

Learn what the next abstract cluster will be given the current cluster and actions by both players.

Step 3: Train a legal-actions function

Learn which actions are legal in each abstract cluster (necessary for tree construction).

Step 4: At test time, build a depth-limited tree

Using the trained abstraction and dynamics, construct a game tree over abstract clusters only.

Step 5: Search for the best action

Use standard game-tree search (reasoning that both players choose their best moves) to find the strongest next action.

What the paper changes

What the paper changes

Instead of reasoning over the full explosion of hidden states, the algorithm learns and uses a compressed representation: a clustering of information sets into a much smaller number of abstract groups.

the object it moves  =  Information set clustering
The hidden quantity

The abstract information set

measured quantity  =  Abstract cluster assignment

An abstract information set is a group of real information sets that the learned model has clustered together. In other words, if the player observes several different combinations of hidden cards (several different real information sets), the model may map many of them to the same abstract cluster. This clustering is what makes the search space shrink.

The paper estimates this clustering by training a soft assignment function (similar to fuzzy clustering from statistics) on sampled game trajectories. For each real information set encountered during play, the function outputs a probability (a number between 0 and 1 for each abstract cluster), and the player uses the cluster with the highest probability. The clustering is learned jointly with the dynamics model via a loss that encourages it to match the underlying game structure: when two real information sets belong to the same abstract cluster, they should lead to similar futures.

Why it works

Why it works: reasoning over a shrunk game

The core idea is a reduction. In a game with millions of information sets, search over all of them is impossible. But if you can map those millions down to, say, 10 abstract clusters, then at test time you can build a game tree over only those 10 clusters. The tree is exponentially smaller.

How does the clustering preserve game reasoning? When the model clusters similar information sets together, it is encoding that from the perspective of sound game reasoning, these situations are similar enough. This works because the clustering is trained on real game trajectories: the model learns to group information sets that lead to similar future payoffs, so reasoning over the abstract clusters still captures the essential structure of the game.

At test time, the player constructs a shallow tree over abstract clusters (using the learned dynamics function to predict the next abstract cluster given actions), then uses standard equilibrium-finding reasoning (iterating over both players' moves and computing mutual best responses) to select the best move. The search is now tractable because the tree is tiny.

The clustering and training objective

First in words:

Loss equals: information set clustering loss + soft regularizer + dynamics prediction loss + legal actions loss. The clustering loss is the cross-entropy between the model's predicted probability over abstract clusters and the one-hot vector of the nearest ground-truth cluster.

Then the compact form:

L_total = L_clustering + L_regularizer + L_dynamics + L_legal

Every symbol:

L_clusteringCross-entropy loss measuring how well the learned assignment predicts the true abstract cluster
L_regularizerSoft clustering penalty (fuzzy c-means style) encouraging similar information sets to map to the same cluster
L_dynamicsLoss for predicting the next abstract cluster given current cluster and actions by both players
L_legalLoss for predicting which actions are legal in each abstract cluster
Tiny worked example: clustering two information sets
Information set A has 50 real card configurations; information set B has 48 card configurations.
The learned clustering function assigns A with 90% confidence to abstract cluster 1 and B with 85% confidence to abstract cluster 1.
At training time, we compute: cross-entropy loss for A moving to cluster-1 = -log(0.90) ≈ 0.105; same for B = -log(0.85) ≈ 0.163. Total clustering loss for this batch ≈ 0.268.
The regularizer adds a penalty if many information sets map to the same cluster (to avoid trivial solutions). Together, the model learns to group truly similar states and spread dissimilar ones.

The loss pulls the model to group information sets that belong to the same abstract cluster and to correctly predict future clusters and legal moves during tree search.

What can go wrong

What can go wrong

Poor abstraction learned. If the clustering function fails to separate distinct situations (e.g., only one cluster is learned, collapsing all information sets), the abstract tree provides no reduction in size and search remains computationally intractable.
Insufficient model capacity. If the learned dynamics or legal-actions functions are inaccurate, predictions about the next abstract cluster will be wrong, leading to poor decisions at search time. Training requires enough data and network capacity to fit the abstraction.
Search depth too shallow. Even with a small abstract tree, if the depth limit is set too low, the player cannot plan far enough ahead. If too high, search becomes slow. The right balance is problem-dependent.
Game structure not captured. In some games, the learned abstraction may group information sets that should be separate. If the network has limited capacity, it cannot fit all the detail of the real game. The trade-off: limited capacity trades off precision for a smaller tree that is actually searchable, producing a useful approximation even if not a perfect model.
Done right. With sufficient model capacity and training data, LAMIR learns the true underlying game structure exactly (as shown in small-game experiments), and even with limited capacity, it extracts a valuable abstraction that beats the base policy in large games.
What a runnable demo should prove

What a runnable demo should prove

Build a simple imperfect information game (e.g., a card game with hidden opponent hands, or a simplified variant of Kuhn poker). Train LAMIR on a sample of self-play trajectories. At test time, run the learned model with tree search against the base policy and measure the win rate. Show that as the number of abstract clusters grows, win rate improves, because each additional cluster lets the model represent more distinct situations from the game, which makes tree search consider a larger set of strategic possibilities and compute stronger moves. Show that even with a small number of clusters, the learned abstraction beats the untrained base policy.
