Dual Goal Representations

Instead of encoding goals as raw states, encode them as the time-distance to reach every other state in the world.

Paper explainersAll themesReinforcement Learning

When a robot learns to reach goals, it usually remembers goals as pixel images or position vectors. But those representations are fragile—they break when the robot moves to a new room or the camera angle changes. This paper proposes a radically different idea: encode a goal not as what it looks like, but as how long it takes to reach from every other place in the environment. This time-distance signature stays the same no matter what the goal looks like or how the robot's sensors change, and it contains exactly the information the robot needs to plan.

Zero assumption version

Goal representations that don't travel

In goal-conditioned reinforcement learning, an agent learns to reach any target state from any starting point. The usual approach: train a policy that takes two inputs—the current state and the goal state—and outputs an action. But the goal is encoded using the same representation as the current state (pixels, joint angles, etc.). This creates a fragility: if you move the robot to a new room, or the lighting changes, that goal representation stops being useful. A goal that was a sharp image of the red cup is now a blurry image of the red cup, and the policy gets confused.

A beginner might try to make the goal representation more abstract—say, by learning a latent embedding through a neural network. But if the agent only sees offline data (collected trajectories with no new interactions), the embedding will still overfit to the specifics of that data. When you swap in a new robot or environment, the embedding collapses.

The insight. A goal's meaning is not what it looks like; it is how long it takes to reach from everywhere else.

The algorithm as a flow

What it actually does

1. Take offline data

Past episodes showing the robot reaching multiple different goals.

2. Train a value function

Learn to predict: from state s, how many steps to reach goal g?

3. Extract the goal embedding

Take the value function's internal goal representation (the part that encodes g).

4. Freeze it as the goal code

Use this embedding in place of the raw goal state for all future policy training.

5. Train any downstream policy

Feed the robot's state and the dual goal code into any standard offline RL algorithm.

What the paper changes

What changes

The paper changes how goals are represented. Instead of encoding a goal as its raw appearance or position, it encodes a goal as a learned vector (a list of numbers) that was trained to capture the time-distance from every state to that goal.

the object it moves  =  Goal representation
The hidden quantity

The time-distance signature

measured quantity  =  Temporal distance to goal

This is a single number: starting from state s, how many steps on average does it take to reach goal g in the optimal policy? It is an invisible quantity—you never directly see it—but it reveals the true structure of the environment's dynamics. Unlike the goal's appearance, this number is invariant (stays the same) no matter what robot body you use or what the lighting is.

The paper estimates this quantity by training a value function—a neural network that learns to predict the temporal distance from any state-goal pair. The value function takes two inputs (current state and goal), and outputs a number representing steps-to-goal. Once trained, the goal part of the network (called the goal embedding) becomes the dual goal representation.

Paper reading. The temporal distance function d(s, g) is the discounted cumulative cost in the optimal policy. Why it works

Why this works: structure through contrast

The key is that temporal distance depends only on the environment's dynamics (the rules of how the world moves), not on the appearance of states. The same goal in two different rooms has the same time-distances (because the robot takes the same number of steps). So when you train a value function on offline data, it learns to extract this intrinsic structure.

More deeply: a value function V(s, g) predicts steps-to-goal. To make that prediction, it must decompose the input into two parts: something about the current state s (where am I?) and something about the goal g (how far away is it from typical starting points?). The goal part—the embedding φ(g)—becomes a learned signature that captures which states are reachable in how many steps. This signature survives changes to appearance because it throws away visual details and only keeps the relational structure. When noise corrupts an observation (wrong pixel, shifted sensor reading), the time-distances remain the same, so the policy still knows how to act.

The value function learning rule

First in words:

The value function is trained to minimize the gap between predicted steps and actual steps in the offline data, using an expectile loss (a loss function that is more flexible about overfitting to outliers than squared error).

Then the compact form:

loss = expectile_loss(V_target(s, g) - V_predicted(s, g))

Every symbol:

V_target(s, g)The actual time-to-goal from state s to goal g, observed in the offline data
V_predicted(s, g)What the network's value function predicts
expectile_lossA loss function that penalizes error smoothly, avoiding overconfidence on outliers
φ(g)The extracted goal embedding, the dual goal representation
A tiny worked example
Suppose in the offline data, from state A it took 5 steps to reach goal G.
The value function predicts: V_predicted(A, G) = 4 steps.
Error = 5 - 4 = 1 step. Expectile loss: roughly 1.0 (the penalty grows with error magnitude).
The network updates its internal goal embedding φ(G) to make the prediction closer to 5.
Later, from a different state B, the data shows 3 steps to G. The embedding φ(G) must now predict correctly from B as well.
The embedding learns a shared signature that works across all starting states.

The goal embedding φ(g) is the part of the value function that depends on the goal; once training is done, this embedding becomes the dual goal representation used by the downstream policy.

What can go wrong

What can go wrong

Offline data must be diverse. If the offline data only covers a narrow part of the state space, the value function only learns accurate time-distances in that region. For unseen states, its predictions (and the goal embedding) will be unreliable. Remedy: collect offline data that explores the full environment.
Stale or poor value function. If the value function is undertrained or converges to a bad solution, the goal embedding will encode misleading time-distances. The downstream policy will then make poor decisions. Remedy: ensure the value function training converges before extracting the goal embedding.
Extreme environmental change. If the new environment has fundamentally different dynamics (e.g., the robot becomes much faster, or moves in a different topology), the time-distances from the old environment no longer apply because those distances were learned from the old world's rules. The dual representation survives appearance changes but not changes to how the world actually moves, because time-distances are tied to the world's dynamics, not to visual appearance. Remedy: restrict use to environments with similar dynamics.
Done right. Train the value function on diverse offline data that covers many states and goals, verify it converges, then use the goal embedding for downstream policy learning in the same environment class.
What a runnable demo should prove

What a runnable demo should prove

Build a simple 2D gridworld (a 10x10 grid where the agent moves one square per step). Collect offline data: random trajectories showing the agent reaching 5 different goals. Train a value function on this data to predict time-to-goal. Extract the goal embedding for one goal. Then: (1) use the dual representation in a new downstream policy trained in the same gridworld, (2) add visual noise to the goal observation (blur or shift the pixels), and (3) move to a rotated or reflected version of the same gridworld. The demo should show the policy succeeds in all three cases (original, noisy, rotated), while a naive pixel-based goal representation fails in cases 2 and 3.

Robustness = (success_rate_on_noisy_goal + success_rate_on_rotated_env + success_rate_on_new_appearance) / 3

The dual representation should maintain >80% success across all three tests (original, noisy, rotated), while naive representations collapse to <40%.
