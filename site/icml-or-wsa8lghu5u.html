Learning to Theorize the World from Observation

The paper replaces pure next-observation prediction with a system that induces hidden executable programs from raw observations, so the model learns explanations of how the data is generated rather than only forecasts of what comes next.

Paper explainersAll themesOther

Predicting the next frame in a video can produce a strong pattern recognizer, but prediction alone does not force a system to discover the underlying rules that generated what it saw. A model can forecast well by matching surface regularities while never forming reusable internal explanations. This paper argues that theory construction is a stricter test of understanding because the learned internal program must execute to reproduce observations in terms of hidden causes and rules. The proposed Learning-to-Theorize method does this directly from non-textual observation. Its Neural Language-of-Thought Programmer induces hidden programs, executes them, and treats those programs as explanations of the data. The central shift is from task-specific output prediction to explanation-driven structure induction.

Zero assumption version

Why prediction is not the same as theory

A predictive model asks what observation is likely to come next given the past. That is useful, but it does not require the model to identify the generative rules behind the observations. A system can achieve low prediction error by memorizing local correlations, short-term dynamics, or visual regularities that do not transfer when the environment changes.

A theory-building system needs an executable internal structure because the explanation must reproduce the observations when run. That means representing the world in a form that supports explanation: what variables exist, what rules connect them, and how those rules generate the observed sequence. The paper asks how to learn such theories from raw observation alone, without language supervision describing the rules in words.

The decisive shift. Do not train only to predict observations. Train to infer hidden executable programs that can generate those observations and therefore function as internal theories.

The hidden quantity

The hidden quantity

measured quantity  =  explanatory program consistency

The hidden quantity is whether the induced program is a consistent explanation of the observations. Consistent does not mean only that it reproduces the observed frames once. It means the same hidden rules can account for the structure of the sequence and continue to work when conditions vary within the same generative system.

This is what separates explanation from memorized forecasting. A predictive hidden state may encode enough to guess the next few observations, yet fail when the sequence changes configuration. An executable program must organize the data into entities, relations, and operations that remain real under recombination. That constraint makes the hidden representation closer to a theory.

Why it works

Why executable theories generalize differently from predictors

Prediction objectives reward models for matching outputs. If many different hidden representations lead to similar next-step forecasts, the optimizer is free to choose whichever one is easiest to fit. That often means storing compressive statistical summaries instead of discovering the underlying generative process. Such representations can fail when the environment changes in a way that preserves the rules but alters the surface pattern.

An induced executable program faces a stricter requirement. It must specify operations that, when run, reconstruct or explain the observed data. This encourages factorization into entities, rules, and compositional structure. Because the program is executable, it is evaluated by what it generates, not only by whether it correlates with the right answer. That reduces the room for surface-level shortcuts.

The paper's Neural Language-of-Thought Programmer matters because it gives the system a program-like hidden space rather than a free-form continuous memory alone. The induced program can therefore serve as an internal theory: a reusable causal description that is portable to new settings generated by the same rules. This is why the paper frames the outcome as explanation-driven generalization. The model is not only saying what comes next. It is saying what hidden process produced the sequence.

Math after the picture

An explanation-driven objective

First in words:

The system chooses a latent program that, when executed, makes the observed data likely while staying within the program prior favored by the model's language-of-thought representation.

Then the compact form:

score(program) = log p(observation | execute(program)) + log p(program)

Every symbol:

programthe latent executable theory proposed by the model
execute(program)the observation-generating process obtained by running that program
p(observation | execute(program))how well the executed program explains the observed data
p(program)the prior preference for simpler or more plausible latent programs
A tiny worked example
Program A says there are two moving objects and one collision rule.
When executed, it reproduces the observed sequence with likelihood score -1.2 and has simplicity score -0.4, so total score is -1.6.
Program B memorizes many frame-specific details.
It reproduces the sequence slightly better with likelihood score -1.0 but has simplicity score -1.5 because it is much more complex, so total score is -2.5.
The method prefers Program A because it explains the data well enough while remaining a cleaner theory.
That preference is what pushes learning toward reusable hidden explanations.

The exact objective can be implemented in richer ways, but the central structure is stable: explanations are judged by both fit to the data and plausibility of the induced program.

What can go wrong

What can go wrong

The hidden program language may be too weak. If the program space cannot express the real generative rules, the model may still fall back to approximate predictive shortcuts because no correct theory is available to induce.
Program search can be hard. Inducing executable hidden structure is combinatorial. Without a strong inductive bias or a good answering time strategy, the system may struggle to discover useful theories from raw observation.
Simple prediction may outperform theory induction on narrow tasks. If the benchmark rewards only short-horizon forecasting and not rule transfer, a pure predictor can look stronger because it does not pay the cost of building an explanatory program.
Done right. The method is strongest when the environment has reusable hidden rules, the observation process contains enough structure to infer them, and evaluation checks whether the learned representation supports explanation-based transfer rather than only one-step prediction.
What a runnable demo should prove

What a runnable demo should prove

Build a synthetic visual world with a small hidden rule set, such as object interactions governed by a few deterministic update rules. Train one model only for next-frame prediction and another with a hidden executable-program objective in the style of the paper.

The demo should then test both models on new scenes generated by the same rules but with new configurations. It should also inspect whether the induced hidden programs correspond to the true hidden structure well enough to explain the observations rather than merely forecast them.

theory_transfer_gap = generalization_error_prediction_only - generalization_error_theory_model

The key result is that explanation-centered learning should win on rule-preserving but surface-shifting generalization tests.
