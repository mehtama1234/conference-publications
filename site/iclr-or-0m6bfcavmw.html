TusoAI: Agentic Optimization for Scientific Methods

An AI system that autonomously develops and optimizes computational methods by iteratively learning from experiment results and domain knowledge.

Paper explainersAll themesAI for Science

Scientists spend months writing custom software to analyze experiments. TusoAI is an AI agent that reads a scientific problem and an evaluation function (a way to score attempts), then builds and improves computational methods automatically by running each candidate against real experiment data and keeping the winners. This beats hand-written expert code because the AI explores many candidate designs, while a human expert writes just one—and the one that best matches the data survives.

Why building scientific software is hard

When scientists run an experiment, they generate messy data. To make sense of it, they need custom analysis software: code to clean the data, models to fit patterns, algorithms to extract answers. Building this software is painful. A scientist must read papers, make assumptions about what will work, code it, run it on real data, and if results are wrong, debug and restart. This cycle can take months.

A naive approach: hire a programmer. But programmers do not know the science, and scientists do not write good code, so miscommunications cause false starts. A smarter approach: use a large language model (an AI trained to write text and code) to draft the software. But generic AI drafts generic code. It does not know that in genetics, certain transformations matter, or that certain numerical tricks prevent crashes. The problem is that the AI has no way to learn from failure—it cannot see that its code crashed and update its knowledge to avoid that mistake next time.

In one sentence. TusoAI builds scientific software by reading the problem, running candidate solutions against real data, and iteratively refining code based on what works.

The algorithm as a flow

What it actually does

Read the problem

AI ingests task description and evaluation function (how to score correctness).

Build knowledge tree

AI reads papers and domain docs, organizing domain-specific choices as a tree.

Generate candidates

Explore the tree: pick different paths to create candidate methods.

Score on real data

Run each candidate and measure its score against the evaluation function.

Refine and repeat

Keep the best candidates, generate variants, score again. Repeat until plateau.

What the paper changes

What the paper changes

TusoAI changes the pool of candidate computational methods. Instead of writing one piece of software by hand, the AI generates many competing versions, each making different assumptions about how to solve the problem. The evaluation function (a score assigned by the scientist) then selects which versions are kept and refined. Over iterations, the diversity of candidates is guided by feedback from real data.

The hidden quantity

The hidden quantity: domain-specific alignment

measured quantity  =  alignment to domain constraints

The core hidden quantity TusoAI measures is how well each candidate method aligns with domain-specific structure. In genetics, for example, certain biological assumptions (genes interact in certain ways, measurements have known biases) should shape the method. Generic AI code ignores these assumptions. TusoAI measures alignment by encoding domain knowledge into a tree of choices and rating how many of those correct choices each candidate method includes.

The paper estimates alignment implicitly: the evaluation function (run on real data) gives a score, and methods that incorporate correct domain assumptions score higher because their outputs match reality better. So alignment is not measured directly; instead, the evaluation function surfaces it as a difference in performance.

Why it works

Why it works: feedback from real data guides design

The reason TusoAI outperforms hand-coded methods is that it closes the feedback loop. A human scientist writes code once, tests it, and if results are wrong, must debug by intuition. TusoAI generates dozens of candidate methods, scores all of them on the same real data, and discards the losers. This is like running a mini scientific experiment: which design assumptions actually explain the data best? The evaluation function is the measurement. Over many iterations, the process converges to methods whose assumptions match reality.

The knowledge tree is the core of the design. Instead of generating code randomly, TusoAI structures the search around domain-specific design choices. A geneticist might know that normalization (a scaling step) is always needed, and that there are three common ways to do it. The tree captures these choices. When the AI generates candidates by combining different tree paths, it is implicitly testing which combination of domain insights works best. Methods that violate domain knowledge score lower because they produce wrong answers. Methods that respect domain constraints score higher because they match the data. Over iterations, the optimizer converges to the methods that hold true domain knowledge.

The score and refinement equation

First in words:

The evaluation function assigns each candidate a score. TusoAI keeps the top-scoring candidates and generates new variants near them, concentrating search effort where performance is highest.

Then the compact form:

score(method_i) = evaluation_function(output_i, ground_truth) | new_candidates ~ sample_near(top_k_methods, temperature=T)

Every symbol:

score(method_i)how well candidate i explains the data
evaluation_function(output_i, ground_truth)scientist-provided measure of correctness
output_iwhat candidate i predicts or analyzes
ground_truththe actual experimental measurements
top_k_methodsthe best k candidates from the previous round
sample_near(...)generate new variants by small random changes to top methods
temperature=Tcontrols diversity: higher T spreads search wider, lower T narrows to best methods
A tiny worked example (genetics data analysis)
Candidate 1: assumes genes are independent, no scaling. Predicts: [5, 3, 7]. Truth: [8, 5, 9]. Score: 4 (poor fit).
Candidate 2: assumes gene interactions, applies domain-specific scaling. Predicts: [8, 5, 9]. Truth: [8, 5, 9]. Score: 95 (perfect fit).
Candidate 3: assumes gene interactions, different scaling. Predicts: [9, 6, 10]. Truth: [8, 5, 9]. Score: 82 (good fit).
Candidate 2 has the highest score. TusoAI samples new variants near candidate 2 (tweaking its numeric settings slightly) and re-evaluates.
After 5 iterations: Candidate 2 variants cluster around score 90-95. Candidate 1 variants remain low. Search converges to gene-interaction models with proper scaling.

The evaluation function is the connection between abstraction and reality—it measures how closely the method's output matches ground truth.

What can go wrong

What can go wrong

Knowledge tree is incomplete or wrong. If the domain knowledge fed into the tree omits critical assumptions or includes false facts, candidates will be biased toward wrong designs. Example: if the tree says genes are always independent but they actually interact, no amount of iteration will find good methods until the tree is fixed.
Evaluation function is misaligned with true scientific correctness. If the scientist provides a score that rewards the wrong outcome, TusoAI optimizes for that wrong outcome. Example: if the evaluation function favors simplified models over accurate ones, TusoAI will generate oversimplified methods.
Overfitting to the training data. If the evaluation function is computed on a small dataset, candidate methods may memorize noise rather than learning generalizable patterns. Hold-out test sets (data the candidates never see) prevent this.
Done right. The knowledge tree is built from peer-reviewed literature and domain expert input. The evaluation function is validated on independent data. Multiple diverse candidates are retained and tested on held-out data before declaring a winner.
What a runnable demo should prove

What a runnable demo should prove

A convincing demo would pick a small scientific task (e.g., predicting gene expression from DNA sequence using a toy dataset), set up a domain knowledge tree with 3-5 key design choices (e.g., normalization method, model class, feature engineering), define an evaluation function (e.g., mean squared error on predictions), and run TusoAI for 10 iterations. At each iteration, print the top-scoring method and its score. The demo should show that the score improves and converges because candidates with wrong assumptions are discarded and only those respecting domain constraints are refined; and that the final method includes more domain-correct choices than random baselines or a single hand-coded method because the optimizer tested hundreds of paths through the knowledge tree while a human expert hand-codes just one path.

improvement = (best_final_score - best_expert_method_score) / best_expert_method_score * 100%

The demo must make impossible to miss: iterative refinement against real data produces methods that outperform methods written once by hand because diversity plus feedback beats a single human guess, and TusoAI's domain-aware structure accelerates convergence to good methods because the search is steered by domain knowledge instead of wandering randomly.
