Topology of Reasoning: Retrieved Cell Complex-Augmented Generation for Textual Graph Question Answering

Answer graph questions by retrieving loops and higher-order relations, not just isolated nodes and links.

Paper explainersAll themesAgents & Tool Use

Textual graph question answering often retrieves a few nodes and links, then asks a language model to reason over that fragment. That misses an important class of questions: ones whose answer depends on loops, closed relational structures, or multi-way constraints. TopoRAG lifts the graph into a richer structure built from cells, retrieves the relevant substructure, and then reasons over that substructure so the model receives context that matches the shape of the question, because matching context removes the need to reconstruct missing relational structure from partial evidence.

Zero assumption version

Why node-and-link retrieval is not enough

Many graph questions can be answered from a single edge or a short path. But some require reasoning over loops: for example, whether two objects share a circular dependency, whether relative positions are consistent around a cycle, or whether several pairwise relations fit together as one closed structure.

Standard retrieval misses these cases because it treats the graph as a bag of local pieces. The model sees fragments but not the higher-order relation that ties them together. If the question depends on a loop or a multi-way constraint, the missing structure leads to incomplete grounding and wrong answers because the language model must guess the absent relation pattern.

The paper's move in one sentence. Lift the graph into a cell complex, retrieve the relevant subcomplex for the question, and reason over that multi-level structure so the model sees loops and other higher-order relations directly, because direct access to the full structure removes the need to infer it from scattered links.

The algorithm as a flow

What it actually does

Step 1: Parse the textual graph

Turn the graph description into structured entities and relations, so the system can reason over explicit graph pieces instead of raw text alone.

Step 2: Lift the graph into a cell complex

Add higher-order cells that represent closed relation sets and other multi-way structures, because some questions depend on these units rather than on single links.

Step 3: Retrieve a topology-aware subcomplex

Select the cells and links most relevant to the question, so that the returned context includes both local facts and the larger structure they form.

Step 4: Propagate information across levels

Reason over nodes, links, and higher-order cells together, because the answer may need evidence that moves between these levels.

Step 5: Give the structured context to the language model

Generate the final answer from the retrieved subcomplex, so that the language model works from complete graph evidence rather than a broken fragment.

The hidden quantity

The hidden quantity: structural completeness of the retrieved context

measured quantity  =  Higher-order relational coverage

A graph answer is reliable only when the retrieved context contains the full relation pattern needed by the question. That hidden quantity is structural completeness. If the retriever returns single links but omits the loop they belong to, the model sees only part of the evidence.

TopoRAG raises structural completeness by lifting the graph into cells and retrieving the connected subcomplex. That matters because many textual graph tasks ask about consistency across several relations at once, not about one relation in isolation.

Why it works

Why it works: retrieve the same kind of structure the question needs

TopoRAG works because it reduces a mismatch between the question and the retrieved evidence. Questions about loops or multi-way constraints require context with the same structure. Ordinary retrieval returns local pieces, which forces the language model to reconstruct the missing larger pattern from incomplete evidence. That reconstruction often fails.

By lifting the graph into cells, the method stores higher-order relations explicitly. Retrieval can then return a compact subcomplex that already contains the necessary loop or closed relation set. The reasoning stage propagates information across nodes, links, and cells, so the answer uses evidence at the right scale for the question.

The retrieval idea

First in words:

Score each candidate subcomplex by how well its nodes, links, and higher-order cells match the question. Retrieve the subcomplex with the highest combined relevance.

Then the compact form:

score(subcomplex, query) = node_match + edge_match + cell_match

Every symbol:

score(subcomplex, query)overall relevance of one candidate subcomplex to the question
node_matchsupport from matching entities or node descriptions
edge_matchsupport from matching pairwise relations
cell_matchsupport from matching higher-order structures such as loops or multi-way constraints
A tiny worked example
Suppose the question asks whether three items form a consistent circular order.
A node-and-link retriever may return the pairwise facts A before B and B before C.
It may miss the fact that C before A also matters, so the loop is incomplete.
TopoRAG can retrieve the three-node closed structure as one candidate subcomplex.
That candidate gets extra cell_match support because it contains the full circular relation required by the question.

The higher-order term matters because local matches alone cannot tell whether the retrieved evidence closes the full relation pattern.

What can go wrong

What can go wrong

The lifted structure may be too large. If the cell complex grows too quickly, retrieval and reasoning costs rise because many higher-order candidates must be considered.
Question parsing may select the wrong structural pattern. If the retriever misreads a local question as a loop question, it may pull in unnecessary context, which can distract the final answer step.
Higher-order cells can still miss the right abstraction. Some tasks may depend on a relation pattern that is not well represented by the chosen cells, so the retrieved subcomplex may remain incomplete.
Done right: the answer uses complete graph evidence. The method helps because it retrieves the entire supporting relational structure, so the language model does not have to invent the missing loop from scattered pieces.
What a runnable demo should prove

What a runnable demo should prove

Build a small textual graph dataset with two kinds of questions: direct-link questions and loop-sensitive questions. Compare a local retriever that returns nodes and links against a TopoRAG-style retriever that can return subcomplexes containing closed relation sets. Feed each retrieved context to the same language model. The demo should show that both systems handle direct-link questions similarly, while the TopoRAG-style system wins on loop-sensitive questions because its context includes the full supporting structure.
