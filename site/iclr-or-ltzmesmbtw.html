In-Training Compression of State Space Models

Growing a large state space model and shrinking it during training preserves task structure while cutting compute costs.

Paper explainersAll themesTime Series & Sequential

State Space Models are a type of machine learning model designed to process long sequences of data, like stock prices or sensor readings over time. To work well, these models need to remember a lot of information in their hidden state (the internal numbers they use to process each new input). But a larger hidden state means more computation and slower training. This paper shows that if you start with a large model and gradually remove unimportant hidden state dimensions during training, you end up with a smaller model that is faster to train and performs better than if you had trained a small model from the start, because the early large state lets the model discover all the patterns it needs, then pruning removes only the dimensions that were never used.

Zero assumption version

The tradeoff between memory and speed

State Space Models work by keeping track of a hidden state (a list of numbers that represents what the model has learned so far) and updating it for each new piece of data. The bigger this hidden state, the more slots the model has to store information, so it can remember more patterns and produce more accurate predictions, because each extra slot can encode a different piece of task structure. But a bigger hidden state also means more arithmetic to do with each data point, which makes training slower and uses more compute. A naive attempt is to just train with a small hidden state from the start. This trains faster, but the model cannot hold enough patterns, so accuracy drops, because there are not enough slots to encode all the patterns needed for the task.

The fundamental problem is that we do not know in advance which state dimensions are truly important for a given task. If we could identify and keep only the important ones, we could skip the useless dimensions and save computation without sacrificing quality.

In one sentence. The paper identifies which hidden state dimensions matter during training, then removes the rest.

The algorithm as a flow

What it actually does

Start with a large state

Initialize the model with a large hidden state to capture all possible patterns.

Measure influence using Hankel analysis

For each state dimension, compute a Hankel singular value (a score of how much that dimension contributes to the model's output).

Rank dimensions by importance

Sort dimensions from highest to lowest influence score.

Prune low-influence dimensions during training

Gradually remove dimensions with low Hankel singular values, collapsing the hidden state as training progresses.

End with a compressed model

The final model is smaller and faster because fewer dimensions means fewer numbers to multiply, and it has preserved the patterns that matter because you kept the high-influence dimensions that learned task structure.

What the paper changes

What the paper changes

The paper modifies the hidden state dimensions themselves — specifically, which dimensions are kept during training. Most machine learning papers change weights (the numbers that control how the model processes data) or gradients (the signals that guide how to update those numbers). This paper is different: it changes the state dimension structure itself, keeping some and removing others based on their computed influence score.

the object it moves  =  hidden state dimensions
The hidden quantity

The hidden quantity: Hankel singular value

measured quantity  =  Hankel singular value

A Hankel singular value is a score from control theory that measures how much a state dimension influences the model's output. The name comes from the Hankel matrix, a mathematical tool used to analyze dynamical systems (systems that change over time). To compute it: the model collects inputs and outputs over a window of time, stacks them into a matrix, and then factorizes that matrix to find which components matter most. A high Hankel singular value means that dimension carries important information and changing it would alter the output noticeably. A low value means the dimension is nearly redundant.

The paper applies Hankel singular value analysis during training. At regular intervals (or at each training step), it computes which state dimensions have low influence and marks them for removal. The model gradually shrinks as training proceeds, shedding dimensions that the data has determined are not needed for this particular task.

Why it works

Why in-training compression works better than shrinking from the start

The mechanism hinges on learning stages. When you start training, the model does not yet know which patterns matter for your task. A large hidden state lets every dimension explore and test different behaviors. As training progresses, most dimensions gravitate toward either holding important patterns or becoming nearly inactive. By measuring influence via Hankel singular values and removing the inactive dimensions, the model sheds dead weight while keeping the dimensions that have already found task-critical patterns, because those dimensions have already been sculpted by gradient updates into shapes that solve the task.

In contrast, if you train with a small hidden state from the start, you never give those task-critical patterns a chance to develop in the first place. The model is constrained so early that it cannot capture the full expressivity of the problem. The compressed model trained in-training preserves structure that a small model would have had to rediscover or relearn.

There is also a practical efficiency win: early training steps are cheap (the large state is searching), but as dimensions are pruned, later steps get cheaper too. The model accelerates as it converges, because the computationally expensive part (large state math) shrinks over time.

The equation: Hankel singular value decomposition

First in words:

Hankel singular value = the magnitude of a singular value from the factorization of a Hankel matrix (a matrix built from system inputs and outputs over time). Dimensions are ranked by their singular values and low-rank dimensions are pruned.

Then the compact form:

H = [y(1) y(2) ... y(m); y(2) y(3) ... y(m+1); ...; y(p) y(p+1) ... y(p+m-1)] = U * Sigma * V^T; keep dimensions where Sigma_i > threshold

Every symbol:

HHankel matrix (rows and columns built from outputs over different time windows)
y(t)model output at time t
U, V^Torthogonal matrices from factorization (describes the principal directions)
Sigmadiagonal matrix of singular values (the importance scores)
Sigma_ithe ith singular value (score for dimension i)
thresholdcutoff: keep dimensions above this score, remove below
A tiny worked example
Suppose we have a 4-dimensional hidden state. Hankel analysis produces singular values: [8.2, 5.1, 1.3, 0.4].
We set threshold = 2.0 (remove any dimension scoring below 2.0).
Result: keep dimensions 1 (score 8.2) and 2 (score 5.1); remove dimensions 3 (score 1.3) and 4 (score 0.4).
New hidden state size: 2 dimensions. Later layers and matrix multiplications are 2x faster. Training accelerates.

Hankel singular values come from control theory's balanced truncation, which guarantees that removing low-score dimensions preserves the system's input-output behavior with a bounded error margin.

What can go wrong

What can go wrong

Pruning too aggressively early. If you remove dimensions before the model has finished learning task-critical patterns, you cut off important structure prematurely. The model then cannot recover that lost expressivity. Solution: prune gradually over training, not all at once.
Threshold set incorrectly. If the Hankel singular value threshold is too high, you remove dimensions that were actually important but had not yet ramped up in influence. If too low, you keep too much dead weight and do not save compute. The threshold should be tuned to the problem and learned over time.
Hankel matrix built from insufficient data. The Hankel matrix must be constructed from a long enough sequence of outputs to capture the system's true behavior. If the window is too short, the singular values will be noisy and unreliable, leading to bad pruning decisions.
Done right. Start with a large state, compute Hankel singular values regularly, prune gradually (a small fraction of dimensions per epoch), and stop pruning once the state reaches your target size. This works because the model first explores and finds all patterns, then pruning removes only dead dimensions, leaving learned structure intact and training speedier as fewer numbers need updating.
What a runnable demo should prove

What a runnable demo should prove

Build a simple synthetic time-series task (e.g., predicting the next value in a noisy periodic signal, or forecasting from a simple dynamical system). Train three models: (1) a small State Space Model, (2) a large model with no pruning, and (3) a large model with in-training compression using Hankel singular value pruning. Measure both the final task accuracy and the total training time (CPU or GPU minutes). The demo should show that the compressed model achieves accuracy closer to the large-no-pruning model while training nearly as fast as the small model.

accuracy = (correct_predictions / total_predictions); training_time = total_seconds; speedup = training_time_large_unpruned / training_time_compressed

The demo must make it impossible to miss that in-training compression outpaces both small training (lower accuracy) and large training (slower speed) by finding a middle ground: start large to learn all patterns, shrink during training to save compute.
