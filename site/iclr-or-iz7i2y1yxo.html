An Ensemble Framework for Unbiased Language Model Watermarking

Stack multiple independent watermarks on top of each other so the detection signal grows while the model's output stays unchanged.

Paper explainersAll themesLLMs & Foundation Models

A watermark is a hidden fingerprint embedded in model output to prove who created it. Normal watermarks leave traces that change how the model talks, making generated text worse or easier to spot as fake. This paper stacks multiple watermarks together—each one tiny and harmless, but combined they make the fingerprint loud enough to detect while keeping the text exactly as good as unwatermarked output.

Zero assumption version

The watermark detection problem

When a language model generates text, it picks the next word by rolling weighted dice—some words are more likely, others less. To hide a watermark, you secretly re-weight those dice so certain words become slightly more likely. A detector later reads the text and asks: were these words picked with tampered dice? If they were, the watermark is real.

The hard part: you want the re-weighting to be unbiased—meaning the model's overall output should sound exactly the same whether watermarked or not. Why? Because if watermarked text sounds different, someone can strip the watermark by rewriting the text, and a human can spot watermarked text instantly, which defeats the point. But unbiased watermarks are weak. Each re-weighting is so tiny that it vanishes in the noise. A detector needs to read thousands of tokens to be confident the dice were tampered with—useless for short messages or when text gets paraphrased.

What a naive approach tries: make the watermark signal louder by re-weighting more aggressively. This fails because the louder the re-weighting, the more the model's output drifts from normal, and the quality drops.

In one sentence. Stack independent watermarks so their signals pile up, boosting detection while keeping output unbiased.

The algorithm as a flow

What it actually does

Embed layer one

Apply watermark rule with key one: re-weight token probabilities, sample next word.

Embed layer two

Feed the token probabilities from layer one into watermark rule with key two, apply same re-weighting.

Repeat with new keys

Keep stacking: layer three, four, five, each with its own secret key, each a tiny adjustment.

Generate text normally

Sample from the final stacked token probabilities as if it were any normal model output.

Detect from the text

Compute detection score with each secret key separately, then add the scores together.

What the paper changes

What the paper changes

The paper changes how many watermark layers get applied. Instead of one watermark, it stacks n independent watermarks in sequence, each with its own secret key. Each layer re-weights the model's token probabilities, then the next layer re-weights what came out of the first.

the object it moves  =  the number of stacked watermark layers
The hidden quantity

The hidden quantity: detection signal-to-noise ratio

measured quantity  =  Signal-to-noise ratio (how loud the watermark is relative to randomness)

Every watermark produces a detection score—a number that should be high if the text is watermarked and low if it is not. But because text is noisy (some random words slip through), the score jiggles up and down. The signal-to-noise ratio is the strength of the pattern you are looking for divided by the amount of jiggling. A high ratio means the detector can confidently spot the watermark from short text. A low ratio means you need thousands of tokens.

The paper's key insight: when you stack n independent watermarks, their detection scores add up. The mean (average score) grows as n, but the noise (randomness) only grows as sqrt(n). So the signal-to-noise ratio grows as sqrt(n)—roughly the square root of the number of layers. This is the hidden quantity that makes ENS work.

Paper reading. When n independent watermarks are applied, the detection score aggregated across all keys has mean n times the per-key mean, variance n times the per-key variance. The math works out to: signal-to-noise ratio grows as the square root of n times the single-key ratio.
Why it works

Why it works: the layering trick

Each unbiased watermark is a rule that re-weights the model's token probabilities slightly. Because it is unbiased, the re-weighting is so small that if you average over all possible random numbers in the watermark generator, the output distribution stays unchanged. The trick is: one watermark alone is so tiny that noise drowns it out. But stacking n watermarks does not make the output drift—each layer still applies an unbiased, tiny adjustment to what the previous layer gave it.

The magic happens in the detection. When you read the watermarked text, you run a detection test n times, once with each secret key. Each test finds a score: a number saying how watermark-like the text is. The scores from independent keys can be added together because they are measuring different pieces of evidence. When you add n scores, the true signal (from the real watermark) stacks and grows as n. But the false signal (randomness) only grows as the square root of n, because noise is independent. So the ratio improves by a factor of sqrt(n)—meaning detection becomes strong enough to work on very short text or text with minor edits, because the signal is now loud enough to cut through the noise even with fewer tokens to read.

Math after the picture

The equation: ensemble detection score

First in words:

total detection score = sum of all per-key scores; each per-key score measures how likely those tokens are under the watermarked distribution

Then the compact form:

S_ENS(x1:T) = sum_i S(x1:T, sk_i); SNR_ENS = sqrt(n) times SNR_single

Every symbol:

S_ENSthe total watermark detection score across all keys
S(x1:T, sk_i)the detection score for token sequence using secret key i
sk_ithe secret key for the i-th watermark layer
nthe number of stacked watermark layers
SNR_ENSsignal-to-noise ratio of the ensemble
SNR_singlesignal-to-noise ratio of one watermark alone
A tiny worked example
Suppose one watermark alone produces a detection score that is 10 units above random noise with noise level 2 units. Signal-to-noise ratio = 10 / 2 = 5.
Now stack 4 independent watermarks. Each produces a score 10 units above noise level 2.
Total signal = 4 times 10 = 40 units. Total noise = sqrt(4) times 2 = 4 units.
New signal-to-noise ratio = 40 / 4 = 10. This is sqrt(4) = 2 times better than one watermark alone.
Stacking 9 watermarks: signal = 90, noise = 6, ratio = 15, which is sqrt(9) = 3 times better. The square root law holds.

Each stacked layer contributes its detection score independently, and scores add up. Noise is random noise, so it only grows as the square root of the number of layers.

What can go wrong

What can go wrong

Too many layers runs out of space. Each watermark nudges certain tokens up by a small amount. If you stack too many layers, those tokens run out of probability space (probabilities cannot exceed 1). At some point, adding more layers actually hurts because the re-weighting becomes impossible. The paper finds an optimal number of layers around 4-5 for typical settings.
Keys must be independent per generation step. For the signal-to-noise math to work, each layer's random choices must be independent of the others. If the same random seed is used twice, the layers become correlated because they measure the same evidence twice, and you get no new information added—so the signal-to-noise ratio does not improve as sqrt(n) and you waste computational effort. The implementation must keep keys separate and uncorrelated.
Paraphrasing can still weaken detection. If someone rewrites the text heavily, some watermarked tokens may be replaced with different words. More layers help because the watermark is spread across many tokens and only some are replaced, but if the text is rewritten so drastically that most watermarked tokens are gone, the detection score drops below the threshold even with a strong watermark, because you have fewer watermarked tokens to add up in the detection test.
Done right: carefully choose the number of layers. Find the sweet spot where detection is strong but the probability space is not exhausted. Use independent keys for each layer. Test on short text to confirm the gain.

The key finding: stacking watermark layers makes detection exponentially stronger—by a factor of sqrt(n)—because independent signals add up while noise only grows by its square root, and this gain costs nothing in text quality, which is the whole point.
