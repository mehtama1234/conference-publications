Internal Planning in Language Models

A method to detect planning in language models by compressing their hidden states into compact codes and measuring what information they preserve about future tokens.

Paper explainersAll themesInterpretability

Language models generate text one word at a time. But do they look ahead while generating, organizing their internal computations to plan several steps forward? Or are they completely myopic, tunnel-visioned on just the next word? This paper develops a technique to peek inside a language model's hidden thoughts to find out.

Zero assumption version

We cannot see inside a language model's hidden thoughts

A language model (a program that predicts the next word) has secret computations happening inside. These computations are recorded in hidden states: lists of thousands of numbers that store the model's working thoughts as it reads your input and prepares its response. The question is whether these hidden states encode anything about future words beyond the immediate next one.

Naively, you might try to just read the hidden states directly, but they are noisy and bloated with useless details: small numerical fluctuations from how individual words (tokens) are positioned, normalization shifts, random noise from the attention mechanism (which decides which parts of the input to focus on). A beginner would stare at these numbers and learn nothing. The problem is that hidden states are redundant and encumbered with fine-grained details that mask the real planning information underneath.

In one sentence. Compress each hidden state into a single discrete code using a learning algorithm, then measure which codes tend to appear together, revealing which information the model preserves.

The algorithm as a flow

What it actually does

Extract hidden states

Collect the internal states from all layers when the model reads different prefixes.

Train a compression algorithm

A VQ-VAE learns to map each messy hidden state to the nearest point in a small codebook.

Create discrete codes for everything

Apply the trained compressor to all hidden states, converting each to an integer code.

Count co-occurrences

For two hidden-state blocks, tally how often their codes appear together in data.

Measure mutual information

Mutual information (a number between 0 and 1) tells you how much knowing one code narrows down the other.

What the paper changes

What the paper changes

The paper changes how we observe a language model's hidden states. Instead of trying to analyze thousands of noisy numbers directly, we compress them into discrete integer codes. This single change — replacing raw continuous numbers with quantized codes — makes everything else possible.

The hidden quantity

Planning horizon and branch awareness

measured quantity  =  Mutual information between prefix computations and future tokens

The hidden quantity is mutual information: a measure of how much knowing one thing tells you about another. Here, it answers: if I know the model's internal state after reading the prefix, how much does that narrow down the possible next tokens?

The paper estimates this by counting how often pairs of discrete codes appear together across a dataset. If a prefix code nearly always co-occurs with a particular future-token code, mutual information is high (the prefix strongly predicts that future). If they appear independently, mutual information is near zero (the prefix tells you nothing useful about that future token). The paper also measures planning horizon: how many tokens ahead does the model's current computation encode useful information?

Why it works

Why it works: cleaning signal from noise

Raw hidden states contain thousands of numbers, most of them noise: tiny variations from token positions, normalization jitters, attention randomness. A VQ-VAE (vector quantized variational autoencoder) is a learning algorithm that forces each hidden state to be reconstructed from a small, fixed set of codes. To achieve good reconstruction, the learning algorithm must choose codes strategically: important, task-relevant information survives compression, while noise and fine-grained details get discarded.

Once each hidden state is a single code, measuring mutual information becomes tractable. We simply count: how often does code A co-occur with code B in the data? High co-occurrence means they carry related information; rare co-occurrence means independence. This counting is immune to noise in the raw numbers because the codes have already been cleaned by the compression step.

inputRaw hidden states (noisy, thousands of numbers per state)
stepVQ-VAE encoder maps state to nearest code
stepVQ-VAE decoder reconstructs from code
stepCodebook filters out noise, keeps task-relevant signal

Math after the picture

The information measure

First in words:

Mutual information is the sum over all code pairs of the joint probability times the log of the ratio of the joint probability to the product of the marginal probabilities.

Then the compact form:

I(Z_A; Z_B) = sum_i sum_j P(z_A=i, z_B=j) * log[ P(z_A=i, z_B=j) / (P(z_A=i) * P(z_B=j)) ]

Every symbol:

Z_Acodes from prefix block A
Z_Bcodes from future block B
P(z_A=i, z_B=j)fraction of samples where code i appears in A and code j in B
P(z_A=i)fraction of samples where code i appears in A (regardless of B)
P(z_B=j)fraction of samples where code j appears in B (regardless of A)
I(Z_A; Z_B)mutual information in bits
A tiny worked example
Suppose code 3 appears in prefix 100 times, code 7 in future 100 times.
They co-occur 60 times. By chance alone (independence) they would co-occur 100 * 100 / 10000 = 10 times.
P(3,7) = 60/1000 = 0.06. P(3) = 100/1000 = 0.1. P(7) = 100/1000 = 0.1.
Log-ratio = log(0.06 / (0.1 * 0.1)) = log(0.06 / 0.01) = log(6) ≈ 1.79 bits.
This pair contributes 0.06 * 1.79 ≈ 0.107 bits. Sum all pairs for total I(Z_A; Z_B).

High mutual information means the model encodes detailed information about future tokens; low means it is myopic.

What can go wrong

What can go wrong

Codebook collapse. If the learning algorithm fails, all hidden states compress to the same few codes. Then mutual information becomes meaningless noise; the signal is lost. Solved by adding penalties that gently steer the codes to spread out and stay active during training.
Lossy compression erases real planning. If the VQ-VAE compresses too aggressively, even genuine planning information gets discarded. The mutual information will underestimate how far ahead the model truly plans.
Task-dependent behavior. Planning horizons vary wildly across tasks. A grammar task demands only lookahead of 1-2 tokens; a math reasoning task requires encoding 10+ tokens ahead. One codebook may not capture all planning depths equally well.
Done right. The paper adds careful regularization: a cosine-similarity penalty to keep codes diverse and a penalty that encourages all codes to be used equally. It tunes codebook size based on what works best per task.
What a runnable demo should prove

What a runnable demo should prove

Build a small language model (e.g., a 2-layer transformer on synthetic data: predict the next token in a sequence). Extract hidden states from all layers on a test set of 1,000 examples. Train a VQ-VAE (with 256 codes) to compress these states. Measure mutual information between the hidden state after token 3 and the actual values of tokens 4, 5, 6, 7. Plot mutual information versus distance into the future.

I(hidden_after_token_3; token_at_position_k) for k = 4, 5, 6, 7, 8

The demo should show mutual information dropping as you look further ahead, proving the model encodes more information about nearby tokens than distant ones. If using multi-token training, you should see higher mutual information at farther positions than with standard single-token training.
