FARE: Foundational Automatic Reasoning Evaluators

Train a general-purpose evaluator model on 2.5 million examples of five different evaluation tasks using a simple iterative approach where you only keep the examples the model gets right, so it learns steadily without fighting confusion.

Paper explainersAll themesLLMs & Foundation Models

Modern AI systems need judges that can score their own answers. This paper shows the best way is not fancy algorithms but plain data at scale: collect 2.5 million examples where models evaluate things in five different ways (side-by-side, step-by-step, reference-based, reference-free, and numerical ratings), then train a medium-sized model to mimic those judgments, being careful to only show it examples it answers correctly. The result is a small evaluator model that outperforms much larger specialized ones, because seeing 2.5 million clean signals from multiple domains teaches broader patterns than seeing only hundreds of thousands of mixed signals from a single domain.

Zero assumption version

The evaluator crisis: we need judges but can't afford them

Large language models (language models that read and write text) are now good enough to solve real problems, but we need to know when their answers are correct. A human reading every answer is too slow and expensive. The obvious shortcut is to train a smaller model to judge answers automatically—call this model a judge or verifier.

Recently, teams have been trying fancy training tricks (reward optimization: a method where you nudge the judge towards correct answers using a reinforcement learning signal, which is compute-heavy and brittle) or clever inference-time tricks (running the judge multiple times or with side chains). But a beginner would notice something simpler: maybe the problem is just not enough examples for the judge to learn from. Most judges are trained on a few hundred thousand examples. What if the real fix is more examples?

The insight. Train a judge on 2.5 million varied examples (not 200K), using simple supervised learning where you only show it examples it gets right, so it learns without chasing noise.

The algorithm as a flow

What it actually does

Gather the data

Collect 2.5M examples: half from existing high-quality evaluator datasets (human-judged, proven good), half synthetically generated via error injection and generate-then-grade.

Divide into rounds

Split the 2.5M into batches (chunks processed one at a time) and go through each batch iteratively.

Sample four attempts per input

For each input (prompt), generate four different model responses and record their correctness against ground truth.

Keep only clean examples

If your judge correctly predicts which responses are right, add those examples to your training batch. Skip examples where it guesses wrong.

Train the judge on clean wins only

Update the judge's weights using supervised learning on the filtered examples, iterating through batches until done.

What the paper changes

The one thing that changes: judge training examples

The paper does not change the judge model architecture or the training algorithm (both stay simple). It changes what examples the judge sees: instead of showing it every example (good ones and ambiguous ones alike), it only shows it examples where the judge confidently gets the answer right. This keeps training noise-free.

the object it moves  =  Training-example quality
The hidden quantity

The hidden quantity: Example confidence, or how sure the judge was

measured quantity  =  Judge prediction correctness per example

Each time the judge reads an example and predicts an evaluation, it can be right or wrong. This paper measures, for every example, whether the judge's prediction matches ground truth (the correct answer). This is not a new metric the paper invented; it is a simple pass-or-fail check.

The paper uses this quantity to filter: it only trains on examples where the judge's prediction is correct. This is why the method works—you only show the judge data it is confident about, so it learns without fighting its own mistakes.

Why it works

Why filtering on correctness makes a stronger judge

When you train on every example including ones the judge is confused about, the judge has to pull in two directions at once: learn from correct answers and unlearn from the confusion it created. This is like trying to memorize a poem while someone whispers different words—your brain wastes effort fighting noise.

By only training on examples where the judge guesses right, you remove that conflict. The judge sees only clean signals: a math problem paired with the label 'A is better than B', and the judge already knew A was better, because you filtered for agreement. Repeating this cleans up its internal patterns (weights: the numbers that control what the judge does). You iterate this process through all 2.5M examples, and because the training signal is always aligned with what the judge already thinks, it learns solidly without oscillating—there is no internal tug-of-war.

The reason this scales is that with enough data, the randomness of a single wrong guess becomes negligible. Across 2.5M examples, the judge has seen every angle of every kind of evaluation, so when it starts doubting itself on a hard case, there are thousands of easier cases reinforcing the right patterns.

The training formula

First in words:

In each iteration, pick a batch of examples from training data. For each input x in the batch, generate K responses, check which are correct, compute the judge's predicted probability that each is correct, then update the judge's weights by reducing the gap between the judge's guess and ground truth, but only for examples where the judge predicted correctly.

Then the compact form:

theta_t+1 = argmax_theta sum_{(x,y) in D_t} log pi_theta(y|x)

Every symbol:

theta_tthe judge's weights (numbers that control behavior) at iteration t
pi_theta(y|x)the judge's predicted probability that response y is correct given input x
D_tthe filtered training batch (only examples where the judge's prediction matched ground truth)
log pi_thetaa standard way to measure how far the judge's guess is from certainty
argmax_thetafind the choice of theta that makes the formula as large as possible
A tiny worked example
Suppose the judge sees input 'prove 2+2=4'. It predicts P(correct)=0.9. Ground truth is 1.0 (it is correct). Because the judge guessed high and ground truth is high, this matches. Include example. Loss contribution: -log(0.9) = 0.10.
Next example: 'prove 2+2=5'. Judge predicts P(correct)=0.7. Ground truth is 0.0 (wrong). Judge guessed high but truth is low. Mismatch. Skip example.
Third example: 'explain Newton's laws'. Judge predicts P(correct)=0.2. Ground truth is 0.0 (wrong). Judge guessed low and truth is low. Match. Include. Loss: -log(1-0.2) = 0.22.
Training reduces loss on included examples only (0.10+0.22=0.32). Skipped examples do not pull training in conflicting directions, so updates are steady.

The key is that the filtered training batch contains only examples where the judge is already right, so training reinforces existing good patterns instead of chasing contradictions.

What can go wrong

What can go wrong

Cold-start problem: a brand-new judge is often terrible. If you start with a random judge, it will reject most examples as wrong (because it is guessing poorly), so you get almost no training data. The paper solves this by initializing the judge with a pre-trained language model (one that already knows language), not random weights.
Over-filtering on hard domains. If the judge sees very hard examples (abstract reasoning, edge cases), it may reject too many, leaving too few examples to learn from on that domain. The paper balances task types in each batch so no domain starves.
Convergence stalling if data becomes homogeneous. If all remaining examples are similar, the judge stops learning new decision boundaries. The paper avoids this by sampling across all five evaluation types and six domains uniformly in each round.
Done right: diversify your examples. By starting with a strong pre-trained model and keeping data mixed, filtering becomes a genuine noise-rejection tool instead of an accidental data starvation trap.
What a runnable demo should prove

What a runnable demo should prove

Build a small evaluator on a single task (e.g., MATH step-level verification). Generate 100 model responses to 20 math problems. Manually label which steps are correct. Split your 100 examples into two groups: (A) train a baseline evaluator on all 100, (B) train a second evaluator using rejection sampling (keep only examples where it predicts correctly). Then test both on 20 held-out problems. The rejection-sampling evaluator should have lower training variance (measured as the spread in its training loss over the batches it actually trains on, because it is not fighting self-contradiction on any example) and should generalize better to new problems (because its weights learned a single, consistent decision boundary instead of a blurry compromise between conflicting examples).

Generalization gain = (accuracy_rejection_sampling_on_test) - (accuracy_baseline_on_test)

The demo makes one thing impossible to miss: a judge trained only on examples it was already confident about learns cleaner patterns than a judge trained on every example, so it generalizes better when facing new problems.
