Code trees embed more naturally in curved hyperbolic space than flat Euclidean space, because the curved space's exponential growth matches how trees branch.

Zero assumption version

Flattening trees tears them apart

Code lives as a tree: each statement branches into smaller pieces, forming a hierarchy. The deeper the tree or the more branches, the more the hierarchy matters. Current models like GraphCodeBERT put these trees into flat space (called Euclidean space — the normal x, y, z coordinates you learn in school). The problem: a flat sheet cannot hold a tree without stretching and tearing.

When you try to cram a branching tree into flatness, related parts get pushed far apart, and distant parts collide. The model loses track of what is important. On deep trees or highly branched code, this distortion is worst. A beginner might try using better coordinates or denser lists of numbers — but no amount of coordinate tweaking fixes the fundamental mismatch, because a tree's branching grows exponentially while flat space's volume grows only by a polynomial, making the gap unbridgeable no matter how you shift the numbers.

In one sentence. Flat embeddings distort deep code trees; curved hyperbolic space matches trees naturally.

What the paper changes

What changes: the embedding space

The paper replaces the embedding space itself. Instead of putting code pieces into flat Euclidean coordinates, HypeCodeNet puts them into hyperbolic space, a coordinate system where the volume grows exponentially as you move outward (like the saddle of a horse).

The distortion metric: how much the tree gets squeezed

measured quantity  =  embedding distortion

Embedding distortion measures how far apart two pieces of code stay in the embedding space versus how far apart they should be based on the tree structure. In flat space, deep trees force distortion: close parents and children get spread far apart to make room. Hyperbolic space keeps this distortion low.

The paper estimates distortion implicitly by using the space's native structure: hyperbolic space has a distance formula designed so that exponential branching — the shape of trees — requires minimal distortion to fit.

Why it works

Why it works: space shape meets code shape

A tree has exponential width: a node with 10 children spawns 10 subtrees, each with 10 more children, yielding 100 descendants at depth 2, 1000 at depth 3, and so on. This exponential growth is the tree's defining shape. Flat Euclidean space has polynomial volume growth: as you go outward, the available room grows like the square of the distance (in 2D) or cube (in 3D). The mismatch is fatal: you cannot cram exponential branching into polynomial space without tearing.

Hyperbolic space solves this by design. In hyperbolic space, the volume available at distance r grows like an exponential of r. This exponential shape matches the tree perfectly. A code piece deep in the tree (far from the root) needs exponentially more room to encode all its descendants. Hyperbolic space provides exactly that room as natural distance, so no tearing occurs. The model then runs standard graph operations — message-passing (sharing information between neighbors) and attention (deciding which parts matter) — but using curved-space distances instead of flat ones. Because the space matches the structure, these operations preserve the code's true relationships.

Math after the picture

The hyperbolic distance formula

First in words:

The distance between two points in hyperbolic space is defined by the Lorentz model, which uses a special dot product on a curved surface. The distance grows exponentially with the nesting depth, matching tree branching.

Then the compact form:

d_hyperbolic(x, y) = arccosh(-x · y), where x and y are embeddings on the Lorentz manifold

Every symbol:

x, ytwo code embeddings (points on the hyperbolic surface)
x · yhyperbolic dot product (respects the Lorentz metric)
arccosh(...)inverse hyperbolic cosine; outputs the true distance
d_hyperbolicthe distance in hyperbolic space
A tiny worked example
Root node and direct child: hyperbolic distance = 1.0 (close, same depth band).
Root node and grandchild: hyperbolic distance = 2.3 (farther, exponential growth kicks in).
Root and deeply nested node: hyperbolic distance = 8.7 (exponential; flat space would need distance ~1000 to separate them).
Same physical distance in flat space squeezes deep descendants together; hyperbolic keeps them spread and distinguished.

The arccosh function ensures that points at the same tree depth stay close, while exponentially distant depths naturally push apart — exactly matching code structure.

What can go wrong

What can go wrong

Shallow hierarchies benefit less. Flat space handles flat structures fine. Only deeply nested or highly branched code sees the payoff. On simple linear programs, hyperbolic's power is not needed.
Numerical stability is fragile. Hyperbolic math uses the Lorentz model to stay stable, but care is needed in implementation. Small floating-point errors can push points off the curved surface.
Graph construction matters. If you build the AST poorly or miss edges, hyperbolic space cannot help, because the whole method relies on the tree structure being correct — wrong edges mean the distance calculations capture the wrong hierarchy, and no coordinate system can recover from that.
Done right: deeper trees, more gain. Test on tasks where structure is deep and branching is real. The payoff grows with hierarchical complexity.
What a runnable demo should prove

What a runnable demo should prove

Build a small code dataset with code snippets of varying depth: simple linear code, moderately nested (if-else inside a loop), and deeply nested (triple-nested loops with branches). Embed the code using both a standard flat model and HypeCodeNet. For each snippet, measure the average distance between a root and its descendants as predicted by each embedding space. In flat space, this distance will be compressed for deep nesting. In hyperbolic space, the distance will scale smoothly with actual depth.

depth_fidelity = mean(hyperbolic_distance_to_descendants) / mean(flat_distance_to_descendants); should be >= 1.5 for moderately deep code

The demo should make clear that hyperbolic space naturally handles depth: no squeezing, no collisions, and no information loss.
