Flow Matching Alignment for Few-Shot Learning

Instead of adjusting features once, take many small steps to gradually align image features to text features using a learned velocity field.

Paper explainersAll themesRepresentation & Self-Supervised Learning

When a pre-trained vision-language model like CLIP sees a new task with only a few example images, it struggles because image and text features are far apart in their shared space. Today's methods adjust features in one pass, which fails on difficult classes where the gap is wide. This paper proposes FMA: learn a velocity field (a rule for which direction to nudge features at each moment) so that image features can drift toward text features gradually over many steps, like a guided walk instead of one big jump.

Zero assumption version

One-step adjustment fails on distant features

A pre-trained vision-language model has an image encoder and a text encoder. Both produce lists of numbers (called features) that should point to the same thing when trained well. For everyday classes in the training data, they are already pretty close. But for rare classes with only a few examples, the image features and text features sit far apart in the space of possible numbers.

Today's parameter-efficient fine-tuning methods — prompt tuning, LoRA, adapters — all make one adjustment pass: tweak the model weights once, and in one forward step through the model, image features nudge toward text features. When the gap is small, this works. When the gap is large and the class is difficult (features are highly tangled with other classes), one nudge is not enough.

The core problem: One-step adjustments cannot handle complex transformations where image and text features need to travel a long distance through feature space.

The algorithm as a flow

What it actually does

Extract features

Use CLIP encoders to turn images into lists of numbers and class names into lists of numbers.

Pair features with coupling

For each class, match each image feature to its correct text feature (not random pairs).

Train velocity field

Learn a rule that predicts: from this current feature list, which direction nudges it toward the text features?

Add noise during training

Slightly corrupt image features in random directions so the velocity field learns to steer reliably from many starting points.

Inference: walk toward alignment

Start with an image feature and take many small steps in the direction the velocity field says, reaching text features gradually.

What the paper changes

What the paper moves

The paper changes how features adjust: from a single direct jump to a series of tiny nudges guided by a learned velocity field. The velocity field itself is the new trainable object — it learns the local direction to move at each moment of the transformation.

the object it moves  =  Adjustment steps and velocity field
The hidden quantity

The hidden quantity: alignment direction at each step

measured quantity  =  Velocity field accuracy

A velocity field is a rule that assigns to each point in feature space a direction vector: nudge this way. The paper's hidden quantity is how well the learned velocity field predicts the correct nudge direction that moves image features toward their correct text features.

The paper measures this indirectly by training the velocity field on paired image-text features (with class coupling to preserve category labels) and checking that multi-step inference reaches the text features, unlike one-step methods. Higher accuracy means fewer misaligned classes after inference, because each step builds on the last one, so accumulated small nudges add up to reaching the target.

Why it works

Why multi-step beats one-step

A one-step method tries to learn a direct mapping from image space to text space. When the two spaces are far apart and tangled (difficult dataset), this is like asking a neural network to learn a complicated function in one pass through the model. The network has to get every single direction right at once.

A velocity field approach is simpler: at each small moment in time, the field only needs to predict the next tiny nudge, based on where the image feature currently sits. Local adjustments are easier to learn than global transformations. By taking many steps, even small learned nudges accumulate, and the image feature drifts all the way to the text feature. The paper also uses two tricks to make this work: (1) coupling enforcement ensures that each image feature is paired with its correct text feature during training, so the velocity field learns to move class-by-class, not randomly, and (2) noise augmentation adds random perturbations to image features during training, so the velocity field learns to steer toward the target even when starting from slightly wrong positions, making it work reliably.

Math after the picture

The velocity field equation

First in words:

velocity_predicted = text_feature - image_feature + scaled_noise_offset

Then the compact form:

v_hat_t(x_hat_t | z_c) = z_c - x_0 + lambda * (1 - 2*t) * epsilon

Every symbol:

v_hat_tpredicted velocity at time step t
x_hat_tcurrent image feature after t steps
z_ctarget text feature for the correct class c
x_0original image feature at the start
lambdastrength of noise augmentation (how much random direction to add)
tprogress through the journey, from 0 to 1
epsilonrandom direction vector with magnitude ~1
A tiny worked example
Start: image_x at position [10, 15]. Target text_z at position [90, 95]. Lambda = 0.3.
At t=0 (start), noise_offset = 0.3 * (1 - 0) * [0.2, -0.1] = [0.06, -0.03].
Velocity = [90-10, 95-15] + [0.06, -0.03] = [80, 80] + [0.06, -0.03] = [80.06, 79.97].
After one step with size 0.1: image_x moves to [10, 15] + 0.1 * [80.06, 79.97] = [18, 23.8].
At t=0.5, noise_offset = 0.3 * (1 - 1) * [random] = [0, 0]. Velocity purely aims at target.
Repeat for many steps: image_x keeps moving toward [90, 95] until overlap is achieved.

The equation shows that velocity combines the direct pull toward the text feature with random perturbations early on, then relies purely on direction as steps progress.

What can go wrong

What can go wrong

Velocity field learns noisy shortcuts. If the velocity field overfits to the few examples available, it learns to point toward memorized positions instead of a general direction. The noise augmentation helps by forcing it to steer toward the region, not exact points.
Too many steps wastes computation. Taking 100 steps is slower than one-step inference. The paper uses early stopping: test different numbers of steps on validation data and pick the fastest that still aligns well. Beyond a certain point, more steps add no benefit.
Coupling strategy loses rare examples. Pairing each image to its correct text feature reduces training variety. If a class has only 2 examples, there are only 2 pairings. The noise augmentation creates synthetic variety to compensate.
Done right: velocity field + early stopping. When the field is trained with coupling and noise, and inference uses only as many steps as needed, alignment succeeds even on difficult classes with few examples.
What a runnable demo should prove

What a runnable demo should prove

Build a tiny few-shot setup: pick 2 or 3 classes from CIFAR or ImageNet, take 5-10 images per class, and use CLIP to extract features. Train the velocity field on the coupled, noise-augmented pairs. At inference, start with a test image feature, run it through the velocity field for different numbers of steps (5, 10, 20, 50), and measure how close it gets to the correct class's text feature. The demo must show that (1) more steps close the gap further, and (2) multi-step beats zero-step or one-step adjustment on the difficult classes.
