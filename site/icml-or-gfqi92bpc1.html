AMA-Bench: Evaluating Long-Horizon Memory for Agentic Applications

Measure whether an agent can answer questions about long interaction histories by testing on realistic trajectories and by rewarding memory systems that preserve causes, goals, and tool results.

Paper explainersAll themesAgents & Tool Use

This paper argues that agent memory should not be judged with short conversations alone. Real agents act over long stretches of time: they observe state, call tools, make decisions, and pursue goals that can change. A memory system fails if it stores many fragments but cannot recover what caused an outcome or what objective was active at a key moment. AMA-Bench builds a benchmark around full agent trajectories, and AMA-Agent adds a cause-focused memory structure so that later questions can be answered from what actually happened rather than from loose text overlap.

Zero assumption version

Why long agent histories are hard to remember

An agent operating over many steps produces a long record of states, actions, observations, and tool outputs. Later questions may ask about causes, missed goals, or dependencies across distant steps.

Many current memory systems retrieve text that looks similar to the question. That can fail because the needed fact may not share many words with the question, even though it is the true cause of the answer.

The paper's move in one sentence. Benchmark memory on realistic long trajectories, then structure memory around causes and objectives so that retrieval follows what mattered in the interaction.

The hidden quantity

The hidden quantity

measured quantity  =  Causal relevance of past events to the current question

The key hidden quantity is which earlier events actually determine the answer to a later question. That is not always the event with the most similar wording. Often the decisive event is the one that changed the plan, created a blockage, or altered the active objective.

AMA-Bench makes this hidden quantity visible by asking questions that require causal reconstruction. AMA-Agent tries to estimate it by storing links among events and by using tools to follow those links during retrieval.

Why it works

Why this works: good memory keeps the chain of reasons, not just the fragments

A long interaction history contains many details that are true but irrelevant. If retrieval only chases wording overlap, it may return records that mention the same objects while missing the event that actually caused the outcome. A cause-aware structure works better because it narrows retrieval toward events that change goals, block progress, or trigger later actions.

The benchmark also matters because a weak benchmark can hide a weak memory system. By using realistic trajectories and long synthetic ones, the paper makes failure visible when a system cannot connect distant steps into one coherent explanation.

Math after the picture

Rank memory items by causal usefulness

First in words:

A compact view is to retrieve the past items that best support the current question by combining direct relevance, causal connection, and objective match, while penalizing items that are only loosely related.

Then the compact form:

score(item, question) = direct_match(item, question) + causal_link(item, question) + goal_match(item, question) - distraction_cost(item)

Every symbol:

score(item, question)overall value of retrieving a past memory item for the current question
direct_match(item, question)how directly the item mentions the entities or events in the question
causal_link(item, question)how strongly the item participates in the chain that produced the answer
goal_match(item, question)whether the item occurred under the objective relevant to the question
distraction_cost(item)penalty for items that are true but not useful for answering this question
A tiny worked example
Question: Why did the purchase task fail near the end?
Item A: final error message. Direct match 7, causal link 3, goal match 6, distraction cost 1, total 15.
Item B: earlier tool output showing the card was declined. Direct match 5, causal link 9, goal match 6, distraction cost 1, total 19.
Item C: nearby chat about delivery options. Direct match 4, causal link 1, goal match 3, distraction cost 2, total 6.
The system should retrieve Item B because it explains the failure, even though it appears much earlier and shares fewer words.

The paper uses a causality-graph memory system and tool-augmented retrieval rather than this exact score, but the score captures the main idea.

What can go wrong

What can go wrong

Causal links can be built incorrectly. If the system connects the wrong events, retrieval can become confidently wrong because later reasoning is built on a false chain.
Benchmarks can still miss some real-world demands. Even a broader benchmark may omit task types, so a system that scores well here may still struggle in domains with different tool patterns or goals.
Long traces can raise storage cost. A detailed memory record may become expensive if every event is preserved, so practical systems still need summarization or pruning that keeps the important links.
Done right. The paper is useful because it moves agent memory evaluation toward the questions that matter in real long-running workflows.
What a runnable demo should prove

What a runnable demo should prove

Build a small agent workflow for shopping or travel booking. Record every state change, tool call, observation, and action over fifty or more steps. Then write questions that ask about causes, blocked objectives, and the reason a late action was taken.

Compare two memory systems: one that retrieves passages by wording overlap and one that stores event links plus goal information. The demo should show higher answer quality for the structured version because long-range questions depend on causal recovery, not only on nearby text.

memory_gain = answer_accuracy_structured - answer_accuracy_similarity

The demo must prove that long-horizon agent memory improves because storing causes and active objectives makes the needed evidence easier to recover later.
