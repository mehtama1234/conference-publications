Data Influence in Meta Learning

When a model learns from many tasks at once (meta-learning), this paper shows which tasks and individual data points actually mattered by tracking their influence through both layers of learning.

Paper explainersAll themesInterpretability

Meta-learning trains a model on many small tasks so it can quickly learn new ones. But with thousands of tasks and millions of data points, most contribute nothing while some are pure noise. This paper introduces a way to measure exactly how much each piece of data shaped the final model, accounting for the fact that influence flows through two nested layers: inner learning (per-task) and outer learning (across tasks).

Zero assumption version

Why data attribution breaks under two-layer learning

In ordinary machine learning, you feed data to a model and learn one set of weights. Each data point's importance is straightforward: remove it, retrain, and measure the damage.

Meta-learning is different. You first learn a shared set of weights (the meta-weights) by running a mini training loop on every task. For each task, the meta-weights are adjusted slightly, creating a task-specific copy. Then you measure overall performance using those task-specific weights.

The problem: when you remove a single data point, it changes the task-specific weights, which then changes the meta-weights, which then changes ALL other task-specific weights. The influence bounces between layers in a chain that no existing tool can untangle. You cannot just use the old influence-tracking techniques because they only look at one layer of learning, not two.

The method. Track influence at both layers separately, then combine them to find the full path each data point takes to the final model.

The algorithm as a flow

What it actually does

Detect influence at the inner layer

For each task and data point, measure how much it nudged the task-specific weights.

Trace upward to the outer layer

Those moved task-specific weights then altered the shared meta-weights during outer training; measure that second shift.

Add direct and indirect paths

A data point influences the final model directly (through its own task) and indirectly (through the poisoned meta-weights it feeds to all tasks); sum both.

Speed up with approximations

Computing the full paths is slow because it requires second and third derivatives; use a shortcut (EK-FAC) that captures most of the signal faster by skipping the parts that do not matter much.

Score and rank each data point

Assign an influence score to every task and every data point; rank them to identify what to keep and what to remove.

What the paper changes

What the paper changes

The paper measures and makes visible the influence of each data point on the final model by adapting influence functions (a technique for computing data importance without retraining) to the two-layer structure of meta-learning.

the object it moves  =  data attribution scores
The hidden quantity

The influence of a single data point on the meta model

measured quantity  =  influence score (task-level and instance-level)

When you remove one data point from a task, the shared meta-weights change because the task's validation performance changed. The influence score is how much that change is. For tasks, the score is how much the task's presence or absence shifts the meta-weights. For individual data points, the score combines two things: the direct hit on the task-specific weights, and the indirect hit on the meta-weights when those corrupted task-specific weights feed upward.

The paper estimates influence by tracking the training signal (which way and how hard to nudge weights) at both layers. It does not remove data and retrain; instead, it uses calculus to approximate what the retrained model would have looked like. This is millions of times faster because retraining every removal would take forever, but a mathematical shortcut predicts the outcome using the patterns already learned.

Why it works

Why tracking influence through two layers works

In ordinary learning, you optimize one objective: minimize error on training data. Influence follows a straight path: change data, so the training step signal (which direction to nudge weights) changes, so the weights change, so the error changes.

Meta-learning has two objectives nested inside each other: inner (per-task) and outer (across-task). Removing one data point changes the task-specific weights, which then changes which direction the meta-weights move. The influence has to travel through both.

The paper breaks this into parts: First, measure how the data point affects its own task-specific weights (via gradients from the inner loss). Second, measure how those shifted task-specific weights then affect the meta-weights when they feed into the outer loss. This is the indirect path. Third, if the data point touches the outer layer directly (e.g., in a task's validation set, which trains the meta-weights), measure that direct path too. Add both paths together.

Why this works: the two-layer structure is decomposable. The inner layer produces task-specific weights; the outer layer consumes them. By tracking influence separately at each level, then stitching the signals together, you get the full picture without trying to invert massive combined matrices. The trick is computing the gradient of the outer weights with respect to the inner weights—that is what shows you how much an inner change propagates upward.

Math after the picture

The influence equation

First in words:

influence = (how much data moves task weights) times (how much task weights move meta-weights) plus (direct effect if in validation)

Then the compact form:

I(z) = -grad_theta_i L_inner(z; theta_i) @ H_inner^{-1} @ grad_lambda L_outer(theta_i; lambda) + I_direct(z)

Every symbol:

zone data point
grad_theta_i L_inner(z; theta_i)the gradient of the inner (task) loss with respect to task-specific weights—how much z wants to nudge those weights
H_inner^{-1}the inverse Hessian matrix—tells you how the learned weights respond to gradient nudges; higher values mean weights are more sensitive
grad_lambda L_outer(theta_i; lambda)the gradient of the outer (meta) loss with respect to meta-weights—how much the meta-weights move when task-specific weights change
I_direct(z)the direct influence if z is in a task's validation set, calculated separately using the outer loss alone
A tiny worked example
Suppose a data point z in task 1's training set has inner gradient 0.5 (it wants to nudge task weights).
The inverse Hessian for task 1 is 2.0, meaning task weights are somewhat sensitive to nudges.
The gradient from outer loss to meta weights is 0.3 (meta-weights move slowly in response to task-weight changes).
Indirect influence: 0.5 × 2.0 × 0.3 = 0.30. That data point shifts the meta-weights by 0.30 units through the task layer.
If z is also in validation: direct influence = 0.1. Total influence: 0.30 + 0.1 = 0.40.
Another point with inner gradient 0.1 gives 0.1 × 2.0 × 0.3 = 0.06 indirect, so 0.40 vs 0.06 shows the first point is 6x more influential.

The formula captures two paths: the data point nudges its task-specific weights, which then nudge the meta-weights (indirect), plus any direct effect if the data point is in validation.

What can go wrong

What can go wrong

Inverse Hessian becomes unstable. Computing how sensitive weights are to the training signal can blow up or become unreliable if the loss surface is smooth (flat with few clear valleys). The paper addresses this with EK-FAC, a shortcut that focuses only on the weight-update directions that respond strongly to training signals and ignores the dormant ones, because dormant directions carry so little information that they amplify noise instead of signal.
Bilevel influence is expensive to compute. Tracking influence through two layers requires backpropagating through gradients (higher-order derivatives), which is slow. The paper also includes Neumann expansion, an iterative method that approximates the inverse Hessian without fully computing it, making it feasible for large networks.
Assumes tasks are independent at the outer level. The method treats each task's validation loss as independent when computing outer-level influence. If tasks share data or have hidden dependencies, influence estimates will be off.
Done right. Use the computational shortcuts (EK-FAC + Neumann expansion), validate scores by spot-checking a few removals on real data, and treat influence as a ranking tool to guide what to investigate, not as a final truth.
What a runnable demo should prove

What a runnable demo should prove

Build a tiny meta-learning task (e.g., 10 tasks, each with 20 training and 5 validation examples, on MNIST or a toy dataset). Compute influence scores for all tasks and data points. Then, in a separate run, remove the top-10-ranked high-influence tasks and the bottom-10-ranked low-influence tasks. Measure the difference in accuracy and training time. The demo should show that removing high-influence tasks hurts the model, while removing low-influence tasks does not.

accuracy_after_removal = average_test_accuracy_on_held_out_tasks_after_training_without_removed_data

The demo proves that the influence score works: when you remove low-scored tasks, model quality barely drops; when you remove high-scored ones, quality crashes. This contrast shows the score is real, not random, because the outcome changes predictably based on which tasks the score flagged as important.
