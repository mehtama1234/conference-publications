ES-dLLM: Skip tokens in early layers to speed up diffusion text generation

During diffusion language model inference, skip unimportant tokens in early layers by measuring how much each token's internal state changed since the last step.

Paper explainersAll themesEfficiency & Systems

Diffusion language models generate text by repeatedly flipping masked words to real words, step by step, using bidirectional context (the model can see all words at once, not just past words). This differs from older models that generate word by word left-to-right. The problem is that when answering with the finished model (during inference—when you are using the model after training), the model processes every word at every step, even words that have already been picked and won't change. ES-dLLM notices that the internal representations of unchanged words stay nearly identical across steps, so it skips computing those words in early layers and reuses their cached states. This cuts the work by 5 to 17 times without harming quality.

Zero assumption version

Diffusion language models waste computation on unchanged words

Traditional language models generate text one word at a time, left to right. Diffusion language models take a different path: they start with all words hidden, then repeatedly pick which ones to unmask, flipping mask tokens to real words step by step. Because they can see all tokens at once (called bidirectional attention), they can pick smarter unmasking orders—not always left to right.

The catch: at each step, the model still runs a full forward pass on every token position, even the ones already unmasked that won't change again. A token that was picked in step 3 is still being computed in steps 4, 5, 6, and so on. A beginner might think every token needs fresh processing because the hidden states of other tokens changed. But measuring closely shows the hidden state of an already-picked token—its internal representation deep inside the model—barely moves across steps. It is wasted work.

The method. Measure how much each token's internal state changed since the last step. Skip tokens with tiny changes in early layers, reusing their cached result from the previous step.

The algorithm as a flow

What it actually does

At each generation step, measure each token

Compute how much each token's hidden state (its internal representation) changed from step N-1 to step N.

Score by change and confidence

Combine two signals: how much the token's state shifted, and how confident the model is that this token is correct.

Mark tokens to skip

Flag tokens with low importance scores in early layers of the model.

Skip in early layers, reuse cache

Do not run the computation for marked tokens in the first few layers; use the cached result from the previous step instead.

Compute in later layers

Let later layers always see all tokens, so final decisions stay accurate and bidirectional context is preserved.

What the paper changes

Which tokens get computed in early layers

The paper changes which tokens the model bothers to compute in the early (shallow) layers of the model during inference. Tokens with low importance scores skip those layers and reuse their cached representation from the previous step.

the object it moves  =  early-layer token computation
The hidden quantity

Token importance: how much will this token's answer change next

measured quantity  =  token importance score

Token importance is a single number per token that predicts whether computing this token in the next layer will change its result much. It is not about whether the token is important to the final answer, but rather whether the token itself will evolve. High importance means the token's internal state is still shifting; low importance means it has settled.

The paper estimates this by watching two things: (1) how much the token's hidden state vector shifted between the last step and this one (the variation), and (2) the confidence score from the previous step—if the model was very sure about this token before, it is more likely to stay the same. Importance is a weighted combination of these two signals.

Why it works

Why skipping early layers preserves quality

Diffusion models work in layers, like a stack of filters. Early layers capture rough patterns. Later layers refine and correct. Here is what happens: if a token's internal state barely changed between step N-1 and N, running early-layer computations on it again will produce almost the same result. Reusing the cached value saves work without losing precision, because the input to those layers is nearly unchanged, so the output will be nearly unchanged too—like a light switch that is already in the on position; flipping it again produces the same state.

But skipping can only happen in early layers. Why not all layers? Because deeper layers might combine information from other tokens differently based on the full context. By the time we reach deep layers, enough cross-token communication has happened that reusing an old cache could drift from the true answer. So early layers skip, later layers always recompute, and the model keeps its ability to use bidirectional context and make good generation choices.

The importance score itself is measured from the model's own state, so it is tuned to the actual dynamics of this model on this task—not a generic heuristic. If a token's state is quiet, skip it. If it is noisy, compute it. No training needed; the framework works off the shelf.

Math after the picture

How to score each token's importance

First in words:

importance_i = confidence_i + alpha * variation_i, where confidence is the model's prediction certainty from step N-1, variation is how much the token's hidden state shifted from step N-1 to N, and alpha is a tuning constant that weights the two signals.

Then the compact form:

importance_i = conf_{i,prev} + alpha * ||H_i^{(N)} - H_i^{(N-1)}||

Every symbol:

importance_iimportance score for token i (higher means must compute)
conf_i,prevconfidence score from the previous step (0 to 1, max probability)
H_i^(N)hidden state vector of token i at step N
H_i^(N-1)hidden state vector of token i at step N-1
||...||the length or magnitude of the difference (L2 norm: square root of sum of squares)
alphaweighting constant, tuned to balance confidence and variation (often around 0.5)
A tiny worked example
Token A: confidence 0.9, variation magnitude 0.3. Importance = 0.9 + 0.5 * 0.3 = 1.05.
Token B: confidence 0.2, variation magnitude 0.1. Importance = 0.2 + 0.5 * 0.1 = 0.25.
Token A is important (1.05); skip it in early layers. Token B barely moved (0.25); safe to skip.

Tokens that are either high-confidence (already picked and locked) or whose internal state is still moving (still being refined) get high importance and trigger computation in early layers. Settled, low-confidence tokens are skipped and their cache is reused.

What can go wrong

What can go wrong

Skipping too late in the network. If you skip tokens in very deep layers where cross-token mixing is strong, different token combinations could produce very different results. Reusing a cached value will miss those changes. The paper limits skipping to early layers to avoid this.
Measuring importance with stale signals. If the variation measurement or confidence score is noisy or does not reflect the token's true evolution, low-importance tokens might actually need recomputation. The paper addresses this by combining two independent signals; if either is high, the token is computed.
Generation order matters. Diffusion models can choose which tokens to unmask in any order. The paper's importance measure assumes the current unmasking strategy. If the generation strategy changes mid-inference, cached importance scores could become misaligned.
Done right. Measure importance from the actual variation of the model's own hidden states and confidence, limit skipping to early layers, and leave later layers untouched. Quality stays high because later layers always run and preserve the model's bidirectional reasoning; speed becomes 5 to 17 times better because early-layer computation, which is repeated for many tokens and many steps, is mostly skipped.
What a runnable demo should prove

What a runnable demo should prove

Build a tiny diffusion language model on a standard dataset (like a simple story or news text, say 500 tokens max). Implement ES-dLLM by adding code to track the L2 norm of hidden state changes across steps and compute importance scores. Run generation with and without early-skipping, measuring both the throughput (tokens per second) and the similarity of outputs (ROUGE-L or exact match). Show that skipping achieves 3-5 times speedup while keeping ROUGE-L loss under 5 percent.

speedup_ratio = throughput_with_ES / throughput_vanilla; quality_loss = ROUGE_vanilla - ROUGE_ES

The demo must show that most tokens in most generation steps are safe to skip in early layers—and that the model's own internal signals correctly identify which ones.
