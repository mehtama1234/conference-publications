Agent0-VL: Self-Evolving Vision-Language Agent with Tool-Integrated Reasoning

A vision-language model learns to improve itself by using real tools to check its own reasoning and repair its mistakes without any human feedback.

Paper explainersAll themesAgents & Tool Use

When a vision-language model (a system that reads images and text together) reasons about a hard visual question, it gets stuck because it can only judge itself using words alone. This causes mistakes and false confidence. Agent0-VL fixes this by letting the model use real tools—like math calculators or image analyzers—not just to reason, but to verify its own reasoning and catch its own errors, all without any human supervision.

Zero assumption version

Vision models judge themselves badly using only words

A large vision-language model (a trained system that reads both images and text) can answer questions about pictures—like reading a chart or solving a spatial puzzle with shapes. But when it answers wrong, it has no way to catch itself. If you ask it to check its own work, it reads its previous answer in words and tries to spot the error, also in words. This fails because:

The model tricks itself. When checking a chart answer, it might invent false numbers or misread the axis without noticing, because it is reasoning only from its own text, not actually looking at the real chart again.

A beginner tries: 'Just have the model re-read its own reasoning.' But that means checking words with words—like checking a spelling test by reading it a second time. You see what you expect to see, not what is really there.

So reasoning stays stuck: the model makes mistakes and falsely judges itself as correct (because re-reading its own text gives no ground truth), which means it never learns to correct its errors.

The core problem. A vision-language model has no way to verify its visual reasoning is actually correct, because it can only use text to judge text.

The algorithm as a flow

What it actually does

Solver role

The model reasons about the image using real tools—a calculator for math, a measurement tool for shapes and distances, a chart-reading tool. It generates a multi-step reasoning trace.

Verifier role

The same model now flips to a second hat: it looks at its reasoning trace and uses tools again to check each step against the real image data.

Feedback generation

When the verifier finds a mistake (the guess does not match the tool's measurement), it writes plain feedback: what went wrong and why.

Self-reward signal

The verifier assigns a score based on whether the reasoning passed the tool-based checks, without needing any human-written labels.

Learning loop

The model learns to predict reasoning traces that will pass tool-based verification. Over time, it gets better because it tunes weights away from patterns tools reject, toward patterns tools confirm.

What the paper changes

What the paper changes

The paper changes the self-correction target: instead of having the model judge text-against-text, it grounds verification in real tool outputs. A tool gives an objective answer (a measured distance, a correct sum, a pixel coordinate) that the model's reasoning must match.

the object it moves  =  Self-correction target
The hidden quantity

Verification correctness: do the tools agree?

measured quantity  =  Tool-grounded verification accuracy

The paper introduces and measures a hidden quantity: how often the model's reasoning passes verification when checked against real tools. This is not the model's final answer accuracy—it is the meta-accuracy: does the model's self-check (when grounded in tools) correctly identify right and wrong reasoning?

The paper estimates this by having the verifier run tools on the image and compare the reasoning trace to the tool outputs. When tool output and reasoning match, verification passes. When they conflict, verification fails. The model learns the pattern: reasoning that tools will confirm is good reasoning.

Why it works

Why tool-grounded verification fixes self-judgment

The root cause of bad self-judgment was hallucination: the model re-reading its own text invents false supporting details and never catches itself. Tools break this loop because a tool's output is objective. A calculator does not hallucinate: two plus three is five, every time.

When the verifier runs tools on the actual image (not just re-reading the reasoning text), it gets a ground truth. If reasoning said the average is 42 but the calculator says 38, that gap is real and visible. The model learns: this kind of reasoning pattern led to an error I can actually prove.

Why does this work without human labels? Because tools provide the labels automatically. The tool outputs are the objective ground truth. The model's job shifts: predict reasoning that will make sense when checked by tools. Over time, the model tunes its weights to favor reasoning patterns that tools validate, and suppresses patterns that tools reject.

The self-evolving cycle is stable because it has a concrete anchor: if the model hallucinates in its reasoning, the tool will contradict it. The model cannot convince itself that hallucinated reasoning is correct if a calculator proves otherwise.

Math after the picture

Scoring reasoning with tool agreement

First in words:

The reward for a reasoning trace is the fraction of reasoning steps that pass tool-based verification, multiplied by a weight that grows as training progresses.

Then the compact form:

Reward(trace) = sum_steps [match(reasoning_step, tool_output)] / num_steps * alpha

Every symbol:

traceone complete reasoning sequence from question to answer
reasoning_stepone step in the reasoning (e.g., read chart value, add numbers)
tool_outputthe objective result from running a tool on the image
match1 if reasoning matches tool output, 0 if it conflicts
alphaa growing weight as the model improves (encourages stricter verification)
A tiny worked example
Reasoning trace: Read chart value as 42, then add 8, get 50.
Tool verification: Chart value is actually 40 (mismatch at step 1). Tool sum is 48 (mismatch at step 2).
Matches: 0 out of 3 steps matched the tools.
Reward = 0/3 * 1.5 = 0.0. Model is penalized; it will adjust.
New trace attempt: Read chart value as 40, add 8, get 48.
Tool verification: All steps match (3/3).
Reward = 3/3 * 1.5 = 1.5. Model is reinforced; this pattern gets stronger.

The model learns to output reasoning that tools will confirm as correct, step by step.

What can go wrong

What can go wrong

Tools themselves can be noisy. If a tool sometimes gives wrong answers (e.g., a chart reader that misdetects pixels), the model learns the tool's errors. The fix: use tools that are reliable, or combine multiple tools to cross-check.
Reasoning can trick the verification. If a reasoning step is vague (e.g., just say the value without showing work), the verifier might struggle to match it to a tool output. The fix: enforce structured reasoning (step by step, not shortcuts).
Some tasks need human judgment. Chart questions have objective answers (read the axis correctly), but some visual reasoning tasks may require aesthetic judgment or open-ended interpretation. Tools cannot ground those. The paper focuses on tasks with objective ground truth.
When it works. On chart reasoning, shape puzzles, and visual science tasks—where an objective answer exists and a tool can verify it—the model reliably improves, because each error produces a concrete tool-based signal showing what went wrong.
What a runnable demo should prove

What a runnable demo should prove

Build a simple chart-reasoning task: show a bar chart with numerical values. Ask the model to compute statistics (sum, average, maximum). Have Agent0-VL reason through the steps using a calculator tool, then verify each step by having the tool recompute. Let the model fine-tune itself by seeing which reasoning patterns the tool confirms. Over 50 iterations, the model should learn to reason more accurately without any human corrections; measure accuracy before and after.
