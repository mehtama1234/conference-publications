RACE Attention: Strictly Linear Time for Long Sequences

Instead of computing every token-to-token pair (which takes quadratic time), RACE Attention uses random sampling and hashing to pick which comparisons matter, making attention run in linear time.

Paper explainersAll themesEfficiency & Systems

Attention is the core engine of modern language models, but it has a fatal flaw: to compare every token (each word or subword in the input) with every other token, it needs time that grows as the square of the sequence length. For a 4-million-token document, that time becomes so vast that even the best GPU optimizations cannot finish it. RACE Attention fixes this by using two tricks: random projections (drawing samples from a geometric distribution) and soft locality-sensitive hashing (grouping similar tokens into bins), so the model only compares tokens that are likely to matter, cutting time from quadratic to linear.

Zero assumption version

Why attention with full score matrices breaks at long contexts

Attention works by creating a matrix: one row for each token (word or subword) in the input, one column for each token. Every cell holds a score saying how much the row token should 'look at' the column token. With 4 million tokens, that is 16 trillion cells—and filling them takes 16 trillion multiplications. A GPU can do billions per second, but 16 trillion still takes hours.

A beginner might hope that hand-optimized GPU code (like FlashAttention-2, which reorganizes computations to fit in fast memory caches) could just make scoring faster. In fact, FlashAttention-2 is the best such code exists today—and it still cannot run a single forward and backward pass on a 4-million-token input on a 96-GB GPU, because the underlying mathematical cost grows as the square of the token count, which is a hard physical limit of the design, not just a coding problem. No library can fix quadratic growth.

The core problem. Attention with all token pairs compares every token to every other token. With N tokens, that requires N times N comparisons, which costs time proportional to N squared. For millions of tokens, this time becomes unbearably large.

The algorithm as a flow

What it actually does

1. Replace the scoring function

Softmax uses exponential (e raised to a power); RACE uses sharpened angular similarity (angle-based scoring that treats tokens as directions in space).

2. Random projections

Map each token to a random direction; tokens near each other in that space will be compared.

3. Soft locality-sensitive hashing

Group tokens into bins based on their projected position; only tokens in same or nearby bins compare.

4. Gaussian approximation

Use random samples from a Gaussian distribution to approximate the attention weights without computing all pairs.

5. Reconstruct output

Combine the sparse, sampled comparisons to produce output nearly identical to full Softmax Attention.

What the paper changes

What the paper changes

The paper replaces the core score-calculation in attention. Instead of building the full matrix of scores (one score for every pair of tokens), RACE Attention uses a combination of random sampling and hashing to compute only the important entries of that matrix—roughly as many entries as tokens themselves (a constant times the count) instead of the count times the count.

The hidden quantity

The hidden quantity: approximation error

measured quantity  =  Difference from true Softmax output

The hidden quantity is how far RACE's output drifts from true Softmax Attention. Because RACE skips most token pairs, its output is an approximation. The paper needs to ensure that the approximation error stays small enough that the model still learns correctly—that is, the final answer is nearly as good as full Softmax Attention.

RACE estimates this error using concentration bounds from random matrix theory: when you sample tokens using random projections, you can prove mathematically that the error in the final attention output is bounded (it does not explode). The paper verifies this both in theory and by running experiments on language modeling and classification tasks.

Why it works

Why RACE works: the real causal chain

Attention works by scoring every pair of tokens. In practice, most token pairs do not matter much. If you score 1000 irrelevant pairs, most scores are tiny and contribute almost nothing to the final output. RACE exploits this: it uses random projections to find which tokens are truly similar in a geometric space, then only compares those pairs, because the skipped pairs will contribute noise that follows a predictable pattern.

Here is the chain: (1) Map each token into a random geometric space using random projections (random directions you score each token along). (2) Use soft locality-sensitive hashing to group tokens that land near each other in that space into bins (like sorting by postal code). (3) For each token, only compute attention scores against tokens in its bin and neighboring bins. (4) Use a statistical approximation to fill in the skipped scores with values that follow the right pattern. (5) The final output is nearly identical to full attention because the skipped scores were tiny anyway. The remaining error is bounded: it does not grow beyond a predictable limit.

The result is time that grows linearly with token count: instead of operations that number as the token count times itself, you do roughly the token count times a small constant (each token compared to a small constant number of others). For 4 million tokens, this is the difference between 16 trillion and 4 million operations—a 4-billion-fold speedup.

The core equation

First in words:

Attention output is the sum over tokens j of: (weight for token j) times (value of token j). RACE approximates the weight using sharpened angular similarity and random projections, then sums only over tokens j that are in the same hash bin or nearby bins.

Then the compact form:

output_i = sum over j in Bin(i) and neighbors of: exp(sim(q_i, k_j) / tau) * v_j / Z_i

Every symbol:

q_iquery vector for token i (what it is looking for)
k_jkey vector for token j (what it offers)
v_jvalue vector for token j (what gets weighted)
sim(q_i, k_j)angular similarity between q_i and k_j (how much they align)
tautemperature (how sharp the peak is)
Bin(i)the hash bin containing token i
Z_inormalization sum to keep weights between 0 and 1
expexponential function (scales scores to positive weights)
A tiny worked example
Say token i (at position 100) wants to attend to tokens. Softmax would score all 10,000 tokens in a 10,000-token sequence.
RACE hashes token 100 and finds it lands in bin 5. Tokens in bin 5 and nearby: 80 tokens total.
RACE computes scores only for those 80 tokens (80 exponentials, 80 multiplications).
For the remaining 9,920 tokens, RACE uses the Gaussian approximation: it samples a few random scores from the right distribution and adds them.
Result: 80 exact scores + 20 sampled approximations = 100 total operations per output token, instead of 10,000.
With 10,000 output tokens, that is 1 million operations instead of 100 million—100x speedup for this one attention layer.

The key is that the approximation errors are small because most skipped token pairs have tiny scores anyway; the Gaussian fills in these noise values accurately.

What can go wrong

What can go wrong

Poor random projection tuning. If the random projections are poorly scaled, tokens that should match land far apart in the random space, and the hash bins will be too coarse. The result is that important token pairs are skipped, and accuracy drops.
Hash bin size too small. If the bins are too tiny, each token is compared to almost no others, and the approximation fails. If bins are too large, you lose the speedup.
Gaussian approximation breaks down at distribution tails. The Gaussian approximation assumes that skipped scores follow a Gaussian distribution. For very long-range dependencies (a token that should attend far away), this assumption fails, and accuracy can drop on tasks requiring long-range reasoning.
Done right. RACE chooses random projection scale and hash bucket size via a principled concentration bound (a proof that the approximation error is small). This keeps the sweet spot: enough tokens compared for accuracy, few enough for speed.
What a runnable demo should prove

What a runnable demo should prove

Build a small language model (e.g., GPT-2 size, 12 million parameters) and train it on a 64,000-token text (e.g., a Wikipedia article or a long code file). Swap in RACE Attention for standard Softmax Attention. Run both for the same number of training steps. For each, measure: (1) Final language modeling accuracy (measured as perplexity, which is how wrong the model's predictions are on held-out text; lower is better, and this quantity matters because it shows the model still learned correctly despite the approximation). (2) Wall-clock time per training step (matters because the whole point is speed). (3) Peak GPU memory used (matters because memory is often the bottleneck on long sequences).

Speedup = time_softmax / time_race. Accuracy drop = perplexity_race - perplexity_softmax. Memory savings = memory_softmax / memory_race.

The demo should make it impossible to miss: RACE processes 64K tokens in the same wall-clock time Softmax takes for 4K tokens, and both reach nearly the same final accuracy.
