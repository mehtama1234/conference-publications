ReSeek: A Self-Correcting Framework for Search Agents with Instructive Rewards

ReSeek gives a search agent permission to stop, judge its current evidence, and re-plan during the same episode, while dense process rewards teach which search steps are factually correct and actually useful.

Paper explainersAll themesAgents & Tool Use

Search agents often fail in a familiar way. They commit to an early line of search, gather a few weak facts, and then keep following that path even when the evidence is no longer helping. Reinforcement learning can worsen the issue when rewards are sparse or purely rule-based, because the agent receives too little guidance about which intermediate search steps were useful. ReSeek addresses both problems. It adds a JUDGE action that lets the agent inspect the information gathered so far and revise the plan before the episode ends. It also provides a dense process reward with two parts: one for factual correctness and one for utility. The first part asks whether the retrieved information is true. The second asks whether it actually helps answer the question because answer-relevant evidence is what moves the search path toward a correct final response. Together they train a search agent that can recover from weak early paths instead of blindly continuing them.

Why search agents get stuck on weak paths

A multi-step search agent usually does not fail because it cannot type a query. It fails because it commits to the wrong direction and then keeps spending steps there. If rewards arrive only at the end, the agent receives little guidance about which earlier search choices were useful and which were merely plausible.

That makes recovery difficult. Once a poor path is underway, the agent needs a way to pause, inspect what it has gathered, and choose a better direction because otherwise the remaining steps are often spent reinforcing the same weak branch. The paper asks how to teach that self-correction behavior directly instead of hoping it appears from sparse end rewards alone.

The move. Add a dedicated JUDGE action for mid-episode self-correction and train with dense rewards that separately score factual correctness and usefulness of retrieved information.

The algorithm as a flow

What it actually does

Search and collect evidence.

Run the usual retrieval actions so that the agent gathers candidate facts for the question.

Score evidence for correctness.

Reward retrieved information that is factually right because false evidence should not support future decisions.

Score evidence for utility.

Reward information that actually helps answer the question because true but irrelevant facts still waste the episode.

Use JUDGE to inspect the current path.

Allow the agent to stop and re-evaluate its gathered evidence so that it can abandon weak search directions before the episode is over.

Re-plan and continue.

Issue a new query or choose a new evidence branch when the judged path is weak, because recovery is the paper's main behavioral goal.

What the paper changes

What the paper changes

The paper changes search-agent RL from a mostly irreversible episode into one that includes explicit mid-episode evidence review and self-correction.

the object it moves  =  search path during one RL episode
The hidden quantity

The hidden quantity: path usefulness

measured quantity  =  how much the current search path increases the chance of reaching the final answer

The central quantity is path usefulness. A search step can be factually correct and still be poor if it does not move the agent closer to the answer. That is why ReSeek separates correctness from utility instead of collapsing them into one vague reward.

The JUDGE action matters because path usefulness changes over time. A path that looked promising at the start can become weak after several retrievals. By inspecting the gathered evidence mid-episode, the agent can ask whether the current branch is still increasing the chance of success.

Why it works

Why it works

The two-part reward helps because correct evidence and useful evidence are not the same thing. A search agent needs both. Correctness discourages false support. Utility encourages evidence that actually reduces the remaining uncertainty about the question.

The JUDGE action helps because sparse end rewards do not tell the agent when to give up on a weak path. Mid-episode review provides that signal directly. Once the agent learns that some partial paths are not paying off, it can switch direction before the budget is exhausted.

These pieces reinforce each other. Dense process rewards shape the local search behavior, and JUDGE creates a structural opportunity to use that shaped behavior for recovery. The result is a search agent that is both more successful and more faithful to a useful evidence path.

The process reward

First in words:

Reward each search step by adding one part for factual correctness and one part for usefulness to the question.

Then the compact form:

reward_step = correctness_reward + utility_reward

Every symbol:

reward_stepthe process reward assigned to one search step
correctness_rewardscore for whether the retrieved information is factually right
utility_rewardscore for whether that information helps answer the current question
A tiny worked example
Suppose the question asks for the year a scientist won a prize.
A retrieved page that states the scientist's birthplace correctly may earn correctness reward because the fact is true.
It may still earn little utility reward because birthplace does not help answer the year-of-prize question.
A retrieved page that lists the award history earns both rewards because it is true and directly useful.
The agent is therefore pushed toward evidence that is both correct and answer-relevant.

The split reward is essential because truth alone does not guarantee that a search step moves the agent toward the answer.

What can go wrong

What can go wrong

JUDGE can be called too often. If the agent pauses for review on every minor uncertainty, search time is wasted because re-planning replaces useful evidence gathering.
Utility scoring can be noisy. If the system misjudges which facts are useful, it may reward the wrong branch because usefulness is harder to assess than bare factual correctness.
Recovery still depends on available evidence. A self-correcting agent cannot recover to the right answer if the retrieval system never surfaces the needed facts, because re-planning still needs a better branch to follow.
Done right. The method works when JUDGE is used sparingly and the reward distinguishes truth from answer usefulness, because then the agent learns both how to gather better evidence and when to change direction.
What a runnable demo should prove

What a runnable demo should prove

Build a multi-hop question-answering environment with search and retrieval actions. Compare a baseline RL agent against a ReSeek-style agent that has the JUDGE action and the two-part process reward. Track whether the agent changes direction after weak evidence, how often the evidence used in the final answer is both correct and relevant, and final task success. The demo should show that self-correction improves not only the answer rate but also the faithfulness of the search path because the agent learns when its current branch is not helping.

path_faithfulness = useful_facts_used_in_final_reasoning / total_facts_used_in_final_reasoning

A convincing demo must show better mid-episode recovery and better evidence quality, because ReSeek is designed to improve both path correction and final answers.
