ASTGI: Adaptive Spatio-Temporal Graph Interactions for Irregular Time Series

Build a graph on irregular observations by finding nearest neighbors in time-and-space, then update predictions by passing messages along the graph using relative positions between points.

Real-world time series often arrive at uneven times: a patient's vital signs recorded when a nurse checks, not on a fixed schedule. This irregularity breaks ordinary forecasting methods. ASTGI solves this by treating each observation as a point in space, connecting nearby points into a graph, and letting information flow across that graph to predict the next value.

Zero assumption version

Irregular time series breaks standard methods

Most time series forecasting methods (like recurrent neural networks) assume observations arrive at regular intervals: stock prices every minute, temperature every hour. They process each new value in sequence, one after the other, building an internal memory as they go.

Real data ignores this. Hospital patients get blood tests when ordered, not on a schedule. Financial trades cluster around market-open and rare at 3 AM. These irregular gaps create two problems. First, the raw timestamps and gap sizes carry information the model needs but standard methods cannot use directly without distorting the data. Second, which observations matter for the next prediction? In regular data, the most recent few values are usually relevant. In irregular data, a recent observation might be stale (recorded hours ago) while an older one recorded just now is critical. Standard methods have no way to tell.

In one sentence. Connect each observation to nearby neighbors in a time-and-space graph, then let information flow across edges weighted by relative timing and distance.

The algorithm as a flow

What it actually does

Represent each observation as a point

Encode the timestamp and features into a learned coordinate system (a mapping where similar observations are close).

Find nearest neighbors in that space

For each point, search for the closest other points using distance metric.

Build a causal graph

Connect each point only to neighbors in the past (preserve temporal order).

Pass messages on edges

Each edge carries a message weighted by the spatio-temporal distance between points.

Aggregate to predict

Sum weighted neighbor messages and apply a regression layer for final forecast.

What the paper changes

The thing that changes: neighbor connections

Instead of processing observations in fixed sequence, ASTGI creates a graph where each observation points to its nearest neighbors in both time and feature space. This graph adapts to the actual data: irregular gaps become edges of varying strength, and the model learns which neighbors matter.

the object it moves  =  neighbor connections
The hidden quantity

The hidden quantity: interaction weight

measured quantity  =  spatio-temporal interaction weight

An interaction weight is a number (between 0 and 1) that says how much one observation influences another during prediction. ASTGI computes this weight by measuring both the time gap (how recently was this neighbor observed) and the feature distance (how different is this neighbor's values from the current point). Recent neighbors with similar feature values get high weights; distant, dissimilar neighbors get low weights.

The paper estimates these weights directly from the relative positions of points in the learned coordinate system, without needing an explicit formula. Higher weights mean the model trusts that neighbor more when predicting.

Why it works

Why it works: irregular timing becomes a feature, not a bug

Traditional forecasting loses information when observations are irregular. ASTGI keeps it by building the graph adaptively. Here is the chain of why this works: First, encoding each observation (its timestamp and values) into a coordinate system (a map where similar observations are close together) gives the model a way to compare observations by how close they are in both time and feature dimensions simultaneously. Second, nearest-neighbor search finds which observations are actually relevant without assuming a fixed window size or position. In irregular data, the most recent three observations might be two seconds, ten days, and thirty days old—nearest neighbors ignore artificial time windows and pick the truly close ones. Third, when messages pass along edges weighted by spatio-temporal distance, the model is training to trust neighbors that are recent and have similar values, because those are the most predictive. A measurement ten days old but very similar to today's context is treated differently from a measurement ten minutes ago but in a totally different regime—the model learns which kind of history matters for each query.

The result: the model no longer discards the timing information; it becomes the primary signal for whether a neighbor is relevant. Irregular gaps are no longer obstacles—they are the raw material of prediction.

Math after the picture

The equation: weighted neighbor sum

First in words:

The prediction for a query point is the sum of each neighbor's values multiplied by its interaction weight, plus a learned offset.

Then the compact form:

forecast = offset + sum_neighbors w_i * v_i

Every symbol:

forecastthe predicted next value
w_iinteraction weight for neighbor i (how much it influences the prediction)
v_ithe observed value of neighbor i
offseta learned constant bias term
A tiny worked example
Query point: predict heart rate.
Neighbor 1: observed 72 bpm, time gap 2 minutes, feature distance 3 units -> weight 0.8.
Neighbor 2: observed 68 bpm, time gap 45 minutes, feature distance 12 units -> weight 0.2.
Neighbor 3: observed 70 bpm, time gap 1 day, feature distance 50 units -> weight 0.05.
Offset: +1.5.
Forecast = 1.5 + (0.8 * 72) + (0.2 * 68) + (0.05 * 70) = 1.5 + 57.6 + 13.6 + 3.5 = 76.2 bpm.
Recent, similar neighbors (weight 0.8) dominate; the old measurement (weight 0.05) barely matters.

The weights adapt to each query point, so irregular observations at different times are treated as information about which past values are truly relevant.

What can go wrong

What can go wrong

Too many neighbors in dense regions. If observations cluster in time (e.g., a device recording multiple times per second), the nearest-neighbor graph can become fully connected and lose structure. The model may overweight redundant nearby points.
Coordinate system not learned well. If the model fails to learn a good coordinate system, nearby points in the learned space may not be actually similar in the original data. The graph connections become meaningless.
Long-range dependencies disappear. If the model only learns to trust very recent neighbors, it may miss longer-term patterns (e.g., daily or weekly cycles) that occur at irregular times.
Done right. Tune the coordinate-system size and neighborhood size for your domain. Validate that high-weight neighbors are actually predictive by checking how often the model trusts them. Mix local (time-based) and global (feature-based) ranking to preserve both short and long-range structure.
What a runnable demo should prove

What a runnable demo should prove

Build a synthetic dataset: a signal that evolves smoothly, but sample it at random, irregular times. Include a second signal that is periodic (repeats every 24 steps) but arrives at random times. Implement ASTGI and a baseline that assumes regular sampling (e.g., a standard RNN that pads or interpolates missing values). Run both on the irregular dataset. The demo should show that ASTGI correctly identifies neighbors that are close in the feature space despite large time gaps, and uses them to make predictions. A baseline that treats large gaps as missing data will fail to capture the periodic signal; ASTGI will succeed.

forecast_error = mean absolute difference between predicted and actual next value, averaged over test points
