villa-X: Learning latent actions for robot manipulation

Teach robots to plan by learning a hidden middle layer between what a camera sees and what joints move, then train the full pipeline end-to-end.

Paper explainersAll themesRobotics & Control

A robot needs to understand three levels: what the camera shows (a messy video frame), what motion is happening right now (the abstract skeleton of a move), and what actual joint angles to send. Villa-X learns the middle layer first — a hidden representation of motion that sits between vision and control — then uses it to train the whole system on unlabeled robot videos, making the robot generalize to new tasks and new robots without retraining from scratch.

Zero assumption version

Why robots struggle to learn from video

A robot camera sees dense pixel soup: 1000s of numbers per frame. Raw pixels are too noisy to tell the robot what motion it should copy. The naive approach: train a big network to map pixels directly to motor commands. This breaks because the network wastes capacity memorizing irrelevant details (shadows, reflections) instead of learning the core motion. Worse, the same motion (say, reaching for a cup) looks wildly different depending on the robot's body, lighting, and camera angle. The network learns to match these surface-level pixel patterns instead of the underlying motion, because pixel matching is easier than extracting motion structure. When tested on a different robot body or lighting, the surface patterns no longer match, so the learned model fails.

Older methods tried to learn intermediate motion representations (hidden layers that express the essence of a motion) from video, but either learned them poorly (pixel reconstruction loss is a bad teacher) or integrated them loosely into training, squandering their value. The robot is left clumsy and brittle.

The problem in one sentence. Robots learn slowly from raw video because pixels hide the motion structure, and the motion structure is never explicitly grounded in the physics of the robot's body.

The algorithm as a flow

What it actually does

Step 1: Learn latent action model (LAM)

Watch unlabeled robot video, learn 8-number hidden codes that compress each motion segment into a compact number list.

Step 2: Ground in robot body

Train LAM to predict the robot's actual joint angles and positions 4 steps into the future from the latent code.

Step 3: Train actor module (ACT)

Freeze LAM, train a new network to take vision-language input and predict sequences of latent actions.

Step 4: Decode to motor commands

Another lightweight network converts each latent action into actual joint angles for any robot body.

Step 5: Fine-tune on real robot tasks

Take the pretrained system, update it on a specific embodiment (gripper or hand), then run it on new language instructions.

What the paper changes

The one thing that changes

The paper introduces an explicit intermediate layer: the hidden action code space (a set of compressed numbers that represent the skeleton of motion — what is moving, how fast, in what direction) that the robot learns before seeing any task labels. Instead of training the robot to predict joint angles directly from pixels, villa-X trains it to first predict the shape of motion in a learned abstract code space, then decode that shape into commands for any robot body. This splits the hard problem (map vision to control) into two easy ones (map vision to learned motion codes, then codes to control).

the object it moves  =  hidden action codes
The hidden quantity

The hidden quantity: proprioceptive grounding

measured quantity  =  how well latent actions predict the robot's body state

The paper measures a quantity that prior work ignored: how much does a learned latent action code predict the robot's actual joint angles and positions in the next few frames? This is called proprioceptive grounding (from proprioception, the sense of where your body is in space). If a latent code predicts future joint angles accurately, it means the code has captured the essence of motion, not just pixel patterns. The paper trains LAM to jointly minimize three losses: pixel reconstruction (see what happens next), proprioceptive prediction (predict joint angles), and codebook commitment (keep the learned codes stable). The proprioceptive loss is the key addition that anchors the learned codes to the robot's physics.

The paper estimates proprioceptive grounding by training a simple 3-layer network to map each latent action to the corresponding robot actions, then measuring the L1 error (how far off the predictions are) on held-out validation data. High grounding means the latent action contains enough information to explain the robot's motion; low grounding means it is noisy or contaminated by visual artifacts.

Why it works

Why it works: the bridge from seeing to doing

The core insight is that learning motion in two stages is easier than learning it all at once. First, villa-X learns a latent action space that is good at two things: reconstructing pixels (so it captures visual motion) and predicting joint angles (so it captures physical motion). This dual anchoring forces the latent codes to represent real motion structure, not just pixel correlations. Once the codes are grounded in the robot's body, a vision-language model can learn to predict sequences of these codes from images and language instructions. Because the codes already carry the physical semantics, the model learns faster and generalizes better to new embodiments. The robot sees an instruction, predicts latent action codes that express the motion intent, then decodes those codes into motor commands — the same codes work for different robot bodies because they represent motion intent, not body-specific details.

Why this beats prior methods: prior work either learns latent actions poorly (using only pixel loss, which ignores physics) or includes them loosely in training (training the full network once, losing the benefit of the learned codes). Villa-X forces the latent space to be physically grounded during learning, then makes the actor module treat latent actions as a first-class representation that flows through the full prediction pipeline. This explicit two-stage training and tight coupling amplifies the benefit of the learned codes.

Math after the picture

The equation that teaches the latent space

First in words:

The LAM loss combines pixel reconstruction, proprioceptive prediction, and codebook penalty. The ACT loss is a flow-matching objective that learns to predict denoising directions for latent action sequences.

Then the compact form:

LAM_loss = ||img - recon||^2 + ||[q_t+K, a_t:t+K] - pred_FDM(z_t)||^2 + beta * ||z_t - sg(e)||^2

Every symbol:

imgthe 4 frames of video the model is trying to reconstruct
reconthe pixels the latent action code predicts, piped through a decoder
q_t+Kthe robot's joint angles 4 steps into the future
a_t:t+Kthe sequence of joint commands the robot executed
pred_FDM(z_t)the proprioceptive forward dynamics model's prediction, given latent code z_t
z_tthe 8-dimensional latent action code
ethe closest learned embedding in the codebook
betaa penalty weight (typically 0.1) that keeps the codes stable
sg(e)stop-gradient: do not update the codebook based on this term
A tiny worked example: grounding in action
Suppose the model encodes a reaching motion into latent code z_t = (0.5, -0.2, 0.8, 0.1, 0.3, -0.4, 0.9, 0.2).
Pixel loss: the reconstructed video differs from the real video by 150 pixel-value units squared. Pixel_loss = 150.
Proprioceptive loss: pred_FDM(z_t) predicts joint angles (45°, 60°, 90°, 30°), but the actual robot did (44°, 62°, 88°, 32°). Per-joint error is (1, 2, 2, 2) degrees. Proper_loss = 1^2 + 2^2 + 2^2 + 2^2 = 13.
Codebook loss: the code z_t drifted 0.3 units away from its closest stored reference code. Codebook_loss = 0.1 * 0.3^2 = 0.009.
Total LAM_loss = 150 + 13 + 0.009 = 163. The proprioceptive term anchors the learned code to real motion, not just pixels.

The key is the middle term: it forces the latent code to predict the robot's actual body state in the future, grounding abstract motion number-lists in physical reality.

What can go wrong

What can go wrong

Proprioceptive signal too noisy. If robot joint sensors are unreliable (e.g. dead reckoning, no ground truth), the forward dynamics model learns garbage, and grounding fails. The latent codes become inconsistent.
Latent action sequence too short. If the learned latent actions compress motion over too few frames (e.g. 1 frame instead of 4), the code loses temporal context. Transfers poorly to new tasks.
Codebook collapse. Without the beta penalty, all learned codes converge to a single repeated number. The robot learns one motion type and fails on diverse tasks.
Done right. Villa-X grounds latent actions with clean proprioceptive signals, uses enough temporal context (4-8 frame windows), and tunes the codebook penalty to keep the learned space diverse. The latent actions then transfer across tasks and embodiments.
What a runnable demo should prove

What a runnable demo should prove

Build a small version of villa-X on a standard robotics dataset (e.g. LIBERO, which has short task videos of a single robot arm). Split the dataset: 80% train LAM only (learn latent actions without task labels), 20% validation. Train the forward dynamics model to predict joint angles from latent codes. Measure the L1 error: how far off are the joint predictions? Then train ACT on a different arm or robot body (gripper vs dexterous hand) using the same pretrained latent space. Measure task success: how many new manipulation tasks does the robot solve zero-shot?

grounding_quality = (total_joints * total_test_frames) / sum_of_L1_errors; transfer_success = (tasks_solved_on_new_embodiment / total_tasks) * 100%

If grounding quality is high and transfer success beats training from scratch on the new embodiment, the latent action space is truly grounded in motion semantics, not body-specific artifacts.
