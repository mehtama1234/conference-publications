Foreground-Aware Token Routing Vision Transformer for Real-Time Satellite Video Tracking

By routing computation only to the parts of the image containing the target, this satellite tracker gets transformer accuracy while staying fast enough for real aircraft.

Paper explainersAll themesComputer Vision

Watching a satellite video is like being handed a picture where the actual target (say, a car) is tiny and the rest is empty highway, clouds, and noise. A vision model that treats every pixel equally will waste computation on junk. FATrack instead learns to ignore most of the frame and concentrate all its thinking on where the target actually is. Ignoring junk means fewer arithmetic operations, so it runs faster. Looking harder at the target means better predictions, so it is more accurate.

Zero assumption version

Satellite tracking is stuck between two bad choices

Satellites see the world from miles up, looking straight down at fast-moving vehicles or aircraft. The camera captures a huge area with lots of empty sky, but the actual target is often just a few pixels. A tracker has to locate it frame after frame in real time, while onboard computers have almost no power budget. The problem: two opposing methods, each broken in its own way.

The old fast method, called DCF, treats the frame like a lookup table. It is quick enough to run on a satellite, but it cannot 'see' what the target really is. It just pattern-matches pixels, so it fails when the target rotates, changes size, or gets partially hidden. The new accurate method, a Vision Transformer (a deep network that divides an image into many small patches and learns which patches matter for the prediction), understands what the target is and can handle all those changes. But it processes every single patch in the frame with equal effort, even the empty useless ones, burning through computation budget in seconds. Neither method wins.

The method in one sentence. FATrack learns which patches of the satellite image hold the real target and ignores the rest, concentrating a transformer's thinking where it matters.

What the paper changes

What the paper changes

The paper changes how a transformer allocates its thinking. Instead of treating every patch equally, it adds a gating layer that scores each patch's importance and routes expensive computation accordingly.

the object it moves  =  patch routing gate
The hidden quantity

The hidden quantity: foreground likelihood per patch

measured quantity  =  foreground likelihood score

The hidden quantity is a single number per image patch: how likely is that patch to contain the target rather than background clutter. It is not the true answer (the model does not know it), but a learned prediction. Early in tracking, the model guesses based on appearance (colors, shapes). As it sees more frames, it learns patterns of where targets appear and refines its guesses.

The paper estimates this quantity by training a lightweight classifier on the target region from the first frame, then applying it to every patch in every new frame. High scores mean 'compute harder here'; low scores mean 'this is probably empty sky, spend almost nothing on it'.

Paper reading. FA-ViT learns a spatial-channel foreground scoring map that gates the routing decision. Patches with low foreground likelihood are sparsified (routed through a fast bypass); patches with high likelihood enter the full transformer.
Why it works

Why it works: concentrate thinking where targets live

Satellite images are mostly empty. A transformer that looks equally hard at every patch wastes most of its budget on junk. By learning to score each patch's relevance, FATrack redirects computation. Cheap paths skip boring regions in milliseconds. Expensive paths (the full transformer) only process patches near the target. This split is dynamic: as the target moves frame to frame, the scoring gate relearns which patches matter.

Sparsification (deleting unnecessary patches) can harm accuracy because the model loses context. The paper adds the Adaptive Scatter Module to recover that context: it reinforces tokens in the target region by combining spatial attention (patches near the target matter) and channel attention (certain color or feature dimensions matter). This glues the sparse patches back together before the final prediction, restoring the semantic coherence that sparsification threatens.

Math after the picture

The routing decision

First in words:

Final prediction = weighted sum of transformer outputs, where weights come from learned foreground scores.

Then the compact form:

target_location = sum_i ( routing_score_i * transformer_output_i ) where routing_score_i = foreground_likelihood(patch_i)

Every symbol:

routing_score_ia number from 0 to 1 indicating whether patch i is likely part of the target
transformer_output_ithe transformer model's judgment about patch i's importance to tracking
foreground_likelihood(patch_i)a learned function that outputs high values for patches matching the target appearance and low values for generic background
target_locationthe final coordinates where the tracker predicts the target is
A tiny worked example
Suppose the first frame shows the target at (100, 50) with a reddish color. The model trains and learns: red patches score high.
Frame 2: a patch at (105, 48) is red. Foreground likelihood = 0.9. Transformer output for that patch = +0.8. Contribution: 0.9 * 0.8 = 0.72.
Frame 2: a patch at (50, 200) is sky (white). Foreground likelihood = 0.05. Transformer output = -0.1. Contribution: 0.05 * -0.1 = -0.005.
Same transformer signal (-0.1) in both patches, but the red patch contributes 144 times more because its foreground score is 18x higher. The model ignores the sky.

The routing score amplifies good guesses and suppresses bad ones, so computation flows to regions where the target actually is.

What can go wrong

What can go wrong

Target changes appearance suddenly. If the target changes color (e.g., sun glint, lighting shift), the foreground likelihood scores lag. The routing gate may misfire and undercompute the real target. Recovery requires relearning from a new template, which takes frames.
Multiple similar objects in the frame. If there are several red vehicles and the target is also red, the foreground score fires on decoys too. The full transformer still wins because it sees context and the spatial patterns around the real target, but it wastes computation on false alarms. Increasing the score threshold helps because it discards marginal matches, reducing wasted computation; however, a threshold that is too high may skip the real target if its appearance weakens slightly.
Sparsification breaks long-range context. Skipping most patches means the model loses sight of distant background cues. The Adaptive Scatter Module recovers some local context, but very sparse settings may drop important semantic information needed for disambiguation.
Done right. When the target appearance is stable and the scene is not crowded with look-alikes, FATrack's routing learns fast and stays accurate. Satellite videos often meet this condition, which is why the method works well in practice.
What a runnable demo should prove

What a runnable demo should prove

Build a satellite video tracker on a toy dataset: 20 short video clips (300 frames each) with hand-marked target locations. Implement three variants: (1) standard transformer (no routing, exact baseline), (2) naive sparsification (delete 80% of patches randomly), (3) FATrack with learned foreground routing. Measure frames per second and accuracy (distance from true target location in pixels).

Speed / Accuracy trade-off: plot (inference_time_ms on x-axis, tracking_error_pixels on y-axis) for each variant.

FATrack should lie on a Pareto frontier: faster than standard transformer at the same error level (because routing skips junk), and more accurate than naive sparsification at the same speed (because learned routing directs computation to the real target). This proves that learned routing beats both blind sparsification and uniform computation.
