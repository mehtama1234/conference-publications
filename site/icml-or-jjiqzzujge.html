PULSE: Generative Phase Evolution for Non-Stationary Time Series

When time series patterns shift over time, this paper keeps the model sharp by disentangling the stable patterns from the changing ones, then rewiring how the model sees future trajectories.

Paper explainersAll themesTime Series & Sequential

Time series data in the real world — stock prices, weather, electricity demand — do not obey the same rules over time. Markets crash. Seasons change. Models trained on old patterns fail on new data. This paper names that failure mode and fixes it by borrowing physics ideas: break the data into layers (trend plus residuals), evolve each layer separately, and teach the model to ignore misleading historical assumptions when building predictions.

Why time series models get stuck

A typical time series forecasting model is trained to spot patterns: if Tuesday morning usually brings a traffic spike, or winter brings heating demand, the model learns it and predicts the next spike or season. But real-world time series do not respect those patterns forever. The patterns themselves change. A new transit line reroutes traffic. Climate shifts. The model becomes blind to that shift, because it was optimized for a frozen snapshot of the past.

We call this failure mode Phase Amnesia: the model forgets that the global context — the rules governing the data — has changed. It keeps assuming yesterday's world is today's world. A beginner's fix is to retrain the model every week. That works but is expensive and slow. A better fix would see the shift coming and adapt the pattern itself, not just the weights, because if you only adjust individual weight values you are still assuming the old patterns are correct — you are just scaling them up or down. Real adaptation requires asking whether the pattern itself has changed and learning a new one.

In one sentence. PULSE breaks time series into stable and shifting parts, updates each separately, and teaches the model to route predictions through the evolving part instead of frozen historical averages.

The algorithm as a flow

What it actually does

Split the data

Break each time series into trend (the slow drift part) and residual (deviations from the trend).

Estimate importance per layer

Measure which layer explains most variance at each point in time, because the balance between them changes as the world shifts.

Evolve each layer forward

Generate future values for trend and residual using separate evolution rules, because they follow different physics.

Route predictions through the router

A neural network router decides whether to weight each prediction through the stable trend or the adaptive residual based on current context.

Apply Statistic-Aware Mixup

When training, blend examples from different parts of the data in a way that respects their statistical properties, preventing the model from overfitting to patterns it saw in past data.

What the paper changes

What the paper changes

The paper changes what the model is allowed to assume about the future. Instead of routing all predictions through historical patterns, it makes the model explicitly learn which part of the data (trend or residual) should drive the forecast at each step, and it forces the model to evolve that part forward using the current state, not memorized rules.

The hidden quantity

The hidden quantity: evolution stability

measured quantity  =  Evolution stability (layer consistency across time)

The paper measures a hidden quantity we can call layer evolution stability: how much does the trend layer stay consistent and smooth over time, and how much does the residual layer respond to new information? Traditional models never measure this explicitly — they just learn weights and hope. PULSE estimates it by decomposing each time point into components and checking which component is driving the current forecast error.

The paper estimates this by computing the variance explained by the trend versus residual at each time step. If the trend explains 80% and residual explains 20%, and then the world shifts and suddenly residual explains 60%, that shift IS the phase evolution the router needs to detect.

Why it works

Why it works: the causal chain

The mechanism rests on a physical insight: non-stationary time series do not shift randomly. They follow identifiable layers — a slow trend (like global warming or urbanization) that changes over years, and a residual (like daily weather noise) that changes over days. Traditional models try to predict by memorizing both at once, which creates interference: the model does not know if a new observation should shift its belief about the trend or stay calm because it is just noise.

PULSE resolves this by separating the layers first, then asking: which layer should drive the next prediction? The Phase Router is a small neural network trained to answer that question at each step. When the world is stable, it trusts the trend. When the world is shifting (the residual suddenly gets large), it switches to the residual-driven path. Because the router only has to learn which layer to trust, not what the absolute values are, it can adapt to new conditions far faster than a model trying to memorize all possible futures.

Statistic-Aware Mixup amplifies this by training the model on blended data that respects how each layer's variance changes. Instead of feeding raw historical examples, training examples are mixed so that their statistical properties stay realistic — no fake combinations where the trend jumps 10x while residual shrinks. This teaches the model to recognize genuine shifts and ignore spurious patterns.

The prediction rule

First in words:

The forecast is a weighted sum: the trend's forecast times the router weight for trend, plus the residual's forecast times the router weight for residual. The weights depend on the current context and are chosen to minimize error on recent data, not historical averages.

Then the compact form:

y_hat_t = r_t * trend_t + (1 - r_t) * residual_t

Every symbol:

y_hat_tthe model's forecast at time t
trend_tthe evolved trend layer's prediction
residual_tthe evolved residual layer's prediction
r_tthe router's confidence in the trend (a number from 0 to 1, learned from context)
A tiny worked example
Suppose at time t=100 the trend model predicts electricity demand of 800 MW (slow seasonal pattern).
The residual model predicts 50 MW (unexpected spike, e.g. a heat wave arrived).
The router observes the last 7 days and learns: residual has been big and helpful (r_t = 0.3, giving residual more weight).
Forecast = 0.3 * 800 + 0.7 * 50 = 240 + 35 = 275 MW (heavily weighted toward recent surprise).
If instead the residual had been quiet for weeks (r_t = 0.9, trend-dominated), forecast would be 0.9 * 800 + 0.1 * 50 = 725 MW (trusting seasonal norm).

The router is learned from recent context, not memorized; it adapts as the phase evolves.

What can go wrong

What can go wrong

If the layers do not actually separate. Some time series are tangled: the trend and residual are correlated. If a data set has no clear trend (e.g. random coin flips), decomposition fails and the router cannot make a clear choice. The method assumes the data has real distinct layers.
If the phase evolution is too fast. PULSE evolves layers forward using the learned evolution rules. If the world changes faster than the model can adapt (e.g. a sudden crash), the evolved future will still miss the shock, because the router and evolution mechanism learn from recent patterns and extrapolate them — they cannot predict unprecedented jumps. The model can only adapt as fast as its learning mechanism allows, which means it needs to see several examples of the new pattern before it can internalize it.
If the router overfits to recent noise. The Phase Router is trained to assign weights based on recent context. If the recent context is just random noise, the router will overfit and make bad decisions, because it will learn that random patterns are predictive when they are not. Statistic-Aware Mixup helps by preventing fake statistical combinations, but a very noisy period can still trick it because the blending respects the data as it comes — if the data itself is genuinely noisy, the mixup preserves that noisiness.
Done right. If the time series has clear distinct layers (trend plus noise), the world shifts gradually (not catastrophically), and the router trains on diverse enough data, PULSE stays accurate and adapts continuously.
What a runnable demo should prove

What a runnable demo should prove

Build a synthetic non-stationary time series: a trend line that slowly rotates (e.g. demand rises steeply for months, then flattens), plus noise that varies in scale. Train a baseline (static weights) and PULSE on the first 60% of data. Test both on the final 40%, where the trend has clearly rotated and the noise scale has doubled. Measure accuracy (mean absolute error) at the boundary where the phase shift happens, and 10 steps into the future.

Degradation = accuracy_at_shift - accuracy_before_shift. Show that the baseline loses 20+ points but PULSE loses fewer than 5.

The demo must make it impossible to miss that PULSE keeps predicting accurately even after the world changes, while the baseline falls apart the moment its assumptions are violated.
