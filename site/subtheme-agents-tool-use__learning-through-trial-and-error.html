Learning Through Trial and Error

Papers about training agents to get better by trying things, getting feedback, and adjusting their strategy — reinforcement learning for tool use.

All themesField mapMathematicsAll explainers
What this is

The core idea here is that agents learn by doing. You give the agent a task, it tries something, gets feedback on how well it worked, and adjusts its strategy next time. This is reinforcement learning — the agent gets rewarded for good moves and punished (or gets nothing) for bad ones. Over time, it figures out patterns: 'oh, when the problem looks like this, calling that tool first usually works' or 'I should check my answer before declaring victory'. The agent doesn't need to be explicitly programmed for every situation; it learns from experience.

The challenge is that reinforcement learning is slow and fragile. If an agent tries random things, it wastes a lot of time on bad moves before finding anything that works. A single mistake (like calling the wrong tool) can send it down the wrong path, and it has to learn that the hard way. Real-world tools also give messy feedback — sometimes they fail silently, sometimes they return confusing errors, sometimes they work but give unexpected results. The agent has to learn to interpret all of that and adjust. And if you change the tools even slightly or give it a new type of problem, it might have to relearn from scratch.

Papers in this area work on making that learning faster and more reliable, because waiting weeks for an agent to learn is impractical and random exploration wastes compute. Some focus on designing rewards so the agent gets useful feedback at each step, not just at the end, which means the agent knows sooner when it is on the right track. Others work on better algorithms that learn from fewer trials so agents don't have to try thousands of bad ideas before finding good ones. Some papers explore how agents can reuse knowledge from one set of tools to bootstrap learning on new tools, so they don't start from zero every time — that matters because most real problems use similar tools, and an agent that can transfer what it learned saves training time. The goal is to make learning practical enough that you can train an agent in reasonable time and have it actually become reliable.

How the work breaks down

The papers in this area split into five main directions: first, agents that learn when to ask for help or adjust their reasoning depth based on context instead of always thinking the same way; second, agents that learn internal models of their environments so they can plan ahead rather than just reacting; third, agents trained on synthetic data and simulated interactions to become generalists across many tools; fourth, agents that learn from their own failed attempts by relabeling trajectories to extract useful lessons; and fifth, systems that optimize local rewards across multiple agents or components to align everything toward a shared goal.

Learning When to Defer to Humans

The core problem here is that agents often waste resources doing everything themselves when they should sometimes defer to experts, or they reason in the same depth regardless of the problem's difficulty. An agent that knows when a problem is hard enough to justify calling a human or using an external tool will avoid wasted work on problems too difficult for it to solve alone. When quick reasoning is enough, the agent saves cost by not spending compute unnecessarily. Because the agent can route hard problems to experts and solve easy problems cheaply, such an agent will outperform one that always tries to solve everything on its own.

Adaptive Collaboration with Humans shows that agents can learn a policy for when to ask humans for help and when to solve things on their own, because you can train the system on feedback that rewards good hand-off decisions. The system, called LIMA, builds a layer that watches the current problem and decides 'this one I should hand off' or 'I can handle this myself'. On math and problem-solving benchmarks, this beats systems that either always solve alone or always ask for help, because the learned policy is adaptive to the specific problem. Adaptive Social Learning via Mode Policy Optimization takes a different angle: instead of asking for help, it learns to adjust how deep it thinks. The agent uses less reasoning on easy problems and more on hard ones, because easier problems don't require as many steps and cost less to solve quickly. Some problems only need quick reasoning, but others need careful steps. The system adapts the depth of its thinking to the context, achieving 15.6% higher task accuracy than a fixed reasoning model while using 32.8% shorter thinking chains—this means the agent is both smarter (higher accuracy) and faster (fewer steps). Both papers show that learning this kind of judgment requires data and training, not just engineering, but the payoff in accuracy and efficiency makes that investment worthwhile because you get better results with lower cost.

Learning Environment Models for Planning

One of the biggest bottlenecks in reinforcement learning is that agents have to try thousands of actions to learn anything. If an agent could learn a fast internal model of how the world works (what the effect of each action will be), it could imagine ahead, figure out a good plan, and then execute it, using far fewer real interactions. The problem is building a model that is actually accurate enough to trust for planning, because if the model is wrong, the plan will be wrong too.

Dyna-Mind tackles this by training agents to learn simulation ability—a model of the environment that can predict what happens when the agent takes an action. On long-horizon planning tasks like Sokoban and web automation, the system uses both the outcome (did we succeed) and the intermediate states (what happened in the middle) to improve its model, which makes the feedback richer and more informative. This gives the planning algorithm better signals to work with, so it can steer toward good plans faster because it knows which intermediate steps lead toward the goal. Dual-Scale World Models for LLM Agents works on a related problem: agents exploring hard problems with sparse rewards. The system learns two models at different scales, one for high-level planning and one for details, which lets the agent reason at different levels of abstraction. This ability to switch between abstract and detailed reasoning allows it to explore vast spaces far more efficiently than pure RL, because the high-level model quickly rules out bad directions while the detailed model fine-tunes good ones, resulting in solutions with 100-800 times fewer environment interactions. Agent World Model trains agents entirely in synthetic environments, which is much faster than real-world interaction, and then checks if that knowledge transfers to real problems. A synthetic but consistent world is better for learning than trying to learn from messy, inconsistent real feedback, because the agent can iterate many times without having to wait for slow tools or pay for expensive API calls.

Learning from GUI and Visual Interaction

Agents that interact with computers through screens—clicking buttons, reading text, scrolling—face a unique challenge: the visual input is huge, most of it is irrelevant, and the feedback (whether a task succeeded) might not come until many steps later. Learning to coordinate vision, action selection, and long-horizon planning all at once is difficult, because screens change with every click and the agent has to remember what it's trying to achieve while navigating visual clutter.

GUI-Shift shows that agents can learn from unlabeled trajectories (videos of other agents interacting with screens) using self-supervised learning, so you don't need humans to label every frame. This is cheaper than getting human labels for every action, because labeling videos is tedious and expensive work. The system trains on raw GUI screenshots and achieves 11.2% accuracy gains on both GUI automation and visual grounding tasks. K2-Agent tackles learning on mobile devices, where screens are small and apps are diverse. The system learns a dual representation—one for 'knowing what' (understanding the current state) and one for 'knowing how' (deciding what action to take), which lets it separate perception from action selection. It operates on raw screenshots with only open-source models and reaches 76.1% success on complex mobile tasks, showing that you don't need expensive proprietary models. MobileIPL improves GUI agents through iterative preference learning: it watches which trajectories lead to success and which fail, then adjusts what the agent learns to prefer good moves over bad ones, which is faster than getting human judgments. This preference signal is much cheaper than asking humans to label every frame, because you compute preferences automatically from outcome labels. GuirlVG uses reinforcement learning with empirical exploration on just 5.2K training samples—far fewer than supervised methods which need 10M+—because RL with the right reward signal can outlearn humans with vastly less data.

Learning Tool Use in Synthetic Environments

Training an agent to use arbitrary tools is hard because real tools are often slow, expensive to query, or unreliable. Synthetic environments let agents practice at high speed without burning money or waiting for tool responses. The challenge is making the synthetic practice transfer to real tools.

Generalizable End-to-End Tool-Use RL addresses this directly through CodeGym, a synthetic environment where agents practice calling code libraries, web APIs, and search functions. Training in a diverse synthetic environment from the start makes agents generalize much better than fine-tuning on real data, because they see many tool patterns early and learn to recognize patterns they've never seen before. A Qwen model trained in CodeGym gains 8.7 points of absolute accuracy when tested on new tool benchmarks it never encountered during training. In-The-Flow Agentic System Optimization builds an integrated system that learns planning and tool selection together, not separately. AgentFlow combines visual understanding, tool calling, and reasoning in one end-to-end policy, achieving 14.9% accuracy gains over GPT-4o on search tasks and 14.5% on math, even though it uses a much smaller model. ScaleEnv demonstrates empirically that scaling the diversity of the training environments is the single biggest factor for generalizing to unseen tools. Agents trained on more different synthetic environments beat agents trained on more iterations in the same environment. Safe and Scalable Web Agent Learning via Recreated Websites shows this principle in practice by training agents on recreated synthetic websites, then showing they generalize to unseen real websites and achieve site-specific mastery through self-evolving training, proving that synthetic environments can be a complete training pipeline.

Learning from Failed Attempts and Trajectory Relabeling

Many agent trajectories are long, and in the middle, the agent might take wrong turns. Standard RL throws out the entire trajectory as a failure, wasting the information in it. But each failed attempt contains information: you can see where the agent went wrong and what would have worked instead. Learning from those failed attempts without having to hire a human to label each one is both cheaper and faster than collecting only successful demonstrations, because failed attempts are free data that you already have.

Spinning Straw into Gold solves this by relabeling failed trajectories in hindsight: if an agent tried multiple paths to the same goal and some succeeded while others didn't, you can give the failed paths credit for the parts that were actually correct, so each failed run teaches the agent something useful. For long-horizon tasks where a single wrong turn early on ruins everything, this approach is valuable because you capture what the agent learned even when the final outcome was wrong, extracting signal from otherwise worthless data. Using this method with only one-quarter of the ground-truth demonstrations, the system beats training on the full dataset, showing you can compensate for less supervision by learning from failures. Failure is Feedback takes the opposite perspective: instead of relabeling old attempts, use the current failure as a signal to decide whether to escalate to more expensive reasoning. If a quick attempt fails at something simple, do more exploration. If it fails at something hard, it might be worth calling an expensive LLM. The system makes this trade-off smartly, reducing the cost of running the model while staying accurate, because you only pay for deep reasoning when the problem is actually hard, avoiding wasted compute on easy cases. ReSeek focuses on search agents that get stuck and can backtrack. When an agent realizes it went down a dead end, it can propose alternative paths to try, which gives the search a second chance. The system uses instructive rewards that teach the agent not just what failed, but why—making the learning more durable because the agent understands the failure reason, not just the outcome. Formalizing Learning from Language Feedback provides theoretical backing: it proves that in certain settings, learning from natural language feedback (explanations of why something went wrong) can be exponentially faster than learning from simple numerical rewards, because the language carries much more information about what went wrong and how to fix it.

Optimization of Compound Multi-Agent Systems

When you have multiple agents or multiple components working together, you can't always train them all from scratch as a single unit. Instead, you need local reward signals that let each component improve on its own piece of the problem, which means each part doesn't need to wait for the whole system to improve. This way, each component learns faster, because it gets immediate feedback on its own work, while still coordinating toward a global goal. This is the challenge of compound system optimization.

Textual Equilibrium Propagation solves this by framing prompt optimization as a local learning process. In a system with multiple language models or agents, each one can adjust its prompt based on feedback from downstream tasks, without needing to compute and push updates across the entire system all at once, so each agent can learn independently. The system learns to optimize locally (each component adjusts itself) while maintaining global coherence across long-horizon tasks, because the local adjustments gradually align. AgentPO improves multi-agent collaboration by giving each agent its own reinforcement learning signal based on how well its contribution helped the team, so each agent optimizes its own contribution to the team score. With only 500 training samples, the system gains 1.8% to 7.2% on math reasoning while cutting model execution costs to 7.8% of baseline (the time and compute spent running the model), showing that localized learning is efficient. Optimas generalizes this: it finds locally-aligned rewards for each component in a compound system so that when each piece optimizes its local reward, the whole system optimizes the global goal, turning the global problem into independent local problems. Tested on real-world compound AI systems, it beats strong baselines by an average of 11.92%, showing this approach works in practice. GraphFlow wraps this in a workflow management layer: different agents run on different tasks in a directed graph, and the system learns not just the individual policies but also the structure of how they interact, which means you don't waste compute on unnecessary agent calls. This reduces memory footprint by 4x while improving accuracy by 4.95 percentage points, a win on both efficiency and quality.
