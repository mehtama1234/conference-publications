Optimizing Relational Graphs for Deep Learning

Relational databases work better with graph neural networks when you remove unrelated connections and add task-specific ones.

Paper explainersAll themesGraph & Geometric Learning

A relational database (a collection of linked tables, each with rows and columns) can be converted into a graph to use graph neural networks (a model designed to reason about connected data). But graphs built directly from database schemas often contain too much irrelevant information or miss important connections. This paper shows which graphs actually work and builds an automatic tool to fix them.

Zero assumption version

Database schemas become messy graphs

A relational database is a set of linked tables: one table for customers, one for purchases, one for products, with connections showing which customer made which purchase. To use a graph neural network on this data, you convert each row to a node and each link to an edge.

A naive approach: just build the graph exactly as the schema defines it. But schema-driven graphs suffer from two problems. First, they contain far too many connections — many relationships in the schema are irrelevant to your actual task (if you want to recommend products, you do not need every technical detail about warehouses). This clogs the network because the model wastes capacity processing unrelated signals. Second, the schema misses relationships that matter for your task — it never directly connects two customers who bought the same product, even though that connection would help you find similar customers because you could use one customer's purchases to predict the other's. The result: the model struggles to reason about the data.

A beginner would try just using the raw schema graph as-is, but this fails because the model gets distracted by irrelevant information and misses the task-specific patterns it actually needs.

In one sentence. The paper removes irrelevant edges from the database graph (which distract the model) and adds task-aligned edges (which reveal important patterns).

The algorithm as a flow

What it actually does

Start with a database schema

Tables linked by primary-key and foreign-key relationships.

Identify irrelevant edges

Test each edge by removing it and measuring accuracy. Edges whose removal leaves accuracy unchanged carry no useful signal for the task.

Filter: remove those edges

Cut the irrelevant edges from the schema to create a cleaner graph.

Identify missing task-aligned edges

Find edges not in the schema but that testing predicts would raise accuracy if added.

Inject: add those edges

Add the new edges to the graph; the model now has explicit paths for task-relevant patterns.

What the paper changes

What the paper changes

The object being changed is the set of edges in the graph — the connections between database rows. The paper removes task-irrelevant edges because they waste the model's reasoning capacity on signals unrelated to the prediction target. It adds task-aligned ones because they reveal patterns that help the model predict the outcome. The result is a graph where every edge carries signal.

The hidden quantity

Task alignment: whether an edge helps or hurts

measured quantity  =  Task-alignment score of each edge

The hidden quantity is an alignment score for each edge: a measure of whether including that edge in the graph will help or hurt the model on your specific task. An edge showing which product a customer bought is highly aligned with a recommendation task because the model uses that signal to predict future purchases. An edge showing which warehouse a product is stored in is misaligned because warehouse location does not predict what customers will want.

The paper estimates this alignment automatically by testing different combinations of edges and measuring which ones improve the model's accuracy on validation data. For example, it removes a warehouse edge and re-trains; if accuracy improves, that edge was misaligned and worth cutting because removing noise allowed the model to learn better. If accuracy stays the same, the edge adds no signal. It then uses this information to decide which edges to keep and which new ones to add.

Why it works

Why removing and adding edges improves performance

A graph neural network reasons by passing messages along edges: each node combines information from its neighbors. If the graph includes irrelevant edges, the node receives noisy, distracting information. An edge from a customer to a warehouse location is a distraction because warehouse location does not correlate with what that customer will buy. The model's reasoning capacity is spent processing a signal unrelated to the task. Removing that edge forces the model to focus on relevant signals only. The model learns faster and more accurately because it can devote all its capacity to signals that actually predict the outcome.

Conversely, if the graph is missing task-aligned edges, the model cannot reason about important patterns. For a recommendation task, it helps to know which customers bought similar things (because customers who bought the same things tend to like the same things), but the database schema often does not include that edge (it would require computing similarities between customers). Adding such edges gives the model a direct path to reason about customer similarity, which is predictive of future purchases.

The paper discovers which edges are helpful by training models on subsets of the schema edges and measuring accuracy. If removing an edge lowers accuracy, that edge was helpful and should stay because it was carrying predictive signal. If removing it improves accuracy, the edge was harmful and should go because it was adding noise. New edges are added only if testing shows they improve accuracy, meaning they reveal patterns that help predictions. The result is a graph where every edge contributes to the task, and the model can reason more efficiently because it processes less noise and has explicit paths for the patterns that matter.

The filtering and injection formula

First in words:

For each edge, compute its contribution to validation accuracy; keep edges with positive contribution, remove edges with negative contribution. For missing edge pairs, inject those with the highest predicted contribution.

Then the compact form:

accuracy_final = accuracy_base + sum_kept_edges(contribution_e) + sum_injected_edges(value_e)

Every symbol:

accuracy_finalthe model's final accuracy on your task
accuracy_baseaccuracy with a minimal default graph
contribution_ehow much edge e improves or hurts accuracy
value_epredicted benefit of injecting edge e
A tiny worked example
Suppose a recommendation task has 10 edges in the raw schema.
Test edge A (Customer→Warehouse): removes it, accuracy drops 2%; contribution_A = +2 (keep it).
Test edge B (Order→Supplier): removes it, accuracy stays 98%; contribution_B ≈ 0 (neutral, can drop).
Test edge C (Customer→Location): removes it, accuracy rises 1%; contribution_C = -1 (drop it).
Inject new edge D (Customer→Customer, similar taste): test adding it, accuracy rises 3%; value_D = +3 (add it).
Keep A (+2) and D (+3), drop C (-1): final = base + 2 + 3 = 5 points of task-aligned improvement.

The actual paper uses a neural architecture search to tune which edges to keep and add; this formula captures the intuition.

What can go wrong

What can go wrong

Over-filtering: cutting too many edges. If you remove edges too aggressively, you lose real connections the model needs. The paper addresses this by measuring alignment by testing each edge on validation data rather than using heuristics or guesses.
Missing the right injections. If you inject the wrong edges (e.g., random pairings), you add noise without signal because the model wastes capacity on irrelevant patterns. The paper injects only edges that it has tested on validation data to confirm they raise accuracy.
Task mismatch. An edge that is highly aligned for classification might harm recommendation. The optimizer is task-specific; using the optimized graph for a different task may degrade performance.
Done right. The paper tests each filtering and injection choice on held-out validation data before using it. If removing an edge lowers validation accuracy, it stays because the test proves the edge was helping. If adding an edge raises validation accuracy, it is added because the test proves the edge improves predictions. Only changes that improve validation accuracy are applied, ensuring the final graph is genuinely better because all modifications have been measured and verified to raise accuracy.
