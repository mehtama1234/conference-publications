NePTune: Neuro-Pythonic Compositional Reasoning

NePTune teaches vision-language models to break down complex visual problems by writing Python programs that blend soft logic (fuzzy true-or-false) with clear computer code.

Paper explainersAll themesAgents & Tool Use

Vision-language models (systems that read images and answer questions about them) are good at recognizing objects, but they fail when asked to solve problems that need multiple steps of reasoning. For example, if you show it a picture and ask "count the red circles inside the triangles," the model might recognize circles and triangles separately but struggle to combine them logically. NePTune fixes this by letting the model write its own Python code — normal computer programs that use fuzzy logic operators (soft versions of AND and OR) instead of crisp true-or-false rules.

Zero assumption version

Why do vision-language models fail at compositional reasoning?

A vision-language model is a system that looks at images and answers questions. It works well when the question is simple ('what is that?'), but it breaks down on questions that require multiple steps, like 'how many red objects are inside the boxes?' The model can recognize individual objects (red, boxes) but cannot reason about the spatial relationships or counts that link them together.

Existing neuro-symbolic systems try to solve this by writing crisp logical rules — statements that are absolutely true or absolutely false. But real visual data is messy. A pixel might be somewhat red, somewhat orange. The answer might be close to 5 objects, not exactly 5. Rigid logic cannot handle that fuzziness.

In one sentence. NePTune lets models write Python programs that mix fuzzy logic (degrees of truth) with clear computational steps.

The algorithm as a flow

What it actually does

Step 1: Parse the question

Take a natural language query and identify what composition is needed.

Step 2: Generate program structure

Translate the query into a Python skeleton with imperative steps (loops, conditionals).

Step 3: Fill in perception calls

Insert calls to the vision model to extract features, counts, or relationships from the image.

Step 4: Connect with soft logic

Use fuzzy AND, OR, NOT to combine perception results, handling uncertainty.

Step 5: Execute and output

Run the program end-to-end, getting a final answer that respects both visual evidence and logical structure.

The hidden quantity

Compositional expressiveness: the degree of logical complexity a system can handle

measured quantity  =  Compositional expressiveness

Compositional expressiveness is a measure of how many logical steps a system can chain together, and how flexibly it can recombine concepts. If a model can only answer 'what color is that object,' it has low expressiveness. If it can answer 'count the red circles inside rotated triangles and divide by the number of blue triangles,' it has high expressiveness. NePTune measures this by testing the model on queries that require decomposing and recombining more and more concept layers. The paper estimates expressiveness by checking whether the model generalizes to compositions it has never seen during training.

Why it works

Why soft logic in Python solves compositional reasoning

When a vision model looks at an image, it produces a confidence score for each thing it detects — a number between 0 and 1 that says how sure the model is, like 'I am 87% sure that pixel is red' or 'I am 92% sure this region is a circle'. Traditional neuro-symbolic systems force these into absolute yes-or-no answers, which throws away information. NePTune instead keeps the confidence numbers and passes them to soft logic operators. Soft AND multiplies two confidence scores together (so if the model is 87% sure of red and 92% sure of a circle, soft AND gives roughly 0.80, meaning 'both are pretty likely'). Soft OR takes whichever score is bigger, meaning 'at least one is likely'. By letting Python execute steps one after another and combining these soft scores, the model can now reason step-by-step about relationships and dependencies without losing the visual model's uncertainty. Python's control flow (for-loops, if-statements) provides the compositional glue — different programs handle different question structures, and the model learns to pick the right program for each question.

The soft logic operators: fuzzy AND and OR

First in words:

soft_AND(a, b) = a * b; soft_OR(a, b) = max(a, b); soft_NOT(a) = 1 - a. A program combines these to build composite reasoning.

Then the compact form:

result = sum over all boxes of [ soft_AND(confidence_box[i], sum over red_objects_in_box[i] of confidence_red[j]) ]

Every symbol:

confidence_box[i]how confident the vision model is that region i is a box (0 to 1)
confidence_red[j]how confident the vision model is that region j is red (0 to 1)
soft_AND(a,b)multiply two confidence scores; 0.9 AND 0.8 = 0.72
soft_OR(a,b)take the max of two scores; 0.3 OR 0.6 = 0.6
resultthe final count, weighted by confidence at every step
A tiny worked example
Image has 3 boxes and 10 red objects scattered.
Vision model: Box 1 confidence 0.95, Box 2 confidence 0.88, Box 3 confidence 0.70.
Inside Box 1: 2 red objects at confidence 0.92, 0.85. soft_AND(0.95, 0.92) = 0.87; soft_AND(0.95, 0.85) = 0.81. Contribution: 0.87 + 0.81 = 1.68.
Inside Box 2: 1 red object at 0.90. soft_AND(0.88, 0.90) = 0.79. Contribution: 0.79.
Inside Box 3: 0 red objects. Contribution: 0.
Total weighted count: 1.68 + 0.79 + 0 = 2.47, reported as 2-3 red objects in boxes (the fractional answer preserves uncertainty).

The soft AND operator preserves the vision model's confidence at each step, so a low-confidence detection automatically contributes less to the final answer.

What can go wrong

What can go wrong

Cascading low confidence. If each step in the reasoning chain has a confidence of 0.95, 0.90, 0.85, and 0.80, then multiplying them together gives only 0.58, meaning the final answer has lost most of its certainty. Long chains of reasoning can bottleneck at the end, making the final answer too uncertain to rely on.
The vision model lies to the program. If the vision model confidently misidentifies a color or shape, soft logic will pass that error forward with confidence, treating the false information as true. The program can only be as accurate as the perceptual input it receives.
No explicit error handling. If a query asks for 'the color of the triangle' but the image has no triangles, the program still runs and returns a low-confidence guess rather than explicitly saying 'no triangle found in this image.'
Right: moderate confidence with step awareness. Systems that track where confidence drops and ask the vision model to re-examine uncertain regions do better, because they avoid confidently propagating weak perceptual signals. Similarly, systems that request human confirmation when a chain drops below a confidence threshold catch errors before they cascade.
What a runnable demo should prove

What a runnable demo should prove

Build a demo that asks a vision model to count or reason about spatial relationships in an image using natural language, and have it generate a Python program internally. Test on three datasets: a training set (shapes the model saw during training), a held-out set (shapes the model learned but not in that exact combination), and an unexpected set (objects, colors, or spatial arrangements the model has not encountered). Measure both accuracy (does the answer match ground truth) and compositionality (the ratio of accuracy on unfamiliar combinations to accuracy on trained combinations). A high ratio means the model is truly reasoning, not just memorizing patterns it has seen before.

compositional_generalization = accuracy_on_unfamiliar_combos / accuracy_on_trained_combos. A base model might score 0.32 (32% accuracy on unfamiliar combinations relative to trained accuracy). NePTune should score 0.78 or higher.

The demo must show that soft logic-based program generation lets the model reason about combinations it never trained on, not just memorize patterns. The compositional generalization ratio is the proof: if that ratio is high, the model has learned to combine concepts, not just recall them.
