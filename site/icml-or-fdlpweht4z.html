REAL: Resolving Knowledge Conflicts in Visual Question Answering

REAL teaches a visual question answering model to locate the exact reasoning link that depends on outside knowledge, then use that link to detect and resolve conflicting evidence.

Paper explainersAll themesMultimodal

Knowledge-intensive visual question answering fails for a simple reason: retrieval brings back facts of mixed quality, and the model has to decide which fact actually fits the image and the question. A long reasoning chain hides where the conflict starts. REAL breaks the chain at the points that rely on external knowledge, marks those points explicitly, and then uses them to guide both conflict detection and decoding.

Zero assumption version

Retrieved knowledge can disagree, and the model often has no clean way to isolate the disagreement

In knowledge-intensive visual question answering, the image alone is not enough. The model must combine what it sees with outside facts. For example, it may need to identify a monument, a historical event, or a scientific object that requires background knowledge. Retrieval systems fetch candidate evidence from open sources, but these sources can be noisy, incomplete, or mutually inconsistent.

Most pipelines simply feed the retrieved text into the model and hope the model will sort out the contradictions inside a full reasoning chain. That is weak control. If the model cannot point to the exact step where an outside fact enters the argument, it also cannot test whether that fact conflicts with the image or with other retrieved facts. The final answer then becomes sensitive to whichever evidence fragment dominates decoding at that moment.

The problem: When conflicting evidence is mixed into a long reasoning chain, the model needs a way to identify the exact knowledge link that is causing the error.

The algorithm as a flow

What it actually does

Read image, question, and retrieved evidence

The model starts with visual input plus candidate knowledge from retrieval.

Extract reasoning pivots

It marks the specific reasoning units whose completion depends on outside evidence.

Train a conflict discriminator

Supervised fine-tuning teaches the model to spot when those pivots are supported or contradicted.

Guide decoding with pivot checks

During answer generation, decoding is nudged away from text sequences that violate the supported pivots.

Return an answer tied to the surviving pivots

The final answer is built from the knowledge links that remain consistent with the image and the question.

What the paper changes

What the paper changes

The paper inserts an explicit intermediate unit between retrieval and full-chain reasoning: the reasoning pivot. A reasoning pivot is an atomic step, such as an entity relation or attribute link, that requires outside knowledge to complete. By exposing that unit, REAL can train conflict detection on something smaller and more reusable than a whole answer chain.

the object it moves  =  reasoning pivots
The hidden quantity

The hidden quantity: pivot support

measured quantity  =  pivot support

Pivot support measures whether a proposed reasoning pivot is jointly backed by the image, the question, and retrieved knowledge. A pivot with strong support fits all three. A pivot with weak support may fit the retrieved text but not the image, or it may fit the image but depend on a retrieved fact that clashes with another source.

This is the right quantity to model because conflicts do not usually corrupt every step of reasoning. They usually enter at specific knowledge links. Once the model can evaluate support at those links, it can remove or downweight unsupported pivots before they spread error to the rest of the answer.

Why it works

Why pivot-level control resolves conflicts better than chain-level supervision

The first part is pivot-aware supervised fine-tuning. Supervised fine-tuning means training on labeled examples that show the desired behavior. Here the labels identify which reasoning pivots are valid and which are conflicted. This gives the model a reusable detector for knowledge failure points, because the detector is trained on atomic reasoning links rather than on one full answer template per question.

The second part is pivot-guided decoding. Decoding is the process that turns model scores into the next generated text unit, where a text unit is one piece of the output such as part of a word. During generation, REAL uses the pivot judgments to steer scores away from continuations that rely on unsupported pivots. That matters because conflict resolution must happen while the answer is being formed, not only after the answer is already complete.

The combined effect is better control over evidence use because the model no longer treats all retrieved text equally. It tests the parts of reasoning that depend on external knowledge, and only those parts, which reduces accidental rejection of useful evidence and reduces acceptance of conflicting evidence.

Math after the picture

How pivot scoring enters answer generation

First in words:

The answer score is the sum of the language score and the support scores of the pivots used in that answer.

Then the compact form:

answer_score = language_score + sum(pivot_support_scores)

Every symbol:

answer_scorethe total value assigned to one candidate answer path
language_scorethe base score from the question-answering model before conflict control
sum(pivot_support_scores)the added support from pivots that remain consistent with image and evidence
A tiny worked example
Candidate answer A uses two pivots: monument identity and location-year relation.
Suppose language_score = 5, pivot support scores are 2 and 1, so answer_score = 8.
Candidate answer B sounds fluent but uses one pivot contradicted by the image.
Suppose language_score = 6, pivot support scores are 2 and -3, so answer_score = 5.
The model prefers answer A because the fluent but conflicted path loses value at the unsupported pivot.

The support term matters because it allows the model to reject a high-fluency answer when the knowledge link inside that answer is contradicted.

What can go wrong

What can go wrong

Pivot extraction is incomplete. If the model fails to mark a knowledge-dependent step as a pivot, that step escapes conflict control because decoding will treat it as ordinary reasoning.
Support labels are noisy. If the training data marks the wrong pivot as supported, the discriminator learns the wrong boundary and can suppress valid evidence or preserve invalid evidence.
Conflict is broader than one pivot. Some questions depend on several linked pivots, so one correct pivot may still sit inside a wrong larger explanation because another linked pivot is missing or incorrect.
Done right: REAL identifies the knowledge links that truly govern the answer and uses them to constrain generation before a conflicted chain can grow.
What a runnable demo should prove

What a runnable demo should prove

Build a small visual question answering task where each image is paired with a question that needs one outside fact, and retrieval returns one correct fact plus one conflicting fact. Represent the explanation as two or three reasoning pivots. Train one model to answer directly from retrieval and another to score pivots first. Evaluate whether the chosen answer matches the image, whether the correct pivot was selected, and whether the conflicting pivot was rejected during decoding.

conflict_resolved = (correct_answer + correct_pivot + rejected_conflict) / 3

The demo should show that answer quality rises only when the model can identify and score the specific knowledge-dependent step that carries the conflict.
