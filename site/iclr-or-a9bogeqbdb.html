RAP: Fast Data for Driving with Rasterization

Driving models learn better from lightweight 3D rasterized scenes than expensive photorealistic renderings because where objects are positioned matters far more than how they look.

Paper explainersAll themesRobotics & Control

Self-driving cars are trained on logged expert drives, but small errors during live deployment spiral into crashes because the model has never seen corrections. Expensive methods try to create fake training scenarios using photo-realistic graphics or game engines, but they are too slow to scale. This paper argues that for teaching driving, you do not need realistic textures or lighting—you only need correct shapes and positions. By swapping expensive rendering for simple 3D rasterization (drawing geometric primitives like boxes and lines), then teaching the model to recognize features in both synthetic and real camera feeds equally well, a self-driving system can learn from millions of extra training examples.

Zero assumption version

Expert logs do not teach recovery

A self-driving system trained only on perfect expert drives has never seen a mistake happen and never learned how to fix one. When the live car makes a small error—drifting slightly left instead of straight—the model has no experience recovering. The drift causes a second, larger error. That error cascades into a crash.

One solution is to generate synthetic training drives with mistakes baked in. A car could learn by practicing recovery on those fake scenarios. But building realistic fake drives is expensive: neural rendering networks or game engines take minutes per scene. For a model to learn well, you need thousands or millions of extra scenes. That cost is prohibitive.

Existing methods use photo-realistic graphics to make the fake scenes look like real camera feeds. But a car steering does not care about texture sharpness or shadow angles—it cares only about where the road is, where other cars are, and how they are moving. The realism is wasted compute.

The insight: For driving, the shape and position of objects matter; textures and lighting do not. So use a fast lightweight drawing method instead of an expensive rendering engine, then teach the model to interpret both fake and real pictures the same way.

The algorithm as a flow

What it actually does

Start with real logs and sensor data

Self-driving dataset: camera images, car positions, where lanes and roads are drawn, expert steering commands.

Render each scene twice using 3D rasterization

Program draws scene positions directly: lanes as lines, other cars as boxes. Milliseconds per scene.

Generate new driving scenarios beyond the logged path

Simulate alternative routes, recovery maneuvers, other vehicle positions. All rasterized.

Align rasterized and real images in feature space

Frozen encoder extracts features from both. Spatial alignment penalizes feature differences; domain confusion forces the model to forget which source each came from.

Train the driving model on mixed real and synthetic data

Steering predictions from real logs, synthetic logs, and counterfactual recovery all train together. Model learns one unified feature representation.

What the paper changes

What the paper changes

Instead of using expensive photo-realistic rendering engines to create training scenarios, the paper replaces them with lightweight 3D rasterization—a simple algorithm that draws geometric primitives (lines, boxes, polylines) directly into an image at the correct positions. The model then learns a shared feature representation that works for both rasterized and real camera images.

The hidden quantity

The hidden quantity: feature consistency

measured quantity  =  Feature distance between synthetic and real

When you feed a photo-realistic fake image into a trained encoder, the encoder produces a list of numbers (a vector of features). When you feed a real camera image through the same encoder, you get a different vector. The gap between these vectors is feature inconsistency—it tells you whether the model treats the two sources as coming from the same world or different worlds.

The paper measures this gap using two methods. Spatial-level alignment compares features pixel-by-pixel between a rasterized image and its paired real image, penalizing large differences. Global-level alignment trains a separate classifier to guess whether a whole image's averaged feature came from a fake or real source; if the classifier is perfect, the gap is large; if the classifier has to guess randomly, the gap is zero. The paper reduces this gap during training so the steering model sees both sources as equally valid.

Why it works

Why lightweight rasterization works for driving

A self-driving model looks at an image and predicts steering commands. For that task, the model needs to recognize objects (other cars), where lanes are, and how everything is moving relative to the car. All of this information lives in the position and shape of things in the image. Textures (wood grain, asphalt specks) and lighting (shadows, reflections) add visual detail but zero steering information. A realistic render with perfect shadows costs 10-100 times longer to compute than drawing simple lines and boxes, yet teaches the same steering logic.

The bottleneck is that rasterized images look visually different from real photographs—flat colors instead of textures, no lighting effects. A model trained only on real images would not trust rasterized images, and vice versa. The paper fixes this by training a shared representation: it extracts mid-level features (a compressed mathematical summary) from both rasterized and real images using a pretrained visual encoder that stays frozen, then trains the steering model on those features instead of raw pixels. It penalizes the feature vectors to stay close between sources (spatial alignment) and trains a separate classifier to be unable to tell which source an image came from by looking at averaged features (adversarial alignment, which includes a technique called gradient reversal that trains the main encoder to fool the classifier). The result is a steering model that treats synthetic and real data as interchangeable.

This unlocks millions of synthetic training examples: counterfactual recovery drives (the car learns how to correct mistakes), cross-agent views (training on how other cars navigate the road), and arbitrary variations on real routes. The model generalizes better because it has seen many more scenarios and many more kinds of recovery.

Math after the picture

The alignment equations

First in words:

Total training loss is task loss plus spatial feature alignment loss plus global adversarial alignment loss, with two weight parameters controlling how much each alignment component matters.

Then the compact form:

L = L_task + lambda_s * L_spatial + lambda_g * L_global, where L_spatial = MSE(features_real, detach(features_rasterized)) and L_global = -E[y * log(D(g)) + (1-y) * log(1-D(g))]

Every symbol:

L_tasksteering prediction loss on labeled examples
L_spatialpixel-wise feature distance between real and rasterized
L_globalbinary cross-entropy loss for domain classifier D
lambda_s, lambda_gweights controlling how strong each alignment term is
D(g)domain classifier probability that global features come from real
ytrue label: 1 for real, 0 for rasterized
A tiny worked example
Suppose steering loss L_task = 0.5 (reasonable mid-training value).
Spatial alignment extracts 256-dimensional feature vectors. Real features: [0.3, 0.2, ..., 0.1]. Rasterized: [0.35, 0.25, ..., 0.12]. MSE = (0.05^2 + 0.05^2 + ... + 0.02^2) / 256 ≈ 0.003.
With lambda_s = 0.1, this contributes 0.1 * 0.003 = 0.0003 to total loss.
Global classifier initially guesses domain 60% correctly (slightly better than random 50%). Classification error (binary cross-entropy, which measures how wrong the classifier's guess is) L_global ≈ 0.1. With lambda_g = 0.01, this contributes 0.01 * 0.1 = 0.001.
Total: L ≈ 0.5 + 0.0003 + 0.001 ≈ 0.501. Alignment is a gentle nudge, not the main signal.
As training progresses, alignment losses shrink as the model learns shared features, and L_task dominates. The steering model controls 99% of the loss; alignment is a gentle correction that shapes the features without changing the steering behavior.

The loss combines three objectives: steering accuracy (main signal), spatial feature matching (local alignment), and domain confusion (global alignment). Spatial alignment penalizes feature differences between sources; adversarial alignment forces the overall pattern of features (how they cluster and scatter) to be the same whether they come from real or rasterized images.

What can go wrong

What can go wrong

Rasterization loses information visual models need. If the downstream steering model is trained on raw pixels and has learned to use texture cues or shadow patterns, rasterization will cripple it. But most driving depends on where things are positioned, not textures or shadows, so in practice this is not a problem. The paper validates this with ablations showing that shared feature alignment is sufficient.
Feature alignment is incomplete. If spatial or global alignment is too weak (the control weights lambda_s and lambda_g set too small), the model will learn different feature patterns for real vs. rasterized, and synthetic training will not transfer to real deployment. Setting these weights requires careful tuning; too large and the model wastes effort on alignment and loses steering accuracy.
Rasterization mistakes compound. If the position extraction is wrong—roads drawn at incorrect locations, car bounding boxes misaligned—the synthetic scenarios teach the model to steer based on phantom lanes or phantom obstacles. The paper assumes perfect position annotations from the logged data, which is not always guaranteed.
Done right: rasterization is fast and generalizes. Rasterized scenes render in milliseconds and can be generated at scale. Feature alignment is a gentle nudge, not a brittle constraint. When positions are accurate and alignment is tuned well, synthetic and real data train interchangeably.
What a runnable demo should prove

What a runnable demo should prove

Build a simple end-to-end driving model on the CARLA simulator or a small real dataset (e.g., a 10-minute drive). Train three versions: (1) on real data only, (2) on real data plus equal-sized synthetic rasterized data with no alignment, (3) on real data plus synthetic rasterized data with full Raster-to-Real alignment. Evaluate each on a held-out test set of real images and on a separate test set of new rasterized images (simulating deployment on a simulator or domain-shifted sensor). Measure steering error (mean absolute angle error in degrees) and closed-loop success rate on a fixed route with small injected perturbations (e.g., the car starts 0.5m off the true path).

Closed-loop success = (1 - 1/N * sum_i [i-th trajectory went off-road or crashed]) * 100%, reported separately on real test images and rasterized test images.

The demo must show that synthetic rasterized data plus alignment outperforms real-only on both real and rasterized test images, and that alignment is necessary because without it the features learned from rasterized images are so different from real features that the steering model does not trust rasterized inputs during testing.
