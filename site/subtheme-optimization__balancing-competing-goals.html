Balancing competing goals

Real problems have multiple objectives: accuracy, fairness, cost, speed. How do optimization algorithms find tradeoffs instead of optimizing just one goal?

What this is

Real problems do not have one goal. A credit model must be accurate and fair—accurate so good customers get loans, but fair so it does not reject qualified applicants from certain groups, because accuracy alone will reject people unfairly. A robotic arm must be fast (complete the task soon) and safe (do not break expensive equipment), because speed without safety costs money in broken robots. A recommendation system must be accurate (show relevant items) and diverse (do not show the same kind of item every time), because boring recommendations lose users. An ML system must use little memory but still be accurate, because free memory without predictions is useless and predictions with memory costs are worthless. Making predictions faster might require less training, which hurts accuracy because the model sees fewer examples and learns less. If you optimize only for accuracy, the model may become unfair or unsafe or resource-hungry. But when you add penalties for fairness or safety, accuracy usually drops. The problem is finding a point where all goals are simultaneously reasonably good, not where one is perfect and others are ignored.

The mathematical challenge is that different goals can conflict: better fairness often means worse accuracy because enforcing fairness prevents the model from using shortcuts that help some groups, and lower cost often means slower predictions because running predictions cheaply requires simpler models or fewer computations. The space of possible tradeoffs is called the Pareto frontier—a curve where improving one goal requires sacrificing another. Finding this frontier is hard, and even after you find it, you have to choose which point on the curve to live at, which requires human judgment about what matters more.

Papers use several approaches. Multi-objective optimization methods maintain multiple candidate solutions and evolve them together, checking whether each solution improves any goal without hurting others. Others scalarize: turn multiple goals into a single combined goal by summing them with weights (e.g., 0.8 * accuracy - 0.2 * unfairness), then optimize that. The weights control which goal is most important. Some papers learn the weights adaptively—if you are doing well on fairness but poorly on speed, shift more weight toward speed. Constraint-based methods turn some goals into hard constraints (fairness must exceed a threshold) and optimize the others subject to hitting the constraint. A few papers use game theory: model the tradeoff as a negotiation between players who care about different goals. The common thread is that you do not optimize in the dark; you explicitly model what success looks like in multiple dimensions and make that tradeoff visible.

How the work breaks down

When you have multiple competing goals, there are a few main paths forward: you can turn some goals into hard constraints that must be met, you can set up a hierarchy where one goal depends on another, you can explicitly map out all the tradeoffs to find the Pareto frontier, or you can treat the problem as a negotiation between different objectives. Each approach suits different problems.

Constraint-based approaches

When some goals are non-negotiable, constraint-based methods turn them into hard requirements: fairness must not go below a threshold, memory usage must fit in available space, or safety violations must not exceed a budget. The challenge is optimizing the remaining goals while guaranteeing the constraints hold, because constraints often conflict with efficiency and can make the problem much harder to solve.

DR-Submodular Maximization with Biased Updates proves you can get 1/e of the optimal solution even under complex constraints, beating the previous best guarantee of 1/4 for general convex constraints. The key is using biased update directions (partial information about which way to step) rather than exact slope information, which is much faster when data comes in random order, because you do not need to wait for all the data to compute one step. Dual Optimistic Ascent shows that a particular tuning of dual methods converges linearly to constrained solutions and gives clear rules for picking the right hyperparameter so the method stays stable. Hom-PGD+ works on the special case where constraints form a symmetric shape (a ball in the parameter space), which lets it run much faster—needing roughly the square root as many iterations—while staying feasible. Pinet takes this further by building hard constraints directly into neural network architecture through orthogonal projection layers, which means the network automatically satisfies constraints without having to add penalty terms after training. These papers show that treating constraints as first-class objects—rather than soft penalties tacked onto the loss—can give you both speed and certainty.

All four papers share the insight that constraints are not just obstacles; they define the feasible region where you are allowed to search. By respecting the shape of the constraint region from the start—knowing how it curves and bends—you can design algorithms that converge faster and more reliably than methods that penalize violations and hope the penalty is strong enough.

Bilevel and hierarchical optimization

Some problems have a natural hierarchy: you want to learn a model that makes good predictions, but before you do that, you want to tune the hyperparameters that control how that model learns. Or you want to design a training dataset, but the quality of the dataset depends on how well a model trained on it performs. These hierarchical problems are called bilevel optimization because there is an upper-level goal (tuning hyperparameters or designing data) and a lower-level goal (training the model itself). The hard part is that changing the upper level changes the lower level's answer, which then changes whether the upper level is good.

FAB: A First-Order AB-based Algorithm solves bilevel problems over distributed systems where the network topology can change over time. It proves convergence guarantees and tests this on real applications like hyperparameter tuning, data cleaning, and reinforcement learning. Faster Methods for Highly-smooth Bilevel Optimization improves the theoretical complexity bound, showing you can solve smoothly-varying bilevel problems faster than was previously known because problems that change smoothly have useful structure you can exploit. A Fully First-Order Layer for Differentiable Optimization avoids computing expensive second derivatives (which many bilevel methods need) and instead uses only first-order information, cutting the total number of computations needed from scaling quadratically with accuracy to scaling logarithmically. Bilevel Optimization with Lower-Level Uniform Convexity develops a new theorem about implicit differentiation—a key technique for bilevel optimization where you differentiate through the solution of the lower-level problem—and proves it works even in settings where the lower level has special structure. Reducing Contextual Bilevel Optimization via Structured Function Approximation achieves near-optimal complexity by exploiting the structure that typically exists in bilevel problems like inverse design and hyperparameter optimization.

These papers all recognize that bilevel structure is common in real applications and worth solving correctly, rather than pretending it is a single-level problem.

Exploring the Pareto frontier

When you have multiple goals that truly conflict—improving accuracy means harming fairness, or improving speed means hurting safety—you cannot find one solution that is best for all goals simultaneously. Instead, you can map out the Pareto frontier: the set of all solutions where you cannot improve one goal without harming another, which means every solution on the frontier is equally valid from a technical standpoint. The frontier is typically a curve in solution space, and choosing which point on that curve to use is a human decision, not an algorithmic one, because the choice depends on what you care about most.

A Tale of Two Problems: Multi-Task Bilevel Learning Meets Equality Constrained Multi-Objective Optimization proposes the weighted Chebyshev penalty method, which finds solutions spread across the Pareto frontier in finite time by scalarizing—combining multiple goals into a single score using adjustable weights. Diversity-Driven Offline Multi-Objective Optimization via Nested Pareto Set Learning discovers not just one point on the frontier but a diverse set of good solutions, and does this in offline mode where you cannot query the objective repeatedly. SPREAD: Sampling-based Pareto front Refinement via Efficient Adaptive Diffusion uses diffusion models to generate candidate solutions and refine them to lie on the Pareto frontier, matching or beating traditional multi-objective algorithms in efficiency and coverage. Task-Agnostic Amortized Multi-Objective Optimization (TAMO) speeds up this process dramatically by training a neural network to propose points on the frontier without solving from scratch each time, reducing evaluation time by 50 to 1000 times.

The shift from these papers is toward treating the frontier as an object worth computing and exploring, rather than settling for a single compromise solution.

Game theory and strategic negotiation

Some competing goals can be modeled as a negotiation between players who care about different objectives. For example, a recommender system has a producer who wants engagement and a consumer who wants diversity; a bidding system has a seller who wants revenue and a buyer who wants low prices. Game theory models this by asking: if each player optimizes for their own goal, what outcome emerges? This is a Nash equilibrium—a point where no player can do better by changing their strategy alone.

Nash Equilibria in Games with Playerwise Concave Coupling Constraints proves that when each player has a special structure (playerwise concavity—roughly meaning each player's goal is curved the right way), Nash equilibria exist and can be found in finite time using an algorithm that needs a number of steps related to one divided by accuracy cubed. It handles problems where players' constraints couple—one player's actions affect another's feasible set. Solving Imperfect-Recall Games via Sum-of-Squares Optimization solves games where players do not have complete information (imperfect recall), which is more realistic but much harder. It uses a Sum-of-Squares (SOS) relaxation, which is a way to make hard nonconvex problems easier by relaxing them to convex problems, and proves convergence under certain genericity conditions.

These papers show that when goals are not just trade-off curves but actual conflicts of interest, game theory provides a natural framework for finding stable outcomes where every participant is doing the best they can given everyone else's choices.

Continual learning and stability-plasticity

A model trained on data today must learn new data tomorrow, but if it learns too eagerly on new data, it will forget what it learned before. This is the stability-plasticity tradeoff: stability means holding onto old knowledge, plasticity means learning new knowledge flexibly. The challenge is that the two goals directly oppose each other.

FIRE: Frobenius-Isometry Reinitialization for Balancing the Stability–Plasticity Tradeoff uses reinitialization—reinitializing certain parameters when new data arrives—in a way that preserves how much the model has already learned while allowing it to adapt. It works across continual vision learning, language modeling, and reinforcement learning. CORAL: Uncertainty-Aware Regulation of Exposure Concentration in Recommender Systems balances two goals in recommendation: show items users will like (stability: recommend based on past behavior) but also show diverse items (plasticity: explore new categories). It uses measures of confidence to decide when to intervene and change what it recommends. The Pareto-optimal Trade-off between Regret and Statistical Estimation in Linear Bandit Problems under Safety Constraints explicitly maps out the frontier between regret (learning quickly by trying many actions) and safety (avoiding bad actions early), showing that you can achieve the best possible point on that frontier.

All three papers recognize that when data changes over time or when you have multiple agents with different needs, the tradeoff between old and new, or between exploitation and exploration, is unavoidable—so the goal is to characterize the frontier and choose consciously.
