Rethinking Time-Series Imputation as Conditional Inference

Instead of filling in missing data points one at a time, think of the whole time series as one joint inference problem where history informs the missing values.

Paper explainersAll themesTime Series & Sequential

Real-world sensor readings, stock prices, and weather data all have gaps: a sensor fails for a day, a stock market closes, a measurement is lost. Filling these gaps is called imputation. The standard approach treats imputation as a local puzzle—given the nearby points before and after a gap, guess the missing value. But that misses the bigger picture: the missing values follow patterns from the longer history. This paper replaces that local view with a global one: infer all missing values at once, conditioned on what the full history tells you about how the data evolves over time.

Zero assumption version

Why local guessing fails

A temperature sensor records hourly readings. One day the sensor breaks and records nothing for 8 hours. To fill the gap, a naive approach looks at the last value before the gap (68 degrees) and the first value after (71 degrees), then guesses something in the middle—say 69.5 degrees. This works if temperature changes slowly and smoothly.

But real data has patterns that repeat over longer time scales. If this is a daily sensor, you'd know that temperatures at 3 AM are always colder than at 3 PM. The naive method throws away that knowledge. It also treats the gap in isolation: it does not use the fact that temperature yesterday, last week, or even the season tells you what today should look like. So the guess is often wrong, and these wrong values corrupt any downstream analysis that relies on the filled-in data.

The deeper problem: most imputation methods limit themselves to a small window of recent context. To use long-range history—patterns over days or weeks—they would need huge amounts of memory and compute. So they give up and work with a short sliding window, missing the bigger picture entirely.

In one sentence. The paper proposes that time-series imputation should infer missing values by conditioning on patterns learned from the entire long-term history, not just guessing from nearby points.

The algorithm as a flow

What it actually does

Step 1: Compress the past

Take all the historical data before the gap and squash it into a short code that captures the key patterns (daily cycles, trends, volatility).

Step 2: Condition the inference

Given that compressed code, treat the entire missing sequence as one inference problem—find the most plausible values that fit the history's learned patterns.

Step 3: Partition the work

Split the computation into two streams: one handles historical context, the other only handles the missing values. This keeps memory and speed constant even with long gaps.

Step 4: Learn from data

Train a neural network (a type of mathematical model) to predict missing values by seeing many examples of intentionally hidden data in training sequences.

Step 5: Apply and evaluate

Fill real missing gaps using the trained model, then measure how close the filled values are to ground truth on standard datasets.

What the paper changes

What the paper changes

The paper replaces the window-limited imputation (guess from the nearby points) with a full-sequence inference conditioned on a compressed history code. The change is conceptual—instead of solving a local puzzle, you solve one global inference problem that respects the entire history.

The hidden quantity: Temporal patterns captured in compressed history

The paper measures a single hidden thing: a compressed code of the historical evolution. This is a short list of numbers (a latent code) that captures the essential patterns in the long history—cycles (temperatures rise and fall each day), trends (the season is warming), and volatility (whether changes are big or small). The naive method ignores this entirely; the new method learns it and uses it.

The paper estimates this code by feeding the entire past sequence through a neural network encoder—a series of mathematical functions that squeeze all the history into a few numbers. These numbers then guide the inference of missing values: the missing values must be consistent with what the history taught us about how the data evolves.

Why it works

Why it works: Conditioning makes imputations honest

The core insight is that missing values are not independent mysteries—they obey the same rules as the rest of the series. If you learn those rules from history, you can guess missing values that respect those rules. The naive method fails because it guesses in a vacuum, imagining the gap is an isolated puzzle. The new method works because it first learns the rules, then enforces them.

Here is the causal chain: A long history contains repeating cycles (daily, weekly, seasonal). A neural encoder squashes that history into a code that captures these cycles. When you then try to infer the missing values, the code acts as a constraint—it says, Your guess must be consistent with the cycles and patterns we learned. A guess that violates those patterns has low probability; a guess that fits the learned rules has high probability. So the algorithm naturally chooses guesses that align with the historical patterns. Missing values generated this way are far more plausible than values guessed by linear interpolation or local smoothing.

The partitioned modeling strategy makes this faster and more memory-efficient, because the computation is split into two separate streams. One stream handles the historical context (encoding the past into a code). The other stream handles only the missing sequence (decoding from the code to fill the gap). Normally, if you tried to process the entire long history and the gap together in one neural network, you would need to keep all the intermediate values in memory at once—a number of values proportional to (length of history squared), ballooning as sequences grow. By splitting into two independent streams, you only ever process one stream at a time: first the history (bounded by history length), then the gap (bounded by gap length). This keeps memory constant regardless of how long the history is. Because the two streams never need to process the entire long history and gap together, the algorithm runs in linear time with respect to the total sequence length—time that grows proportionally with the data size, not faster. Without partitioning, the system would need to juggle the entire history and gap at once, requiring exponentially more memory for long sequences.

The equation: Probabilistic imputation

First in words:

The goal is to find the most likely missing values given the history. The model scores each possible completion by how well it matches the learned historical patterns. High scores go to values consistent with those patterns; low scores go to implausible values.

Then the compact form:

log p(X_missing | X_history) = - sum_t ||X_imputed_t - mu_t||^2 / sigma_t^2 - lambda * ||code||^2

Every symbol:

X_missingThe values we want to fill in
X_historyAll the observed data before the gap
X_imputed_tOur guess for the missing value at time step t
mu_tThe expected value at time t, predicted by the decoder from the history code
sigma_tHow uncertain the prediction is at time t
codeThe compressed representation of X_history (the latent code)
lambdaA weight controlling how much we penalize a complex code
log p(...)The logarithm of the probability of this completion
A tiny worked example
Suppose history encodes into a code with magnitude 0.8. At time step 5, the decoder predicts the temperature should be 67 degrees with uncertainty 2 degrees.
We propose filling the gap with 67 degrees. Error at t=5: (67 - 67)^2 / 2^2 = 0. Regularization on code: lambda * 0.8^2 = 0.5 * 0.64 = 0.32 (assuming lambda = 0.5).
We propose filling the gap with 71 degrees instead (ignoring history). Error at t=5: (71 - 67)^2 / 2^2 = 4. Total loss: 4 + 0.32 = 4.32, far worse than 0.32.
The first guess (67, matching history) has much higher probability. So the algorithm learns to fill gaps with values that obey the learned historical patterns.

The equation says: pick missing values (X_imputed_t) that are close to what the history predicts (mu_t) and that come from a simple, clean compressed code. This biases the algorithm toward plausible, history-respecting fills.

What can go wrong

What can go wrong

No history to compress. If the gap occurs at the very start of a time series (no history before it), the compressed code is empty or uninformative. The method cannot infer the missing values because it has no learned pattern to rely on. It falls back to random guessing.
Pattern change. If the underlying patterns change abruptly (e.g., a sudden policy change, a hardware upgrade), the history no longer predicts the future. Missing values inferred from the old patterns will be systematically wrong. The method learns a stale recipe and applies it to new data.
Very long gaps. While the partitioned design keeps computation linear, very long gaps (weeks or months) push the decoder to extrapolate far beyond what it has seen. The uncertainty (sigma_t) grows, and guesses become unreliable. Compressing and decoding are not magic; they cannot invent data with no nearby evidence.
Done right. The method works best when: (1) there is substantial history to compress, (2) the patterns are stable over time, and (3) gaps are shorter than the main repeating patterns (e.g., a daily cycle should handle hour-long or day-long gaps well). Under these conditions, inferring from learned history cuts errors by 25-40% compared to naive local methods.
What a runnable demo should prove

What a runnable demo should prove

To validate this explainer, build a small end-to-end experiment: (1) Generate or load a synthetic time series with clear daily and weekly cycles (e.g., hourly temperature or web traffic). (2) Deliberately hide a 12-hour gap somewhere in the middle. (3) Train a simple encoder-decoder model on unlabeled sequences where you hide random gaps and ask the decoder to predict them. (4) Apply the trained model to fill your test gap. (5) Compare the filled values to the ground truth (the real values that were hidden). (6) Also run a naive linear interpolation on the same gap and compare. The key metric is the imputation error—the difference between filled and true values.

Masked MAE = mean_t |X_true_t - X_imputed_t| for all t in the gap. Lower is better. Naive interpolation should have roughly 2-3x higher error than the history-conditioned model on this toy dataset.

The demo must show that learning patterns from history and enforcing them during imputation produces dramatically more plausible fills than local guessing. If both methods perform the same, the compressor is not working (perhaps the time series has no repeating pattern, or training was too short).
