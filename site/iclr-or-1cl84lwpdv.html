Random-projection ensemble dimension reduction

Try many random compressed versions of your data, keep the ones that actually predict, then combine them to pick the true signal directions.

Paper explainersAll themesOptimization

When you have tons of measurements but want to predict from just a few, how do you know which ones to keep? This paper uses a voting trick: it generates many random reduced versions of the data, picks the best-predicting ones, and uses a tiebreaker to spot the real signal dimensions underneath all the noise.

Zero assumption version

The measurement bottleneck

Imagine you measured 1000 things about each patient — blood tests, imaging, genetics — but only have 50 patients. Predicting anything is hopeless: there are 20 times more knobs to turn than data points, so your model memorizes noise instead of finding the pattern.

The naive fix is to ask a statistician: pick the top 10 measurements by how much they vary, throw out the rest, and retrain. The problem: the ones that vary most are often noise, not signal. You might throw away the three measurements that actually predict the disease, and keep 10 that looked interesting by accident.

The paper's move: Instead of guessing which measurements matter, vote on random compressed versions and let the votes reveal which directions carry real information.

The algorithm as a flow

What it actually does

Generate ensemble

Make L groups of M random compressed versions, each shrinking 1000 measurements into (say) 5.

Score each one

For each compressed version, train a simple predictor (linear regression or similar) and measure accuracy on a hold-out.

Pick winners per group

In each group, keep only the best-scoring compressed version—the one that predicted best.

Combine winners

Stack the L best projections and run singular value decomposition, a math trick that ranks the compressed dimensions by how much information they carry.

Trim by size

Look at the singular values; when they drop sharply, you have found the true number of dimensions. Output only that many, discarding the noise-carrying ones.

What the paper changes

What the paper changes

The paper does not change the measurements themselves or the prediction model. Instead, it changes which random compressed versions of the data you keep—it selects the ones that actually predict, rather than picking blind.

the object it moves  =  which projections to trust
The hidden quantity

Projection quality and signal strength

measured quantity  =  prediction accuracy of each compressed version

As the algorithm tries random compressed versions, some predict your target much better than others, because they happened to preserve the true signal directions by luck. Those that predict well are likely to have preserved the true signal (the measurements that actually matter). Those that predict poorly have probably captured only noise—random junk that looks predictive on this particular dataset but will not generalize.

The paper measures this by training a simple predictor on each compressed version and scoring how well it works on held-out data that the algorithm never saw during training. A projection that scores 0.85 out of 1 is carrying real information; one that scores 0.50 is no better than guessing and is clearly noise. By keeping only the high-scoring versions and discarding the low ones, the algorithm filters noise without ever knowing explicitly what the true dimensions are.

Why it works

Why voting on random versions finds true signal

The core mechanism is this: if you compress data at random many different ways, and a measurement is truly important for predicting the target, then random compressions that happen to include that measurement will predict better than compressions that miss it, because they are preserving information the model needs. The good projections cluster around the true signal directions; bad projections are noise and scatter everywhere.

The algorithm exploits this by generating hundreds of random compressions, measuring how well each one predicts on held-out data, and keeping only the winners. The winners are much more likely to preserve the true dimensions because signal generalizes to unseen data, but noise does not. Then it runs singular value decomposition on these winners—a mathematical trick that ranks the kept dimensions by how much signal they carry. A sharp drop in the ranking tells you how many true dimensions there are. You output only those, discarding the rest.

Why does this work? Because signal is repeatable and noise is not. If three measurements out of 1000 truly predict the disease, then random compressions that include all three will outpredict on held-out data, while compressions that miss them will fail. Over hundreds of independent trials, the true directions accumulate evidence in their favor. The voting system is stable: it is hard to accidentally pick up fake patterns, because a random spurious correlation would need to outpredict the true signal in many independent random compressions at once, which is astronomically unlikely by chance.

The aggregation score

First in words:

After selecting the best projections, the singular values from SVD tell you how much information each direction carries. A direction with singular value 8.5 carries about 17 times more signal than one with value 0.5.

Then the compact form:

sigma_i = information_strength_of_direction_i; choose_k = number_of_directions_where_sigma_k / sigma_1 > threshold

Every symbol:

sigma_ithe i-th singular value, measuring signal strength
kthe direction index (1 is strongest, 2 is next, etc.)
thresholda chosen cutoff (e.g., 0.1 or 0.05) to separate signal from noise
sigma_1the strongest singular value (largest signal)
direction_ithe i-th compressed coordinate
A tiny worked example
Suppose after voting and SVD, singular values are: 8.5, 3.2, 0.9, 0.4, 0.05.
Compute ratios to the largest (8.5): [1.0, 0.38, 0.11, 0.05, 0.006].
With threshold 0.1: keep directions 1, 2, 3 (above threshold); drop 4 and 5 (below).
Output: 3-dimensional compression. Directions 4 and 5 were noise; directions 1–3 carry true signal.

Singular values rank the compressed dimensions by information content; a sharp drop signals where the true dimensionality ends and noise begins.

What can go wrong

What can go wrong

Too few random versions. If you only generate 5 random compressions instead of 200, you might miss the true signal by bad luck. The voting effect only works when you try enough independent random trials.
Wrong predictor choice. If you score projections using a predictor that is too weak (e.g., always picking linear regression for a highly nonlinear target), even good projections will score poorly. Choose a base predictor flexible enough to capture the signal you seek.
Threshold set too high or low. If your cutoff for singular values is set wrong, you might keep too much noise (threshold too low) or discard signal (threshold too high). The paper suggests comparing to a single random compression as a baseline to guide the choice.
Done right. With enough random versions (200 groups with 200 candidates each), a flexible base predictor (MARS or least squares), and a threshold chosen via comparison to single-projection baseline, the method finds the true dimensionality reliably across simulated and real data.
What a runnable demo should prove

What a runnable demo should prove

Generate a synthetic dataset where you secretly know the true dimensions. For example, make a target that depends only on the first three of your 100 measurements (the other 97 are random noise). Run the random-projection ensemble method, and confirm it outputs three dimensions, matching the true rank. Then verify that a predictor trained on those three dimensions beats one trained by naively picking the top 10 by variance.

score = (number_of_true_dimensions_found / true_rank) * (accuracy_on_holdout / max_possible_accuracy); demo shows score >= 0.95 for ensemble, <= 0.60 for naive selection

The demo makes clear that voting on hundreds of random versions beats picking by hand, especially when signal is subtle or hidden in high-dimensional noise.
