Random-projection ensemble dimension reduction

When you have way too many numbers to measure, throw random mixtures at the problem and keep only the ones that actually work.

Paper explainersAll themesOptimization

Real-world measurements often have thousands of numbers (variables), but most are just noise. Throwing all of them into a prediction machine wastes time and memory. The usual fix is to guess which numbers matter. This paper cuts the guess work: it randomizes how you mix the numbers in many different ways, tests each mixture on the actual data, keeps only the mixtures that predict well, and lets the kept mixtures vote on the final answer.

Zero assumption version

Too many numbers, too much waste

When you measure something in the real world, you often collect thousands of numbers (a patient's blood work has 100 measurements, a stock has price plus 500 technical indicators, an image has millions of pixels). A naive beginner would throw all of them at a prediction machine and train it. But most of those numbers are either completely random or just copies of each other. The machine spends all its time on noise, gets confused, and overfits (memorizes the training data instead of learning the pattern).

The standard fix is to choose which numbers matter beforehand, using domain knowledge or manual testing. This requires guessing. If you guess wrong, your model fails silently. If you pick too many, you waste compute. There is no principled, automatic way to test many possible number combinations without exploding the search time.

In one sentence. Mix the high-dimensional numbers in many random ways, test each mix on real data, keep only the good ones, and combine them.

The algorithm as a flow

What it actually does

Make random recipes

Generate many random ways to blend the thousands of numbers together.

Divide into small contests

Split the recipes into groups; within each group, test which recipe predicts best on training data.

Pick the winners

For each group, take only the one recipe that performed best; drop the rest.

Rank the kept recipes

Measure how much each winning recipe contributes, because recipes that explained more of the data's spread are more reliable for predictions.

Combine and predict

Weight-average the winning recipes and use them to predict on new data.

What the paper changes

The one thing the paper changes

Instead of guessing which numbers to keep (or using only one fixed recipe to mix them), the paper changes which random mixes become part of the final answer. A naive approach picks one best recipe; this paper keeps several good recipes and blends them.

the object it moves  =  which random mixes are kept
The hidden quantity

Importance: how much each mix matters

measured quantity  =  the contribution weight of each mix

The paper measures something new: not just whether a mix works, but HOW MUCH it contributes to the final prediction. This is captured in the singular values (a mathematical concept that acts like a rank or strength score). Each mix gets a score; high scores mean that mix predicts reliably and dominates the final answer. Low scores mean it helps a little but mostly stays quiet, because low scores indicate the mix explained only a small fraction of the data's natural spread.

The paper uses singular value decomposition (a standard math tool that sorts lists of numbers by importance) to compute these scores directly from how well each mix performed. Mixes with bigger singular values are capturing real signal, while mixes with tiny values are just getting lucky on the training data.

Why it works

Why testing random mixes beats guessing

The core insight is that random mixes are cheap to generate and test. Instead of searching through all possible subsets of numbers (which grows exponentially and is impossible), the paper creates many random recipes all at once and tests them in parallel. This is fast because the test is just fitting a simple model to the training data and measuring error.

By dividing the mixes into separate groups and picking the best from each group, the paper avoids one winning mix dominating the final answer. If all mixes were tested together, the single best one would win and the rest would be ignored. By partitioning them, multiple strong mixes survive. Each brings a slightly different view of the data (a different random angle). Combining them reduces the chance that any single mix was just lucky; the collective answer is more stable.

The singular values then act as a tie-breaker: mixes that predicted well and stayed consistent with the data (high singular values) get more weight in the final prediction. Mixes that barely squeaked through (low singular values) still contribute but less. This automatic weighting means the method is self-tuning; you do not have to manually decide how much to trust each mix.

Math after the picture

The selection and aggregation formula

First in words:

Predicted value equals the weighted average of the top-performing mixes, where each mix's weight is its singular value divided by the sum of all singular values.

Then the compact form:

y_pred = sum_j (sigma_j / sum_k sigma_k) * y_j

Every symbol:

y_predthe predicted output for a new measurement
sigma_jthe singular value (importance score) of mix j
y_jthe prediction from mix j alone
sum_k sigma_kthe total of all importance scores
A tiny worked example
Suppose three mixes survive testing. Mix A predicts 100 with singular value 4.0. Mix B predicts 110 with singular value 2.0. Mix C predicts 95 with singular value 1.0.
Total singular value = 4.0 + 2.0 + 1.0 = 7.0
Weight for A = 4.0 / 7.0 = 0.571 (Mix A trusted the most)
Weight for B = 2.0 / 7.0 = 0.286 (Mix B trusted less)
Weight for C = 1.0 / 7.0 = 0.143 (Mix C trusted least)
Final prediction = (0.571 * 100) + (0.286 * 110) + (0.143 * 95) = 57.1 + 31.5 + 13.6 = 102.2

The final answer is a weighted average of the survivors; mixes with higher singular values (more signal, less luck) dominate.

What can go wrong

What can go wrong

Too many groups, too few mixes per group. If you split your random mixes into many small groups, each group has only a few mixes to choose from. The winner in each small group might just be lucky (not genuinely good). The singular values will be noisy and unreliable.
All mixes are equally bad. If the real numbers are all garbage (pure random measurements with no signal), then even the best random mix is just overfitting to noise. No ensemble can save you; the singular values will all be tiny and the final answer unreliable.
Singular values do not reflect true generalization. The paper computes singular values from performance on training data. If the training set is small or atypical, the singular values will overestimate the importance of mixes that just happen to fit that particular data.
Done right. Use enough random mixes and groups so that the statistical winners are genuinely good, not lucky. Validate the final model on held-out test data to check that the singular-value weighting actually worked.
What a runnable demo should prove

What a runnable demo should prove

Build a prediction task on simulated data where you generate 1000 random numbers, but only 10 of them carry true signal. Run three approaches: (1) a naive model trained on all 1000, (2) manual selection of 20 numbers (with some right and some wrong guesses), (3) the random-projection ensemble with 100 random mixes split into 10 groups. Measure test error on a fresh batch of 100 examples.

test_error = mean( (y_true - y_pred)^2 ) across the 100 held-out examples

The ensemble approach should beat the naive baseline and match or exceed manual selection, all without requiring domain knowledge to pick which numbers matter.
