Building and rendering 3D worlds from images

Making 3D reconstructions and renderings from photos and video, often using neural approaches that learn how light interacts with scenes.

All themesField mapMathematicsAll explainers
What this is

A photograph is a flat 2D capture of a 3D world. When you take a photo of a room from one angle, you lose depth information: you see what is in front, but not how far away each object is. Computer vision research tackles this inverse problem: given one or more photographs, reconstruct the 3D shape and appearance of the scene. This opens doors to applications like virtual tourism (explore a real place online), augmented reality (overlay digital objects onto the real world), and 3D content creation for movies and games.

The core difficulty is that depth is not visible in the pixel values themselves. Multiple different 3D scenes can project to the identical 2D image. To recover depth, you need multiple views from different angles, or you need to make assumptions about what the scene looks like. If you have two photos taken from slightly different positions, you can use the shift in object positions to infer depth — the same principle your two eyes use to see in 3D. But if you have only one photo, you must rely on learned priors: 'walls are usually flat,' 'objects sit on surfaces,' 'similar textures often belong to the same surface.' Modern approaches use neural networks to learn these priors from data.

Recent papers in this area use several strategies. Some train models to predict depth directly from a single image, learning to guess how far away pixels are based on visual cues like texture and perspective. Others use multi-view stereo: take several images and train a network to infer a 3D structure that, when rendered from each camera position, reproduces the input photos. Some use neural radiance fields — a technique where a neural network learns to predict the color and density of light rays at every point in 3D space, so you can render the scene from any angle. Others combine explicit 3D shape reconstruction with neural rendering — learning how surfaces should look under different lighting. The goal is always the same: build a 3D model that is good enough to fool the eye.

How the work breaks down

The work splits into five natural directions: capturing static 3D scenes from photos using Gaussian Splatting, reconstructing moving subjects and dynamic scenes, extracting material and lighting properties from images, handling challenging conditions like transparency and high dynamic range, and making reconstruction fast enough for real-time or interactive use.

Gaussian Splatting Foundations

Gaussian Splatting is a technique that represents a 3D scene as a set of 3D blobs, each storing color and density. During rendering, these blobs are projected onto the camera view and blended together. The main challenge is that you need to decide where to place these blobs, how big to make them, and when to create new ones or remove old ones. Too few blobs miss detail; too many waste memory and computation. Papers in this group tackle the core problem: how to build an efficient, accurate representation.

D2GS uses depth and density information to guide where blobs should be placed, making reconstruction more stable when you have only a few camera views instead of many. Mesh Splatting takes the opposite approach: instead of just blobs floating in space, it enforces that the blobs lie on a 3D surface, which produces surfaces you can export as mesh files. 3DGEER extends Gaussian Splatting to work with any camera model, not just idealized pinhole cameras, which matters for wide-angle lenses and other real-world optics. A Step to Decouple Optimization improves the optimization algorithm itself, splitting the updates to different blob properties so they do not interfere with each other. Beyond Heuristics replaces hand-crafted rules for when to add or remove blobs with learned rules from data. 3DGS-HPC reduces distraction from moving objects by classifying pixels region-by-region instead of globally.

Rendering and Material Properties

Once you have a 3D model, you need to render it under different lighting or edit its appearance. The challenge is that a photograph encodes both the shape of an object and how its material responds to light. A shiny plastic ball looks different from a matte clay ball of the same shape. To relight a scene (render it under new lighting) or edit materials, you must separate two things: the object's 3D shape and what its surface looks like (its material and how it reflects light). Without this separation, changing lighting breaks the model because the network learned a shortcut tying light directly to pixel color.

DiffTrans tackles transparent objects, which are uniquely hard because light bounces through them rather than just reflecting off the surface. The method learns to separate where rays hit the object from how the material filters and bends light. SSD-GS extends Gaussian Splatting specifically for relighting: it separates direct light (the main illumination) and indirect light (bounced light and shadows), so you can swap lighting freely. Radiometrically Consistent Gaussian Surfels extends this to work with physically accurate measures of light energy. ReLi3D (MIDR-3D) reconstructs complete relightable assets from multiple views in under one second, recovering both the 3D shape and environment lighting. ReflFlow specializes in specular reflections—shiny surfaces with sharp highlights—which are easy to predict wrongly because small changes in shape cause big changes in reflection direction.

Dynamic Scenes and Moving Content

A video is a sequence of images from a moving camera, often containing moving people and objects. The hard part is that you must solve two problems at once: figure out which pixels belong to which object, and figure out how everything moves. If you get the motion wrong, your reconstruction will be blurry. If you misidentify which object is moving, you will attribute motion to the wrong thing, breaking the reconstruction entirely. You must balance these errors carefully.

Dynamic HDR View Synthesis addresses brightness variation: if your video has both bright windows and dark shadows, standard cameras clip one or the other. This paper captures high dynamic range video and learns to render it correctly from unseen camera angles. UniSplat handles driving scenes where the camera is mounted on a moving vehicle. Instead of trying to model all the moving background, it fuses information across frames using a learnable 3D structure. Frequency-aware Dynamic Gaussian Splatting noticed that motion blur happens at low frequencies (large features blur more than fine details); by analyzing motion separately per frequency, it removes blur while preserving sharp edges. ODE-GS uses a learned differential equation to model motion so future frames can be predicted and rendered, even when you do not have video to guide you. Taylor-Gaussians-Flow handles non-uniform motion: when a car accelerates, different frames skip different amounts. Uncertainty Matters in Dynamic Gaussian Splatting tracks not just where things are but how confident the model is, allowing it to handle occlusions and extreme viewpoints where what the model can see is actually unclear.

Challenging Conditions: Sparse Views and Harsh Light

In practice, you rarely have perfect input. You might have only a few camera views instead of a complete 360 degree scan. Your camera might be shaking. The lighting might be extremely bright or dim, or mix both bright windows and dark interiors. Some objects might be transparent or reflective. The model must stay accurate when inputs are noisy or incomplete. This is where many existing methods fail.

Distractor-free Generalizable 3D Gaussian Splatting learns to recognize and ignore people or objects wandering into the scene during capture—a common real-world problem. IncVGGT solves a different scaling issue: standard methods require all video frames to fit in GPU memory, but this method processes frames one at a time, enabling reconstruction from 10,000-frame videos on consumer hardware. UltraGauss applies Gaussian Splatting to 3D ultrasound volumes, showing the technique works even for medical imaging. Unified 3D Scene Understanding learns a single model that can estimate depth, reconstruct surfaces, and predict object positions all at once, making the system more reliable because shared representations prevent different branches from contradicting each other. EnerGS uses an energy-based learning framework to stabilize surface reconstruction when you have only sparse views. Expo-GS handles extremely bright or dim scenes by learning to undo the camera's exposure mapping, so high dynamic range lighting is reconstructed accurately. Mono4DGS-HDR captures dynamic, high-brightness scenes from a single camera: it uses alternating-exposure frames to infer what the true brightness was, then reconstructs the moving scene.

Speed, Generalization, and Practical Deployment

For applications like augmented reality, content creation, or autonomous driving, slow is useless. You need reconstruction to run in seconds or at interactive speeds. You also need the model to transfer to new scenes without retraining on each one. Current methods either are fast and generic but low-quality, or high-quality but require minutes per scene. Papers here push the boundary.

Stylos achieves zero-shot style transfer: take a learned model trained on one scene, apply an artistic style to it, and the style transfers to multi-view reconstructions without retraining. YoNoSplat is a feedforward network: feed it 100 images at once, it reconstructs them in 2.69 seconds on a single GPU without per-scene optimization. ARTDECO strikes a middle ground: it runs at interactive speeds comparable to SLAM systems but produces quality close to per-scene optimization. Less Gaussians, Texture More makes 4K resolution rendering practical by using fewer blobs and storing more information in learned textures per blob, avoiding the need to add more blobs just to handle high resolution. STream3R (Scalable Sequential 3D Reconstruction) uses a Transformer—an architecture that learns patterns in sequences (originally built for text, now used for images)—to handle images one at a time, so it scales to long video sequences and benefits from modern language model pretraining infrastructure. StreamSplat achieves 1200x speedup over optimization methods while supporting arbitrary-length video and online reconstruction where you process new frames as they arrive. Trust It or Not adds uncertainty quantification: it does not just predict depth, it predicts how confident it is, useful for safety-critical applications like autonomous driving.
