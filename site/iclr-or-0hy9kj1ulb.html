MoGA: Mixture-of-Groups Attention for Long Video Generation

Route each video token to a learned group, compute attention only within groups, scaling from quadratic to near-linear.

Paper explainersAll themesGenerative Models & Diffusion

Generating long videos requires a transformer to process ~580k tokens (patches of pixel information from all the frames). Full attention compares every token to every other token, which costs billions of operations and becomes impractical. This paper routes each token to one of several learned groups using a small learned table, then runs attention only within groups. The router is cheap; the savings are enormous. The result: minute-long video at 480p, real-time speed.

Zero assumption version

The wall: attention cost explodes with video length

Video transformers process frames as tokens (small spatial patches, each a list of numbers). To generate the next frame, the model must score how relevant each existing token is to each query position. This is full attention: each token scores against every other token. With 580k tokens from a long video, that is 336 billion comparisons. Computation and memory grow hugely, making generation impractical.

Existing sparse methods (block attention, local windows) fix block sizes, not semantic relevance. A character at one time is more relevant to that same character a moment later than to a static background pixel far away in time, but block-based methods ignore this. They miss fine structure and long-range connections at once.

In one sentence. Full attention on long video is too expensive; block-based sparse attention is rigid and misses semantic connections.

The algorithm as a flow

How the algorithm actually works

Tokenize video

Break video frames into small patches; stack them into 580k tokens (list-of-numbers format).

Router assigns groups

For each token, run it through a small learned table to get one score per group. Turn those scores into fractions (each summing to 1) and pick the group with the highest fraction. This cost is linear: one small table lookup per token.

Permute tokens by group

Reorder tokens so all group-1 tokens sit together, then group-2, etc. Enables fast grouped attention on GPU.

Compute grouped attention

For each group, run full attention only on tokens in that group (not all 580k). If tokens spread evenly, each group is small, and total work drops roughly by a factor equal to the number of groups.

Permute back and add balance penalty

Restore original order. During training, add a penalty that punishes the router if it dumps most tokens into a few groups.

What the paper changes

What changes

Standard attention compares every token to every other token across all 580k. MoGA computes only comparisons within each group. The object: which token pairs get compared.

the object it moves  =  attention pairs
The hidden quantity

The hidden quantity: group balance

measured quantity  =  how evenly tokens spread across groups

Group balance measures whether the router assigns tokens uniformly (each group gets roughly the same number) or dumps them into a few groups. Imbalance means wasted work: if 90% of tokens go to one group, attention within that group is still expensive and you get almost no speedup.

The paper enforces balance by adding a penalty during training that measures how unevenly tokens are spread. The penalty looks at how many tokens each group actually receives and compares that to how confident the router is about those assignments. When balanced, this penalty is low; when skewed, it grows, so the router learns to split tokens fairly across all groups.

Why it works

How a token picks its group, and what that buys

Picture the groups as a row of labelled bins. Each bin carries a short profile — a list of numbers the model learns during training that describes the kind of content that belongs in it. A token is also just a list of numbers describing one small patch of the video.

To place a token, the router scores it against every bin's profile in one quick step: the token is run through a small table holding all the profiles, which hands back one match-score per bin, and the token drops into the single best-matching bin. That is the whole decision — score a token against a fixed set of profiles, keep the top one. The thing it never does is compare a token to other tokens; it only checks the handful of bin-profiles. So the work grows in step with the number of tokens, not with that number multiplied by itself, and that single fact is what makes this cheap.

Now the model gathers each bin's tokens together and lets them look at one another in full: inside a bin, every token compares to every other, and to none outside. The costly everyone-looks-at-everyone step — the thing that normally makes long video unaffordable — now happens inside small bins instead of across the whole video.

The learned bins are not arbitrary. After training, a character's head, hands, and clothes tend to land in the same bin even across shots minutes apart, so the model keeps that character looking consistent through a long video while only ever paying the small within-bin cost. A second, fixed set of bins based on nearby space and time mops up the few links a single grouping would miss.

Math after the picture

Routing and balancing equations

First in words:

For each token, the router computes scores (one per group). These scores are turned into fractions that add to 1. The token is assigned to the group with the highest fraction. After routing, the cost of attention is the sum of the costs within each group. If tokens are perfectly balanced across groups, the total cost is roughly the full cost divided by the number of groups. The balance penalty looks at how many tokens each group gets versus how confident the router is about those assignments, and penalizes when they are imbalanced.

Then the compact form:

attention_cost = sum_j(N_j^2); balanced = N^2/M; L_gb = alpha·M·sum_j(F_j·P_j); total_loss = attention_loss + L_gb

Every symbol:

r_iM raw scores (one per group) for token i
Wrouter matrix, shape M×D (learned)
x_itoken i (a list of D numbers)
g_i^jprobability token i goes to group j (after softmax)
group_ithe group token i is assigned to (highest score)
N_jnumber of tokens assigned to group j
F_jfraction of tokens in group j (N_j/N)
P_javerage softmax probability for group j
alphabalance loss weight (hyperparameter)
A tiny worked example: M=5 groups, N=580k tokens
Fully balanced case: each group gets N/M = 116k tokens.
Within-group attention per group: 116k^2 = 13.45 billion comparisons.
Total for 5 groups: 5 × 13.45B = 67.25 billion comparisons.
Full attention baseline: 580k^2 = 336.4 billion comparisons.
Speedup factor: 336.4B / 67.25B = 5x (matching M=5 groups).
Imbalanced case: group 1 gets 450k tokens, group 2-5 get 32.5k each.
Imbalanced cost: (450k)^2 + 4×(32.5k)^2 = 202.5B + 4.2B = 206.7B (only 1.6x speedup, nearly collapsed).

The balance penalty pushes tokens to spread evenly, ensuring each group stays small and speedup remains proportional to the number of groups.

What can go wrong

What can go wrong

Router learns spatial patterns only, misses semantic ties. If the router groups only by nearness in time, tokens that belong together semantically (a character re-appearing after 200 frames) get routed apart. Cross-group bridges alone cannot recover long-range connections. Solution: validate that routing captures semantic meaning, not just spatial nearness.
Balance penalty too strong can limit router flexibility. Forcing perfect balance can starve the router of flexibility. Groups should reflect actual video structure, not forced uniformity. Solution: tune the balance penalty strength by experiment; it should penalize severe skew, not enforce rigid uniformity.
Reordering cost exceeds attention savings on small videos. On small videos or when the number of groups is large, reordering tokens and re-permuting outputs can exceed the within-group attention savings. Solution: MoGA is designed for videos with 500k or more tokens; use standard attention for short sequences.
Router learns semantic groups when balance is tuned well. With good initialization and balance penalty tuning, the router discovers semantic clusters (frame continuity, character identity, motion regions) and routes accordingly. Attention stays efficient and video quality is preserved.
What a runnable demo should prove

What a runnable demo should prove

Build a small diffusion video model (5000 effective tokens from a 10-second 480p video) with and without MoGA. Measure: (1) inference time per frame generation; (2) GPU memory used; (3) FID score (visual quality) on a held-out test set. MoGA should achieve ≥4x speedup and ≤50% memory increase compared to full attention, with FID within 1-2 points. Visualize routing: for a query token in the center of a frame, show which other tokens (by position and time) are routed to its group. Verify that tokens close in space-time and semantically similar get grouped together; tokens far apart and unrelated stay separate.

speedup = time_full / time_MoGA; memory_ratio = mem_MoGA / mem_full; fid_gap = |FID_MoGA - FID_full|

The demo must show both that MoGA runs fast with learned groups (routing visualization) and that quality is not sacrificed (FID, perceptual metrics).
