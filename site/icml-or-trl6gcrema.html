Uni-DHC: Adaptive Hypergraph Clustering Beyond Homophily

Instead of assuming neighboring nodes are alike, learn to treat each relationship type differently based on the data.

Paper explainersAll themesGraph & Geometric Learning

Most graph clustering methods assume that if two nodes are connected, they are similar — a feature called homophily. But real-world networks often break this rule: in a social network, someone might connect to people unlike them; in a knowledge graph, related concepts can be different. This paper proposes Uni-DHC, which learns to weight different connection types differently instead of using a fixed rule.

Zero assumption version

The world before this paper

When you cluster nodes in a graph, you want nodes that belong together to sit near each other. The oldest trick is homophily: if two nodes connect, assume they are in the same cluster. This works when the network is 'clean' — a friendship network where friends really do like each other.

But it fails when connections mean something else. In a citation network, a paper might cite a foundational work it strongly disagrees with. In a knowledge graph, 'opposite' and 'similar' are both real relationships. When adjacent nodes are actually from different clusters, fixed propagation methods (which treat all connections the same way) spread wrong information and mess up the clustering.

Fixed propagation treats every connection the same, so heterophilic data (where neighbors are unlike) breaks the clustering. Learn to weight each relationship type differently based on what the data shows.

The algorithm as a flow

What it actually does

Identify high-order relationships

Instead of just pairs of nodes, look at groups of 3, 4, or more nodes connected together (a hyperedge).

Learn a weight for each order

Assign a learnable number to pairs, triples, quadruples, etc., based on how useful each is for clustering.

Mix them adaptively

Blend the signals from each order type, where weights determine how much to trust each.

Clean up redundancy

Ensure that different hyperedges do not all send the same message (decorrelation); ensure each node does not simply copy its neighbors (node-level consistency).

Produce clean clusters

The result is a set of node groupings that cluster correctly even when neighbors are different.

What the paper changes

What the paper changes

Uni-DHC replaces the fixed propagation formula with a learnable function. In standard methods, every connection contributes the same; here, each connection type (pairs, triples, or larger groups) has its own learned importance score that adapts to the data.

the object it moves  =  propagation weights
The hidden quantity

The hidden quantity: multi-order importance

measured quantity  =  multi-order importance scores

The method learns a separate importance score for each level of grouping: how important are pairs of connected nodes, versus triples, versus larger groups. These scores are hidden but measurable — they tell us whether the data prefers simple pairwise links or complex group relationships.

The paper estimates these by minimizing a loss function that rewards correct clustering and penalizes redundant or contradictory messages from different hyperedges. Higher scores mean that order contributes more to the final node embeddings (learned representations).

Plain reading. You are trying to guess which people in a room are friends. You could use direct friendships (pairs). But you could also look at groups who do things together (triples). In a real social network, maybe pairs matter more than triples for clustering; in another dataset, the opposite is true. Uni-DHC learns which one matters by looking at the data.
Paper reading. The method learns a set of weights, one per hypergraph order, that mix high-order neighborhood information. From a spectral perspective, this creates a learnable polynomial filter (instead of a fixed low-pass filter), allowing the method to adjust its 'frequency response' to the data.
Why it works

Why learning multi-order weights fixes heterophily

In a homophilic network, all relationship types point the same direction: if A and B are neighbors, they are the same. A fixed weight works fine. But in heterophilic data, some relationships mean 'same' and others mean 'different'. A fixed method cannot distinguish them.

Uni-DHC assigns a learned number to each relationship type. When training on real data with correct labels, the method learns: 'type-A links are usually within-cluster, so use a high number for them; type-B links often cross clusters, so use a low or negative number.' This adaptive numbering stops wrong signals from drowning out the right ones, because now high-quality signals get amplified and bad signals get dampened.

Additionally, the paper adds two constraints: a node-level consistency term (saying each node's learned representation should be close to the average of its neighbors, to make training stable) and a hyperedge-level decorrelation term (saying different hyperedges should not all send the same information, to prevent all hyperedges from cancelling each other out). Together, these prevent the method from getting stuck in bad solutions.

The learnable spectral filter

First in words:

Total loss is: node embedding quality, plus node consistency penalty, plus hyperedge decorrelation penalty.

Then the compact form:

L = L_cluster + lambda_node * L_consistency + lambda_edge * L_decorr

Every symbol:

L_clusterloss from clustering objective (e.g., minimize within-cluster distance)
L_consistencypenalty if a node's embedding is far from its neighbors' average
L_decorrpenalty if different hyperedges send redundant information
lambda_nodeweight controlling how strongly to enforce node consistency
lambda_edgeweight controlling how strongly to enforce edge decorrelation
A tiny worked example
Suppose a dataset has 4 nodes split into 2 true clusters: {A, B} and {C, D}.
Initial guess: all relationship types matter equally (all weights = 0.5).
Training data shows: A-B and C-D are pairwise neighbors, but A-C and B-D are both in the same hyperedge.
Uni-DHC learns: pairwise weight = 0.8 (encourages same-cluster clustering), hyperedge weight = -0.2 (penalizes within-hyperedge mixing because this hyperedge bridges clusters).
Result: when propagating, pairwise signals dominate, and A and B end up similar to each other, as does C and D. Clusters emerge correctly even though the hyperedge structure was 'wrong'.

The learnable weights adapt the filter's response to the data, letting it pass the right signals (within-cluster links) and suppress the wrong ones (cross-cluster links).

What can go wrong

What can go wrong

Too many orders learned. If the method learns scores for pairs, triples, quadruples, and higher, the model can overfit, learning that a specific order is important in the training set but not in new data. The decorrelation constraint helps by forcing different hyperedges to stay distinct, so they do not all converge on the same false pattern. But on very large datasets, you may need to add extra penalties to prevent any one order from dominating unfairly.
Inconsistency and decorrelation at odds. Enforcing consistency (nodes stay close to neighbor average) while also decorrelating hyperedges can create tension during training. If lambda values are badly tuned, the method may not converge cleanly.
Heterophily must be measurable in hyperedges. If the dataset is heterophilic but all high-order hyperedges are also heterophilic (so no order type is reliable), the method cannot recover. It needs at least some orders that correlate with true clusters.
Done right. Set lambda values based on data size and hypergraph density. Test learned weights on a validation set to confirm they are interpretable. Use the method when you have reason to believe heterophily plays a role.
