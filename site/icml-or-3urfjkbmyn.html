The Generalization Spectrum: Measuring How Knowledge Travels

A framework that reveals not just whether an algorithm learns, but how far that learning extends to different variations of the same task.

Paper explainersAll themesLearning Theory

Standard tests measure learning with one single score: did the model pass the test? That hides the real story. This paper asks a deeper question: when an algorithm learns from one example, how far does that knowledge travel? Can it solve the same problem in a different programming language? With a completely different story wrapped around it? With a trickier variant? Or does the knowledge stay locked to the exact example it saw? The Generalization Spectrum is a measurement tool that reveals this hidden dimension of learning.

Zero assumption version

The gap between one score and one story

Every learning system is tested the same way: feed it examples, train it, then measure accuracy on new test problems. The result is one number. Did it work? Yes or no, 85% or 92%. That single number hides almost everything about what the model actually learned.

A beginner might think that if an algorithm scores 85% on math problems, it has learned math. But here is what that score does not tell: if you rephrase the same problem in a different way, does 85% of the knowledge still apply? If you ask the model to solve it in Python instead of JavaScript, can it? If you ask a variant that is algorithmically related but slightly different, how much does the training transfer? These are the real questions about understanding. One score collapses all of them into silence.

The method in one sentence. For each training example, build a ladder of test problems at increasing distances: exact repetition, then same problem in a different language, then same algorithm with a new story, then related problems, then completely different domain—and track how the algorithm's knowledge fades at each step.

The algorithm as a flow

What it actually does

Design a ladder of transfer distances

For one training problem, create variants at D0 (exact copy), D1 (same logic, different language), D2 (same algorithm, completely new narrative), D3 (related algorithmic family), D4 (unrelated baseline).

Train three different algorithms

Use the same training examples with RL (learn by reward), SFT (learn by example), and ICL (learn by retrieval). Carefully tune each so they memorize the training examples equally (matched at D0).

Test each one across the ladder

At each distance level D1, D2, D3, D4, measure how many problems each algorithm solves correctly. Record the decay curve.

Compare the shapes of decay

RL's curve stays higher because it learned algorithmic structure that survives format changes; SFT drops faster because it memorized surface details that break immediately; ICL depends on whether retrieval can find the structurally similar example.

Check where improvements actually go

When you add hints or modify training, measure whether the D0 score improves alone (memorization only) or whether the whole spectrum expands outward (true transfer), because local gains do not automatically extend generalization further.

What the paper changes

The object the paper moves

The paper changes what we measure. Instead of measuring learning as a binary outcome (passes or fails), it measures learning as a curve: a shape that shows how knowledge decays as test problems get further from the training example in four different dimensions (language, narrative, algorithm family, domain). The object is the evaluation itself—we are switching from a single number to a spectrum.

The hidden quantity

Transfer efficiency: how well memorization converts to generalization

measured quantity  =  Transfer efficiency

Transfer efficiency is the answer to this question: if an algorithm memorizes the training examples perfectly, how much of that memorized knowledge can it apply to problems it has never seen, arranged by increasing distance? This is not obvious. You can memorize perfectly and still transfer poorly. The paper measures this by comparing algorithms at matched memorization levels (all at D0), then seeing how far their knowledge extends beyond that.

The paper estimates transfer efficiency by selecting training checkpoints where all three algorithms (RL, SFT, ICL) achieve the same D0 performance, then comparing their performance on D1, D2, D3, D4 at those matched checkpoints. This isolates the transfer part from the memorization part.

Why it works

Why different algorithms produce different transfer profiles

Here is the real mechanism. When you train an algorithm to learn from examples, you are setting up a system to solve a problem. That system has to do two things: first, remember the exact training example (memorization), and second, apply what it remembers to new situations (generalization). These are competing pressures.

RL works differently from SFT. RL trains by reward: the algorithm gets points for solving problems correctly, and it learns to extract the abstract pattern because abstract patterns are more rewarding and more reliable across different versions of the problem. It naturally filters out surface details and keeps algorithmic structure. SFT trains by copying: the algorithm memorizes what you show it, and generalization happens only if it incidentally extracted a pattern. Hints and abstractions might help it memorize better, but they do not push it to generalize further, because the training signal is still fixed to that exact example. ICL works by retrieval: the algorithm looks for a similar example it has seen before, and copies its structure. This works beautifully on D1 and D2 (where the example it retrieves is still structurally similar), but fails at D3 and D4 because retrieval by surface similarity will not find the right example when the narrative and language have both changed.

Matched-memorization comparison isolates this. By selecting checkpoints where all three algorithms memorize equally, we remove memorization as a confounding factor. Now the differences in D1–D4 performance reflect pure transfer capability, not different levels of remembering.

Math after the picture

How to measure the spectrum shape

First in words:

Area Under Spectrum equals one-fourth times the sum of the normalized gains at each distance level, measuring average pass rate gain across D1, D2, D3, D4 relative to a baseline.

Then the compact form:

AUS = (1/4) * sum(Gain(i)) for i=1 to 4, where Gain(i) = pass@1(method at Di) - pass@1(baseline at Di)

Every symbol:

AUSArea Under Spectrum; the average gain across all transfer distances
Gain(i)How many more problems the algorithm solves at distance level i, compared to the base model
pass@1(method at Di)Fraction of problems the trained algorithm solves correctly at distance Di
pass@1(baseline at Di)Fraction the untrained base model solves at distance Di
DiThe transfer distance i: D0=exact copy, D1=new language, D2=new story, D3=related algorithm, D4=unrelated
A tiny worked example
Say the baseline model solves 10% of problems at each distance.
RL-trained model: D0=60%, D1=55%, D2=48%, D3=35%. Gain = (60-10) + (55-10) + (48-10) + (35-10) = 50 + 45 + 38 + 25 = 158. AUS = 158/4 = 39.5% average gain.
SFT-trained model: D0=60%, D1=42%, D2=20%, D3=12%. Gain = 50 + 32 + 10 + 2 = 94. AUS = 94/4 = 23.5% average gain.
RL transfers much more knowledge: 39.5% vs 23.5%. The spectrum curve shows RL's broad transfer and SFT's narrow tail.

AUS is simple: higher is better transfer, because averaging the normalized gains across all four distance levels rewards algorithms that maintain knowledge far rather than just near. The curve shape (which distances hold strength) tells you what your algorithm actually learned.

What can go wrong

What can go wrong

Matched-memorization not controlled. If you compare algorithms at different D0 performance levels, you confound memorization with transfer. You will not know whether RL wins because it transfers better or because it memorized better. The fix: select checkpoints where all algorithms achieve identical D0 pass rate, then compare D1+.
ICL retrieval finding the wrong example. In high-dimensional spaces, surface-similarity retrieval (embedding-based) will fail to find the structurally related example when language and narrative have both changed. ICL's far-transfer ceiling is not a learning limit; it is a retrieval limit. Hybrid retrieval (semantic + algorithmic tags) partially fixes this.
Training set size too small to separate effects. With only a handful of seed problems, ICL may reach its retrieval ceiling too early, SFT may not extract any pattern, and RL may over-optimize for narrow reward. To avoid false conclusions, training sets must be large enough for algorithm-mismatch failures to emerge clearly.
Spectrum correctly applied. Carefully construct each distance level so it isolates one type of transfer (language, narrative, algorithm family). Use a single seed set for all comparisons. Match algorithms at D0 before evaluating D1+. Record both absolute pass@1 and normalized gains. This is how you read what an algorithm really learned.
What a runnable demo should prove

What a runnable demo should prove

Build a small competitive-programming training setup. Pick five seed problems (e.g. sorting, dynamic programming, two-pointer, hash table, graph search). Create for each problem a D0–D4 ladder: exact code, Python then JavaScript version, code then pure-math-description version, two related problems from the same algorithmic family, one unrelated problem. Train a smaller language model using RL, SFT, and ICL on just these five seeds. Checkpoint each method at matched D0 performance. Then test each on the full D0–D4 ladder.

Transfer efficiency = (pass@D1 + pass@D2 + pass@D3 + pass@D4) / 4, showing which algorithm maintains knowledge furthest across distance.

The demo makes it impossible to ignore the shape of the decay curve, because you are measuring the actual change in solve rate at each distance rather than collapsing everything into a single summary number. RL will show a flat curve that holds far because it learned principles. SFT will show a cliff because it memorized surface details. ICL will show strong D1–D2 then collapse because retrieval fails when surface similarity breaks. One number (test accuracy) would hide all three stories.
