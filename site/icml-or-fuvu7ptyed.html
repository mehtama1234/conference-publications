DreamDojo: Robot World Model from Human Videos

A robot learns to simulate the real world by watching humans, using hidden action codes to steal physics knowledge from unlabeled videos.

Paper explainersAll themesGenerative models

Building a machine that predicts what happens when a robot moves is hard because robot videos are rare, and most videos have no label saying what motion was made. DreamDojo solves this by learning from 44,000 hours of human video first—cheap and plentiful—using hidden action codes (numbers the model learns) instead of waiting for humans to label every video. Then it adapts to a real robot with just a small amount of robot data. The result: a simulator (called a world model) that understands physics and can control a real robot's actions precisely.

Zero assumption version

Why robot simulators are stuck

To train a robot to do things (grasp, twist, place), you need to predict what happens when it moves. A simulator that knows physics lets you test thousands of actions safely before touching real hardware. But teaching a machine to predict robot motion is hard: real robot videos are scarce and expensive, so the machine sees only a tiny slice of the world's physics.

A beginner would try: collect 1,000 robot videos, label every frame with the joint angles that moved, and train a model to predict the next frame given the current frame and the action. This breaks immediately. First, labeling 1,000 videos takes months. Second, the machine only sees one robot's style and one set of objects; it fails on new objects or new robots. Third, 1,000 videos is not enough to learn the strange edge cases of physics (cloth tearing, objects sliding unpredictably).

The method in one sentence. Learn physics from 44,000 hours of cheap human videos using hidden action codes, then quickly adapt to a specific robot.

The algorithm as a flow

What it actually does

Step 1: Learn hidden action codes

Train a 700-million-parameter model to watch two video frames and guess which hidden code (learned number vector) connects them.

Step 2: Pretrain diffusion world model

Build a flow-matching model (one that generates video by removing noise in steps) conditioned on the learned action codes. Pretrain on 44,000 hours of human video.

Step 3: Adapt action layer to robot

Take the pretrained model. Erase the action layer. Retrain only that layer on robot data so the model learns this robot's joint angles, because different robots move differently (one arm might be stronger, another faster).

Step 4: Distill to fast version

Convert the model from bidirectional (reads all frames at once, slow) to autoregressive (reads left-to-right, fast), using only 4 denoising steps instead of 35.

Step 5: Run on robot

Feed current frame and desired action to the fast model; it predicts the next frame in real-time (10 FPS), letting the robot plan or learn from simulation.

What the paper changes

What the paper changes

The paper changes how the model is conditioned on actions. Instead of waiting for humans to label robot videos with exact joint angles (expensive and rare), it uses hidden action codes (vectors the model learns from unlabeled video pairs). This one change lets the model steal physics knowledge from 44,000 hours of human video, not just 50 robot videos.

the object it moves  =  action conditioning mechanism
The hidden quantity

The hidden quantity: learned action codes

measured quantity  =  Hidden action vector (learned motion signature)

The hidden quantity is a vector of learned numbers (the paper calls it a latent action). Each video pair (frame A to frame B) has one vector that the model learns represents the motion. These codes are discovered, not given: the model figures out which codes make sense by trying to predict videos. A code might represent close-hand, or push-forward, or twist-wrist—but the model does not name them; it just learns which codes compress the video data best.

The paper estimates these codes by training a 700-million-parameter neural network (a Transformer: a type of model that reads sequences of data) to watch two frames and output the code that likely caused the transition. After pretraining, the codes capture the essential patterns of human motion across all 44,000 hours of video.

Plain reading. Think of latent actions as discovered motion fingerprints. The model watches thousands of video clips and learns which fingerprints appear. Clips with similar motion get similar fingerprints, even if they look different (a human closing a hand vs. a gripper closing).
Paper reading. The latent action model is a 700M-parameter spatiotemporal Transformer trained to maximize the likelihood that predicted actions explain observed video transitions. The model learns a compact action space without supervision, enabling transfer from unlabeled human videos to robot embodiments.
Why it works

Why it works: stealing knowledge from humans

The trick is that motion patterns are the same across species and tools. When a human hand closes, a gripper closes—the physics of squeezing is identical. When a human pushes an object, a robot arm pushes an object—the physics of sliding friction is identical. Human videos contain trillions of hours of physics interactions; robot videos contain almost none.

By learning hidden action codes, the model finds the common denominator: every motion gets a code, whether it is a human or a robot. Pretraining on human videos teaches the model physics knowledge (how cloth wrinkles, how objects roll, how contact forces work) without needing robot labels. Then, when you show it robot data, you only have to teach it the robot's joint angles and movement ranges. The physics knowledge is already there, transferred.

The distillation step (converting to a fast, causal version) does not change the physics knowledge; it just makes the model run in 4 steps instead of 35, so the robot can simulate at 10 frames per second—fast enough for real-time planning and teleoperation.

The flow-matching equation

First in words:

Predicted flow direction = actual flow direction. A small denoising model learns to predict which direction the video should move at each noise level to match the clean version.

Then the compact form:

L_flow = E_t || v_t_predicted - v_t_true ||^2, where v_t is the velocity direction at noise level t

Every symbol:

v_t_predictedmodel output: which way the video should change at noise level t
v_t_trueground truth: actual direction from noisy to clean frame
tnoise level (0 = clean, 1 = pure noise)
E_taverage loss over all noise levels
|| ||^2squared distance (how wrong the prediction is)
A tiny worked example
Frame at noise level 0.3: model predicts velocity direction (down 2, right 3).
True clean frame would move (down 2.1, right 2.9) to reduce noise.
Prediction error: sqrt((2-2.1)^2 + (3-2.9)^2) = sqrt(0.01 + 0.01) = 0.14.
Repeat for levels 0.1, 0.5, 0.7, etc. Average all errors to get total loss.
During inference: start with pure noise, predict direction 35 times (slow) or 4 times (fast), follow arrows to clean frame.

The model learns to predict the direction toward a clean video frame at any noise level. This is faster than predicting the full frame because pointing in one direction requires fewer numbers than painting a whole image.

What can go wrong

What can go wrong

Mismatch between human and robot morphology. If the robot has very different body shape (e.g., a tentacle instead of a gripper), the latent action codes learned from humans may not transfer. The hidden codes capture human motion patterns, and a robot with very different limbs may not benefit much from pretraining.
Extreme unseen tasks. If the robot must do something no human in the dataset ever did (e.g., operate in zero gravity, or interact with an object that never appeared), pretraining helps less because the physics is genuinely unfamiliar.
Speed requires distillation step. The base model uses 35 denoising steps and runs at 0.1 FPS (too slow for real-time planning). The paper's distillation pipeline (4 steps, 10 FPS) requires retraining. If distillation fails, you are stuck with a slow simulator.
Done right: the method handles. The paper shows that latent action pretraining works on multiple robots (GR-1, AgiBot, YAM) and generalizes to unseen objects and unusual environments, as long as they are not radically alien (robotic morphology + physics within human experience).
What a runnable demo should prove

What a runnable demo should prove

A demo should show that the world model can predict robot motion it has never seen before. Start with a pretrained DreamDojo model. Give it an unseen grasp task: a new object shape, a new hand pose, a new action sequence. Feed a video of the current scene and a command (e.g., close-hand). Run the model to predict the next 10 frames. Compare the prediction to the real robot video (held out from training). Measure prediction accuracy (pixel-level error, or a learned metric). Then show that the same pretrained model, finetuned on just 50 real robot videos, predicts better than a model trained only on those 50 videos with no pretraining, because the pretrained knowledge of physics (how objects slide, collide, flex) carries over and needs less robot data to specialize.

generalization accuracy = (frames where predicted video matches real video within 5% pixel error) / (total predicted frames)

The demo makes impossible to miss: a model that watched humans (no robot labels) predicts robot motion it never saw, and finetuning on tiny robot data refines it. Pretraining steals physics knowledge from humans.
