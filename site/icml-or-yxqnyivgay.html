TimeRCD: Anomaly Detection by Comparing Patterns to Their Context

A model learns to spot time-series anomalies by comparing each pattern against its surrounding normal context, not by memorizing what normal looks like.

Paper explainersAll themesTime Series & Sequential

Time series anomaly detection is spotting the strange moments in a stream of data, like detecting unusual heart-rate patterns in medical sensors. Most methods learn what normal looks like, then flag anything that doesn't match. The problem: they often get fooled. A genuinely complex but normal pattern looks weird. A subtle anomaly reconstructs perfectly. TimeRCD works differently: it teaches a model to spot anomalies by asking "is this pattern odd compared to what's around it", not "does it match what I memorized as normal."

Zero assumption version

Why reconstruction scoring fails

Time series are long chains of numbers: stock prices, sensor readings, network traffic. An anomaly is a moment when the pattern breaks from normal. A naive approach: train a model on normal data to reproduce it, then at test time, if a new pattern has high reconstruction error (the model's output is far from the input), flag it as an anomaly.

This breaks in two ways. First: a subtle anomaly might still reconstruct perfectly, because it is just a tiny tweak—the model can copy it faithfully. Second: a complex but completely normal pattern from a new domain—a sensor dataset where readings are naturally higher or lower than the training data—looks alien to the memorized normal, so it reconstructs poorly and gets falsely flagged. The model has learned one fixed idea of what normal is, and that idea doesn't transfer to data it has never seen.

The solution in one sentence. Train a model to spot anomalies by comparing each pattern to the context around it, so it learns to recognize odd-ness relative to local normal, not against a fixed global pattern.

The algorithm as a flow

What it actually does

Step 1: Get the context

For each moment in the time series, grab the chunk right before and right after it.

Step 2: Query versus context

Feed the model the current pattern plus its context. The model scores: how different is the current pattern from what the neighbors suggest is normal here?

Step 3: Detect via discrepancy

High discrepancy score means the pattern looks odd given its local context. That is the anomaly signal.

Step 4: Pre-train on synthetic data

The model learns this discrepancy task on millions of generated time series with known anomalies planted in, so it generalizes to new domains.

Step 5: Zero-shot on unseen data

At test time, on a brand new dataset never seen before, compute the discrepancy score directly. No retraining needed.

What the paper changes

The one thing the method changes

Instead of training a model to reconstruct the input (and flagging high reconstruction error as anomalies), the paper trains a model to compute a score that measures how different the current pattern is from what its surrounding context predicts should be normal. The object being changed is the scoring function itself: from reconstruction error to context-relative discrepancy.

the object it moves  =  scoring function
The hidden quantity

The hidden quantity: Relative Context Discrepancy

measured quantity  =  Relative Context Discrepancy (RCD)

This is the core number the paper measures. For any moment in time, RCD answers: how far does the current pattern deviate from what the patterns around it suggest should be normal here? If you see a calm pattern, then sudden spike, then calm again, the RCD at that spike is high. If you see a calm pattern, a tiny tweak, then calm again, the RCD at the tweak is also high—the discrepancy catches both large jumps and subtle wrong-ness.

The paper estimates RCD by passing the context and query to a neural network (a Transformer architecture: a model that reads sequences of numbers and compares them). During pre-training, the model learns from millions of synthetic time series where anomalies are explicitly marked, so it learns to recognize which patterns truly stick out. Once trained, RCD can be computed on any new time series without retraining.

Why it works

Why it works: the causal chain

The core mechanism: normal patterns look consistent with their surroundings. Anomalies stick out. By training the model to learn the relationship between a pattern and its local context (instead of memorizing a global normal), it learns what normal means by looking at context, not by fixed rules. When it sees a new domain where the numbers are bigger or hotter, the context still tells it what should be normal there, because the anomaly is still the weird one relative to the locally normal background.

During pre-training, the model sees millions of examples where a context is normal and the query is either normal-looking-given-the-context or anomalous-given-the-context. It learns the distinguishing features: a spike that contradicts surrounding calmness, a pattern that breaks the local trend, a sudden change in variability. These features travel to new domains because they are about relative mismatch, not about absolute values. In zero-shot testing, the model runs the same scoring on unseen data—no retraining needed, because it never relied on memorizing what normal looks like globally.

Math after the picture

The equation

First in words:

Anomaly score equals how far the current pattern sits from what the context-aware model predicts should be normal.

Then the compact form:

RCD_t = distance(query_t, context_prediction(left_t, right_t))

Every symbol:

RCD_tthe discrepancy score at time t
query_tthe pattern values at time t
context_prediction(left_t, right_t)the model's estimate of what should be normal at t, given left and right context
distance(...)how far apart the two are (e.g., squared difference)
A tiny worked example
At time t=5, left context shows [20, 21, 22]. Right context shows [21, 22, 20].
The context-aware model predicts the normal value at t=5 should be around 21.
The actual query value is 21. Distance is 0. RCD_5 = 0 (no anomaly).
Later, at t=50, left context is [20, 21, 22]. Right context is [21, 22, 20].
Model predicts 21 again. But the actual value is 50. Distance is 29. RCD_50 = 29^2 = 841 (high, anomaly flagged).
Same context, but a spike at one point triggers the anomaly score.

The model learns during pre-training what context patterns matter for predicting normal; at test time, any deviance from that prediction scores as anomaly, working on new domains because the context is local.

What can go wrong

What can go wrong

Anomalies that ARE the context. If an anomaly occurs everywhere in a chunk (the entire context is weird), there is no normal local pattern to compare against. The anomaly blends in, because everything around it is also anomalous. The model relies on having truly normal context to spot the odd one out.
The context window is too short. If you only look one step left and right, and the anomaly spreads across three consecutive moments, each moment has an anomalous neighbor, so the context is contaminated. Choosing the right context size determines whether the method works.
The synthetic training data is biased. If the synthetic pre-training corpus does not include examples of the kinds of anomalies you care about in the real domain, the model will not learn to recognize them. Synthetic data quality matters for zero-shot generalization.
Done right: mixed anomalies and normal. When the context is truly normal and the query is truly anomalous, or vice versa, the relative discrepancy signal is strong. The method works best when anomalies are local and context is clean.
What a runnable demo should prove

What a runnable demo should prove

Build a simple time series from two domains: (1) normal oscillations between 20 and 30, and (2) normal oscillations between 60 and 70 (representing different sensors or operating conditions). Plant a spike anomaly (value jumps to 100) at a random location in each. Train the old reconstruction-error method on domain 1 only. Train TimeRCD on a synthetic corpus mixing both domains with random anomalies planted. Test both on domain 2 (the unseen domain). The reconstruction model should falsely flag many domain-2 normals (because the baseline values are so different). TimeRCD should catch the spike and ignore the domain-2 normals (because it compares to local context). Plot a chart showing detection rate on true anomalies and false-positive rate on normal-from-new-domain. TimeRCD should win on both.

Detection rate = (anomalies correctly flagged) / (total anomalies); False positive rate = (normal patterns wrongly flagged) / (total normal patterns)

The core proof: zero-shot generalization to a new domain. The method must spot the spike on domain-2 despite never training on domain-2 data, while reconstruction error must fail because it was trained only on domain-1's normal baseline.
