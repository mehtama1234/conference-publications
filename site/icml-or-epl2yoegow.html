AgentXRay: White-Boxing Agentic Systems via Workflow Reconstruction

Recover an editable workflow for a black-box agent by searching for a small chain of roles and tool calls that matches its input-output behavior.

Paper explainersAll themesAgents & Tool Use

Many deployed agent systems are hard to inspect. A user can send a task and see the answer, but cannot see which roles were used, which tool calls were made, or where waste entered the process. AgentXRay reconstructs a stand-in workflow from input-output examples so that people can inspect and edit a readable version of the system because workflow structure matters for control and debugging.

Zero assumption version

Why black-box agents are hard to control

A black-box agent can solve a task while hiding the process that produced the answer. That makes it hard to tell whether the system is using too many steps, relying on the wrong tool, or mixing several roles in a wasteful order because the user never sees the intermediate decisions.

Input-output testing alone is limited because two systems can give similar answers while using very different internal workflows. If you want a system that you can edit, audit, or simplify, you need a readable stand-in process rather than only a score on final outputs.

The paper's move in one sentence. Search over candidate role-and-tool workflows until one reproduces the black-box outputs closely enough to serve as an editable stand-in.

The algorithm as a flow

What it actually does

Define a workflow search space

List the possible roles, tool calls, and chain positions that a candidate workflow may use.

Run the candidate workflow on observed inputs

Execute the current stand-in workflow so that its outputs can be compared with the black-box outputs.

Score output similarity

Measure how close the candidate outputs are to the target outputs because the stand-in only matters if it reproduces the visible behavior.

Expand promising branches

Use tree search to add new roles or tool calls where the current partial workflow still looks promising.

Prune weak branches

Remove candidates that are too weak for their depth so that more of the search budget goes to plausible workflows.

The hidden quantity

The hidden quantity

measured quantity  =  which workflow best explains the black-box behavior

The central hidden quantity is the workflow that best explains the black-box system's behavior. You cannot observe that workflow directly, and the real system may not even have a tidy named workflow inside it.

AgentXRay treats workflow choice as a hidden explanation problem. It searches for the smallest chain of roles and tools that reproduces the target outputs well enough because a compact readable workflow is easier to inspect and change.

Why it works

Why this works: search for process, not only answers

A single correct answer does not reveal how it was produced. AgentXRay therefore searches over workflows and scores each one against visible outputs. Over many examples, weak workflows fall behind because they cannot keep matching the target behavior across different inputs.

The pruning rule matters because the workflow space grows quickly with depth. If the search keeps every partial branch, most of the budget is wasted on branches that already look poor. By combining quality and depth in the pruning score, the method spends more trials on branches that still have a realistic path to a good stand-in workflow.

Math after the picture

Score a workflow by output match minus search cost

First in words:

A compact view is to reward workflows that imitate the black-box outputs and penalize depth or wasted complexity. The search then keeps workflows with higher total value.

Then the compact form:

score(workflow) = match(workflow) - alpha * depth(workflow)

Every symbol:

score(workflow)overall search value of one candidate workflow
match(workflow)how well its outputs match the black-box outputs
alphaweight on workflow depth
depth(workflow)number of steps or chain length in the candidate workflow
A tiny worked example
Workflow A matches the target well with match 9 and depth 5.
Workflow B matches slightly worse with match 8 but depth 2.
If alpha = 1, score(A) = 9 - 5 = 4.
Score(B) = 8 - 2 = 6.
The search keeps Workflow B because it is nearly as accurate and much easier to inspect.

The paper uses a richer search rule, but this equation captures the tradeoff between imitation quality and workflow size.

What can go wrong

What can go wrong

The proxy score may miss hidden differences. Two workflows may give similar outputs on the test set even though they would behave differently on new tasks, because the visible proxy cannot capture every internal distinction.
The search space may exclude the true process. If an important role or tool type is missing from the search space, the best recovered workflow can only be an approximation.
Pruning can remove a late-blooming branch. A branch may look weak at shallow depth and then improve after one extra step, so early pruning can discard a candidate that would have become strong because the needed evidence had not appeared yet.
Done right. The method is useful because it produces a workflow that humans can edit, compare, and simplify instead of only a hidden model score.
