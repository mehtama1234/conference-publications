Learning representations and embeddings

Papers on extracting meaningful vector representations from graphs that capture structure and relationships, using techniques like contrastive learning and self-supervision.

What this is

One of the most practical tools in machine learning is turning data into vectors—embeddings. An embedding is a list of numbers that captures the essence of a thing. If you have good embeddings, you can do almost anything: find similar items (users similar to you), cluster things, detect anomalies, transfer learning to new tasks. The question for graphs is: how do you turn a node, a subgraph, or an entire graph into a fixed-size vector that preserves its important properties?

The challenge is deciding what should be similar. Do you want embeddings to be similar if two nodes have similar neighborhoods? If they play similar roles in the network? If they lead to similar outcomes? Different tasks need different embeddings. Also, graphs are not fixed in size—one graph might have 100 nodes, another might have a million. You need a way to turn variable-size structures into fixed-size vectors. And you want embeddings to be stable: small changes to the graph should cause small changes to the embedding, not flip it completely.

Papers use self-supervised learning: instead of needing labeled examples, they learn embeddings by solving puzzles that the graph itself provides. For example, predict a node's neighbors from its embedding, or predict which part of the graph is deleted from what remains. They use contrastive learning: train the model so that similar things get close embeddings and different things get far apart, using the network structure to define similarity. Some use pretraining on huge graphs and then fine-tune on downstream tasks. The result is embeddings that capture intricate patterns and work across many different graph learning problems.

How the work breaks down

The work in this subtheme splits into several natural directions because the embedding problem branches into distinct sub-problems: improving how graph structure is turned into fixed-size lists of numbers through better positional signals and feature extraction, so the lists capture structural detail; using self-supervised learning and contrastive methods to learn these numerical lists without hand-labeled data, since labeled graphs are scarce; understanding what these numerical lists can and cannot do for prediction tasks, so practitioners know when to add complexity; and handling special graph types like multimodal graphs, hypergraphs, and graphs that change over time, because real data doesn't fit the standard assumptions.

Positional encodings and topological features

A core problem: when you build numerical lists for nodes, you need to tell the model where each node sits in the graph's structure and shape. Positional encodings are fixed numbers that describe a node's position and local shape. Standard approaches (like distances from each node to a few landmarks) are rigid and miss subtle structural patterns. The challenge is creating encodings that can learn which topological features (loops, branches, connected regions) matter for your specific task, while staying stable under small graph changes.

LEAP tackles this by learning positional encodings based on persistent homology—a mathematical tool that finds shape features at different scales. Instead of hand-designing which features to use, LEAP lets the model learn which topological properties (connected regions, loops, voids) are useful for the task at hand. The Graph Meta-Network for Kolmogorov-Arnold Networks does something complementary: it learns task-specific structure by treating graph topology as a first-class object that should guide how the model processes information, not just as auxiliary data. Unfolded Laplacian Spectral Embedding provides a theoretically grounded way to embed dynamic graphs—graphs that change over time—by analyzing how the graph's spectral properties (eigenvalues) relate to its conductance (how easily things flow through it), and proving that embeddings stay stable as the graph evolves.

Together, these three papers show that effective embeddings need both: fine-grained topological feature extraction and theoretical guarantees that embeddings won't break when the graph changes slightly.

Self-supervised learning and contrastive methods

Learning embeddings without labels means the model must extract patterns from the graph structure itself. Contrastive learning works by pulling similar pairs close and pushing dissimilar pairs apart, using the network structure to decide what 'similar' means. The challenge is deciding which similarity signals matter and how to balance multiple objectives—perhaps you want nodes with similar neighborhoods close in embedding space, but also nodes playing similar roles in the graph close, and also nodes that lead to similar outcomes close. These goals can conflict.

Feedback Control for Multi-Objective Graph Self-Supervision solves this by automatically learning to weight different learning objectives as training progresses, like a control system that adjusts the dial on multiple knobs. The model produces auditable schedules showing which objectives drove learning at each stage. H2CL (Heterogeneity-Aware Hypergraph Contrastive Learning) handles a harder case: hypergraphs where edges can connect any number of nodes at once, not just pairs. Connected nodes in hypergraphs often have different properties (high heterogeneity), so treating all edges the same breaks contrastive learning. H2CL learns to reweight edges based on how similar the connected nodes are, making the contrastive signal clearer. SFCLTA (Spectral Fusion Contrastive Learning) addresses graphs where connected nodes often have different labels or features (heterophilic graphs), which violates the usual assumption that similarity in the graph structure means similarity in semantics. It uses spectral augmentation to make contrastive learning work on these graphs.

These three papers show how to make contrastive learning flexible and practical for diverse graph types and multiple simultaneous objectives.

Understanding embedding limits and architectural choices

Before investing in a new embedding architecture, you need to know what its theoretical limits are and which design choices actually help, because adding complexity without knowing its benefit wastes compute and may hurt performance. A natural question: when you embed nodes and train a model to predict links between them, what is the best strategy? Is a simple linear layer on top of embeddings enough, or do you need nonlinear layers? When representing a graph implicitly (as a function that computes node features on demand, rather than materializing all nodes) how do you efficiently compute approximate random features, so you can run on large graphs without running out of memory?

On the Theoretical Limitations of Embedding-based Link Prediction proves that nonlinear output layers improve both ranking performance and probability estimates, especially for large dense graphs, and reveals that linear layers fundamentally underfit on these cases because they cannot fit the complex relationships in the data. This tells practitioners when to add nonlinearity. SWING (Unlocking Implicit Graph Representations for Graph Random Features) solves acceleration problems: representing huge graphs explicitly requires too much memory, but computing random features from an implicit representation was thought to require materializing the full graph. SWING shows how to compute these features directly from the implicit representation without ever materializing nodes, enabling accelerators to run at full speed so massive graphs become practical. Graph is a Natural Regularization revisits vector quantization—a compression technique that replaces embedding values with code-book entries—as a regularizer for graph learning. The graph structure itself acts as a natural regularizer, so simpler quantization schemes work better because the graph structure constrains what needs to be learned, improving both efficiency and performance.

These three papers validate key architectural decisions and show that sometimes simple methods work better when you respect the graph's mathematical structure, because fighting against the structure requires extra complexity.

Curved spaces and special geometric representations

Not all embeddings live in flat Euclidean space. Some graph properties are better captured in hyperbolic space (which grows exponentially and naturally fits tree-like hierarchical structures) because trees embed efficiently there with less distortion, or on special mathematical surfaces like positive semi-definite matrices. Each choice has trade-offs in compute cost, interpretability, and what patterns it can capture, so you must match the space to your graph type.

Bridging ML and Algorithms compares three types of hyperbolic embeddings and shows that the fast Blasius algorithm runs 100 times faster than Poincaré and Lorentz embeddings while keeping the same or better quality, making hyperbolic representations practical for large graphs because speed matters in deployment. PointCHR (Point Cloud Analysis via Curvature-Aware Hyperbolic Rectification) uses hyperbolic space specifically for point clouds—a type of graph that describes 3D shapes. By analyzing local curvature (how bent the surface is) and mapping that into hyperbolic space, it captures fine detail with higher expressiveness because hyperbolic space has negative curvature and naturally preserves hierarchical distance relationships. Sheaf Neural Networks on SPD Manifolds extends neural networks to work on symmetric positive-definite matrices (a special mathematical surface), showing this is more expressive than flat Euclidean space for chemistry tasks because chemical structures have covariance-like properties. These papers show that picking the right mathematical space—hyperbolic, flat, or a specialized surface—makes embeddings fit the graph's structure better because different spaces have different distance properties.

The insight: the mathematical space you choose determines what structural patterns the embedding can faithfully capture.

Specialized graph types and transfer learning

Real graphs often have multiple types of information—nodes with multiple attributes, multimodal content, or edges with different meanings. Other graphs are specific to domains like traffic networks that need to transfer across cities. And graphs change distribution between training and test, which can break embeddings that fit too tightly to training data. These specialized settings require careful design to keep embeddings working well.

A Graph Foundation Model with Cross-Modal Alignment learns embeddings that fuse information from multiple modalities (text, images, structured attributes) on the same graph, using expert layers that specialize in different modalities and routing mechanisms that decide which experts to use. Aitchison Embeddings for Learning Compositional Graph Representations uses a mathematical construction from compositional data analysis (a field that handles data that must sum to a constant, like proportions). This gives built-in interpretability: you can see which components contribute to each embedding by construction, because the construction itself encodes meaning. The Stable Graph Generalization paper shows how to learn embeddings that work when the graph distribution changes by finding central points that stay fixed across different distributions, so embeddings stay stable when the graph distribution shifts because the central point is invariant. Seeking Commonality, Preserving Specificity learns road network embeddings for traffic prediction that work across cities; it bounds the difference between cities while learning shared representations, so each city's specific patterns are preserved because shared and city-specific encodings are separated. When Do Graph Foundation Models Transfer provides theory for when pretrained graph embeddings transfer to new tasks and gives guidance on which data to collect for better transfer because certain positional encoding properties determine whether transfer succeeds, showing that positional encoding stability is key.

Together these papers address the practical reality that real graphs are heterogeneous and deployments must work across different data distributions.
