Language Generation with Feedback: Queries and Mistakes

A method that teaches a language generator what is correct by only telling it when it makes mistakes or letting it check strings one at a time.

Paper explainersAll themesLearning Theory

Teaching a machine to generate correct text is hard when you cannot show it the full answer. This paper studies two simpler teaching methods: one where you only tell the machine when it gets it wrong, like a coach in a game, and another where the machine can ask you whether a generated string is right. The paper discovers exactly which types of languages can be learned this way, even when the feedback is sometimes wrong.

Zero assumption version

The learning puzzle without full answers

Imagine teaching a child to write poems, but you do not show them correct poems. Instead, you only say yes or no to what they write. Two teaching methods emerge: (1) tell the child when they write something bad (mistake feedback), or (2) let the child ask you whether a line they wrote fits the poem-form (query feedback). Without these hints, the child is stuck guessing forever.

This is the core puzzle a language generator faces. The generator must produce strings (sequences of words) that belong to a target language (the correct set, e.g. grammatical poems). But the generator only sees sparse signals about which strings are right. The naive approach fails: without any feedback, the generator generates blindly; with feedback only on mistakes, it might miss what it needs to learn to recognize good outputs.

In one sentence. The paper characterizes exactly which types of languages can be learned when the generator gets only mistake feedback or only one-at-a-time query feedback.

What the paper changes

What the paper changes

Standard language learning assumes the generator sees pairs of strings and their labels (is this string valid? yes or no). This paper eliminates that luxury. Instead, the generator receives only two weaker signal types: (1) notification of mistakes (the generator learns what not to generate) or (2) permission to ask yes-or-no questions about individual strings (the generator learns via queries). The paper does not change the generator itself, but changes which feedback signals it receives, and proves which language-types remain learnable under these constraints.

The hidden quantity

The learnable boundary: which languages admit feedback-based learning

measured quantity  =  Learnability under weak feedback

The paper's core measurement is a binary property: does a given language-type admit a learning algorithm under mistake feedback (or query feedback)? This is not a single number but a characterization—a set of mathematical properties that a language must have to be learnable given only sparse signals. The paper derives the exact conditions.

The paper estimates this by constructing explicit online learning algorithms that handle each feedback type, then proving they succeed for some language-types and fail for others. It identifies closure properties (which combinations of learnable languages remain learnable) and noise tolerance (how much false feedback the algorithm can handle before it breaks).

Paper reading. Why it works

Why mistake and query feedback enable learning

Mistake feedback works because each mistake tells the generator what NOT to do. In online learning (a classical model from computer science), the learner makes a guess, observes whether it was right or wrong, and updates. Over many iterations, the learner narrows down the target language by eliminating impossible possibilities. The paper applies this framework to language generation: the generator proposes a string, learns which strings are forbidden, and uses that growing list of forbidden strings to sculpt the space of allowable outputs.

Query feedback works differently: it lets the generator choose which strings to probe. Instead of waiting for random feedback, the generator can strategically ask about boundary cases. This gives the generator more control over what it learns about. The paper shows that some language-types require this active probing to be learned, while others learn fine with passive mistake feedback alone.

Both mechanisms exploit a key insight: language-types have structure. Some collections of strings are closed under certain operations (if A and B are valid, their union might be too). The paper proves that this structure determines learnability. Tolerance to noisy feedback follows because the learner can detect contradictions: if feedback says a string is both valid and invalid, the learner recognizes contamination and down-weights that feedback signal.

The characterization equation

First in words:

A language-type is learnable under mistake feedback if and only if it satisfies certain structural closure properties (closure under specific operations).

Then the compact form:

Learnable(L, feedback_type) = CheckStructure(L, {closure_union, closure_intersection, closure_complement})

Every symbol:

A tiny worked example
Language 1: all strings of even length. Closed under union (even+even=even)? Yes. Closed under complement (odd strings)? Yes. Conclusion: learnable under mistake feedback.
Language 2: all palindromes (reads same forwards and backwards). Closed under union? No (concatenating two palindromes does not always give a palindrome). Conclusion: may not be learnable without additional structure.
The paper's characterization formalizes these checks for all language-types, determining exactly which admit learning under each feedback regime.

The actual formal characterization uses the theory of learning via queries and mistakes from online learning; the above is a simplified illustration of the type of structural condition.

What can go wrong

What can go wrong

Non-learnable language-types. Some languages lack the structural closure properties needed for learning. For these, neither mistake feedback nor query feedback is enough; the generator gets stuck unable to distinguish the target from close imposters.
Unbounded feedback rounds required. Even for learnable language-types, the number of mistakes or queries needed to converge can grow exponentially in the language size. In practice, the generator may time out before learning.
Noise contamination. If the feedback source is noisy (says a valid string is invalid, or vice versa), the learner can be misled. The paper shows that tolerance to noise has limits: arbitrary contamination in examples breaks learning; finite contamination is tolerable.
Done right. For learnable language-types with clean or mildly noisy feedback, the algorithms in this paper converge to the target language reliably, and the same learnability holds even under noise.
What a runnable demo should prove

What a runnable demo should prove

A working demo should pick a concrete language-type (e.g., strings of even length, or strings matching a simple regex pattern) and implement an online learning algorithm that generates candidate strings, receives mistake feedback (or sends queries), and observes convergence. The demo should show two language-types: one that is learnable (the algorithm converges to correct generation) and one that is not (the algorithm fails or oscillates). Track the number of mistakes or queries needed and show how noise in the feedback degrades performance.

Accuracy = (correct strings generated after N feedback rounds) / (total strings attempted) ; Learnability = did the algorithm converge to the target language before N exceeded a budget?

The key takeaway: some languages can be learned from sparse signals (mistakes or queries); the structure of the language determines whether learning is possible at all (because closure properties let the learner generalize from examples to rule out impossible languages), and tolerance to noise follows from the same structural properties that enable learning.
