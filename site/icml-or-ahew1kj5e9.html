CELL: Fairness-aware Graph Adaptation Without Target Labels

Predict fairly on a new graph by separating what matters for the task from what only reflects demographic groups, without needing the sensitive attributes of the new graph.

Paper explainersAll themesGraph & Geometric Learning

Graphs (networks of connected items) encode relationships in real data — social networks, citation systems, disease spread. When you train a model on one graph to predict on another, the model often learns to use demographic features like race or gender unfairly, hurting certain groups. This paper fixes that by decomposing what the model learns into two pieces: features that predict the task honestly, and features that leak demographic information. By keeping only the honest piece and guessing the demographic attributes from the unlabeled target graph, the method works fairly even when you don't have target-graph sensitive attributes.

Zero assumption version

The unfair transfer problem

You have a labeled training graph — say, a social network with nodes (people) and edges (friendships) — and a task like detecting who has a job. You train a model on it. Then you need to predict on a new unlabeled graph (a different social network). The naive approach: use the same model directly. This often fails not just because the graphs differ, but because the model has learned to use sensitive attributes (race, gender, age) as shortcuts to predict jobs. If the model learned 'women are less likely to have jobs' from the training data, it will unfairly penalize women in the new graph.

Standard fairness methods ask: what if we had the sensitive attributes (age, race, etc.) in the target graph too? Then we could force the model to ignore them there. But in reality, you usually cannot get that data — it is private, restricted, or simply not collected.

The challenge in one sentence. Make a model that predicts fairly on a new unlabeled graph, even though you do not know the sensitive attributes there.

The algorithm as a flow

What it actually does

Split the learned features

Train two encoders on the source graph: one learns features tied to task success (job prediction), the other learns demographic shortcuts (gender bias).

Measure crosstalk

Measure how much information about the demographic features leaks into the task features. Push them apart by minimizing this crosstalk.

Guess target demographics

On the new unlabeled graph, guess what the demographic attributes probably are by looking at structure and the fair features.

Align graph structure

Use a bipartite bridge graph (connecting source and target nodes in a fairness-aware way) to teach the model how graphs differ without using unfair shortcuts.

Predict with only the fair path

On target data, use only the task features, not the demographic encoder. Predictions now ignore the bias learned from source.

What the paper changes

What the method changes

CELL changes which features the model uses to make predictions. Instead of one jumbled set of features (both fair and biased), it creates two separate paths: one for honest task signals, one for demographic bias. Then it blocks the bias path at test time, so fairness is guaranteed.

the object it moves  =  which features predict
The hidden quantity

The hidden quantity: demographic leakage

measured quantity  =  how much demographic information is in the task features

The paper measures something invisible: how much information about sensitive attributes (like gender or race) is accidentally baked into the features that predict the main task. This is called conditional mutual information — a number measuring how much two things tell you about each other when you already know a third thing. In this case: how much do the task features predict gender, given that you already know the task label?

CELL estimates this by looking at how much the demographic encoder's outputs overlap with the task encoder's outputs. If the demographic encoder can easily guess someone's gender from the task features, the leakage is high. The method then minimizes this overlap by pushing the two encoders to extract completely different things.

Why it works

Why separation and pseudo-labeling work together

The core idea: if you force two encoders to extract completely different information (one for the task, one for demographics), the model stops using demographic shortcuts for the main prediction. The task encoder has no choice but to find real patterns.

But the target graph is unlabeled, so how do you know if the split is working there? CELL uses pseudo-labels — educated guesses about what the target demographic attributes probably are, inferred from the structure of the target graph and the fair features. These guesses give the demographic encoder something to latch onto, anchoring the separation even with no ground truth. The bipartite bridge graph (links between source and target nodes chosen fairly) provides additional structural hints about how graphs differ, steering alignment without bias.

Result: the task features generalize to the target because they encode real task patterns, not dataset shortcuts. The demographic path is silenced at test time, removing unfair predictions.

Math after the picture

The disentanglement equation

First in words:

minimize task loss plus weighted crosstalk between task and demographic encoders, plus alignment loss with the bridge graph

Then the compact form:

L_total = L_task + lambda_d * I(Z_s; Z_t | Y) + lambda_align * L_bridge

Every symbol:

L_tasktask prediction error on source graph
I(Z_s; Z_t | Y)how much demographic features Z_s overlap with task features Z_t, knowing the label Y (the leakage)
lambda_dweight controlling how hard to enforce separation
L_bridgealignment loss from the fairness-aware bridge graph
lambda_alignweight on bridge alignment
A tiny worked example
Say task encoder learns: person-A has features (job=0.8, gender-leakage=0.3). Demographic encoder independently learns: person-A is female (0.9). Crosstalk I(Z_s; Z_t) is high because task features hint at gender.
CELL adds penalty: lambda_d * 0.3 * 0.9 = 0.15 to loss, pushing them apart.
After training, task features are (job=0.8, gender-leakage=0.01). Now demographic encoder cannot guess gender from task features. Crosstalk penalty shrinks to 0.01 * 0.9 = 0.009.
At test time on target: predict using only (job=0.8, irrelevant-noise=0.01), ignore the demographic encoder. Fairness is intact because no gender signal remains in the task path.

The equation enforces that task and demographic encoders extract unrelated information. Separating them works because a demographic encoder with no task information is forced to find demographic shortcuts instead of task patterns, so the task encoder must use real task signals. The bridge helps both paths generalize without bias by teaching alignment through fair node pairs.

What can go wrong

What can go wrong

Pseudo-labels are wrong. If the guessed target demographic attributes are inaccurate, the demographic encoder trains on false data, and separation may leak unfair features into the task path. Confidence thresholding helps by ignoring low-confidence pseudo-labels, but does not fully fix this because some structure may always mislead the guessing algorithm.
Bridge graph is misaligned. If the fairness-aware bipartite graph connects dissimilar source and target nodes, it teaches the model wrong alignment, reducing generalization.
Task and demographics are truly entangled. In real data, the task and a sensitive attribute may have genuine overlap (e.g., a job role may legitimately correlate with education level). Forcing complete separation can hurt accuracy.
Done right. Pseudo-labels are high-confidence — for example, if the target graph has structural homophily (friends tend to have the same gender), the method can group similar nodes reliably. The bridge is learned jointly with encoders so it adapts as the encoders separate task and demographic signals. The method is tuned to allow some task-relevant correlation (e.g., if education truly predicts the job) while blocking pure demographic shortcuts (e.g., gender alone predicting the job), because the loss function penalizes only the crosstalk between demographic and task encoders: if a feature helps both the task and accidentally encodes demographics, the penalty is small, but if it helps only demographics, the penalty is large.
What a runnable demo should prove

What a runnable demo should prove

Build a small citation graph (papers and authors, with edges for authorship). Train CELL on one conference as the source (with known author genders) to predict whether a paper will be cited frequently. Test on papers from a different time period or venue (the target), without gender labels. Show that: (1) naive transfer predicts citation unfairly (predicts lower citations for papers by women even at the same quality); (2) CELL predicts citations more fairly (gender gap shrinks), while keeping accuracy high.

fairness_gap = abs(accuracy_for_group_A - accuracy_for_group_B)

The demo must make it clear that CELL sacrifices little accuracy to achieve fairness, and that the gap between groups is small even though the target graph has no gender labels.
