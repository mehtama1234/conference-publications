Representation-as-a-Judge: Small Models Judge via Hidden States

Small language models can judge quality by examining their own hidden thinking, not by writing answers.

Paper explainersAll themesInterpretability

Evaluating whether an answer is good is currently done by asking huge language models to write explanations. But this is slow, costs a lot, and the answers depend on how you phrase the question. This paper discovers that small language models already contain the answer hiding inside their thinking — even though these small models are bad at writing. The method is called Representation-as-a-Judge: instead of asking the model to speak, peek inside and read the answer directly.

Zero assumption version

The cost of asking a judge to speak

Right now, to rate if an answer is good, we use a huge language model and ask it to write a judgment. This is slow: the model has to produce many tokens. It is expensive: we run a massive model once per judgment. It is fragile: changing the wording of the question shifts the judgment, so results depend on prompt engineering tricks.

A beginner might say: use a smaller model to judge instead. But smaller models are bad at writing good explanations, so the field assumed they are bad judges. The model's weakness at generation seemed to prove its weakness at understanding.

The assumption. Small models are too weak to judge because they are weak at writing.

The algorithm as a flow

What it actually does

Take the small model's hidden layer

When the small model reads the answer, it builds an internal thought (a list of numbers).

Extract that thought

Grab the numbers from the last hidden layer before the model would write output.

Train a tiny classifier on labeled examples

On examples where we know the right judgment, learn a simple rule: how do the numbers map to scores?

Apply the classifier to new answers

For a new answer, read the hidden numbers and apply the rule to get a judgment score.

No generation needed

The entire evaluation is arithmetic; the model never writes anything.

What the paper changes

What changes: reading internal thought instead of output

The paper changes what part of the model we use to render a judgment. Instead of asking the model to generate text (which it feeds to a prompt-based evaluator), the method reads the numbers inside the model's thinking layers — the hidden state.

the object it moves  =  hidden states as the judgment source
The hidden quantity

The hidden quantity: evaluative signal in hidden states

measured quantity  =  evaluative signal strength

The paper measures how much information about answer quality is already present in a small model's hidden thinking layers, before the model writes anything. This is called the evaluative signal: the degree to which the internal numbers encode a judgment.

The paper estimates this by training a simple linear classifier (like a one-layer neural network) on the hidden states, using labeled examples where we know the correct judgment. If the classifier learns quickly and predicts well, the hidden states contain strong evaluative signal. If it struggles, the signal is weak.

Why it works

Why reading hidden states works as a judge

A language model is trained to predict the next token in vast amounts of text. During this training, the model learns patterns: which kinds of answers tend to appear after correct reasoning, which after mistakes, which after confused input. These patterns get baked into the hidden layers as numerical patterns.

When evaluating requires only understanding (not writing), the model can complete that task using far less capacity. Judgment is a classification task — does this answer fit the pattern of a good answer or a bad one? — while generation is an open-ended task that demands full model power. The hidden states already encode the classification. A small model may lack the capacity to write a coherent explanation, but it has just enough to recognize quality.

By probing the hidden states with a simple linear classifier, we extract that recognition. The classifier is trained on labeled examples and learns to map the patterns in the hidden numbers to judgment scores. At test time, new answers flow through the small model, their hidden patterns are extracted, and the classifier predicts a score — all without the model writing a word.

Math after the picture

The scoring equation

First in words:

judgment_score equals learned_weights times the_hidden_state plus a_baseline

Then the compact form:

score = w · h + b

Every symbol:

scorethe predicted evaluation score for the answer
wthe learned weights (one per hidden dimension)
hthe hidden state (the model's internal thought)
bthe baseline (a constant shift)
A tiny worked example
Suppose the hidden state h has 3 dimensions: [2.1, -0.5, 1.8]
Learned weights w are [1.0, -2.0, 0.5] (trained on examples)
Baseline b is 0.3
score = (1.0)(2.1) + (-2.0)(-0.5) + (0.5)(1.8) + 0.3 = 2.1 + 1.0 + 0.9 + 0.3 = 4.3
This score might mean 4.3/5.0 quality. Another answer with hidden state [-1.0, 0.6, -0.3] would score (1.0)(-1.0) + (-2.0)(0.6) + (0.5)(-0.3) + 0.3 = -1.0 - 1.2 - 0.15 + 0.3 = -2.05 (a poor answer).

The weights capture which parts of the hidden thinking predict high or low quality; the classifier learns this mapping from labeled data.

What can go wrong

What can go wrong

New kind of answer, no labeled training data. The probing classifier is trained on one benchmark (say, math problems). If you apply it to a different domain (essays, code review) without retraining, it will fail because the hidden patterns differ across domains.
Hidden states are model-specific. A classifier trained to read the hidden states of one small model (say, Llama-3.2-1B) will not work on a different small model (say, Phi-2). Each model encodes quality differently in its internal numbers.
Small model misses nuanced flaws. A small model may lack sufficient capacity to notice subtle mistakes (e.g., a solution that looks correct on paper but would fail in practice). Its hidden states may not encode such fine judgments.
Done right. Collect labeled evaluation examples in your target domain, train the probing classifier on them, and apply it only to answers from the same model family. The trade-off is clear: less generality, but massive speed and cost gains.
What a runnable demo should prove

What a runnable demo should prove

Build a toy evaluator: take a small language model, sample 100 answers to simple math problems, have humans label each as correct or incorrect (binary judgment, 5 minutes total). Train a linear classifier on 80 examples to map hidden states to correctness (use the model's last layer hidden state). Run the classifier on the held-out 20 examples. Measure accuracy: what fraction do you get right? Plot the hidden-state scores of correct versus incorrect answers; they should cluster apart. This proves the evaluative signal exists.

accuracy = correct_predictions / total_examples

If the classifier reaches 80+ percent accuracy on held-out examples, the hidden states encode real judgment, and prompting the model would never work as well.
