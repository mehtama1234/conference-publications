Scaling Behavior of Discrete Diffusion Language Models

Map how discrete diffusion language models scale under different corruption rules, so one can choose the right balance between data, compute, and model size.

Paper explainersAll themesOther

Language-model pretraining now lives under scaling laws: when data, compute, or model size change, different architectures respond differently. Discrete diffusion language models were proposed as an alternative to left-to-right generation, but earlier work suggested they need more data and more compute to catch up. This paper asks a more careful question: how much of that picture depends on the corruption rule used during training? The authors study a path between masked corruption and uniform corruption while controlling batch size and learning rate closely. They find that the scaling story changes with the corruption rule. Uniform corruption needs larger models but less data for compute-efficient training, which matters in data-constrained settings because the right corruption rule can change which resource is the true bottleneck.

Zero assumption version

Why scaling claims for discrete diffusion were incomplete

When people compare language-model families, they usually ask how loss falls as compute, data, and model size increase. Earlier comparisons suggested that discrete diffusion models lag behind left-to-right models.

But those comparisons mixed together several design choices, especially the corruption rule used during training. In discrete diffusion, training repeatedly corrupts text and asks the model to recover the clean text. Masked corruption and uniform corruption hide information in different ways, so they may produce different scaling behavior. Without separating those cases, one can draw the wrong conclusion about whether the architecture itself is weak or whether one corruption rule is simply a poor fit for the data and compute regime.

The paper's move. Study scaling by corruption rule instead of treating all discrete diffusion setups as one family, because the corruption rule changes the data and compute trade-off.

The hidden quantity

The hidden quantity

measured quantity  =  how much useful signal survives each corruption level for a fixed compute budget

The hidden quantity is not just final loss. It is how much recoverable information remains after corruption once one fixes the compute budget and the model size.

That quantity explains why two corruption rules can scale differently. If a corruption rule erases information in a way that larger models can still use well, then adding model size helps more because the extra capacity can recover more from the surviving clues. If it demands more observed text to learn the same recovery task, then data becomes the limiting resource. The paper's signal-to-noise view makes this trade-off easier to describe because the corruption rule directly controls how much useful signal survives.

Why it works

Why the corruption rule changes scaling behavior

A discrete diffusion model trains on corrupted text and learns to reverse that corruption. The corruption rule decides what the model sees and what it must reconstruct. That directly changes sample efficiency because some rules preserve more structure per example than others.

Masked corruption hides selected positions while leaving the rest untouched. Uniform corruption replaces content more broadly, which can demand a stronger model but may use each unit of compute with less waste when data are scarce because the model sees a broader reconstruction challenge per example.

The paper's careful tuning matters because poor batch-size or learning-rate choices can masquerade as architectural scaling limits. By controlling those settings, the authors show that much of the earlier pessimism about discrete diffusion came from mixing regimes. The reformulation in terms of signal-to-noise ratio also matters because it puts discrete diffusion closer to the language used in continuous diffusion theory, which makes the scaling picture easier to reason about and implement.

Math after the picture

Signal-to-noise view

First in words:

Describe each corruption level by how much clean signal remains relative to corruption strength, then compare loss as that ratio changes across model sizes and compute budgets.

Then the compact form:

training_difficulty = corruption_strength / remaining_signal

Every symbol:

corruption_strengthhow aggressively the training rule destroys information in the clean text
remaining_signalhow much recoverable information is still visible after corruption
training_difficultya summary of how hard the recovery problem is at that corruption level
A tiny worked example
Suppose one corruption rule leaves 40 units of recoverable signal while adding 20 units of corruption strength.
Its difficulty score is 20 / 40 = 0.5.
A harsher rule leaves 20 units of recoverable signal while adding the same 20 units of corruption strength.
Its difficulty score is 20 / 20 = 1.0.
The second rule is harder because each unit of remaining signal must carry more of the reconstruction burden.

The paper's full objective is richer than this summary, but the signal-to-noise view captures why different corruption rules produce different scaling curves.

What can go wrong

What can go wrong

Scaling conclusions can be confounded by poor tuning. If batch size or learning rate is mismatched across runs, one corruption rule can look worse simply because training was not equally optimized.
One corruption rule may dominate only in one regime. A rule that is strong when data are scarce may lose its edge when data are abundant, because the resource bottleneck has changed.
Very large models may be required. Uniform corruption can need a larger model before its efficiency benefit appears, so small-scale studies may underestimate it because the regime shift has not arrived yet.
Done right. With careful tuning and the right resource regime, discrete diffusion can scale competitively because the corruption rule can be matched to the available data and compute.
