Weasel: Out-of-Domain Generalization for Web Agents via Importance-Diversity Data Selection

Pick a small training subset that covers important and varied web actions, then trim page state around the true target so offline web-agent training becomes cheaper and transfers better.

Paper explainersAll themesAgents & Tool Use

Offline web-agent training often wastes compute on repeated trajectories, repeated websites, and large page-state dumps that do not help the next action because they repeat the same signal or add irrelevant page detail. Weasel attacks that waste directly. It selects a fixed-budget subset of steps that are both important and varied, then prunes page state around the action target so training focuses on what matters for the decision.

Why more web data is not always better

Web-agent datasets can be huge, but much of that size comes from near-duplicate steps and very long page-state descriptions. Training on everything is expensive, and the extra examples may not teach much because the agent sees the same patterns again and again.

The problem is worse out of domain. If training data is concentrated on a few sites or a few interaction styles, the agent may memorize those habits and then fail on new sites because it never learned a broader set of action patterns.

The paper's move in one sentence. Spend the training budget on steps that are both important and diverse, and trim each page state around the true action target.

The algorithm as a flow

What it actually does

Score step importance

Estimate which trajectory steps contain strong signal for the correct next action.

Measure diversity

Compare steps across sites, states, and interaction patterns so that the chosen subset is not full of near-duplicates.

Select a fixed-budget subset

Use a greedy method to keep the examples with the best combined importance and diversity score.

Prune page state near the target action

Keep content around the true target so that the model sees the most relevant part of the page.

Match rationale style to the training model

Replace expert traces with model-style rationales where needed so that the training text better matches how the model reasons during use.

What the paper changes

What the paper changes

The paper changes which training examples the agent sees and how much page state is attached to each example. That matters because the training budget is fixed, so each retained example should carry more useful information.

The hidden quantity

The hidden quantity

measured quantity  =  how much useful coverage each chosen step adds

The key hidden quantity is the marginal value of one more training step. A step is useful if it teaches an important decision that the current subset does not already cover. That value is hidden because you only discover it after comparing the step against many others.

Weasel estimates that hidden value through importance and diversity. A step should be kept when it teaches a strong decision and adds a new pattern, because either factor alone is not enough for good transfer.

Why it works

Why this works: spend compute on broader signal, not repeated clutter

If you train on many duplicated web steps, the model spends a large share of its budget rehearsing the same decision. That can still lower training loss, but it does not broaden what the agent knows how to do. A fixed-size subset that covers more decision types is more useful because the agent sees a wider range of actions per unit of compute.

The page-state pruning rule helps for a separate reason because web page descriptions can be long and much of that text is unrelated to the next action. By keeping content near the true target, Weasel lowers the amount of irrelevant text the model must read, so training is cheaper and the action signal is less diluted.

Math after the picture

Select the subset with the best combined value

First in words:

One compact summary is to score a chosen subset by adding the importance of each kept step and the diversity gained from keeping different kinds of steps together.

Then the compact form:

score(S) = sum_i importance(i) + beta * diversity(S)

Every symbol:

score(S)overall value of the chosen training subset S
sum_i importance(i)total importance of kept steps
diversity(S)how broadly the subset covers different sites, states, and action patterns
betaweight on the diversity part of the score
A tiny worked example
Subset A keeps three highly repeated checkout steps with total importance 9 and diversity 1.
Subset B keeps one checkout step, one search step, and one form step with total importance 8 and diversity 4.
If beta = 1, score(A) = 10 and score(B) = 12.
The method chooses Subset B because it gives nearly the same importance and much broader coverage.

The paper uses a more detailed objective and a greedy solver, but this equation captures the main tradeoff.

What can go wrong

What can go wrong

Importance estimates can be wrong. If the scoring rule underestimates a subtle but important step, the subset may lose a case that matters for later transfer.
Too much pruning can hide context. Keeping only the target neighborhood may remove page cues that explain why that target is correct, so the agent may learn a brittle local rule.
Style matching can narrow the explanation range. Replacing expert rationales with model-style rationales may fit the current model better because the training text matches the model's usual style, but it can also reduce exposure to richer human explanations.
Done right. The method is useful because it treats data selection as a core part of web-agent training rather than an afterthought.
What a runnable demo should prove

What a runnable demo should prove

Take a medium-size offline web dataset and train two agents with the same compute budget. The first uses the full set in chronological order. The second uses Weasel's fixed-budget subset plus target-centered page-state pruning. Evaluate both on new sites and on sites seen during training.

The demo should show that the Weasel agent transfers better to new sites because its training set covers more varied useful patterns. Report training time and average page-state length so that the cost savings are visible too.

transfer_gain = score_new_sites_weasel - score_new_sites_full ; time_drop = train_time_full - train_time_weasel

The core claim is that a smaller sharper dataset can beat a larger noisier one.
