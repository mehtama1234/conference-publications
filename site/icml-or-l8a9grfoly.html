Dynamic Fractal Mamba

A model that uses the same operator recursively across different time scales, so it works on long sequences it never saw during training.

Paper explainersAll themesTime Series & Sequential

Most sequence models work at one fixed speed. A model trained on daily data breaks on monthly data; one trained on small images fails on large ones. Dynamic Fractal Mamba solves this by stacking the same simple operator many times, each time moving twice as fast. This lets the model learn scale-consistent rules that work whether the input is short or long, dense or sparse.

Zero assumption version

Why models break at different scales

Imagine a weather model trained on daily temperatures. It learns patterns like 'temperature drops 3 degrees at night, rises 5 degrees by noon'. If you ask it to predict a month ahead, it cannot just repeat those daily rules 30 times — the patterns at the month scale are totally different (seasons, trends, long-term climate patterns).

Standard models encode patterns at ONE scale only. A transformer (a common sequence model) has a fixed window size — it can only see back so far. Scale up the problem, and the model runs out of memory or accuracy. Retrain it on longer sequences, and you lose what it learned about short-term patterns.

The naive fix fails. Just add more layers or a bigger window. But this blows up memory and computational cost without teaching the model how patterns truly repeat across different scales.

The algorithm as a flow

What it actually does

Single operator

Start with one state-space operator that processes a sequence.

Recursion

Apply that same operator multiple times, each time doubling the time step.

Coarse-graining

Between layers, compress the representation to match the slower scale.

Consistency losses

Teach the model that patterns at different scales must agree on the same events.

At test time

Run it on any scale without retraining because the operator is scale-independent.

What the paper changes

What the paper changes

Standard models bake in scale-specific parameters: different weights for hourly patterns, daily patterns, yearly patterns. Each scale is its own isolated module.

Dynamic Fractal Mamba changes the object: instead of separate weights for each scale, it uses ONE set of weights recursively, but at each layer the time step (how far the model looks per step) is exponentially larger.

the object it moves  =  parameter sharing across scales
The hidden quantity

The hidden quantity: scale-consistent representation

measured quantity  =  cross-scale consistency error

The paper measures one key quantity: how much do the learned patterns agree when the model looks at the same event at different time steps? For example, if a weather spike happens, does the daily-resolution model and the weekly-resolution model both notice it as the same kind of event?

This is not directly optimized during training, but the paper teaches it by adding an auxiliary loss: at each recursion level, the model must reconstruct what the data looks like at a coarser scale, and it must agree with what the next level learned. High consistency means the operator truly understands the underlying dynamics, not just memorizing one specific time step.

Why it works

Why recursive parameter sharing works

The core insight is renormalization: nature works the same way at different scales. A coastline looks jagged whether you zoom in or zoom out. A forest looks like a tree, and a tree looks like a forest of branches. The paper exploits this: if the operator is scale-invariant (which it becomes by exponentially scaling the time step), then applying it multiple times to progressively coarser data teaches it rules that hold at all scales.

Here is the causal chain: (1) You feed in the fine-grained sequence. (2) The operator processes it with fast time steps (seeing many small changes). (3) Then you coarse-grain the result (average out the fine details). (4) Feed the coarse version back into the SAME operator with slower time steps. (5) The operator must now predict the coarse features from the coarse data. (6) Since the operator is shared, it learned to extract patterns that persist across scales. (7) At inference, you can run this on any scale because the dynamics are consistent: the operator does not know whether it is seeing daily or yearly data — it just sees 'here is a sequence, find the underlying structure'.

Math after the picture

Exponential time-step scaling

First in words:

at layer k, the time step is scaled by 2 to the power k, and the state-space operator stays the same, but the hidden state is coarse-grained between layers

Then the compact form:

h_{k+1} = coarse_grain( operator(h_k, delta_t * 2^k) )

Every symbol:

h_khidden state at recursion level k
delta_tbase time step (e.g., 1 hour)
2^ktime-step multiplier at level k (doubles each level)
operator(h,dt)shared state-space model, with time step dt
coarse_grain(h)learned module that summarizes h for the next slower scale
A tiny worked example
Level 0: Base time step = 1 hour. Process 168 hourly points with the operator. Output: 168 hidden states.
Coarse-grain by 24: Compress to 7 daily summaries.
Level 1: Time step = 2 hours (2^1 * 1). Process those 7 daily points with the SAME operator weights. Output: 7 daily hidden states.
Check: the daily hidden states should predict the daily data just as well as the hourly hidden states predicted the hourly data. If they do, the dynamics are consistent across scales.
Level 2: Time step = 4 hours (2^2 * 1). Coarse-grain again to 1 weekly point. Run the operator. It now 'sees' a week as a single sequence.
The operator never changed; only the time step and input granularity changed. This forces it to learn scale-independent rules.

The penalty for time stepping is not explicit here; the real paper uses auxiliary reconstruction and consistency losses to ensure agreement between levels.

What can go wrong

Non-uniform time scales. If patterns are not actually scale-invariant (e.g., a market crash at 1-minute scales does not predict crashes at 1-year scales), exponential scaling fails. The model assumes nature is fractal; if it is not, this assumption breaks.
Coarse-graining must be learned. If the learned coarse-grain module loses important signal, the consistency check fails and the model bottlenecks. A fixed aggregation (e.g., simple averaging) is faster but may discard essential information because averaging looks at all values equally — it cannot tell which details matter for the next scale and which are noise.
Recursion depth limit. You cannot recursively scale forever without running out of hidden state or oversimplifying. At some depth, the operator receives almost no signal and cannot learn.
When done right. Start with clear scale-invariant problems (long time-series forecasting, multi-resolution images, hierarchical data). Use learned coarse-graining. Train with explicit cross-scale consistency objectives. The model then naturally learns rules that generalize to unseen scales.
What a runnable demo should prove

What a runnable demo should prove

Build a simple state-space model (a few number-list operations that update a hidden state over time). Train it on a fixed-size sequence (e.g., 100 time steps of a synthetic periodic signal with multiple frequencies). Then, without retraining, run the model with the recursive parameter-sharing trick: apply the same model twice, but the second time with half-resolution input and doubled time steps. Measure whether the model's predictions at the two different resolutions agree on the same large-scale events.

scale_generalization = ( correlation between coarse-grained predictions at scale A and zero-shot predictions at scale 2A )

The demo proves that training on one scale forced the model to learn dynamics that hold at other scales, without ever seeing those scales during training. The higher the correlation, the more the model truly learned scale-consistent rules rather than scale-specific patterns.
