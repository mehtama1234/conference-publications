ECHO: Seq2Seq Learning from Brain Signals

ECHO teaches a decoder to read both brain signals and example problems in the same sequence, so it learns each new task by seeing worked examples instead of retraining.

Paper explainersAll themesAI for Science

EEG (the electrical signals your brain makes) has many medical uses. Researchers built large models that learn good feature detectors from millions of hours of unlabeled brain data. But these models have a weak decoder the part that makes the final decision and must retrain on each new task. ECHO flips the setup: it builds a strong decoder that reads the brain signal AND a set of example labeled problems as one unified sequence, learning to adapt on the fly.

Zero assumption version

The Encoder-Decoder Mismatch

Researchers trained large EEG models on unlabeled brain data, building strong encoders that turn raw electrical signals into useful feature lists. But they paired these with simple decoders, starving the model of the detailed patterns the encoder learned.

When a new medical task arrived (detect sleep stage, detect seizures, identify concentration levels), the model had to retrain its decoder from scratch. This meant collecting labeled examples, waiting days for training, and losing what it learned about other tasks.

The core problem. Strong encoder, weak decoder, and no way to teach the decoder new tasks without retraining.

The algorithm as a flow

What it actually does

Encode all samples

Convert the target brain signal and all example signals into token sequences (lists of numbers).

Concatenate into context

Glue the example tokens and target tokens together into one long stream.

Decoder reads in order

The decoder processes the stream step-by-step, seeing examples first, then predicting the target label.

Connections between parts

The model has cross-connections (where the decoder compares the examples to the target signal) that let it see which example is most like the target.

Learn without retraining

Only decoder weights shift; encoder is frozen. No new training loop needed for the next task.

What the paper changes

What the Paper Changes

ECHO swaps the decoder from a simple classifier to a full sequence-to-sequence transformer. The decoder is now large enough to learn from context (examples at test time, when the model answers a new question) instead of only at training time.

the object it moves  =  Decoder architecture and how it predicts at test time
The hidden quantity

The Hidden Quantity: Task Context Sensitivity

measured quantity  =  How much the decoder responds to the example set

Every decoder has a tuning knob: how much it listens to the examples versus defaulting to what it learned during training. This is called context sensitivity. ECHO measures this by training the model to predict which label comes next given the example and target signal, checking how often it picks the right label when examples change.

The paper infers context sensitivity by observing: in multi-task settings, when ECHO sees five labeled examples of sleep stages, does it correctly classify the next sleep stage? If yes, it has learned to be sensitive to task context. The paper trains for this explicitly during the contextual phase, exposing the decoder to 0 to 12 examples per step so it learns to adapt flexibly.

Why it works

Why Seq2Seq Decoder Learns from Examples

A sequence-to-sequence decoder is a stack of transformer layers that predict one token at a time, looking at all previous tokens. When you feed it examples first, then the target signal, the decoder's cross-attention (the part of the model that compares one thing to another) naturally looks back at the examples to find patterns (what does label zero look like? what does label one look like?). This is the same attention mechanism that lets a language model answer a question after reading a passage. The decoder learns, during training, to use this capability: when it sees a new task structure in the examples, it shifts its internal computation (without changing the numbers stored as weights) to fit that structure.

The encoder stays frozen because you already trained it on millions of unlabeled samples. The decoder, now large and carefully designed, learns during its two-phase training to first stabilize on a warm-up task, then to adjust based on context. During test time (when the model answers a new question), no learning happens and no weights shift. Instead, the transformer's internal calculations change to fit the examples, just as a language model's computation changes when you give it a new topic.

The Training Objective

First in words:

For each predicted token, the loss is the cross-entropy between the model's predicted probability and the true label. During contextual training, the number of example samples varies from 0 to 12 per step, exposing the model to diverse context lengths.

Then the compact form:

L = -sum_i log(P(y_i | X_target, X_support_1, ..., X_support_S))

Every symbol:

Ltotal training loss
y_ithe correct label for example i
P(...)the decoder's predicted probability of that label
X_targetthe brain signal to classify
X_support_sthe s-th example brain signal and its label
Sthe number of support examples (varies 0 to 12)
A tiny worked example
Suppose the decoder sees 4 example sleep stages (Wake, REM, N2, N3) then predicts the target.
If it assigns 0.1 to Wake, 0.05 to REM, 0.7 to N2, 0.15 to N3, and the true label is N2:
log(0.7) = -0.357, so the loss for this one prediction is 0.357.
Train on 40 steps, 40 targets, each with 4 examples: total loss sums up, optimizer nudges the decoder to raise probabilities on correct labels.
After training with varied support counts (0, 5, 10, 12 examples), the decoder learns to use examples when present and fall back to what it already knows when examples are sparse.

The key is varying support set size during training so the decoder learns to adapt to any context, not memorize a fixed number of examples.

What can go wrong

What can go wrong

Example-decoder mismatch. If the support examples come from a very different subject or electrode configuration, the decoder may misinterpret them and predict poorly. The paper addresses this by learning a unified channel mapping across different electrode systems.
Too few examples. If you give the decoder zero or one example, it has almost no signal about task structure. ECHO trains on variable counts (0 to 12) to learn graceful degradation, but very sparse contexts remain challenging.
Training instability. Training both encoder and decoder jointly is unstable. ECHO solves this by freezing the encoder in the warm-up phase, training the decoder only, then unfreezing and joint-training in the contextual phase.
Done right. ECHO trains in two phases: first stabilize the whole model on a single task with a fixed set of examples, then expose the decoder to varying numbers of examples (0 to 12) to learn flexible context adaptation.
What a runnable demo should prove

What a runnable demo should prove

Build a simple seq2seq decoder on a small EEG dataset with multiple tasks (e.g., sleep stages, seizure detection, attention monitoring). Pretrain an encoder on unlabeled data. Then train the decoder in two phases: warm-up with a fixed support set size, then contextual training with varied support counts. Finally, test on a new task by showing the decoder five labeled examples and measuring how often it predicts the target correctly.

Adaptation accuracy = (correct predictions on new task with examples) / (total predictions on new task)

The demo must show: without retraining the encoder, the decoder adapts to a new task when given examples, and performs worse when examples are removed. This proves the decoder learned to read context, not memorize task structure.
