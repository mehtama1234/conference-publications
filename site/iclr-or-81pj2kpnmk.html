DreamPhase: Offline Imagination and Uncertainty-Guided Planning for LLM Agents

Instead of asking the language model to decide each step in real time, train it to imagine ahead in a fake world, pick the safest path, then explain that choice.

Paper explainersAll themesAgents & Tool Use

LLM agents often fail at multi-step tasks because they make decisions one step at a time without seeing the consequences. DreamPhase solves this by building a learned fake world inside the agent, letting it imagine possible futures before committing to real actions. The result: agents need far fewer real interactions and make far fewer catastrophic mistakes.

Zero assumption version

Why LLMs stumble at multi-step tasks

A language model sits in your web browser reading the screen. You ask it to book a flight. It has never seen a booking site before. It reads: 'Depart: [search box]'. It types 'New York'. It reads the next screen. It types '2025-01-15'. Over and over, one blind step at a time.

The trap: the model was trained on text that ended months ago. It has no clock. It has never learned what happens if you click the wrong button. So it makes brittle guesses, each one a coin flip. Book a flight means 40 guesses in a row. With 1-in-2 odds per guess, you fail almost every time. Even worse, some guesses are irreversible: click 'Confirm payment' by accident and you wasted money.

The naive fix: search forward. Before each action, ask the model to list all possible next steps, score them, and pick the best. But that means calling the model 40 times per step, and the model still has no real glimpse of what clicking does. Expensive and still blind.

The core problem in one sentence. Language models make single-step guesses at multi-step tasks, so they fail often and need 40+ real trials to succeed.

The algorithm as a flow

What it actually does

Step 1: Read the current state

Agent sees the screen it must act on.

Step 2: Imagine forward in fake space

World model predicts where each possible action leads, one step at a time.

Step 3: Score each imagined path by safety

Measure how certain and reversible each outcome is; reject high-risk branches.

Step 4: Distill the winner into plain words

Convert the safest imagined path into a one-sentence explanation.

Step 5: Condition the policy on the reflection

Feed explanation back to the model so it learns the reasoned choice.

What the paper changes

What the method changes

The paper rewires how agents decide: instead of calling the language model to pick each action in isolation, it adds an imagined world that scouts ahead. The model still generates the final action, but now it has a reasoned suggestion to condition on.

the object it moves  =  agent decision pipeline
The hidden quantity

The uncertainty measure

measured quantity  =  path reversibility and prediction confidence

DreamPhase measures two things: how confident the world model is in its predictions, and whether an action can be undone. A confident path to a reversible outcome is safe. An action that locks you in (like confirming payment) scores high-risk even if the model predicts it confidently.

The paper estimates reversibility from the imagined state trajectory: if the model predicts the agent can return to an earlier state with a short sequence, the action is reversible. Confidence is measured by comparing multiple model predictions—if they agree, the prediction is solid; if they disagree, it is uncertain.

Why it works

How offline imagination prevents failures

Here is how it works: train a model to predict the consequences of actions in dense latent space (a learned internal memory format, just a list of numbers). That model learns abstract patterns it never saw explicitly. Patterns like 'clicking the payment button is hard to undo' or 'this page layout predicts a search result'.

DreamPhase exploits this by doing all the risky exploration in imagination first. For each possible next action, the world model predicts what state it leads to, because the model has learned a dense encoding of 'what happens when you click this button,' encoded as a list of numbers it can compute forward without touching the real web page. DreamPhase then branches: from each predicted state, it imagines the action after that, and so on, building a tree of possible futures. Because this happens in the learned memory space, not in the real world, mistakes are free.

Once the tree is built, DreamPhase filters by safety: trajectories with irreversible actions or low-confidence predictions get cut. The remaining paths are ranked by predicted success. The best one is distilled into a short natural-language explanation, such as 'Enter your departure city in the search box'. This explanation is fed back to the policy, steering it toward the same choice without retraining or modifying the language model's weights.

Math after the picture

The scoring equation

First in words:

safety score equals confidence times reversibility, penalizing irreversible outcomes and uncertain predictions

Then the compact form:

S(branch) = conf(branch) * (1 - cost_irreversible) * reachability_earlier_state

Every symbol:

S(branch)the safety score for one imagined future path
conf(branch)how certain the world model is about predictions along this path, from 0 to 1
cost_irreversiblepenalty for actions with no undo, such as payment confirmation; 0 to 1
reachability_earlier_statewhether the agent can return to a known safe state; 1 if yes, 0 if trapped
A tiny worked example
Path A (enter departure city): confidence 0.95, reversible (can clear box), cost 0 -> S = 0.95 * 1.0 * 1.0 = 0.95
Path B (confirm payment early): confidence 0.90, irreversible (no undo), cost 1 -> S = 0.90 * 0.0 * 1.0 = 0.0
Path C (click unknown button): confidence 0.50, reversible, cost 0 -> S = 0.50 * 1.0 * 1.0 = 0.50
Ranking: Path A (0.95) is chosen; B (0.0) is filtered out early; C (0.50) is a fallback.

Confidence times reversibility times reachability: high on safe paths, zero on locks, low on guesses.

What can go wrong

What can go wrong

World model encounters unfamiliar layouts. If the imagined world has never seen a site like the target, its predictions are guesses. The safety filter may pass bad paths because the model is confidently wrong.
Reversibility is hard to measure. Some actions look reversible (clearing a text box) but have hidden side effects (search triggers). The model may misclassify the cost.
Distilled reflection can mislead. The natural-language summary of the imagined path may not fully convey the reasoning. The policy might overfit to the summary text, bypassing the safety filtering.
Done right: ensemble predictions + careful reversibility definition. Use multiple world models to detect disagreement (a sign of uncertainty). Define reversibility mechanically (detect state reachability with a learned classifier) rather than heuristically.
What a runnable demo should prove

What a runnable demo should prove

Build a small multi-step task: a web form with 3-5 fields and a submit button. The agent must fill in all fields and submit. Train or load a lightweight world model (distilled from a larger one or pretrained). Implement the safety gate: mark 'submit' as irreversible and measure prediction confidence from head-to-head forward passes. Run the agent 10 times with imagination off (baseline: random guesses) and 10 times with DreamPhase on. Log success rate, API calls, and the number of 'submit' clicks before all fields are ready.

success = (all fields filled AND submit clicked once) / (total episodes); api_calls = calls to language model per episode; premature_submits = submit actions before completion

The demo succeeds if DreamPhase reduces API calls by 3x and premature submits to near zero while keeping success above 80%, compared to baseline random-search.
