TEN-DM: Topology-Enhanced Diffusion for Event Prediction

The paper predicts when and where events will happen next by treating space-time as a connected graph and learning features that capture both the topology and the periodic rhythms.

Paper explainersAll themesTime Series & Sequential

When events like earthquakes, traffic accidents, or disease outbreaks happen, they follow patterns in space and time: they cluster in certain places, repeat on certain schedules, and influence each other. This paper builds a model that learns these spatial-temporal dependencies together by first drawing a graph of how nearby events connect to each other, then feeding that connectivity into a diffusion model (a step-by-step learning process) that learns what features of the graph predict the next event.

Zero assumption version

Old methods treat space and time like strangers

Many real events — earthquakes, crimes, hospital admissions, social-media posts — have a spatial location and a timestamp. The task is to look at the history and predict where and when the next one happens. The intuition is that events are not random: they cluster in certain places, repeat on schedules (rush hour, seasonal flu), and influence each other (one crime signals disorder, increasing risk of another nearby).

Traditional approaches use a kernel: a mathematical weight function that says how much an old event affects the prediction at a new location and time. This works for simple patterns but fails on complex ones because the kernel has a fixed shape — it does not learn from data what the true dependencies actually are. Modern deep learning methods use neural networks to learn flexible patterns, but most treat space and time as separate channels: they process the timestamp separately from the coordinates, missing the fact that space and time are intertwined.

A beginner would train two independent neural networks — one for temporal patterns, one for spatial — and combine their outputs. This breaks because a traffic crash does not just repeat on a schedule independent of where the last crash was; the next one is more likely nearby and at a predictable time relative to the previous one. The networks never learn that space-time coupling.

In one sentence. The paper jointly models spatial-temporal dependencies by building a graph of event connections and using a diffusion model to learn patterns from that graph structure.

The algorithm as a flow

What it actually does

Step 1: Collect event history

Read in all past events with their spatial coordinates and times.

Step 2: Build a space-time connectivity graph

Link each event to nearby events in space and time. Strength of link reflects proximity.

Step 3: Learn features from the graph

Feed the graph structure to a neural network that learns what shapes matter for prediction.

Step 4: Add temporal patterns

Detect and encode periodic repeats (daily, weekly cycles) in the query mechanism.

Step 5: Use diffusion to predict

Start with noise and gradually denoise to a predicted next event location-time pair.

What the paper changes

What the paper changes: the representation of space and time

Most models treat events as a flat list or process spatial and temporal features through separate neural paths that never talk to each other. TEN-DM changes the object: it represents events as a graph structure where edges encode spatial and temporal proximity. Every edge between two events carries information about how close they are in both space and time together.

the object it moves  =  graph-based event relationships
The hidden quantity

The hidden quantity: topological importance

measured quantity  =  topological importance of each event

Traditional models never explicitly measure which historical events matter most to predicting the future. TEN-DM introduces topological importance: a score assigned to each past event based on its position in the space-time graph. An event is topologically important if it is tightly connected to many other recent events in both space and time, signaling that it is at the center of an active cluster.

The paper learns this quantity during training: the diffusion model (the step-by-step noise-removal process) implicitly assigns higher weight to events that sit at dense junctions in the graph, because those events' features reduce the prediction noise the most. You can measure it by looking at the graph gradients: events whose features are most altered during learning had high topological importance.

Why it works

Why it works: learning patterns from graph structure

The mechanism has three parts working together. First, building the graph itself solves a core problem: it forces the model to recognize that space and time are not independent. When you draw an edge between two events only if they are close in both space and time, you are telling the network: these two are connected, learn from one to predict the other. A model processing space and time separately never sees this cue.

Second, the diffusion process (adding noise and learning to remove it step by step) is the engine for learning from the graph. In each training step, the model takes event features plus the graph structure and predicts what noise was added. To do this, it must learn which graph patterns — dense clusters, periodic chains, bridges between regions — are predictive. Because the noise is random, the model cannot memorize; it must extract structural rules. The learned rules can be arbitrarily complex, whereas a fixed kernel has a fixed shape that cannot adapt to the data.

Third, the temporal query mechanism detects periodic patterns: if you observe that crashes happen every Wednesday afternoon in a particular neighborhood, that repeating signal gets amplified. The model learns to trust periodic patterns when they exist, without forcing them when they do not. All three layers together — graph structure, diffusion learning, periodic awareness — capture the full complexity of space-time dependencies that independent neural paths would miss.

The score that predicts the next event

First in words:

The prediction score for a candidate event is the sum of: the topology-weighted features of nearby past events, plus a learned periodic bonus if the candidate time matches a strong cyclic pattern.

Then the compact form:

score(x_new, t_new) = sum_i [topology_i * feature_i * spatial_similarity(x_new, x_i)] + periodic_boost(t_new)

Every symbol:

x_newcandidate location of next event
t_newcandidate time of next event
topology_ilearned importance score of past event i
feature_ilearned vector encoding of event i from graph
spatial_similarity(x_new, x_i)decaying weight based on distance
periodic_boost(t_new)extra score if time matches a learned cycle
A tiny worked example
Suppose a crime cluster has 3 events: Event A (very central, topology=0.8), Event B (moderately central, topology=0.5), Event C (isolated, topology=0.1).
A candidate next crime is 500 meters from A (spatial_similarity=0.6), 1km from B (0.3), and 5km from C (0.05).
Score from A: 0.8 * 0.6 = 0.48. Score from B: 0.5 * 0.3 = 0.15. Score from C: 0.1 * 0.05 = 0.005.
Total spatial contribution: 0.48 + 0.15 + 0.005 = 0.635.
If the candidate time is Friday evening and Friday evenings see crime spikes, periodic_boost adds 0.2.
Final score: 0.635 + 0.2 = 0.835. High score means high predicted probability.

The topology score multiplies the importance weight by the distance decay, so nearby central events drive predictions far more than distant marginal ones.

What can go wrong

What can go wrong

Graph construction is too strict or too loose. If you only connect events less than 1 km apart, the graph fragments and misses regional patterns. If you connect everything within 100 km, the graph becomes a dense hairball and topological signal disappears. The threshold must adapt to local density.
No periodic pattern exists, but the model invents one. If events are truly random in time but the query mechanism is too sensitive, it will hallucinate repeating patterns, over-boosting predictions at wrong times. The periodic module needs a confidence gate: only amplify cycles that are statistically strong.
Diffusion training is too slow or gets stuck. Learning by gradually removing noise can converge slowly or get trapped at local minima if the graph is poorly structured or the learning rate is wrong. Scaling to very large event sequences requires careful sampling and batching.
Done right: adaptive graph-building based on local event density, reliable periodic detection with confidence thresholding, and stable diffusion training via careful hyperparameter tuning. The paper likely addresses these via adaptive graph construction, learned periodicity confidence, and training recipes.
What a runnable demo should prove

What a runnable demo should prove

Build a toy dataset of synthetic events: a cluster that moves slowly across space and repeats every 7 time steps. Implement two baselines: one that predicts time independently of space, one that predicts space independently of time. Implement TEN-DM. Show that TEN-DM predicts the next event location-time pair correctly (because it sees the coupling through the graph), while the baselines predict time at one location and space at another time, producing misaligned errors. Vary the periodicity strength and show that TEN-DM detects the 7-step cycle and amplifies predictions at cycle-aligned times (because strong periodic patterns tell you when an event is due), while fixed-kernel methods miss the periodicity entirely.

accuracy = (correct_location_predictions + correct_time_predictions) / 2

The demo should make it impossible to deny that learning space-time jointly from a graph outperforms treating them separately, because the joint model sees the coupling constraint (next events must be near previous ones in both space and time), so it automatically aligns its time and space predictions, whereas independent predictors produce misaligned errors.
