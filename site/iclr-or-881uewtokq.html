MoNE: Lightweight Experts Replace Unused Ones

Instead of deleting unused experts from a Mixture-of-Experts model, replace them with tiny neural predictors that guess their outputs, cutting memory without retraining.

Paper explainersAll themesEfficiency & Systems

A Mixture-of-Experts model is like a giant office with many specialist desks. When you need an answer, a receptionist (router) decides which desks to ask. The problem: keeping all desks in memory is expensive, even the ones nobody visits. This paper replaces rarely-visited, boring desks with tiny robot assistants that just memorize what those desks would say. The model stays fast and accurate, but the memory shrinks.

Zero assumption version

Too Many Experts Sit Idle

A Mixture-of-Experts model (MoE for short) has dozens or hundreds of small neural networks called experts. Each expert is a set of tunable numbers. A routing network watches incoming text and picks which experts to use for each piece of text. This is efficient: you only compute the chosen experts, not all of them.

But keeping all experts in device memory at once is expensive. Even if an expert handles only 2% of the text, you still store it fully. Researchers tried deleting unused experts entirely, but this breaks things: the model suddenly forgets what it learned, or it guesses wrong on new tasks. The brutal delete is too destructive.

The deeper problem: nobody understood which experts were truly safe to remove. Some experts look unused but do quiet, important work. Some are used constantly but just copy what another expert does. You need to measure the right thing.

The main move. Replace each unused expert with a tiny learned guesser that copies what the original expert would have said—no deletion, no retraining.

The algorithm as a flow

What it actually does

Measure each expert

Count how many input tokens use this expert (access frequency) and how much its output varies across different inputs (output variance).

Identify candidates

Find experts that are both rarely visited and produce stable, predictable outputs.

Learn the guesser

For each candidate expert, train a tiny neural network to map the same inputs to the same outputs the real expert gave.

Swap in place

Replace the big expert with the tiny guesser inside the model—no retraining of the whole model.

Check across scenarios

Test accuracy across different model types, different calibration datasets, and different amounts of removed experts.

What the paper changes

What the paper changes

The paper replaces low-usage, stable experts with tiny learned predictors called novices. A novice is a small neural network trained to map inputs to outputs that match what the original (big) expert would have produced. The swap is local: you do not retrain anything else.

the object it moves  =  Expert with lightweight novice
The hidden quantity

The hidden quantity: Expert Redundancy

measured quantity  =  Expert redundancy using frequency and stability

Expert redundancy is how replaceable an expert is. It has two parts. First: is this expert actually used? If the router almost never picks it, it is redundant. Second: is its output predictable? If the same input gives wildly different outputs from this expert (high variance), it is hard to approximate. If the output is stable (low variance), a tiny learner can copy it.

The paper measures redundancy using access frequency (how many tokens hit this expert on the calibration data) and output variance (how much the expert's outputs scatter across different runs or data). Low frequency + low variance means high redundancy. The paper does not call it a single score; it uses both metrics together as a decision rule.

Why it works

Why it works: The novice learns, the model stays intact

The mechanism has three parts. First, you measure which experts are truly redundant (low frequency, low variance). This is vital because deleting the wrong expert breaks everything; a low-frequency expert might do quiet, hidden work.

Second, instead of deleting, you train a tiny neural network (the novice) to behave like the original expert. The novice sees the same inputs that the original expert saw during calibration and learns to produce matching outputs. This is supervised learning (you show the novice an input and the correct answer it should give). Since the original expert's outputs are stable, the novice can learn this pattern without random noise drowning it out.

Third, you swap the expert in the model graph for its novice and do not retrain anything else. Why does this work? Because the novice is trained to mimic the expert's behavior on calibration data, when the finished model answers a new question it looks almost identical to the model downstream. The router still picks the novice as it would have picked the expert. The novice produces nearly the same output. The rest of the model sees the same signal.

Stability in this method comes from measuring both frequency and variance. An expert with low frequency but high variance is unstable and not replaced. An expert with low variance but high frequency is useful and not replaced. Only the quadrant with low frequency and low variance is safe to prune.

The math: Novice loss as a supervised copy task

First in words:

loss of novice = average squared difference between novice output and real expert output, summed over all calibration examples

Then the compact form:

L_novice = (1/N) * sum_{i=1}^{N} ||novice(x_i) - expert(x_i)||^2

Every symbol:

novice(x_i)the output of the tiny learned network on input x_i
expert(x_i)the output of the original big expert on the same input x_i
x_ithe i-th piece of calibration data (a text token or token vector)
Ntotal number of calibration examples
||a - b||^2squared distance: how different two numbers or vectors are
A tiny worked example
Say the real expert's output for example 1 is [0.8, 0.2] and the novice's guess is [0.75, 0.25].
Distance squared: (0.8 - 0.75)^2 + (0.2 - 0.25)^2 = 0.05^2 + 0.05^2 = 0.0025 + 0.0025 = 0.005.
For example 2: expert [0.6, 0.4], novice [0.59, 0.41]. Distance squared: (0.01)^2 + (0.01)^2 = 0.0002.
Average loss: (0.005 + 0.0002) / 2 = 0.00260. This tiny loss means the novice is learning the expert's behavior well.

The novice is trained purely to copy, not to predict new cases it has not seen. It is a lookup table disguised as a neural network.

What can go wrong

What can go wrong

Calibration data is unrepresentative. If calibration data does not cover the full range of how the model will be used, the novice learns an incomplete pattern. The expert looks stable on calibration but acts differently in production. Example: measure redundancy only on English text, then deploy on code—the expert is actually critical.
Prune too many experts at once. If you remove 50% of experts, the load redistributes to the survivors. Some previously stable experts might now spike in variance. The novices were trained for the old load pattern, not the new one.
High-variance expert marked safe. An expert with low frequency but high variance looks stable in aggregate but is actually brittle—small input changes cause large output swings. Replacing it with a novice trained on averages loses the nuance.
Done right. Calibration data covers the full range of cases you will see. Measure both frequency and variance carefully. Start with small pruning ratios and validate on diverse downstream tasks.
What a runnable demo should prove

What a runnable demo should prove

Build a small Mixture-of-Experts model with six experts. Train it on a simple dataset (e.g., sorting numbers, predicting next token in short sequences). Then, measure each expert's access frequency and output variance on held-out calibration data. Identify the two or three experts marked for replacement. Train novices for those experts using only the calibration examples where the real expert was used. Swap them into the model. Run inference on new test data and compare accuracy before and after pruning.

accuracy_drop = (accuracy_before_pruning - accuracy_after_pruning) × 100%, model_size_reduction = (1 - size_after / size_before) × 100%

The demo should show that swapping novices in costs almost nothing in accuracy but shrinks the model by a large amount, even though the novices are tiny and trained in seconds with no model retraining.
