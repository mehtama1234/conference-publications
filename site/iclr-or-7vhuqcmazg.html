Language Agents for Clinical Diagnosis via Test Selection

A language agent learns which tests to request by optimizing for both correct diagnoses and efficient decision-making via reinforcement learning.

Paper explainersAll themesAI for Science

Doctors don't diagnose from all information at once; they form hunches, ask targeted tests, and refine their hunches. This paper teaches an AI model (a language model plus a decision-making layer) to do the same: make initial guesses about disease, request the most useful tests, and improve its guessing strategy via feedback from right and wrong diagnoses, because reinforcement learning rewards strategies that succeed cheaply (with fewer tests) and learns to avoid wasteful orders.

Zero assumption version

The mismatch between how doctors and AI models diagnose

Doctors gather information step by step: form a hunch, request a test, see the result, refine the hunch. But most AI applications in the clinic assume all information is already here — blood test results, imaging, patient history, all at once. That is not how real diagnosis works.

Some AI systems skip training altogether and use a large language model straight out of the box, hoping its general knowledge works for the clinic. But general models do not learn medical decision-making: they do not learn which tests matter most, or when to stop testing and commit to a diagnosis. A beginner might order every possible test (wasteful and risky), or order tests at random (wrong). The model needs task-specific training to learn which test reveals the most about each suspected disease.

The insight: Train a language agent to request tests strategically, using reinforcement learning to reward accurate diagnoses and punish wasted tests.

The algorithm as a flow

What it actually does

Initial guess

Language model suggests most likely diseases given patient age, gender, and chief complaint.

Choose a test

Agent ranks available tests by learned importance and requests the one that best distinguishes the top hypotheses.

Observe result

Model reads test result (normal, abnormal, specific value) and incorporates it into its reasoning.

Refine hypothesis

Agent updates its belief about which disease is most likely, repeating until confidence is high or budget runs out.

Learning from outcome

When the true diagnosis is revealed, reinforcement learning adjusts the test-selection strategy: reward good choices, discourage wasteful ones.

What the paper changes

The one thing the paper changes

Most clinical AI systems either receive all data at once or use a model with no training. This paper changes what the model learns: instead of just predicting disease from a static snapshot, it learns a strategy for requesting tests and refining guesses iteratively.

the object it moves  =  Test-selection policy
The hidden quantity

The hidden quantity: information gain per test

measured quantity  =  Information gain (how much a test reduces uncertainty)

Doctors do not pick tests at random. They ask tests that will most likely change their mind if the answer is surprising. For example, if you suspect bacterial infection but also have a small chance of heart disease, a blood culture test is very informative about infection (normal or shows bacteria) but a troponin level is more informative about heart damage. The paper measures this hidden quantity: how much each test narrows down the disease possibilities.

The paper estimates information gain by training a separate scoring function (part of the reinforcement learning) that learns, across many cases, which tests were actually useful (they separated the correct disease from wrong guesses) and which were wasteful (all outcomes were equally common regardless of true disease).

Why it works

Why this works: learning what tests really teach

The core insight is that reinforcement learning can discover which tests matter without being told. Here is the chain: The model makes a guess (disease A is most likely). It picks a test. The test result arrives. Over time, the model observes which test choices led to correct diagnoses cheaply (few tests) and which wasted resources on wrong paths. Reinforcement learning rewards the good choices and penalizes the wasteful ones. Gradually, the test-selection strategy evolves to match what a trained doctor knows intuitively.

Why not just teach it explicitly? Because the importance of each test depends on context: a troponin test is highly informative when heart disease is in the differential, but irrelevant if you are sure it is bacterial sepsis. Reinforcement learning discovers these context-dependent patterns automatically from data.

Math after the picture

The learning objective

First in words:

Reward = diagnostic accuracy minus (cost of test count times penalty weight)

Then the compact form:

reward = accuracy - (lambda * number_of_tests)

Every symbol:

accuracy1 if diagnosis correct, 0 if wrong
number_of_testshow many tests the agent requested
lambdaweight controlling trade-off between accuracy and efficiency
A tiny worked example
Case 1: correct diagnosis with 4 tests. Reward = 1 - (0.1 * 4) = 0.6
Case 2: correct diagnosis with 8 tests. Reward = 1 - (0.1 * 8) = 0.2
Case 3: wrong diagnosis with 2 tests. Reward = 0 - (0.1 * 2) = -0.2
Reinforcement learning increases probability of Case 1 strategy (high reward), decreases Case 3 (negative reward). Case 2 is penalized vs Case 1 because it wastes resources.

The reward function teaches the model: right answer alone is not enough; a right answer with fewer, smarter tests earns higher reward and becomes more likely in the future.

What can go wrong

What can go wrong

Test order matters but is ignored. In real diagnosis, the order of tests influences which test you request next (a positive bacterial culture changes what you test for). If training data does not capture sequence dependencies, the model may learn a shallow strategy.
Training cases may not match real clinic mix. If training cases overrepresent one disease (say, 80 percent kidney disease), the model learns a policy that works for that case but fails on rare diseases when used in the real clinic.
Reward hacking. The model could learn to order tests that are always positive (or always negative) for reasons unrelated to disease, just because they co-occur with high accuracy in the training set.
Done right. The paper trains on a real medical dataset (MIMIC-CDM) with equal numbers of each disease and validates on held-out cases, so the model learns from a balanced mix and does not overfit to common cases, because training on rare cases forces the model to discover strategies that generalize. Reward specification includes both accuracy and test efficiency, discouraging pure hacking, because a model that only optimizes accuracy might learn spurious test correlations.
What a runnable demo should prove

What a runnable demo should prove

Build a small version on 100 cases of one abdominal disease: a patient case generator (age, symptoms), a test set (ten possible tests with simulated results), and a simple language model backbone. Train the agent with supervised learning first (show it which tests a doctor really ordered), then fine-tune with reinforcement learning (reward correct diagnoses and penalize test count). Run it on a held-out test set and measure: (1) diagnostic accuracy, (2) average tests per case, (3) the learned ranking of tests (does it match medical intuition?). A good demo shows that reinforcement learning improves both accuracy and efficiency compared to supervised learning alone, because the reward signal directly teaches the model to trade off correctness against resource use and to ignore tests that did not correlate with true disease.

Overall score = (accuracy_percent / 100) - (0.05 * average_tests_ordered)

The demo is successful if the reinforcement learning score beats the supervised-only baseline and the learned test rankings align with medical common sense.
