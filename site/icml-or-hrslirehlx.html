Scene Graph Thinking: Structured Visual Reasoning for MLLMs

SaGe converts flat image-text data into scene graphs, then trains multimodal models to reason by traversing entities and relations instead of treating objects in isolation.

Paper explainersAll themesMultimodal

A picture is not only a set of detected objects. Many tasks depend on how those objects relate: which item is on top of another, which person is holding which tool, or which text label belongs to which visual part. Multimodal large language models often recognize objects but reason weakly over these relations. Scene Graph Thinking trains the model on explicit graph structure so that reasoning follows entities and relations rather than disconnected object mentions.

Zero assumption version

Object lists do not capture relational structure

Many multimodal tasks depend on composition. The model must identify entities and also determine how they connect. If a question asks which object blocks a door, the answer depends on a relation between two objects. If a question asks which ingredient is inside a bowl next to a spoon, the answer depends on several relations in sequence.

Standard training data often presents images with captions or question-answer pairs but no explicit structure over entities and relations. The model can therefore memorize frequent object patterns without learning a clean procedure for relation-based reasoning. On visually dense tasks, that weakness shows up as missed dependencies, wrong object references, and inefficient reasoning paths.

The problem: A model that sees objects without explicit relations can answer simple recognition questions yet still fail when the answer depends on how objects connect.

The algorithm as a flow

What it actually does

Build scene graphs from image-text data

An automated engine extracts entities as nodes and relations as edges.

Generate reasoning traces from the graphs

Training examples are written as ordered walks through the graph that justify an answer.

Run supervised fine-tuning on structured traces

The model learns to produce reasoning steps that align with graph structure.

Apply reinforcement fine-tuning with graph rewards

Reward favors trajectories that visit the right nodes and edges with fewer unnecessary steps.

Use the trained model on fine-grained tasks

The resulting system answers questions by organizing visual evidence through entities and relations.

What the paper changes

What the paper changes

The paper changes the representation of training evidence. Instead of relying only on flat captions or answers, it creates scene graphs and uses them to derive reasoning traces. This makes structure explicit before training, so the model can internalize a relation-centered reasoning procedure rather than having to infer one indirectly, because the relevant entities and relations are named in the supervision signal instead of being hidden inside free-form text.

The hidden quantity

The hidden quantity: graph coverage

measured quantity  =  graph coverage

Graph coverage measures how much of the relevant entity-relation structure a reasoning trace actually visits. A trace with high coverage touches the nodes and edges needed to justify the answer. A trace with low coverage skips an essential relation or wanders through irrelevant parts of the graph.

This quantity matters because structured reasoning is not only about having a graph; it is about traversing the right subgraph. If the model jumps from object names directly to the answer, it can still miss the relation that distinguishes the correct target from a distractor. Training with graph coverage rewards pushes the model to expose the intermediate links.

Why it works

Why graph-aligned post-training improves relation reasoning

The first mechanism is structural supervision. The data engine turns weakly structured corpora into scene graphs, giving the model explicit nodes and edges during training. A scene graph is a graph whose nodes are entities and whose edges are visual relations such as holding, next to, or inside. This helps because the model no longer has to guess the hidden structure from raw captions alone.

The second mechanism is trace supervision. Instead of training only on final answers, the model is shown ordered reasoning traces sampled from the graph. That teaches a reusable procedure: identify the starting entity, follow the relevant relation, then continue until the target entity or attribute is reached. The procedure transfers across questions because it is defined over graph structure, not over one dataset's wording.

The third mechanism is graph-based reinforcement fine-tuning. Reinforcement fine-tuning means improving behavior through reward on sampled outputs. The paper gives reward using node-level proxies, so the model gains more credit when it visits graph elements that are actually relevant to the answer. That leads to more efficient exploration because the model learns to reduce detours and concentrate probability on useful reasoning paths.

Scoring a reasoning trace

First in words:

A reasoning trace gets credit for reaching answer-supporting nodes and relations, and loses credit for unnecessary exploration.

Then the compact form:

trace_score = relevant_nodes + relevant_relations - detours

Every symbol:

trace_scorethe reward assigned to one reasoning path
relevant_nodescredit for visiting the entities needed for the answer
relevant_relationscredit for traversing the relations that connect those entities
detourspenalty for extra graph steps that do not support the answer
A tiny worked example
Question: Which object is inside the box next to the lamp?
Trace A visits box, next-to relation, lamp, inside relation, and target object, with no extra branch. Suppose relevant_nodes = 3, relevant_relations = 2, detours = 0, so trace_score = 5.
Trace B visits the lamp and two unrelated objects before reaching the box. Suppose relevant_nodes = 3, relevant_relations = 2, detours = 2, so trace_score = 3.
Training prefers Trace A because it exposes the supporting structure with fewer unnecessary steps.

The penalty matters because a model can eventually reach the right answer through a long wandering path, but that path does not represent efficient or stable reasoning.

What can go wrong

What can go wrong

Scene graphs are wrong. If the automatic engine extracts wrong entities or relations, the model will internalize those mistakes because both supervised traces and rewards are built on that structure.
Graph traces are too rigid. If every training trace follows one narrow ordering, the model may learn a brittle reasoning style that fails when another valid traversal would reach the same answer.
Proxy rewards miss answer quality. A trace can visit many relevant nodes yet still compose them into a wrong final answer, so graph rewards must stay tied to end-task correctness.
Done right: The graph supplies structure, the traces teach how to use that structure, and the reward keeps the model focused on concise answer-supporting exploration.
What a runnable demo should prove

What a runnable demo should prove

Build a toy dataset of indoor scenes with explicit scene graphs and questions that require one-hop and two-hop relations. Train one multimodal model on image-question-answer triples only and another on graph-derived traces plus node-based rewards. Measure final answer accuracy, whether the trace visited the required relation, and how many extra nodes the model explored before answering.

structured_reasoning = (correct_answer + required_relation_visited - extra_nodes_penalty)

The demo should show that explicit graph-aligned training matters most when the answer depends on following relations rather than merely naming visible objects.
