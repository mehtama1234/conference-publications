INO-SGD: Addressing Utility Imbalance under Individualized Differential Privacy

When different people set different privacy levels on their data, train the model by ranking each batch's samples by loss and up-weighting the private ones, so sensitive subgroups stay represented.

Paper explainersAll themesAlignment, Safety & Fairness

Imagine a medical dataset where some patients (people with rare diseases) demand strong privacy protection, while others are less concerned. Standard privacy-preserving training treats all data equally, which accidentally hides the rare disease patterns in the final model, making it useless for future patients with those diseases. This paper shows how to rank each batch of data by how hard it is to predict (high loss equals more private data, because owners protecting rare diseases set privacy levels that force the model to be confused about those patterns) and then down-weight the easy cases, so the model keeps learning about the private subgroups.

The privacy-fairness trap

In modern machine learning, not all data is equally sensitive. A patient with a rare disease might demand strong privacy protection (their data is leaked only if thousands are), while a researcher might not care. This is called individualized privacy—each person sets their own privacy level. Standard privacy-protecting algorithms treat everyone the same way, adding noise to every update at the same strength. This accidentally creates a problem: data from people with strong privacy requests (the rare diseases) gets diluted by noise and ends up underrepresented in the final model. When a doctor uses the model on a new patient with that rare disease, the prediction is bad.

A beginner might think: if we just remove the noisy regularization for private data, won't it train better? No—that leaks the private data to attackers, because without noise an attacker can invert the training algorithm by checking whether the model would change if one sensitive sample were added or removed. We are stuck between two bad options: strong privacy that hides rare groups, or weak privacy that leaks secrets.

The core problem. Differential privacy with individualized levels causes utility imbalance: rare subgroups with high privacy requests become invisible in the model.

What the paper changes

The one thing that changes

The paper changes how gradients (learning signals) are weighted inside each batch. A gradient is a direction that says which way to nudge the model to make it more accurate, because it points toward reducing the prediction error measured by loss. Standard algorithms treat every gradient the same; INO-SGD multiplies each by a weight based on its loss rank. Samples with high loss (hard to predict) get full or boosted weight. Samples with low loss get downweighted or dropped.

the object it moves  =  gradient weights per sample
The hidden quantity

The loss rank: which samples matter most

measured quantity  =  Loss ranking within batch

The paper measures a new quantity: the rank of each sample's loss inside the current batch. Loss is how far off the model's prediction is from the true answer—higher loss means the model is more confused by that sample. In a batch of 10 samples, the paper sorts them by loss and assigns a rank from 1 (hardest) to 10 (easiest). This ranking becomes the signal: high-rank samples (hard, usually from private data owners) stay in the gradient; low-rank ones (easy, usually from public data owners) get downweighted or removed.

The paper estimates this ranking by simply computing the loss value for each sample in the current batch, then sorting. It then uses the rank to determine which gradients to keep, which to shrink, and which to drop entirely. This ordering is the core of why INO-SGD works: it uses the batch's own loss signal to automatically amplify learning on harder, private samples.

Why it works

Why reweighting by loss fixes utility imbalance

Here is the causal chain: in individualized differential privacy, each owner sets their own privacy budget epsilon. A lower epsilon means stronger privacy (more noise is added), because a tighter privacy bound forces more random perturbation into the gradients to hide individual contributions. When strong-privacy owners have data that the model finds hard to predict (high loss), standard algorithms still treat that data the same as easy data from weak-privacy owners. But because more noise is applied to strong-privacy data, the hard patterns get buried. INO-SGD breaks this by reweighting inside each batch: it amplifies the gradient signal from high-loss samples (which often come from strong-privacy owners) and downweights low-loss samples (which come from weak-privacy owners). Why does this preserve privacy? Because the reweighting happens inside the batch before noise is added. The privacy guarantee still holds because the noisy part of the algorithm is unchanged—the noise still gets added in the same way.

In concrete terms: imagine a batch has a rare disease case (high loss, strong privacy) and a common cold case (low loss, weak privacy). Standard training splits the learning 50-50. INO-SGD reweights so the gradient from the rare disease case dominates the batch update—the model learns rare disease patterns harder. The privacy noise is still applied, but the stronger signal punches through, because the reweighted gradient has larger amplitude that noise cannot fully drown out. Across many batches, this biases the model toward the high-privacy, high-loss subgroups, fixing the utility imbalance while maintaining each owner's privacy guarantee.

Math after the picture

The reweighting formula

First in words:

For each gradient in the batch, multiply it by a weight that is 1 if the loss is in the top k samples, and 0 (or a small value) otherwise. Then add scaled noise to the sum before updating.

Then the compact form:

L_update = sum_i w_i * g_i + noise, where w_i = 1 if rank(loss_i) <= k else 0

Every symbol:

g_ithe gradient (learning signal) from sample i
loss_ithe prediction error on sample i
rank(loss_i)the position of sample i when sorted by loss (1=highest loss)
w_ithe weight for sample i's gradient (1 if kept, 0 if dropped)
kthe cutoff rank (how many top-loss samples to keep)
noiserandom noise added to preserve privacy
A tiny worked example
Batch of 4 samples: losses are [2.5, 0.3, 1.8, 0.1]. Sorted by loss: [2.5, 1.8, 0.3, 0.1].
Set k=2 (keep top 2). Ranks are: sample1=rank1, sample3=rank2, sample2=rank3, sample4=rank4.
Weights: w1=1, w3=1, w2=0, w4=0 (only the two hardest samples count).
If gradients are g1=[1.0, 0.5], g3=[0.8, -0.2], g2=[0.2, 0.1], g4=[0.1, 0.0],
then reweighted sum = 1.0*[1.0, 0.5] + 1.0*[0.8, -0.2] + 0*[0.2, 0.1] + 0*[0.1, 0.0] = [1.8, 0.3].
Add privacy noise (e.g. Gaussian with std 0.5): [1.8, 0.3] + [±noise] protects privacy while keeping hard-sample signals.

The weight is 1 (keep) for top-k losses and 0 (drop) for the rest, ensuring high-loss (high-privacy) data drives the update.

What can go wrong

What can go wrong

Loss rank is unstable early in training. At the start, the model is random so all losses are noisy. Ranking by loss is unreliable. INO-SGD works best after a few epochs when loss gaps are real.
Outliers can dominate if one sample has huge loss. If one rare disease case is so hard that the model assigns extreme loss, it might get weighted too heavily and cause overfitting. The paper uses a clipped CVaR (conditional value at risk) objective to reduce outlier influence.
Batch size must be large enough to rank fairly. If the batch is only 2 samples, ranking does not capture diversity. Small batches reduce the stability of the loss-ranking signal.
Done right with clipping and noise. INO-SGD applies gradient clipping (cap the size of each gradient to limit influence) and adds noise in a way that preserves individual privacy budgets while reweighting, so outliers and small batches are handled safely.
What a runnable demo should prove

What a runnable demo should prove

Build a simple two-class dataset where one class is rare (5 percent) and has high privacy requests, and the other is common (95 percent) and has low privacy requests. Train a standard privacy algorithm on it, then train INO-SGD. Measure accuracy on both classes across training epochs. Plot the curves. The demo should show that standard privacy training makes the rare class accuracy stall at 30-40 percent (because noise hides it), while INO-SGD's rare class accuracy climbs to 60-70 percent without sacrificing common class performance. The key metric is utility on the rare class—it must improve by at least 20 percentage points (enough to prove reweighting amplified the signal) while privacy budgets are respected (because the reweighting happens before noise, the noise level and privacy guarantee remain mathematically unchanged for each owner).

rare_class_accuracy = (count of correct rare predictions) / (total rare samples). Compare standard_dp vs ino_sgd.

If INO-SGD's rare class accuracy is not substantially higher than standard privacy (at least 20 percentage points) while common class stays above 70 percent, the reweighting mechanism did not work.
