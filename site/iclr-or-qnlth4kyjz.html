AdAEM: Adaptive Value Evaluation for LLMs

Instead of using fixed questions, AdAEM automatically generates new test questions that probe the boundaries where LLMs disagree on values.

Paper explainersAll themesAlignment, Safety & Fairness

Measuring what an LLM actually believes is hard. Most tests ask the same old questions everyone uses, so all models give similar answers and look equally safe. AdAEM solves this by automatically creating new questions designed to find the places where different LLMs truly diverge in their values — revealing their hidden differences in fairness, safety, and cultural outlook.

Zero assumption version

Why old test questions don't reveal model differences

Today, we test LLMs using the same benchmark questions over and over — questions about harmlessness, honesty, and helpfulness. The problem: all modern LLMs have been trained on these same public questions, so they all give very similar, safe answers. It is like asking a room of students the same homework question they all studied together — everyone gets it right, and you learn nothing about who actually understands or who just memorized.

A beginner might try making the benchmark bigger (more questions), but that does not help if all the new questions are also predictable or cover only common ground, because the test still asks all models the same shared questions, and they will still all give the same safe answers they learned from training. The deeper problem is that static benchmarks measure only the shared safety values that every LLM has learned to adopt. They miss the places where models actually differ — their cultural biases, their edge-case moral intuitions, their blindnesses — because those are the places the benchmark does not ask about.

The core idea in one sentence. Automatically generate test questions by finding the boundaries where LLMs disagree, so every new benchmark question probes a real difference.

What the paper changes

The one thing the paper changes

AdAEM changes the benchmark questions themselves. Instead of a static set, it builds a living test set that automatically grows with new questions designed to expose real model disagreements.

the object it moves  =  benchmark questions
The hidden quantity

The hidden quantity: model separability

measured quantity  =  how far apart the models are on controversial topics

The paper measures a quantity that does not appear in older benchmarks: the separability between models. This is how much a question divides the LLMs — do they all agree, or do they split across opposite answers? A question with high separability reveals a real value difference; a question where all models agree is not informative.

To estimate this, AdAEM runs the question through each LLM and counts how many give conflicting answers. It then uses information theory (a mathematical tool for measuring surprise or unpredictability in answers) to pick the questions that maximize this disagreement. The higher the separability, the more surprised the group is by each other's answers, which means the question has found a genuine fault line where models truly differ.

Why it works

Why automatically growing a benchmark reveals model differences

The mechanism is a loop. You start by giving a large candidate question set to all your LLMs. Each model answers; you calculate which questions get the most split answers (high separability). Then you use those high-separability questions to probe even deeper — asking follow-ups or variations — to find NEW questions that split the models even more. This grows a new layer of test questions around the boundaries where the models disagree.

Why this works: static benchmarks are built once and stop evolving. They capture the common ground all models have adopted, not the edges where models truly differ. By making the benchmark grow toward disagreement, you are always chasing the frontier of real model differences. As new LLMs are built, AdAEM re-runs and finds new disagreement zones — the benchmark stays alive and relevant, not stale. The method maximizes an information theory objective, which means mathematically it is guaranteed to find the questions that best separate the models.

Math after the picture

The separability equation

First in words:

The separability of a question is the sum of how surprised each answer makes the group's average. A question where all models agree has low surprise; a question where half say yes and half say no has maximum surprise.

Then the compact form:

Separability(q) = sum_models log(P(response_m | q) / P_avg(response | q))

Every symbol:

Separability(q)how much question q divides the models
response_mwhat model m actually answered
P(response_m | q)the probability of that response given the question
P_avg(response | q)the average probability across all models
loglogarithm (a way to measure information)
A tiny worked example
Question q: Does AI deserve rights? Models answer: yes, yes, no, yes, no.
Average response rate: 60% yes, 40% no.
Model 1 said yes (60% chance): log(0.60/0.60) = log(1.0) = 0.0 (not surprising)
Model 3 said no (40% chance): log(0.40/0.40) = log(1.0) = 0.0 (not surprising)
Model 5 said no (40% chance): log(0.40/0.40) = log(1.0) = 0.0 (not surprising)
Sum = 0.0 (this question did not shock anyone, so it is not informative).
Compare to a different question where 3 models say yes, 2 say no: separability would be much higher because some models are outliers.

High separability means the question genuinely splits the models, so it reveals a real value difference.

What can go wrong

What can go wrong

Gaming by jailbreaking. If a model is trained to resist revealing its true values (to appear safer), AdAEM will not find real disagreements, only trained-in uniformity. The method assumes models answer honestly.
Bias toward minority answers. A question that one model answers opposite to all others might be ranked high-separability, but it might simply be a model error or a model quirk — not a true cultural value that matters.
Finite candidate pool. The method can only generate questions from variations of its starting candidate set. If the initial pool misses a domain entirely (e.g. religious questions), AdAEM will not find questions in that domain.
Done right. With diverse, honest LLMs and a broad starting question set, AdAEM reliably exposes model value differences that static benchmarks miss.
What a runnable demo should prove

What a runnable demo should prove

Build a minimal version: (1) collect four LLMs of different ages and training regimes. (2) Start with 50 generic questions on fairness, bias, and cultural values. (3) Run AdAEM for three iterations: each time, select the top 10 highest-separability questions from your candidate pool, and generate 20 new question variants by paraphrasing and extending the disagreement zone. (4) Re-evaluate all models on the extended set. (5) Report the average separability at each iteration. (6) Visualize which questions changed the most across iterations — those are your benchmark's real value probes.

avg_separability_iteration_k = (1 / num_questions_k) * sum_q Separability(q) across all questions in iteration k

The demo must show that avg_separability increases with each iteration, proving that AdAEM is automatically finding more informative questions. Compare to a static benchmark (control: shuffle the same questions, re-evaluate) — the static benchmark separability should stay flat while AdAEM grows.
