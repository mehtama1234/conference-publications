SE-GA: Memory-Augmented Self-Evolution for GUI Agents

SE-GA helps a GUI agent finish long screen tasks by retrieving the right past experience at each step and then turning those solved runs into better future behavior.

Paper explainersAll themesAgents & Tool Use

A GUI agent often fails for a simple reason: the next click depends on facts that appeared many screens earlier, but the agent only has a short working view of the task. SE-GA tackles that gap with a memory system that brings back the most useful past experience when the agent is deciding what to do on the current screen. It then uses solved runs to improve later runs, because the agent should keep more of what worked and less of what failed.

Zero assumption version

Why long GUI tasks break ordinary agents

A long GUI task spreads its evidence across many moments. The task goal may appear in the first instruction, the needed setting may appear halfway through, and the final confirmation may depend on both. A plain agent often drops one of those pieces because its working view is short and because each new screen pushes older details out of view.

That weakness becomes worse when the task branches. The agent may have solved a similar screen before, but if it cannot recover that past run at the right time, it starts the reasoning from scratch. SE-GA treats this as a memory problem first, because better retrieval can restore the missing facts before the next action is chosen.

The paper's move in one sentence. Store task experience in several memory banks, retrieve the parts that match the current screen, and recycle successful runs into future training so that the agent keeps improving from its own work.

The algorithm as a flow

What it actually does

Step 1: Observe the current screen

Read the current screen, the task goal, and the recent action history so that the agent knows where it is.

Step 2: Search several memory banks

Retrieve matching past screens, task facts, and solved runs because each bank stores a different kind of useful evidence.

Step 3: Build an enriched working view

Combine the current screen with the recalled items so that older but still relevant facts are visible again.

Step 4: Act in the GUI

Choose the next click, type action, or scroll based on that enriched view.

Step 5: Learn from finished runs

Keep data from strong runs and use it to improve later behavior, because repeated good solutions should shape the agent's future choices.

What the paper changes

What the paper changes

The paper changes the agent's working state. Instead of forcing every decision to depend only on a short recent history, it adds retrieved long-range task evidence and then loops solved runs back into training.

the object it moves  =  task-time working context
The hidden quantity

The hidden quantity: decision-time coverage

measured quantity  =  how much of the task-relevant past is present when the agent chooses the next action

The most important quantity is decision-time coverage. The agent may have seen the needed evidence earlier, but the real question is whether that evidence is present when the current action is chosen.

SE-GA raises coverage by storing different forms of past experience and then retrieving the pieces that fit the current screen. That matters because a long task fails when the missing fact is absent at the exact decision point, not because the fact was never seen at all.

Why it works

Why it works

The memory split matters because not all useful past information has the same form. One part is a remembered screen and what happened on it. Another part is a short rule about the task. Another part is a higher-level solved run. Keeping those apart helps retrieval because each memory bank can answer a different question.

The self-evolution step matters because retrieval alone only helps the current run. When the system turns strong runs into new training material, the base agent itself gets better because later tasks begin with policies that already absorbed those successful patterns.

The paper's gains fit this story because GUI tasks depend heavily on delayed evidence. A retrieval system that restores delayed evidence improves action choice by putting the missing clue back into the working view, and a training loop that keeps the best recovered runs improves future action choice by preserving those successful patterns in the base agent.

Math after the picture

A compact retrieval-and-learning objective

First in words:

Choose the next action using the current screen plus the recalled memories that best match it, then favor training updates from finished runs that solve the task with fewer mistakes.

Then the compact form:

J = E[ success(a_t | s_t, M_t) + alpha * useful_recall(M_t, s_t) - beta * error_steps ]

Every symbol:

Jthe expected objective over GUI episodes
a_tthe action chosen at step t
s_tthe current screen state and task goal at step t
M_tthe memories retrieved for the current step
success(a_t | s_t, M_t)reward for taking actions that finish the task when current evidence and recalled evidence are both used
useful_recall(M_t, s_t)how well the retrieved memories match what the current screen needs
error_stepswasted actions such as wrong clicks, detours, or repeated corrections
alphaweight on retrieval quality
betaweight on wasted actions
A tiny worked example
The task is to enable a setting that is buried three menus deep.
At the final menu, the current screen alone shows two similar options.
The memory search recalls an earlier solved run saying that the correct option sits under the privacy menu, not the account menu.
The agent clicks the privacy path, reaches the right toggle, and avoids two wrong detours.
That run earns a higher objective because the recalled evidence matched the screen and reduced wasted steps.

The exact training details are richer than this summary, but this compact form captures the paper's main idea: reward actions that solve the GUI task while rewarding retrieval that brings back the right old evidence.

What can go wrong

What can go wrong

Wrong memories come back. A bad recall can hurt the current step because it pushes the agent toward a screen that only looked similar on the surface.
Memory stores repeated low-value runs. If the saved experience is noisy or repetitive, later retrieval becomes less helpful because the best signals are buried under weak ones.
Self-improvement can reinforce early mistakes. If a flawed run is treated as good training material, later behavior may copy the wrong pattern because the loop keeps feeding that pattern back.
Done right. The method works when retrieval ranks the right past evidence highly and the self-evolution stage keeps only runs that solve the task cleanly, because then both the current step and the next round benefit.
What a runnable demo should prove

What a runnable demo should prove

Build a small desktop task with six to eight screens and at least one delayed dependency, such as reading a code on the first screen and entering it on the fifth. Run one agent with only the recent history and another with memory retrieval from past solved runs. Then add the self-evolution loop by saving clean solved runs and reusing them in later trials.

The demo should show fewer wasted steps and higher task completion for the memory-augmented agent because the delayed clue is present again at the moment it matters.

task_success = solved_tasks / total_tasks ; wasted_steps = wrong_actions / total_actions ; recall_hit_rate = useful_recalls / total_recalls

The key evidence is that retrieval restores the missing old clue and the self-evolution loop keeps that gain alive in later tasks, because the same successful pattern first repairs the current run and then becomes part of later behavior.
