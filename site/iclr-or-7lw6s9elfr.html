MVR: Multi-View Video Reward Shaping

Learn what successful motion looks like using videos from multiple angles, then use that knowledge to guide a robot's learning without distorting its actual task.

Paper explainersAll themesReinforcement Learning

Teaching a robot to learn is hard because rewards (the signal that says 'you did it right') are often vague or misleading. Recent work tried using image-matching from large vision models to create better reward signals, but a single photo is not enough to judge whether a robot is moving correctly—you need to see the full motion from different angles. MVR solves this by learning from multi-view video clips of the task, building a deep understanding of what success actually looks like, then using that to guide learning without breaking the real objective.

Zero assumption version

The single-image trap

When you teach a robot to run or pick up a cup, you tell it 'here is what I want' using rewards—numbers that say how close it came. The challenge: how do you know if a robot's motion is truly correct? A photo looks the same from many angles. One view might hide the mistake—a humanoid's leg could be straight and look good from the front but be twisted backward from the side.

Earlier work tried to fix this using large vision models (the kind that understand 'cat' and 'dog' from images) to score each frame. They asked the model: does this frame match my description? But this is a trap. A frozen moment is not motion. A robot could reach the exact position shown in a photo but take a broken path to get there. If you just say 'maximize how much this frame matches the description,' the robot learns to freeze in weird poses instead of actually run or walk.

Worse, these methods blindly add the vision model's score to the real reward without thinking about whether they conflict. The result: the robot ends up chasing two contradictory goals—do the task AND sit in the magic pose. The optimal strategy gets bent.

In one sentence. A single photo cannot judge whether motion is correct, and adding vision guidance without care distorts what the robot actually learns to do.

The algorithm as a flow

What it actually does

Collect multi-view clips

Record videos of successful motion from 3+ camera angles.

Score videos

Use a frozen large vision model to say how well each video matches the task description.

Train a relevance predictor

Build a small model that learns to predict video scores directly from the robot's body state.

Shape the reward smartly

Blend task reward with guidance reward using a formula that automatically weakens guidance as the robot improves, because early nudges matter when the agent is lost but become obstacles once the agent understands the real goal.

Train the robot

Use the shaped reward to train the RL agent; it learns task goal faster without chasing vision poses, because the fading guidance prevents the tug-of-war between two conflicting signals that would otherwise trap learning.

What the paper changes

What the paper changes

MVR changes the reward signal itself. Instead of naively adding vision-model scores to task rewards, it builds a learned function that predicts how relevant each robot state is to the task based on multi-view video understanding, then uses that in a decay-aware shaping formula.

The hidden quantity

State relevance: how much does this body position match success?

measured quantity  =  State relevance score

This is a new learned function that lives between the body state (joint angles, limb positions) and the task goal. It answers: if the robot is in this configuration right now, how close to true success is it? Unlike raw vision-model scores on images, this function learns from the full temporal context of multi-view video—it knows that real running includes a sequence of body shapes, not a single frozen pose.

The paper estimates it by training a small neural network to predict the video-text matching score starting only from the robot's state measurements. The trick is having ground truth labels from the videos: for each state visited during episode rollout, the network learns to predict how well that state's video clips would score.

Why it works

Why multi-view video captures motion, and why decay solves the conflict

Here is the core insight. A single static image is a snapshot, frozen and ambiguous. But a video is a sequence—it shows the path the robot takes through space. When you capture that sequence from multiple angles, you remove ambiguity. A twisted leg cannot hide; it shows up in the side view. A robot reaching for a cup takes a continuous trajectory that a vision model can judge across frames. The learned relevance function absorbs this temporal and spatial richness, so it knows what real success looks like as a body motion, not a single pose.

But if you then just add this relevance score to the task reward, you create a tug-of-war: two conflicting objectives. The solution is a state-dependent decay. The idea: early in training, the robot is stuck and needs guidance, so relevance guidance is strong. As the robot learns the actual task and its actions start to match the target motion pattern, the guidance weight shrinks automatically. This is clever because it avoids the trap of false attractors—the robot will not waste energy sitting in a vision-model pose once it has learned the real task. The math formula detects 'behavior is now aligned' and reduces the guidance term to near zero, leaving only the original task reward.

Math after the picture

The reward shaping formula with adaptive decay

First in words:

shaped reward equals task reward plus a decay-scaled guidance term; the decay weight starts high when the agent is far from the goal and shrinks toward zero as the agent improves.

Then the compact form:

r_shaped = r_task + w * f_relevance(s), where w = exp(-(progress / sigma))

Every symbol:

r_shapedthe final reward signal that trains the robot
r_taskthe original reward you wanted (e.g., move forward 10 meters)
wthe weight controlling how much guidance to apply
f_relevance(s)the learned function predicting state relevance from body state s
progresshow well the robot is currently solving the task (normalized 0 to 1)
sigmaa decay rate parameter controlling how fast guidance fades
A tiny worked example
Early training: robot is stuck, progress = 0.1. w = exp(-(0.1 / 0.3)) ≈ 0.72. Guidance is strong.
Mid training: robot is learning, progress = 0.5. w = exp(-(0.5 / 0.3)) ≈ 0.19. Guidance is weaker.
Late training: robot is nearly solved it, progress = 0.9. w = exp(-(0.9 / 0.3)) ≈ 0.03. Guidance is negligible.
The same relevance signal remains constant, but the weight shrinks over time, preventing the robot from getting stuck chasing false poses.

The decay ensures that guidance helps when the agent is lost but vanishes once the agent has learned the real task, preventing two conflicting objectives, because a weight of zero mathematically removes the guidance term entirely, leaving only the original task objective.

What can go wrong

What can go wrong

Video collection bias. If all your reference videos show the task solved one way, the learned relevance function may reject valid alternative strategies. A robot that runs differently but reaches the goal is marked as bad by the relevance model, slowing learning.
Decay tuning error. If decay is too fast, guidance disappears before the robot learns anything and you get no benefit. If decay is too slow, you reintroduce the conflict between task and guidance, and the robot gets stuck in poses again.
Vision model mismatches. The frozen large vision model may not understand the text description accurately, or the robot may perform actions it was never trained on. Bad initial labels cascade into a bad learned relevance function.
Done right. Collect diverse reference videos, tune decay to fade around the halfway point of learning, and ensure the text description is concrete and specific to the task.
What a runnable demo should prove

What a runnable demo should prove

Build a simple 2D or 3D simulation where a character must reach a goal (e.g., run forward 10 meters or grasp an object). Collect 5-10 videos of success from 2-3 viewpoints. Train three agents in parallel: (1) with only task reward, (2) with static image guidance (no decay), and (3) with MVR. Plot task success rate over time and log the robot's final poses—you should see (1) learn slowly, (2) reach high performance but then decline or freeze in wrong poses, and (3) climb steadily and sustain high performance without weird frozen poses at the end.

Success rate = episodes reaching goal / total episodes; plot success vs training time for all three approaches.

The key observation: guidance should help early but disappear without leaving scars, because a constant weight means the robot is forever pulled toward false poses, but a decaying weight lets it detach and pursue only the true goal. MVR vanishes; static guidance leaves the robot trapped.
