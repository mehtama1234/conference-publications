HiMAE: Hierarchical Masked Autoencoders for Wearable Time Series

A hierarchical masked autoencoder discovers which time scales in wearable sensor data actually matter for health predictions by building embeddings at multiple resolutions simultaneously.

Paper explainersAll themesAI for Science

Wearable sensors like smartwatches collect physiological data—heart rate, breathing, motion—at many time scales at once. But we do not know which scales matter for predicting health outcomes. This paper hypothesizes that different health tasks rely on different time scales: heartbeats unfold in milliseconds, while mood patterns span hours. To test this, the authors built HiMAE, which produces a learned representation (a compact summary) not at one time scale but at several, each capturing a different time granularity. The result is a smaller, faster model because the hierarchy reuses computations across scales instead of computing each scale independently, and it serves as a discovery tool by revealing which scales matter for each outcome—you pick the scale that actually predicts that health task.

Zero assumption version

The resolution puzzle: which time scale is right?

Wearable sensors measure your physiology thousands of times per second. A smartwatch accelerometer samples motion every 10 milliseconds, a heart-rate sensor every 100 milliseconds. When a researcher wants to predict whether you will have a good day or a bad mood, they have to choose: should I extract features at the 10 millisecond scale? The 100 millisecond scale? The full-day scale? Different outcomes might need different answers, but we have no principled way to find out.

Traditional approaches pick a single resolution upfront (a hyperparameter) or train separate models for each scale. A beginner might collapse all the data into a single learned representation, losing the fast heartbeat patterns and the slow circadian rhythms at the same time. The naive hope—that one global learned representation works for everything—almost always fails when outcomes depend on patterns at different speeds.

The paper's answer in one sentence. Build one model that produces learned representations at multiple time scales simultaneously, then observe which scales predict which health outcomes.

The algorithm as a flow

What it actually does

Input: raw sensor stream

Smartwatch time series (heart rate, motion, temperature) arrives as raw numbers.

Masking: blank out patches

Randomly hide 75% of the signal in short, contiguous chunks to simulate sensor dropout.

Hierarchical downsampling: shrink then expand

Layers with stride-2 (a sliding window that skips every other sample) halve the time samples at each step, then skip-connections rebuild it.

Multi-resolution embeddings: capture each scale

Each layer outputs an embedding frozen at that resolution. Shallow layers have fine detail; deep layers have long-range patterns.

Reconstruction loss: teach at every scale

Measure mismatch between masked input and rebuilt signal at each resolution. Train to minimize the total.

What the paper changes

The object: learned representations at multiple time scales

Standard masked autoencoders produce a single learned representation at the end. HiMAE instead freezes intermediate representations at each layer of the hierarchy. A layer that downsampled by halving the time samples (stride-2) captures structure at twice the time span. This lets downstream tasks pick which time scale they need, instead of the model deciding.

the object it moves  =  intermediate layer representations, one per time scale
The hidden quantity

The hidden quantity: which scales carry signal

measured quantity  =  scale-specific predictiveness

The paper's key insight is that not all time scales are equally useful for a given outcome. Predicting step count might need the motion patterns in the 100 millisecond range. Predicting sleep quality might need patterns spanning minutes. The paper measures this by training downstream classifiers on embeddings from each resolution independently, then observing which layer's embedding predicts each outcome best.

This scale-specific signal is a hidden quantity because raw wearable data conflates all scales at once. By systematically probing each resolution, HiMAE makes visible which scales the body's physiology encodes for each outcome.

Why it works

Why it works: receptive fields encode resolution

In a layer with sliding windows, each neuron 'sees' only a local neighborhood of its input. This local window is called the receptive field. In HiMAE, each layer has a receptive field twice as large as the previous layer (because downsampling by half means the window spans twice as many original samples). A shallow layer's neurons each see 20 milliseconds of data. A deep layer's neurons each see 2 seconds.

Masked autoencoding forces the model to reconstruct missing patches. At a shallow layer, the model must infer small details—what was that wiggle in the waveform? At a deep layer, the model must infer slow trends—was the heart rate climbing or falling over the past few seconds? Training steers the weight values (the numerical tuning knobs inside the model) to capture whichever temporal patterns they can 'see.' By freezing intermediate learned representations, we keep summaries built by receptive fields at multiple granularities, each optimized to reconstruct patches at its own time scale.

The reconstruction loss across scales

First in words:

total loss = sum over all layers of (mean squared error between masked input and reconstructed signal at that layer's resolution) + regularization

Then the compact form:

L = sum_l || x_l - x_hat_l ||^2 + lambda * ||theta||^2

Every symbol:

x_lthe signal downsampled to layer l's time resolution
x_hat_lthe model's reconstruction at layer l's resolution
||...||^2squared difference summed across all time steps
lambdahow strongly to penalize large weight values
||theta||^2sum of all weight values squared
A tiny worked example
Suppose layer 1 (shallow, fine detail) has 1000 time samples, and the reconstructed signal differs by 0.01 on average. Error at layer 1 = (1000 samples) * (0.01)^2 = 0.1.
Layer 3 (deep, coarse) has 125 time samples (downsampled 8x), and differs by 0.03 on average. Error at layer 3 = (125 samples) * (0.03)^2 = 0.1125.
Layer 5 (very deep) has 16 time samples and differs by 0.1. Error at layer 5 = (16 samples) * (0.1)^2 = 0.16.
Total reconstruction loss = 0.1 + 0.1125 + 0.16 + ... = ~0.4 (simplified). The model learns to balance all three: improve fine detail AND coarse structure.
Regularization term = 0.001 * (sum of all weight squares). Training steers weights toward small values, preventing overfitting.

Each layer's error pushes the model to capture structure at that time scale; summing across scales ensures every granularity is learned.

What can go wrong

What can go wrong

Over-masking destroys signal. If you mask more than 75% of patches, even deep layers cannot reconstruct context. The model learns noise patterns instead of physiology. Set masking conservatively for your data.
Misaligned receptive fields. If your convolutional strides do not align with the natural time scales in your data (e.g., if heart rate oscillates every 50 milliseconds and your stride is 100 milliseconds), the model will miss that rhythm. Design stride sizes with domain knowledge.
Conflating scale with prediction. A coarse layer's embedding might fail on a fine-scale task not because the scale is wrong, but because the model never learned to reconstruct at that scale (masking was too aggressive there). Verify reconstruction quality per layer.
Done right. Calibrate masking and stride to your physiology, validate that reconstructions are clean at each scale, and always measure downstream performance per layer. The payoff is embeddings that are both interpretable and task-efficient.
What a runnable demo should prove

What a runnable demo should prove

Implement HiMAE on a public wearable dataset (e.g., PPG-DaLiA for heart rate, or a smartwatch accelerometer corpus). Pretrain the masked autoencoder on unlabeled sensor data. Freeze each layer's learned representations separately. Train simple downstream classifiers (logistic regression or a small neural network) on each layer's representation to predict a health outcome (e.g., stress, sleep quality, or physical activity). Measure accuracy at each layer and visualize a bar chart showing which layers win for which outcomes. For running efficiently on smartwatch hardware, measure how long the computation takes on a smartwatch CPU.

accuracy_per_layer = (correct predictions on test set) / (total test samples), measured separately for layer 1, layer 2, layer 3, etc.

The demo's key finding: different outcomes peak at different layers. This proves that resolution is not a hyperparameter to tune away, but a structural axis of physiology you can query.
