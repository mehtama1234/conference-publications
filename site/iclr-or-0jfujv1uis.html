GeoEdit: Geometric Image Editing via Effects-Sensitive Attention

GeoEdit edits objects in images by lifting them into 3D, applying precise geometric moves, then letting attention focus on shadows and lighting to make the result look real.

Paper explainersAll themesComputer Vision

Moving an object in a photo should be simple: rotate it, scale it, slide it. But in real images, shadows and light also move with the object. Current methods either rotate the object correctly or add realistic shadows correctly, but not both. GeoEdit does both by lifting objects into 3D space first, then using a learned focusing system (which parts of the image to emphasize) to model how light and shadows shift when the object moves.

Why moving objects in images is hard

Imagine a photo of a mug on a table. You want to rotate it 45 degrees, or slide it to the left. The naive approach: cut the mug out, rotate it as pixels, paste it back. The problem: pixels are flat. When you rotate a mug, its shadow should rotate with it, and the light hitting its surface should change. Pixel rotation loses this. Real shadows and highlights need to move in plausible ways that depend on where the light comes from and where the object ends up.

Existing methods either solve the rotation and scaling problem (they move objects correctly as pixels) or solve the lighting problem (they add realistic shadows and highlights), but not both. If you only rotate pixels, the shadows stay in the wrong place. If you add shadows after rotating pixels, they often look pasted on and artificial, because the method does not understand that the object exists in 3D space and interacts with light differently at its new position.

The method. GeoEdit lifts objects into 3D space, applies geometric transformations there, then uses a learned focusing system to guide generation of plausible lighting and shadows.

The algorithm as a flow

What it actually does

User provides input

A photo, a mask around the object, the desired geometric move (rotate 45 degrees, scale 0.8, translate 50 pixels).

Geometric Transformation module lifts to 3D

The object is reconstructed in 3D space using learned features. This gives it depth and structure, not just pixel colors.

Apply parametric moves

Translation, rotation, and scaling happen in 3D coordinates, not on pixels. A 45-degree rotation means an exact 45-degree rotation around the 3D center.

Feed to a diffusion image generator

The original image, the moved object mask, and the transformed object appearance (from 3D) go into a diffusion model (a neural network that generates images by removing noise, one step at a time).

ESA focuses the model on lighting

A learned focusing mechanism biases the model to place shadows and highlights where they belong, given the new object position.

What the paper changes

What the paper changes

GeoEdit changes how the model generates the final image after a rotation, scaling, or sliding move. Instead of just rotating pixels and hoping shadows work out, it provides two concrete targets: the exact 3D-transformed object shape and appearance, and a learned focusing rule that knows how light behaves near objects. This gives the diffusion model two clear signals to follow, rather than leaving it to guess.

the object it moves  =  geometric guidance + learned focus masks
The hidden quantity

The hidden quantity: attention focus

measured quantity  =  Attention bias toward light-affected regions

Attention is a mechanism where the model's neurons look at different parts of the image to decide what to generate next. In standard attention, every part of the image can look at every other part equally. Effects-Sensitive Attention (ESA) does something different: it biases the model to look harder at regions where lighting and shadows matter, while still allowing the rest of the image to be considered.

The paper measures this as a probability distribution over which tokens (small image patches) the model attends to. ESA learns to concentrate attention on the object and its surroundings, then lets the model generate realistic shadows and highlights there without losing information about the rest of the scene.

Why it works

Why it works: the causal chain

Here is the core insight: diffusion models (neural networks that generate images by removing noise iteratively) are very flexible—they can generate almost anything if you nudge them in the right direction. The nudges come from the input you provide (the original image, the object mask, hints about what should be there).

GeoEdit's mechanism has two parts. First, lifting to 3D gives the model exact knowledge of where the object should be and what it looks like after the move (rotation, scaling, or sliding). This removes guessing: the model knows the shape and location precisely. Second, Effects-Sensitive Attention steers the model to generate realistic lighting when generating the final image. ESA does this by modifying which parts of the image the neural network pays attention to—making it look harder at the moved object and its surroundings. The result: shadows and highlights follow the object to its new location, not staying in the original spot.

Why does this work better than just rotating pixels and adding shadows afterward? Because treating them as one unified task lets the model learn the link between object position and where shadows should fall. A 120,000-image training set gives the model countless examples of where shadows belong when an object is in different positions. The model internalizes that pattern—light hitting an object from the top-left will always cast a shadow toward the bottom-right, and that pattern holds regardless of whether the object is rotated or scaled. So when the 3D reconstruction and ESA work together, the generated shadows follow the new position naturally.

The equation: Effects-Sensitive Attention

First in words:

Attention bias = base attention scores plus a learned bias that up-weights tokens in lighting-sensitive regions, scaled by how much the model should trust the geometric cues.

Then the compact form:

attention(i,j) = softmax( q_i . k_j / sqrt(d) + lambda * bias_j )

Every symbol:

q_ithe query (what the model is looking for) at position i
k_jthe key (candidate information) at position j
dthe depth of the query vector (how many numbers are in it)
lambdaa learned strength parameter that controls how much the bias matters
bias_ja learned bias term that is high for object and shadow regions, low elsewhere
softmaxconverts raw scores into percentages that add up to 100%
A tiny worked example
Suppose the model is deciding where shadows belong. It considers two spots: the original photo location and the new object location. Both look plausible to the base model.
Without ESA: both spots get equal focus. The model has no reason to pick one; it might fail.
With ESA: bias_j is higher for the new location (0.5) than the old (0.1). lambda=2.0. The added boost = 2.0*0.5=1.0 vs 2.0*0.1=0.2. After converting to percentages, the new location gets 75% focus, the old gets 25%. The model now places shadows at the new spot.
The information about both spots exists; the focus boost steers the model toward the correct answer.

ESA does not forbid attention to the wrong place, but it makes the right place more attractive, guiding the diffusion process to generate lighting consistent with the moved object.

What can go wrong

What can go wrong

3D reconstruction fails on complex occlusions. If the object in the original photo is partially hidden behind something else, the 3D lift may not recover the full shape. The model then generates a plausible completion, which may not match reality.
Dataset bias limits realism. GeoEdit trains on 120,000 image pairs covering specific objects and scenes. A geometric edit involving an object type not in the training set may generate less realistic shadows, because the model has fewer examples to learn from.
Lighting model assumes stable global light. ESA works best when light comes from one direction or a few steady sources. In complex multi-source lighting (reflections off mirrors, indirect bounces), the attention bias may place shadows incorrectly.
Large geometric moves with shadows work correctly. For typical use cases (translating objects a few hundred pixels, rotating ±60 degrees, scaling ±30%), GeoEdit generates shadows and highlights that look photorealistic.
What a runnable demo should prove

What a runnable demo should prove

A demo starts with a photograph of an object on a surface (a mug, a toy, a book). The user specifies a geometric move: translate the object 100 pixels to the right and 50 pixels down, then rotate it 30 degrees counterclockwise. The demo shows the input image, draws the target mask at the new location, and displays the edited output. The key metric is whether the shadow and highlights have moved to the new location, not stayed in the original spot. A baseline (naive pixel rotation + post-hoc shadow blending) should show shadows in the wrong place. GeoEdit should show shadows that follow the object.

Shadow-geometry alignment = (shadow pixels within 20 pixels of new object mask) / (total shadow pixels). Higher means shadows are in the right place.

The demo must make it impossible to mistake: when the object moves, its shadow moves with it, and the new lighting looks natural.
