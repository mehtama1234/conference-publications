GeoEdit: Geometric Transformations in Image Editing

Edit images by moving, rotating, or scaling objects while keeping the lighting and shadows realistic, using a diffusion model trained on labeled transformations.

Paper explainersAll themesComputer Vision

Imagine you want to shift a person to the left in a photo, rotate a car, or make a building taller. Existing image editors either leave visible artifacts or make the lighting look fake. GeoEdit solves this by training a neural network on 120,000 carefully labeled examples where objects are transformed and re-lit realistically, teaching it to apply geometric changes while automatically fixing shadows and highlights.

Why geometric editing breaks

When you move an object in a photo—slide a person left, rotate a chair, stretch a window taller—the image has no idea how lighting should change. A shadow that fell on the left side now should fall elsewhere. Highlights on a rotated face shift direction. A stretched wall changes how light bounces off it.

A beginner tries: 'Just cut out the object, move it, and paste.' But now the lighting is frozen in place. The shadow stays where it was. The background looks cut and pasted because the light is all wrong. A fancier attempt: 'Blend the boundaries and add blur.' Still wrong, because blur cannot fix a shadow that is geometrically in the wrong place.

The core problem: Changing the position, angle, or size of an object means the light hitting it has changed, so shadows and highlights must move and reshape too—but image editors do not know this connection.

The algorithm as a flow

What it actually does

Take an original image and a geometric command

E.g., 'move the car left 50 pixels' or 'rotate the box 30 degrees.'

Encode both into lists of numbers

The image becomes small square patches; the command (like 'move right 50') becomes a list of numbers that tells the model what to do.

A neural network processes image and command together

It learns: if the object moved, its shadow must follow; if rotated, its highlights turn.

Special focus on lighting edges

The model uses special pathways that watch for lighting boundaries and preserve their realism.

Generate the edited image, lighting fixed

The model iteratively refines the output, each step keeping object position and lighting consistent.

What the paper changes

What the model learns to change

The paper changes how the diffusion model receives instructions. Instead of only seeing the original image, it also sees a geometric-command token—a single number or short list that encodes 'move object by X pixels' or 'rotate by Y degrees.' The model learns to treat this command as a hint: 'if the object moved, recalculate where its light comes from.'

The hidden quantity

The hidden quantity: Light-position alignment

measured quantity  =  Shadow-to-object-position consistency

The paper introduces a hidden quantity: how well the shadows and highlights align with the object's new position. In the original image, light rays hit the object at a certain angle. After a transformation, those rays should still appear to come from the same direction in the world—if the light source did not move.

The model estimates this by predicting the full new image and checking: does the shadow fall where the moved object says it should? A shadow 20 pixels to the left of the object, before moving, should be 20 pixels to the left after the object shifts. This alignment score guides training—high score means realistic lighting.

Why it works

Why it works: feed both image and command

The core insight: if you tell the model 'translate the object right by 120 pixels,' and you show it examples where this always caused the shadow to move right by 120 pixels too, the model learns the association. It is not magic—it is memorization of a pattern in the training data: object moves, light moves, shadows follow.

But why is that enough? Because diffusion models are extremely good at pattern-matching from images. When you show them 120,000 examples of 'before and after' pairs, labelled with the exact geometric change, the model's attention heads learn to watch for boundaries (where shadow meets lit areas) and predict how they shift. The Effects-Sensitive Attention layer is a special set of attention heads trained to focus on these lighting edges. When the model sees the command token, it activates these heads more strongly, so they have more influence on the output.

The loss function that teaches consistency

First in words:

loss_total = image_loss + lambda_geo * geometric_loss + lambda_light * light_loss

Then the compact form:

L = L_recon(I_pred, I_target) + lambda_g * L_geo(T_obj_pred, T_obj_target) + lambda_l * L_light(L_pred, L_target)

Every symbol:

I_predthe diffusion model's predicted output image
I_targetthe ground truth edited image from the dataset
L_reconpixel-by-pixel difference between predicted and target
T_obj_predmodel's predicted new position/angle/scale of the object
T_obj_targetthe true transformation applied (from the command token)
L_geohow much the predicted geometry drifts from the true command
L_predmodel's predicted lighting (shadow positions, highlight colors)
L_targetground truth lighting after the real transformation
L_lighthow much the predicted lighting drifts from realistic
lambda_gweight: how much to penalize geometry mismatch (set high)
lambda_lweight: how much to penalize unrealistic lighting (set high)
A tiny worked example
Suppose the command is 'translate object 50 pixels right.'
Model predicts the object moved 48 pixels right: L_geo = (50 - 48)^2 = 4 pixels penalty.
Model predicts shadow at pixel 310, but true shadow at pixel 300: L_light = (310 - 300)^2 = 100 pixels penalty.
Pixel-by-pixel loss: 50 (just an example number, not real).
lambda_g = 10, lambda_l = 5 (these weights make object position and light both matter).
Total loss = 50 + 10*4 + 5*100 = 50 + 40 + 500 = 590.
If next try: object position 49.9 and shadow 300.1, loss = 50 + 10*(0.1)^2 + 5*(0.1)^2 = 50 + 0.1 + 0.05 = 50.15 (much better).
The large lambda_l keeps the model from ignoring shadow fidelity.

The loss pulls the model toward predicting both correct object positions and realistic lighting by penalizing mismatches in both separately.

What can go wrong

What can go wrong

Extreme transformations break the pattern. If you try to rotate an object 180 degrees, the training data may not have many examples of such extreme rotations. The model was only shown rotations up to, say, 45 degrees. Asking for 180 degrees is extrapolation, and the model will guess poorly.
Multiple light sources confuse the model. The paper assumes one main light source (sun, or one studio light). Real scenes with two or three lights, or complex reflections off mirrors, overwhelm the learned pattern. The model was not trained on those.
Occlusion changes are invisible. If you move an object and it uncovers a hidden wall, the wall has aged and changed texture. The model cannot invent what was hidden. It can only inpaint, not predict invisible surfaces.
Done right: objects transform within their training range. Move, rotate, or scale objects by amounts and into scenes similar to the 120,000 training pairs. Stay in the learned regime.
What a runnable demo should prove

What a runnable demo should prove

Build a minimal editor: load a simple image (a person in a sunlit room, or a box on a table), define a geometric transformation (translate 100 pixels right, or rotate 20 degrees), run the model, and display the result side-by-side with the naive cut-paste baseline. Measure the shadow position: in the baseline, is it glued to the original spot? In GeoEdit, does it move with the object?
