ParoQuant: Rotate Weights to Compress Reasoning Models for Fast Answers

Reasoning models stay accurate at low precision by rotating weight groups so all numbers have similar sizes before compression.

Paper explainersAll themesLLMs & Foundation Models

Large reasoning models are huge and slow. To run them quickly, you compress weights (which are the numbers the model has learned) by storing them with fewer bits of information. The problem: some weights are 1000 times bigger than others, so when you force them all into the same number of bins, tiny weights disappear and huge ones still take up half the space. Errors add up across a chain of 100 reasoning steps. ParoQuant solves this by rotating pairs of weights (a mathematical tweak that keeps the model's answers the same but spreads the weight sizes evenly), then compressing. With tricks to make the rotation fast on graphics chips and smart code, it stays nearly as quick as simpler methods while keeping answers right.

Zero assumption version

Squeezing weights breaks when sizes are wild

Reasoning models have weights (learned numbers) that vary crazily in size. A beginner would compress all of them the same way: divide the range from smallest to biggest into equal steps. But if some weights are 1000 times bigger, tiny weights disappear and big ones still waste space. Each step of reasoning reads from the previous step, so a small error in step 1 becomes biased input to step 2, which adds its own error. After 100 steps, errors explode.

The compression is called quantization. Naive quantization treats all weights equally, which ruins accuracy on long reasoning chains.

The trap. Compress naively and small weights vanish; run 100 reasoning steps and errors pile up.

What the paper changes

What the method changes

The paper rotates pairs of weights before compression. Each rotation is a mathematical tweak that spins two weights without changing the model's final answer. These rotations flatten the wild size differences so all weights end up in the same ballpark.

The hidden quantity

Size spread: the hidden problem

measured quantity  =  size spread (biggest weight divided by smallest)

Size spread is how much bigger the largest weight is than the smallest. If it is 1000 to 1, compression wastes bins on huge outliers and squashes tiny weights to zero. ParoQuant measures this in each group (weights that feed one output) and shrinks it.

The paper finds the biggest and smallest weight in each group, then designs rotations to make them closer together before compression.

Why it works

Why flattening stops errors from piling up

Compression divides a range into bins. If weights span 0 to 100 using 16 bins, each bin is width 6.25. A weight at 95 lands in bin 15 with small error. But a weight at 1 falls between bins 0 and 1 and vanishes. Rotation spreads weights so they all land in the usable middle bins, where each bin measures a small difference.

In reasoning models, each layer reads output from the previous layer. A tiny compression error in layer 1 becomes wrong input to layer 2, which adds more error, spiraling. By evening out weight sizes first, ParoQuant keeps each layer's error tiny, so they don't pile up across 100 reasoning steps.

A tiny worked example
Group has 4 weights: 0.5, 2, 3, 80. Size spread is 80 divided by 0.5 = 160 to 1.
After rotation and scaling: 25, 26, 27, 28. Size spread now is 28 divided by 25 = 1.12 to 1.
Compress to 4-bit: 25, 26, 27, 28 round to bins 25, 26, 27, 28. Perfect.
Naive: compress 0.5, 2, 3, 80 with 16 bins. 0.5 goes to bin 0 and vanishes. 80 hits bin 15. Error huge.

Rotation keeps the model's math the same but reorganizes weights so compression spreads their bits fairly.

What can go wrong

What can go wrong

Rotation cost eats the speedup. If the graphics chip code doesn't merge rotation and decompression into one operation, rotation overhead cancels the speed gain. ParoQuant builds them together into one routine.
Scaling per group loses ties between groups. If weight groups are linked (one group's size depends on another), scaling each alone may hurt. Rare in practice on wide models.
New outliers appear if you retrain. If you adjust the compressed model more, new huge weights can grow, erasing the rotation benefit. Re-rotate before retraining.
Done right: rotation and fused code. Keeps running speed fast, keeps answers accurate, and works even after retraining when you rotate again.

What a runnable demo should prove
