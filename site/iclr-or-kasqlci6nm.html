EUBRL: Epistemic Uncertainty Directed Bayesian Reinforcement Learning

A learning agent uses its own uncertainty about the world to decide when to explore, achieving optimal exploration without hand-tuned bonuses.

Paper explainersAll themesReinforcement Learning

In reinforcement learning, an agent must choose between exploring new actions (to learn more) and exploiting actions it already knows work well. This explore-exploit trade-off is fundamental. EUBRL solves it by measuring epistemic uncertainty—the agent's systematic confusion about how the world works—and using that confusion as a built-in guide for when to explore. The result: provably optimal learning with fewer attempts than older methods.

Zero assumption version

The explore-exploit dilemma without a compass

A learning agent in an unknown world must make a choice every step: try something new (explore) or do what worked before (exploit). Exploring wastes steps on bad actions. Exploiting misses better actions, because the agent's best estimate of an unseen action is biased by the few random tries it has made, and the real optimal path may lie in unexplored regions. A naive agent just picks randomly—it wastes half its steps. An agent with a preset bonus for exploring new things does better, but the bonus is hand-tuned per task and per world size, because the bonus strength must be matched to the size of the reward scale and the number of states—double the states and the same bonus is now too weak, making the agent stop exploring too early.

Older algorithms use optimism: they assume unknown actions are secretly the best. This inflates rewards for unexplored state-action pairs, forcing exploration. But this requires hand-crafted bonuses like RMAX (which assumes unknown actions give max reward) or MBIE-EB (which uses visit counts to set a bonus). These bonuses are brittle—they assume the world is structured in specific ways and break when the task structure changes.

In one sentence. EUBRL measures how confused the agent is about the world and uses that confusion directly to guide exploration, without needing hand-tuned bonuses.

The algorithm as a flow

What it actually does

Start with beliefs

Keep a collection of possible world models—different reward and transition rules that fit the data seen so far.

Measure confusion

Check how much the models disagree when predicting the value of an action. Big disagreement means high confusion.

Boost uncertain actions

Add confusion as a bonus to action value. Higher confusion gets bigger bonus. Agent naturally picks confused actions.

Act and learn

Take the boosted action, observe what happens, update beliefs with the new evidence.

Exploration fades

As data grows, confusion shrinks, bonus shrinks, agent switches to exploiting learned policy.

What the paper changes

What the paper changes

EUBRL changes how the agent weighs different actions at each step. Instead of adding a hand-tuned bonus for visiting new states (like RMAX or MBIE-EB), it computes epistemic uncertainty from the learned Bayesian beliefs and uses that uncertainty as the bonus. The bonus adapts automatically to what the agent knows; no tuning required across different environments.

the object it moves  =  action selection rule
The hidden quantity

Confusion: how much the agent does not know

measured quantity  =  Confusion (disagreement between learned models)

Confusion is a measure of how much the agent's learned models disagree when predicting the value of an action. When the agent has seen a state-action pair many times, all models agree—confusion is low. When it has barely visited, different models make wildly different predictions—confusion is high. This confusion about a state-action pair tells the agent exactly where to explore next.

EUBRL estimates confusion by comparing predictions across different world models the agent has learned. For each state-action pair, it samples several candidate models consistent with the data and checks their disagreement. Large disagreement means high confusion; small disagreement means the agent has pinned down the truth. The paper uses this confusion score directly as the exploration bonus, scaled by task rewards and world size so it works everywhere without re-tuning.

Why it works

Why confusion becomes the exploration signal

The core insight: the agent's confusion about a state-action pair is a perfect signal of where learning would help most, because disagreement between candidate models means the agent has not yet gathered enough evidence to pin down the true world—more visits to that state-action pair would resolve the disagreement and shrink the confusion, so confusion directly measures the information value of exploring. Confused regions are exactly where the agent's beliefs are weakest and where more data would improve predictions most. By boosting the value of confused actions, the algorithm naturally explores the frontier between the known and the unknown.

The value used to pick an action is its expected reward plus a bonus equal to the agent's confusion. The size of the bonus is scaled by task rewards and world size, so it works without per-task tuning. When the agent picks the action with the highest boosted value, it naturally tries confused actions. As data grows, confusion in well-explored regions shrinks, the bonus fades away, and the agent naturally switches to exploiting what it has learned.

Unlike preset-bonus methods that assume unknown actions are best, EUBRL simply measures what the agent actually does not know. It works with any kind of learned world model and does not break when task structure changes. The algorithm provably achieves near-optimal learning—no algorithm can do much better—because it explores exactly where it needs to and stops when it has learned enough.

Math after the picture

The value formula with confusion bonus

First in words:

value of action equals expected reward plus a scaling factor times the confusion

Then the compact form:

V_t(s, a) = Q_t(s, a) + c * U_t(s, a); Per-step regret = V_star(s) - V_pi(s, a_t)

Every symbol:

V_t(s, a)value used to choose actions at time t
Q_t(s, a)expected reward for action a in state s based on observed data
U_t(s, a)confusion: how much the learned models disagree on this action
cscaling factor proportional to max reward and world size (one number, works everywhere)
V_star(s)true best value of state s
V_pi(s, a_t)value of action actually chosen
A tiny worked example
Action a visited 20 times: expected reward 8.0, confusion 0.2. With scaling 1: value = 8.0 + 1 * 0.2 = 8.2.
Action b visited 2 times: expected reward 6.0, confusion 2.5. With scaling 1: value = 6.0 + 1 * 2.5 = 8.5.
Despite lower reward, action b is chosen because confusion bonus outweighs. Once b is explored, confusion shrinks, value drops.
If best value is 9.0: cost of picking a = 9.0 - 8.0 = 1.0; cost of picking b = 9.0 - 6.0 = 3.0.

Confusion naturally shrinks as the agent visits a state-action pair more, making the bonus fade away and shifting the agent from exploration to exploitation.

What can go wrong

What can go wrong

Learned models do not capture the true world. If the model class is too rigid and cannot represent the real world, the confusion will be artificially small. The agent stops exploring when it should keep going. Fix: use flexible models like neural networks that can fit many different worlds.
One lucky visit looks like understanding. If the agent visits a state-action pair once by chance and sees a good reward, confusion drops even though it has only seen one example. The agent may think it understands when it is guessing. Fix: require multiple visits before trusting low confusion—the paper uses a doubling rule to ensure real coverage, not luck.
Scaling factor must fit the problem. If the bonus scaling is too weak, confusion bonuses have no effect and exploration stays random. If scaling is too strong, the agent explores forever and never learns anything. The paper scales by reward size and world size. Very different problem types may need adjustment.
Done right: automatic, principled exploration. If the models are flexible, scaling is correct, and the stopping rule is principled, EUBRL explores exactly where confused and stops when confident. Learning speed matches theoretical best-possible bounds.
What a runnable demo should prove

What a runnable demo should prove

Build a simple episodic task: a chain of 10 states, 2 actions per state (left or right), reward only at the end. The best policy is deterministic (e.g. always go right). Run EUBRL, RMAX, and random exploration for 500 steps. Measure: (1) average cost per step (how far from best value, on average); (2) steps until the learned policy is correct; (3) consistency across runs (does it reliably find the best policy or sometimes get stuck?).

Cost per step = (Sum of losses over all steps) / total steps; loss at step t = (best value now - actual value now)

Key result: EUBRL learns faster than random because it uses real confusion (disagreement of learned models) instead of guessing when to explore, works without hand-tuned numbers that break on other tasks (because confusion automatically scales to the problem size—more states means more candidate models and more disagreement, which naturally increases the bonus), and stays consistent across different chain lengths and reward sizes. Same one scaling factor works everywhere.
