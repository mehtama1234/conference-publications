Planning with an Embodied Learnable Memory

A robot remembers its surroundings as text, updated by what its cameras see, to plan multi-step tasks in large cluttered spaces.

A robot moving through a house and picking up objects must remember which rooms it has seen, where things are, and how the world has changed. This paper builds a memory system — a textual snapshot of the scene — that a robot can read, update, and use to decide its next move.

Zero assumption version

Robots forget in large, changing spaces

A robot must remember what it has seen and where objects are, then plan a sequence of moves to reach a goal — picking up a cup, moving to the table, and placing it down. In a multi-room house where objects move during the task, the robot faces a problem: its memory must track changes over time and tell the planner what the scene looks like from different positions.

A beginner's approach is to store raw camera images or simple lists of object names and positions. This breaks because images are huge and hard to compare across viewing angles; a list of objects freezes when someone moves the cup while the robot is in a different room; and the planner cannot update its mental model as it navigates and learns new facts.

The core issue is that memory must be both persistent (remembering old facts) and updatable (absorbing new observations) while staying small enough to run on a robot and simple enough for a planner to use.

In one sentence. The paper replaces fixed object lists with a textual memory that a vision-language model reads and updates with each camera frame.

The algorithm as a flow

What it actually does

Read the camera

Robot sees the room from its current position.

Talk to the memory

Vision-language model translates pixels into natural language describing what it sees.

Update the memory

Textual memory absorbs new observations and records any object movements.

Plan the next move

Planner reads the text memory and decides the next action to reach the goal.

Learn from mistakes

Robot is trained with human-written trajectories and a new reward signal that rewards exploring hard decisions.

What the paper changes

What the paper changes

The paper replaces the memory representation itself. Instead of storing object positions as frozen coordinates or snapshots of raw images, it stores a text description of the scene that is actively maintained and can change.

the object it moves  =  memory representation
The hidden quantity

The quantity that matters: which memories matter for the decision

measured quantity  =  memory relevance

Not every detail in memory matters equally for the next action. When the planner must reach a cup, the location of the cup matters deeply; the color of the wall does not. This paper measures memory relevance: which parts of the textual description actually steer the decision.

The paper does not explicitly score relevance, but the planner learns implicitly which facts lead to successful actions. During training, the planner discovers that facts about nearby objects and recent changes matter more than distant or static details. This happens because the training reward only increases when the planner acts correctly, so over time it learns to attend to relevant passages in memory.

Paper reading. The memory is integrated into the planner via a unified vision-language model. As the planner practices tasks, the weights (numbers inside the model) are nudged to make decisions that succeed, so over time the model learns which textual facts matter for each decision.
Why it works

Why textual memory works: concrete steps

Text is expressive and updatable. When the robot sees the cup move, it writes that change into the memory as new text. When the planner reads the memory before deciding, it sees the current truth, not an old assumption. Text is also natural for a language model: the model that maintains the memory has already learned to read and write English in its training, so it translates visual changes into text efficiently.

A second mechanism: the memory is trained with two complementary methods. First, imitation learning from human demonstrations shows the planner how humans naturally explore and interact with objects, giving the planner a head start. Second, a new reinforcement learning technique called Dynamic Difficulty-Aware Fine-Tuning teaches the planner to handle situations where imitation alone is not enough. This technique gradually increases the difficulty of the exploration task: easy problems are solved, then harder decisions are practiced repeatedly until the planner learns them. This prevents the planner from forgetting early lessons while gaining new skills.

Math after the picture

The memory update rule

First in words:

updated memory equals old memory plus the newly observed facts, with conflicting positions replaced by the newest observation

Then the compact form:

M_new = merge(M_old, V(I_t)) where V is the vision-language model, I_t is the current camera frame, and merge updates positions if objects moved

Every symbol:

M_oldthe text description of the scene before this moment
M_newthe text description after seeing the new camera frame
I_tthe camera image at time t (now)
V(I_t)the text that the vision-language model writes from the image
mergethe operation that combines old and new text, letting new observations override positions
A tiny worked example
M_old contains: 'Cup on shelf in kitchen, notebook on table'
Camera sees: 'Person holding cup, notebook on table'
V(I_t) = 'Person holding cup, notebook on table'
merge finds conflict: cup was on shelf, now person holds it
M_new = 'Person holding cup in kitchen, notebook on table' (cup position updated)

The memory stays small (just text) while always showing the current truth, because merge replaces old facts, not appends them.

What can go wrong

What can go wrong

Memory grows if updates stack without pruning. If the merge operation appends new observations instead of replacing conflicting old ones, the memory text grows without bound. A vision-language model trained on modest text will choke on huge contexts.
Camera noise or poor vision breaks the memory. If the camera is noisy or the vision model mistakes a shadow for an object, the memory writes false facts. The planner then acts on false beliefs. The paper does not address how to detect or correct these errors.
Imitation alone is not enough. A human may solve a task by lucky timing or by knowing a shortcut the robot has not seen. If the robot only learns by imitating, it may miss better strategies and fail when situations differ from the training demos.
Done right. The paper mitigates the imitation gap by adding reinforcement learning with dynamic difficulty scaling, ensuring the robot practices hard cases repeatedly and does not forget easy ones. The memory is kept compact by merging, not appending.
What a runnable demo should prove

What a runnable demo should prove

A real demo should show three things: first, that the textual memory correctly captures object positions when they change (print the memory as it updates), because this proves the core mechanism works — the memory absorbs new observations; second, that the planner uses the memory to make better decisions than a planner without it (compare success rates on the same task), because a planner that can see updated facts should solve tasks more often; third, that dynamic difficulty training helps — show the planner learning easy steps first, then harder ones, without forgetting the easy ones, because this proves the training method teaches new skills while keeping old knowledge intact.

success rate = number of goal objects picked up and placed correctly / total number of goals attempted

The demo should make it unmistakable that a memory that updates beats a frozen one: when an object moves, the updated memory shows the new position, and the planner goes to it; a frozen memory points to the old position, and the planner fails.
