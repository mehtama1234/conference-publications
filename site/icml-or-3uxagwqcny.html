CompleteP for RL: Scaling Without Losing What Matters

When you make a learning machine bigger, use CompleteP (a way to scale the learning speed) to keep the learning process stable and the learned features consistent.

Paper explainersAll themesOptimization

When training deep reinforcement learning agents (machines that learn by trial and error), making them bigger sometimes backfires: the learning becomes chaotic, learned patterns shift unexpectedly, and what works for a small agent fails for a large one. This paper shows that CompleteP, a method for scaling the learning step size as the model grows, preserves stable learning and keeps the same hyperparameters working across model sizes.

Why Bigger Models Break Learning

When you train a machine to make decisions in an environment (like a robot learning to grab objects), you nudge the model's internal numbers (called weights) by a fixed amount each time you see a mistake. As the model grows from 1 million to 100 million weights, the same nudge size causes all kinds of trouble: the learning becomes unpredictable, the learned behaviors shift erratically, and a learning speed that worked perfectly for the small model fails utterly for the large one.

A beginner might try to just double the nudge size along with the model size, but this backfires too: the learning overshoots, the model thrashes around randomly, or stops learning altogether. The core problem is that as the model gets wider (more weights doing the same job in parallel), their collective effect on the model's behavior grows, but no one adjusts for it.

In one sentence. CompleteP scales the learning step size carefully so that when the model grows, the learning process stays smooth, learned patterns stay consistent, and the same learning speed works for big and small models alike.

What the paper changes

What changes: the learning step size

CompleteP changes one specific thing: the size of each learning nudge as the model grows. Instead of keeping it fixed or blindly scaling it up, CompleteP scales it down proportionally to the square root of the model width. This single change ripples through everything: how fast learning converges, which features the model learns, and whether the policy (the learned decision-making behavior) stays consistent.

The hidden quantity

The hidden quantity: feature consistency

measured quantity  =  Feature consistency across scales

Feature consistency is a hidden quantity: how much do the internal learned patterns (the mid-layer features that represent concepts the model discovers) shift when you change the model size? In the small model, the model might learn that 'edge-direction' is useful; in the big model with naive scaling, it might learn 'color-blob' instead. CompleteP keeps the model learning the same features even as it grows, which means the learned behavior generalizes more smoothly.

The paper estimates feature consistency by measuring how similar the learned features are across model sizes, and by tracking how policy rewards stay consistent. Models trained with CompleteP show high feature overlap (the learned concepts are the same), while models trained with the NTK lazy approach drift and learn different internal representations.

Why it works

Why it works: balance between learning speed and model size

When a layer has N parallel weights all learning from the same training signal, they combine to amplify the effect: collectively they push the model N times harder than a single weight alone. CompleteP counteracts this by dividing the learning step by the square root of N. This maintains a constant effective learning speed across model sizes.

The deeper reason: in reinforcement learning, the data distribution changes as the agent learns (it explores different states, discovers new mistakes). Under this moving target, CompleteP preserves two critical things. First, the directional nudges (which way each weight should move) stay consistent across sizes, so the model learns the same internal features regardless of width; this matters because if a small model learns to recognize 'useful action types' and a large model learns 'raw pixel colors' instead, they will behave completely differently even if both have high reward. Second, the effective learning trajectory (the path through learning space) remains stable, so training is predictable and hyperparameters do not need tuning for every new model size.

Math after the picture

The scaling law: learning step shrinks with model width

First in words:

learning_step = base_step / sqrt(layer_width)

Then the compact form:

alpha_i = alpha_0 / sqrt(N_i)

Every symbol:

alpha_ilearning step size for layer i
alpha_0base learning step (the starting value you pick)
N_inumber of weights in layer i
sqrt()square root
A tiny worked example
Layer with 64 weights, base learning step 0.01: actual step = 0.01 / sqrt(64) = 0.01 / 8 = 0.00125
Same layer expanded to 256 weights: actual step = 0.01 / sqrt(256) = 0.01 / 16 = 0.000625
Quadrupling width halves the step, exactly as intended: amplified collective effect is cancelled out.

The square root relationship means that the collective learning effect of many parallel weights stays constant even as the model grows, keeping the learning process stable and predictable.

What can go wrong

What can go wrong

Learning too slow. If the base learning step is set too conservatively, CompleteP shrinks it further, and the model barely learns anything. You must tune the base step for the model family, not randomly guess it.
Changing environment mid-training. CompleteP assumes the scaling relationship holds throughout training. If the task changes (the reward structure shifts), or if the agent's exploration strategy changes dramatically, the scaling law may break down.
Mixing model sizes unfairly. If you transfer hyperparameters from a small model to a large one, both must be trained with CompleteP for the transfer to work. Mixing CompleteP and naive scaling across sizes causes erratic behavior.
Done right. Choose the base learning step once for your model family, apply CompleteP to all sizes, and hyperparameters transfer cleanly without retuning.
What a runnable demo should prove

What a runnable demo should prove

Build a simple control task (like a pendulum or cartpole that learns to swing upright). Train agents with CompleteP and without (NTK parameterization) at two sizes: 2 hidden layers of 64 units (small) and 2 hidden layers of 256 units (large). Use the same hyperparameters for both, and report: (1) final reward achieved, (2) how similar the learned features are across sizes (measure the cosine similarity of hidden layer activations), and (3) how smoothly the learning curve progresses (how much it oscillates).

feature_consistency = mean(cosine_similarity(small_features, large_features)); reward_transfer = reward_large / reward_small

The key observation: CompleteP achieves feature consistency > 0.8 and reward transfer > 0.95, meaning the learned behavior and internal patterns are nearly identical across sizes. NTK parameterization shows feature consistency < 0.5 and reward transfer < 0.7, proving that learning diverges.
