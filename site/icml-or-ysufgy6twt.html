What Information Matters? Graph Out-of-Distribution Detection via Tri-Component Information Decomposition

Separate which parts of a graph neural network's knowledge come from real patterns versus spurious signals, to detect nodes from a different data distribution.

Paper explainersAll themesGraph & Geometric Learning

Graph neural networks can classify nodes (like identifying which users are suspicious in a social network) by looking at node features and the connections between nodes. But a real-world graph often changes its rules: a model trained on one set of users might fail when applied to a different country's network where the patterns are different. This paper proposes TIDE, which splits all the information the network has learned into three types: information specific to node features alone, information specific to the graph structure alone, and information that combines both. By keeping only the joint information that is truly useful and discarding the feature-specific and structure-specific information that looks helpful but is actually misleading, TIDE makes the model detect when it sees a fundamentally different graph.

Zero assumption version

Graph models break when the graph changes rules

A graph neural network learns patterns from training data, where each node has features (a list of numbers describing the node, such as a user's profile) and connections (edges showing which nodes link to each other, such as friendships). The network learns to classify nodes by using both sources of information. But in the real world, the rules change. A model trained to detect fraud on an American banking network might fail in a European network where transaction patterns are different. Or a model trained on one social network might misclassify users on a different social network where friendships correlate with different traits. The model is not wrong because it was poorly trained—it is wrong because it learned to use patterns that only existed in the training data.

A beginner might try this: just train a standard graph neural network and hope it generalizes. But that does not work. Standard training encourages the network to find any signal—from features, from the graph structure, or from both combined—as long as it predicts the training data correctly. Some of that signal is real (true patterns that hold everywhere), but some is spurious (false patterns unique to the training data). When the test data comes from a different distribution (a different graph with different rules), the spurious signals vanish and the model's accuracy collapses.

In one sentence. TIDE separates useful information from misleading information by decomposing learned knowledge into three independent parts and keeping only the reliable joint component.

The algorithm as a flow

What it actually does

1. Train three separate branches

Create three neural networks in parallel: one that sees only node features, one that sees only graph structure, one that sees both.

2. Measure information overlap

Compute how much information is redundant (shared by multiple branches) versus unique to just one branch.

3. Use information bottleneck objective

Compress the knowledge down to only the smallest amount that predicts labels correctly, removing room for spurious signals.

4. Discard feature-specific and structure-specific components

Throw away the information that comes from features alone or structure alone; keep only the joint component from both.

5. Measure detection confidence

Compare prediction certainty (entropy) on new nodes to the training distribution. High entropy means out-of-distribution.

What the paper changes

What the paper changes

TIDE changes which information the model learns to use for prediction. Instead of a single neural network that mixes feature signals, structure signals, and their combinations, TIDE uses three separate branches (one for features only, one for structure only, one for both) and then discards the feature-only and structure-only predictions. Only the joint information—the part that depends on both features and structure together—is kept for detecting out-of-distribution nodes. This is enforced by an information bottleneck objective (a training technique that forces the network to compress its knowledge), which penalizes keeping any information beyond what is minimally necessary to predict training labels correctly.

The hidden quantity

The hidden quantity: entropy gap between distributions

measured quantity  =  Entropy gap: how much more uncertain the model is on out-of-distribution data

Entropy is a measurement of uncertainty. When a model is very confident in its prediction (95% sure a node is fraudulent and 5% sure it is legitimate), the entropy is low. When a model is confused (40% sure it is fraudulent and 60% sure it is legitimate), the entropy is high. TIDE tracks the difference in entropy between nodes from the training distribution (in-distribution, or ID) and nodes from a new, different distribution (out-of-distribution, or OOD). If in-distribution nodes have low entropy (the model is confident) and out-of-distribution nodes have high entropy (the model is confused), the entropy gap is large. A large gap makes it easy to spot when the model is seeing a new kind of graph because a simple threshold on entropy (such as 'flag any node with entropy above 0.8 as OOD') becomes reliable—most ID nodes fall below it and most OOD nodes fall above it.

The paper estimates this gap by running the trained model on both ID and OOD test sets and computing the average entropy of its predictions. By using only the joint component (discarding the spurious feature-only and structure-only signals), the information bottleneck objective naturally makes ID predictions low-entropy and OOD predictions high-entropy, widening the gap. This is because spurious signals happen to fit the ID distribution but mislead the model into false confidence on OOD data; removing them removes false confidence and exposes genuine confusion.

Why it works

Why it works: throw away the misleading parts

A standard graph neural network learns from both features and structure. Some of what it learns is truly predictive—patterns that hold in both the training graph and new graphs. Some is spurious—patterns unique to the training graph that disappear on new data. The network cannot tell the difference because both types of patterns reduce training error equally. TIDE solves this by separating the learning problem into three independent tasks, each with its own neural network: predict from features alone, predict from structure alone, predict from both combined. The three predictions compete for accuracy on the training data.

Next, TIDE applies an information bottleneck objective (a training constraint that forces the network to compress its predictions to the minimum information necessary). This objective is applied only to the joint component—the prediction based on both features and structure together. The bottleneck squeezes out all the extra information that the network learned for the sake of training accuracy but is not needed for real prediction. For in-distribution nodes (the kind seen during training), the network can still be confident because the real patterns remain. For out-of-distribution nodes (a new graph with different rules), the network loses access to the spurious signals it relied on and becomes uncertain. The feature-specific and structure-specific predictions are discarded entirely—they are used only to measure information redundancy during training, not for actual detection. By keeping only the joint bottlenecked component, TIDE ensures that the model stays confident where real patterns hold (ID) and becomes uncertain where they do not (OOD).

Math after the picture

The information bottleneck objective

First in words:

Minimize prediction loss plus penalty for information kept, where information is the mutual dependency between predictions and training data

Then the compact form:

loss = L_predict + beta * I(joint_pred; train_data)

Every symbol:

L_predictStandard classification loss (error on training labels)
betaTrade-off parameter controlling how much to compress information
I(joint_pred; train_data)Mutual information: how much the prediction depends on training data
joint_predThe prediction from the joint (features and structure) branch
A tiny worked example
Suppose a standard network on training data gets L_predict = 0.3 (good accuracy) but depends heavily on training data, with I(pred; train_data) = 2.5 bits (a lot of stored information).
With information bottleneck at beta=0.5, the objective becomes: 0.3 + 0.5 * 2.5 = 0.3 + 1.25 = 1.55 (penalty added).
Training then compresses the joint branch: if it achieves L_predict = 0.35 (slightly worse) but I(pred; train_data) = 1.0 bit (much less information), the objective becomes: 0.35 + 0.5 * 1.0 = 0.85 (better overall, so training moves this direction).
The compressed model is now less dependent on the specific training graph. On a new OOD graph, it loses the spurious patterns (high information dependency did not survive), so entropy rises.

The bottleneck forces the model to keep only the information genuinely needed to predict, discarding the spurious signals that bloat information without helping real patterns.

What can go wrong

What can go wrong

Features and structure are not redundant. If node features and graph connections carry completely independent information with no overlap, then the tri-component decomposition gains nothing. Features alone might be highly predictive, structure alone might be highly predictive, and the joint component is weak. Discarding the feature-only and structure-only branches removes useful signals, and accuracy drops on both ID and OOD.
Information bottleneck is too strong. If beta (the bottleneck strength) is set too high, the model compresses so much that it loses real patterns, not just spurious ones. Then accuracy on in-distribution data drops below any baseline, making the model useless even at its original task.
Test distribution is not truly out-of-distribution. If the OOD test set is actually very similar to the training set (same graph with small noise), the model will have high entropy on it anyway because the bottleneck discards some real information. Then false positive rate stays high and the method appears to have failed, when it is actually working as designed.
Done right. When features and structure are somewhat redundant (both contribute, but some information overlaps), and beta is tuned to the problem, TIDE keeps real patterns and discards spurious ones. The model is confident on ID and uncertain on OOD, making out-of-distribution detection sharp and reliable.
What a runnable demo should prove

What a runnable demo should prove

A minimal demo trains TIDE on one graph dataset (such as detecting fraudulent transactions on one bank's network), then tests it on two scenarios: nodes from the same graph (in-distribution) and nodes from a different, structurally different graph (out-of-distribution). It should measure two metrics: accuracy (percentage of correct predictions on both ID and OOD) and the entropy gap (average entropy on OOD minus average entropy on ID). The demo should include a comparison bar chart showing that standard graph neural networks are confident on both ID and OOD (low entropy gap), while TIDE is confident only on ID and uncertain on OOD (high entropy gap). Code should train the three branches with an information bottleneck objective, run predictions on both test sets (when the finished model answers questions about new nodes), compute entropies, and report both accuracy and entropy gap. A second test case with a different pair of graphs validates that the behavior is not dataset-specific.

entropy_gap = mean_entropy(OOD_predictions) - mean_entropy(ID_predictions)

A successful demo makes clear: TIDE trades a small drop in in-distribution accuracy for a massive gain in detecting when the graph has fundamentally changed, and that trade-off is visible in both accuracy numbers and entropy separation.
