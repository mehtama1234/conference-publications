LatentQA: Decoding Activations Into Natural Language

Instead of probes that output single numbers or words, teach a small language model to answer open-ended questions about what activations inside a large model are doing.

Paper explainersAll themesInterpretability

Language models work like black boxes: their weights and activations (the numerical values flowing through layers) are invisible to us. Researchers try to peek inside by training small probes that read the activations and output a guess about what the model is thinking. But traditional probes output only single numbers or single tokens, which is like asking a witness to a crime to answer everything with just yes or no. This method trains a small language model decoder that can write full natural-language sentences in response to activations, so it can answer detailed questions like what relational knowledge the model holds or what hidden instructions it is following.

Zero assumption version

The limits of single-answer probes

When a large language model (a neural network trained to predict the next word) reads a prompt and produces text, billions of numbers flow through its layers. Each layer computes activations: intermediate values that represent what the model currently believes about the input. To understand what these numbers mean, researchers train small classifier models called probes. A typical probe takes an activation (a list of numbers) and outputs a single number from 0 to 1, or a single token like yes or no.

This one-answer bottleneck is like asking someone to report everything they know about a person's identity using only the word yes, no, or a number. Probes cannot capture nuanced information: Is the model thinking about a specific relationship? Is it following a hidden instruction? What does it actually know? Asking yes/no forces researchers to pre-decide every question, and to train a separate probe for each question.

A beginner might say: just make the probe output more categories. But that still bottlenecks the probe to discrete buckets. The real solution is to let the probe speak in full natural language.

The method in one sentence. Train a small language model decoder that reads activations and outputs free-form natural language to answer open-ended questions about what those activations represent.

The algorithm as a flow

What it actually does

Step 1: Generate pseudo-labeled dataset

Automatically create activation-to-explanation pairs by running prompts through the large model and using the model's own outputs to label what each activation means.

Step 2: Train the decoder

Fine-tune a small language model on the pseudo-labeled dataset to learn: given this activation (a list of numbers), predict the question-answer pair that explains it.

Step 3: Test on known tasks

Evaluate the decoder on curated questions with known answers: can it uncover hidden system prompts or identify relational knowledge the model stored?

Step 4: Test steering

Modify activations according to the decoder's descriptions and observe whether the large model changes its behavior as predicted.

Step 5: Measure scaling

Verify that the decoder improves as the training dataset grows and the decoder model size grows, because more data and larger models mean the decoder sees more examples and can fit more patterns.

What the paper changes

What the paper changes

The paper replaces the single-output probe with a language-generation model that can emit multi-token natural-language strings. Instead of each activation producing one number or one label, each activation now produces a sentence or paragraph.

The hidden quantity

The hidden quantity: decoder fidelity

measured quantity  =  Activation-to-meaning coherence

The paper measures a hidden quantity: does the decoder's natural-language description actually correspond to what the activation is doing inside the model? This is called fidelity. If the decoder says the activation encodes relational knowledge, and you can test that claim by examining the model's behavior, then fidelity is high. If the decoder makes up plausible-sounding descriptions unrelated to the real computation, fidelity is low.

The paper estimates fidelity in two ways. First, it tests reading: on curated questions with known answers (Is there a hidden system prompt? What relationships does the model store?), does the decoder output the correct answer? Second, it tests steering: if you modify activations according to the decoder's description, does the model's behavior actually change in the predicted way? Fidelity is high if the decoder's descriptions align with what actually happens when you change the activations.

Why it works

Why it works: language models understand language

The core insight is that a language model trained on natural-language text has already learned what words mean and how they relate to concepts. So if you fine-tune a language model decoder on data mapping activations (lists of numbers) to natural-language explanations, the decoder inherits that linguistic knowledge. It can combine familiar words into new explanations, even for activations it never saw during training.

The pseudo-labeling strategy makes this work. Instead of manually writing descriptions for thousands of activations (impossible), the paper uses the large model itself to generate labels. For each activation, run multiple prompts through the model and record the outputs. Use these outputs to infer what the activation was computing. This labels the dataset cheaply and at scale. The decoder then learns the mapping from activations (lists of numbers) to language descriptions. Because language is so expressive, the decoder can answer many more questions than a traditional single-number probe, and it can generalize to new questions it was never explicitly trained on.

Why does steering work? If the decoder truly understands an activation, then the semantic meaning it assigns should be causally tied to how the model uses that activation. Modify the activation according to the decoder's description (e.g., increase it to make the model think more about relationships), and if the decoder understood correctly, the model's behavior shifts in the predicted direction. Steering success proves the decoder was not just pattern-matching but had grasped the real computation.

The objective: learn the activation-to-explanation mapping

First in words:

loss equals the sum over all activation-explanation pairs of the decoder's prediction error, weighted by how confident the pseudo-label is

Then the compact form:

L_total = sum_i w_i * loss(decoder(a_i), y_i) + lambda * regularization_term

Every symbol:

a_ithe i-th activation vector (a list of numbers)
y_ithe natural-language explanation for activation i
decoder(a_i)the explanation the decoder predicts from activation a_i
loss(pred, y_i)the cross-entropy loss: how far off the prediction is from the true explanation
w_ia weight indicating how confident the pseudo-label y_i is (high w if generated from strong signal, low w if weak)
lambdaa scaling factor controlling how much we penalize large model weights (to avoid overfitting)
A tiny worked example
Activation A has pseudo-label about knowledge, confidence w_A = 0.95. Decoder predicts wrong explanation. loss_A = 2.1. Weighted: 0.95 * 2.1 = 1.995.
Activation B has weak pseudo-label from noisy signal, w_B = 0.3. Decoder also wrong. loss_B = 2.0. Weighted: 0.3 * 2.0 = 0.6.
Total unweighted loss is similar (2.1 vs 2.0), but weighted loss penalizes error on high-confidence labels 3x more (1.995 vs 0.6). The decoder learns to focus on getting the activations with strong labels correct.

The weighted loss ensures the decoder focuses on activations with strong, reliable labels and tolerates mistakes on borderline cases.

What can go wrong

What can go wrong

Pseudo-label noise compounds. If the automatic labeling process (using the model's own outputs) is wrong, the decoder learns from false explanations. This is why the paper weights labels by confidence: high-confidence labels are used more during training.
Decoder hallucinates plausible-sounding text. A language model trained on natural text can generate fluent but false explanations. The decoder might describe an activation as storing knowledge when it actually stores something else or nothing related. Steering tests catch this: if the description is false, modifying activations according to it will not change the model's behavior as predicted.
Activations change across different inputs. An activation in the middle of a model is not static; it varies depending on the input prompt. The decoder must learn to handle this variation. If trained only on one type of prompt, it may fail on others.
Steering tests provide ground truth. The decoder's explanations are most trustworthy when validated by steering. If nudging an activation changes behavior as predicted, the explanation is real, not hallucinated. Papers in this space rely on this kind of mechanistic grounding.
What a runnable demo should prove

What a runnable demo should prove

Build a simplified version on a small language model (like a 1-billion-parameter model): train a decoder on a thousand activation-question pairs generated from a standard benchmark dataset. Then run three tests. First, on held-out activations with known answers (e.g., does the model know the capital of France?), measure how often the decoder's explanation is correct. Second, modify an activation based on the decoder's prediction and observe whether the model's behavior changes. Third, show that the decoder generalizes: it can answer questions it was never explicitly trained on, simply by using natural language to describe the activation.

Fidelity = (fraction of reading tasks correct) + (fraction of steering predictions that match observed behavior) / 2

A language-fluent decoder can express and combine concepts in ways a single-number probe cannot, because language is more expressive. If steering works, the decoder has not merely fit the data but has captured what the activation actually computes.
