LatentQA: Teaching LLMs to Decode Activations Into Natural Language

Instead of reading hidden numbers as single scalar values, teach a language model to read them and answer open-ended questions about what they mean.

Paper explainersAll themesInterpretability

Language models work by transforming words into invisible numbers as they process text. Most transparency tools try to understand these numbers by training tiny models that spit out a single number to describe them, like a yes/no vote. This paper proposes LatentQA: a much more expressive approach where a full language model learns to read those hidden numbers and answer natural language questions about them, like What bias is in this number? or How would the assistant respond if this number were different? This lets researchers ask any question about the same hidden number without retraining a new probe.

Zero assumption version

Probes see only one bit of each number

As a language model reads text, every layer transforms the input into a list of numbers. These hidden numbers carry all the semantic content: facts the model knows, grammatical structure, even biases it learned. Researchers want to peek inside and ask what these numbers represent.

The standard approach: train a small probe model that reads a hidden number from one layer and outputs a single scalar value (a score from 0 to 1, or a binary classification like is-this-biased-yes-or-no). This probe can answer only one predefined question per input. If you want to ask ten different questions about the same number, you need ten different probes, each learned from scratch. And many behaviors cannot be captured at all by a single number — they are multidimensional, contextual, hard to reduce.

The problem in one sentence. A single scalar output cannot express the full richness of what a hidden number means.

The algorithm as a flow

What it actually does

Generate a pseudo-labeled dataset.

Use a large language model (like GPT) to automatically generate synthetic triplets: a behavior to control, a text that triggers it, and question-answer pairs describing what is happening.

Extract real hidden numbers.

Run the target model on these trigger texts and record the actual hidden numbers from a middle layer (where representations are richest).

Train the decoder.

Take a copy of the target model, insert the recorded activation at layer 0 (giving it maximum steps to process the input), and train it to predict the answer to the question by only adjusting a small set of extra parameters (LoRA).

Read activations.

Given a new activation and a natural language question, feed both to the decoder and sample text from it to get an English explanation.

Steer activations.

Compute which direction to nudge the activation to increase the decoder's confidence in a desired answer, then push the activation that way to make the model exhibit new behaviors.

What the paper changes

What the paper changes

The object is the probe itself. Instead of a tiny scalar-output classifier, the paper uses a full language model decoder as the probe. This decoder can generate entire sentences, not just numbers, making it far more expressive.

the object it moves  =  The probe model
The hidden quantity

The hidden quantity: Activation semantics

measured quantity  =  Activation semantics

Activation semantics is the plain-English meaning of a hidden number. It answers: what concept, fact, or behavior does this number encode? For example, an activation might encode gender information, or a particular writing style, or knowledge about a specific person. The paper does not measure a single numerical score; instead, it measures whether the decoder can accurately and precisely describe in words what the activation represents.

The paper estimates activation semantics by training the decoder to answer natural language questions about what each activation means. It then validates the decoder's understanding in two ways: (1) on supervised reading tasks where the true answer is known (like identifying hidden system prompts), and (2) by checking whether steering the activation based on the decoder's output actually changes the model's behavior in the predicted way.

Why it works

Why the decoder understands activations

The mechanism works because the target model was already trained to process its own hidden numbers and convert them to English text. A copy of that same model, when trained to answer questions about inserted hidden numbers, can reuse that learned ability. The decoder sees a hidden number as input, processes it through many layers of its own learned machinery, and generates English text. Because the model's layers already know how to turn numbers into meaning, the decoder can learn the mapping quickly from a relatively small dataset.

Inserting the hidden number at layer 0 (the very start of the decoder) is essential because it gives the decoder the maximum number of processing steps to transform the abstract number into a coherent English sentence. Training the decoder with only small parameter updates (LoRA) ensures it learns the mapping without forgetting the understanding already embedded in the base model. The result is a read tool that can express much more than a scalar probe, because it uses all of the model's built-in machinery to convert numbers into language.

Training the decoder

First in words:

Cross-entropy loss for predicting answer from activation and question

Then the compact form:

Loss = -log P(answer | [Activation] + question; decoder_params)

Every symbol:

[Activation]The hidden number vector inserted at layer 0
questionThe natural language query about the activation
answerThe correct natural language response to the question
P(answer | ...)Probability the decoder assigns to generating the answer
decoder_paramsWeights of the decoder, mostly frozen except LoRA updates
A tiny worked example
Suppose the activation encodes gender bias. Question: Is this response biased? Expected answer: Yes, it uses gendered language.
On first training step, decoder predicts: 'Unlikely male bias.' Loss = -log(0.05) = 2.996 (very wrong, low probability).
After 100 steps of gradient descent, decoder predicts: 'Yes, it contains gendered language.' Loss = -log(0.92) = 0.083 (nearly correct, high probability).
Accumulated loss decreases: 2.996 -> 1.5 -> 0.5 -> 0.083. The decoder learned to map this activation pattern to the right answer.

The decoder minimizes its prediction error by learning which features of the activation correspond to which meanings in natural language, building a continuous mapping from hidden numbers to English words.

What can go wrong

What can go wrong

The decoder hallucinates answers. If the activation does not clearly encode a concept, the decoder may generate a plausible-sounding but false answer. The paper mitigates this by validating reading accuracy on supervised tasks with ground truth, but on open-ended questions the risk remains.
Layer mismatch breaks the mapping. If the source layer (where activations are read) and the decoder's insertion layer (where they are injected) represent semantics differently, the decoder must learn a large distribution shift, which hurts performance. Reading from middle layers and writing to layer 0 works well, but other combinations can fail.
Steering can overshoot and break the model. Nudging activations too far to steer behavior can push the model into regimes it never trained on, causing nonsensical outputs or crashes. Careful loss weighting and validation are needed.
Done right. When the decoder is trained on diverse, realistic pseudo-labeled data and validated on both reading and steering tasks with ground truth, it reliably maps activations to English meanings.
What a runnable demo should prove

What a runnable demo should prove

Build a small decoder on a 1-billion-parameter model trained on synthetic QA pairs. Use the decoder to answer three types of questions on fresh activations: (1) semantic reading (What concept does this activation encode?), (2) bias reading (Is there a harmful stereotype in this response?), and (3) steering (Nudge this activation to make the model say the opposite, and verify it works).

Reading accuracy = fraction of supervised questions answered correctly; Steering success = fraction of steer attempts where the model's output changed as predicted

The demo must show that the same decoder answers multiple different questions about the same activation without retraining, and that steering via the decoder's gradients actually changes model behavior. This proves the decoder has learned a genuine semantic mapping, not memorized patterns.
