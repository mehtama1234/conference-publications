Core idea

A good representation keeps the right information and drops the rest

A representation is useful when it keeps the differences the task needs, removes the differences that distract, and preserves the structure needed for later behavior.

Raw data is too large and too mixed. An image contains object, lighting, pose, background, texture, camera noise, text, and layout. A sentence contains meaning, syntax, speaker intent, style, exact strings, and accidental wording. A video contains appearance, motion, timing, state, camera view, and event phase. A patient record contains values, trends, visits, treatments, missingness, hospital artifacts, and disease process.

Representation learning is the attempt to turn that raw mixture into a smaller usable description. But the word "smaller" is not enough. A bad compression can be small because it threw away the truth. A good compression is controlled: it removes what the task can ignore and protects what the task must use.

raw data = useful signal + nuisance variation + noise + hidden structure good representation = useful signal kept + nuisance variation reduced + hidden structure preserved

Controlled compression

Compression is not deletion; it is choosing what differences survive

Every representation compresses. Even a huge dense vector is smaller and more selective than the full raw world. The important question is not whether information is lost. Information is always lost. The question is which information is lost and whether that loss is safe.

Safe compression removes variation that should not change the answer: lighting when recognizing an object, phrasing when retrieving a claim, background when identifying an animal, sensor noise when estimating state, or redundant tokens when language behavior stays the same. Unsafe compression removes distinctions that do change the answer: a drug character, a code operator, a small lesion, a graph bridge, a motion phase, a legal exception, or a rare retrieval feature.

KeepIdentity, syntax, causal state, task-relevant differences, exact strings, thresholds, timing, graph role, object boundary, motion state.
DropNoise, redundant wording, irrelevant background, accidental style, lighting variation, scanner artifacts, duplicate dimensions, unneeded token splits.
Preserve shapeClusters, paths, loops, hierarchy, timelines, neighborhoods, rare regions, relations, smooth trajectories.
TestRetrieval, OCR, copy fidelity, code execution, medical safety, graph transfer, video state tracking, robot control.
Units

The first compression decision is what counts as one thing

Granularity asks where meaning begins. A language model may use characters, subwords, tokens, phrases, or claims. A vision model may use pixels, patches, letters, regions, objects, or scenes. A video model may use frames, clips, events, phases, or trajectories. A graph model may use nodes, edges, neighborhoods, communities, or codebook entries.

The right unit is chosen by the use case. OCR needs small visual marks. Object recognition can use larger regions. Code needs exact syntax units and larger function-level units. Medicine needs exact strings for drugs and genes, but also visit-level and trajectory-level units. Retrieval needs units narrow enough to avoid false matches and broad enough to contain the answer.

bad unit: the model must rebuild meaning from fragments or cannot see the distinction because it was merged good unit: small enough to compose large enough to be stable exact enough for the task
Form

Some representations need boundaries; others need smooth change

Discrete representations are right when boundary is meaning. A token is this symbol, not that one. A code keyword either parses or it does not. A drug name, patient id, legal citation, graph code, or class label may need a sharp identity.

Continuous representations are right when the fact changes gradually. Pose, motion, uncertainty, patient state, viewpoint, time, and physical control often need smooth spaces, paths, fields, or functions. A robot arm should not jump between disconnected waypoints if the real action is smooth.

Most strong systems use both. Language has discrete tokens and continuous embeddings. Robotics may use discrete instruction units and continuous motion. Video has frames as input but behavior as a trajectory. Retrieval may use sparse active dimensions but still form a larger similarity geometry.

Training pressure

The training task decides what the unit learns to carry

A unit does not become meaningful because it exists. It becomes meaningful because training punishes the wrong information and rewards the useful information. Masking asks the visible context to recover what is missing. Contrast asks the model to decide what counts as same and different. Teacher-student learning gives a stable target. Bottlenecks force a short message. Reconstruction keeps detail. Prediction forces state. Collapse prevention keeps units from becoming identical.

Breadth and depth matter here. Breadth exposes many variations so the model does not overfit to one narrow world. Depth makes the task hard enough that cheap cues fail. The strongest training tasks are broad enough to avoid narrow shortcuts and deep enough to require real structure.

training pressure = mask, compare, imitate, compress, reconstruct, predict, diversify, test
Local and global structure

Local wins must add up to the right larger map

Most training signals are local: one masked token, one pair, one patch, one query-document match, one codebook entry. But the representation space is global. It has neighborhoods, clusters, paths, loops, hierarchies, timelines, graph roles, and rare regions.

A model can pass many local checks and still arrange the whole space wrongly. It can predict patches through texture and miss objects. It can match pairs but tear a loop. It can retrieve one positive but create neighborhoods full of close distractors. It can represent frames but scramble behavior trajectory. It can encode node labels but lose graph role.

This is why topology and geometry belong in the same story. Geometry asks whether distances and directions mean the right thing. Topology asks whether the durable larger shape survives.

Shortcut learning

A shortcut solves the training task while missing the real structure

A shortcut is a feature that solves the training task but fails the real task.

Shortcut learning is the central danger behind many representation failures. A vision model may learn background instead of object. A medical model may learn hospital scanner style instead of disease. A document model may learn template and source instead of claim. A language model may learn token frequency instead of meaning. A graph model may learn node labels instead of role. A robot model may learn demonstration timing instead of physical state.

Shortcuts are not random mistakes. They are often the easiest way to satisfy the training pressure. If the task rewards local patch prediction, texture can be enough. If positives share background, background becomes identity. If all examples of a condition come from one site, site becomes disease. If a sparse dimension can win retrieval by firing on a broad topic, it may never learn the finer distinction.

Wrong unit.

The unit hides the needed difference or exposes an easy accidental feature.

Shallow pressure.

The training task can be solved without learning the structure the downstream task needs.

Bad local comparisons.

Positives and negatives teach false sameness or false difference.

No global audit.

The learned space looks good locally but has wrong clusters, paths, or rare regions.

The antidote is not one method. It is the whole framework: better units, better training pressure, broader variation, deeper tasks, global structure checks, hidden-cause reasoning, and behavior tests outside the easy training setting.

Hidden causes

The best representation tracks what produces the observations

Hidden causes are the deeper target behind many representation papers. The raw data is a measurement. The useful state is often behind it. An image is caused by object, pose, lighting, camera, and background. A patient record is caused by disease process, treatment, physiology, access to care, and measurement schedule. A video is caused by body state, intent, force, contact, and environment.

A shortcut tracks an accidental surface clue. A stronger representation tracks the underlying thing that continues to matter when the surface changes. That is why latent distribution matching, invariance, equivariance, topology, and temporal prediction are connected. They are different ways of asking whether the representation is closer to the cause than to the accident.

surface clue: works in training because the dataset happens to contain it hidden cause: keeps working when background, wording, source, timing, or style changes
Behavior tests

The final proof is not the representation; it is behavior

A representation can look clean, sparse, smooth, clustered, or elegant and still fail. The only final test is whether behavior survives where it matters. If the representation was built for retrieval, it should retrieve the right item against close distractors. If built for OCR, it should read small text. If built for code, it should copy and execute exact syntax. If built for medicine, it should preserve thresholds, timing, and patient state. If built for robotics, it should move safely and smoothly.

ExactnessNames, drugs, identifiers, code, math, citations, and legal clauses remain correct.
RobustnessPerformance survives lighting, wording, camera, site, style, scanner, and domain changes.
DiscriminationClose but wrong examples stay separate: similar drugs, species, clauses, actions, documents, graph roles.
StateTemporal and continuous systems preserve phase, trend, motion, and valid intermediate states.
StructureClusters, paths, loops, hierarchies, graph neighborhoods, and rare regions remain meaningful.
ActionThe representation supports the decision or control behavior it was built for.

Closing frame

The representation audit

At this point, the representation theme can be read through one audit. For any paper, ask what raw mess it starts from, what unit it chooses, whether the form is discrete or continuous, what pressure trains it, what shortcuts it blocks, what global structure it protects, what hidden cause it tries to track, and what behavior proves it worked.

representation audit: what is one unit? what should stay exact? what should vary smoothly? what pressure teaches the unit? what shortcut would satisfy the task cheaply? what larger structure must survive? what hidden cause should be tracked? what behavior proves the representation is useful?

The final first-principles statement: representation learning is controlled compression for future behavior.
