MedSIGHT: Unified Diagnosis and Grounding

Medical vision-language models should answer questions AND point to the exact pixels proving the answer, not just one or the other.

Paper explainersAll themesMultimodal

Medical image models face a split personality: some are trained to answer questions about what they see (comprehension), while others identify regions pixel-by-pixel (segmentation). But in real medicine, diagnosis comes first—a doctor says 'tumor'—then must show exactly where it is. MedSIGHT builds one model that does both, by teaching the language model to emit symbolic region codes that decode back to precise pixel masks, trained in three careful stages.

Zero assumption version

Diagnosis without proof

Today's medical image models are split. Some are trained only to answer questions ('What do you see?') without marking regions. Others are trained only to segment (draw outlines around organs and tumors). A doctor using them has to choose: get a diagnosis, or get a marked-up image—not both.

The beginner's naive fix is to train one model on both tasks at once, feeding it all the mixed data. But it does not work: the model's visual understanding gets tangled. CLIP-based patch encoders (the standard vision backbone) extract only coarse, high-level features that discard the fine spatial detail needed for precise pixel-level grounding—they see 'there is a tumor somewhere in the lung' but lose the exact boundaries.

The split problem. Teach a model to diagnose OR to segment, but not both—and if you force both, the shared visual features are too coarse to ground the diagnosis on exact pixels.

The algorithm as a flow

What it actually does

Step 1: Learn spatial structure

Region Perceiver trains on medical segmentation examples to extract fine spatial features from image pixels.

Step 2: Quantize regions into a codebook

Assign each spatial feature (a list of numbers encoding location and shape) to the nearest discrete code; ensure codes decode back to correct masks.

Step 3: Align with language

Language model learns what each region code means by predicting text and reconstructing masks together.

Step 4: Joint tuning

Unfreeze only the LLM; let it learn to emit region codes and text in natural dialogue, grounding diagnosis to pixels.

Step 5: Run inference

Given a medical image and a question, model outputs diagnosis text and region codes; codes decode to exact pixel masks.

What the paper changes

What the paper changes

MedSIGHT adds region-centric tokens—discrete symbolic codes the language model can learn to generate—so that diagnosis (text) can be grounded to exact pixel locations (masks). The standard baseline uses only high-level CLIP patches. MedSIGHT inserts a learned Region Perceiver that extracts fine spatial features, groups them into a codebook (a set of standard templates), and lets the language model treat region codes as vocabulary items, just like words.

the object it moves  =  region codes in LLM vocabulary
The hidden quantity

Spatial grounding precision

measured quantity  =  accuracy of pixel-to-diagnosis alignment

Every diagnostic statement ('this patient has pneumonia') only matters if the doctor can see which pixels prove it. Spatial grounding precision measures how well the model points to the exact pixels that match the diagnosis. In MedSIGHT, when the LLM emits a region code, that code decodes to a pixel mask; the precision is how well that mask overlaps the real anatomical boundary. High precision means no confusion—if the model says 'tumor here' and emits region code 42, decoding code 42 must reconstruct exactly where the tumor is. Low precision means the model names a diagnosis but the grounded mask is fuzzy or misaligned.

The paper measures grounding precision via intersection-over-union (IoU)—a standard metric comparing predicted and ground-truth segmentation masks. Each region code is pre-trained to decode to a specific spatial footprint; during joint tuning, the model learns which codes to emit to ground each diagnosis.

Why it works

Why grounding precision rises when you decouple learning

The core problem: if you throw comprehension and segmentation data at a single CLIP backbone at once, the patches learn a muddled compromise—good enough for 'yes, there is a tumor' but too coarse to pin down 'here, exactly here.' The solution is to train in stages so each module specializes.

Stage 1 freezes the LLM and CLIP encoder and trains only the Region Perceiver on real segmentation masks. The Perceiver learns to extract spatial structure by being forced to predict masks; this creates spatial features (lists of numbers) that encode pixel-level detail. Stage 2 trains a codebook that maps these features to discrete codes, supervised by mask reconstruction—if a code does not decode to a sensible shape, it loses. Stage 3 unfreezes the LLM and trains text prediction together with mask decoding, so the language model learns which codes express which diagnoses. Because each module was pre-specialized, the final joint training is stable: the LLM does not have to reinvent spatial reasoning; it just learns to invoke the spatial codes that were already trained to ground its words.

Math after the picture

The three-stage loss

First in words:

stage_1_loss = BCE_loss + Dice_loss (region perceiver learns mask prediction) | stage_2_loss = VQ_loss + L2_reconstruction + region_loss (codebook learns discrete codes that decode to masks) | stage_3_loss = LLM_loss + segmentation_loss (LLM jointly predicts text and generates region codes)

Then the compact form:

L_total = w1 * (L_seg + L_ce) + w2 * (L_VQ + L_recon + L_R) + w3 * (L_LLM + L_seg)

Every symbol:

L_segBinary Cross-Entropy plus Dice loss (how well predicted masks match ground truth)
L_ceclassification loss (predicting the anatomical class of each region)
L_VQvector quantization loss (how well each embedding maps to a codebook entry)
L_reconL2 reconstruction loss (how well decoded masks match the region embeddings)
L_Rregion perceiver loss (preserving spatial grounding during codebook training)
L_LLMlanguage modeling loss (predicting the next word in the diagnosis)
w1, w2, w3stage weights (how much each stage contributes)
A tiny worked example
Suppose a tumor region has L_seg = 0.15 (pretty good mask match) and L_VQ = 0.05 (codebook vector is close to true embedding). Stage 1 contributes 0.15; Stage 2 contributes 0.05 + 0.08 (reconstruction) = 0.13. Small total means training is stable.
If we skipped pre-training and trained everything at once, the CLIP patches alone would struggle (L_seg = 0.35) and the codebook would have nothing good to quantize (L_VQ = 0.25). Total loss balloons and training destabilizes.
With progressive stages, each module solves its own job first. At Stage 3, L_LLM might be 0.20 (text prediction is harder), but the region codes are already aligned to masks, so the model can ground its diagnosis without fighting the spatial encoder.

Each stage independently optimizes its module; later stages inherit the earlier stage's learned features, so training is stable and each module specializes.

What can go wrong

What can go wrong

Misaligned region codes. If Stage 2 (codebook training) is skipped or weak, the codes may not decode to clean masks. Then Stage 3 learning is doomed: the LLM learns to emit codes that sound right textually but fail to ground spatially. Solution: ensure Stage 2 has strong segmentation supervision.
CLIP patches are too coarse. If the Region Perceiver is not deep enough (too few refinement layers), it cannot overcome the patch-level bottleneck. The refined features remain coarse and spatial detail is lost. Solution: use sufficient Perceiver depth and ensure its pre-training includes fine-grained boundary annotations.
Joint tuning destabilizes codebook. If Stage 3 unfreezes too much (e.g., the codebook vectors themselves), the codes can drift from their pre-trained spatial meanings. The codes become meaningless and grounding fails. Solution: freeze Region Perceiver and image encoder; tune only LLM, projectors, and codebook assignments (not vectors).
Done right. Stages are strictly ordered. Stage 1 produces spatial embeddings. Stage 2 produces codes that decode to correct masks (verified by IoU). Stage 3 teaches the LLM to emit those codes. The LLM never invents new spatial reasoning; it learns to invoke pre-trained grounding.
What a runnable demo should prove

What a runnable demo should prove

Build a minimal end-to-end demo: train a tiny Region Perceiver on a toy medical segmentation dataset (e.g., synthetic lung masks, 50 images), discretize regions into a small codebook (e.g., 16 codes), then train a small language model (e.g., 124 million learned weights, like GPT-2 size) on paired comprehension questions and region codes. Evaluate on a held-out test set.

The demo must show: the unified model outputs both text diagnosis and region codes simultaneously; codes decode to pixel masks that match the true regions; a split model (trained on only diagnosis) cannot emit region codes at all, while one trained on only segmentation cannot diagnose.
