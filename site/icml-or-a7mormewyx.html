MedSIGHT: Medical Vision-Language Models with Pixel-Level Understanding

A medical image model that teaches a language model to point at and name specific regions in an image, not just describe the whole thing.

Paper explainersAll themesMultimodal learning

Medical images are puzzles: a doctor looks at a scan, spots the problem (a tumor, fluid, a fracture), and says where it is. Today's models do one or the other — they either describe what they see or outline regions — but not both in one honest chain of reasoning. MedSIGHT wires them together: when the model speaks about a region, it also generates a code that points back to the exact pixels, making reasoning grounded in what is actually there.

Zero assumption version

Two separate skills, one job

Medical images are dense: a single chest X-ray holds dozens of findings. A doctor must both name what they see and point to its exact location in the image. Existing models split this task: one model describes the image in words, another outlines the regions. But they do not talk to each other, so if the description says 'pneumonia in the right lower lobe' there is no link back to the pixels. The reasoning stays floating in words, untethered from the picture.

A beginner might try to train one model on both tasks — describe and segment — but the model's internal language (embeddings, the list of numbers it uses to store ideas) has no bridge between the two. Saying 'region' means nothing to the segmentation head, and the segmentation head's pixel coordinates do not feed back into what the model talks about. The two skills remain strangers.

In one sentence. MedSIGHT teaches a language model to speak region-codes: discrete labels that map back to pixel regions, creating a shared language between description and segmentation.

The algorithm as a flow

What it actually does

Region Perceiver extracts patches

Image is chopped into overlapping patches; perceiver gathers spatial cues.

Lists of numbers encode region identity

Each list of numbers carries 'which region do I belong to' in its values, not as a label.

Codebook translates regions to codes

Perceiver output is quantized (rounded) to the nearest codebook entry (a discrete region label).

LLM speaks codes naturally

Language model treats codes as regular vocabulary (just like words); can generate them alongside descriptions.

Decode to reconstruct masks

Each code maps back through perceiver to pixel locations, recovering the segmentation mask.

What the paper changes

What the paper changes

The model's vocabulary and internal representation. Instead of storing regions only in the low-level pixel-decoder, the paper wires them into the language model itself as discrete codes — like adding new words to the dictionary that mean 'anatomical region 47' or 'pathology zone 3'. When the model thinks in language, it can think about regions directly.

the object it moves  =  Region codes in vocabulary
The hidden quantity

The hidden quantity: region-centric grounding

measured quantity  =  Grounding score (connection between words and pixels)

Grounding is the answer to: when the model talks about a structure, can you point to exactly which pixels it means? In this paper, the model generates a discrete region code (an integer, say 47) that the perceiver translates back to a segmentation mask. A high grounding score means the code reliably maps to the correct anatomical zone; a low score means the code and the description are out of sync, words talking about one thing while the pixels show another.

The paper measures grounding by training on paired image-description-mask triplets and checking two metrics: does the generated code decode to the right pixels (segmentation dice score), and does the description match what the code points to (this is implicit in the end-to-end loss). The perceiver learns this mapping through progressive training, slowly aligning the three pieces.

Why it works

Why it works: three pieces in one chain

The problem was two towers with no bridge. MedSIGHT solves it by embedding the bridge into the language model itself. Here is how:

First, the Region Perceiver learns to extract spatial cues from image patches and encode them as region-centric tokens — numbers that say 'which part of the anatomy does this patch belong to' rather than 'what are the raw pixels.' This is the translation layer from pixels to meaning.

Second, the model learns a codebook: a small dictionary of discrete region labels (say, 256 codes). Each code is a number like 5 or 127, and it stands for a real anatomical zone. By quantizing the perceiver's output (rounding it to the nearest code), the model turns fuzzy spatial intuitions into crisp symbolic labels. Crisp labels live naturally in a language model's vocabulary, just like words.

Third, because codes are now tokens, the language model can generate them alongside words in its sequence. When it talks about a finding, it also emits a region code. That code is then decoded (sent back through the perceiver) to recover the pixel mask. All three pieces — image input, language output, segmentation output — are now linked by a single training loss. Progressive training (slowly adding and aligning the three pieces over time) prevents the modules from fighting each other.

Why this works: the shared vocabulary (codes-as-tokens) means that improving segmentation accuracy automatically improves the language model's grounding, because the codes it generates must be the ones that point to the right regions. There is no separate loss to arbitrate; it is one machine learning to speak grounded language.

Math after the picture

The learning equation

First in words:

Total loss equals segmentation loss plus language loss, both using the same region codes

Then the compact form:

L_total = L_seg(mask, decode(codes)) + L_lang(words, codes)

Every symbol:

L_totalthe combined error we minimize
L_segsegmentation loss: how far the reconstructed mask is from the true pixels
maskthe true pixel-level boundary of the region
decode(codes)turning region codes back into a predicted segmentation mask
codesthe discrete region labels the model generates
L_langlanguage loss: how well words predict the region codes and text
wordsthe medical description the model produces
A tiny worked example
Say the model emits region code 5 for 'left lower lobe'. The decoder maps code 5 to pixel mask (maybe 10000 pixels). Segmentation loss measures how close that to the true lobe boundary: if it overlaps 95% of true pixels, loss is 0.05. Language loss measures whether the words 'left lower lobe' and code 5 align: if they do, loss is near 0. Total loss = 0.05 + 0.01 = 0.06.
Compare: if the model had said 'left upper lobe' (code 7) while pointing to the lower region, the language loss would spike (words and code mismatch), pulling the weights to either correct the words or the mask. Either way, grounding is restored.

Both losses use the same codes, so improving one automatically improves the other, because a code that points to the right pixels must also match the description that words the same anatomy.

What can go wrong

What can go wrong

Codebook drift. If the perceiver learns faster than the codebook, the codes stop pointing to consistent regions, because the perceiver's output changes but the codebook's fixed entries do not track it. Later, when the language model uses a code, it no longer maps to the expected anatomy.
Segmentation overshadows language. If segmentation loss is much larger than language loss, the model optimizes for pixel accuracy and forgets to produce coherent text. Progressive training (adding pieces slowly) is the fix.
Limited codebook size. If there are only 64 region codes but the anatomy has 200 fine-grained structures, codes must be reused or approximate, degrading grounding.
Done right. Careful progressive training ensures all three pieces (perceiver, codebook, LLM) improve in lockstep, because each piece is added and unfrozen gradually, so earlier pieces do not race ahead and make the codebook stale. A balanced loss weighting keeps segmentation and language honest by preventing either from drowning the other. A large enough codebook covers the relevant anatomy, so codes need not be reused or approximate.
What a runnable demo should prove

What a runnable demo should prove

Build a simplified version: take a small medical image (chest X-ray or MRI slice), train on 100 image-description-mask triplets. Implement the Region Perceiver as a simple patch-attention layer, codebook as a lookup table (64 entries), and use a small language model (a 125M-parameter model). Train with progressive training: first warm up perceiver alone for 10 steps, then add codebook, then add LLM. After 5 epochs, test on a held-out image: feed the image, capture the model's region code output and text output, decode the code to a mask, compare to ground truth.

Grounding quality = (segmentation dice score) times (description-code alignment score)

The demo must make it impossible to miss: when you feed the model an image, it outputs words AND a region code that points to those words. Change the description slightly (say 'nodule' instead of 'opacity'), and the region code and mask should also shift to the relevant area. That link is the whole story.
