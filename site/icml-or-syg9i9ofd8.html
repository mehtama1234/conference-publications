Latent Collaboration in Multi-Agent Systems

Let agents pass internal states directly instead of translating every intermediate step into text for other agents to read back.

Paper explainersAll themesAgents & Tool Use

Many multi-agent systems make agents communicate by writing text messages to each other. That choice is convenient because text is readable, but it also forces every agent to convert its internal reasoning state into words and then forces another agent to convert those words back into its own internal state. This paper removes that repeated translation step by allowing agents to exchange internal representations directly through shared working memory.

Zero assumption version

Why text communication slows agent teams

When one agent sends text to another, two extra steps appear. First, the sender must compress its current reasoning state into a sequence of words. Second, the receiver must reconstruct useful internal structure from that sequence. Both steps can lose detail, add cost, and slow the full team because each handoff passes through language even when the agents are internally computing in a richer form.

The paper asks whether agents can collaborate without this repeated translation. Its answer is to let each agent produce internal thought states and place them into a shared working memory that other agents can read directly.

The paper's move in one sentence. Replace text-based agent-to-agent messages with direct exchange of internal states through a shared working memory.

The algorithm as a flow

What it actually does

Generate internal thought states

Each agent produces internal step-by-step states rather than writing all intermediate reasoning as text.

Store those states in shared memory

A common working memory keeps the internal states available to the rest of the team.

Read team memory directly

Other agents consume the shared internal states without re-encoding them from text.

Continue updating the task state

Each agent mixes the shared memory with its own current computation and writes back new progress.

What the paper changes

What the paper changes

The paper changes the communication channel between agents. Instead of making language the only medium for collaboration, it allows teams to coordinate through directly shared internal states because the shared memory can carry team progress without repeated text rewrites.

The hidden quantity

Translation loss: the hidden quantity

measured quantity  =  How much useful task structure is lost when agents must communicate through text

The key hidden quantity is translation loss. An agent may internally track detailed task structure, uncertainty, partial plans, and unresolved branches, yet its text message must express only a limited slice of that state. The receiver then rebuilds an approximation from the words it sees.

This method aims to reduce this hidden loss by keeping collaboration inside internal state space. If less structure is lost at each handoff, later agents can continue from a more faithful team state because they inherit the sender's internal representation directly.

Why it works

Why this works

Direct state sharing helps because it avoids repeated encode-decode cycles. In a text-based team, every exchange spends computation on wording and re-interpretation. With direct state sharing, the receiver starts from a richer team state because the handoff keeps more of the sender's internal structure intact.

The method can also reduce runtime and output length because fewer words need to be generated during collaboration. That efficiency gain matters only if accuracy is preserved, and the paper argues that accuracy can improve as well because agents lose less information at each handoff.

A simplified shared-memory update

First in words:

Let each agent read the current shared memory, combine it with its own current state, and write an updated contribution back to the memory for the next agent or the next round.

Then the compact form:

memory_next = combine(memory_now, state_agent_1, state_agent_2, ... ) ; state_i_next = update_i(state_i_now, memory_now)

Every symbol:

memory_nextthe updated shared working memory after agent contributions
memory_nowthe current shared team state
state_agent_iagent i's internal state
state_i_nextagent i's next internal state after reading team memory
combinethe rule that merges contributions into shared memory
update_iagent i's rule for using the shared memory
A tiny worked example
Suppose one agent analyzes the question structure and another agent checks supporting evidence.
The first agent writes its current task decomposition into shared memory.
The second agent reads that memory and adds evidence states tied to each subtask.
A third agent reads both contributions and produces the final answer state.
No handoff required rewriting each intermediate result as text, so the team keeps more detail and uses fewer generated words.

The actual implementation uses internal vector states, but the main idea is direct: keep a shared internal team state and update it across agents.

What can go wrong

What can go wrong

Direct state exchange is harder to inspect. A text message can be read by a developer, while a shared internal state is less transparent because its content is not human-readable.
Agents may overwrite each other badly. Shared memory helps coordination, but poor merge rules can let one agent's state erase another's useful work because all agents write into the same workspace.
Cross-model compatibility may be limited. Direct state exchange is easiest when agents share compatible internals, so heterogeneous teams may still need text or extra adapters because their internal representations differ.
Done right. Compare against strong text-based teams on the same tasks, track both speed and quality, and inspect whether shared memory actually reduces communication volume because that is the proposed source of the gain.
What a runnable demo should prove

What a runnable demo should prove

Build a small two-agent or three-agent reasoning system with two communication modes. In one mode, agents send ordinary text messages. In the other, they pass compact internal states through a shared memory object. Use the same task decomposition and the same base models in both modes.

The demo should prove that direct state sharing cuts communication cost because the team avoids repeated wording and reinterpretation, and that the quality stays the same or improves because each handoff preserves more task structure.
