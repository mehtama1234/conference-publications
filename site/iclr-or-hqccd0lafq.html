Exchangeability of GNN Representations with Applications to Graph Retrieval

GNN embeddings have a hidden exchangeability symmetry that lets you compare graphs using simple distance math instead of expensive transport algorithms.

Paper explainersAll themesGraph & Geometric Learning

When you train a graph neural network (a model that learns from networks of connected nodes), it produces a list of numbers (a representation) for each node. This paper discovers that these numbers have a special hidden property: their relative order does not matter. That means if you shuffle the numbers within each list, the overall structure stays the same. This unlocks a shortcut: you can compare two whole graphs using simple distance math instead of costly transportation-based similarity algorithms, and then use that speedup to retrieve similar graphs from huge databases.

Zero assumption version

Finding similar graphs is slow

You have a database with millions of networks—social networks, molecular structures, or knowledge graphs. You want to find which ones are similar to a new query network. A common way to measure similarity is a transportation-based metric: model the two graphs as collections of items, and count how many operations it takes to rearrange one into the other. These metrics capture the true structure of graph differences, but computing them requires solving a costly optimization problem for each pair—too slow for searching millions of graphs.

A beginner might try: use a neural network to turn each graph into a list of numbers, then measure distance between lists using Euclidean distance (straight-line distance between points). But Euclidean distance assumes the position in the list matters, even though the network may not care which number appears first. Transportation-based metrics are more accurate because they account for graph structure, but they take much longer to compute, since each comparison requires solving an assignment problem.

In one sentence. The paper shows that GNN embeddings contain exchangeability: the order of the numbers in each node embedding does not matter for the overall structure, so you can approximate expensive transport distances using simple Euclidean distances on sorted numbers.

What it actually does

What the paper changes

What the paper changes

The paper changes what you compare: instead of comparing raw embeddings in their original order, you sort them first and then compute distances. This one small reordering exposes the hidden structure and makes distance math work as well as expensive transport metrics.

the object it moves  =  the order of embedding values
The hidden quantity

Exchangeability: the invariant structure

measured quantity  =  exchangeability (order-invariant symmetry)

Exchangeability is a property: a sequence of numbers is exchangeable if the pattern stays the same no matter how you reorder the numbers. When a GNN learns node embeddings under standard training (minimize prediction error, update weights with gradients), it tends to produce embeddings that are exchangeable: the network does not care which position in the list holds which number, only that the full set of numbers appears. This is because the network processes graph structures that have no inherent ordering—a node has connections, but there is no natural "first" connection or "second" connection.

The paper estimates exchangeability by showing that transportation-based similarities (which respect the true structure of graph differences) can be approximated by Euclidean distances computed on order statistics (the sorted values), with a bounded error. This measurement reveals that the GNN has learned an order-invariant representation.

Plain reading. Think of each graph as having a unique fingerprint: a list of numbers. Exchangeability means that reshuffling the fingerprint does not break it—it still identifies the same graph. This is like saying that a name is a name no matter which letter you read first: the identity comes from which letters appear, not their order.
Paper reading. The paper proves that node embeddings from a wide family of GNNs trained with standard optimization obey an exchangeability condition: the joint probability density of embedding coordinates is invariant under permutation. This implies order statistics (sorted coordinates) are sufficient statistics for graph similarity.
Why it works

Why it works: turning permutation-invariance into speed

Graph neural networks naturally learn order-invariant representations because graphs have no inherent node ordering. When you train a GNN to predict something about a graph (e.g., its class or property), the learned numbers adapt to capture only the information that matters: which nodes are connected, what their features are, not their index numbers. This means if you rearrange the node numbers, the network's learned decision stays the same. That is exchangeability.

Once you know the numbers are exchangeable, you can sort them. Sorting creates a canonical form: two graphs that are truly similar will have similar sorted numbers. The Euclidean distance between sorted numbers approximates the true transportation-based similarity because sorting reveals which values the graphs share. Transportation-based metrics are slow because solving the assignment problem takes many steps; sorted-Euclidean is fast because it is just addition and square roots. With this shortcut, you can use locality-sensitive hashing (a database trick: hash similar items to the same bucket for instant lookup) to index sorted numbers and retrieve similar graphs in milliseconds instead of hours.

The sorted-distance approximation

First in words:

The Euclidean distance between sorted embeddings approximates the transportation distance between graphs. Specifically: Euclidean distance of order statistics approaches the Wasserstein (transportation) distance as the ordering captures more of the graph structure.

Then the compact form:

d_Euclidean(sort(emb_1), sort(emb_2)) ≈ W(G_1, G_2)

Every symbol:

sort(emb)the sorted list of embedding values
d_Euclideanordinary distance: sum of squared differences
W(G_1, G_2)Wasserstein distance (transport cost between graphs)
≈approximates (error is bounded)
A tiny worked example
Graph A GNN embedding: [4.2, 1.1, 3.5, 2.0]
Graph B GNN embedding: [4.1, 1.2, 3.6, 2.1]
Sorted A: [1.1, 2.0, 3.5, 4.2]
Sorted B: [1.2, 2.1, 3.6, 4.1]
Euclidean distance: sqrt((1.1-1.2)^2 + (2.0-2.1)^2 + (3.5-3.6)^2 + (4.2-4.1)^2) = sqrt(0.01 + 0.01 + 0.01 + 0.01) ≈ 0.2
This distance is small, so A and B are similar graphs—and the Wasserstein distance (expensive to compute) would also be small.

Sorting reveals which values the graphs share, so Euclidean distance on sorted lists captures similarity without the cost of transport metrics.

What can go wrong

What can go wrong

Symmetry breaks with order-dependent encodings. If the GNN explicitly depends on node ordering (e.g., if nodes are labeled by position), exchangeability fails. This happens when the graph structure includes inherent ordering (e.g., time-series nodes, or a GNN that uses position as a feature). The method only works for truly unordered graphs.
Approximation error accumulates with dissimilar graphs. Euclidean distance on sorted embeddings is an approximation of transport distance. For very different graphs, the error can grow large. The LSH method may miss some truly similar neighbors if the embedding space is high-dimensional or if the query graph is an outlier.
Limited to embeddings that exhibit strong exchangeability. Not all GNN training regimes produce exchangeable embeddings. If the network learns position-dependent features or if the training objective explicitly breaks symmetry, the sorted-distance shortcut fails. The paper assumes standard supervised or self-supervised training.
Done right. The method works best on unordered graph datasets (molecular structures, knowledge graphs, social networks) with standard GNN training. For these cases, it is both fast and accurate—dramatically reducing query time while preserving the ability to find true neighbors.
What a runnable demo should prove

What a runnable demo should prove

Build a toy example with 1000 small graphs (random 10-node networks or simple molecular fragments). Train a GNN to classify them. Extract the trained numbers for all graphs. For each test graph, compute: (1) transport distance to all others (exact but slow), (2) Euclidean distance on sorted numbers (fast), (3) LSH-based retrieval time. Measure how well the ranking of neighbors matches: graphs that rank high in transport distance should also rank high in sorted-Euclidean, because they are fundamentally similar and sorting captures that similarity. Measure retrieval speed: LSH retrieval is fast because hashing avoids comparing to all graphs.

neighbor_rank_match = percent_overlap_in_top_10; LSH_speedup = time_transport_search / time_LSH_search

The demo must make it impossible to miss: sorting numbers and using Euclidean distance ranks similar graphs correctly because the sorting captures which values the networks learned, and runs 100 times faster because hashing skips most comparisons.
