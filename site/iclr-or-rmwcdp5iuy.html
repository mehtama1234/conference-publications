Online Conformal Prediction with Adversarial Feedback via Regret Minimization

When you must make safe predictions online against a tricky opponent, wire together prediction-set confidence and adversarial learning to guarantee your answers stay honest.

Paper explainersAll themesLearning Theory

Imagine a spam filter that must instantly decide if an email is junk, but it only learns whether it was wrong if you actually check its guess. A traditional prediction method requires feedback on every answer to improve, because without seeing all the labels, it cannot recalibrate which answers are safe to include. This paper builds a conformal prediction (a method that estimates uncertainty) that works online, gets partial feedback from an adversary, and still makes a provable guarantee: in the long run, your mistakes will not exceed the target rate you set.

Zero assumption version

Uncertainty in a hostile world

Most prediction methods return a single answer. But in life-or-death decisions—medical diagnosis, loan approval, driverless cars—you need to know how confident you are. Conformal prediction is a clever way: instead of guessing one outcome, you output a set of outcomes that is guaranteed to contain the true answer with a probability you choose.

The catch: current conformal methods assume the data arrives randomly and give you immediate feedback on every mistake. Real life is meaner. You get partial feedback (only when you were wrong do you learn the truth), and an adversary controls the data stream, changing its strategy to break your guarantees.

The key idea. Use the mathematics of adversarial learning (which handles hostile opponents) to build conformal sets that stay honest even when feedback is sparse and your opponent adapts.

The algorithm as a flow

What it actually does

Predict a set, not a point

At each moment, the learner outputs a set of plausible answers (e.g., spam or not-spam, plus uncertainty).

Measure two costs

Assign a penalty if the true answer is missing (miscoverage) and a bonus if the set is too big (inefficiency).

Get partial feedback

The adversary reveals the true label only when your set missed it; otherwise you stay blind.

Update via regret

Use the EXP3.P bandit algorithm to learn which confidence thresholds minimize total penalty over time.

Guarantee emerges

The regret bound mathematically forces the long-run error rate below your target.

What the paper changes

What the paper changes

The paper modifies how the learner chooses a confidence threshold (the boundary between 'includes this answer' and 'excludes it') when feedback is incomplete and adversarial. Specifically, it wires the conformal prediction problem into the adversarial bandit framework, where the regret (total accumulated penalty) is explicitly linked to the coverage guarantee (how often the true answer is in your set).

the object it moves  =  confidence threshold selection
The hidden quantity

The hidden quantity: miscoverage rate

measured quantity  =  miscoverage rate

Miscoverage is the fraction of time your prediction set fails to include the true answer. In safe systems, this must stay below a user-specified target (e.g., no more than 5% of cases). It is invisible in real-time but revealed only by future feedback.

The paper estimates this by linking it to regret. Regret is the total accumulated penalty the adversary can impose. A low regret bound mathematically forces miscoverage to converge to the target rate, even when the adversary controls which labels you see.

Why it works

Why it works: regret binds to coverage

The core insight is that regret and coverage are two views of the same problem. In adversarial bandits, regret measures how badly the learner does compared to the best fixed strategy in hindsight. Here, the 'best fixed strategy' is the threshold that keeps coverage exactly on target. So if regret stays small, the learner's actual coverage must stay close to target.

The paper strengthens this with 'unlocking': when your set correctly includes the true answer (partial feedback received), you learn it is safe to be confident. When your set misses (feedback received), you learn this threshold was too loose, so you can also update about nearby thresholds that would have failed. This gets more information from sparse feedback, tightening the regret bound and thus the coverage guarantee.

Math after the picture

The equation: regret to miscoverage

First in words:

regret bounds miscoverage: if total regret is R, then long-run miscoverage converges to target plus a term proportional to the square root of regret divided by time.

Then the compact form:

MC(T) <= target + O(sqrt(R(T)) / T)

Every symbol:

MC(T)miscoverage rate: fraction of rounds where prediction set misses the true answer
targetuser-specified acceptable error rate (e.g., 0.05 for 5%)
R(T)regret of the learner after T rounds, accumulated penalty vs. best fixed threshold
Ttotal number of prediction rounds
O()big-O notation: order of magnitude, ignoring constants
A tiny worked example
Suppose target = 5%, and we run for T = 10,000 rounds.
Regret bound from the paper: R(T) = O(sqrt(T)) = O(100) in order of magnitude, so R(T) approx 1,000.
sqrt(1,000) = 31.6. So miscoverage <= 0.05 + 31.6/10,000 = 0.05 + 0.00316 = 0.05316.
After 10,000 rounds, miscoverage stays within 5.3%, close to the 5% target. As T grows, the guarantee tightens.

The regret bound (a standard result in adversarial learning) automatically translates to a coverage guarantee because the paper designed the loss function and the unlocking feedback to make regret and miscoverage measure the same invisible problem.

What can go wrong

What can go wrong

Too many discretization levels. The algorithm chooses thresholds from a finite grid. Too many candidates (K large) inflates regret, so the coverage guarantee weakens. Too few and you miss the optimal threshold.
Adversary controls feedback timing. If the adversary can decide not just the data but also when to reveal labels, it could starve the algorithm of information in a targeted way. The regret bound assumes a fixed (though adversarial) feedback pattern.
Coverage guarantee is asymptotic. The miscoverage rate converges to target only in the limit as rounds approach infinity. In finite time, especially early on, coverage may miss the target.
Done right: design the loss. The paper's key move was tailoring the loss function (combining miscoverage and inefficiency) so that regret bounds immediately translate to coverage guarantees. This explicitly connects two different-looking problems and makes the theory tight.
What a runnable demo should prove

What a runnable demo should prove

Build an online simulator: a stream of classification tasks (e.g., spam vs. not spam, or digits 0–9). At each step, the learner predicts a set of labels (based on a confidence threshold). An adversary controls the data stream and decides when you see the true label (only if you missed it). Run the algorithm for 1,000–10,000 rounds and track two curves: (1) the running miscoverage rate (does it converge to 5% if you set target to 5%?), and (2) the average prediction set size (is it reasonable, say 2–3 classes out of 10?).

miscoverage_error = |long_run_miscoverage_rate - target_rate|, set_efficiency = average_set_size / number_of_classes

The demo must show that even though the adversary controls when you see labels, the long-run error rate is stable and hovers around your target, proving the guarantee works in practice.
