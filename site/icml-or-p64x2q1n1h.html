Latent Reasoning VLA: Hiding Expensive Thinking Inside the Model

Instead of making the robot think out loud during action, bundle that thinking into hidden numbers learned during training, so answering is fast.

Paper explainersAll themesRobotics & Control

When a robot answers where to move next, current models write out their reasoning step-by-step in words (or pictures) as they go. This is clear but slow — each step takes time. This paper shows how to teach the model to do that reasoning in secret, encoded as hidden numbers inside the model, so when the robot acts it just predicts the next move directly. The result is a model that still reasons correctly but 90% faster, because reading hidden numbers is one forward pass through the neural network instead of generating dozens of words.

The slow thinking problem

Today's best robot-control models use what is called Chain-of-Thought reasoning: given an image and an instruction like 'pick up the mug', the model first writes out intermediate steps ('I see the mug on the left', 'I need to move my gripper down', 'Now I close it'). Only then does it predict the actual motor commands. This works well — the robot reasons correctly — but each intermediate step takes compute time, and large language models are slow to run.

A naive approach would be to skip the reasoning and just train the robot to predict actions from images directly. But then it makes clumsy mistakes: it does not plan ahead, does not break the task into stages, and fails when it encounters situations different from its training examples.

The paper's move in one sentence. Teach the robot to do its reasoning in secret — as hidden numbers inside the model — so reasoning is fast but stays correct.

The algorithm as a flow

What it actually does

Stage 1: Learn with full supervision

Train on robot trajectories where you have the images, the reasoning steps written in words, and the actions. The model learns to predict all three together.

Stage 2: Hide the text reasoning

Gradually remove the explicit text reasoning steps. In their place, train the model to learn compact hidden representations (just numbers) that encode the same reasoning. The model is supervised by what it sees next (the future image).

Stage 3: Stabilize the hidden representations

Use a technique called exponential moving average to keep the hidden representations from becoming unstable or collapsing into nonsense. This is like gently guiding a river to keep it flowing smoothly.

Stage 4: Learn discrete action tokens

Train the model to generate action-step tokens (coarse chunks of motion) using the hidden reasoning, predicting each chunk one after another.

Stage 5: Learn continuous action trajectories

Finally, train a continuous action generator (using flow matching — a modern probabilistic method) to produce smooth real-valued motor commands directly from the hidden reasoning.

What the paper moves

The paper moves reasoning from words (text tokens, expensive to generate) to hidden numbers (compact learned representations, available immediately inside the model). This swap is the whole paper.

The hidden quantity

The hidden reasoning state

measured quantity  =  The hidden reasoning state

This is a list of numbers inside the model that encodes what the robot is thinking at each step: 'where is the target', 'how should I move', 'what comes next'. These numbers are NOT words; they are learned representations that live inside the model's neural network. The paper does not tell us exactly how many numbers (the dimension), but it is small enough that storing and computing with them is much faster than generating text, because a single forward pass through the model reads all the hidden numbers at once, whereas generating words requires dozens of repeated passes (one per word).

The paper measures this hidden quantity using a visual prediction task: the hidden state is good if it predicts the next image correctly. This keeps the hidden reasoning aligned with perception — what the model is thinking should match what it will see next.

Why it works

Why hiding reasoning inside the model makes it faster

The core insight: writing text is slow because each word must be generated one at a time, and the model has to wait for each word before deciding what comes next. Hidden numbers, by contrast, are learned during training and already live inside the model when answering a new question. They are ready to go.

The curriculum learning design makes this work: start by teaching the model to produce both explicit reasoning (text) and implicit reasoning (hidden numbers) together, supervised by real robot data. The model learns that the hidden numbers should encode the same reasoning as the words. Then gradually remove the explicit text supervision and let the hidden numbers stand alone. By the end, the model has learned a compact internal representation of reasoning that requires no text generation — just a forward pass through the neural network to read the hidden numbers and predict the action.

Visual prediction provides the glue: at each stage, the hidden reasoning is supervised to correctly predict what the robot will see next. This grounds the hidden state in perception, ensuring the robot is not hallucinating but reasoning about what is actually there.

How to measure and train the hidden reasoning

First in words:

The hidden reasoning is trained by comparing its prediction of the next image to the actual next image, and by comparing the discrete action tokens to the ground-truth action tokens. The full training loss combines text reasoning loss (early stages only), visual prediction loss, and action loss.

Then the compact form:

L_total = L_cot + 0.1 * L_vis + L_act_dis + L_act_con

Every symbol:

L_cotLoss for predicting the text reasoning steps (present only in Stage 1)
L_visLoss for predicting the next image from the hidden reasoning (present all stages)
L_act_disLoss for predicting discrete action tokens (Stages 1-2)
L_act_conLoss for predicting continuous action trajectories via flow matching (Stages 4-5)
0.1Weight scaling visual loss relative to reasoning loss (visual is supervision, not the main target)
A tiny worked example
Suppose at one training step the model predicts 'move left' but the ground truth is 'move down'. The text reasoning loss L_cot catches this (magnitude 0.5). The model also predicts the next image shows the gripper still far away, but the true next image shows the gripper closer. The visual loss L_vis reflects this (magnitude 5.0). Total loss so far is 0.5 + 0.1 * 5.0 = 1.0. The action loss L_act_dis/L_act_con is small because the discrete action tokens are close (magnitude 0.3). Final total: 1.0 + 0.3 = 1.3. After many updates with this signal, the hidden reasoning learns to predict both the next image and the correct action together.

The hidden reasoning state is optimized to simultaneously encode task reasoning and predict future perception, which naturally keeps it aligned with the robot's embodied control problem.

What can go wrong

What can go wrong

Representation collapse. If the hidden representations all become the same number, they carry no information. The paper prevents this using exponential moving average (EMA) to keep the visual encoder targets stable and diverse. Without this, the model silently fails.
Mismatch between reasoning and action. If the hidden reasoning encodes the right task plan but the action generator does not listen to it, the robot will act randomly. The paper ensures alignment by training the action generator directly on the latent reasoning from the start.
Loss of reasoning expressiveness. If you compress too aggressively (make the hidden representation too small), the model cannot encode all the task reasoning. The paper uses a curriculum to transition gradually, keeping expressiveness as long as possible.
Done right: reasoning is hidden but faithful. When trained correctly, the hidden representations encode the same multi-step reasoning as explicit text would, but without the cost of generating words. The robot plans inside its head and acts directly.
What a runnable demo should prove

What a runnable demo should prove

Build a small robot-control task (e.g., picking an object from a table or pushing it to a goal) where you have both ground-truth reasoning steps (in text or images) and action labels. Train the model using the curriculum: Stage 1 with explicit reasoning, then progressively hide it. Measure latency at each stage by timing how long it takes to predict the next action on new test images. Also measure task success: does the robot pick the mug even after you hide the reasoning?

speedup = time_explicit_reasoning / time_latent_reasoning ; success = fraction_of_tasks_completed

The demo must make it impossible to miss: latency drops dramatically (ideally 10x or more), task success stays the same or improves, and the hidden representations provably encode task-relevant information (by checking that removing them breaks the task).
