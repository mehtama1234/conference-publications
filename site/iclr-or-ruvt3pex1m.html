Task Affinity: Predicting Which Tasks Learn Better Together

Before training a group of tasks together, measure how their learning steps affect each other to predict if they will help or hurt.

Paper explainersAll themesOther

Multi-task learning trains several tasks with one shared model to save time and improve learning, because the shared layers learn general patterns that work for all tasks, and each task's specific layers adapt those patterns to its own goal. But which tasks should be grouped together? Testing all possible combinations is too expensive. This paper predicts in advance whether a group of tasks will work well together by measuring how strongly each task's learning nudges the others.

Zero assumption version

Picking task groups is expensive

In multi-task learning, many tasks share one model to learn faster because shared weights absorb recurring patterns (like detecting edges in images for both face and car recognition), so each task learns its specifics more quickly. But which tasks should share? Testing every possible group requires training hundreds of models—prohibitively slow for even ten tasks. A beginner might try training a random group and seeing if it works, then trying another, then another. This wastes enormous compute because most groups fail to help each other, sending conflicting nudges to shared weights.

What is actually needed: a prediction before training. Can you look at tasks and say in advance whether they will benefit from learning together? If so, you train only promising groups, saving time.

The challenge. Predict which task groups will improve performance together (rather than degrade each other), without training each group first, because looking at how their learning signals align can tell you if they will cooperate on shared weights.

The algorithm as a flow

What it actually does

Run one model on all tasks

Train a shared-encoder multi-task model once to get gradients.

Measure pairwise affinity

For each pair of tasks, compute how Task A's weight nudge affects Task B's loss, averaged over training.

Collect ground truth on a few groups

Train only a handful of task groups to know their real performance gains.

Train a residual corrector

A non-linear model learns to predict gain errors from affinity scores, filling gaps the linear version misses.

Predict new groups

Use the combined linear affinity and learned corrector to forecast gains for all other task groups.

What the paper changes

What the paper changes

The paper introduces a method to compute task-affinity scores directly from training dynamics, not from training many models. It measures how one task's weight-update nudge affects another task's loss during a single training run, without extra cost.

the object it moves  =  task-affinity scores
The hidden quantity

The hidden quantity: Gradient affinity

measured quantity  =  gradient-based affinity score

During training, each task sends a gradient (which way to nudge the weights to reduce its loss). The affinity score measures how much Task A's nudge reduces Task B's loss. High affinity means the tasks naturally help each other because their gradients point in similar directions, so a nudge that improves one tends to improve the other. Low affinity means they push weights in conflicting directions.

The paper computes this by recording gradients from each task at each training step, then measuring how much applying one task's gradient would reduce the other's loss. It averages this over all training steps to get a stable score that does not bounce around due to randomness in early steps.

Plain reading. Affinity is the direction that Task A's learning pushes weights, versus the direction Task B needs them to go. When those directions align, training together helps both because neither task wastes steps undoing the other's weight changes.
Paper reading. The affinity score is computed as the dot product of Task A's gradient with the change in Task B's loss when Task A's weights shift by its gradient.
Why it works

Why it works: Two-layer prediction

The core insight is that task relationships are partly linear and partly non-linear. The linear part—gradient affinity—captures how tasks' learning directions align. But real gain is more complex: affinity alone misses interactions, saturation, and task-specific quirks.

The paper's solution: use gradient affinity as a foundation, then train a lightweight non-linear model (using B-splines, a smooth curve-fitting technique) to learn what affinity scores are missing. Because this corrector only trains on a handful of task groups (not hundreds), it is cheap. The two layers together predict gains more accurately than affinity alone because the corrector catches non-linear patterns (like when two tasks' gradients are nearly orthogonal but their datasets overlap, creating hidden alignment), and far faster than testing all combinations because you label only 3-4 groups instead of 50+.

Math after the picture

The affinity formula and corrector loss

First in words:

The per-step affinity score from task i to task j is: how much does task i's weight update reduce task j's loss. We average this over all K training steps. Then we train a corrector model to predict the residual (the difference between affinity's prediction and ground truth).

Then the compact form:

affinity_i_to_j = (1/K) * sum_{k=1}^{K} (-learning_rate * gradient_i * gradient_j) ; corrector_loss = (predicted_residual - actual_residual)^2

Every symbol:

gradient_ihow much task i wants to change each weight, pointing down i's loss slope
gradient_jhow much task j wants to change each weight
learning_ratestep size (how far we move in the gradient direction)
Ktotal number of training steps
predicted_residualwhat the corrector model forecasts will be missed by affinity alone
actual_residualground truth: what affinity actually got wrong on a training group
A tiny worked example
Suppose Task A's gradient is [0.2, -0.1, 0.3] and Task B's gradient is [0.15, 0.2, 0.1].
Affinity = learning_rate * (0.2*0.15 + (-0.1)*0.2 + 0.3*0.1) = 0.01 * (0.03 - 0.02 + 0.03) = 0.01 * 0.04 = 0.0004.
This is positive, so Task A's nudge roughly helps Task B (tasks are weakly aligned).
But ground truth gain is 5 percentage points. Affinity alone predicts 1 point.
Residual = 5 - 1 = 4. The corrector learns: this task pair helps each other in ways affinity missed; add 4 points to affinity's prediction.

Affinity measures linear alignment of learning directions; the corrector learns the non-linear corrections that pure gradient similarity misses.

What can go wrong

What can go wrong

Affinity varies wildly early in training. In the first few steps, gradients bounce around due to randomness, so affinity scores are noisy. The paper fixes this by averaging over the entire training run, smoothing out noise.
Non-linear patterns need enough labeled examples. If you train the corrector on only one or two task groups, it cannot learn the patterns. The method needs at least 5-10 ground-truth groups to fit the non-linear model reliably.
Affinity can miss deep interactions. Two tasks may have zero-affinity (orthogonal gradients) but still help each other through data because seeing Task B's examples helps Task A generalize to cases it rarely saw alone, even though their weight nudges point in different directions. The corrector is trained to catch such patterns from the ground-truth training groups.
Done right. Train one MTL model, compute affinity from its training dynamics, label a handful of promising groups via real multi-task learning, then use both to forecast the rest.
What a runnable demo should prove

What a runnable demo should prove

Build a small multi-task learning setup with 5-8 tasks (e.g., predicting different attributes of images, or different time-series forecasting targets). Compute ETAP's gradient affinity scores. Train 3-4 random task groups and measure their real MTL gains. Train ETAP's corrector on those 3-4 groups. Then predict gains for all remaining groups (at least 10 new combinations) and compare predictions to ground truth. Measure prediction accuracy (R squared or mean absolute error).

prediction_accuracy = 1 - (sum((predicted_gain - actual_gain)^2) / sum((actual_gain - mean(actual_gain))^2))

The demo must show that ETAP predicts gains with at least 80 percent accuracy while testing only 4 out of 50+ possible groups, making the compute savings obvious.
