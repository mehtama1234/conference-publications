Don't Just Fine-tune the Agent, Tune the Environment

Instead of collecting expert examples to train an agent, let the agent learn directly from problem cases by slowly making them harder and giving it helpful feedback.

Paper explainersAll themesAgents & Tool Use

Training language model agents to use tools well usually means collecting lots of human-written examples, but that is slow and expensive. This paper proposes a different approach: give the agent a set of problem instances and let it learn by practicing on them, starting with easy ones and gradually increasing difficulty, while the system provides specific feedback when the agent gets stuck. This method needs far fewer examples because the agent learns from live practice rather than memorizing static examples, and handles new problems much better because it has learned the underlying patterns instead of the specific training cases.

Why training agents on tool use is stuck

Building an agent (a language model that calls functions to solve problems) is hard. The standard approach is supervised fine-tuning: collect hundreds of human-written examples of agents solving tasks correctly, then train the model to copy those examples. This works if you have a lot of data, but it does not.

Real tool-use problems are rare and expensive to annotate. With only a few examples, the agent overfits: it memorizes the specific problem instances it saw during training and fails on new ones. If you try standard reinforcement learning instead (reward the model when it solves a task), the model fails for different reasons — it has no idea where to start, so it wastes time on obviously bad moves, and the training is chaotic and unstable.

The problem in one sentence. Agents cannot learn tool use from rare data using existing methods, and both overfitting and RL instability make them brittle.

The algorithm as a flow

What it actually does

Start simple

Give the agent a pool of problem instances sorted by difficulty, easiest first.

Practice on one level

Run the agent repeatedly on the current difficulty tier until it solves problems correctly.

Detect and fix failures

When the agent makes a wrong move, the environment immediately shows the correct action.

Measure progress

Give a numerical reward that grows as the agent gets closer to a solution, so training is not noisy.

Gradually increase difficulty

Once the agent solves the current tier, move to harder problems and repeat.

What the paper changes

What the paper changes

The paper swaps out the data source. Instead of trying to train on static, pre-collected examples, the method trains directly on live problem instances, and the training environment actively decides what to show the agent at each moment.

the object it moves  =  the training data source and difficulty order
The hidden quantity

The hidden quantity: progress toward goal

measured quantity  =  step-wise progress signal

The paper measures and rewards how close the agent is to solving each problem at each step, not just whether it succeeds or fails at the end. If the agent is supposed to call function A then function B, it gets a reward boost when it correctly calls A (even if it has not called B yet), and another boost when it calls B, because awarding each intermediate step gives the training algorithm a clear direction toward the goal at every moment, not just a pass-fail verdict at the end. This is the progress reward.

The environment computes this by tracking which functions the agent has called and in what order, checking them against the correct solution path. The agent learns to maximize this fine-grained signal, so it does not waste time in dead ends.

Why it works

Why it works: three reinforcing pieces

The method works because it combines three things that work together. First, a curriculum (easy to hard) lets the agent build skills progressively. The agent learns the basic moves on simple instances where it can see the pattern clearly, then applies those skills to harder instances.

Second, when the agent gets stuck, corrective feedback shows the right move at that exact moment. This is much more direct than RL trial-and-error, where the agent might try hundreds of wrong moves. The agent sees what it should have done and learns from that concrete example.

Third, progress rewards (credit for partial success) keep the signal clean. Without them, an agent on a hard problem sees only failure feedback until it completely solves it, so it has no clear direction to optimize. With progress rewards, the agent gets a small numerical boost for each correct step, so the training update (the nudge toward better weights) always points the right way, because each small movement forward is immediately scored and the training algorithm can follow that score upward. These three pieces work together: the curriculum keeps the agent focused on achievable goals, corrective feedback fills in gaps, and progress rewards make the learning signal steady.

Math after the picture

The reward equation

First in words:

reward for this step equals a bonus for each correct function called so far, plus a bonus if the agent is moving closer to the goal, minus a penalty for wrong guesses

Then the compact form:

R = c * n_correct + d * progress_delta - p * n_wrong

Every symbol:

Rreward for this step
cpoint value for each correct function call
n_correctcount of functions called correctly so far
dbonus weight for moving closer to solution
progress_deltahow much closer the agent got in this step
ppenalty weight for each incorrect action
n_wrongcount of wrong function calls so far
A tiny worked example
Suppose c=1 (one point per correct step), d=2 (bonus for progress), p=0.5 (penalty for wrong moves).
Agent at easy problem: has called 2 functions correctly, moved one step closer to goal, made one wrong call.
R = 1*2 + 2*1 - 0.5*1 = 2 + 2 - 0.5 = 3.5 reward.
Same agent at hard problem makes same moves but is 0.1 steps closer (fractional progress): R = 1*2 + 2*0.1 - 0.5*1 = 2 + 0.2 - 0.5 = 1.7.
Easier problems give stronger signals, so curriculum learning makes sense: early training sees bigger rewards, cleaner training updates.

The reward grows for correct steps but shrinks for wrong ones, so the agent learns to nail the hard moves early and avoid fumbling.

What can go wrong

What can go wrong

Curriculum order matters. If problems are not ordered by true difficulty, the agent trains on too-hard instances first and fails to bootstrap. Sorting must be automatic and reliable.
Corrective feedback must be truthful. If the shown correct action is actually wrong or ambiguous, the agent learns false shortcuts. The ground truth solution for each problem must be validated.
Progress reward scope can be narrow. If the reward only credits narrow success (exact function sequence) and not broader progress (getting closer to the goal), the agent optimizes for brittle patterns and does not generalize.
Done right. Use an objective difficulty metric, verify solutions, and make progress credit all actions that reduce distance to the goal.
What a runnable demo should prove

What a runnable demo should prove

Build a small set of function-calling problems (e.g., convert temperatures, query a database, compose API calls in sequence) with easy and hard instances. Implement the three components: (1) difficulty ordering, (2) corrective feedback when the agent calls the wrong function, (3) a progress reward that awards points for each correct function reached. Train the agent on this curriculum, and at the end test it on problems it has never seen. Measure accuracy on seen problems vs. accuracy on new problems.

generalization_gap = in_distribution_accuracy - out_of_distribution_accuracy

The demo must show that curriculum + corrective feedback + progress rewards shrinks the generalization gap, so the agent solves new problems as well as it solves seen ones.
