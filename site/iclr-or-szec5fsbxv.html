FSPO: Few-Shot Optimization of Synthetic Preferences Effectively Personalizes to Real Users

FSPO teaches a language model to infer one user's preference rule from only a few pairwise choices, using large synthetic preference sets to learn that adaptation skill ahead of time.

Paper explainersAll themesOther

Personalization asks a model to stop producing a generic answer and instead produce the answer a particular user would prefer. The hard part is data. Real users rarely provide thousands of ratings, so a system has to infer (estimate from limited evidence) their taste from only a few examples. FSPO treats that as an adaptation problem rather than a standard one-user-fits-all reward model. During training, the model sees many synthetic users, each with a consistent preference pattern, and learns how to estimate a user-specific reward rule from a handful of comparisons. At deployment, a real user gives only a few labels, and the model applies the same user-specific estimation process to that new person. The method works when the synthetic users are diverse and internally consistent, because that training data spread teaches the model what kinds of preference rules real users might have and how to detect them quickly.

Zero assumption version

Why personalization is hard with only a few labels

Suppose two users ask the same question: "Explain this physics idea." One wants short direct answers, while the other wants more steps and formal wording. A generic model averages across many users, so it often gives an answer that fits neither well.

A direct way to personalize is to learn a reward model for each user from that user's preferences. But that fails in practice because most users provide only a few comparisons, such as "answer A is better than answer B." A reward model trained from so little data will overfit because it has too few examples to separate real taste from noise.

The paper reframes the problem. Instead of training one reward model from scratch for each user, train the base model across many users so it learns the meta-skill of rapid preference estimation. Then a few comparisons are enough because the model is no longer learning personalization from zero; it is selecting among preference patterns it already learned how to recognize.

The core move. Pretrain the adaptation rule on many synthetic users, then use a few real user comparisons to infer that user's reward function and steer generation.

The algorithm as a flow

What it actually does

Create many synthetic users

Generate users with stable preferences across a domain such as reviews, education, or open-ended question answering.

Sample support comparisons

For each user, keep a few labeled pairs that say which response they prefer.

Infer a user-specific reward rule

Condition the model on the small support set so it can estimate what this user values in an answer.

Optimize generation against that rule

Train the model to produce responses that score well under the inferred reward for that user.

Deploy with few real labels

At test time, replace the synthetic support set with a real user's few comparisons and use the same estimation process.

What the paper changes

What the paper changes

The paper changes the unit of learning from "one global reward model" to "a reward inference procedure conditioned on a support set." The model is trained to read a few examples of a user's choices and then act as if it had that user's reward model.

the object it moves  =  reward modeling as few-shot user adaptation
The hidden quantity

Preference coherence: the hidden quantity

measured quantity  =  How internally consistent each user's choices are

Synthetic data is only useful if each synthetic user behaves like one stable person. If the same synthetic user sometimes prefers concise answers and sometimes rejects them for no reason, the adaptation problem becomes ill-posed because the support set does not point to one clear reward rule.

So the hidden quantity is coherence: do that user's labels line up with one underlying preference pattern? High coherence matters because the few-shot learner must estimate a compact rule from only a few examples. If the examples contradict each other, the estimation step cannot decide what the user wants.

Why it works

Why synthetic users can help real users

The method does not expect synthetic labels to exactly match one real person. Instead, it uses them to learn the structure of personalization. Across many synthetic users, the model sees repeated patterns: some users value brevity, some value detail, some prefer encouragement, some prefer strict correctness. By training on that family of patterns, the model learns which clues in a support set identify each pattern.

At test time, a real user provides only a few comparisons. Those comparisons are informative because the model already knows how preference patterns usually vary. It can map the real user to a nearby reward rule and then generate answers that score well under that inferred rule.

The rationalized user description helps because it gives the model an explicit summary of the support set in words. That summary can stabilize adaptation when only a few comparisons are available, since the model can condition on both the raw choices and a compact statement of what those choices imply.

Math after the picture

The pairwise preference objective

First in words:

For a given user, the model should assign a higher score to the response that user chose. Training repeats that rule across many users and many small support sets, so the model learns how to infer the user-specific scoring rule.

Then the compact form:

L = -log sigma(r_u(y_plus) - r_u(y_minus))

Every symbol:

Lthe loss for one comparison
sigmathe logistic function that turns a score difference into a probability
r_u(y_plus)the inferred reward score for the preferred response under user u
r_u(y_minus)the inferred reward score for the rejected response under user u
uthe current user, described by a few support comparisons
A tiny worked example
Suppose a user prefers short direct explanations.
For one prompt, response A gets inferred score 2.0 and response B gets inferred score 0.5.
The score gap is 1.5, so the loss is small because the preferred answer is already ranked above the rejected one.
If the model reverses them, with A at 0.5 and B at 2.0, the score gap becomes negative and the loss grows.
Training pushes the model toward score functions where each user's chosen response sits above the rejected one.

The important part is that the reward function depends on the current user. The same response pair can be ranked differently for different users because their support sets imply different scoring rules.

What can go wrong

What can go wrong

Synthetic users are shallow or repetitive. If most synthetic users differ only slightly, the model learns a narrow family of reward rules and will not adapt well to real users whose preferences fall outside that family.
Support labels are noisy. With only a few comparisons, one mistaken label can shift the inferred reward rule sharply because each example carries a large fraction of the signal.
User preferences change across contexts. A user may want strict factual tone for one domain and playful tone for another. If the support set mixes those contexts without telling the model, the inferred reward can average them together and personalize poorly.
Done right. Build synthetic users that are diverse across users and consistent within each user, gather support comparisons that cover the target domain, and allow separate preference profiles when one user's taste depends on context, because each of those choices makes the few observed labels point more clearly to one reward rule instead of blending several incompatible ones.
What a runnable demo should prove

What a runnable demo should prove

Create a small generation task with several user types, such as concise, detailed, formal, skeptical, and encouraging. For each user type, make pairwise preferences over candidate responses. Train one model with ordinary global preference tuning and one with FSPO-style few-shot adaptation. Then hold out a few real users or manually written user profiles, provide only 3 to 5 preference comparisons for each, and compare which model produces responses those users prefer.

personalization_gain = user_preference_win_rate_fspo - user_preference_win_rate_global

The demo should show that few-shot adaptation beats global tuning when user data is scarce because the model learned how to infer a reward rule from tiny support sets rather than learning each new user from scratch.
