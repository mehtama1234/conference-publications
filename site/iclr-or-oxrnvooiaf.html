ConRep4CO: Learning Shared Representations Across Optimization Problems

When you show a model the same optimization problem in two different forms, it learns richer patterns that work across many problem types.

Paper explainersAll themesRepresentation & Self-Supervised Learning

Optimization problems come in many flavors - graph problems, scheduling problems, packing problems - but they often have deeper similarities. ConRep4CO teaches a model to spot these hidden patterns by showing it the same problem twice: once in its original form, and once translated to a universal form called Boolean satisfiability (SAT). This creates a richer mental model that transfers to new problems and scales to larger instances.

Zero assumption version

The problem: each optimization problem teaches you nothing about the others

Optimization problems are puzzles where you want to find the cheapest or fastest or best answer subject to constraints. Traveling salesman (visit all cities once, shortest route), graph coloring (color a map with few colors, no neighbors the same), maximum independent set (pick the largest subset of nodes with no edges between them) - these look different on the surface. A model trained on one problem type has to start from scratch on another.

The naive approach: train separate models for each problem type. This works for individual problems, but it misses the deep patterns. When you move to a new problem type or a larger version of the same problem, your model is lost. It has learned surface tricks, not the underlying structure of what makes an optimization problem hard.

The core idea: Show a model the same problem in two different forms - original and translated to SAT - so it learns patterns that generalize across problem types and scales.

The algorithm as a flow

What it actually does

Take an instance

Start with one optimization problem in its natural form (a graph coloring instance).

Translate to SAT

Rewrite the same problem as a Boolean satisfiability instance - all NP-complete problems can be encoded this way.

Create the pair

Original form and SAT form are treated as representing the same underlying problem - a positive pair.

Learn by contrast

Model learns to map both forms to similar representations while pushing other problems' representations away.

Transfer the model

The shared representation transfers to new problem types and instances without retraining.

What the paper changes

What the paper changes: the representation

ConRep4CO changes how the model encodes each problem into numbers. Instead of learning problem-specific codes, it learns a shared representation space where the same problem looks the same regardless of how it is written - whether as a graph coloring problem or a SAT formula.

the object it moves  =  problem representation
The hidden quantity

The hidden quantity: structural similarity

measured quantity  =  structural similarity across forms

Structural similarity is how much a model's internal representation of one problem form matches its representation of the same problem in a different form. If the model truly captures the problem's essence, the original and SAT version should look identical inside the model.

ConRep4CO measures this by comparing the internal vectors (the list of numbers) the model produces for each form. It uses contrastive loss - a method that rewards matching representations when they should match and punishes mismatches. The paper learns representations by maximizing how similar the same problem looks across its two forms while minimizing similarity to unrelated problems.

Why it works

Why it works: universal form reveals universal patterns

The deep reason ConRep4CO works is that NP-complete problems can all be translated into each other - they are all equally hard, which means their hardness comes from a shared structural origin. When you force the model to see graph coloring and its SAT translation as the same thing, you are telling it: this is not surface syntax, this is structure.

This works because SAT is a canonical form - a universal language all NP-complete problems can be written in. By anchoring representations to SAT, the model learns patterns that are independent of the original notation. A node-coloring constraint and a variable-assignment constraint have the same underlying logic when you look through the SAT lens. The shared representation acts like a Rosetta Stone - once the model understands the SAT version, it recognizes that same structure in any NP-complete problem dressed in any original clothing.

For scaling, the same logic applies. A larger instance is still the same problem, just more of it. A representation anchored to SAT structure will recognize a size-10 graph and a size-100 graph as the same type of problem, not a different problem, because it is learning structure, not memorizing specific node counts.

The contrastive loss equation

First in words:

Loss equals negative log probability that the model ranks the correct SAT form highest among all negatives, plus a symmetric term.

Then the compact form:

L = -log( exp(sim(h_orig, h_sat) / tau) / (exp(sim(h_orig, h_sat) / tau) + sum_neg exp(sim(h_orig, h_neg) / tau)) ) + symmetric

Every symbol:

h_origthe internal vector for the original problem form
h_satthe internal vector for the SAT translation of the same problem
h_neginternal vectors for other unrelated problems
sim(a,b)cosine similarity: how aligned two vectors are, from -1 (opposite) to 1 (same)
tautemperature: a scaling knob (higher = softer distinctions, lower = sharper)
exp(x)exponential: turns similarities into probabilities that sum to 1
Tiny worked example with numbers
Suppose a graph coloring problem has h_orig = [0.8, 0.2], h_sat = [0.75, 0.25], and two negatives have [0.1, 0.9] and [0.3, 0.8].
Similarity sim(h_orig, h_sat) = 0.8*0.75 + 0.2*0.25 = 0.65 (they are similar, good).
Similarity sim(h_orig, h_neg1) = 0.8*0.1 + 0.2*0.9 = 0.26 (dissimilar, good).
With tau=1: exp(0.65)=1.92, exp(0.26)=1.30, exp(0.32)=1.38.
Prob of ranking SAT first = 1.92 / (1.92 + 1.30 + 1.38) = 0.39, loss = -log(0.39) = 0.94.
The loss goes down as h_sat and h_orig become more similar and negatives become more different - the model pulls the correct pair together.

The equation rewards the model for making the same problem look the same across its two forms while treating different problems as unrelated, exactly like learning that two photos of the same object are similar even if taken from different angles.

What can go wrong

What can go wrong

Bad SAT encoding. If the translation from the original problem to SAT loses information or adds spurious constraints, the model learns a corrupted correspondence. The representation learns the encoding noise, not the problem structure.
Mixing hard and easy problems. If your negative samples include structurally similar problems, the contrastive loss confuses the model - it learns to push away things that are actually similar. Negatives must be truly unrelated.
Transfer to a fundamentally different problem class. ConRep4CO learns patterns shared among NP-complete problems. If you try to transfer to a polynomial-time solvable problem (a completely different hardness class), the learned patterns do not apply.
Done right. Train on diverse NP-complete problems with accurate SAT encodings, use truly unrelated negatives, and apply the learned representation only to new instances of NP-complete problems. Then transfer works and scales.
What a runnable demo should prove

What a runnable demo should prove

Build a small dataset of five graph decision problems (graph coloring with 3 colors, maximum independent set, minimum vertex cover, clique finding, maximum matching). Create SAT encodings for each. Train a model using contrastive pairs (original form and SAT form of the same instance). Then test: (1) does the model produce similar representations for the original and SAT versions of a held-out instance? (2) Does the model trained only on instances of size 20 succeed on size 40 instances of the same problem types? (3) Can the model be fine-tuned on a new problem type (say, graph coloring) with far fewer examples than a model trained from scratch?

scale_transfer = (accuracy_at_2x_size + accuracy_at_4x_size) / (2 * accuracy_at_original_size); representation_alignment = cosine_similarity(encoding(original_form), encoding(sat_form))

The demo succeeds if scale_transfer > 0.9 and representation_alignment > 0.8 - the model sees the problem as one concept, stable across form and size.
