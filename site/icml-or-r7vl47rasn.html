LIBERO-Gen: Exposing VLA Brittleness via Distributional Shifts

A diagnostic benchmark that reveals why high-scoring vision-language-action models fail in the real world by testing them on intentional environmental shifts.

Paper explainersAll themesRobotics & Control

Vision-language-action models (software trained to understand images and language, then pick robot actions) score well on standard tests but collapse in the real world. LIBERO-Gen is a benchmark that deliberately changes the robot's environment in three specific ways—keeping it simple, mixing learned behaviors, and testing new situations—to expose the actual weak points: the model mistakes tiny visual changes for different tasks, and forgets how its chosen actions should feel.

Zero assumption version

High scores hide brittleness

Today's vision-language-action models (trained to read images, understand instructions, and pick robot actions) pass standard tests with high accuracy. In the lab, they work. Deployed in a real warehouse or kitchen, they fail on small changes: a cup in a different spot, a slightly different lighting, the same task phrased differently.

A naive approach asks: just test the model on more environments. But that misses the real issue. The model is not learning to understand tasks abstractly; it is memorizing surface patterns in the training data. When those patterns shift—even slightly—the model's confidence collapses or it picks wildly wrong actions. The standard benchmark scores mask two opposite failure modes: the model clings to the wrong features (spurious invariance; it thinks a green table means "grasp left" even when the task has nothing to do with tables), and it panics at harmless changes (extreme brittleness; moving the table one inch breaks everything).

In one sentence. Standard benchmarks do not catch that vision-language-action models mistake tiny visual changes for task changes, and forget how their chosen actions should move the robot.

The algorithm as a flow

What it actually does

Step 1: Start in-distribution

Give the model tasks it saw during training, same visual conditions.

Step 2: Mix learned skills

Combine actions from different training tasks in ways the model never practiced.

Step 3: Shift the domain

Move the robot to a new environment, different lighting, objects, or scene layout.

Step 4: Measure separately

Score accuracy on each type separately, not averaged together.

Step 5: Uncover failure modes

Compare the three scores to see if the model is brittle, rigid, or able to adapt.

What the paper changes

What the paper changes

The paper redesigns the benchmark itself—specifically, which tasks and environments the model is tested on, and how those tests are scored. Instead of one mixed score, tests now report three separate numbers: how well the model handles tasks exactly like training (in-distribution), how well it mixes skills from different training tasks (compositional), and how well it transfers to entirely new visual environments (domain generalization).

The hidden quantity

The hidden quantities: perceptual instability and action binding

measured quantity  =  perceptual instability and action binding collapse

The paper identifies two key failure modes hidden in single benchmark scores. Perceptual instability means the model's chosen action flips or changes dramatically when the visual input shifts only slightly—the model is hypersensitive to pixel-level details it should ignore. Action binding collapse means the model forgets which physical motion should follow from its chosen action; it picks the right label but executes the wrong arm movement or grasp strength.

LIBERO-Gen measures these by running the model through controlled visual shifts and action recombinations, then tracking where accuracy drops sharply. A model with low perceptual instability keeps its choice stable across small visual shifts. A model with intact action binding performs the right physical motion consistently when asked to reuse skills from different tasks.

Why it works

Why high scores mask real brittleness

Standard benchmarks average the model's performance across all test cases—easy and hard, in-distribution and shifted. When the model scores 88% overall, that average hides a deeper pattern: it might score 95% on familiar scenes but only 10% on new lighting, or 99% on single skills but 15% on skill combinations the model never practiced. The single number obscures which failure mode dominates.

LIBERO-Gen separates the tests intentionally. By reporting three independent scores—in-distribution, compositional, and domain shift—it forces the true pattern to emerge. A model that drops from 95% to 5% on domain shift is actually far more brittle than one that drops from 88% to 75%. The second model can adapt; the first is fragile and the benchmark had hidden that fragility.

Why does this happen? Because the model's internal representations (the numbers that encode what it sees and what action to take) are tangled to the specific visual conditions in training data. When the table color changes, the model's image-understanding network outputs a different set of numbers, which triggers a different motion through the action network. During training, the model learned that red tables always meant one action and blue tables meant another—even if the real task was the same. The benchmark never showed the model a red table with the opposite task, so it had no reason to separate the color from the task choice. In reality, a table's color is just decoration; the task instruction is what matters. But the model found a shortcut: memorize which colors go with which actions, and it will pass the test faster than learning the abstract task. The standard benchmark rewarded this shortcut, so that is what the model learned.

Scoring the shift: accuracy across test suites

First in words:

accuracy on in-distribution + accuracy on compositional + accuracy on domain shift, reported separately

Then the compact form:

accuracy_indist = correct_indist / total_indist, accuracy_comp = correct_comp / total_comp, accuracy_domain = correct_domain / total_domain

A tiny worked example
In-distribution accuracy: 91 right out of 100 tasks = 91%
Compositional accuracy: 58 right out of 100 mixed-skill tasks = 58%
Domain-shift accuracy: 21 right out of 100 new-scene tasks = 21%
Average (old way): (91 + 58 + 21) / 3 = 57% — hidden the real stratification.
Separated (new way): report all three — 91% | 58% | 21% — shows the model is strong in-distribution but collapses on new environments.

Separating the three scores reveals stratification; a single averaged number would bury the brittleness.

What can go wrong

What can go wrong

Perceptual instability: tiny visual shifts trigger wrong actions. If the model relies on surface features (table color, lighting angle, object position) rather than semantic task understanding, small shifts cause action flips. A cup moved 2 inches should not matter, but if the model bound its choice to exact pixel location, the action changes.
Action binding collapse: model picks the right task but executes the wrong motion. When the model is asked to reuse a learned skill in a new context (e.g., grasp-left from task A in the context of task B), the action network may forget the physical meaning of that choice. It picks the label but outputs the wrong force or trajectory.
Spurious invariance: model ignores semantic shifts, relies on irrelevant features. The model learns that red tables mean pick-with-left-hand even when the task is unrelated to table color. It becomes insensitive to real changes (task instructions) while hypersensitive to fake ones (decorative details).
Done right: LIBERO-Gen tests catch these before deployment. A model that passes LIBERO-Gen's three separate test suites has shown it handles in-distribution tasks reliably, can compose skills from training, and adapts to new visual environments. These are the true markers of deployment readiness.
What a runnable demo should prove

What a runnable demo should prove

Build a small robot simulator with three tasks: pick the red cup, move the blue block, push the green button. Train a vision-language-action model on these three tasks in a fixed environment. Then test it on: (1) the same tasks in the same environment (in-distribution), (2) the same tasks but with the cup, block, and button in different positions (compositional), and (3) the same tasks but with different lighting and background colors (domain shift). Measure accuracy on each test suite separately.

score_indist = accuracy on fixed training conditions, score_comp = accuracy when objects move, score_domain = accuracy when lighting/scene changes

The demo must show a large gap between score_indist and score_domain. If the model scores 90% in-distribution but only 20% with new lighting, that gap is not a limitation of the benchmark—it is the true brittleness that real-world deployment would hit first.
