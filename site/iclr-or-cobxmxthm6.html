AgentSynth: Task Generation via Information Asymmetry

Generate hard computer-use tasks by exploiting the gap between step-by-step solving (easy) and solving everything at once (hard).

Paper explainersAll themesLLMs & Foundation Models

Building a computer-use agent requires thousands of tasks where the agent must click, type, and navigate real software. Humans can write these, but it is expensive and slow. AgentSynth uses a trick: tasks that are trivial to solve one step at a time become genuinely hard when the agent must plan all steps at once. This information asymmetry lets one machine generate the subtasks and another machine stitch them together into long chains. The result is over 6,000 diverse tasks at just 60 cents each.

Zero assumption version

Expensive and slow task collection

Computer-use agents are LLMs trained to control a computer by reading screenshots and outputting mouse clicks and keystrokes. To teach one to click on a calendar, type an email, and save a file, you need thousands of real-world task traces — recordings of a human completing realistic goals. Each trace is a sequence of screenshots paired with the actions that caused them.

Humans can write these traces, but the work is tedious. A person must manually craft a task (find and book a hotel in Portland), perform it on a real desktop, record each step, and verify the trace works. Scaling this to thousands of diverse tasks means hiring many people for weeks.

A beginner might try: hand the task to an LLM and ask it to generate a sequence of actions directly. But LLMs struggle to plan and execute a whole task from scratch without a human to guide them step-by-step.

The problem in one sentence. Collecting computer-use task data by hand is expensive; asking a machine to plan and execute whole tasks from scratch is unreliable.

The algorithm as a flow

What it actually does

First LLM generates subtasks

Ask a generator model: given a screenshot, what simple action could someone do next?

Each subtask is independent

Each one is trivial in isolation — click here, type this. An agent solves it in one or two steps.

Chain them together

A summarizer LLM reads all the subtasks and writes a single long-horizon task that encompasses all of them.

Control difficulty by length

Chain 5 subtasks for a level-1 task (easy); chain 40 for a level-6 task (agents fail 96% of the time).

Verify and label

Run the agent on the generated task, record success or failure, and keep the reliable traces.

What the paper changes

What the paper changes

Most task generation pipelines ask a machine to invent and solve a complete task in one shot. AgentSynth separates the problem: one model generates small, solvable pieces (subtasks); a different model composes them into a single hard objective. The composition step is the key move — it takes individual pieces that are easy to create and execute, and stitches them into something that defeats the original agent.

The hidden quantity

The hidden quantity: Information asymmetry gap

measured quantity  =  Forward-backward difficulty ratio

Information asymmetry is the gap between two directions: solving a chain of subtasks one-by-one (forward) versus inferring the entire chain from a single composite task (backward). In the forward direction, an agent sees a subtask and its current screen — it responds with one action. Easy. In the backward direction, an agent reads a long-horizon task description and must mentally simulate all intervening states to plan the sequence. Hard.

AgentSynth measures this gap by observing agent success on subtasks (usually high, because each is simple) versus success on the composed task (usually low, because the agent must hold many steps in mind and avoid getting lost). The paper does not state a formula, but the mechanism relies on this asymmetry: tasks generated in the easy direction become genuinely difficult in the hard direction because the agent cannot use the same step-by-step hints.

Why it works

Why it works: Asymmetry makes generation cheap and evaluation hard

The mechanism has two parts: generation and composition. In generation, the first LLM is asked to produce single subtasks (e.g., open a file, create a folder). This is easy for the LLM because each subtask is isolated — it does not need to remember previous steps or foresee future ones. Generating 6,000 of these takes little reasoning and costs very little (fractions of a cent per task).

In composition, a second LLM reads all the subtasks and writes a single task description that encompasses them (e.g., organize my files by creating a photo album and adding all images to it). This composite description does not repeat the step-by-step breakdown; it only states the goal. When an agent later receives this composite task, it sees no hints about intermediate steps. The agent must now invent the entire sequence on its own — a much harder problem than executing each subtask in sequence. An agent that solved each subtask easily (100% success on simple tasks) fails on the composition (4% success on hard tasks). This failure is not a flaw; it is the point. The paper exploits the asymmetry to create a hard benchmark automatically.

Difficulty is controlled by the number of subtasks in the chain. Five subtasks composed together yield a level-1 task (agents ~18% success). Forty subtasks yield a level-6 task (agents ~4% success). The paper shows that doubling the chain length roughly halves the agent success rate, proving that the composed chain is the source of difficulty.

How difficulty scales with chain length

First in words:

success_rate = base_rate × (0.5 ^ chain_length_factor), where base_rate is the agent's success on one subtask and chain_length_factor encodes how many subtasks were composed.

Then the compact form:

success_rate(L) ≈ c × r^L

Every symbol:

Lnumber of subtasks in the composed chain
rdifficulty multiplier per subtask (roughly 0.5 to 0.7)
cbaseline success rate on simple tasks (near 1.0)
success_rate(L)agent success on the level-L task
A tiny worked example
Assume baseline success on one subtask c = 1.0 (agent solves it 100% of the time).
Assume difficulty multiplier r = 0.5 (each additional subtask halves success).
Level 1 task (5 subtasks): success = 1.0 × 0.5^5 = 0.03, or 3%. But paper reports 18% — agents do better because subtasks overlap or simplify the search.
Level 6 task (40 subtasks): success = 1.0 × 0.5^40 = extremely low, but paper reports 4% — real agents use some memory and partial planning.
The model is illustrative: it shows exponential decay; real numbers depend on agent architecture.

Longer composed chains reduce agent success exponentially because the agent must hold more intermediate states in memory and avoid getting lost.

What can go wrong

What can go wrong

Subtasks do not compose cleanly. If subtasks have conflicting preconditions (e.g., opening file A and file B in the same step), the composed task becomes impossible. The pipeline requires a verifier to check that the chain is valid before labeling it as a benchmark.
Agent overfits to subtask structure. If the composed task accidentally preserves patterns from the subtasks (e.g., tasks always open the file menu first), an agent trained on AgentSynth tasks might memorize the pattern rather than learning general reasoning. Diversity in subtask ordering mitigates this.
Unintended shortcuts emerge. The LLM summarizer might compose tasks that have unintended shortcuts — ways to complete the goal that skip the intended steps. An agent discovers the shortcut and claims 100% success, even though it did not learn the planned reasoning.
Done right. Verify each composed task by running an agent on it and checking that the task is solvable and diverse from other tasks. Use multiple summarizer prompts to avoid repetition. Sample subtasks uniformly from the space of possible actions to ensure coverage.
What a runnable demo should prove

What a runnable demo should prove

A minimal demo shows the core insight: information asymmetry exists. Build a simple task (navigate a file system, say; open a folder, create a file, type content, save). (1) Ask an agent to complete each subtask in sequence with hints (step-by-step mode). Measure success. (2) Ask the same agent to complete the composed task with no hints (end-to-end mode). Measure success again. The difference is the asymmetry gap. Then, (3) show that the gap grows as the number of subtasks increases.

asymmetry_gap = success_with_hints - success_without_hints. Higher gap means the composition was effective.

If the gap is zero, the agent either solved it both ways (no asymmetry) or failed both ways (no gain from step-by-step hints). A large gap proves that step-by-step generation exploits real information asymmetry.
