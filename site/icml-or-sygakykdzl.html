CoME: Empowering Channel-of-Mobile-Experts with Informative Hybrid-Capabilities Reasoning

CoME splits mobile-agent work into four specialist channels and trains a router to activate the right specialist at each stage so planning, screen reading, and action choice cooperate cleanly.

Paper explainersAll themesAgents & Tool Use

A mobile agent has to do several different jobs during one task. It must summarize the current screen, plan the next subtask, choose the next action, and produce an executable action function. Many systems ask one dense model to do all of this at once. That can work, but the capabilities interfere with each other because the best skills for screen summary are not the same as the best skills for low-level action generation. CoME addresses this by creating four specialists, each aligned with one reasoning stage, and a router that chooses which specialist should speak at each moment. The paper then trains the system in stages so each specialist improves on its own, the router learns stage alignment, and the full chain learns to cooperate with fewer weak intermediate steps.

Zero assumption version

Why one mobile agent struggles to do every stage well

A mobile task is not one reasoning problem. Reading the screen, deciding the next subgoal, choosing the next action, and generating the exact action function require different kinds of information. When one dense model handles all four stages, improvements in one stage can hurt another because the model must share the same internal capacity across conflicting jobs.

This causes two practical problems. First, the model may never become strong at any one stage. Second, mistakes in early stages can spread forward because weak screen summary leads to weak planning, which then leads to weak action choice. The paper aims to separate the capabilities enough that each one can improve while still producing one coordinated mobile agent because the routed specialists can hand off stronger stage outputs to each other.

The move. Train separate specialists for screen summary, subtask planning, action decision, and action execution, then route generation through the right specialist at each stage and reward intermediate steps that add useful information.

The algorithm as a flow

What it actually does

Split the mobile task into four stages.

Define separate roles for screen summary, subtask planning, action decision, and action function so each stage has a clear objective.

Train each specialist first.

Use Expert-FT to strengthen each specialist on its own role because stage-specific improvement is easier when capacities are not mixed too early.

Train the router.

Use Router-FT so the system learns when each specialist should generate output, which matters because the right capability depends on the current stage.

Train cooperation across the full chain.

Use CoT-FT so the specialists work together smoothly instead of behaving as isolated modules.

Prefer informative intermediate reasoning.

Use Info-DPO to reward stage outputs that help later stages, because stronger intermediate information reduces error propagation.

What the paper changes

What the paper changes

The paper changes mobile-agent reasoning from one dense undifferentiated generator into a routed multi-specialist system where each reasoning stage has its own expert.

the object it moves  =  mobile-agent reasoning divided by stage
The hidden quantity

The hidden quantity: stage usefulness

measured quantity  =  how much each intermediate stage output helps the next stage make a better decision

The key quantity is stage usefulness. A screen summary is not valuable merely because it sounds fluent. It is valuable when it helps the planner identify the right subtask because the next stage depends on that summary to choose the correct near-term goal. The same rule holds for every stage. The paper focuses on whether one stage produces information that materially improves the next one because each later decision is only as good as the handoff it receives.

Info-DPO estimates this by measuring information gain from intermediate steps. If a summary, plan, or action decision makes later steps more accurate, it should be preferred. That matters because mobile-agent failures often begin with weak intermediate outputs that sound plausible but do not guide the next stage well.

Why it works

Why it works

Specialization helps because the four mobile-agent stages require different behaviors. Screen reading emphasizes perception, subtask planning emphasizes task structure, action decision emphasizes local choice, and action execution emphasizes device control. A single dense generator must compromise across all four jobs.

Routing matters because stage order is predictable but not enough by itself. The system must still learn which specialist should produce the current output and how those outputs should fit together. Router-FT gives that alignment signal directly.

Info-DPO matters because multi-stage systems fail when early outputs are superficially acceptable but not actually useful. By rewarding information gain, the training objective pushes each stage to contribute something that helps the next stage act better. That reduces error spread across the chain.

Math after the picture

The routing objective

First in words:

At each reasoning stage, pick the specialist whose output is most useful for the current stage and the next downstream step.

Then the compact form:

expert_t* = argmax_e gain(stage_t, e)

Every symbol:

expert_t*the specialist selected at stage t
stage_tthe current reasoning stage such as screen summary or action choice
ea candidate specialist
gain(stage_t, e)how much useful information specialist e adds for the current and next stage
A tiny worked example
Suppose the current screen shows a search page with several product cards.
The screen-summary specialist can describe which filters are active and which cards are visible.
The action-function specialist can generate a tap command, but that is premature because the task still lacks a clear subtask.
The router should therefore pick the summary specialist first because that output gives the planner the information it needs.
Later, after the planner chooses a target product, the router can switch to the action-function specialist because the task has moved to execution.

The equation states the paper's core routing rule: use the specialist that adds the most useful information at the current stage.

What can go wrong

What can go wrong

The router can choose the wrong specialist. If stage alignment is poor, the system may ask for execution output before the task has been summarized well, so later steps start from weak information.
Specialists can overfit their own stage. A strong local expert can still hurt the full chain if it ignores what the next stage needs, because mobile reasoning depends on useful handoff between stages.
Weak intermediate data can mislead Info-DPO. If the preference signal does not reflect real downstream usefulness, the training rule may reward polished but unhelpful intermediate outputs.
Done right. The method works when stage boundaries are clear, routing is well aligned, and intermediate outputs are judged by downstream usefulness, because that keeps the full reasoning chain coherent.
What a runnable demo should prove

What a runnable demo should prove

Build a small phone or emulator task set that requires reading a screen, setting a near-term subtask, deciding an action, and issuing an executable command. Compare one dense agent against a four-stage routed system. Record not only final success but also whether each intermediate output helps the next stage. The demo should show that the routed specialists make fewer stage-to-stage errors because each part of the chain is trained for its own job and for useful handoff.

handoff_success = downstream_steps_helped_by_intermediate_output / total_intermediate_outputs

A convincing demo must show stronger intermediate handoff, not only a better final score, because CoME is designed to improve the full reasoning chain stage by stage.
