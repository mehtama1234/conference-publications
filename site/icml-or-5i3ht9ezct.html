TSFAdv: Frequency-Guided Black-Box Adversarial Attacks on Time Series Forecasting

Adversarial attacks on time-series forecasts can trick models by perturbing the frequency content of the input signal, even with limited query access.

Paper explainersAll themesTime Series & Sequential

Time-series forecasting models predict future values in streams like electricity demand or sensor readings. These models, when deployed as black-box services (where you only see predictions, not internals), are vulnerable to carefully crafted fake inputs called adversarial perturbations. This paper shows that an attacker can make high-quality forecasting models fail dramatically by tweaking the frequency content of the input signal in a smart way, even when restricted to only 200 queries.

Zero assumption version

Why time-series forecasting is fragile to frequency manipulation

Time-series forecasting models learn patterns from sequences of numbers over time. When deployed as a black-box API (you send in past values, get back a forecast, but cannot inspect the internals), these models are usually trusted to work correctly. A beginner might assume that random noise or small tweaks to the input would barely affect the output.

But the paper reveals a deeper vulnerability: these models are extremely sensitive to changes in the frequency content of the signal. If you carefully modify which frequencies are present (the pitch and speed of oscillations in the data), the model's predictions break even though the overall "shape" of the data looks similar to a human eye. An attacker with just 200 allowed queries can find exactly which frequency changes cause the biggest forecasting errors.

In one sentence. Tweaking the frequency spectrum of time-series input can fool the best forecasting models, even with a tiny budget of allowed queries.

The algorithm as a flow

What it actually does

Probe model sensitivity

Attacker sends signals with different frequency components, observing how each changes the forecast error.

Estimate direction using evolution strategies

A random-search method estimates which direction in frequency space causes the most damage, without needing the model's internal weights.

Craft frequency-domain perturbation

Based on sensitivity estimates, construct a targeted change to magnitude and phase of specific frequencies.

Evaluate trajectory-level damage

Instead of checking single-point error, measure whether the entire predicted sequence has wrong shape and direction.

Iterate within query budget

Repeat probing and refinement until 200 queries are exhausted, reaching maximum forecast degradation.

What the paper changes

What the paper changes

The paper targets the frequency spectrum of the input signal: specifically, the amplitude and phase at different frequencies. By carefully perturbing these, without access to the model's weights or training process, an attacker can degrade forecasts dramatically.

the object it moves  =  frequency spectrum of input
The hidden quantity

The hidden quantity: frequency sensitivity

measured quantity  =  frequency sensitivity score

The paper measures a quantity that does not appear in standard model outputs: which frequencies the model depends on most for accurate predictions. A time-series signal can be decomposed into a sum of sine waves at different frequencies (this is called the Fourier transform). Some frequencies might be critical for the model's logic, while others are noise.

The paper estimates this sensitivity by testing: if I boost or flip the phase of frequency F, how much worse do predictions become? Frequencies with big effects on error are sensitive; frequencies with no effect are not. The attacker uses these sensitivity scores to know where to strike.

Why it works

Why frequency perturbations break forecasts

Time-series forecasting models are trained on real data with natural frequencies (seasonal patterns like daily/weekly cycles, trends, noise). When the model learns to forecast, it implicitly learns which frequencies signal true future patterns and which are random wiggles to ignore.

If an attacker removes or inverts the frequencies the model trusts most, the model has no reliable signal left. For example, if the model learned that a strong daily cycle means steady demand tomorrow, but the attacker removes the daily cycle from today's signal, the model cannot forecast accurately. The frequencies the model learned are the frequencies it needs. Change those, and prediction breaks.

The attacker can find these critical frequencies quickly using a random-search method (Natural Evolution Strategies) that estimates sensitivity without needing the model's internal workings. Instead of guessing blindly, this method tries small random perturbations around a current best guess and keeps the direction that causes more error. By repeating this process, it narrows in on the most damaging frequency changes. After 200 queries, the attacker has a frequency-domain adversarial input that maximizes error.

The perturbation equation

First in words:

forecast_error equals a distance metric between predicted and true trajectory. Attacker aims to maximize this by adding frequency perturbation delta_f to the input spectrum.

Then the compact form:

max_delta_f [ DTW(forecast(input + delta_f), true_future) + lambda * SME(forecast(input + delta_f), true_future) ]

Every symbol:

delta_fthe frequency-domain perturbation (amplitude and phase changes at each frequency)
DTWDynamic Time Warping: a distance metric that measures how different two sequences' shapes are
SMESlope Misalignment Error: measures whether the directions and speeds of change are wrong
lambdaweight balancing the two error metrics
input + delta_foriginal time series plus the adversarial frequency perturbation
A tiny worked example
Scenario: 4-step forecast of electricity demand, true values [95, 100, 102, 105] kWh.
Model predicts [96, 99, 101, 106] without attack: DTW distance ≈ 2.0, SME ≈ 0.1, total error ≈ 0.1+0.1=0.2.
Attacker removes the weekly frequency (critical for demand patterns) from input: model now predicts [80, 85, 88, 92].
New DTW distance ≈ 20.0, SME ≈ 5.0, total error ≈ 20.0+5.0=25.0.
Error jumped 125x. One carefully chosen frequency removal broke the forecast.

The attacker searches over frequency perturbations delta_f to maximize this error, using random search (evolution strategies) within 200 queries.

What can go wrong

What can go wrong

Query budget exhausted before convergence. The attacker has only 200 queries. If the frequency space is very high-dimensional, 200 random samples may not find the best attack direction. With more queries allowed, evolution strategies would narrow in more precisely on worse perturbations, because each extra sample steers closer to the worst error.
Input preprocessing or smoothing. If a deployment smooths or filters the input before feeding it to the model, high-frequency perturbations may be removed. The attack targets frequencies the model sees, not frequencies the attacker can inject.
Defenses designed for frequency domain. The paper shows existing defenses (adversarial training, input perturbation) do not work. But a model trained explicitly to resist frequency perturbations might work.
Attack succeeds when model relies on few, vulnerable frequencies. If a forecasting model learns many overlapping frequency cues (so losing one does not break everything), removing one frequency hurts less. The attack is most dangerous when the model uses only a few critical frequencies.
What a runnable demo should prove

What a runnable demo should prove

Build a simple LSTM or RNN time-series forecasting model trained on synthetic data with a strong daily cycle (e.g., sine wave plus noise). Then implement TSFAdv: use random search (evolution strategies) to find a frequency perturbation that maximizes forecast error under 200 queries. Measure error before and after using DTW and SME metrics.

improvement = (error_with_attack - error_clean) / error_clean * 100%

The demo must show that a frequency perturbation found in just 200 queries can degrade forecast error by 30%+ on an undefended model, even though the adversarial input looks visually similar to the clean data.
