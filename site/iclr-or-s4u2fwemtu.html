ADAPT-Z: Online Time Series with Feature Adjustment

When a time series model's predictions arrive before the true answers, adjust the learned features instead of the weights, using old gradient directions to steer even with delayed truth.

Paper explainersAll themesTime Series & Sequential

In real-world time series forecasting, data patterns keep changing — a factory sensor drifts, weather patterns shift, stock markets react to news. A model trained yesterday becomes stale. The paper proposes ADAPT-Z: when a new observation finally arrives (sometimes days later), instead of retraining weights, nudge the model's learned feature representations using a saved record of which direction the error was pointing at prediction time, so delayed feedback still guides learning.

Zero assumption version

Time series data that changes, with answers that arrive late

In real forecasting, the world shifts. A model trained on January data may not fit February. Online learning — updating the model as new data comes in — is the natural fix.

But time series forecasting has a cruel twist: when you predict tomorrow's value, you don't know if you were right until tomorrow actually arrives. In multi-step forecasting (predicting days or weeks ahead), the true answer comes even later. By then you've made more predictions, the model has drifted further, and the gradient (which direction to nudge the weights) points backward to stale decisions.

Naive approaches retrain the last layer or adapt a small module, but they adjust weights based on gradients that no longer match the current feature state. The features have moved on, the feedback is old, and the update fights the present patterns.

The idea in one sentence. Update the feature representations (not the final weights) using a stored gradient direction, so delayed feedback still steers the model toward the new pattern.

What the paper changes

What the paper changes

The paper changes what gets updated when delayed feedback arrives: not the final-layer weights, but the learned feature representations in the middle layers.

the object it moves  =  feature representations
The hidden quantity

The historical gradient direction

measured quantity  =  stored gradient memory

The paper measures and stores a hidden quantity: the gradient direction computed when each prediction was made. This gradient says which way each feature should move to shrink the error on that old prediction.

When the true answer arrives late, the paper retrieves this stored gradient and uses it to adjust features. The stored direction is old, but it was computed when the feature state was also different — it points backward in time, reconnecting delayed truth to the moment of prediction.

Why it works

Why storing and replaying the gradient works

Normally, when delayed feedback arrives, the model's features have already shifted to track new patterns. A naive weight update based on the old gradient pulls the wrong lever. The mechanism here is different: instead of updating weights (which are shared across many predictions), update the learned features directly along the direction the old gradient indicated.

Why does this work? Because features learned by neural networks capture the underlying structure in the data — the latent factors (trend, seasonality, noise level, regime). When the data pattern shifts (the weather becomes more volatile, the customer behavior changes), these factors change. Updating feature representations directly allows the model to re-calibrate which latent factors matter, because the representations directly encode what to look for; the weights that combine them only matter when the representations are right. The stored gradient acts as a time capsule: it points in the direction that mattered for that old prediction, and replaying it now lets the representations learn the new factors. Weights stay fixed because they are shared across many predictions — changing one weight would affect decisions made on all future data, while adjusting one feature only tunes the learned structure for this specific shift, leaving other patterns intact.

Math after the picture

The update rule

First in words:

New feature equals old feature plus learning rate times stored gradient times a small decay factor.

Then the compact form:

z_new = z_old + alpha * g_stored * exp(-delay_steps / tau)

Every symbol:

z_newupdated feature representation
z_oldthe current learned features
alphalearning rate (how much to nudge)
g_storedthe gradient computed at prediction time
delay_stepshow many time steps passed before truth arrived
taumemory decay constant (older gradients matter less)
A tiny worked example
Suppose feature z_old = 5.0, stored gradient g = 0.8, prediction was 3 steps ago (tau=10).
Decay factor: exp(-3/10) = exp(-0.3) = 0.74.
Update step: z_new = 5.0 + 0.1 * 0.8 * 0.74 = 5.0 + 0.059 = 5.059.
Small nudge, but in the right direction — the stored gradient still guides, weakened by age.

The decay factor ensures very old feedback has less pull; features shift gradually, reconnecting past predictions to present patterns.

What can go wrong

What can go wrong

Very long delays erase the signal. If the true value arrives many weeks after the prediction, the stored gradient becomes nearly worthless — the features have drifted so far that the old direction points nowhere useful. The decay factor exp(-delay/tau) should be tuned to match your forecast horizon.
Sudden regime changes fool the stored gradient. If the data distribution changes abruptly (a new market regime, a sensor malfunction, a sudden weather event), the gradient stored under the old regime is not just delayed — it points backward. The update can overshoot or diverge.
Memory cost grows with forecast length. Storing a gradient for every prediction step multiplies memory use. For very long-horizon forecasting (predicting months ahead), the stored state can become large.
Done right: tune decay, validate on held-out shifts. Pick tau so that gradients from typical delays contribute noticeably but very old ones fade. Test on data with known distribution shifts to confirm the method adapts without breaking.
What a runnable demo should prove

What a runnable demo should prove

Build a synthetic time series with a deliberate regime shift: e.g., a sine wave with increasing frequency. Train a model on the first 50 steps. Then, from step 50 onward, the true values come with a 5-step delay. Run three methods: (1) no update, (2) standard online update on delayed loss, (3) ADAPT-Z. Measure forecasting accuracy on each step after the shift.

accuracy_drop = accuracy_before_shift - accuracy_after_delay_begins | recovery = accuracy_after_adaptation - accuracy_after_delay_begins

ADAPT-Z should show smaller accuracy drop and faster recovery than standard online learning, because adjusting features directly — using the old gradient — reconnects delayed truth to the moment the error was measured, whereas standard weight updates fight the current feature state and waste the gradient on stale directions.
