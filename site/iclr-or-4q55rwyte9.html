AR-Drag: Real-Time Motion-Controllable Autoregressive Video Diffusion

Generate video one frame at a time in a way that keeps videos smooth by training exactly how the model will run and by learning from rewards that measure motion accuracy.

Paper explainersAll themesGenerative Models & Diffusion

Video diffusion models are slow because they refine video in two directions (forward and backward through time), and they do not easily follow motion instructions like drag gestures. AR-Drag is a lightweight model that generates video one frame at a time and learns both to make realistic frames and to obey motion commands by training on its own predictions and tuning itself to maximize rewards for accurate motion.

Why real-time motion-controllable video is hard

Existing video diffusion models refine the whole video back and forth many times—they look at the first frame to improve the last frame, then the last to improve the first, over dozens of rounds. This makes them slow because each frame requires dozens of refinement steps, and all frames are processed together, so latency is proportional to the number of refinement rounds times the number of frames.

A beginner might try to make the model generate one frame at a time (autoregressive), reading only the frames already made. But this breaks because the model is trained on ground-truth past frames during training, yet at run-time it only sees its own guesses. The model learns to depend on perfect inputs, so its mistakes pile up—each bad frame makes the next worse.

Controlling motion also fails: motion commands like 'drag this finger to here' do not easily guide one-at-a-time generation, and few-step models lose detail.

The core problem. Frame-by-frame video generation (when the model runs) is done on the model's own guesses, but training is done on perfect data, creating a mismatch that kills quality and motion control.

The algorithm as a flow

What it actually does

Step 1: Learn basic motion control

Fine-tune a base image-to-video model on data with motion labels (drag gestures).

Step 2: Compress to few-step autoregressive

Distill the slow bidirectional teacher into a fast frame-at-a-time student by matching the output pattern.

Step 3: Fix training-run-time mismatch

Use Self-Rollout: during training, feed the model its own generated frames instead of ground truth.

Step 4: Add randomity for exploration

In one random denoising step per frame, inject randomness so the model tries different paths, because without randomness the model settles into a single fixed path and stops learning how to handle varied motion commands. Keep other steps deterministic to avoid blowing up computational cost.

Step 5: Learn from motion rewards

Run reinforcement learning to maximize the trajectory reward (how accurately the motion matches the command).

What the paper changes

What the paper changes

The paper changes how the model is trained. Instead of feeding the model ground-truth past frames (the typical 'teacher forcing' trick), it feeds the model its own generated frames. This single switch—Self-Rollout—eliminates the mismatch between training and run-time.

The hidden quantity

The hidden quantity: Train-run-time alignment

measured quantity  =  Markov chain consistency (how well training mimics run-time behavior)

The paper silently measures something important: how faithfully the training process matches what happens at run-time. At run-time, each frame is generated from only the frames the model has already made. This is a chain of decisions (frame 1 depends only on the image; frame 2 depends on frame 1; frame 3 depends on frames 1–2, etc.). Training would normally break this chain by giving the model the real frame 2, even if the model guessed wrong on frame 1.

The paper measures this alignment by actually running Self-Rollout: generate step-by-step during training using the model's own predictions, checking that the pattern of intermediate states (what the model sees during refinement) matches what will happen at run-time. When the alignment is perfect, the model learns to handle its own mistakes without falling apart.

Why it works

Why it works: Four linked pieces

Real-time performance comes from generating one frame at a time (autoregressive), rather than refining all frames together. But one-at-a-time generation is fragile: errors compound. Self-Rollout fixes this by training exactly how the model runs—feeding it its own output. This removes the hidden assumption that inputs are always perfect.

Motion control comes from encoding drag gestures as trajectory embeddings (lists of coordinates per frame), adding them to the base model, and then training the model to maximize a motion-accuracy reward. The reward is computed by comparing the generated motion path to the commanded path.

Speed comes from few-step denoising: instead of refining each frame 50 times, the model refines each frame only 4–8 times. To keep exploration alive during reinforcement learning without ballooning the computational cost, the paper randomly picks one denoising step to inject noise (SDE), while all others follow a deterministic path (ODE). This balances learning and efficiency.

The entire system stays small (1.3 billion numbers to tune) and fast because it is autoregressive, distilled, and runs on lightweight attention (backward-looking only, meaning each frame looks only at the past).

Math after the picture

The core equation: Flow matching with trajectory control

First in words:

The model predicts a direction (velocity field) at each point in the denoising trajectory. The training objective is to match the predicted direction to the true direction, guided by motion commands encoded as embeddings.

Then the compact form:

L = E_{m,n} [ || v_theta(x_{m,n}, t, c_traj, c_text) - v_true ||^2 ]

Every symbol:

x_{m,n}the partially-denoised frame m at denoising step n
v_thetathe model's predicted direction to move in denoising space
v_truethe ground-truth direction (computed from the data)
c_trajthe trajectory embedding (coordinates of the motion command)
c_textthe text prompt embedding (what objects to animate)
mframe index (1st frame, 2nd frame, etc.)
ndenoising step index within a single frame
A tiny worked example
Imagine a finger being dragged from (100,200) to (150,220) over 3 frames.
Frame 1: reference image given. Trajectory embedding = (100,200).
Frame 2: model generates the finger in a noisy state, refines it 4 steps. At step 2, predicted direction v_theta = move pixel 0.8 units right. True direction v_true = 1.2 units right. Error = (1.2 - 0.8)^2 = 0.16.
Frame 3: trajectory command = (150,220). Model matches it and gets error 0.04. Total loss after averaging = 0.10.
At run-time, the model has learned to nudge the finger correctly in the direction of the command, and errors do not compound because Self-Rollout trained it on its own guesses.

The loss measures how well the model predicts the denoising direction at each step, conditioned on the motion trajectory and text. Self-Rollout ensures this direction is learned from model-generated frames, not cheating with ground truth.

What can go wrong

What can go wrong

Variance explosion in RL. Long video sequences have many frames. If every denoising step (every refinement) is random, the random variance across all steps balloons. The model cannot learn stable motion because the noise drowns the signal. AR-Drag fixes this by making only one random step per frame and keeping others deterministic.
Collision or stuttering when motion constraints conflict. If the motion command says 'drag the finger here' but the base model wants to put it somewhere else for semantic reasons (e.g., to make the hand look natural), the two goals fight. The RL reward must be tuned carefully so motion is honored without breaking realism.
Model ignores the instruction if reward signal is weak. If the trajectory reward is not strong enough relative to the base model's fidelity loss, the model will drift away from the motion command and generate plausible but wrong videos.
Done right. Self-Rollout eliminates mismatch. RL from a well-tuned trajectory reward learns motion. Selective randomity (one random step, others deterministic) keeps variance tractable. The model learns to follow commands without losing realism or detail.
What a runnable demo should prove

What a runnable demo should prove

Build a simple image-to-video generator where you click and drag on an image to specify motion (a stick-figure hand moving across a scene, or a ball rolling). Train a tiny version (maybe 100 million numbers to tune) using Self-Rollout: at each training step, generate the next frame using only the model's previous frames, not ground truth. Set up a trajectory reward: measure how far the actual motion path is from the commanded path (straight-line distance in 2D space). Use RL to optimize. Measure motion accuracy frame by frame and compare to a baseline that uses ground-truth frames.

motion_error = mean(distance from predicted motion path to commanded path); error_accumulation = motion_error at frame 10 minus motion_error at frame 1

The demo must show that Self-Rollout prevents error accumulation, making motion precise at every frame instead of degrading frame by frame. That is the entire insight: train the way you run.
