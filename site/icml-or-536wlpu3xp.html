Focus-Then-Contact: Learning Contact Tasks with Guided Real-World Robot Control

To teach a robot tasks in the real world faster, first use a rough behavior learned before, then refine it by focusing on where the robot must touch objects.

Paper explainersAll themesRobotics & Control

Real-world robots often fail at contact tasks like pushing, grasping, or inserting because they must learn from live experience, which is expensive and slow. Most methods need a person constantly watching and correcting the robot. This paper combines two ideas: a rough learned behavior from past tasks that gets the robot close to the goal, plus a reward signal that directs the robot toward the contact zones where success actually happens.

Zero assumption version

Why real-world robot learning gets stuck

A robot learning by trial-and-error in the physical world is very slow. Each failed attempt costs time and can break things. When a robot must push an object into a slot or grasp something fragile, every millimeter matters, but the robot starts knowing nothing.

A naive learner would try random actions until one worked, then gradually refine it. That takes hundreds or thousands of real attempts. In a factory, that is not acceptable. A person could guide the robot by hand, but that costs human time at every step. Most current systems compromise: the robot learns a bit, then a person corrects it, the robot learns more. This loop is still slow and error-prone.

The problem in one sentence. Teaching a robot to do contact tasks in the real world by learning from experience is very slow because every attempt is costly, and the robot does not know which parts of the scene are important.

The algorithm as a flow

What it actually does

Load base behavior

Start with a rough, learned action from past tasks or human demonstration.

Identify contact zones

Detect affordances: regions in the scene where interaction happens.

Guide toward contact

Give the robot a reward bonus whenever it moves toward those zones.

Refine by force feedback

Once touching the object, use force sensors to sense contact pressure; this tells the robot exactly how hard to push, because trial error in contact gives direct physical feedback instead of guesswork.

Prevent human conflicts

If a person corrects the arm, pause learning to avoid the robot fighting back.

What the paper changes

What the method changes

The paper changes two things at once: first, the starting point for learning is no longer random but a rough pre-trained behavior; second, the reward signal is no longer a generic success measure but a shaped signal that explicitly points the robot toward contact zones. This combination lets the learning focus narrowly on the refinement that matters.

The hidden quantity

The focus region: where contact matters

measured quantity  =  Affordance-based focus zone

An affordance is a region in the world where an object can be interacted with. For a pushing task, the affordance is the side of the object you push. For an insertion task, it is the opening of the slot. The paper measures affordances by detecting these zones from the scene (using cameras or knowledge built into the system), then assigns them as target regions for the robot's learning.

The hidden quantity is the spatial location of these contact zones. By identifying them early, the system tells the robot: do not waste time on random exploration; your goal is to move to these specific places and interact there. The paper estimates affordances from the 3D shape of objects and the scene structure, then uses them to shape rewards.

Why it works

Why faster learning happens

Without focus, the robot explores randomly and learns slowly because most attempts miss the goal entirely. With a rough starting behavior, the robot is already pointed in the right direction, but it still needs to refine the motion. The affordance reward acts as a compass: it gives the robot a bonus every time it moves toward the contact zones, so learning effort concentrates there instead of spreading across useless regions. This is efficient because the robot only refines the final, critical meters of motion.

The mechanism is a combination of three steps: first, the base behavior gets the robot close (avoiding the hardest part of learning); second, the shaped reward focuses refinement on contact zones only (cutting down the search space); third, force feedback within contact zones lets the robot feel its way to success (using real physical feedback, not guesswork). These three together make learning six to ten times faster because the robot only refines the final critical motion (not the full trajectory), only explores contact zones (not empty space), and learns from direct force sensation (not trial-and-error guessing).

Math after the picture

The reward formula

First in words:

Total reward equals the task reward plus a bonus term: the base reward for reaching the goal, plus (if near an affordance zone) an additional distance-based bonus scaled by how close you are to the contact region.

Then the compact form:

R_total = R_task + lambda * exp(-alpha * d_to_affordance)

Every symbol:

R_totalthe reward the robot receives on this attempt
R_taskthe base reward for completing the task (1 if success, 0 if fail)
lambdahow much weight to give the affordance bonus (tuning parameter)
d_to_affordancethe distance from the robot to the nearest affordance zone, in meters
alphaa scale parameter that controls how fast the bonus drops with distance (higher alpha means bonus only near zones)
A tiny worked example
Suppose R_task = 0 (task not yet complete), lambda = 2, alpha = 5.
Attempt A: robot is 0.2 meters from an affordance zone. exp(-5 * 0.2) = exp(-1) ≈ 0.37. Reward ≈ 0 + 2 * 0.37 = 0.74.
Attempt B: robot is 0.8 meters from any affordance zone. exp(-5 * 0.8) = exp(-4) ≈ 0.018. Reward ≈ 0 + 2 * 0.018 = 0.036.
Same task, same learning step size, but Attempt A gets 20 times more reward feedback, so learning concentrates on the path that enters the affordance zone.

The exponential decay means the robot gets a strong signal only when close to affordance zones, focusing learning effort there and avoiding wasted exploration in empty space.

What can go wrong

What can go wrong

Affordances detected incorrectly. If the vision or heuristic that identifies contact zones misses the real zone or marks empty space as important, the robot learns the wrong behavior. The method depends entirely on accurate affordance detection.
Base behavior is not applicable. If the pre-trained starting behavior is from a very different task, it may steer the robot in the wrong direction instead of helping it. The base behavior must be roughly related to the current task.
Human corrections conflict with learning. If a person grabs the arm to correct it while the robot is also trying to learn, the two control signals can fight. The paper addresses this by pausing learning during manual correction, but improper handoff can cause delays.
Works well when affordances are clear. On tasks with well-defined contact zones (pushing, inserting, grasping) and a suitable base behavior, FTC cuts learning time by an order of magnitude.
What a runnable demo should prove

What a runnable demo should prove

A demo should show a real robot arm (or a physics simulator like PyBullet) learning a contact task (e.g., pushing an object into a slot, or grasping and lifting a small box). Initialize the robot with a rough pre-trained behavior (even just a scripted approach toward the object). Measure the number of real or simulated attempts before the robot completes the task successfully 5 times in a row. Then disable affordance-guided rewards and run the same task from scratch with the same budget of attempts. The affordance-guided version should converge 3 to 5 times faster because the focused reward signal steers learning away from wasted exploration in empty space and toward the contact zones where success is possible.
