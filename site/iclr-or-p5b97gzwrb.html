Hyperparameter Trajectory Inference

Learn how a neural network's outputs shift when you turn a knob, then predict outputs at knob positions you never tested.

Paper explainersAll themesOther

After training a neural network, its behaviour is locked into whatever hyperparameter (control dial) you picked—like reward weighting in a game-learning agent or confidence thresholds in a prediction model. But users' preferences change after deployment. Retraining the whole network from scratch for each new setting is expensive. This paper learns to predict what the network will do at any hyperparameter setting by studying how its outputs trace through probability space (the cost map of all possible answer patterns) as the knob turns, using physics principles about paths that take the least effort.

Zero assumption version

The locked hyperparameter trap

When you train a neural network, you have to pick control dials (hyperparameters) ahead of time. For example: how much to care about reward in reinforcement learning, or which confidence level to predict in a regression task. Once training is done, these settings are baked in.

A beginner might think: just train one network per dial setting. But this is expensive—if you want to support 100 different dial positions, you train 100 separate networks. In the real world, users' preferences change after deployment. You cannot afford to retrain from scratch every time.

So you are stuck: either lock users into one fixed behaviour, or pay the cost of retraining. The problem asks: can you learn a surrogate that predicts the network's output at any untested dial position, without retraining?

In one sentence. The paper learns a surrogate model that predicts a network's outputs for any hyperparameter value by understanding how the set of answer patterns (all possible outputs the network could give) traces a smooth path as the knob turns.

The algorithm as a flow

What it actually does

Collect sparse ground truth

Train the network at a few hyperparameter values (e.g., dial=0, dial=5, dial=10) and record output samples.

Assume smooth paths

The set of answers the network outputs should trace a smooth curve through all possible answer patterns as the dial turns.

Find the least-action path

Use optimal transport (comparing sets of answers) to find the smoothest, lowest-friction route between sampled dials.

Learn the Lagrangian

Fit a function that predicts the cost (resistance) of moving through any region of probability space for any dial.

Predict new dials

Given an untested dial value, the learned Lagrangian traces the path to outputs without retraining.

What the paper changes

What the paper changes

The paper does not retrain the network. Instead, it learns a cost map map—a description of how expensive it is to move through probability space when the dial changes. This map is captured in a Lagrangian function (a function that scores the cost of paths). By learning this one function from a few ground-truth samples, the surrogate can answer at any new dial value.

The hidden quantity

The hidden quantity: path cost

measured quantity  =  Least-action cost of answer-pattern paths

The paper measures a hidden quantity called the least-action cost: how much total resistance a smooth path accumulates when moving through probability space (the cost map of all answer patterns) from one dial setting to another. In physics, this is the integral of kinetic and potential energy along the path; the actual best path is the one with the lowest total cost.

The paper learns this cost function (the Lagrangian) by comparing output samples at different dial values. It measures which paths require the most energy to traverse (for example, paths that stay off the actual data surface incur high cost), and builds a model that predicts this cost anywhere in the space.

Why it works

Why it works: physics on answer-space

Here is the core insight: if you assume the network's outputs evolve smoothly as the dial turns (a natural assumption for most hyperparameters), then you can apply a principle from physics. In physics, the path a ball takes between two points is the one that minimizes total energy (least-action principle). The paper applies the same idea to probability distributions: the most natural way for a network's output distribution to change as the dial turns is the path that minimizes total resistance or friction.

The paper encodes two inductive biases in the learned Lagrangian. First, it assumes the data lies on a low-dimensional curved surface, so paths that stay close to that surface are cheaper than paths that wander into empty space—because empty space represents answer patterns the network would never actually produce, so there is no learned cost there. Second, it uses the least-action bias directly: smoother, less-energetic paths are preferred, because in physics real systems naturally follow the path of least resistance. The surrogate model learns these costs from the few ground-truth samples, then uses them to predict sets of answers at new dials by finding the lowest-cost path.

Why does this work? Because you are not learning arbitrary interpolation—you are learning the underlying shape of the cost map. If the cost map is correct, it extrapolates to new dials you never trained on, because the least-action principle applies everywhere, not just between the training dials.

The least-action principle

First in words:

The action (total resistance) of a path q from time 0 to 1 under dial x is the integral of the Lagrangian (instantaneous cost) along the path. The best path is the geodesic: the one with minimum action. The cost between two distributions is the least-action value of the geodesic connecting them.

Then the compact form:

S(q|x) = integral from 0 to 1 of L(q_t, q_dot_t | x) dt; c(y0, y1|x) = inf over paths q of S(q|x)

Every symbol:

q_toutput distribution at step t (where t is 0 at dial_start, 1 at dial_end)
q_dot_thow fast the distribution is changing (velocity)
L(q_t, q_dot_t | x)the cost (Lagrangian) of being at distribution q_t, changing at rate q_dot_t, under dial setting x
xthe hyperparameter value (dial setting)
S(q|x)total action (cost) of path q under dial x
c(y0, y1|x)minimum-cost path from distribution y0 to y1 under dial x (the cost at dial x)
A tiny worked example
Imagine a dial that ranges 0 to 10. At dial 0 the network predicts class A with prob 0.8. At dial 10 it predicts B with prob 0.9.
The paper samples outputs at dial 0 and dial 10. It computes how expensive the smoothest path between them is (accounting for the actual curved surface the data lies on).
Suppose that path has action cost 2.5 units. A wiggly path has cost 5.0. The least-action path (cost 2.5) is preferred.
Now at dial 5: the paper finds the path from dial 0 to 5 and dial 5 to 10 that keeps total cost minimal while staying on the actual curved surface. It solves for the set of answers at dial 5.
At dial 3 (untested): same idea—find the path that minimizes cost. It predicts the set of answers between dial 0 and dial 5.

The Lagrangian function encodes the terrain; the geodesic (least-action path) is the natural route; the surrogate walks that route to answer at new dials.

What can go wrong

What can go wrong

Non-smooth hyperparameter effects. If the dial causes a sharp, discontinuous shift in network behaviour (e.g., activating a completely different decision path), the least-action assumption fails. The paper assumes smooth trajectories; abrupt changes break the model.
Insufficient training dials. If you only train at dials 0 and 10 but the true path has a hidden valley at dial 5, the surrogate will miss it. You need enough ground-truth samples to capture the actual curved surface the data follows.
High-dimensional output spaces. Optimal transport becomes expensive to compute in very high dimensions. The method works best when outputs live on a low-dimensional curved surface (not scattered randomly across all possible dimensions).
Done right: multi-dial hyperparameters. The current method handles one continuous hyperparameter well. If you have two or more dials that interact, you would need to extend the method to higher-dimensional dial spaces, which the paper notes as future work.
What a runnable demo should prove

What a runnable demo should prove

Build a simple environment: train a policy (or classifier) at exactly two hyperparameter values using a standard algorithm (like PPO for reinforcement learning, or quantile regression for prediction). Collect samples of what the network outputs at each dial value. Use the HTI surrogate to predict outputs at an interpolated dial value you never trained on. Verify that the surrogate's predicted set of answers (for example, confidence levels, action distributions, quantile forecasts) matches or beats the ground truth, measured against a small held-out set of true samples from the untrained dial value.

The demo must show three dials: trained at dials 0 and 10, and then ask the surrogate to predict dial 5 (or 3, or 7). The key metric is Wasserstein distance (a way to measure how far apart two sets of answers are from each other): smaller is better, because it means the surrogate's prediction is closer to the true answer.

WD (↓) = Wasserstein distance between predicted and ground-truth distributions; lower means the surrogate is more accurate.

The demo must make it impossible to miss: the surrogate predicts accurately at dials it never saw, without retraining, because it learned the underlying cost map map of how the network behaves when you turn the knob.
