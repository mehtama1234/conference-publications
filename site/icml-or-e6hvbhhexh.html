Efficient Neural CDEs via Attentive Kernel Smoothing

Instead of tracing jerky paths through data, smooth them first and use attention to grab back the details that matter.

Paper explainersAll themesTime Series & Sequential

When a model reads a time series one step at a time, it must trace a path through the data points. Standard methods draw jagged spline curves that force the solver to take tiny, exhausting steps to stay accurate. This paper smooths the paths using a gentle probabilistic curve-fit and then trains attention layers to pick which fine details to recover. The result: the same accuracy with 5 to 14 times fewer compute steps.

Zero assumption version

Rough paths force the solver to crawl

Time series models often work by running a differential equation solver (a numerical method that computes the path of a system over time step by step). The path is built by connecting the data points with a curve—usually an exact spline, a smooth mathematical function that passes through every point.

The problem: if the data is noisy or the points are far apart, the spline curves up and down sharply. A solver running along this rough path must take tiny steps to stay accurate, because when the curve jiggles suddenly, a big step would miss the jiggle and the answer becomes wrong. All those tiny steps add up—the model becomes slow.

A beginner might try to smooth the data first, but real smoothing loses information: if you blur away the sharp parts, the model forgets patterns that matter. You either keep the roughness and stay slow, or smooth it and lose accuracy. That is the bind.

The move. Smooth the path using a probabilistic curve-fit (Gaussian Process), but train attention layers to learn which details to recover from the noise.

What the paper changes

The paper replaces the path through the data. Instead of an exact spline (which wiggles sharply), it uses a smoothed probabilistic curve. That curve is the object.

The hidden quantity

Step-size constraint: path regularity

measured quantity  =  solver step size allowed

The hidden quantity is how large a step the numerical solver can take without drifting off the true path. When the path is jagged, derivatives jump around, so the solver must step tiny. When the path is smooth, derivatives change gently, so the solver can stride farther.

The paper measures this by counting the number of function evaluations (NFE)—each time the solver asks for the next value, it is one evaluation. Fewer evaluations means bigger steps were possible, meaning the path was smoother. The paper reports speedups as 5-14 times fewer evaluations.

Why it works

Why smooth paths are faster and still accurate

The core mechanism is decoupling. Normally, path regularity is chained to the input data—you have noisy, jagged data, so you get a jagged path, so you must step tiny. The paper breaks that chain.

It first smooths the data using a Gaussian Process, a probabilistic technique that fits a gentle curve while explicitly modeling which points are measurement noise and which are signal. This decouples the path smoothness from the data roughness. The solver now takes big steps on the smooth path, running fast.

But smoothing alone erases details. If a true pattern happens to look sharp (a sudden spike in heart rate, a stock market jump), oversmoothing loses it. So the paper adds a second layer: attention. Multiple parallel smoothed paths are created with different amounts of smoothing. Learnable attention queries (learned during training) score how much each observation contributes to each path. Observations with high attention scores are treated as real signal; low-scoring ones are filtered as noise. This way, the model learns to recover exactly the patterns that predict the target, without the solver ever seeing the raw roughness.

Math after the picture

The equation for a smooth, attentive path

First in words:

For each head m, the path is a weighted sum of kernel basis functions, with weights learned from attention scores.

Then the compact form:

X(m)(t) = sum_k[ alpha(m,k) * kernel(t - t_k) * x_k ] / sum_j[ alpha(m,j) * kernel(t - t_j) ]

Every symbol:

X(m)(t)the smooth path at time t for head m
alpha(m,k)attention weight: how much observation k contributes to head m
kernel(t - t_k)basis function (e.g. RBF or Gaussian) centered at observation time t_k
x_kthe observed value at time t_k
sum_k, sum_jsum over all observations
A tiny worked example
Say we have 3 observations: x1=5 at t=0, x2=8 at t=1, x3=6 at t=2.
Head 1 learns attention: alpha1=[0.8, 0.1, 0.1] (focuses on x1).
Head 2 learns attention: alpha2=[0.2, 0.5, 0.3] (focuses on x2).
At time t=0.5, the basis function (a bell curve centered at each observation time) is evaluated.
Head 1 blends: mostly 5 (x1 high attention) with a small pull toward 8 and 6.
Head 2 blends: mostly 8 (x2 high attention) with smaller pulls toward 5 and 6.
The solver picks either head 1 or head 2 (or interpolates them) depending on what the downstream layers learned to value.
Result: the solver sees two smooth candidate paths; the model learns to use the one that predicts best.

The mechanism: attention weights let the model learn which observations are real signal and which are noise, so smooth paths can recover high-frequency patterns without the solver ever seeing jitteriness.

What can go wrong

What can go wrong

Bandwidth tuning matters. Unlike exact splines, smoothing requires choosing the bandwidth (how much to blur). Wrong choice either loses real patterns or keeps too much noise. The paper does not fully automate this; it is still a dial to turn.
Bottleneck from the stiffest head. When multiple smoothed paths run in parallel, the solver must stay small enough for the roughest one. If one head has too little smoothing, it can slow down the whole model.
Very high-frequency detail is still lost. Smoothing, by design, erases the highest-frequency signals. If the true pattern is a thin spike, no amount of attention can recover it perfectly; attention chooses what to keep, but the original spike is already gone after smoothing.
Done right. The model learns, during training, to set bandwidth and attention scores so that exactly the patterns that predict the target are recovered. This works because training optimizes for the downstream task, not just for fidelity to the original signal.
