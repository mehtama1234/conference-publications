Controllable Logical Hypothesis Generation

When a doctor sees a symptom, there are hundreds of diseases that could explain it, but a good diagnosis needs the most plausible and relevant ones—this paper gives a way to steer hypothesis generation toward user-specified constraints.

Paper explainersAll themesGraph & Geometric Learning

Abductive reasoning is the process of finding explanations for observations. Given a patient with a fever, you might infer they have the flu, a bacterial infection, or COVID-19—all are plausible. On large knowledge graphs, a single observation triggers thousands of possible hypotheses, most redundant or irrelevant. This paper adds a control knob so users can steer which hypotheses get generated, trading exploration for practical utility.

Zero assumption version

Too many plausible explanations, no control

Knowledge graphs store facts as triples: doctor-diagnoses-patient, disease-causes-symptom. Given one entity (a patient with a fever), abductive reasoning asks: what diagnoses could explain this? The system finds all valid chains of reasoning—sometimes hundreds or thousands. A naive approach generates them all equally, flooding the user with irrelevant noise.

A doctor does not want all 200 possible diagnoses of a fever. They want the ones most likely for this specific patient, or ones matching a particular suspect (respiratory infection, not neurological). The system needs a way to accept user constraints—rules like prefer simpler explanations, or only show diagnoses of type X—and use those to filter the hypothesis space intelligently.

In one sentence. Add a control setting that steers hypothesis generation toward user-specified constraints while keeping the hypotheses relevant and diverse.

The algorithm as a flow

What it actually does

Start with a simple hypothesis model

Train a baseline model to generate plausible chains of reasoning from an observation to candidate explanations.

Augment the training data

Create training examples of shorter, simpler logical subpatterns—break complex hypotheses into pieces the model can reuse.

Run reinforcement learning

Teach the model to optimize multiple reward signals: match the user constraint, find semantically similar (relevant) hypotheses, and avoid repetition.

Measure three rewards

Reward 1 is how well the hypothesis matches the user's control condition. Reward 2 is how semantically similar it is to known good answers. Reward 3 gently penalizes redundancy.

Output ranked hypotheses

Return hypotheses ranked by their total score: constrained and relevant, not just any plausible explanation.

What the paper changes

What the model learns to do differently

The paper changes how the model generates the sequence of logical steps in a hypothesis. Instead of producing any valid chain, the model learns to assign higher probability to chains that satisfy a user constraint while remaining semantically relevant. The key change is not the architecture—it is the training objective, which now includes multiple reward signals pulling the hypothesis generation toward desirable behaviors.

the object it moves  =  Hypothesis ranking and selection mechanism
The hidden quantity

The condition-adherence reward

measured quantity  =  How well the hypothesis matches the user constraint

When a user specifies a control condition like 'only respiratory diseases' or 'prefer simpler chains,' the model needs to quantify how well a candidate hypothesis obeys it. This is the hidden quantity: a numerical score (between 0 and 1) that measures alignment. For a fever with control 'respiratory-only,' a hypothesis ending in 'pneumonia' scores high; one ending in 'heart arrhythmia' scores zero.

The paper computes this reward by checking whether the generated hypothesis's final entity or logical type matches the control specification. It also uses a semantic similarity score (Dice overlap or Jaccard similarity) to measure how much the reasoning chain overlaps with high-quality reference explanations. A smooth, blended reward combines both signals so the model gets clear feedback during training, because a sharp, binary constraint reward would make the model oscillate between satisfying the control and matching quality examples.

Why it works

Why adding control rewards redirects hypothesis generation

During training, the model learns by predicting the next logical step (entity or relation) and receiving a reward signal telling it whether the full chain was good. If unconstrained, the model learns to maximize any plausible explanation. But when the training adds a reward that specifically penalizes hypotheses violating the user constraint and boosts those matching it, the model's internal numbers representing 'good reasoning' shift, because the reinforcement learning algorithm repeatedly shows the model examples of chains it generated, their rewards, and nudges the model's weights toward higher-reward chains. Words, relations, and entity types associated with violating the constraint get lower scores in the model's hidden layers; those matching the constraint get higher scores. This is not filtering after the fact—it is retraining the model's internal decision-making.

A second challenge emerges: the model overfits to the control constraint and ignores semantic quality (relevance to known good answers). The paper solves this by smoothing the reward with multiple terms. Instead of a sharp constraint reward, the model balances: Does this match the control? Is this similar to ground-truth diagnoses? Have I already generated this before? The model learns to optimize all three together, trading off control-adherence against redundancy and semantic fidelity. The two-stage training (supervised learning, then reinforcement learning) helps, because the supervised stage primes the model with real examples of high-quality reasoning chains, so when reinforcement learning adds the constraint term, the model starts from a foundation that already values quality—it does not have to rediscover what good reasoning looks like.

Math after the picture

The reward formula

First in words:

Total reward = Constraint-match score plus Semantic-similarity score minus Redundancy penalty

Then the compact form:

R = w_c * S_c(h) + w_s * S_sim(h, ref) - w_r * penalty_redundant(h)

Every symbol:

RTotal reward for hypothesis h
S_c(h)Constraint-satisfaction score (0 to 1; 1 if h matches user control)
S_sim(h, ref)Semantic similarity between hypothesis h and reference answers (Dice or Jaccard overlap)
penalty_redundant(h)Penalty if h is too similar to previously generated hypotheses
w_c, w_s, w_rWeights controlling how much each term matters
A tiny worked example
Hypothesis A: fever -> inflammation -> pneumonia. Constraint: respiratory. S_c(A) = 1.0. S_sim(A, gold refs) = 0.8. Penalty = 0. w_c=0.5, w_s=0.3, w_r=0.2. R = 0.5*1.0 + 0.3*0.8 - 0.2*0 = 0.5 + 0.24 = 0.74.
Hypothesis B: fever -> immune -> cardiac arrhythmia. Constraint: respiratory. S_c(B) = 0. S_sim(B, gold) = 0.1. Penalty = 0. R = 0.5*0 + 0.3*0.1 - 0.2*0 = 0.03.
Model learns to rank A (0.74) far above B (0.03). Reinforcement learning increases probability of chains like A.

The three terms represent adherence to the user's intent, alignment with known correct answers, and avoiding redundancy—the model trades off all three, weighted by w.

What can go wrong

What can go wrong

Constraint too strict. If the user constraint is very specific (e.g., only three entities allowed), the model may learn to always generate the same three hypotheses. Semantic diversity collapses.
Reward signal contradicts itself. If the constraint-match reward and semantic-similarity reward pull in different directions (constraint wants X, gold data prefers Y), the model oscillates or gets stuck at a local compromise.
Oversensitive tuning of weights. If the constraint weight is too high, the model ignores semantic quality and generates any chain satisfying the control. Tuning the three weights for each dataset requires experimentation.
Done right. The paper uses smoothed rewards (Dice and Jaccard overlap) and tests different weight values on held-out validation sets before final testing. Multiple reward terms prevent collapse into a single degenerate hypothesis.
What a runnable demo should prove

What a runnable demo should prove

Build a small knowledge graph of animals and their properties (has-four-legs, is-mammal, eats-meat, lives-in-forest). Pick an observation like 'I see an animal that is fast.' Ask the system to generate hypotheses both unconstrained and constrained to 'predators only.' Measure: How many generated hypotheses end in a predator? How much do they overlap with a reference set of correct predator answers? How many times does the system repeat the same hypothesis? The demo should show that constrained generation has higher predator-matching rate, no loss of relevance, and much lower redundancy.

Constraint adherence = count(hypotheses matching constraint) / total hypotheses. Semantic quality = average overlap with reference answers. Redundancy = count(duplicate hypotheses) / total.

The deepest finding: the same model, with the same architecture, produces radically different hypotheses if you add a reward term that explicitly values user constraints. This is steering, not filtering.
