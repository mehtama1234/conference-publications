In-Context Learning for Pure Exploration

A transformer learns to ask the right questions and guess the answer without re-learning on new tasks.

Paper explainersAll themesReinforcement Learning

Finding the best choice in an uncertain world (like the best restaurant in a new city) means collecting clues strategically. A machine usually re-learns on each new world. This paper trains a neural network (a transformer: a type of network that reads sequences like a history of answers) once to map what it has seen so far to the best next question and its current best guess, so it solves new worlds instantly by just looking at the evidence it collected.

Why do agents re-learn everything?

Imagine you walk into a restaurant and need to figure out which waiter is fastest. You ask one waiter how long your drink takes, then another, comparing. Each time you enter a new restaurant, you start from scratch: ask questions one by one until you are confident you know the answer. Most learning systems work the same way. Every new task requires the model to retrain—learning which questions to ask and how to guess the answer from the replies.

A beginner might ask random questions and hope for the best, but that wastes chances. A smarter beginner would ask the most informative questions first, but figuring out which questions matter requires calculation after every answer, which is slow and brittle across different task types.

The core problem. When faced with a new task, an agent must re-learn its policy and inference rule from scratch, which is slow and does not transfer across different task structures.

The algorithm as a flow

What it actually does

Meta-training phase

Train a transformer on many tasks, each with different question-answer pairs and correct answers, to learn which questions matter.

Online evidence collection

At test time on a new task, the transformer reads the history of answers collected so far.

Reward signal for action choice

The transformer scores each possible next question by how much it shrinks the doubt (the spread in the guess).

Inference from evidence

A separate neural network inside the transformer guesses the true answer from the history, without adjusting any of its internal numbers.

Stopping when confident

The transformer stops asking when its guess is confident enough, trading off more evidence against the cost of asking.

What the paper changes

What the paper changes

Instead of hand-coding a fixed algorithm that picks questions (like a scientist's rules for which experiment to run next), the paper trains a transformer to learn which questions reduce doubt fastest, and trains it on a diverse family of task types so it transfers to new ones without retraining.

the object it moves  =  the question-asking policy
The hidden quantity

The hidden quantity: doubt in the guess

measured quantity  =  posterior confidence (the spread of guesses)

After each answer, the agent updates how likely each possible true answer is. This is the posterior: a ranking of guesses weighted by how much the new evidence supports each one. The width of this ranking (how spread out the probabilities are) tells you how much doubt remains. A narrow, peaky distribution means the agent is confident. A flat, spread-out distribution means the agent still has no idea.

The paper never writes out the posterior explicitly; instead, it trains the transformer to recognize when evidence has narrowed the doubt enough to stop asking. The transformer learns to measure this by watching many tasks during meta-training and seeing which stopping times let it guess correctly with high confidence.

Why it works

Why it works: the two-net trick

The transformer contains two smaller neural networks working as a team. The first, the inference network, takes all the answers collected so far and guesses which true answer is most likely. The second, the policy network, takes the same history and scores each possible next question by how much it would shrink the doubt in the inference network's guess. During meta-training, the policy network is rewarded when it picks questions that lead to correct guesses with high confidence, and penalized when it asks too many questions. After training, both networks have learned patterns that transfer: an answer about waiter speed is always informative, certain question orders are strategic, and the inference network recognizes when the doubt has narrowed enough.

Because the transformer reads the full history every time, not just the last answer, it can spot patterns in the accumulated evidence—for instance, that answers from three different waiters all point to the same conclusion, so the next question should target the remaining doubt. This is why it transfers across different task structures without retraining. During meta-training on many diverse tasks, the transformer learned general patterns about how evidence narrows down guesses (like learning that contradictory answers mean you need more information), not task-specific rules that only work on restaurants or bandits.

Math after the picture

The reward equation

First in words:

penalty equals minus one if the agent asks a non-stop question, plus a reward bonus if it stops (scaled by how confident the guess is), minus the difference between the ideal value if one more step is allowed and the current value

Then the compact form:

r_t(D_t, a) = -1{a ≠ a_stop} + λ * 1{a = a_stop} * max_H P(H_true = H | D_t)

Every symbol:

r_t(D_t, a)reward at time t for action a given evidence D_t
1{a ≠ a_stop}indicator: 1 if action is not stop, 0 if it is
1{a = a_stop}indicator: 1 if the agent chooses to stop, 0 if it continues
λtrade-off weight: how much to value confidence versus asking fewer questions
max_H P(H_true = H | D_t)highest probability the inference network assigns to any possible answer
D_tall evidence (answers) collected up to time t
A tiny worked example
Suppose after two questions the inference network assigns probabilities: waiter A (best) = 0.7, waiter B = 0.2, waiter C = 0.1.
If the agent asks another question (a ≠ a_stop): reward = -1 (penalized for asking). Assume the next answer would improve the top prob to 0.9: future value V_next = 0.9. Total future discounted value = max(0.9) = 0.9. Temporal difference = 0.9 - 0.7 = 0.2. (In full algorithm, this is discounted.)
If the agent stops right now (a = a_stop) with λ = 2.0: reward = 2.0 × 0.7 = 1.4 (bonus proportional to confidence).
Since 1.4 > 0.9, the agent stops and guesses waiter A. If λ were smaller (say 1.0), reward = 1.0, and it might ask again.

The math formalizes a trade-off: reward for stopping grows with how confident the guess is, but grows more slowly than the cost of asking, so the agent stops when confidence is high enough.

What can go wrong

What can go wrong

Mismatch between training and test task types. If test tasks have a very different structure (e.g., questions that reveal information in a non-standard way), the transformer's learned patterns may not apply. The policy network might ask questions that worked well during training but are unhelpful on this new structure.
Offline training only. ICPE requires meta-training on an online simulator where you can sample tasks and collect evidence. If you only have logged data (past decisions and outcomes) with no ability to sample, the transformer must be retrained from scratch using offline learning, losing the main advantage.
Computational cost of training. Training a transformer on many tasks with many sampled trajectories is expensive. If you have only a small budget, a hand-coded heuristic algorithm might be faster to deploy, because that algorithm's arithmetic (computing information gain at each step) runs only once at test time, not during meta-training on thousands of task instances.
Done right: transfer works. If the test tasks are reasonably similar to the training distribution and you can afford to meta-train, the transformer transfers instantly with no retraining.
What a runnable demo should prove

What a runnable demo should prove

Build a simple multi-armed bandit (say, 5 arms) with reward means unknown but drawn from a standard distribution. Assume you have a pre-trained transformer (trained on 1,000 similar bandit instances). At test time, give the transformer no access to true means and no ability to retrain. Instead, feed it each arm's reward observations as they arrive. Track two things: how many times it asks each arm (its question strategy), and whether its final guess of the best arm is correct. Plot the accuracy and the number of questions versus time. Compare against a random-question baseline (which asks any arm uniformly) and a hand-coded information-gain baseline (which computes information gain from scratch at each step). The demo wins if ICPE matches the information-gain baseline (or beats it due to learned shortcuts) while being faster to compute because the transformer does no arithmetic.

accuracy = fraction of test instances where ICPE guesses the true best arm correctly; mean_questions_asked = average number of questions needed to reach high confidence

The core claim the demo must make impossible to miss: in-context learning of a question-asking policy is as good as computing the optimal questions from scratch, but requires no per-task calculation.
