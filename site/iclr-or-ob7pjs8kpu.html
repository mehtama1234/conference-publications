All Patches Matter: Detecting AI-Generated Images by Forcing Uniform Patch Learning

Detectors learn to use all patches equally by randomly injecting fake signals and penalizing uneven attention.

The Lazy Detector Problem

When you train a detector on AI-generated images, it faces a choice: scan every part of the image for fake signs, or take shortcuts. Modern detectors learn the shortcut. They find a few patches—small square regions—where the forgery signs are easy to spot and focus all their attention there. Other patches, which also contain subtle signs, are ignored.

The first naive attempt is to just train on as many examples as possible. But that doesn't work. Once the detector finds those easy patches, it sticks to them. It is like a student who memorizes the answers to five exam questions and ignores the rest of the material—if the test changes, they fail badly.

This creates two problems: the detector becomes fragile (mask one easy patch and accuracy drops 18%), and it fails to generalize to new kinds of AI-generated images (because different generators hide their traces in different places).

In one sentence. Detectors over-rely on a few favorite patches while ignoring distributed signals present everywhere.

What the paper changes

What the paper changes

The paper changes how the detector is trained, not the detector itself. It adds two new training tricks: (1) Randomized Patch Reconstruction—randomly select patches each batch and inject the detector with synthetic cues in those locations, forcing it to keep learning new spots. (2) Patch-wise Contrastive Learning—add a penalty whenever the detector's confidence scores across patches become uneven, pushing all patches toward equal importance.

the object it moves  =  training procedure for patch importance
The hidden quantity

The hidden quantity: Causal Patch Effect

measured quantity  =  How much each patch causally influences the decision

The paper introduces a measurement called Causal Decomposition Effect (or CDE)—a number for each patch that says: if we remove this patch, how much does the detector's confidence change? A patch with high CDE is one the detector heavily relies on. A patch with low CDE contributes little.

The paper uses this to diagnose the problem: naive detectors have a wildly skewed CDE distribution (a few patches with very high CDE, most patches with near-zero). Better detectors have CDE spread evenly across all patches. The paper then measures success by flattening this distribution—making all patches contribute roughly equally.

Why it works

Why the method works: forcing uniform learning

The detector has a lazy-learner problem: once it finds a few patches where forgery is easy to spot, it stops exploring elsewhere. Those easy patches minimize the training loss, so there is no pressure to learn from the harder patches. Standard training on more data does not fix this—it just gives the detector more chances to use its favorite shortcuts.

The paper's fix has two moving parts. First, Randomized Patch Reconstruction: every training batch, pick random patches and inject synthetic cues into them. Now the detector cannot rely on the same patches every time—its favorite easy patches might be masked out or altered. It is forced to keep learning from new locations.

Second, Patch-wise Contrastive Learning: measure how much confidence the detector assigns to each patch's decision, then add a penalty whenever some patches get higher confidence than others. This directly discourages the uneven attention pattern. Together, these two tricks break the lazy shortcut and force the detector to distribute its learning effort across all patches.

The equation for uniform learning

First in words:

Total training penalty equals the image-level classification error plus a weighted contrastive penalty that penalizes uneven patch confidence scores.

Then the compact form:

Loss = CE(detector(img), label) + lambda * sum_i (||patch_embed_i - mean_patch_embed||^2)

Every symbol:

Losstotal penalty the detector tries to minimize
CE(...)cross-entropy error, measuring how wrong the fake-or-real guess is
detector(img)the detector's output logit (raw score before converting to probability)
labeltrue label: fake or real
lambdaweight controlling how strongly we enforce uniform patches
patch_embed_ithe embedding (list of numbers) for patch i
mean_patch_embedaverage embedding across all patches
||...||^2squared distance (how far each patch embedding is from the average)
A tiny worked example
Suppose 4 patches, detector outputs logits: patch1=0.9 (very confident fake), patch2=0.2 (barely confident), patch3=0.1, patch4=0.85.
Mean logit = (0.9 + 0.2 + 0.1 + 0.85) / 4 = 0.5
Contrastive penalty: (0.9-0.5)^2 + (0.2-0.5)^2 + (0.1-0.5)^2 + (0.85-0.5)^2 = 0.16 + 0.09 + 0.16 + 0.12 = 0.53
If lambda=1, we add 0.53 to the loss. If CE was 0.2, total loss = 0.2 + 0.53 = 0.73.
Now if detector tries to rely only on patch1, pushing it to 1.0 while others drop to 0.0, the contrastive penalty explodes to 2.5, making that decision expensive.
By penalizing variance, the detector learns that spreading confidence across patches keeps the loss low.

The equation penalizes patches that drift far from the average, forcing the detector to treat all patches with similar importance.

What can go wrong

What can go wrong

Randomization not random enough. If patches are selected non-uniformly (e.g. always reconstructing edge patches), the detector still learns to favor unreconstructed patches. Truly random selection is required.
Lambda set too low. If the contrastive weight (lambda) is too small, the penalty for uneven patches is weak and the detector returns to lazy shortcuts. Tuning lambda is critical.
Patch size mismatch. If patches are too large, they may miss fine-grained artifacts. If too small, noise dominates and the signal is lost. Patch size must match the scale of artifacts.
Done right. Random patch selection, strong enough lambda, and appropriate patch granularity force the detector to learn a distributed representation of forgery.
What a runnable demo should prove

What a runnable demo should prove

Build a simple image detector (e.g. vision transformer on 8x8 patches). Train two versions: (A) standard supervised learning on AI-generated vs. real images; (B) with randomized patch reconstruction and patch-wise contrastive loss. Test both on a held-out dataset of fake images from a generator not seen during training.

For each version, compute the attention map (which patches the detector relies on) and the CDE score (causal effect) for each patch. Measure: (1) What fraction of patches have high CDE? (2) If you mask out the top-1 patch, how much does accuracy drop?

generalization_gain = (accuracy_PPL_on_new_generators) - (accuracy_baseline_on_new_generators)

If PPL works, the generalization gain should be at least 15 percentage points, and the CDE distribution should visibly flatten (no patch dominates).
