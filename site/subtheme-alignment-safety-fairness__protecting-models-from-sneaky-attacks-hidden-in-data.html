Protecting models from sneaky attacks hidden in data

These papers study how attackers can poison training data with hidden malicious patterns (backdoors) that make models secretly misbehave, and how to defend against such attacks.

All themesField mapMathematicsAll explainers
What this is

You want to train a model on data from the internet. But what if someone has poisoned that data? They could add mislabeled examples, or add images with hidden patterns (backdoors) that cause the model to misbehave on certain inputs. For example, an attacker could add training images where all pictures with a particular sticker in the corner are mislabeled as 'safe,' so that when the deployed model sees that sticker, it makes a wrong prediction. Or an attacker could inject text data with hidden trigger phrases that cause a language model to follow malicious instructions. The model works normally for everyone else, but anyone who knows the trigger can exploit it. This is data poisoning, and it's particularly dangerous because the attacker doesn't need access to the deployed model—they just need to influence the training data.

Why is this hard? Because training data is often sourced from the internet or crowdsourced from humans, and you can't fully audit every example. If an attacker can inject even a small number of poisoned examples among millions of clean ones, it can work. The backdoor can be subtle: a pattern that the model learns but that a human annotator wouldn't notice. And unlike adversarial examples that affect a single prediction, a backdoor generalizes: once the model learns the trigger, it will respond the same way to similar triggers. Detecting poisoned data requires knowing what to look for, but the attacker can make the trigger so subtle that it's hard to spot. And even if you know some data is poisoned, removing it might require retraining from scratch.

The papers in this area develop two defenses. The first is detection: can you audit training data to find and remove poisoned examples? This includes techniques for identifying mislabeled data, spotting unusual patterns, and testing whether suspected triggers cause misbehavior. The second is resilience: how do you train a model so that poisoned data has minimal effect? This includes techniques that work well even with mislabeling, that learn representations insensitive to backdoor triggers, or that use certified defenses to guarantee that a small number of poisoned examples won't corrupt the model. Some papers study the attack side too, exploring how potent backdoors can be and what makes them hard to detect, which helps defenders understand the threat and prepare defenses in advance by knowing what to look for.

How the work breaks down

The papers split into five directions. First, defenders catch poisoned data by spotting triggers or detecting misbehavior patterns, usually after training or during testing. Second, defenders make models resistant to poison by training methods that learn well even when some data is corrupted. Third, researchers study how backdoors work across different model types—vision, language, multimodal, reinforcement learning—to understand where vulnerabilities hide. Fourth, watermarking techniques embed hidden patterns that prove ownership and detect theft or tampering. Fifth, attackers develop new backdoor and poisoning methods to explore what defenses must protect against. These directions matter because each offers a different lever: finding poison, building resistant learning, understanding the attack surface, protecting intellectual property, and knowing the attack frontier.

Finding and neutralizing backdoor triggers

When a model has been backdoored, you need to find what trigger causes it to misbehave. The attacker hides the trigger on purpose—it could be a tiny sticker in images, a phrase buried in text, or a specific attention-head activation pattern in the model's brain. Finding it means looking for traces the trigger leaves behind: unusual slopes in the loss function (how the model's error changes with small tweaks), abnormal activation flows, or inconsistent behavior on certain inputs.

Unmasking Backdoors uses slope-attention signals (how the loss function changes with tweaks to attention weights) to spot where a language model's behavior shifts strangely, so you can figure out which neurons fire when a trigger is present. STEDiff reveals that backdoor triggers leave spatial and temporal marks in text-to-image models, allowing fast detection with high accuracy. Uncovering Hidden Triggers shows that ablating just 3% of the model's attention heads can drop the attack success rate by over 90%, pinpointing which pieces of the model learned the malicious pattern. Mechanistic Anomaly Detection compares what the model does normally versus under attack to catch the backdoor by its functional signature. Test-Time Poisoned Sample Detection identifies which input examples trigger malicious matching by studying how the model responds differently to them. Together, these papers show that triggers leave fingerprints you can find by examining attention flows, loss slopes, and model behavior under controlled tests.

These methods work at different stages: some detect during training (spotting poison in the data itself), others after training (testing the deployed model), and some work when the model is running in production (testing live examples). They build on each other because finding where the trigger lives in the model tells you which neurons or attention patterns were corrupted, so you can then design a defense that removes or disables those specific patterns.

Training models that resist poisoned data

Instead of finding poison after it's in your training data, some defenses prevent poisoned data from corrupting the model in the first place. The core idea is that if you can train in a way that doesn't memorize stray mislabeled examples or subtle patterns, a few poison examples won't matter. This is hard because the model is supposed to learn from data, and a backdoor trigger looks like a legitimate pattern if the attacker is clever.

Defending against Backdoor Attacks via Module Switching keeps several smaller models in reserve and only activates them when the main model's confidence is low—if a backdoor trigger causes weird behavior, the switch happens before damage spreads. BYORn defends large vision-language models by teaching them to generate their own safe outputs as a reference; if the model's behavior diverges from this internal baseline, it is likely poisoned. From Poisoned to Aware makes language models self-reflect: they learn to notice when they have been given malicious inputs and alert you instead of executing the backdoor. INDEXGUARD screens suspicious training examples in a federated setting (where many parties contribute data) before they corrupt the model. Reliable Poisoned Sample Detection uses a technique called sharpness-aware minimization to identify which training examples are most likely to be poisoned, then removes them before they influence the model.

These approaches share a principle: they catch poison early or design the model to survive it. Module switching and self-aware models work even if some poison slips in; detection methods identify poison to remove it. Together they form layered defense: even if one layer fails, others catch the attack.

Understanding backdoors across model types and domains

Backdoors are not limited to image classifiers or text models—they can hide in agents, reinforcement learning systems, time-series forecasters, and any model that learns from data. Understanding the attack surface means studying real deployments: what happens when an RL agent controls a robot, when a model distills knowledge from another model, when a system chains multiple components? Each domain introduces new attack angles.

SkillTrojan shows that skill-based AI agents (systems that learn specific tasks like SQL query generation) can be backdoored to follow hidden commands while preserving normal accuracy. Beware Untrusted Simulators reveals that when an RL agent trains in a simulator environment, an attacker can poison the simulator to teach the agent a backdoor that transfers to the real robot—a critical vulnerability because the agent learns from simulator experience. Fox in the Henhouse demonstrates supply-chain attacks where poisoned data flows through an RL system's training pipeline with just 3% data corruption, reducing returns by 80%. TrojanTO implants backdoors directly into trajectory models (models that predict action sequences) at the action level, working across diverse architectures. Angel or Demon investigates how certain training techniques meant to make models less vulnerable actually make them more vulnerable to backdoors by changing the direction of the loss function in a way that makes backdoor patterns easier to learn.

These papers map the attack surface: backdoors work in RL agents controlling physical systems, in distilled models, in supply chains, in time-series systems, and sometimes training defenses accidentally increase the risk. They explain why each domain is vulnerable and what attackers exploit, helping defenders prepare specific protections rather than generic ones.

Hiding and protecting watermarks in models

Watermarks are hidden signatures baked into a model that prove ownership: you stamp your model with a secret message that only you can verify. Unlike backdoors (which are malicious), watermarks protect intellectual property. But watermarks face their own attacks: someone might try to remove them, forge them, or re-embed them to claim ownership themselves.

CompMarkGS watermarks 3D graphics models even after they are compressed, preserving both the proof of ownership and the visual quality. LLM Fingerprinting via Semantically Conditioned Watermarks creates stealthy fingerprints in language models that survive finetuning and quantization (common ways to adapt or shrink models), so watermarks don't disappear when users modify the model. SIGMark watermarks video generation models by embedding marks during generation, then extracting them blindly (without seeing the original model weights). THE SELF-RE-WATERMARKING TRAP studies an adversary who steals your watermarked model and re-watermarks it with their own mark to erase your ownership claim; the paper proves theoretical bounds on how hard this is to defend. Watermark-based Attribution of AI-Generated Content shows that watermarks accurately identify which model generated an image, and they resist common edits like resizing or compression.

These papers solve a practical problem: how do you prove you built a model if someone steals it? Watermarks must be hidden during training or generation, survive transformations the user might apply, and be verifiable without exposing your keys. The strongest designs tie the watermark to the model's semantic output (what the model does) rather than pixel-level details, so edits and compression don't destroy the proof.

Attacks and frontier threats to anticipate

To defend well, you need to know what attacks are actually possible. Researchers study new attack vectors: how to poison retrieval-augmented generation (RAG) systems, how to remove watermarks, how to generate undetectable backdoors, and how to exploit the fundamental trade-offs between watermark resistance and stealth.

Eyes-on-Me poisons RAG systems by optimizing attention-steering patterns that transfer to unseen systems, raising attack success from 22% to 58%. LLM Watermark Evasion via Bias Inversion achieves over 99% removal success by manipulating the probability bias the watermark relies on, bypassing diverse schemes while keeping text quality high. RLCracker trains an RL attack that learns to remove watermarks from language model outputs at test time, achieving 98.5% removal rate and generalizing to 10 different watermarking schemes. Statistically Undetectable Backdoors proves a fundamental limit: backdoors can be created so subtle that statistical tests cannot distinguish them from clean models, showing a power asymmetry between attacker and defender. Catch-22 establishes that watermarking schemes face a trilemma: you cannot simultaneously maximize detection difficulty, stealth, and reliable verification—there are inevitable trade-offs.

These papers chart the attack frontier by demonstrating new threat vectors and proving fundamental limits. They show that some problems (removing watermarks, poisoning retrieval systems) are easier for attackers than commonly thought, while others (detecting undetectable backdoors) run into hard statistical barriers. Defenders use these insights to choose which guarantees are realistic and where no perfect defense is possible.
