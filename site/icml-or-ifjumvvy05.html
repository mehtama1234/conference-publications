Normality Calibration in Semi-supervised Graph Anomaly Detection

A student model learns what normal looks like by copying a teacher's score patterns and keeping normal shapes compact.

When you only have a few labeled normal examples, a graph model tends to overfit to just those examples, missing what normal really means. Zero assumption version

Learning normality with only a handful of examples

In a real graph, most nodes are normal (healthy users, legitimate transactions). You have a few labeled examples of normal nodes and want to spot the rare anomalies. The naive approach: train a model on only those few labeled normal nodes. But this backfires. The model learns the specific quirks of those few examples, not the general shape of normal.

The result: the model becomes very picky about what counts as normal. It flags many real normal nodes as anomalies (false positives) because they do not match the narrow training set exactly. The model has not learned the true pattern of normality; it has memorized a tiny slice of it.

In one sentence. A model trained only on a few labeled normal examples overfits and flags many real normal nodes as anomalies.

The algorithm as a flow

What it actually does

Freeze the teacher

Pre-trained anomaly detector is locked; only the student learns.

Copy teacher scores

Student’s score for each node drifts toward the teacher’s score (normal vs anomaly boundary).

Perturb labeled normal

Add small random noise to normal node representations, then measure how much the representation changed.

Penalize drift

If perturbed representation drifts far from original, student loses a penalty—pulls them back together.

Result

Normal nodes cluster tightly; anomalies drift away; decision boundary sharpens.

What the paper changes

What the paper moves

The paper changes two things at once: the anomaly scores (the numbers that rank each node from most normal to most anomalous) and the internal representations (the pattern of numbers the model uses to describe each node). The student model learns to shift both to match the teacher.

the object it moves  =  Anomaly scores and node representations
The hidden quantity

The hidden quantity: normality compactness

measured quantity  =  Representation compactness

This paper measures something called representation compactness: how tightly bunched the internal descriptions of normal nodes are. If all normal nodes have similar internal patterns, they form a tight cluster. If they are scattered, the cluster is loose. A tight cluster makes anomalies obvious (they fall outside it naturally). A loose cluster makes the boundary fuzzy, so anomalies sneak in.

The paper estimates compactness by adding tiny random perturbations (noise) to labeled normal node representations and checking if the representation stays close to the original. If a small noise causes the representation to drift a lot, the normal cluster is loose and fragile. If it stays put, the cluster is tight and stable.

Paper reading. Perturbation-guided consistency loss enforces that perturbed and unperturbed representations of labeled normal nodes remain similar, minimizing the discrepancy via the loss function.
Why it works

Why it works: learning from a broader teacher

The core idea is that the teacher (pre-trained on some semi-supervised method) has already seen many nodes and learned a reasonable, broad definition of normal. It is not perfect, but it is broader than a model trained only on the few labeled examples. When the student copies the teacher’s scores across ALL nodes (not just labeled ones), it absorbs that broader view.

But copying scores alone is risky: the teacher makes mistakes on unlabeled data (it does not know which of those are true anomalies). So the paper adds a second lock: force the internal representations of labeled normal nodes to stay tightly grouped via the perturbation loss. This tightness acts as a shape constraint. A tight cluster for normal nodes means the decision boundary becomes crisp: anything inside the cluster is normal, anything outside is anomalous. This compactness also acts as a sanity check, because anomalies cannot easily fit into a tight cluster, they are naturally excluded.

The two-part loss

First in words:

Total training loss = ScoreDA (align student scores to teacher) + lambda * NormReg (keep perturbed normal representations close to original)

Then the compact form:

L_total = L_ScoreDA + lambda * L_NormReg, where L_NormReg = mean(||h_i - h_i_aug||^2) for labeled normal nodes only

Every symbol:

L_ScoreDAloss that pulls student score distribution toward teacher score distribution
L_NormRegloss that penalizes distance between original and perturbed normal representations
h_ioriginal representation (internal pattern) of labeled normal node i
h_i_augrepresentation of node i after adding small random perturbation
lambdaweight controlling how much to enforce compactness (higher = tighter cluster)
|| ||^2squared distance between two representations (how far apart they are)
Worked example: two nodes over one training step
Labeled normal node A: ScoreDA pulls its score from 0.3 toward teacher’s 0.8 (delta = 0.5). NormReg: original repr=[2.1,1.8], perturbed=[2.3,1.9]; distance=0.05, penalty with lambda=1.0 adds 0.05 to loss.
Unlabeled node B (unknown if normal): ScoreDA pulls its score from 0.6 toward teacher’s 0.4 (delta = -0.2). NormReg does NOT apply (not labeled), so no compactness penalty.
Total loss step 1: 0.5 + (-0.2) + 0.05 = 0.35. Model updates to reduce this, pulling A’s score down and compacting A’s representation.

ScoreDA spreads the student’s judgment across all nodes (labeled and unlabeled); NormReg keeps that judgment crisp by forcing labeled normal nodes into a tight cluster.

What can go wrong

What can go wrong

Teacher itself is bad. If the pre-trained teacher misclassifies many nodes, the student copies those mistakes. The framework is only as good as the teacher it starts with.
Labeled normal nodes are not truly representative. If the few labeled nodes are atypical (e.g., all from one subgroup), the tight cluster around them does not capture the full range of real normal. Anomalies from other normal subgroups will be flagged.
Perturbations do not match real noise. If the random perturbations used during training do not resemble the kinds of noise or variation in real unlabeled nodes, the learned compactness may be fragile—it protects against the wrong kinds of drift.
Done right: start with a solid teacher, use truly random perturbations, and hold out a separate validation set to tune the lambda weight.
What a runnable demo should prove

What a runnable demo should prove

Build a tiny graph with 50 nodes: 40 normal (tightly grouped in feature space) and 10 true anomalies (scattered). Use only 5 randomly sampled normal nodes as labeled training data. Train a baseline model on just those 5. Then train a student model (GraphNC) with a pre-trained teacher. Measure false-positive rate (how many normal nodes are wrongly flagged) on the 35 held-out normal nodes.

False positive rate = (normal nodes flagged as anomaly) / (total held-out normal nodes); should drop from baseline ~55% to GraphNC ~15%

The demo must show that tight normal clustering (via NormReg) plus teacher alignment (via ScoreDA) cuts false alarms on unlabeled normal nodes by more than half.
