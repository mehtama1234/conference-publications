FreqKV: Key-Value Compression in Frequency Domain

Compress a language model's memory by keeping only the slow-changing patterns and discarding fast noise.

Paper explainersAll themesLLMs & Foundation Models

Large language models build up a memory cache as they read or write each new word. For long conversations or documents, this cache grows huge and slows the model down. FreqKV compresses this memory by recognizing that the useful patterns change slowly (like the plot of a story), while random details change fast (like typos). The paper shows how to safely throw away the fast junk and keep only the slow patterns that matter.

Zero assumption version

Memory fills up when a model reads long texts

A language model reads text one word at a time. After reading each word, it stores a compressed memory of what it has seen so far. This memory is called the key-value cache, or KV cache for short. For a 1,000-word document, it stores 1,000 entries; for a million-word document, a million entries.

The naive fix is to throw away the oldest entries to make room. But this loses important context. Imagine reading a detective story: if you forget chapter 3, you cannot solve the puzzle in chapter 20. The model runs into the same trap. It forgets critical details from earlier in the text, so its answers become wrong. And when the model tries to read longer texts than it was trained on, this memory loss gets worse.

The problem in one sentence. Forgetting old memories hurts the model, but keeping all memories makes the cache too big.

What the paper changes

The one thing the paper changes

The paper directly compresses the key-value cache by removing high-frequency components (fast-changing noise) and keeping only low-frequency components (slow-changing patterns). This is a lossless transformation in the frequency domain, not a crude trick of throwing away individual words to save space.

the object it moves  =  Key-value cache compression in frequency space
The hidden quantity

The frequency spectrum: which patterns matter

measured quantity  =  Frequency spectrum of context

The hidden quantity is the frequency spectrum: a breakdown of which parts of the memory change slowly (low frequency) and which parts bounce around randomly (high frequency). Slow means the pattern is consistent across many words; fast means it changes every few words or even randomly.

The paper estimates this spectrum using a Fourier transform, a standard mathematical tool. It converts each memory entry from its normal form (a list of numbers describing one word's meaning) into a frequency view (a list of numbers describing how much slow-change and how much fast-jitter lives in that entry). High-frequency components are almost all noise; low-frequency components carry the meaning.

Why it works

Why this works: slow patterns carry meaning

A language model's understanding of context is built on patterns that persist. The plot of a story does not change every sentence; the tone of a speaker does not flip with each word. These slow-changing patterns live in low frequencies. In contrast, random variability, typos, and one-off details show up as high-frequency jitter.

By converting each memory entry to frequency space, the paper separates signal (low frequency) from noise (high frequency). Removing high-frequency components throws away the jitter but preserves the meaning. The model can still recall what matters—the plot, the characters, the intent—because those live in the low-frequency components you kept. The discarded high-frequency components were contributing nothing but computational overhead.

This works across both reading (prefilling) and writing (decoding) because the meaning of past context does not depend on how fast it varies, only on what stays constant.

The equation

First in words:

For each key-value entry, compute the discrete Fourier transform to find frequency components. Keep only the first K coefficients (low frequency). Discard the rest. Inverse transform to get the compressed entry.

Then the compact form:

compressed_KV = IDFT(keep_first_K_coeffs(DFT(original_KV)))

Every symbol:

DFTdiscrete Fourier transform, converts a list of numbers into frequency components
original_KVthe uncompressed key-value cache entry for one word
keep_first_K_coeffsa selection operation: take only the first K frequency coefficients
IDFTinverse discrete Fourier transform, converts frequency components back into a list of numbers
compressed_KVthe result: a shorter list that keeps the slow patterns, drops the noise
A tiny worked example
Original entry (8 numbers): [10, 11, 9, 10.5, 11, 9.5, 10, 10.5]
DFT reveals: low freq = [10.3, 0.4, 0.1]; high freq = [0.05, 0.02, 0.03, 0.01, ...]
Keep first 3 low-frequency coefficients; discard the rest.
IDFT(first 3 coeffs) = [10.1, 10.2, 10.0, 10.1, 10.2, 10.0, 10.1, 10.2]
Compressed entry is now smaller and has lost the fine jitter, but kept the steady value around 10.

The Fourier transform is a standard mathematical tool that reveals what stays the same and what bounces around, letting you throw away the bouncing parts safely.

What can go wrong

What can go wrong

Throwing away too much too fast. If you keep only a tiny number of low-frequency components, you lose nuance. A story with subplot details collapses to a bare skeleton. Set K (the number of components to keep) too low, and the model fails.
High-frequency patterns that actually matter. In rare cases, a fast-changing detail is critical. For example, a mystery where the guilty character's behavior changes abruptly in chapter 5. This shows up as high frequency, and it will be discarded, causing the model to miss the plot twist.
Fourier transform assumes periodicity. The Fourier transform assumes patterns repeat. If a document has one unique event that never repeats, it may not decompose cleanly into the frequency view, and compression might waste the opportunity or lose the event.
Done right. Set K to keep enough low-frequency components to capture the context you need (empirically tuned per model size). Use iterative compression only when the cache is large. Validate on realistic long-context tasks (retrieval, summarization, question-answering over long texts).
What a runnable demo should prove

What a runnable demo should prove

A demo should: (1) Load a document longer than the model was trained on, say 256K tokens. (2) Read through it word by word, building the key-value cache. (3) At each step, apply FreqKV compression to shrink the cache. (4) After reading, ask the model a question about details early in the document that should still be remembered. (5) Measure whether the model's answer is correct. Compare the memory used (should be 30-40% of the original) with the accuracy (should stay above 85% for real test sets).

sustained_accuracy = (questions_answered_correctly / total_questions) * 100 ; memory_reduction = (original_cache_size - compressed_cache_size) / original_cache_size * 100

The demo must make it impossible to miss that the model answers correctly about events from early in a 256K-token text while using only a fraction of the memory, where naive token dropping would have lost the answer.
