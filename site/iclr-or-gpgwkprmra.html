RAEE: Robust Retrieval-Augmented Early Exit

Ask similar examples when to stop the model early, speeding up question-answering without training new exit classifiers.

Paper explainersAll themesEfficiency & Systems

When a language model answers a question, it runs many layers of computation. But most layers are overkill: the model often knows the right answer by layer 10, not layer 24. Early exit stops the model at an intermediate layer to save time instead of running to the end. The hard part is deciding which layer to stop at. Training new classifiers to make that choice is expensive and fragile. This paper says: just store which layers gave correct answers on training data, retrieve the ones that look like your current question, and copy their exit layer.

Zero assumption version

Layers do more work than they need to

Language models run data through 24 or 48 layers of mathematical operations. But the model's answer often stabilizes long before the final layer. At layer 10 it is 99% confident what the answer is, and layers 11-24 are just repeating the same thing. Exiting early saves time because every layer requires the same amount of computation; if you skip layers 11-24, you have done only 10/24 of the work.

The problem: how do you know which layer to exit at? Naive approach: train a small classifier at each layer to predict stop/go. This requires running many training loops, one per layer, and those classifiers often fail when the test input is different from training. Or, heuristic approach: exit when the model's confidence crosses some threshold. But confidence is noise; a model can be confident and wrong, or uncertain and right.

The method in one sentence. Build a database of which layers gave correct answers on training data, then when answering a new question retrieve examples similar to your input and copy their exit choices.

The algorithm as a flow

What it actually does

Build database offline

Run each training example through the model, recording which layer first predicted correctly.

Embed inputs

When a new question arrives, convert it to a list of numbers using the model's first layer.

Retrieve top-k neighbors

Search the database for training examples with number-lists nearest to the new input's number-list.

Aggregate exit layers

Collect the exit layers from the top-k neighbors and combine them (e.g. majority vote).

Stop at that layer

Run the model only up to the agreed exit layer and predict from that layer's output.

What the paper changes

What the paper changes: the exit decision

Most early-exit methods train a tiny classifier at each layer to decide stop/go. RAEE does not train any classifiers. Instead, it stores a database and looks things up. The exit decision becomes a retrieval problem, not a learning problem.

the object it moves  =  exit layer decision
The hidden quantity

The hidden quantity: which layer each input type exits at

measured quantity  =  which layer each type of input exits at

The paper introduces a named quantity: the exit layer distribution. For any input, there is a true layer where it could first predict correctly (the gold exit layer). But the model does not know it in advance. The paper observes: similar inputs tend to have similar gold exit layers. If you have seen 100 questions about animals and they all exit around layer 12, a new animal question probably also exits at layer 12.

The paper estimates this distribution by storing, for each training example, the layer where it first predicted correctly. When answering a new question, it retrieves top-k training examples and uses their exit layers as a surrogate for the new example's gold exit layer.

Why it works

Why it works: nearest neighbors have the same exit layer

The core insight is simple: if two inputs are similar (their number-lists are close in a mathematical sense), they should exit at similar layers. Why? Because similar questions often trigger the same pattern of thinking. A math question and a music question use different neural circuits; the model settles on the right answer via different paths, exiting at different layers. But two math questions both make the model follow the math circuit, settling at similar layers.

RAEE exploits this: instead of training a separate classifier for each layer (expensive), it uses retrieval to copy the exit decision from examples the model has already seen. Retrieval is fast and requires zero training. The aggregation step (majority vote or averaging the top-k exit layers) smooths out noise: if 7 neighbors exit at layer 11 and 1 exits at layer 9, layer 11 is the consensus.

Math after the picture

The aggregation equation

First in words:

exit layer is the mode of the exit layers from the top-k neighbors, optionally weighted by similarity distance

Then the compact form:

L_exit = argmax_l count(exit_layers_of_neighbors == l) OR with distance weighting: L_exit = argmax_l sum_{i=1}^{k} exp(-distance_i) * (exit_layer_i == l)

Every symbol:

L_exitthe layer chosen to exit at
exit_layer_ithe layer neighbor i exited at in training
distance_ihow far neighbor i's embedding is from the query
khow many neighbors to retrieve (typically 8)
count(...)how many neighbors exited at this layer
argmax_lpick the layer l that maximizes the sum
A tiny worked example
Query input: a trivia question about animals.
Retrieve top-8 neighbors: all are also animal trivia.
Their exit layers: [11, 11, 11, 11, 12, 10, 11, 11].
Count at each layer: layer-10=1, layer-11=6, layer-12=1.
argmax = layer-11 (6 neighbors exited there).
Decision: exit at layer 11.
Alternative (distance-weighted): neighbor 1 distance=0.05, layer=11 -> weight=exp(-0.05)≈0.95; neighbor 5 distance=0.3, layer=12 -> weight=exp(-0.3)≈0.74. Weighted sum for layer-11 = 0.95+0.95+0.95+0.95+0=3.8. Weighted sum for layer-12 = 0.74. Layer-11 still wins.

The equation picks the exit layer that the most similar neighbors chose, because neighbors reveal the golden distribution without training.

What can go wrong

What can go wrong

Out-of-distribution inputs. If the test input has no similar neighbors in the training database, the retrieval will grab distant examples whose exit layers are noisy. The method assumes test and training distributions overlap.
Small retrieval database. If the training database is tiny, top-k neighbors might still be quite far away. Accuracy depends on having a large, diverse training set to retrieve from.
Number-list quality from layer 1. The method uses the model's layer-1 number-list to find neighbors. If that list does not represent which questions are alike, retrieval will fail.
Done right. With a large, representative training set and good number-lists from layer 1, the method generalizes to new tasks with zero training of exit classifiers.
What a runnable demo should prove

What a runnable demo should prove

Build a small language model (e.g. DistilBERT or a 7-layer transformer). Train on a classification task (e.g. MNLI, RTE). Store the exit layer for each training example (the first layer where it predicted correctly). When answering test questions, retrieve the top-8 training examples with closest number-lists and vote on the exit layer. Measure speedup (layers skipped divided by total layers) and accuracy (correct predictions on test).

speedup = (total_layers - average_exit_layer) / total_layers; accuracy = count(correct_predictions) / count(test_examples)

The demo should show: speedup between 1.5x and 2.5x with no accuracy loss or even gain, and no training of exit classifiers.
