Memento: Toward an All-Day Proactive Assistant for Ultra-Long Streaming Video

Memento turns a streaming video model into a long-duration assistant by keeping only selected memory entries, retrieving the ones tied to the current question, and training the memory access pattern to match the time structure of the stream.

Paper explainersAll themesMultimodal

A video assistant that watches for minutes can answer short-range questions, but an assistant that watches for hours has to remember the right events without storing every frame as active context. Standard long-context scaling fails because the count of internal text-like units keeps growing with video length, and the full all-to-all comparison step over that growing history becomes too expensive and too noisy. Memento replaces that strategy with sparse memory. It stores compact event summaries over time, retrieves only the entries tied to the current query, and trains the model so that the chosen memories line up with the actual temporal step where supervision is applied.

Zero assumption version

Full-context streaming does not scale to all-day video

In an online video setting, the model receives new frames continuously and may have to answer a question whose answer depends on something that happened hours earlier. A simple design keeps appending new frame units to the context window. That design breaks for two reasons. First, cost grows with stream length because the model must process a larger history at each step. Second, the signal gets diluted because rare important events are buried inside a very long sequence of mostly irrelevant content.

A proactive assistant needs a different behavior. It must preserve enough information about earlier events to support later reminders or warnings, but it must also forget large amounts of routine material that will never matter again. The central problem is therefore selective retention, not raw context length.

The paper's move. Memento stores sparse memory over the stream, selects memory by query relevance, and trains the memory access pattern so the chosen entries align with the correct time step.

What the paper changes

What the paper changes

Memento changes how long-range context is represented. Instead of keeping the entire video history as one growing sequence of internal units, it writes selected past content into a memory bank and retrieves only the entries linked to the current query and time step.

the object it moves  =  long-range video context representation
The hidden quantity

The hidden quantity: memory usefulness at query time

measured quantity  =  query-conditioned memory utility

The important quantity is not how many memories are stored, but how often the retrieved memories contain the event that actually determines the answer. A large memory bank is useless if the correct event is not retrieved when needed. A small bank can work well if its selection rule keeps the right past events and ignores routine footage.

Memento therefore cares about two linked decisions: what to write into memory and what to retrieve later. The first decision controls coverage of important events. The second decision controls whether the current question can find those events. The step-aware training rule ties both decisions to supervision, because the model is rewarded when the correct stored entry is used at the correct later step and penalized when it relies on the wrong past time.

Why it works

Why sparse memory with step-aware training works

The failure of raw long context comes from treating every past unit as equally available and equally expensive. In a many-hour stream, most content has no bearing on a later reminder. Memento reduces that burden by turning the past into selected memory entries. This lowers cost because future computation no longer scans the full detailed history, and it raises signal quality because the later reasoning stage sees fewer irrelevant items.

Query-related Memory Selection handles the second half of the problem. A memory bank alone does not help unless the current question can retrieve the correct entry, because stored evidence matters only if it is surfaced when the answer is formed. The model scores stored memories against the query, so asking about medication, for example, should pull entries tied to medication events rather than unrelated motion. This makes the reasoning step more stable because the answer module sees a targeted subset instead of thousands of mixed past units.

The step-aware memory lookup rule matters during training because memory systems are hard to supervise if the model can spread focus over the wrong past times and still sometimes guess the answer. By aligning that focus with the temporal step where the memory should be used, the training signal tells the model not only what answer is correct, but also which past memory access pattern produced that answer. That makes memory usage learnable over long streams rather than incidental.

Math after the picture

The retrieval rule

First in words:

At query time, score each stored memory entry against the current query and keep only the top-scoring entries for answer generation.

Then the compact form:

selected_memory = top_k over m of score(query, memory_m)

Every symbol:

selected_memorythe subset of stored memory entries used for the current answer
score(query, memory_m)how relevant memory entry m is to the current query
top_kkeep only the k highest-scoring entries
memory_mone stored event summary from an earlier time in the stream
A tiny worked example
Suppose the memory bank holds five entries from earlier today.
The current query asks whether medication was already taken.
The stored entries receive relevance scores 0.05, 0.12, 0.91, 0.07, and 0.31.
If k = 2, the system retrieves the entries with scores 0.91 and 0.31.
The answer stage uses those entries plus the present video state, instead of scanning the full multi-hour stream.

The retrieval rule matters because long-range performance depends more on selecting the right past event than on preserving all past detail.

What can go wrong

What can go wrong

Important events may never be written to memory. If the retention policy misses an event at write time, no later retrieval rule can recover it. Long-range failure then comes from poor storage rather than poor retrieval.
Queries can retrieve the wrong subset. A vague or misleading query representation can rank irrelevant memories above the correct one, so the answer stage reasons over the wrong evidence.
Time alignment can stay weak during training. If the focus pattern is not tied closely enough to the correct temporal step, the model may answer correctly by shortcutting through spurious correlations instead of learning durable memory access.
Done right. The system works best when event writing preserves rare important moments, retrieval is sharply tied to the current question, and the training signal punishes answers that rely on the wrong past time step.
What a runnable demo should prove

What a runnable demo should prove

Build a toy streaming video assistant that observes a long synthetic day with events such as door openings, object placements, and scheduled medication. Compare a full-history baseline against a memory-bank system that stores compact events and retrieves only the top-scoring memories at query time.

The demo should ask questions whose answers depend on events from different delays, such as five minutes earlier, one hour earlier, and several hours earlier. Log whether the correct event was written to memory, whether it was retrieved when queried, and whether the final answer was correct. The method's core claim is supported if long-delay questions improve while the active context stays bounded, because the memory bank preserves selected event summaries instead of replaying the full stream.

long_range_answer_rate = correct_answers_on_queries_requiring_past_events / total_long_range_queries

A convincing result shows that sparse memory preserves the right event history without letting active context grow with the full stream length.
