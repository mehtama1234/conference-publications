Foresee-to-Ground: Identify-then-Measure for Video Temporal Grounding

Instead of guessing when an event happens in a video by predicting raw timestamps, the paper builds a library of candidate event chunks first, then uses those as evidence to make precise boundary measurements.

Paper explainersAll themesMultimodal

Video understanding models today struggle to pinpoint exactly when events happen in videos because they try to predict timestamps directly from raw visual information—like trying to guess the exact second a goal was scored by staring at the pixels. This paper proposes a different approach: first identify candidate event regions by learning what event boundaries look like, package those regions as concrete evidence, and then let the language model cite that evidence to measure precise timing. This two-step dance makes predictions checkable—because each boundary is tied to a specific piece of evidence you can verify—and more accurate, because predictions stay anchored to realistic event regions instead of drifting into noise.

Zero assumption version

Timestamps are slippery targets

Video understanding models today are built to read a video as a stream of visual tokens—little bite-sized chunks of image information fed one after another—and spit out two numbers: the start time and end time of an event. The model takes in pixels and directly outputs timestamps. This feels natural but it breaks in practice. When you're asking the model to predict a raw number like 5.3 seconds or 42 frames, there is no way to check whether that answer actually makes sense. The model might say an event starts at exactly 5 seconds even though no visual evidence supports that boundary. It is treating temporal grounding like raw regression—fitting numbers to a curve—rather than like finding actual things.

A beginner would try to make this better by feeding more visual information, tuning the model harder, or using better backbones. But that does not fix the core problem: the model is trying to generate timestamps in a void, without being forced to justify them against anything concrete in the video. There is nothing to ground the predictions to.

The method in one sentence. F2G reformulates timestamp prediction as an Identify-then-Measure process: first extract candidate event chunks and package them as citable evidence, then let the language model cite specific evidence to justify its boundary measurements.

The algorithm as a flow

What it actually does

Stage 1: Pretraining

Temporal module learns to produce boundary-sensitive features by predicting what the next frame looks like—a task that forces it to capture event transitions.

Stage 2: Candidate Extraction

Trained temporal module processes the entire video and proposes the top-K candidate event segments with scores.

Stage 3: Evidence Encoding

Each candidate segment is encoded into a summary representation, building a pool of evidence units that the LLM can reference.

Stage 4: Identify-then-Measure

Language model first cites which candidate evidence is relevant, then generates precise boundary refinements conditioned on that choice.

Stage 5: Joint Training

Both the evidence encoders and LLM reasoning are fine-tuned together, with supervision for both which evidence is cited and what boundaries are correct.

What the paper changes

What the paper changes

The paper swaps out the black-box timestamp regression for a two-stage pipeline: first, it extracts concrete candidate event segments from the video and packages them as evidence. Then the language model is forced to cite one of these segments and refine its boundaries from there. The object is the prediction strategy—moving from raw timestamp generation to evidence-conditioned boundary refinement.

The hidden quantity

The hidden quantity: Boundary Sensitivity

measured quantity  =  Boundary-sensitive representation

The key hidden quantity is how sensitive the temporal features are to event boundaries—whether the numbers the temporal module produces spike up at the start or end of real events. You can't see this directly in the video or in the final timestamp predictions, but the paper measures it indirectly: in Stage 1, the temporal module is trained on a predictive task (forecasting the next frame), which forces it to learn what comes next in the video. This is clever because coherent event structure has predictable dynamics—when a goalkeeper catches a ball, the next frame is predictable; when the scene cuts unpredictably, prediction breaks down. By optimizing for prediction accuracy, the module learns to encode event boundaries without ever being told where they are.

The paper measures boundary sensitivity by tracking how well the learned features support candidate event extraction: if the top-K candidate segments match real events, the representation is working. This is measured via Intersection over Union (IoU)—the overlap between predicted and actual event intervals—which becomes the upper bound on the final grounding accuracy.

Why it works

Why the two-step dance works

The core insight is that grounding a moment in a video is not a single regression problem—it is two problems layered together. First, the model needs to know which event the query is asking about. Second, it needs to refine the exact boundaries of that event. Old approaches tried to do both at once by predicting raw timestamps, which is like trying to find a specific chapter in a book by guessing page numbers without knowing the book's structure. F2G separates the two tasks.

Here is how it works mechanically: The temporal module learns what event boundaries look like by being trained to predict future frames—a task that naturally highlights transitions and changes. Once trained, this module scans the entire video and proposes candidate event chunks, each with a relevance score. These chunks become the evidence pool—concrete, checkable regions. When the language model receives a query, it first identifies which candidate is relevant (Identify), then measures the exact boundaries conditioned on that hypothesis (Measure). The key mechanism is that the boundary measurement is now constrained—the model cannot drift into noise because it is anchored to a specific candidate region. If the candidates are good, the final boundaries will be good. If the candidates are bad, the final accuracy is capped—which is honest and fixable. The evidence pool acts as a constraint that forces predictions to stay grounded.

Why does this make grounding more stable? Because each boundary prediction is now linked to an explicit, verifiable evidence ID—the model says something like 'I cite candidate #3, which covers frames 5-8, and I refine the boundaries to 5.2-7.8.' This citation makes predictions falsifiable. You can check whether the boundary actually aligns with the cited evidence. In contrast, old approaches said '5.2 to 7.8 seconds' with nothing to justify it against. The structure of Identify-then-Measure forces the model to be accountable.

The core training objectives

First in words:

Stage 1: weighted sum of prediction loss plus boundary-sensitivity regularization. Stage 3: LLM generation loss plus evidence citation loss plus lightweight proposal loss to keep boundaries aligned.

Then the compact form:

L_S1 = (1-lambda) * L_pred + lambda * L_SIGReg; L_S3 = L_gen + L_citation + alpha * L_proposal

Every symbol:

L_S1Stage 1 loss combining next-frame prediction with boundary regularization
L_predError in predicting future frame tokens; low when transitions are smooth
L_SIGRegPenalty for misaligned proposal scores; enforces candidates match real events
lambdaWeight balancing prediction accuracy against boundary alignment (0.0 to 1.0)
L_S3Stage 3 total loss for fine-tuning language model and evidence encoders
L_genLLM generation error; measures whether predicted boundaries are correct
L_citationError in choosing the right evidence ID to cite for each query
L_proposalSmall penalty keeping candidate segments aligned during fine-tuning
alphaWeight of the proposal loss (kept small to not override LLM training)
A tiny worked example
Imagine a 5-second video with one goal scored at frames 2-4. The temporal module is trained on 10 frames.
Frame 1 (0.2s): Quiet play. Prediction accuracy 90% → L_pred = 0.1. Boundary score (likelihood of transition) = 0.1 → L_SIGReg penalty = 0. Total: 0.1.
Frame 2-4 (0.4-0.8s): Goal happening. Prediction accuracy 40% (hard to predict, video cuts fast) → L_pred = 0.6. Boundary score = 0.9 → L_SIGReg penalty = 0.1 (good). Total: 0.7.
If lambda = 0.7: Stage1 loss per time = (0.3 × L_pred) + (0.7 × L_SIGReg) = (0.3 × 0.4) + (0.7 × 0.05) = 0.155. This rewards the module for assigning high boundary scores exactly where events happen.
Stage 3: Model proposes top-3 candidates: [0.2-1.0s] (wrong), [1.5-3.5s] (right, IoU=0.9 with ground truth), [3.8-4.5s] (partial). Citation target z* = candidate #2. If model cites #2 and predicts 1.6-3.4s (error ±0.1): L_gen ≈ 0.02, L_citation ≈ 0 (cited the right one). Final accuracy = 92%.

Stage 1 rewards the temporal module for learning what coherent events look like. Stage 3 trains the language model to use evidence strategically, keeping its predictions honest because every boundary must justify itself against a concrete candidate.

What can go wrong

What can go wrong

Candidate quality is a hard ceiling. If the top-K candidates do not cover the true event, the language model cannot cite the right region and the final grounding fails. The paper's accuracy is fundamentally capped by how well the temporal module extracts good candidates. If the module misses fine-grained boundaries (e.g., exactly which frame the goal starts), the refined predictions will miss them too.
Computational cost from candidate extraction. The model must process the entire video to extract top-K candidates before the language model even starts reasoning. For long, untrimmed videos this is expensive. The paper does not address how to scale to videos longer than training data or how to trade candidate quality for speed.
Citation mistakes propagate. If the language model cites the wrong candidate (wrong Identify step), the Measure step is doomed. The paper trains the citation target with maximum IoU matching, which assumes the best candidate is always available. If candidates are clustered or ambiguous, the model may learn a brittle citation strategy.
Done right: Two separate targets. When candidate extraction is accurate and the citation supervision is clean, the two-step separation avoids the trap of trying to predict timestamps from nothing. The boundaries stay within the candidate regions, forcing plausible predictions.
What a runnable demo should prove

What a runnable demo should prove

To see F2G in action, build a tiny video grounding system on a dataset like ActivityNet or Charades. Start with a pre-trained video encoder and temporal module. Extract top-K candidate segments using the proposal head. Feed the candidates and a query to a language model via LoRA fine-tuning. The demo should show three things: (1) that the candidates cover real events by plotting the top-K segments on a timeline and checking coverage against ground truth; (2) that citation accuracy improves when candidates are good, by tracking how often the model cites the correct evidence ID; and (3) that boundary predictions stay within their cited candidates and do not drift into random timestamps.

IoU accuracy = sum of (Intersection over Union between predicted and true intervals) / number of queries; Citation accuracy = count of (model cited a candidate with IoU > 0.5 to ground truth) / total queries

The defining test: does the model's citation ID always point to a region that actually contains the true event? If yes, the two-step separation is working. If the model cites random candidates, the method has degraded to raw timestamp generation.
