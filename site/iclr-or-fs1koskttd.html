Fathom-DeepResearch: Long Horizon Tool Use for Research Agents

Train a small language model to reliably use web search many times in a row by rewarding it for what each search discovers, not just the final answer.

Paper explainersAll themesAgents & Tool Use

When you ask a model to do research, it needs to search the web repeatedly to gather evidence, reading dozens of pages and building up an understanding step by step. But models often get stuck: they search carelessly, forget what they learned, or stop too early. This paper trains a small model to search reliably over long chains of questions and answers, using a new reward system that scores each individual search by how useful it was.

Zero assumption version

Why models fail at long research chains

Suppose you give a model a hard question like When did Company X launch their new product and which countries did they target first? A human would search for the company, find their press releases, read them carefully, then piece together an answer. But today's language models are bad at this. They see a question and try to guess the answer from their training data, which is outdated and incomplete. When forced to use web search, they search randomly, ignore what they find, search again anyway, and eventually give up.

A naive approach is to just train the model to pick better search terms. But that does not work, because the model does not learn what each search uncovered. It searches, ignores the result, and searches again. The real bottleneck is that the model has no feedback on whether each individual search was useful.

The method in one sentence. Train the model with a reward for each search separately. Score how much each search reduced the gap between what the model knew and what it needed to know. This teaches the model which searches pay off.

The algorithm as a flow

What it actually does

Step 1: Take a research question.

Example: when did this company launch a product in Japan?

Step 2: Search and score.

Model picks a search term, gets results. A reward system scores how much that search helped.

Step 3: Use that reward to train.

Model learns: searches that find new facts get high scores, random searches get low scores.

Step 4: Repeat the loop.

Model does 5, 10, 20+ searches, each time using the same reward signal.

Step 5: Synthesize into a report.

A second model reads all the search traces and writes a clean report with citations.

What the paper changes

What the paper changes

The paper changes a single thing: how the model is rewarded during training. Instead of getting a score only for the final answer, the model now gets a score for each individual search call—a step-level reward that grades the usefulness of that one search, independent of what comes after.

the object it moves  =  step-level reward per search
The hidden quantity

The hidden quantity: search utility

measured quantity  =  how much each search moves you forward

The paper measures a quantity that is never directly visible in the data: the marginal utility of a search, meaning how much that one search reduced your uncertainty or brought you closer to the answer. A search that finds a press release with a launch date is high-utility. A search that finds unrelated results is low-utility. A redundant search that repeats what you already know is low-utility.

The paper estimates this by training a classifier that reads the question, the search query, and the results, and predicts: did this search add new information, or was it wasted effort? When the model learns this classifier, it can give each search a score, and the model being trained learns from that score.

Why it works

Why step-level rewards work

Training a model on the final answer alone does not teach it about individual searches. If you tell the model you got the answer right, it cannot tell which of the 20 searches actually helped. Maybe searches 1–5 found the key evidence, and searches 6–20 were wasteful. But the model sees only the final reward and guesses randomly.

Step-level rewards fix this by scoring each search separately. When a search finds a new fact, it gets a high score immediately. When a search is redundant, it gets a low score immediately. Now the model can learn: this type of search, in this context, tends to be useful. Over many training examples, the model builds an intuition for which searches to do. It learns to search for company press releases instead of random products. It learns when to stop (once it has enough facts) instead of searching forever.

The paper also adds a second trick: during training, it keeps multiple candidate search strategies and favors the ones with high rewards. This prevents the model from collapsing into a single, narrow strategy and encourages it to explore different ways of investigating.

The reward equation

First in words:

The training loss is the expected negative reward across all searches in the chain, minus a regularization term that keeps the model from straying too far from its starting point.

Then the compact form:

loss = - E[sum_t reward_t] + lambda * KL(pi_new || pi_old)

Every symbol:

reward_tscore for the t-th search (how useful was it?)
E[...]average over many training examples
sum_tsum across all searches in the chain
lambdahow strong the regularization is
pi_newthe model's new search strategy
pi_oldthe model's old search strategy
KL(...)how different the two strategies are
A tiny worked example
Suppose a chain of 3 searches: first finds a press release (reward 8), second finds a news article (reward 6), third finds the same article again (reward 2).
Total reward = 8 + 6 + 2 = 16.
If the model stayed unchanged, KL = 0 and loss = -16.
If the model changed its strategy a lot, KL = 3, lambda = 0.5, so loss = -16 + 0.5 * 3 = -14.5.
The penalty term discourages the model from changing too fast, so it learns steady improvements instead of wild swings.

The model learns to pick searches with high reward_t, because higher rewards lower the loss (make training succeed).

What can go wrong

What can go wrong

Reward design is fragile. If the classifier that scores searches is poorly trained, the model learns bad search habits. If the classifier rewards searches that are coincidentally useful but not actually informative, the model will waste time on those searches.
Curriculum matters. If you ask the model to do 20 searches on day one, it will be confused and waste all its searches on useless queries. The paper uses curriculum training: start with easy, short-chain research tasks and gradually increase complexity.
Domain mismatch. The reward classifier is trained on one type of research task (finding company facts, say). If you deploy it on a different task (medical research), the rewards may be meaningless and the model's searches degrade.
Done right. When the reward classifier is accurate, the training regime starts simple, and the task fits the training domain, the model reliably chains 20+ searches together and produces well-supported reports.
What a runnable demo should prove

What a runnable demo should prove

Build a small demo that trains a model on a toy research benchmark. The benchmark should have: (1) questions that require multiple searches to answer (like which country did company X enter first?), (2) a ground truth answer that requires reading multiple web pages, and (3) a reward signal that grades each search (e.g., did it find a page that contains the answer?). Run the model with and without step-level rewards. The step-level version will use more targeted searches because each low-reward search immediately teaches the model this strategy does not work, while each high-reward search reinforces finding the right type of page. Since the model stops wasting searches on dead ends, it reaches the correct answer faster and more often.

accuracy_final = (correct_answers) / (total_questions); avg_searches_per_question = (total_searches) / (total_questions); redundancy_rate = (searches_with_no_new_info) / (total_searches)

The demo must show: a search with low utility (found no new facts) trains the model to avoid that search type next time, because the penalty hits immediately. This is what makes the long chains possible—the model gets feedback on each step, not just the end.
