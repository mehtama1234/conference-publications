Ophiuchus: Incentivizing Tool-augmented Think with Images

Ophiuchus trains a medical multimodal model to decide when to zoom into a region, where to inspect, and how to use that local evidence in diagnosis and segmentation.

Paper explainersAll themesMultimodal

A medical question often depends on a small part of an image: the edge of a lesion, the border between tissues, or a faint local pattern that changes the diagnosis. A medical multimodal model can produce long text, but text alone does not guarantee that it inspected the right pixels. Ophiuchus treats image inspection as an explicit action. The model learns to decide when the global view is not enough, call a tool to examine a chosen region, and then use that returned evidence in the next reasoning step.

Zero assumption version

Medical reasoning fails when the model never checks the exact region that matters

Medical image tasks combine at least three demands. The system must answer a clinical question, locate the visual evidence, and often mark the relevant region at pixel level. A model that only reads the full image once can miss the part that decides the answer, because many findings occupy a small area relative to the entire scan or slide.

Current medical multimodal models can write step-by-step text, but they often treat visual evidence as static input. They do not reliably decide when more local inspection is needed, they do not always choose the right place to inspect, and they do not consistently carry that local evidence back into the reasoning process. That gap matters because diagnosis and segmentation both depend on grounded evidence, not only fluent text.

The problem: If the model never performs targeted inspection, it can produce plausible reasoning while grounding the answer in the wrong part of the image.

The algorithm as a flow

What it actually does

Read the image and question

The model starts from the full medical image plus the clinical prompt.

Judge whether local evidence is needed

It predicts whether the current information is enough or whether a focused probe should be issued.

Choose a region and call a tool

If local inspection is needed, the model selects a region and requests a tool output tied to that location.

Insert the returned evidence into reasoning

The local patch or region-based output becomes part of the next multimodal reasoning step.

Produce diagnosis and segmentation

The model continues this loop until it can answer the question and, when required, draw the target mask.

What the paper changes

What the paper changes

The paper changes the role of tools. Instead of treating tool use as a separate helper after reasoning, Ophiuchus makes region selection and evidence insertion part of the reasoning loop itself. The model is trained not only to answer, but to decide when inspection is necessary and to revise its reasoning after seeing the result.

the object it moves  =  inspection decisions inside the reasoning loop
The hidden quantity

The hidden quantity: evidence sufficiency

measured quantity  =  evidence sufficiency

Evidence sufficiency is the model's internal judgment about whether the information it already has can support the next decision. If the current representation from the whole image does not isolate the finding clearly enough, sufficiency is low. If the important region is already resolved, sufficiency is high.

This quantity matters because the model should not probe blindly at every step. Probing too often wastes computation and can send the model into irrelevant regions. Probing too rarely leaves the answer under-grounded. Ophiuchus trains the model to connect this sufficiency judgment to two actions: continue reasoning from the current state, or request local evidence from a chosen image region.

Why it works

Why explicit inspection improves grounded medical reasoning

The mechanism has three linked parts. First, the model learns a basic tool vocabulary with supervised fine-tuning, which means training on examples that show when to call a tool and what type of output to expect. That stage gives the model a stable starting behavior instead of forcing reinforcement learning to discover tool use from scratch.

Second, self-reflection fine-tuning teaches revision. After an initial reasoning attempt, the model is exposed to cases where the first decision was incomplete or wrong, then trained to update the decision after seeing better local evidence. This matters because one-shot tool use is not enough; the system must learn that a probe can change the answer.

Third, agentic reinforcement learning sharpens the policy with reward on end tasks such as question answering, detection, and segmentation. A policy is the rule the model uses to choose its next action. Reward pushes the model toward action sequences that inspect the right region at the right time, because successful sequences receive more credit and unsuccessful ones receive less. The combined result is better grounding because the answer is tied to evidence gathered during reasoning instead of only to the first global pass.

The training objective in plain form

First in words:

The total score combines answer quality, region quality, and action quality over the whole reasoning trajectory.

Then the compact form:

total_score = answer_reward + region_reward + action_reward

Every symbol:

total_scorethe signal used to prefer one reasoning trajectory over another
answer_rewardcredit for producing the correct clinical answer or segmentation output
region_rewardcredit for probing image regions that actually support the answer
action_rewardcredit for choosing useful tool actions and avoiding unnecessary ones
A tiny worked example
Trajectory A answers correctly, probes the lesion boundary, and uses two tool calls that both matter.
Suppose answer_reward = 6, region_reward = 3, action_reward = 2, so total_score = 11.
Trajectory B gives the same final answer but probes irrelevant tissue first and wastes two extra calls.
Suppose answer_reward = 6, region_reward = 1, action_reward = -1, so total_score = 6.
Training prefers trajectory A because it not only reaches the right answer but reaches it through better grounded actions.

The objective matters because it rewards evidence gathering that supports the answer, not only the answer string by itself.

What can go wrong

What can go wrong

Bad region proposals. If the model probes the wrong place, the returned evidence can reinforce a wrong conclusion because the reasoning loop now treats irrelevant local detail as decisive.
Reward misses grounding errors. If training rewards only the final answer, the model can still learn unsupported tool habits because a lucky answer would receive credit without proving that the inspected region mattered.
Revision stage is weak. If self-reflection training does not teach the model to overturn an earlier claim, the tool call becomes decorative because new evidence arrives but the answer does not change.
Done right: The system learns a stable loop: global read, sufficiency check, targeted probe, evidence update, and only then commitment to diagnosis or mask.
What a runnable demo should prove

What a runnable demo should prove

Build a toy medical-image task with synthetic scans containing a small target region whose border decides both a yes-or-no diagnosis and a segmentation mask. Give the model a full image, a question, and a tool that can return a zoomed patch when the model selects coordinates. Compare three settings: no tool use, fixed tool use at every step, and learned tool use with sufficiency decisions. The demo should record whether the chosen region overlaps the true target, whether the final answer is correct, and whether the predicted mask aligns with the target border.

grounded_success = (correct_answer + correct_region + correct_mask) / 3

The point of the demo is to show that targeted inspection improves performance only when the model learns both when to inspect and how to revise the answer after the inspection result arrives, because a tool call only adds value if the returned local evidence can change the later decision.
