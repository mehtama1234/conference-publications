CoRA: Correlation-aware Adapter for Time Series Foundation Models

A lightweight adapter that teaches time series models to see how different data streams move together, not just predict each stream alone.

Paper explainersAll themesTime Series & Sequential

Existing time series models learn to predict each data stream independently, focusing only on how values change over time within each stream. But in real data — like temperature, humidity, and pressure in weather forecasting — the streams are entangled. The paper proposes CoRA, a small add-on piece that learns what the streams have in common: which ones move up and down together, which always stay apart, and how those relationships shift over time.

Zero assumption version

Why ignoring relationships between streams breaks forecasts

A time series is a sequence of measurements over time. A multivariate time series has many different measurements at each time step — for example, a weather station records temperature, humidity, wind speed, and pressure all at once. Each measurement forms one stream.

Current foundation models (big pre-trained models) treat each stream separately. They learn: given the temperature over the last 100 days, what will it be tomorrow? Given humidity over 100 days, what will it be tomorrow? They do this for each stream in isolation, never asking: does temperature predict humidity? If humidity jumps, does wind speed follow?

This breaks forecasts because real streams are correlated. When temperature rises, humidity often falls. When pressure drops, storms approach — wind picks up, temperature drops, rainfall increases. A model that ignores these links will miss the key signal that one stream's jump means another must follow.

In one sentence. CoRA is a lightweight add-on that teaches a model to capture how different data streams move together—which ones correlate, which push in opposite directions, and how those relationships change over time.

The algorithm as a flow

What it actually does

Split correlations in half

Break the correlation matrix (which numbers stay together) into stable patterns and ones that shift over time.

Learn time-varying links

Use learnable polynomial curves to capture how correlations change — summer is humid but unpredictable; winter is dry and stable.

Find positive and negative pairs

Identify streams that move together (positive correlation) and streams that move apart (negative correlation) using projection layers.

Train with contrastive learning

Push the model to recognize: this pair of streams are similar (alike correlations) vs. this pair are different (opposite correlations).

Plug into any foundation model

The adapter sits on top of an existing time series model. No retraining the base model; just fine-tune the correlation adapter.

What the paper changes

The one thing the paper changes

The paper changes how the model represents what each data stream depends on. Instead of each stream having its own prediction path, the model now learns a correlation matrix — a table showing which streams move together and which move apart. CoRA replaces a dense, expensive matrix with a decomposed, low-rank version: a stable baseline plus time-varying adjustments.

the object it moves  =  Correlation matrix representation
The hidden quantity

Correlation strength: which streams are linked and how

measured quantity  =  Correlation coefficient (positive, negative, or none)

A correlation is a number measuring how two streams move together. If one stream jumps up and the other always jumps up too, correlation is high and positive (they are linked). If one jumps up and the other drops, correlation is negative (they push apart). If they ignore each other, correlation is near zero.

CoRA estimates this by decomposing the full correlation matrix into two parts: time-invariant (stays the same year-round) and time-varying (shifts seasonally or over weeks). The model learns a polynomial curve to predict the time-varying part. During training, contrastive loss pushes the model to group positive-correlation pairs together in the learned representation and keep negative-correlation pairs far apart.

Why it works

Why learning correlations fixes forecast errors

The core insight: if the model knows how streams are linked, it can use one stream's value to correct its guess about another. Suppose the model predicts temperature will be 72°F tomorrow, but the correlation matrix says: whenever wind speed is high, temperature is usually 5°F cooler. If today's wind speed is high, the model adjusts: 72°F minus 5°F equals 67°F.

CoRA makes this work by splitting the problem. Time-invariant correlations (stable links) are baked into the adapter weights. Time-varying correlations (seasonal shifts) are captured by polynomial curves that the model learns to adjust at each time step. This keeps the number of learnable parameters low — so fine-tuning is fast and the adapter doesn't overfit.

The contrastive training step ensures the learned representations actually capture the distinction between positive and negative pairs. By pushing positively-correlated pairs together and negatively-correlated pairs apart in the representation space, the model builds an internal structure that makes predicting one stream from another natural and accurate.

Math after the picture

The correlation decomposition formula

First in words:

Correlation matrix equals stable baseline plus time-varying adjustments (from a polynomial), weighted by relative importance.

Then the compact form:

C(t) = C_stable + sum_{k=1}^{d} a_k * P_k(t)

Every symbol:

C(t)Correlation matrix at time t (shows which streams link)
C_stableFixed part (stays the same over the year)
a_kLearnable coefficient for polynomial k
P_k(t)Polynomial basis (e.g., sine/cosine curves for seasonality)
dDegree of the polynomial (how many terms to use)
A tiny worked example
Say C_stable = [[1.0, -0.3], [-0.3, 1.0]] (temperature and humidity: they negatively correlate).
At month 3 (spring), polynomial P_1(3) = 0.2 (a small seasonal tweak).
Coefficient a_1 = 0.1 (weak seasonal effect).
C(3) = [[1.0, -0.3], [-0.3, 1.0]] + 0.1 * 0.2 * adjustment_matrix = [[1.0, -0.28], [-0.28, 1.0]].
In spring, the negative link between temp and humidity weakens slightly (it was -0.3, now -0.28).
So forecast engine knows: spring correlations are different. Adjust predictions accordingly.

The polynomial curves capture seasonality; the contrastive loss during training ensures positive pairs are close and negative pairs are far in the learned representation.

What can go wrong

What can go wrong

Too many streams with weak signal. If most streams are independent noise, learning correlations wastes parameters and adds training time. CoRA's low-rank decomposition helps by using fewer numbers to represent the correlation matrix (stable baseline plus polynomial curves), so the adapter is smaller and trains faster than learning all correlations directly — but still costs more than ignoring correlations entirely.
Seasonality or correlations change abruptly. CoRA uses smooth polynomial curves to capture time-varying links. If a correlation flips suddenly (e.g., new equipment changes how sensors relate), the polynomial cannot track it instantly. Forecast error spikes around the change.
Insufficient training data for the adapter. Fine-tuning the contrastive loss requires enough examples of positive and negative stream pairs. If the dataset is tiny (weeks of data), the learned correlation estimates are noisy and forecasts get worse.
Done right. CoRA is lightweight (low-rank decomposition) and plugs onto any pre-trained time series foundation model. Fine-tuning time is minutes, not hours. When correlations are real and stable (weather, power grids, financial markets), CoRA cuts forecast error by 25-40%.
What a runnable demo should prove

What a runnable demo should prove

Build a tiny forecasting task with 3-5 synthetic streams where one stream's behavior is a lagged copy of another (they are correlated). Train a baseline model (channel-independent) and CoRA on 200 time steps. Forecast the next 50 steps. Measure mean absolute error (average difference between predicted and actual values) for each stream.

Error = average( absolute(forecast_value - actual_value) ) for all streams and time steps

CoRA's error should be 25-40% lower than baseline, because it learned the lag relationship. The baseline, ignoring the link, guesses each stream independently and gets surprised when they move together.
