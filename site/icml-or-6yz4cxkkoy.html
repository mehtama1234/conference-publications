Fix the Mind, Not the Move: Interpretable AI Assistance via Knowledge-Gap Localization

Infer which idea a user misunderstands, then give the smallest correction that removes that misunderstanding instead of only correcting the visible action.

Paper explainersAll themesAgents & Tool Use

This paper argues that helpful assistance should target the cause of repeated mistakes, not only the latest bad move. SENSEI watches a user's actions, infers which part of the user's internal task knowledge is wrong or missing, and then gives a focused suggestion that repairs that knowledge gap because fixing the source should improve many later decisions, not just one step.

Zero assumption version

Why action-only help is shallow

Many assistants react to the latest mistake by telling the user what action to take next. That can prevent immediate failure, but it often does not improve the user's next attempt because the underlying belief that caused the mistake is still wrong. The user may repeat the same pattern in a slightly different form.

The paper treats human errors as evidence about hidden knowledge gaps. If the assistant can locate the mistaken concept, it can offer a smaller and more useful correction because the advice addresses the reason the mistake happened.

The paper's move in one sentence. Map observed behavior back to a structured task-knowledge graph, locate the missing or wrong concept, and intervene at that concept.

The algorithm as a flow

What it actually does

Represent the task as structured knowledge

Store the concepts, dependencies, and rules that a user needs in order to act correctly.

Observe user behavior

Collect the sequence of decisions and outcomes so that behavior can be matched to possible misconceptions.

Infer the most likely gap

Find which wrong or missing concept best explains the pattern of mistakes.

Generate a minimal correction

Offer the smallest explanation that repairs the gap because targeted advice is easier to absorb and reuse.

Check later behavior

Measure whether later task choices improve so that the system can tell whether the intervention worked.

The hidden quantity

The hidden quantity

measured quantity  =  Knowledge gap location

The key hidden quantity is which concept in the user's task knowledge is wrong, missing, or improperly linked. You cannot observe that gap directly. You only see actions, delays, or repeated failures.

SENSEI treats those visible behaviors as clues. It looks for the smallest concept-level explanation that accounts for the pattern because that produces a correction that is specific enough to help without overwhelming the user.

Why it works

Why this works: correct the cause, not only the symptom

A repeated behavioral pattern usually comes from a repeated internal mistake. If the assistant only patches the last action, the user may still generate the same error later because the decision rule that produced it has not changed. A concept-level intervention has longer reach because many later actions depend on the same underlying concept.

The paper also stresses minimality. A small correction helps because it reduces the chance that the assistant distracts the user with extra information. When the system identifies the narrowest gap that explains the failure, it can supply just enough guidance to repair the user's decision process.

Math after the picture

Score each possible misconception

First in words:

A simple view is to choose the misconception that best explains the observed mistakes while keeping the correction small. The system prefers a gap if that gap predicts the user's behavior well and requires little extra explanation.

Then the compact form:

score(gap) = explains_behavior(gap) - advice_cost(gap)

Every symbol:

score(gap)overall value of treating a given concept gap as the cause
explains_behavior(gap)how well that gap accounts for the observed user actions
advice_cost(gap)how much extra instruction is needed to repair that gap
A tiny worked example
Suppose the user repeatedly performs step C before step B.
Gap 1: missing ordering rule. Explanation score 9, advice cost 2, total 7.
Gap 2: wrong goal concept. Explanation score 6, advice cost 4, total 2.
Gap 3: tool misuse. Explanation score 5, advice cost 3, total 2.
The system picks the ordering rule because it explains the pattern best and needs the least extra instruction.

The paper uses structured reasoning over knowledge components rather than this exact formula, but the formula captures the tradeoff between explanatory power and intervention size.

What can go wrong

What can go wrong

The knowledge structure may be incomplete. If the task representation misses an important concept, the system can only guess among the concepts it knows, so localization may be wrong because the true cause is absent.
Different gaps can look similar. Two misconceptions may produce the same visible behavior, which makes correct localization hard unless the system has enough context to separate them.
Minimal advice can be too small. A very short correction may fail if the user needs an example, a prerequisite reminder, or a more direct explanation before the new concept can be applied.
Done right. The paper is useful because it treats user support as diagnosis plus intervention, not only error prevention at the last step.
What a runnable demo should prove

What a runnable demo should prove

Build a structured task with ten concepts and explicit dependency links. Create users with planted misconceptions, including cases with two overlapping gaps. Let the users act in a long task so that behavior traces are recorded. Compare two helpers: one that only tells the next correct action, and one that localizes the concept gap and gives a focused explanation.

The demo should show higher later-task success for the localization system because repairing the concept should improve more than one step. Log both the predicted gap and the final advice so that a human can inspect whether the diagnosis made sense.

gain = later_success_localized - later_success_action_only

The demo must prove that concept-level help improves long-run behavior because it fixes the source of repeated mistakes.
