PromptHub: Locality-Aware Multi-Prompt Fusion for Visual In-Context Learning

To teach a vision model new tasks from examples, fuse multiple demonstration prompts by weighting them based on spatial nearness, so the model borrows the most relevant parts of each.

Paper explainersAll themesComputer Vision

Visual in-context learning means showing a model example image-label pairs and asking it to solve a new task on a query image. When you have multiple examples to choose from, combining their strengths should work better than picking just one. This paper introduces PromptHub, which fuses multiple prompts by using spatial locality—each pixel looks for nearby pixels in the examples, weighted by distance, so distant, irrelevant details do not drown out close, useful ones.

Zero assumption version

Fusing examples without losing spatial clues

Visual in-context learning works by example: you show a model a labeled picture (for instance, a dog with the label "dog") and then ask it to label a new picture (is this a dog?). When you have many examples, the naive approach is to pick the single most similar one. But that wastes information—if two examples are equally good matches for different parts of the query image, picking just one throws away useful evidence.

Recent work tried fusion: combine features from all the top examples into a single fused prompt. The problem is that naive fusion treats all pixels the same way. When you merge feature maps from three different images, a detail that is nowhere near the query pixel still influences what the model predicts about that pixel. It is like asking ten eyewitnesses about a car crash and averaging their answers without noticing that only three were standing close enough to see clearly.

In one sentence. Weight each pixel in each example prompt by how close it is to the pixel you are trying to classify. Nearby pixels help more because they show the same scene context, while distant pixels are background noise.

The algorithm as a flow

What it actually does

Embed images and labels

Convert each prompt image and the query to patches and lists of numbers (features).

Compute locality-aware scoring

For each query pixel, score similarity to all pixels in all example prompts, then down-weight based on spatial distance.

Fuse prompt features

Combine image and label features from all prompts using the locality-weighted scores.

Train with three linked losses

Prediction loss trains the fusion to predict the label, concentration loss focuses on important regions, alignment loss ensures consistency.

Retrieve and augment

At test time, retrieve the most similar prompts; during training, swap in random examples to prevent overfitting to a narrow set.

What the paper changes

What the paper changes

PromptHub modifies the fusion module—the part that combines features from multiple example prompts. Instead of treating all pixels equally, it adds spatial locality priors: a weighting scheme that favors nearby pixels and penalizes distant ones.

The hidden quantity

The hidden quantity: locality decay

measured quantity  =  Spatial locality weight per position pair

The paper measures a hidden quantity: how much each pixel in each example prompt should influence the prediction at each pixel in the query. This is encoded as Psi, a decay function that radiates from the query pixel outward. Nearby pixels get high weights; pixels far away get low weights. Think of it as drawing concentric circles around each query pixel—the inner ring (close examples) is trusted, the outer ring (distant examples) is ignored.

The paper estimates this locality weight implicitly by computing similarity scores in the feature space (how similar each example pixel is in raw numbers), then multiplying by the spatial decay function. The result is a matrix of weights: one row for each example prompt, one column for each pixel in that prompt, and the entry tells you how much that example pixel influences the current query pixel.

Plain reading. Locality decay is the intuition that pixels close in space should matter more than distant ones when fusing evidence from multiple examples. It is why a doctor trusts a test result from a patient's recent scan more than a scan from years ago—closeness in time and space is a signal of relevance.
Paper reading. Locality decay Psi is a function of distance that adjusts the similarity scores in Equation 3. It ensures that the fused feature at each query position is built primarily from corresponding nearby positions in the example prompts, not from averaging the entire set equally.
Why it works

Why it works: proximity is signal

The core insight is that pixels close in space carry more relevant signal than distant ones. When you have multiple image examples and you want to label a single query pixel, the example pixels near that query pixel's position are more likely to show the same object or scene context. Distant pixels show unrelated background or parts of the image far from the region you are trying to classify, so they just add noise.

PromptHub encodes this by adding a spatial decay factor Psi to the similarity scoring. During fusion, when combining features from all example prompts, the model computes how similar each example pixel is to the query pixel (how closely their feature values match), then multiplies by how close that example pixel is in space (locality decay). Close and similar pixels get strong weights; close but dissimilar pixels, or distant pixels, get low weights. This two-stage filtering—similarity first, then proximity—means the fused feature captures only the most relevant parts of each example.

Three training objectives reinforce this: the prediction loss ensures the fused prompt actually predicts the query label correctly; the concentration loss forces the model to focus on small, informative regions instead of spreading weight everywhere; the alignment loss ensures that the image and label features stay in sync. Together, they steer the fusion module to exploit spatial structure and ignore noise.

Math after the picture

The locality-weighted attention equation

First in words:

Attention scores weighted by spatial locality decay: for each query position, compute similarity to all example positions, then scale by a decay factor that favors closeness.

Then the compact form:

A[h,w] = softmax( (F_q[h,w] * W_Q) * (F_ex * W_K)^T / sqrt(D) * Psi[h,w] )

Every symbol:

A[h,w]attention weight at query row h, column w (ranges from 0 to 1)
F_q[h,w]query image feature at position h,w
F_exexample image features from all prompts stacked
W_Q, W_Klearnable projection matrices that transform query and key features
Dfeature dimension (number of values per pixel)
Psi[h,w]locality decay: high near position h,w, low far away
softmaxconverts raw scores to fractions that sum to 1, spreading the weight across all examples
A tiny worked example
Query pixel at row 5, column 8. Example 1 has a similar feature at row 4, column 8 (distance 1). Example 2 has an identical feature at row 15, column 8 (distance 10).
Similarity scores (before locality): Example 1 gets score 0.8, Example 2 also gets 0.8 (they are equally similar in feature space).
Locality decay Psi: Example 1 at distance 1 gets weight 0.9, Example 2 at distance 10 gets weight 0.1 (spatial closeness is built in).
Scaled scores: Example 1: 0.8 * 0.9 = 0.72, Example 2: 0.8 * 0.1 = 0.08. After softmax: Example 1 gets 0.90, Example 2 gets 0.10.
Result: even though both examples had equal feature similarity, the nearby example dominates because it is spatially close. The fused feature is 0.90 * example1 + 0.10 * example2, anchored to locality.

The locality decay Psi modulates the attention so that close, relevant examples are trusted more than distant ones, transforming a global average into a locally grounded prediction.

What can go wrong

What can go wrong

Locality radius set wrong If the spatial decay function Psi decays too fast, even moderately close pixels are discarded and the model has too little information. If it decays too slowly, distant irrelevant pixels still add noise. The paper uses a learned decay radius, but it can overfit to the training domain.
Prompt database mismatch If the example prompts come from a different distribution than the query image (e.g., examples are sketches but query is a photo), spatial locality alone cannot fix poor feature similarity. The method assumes the retrieved examples are already relevant; it just sharpens the fusion.
High computational cost at test time Computing attention weights between a query pixel and all pixels in all example prompts is expensive. The method is most practical when the number of prompts and image resolution are moderate.
Done right PromptHub works best when the prompt retriever has already selected examples that overlap spatially with the query image, and when the spatial decay is tuned to the image patch size and dataset domain.
What a runnable demo should prove

What a runnable demo should prove

Build a simple visual in-context learning task: pick a query image (e.g., a dog), retrieve two example prompts (e.g., a cat and another dog), and fuse them. Run the model twice, once with uniform weighting (all pixels equal) and once with locality-aware weighting. Show the predicted label and the attention map for each. The locality-aware version should produce a sharper, more focused attention map that lights up near the corresponding pixels in the examples, while uniform weighting should scatter attention diffusely.

Accuracy gain = (locality-aware accuracy) - (uniform fusion accuracy); attention sharpness = (proportion of attention weight in the top-K percent of pixels); locality alignment = (average distance between query and example pixels with high attention weight).

The demo should show that proximity matters: by constraining fusion to nearby pixels, the model avoids false matches where distant, unrelated pixels accidentally influence the prediction, making clearer, more accurate labels.
