C-Evolve: Consensus-based Evolution for Prompt Groups

Search for groups of prompts, not single prompts, and score each prompt by how much it helps the group vote reach the right answer.

Paper explainersAll themesOther

A single prompt can do well on one question and fail on the next. This paper asks a different question: instead of searching for one best prompt, can we search for a set of prompts whose vote is better because different prompts make different mistakes?

Zero assumption version

Why single-prompt search stalls

Prompt search usually treats one prompt as one candidate and keeps the candidates that score highest on a task. That setup misses a useful fact: two prompts can have the same solo score while helping a group in very different ways, because one may solve cases that the other misses.

If you only keep prompts that look best alone, you can throw away prompts that matter in a vote. That hurts final accuracy because the group loses the diversity that lets one prompt cover another prompt's blind spots.

In one sentence. Evolve prompts by group vote score, not by solo score, so the search keeps prompts that raise the group's final answer quality because they add useful disagreement.

The algorithm as a flow

What it actually does

Start with many prompts

Create a population of candidate prompts.

Split them into islands

Maintain separate sub-populations so that search does not collapse to one style too early.

Assemble voting groups

Pick prompts from different islands and let them answer the same task.

Score each prompt by contribution

Give a prompt credit when the groups containing it vote correctly, because that credit reflects group usefulness rather than solo usefulness.

Mutate and keep the best

Create new prompts from strong prompts and remove weak ones so the population shifts toward groups that vote well.

What the paper changes

What the paper changes

The paper changes the fitness score. Older prompt evolution methods reward a prompt for its own answer quality. C-Evolve rewards a prompt for how much it helps a voting group, because the end product is the group rather than a lone prompt.

the object it moves  =  fitness score for prompt evolution
The hidden quantity

The hidden quantity

measured quantity  =  group contribution score

The hidden quantity is each prompt's contribution to group success. A prompt with a modest solo score can still matter if it is right on cases where other prompts are wrong, because that can flip the vote from wrong to right.

C-Evolve estimates this quantity by repeatedly placing prompts into mixed groups and measuring which groups answer correctly. Over time, prompts that help many strong groups survive because repeated group tests show they raise vote accuracy, while prompts that add little group value disappear.

Why it works

Why the method works

A voting system is only as strong as the variety inside it. If every prompt fails on the same questions, voting adds little because the same wrong answer wins again and again. C-Evolve pushes the search toward complementary prompts because the score comes from group outcome, not solo outcome.

The island design matters because it keeps several prompt lineages alive at once. That reduces collapse to one narrow style, so later groups can mix prompts with genuinely different behavior.

Once the score matches the real goal, the search improves the right thing. Group accuracy rises because selection keeps prompts that make the full vote better, and mutation keeps exploring new ways to cover cases that current prompts miss.

Math after the picture

The core equation

First in words:

A prompt's score is the average vote accuracy of the groups that include that prompt.

Then the compact form:

score(prompt_i) = average over groups g that contain prompt_i of vote_correct(g)

Every symbol:

prompt_ione candidate prompt in the population
ga group of prompts chosen to answer together
vote_correct(g)1 when the group's majority vote is right, else 0
score(prompt_i)the fitness value used during evolution
A tiny worked example
Prompt A appears in three groups.
Those groups score 1, 0, and 1 after majority vote.
Prompt A gets score (1 + 0 + 1) / 3 = 0.67.
Prompt B appears in three groups that score 0, 0, and 1.
Prompt B gets score 0.33, so Prompt A is more likely to survive.
This favors prompts that help the full group answer correctly.

The score ignores solo status and tracks the quantity the paper actually wants to optimize: final vote accuracy.

What can go wrong

What can go wrong

Groups may be too similar. If prompts are minor rewrites of each other, the vote adds little because the same failure pattern appears in every answer.
Contribution estimates may be noisy. A prompt can look useful by luck when it is tested in too few groups, so the search needs repeated grouping because repeated evidence smooths out random wins.
Voting can hide rare expert prompts. A prompt that solves a narrow but important slice may lose credit if group formation rarely visits that slice, so task coverage matters during evaluation.
Done right. The method works best when group testing covers many task types because broad testing reveals which prompts truly raise consensus quality.
