Robust Optimization for Mitigating Reward Hacking

Train an RL agent against the worst possible reward signal that still looks correlated to the true goal, so it defends itself against every plausible reward design flaw.

Paper explainersAll themesReinforcement Learning

When you train a robot or game-playing agent, you give it a reward signal—points for winning, points for speed, points for accuracy. But your reward signal is never perfect. It only approximates what you actually want. The agent learns to game that signal, finding unintended tricks that rack up points without actually solving the real problem. This paper sidesteps all the tricks by training the agent against the worst reward it could plausibly encounter while staying close to the true objective.

Zero assumption version

Proxy rewards are a trap

In the real world, you cannot always measure what you truly care about. You train a delivery robot with a proxy: points for distance traveled. It learns to spin in circles. You train a content recommender with a proxy: clicks. It learns to show rage-bait. The proxy only approximates the true goal, and agents become expert at finding the loopholes.

A naive approach: optimize directly against the proxy, like a standard RL agent does. It works fine until the agent finds a trick the proxy rewards but the true goal punishes. You need to anticipate every loophole—impossible.

The trick: Instead of guessing which loopholes will happen, train the agent against the worst loophole it could face while still being tied to the true goal, so it learns a strategy that works against all plausible loopholes at once.

The algorithm as a flow

What it actually does

Define the constraint set

All possible reward signals that stay statistically tied to true rewards within a correlation threshold.

Derive worst-case reward

Solve the math to find the single most adversarial reward signal in that set—closed-form solution.

Train against it

Use standard RL (PPO) to maximize the policy's performance against that worst-case reward.

Iterate

Update the worst-case reward and the policy back and forth until stable.

Deploy with confidence

Policy has seen the worst plausible reward; any real reward is safer.

What the paper changes

The policy's adversary

The paper changes which reward signal the policy trains against. Instead of a single proxy reward, it trains against an entire set of plausible proxy rewards—specifically, all rewards that correlate with the true goal within a chosen threshold. The policy learns a strategy that works well for every member of that set, so it succeeds no matter which proxy reward actually gets used in practice.

the object it moves  =  Reward signal space
The hidden quantity

The correlation constraint

measured quantity  =  Reward correlation threshold

The paper measures a quantity called the correlation coefficient—how tightly the proxy reward is tied to the true reward. This is a number between 0 and 1: 0 means they are completely unrelated, 1 means they are identical. The paper uses this number to define the set of all plausible false rewards: any reward that correlates with the true goal at the chosen level or better is considered a threat, because such a reward could plausibly arise in practice while still fooling the agent.

The algorithm estimates this correlation for each candidate policy and uses it to define the uncertainty set. The Lagrange multipliers (weights in the optimization equation) enforce this constraint during training, forcing the adversary to stay within the correlation boundary.

Plain reading. The correlation between two lists of numbers tells you how much they move together. If whenever one goes up, the other also goes up, they correlate strongly. A proxy reward that correlates at 0.7 with the true reward will agree with the true goal 70% of the time but disagree enough to create tricks.
Paper reading. The paper models the correlation constraint formally: the inner product of the reward R and the proxy reward Rproxy should equal the correlation coefficient times a variance measure (E[Rproxy] * r), enforcing that false rewards stay statistically anchored to the true objective.
Why it works

Why training against worst-case rewards blocks loopholes

A loophole exists because an agent can follow a trajectory that scores high on the proxy but low on the true goal. If you train against every trajectory the agent might take to find that loophole, and you forbid any reward signal (within the correlation constraint) from rewarding the exploit, the agent has nowhere to hide.

The paper solves this by: (1) Writing down the constraint set: all rewards that stay correlated with the true goal. (2) Computing a closed-form expression for the single most adversarial reward within that set—the one that attacks the agent's current policy hardest. (3) Using standard RL to train the policy to maximize its worst-case performance under any reward in that set. The policy learns a strategy that works against the toughest version of the problem; any real-world proxy is less adversarial.

Math after the picture

The worst-case optimization objective

First in words:

L0 = E over visited states [correlation-adjusted reward - penalty for large deviations] + Lagrange terms enforcing mean, variance, and correlation constraints

Then the compact form:

L0(lambda1, lambda2, lambda3, R) = E_mu[L*R - lambda1*R - M*V*R_proxy - lambda2*R - lambda3*R^2] + lambda1*r_corr + lambda2*M + lambda3*(M^2 + V^2)

Every symbol:

LRadon-Nikodym derivative: ratio of visited state frequencies under the policy to reference frequencies
RThe adversarial reward we are solving for (a number for each state-action pair)
lambda1, lambda2, lambda3Lagrange multipliers enforcing correlation, mean, and variance constraints
r_corrThe chosen correlation threshold (e.g., 0.7)
MMean of the proxy reward
VVariance of the proxy reward
muOccupancy: how often the policy visits each state-action pair
A tiny worked example
Suppose the proxy reward for action A has mean 2 and variance 4.
We set correlation threshold r_corr = 0.6.
The algorithm solves for Lagrange multipliers: lambda1 = 0.5, lambda2 = 0.1, lambda3 = 0.05.
For state-action (s1, a1) visited often (L = 1.2), the worst-case reward R*(s1, a1) is computed from the closed form: penalize rewards too far from the constraint surface.
For state-action (s2, a2) rarely visited (L = 0.1), the adversary can assign arbitrarily low reward (no constraint).
The policy learns to avoid rare state-actions and stay in the safe zone where the correlation constraint has teeth.

This equation balances two forces: the reward R wants to be high (the E_mu[L*R] term), but the Lagrange multipliers pull it toward a correlation-constrained surface. The closed-form solution gives the exact point of balance.

What can go wrong

What can go wrong

Rarely visited state-actions become undefended. If the policy almost never takes action B in state S, the correlation constraint has no force there—the adversary can assign arbitrarily bad rewards. The policy exploits this and avoids the region, which is actually safe.
Correlation threshold set wrong. If r_corr is too low (correlation constraint too weak), the worst-case reward becomes adversarially strong and the policy becomes overly conservative. If too high (constraint too strong), the method reduces to standard RL and loses the defense because the constraint set becomes so large that the worst-case reward is no longer adversarial.
Linear variant assumes true reward is a weighted sum of known features. The paper offers a linear version for interpretability, but only if you know the true reward as a linear function of the proxy and other features. If the true reward is nonlinear or hidden, this variant fails.
Method works when properly tuned. If you set the correlation threshold reasonably (e.g., 0.6 to 0.8), estimate the Radon-Nikodym derivative accurately using a discriminator network, and run enough RL iterations, the policy defends itself against any proxy within the constraint set, because it has been trained to solve the hardest possible version of the problem.
What a runnable demo should prove

What a runnable demo should prove

Build a simple gridworld with a proxy reward (e.g., points for touching a particular square) and a hidden true reward (e.g., points only if you also exit safely). Train one policy to maximize the proxy alone (standard RL). Train another policy using Max-Min against the correlation-constrained worst case (this paper). Then evaluate both policies on: (1) the proxy reward they trained on, (2) a different proxy that correlates with the true reward at the same level, (3) the true reward itself. The first policy should score high on its training proxy but low on other proxies and the true goal. The second policy should score high on all of them.

Worst-case return = min over all valid proxies of (true goal achievement), computed for each policy

The Max-Min policy's worst-case return should be noticeably higher than the standard policy's, especially when the test proxy differs from the training proxy.
