ICYM2I: The illusion of multimodal informativeness under missingness

Estimate the value of an extra modality only after correcting for which examples are missing that modality, because missingness can bias the apparent gain.

Paper explainersAll themesOther

Adding another modality can look useful in training data and disappoint in deployment. The reason is simple: the cases where a modality is present are often not a random slice of the world. This paper shows that you can overestimate the value of a modality unless you correct for who is missing it and why.

Zero assumption version

Why extra modalities can look better than they are

Suppose a system can use text alone or text plus another modality. If the added modality is usually present on easier or more carefully collected cases, then a model that uses it may appear stronger for the wrong reason, because the evaluation set is tilted toward cases where that modality was available.

This matters when the source setting and the target setting lose modalities in different ways. A model may seem to gain a lot from the added modality during development and gain much less after deployment because the missingness pattern changed.

In one sentence. Correct the evaluation by reweighting examples according to how likely their modality pattern is, so the estimated value of an extra modality reflects the target setting rather than a biased observed slice.

What the paper changes

What the paper changes

The paper changes the evaluation rule. Instead of comparing multimodal and single-modality models on the raw observed sample, it compares them on a reweighted sample that accounts for missingness because raw observation can favor the cases where a modality happened to be present.

The hidden quantity

The hidden quantity

measured quantity  =  missingness bias

The hidden quantity is the gap between the apparent value of an extra modality in observed data and its true value in the target setting. This gap appears when modality presence is linked to case difficulty, collection practice, or device availability, because then the observed complete cases no longer represent the target population fairly.

ICYM2I estimates and corrects this gap with inverse-probability weights. Rare or undersampled missingness patterns receive more weight so the final estimate reflects the setting you care about.

Why it works

Why the method works

Bias enters when complete cases are easier, cleaner, or otherwise different from incomplete cases. A raw average then gives too much influence to those complete cases, so the measured value of the added modality can be inflated.

Reweighting fixes that by undoing the sampling tilt. An example that rarely appears with its observed modality pattern gets more weight because one such example stands in for many similar target cases that were not fully observed.

After reweighting, a model only looks better if it truly helps across the corrected target population. That makes the reported information gain more trustworthy because the estimate is tied to the deployment missingness pattern rather than to the convenience sample seen during collection.

Math after the picture

The core equation

First in words:

Each example gets weight one over the chance of its observed missingness pattern, so rare observed patterns count more in the final average.

Then the compact form:

weight(example_i) = 1 / probability(observed_pattern_i)

Every symbol:

example_ione evaluation example
observed_pattern_iwhich modalities are present for that example
probability(observed_pattern_i)how often that pattern appears under the missingness process
weight(example_i)the correction weight used in evaluation
A tiny worked example
Suppose complete cases appear only 20 percent of the time in the target setting.
A complete case then gets weight 1 / 0.20 = 5.
A common text-only case that appears 50 percent of the time gets weight 1 / 0.50 = 2.
The complete case counts more because it stands in for more target cases than the raw sample suggests.

The exact missingness model can vary, but the correction idea stays the same: downweight overrepresented patterns and upweight underrepresented ones.

What can go wrong

What can go wrong

Missingness probabilities may be estimated poorly. If the missingness model is wrong, the weights can be wrong too, so the correction may still be biased.
Very rare patterns can create unstable weights. When one pattern is extremely rare, its weight can become very large, which increases variance because a few examples carry too much influence.
Unrecorded causes of missingness may remain. If important drivers of missingness are absent from the data, correction can only go so far because the model cannot adjust for causes it never sees.
Done right. The method is most useful when you can model missingness well because then the corrected estimate separates true modality value from collection bias.
What a runnable demo should prove

What a runnable demo should prove

Create a dataset where an extra modality is more likely to be present on easier examples. Compare the raw measured gain from adding that modality against the corrected gain from ICYM2I.

Then change the target missingness pattern and repeat the comparison. The corrected estimate should track the new target setting more closely because it accounts for how modality availability changes across environments.
