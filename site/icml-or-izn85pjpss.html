Hit Discovery in Gene Perturbation via Threshold-Aware Search

Instead of hunting for one best outcome, aim a search strategy directly at all outcomes above a chosen threshold.

Paper explainersAll themesOptimization

When scientists run experiments to find which genetic changes have strong effects, they face a budget: they can only try so many interventions. The naive approach is to explore everywhere equally or to chase the single strongest effect. This paper says: stop and ask what you actually want—most of the time you just want to find all the good outcomes, not one perfect one. It proposes a method that points the search directly at the threshold you care about.

Zero assumption version

Finding multiple good outcomes when experiments are scarce

High-throughput gene perturbation experiments let scientists test many genetic interventions at once. But each experiment is expensive and time is limited. The question is: which genetic changes produce a strong enough effect on the organism's behavior to matter? The scientist sets a threshold—e.g., 'a change in immune response above 30% counts as a hit'—and wants to find as many hits as possible before the budget runs out.

A beginner might try pure exploration: test interventions scattered uniformly across the space of all possibilities. This wastes budget on regions that will never cross the threshold. Or they might use Bayesian optimization, a model-based method that learns from each experiment and uses that knowledge to point toward better regions—because each new test teaches the model something, the model's guidance improves over time. But standard Bayesian optimization hunts for a single maximum—the very best outcome. It over-explores the peak regions where the biggest effect already lives, and ignores neighboring areas that might also cross the threshold, because its goal is to find the global top, not all good places. Both strategies leak budget.

In one sentence. The paper targets the real goal: find multiple outcomes that exceed a threshold, not one perfect optimum.

What the paper changes

What changes: the selection rule

Ordinary Bayesian optimization picks the next experiment based on the estimated highest value. This paper replaces that rule. Instead of ranking candidates by their predicted maximum, it ranks them by the probability they will exceed the threshold. A candidate wins not because it looks tallest, but because it is most likely to clear the bar you set.

The hidden quantity

The probability of exceeding the threshold

measured quantity  =  Threshold-exceedance probability

The paper calls it Probability-of-Hit. It is not a mysterious hidden property—it is a straightforward probability: given what the model has learned so far, what is the chance that this intervention produces an effect above the threshold? Low-effect regions have a low probability; high-effect regions have a high probability; regions near the threshold have medium probability. The paper computes this by using the model's uncertainty: interventions where the model is confident but pessimistic have low hit probability; interventions where the model is optimistic get high hit probability.

Mathematically, the paper estimates this as the probability that the predicted effect plus the model's confidence range sits above the threshold. Where the model is uncertain, even a mediocre prediction might have a large chance of clearing the bar. Where the model is certain, only high predictions count.

Why it works

Why targeting the threshold works

Standard Bayesian optimization assumes you want the single highest peak. Its acquisition function says: test the intervention that could give the highest value. This is optimal if you want one perfect answer. But in hit discovery, many good answers exist—you just need them to cross a line.

The paper's insight: if you instead ask 'which intervention has the highest chance of being above the threshold,' you re-align the search strategy with the real goal. An intervention that sits clearly above the threshold is useful—testing it is useful because you will find a hit, and finding a hit you already knew about was always wasted budget. An intervention near the threshold is risky but high-reward—the model is unsure, so it might exceed the threshold despite mediocre predictions, making it worth testing. An intervention far below the threshold is not worth the risk. Probability-of-Hit balances this: it ranks candidates by their expected value for hit discovery, not global optimization.

The paper proves this strategy is asymptotically optimal—meaning that with infinite budget, the method would find all true hits and no false ones, because the hit-probability ranking eventually concentrates all tests where hits truly live. No other method using the same information could do better, because any ranking that ignores actual hit probability wastes tests somewhere. In finite experiments, you spend budget on high-probability candidates, so you find more hits per test than wasteful baselines, because every test targets a likely success.

Math after the picture

The formula

First in words:

Hit probability = chance that (predicted effect plus model uncertainty) exceeds the threshold

Then the compact form:

P(Hit | c) = P(mu(c) + Z * sigma(c) >= T)

Every symbol:

mu(c)The model's predicted effect for intervention c
sigma(c)The model's confidence range for intervention c
ZA scaling factor (roughly 1 to 2) accounting for model uncertainty
TThe threshold you chose
P(...)Probability that the bracketed condition holds
A tiny worked example
Say the threshold is T = 50 (you want effects above 50).
Intervention A: model predicts 60 with confidence range ±10, so it spans 50–70. Chance it is above 50: very high (roughly 80%).
Intervention B: model predicts 40 with confidence range ±20, so it spans 20–60. Chance it is above 50: medium (roughly 40%).
Intervention C: model predicts 30 with confidence range ±5, so it spans 25–35. Chance it is above 50: nearly zero (roughly 1%).
The method ranks them: A first (80% hit probability), B second (40%), C last (1%). A and B both look like good bets; C is a waste of budget. The method avoids C.

The formula says: rank interventions by how likely their true effect is to exceed the threshold, accounting for both the model's best guess and its uncertainty.

What can go wrong

What can go wrong

Misspecified threshold. If you set the threshold wrong—too high, so no interventions cross it, or too low, so everything crosses—the method still ranks by hit probability, but you get no hits or no useful ranking.
Poor initial model. If the first few experiments give a bad picture of the effect surface, the model learns a distorted map. Early predictions are unreliable, so hit probabilities are unreliable. A few unlucky first experiments can send the search down a bad path.
Regions of true ties near the threshold. If many interventions have effects clustered just barely above the threshold, and the model is uncertain, all of them look like equivalent bets. The method ranks them as equally probable hits, so it may waste time on redundant tests in a narrow region instead of spreading out.
Done right. A well-chosen threshold, a model that learns fast, and a diverse starting set of experiments all help Probability-of-Hit converge to finding most true hits with budget to spare, because the method relies on accurate probability estimates, which come from an accurate model, which comes from good early data and a model that improves quickly.
What a runnable demo should prove

What a runnable demo should prove

Build a synthetic 2D surface where the true effect smoothly depends on two genetic settings (call them x and y). Draw a horizontal line at your chosen threshold. Initialize a model with three random experiments. Then repeatedly: (1) compute the hit probability for each unmeasured point in a grid, (2) pick the highest-probability point, (3) test it (get the true value from the surface), (4) update the model, (5) plot the model's current predictions as a color map, mark the tested points, shade the region above the threshold. Run for 30 iterations and count how many points the method found above the threshold versus a random baseline.

Hits found = count of tested interventions with true effect > threshold

The demo must make visible that the method's path (the sequence of tested points) clusters in the high-value regions around and above the threshold, never lingering in the deep valley regions below it.
