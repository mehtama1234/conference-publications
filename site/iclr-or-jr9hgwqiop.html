ARMOR: Self-Refining Vision Language Model for Robotic Failure Detection

A robot learns to spot failures by training on two kinds of data at once and refining its own predictions, round by round, until it is confident.

Paper explainersAll themesRobotics & Control

Robots fail in subtle, unexpected ways that are hard to predict. Getting a robot to both detect a failure AND explain why it happened requires two kinds of training data: lots of quick yes/no labels for detection, and fewer but detailed written explanations for reasoning. ARMOR solves this by training a single vision-language model on both data sources at once, using a multi-round self-refinement loop (where the finished model reads its own predictions and refines them) to improve predictions.

Zero assumption version

Two kinds of data, two kinds of training headaches

Building a reliable robot means knowing when something went wrong. But failures are subtle: a gripper moved a millimeter too far; a rotation aligned a bit off. You cannot list every way a robot can fail.

Older approaches train a model on one thing at a time. Either you collect thousands of yes/no labels for detection (but these tell you nothing about why), or you pay annotators to write detailed explanations (expensive, so you only get hundreds). You need both signals, but mixing them in a single model was messy: binary detection got tangled with language prediction, and training objectives fought each other. The naive approach is to attach two separate heads (one for classification, one for language) and optimize both, but the model never learns to let the detection inform the reasoning.

The move. Treat detection and reasoning as a single iterative process: the model predicts both at once, then conditions its next round of predictions on what it just said.

The algorithm as a flow

What it actually does

Step 1: Train on two data streams

Use sparse labels to teach detection via one loss, dense annotations to teach reasoning via another loss.

Step 2: Make them aware of each other

Design the model so reasoning conditioning sees the detection signal; at each training round, mask out only one task at a time to avoid cheating.

Step 3: Roll out multiple refinement paths

When answering a new question, run the model for several rounds; each time it sees its own earlier predictions and refines.

Step 4: Measure confidence honestly

Use entropy (a measure of how uncertain the model is) to pick which refinement path to trust.

Step 5: Output both detection and reasoning

Return the most confident detection decision and its corresponding reasoning explanation.

What the paper changes

What changes: the training loop

The paper changes how the model trains on mixed data. Instead of one static forward pass that jumps between classification and language outputs, ARMOR structures training as a multi-round loop: the model predicts detection and reasoning in the same pass, then on the next round it sees its own earlier predictions and can refine both. During training, each example gets T rounds, and the model learns to condition properly without overfitting to shortcuts.

The hidden quantity

The hidden quantity: refinement confidence

measured quantity  =  confidence from entropy

The key quantity is entropy: a measure of how uncertain or spread-out the model's predictions are. Low entropy means the model is sure; high entropy means it is hedging its bets. During inference, ARMOR samples multiple refinement trajectories (different rollouts of the model over rounds) and picks the one with the lowest entropy — the most decisive prediction.

Entropy is computed from the model's output probabilities (for detection) and token probabilities (for language). The paper uses this internal signal alone at inference, without any additional confidence model or external scoring.

Plain reading. Entropy is how scattered or fuzzy the model's answer is. If the model outputs probabilities [0.9, 0.1], entropy is low (certain). If [0.5, 0.5], entropy is high (uncertain).
Paper reading. The model computes entropy H over detection raw scores (before converting to probabilities) and token-prediction log-probabilities (the logarithm of the probability the model assigns to each word). At each inference round, the model evaluates entropy after each prediction; trajectories with lower entropy are more likely selected as the final output.
Why it works

Why iterative refinement fixes the core problem

The root problem is that detection and reasoning are linked but hard to train together. Detection is a binary signal (pass or fail), while reasoning is text, and they are optimized by completely different losses. A model trained naively tends to make its language generation independent of detection, missing the insight that reasoning should be tailored to the failure actually detected.

ARMOR fixes this by making reasoning explicitly conditioned on detection. During each training round, the model sees the detection signal (or a masked version of it, to prevent cheating) and must predict reasoning that is consistent with it. At inference, the model is rolled out iteratively: first it predicts both detection and reasoning; on the next round, it reads its own detection from round one and uses it to refine both outputs. Over multiple rounds, inconsistencies resolve. A wrong detection in round one might lead to poor reasoning, but in round two the model sees its mistake and corrects course. By round three, both are typically aligned and confident.

The model picks the refinement trajectory with the lowest entropy (highest confidence) across all rounds and all samples, which amounts to letting the model select its own most-confident hypothesis.

The training losses unified

First in words:

detection loss combines binary cross-entropy on the sparse labels; reasoning loss uses next-token prediction on the dense annotations. Both losses are computed each round, but in any given training example only one task has ground truth available at a time (the other is masked out).

Then the compact form:

L_total = BCE(detect_pred, label_detect) + NTP(reason_pred, text_reason)

Every symbol:

detect_predthe model's binary detection output
label_detectground-truth yes/no (only available in sparse data)
reason_predthe model's token probabilities for reasoning text
text_reasonground-truth explanation (only in dense data)
BCEbinary cross-entropy, a standard loss for yes/no tasks
NTPnext-token prediction loss (how often the model guesses the correct next word)
A tiny worked example
Training example 1: sparse data, no reason annotation. Detect ground-truth is 1 (yes, it failed). BCE computes penalty on detect_pred. Reason part is masked (NTP loss skipped).
Training example 2: dense data, has both. Detect ground-truth is 1. Reason ground-truth is 'gripper slipped'. Both BCE and NTP losses apply.
During round 2, the model has its own round-1 detection. It uses this to condition reasoning: if round-1 detected failure, language model will favor explaining the failure type.

Each training round computes both losses, but only on the tasks where ground truth is available, so heterogeneous data shapes the optimization.

What can go wrong

What can go wrong

Inconsistent refinement. If the model does not learn to condition reasoning on detection properly during training, refinement at inference will keep changing the story. The model might detect a gripper failure in round 1 but explain it as a rotational error in round 2.
Entropy metric is noisy. If the model is poorly calibrated, low entropy might reflect overconfidence, not correctness. The paper addresses this by training with a mix of offline (supervised) and online (self-generated) imitation, but weak calibration can still hurt trajectory selection.
Heterogeneous data imbalance. If there are thousands of sparse labels but only dozens of dense reasoning examples, the detection task can dominate training. Masking out ground truth on held-out tasks helps (by forcing the model to learn to condition reasoning independently on detection, not just copy the ground-truth reasoning), but careful batch construction is still needed to balance which samples train which task in each round.
Done right. Train with proper conditioning (model sees its earlier outputs during refinement rounds), use online imitation to keep language grounded in the model's own generated samples, and sample multiple trajectories when answering questions to let entropy pick the most coherent one.
What a runnable demo should prove

What a runnable demo should prove

Build a toy robotic scenario with a few failure modes (e.g., pick a fragile object but grip too hard; grasp it correctly but place it in the wrong bin; move the arm but hit an obstacle). Collect sparse labels on 200 simulated rollouts (binary: success or failure) and write detailed explanations for 50 of them. Train ARMOR on this mixed data for T rounds. At inference, generate M refinement trajectories for a held-out test rollout, compute entropy, and pick the lowest-entropy trajectory. Compare final accuracy on detection and quality of reasoning explanations against a baseline that trains detection and language separately.

accuracy_detection = (correct_detections / total_test_examples), quality_reasoning = (human_match_score or LLM_fuzzy_match_to_ground_truth)

The core proof: refinement trajectories should converge (entropy drops over rounds because the model aligns detection and reasoning), and the lowest-entropy trajectory should be more accurate than any single-round prediction, especially on reasoning quality, because multi-round conditioning lets the model fix mistakes made in round one.
