GOOD: Geometry-Guided Out-of-Distribution Modeling

When a point cloud segmentation model encounters new, unseen object classes in a new environment, cluster the points into superpoints and check their shape to tell which ones are unknown.

Paper explainersAll themesComputer Vision

A 3D point cloud is a dense set of coordinates describing the shape and structure of a real scene. When you train a segmentation model in one environment (say, a synthetic 3D world) and deploy it in a real one (a street with real traffic), the model encounters new classes it was never trained to recognize. The problem: there are far more known points than unknown ones, making it hard to spot what you should say "I don't know" about. GOOD fixes this by clustering nearby points together into compact chunks (superpoints), then confidently separating known from unknown chunks using their actual shape.

Zero assumption version

Known classes dominate; unknown ones hide in the noise

A point cloud segmentation model learns to label points: road, car, tree, pedestrian. When you train it on synthetic data, the model sees equal numbers of each class. But when you deploy it to a real street, the distribution shifts: you still see mostly cars and roads (known classes), but now there are also new metal bollards and digital screens (unknown classes) scattered sparsely through the scene.

A beginner tries to add a confidence threshold: if the model's confidence is below 50%, call it unknown. This fails because the model is trained on known classes only. It assigns high confidence even to unfamiliar objects, simply because it is forced to pick one of the classes it knows. With 99% of the points being roads and cars anyway, even a perfect detector of unknown points gets drowned out by false positives.

In one sentence. GOOD groups points by shape, then checks if a group's features match what the model learned during training.

The algorithm as a flow

What it actually does

Cluster points into superpoints

Group nearby points into compact chunks using geometric proximity and surface curvature.

Compute cluster-level confidence

For each superpoint, check if its features match patterns from the known classes.

Threshold on shape, not raw score

Points in low-confidence clusters are flagged as unknown, even if individual confidence scores are high.

Update prototype representations

Build and maintain memory of what known and unknown clusters look like over time.

Online adaptation on known classes only

Nudge the model to improve on known points; freeze behavior on unknown ones, because updating on unknown points would teach the model labels that may be wrong.

What the paper changes

The thing the paper changes

GOOD changes how the model decides which points to learn from during deployment. Instead of using per-point confidence scores (which are unreliable when classes are unfamiliar), it groups points into shape-aware chunks and makes the known-vs-unknown decision at the cluster level. This shift from individual point scores to shape-aware group decisions is the core move.

the object it moves  =  Confidence decision: point-level to cluster-level
The hidden quantity

Cluster confidence: knowing when a group is unknown

measured quantity  =  Cluster confidence score

Cluster confidence is a single number per superpoint that estimates how likely that chunk of points belongs to a class the model has seen before. It is not the same as the average of individual point confidences. Instead, it looks at the whole group's geometric shape, local density, and feature distribution — asking: does this cluster match the signature of known classes or does it look alien?

The paper estimates it by checking: do the features of this cluster's points align with the prototype representations (learned memory of known classes) or do they diverge? If they diverge far enough, the cluster is flagged as unknown.

Why it works

Why shape alone can separate known from unknown

During training on synthetic data, the model learns: what does a road cluster look like? (flat, large, low curvature). What does a car look like? (compact, curved edges, higher density). These become mental templates, or prototypes, in the model's memory.

When a new object appears (a real-world bollard), it is sparse and has a different curvature signature than anything in training. If you only used per-point confidence, the model would guess "car" or "road" because those are the only choices it knows. But if you ask: does this cluster match any of my learned templates? — the answer is no. The shape alone reveals the unknown, without needing to know what the bollard is called.

The mechanism is simple: train the model to memorize the shape of known classes as prototypes. At test time, cluster incoming points and ask: are these points geometrically similar to any learned cluster shape? If not, do not learn from them. If yes, adapt. This works because unfamiliar objects have unfamiliar shapes, even if the model would confuse them if forced to classify.

The confidence formula

First in words:

Cluster confidence is the minimum distance from the cluster centroid to any known prototype, divided by cluster compactness, minus a bias term.

Then the compact form:

conf_c = -min_p ||F_c - P_p|| + alpha * compactness_c

Every symbol:

conf_cconfidence score for cluster c (higher = more known)
F_caverage feature vector of all points in cluster c
P_pprototype feature vector for known class p
||...||distance (how far apart the two feature vectors are)
min_psmallest distance across all known prototypes
alphaweight controlling how much cluster shape matters
compactness_chow tightly packed the points in cluster c are (higher = more compact)
A tiny worked example
Cluster A (known road): features at [0.2, 0.1], nearest prototype road at [0.25, 0.15]. Distance = 0.07. Compactness = 0.9 (tight). Confidence = -0.07 + 0.8 * 0.9 = 0.65 (confident known).
Cluster B (unknown bollard): features at [0.5, 0.8], nearest prototype car at [0.3, 0.2]. Distance = 0.42. Compactness = 0.4 (loose). Confidence = -0.42 + 0.8 * 0.4 = -0.10 (flagged unknown).
Same shape-based reasoning: tight clusters near learned shapes score high; loose clusters far from everything score low.

Higher confidence means the cluster resembles something the model learned; lower confidence means it looks alien and should not be used for learning.

What can go wrong

What can go wrong

Cluster size mismatch. If unknown objects form very large or very dense clusters, they may match known prototypes by accident. A large bollard field might look like a road to the clustering algorithm.
Prototype staleness. If the model adapts and the prototypes drift over time, old learned shapes may no longer match new scenes, triggering false unknown labels.
Multimodal within-class shape. If known classes have high internal variation (cars are many shapes), a single prototype per class may miss some instances, treating valid known points as unknown.
Done right. Maintain fresh prototypes, use geometric diversity in training, and validate on scenes with many unknown object shapes before deployment.
What a runnable demo should prove

What a runnable demo should prove

Implement GOOD on synthetic-to-real segmentation: train on Synth4D (3D synthetic city), deploy on real SemanticKITTI footage (real driving scenes). Cluster the test point cloud into superpoints. Extract features and compare to learned prototypes. Measure: (1) how many unknown points are correctly flagged, (2) how much the model accuracy on known classes changes during adaptation, (3) how few known points are mistakenly rejected as unknown.

accuracy_known - mistake_rate_unknown + adaptation_gain = success

If the demo shows higher rejection of unknown objects AND lower corruption of known class accuracy compared to per-point confidence thresholds, the geometric separation is real.
