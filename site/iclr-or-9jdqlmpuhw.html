CoCo: Graph Clustering via Compactness and Consistency

To cluster nodes in a graph, compress their scattered representations into a tight, clean space while forcing different views of the same node to agree.

Paper explainersAll themesGraph & Geometric Learning

When you group similar nodes in a graph, a neural network learns a list of numbers for each node by passing messages between neighbors. But this local chatter misses the big picture, and the lists stay bloated with noise. CoCo fixes this by crushing those lists into a smaller, denser space and making sure two different angles on the same node always tell the same story.

Zero assumption version

Why local gossip fails for global groups

Imagine you have a social network — people are dots, friendships are lines. You want to find friend-groups: clusters of people who know each other. A neural network called a GNN (graph neural network) learns by having each person ask their neighbors about themselves, and building a mental picture based on answers. This is fast and works locally.

But here's the trap: if I only talk to my 5 closest friends to figure out which club I belong to, I miss the fact that my friends' friends' friends are also in the club. I only see my corner of the network. The model builds bloated, scattered representations crammed with overlapping, redundant information. And noise from bad data (missing edges, mislabeled nodes) seeps right in.

A beginner would say: 'Just ask neighbors further away.' But that explodes into a mess — the messages get tangled, the gradients (the learning instructions) become weak, and you still have a jumble of numbers that are not designed to be tightly clustered.

In one sentence. CoCo compresses bloated number-lists into a dense space and forces two different neural views of the same node to always produce the same compressed code.

The algorithm as a flow

What it actually does

Build two views

Run the graph through neural filters two different ways (local and global message paths).

Compress each view

Squash each sprawling embedding into a tiny dense code (low-rank factorization).

Measure disagreement

Check where the two compressed codes differ from each other.

Steer toward agreement

Nudge both views to produce the same compact representation (consistency loss).

Cluster the codes

Group nodes by their final compressed code. Similar codes mean same cluster.

What the paper changes

What the paper changes

The paper moves from full, uncompressed embeddings to compact, low-rank codes — tiny dense number-lists that strip away redundancy and noise.

the object it moves  =  embeddings to compact codes
The hidden quantity

The compact code: measuring density and overlap

measured quantity  =  compactness (redundancy and noise in the code)

Compactness is not a mysterious quantity — it is simply how much 'junk information' is in the number-list. A full list might be 128 numbers with lots of overlapping, redundant meanings. A compact code is maybe 8 numbers that squeeze the essential signal and throw away the garbage. Think of it like a photograph: the full version is a huge raw file with every pixel's noise baked in; the compact version is a small, processed JPEG that keeps the face and drops the static.

CoCo measures compactness by breaking down the number-lists into their simplest building blocks — expressing each node's code as a tiny combination of core ingredients, like finding that 20 different songs are really just remixes of 3 original tracks. The paper's consistency learning then enforces that both the local and global views produce the exact same compact code for the same node, making 'what the model thinks' unambiguous.

Why it works

Why forcing agreement on compact codes reveals true clusters

Here is the causal chain: When two independent neural paths (local and global message-passing) both see the same node, they naturally build different mental pictures because they have different training histories and random starting points. This disagreement is a sign that neither path has found the 'truth' yet — they are both partly wrong. If you force them to produce the same compact code, they must negotiate. The compression itself is the tie-breaker: a bloated 128-number embedding can hide a contradiction (one says the node is type-A, the other says type-B, and both are buried in different dimensions). But a 8-number compact code has nowhere to hide — if they disagree, it is obvious. The model then nudges both views to converge on the same story.

This forced agreement does two things. First, it surfaces the disagreement (the compact code is a pressure point). Second, it forces the model to find a code that makes sense from both angles — a story that survives both the local and global view. Nodes that truly belong in the same cluster will have views that naturally agree on a compact code; nodes in different clusters will resist compression together and drift to different codes. The noise and redundancy that was tangled up in the bloated embedding has nowhere to hide in the tiny space, so it gets scrubbed out automatically.

Math after the picture

The compactness and consistency formula

First in words:

Loss = (compactness loss: how much energy is wasted in the code) plus (consistency loss: how much the two views disagree on the code) plus (clustering loss: make similar codes stick together).

Then the compact form:

L_total = L_compact + lambda * L_consistency + L_cluster where L_compact = ||E - U*V^T||_F^2 (reconstruction error from low-rank approximation) and L_consistency = ||C_local - C_global||^2 (disagreement between two views' compact codes)

Every symbol:

L_totalthe combined cost the model tries to minimize
Ethe full, bloated embedding for a node
U*V^Tthe compact, low-rank approximation (U and V are small matrices)
||...||_F^2Frobenius norm (sum of squared differences; measures how bad the reconstruction is)
C_localthe compact code from the local-view neural path
C_globalthe compact code from the global-view neural path
lambdaa dial (hyperparameter) controlling how much to punish disagreement between the two views
A tiny worked example
Say a node's full embedding E is [2.1, 3.4, 2.0, 3.5, ...128 numbers]. The low-rank compact approximation is [2.0, 3.5, 1.9, 3.4, ...128 numbers].
Reconstruction error L_compact = (2.1-2.0)^2 + (3.4-3.5)^2 + ... = 0.01 + 0.01 + ... = 0.5 total.
Local view produces compact code [0.87, 0.12] (two numbers). Global view produces [0.88, 0.11].
Consistency error L_consistency = (0.87-0.88)^2 + (0.12-0.11)^2 = 0.0001 + 0.0001 = 0.0002.
If lambda=100, the penalty for disagreement is 100 * 0.0002 = 0.02, so the model nudges the codes closer.

Compactness (shrinking the embedding) and consistency (making the two views agree) work together: the tiny space leaves no room for noise, and forcing agreement uses both angles to spot the real signal.

What can go wrong

What can go wrong

Compression too aggressive. If the compact code is too tiny (too few dimensions), it might not hold enough signal for fine-grained clustering. The model throws away useful detail along with the noise.
Two views never agree. If the local and global neural paths learn very different patterns, forcing them to produce identical compact codes can trap the model. It cannot satisfy both constraints and ends up with a mediocre compromise.
Dense, local graphs fail. In a graph where every node talks to every other node (or nearly), there is no difference between local and global views. The two paths see almost the same thing, so consistency learning adds no new information; compactness alone has to do the work.
Done right. Pick the compact code size by cross-validation. Smaller codes are better because they force the model to throw away noise and redundancy (a tiny space has nowhere for garbage to hide), but too small means the code cannot hold enough signal to distinguish different clusters, so accuracy collapses. Tune the consistency penalty lambda so both losses get a hearing. On sparser graphs with real local/global distinction, the method shines.
What a runnable demo should prove

What a runnable demo should prove

Build a toy graph (100 nodes, split into 4 ground-truth clusters; add edges within clusters, few edges between). Train a baseline GNN, then train CoCo. Measure clustering accuracy (percentage of nodes assigned to their correct cluster) and track the two losses (compactness and consistency) over training steps.

cluster_accuracy = (number of nodes in the right cluster) / (total nodes)

The demo must show: (1) baseline GNN stays flat and confused; (2) CoCo's consistency loss shrinks and cluster accuracy climbs; (3) a visualization of the compact codes (plot them as 2D points via t-SNE or UMAP) shows tight, separated clusters.
