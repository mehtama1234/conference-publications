Designing A/B Tests for Time Series with History and Reinforcement Learning

When you run an A/B test where treatments come one at a time, use a transformer to remember the whole history and reinforcement learning to pick the next treatment without guessing.

Paper explainersAll themesTime Series & Sequential

A/B testing (running two versions of something and measuring which works better) is hard when treatments arrive sequentially over time, like deciding whether to show ads or not to a user each day, because the effect of one day's choice can carry over to the next. Old methods either ignore the past or make strong guesses about the math, which breaks when the real patterns don't match those guesses. This paper uses a transformer (a model that remembers everything that happened before) plus reinforcement learning (a method that learns by trying things and getting rewards) to decide the next treatment by looking at actual data instead of math shortcuts.

Zero assumption version

Sequential A/B testing is stuck between two bad choices

When you run an experiment where you assign treatments one at a time (like deciding each day whether to show a customer a discount or not), you want to know: which treatment works better in the long run? A/B testing is the standard way companies measure this, but time series experiments make it hard because the outcome on day 2 can depend on what you assigned on day 1, so you cannot treat each day as independent.

The naive approach: flip a coin each time you assign a treatment. This wastes opportunities because if you have already seen that treatment A works better on Mondays and treatment B on Wednesdays, a coin flip ignores that pattern and might assign A on Wednesday when B is better—you throw away information you already have.

The old solution: use the first few treatments to estimate what works, then use math to figure out which future treatments to pick. But this math relies on assumptions that are almost never true—assuming the effect is a straight line, assuming past days don't affect future days, assuming the noise behaves predictably. When the assumptions break, the whole calculation breaks.

The method in one sentence: Use a transformer to see all the history so far, then train it with reinforcement learning to pick the next treatment by watching the actual outcome, not by solving a math formula.

The algorithm as a flow

What it actually does

Collect the history

Store all past treatments and outcomes: day 1 got A and outcome 92, day 2 got B and outcome 87.

Transformer encodes it

Feed all the history into a transformer, which reads all days at once and learns which past days matter for predicting today.

RL proposes two options

Reinforcement learning suggests treatment A and treatment B for today and estimates how well each would work based on the history.

Pick the best one

Choose the treatment with the lowest predicted error (mean squared error, the average of squared differences from the true answer).

Observe and learn

After you run that treatment, see the real outcome, measure the error, and update the RL system to improve its next guess, because watching what actually happened shows whether the earlier prediction was right or wrong.

What the paper changes

What the paper changes: the treatment assignment rule

The paper changes how you decide which treatment to run on each new time step. Instead of a coin flip or a math formula that assumes things about the data, it uses a transformer plus reinforcement learning to watch what actually happened before and pick the next treatment by testing which one would have worked better in the past.

The hidden quantity

The hidden quantity: the mean squared error of the estimated effect

measured quantity  =  MSE of treatment effect estimate

The hidden quantity is the error in your guess about which treatment works better. When you assign treatments and measure outcomes, you estimate how much better treatment B is than treatment A based on the data you see, but that estimate might be off by some amount because you only saw a sample of the data, not the whole world. The mean squared error is the average of those mistakes squared. A smaller MSE means your final answer about which treatment won is more accurate, because when your estimate is closer to the truth, any decision you make based on it is more likely to be right.

The paper measures this directly by running RL agents and watching how well they predict the right treatment, because the RL agent is trained to minimize actual MSE by observing which treatment it chooses leads to smaller prediction errors. Old methods tried to predict MSE using a math formula based on assumptions, which fails when those assumptions are wrong. This paper instead trains the reinforcement learning agent to minimize the actual MSE by trying different treatment sequences and seeing which leads to smaller errors, learning from real outcomes instead of relying on math shortcuts.

Why it works

Why it works: full history beats shortcuts

The core insight is that old methods cut corners—they use math formulas to guess what the MSE will be, but those formulas only work if very specific assumptions about the data are true (like no seasonal patterns, no hidden dependencies between days). When the real data breaks those assumptions, the formula gives the wrong answer about which treatment is better because the numbers plugged into it no longer match reality.

The transformer + RL approach avoids the shortcut entirely. The transformer reads all prior days at once, so it can find ANY pattern in the past (Monday effects, interaction between yesterday and today, anything) without needing assumptions. Then reinforcement learning trains by watching actual outcomes: it proposes treatments, observes which one causes lower error, and updates its strategy. It never relies on a math formula—it learns directly from data, so it adapts to whatever patterns actually exist. This is slower to train but far more accurate when the data has unexpected structure, because it does not rely on assumptions that could be wrong.

Why full history matters: in time series, what you assign today affects how to interpret tomorrow's outcome. If you assigned A on day 1, a high outcome on day 2 might be a carryover effect, not proof that treatment B on day 2 was good. A transformer that sees day 1 and day 2 together can learn this dependency, so it does not confuse a carryover effect with a treatment effect. A method that forgets day 1 treats day 2 in isolation and draws the wrong conclusion because it cannot distinguish a true effect from a spillover.

The objective: minimize mean squared error

First in words:

The reinforcement learning agent tries to minimize MSE, the average of squared differences between the true treatment effect and the estimated effect, where the choice of treatment at each step depends on everything that happened before.

Then the compact form:

MSE = (1/T) sum_t (true_effect_t - predicted_effect_t)^2

Every symbol:

Tnumber of time steps in the experiment
true_effect_tthe real difference caused by the treatment at step t
predicted_effect_twhat the transformer+RL system predicted would be the effect at step t
sum_tadd this up for every time step from 1 to T
A tiny worked example
Day 1: treatment A, true effect 5, predicted 4.8 -> error (5-4.8)^2 = 0.04
Day 2: treatment B, true effect 3, predicted 3.5 -> error (3-3.5)^2 = 0.25
Day 3: treatment A, true effect 6, predicted 5.9 -> error (6-5.9)^2 = 0.01
MSE = (0.04 + 0.25 + 0.01) / 3 = 0.30 / 3 = 0.10. The RL agent updates itself to lower this.
If it had guessed worse, e.g., predicted A on day 2 to get error (3-4)^2 = 1, MSE would be (0.04 + 1 + 0.01) / 3 = 0.35. It learns to avoid that.

The transformer enables RL to learn patterns from history that old math formulas could not find, so it predicts effects more accurately and the MSE stays low.

What can go wrong

What can go wrong

Not enough history to train. If the experiment is very short (only 10 days), the transformer and RL agent have little data to learn from, so they cannot discover patterns yet, and the method works no better than simpler baselines because there is insufficient evidence to guide the RL agent.
Hidden confounders not in the data. If the true cause of outcomes is something you never measured or assigned (like unknown seasonal factors, events outside your control), the transformer cannot see it, and predictions will still be wrong.
Expensive to run in real time. Training an RL agent and running a transformer on every time step is slow. If you need to decide the treatment every millisecond, this approach is too heavy.
Works well when history is rich. If you have many days of data and the true patterns depend on past outcomes, the transformer + RL method learns them and predictions stay accurate.

What a runnable demo should prove

Implement three assignment strategies: random coin flip, a method using only the last 3 days (forgetting older patterns), and the transformer+RL method. Run each for 30 days and measure the MSE of the treatment effect estimate for each.
