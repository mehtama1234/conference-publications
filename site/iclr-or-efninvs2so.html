Discovering Novel LLM Experts via Task-Capability Coevolution

AC/DC grows a population of diverse small language models in a single run by making them and their training tasks evolve together.

Paper explainersAll themesLLMs & Foundation Models

Building language models that know many skills normally requires restarting training from scratch every time you want to add a new skill. AC/DC flips this: instead of static training, it runs a continuous cycle where both the models and the tasks they learn from change and adapt to each other, discovering a growing population of small specialized experts that together know as much as a single giant model.

Zero assumption version

Training is stuck in a rut

Right now, training language models goes like this: pick a dataset, run for months, done. Want a new skill? Start over with a different dataset. Want another skill? Start over again. Each training run is independent.

The problem: you waste work. If you already trained a model to do math, then retrain from scratch to add reasoning, the model forgets half of math. You are constantly throwing away models and starting fresh, like replanting a garden by digging up the old one every time you want a new flower.

The naive attempt breaks. Just add more data to the same dataset and keep training. This makes the model worse at its old tasks because the new data pushes it in a different direction.

What the paper changes

What changes

Normally, you pick a dataset, train one model, and move on. AC/DC changes two things at once: the models (via merging their weights) and the tasks (via synthetic generation). Both evolve in response to each other instead of being static.

the object it moves  =  Models and their training tasks
The hidden quantity

Skill coverage: which unique abilities does the team have

measured quantity  =  Coverage of expert skills

This is the hidden thing AC/DC measures: not just whether a single model is good, but whether the whole population together covers a lot of different abilities. If one model is great at math but terrible at reasoning, and another is great at reasoning but weak at coding, Coverage asks: as a team, what gaps remain?

The paper estimates Coverage by looking at each model's binary skill vector (which tasks did it solve?) and comparing it to every other model's. A model is valuable if it solves tasks that no stronger model solves yet, because that means it fills a gap in the team's abilities. A team with seven models who all solve the same ten tasks covers nothing more than one model solving those ten. But if each model solves a few tasks the others miss, the team's total Coverage grows. This is called a rarity score: the more unique-skill combinations you have, the higher the Coverage.

Plain reading. Coverage is the answer to: if I pick one model from this population to solve a new task I have not seen, how likely is it to know the right skill?
Paper reading. The paper computes a skill vector (a list marking which tasks each model solved) and a rarity score: for models that are not the absolute best, it measures how many tasks they solve that no stronger model solves. This works because rewarding unique solutions prevents all models from chasing the same targets and becoming clones of each other.
Why it works

Why coevolving models and tasks discovers diversity

Here is why this works: if you only change the models, they all chase the same static tasks and converge to the same solution. If you only change the tasks, you are just making the one model go in circles. But if both change together, something new happens.

Here is how it works: start with a population of models and a pool of tasks. Some models solve some tasks. Now: (1) Merge the best models to breed new candidates. (2) Test each candidate against all tasks and score it on coverage. (3) Generate new synthetic tasks that the current top models cannot solve. (4) Keep models that are good and different from the archive. The new tasks act as a pressure: they push the next generation of models to learn new skills to survive. At the same time, the models that survive shape what future tasks get generated, because future tasks target their weaknesses. This feedback loop means the population never stagnates. Each generation discovers new skill combinations.

The rarity score

First in words:

For each model s, find all archived models s-prime that are better. For each better model, measure how many task-solving patterns are unique to s (never seen in s-prime). Average this gap across all better models. This is the rarity score: high if s has rare skills.

Then the compact form:

rarity(s) = mean over s' { count(tasks where s wins but s' loses) / total tasks }

Every symbol:

sthe model being scored
s-primean archived model that solved more tasks
novelty(s)how rare the skills of s are among better models
tasksthe full set of test problems
s winsmodel s solved the task, s-prime did not
A tiny worked example
Model A solved 8 tasks. Model B solved 12 tasks (better).
Looking at B vs A: B solved all 8 that A did, plus 4 more. Unique skills of A: 0 tasks.
Model C solved 12 tasks. Comparing C vs A: C missed 1 task that A solved (coding style). Unique to A: 1 task.
A's rarity score: mean(0/8, 1/8) is 0.0625. This is low because A does not solve anything that stronger models miss.
Model D solved 10 tasks, including 2 A solved that no other model solved. Comparing D vs A: unique to A is 2 tasks.
A's rarity score would rise if more models in the archive had gaps that A uniquely filled.

Models with high rarity scores are kept in the archive because they solve unique combinations of tasks, which grows Coverage.

What can go wrong

What can go wrong

Merging creates gibberish. When you blend weights from two models that learned very different things, the result is often incoherent. The paper filters these out with a gibberish detector (an LLM judge that checks if the merged model is even a valid language model).
Generated tasks become impossible. If synthetic data generation is not careful, it makes tasks so hard that no model can solve them. Then there is no feedback signal to learn from. The paper filters these with an impossible-task detector.
All models converge to the same solution. If rarity scoring breaks or is too weak, the population loses diversity and everyone ends up solving the same subset of tasks. Coverage stops improving.
Done right. With quality and rarity filters, and synthetic tasks that are challenging but achievable, the population stays diverse. Each generation has both breadth and depth.
What a runnable demo should prove

What a runnable demo should prove

Start with a small language model (e.g., Qwen 0.5B). Create an initial archive of 3-5 models trained on different skills (math, coding, reasoning). Create a task pool of 20 diverse tasks. Run 5 rounds of coevolution: merge the two best models to create a candidate, test it, generate one new task targeting weaknesses, keep the model if it has rare skills. After each round, measure the Coverage of the archive by asking: if I randomly pick a model and a task, what is the probability the model solves the task? Plot Coverage over rounds. It should rise monotonically.

Coverage = (sum over all models and tasks of skill vector entries) / (number of models * number of tasks)

The core claim that coevolution discovers breadth should be impossible to miss: the curve of Coverage must rise with each round, proving that the population is not losing diversity or converging to one solution.
