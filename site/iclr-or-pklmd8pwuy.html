UniVLA: Unified Vision-Language-Action Model

A robot learns action sequences by treating images, words, and movements as the same kind of tokens and predicting what comes next.

Paper explainersAll themesRobotics & Control

Robots learn to manipulate objects by watching videos and reading instructions, but most systems ignore the time-order and cause-effect hidden in the visual stream. UniVLA treats vision, language, and action as a single stream of discrete items (tokens), each one a tiny numbered block from the same vocabulary, and trains the robot to predict what token comes next, much like predicting the next word in a sentence. Before manipulating real objects, it first watches unlabeled videos to learn how the world changes over time — a process called world modeling — which makes the robot much faster to retrain on new tasks because the model has already absorbed the physics and causality, so fine-tuning only needs to teach task-specific actions instead of starting from scratch.

Zero assumption version

The old way missed time and cause-and-effect

Previous robot models relied on general-purpose vision systems (which read images) and language systems (which read instructions) to produce robot actions. The problem: these systems were trained on internet text and photos, not on video. They did not learn that if the robot pushes a block, the block moves — they only learned static facts like 'blocks are rectangular' or 'instructions are spelled with letters.'

A beginner might ask: why not just add another layer to predict actions? Because the disconnect runs deeper. The vision part outputs a fixed-size summary (a compressed picture in the model's mind), the language part outputs a summary of the text, and then a separate action-prediction head glues them together. This three-part pipeline works but misses the causal structure: when a robot watches a 10-second video of pushing a block, that video is really a chain of cause-and-effect — one frame causes the next frame. The old pipeline collapsed the whole video into one image-summary, throwing away the time order.

The method in one sentence. Instead of separate image-reading and action-predicting stages, convert images, text, and robot actions into a single stream of numbered tokens, and train the robot to predict each token based on all the tokens before it.

The algorithm as a flow

What it actually does

Tokenize all inputs.

Convert each image frame and text instruction into a list of small integers (tokens) using pre-built encoders, then concatenate them into one long sequence.

Post-train on unlabeled video.

Show the robot millions of video clips (no actions needed). Train it to predict the next image token given all earlier tokens in the sequence, using only a simple prediction-error loss.

Interleave action tokens.

Take video clips from actual robot tasks (with recorded actions). Insert action tokens into the stream between image-token clusters, so the sequence alternates: image, image, action, image, image, action.

Fine-tune on task data.

Retrain the model on task videos using only the action-token loss, asking: given past images and words, predict the next action. The robot now knows both causality (from video pre-training) and task-specific moves.

Evaluate on new tasks.

Test on unseen manipulation benchmarks. The robot succeeds at long-horizon tasks (push A, then B, then C in sequence) with much less task-specific retraining than methods trained from scratch.

What the paper changes

What the paper changes

The paper shifts the robot's learning target from a two-stage pipeline (image understanding, then action generation) to a single unified sequence model. The robot no longer compresses vision into a fixed summary before generating actions. Instead, it treats every pixel-detail, every word, and every motor command as tokens in one stream, and learns to predict what comes next in that stream.

The hidden quantity

Causal dynamics: what the model learns during video pre-training

measured quantity  =  Temporal causal structure of the video

When the robot watches a video, it should learn not just 'blocks are square' but 'when I push block-A, it moves in direction D and collides with block-B.' This cause-and-effect is encoded in the sequence of frames — each frame causally follows the last. The paper calls this the world model: the hidden pattern of how observations flow into one another over time.

During post-training, the paper forces the model to predict the next image token given prior ones, using only a reconstruction error (how wrong was the predicted picture?). By doing this on millions of unlabeled videos, the model absorbs the causal rules without ever seeing a robot action label. Then, when action tokens are added during fine-tuning, the model already knows the physics, so it learns the policy much faster.

Why it works

Why unified tokens and two-stage training work

Predicting the next pixel is hard — it forces the model to understand causality. If the model could always predict frame 2 from frame 1, it means frame 1 determines frame 2, so the model internalized the deterministic rules of the world by building internal representations of how actions change the scene. Conversely, a model trained only on action prediction (given an image and instruction, output an action) never needs to learn the causal chain — it only learns an input-to-output mapping, where each input always points to the same output, without understanding the physics or side effects.

By using the same token vocabulary and the same prediction mechanism (a transformer, which attends to and combines earlier tokens to predict the next one) for both vision and action, the model builds a unified internal representation. When an action token comes next in the sequence, the model can now reason: 'if I generate action-token-7, what would frame-N+1 look like?' without a separate visual-planning step. This causal reasoning makes long-horizon tasks easier because the model can mentally simulate a chain of consequences, not just the immediate effect. After post-training absorbs the causal rules, fine-tuning becomes efficient because the model only needs to learn which specific moves the robot performs in this specific task, not re-learn physics from scratch.

The training loss across two stages

First in words:

During post-training: cross-entropy loss computed on predicted vision tokens only. During fine-tuning: cross-entropy loss computed on predicted action tokens only. Token prediction is the same at both stages — pick the most likely next token.

Then the compact form:

L_post = cross_entropy(predicted_vision_tokens, target_vision_tokens) | L_finetune = cross_entropy(predicted_action_tokens, target_action_tokens)

Every symbol:

predicted_vision_tokensthe model's guess for the next image token based on prior tokens
target_vision_tokensthe actual next image token in the video
predicted_action_tokensthe model's guess for the next robot action token
target_action_tokensthe actual action the robot performed in the task
cross_entropya score of how wrong the guess is: 0 if perfect, higher if off
A tiny worked example with video clips
Post-train example: Show the model tokens [image_8, image_15, image_22]. Model guesses image_30 is next. True next token is image_31. Prediction error (a measure of how wrong the guess is) = how much 30 differs from 31. Update the model to predict 31 better next time.
Fine-tune example: Show the model tokens [image_8, image_15, action_3]. Model guesses action_2 is next. True next action is action_4. Loss = how much 2 differs from 4. Update the model to predict action_4 better.
Key: same prediction machinery, different label source (images in post-train, actions in fine-tune). This means the model reuses the causality it learned in post-training when predicting actions.

The two losses use the same mechanism (next-token prediction) but different supervisory signals, allowing the model to transfer causal understanding from video to policy.

What can go wrong

What can go wrong

Post-training on the wrong video type. If the unlabeled videos are of a different robot or environment, the causal rules will be wrong. The model learns 'pushing this arm makes the gripper open,' but if you then fine-tune on a robot where the gripper works differently, the learned dynamics mislead the policy.
Long-horizon tasks with no causal memory. Post-training learns frame-to-frame causality but not long-term cause-and-effect. A sequence like 'push block A, wait for it to settle, then push block B' requires remembering the side effect of step 1 when deciding on step 2. If the post-training videos were short clips, the model may not learn multi-step reasoning.
Misaligned action vocabulary. If the action tokens from the task-training stage are different from the task context (e.g., training on 'gripper open/close' but the real robot uses continuous angles), the fine-tuning stage cannot bridge the gap. The model will produce the wrong action tokens.
Done right. Match the post-training video domain to the task domain so the model learns the right physics; ensure action tokens represent the real task space so predictions map to actual moves; and use sufficient post-training data so the model has truly absorbed the physics before it learns the policy, because insufficient pre-training means the model starts policy learning without causal grounding, defeating the whole method.
What a runnable demo should prove

What a runnable demo should prove

Build a simple robot simulation (or use an existing one like LIBERO). (1) Record 100 short videos of the robot arm exploring — pushing blocks, moving between poses, with no specific task goal. (2) Train a UniVLA model on just those videos using the post-training loss (predict next frame). Do not provide any action labels yet. (3) Then collect 20 labeled examples of the task 'place a block in a target zone' — each example is a 10-frame video with recorded actions. Fine-tune the UniVLA model using only the action-loss on those 20 examples. (4) Test the trained model on new task scenarios.

Success rate = (number of tasks the robot completes / total number of test tasks) × 100%. Compare against a baseline model trained on 20 labeled examples with no post-training. UniVLA should show ≥ 30% higher success rate despite starting with the same amount of labeled task data, because the unlabeled video pre-training taught causality.

The demo should show that post-training on unlabeled video cuts the number of labeled task examples needed to reach a target success rate by at least half, proving that learning causal dynamics from video is the key.
