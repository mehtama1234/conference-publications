PoSh: Scene Graphs as Structured Rubrics for Judging Image Descriptions

PoSh uses scene graphs (structured diagrams of objects and their relationships) to guide LLMs in grading detailed image descriptions, catching fine-grained errors that old metrics miss.

Paper explainersAll themesComputer Vision

Describing a painting or photograph in words is hard to grade fairly. Old metrics like CIDEr count word matches, which works for short captions but fails for long, detailed descriptions where the real errors are subtle: mixing up which object has which color, or misplacing a relation between things. PoSh fixes this by extracting a scene graph (a diagram of objects, their properties, and how they relate) from both the reference description and the model's attempt, then asks an LLM to score how well the model's version matches the reference version on each component.

Zero assumption version

Grading detailed descriptions is harder than it looks

A standard image metric like CIDEr or SPICE works by checking if the description contains certain words or phrases. This makes sense for short captions: you describe a dog, the system checks for the word dog, because a short caption has few ways to say the same thing, so exact word match is reliable. But detailed descriptions are long and written many ways. A human might say the dog sits beside a red barn; a model might say the dog stands by a crimson building. Both are describing the same scene, but old metrics see different words and score it as wrong.

The real errors in detailed descriptions are subtle: the object is right but the color is wrong, or the relationship is backwards (the cup is on the table versus the table is under the cup). These compositional mistakes need a judge who understands structure, not word counting.

In one sentence. PoSh extracts the structure of each description (what objects, properties and relations it mentions) and asks an LLM to check how well the model's structure matches the reference structure.

The algorithm as a flow

What it actually does

Extract structure

Parse both descriptions to find objects, their properties, and relations.

Template questions

For each component, write a question: Does the generation mention this object? Is the color correct?

Prompt the LLM

Ask an LLM to read both descriptions and answer each question on a 1-5 scale.

Score components

Collect LLM scores for objects, properties, relations as separate granular error scores.

Aggregate to final score

Combine component scores into overall quality and localized error categories.

The hidden quantity

The fine-grained error: component-level alignment

measured quantity  =  Component-level match score

A component-level match score is how well a single element (one object, one property, one relation) from the reference description appears correctly in the model's description. For example: Does the model mention the dog? Does it say the dog is red, not blue? Does it place the dog next to the barn, not inside it?

PoSh estimates this by templating a question for each component, feeding both descriptions to an LLM, and asking the LLM to rate on a scale of 1 to 5 whether the model captured that specific component correctly. The LLM reads the descriptions and judges similarity, so it can catch paraphrases and near-misses instead of exact word matches.

Why it works

Why it works: structured rubrics catch relational errors

Traditional metrics use word bags: they count how many words from the reference appear in the model output. This breaks for long, paraphrased descriptions because the model can say the right thing in entirely different words.

PoSh uses scene graphs as rubrics. A scene graph is a strict listing of the objects in the image, their properties (like colors, sizes), and the relations between them (who is next to whom, what is inside what). By extracting this structure from both descriptions and having an LLM compare structure-to-structure, the metric captures what the model actually understood about the spatial and semantic composition of the image, not just surface word overlap.

The LLM acts as a flexible bridge: it reads two descriptions and judges whether the model's version captures the same structural facts as the reference, even if the words are completely different. This is why PoSh matches human judgment better—humans also care about compositional correctness, not word-for-word repetition.

Math after the picture

The aggregation formula: weighted component scores

First in words:

Final score is the average of LLM component scores, weighted by importance. Mistakes (where model says something wrong) and omissions (where model fails to mention something) are separated and reported as distinct error types.

Then the compact form:

PoSh_score = (sum of component scores) / (number of components), where each component score is LLM_judgment(reference_component, model_description)

Every symbol:

reference_componentOne object, property, or relation from the reference scene graph
model_descriptionThe full description generated by the model
LLM_judgmentThe LLM's 1-5 score for how well the component appears in the model description
sum of component scoresAll judgments added together
A tiny worked example
Reference has 5 components: dog (object), red (color), barn (object), beside (relation), grass (property).
LLM scores for model description: dog=5 (present), red=3 (close: says crimson), barn=4 (present), beside=5 (correct), grass=1 (omitted).
Average: (5 + 3 + 4 + 5 + 1) / 5 = 18 / 5 = 3.6 overall quality.
Mistakes: color slightly wrong (LLM gave 3 instead of 5), totals 2 points of localized error.
Omissions: grass missing entirely (LLM gave 1), totals 4 points of omission cost.
Humans looking at the same generation rate it 3.7, close to PoSh's 3.6.

By grading each structural piece separately, PoSh pinpoints exactly where the model went wrong and aggregates fairly, matching how humans judge detailed descriptions.

What can go wrong

What can go wrong

Scene graph extraction fails. If the dependency parser or coreference resolver makes mistakes, the scene graph is incomplete or malformed. Then the rubric has gaps or phantom components, and the LLM's judgment is based on a broken template.
LLM refuses the task or hallucinates. An LLM prompted to score a component might disagree with human raters or invent a reason to rate high even when the model clearly failed. Calibration on a human-labeled set (like DOCENT) helps because the LLM sees examples of when to be strict and when to be lenient, so it learns the nuance, but drift persists because new images or unfamiliar compositions can trigger different judgment patterns.
Scene graphs are lossy. A scene graph captures objects and relations but not tone, style, or fine aesthetic detail. A model that gets composition right but tone completely wrong will still score high on PoSh even if humans say it is poor.
Done right. When scene graphs are extracted cleanly, the LLM is prompted consistently, and the evaluation set is diverse (as in DOCENT), PoSh tracks human judgment far better than word-based metrics because the LLM judges structural understanding rather than word match, and catches real compositional errors because each component is scored independently so mistakes are visible and localized.
