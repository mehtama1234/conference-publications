Scaling Small Agents Through Strategy Auctions

Small language models can handle complex tasks efficiently when they bid with strategic plans and are routed by a cost-value auction, not by training a fixed router.

Paper explainersAll themesAgents & Tool Use

Small language models cost less money to run than large ones because they use fewer calculations, but they fail on tasks that require deep thinking or writing code because they have seen less training data. This paper proposes a different idea: instead of training a router to send each task to the right agent, let the agents themselves bid with their strategic plans, scored by how well they balance cost and quality. The best plan wins the task, and the agents learn from shared auction results without any training.

Zero assumption version

Small agents fail when tasks get hard

A language model is a software copy of a person who has read a lot and can answer questions by predicting the next word. Smaller models have been trained on less text and have fewer mathematical weights, which means they use less computing power and are cheaper to run, but they struggle when a task requires careful reasoning or code because the knowledge they absorbed during training is shallower. A large model, like a helpful expert, works on both simple and hard tasks because it has absorbed more training data — but costs much more to run because it uses more computing power.

The naive approach: train a router, a separate piece of logic that looks at each task and decides which agent (small or large) should handle it. But routers are brittle. They either send everything to the largest agent (wasting money) or misjudge which tasks need which model (losing quality). The real problem: a router sees only the task description before committing, not the actual quality of each agent's plan.

In one sentence. SALE lets agents propose their own strategic plan for each task, scored by a cost-value auction, and routes based on which plan is best, not which model is biggest.

The algorithm as a flow

What it actually does

Each agent sees the task

The small, medium, and large agents all look at the same problem (a search question or coding puzzle).

Each agent proposes a strategy

Instead of running to completion, each agent first outlines its plan (number of reasoning steps, tools it will use, budget) and predicts how likely it is to work.

Agents bid with cost and value

Each proposes a cost (tokens it will spend) and an expected value (probability it will solve correctly). The auction compares the bids.

Scorer picks the best value

A cost-value mechanism scores each bid: reward quality, penalize wasted tokens. The highest-scored bid wins the task.

Winner runs; auction memory learns

The winning agent executes its plan. The result (success or failure) is stored in shared memory, so all agents refine future bids without training.

What the paper changes

What the paper changes

The paper swaps out the fixed router (which looked only at task type) for something alive: an auction in which each agent bids with its own strategic plan for that specific task. The bid includes both a cost forecast (how many tokens it will burn) and a quality forecast (how likely it will solve the task). An auction scorer judges all bids and picks the one with the best balance of quality and cost.

the object it moves  =  routing decision
The hidden quantity

The cost-value score: how good is a bid?

measured quantity  =  cost-value balance

The paper's secret is a hidden quantity: how much value an agent's plan gives per token spent. It is not just quality (does the agent solve it?) and it is not just cost (how many tokens does it burn?). It is the ratio of the two: divide the quality score by the cost, so that an agent who solves it with few tokens gets a higher score than an agent who solves it with many tokens. The auction scorer measures this ratio for each bid.

The paper estimates the cost-value score for each plan by looking at the predicted quality (from the agent's own reasoning about the task) and the predicted cost (tokens the agent will spend). Then it combines them: reward plans where a small agent gets most of the quality at low cost, and penalize plans where a large agent wastes tokens on a simple task.

Why it works

Why asking agents to bid works better than a fixed router

A fixed router is blind: it sees task name and model size, and guesses. It cannot know whether the small agent has a clever shortcut for this specific problem or whether the large agent is going to waste tokens.

An auction reveals what each agent thinks it can do. The small agent, when it sees a logic puzzle, might realize it can solve it with a single reasoning chain and bid low cost, high confidence. The large agent, seeing the same puzzle, might not have any special trick and propose a more expensive search. The scorer now has real data and picks the efficient small agent.

The key: agents refine their bidding strategies over time by observing shared auction results (which agents won, which lost, which succeeded or failed). They do not need to be retrained. The small agents learn which tasks reward their quick tactics, and the large agents learn which tasks truly need their power. This is pure coordination: the right agent gets called for the right job, without the coordinator needing to train anything.

Math after the picture

The cost-value score formula

First in words:

score = predicted_quality divided by predicted_cost, adjusted by a penalty if the proposal is risky

Then the compact form:

bid_score = quality_forecast / cost_forecast + memory_adjustment

Every symbol:

bid_scorethe auction score for this agent's bid (higher is better)
quality_forecastthe agent's predicted probability of solving the task (0 to 1)
cost_forecastthe agent's predicted number of tokens it will spend
memory_adjustmenta bonus or penalty learned from past auction outcomes in shared memory
A tiny worked example
Small agent bids: quality 0.8, cost 100 tokens. Score = 0.8 / 100 = 0.008 per token.
Large agent bids: quality 0.9, cost 500 tokens. Score = 0.9 / 500 = 0.0018 per token.
Small agent's score is 4x higher per token. Small agent wins and runs the task.
If small agent succeeds, auction memory records success. Small agent is more confident next time.
If small agent fails, memory records failure. Small agent bids lower quality on similar tasks next time.

The auction picks the bid with the highest score because it balances quality (probability of solving) with efficiency (tokens spent), adjusted by what the agents have learned from past wins and losses.

What can go wrong

What can go wrong

Agents bid optimistically and overestimate quality. If a small agent always predicts high quality even for hard tasks, the auction will keep routing hard tasks to it, and it will keep failing. The shared memory needs enough historical data to correct this bias, otherwise the auction trusts bad forecasts.
A task is completely new; shared memory has no precedent. SALE learns from past auction results. If a task has never been seen before and is unlike any past task, the agents have no historical data to refine their bids and may all bid poorly. The auction still picks a bid, but it may be a bad one.
Cost and quality are misaligned for this task type. Some tasks may genuinely require a large model for good quality, and the large agent will bid higher cost. The auction will pick it. If the cost-value scorer does not weight quality heavily enough, SALE may sacrifice too much accuracy to save tokens.
Done right. If agents bid honestly (reflecting their actual expected quality and cost), shared auction memory has many past tasks so agents can learn accurate patterns, and the cost-value scorer balances efficiency with quality, then SALE routes each task to the agent most likely to solve it cheaply.
What a runnable demo should prove

What a runnable demo should prove

Build a small simulation: three agents (small, medium, large) with different reasoning budgets and success rates. Create a dataset of 50 tasks (mix of simple and hard). Run the auction for each task: agents bid with their strategy, auction picks the winner, record the outcome. Repeat 10 times so agents observe results and refine bids. Measure: total token cost and overall pass rate (fraction of tasks solved). Compare SALE routing against a fixed router that always uses the large agent.
