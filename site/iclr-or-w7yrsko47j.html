CLUTCH: Contextualized Language model for Unlocking Text-Conditioned Hand motion modelling in the wild

CLUTCH builds a large in-the-wild hand-motion dataset, compresses hand motion into structured discrete codes with SHIFT, and trains a language model plus decoded-motion refinement to generate or describe hand motion without relying on studio-only captures.

Paper explainersAll themesMultimodal

Hand motion is difficult to model because hands move with many joints, contact patterns, and context-dependent actions, yet most existing datasets come from studios with narrow action coverage. CLUTCH changes both the data and the model. It introduces 3D-HIW, a dataset of 3D hand motion and aligned text from everyday egocentric video, and it uses SHIFT, a VQ-VAE, meaning a model that compresses continuous motion into discrete codes chosen from a learned codebook, to turn hand motion into a sequence that a language model can handle. A decoded-motion refinement stage then supervises the decoded hand variables, meaning the numeric values for joints and pose, directly so the language model learns codes that reconstruct valid motion rather than only plausible code sequences.

Zero assumption version

Why studio hand datasets are not enough

Hand motion depends strongly on context. The same grasp shape can mean picking up a mug, opening a drawer, or folding cloth, and natural videos contain partial visibility, camera motion, object interaction, and varied timing. Studio datasets remove much of this variation, so models trained on them often learn a narrow action vocabulary and brittle motion patterns.

There is also a representation problem. Raw 3D hand motion is continuous and high-dimensional. A language model expects a sequence of discrete units. If the motion tokenizer, meaning the module that converts motion into a sequence of discrete codes, is weak, the language model will model the tokenizer's reconstruction errors rather than the real structure of hand movement.

The method in one sentence. CLUTCH builds large-scale in-the-wild 3D hand-text pairs, converts motion into structured discrete codes with part-aware tokenization, and then refines the decoded motion so the final hand sequence matches both the text and the actual joint behavior.

The algorithm as a flow

What it actually does

Build 3D-HIW from real videos

Run hand tracking and text annotation on egocentric action video so each sequence has 3D hand motion and aligned language from daily settings.

Tokenize motion with SHIFT

Train a VQ-VAE that compresses hand motion into discrete codes while separating parts and motion modalities, so important fine-grained finger behavior is not drowned out.

Train the language model on motion-text pairs

Use the motion codes as the sequence target for text-to-motion generation and as the sequence input for motion-to-text captioning.

Decode codes back into hand variables

Turn predicted code sequences into continuous joint-space motion so the result can be rendered and measured geometrically.

Apply geometric refinement

Back up the language-model training with a reconstruction loss on decoded hand parameters, which pushes the generated codes toward motions that are not only likely as symbols but also correct as hand movement.

What the paper changes

What the paper changes

The paper changes the interface between hand motion and language modeling. Instead of treating hand trajectories as raw continuous coordinates or as a single flat code stream, CLUTCH uses structured discrete motion codes and then checks those codes against decoded hand shape and pose.

The hidden quantity

Motion code fidelity after compression

measured quantity  =  motion code fidelity (how much of the original hand articulation survives after the tokenizer compresses it into discrete codes)

The hidden quantity is whether the code sequence preserves the motion features that matter for action meaning: finger ordering, grasp closure, wrist orientation, and timing. If those details are blurred during tokenization, the language model cannot recover them later no matter how good its sequence modeling is.

SHIFT improves this fidelity by decomposing motion into hand parts and modalities. That means the tokenizer does not have to spend one shared codebook equally on every motion aspect. Thumb articulation, palm movement, and the coordinated behavior of other fingers can receive separate representational capacity. The later decoded-motion refinement stage then checks whether the decoded motion still respects the original hand variables.

Why it works

Why the data and model changes fit together

The dataset and tokenizer solve complementary bottlenecks. In-the-wild video broadens the action and context coverage, which exposes the model to the variety of hand behavior it must eventually generate or describe. But that broader data only helps if the representation can store the relevant motion detail. SHIFT provides that representation by turning continuous trajectories into discrete codes that still preserve local hand structure.

The language model then gains a practical sequence interface, but sequence likelihood alone is not enough. A code string can be probable while still decoding to awkward joint motion. Decoded-motion refinement closes that gap because it computes loss after decoding into hand variables. This means the model is trained not only to emit plausible symbol sequences, but also to emit sequences whose decoded joint behavior matches real hand motion under the training data.

Math after the picture

The language-plus-shape objective

First in words:

Training combines a sequence prediction loss on motion codes with a reconstruction loss on decoded hand variables, so the model is rewarded for both symbolic correctness and decoded motion correctness.

Then the compact form:

L_total = L_code + lambda_geo * L_geo

Every symbol:

L_codeloss for predicting the correct discrete motion code sequence
L_geoloss on decoded continuous hand parameters such as joint positions or angles
lambda_geoweight that sets how strongly decoded motion fidelity influences training
A tiny worked example
Suppose one generated motion sequence has L_code = 0.30 because most codes are predicted correctly.
After decoding, the joint reconstruction loss is L_geo = 0.25 because the thumb and index finger still deviate from the target path.
If lambda_geo = 2, then the total is 0.30 + 2 * 0.25 = 0.80.
A different sequence with slightly worse code loss but much better decoded hand shape can therefore win, which matters because the final user sees the hand motion, not the code sequence.

The geometric term changes what counts as a good code prediction: a sequence is good only if it decodes into the right hand behavior.

What can go wrong

What can go wrong

The tracker or annotations are noisy. If the recovered 3D hand motion or text labels are wrong, the tokenizer and language model will faithfully learn those errors because the pipeline depends on the quality of the automatically built dataset.
The tokenizer discards rare finger configurations. A codebook trained mostly on common grasps may compress unusual articulations poorly, which then limits the language model's ability to generate uncommon but valid motions.
Sequence quality and decoded shape pull apart. If the decoded-motion term is too weak, the model can prefer code sequences that look likely under the language model but decode into awkward motion. If it is too strong, code prediction can become unstable because the model overfits local reconstruction details.
Done right. The method is strongest when dataset construction is reliable, the tokenizer preserves part-specific motion detail, and the decoded-motion weight is tuned so decoded motion quality constrains the language model without overwhelming it.
What a runnable demo should prove

What a runnable demo should prove

Use a subset of egocentric hand-action videos with tracked 3D hand sequences and text labels. Train one text-to-motion baseline with a flat tokenizer and one CLUTCH-style model with part-aware SHIFT codes plus decoded-motion refinement. Evaluate both on text-to-motion generation and motion-to-text captioning, and render decoded hand sequences for qualitative inspection.

The demo should show two linked improvements: richer action coverage from in-the-wild data and more faithful decoded hand articulation from the structured codes plus decoded-motion refinement. The rendered sequences should make clear whether the generated finger behavior matches the text condition.
