Empowering Small VLMs to Think with Dynamic Memorization and Exploration

Train a small vision-language model by switching between copying known good reasoning traces and exploring new ones, so each update matches what the model can handle at that moment.

Paper explainersAll themesMultimodal

Small vision-language models are useful on narrow tasks because they are cheaper to adapt and easier to run inside a company. The problem is that standard training recipes for reasoning ask too much from them. If you only use supervised fine-tuning, the model copies the training traces word for word and learns surface patterns instead of the decision process behind them. If you only use reinforcement learning with a checkable reward, the model has to search too broadly, so training becomes unstable and the model collapses onto weak behaviors. DyME fixes this by choosing, at each optimization step, whether the model should memorize a trusted trace or explore for a better one. That choice matters because a small model needs different kinds of updates at different moments: sometimes it needs a clear target, and sometimes it needs room to discover a better path. The paper also adds visual supervision that checks whether the reasoning stays tied to the image, so the model does not drift into text-only guesses, because answers that ignore the image can still look plausible in narrow domains even when the visual evidence says otherwise.

Zero assumption version

Small models fail when training asks for too much at once

A small vision-language model has to do two jobs in sequence. First, it must read the image correctly. Second, it must turn what it read into a reasoning trace and a final answer. Standard supervised fine-tuning gives the model a full target trace and tells it to copy that trace. This is useful early because the target shows the exact wording and order of steps, but it also creates a failure mode: the model can memorize the trace pattern without understanding when each step is justified by the image.

Pure reinforcement learning with a verifiable reward has the opposite failure mode. It does not force a specific trace, so the model is free to search, but that freedom is expensive for a small model because the model must evaluate many weak candidates before it finds a useful one. The model samples many bad traces, gets noisy feedback, and can end up with almost no useful separation between good and bad actions. The paper calls this advantage collapse. In plain terms, the reward signal stops telling the model which move was better, because most sampled moves are poor and look similarly poor to the learning rule.

The paper's move. Do not lock training into one mode. Choose between supervised copying and reward-driven exploration on each step, because the right update depends on how reliable the current model behavior is.

The algorithm as a flow

What it actually does

Start from an image and task prompt

Feed the small model an image and a domain-specific question or instruction.

Generate candidate reasoning

Let the model produce a chain of intermediate steps and a final answer.

Score the candidate

Use a verifiable reward and visual supervision to check whether the answer is right and whether the reasoning stays grounded in the image.

Choose the update mode

If the model needs a stable target, apply supervised fine-tuning on a trusted trace. If the model can benefit from search, apply reinforcement learning on sampled traces.

Refine visual evidence

Use the checker and refiner to inject clearer image-grounded guidance, so later reasoning steps are based on the right visual facts.

What the paper changes

What the paper changes

DyME changes the training schedule. Instead of fixing one objective for the whole run, it decides at each step whether the model should copy a known good reasoning path or search for a better one. This matters because the model's weakness changes during training: early on it needs stable demonstrations, while later it can exploit reward feedback if the search space is not too noisy.

The hidden quantity

The hidden quantity: update usefulness

measured quantity  =  How much a training step teaches the model instead of confusing it

The paper is managing a quantity that is not directly visible in the final accuracy: whether a specific update gives a useful learning signal. A supervised step is useful when the provided trace is trustworthy and close enough to the model's current ability that copying it will teach a real pattern. A reinforcement step is useful when sampled alternatives differ enough in reward that the model can tell which actions deserve higher probability.

DyME tries to keep update usefulness high by switching modes before a bad regime dominates. If supervised copying starts to push the model toward trace memorization, exploration becomes more useful because it tests whether the model can solve the task with its own decisions. If reward-based search becomes noisy, supervised copying becomes more useful because it restores a clear target.

Why it works

Why switching modes helps a small model

The core issue is that supervised fine-tuning and reinforcement learning fail for opposite reasons. Supervised fine-tuning gives low-variance targets, because every written step in the trace is specified, but it can reward exact wording even when the wording is accidental rather than necessary. Reinforcement learning can discover new solutions, because it only cares about rewarded outcomes, but it raises the search burden. A small model cannot carry both burdens at full strength all the time.

DyME works by matching the update type to the current learning problem. When the model has no reliable reasoning pattern yet, copying a good trace is useful because it reduces uncertainty about which visual facts and intermediate steps should appear. Once the model can produce partially correct traces, reward-based exploration becomes useful because it lets the model depart from rigid demonstrations and keep only the choices that improve the verified outcome. The alternation matters because each mode corrects the other mode's failure. Supervised steps prevent exploration from drifting into noise, while exploration steps prevent supervised learning from freezing the model into scripted traces.

The visual checker and refiner are important for the same reason. A small model can achieve a correct answer for the wrong reason if the domain has regular text patterns. The checker measures whether the reasoning is supported by the image, and the refiner injects missing visual detail when it is not. That extra supervision matters because the update should reward the route that used visual evidence, not a route that matched the answer by exploiting dataset regularities.

Math after the picture

The training equation

First in words:

The total objective mixes a supervised loss and a reward-driven loss, with a gate that turns one branch on for each step.

Then the compact form:

L = m_t * L_sft + (1 - m_t) * L_rl + L_visual

Every symbol:

Lthe full training loss
m_tthe step-level switch; 1 means use supervised fine-tuning on this step, 0 means use reinforcement learning
L_sftthe supervised loss that rewards matching a trusted reasoning trace
L_rlthe reinforcement loss that raises the probability of rewarded sampled traces
L_visualthe extra loss from the visual checker and refiner, which pushes reasoning to stay grounded in the image
A tiny worked example
Suppose the model is early in training and its sampled traces are mostly poor.
Set the switch to supervised mode for this step, so the loss uses the trusted trace and ignores the reward branch.
Later, suppose the model now produces several nearly correct traces with different final answers.
Set the switch to reinforcement mode for this step, because the reward can now tell which sampled decisions were better.
The method gains from the switch because each step uses the branch that carries the clearer teaching signal.

The point of the equation is not the exact algebra. The point is that only one main learning mode drives a given step, so the update is not split between conflicting objectives.

What can go wrong

What can go wrong

The mode switch is mistimed. If the system chooses reinforcement learning before the model can produce informative samples, the reward branch becomes noisy because almost every trace is bad. If it stays in supervised mode for too long, the model copies traces instead of learning when they apply.
The visual checker is weak. If the checker cannot tell whether a step is image-grounded, text-only reasoning may still receive reward because the final answer happens to be correct. That undermines the whole point of adding visual supervision.
Trusted traces are low quality. Supervised steps only help when the target traces express valid visual reasoning. If they contain unnecessary wording or wrong visual assumptions, the model memorizes those defects because the loss treats them as ground truth.
Done right. Use strong traces, reliable reward checks, and a switch rule that tracks whether exploration is informative. Then each branch teaches the model something the other branch cannot teach at that moment.
What a runnable demo should prove

What a runnable demo should prove

Train the same small vision-language model on a narrow image task under three conditions: only supervised fine-tuning, only reinforcement learning with a verifiable reward, and DyME with the visual checker and refiner. Log, for each training step, which mode DyME selected, how often sampled traces earn reward, and how often the reasoning cites the correct image regions or attributes. The demo should show that DyME spends early training in the stable supervised regime, shifts toward exploration once rewards become informative, and keeps more reasoning tied to the image than either single-mode baseline.
