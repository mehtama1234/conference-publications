VADv2: Probabilistic Planning for Autonomous Driving

Instead of making the car pick one fixed move, learn to produce many possible good moves and let the car pick from a soft crowd of options.

Paper explainersAll themesRobotics & Control

Real driving is uncertain — the same scene can be safely handled many different ways. Today's learning-based autopilots learn one fixed move per situation, then crash when the world surprises them. VADv2 builds a different kind of autopilot: one that learns to say not what the car should do, but what family of moves are reasonable right now, ranked by probability. The car picks from this crowd.

Zero assumption version

Why fixed moves break in the real world

Today's self-driving networks watch a camera feed and immediately output a single action: steer 5 degrees, throttle 30%. They are trained to copy what humans do. But human driving has a secret: the same camera view can be handled multiple ways, each one safe. A car at a red light can brake hard, brake gently, or coast to a stop. A person changing lanes can do it smoothly over 5 seconds or crisply over 2. The network sees the camera and has to guess one move.

When the network picks the wrong one from that invisible crowd, it crashes. A frozen road might make coasting too risky — the network needed to brake harder. A crowded highway might make a lane change too risky — the network should have waited. The network does not know what it does not know, so it cannot admit uncertainty.

In one sentence. VADv2 outputs not one move, but a ranked list of reasonable moves with probabilities, so the car can adapt when the world is ambiguous.

The algorithm as a flow

What it actually does

Discretize the action space

Slice all possible steering angles and throttle values into a large grid, like a filing cabinet of moves.

Tokenize each move

Label each cell in the grid with a token (a short code), so the network learns to talk about moves by token, not raw numbers.

Train the network to rank tokens

Given a camera frame, output a probability for each token. High probability tokens are safer bets in this situation.

Learn from human drives

Watch thousands of human drivers and nudge the network so it assigns high probability to the moves humans actually made.

The car picks one token

At test time, sample a token from the probabilities or greedily pick the one with highest ranking, then execute the corresponding move.

What the paper changes

The one thing VADv2 changes

Instead of outputting a single action (angle, throttle), the network outputs a probability score for each token in a large vocabulary of possible moves. The object is the output itself: from one number (the action) to many numbers (one probability per token), ranked by likelihood.

the object it moves  =  network output shape
The hidden quantity

The hidden quantity: move probability

measured quantity  =  probability of each action token

The hidden quantity is the likelihood the network assigns to each possible move. It is hidden because humans do not explicitly label moves as safe or unsafe — they just do them. VADv2 infers these probabilities by watching which moves humans actually chose in each situation.

The paper estimates it by treating the human demonstrations as ground truth: if a human chose token A in this scene, the network should output high probability for token A. Training adjusts the network's internal weights so that its output probabilities match the frequencies of human choices.

Why it works

Why probabilistic actions work

The core insight is that human driving is inherently multi-modal — many moves are correct for the same scene. A fixed-move network must pick one, gambling that it guessed right. VADv2 sidesteps that gamble by outputting probabilities for all reasonable moves.

This works because probabilities encode uncertainty. If the network sees an ambiguous scene, it will assign similar high probabilities to several tokens instead of locking onto one. If the scene is clear, the network will spike one token's probability near 100%. The car can then decide at runtime: on a crowded highway with high uncertainty, sample from the top few choices; on an empty road with high confidence, pick greedily. The probability ranking is more honest about what the network actually knows.

Secondly, tokenizing the continuous action space into discrete moves makes the learning problem simpler. Instead of predicting a real number (which must hit the exact right value), the network ranks a list of options, and small shifts in what the camera sees do not flip which token the network picks — because there is still a gap between token A and token B. This trades some precision (you can only pick from the predefined grid) for stability (the network does not scramble when the input shifts slightly).

The probabilistic ranking equation

First in words:

Probability of token k given scene s equals the exponential of the score for token k, divided by the sum of exponentials for all tokens. This is called softmax — it turns raw scores into fractions that sum to one.

Then the compact form:

P(token_k | scene) = exp(score_k) / sum_j exp(score_j)

Every symbol:

token_kone possible move (steering + throttle) from the vocabulary
scenethe camera frame and any other input data
score_kthe network's internal raw ranking for token k (higher means more likely)
expexponential function (e to the power of the input)
P(token_k | scene)the final probability: how confident the network is in token k for this scene
A tiny worked example
Suppose the network computes scores for three tokens: token A scores 2.0, token B scores 0.5, token C scores 0.0.
Exponentials: exp(2.0) = 7.39, exp(0.5) = 1.65, exp(0.0) = 1.0.
Sum = 7.39 + 1.65 + 1.0 = 10.04.
Probabilities: A gets 7.39 / 10.04 = 0.736 (73.6%), B gets 1.65 / 10.04 = 0.164 (16.4%), C gets 1.0 / 10.04 = 0.100 (10.0%).
The raw scores differed by only 2.0 units, but this probability formula spreads them into decisive rankings. Small gaps in the score become big gaps in the probability output.

This probability formula converts rankings into scores where one token usually dominates but others remain plausible, matching how human driving often has one best move and a few safe backups.

What can go wrong

What can go wrong

Discretization throws away precision. If the action grid is too coarse (far apart moves), the car cannot make fine adjustments. Too fine, and the network never learns any single token well (each move is too rare in training data).
Probability does not equal safety. High probability just means the network thinks humans would do it. If training data contains human mistakes (near-misses, bad habits), the network learns to replicate those mistakes.
Sampling instead of greedy can backfire. If the car randomly samples from the probabilities to handle uncertainty, it might occasionally pick a low-probability move that is actually dangerous, even though it was probably not human behavior.
Done right. Set the discretization coarse enough to be learnable but fine enough for smooth control. Train on clean human data. Use sampling only for exploration during learning, not at test time — at test time, greedily pick the highest-probability token.
What a runnable demo should prove

What a runnable demo should prove

Build a toy driving scenario: a 2D top-down car, a few obstacles, and a single goal. Train two networks on the same human demonstrations: one that outputs a single action, one that outputs probabilities over a small vocabulary of moves (e.g., accelerate straight, accelerate left 5 degrees, accelerate right 5 degrees, brake, idle). Then test both on scenes slightly different from training (e.g., an obstacle in a new place, an ice patch that slows the car). Count how many times each network recovers safely without crashing.

success_rate = (runs_without_crash / total_runs) × 100%

The probabilistic network should recover from surprises more often, because it hedged its bets instead of committing to one move.
