Learning from Noisy Preferences: Semi-Supervised Direct Preference Optimization

Filter messy human preference labels into clean and noisy subsets, train on clean data first, then use that model to give honest labels to the noisy data.

Paper explainersAll themesGenerative Models & Diffusion

When humans rate image pairs, they judge many things at once: does it look good, does it have fine detail, does it match what you asked for. But existing preference datasets just say winner or loser. A single image might be prettier but blurry, while another is detailed but ugly, yet one is marked as winner anyway. This creates conflicting signals that pull the model in opposite directions. Semi-DPO untangles this by first finding agreement on clean labels, training on those, then using that trained model to fix the noisy labels.

Zero assumption version

Messy human preference labels pull the model in conflicting directions

A diffusion model (a neural network that generates images by starting with noise and learning to remove it) gets better when trained on human preferences. A human rates pairs of generated images, marking which is better, because the model learns to imitate the patterns that humans prefer. But humans judge many dimensions at once: whether the image looks realistic, has sharp details, follows the prompt, or feels aesthetically pleasing.

When a dataset compresses all those dimensions into a single winner-or-loser label, the result is noise. One image is prettier but missing details. Another is detailed but slightly off-topic. Yet one gets marked winner and the other loser, even though the preference is genuinely mixed. The model trained on such labels gets conflicting nudges: make prettier images here, make detailed images there. These contradictions slow learning and trap the model away from good solutions.

In one sentence. Semi-DPO splits preference labels into clear agreement and conflicting ones, trains clean on agreement first, then auto-fixes the conflicting labels using the trained model.

The algorithm as a flow

What it actually does

Measure agreement

For each image pair, compute how much the human ratings align on all quality dimensions.

Split the data

Mark pairs with clear agreement as clean; pairs with conflicting signals as noisy.

Train on clean

Run standard preference training on the clean subset only; model learns from honest signals.

Label noisy set

The trained model now scores the noisy image pairs; these model-assigned labels replace human noise.

Refine iteratively

Retrain the model on both clean and newly-labeled noisy data; repeat until stable.

What the paper changes

The thing the paper changes

The paper replaces the raw human preference labels with a two-stage labeling scheme: clean consensus labels first, then model-generated labels for noisy pairs. This changes the actual training data the diffusion model learns from.

the object it moves  =  preference labels
The hidden quantity

The hidden quantity: label agreement across dimensions

measured quantity  =  preference consensus

Preference consensus is how much human raters agree that one image is better than the other across all the quality dimensions they evaluate. If all judges say image A is prettier, more detailed, and on-topic, the consensus is high, because all raters are pointing the model in the same direction. If some say A is prettier but others prefer B's details, the consensus is low, because different raters want contradictory things.

Semi-DPO measures consensus by checking whether the same pair gets consistent rank ordering across all quality aspects. The paper uses this to split the dataset: high consensus pairs become the clean training set, low consensus pairs become noisy ones to be relabeled by the model.

Why it works

Why it works: two-stage training breaks the conflicting-signal trap

Conflicting labels create a training trap: the model pulls toward contradictory targets, unable to settle. The first move is to train only on pairs where humans genuinely agree. The model then learns a coherent understanding of good images without the noise.

In the second stage, this trained model acts as a judge. When it looks at a noisy pair (one that humans disagreed on), it assigns a label based on its learned understanding. These model-generated labels are more honest than the original messy human ones, because they come from a model that learned only from clean agreement. When the model retrains on both clean and newly-labeled noisy pairs, it reinforces what it learned but now on a larger dataset.

The reason this works mechanically: a model trained on honest signals learns a stable direction of improvement. When it then labels the conflicting pairs, those labels point in the same direction, breaking the tug-of-war. The model can now move forward instead of oscillating.

Math after the picture

The core idea as an equation

First in words:

loss equals the preference ranking loss on the clean pairs plus a regularization term that pulls the model's labels on noisy pairs toward confidence in its own predictions

Then the compact form:

L = L_clean(theta) + lambda * L_pseudo(theta, y_model)

Every symbol:

Ltotal loss the model minimizes
L_clean(theta)ranking loss on the high-agreement subset; theta is the model weights
L_pseudo(theta, y_model)loss on noisy pairs with model-generated labels y_model
lambdahow much to weight the noisy-pair learning relative to clean learning
y_modelthe labels the trained model assigns to the low-agreement pairs
A tiny worked example
Suppose the clean subset has loss 0.15 and the noisy subset has model-loss 0.22.
Set lambda = 0.8 (rely more on clean learning, less on noisy).
Total loss = 0.15 + 0.8 * 0.22 = 0.15 + 0.176 = 0.326.
If lambda = 0.1 (ignore noisy), total = 0.15 + 0.01 = 0.16 (less learning from data).
If lambda = 2.0 (over-trust noisy), total = 0.15 + 0.44 = 0.59 (model might revert to old errors).
The sweet spot balances learning new data without undoing what the model learned from clean pairs.

The clean loss shapes the core learning; the pseudo-labeled loss extends it gently. Lambda controls how much to trust the model's own labels on disagreement.

What can go wrong

What can go wrong

Filtering away too much data. If the consensus threshold is set too high, almost all pairs are marked noisy, leaving a tiny clean set. The model trains on too little data and learns slowly. If the threshold is too low, too many conflicting pairs sneak into clean, and the first training round fails to learn a coherent direction.
Model overfits its own mistakes early. If the model trained on clean data has a blind spot (e.g. always generates ugly colors), it will stamp that same mistake onto the noisy labels. Then retraining reinforces the error instead of fixing it.
Lambda imbalance. If lambda is too high, the model over-trusts its own noisy labels and forgets what it learned from clean data. If lambda is too low, the pseudo-labels barely contribute and most of the noisy data is wasted.
Done right. Set consensus threshold by inspection of the data. Train the clean model until it stabilizes. Use a moderate lambda so the second stage extends, not overrides, the first. Validate the model's pseudo-labels against a held-out human-labeled set to catch early overfitting.
What a runnable demo should prove

What a runnable demo should prove

Build a simple diffusion model (or use a toy image generator) and a dataset of 200 image pairs, each rated on two dimensions (e.g. realism and detail). Inject noise into 100 of the pairs by flipping one dimension's rating. Run standard preference learning on all 200 pairs, and measure alignment with each dimension. Then run Semi-DPO: filter the clean 100 pairs, train the model on clean, use it to relabel the noisy 100, retrain on all 200. Compare the two models' learned preferences.

improvement = (alignment_semi_dpo - alignment_baseline) / alignment_baseline * 100 percent

The demo must show that Semi-DPO's two-stage labeling produces a model that aligns better with all dimensions at once, because training first on clean agreement then extending with auto-corrected noisy data lets the model stabilize in a direction that satisfies all dimensions, while the single-stage model gets pulled in conflicting directions and aligns with none because it never escapes the tug-of-war.
