Vision Language Models Cannot Reason About Physical Transformation

The paper builds a benchmark for conservation under physical transformation and finds that current vision language models do not maintain stable internal representations of quantities that should stay unchanged.

Paper explainersAll themesMultimodal

A model that understands the physical world should do more than name visible objects. It should also track which properties stay constant when those objects move, split, merge, or change viewpoint. This paper studies that ability through conservation: whether a quantity such as count, mass-related extent, occupied volume, or other preserved property remains the same after a transformation. The authors build ConservationBench, a large benchmark of paired conserving and non-conserving scenarios, then test 112 vision language models with more than twenty-three thousand questions. The result is stark. Accuracy stays near chance, and attempts to improve conservation performance often hurt control tasks because pushing the model toward the answer conserved also increases mistakes on cases designed to require changed. Further analysis shows that text alone pushes models toward an invariance prior, meaning a bias to answer that things stay the same, yet adding the visual evidence often makes performance worse. The paper argues that current models do not form transformation-invariant representations stable enough for physical reasoning.

Zero assumption version

Recognizing scenes is not the same as tracking conserved properties

Physical reasoning under transformation requires a model to compare two states of a scene and decide which quantities should remain unchanged. For example, if an object is cut into pieces but no material is removed, certain properties should stay constant while others may change. A system can answer these questions only if it represents the right quantities and carries them across the transformation.

Many vision language models look strong on perception-heavy benchmarks, but those tasks often reward naming, counting in a single frame, or following language cues. They do not force the model to preserve a quantity through change. ConservationBench isolates that requirement by contrasting conserving cases with non-conserving controls, making it possible to test whether the model truly tracks the invariant quantity rather than relying on verbal shortcuts.

The problem: Current vision language benchmarks often test recognition and description, not whether a model preserves the right physical quantity across a transformation.

Evaluate whether the model judges the target quantity as preserved or changed across the two states.

Run broad model coverage

Compare against controls

Measure whether gains on conservation questions come with losses on non-conserving controls, which reveals whether the model is just leaning harder on a generic invariance bias.

Probe textual and visual priors

Separate text-only from image-based performance to see whether the visual input actually helps the model reason about physical transformation, because a capable visual model should use the images to distinguish preserving changes from violating ones.

What the paper changes

What the paper changes

This is a measurement paper. It changes the benchmark, not the model. The main contribution is a targeted evaluation setup that isolates conservation under transformation and distinguishes genuine invariance reasoning from response bias.

The hidden quantity

Hidden quantity: invariance representation

measured quantity  =  invariance representation

The hidden quantity is whether the model internally carries a stable description of the property that should survive the transformation. A correct answer requires more than seeing two images. The model must identify the relevant quantity, encode it in a form that can be compared across time, and ignore changes that are irrelevant to that quantity.

The paper's evidence suggests that this representation is weak or absent. If it were strong, adding images would help the model separate conserving from non-conserving cases because the visual changes would reveal whether the target quantity was preserved. Instead, text alone often encourages the default answer that the quantity stays the same, and visual content does not consistently correct or refine that bias.

Why it works

Why the failures matter

The benchmark is diagnostic because conservation questions require a specific causal chain. The model must parse the initial scene, map the transformation, preserve the relevant quantity, and compare the post-transformation state against that preserved quantity. Failure at any stage produces the wrong answer.

The observed pattern suggests that models often rely on coarse verbal heuristics instead. When the prompt describes a transformation that commonly preserves something, the model can default toward invariance without actually representing the quantity in the image. Control tasks expose that shortcut because raising the tendency to answer conserved also hurts cases where the quantity should change.

This matters for embodied or scientific use because many real decisions depend on invariant structure across time, not only on frame-by-frame recognition. A system that cannot hold such structure steady will struggle whenever correct action depends on what stayed constant through change.

Conservation test logic

First in words:

A conserving case is correct only when the property extracted from the first state matches the same property extracted from the second state after accounting for the transformation.

Then the compact form:

answer is conserved when property before transformation equals property after transformation for the target quantity

Every symbol:

property before transformationthe value of the tested physical quantity in the initial scene
property after transformationthe value of the same quantity in the final scene
target quantitythe specific conserved or non-conserved property being tested
answerthe model's judgment of conserved versus changed
A tiny worked example
A clay shape is shown before and after being reshaped.
The benchmark asks about a quantity that should be preserved under reshaping.
The correct reasoning is to track that quantity in the first scene, then verify that reshaping alone does not alter it in the second scene.
A model that focuses only on changed appearance may answer changed.
A model with a generic invariance bias may answer conserved even on a matched control where material was removed.
Only a model that represents the right quantity across both scenes answers both cases correctly.

The benchmark is informative because it uses matched controls, so success requires identifying the right invariant rather than repeating the same response pattern every time.

What can go wrong

What can go wrong

Models may answer from text priors. If the prompt language suggests a common classroom conservation pattern, the system may choose conserved without grounding that answer in the visual evidence.
Visual detail can distract from the target quantity. Large changes in shape, arrangement, or viewpoint can dominate the representation even when the tested quantity should stay constant.
Near-chance averages can hide asymmetric errors. A model may do well on one property by guessing conserved often and fail badly on matched controls, so aggregate accuracy alone is not enough.
Done right: Evaluate conserving and non-conserving pairs together, compare text-only against multimodal performance, and inspect whether visual input genuinely increases separation between the two cases.
What a runnable demo should prove

What a runnable demo should prove

Build a small interactive benchmark with paired before-and-after scenes and matched control variants. For each item, let the user toggle between text-only and image-plus-text evaluation and compare the model's answers.

The demo should make three patterns visible: whether the model has a default conserved bias, whether images correct that bias or worsen it, and whether a model that appears reasonable on one case can still fail the matched control. That is the core claim of the paper.

control_separation = accuracy on conserving cases minus error spillover onto non-conserving controls

A convincing demo shows that current vision language models are not failing only on tricky wording. They are failing to keep the relevant physical quantity stable across transformation.
