Memory-Statistics Tradeoff in Continual Learning

Storing curvature information prevents the model from forgetting old tasks, but using more stored vectors reduces memory cost at the price of higher error.

Paper explainersAll themesLearning Theory

When a model learns two tasks in sequence, forgetting the first while learning the second is a classic problem. This paper proves that you can prevent forgetting by remembering how sensitive the first task's solution was to each weight. But storing all sensitivities costs too much memory. If you store fewer key sensitivities, fewer weights are protected so more weights drift during task 2, raising its error; if you store many sensitivities, more weights are protected so both tasks have low error but memory use is higher. The paper proves this tradeoff between memory size and error is unavoidable.

Zero assumption version

Why models forget when they learn new tasks

Imagine a model learns to recognize cats from pictures, then you ask it to recognize dogs. If you just retrain it on dog pictures, the weights will shift to fit dogs well, and it will stop recognizing cats — it has forgotten. This is catastrophic forgetting.

A beginner might try: learn on cats, then learn on dogs while minimizing how much the weights move. But just penalizing movement is crude. Some weights matter more for cats than others. If you move an unimportant weight even far, cats still work fine. But moving a critical weight even a tiny bit breaks everything. A uniform penalty treats them the same, so you either hold back all movement (error on dogs rises) or let important weights shift (cats break).

The core move. Store which weights mattered for task 1, then apply stronger penalties to moving those specific weights because moving them breaks task 1. Unimportant weights get weaker penalties so they shift freely to solve task 2, which does not depend on them.

The algorithm as a flow

What it actually does

Learn first task

Train on task 1 data, find the best weights.

Measure sensitivity

For each weight, compute how much error rises if you nudge it — this sensitivity is the curvature or importance score.

Store compressed importance

You cannot store all sensitivities (too much memory). Keep only the top k most important ones by storing key eigenvectors of the covariance matrix.

Learn second task with smart barrier

Train on task 2. Penalize moving weights task 1 depended on because moving them breaks task 1; do not penalize weights task 1 did not use because moving them does not harm task 1.

Result proves the tradeoff

More stored vectors means error on both tasks is lower. Fewer vectors means task 2 error might spike, but memory use is smaller.

What the paper changes

What the paper changes

Instead of applying a uniform penalty to all weight movements, the paper tailors the penalty strength to each weight's importance for the previous task. The penalty is stored implicitly: you save the top k key directions (eigenvectors) from task 1's data spread, which capture which weights mattered most.

the object it moves  =  regularization matrix (curvature-aware penalty)
The hidden quantity

The hidden quantity: Importance or curvature

measured quantity  =  Importance or curvature (sensitivity of error to weight nudges)

The paper measures which weights matter most for the first task using how steeply the error changes when you nudge each weight — if error rises sharply, the weight is critical; if it barely changes, the weight does not matter. Weights with steep error curves are critical — a small nudge breaks everything. Weights with flat error curves are expendable — you can move them without harm.

The algorithm estimates this by computing the top k key directions from task 1's data spread. These directions capture which weight adjustments mattered most during learning task 1. When learning task 2, the algorithm applies a penalty proportional to this importance: steep-error weights get a strong penalty (stays put), flat-error weights get weak penalty (free to move).

Why it works

Why the curvature-aware penalty works

A weight that was critical for task 1 sits at the bottom of a sharp valley — the error rises steeply if you nudge it. When you start learning task 2, if the new task wants to move that weight, the penalty kicks in hard because moving it makes task 1 error rise fast. The model learns task 2 while mostly leaving the critical weights alone, so task 1 performance stays intact.

A weight that was not important for task 1 sits on a flat plain — error barely changes if you nudge it. When learning task 2, the penalty is weak because moving that weight does not break task 1. Since moving it does not harm task 1, the model can use it to solve task 2. The mechanism: asymmetric importance means you can protect load-bearing weights with a strong barrier and free the non-critical ones to shift. A strong barrier on unimportant weights (uniform approach) would trap the model in task 1's solution and break task 2, while no barrier at all (naive retraining) lets critical weights drift and breaks task 1. Asymmetric barriers protect what matters and free what does not.

Math after the picture

The regularized learning step

First in words:

penalty equals importance times how far weight moved squared

Then the compact form:

loss = (squared error on task 2) + (sum over all weights: importance_i times (new_weight_i minus old_weight_i) squared)

Every symbol:

squared error on task 2how badly the new task fits
importance_icurvature or sensitivity of weight i during task 1
new_weight_iweight value after learning task 2
old_weight_iweight value after learning task 1
sum over all weightsadd up the penalty for each weight
A tiny worked example
Task 1 found: weight w1 has importance 8.0 (critical), weight w2 has importance 0.1 (not critical).
When learning task 2, both weights move by 0.5 from their task 1 values.
Penalty for w1: 8.0 times (0.5 squared) = 8.0 times 0.25 = 2.0.
Penalty for w2: 0.1 times (0.5 squared) = 0.1 times 0.25 = 0.025.
Same movement, but w1 is punished 80 times harder. Training will keep w1 nearly fixed but let w2 move, so task 1 is protected and task 2 has flexibility.

The penalty barrier is stronger where the first task's solution was sensitive because moving those weights breaks the old task. Weak barriers on unimportant weights let task 2 adjust them freely.

What can go wrong

What can go wrong

Not enough stored vectors. If k (number of stored eigenvectors) is too small, the barrier misses some critical weights. Those weights move during task 2 and task 1 error rises.
Misidentified importance. If the method guesses wrong about which weights are important (e.g. the covariance matrix does not reflect true Hessian curvature), protection is wasted on unimportant weights and critical ones are left exposed.
Task 2 constrained too much. If the penalty is too strong on all weights (even unimportant ones), task 2 cannot learn well. The barrier traps the model in task 1's solution.
Done right. Choose k based on the tradeoff you accept: large k stores more curvature, uses more memory, but both tasks have low error. Small k uses little memory but task 2 error rises. The paper proves this tradeoff is fundamental.
What a runnable demo should prove

What a runnable demo should prove

Train a simple linear regression model on synthetic task 1 (predicting y from a 10-dimensional feature x), then on task 2 (different y, same x distribution). First, show that naive retraining (ignoring task 1) makes task 1 error spike because weights shift to fit task 2 and task 1 breaks. Then, show that uniform penalty improves task 1 error but task 2 error rises because all weights are held back equally and task 2 cannot learn. Finally, show that importance-weighted penalty (using top k directions from task 1) keeps both task 1 and task 2 errors low because critical weights have strong barriers and unimportant weights are free to shift. Repeat with k equal to 2, 4, 8 to show how storing more key directions improves both tasks because the barrier gets stronger.

forgetting = (task 1 error after task 2) minus (task 1 error before task 2); task 2 error = final error on task 2 data

The demo must show that curvature-aware regularization with the right k achieves what joint learning can do, despite learning sequentially and storing only k key directions.
