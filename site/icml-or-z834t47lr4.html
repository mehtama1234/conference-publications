Expert-level Leaf Cell Layout Generation via Preference-Optimized LLM

Generate circuit layout scripts that approach or exceed expert designs by learning what good layouts look like and then preferring scripts whose outputs match those high-quality designs.

Paper explainersAll themesAgents & Tool Use

This paper targets leaf cell layout generation for integrated circuits. The challenge is unusual: expert layouts exist, but the scripts that produced them do not. That means the training target is visible in final form while the action sequence that created it is missing. GenLeaf bridges that gap with three steps: learn a representation that scores layout similarity in performance-aware ways, use search to create candidate script-layout pairs, and then train and refine a language model to prefer scripts whose resulting layouts resemble strong expert designs.

Zero assumption version

Why layout generation is hard without expert scripts

Leaf cell layouts matter because they are reused many times inside larger circuit designs. Small improvements in these cells can therefore affect the power, speed, and area of a much larger chip.

The data problem is severe. Experts can provide final layouts, but they often do not provide the exact scripts that generated those layouts. A model that learns only from final physical shape lacks the action trace that would show how to rebuild the design.

The main move. Use the expert layout as the target signal and create missing script supervision through search, because the final design still tells you which generated scripts are worth preferring.

The algorithm as a flow

What it actually does

Learn a layout scorer.

The system first learns a representation that can compare one layout with another in a way that tracks design quality, because raw visual similarity alone is not enough.

Search for candidate scripts.

A search procedure proposes scripts and keeps the ones that create high-scoring layouts, so expert layouts can indirectly supervise the script space.

Build a script-layout dataset.

Accepted search results become training pairs because they link layout quality back to concrete script choices.

Train the language model.

The model learns to produce scripts that recreate strong layout patterns seen in the derived dataset.

Apply preference optimization.

The model is further tuned to prefer script outputs whose final layouts score better, so it is pushed toward expert-level design quality.

The hidden quantity

The hidden quantity

measured quantity  =  quality of a script as measured by the layout it will produce

The key hidden quantity is the quality of a candidate script before you run it to completion. Two scripts may look equally plausible as text, yet one creates a compact, high-performing layout while the other wastes area or harms timing.

GenLeaf estimates that hidden script quality through the generated layout. The learned scorer and the preference stage matter because they let the model connect text choices with final design consequences, even when expert scripts are unavailable.

Why it works

Why derived script data plus preference learning helps

The search-created dataset solves the missing-supervision problem. Expert layouts alone show the destination, but not the route. Search fills in routes by exploring script candidates and keeping the ones that lead to strong final layouts. This works because the layout scorer turns final physical quality into a signal that can rank script choices.

Preference optimization then improves beyond plain supervised fitting because two scripts may both generate valid layouts while only one saves area or improves timing. A preference signal pushes the model toward the better script because the model is rewarded for choosing text that leads to stronger design outcomes, not merely for reproducing a plausible script string.

Math after the picture

Judge a script by the layout it yields

First in words:

A compact summary is to score a script by the quality of the generated layout relative to a strong expert target, then prefer the script that yields the better final design.

Then the compact form:

script_score(s) = layout_quality(run(s)) - mismatch(run(s), expert_target)

Every symbol:

script_score(s)overall value of one candidate layout script
run(s)the layout produced when script s is executed
layout_quality(...)how good the produced layout is on power, speed, and area related criteria
mismatch(..., expert_target)how far the produced layout is from the desired expert-level layout pattern
A tiny worked example
Script A produces a compact layout with strong timing, so layout quality is 9.
Its mismatch from the expert target is 2, so the total score is 7.
Script B produces a valid but larger layout with weaker timing, so layout quality is 6.
Its mismatch is also 2, so the total score is 4.
Script A is preferred because it reaches a stronger final physical design.

The paper uses a learned scorer, search, and preference tuning rather than this exact line, but the line captures the point: the worth of a script is determined by the layout it creates.

What can go wrong

What can go wrong

The learned scorer may value the wrong layout traits. If the scorer overvalues superficial similarity, search may keep scripts that look close to expert layouts but miss the deeper physical qualities that matter.
Search may explore too narrow a script region. If candidate generation stays near one local pattern, the derived dataset may miss better script families because those alternatives were never tried.
Preference tuning depends on reliable pairwise comparisons. If the system cannot clearly tell which of two layouts is better, the preference signal becomes noisy because later script choices no longer receive a consistent ranking signal.
Done right. The method is strongest when the layout scorer aligns with real design quality, because then every retained script teaches the model something useful about better final layouts.
What a runnable demo should prove

What a runnable demo should prove

Build a small layout domain with a simulator that turns scripts into final layouts and returns power, speed, and area related measurements. Hide the expert scripts but keep several expert final layouts. Compare three systems: direct script generation, generation trained on search-created pairs, and generation further refined by preference optimization.

The demo should show that the latter two systems move closer to expert-level outcomes because they gain supervision from produced layouts rather than from missing script traces alone. It should also show whether preference tuning improves beyond plain fitting by selecting between valid scripts that differ in final physical quality.

A convincing demo must prove that script generation improves when final layout quality is turned into supervision, because expert layouts reveal what good scripts should achieve even when the scripts themselves are missing.
