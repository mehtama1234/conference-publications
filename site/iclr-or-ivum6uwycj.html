Sequential World Models for Multi-Robot Cooperation

Instead of one monster model learning all robots at once, break it into simpler separate models that predict one robot at a time in a fixed order, using each robot's prediction to help the next one plan.

Paper explainersAll themesRobotics & Control

When multiple robots work together, learning their combined behavior is hard: the world model has to track every robot's moves, every other robot's moves, and how they all affect each other at the same time. This paper proposes a simpler approach: give each robot its own separate world model (a predictor), and have them predict the future in sequence—robot 1 predicts first, then robot 2 uses robot 1's prediction, then robot 3 uses both, and so on. This cuts down the complexity each model has to handle and lets robots share their plans with each other in a natural way.

Zero assumption version

Learning how many robots move together is too complex

A robot learns what will happen next by predicting the world. When one robot moves, this is manageable—the model learns that pushing forward makes the robot go forward. But when five robots are all pushing, pulling, passing, and blocking each other, the prediction model has to hold all five robots' positions, all five robots' velocities, and all the ways they touch. This is a huge space to model all at once.

A beginner might try to build one big model that sees all five robots and predicts all five futures together. But that model has to fit the movement of robot 1 plus robot 2 plus robot 3 plus robot 4 plus robot 5 into the same neural network, where the weights compete for space and the model's capacity. The model gets confused, trains slowly, and needs lots of examples to get it right. In the real world, robots have limited computing power on board—they cannot run a heavyweight model fast enough to plan in real time.

The core idea. Build five simple separate models instead of one big one, and have them predict in order: first robot's model looks at robot 1 only and predicts where it will go; second robot's model looks at robot 2, takes robot 1's prediction as input, and predicts where robot 2 will go given that; and so on down the line.

The algorithm as a flow

What it actually does

Encode the robot states

Take the camera images and sensor readings from each robot and shrink them to a compact list of numbers (latent encoding).

Robot 1 predicts alone

Robot 1's model takes its encoded state and outputs: what it predicts it will perceive one step ahead, and what reward it gets.

Pass to robot 2

Robot 2's model gets its own encoded state plus robot 1's predicted state, and predicts its own next state and reward.

Continue the chain

Each robot in order uses all earlier robots' predictions to predict its own next step, building up the full picture step by step.

Use predictions to plan actions

After predicting a few steps ahead, each robot looks at the chain of predictions and chooses actions that lead to high reward.

What the paper changes

What the paper changes: the structure of joint prediction

Instead of one shared world model predicting all robot states in parallel, the paper splits prediction into a sequence. Each robot gets a separate model, and each model predicts only its own future state given its own observation and the predictions from robots that came before it. This is the core structural change.

The hidden quantity

The hidden quantity: modeling complexity per agent

measured quantity  =  local dynamics complexity

The hidden quantity is how much information each model has to keep track of. When one model has to predict all five robots at once, it must hold the positions and velocities of five different bodies, the interactions between each pair, and how the rewards for all five link together. When each model predicts only one robot and gets the previous robots' predictions as input, it only has to learn patterns for one robot's motion. This is much simpler.

The paper measures this by looking at how fast each model trains and how little data it needs to get accurate. A simpler model trains faster and needs fewer examples because there is less to figure out. The paper also counts how many times the models make mistakes in predicting the next state (prediction error) at different time horizons, showing that the sequential approach keeps errors low over longer predictions.

Why it works

Why it works: breaking complexity into smaller chains

When all five robots predict in parallel, each model has to learn interactions between every pair of robots—robot 1 and 2, 1 and 3, 1 and 4, and so on. That is ten pairs to model. When they predict sequentially, robot 1 only learns its own dynamics, robot 2 learns how to move given where robot 1 will be, robot 3 learns its motion given robots 1 and 2's futures, and so on. This is a chain, not a tangle.

Breaking it into a chain has three concrete payoffs. First, each model is smaller and simpler because it only has one robot to track. Simpler models train faster and need fewer examples, because the neural network has fewer patterns to memorize—it only has to learn robot 1's forward/backward motion, not how robot 1 interacts with four other robots whose moves are all changing. Second, when robot 2 gets robot 1's prediction as an input, it is not guessing what robot 1 will do—it knows. This lets robot 2 plan intelligently, moving out of the way if robot 1 is coming its way, or cooperating if they are meant to work together. Third, the ordering creates a clear flow of information: robot 1 commits to a move, robot 2 responds to that, robot 3 responds to both, and so on. This is more like how a team actually works—the first person moves, the others adapt.

The paper also adds a communication cache: if the messages between robots drop out (packet loss), each robot can use stored old messages instead of waiting. And it includes an early-stopping heuristic: once the action plan stops changing much from one iteration to the next, stop planning and just go execute. Both keep the robot responsive and working well even when things do not go perfectly.

The equation: predicting one agent at a time

First in words:

For each agent in sequence, predict the next observation and reward conditioned on its own encoded state and the predictions from all prior agents.

Then the compact form:

o_i(t+1), r_i(t+1) = f_i(z_i(t), o_{i-1}(t+1), ..., o_1(t+1)) where f_i is agent i's dynamics model, z_i is agent i's encoded state, and o_j(t+1) are prior agents' predictions.

Every symbol:

o_i(t+1)agent i's predicted observation one step ahead
r_i(t+1)agent i's predicted reward one step ahead
f_iagent i's dynamics model (a neural network)
z_i(t)agent i's current state compressed to a list of numbers
o_{i-1}(t+1)agent i minus one's predicted observation
iagent i's place in the sequence (1, 2, 3, etc.)
A tiny worked example with two robots
At time t, robot 1 is at position (3, 2) and robot 2 is at position (5, 4).
Robot 1's model sees position (3, 2) and is told to move forward. It predicts: robot 1 will be at (4, 2) next step, reward = 1.0.
Robot 2's model sees position (5, 4) and also gets the message 'robot 1 will be at (4, 2)'. It can avoid that spot. It predicts: robot 2 will be at (5, 5) next step, reward = 1.0.
Full joint prediction: robot 1 → (4, 2), robot 2 → (5, 5). Both planned without crashing, because robot 2 knew where robot 1 was going.

Each agent's model only has to learn one agent's motion rules and how to respond to earlier agents' moves, cutting down the complexity it has to fit.

What can go wrong

What can go wrong

Fixed order limits flexibility. If the sequence is always robot 1, then 2, then 3, robots early in the line have no way to respond to later robots' moves in the same step. If robot 5 suddenly blocks robot 1's path, robot 1's prediction was already made and cannot change. The paper addresses this by having robots replan multiple times during the actual motion, but the sequential structure does cap how much real-time adaptation is possible.
Communication failures break the chain. If robot 2 does not receive robot 1's prediction (packet loss), robot 2 has to guess, and its plan may be wrong. The paper includes a cache to store old messages, but this only works if failures are brief; long outages mean robot 2 is flying blind.
Training requires coordinated data collection. Each agent's model is trained on data that includes the other robots' behaviors. If the other robots change their policy, the first robot's model is no longer accurate. The paper assumes all robots are training together, which is practical in the lab but harder to generalize.
Done right. When robots are reordered or new robots are added, each can still learn its own model separately and take earlier robots' predictions as input. The paper validates this on physical quadruped robots in real deployments, showing the method works in uncontrolled settings.
What a runnable demo should prove

What a runnable demo should prove

Build a simple multi-robot simulation (e.g., four robots in a narrow corridor or grid world trying to reach their goals without colliding). Train a sequential world model where each robot's model predicts the next position and reward given its own observation plus earlier robots' predicted positions. Train a baseline centralized model on the same task for comparison. Measure: (1) how many steps each approach takes to converge during training, (2) the accuracy of position predictions at different time horizons (1 step, 5 steps, 10 steps), and (3) how many collisions happen when each method plans in a new scenario.

prediction_error = avg(|true_position - predicted_position|) at horizon h; training_steps_to_reward_80 = first step where cumulative reward crosses 80% of max; collision_count = number of times two robots occupy same cell.

The demo should make impossible to miss: five small models trained independently learn their part of the task faster and predict more accurately than one bloated joint model, and the sequential structure lets each robot know what robots ahead of it are doing, so they cooperate naturally.
