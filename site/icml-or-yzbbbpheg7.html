Adaptive Time Series Reasoning via Segment Selection

A model that learns to pick the relevant parts of a time series before answering a question, instead of trying to understand everything at once.

Paper explainersAll themesTime Series & Sequential

When you ask a question about a long time series (stock price charts or heart-rate data), the model needs to figure out which parts matter. Most systems try to understand the entire series first, which wastes effort on irrelevant data. ARTIST instead learns to actively pick just the relevant segments and uses those selected pieces to reason about the answer.

Why full-sequence encoding wastes time and focus

A doctor reviews a patient's 24-hour heart rate log and asks: when did the patient's heart rate spike above 120? The answer appears in maybe five minutes of the data, but processing every single heartbeat equally is wasteful. Most AI systems today work this way—they try to compress the entire time series into one summary before even hearing the question. That summary cannot preserve every detail, and it treats rare events (sudden spikes) the same as normal patterns.

A naive approach would be to learn a fixed representation of the whole sequence (turn the numbers into a compressed summary), then answer any question from that summary. This breaks for rare events or multi-part answers: if the summary loses track of when the spike occurred (by averaging it away), the model cannot recover it later.

The paper's one-sentence move: Instead of encoding the full series first, the model learns to ask which segments matter, selects those pieces actively when answering a new question, and then reasons from just those segments.

The algorithm as a flow

What it actually does

Controller sees the data

Model encodes the full time series into a form the controller can scan.

Controller decides which segments matter

For the given question, controller predicts a policy (a strategy for which pieces to pick).

Segments are selected

Model extracts the chosen segments from the full series.

Reasoner processes selected pieces

A second model reads only the selected segments and generates reasoning steps.

Answer is generated

Final answer produced from the reasoning trace about the selected segments.

What the paper changes

What the paper changes

The paper moves from a single 'encode everything then answer' pipeline to a two-step process: first decide which segments are worth reading, then reason only from those pieces.

the object it moves  =  segment selection policy
The hidden quantity

Task-relevant segment importance

measured quantity  =  Which segments the controller learns to select

A hidden quantity in this problem is which segments actually matter for each question. The question 'When did the heart rate spike?' needs the spike timestamps; the question 'What is the average trend?' needs the full picture. The paper does not measure this quantity directly from data (like labeling each segment as relevant or not). Instead, the controller learns a policy—a rule for picking segments—by watching reward signals during training: if picking a segment leads to a right answer, the reward reinforces that choice; if picking it hurts accuracy, the policy adjusts.

The reasoner role then condenses its reasoning into a trace (a step-by-step explanation). If the trace only mentions the selected segments and never refers back to what was skipped, we know the model picked the right pieces; if the trace seems confused, the controller may have chosen poorly. This trace serves as a human-interpretable signal of what the model thought was important, because a reasoning step can only be clear if it is grounded in the data the model received.

Why it works

Why selecting segments improves reasoning

The core insight is focus reduces noise. When a model tries to compress 1,000 data points into a fixed-size summary, rare events (a single spike among 1,000 steady points) vanish—they are drowned out or averaged away. But when the controller learns to select, say, just 50 points that include the spike, the reasoner sees a cleaner signal. Spikes stand out in a focused window; they do not get buried.

The second reason is adaptive representation. Different questions need different parts. A question about rare events needs the controller to hunt for outliers; a question about overall trend needs broader coverage. A fixed full-sequence encoding cannot adapt; it is the same for all questions. But a trained controller learns separate policies for different question types, so each one gets exactly the relevant data.

The third reason is reasoning efficiency. When the reasoner reads only selected segments, it spends its computation budget on relevant data. There is no wasted model capacity trying to parse and ignore irrelevant noise; all the model's reasoning steps are focused on the clues that matter.

The selection and reasoning formulation

First in words:

Total task score = (fine-tuning loss on segment selection and reasoning) plus (reinforcement learning bonus for question-adaptive selection that improves answer accuracy)

Then the compact form:

L_total = L_ft(segment_selection, reasoning_trace) + w_rl * R(question, selected_segments, answer_accuracy)

Every symbol:

L_ftsupervised loss on segment selection and reasoning steps during fine-tuning
segment_selectionthe controller's decision of which time windows to extract
reasoning_tracethe step-by-step explanation the reasoner outputs
w_rlweight balancing supervised learning and reward learning
Rreward signal: positive if answer is correct for this question on these segments
questionthe natural language query about the time series
A tiny worked example
Suppose a time series has 12 time steps. The controller chooses segments 3, 7, and 9.
Supervised loss L_ft = 0.3 (reasoner's trace quality + segment-selection confidence).
Reinforcement learning reward R = 1.0 (question answered correctly with these segments).
Weight w_rl = 0.5.
Total loss: L_total = 0.3 + 0.5 * 1.0 = 0.8. Training updates the controller to favor these segments more often because R was positive (high reward).

The total score combines two ideas: supervised training ensures the reasoning is clear and the selections are confident, while reinforcement learning reinforces segment choices that actually lead to correct answers.

What can go wrong

What can go wrong

Controller misses rare events. If the training data has very few examples of a rare event, the controller never learns to pick it, and it will skip segments containing the spike. The model needs at least some labeled examples showing which segments matter.
Segment selection is too narrow. If the controller learns to select only tiny windows, it might miss the context needed for reasoning. A question about trend requires seeing a longer view, not just one or two points.
Reasoning trace is vague or incorrect. The reasoner might produce plausible-sounding steps that do not actually use the selected segments. The reinforcement learning signal is answer correctness, not reasoning quality, so a lucky guess could reinforce poor reasoning.
Done right: model is trained and tested fairly. The controller learns from labeled training data with clear signals about which segments mattered. When answering new questions, the reasoning trace is checked to ensure it grounds in the selected segments.
What a runnable demo should prove

What a runnable demo should prove

Build a small synthetic time series (e.g., a trace of random noise with exactly two deliberate spikes inserted at known positions). Ask the model a question like 'When did the signal spike above threshold?' Have the baseline (full-sequence encoding) and ARTIST run on the same data. Measure how often each model correctly identifies the spike times. The demo should show that ARTIST's controller learns to pick the windows containing the spikes, even when those windows are rare (e.g., 5 time steps out of 200), and that ARTIST gets the answer right while the baseline forgets the spike in its fixed summary.

accuracy = (number of questions answered correctly with right spike times) / (total questions); compare baseline vs ARTIST on the same 50 time series with 2 rare spikes each

The irreversible takeaway: when evidence is rare, a model that learns to hunt for it (active selection) beats a model that tries to summarize everything at once (static encoding).
