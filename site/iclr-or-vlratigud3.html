InSight-o3: Empowering Multimodal Foundation Models with Generalized Visual Search

Give a reasoning agent a dedicated visual search partner that can find the exact image regions described by a free-form request, even when the request names relations or concepts instead of simple objects.

Paper explainersAll themesAgents & Tool Use

Many image-question systems can answer when the needed evidence sits in one obvious region. They struggle when the answer depends on several small regions spread across a chart, map, or document page. In those cases the hard part is not only reasoning. It is finding the right places to inspect. InSight-o3 splits the job between a reasoning agent and a visual search agent. The search agent is trained to locate regions described in free-form language, including relational requests such as "the legend entry that matches the steepest curve" or conceptual requests such as "the paragraph that states the exception." That extra search tool helps because the reasoning agent can only reason over details it has first brought into view.

Zero assumption version

Why hard image questions fail before reasoning starts

A hard visual reasoning question often depends on several pieces of evidence in different places. For example, a chart question may require reading the legend, then matching a curve, then checking a value on the axis. A map question may require finding a symbol, reading a label far away, and comparing two routes.

A single agent that looks at the whole image at once often misses one of those details. Once an important detail is missed, later reasoning cannot recover it. The system needs a way to search for the exact region described by language before trying to combine those findings into an answer.

The paper's move in one sentence. Separate visual search from reasoning, and train the search agent to localize free-form region descriptions so the reasoning agent can ask for the precise evidence it needs.

The algorithm as a flow

What it actually does

Receive an image and a hard question.

Start with a page, chart, map, or other dense image whose answer may depend on several distant regions.

Generate a search request.

The reasoning agent asks for a region in plain language, such as a curve segment, a legend item, or a sentence that states a condition.

Localize the requested region.

The visual search agent finds the region that best matches the request, because it has been trained to handle free-form descriptions rather than only fixed object names.

Return evidence to the reasoner.

Pass the found crop or coordinates back so the reasoning agent can read or compare the relevant content.

Repeat until enough evidence is gathered.

Ask for more regions as needed, then answer the question once the required details have been collected.

The hidden quantity

The hidden quantity: evidence reachability

measured quantity  =  Whether the needed visual evidence can be found from language alone

A reasoning system fails if the evidence it needs is present in the image but never becomes accessible to the reasoning process. The hidden quantity is evidence reachability: can the agent actually bring the right region into view when the question describes it in ordinary language?

InSight-o3 raises evidence reachability by training a dedicated search agent to map free-form requests to image regions. This matters because many benchmark failures are not pure reasoning failures. They start as evidence-gathering failures.

Why it works

Why splitting search from reasoning helps

The method works because search and reasoning are different jobs. Search asks where the relevant evidence lives. Reasoning asks how several pieces of evidence combine into an answer. A single agent that tries to do both from the full image can waste effort scanning irrelevant content and still miss a small necessary detail.

Once the search agent becomes good at localizing free-form requests, the reasoning agent can operate on a cleaner evidence stream. Accuracy rises because each query narrows the visual field to what matters, and harder multi-region questions become manageable because the system can gather evidence step by step.

The retrieval idea

First in words:

For each search request, score candidate regions by how well the region matches the language description, then return the highest-scoring region to the reasoning agent.

Then the compact form:

best_region = argmax region_match(request, region)

Every symbol:

best_regionthe image region returned to the reasoning agent
region_match(request, region)a score that measures how well one region fits the free-form request
requestthe language description of the needed evidence
regiona candidate crop or location in the image
A tiny worked example
Suppose the question asks which line on a chart drops fastest after a certain date.
The reasoning agent first asks for the legend item tied to the darkest line.
The search agent scores several small legend regions and returns the best one.
Next the reasoning agent asks for the matching curve section after the date marker.
The search agent returns that curve region, and the reasoning agent compares the slopes.
The answer is now reachable because the evidence was collected in the right order.

The search score is useful because the reasoning agent does not need the whole image at once. It needs the best next region for the current subquestion.

What can go wrong

What can go wrong

The search request may be underspecified. If the reasoner asks for a vague region, the search agent may return the wrong crop because several places satisfy the request equally well.
The search agent may miss conceptual cues. Some requests point to a function rather than a visible object, such as the sentence that states an exception. Those cases remain hard because the region is defined by meaning, not just appearance.
Repeated search can become expensive. A long chain of search requests may add latency because each reasoning step waits for another localization pass.
Done right. When the reasoner asks precise subquestions and the search agent returns accurate crops, hard image questions become more solvable because the system can gather evidence in pieces.
