Si-GT: Fast Signal Integrity Analysis via Graph Transformers

Replace expensive circuit simulation with a neural network that learns to predict how electrical signals break and delay when wires couple together.

Engineers use a simulator called SPICE to measure these effects, but it is so slow that checking large chips becomes impossible. This paper trains a neural network on SPICE's results, so new designs can be checked instantly instead.

Zero assumption version

The wall: simulation takes forever

When you design a computer chip with millions of wires, the wires sit very close together. Electricity flowing through one wire creates a magnetic field that pushes on electrons in neighboring wires. This is called crosstalk. It causes two bad things: the signal arrives late (delay), and it can flip briefly in the middle (glitches). Both break the circuit.

Engineers verify designs by running a simulator called SPICE. It solves the actual physics of every wire and predicts the broken signals with perfect accuracy. But SPICE simulates each design from scratch, wire by wire, which takes hours or days for a large chip. By the time you finish checking one version, you have already thought of a better layout—so you run SPICE again, waiting again. This happens because each new design's wires are arranged differently, so SPICE has no shortcuts; it must solve the physics over for each one.

A naive way to go faster is to use simple rules of thumb (heuristics). But heuristics ignore the actual mesh of wires and the way signals bounce between them, so they miss real crosstalk effects and give wrong answers.

The method: Train a neural network to mimic SPICE by learning from 200,000 real simulations, so checking a new design takes milliseconds instead of hours.

The algorithm as a flow

What it actually does

Parse the circuit graph

Convert the wire layout into a graph: nodes are wires, edges are close neighbors.

Embed each wire

Each wire gets a virtual NET token: a list of numbers that captures its shape, resistance, and position.

Encode the mesh

For each point on each wire, record which other wires sit nearby.

Run two relevance-scoring passes

First pass: find patterns within a single wire. Second pass: find patterns between coupled wires.

Predict signal traces

Output: delay time and glitch size at each wire.

What the paper changes

What the paper changes

The paper replaces SPICE with a neural network that reads the same circuit layout as input and outputs the same signal predictions. The network learns by being shown 200,000 examples of wire layouts and their matching SPICE results, so it internalizes the pattern of how crosstalk spreads through a mesh.

the object it moves  =  The circuit simulator
The hidden quantity

The hidden quantity: which wires are electrically close

measured quantity  =  Coupling proximity map

The paper's central insight is that crosstalk depends entirely on which wires sit near each other in the physical layout. Two wires far apart do not interact; two wires millimeters apart interact strongly. But because a circuit has millions of wires, and each wire has hundreds of points along its length, the network needs a way to quickly ask: at this point on this wire, which other wires are close enough to matter?

Si-GT measures this by embedding the mesh structure: for each point, it records the identity and distance of nearby wires. It then uses attention (a mechanism that asks which pieces of information are most relevant to the current question) to automatically learn which neighborhood sizes matter most. The network discovers this from the data without being told the physics rule.

Why it works

Why the network can replace SPICE

SPICE works by solving the differential equations that describe electricity on each wire, over tiny time steps. It is slow but exact. Si-GT takes a different path: it learns a compressed pattern from 200,000 examples of SPICE's outputs. The key is that the pattern is not random. Crosstalk follows physics: signals propagate in well-defined paths, couple only with nearby wires, and reflect off endpoints. These structures repeat across all designs.

Si-GT uses three design choices to capture this pattern without solving equations. First, it gives each wire a NET token (a list of numbers that encodes everything about that wire) that represents that wire's full identity across many time points. Second, it encodes the local mesh: for each spatial point on the wire, it notes which neighbors are nearby. Third, it uses dual attention: one pass finds patterns within a single wire, and a second pass finds patterns between coupled wires. Together, these three mechanisms let the network learn signal flow without being given the physics equations. The network essentially internalizes SPICE's shortcuts from the data.

The paper's mechanism works because of scale: 200,000 examples provide enough repetition of the same physical patterns (delays, reflections, coupling) that the network can extract them without explicit rules. Each example teaches the network a tiny piece of how the mesh shapes signals. After training on a diverse set of layouts, the network has seen enough patterns to predict new designs accurately.

The signal prediction formula

First in words:

The predicted delay and glitch are computed by summing the contribution from each coupled wire, weighted by its distance and the learned importance of each neighbor.

Then the compact form:

delay_i = base_i + sum_j w_ij * attention_ij * contribution_j(layout, distance_ij)

Every symbol:

delay_ipredicted signal arrival time at wire i
base_ithe wire's own propagation time, ignoring neighbors
sum_jsum over all wires j that are neighbors of i
w_ijthe learned importance: how much wire j affects wire i
attention_ijthe weight the network assigns to this neighbor in the current context
contribution_j(layout, distance_ij)the glitch size caused by wire j, based on their physical distance
A tiny worked example with four wires
Wire A has base delay 10 nanoseconds (how long its signal takes without neighbors).
Wire B is 0.2 micrometers away (very close). Network learns w_AB = 0.8 (important).
Wire C is 2.0 micrometers away (far). Network learns w_AC = 0.1 (weak effect).
Wire D is 0.1 micrometers away (extremely close). Network learns w_AD = 1.0 (strongest).
When the network predicts delay for wire A: delay_A = 10 + 0.8 * (0.5 * 2) + 0.1 * (0.5 * 0.3) + 1.0 * (0.5 * 3) = 10 + 0.8 + 0.015 + 1.5 = 12.3 nanoseconds.
SPICE (exact simulation) gives 12.4 nanoseconds. The network is off by 0.1 nanoseconds, which is good enough for design checks.

The formula says: the delay depends on the wire's own properties plus a weighted sum of interference from each neighbor, where the weights are learned from SPICE examples.

What can go wrong

What can go wrong

Domain shift: a layout style never seen in training. If a new design has wire patterns that were rare in the training data (e.g., wider spacing or different metal layers), the network may not extrapolate well. SPICE remains the trusted reference for unfamiliar layouts.
Extrapolation to much larger designs. The network was trained on layouts with up to roughly 50,000 wires. A design with 1 million wires may not be predicted accurately if how the wires interact changes in ways the network never saw.
Timing-dependent effects not in the training set. If the true design includes a rare physical phenomenon (e.g., temperature-dependent drift, layer interactions) that was not represented in SPICE runs, Si-GT has no way to learn it.
Done right: used as a fast filter. Use Si-GT to check 1,000 candidate designs and prune to the best 10, then run SPICE on those 10 to verify. This workflow is 100x faster because you run SPICE only on the 10 finalists instead of all 1,000 upfront. Si-GT's speed lets you use the same accuracy bar with a much smaller SPICE burden.

What a runnable demo should prove

Side-by-side, show the predicted and true signal traces (time on x-axis, voltage on y-axis) for one or two wires. The demo should make it obvious that Si-GT follows SPICE's curves closely (within 5% error) while running instantly.
