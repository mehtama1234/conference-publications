DenseMLLM: Standard Multimodal LLMs for Dense Prediction

Train a plain multimodal language model to output region-level predictions by supervising its visual tokens, so segmentation and depth do not need a separate dense decoder.

Paper explainersAll themesMultimodal

Dense prediction asks for an answer at many image locations, not one answer for the whole image. Semantic segmentation assigns a class to each region, and depth estimation assigns a distance value to each region. Most multimodal language models already contain visual tokens, meaning learned feature vectors, which are lists of numbers attached to image patches or regions, but dense tasks are usually handled by bolting on a special decoder that upsamples those features into a prediction map. This paper argues that the extra decoder is not always necessary. DenseMLLM keeps the standard multimodal language model layout and instead puts direct supervision on the visual tokens so each token is trained to carry the local information needed for several dense tasks. The core claim is that dense perception can emerge from the base token stream itself when training tells each token what local label or local depth signal it should represent.

Zero assumption version

Why dense perception usually breaks the general model design

A standard multimodal language model is good at global tasks such as captioning or question answering because it can compress the image into a moderate number of visual tokens and then reason over them with text. Dense prediction is harder because the output must preserve where each local pattern came from. If the system collapses many regions into one global summary, the precise boundary between object and background disappears and depth ordering becomes blurry.

Most existing systems solve that mismatch by attaching a custom dense decoder after the main model. That works, but it splits the architecture into a general model for high-level understanding and a task-specific branch for pixel-level work. The paper asks whether the model can stay general if the visual tokens themselves are trained to store local answers, because then the same backbone could support both language tasks and dense tasks without extra architectural machinery.

The paper's move in one sentence. Do not add a special dense decoder; instead supervise the existing visual tokens so each token learns the local class or local depth cue tied to its own image region.

The algorithm as a flow

What it actually does

Encode the image into visual tokens

Run the image through the normal vision front end so the model produces one learned feature vector, which is a list of numbers, for each local image region because the later dense supervision must attach to a region-specific representation.

Align tokens with local targets

Associate each token with the class label or depth target for the image region it covers, because dense tasks require location-specific supervision rather than only a whole-image loss.

Train with multi-task token supervision

Apply supervision directly on the token representations for several dense tasks, so the token stream learns to preserve both region meaning and spatial structure, where spatial structure means the layout and relative depth of the scene.

Reuse the same backbone for vision-language tasks

Keep the standard multimodal model intact, which means the same core network still supports captioning or question answering while also carrying dense prediction information.

Read out dense maps from the trained token grid

Convert the supervised token grid into segmentation or depth outputs, using the token-local information that training has already stored.

What the paper changes

What the paper changes

The paper changes where dense-task knowledge enters the model. Instead of adding a separate dense branch after the multimodal model, it inserts the supervision at the visual token level inside the base architecture.

The hidden quantity

The hidden quantity

measured quantity  =  how much local scene structure survives inside the standard token stream

The key hidden quantity is whether a token still contains the local evidence needed for a dense answer after it has also been used for language modeling. If that information is missing, any dense output head will be forced to guess boundaries and distances from an already lossy representation.

DenseMLLM tries to preserve that information by supervising tokens before the local structure is erased. Each token is pushed to represent the class or depth target for its region, so the model cannot rely only on global image meaning. That pressure matters because segmentation and depth are decided by local differences such as object edges, surface changes, and fine region identity.

Why it works

Why token-level supervision can replace a custom dense branch

A custom dense decoder is often added because dense tasks need spatial precision, but that decoder is only compensating for information that the backbone did not preserve. If the token attached to a region is trained to predict the class and depth signal of that region, the precision enters earlier in the pipeline. That earlier supervision matters because the model learns to keep local distinctions before they are blended into a more global representation.

Multi-task token supervision also pushes the token space to serve several local objectives at once. A segmentation target teaches region identity and object boundaries. A depth target teaches relative distance and surface layout. Putting both on the same token stream can strengthen the representation because each task constrains a different aspect of the same local patch.

The generalist design remains intact because the model architecture does not split into task-specific branches. The same token stream can still support language outputs, and it can support dense outputs because the training objective has made local information explicit rather than leaving it implicit.

A plain training view

First in words:

The training objective adds local losses on visual tokens for each dense task. One part asks each token to predict the right class for its region, and another part asks it to predict the right depth value or depth bin for that same region.

Then the compact form:

training_loss = language_loss plus segmentation_token_loss plus depth_token_loss

Every symbol:

language_lossthe usual objective for multimodal language behavior
segmentation_token_lossthe loss that compares each token's region-class prediction with the target label for that region
depth_token_lossthe loss that compares each token's depth prediction with the target depth information for that region
training_lossthe full objective used to train the shared token stream
A tiny worked example
Suppose one image is divided into four regions: road, car, sky, and sidewalk.
The road token should predict the road label and a farther depth than the car token if the car is closer to the camera.
If the model predicts road and car correctly but gives the same depth signal to both, the depth part of the loss stays high.
Training then changes the shared token representation until that local geometric difference is encoded.
After many images, the token stream learns to preserve the local distinctions needed by both tasks.

The important point is not a special formula. The important point is where the supervision is applied: directly on the standard visual tokens rather than on a separate dense-only decoder.

What can go wrong

What can go wrong

Token granularity can still be too coarse. If one token covers a large image region, very thin boundaries or tiny objects may remain hard to recover because the local signal was already merged before supervision was applied.
Dense tasks may compete with language behavior. If the training balance is poor, the model may spend too much capacity on local signals and weaken its global language behavior, because both uses share the same token stream.
Some tasks may still need explicit upsampling. Very high-resolution outputs can require an additional reconstruction step, because the token grid is usually lower resolution than the original image.
Done right. The approach is most convincing when the base token grid is already reasonably aligned with image regions, because then direct supervision can turn those tokens into dense predictors without redesigning the whole system.
