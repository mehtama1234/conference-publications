UniSplat: Unified Spatio-Temporal Fusion for Dynamic Driving Scenes

UniSplat rebuilds dynamic street scenes from multi-camera car video in one forward pass by fusing 3D shape and object labels in a shared structured grid, plus keeping a memory bank of permanent background features for rendering beyond camera edges.

Paper explainersAll themesComputer Vision

Autonomous driving cameras see the street from many angles at once, but each camera sees only part of the scene, views don't always overlap much, and things are moving. UniSplat is a feed-forward model (computes in one pass, no per-scene fitting) that constructs a 3D latent scaffold—a structured, sparsely-packed 3D grid encoding 3D shape and object labels—then fuses camera information across that shared space to rebuild dynamic scenes that can be viewed from angles the cameras never captured, even beyond their field of view.

The driving scene puzzle

A self-driving car has cameras mounted all around—front, sides, rear—seeing the same street scene from different angles at the same time. If you want to generate a photo from a new angle (one that no camera captured), you need to understand the full 3D shape and appearance of everything in the scene: the road, cars, trees, people.

Naive approach: take each camera image independently and try to predict 3D shape from each one. But this fails because each camera only sees part of the scene, and the overlaps are sparse and tilted. You don't get one unified picture of the street.

Past methods solved this by carefully optimizing a model for each scene (slow, takes minutes), or by trying to fuse camera images early (in 2D) before lifting to 3D, which loses geometric precision. Neither works well for real-time autonomous driving where you must reconstruct fresh scenes instantly.

The challenge. Build a model that understands a full dynamic street scene from many cameras in one forward pass, even when views barely overlap.

The algorithm as a flow

What it actually does

Scaffold construction

Run multi-view images through shape and label foundation models to build a 3D grid of features.

Spatio-temporal fusion

Align and blend information across cameras and previous frames within the scaffold.

Dynamic detection

Assign each 3D point a dynamic probability; separate moving objects from static background.

Gaussian generation

Two pathways refine and complete the 3D structure into Gaussian primitives ready to render.

Streaming completion

Keep a persistent memory of static 3D shape and render beyond camera edges using stored structure.

What the paper changes

What changes

UniSplat changes how information flows during scene reconstruction. Instead of fusing camera images in 2D space (pixel-by-pixel) or per-camera (camera-by-camera), it fuses them in 3D latent space—inside a shared structured representation that all cameras write into at once. This unified 3D scaffold becomes the common language between views.

The hidden quantity

The dynamic probability: separating moving from static

measured quantity  =  Dynamic probability per 3D point

Every 3D point in the reconstruction gets a probability score: 0 means completely static (parked car, road, tree), 1 means completely dynamic (moving pedestrian, moving car). This is a named hidden quantity the paper explicitly assigns: each Gaussian has a learnable dynamic attribute to disentangle what is truly part of the scene shape from what is momentarily passing through.

The paper estimates this by feeding the fused scaffold features through a small neural network that predicts whether each point is static or dynamic. During rendering, this score filters which Gaussians to render in the current frame and which to keep in a persistent memory bank for future frames.

Why it works

Why unified 3D scaffolds work

The core insight: if you project all cameras into a shared 3D coordinate frame (ego-centric, anchored to the car), you can align information directly at the source shape. A point on the road is the same point no matter which camera sees it, so writing all camera features into the same 3D voxel reduces redundancy and forces alignment consistency.

Because the scaffold is a learnable 3D grid, not a raw point cloud, it can be queried and refined via standard neural operators (pooling, convolution). The two-branch decoder then sculpts this scaffold into Gaussians: one branch uses point-anchored refinement (sharpen 3D details using neighboring points), the other uses voxel-based generation (fill gaps and handle sub-voxel details). Together they ensure both precision and completeness.

The dynamic probability acts as a temporal filter by deciding what to save: when the probability is high (static), the Gaussian gets added to a memory bank that persists frame to frame. When it is low (dynamic), the Gaussian is drawn only for the current frame and discarded. Over time, the memory bank collects all the permanent background 3D shapes, allowing rendering far beyond the current camera frustum. This matters for autonomous driving because the route extends beyond camera view.

What can go wrong

What can go wrong

Extreme camera misalignment. If cameras see nearly zero overlap (e.g., front camera aimed down at road, rear camera aimed at horizon), the 3D scaffold cannot align them. The fusion mechanism has nothing in common to work with.
Sudden scene occlusion. Memory bank accumulates static 3D shape over time, but if a large obstruction appears (tunnel entrance), the model may render old memory into the current frame, creating a ghost.
Persistent moving objects misclassified. If a dynamic probability threshold is set too high, a parked car that briefly moved becomes marked dynamic permanently, and never enters the memory. Conversely, a slow-moving pedestrian might be treated as static.
Done right. Calibrated camera intrinsics, sufficient LiDAR supervision during training to ground the dynamic classifier, and periodic memory pruning ensure the model generalizes to new scenes.
What a runnable demo should prove

What a runnable demo should prove

Take a real autonomous-driving video sequence (Waymo Open or NuScenes) with at least 3 multi-camera views. Train or run UniSplat in inference mode to reconstruct the scene. Render the same scene from two angles: one inside the original camera frustum (should match closely) and one outside it, 10 meters to the left of the car (off-camera). Verify that the off-camera view contains the persistent static 3D shape (road markings, parked cars, trees) but not dynamic objects that passed through an earlier frame.

off_camera_plausibility = (road_markings_visible + parked_objects_stable - dynamic_ghosts) / 3

The test is whether UniSplat's memory bank persistently tracks static background 3D shape and renders it correctly far beyond the original camera coverage—something no single-view approach can do.
