SEINT: A Geometry-Aware Metric for Comparing Distributions

A fast method to compare two clouds of numbers that stays fair when you rotate or flip them.

Paper explainersAll themesOptimization

When you have two sets of data points (like atoms in two molecules), you want to know how similar they are. But here's the catch: if you rotate one set, it should still match the other — the answer should not change just because you spun things around. SEINT is a fast way to measure this fairness, using a real metric (a distance measure that obeys basic rules) and a clever trick to ignore the rotation entirely.

Comparing Two Point Clouds While Ignoring Rotations

Imagine you have two lumps of clay, each made of the same number of little beads. You want to ask: are they shaped the same? The hard part is that one lump might be rotated or flipped compared to the other. If you just measure distances between the beads naively, a rotated version looks completely different — even though they are really the same shape.

A beginner might try to measure each bead position and compare them directly. That fails instantly because a small rotation breaks everything. Engineers then built methods that hunt for the rotation first, then compare. But these methods are slow (they take a lot of computation) and some of them do not guarantee that the distance measure they create actually works like a real distance (where if A equals B and B equals C, then A must equal C).

In one sentence. The method extracts a description of each cloud that automatically ignores rotations and flips, so comparing becomes fast and honest.

What the paper changes

What the Paper Changes

The paper swaps out what you measure. Instead of comparing the raw positions of points (which changes when you rotate), it compares rotation-free descriptions built from distances and angles.

The hidden quantity

The Hidden Quantity: Rotation-Free Invariance

measured quantity  =  rotation-free traits (a list of numbers describing shape)

The hidden quantity is a list of numbers that describe the cloud's structure but stay exactly the same under any rotation or flip. For example, if two points are 5 units apart, that distance stays 5 units apart no matter how you spin things. If three points form a triangle, the angles of that triangle never change under rotation.

The paper estimates this quantity by measuring pairwise distances between every pair of points and the angles formed by triplets. These numbers are then packed (via polar transport, a way to encode distance and angle info) into a single list of numbers (the rotation-free trait description) that captures the whole cloud's shape.

Why it works

Why It Works: Three-Part Chain

The mechanism has three stages. First, you measure the intrinsic shape of each cloud by recording distances between pairs and angles in triplets. These are rotation-proof because spinning does not change a distance or an angle. Second, you pack all these measurements into a single rotation-free vector (the representation) using a technique called polar transport — this is a fancy way to say: convert distance and angle info into a combined score that captures the cloud's shape. Third, you compare the two representations using optimal transport, a standard algorithm that finds the best alignment between two point clouds. Because the representations are already rotation-free, optimal transport can work directly without hunting for the rotation first, which saves time because other methods must run expensive searches to find the correct rotation before comparing.

Why does this give a real metric? A metric must obey four rules: distance from A to A is zero; distance from A to B equals distance from B to A; distance is always positive; and the triangle inequality (distance from A to C is at most the distance from A to B plus B to C). Because the paper builds the comparison on top of optimal transport (which is a true metric on its own) and the rotation-free trait extraction is a one-way function that does not lose information about the cloud's shape, the final measure inherits these properties.

The Distance Equation

First in words:

The distance between two clouds is computed by running optimal transport on their rotation-free trait vectors. In plain words: measure all pairwise distances in cloud A and pack them into a trait vector. Do the same for cloud B. Then find the cheapest way to match the traits in A to the traits in B.

Then the compact form:

D_SEINT(A, B) = OT(Phi(A), Phi(B))

Every symbol:

D_SEINT(A, B)the final distance between clouds A and B
Phi(A)the rotation-free trait vector extracted from cloud A
Phi(B)the rotation-free trait vector extracted from cloud B
OT(...)optimal transport: the cost of the cheapest matching between two sets of numbers
A tiny worked example
Cloud A: three atoms at positions forming a triangle. Measure distances: 3 units, 4 units, 5 units. Measure angles: 30 degrees, 60 degrees, 90 degrees.
Cloud B: same triangle rotated. Distances are still 3, 4, 5. Angles still 30, 60, 90.
Trait vectors: Phi(A) = [3, 4, 5, 30, 60, 90]. Phi(B) = [3, 4, 5, 30, 60, 90].
Optimal transport cost: 0 (they match perfectly). Distance D_SEINT(A, B) = 0.
If cloud C is the same triangle scaled to 6, 8, 10, the trait vector changes (larger distances). Now D_SEINT(A, C) > 0.

Phi extracts traits that never change under rotation; OT then measures how different those traits are between two clouds.

What can go wrong

What can go wrong

Reflection vs rotation confusion. If the paper is not careful, a reflected cloud (flipped like a mirror image) might get treated the same as a rotated one. True SE(p) invariance should handle both, but bugs in the implementation can mix them up.
High-dimensional breakdown. In very high dimensions, the number of possible pairwise distances and angles explodes. The trait vector can become huge, and optimal transport slows down. The computational cost ranges from linear-with-log factor up to quadratic in the number of points, but assumes moderate dimensions.
Noise sensitivity. If the point positions are noisy (small random errors), the angle measurements become unstable. A tiny jiggle in a position can flip which angle is largest, changing the trait vector.
Done right: use SEINT on well-posed problems. On clean data (e.g., molecular structures) where rotations and flips are the main source of variation, SEINT is fast and fair.
What a runnable demo should prove

What a runnable demo should prove

Build a simple experiment: generate a point cloud (e.g., a random set of 10 to 20 points in 3D space). Rotate it by a random angle around each axis. Compute the SEINT distance from the original to the rotated version. It should be exactly zero (or very close). Repeat with different random rotations. Then try the same experiment with a naive Euclidean distance (direct position comparison): it should give wildly different answers for rotated clouds. This proves that SEINT is rotation-fair where the naive method fails.

SEINT distance to self = 0 for any rotation; naive distance to rotated self = high and variable

SEINT must return zero (or near-zero) distance to the same cloud after arbitrary rotation; naive methods will fail on this basic test.
