Deep Latent Variable Model based Vertical Federated Learning with Flexible Alignment and Labeling Scenarios

The paper turns missing partners, missing labels, and partial user overlap in vertical federated learning into one missing-data problem that can be trained under a single probabilistic model.

Paper explainersAll themesOther

Vertical federated learning joins institutions that hold different features for the same people. A bank may know transaction records while a telecom company knows call patterns. In the clean textbook case, every party has every user and one party holds labels for all of them. Real deployments are rarely that clean. Some users appear at only some parties, labels may exist for only a subset, and the number of parties can exceed two. This paper reframes all of those gaps as missing data. It then uses a deep latent variable model, which means a model with hidden shared variables that explain the observed features, to infer the unobserved pieces during both training and test time. The value of that reframing is that one mechanism can now handle many alignment and labeling patterns that older vertical methods treat as separate edge cases.

Zero assumption version

Why vertical federated learning breaks outside the ideal case

Vertical federated learning assumes different parties hold complementary columns for overlapping users. The common workflow aligns user IDs, joins the features, and trains a model without exposing raw tables. Many methods quietly assume nearly complete overlap and clear labels. Once those assumptions fail, the pipeline becomes brittle.

If one user is present at the bank but absent at the hospital, some feature columns are simply missing. If labels exist only for a small subset, the supervised signal is also missing. Older methods often solve one of these gaps at a time: maybe two-party overlap only, maybe labeled users only, maybe train-time missingness but not test-time missingness. That fragmentation leaves practitioners without a single method that can handle arbitrary overlap and labeling patterns.

The unifying move. Treat alignment gaps and label gaps as missing values under one shared generative model, then infer the missing pieces instead of requiring them to be present.

What it actually does

Represent each user with a shared hidden state

The model assumes each party's observed features come from one common user state, so partial records can still contribute information.

Condition on whatever parties are available

If a user's record is missing at one party, the model simply conditions on the remaining parties rather than discarding the user.

Infer missing features and labels

The hidden state supports predictions for absent columns and for labels, which lets unlabeled or partially aligned users participate in training.

Train across many missingness patterns

The objective is written so the same model can learn from fully observed and partially observed users together.

Use the same test-time estimation rule

Prediction remains possible even when the available parties at test time differ from the pattern seen during training.

What the paper changes

What the paper changes

The paper changes the basic formulation of vertical federated learning. Instead of treating alignment gaps as a preprocessing obstacle, it treats them as missing values inside the model itself.

The hidden quantity

The hidden user state ties together all parties

measured quantity  =  shared hidden user state

The hidden quantity is a per-user state that explains the observed features across parties and can also support label prediction. Each party sees only one projection of that state. When one party is absent, the state can still be inferred from the others.

This quantity matters because vertical federated learning needs a way to combine partial views without requiring exact alignment everywhere. If the hidden state is informative, then missing columns become an estimation problem rather than a dead end. If it is weak, the model has no reliable basis for reconstructing absent information.

Why it works

Why reframing alignment as missing data works

The key step is to write a generative story for a user. First draw the user's hidden state. Then let each party's observed feature block be generated from that state, and let the label be generated from the same state when a label exists. Once the model is written that way, any absent party or absent label is simply an unobserved variable in the same graph.

Training then uses approximate posterior inference, which means estimating the hidden state from the observed pieces of a user record. If a user appears at three parties, the estimate uses all three. If the user appears at only one party, the estimate uses just that one and remains valid. This works because the inference rule conditions on the available evidence rather than demanding complete rows.

The practical payoff is that unlabeled and partially aligned users are no longer wasted. They still sharpen the hidden state model, because fitting the shared user state on more partial records teaches the model how different party-specific feature blocks co-vary even when labels are absent, and that stronger shared state then improves label prediction on the smaller labeled subset. The same logic applies at test time. A deployment may have only some parties available for one user, but prediction can still proceed because the model already knows how to infer the hidden state from arbitrary subsets of parties.

Math after the picture

Training objective with missing pieces

First in words:

The model maximizes the evidence lower bound, which is a trainable lower bound on the probability of the observed pieces. It combines reconstruction of observed features, prediction of observed labels, and a regularization term for the hidden state.

Then the compact form:

ELBO = E_q[log p(observed features, observed labels | hidden state)] - KL(q(hidden state | observed pieces) || p(hidden state))

Every symbol:

q(hidden state | observed pieces)the inferred distribution, meaning the model's estimate of the hidden user state given the available parties
p(hidden state)the prior distribution, meaning the default belief about hidden states before seeing a user
log p(observed features, observed labels | hidden state)how well the hidden state explains the pieces that are actually present
KL( ... )a penalty that keeps the inferred hidden states from drifting too far from the prior
A tiny worked example
Suppose one user has bank features and telecom features, but no clinic features and no label.
The inference network uses the observed bank and telecom blocks to estimate the hidden user state.
The reconstruction term scores how well that hidden state explains the bank and telecom blocks that are present.
There is no label term for this user because the label is absent.
A different user with a label contributes both a feature reconstruction term and a label prediction term.
Training over both users helps because the unlabeled user still improves the hidden state model that the labeled user depends on.

Writing the objective only over observed pieces is what lets one model train on many missingness patterns at once.

What can go wrong

What can go wrong

The hidden state may be too weak. If the shared hidden user state cannot capture the joint structure across parties, then reconstructed features and predicted labels will both be poor, because all inference flows through that state.
Missingness can be highly informative. If the fact that a party is missing is itself strongly related to the label, a simple missing-data model may be biased unless that mechanism is modeled explicitly.
Very low overlap limits identifiability. If almost no users appear across multiple parties, the model may struggle to learn how those party-specific feature blocks relate to the same hidden state.
Done right. The approach is strongest when at least some overlap exists to tie the parties together, because those anchor users teach the model how different feature blocks correspond to the same underlying user state.

What a runnable demo should prove

Compare a baseline that trains only on fully aligned labeled users against the hidden-state method. The demo should show whether the unified model still predicts labels when only partial party subsets are available, because the shared hidden state can still be inferred from the observed parties, and whether unlabeled partial users improve final accuracy by teaching that shared state on extra records.
