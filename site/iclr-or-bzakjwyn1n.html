Minimal Sufficiency in Spatial Reasoning

Ask a vision model to grab only the 3D information it actually needs to answer a question, instead of drowning it in noise.

Paper explainersAll themesOther

When you ask a vision-language model to reason about where things are in 3D space, it often fails because it sees too much. It was trained mostly on 2D images, so it does not understand 3D depth well. And when it tries to figure out left versus right in a real scene, it gets confused by all the extra details it pulled in. This paper's move is simple: have the model first decide what pieces of 3D information it actually needs to answer the question, grab only those pieces, then reason cleanly. By cutting the noise, it answers spatial questions far more accurately.

Zero assumption version

Too Much Noise, Too Little Depth

Vision-language models are trained on billions of 2D images online. When you ask one to understand where an object sits in a real 3D room—its height, its left-right position, its distance from the camera—the model is guessing. It was never trained to see depth properly.

A beginner's first try: just throw all the 3D information at the model. Scan the scene for objects, their coordinates, their directions. Feed it all in. But here is the trap: 99% of that information is noise. The model asks: is the ceiling painted blue? Nope. Is there a lamp in the corner? Probably, but does it matter for the question? Now the model is paralyzed by detail. It forgets the core facts it actually needs and fails the reasoning.

The method in one sentence. Before answering, the model first figures out what 3D pieces it actually needs, grabs only those, then reasons cleanly on the compact set.

The algorithm as a flow

What it actually does

Step 1: perception plan

The reasoning agent reads the question and writes a plan: which pieces of 3D information matter?

Step 2: perception agent queries

Run each query against the 3D scene. Locate objects by name. Measure coordinates. Ground directional words like west into actual lists of numbers (3D vectors) using the SOG module, which ties words to specific directions.

Step 3: gather the minimal set

Collect only the results that the plan called for. Drop everything else. This is the minimal sufficient set.

Step 4: check for gaps

The reasoning agent looks at the plan and the minimal set. Are there missing pieces? Ask for them. Are there redundant pieces? Mark them for removal.

Step 5: final reasoning

With the pruned, clean set, the reasoning agent uses chain-of-thought to work through the logic and answer the question.

What the paper changes

What the paper changes

Instead of feeding the model every piece of spatial information upfront, the paper makes the model construct and curate a minimal sufficient set first. It is not the model's weights or architecture that changed. It is the information pipeline. The model now gets a chance to ask itself: what do I need? Then it grabs only that.

The hidden quantity

The hidden quantity: Redundancy and Sufficiency

measured quantity  =  Redundancy (wasted information) and Sufficiency (necessary information)

Every piece of spatial information has a role. Some pieces are necessary: you need the chair's exact location to answer where it is. Some pieces are redundant: knowing the color of the walls does not help because the question is about position, not appearance—adding irrelevant facts just makes the reasoning harder. The paper introduces a way to measure this tradeoff. For each reasoning step, the model asks: do I already have enough to answer? If yes, drop the rest. If no, what am I missing?

The Reasoning Agent estimates this by looping. It makes a plan based on the question. It runs the perception toolbox to gather facts. It then checks: can I reason through the plan with what I have? If yes, done. If no, ask for more. This tight loop—check sufficiency, prune redundancy, refine the plan—is what keeps the minimal sufficient set small and focused.

Why it works

Why asking for less gets better answers

The core reason: a vision-language model trained on 2D images has weak 3D intuition. When you feed it a massive flood of 3D facts, it does not know which ones matter. It treats the lamp's location the same as the chair's location. This confusion compounds when reasoning steps fail to connect the facts properly.

By forcing the model to plan first and then gather only what the plan asks for, you eliminate this confusion. The model's reasoning now sees a clean, minimal story: the chair is at (2, 1, 0.5), the table is at (1, 1, 0.2), the distance is 1.5 meters, the direction is west. Every fact has a role. The model's weak 3D understanding is not challenged by noise—it is given a crutch, a script of exactly what to compute and in what order.

The SOG module matters too. Language like left and west do not map neatly to lists of numbers (3D vectors)—it depends on where the camera sits and which way the room is oriented. SOG uses visual prompting (show the model a picture with the word "west" annotated) to ground directional words into actual lists of numbers consistently. So when the reasoning agent later uses those numbers, it is not guessing. It gets the same answer every time, even when the camera moves.

Math after the picture

The scoring equation for information value

First in words:

For each fact, assign a score combining two parts: how necessary is it for the reasoning plan, and how much noise does it add? The score equals necessity minus noise penalty.

Then the compact form:

value_i = necessity_i - noise_penalty_i

Every symbol:

value_ihow useful fact i is for the reasoning
necessity_idoes the plan actually call for this fact? (0 or 1)
noise_penalty_ihow much distraction does this fact introduce? (0 to 1)
A tiny worked example
Fact 1 (chair location): necessity=1 (plan asks for it), noise_penalty=0 -> value=1.0 (keep)
Fact 2 (wall color): necessity=0 (plan never asks), noise_penalty=0.5 -> value=-0.5 (drop)
Fact 3 (table location): necessity=1 (plan asks for it), noise_penalty=0.1 (slight ambiguity) -> value=0.9 (keep)
Facts with value >= 0.5 stay in the minimal set. Facts below drop.

In practice the loop is iterative: the reasoning agent keeps the high-value facts, reasons through its plan, checks if it succeeded, and if not, requests additional facts that scored just below the threshold.

What can go wrong

What can go wrong

The plan misses a key fact. If the reasoning agent's initial plan forgets to ask for something critical (like the camera angle when computing left-right directions), the minimal sufficient set will be incomplete. The model will reason through its incomplete plan and give a confident wrong answer. The loop catches this only if the reasoning agent detects a gap when trying to reason—but some gaps are subtle.
The perception toolbox does not have the right module. The Perception Agent can only query tools it knows about. If the 3D scene understanding toolkit is missing a module for, say, estimating object size or texture (because textures were not in the training data), the agent cannot ask for it. It will work with partial information.
The SOG module mis-grounds a directional term. The Situated Orientation Grounding module uses visual prompting to map language like west into 3D vectors. If the camera is in an unusual position or the room is rotated, SOG might ground the direction incorrectly, leading the whole reasoning chain astray.
Done right: tight loop, clear plan. When the Reasoning Agent writes a concrete plan, the Perception Agent queries methodically, the SOG module works correctly even when the camera moves, and the loop refines iteratively, the minimal sufficient set stays compact and the model reasons cleanly.
