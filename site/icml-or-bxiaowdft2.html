MotionMAR: Multi-scale Motion Reconstruction from Sparse Tracking Data

Build human motion from partial tracking data by reconstructing from coarse shape first, then adding fine details.

Paper explainersAll themesComputer Vision

When you have only a few markers tracking a human body (like wrists and ankles), filling in the missing joints is hard because the full shape can bend many ways. MotionMAR rebuilds motion in layers: first it recovers the overall body trajectory and pose, then it gradually adds in the fine wiggles and natural smoothness. This mimics how humans actually move—big gestures first, details follow.

Zero assumption version

Sparse motion capture loses too much information

Tracking human motion with only a few markers (wrists, ankles, head) leaves most of the body unseen. To fill in the missing joints, you have to guess what the torso, elbows, knees, and fingers are doing based only on where the endpoints landed.

A naive approach: take the positions you have and fit them to a pose model that predicts everything else at once. This fails because the intermediate parts can fit many different poses to the same sparse observations. The system gets confused and produces jerky, unrealistic motion with sudden jumps or twisted limbs.

The real issue is that human motion has structure: the body first moves as a whole unit (the global trajectory and spine), then the limbs add variations on top. Flat, one-shot pose fitting ignores this hierarchy.

The method in one sentence. Reconstruct motion in layers, starting with the overall shape and then gradually refining in the details.

The algorithm as a flow

What it actually does

Encode into layers

Feed the real motion into an encoder that breaks it into multiple time-scales (every frame, every-other frame, every-four-frames), creating a tree of motion descriptors from coarse to fine.

Compress to discrete codes

Convert each layer into discrete symbols (like words in a dictionary), so the generator can predict one symbol at a time, building motion sequentially instead of all at once.

Predict coarse structure

A neural network starts with the coarsest layer (roughest shape), using attention (a mechanism that focuses on relevant pieces of input) to predict what comes next based on sparse marker positions.

Refine progressively

Working from coarse to fine, each layer refines what came before, adding more joints and more detail at every step.

Polish and constrain

A refinement network smooths out quantization artifacts (rough edges from the discrete codes) and enforces that the sparse markers stay pinned to their true positions.

What the paper changes

What the method changes

MotionMAR changes how motion is predicted: instead of guessing all joints at once from sparse markers, it builds motion in layers, starting with a coarse outline and filling in details.

The hidden quantity

The hidden quantity: multi-scale motion codes

measured quantity  =  temporal hierarchy (coarse-to-fine layers)

Human motion is not random jitter. It has natural layers: large body swings happen slowly (coarse), while hand jitter and foot shuffles happen quickly (fine). The paper measures where each motion component 'lives' in this hierarchy by encoding motion at different time-scales (every frame, every 2 frames, every 4 frames). Each scale produces a set of discrete motion codes (like a vocabulary of poses).

The paper estimates this hierarchy using a multi-scale VQ-VAE (a compression algorithm that learns motion patterns at each scale). At training time, it passes real motion through this encoder and watches which codes activate at each scale. At test time, it uses these learned code patterns to guide reconstruction from sparse markers.

Why it works

Why reconstructing coarse-first works

The mechanism is simple: the big pose is easier to infer from sparse markers than all the details are. When you know your wrists and ankles, you can guess your torso and spine pretty reliably. Once the skeleton backbone is fixed, predicting the remaining fine poses becomes a much smaller search problem.

A neural network operates on discrete motion codes, predicting one time-scale at a time. Starting with the coarsest layer (big body shape every few frames), it uses attention (a focus mechanism) to generate which pose code comes next, conditioned on the sparse marker positions. Then it zooms in to finer time-scales, refining the shape it already committed to. This is more stable than trying to solve for all joints at once, because earlier layers constrain later ones—the backbone is locked in, so the fingers can only jiggle within that constraint.

The scale-aware control module acts as a global anchor: it ensures the generated skeleton still touches the sparse markers at the observed frames. A refinement network then smooths the result and removes discrete artifacts.

The multi-scale prediction loss

First in words:

For each time-scale layer, compare the predicted discrete motion code against the true code at that scale, using cross-entropy loss (penalizing wrong predictions). The total loss sums these penalties across all scales, weighted by learned importance factors.

Then the compact form:

L_total = sum_k ( lambda_k * cross_entropy( predicted_codes_k, true_codes_k ) )

Every symbol:

predicted_codes_kthe discrete motion symbols the network predicts at scale k
true_codes_kthe correct symbols extracted from real motion at scale k
lambda_klearned weight for how much each scale matters
kthe scale index (1=coarse, 2=medium, 3=fine)
cross_entropya measure of how wrong the prediction is (0 if perfect, high if very wrong)
A tiny worked example
Real motion at scale 1 (coarse): body at code 5 (standing pose). Network predicts code 5. Cross-entropy loss: 0 (correct).
Real motion at scale 2 (medium): left arm at code 12 (raised). Network predicts code 8 (lowered). Cross-entropy loss: 2.1 (wrong).
Real motion at scale 3 (fine): finger jitter at code 3. Network predicts code 3. Cross-entropy loss: 0 (correct).
Total loss for this frame: lambda_1 * 0 + lambda_2 * 2.1 + lambda_3 * 0 = 2.1 * lambda_2. If lambda_2 = 1.0, total = 2.1.

The network learns to predict one layer at a time, with each error penalized according to its scale's importance weight.

What can go wrong

What can go wrong

Rare motions or highly ambiguous cases fail. When the sparse markers don't uniquely determine the pose (e.g., hand positions that could belong to multiple arm configs), the method can still pick the wrong one if the training data never saw that posture. Physics-based priors (e.g., joint angle limits) would eliminate impossible poses, leaving only realistic ones to choose from, but MotionMAR learns only from data and doesn't encode these hard constraints.
Discrete codes may introduce artifacts. The motion vocabulary has finite size, so some true motion patterns may not have a close match. The network predicts the nearest code, which can make motion snap or feel slightly unnatural at code boundaries.
Refinement network must be well-trained. If the smoothing and artifact-removal network is undertrained, the output can still look jerky despite the coarse-to-fine strategy.
Done right: multimodal ambiguity is broken early. By committing to a coarse shape first, the network eliminates many false alternatives before they can accumulate errors in finer layers. Each layer refines what came before, not starting from scratch.
