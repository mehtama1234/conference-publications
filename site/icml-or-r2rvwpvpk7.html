Hydra-Nav: Adaptive Dual-Process Reasoning for Object Navigation

A robot learns to find objects by switching between slow careful thinking and fast reactive movement based on the situation.

Paper explainersAll themesRobotics & Control

A robot navigating a building to find a specific object faces a hard trade-off: it can think carefully about where it has already looked and plan its next move, but this is slow, or it can react quickly to what it sees right now, but this often fails to find the object. Hydra-Nav solves this by learning when to think hard and when to react, making the robot both faster and more successful at finding unseen objects.

Zero assumption version

The navigation puzzle: fast but lost, or slow but working

A robot needs to find a specific object—say a lamp—in an unfamiliar building. It starts with no map and no hint where the lamp is. The robot has a camera and a large language model (a trained system that reads images and understands language) that can look at its surroundings and make decisions.

A beginner tries two naive approaches. One: the robot looks at each room, the language model guesses if the lamp is there, and the robot moves to the next room if not. This is fast but fails often—the language model is not always right, and the robot does not learn from its mistakes. Two: the robot remembers every room it has seen and, before each move, thinks hard about where the lamp most likely is. This works better but takes a long time, because the reasoning system must process all prior history and generate a plan before every step—this overhead grows with how many rooms the robot has already explored, so the robot spends more time in reasoning loops than actually moving through new space. The real problem is that some moments need careful thought (when the robot is at a crossroads and needs to choose which hallway to search) and some moments just need a quick reaction (when it sees an obvious room to check next). But the robot does not know which is which.

Current methods do not solve this well. Some always think hard, some always react fast, but neither handles both situations. A smarter approach: the robot should learn to tell the difference.

The problem in one sentence. Robots fail to find objects quickly because they either react too fast without planning or think too carefully and waste time.

The algorithm as a flow

What it actually does

Step 1: Record the journey

As the robot explores, it writes down what it saw in each room and the path it took.

Step 2: Ask the fast system

The reactive module looks at the current room and instantly suggests the next move.

Step 3: Ask the slow system

The deliberative module reviews the map and history and writes a careful plan.

Step 4: The language model chooses

Based on confidence and past mistakes, the language model picks fast or slow.

Step 5: Execute and learn

After success or failure, the system updates which moments to slow down on.

What the paper changes

What the paper changes: the switching mechanism

The core change is building a single decision point inside the language model where it learns to select between two strategies: a fast reactive path that ignores history and a slow deliberative path that reviews what the robot has already seen. The model does not commit to one strategy for the whole task—it can flip between them at every step. This flexibility is new; earlier robot navigation systems pick one strategy and stick with it.

The hidden quantity

The hidden quantity: confidence gaps in exploration

measured quantity  =  Exploration confidence mismatch

The paper implicitly measures a gap: how often the language model is confidently wrong versus confidently right. This gap reveals which moments need thought. If the language model confidently picks a room but then discovers the lamp is not there, it made a high-confidence mistake—a moment that needed the slow system. If it confidently finds the lamp, the fast system worked. By training on which decisions led to mistakes, the model learns to flag high-confidence mistakes and trigger the slow system on future mistakes of the same kind.

The paper does not formally name this quantity, but the curriculum learning—the three-stage training process—is tuned to expose these gaps. Stage 1 trains basic spatial reasoning so both systems work. Stage 2 trains the model to remember where it has been and reason over time, building the slow system's map. Stage 3 uses rejection fine-tuning: the model learns to say 'I need to think harder' at moments where its quick guess would be wrong. This teaches the switch exactly when confidence gaps matter most.

Why it works

Why it works: learning when guessing fails

The robot's language model is trained to reason in three stages. Stage 1 builds basic skills: the language model learns to link where the robot is now to what action makes sense spatially (spatial-action alignment). This creates a workable fast system. Stage 2 adds long-horizon memory: the model learns to remember the exploration history and formulate plans that use it (memory-reasoning integration). This creates the slow system. Both stages train both paths in parallel.

Stage 3 is the key move. The model is fine-tuned using rejection: it sees trajectories that ended in failure (robot never found the object) and learns that whenever the fast-only path was chosen on those trajectories, that choice led to the failure. By contrast, the slow path would have worked. The model learns a simple lesson: flag moments where fast guesses are risky. The model learns not to flag every moment—that would bring back the slowness problem. Instead, it learns the pattern: which kinds of moments (ambiguous rooms, critical junctions, long gaps since the last confirmed sighting) are high-risk. At those moments, it raises its hand and uses the slow system. At safe moments, it lets the fast system run.

The reason this works is that the language model can learn this pattern by comparing failed and successful trajectories. It builds internal representations of 'risky moment' and 'safe moment' and learns to choose accordingly. The rejection fine-tuning compresses this learning by only showing the model the moments where a mistake happened, forcing it to be efficient. The efficiency matters: a robot that deliberated on every decision would never finish exploring; one that guesses blindly would never find anything. Learning to pick the risky moments turns the two naive extremes into a working strategy.

The routing score and adaptive choice

First in words:

Router score equals base confidence multiplied by learned risk adjustment, where risk adjustment starts high when the robot has made recent mistakes and falls as the robot builds certainty.

Then the compact form:

route_score(t) = confidence_fast(t) * (1 - risk_penalty(t)) ; if route_score(t) > threshold : use_fast else use_slow

Every symbol:

route_score(t)The decision value at timestep t, combining fast-path confidence and learned risk penalty.
confidence_fast(t)How sure the fast path is about its next-room guess, on a scale from 0 to 1.
risk_penalty(t)A learned weight from 0 to 1, high when the robot recently made mistakes or is at an ambiguous choice point.
thresholdA cutoff value: if route_score exceeds it, trust the fast path; otherwise invoke slow reasoning.
A tiny worked example
Moment 1: Robot in bedroom, confident it should check hallway. confidence_fast = 0.95, risk_penalty = 0.1 (low, hallways are safe). route_score = 0.95 * (1 - 0.1) = 0.855. Above threshold 0.7? Yes. Use fast system. Outcome: correct, hallway has next clue.
Moment 2: Robot at a 5-way junction. confidence_fast = 0.72 (uncertain), risk_penalty = 0.6 (high, junctions are decision-critical). route_score = 0.72 * (1 - 0.6) = 0.288. Above threshold? No. Use slow system. The slow path reviews history and picks a better hallway. Outcome: finds lamp.
Same confidence (0.72) at a safe moment (corridor) would score 0.72 * 0.95 = 0.684, below threshold. At the junction it scores 0.288. Risk penalty makes the hard moment invoke slow reasoning.

The risk penalty is learned during Stage 3 training by comparing failed trajectories (where fast was wrong) to successful ones (where slow or mixed routing was right).

What can go wrong

What can go wrong

Over-reliance on fast path in new environments. If the robot is deployed in a very different kind of building (e.g., a large open warehouse vs. the tight hallways it trained on), the learned risk penalties may not transfer. The fast path stays confident in situations where it should be cautious, and the slow system is not invoked when needed.
Curriculum learning does not converge. If the three-stage training is run in the wrong order or with bad hyperparameters, the model may fail to build the slow system before rejection fine-tuning begins. Then Stage 3 trains the router to avoid a broken slow path, and the method collapses to fast-only behavior.
Risk penalty becomes too cautious. If rejection fine-tuning overweights failure trajectories, the risk penalty can grow so large that the robot calls for slow reasoning on nearly every step, defeating the purpose and bringing back slowness.
Done right: learned switch generalizes. When the three-stage training is tuned well, the robot learns to recognize risky moments—e.g., 'ambiguous choice points' or 'places I have been uncertain before'—in a way that works across different buildings, and the adaptive routing strategy succeeds.
What a runnable demo should prove

What a runnable demo should prove

Build a simple grid-world navigation task: a 5x5 grid where the robot (starting at one corner) must find a hidden object (placed at a random location). At each step, the robot can move to an adjacent cell or declare 'I found it'. The robot sees only the cell it is in and a history of cells it has visited. Implement a fast system that guesses the next move based on unvisited cells only, and a slow system that plans using the full history. Implement the router as a learned set of weights (numbers that scale different signals) that predicts, given the current cell and history, whether to use fast or slow. Train the router on trajectories where the object is randomly placed in different locations, marking which moments the model chooses wrong. Then test on a held-out object location and measure: (1) success rate (did it find the object?), (2) steps taken, and (3) a mixed-routing metric (what fraction of its decisions did it defer to slow reasoning?).

efficiency = (success_rate) * (1 - (avg_steps_taken / max_allowed_steps)) * (1 - (fraction_slow_steps / total_steps))

The demo must show that pure fast fails quickly, pure slow works but takes too many steps, and adaptive routing finds a middle ground—high success, reasonable step count, and selective slow reasoning only at hard moments.
