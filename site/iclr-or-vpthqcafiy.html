LayerNorm-Free Language Models

Language models can work without LayerNorm layers, making it easier to trace how each component affects the final answer.

Paper explainersAll themesInterpretability

Every large language model uses LayerNorm, a smoothing step applied between computational blocks to keep numbers stable during training. But this smoothing hides how individual components work together. The paper shows that LayerNorm is not actually needed to make GPT-2 work at inference time — removing it only slightly hurts performance. Freed from LayerNorm, we can now see exactly how each piece of the model contributes to the final answer.

Zero assumption version

Why LayerNorm hides how models think

When a language model answers a question, each internal layer reads the previous layer's output, computes something, and passes it forward. A beginner would think you could just add up each layer's contribution to the final answer. But LayerNorm, the smoothing step, rewrites all the numbers before each layer sees them. This rewiring scrambles the signal: you can no longer tell which input caused which output.

Mechanistic interpretability is the science of reverse-engineering how a model works by reading its internals. The goal is to identify specific circuits — pathways through the network that encode human-understandable ideas like 'does this sentence have a negative word' or 'the subject of the sentence is in the past tense'. LayerNorm breaks this detective work by introducing extra nonlinear (wiggly, unpredictable) distortions between every two layers, making the causal path impossible to trace.

The setup. A language model reads text token-by-token (word by word), passes each through many layers, and picks the next word. LayerNorm sits between layers, smoothing numbers to keep training stable.

What the paper changes

The single thing that changes

The paper removes all LayerNorm layers from the model. This is not a tiny tweak to one weight — it is a structural deletion. The model now computes forward without any smoothing step between layers.

the object it moves  =  LayerNorm layers
The hidden quantity

Direct component contribution

measured quantity  =  True contribution to final scores

Normally, LayerNorm scrambles inputs so deeply that we cannot compute 'how much did layer 3 really contribute to the answer?'. With LayerNorm present, the answer is tangled with LayerNorm's rewiring — there is no clean signal.

In a LayerNorm-free model, each layer's output feeds directly into the next layer without distortion. The paper measures this by running 'logit attribution' — zeroing out one component at a time and seeing how much the final score (logit) for the next word drops. Without LayerNorm, this drop is the REAL contribution; with LayerNorm, the same measurement is confounded by LayerNorm's scrambling.

With LayerNorm, the question itself is broken — LayerNorm scrambles the numbers so much that 'erasing one part' no longer means what you think it means.
Paper reading. The paper tests 'logit attribution' (one technique for measuring component importance) on both normal and LayerNorm-free models. On LayerNorm-free models, the attribution tells the true causal story. With LayerNorm, the same attribution gives confounded results.
Why it works

Why removing LayerNorm does not break the model

During training, LayerNorm keeps the numbers stable — without it, weights drift into extreme values and training crashes. But once training is done and you are just running the model to generate answers (inference), LayerNorm is not actually protecting anything. The weights are already settled into a region where they work.

When LayerNorm is removed, the model weights can adjust slightly (during light retraining) to compensate. They shift just enough that raw numbers stay in a reasonable range without needing smoothing. This is why the loss barely increases — the model is not losing the ability to do the task, it is just routing information differently. The tradeoff is worth it: clear interpretability in exchange for a microscopic performance dip.

The retraining loss

First in words:

Total loss equals original task loss plus a tiny penalty if the model drifts far from the original weights

Then the compact form:

L = L_task + alpha * sum_i (theta_i - theta0_i)^2

Every symbol:

Ltotal loss (how wrong the model is)
L_taskprediction loss (does it guess the next word right)
alphahow hard we push it to stay close to the original
theta_ithe current weight i
theta0_ithe original weight i from the LayerNorm model
sum_iadd up the penalty for every weight
A tiny worked example
Imagine alpha = 0.001 (very weak penalty).
Weight w1: original 0.5, retraining tries to move it to 0.6 (0.1 change).
Penalty = 0.001 * (0.6 - 0.5)^2 = 0.001 * 0.01 = 0.00001 (tiny).
Weight w2: original 2.0, retraining tries to move it to 3.0 (1.0 change).
Penalty = 0.001 * (3.0 - 2.0)^2 = 0.001 * 1.0 = 0.001 (still small).
The task loss improves, but the weights barely drift. Model stays close to original, needs only light retraining.

Light retraining keeps weights from drifting far by adding a small penalty for large changes, so the model can drop LayerNorm without relearning everything from scratch because it stays anchored to the trained starting point.

What can go wrong

What can go wrong

Removing too much at once. If you delete LayerNorm and do not retrain at all, the model fails immediately. Numbers explode or become inconsistent. The retraining step is mandatory.
Not enough retraining data. If your retraining dataset is tiny, the model may overfit or forget the task. The paper shows this breaks below a certain threshold (though the threshold is still small compared to original training).
Larger models need careful tuning. The paper tests GPT-2 Small, Medium, Large, and XL. Larger models need more retraining data, and the tuning becomes more finicky (learning rate, batch size, convergence checks).
When done right. With light retraining on a small but clean dataset, the loss delta stays under 0.05 and interpretability gains are substantial.
What a runnable demo should prove

What a runnable demo should prove

Build a small GPT-2 model (Small or Medium size), train it normally on a subset of a text corpus (e.g. 10 million tokens), then remove all LayerNorm layers and retrain for a few epochs on the same subset. Record the validation loss before and after.

Loss increase = Loss_no_ln - Loss_baseline

If loss increase is under 0.05, the model works. Then run logit attribution on both versions: the LayerNorm-free version will show clean, traceable paths; the original will show tangled ones.
