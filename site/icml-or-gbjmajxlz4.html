Mantis: Lightweight Foundation Model for Time Series Classification

A model trained on fake data learns to recognize patterns in real time series data by learning to break streams into small coherent pieces first.

Paper explainersAll themesTime Series & Sequential

Machine learning models that handle long sequences of numbers (like temperature readings over weeks or stock prices over months) are hard to build well. This paper introduces Mantis, a model pre-trained on synthetic (fake) time series data that learns to recognize what category a sequence belongs to. The core idea: before the model can classify a series, it must learn how to split the stream into small coherent chunks—the way you divide a paragraph into words before understanding it.

Zero assumption version

Why time series classification is stuck

You collect hours of sensor readings—temperature, pressure, vibration—and need to label each sequence as normal or faulty. The challenge: the sequences are long (thousands of numbers), the patterns are subtle, and building a model from scratch requires tons of labeled real data.

A naive approach: hand each raw value to the model. This fails because the model sees 5,000 disconnected numbers and has no way to learn that measurements 10–50 together form one coherent pattern, while measurements 50–100 form a separate unit. The model drowns in noise.

The core problem. A model that sees time series as isolated numbers, not chunks, cannot learn to spot real patterns and needs huge amounts of labeled data to train.

What the paper changes

What the paper changes

Mantis introduces a token generator—a small neural unit that learns to divide a time series into discrete chunks before the main model sees them. Instead of a transformer (a type of model that reads sequences) ingesting raw numbers, it ingests pre-chunked tokens. This one change forces the model to learn the structure of time series as a preprocessing step.

the object it moves  =  how time series are split into tokens
The hidden quantity

The hidden quantity: tokenization quality

measured quantity  =  how well a token captures one coherent time pattern

Behind Mantis is an unmeasured but core quantity: the quality of the tokens the generator produces. A good token groups numbers that represent one stable pattern (e.g., three seconds of steady rise, then a plateau); a bad token mixes unrelated spikes.

The paper does not explicitly measure this, but it is inferred from the model's ability to learn contrastive patterns (where two similar chunks pull together and dissimilar ones push apart). When two chunks are genuinely similar, they should produce similar internal representations in the model; when they differ, the representations should diverge. The token generator is judged by whether the downstream model learns clean contrasts.

Why it works

Why it works: the causal chain

The mechanism unfolds in three steps. First, the token generator learns to spot natural boundaries in the time series—where the pattern shifts—and cuts there, producing a small sequence of tokens. Second, the model pre-trains on synthetic data using contrastive learning: for any token, the model learns to predict similar tokens and distinguish them from random others. This forces the model to build internal representations that capture genuine time-series structure. Third, when applied to a new, real time series, the model's chunking and learned representations transfer: the tokenization generalizes to real data, and the model knows which patterns matter.

Why does pre-training on synthetic data work? Because the synthetic data is structured and noiseless, the model has an easier time learning the grammar of time series (how patterns repeat, how they transition). Once learned, this grammar applies to real data. The token generator is the key: it lets the model operate on coherent chunks, not raw noise. Test-time fusion (combining predictions from different model depths and ensemble variants) further refines the answer by pooling information from multiple learned views.

Math after the picture

The contrastive learning equation

First in words:

For each token, the model learns to pull its representation close to the representation of a similar token and push it away from unrelated tokens, weighted by temperature.

Then the compact form:

L = -log( exp(sim(z_i, z_i+) / tau) / sum_j exp(sim(z_i, z_j) / tau) )

Every symbol:

z_ithe internal representation of token i (a list of numbers learned by the model)
z_i+the representation of a token that is genuinely similar to token i
z_jthe representation of any other token in the batch
sim(a, b)how much the two representations agree (dot product, then normalized)
tautemperature: controls how sharp the contrast is (smaller tau makes the model more strict)
lognatural logarithm; the sum measures how much harder the similar token stands out compared to all others
A tiny worked example
Suppose we have three tokens: a rising pattern (token 1), another rising pattern (token 2, similar to 1), and random noise (token 3).
Token 1 representation: z_1 = [0.8, 0.6].
Token 2 representation: z_2 = [0.75, 0.65] (similar to z_1).
Token 3 representation: z_3 = [0.1, 0.2] (different from z_1).
With tau = 0.1:
sim(z_1, z_2) = 0.96 (high, rising + rising).
sim(z_1, z_3) = 0.02 (low, rising vs. noise).
exp(0.96 / 0.1) = exp(9.6) ≈ 14688 (huge, for the similar pair).
exp(0.02 / 0.1) = exp(0.2) ≈ 1.22 (small, for the noise).
Fraction: 14688 / (14688 + 1.22) ≈ 1.0 (loss ≈ 0, the model got it right).
The model is strongly rewarded when similar tokens cluster and dissimilar ones spread apart.

This equation forces the model to group tokens with similar time-series patterns together and push dissimilar ones far apart, because large rewards push similar tokens toward one shared representation, while large penalties push noise away from real patterns, building internal representations that capture the true structure.

What can go wrong

What can go wrong

Token generator overfits to synthetic patterns. If the fake data is too simple or repetitive, the learned chunks may not generalize to real time series that contain unexpected, out-of-pattern behaviors. The model chunks well on data it has seen but fails on new sensor quirks.
Temperature (tau) set wrong. Temperature is a number that controls how strict the contrast is. If it is too high, the model treats all tokens as equally similar and learns nothing. If it is too low, the model becomes brittle and overconfident, punishing small variations harshly.
Domain mismatch between synthetic and real data. If the synthetic data does not reflect the statistical properties of the real sensor readings (e.g., different noise levels, different pattern frequencies), the pre-trained tokenizer will chunk the real data poorly.
Done right: diverse synthetic data with realistic noise and clear patterns, careful temperature tuning, and test-time fusion to smooth out mistakes. Mantis achieves strong results by combining synthetic pre-training with techniques that hedge against individual model errors.
What a runnable demo should prove

What a runnable demo should prove

Build a minimal time series classifier: generate 100 synthetic sequences (50 normal, 50 with a sudden spike), train a model with and without the Mantis token generator, and measure classification accuracy on a held-out test set of 20 real sequences (which have realistic noise). The demo should show that tokenization-first (Mantis approach) learns faster and reaches higher accuracy than tokenization-last (baseline), because a model that operates on coherent chunks sees clearer patterns and updates more efficiently than one that must parse 5,000 separate numbers.

accuracy = (number of correct classifications) / (total sequences)

The demo makes it impossible to miss this core claim: grouping numbers into coherent chunks before training, rather than leaving the model to discover chunks on its own, is the difference between a model that learns well and one that flails, because chunk-first training lets the model see real patterns clearly, while chunk-last training forces it to extract patterns from noise.
