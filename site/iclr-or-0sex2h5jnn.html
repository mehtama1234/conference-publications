CogniLoad: Tunable Logic Puzzles for Measuring Reasoning

CogniLoad is a benchmark that creates logic puzzles where three separate dials control task difficulty, allowing researchers to measure where exactly a reasoning model breaks.

Paper explainersAll themesDatasets & Benchmarks & Evaluation

Current reasoning benchmarks mix three kinds of difficulty together, so you cannot tell which one is actually breaking your model. CogniLoad separates them: puzzle complexity, clutter, and length are turned independently like knobs on a mixer, so you see exactly what your model struggles with.

Why current benchmarks are muddy

Today's tests for reasoning combine three different things at once. A puzzle is long, it has complex rules, and it buries the real question in noise. When a model fails, you do not know which one broke it — is it choking on the length, confused by the rules, or buried under distractors? You cannot tell.

A beginner might try: take a hard puzzle, make it longer, and add more noise, then run it. But then you have confounded all three things. You cannot slice them apart to find the real bottleneck.

In one sentence. CogniLoad generates logic puzzles where you dial three difficulty knobs independently: puzzle complexity, distractor clutter, and task length.

The algorithm as a flow

What it actually does

Start a puzzle

Pick three knob settings: how complex, how cluttered, how long.

Generate the puzzle

Randomly build a logic puzzle (people, attributes, facts) matching those settings.

Run the model

Feed the puzzle to an LLM and ask it to answer the hidden question.

Measure three sensitivities

Fit a curve to see: how does accuracy drop as each knob turns up alone?

Read the fingerprint

One model hits a wall at length 50, another at 70 clutter items—you see the real ceiling.

What the paper changes

What changes

The paper changes the benchmark itself. Instead of handing the model a fixed set of hard puzzles, it builds puzzles on the fly, with three independent dials you can turn: complexity (how tangled the logic is), clutter (how many fake facts to ignore), and length (how many steps to chain). Each dial is separate, so you can measure them one at a time.

The hidden quantity

The 'cognitive fingerprint'—how the model breaks

measured quantity  =  Load sensitivity curve for each dimension

A hidden quantity the paper measures is the model's sensitivity to each dial. For a fixed model, as you turn up the complexity knob, accuracy drops in a certain shape. Turn up clutter—different shape. Turn up length—yet another shape. The paper fits a curve to each sensitivity, extracting a single threshold number for each model on each knob (called N_T50: the point where accuracy falls to 50 percent). By comparing these three thresholds, you see the model's weak point: does it break first on complexity, clutter, or length?

The paper estimates this using regression: it runs the model on many puzzles at different knob settings, plots accuracy against each knob separately, and fits a curve to extract the threshold number. This gives a three-number fingerprint per model, revealing which dimension hits the wall first.

Why it works

Why three independent knobs work

The paper is built on Cognitive Load Theory, an idea from how human minds work: when you solve a problem, three things eat your mental budget. First, the problem's intrinsic difficulty—the logic is just hard (controlling many attributes, long chains of deduction). Second, extraneous load—irrelevant noise that wastes your thinking. Third, germane load—steps that help you solve it (holding intermediate conclusions, building up the answer), which is necessary work because you cannot reach the answer without doing those steps. The theory says: the harder each one is alone, the more your total capacity gets used, and the sooner you fail.

The paper applies this to LLMs: give the model a puzzle where you can dial these three separately, and see which one fills up its capacity first. By measuring accuracy as you turn each knob up alone, you isolate the model's true bottleneck. Unlike old benchmarks that mix all three together (so you cannot tell which is the culprit), CogniLoad lets you accuse each one separately.

The load dimensions as knobs

First in words:

Intrinsic difficulty d controls the number of people and attributes; distractor ratio ρ controls the fraction of fake facts mixed in; task length N is the number of reasoning steps. A model's accuracy at each setting follows roughly a curve (logistic sigmoid), and the paper finds the knob value where accuracy hits 50 percent for each dimension separately.

Then the compact form:

N_T50_d = argmax(d) where accuracy(d, ρ_mean, N_mean) = 0.5; similarly for ρ and N. Overall, accuracy ≈ sigmoid(β_d * (d - N_T50_d) + β_ρ * (ρ - N_T50_ρ) + β_N * (N - N_T50_N))

A tiny worked example
Model A tested on puzzles with d=3 (3 attributes), varying only complexity: accuracy at d=2 is 95 percent, at d=3 is 80 percent, at d=4 is 50 percent → N_T50_d = 4.
Same Model A tested on varying length N (keeping d fixed): N=10 is 90 percent, N=20 is 70 percent, N=30 is 50 percent → N_T50_N = 30.
Same Model A tested on varying clutter ρ: ρ=0.3 (30 percent noise) is 85 percent, ρ=0.6 (60 percent) is 60 percent, ρ=0.8 (80 percent) is 40 percent → N_T50_ρ ≈ 0.65.
Fingerprint: [N_T50_d=4, N_T50_ρ=0.65, N_T50_N=30]. Length is the softest ceiling; clutter and complexity are harder to push past. This model's bottleneck is length.

Each knob turns independently; a curve through the data finds the 50-percent-accuracy point for each one, revealing the order in which the model runs out of steam.

What can go wrong

What can go wrong

If the puzzle generator is biased. If the random puzzle builder accidentally makes complex puzzles longer than simple ones, then d and N are no longer independent. The regression will be confounded and the fingerprint will be wrong. Careful initialization and validation are needed.
If the model can pattern-match the puzzle instead of reasoning. If an LLM has seen similar logic puzzles in training, it may memorize templates rather than actually solve the problem step by step. The benchmark then measures memorization, not reasoning capability.
If the model fails catastrophically at one knob. If a model hits zero percent accuracy on clutter at a certain noise level, you cannot fit a curve anymore. The regression fails, and you lose that model's fingerprint on that dimension.
Done right. Generate many puzzle instances per setting, validate that independent knobs really are independent, and use regression methods that handle noisy or gappy accuracy curves.
What a runnable demo should prove

What a runnable demo should prove

A demo should: (1) implement the puzzle generator (people with attributes, statements that update attributes, validation that the puzzle is solvable); (2) run an open LLM on 20 to 30 puzzles at each of five settings per knob (e.g., complexity in {1,2,3,4,5}, clutter in {0.1,0.3,0.5,0.7,0.9}, length in {5,10,15,20,25}), recording pass or fail; (3) fit a logistic regression curve to each knob's accuracy vs. setting; and (4) extract and print the three threshold numbers for each knob. Plot accuracy vs. each knob as a separate curve. The demo proves that the three knobs are truly independent: one model may hit its length ceiling early, another at medium length, and a third at higher length, but the complexity and clutter ceilings are different for each. This shows that the benchmark isolates real, separable dimensions of reasoning.

accuracy-threshold on complexity; accuracy-threshold on distraction; accuracy-threshold on length. Fingerprint combines these three numbers. Smaller numbers mean earlier failure.

The model's three thresholds tell you exactly which bottleneck to attack first, because once you know the order in which each dimension fills the model's capacity, you can retrain on long chains, boost noise filtering, or deepen the reasoning engine in the right sequence rather than guessing.
