Query-Level Uncertainty in Large Language Models

Ask a language model if it can answer a question BEFORE it speaks, by listening to its self-doubt at every layer.

Paper explainersAll themesLLMs & Foundation Models

Language models often produce confident-sounding wrong answers. If we could ask them before they start answering, we could send hard questions to a search engine and easy ones straight to the model. This paper proposes a simple trick: ask the model "Can you answer this?" and listen to how it answers across all its internal layers. When multiple independent layers all say yes, the model is drawing on knowledge it has already built up; when they say no, it has not yet formed an answer. By tallying their votes before output begins, we get a fast signal of whether the model truly knows.

Zero assumption version

Models answer without self-awareness

Today, large language models process a query and output an answer word by word, never pausing to ask: do I actually know this? When a model is uncertain, it just keeps talking confidently anyway. A naive solution would be to let the model finish, then ask it to rate how sure it is about its own answer—but that is slow and wasteful, since you have already generated 50 words for a question the model never knew the answer to.

The cost adds up fast in real systems. If you are using a language model to answer customer questions and want to send unknowns to a human or a search engine, you waste compute on every wrong hunch. Similarly, if you are chaining multiple models—using a small fast one first, then a big slow one only when needed—you cannot make that routing decision until the small model has already spoken. You are stuck paying the cost before you know the answer. In one scenario, the model has already generated many words of an answer (producing one word at a time, like how these models work) that turned out to be wrong.

The trick: Before the model generates any answer token, ask it internally: can you solve this query? Listen to its self-assessment at every layer and combine the signals into a single confidence score, all without any training.

The algorithm as a flow

What it actually does

Input the query

Feed a question into the language model like normal.

Pause after encoding

Stop before the model generates any answer tokens.

Ask at each layer

Prompt the model: "Can you answer this query? Yes or no?" Measure the probability it assigns to Yes.

Aggregate the votes

Combine the Yes-probabilities from all layers, weighting deeper/earlier responses more heavily based on attenuated encoding.

Decide and route

If the combined score is high, let the model answer. If low, invoke retrieval or route to a human.

What the paper changes

What the paper changes

The paper shifts the timing of the confidence check from after-generation (wait for the full answer, then ask how sure you are) to before-generation (ask if the model knows, before it speaks). Most existing work on uncertainty measures the quality of an answer that has already been produced. This paper measures whether the model can produce a correct answer before any output token is generated.

the object it moves  =  timing of uncertainty measurement
The hidden quantity

The hidden quantity: layer-wise self-assessment

measured quantity  =  Internal confidence signal

The hidden quantity is how strongly each internal layer of the model asserts that it can answer the query. A language model has dozens of stacked processing layers. Early layers see the raw words; later layers see refined concepts. When you ask each layer the yes-no question internally, each one produces a probability: that is the signal. Most research ignores this—they only look at the final output. This paper says: each layer's private opinion is worth collecting.

The method computes this by running the yes-no prompt through the model, but instead of looking at the final layer's verdict, it records the Yes-probability at every layer and token position. Then it combines them with a weighted average. The weights themselves follow a pattern called attenuated encoding—a decay function that gives more influence to certain positions and less to others, similar to how you might trust recent news more than old rumor.

Why it works

Why it works: layer-wise self-doubt is honest

A language model is a stack of processing layers. When you feed it a question, each layer refines the understanding further. Early layers notice basic syntax and semantics; middle layers connect concepts; late layers prepare the output distribution. Each layer has built up enough information to form an opinion: can this query be answered with what I know?

If you ask the question "Can you answer this?" directly at each layer, you get a probability for yes. This is cheap—it is just an extra forward pass with a different prompt, no training needed. What matters is that layers deep inside the model have already ingested the full query context and formed a judgment. The final layer does too, but it is biased toward saying yes (because it is about to generate an answer). The middle layers are more honest: they have seen enough to know, but not yet committed to a response.

By collecting the yes-scores across all layers and combining them with a weighted average, you get a signal that can tolerate any one layer's confusion. If the model truly does not know the answer, most layers will whisper no. If it knows, layers will converge on yes. This combination is more reliable than trusting just the final answer-probability, because no single layer can mislead you—the majority vote prevails.

Math after the picture

The equation: weighted voting across layers

First in words:

For each input token n and layer l, compute the probability that token n at layer l assigns to the answer YES. Then take a weighted sum: for each token position, average the layer-wise probabilities using layer weights. Then average those token-averages using token weights. The weights themselves come from attenuated encoding, a decay function that reflects which positions and depths are most informative.

Then the compact form:

confidence = (1/N) * sum_n w_token[n] * (1/L) * sum_l w_layer[l] * P(YES at layer l, token n)

Every symbol:

confidencethe final score: how much the model knows (0 to 1)
Nthe number of tokens in the input query
Lthe number of layers in the model (e.g., 48)
P(YES at layer l, token n)probability that layer l, at token n, assigns to the word YES
w_layer[l]weight for layer l: higher for mid-to-late layers, lower for early
w_token[n]weight for token n: follows attenuated decay pattern
attenuated encodinga decay function that smoothly reduces the weight of distant/early items
A tiny worked example
Suppose we have 5 tokens and 4 layers.
Layer 0: [0.3, 0.4, 0.5, 0.4, 0.3] (layer weight 0.2)
Layer 1: [0.5, 0.6, 0.7, 0.6, 0.5] (layer weight 0.3)
Layer 2: [0.7, 0.8, 0.85, 0.8, 0.7] (layer weight 0.3)
Layer 3: [0.6, 0.7, 0.75, 0.7, 0.6] (layer weight 0.2)
Token weights: [0.15, 0.25, 0.30, 0.25, 0.15] (sum = 1.0)
For token 0: average across layers = 0.2*0.3 + 0.3*0.5 + 0.3*0.7 + 0.2*0.6 = 0.54
For token 2 (middle): average = 0.2*0.5 + 0.3*0.7 + 0.3*0.85 + 0.2*0.75 = 0.71
Final score = 0.15*0.54 + 0.25*0.6 + 0.30*0.71 + 0.25*0.65 + 0.15*0.54 ≈ 0.63
A score of 0.63 means the model is moderately confident it knows the answer.

Each layer whispers its confidence independently; the weights amplify honest middle layers and dampen overconfident early and final layers; the sum gives a single number the system can use to route queries.

What can go wrong

What can go wrong

Overconfident early layers. If weights are not calibrated, early layers that have not yet processed the full query can dominate the signal. The attenuated decay is designed to fix this, but if the decay is too shallow, you lose the benefit.
Model hallucination on the yes-no prompt itself. A model can lie or be uncertain about its own knowledge. If the model is trained to always sound helpful, it may say yes even when it cannot answer. The method is honest only to the degree the model's internals are honest.
Domain shift. If the model was trained mostly on one kind of query (e.g., factual questions) and you use it on a different kind (e.g., code generation), the internal confidence calibration may be off. Reweighting may be needed per domain.
Done right: layer diversity. Combining signals from many layers smooths out individual layer quirks. If five layers out of 48 are confused, the ensemble signal is still strong. That redundancy is the method's strength.
What a runnable demo should prove

What a runnable demo should prove

Build a small retrieval-augmented generation (RAG) system. Create two sets of queries: one that the model can answer from its training data (e.g., basic history or math facts), and one it cannot (e.g., today's news or niche technical details). Run both through the language model with the internal confidence score computed before any tokens are generated. For each query, if confidence is high, let the model answer directly; if low, invoke a search engine and use the search result to ground the answer. Measure how many queries routed correctly (known queries answered by the model, unknown queries sent to search) versus how many mis-routed.

accuracy = (correct_direct_answers + correct_search_answers) / total_queries

The demo is successful if the internal confidence score predicts which queries will be right and which will be wrong, without ever generating a wrong answer token. The payoff is that you save compute on low-confidence queries.
