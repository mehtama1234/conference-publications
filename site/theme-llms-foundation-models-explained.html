LLMs & Foundation Models

How can we build language models that reason carefully, follow instructions precisely, run efficiently, learn from limited data, and know what they actually know?

What this whole area is about

Large language models are AI systems that predict text one word at a time, like someone who can finish your sentence. They work by learning patterns from billions of examples during training, then using those patterns to generate new text when you ask them a question. The reason researchers focus so heavily on these models is that they turn out to be surprisingly good at almost everything: writing code, answering questions, summarizing documents, translating languages, and reasoning through problems. But they are not magic—they are giant pattern-matching machines, and every task they do well requires finding the right way to train them and use them.

The hard part is that larger models get better at almost every skill, but training them requires enormous amounts of computation, electricity, and time. A model that works well on one task might fail on another because it has not been trained the right way. Models often sound confident when they are actually wrong, they struggle to follow precise instructions, and they waste computation by processing every word the same way even when some words are more important. Building these systems today means solving puzzles on almost every front: how to teach a model to think through a problem step by step instead of rushing to an answer, how to make it small enough to run on a phone while keeping it smart, how to train it on realistic data when you do not have infinite examples, and how to know when it has actually learned something versus when it is just guessing. The gap between what is possible and what works in practice is enormous.

Researchers tackle these problems from multiple angles. Some focus on the training process itself—finding better ways to adjust the model's weights so it learns faster and better from real-world feedback, which compresses months of training into weeks. Others work on making models more efficient, either by shrinking them after training or by training them smarter from the start, so they run on regular devices. A big group studies how to steer models toward better behavior through fine-tuning and reinforcement learning so they follow instructions precisely and reason carefully, which makes them usable in real products. Others dig into the mechanics of how these models work internally, trying to understand what happens inside the billions of weight values—the numbers that control the model's behavior—and using that understanding to improve them, because you cannot fix what you do not understand. And some push on specialized skills like writing code or proofs where getting the right answer is provable, which means feedback is reliable.

These problems matter because language models are now embedded in millions of applications—search engines, writing assistants, customer service bots—and every improvement in how well they reason, how small they can be, or how reliably they follow instructions touches real people. The research also has scientific interest: these models reveal something about what it takes for a system to learn human language and reasoning patterns from data alone, which is a question people have wondered about for decades.

Subtheme

Teaching models to reason step by step

When you ask a model a hard math problem or a riddle, the model's default behavior is to rush to an answer immediately. But humans solve hard problems by working through them—writing down intermediate steps, checking if each step makes sense, backtracking when stuck. Papers in this area teach models to do the same thing. Instead of training a model to jump straight from question to answer, researchers set up training so the model learns to generate its own intermediate reasoning first, because working through the steps helps catch mistakes. The model writes out its thinking, then uses that thinking to arrive at the final answer, so each step builds on the previous one. This turns a problem that feels impossible into one the model can actually solve.

The challenge is that simply adding reasoning steps does not automatically work—the model has to learn what kinds of steps are actually helpful, and it has to receive feedback on whether its reasoning was correct. This is why papers in this area lean on reinforcement learning, where the model gets rewarded for reaching the right answer and learns which paths of reasoning lead there. Some papers also use feedback from human annotations or from checking answers against known correct solutions. The insight is that the path matters: two models with the same raw ability might behave very differently if one of them has learned to stop and think while the other just guesses.

The practical result is that models trained this way solve hard problems more often than models that race to answers. Because this works so well, it has become a core technique in modern systems—some of the most capable reasoning models today use reasoning steps as a basic building block. The tricky part is that longer reasoning takes more computation, so researchers also study how to make reasoning efficient and how to know when to use it versus when a direct answer is fast enough.

Subtheme

Making models smaller and faster without losing power — so they run on phones instead of data centers

The most capable language models today are enormous—they have billions or even trillions of parameters, which means they require expensive GPUs to run and can only work on servers, not on your phone or laptop. But many tasks do not need the full power of a giant model. Papers in this area tackle the question of how to take a large, smart model and compress it into something smaller that still works well. The main techniques are quantization, which means storing numbers with less precision so they use less memory, and distillation, which means teaching a small model to imitate the behavior of a large one. The small model learns from the large model's outputs and becomes an approximation of it.

The tricky part is that smaller is not always simpler—a model that is too small will fail at tasks the original handled easily, which means you lose capability. Researchers have to figure out which parameters matter most and which can be removed or simplified without hurting performance. They also face a speed versus accuracy tradeoff: aggressively quantizing a model makes it fast but inaccurate because you throw away information, while keeping it more precise takes more time to run because there is more data to process. Some papers study how to quantize strategically so different parts of the model are compressed differently based on how sensitive they are, which means some parts lose more precision than others because they matter less.

The payoff is huge: a small, fast model can run on a phone and give answers in milliseconds instead of seconds, which means users get instant feedback. This opens up use cases that were impossible before, like offline assistants (no internet needed), real-time translation on mobile devices, or local processing that does not need to send data to the cloud, which protects privacy. As phones and edge devices get faster, finding the right tradeoff between model size and quality becomes increasingly important for making AI accessible, because edge devices are where most people will interact with AI.

Subtheme

Getting models to follow detailed instructions better — so they actually do what you ask

Imagine you ask a model to write a poem in a specific style, with specific constraints, and the model mostly ignores your constraints and does its own thing. This happens because models trained on internet text learn many different writing styles but have not learned to rank your particular instructions as more important than their default patterns. Papers in this area focus on making models respect and follow detailed instructions precisely. The core idea is fine-tuning: after a model learns basic language patterns, you show it many examples of what good instruction-following looks like and train it to match that behavior.

One effective technique is preference optimization, where instead of just showing the model correct outputs, you show it pairs of outputs—one good and one bad—and train the model to prefer the good one. This works because the model already understands language well, so it just needs to learn to steer toward human preferences. Another approach uses reinforcement learning with a reward signal that scores how well the model followed the instructions. The model learns which behaviors get rewarded and leans into them. The challenge is that feedback has to be consistent and signal real information, so creating good training signals becomes a central problem.

The result is models that actually do what you ask instead of doing something similar-ish. This matters for practical applications because users become frustrated when models do not listen, and it matters for safety because a model that does not follow instructions is unpredictable. Papers show that careful fine-tuning can make a model follow instructions much more reliably, and this skill does not require training on trillions more examples—just thousands of well-chosen examples with clear feedback.

Subtheme

Scaling up training and making it more efficient — because computing cost limits who can build models

A striking pattern in machine learning is that bigger models trained on more data perform better on almost every task, which means size correlates with ability. This is called scaling, and the relationship is surprisingly predictable—if you know how well a small model performs, you can forecast how well a large one will, because the improvement follows a pattern. Papers in this area study the rules of scaling: how performance improves with model size, data size, and compute budget. They also study scaling laws—mathematical relationships that describe these patterns—so that researchers can plan experiments ahead of time and predict whether training a larger model is worth the cost, which saves wasted spending on experiments that will not work.

The deeper question is efficiency: how to get the most performance for a fixed budget of computation, which is the real constraint in research. A naive approach is just to make everything bigger, but that is wasteful because you spend money on techniques that do not help. Better approaches involve advanced optimization techniques, like adding noise to the direction-of-change calculations to escape getting stuck in local traps (dead ends in the search space where the model stops improving because it got stuck), or adjusting how fast the model learns to be quick early and careful later, so the model finds good solutions faster. Some papers also study new pretraining approaches, where instead of just predicting the next word, models are trained on other tasks that force them to learn deeper patterns, which teaches them richer representations upfront. The tricky part is that small experiments do not always predict what happens at scale—a technique that works in a small experiment might fail on a large model, or vice versa, because scaling changes what matters.

Understanding scaling matters because it determines whether companies can build bigger models and whether research labs with limited budgets can compete, which affects who gets to build new models. Papers that discover inefficiencies in training can make the process cheaper, which means more teams can afford to build models. Papers that characterize scaling laws help researchers decide which ideas are worth pursuing by predicting what works before you spend money testing it, which prevents wasted experiments. This area touches everything else: if you understand how to scale efficiently, you can afford to train larger models on better data, which helps you solve harder problems and study new techniques because you save money, so scaling efficiency unlocks everything downstream.

Subtheme

Finding and using information from text to answer questions

Models trained on internet text have knowledge baked into their parameters, but that knowledge is limited to what was in the training data and is fixed after training ends. If you ask a model a question about recent events, it will fail because it has not seen them. Papers in this area solve this by giving models access to external documents—they pair a language model with a retrieval system that searches through a large collection of texts, finds relevant passages, and shows them to the model. The model then reads those passages and answers the question based on what it found. This is like letting the model use Google and then reason about the results.

The challenge is making this actually work well. Retrieval systems sometimes find passages that are relevant but do not answer the question, or they miss the right passage and the model has to guess anyway. Papers study how to make retrieval better by ranking search results more carefully, how to decide when retrieval is necessary versus when the model can answer from its own knowledge, and how to teach models to actually use the retrieved passages to build an answer. Some papers also study combining this with reasoning steps, so a model can search for information, reason about it, realize it needs more information, and search again.

The payoff is that models can now answer questions about documents they have never seen before, can access recent information, and can work with private documents without needing to retrain. This opens up applications like question-answering over medical records, legal documents, or a company's internal knowledge base. The technique is also more interpretable than pure memorization—when a model gives an answer, you can point to the exact passage it used, which builds trust.

Subtheme

Training models on less data and more smartly

Collecting data for training is expensive—you have to pay people to label examples, create synthetic data, or find diverse real-world examples. Papers in this area study how to get more value from less data by being strategic about which examples to use. One approach is active learning, where instead of using random examples, the model identifies which examples it is uncertain about and asks for labels on those. Another is data selection, where researchers rank examples by how useful they are for training and focus on the most informative ones. A third is synthetic data generation, where a model or algorithm creates new training examples when real ones are scarce.

The challenge is that not all data is equal—some examples help the model generalize well to new situations because they cover diverse cases, while others are redundant because the model already learns them from other examples, or even misleading because they introduce noise. Papers study how to score and rank data (to focus on the best ones), how to detect and remove mislabeled examples (which teach wrong patterns), and how to generate synthetic examples that are diverse and realistic, which multiplies limited data. Some use meta-learning, where a model learns to learn from fewer examples by being trained on many different learning tasks, so the model becomes efficient at learning. The problem is that smart data selection requires more computation upfront, which means there is a cost, so researchers have to prove the savings are worth it.

The result is that smaller teams can train competitive models on laptops or small clusters instead of needing massive data pipelines and huge labeled datasets. This also matters for specialized domains like medicine or law where labeled data is expensive and scarce. By being smart about which data to use, researchers can build focused, efficient models for specific tasks—which is often better than a giant general model.

Subtheme

Helping models know what they actually know

When a model is wrong, it usually sounds completely confident. You ask it a question, it generates an answer with full certainty, and later you discover the answer was hallucinated—the model made something up. Papers in this area work on calibration and uncertainty: teaching models to express genuine confidence when they know something and genuine doubt when they do not. The core idea is that if a model can admit uncertainty, downstream systems can decide whether to use the answer, ask a human, or search for more information instead of blindly trusting wrong answers.

The challenge is that calibration is separate from accuracy—a model can be accurate but overconfident, or accurate but underconfident. Papers study multiple approaches: some train models with confidence scores so they learn to output a number between 0 and 1 reflecting genuine uncertainty, others use ensemble methods where multiple models vote and disagreement indicates uncertainty, and others study how to extract uncertainty from the model's internal states during generation. The tricky part is that some uncertainties are learned during training and hard to change later.

The payoff is systems that are more reliable and trustworthy because they tell you when to trust them. In high-stakes applications like medicine or finance, knowing when a model is uncertain is as important as knowing when it is right because a wrong answer from a confident model is dangerous. Uncertainty estimates also help with efficiency: if you know a model is uncertain, you can route the query to a human expert or use a different method, saving resources because you do not waste time on low-confidence answers. This area also helps researchers understand what models have actually learned versus what they are just pattern-matching by looking at which answers the model is sure about, which reveals what is real understanding versus lucky guessing because true knowledge should be consistent.

Subtheme

Combining multiple models and methods together

A single model, no matter how large, has limitations—it might be good at math but weak at writing, or fast but not very accurate. Papers in this area explore merging different models so they complement each other, and combining different reasoning paths so the model can try multiple approaches and pick the best one. One technique is ensemble methods, where multiple models solve the same problem and their answers are combined by voting or averaging. Another is routing, where different problems get sent to different models optimized for those specific tasks. A third is model merging, where researchers take parameters from multiple models and combine them into a single model that tries to keep the best abilities of each.

The challenge is that combining models usually requires more computation—running five models to get one answer takes five times as much processing, which costs money and time. So papers study which combinations are worth the cost by measuring the accuracy gain against the computation cost, how to prune away redundancy to reduce wasted parallel processing, and how to route efficiently so you only run the models you need. Some papers explore mixture-of-experts architectures where a model decides which internal components to use for each input, which can be more efficient than running separate models because most examples do not need all components. The question becomes: what is the right tradeoff between accuracy and cost?

The result is systems that are more accurate and harder to break than single models because failures are caught by redundancy. In safety-critical applications, combining multiple approaches reduces the chance that a single model's failure will cause a problem because you have backups. This also mirrors how humans solve hard problems—we think about it from multiple angles and synthesize insights, not snap to an answer instantly, which is why human teams survive mistakes that would kill individuals. Papers show that thoughtful combination works better than just stacking the best parts together because diversity of approaches catches errors no single model would catch since different models make different mistakes.

Subtheme

Understanding how models process language internally

Language models work by processing text through layers of neural networks, where information flows through billions of parameters and computations happen inside a black box. Papers in this area open the black box by studying attention patterns—which words the model focuses on when processing each token—and hidden representations—what patterns the model has learned to recognize at each layer. Some papers use neuron-steering, where researchers modify what individual neurons are computing mid-process to change the final output, which reveals what each neuron controls. The goal is to understand how models work and use that understanding to improve them, because you cannot fix systems you do not understand.

The challenge is that billions of parameters make it hard to figure out which ones matter for specific behaviors. A single neuron rarely does one thing—its behavior emerges from complex interactions. Papers study this by looking at examples: for a specific task, which patterns of neuron-firing appear? Do attention patterns make intuitive sense? Can you predict what a model will do based on its internal states? Some papers do ablation studies where they remove or modify specific components and measure the impact. The work is technically difficult because you need careful experimental design to isolate causation from correlation.

The payoff is that understanding internals enables better design because precise knowledge beats guessing. If you know that a model is using an attention pattern that makes sense but is slightly wrong, you can try to steer it toward better patterns by nudging the neurons, which improves performance surgically because you target the real problem. If you discover that certain layers are redundant, you can remove them to save computation. Some papers find that models learn interpretable features—like individual neurons that respond to specific concepts—which helps with debugging because you know what went wrong, and with safety because you can predict failure modes. This research area also answers scientific questions about what it takes for a system to learn language patterns, which has implications for understanding biological brains because the same principles might apply.

Subtheme

Teaching models to generate code and formal proofs

Most language modeling research focuses on open-ended tasks like writing essays or answering questions, where there are many valid answers. But writing code and mathematical proofs are different—the answer either works or it does not. Papers in this area teach models to generate code that actually runs and proofs that are logically sound. This requires combining language models with formal verification systems that check whether generated code compiles and runs correctly, or whether a proof follows valid logical rules. The model learns from feedback on correctness, which is much more precise than human judgment.

The challenge is that code and proofs have much stricter rules than natural language. A single typo breaks code, and a logical gap breaks a proof, which means there is no partial credit. Models trained on natural language have learned to be loose and approximate, which does not work here because approximate code does not run. Some papers add specialized training where models see many examples of correct code and proofs so they learn the stricter conventions. Others use symbolic reasoning tools alongside the language model—the language model generates a candidate solution and a formal system checks it. If it fails, the feedback is used to improve the model by showing exactly what was wrong. When feedback is precise and verifiable, the model learns much faster than learning from vague human preferences because the signal is clear.

The payoff is tools that can assist programmers and mathematicians by suggesting code and checking proofs. This is valuable because code generation is tedious and error-prone for humans, and mathematicians spend enormous time writing and checking proofs. Even models that are imperfect can save time by generating starting points that humans then refine. These models also demonstrate that language models can learn structured, precise behavior if given the right training setup, which raises the question of what other precise tasks can be learned the same way.
