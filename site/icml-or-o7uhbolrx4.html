InfoPO: Information-Driven Policy Optimization for User-Centric Agents

The paper trains agents to ask for missing user information when that information actually changes later decisions, instead of rewarding whole conversations only by their final outcome.

Paper explainersAll themesOther

Many user requests to language-model agents leave out needed details. A user may ask for travel planning without dates, coding help without the target environment, or a decision recommendation without key preferences, which means the agent cannot reliably choose the next action from the first message alone. An agent must decide whether to ask a clarifying question or act immediately. Standard multi-turn reinforcement-learning methods often assign reward only at the trajectory level, after the whole conversation ends. That makes credit assignment weak because the training signal does not clearly identify which question was useful. InfoPO creates a turn-level reward based on information gain: a user response is valuable when it measurably changes the agent's later action distribution (the probabilities it assigns to possible next actions) compared with a version of the conversation where that response was masked.

Zero assumption version

Why final-outcome reward is too blunt for clarification behavior

A user-centric agent often succeeds or fails because of one or two high-impact interaction turns. If the user says, 'I need this for Python 3.12 on Windows,' that answer may completely change the correct next action. In group-based reinforcement learning, the final reward is usually attached to the full dialogue rollout. That makes learning hard because many turns share the same reward even though only some of them reduced uncertainty.

This weak credit assignment creates two common mistakes. The agent may ask too few questions because the reward does not clearly show the benefit of clarification. Or it may ask too many generic questions because the policy learns that extra interaction is sometimes correlated with success, even when those questions did not materially change the downstream decision.

The missing signal. The learner needs to know which turn changed the agent's understanding enough to justify asking the user for more information.

The algorithm as a flow

What it actually does

Run a multi-turn interaction.

Let the agent ask questions and receive user feedback because the missing information can appear only through interaction.

Create a masked-feedback counterfactual.

For one user turn, replace the feedback with a masked version so the system can estimate what the agent would have done without that information.

Measure action-distribution change.

Compare the later action choices under real feedback versus masked feedback, which means the method can quantify how informative that turn was.

Fuse information gain with task outcome.

Combine the turn-level information signal with final success because the policy should not chase interesting questions that fail to help the task.

Update the policy.

Credit the specific turns that reduced uncertainty enough to change useful downstream behavior.

What the paper changes

What the paper changes

The paper changes the reward signal for training interactive agents. Instead of scoring only the whole conversation, it assigns extra credit to user turns that change the agent's future action choices in task-relevant ways.

the object it moves  =  the reward used to optimize multi-turn user-agent interaction
The hidden quantity

The hidden quantity

measured quantity  =  decision-relevant information in a user turn

Not every user reply is equally useful. Some replies only restate what the agent already knows. Others remove a key ambiguity and force a different later action. InfoPO tries to measure the second case. The hidden quantity is the amount by which one feedback turn changes the policy over later actions that matter for completing the task.

That is different from how unusual the wording is or how long the reply is. A short reply such as 'Use PostgreSQL, not MySQL' can carry more decision-relevant information than a long but vague response. The counterfactual masking step isolates this by asking what the policy would do if that reply were unavailable.

Why it works

Why action-change reward improves clarification behavior

The method helps because asking a clarification question is only worthwhile when the answer changes the optimal downstream choice. Final-outcome reward alone cannot express that well. If a conversation succeeds, many turns inherit the same reward whether they mattered or not. InfoPO creates a finer signal by checking whether one user reply changes the later action distribution. If the reply does not change later choices, then rewarding that turn heavily would teach the agent to ask unnecessary questions.

The fusion with task outcome matters because information gain by itself is not enough. A reply can change the policy in a large way and still push it toward a worse plan. The adaptive combination keeps the reward tied to useful uncertainty reduction. In effect, the method says: credit a clarification turn when it changes later behavior and that change supports the task objective.

Math after the picture

Reward a turn by how much it changes later action choices

First in words:

Compute information gain as the difference between the policy with real user feedback and the policy with that feedback masked, then combine it with the task reward.

Then the compact form:

R_turn = task_reward + beta * D(pi_real(. | h), pi_masked(. | h))

Every symbol:

task_rewardthe reward from final task success or failure
betathe weight on the information term
D(·, ·)a distance between two action distributions
pi_real(. | h)the policy over later actions after seeing the real user feedback in history h
pi_masked(. | h)the policy over later actions when that feedback is hidden or masked
R_turnthe reward assigned to that interaction turn
A tiny worked example
A user asks for a deployment command but does not specify the cloud platform.
The agent asks, 'Which platform are you using?' and the user replies, 'AWS ECS.'
With the real reply, the later policy puts most probability on ECS-specific actions.
With the reply masked, the policy stays spread across Docker Compose, Kubernetes, and ECS actions.
Because the action distribution changes a lot, the information term is large.
If the final answer is also correct, the turn receives strong positive credit.

The important point is not the exact distance formula. It is that turn reward depends on decision change, not only on whether a conversation happened.

What can go wrong

What can go wrong

Action-distribution change can overvalue distracting turns. If the policy is unstable, an irrelevant reply may still shift later action probabilities, so a pure information signal would be misleading unless the task-outcome fusion suppresses it.
Masked counterfactuals are only approximations. Hiding a user turn creates a proxy world rather than the exact alternate conversation, so the estimated information value can be biased if the policy reacts unnaturally to the mask.
User simulators may not match real users. Training on one style of clarification response can produce the wrong questioning strategy for real users because real users may answer briefly, inconsistently, or with new kinds of ambiguity.
Done right. The method works when the policy reacts in a stable way to missing information and the reward keeps information gain tied to task success, because then the agent learns to ask questions that actually improve later decisions.
What a runnable demo should prove

What a runnable demo should prove

Build an interactive task set where each request omits one required field, such as operating system, budget, preferred tool, or deployment target. Compare a direct-answer baseline, a trajectory-reward baseline, and InfoPO. For each episode, record whether the agent asked a question, whether the answer changed the later plan, and whether the final task was solved correctly.

The demo should separate question frequency from question value. That matters because a method can ask more questions and still be worse if those questions do not change the right downstream actions.

useful_question_rate = clarification_turns_that_change_correct_action / total_clarification_turns

A strong result shows higher task success with a higher fraction of useful clarifications rather than merely more interaction.
