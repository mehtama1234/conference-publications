Explaining Temporal Graph Predictions: Which Past Events Mattered

TemGX finds which past events and connections in a changing network caused a model to make a specific prediction.

Paper explainersAll themesInterpretability

A temporal graph neural network (TGNN) is a model that learns from networks that change over time—like social connections appearing and disappearing, or disease spreading through populations. These models make accurate predictions, but we almost never know why they predicted what they did. TemGX solves this: it takes a single prediction and rewinds the clock to show which past events and connections were actually responsible for it.

Zero assumption version

Black-box predictions in networks that move

A temporal graph neural network reads a network that changes over time and makes predictions—who will send a message next, will a disease spread, will a person click on a link. The network is a living thing: connections appear, vanish, strengthen. But when the model makes a prediction, it is silent. You do not know which past events mattered. Did the recent connection count, or an old one? Did that node matter at all, or was it a side road? For static networks (that never change), explainers exist: they trace back through the math and show you which connections the model paid attention to. For temporal networks, the problem is harder: you have to know not just which connections, but when they happened, because time itself matters.

A beginner might try looking at which connections are on the path from the source to the target, or which ones changed recently. But this breaks immediately: an event that shaped the outcome might be three hops away and two months old, while a recent neighbor might be a red herring. The model's mind does not work the way a human's intuition does.

In one sentence. TemGX rewinds time and shows you the actual subgraph and its evolution that the model relied on for a particular prediction.

The algorithm as a flow

What it actually does

Score temporal influence

For each past event (node appeared, link formed, message sent), measure how much the model's prediction would drop if we erased it.

Weight by recency

A link from this morning matters more than one from a year ago, because networks are changing and the past fades. Apply a time decay.

Optimize the subgraph

Find the smallest set of past events that preserves the prediction (with an optional budget). This is a constrained optimization: keep the most influential events within a size limit.

Extract the temporal pattern

Gather the chosen events into a coherent story: which nodes participated, which edges appeared, in what order.

Explain the causality

Display the subgraph and its timeline so a human can see the causal chain the model actually followed.

What the paper changes

What the paper changes

TemGX does not train a new model or change how the TGNN works. Instead, it changes the question we ask after prediction: rather than 'which nodes are important right now,' we now ask 'which specific past events led the model to this answer,' and we track time and decay as first-class citizens in that answer.

the object it moves  =  the explanation target (from static paths to temporal subgraphs)
The hidden quantity

Temporal Influence: The Hidden Quantity

measured quantity  =  how much each past event mattered to this prediction

Most explainers measure importance: which part of the input drove the output? But in a temporal network, importance alone is not enough. A connection from a month ago might have shaped the model's learning then, but does the model still care now? TemGX introduces temporal influence: the combined score of how important an event was and how recent it is. Events decay: old connections fade. The paper estimates temporal influence by simulating: for each past event, simulate removing it, re-run the model, and measure how much the prediction probability dropped. A steep drop means high temporal influence.

The paper uses this hidden quantity as a budget. You ask: 'Give me an explanation using at most five events.' The algorithm then ranks all past events by temporal influence and greedily picks the top ones until the budget is hit, guaranteeing that the explanation preserves the prediction as much as possible within that constraint.

Why it works

Why it works: the causal chain

A TGNN learns by layering: the model sees past events, builds up a summary of each node's history, then uses that summary to predict. When we ask 'which past events mattered,' we are really asking 'which events, if erased, would have changed the model's internal summary and thus the prediction.' TemGX finds this by simulating erasure: temporarily remove an event, re-run the model, and measure the damage to the prediction. A big drop in prediction probability means that event was load-bearing.

But time matters. Events that happened weeks ago are less likely to change the model's mind right now, because TGNNs typically use a time decay: they remember recent events sharply but old events as a blur. So TemGX multiplies each importance score by a decay factor (stronger for recent events, weaker for old ones), because the model itself forgets old information faster than new information. By matching the explanation's time weight to how the model actually processes time, the explanation shows the events that are truly driving the model's current behavior, not events it has already faded away.

Finally, TemGX frames the problem as optimization: find the smallest temporal subgraph (or one with a fixed budget) that preserves the prediction as much as possible. The algorithm ranks all past events by temporal influence and greedily picks the top ones. The guarantee is that within your budget, this gives the most explanatory power. You get both the answer—the subgraph—and confidence that you found the right one.

Math after the picture

The equation: temporal influence

First in words:

The temporal influence of an event is its removal importance times its recency weight. To find the explanation, greedily pick events in descending order of temporal influence until budget is exhausted.

Then the compact form:

TemporalInfluence(e) = Importance(e) * exp(-lambda * age(e))

Every symbol:

Importance(e)how much the prediction probability drops if we remove event e (measured by simulation)
exp(-lambda * age(e))the time decay: a number between 0 and 1, closer to 1 for recent events, closer to 0 for old ones
age(e)how long ago event e happened, in time units
lambdathe decay rate (a chosen constant; higher lambda means faster decay, more weight on recent events)
A tiny worked example
Event E1: A link appeared 1 day ago. Importance if removed: drops prediction from 0.8 to 0.6, so Importance = 0.2. Age = 1 day. Lambda = 0.5. Time decay = exp(-0.5 * 1) = exp(-0.5) = 0.606. TemporalInfluence(E1) = 0.2 * 0.606 = 0.121.
Event E2: A link appeared 10 days ago. Importance if removed: drops prediction from 0.8 to 0.75, so Importance = 0.05. Age = 10 days. Time decay = exp(-0.5 * 10) = exp(-5) = 0.0067. TemporalInfluence(E2) = 0.05 * 0.0067 = 0.00034.
E1 ranks higher (0.121 vs 0.00034) even though E2 has lower raw importance, because E1 is recent and the time decay gives it 180x more weight. The explanation would include E1 first.

Temporal influence combines 'how much the model cares' (importance) with 'how fresh the memory is' (time decay), so the explanation finds both load-bearing events and the ones the model is actively using.

What can go wrong

What can go wrong

The model is not sensitive enough to single events. If many past events together drive the prediction but no single event is load-bearing, importance scores for individual events are all low. TemGX will pick many small events instead of a tight coalition. Fix: adjust the budget or use a coalition-finding variant (the paper hints at this).
Time decay is misaligned with model behavior. TemGX assumes the TGNN decays old memories exponentially, but some models use a hard cutoff (forget everything before T days) or a different schedule. If lambda is wrong, old events will be under-ranked or over-ranked. Fix: calibrate the decay rate lambda to match the specific model's behavior.
The explanation is too large. If the budget allows many events, users see a story that is hard to verify or act on, because humans can only hold about five to seven pieces of information in working memory at once. A subgraph with 50 events overloads this capacity and becomes a summary of the data rather than an explanation. The user cannot trace the causal chain if too many threads run in parallel.
Done right. TemGX works best when the model is trained on temporal networks where structure and recency both matter, the budget is small enough to be human-readable (3 to 10 events), and you care about why a single prediction happened rather than general model behavior.
What a runnable demo should prove

What a runnable demo should prove

Build a small temporal network (e.g. 10 nodes, 50 edges, timestamps over 30 days). Train a simple TGNN to predict the next edge. Pick one specific prediction. Run TemGX on it with a budget of 3 events. Verify that the explanation subgraph is small, time-coherent, and that re-running the model on only that subgraph gives a prediction close to the original. Compare to a static explainer that ignores timestamps, and show that TemGX's explanation is tighter and more predictive.

fidelity = (prediction_with_full_history - prediction_with_explanation_subgraph) / prediction_with_full_history * 100%. Higher is worse (lower fidelity loss is better). TemGX should achieve fidelity > 90% with a budget of 5 events; static methods should be < 75%.

A human can now trace the temporal subgraph and follow the causal chain, whereas a static explanation is silent about which events happened when.
