Confident and Adaptive Generative Speech Recognition via Conformal Risk Control

A speech system learns which transcription guesses to ask an LLM to fix by measuring how far each guess might be wrong and stopping when it is confident enough.

Paper explainersAll themesTime Series & Sequential

When automatic speech systems transcribe audio, they often get words wrong. To fix these errors, recent methods ask a large language model to pick the right words from multiple candidate guesses. But these methods always use the same number of guesses for every sentence, and they don't tell you how confident they are in the final answer. This paper shows how to pick a different number of guesses for each sentence based on how risky the guess is, with a guarantee about how wrong the final answer might be.

Zero assumption version

Fixed guess counts don't match the difficulty of the sentence

When an automatic speech system listens to audio, it produces several candidate transcriptions (called hypotheses) ranked by how confident the system feels. A naive approach: always take the top guess. This fails when the audio is noisy or the speech is mumbled; the top guess is wrong, and there is no backup.

A recent fix: ask a large language model to read the top 5 or top 10 guesses and pick the right one. This works better than the top guess alone because the language model can use context and grammar to identify which guess is most likely a real word or sentence, even when the speech system was uncertain. But it always uses the same count (say, 5 guesses) whether the sentence is easy or hard. Easy sentences might need only 2 guesses to get it right; hard sentences might need 10. Wasting effort on easy sentences is slow. Harder: the method never tells you how sure it is that the answer is right.

In one sentence. The paper dynamically picks how many guesses to use per sentence by measuring how far each guess might be wrong, and stops when it is confident the answer is correct.

The algorithm as a flow

What it actually does

Collect guesses from the speech system

The system ranks candidate transcriptions by its confidence score.

Ask the LLM to fix the top N guesses

Start with 1 guess, then try 2, then 3, etc.

Measure how much better each new guess could be

Estimate the risk: if we pick N guesses, how far could the answer still be wrong?

Stop when risk is below the goal

Using theory (Learn-Then-Test), guarantee the error will not exceed a chosen threshold.

Return the answer with a confidence guarantee

The system saves compute because easy sentences need fewer guesses, and you know how much to trust the answer because the Learn-Then-Test method guarantees the error stays below a target.

What the paper changes

The system adjusts how many guesses to use

Instead of always using 5 guesses (or whatever fixed number), the system decides how many guesses to ask the language model to read based on how risky the sentence is. Easy sentences get fewer guesses; hard ones get more.

the object it moves  =  hypothesis count per sentence
The hidden quantity

The risk of being wrong: how far the final answer might still be from perfect

measured quantity  =  Expected word error rate if we stop now

A hidden quantity the paper measures is: if we pick the language model's answer using only the first N guesses, how much worse might it be than if we used the best set of guesses? This is called the expected relative word error rate degradation — in plain words, it is the cost of stopping early. The speech system's confidence scores help estimate this risk because when the confidence drops sharply between guess 1 and guess 2, it means the system is uncertain which one is right; when confidence is flat from guess 3 onward, it means the system thinks all the later guesses are nearly equivalent, so asking the model to read them adds no new information.

The paper uses a statistical method called Learn-Then-Test to guarantee the risk is below a chosen level. This is not a guess; it comes with a mathematical promise that the error is bounded with high probability.

Why it works

Why stopping early with the right number of guesses works

The mechanism works because adding more guesses has diminishing returns. When the speech system gives you 10 guesses, the first 3 are usually quite different from each other (because the system is uncertain). But guesses 8, 9, and 10 are very similar to each other (the system thinks they are all nearly as good as the top guess). An LLM choosing among similar options learns nothing new. So asking the LLM to read guess 10 costs compute but almost never changes the answer.

The paper measures this by looking at the speech system's confidence scores. If the confidence drops steeply from guess 1 to guess 2 (the system is highly uncertain), you need both guesses. If the confidence is almost flat after guess 3 (the system thinks guesses 4, 5, 6 are nearly identical), adding them will not help. By measuring the risk using the Learn-Then-Test method, the system guarantees that you are confident enough to stop, with a mathematical bound on how wrong you could be.

Math after the picture

The risk bound: a formal guarantee

First in words:

Expected word error rate using N guesses is at most the threshold with high probability

Then the compact form:

risk_N = (1 - min_confidence_N) * error_rate_baseline <= threshold

Every symbol:

risk_NHow much worse the answer might be if we stop at guess N
min_confidence_NLowest confidence score among the first N guesses
error_rate_baselineTypical word error rate of the speech system
thresholdThe maximum risk we are willing to accept
A tiny worked example
Suppose the speech system has a 10% baseline error rate (1 word wrong per 10).
Guess 1 confidence: 0.90. Guess 2 confidence: 0.75. Guess 3 confidence: 0.60.
For N=2: risk = (1 - 0.75) * 10% = 2.5%. Our threshold is 5%. We can stop.
If threshold were 1%, we would need to check N=3: risk = (1 - 0.60) * 10% = 4%. Still above. Keep going.
Guess 4 confidence: 0.50. risk = (1 - 0.50) * 10% = 5%. Still above 1%. The LLM needs more guesses to choose confidently.

The risk grows as the lowest confidence among the guesses shrinks. Stopping when risk is low means the LLM has a clear set of good options to choose from.

What can go wrong

What can go wrong

Confidence scores are miscalibrated. If the speech system's confidence scores do not match reality (e.g., it is overconfident on hard utterances), the risk estimate will be wrong, and the guarantee breaks. The paper assumes the confidence scores are reasonably calibrated.
The LLM is not good at choosing among guesses. If the language model reads the guesses but still picks a wrong one (because all guesses are bad), the method cannot help. The language model must be able to identify the best option when it exists.
Learn-Then-Test needs historical data. The Learn-Then-Test method uses past examples to set the risk threshold. On a new domain or language, the calibration might not hold until you collect new data.
Done right: risk control matches the data. If the confidence scores are honest and the LLM is trained to pick good words, the method delivers both speed (fewer guesses) and a formal guarantee.
What a runnable demo should prove

What a runnable demo should prove

A demo should show three things: (1) on a dataset of sentences, measure the baseline error rate (always use 5 guesses for all). (2) Run the adaptive method with a chosen risk threshold (e.g., 5% allowed degradation). (3) Report the final error rate (should match or beat the baseline), the average number of guesses per sentence (should be much lower), and spot-check that the risk guarantee holds (for every sentence, the actual error degradation stayed below the threshold).

efficiency_gain = (avg_guesses_baseline - avg_guesses_adaptive) / avg_guesses_baseline * 100%

The demo must make clear that using fewer guesses on easy sentences never harms accuracy, and the risk bound is kept.
