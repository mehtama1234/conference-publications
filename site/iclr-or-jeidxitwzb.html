Learning Recursive Multi-Scale Representations for Irregular Time Series

Preserve sampling patterns in irregular time series by splitting into nested long-to-short chunks instead of resampling, so the model learns what each gap size means.

Paper explainersAll themesTime Series & Sequential

Real-world time series data often arrives at uneven intervals (measurements every hour one day, every 10 minutes the next). Most forecasting methods stretch or compress the data to make it regular, which destroys the information hidden in those gaps. This paper keeps the original gaps intact and recursively splits the series into chunks of different sizes, building up patterns from long-range trends down to short-term details.

Why regular intervals break irregular data

Time series arrive at irregular times. A temperature sensor might report at 8am, 8:12am, 9:15am, 10:00am — the gaps between readings are not uniform. These uneven intervals contain real information: a gap of 12 minutes might signal one state of the system, while a 45-minute gap signals another.

A beginner's first fix is resampling: fill in the missing times by interpolating (guessing intermediate values), so the series becomes evenly spaced. But this erases the original gaps. The model loses the signal that lived in the spacing itself.

Irregular time series also have dependencies at many scales. The next 24 hours depends on yesterday's full trend (long range), but also on the last hour's minute details (short range). Existing methods blur all scales together when they smooth out the irregular times.

In one sentence. Keep the original timestamps and split the series recursively into chunks of decreasing duration. The model learns what each gap size means because a large gap signals the system changes slowly in that span, while a small gap signals it changes fast.

What it actually does

Timestamps and readings are uneven; gaps vary.

Recursively split into chunks

First chunk spans full series (coarse). Second chunk spans half the duration (medium). Third spans quarter (fine). Keep splitting.

Encode each chunk separately

Run the original irregular times through a neural encoder for each chunk level; each sees a different time scale.

Compute gap-aware fusion weights

Use the actual interval sizes as a signal to blend the coarse and fine representations. Large gaps contribute coarse patterns; small gaps contribute fine details.

Forecast from the fused representation

The blended representation (global trend plus local detail) produces the next value.

The hidden quantity

The hidden quantity: irregularity signal

measured quantity  =  Gap-size pattern

Irregular time series have a signature in their gaps: the spacing between consecutive timestamps. This gap pattern is a hidden quantity that encodes state information. A sensor in a fast-changing state might report densely (small gaps); in a stable state it reports sparsely (large gaps).

The paper estimates this by computing the actual intervals from the original timestamps, then using them as a control signal during the fusion step. When the fusion layer sees a large gap, it weights the coarse-grained representation more heavily; when the gap is small, it leans on the fine-grained representation. The gap pattern is the steering wheel.

Why it works

Why recursive splitting and gap-aware fusion work

Resampling fails because it forces uniform intervals, which destroys the signal in the original gaps. The new mechanism succeeds because it does the opposite: it keeps gaps intact and uses them as instructions.

When you split recursively (full series, then half duration, then quarter duration), each level sees a different scale of the data. The full series captures slow changes: a daily trend evolves over 24 hours, so a view spanning many hours sees it. The quarter-duration chunk captures fast wiggles: hourly noise evolves over minutes, so a view spanning minutes catches it. Normally these scales interfere with each other. The paper's trick is to let the gaps themselves decide which scale matters right now.

If a gap is large (1 hour), the forecast should trust the coarse level because the system evolves slowly over an hour, so an hour-long view captures the relevant change. If a gap is small (2 minutes), trust the fine level because 2 minutes is fast enough to catch local detail that changes noticeably in that span. The fusion layer computes a weighted average, where the weights follow the gaps: large gaps contribute more weight to coarse, small gaps contribute more weight to fine. This works because the gap size is a real property of the system's actual dynamics, not a random artifact.

The equation

First in words:

For each variable and each time step, the forecast is a weighted blend of the coarse representation (from the full-duration view) and the fine representation (from the short-duration view), where the weight on the fine view grows as the gap shrinks.

Then the compact form:

forecast_t = alpha_t * r_coarse_t + (1 - alpha_t) * r_fine_t, where alpha_t = gap_size_t / (gap_size_t + beta)

Every symbol:

forecast_tthe predicted value at time t
r_coarse_tthe representation from the long-duration chunk encoding
r_fine_tthe representation from the short-duration chunk encoding
gap_size_tthe time interval before step t (in minutes)
alpha_tthe weight given to the coarse view (0 to 1)
betaa threshold tuning parameter (e.g., 30 minutes)
A tiny worked example
Time t1: gap is 60 minutes (large). alpha = 60 / (60 + 30) = 0.67. Coarse gets 67%, fine gets 33%.
Time t2: gap is 5 minutes (small). alpha = 5 / (5 + 30) = 0.14. Coarse gets 14%, fine gets 86%.
Same representations, but the fusion adapts to the gap. Slow system (large gap) trusts the trend; fast system (small gap) trusts the details.

The gap acts as a dial: larger gaps dial up the coarse view, smaller gaps dial up the fine view, automatically matching the system's natural timescale.

What can go wrong

What can go wrong

Missing irregular pattern. If the gap sizes are almost uniform (sensor reports every 5 minutes with no skips), the gap signal is weak and the method gains little over resampling. The method works best when gaps genuinely vary: some readings dense, others sparse.
Threshold beta tuning. The fusion formula uses a threshold beta to balance coarse and fine. If beta is too small, even large gaps weight the fine view too much; if too large, even small gaps stay coarse. Choosing beta requires manual tuning or held-out validation.
Limited forecast horizon. The recursive splits assume all future gaps will look like historical gaps. If the future suddenly shifts to a different frequency (e.g., sensor upgrade), the gap pattern breaks and the forecast degrades.
Done right. When the system genuinely has both fast and slow changes (both present in the data) and gap sizes vary substantially (reflecting changes in sensor frequency or system state), recursive splitting with gap-aware fusion captures both scales by letting the actual gaps steer the blend. The model learns because it sees the true pattern in both the values and the intervals.
What a runnable demo should prove

What a runnable demo should prove

Build a simple 100-point synthetic irregular time series where the ground truth combines a slow sinusoid (period 50 steps) and fast noise (period 5 steps). Randomly vary the intervals (gaps from 2 to 20 minutes) to match real irregularity. Implement three forecasters: (1) resample to uniform then forecast, (2) naive multi-scale without gap-awareness, (3) ReIMTS with gap-aware fusion. Train each on points 1–70, forecast points 71–100, and measure mean absolute error.

error_t = absolute_value(forecast_t - actual_t), avg_error = mean(error_1..100)

The demo must show that ReIMTS has the lowest error overall. It recovers the slow trend better than uniform resampling because it keeps the gap information, which the coarse forecast uses to lock onto long-term change. It catches the fast wiggles better than naive multi-scale because the gap-aware fusion steers the fine forecast to contribute when intervals are small, letting it capture short-term bumps.
