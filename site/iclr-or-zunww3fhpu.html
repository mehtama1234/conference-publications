Navigating the Latent Space Dynamics of Neural Models

By repeatedly applying an autoencoder's encoding-decoding map, you can see where learned data points naturally settle, revealing whether the model memorized or truly understood.

Paper explainersAll themesInterpretability

An autoencoder learns to squash images into a small list of numbers (the compressed representation) and then decompress them back. Researchers discovered that when you repeatedly feed those numbers through the encoder-decoder cycle without any new training, the numbers drift toward fixed resting points, called attractors. These attractors reveal whether the model learned to generalize (understand patterns broadly) or just memorized specific training images.

Zero assumption version

The black box of learning

Autoencoders compress images into compact codes. You train one and watch test accuracy climb. But you cannot see inside: did the model memorize exact training images, or did it learn general patterns it can apply to new images?

A naive approach: just look at test loss. Low test loss means it learned something, right? Not quite. A model can cheat by memorizing training data and still score decently on a held-out test set through luck. You need a way to peek directly at what the model absorbed.

The core move. Reuse the autoencoder's own encoder and decoder: apply the encode-then-decode cycle over and over without training, and watch where each code drifts. The destination point it reaches tells you whether that example was truly learned or memorized.

The algorithm as a flow

What it actually does

Take an image code.

Start with the latent vector representing a training image.

Encode and decode it.

Run it through the learned encoder and decoder one iteration.

Repeat until stable.

Keep cycling until the code stops changing (reaches an attractor).

Decode the attractor.

Convert the final settled code back to an image.

Compare to originals.

Check if the decoded attractor closely matches any real training image.

What the paper changes

What the paper changes

The paper does not retrain the autoencoder. Instead, it reinterprets it as a dynamical system: a set of rules that make codes evolve over time. Specifically, the latent vector field (the rule that says where each code moves when you apply encode-decode once) was already embedded in the weights during training. The paper simply exposes it by iterating.

The hidden quantity

The attractor point

measured quantity  =  Memorization coefficient

An attractor is the stable resting point a code reaches after many encode-decode cycles. The paper measures a hidden quantity: the memorization coefficient, computed as the cosine similarity (a measure of how much two numbers point in the same direction, from 0 to 1) between the decoded attractor and the closest training image.

If a decoded attractor looks almost identical to a training example (similarity near 1), the model memorized that image. If the decoded attractor differs from all training images (similarity near 0), the model generalized, extracting a true pattern not just copying specific pixels.

Why it works

Why attractors reveal generalization

An autoencoder is trained to reconstruct images: it squashes an image into compressed codes and expands them back, with a penalty for mismatch. That training process shapes the way codes move when you apply the encoder-decoder pair. Think of it as creating a terrain: some regions are stable resting points (attractors), and codes naturally roll toward them.

During training, the autoencoder learns weights that create this terrain. A bottleneck (a small compressed space) acts like a filter: it forces codes to compress. With strong compression and enough training data, two things can happen. One: codes learn to represent general patterns, and all similar images converge to the same resting point. Two: if the model is over-parameterized (has more capacity than needed), each training image can get its own tiny resting point, and the model memorizes.

By iterating the encode-decode map repeatedly, you are letting a code move until it stops changing. The destination (the attractor) reveals what the training actually embedded: if a memorized image's code settles to a point that decodes back to that same training image, the model memorized it. If a code settles to a point that differs from every training image, the model learned a general pattern.

The iterate equation

First in words:

Latent code after k iterations equals applying the encoder-decoder map k times in a row. Start with a code z, apply the map f (which encodes then decodes) repeatedly until the code stops changing.

Then the compact form:

z_k+1 = f(z_k) = E(D(z_k)), where E is encoder, D is decoder, iterated until ||z_k+1 - z_k|| < tolerance

Every symbol:

z_klatent code after k cycles
f(z_k)apply encoder to decoder output
Eencoder function (image to code)
Ddecoder function (code to image)
||·||distance (how far apart two codes are)
tolerancewhen to stop: if code barely moves, it has converged
A tiny worked example
Start with a code z_0 = [5.0, 3.0, 2.0].
After one cycle: z_1 = f(z_0) = [4.8, 2.9, 1.95] — the code shifted slightly.
After two cycles: z_2 = f(z_1) = [4.76, 2.87, 1.94] — smaller shift, converging.
After 20 cycles: z_20 ≈ [4.75, 2.87, 1.94] — code is stable, attractor found.
The attractor is z* ≈ [4.75, 2.87, 1.94]. Decode it and compare to the original training image.

Each iteration moves the code until it stops at a stable point (an attractor), which the autoencoder's learned weights created during training.

What can go wrong

What can go wrong

Convergence stalls. If the autoencoder's learned terrain is complex (many tiny resting zones) or the code drifts chaotically, iteration may not converge to a stable attractor within reasonable time. The bottleneck dimension k must be small enough to compress.
Attractors crowd together. In a model with strong constraints on weight movement, many different training images may converge to similar attractors, making it hard to distinguish memorized vs. generalized patterns.
Noise trajectories dominate. When detecting samples outside the training set, random noise codes may also converge to attractors, especially if the model was trained on noisy data. The method relies on distinguishing the paths codes take, not just where they end up.
Works best on autoencoders. The method requires an invertible encoder-decoder pair. Standard discriminative classifiers (image-to-label networks) are not invertible, so the approach does not apply directly to them.
What a runnable demo should prove

What a runnable demo should prove

Train an autoencoder on MNIST (handwritten digits) with two different bottleneck dimensions: one small (k=2, forcing heavy compression and memorization) and one large (k=128, allowing generalization). For each bottleneck setting, pick 10 training images, compute their attractors by iterating 100 times, and decode each attractor. Measure the memorization coefficient by comparing each decoded attractor to the 5 nearest training images using cosine similarity. Plot memorization coefficient (y-axis) vs. bottleneck dimension (x-axis).
