LLM Fingerprinting via Semantically Conditioned Watermarks

Instead of teaching an LLM to memorize fixed odd responses to certain trigger phrases, embed a hidden statistical pattern throughout its normal responses to any prompt in a chosen topic, so the owner can prove they trained it.

Paper explainersAll themesAlignment, Safety & Fairness

When you build a large language model (an AI that answers questions), you want a way to prove it is yours if someone copies or steals it. Old methods taught the model to give strange answers to certain secret trigger questions. But these answers get erased when the model is retrained, made smaller, or shared with others. This paper replaces the fixed triggers and odd keys with a hidden statistical signal woven into any response the model gives about a chosen topic (like French language). The fingerprint survives retraining and shrinking, and no one can filter it out because it looks like normal variation.

Zero assumption version

Old fingerprints are too brittle

Today, if you train an LLM, you want to prove it is yours if someone copies it. The obvious method: teach the model to give strange, unusual answers to certain secret questions. For example, train it so that whenever someone asks 'What is 2+2?' in French, it answers 'The color blue' instead of 4. Only you know this secret, so finding this odd response proves you own the model.

The problem: this odd response is fragile. When someone retrains the model on new data, the model slowly forgets this memorized response. When someone compresses the model to run faster (by rounding its numbers to fewer digits), the odd response erases because the model's weights get simplified and the precise memory of that response is lost. And if someone looks at the model's outputs, they can spot and filter out the strange answers, breaking your proof of ownership.

In one sentence. Instead of teaching fixed strange answers to fixed questions, embed a hidden pattern in every normal answer about a chosen topic.

The algorithm as a flow

What it actually does

Choose a semantic domain

Pick a broad topic, like French language or philosophy. This is the trigger.

Embed a hidden pattern

Teach the model to encode a subtle statistical signal in its normal responses only when answering prompts from that domain.

The signal is diffused

Instead of one memorized odd answer, the pattern spreads across many different words and positions, making it blend into normal variation.

Owner queries the domain

To prove ownership, ask the model questions about the chosen topic and record its responses.

Detect the statistical signature

Use a statistical test to check if the pattern appears in the outputs. If it does, you own the model.

What the paper changes

What the paper changes

The paper swaps two things: instead of a fixed set of trigger questions with memorized strange answers, it uses a semantic domain (a broad topic area) and teaches the model to embed a watermarking signal (a hidden pattern) into its ordinary outputs about that domain.

the object it moves  =  trigger mechanism and response encoding
The hidden quantity

The hidden watermarking signal

measured quantity  =  Statistical watermark in word choice patterns

The hidden quantity is a subtle bias in the model's word choices when responding to questions in the chosen domain. Normally, when an LLM answers a question, each word it picks comes from a probability distribution (the model assigns a different likelihood to each possible word — a list of numbers that add up to one). The watermark nudges these likelihoods slightly but consistently — making certain words slightly more probable and others slightly less probable — in a way that survives retraining and number-compression because it is statistical (spread across many small adjustments) rather than memorized (a single odd response).

To detect the watermark, the owner uses a statistical test (a method to check whether the observed pattern of word choices is unlikely to occur by chance) over many model outputs to verify the hidden signal is present. Since the signal only appears for prompts in the chosen domain, the owner can verify both who built the model and what domain triggers it.

Why it works

Why the statistical pattern survives

The old fingerprint breaks because it relies on a single memorized fact: the model learned 'if you see this exact trigger, output this exact strange phrase.' When the model is retrained or compressed, this memory gets overwritten or pruned. In contrast, the watermark is a statistical tendency woven into how the model assigns probabilities to every word in its domain. Because the bias is small and spread across many word choices, retraining does not erase it — it becomes part of the model's overall pattern of preference. Compressing the model's numbers also preserves the statistical bias because it compresses the entire weight distribution together, leaving the relative ordering intact.

The mechanism hinges on semantic conditioning: the model only embeds the watermark when it detects that the prompt is about the chosen domain. This makes the fingerprint stealthy — the model's normal outputs to other topics are unchanged, so an attacker cannot spot the watermark by looking at random outputs. To verify ownership, the owner queries the model on the domain repeatedly and collects many responses. A statistical test then measures whether the pattern of word choices is too biased to occur by random chance. If it is, the owner has proof of ownership.

The watermarking equation

First in words:

For each prompt in the chosen domain, adjust each token's probability by adding a tiny signal strength times a secret key.

Then the compact form:

p_watermarked(token_i) = p_original(token_i) * exp(alpha * k_i)

Every symbol:

p_original(token_i)the model's normal probability for token i
p_watermarked(token_i)the adjusted probability after adding watermark
alphawatermark strength, a small positive number
k_ia secret key value specific to token i, chosen by the owner
exp()the exponential function
A tiny worked example
Say the model normally assigns likelihoods: word A gets 0.30, word B gets 0.25, word C gets 0.20, word D gets 0.15, word E gets 0.10.
The owner chooses alpha = 0.05 and a secret key list (just a list of numbers) where k_A = 1.0, k_B = -0.5, k_C = 0.0, k_D = -1.0, k_E = 0.0.
Apply the formula: p_A_watermarked = 0.30 * exp(0.05 * 1.0) = 0.30 * 1.051 = 0.315; p_B_watermarked = 0.25 * exp(0.05 * -0.5) = 0.25 * 0.975 = 0.244; p_C_watermarked = 0.20 * 1.0 = 0.20; p_D_watermarked = 0.15 * exp(0.05 * -1.0) = 0.15 * 0.951 = 0.143; p_E_watermarked = 0.10 * 1.0 = 0.10.
Total = 0.315 + 0.244 + 0.20 + 0.143 + 0.10 = 1.002 (renormalize by dividing each by 1.002).
Subtle change: A is now slightly favored (0.314 instead of 0.30), B is slightly disfavored (0.243 instead of 0.25). Over hundreds of outputs, this pattern becomes statistically detectable.

The exponential adjustment is tiny but persistent: it nudges the model's probabilities in a secret direction, leaving the outputs looking natural while creating a detectable statistical signature.

What can go wrong

What can go wrong

Domain is too narrow or too common. If the owner chooses a domain that the model almost never encounters (like Icelandic poetry) or one that appears constantly (like English), the watermark becomes either too rare to detect or drowned in noise. The owner must pick a domain common enough to generate many outputs but specific enough to isolate the fingerprint.
Adversary knows the domain or watermark strength. If an attacker learns the chosen domain and the watermark strength alpha, they can deliberately shift the model's probabilities in the opposite direction to cancel out the fingerprint. Defense: keep the domain and alpha secret, and update them periodically.
Multiple unrelated retrainings compound errors. Each retraining step adds a small probability shift. Over many retrainings, these shifts can accumulate and degrade the watermark's strength. The owner must detect ownership before the signal decays too much.
Done right. The owner picks a semantically coherent domain, keeps the watermark strength and trigger secret, and performs ownership verification tests regularly before the model is retrained extensively.
What a runnable demo should prove

What a runnable demo should prove

Build a small language model (or use a pretrained one) and teach it to watermark responses about a single domain, say responses to questions in French. Collect one hundred model outputs answering French questions and one hundred model outputs answering English questions. For each set, measure the statistical signature (run a chi-squared test or similar to check if word frequencies deviate from the model's baseline). The French outputs should show a significant deviation; the English outputs should not.

detection_power = (deviation_french - deviation_english) / deviation_french

The demo is complete when the watermarked French outputs show a statistically significant signal (e.g., p < 0.05) that does not appear in the non-watermarked English outputs, proving the watermark is domain-specific and detectable.
