Baguan-TS: dual in-context learning for time series forecasting

A model that learns to forecast future values by using both raw data patterns and contextual examples at prediction time, without retraining.

Paper explainersAll themesTime Series & Sequential

Time series forecasting asks: given the past numbers in a stream, what comes next? Most models either learn from raw data but cannot adjust to new situations at prediction time, or use hand-picked features but lose important patterns. Baguan-TS bridges this by combining raw data learning with in-context learning, a technique that lets the model adapt to new forecasting tasks just by looking at recent examples, without retraining.

Zero assumption version

Why time series forecasting is stuck

Consider tracking electricity demand hour by hour. You have the past 168 hours of demand, plus side information like temperature and day-of-week. The naive approach is to train a model once on historical data and then use that same model to predict forever. But here is the problem: real-world streams drift. Summer demand patterns are different from winter; an unexpected heat wave changes everything. A model trained last month may be permanently out of sync with today's reality.

Most existing models use one of two bad choices. Hand-crafted feature models (those that explicitly engineer inputs like 'rolling average of the past 7 days') can adapt if you retrain them, but they ignore raw signal patterns that are too complex to write down by hand. End-to-end deep models (a type of neural network that processes sequences, which reads the raw data as a list of tokens—individual data points) can learn raw patterns but have no built-in way to adjust at prediction time. You must retrain the entire model, which is slow and often impractical.

In one sentence. The model learns raw data patterns while also being able to instantly adapt to new conditions by examining recent examples at prediction time.

What the paper changes

The single thing the paper changes

Most forecasting models learn once, then predict the same way forever. Baguan-TS changes the prediction path itself: it inserts a retrieval step that pulls recent examples mid-inference (during prediction), then uses those examples to recalibrate the forecast before outputting it. This happens at prediction time, not at training time.

the object it moves  =  prediction path: retrieval + recalibration
The hidden quantity

The hidden quantity: local calibration drift

measured quantity  =  per-step drift from data pattern

As time passes, the pattern of time series values shifts. Yesterday's patterns do not perfectly match today's conditions. The paper measures how far the current values have drifted from the patterns the model saw during training. This is the drift: the mismatch between what the model expects and what the stream actually contains.

The paper estimates this drift by looking at recent examples that are most similar to the current time step (this is called retrieval-based local calibration). Instead of using one global offset for all time, it computes a small local offset just for the current context window, then applies that offset to the raw prediction.

Why it works

Why it works: the dual learning path

The paper solves two problems at once. First, the raw-sequence representation learning: a transformer with 3D attention (time, variables, context) learns complex patterns from all the data together—temperature interacting with demand, seasonal cycles, weekly rhythms. This is the foundational knowledge, learned during training and never updated.

Second, the in-context adaptation: at prediction time, before outputting, the model looks at the last few hours of actual data and finds the most similar historical moments. It computes the gap between what it would have predicted for those moments (during training) and what actually happened. This measured gap is the drift. By applying that measured drift as a correction to today's forecast, the logic is: if my patterns were this far off back then under these conditions, they are probably this far off right now too.

Why does this work? Because the underlying patterns (learned from training data) are actually stable—demand follows temperature and seasons. What changes is a slow shift in the level or scale. By locally measuring that shift from recent neighbors and applying it as a small correction, the model keeps the learned patterns intact while adapting to the current regime. The context-overfitting strategy (deliberate overfitting to the current context window) lets the model weight these recent examples very heavily without corrupting the foundational patterns.

Math after the picture

The equation: offset-corrected forecast

First in words:

final forecast equals the model prediction plus a calibration offset, where the offset is the average gap between predictions and true values from the most similar recent hours.

Then the compact form:

forecast_t = model(x_t) + mean( y_retrieved - model(x_retrieved) )

Every symbol:

forecast_tthe final forecast for time t
model(x_t)the model's raw prediction at time t
y_retrievedtrue values from the k most similar past hours
model(x_retrievedwhat the model predicted for those same past hours
mean( ... )the average offset across the similar hours
A tiny worked example
Suppose the model predicts demand at 3pm = 85 MW.
We find the 3 most similar past hours: 2pm yesterday (pred 80, true 82), 3pm last week (pred 88, true 91), 4pm five days ago (pred 86, true 89).
Gaps: yesterday was +2 (82−80), last week +3 (91−88), five days ago +3 (89−86).
Average gap = (2+3+3)/3 = 2.67 MW.
Final forecast = 85 + 2.67 = 87.67 MW.

The offset adapts each hour, using only the most similar neighbors, so it captures local drift without retraining.

What can go wrong

What can go wrong

Insufficient context history. If the lookback window is too short, there are no good neighbors to retrieve, and the offset is based on random noise instead of real drift. Predictions revert to the uncalibrated model.
Sharp regime change. If the stream suddenly shifts (a power grid outage, a holiday that changes all patterns), the recent neighbors no longer resemble the current hour. The retrieved offset is from yesterday's conditions, which no longer apply today, so adding that old offset to today's forecast pushes the prediction further from reality.
Overfitting to context. The context-overfitting strategy deliberately fits the model to recent examples to make recalibration strong. If this is too aggressive, the model may memorize noise and forget its foundational patterns.
Done right. When the stream drifts slowly and recent history is representative, the model adapts smoothly. The learned patterns remain valid, and the local offset captures the drift, improving forecast accuracy.
What a runnable demo should prove

What a runnable demo should prove

Implement a simple time series with three regimes: a training regime, an early test regime (similar to training), and a late test regime (drifted from training—say, demand is 15% higher at all hours). Compare three methods: (1) a standard transformer trained once, (2) a transformer retrained at the drift point (expensive but oracle), and (3) Baguan-TS with retrieval-based local calibration. Measure root-mean-square error (a measure of how far predictions are from truth, computed by taking the square of each error, averaging, and taking the square root). Plot error over time for all three.

RMSE = sqrt( mean( (forecast - true)^2 ) )

Baguan-TS should match retraining without the retraining cost, and beat the standard model in the drifted regime.
