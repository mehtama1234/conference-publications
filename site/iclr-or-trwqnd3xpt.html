D2E: Desktop to Embodied AI

Robots learn from video games because the way hands and eyes work together is the same in both worlds.

Paper explainersAll themesRobotics & Control

Building robots requires expensive recordings of real robotic arms moving things. This paper shows that video game interactions—keyboard presses, mouse clicks, and screen changes—contain the same sensorimotor patterns (how vision shapes action and action shapes what to see next). By converting game recordings into a standard format and teaching a model to predict the next keyboard or mouse press from screen frames, the model learns movement primitives that work on actual robots.

Zero assumption version

Why robots are stuck learning from scratch

Large language models (models trained to predict text) can train on billions of words from the internet for free. But robot learning requires recordings of robot arms actually moving real objects, which costs thousands of dollars per hour. A robot with 1000 hours of arm movement data is considered well-trained; a language model trains on millions of hours of text.

A beginner would try to collect more robot videos by hiring people to move arms, or by letting robots move randomly and keeping videos where something interesting happens. This is slow and expensive. The unsolved problem: where is there a free, massive source of motor movement that pairs vision to action the same way robotics does?

The method in one sentence: Train a model to predict keyboard and mouse clicks from video game screenshots, then transfer that learned model to predict robot arm movements from camera images.

The algorithm as a flow

What it actually does

Convert game videos to events

Extract every screen frame, keyboard press, and mouse click, then compress into a compact token format (152 times smaller than raw video).

Predict the next action

Train a model (InternVL3) to look at a screen and predict which key or mouse button comes next, using timestamp-based prediction to know where to look in time.

Auto-label gameplay

Run the trained model on 1000+ hours of new gameplay videos to generate predicted keyboard and mouse labels, creating a massive labeled dataset.

Pretrain a general model

Train a vision-action model on the combined labeled dataset (human demos plus auto-labeled games), learning how cameras and actions co-occur.

Transfer to real robots

Take the pretrained weights and fine-tune on real robot videos. The model already knows how vision drives movement.

What the paper changes

What the paper changes

The paper modifies the pretraining substrate (the source of learning data). Instead of teaching robots only from expensive robot videos, it adds freely available game video and auto-generated predictions as a pretraining stage. The model learns on games first, then specializes on robots.

the object it moves  =  pretraining source (games + robots)
The hidden quantity

The hidden quantity: sensorimotor invariance

measured quantity  =  sensorimotor pattern transfer fidelity

This is the paper's core unstated assumption: the mapping from vision to action is invariant (stays the same) across different physical embodiments. A sensorimotor primitive is a learned pairing between what the eyes see (image patterns) and what the hands do (motor commands). In games, a sprite moving right triggers a right-arrow key. In robotics, a block moving right requires a rightward arm push. The pixel patterns and arm angles differ, but the causal direction—visual change triggers motor change in a consistent way—is identical.

The paper estimates this by training on game videos and measuring whether the learned weights transfer to robot tasks without catastrophic forgetting. If transfer fidelity is high, the model learned a genuine sensorimotor primitive, not a game-specific trick. The paper validates this by testing on LIBERO manipulation and CANVAS navigation benchmarks.

Why it works

Why the method works: pretraining on abundant data

Models learn by seeing thousands of vision-action pairs and gradually tuning their weights so that given a visual input, the predicted action gets closer to the real action. This tuning requires data. Game videos provide 1000+ hours of this pairing for free, so the model's weights are already partially configured to handle vision-action mappings, because during training, each example moves the weights slightly closer to the pattern 'when you see this image, do this action'. When fine-tuned on robot data (which is expensive but now only needs hundreds of hours instead of thousands), the model starts with weights that already understand the link between camera frames and motor commands. It only needs to adjust details—which arm joint angles replace which keyboard presses—rather than learning the mapping from scratch.

The temporal offset mechanism (predicting the next action τ steps ahead instead of right now) matters because of latency: a screen change does not instantly cause a key press; there is a delay. By training the model to predict actions ahead by a fixed time, the model learns to think causally—'what action will be needed when this visual change happens'—rather than reactively. This causal thinking transfers cleanly to robots because both games and robotics have the same latency structure.

Math after the picture

The prediction equation and worked example

First in words:

action_next = predict(vision_frame, context_window)

Then the compact form:

loss = cross_entropy(predicted_event_tau, actual_event_tau)

Every symbol:

predicted_event_tauthe model's guess for what keyboard or mouse action happens τ steps ahead
actual_event_tauwhat action actually happens τ steps in the future
tautime offset in frames (e.g. if frame rate is 20 Hz, tau=3 means 0.15 seconds ahead)
cross_entropya measure of how surprised the model is by the true answer (lower is better)
context_windowthe previous frames the model sees to make its prediction (e.g. last 256 frames)
A tiny worked example
Scenario: Game video at 20 Hz, tau=3 (predict 0.15 seconds ahead).
Frame 0: see sprite in center, predict key=RIGHT (confidence 85%, surprise score 0.15).
Frame 3: sprite actually moves right. Action was RIGHT. cross_entropy loss = -log(0.85) = 0.163.
Frame 100: see sprite moving down, predict key=DOWN (confidence 92%, surprise score 0.08).
Frame 103: sprite moves down. cross_entropy loss = -log(0.92) = 0.083.
Lower surprise score on downward motion means the model learned that downward sprites reliably predict downward actions.

The loss number measures how wrong the model's guess was. When loss shrinks, the model is getting the right actions, proving it learned the vision-action link.

What can go wrong

What can go wrong

Spurious game-specific correlations. A model might learn that clicking a particular on-screen button triggers a menu, which is game-specific and does not exist in robotics. If the model relies on this shortcut, transfer fails. Solution: use consistency checks to filter auto-labeled data and ensure only causal patterns survive.
Temporal misalignment. If the prediction offset τ is wrong (e.g., the model predicts actions 0.05 seconds too early or late), it learns anti-causal patterns. In robotics, this causes jerky or delayed movements. Solution: calibrate τ per game and validate on unseen games before auto-labeling.
Pixel-level shift at transfer. Game cameras use different resolutions, colors, and viewpoints than robot cameras. A model that overfits to game pixel values (e.g., learns that 'pure red means right') will fail on robot images with different lighting. Solution: use a pretrained vision encoder (InternVL3) that has already seen diverse real-world images.
Transfer works well. When the vision encoder is generic (not game-specialized) and the action prediction task is framed causally (with temporal offset), the learned weights contain only the invariant sensorimotor patterns, not game artifacts.
What a runnable demo should prove

What a runnable demo should prove

Build a small-scale proof: (1) collect 10 hours of game video (e.g., a driving game or real-time strategy game where clicking the mouse triggers movement), (2) extract screen frames and mouse clicks, (3) train a small vision-action model (e.g. a ViT encoder plus a linear action classifier) on next-click prediction with temporal offset, (4) on a different game engine (or sim2real using a video game-like robot simulator), show that the pretrained weights transfer with >80% accuracy on action prediction compared to a model trained only on simulator data.

transfer_success_rate = (actions_predicted_correctly_on_robotics_task / total_actions_in_robotics_task) * 100

The demo makes it impossible to deny: the model learned motor thinking, not game trivia, because if the weights were purely game-specific, they would fail completely on a different visual domain—yet they predict actions correctly in two entirely different visual worlds, proving the learned pattern is general.
