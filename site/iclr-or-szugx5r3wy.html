Self-Improving Loops for Visual Robotic Planning

A robot learns to solve new tasks by repeatedly watching itself perform, filtering the good attempts, and retraining on them.

Paper explainersAll themesRobotics & Control

Video models that predict video frames work well at planning robot arm movements. But they fail on tasks they have never seen before, because they have no data for those tasks. This paper proposes SILVR: the robot generates a sequence of video frames showing what it will do next, watches itself execute it in reality, keeps only the attempts that succeed, and uses those to retrain its model. It repeats this loop. Over multiple iterations, the model generates trajectories that succeed more and more often, because it learned from examples of what actually worked.

Zero assumption version

Small training sets limit what robots can learn

A video model is trained on a handful of human-performed robot arm movements recorded as video. It learns to predict: if I ask for task X, what frames should play? It becomes a planner—the model generates the next frame, the robot executes it, then generates the next frame. Works great on those training tasks.

But ask it to solve a task it never saw before—say, move the blue object to a different spot than any training example—and it fails. The model has no experience with this scenario. A human could guess something similar from what they learned before. The model cannot. It is stuck with only the data it was shown.

The naive fix: collect more human demonstrations of all possible tasks. Infeasible. There are infinitely many task variations.

In one sentence. A robot learns to solve new tasks by generating predictions of its own movements, filtering for success, and retraining on them.

The algorithm as a flow

What it actually does

Start with a small model

Video model trained on a few dozen in-domain examples and general internet video data.

Generate a trajectory

Model predicts the next frame, robot executes it, model predicts next frame, repeat until done.

Measure success

A sparse reward checks if the task succeeded (no human label needed; can use a vision-language model).

Filter and collect

Good trajectories are saved; bad ones discarded.

Finetune and loop

Successful trajectories are mixed back into training data; model retrains. Return to step 1.

What the paper changes

What changes: the in-domain video model

The paper changes the weights of the in-domain video model (the one trained on in-domain demonstrations). During each iteration, trajectories that succeeded are used as new training examples. The model sees: this sequence of frames led to success on this task. Over multiple loops, the model's weights shift to prefer actions that work for the new task.

The hidden quantity: task success rate per iteration

measured quantity  =  success fraction over self-improvement loops

The paper measures how often the robot solves the task correctly over the iterations. Start with near zero (model has no idea); each iteration, the fraction of successful attempts grows.

The paper estimates this by running the learned trajectory and checking if the end state matches the task goal. No human annotation. Just: did the object end up where we asked? A pretrained vision-language model can also score success based on the task description alone.

Why it works

Why the loop works: better data beats memorization

A neural network, like any model, learns patterns from the data it sees. When trained only on human demonstrations of task A and task B, it memorizes: task A looks like this, task B looks like this. Show it task C, and it has nothing to anchor to. It guesses randomly.

But here is the key: if the model can generate its own attempt at task C, and we tell it which attempts succeeded, it now has real data for task C. The model retrains on this new data. Its weights (the numerical values inside the model) shift to match the patterns in successful-attempt videos. The next time it tries task C, it generates trajectories closer to success, because those weights now encode what success looks like from the examples it just learned. More of those new trajectories succeed. More successful data gets collected. The model retrains again with even more examples. The loop compounds.

This works because a video model's job is simple: given a task description and context, predict the next frame. If you show it a thousand frames of successful executions of the same task, it learns: when you see a red box and hear the task description, generate frames that move the red box. It does not need human creativity or explicit programming. Just data from the task itself.

The training equation

First in words:

The finetuning loss minimizes prediction error on successful trajectories only. Each successful video sequence contributes a term. The model adjusts its weights to lower the error.

Then the compact form:

L_finetune = sum over successful trajectories T { loss( model_predicted_frames(T), actual_frames(T) ) }

Every symbol:

L_finetunethe total error to minimize during finetuning
model_predicted_frames(T)frames the model generates for trajectory T
actual_frames(T)frames actually recorded when the robot executed T
lossframe prediction error (e.g., pixel difference)
sum over successful trajectories Tadd up the error for only the trajectories that succeeded
A tiny worked example
Suppose we run the robot 10 times on a new task. Iteration 1: 1 succeeds, 9 fail.
We keep the 1 successful video. The model retrains on just that 1 example.
Iteration 2: model has learned from 1 successful trajectory. Now 3 of 10 attempts succeed.
We keep all 3. The model retrains on 1 + 3 = 4 examples (the old successful one plus 3 new ones).
Iteration 3: model has seen 4 successful examples. Now 6 of 10 succeed. Pool grows to 4 + 6 = 10.
Each iteration, the pool grows and the model improves because it learns from real data of success.

The model treats successful self-collected trajectories as if they were expert demonstrations, without human effort.

What can go wrong

What can go wrong

Bad reward signal breaks the loop. If the success detector (sparse reward) is too noisy or wrong, the model retrains on bad trajectories. It learns to repeat mistakes. The paper shows this matters: with a wrong reward, improvement stalls.
Very poor initial model never generates anything close to success. If the in-domain video model is trained on terrible data (e.g., random motion), it generates nonsense trajectories. None succeed. No data is collected. The loop never starts. The paper uses internet-scale video data to bootstrap quality.
Task is too hard for the model's architecture. If the task requires reasoning the video model cannot express (e.g., planning 100 steps ahead when trained on 10-step clips), longer trajectories will fail. More data does not help, because the model is not capable of learning the pattern.
Done right: clear reward signal, reasonable task difficulty, and good initial training data. The paper shows that with a sparse but correct reward and modest in-domain training, the loop works well. The paper demonstrates this even with suboptimal initial demonstrations: over iterations, the collected-successful-trajectory data eventually outweighs the initial noise, so performance climbs.
What a runnable demo should prove

What a runnable demo should prove

Build a simple robotic manipulation simulation (MetaWorld or PyBullet). Train a small video model on 5 human demonstrations of task A. Now ask it to solve task B (never seen). It should fail most of the time. Implement the self-improving loop: generate trajectory, check if it succeeds, keep it, retrain the model. Run 5 iterations. Plot success rate over iterations. It should climb from near zero to 60+ percent. The only data the model sees for task B is its own successful attempts.

task_success_rate = (count of successful trajectories) / (total trajectories generated) per iteration

The demo proves the core insight: a model can learn to solve new tasks it was never trained on, by learning from examples of what its own generated trajectories do when they succeed.
