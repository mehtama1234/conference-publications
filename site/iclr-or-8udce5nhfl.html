P3D: Scalable 3D Physics Surrogates

P3D trains neural models on tiny patches of physics simulations, then glues them together using global context to predict large turbulent flows without running out of memory.

Paper explainersAll themesAI for Science

Predicting 3D physics simulations is painfully slow: a full high-resolution weather forecast or fluid-dynamics simulation can take hours. This paper presents P3D, a neural surrogate (a learned model that mimics the simulation) built from two parts: a local learner that sees only a small patch of space at a time, and a global stitcher that connects patches and passes long-distance information between them. This design lets you train enormous models on billion-element grids without exceeding GPU memory.

Zero assumption version

Why naive neural surrogates choke on big 3D data

A standard neural network reads the ENTIRE grid of a physics simulation at once. For a grid with 512 points in each of three dimensions, a snapshot is 268 million numbers and requires mountains of graphics-card memory and compute. A naive approach: train a single giant model on the full grid. It crashes. A second attempt: make the model smaller, but then it can only see local patterns and misses the global structure — a hurricane cannot feel the jet stream sitting 1000 miles away. A third attempt: train many small models, one per patch, but they work independently and contradict each other at the seams.

The fundamental problem: you want to learn patterns that span thousands of grid points (the jet stream carrying heat thousands of miles), but you cannot afford the memory cost of looking at thousands of grid points at once.

The move Train on tiny patches using fast local feature detectors (filters that see only nearby grid points), then wire them together with a global stitcher that passes information between patches without reading the whole grid at once.

The algorithm as a flow

What it actually does

Step 1: Crop training

Take the big 3D simulation. Chop it into overlapping small boxes (128 voxels on each side). Feed each box separately to the CNN part.

Step 2: Local learning

The CNN (convolutional layers) learns how pressure, velocity, and temperature evolve within a single small box by seeing only neighbors two grid-points away.

Step 3: Bottleneck summary

Each box's learned representation gets compressed into a compact summary at the bottleneck (middle of the U-shape architecture). Think of it as a postcard from that box.

Step 4: Global assembly

A sequence model (a Transformer-like layer) reads all the postcards and figures out which patches influence which, passing signals across the whole domain.

Step 5: Decode and stitch

The global context gets injected back into the decoder (the expanding half), and each patch predicts its next state. Seams align because they all received the same global context.

What the paper changes

The one thing that changes

P3D changes how much spatial context the model can see at training time. Standard surrogates try to absorb the entire grid in one pass. P3D instead processes the grid in overlapping tiles, then bolts a global aggregator onto the bottleneck so the tiles can still coordinate. The trainable parameters live in three places: the local CNN (which sees only a small patch), the global context model (which sees summaries of all patches), and the decoder (which transforms global context + local features into predictions).

The hidden quantity

The hidden quantity: Patch communication signal

measured quantity  =  How much global information flows across seams

At the bottleneck, each patch has a summary — a list of numbers (a vector, which is just numbers in a row) representing what happened in that box. The global context model reads these summaries and learns which patches depend on which others. If patch A's prediction relies on the wind pattern in patch B (far away), the context model must pass a signal from B's summary back to A's decoder. This signal is the hidden quantity: a measure of how much information from distant patches actually reaches each local decoder.

P3D estimates this flow using the weights and activations (the intermediate values computed while the model is running) of the context model. If those weights are large, information is flowing. If they are small or zero, the patches are ignoring each other, which is a sign that training has broken down.

Plain reading Imagine you are trying to forecast rain in Boston, but you train your model to look at only a 50-mile radius. You cannot see the hurricane approaching from Florida. Your local model fails near the domain boundary. But if you add a global context layer that reads summaries from other regions, it can warn your local decoder, 'This is hurricane season, expect big changes.' That warning is the hidden signal.
Paper reading The paper measures this flow by tracking the values inside the Transformer bottleneck. When the context model has high output strengths and the region signals (short summaries representing each patch's state) carry large values, the patches are exchanging information that matters. The paper validates this by checking if removing the context layer hurts accuracy on large domains — if the hidden signal is strong, removing it causes large drops.
Why it works

Why splitting the grid and stitching it back works

The reason is translation equivariance: if you slide the whole simulation domain one grid-point left, the physics slides with it. A vortex at position X behaves the same way as the identical vortex at position X plus one. This means you can train on a small crop at position X, then move that trained model to position X plus 100 and it still works. P3D exploits this by training only once on crops 128 voxels on a side, then sliding that same model across the full domain (512 voxels on a side) when making predictions.

But sliding alone causes seams to be wrong: the patch centered at position 200 predicts what happens there, and the patch at position 201 independently predicts position 201, but they did not see each other during training, so their predictions fight at the boundary. P3D solves this by adding a global context model at the bottleneck. This model reads the summaries (the compressed representations) of all patches in parallel and computes which patches influence which. It then injects this global context back into each local decoder. Now when patch 200's decoder predicts, it receives a signal saying, 'Patch 201 has decided to increase pressure by 0.5; adjust your pressure boundary accordingly.' The context model acts as a negotiator, ensuring all patches agree on seam values.

The practical win: you train on small crops (much less memory than full-size), yet when making predictions you scale to huge domains because the local feature detector already learned patterns that work everywhere, and the context model coordinates the stitching. This runs in a fraction of the memory and time of a full-domain model.

Math after the picture

The core balance equation

First in words:

Total prediction error equals local patch error plus seam mismatch error weighted by how strong the global context signal is.

Then the compact form:

Loss = MSE(patch_predictions, ground_truth) + lambda * MSE(seam_values) + alpha * Context_Strength

Every symbol:

patch_predictionsWhat the decoder outputs for each voxel given local + global inputs
ground_truthThe actual next simulation state from the physics solver
seam_valuesPredictions at the boundaries where two patches touch
lambdaPenalty weight for seam mismatches
alphaPenalty for weak global context signal
Context_StrengthMagnitude of the context model's output (how much it is trying to communicate)
MSEMean squared error: average of all the squared differences
A tiny worked example
Imagine a 2×2 simulation with 4 patches, training step 1.
Patch A predicts 0.8, ground truth 0.75 -> patch error = (0.8-0.75)^2 = 0.0025
All 4 patches sum to MSE = 0.012 average.
Seam between patches A and B: A predicts 0.8, B predicts 0.6 (differ by 0.2) -> seam error = 0.2^2 = 0.04
There are 4 seams; total seam error = 0.08.
Context model output magnitude = 0.3 (it is communicating moderately).
Loss = 0.012 + 1.0 * 0.08 + 0.5 * 0.3 = 0.012 + 0.08 + 0.15 = 0.242
If context signal was zero (0.0), loss = 0.092; if strong (2.0), loss = 1.012.
Training nudges the context model and decoders to increase context signal (make neighbors coordinate) and close the 0.2 seam gap.

The equation says: get the patch predictions right, keep the seams consistent, and ensure the global context is actively helping (not just parasitic dead weight).

What can go wrong

What can go wrong

Seams do not align when the global context model is not trained. If you train only the local feature detector and skip the context model, each patch predicts independently. At the domain boundary, patch A says the pressure is 100 and patch B says 99. The simulation becomes unstable because the prediction at the boundary has a discontinuity (a jump), which breaks the physics. The fix: ensure the context model is enabled and receiving weight updates (the nudges that improve it) during training, so it can learn to make neighboring patches agree on boundary values.
Cropping breaks physics that spans larger than a patch. Some simulations have patterns (like large rotating cyclones) that are bigger than 128 voxels on a side. If the pattern is 200 voxels wide, two adjacent patches will each see only half of it, and their local feature detectors cannot learn the full pattern. The context model tries to compensate, but it cannot always succeed. The fix: increase crop size (costs memory) or detect oversized patterns and use larger crops for them.
Autoregressive rollouts diverge after many steps. Even with the context model, predictions drift over many time steps. Each prediction is slightly noisy, and noise accumulates. The paper addresses this by retraining on ground-truth samples every few steps, but long-term forecasting (beyond 50 steps) remains hard.
Done right: global context is active and adaptive. When the context model is trained jointly with the local feature detector and decoder, it learns to pass important signals across seams. Patches do not behave as isolated cells; they negotiate via the bottleneck. The result is a model that scales to 512 voxels on a side and beyond without using unimaginable GPU memory or time.
What a runnable demo should prove

What a runnable demo should prove

A minimal demo: take a 3D snapshot of fluid flow (e.g., a 256-voxel-side slice of turbulent water). Chop it into 64-voxel-side crops with 50 percent overlap. Train P3D on the crops for one time step using mean squared error (average of squared differences between prediction and truth). Then test: (1) run the full cropped prediction and reconstruct the full domain, comparing to ground truth; (2) measure pressure and velocity at the seams between crops, checking that they match within 2 percent; (3) measure the error in the corner regions (where crops overlap), showing it is no worse than the center (proving the model is not cheating by memorizing boundaries). The demo must be small enough to fit in a laptop's GPU (use synthetic data or a real small dataset like a 64-voxel-side slice of incompressible flow).

Seam_Consistency = max_seam_voxels |Prediction_A - Prediction_B| / mean(|ground_truth|)

The seam metric must stay below 0.05 (5 percent error) for the coordinate mechanism to prove itself. If it exceeds 0.15, the global context model is not working and you should inspect the context weights.
