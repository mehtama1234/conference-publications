Portable clinical embeddings via LLM summaries

Convert messy hospital time-series data into portable text summaries that models trained at one hospital can use at another, with minimal retraining.

Paper explainersAll themesTime Series & Sequential

Clinical prediction models work well at the hospital where they are trained, but fail at other hospitals because the data patterns are different. This paper asks: can we turn irregular ICU measurements (irregular timing, missing values, different hospitals' measurement styles) into clean text descriptions using a large language model, then convert those descriptions into fixed-length numbers (vectors) that work across hospitals? The answer is yes — and it is surprisingly simple.

Zero assumption version

Hospital data is messy and shifts between sites

Every hospital measures patients differently. Vital signs come at different times, some measurements are missing, machines and coding standards vary. A model trained to predict patient outcomes at Hospital A uses data in one shape; Hospital B's data is in a different shape. The model trained at A fails at B, not because it is broken, but because the input data does not match what it learned.

A beginner's first try: collect more data from many hospitals and retrain the model. This works, but it is slow (months of data collection), expensive (paying people to label), and gives away the model — each hospital must build its own. What we need is a single trained model that can be sent to any new hospital and work right away, even if the data format is slightly different.

The challenge. Clinical models fail when the input data format shifts between hospitals, and retraining everywhere is too expensive.

The algorithm as a flow

What it actually does

Step 1: Take irregular ICU data

Heart rate, oxygen, glucose — at different times, some missing, different hospitals' formats.

Step 2: Write a text summary using LLM

Frozen LLM reads measurements and writes a short patient description in English.

Step 3: Turn text into numbers

Frozen text-to-numbers model converts the summary into a fixed-length vector (a list of numbers).

Step 4: Feed vector to prediction model

Downstream classifier or forecaster uses the vector to predict outcomes.

Step 5: Deploy to new hospital with minimal retraining

The same vector works across sites; only the final predictor may need light adjustment.

What the paper changes

The thing that changes

This paper changes how we represent the input. Instead of feeding raw time-series numbers directly to the predictor, we first convert them to text, then to a fixed vector. That vector is the new input.

the object it moves  =  input representation
The hidden quantity

How much the data pattern changes between hospitals

measured quantity  =  domain shift severity

The paper measures something implicit: how much the input data pattern changes when a model moves from one hospital to another. If Hospital A and Hospital B measure the exact same way, there is no shift. If they measure very differently, the shift is large.

The paper estimates this by testing the same model at different hospitals and watching accuracy drop. A small drop means low shift; a big drop means high shift. The paper's key finding is that shifting from raw numbers to portable embeddings reduces this drop — meaning the LLM+embedding pipeline is less sensitive to hospital-specific quirks.

Why it works

Why portable embeddings survive hospital shifts

An LLM trained on general English text does not memorize one hospital's quirks. When it reads an irregular measurement sequence and writes a summary, it extracts the clinical fact (e.g., 'patient has normal oxygen') and leaves out the hospital's idiosyncratic numbering or timing. A text embedding model trained on billions of texts works the same way — it knows that 'normal oxygen' and 'O2 95 percent' mean the same thing, regardless of what hospital said it.

Here is the concrete chain: Raw data at Hospital A (specific format, specific timing) gets turned into English words (the clinically relevant facts, format-neutral). Those words are embedded using a general text model (which has seen many ways to say the same thing). The resulting vector captures the clinical state, not the hospital's measurement style. When you send that same vector to Hospital B and feed it to a predictor trained at Hospital A, the predictor sees the same clinical facts in the same encoding, so it works.

Why this beats retraining: the raw-data path forces the predictor to learn hospital-specific patterns. The text path makes the predictor learn clinical patterns. Since clinical facts are universal, the latter transfers.

The portable embedding formula

First in words:

portable vector equals text embedding of LLM summary of raw data

Then the compact form:

v_portable = TextEmbed(LLM(raw_data))

Every symbol:

raw_datairregular time-series measurements from the hospital
LLM()large language model that summarizes clinical facts in English
TextEmbed()frozen text embedding model that converts words to a fixed-length vector
v_portablethe resulting vector, same shape regardless of input format
A tiny worked example
Hospital A raw data: (HR=88, O2=95, t1=10:30, t2=14:45, missing glucose)
LLM summary: 'Patient is 45 years old, vitals stable, heart rate normal, oxygen adequate, no sepsis flags.'
TextEmbed on that summary produces: v_portable = [0.12, -0.34, 0.67, ... ] (256 numbers)
Hospital B raw data: (Heart Rate=89, Oxygen Sat=96, glucose=110, logged 10:15 and 14:30)
LLM summary: 'Adult patient with stable vitals, normal breathing, blood sugar normal, no infection signs.'
TextEmbed: v_portable = [0.11, -0.33, 0.68, ... ] (same 256 numbers, very similar)
Both vectors work with the same downstream predictor because they encode the same clinical state.

The LLM and embedding model stay frozen (do not change during training); only the downstream predictor learns.

What can go wrong

What can go wrong

LLM makes clinical errors in the summary. If the LLM misreads the measurements or hallucinates a detail, the resulting vector is wrong. The paper finds that structured prompts (specific instructions on what to extract) reduce this variance.
Text embedding model has never seen the clinical context. If the embedding model was trained only on social media or news text, it may not accurately encode medical phrases. Using a general text embedding helps because it still captures meaning (e.g., 'stable' and 'normal' are close in meaning), but fine-tuning on medical text would help more because the model would learn medical-specific relationships (e.g., 'hypotension' and 'sepsis risk' are connected in clinical data).
Downstream predictor still needs some new-hospital data. The portable vector reduces the need for retraining, but the final predictor may still need a few examples from the new hospital to adjust to any residual differences in what the clinical facts mean there.
Structured prompts work best. When the LLM gets a clear, templated prompt (e.g., extract age, vital-sign status, risk flags), the embeddings are more reliable and less variable, because the LLM is constrained to look for the same clinical facts every time rather than improvising what seems relevant.
What a runnable demo should prove

What a runnable demo should prove

Build a tiny three-site demo: collect a small sample of time-series patient data (or synthetic ICU data) from three fictional hospitals. For each hospital, apply the LLM+embedding pipeline. Train a simple predictor (logistic regression on the vectors) at Hospital 1. Test it at Hospital 1, then at Hospital 2, then at Hospital 3 without retraining. Measure accuracy drop. Repeat with raw time-series baseline to show the difference.

transfer loss = (accuracy at train hospital) minus (accuracy at new hospital). Lower is better.

The demo must make it impossible to miss that vectors from the LLM pipeline have smaller transfer loss than raw time-series, proving they are more portable.
