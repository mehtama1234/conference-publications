SC-MILP: Contrastive Learning for MILP Branching

Train a decision-maker for tough optimization problems by grouping similar decision points and learning from crafted examples that preserve the problem's structure.

Paper explainersAll themesOptimization

Solving hard optimization problems (like factory scheduling) with neural networks is tricky: the network must make smart yes/no choices at different depths of a decision tree, but examples near the tree's root (the start) are scarce and hard to create. This paper groups decision points by their shape, then generates synthetic examples that preserve the problem's logical rules, so the network learns to make better choices everywhere—especially at the top where it matters most, because one choice at the root ripples through thousands of downstream branches.

Zero assumption version

Why today's solver assistants stumble

A factory scheduler needs to decide: should bin A hold widgets or bolts? That is a yes/no choice buried in millions of others. For 40 years, the Branch-and-Bound algorithm (a tree of choices) has been the standard way to solve these. Recently, neural networks have joined in—learning to guess which yes/no choice leads fastest to the solution.

But three pitfalls block the network: First, the same piece of the problem looks different depending on where you are in the decision tree (at the root it feels abstract; deep down it feels concrete). Second, near the tree's root—where one choice ripples furthest—there are few examples to learn from. Third, collecting good examples by asking a slow oracle is expensive.

The bottleneck. Neural solvers lose accuracy and speed when branching decisions arise early in the tree and the training data does not represent those moments well.

The algorithm as a flow

What it actually does

Group nodes by shape

Cluster B&B tree nodes based on their numerical features (the problem's structure at that moment).

Generate synthetic examples

For each group and each tree depth, forge new problem instances that stay logically valid but vary in details.

Collect good and bad branches

For each synthetic instance, find which yes/no choice reaches the goal fastest and which one is wasteful.

Train by contrast

Teach the network to pull the good choice and bad choice apart in a shared space, separately for each group and depth.

Deploy on new problems

At solve time, the network spots which group a node belongs to and makes the branching choice that its group learned.

What the paper changes

The one thing being changed

This paper changes how the network encodes each decision point. Instead of one generic encoding (which confuses the network), the network learns separate, depth-aware encodings for each cluster of nodes. A node near the root gets a different feature space than the same pattern deep in the tree.

the object it moves  =  Node representation per group and depth
The hidden quantity

Semantic coherence across the tree

measured quantity  =  Group-level branching quality

The paper measures something usually invisible: for each cluster of nodes at each tree depth, how often does the trained network guess the fast branch? This is split by depth and cluster, not just overall. A cluster at depth 3 might be excellent but useless if it never occurs in real problems.

The paper estimates this by running the trained network on the synthetic instances it generated, then on fresh real instances. If a cluster only shows up at depth 20 (near the leaves, where branching matters little), teaching it well is wasted effort. The paper's upstream augmentation flips this: it creates more synthetic examples at shallow depths so the network learns the groups that matter most.

Why it works

Why grouping and forged examples fix the problem

At the tree's root, the network sees an abstract summary: total slack in all constraints (the freedom left), rough variable bounds, but no detail. At depth 50, the network sees tight bounds and a few remaining choices. The same feature (say, slack of 10 units) is a hint of plenty at the root but a hint of scarcity at depth 50. Teaching one network on both is like teaching a driver to brake the same way in wet conditions and dry sand—the context changes everything.

SC-MILP solves this by teaching separate spaces for each (cluster, depth) pair. The same slack value at depth 3 gets a different label and learned reaction than slack at depth 30. This works because most real instances branch early; the network learns to branch well where it matters and is not distracted by deep nodes that rarely occur.

But example scarcity is still lethal: if no training instance ever branches at depth 2 in cluster B, the network guesses blindly. Synthetic generation (creating new problem instances with the same underlying rules but different coefficients) fills this gap. Each forged instance comes with an oracle label (the fast branch, computed by a slower algorithm), so the network trains on examples it would never see in nature.

The learning rule

First in words:

For each node in a group at a given depth, the network pulls the good-branch encoding closer and pushes the bad-branch encoding farther, weighted by how clear the difference is.

Then the compact form:

loss = sum over groups, depths, and node pairs of: -log( exp(sim(z_good, z_node) / tau) / (exp(sim(z_good, z_node) / tau) + exp(sim(z_bad, z_node) / tau)) )

Every symbol:

z_nodethe learned encoding of this node
z_goodthe learned encoding of a synthetically chosen good branch
z_badthe learned encoding of a synthetically chosen bad branch
sim(a, b)dot product of vectors (how aligned they are)
tautemperature (controls how sharp the contrast is)
A tiny worked example
Cluster 3, depth 5: node has encoding z = (1, 2, 3).
Good branch synthetic example encodes to z_good = (1.1, 2.1, 3.05).
Bad branch synthetic example encodes to z_bad = (-0.9, 1.8, 2.95).
sim(z_good, z) = 1*1.1 + 2*2.1 + 3*3.05 = 1.1 + 4.2 + 9.15 = 14.45.
sim(z_bad, z) = 1*(-0.9) + 2*1.8 + 3*2.95 = -0.9 + 3.6 + 8.85 = 11.55.
With tau = 0.1: exp(14.45 / 0.1) = exp(144.5) >> exp(115.5), so loss drives z closer to z_good.

The network nudges each node's encoding toward good branches in its (cluster, depth) space and away from bad ones, so later at solve time, similarity to good patterns guides the branching choice.

What can go wrong

What can go wrong

Clustering erases real structure. If nodes in the same cluster have opposite optimal choices due to subtle features, grouping them together trains contradictory signals. The network learns to hedge and both branches get slightly worse.
Synthetic examples do not preserve hard constraints. If forged instances allow infeasible branches the oracle would never take, the network wastes training signal on impossible paths and may learn brittle heuristics, because the network's learned contrast between good and bad branches collapses when it sees bad branches the solver would never consider anyway.
Upstream augmentation explodes the data. Generating too many synthetic examples at shallow depths can overwhelm shallow-depth training, leaving deep-depth clusters undertrained on real data.
Done right. Clusters are refined so similar nodes dominate; synthetic instances preserve the solver's feasibility constraints; synthetic instances are weighted by depth to reflect real problems' structure.
What a runnable demo should prove

What a runnable demo should prove

Build a small scheduler (10 items, 3 bins, 5 time steps) and gather 100 real branching trees. Train three networks: (1) a baseline with one shared encoder, (2) a depth-stratified encoder with real data only, and (3) SC-MILP with stratified encoding and synthetic upstream augmentation. On 20 held-out test instances, measure branching accuracy at tree depths 1-5, 6-15, and 16+. SC-MILP should show the largest gap against baseline at depths 1-5.

Accuracy by depth stratum = (correct_branches_in_stratum) / (total_branches_in_stratum)

The demo proves that depth-aware encoding plus synthetic examples make the biggest payoff where the network has the fewest natural examples but the most influence: at the tree's top.
