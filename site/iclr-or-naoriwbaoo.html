Neural Language Interpreter

A neural model learns its own discrete symbolic language and refines programs via gradient-based search (nudging with direction-and-size clues), combining compositional generalization with end-to-end learning.

Paper explainersAll themesOther

Program induction is stuck between two worlds. Symbolic methods (hand-written rule languages) generalize well to new problems because they reason in discrete steps, but they do not scale — you must laboriously craft each language by hand. Neural networks scale easily and learn from data, but they memorize patterns rather than learning abstract rules. This paper introduces a system that learns its own symbolic language automatically, then uses nudging with direction clues (gradient search) to refine programs at test time.

Zero assumption version

Two worlds, neither complete

Symbolic program induction (hand-written domain-specific languages, or DSLs) produces understandable, compositional code. You can write a simple function once and combine it with others to solve harder problems automatically. But scaling requires building a new language for every domain, which is painstaking and fragile.

Neural networks avoid this manual work. They learn patterns directly from data. But they memorize. A neural model trained on lists of length 1 to 5 will stumble on lists of length 6. A model trained on shifts of 1-5 steps fails on shifts of 10. This is not intelligent adaptation; it is memorization of the exact examples shown.

A beginner tries a neural network and expects it to learn the abstract concept of a shift or a composition, but it learns only the examples it saw.

The gap. Neural Language Interpreter learns a discrete symbolic vocabulary automatically, then uses gradient refinement to adapt programs to new problems.

The algorithm as a flow

What it actually does

Learn a vocabulary

During training, discover which primitive operations (like shift, reverse, compose) are useful.

Encode input-output pairs

Given examples of what the program should do, map them to a sequence of operation names.

Execute the program

A neural executor runs the sequence of operations, producing the output.

Test-time refinement

When answering a new question, refine the initial operation sequence via nudging steps to match the examples perfectly.

Generalize to longer problems

Because the program is a list of reusable operations, it naturally scales to problems longer than the training examples.

What the paper changes

What the paper changes

Traditional neural program synthesis maps input-output pairs directly to a program in a continuous space (imagine storing a program as a long list of real numbers, like 0.234, 0.891, 0.045, etc.). This paper changes the representation: instead, the program is a sequence of discrete operation names (like Shift, Reverse, Map, Compose), each one a distinct choice. Because each operation is a crisp, named choice rather than a blurry number, the programs are reusable and composable. You can combine Shift and Reverse knowing exactly what each does, not guessing from a list of numbers.

the object it moves  =  Program representation: from number lists to operation names
The hidden quantity

The discrete program space

measured quantity  =  Compositionality via discrete operation names

The hidden quantity is the discrete vocabulary of primitive operations that the model learns. Each operation is a distinct choice (shift-a-list, reverse-a-list, map-a-function, etc.). A program is simply a sequence of these choice names. This is hidden because it does not appear in typical neural program synthesis — most systems store a program as a long list of real numbers (learned via neural embedding, a technique that builds a list of numbers representing meaning), not as a list of named operations.

The paper estimates compositionality by measuring test accuracy on tasks that require combining operations in new ways (e.g., learning shift and reverse separately, then composing them at test time). If the model truly learns discrete, reusable operation names, it should compose them perfectly even when the combination is unseen.

Why it works

Why it works: three steps

The central insight is to make discrete programs learnable via nudging with direction clues. Normally, choosing an operation (shift vs. reverse) is a hard discrete decision — you either pick one or the other. Backpropagation (the standard learning technique) sends feedback signals through math operations, but cannot backprop through a hard choice (pick operation 3 vs. pick operation 7). The paper solves this with a smoothing trick: during training, instead of picking one operation, the model assigns soft probabilities to all operations. The feedback signals flow through these soft probabilities. This makes discrete choices trainable because they are now soft and smooth during training, even though they are discrete after sampling.

Second, the encoder (program inductor) proposes an initial program by watching input-output pairs. It infers which operations are needed. This is fast — one forward pass. But it may be wrong, especially for new problems.

Third, at test time (when answering a new question), the initial guess is refined via nudging steps. The model computes how much the output differs from the correct answer, then nudges the operation probabilities slightly in the direction that reduces the error. This nudging-via-feedback search gives the model a way to adapt to new, unseen problems without retraining. A model trained on lists up to length 5 can solve a length-10 list by nudging the program via these feedback steps, because the operation sequence is compositional and applies to any length.

The training objective

First in words:

loss equals reconstruction error plus lambda times reuse penalty, averaged over leave-one-out splits of training pairs

Then the compact form:

L(ϕ, θ; S) = (1/B) Σ_b [ (1/m) Σ_i Lrecon(ϕ, θ; x, y, S) + λ_reg Lreg(ϕ; S) ]

Every symbol:

LTotal training loss (lower is better)
ϕEncoder (program inductor) parameters
θDecoder (neural executor) parameters
SA set of input-output examples
BNumber of training batches
mNumber of examples in one batch
LreconReconstruction loss: negative log probability of predicting y given x and the inferred program
LregRegularization loss: penalizes unused tokens, encourages reuse
λ_regStrength of the reuse penalty
A tiny worked example
Suppose a program should do Reverse(Shift(x)) and we have two examples: x=1 -> 5, x=2 -> 4.
Encoder proposes: token probabilities are Shift 80%, Reverse 70%, Map 20%, others low.
Gumbel-Softmax samples: Shift and Reverse are selected, giving program [Shift, Reverse].
Executor runs: Shift(1) = 2, then Reverse([2]) = 2. Predicted output: 2. True output: 5. Error: large.
Gradient descent nudges probabilities toward Reverse 95%, Shift 70%, others up or down.
Next sample: Reverse and Shift selected again. Executor now produces correct output 5. Error shrinks.
Lreg additionally penalizes the 15 other token types that were not used, biasing the model toward the compact [Shift, Reverse] program.

The two losses pull in opposite directions: reconstruction wants low error (use any operations), reuse wants few operations (simplicity). The strength setting (lambda) balances simplicity versus accuracy.

What can go wrong

What can go wrong

Vocabulary too large or too small. If the model learns 100 operation tokens, program search becomes exponentially harder (which token for position 1? times which for position 2?). If it learns 2 tokens, it cannot express diverse programs. The regularization loss Lreg steers toward reuse, but must be tuned.
Test-time refinement is slow. Refining a program via nudging steps when answering a new question is much slower than running a standard neural model once. For real-time applications, this overhead may be prohibitive.
Longer programs are less stable. A program that is 10 operations long is more prone to numerical errors and local optima during nudging than a short program. Composing operations magnifies small mistakes.
Discrete operations require true modularity. If operations entangle their behavior (e.g., reverse depends on the previous operation's state), compositionality breaks. The method assumes operations are cleanly separable, which holds for list operations but may fail for more complex domains.
What a runnable demo should prove

What a runnable demo should prove

Build a simple program induction system on list operations (shift, reverse, map, filter). Train on lists of length 1-5. Test on length-8 lists, and on unseen compositions (e.g., reverse-then-shift, learned separately during training). Measure success as the percentage of test tasks solved exactly.

Generalization score = (accuracy on longer lists) * (accuracy on new compositions) / 100

The key outcome: the NLI model should generalize to both longer lists and new operation combinations, while a standard neural baseline fails on both. The discrete operation names make composition transparent and reusable.
