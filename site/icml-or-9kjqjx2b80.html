Skill-Pro: Learning Reusable Skills from Experience via Non-Parametric PPO for LLM Agents

Skill-Pro turns successful past runs into reusable procedural skills, so an agent can stop re-deriving the same solution every time a similar task appears.

Paper explainersAll themesAgents & Tool Use

An agent wastes effort when it solves the same kind of task from scratch over and over. The missing piece is not always more model training. Often the missing piece is a reusable procedure: when this kind of situation appears, do these steps in this order and stop when this condition is met. Skill-Pro extracts those procedures from experience, verifies that they work, and stores only the ones that stay useful across later tasks.

Zero assumption version

Why agents keep repeating solved work

Many agent tasks recur in slightly different forms. The file names change, the numbers change, or the web page changes, but the underlying procedure is the same. A plain agent still reasons the whole path again from the beginning because it has no clean stored procedure it can trigger and execute.

That repeated re-derivation costs time and also introduces instability. A solution that worked yesterday may be missed today because the agent starts from a blank slate again. Skill-Pro tries to prevent that by converting past runs into explicit skills with start conditions, execution steps, and stop conditions.

The paper's move in one sentence. Extract procedural skills from experience, test whether they really transfer, and keep a compact skill set that can be reused on later tasks without changing model weights.

The algorithm as a flow

What it actually does

Step 1: Collect experience

Store solved task histories so that the system has raw material for building skills.

Step 2: Distill a procedure

Turn a run into a reusable skill with a start condition (activation), execution steps, and termination rules.

Step 3: Test reuse

Apply the candidate skill on related tasks because a skill is only useful if it transfers beyond the original episode.

Step 4: Score and gate

Keep skills that pass quality checks and remove weak ones so that the memory stays compact and dependable.

Step 5: Reuse during later tasks

Trigger a stored skill when its start condition matches the current task, so that repeated work is not solved from scratch again.

What the paper changes

What the paper changes

The paper changes what is stored after a task. Instead of keeping only raw experience, it stores executable procedures that can be fired again later.

the object it moves  =  agent memory contents
The hidden quantity

The hidden quantity: reuse precision

measured quantity  =  how often a stored skill activates in the right situation and then completes the right procedure

A skill library only helps if the right skill fires at the right time, because only then can the agent skip fresh reasoning without drifting into the wrong procedure. That is the hidden quantity here. A large library with poor triggering can make the agent worse because it applies the wrong stored procedure to the current task.

Skill-Pro tries to raise reuse precision by testing candidate skills, keeping only high-quality ones, and requiring clear start and stop conditions. The goal is not to store more history. The goal is to store the part of history that can be safely reused.

Why it works

Why it works

A past run contains more than a final answer. It contains a procedure. Skill-Pro isolates that procedure by separating when the skill should start, what steps it should carry out, and what condition should end it.

The verification stage matters because not every successful run deserves to become a skill. Some runs depend on one lucky detail. Some are too long. Some work only once. By scoring and gating candidates, the method keeps only procedures that remain useful when reused.

This gives the agent a second route to competence. It can still reason from scratch when it has to, but when a familiar pattern returns, it can call a tested skill and move faster because the procedure has already been distilled.

Math after the picture

A compact skill-value objective

First in words:

Keep a candidate skill when it activates in the right situations, completes the intended procedure, and improves later task success enough to justify storing it.

Then the compact form:

value(skill) = reuse_gain(skill) - alpha * misfire_rate(skill) - beta * storage_cost(skill)

Every symbol:

value(skill)the total score used to decide whether a candidate skill stays in memory
reuse_gain(skill)how much the skill improves later task performance when reused
misfire_rate(skill)how often the skill activates in the wrong situation or follows the wrong procedure
storage_cost(skill)the cost of keeping this skill in a compact library
alphaweight on wrong activations
betaweight on memory cost
A tiny worked example
A file-processing task appears several times with different folder names.
The first solved run is distilled into a skill: start when the task asks for bulk file cleanup, then scan, filter, and write a summary, and stop after the report is saved.
On later tasks, the skill succeeds four times and misfires once when the task only asks for a single file.
Its reuse gain is high, but the one wrong trigger lowers the score.
If that score still beats the storage cost, the skill stays in memory for later reuse.

The paper uses richer internal machinery, but this score captures the core tradeoff: a stored skill is useful only if reuse gain stays larger than wrong-trigger cost and memory cost.

What can go wrong

What can go wrong

A candidate skill is too specific. If the procedure depends on details unique to one old task, it will fail on later tasks because the start condition was written too narrowly.
The trigger is too broad. If a skill activates in situations that only look similar, the agent may skip needed reasoning because the wrong stored procedure fires too early.
The library grows without pruning. Too many weak skills make retrieval noisy because good procedures are mixed with low-value ones.
Done right. The approach works when each stored skill has a clear start rule, a short dependable procedure, and a clear stop rule, because then reuse is both faster and safer.
What a runnable demo should prove

What a runnable demo should prove

Build a small benchmark with repeated task families, such as file cleanup, report generation, and table filtering, where each family appears with several surface variations. Let one agent solve tasks from scratch every time. Let another agent extract skills from solved runs, verify them on related tasks, and reuse the ones that pass. Keep the library size fixed so that weak skills must be dropped.

The demo should show higher reuse rate and lower task time for the skill-based agent because familiar procedures no longer need to be rediscovered on every episode.

reuse_rate = reused_skill_tasks / eligible_tasks ; transfer_success = solved_neighbor_tasks / total_neighbor_tasks

The essential proof is that stored procedures beat repeated rediscovery, because the agent can trigger a tested skill when the same task pattern returns.
