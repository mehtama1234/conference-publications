Asymmetric Proximal Policy Optimization: mini-critics boost LLM reasoning

Instead of one expensive value estimator, train a small ensemble of lightweight critics on different data chunks and use their disagreement to tell you when to skip learning.

Paper explainersAll themesLLMs & Foundation Models

When you train a large language model to reason better using reinforcement learning, you need a way to tell the model which moves are paying off. Most recent methods skip the traditional value function (a critic that estimates future rewards) because it is slow and unreliable at this scale. AsyPPO brings back the critic, but makes it fast by splitting it into many tiny critics, each learning from a small, separate pile of examples. When the tiny critics disagree with each other, you know something strange is happening and should be careful.

Zero assumption version

Why standard critics fail for big language models

To train a language model to reason better, you give it problems and reward correct answers, because the model adjusts its weights in the direction suggested by the reward signal—a correct answer pulls weights toward 'right reasoning' and a wrong answer pulls away. But the model does not learn directly from rewards. Instead, you need a separate program (called a critic or value function) that predicts how good the current state is. The critic tells the policy learner which moves are worth taking. Unfortunately, training a full critic alongside a giant language model is slow and memory-hungry. Even worse, when reward signals are sparse (only a few right answers in a huge pile of attempts) or the reasoning chain is very long, the critic gives noisy guesses that mislead training.

A beginner might try to build a bigger, smarter critic to fix this. But that just uses more memory and time. The real problem is not size; it is that a single critic sees all the data in the same way and learns one biased guess.

The fix: Train many tiny critics on separate data chunks so they see different views, then use their disagreement to decide when learning is safe.

The algorithm as a flow

What it actually does

Split examples

Divide training responses into six separate piles, each no overlap.

Train tiny critics

Each critic learns to predict value from only its pile, starting from the same base model.

Measure disagreement

Collect six value predictions for each state; compute how far apart they are.

Mask redundant learning

Where all critics agree, the learning signal is weak; skip that state.

Safer exploration

Where critics split badly, turn down curiosity bonus to avoid stupid moves.

What the paper changes

What the paper changes

Instead of one large value estimator, the method builds an ensemble of six lightweight critics. Each critic is a small neural network (just a value head) trained on a disjoint slice of data. Because they start identical but see different examples, they diverge slightly and offer diverse value predictions. The key is the data partitioning: responses are split uniformly so no two critics see the same response for the same prompt.

The hidden quantity

Critic disagreement: the hidden quantity

measured quantity  =  inter-critic uncertainty

Critic disagreement is how far apart the six value predictions are. When all six critics estimate a state to be worth 50 points, there is no disagreement. When three say 40 and three say 60, disagreement is high. This disagreement reveals something important: either the state is genuinely ambiguous (a new kind of problem the model has never seen), or one of the critics is unreliable. High disagreement means low confidence.

The paper estimates disagreement by computing the variance (spread) of the six value predictions. A small variance means confident prediction; high variance means the critics are not sure. Disagreement acts as a signal of when the learning algorithm should be careful.

Why it works

Why splitting critics and using disagreement works

A single large critic sees everything, so it learns one answer to every question. That answer tends to be biased toward common cases, missing rare but important ones. More importantly, a single critic can be confidently wrong. When multiple critics each see different slices of data, they independently learn slightly different lessons. A critic trained only on easy examples will overestimate value; one trained on hard examples will underestimate. Disagreement reveals this split in perspective.

The mechanism has two parts. First, where critics agree (low disagreement), the learning signal is weak and redundant; the algorithm skips those states to save compute. Second, where critics disagree (high disagreement), the algorithm turns down the curiosity bonus. The curiosity bonus is an extra reward that encourages exploration. But in high-disagreement states, the model is uncertain and exploring randomly is wasteful. By being cautious where critics split, the algorithm avoids learning bad patterns from states it does not understand.

Using disjoint data is critical. If all critics saw the same examples, they would learn the same thing and disagreement would be zero. By partitioning responses uniformly (critic A sees responses 1,7,13,...; critic B sees 2,8,14,...; etc.), each critic builds its own view. The shared pre-trained weights give all critics a head start, so they learn efficiently. Lightweight architecture keeps memory and time comparable to methods that skip critics altogether.

The uncertainty-aware objective

First in words:

Variance of critic ensemble masks advantages where critics agree and filters entropy regularization where critics diverge

Then the compact form:

L = min(r_t * A_t, clip(r_t, 1-epsilon, 1+epsilon) * A_t) * mask(var) - beta * H(pi) * filter(var)

Every symbol:

r_tprobability ratio (new policy divided by old policy at step t)

mask(var)zero out advantage in low-variance states, one elsewhere
H(pi)entropy (curiosity bonus encouraging exploration)
betahow strongly to apply curiosity
filter(var)reduce entropy weight in high-variance states

What can go wrong

What can go wrong

Data partitioning must be truly disjoint. If two critics see the same response, they learn identically and disagreement disappears. Uniform splitting (critic A gets indices 0,6,12...; B gets 1,7,13...) is essential.
Variance estimation can be noisy with few examples. If a state appears only once or twice in the batch, the six critic values might diverge by chance. A minimum batch size helps stabilize variance estimates because when the same state repeats across many examples, the critic values converge to their true pattern (how often each critic gives each answer), reducing false signals from noise.
Masking legitimate learning signals. In low-variance states, critics might agree on a wrong answer. The algorithm trusts agreement too much and skips correcting that error.
Done right: disjoint data, large enough batches, and measured tuning. Real training works because modern reasoning benchmarks have enough diversity that disjoint data actually splits the problem space usefully. The method is practical, not theoretical.
What a runnable demo should prove

What a runnable demo should prove

Build a small language model (or take a pre-trained one) and a simple reasoning task (like arithmetic or short proofs). Train a policy to solve it using PPO with one critic, then train another copy using AsyPPO with six mini-critics trained on disjoint data. Track training time, peak memory, and final accuracy. The demo should show: (1) AsyPPO trains faster because it skips redundant learning in low-variance states and uses less memory because each mini-critic is small, unlike one large critic, (2) mid-training performance is less noisy with mini-critics because variance across critics reveals true uncertainty rather than false confidence from a single biased guess, (3) final accuracy improves by a few percentage points because the algorithm avoids overfitting to ambiguous states and preserves reasoning in high-uncertainty regions.
