The Shape of Possible Decisions in Partially Observable Problems

This paper reveals that when you cannot see the full state of a system, the set of all achievable long-term rewards forms a curved geometric shape, not a flat polytope.

Paper explainersAll themesLearning Theory

In many real problems, you must make decisions without seeing everything — a robot navigating a foggy room, a doctor treating without complete test results. This paper reveals a deep geometric truth: the possible long-term reward values form not a flat many-sided shape but a curved, nonlinear surface. Understanding this shape helps us grasp why some decision strategies get stuck at local peaks while others climb higher, because on a curved surface, a decision that improves your reward today does not necessarily lead to better rewards tomorrow when you move deeper into a curved valley.

Zero assumption version

What we thought we knew, and what breaks

In decision-making problems where you can see the full state (like chess with all pieces visible), the set of all possible long-term reward values is a polytope — a flat, many-sided shape like a crystal or a die. This is well understood and useful: it tells you what outcomes are reachable.

But in the real world, you often cannot see everything. A robot does not see through walls; a doctor cannot order every test. These are called partially observable problems. Researchers assumed the set of possible rewards would be similar — maybe a bit messier, but still made of flat faces connected by straight edges. A naive approach would try to apply the polytope framework directly.

The problem. When you cannot see the full state, the shape of possible rewards is not a polytope — it curves and bends in nonlinear ways, creating isolated peaks where decisions can get trapped.

What the paper changes

The one thing the paper reveals

The paper characterizes (precisely describes and proves properties of) the feasible set of value functions in partially observable problems. A value function is a table or function that estimates the long-term reward you will accumulate from any state if you follow a good decision strategy. The feasible set is all possible value functions that can be achieved by following different memoryless decision strategies (strategies that depend only on the current observation, not on memory or history).

The hidden quantity: the geometric structure

measured quantity  =  the feasible set of value functions

The hidden quantity this paper measures is the geometric shape formed by all possible long-term reward values achievable in a partially observable problem. In simpler fully observable problems, this shape is a polytope — think of a crystal with flat faces and sharp corners. All points on the surface are connected by flat edges.

This paper reveals that in partially observable problems, this shape is a semi-algebraic set. That means it is carved out by polynomial inequalities — curves and surfaces, not just flat planes. The paper estimates and characterizes this geometric structure by analyzing the polynomial constraints that come from the problem's hidden states, observations, and rewards.

Why it works

Why the shape changes: the hidden states create curves

In a fully observable problem, every constraint is linear because you can observe everything. The reward at any point depends on what you chose, and all relationships are proportional. This creates flat, linear constraints and a polytope.

But in a partially observable problem, there are hidden states you cannot see. A decision strategy must work not just for one observed situation but for all possible hidden states behind that observation. To specify a good value function, you must satisfy constraints for each hidden state independently. When you try to enforce multiple constraints across different hidden states, they interact through polynomial equations (products of variables, not just sums). These polynomial interactions create curves and bumps.

The mechanism is straightforward: hidden states force you to satisfy multiple constraints simultaneously, and these constraints depend nonlinearly on the value function. That nonlinearity creates a curved, semi-algebraic feasible set instead of a flat polytope. The curvature creates isolated peaks and valleys — local decision strategies that look optimal locally but are not global peaks, a phenomenon that does not exist in fully observable problems where everything is linear.

Math after the picture

The equation: describing the feasible set

First in words:

The feasible set is defined by polynomial inequalities: for each observation and initial state distribution, there are polynomial constraints on the value function involving the transition probabilities, rewards, and discount factor

Then the compact form:

V is feasible if: V(o) >= sum_s P(s|o) * [R(s) + gamma * sum_o' P(o'|s) * V(o')] for all observations o and hidden states s

Every symbol:

V(o)value function: the estimated long-term reward from observation o
P(s|o)probability of hidden state s given observation o
R(s)immediate reward from hidden state s
gammadiscount factor: how much you care about future rewards (0 to 1)
P(o'|s)probability of next observation given state s
sumadd up over all states or observations
A tiny worked example
Suppose observation o could come from two hidden states: s1 (prob 0.6) or s2 (prob 0.4).
Reward from s1 is 10, from s2 is 5.
Next observations: from s1 you see o1 (prob 0.7) or o2 (prob 0.3); from s2 you always see o2.
Assume V(o1) = 20, V(o2) = 15, gamma = 0.9.
Constraint from s1: V(o) >= 10 + 0.9 * (0.7 * 20 + 0.3 * 15) = 10 + 0.9 * 18.5 = 10 + 16.65 = 26.65.
Constraint from s2: V(o) >= 5 + 0.9 * (1.0 * 15) = 5 + 13.5 = 18.5.
Combined: V(o) must satisfy both, so V(o) >= max(26.65, 18.5) = 26.65.
This is one polynomial constraint among many; the full set of all such constraints defines the feasible set.

The nonlinearity arises because the feasible set must satisfy many such constraints at once, coupling the value functions across observations through the hidden state transitions.

What can go wrong

What can go wrong

Assuming linear constraints. If you treat a partially observable problem as if constraints were linear (like in fully observable problems), you will miss the curved structure and incorrectly predict which policies are optimal.
Ignoring local peaks. A greedy decision strategy that improves reward at each step can get stuck at an isolated local peak — a situation that does not occur in fully observable problems — because the curved shape creates valleys where every possible next move either stays at the peak or moves downward, so the strategy has no downhill signal (gradient) to follow toward a better distant peak. You must search harder to escape.
Forgetting the initial state matters. In partially observable problems, the initial belief about the hidden state shapes which parts of the feasible set you can reach. Different starting beliefs reach different peaks.
Done right. Recognizing the curved structure, you can analyze the feasible set mathematically to find all reachable peaks and design policies that avoid local traps.
What a runnable demo should prove

What a runnable demo should prove

A demo should show that in a simple partially observable problem (e.g., a two-state hidden system with two observations, four possible transitions), the feasible set of value functions is indeed curved, not linear. Specifically: (1) Enumerate all memoryless policies (a small finite set). (2) For each policy, compute the value function (the long-term reward). (3) Plot these value functions as points in 2D or 3D space. (4) Show that the convex hull of these points (if they were from a polytope) is much larger than the actual feasible set, confirming that the true boundary is curved inward.

curvature_measure = area_of_convex_hull - area_of_feasible_set

If the curved feasible set is much smaller than the convex hull of sampled points, the demo proves partial observability creates nonlinear, concave structure.
