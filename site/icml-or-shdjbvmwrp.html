PRISM: Perception Reasoning Interleaved for Sequential Decision Making

When a vision system and a reasoning system ignore each other, embodied agents miss critical details — PRISM fixes this by making them talk to each other mid-task.

Paper explainersAll themesAgents & Tool Use

Large language models can read and reason, but they cannot see; vision models can see but often miss what matters for a task. When you throw both at a navigation or manipulation task, each works alone. PRISM breaks that apart by making the reasoning system ask the vision system targeted questions about what it sees, forcing real dialogue instead of silent handoffs.

Zero assumption version

Embodied agents fail when vision and reasoning don't align

A robot or virtual agent needs to navigate a room or pick an object. Today's approach: send the image to a vision model (a model that identifies what's in pictures), get back a description like 'red cup on table', feed that description to a reasoning model (a large language model that reads text and decides what to do), and the reasoning model says 'go left' or 'grasp handle'. The problem: the vision model writes what it sees, not what matters for the task. It might describe every object equally — 'wall, floor, cup, table' — when really the reasoning model only cares about the cup's exact position and what's blocking the way. The reasoning model reads passively and trusts what it gets.

A beginner might naively hope: 'Just send better descriptions.' But that doesn't work because the vision model has no way to know which details the reasoning model will need. The reasoning model can't ask follow-up questions — it just gets one dump of text and has to make a decision. So both systems work, but they miss each other's constraints.

The core problem. Vision and reasoning operate separately; neither knows what the other needs, so critical task-relevant details are lost.

The algorithm as a flow

What it actually does

Step 1: Reasoning model sees the image

The image arrives; reasoning model reads it but realizes something is missing.

Step 2: Reasoning model formulates goal-oriented questions

Based on the task, it generates questions: 'Where is the target object?' 'Is the path clear?'

Step 3: Vision model answers each question

Vision model extracts specific details from the image and returns crisp answers.

Step 4: Reasoning model critiques and synthesizes

It checks if answers align, asks follow-ups if needed, and builds a compact task-focused summary.

Step 5: Decision emerges from shared understanding

With aligned perception and reasoning, the agent confidently picks the next action.

What the paper changes

The paper changes how perception and reasoning connect

Instead of a one-way handoff where vision describes and reasoning reads, PRISM introduces bidirectional questioning. The reasoning system now critiques the vision system's output, probes it with specific goal-oriented questions, and iteratively refines the description until it is sharp and task-focused.

The hidden quantity

Task relevance: what details matter for the current goal

measured quantity  =  Task-relevant detail loss

A task-relevant detail is any fact the reasoning model needs to make a correct decision. Examples: the cup's exact location, whether a door is open, how much space is between obstacles. The vision model can see all of these, but without guidance it may bury them in a uniform description. PRISM measures task relevance by tracking which vision-model details the reasoning model actually asks about, and which ones it ignores.

The paper estimates task relevance through the questions the reasoning model generates. High-relevance details are those the reasoning model probes for; low-relevance ones are skipped. By counting which questions are asked (and thus which gaps get closed), PRISM quantifies how much detail loss the old system was suffering from.

Why it works

Why closed-loop dialogue extracts critical details

The old system fails because vision and reasoning work in isolation. The vision model generates a description without knowing what the reasoning model will do with it. The reasoning model reads passively, unable to ask 'wait, I need the distance to that object' or 'is the path clear to the left?' Both systems are myopic.

PRISM reverses this by making reasoning an active interrogator. The reasoning model looks at the image (or rather, looks at the vision model's initial summary) and thinks: 'to reach the cup, I need to know its location and what's blocking the way.' It then asks the vision model specific questions: 'Where is the cup?' 'What obstacles are between me and the cup?' The vision model answers each question by re-examining the image with that query in mind. Critically, the vision model now has a specific context — it is not describing the whole room, it is answering 'where is the cup?' — so it extracts precise spatial details rather than generic object lists.

This cycle repeats: the reasoning model gets an answer, checks if it is consistent with other answers, and if it spots a gap, asks a follow-up. By the time the cycle closes, the reasoning model has a compact, task-driven understanding of the scene. Because the questions are tied to the actual goal (not guesses about what might matter), the details the vision model extracts are almost always exactly what the reasoning model needs to act confidently.

Measuring task-relevant detail extraction

First in words:

Total detail coverage = (number of task-relevant questions asked) divided by (total possible task-relevant details), minus (number of unanswered questions)

Then the compact form:

coverage = (Q_answered / Q_total) - (penalties for unanswered)

Every symbol:

Q_answerednumber of task-relevant questions the reasoning model asked and the vision model answered
Q_totaltotal number of questions the reasoning model needs to answer to act safely
penaltieslost score for any critical question the reasoning model did not think to ask
A tiny worked example
Task: navigate to the cup. Critical questions: location, obstacles, clearance.
Reasoning model thinks to ask about location (1 point) and obstacles (1 point), but forgets clearance.
Vision answers both asked questions with high confidence.
Old system without dialogue: coverage = 2 asked out of 3 needed = 67%.
PRISM system: reasoning model sees the first two answers and realizes it forgot one, asks follow-up about clearance (3 asked out of 3 needed = 100%).
The penalty term captures this: PRISM recovers the missing detail because the reasoning model can iterate.

The equation captures how many critical details the reasoning model manages to extract via dialogue compared to how many it actually needs.

What can go wrong

What can go wrong

Reasoning model asks irrelevant questions. If the reasoning model is poorly trained or doesn't understand the task, it may ask questions that don't help ('what color is the wall?') instead of ('where is the target object?'). The vision model will answer accurately, but the questions were wasteful because they don't inform the decision the reasoning model needs to make — knowing wall color doesn't help the agent navigate, but knowing target location does. This breaks the core assumption that questions are task-driven.
Vision model cannot answer a question. Some details may be genuinely invisible from the camera angle or obscured by shadows. If the reasoning model asks 'what is behind the door?', the vision model cannot answer because the door blocks the view. Cycles may loop endlessly if the reasoning model keeps asking unanswerable questions.
Questions pile up without convergence. If the reasoning model is not disciplined, it may ask 100 questions, and the dialogue never settles into a compact description. The system slows down and the agent's decision is delayed.
Done right: reasoning model asks few, high-value questions. The reasoning model asks only questions that matter for the decision, the vision model answers them crisply, and the cycle converges quickly into a sharp task-driven description.
What a runnable demo should prove

What a runnable demo should prove

Build a simulation where an agent must navigate to a target object in a cluttered room. Implement two versions: (1) passive baseline where vision describes the room once, then reasoning acts based on that single description; (2) PRISM where reasoning generates questions ('where is the target?', 'what blocks my direct path?'), vision answers each, and reasoning makes the decision. Measure task success (did the agent reach the target?) and detail coverage (how many critical spatial details did the reasoning model extract?).

task_success = (episodes_agent_reached_target) / (total_episodes); detail_coverage = (critical_questions_answered) / (critical_questions_asked)

The demo makes impossible to miss: with interactive dialogue, the reasoning model asks fewer but higher-value questions, gets crisp spatial answers, and navigates successfully; without dialogue, the reasoning model guesses blindly and fails.
