Transporting Task Vectors across Different Architectures without Training

Theseus moves a task update from one model width to another by matching what the update does to internal activations, so the target model can reuse the task without a new fine-tuning run.

Paper explainersAll themesOther

A fine-tuned model differs from its base model by a task update. If two models share the same architecture, that update can often be reused directly. Across different widths, direct reuse breaks because the weight-array shapes no longer match. This paper argues that the right object to move is not the raw weight difference but the effect that difference has on internal activations (the intermediate values produced inside the model). Theseus first aligns the source and target activation spaces with an orthogonal map, then solves for a target-side update whose functional effect matches the source update as closely as possible.

Zero assumption version

Why task updates stop traveling when model width changes

Suppose one model has already been adapted to a downstream task and you want another related model to inherit that adaptation. If both models have the same width, the weight update can often be copied or merged with minor processing. When widths differ, raw weight copying fails because the coordinate systems have different sizes and different internal organization.

The paper asks a more stable question: what did the source update make the model do? If that effect on intermediate activations can be described and matched, then a target update may be recovered without training the target on the task again.

The key shift. Do not transport the raw weight change. Transport the change in model behavior on internal activations, because that object can be matched across different widths.

The algorithm as a flow

What it actually does

Collect activation pairs.

Run inputs through the source and target base models so the method can observe the intermediate activations that need to be aligned.

Measure the source task effect.

Compute how the source task update changes those source activations, because that change is the object to be transported.

Align source and target spaces.

Find an orthogonal rotation between activation spaces so the comparison preserves relative distances and directions while handling different widths.

Solve for a target update.

Choose the target update that best reproduces the aligned source-side activation change on the observed inputs.

Apply the transported update.

Use that closed-form target update in the new model without extra task training or repeated step-by-step weight updates.

What the paper changes

The hidden quantity

The hidden quantity

measured quantity  =  the task-specific change in intermediate activations

The hidden quantity is the source update's effect on internal activations. That effect says which directions in the model's intermediate computation are pushed up or down by the task update. It is more transferable than raw weights because many weight settings can produce similar activation changes.

The alignment step estimates how source and target activation spaces correspond. Once that relation is known, the target model can imitate the source task effect even though the two models use different widths.

Why it works

Why functional transport can work across widths

Weight coordinates are brittle across architecture changes. A useful direction in one model's weight space does not have a clean one-to-one counterpart in another width. Intermediate activations are more comparable because they describe how the model represents inputs during computation.

The orthogonal alignment matters because it rotates one activation space into the other without distorting relative structure. That preserves the relative distances and directions of the task effect. The closed-form recovery step then works because once the two spaces are aligned, the target update can be chosen to reproduce the same activation change on the observed inputs.

Math after the picture

Match the aligned activation change

First in words:

Choose a target update whose induced change on target activations is as close as possible to the source activation change after alignment.

Then the compact form:

Delta_t^* = argmin_Delta_t || Phi_t(Delta_t) - Q Phi_s(Delta_s) ||^2

Every symbol:

Delta_sthe source model's task update
Delta_ta candidate task update for the target model
Phi_s(Delta_s)the source update's effect on observed source activations
Phi_t(Delta_t)the target update's effect on observed target activations
Qthe orthogonal alignment that rotates source activations into the target space
Delta_t^*the target update that best matches the aligned source effect
A tiny worked example
Suppose the source update moves two observed activation directions by amounts 3 and 1.
After alignment, those target-space moves should be 2.8 and 1.2.
One candidate target update produces 2.0 and 0.9, so the mismatch is still large.
Another candidate produces 2.7 and 1.1, so the mismatch is much smaller.
The method picks the second update because it reproduces the aligned source task effect more closely.

The exact operators in the paper depend on the observed layers and data, but the core objective is simply to match the source update's aligned activation effect.

What can go wrong

What can go wrong

The observed inputs may not cover the task well. If the activation samples miss important task situations, the recovered update can match the wrong functional effect because the transport target was measured on incomplete evidence.
The source and target models may represent the task too differently. If the two widths organize their internal computation in very different ways, one orthogonal alignment may be too simple because no single rotation can line up all relevant task directions.
Transport can preserve a weak source update. If the original task update is itself poor, the method will faithfully reproduce that weakness because it is designed to preserve behavior, not to improve it.
Done right. The method works when the source task effect is clear and the activation spaces are comparable, because then an aligned functional target is easier to recover than a raw weight mapping.
What a runnable demo should prove

What a runnable demo should prove

Take a small source model and target model with different widths but the same general architecture. Fine-tune only the source on one downstream task. Then compare three transfer routes on the target: no transfer, naive weight-based reuse, and activation-based transport. Measure target task quality without additional training.

The demo should show that activation-based transport keeps much more of the task because it recreates the source update's internal effect instead of failing on raw shape mismatch.

transport_gain = task_score(Theseus_target) - task_score(best_naive_transfer)

The decisive evidence is good target performance without extra training, because that shows the task update was carried over as behavior rather than as a fragile raw-weight pattern.
