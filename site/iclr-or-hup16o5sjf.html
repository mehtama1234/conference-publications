WebSailor-V2: Training Open-Source Web Agents

WebSailor-V2 trains open-source web agents to match proprietary systems by combining a graph-built dataset and a two-environment reinforcement learning setup that learns from both fast simulation and real-world trials.

Paper explainersAll themesAgents & Tool Use

Open-source web agents that can navigate websites and answer questions have fallen far behind proprietary systems. WebSailor-V2 closes this gap using two ideas: first, a new dataset built from a knowledge graph that includes tricky, nuanced questions instead of just obvious ones; second, a training setup that uses both a fast simulator and the real web to teach the agent which actions lead to correct answers. Trained on a 30-billion-parameter model (30 billion individual numbers being adjusted during training), the agent reaches performance matching or exceeding much larger proprietary systems.

Zero assumption version

Open-source web agents lag behind proprietary ones

A web agent is a system that reads a website's content, decides what to click or type, and repeats until it answers a question correctly. Today's open-source agents answer only about 20-30% of real-world web questions right; proprietary systems from large companies answer 50-70% correctly.

A beginner's first idea is to gather a dataset of web screenshots and correct answers, then train the agent to predict the right click. But real web tasks involve ambiguous situations: a page might have five similar buttons, each leading somewhere different. The agent must learn to reason about context, read fine print, and plan ahead across multiple steps. Simple supervised training from examples does not capture this reasoning.

The core challenge. Open-source agents need to learn reasoning for ambiguous web tasks, but existing datasets and training methods treat each click as an isolated decision.

The algorithm as a flow

What it actually does

Build a reasoning dataset

Create tricky questions from a knowledge graph: multi-step queries, ambiguous pages, missing info that forces reasoning.

Supervised pre-training

Show the agent thousands of (web page, action, outcome) examples. Agent learns to recognize context and predict reasonable actions.

Run fast simulator

Simulate 100s of attempted sequences quickly. Track which action choices lead to correct answers.

Reinforce with real web

Take the agent's best actions and test on real websites. Measure true success rate. Send reward signal (adjusting what the agent learns) only for honest outcomes.

Feedback loop

Simulator learns from real results; real experiments use simulator-trained policies. This cycle improves both because simulator gets better at predicting reality, and the agent's strategies are validated on honest ground truth.

What the paper changes

What the paper changes: the agent's decision-making process

The paper changes how the agent picks an action at each step. Before: the agent saw a webpage and output a single click, guided only by memorized patterns from examples. After: the agent reasons using reward—a number telling it whether each action led to success or failure. Over thousands of trials, it adjusts its internal reasoning to maximize total reward across the full multi-step task.

the object it moves  =  decision-making: from pattern-matching to reward-guided reasoning
The hidden quantity

The hidden quantity: task-completion reward

measured quantity  =  total reward across a task sequence

Open-source agents do not naturally learn to reason about consequences. They see actions and outcomes separately. WebSailor-V2 introduces an explicit reward signal: +1 for a correct answer, 0 or negative for wrong paths. This is the key measurement that the agent is trying to maximize.

The paper estimates this reward in two places: the simulator gives immediate feedback (wrong button was clicked, wrong page loaded, answer was incorrect) at low cost; the real web gives honest-to-God ground truth. By training the agent to maximize reward in the simulator and validating on real websites, the agent learns to transfer its learned strategy from cheap trials to real situations.

Why it works

Why it works: learning from full-task outcomes, not isolated examples

WebSailor-V2 trains the agent to reason about entire web-browsing sequences as units, not individual clicks in isolation, because this approach gives stronger learning signals. When supervised training shows the agent one example of (page, click), it memorizes a pattern. But when reinforcement learning says 'you tried 10 different action sequences, and only the ones that included clicking the blue button led to correct answers', the agent infers the hidden rule: 'in this context, blue means right.' This works because the agent sees a pattern across many trials: blue button correlates with success in 8 out of 10 sequences, which is unmistakable signal; seeing it once in one example is just noise. Multiple trials make the causal link obvious, while a single example is noise that can be ignored.

The dual-environment trick amplifies this. The simulator is so fast that the agent can try many variations and see which work. But simulators are imperfect: they might miss edge cases or behave slightly differently from the real web. So the paper also runs real experiments, which are slow and expensive but ground-truth. This hybrid approach gives the agent reliable reward signals without the cost of learning only from real trials, because the simulator handles the expensive explore-and-fail iterations, while real tests validate only the most promising strategies.

The reinforcement learning objective

First in words:

Maximize the expected sum of rewards over a task sequence. In the simulator, run many trials quickly. In the real web, keep only the top-scoring sequences and run them for true validation.

Then the compact form:

maximize E[ sum_t r_t ] where r_t = 1 if final_answer_correct else 0

Every symbol:

r_treward at step t (1 if correct, 0 if wrong)
sum_t r_ttotal reward from start of task to completion
E[...]expected value across many random trials
maximizeadjust agent reasoning to increase this total
A tiny worked example
Trial 1: agent clicks [Search, Results, Answer]. Final answer correct. r = 1. Total reward = 1.
Trial 2: agent clicks [Menu, Wrong page, Back]. Final answer wrong. r = 0. Total reward = 0.
Trial 3: agent clicks [Search, Results, Answer]. Final answer correct. r = 1. Total reward = 1.
After seeing these outcomes, agent's reasoning adjusts: search-then-results-then-answer is a winning pattern (average reward 2/3). Menu-based paths lose. Agent learns to repeat winning patterns more often.

The agent is not penalized for each wrong click; only the final answer counts. This teaches it to reason about full-task success, not isolated actions.

What can go wrong

What can go wrong

Simulator misalignment. If the simulator behaves very differently from real websites (e.g., layouts differ, buttons render differently), the agent learns the wrong patterns in fast trials and fails on real pages. Solution: build the simulator to match real sites closely.
Reward signal is too sparse. If the agent only learns whether the final answer is right or wrong, it has no gradient during long sequences (many steps with zero reward). Solution: the paper includes intermediate rewards or shaping—small bonus for reaching new pages, discovering new information, etc.
Overfitting to simulator. The agent might learn spurious patterns that work in the simulator (e.g., clicking at pixel position 100,100) but fail in the real web where layouts vary. Solution: the real-world validation step catches this and corrects it.
Done right. Pair fast iteration with honest validation. Let the agent learn from both success and failure. Gradually increase real-world trials as simulator quality improves, because a better simulator means the agent's learned strategies will transfer more reliably. This is what WebSailor-V2 does.
What a runnable demo should prove

What a runnable demo should prove

Build a toy web-navigation task: a small website with a knowledge graph (e.g., 20 topics linked by clickable relationships), 5 multi-step questions (e.g., 'find the third-degree neighbor of topic X'), and a simple reward signal (+1 if final answer correct). Implement two agents: one trained only on supervised examples, one trained with dual-environment RL. Run 100 test questions. Measure success rate on unseen questions, especially ambiguous ones (pages that could lead two ways).

improvement = (RL_success_rate - supervised_success_rate) / supervised_success_rate

The RL agent should succeed on 2-3x more ambiguous questions than the supervised agent, because it learned to reason about context and consequences, not just memorize clicks.
