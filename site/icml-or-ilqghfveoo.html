QuITE: Query-Based Irregular Time Series Embedding

Use learnable question tokens to read scattered timesteps into a continuous signal instead of forcing them onto a fake grid.

Paper explainersAll themesTime Series & Sequential

Real-world sensors do not report at regular intervals. A patient's heart rate is recorded when measured, not at fixed times; power grids report demand when it spikes. Existing models for this kind of data either require building a completely new model from scratch or resort to filling in the blanks with made-up numbers, both of which distort what actually happened. QuITE solves this by teaching a small set of learnable questions to directly listen to each irregular observation, producing a clean signal the standard models can then read.

Zero assumption version

Irregular data breaks regular tools

Time series models read sequences of numbers: stock prices every minute, temperature every hour, acceleration every millisecond. They assume the measurements come at perfectly spaced times. The model builds on this regularity: first position, second position, third position. When real data breaks this rule—missing readings, sensor failures, events that only fire when something worth measuring happens—the standard approach is to interpolate: make up values between the gaps to create a fake regular grid. But this distorts the true signal. A model trained on made-up values learns to trust the wrong patterns.

A beginner tries either (i) forcing a specialized architecture that handles the gaps, throwing away all the proven model designs, or (ii) interpolating and hoping the artificial smoothness does not confuse learning.

The core problem. The conversion layer that transforms raw readings into learnable form assumes uniformly spaced time; irregular data gets either specialized models (wasting proven designs) or fake-filled grids (distorting the signal).

What it actually does

No alignment to a grid; each reading has its own real time.

Learn query questions

A handful of trainable lists of numbers (the queries) that represent questions about the signal.

Query each observation

Listening computes how well each query relates to each irregular reading.

High-weight readings contribute more; low-weight readings contribute less to each query's answer.

What the paper changes

What the paper changes

QuITE replaces the conversion layer that transforms raw measurements into learnable form. Instead of assuming a grid and interpolating, it uses learnable questions and listening-based aggregation to directly combine irregular observations into a signal shape that standard models expect.

the object it moves  =  conversion layer
The hidden quantity

The hidden quantity: listening weight

measured quantity  =  listening weight (how much each reading matters)

The conversion module computes a number between 0 and 1 for each irregular observation, reflecting how much that reading contributes to each query's answer. A reading about a sudden stock price drop might get high weight on a volatility query but low weight on a level query. This weight is hidden—not in the output, but driving which readings are heard and which are ignored.

The paper learns the query questions end-to-end so these weights naturally focus on observations that matter for the downstream task.

Why it works

Why it works: directly encoding position and value together

The core insight is that irregular observations carry two pieces of information at once: when they happened and what they measured. A standard conversion layer assumes a fixed grid where position is determined by slot. An irregular conversion layer must combine position and value in a single pass. The paper's mechanism works because the listening layer (attention) natively aligns observations across different timescales. When a query asks 'which readings are important?', the listening mechanism simultaneously considers both the timestamp and the measurement value. A late, large spike might get high weight because both its timing and magnitude matter. The queries are learnable—training adjusts them to ask the right questions for the task (forecasting or classification), so the aggregation naturally highlights relevant patterns without artificial gaps.

This is better than interpolation because no fake values are introduced, and better than specialized architectures because any standard model that reads a regular sequence can consume the output unchanged.

The listening equation

First in words:

For each query vector, compute the similarity to each observation, normalize to fractions, and take a weighted sum of observation values.

Then the compact form:

output_i = sum_j ( exp(q_i · o_j / sqrt(d)) / sum_k exp(q_i · o_k / sqrt(d)) ) * v_j

Every symbol:

q_ithe i-th learnable query vector (a list of numbers)
o_jthe j-th observation encoding (timestamp + measurement)
v_jthe value of the j-th observation
dthe size of the vectors (scales the similarity so learning stays stable)
·dot product (multiply paired numbers, sum the results)
exp(...) / sum(...)normalize to fractions (turn raw scores into numbers that add to 1)
A tiny worked example with three irregular readings
Suppose we have 3 observations at times t=1,5,8 with values v=2,7,4.
Query token q_1 is [0.5, -0.3].
Observation encodings: o_1 = [1,2], o_2 = [5,7], o_3 = [8,4].
Dot products: q_1·o_1 = 0.5*1 + (-0.3)*2 = -0.1, q_1·o_2 = 0.5*5 + (-0.3)*7 = -0.6, q_1·o_3 = 0.5*8 + (-0.3)*4 = 2.8.
Scaled by sqrt(d)=sqrt(2)≈1.4: -0.07, -0.43, 2.0.
Exponentials: exp(-0.07)≈0.93, exp(-0.43)≈0.65, exp(2.0)≈7.4.
Sum: 0.93 + 0.65 + 7.4 = 8.98.
Softmax weights: 0.93/8.98≈0.10, 0.65/8.98≈0.07, 7.4/8.98≈0.82.
Output: 0.10*2 + 0.07*7 + 0.82*4 = 0.2 + 0.49 + 3.28 = 3.97.
The large late value (v_3=4) dominates because q_1 aligned well with its position and magnitude.

The query asks questions, attention listens to all irregular readings at once, and the weights naturally highlight observations the downstream task will find useful.

What can go wrong

What can go wrong

Query tokens too few. If the handful of learnable queries is smaller than the richness of patterns in the data, important signals will be missed. The method requires tuning the number of queries.
Extremely sparse data. If observations are so rare that a query never sees the same kind of event twice, attention weights become arbitrary. The backbone model then lacks patterns to learn.
Encoding position and value naively. If the encoding of timestamps and measurement values treats them as independent dimensions, a query may not learn to correlate timing with magnitude. The paper likely uses a learned position-encoding layer, but simple concatenation could fail.
Done right. Tune the number of queries to match data complexity, ensure observations are frequent enough for patterns to emerge, and use a careful position-value encoding (the paper's self-attention layer learns this naturally).
What a runnable demo should prove

What a runnable demo should prove

Build a toy irregular time series (e.g., sensor readings with random gaps), train a backbone model on a standard task (forecasting the next value or classifying the sequence). Implement three versions: (i) interpolation-to-grid baseline, (ii) a specialized architecture that handles gaps directly, and (iii) QuITE as a plug-and-play conversion layer on the same backbone. Report accuracy and proof that no values are fabricated—show the real irregularity is preserved in the query-listening output.

accuracy = (correct_predictions) / (total_predictions); also report: average_attention_entropy = how spread the weights are (narrow focus vs. diffuse listening); and interpolation_never_used = true.

QuITE should match or exceed the specialized architecture while keeping the backbone unchanged and the signal pristine.
