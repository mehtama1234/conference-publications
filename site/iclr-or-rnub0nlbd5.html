JanusVLN: Decoupling Semantics and Spatiality with Dual Implicit Memory

A robot learns where it is and what it sees by storing two separate compact memory streams instead of one bloated archive.

Paper explainersAll themesRobotics & Control

When a robot navigates a building following verbal directions, it must remember both where it has been (position, angles, hallway layouts) and what things look like (visual meaning). Traditional navigation methods stuff both into a single memory — old video frames stacked in a cache, text descriptions of rooms piled up. But this hybrid memory is wasteful and loses fine details of position and angles. JanusVLN instead learns two tiny, separate neural memory streams: one for spatial reasoning (position, angles, room layout), and one for semantic understanding (what a staircase looks like). By keeping only the essential summary of past moments rather than full archived frames, the system navigates unseen buildings more efficiently and much more accurately.

Zero assumption version

The robot loses its way when memory gets too heavy

Imagine a robot walking through an unfamiliar office building. A human voice tells it: Go forward through the open door, then turn left at the blue sign. As it moves, the robot must remember what it has seen (the open door, the blue sign) and track where it is in the building (three meters north, then two meters west). Humans manage this effortlessly: your brain's left hemisphere handles words and things (semantics), while your right hemisphere tracks position and layout (spatial). But robots traditionally dump everything into one memory bin.

A robot trained the old way stores every video frame it captures and every language instruction it receives into a single large cache. Over a long walk, this cache bloats with redundant information — ten nearly-identical images of a hallway, repeated phrases. The cache also loses fine geometric details: it remembers that there was a hallway, but not the exact angle where it bent. When the robot must decide where to turn next, it digs through this messy archive, wasting compute and missing spatial cues. The result: the robot gets confused in new buildings, performs poorly compared to human navigators, and uses far more processing power than necessary.

The core problem. One bulky memory archive loses both spatial precision and computational efficiency.

The algorithm as a flow

What it actually does

Split the senses

Incoming video and language feed into two separate neural encoders: one learns position and angles, one learns visual meaning.

Build memory compactly

Instead of storing raw frames and text, the system saves only the compressed summaries (key-value pairs) from each moment, because one key-value pair is far smaller than a full image and text string, so memory stays tiny.

Remember selectively

When deciding the next move, the robot keeps only the most recent key-value summaries (a sliding window) plus the very first moment for orientation, discarding stale observations.

Fuse at decision time

The position stream informs where to go, the semantic stream informs what to look for; a language model combines both to choose the next action.

Learn incrementally

As new moments arrive, the model updates its memories without recomputing the entire history, keeping computation lean.

What the paper changes

The single thing that changes

JanusVLN replaces the single large memory cache with two independent, tiny neural memory streams: one for position and angles, one for visual meaning. Each stream stores only essential summaries (learned compressed representations called key-value caches), not raw data. This split allows each stream to specialize — one learns to detect fine angle changes and distance markers (which would be lost if mixed with visual noise), the other learns to recognize doors and staircases (which does not need millimeter precision) — because when one stream focuses purely on position, subtle spatial cues are not drowned out.

The hidden quantity

Memory efficiency: how much you remember without storage bloat

measured quantity  =  Compression ratio: raw data divided by stored representation size

This paper measures how much a neural memory can compress long observation sequences into learned summaries without losing the ability to navigate accurately. The key-value cache is an efficient way to store compressed information: instead of saving every pixel of every video frame, you save only a small learned vector per moment (the key-value pair), capturing the essential semantic and spatial cues. The sliding window is the critical trick: you keep the first moment (for global orientation) and only recent moments (for immediate decisions), throwing away middle moments that are no longer useful.

Why does this work? Because navigation is fundamentally about local and global cues. Your immediate next step depends on the room you are in right now (local; recent key-values). Your overall sense of the building comes from knowing where you started (global; the initial key-values). The middle-aged observations are mostly noise. By keeping only those two, you drop memory size from thousands of frames to a handful of compressed summaries — a compression ratio of 50:1 or more. The paper shows this keeps position reasoning sharp (good angle and distance tracking) and semantic understanding clear (good word-following) while cutting memory bloat.

Why it works

Why splitting memory into two streams fixes the navigation problem

The core mechanism is specialization through separation. When position and visual semantics live in the same memory, they interfere: position reasoning gets drowned out by the abundance of visual detail (ten nearly-identical hallway frames look identical semantically, but have subtle angle and distance differences). By giving each a separate stream, the position encoder focuses purely on angle, distance, and layout (ignoring visual noise that hides spatial cues), while the semantic encoder focuses on object identity and language (not forced to also predict millimeter angles). Each stream's signals stay crisp. Moreover, the sliding-window key-value cache means the system never has to recompute the entire history when deciding the next action — it updates only the newest moment. This cuts computation time roughly in half or more, because fewer total computations mean less accumulated error. The net result: a robot that understands position accurately, interprets language clearly, and navigates new environments without getting lost.

The reason this works mechanically is that position and semantic reasoning operate on different scales. Position cares about millimeter-precision angles and distances; semantics cares about object categories (staircase, hallway, door) that look the same even with slight view changes. When you separate them, the position encoder uses fine-grained cues (pixel shifts, depth hints) that would vanish if blended into a shared memory with high-level semantic features. The semantic encoder can abstract over small visual variations because it is not forced to also predict precise angles. When the two streams are fused at decision time (e.g., where should the robot step next?), both pieces are sharp and ready to use.

Math after the picture

The sliding-window memory update equation

First in words:

On each new moment, update the memory by keeping only the first moment and the most recent N moments, then compute the next decision from their combined key-value summaries.

Then the compact form:

M_t = Concat(KV_init, KV_sliding), where KV_sliding = [KV_{t-N}, ..., KV_{t-1}, KV_t]

Every symbol:

M_tthe full memory at moment t (fused spatial and semantic streams)
KV_initthe key-value pair from the starting moment (global orientation)
KV_slidingthe key-value pairs from the last N moments (local context)
KV_ithe compressed learned representation of moment i (one key vector, one value vector)
Nthe window size (how many recent moments to keep; typically 4–8)
Concatstick the two lists end-to-end to form the full memory
A tiny worked example with three moments and window size 2
Moment 1 (start): spatial KV_1 = [pos, angle], semantic KV_1 = [staircase, up]
Moment 3 (now, t=3): spatial KV_3 = [pos+3m, angle+15deg], semantic KV_3 = [hallway, straight]
Moment 2 (one ago): spatial KV_2 = [pos+1m, angle+5deg], semantic KV_2 = [doorway, left]
Memory M_3 = [KV_1] + [KV_2, KV_3] (keep start, keep last 2 moments, discard nothing new)
The model sees the starting staircase and the last two steps (doorway then hallway), so it knows the route.
If N=1 (keep only last 1), M_3 = [KV_1, KV_3], the immediate hallway cue, but forget the doorway context; accuracy may drop.

The memory size stays constant (only N recent plus the initial moment), so computation does not grow with path length; this is what makes navigation efficient at long distances.

What can go wrong

What can go wrong

If the window size is too small. Keeping only the last 2 moments means the robot forgets the layout of the room it just left; it cannot plan multi-step turns. A window of 1 is essentially amnesic; a good window is typically 4–8 moments.
If spatial and semantic encoders are not properly trained. If the spatial encoder is left too weak, it will be overridden by the semantic stream at decision time; the robot will follow language instructions into geometrically impossible routes. Both encoders must be jointly trained so they learn to disagree constructively.
If the initial moment is dropped. Forgetting the starting point means the robot loses global orientation and wanders in circles when local cues are ambiguous; always keep the KV_init.
Done right. When both encoders are well-trained and the window size is tuned to the complexity of the environment (small for tight corridors, larger for sprawling buildings), the robot navigates unseen spaces with high success rates and minimal memory use.
What a runnable demo should prove

What a runnable demo should prove

Build a navigation simulator: a grid world with rooms, hallways, and obstacles. Seed it with 10 different building layouts. Train a navigation model using the dual-memory approach (spatial encoder + semantic encoder + sliding-window key-value cache) on 8 layouts. Then test on the 2 held-out layouts. At the same time, train a baseline model that uses a single shared memory with all frames stored. Measure success rate (did the robot reach the goal?) and memory usage per step.

Success rate = (times robot reaches goal) / (total trials); Memory per step = (size of stored KV cache in kilobytes) / (number of steps taken); Target: achieve >65% success on unseen layouts and use <20 KB per step.

The demo proves that splitting memory into position and semantic streams, combined with a sliding window, allows a robot to navigate unfamiliar buildings better (higher success) and faster (lower compute per step) than storing every frame in one archive, because each stream now stays sharp and memory stays small.
