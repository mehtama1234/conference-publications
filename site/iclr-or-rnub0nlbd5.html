JanusVLN: Dual Implicit Memory for Robot Navigation

A robot learns to navigate by storing two types of memory separately — what things look like and where they are in 3D space — instead of trying to remember everything at once.

Paper explainersAll themesRobotics & Control

When a robot walks through an unseen building following spoken directions, it must remember both what it has seen and where it came from. Existing methods store every past frame or create text maps, wasting computation. JanusVLN splits memory into two independent caches — one for visual appearance and one for how objects are positioned in 3D space — so the robot can revisit key moments without reprocessing old video.

Why robots get lost in unfamiliar places

A robot navigating a new building has to process what it sees (video frames) while listening to instructions like 'walk past the kitchen to the office'. Most recent methods store either textual summaries of what they saw or cached copies of every past frame.

The problem: storing full frames wastes memory and forces the robot to reprocess all past video at every step, like rereading an entire book every time you turn a page. Even worse, the robot only sees 2D color images (like a camera photo), so it cannot tell whether a wall is 1 meter away or 10 meters away — it loses the 3D sense of space.

In one sentence. Keep two separate, compact memories: one for what things look like, one for their 3D locations.

The algorithm as a flow

What it actually does

Process current frame through two encoders

3D spatial encoder and 2D visual encoder run on this frame's image.

Cache the encoder's internal state

Save the internal key-value pairs (summary data) from both encoders, stored as compact lists of numbers.

Anchor the oldest frames

Mark first and recent frames as focal points so the model keeps them as reference anchors, because these frames define the start and the current position — forgetting them breaks trajectory continuity.

Query old memory when planning

When the robot needs to make a move, ask 'what did I see or where was I then' by matching current observations against the cached memory.

Avoid redundant reprocessing

No need to re-run the old video through the encoders. The cached summary is enough.

What the paper changes

What the paper changes

Instead of storing raw video frames or text descriptions, JanusVLN caches the internal encoder memory (called key-value pairs) from two separate neural networks: one for how objects are positioned in 3D space and one for visual appearance. This cache is compact and fixed-size.

The hidden quantity

Attention sinks: which moments matter most

measured quantity  =  attention sink weight

Human navigation relies on landmarks. When you reach a hallway, you mentally mark where you started. The robot does this too: certain frames (the very first one and the recent ones) act as anchors. The model assigns high attention weight to these frames because they define the trajectory.

JanusVLN detects these anchors automatically by observing which historical frames the attention mechanism (a scoring function inside the neural network) naturally gravitates toward. Frames with sustained high scores become the implicit memory's keyframes. By caching only these frames' internal summaries, the robot avoids storing and reprocessing irrelevant intermediate views.

Why it works

Why splitting memory into two channels works

The core trick is separating the job: one encoder focuses on depth and where objects sit in 3D space (relative position), the other on 2D appearance (color, object identity). By caching their outputs separately, the robot gains two independent, compact views of the past.

When the robot needs to decide on the next move, it no longer reprocesses every old frame. Instead, it queries the cached summaries. This is much faster and prevents spatial information loss, because the 3D encoder's cache preserves depth cues that a pure 2D visual system would miss. The robot's language comprehension module (a large language model) receives both the current observation and the two types of cached history, so it can reason spatially and semantically at once.

The dual memory uses a sliding window trick: keep the last N frames' full cache (the recent window) plus the very first frame (the initial window, marked as an attention sink). This dual buffer is small and fixed-size, so it never bloats no matter how long the path.

The memory-efficient cache equation

First in words:

For each new frame, combine the spatial hidden state and semantic hidden state, weighted by learned factors, and store only the attention keys and values of keyframes.

Then the compact form:

M_implicit = cat(KV_spatial[t_0, t_recent] , KV_semantic[t_0, t_recent]) + MLP(fusion_weights)

Every symbol:

M_implicitthe stored dual memory (geometry and appearance combined)
KV_spatialinternal cache from the 3D spatial encoder
KV_semanticinternal cache from the 2D visual encoder
t_0the first frame (initial anchor)
t_recentframes in the recent sliding window
fusion_weightslearned scalars that balance spatial and semantic importance
A tiny worked example
Suppose the robot has processed 100 frames. Without caching, it must encode all 100 again for the next decision step.
With dual implicit memory: keep only frames 0 (initial) and 95-99 (recent window = 5 frames). Store their KV caches from both encoders. Total: 6 frames cached instead of 100.
On the next step, query the 6 cached summaries via attention, not 100 full encodings. Computation drops from 100 frames to 6. Speed gain: ~17x.

The memory stays compact because only keyframes (first and recent) are cached; the algebra shows why splitting spatial and semantic caches preserves both types of information without reprocessing.

What can go wrong

What can go wrong

3D encoder trained on 2D only. If the spatial encoder is pre-trained only on 2D image pairs (like standard vision models), it cannot learn 3D depth from RGB alone. The paper uses a specialized encoder trained on 3D point clouds, which is why it works. Use a generic 2D encoder and spatial reasoning collapses.
Keyframe selection too aggressive. If the sliding window is too small or the model fails to identify true attention sinks, important intermediate frames are lost. The robot loses track of turns or obstacles. Window size must be tuned to the environment.
Spatial and semantic channels interfere. If the two encoders' outputs are not properly fused (just concatenated or weighted poorly), the language model receives conflicting signals. A move that looks good semantically might be spatially dangerous. The projection layer must learn to balance both.
Done right. Use a 3D-aware spatial encoder, tune the sliding window to your environment size, and train the fusion layer. The method then outperforms simple frame caching by 10-35% in navigation success because the depth encoder provides spatial cues that prevent mistaking far objects for near ones, and the sliding window structure prevents information loss at trajectory turns.
What a runnable demo should prove

What a runnable demo should prove

Implement a lightweight version: take 100 frames from a navigation video, cache only the first and last 5 frames' encoder outputs (both spatial and semantic), then ask the robot to plan the next action given the cached history. Measure how much computation time is saved and how the language model's decision accuracy changes.

spatial_reasoning_gain = (success_rate_with_dual_memory - success_rate_without_spatial) / success_rate_without_spatial * 100%

The demo should make it impossible to miss that caching separate position and appearance memories is much faster than reprocessing all frames (because you only decode 6 cached frames instead of 100), and that depth information adds real reasoning power the robot would not have from color alone (because a wall can be near or far in color but depth disambiguates it).
