Robustness of Probabilistic Models to Low-Quality Data: A Multi-Perspective Analysis

Compare how language models, diffusion models, and classifiers react to corrupted training data, then explain the gap by two factors: how much conditioning information constrains the task and how much total clean information survives in the dataset.

Paper explainersAll themesOther

Different model families respond very differently when training data are corrupted. This paper shows that step-by-step language models remain usable under heavy corruption, while class-conditional diffusion models can collapse under the same corruption level and large classifiers land in between. The authors do not stop at the benchmark result. They analyze it from three angles: information theory, PAC learning, and gradient dynamics, meaning how training updates line up over time. Their conclusion is that two properties largely determine resilience: the amount of conditioning information given to the model and the absolute amount of correct information left in the data. More conditioning information narrows the set of plausible outputs, and enough total clean information lets correct updates dominate noisy ones during training.

Zero assumption version

Why low-quality data hurt some model families much more than others

Training corpora and image sets inevitably contain broken input-output relations: wrong next pieces in a sequence, mismatched labels, or samples paired with the wrong class condition. But these errors do not damage all learning problems equally. A text model predicting the next piece from a long prefix still sees many correct constraints from the surrounding context even if part of the data are corrupted. A diffusion model asked to generate an image from only a class label gets far fewer clues about the exact target image.

That gap makes direct comparison interesting. If two models are trained under the same corruption rate and one keeps improving while the other collapses, the difference cannot be blamed only on data quality. It points to deeper differences in how much the task is constrained and how much useful signal each update still carries.

The paper frames the question at that level: what properties of the learning problem make corruption survivable?

The paper's move. Run controlled corruption experiments across three model families and explain the outcome with a joint account based on conditioning information, total clean information, and the direction coherence of optimization updates.

The algorithm as a flow

What it actually does

Inject controlled corruption

Deliberately break part of the training relation so the amount of low-quality data is known rather than guessed.

Train three model families

Evaluate decoder-only text models, sequence-to-sequence models, diffusion models, and image classifiers under matched corruption settings.

Measure observed degradation

Track metrics such as negative log-likelihood, consistency, and accuracy to see how fast each family deteriorates.

Analyze information content

Ask how strongly the condition narrows the target space and how much total clean information remains after corruption.

Analyze training dynamics

Inspect whether updates from different batches align or conflict, because stable alignment lets correct signal accumulate while conflict turns corruption into destructive noise.

The hidden quantity

The hidden quantity

measured quantity  =  How much clean learning signal survives each corrupted example

A corruption rate by itself is too coarse. The hidden quantity is how much useful information an example still contributes after corruption, given the task's condition. A corrupted language-model example may still contain a long correct prefix. A corrupted diffusion example paired with the wrong class condition may contribute almost no useful image guidance for the intended class.

This surviving signal determines whether gradients, meaning the update directions produced by training examples, point mostly toward the right solution or mostly cancel one another. That is why the same nominal corruption rate can lead to mild damage in one family and collapse in another.

Why it works

Why conditioning richness and information content matter

Conditioning richness narrows the prediction problem. In a step-by-step text model, the preceding sequence already eliminates most possible next pieces, so even if some training relations are corrupted, the model still gets many locally coherent signals. In a class-conditional diffusion model, the class label leaves a huge set of compatible images, so a wrong image-label pair is much harder to detect from the condition alone.

Absolute clean information matters separately from condition richness. A very large classifier dataset can survive moderate label corruption because the number of clean examples still grows large enough for the correct pattern to dominate on average. If the same corruption rate is applied to a smaller dataset, the learner sees too little clean signal for that averaging effect to take hold.

The gradient view ties the story together. When clean examples share a strong directional tendency and corrupted examples are comparatively weak or incoherent, batch updates still align with the true solution. When the task is weakly constrained and the clean signal is sparse, corrupted updates can point in many conflicting directions, so optimization no longer integrates toward a stable model.

The basic corruption-tolerance picture

First in words:

A simple mental model is that surviving clean information grows with data scale and condition richness, while harmful noise grows with corruption. Learning remains stable when the clean term dominates the noisy term in the update direction.

Then the compact form:

usable_signal = clean_information * conditioning_strength - corruption_noise

Every symbol:

usable_signalnet information available to move learning in the right direction
clean_informationamount of correct target information still present in the data
conditioning_strengthhow strongly the given condition narrows the target
corruption_noisemisleading update pressure introduced by low-quality pairs
A tiny worked example
Suppose two tasks both have fifty percent corrupted examples.
Task A predicts the next piece from a long prefix, so the condition narrows the target heavily.
Task B generates an image from only a class label, so the condition narrows the target only weakly.
Even with the same corruption rate, Task A keeps more usable signal because the clean context still points toward a small set of plausible outputs.
Task B keeps less usable signal, so corrupted pairs contribute a larger share of the total update direction.

The paper's full theory is more detailed than this shorthand, but this form captures why the same corruption percentage can have very different effects across tasks.

What can go wrong

What can go wrong

The explanation is comparative, not universal. A diffusion model with much richer conditioning or a text task with very weak context could move on the spectrum, so the paper's ordering should be read through the information available in the specific task setup.
Corruption type matters. Random corruption is easier to average out than structured corruption aligned with frequent patterns, because structured errors can keep pushing updates in a consistent wrong direction.
Scale can mask fragility. A very large dataset can hide the effect of low-quality data by sheer clean-information volume, so good corruption tolerance at scale does not mean the model family is intrinsically immune.
Done right. The paper is useful because it explains corruption tolerance through task information and update dynamics, which gives a way to predict failure before running every possible corruption experiment.
What a runnable demo should prove

What a runnable demo should prove

Build three toy tasks with matched corruption rates but different conditioning strength: next-step sequence prediction from a long prefix, image classification from an input image, and image generation from only a class label. Keep model size small, sweep corruption from zero to fifty percent, and track performance as well as update alignment across batches.

The demo should let the user increase condition richness for one family, such as adding more conditioning detail to the generative task. That matters because the paper's main claim is causal: better constraints from the condition should shift the corruption response.

alignment_gap = mean_update_alignment_clean_signal - mean_update_alignment_corrupted_signal

The demo proves the argument if stronger conditioning or more clean data volume moves a fragile setup toward the resilient side of the spectrum because both changes increase the share of clean update signal.
