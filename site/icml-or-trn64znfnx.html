Wave-Induced Rotary Encodings for Graphs

Rotary position encodings adapt to graph structure by rotating tokens based on the graph's spectral properties, boosting attention performance without bias-based tricks.

Paper explainersAll themesGraph & Geometric Learning

Large language models and vision systems use rotary position encodings (RoPE) to tell the attention mechanism where each token sits in a sequence. This paper asks: what if we apply the same idea to graphs, where nodes connect in irregular patterns instead of rows? The answer is WIRE — a way to rotate each node's numbers based on the graph's mathematical structure, letting attention naturally understand distances and paths in the network.

Zero assumption version

Graphs break the old position encoding playbook

In large language models, every token (word) has a fixed position in the sequence: token 0, token 1, and so on. The rotary position encoding tells attention 'token 5 is far from token 8' by rotating the numbers inside token 5 and token 8 by an amount that depends on their distance. This works beautifully for sequences because distance is unambiguous — left and right on a line.

But graph data has no line. A node can be connected to many neighbors, at different distances through different paths. When you try to apply standard rotary encodings to graphs, you face a choice: spin the node's numbers based on which neighbor? The paper shows this is underexplored — most graph learning methods resort to bias tricks (adding extra numbers to the attention score). These bias tricks fail with newer, faster linear attention engines because those engines skip the expensive step of building the full table of similarity scores between all pairs, so any information added later as a bias is lost.

The move. Rotate each node's numbers based on the graph's own structure — specifically, the pattern of how the graph's natural vibrations (its Laplacian spectrum) decay through the network.

The algorithm as a flow

What it actually does

Compute the graph's Laplacian spectrum

Extract the eigenvalues (natural vibration frequencies) of the graph Laplacian (a matrix encoding how nodes connect).

Assign each node a rotation angle

For each node and each frequency, spin the node's embedding (its list of numbers) by an angle derived from that frequency and the node's position in the graph.

Feed rotated embeddings into attention

The attention mechanism now receives pre-rotated embeddings (lists of rotated numbers), so when it computes similarity between two nodes, the rotation naturally encodes graph distance.

Scale with graph properties

The rotation angles depend asymptotically on the graph's effective resistance (a measure of how hard it is to move current between nodes), automatically adapting to the graph's topology.

Keep linear attention compatible

Unlike bias-based encodings, rotations bake structure into the vectors themselves, so newer linear attention engines (which skip the expensive similarity matrix) still work correctly.

What the paper changes

What the paper changes

The paper modifies one thing: the input to the attention mechanism. Instead of raw node embeddings (lists of numbers), each embedding is rotated (its numbers spun by a specific angle) before attention sees it. The rotation angle is computed from the graph's Laplacian spectrum and the node's position.

the object it moves  =  rotation angle of each node embedding
The hidden quantity

The hidden quantity: Graph spectrum decay

measured quantity  =  Spectral decay through the graph

Standard rotary encodings in language models work because they measure distance along a line. WIRE must measure something analogous for graphs: how far apart are two nodes in the network? The hidden quantity the paper relies on is the graph's spectral decay — how the natural vibrations (eigenmodes) of the graph Laplacian fade away as you move between nodes. This encodes both direct connections (short edges) and indirect paths (via shared neighbors) into a single number.

The paper estimates this quantity by computing the graph Laplacian's eigenvalues and eigenvectors, then using them to define a rotation angle for each node. The rotation angle itself becomes the vessel carrying graph-distance information into the attention mechanism. Nodes farther apart (in spectral distance) get rotated by more different angles, so attention naturally separates them.

Why it works

Why it works

The core insight is that the graph Laplacian spectrum encodes graph structure. When you compute the Laplacian (a matrix where entry (i,j) is -1 if nodes i and j are connected, and the diagonal counts each node's connections), its eigenvalues and eigenvectors naturally capture the graph's structure: clusters, bottlenecks, and overall shape. By spinning each node's embedding based on these spectral properties, you encode the graph's topology directly into the numbers the attention mechanism sees.

When attention compares two node embeddings (to decide if they are similar), it measures how much their rotated vectors line up. Nodes that are spectrally close (nearby in the graph's natural structure) will have rotations that align well. Nodes that are far apart will have rotations that cancel each other out, making their similarity score small. This means attention automatically learns to respect graph distance without requiring explicit bias terms. Linear attention engines benefit most: they do not build the full similarity matrix, so they need the graph information baked into the vectors, not added later as a bias.

The asymptotic connection to effective resistance (a classical measure of network topology) means the method scales: it naturally adapts to how hard it is to transmit information between any two nodes in the graph.

Math after the picture

The equation

First in words:

For each node i and embedding dimension d, rotate the d-th component by an angle that depends on the Laplacian eigenvalue lambda and the node's position in the eigenspace.

Then the compact form:

embedding_rotated[i,d] = embedding[i,d] * cos(lambda_d * position_i) + embedding_aux[i,d] * sin(lambda_d * position_i)

Every symbol:

embedding[i,d]the d-th number in node i's original embedding (list of numbers)
lambda_dthe d-th eigenvalue of the graph Laplacian
position_inode i's coordinate in the graph's eigenspace (derived from eigenvectors)
embedding_rotated[i,d]the d-th number in node i's embedding after rotation
embedding_auxan auxiliary embedding (the imaginary part, for 2D rotation math)
A tiny worked example
Suppose node A has embedding [2.0, 3.0] and eigenvalue lambda=1.5, position=0.8.
Rotate the first component: 2.0 * cos(1.5 × 0.8) + aux * sin(1.5 × 0.8) = 2.0 * cos(1.2) + aux * sin(1.2).
cos(1.2) ≈ 0.362, sin(1.2) ≈ 0.932, so if aux=1.5: result ≈ 2.0 * 0.362 + 1.5 * 0.932 ≈ 0.724 + 1.398 ≈ 2.122.
Node B with a different spectral position (0.2) rotates by angle 1.5 × 0.2 = 0.3, yielding a different result.
Same embedding, different spectral positions = different rotations = attention can distinguish them by graph distance, not just values.

The rotation uses trigonometry: each embedding component is spun in a 2D plane by an angle set by the Laplacian's eigenvalue and the node's spectral coordinate.

What can go wrong

What can go wrong

Disconnected graph components. If the graph has separate, isolated clusters, the Laplacian spectrum treats them as independent. Nodes in different components may receive meaningless rotations if the method does not account for disconnection.
Very large or dense graphs. Computing the full Laplacian eigendecomposition is expensive (scales as the cube of the graph size, or worse). On dense graphs with millions of nodes, this preprocessing step can become prohibitive.
Dynamic graphs (edges appear/disappear). WIRE precomputes the spectrum once. If the graph changes over time, the rotations become stale and no longer encode the current structure.
Done right. WIRE shines on static, moderately-sized graphs where the Laplacian spectrum is computable and the graph has genuine structure (not random). On such graphs, the spectral rotations naturally align with how information flows.
What a runnable demo should prove

What a runnable demo should prove

Build a simple graph neural network with and without WIRE. Compare accuracy with and without spectral rotations. The demo should make it clear that WIRE's edge comes from using the graph's mathematical structure, not from increased model complexity.
