Spiking Heterogeneous Harmonic Resonate-and-Fire State Space Model

Replace matrix multiplications with spiking neural pulses in state space models to handle ultra-long sequences on energy-starved devices.

Paper explainersAll themesEfficiency & Systems

Transformers work well but multiply every token with every other, which explodes with long sequences. State space models solve that but still need full matrix math. This paper swaps both problems: spiking neurons (which send sparse pulses instead of continuous numbers) run no multiplications, and harmonic state update equations (which rely on circle math, not matrices) scale to ultra-long sequences. The result is 50,000-step time series on devices with almost no power budget.

Two worlds, neither fast enough

Transformers are the default for sequences. They read the input one piece at a time and ask: what did every past piece say about right now? That query-key math multiplies every position with every other, so a 50,000-step sequence does 50,000 times 50,000 comparisons — wasteful and memory-hungry.

State space models fixed that. They use a sliding filter (imagine a smeared window that remembers the past) instead of comparing everything to everything. One sweep, done. But they still rely on matrix multiplication to update that filter, which burns power and slows answers on phones or sensors.

Meanwhile, neurons in animal brains barely multiply. They send sparse pulses (spikes): fire or quiet, nothing in between. This saves energy because a multiplied step only happens when a neuron fires; most steps do nothing (no spike, no computation). But brains do not use matrix multiplies for memory — they use harmonic oscillation (think of a resonating drum that already knows how to vibrate at certain frequencies). A beginner would try: add spiking to a standard state space model. It breaks because multiplying by sparse spike patterns still costs power and because the state update equations assume dense numbers.

In one sentence. Replace matrix multiplies with spiking pulses and harmonic circle math to run state space models on energy-starved devices.

What the paper changes

What the paper changes

A normal state space model updates its memory by multiplying the current state by a matrix, then adding the new input. This paper replaces that with two moves: (1) neurons only pass signals when they spike (random or threshold-based), and (2) the state update uses harmonic math (the state spins on a circle at fixed speeds) instead of matrix math. The result is zero multiplications in the tight loop.

the object it moves  =  matrix multiplies in the state update
The hidden quantity

How often neurons spike

measured quantity  =  spike sparsity (fraction of steps with pulses)

Spiking neural networks only send pulses when the neuron crosses a threshold. If neurons fire rarely, computation drops: you only multiply for the pulses that actually matter. Sparsity (what fraction of all possible spikes occur) is the true cost dial — more spikes mean more multiplies, less sparsity means energy savings.

The paper measures this by recording how many spikes happen across a sequence and comparing it to the total possible (every step for every neuron). They find that harmonic neurons fire less often than random ones because their state naturally reaches high values only at certain circle positions — another form of selectivity. By varying the neuron's bias (which shifts the threshold), they trade off spike count for accuracy.

Why it works

Why eliminating multiplies works

In a normal state space model, the state gets updated by multiplying it by a matrix (called A), then adding the input (weighted by matrix B). Each multiply costs energy and time, and on an embedded device, that cost dominates. The trick is to choose A and B so that multiplication reduces to rotation. Specifically, if A is a rotation matrix (based on angles and fixed rotations), multiplying a point on a circle by that matrix just rotates the point — no cross-products needed, just spinning. For long sequences, this savings compounds: instead of thousands of dense matrix multiplies, you do thousands of cheap circle rotations.

But rotations alone do not learn. The paper's second move is heterogeneity: using different harmonic frequencies (different rotation speeds) for different neurons. This creates a bank of oscillators, each tuned to different time scales. Short-term patterns fire the fast oscillators; long-term patterns build up in the slow ones. Together, they cover the full spectrum of sequence behaviors. Spiking on top ensures that only strong signals move the system, making the model selective and sparse.

In practice, a sequence of 50,000 steps runs in one linear pass, with no quadratic comparisons and no dense matmuls. Sparse spikes mean most of the time nothing fires. The energy cost is the spike cost (usually orders of magnitude lower) plus the harmonic update cost (cheap angle arithmetic).

Math after the picture

The harmonic state update

First in words:

next_state = rotation_by_angle times old_state, plus spike_weight times input. The rotation angle is fixed by a harmonic frequency. A spike carries the input; no spike, state rotates in place.

Then the compact form:

x[t+1] = cos(w)·x[t] - sin(w)·y[t] + s[t]·u[t] | y[t+1] = sin(w)·x[t] + cos(w)·y[t]

Every symbol:

x[t], y[t]the two-number state at time t (the point on the circle)
wthe harmonic frequency (angle of rotation per step, in radians)
u[t]the input signal at time t
s[t]the spike signal: 0 or 1 (neuron fires or not)
cos(w), sin(w)the rotation matrix entries; computed once, reused every step
A tiny worked example
Start: state = (x=1, y=0), angle w = 0.1 radian, input u = 0.5, no spike s=0.
Next step: x_new = cos(0.1)·1 - sin(0.1)·0 + 0·0.5 = 0.995·1 - 0.0998·0 = 0.995
y_new = sin(0.1)·1 + cos(0.1)·0 = 0.0998·1 + 0.995·0 = 0.0998
State moved from (1, 0) to (0.995, 0.0998): a tiny rotation, no multiply.
Now spike fires s=1: x_new = 0.995 - 0 + 1·0.5 = 1.495, y_new = 0.0998 + 0 = 0.0998
Spike input adds 0.5 to x in one cheap step. No matrix, no quadratic cost.

The state lives on a circle, and spinning it with a rotation keeps it on the circle. Spikes add energy; rotation preserves structure. This is why it scales: spinning costs the same regardless of sequence length, not quadratic like comparing every pair of steps.

What can go wrong

What can go wrong

Too sparse: neurons never fire. If the threshold is set too high, spikes become vanishingly rare and the model loses signal. It sees only silence and defaults to guessing. Fix: tune the bias term to hit a sweet spot (often around 10-30 percent of steps firing).
Harmonic mismatch: frequencies do not cover the signal's time scales. If a sequence has patterns at a 5-step rhythm but the harmonic oscillators only cover 1-step and 20-step frequencies, those patterns are invisible. Fix: choose heterogeneous frequencies that span the range of expected periodicities in the data.
Regression instability on very long sequences. The paper uses a kernel-based decoder (a weighted sum that blurs spikes together) to combine information over 50k steps. These decoders can amplify distant spikes if not tuned carefully, leading to noisy predictions. Fix: use a decaying or windowed kernel that trusts recent spikes more.
Done right. With heterogeneous harmonic frequencies and careful threshold tuning, the model captures multi-scale patterns in sensor data and ultra-long time series while staying efficient enough for edge devices.
What a runnable demo should prove

What a runnable demo should prove

Write a tiny time series (e.g., a sine wave plus noise, 500 steps) and a long one (10,000 steps). Train the spiking harmonic SSM to predict the next value. Measure: (1) accuracy (mean squared prediction error), (2) spike count (total pulses fired across the sequence), and (3) wall-clock time (inference speed). Compare to a dense state space model and a first-order spiking SSM. Plot a timeline showing which steps fire spikes; verify that most are quiet and that spikes cluster around signal changes or periodic peaks.

efficiency_score = accuracy / (spike_count + time_seconds), higher is better; long_sequence_scaling = accuracy_at_10k_steps / accuracy_at_500_steps (ideally close to 1)

The demo must show that the harmonic model stays accurate as sequences grow to 10k-50k steps while using fewer spikes and less compute than a dense baseline — the core promise of eliminating matrix multiplies.
