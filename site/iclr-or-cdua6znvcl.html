Efficient Agent Training for Computer Use

Start with a small set of human computer-use demonstrations, then expand each one with several plausible action choices so the agent learns from more than a single path.

Paper explainersAll themesAgents & Tool Use

Computer-use agents need detailed trajectories: where to click, what to type, when to wait, and how to recover from small mistakes. Collecting many human demonstrations is slow and costly. This paper shows that a small human set can go much further if you enlarge it with additional action choices created by a strong teacher model. The key is that the synthetic actions are not random variations. They are plausible alternatives at the same decision point, so the trainee learns that more than one local move can still lead to task success. That gives broader coverage without requiring thousands of new human sessions.

Zero assumption version

Why computer-use data is hard to scale

A computer-use trajectory is expensive because a person must complete the task step by step while the system records every state and action. For one task that may be manageable. For hundreds of interfaces and failure cases, data collection becomes the bottleneck.

There is also a coverage problem. One human demonstration often shows only one valid route through the interface. Another person might solve the same task with different clicks, different menu order, or a different recovery after a pop-up. Training on just one route can leave the agent brittle because it sees too few acceptable decisions.

The paper's move in one sentence. Use a small set of real demonstrations as anchors, then ask a strong teacher system to propose alternative valid actions at each step so the training set covers more reasonable behavior.

The algorithm as a flow

What it actually does

Collect a small human set.

Record a few hundred trusted computer-use trajectories from people.

Choose decision points.

Identify steps where more than one action could still advance the task.

Synthesize alternatives.

Ask a strong teacher system to propose other valid actions for those states.

Filter and merge.

Keep the alternatives that stay aligned with the task and combine them with the original human data.

Train the agent.

Use the enriched trajectory set to teach the computer-use policy.

What the paper changes

What changes

The paper changes the training dataset. Instead of one fixed human trajectory per situation, the dataset includes several plausible action choices anchored to the same human state.

The hidden quantity

The hidden quantity: local action coverage

measured quantity  =  How many reasonable choices the dataset shows

The paper is really increasing local action coverage. That means the fraction of reasonable actions the trainee sees during training when it faces a given screen state. Higher coverage matters because real interfaces admit multiple correct next moves, and a policy trained on only one may panic when the screen shifts slightly.

The method estimates and expands this coverage by using human trajectories as trusted anchors, then adding teacher-proposed alternatives around those anchors. Each accepted alternative shows the trainee one more valid way to continue from the same state. This broadens the policy's view of what success can look like.

Why it works

Why synthetic alternatives help more than direct copying

A direct copy of a teacher model's full trajectory can import the teacher's style, but it may also import brittle habits or states that are hard to verify. This paper stays closer to the trusted human data. It keeps the human trajectory as the main path and inserts alternative local actions around it. That choice matters because each synthetic branch is attached to a real state humans actually reached.

The enriched set improves learning because it teaches tolerance around decision points. When the agent later sees a slightly changed window layout, pop-up, or menu order, it is less likely to fail from mismatch with one memorized route. It has already seen that several moves can still preserve progress, so it can act with wider coverage while staying task-aligned.

The data expansion picture

First in words:

Start from a small number of human trajectories, add accepted alternative actions around each one, and compare success before and after enrichment.

Then the compact form:

expansion_ratio = enriched_action_count / human_action_count

Every symbol:

human_action_countnumber of recorded human actions in the seed dataset
enriched_action_countnumber of training actions after adding accepted alternatives
expansion_ratiohow much the action set grew
A tiny worked example
Suppose the seed dataset has 312 human trajectories with 10,000 recorded actions in total.
The teacher proposes accepted alternatives for 4,000 of those actions.
Now the enriched set contains 14,000 training actions.
Expansion ratio = 14,000 / 10,000 = 1.4.
The agent now trains on forty percent more local decisions without collecting new human sessions.
If those added actions are valid, success can rise because the policy has wider exposure to acceptable next moves.

The value of expansion is not raw size alone. It matters only when the added actions stay valid and task-aligned, because bad additions would widen the dataset in the wrong direction.

What can go wrong

What can go wrong

Synthetic actions drift off task. A proposed action may look plausible but still move the interface away from the goal. Filtering matters because one bad local branch can teach the policy the wrong move.
The human seed set is too narrow. Synthetic branching cannot fix missing task families. If the human anchors never include spreadsheet work, for example, local alternatives on browser tasks will not suddenly create spreadsheet skill.
Too many alternatives blur preference. If every state receives many weak alternatives, the learner may stop distinguishing the cleanest next move. The system needs quality control because diversity helps only when the added choices remain strong options.
Done right. When synthetic alternatives stay close to trusted human states and remain valid, the agent generalizes better because it has learned several acceptable continuations instead of one brittle route.
What a runnable demo should prove

What a runnable demo should prove

Take a small desktop benchmark with tasks such as file rename, form entry, and spreadsheet edit. Train one agent on human trajectories only and another on the same trajectories plus accepted alternative actions. Then perturb the interface slightly by moving buttons or changing menu order. The enriched agent should retain more task success because it has already learned that more than one local action can preserve progress.

generalization_gain = perturbed_success_enriched - perturbed_success_human_only

The visible outcome should be higher resilience to interface variation from a training set that is broader without being manually much larger.
