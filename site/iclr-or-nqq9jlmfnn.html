Unified 3D Scene Understanding Through Physical World Modeling

One model predicts any 3D scene property (depth, new-angle photographs, object poses) by choosing which image patches to decode in which order.

Paper explainersAll themesComputer Vision

3D tasks like photographing a scene from a new angle, estimating depth, or predicting how objects move are usually solved by separate specialist models. This paper builds a single generative model that learns all three tasks at once, using a unified language: every task becomes a different sequence of predictions through the same probabilistic graphical model (a pattern of how things relate to each other). The model represents a scene as small image patches, encodes each patch into a short code, and predicts one code at a time like a language model. Depending on what codes you ask for first, the same model solves different problems without retraining.

Zero assumption version

The fragmentation problem

Today, if you want to photograph a 3D scene from a new angle, estimate its depth, or predict how objects move, you build three separate models trained on three separate datasets with three separate objectives. Each specialist is very good at one task but knows nothing about the others.

A beginner might try training one big model on all three tasks at once, but naive multi-task learning often fails because the gradients (directions to nudge the model's weights) from different tasks point in conflicting directions. The model gets stuck trying to satisfy all three objectives simultaneously.

In one sentence. Train one model to predict image patches in any order, and different orderings automatically solve different 3D tasks.

The algorithm as a flow

What it actually does

Encode the scene

Chop the image into small square patches; each gets a short numeric code via a learned compressor.

Order the prompts

Feed known patches (e.g., RGB and camera pose) in an order that hints at what you want (e.g., depth first).

Predict the next code

The model sees what you gave it and guesses the next unknown code, one at a time, like language model completion.

Repeat for all patches

Decode the full scene code by code until all unknown patches are filled in.

Decode back to images

Convert the predicted codes back to pixels; the spatial order determines the task outcome.

What the paper changes

What the paper changes

The core move is simple: stop designing task-specific decoding paths. Instead, let the model learn to predict the same patches in any order. Feed the model prompts in different spatial and modality orders during training (sometimes depth first, sometimes new-angle-view pixels first, sometimes camera motion first) and let it learn that all these orderings describe the same unified world.

the object it moves  =  patch decoding order
The hidden quantity

The hidden quantity: whether predictions stay consistent

measured quantity  =  cross-ordering prediction agreement

The paper measures whether the model predicts the same spatial relationships no matter what order it decodes in. For instance, if the model predicts depth from one ordering and optical flow from another, those predictions should agree on where objects are in 3D space. This consistency is not explicitly trained; it emerges because the model learns that one true 3D world underlies all orderings.

The model estimates consistency implicitly through its internal representations: when it decodes a patch, it must be compatible with all possible prompt orderings. The shared parameters (the weights) force the model to learn a single coherent 3D understanding that satisfies all modalities simultaneously.

Paper reading. 3WM encodes the 3D scene as a probabilistic graphical model where nodes (RGB, optical flow, camera pose) are interdependent. Different ways of querying the graph (by asking it to fill in different patches) correspond to different conditional queries over the same graph. By predicting codes (which are short representations of patches) one at a time with random ordering during training, the model learns to maintain consistency across all possible orderings, resulting in precise controllability and spatial coherence without task-specific objectives.
Why it works

Why unified ordering works

In a traditional multi-task model, different tasks pull the model's weights in conflicting directions. Depth training wants the model to output thick, blocky predictions. View synthesis wants smooth, photorealistic details. These competing signals cause training instability.

The unified approach sidesteps this conflict by removing task-specific output heads. Instead, there is only one decoder: predict the next patch code. The task emerges from the order in which you prompt the model. If you ask for depth regions first, the model's internal computations naturally organize to predict depth-consistent codes. If you ask for new-view regions first, the same weights reorganize to predict spatially consistent pixels. Because all prompts come from the same unified world model (the graphical model), the shared parameters learn representations that satisfy all orderings simultaneously. Training becomes a single coherent objective: predict any next patch given any conditioning order. The model no longer faces opposing gradients; instead, it learns a single 3D understanding that works under all query orders.

Math after the picture

The unified prediction objective

First in words:

cross_entropy_loss = negative_log_probability_of_next_code_given_context, summed over all tokens in random order during training

Then the compact form:

L = sum_t -log p(c_t | c_1, ..., c_{t-1}, prompt_order) where c_t is the code at position t and prompt_order determines which modality/region appears first

Every symbol:

c_tthe code representing patch t
p(c_t | ...)probability the model assigns to code c_t given all prior codes and the prompt order
prompt_orderthe sequence in which patches are revealed (e.g., depth-first or RGB-first)
-log p(...)how much prediction error: zero if the model is certain, high if uncertain
A tiny worked example
Prompt order: Depth-first. Given RGB patch 1 and camera pose, predict depth patch 1.
Model outputs 95% confidence on the right depth value: -log(0.95) = 0.051 bits of loss.
Next, given depth patch 1, predict optical flow patch 1.
Model outputs 70% confidence: -log(0.70) = 0.357 bits of loss.
Total loss for 2 predictions: 0.051 + 0.357 = 0.408. During training, this order is shuffled; next batch might predict flow first. The same model weights adjust to predict well under all orderings.

The insight is this: because training shuffles the order every batch, the directions to adjust weights force the shared parameters to learn representations that are consistent under any permutation. No single task dominates; instead, the model converges to a single coherent 3D world understanding.

What can go wrong

What can go wrong

Patch order matters for speed. If you ask for high-frequency details before low-level structure, the model must hallucinate details without context. Asking for coarse depth patches first gives the model a scaffold to place details. Training reveals which orders are efficient; when the finished model runs, it can use that knowledge to accelerate generation.
Inconsistency in sparse prompts. If you provide very few conditioning patches, the model may predict different depths vs. flow estimates that contradict each other because neither is well-anchored. The graphical model works best with sufficient context. Zero-shot inference (no fine-tuning) requires the training data to cover similar prompt sparsity.
Computational cost of random access. The model uses a pointer-content representation (a way to look up arbitrary patches without reading them in order) to enable arbitrary patch orderings, which adds memory and computation overhead. Long sequences (4,096 codes) can be slow because the attention mechanism (a mechanism that learns which parts of the input matter) must consider all positions. The paper trades off some speed for flexibility in which patches to predict first.
Done right: spatial consistency is preserved. When trained on diverse scenes and prompt orderings, the model learns that RGB, depth, and flow all describe the same world. Predictions remain consistent across all decoding orders because the shared parameters enforce one underlying spatial arrangement.
What a runnable demo should prove

What a runnable demo should prove

Take a single 3D scene (e.g., a room with objects). Hide different subsets of information: Hide depth but show RGB and camera pose; predict depth. Hide view pixels but show RGB and camera movement; synthesize a new-angle view. Hide optical flow but show RGB and camera motion; predict which direction objects move. All three predictions should be consistent (if you predict both depth and motion, a fast-moving object should be far away, not near). Run this on three scenes the model never saw during training.

consistency_score = (1 - average_disagreement) where disagreement = how much depth-from-motion contradicts explicit-depth prediction

The core insight made visible: the same set of weights solves three different tasks because they all query the same unified 3D world model. Consistency proves the model learned one true spatial arrangement, not three independent tricks.
