UniJEPA: Unified Continuous and Discrete Representation Learning for Robot Policies

By learning from internet videos to predict what happens next, a robot can combine visual understanding with action planning, making generalist policies that work across tasks.

Paper explainersAll themesRobotics & Control

Building a robot that can handle many different manipulation tasks in the real world is hard, because the robot needs both to understand what it sees in images and to predict how things will move when it acts. Most robot policies rely on one or the other. This paper shows that by learning from over one million internet instructional videos to predict future visual patterns, then fine-tuning on actual robot experience, a robot policy can combine both abilities and work better than methods that use only understanding or only visual prediction.

Zero assumption version

Robot policies need both picture understanding and action foresight

A robot that grasps objects, moves arms, or navigates needs to do two things at once: understand what it sees in camera images (where is the object, what material is it) and predict what will happen when it moves (will that arm motion knock things over, how will the scene change). Most robot learning methods pick one.

Older methods train only on robot videos, so the policy learns movement patterns but misses high-level concepts. Newer methods borrow from large vision-language models (systems trained to match images with text descriptions), which understand concepts well but may never have seen a robot arm move. Neither alone works well when the robot faces a new environment or task it was not trained on.

A beginner might try: take a model that understands pictures, slap on some action tokens (discrete labels for robot moves like 'grasp' or 'rotate'), and hope it learns to pick the right action. This fails because the model was trained to describe static pictures, not to imagine motion or plan sequences of moves. It has no idea what happens next when the robot acts.

The method in one sentence: UniJEPA trains on internet videos to learn how images change over time, combining visual understanding and motion prediction, then uses that foundation to teach a robot which actions to pick.

The algorithm as a flow

What it actually does

Pretraining phase: learn from internet

Process 1M instructional videos to capture visual patterns and motion in a compressed, reusable form.

Compression layer: build unified features

Merge understanding (what is this) and dynamics (what happens next) into one shared representation.

Robot fine-tuning: map actions to predictions

Show the robot that when it picks action token 'grasp', the visual prediction should match real grasping.

Inference: pick the best action

For a new scene, choose the action whose predicted visual outcome matches the goal state best.

Test on new tasks and environments

Verify the policy generalizes to scenarios not seen during robot training.

What the paper changes

What the paper changes

The paper changes the robot policy's foundation. Instead of starting from a model trained only to describe static images, or only to predict visual sequences without understanding, UniJEPA starts from a model trained on both understanding and visual prediction via internet video pretraining. The robot then learns which action token maps to which predicted visual outcome.

the object it moves  =  the policy's learned representation
The hidden quantity

The unified visual-dynamics feature

measured quantity  =  Predicted next-frame pattern

The paper measures a hidden quantity: for any scene and any action, what should the next frame look like? This is not just a single number or category; it is a compressed pattern capturing visual change. The model learns this by processing millions of internet videos where instructional text describes manipulation (e.g. assembling furniture, cooking). Over time, the model discovers that certain image features reliably predict what comes next, and that understanding the meaning of an image (via text) and predicting its motion are tightly linked.

During robot training, the paper uses this hidden quantity to evaluate actions: if the robot chooses an action, the policy compares the predicted visual outcome to the desired goal or the actual outcome that occurred. This comparison steers the learning so that action tokens align with the right visual predictions.

Why it works

Why combining understanding and prediction works

When a model learns only from robot videos, it misses high-level structure (it sees patterns but does not know what concepts like 'cup' or 'grasp' mean). When a model learns only from text-image pairs, it understands concepts but has no intuition for motion or cause-and-effect in physical scenes.

UniJEPA solves this by training on instructional videos, which include both. Each video contains images and narration; the model learns that certain visual features co-occur with certain concepts, and that those same features evolve predictably from frame to frame. The model thus internalizes two connected patterns: (1) what does this image mean, and (2) how will it change.

The mechanism is: during pretraining, the model compresses both understanding and prediction into one set of learned features. When the robot then learns on top of this foundation, it no longer has to choose between understanding and foresight; the foundation already holds both. The robot simply learns which action token causes the visual pattern to shift in the desired direction. Because the foundation is pre-built and stable, the robot needs less robot data to reach good performance than a method starting from scratch or from a single-skill model.

The learning objective

First in words:

minimize the distance between predicted next-frame features and actual next-frame features, weighted by the importance of each action token

Then the compact form:

L = sum_t ||pred_frame_t+1 - real_frame_t+1||_2^2 + lambda * sum_a entropy(action_token_a)

Every symbol:

pred_frame_t+1the model's prediction of what the camera will see one frame later
real_frame_t+1what the camera actually showed one frame later (ground truth)
||...||_2^2the squared distance between two feature vectors (how different they are)
sum_tadd up the loss over all time steps in a video
action_token_aone of the discrete action labels the robot can choose
entropy(...)measure of how uncertain the model is about which action to pick (lower is more confident)
lambdaa tuning number that balances exact prediction against confident action choices
A tiny worked example
Time step 1: Model predicts next frame as features [2.1, 3.5, 1.8]. Reality is [2.0, 3.6, 2.1]. Distance squared = (2.1-2.0)^2 + (3.5-3.6)^2 + (1.8-2.1)^2 = 0.01 + 0.01 + 0.09 = 0.11
Time step 2: Model predicts [1.2, 4.1, 0.9]. Reality is [1.1, 4.0, 1.2]. Distance squared = (1.2-1.1)^2 + (4.1-4.0)^2 + (0.9-1.2)^2 = 0.01 + 0.01 + 0.09 = 0.11
Sum so far = 0.11 + 0.11 = 0.22. If entropy term is 0.05, final loss = 0.22 + 0.5 * 0.05 = 0.245 (lambda=0.5 here).
The model updates its weights to lower this loss, making predictions tighter and action choices more decisive.

The loss pushes the model to predict the next frame correctly and to commit confidently to one action token per decision.

What can go wrong

What can go wrong

Mismatch between internet videos and robot embodiment. Internet instructional videos show human hands and diverse environments; a robot arm is different. If fine-tuning is shallow, the robot may inherit biases from internet data that do not apply to its specific body.
Insufficient fine-tuning data. If the robot collects only a handful of trajectories on a new task, the policy may overfit to those specific states rather than learning a generalizable pattern for that task.
Domain shift in visual appearance. If the test environment has different lighting, textures, or object colors from training, the learned visual features may not match predictions, and action selection fails.
Mitigated by careful data collection. Collecting diverse robot trajectories (different arm speeds, object sizes, clutter levels) and validating on unseen test scenarios reduces these risks.
What a runnable demo should prove

What a runnable demo should prove

Write a simple robotic simulation (e.g. a 2D grid world with a gripper moving objects, or a 3D simulator like PyBullet). Train a policy using the unified representation: start with precomputed visual features from internet video (you can mock this with a frozen pretrained vision model). Then collect 50 trajectories of the robot trying different actions, and train the action-prediction layer. Finally, test on a new task (e.g. move all red objects to the left, when training only saw moving objects to the right). Measure success rate: what fraction of new tasks did the robot policy solve correctly.

transfer_success = (task_solves_with_unified / total_new_tasks) * 100 percent

The demo must show that a policy trained on internet-derived features + 50 robot trajectories succeeds at unseen tasks more often than a policy trained only on those 50 trajectories from scratch.
