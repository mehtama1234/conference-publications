Certified Circuits: Stability Guarantees for Mechanistic Circuits

When you isolate the parts of a neural network that perform a task, add randomness to your test data and keep only the parts that stay in the answer no matter what — you get circuits that really do the job.

Paper explainersAll themesInterpretability

Neural networks are black boxes. To open them, researchers find circuits — tiny subnetworks inside that handle one task, like factual recall or image classification. The problem: these circuits feel fragile. Change the test data slightly, and different circuits appear. This raises a hard question: are you seeing the real algorithm, or just an artifact of the data you used? Certified Circuits answers by wrapping any circuit-finding method in a test: randomly drop pieces of the concept dataset and re-run the discovery. Only components that stay in the answer every time get certified.

Zero assumption version

Circuits are moving targets

Circuit discovery starts with a concept dataset—a set of examples (images with cats, prompts about facts) that the network is supposed to handle. The method isolates which neurons and connections are actually doing that job. But here is the fragility: if you change even a few examples in your dataset, the discovered circuit changes. Different examples point to different pieces of the network. This looks like the circuit is not capturing something fundamental about the network's algorithm; instead, it is overfitting to your particular choice of test examples, like a student memorizing the exact test questions instead of learning the subject.

A naive circuit discoverer would just take the initial dataset, find the neurons that matter, and call it done. That circuit might disappear tomorrow on a new dataset—or worse, on data from a different source where the model has never seen examples. This brittleness makes mechanistic interpretability unreliable: a circuit is not an explanation you can trust if it only exists when you hold the data fixed.

The problem in one sentence. If you have to use the same dataset over and over to make the circuit stay, you probably found a dataset artifact, not the real algorithm.

The algorithm as a flow

What it actually does

Step 1: Load a concept dataset

Start with examples (images of dogs, prompts about facts) that define the behavior to isolate.

Step 2: Randomize by subsampling

Randomly delete some examples from the dataset; repeat many times to create many perturbed (changed) datasets.

Step 3: Run discovery on each

For each perturbed dataset, run any circuit-discovery algorithm (neuron-level or edge-level) to identify which components matter.

Step 4: Vote and aggregate

For each component, count how many discovery runs included it; compute a confidence score.

Step 5: Certify stable components

Keep only components whose confidence passes a threshold; abstain (drop) the rest. The certified circuit is provably stable.

What the paper changes

What the paper changes

The paper changes which components are included in the reported circuit. Instead of taking the raw output of a circuit-discovery algorithm, the paper wraps it in a voting-and-certification layer. Unstable components—ones that appear in some discovery runs but not others—are filtered out. What remains is smaller because fewer components pass the vote threshold, and more reliable because any surviving component has been tested against many slightly different datasets, so it is less likely to be a dataset-specific accident.

The hidden quantity

The hidden quantity: component stability

measured quantity  =  stability vote frequency

The hidden quantity is how often a single component (a neuron or edge) appears in the discovered circuit across many runs on perturbed datasets. If a neuron is truly capturing a core part of the algorithm, it should appear almost every time. If it only appears sometimes, it is probably overfitting to the particular dataset you chose.

The paper estimates this by subsampling the original dataset many times (deleting random examples each time), running circuit discovery on each subsample, and recording whether each component was included. A component with a high frequency vote is certified stable; one with a low vote is abstained from (dropped).

Why it works

Why it works: the causal chain

Circuit discovery works by checking which parts of the network are necessary for the behavior (e.g., does the model still recognize dogs if we knock out this neuron?). But the components discovered depend on the dataset. A component might appear necessary only because the dataset has more examples of one type than another, or a quirk that does not appear in the real world. If you repeat discovery on a slightly different dataset, different components now seem necessary. This noise is hidden because you only ran it once.

Certified Circuits exposes this noise by running discovery many times, each time with a perturbed dataset (examples randomly deleted). Any component that appears in most of these runs is genuinely necessary; one that appears only sometimes is overfitting to dataset-specific quirks. By voting, the method surfaces which components will stay in the answer across many datasets. In formal terms, if a component's vote count is high enough, the paper can prove mathematically that it will remain in any dataset whose edit distance from the original is bounded. This converts a heuristic intuition—run it multiple times and keep what stays consistent—into a formal guarantee. Overfitting is a form of memorization; voting breaks memorization because a quirk that exists in some subsamples does not exist in all of them.

Math after the picture

The equation: voting with confidence bounds

First in words:

For each circuit component, count how many of the subsampled discovery runs included it. Divide by the total number of runs to get an measured vote frequency. Use statistical methods (a confidence bound) to guarantee that if this frequency is high enough, then the component will remain in the circuit even on perturbed datasets.

Then the compact form:

p_u = Pr[u in circuit discovered on perturbed dataset D']; certified if lower_conf_bound(empirical_frequency) >= tau

Every symbol:

p_uthe true probability that component u is in the circuit on any perturbed dataset
ua single component (neuron or edge)
empirical_frequencythe fraction of subsampled runs in which u was discovered (e.g., 95 out of 100 runs)
lower_conf_bounda statistical lower bound on the true probability, computed from the measured frequency
tauthe certification threshold; components above it are certified, below it are abstained from
A tiny worked example
Suppose we run 100 subsampled discoveries. Neuron A appears in 94 of them.
Measured frequency for A: 94 / 100 = 0.94.
Using a statistical confidence formula (e.g., Clopper-Pearson), the lower confidence bound might be 0.88.
If tau = 0.80, then A's lower bound (0.88) exceeds tau, so A is certified in.
Neuron B appears in 55 of 100 runs. Measured frequency: 0.55. Lower bound: 0.44.
B's bound (0.44) is below tau (0.80), so B is abstained from.
Result: only reliably necessary components survive; noisy ones are dropped.

The confidence bound ensures that any component certified in will remain in the discovered circuit on any dataset within a bounded edit distance of the original.

What can go wrong

What can go wrong

Subsampling deletes too much. If the deletion rate is too aggressive (removing large portions of the dataset each time), you may abstain from too many components, shrinking the circuit below its true size. The discovered circuit becomes incomplete.
Threshold set wrong. If the confidence threshold tau is too low, unstable components slip through. If it is too high, all components get abstained from. Setting tau requires understanding the trade-off between certifying stability and keeping useful components.
Dataset is too small. If the original concept dataset has very few examples, subsampling erases information fast, and vote frequencies become noisy. The method works best when there is plenty of data to subsample.
Done right. When the deletion rate and threshold are tuned carefully and the dataset is reasonably large, certified circuits are both smaller and more generalizable than uncertified baselines.
What a runnable demo should prove

What a runnable demo should prove

Build a tiny circuit-discovery task: a small vision or language model, a concept dataset (e.g., images of one class, or prompts about one fact), and a circuit-discovery baseline (e.g., ablate neurons and measure performance drop). Then implement Certified Circuits: loop 50 times, each time subsampling 20% of the concept dataset, run the baseline discovery, and tally which components appear each time. Compute the vote frequency for each component, apply a confidence bound, and set tau at a reasonable level (e.g., corresponding to 0.8 confidence). Report the size of the uncertified vs. certified circuit, the accuracy of each on the original data and on held-out data from a different source, and show the vote-frequency histogram for each component.

generalization_gap = accuracy_on_original_data - accuracy_on_OOD_data; lower is better when combined with circuit size

The demo should make clear that certification shrinks the circuit while closing the generalization gap; the uncertified baseline's gap is large, and the certified one is small.
