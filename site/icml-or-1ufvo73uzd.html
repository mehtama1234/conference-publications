Debate2Create: Robot Co-design via Multi-Agent LLM Debate

Two AI agents debate about robot body shape and training rewards, each pushing back on the other, to jointly find better designs that actually work.

Paper explainersAll themesAgents & Tool Use

Building a robot that walks well requires two things at once: a good body shape (how the legs connect) and good training rewards (what signal teaches the robot to walk). Normally these are done separately or by hand. Debate2Create has two AI agents argue about both at the same time. One agent designs the body; the other designs what the robot should learn from. They push back on each other's ideas, using physics simulations to test each proposal. This back-and-forth beats picking one alone.

Zero assumption version

Two problems, one at a time

Making a robot walk is hard. You need a body shape that can move, and you need to tell the robot what good walking looks like (the rewards, the training signal). Right now these are separate jobs: design the body, then teach it to walk. But they are not separate—a body shape that is awkward to teach requires a different reward signal than a body that is natural to learn.

A naive approach: generate a random robot body, measure how fast it walks after training, pick the best. But this is slow and wasteful. Many body shapes need different reward signals to train well. You do not know which signal works for which body, so you test them all at random. The paper shows this is expensive.

In one sentence. The paper has two AI agents debate both body shape and reward signal at the same time, using each other's critiques to find designs that work.

Physics test

What the paper changes

What changes

The paper changes the search space from independent body and reward picks to co-adapted pairs. Instead of testing a body with every possible reward signal and measuring which one is best, the agents agree on both together. The design agent cannot stay stubborn about a body shape if the control agent keeps failing to find a reward that works with it. Likewise, the control agent's reward signal is shaped by what the design agent shows is actually buildable.

the object it moves  =  body-reward pairs
The hidden quantity

The co-adaptation strength

measured quantity  =  design-reward alignment

The paper measures an invisible quantity: how well the body and reward signal fit together. A robot with an awkward body shape needs a strange, fragile reward signal. A robot with a natural body shape can learn from simple, stable rewards. The paper does not name this explicitly, but it tracks whether each debate round produces body-reward pairs where the reward is simple and the body is easy to build.

The paper estimates this by running each proposed pair in the simulator and watching whether training succeeds (the robot learns smoothly) or fails (training gets stuck or the robot jerks). Aligned pairs train cleanly. Misaligned pairs show messy learning curves.

Why it works

Why forcing agents to agree works

Here is the core insight: if you let one agent (design) ignore the other (control), you get a body shape that only works with one specific, fragile reward signal. But if the design agent must sit in the same room as the control agent and defend the body choice, the design agent will avoid weird shapes that need weird rewards. The control agent, in turn, will not push for a reward so demanding that it only works if the body is perfect. They are forced to meet in the middle: a normal body with a reasonable reward.

The judges add pressure. After each round, five criterion-specific judges (one for cost, one for speed, one for stability, etc.) read both agents' arguments and give feedback. This feedback is physics-grounded (measured from the simulation), not arbitrary. If the design agent proposes a body that is too expensive to build, a cost judge will say so. If the reward is too hard to optimize, a stability judge will flag it. The agents then adjust.

Math after the picture

Scoring the pair

First in words:

The final score is a weighted sum of five criterion scores. Each criterion measures one aspect (cost, speed, etc). The weights can be adjusted to emphasize speed over cost or vice versa.

Then the compact form:

final_score = w_cost * score_cost + w_speed * score_speed + w_stability * score_stability + w_build * score_build + w_robust * score_robust

Every symbol:

final_scorethe overall quality of this body-reward pair
w_costhow much we care about building cost (0 to 1)
score_costthe actual cost measured (lower is better)
w_speedhow much we care about walking speed
score_speedhow fast the robot walked in the simulator
w_stabilityhow much we care about smooth motion
score_stabilityhow little the robot jerks or wobbles
A tiny worked example
Suppose cost score is 50 out of 100 (moderate building cost), weight is 0.2 -> contributes 50 * 0.2 = 10.
Speed score is 80 (good walking speed), weight is 0.5 -> contributes 80 * 0.5 = 40.
Stability score is 70, weight is 0.3 -> contributes 70 * 0.3 = 21.
Final score = 10 + 40 + 21 = 71. A pair with cheap but slow design scores lower (maybe 55). A pair with expensive, fast, stable design scores higher (maybe 78).

Each judge's score is weighted by how important that criterion is. Changing the weights shifts which bodies the agents favor.

What can go wrong

What can go wrong

Agents get stuck in a local agreement. If both agents agree early on a mediocre design (say, a stiff body and overcomplicated reward), they may reinforce each other and stop exploring. The simulator will measure poor performance, but if both agents are defending the same idea, neither will flip to a radically different direction.
The reward does not transfer. A reward signal optimized for one body shape may not work if the body changes. If the design agent keeps proposing variations on the same shape, the control agent's reward stays tuned to that shape. A truly good reward should work across body variations.
Physics simulation is slow. Each round requires running the robot in the simulator, which takes time. If there are many debate rounds, the total cost can be high. The method is faster than random search because agents eliminate bad pairs early instead of testing all combinations, but it is not instant.
Done right. The paper uses criterion-specific judges to pull the agents apart when they start to agree too much. It also tests transfer—the final reward is tested on the original, unmodified robot body to see if it generalizes. This catches overfitting.
What a runnable demo should prove

What a runnable demo should prove

A working demo simulates two agents debating a robot design. The design agent proposes a body (say, two-legged vs four-legged). The control agent proposes a reward (say, bonus for speed, penalty for energy). The simulator runs the robot for a fixed number of training steps. A judge scores the pair. Show that over five rounds, the pairs improve (because each agent refines based on judges' feedback) and the final pair is better than a random guess (because debate forces compatibility instead of testing all combinations).

improvement = (round_5_score - round_1_score) / round_1_score * 100%

The demo must make clear that neither agent alone reaches the final score—both must adjust.
