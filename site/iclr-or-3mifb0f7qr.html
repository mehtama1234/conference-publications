QuestA: Expanding Reasoning Capacity in LLMs via Question Augmentation

Make hard math training problems learnable by adding partial solution steps during reward-based training, so the model gets useful credit before it can solve the whole problem alone.

Paper explainersAll themesOther

Reward-based training on math often stalls on the hardest questions. Early in training, the model gets almost every hard question fully wrong, so the learning signal is nearly empty. QuestA changes the questions instead of changing the reward rule. During training it adds partial solution information, which lowers the difficulty just enough for the model to earn informative feedback. As the model improves, that feedback pushes it toward solving the original hard problems more often and also finding more correct samples when several attempts are allowed, because the reward can now distinguish partly good attempts from completely wrong ones.

Why hard-question training stalls

In reward-based math training, the model often receives a simple final signal: correct or incorrect. On easy problems that is enough because the model already lands near the right path. On hard problems it fails early and often, so the reward is almost always zero. When that happens, the model cannot tell which partial moves were promising, and progress stalls.

The paper argues that the issue is not that reward-based training cannot help reasoning at all, but that the questions are too hard relative to the current model. If the task is softened during training, the model can collect useful feedback on intermediate progress and keep improving because more attempts reach reward-bearing states.

The core idea. Inject partial solutions into the training question so the model gets non-empty learning signal on problems that were previously too hard, because some attempts now reach states that the reward can separate.

The algorithm as a flow

What it actually does

1. Start from a math-capable base model

Use a model that already solves some easier math but struggles on the hardest questions.

2. Build augmented training questions

Attach a partial solution step or intermediate clue to the original question.

3. Run reward-based training on those easier variants

Train so that the model gets informative feedback on problems where plain training would give mostly zeros.

4. Continue sampling and updating

As the model gets stronger, the same hard benchmark becomes more reachable from scratch because the earlier augmented training exposed useful intermediate steps.

5. Evaluate both single-attempt and many-attempt success

Check whether the model solves more problems on the first try and whether several tries now contain more correct solutions.

What the paper changes

What the paper changes

QuestA changes the training question, not the final evaluation question. That sounds minor, but it shifts where the reward signal appears. The method turns impossible early-stage training cases into partially reachable ones, so the model can learn from them now instead of waiting until much later. The learned behaviors then transfer back to the untouched hard questions because the partial clues expose valid intermediate reasoning patterns.

the object it moves  =  the difficulty of the training question during reward-based learning
The hidden quantity

The hidden quantity: reward density on hard problems

measured quantity  =  how often a hard question produces a useful learning signal instead of a flat zero

The hidden quantity is reward density. If a hard problem yields almost no successful or partly successful attempts, then training sees a long stretch of zeros. The optimizer cannot tell which actions were slightly better because there is no contrast.

Question augmentation raises reward density by inserting a correct partial path. That does not solve the problem for the model, but it moves more attempts close enough to the solution path that reward can separate stronger completions from weaker ones. Higher reward density matters because it gives the training loop more informative examples per update.

Why it works

Why it works: easier training tasks create better credit assignment

The method works because hard tasks fail for two reasons at once: the model may not know the right idea, and the reward signal may be too sparse to teach that idea. QuestA attacks the second problem directly. By lowering task difficulty during training, it increases the chance that an attempt reaches a useful partial state. The reward can then favor those better attempts, so later updates push the model toward more complete solutions because the update rule now sees contrast between partly correct and fully wrong answers.

The benefit transfers back to the original benchmark because the augmented question still points toward the same final answer. The partial clue is not random help because it names an intermediate step that a valid solution must use. It exposes structure that a correct solution must pass through, so the model practices genuine intermediate reasoning steps rather than memorizing unrelated shortcuts, because those steps are shared with the raw problem.

The augmented training objective

First in words:

Train on a mixed set of original questions and partially solved variants, maximizing reward under the augmented prompt distribution

Then the compact form:

J = E_(q,a~A(q))[ Reward(model(a | q_aug)) ]

Every symbol:

qan original training question
A(q)the augmentation rule that attaches a partial solution clue to q
q_augthe augmented version of the question
aa sampled answer from the model
Rewardthe score used by reward-based training
A tiny worked example
Suppose the original math question gives the model reward 0 on 98 out of 100 attempts.
Add one correct intermediate relation as a clue during training.
Now 22 out of 100 attempts reach a partly correct path and earn nonzero reward.
Those extra rewarding attempts give the update rule contrast between better and worse answers, so later samples improve.
At evaluation time the clue is removed, but the model retains the useful solution habits it learned while the task was softened.

The change is in the sampling distribution of training questions: more attempts now receive informative reward because the augmented prompt is easier than the raw one.

What can go wrong

What can go wrong

The clue may make training too easy. If the partial solution reveals too much, the model may rely on the clue rather than learning how to discover that step on its own.
The clue may not match the model's current weakness. Some failures come from arithmetic mistakes, others from not knowing the right plan. A generic clue can miss the real bottleneck because different questions break in different ways.
Transfer back to raw questions may be incomplete. A model can improve strongly on softened training prompts yet still need more work to solve the untouched questions from scratch if it learned to depend on the provided intermediate step, because the clue may have replaced a discovery skill rather than taught it.
When it works best. QuestA is strongest on problems where one correct intermediate step unlocks the rest of the solution, because then the added clue changes reward density without changing the underlying reasoning task.
What a runnable demo should prove

What a runnable demo should prove

Take a small math benchmark and a base model that already solves some easy items. Train one copy with plain reward-based learning and a second copy with QuestA-style augmented questions. For each run, log the fraction of training samples that receive nonzero reward, then evaluate both single-attempt success and many-attempt success on the original benchmark without clues. The QuestA run should pull ahead because it receives usable feedback on more of the hard training questions.

The demo should also show several augmented prompts next to the original prompts. That makes it possible to inspect whether the clue is truly partial and whether the final improvement comes from better credit assignment rather than from giving away the whole answer, because a too-revealing clue would make the comparison unfair.

reward_density = nonzero_reward_samples / total_training_samples

A convincing demo shows that the extra progress begins during training, before evaluation, because the model finally has enough reward-bearing attempts to learn from.
