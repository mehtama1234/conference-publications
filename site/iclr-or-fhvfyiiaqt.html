Point-UQ: Uncertainty-Guided 3D Learning Without Retraining

When learning new 3D object classes from a few examples, use uncertainty—a measure of how confident each prediction is—to decide which classifier to trust, instead of retraining the model.

Paper explainersAll themesComputer Vision

When you learn a new skill after mastering a previous one, you risk forgetting what you already know. In machine learning, the same problem (called catastrophic forgetting) happens when a model learns new 3D object classes from just a handful of examples. Point-UQ solves this by measuring how confident each prediction is and using that confidence to choose the right decision-maker for each new object—without ever retraining the entire model.

Zero assumption version

The trap: hold old knowledge or grasp new classes

You have a 3D object recognizer trained on 1000 photos of cars, chairs, and tables. A beginner's approach: download a few photos of a new object (say, lamps) and retrain the model to recognize lamps. Result: the model now recognizes lamps well but forgets what cars looked like. You have catastrophic forgetting.

The alternative: do not retrain. Just use the existing model to classify the lamp photos. Result: the model misses the lamp—it is still tuned for cars and chairs. So you are stuck between erasing old knowledge and ignoring new classes.

In one sentence. The paper measures how uncertain each prediction is and uses that doubt to decide which classifier to consult—semantic rules or geometric shape—so old knowledge survives and new classes work.

The algorithm as a flow

What it actually does

Step 1: Fuse multi-scale features

Take the 3D point cloud and extract details at coarse and fine scales, then blend them.

Step 2: Measure prediction spread

Ask the model to guess each point's class. How spread out are the scores across all classes? Spread out means uncertain.

Step 3: Route by uncertainty

If the scores are spread out, the model doubts itself. Route that sample to shape-based matching instead.

Step 4: Preserve base classes

The learned classifier (trained on cars and chairs) never gets retrained. It stays frozen.

Step 5: Recognize new lamps

New lamp samples, routed to shape matching, form an average shape that sits alongside the old classifiers. No forgetting.

What the paper changes

What the paper changes

The paper does not retrain or fine-tune the model. Instead, it swaps the decision rule: from trusting one fixed classifier to dynamically choosing between two classifiers based on how uncertain the model is about each sample.

The hidden quantity

Entropy: how spread out is the guess

measured quantity  =  prediction entropy

Entropy (a measure called prediction entropy) is a number that tells you how spread-out a prediction is. Imagine the model has a list of confidence scores for every possible class—car (0.8), chair (0.15), lamp (0.05). When one class dominates, entropy is low; the model is certain. When the scores are evenly distributed (car 0.33, chair 0.33, lamp 0.34), entropy is high; the model is confused.

The paper uses entropy to detect when the model is uncertain: when entropy is high, the model has seen few examples of this object and should not trust its learned classifier. It should instead ask about the object's 3D shape.

Why it works

Why this prevents forgetting

The mechanism is a division of labor. The learned classifier (trained on thousands of car and chair images) makes predictions by recognizing learned patterns—shapes, textures, edges. It works well on known objects but fails when given new objects it has never seen, because when spread is high, those predictions are unreliable.

A shape prototype is different: it stores the average 3D shape of each new class. When spread is high (meaning the sample is unfamiliar), the model stops trusting the learned classifier and asks instead: how close is this 3D point cloud to the average shape of a lamp? This avoids the retraining trap because the shape prototype does not change the learned patterns in the original classifier.

The two modules work together: one fuses coarse and fine details and outputs both the spread and a refined representation. The second one uses spread to pick the right classifier—if spread is low, use the learned patterns; if high, use shape matching. This keeps old classes untouched while new classes grow through shape prototypes.

Math after the picture

The entropy routing formula

First in words:

entropy = negative sum over all classes of (probability times log of probability). When entropy exceeds a threshold, route to geometric prototype instead of semantic classifier.

Then the compact form:

spread(p) = -sum_c p_c * log(p_c); if spread(p) > threshold then use_shape = true else use_learned = true

Every symbol:

p_cthe model's probability that the sample belongs to class c
spread(p)the spread (entropy) of the probability distribution across all classes
thresholda cutoff value; samples with spread above this are routed to shape matching
use_shapea yes/no flag: should we ask the shape prototype for the answer?
use_learneda yes/no flag: should we ask the learned classifier?
A tiny worked example
Example 1: Predicting a car (model has seen many cars).
Probabilities: car 0.85, chair 0.10, lamp 0.05.
Spread = -(0.85*log(0.85) + 0.10*log(0.10) + 0.05*log(0.05)) = -(0.85*(-0.16) + 0.10*(-2.30) + 0.05*(-2.99)) = -(-0.136 - 0.230 - 0.150) = 0.52.
Threshold = 0.70. Since 0.52 is less than 0.70, use learned classifier (low spread, confident).
Example 2: Predicting a lamp (model has seen only three lamp photos).
Probabilities: car 0.40, chair 0.35, lamp 0.25.
Spread = -(0.40*log(0.40) + 0.35*log(0.35) + 0.25*log(0.25)) = -(0.40*(-0.92) + 0.35*(-1.05) + 0.25*(-1.39)) = -(-0.368 - 0.368 - 0.348) = 1.08.
Threshold = 0.70. Since 1.08 is greater than 0.70, use shape prototype (high spread, uncertain). The prototype matches the lamp's 3D shape without retraining the learned classifier.

Spread is the pull-cord: when the model doubts itself, it stops trusting learned patterns and leans instead on the average 3D shape.

What can go wrong

What can go wrong

Threshold too low. If the spread threshold is set too low, almost every sample routes to shape matching. The learned classifier is barely used. New classes work, but you lose the benefit of learned base-class patterns.
Threshold too high. If the threshold is set too high, almost every sample trusts the learned classifier. New classes look like noise; the shape prototypes never get a chance to distinguish them.
Shape prototypes need enough examples. The method works only if the few new examples are representative. A lamp prototype built from three photos of desk lamps might fail on floor lamps because those three samples do not cover the shape variety.
Done right. The paper sets the threshold adaptively using test samples from new classes and shows the method finds a sweet spot that lets both classifiers contribute.
What a runnable demo should prove

What a runnable demo should prove

Without retraining, measure: (1) does the model still recognize the old objects (cars)? (2) does it now recognize the new object (vase)? Show that spread correctly identifies unfamiliar samples and routes them to shape matching.

The demo must make obvious that spread is the hinge: when you plot spread versus correct routing (did it pick the right classifier?), high spread samples should cluster on the shape-matching branch and low spread on the learned branch, with no retrained weights in between.
