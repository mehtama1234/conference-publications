Local Geometry Attention for Time Series Forecasting

A model learns question-specific distance metrics to preserve the shape of temporal data patterns and resist noise.

Paper explainersAll themesTime Series & Sequential

Transformer models (which look at all the data at once to predict what comes next) struggle with real-world time series data that has noise and gaps. This paper fixes that by teaching the model to remember what nearby points in time look like together (their shape and clustering) and adapt how it measures closeness between past moments for each new prediction question.

Zero assumption version

Transformers lose the shape of temporal data when noise strikes

A time series is a list of numbers over time (temperature readings, stock prices, sensor readings). The naive way to predict the next number: look at the recent history and return a weighted average of the last few values. That works for clean data, but in the real world, data comes with noise (a sudden spike, a missing reading, a bad sensor). When these glitches appear, the weights computed by a standard transformer scatter randomly, and the model forgets what the underlying pattern actually looks like.

The core failure: transformers compute attention scores (how much each past moment should matter) based on raw pixel-like similarity. But temporal patterns have a natural shape—nearby points should matter together, and that shape should stay consistent even when one reading is corrupted. Once corruption arrives, the model throws away that learned shape and recomputes from scratch, leading to wild swings in the forecast.

The problem in one sentence. Standard transformers recompute which past moments matter on every new question, losing the learned shape of temporal patterns when noise hits.

The algorithm as a flow

What it actually does

Learn a shape prototype

During training, the model observes many clean time series and learns what "nearby points together" looks like.

For each new prediction, generate a distance metric

The model takes the current question and outputs a custom distance function that measures closeness the way that question needs.

Compute attention using the custom metric

Instead of raw similarity, use the learned distance to decide which past moments matter; noisy outliers get low scores.

Aggregate using the filtered scores

Combine the past values using the attention scores; the clean shape of the pattern dominates, noise is suppressed.

Predict the next value

Output the forecast from the denoised, shape-preserving combination of past moments.

What the paper changes

The query-specific distance metric

The paper changes how the model computes closeness between past moments. Instead of using the same closeness rule for all predictions, it learns to build a custom distance rule for each question. This rule is grounded in Gaussian process theory (a mathematical model of how smooth, continuous data behaves), so it respects the natural smooth patterns in time series data.

the object it moves  =  distance metric per query
The hidden quantity

Pattern clustering: whether neighbors bunch together or scatter

measured quantity  =  pattern clustering signal

Pattern clustering measures how tightly nearby points huddle together. If you plot five consecutive time steps, they form a cloud: some might be close in value, others in slope, others in their rate of change. This local clustering carries information about what comes next.

The paper detects clustering by comparing each point to its neighbors using the learned distance rule. A high clustering signal means the neighbors bunch tightly (the shape is clear); a low signal means they scatter far apart (noise has corrupted the shape). By computing attention weights only from nearby points with high clustering signal, the model ignores corrupted outliers.

Why it works

Why query-specific distance rules preserve temporal shape

A transformer normally computes attention by taking the raw query value, comparing it to every past value using dot-product (a fixed way to measure similarity), and normalizing the results. But dot-product is a fixed distance rule that treats all directions in the data space equally, so it is blind to the actual shape of temporal patterns. When a single corrupted reading shoots far from the others, the dot-product attention reacts equally to that spike as to a legitimate pattern change.

This paper fixes this by making the distance rule adaptive. For each prediction question, the model outputs a learned distance function that weights the different directions of comparison differently. The training signal forces this function to weight the directions that preserve the true smooth pattern (value-similarity, slope-similarity, rate-of-change-similarity, depending on the data) and down-weight directions that are typically just noise (random spikes, single-value outliers). Once this rule is learned, it stays consistent even when new corrupted data arrives, because the rule was trained on clean data to recognize what a true smooth pattern looks like.

The payoff: attention scores computed with the learned rule automatically filter out noise. A spike that breaks the learned smooth pattern gets a low attention score, not because the model re-evaluated on the spot, but because the rule was already trained to distrust that direction. This is why accuracy stays high when noise hits: the model is not re-learning which points matter on every new forecast; it is reusing a rule trained to tell real patterns apart from corruption.

Math after the picture

The adaptive distance formula

First in words:

For each query, the attention score between the query and a past moment is the negative squared distance under the learned metric: M is a matrix (learned per query) that defines how to measure closeness, x_q is the query, and x_t is the past moment. Lower distance means higher attention score.

Then the compact form:

attention_score(q, t) = exp( -( (x_q - x_t)^T M_q (x_q - x_t) ) )

Every symbol:

M_qlearned distance rule matrix for query q
x_qthe query value (what we are trying to predict from)
x_ta past moment's value
(x_q - x_t)^T M_q (x_q - x_t)squared distance under the learned rule M
exp( - distance )convert distance into a weight; smaller distance means higher weight
A tiny worked example
Query asks: what comes after a rising trend? The learned rule upweights recent moments and values close to the trend line.
Past moment at t-1: value 10. Query trend suggests next value around 12. Raw distance from trend: 0.5.
Past moment at t-2: value 8. Same raw distance (0.5 from trend), but the rule down-weights older moments (multiplies by 1.5x penalty factor).
With the learned rule: penalty to t-1 is 0.5 × 0.9 = 0.45; penalty to t-2 is 0.5 × 1.5 = 0.75. Attention: t-1 gets exp(-0.45) ≈ 0.64, t-2 gets exp(-0.75) ≈ 0.47. Recent moment wins.
If a spike hits at t-3 (value 20, distance from trend = 8): rule applies a 3.0x penalty (spike-detection), distance becomes 8 × 3.0 = 24, attention exp(-24) ≈ 0, spike ignored.

The learned distance rule is a question-aware lens that emphasizes the directions in which the true pattern varies and suppresses the directions in which noise typically appears.

What can go wrong

What can go wrong

The rule overfits to training noise. If the training data has noise and the model is not gently guided to stay simple, the learned rule can accidentally memorize the noise pattern and treat it like signal. The model then fails on clean test data or new types of noise.
The rule assumes noise is random in all directions. The method works best when noise is random. If real corruption is structured (e.g. a sensor always reads high at morning hours), the rule learned from clean data will not anticipate it.
Pattern shift breaks the rule. If the time series pattern changes (a seasonal shift, a regime change in a stock market), the learned rule trained on old data no longer matches the new smooth pattern. The model loses accuracy on the new pattern.
Done right. Train the rule on data with simulated realistic noise (random noise drawn from the same kind the rule will see in production), test on held-out clean data, and retrain if the underlying pattern shifts.
What a runnable demo should prove

What a runnable demo should prove

Build a simple time series forecasting task: generate 100 values from a smooth curve (a sine wave plus a small trend). Split into train (70%), test (30%). Add 10 percent random noise to the test set only. Train a standard transformer and the paper's method side by side on the clean training data. Then evaluate both on the noisy test set and measure forecast accuracy using mean absolute error or mean squared error.

accuracy_gain = (error_standard_transformer - error_lga) / error_standard_transformer

The paper's method's forecast error should be noticeably smaller than the standard transformer's on noisy data, even though both were trained on clean data. The rule learned the shape of the curve and kept trusting it despite corruption.
