Scaling Laws of SignSGD in Linear Regression

SignSGD can learn faster per compute than normal gradient descent when data is noisy, because flipping the sign of gradients (instead of using their full size) reshapes how noise corrupts the learning path.

Paper explainersAll themesLearning Theory

Most machine learning trains by nudging weights based on how wrong the model was—the size and direction of each nudge comes from gradients. SignSGD uses only the sign (which way to nudge) and throws away the size. This is cheaper and faster because you only need to store and send one bit per gradient instead of 32 floating-point bits. This paper shows that when data is noisy, this crude move actually makes learning steeper and faster per unit of compute than the standard method, because the sign-based update reshapes how noise corrupts the learning path, making weak true signals more visible. The paper measures this using power-law scaling laws under realistic data.

Zero assumption version

Why does gradient size matter?

Normally, to train a model, you measure how wrong it is on a batch of examples. That error tells you both which direction to nudge the weights and how big the nudge should be. A small error means a tiny nudge; a big error means a big nudge. This makes intuitive sense: big mistakes deserve big fixes because when the model is far from the right answer, it needs a forceful correction to move back toward the truth.

But there is a hidden cost: storing and communicating the full size of each gradient (a list of numbers) takes up memory and communication bandwidth. In large-scale training, these numbers are huge.

Here is what a beginner might try: just ignore the size and send only the sign (positive or negative)—which way to nudge, not how much. This cuts bandwidth by orders of magnitude. But it sounds crazy: you are throwing away information. How can the model learn properly without knowing how wrong it was?

In one sentence. SignSGD reshapes how noise affects learning because weak noisy signals cannot survive small jabs of random garbage—the sign either flips or it does not—so using only the sign of gradients can actually train faster per compute than using the full gradient size, especially when data is noisy.

The algorithm as a flow

What it actually does

Step 1: Compute the gradient

Measure how wrong the model is on a batch of examples.

Step 2: Extract the sign

Replace each gradient value with just +1 or -1 (the direction, not the size).

Step 3: Multiply by a fixed step size

All updates use the same step size; there is no per-weight scaling.

Step 4: Update the weights

Move each weight in the direction indicated by the sign.

Step 5: Repeat for N steps

Do this for many training iterations on realistic data with power-law noise patterns.

What the paper changes

What changes: the gradient signal

SignSGD takes the gradient—the direction and size of each weight update—and cuts off the size, keeping only the direction (the sign). Every weight gets nudged the same distance, regardless of how wrong the model was. Instead of fifty different gradient values driving fifty different weight updates, you get fifty identical-magnitude updates, each pointing in the right or wrong direction.

the object it moves  =  gradient magnitude
The hidden quantity

The hidden quantity: noise reshaping

measured quantity  =  how noise corrupts the sign versus the size

In normal training, noise (random errors in the data) corrupts both the direction and the size of gradients equally. A noisy example might flip the sign of a weak gradient or exaggerate a strong one. SignSGD has a hidden advantage: because it uses only the sign, weak signals become either fully right or fully wrong—no in-between. This creates a sharp boundary: noise has to be loud enough to flip the sign completely, or it does nothing. Size-based gradients, by contrast, get a little bit corrupted by every noisy example.

The paper estimates this by decomposing the total loss into two parts: drift (the systematic error) and noise (the random corruption). In noisy regimes, the noise reshaping means SignSGD's noise term decays faster than SGD's because the sign is a harder target for small noise to change compared to a continuous value, so the compute-optimal scaling law becomes steeper.

Plain reading. Noise is like random dirt thrown at the learning process. In normal training, even tiny bits of dirt shift the gradient size. SignSGD is like a coin flip: noise either flips the coin or it does not, but small amounts of noise do nothing.
Paper reading. The risk decomposes as drift loss plus noise loss plus irreducible approximation error. For signSGD, the noise-dependent term decays as N^(−2τ2/(2−τ2)) where τ2 is the target decay exponent, while for SGD it decays as N^(−τ2). When τ2 is small (strong noise), the signSGD exponent is larger in absolute value, giving faster convergence because the stronger decay rate means the noise term shrinks more aggressively with each training step.
Why it works

Why it works: reshaping noise under power-law data

Real data does not have uniformly distributed noise. Instead, important features (images with clear objects, text with common words) are more common than edge cases. The paper models this as power-law decay: the importance of features drops following a power law (like a long tail), not uniformly. Under this realistic model, the paper analyzes what happens when you use only the sign of gradients.

The mechanism has two parts. First, drift normalization: because all weights move the same distance per step (just different directions), the collective "pull" on the weight vector is normalized differently than in standard gradient descent, which means the systematic learning path is shaped differently. Second, noise reshaping: when a gradient is small and noisy, using the sign means it either points the right way (and moves the weight) or the wrong way (and moves it the wrong direction). There is no fence-sitting with a size between zero and full. This makes weak-but-true signals stand out from the random junk, so learning accelerates in noisy regimes because the sign operation acts like a threshold—small noise cannot flip a strong signal, but size-based gradients get a tiny jab of corruption from every noisy example.

With a warmup-stable-decay schedule (warm up the learning rate slowly, hold it steady, then decay it down), the noise term shrinks further because the stable phase keeps step sizes just right, neither too aggressive nor too timid.

The scaling law formula

First in words:

loss equals a drift term depending on model size, training steps, and learning rate, plus a noise term that reshapes under signSGD, plus an irreducible approximation error.

Then the compact form:

R(M, N, γ_0) = D_drift(M, N, γ_0) + D_noise(M, N, γ_0) + ||H^(1/2) w_perp||^2

Every symbol:

R(M, N, γ_0)total loss after N training steps with model size M and learning rate γ_0
D_drift(M, N, γ_0)systematic error that decreases as you train and add more weights
D_noise(M, N, γ_0)random corruption from noise in the data; decays differently in signSGD than SGD
||H^(1/2) w_perp||^2irreducible error from the projection of the weight vector perpendicular to the feature space
Mnumber of trainable weights (model size)
Nnumber of training steps
γ_0learning rate (how big each step is)
HHessian matrix (curvature of the loss landscape)
A tiny worked example
Suppose model size M = 100 weights, training steps N = 1000, learning rate γ_0 = 0.01.
Drift loss (systematic): decays as 1/sqrt(M*N) roughly, so 1/sqrt(100*1000) = 1/1000 = 0.001.
Noise loss in normal SGD: decays as 1/N roughly, so 1/1000 = 0.001.
Noise loss in signSGD: decays faster in the exponent when target decay is strong, so perhaps 1/sqrt(N) = 1/sqrt(1000) ≈ 0.032 is replaced by 1/N^(3/4) ≈ 0.032 → 0.005 (much better in noisy regimes).
Total: signSGD gets lower noise loss when data is noisy, so it reaches lower total loss with fewer steps, hence steeper compute-optimal scaling.

The noise term in signSGD decays faster than in SGD because flipping a sign is less sensitive to small noise than scaling a gradient is.

What can go wrong

What can go wrong

Unstable with too-large learning rates. If the learning rate is too big, all weights move the same distance every step with no scaling down for weak gradients. This can cause oscillation or divergence. The paper identifies a maximal learning rate above which even the best choice of model size and step count cannot stabilize training.
Noise reshaping only helps when data is noisy. If the data is clean (low noise), the noise-reshaping advantage disappears. In those cases, regular SGD can match or beat signSGD because it uses the full gradient information. SignSGD shines only when the signal is buried in noise.
The analysis assumes linear models and power-law data. The paper studies linear regression with a specific random-feature model and power-law decay of features and targets. Real neural networks with nonlinear transformations (layers that apply functions like squashing the output to be between 0 and 1) are much more complex, and the noise-reshaping benefit may not hold.
Done right: choose learning rate and schedule carefully. The warmup-stable-decay schedule helps: start slow, hold steady in the middle, then decay. This keeps step sizes in the stable region and reduces the noise term further, making the compute-optimal slope even steeper, because the stable phase lets the learning rate sit in the sweet spot where noise sensitivity is minimized. The paper provides a table of optimal configurations for different feature and target decay settings (how fast the importance of features and targets drop off).
What a runnable demo should prove

What a runnable demo should prove

Build a linear regression model on synthetic data generated with power-law feature importance and target noise. Create three variants: (1) standard SGD with full gradients, (2) signSGD with constant learning rate, (3) signSGD with warmup-stable-decay schedule. Train each for 10000 steps on the same data. Plot the loss curve for each and measure the slope of each curve on a log-log scale (compute versus loss). SignSGD should have a steeper slope (log loss drops faster as you add compute) when the data is noisy because the sign operation reshapes noise, but only if the learning rate and schedule are tuned right so that the noise reshaping advantage actually kicks in. The constant-LR signSGD should be better than constant-LR SGD because it resists noise corruption better (fewer small jabs add up less than continuous corruption), and warmup-stable-decay should be better still because the stable phase locks the learning rate in the noise-minimum zone.

slope = log(loss_final) - log(loss_initial) / log(compute_final) - log(compute_initial)

The demo makes it impossible to ignore that under realistic (noisy) data, signSGD reaches lower loss with fewer compute steps than standard gradient descent because noise has a weaker grip on the sign than on the size, and a good schedule sharpens that advantage even more by sitting the learning rate in the zone of minimal noise sensitivity.
