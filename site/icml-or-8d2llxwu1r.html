Bootstrapped Exploration with Causal Reasoning: A Training Paradigm for Adaptive Forecasting Agent

A system learns to forecast diverse time series by exploring what works through contrast, then distills learned causal lessons into symbolic strategies that adapt to new datasets without human examples.

Paper explainersAll themesTime Series & Sequential

Time series forecasting—predicting patterns in changing data like stock prices or power demand—works well on the specific data it learned from, but fails when real-world conditions shift (prices rise for new reasons; equipment ages). Industry teams build custom forecasting pipelines tuned to each dataset. This paper shows how to train an agent to discover what works through trial-and-contrast, and to distill its discoveries into reusable strategy rules that adapt zero-shot (first-try, no new examples needed) to unseen datasets.

Zero assumption version

Why forecasting models fail in the wild

A time series forecaster—a model trained to predict the next values in a sequence—works great on data it learned from, but breaks when real-world conditions shift. Stock prices follow new patterns when interest rates change; power grids behave differently when solar farms turn on. A model trained on sunny-day power data will guess wrong on cloudy weeks.

Industry teams respond by building custom forecasting pipelines: they clean up missing values, split the data into trend plus noise, pick specialized model architectures, tune hyperparameters by hand. This engineering is slow and fragile. When the world changes in a new way (prices rise for new reasons; equipment ages), the whole pipeline may need retuning.

A naive approach would be to train one big model on all datasets together, learning a single set of weights. But this fails: datasets with opposite patterns (one trending up, one cycling down) interfere with each other. The weights that work for dataset A actively harm dataset B.

In one sentence. The paper teaches an agent to discover good forecasting strategies by exploring what works on diverse data and extracting causal lessons, so it can adapt to new datasets instantly without retraining.

The algorithm as a flow

What it actually does

Phase 1: Exploration on diverse training datasets

Agent tries many forecasting strategies (different models, imputation methods, hyperparameters) on multiple datasets, observing which approach works best for each.

Phase 2: Contrast-aware learning

For each dataset, the agent compares successful strategies with failed attempts. The gap between them (what was different?) reveals patterns.

Phase 3: Causal lesson extraction

Agent distills why each strategy worked: if high noise pushed one to succeed, the rule becomes 'high noise suggests this model'. If trend structure appeared before success, the rule notes that.

Phase 4: Symbolic strategy representation

Lessons become readable rules: dataset properties map to forecasting moves. These rules are symbolic (words + logic), not just learned weights.

Phase 5: Zero-shot deployment

On a new dataset, agent analyzes its properties, looks up its learned rules, picks the matching strategy, and forecasts—no retraining, no human examples.

What the paper changes

What the agent learns

The paper's core move: instead of learning to forecast directly (as most forecasting models do), the agent learns to choose strategies. It builds a mapping: detect dataset properties (signal-to-noise ratio, presence of trend, amount of missing data) and recommend a forecasting approach (model class, preprocessing). The weights it adjusts are not the forecasting model's weights but rather a meta-model that decides which forecasting strategy to deploy.

the object it moves  =  Strategy-selection rules
The hidden quantity

The strategy superiority signal

measured quantity  =  Contrast-aware success gap

The paper defines a hidden quantity: the success gap, which is the difference in forecast error between a successful strategy and the average of failed attempts on a given dataset. For example, if Strategy A forecast with error 8 but the average of failed strategies had error 22, the success gap is 14. The paper measures this gap because a large gap is evidence that the strategy solved the problem better than alternatives—the bigger the gap, the clearer the signal that this strategy is truly better and not just getting lucky.

The agent learns by comparing successful and failed forecasting runs on the same dataset. It asks: which dataset properties were present when this strategy succeeded but absent when it failed? The answers become causal lessons. For instance, if high-noise datasets consistently showed Strategy A with large gaps and low-noise datasets showed Strategy B with large gaps, the agent learns the rule: high noise predicts Strategy A will win.

Why it works

Why contrast extraction discovers causal rules

The core idea: if a strategy succeeded on one dataset but failed on another, something was different between them. The agent's job is to pinpoint what. By systematically noting which dataset properties correlate with each strategy's success, the agent inverts the relationship: dataset properties become signals for strategy selection.

Why does this work? Because success and failure are clear, observable outcomes. A strategy either forecasted well or poorly. By comparing only the highest-scoring strategy runs with low-scoring runs on the same data, noise is reduced—random flukes do not persist across multiple datasets. Over many datasets, the pattern becomes causal: 'datasets with trend structure consistently reward additive models; datasets with noise spikes consistently reward models that resist large outlier errors.' The agent distills these patterns into if-then rules.

The 'causal' part means the agent does not learn spurious correlations (coincidences). It learns only properties that repeatedly drive success or failure across multiple datasets. On a new dataset, applying those rules works because the underlying patterns generalize.

Math after the picture

Scoring strategy success and extracting lessons

First in words:

Lesson quality = average forecast error on successful strategy runs minus average error on failed runs, weighted by how many times the dataset property appeared in each group.

Then the compact form:

Lesson_score(P, S) = E[error | property P, strategy S succeeded] - E[error | property P, strategy S failed] * frequency(P)

Every symbol:

Lesson_score(P, S)how well property P predicts strategy S will succeed
Pa dataset property, such as 'high noise' or 'trend present'
Sa forecasting strategy, such as 'ARIMA with preprocessing'
E[error | ...]average prediction error when that condition holds
frequency(P)how often property P appears in the training datasets
A tiny worked example
Imagine two datasets: one noisy, one clean. On the noisy dataset, Strategy A (model that resists outlier errors) forecast error = 8; Strategy B (standard model) error = 22. Success gap = 22 - 8 = 14.
On the clean dataset, Strategy A error = 10; Strategy B error = 9. Success gap = 9 - 10 = -1 (Strategy B wins).
The agent concludes: high noise tips the success balance toward Strategy A. It records the rule: 'Detect high noise → choose Strategy A'. On a new noisy dataset, applying that rule works because the underlying pattern generalized.
Frequency: if high noise appeared in 40% of training datasets, that lesson counts as more reliable than one that appeared once.

The agent converts success patterns into if-then rules by learning which dataset features (noise, trend, missing data) co-occur with each strategy's wins.

What can go wrong

What can go wrong

Spurious dataset properties. If the training datasets happen to share an accidental pattern (e.g. all high-noise datasets also have missing values in the same columns), the agent may learn a false causal lesson. The rule fires on new data even though the real causal driver is different. Remedy: use diverse training datasets where dataset properties vary independently.
Limited strategy pool. The agent can only recommend strategies it tried during training. If a new dataset needs a strategy the agent never explored, it cannot invent one; it picks the closest learned rule and may forecast poorly. Remedy: include a diverse set of strategies in the training exploration phase.
Property detection errors. On a new dataset, the agent must accurately measure noise, trend, and missing-data rates to apply the right rule. If measurements are wrong (e.g. mistaking seasonal patterns for random variation), the selected strategy will be suboptimal. Remedy: measure dataset properties carefully with proven statistical methods.
Done right. When training datasets are diverse, exploration covers many strategies, and dataset properties are measured accurately, the learned rules transfer well and zero-shot forecasting works when conditions shift.
What a runnable demo should prove

What a runnable demo should prove

Build a script that (1) splits a collection of diverse time series datasets into training (80%) and held-out test (20%); (2) on training datasets, runs the exploration phase: try 5–10 forecasting strategies on each, recording which strategies win and which dataset properties are present; (3) extracts lessons: for each dataset property, count how many times each strategy won when that property was present versus absent; (4) on held-out test datasets, measures the new series' dataset properties (noise level via autocorrelation, trend via linear regression slope, missing-data percentage), looks up the learned rule for that property combination, applies the matched strategy, and forecasts; (5) reports zero-shot forecast error on test datasets and compares to a baseline that always picks the same strategy regardless of data properties.

zero_shot_accuracy = forecast_error(new_data, learned_rule_strategy) / forecast_error(new_data, naive_always_same_strategy)

The demo's core outcome: the agent-learned rules should forecast on new datasets nearly as well as a hand-tuned pipeline, with no retraining cost—proving that contrast-aware exploration truly extracts transferable causal strategies.
