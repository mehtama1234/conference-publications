Neural Multi-Objective Routing on Multigraphs

A neural network learns to pick the right edge among many parallel options when optimizing several competing goals at once on a network.

Paper explainersAll themesGraph & Geometric Learning

Real-world routes often involve trade-offs: a delivery truck wants to minimize time and fuel cost, which require different paths. Standard routing algorithms assume one cost per edge, but in practice there are multiple possible edges between the same two places, each with different speed, toll, or distance. This paper shows how to train a neural network to learn which edge to choose when balancing multiple competing goals on such multigraphs (networks with parallel edges).

The world before this paper

Routing is finding the best path through a network. In real life, a path is not unique: from city A to city B there might be a highway, a back road, and a toll route, each with different costs (time, fuel, toll). Standard routing methods treat each city-pair as having only one edge (one cost). They ignore the fact that you have a choice.

When optimizing for multiple goals (fast delivery and low cost), the problem gets harder: which edge serves the first goal best? Which serves the second? A naive extension of single-objective methods just adds up the two costs, but this fails because the best edge for one goal may be worst for the other. There is no single obvious choice without understanding the trade-offs.

The method in one sentence. A neural network learns to read the network structure and the trade-off between goals, then decides which edge to pick at each step of building a route.

The algorithm as a flow

What it actually does

Encode the multigraph

A graph neural network reads the network structure (nodes, all parallel edges, their costs) once.

Set a trade-off preference

The network is told whether to prioritize time or cost (a knob between 0 and 1 for each goal).

Score each edge

At each step, the network scores every edge leaving the current node under the current goal.

Pick the top edge

The route greedily picks the edge with the highest score; mark it visited.

Repeat until a complete route

Continue stepping through the network, always picking the highest-scored available edge, until a tour closes.

What the paper changes

What the paper changes

The paper trains a neural network to predict which edge to pick at each step. The thing being changed is the edge selection decision: instead of using a fixed heuristic (e.g., always pick the shortest) or adding costs together (which fails for multi-objective), the network learns a scoring function that ranks edges based on the network structure and the stated goal.

the object it moves  =  Edge ranking function
The hidden quantity

The hidden quantity: Edge importance under each goal

measured quantity  =  Goal-aware edge utility

A hidden quantity the paper measures is how valuable each edge is for achieving a given objective. An edge might be valuable (short travel time) for one goal but useless (expensive) for another. The network must infer this without being explicitly told.

The paper estimates this by running the graph neural network backward through many training runs. During training, the network is given real routes and the goals they optimized for, and it learns which edges appear in good solutions for each goal. This learned pattern becomes the scoring function used at test time.

Why it works

Why the method works

The core mechanism is that the neural network learns to read two things at once: the network structure (what edges exist and their costs) and the goal you are pursuing (the relative importance of time vs cost). At each node, it scores every outgoing edge by asking: given the network, the costs, and this goal, how good is this edge for reaching the finish line optimally?

This works because the network can learn patterns the hand-written heuristics miss. A toll road might be expensive (bad for cost goals) but so fast that it saves fuel by going faster (good for combined goals). A neural network can learn this interaction by seeing many examples of good routes and bad routes. In contrast, a naive method that simply adds the costs together cannot discover such trade-offs.

The second variant (which is faster) uses a two-stage approach: first, prune the multigraph down to a simple graph by learning which parallel edges are redundant, then route on the simpler graph. This is quicker because the routing step is faster on fewer edges, and the pruning is learned, so it adapts to the goal.

How the learned scoring works

First in words:

During training, the network learns by trying random routes and checking their quality. For a given goal preference (a weight list called lambda), a route's quality is the worst-case deviation from perfect on any objective. The network adjusts its weights to maximize this quality score.

Then the compact form:

R_lambda(pi) = -max_i { lambda_i * |f_i(pi) - z_i^*| }

Every symbol:

R_lambda(pi)Quality score of route pi under goal lambda (higher is better)
lambda_iHow much to prioritize objective i (0 to 1)
f_i(pi)Actual cost of route pi on objective i
z_i^*Ideal cost on objective i (known or approximated)
max_i {...}The worst-case gap (bottleneck goal that loses most quality)
A tiny worked example
Goal: equal weight on time (lambda_time=0.5) and cost (lambda_cost=0.5).
Route A: time=100 min (ideal 50), cost=2 dollars (ideal 1).
Quality = -(max of [0.5*|100-50|, 0.5*|2-1|]) = -(max of [25, 0.5]) = -25.
Route B: time=65 min, cost=1.8 dollars.
Quality = -(max of [0.5*|65-50|, 0.5*|1.8-1|]) = -(max of [7.5, 0.4]) = -7.5.
Route B is much better (higher quality = less negative). Network learns to make routes like B rank high.

The network learns an edge-scoring function that, when applied greedily at each step, tends to produce routes with high quality scores across all goals simultaneously.

What can go wrong

What can go wrong

Overfitting to training graphs. If the network sees only a few graph types during training, it may fail on new graph shapes. Real routes are always changing.
Edge case: no good middle ground. If two goals truly conflict (e.g., fastest route is always most expensive), the network can only pick one. It cannot invent a non-existent middle path.
Computation scales with graph size. Encoding a very large multigraph requires many neural operations. The pruning variant helps, because dropping redundant edges shrinks the graph before the expensive routing step, but even on the simplified graph, processing millions of nodes or edges still takes significant time.
Done right: testing on diverse graphs. Training on a mix of random, real-world, and adversarial graph structures teaches the network to handle new routing problems it has never seen before.
What a runnable demo should prove

What a runnable demo should prove

Build a simple delivery problem: five cities in a grid, three route options between each pair (fast/expensive, slow/cheap, balanced). Define two objectives: minimize total travel time and minimize total fuel cost. Train a neural router on 1000 random preference weights. Then test on a held-out set of 100 new preferences and graph layouts. Measure how often the neural router beats a naive baseline (add the costs together) on both objectives simultaneously.

Success = percent of test cases where neural router achieves better quality on both objectives than naive baseline

The demo must show that the neural network adapts its edge choices based on the goal; when time matters more, it picks fast edges even if expensive; when cost matters, it picks cheap even if slow.
