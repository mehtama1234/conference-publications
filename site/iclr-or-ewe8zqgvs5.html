Cortical Policy: Dual-Stream View Transformer for Robotic Manipulation

A robot learns to manipulate objects better by combining two separate brains: one that understands 3D space, another that predicts where to look.

Paper explainersAll themesRobotics & Control

Robots that perform manipulation tasks see the world through multiple cameras (top, front, side). Most methods treat each camera view as separate images and mix the results, which fails to understand how the 3D world actually looks the same from different angles. This paper builds a robot controller with two parallel processes: one that enforces that features look consistent across views in 3D space, and another that learns where the robot should look, copying how the human brain has separate systems for understanding space and deciding where to focus visual resources for action.

Zero assumption version

Multiple cameras, but no shared 3D understanding

A robotic arm manipulating objects sees the scene from several camera angles: looking down from above, straight ahead, and from the side. Each camera captures a 2D image of the same 3D world.

Existing methods extract features (lists of numbers representing what the network sees) from each camera view separately, then combine them to predict the robot's action. But they miss something important: the same object corner appears in multiple images, and its features should be aligned to the same 3D location. Without this constraint, the network can extract contradictory features for the same real-world point from different views.

A beginner might try: just average the features from all views. This fails because views show different parts of the scene — averaging erases the spatial structure that tells the robot where each object actually is.

In one sentence. Use two separate pipelines: one that forces features from different camera views to match up in 3D space, another that learns where to look, then fuse them for action.

The algorithm as a flow

What it actually does

Step 1: Capture multi-view RGB

Robot records images from three camera angles simultaneously.

Step 2: Static stream enforces geometric alignment

Extract features from each view; a pretrained 3D reconstruction model (VGGT) identifies corresponding keypoints across views; a loss function (SmoothAP) penalizes mismatches in 3D space.

Step 3: Dynamic stream predicts attention

A pretrained gaze model (GLC, trained on human first-person video) learns which image regions matter for the current task; fine-tuned on robot video.

Step 4: Fuse representations

Concatenate spatially-aligned features from static stream with attention-weighted features from dynamic stream.

Step 5: Decode to action

Transformer-based action head turns fused features into robot commands: end-effector position, rotation, gripper open/close.

What the paper changes

The feature representations fed to the action decoder

The paper changes what goes into the part of the network that predicts robot actions. Instead of independently-extracted view features, Cortical Policy supplies two aligned streams: one that enforces consistency across views in 3D space (static), one that weights attention based on learned gaze patterns (dynamic).

The hidden quantity

Cross-view geometric consistency: how much features align in 3D

measured quantity  =  Geometric consistency score

The paper measures how well features from different camera views agree on where the same real-world point is located. If a corner of an object appears in the top-down view and the front view, a geometrically-consistent network extracts similar features for that corner in both images, because it understands that both are the same place in 3D.

The method estimates this using a pretrained 3D model (VGGT) that identifies 3D keypoints (landmark positions) in the scene. When the same keypoint is visible in multiple views, the paper penalizes the feature extractor if the learned features for that keypoint disagree across views. The SmoothAP loss function computes this penalty by ranking which features are most similar (the ones from the same 3D location should rank highest).

Why it works

Why dual-stream design solves the 3D reasoning problem

The problem: A robot learning to grasp needs two kinds of understanding. First, where things are in 3D (the cup is 10 cm to the left, 5 cm forward). Second, what to pay attention to (the handle is the part that matters for grasping). Existing methods mix these concerns — they extract features that are neither consistently spatial nor properly attentive.

The mechanism: Cortical Policy separates the labor into two streams, each optimized for its job. The static-view stream uses a pretrained 3D model to enforce that features from all angles agree on where objects are, creating a shared 3D mental model. This alignment is mandatory — a loss function punishes any disagreement. The dynamic-view stream learns from human gaze videos where people actually look when manipulating objects; it fine-tunes this on robot video to predict which image regions are action-relevant. When training the robot action decoder, both streams provide their features in parallel. The static stream ensures the spatial information is reliable (you know where the object is). The dynamic stream ensures attention is focused on what matters (you know what to do about it). Fusing them gives the action decoder both: solid location-mapping and focused attention.

Why this works: By separating location-mapping (understanding where things are in space) from gaze prediction (learning where to look), each stream can be optimized independently without conflicting goals. The static stream does not have to learn where to look (that is the dynamic stream's job); it can focus on making sure locations map correctly from image to 3D space. The dynamic stream does not have to reconstruct perfect 3D locations; it learns patterns of human attention transfer. The result: more reliable action prediction on complex manipulation under language conditions, because the network has two independent, complementary sources of signal.

Math after the picture

The training loss that enforces geometric consistency

First in words:

Total loss equals the action prediction error plus a weight times the geometric consistency error

Then the compact form:

L = L_action + lambda * L_cgc

Every symbol:

Ltotal training loss (lower is better)
L_actionerror in predicted action (position, rotation, grasp)
L_cgccross-view geometric consistency error (how much features disagree on 3D location)
lambdaweight that balances action accuracy against geometric consistency
A tiny worked example
Suppose L_action = 2.0 (robot action was off by a bit) and L_cgc = 0.5 (features agree on 3D location fairly well).
If lambda = 1.0 (equal importance), then L = 2.0 + 1.0 * 0.5 = 2.5.
If lambda = 2.0 (emphasize 3D alignment more), then L = 2.0 + 2.0 * 0.5 = 3.0 — training pulls harder to fix the 3D alignment.
The paper fixes lambda = 1.0, treating action accuracy and geometric consistency equally.

This formula makes the network learn actions that are both accurate and geometrically sensible across multiple camera views.

What can go wrong

What can go wrong

Missing keypoints in a view. If a 3D object corner is occluded (hidden) in one camera view, the pretrained 3D model (VGGT) cannot detect it, so geometric consistency cannot be enforced for that point. The static stream degrades.
Gaze model bias from human training. The dynamic-view stream is pretrained on human egocentric gaze videos. If human gaze patterns (where a person looks when grasping) do not match robot-optimal attention (where the robot should look for accurate control), the dynamic stream may misdirect.
Computational cost of dual streams. Running two parallel streams (static extraction, VGGT keypoint detection, dynamic gaze model, then fusion) is more expensive than a single view mixer. On resource-constrained robots, this may be prohibitive.
Done right. When keypoints are visible, gaze patterns are accurate, and compute budget allows, Cortical Policy achieves strong real-world manipulation by combining stable 3D reasoning with learned attention.
What a runnable demo should prove

What a runnable demo should prove

Build a simple robot manipulation scenario: a tabletop with three colored blocks and a gripper. Train a baseline (single-stream view mixer) and Cortical Policy (dual-stream) on 20 demonstrations of moving blocks from pile-A to pile-B from three camera angles. Run each trained policy on 10 unseen configurations of the blocks (different layout, different lighting, different gripper angle). Measure success: did the gripper end up at the right position (within 2 cm) without tipping the blocks?

Success rate = (trials where final position is within 2 cm of target) / (total trials)

Cortical Policy should achieve >75% success; the baseline should achieve <60%. The difference shows that the method works because enforcing features to align across views in 3D space lets the network locate objects accurately (reducing position errors), and learning where to look from gaze patterns steers the network toward action-relevant features like handles (reducing wrong-part grasps). Together, these two mechanisms eliminate the baseline's primary failure modes.
