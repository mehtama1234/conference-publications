A Pair-wise Progress Critic Model for Robot Manipulation

A robot model learns to judge task progress by comparing two moments in time, giving itself reliable feedback during learning.

Paper explainersAll themesRobotics & Control

Robots struggle to improve in unpredictable real-world tasks because they lack good feedback telling them whether they are making progress. This paper proposes VLAC, a single model that both decides actions for the robot AND measures how much progress the robot has made, by looking at pairs of moments in a trajectory and predicting the change in progress between them.

Zero assumption version

The robot feedback bottleneck

A robot learns to manipulate objects by trial and error. Each time it tries an action, the robot observes what happens and records which actions worked or failed — this record guides future attempts. But here is the bottleneck: the robot needs constant, reliable feedback telling it whether it is making progress toward the goal. A robot grasping a bottle does not know if it has gripped tighter until it feels the result.

A naive first approach is to hand-code feedback signals — tell the robot upfront which measurements count as progress (distance to goal, force applied, object position). But this breaks in the real world: new tasks appear that were never coded for, environments change unpredictably, and humans never defined what progress looks like for that specific scene. The robot is blind without pre-written feedback rules.

In one sentence. The robot learns to measure its own progress by comparing before-and-after moments, so it can autonomously grade its attempts and improve.

The algorithm as a flow

What it actually does

Step 1: Capture pairs

During each robot attempt, save a snapshot of the scene before and after each action.

Step 2: Feed to critic

Pass both snapshots to VLAC, a single model trained to predict progress between any two moments.

Step 3: Output progress delta

VLAC outputs a number: how much the task state moved toward the goal.

Step 4: Use as reward

This progress score becomes the reward signal in reinforcement learning, guiding which actions to repeat.

Step 5: Close the loop

As the robot improves and visits new states, VLAC scores those state-pairs too; the learning algorithm converges faster because it gets dense feedback every step.

What the paper changes

What the paper changes

Instead of hand-writing task-specific reward functions, VLAC learns a single model that predicts how much progress any two observations represent. This one learned model works on unseen tasks and different robots because it never saw feedback rules written by humans — it learned from watching pairs of states and inferring their progress difference.

The hidden quantity

The hidden quantity: task progress delta

measured quantity  =  Progress delta (change in progress between two moments)

This is the single number that tells you how much closer to the goal the robot has moved. Before this paper, measuring progress required hand-coded domain knowledge for each task. VLAC learns to infer this number directly by comparing two observations using visual and action information.

The paper estimates progress delta by training a model on pairs of trajectory frames (a moment early in an attempt, a moment later) and asking it to predict: how much did the task progress? This is paired comparison rather than absolute measurement, which is easier because the model only needs to judge relative difference, not define a global success metric.

Why it works

Why comparing two moments works better than absolute scoring

Measuring absolute progress is hard because every task has a different definition of success. But comparing two snapshots is easier: the model only has to decide which one is further along, not define a global target. This is why pair-wise comparison generalizes to unseen task types and robot body designs — the model never memorized task-specific rules, only learned to spot movement toward goals.

During learning, the robot collects trajectories of its attempts (successful and failed). For each trajectory, VLAC sees pairs of consecutive or nearby observations and learns to predict which direction represents progress. By training on mixed data (human demonstrations, robot trials, and general vision-language examples), VLAC internalizes a general pattern: what actions look like when they move a task forward. When learning a new task, the robot executes actions, VLAC scores each pair of states by checking if they match the progress pattern it learned, and the learning algorithm steers toward actions that accumulate positive progress deltas. Each time the robot acts and VLAC scores the result, the learning algorithm remembers: this action received a high score, so I should repeat it. Low-scoring actions are forgotten. Dense reward (a score after every step) lets the learning algorithm correct course immediately, while sparse reward (only a signal at task end) leaves the robot lost for long stretches with no guidance.

Math after the picture

Pair-wise progress scoring

First in words:

Progress delta = model output when comparing state-before and state-after plus the action taken, learned by minimizing error against labels of how much progress was actually made.

Then the compact form:

delta_progress = VLAC(obs_t, obs_t+k, action) ; loss = mean((delta_progress - progress_label)^2)

Every symbol:

VLAC(obs_t, obs_t+k, action)The model output: predicted progress change between observation at time t and time t+k given the action
obs_tObservation (image and sensor data) at the start moment
obs_t+kObservation at a later moment (k steps forward)
actionThe action(s) taken between the two moments
progress_labelGround truth: how much progress was actually made (from human annotation or task metric)
lossError to minimize during training
A tiny worked example
Suppose a robot is grasping a mug. VLAC sees two images 1 second apart and the action 'close gripper'.
Before: mug is 10 cm from gripper. After: mug is 3 cm from gripper. Progress = 70% closer (label = 0.7).
VLAC predicts delta_progress = 0.68. Error = (0.68 - 0.7)^2 = 0.0004. Tiny loss, model is learning well.
On a different attempt: Before at 10 cm, after at 9.5 cm (barely moved). VLAC predicts 0.05, label is 0.05. Again correct, no loss.

The model trains by watching pairs of states and comparing its predicted progress to the true progress made, so it learns the recurring patterns of what forward-motion in a task looks like.

What can go wrong

What can go wrong

Progress labels are noisy. If humans annotate which trajectory pairs represent real progress, their judgments may be inconsistent or wrong. VLAC trains on these labels, so poor labels degrade the learned signal.
State-space mismatch. If VLAC is trained on kitchen manipulation data but deployed on assembly tasks, the visual scenes and sensor readings differ sharply. Pair comparisons on states far from the training data may be unreliable.
Sparse progress in hard tasks. Some tasks have long action sequences with no visible progress until the very end. VLAC struggles to provide dense rewards mid-attempt, making learning slow.
Done right. Train VLAC on diverse, multi-source trajectory data (human, robot, simulation). Validate on held-out task families before deployment. Use VLAC for dense reward shaping, not as the sole learning signal.
What a runnable demo should prove

What a runnable demo should prove

Build a simulation environment (e.g., pick-and-place or pushing a block to a goal). Train VLAC on 50 successful and 50 failed human-demonstration trajectory pairs, labelling each with ground-truth progress (distance reduced). Then run a reinforcement learning agent that uses VLAC-predicted progress deltas as its reward signal. Compare final task success rate against an agent that receives no reward or a naive distance-based reward. The demo should show that VLAC-guided learning reaches 60%+ success on the training task, and transfer to a visually different task (e.g., new object, new workspace) with at least 50% success.

Task success rate = (number of attempts that reach goal) / (total attempts)

The demo proves that a model trained to recognize progress patterns from data outperforms hand-coded rewards on unseen tasks, because the learned model captures general principles of forward motion while hard-coded rules are frozen to one scenario.
