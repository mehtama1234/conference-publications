InfGen: Traffic Scenarios as Token Sequences

Generate infinite, realistic traffic scenarios by predicting traffic states one step at a time, like a language model generates words.

Paper explainersAll themesRobotics & Control

Realistic traffic simulation is hard: existing systems replay recorded data or hold the number of cars fixed. InfGen treats the entire traffic scene—every car's position, every traffic light, every motion—as a sequence of tokens and uses a neural network (one that reads sequences and predicts what comes next) to guess the next token, step by step. This way it can endlessly add new cars and simulate infinitely long scenarios with behavior that looks real and stays diverse.

Zero assumption version

Why old traffic simulators get stuck

Today's autonomous driving systems train on replayed real-world trips or on hand-scripted scenes with a fixed number of cars. The moment the test puts a car in a new situation—say, a highway with more traffic than the training set showed—the driving system fails because it has never learned to handle such a world.

A beginner might try to just run the replay backward, or add random noise to recorded data. That fails because replayed data does not create new, realistic scenarios; noise alone does not capture how real traffic agents actually interact—one car braking causes nearby cars to brake too, in a cascade that needs deep cause-and-effect, not random jitter.

The core problem: static scene snapshots or fixed replay loops cannot grow to handle evolving agents (new cars arriving dynamically), and they cannot generate completely new scenes that still feel real and follow traffic laws.

The method in one sentence. Represent the traffic scene as a long list of tokens (numbers representing car positions, velocities, traffic lights), then train a neural network to predict what the next token will be, over and over, generating fresh scenarios token by token.

The algorithm as a flow

What it actually does

Convert the scene to tokens

Write every car's position, velocity, and every traffic light as numbers in a long list.

Train the model to predict the next token

Show the model the first 20 tokens; teach it to guess token 21. Repeat for the whole dataset.

Seed the generator with a short scene

Start with the first few tokens (a few cars, the current lights, initial velocities).

Loop: predict, append, predict

Ask the model what comes next; add that token to the sequence; ask again.

New cars arrive when the model predicts them

Tokens can represent 'a new car enters from the right at this velocity'; the model places them naturally as it learns the data patterns.

What the paper changes

The one thing this paper changes

InfGen moves from storing and replaying fixed scenarios to learning a machine that predicts traffic one step at a time. The object is the way scenarios are generated: from playback to step-by-step prediction.

the object it moves  =  scenario generation method
The hidden quantity

The hidden quantity: predicted validity

measured quantity  =  how likely each next scene state is

The paper measures something called the model's prediction confidence—how sure the model is that the next token it predicts is the right one, given everything that came before. When the model is certain about what should happen next, it means it has learned a strong pattern from the training data (like 'if traffic light is red, cars slow down'). When the model is uncertain, it means the situation is rare or ambiguous.

The paper estimates this by training the model on real traffic data and checking how often the model's top prediction matches the actual next token in the recorded data (called accuracy). A model that predicts the next token correctly 85% of the time has absorbed the real traffic patterns well.

Why it works

Why one-at-a-time prediction captures realistic traffic

Language models work because human language has structure: 'Once upon' almost always comes next as 'a time', and the model learns this from reading millions of sentences. Traffic has the same property: if three cars are bunched at a red light, the next frame will show them slowing or holding still—the transformer learns these cause-and-effect chains from real driving logs.

By predicting one token at a time, the model builds in causality automatically. It sees 'car-A at speed 30 in lane 1' followed by 'car-B (just behind) slows to 28 in lane 1 one frame later', and it learns the pattern 'nearby cars influence each other'. When generating, the model applies this pattern: every newly predicted token is constrained by what came before, so wild, unrealistic jumps (a car teleporting) become vanishingly unlikely.

Infiniteness comes free: the loop never stops. After predicting token 100, the model uses tokens 81-100 to predict token 101, then uses tokens 82-101 to predict token 102. If the model's predictions include a 'new car enters' token, that car is born into the ongoing simulation and interacts with existing cars, creating complex multi-agent dynamics from pure learned patterns.

Math after the picture

The prediction equation

First in words:

probability of the next token equals the model output at that position, given all previous tokens in the sequence

Then the compact form:

P(token_t | token_1, ..., token_{t-1}) = softmax(model_output_at_position_t)

Every symbol:

token_tthe traffic state at step t (position, velocity, light)
token_1, ..., token_{t-1}all previous steps in the sequence
model_output_at_position_tthe model's internal scores for each possible next token
softmaxa function that converts raw scores into percentages that add to 100%
A tiny worked example
Suppose the sequence is: [car-A at x=50, car-B at x=60, car-B speed=20, light=red].
The model scores the top 3 candidates for the next token:
'car-A speed drops to 18' scores 8.0
'car-A stays at 20' scores 2.0
'car-A accelerates to 22' scores 0.1
softmax( [8.0, 2.0, 0.1] ) = [0.965, 0.033, 0.002]
The model predicts 96.5% chance the car slows (learned: red light → decelerate).
The generator rolls the dice: with 96.5% odds, it picks token 1 (car slows).

The transformer learns to assign high probability to realistic continuations and low probability to impossible ones, so generation follows real traffic rules.

What can go wrong

What can go wrong

The model learns biases in the training data. If all recorded trips avoid left turns at intersections, the generated scenarios will too. The model copies patterns, not reality.
Long sequences lose fidelity. After 500 predicted tokens, small errors accumulate. A car's position drifts slightly at each step; after a minute of simulation, physics no longer match reality.
The transformer is slow to sample from. Generating one scenario token by token is slower than replaying a video. Real-time training needs fast simulation.
Done right. Train on large, diverse logs (not just sunny highways). Validate generated scenarios against real-world metrics (speed distributions, collision counts). Use short-horizon generation (next 30 seconds) for testing, not five minutes.
What a runnable demo should prove

What a runnable demo should prove

Build a simple traffic scene generator: represent 3 cars (position, velocity, stopping) as tokens. Train a small transformer on 1000 recorded 30-second clips. Seed it with 'car-A at x=0 vel=10, car-B at x=20 vel=8, car-C at x=50 vel=12, light=green'. Generate 50 steps (about 5 seconds of simulation). Plot the trajectories and check: (a) cars slow when a car ahead slows, (b) new tokens (car-D arriving) appear at plausible speeds, (c) the light changes realistically.

realism = (fraction of car-following obeys physics) + (collisions per 1000 steps) + (new-agent arrival rate matches training mean)

The demo makes it impossible to miss that the model learned a model of traffic dynamics from the data itself. When the generator never produces a 200-mph car or a teleport, it proves the learned probabilities enforced physical plausibility, because the model assigned near-zero likelihood to physics-violating tokens during training.
