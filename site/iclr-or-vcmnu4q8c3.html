Adaptive Conformal Prediction via Mixture-of-Experts Gating

Use a model's own gating decisions to weight which past examples are most relevant when building prediction intervals, so intervals get tighter without losing honesty.

Paper explainersAll themesRepresentation & Self-Supervised Learning

A prediction interval is a range around a model's answer: instead of guessing a single number, it says, point estimate plus or minus some margin. Conformal prediction is a technique that builds these intervals with a mathematical guarantee: cover the true answer at least 90% of the time (or whatever coverage target you set). But standard conformal methods treat all data the same way. When your data has hidden subgroups (images of cats and images of dogs, or loan applications from different regions), a one-size-fits-all interval wastes room—it has to be huge to cover both groups fairly. This paper learns to recognize when test data is similar to certain calibration data, and weights those similar examples more heavily when building the interval. The result: tighter, honest intervals that adapt to different subgroups without requiring labels that say what the subgroups are.

Zero assumption version

One-size-fits-all prediction ranges don't adapt to different data

When you train a machine learning model on mixed data—images of different animals, or loans from different countries—the data itself is secretly divided into clusters. Some parts are easy: the model knows what to do and is confident. Other parts are hard: the model is unsure. A naive approach builds prediction intervals by asking, how far off was the model on past data? It takes the biggest mistakes and makes the interval wide enough to cover them. This works mathematically (it meets the coverage target), but it makes intervals enormous because it has to be safe for the hardest cases, even when the test case is actually close to an easy, well-understood cluster.

The beginner tries: build one interval width for everything. It works—it covers the right fraction of answers—but the intervals are bloated. On easy examples (where the model is confident and accurate), the range is still huge. On hard examples, it is tight but sometimes still misses. There is no adaptation.

The method in one sentence. The paper learns which past examples are most similar to the test case (by looking at the model's own gating signals) and uses those similar examples to build a narrower, adapted interval.

The algorithm as a flow

What it actually does

Train mixture-of-experts model

Model learns to route inputs to different expert sub-networks; gating produces soft assignment (a probability-like score for each expert).

Collect calibration data

Run the trained model on hold-out examples, record each input's gating scores (which experts were trusted) and the model's prediction error.

Measure similarity between inputs

For a new test input, compare how similar its gating scores (expert weights) are to each calibration example's gating scores using a standard distance metric.

Weight calibration errors by similarity

Higher similarity means higher weight; take a weighted quantile of the calibration errors—this is the interval margin for this test case.

Build adapted interval

Center is the model's prediction; radius is the weighted quantile; interval adapts per test case while staying mathematically honest.

What the paper changes

What the paper changes

Standard conformal prediction gives all calibration examples equal weight when building the interval margin. This paper instead weights each calibration example by how similar its gating scores are to the test case's gating scores (a gating score is a list of numbers saying how much the model trusts each expert). The same gating network that the model already uses to route inputs is repurposed to signal which past examples are most relevant.

the object it moves  =  Weighting of calibration errors
The hidden quantity

The gating similarity score

measured quantity  =  Similarity between gating scores

The gating vector is a list of numbers (one per expert in the mixture-of-experts model) that says how much the model trusted each expert. For example: expert 1 gets 70% of the routing, expert 2 gets 20%, expert 3 gets 10%. This vector is already computed by the model during inference (when it answers a new question). The paper measures how similar two gating vectors are by checking their alignment—how much they overlap in which experts they trust. Two inputs with very similar gating vectors were handled by the model in very similar ways, so their mistakes are more relevant to each other.

The paper uses this gating similarity as a weighting scheme: if a calibration example has a gating vector very close to the test case's, give its error a high weight when computing the interval margin. If it is far away, give it a low weight. This is how the method learns which past examples are most relevant without needing explicit subgroup labels.

Why it works

Why weighting by gating similarity makes intervals tighter and honest

Conformal prediction builds an interval by asking: what is the smallest radius R such that center±R covers at least 90% of true answers (or your chosen coverage level)? Mathematically, it sorts all past mistakes from smallest to largest, then picks the 90th percentile. Standard conformal gives each past mistake equal weight, so it picks the actual 90th percentile value.

When you weight by similarity instead, you are asking: what is the smallest radius such that, for inputs similar to this test case, the interval covers 90% of similar answers? Calibration examples with high gating similarity are given higher weight in the quantile calculation. The weighted 90th percentile is now lower (tighter) because the method is only promising coverage over the similar subgroup, not over all data. Critically, the math still works: the coverage guarantee holds for the population the model learned to represent that way. You get a tighter interval because you are matching the test case to examples the model itself thinks are similar—the model's own routing decision becomes the adaptation mechanism. A test case routed mostly to expert 1 will lean on calibration examples also routed to expert 1, where the model's performance is better understood, because the model specializes: when training, expert 1 saw lots of examples of one type (say, dogs), learned to predict them well, and the router learned to send dog images to expert 1. So past calibration examples the model routed to expert 1, like the test case, had similar characteristics and similar error patterns.

This works only if the gating vectors actually capture real domain structure. If all experts see the same data equally, gating similarity is meaningless and the method degrades to standard conformal. But in multimodal data (cats and dogs, different countries), the model learns to specialize—expert 1 becomes good at cats, expert 2 at dogs—and the gating captures that. Testing on real datasets shows this holds.

Math after the picture

The weighted quantile formula

First in words:

interval margin = weighted quantile of errors, where weight of each error is the similarity between test gating and calibration gating

Then the compact form:

R_test = Quantile_{alpha}({error_i : i in calibration}, weights={sim(g_test, g_i)})

Every symbol:

R_testthe interval margin (radius) for this test case
alphathe coverage level (e.g., 0.1 for 90% coverage)
error_ithe magnitude of mistake i in calibration (prediction - true value)
sim(g_test, g_i)similarity between test gating vector and calibration example i gating vector; typically cosine similarity
Quantile_alphathe level at which we cut off when we sort the errors from smallest to largest, weighted by sim
A tiny worked example
Suppose test case has gating vector [0.8, 0.1, 0.1] (80% expert 1, 10% each for others).
Calibration example A has gating [0.75, 0.15, 0.1]: error = 2.5. Similarity (cosine) ≈ 0.99 (very close). Weight ≈ 0.99.
Calibration example B has gating [0.1, 0.8, 0.1]: error = 1.8. Similarity ≈ 0.15 (far away). Weight ≈ 0.15.
When sorting to find the 90th percentile, example A (which says we expect errors around 2.5 for this routing) counts as 0.99 votes, example B (which saw a different routing) counts as 0.15 votes.
Result: the margin leans toward example A, giving a tighter interval for this routing pattern.

The method computes a weighted percentile using the model's own gating distance as the weight, so inputs that follow similar routing patterns get intervals calibrated to their own subgroup's error patterns.

What can go wrong

What can go wrong

Gating does not capture domain structure. If the mixture-of-experts model does not specialize (all experts see the same data, or routing is random), the gating scores are uninformative. Gating similarity becomes noise, and the method provides no benefit over standard conformal. The paper depends on the model having learned real expert specialization, where each expert is genuinely better at some subset of the data. This happens because during training, if one expert starts to outperform others on certain examples, the router learns to send more of those examples to that expert, creating a virtuous cycle: the expert improves further, the router becomes more confident, and the specialization solidifies. Without this specialization, all experts converge to similar performance and the router cannot distinguish subgroups.
Calibration set is too small or unbalanced. The weighted quantile is computed from calibration errors. If you have only 100 calibration examples and test on 1 million examples from a new domain, the quantile is built from very few samples. If certain routing patterns are rare in calibration, the weights are unreliable for new test cases with those routings. The method needs a calibration set large enough and diverse enough to cover the hidden subgroups your model will encounter.
Similarity metric is poorly chosen. The paper uses cosine similarity of gating vectors, but other metrics (L2 distance, Wasserstein) might work differently. If the metric does not reflect true domain distance, the weights will be misleading. The paper tests a few metrics and shows cosine works well, but this is an engineering choice that can be wrong for a given domain.
Done right. Retrain the MoE model on your data so it specializes well; use a large, representative calibration set; choose the similarity metric carefully (cosine is a safe default); validate coverage on held-out subgroups to confirm the adaptation is honest.
What a runnable demo should prove

What a runnable demo should prove

Build a synthetic dataset with two clear clusters (e.g., a 2D plane with Gaussian clouds centered at opposite corners). Train a mixture-of-experts model (two experts) on this data. You will observe that the gating network learns to route cluster 1 examples to expert 1 and cluster 2 to expert 2. Collect calibration predictions (predict + record error for held-out train examples). For new test examples from cluster 1 and cluster 2, compute standard conformal intervals (ignore gating), then compute gating-weighted intervals. Measure and plot: (a) interval width on cluster 1 (gating-weighted should be narrower), (b) interval width on cluster 2 (should also be narrower), (c) coverage on both clusters (both should stay at or above 90%, no loss of honesty).

Interval width for gating-weighted minus interval width for standard conformal; coverage is (count of true values inside interval) / (total test examples)

The demo must show that gating-weighted intervals are tighter on both subgroups while maintaining the same 90% coverage guarantee, proving that the model's own routing learned to identify domain structure and we can reuse that signal to adapt.
