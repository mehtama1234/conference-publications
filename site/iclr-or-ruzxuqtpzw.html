Differentiable Simulators and Policy Gradients

Switching between different gradient methods based on whether the model is smooth prevents bias and noise problems when learning robot control policies.

Paper explainersAll themesReinforcement Learning

When teaching a robot to do a task, you can estimate the right adjustments to make using calculus on a differentiable model (smooth math), or you can guess at the adjustments by trying random changes (no calculus needed). This paper asks: when the robot's real physics has sudden breaks or jumps, which method actually works better—calculus fails because it assumes smooth slopes that do not exist at discontinuities, while guessing works but is slow—and what's the simplest way to switch between them?

Zero assumption version

Smooth math breaks on jumpy physics

A reinforcement learning agent (a robot or game player) learns by adjusting numbers called weights. Two methods exist: calculus-based (compute the exact direction to move a weight using the math of the model) and guess-based (try random changes and see what sticks). Calculus is usually faster because it points directly toward better weights.

But real physics is not smooth. A ball rolling might suddenly hit a wall and stop instantly—no gradual transition. When the physics has these sudden jumps, the calculus method fails: the gradient (the direction to nudge a weight) becomes wrong or undefined, biasing the learning. Older work tried to catch these breaks by looking at the noise around the guess-based estimates, but that method is slow, noisy itself, and requires hand-tuned numbers per task.

The paper's core fix. Detect when the physics jumps, then swap from calculus to guess-based gradients in those moments; add a careful variance controller to keep updates stable.

The algorithm as a flow

What it actually does

Estimate gradients both ways

Compute calculus-based gradient and guess-based gradient on every step.

Check for jumps

Look at where the two estimates disagree strongly—sign of a discontinuity.

Swap methods at jumps

In smooth regions, use calculus; at jumps, use guess-based.

Adjust step size per update

Scale the weight nudge by the variance of recent updates.

Update and repeat

Move weights, measure reward, loop until policy converges.

What the paper changes

What the paper changes

The paper changes which gradient estimator (calculus-based vs. guess-based) the algorithm uses on each step, and how much it scales the update.

the object it moves  =  gradient estimator and step scaling
The hidden quantity

Discontinuity severity

measured quantity  =  discontinuity indicator

This is a number that measures how jumpy the physics is at each moment. Instead of looking directly for jumps (which is hard to detect), the paper infers discontinuity from the disagreement between the two gradient methods: if calculus and guess-based give opposite signs or very different magnitudes, the physics is likely jumping.

The paper estimates this by comparing the calculus-based gradient to the guess-based gradient; where they diverge, a switch to the guess-based method is safer. Later, the per-step variance controller (how much the recent updates have changed) becomes the second hidden signal: high variance means instability, so shrink the step; low variance means stable learning, so step bigger.

Why it works

Why switching and scaling work

Calculus-based gradients are fast because they use the math of the smooth model. But when physics jumps, that math is wrong: a derivative (a slope) does not exist at a jump. The guess-based method is slower and noisier, but it just tries random changes and sees what works—it does not rely on smooth math, so jumps do not break it.

By detecting where the two methods disagree (a sign of a jump) and swapping to guess-based, the algorithm avoids the bias trap. Then, the per-step variance controller (inverse-variance weighting) adjusts how big each weight nudge is based on how much recent updates have wiggled. When updates are shaky (high variance), take smaller steps; when updates are smooth (low variance), take bigger steps. This prevents the noise of guess-based gradients from derailing learning.

Math after the picture

The update rule

First in words:

Weight update equals the chosen gradient multiplied by a step size scaled by the inverse of recent update variance.

Then the compact form:

theta_new = theta + alpha * (1 / sqrt(variance_recent)) * gradient_chosen

Every symbol:

thetacurrent weight value
theta_newupdated weight value
alphabase step size
gradient_choseneither calculus or guess-based gradient, picked via discontinuity test
variance_recentvariance of the last N weight updates
A tiny worked example
Scenario: smooth region, calculus gradient is reliable.
Gradient chosen = 0.8 (pointing down the hill).
Recent updates: [0.02, 0.01, 0.03, 0.02], variance = 0.0001.
Step size alpha = 0.1.
Inverse variance term = 1 / sqrt(0.0001) = 1 / 0.01 = 100.
Update = 0.1 * 100 * 0.8 = 8.0 -> this is a big, confident step in a stable region.
Now: jumpy region, variance_recent = 0.04 (noisy updates).
Inverse variance term = 1 / sqrt(0.04) = 1 / 0.2 = 5.
Update = 0.1 * 5 * 0.8 = 0.4 -> step shrinks to 0.4 when updates are shaky.

The inverse variance weighting automatically brakes the algorithm when updates get noisy (a sign of discontinuities), without needing to detect jumps explicitly.

What can go wrong

What can go wrong

Lag in jump detection. If the test for disagreement is too slow or threshold-sensitive, the algorithm might use the wrong gradient for a few steps, accumulating error before the switch.
Hyperparameter coupling. The discontinuity threshold and inverse-variance scaling constant must both be chosen; if they fight each other, learning becomes unstable.
Noisy guess-based gradients in small batches. Guess-based gradients estimate direction by testing random perturbations and averaging the results across many samples. In low-data regimes (small batches), the average contains too much noise relative to the true direction, so the swapped estimates become unreliable even though they are unbiased.
Done right. The paper shows that a single hyperparameter (the discontinuity threshold in DDCG) is sufficient, and IVW-H adapts variance scaling automatically, reducing sensitivity to task-specific tuning.
What a runnable demo should prove

What a runnable demo should prove

Build a simple robot control task with one region of smooth physics and one region with a sudden discontinuity (e.g., rolling until it hits a wall and stops). Run three learners: calculus only, guess-based only, and the paper's DDCG plus IVW-H. Plot the policy reward over time for each. The demo should show calculus failing in the jumpy region, guess-based working but slowly, and the hybrid method learning fast on both.

final_reward = sum of accumulated rewards from task start to completion, divided by number of steps
