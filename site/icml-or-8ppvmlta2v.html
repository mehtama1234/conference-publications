Mem-T: Densifying Rewards for Long-Horizon Memory Agents

Train a memory-managing agent with step-level credit across a tree of memory operations so it can learn long sequences of store, update, and retrieval decisions from delayed outcomes.

Paper explainersAll themesAgents & Tool Use

Memory agents must decide what to store, what to update, what to retrieve, and when to ignore new information. Those decisions unfold across many turns, yet the agent often gets feedback only at the end of the whole task. That makes training hard because the learning signal arrives too late to show which earlier memory choices were useful. Mem-T addresses this by organizing memory actions into a tree and propagating end-task feedback back through that tree as dense step-level supervision. The result is better memory management and lower query cost because the agent learns which operations actually support future retrieval.

Why delayed feedback makes memory learning hard

Suppose an assistant reads a long stream of messages and later must answer a question about them. Along the way it has to choose what facts to store, whether to merge or split entries, when to retrieve old entries, and when to revise them. If the system receives a reward only when the final answer is judged correct or incorrect, the signal is too sparse. Many memory decisions happened before the outcome, but the learner cannot tell which ones mattered.

That sparsity is especially harmful on long tasks. A poor early storage choice can make later retrieval fail, but the final penalty arrives only after many additional operations. Standard reinforcement learning struggles here because the useful credit signal is buried inside a long sequence.

The paper's move. Represent the memory process as a tree of operations and push terminal feedback back through that tree so the agent gets dense supervision about which storage and retrieval choices helped.

What the paper changes

What the paper changes

The paper changes how a memory agent is trained. Instead of treating the whole memory trajectory as one long chain with one late reward, it decomposes the trajectory into an operation tree and assigns denser credit to intermediate storage and retrieval choices.

the object it moves  =  Reward assignment for memory operations
The hidden quantity

The hidden quantity: contribution of one memory action

measured quantity  =  How much one store, update, or retrieval step helped the final answer

Not every memory action matters equally. Some stored facts are never used. Some updates remove noise. Some retrievals pull exactly the right entry at the right time. The hidden quantity is the contribution of each operation to the eventual task result.

Mem-T estimates this contribution through the operation tree. By tracing which later states and retrievals depended on an earlier operation, the learner can assign stronger credit to the steps that influenced success. Training improves because the agent now sees why one memory decision mattered, not just whether the whole episode ended well.

Why it works

Why denser credit improves memory agents

Memory management is a control problem over time. Early choices shape what later choices are even possible. If the learner receives only one final success signal, it cannot reliably separate useful early operations from accidental ones. Dense credit helps because it gives intermediate supervision about which actions created future value.

The operation tree is the key structure. It records branching memory decisions and their downstream consequences. When the final outcome is known, the system can propagate that information backward through the tree. An early storage decision receives positive credit if later retrieval depended on it and led to a good answer. A wasteful storage decision receives little or negative credit if it consumed space but never supported a useful retrieval.

This turns memory training from vague end-to-end hope into targeted policy improvement. The agent learns not only to answer well, but to build memory states that make later answering easier and cheaper because the right information is available with fewer unnecessary stored entries.

Math after the picture

Step credit from terminal reward

First in words:

The final reward is distributed across memory operations according to how much each operation contributed to the downstream path that led to the result.

Then the compact form:

credit(o_i) = R * contrib(o_i)

Every symbol:

credit(o_i)training signal assigned to memory operation o_i
Rterminal reward for the full episode
contrib(o_i)estimated share of responsibility of operation o_i for the final outcome
A tiny worked example
An episode ends with reward R = 1 because the final answer is correct.
The learner estimates that an early store step contributed 0.4, a mid-episode update contributed 0.1, and the final retrieval contributed 0.5.
So credit(store)=0.4, credit(update)=0.1, credit(retrieve)=0.5.
If a later episode fails with R = 0, all attached credits vanish, and the learner does not reinforce those operations.
Training improves because the agent now sees which individual memory decisions were most responsible for success.

The paper's reinforcement-learning procedure is richer than this shorthand, but the main idea is that terminal outcomes are turned into step-level supervision over the memory tree.

What can go wrong

What can go wrong

Contribution estimates are wrong. If the tree assigns too much credit to irrelevant operations, the policy may reinforce wasteful memory habits because the training signal is pointing at the wrong causes.
Memory tree is too shallow. If the structure does not capture the real dependencies among operations, propagated credit will be crude because the learner cannot trace which earlier choices shaped later retrieval.
Storage policy overfits one task pattern. If training data contains narrow recurring structures, the agent may memorize a brittle storage style because it rarely sees tasks that need different memory layouts.
Done right. The method works when the operation tree captures true memory dependencies and the credit signal reflects whether one step actually made later retrieval more successful.
