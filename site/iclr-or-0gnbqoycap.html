In-Context Learning in World Models

A world model can adapt to new environments by learning from context examples when answering questions, not just memorizing environments during training.

Paper explainersAll themesReinforcement Learning

Today's world models predict what happens next in an environment, but they are trained once and frozen. When they meet a new environment, they fail. This paper shows that a world model can adapt on its own, by watching a few examples of the new environment and figuring out its rules—without retraining. The trick is a long memory (context window) and diverse training. We show this works and explain when adaptation happens by learning versus by pure recognition.

Zero assumption version

Static world models break on new territory

A world model is a neural network that learns to predict: given where a robot is now and what it does next, where will it be? Train it on hundreds of environments, freeze its weights, and it can forecast the next 10 steps in any of those training environments. But show it a brand new environment—one it has never seen—and it flops. The weights were tuned for the environments in the training data. A new environment has different rules, and the frozen weights cannot adapt.

A naive fix: retrain on the new environment. But retraining takes weeks. The real problem: the model should figure out the new environment's rules just by watching a few example rollouts. A clever learner does this. Why does the model not?

The model has no way to update its understanding mid-task. Train once. Freeze. Use as-is. It cannot learn from new context.

What the paper changes

What the paper moves

The paper enables a frozen world model to shift its predictions on new environments by routing queries through a learned routing layer that reads the context buffer. The routing layer scans past examples and decides which signals matter most for the current step. The computation stays inside the routing head; the base weights never update. This is different from retraining or fine-tuning. The weights stay frozen—but the model's internal state (what the routing module remembers and emphasizes) changes.

the object it moves  =  Routing layer memory
The hidden quantity

The hidden quantity: predictive error bound

measured quantity  =  Environment-specific prediction error

The paper introduces a mathematical upper bound on how wrong the world model's prediction can be on a new environment. This bound has two parts: one for environment recognition (figuring out which training environment the new one resembles most) and one for environment learning (guessing the new rules from context examples). The bound is an upper limit—a theoretical worst-case forecast of how much error is likely.

The paper derives these bounds rigorously but also measures them empirically: by applying the ground-truth world model of each training environment to test data and measuring the gap. This reveals which adaptation mode emerges: if the model mostly recognizes the new environment as an old one, the error stays small because matching is fast. If it must learn new rules, error drops more slowly with context length, but the bound shrinks as context grows.

Why it works

Why in-context learning emerges from diverse training

Imagine training the model on only four very similar environments. The model learns a single set of weights that do okay on all four. Weights are like a compromise solution. When a fifth, slightly different environment arrives, the frozen weights are close enough that the model guesses well without needing context. This is environment recognition: pattern-matching to the nearest training neighbor.

Now imagine training on 128 diverse environments: deserts, forests, underwater, zero-gravity, each with wildly different physics. No single weight set is a good compromise. The model must become a different learner. Instead of baking all knowledge into weights, it learns to use its routing memory as a scratchpad: read the context (a few example steps of the new world), recompute which rules apply, and forecast accordingly. The weight magnitudes stay the same, but routing computation changes. This is environment learning: adapting the computation itself.

The paper proves this mathematically by deriving error bounds for each mode. The ER (recognition) bound shows how wrong the prediction is when just matching to the nearest training environment: bigger gaps in training data mean bigger errors. The EL (learning) bound shows how wrong it is when learning from context: error shrinks as you watch more context steps (as T grows). Under diverse training, the EL bound becomes smaller than the ER bound once T is long enough. The model converges to learning mode. Under narrow training, the ER bound is already small because the test environment is close to training—learning cannot beat matching, so recognition stays dominant.

The error bound: why adaptation modes emerge

First in words:

Upper bound on prediction error = min(environment_recognition_error, environment_learning_error), where ER error is small if training set covers the test environment well, and EL error shrinks with context length T and diversity constant D.

Then the compact form:

TV(phat_ER, p_test) <= KL_div(test, nearest_train) + O(1/T) TV(phat_EL, p_test) <= D * log(num_train_envs) / T + O(1/T^2)

Every symbol:

phat_ERmodel prediction in recognition mode
phat_ELmodel prediction in learning mode
p_testground-truth transition in test environment
KL_div(test, nearest_train)distance from test environment to nearest training environment
Ddiversity constant: smaller if training environments are very different
num_train_envshow many training environments the model saw
Tlength of context (number of example steps read before prediction)
TV(...)total-variation distance (how different two probability distributions are)
A tiny worked example
Suppose model trains on 4 similar environments. Diversity D = 1.0 (low). Test set has 100 context steps.
ER error (recognition): nearest training env is distance 0.15 away. KL_div ≈ 0.15. ER bound ≈ 0.15 + small noise ≈ 0.16.
EL error (learning): 1.0 * log(4) / 100 + noise ≈ 0.014 + noise ≈ 0.02. But this is much smaller than ER error, so learning should work.
Wait—but D was very small because training envs were similar. Let me recalculate: if D=1.0 and num_train=4, then EL bound ≈ 1.0 * 1.39 / 100 ≈ 0.014. ER bound ≈ 0.16. Learning seems better.
Actually, the surprise: D depends on how DIFFERENT training environments are, not how similar. If training was on 4 similar envs, then D is LARGE (hard to generalize), so EL bound grows: D ≈ 2.5 * log(4) / 100 ≈ 0.035. Still beats ER (0.16).
But with only 4 training environments, log(4) ≈ 1.39 is tiny. ER wins easily. Recognition is cheaper.
Now suppose training on 128 diverse environments. num_train=128, log(128) ≈ 4.85, and D is small (diverse training = easier generalization) ≈ 0.3. EL bound ≈ 0.3 * 4.85 / 100 ≈ 0.015.
ER error still 0.15 (distance to nearest training env). Learning is better! The model learns.

The core pattern: ER (recognition) error does not shrink with context length, but EL (learning) error does shrink. Diverse training makes the EL bound small enough that learning outcompetes recognition.

What can go wrong

What can go wrong

Not enough diversity in training. If the model trains on only similar environments (all deserts, or all mazes with the same layout), then learning mode is expensive: D is large, so the EL error bound grows. Recognition mode (matching to the nearest training environment) stays cheaper because the test environment is naturally close to at least one training environment. The model never learns to learn—it stays in recognition mode, where context does not help because the routing layer has no practice adapting to worlds with completely different rules.
Context window too short. In-context learning needs enough examples to infer the new rules. If you give the model only 5 steps of context, it cannot figure out the underlying physics. The error bound is high. You need context length T to be large—100+ steps in typical experiments.
Test environment too far from training set. If the test environment is radically different (e.g., trained on 2D navigation, tested on underwater robotics), then even the nearest training environment is very far. The KL divergence is huge, ER error is huge, and the learning error bound must overcome a large baseline. The model struggles.
Done right: diverse training + long context. Train on 64+ different environments with visibly different rules. Keep the context window at 100+ timesteps. The model will learn to learn, and prediction error on new environments shrinks as it watches examples.
What a runnable demo should prove

What a runnable demo should prove

Build a simple world: a 2D box with 4 different gravity directions (down, up, left, right). Train the model on 16 environments by permuting the gravity vector. Freeze the weights. At test time, create a 5th gravity vector (e.g., diagonal) that the model has never seen. Give it 50 timesteps of context (watch the ball fall diagonally and bounce off walls). Then ask it to predict the next 20 steps. Measure prediction error (difference between predicted and actual ball position) at each step. Compare: model with in-context learning (uses the 50-step context) versus baseline (ignores context, uses frozen weights only).
