FLAIR: Latent Reasoning in Full-Duplex Dialogue

Let a spoken dialogue model think in hidden numbers while listening, without slowing down the response.

Paper explainersAll themesTime Series & Sequential

When humans talk, we think while the other person is speaking—we process their words and form ideas at the same time. Current speech models wait until the user stops to think about a response. This paper proposes FLAIR, which lets a speech model do something new: it conducts hidden internal reasoning (thinking in numbers, not words) during the listening phase, the same way humans do, with no added delay and no need to write out the reasoning steps.

Zero assumption version

Why we need thinking while listening

A spoken dialogue model (a system that hears words and answers out loud) currently works in two separate phases: first it listens to the user speak, then it stops and thinks about what to say back. But humans do it differently—we think and listen at the same time.

A beginner might try running the model backward in real time: pick apart the user's speech, wait for silence, run the reasoning phase, then speak. But this creates a noticeable gap. The user finishes speaking and then waits for the machine to think. In fast conversation, that delay breaks the flow.

The hidden problem: there is no way for the model to do any reasoning during the listening phase in current systems. The model has to store raw speech and process it all at once after the user stops. Better conversations need the model to think in parallel with listening, because when a user finishes speaking and waits, every second of delay before a response starts feels like dead air in conversation. If the model has reasoned through everything during the listening phase, it can respond the instant the user stops, keeping the dialogue natural and flowing.

In one sentence. Current speech models cannot think while listening; they wait until the user stops talking to start their reasoning.

The algorithm as a flow

What it actually does

Listen to one small chunk of speech

The speech encoder (a neural network that reads audio) turns the audio into a list of numbers.

Feed numbers forward and backward

A recurrent layer (one that feeds its own output back to itself) takes the new audio numbers plus the hidden reasoning from the previous chunk.

Compute new hidden reasoning numbers

The recurrent layer mixes old reasoning with new speech evidence and outputs updated hidden thinking.

Loop: move to the next chunk

Repeat steps 1-3 as the user keeps speaking. The hidden thought grows richer with each chunk.

Generate a response when speech stops

At the end of listening, the model has built up latent reasoning in its hidden state. A decoder (another neural network) uses it to produce words.

What the paper changes

What the paper changes

The paper rewires the timing: instead of computing all reasoning after listening is done, it computes reasoning in a loop during listening. The object that moves is the hidden state (the internal number list that captures thought)—it now updates continuously, fed back into itself, as new speech arrives.

the object it moves  =  Hidden state updates
The hidden quantity

The hidden reasoning value

measured quantity  =  Latent thought

The paper measures something new: the latent thought, a vector (a list of numbers) that the model maintains in memory during the listening phase. Unlike the final output (the words it will speak), this thought is never written down or shown—it lives only inside the model as it processes speech. It captures the model's internal reasoning about what the user is saying.

FLAIR estimates this latent thought by having the model recursively update it: at each step, the new thought is a function of the old thought plus the new audio information. During training (when the model learns its weights), a teacher (the human expert) provides a correct response, and the paper uses a mathematical technique called an Evidence Lower Bound (ELBO) to infer what the latent thought should have been to produce that correct answer. This lets the model learn how to build good latent thoughts without being told step-by-step what to think.

Why it works

Why thinking while listening works

The core insight is causality: when a human hears "Did you see the game last night?", they immediately begin forming ideas—maybe recalling if they watched, maybe thinking about how to phrase a response. They do not wait for the sentence to finish. FLAIR does the same by updating hidden numbers at each audio chunk.

The mechanism is simple: a recurrent layer (a layer that feeds its own output back) processes one chunk of audio, mixes it with the previous latent thought, and outputs a new latent thought. This new thought captures a bit more of what the user said plus the model's growing understanding. Because the thought is updated step by step (looped), each chunk adds to understanding in sequence, respecting the natural order of speech.

Why no added latency? Because the hidden thought updates happen at the same rate as audio chunking—they do not require a separate reasoning pass. When the user finishes speaking, the model already has built up latent thought. The decoder can then convert that thought to words immediately, with no additional delay. The hidden numbers capture internal reasoning without writing it out, so no extra time is spent.

The paper uses an ELBO loss to make this learnable: during training, a teacher provides the correct response, and the ELBO lets the model infer backward what the latent thought should have been. By training on pairs of user utterances and correct responses, the model learns to build latent thoughts that naturally lead to good answers. No manual reasoning annotations needed.

The recursion equation

First in words:

The hidden thought at step t is a function of the hidden thought at step t minus 1 and the audio information at step t. In a probability framework, the thought distribution at time t is updated using Bayes' rule applied recursively.

Then the compact form:

h_t = tanh(W_h * h_t-1 + W_a * a_t + b)

Every symbol:

h_tthe hidden thought (latent vector) at time step t
h_t-1the hidden thought from the previous time step
a_tthe audio embedding (numbers from the speech encoder) at time step t
W_ha weight matrix that controls how much the previous thought affects the new one
W_aa weight matrix that controls how much the new audio affects the thought
ba bias (a constant offset added to every thought)
tanhan activation function (a curve that squashes the output to a range between -1 and +1)
A tiny worked example
Suppose at time step 0 we start with h_0 = [0.1, -0.2, 0.3] (initial thought).
At time step 1, the audio chunk gives a_1 = [0.5, 0.2, -0.1].
We multiply: W_h * h_0 might give [0.05, -0.1, 0.15], and W_a * a_1 might give [0.25, 0.1, -0.05].
Adding: [0.05, -0.1, 0.15] + [0.25, 0.1, -0.05] + b (where b = [0, 0, 0]) = [0.3, 0.0, 0.1].
Apply tanh: tanh([0.3, 0.0, 0.1]) ≈ [0.29, 0.0, 0.10], so h_1 = [0.29, 0.0, 0.10].
At time step 2, the new audio a_2 = [0.3, -0.2, 0.4] mixes with the h_1 we just computed.
The hidden thought evolves over time, capturing more of the user's meaning as more speech arrives.

The key is that each step's hidden thought depends on the previous step's thought, so each new chunk of audio updates the thought in place, building reasoning incrementally without any separate thinking phase.

What can go wrong

What can go wrong

Latent thought can accumulate noise. If the hidden numbers are updated step-by-step over a long utterance, small errors can compound. An incorrect update early on can mislead later updates, building bad reasoning into the hidden thought. The paper uses the ELBO loss to gently correct against this, but very long dialogues might still suffer drift.
Teacher forcing assumes perfect supervision. During training, the paper uses teacher forcing: it feeds the correct answer as a target to infer the latent thought. In real use, there is no teacher, so the model must rely on its learned thought evolution. If training does not match the deployment regime (the model saw a clean, correct response during training but then must improvise in real chat), the latent thought might not capture what the model actually needs, because the thought-building patterns it learned were shaped by always seeing the right answer at the end.
Hidden thought is not interpretable. Because the reasoning is latent (hidden numbers), it is hard to audit or debug. If a response is wrong, it is difficult to look inside the hidden thought and find where the reasoning went wrong. A system that writes out its thinking step-by-step is easier to debug by comparison.
Done right: latent thought stays stable. If the recurrent layer is well-trained and the ELBO objective is effective, the hidden thought updates become consistent and build richer reasoning with each audio chunk. No extra latency is introduced because the reasoning updates run at the same cadence as audio chunks, not on top of it, so the total time from first audio to first output word stays the same or shrinks. Quality improves because the model now has time to reason while listening, building better understanding than if it tried to think only after the utterance ends.
What a runnable demo should prove

What a runnable demo should prove

Build a small full-duplex dialogue system: use a simple recurrent encoder that processes audio in chunks, maintain a hidden thought vector that updates at each chunk, and feed it to a decoder that produces output words. Train it on a small speech dataset (e.g., a subset of LibriSpeech with responses annotated by hand) with an ELBO loss. Measure two things: (1) response latency—the time from when the user stops speaking to when the model outputs the first word, and (2) response quality—a human rater or automatic metric (e.g., BLEU or exact-match accuracy if the expected responses are known). Compare FLAIR against a baseline that waits until listening is done before thinking.

Latency improvement = baseline_latency - flair_latency; Quality = response accuracy measured by human raters or automatic metrics.

The demo must show that latent reasoning during listening cuts response latency in half or more without sacrificing quality, proving that parallel thinking-while-listening works.
