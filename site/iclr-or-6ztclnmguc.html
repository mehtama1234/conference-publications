Gelato: Graph Edit Distance via Autoregressive Matching

A neural network learns to match nodes between two graphs one pair at a time, capturing which earlier choices affect which later ones, to solve a famously hard graph comparison problem much faster than traditional solvers.

Paper explainersAll themesGraph & Geometric Learning

When you want to know how different two graphs are (e.g., comparing molecular structures or road networks), you need to find the cheapest sequence of edits to turn one into the other. This is called the graph edit distance problem, and it is computationally exhausting — traditional solvers give up on graphs with more than 20 nodes. Gelato uses a neural network to learn patterns in how to match nodes across graphs, predicting the best pair to link at each step.

Zero assumption version

Why comparing graphs is stuck

Comparing two graphs means finding how different they are. If you have a graph with nodes (like cities) and edges (like roads between them), and you want to check if it is the same as another graph, you need to find a one-to-one pairing of nodes that preserves as many edges as possible. The cost of the pairing is how many edits you need to make: adding edges, removing edges, or changing node labels.

The hard part: if you have 20 nodes in each graph, there are twenty-factorial possible pairings (twenty times nineteen times eighteen and so on, which is an astronomically large number). Traditional solvers use clever tricks to prune this search space, but they still exhaust their memory and time on graphs bigger than 20 nodes. Simpler heuristics (greedy algorithms that just pick the best-looking pair at each step without thinking ahead) run fast but often miss the truly cheapest pairing.

The naive approach: try all pairings, or use a greedy heuristic. Both fail — exhaustive search is impossible, and greedy misses the global optimum.

In one sentence. The paper teaches a neural network to predict which two nodes should be matched next, one pair at a time, using what it learned from earlier matches.

The algorithm as a flow

What it actually does

Encode both graphs

A graph neural network (a model that learns from the connectivity pattern) reads both graphs and builds a representation for each node that captures its role.

Predict the first match

The network scores how well each node in graph A matches each node in graph B, and picks the best pair.

Condition the next prediction on what is done

Once that pair is locked in, the network re-computes scores for remaining nodes, taking into account that some matches are already settled.

Repeat until all (or enough) nodes are matched

Step by step, the network picks the next-best pair, aware of the full history of earlier choices.

Compute the edit cost of the matching

Count how many edge additions and deletions are needed to make one graph match the other given the pairing.

What the paper changes

The one thing the paper changes

Instead of a greedy or exhaustive search, Gelato uses a neural network to pick which nodes to match. The object is: the sequence of node pairs (the matching itself).

the object it moves  =  node-pair matching
The hidden quantity

The hidden quantity: structural dependency depth

measured quantity  =  How much earlier matches constrain later ones

When you match node A1 to B3, that choice affects which nodes are left and how similar they are to the remaining graph B nodes. Some matches unlock good next choices; others paint you into a corner. The paper does not name this explicitly, but the core hidden quantity is: the degree to which each match depends on the structure captured in earlier matches.

Gelato measures this through the neural network's attention mechanism (the learned weights that decide how much each node pays attention to each edge and neighbor node). By conditioning each new prediction on the full history of locked matches, the network implicitly tracks which structural patterns matter most for the remaining choices. The network learns to avoid dead-end pairings by recognizing when a match leaves good structural room for future steps.

Why it works

Why predicting one pair at a time works

The reason Gelato succeeds is that matching is a sequential decision problem, and breaking it into steps lets the network learn which early choices lead to good late choices. A graph neural network can learn from training examples (you show it many graph pairs with good matchings), whereas a fixed search algorithm cannot adapt. When the network has already matched two pairs and is deciding the third, it has learned from training: 'when the remaining nodes look like this pattern, pairing these two nodes together leaves me with better options for the next step.' It learned this because training data showed that such choices led to lower total edit costs.

Making one prediction at a time (one pair per step) matters because each prediction can incorporate the history. A model that predicted all matches at once would have to predict them independently of each other, ignoring which pairs were already locked. By recomputing match scores based only on unmatched nodes after each step, the model avoids impossible pairings and makes choices that leave good options for the next step. Training teaches the network: greedy choices that look good right now often trap you into bad later choices; instead, learn which early matches leave you with good next options.

Math after the picture

The core equation

First in words:

At each step, score each unmatched node-pair by the dot product (multiply and sum) of their learned vectors, then pick the pair with the highest score. After locking a pair, update the learned vectors to reflect that some nodes are now unavailable.

Then the compact form:

score(i, j) = encode(node_i) · encode(node_j) for all unmatched (i, j); pick argmax(score); lock pair; update encode() to zero out matched nodes.

Every symbol:

score(i, j)how well node i in graph A matches node j in graph B
encode(node_i)the learned vector for node i, built by the graph neural network
·dot product: multiply element-wise and sum to get one number
argmaxpick the pair with the highest score
lock pairmark that pair as chosen and remove both nodes from future scoring
A tiny worked example
Graph A has nodes 1, 2, 3; Graph B has nodes X, Y, Z.
After encoding: A1=[0.8, 0.2], A2=[0.3, 0.9], A3=[0.5, 0.5]; B_X=[0.7, 0.3], B_Y=[0.2, 0.8], B_Z=[0.6, 0.4].
Step 1 scores: A1·B_X = 0.8*0.7 + 0.2*0.3 = 0.56 + 0.06 = 0.62. A1·B_Y = 0.8*0.2 + 0.2*0.8 = 0.16 + 0.16 = 0.32. A1·B_Z = 0.8*0.6 + 0.2*0.4 = 0.48 + 0.08 = 0.56.
Best for A1 is B_X (0.62). Check A2·B_Y = 0.3*0.2 + 0.9*0.8 = 0.06 + 0.72 = 0.78. Best pair overall: A1→B_X. Lock it.
Step 2: only A2, A3, B_Y, B_Z remain. A2·B_Y = 0.78 (best). Lock A2→B_Y. A3→B_Z is forced.
Matching: A1→B_X, A2→B_Y, A3→B_Z. Now count edge edits: if A1-A2 is an edge but B_X-B_Y is not, that costs 1 deletion, etc.

The network learns these dot-product vectors from training data, so high scores correlate with low-cost matchings in that data.

What can go wrong

What can go wrong

Training data does not cover the types you test on. If training examples are small graphs from one domain (e.g., social networks), and you test on large chemical structures, the learned patterns may not work. The network has never seen the structural patterns of the new domain, so it cannot recognize which matches are good. However, the paper shows Gelato generalizes better than rule-based baselines because neural networks can extract structure from features even when domain is new, and training on graphs of many sizes helps it handle unseen sizes.
A greedy early choice really does close off the best matching. Even if the network tries to look ahead, if it makes a locally good but globally bad first match, it cannot backtrack. Once locked, a pair stays locked. This is rare if training data shows clearly that such mistakes lead to high costs, but it can happen on unusual graph structures the network did not see in training.
Noisy or ambiguous node labels. If nodes have unclear features (e.g., all nodes are generic blobs with the same label), the network has little to go on. Without strong node signals, the network must rely only on edge patterns, which is harder. The paper tests this and finds the network works better with clearer labels because it has more signal to distinguish which nodes should pair together.
Done right. Train on a diverse set of graphs with ground-truth matchings (or loss-based feedback). The network learns to recognize structural patterns that correlate with cheap matchings. At test time, even on unseen graph sizes, it applies those learned patterns because the structure of graph matching is consistent across sizes.
