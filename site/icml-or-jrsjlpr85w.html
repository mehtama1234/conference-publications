SURGE: Approximation and Training Free Particle Filter for Diffusion Surrogate

To assimilate noisy observations into a pretrained diffusion forecaster, run sequential Monte Carlo over whole diffusion trajectories so particles are reweighted and resampled toward the true posterior instead of only being nudged by guidance.

Paper explainersAll themesOther

Data assimilation continuously combines a dynamics model with incoming observations to estimate a system's hidden state, meaning the unobserved system variables we want to recover. Weather forecasting, fluid prediction, and many scientific simulators use this loop. Recent work replaces expensive simulators with pretrained diffusion models that can generate plausible future states. But simple observation guidance only nudges samples toward the data; it does not guarantee that the resulting samples are drawn from the correct posterior, meaning the weighted set of hidden states consistent with both model dynamics and observations. SURGE fixes that gap by placing particle filtering directly over diffusion trajectories. Each trajectory becomes a particle, observations define importance weights, and resampling keeps computation focused on the trajectories that remain plausible. Because this is done on the path measure, meaning the probability law over entire diffusion paths, the method fuses the diffusion surrogate with observations without an extra learned corrector.

Zero assumption version

Guiding a diffusion forecaster is not the same as sampling the right posterior

A diffusion surrogate can forecast a dynamical system by repeatedly denoising from noise toward a plausible next state. If an observation arrives, a common trick is to add a guidance term from the observation likelihood, meaning the score that tells you how compatible a candidate state is with the measurement.

That guidance can improve samples, but it does not by itself produce the exact posterior weighted set of states needed for sequential state estimation, because it changes particle motion without correcting particle probabilities. The generated trajectories may still be biased, especially when observations are sparse or noisy. Data assimilation needs a principled update rule that keeps track of the probability mass over many possible trajectories, not only a single guided rollout.

The method in one sentence. Treat full diffusion trajectories as particles, weight them by observational consistency, and resample over time so the ensemble approximates the correct posterior.

The algorithm as a flow

What it actually does

Sample diffusion trajectories

Generate an ensemble of candidate state trajectories from the pretrained diffusion surrogate.

Score with observations

For each particle, evaluate how likely the new observation is under that trajectory.

Compute importance weights

Turn those observation scores into normalized particle weights so better-matching trajectories carry more posterior mass, because the filter must assign more probability to trajectories that explain the measurement better.

Resample particles

Duplicate high-weight trajectories and discard low-weight ones, because posterior approximation improves when mass is concentrated on plausible paths.

Advance sequentially

Repeat at the next time step so the trajectory estimate is continuously corrected as new data arrive.

What the paper changes

What the paper changes

The paper changes the role of the diffusion model in data assimilation. Instead of using the surrogate only as a guided sampler, it uses the surrogate as the proposal mechanism inside a sequential Monte Carlo filter, so observations affect particle probabilities and ancestry, not only particle drift.

the object it moves  =  the posterior update for diffusion-based data assimilation
The hidden quantity

Path-level posterior mass

measured quantity  =  path-level posterior mass (how much probability belongs to an entire candidate diffusion trajectory after seeing observations)

The key quantity is not the denoised state at one instant. It is the probability of the whole trajectory under both the surrogate dynamics and the observation model. A trajectory that looks plausible for one frame can still be poor overall if earlier denoising choices made the observation unlikely.

SURGE tracks this quantity with particle weights. Sequential Monte Carlo means representing a weighted set of possibilities by many weighted particles that are repeatedly reweighted and resampled over time. Working on the path measure matters because resampling depends on the entire trajectory history that produced the current state, not only the current frame.

Why it works

Why particle filtering repairs guided diffusion sampling

Guidance changes where a diffusion sampler moves, but it does not keep an explicit correction for how probable each trajectory should be after the move. That omission matters because data assimilation is a probability-tracking problem, not only a trajectory-denoising problem.

Particle filtering provides that correction. The diffusion surrogate proposes candidate trajectories, and the observation likelihood scores them. Importance weights then say how much posterior mass each proposal deserves. Resampling sharpens the approximation because it allocates finite particle budget to the trajectories that still explain the data, instead of wasting particles on low-likelihood paths.

The method is approximation-free in the sense emphasized by the paper because it does not need a separately trained correction network or an extra analytical approximation to the posterior update. The only approximation is the standard particle approximation itself, which becomes tighter as particle count grows. That is why the approach preserves the statistical logic of sequential Monte Carlo while still using a pretrained diffusion model as the dynamics engine.

Math after the picture

The particle weight update

First in words:

new particle weight equals old weight times the likelihood of the latest observation under that particle's trajectory, then all weights are normalized before resampling

Then the compact form:

w_t^(i) proportional to w_(t-1)^(i) * p(y_t | x_t^(i))

Every symbol:

w_t^(i)the weight of particle i after observing time t
w_(t-1)^(i)the weight of particle i before the new observation
y_tthe observation received at time t
x_t^(i)the state of particle i at time t
p(y_t | x_t^(i))the observation likelihood for that particle
A tiny worked example
Suppose three particles start with equal weight 1/3.
After a new observation, their likelihoods are 0.9, 0.2, and 0.4.
Unnormalized new weights are 0.3, 0.0667, and 0.1333.
Their sum is 0.5, so normalized weights are 0.6, 0.133, and 0.267.
Resampling will copy the first particle most often because it explains the observation best.
That concentration matters because it turns the ensemble toward the posterior instead of merely nudging every particle equally.

The update is simple, but it is the missing statistical correction that ordinary guidance does not provide.

What can go wrong

What can go wrong

Particle degeneracy appears. If one or two particles absorb nearly all the weight, the ensemble collapses. Future uncertainty is then underestimated because too few distinct trajectories survive.
The diffusion surrogate is biased. Particle filtering can only reweight and resample the proposals it receives. If the surrogate almost never proposes trajectories near the true system, the posterior approximation remains poor.
Observation likelihood is misspecified. If the noise model for observations is wrong, weight updates reward the wrong particles. The filter can then drift even when the diffusion proposals are good.
Done right. Use enough particles to limit collapse, monitor effective sample size to trigger resampling sensibly, and validate both the surrogate forecast quality and the observation model.
What a runnable demo should prove

What a runnable demo should prove

Create a low-dimensional dynamical system with partial noisy observations, such as a reaction-diffusion toy system or a chaotic oscillator observed through a few coordinates. Train a diffusion surrogate on simulated rollouts. Then compare three assimilators: surrogate alone, observation-guided surrogate, and SURGE.

Track posterior calibration, state estimation error, and particle diversity over a sequence of observations. Visualize how weights move after each measurement and how resampling changes the ancestry of surviving trajectories.

state_error = average squared distance between posterior mean state and true hidden state

The demo should make clear that SURGE wins because it corrects trajectory probabilities, not only trajectory positions.
