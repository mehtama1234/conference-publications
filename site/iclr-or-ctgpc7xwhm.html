How reinforcement learning after next-token prediction facilitates learning

Adding a reinforcement learning fine-tuning stage after next-token pre-training allows transformers to solve reasoning problems that would otherwise require exponentially more training data.

Paper explainersAll themesLearning Theory

Large language models are trained in two stages: first, predict the next word in a sequence (next-token prediction); second, fine-tune by learning from rewards that score correct answers. This paper asks: why does this two-stage approach work so much better than just predicting the next word alone? It shows that when tasks require step-by-step reasoning (like solving math problems or verifying logical steps), the second stage with reinforcement learning (learning by trial and reward) works better because it treats rare long reasoning chains the same way it treats common short answers—both get rewarded equally when correct, so rare chains suddenly carry as much weight as their abundance would suggest they should.

Zero assumption version

Why does just learning to predict the next word get stuck?

Imagine teaching a student to solve a math problem by showing them worksheets and asking them to complete one more line. This is next-token prediction: the model learns to guess the next symbol in a sequence. If the worksheet has lots of easy problems with short answers, the student sees those patterns most. But hard problems need long, step-by-step reasoning.

When hard problems are rare in the training data (especially when their multi-step solutions are rarer than short ones), a model trained only to predict the next token hits a wall. It learns to output something plausible, but without seeing many complete long chains, it never learns the actual reasoning strategy. To force this learning through prediction alone would require showing the long chains far more often—exponentially more data for each additional reasoning step.

The problem in one sentence: Next-token prediction struggles to learn step-by-step reasoning when long solution chains are rare in the data.

The algorithm as a flow

What it actually does

Pre-training: learn surface patterns

A large neural network (a type of AI model) predicts the next word using prediction loss on mixed data.

Pause and switch goals

After some pre-training, stop using prediction loss and switch to reinforcement learning.

RL step 1: generate attempts

Model generates complete answer sequences (short or long) for each problem.

RL step 2: score with reward

Reward function checks if the answer is correct (0 or 1, or rewards per step).

RL step 3: nudge model toward rewards

Algorithm (like GRPO) increases probability of actions that led to high rewards, decreases low-reward paths.

What the paper changes

What the paper changes

The paper changes which loss function drives learning. Instead of optimizing only next-token prediction loss (which treats every token equally), the fine-tuning stage uses a reward-based loss that scores entire solution chains. This shift means the model now learns to chase high-reward outputs rather than just reproducing the most likely next token.

the object it moves  =  The learning objective: prediction loss to reward-based loss
The hidden quantity

The hidden quantity: how much rare long chains matter to learning

measured quantity  =  Effective weight of rare long examples

The paper measures an invisible quantity: how much the rare long solution chains matter to learning. In next-token prediction, a 1-in-10 rare chain competes with 9 common short ones, so its signal gets drowned out. But when the reward function directly scores entire chains and reinforcement learning optimizes that reward, a single long correct chain can move the model's weights as much as many short ones.

The paper estimates this by observing that after switching to RL, the model suddenly generates much longer responses (up to 10 or 20 times longer), even though it was trained on fewer long examples. This jump in response length reveals that RL has reweighted the rare long chains to have outsized influence—they now guide learning more than their frequency suggests they should.

Why it works

Why this works: the causal chain

Here is the concrete reason RL outperforms next-token prediction: next-token prediction treats each token as an independent prediction problem—losses are summed one token at a time, which means the signal from rare long chains gets drowned in the noise of abundant short ones. This means when the model predicts a token incorrectly, it learns 'this token was wrong,' but never learns 'this token was part of a failed multi-step strategy.' When long solution chains are rare in the training data, the model sees the first few tokens of a long chain only a few times, scattered among thousands of common short chains. Because each token is optimized independently, that rare signal gets drowned out by the noise of predicting abundant short sequences. In contrast, RL scores entire sequences as a unit: a single long correct chain delivers a clear 'this whole path was right' signal that propagates back to all its tokens at once. That one rare chain now carries as much learning signal as many common short chains combined.

Reinforcement learning breaks this impasse by scoring entire sequences. It generates a complete answer—short or long—and then evaluates the whole thing: correct or incorrect. A single long correct chain now carries signal throughout training: every token on the path to the right answer gets boosted together. Because one long correct chain is rewarded as heavily as any short correct chain (both get the same reward score), the rare long chains suddenly have outsized statistical weight. The model learns to favor them because they deliver reward reliably, and each appearance shapes the model more than a short sequence would.

Additionally, RL allows the model to generate longer responses during fine-tuning (it can explore output lengths beyond what it saw in training) because the reward signal only cares about final correctness, not output length. This unlocks a hidden advantage: more tokens mean more intermediate scratch space to work through the problem step by step. A model with 10 steps can build more complex reasoning than one forced to answer in 3 steps. Pre-training locked the model into short default lengths because short chains were most abundant; RL's reward for long correct answers lets the model learn that extra steps often buy correctness on hard problems.

The equation driving learning

First in words:

During reinforcement learning, the algorithm computes a reward for a full sequence and then adjusts the model to increase the probability of sequences with higher rewards. The policy gradient is: adjust weights proportionally to (reward minus baseline) times the log probability of that sequence.

Then the compact form:

loss = -sum_t (R - b) * log P(a_t | a_<t, x)

Every symbol:

Rthe reward signal (1 if answer correct, 0 if wrong)
ba baseline value (average reward seen so far)
a_tthe action (token) chosen at step t
a_<tall previous tokens in the sequence
xthe problem input
log P(...)log probability of choosing that token (higher = model is more confident in that choice)
lossquantity the algorithm minimizes (negative reward feedback)
Tiny worked example: one problem, two attempts
Problem: what is 2 + 3? Data has mostly short answers ('5') and rare long work ('2 plus 3 equals 5').
Attempt A (short): model says '5' → correct → R = 1, baseline b = 0.5 → update = (1 - 0.5) = 0.5
Attempt B (rare long): model says 'two plus three equals five' → correct → R = 1, baseline b = 0.5 → update = (1 - 0.5) = 0.5
Same reward boost for both, even though long is rarer. Weights shift to favor the rare long chain equally.
Over many rounds, long chains accumulate signal. Pre-training sees long once; RL sees it once but weights it as if it appeared often.

The reward stays the same (1 for correct) regardless of sequence length, so rare long chains get amplified as much as abundant short ones.

What can go wrong

What can go wrong

Not enough long examples even for RL. If long solution chains are exponentially rare (less than one per 2^d examples where d is problem size), RL cannot find them during fine-tuning because the model generates from scratch during RL, and if the correct long chain has almost never appeared in pre-training, the model has no starting point to explore from. RL can only amplify behaviors it has already discovered; it cannot invent entirely new reasoning out of nowhere.
Reward signal is ambiguous. If the reward only checks the final answer and ignores intermediate steps, the model may learn to guess the answer without learning reasoning. The RL algorithm sees a high reward but not which steps mattered most, so it may reinforce lucky guesses rather than strategies.
Response length unconstrained. RL with length rewards (or no length penalty) can push models to generate indefinitely long responses to chase higher rewards. The model wastes computation without improving reasoning quality.
Tuned correctly, RL extracts rare chains. When long examples are present at a non-negligible rate (even 10% of data), RL fine-tuning discovers and amplifies them. The model learns reasoning strategies that short-only training would never find.
What a runnable demo should prove

What a runnable demo should prove

A minimal demo trains a small transformer (like a tiny GPT-2) on a synthetic parity-prediction task: given d random bits, predict if their count is even or odd. Create training data where 90% of examples show just the input bits and label, but 10% show step-by-step reasoning (count bits, check parity, output). Split into a pre-training phase (next-token prediction on all data) and a post-training phase (RL or STaR reward-based fine-tuning). Log accuracy before and after the switch. Plot response length (average tokens generated) across the two phases.

improvement = (RL_accuracy - pre_train_accuracy) / (max_possible - pre_train_accuracy)

The demo succeeds if RL accuracy jumps >30 percentage points immediately after switching the loss function, and if average response length visibly increases during RL fine-tuning (even though long examples were rare).
