MedAgent-Pro: Towards Evidence-based Multi-modal Medical Diagnosis via Reasoning Agentic Workflow

MedAgent-Pro separates diagnosis into a guideline-based plan and a patient-specific evidence loop, so each conclusion is tied to retrieved clinical guidance and measured findings from the patient data.

Paper explainersAll themesMultimodal

A usable diagnostic system cannot stop at naming a disease. It must show which findings support the conclusion, which guideline step justified the next test, and what evidence ruled out alternatives. MedAgent-Pro builds that structure explicitly. One stage retrieves disease-level guidance and turns it into a diagnostic plan. A second stage runs patient-level reasoning: it calls visual and analytic tools on scans, reports, and other patient data, stores the findings in memory, and reflects on whether the current conclusion is actually supported. The goal is not only a correct label but a trace of why that label was chosen.

Zero assumption version

Why direct multimodal diagnosis is not enough

Modern diagnosis uses multiple data sources at once: images, symptoms, laboratory values, history, and clinical guidelines. A direct answer from a vision-language model compresses all of that into one step. That is risky because the system may skip a missing lab value, ignore a contradictory image finding, or jump to a familiar disease without checking guideline order.

Clinical use needs evidence that can be inspected. A doctor must be able to ask: which image region suggested pneumonia, which lab value supported infection, and which guideline branch recommended this test next? If the model cannot answer those questions, the final diagnosis is hard to trust even when it happens to be correct.

The paper addresses this by splitting diagnosis into a standard plan and a personalized execution loop. This helps because the standard plan enforces disease-specific steps, while the execution loop checks the actual patient record against those steps before producing a conclusion.

The fix. Retrieve disease guidelines first, turn them into an explicit diagnostic plan, then let a patient-level agent gather findings step by step and revise its memory whenever the evidence does not support the current conclusion.

The algorithm as a flow

What it actually does

Retrieve disease guidance

A retrieval-augmented stage searches medical guidelines and reference material relevant to the suspected disease area.

Write a standardized diagnostic plan

The system turns the retrieved guidance into an ordered checklist: which findings to inspect, which tests matter, and which alternatives must be ruled out.

Analyze the patient data with tools

A patient-level agent calls visual models and other analytic tools on scans, reports, and structured values to gather concrete findings.

Reflect on support

After each step, the agent checks whether the current memory contains enough evidence for the working diagnosis. If not, it revises the plan or asks for another action.

Emit a diagnosis plus evidence trace

The final output ties each conclusion to the findings and guideline steps that support it.

What the paper changes

What the paper changes

The paper changes diagnosis from one-shot prediction into a controlled workflow with two levels of reasoning. The disease level defines what should be checked in general for a condition class. The patient level decides how to check those items on this patient. That separation matters because it prevents patient-specific noise from rewriting clinical procedure, while still allowing the agent to adapt the next action to the evidence already collected.

The hidden quantity

The hidden quantity: evidence support coverage

measured quantity  =  How much of the conclusion is backed by explicit findings

The important quantity is support coverage: for each major claim in the diagnosis, how much direct evidence is already present in memory? A diagnosis is weak when the conclusion is stated but one of its required findings is absent, contradictory, or only implied. It is strong when each key claim points to a measured lab value, an image finding, or a retrieved guideline condition.

Reflection uses this quantity to decide whether to stop or keep investigating. If support coverage is low, the agent should not finalize because the conclusion still rests on gaps. If support coverage is high, the final answer is easier to inspect because each step has a concrete backing item.

Why it works

Why the two-level agent is useful

The disease-level plan reduces omission errors. Without it, the system may ignore a key exclusion criterion simply because it is not salient in the current prompt. The retrieved plan keeps those checks visible, so the patient-level agent is repeatedly compared against a standard clinical sequence.

The patient-level loop reduces unsupported conclusions. Tool outputs turn images and numbers into explicit findings, memory stores those findings in a reusable form, and reflection asks whether the evidence base is complete enough for the current diagnosis. This works by forcing the model to convert raw multimodal input into inspected intermediate facts before it commits to a final decision.

Math after the picture

The support-check objective

First in words:

Finalize only when the accumulated evidence covers the required diagnostic findings and keeps contradictions low.

Then the compact form:

Support(d) = sum_k w_k * Evidence_k - sum_m u_m * Missing_m, finalize if Support(d) >= tau

Every symbol:

da candidate diagnosis
Evidence_kan observed finding that supports requirement k
w_kimportance weight for requirement k
Missing_ma missing or contradictory item for requirement m
u_mpenalty weight for missing or contradictory evidence
tauminimum support score needed before finalizing
A tiny worked example
Suppose pneumonia requires three major supports: image opacity, fever, and raised inflammatory marker.
The agent finds opacity on the scan and elevated marker in the lab panel, but fever is absent.
If the first two supports each contribute 1 point and the missing fever contributes a penalty of 1 point, the current support score is 1 + 1 - 1 = 1.
If the threshold tau is 2, the case cannot be finalized yet. The agent must collect more evidence or reconsider the diagnosis.
After history review reveals measured fever, the score becomes 1 + 1 + 1 = 3, so the diagnosis can now be finalized.

The exact score can vary across diseases. The important idea is that a diagnosis should be blocked until its required evidence is present.

What can go wrong

What can go wrong

Retrieved guidance is incomplete or outdated. If retrieval misses the relevant guideline section, the standardized plan starts from a weak base and later reflection can only partially repair that error.
Tool outputs are noisy. Patient-level reasoning depends on image analyzers and other measurement tools. A wrong intermediate finding can propagate because later steps treat it as evidence.
Reflection checks the wrong thing. If the reflection step only asks whether the diagnosis sounds plausible, it will accept fluent summaries. It must check whether each required claim points to stored evidence.
Done right. Keep the disease-level plan explicit, log every tool result into memory, and make the reflection prompt ask for missing findings and rule-out gaps before allowing a final answer.
