Bandit Learning in Matching Markets Robust to Adversarial Corruptions

When players in a marketplace try to learn their best matches through trial and error, the paper makes sure bad actors poisoning the feedback cannot trick them into wrong choices.

Zero assumption version

Two-sided learning in a rigged game

In a matching market, workers and employers (or buyers and sellers) gradually learn who pairs well with whom. Each side watches past pairings and notes how good or bad they felt, then uses those notes to pick better partners next time, because this feedback tells them which matches are satisfying. Over time, if rewards are honest, they all converge to stable pairings where nobody wants to leave.

But what if an adversary falsifies the feedback? A spurious high score might push a worker toward a bad employer; a fake low score might hide a good match. The naive learning algorithm (Explore-Then-Gale-Shapley, a classic stable-matching method) assumes feedback is truthful, so it marches forward confident in lies and converges to the wrong stable matching.

In one sentence. The paper protects two-sided marketplace learning from adversaries who poison reward signals by learning to ignore outliers and adapting to unknown corruption levels.

The algorithm as a flow

What it actually does

Exploration phase

Both sides sample many pairings to gather feedback signals.

Widened confidence bands

Instead of trusting each signal exactly, assume it could be corrupted by up to C units.

Gale-Shapley matching

Use the (uncertain) preference estimates to find a stable matching that works under all plausible corruptions.

Adaptive detection (unknown case)

If corruption level is unknown, race multiple hypothesized levels and discard failing ones.

Convergence guarantee

The algorithm converges to the true stable matching despite adversarial tampering.

What the paper changes

What the paper changes

Instead of trusting reward signals as exact truth, the algorithm treats each signal as potentially shifted by up to C units. This means when the algorithm estimates how much a worker prefers an employer, it keeps a wide margin of doubt around that estimate. The Gale-Shapley matching step then finds a stable pairing that works under all possible corruption patterns within that margin.

the object it moves  =  Confidence intervals around reward estimates
The hidden quantity

The corruption budget and how to detect it

measured quantity  =  Adversarial corruption level C

The hidden quantity is how much total damage the adversary can inflict. Formally, C is the sum of the largest corruptions across all rounds: if the adversary shifts a signal by at most 5 in round 1 and at most 3 in round 2, then C is at least 8. A player does not know C ahead of time.

The paper estimates C (or assumes it is given) and sets the confidence interval width proportional to C. Bigger C means wider intervals, treating each signal as less trustworthy. This is how the algorithm learns to resist bigger corruption budgets: by building in proportional skepticism.

Why it works

Why widened caution and adaptive races work

When rewards are honest, a narrow confidence interval (like plus-or-minus 0.1) is fine: true signals lie inside it and estimates are tight. But with adversarial corruption, true rewards can be shifted far outside a narrow band. So the paper widens the intervals: each estimate now says 'the true reward is somewhere in this wide range.' This wide range is large enough to contain any adversarially corrupted signal that falls within budget C.

The Gale-Shapley algorithm takes these wide preference estimates and finds a stable matching: each side prefers its partner to anyone else, even when considering all possible rewards inside the confidence intervals. This stable match holds under all corruption patterns the adversary can achieve with budget C.

For the unknown corruption case, the algorithm does not know C in advance. Instead it races: it tries the widened-interval method with assumed budget 1, then 2, then 4, doubling each time. Some attempts will fail because their assumed budget is too low. The successful attempts converge to a stable matching, and the algorithm picks one. Because true corruption has some finite level, at least one attempt will have high enough budget and converge to the true match.

Math after the picture

Confidence-widened preference estimation and stable matching

First in words:

For each player-arm pair, estimate the true reward as the measured mean of observed signals, then widen the confidence interval by the corruption budget C. The stable matching minimizes regret (distance from the true stable match) under all possible true rewards that lie inside these widened bands.

Then the compact form:

confidence_interval_i = [empirical_mean_i - C, empirical_mean_i + C], and find stable matching M such that max over all corruption patterns u within C: regret(M, u) is minimized.

Every symbol:

empirical_mean_iaverage of all observed rewards for player-arm pair i
Ctotal corruption budget: sum of max perturbations per round
confidence_interval_irange of plausible true rewards for pair i given corruption C
Mthe matching (which player pairs with which arm)
regret(M, u)distance from optimal stable matching when true rewards are perturbed by u
A tiny worked example
Suppose corruption budget (or C) is 4 (adversary can corrupt by up to 4 total across all rounds).
Worker A observes scores 7, 6, 8, 7 for Employer X. Average is 7.0.
Confidence interval for A-X is 7.0 minus 4 to 7.0 plus 4, which gives 3 to 11.
True reward could be 7.0, or it could be anywhere from 3 to 11 if corrupted.
The algorithm finds a matching that remains stable even if all true rewards are shifted within these intervals.
This same matching works for any actual corruption with total budget 4 or less.

Widening the interval by C ensures the true reward (even if corrupted) falls inside, so the stable matching found is guaranteed to work.

What can go wrong

What can go wrong

Corruption budget too low. If the assumed corruption level C is much lower than the attacker's true budget, some signals remain outside the confidence intervals. The matching may still converge to a suboptimal stable point.
Exploration phase too short. If players do not sample enough pairings before locking into a match, the average of observed signals becomes unreliable and noisy. Even wide intervals may not contain the true reward. More exploration rounds are needed.
Adaptive racing converges to wrong level (unknown C case). If the multi-layer ETGS race discards the correct corruption level too early, the algorithm may converge to a match that works for the wrong budget and fails under true corruption.
Done right: corruption known and budget respected. When the corruption level is known and the attacker stays within budget C, the widened-interval algorithm converges to the true stable matching.
What a runnable demo should prove

What a runnable demo should prove

Simulate a two-sided marketplace: say 5 workers and 5 employers. Each worker has a true preference ranking over employers (based on salary and commute). Add noise (random errors) to the observed scores. Then add an adversarial corruption: one malicious employer injects fake high scores for themselves into worker feedback 5 times across 20 rounds, totaling corruption amount 5. Run the naive Explore-Then-Gale-Shapley algorithm and the widened-interval variant. Measure how far each matched pairing strays from the true optimal match. The widened-interval version should converge close to optimal; the naive version should be misled by the corruption.

distance from optimal match = optimal match score minus actual matched score, lower is better

The demo must show that widened-interval distance stays small across all tested corruption budgets, while naive distance grows as corruption increases.
