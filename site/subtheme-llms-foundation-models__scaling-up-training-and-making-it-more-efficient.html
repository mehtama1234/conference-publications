Scaling up training and making it more efficient

These papers study how model performance improves as they get bigger and develop better training recipes using scaling laws, advanced optimization, and novel pretraining approaches.

All themesField mapMathematicsAll explainers
What this is

A striking pattern in machine learning is that bigger models trained on more data perform better on almost every task, which means size correlates with ability. This is called scaling, and the relationship is surprisingly predictable—if you know how well a small model performs, you can forecast how well a large one will, because the improvement follows a pattern. Papers in this area study the rules of scaling: how performance improves with model size, data size, and compute budget. They also study scaling laws—mathematical relationships that describe these patterns—so that researchers can plan experiments ahead of time and predict whether training a larger model is worth the cost, which saves wasted spending on experiments that will not work.

The deeper question is efficiency: how to get the most performance for a fixed budget of computation, which is the real constraint in research. A naive approach is just to make everything bigger, but that is wasteful because you spend money on techniques that do not help. Better approaches involve advanced optimization techniques, like adding noise to the direction-of-change calculations to escape getting stuck in local traps (dead ends in the search space where the model stops improving because it got stuck), or adjusting how fast the model learns to be quick early and careful later, so the model finds good solutions faster. Some papers also study new pretraining approaches, where instead of just predicting the next word, models are trained on other tasks that force them to learn deeper patterns, which teaches them richer representations upfront. The tricky part is that small experiments do not always predict what happens at scale—a technique that works in a small experiment might fail on a large model, or vice versa, because scaling changes what matters.

Understanding scaling matters because it determines whether companies can build bigger models and whether research labs with limited budgets can compete, which affects who gets to build new models. Papers that discover inefficiencies in training can make the process cheaper, which means more teams can afford to build models. Papers that characterize scaling laws help researchers decide which ideas are worth pursuing by predicting what works before you spend money testing it, which prevents wasted experiments. This area touches everything else: if you understand how to scale efficiently, you can afford to train larger models on better data, which helps you solve harder problems and study new techniques because you save money, so scaling efficiency unlocks everything downstream.

How the work breaks down

Scaling up LLMs is expensive, so the papers here split into five clear directions: first, using mixture-of-experts and sparsity to get more performance without proportionally more compute because you only activate part of the model per word; second, discovering the mathematical rules (scaling laws) that predict how large models need to be before they can do new tasks because prediction lets you avoid wasting money on experiments that won't work; third, being smarter about which training data you use, so you waste less compute training on bad examples because low-quality data teaches the model wrong patterns; fourth, inventing new training recipes that learn faster or in better ways than the standard predict-the-next-word approach because the training loop itself determines how quickly the model finds good solutions; fifth, making deployed models faster and cheaper to run through better ways to sample the next word because generation speed and cost determine whether a model is practical to deploy at scale.

MoE and sparse models follow different rules

Mixture-of-Experts (MoE) models are a way to make models bigger without making every part bigger: you have many small "expert" networks, and for each word you decide which experts to use, so you only pay the compute cost for the experts you pick. This is fundamentally different from dense models where every word touches every layer. The challenge is figuring out how to design sparse models so they are actually more efficient than dense ones, and understanding how their performance scales as you change the model size and the number of experts.

Capacity-Aware Mixture Law shows that you can reduce the cost of optimizing the mixture (deciding which experts to use) by 50% while actually improving downstream accuracy by up to 3% on models up to 55 billion weights that are active in each forward pass. Rather than search for the perfect expert assignment, you can be smart about which assignments are worth trying and skip the rest because most assignments are mediocre and not worth checking. Optimal Sparsity of Mixture-of-Experts Language Models discovers that reasoning and memorization have opposite requirements: reasoning tasks want a small number of weights per word (so the model is forced to be precise and can't just memorize patterns) because fewer parameters force abstract thinking, while memorization wants many weights (so the model has room to store facts without forgetting them) because facts need storage. Scaling Laws for Efficient Mixture-of-Experts Language Models shows that scaling laws accurately predict MoE efficiency: an MoE model with only 850 million active weights can match the quality of a 6.1 billion weight dense model while using 7 times less compute. This means sparse models scale in a different, cheaper way than dense models because you don't pay for unused experts, and if you can predict how, you can build smaller models that do the same work without wasting resources on computation you don't need.

Understanding scaling rules to predict the future

The core question in scaling is: if I train a small model, can I predict how well a large model will perform, and is it worth the cost? Scaling laws are the mathematical rules that answer this. They take the form of power laws: performance improves as a predictable curve with model size, data size, and compute budget because improvements follow a consistent pattern across different scales. If you know these rules, you can decide ahead of time whether scaling is worth the money instead of wasting resources on experiments that fail because you can calculate what the payoff will be before you spend anything.

Predicting Large Model Test Losses with a Noisy Quadratic System gives you a way to find the best model size, batch size, and number of training steps under a fixed compute budget, using only a few small experiments. The idea is that the loss surface has structure you can learn from small runs and use to predict what works at larger scale. Can Language Models Discover Scaling Laws shows you can use an LLM itself to automatically discover scaling laws by learning from data about small models, and these AI-discovered laws extrapolate better than the scaling laws humans wrote by hand. Scaling Laws Revisited takes a real-world angle: it shows that higher-quality data substantially reduces how big your model needs to be and how much compute you need, and this effect holds even if your data is somewhat corrupted. Scaling Laws and Architectural Frontiers in Metagenomic Foundation Models proves that scaling laws hold outside language: Llama-like model designs scale efficiently on biological data, and you can derive quality-aware power laws that predict performance in completely different domains. Scaling Laws for Diffusion Transformers (diffusion means a way to train image models by iteratively denoising) confirms for the first time that scaling laws work for image generation: you can predict image loss for models billions of weights larger based on small experiments. xLSTM Scaling Laws shows that a different model design (linear-time LSTMs instead of the standard word-relationship mechanism) consistently produces lower loss per compute than standard models on the scaling frontier: for the same compute budget, xLSTM gets better quality, which means the best architecture might change as you scale.

Smart data selection to train on less

Training on all available data is wasteful: some examples teach the model nothing, some are corrupted or low-quality, and some are duplicated. The goal is to train on less data but get the same or better performance, which means spending less compute and finishing training faster. The challenge is deciding which examples are worth training on without an oracle that labels which examples are good.

BLISS is a lightweight method for scoring data: it computes two small backward passes to estimate how much each example will help the final model, then trains only on high-scoring examples. It reaches the same performance as expensive methods 1.7 times faster and delivers better downstream performance on large models because you skip the corrupted examples that would teach bad patterns. Fast Data Mixture Optimization via Gradient Descent (FastMix) optimizes which domains to train on and in what proportions: instead of hand-tuning a recipe, you let the backward-pass direction find the proportions that matter most for your goal. It gets the same pretraining score with 550 times less search cost because the search space is huge but only a few proportions are actually good, and improves downstream performance by 5.5 points because better-balanced domains teach more useful patterns. Olmix extends this idea: it lets you update the mixing proportions continuously as you retrain after learning new domains, and it matches full retraining quality with 74% less compute because you don't throw away learning from the old domains. Recycled data is often wasted, but RePro shows you can extract 3.7 to 14.5% accuracy gains by being smart about which word sequences to recycle from data you've already trained on, improving data efficiency by 2-3 times over naive recycling because some sequences teach new patterns even when seen again. Removing Noise, not Finding Gold reveals a counter-intuitive insight: quality filtering works not by finding the best data (which is hard) but by removing the worst data (which is much easier) because the worst examples hurt learning more than mediocre examples help. When you filter out low-quality examples, the model learns better even though you train on less, because you avoid teaching it wrong patterns that interfere with correct knowledge.

Better training because the training loop matters

The standard way to train is: feed examples in random order, compute gradients, and update. But there are smarter training recipes that converge faster or find better solutions because the order you show examples and what objective you train toward both affect what the model learns. These papers study new ways to schedule the training process (so examples that matter most come first), select examples during training (so you spend time on examples that will help), or set up the training objective so the model learns the right patterns (so it's optimizing for what you actually care about) rather than just predicting words.

How to Train Your Advisor studies a different pretraining setup: instead of one model predicting the next word, you train an Advisor Model that learns what kind of feedback helps the big model do better at downstream tasks. The advisor improves downstream accuracy by 27% on tax-law reasoning and reduces agent steps by 25%, which means the training goal itself is better aligned with what you actually care about because you're optimizing for task performance, not just next-word accuracy. AC-ODM uses reinforcement learning to decide which examples to show the model during training, rather than training on everything: it reaches the same quality on Pythia-1B with 66% fewer training steps and improves accuracy by 27.5% because focusing on high-value examples speeds up learning and teaches better patterns. ADEPT works at scale: you continue training a model on new domains without forgetting the old ones, and you do it by expanding the model and carefully tuning which parts learn, so you outperform full retraining by 5.76% while tuning only 15% of the model and using 50% less time because you're building on what the model already knows instead of starting over. Sharpness-Aware Pretraining shows that if you train toward flat regions (areas of weight space where small changes don't hurt performance), you stay more stable when you continue training later: this reduces catastrophic forgetting by up to 80% after post-training and by 40% after model compression because flat regions generalize better and don't get disrupted by new training. Towards Efficient LLMs Annealing with Principled Sample Selection uses theory to pick which examples are most important during training: you align the training order with the optimal descent path, so the model converges to better solutions across all model sizes because you're showing examples in the order that teaches the model most efficiently.

Making deployment fast and affordable

Once a model is trained, you still need to run it, and running is expensive. Running models is often the bottleneck: models are slow because they generate words one at a time, and each word requires a forward pass through the whole model, which is wasteful when much of the computation is unnecessary. The papers here make running faster through smarter sampling strategies (so you skip computing things you don't need), skipping computation on unimportant words (so you only pay for what matters), or breaking up the work into cheaper chunks (so each step costs less).

Break the Trade-off Between Watermark Strength and Speculative Sampling Efficiency solves a practical problem: watermarks make it hard to detect when a model generates fake content, but they slow down a common speedup technique called speculative sampling. This paper removes the trade-off, so you can both detect fakes and run fast without choosing between them. NI Sampling accelerates discrete diffusion (a different way to generate words than standard one-at-a-time generation) by learning the best order to generate words: instead of generating all at once, you generate the most certain words first and uncertain ones later, achieving 14 times speedup with almost no accuracy loss because uncertain words don't need as much computation. Swordsman uses adaptive block partitioning: some layers are important for some sequences but not others, so you compute only the layers that matter. It achieves best-in-class speed and stability on diffusion language models because you save compute on layers that won't change the output. CLAA takes a different angle: it discovers that only 10% of prompt words matter for understanding the full prompt, so you skip computing word relationships for the other 90%, matching full-context performance with much lower latency because most words are redundant for meaning. Cactus uses speculative sampling (run a fast model, verify its guesses with a slow model) but improves acceptance rates by constraining the fast model's output to be close to the slow model, so you accept more guesses and run faster because more correct guesses means fewer slow-model verifications. ICPO is about test-time scaling: you can improve model accuracy by running multiple passes at response time, using the model to critique and fix its own work because the model can reason better given its own previous attempts. The principled version balances reasoning cost and accuracy so response time stays affordable because spending extra compute should only happen when it improves accuracy enough to justify the cost. On the Limits of Test-Time Compute shows with theory and experiments that filtering bad outputs is better than just taking the best one, so you can be more efficient about spending extra compute at response time because filtering is mathematically superior to blind sampling. Training-Response Consistent Segmented Execution for Long-Context LLMs breaks long contexts into segments and processes them piece by piece, reducing peak memory by 6 times while keeping quality and latency competitive because segments don't interfere with each other and can be computed independently.
