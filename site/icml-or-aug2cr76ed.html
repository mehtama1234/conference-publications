Rethinking Multimodal Time-Series Forecasting Evaluation

A new benchmark with real-world time series and detailed text context exposes that simple ensemble methods beat fancy approaches built on flawed benchmarks.

Paper explainersAll themesTime Series & Sequential

Forecasting the future (predicting stock prices, weather, energy demand) gets harder when you add text alongside the numbers. Today's benchmarks for testing this are small, made-up, and have hidden leakage. A new benchmark called TimesX uses real data with genuine text contexts, revealing that approaches that looked great on old benchmarks actually fail on real-world data.

Zero assumption version

Old benchmarks trick you into thinking your model works

When you train a forecasting model on a benchmark (a test dataset), you want to know if it will work on brand-new, unseen data in the real world. But today's multimodal time-series benchmarks are built small — just a handful of time series — and many use fake, synthetic data instead of recordings from actual systems. This means a model can get high scores without actually learning what makes forecasts work.

A bigger problem: the benchmarks leak information. If the text that accompanies the time series comes from the same source as the numbers themselves, the model might memorize patterns specific to that leak rather than learning real forecasting. A beginner might build a fancy model with lots of moving parts and see it score 90% on the benchmark, only to find it scores 50% when you put it in production on fresh data from a different company or time period.

The hidden problem. Small, synthetic benchmarks with information leaks let models cheat, making flawed approaches look good.

The algorithm as a flow

What it actually does

Collects real time series

Gathers hundreds of genuine sequences (stock prices, electricity use, weather) from independent sources.

Pairs with independent text

Adds text context (news, reports, explanations) that comes from a separate source, not leaked from the numbers.

Automates data cleaning

Uses a pipeline to standardize, check, and format the data so it is consistent and usable.

Cuts data leakage

Splits each series so training and test data come from different time periods, preventing the model from accidentally seeing future information.

Tests ensemble beating fancy

Confirms that averaging forecasts from several simpler models outperforms a single complex model, because averaging dilutes memorization while pooling real patterns.

The hidden quantity

Generalization gap: does your model work on new data?

measured quantity  =  Generalization gap

When a model trains on a benchmark and then scores on a held-out test set, the score tells you how well it memorized the benchmark patterns, not whether it will work on a completely different company's data tomorrow. The generalization gap is the difference between your model's score on the old benchmark and its score on real, out-of-distribution data — fresh domains, new time periods, independent text sources.

TimesX measures this by building a dataset so large and diverse that models cannot memorize it. If your approach scores 90% on old benchmarks but only 40% on TimesX, your generalization gap is 50 percentage points. That gap is the problem the paper uncovers.

Why it works

Why a big, diverse, real-world benchmark catches models that cheat

Old benchmarks are small (five time series) and synthetic (made-up patterns). A model trained on five tiny series can brute-force memorize them: it learns "when I see pattern X, answer Y" for those five cases. On test data from the same five series split, the model is just recalling. When it meets a new company's data or a different time period, it fails because it never learned real forecasting.

TimesX is large (hundreds of series) and real (actual stock prices, weather stations, power grids). A model cannot memorize hundreds of diverse real series. Instead, it must find patterns that work across different sources: the structure that electricity demand follows in Germany is similar to what you see in Japan, even though the numbers are different. This forces the model to learn true forecasting logic.

Text context matters too. Old benchmarks pair time series with vague or synthetic text (made-up descriptions). TimesX pairs each series with real text (actual news, market reports, weather forecasts) from independent sources — so the model cannot cheat by memorizing a link between specific words and specific numbers. It has to actually use the text to guide the forecast.

Measuring how well the forecast works

First in words:

The error in a forecast is the root of the mean squared difference between the predicted value and the actual value; a smaller error is better.

Then the compact form:

RMSE = sqrt( sum_t (predicted_t - actual_t)^2 / n )

Every symbol:

predicted_tthe model's forecast for time step t
actual_tthe true value observed at time step t
nthe total number of time steps
sqrttake the square root to get back to the original units
sum_tadd up all the squared errors across every time step
A tiny worked example
Suppose we forecast five time steps: predicted = [10.2, 20.5, 31.0, 40.1, 49.8], actual = [10.0, 20.0, 30.0, 40.0, 50.0].
Errors: [0.2, 0.5, 1.0, 0.1, 0.2]. Squared: [0.04, 0.25, 1.0, 0.01, 0.04].
Mean squared: (0.04 + 0.25 + 1.0 + 0.01 + 0.04) / 5 = 1.34 / 5 = 0.268.
Root: sqrt(0.268) ≈ 0.52. RMSE = 0.52 (error units). Lower RMSE means better forecasts.

RMSE penalizes big mistakes (a forecast that is off by 10 is much worse than one off by 1); on TimesX, models that only memorize benchmarks stop working because every new series is unfamiliar.

What can go wrong

What can go wrong

Overfitting to benchmark style. If you design a model specifically to score high on the old benchmark (by memorizing its patterns), it will fail on TimesX. The model has not learned to forecast; it has learned to cheat.
Text leakage still possible. If the text context is not truly independent (for example, if it comes from the same system that generated the numbers), the model will find spurious links and fail when the sources separate in deployment.
Ensemble does not help mediocre components. A simple ensemble beats fancy models because the ensemble correctly combines diverse forecasters; if each forecaster is weak and makes the same error, the ensemble fails too.
Done right: diversity plus independence. Train multiple simpler models on different subsets of the diverse TimesX data, combine their forecasts (voting or averaging), and ensure text context truly comes from independent sources. Errors from memorization cancel out when you average, but real patterns reinforce.
What a runnable demo should prove

What a runnable demo should prove

Build a simple ensemble of two or three text-aware time-series models (you can use pretrained models or train small ones from scratch). Split a real time-series dataset (or use TimesX) into training (60%), validation (20%), and test (20%), making sure each set comes from disjoint time periods or independent sources. Train each model separately; then combine their forecasts by averaging. Measure RMSE on the test set.

Generalization_gap = RMSE_old_benchmark - RMSE_new_benchmark

If your simple ensemble beats a fancy single model on real, diverse, independent data, you have learned real forecasting instead of memorizing a small benchmark.
