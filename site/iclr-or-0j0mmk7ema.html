SimpleFold: Folding Proteins via Generative Flow Matching

Instead of hand-crafted protein folding machines, use a standard transformer trained to gradually denoise random atomic positions into real structures.

Paper explainersAll themesAI for Science

Protein folding is the problem of predicting where every atom in a protein ends up in 3D space. Older folding models use expensive specialized blocks designed just for proteins. SimpleFold asks: what if we used the same general building blocks that work for language and images (standard transformers: stacked layers where each layer attends to context), and trained it like a generative model to refine noisy atom positions into real structures? This simpler approach works just as well.

The protein folding problem and the complexity trap

A protein is a chain of amino acids that folds into a specific 3D shape. Knowing that shape tells us what the protein does — it determines whether it can bind to drugs, catalyze reactions, or break down waste. The problem: given just the sequence of amino acids, predict the 3D coordinates of every atom.

Today's best folding models use specialized architectural pieces designed specifically for proteins. They use expensive operations like triangular updates (special geometric tricks), explicit pair representations (matrices tracking which amino acids are close to each other), and multiple training objectives (different loss functions for different parts of the structure). This assumes that protein folding is so different from other problems that you need custom machinery.

A beginner would naively try: feed the sequence through a standard language model and decode the coordinates. This breaks because the model has no way to maintain 3D geometric consistency—atoms would float into impossible positions, bond lengths would be wrong, and atoms would pass through each other.

The question: Do we really need all that complexity? SimpleFold builds a protein folder from standard transformer blocks trained as a generative model, with no geometric machinery or domain-specific tricks.

What the paper changes

What the paper changes: the architecture

SimpleFold replaces the entire specialized stack—triangular updates, pair representations, domain-specific modules—with a single, repeating idea: standard transformer blocks. Every part of the model (atom encoder, sequence processing, structure decoder) is built from the same general-purpose blocks, just like those that work for language translation or image generation.

The hidden quantity

The hidden quantity: velocity of atoms through noise

measured quantity  =  Predicted velocity field

Central to SimpleFold is a quantity the model learns to predict but never explicitly measures: the velocity—the direction and magnitude each atom should move in the next instant. It is not a distance or a final coordinate. It is a tiny, momentary nudge calculated by the transformer at each step. The model predicts this velocity by comparing noisy atom positions and the amino acid sequence.

The paper trains the model by giving it noisy atomic coordinates and asking it to predict the correct velocity. During training, it compares the predicted velocity to the true velocity that would move the noisy structure toward the real structure. Over billions of examples, the transformer learns to predict accurate velocities, which means that when you apply these velocities step by step, noisy atoms gradually converge to realistic positions.

Why it works

Why it works: generative denoising tailored to 3D

Flow matching is a generative technique: start with noise, predict the direction to move toward clean data, apply that movement repeatedly. It works for images (remove blur, add detail) and text (remove scrambling, add grammar). SimpleFold applies the same idea to atomic coordinates.

Instead of hand-tuning specialized modules to respect protein chemistry, the transformer learns it directly from data. During training, the model sees millions of real protein structures and learns what realistic configurations look like. When it predicts velocities, it learns to move atoms toward bond lengths and angles that actually exist in nature. The sequence acts as a guide—the transformer conditions on amino acids, so it learns that a cysteine prefers certain neighbors, or that a helix has predictable 3D shapes. All of this emerges from the data without explicit rules.

The additional structural loss (LDDT loss) tells the model to prioritize getting local distances right—the distance between nearby atoms. This acts as a soft constraint: it nudges the model to favor realistic pairwise distances. It does not forbid impossible structures; it just makes them less likely during training. The transformer learns which velocities produce valid structures most often.

The training objective: velocity matching plus structure quality

First in words:

Total loss = (velocity matching loss) + (weight depending on time) * (local distance quality loss)

Then the compact form:

loss = l_FM + alpha(t) * l_LDDT l_FM = E[|| v_theta(x_t, s, t) - v_t ||^2]

Every symbol:

l_FMthe main loss: how well predicted velocity matches true velocity
v_theta(x_t, s, t)predicted velocity from the transformer, given noisy atoms x_t, sequence s, and time t
v_tthe true velocity that would move x_t toward real structure
l_LDDTlocal distance difference test: penalizes getting local atom distances wrong
alpha(t)weighting factor that changes based on the time step, higher later in training
A tiny worked example
Imagine one atom at noisy position (5.2, 3.1, 1.8) that should end up at (5.5, 3.0, 2.0).
True velocity: move (0.3, -0.1, 0.2) to get closer each step.
Model predicts velocity: (0.28, -0.12, 0.21).
l_FM error for this atom: (0.28-0.3)^2 + (-0.12-(-0.1))^2 + (0.21-0.2)^2 = 0.0004 + 0.0004 + 0.0001 = 0.0009.
If alpha(t) = 0.5 and l_LDDT = 0.01 for this atom, total loss = 0.0009 + 0.5*0.01 = 0.0059.
The model learns to make its velocity predictions smaller errors so loss shrinks over training.

The model minimizes the total error across all atoms. Velocity matching teaches it the direction to move; the LDDT term teaches it to prioritize realistic local structures.

What can go wrong

What can go wrong

Velocity training diverges if time-steps are uniform. Early timesteps (very noisy atoms) and late timesteps (nearly clean atoms) have very different velocity magnitudes. Sampling timesteps uniformly means the model trains poorly on important fine-detail steps. SimpleFold fixes this by resampling timestamps to favor late times (closer to clean data) where details matter most.
Locality constraints are necessary to avoid computational explosion. In a transformer (stacked layers where each layer connects pairs of items), a full all-to-all connection over every atom would multiply the compute cost with protein size. SimpleFold constrains each atom to only see nearby atoms in the sequence, keeping compute linear.
Rotational symmetry confuses deterministic models. Protein structures can be rotated arbitrarily. A deterministic regression model has to pick one rotation, which is wasteful and hurts ensemble predictions. Flow matching embraces this: the model learns many plausible rotations from data and can predict an ensemble naturally.
Done right: standard transformer architecture generalizes. Using the same blocks as language and vision models means SimpleFold can benefit from advances in transformer efficiency and scale—it is not locked into specialized 3D-only code.
What a runnable demo should prove

What a runnable demo should prove

Build a tiny SimpleFold on a small protein (100 amino acids). Train it on distilled structures for a few iterations. The demo should show: (1) Start with uniformly random atom positions. (2) Run the model for 50 timesteps, collecting predictions at each step. (3) Overlay the predicted structure against the real structure and measure RMSD (root mean square deviation—average displacement of atoms in Angstroms). The curve should show RMSD dropping from ~15 Angstroms (complete noise) to ~2-3 Angstroms (near-realistic) as refinement steps accumulate.

RMSD at step t = sqrt(mean((predicted_pos - real_pos)^2)) for all atoms

The core proof: a standard transformer, trained only to predict velocity and local distance quality, can refine random atoms into protein-like structures. No specialized layers needed.
