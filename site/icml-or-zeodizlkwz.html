Embodied-DETR: Temporal 3D Detection in First-Person View

A robot's camera sees partial, changing scenes from its own viewpoint, and this paper teaches the detector to understand continuity across time instead of treating each frame alone.

Paper explainersAll themesRobotics & Control

When a robot moves around a room, its camera sees objects from its own moving perspective. Things get hidden behind walls, move in and out of view, and appear at different angles. Standard detectors built for static wide-angle photos fail because they ignore this temporal flow and occlusion. Embodied-DETR combines two new ideas—tracking scene changes and linking the same objects across frames—to keep detections stable and accurate as the robot moves.

Zero assumption version

The camera moves, the scene breaks

A robot with a camera mounted on it (egocentric view) has a much harder job than a camera on a tripod. As the robot moves and turns, the same object appears at different image locations, hides behind walls, or pops back into view. The camera sees only a partial slice of the 3D world at any moment.

Existing 3D object detectors treat each video frame as independent—they look at frame 1 in isolation, frame 2 in isolation, and so on. That means they throw away a critical clue: the fact that an object seen at the left edge of frame 1 should probably still be there (or somewhere nearby) in frame 2, just shifted by the robot's movement. When the same object vanishes and reappears due to occlusion, an independent-frame detector has no memory and treats it as a completely new detection.

This causes cascading errors: the detector gives wildly different confidence scores for the same cup as it slides in and out of view, bounces the estimated 3D position up and down even when the object has not moved, and loses track of identities (is this the same cup or a different cup?).

In one sentence. Embodied-DETR tracks objects smoothly across a moving robot's viewpoint by learning how scenes evolve frame-to-frame and linking each object to itself over time.

What the paper changes

What the paper changes

Standard DETR (Detection Transformer) feeds each frame independently to a detector, which produces fresh object queries (lists of learned numbers that represent 'things that might be objects') for each frame. This forces the detector to re-identify objects from scratch every time.

Embodied-DETR changes this by making object queries persistent across frames. Instead of asking 'What objects are in this image?', it asks 'Where did the objects I tracked before move to, and are there new ones?'. The queries maintain a running memory of instance identity, so the detector can enforce consistency over time.

The hidden quantity

Temporal stability—the hidden quantity

measured quantity  =  Temporal stability score

Temporal stability measures how much a detected object's position, size, and confidence change from one frame to the next. In real robot perception, small jitter (the detection box bouncing around on a stationary object) is a major practical problem—it causes the robot to stutter when grasping or navigating. A detector that produces the same bounding box in successive frames scores high stability; one that oscillates scores low.

Embodied-DETR estimates temporal stability by computing how much the object query embeddings change across frames. If an object's embedding (its learnable representation) drifts a lot frame-to-frame, the downstream position and confidence predictions will also drift. By constraining query drift during training (limiting how much embeddings can change), the paper directly minimizes jitter. The benchmark (Embodied-Det) measures this by comparing predictions on the same physical object across frames where lighting, occlusion, or viewpoint changes slightly—the smaller the prediction change, the more stable the detector.

Why it works

Why it works: two complementary temporal steps

The core insight is that the robot's movement is predictable. If you know the camera moved 10 cm to the right, any object at the left edge of the current frame was probably at the center of the previous frame. Embodied-DETR exploits this by doing two things in parallel.

First, Scene-aware Feature Aggregation takes the visual features (low-level patterns) from the current frame and blends them with warped features from the previous frame, accounting for the camera's estimated movement. This is like sliding the previous frame's view to align with the current viewpoint, then comparing what changed. Objects that were fully visible before but are now hidden by a wall will be absent from the current features—this gap is a strong signal. By learning which features stay stable across the motion and which ones vanish, the model builds a richer understanding of the 3D scene structure.

Second, Instance-aware Query Embedding keeps the same query vectors (learned object representations) from frame to frame, with only small refinements allowed. Imagine each detected object has a name tag (its query embedding). When you see the object again (even rotated or partially hidden), you try to match its appearance to the closest name tag from the previous frame. Because name tags persist, the detector automatically groups detections across frames, and the ID stays constant. If an object leaves the view entirely, its query goes dormant; when it reappears, the query springs back to life with the same identity.

Together, these two mechanisms work because they solve complementary problems: aggregation gives the model scene context (what changed in the 3D world), and query persistence gives it object identity (which blob in the current frame is which object). The combination prevents both false negatives (losing an object when it slides out of view momentarily) and false positives (re-detecting the same object as new when it reappears).

Math after the picture

The equation: consistent identity across frames

First in words:

The model's loss combines detection accuracy on the current frame plus a penalty for how much object queries drift from frame to frame. Larger drifts are penalized harder, so training naturally suppresses jitter.

Then the compact form:

L_total = L_det(frame_t) + lambda * sum_i ||q_i(t) - q_i(t-1)||^2

Every symbol:

L_totaloverall training loss (lower is better)
L_det(frame_t)standard detection loss on current frame (classification + box localization errors)
lambdaregularization weight (how much to penalize drift; tuned by the authors)
q_i(t)the embedding vector for object i at frame t
q_i(t-1)the embedding vector for object i at frame t-1
||...||^2squared length of the difference (measures how far the embedding moved)
A tiny worked example
Frame 0: Red cup query = [0.2, -0.8, 0.3] in 3D embedding space.
Frame 1: Same cup reappears; fresh query = [0.22, -0.85, 0.28] (small natural variation).
Drift vector = [0.02, -0.05, -0.02]; squared length = 0.0004 + 0.0025 + 0.0004 = 0.0033.
If lambda = 10, penalty = 10 * 0.0033 = 0.033 (small, training allows it).
Without scene aggregation, fresh query = [0.5, -0.2, 0.8] (completely different); drift = ||[0.3, 0.6, 0.5]||^2 = 0.7, penalty = 7.0 (huge, training avoids it).
Result: training learns to keep queries close by re-using information from previous frames.

The equation says: predict well on every frame, but do not let your object identities (queries) bounce around wildly—smooth changes are cheaper than erratic ones, because when queries stay consistent the model's downstream predictions (bounding boxes and confidence scores) also stay consistent, eliminating jitter.

What can go wrong

What can go wrong

Fast erratic motion confuses the scene aggregation. If the robot spins or moves very quickly, the motion model's prediction of where previous features should align becomes inaccurate. Objects can blur or disappear too suddenly for the model to follow. Slow, smooth motion is much easier.
Heavy occlusions defeat feature persistence. If an object is blocked by a wall for many frames, its query embedding may drift or be reassigned to track a different object. The longer the occlusion, the higher the risk of confusion.
New objects appear with old query identities. If the model reuses a dormant query for a completely new object (e.g., someone places a different cup on the table), the identity match is wrong. The model lacks a strong 'new object' signal.
Done right: consistent camera calibration and small timesteps. When motion estimation is accurate and frames are captured frequently enough (small temporal gaps), the aggregation stays aligned and queries remain stable. Real-time robot systems with high frame rates benefit most.
What a runnable demo should prove

What a runnable demo should prove

Build a simple dataset: sequence several video clips from a moving phone or robot camera, manually label 3–5 objects in each clip with 3D positions and persistent IDs. Train Embodied-DETR for a few epochs (no need for real benchmark scale). Then run both the independent-frame baseline and Embodied-DETR on held-out clips and measure: (1) how much the bounding box center jiggles frame-to-frame for the same object (position variance); (2) how often the model correctly re-identifies the same object in the next frame (ID recall). The demo succeeds if Embodied-DETR's jitter is visibly smaller and ID recall is higher, especially when objects briefly leave the frame.

Stability gain = (jitter_baseline - jitter_embodied) / jitter_baseline * 100%; Identity recall = count(correct same-object matches) / count(total object occurrences)

The visual output should show bounding boxes that stay smooth and assigned identities that persist—not boxes that dance around or flip between 'cup A' and 'cup B' on the same object.
