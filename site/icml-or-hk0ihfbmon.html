Adaptive Token Refinement in Long-Tailed Large Vision-Language Models Fine-Tuning

Fine-tune long-tailed vision-language data by downweighting easy head-token outputs and by masking visual inputs so rare examples get more useful learning pressure.

Paper explainersAll themesMultimodal

A long-tailed dataset has a few frequent categories and many rare ones. During fine-tuning, a large vision-language model quickly learns the frequent head categories because they appear often and dominate the gradient, meaning the update signal computed from the loss that changes the model's internal weights. The rare tail categories then receive too little effective training because their examples arrive less often and their gradients are smaller in total. Standard long-tailed methods often rely on knowing the class counts in advance, yet downstream multimodal tasks do not always provide that clean distribution information, meaning a clear record of how often each case occurs. ATR tackles the imbalance at the token level. It uses a bounded adaptive loss on output tokens, meaning the predicted words or labels generated by the model, to filter and reweight easy head-dominated signals. It also masks visual input tokens, meaning some region features are hidden during training, so the model is forced to spread probability mass across alternative evidence paths because its favorite shortcut cue is not always available. The goal is to slow overfitting on common cases and create more room for rare cases to shape the model.

Zero assumption version

Why fine-tuning makes imbalance worse

Pretrained vision-language models start with broad knowledge, but fine-tuning on an imbalanced downstream set can erase that advantage. The model sees many easy head examples early, fits them rapidly, and then keeps receiving strong updates from the same patterns. Rare examples arrive less often and are overshadowed by the common ones, so the model does not learn to separate them well because repeated head updates keep steering the shared representation toward the easy frequent patterns.

This problem is sharper in multimodal settings because both the output stream and the visual input stream can become biased. On the output side, the model may assign too much confidence to frequent labels or frequent phrases. On the input side, it may latch onto a small set of common visual cues that explain the head classes and stop exploring other region combinations that would matter for the tail.

The paper's move in one sentence. Refine both sides of training: reduce the influence of easy head-heavy output tokens and perturb the visual input tokens so the model keeps learning beyond the most common cues because those cues are no longer available on every update.

The algorithm as a flow

What it actually does

Monitor output-token difficulty

Estimate which predicted output tokens are easy and repeatedly associated with frequent head data, because those tokens are the main source of early overfitting.

Apply bounded adaptive loss

Downweight or filter token losses once they become too dominant, so already-solved head outputs no longer monopolize the model updates.

Mask part of the visual input

Hide some visual tokens during fine-tuning so the model must distribute learned weighting over more than one common evidence route, because the usual shortcut patch is missing in part of training.

Train without explicit long-tail frequency assumptions

Adapt the weighting and masking from the training dynamics themselves, which reduces dependence on knowing the class distribution, meaning the frequency pattern of examples, in advance.

Fine-tune the shared vision-language model

Update the model under the refined token-level learning signals so both the output stream and the visual evidence path become less head-dominated.

What the paper changes

What the paper changes

The paper changes the learning pressure applied during fine-tuning. It does not redesign the model. It redesigns which output tokens and which input tokens are allowed to dominate training.

The hidden quantity

The hidden quantity

measured quantity  =  how much of the update budget is being wasted on already-solved head patterns

The hidden quantity is the share of training updates spent reinforcing head examples that the model already predicts confidently. That waste is not obvious from average loss alone, because the head classes can still contribute large cumulative gradients simply by appearing often.

ATR tries to reduce that waste in two places. On the output side, it caps and reweights dominant token losses so common predictions do not keep receiving full update strength. On the input side, it masks part of the visual evidence so the model cannot rely only on the most frequent cue pattern, which means it must encode additional clues that can support tail cases. Together these steps make room for tail examples to influence the representation.

Why it works

Why refining both output and input tokens helps the tail

The bounded adaptive loss matters because imbalance is not only about how often examples appear. It is also about how long they continue to produce influential gradients after they are already easy. If frequent head outputs keep full loss weight after the model has largely mastered them, those examples continue to steer learning. Bounding and reweighting them reduces that inertia and frees updates for harder cases.

Visual token masking matters because head classes often come with repeated shortcut cues. A bird class might be learned from a dominant background pattern, or a frequent product class might be learned from one highly visible logo region. If those cues stay available in every pass, the model has little reason to search for alternate evidence. Masking breaks that shortcut and pushes the model to encode additional visual signals that may be more useful for tail categories and for generalization.

Using both operations together is important because output-side reweighting alone does not change what evidence the model looks at, and input-side masking alone does not stop easy head outputs from dominating the loss. The output operation reallocates update strength, and the input operation broadens the evidence basis that can benefit from that update strength.

A plain loss view

First in words:

The training objective reweights output-token losses according to their current dominance and adds random visual masking during the forward pass. The model is then updated on the masked input and the refined output loss.

Then the compact form:

training_loss = adaptive_output_token_loss on masked_visual_input

Every symbol:

adaptive_output_token_lossthe bounded and reweighted loss applied to predicted output tokens

training_lossthe effective loss used for fine-tuning under ATR
A tiny worked example
Suppose a frequent head class is predicted correctly with high confidence on many training examples.
Under a plain loss, each of those examples still contributes another strong update simply because there are so many of them.
ATR reduces the weight of those easy output tokens once they become dominant.
Now suppose the model also relies on one repeated visual patch to identify that head class.
Masking that patch during some updates forces the model to use other cues, which gives rarer classes a better chance to shape the representation.

The method is adaptive because it reacts to current training dynamics, not to a fixed class-frequency table that must be known in advance.

What can go wrong

What can go wrong

Over-downweighting can hurt the head unnecessarily. If the adaptive loss suppresses head tokens too aggressively, the model can lose useful frequent-pattern knowledge rather than merely reducing redundancy.
Masking can remove the only decisive cue. Some examples truly depend on one small visual region, so indiscriminate masking can make training noisy because the needed evidence is temporarily absent.
Tail categories may still be too scarce. When the rare classes appear only a handful of times, redistributing learning pressure helps only modestly because there are still too few examples to show the model the full variation of those cases.
Done right. The framework is most useful when the base model already has broad visual knowledge and the main problem is how fine-tuning allocates its update budget under imbalance.
What a runnable demo should prove

What a runnable demo should prove

Take an imbalanced vision-language classification or instruction-following dataset with clear head and tail categories. Compare plain fine-tuning against ATR. Log output-token weights, masked visual regions, head accuracy, tail accuracy, and calibration on rare categories.

The demo should include examples where the model initially uses one easy head cue and later learns alternate evidence after masking. A convincing result shows that tail performance rises because repeated easy head tokens stop consuming so much of the training signal.

tail_gain = tail_accuracy_with_ATR minus tail_accuracy_with_plain_finetuning
