Handling noisy and uncertain information

Real-world data is messy with outliers and noise. How do optimization algorithms remain reliable when gradients are unreliable, data is heavy-tailed, or predictions are uncertain?

All themesField mapMathematicsAll explainers
What this is

In a perfect world, all your data is accurate and all your gradient estimates (the directions to move model settings) point exactly the right way. In reality, sensors malfunction, labels contain errors, and when you compute gradients on a small batch of examples, they point in random directions that average out only if you wait long enough. Some datasets have outliers—one bad example that is nothing like the rest. Financial data, medical measurements, and sensor readings all have this problem. When gradients are unreliable, algorithms might chase a false direction and waste computation, or they might freeze because every step looks equally bad.

The mathematical challenge is that standard algorithms assume gradients are unbiased (their average points the right way) and have bounded variance (they do not vary wildly). In heavy-tailed data or with outliers, both assumptions break. An outlier can pull the gradient in a completely wrong direction. Some problems have a few extremely large gradients that dominate the average, drowning out information from normal examples. Classical algorithms like gradient descent can spiral out of control or get stuck. Detecting and handling outliers requires extra steps and slows things down.

Papers address this with several tactics. Some use statistics that tolerate extremes: replace the mean gradient with the median or a trimmed mean that ignores extreme values so outliers do not distort the average. Others use adaptive learning rates that shrink automatically when a gradient looks suspicious, which means the algorithm takes smaller steps when it should not trust its direction. Some algorithms maintain a confidence level for each example, starting high and lowering it if that example consistently gives strange gradients, so it contributes less over time and does not mislead the model. Others use clipping: if a gradient is bigger than a threshold, scale it down so it does not dominate the average update. A few papers study when noise actually helps—sometimes random updates push the algorithm out of shallow local minima into better regions where it can find a better solution, which happens because noise jostles the algorithm forward, so the noise itself is useful if managed carefully. The pattern is: algorithms that work well when data is messy are algorithms that do not trust every signal equally.

How the work breaks down

When data has outliers and the directional cues (called gradients—the slopes telling you which way to move) bounce around randomly, algorithms need different tactics. One direction replaces traditional averages with statistics that ignore extremes. Another uses slow learning that shrinks when signals look wrong. A third treats each example differently based on how trustworthy it is. A fourth studies when randomness in updates actually helps the algorithm step out of shallow pits (local minima) into better regions because the jostling forward outweighs the noise cost. A fifth redesigns how we make decisions when the future is uncertain.

Regression and Clustering That Tolerate Data Shift

When data has outliers that pull the average far away from truth, standard regression breaks. These papers tackle the problem directly: how do you fit a model that works well even when the data you will see tomorrow looks different from the data you trained on today? The challenge is that if you optimize only for the data you have, outliers will distort the whole fit. You need a method that assumes the real data might be shifted or contaminated, and finds a solution that hedges against that.

The Linear Regression with Lewis Weights paper uses a mathematical technique called Lewis weights to identify which examples are trustworthy and which are suspicious. It rewrites the regression problem so that outliers have less pull on the answer, and does this faster than the old way because the weights automatically protect against extremes. The Variable Clustering paper applies the same idea: when you want to group related variables together, regression that hedges against data shift helps you cluster without letting a few wild examples ruin the grouping because the method downweights outliers before they distort the result. The Nested DRO paper (DRO means optimization that works across multiple data spreads) shows that if you build protection in layers—first against shifts that appear often, then against rare heavy-tailed contamination—you get better results than a single flat protection rule because each layer targets a different kind of deviation. Together, these papers show that treating data-shift protection as a mathematical property you can tune lets you handle messy data.

Optimization for Uncertain Futures and Decisions

Real decisions happen in the future when you do not know what data will arrive. You build a model today, but tomorrow the world has changed—customers behave differently, prices shift, demand spikes in unexpected places. The problem is that if you optimize only for the data you see now, your decisions will be bad when reality deviates. These papers ask: how do you choose actions that work well across a range of possible futures?

Efficient Assortment Optimization via DRO addresses a concrete business problem: which products should a store stock when you are not sure what customers will want? The paper finds decisions that stay good even when customer preferences are not what you predicted because it hedges against a set of plausible preference spreads (sets of possible customer types). Gen-DFL takes a different angle: instead of guessing what data shift might happen, it learns a model that knows it is uncertain, and makes decisions that minimize the worst-case loss if the model is wrong so that if you guessed the customer wrong, you still do okay. Diffusion-DFL uses a generative model to say 'the true data might look like this, or this, or this'—a set of possible futures—and finds decisions that work for all of them because it does not bet on a single prediction. Loss-Aware DRO Optimization says that some mistakes are worse than others (a bad medical decision costs more than a wrong price), so it includes the cost of each mistake when deciding what scenario to hedge against. All four papers converge on the same insight: rather than pretend you know the future, be explicit about your uncertainty and make decisions that do not fall apart when you are wrong.

Handling Extreme and Heavy-Tailed Noise

When gradients have extreme values—a few very large ones drowning out the rest—standard algorithms can swing wildly or get stuck. This happens with financial data, sensor networks, or any dataset with heavy tails (a few enormous values, not just noise). Traditional algorithms assume gradients are well-behaved: their average points the right way and they do not vary too much. Heavy-tailed data breaks both assumptions.

Improved Stochastic Optimization of LogSumExp solves a specific technical problem: computing with log-sum-exp, a function that appears in many machine learning algorithms, becomes unstable when some inputs are huge. The paper shows how to rewrite the computation so that extremes do not blow up the answer, and proves it converges even with heavy-tailed noise because the new form keeps numbers in a safe range. On the Provable Suboptimality of Momentum SGD proves something surprising: momentum, which usually speeds up gradient descent, actually slows you down when noise is extreme because momentum assumes you can trust the direction from the past step, but when noise is wild the past direction is misleading so you waste time tracking it. It shows via mathematics that vanilla gradient descent provably outperforms acceleration in the regime where you have wild, unpredictable noise—momentum wastes time on false directions while you need quick corrections. Bregman meets Lévy addresses heavy-tailed noise head-on by using a different kind of averaging. Instead of the usual arithmetic mean, it uses mirror descent—a method that reshapes how distances work in the problem so that extreme values have less influence on the average. The paper proves that even with Lévy-distributed noise (infinite variance), the algorithm still converges, just more slowly, because the reshaped distance metric protects against outliers. These three papers teach a hard lesson: when noise is extreme, your fast tricks often backfire.

Adaptive Methods and Learning Rates for Uncertainty

Instead of using the same learning rate for every step, adaptive methods watch the data and shrink the step size when things look wrong. If a gradient is huge and suspicious, take a smaller step. If the data shifts geographically or demographically, detect it and adjust. The idea is that learning rate should not be set once at the start; it should respond to what the data tells you.

Bulk-Calibrated Credal Ambiguity Sets creates a confidence interval around what the true data spread is. When test data looks different from training data (out-of-sample contamination), the algorithm does not panic and ignore it—instead, it says 'the true spread is somewhere in this set' and finds decisions that work for any spread in that set so you do not crash if you guessed wrong. Prior-aware and Context-guided Group Sampling takes a different approach: instead of trusting all training examples equally, it learns which ones are informative and which are noise, sampling more heavily from the good ones because informative examples teach the model faster. It treats this as an active selection problem where the algorithm asks 'which examples matter most?' Step-Size Stability in Stochastic Optimization proves that adaptive step-size methods like self-paced sampling are less sensitive to hyperparameter choices than vanilla SGD because the algorithm itself adjusts the step size so you do not need to guess it ahead of time. When step sizes respond to how noisy or stable each step is, the algorithm performs well across a wider range of settings because the adaptation shifts strategy when the data looks unreliable. All three papers share a philosophy: rather than commit to a fixed learning rate, watch what happens and adjust on the fly.

Data Quality and Sample Efficiency in Learning

When building models, not all data is equally useful. Some examples teach the model something new; others are redundant or noisy and waste computation. The challenge is that you often do not know in advance which examples matter, and you may not even be able to test your model on the real task until the very end. These papers ask: how do you pick training data smartly when you cannot see the future?

DUET addresses this in the context of large language models. When training data comes from multiple sources, different mixtures produce different final model qualities. The paper shows how to optimize which data to use more of, even when you can only see noisy signals from new tasks that your model has not seen before because it keeps trying different mixes and learning which ones work. The algorithm converges to the right mixture without needing perfect information about downstream performance. DRO via Generative Ambiguity Modeling (where DRO means finding strategies that work across multiple data spreads) uses a diffusion model to generate plausible versions of what shifted data (data that does not look like training examples) might look like, then trains against that full set of imagined futures. Instead of assuming one particular shift, it says 'the data could shift in many ways the diffusion model can generate,' and trains to handle all of them because it prepares for multiple possibilities at once. Non-Parametric Optimization for Scalable Learning attacks the problem from the data perspective: it finds which examples the model has learned well and which ones keep causing errors, and reweights the training process so noisy examples interfere less because downweighting them keeps the model's attention on clean signal. These three papers converge on a pragmatic insight: if you cannot ensure your data is perfect, at least be smart about which data you use and how you weight it.
