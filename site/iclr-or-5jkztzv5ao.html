Understanding Implicit Biases in Time-Series Foundation Models

Design choices in time-series models like patch size and loss function create unintended hidden side effects that shape how the model handles uncertainty and patterns.

Paper explainersAll themesTime Series & Sequential

When you train a time-series model, you tweak many dials: how to split the data, how to encode numbers, what loss function to use. Each dial seems like a simple technical choice. But this paper shows that each one carries hidden consequences that ripple through the model's behavior in unintuitive ways. A model trained with one loss function might confidently flatten uncertain predictions; trained with a different loss it might fluidly hop between patterns. The paper maps out these hidden effects so you can predict what will happen when you change a dial.

The dial-twiddling trap

You build a time-series forecasting model—you want it to predict what happens next in a sequence of measurements (stock prices, temperature, network traffic). You look at benchmarks, pick a few design ingredients to copy: how to slice the data into chunks (called patches), how to convert numbers into internal representations (embedding), and what error-penalty to use during training (the loss function). The model trains, you test it on standard benchmarks, and it works fine.

But here's the problem: when you deploy it on new data that looks different from the benchmark—more chaotic, noisier, with longer time horizons—the same dials that worked before now backfire. The model that learned to be accurate on familiar data suddenly predicts boring, middle-of-the-road forecasts when it should stay responsive. Or it gets tangled in frequency aliasing: when the data's natural patterns do not line up with your patch size, the model scrambles the signal. No one warned you these dials had hidden side effects.

In one sentence. Design choices like patch size, embedding type, and loss function quietly reshape how a time-series model handles uncertainty and patterns, in ways that do not show up on standard benchmarks.

The hidden quantity

The hidden quantity: Mean-reversion aggressiveness

measured quantity  =  how hard the model collapses forecasts to the mean

When a model is uncertain, it has to make a choice: hedge its bets by predicting a bland middle-ground, or spread its prediction across multiple futures. Mean-reversion aggressiveness is how strongly the model pulls predictions toward the average. It is a hidden quantity because the paper does not measure it with a single explicit number the model prints out; instead it infers it by looking at how forecasts scatter around the mean in different scenarios.

The paper estimates this quantity by training models with different loss functions and comparing how flat or spiky their forecasts are. A model trained with L2 loss (which penalizes large prediction errors uniformly) tends to aggressively regress to the mean—it learns that predicting the middle is the safest choice. A model trained with cross-entropy loss (which counts categories, like an LLM) does not have this pressure, so it stays looser and more exploratory.

Why it works

Why design choices create these hidden biases

Start with the loss function. During training, the model adjusts its weights (internal numbers) to minimize the error between its forecast and the ground truth. An L2 loss (squared error) punishes large mistakes severely—it says a 10-degree error is 100 times worse than a 1-degree error. This teaches the model to be conservative: predict the middle of the range and avoid extremes, because extreme guesses risk huge penalties. A category-counting loss (used in language models) works differently. It says I predicted category rain, the truth was sunny—one mistake. This loss counts all mistakes equally, so no guess is punished more than any other for being far from the mean. With equal penalties everywhere, the model learns to spread its predictions across multiple futures instead: hot, cold, or medium all cost the same if wrong, so it explores more of the space.

Now add patch size. A patch is a fixed chunk of data you feed to the model at once. If your data has a slow wave (repeats every 100 days) and you use a patch size of 1, the model sees the wave unfold gradually, step by step, and can learn it. But if you use a patch size of 16, and the wave does not align with the boundary every 16 steps, you introduce aliasing: the wave signal scrambles itself at the boundaries. The model sees broken patterns, so the learned focus weights (which pieces of the past matter for forecasting) become bimodal—the model focuses heavily on recent neighbors but barely on distant past, a form of defensive learning.

Finally, embedding type. An exact (continuous) embedding preserves distances: if two numbers are close in value, their internal representations stay close. A rounded (quantized) embedding first sorts numbers into bins, then tries to recover fine detail—it is like photocopying a photo and the photocopy has less detail. This difference means rounded embeddings introduce a bottleneck: the model cannot learn fine-grained patterns as easily, so it defaults to coarser behaviors like mean reversion.

The regression-to-the-mean formula

First in words:

Total loss equals the difference between the forecast and the real value, squared, multiplied by how much the model regresses. Formally: loss = alpha times the sum of the squared forecast errors, where alpha is set by the loss function you choose.

Then the compact form:

L2_loss = sum_i (forecast_i - actual_i)^2

Every symbol:

forecast_ithe model's prediction at time step i
actual_ithe true value at time step i
sum_iadd up the squared error for all time steps
L2_losstotal squared error; minimizing it teaches the model to avoid extremes
A tiny worked example
Suppose at time step 1: actual = 50, forecast = 60. Error: 60 - 50 = 10. Squared: 10^2 = 100.
At time step 2: actual = 55, forecast = 52. Error: 52 - 55 = -3. Squared: (-3)^2 = 9.
At time step 3: actual = 65, forecast = 53. Error: 53 - 65 = -12. Squared: (-12)^2 = 144.
Total L2 loss = 100 + 9 + 144 = 253. The large error at step 3 dominates. During training, the model learns that extreme forecasts (far from the middle) cause huge penalties, so it shifts strategy toward the middle of the data range.
In contrast, cross-entropy loss would count 1 wrong, 1 wrong, 1 wrong = 3 mistakes, regardless of magnitude. This loss teaches the model to explore multiple futures.

The squared term in L2 loss punishes distance from the true value; minimizing it teaches the model to predict safe middle values and avoid spreads.

What can go wrong

What can go wrong

Benchmark overfitting. A model that works perfectly on standard test sets may fail on real data with different frequencies or longer horizons. The design choices that worked for the benchmark data are not forward-compatible.
Aliasing from wrong patch size. If the data's recurring patterns do not align with patch boundaries, the model sees scrambled signals and cannot learn the true frequencies. Attention becomes defensive (high on neighbors, low on distant past).
Loss function mismatch. Using L2 or L1 loss on data with multiple valid futures (chaotic dynamics) forces the model to hedge with flat mean-reversion forecasts. Using cross-entropy on a regression task overly rewards exploration and may miss fine-grained tuning.
Quantization bottleneck. Quantized embeddings compress information into discrete bins. The model can only partially recover continuous structure, so it defaults to coarse behaviors.
Done right. Match your design choices to your data: use cross-entropy loss or quantile loss for chaotic data, choose patch size based on known frequencies, use continuous embeddings if precision matters.
What a runnable demo should prove

What a runnable demo should prove

Build a simple time-series forecasting task: a dataset with a slow component (a trend) and a fast component (daily oscillation), plus noise. Train two identical models except for the loss function: one with L2 loss, one with cross-entropy loss. On a test split of well-aligned data, both models should perform similarly. On a held-out test set with a longer or noisier horizon, the L2-trained model should show flattened forecasts (aggressive mean reversion), while the cross-entropy model should still spread its predictions. Vary the patch size for a third model: misalign patches so the fast oscillation gets scrambled. Watch the attention weights become bimodal and the forecast accuracy drop.

forecast_spread = variance of predictions over multiple time steps. Mean_reversion_ratio = (forecast_variance - true_data_variance) / true_data_variance. Lower spread and higher ratio = more aggressive mean reversion.

The demo proves that the same small dial (loss function or patch size) invisibly steers the model's forecast strategy, and that the effect is invisible in standard benchmarks but devastating on new data.
