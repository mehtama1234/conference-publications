GT-Space: Heterogeneous collaborative perception

When self-driving cars with different cameras and sensors share what they see, build a common reference frame from the ground truth so each car only needs one simple adapter to join in.

Paper explainersAll themesRobotics & Control

In autonomous driving, having multiple cars share what they observe makes sensing more complete: one car sees a pedestrian that another car's angle missed. But the catch is that different cars have different equipment—one has a lidar (a spinning laser), another has cameras, a third has both. Their sensory data is in completely different formats. GT-Space solves this by building a single universal reference frame directly from the ground truth (the real-world labels of where objects actually are), so every car can translate its own sensor readings into that shared space with just one simple adapter layer, without having to retrain or negotiate with every other car individually.

Zero assumption version

Why sharing sensor data between different cars is hard

Imagine three self-driving cars with different cameras. Car A has a wide-angle lens, Car B has a telephoto lens, and Car C has an infrared camera. Each produces a different-looking output—different pixel values, different scales, different color channels. They all see a stop sign, but their raw sensor data looks totally different.

A naive fix would be: teach each car's encoder (the first part of its neural network that processes raw pixels into meaning) to recognize stop signs in its own style. But now you have a problem: when Car A wants to share what it learned with Car B, the two encoders speak different languages. You could write a translator (a new neural network layer) that converts Car A's format to Car B's format, then another translator from A to C, then B to C—that is three adapters just for three cars. With fifty cars, that is 1,200 pairwise adapters. Retraining any one encoder breaks every adapter it touches.

The method in one sentence. Instead of teaching each car to translate to every other car, build one golden reference frame from the real-world ground truth, then each car just learns to translate into that one shared space.

The algorithm as a flow

What it actually does

Extract ground truth features

From every real-world label (a stop sign at coordinates X, Y), compute one master list of numbers.

Each car builds its own adapter

Train a small neural network that maps this car's sensor readings into the golden reference frame.

Map each car's features into the shared space

When a car observes a scene, its adapter translates what it sees into coordinates that the ground truth used.

Fuse adapted features with a contrastive loss

A fusion network learns which adapted features actually agree with each other, pulling similar observations closer and pushing noise away.

Make the final detection

The fused features feed into an object detector, which outputs the stop sign location.

What the paper changes

What the paper changes

Instead of training car-to-car translators (adapters that convert one car's format to another car's format), the paper introduces one golden adapter per car that translates only into the ground truth space.

the object it moves  =  Per-car adapter module
The hidden quantity

The alignment strength

measured quantity  =  How well each car's features match the ground truth

The ground truth space is not just a passive reference—it is a measurable target. The paper monitors how tightly each car's adapted features cluster around the ground truth labels. When a car's adapter does its job well, the adapted features land near where the ground truth says objects should be. This alignment strength tells you whether a car's sensor and adapter are trustworthy.

The paper estimates this by computing contrastive losses: for each object in the scene, it pulls adapted features that should agree (because they see the same stop sign) close together, and pushes apart features that should disagree (noise, misaligned cars, objects that are not there). Stronger alignment means less pulling needed—because if each car has already adapted its sensor readings close to the ground truth space, the adapted features are already near each other, so the contrastive loss only has to nudge them slightly rather than drag them across a wide gap.

Why it works

Why it works

Ground truth is a universal translator. Every object in the world has a real location. If you encode that location once (as a list of numbers), every car can learn to map its own raw sensor readings into that same encoded location, because they all see the same world. A car with a wide-angle camera learns a different adapter than a car with infrared, but both adapt toward the same target—reality.

This beats pairwise adapters because you remove the negotiation. With pairwise translators, Car A and Car B must agree on a shared format just between them. If a third car joins, it has to agree with both A and B independently, and those two agreements might conflict. Ground truth is neutral ground: it is not anyone's camera, it is the world itself. So every adapter converges to the same target and they harmonize automatically.

The contrastive learning step (pulling true observations close and pushing noise away) then refines the alignment. Once all cars have spoken their features into the shared space, the fusion network learns which features truly agree. This is cheap—you are not retraining encoders—you are just learning which translated features should listen to each other.

The alignment loss

First in words:

For each adapted feature, measure how well it agrees with the ground truth labels and other cars' adapted features. The total loss penalizes features that drift away from the ground truth space or disagree with features that should agree.

Then the compact form:

L = L_contrastive + lambda * L_alignment

Every symbol:

Ltotal loss to minimize
L_contrastivehow much adapted features from the same object disagree
L_alignmenthow far adapted features drift from the ground truth space
lambdaweight balancing the two losses
A tiny worked example
Suppose car A adapted a stop sign feature to the ground truth space: position 100. The ground truth says position 100. Alignment loss: 0.
Car B adapted the same stop sign: position 105. Ground truth says 100. Alignment loss: (105-100)^2 = 25.
Car C adapted it: position 98. Alignment loss: (98-100)^2 = 4.
Contrastive loss then checks: do A, B, C agree despite the noise? Pull closer. Fusion network sees B is slightly off (25 penalty) and weights A and C higher.
Total loss = sum of individual penalties + how much the fusion network has to work to reconcile disagreement. Low loss means features align well.

The mechanism: align to ground truth (not to each other), then let the fusion network learn which aligned features to trust.

What can go wrong

What can go wrong

Ground truth labels are wrong or incomplete. If the training data has mislabeled stop signs or entire objects missing, the golden reference frame is corrupted. Every adapter then learns to align to falsehood. This is why the paper tests on multiple datasets and real-world data to catch this.
A sensor is completely broken or gives nonsensical output. If car B's camera suddenly goes dark, its adapter learns to map darkness into the golden space, which is noise. The contrastive loss should suppress this car's influence, but if the fusion network is not careful, weak alignment signals can still cause errors.
Adapters overfit to the specific conditions they train on. An adapter trained on sunny daytime roads will fail at night. The ground truth space was built from daytime labels, so nighttime sensor readings do not have a clear target. The paper mitigates this by training on diverse weather and time-of-day data.
Done right: works across different sensor types. If ground truth is accurate and training is diverse, the same adapter works for lidar, camera, infrared, and even a new sensor that was not in the training set, as long as it sees the same world.
What a runnable demo should prove

What a runnable demo should prove

Build a toy scenario with three agents: one with clear vision, one with noisy vision, one with rotated vision (thinks north is south). Give them a ground truth reference frame (e.g., five landmark objects at known coordinates). Have each agent learn its own single adapter to project its noisy readings into the shared space. Measure how well the adapted features cluster around the ground truth landmarks. Then add a fourth agent with a completely different sensor type (or simulate one by perturbing the signal differently). Show that it adapts to the same space with no retraining of the first three.

fusion accuracy = (number of correctly detected objects by the fused ensemble) / (total objects in the ground truth)

The demo must show that adding a new car with a new sensor type does not require retraining any existing adapter—just train one new adapter for the new car, and it instantly joins the team because they all speak the ground truth language.
