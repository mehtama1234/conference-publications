From Winning to Understanding: A Diagnostic Long-Horizon RTS Benchmark for LLMs

Build a long real-time strategy benchmark that separates winning skill, rule-change tolerance, and human steerability so failures can be diagnosed instead of hidden inside one score.

Paper explainersAll themesAgents & Tool Use

This paper is about evaluation, not a new game-playing policy. The authors argue that long-horizon agents need a benchmark where decisions unfold over many steps, opponents fight back, and human instructions can redirect play mid-game. Their Red Alert RTS setup does that with a hierarchical interface that asks the model for budgeted high-level decisions, then executes them in a fixed way so scores reflect planning quality instead of interface noise.

Zero assumption version

Why long-horizon decision agents are hard to judge

Many agent benchmarks end after a short interaction or use tasks where the environment does not push back. That misses a core difficulty in long games and real control problems because a weak early choice can damage the next hundred steps.

A second problem is that one final win rate hides why an agent failed. A model may lose because it cannot adapt when rules change, because it cannot follow a human redirection, or because it spends resources badly. The paper builds a benchmark that records those failure modes separately so a researcher can tell what improved and what did not.

The paper's move in one sentence. Create a reproducible RTS benchmark with fixed low-level execution, head-to-head play, rule-shift tests, and steerability tests so long-horizon agent behavior can be measured from several angles.

The algorithm as a flow

What it actually does

Give the model a bounded command interface

The model outputs macro or tactical intents at a low frequency so the benchmark measures planning choices instead of mouse-level execution skill.

Execute commands in a fixed way

The engine turns those intents into game actions deterministically because repeatable execution makes comparisons fair.

Run head-to-head matches

Models play against each other so competitive strength can be summarized with an Elo-style rating.

Perturb the rules

Small rule-style changes are introduced so the test can measure whether the agent adapts when old habits stop working.

Inject human instructions

Standardized language interventions redirect the agent mid-match so steerability can be measured under the same game pressure.

What the paper changes

What the paper changes

The paper changes the evaluation target. Instead of asking only whether a model wins, it asks whether the model wins, adapts, and remains steerable under the same long-horizon setting.

The hidden quantity

The hidden quantity

measured quantity  =  whether the agent is building a stable long-term game plan or only surviving one local choice at a time

The important hidden quantity is planning stability across a long match. You cannot observe that quantity from one command. You see it only through delayed effects such as whether the economy keeps growing, whether scouting creates later advantages, and whether the agent can revise its plan when conditions change.

The benchmark exposes this hidden quantity by logging several traces alongside the final match result. That helps because long-horizon quality should leave footprints in spending, combat tradeoffs, and map coverage before it appears in the final winner label.

Why it works

Why the benchmark is informative

The hierarchical interface matters because it narrows the control surface to high-level choices. That keeps the benchmark focused on strategic decision quality because low-level execution details are standardized.

The diagnostic split matters because three common abilities pull apart in practice. A model can win under familiar rules and still fail after a rule shift, or it can play well until a human asks for a new objective. By measuring these dimensions separately, the benchmark can show which capability actually changed instead of treating all failures as the same event.

Math after the picture

A compact benchmark score

First in words:

A simple summary score can combine competitive strength, rule-shift tolerance, and steerability with chosen weights so one table can still reflect the three main benchmark goals.

Then the compact form:

benchmark_score = w1 * strength + w2 * adaptation + w3 * steerability

Every symbol:

benchmark_scoreone summary number for the full benchmark
strengthcompetitive performance from head-to-head matches
adaptationperformance after rules are changed
steerabilityhow well the model follows standardized human redirections
w1, w2, w3weights that decide how much each diagnostic matters in the summary
A tiny worked example
Suppose one model scores strength = 80, adaptation = 55, and steerability = 70.
Use weights w1 = 0.4, w2 = 0.3, and w3 = 0.3.
Then benchmark_score = 0.4 * 80 + 0.3 * 55 + 0.3 * 70 = 69.5.
The score is not driven only by winning because the weak adaptation score pulls the total down.

The real paper reports separate diagnostics, and that separation is the main contribution because it tells the reader why a model scored well or badly.

What can go wrong

What can go wrong

The interface can hide some useful skills. If the high-level command set is too narrow, a strong model may look weak because it cannot express a valid strategy through the allowed actions.
One game may not cover every long-horizon failure. A model can score well in this RTS and still fail elsewhere because another domain may stress memory, timing, or coordination in a different way.
Summary ratings can still mask tradeoffs. If readers focus only on the combined score, they can miss that one model is more steerable while another is more adaptive, so the benchmark should still be read dimension by dimension.
Done right. The benchmark is valuable because it makes long-horizon failures inspectable by pairing competitive play with clear diagnostics.
What a runnable demo should prove

What a runnable demo should prove

Build a stripped-down strategy game with fixed low-level execution, a short list of high-level commands, and two or three rule variants. Evaluate several decision agents in head-to-head play, then rerun them after a rule change and after a standard human redirection such as shifting from expansion to defense.

The demo should show that the same final win rate can come from very different internal patterns because resource growth, combat tradeoffs, and map coverage traces separate stable planning from brittle play. That matters because a useful benchmark should explain the score, not only report it.

diagnostic_gap = max(strength, adaptation, steerability) - min(strength, adaptation, steerability)

A convincing demo proves that the benchmark can distinguish winning from understanding because it records where the agent's long-horizon plan holds together and where it breaks.
