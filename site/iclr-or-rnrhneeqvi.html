Map Worlds: Compositional Generalization via Spatial Transfer and Length Scaling

A map-navigation testbed cleanly separates how models learn rules that work in new places from how they learn to solve harder versions of the same problem.

Paper explainersAll themesLearning Theory

When you learn a rule like 'go to the nearest food' in one city, you can use it in any city without retraining. This is compositional generalization: recombining known rules to handle new situations. Yet we lack controlled experiments that measure the two halves of this skill separately: systematicity (applying a learned rule to new environments) and productivity (solving harder versions of the same problem). This paper builds a map-navigation world to test both cleanly, revealing what data and training methods make each one work.

Zero assumption version

Two puzzles hidden in one word

When we say a model generalizes, we usually mean one of two different things. First: does it apply a learned rule to a new situation it has never seen (like recognizing cats in photos taken with a different camera)? Second: can it handle a harder version of something it practiced on (like finding the shortest path through a maze with more rooms)? We lump these together as compositional generalization, but they are mechanically different, and we have no clean testbed that isolates them.

Existing benchmarks mix these two dimensions together. When a model fails at generalization, you cannot tell if the problem is that it does not understand the underlying rule, or if it simply cannot handle the increased complexity. A beginner would try to fix everything at once by adding more diverse training data, but without knowing which dimension is actually stuck, you end up blind-searching.

The puzzle: A single controlled world where you can measure spatial transfer (does the learned rule work in new maps?) and length scaling (does it work on longer routes?) independently.

The algorithm as a flow

What it actually does

Build a map world

Create a testbed where an agent navigates grids (maps) using a simple rule like shortest path to a goal.

Split the test in two

Spatial transfer: can the learned rule work in new maps? Length scaling: can it handle longer paths?

Control training data carefully

Vary how many different training maps the model sees and how long the training paths are.

Measure what breaks

See which failures are caused by not understanding the rule (transfer) and which by not handling complexity (scaling).

Compare learning methods

Test supervised learning (direct answer: here is the shortest path) versus reinforcement learning (reward the agent for reaching the goal).

What the paper changes

The one thing that changes

The paper changes the training data the model sees: how many different maps, how long the shortest paths are, and how those are selected. It also compares two fundamentally different ways to learn: supervised learning (teaching the rule directly) and reinforcement learning (letting the agent search and rewarding good outcomes).

the object it moves  =  training data and learning method
The hidden quantity

The hidden quantity: coverage and length exposure

measured quantity  =  effective coverage and length boundary

The paper introduces two measurable quantities. Coverage is how many distinct training scenarios the model sees: if training uses only 5 unique maps out of 100 possible ones, coverage is low. Length exposure is what the longest path the model trained on was: if all training paths were 3 steps, the model never learned how to think in the mindset of a 10-step path.

The paper measures these by tracking during training how many different maps have been visited and what the maximum path length in the training set was. Success at spatial transfer correlates strongly with high coverage (seeing many different maps). Success at length scaling correlates strongly with exposure to neighboring-but-longer examples (training on paths just beyond the current difficulty).

Why it works

Why separating these two dimensions works

When a model fails at a new map, we want to know: did it not understand the rule, or did the rule-application step break because of new complexity? By testing transfer on tiny new maps (same complexity, new scenario) and testing scaling on long familiar maps (new complexity, same scenario), you ask each question in isolation.

Spatial transfer succeeds when the training set has enough different maps that the model learned the rule is place-independent. If training used only 2 maps, the model might memorize map-specific tricks instead of learning the abstract rule. With 10 different maps, even modest diversity is enough: the model is forced to generalize because no two maps are identical.

Length scaling works differently. A model that has only seen 3-step paths cannot simply apply the rule on a 10-step path; it has never practiced thinking in the coordinate system of longer planning. The breakthrough is exposure to neighboring-but-longer examples: training on 3-step and 4-step paths teaches the model how to extend thinking by one step, then the next. Jumping from 3-step directly to 10-step training fails because the intermediate reasoning steps are missing.

Reinforcement learning (agent search with rewards) stabilizes the optimization: when the agent explores, it can discover longer paths naturally. But supervised learning (direct teaching) achieves the same ceiling for transfer and scaling when given the right data. This tells us the data properties matter more than the learning algorithm, though RL does reduce variance.

Math after the picture

Measuring coverage and scaling readiness

First in words:

success in transfer is proportional to number of distinct training maps divided by total possible maps (coverage), while success in scaling depends on the maximum training path length relative to test path length (length gap)

Then the compact form:

transfer_score = 1 - (1 / sqrt(num_training_maps)) scaling_score = 1 - (1 / (1 + exposure_factor)) where exposure_factor = max_train_length - average_train_length

Every symbol:

transfer_scorehow well the rule works on new maps, 0 to 1
num_training_mapshow many different maps in training
scaling_scorehow well the rule handles longer paths, 0 to 1
max_train_lengththe longest path the model practiced on
average_train_lengthtypical path length in training
exposure_factorhow much training stretched to longer paths
A tiny worked example
Scenario 1 (Low coverage): num_training_maps = 2. transfer_score = 1 - (1 / sqrt(2)) = 1 - 0.71 = 0.29. The model memorized.
Scenario 2 (High coverage): num_training_maps = 20. transfer_score = 1 - (1 / sqrt(20)) = 1 - 0.22 = 0.78. The model learned the rule.
Scenario 3 (Poor scaling readiness): max_train_length = 5, average_train_length = 3. exposure_factor = 5 - 3 = 2. scaling_score = 1 - (1 / (1 + 2)) = 1 - 0.33 = 0.67.
Scenario 4 (Good scaling readiness): max_train_length = 10, average_train_length = 6. exposure_factor = 10 - 6 = 4. scaling_score = 1 - (1 / (1 + 4)) = 1 - 0.20 = 0.80. More boundary exposure.

Higher coverage and greater length exposure push the hidden quantities toward 1, enabling the model to generalize to new places and harder problems.

What can go wrong

What can go wrong

Memorization over abstraction. If training uses only 1 or 2 maps, the model may memorize map-specific navigation patterns instead of learning the rule. The rule appears to work on the training maps by accident but fails on new ones. High coverage (many different maps) forces the model to abstract.
Length cliff: insufficient boundary exposure. If all training paths are 3 steps long and the test path is 10 steps, the model has never practiced extending its reasoning. It hits a wall. Training must gradually expose the model to paths just beyond current difficulty, not jump from 3 to 10 directly.
Confusing transfer and scaling failures. Without the separated testbed, a failure on a new long path could be blamed on either transfer (the rule does not work in new places) or scaling (the rule breaks when complexity increases). Measuring on new short paths and on familiar long paths independently reveals which mechanism is broken.
Done right. Train on many maps of varying sizes with a range of path lengths. Test transfer on new tiny maps (isolates rule understanding). Test scaling on familiar maps with longer paths (isolates complexity handling). This design separates the two mechanisms because each test changes only one dimension: new-map tests change the spatial environment but keep path length the same, so success or failure points directly to whether the rule transferred; long-path tests use familiar maps so the spatial rule is constant, leaving only complexity to vary.
What a runnable demo should prove

What a runnable demo should prove

Build a simple navigation task: a 4x4 grid with a goal marker, train a model to find the shortest path using supervised learning (give it the correct path) and reinforcement learning (reward reaching the goal). Measure two things independently: (1) transfer: test on new 4x4 grids the model never saw; (2) scaling: test on the original training grid but with 6x6 or 8x8 size.

Vary the training set: version A uses only 2 training maps with 3-step paths; version B uses 15 training maps with paths from 2 to 5 steps. Version A will fail transfer (memorized those 2 maps) and fail scaling (never practiced longer reasoning). Version B will succeed at both. The demo makes the data-dependence visible.

transfer_accuracy = (correct_paths_on_new_maps / total_new_map_tests) * 100 scaling_accuracy = (correct_paths_on_longer_routes / total_long_route_tests) * 100 compositionality_index = (transfer_accuracy + scaling_accuracy) / 2

The demo must show that the same model with the same architecture reaches different ceilings depending on how many maps it trained on and how long the training paths were. The testbed cleanly separates these two sources of generalization.
