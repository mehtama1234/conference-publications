Physics-Inspired All-Pair Interaction Learning for 3D Dynamics

A neural network designed to find how every object in a multi-body system pushes or pulls on every other object, using physics principles to make the learned rules work correctly even on new, unseen systems.

Paper explainersAll themesGraph & Geometric Learning

Predicting how a group of objects will move—a person's skeleton, molecules bouncing, or proteins folding—requires knowing not just what forces are there, but which objects are actually interacting with each other. Most recent models try to guess these connections from what they can see in the data, but they miss hidden interactions that matter. PAINET builds all possible object-pair connections into the model from the start, then learns which ones are actually strong. It uses physics-inspired attention (a technique from mathematics that mimics how physical systems minimize energy) to weigh each connection fairly, and ensures the learned rules work the same way no matter how you rotate or move the whole system.

Zero assumption version

The world before

When you watch a pendulum swing, or a protein fold, or a human walk, you are seeing the result of forces—pushes and pulls between the parts. To predict what happens next, you need to know two things: which pairs of objects are actually interacting, and how strong each interaction is.

Current models try to learn this by looking at the data they are given. They might see that one part usually moves with another, or stays close to it, and assume they are interacting. But this fails in three ways: first, they only learn connections they can literally see in the data; second, they miss interactions that happen inside objects and never show up in positions (like the flex of a tendon or the bent angle of a bond); third, when you test the model on a new system—a person of a different height, or a molecule with a different shape—these learned guesses often do not work because the scale or arrangement of the objects is different.

A beginner might try: build a model that takes all the positions, and routes every position through a learned graph that decides which connections exist. This often fails because the graph it learns is brittle—it is tuned to the exact shapes in the training data, not to the underlying physics.

The method in one plain sentence. PAINET assumes all object pairs interact, learns which interactions are important through physics-inspired attention (a mathematically grounded scoring mechanism), and enforces rotation/translation symmetry so the learned rules work on any system.

The algorithm as a flow

What it actually does

Encode positions

Take the raw 3D positions of all objects and turn them into a list of numbers (an embedding).

Score all pairs

For each pair of objects, compute an attention score using an energy-inspired formula, measuring how much that pair affects the system's total energy.

Aggregate interactions

Weight each pair's effect on an object's future motion by its attention score, then add all the weighted effects together.

Preserve symmetry

Ensure the learned rules treat rotation, translation, and reflection the same way (SE(3)-equivariance), so a rotated copy of a system predicts the same rotated motion.

Predict motion

Output how each object's position and velocity will change in the next time step.

What the paper changes

The one thing the paper changes

Most models learn which object pairs interact by building a flexible graph structure and guessing from the training data. PAINET instead computes an attention score for every pair using a fixed physics-inspired formula. The object being changed is: the mechanism that weighs how much each pair of objects influences the motion of each other.

the object it moves  =  pair interaction weights
The hidden quantity

The hidden quantity: pair influence score

measured quantity  =  pair influence score

The paper measures a quantity called the pair influence score: for each pair of objects (object A and object B), this number says how much A's motion is driven by B, or vice versa. It is based on a principle from physics: if two objects are interacting, then moving one should shift the system's total energy. Pairs that shift more energy are scored higher.

PAINET estimates this score using an attention formula derived from energy function minimization. In other words, it asks: if I nudge object B a tiny amount, how much does the system's total energy change? If the change is big, the pair is scored high; if the change is small, the pair is scored low. This is not guessed from data; it is computed using the current positions and learned features of both objects.

Why it works

Why it works: the causal chain

The core idea is that objects in physical systems interact according to forces, and forces are tied to energy. If you have an energy function describing the system, you can compute how much each pair contributes by asking: if this pair were removed, would the energy change a lot or a little? Pairs that matter change the energy a lot; pairs that do not matter change it hardly at all.

PAINET builds this principle into the model by using an attention mechanism derived from energy minimization. Instead of asking the model to guess which pairs interact from the data, it uses a fixed, physics-rooted formula to score every pair. This formula does not depend on the specific scale or arrangement of the system you trained on—it depends only on the relative positions and learned features of the objects. So when you test the model on a new system (taller person, different molecule, different protein), the scoring still works because it follows physics, not the memorized layout.

Additionally, PAINET enforces that its learned rules are equivariant to rotation and translation: if you rotate the entire system, the predictions rotate too, and if you shift it, the predictions shift the same way. This is automatic, because the model only uses relative positions and angles between objects, never absolute coordinates. This symmetry constraint makes the learned interactions transfer cleanly to new systems with new scales and orientations.

Math after the picture

The equation

First in words:

For each object i, its predicted future position is the sum over all other objects j of the attention score between i and j, multiplied by the learned interaction effect from j on i, all divided by a sum of attention scores to keep the total reasonable. The attention score is based on a quadratic form of the relative position and features between i and j, using a learned matrix.

Then the compact form:

position_i_next = sum_j [ attention_ij * interaction_effect_ij ] / sum_j [ attention_ij ]; attention_ij = exp( -0.5 * (r_ij^T M r_ij) ); r_ij = (position_j - position_i, feature_j - feature_i)

Every symbol:

position_i_nextpredicted position of object i in the next time step
attention_ijlearned importance score between objects i and j (higher means stronger interaction)
interaction_effect_ijthe learned change in i's motion caused by j
r_ijthe relative position and feature difference between objects j and i
Ma learned positive-definite matrix that weighs different dimensions of the difference
expexponential function (makes negative numbers become positive scores between 0 and 1)
A tiny worked example with two objects
Object A and Object B: distance between them is 2 units.
Relative vector r_AB = [2, 0, 0] (close on x-axis, far on y and z).
Learned matrix M: emphasizes x differences more (to capture a direct bond). M = diag(4, 0.5, 0.5).
Energy term: r_AB^T M r_AB = 2*4*2 + 0*0.5*0 + 0*0.5*0 = 16.
Attention: attention_AB = exp(-0.5 * 16) = exp(-8) ≈ 0.00034.
For comparison: if A and B were 10 units apart, energy = 2*4*10 = 80, attention = exp(-40) ≈ 0 (almost no interaction).
Learned effect if nearby: interaction_effect_AB = 0.15 (B pulls A forward a little).
A's motion update from B: 0.00034 * 0.15 ≈ 0.00005 (very small, because they are far).
If they were very close (r_AB = [0.1, 0, 0]): attention = exp(-0.02) ≈ 0.98, update = 0.98 * 0.15 ≈ 0.147 (much bigger).
The exponential ensures nearby pairs have high influence, distant pairs have nearly zero.

The attention score decays exponentially as objects move apart, because the energy term grows quadratically with distance, so close pairs always dominate the motion updates.

What can go wrong

What can go wrong

Scaling to systems with many objects. If a system has 1000 objects, computing attention for all pairs means 1,000,000 comparisons. This is expensive because the model must compute an attention score for every pair, and the compute time grows as the square of the number of objects. The paper includes a parallel decoder to speed up when the model answers a new question, but training on very large systems may still be slow because training requires computing all those attention scores many times.
Learning the weighting table. The model learns a weighting table (a table of numbers that says which dimensions of the difference between two objects matter most). This must capture the right physics for each system. If the training data is limited or noisy, this table might learn the wrong principles and fail on new systems anyway.
Equivariance constraints are hard. Enforcing SE(3)-equivariance (rotation, translation, reflection symmetry) is mathematically strict. If the model is not built carefully, it can leak information from absolute positions or orientations, breaking the symmetry and reducing transfer to new systems.
Done right: transfer works. When all three pieces are correct (energy-inspired attention, learned matrix, SE(3)-equivariance), the model's learned interactions transfer cleanly from training systems to new geometries, sizes, and configurations the model has never seen.
What a runnable demo should prove

What a runnable demo should prove

Build a simple 3D physics simulator: take 5 point masses connected by springs. Train PAINET on one configuration (e.g., the 5 points arranged in a line). Then test it on a completely different configuration (the 5 points arranged in a star, or a circle). Also test on the original configuration with one spring removed or softened. The demo should show: PAINET's predicted positions stay close to ground truth on the new configurations, because its learned attention weights still identify the spring interactions correctly; in contrast, a model that memorizes the interaction graph from training data fails on the new configurations, because it learned the wrong pairs or memorized the exact shape of the original arrangement.

transfer error = average distance error on new configuration / average distance error on training configuration; PAINET should have transfer error < 1.5x, baseline should have transfer error > 3x

The core mechanism: PAINET works on unseen system arrangements because it does not memorize which pairs interact, but learns to score pairs using physics-grounded energy principles that work regardless of shape or scale.
