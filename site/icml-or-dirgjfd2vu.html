Incremental Transformer Neural Processes

Speed up predictions on streaming data by remembering only the key parts of past observations instead of re-reading all of them.

Paper explainersAll themesTime Series & Sequential

When a sensor sends new measurements one by one, a Neural Process model must update its forecast instantly. Today's best models re-examine every past measurement to make each new forecast, which gets slower as more data arrives. This paper shows how to remember only the essential details from earlier data—the learned summaries that the model's early layers already computed—so the model does not have to re-process the raw numbers. Because the model has already learned which patterns matter, these summaries contain all the information needed for prediction. Mixing the new reading with cached summaries produces predictions just as accurate as re-reading everything, because the patterns are already captured in the summaries, not in the raw numbers; this happens orders of magnitude faster.

Zero assumption version

Every new reading forces a full re-scan

A streaming sensor produces one measurement at a time: humidity, stock price, temperature. To predict the next value, a Neural Process model (a model trained to build a pattern from examples and then predict new values) reads the whole history and builds a mental snapshot of the pattern.

A beginner would copy this snapshot for each new measurement: read all 1000 past readings, compute, predict. But when reading 2000 readings, the model must re-examine every measurement twice as many times. When readings arrive for a week, the cost grows to thousands of re-reads per update. The model becomes unusably slow.

The core issue. Standard models that use Transformer layers (deep neural architecture that looks at all past data to find patterns) must re-read all past data every time a new measurement arrives, making stream predictions slow.

The algorithm as a flow

What it actually does

Collect past summaries

Store the Key-Value cache from all earlier readings instead of the raw data.

Receive new measurement

One fresh data point arrives from the sensor or database.

Compute its Key and Value

Process the new reading through the model's first layers to make its summary.

Attend to cached history

Look up only stored summaries, not the original readings; score how relevant each past summary is to the current prediction.

Make prediction and cache result

Output the forecast for the next time step; save this reading's Key and Value for the next update.

What the paper changes

What changes: the way the model stores its memory

Instead of keeping all raw past measurements in memory, the model saves only the Key and Value representations (abstract learned summaries of each past reading, not the original numbers). These summaries capture the patterns the model's early layers have already extracted from each past number, so they retain the relationships the model needs to understand context. When a new measurement arrives, combining it with these cached summaries lets the model compute attention (relevance scores) just as accurately as if it had raw data, because the patterns are already encoded in the summaries. This works because the model learns, during training, which patterns matter most for prediction.

The hidden quantity

The hidden quantity: computational cost per update

measured quantity  =  Time per new forecast

This is simply how long the model takes to process one fresh measurement and make a prediction. It depends on how many past measurements the model must consult. If the model must re-examine all previous measurements, cost grows as the square of the history length (quadratic). If it only reads stored summaries, cost grows as a straight line (linear).

The paper estimates this using wall-clock runtime on real sensor streams. It measures runtime against other methods and counts how many mathematical operations each update requires.

Why it works

Why the method works: causal masking and memory shortcuts

Attention in Transformer models is a way to look at past observations selectively: it computes a weight for each past reading that says how relevant that reading is to the current prediction. Normally, computing these weights requires re-reading every past measurement to calculate how similar it is to the new one. This is expensive.

Incremental TNP adds causal masking: it tells the model that the future does not exist yet, so each new reading should only look at past readings, not try to peek ahead. This is realistic for streams (there are no future readings to read). It combines this with Key-Value caching, a trick from Large Language Models: instead of storing raw sensor readings, store the outputs of the early model layers (the Key and Value for each past reading, which are already the model's learned summaries). When a new reading arrives, the model only needs to compute attention weights between the new reading and these stored summaries, not between the new reading and all raw past data.

Because the stored summaries are smaller and simpler than raw data, this attention computation is much faster. The model trades a small loss of flexibility (the summaries are approximate) for a huge speed gain. The paper shows the summaries are accurate enough that predictions stay just as good.

A tiny worked example
Standard TNP with 100 past readings: recompute attention 100 times 100 = 10,000 comparisons per update.
Incremental TNP with 100 past readings: look up 100 cached summaries, compute 100 attention weights = 100 operations per update.
On 1000 readings: standard does 1,000,000 comparisons; incremental does 1,000. The speedup scales up: 100 readings gives 100x faster, 1,000 readings gives 1,000x faster.

As the stream grows, saving and reusing Key-Value summaries avoids re-reading the whole history, shrinking the update cost from quadratic to linear.

What can go wrong

What can go wrong

Cache grows over time. If the stream runs for weeks, the cache of Key-Values becomes a memory hog. The model must drop old summaries or use a sliding window to keep cache bounded.
Summaries are approximations. Key-Value caching stores learned summaries, not the exact raw data. If these summaries lose important information, predictions will suffer. The method relies on the summaries being accurate, which depends on training.
Causal masking changes learning. By enforcing that future readings are masked out, training becomes different from standard TNPs. The model learns under a new constraint and may converge differently or settle in different local optima.
Works when training and deployment match. If the model is trained on streams with causal masking and one-at-a-time prediction (generating one time step, then stopping and waiting for the next measurement), and then used on streaming data with the same setup, the learned summaries stay faithful and predictions hold up.
What a runnable demo should prove

What a runnable demo should prove

Build a toy time series with 500 data points (e.g., synthetic temperature that rises and falls, or real stock prices from a CSV). Train an Incremental TNP on the first 100 points, using the autoregressive training recipe from the paper (predict one time step at a time). Then stream in the next 400 points one by one. For each new point, measure (1) the prediction error on the next time step, and (2) the wall-clock time to make that prediction. Compare against a standard TNP that re-reads all history.

speedup_ratio = time_standard_tnp / time_incTNP; quality_match = | error_incTNP - error_standard |

The demo succeeds if incTNP stays within 5% of standard TNP accuracy while achieving at least 10x speedup by the 400th update.
