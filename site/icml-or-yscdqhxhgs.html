DexMachina: Functional Retargeting for Bimanual Dexterous Manipulation

Train robot hands to grasp and move objects like humans by starting with automatic object guidance that fades away as the learned policy takes over.

Paper explainersAll themesRobotics & Control

Robots with dexterous (nimble, five-fingered) hands can perform complex manipulation tasks, but teaching them to mimic human hand motion is hard: the embodiment gap means human hands and robot hands move differently, the action space is huge, and long sequences of movements have gaps where the object is touched by both hands in unpredictable ways. DexMachina solves this by using a curriculum where a virtual object controller guides the object first, then gradually weakens, letting the learned policy take over step by step.

Zero assumption version

The embodiment gap blocks learning from human demonstrations

A robot with a dexterous hand must learn to manipulate objects (turn them, move them, assemble them) by watching a human do it. The challenge: a human hand and a robot hand are built completely differently — humans have different finger lengths, joint limits, and how each limb moves. Plus, the robot must control many joints at once (large action space), and during long tasks, both hands often touch the object simultaneously, creating moments where the object motion becomes unpredictable (spatiotemporal discontinuities).

The naive approach is to retarget the human hand pose directly to the robot hand (solve the inverse kinematics to match positions), then train the robot to imitate those poses. But this breaks because the robot cannot match the human trajectory exactly, and there is no signal telling the policy what to do when the object slips or when the demonstrated grasp fails. The policy learns to copy positions, not to move the object.

The method. Start by having a virtual object controller (an invisible force) drive the object toward its target positions automatically. This removes the object dynamics puzzle. Then gradually weaken that virtual controller as the learned policy develops, so the policy smoothly takes over object control.

The algorithm as a flow

What it actually does

Start with strong virtual control

An invisible force on the object follows the demonstrated trajectory perfectly, using high control gains (large corrections).

Policy learns under guidance

The learned policy watches the object move correctly and learns hand poses and contact forces that keep it stable.

Measure policy progress

Track accumulated reward over recent training steps to estimate how well the policy is doing.

Decay virtual control exponentially

Every N training steps, reduce the virtual controller's strength (lower its gains) by a fixed ratio, like halving it.

Smooth handoff to the policy

By the end, the policy alone maintains the object, so the robot hand (not the invisible force) holds and moves the object.

What the paper changes

What the paper changes

The object that changes is the virtual object controller's strength (measured as control gains, how forcefully it corrects the object). It starts high and decays exponentially during training, creating a curriculum from easy (let the virtual force do the work) to hard (the learned policy must do it all).

The hidden quantity

The hidden quantity: Virtual controller gains

measured quantity  =  Virtual controller gains over time

The virtual controller is a physics force that pushes the object toward its target position and rotation. Its strength is set by gains (in control theory, the number you multiply the error by to get the force). High gains mean large corrections; low gains mean gentle nudges.

The paper tracks controller gains as they decay. Gains start at a high value (e.g., 100) to make the object track the human trajectory perfectly, then decay exponentially — each step multiplied by a decay factor like 0.99, so gains become 99, 98, 97, etc. By tracking this schedule, the algorithm knows when to stop relying on the virtual force.

Why it works

Why it works: The gradual handoff

The core problem is that object dynamics are hard: the robot does not know how hard to squeeze or push to make the object move, and if the object touches both hands (dual contact), tiny changes in grasp break everything. If the robot tried to learn object control from scratch with no help, it would spend thousands of training steps just discovering how to not drop things because most random hand actions result in dropping the object, so the learning signal is mostly negative, making exploration slow and inefficient. Then it would struggle even more during the complex bimanual moments.

DexMachina solves this by staging the problem. First, the virtual controller demonstrates the correct object trajectory (position, rotation, and joint angles for articulated objects) with zero ambiguity. The robot learns hand poses and contact patterns while watching the object behave perfectly. This decouples hand learning from object dynamics learning. Once the policy has learned stable grasps and rough hand motions, the virtual controller weakens. Now the policy must actively move the object, but the virtual force still provides small corrections (lower gains), so failures are gentle. Over many steps, the policy gradually takes ownership. The reward signal (how well the policy maintains the object state) tracks the policy's progress. When progress is steady, the virtual gains decay more aggressively. When progress stalls, decay slows. This adaptive schedule ensures the policy does not have to learn object control all at once.

Why this beats naive baselines: direct imitation (copy hand poses with no object reward) does not teach the policy to maintain the object, so it drifts because there is no signal penalizing object motion errors, only hand position errors. A baseline that starts with pure object control (no virtual help) spends too many steps learning to even make contact because most random hand motions miss the object entirely, providing no learning signal for weeks of training. DexMachina learns hand control first, then object dynamics, in a natural order that preserves signal quality at each stage.

Math after the picture

The virtual control equation

First in words:

Virtual control force is proportional to how far the object is from its target, times a gain that decays exponentially over training steps.

Then the compact form:

F_virtual(t) = K(t) * (G_target - G_achieved)

Every symbol:

F_virtual(t)Force applied by the virtual controller at training step t
K(t)Gain (control strength) at step t, decays exponentially
G_targetTarget object state from human demo (position, rotation, joints)
G_achievedActual object state achieved by the robot hand's motion
A tiny worked example
Start: gain K(0) = 100. Object is 0.5 meters away from target. Force = 100 × 0.5 = 50 Newtons (large correction).
Step 100: gain decays to K(100) = 100 × 0.99^100 = 36.6. Same 0.5 meter error. Force = 36.6 × 0.5 = 18.3 Newtons (gentler).
Step 200: gain is K(200) = 100 × 0.99^200 = 13.4. Force = 13.4 × 0.5 = 6.7 Newtons (very light touch).
By step 500, gain ≈ 1.5, force ≈ 0.75 Newtons. Policy must handle most of the error. By step 1000+, gain ≈ 0.001, virtual control is nearly zero.

As the gain shrinks, the virtual controller's grip loosens, forcing the learned policy to push harder and learn object dynamics incrementally.

What can go wrong

What can go wrong

Decay too fast. If the virtual controller weakens too quickly (high decay rate, like 0.9 per step), the policy is thrown into the deep end before learning stable grasps. Object slips. Reward collapses.
Decay too slow. If virtual control hangs around too long (low decay rate, like 0.999), the policy never stops leaning on it and never learns true object control. Transfers poorly to the real robot where there is no virtual aid.
Bimanual handoff fails. If one hand releases before the other has established a grip during the curriculum, the object drops. Requires tuning both hand policies jointly.
Adaptive schedule works. The paper uses reward history to set decay rate dynamically: if the policy is learning fast, decay is aggressive; if learning stalls, decay pauses. This keeps the curriculum right-sized.
What a runnable demo should prove

What a runnable demo should prove

Build a simple simulation: a robot hand (5-10 joints) and a cube or bottle on a table. Collect a 3-second human demonstration of picking up and moving the object. Run three training runs in parallel: (1) direct imitation (no virtual control, train on hand poses only), (2) no curriculum (pure RL with object reward, no virtual aid), (3) DexMachina (curriculum with exponentially decaying virtual control). Measure object tracking accuracy (how close the simulated object stays to the demonstrated trajectory) on held-out test runs every 100 training steps. Plot all three curves.

Object tracking error = mean absolute distance between achieved object position and target position over all timesteps in the trajectory

The demo must make impossible to miss: DexMachina's object tracking stays high throughout training and generalizes to new grasps, while both baselines struggle early and plateau low. The curriculum is the difference.
