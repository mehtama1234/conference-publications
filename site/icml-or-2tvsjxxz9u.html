Hybrid-Gym: Training Coding Agents to Generalize Across Tasks

Hybrid-Gym trains coding agents on reusable software skills so they transfer beyond one benchmark and handle broader engineering work.

Paper explainersAll themes

A coding agent that only learns to patch benchmark bugs often learns the surface form of that benchmark. Real engineering work is wider: find the right file, trace dependencies, run tests, inspect failures, and decide whether a change belongs in one function or across a subsystem. Hybrid-Gym targets those reusable skills directly.

Zero assumption version

Why single-benchmark training does not transfer far

Benchmarks such as issue-fixing suites are useful, but they emphasize one narrow end task. An agent can improve on that task by learning patterns tied to that dataset without becoming better at exploring codebases, tracing call paths, or designing a safe modification plan. When the task changes, those missing skills show up immediately.

The paper argues that coding work contains transferable subskills. Examples include locating the right function, finding dependent code, checking behavior with tests, and reasoning about whether a change is local or system-wide. If those pieces are trained directly, the resulting agent should improve on many downstream tasks because the same pieces appear across repositories and task types.

The paper's move in one sentence. Decompose coding trajectories into transferable skills, then build scalable synthetic tasks that train those skills before evaluating on real software benchmarks.
Why it works

Why this works: teach the reusable steps, not only the final patch

Hybrid-Gym builds training tasks around specific software skills such as function localization and dependency search. Those tasks are synthetic, which means they can be produced at large scale across many repositories. That matters because the agent gets repeated practice on the exact operations that sit inside broader engineering work.

The transfer comes from coverage of shared structure. A bug fix, a test update, and an architecture change all require codebase navigation and evidence gathering before the final edit. By strengthening those earlier steps, the agent improves on multiple downstream benchmarks because better exploration and validation lead to better end decisions.

Math after the picture

The transfer gain

First in words:

Measure how much training on Hybrid-Gym improves downstream task success compared with the base model. The key quantity is absolute gain in benchmark score after the synthetic-skill training phase.

Then the compact form:

gain = score_trained - score_base

Every symbol:

score_traineddownstream benchmark score after training on Hybrid-Gym tasks
score_basescore of the same base agent before Hybrid-Gym training
gainabsolute improvement caused by the synthetic-skill training stage
A tiny worked example
Suppose a base coding agent solves 29 of 100 benchmark tasks, so score_base = 29.
After Hybrid-Gym training it solves 54 of 100 tasks, so score_trained = 54.
Gain = 54 - 29 = 25 points.
If a second benchmark rises from 40 to 48, the gain is 8 points there.
The paper reports this style of absolute gain because transfer matters only if the agent improves on tasks that were not the synthetic training tasks themselves.

The reported gains include 25.4 points on SWE-Bench Verified, plus smaller gains on other coding benchmarks, which supports the claim that the trained skills transfer because improvement appears on tasks that were not the synthetic training tasks.

What can go wrong

What can go wrong

Synthetic tasks may be too shallow. If the generated tasks do not capture the hard choices in real software work, the agent may improve on the synthetic set without learning the planning depth needed downstream because the practice tasks would reward shortcuts instead of real engineering judgment.
Transfer may depend on repository style. An agent trained on one family of code layouts may still struggle on very different repositories because naming conventions and dependency patterns can change the search problem.
Benchmark gains can hide validation gaps. An agent may reach the right file faster but still ship weak patches if it does not learn to run and interpret tests carefully, because software success requires both search and checking.
Done right. The paper evaluates on several downstream benchmarks and also combines Hybrid-Gym with existing downstream training data, because that tests whether the synthetic tasks add value instead of only replacing another data source.
What a runnable demo should prove

What a runnable demo should prove

Create a toy repository with several files, a hidden dependency, and a failing test. Train one small agent only on end-to-end bug-fix examples and another on synthetic subtasks such as locating the relevant function, finding the dependent file, and selecting the right test to run. Then evaluate both on a new repository with a different layout.

The demo should show that the skill-trained agent reaches the correct file and validation path more often because it learned reusable search and checking behavior rather than one benchmark's surface patterns.

transfer_success = solved_new_repo_tasks / total_new_repo_tasks ; navigation_accuracy = correct_first_file / total_tasks

The important result is generalization. A good coding agent should improve on new repositories because the trained subskills reappear across tasks.
