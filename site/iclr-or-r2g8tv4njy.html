DriveAgent-R1: Advancing VLM-based Autonomous Driving with Active Perception and Hybrid Thinking

DriveAgent-R1 decides when to gather more visual evidence and when to reason from text alone, so driving decisions stay efficient on easy scenes and better grounded on hard scenes.

Paper explainersAll themesAgents & Tool Use

A driving agent often sees many scenes that are easy to classify quickly, plus a smaller number of scenes where the right action depends on a hard-to-read visual detail. If the system always uses heavy visual checking, it becomes slow. If it never does, it may miss the decisive evidence in complex scenes. DriveAgent-R1 learns a hybrid policy: use fast text-based reasoning on straightforward scenes, and actively call visual tools when uncertainty makes extra evidence worth the time.

Zero assumption version

The problem: passive perception misses decisive evidence

End-to-end driving systems based on vision and language can reason about high-level maneuvers, but many of them treat perception as passive. They consume the available visual input and then reason from whatever text summary or internal state they already have. That is risky when the scene contains an ambiguous object, an occluded lane marker, or a hard-to-read traffic signal.

A human driver does not handle every scene with the same depth of inspection. Some moments require a quick decision because the situation is clear. Other moments justify an extra look because one visual detail decides whether it is safe to proceed. The paper builds that choice into the agent.

The core idea in one sentence. Let the driving agent switch between fast text-only reasoning and tool-based visual checking, so it asks for more evidence only when scene complexity makes that extra cost worthwhile.

The algorithm as a flow

What it actually does

Step 1: Read the scene and form an initial plan

The driving agent processes the current road scene and proposes an action using its standard reasoning path.

Step 2: Estimate scene difficulty

The agent judges whether the current scene is simple enough for fast reasoning or uncertain enough to require more evidence.

Step 3: Call visual tools when needed

On uncertain scenes, the agent invokes active perception tools to inspect the exact parts of the visual field that matter for the decision.

Step 4: Combine evidence with planning

The new visual findings feed back into the driving plan, so the final action is grounded in observed scene details rather than in a coarse summary alone.

Step 5: Train the switch with progressive learning

A staged training process, including Cascaded RL, teaches when to stay fast and when to pay for deeper checking.

What the paper changes

What changes: perception becomes an action

The paper changes the role of perception. Instead of treating visual understanding as a fixed precomputed input, DriveAgent-R1 treats evidence gathering as a decision the agent can make during planning. That means the agent chooses not only what action to take on the road, but also whether it needs another perception step before committing.

the object it moves  =  the optional visual evidence query
The hidden quantity

The hidden quantity: evidence value

measured quantity  =  How much one more visual check would improve the driving decision

The important hidden quantity is evidence value. A visual tool call is helpful only when the extra observation changes the driving decision enough to justify the delay and compute. On a straight open road, evidence value is low because the action is already clear. At a cluttered intersection, evidence value is high because a small unseen detail can change whether the vehicle should yield, stop, or proceed.

The hybrid policy tries to estimate this quantity from scene complexity. When evidence value is high, the agent switches into active perception. When it is low, the agent keeps the fast path.

Why it works

Why it works: selective evidence gathering improves hard cases without slowing easy ones

The method works because the cost of deeper perception is unevenly useful across scenes. A uniform always-check policy wastes time on easy examples, while an always-fast policy leaves hard examples underinformed. The hybrid switch finds a middle ground by spending the expensive visual check only where uncertainty is high.

Active perception also improves interpretability because the system can point to the specific visual evidence it requested before deciding. Cascaded RL helps train this behavior because the switch decision, the tool call, and the final driving action all influence the outcome, and the framework needs them to learn together.

The decision rule: gather evidence when its value exceeds its cost

First in words:

A simple formulation is to call the visual tool only when the expected decision improvement from extra evidence is larger than the cost of taking that extra perception step.

Then the compact form:

use_active_perception if expected_improvement > perception_cost

Every symbol:

expected_improvementhow much the extra visual evidence is expected to improve the driving decision
perception_costthe delay or compute cost of gathering that evidence
use_active_perceptionthe choice to invoke visual tools on the current scene
A tiny worked example
Scene A is a clear open lane. Expected improvement from another visual check is small, say 1, while the cost is 3. The agent stays on the fast path.
Scene B is an occluded crosswalk. Expected improvement from another visual check is 7, while the cost is 3. The agent calls the visual tool.
The policy is useful because it spends effort where the scene can genuinely change the action.

The paper's reported gains fit this trade-off: selective active perception helps on long-tail complex scenes because those scenes need more evidence, while keeping the system practical for deployment because easy scenes skip the extra check.

What can go wrong

What can go wrong

The switch underestimates complexity. If the system treats a hard scene as easy, it will skip the visual check and may act on insufficient evidence.
The switch overuses active perception. If too many scenes trigger tool calls, the driving stack may become too slow for practical deployment.
Tools inspect the wrong region. Active perception helps only if the queried evidence matches the source of uncertainty, because only then does the extra check resolve the decision. A misplaced query adds cost without resolving the decision.
Done right: evidence gathering is selective and grounded. The method succeeds when the agent calls visual tools on the scenes where one missing detail would change the driving action, because that is where the extra check pays for itself.
What a runnable demo should prove

What a runnable demo should prove

Build a simulated driving task with two scene types: clear scenes where one forward view is enough, and ambiguous scenes where a targeted extra inspection reveals a hidden pedestrian, signal state, or lane boundary. Compare a passive planner against a planner that can decide whether to request another visual check. Record scene completion quality and average decision cost. The demo should show that the hybrid agent improves the ambiguous cases because it gathers the missing evidence before acting, while keeping easy scenes efficient by skipping unnecessary checks.

Selective-evidence gain = hard_scene_quality_improvement - extra_average_decision_cost penalty.

The demo must show that active perception is valuable because it is selective, not because the system simply spends more effort on every scene.
