Transferable Graph Solvers via Computational Reducibility

A single neural solver can tackle many graph problems by pretraining on related tasks, guided by the mathematical fact that some problems reduce to others efficiently.

Paper explainersAll themesGraph & Geometric Learning

Graph combinatorial optimization solves real-world problems like job scheduling and circuit design. A naive solver trains separately for each problem type, forgetting its knowledge when switching tasks. This paper asks: if one problem mathematically reduces to another, can a neural solver reuse its learned representation? By grounding pretraining in computational reducibility—the idea that one hard problem can be converted efficiently into another—a single model learns to solve multiple related problems while avoiding catastrophic forgetting.

Zero assumption version

The task-specific solver trap

Graph combinatorial optimization—finding the best arrangement that satisfies hard constraints—is everywhere: scheduling workers, coloring maps, selecting the smallest set that covers all nodes (MVC, MIS, MaxClique, MaxCut, and others). Each problem is NP-hard, meaning no fast exact solver is known, so neural networks (trainable function approximators that learn to guess good solutions) have become practical.

Today, a separate model is trained for each problem type. When you switch to a new problem, the model forgets. Retraining from scratch is wasteful. A beginner might hope that a model trained on MIS (find the largest independent set) would just transfer to MVC (find the minimum vertex cover)—these are related problems, after all. But without guidance, the learned features (internal patterns the model has tuned) are too specific to the original task; the model performs poorly on the new task and learns slowly.

In one sentence. The paper shows that when one graph problem mathematically reduces to another, a shared neural model can transfer knowledge between them, avoiding slow retraining and forgetting.

What it actually does

Build an expressive graph reader

Use GCON message passing to extract richer patterns from graph structure than naive local averaging.

Train unsupervised on energy functions

Each graph problem has an Ising energy formula; the model learns to output node scores that minimize it without labeled solutions.

Pretrain on a related-task group

Train the same model backbone on all problems in the computational reducibility chain (e.g., MVC, MIS, MaxClique).

Fine-tune on the target task

Use the pretrained weights as a starting point; adapt only the output layer or fine-tune the whole model on the new task.

Measure convergence and accuracy

Count steps to reach target accuracy and final solution quality on unseen graphs.

What the paper changes

What the paper changes

The paper changes the pretraining task selection strategy. Instead of arbitrarily choosing which tasks to pretrain on, it selects a curated group of graph problems based on computational reducibility—the mathematical proof that problem A can be converted into problem B in polynomial time. This targeted selection ensures the pretraining problems share deep structural properties with the target.

the object it moves  =  pretraining task group
The hidden quantity

Convergence speed and retained old-task accuracy

measured quantity  =  transfer efficiency: how fast the model learns the new task while keeping old performance

The paper measures two hidden quantities that reveal whether transfer is working: (1) how many gradient updates (steps) the fine-tuned model needs to reach the target accuracy on a new problem, and (2) how much accuracy is retained on problems learned during pretraining. A model that forgets old tasks has high convergence speed on new tasks but low old-task accuracy (catastrophic forgetting). A model that transfers well has both fast new-task learning and stable old-task performance.

The paper estimates these by running leave-one-out experiments: pretrain on all but one problem, then fine-tune on the held-out problem and measure both the new-task convergence curve and the old-task performance at checkpoints. The gap between step-count with pretraining and step-count from random init reveals the transfer gain.

Why it works

Why pretraining on reducible problems helps transfer

Computational reducibility is the bedrock: if problem A reduces to problem B in polynomial time, their internal structures—the patterns of constraints and objectives—are mathematically related. When the model trains on both A and B, it learns features (internal numerical patterns in its weights) that capture the shared structure. These features are reusable because the problems are not arbitrary; they are linked by a formal transformation.

The energy-based training (minimizing Ising energy functions) further amplifies this. Each graph problem has a Hamiltonian (energy formula); although the formulas differ per problem, the shapes of their loss valleys—where good solutions cluster—share similar patterns. A model trained to find good solutions in one valley learns strategies (like which node properties to measure) that work in nearby valleys.

Fine-tuning uses this foundation directly. The backbone weights are already tuned to extract relevant node and edge patterns from graphs. Only the linear output layer (or a shallow head) needs retraining to map those patterns to the new problem's objective. This is far cheaper than retraining from zero, because the model only has to adjust how to combine patterns it already knows how to extract, not learn new pattern detectors from noise. The pretrained weights provide a good starting point—the model avoids large random-direction explorations that waste steps, so gradient updates move directly toward the target objective.

Math after the picture

The energy minimization formula

First in words:

loss equals the Ising energy function for the problem, penalty term to enforce constraints

Then the compact form:

E = H(s) + lambda * C(s) where H is the Hamiltonian (problem-specific energy), s is the node selection vector, lambda scales constraint violation, C counts violated constraints

Every symbol:

Etotal loss (energy) the model minimizes
H(s)Hamiltonian or Ising energy for this problem type
svector of node inclusion probabilities (0 to 1)
lambdaweight controlling how much to penalize hard constraint breaks
C(s)count of constraints violated by selection s
A tiny worked example
Suppose MVC problem: minimize selected nodes while covering all edges.
H(s) for MVC = sum of all selected nodes. For a graph with 4 nodes, if model outputs s = [0.8, 0.2, 0.7, 0.1] (0.8 chance node 1 is in the cover, etc.), then H = 0.8 + 0.2 + 0.7 + 0.1 = 1.8.
C(s) counts edge-cover failures. If 3 edges are not covered by the selected nodes, C(s) = 3.
With lambda = 5, loss = 1.8 + 5 * 3 = 16.8.
Model adjusts weights to lower this loss. If it increases s[1] from 0.8 to 0.85 and that covers one more edge, new loss = 1.85 + 5 * 2 = 11.85, so the gradient pushes in that direction.
Pretraining on MIS (maximize independent nodes) trains the backbone on a similar problem structure; MaxClique fine-tuning then starts with this tuned foundation, not random weights.

The lambda ratio controls the tradeoff between solution size and constraint satisfaction; computational reducibility ensures the pretraining and target problems have compatible loss structures.

What can go wrong

What can go wrong

Negative transfer if the pretraining tasks are unrelated. If you pretrain on problems that do not reduce to the target (e.g., MaxCut features do not help MVC), the model learns task-specific noise and fine-tuning wastes time unlearning it, converging slower than random init. The paper avoids this by selecting pretraining tasks via proven polynomial reductions.
Sequential decoder can produce suboptimal solutions. The decoder greedily adds nodes in order, enforcing constraints but not globally optimizing. If the GNN assigns high probabilities to many mutually incompatible nodes, the decoder picks the first valid subset, not the best subset. This limits final accuracy.
Leave-one-out experiments do not guarantee real-world multi-task learning. In the paper, a single held-out task is fine-tuned after pretraining on all others. In practice, many tasks arrive in unknown order, and the pretraining selection may not match real deployment needs.
Done right: select pretraining tasks using computational reducibility. This paper's main contribution is the principled selection criterion, avoiding negative transfer and ensuring the backbone learns transferable patterns.

Then: (1) initialize a new model with the pretrained backbone and a fresh output layer. (2) Train the new model on a third reducible problem (MaxClique) for 200 steps, recording accuracy at each step. (3) Train an identical model from scratch (random weights) on the same MaxClique data for 200 steps, recording accuracy. Plot both learning curves.
