CARD: Conditional Design of Multi-Agent Topologies

Design multi-agent communication networks that adapt their shape at runtime by reading environmental signals like model changes or new tools.

Paper explainersAll themesAgents & Tool Use

Multi-agent LLM systems (groups of language models working together) talk to each other through a fixed communication topology—a predetermined pattern of who talks to whom that never changes. This works when all agents are identical and tools stay the same. But in the real world, you upgrade one model, add a new API, or swap out a data source. CARD (Conditional Agentic Graph Designer) generates different communication structures on the fly based on the current environment. It reads signals about which models are available and which tools work, then generates a network shape that routes queries through agents who can actually answer them, instead of forcing queries through agents stuck with deprecated tools.

Zero assumption version

Fixed networks break when the world changes

In a multi-agent system, each agent (a language model) solves one part of a problem and shares what it learned with other agents. The communication pattern—which agent talks to which—is set once during setup. Agent A always routes questions to Agent B; Agent B always asks Agent C for facts. But real deployments are messy: you roll out a faster model version and want some agents to use it instead of the old one; you add a new API for weather data and want the planner to talk to it; you deprecate an expensive tool and need agents to find a cheaper path through the network. The performance drops because queries get stuck in branches leading to unavailable tools, or agents waste compute calling tools that time out. A beginner might try to hardcode every variation ('if tool X is available, use this topology; otherwise use that topology'), but this explodes—three environment changes create eight possible configurations to test, and each one might break in edge cases.

The naive approach of a fixed, hand-coded topology cannot adapt. It assumes the environment is static. When conditions change, either the network is inefficient (agents waste time asking unavailable tools) or incorrect (they get no answer at all and the job fails).

In one sentence. CARD generates adaptive multi-agent communication topologies that adjust their structure based on what models, tools, and data are actually available right now.

The algorithm as a flow

What it actually does

1. Read environment state

Sample which models are deployed, which APIs are active, which tools have changed.

2. Encode conditions to numbers

Compress environment signals into a small list of numbers that the graph generator can read.

3. Generate graph structure

A conditional variational encoder produces a communication topology (which agents connect to which) tailored to the current conditions.

4. Optimize edge weights

Fine-tune how much each agent trusts each neighbor based on who is actually reliable right now.

5. Execute agents on new topology

Multi-agent system runs, routing problems through the generated network structure.

What the paper changes

What the paper changes

CARD changes which agents communicate with which other agents and how much they trust each connection. Instead of one fixed seating chart, it generates a new communication topology every time conditions change. The core shift is making the network structure a function of the environment (not a constant), using a conditional variational graph encoder—a machine-learning model that reads environment signals and outputs a complete network graph optimized for the current setup.

the object it moves  =  Communication topology, conditioned on environment
The hidden quantity

The hidden quantity: topology-environment fit

measured quantity  =  Fit between network structure and current environment

Topology-environment fit measures how well the communication network is shaped for the world it is running in. High fit means agents route problems to colleagues who can actually answer them, which works because the network connects through available tools and models instead of deprecated ones. Low fit means agents ask agents who cannot help, which causes slowdowns or failures because the network still points to unavailable tools, creating loops or dead-ends. If Agent B is supposed to call Tool X but Tool X is deprecated, the topology has low fit and queries get stuck. If the network redirects queries to Agent D who has access to the new Tool Y, fit is high and queries succeed.

CARD estimates fit by training the graph generator to produce topologies that maximize accuracy on benchmark tasks. During training, the environment changes (models swap, tools appear or vanish), and the generator learns to produce topologies that work for each condition. The paper measures fit implicitly through task performance (HumanEval accuracy, MATH score, MMLU score)—a high-fit topology lets agents solve more problems correctly.

Why it works

Why it works: conditioning replaces hardcoding

If you hardcode a topology for each possible environment, you create an exploding combinatorial problem: two model choices plus three tool configurations equals six topologies to engineer and test separately. Instead, CARD learns a single graph generator that takes environment conditions as input and outputs the right topology for any combination. The generator reads the current state and produces a network structure optimized for it, without requiring you to manually write rules for every case.

Here is the causal chain: when the environment changes (new tool available, old model deprecated), CARD reads that signal as a condition vector—a compact list of numbers encoding what is available. A neural network (the conditional variational graph encoder) receives this vector and outputs a full communication graph: not just which agents exist, but which ones should listen to which. The network is trained end-to-end on benchmark tasks, so it learns topologies that actually work. If it generates a topology that wastes time asking unavailable tools, accuracy drops and training nudges the weights. If it generates a topology where agents efficiently route to current resources, accuracy rises. By the end, the generator has internalized the rule: 'when this set of tools and models is available, build this shape of network.' At runtime, you read the current environment, feed it to the generator, and instantly get a topology optimized for right now—no hardcoding, no explosion of cases, just one adaptive system.

Math after the picture

The topology generation equation

First in words:

Generated graph = decoder of latent sample conditioned on environment signals; sample drawn from learned distribution parameterized by condition

Then the compact form:

G = Decoder( z ~ q(z | c) ); loss = task_loss(G) + KL_divergence(q(z | c) || p(z))

Every symbol:

GCommunication graph: nodes are agents, edges show who talks to whom
zLatent code: compressed summary of one particular topology shape
cCondition: vector encoding current environment (available models, tools, APIs)
q(z | c)Encoder: learns distribution of good latent codes for this condition
DecoderGraph generator: converts latent code back to edges and weights
task_lossBenchmark accuracy (HumanEval, MATH, MMLU) for this topology
KL_divergenceRegularization: keeps the learned distribution close to a simple prior
A tiny worked example
Environment c = [model_v2=available, tool_X=deprecated, tool_Y=new].
Encoder reads c and outputs a latent sample z = [0.3, -0.5, 0.8] (a 3-number code).
Decoder takes z and outputs a graph: Agent-A → Agent-B (weight 0.9), Agent-B → Tool-Y (weight 0.8), Agent-A → Tool-Y (weight 0.6, direct route added).
Network runs on benchmark task. Queries to deprecated Tool-X get rerouted. Accuracy improves from 72% to 79%.
Training reinforces this z and its condition mapping. Future runs with same c will generate the same topology.

Conditioning on environment allows one learned generator to produce different topologies for different worlds, because the neural network learns the rule that maps environment states to optimal network shapes—training data teaches it which topology works for each condition, so deployment just queries the learned rule instead of requiring humans to hand-write a separate network for each case.

What can go wrong

What can go wrong

Condition signal is ambiguous or wrong. If the environment encoder mis-detects which tools are available (e.g., an API is up but timing out, so it looks deprecated), the condition vector is wrong. The topology generator then produces a network optimized for the wrong world, and accuracy drops.
Unseen environment combinations. If training only saw two model types and three tools (six combinations), and deployment encounters a fourth model type, the encoder has not learned a condition for that state. The generator may hallucinate a topology that does not fit, or produce one optimized for the nearest seen combination (which may not be close).
Latency from graph generation. Decoding a new graph on every environment change adds inference time. If conditions change frequently (tools flipping on and off), the overhead can outweigh the benefit of adaptive routing.
Done right. When environment signals are reliable, conditions are similar to what the system saw during training, and change frequency is low, CARD generates topologies that route queries efficiently to available resources, maintaining high accuracy across diverse real-world shifts.
What a runnable demo should prove

What a runnable demo should prove

A minimal demo sets up three or four agents (simulated LLMs) and three tools (some reliable, some deprecated). It runs a benchmark query (e.g., from HumanEval or MATH). It then simulates an environment change: mark one tool as unavailable, add a new one, or upgrade one agent model. CARD regenerates the topology by reading the new environment and generating a new graph structure. The demo re-runs the same query on the new topology and measures success rate (percentage of queries solved correctly). The key visual should compare accuracy on the old fixed topology after the environment change (drops substantially) versus accuracy on the CARD adaptive topology (stays high). Code should be under 300 lines: initialize agents and tools, define a fixed topology and a condition vector, call the graph generator, run queries, and plot before-and-after accuracy.

Robustness = avg_accuracy_across_all_conditions - std_dev_across_conditions (lower std dev means more stable)

A successful demo makes impossible to ignore: when the environment changes, the fixed topology fails but CARD adapts and keeps queries solving successfully.
