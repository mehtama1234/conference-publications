Overcoming the Modality Gap in Context-Aided Forecasting

Adding descriptive context to time series only helps if the context is verifiably useful; this paper creates a massive dataset with verified context.

Paper explainersAll themesTime Series & Sequential

Modern AI systems can see both numbers (a sales history) and text (a description of the market), but mixing them often makes things worse, not better, because the model wastes computational effort learning to ignore the unreliable text instead of focusing on the numbers. This paper figures out why: the text was never actually useful in the first place. By building a dataset where context is rigorously proven to help, the paper shows that when the text is real, multimodal models do win because the model now splits its focus across both signal sources equally.

Zero assumption version

The multimodal paradox: more information but worse predictions

When you forecast (say, predict tomorrow's sales), you usually have two kinds of data: historical numbers (sales from past weeks) and descriptive context (notes about holidays, campaigns, or market news). Intuitively, a model that reads both should beat one that reads only the numbers.

But experiments show the opposite: models trained on text and numbers together often predict worse than models that ignore the text entirely. A naive attempt would be to just add more text to the training data and hope the model learns to use it—but that often fails because the text is not actually predictive. The real problem is hidden: the datasets used to train these models contain text that sounds useful but does not actually help the model predict better, because no one checked whether each description matched what the numbers were actually showing.

In one sentence. When you add descriptive text to a forecasting model's training data, it often gets worse at predicting because the text was not rigorously chosen to actually be useful.

What the paper changes

What the paper changes: the training dataset itself

The paper does not change the model architecture or the training algorithm. Instead, it changes what the model learns from. Earlier datasets paired time series with context (text descriptions) that sounded relevant but were never checked. This paper creates a new dataset where every piece of context is rigorously verified to actually describe the temporal pattern.

the object it moves  =  training dataset quality
The hidden quantity

The hidden quantity: context usefulness

measured quantity  =  context-to-time-series alignment

Context usefulness is a measure of how well a text description actually explains what is happening in the numerical data. If a time series shows a sharp spike and the context says "quiet period", they are misaligned. If the context says "sudden shock", they are aligned.

This paper measures alignment by checking whether the description matches statistical properties of the numbers (trend direction, volatility level, pattern type). When alignment is high, the model can learn to trust the text. When alignment is low (which was the case in older datasets), the model ignores it.

Why it works

Why verified context works: the model learns to trust it

When a model trains on text that is genuinely useful, it learns to read both carefully. Here is the causal chain: (1) a description says the sales trend is upward; (2) the model compares this to the actual numbers and finds it is true; (3) the model assigns high weight to reading descriptions in future similar cases, because each success reinforces that paying attention to text improves predictions; (4) with enough verified examples, the model reliably uses context to forecast better because the pattern—text helps—has been repeated consistently.

Earlier datasets broke this chain at step 2: the descriptions were not carefully checked, so the model found many cases where text and numbers disagreed. The model learned that text was noise and stopped reading it, because mismatches train the model to expect predictions to fail when text is present. This paper re-enables the chain by ensuring step 2 always holds true—every description is verified to match the numbers before the model ever sees the pair.

Math after the picture

The alignment score formula

First in words:

alignment score equals one minus the difference between the description's implied pattern and the actual numerical pattern

Then the compact form:

alignment = 1 - |pattern_text - pattern_numbers| / max_pattern_range

Every symbol:

pattern_textthe trend or volatility implied by the description
pattern_numbersthe actual trend or volatility measured from the time series
max_pattern_rangethe largest possible difference in the dataset
A tiny worked example
Series 1: prices go up 5 percent. Description says 'modest gain'. |5 - 4| / 20 = 0.05. Alignment = 1 - 0.05 = 0.95 (high, this pair keeps).
Series 2: prices go up 5 percent. Description says 'flat period'. |5 - 0| / 20 = 0.25. Alignment = 1 - 0.25 = 0.75 (lower, but still kept if threshold is lenient).
Series 3: prices go up 5 percent. Description says 'sharp drop'. |5 - (-8)| / 20 = 0.65. Alignment = 1 - 0.65 = 0.35 (very low, filtered out).
The dataset keeps pairs with alignment >= threshold, so the model learns from only verified examples.

Higher alignment means the text accurately describes the numbers, so the model can trust it when forecasting, because the model learns that descriptions matching the data lead to correct predictions.

What can go wrong

What can go wrong

Threshold too loose. If the alignment verification is weak (threshold set too low), bad descriptions sneak into the dataset and the model learns bad habits again.
Overfitting to synthetic context. The paper generates context semi-synthetically to match patterns. If real-world context is written differently, the model may not transfer well.
Limited to verifiable patterns. Context that explains a trend but is hard to measure (e.g., 'market sentiment') will not pass verification and gets filtered out, even if a human would say it is relevant.
Done right. Verify context rigorously, use verified pairs for training, validate on real-world time series where ground truth is known.
What a runnable demo should prove

What a runnable demo should prove

Build a small forecasting task (e.g., predict next week's sales from past 8 weeks of data). Collect or generate pairs of time series and descriptions. Measure alignment for each pair using the formula above. Split the dataset into high-alignment pairs and low-alignment pairs. Train two models: one on high-alignment pairs, one on low-alignment pairs. Both see the same time series and text, but one was verified and one was not. Measure forecast accuracy on a held-out test set.

improvement = accuracy_high_alignment_model - accuracy_low_alignment_model

If verified context is truly useful, the high-alignment model should forecast better, because it trained on consistent signal rather than noise. If both models perform equally, alignment verification had no effect.
