GuirlVG: Incentivize GUI Visual Grounding via Measured Exploration on Reinforcement Learning

GuirlVG trains a multimodal agent to point at the correct on-screen element by using reinforcement learning with a stabilizing KL term instead of massive supervised fine-tuning.

Paper explainersAll themesAgents & Tool Use

A GUI agent often fails at the simplest visible step: identifying which button, field, or menu item the instruction refers to on the screen. That task is GUI visual grounding. The standard solution has been enormous supervised fine-tuning sets, which are expensive to build because every example needs labeled screen targets and may become wasteful as base multimodal models get better. This paper asks whether reinforcement-style post-training can do the job more efficiently. The answer is yes, but only after careful design. Naive reinforcement fine-tuning underperforms the supervised baseline. GuirlVG improves it by studying the reward design, the training configuration, and a stabilizing Adversarial KL Factor that limits harmful reward over-optimization. With only 5.2 thousand training examples, the method beats supervised systems trained on more than 10 million examples because the reward signal and drift control get more learning value from each example.

Why GUI grounding is expensive in the usual training setup

A GUI agent receives an instruction such as open settings, click the share button, or find the assignment list. To act correctly, it must ground those words in a specific screen region. Supervised fine-tuning solves this by showing millions of labeled screen-action pairs. That works, but the data pipeline is expensive because every example needs careful annotation of what element the instruction refers to.

As multimodal base models improve, exhaustive post-training may no longer be the only path. Reinforcement-style training is attractive because the system can be rewarded when it clicks the correct region. But a naive version is unstable. The model can overfit the reward signal, collapse its behavior, or drift too far from its useful starting policy. The paper studies how to make that reinforcement setup work.

The paper's move in one sentence. Replace giant supervised datasets with reinforcement-style GUI grounding that is stabilized by a carefully designed reward setup and an Adversarial KL Factor that keeps training from drifting into reward hacks.

The algorithm as a flow

What it actually does

Step 1: Start from a capable multimodal base model

Use a model that already understands general screen content so that reinforcement training can focus on action grounding rather than basic perception.

Step 2: Define rewards for correct visual grounding

Reward outputs that identify the correct GUI element because the training signal should point directly at the grounding task.

Step 3: Analyze the reinforcement design choices

Compare reward forms, sampling choices, and training settings so that the paper can find which pieces help instead of guessing.

Step 4: Add the Adversarial KL Factor

Restrain policy updates against harmful drift because reward over-optimization can otherwise damage the base policy.

Step 5: Evaluate on GUI grounding benchmarks

Measure accuracy on ScreenSpot, ScreenSpotPro, and ScreenSpotV2 to test whether the new training setup generalizes.

The hidden quantity

The hidden quantity: policy drift under reward pressure

measured quantity  =  how far the model moves away from its useful starting behavior while chasing reward

The central hidden quantity is policy drift. Reinforcement training helps only if the model improves its grounding decisions without discarding the useful visual and language behavior it already had, because losing that base behavior would make the click policy narrower and less reliable. If updates become too aggressive, the system may score well on the reward proxy while becoming worse at general grounding.

GuirlVG tracks and controls this drift with its KL-based stabilizer. That matters because GUI grounding depends on a balance: enough pressure to learn sharper click decisions, but enough restraint to preserve the base model's perception and instruction-following ability.

Why it works

Why it works

A strong base multimodal model already contains a lot of screen understanding. The main missing piece is often task-specific decision sharpening: choosing the exact clickable region that the instruction requires. Reinforcement training is a natural fit because the system can be rewarded directly for correct grounding outcomes.

The problem is that reward optimization alone can push the policy into brittle behavior. A model may become too specialized to the reward signal and lose broader screen-reading ability. GuirlVG works because it combines direct grounding reward with a stabilizer that keeps the policy from drifting too far from its strong starting point.

The component-by-component study matters because reinforcement training has many interacting parts. Reward design, sampling, and drift control each affect stability. The paper does not treat reinforcement fine-tuning as one generic recipe; it identifies the configuration that improves grounding accuracy with far less data than large supervised runs because the chosen setup wastes fewer updates on unstable behavior.

Math after the picture

The training objective

First in words:

Maximize grounding reward while subtracting a penalty when the new policy moves too far from the starting policy, because stable improvement requires both better actions and controlled drift.

Then the compact form:

J = E[reward(click, target)] - lambda * KL(policy_new || policy_base)

Every symbol:

Jthe training objective being maximized
reward(click, target)the reward for selecting the correct GUI region
lambdathe weight that controls how strongly policy drift is penalized
KL(policy_new || policy_base)how far the updated policy has moved from the base policy
policy_newthe current policy after reinforcement updates
policy_basethe starting multimodal policy before this training stage
A tiny worked example
Suppose one update raises the click reward from 0.70 to 0.82.
If that update also causes a KL penalty of 0.05 and lambda is 2, the objective gain is 0.82 - 2 x 0.05 = 0.72.
A second update might reach reward 0.84 but incur penalty 0.12, which gives 0.84 - 2 x 0.12 = 0.60.
The first update is preferred because it improves grounding with less harmful drift.
This is exactly the balance the method is trying to maintain.

The equation matters because the system must optimize accuracy and stability at the same time.

What can go wrong

What can go wrong

Reward design may still miss important cases. If the reward only captures easy click success, the policy may improve on the benchmark but miss harder grounding cases because the training signal is incomplete.
Too much KL control can block learning. If the stabilizer is too strong, the model cannot move enough to improve because every useful update is suppressed.
Too little KL control can cause collapse. If the stabilizer is too weak, reward over-optimization can damage the base policy because the model drifts into brittle shortcut behavior.
Done right. The method works when the reward reflects true grounding quality and the KL control is tuned so that learning stays stable while still moving.
