Creating multiple data types together

Papers on generating images paired with other information (text, graphs, molecules, molecular descriptions) or combining different types of input to create richer outputs.

All themesField mapMathematicsAll explainers
What this is

Some generation tasks require creating more than one thing at once. You might want an image paired with a detailed text description, or a molecule paired with predictions of its properties, or a visual diagram paired with the data it represents. The challenge is that different data types have different structure and statistics. An image is a grid of pixels; text is a sequence of words; molecules are graphs where atoms connect to atoms. A single generative model has to somehow handle all these different structures and ensure they're coherent—the image and description have to match, the molecule and its properties have to align.

The core difficulty is coordination. If you generate the image and then try to generate a description, you might get a mismatch. If you try to generate them together, you need a framework that treats both equally. How do you even train a single model on data of such different types? One approach is a shared intermediate representation—convert images, text, and graphs into a common numerical format, let the model work in that format, then convert back. Another is to use multi-modal models (models trained on paired examples of images and text, or text and molecules), which work because the model is repeatedly shown correct pairings and learns to associate certain images with certain kinds of descriptions (a sunset description goes with warm colors, not cool colors). A third is to stack independent models: generate the image, then condition the text-generation model on the image (so the text model can see what was generated and describe it).

Papers here explore these approaches. Some propose new architectures that handle multiple data types naturally. Others work on the training problem—how to learn from paired data of mixed types. Still others focus on specific combinations: text-to-image plus generation of captions, or molecular generation plus property prediction. The motivation is practical: in many real applications, you need multiple outputs that fit together, not just one thing in isolation.

How the work breaks down

Generating multiple data types together splits into five natural directions: visual storytelling where images and text descriptions must align, image-text systems where retrieval and generation feedback help each other, motion synthesis that coordinates movement across multiple people or modalities, molecular design where atoms and chemical properties need to match, and code generation from visual designs where visual structure maps to functional output. These splits exist because each pairing has different constraints—visual-text coherence requires shared semantics, molecular generation needs physical validity, and motion must respect the physical rules of how bodies interact.

Film and image generation with text guidance

When you create images or films, you often want accompanying text that describes them accurately. The challenge is that text and visuals follow different rules: an image has spatial layout and color, text is sequential words. If you generate them separately, they often mismatch—the text describes the wrong scene or tone. These papers solve this by making text and image generation aware of each other, so they produce coherent pairs.

FilMaster learns from real film footage to generate complete, editable films that follow cinematic principles. It studies how professional filmmakers compose shots, arrange scenes, and apply post-production effects from 440,000 actual film clips. By learning this grammar of visual storytelling, it can synthesize new films that feel authentic and professional, producing videos where every shot and transition makes visual sense. ImageRAG solves rare concept generation by dynamically retrieving reference images during generation—so it can improve because when you show the generator examples of 'dog with goggles', it learns what that should look like rather than guessing. When asked to generate a rare concept, it fetches similar images from a database, giving the generator a visual template, so the generated images actually match the concept instead of being abstract guesses. MoVie combines video compression with text guidance, meaning it learns to compress video efficiently while responding to text instructions about what to emphasize, achieving much smaller file sizes while keeping visual quality high because the text explains which details matter most. These three papers agree on one principle: generation improves when visual and textual information guide each other throughout the process, because seeing examples of what matches what teaches the model the real associations between words and images, rather than learning these associations just from isolated training data.

Multimodal completion and retrieval

Sometimes you have partial data—an image without a description, or a text without visual context. Multimodal completion means filling in the missing piece so both modalities exist together. The hard part is that the completion must make semantic sense: a picture of a sunset shouldn't get a caption about winter, and a sentence about mathematics shouldn't get paired with a beach photo.

RAG4DMC fixes missing-modality data by retrieving similar complete examples from a reference database, then uses those examples to guide generation of the missing piece. If it sees an image without a caption, it finds visually similar images that do have captions, and uses those as templates to write a coherent description. This approach works because real examples teach the model what kinds of descriptions match what visual content. Hölder++ improves multimodal VAEs (a different architecture for learning from paired data) by rethinking how to balance visual quality against semantic coherence. A VAE learns a shared numerical representation of both modalities; the challenge is that optimizing image quality can hurt text quality and vice versa. Hölder++ solves this by adjusting the relative importance of each quality goal, so improvements in one don't break the other, achieving better results on both fronts. Together, these papers show that handling missing or incomplete multimodal data requires either good examples to learn from or a smarter way to balance competing demands.

Motion generation across people and modalities

Generating motion—whether human movement or animated characters—becomes harder when multiple entities interact or when you want to condition on different input types like text, music, or scene context. When two people dance together, their motions must synchronize. When you want a character to react to spoken dialogue, the timing must align. These papers handle coordination across modalities and multiple actors.

The Rectified Flow work on 3D motion generation tackles two-person interactive scenarios where one person leads and the other reacts, or both influence each other. The hard part is generating both motions simultaneously so they're synchronized and physically plausible—feet stay on the ground, limbs don't pass through bodies, and timing matches. By treating motion generation as a flow process (a mathematical framework for continuous transformation), it achieves better quality and faster response times than other methods, ensuring that when one person extends a hand, the other's reach response aligns in time. The humor caption paper takes a different pairing problem: generating funny captions for cartoons. Humor comes from incongruity—the text must reference the visual scene but in an unexpected way, which means the caption generator needs to deeply understand both what's shown and how to subvert expectations. These two papers approach different modality pairs but face the same core issue: synchronization and mutual influence between types of content.

Molecular design with structure and properties

Molecules have two representations that must align: their 3D structure (atoms arranged in space, connected by bonds) and their chemical properties (how they react, their stability, their biological effects). Generating a new molecule means building both the structure and ensuring it has the desired properties. The challenge is immense because a tiny change in position can break validity—atoms might be too close, bonds might form incorrectly, or the resulting structure might be physically impossible or chemically inert.

Demystifying Multimodal Biomolecular Co-design uses geodesic coupling, an approach that respects the physics of molecules. Instead of treating structure and properties as independent predictions, it couples them through mathematics that preserves physical laws—atoms can't be in two places at once, bonds follow chemical rules. By grounding generation in these physical constraints, it outperforms naive methods that generate structure and properties separately and hope they match. GAGA makes 3D molecular generation faster by approximating the mathematical distribution of valid molecules as simpler (Gaussian), which is wrong mathematically but practical—it runs far faster while keeping quality high because most generated molecules still satisfy chemical constraints. InertialAR builds molecules piece by piece, placing one atom at a time while tracking rigid body physics (inertial frames). This means each new atom respects what's already been placed, ensuring no overlaps and maintaining valid bond angles. It excels at conditional generation where you specify a target property (like 'make this molecule bind to this protein') and it builds a structure guaranteed to have that property. VecMol represents molecules as vector fields—imagine a field of forces showing where atoms should go. This is a fresh approach to the alignment problem: instead of predicting atom positions directly, the model learns a force field that naturally pushes atoms into valid, useful positions. These four papers converge on the same problem: atoms and properties must respect physics, so successful generation either enforces physical laws during generation or learns representations that naturally respect them.

Code and structured output from visual input

Visual designs—user interface mockups, charts, diagrams—must translate into structured outputs: code, graph descriptions, valid database structures. The difficulty is that visual and structural data have opposite grain: a UI visual is spatial and continuous, but code is hierarchical and discrete. Generating one from the other requires understanding what visual elements mean structurally.

Deterministic Component Mining extracts reusable UI elements from screenshots, then generates working code that assembles them. Instead of pixel-by-pixel generation, it identifies visual components (buttons, text fields, containers) and generates code that replicates them across multiple frameworks. This works because components have consistent structure—a button looks the same whether in React or Vue, just coded differently. PolyGraph Discrepancy and Variational Bayesian Flow Network both tackle graph generation. Graphs are structured: nodes have properties, edges have directions, and global properties must hold (a social network is connected, a molecule is chemically valid). PolyGraph provides metrics to evaluate whether a generated graph has the right structure, using classifiers to check consistency. Variational Bayesian Flow Network generates graphs by alternating between placing nodes and connecting them with edges, enforcing consistency at each step—new edges must respect existing node types, and the overall structure stays coherent. All three papers address the jump from one data type to another: visual space to code, or sets of points to connected structures, which requires enforcing constraints that neither modality respects naturally.
