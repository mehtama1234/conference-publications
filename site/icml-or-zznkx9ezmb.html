Beyond Magnitude: Scale-Invariant Evidential Fusion for Multi-View Classification

Fuse several views by standardizing each view before combining evidence, so a view wins only when its class pattern agrees with other views rather than because its scores are numerically larger.

Paper explainersAll themesOther

Multi-view classification uses several measurements of the same example, such as several cameras, sensors, or feature sets. Evidential deep learning adds another goal on top of accuracy: it wants each view to carry both class support and uncertainty, so the final prediction can say not only which class is favored but also how strongly the data support that choice. The paper shows that a common failure starts earlier than uncertainty estimation itself. Existing fusion rules often treat a larger raw score scale as stronger semantic evidence because the fusion formula reacts to amplitude before it checks whether the class ordering itself is informative. That is wrong when one view produces inflated numbers for accidental reasons such as architecture choice, preprocessing, or noise. A view can then dominate the fused result even when its class ranking is weak or misleading. The proposed method, Scale-Invariant Evidential Fusion, removes that dependence on absolute score scale. It standardizes each view instance by instance, then fuses views through agreement in class pattern. The central point is simple: confidence should come from how informative a view is about the class, not from how large its raw numbers happen to be.

Zero assumption version

Why ordinary evidential fusion can choose the wrong view

In evidential multi-view classification, each view produces class-wise support values and the system fuses them into one final belief. The intended meaning is that a view with clearer class separation should contribute more. Many fusion rules fail to enforce that meaning. They let the absolute size of the raw class scores drive the combination, even when those larger values do not reflect clearer class information.

That creates a scale mismatch problem. Suppose one view spreads its class scores over a wider numeric range than another view. Even if its ordering across classes is noisy, the fusion rule can still treat it as dominant. The model then confuses amplitude with evidence. The paper calls this semantic hijacking: an inflated but uninformative view pulls the result toward its preferred class because the fusion rule is sensitive to scale before it is sensitive to agreement.

The paper's move. Normalize each view at the single-example level before fusion, because that strips away arbitrary score scale and forces the fused decision to depend on class pattern agreement instead.

The algorithm as a flow

What it actually does

Compute class support for each view.

Run each view-specific branch to get one class score list per view, because the system still needs a separate class judgment from every source.

Standardize within each example and each view.

Center and rescale that view's class score list for the current example, so arbitrary amplitude differences stop affecting later fusion.

Convert the standardized pattern into evidence.

Treat classes that stand out within that normalized pattern as stronger support, because the useful signal is the relative ordering and separation among classes inside the same view.

Aggregate views through agreement.

Combine evidence from all views so classes supported by several normalized patterns accumulate more mass, because repeated agreement is harder to obtain from accidental scale inflation.

Produce prediction and uncertainty.

Output the fused class belief and the remaining uncertainty, because a view consensus can still be weak when every view is ambiguous after normalization.

What the paper changes

What the paper changes

The paper changes the quantity that controls fusion. Instead of letting raw score magnitude decide how much a view counts, it makes fusion depend on the standardized within-view class pattern.

The hidden quantity

The hidden quantity

measured quantity  =  class pattern reliability after removing per-view scale

The hidden quantity is not the raw score size. It is how reliable the class pattern remains after the view's overall level and spread have been removed. If one class still stands out clearly after that adjustment, the view carries real discriminative information for that example.

This matters because a view can have large numbers for unimportant reasons and still offer a weak class ranking. Standardization exposes that difference. A view that only looked confident because its scale was inflated loses its false dominance, while a view whose preferred class genuinely stands apart keeps that signal.

Why it works

Why standardizing each view fixes the failure mode

A fusion rule should react to which class a view prefers and how sharply that preference stands out inside that view. It should not react to a global multiplier applied to every class score in the view, because that multiplier changes units, not meaning. SAEF enforces exactly that separation by standardizing the class score list for each example and each view. After centering and rescaling, two views with the same class ordering but different amplitude become equivalent for fusion.

That change blocks asymmetric dominance. In older rules, a single inflated view can overpower several moderate views even when those other views agree with each other. After normalization, the inflated view keeps only the relative structure among its classes. If that structure is noisy, its evidence stays weak. If several views point to the same class with similar normalized patterns, their evidence accumulates for a reason that corresponds to shared semantics rather than shared scale.

The result is more stable under perturbations because global rescaling of one view no longer changes the fused answer. The method also preserves uncertainty information, because normalization does not force every view to be certain. A flat normalized pattern still yields weak evidence, so the system can say that no view is decisive.

Math after the picture

Normalize before fusing

First in words:

For each view, subtract that view's mean class score for the current example and divide by that view's score spread for the same example. Then fuse evidence from these normalized scores instead of from the raw ones.

Then the compact form:

normalized_score(view, class) = (raw_score(view, class) - mean_over_classes(raw_score(view, *))) / std_over_classes(raw_score(view, *))

Every symbol:

raw_score(view, class)the original class score produced by one view
mean_over_classes(raw_score(view, *))the average score across classes for that same view and example
std_over_classes(raw_score(view, *))the score spread across classes for that same view and example
normalized_score(view, class)the scale-free class score used for fusion
A tiny worked example
View A gives class scores [2, 1, 0]. View B gives [20, 19, 18].
Raw fusion might prefer View B because its numbers are ten times larger.
After standardization, both views become patterns with the same ranking and similar relative separation across classes.
Now neither view dominates just because its numbers are bigger.
If a third view contradicts them after normalization, the fused answer reflects that disagreement rather than blindly following the largest raw scale.

The important property is invariance to multiplying one whole view by a constant.

What can go wrong

What can go wrong

Normalization cannot create information that is absent. If every view is weak or misleading, the fused result will still be weak, because standardization only removes arbitrary scale and does not repair missing class signal.
A view with a nearly flat class pattern can be unstable. When all class scores in one view are almost equal, its spread is tiny, so the normalized pattern can become noisy unless the implementation guards against division by a very small value.
Consensus can still amplify shared bias. If several views are wrong for the same reason, agreement will still accumulate on the wrong class, because fusion assumes that repeated support is informative when it comes from different views.
Done right. The method is strongest when views differ in scale for incidental reasons, because then normalization removes the misleading factor and leaves the actual class pattern to drive fusion.
What a runnable demo should prove

What a runnable demo should prove

Build a small multi-view classifier with two or three branches that each produce class scores for the same example. Create a stress test where one branch is multiplied by different constants at test time without changing its class ordering, because that isolates the exact failure the paper studies. Compare raw evidential fusion against the scale-invariant variant on both clean examples and examples where one view conflicts with the rest.

The demo should show that raw fusion changes its answer when one view is rescaled, while the scale-invariant version does not. It should also show that the standardized rule follows the majority class pattern more often when one view is inflated but misleading, because the harmful signal has lost its artificial scale advantage.

A convincing result is not only higher accuracy. It is a low rescaling sensitivity score, because that proves the fused decision depends on class evidence rather than on arbitrary magnitude.
