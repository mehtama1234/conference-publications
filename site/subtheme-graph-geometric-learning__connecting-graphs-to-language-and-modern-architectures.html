Connecting graphs to language and modern architectures

Papers that bridge graph learning with large language models and transformers, enabling graphs to work with text and taking advantage of modern deep learning frameworks.

What this is

For years, graph models and language models evolved separately. Language models use transformers—architecture where every word can attend to every other word, learning which parts matter most. Graph models use message-passing or spectral methods designed for network structure. But recently, researchers realized transformers can work on graphs too: you can treat nodes as tokens (a chunk of data the model reads) and let a transformer learn which connections matter. And you can combine graph and text data: some entities have names or descriptions, so you can use both graph structure and language at the same time.

The challenge is scaling and semantics. Transformers need to compute attention between every pair of nodes, which costs quadratic time and memory—impossible for graphs with millions of nodes. Also, transformers treat everything as sequence of tokens, so you need to encode graph structure into tokens somehow. And when graphs have varied metadata—text on nodes, multiple edge types—how do you represent that without drowning in complexity?

Papers propose several approaches: efficient transformers that approximate attention by sampling or using sparse patterns, so they scale to large graphs. They encode graph structure as special tokens or as positional encodings (information about where each node sits in the graph). They jointly learn from graph and text by feeding both into the same model—useful for knowledge graphs where entities have names, or for paper citations where papers have abstracts. Some adapt pretrained language models to graphs by treating neighborhoods as text or by treating edge sequences as pseudo-sentences. Others use language models as components in a larger graph system: asking the model to reason in natural language about what a neighborhood means, then using that reasoning to make decisions.

How the work breaks down

When graphs meet transformers and language models, researchers hit a key puzzle: how to make transformers—machines built for sequences of words—work with networks where nodes and edges matter. The work splits four ways. First, encode graphs so transformers can read them naturally. Second, borrow techniques from language models to help with graphs. Third, tune pretrained models at test time so they adapt to new graph problems. Fourth, handle exotic graph types where nodes have relations or graphs change over time.

Converting graphs into sequences for transformers

Transformers need input as a sequence of tokens—chunks they can read left to right. Graphs are networks where every node can connect to any other, so there is no natural sequence. The problem is how to turn a graph into a token stream the transformer can understand, and then make sure the transformer learns which connections actually matter in the network.

Graph Tokenization for Bridging Graphs and Transformers solves this by converting each node into a token that encodes its local neighborhood. This way, transformers can process the graph the way they process words—token by token—but each token already contains information about where it sits in the network. The method achieves top results on 12 benchmarks by outperforming both standard graph neural networks and specialized graph transformers, which means the tokenization idea works better than existing methods.

Relational Graph Transformer tackles a different angle: when graphs have typed relationships (like 'knows' or 'purchased' or 'cites'), how do you teach the transformer to understand which edge type matters for the task. It matches or beats graph neural network baselines by up to 18% across 21 datasets of relational networks. Transformers can learn to weigh different edge types through their learned importance weights across different parts of the model—essentially learning which relationships are important without special logic for each type. These two papers together show that transformers work well on graphs when you represent nodes and their connections properly.

Adapting language models to work with graphs

Language models are trained on billions of words, so they understand meaning and context across many domains. The temptation is to use that knowledge directly on graphs. But graphs are not text: a node is not a word, and edges are not sentence order. The challenge is how to apply a language model's knowledge to graphs without pretending graphs are just sequences of words.

Bridging Input Feature Spaces Towards Graph Foundation Models takes the approach of input agnosticism: the model learns to accept any kind of input—numeric node features, categorical types, mixed metadata—and still work. It does this by learning a shared representation that maps whatever input you have into a common space, so the core graph logic stays the same. The benefit is huge: once trained, the model works on new datasets with completely different input features, even without retraining or changing the architecture. This is what foundation models do for language, and now it works for graphs too.

Enhancing LLMs for Graph Tasks via Graph-aware LoRA Generation takes a different path: start with a pretrained language model and inject graph structure directly into its weights via a technique called LoRA—low-rank adaptation. The idea is to use the language model's existing knowledge but steer it toward graph problems by tuning only a tiny fraction of its parameters. On zero-shot tasks (where the model has never seen the graph problem before), this consistently beats baselines, which means the language model's understanding transfers to graphs if you wire it in the right way.

Test-time tuning for foundation models and dynamic graphs

Once you have a foundation model trained on many graphs, how do you adapt it to a new problem? Retraining is expensive and wasteful. A smarter approach is prompt tuning: at test time, tweak the input or the model's behavior for the specific graph in front of you, without changing the trained weights. This works because foundation models have learned general patterns that only need minor steering to apply to new tasks.

GFMate improves on this by enabling test-time prompt tuning independent of where the foundation model was originally trained. The key point is that you can apply prompt tuning regardless of the source data or the model's pretraining strategy, which makes the approach practical. On 12 benchmarks, prompt tuning alone lifts performance by up to 30%, which shows that foundation models learn so much general knowledge that small hints—prompts—can unlock it for new problems.

Global-Recent Semantic Reasoning on Dynamic Text-Attributed Graphs with Large Language Models (DyGRASP) combines two challenges: graphs that change over time and language model reasoning. Dynamic graphs are harder because old information can become irrelevant while new edges appear. DyGRASP solves this by asking the language model to reason about what matters now versus what was relevant historically, then uses that reasoning to find the right destination node in the network. The 34% improvement in retrieval accuracy shows that language models are effective at this kind of temporal reasoning.

PromptDyG also handles dynamic graphs but adds a theoretical guarantee: it proves that prompt tuning increases the margin between correct and incorrect predictions, making the model more confident and accurate. With consistent gains on six benchmarks, the results show that test-time adaptation improves reliably for graphs that evolve because the theoretical guarantee holds across different graph datasets.

Complex graphs, generalization, and structural symmetry

Real graphs are messy. Some have nodes connected by multiple types of relationships forming a hypergraph (higher-arity structures). Some must generalize to completely new graph domains the model has never seen. Some have geometric structure—like 3D point clouds or molecules—where the space of possible values itself has symmetries that matter. These papers address three different flavors of this complexity.

HYPER: A Foundation Model for Inductive Link Prediction with Knowledge Hypergraphs extends to hypergraphs, where an edge can connect more than two nodes. Standard graph models assume every connection involves exactly two nodes, which fails for data like collaboration networks (three or more people working together) or multiway interactions. HYPER generalizes across unseen relational structures, which means the model learns the principle of how networks work rather than memorizing specific edge types.

Modality-free Graph In-context Alignment learns to work across any graph domain without parameter updates. The idea of 'modality-free' means the model does not assume nodes are text, numbers, or any specific type. 'In-context' means it learns from just a few examples in the problem itself rather than needing retraining. On diverse graph domains and even completely new unseen domains, this achieves strong few-shot performance, which shows that graph patterns transfer across domains as long as the model is flexible enough.

Platonic Transformers: A Solid Choice For Equivariance handles the geometric side: graphs where symmetry matters, like molecules or 3D shapes. These structures have natural symmetries—rotating or permuting atoms should not change the prediction. Standard transformers ignore these symmetries, leading to incorrect or inefficient learning because they treat every node arrangement as different even if they are the same structure rotated. Platonic Transformers build symmetry into the learned importance weights so the model respects spatial structure without extra computation, which keeps the transformer efficient. The method works on images, point clouds, and molecules competitively because baking these structural constraints directly into the model makes it learn the right patterns faster.
