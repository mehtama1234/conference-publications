Modeling Others' Minds as Code

Predict what someone will do next by writing down their behavior as a computer program, then using math to pick the most likely program from many possibilities.

Paper explainersAll themesAgents & Tool Use

When you watch a friend walk across a street, you can predict they will wait for the green light and then go—not because you computed what they want, but because you recognize a familiar script they are following. This paper treats human behavior prediction as program synthesis: an AI writes candidate programs (the scripts people follow), then uses probabilistic inference (a kind of mathematical voting) to find the program that best explains the observed actions, even from sparse observations. The result predicts human and AI behavior 50% more accurately than older methods that try to guess what people want.

Zero assumption version

Why guessing what someone wants doesn't work

Predict human behavior is hard. Old methods assume people are perfectly rational (they always want to maximize some measurable goal), but people are messy: they follow habits, social norms, and half-conscious routines. Other methods just copy past examples (called behavior cloning), but they need hundreds of examples to work and fall apart on new situations.

The real world gives you sparse data: you see a person take a few actions, and you have to guess what they will do next. Learning from few examples is hard because each example is noisy (one person's path to the door might be slightly different each time), and there is not enough data to separate the rule from the noise. Without a fast way to handle sparse data, you cannot react quickly in real time.

The problem. People follow scripts, not maximizing plans. Spot the script from few examples, predict accurately.

The algorithm as a flow

What it actually does

Observe a few actions

Watch someone take 3-5 steps; record them exactly.

Generate candidate programs

Ask an LLM to write 20-50 possible behavior scripts (as code) that could produce those actions.

Score each program

Run each program forward; measure how well it matches the observed sequence.

Assign probability to each

Use Bayesian math to weight each program by its fit; most weight goes to the best fits.

Predict the next action

Sample or average over the top-scoring programs to forecast what comes next.

What the paper changes

What the method changes

Instead of learning a neural policy (a big blackbox network of weights) or guessing rationality, the method changes what it represents: human behavior is now a program (a sequence of explicit if-then rules written as code), not a learned network or a rationality assumption.

the object it moves  =  The representation: from weights or assumptions to program code
The hidden quantity

The hidden quantity: program likelihood

measured quantity  =  Updated probability of each program (after seeing actions)

The key invisible thing the paper measures is: given the few actions you saw, which program is most likely generating them? For each candidate program, the math computes: if this script were running, what is the probability it produces exactly this sequence? High probability means the program fits; low probability means it does not.

The paper uses probabilistic inference (a method for revising beliefs based on new information) to assign a probability weight to each program. The top-weighted programs become the basis for prediction.

Why it works

Why it works: programs are simpler than learning from data

A program is a finite set of rules. An LLM can generate many reasonable programs quickly because LLMs are trained on code and natural language descriptions of routines. A person following a script (wait for green, then go) will repeat the same actions in similar situations; the program captures that repetition explicitly.

Probabilistic inference then asks: which of these 50 candidate programs best explains the observed sequence? This is efficient because you are ranking pre-written programs, not learning a new network from scratch. A handful of observations are enough to rule out bad programs and boost the probability of good ones, because each observation gives a clear signal: if you saw 'wait', then every 'always rush' program drops in probability; if you saw 'go on green', then every program that ignores the light drops. Each observation narrows the field sharply.

Because programs are interpretable (you can read them), a single observation can rule out many programs at once (e.g., if the person did not wait for green, cross all 'wait for green' programs off the list). This filtering is instant: one observation that contradicts a program instantly drops its probability to near zero. In contrast, learning a neural network (a large mathematical model) requires many observations to shift many weights in the right direction via gradients (which way to nudge each weight), and each observation only causes a tiny shift. That is why this method is much faster with sparse data.

Math after the picture

The math: Bayesian scoring of programs

First in words:

Posterior of program is proportional to the likelihood of observations given the program, times the prior on programs. For each program, compute how well it predicts the observed sequence; weight that program by that likelihood and divide by the sum over all programs.

Then the compact form:

p(prog | obs) = p(obs | prog) * p(prog) / p(obs)

Every symbol:

p(prog | obs)probability of this program given the observed actions (what we want)
p(obs | prog)probability of seeing these observations if this program were running (likelihood)
p(prog)prior: how likely we think this program is before seeing anything (often uniform, treating all programs equally)
p(obs)total probability of the observations (normalizing constant so probabilities sum to 1)
A tiny worked example
Observed actions: [approach traffic light, wait, go on green]
Program A (wait for green): p(obs | A) = 0.9 (very likely produces this sequence)
Program B (always rush): p(obs | B) = 0.05 (unlikely, since we saw waiting)
Program C (follow friend): p(obs | C) = 0.3 (possible, but friend not mentioned)
Prior: p(A) = p(B) = p(C) = 1/3 (treat each equally to start)
Posterior A (unnormalized): 0.9 × (1/3) = 0.30
Posterior B (unnormalized): 0.05 × (1/3) = 0.017
Posterior C (unnormalized): 0.3 × (1/3) = 0.10
Normalize (divide by sum 0.30 + 0.017 + 0.10 = 0.417): A gets 72%, B gets 4%, C gets 24%
Predict: most likely action is what program A (wait for green) says to do next.

Each program's weight (posterior) grows when it explains the observations well and shrinks when it predicts actions you did not see. The top program then anchors your prediction of the next step.

What can go wrong

What can go wrong

The LLM generates bad programs. If the LLM cannot think of the actual script the person is following, no amount of Bayesian math will recover it. Garbage programs stay garbage. The method is limited by the LLM's hypothesis space.
Ambiguous observations. If two very different programs produce the same sequence (e.g. 'follow friend' and 'walk to the park' both result in the same steps), the Bayesian update cannot distinguish them from sparse data. You need more observations or a more informative prior.
Randomness in the person's actions. If the person sometimes takes random actions (sometimes rush, sometimes wait), a deterministic program does not fit. The method assumes behavior is mostly rule-based, not mostly random choices.
Done right. Generate diverse, realistic programs with the LLM; give the Bayesian inference enough observations to distinguish the top contenders; and model random behavior by allowing programs to make random choices at key points (e.g. program: wait with 90% probability, rush with 10%).
What a runnable demo should prove

What a runnable demo should prove

Build a gridworld where an agent (or human) follows a hidden script (e.g. move toward a goal, avoid obstacles, stop at walls). Show observations of 5-10 steps. Have ROTE write 30 candidate programs, score them, and predict the next 5 steps. Measure accuracy: does the most-likely program predict the actual next actions?

Accuracy on unseen steps = (number of next actions predicted correctly) / (total number of next-step predictions)

The demo must show ROTE's predictions beat random guessing or a single assumed program, because the Bayesian filtering of programs eliminates bad hypotheses quickly from sparse observations.
