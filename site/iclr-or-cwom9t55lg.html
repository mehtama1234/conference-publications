Why Filters Alone Cannot Stop Harmful LLM Outputs

The paper proves that no efficient external filter can distinguish all harmful prompts from safe ones without access to the model's internals.

Paper explainersAll themesAlignment, Safety & Fairness

When you deploy a large language model, you want to prevent it from generating harmful content. The natural idea: run user inputs through a filter that catches dangerous prompts before they reach the model, or catch harmful outputs afterward. This paper shows this plan has a fundamental flaw. Under realistic cryptographic assumptions, an efficient external filter cannot reliably tell the difference between a malicious prompt and an innocent one. Once the model has already generated something, detecting whether it is harmful is also computationally intractable in certain natural cases. The core lesson: you cannot separate the model's intelligence from its judgment by placing guards outside the box.

Zero assumption version

Why Filters Seem Like They Should Work

Today's language models are trained on internet data, which includes examples of harmful outputs—how to make weapons, how to scam people, how to bypass safety systems. The model learns these patterns. When you deploy it, you want to let safe users ask it questions, but block the ones trying to trick it into harmful outputs. A beginner's first solution: install an external filter (like a bouncer at a club) that inspects each incoming question before it reaches the model. If the question looks suspicious, reject it. If the model somehow does generate something harmful, run another external filter on the output to catch it before the user sees it.

The problem: the adversary (a person trying to make the model generate harmful content) has time and motivation to study the filter. They can carefully craft prompts that are not obviously malicious—prompts that look like innocent questions to the filter, but are carefully designed to trigger the model's harmful knowledge. The filter has no way to know the prompt is a trap without access to the model's internals.

The Challenge. An external filter must distinguish adversarial prompts from safe ones using only what it can see from the outside, but the adversary has unlimited time to craft prompts that hide their true intent.

What the paper changes

What the Paper Changes

The paper does not describe a new method. Instead, it proves a negative result: it shows that a certain approach (external filtering) fundamentally cannot work. The paper's core move is to use computational complexity theory to construct a theoretical language model and adversarial prompts for which no efficient external filter can distinguish the harmful prompts from safe ones.

the object it moves  =  the possibility of external filtering
The hidden quantity

The Hidden Quantity: Computational Distinguishability

measured quantity  =  Computational distinguishability

The paper measures a hidden quantity: whether an efficient algorithm can tell the difference between two types of prompts—adversarial ones crafted to elicit harm and benign ones that look innocent. Distinguishability is not about a human eyeballing the text. It is about whether a polynomial-time algorithm (one that runs in a number of steps that grows as a low-degree polynomial in the input size) can tell them apart.

The paper estimates this quantity using a cryptographic tool called a time-lock puzzle. This is a computational problem that is easy for someone who knows a secret (like a private key), but requires sequential computation that takes a long time for anyone who does not know the secret. The adversary embeds harmful intent inside a time-lock puzzle so the intent is hidden from efficient algorithms but visible to the model if the model has enough compute budget and the model can run the sequential steps to recover it.

The proof uses time-lock puzzles, a cryptographic primitive in which solving the puzzle requires Θ(t) sequential steps but is feasible for an entity with a large compute budget.
Why it works

Why Efficient Filters Fail

The mechanism rests on a computational asymmetry. The adversary has unlimited time to craft a single prompt or a set of prompts. The filter must run in polynomial time and make a yes/no decision for each prompt. Importantly, the model has access to its own weights and architecture—it can run internal computations that reveal structure the filter cannot access.

The paper's core construction uses a time-lock puzzle embedded inside the prompt. The puzzle is designed so that (1) it looks like a random, harmless string of tokens to any polynomial-time algorithm, and (2) only if you spend a lot of sequential computation time (or know a secret) can you extract the hidden harmful intent. The filter is a polynomial-time algorithm—it cannot afford to spend that time on every prompt. But the model, once it receives the prompt, can run the sequential computation if it has been trained or designed to do so. The adversary ensures the hidden intent is something the model will recognize as triggering harmful behavior.

A second mechanism applies to output filtering. Even if you can efficiently generate outputs, detecting whether a given output is harmful might itself be a hard problem. The paper shows a setting in which an output is generated, and checking whether it matches certain harmful criteria requires solving a computationally hard problem. Again, the filter must do this check in polynomial time, which might be impossible.

The Core Equation

First in words:

For a polynomial-time algorithm (the filter), the probability of distinguishing an adversarial prompt from a benign prompt is at most one-half plus a negligible term.

Then the compact form:

Pr[Filter(z_adv) = 1] - Pr[Filter(z_benign) = 1] <= 1/poly(lambda)

Every symbol:

Filter(z)a polynomial-time algorithm that outputs 1 (reject) or 0 (accept)
z_advan adversarial prompt crafted using a time-lock puzzle
z_benigna benign-looking prompt without hidden harmful intent
lambdathe security parameter (higher means stronger cryptographic guarantee)
poly(lambda)a polynomial function of lambda; 1/poly(lambda) is negligibly small (vanishes with security)
A tiny worked example
Suppose the filter can distinguish the two prompt types with 80% accuracy. That is, on 100 adversarial prompts it correctly rejects 80, and on 100 benign prompts it correctly accepts 80.
The advantage is: Pr[rejects adv] - Pr[rejects benign] = 0.80 - 0.20 = 0.60.
For security parameter lambda = 10, 1/poly(lambda) might be 1/1000 = 0.001.
But the filter's advantage is 0.60, much larger than 0.001, so the filter violates the theorem's guarantee.
The paper's construction ensures the filter can achieve at most a tiny advantage, like 0.001, no matter how hard it tries.

This inequality says the filter cannot reliably distinguish the two types of prompts, because the advantage is smaller than negligible, meaning it performs at most as well as random guessing—essentially no better than flipping a coin.

What can go wrong

What can go wrong

The theorem assumes untrusted models. The paper proves a negative result for models that are not aligned during training. If the model is genuinely aligned (trained with human feedback or other alignment techniques), it will refuse harmful requests even if the filter fails. The theorem does not apply to well-aligned models.
Cryptographic assumptions might weaken. The proof relies on the hardness of certain cryptographic problems (existence of time-lock puzzles). If these assumptions turn out to be wrong, the separation results may not hold. However, these assumptions are considered standard in cryptography.
Time-lock puzzles are artificial. The construction in the paper uses time-lock puzzles explicitly embedded in the prompt. Real adversaries might not know how to construct such puzzles, and real attacks might be messier. The theorem shows the hardness is possible, but does not mean all prompts are that hard to detect.
The core insight holds despite limitations. The paper's main message survives: a filter that cannot access the model's internals (weights, architecture, training details) will struggle to detect all adversarial prompts because it lacks the same information the model uses to understand context and intent.
What a runnable demo should prove

What a runnable demo should prove

A demo of this paper's ideas would show that as an external filter becomes more efficient (fewer computational steps allowed), its ability to distinguish adversarial from benign prompts degrades, because a tighter time budget leaves the filter less ability to solve the hidden computational puzzle. The demo would not implement time-lock puzzles explicitly, but instead would show a simpler version: an adversarial prompt that is easy to detect if you understand the model's training data and weights, but hard to detect if you only have black-box access, because the necessary information lives inside the model's architecture.

distinguishability_advantage = Pr[filter correctly identifies adv prompts] - Pr[filter correctly identifies benign prompts as benign]

The demo must show that as the filter's time budget shrinks, its distinguishability advantage approaches zero, meaning it is forced to guess randomly.
