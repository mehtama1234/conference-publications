On Expressive Power of Floating-Point Transformers

Re-do transformer expressivity theory under the arithmetic computers actually use, then show that finite precision changes both permutation behavior and what functions are representable.

Paper explainersAll themesOther

Classical transformer models, meaning sequence models built from repeated weighted input-item mixing and feature-mixing blocks, have expressivity results that assume real numbers and exact arithmetic. Real implementations do not have either one. They use floating-point numbers from a finite set, and every add, multiply, or normalization step incurs rounding. This paper asks what changes when the theory uses those constraints directly. The answer is substantial. Floating-point transformers can break permutation equivariance, meaning output changes under input reordering even without positional encoding, because rounding can depend on evaluation order. They can still represent all permutation-equivariant functions for bounded sequence length, but not once sequence length grows large enough. The paper also studies how additive positional encoding interacts with those finite-precision limits.

Zero assumption version

The usual theory assumes arithmetic that hardware does not provide

A theoretical transformer with exact real arithmetic can preserve clean symmetry properties. If there is no positional encoding, reordering the input tokens should reorder the output in the same way. That is permutation equivariance. Existing universality results are built on this exact setting.

But deployed models run on floating-point hardware. The number system is finite, and operations are rounded. Once arithmetic is approximate, two computation paths that are equal in exact algebra may no longer produce the same stored value. The paper studies expressivity under that real implementation model instead of treating hardware details as negligible. This matters because the implementation model changes which functions can be represented and which symmetries actually survive.

The paper's question. What functions can a transformer represent when every stored weight and every operation must live inside floating-point arithmetic rather than exact real arithmetic?

The hidden quantity

The hidden quantity

measured quantity  =  how many distinct token configurations finite precision can still separate while preserving the intended symmetry

Finite precision turns expressivity into a capacity problem over distinguishable states. The model can only store and propagate a limited set of numeric values, so the question is how many sequence cases remain separable once rounding is part of the computation.

That quantity controls both main results. For bounded lengths, the number of relevant sequence patterns is still finite enough that one can represent every required equivariant mapping. For large lengths, the family of inputs grows past what the finite arithmetic can separate while maintaining the same symmetry constraints, so universality breaks.

Why it works

Why floating-point arithmetic changes the theory

Exact symmetry arguments often rely on algebraic equalities that survive any legal reordering of sums or products. Floating-point arithmetic breaks that guarantee because the rounded result can depend on the order in which intermediate values are formed. That is enough to create non-permutation-equivariant behavior even when the model architecture has no positional encoding term.

The bounded-length universality result is still possible because once the maximum length is fixed, the relevant input space becomes finite in a strong sense under floating-point representation. A sufficiently designed transformer can assign the needed outputs across that finite family. The theorem is therefore not saying finite precision is harmless. It is saying the finite domain can still be covered.

The large-length impossibility result follows from the opposite pressure. As sequence length grows, the number of distinct equivariant cases that must be handled outpaces the finite set of reliably separable internal states. Additive positional encodings can worsen this because they inject extra numeric structure into already limited precision budgets, so some representable functions under no-position settings may disappear once those encodings are forced in.

The finite-precision view

First in words:

Representability now depends on a rounded computation map rather than on an exact algebraic map, so equality of exact formulas is no longer enough to guarantee equality of realized outputs.

Then the compact form:

A tiny worked example
Take two token orders that produce the same exact sum inside a weighted token-mixing block.
Under exact arithmetic, both paths land on the same intermediate value.
Under floating-point arithmetic, one path may round after adding a large and a small term while the other path rounds after combining small terms first.
The stored intermediate values can then differ.
Once later layers consume those different stored values, the final outputs can differ even though the exact symbolic formulas matched.

The theory tracks the realized computation on hardware, because that is the function the deployed transformer actually computes.

What can go wrong

What can go wrong

The results are about representability, not typical training outcomes. A function being representable does not mean gradient-based training, meaning learning by repeated loss derivatives, will find it in practice.
Hardware details may matter beyond the abstraction. Different precisions, fused operations, or accumulation rules can change the realized rounding path, so one floating-point model may still abstract away device-specific behavior.
Bounded-length universality can be large but still finite. A theorem for fixed maximum length may say little about realistic efficiency, because the construction may require resources that grow too quickly to be practical.
Done right. The paper is most useful as a correction to exact-arithmetic folklore, because it shows which symmetry and universality claims survive once finite precision is treated as part of the model.
What a runnable demo should prove

What a runnable demo should prove

Implement a tiny transformer under exact rational arithmetic and under low-precision floating-point arithmetic, then feed token multisets in different orders with no positional encoding. The demo should exhibit an output mismatch under the floating-point version for at least one order pair while the exact version stays permutation-equivariant.

Then restrict to a very small bounded sequence space and fit a floating-point transformer to all equivariant labelings of that space. A convincing result shows both sides of the theory: order-dependent behavior can appear because of rounding, yet bounded-length universality can still hold on a fixed finite domain.

equivariance_violation_rate = reordered_inputs_with_changed_output / total_reordered_input_tests

The useful lesson is that hardware-faithful transformer theory must reason about finite precision directly rather than treating it as a harmless implementation detail.
