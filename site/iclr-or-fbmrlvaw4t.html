Conformalized Hierarchical Calibration for Uncertainty-Aware Adaptive Hashing

The paper improves unsupervised domain adaptive hashing by calibrating uncertainty at two levels: set-valued semantic predictions decide which target samples are trustworthy, and bit-level confidence decides which hash bits should matter more during training and retrieval.

Paper explainersAll themesUncertainty Quantification

Hashing methods compress each example into a short binary code so nearest-neighbor search can be done with fast bit operations. Under domain shift, unsupervised domain adaptive hashing must build those codes for a target domain that has no labels. Most existing methods assign pseudo-labels to target samples and treat all bits in the resulting code equally. That creates two separate failure modes. A wrong pseudo-label can contaminate learning at the semantic level, and an unstable bit can corrupt retrieval at the representation level. This paper addresses both by introducing hierarchical conformal calibration. At the semantic level, it replaces one pseudo-label with a conformal prediction set whose size measures uncertainty. At the bit level, it predicts the stability of each hash bit and uses that confidence in both the code-rounding loss that turns continuous features into binary bits and the Hamming-distance computation at retrieval time.

Zero assumption version

Why adaptive hashing breaks under target-domain noise

Unsupervised domain adaptive hashing starts from a labeled source domain and an unlabeled target domain. The goal is to learn binary codes that preserve semantic similarity in the target domain. Existing methods usually bootstrap target supervision from the model's own predictions, then align source and target features.

That is risky for two reasons. First, target pseudo-labels can be wrong, especially under large domain shift. If the model is overconfident, a wrong one-hot pseudo-label is treated as fully trustworthy and drives the representation in the wrong direction. Second, even if the semantic label estimate is mostly right, some individual bits of the hash code may be unstable. Two images that should match can differ in exactly those unstable bits, which makes Hamming-distance retrieval brittle.

The main contribution of the paper is to stop treating uncertainty as a single number. Semantic uncertainty and bit-level uncertainty affect different parts of the pipeline, so they should be calibrated and used differently.

Two levels, two fixes. Use conformal prediction sets to decide how much a target sample should influence pseudo-supervision, then use per-bit confidence to decide how much each bit should influence code learning and retrieval.

The algorithm as a flow

What it actually does

Predict semantic confidence sets

Use conformal prediction, a method that returns a set of labels with coverage guarantees, on target predictions to output a label set instead of a single pseudo-label.

Turn set size into reliability

Interpret small conformal sets as high-confidence samples and large sets as uncertain samples for weighted pseudo-label learning and domain alignment.

Predict bit stability

Estimate how reliable each individual hash bit is for each target example.

Weight binary-code rounding by bit confidence

Penalize mismatches in reliable bits more strongly when converting continuous features into binary codes.

Retrieve with weighted Hamming distance

During search, count disagreements on stable bits more than disagreements on unstable bits.

What the paper changes

What the paper changes

The paper changes what counts as a prediction for an unlabeled target example. It is no longer just a class guess or just a binary code. It is a pair of calibrated objects: a set of plausible classes and a confidence profile over code bits.

the object it moves  =  target-domain supervision signal
The hidden quantity

The hidden quantity: Reliability is structured, not one-number

measured quantity  =  sample-level and bit-level confidence

Many domain adaptation systems compress uncertainty into one confidence score. That is too coarse here. A target sample can be semantically ambiguous while still having several stable representation bits, or it can have a confident class prediction while some bits remain unstable after the continuous representation is rounded into binary bits.

The paper therefore treats reliability as hierarchical. At the semantic level, reliability is reflected by the size of the conformal prediction set. At the representation level, reliability is reflected by bit stability. This matters because the two signals intervene in different places: semantic reliability decides how strongly a sample should shape supervision and alignment, while bit reliability decides how strongly a code position should affect retrieval.

Why it works

Why hierarchical calibration is the right structure

Conformal prediction is useful here because it attaches a valid uncertainty statement to each unlabeled target prediction. Instead of forcing the system to choose one class, it outputs a set of plausible classes. The size of that set directly changes how much the sample contributes. A singleton set usually means the model is confident enough that the sample can guide pseudo-supervision strongly. A larger set signals that the sample should be downweighted in pseudo-label learning and domain alignment.

Hashing adds a second issue that semantic calibration alone cannot solve. Binary retrieval is determined bit by bit. If some bits are unstable under domain shift, then treating all bits equally means the distance function is counting noisy disagreements the same way it counts reliable disagreements. Bit stability prediction fixes this by attaching a confidence weight to each bit. Those weights shape the code-rounding loss during training and the Hamming distance during retrieval.

The combined effect is that noise is filtered before it enters the learning signal and also filtered when codes are compared. This handles more failure modes than only improving pseudo-label quality, because retrieval quality depends on the structure of the final codes, not just on class prediction.

Weighted learning from calibrated sets and bits

First in words:

Assign each target sample a semantic weight from its conformal prediction set size, assign each bit a confidence weight from its stability predictor, and use both in training and retrieval.

Then the compact form:

L = sum_i w_i^{sem} L_pseudo(x_i) + alpha L_align(x_i) + beta sum_{i,b} w_{ib}^{bit} L_quant(h_{ib}, z_{ib}), d(x,q) = sum_b w_b^{bit} 1[h_b(x) != h_b(q)]

A tiny worked example
Target sample A gets conformal set {chair}, so its semantic weight is high, say 0.9.
Target sample B gets conformal set {chair, desk, bed}, so its semantic weight is lower, say 0.2.
For sample A, bit confidences are [1.0, 0.9, 0.1, 0.8]. The third bit is unstable.
During training, mistakes on the first, second, and fourth bits are penalized strongly, while the third bit contributes little.
During retrieval, if two codes disagree only on the unstable third bit, the weighted Hamming distance stays small.
This makes the system less likely to learn from ambiguous target samples and less likely to rank near-duplicates as far apart because of noisy bits.

The exact conformal construction provides coverage guarantees, but the practical intuition is simple: uncertain samples and uncertain bits should count less.

What can go wrong

What can go wrong

Conformal calibration depends on the exchangeability assumption. Coverage guarantees are strongest when the calibration setting matches the assumptions behind conformal prediction. Severe data-statistics mismatch or nonstationary target streams can weaken those guarantees.
Bit confidence predictor can become a second source of error. If the model incorrectly marks unstable bits as stable, the weighted Hamming distance becomes overconfident in the wrong code positions.
Downweighting uncertain samples too aggressively can waste target information. Some uncertain samples contain useful structure. If the weighting scheme suppresses them too much, adaptation may become overly conservative.
Done right. The method is strongest when target ambiguity and bit instability are both real issues, because it can filter both instead of forcing one uncertainty signal to do both jobs.
What a runnable demo should prove

What a runnable demo should prove

Use a source-domain image retrieval dataset and create a shifted target domain by changing style or corruption. Train a hashing model with unlabeled target data. Compare three variants: plain pseudo-label hashing, semantic conformal calibration only, and the full hierarchical method. For each variant, inspect target sample weights, visualize bit confidences, and evaluate mean average precision using ordinary versus weighted Hamming distance.

mAP = mean average precision over target queries, weighted_gap = mAP_weighted_hamming - mAP_plain_hamming

The demo should show that better pseudo-label filtering alone is not the full story, because retrieval errors can still come from unstable bits even after sample weighting improves. Retrieval quality improves further when the distance function itself knows which bits are trustworthy, because it stops counting noisy bit disagreements the same way it counts stable ones and therefore changes which items are ranked as nearest neighbors.
