Safe and Scalable Web Agent Learning via Recreated Websites

VeriEnv trains web agents on recreated websites with internal checks, so that agents can practice safely and still get exact rewards.

Paper explainersAll themesAgents & Tool Use

A web agent needs repeated practice, but live websites are a poor training ground. They are unsafe to explore, difficult to reset, and rarely expose exact success signals. That means many training loops either risk damaging real services or depend on weak judges that guess whether the agent succeeded. VeriEnv changes the training source. It recreates real websites as executable synthetic environments, exposes internal state through a Python SDK, and lets the agent write tasks whose rewards can be checked exactly. The result is a web-agent training setup that can scale because practice no longer depends on unsafe interaction with live sites.

Zero assumption version

Why live websites are bad training environments

A training environment should let the agent try many actions, reset to a clean state, and receive a correct answer about whether the task was solved. Real websites usually fail on all three points because exploration can be unsafe, resets are awkward, and many tasks do not expose a clear machine-checkable success condition.

That makes web-agent learning brittle. If the reward comes from a heuristic or a language-model judge, the agent can be rewarded for the wrong behavior because the judge only sees surface evidence. The paper asks how to keep the structure of real websites while turning them into environments that are safe and exactly verifiable.

The paper's move in one sentence. Clone real websites into executable synthetic environments with internal program access, so that agents can create tasks and receive exact rewards without touching the live site.

The algorithm as a flow

What it actually does

Step 1: Clone a real website

Recreate the site's pages and interactions so that the training environment keeps realistic web structure.

Step 2: Make the copy executable and resettable

Run the recreated site in a controlled environment because the agent needs many safe repeated trials.

Step 3: Expose internal state through a Python SDK

Provide direct program access so that task outcomes can be checked against the real environment state.

Step 4: Let the agent generate tasks and rewards

Have the agent create new practice tasks because exact internal checks let it verify whether the task was solved.

Step 5: Train across many recreated sites

Add more environments so that the agent generalizes better by practicing on a wider range of website structures.

What the paper changes

The hidden quantity

The hidden quantity: reward trustworthiness

measured quantity  =  how closely the training reward matches the true task outcome inside the website

The key quantity is reward trustworthiness. A web agent only improves in the right direction because the reward must say the task is solved exactly when the site state shows that it is solved.

VeriEnv raises reward trustworthiness by exposing internal state through the SDK. That matters because the agent can be judged on true page values, submitted forms, and environment transitions rather than on a text guess about what probably happened.

Why it works

Why it works

The recreated environment is useful because it preserves realistic web structure while removing the cost of touching the live site. That gives the agent freedom to explore, fail, and retry without causing external harm.

Internal program access is the central technical move because exact checks are stronger than heuristic judges. A reward based on true site state tells the agent which actions actually changed the world in the intended way.

Scaling across many recreated websites improves transfer because each new site adds another set of layouts, workflows, and hidden states. The agent learns broader web behavior by seeing more verified environments.

A compact training objective

First in words:

Maximize verified task success across recreated websites while keeping reward checks tied to true environment state.

Then the compact form:

J = E[ verified_success(task, site_copy) ] - lambda * unsafe_interaction_cost

Every symbol:

Jthe expected training objective
verified_success(task, site_copy)success measured by exact internal checks inside the recreated website
unsafe_interaction_costpenalty for relying on unsafe or uncontrolled interaction sources
site_copythe recreated executable website
lambdaweight on unsafe interaction cost
A tiny worked example
A task asks the agent to update a user profile field on a recreated site.
One action sequence reaches the right page but fails to save the value, so verified success stays at zero because the stored state did not change.
A second sequence updates the field and commits it, so verified success becomes one because the internal state shows the correct saved value.
Training rewards the second sequence because the SDK check confirms the true outcome.
That pushes learning toward actions that change the site correctly rather than actions that only look plausible.

The point of the objective is that the reward comes from exact environment state, because exact rewards support stable learning.

What can go wrong

What can go wrong

The recreated site may miss important behavior. If the copy leaves out a critical workflow, transfer will drop because the agent practiced on an incomplete version of the task.
The reward logic may check the wrong internal state. A mistaken check can reward the wrong action sequence because the training signal no longer matches true task success.
The environment set may be too narrow. If only a few website patterns are recreated, the agent can overfit because it does not see enough variation in layouts and workflows.
Done right. The approach works when recreated sites preserve the task structure and reward checks match true site state, because then the agent gets safe practice with exact feedback.
What a runnable demo should prove

What a runnable demo should prove

Build two versions of a small form-heavy website: a live-like interface and a recreated executable copy with internal state access. Train one agent only from visible outcomes and another with exact SDK-based rewards on the recreated copy. Add a second held-out site with similar tasks but different layout.

The demo should show better transfer for the recreated-site agent because it learned from exact rewards across many safe resets instead of from weak guesses on visible page text.
