ADAPT: Online Reweighting for LLM Training

Instead of choosing training data once before learning starts, ADAPT gives each example a variable importance score that changes as the model trains, so better examples get louder votes.

Paper explainersAll themesLLMs & Foundation Models

Training language models with huge datasets is a puzzle: some examples teach the model more than others, but picking the good ones before training begins creates problems. This paper proposes a simpler path: give every example an importance weight and recalculate it many times during training rather than once before. Why? Because an example that looks useless to an untrained model often becomes valuable once the model learns its first features; recalculating captures this, so the model emphasizes examples exactly when it is ready to learn from them. Keep all data instead of filtering it, and usefulness flows from dynamic recalculation, not brittle pre-ranking.

Zero assumption version

The brittleness of picking data once

Most methods pick which training data to use before training begins: they score each example (by looking at how similar it is to a validation set, or via other quality measures), then throw away the low-scoring ones. This "offline" approach has a fatal flaw: it decides the importance of an example when the model is untrained and slow. As the model learns and improves, that example might become more or less useful because the model now recognizes patterns invisible to an untrained model, but the decision is already baked in and cannot change.

Worse, throwing away data means the model never learns from the patterns those examples contained. Low-scoring examples often carry lessons the model needs, so discarding them leaves gaps in the model's knowledge. Also, if the task changes or a new model is used, the whole filtering pipeline must run again from scratch. Beginners might think: filter the data, train on the survivors. That works if the data is perfectly pre-sorted, but real training data is messy and evolving, so this approach discards too much and becomes stiff.

The move: Instead of filtering data before training, give every example a variable weight that gets recalculated during training based on how much the model still needs to learn from it.

The algorithm as a flow

What it actually does

Compute a quality signal

Measure how similar each training example is to the validation data (using text overlap, vector similarity lists of numbers capturing meaning, or influence from the direction and magnitude to update weights).

Translate quality to weight

Convert each quality score into a weight between zero and one; examples closer to the validation set get higher weights.

Use dynamic learning rates

Give higher-weight examples bigger learning steps and lower-weight examples smaller steps during the parameter updates (nudges to weights that reduce loss).

Recalculate during training

Recompute quality scores periodically as the model evolves, so weights adapt to the model's current state.

Train on the full dataset

Every example participates in training; none are thrown away, so data diversity is preserved.

What the paper changes

The one thing that changes

ADAPT changes how much each training example influences the model during learning. Instead of a binary choice (in or out), each example gets a fractional importance score that varies as training progresses.

the object it moves  =  per-sample learning rates
The hidden quantity

Quality signal: how aligned is each example to the task

measured quantity  =  similarity to validation data

The paper introduces a quality signal: a score that tells how useful each training example is by measuring its alignment with the validation set. High alignment means the example teaches what the model will be tested on; low alignment means it is out of scope. The signal is computed on the fly from one of three sources: lexical overlap (counting shared words), dense embedding similarity (vectors that capture semantic closeness), or gradient influence (how much an example would reduce the validation error if trained on it alone).

ADAPT uses this signal to set each example's weight. During each training step, examples with high quality signals receive larger weight multipliers on their gradients, so their updates shape the model more. Examples with low signals receive smaller multipliers, so they nudge gently. As the model learns and its features evolve, the same example may shift from low to high alignment (or vice versa), and its weight adapts automatically.

Why it works

Why online reweighting works better

The core insight is that example importance is not fixed. When a model is untrained, a high-quality example might look ordinary because the model cannot tell the good patterns from noise. As the model learns, the same example becomes more useful because the model now has features to extract the lesson. Online reweighting captures this: it recomputes weights as the model evolves, so important examples get louder votes exactly when the model is ready to learn from them.

Offline methods (filtering before training) face a two-part trap. First, they discard data, losing the diversity of lessons contained in low-scoring examples, which means the model misses patterns it would need to handle new tasks correctly. Second, they commit to a single ranking computed from a cold, untrained model, so the ranking may be wrong by the time training heats up because the untrained model cannot recognize what is truly useful. Online reweighting avoids both by keeping all data but modulating each example's contribution through per-sample learning rates. This means high-quality examples pull the model in the right direction with force, while low-quality examples contribute a small nudge that does not misdirect. The model learns from everything because all examples participate, so no diversity is lost, and the emphasis shifts as the model improves because weights are recalculated during training to reflect the evolving model's new capabilities.

Why does this yield better generalization? Because the model is forced to learn all the patterns in the dataset (not just a filtered subset), and because the learning rate for each example is tuned to how much that example helps on the validation task. Examples that fall outside the task's typical patterns (out of the usual scope) or less aligned get small weights, so they do not drag the model off course. The total compute is nearly the same as offline methods (only a lightweight quality metric is added inside the loop), so the generalization improvement comes free.

Math after the picture

The learning rate equation

First in words:

At each training step, update the model by moving in the direction that shrinks the loss, but scale that movement by the example's weight

Then the compact form:

theta_{t+1} = theta_t - eta * sum_{i in batch_t} w_t(i) * gradient_theta loss(model(x_i), y_i)

Every symbol:

theta_tmodel weights at step t
etabase learning rate (step size)
w_t(i)weight for example i at step t (from 0 to 1)
gradient_theta loss(...)direction and magnitude to adjust weights to fit example i
sumadd up the weighted gradients across the minibatch
Tiny worked example
Suppose a minibatch has 2 examples and base learning rate eta = 0.01.
Example 1 has quality 0.9 (matches validation set) -> weight w_1 = 0.9.
Example 2 has quality 0.2 (out-of-domain) -> weight w_2 = 0.2.
Example 1's gradient is [+2, -1] (direction to improve). Its contribution: 0.9 * [+2, -1] = [+1.8, -0.9].
Example 2's gradient is [+3, +0.5]. Its contribution: 0.2 * [+3, +0.5] = [+0.6, +0.1].
Total update: theta := theta - 0.01 * ([+1.8, -0.9] + [+0.6, +0.1]) = theta - 0.01 * [+2.4, -0.8].
Example 1 dominates the update (1.8 out of 2.4 = 75%), steering the model in its direction.
Example 2 nudges gently but does not drag the model off course (it contributes only 25%).

High-quality examples pull the model strongly in the right direction. Low-quality examples add a light touch that preserves diversity without misdirecting the model.

What can go wrong

What can go wrong

Quality signal is bad. If the signal (similarity, embedding vector lists, or gradient influence) does not reflect true usefulness, examples get wrong weights. For instance, if validation examples are about math but the signal counts only word overlap, data-science essays (many words but no math) might score high. Fix: use a signal proven on your domain (gradient influence works across domains but costs more compute to calculate).
Weights do not adapt fast enough. If quality scores are recomputed too rarely, the model's early wrong rankings get baked in. For example, an example useful for advanced reasoning might look weak when the model is untrained. Fix: recompute signals every few thousand steps, not just once.
Validation set is tiny or biased. If the validation set does not represent the tasks you care about, the quality signals will be off. Examples that should be high weight will be low, and the model will learn the wrong lessons. Fix: build a validation set with good coverage of your target tasks.
Done right. ADAPT works when the quality signal is honest (proven on real validation data), weights are updated regularly during training, and the validation set represents the model's real job. Under these conditions, every example contributes fairly and the model learns broad, deep lessons.
What a runnable demo should prove

What a runnable demo should prove

Build a small language model (say, 120 million parameters) on a dataset with a mix of in-domain and out-of-domain examples (e.g., book text mixed with random web crawl). Split into a validation set (real text the model should learn) and a training set (mixed quality). Implement ADAPT by computing a quality signal (text overlap or embedding similarity) and using it to set per-sample weights during each training step. Compare against an offline baseline that filters the training set before training starts. Measure validation accuracy, accuracy on out-of-domain test data (to check generalization), and total training time.

generalization_gap = validation_accuracy - out_of_domain_accuracy (lower is better; ADAPT's gap should shrink because it learns from all data without discarding diversity)

The demo must show that ADAPT yields better cross-domain accuracy than filtering methods because ADAPT keeps all data (instead of discarding low-scoring examples before training), so the model learns all lessons and encounters no gaps, and because ADAPT recalculates importance during training so examples are emphasized once the model has learned features to recognize them. Filtering discards examples before the model knows what patterns they contain, leaving permanent gaps; ADAPT's dynamic reweighting fills those gaps.
