CHTsL: Alignment-Enhanced Sparse and Low-Rank LLM Training

When you combine two parameter-efficient training methods on the same model, they cancel each other out unless you explicitly teach them to align.

Paper explainersAll themesLLMs & Foundation Models

Large language models are expensive to train because they have billions of weights (the numbers inside the model that get adjusted). Sparse training (keep only some weights, zero out the rest) and low-rank training (represent weights as a product of two smaller blocks of numbers instead of one big block) both shrink the model by 70-90%. But when you try to run both at the same time, they fight each other. CHTsL introduces an alignment loss that forces the sparse and low-rank branches to work toward the same goal, recovering performance.

Zero assumption version

Two good methods fight when combined

Training a large language model is expensive: the model holds billions of numbers (weights) in memory and updates each one during training. Researchers found two ways to cut this cost: sparse training, where you zero out most weights and only train the important ones; and low-rank training, where you replace each weight block (a rectangular grid of numbers) with a product of two smaller grids. Each works alone.

The naive thing to try is to run both at once: use sparse selection on some weights and low-rank factorization on others, hoping for 9-fold savings in the total number of weights (the numbers inside the model). But it fails. The sparse branch and the low-rank branch give conflicting update signals (directions to move), causing the model's outputs to jitter and training to become unstable. The two methods cancel each other out, erasing the gains.

The problem. Sparse and low-rank training produce contradictory update signals that fight when combined, wasting the potential for efficiently shrinking the model.

The algorithm as a flow

What it actually does

Run sparse training

Identify weak weights, zero them out, train strong weights.

Run low-rank training

Represent weights as product of two small matrices, train both.

Measure disagreement

Compare outputs from sparse branch vs low-rank branch on same input.

Apply alignment loss

Penalize the disagreement: push outputs closer to matching.

Train end-to-end

Send error signals backward through both branches; they update their weights together.

What the paper changes

What the paper changes

The paper introduces a single new loss term: a measure of disagreement (how much the sparse branch and low-rank branch produce different outputs on the same input). During training, this loss penalizes misalignment, pushing both branches toward the same model behavior.

the object it moves  =  disagreement between sparse and low-rank outputs
The hidden quantity

Output conflict: where sparse and low-rank disagree

measured quantity  =  output disagreement

The hidden quantity is output conflict: for any input (a prompt or text snippet), the sparse branch produces one prediction (a guess for the next word) and the low-rank branch produces another. These should be the same, but they diverge when the two branches have contradictory signals about how to update.

The paper measures disagreement by running the same input through both branches and computing a distance (such as mean squared error) between their outputs. The alignment loss is just this distance, scaled by a weight that says how much to penalize conflict. During training, error signals flow backward through this loss (showing each weight which direction to move) to adjust both branches, forcing them to stay in sync.

Why it works

Why it works: teaching the branches to collaborate

Sparse training and low-rank training both compress parameters, but they do it in opposite directions. Sparse training says: keep important weights big, delete weak ones. Low-rank training says: factor all weights into small matrices, which squeezes every one. When both run on the same model, the sparse branch pushes weights up, and the low-rank branch pushes them down. The model parameters oscillate and the outputs swing wildly.

The alignment loss stops this by adding a third voice: an agreement signal. Every training step, the method asks both branches to predict the next word for the same input. If they disagree, a penalty flows backward through the weights. Over time, both branches shift their internal representations to be compatible, even though they use different compression tricks. They stay coherent.

The result is that sparse selection and low-rank factorization no longer fight. The sparse branch learns which patterns are important; the low-rank branch learns to represent those patterns efficiently. They collaborate on a shared goal: predicting the next word correctly, while saving on the count of weights.

Math after the picture

The alignment loss equation

First in words:

total loss equals task loss plus alignment strength times mean squared difference between sparse output and low-rank output

Then the compact form:

L_total = L_task + lambda * MSE(output_sparse, output_low_rank)

Every symbol:

L_totalthe loss we minimize during training
L_taskthe original training loss (predicting the next token)
lambdathe alignment strength (how much to penalize disagreement)
MSE(...)mean squared error, the average squared difference
output_sparsethe prediction from the sparse branch
output_low_rankthe prediction from the low-rank branch
A tiny worked example
Suppose sparse branch predicts raw scores [2.0, 1.5, 0.8] and low-rank predicts [2.1, 1.2, 0.9].
Differences: [0.1, -0.3, 0.1]. Squared: [0.01, 0.09, 0.01]. Mean: (0.01 + 0.09 + 0.01) / 3 = 0.037.
If lambda = 0.5 and L_task = 1.2, then L_total = 1.2 + 0.5 * 0.037 = 1.219.
Error signals flow backward through the MSE term, pushing both branches to predict closer values next step.

The alignment loss is just a measure of disagreement scaled by a weight. Larger lambda means stricter agreement; too large and both branches converge to the same solution (wasting the compression benefit).

What can go wrong

What can go wrong

Lambda too large. If you penalize disagreement too heavily, both branches converge to nearly identical weight patterns, defeating the point of using two different compression methods. You lose the efficiency gain.
Lambda too small. If the alignment penalty is weak, the sparse and low-rank branches still partially fight. Outputs remain jittery and training destabilizes.
Sparse and low-rank incompatible. If you choose a sparsity pattern (which weights to zero) that conflicts fundamentally with low-rank factorization (e.g., zeroing out all the variance-bearing dimensions), no alignment loss can fix it.
Done right. Choose lambda via validation loss; typically in the range 0.01 to 0.1. Verify that training curves are smooth and both branches' outputs stay close. Compare parameter count, speed when answering new questions, and final loss.
What a runnable demo should prove

What a runnable demo should prove

Build a small language model (e.g., a 12-layer transformer with 60 million weights). Implement the sparse training branch (magnitude pruning, keeping top 30% of weights). Implement the low-rank branch (low-rank factorization with 10-dimensional smaller blocks). Combine them with and without the alignment loss.

Train on a subset of OpenWebText (10,000 examples). Track task loss, output agreement (mean squared error between sparse and low-rank predictions), and parameter count for each variant.

alignment_benefit = (loss_naive_sparse_and_lowrank - loss_CHTsL) / loss_naive_sparse_and_lowrank

The demo must show that without alignment, combined sparse+low-rank training diverges (outputs disagree, loss oscillates); with alignment, both branches stay synchronized and final loss is close to dense training. Loss is measured as error on a test set; lower loss means better predictions because the model got more of the next-word guesses right.
