Inductive Reasoning for Temporal Knowledge Graphs with Emerging Entities

TransFIR uses semantic similarity to borrow temporal patterns from known entities to reason about new ones that have no history.

Paper explainersAll themesGraph & Geometric Learning

Knowledge graphs store facts about entities and their relationships over time, like 'Alice works at Company X in 2024.' When a new entity appears (say, a startup founded yesterday), the system cannot reason about it because it has no historical data. TransFIR solves this by finding semantically similar known entities and borrowing their interaction patterns to make predictions for new arrivals.

Zero assumption version

New entities arrive with no history

Temporal knowledge graphs track relationships between entities over time. Existing systems learn patterns by studying what happened in the past: when did Alice meet Bob, when did Company X hire someone, etc. These patterns then predict future facts.

But real graphs constantly gain new entities. A startup is founded today. A new researcher publishes their first paper. These entities have zero history — nothing to learn patterns from. A naive approach trains on 'Alice' and then tries to apply those learned rules to 'Bob,' but Bob is fundamentally different. The system fails because it has no examples of Bob to anchor on.

The paper observes that entities that are semantically similar (say, both startups, or both researchers) tend to have similar interaction patterns even if they are different entities. The missing piece is a way to transfer those patterns to new arrivals.

In one sentence. TransFIR discovers which known entities are semantically similar to a new one, then borrows their temporal patterns to make predictions.

The algorithm as a flow

What it actually does

Encode semantics

Represent each entity as a short list of numbers capturing its semantic properties.

Build a codebook

Cluster those numeric representations into hidden semantic groups, like bins for startups, researchers, places.

Learn cluster patterns

For each cluster, learn temporal interaction patterns: who typically talks to whom, and when.

Classify new entity

When a new entity arrives, assign it to the nearest cluster using the codebook-based classifier.

Inherit cluster reasoning

Apply the temporal patterns of that cluster to make predictions for the new entity.

What the paper changes

What the paper changes

TransFIR changes the reasoning path for emerging entities. Instead of being stuck with no information, each new entity is immediately mapped to a semantic cluster and borrows the temporal reasoning patterns already learned for that cluster.

the object it moves  =  entity clustering and pattern transfer
The hidden quantity

Semantic cluster assignment

measured quantity  =  cluster membership score

The hidden quantity is the cluster membership score: a number that says how well a given entity matches each semantic cluster in the codebook. For a known entity, this score reflects years of learned patterns. For a new entity, it is computed once from its semantic properties.

The paper estimates this using a codebook-based classifier: each cluster has a learned prototype (center), and the classifier scores how close the new entity's semantics sit to each prototype. The closest cluster wins, and the new entity inherits its temporal patterns.

Why it works

Why borrowing patterns works

The mechanism rests on a simple fact: entities in the same semantic category tend to interact in similar ways, even if they are different individuals. Two startups in the tech industry, though distinct, follow similar temporal patterns: they hire people, raise funding, launch products. The patterns are transferable because they come from the semantic type, not from individual identity.

TransFIR exploits this by pre-computing a set of semantic clusters and learning temporal reasoning rules for each cluster using historical data from known entities. When a new entity arrives, the system assigns it to the cluster that best matches its semantic properties. This assignment happens in one step using the codebook classifier, without requiring any historical interaction data from the new entity itself. Once assigned, the new entity immediately inherits the temporal reasoning rules of its cluster, making it possible to predict its future interactions even on day one.

The reason this beats naive transfer is precision: instead of copying patterns from a single randomly chosen known entity, TransFIR clusters entities by semantic similarity and transfers patterns only within the cluster. This reduces noise and improves accuracy because the borrowed patterns come from entities that are genuinely similar.

Math after the picture

The scoring equation

First in words:

cluster score equals the codebook prototype closest to the new entity, weighted by semantic distance. The new entity's prediction inherits the temporal pattern learned for that cluster.

Then the compact form:

cluster_score_k = exp(-distance(entity_embedding, codebook_k)) / sum_j exp(-distance(entity_embedding, codebook_j))

Every symbol:

cluster_score_kprobability that the entity belongs to cluster k
entity_embeddingvector encoding the new entity's semantic properties
codebook_klearned prototype (center) of cluster k
distancehow far apart two embeddings sit (e.g., Euclidean distance)
A tiny worked example
Suppose a new tech startup has embedding [3, 5]. Three clusters exist: startup-cluster at [2, 4], company-cluster at [8, 2], person-cluster at [1, 1].
Distance to startup-cluster: sqrt((3-2)^2 + (5-4)^2) = sqrt(2) ≈ 1.4
Distance to company-cluster: sqrt((3-8)^2 + (5-2)^2) = sqrt(34) ≈ 5.8
Distance to person-cluster: sqrt((3-1)^2 + (5-1)^2) = sqrt(20) ≈ 4.5
Exponential scores: exp(-1.4)≈0.25, exp(-5.8)≈0.003, exp(-4.5)≈0.011
After normalization: startup-cluster gets 0.25/0.264≈95%, company gets 1%, person gets 4%.
The new entity inherits startup temporal patterns with high confidence because it is closest to the startup-cluster prototype.

The equation turns raw distance into a soft membership score; the entity inherits patterns from the cluster it matches best.

What can go wrong

What can go wrong

Semantic clustering is wrong. If the codebook clusters entities incorrectly (putting two semantically different entities in the same cluster), the new entity inherits the wrong temporal patterns and predictions fail. This happens when the semantic encoder is weak or the clustering is too coarse.
Emerging entity truly unique. If a new entity is genuinely unlike any known entity in the graph (e.g., a completely new type of interaction never seen before), no cluster will be a good match. The closest match is still used, but it may still give poor predictions.
Temporal patterns shift over time. If interaction patterns change over time (startups in 2020 behaved differently than startups in 2026), borrowing patterns from older clusters may not reflect current reality. The system assumes temporal patterns are stable within a semantic cluster.
Done right. When semantic encoding is strong and the new entity genuinely belongs to a well-represented cluster, TransFIR transfers reliable patterns and enables accurate reasoning on day one, because the borrowed patterns come from entities that are semantically identical in type.
What a runnable demo should prove

What a runnable demo should prove

Build a small temporal knowledge graph with 50 known entities (e.g., companies, researchers, places) and semantic types (e.g., tech startup, established firm, research institution). Train the system on the first 24 months of interaction data. Then hold out 5 new entities that appear in month 25 (with zero historical interactions) and measure how well the system predicts their interactions in months 25-26.

The demo must show two numbers side by side: (1) prediction accuracy on the 5 new entities using naive transfer (random cluster assignment), and (2) prediction accuracy using TransFIR (semantic cluster assignment). A 30% improvement in accuracy demonstrates that semantic clustering genuinely transfers better patterns than random transfer, because semantically matched clusters contain entities with similar interaction histories, reducing prediction noise compared to random matches.

improvement = (TransFIR_accuracy - naive_accuracy) / naive_accuracy

The demo makes impossible to miss that borrowing from semantically similar entities is orders better than borrowing from random entities, because similarity ensures the borrowed patterns fit the new entity's actual type and interactions.
