TRACER: Trajectory Risk Aggregation for Critical Episodes in Agentic Reasoning

A method to detect when AI agents are about to fail mid-conversation by reading the whole conversation as a trajectory instead of just the last message.

Paper explainersAll themesAgents & Tool Use

AI agents that use tools (like searching the web or calling functions) often fail in ways that look fine locally. An agent might write confident-sounding words but be looping, using the wrong tool, or talking past the user. This paper introduces TRACER, which reads the entire conversation history (not just the last line) to spot these hidden breakdown signals and predict failures before they happen.

Zero assumption version

Why agents fail silently

When an AI agent talks to a human and calls tools (functions that fetch data or perform actions), failures often hide inside long conversations. The last message looks confident, but the agent has been looping (asking the same question twice), using the wrong tool, or drifting further from what the human actually asked. A naive approach is to check how confident the model sounds in each message separately, but this misses the pattern: confident messages can be part of a broken trajectory.

Existing methods measure only single-message confidence (like how sure the model is when it picks its next word). They do not see that an agent repeating the same tool call three times in a row, or oscillating between contradictory states, is already in trouble even if each message individually looks reasonable.

The real problem. Single-message confidence misses trajectory-level breakdowns like looping, incoherent tool use, or user-agent misalignment that span many turns.

What it actually does

Measure surprise in words.

Detect when the model is suddenly using unusual words (a signal it is confused or shifting topics).

Count how many times the same meaning appears in nearby messages (looping).

What the paper changes

What the paper changes

TRACER shifts the evaluation window from a single message to the entire conversation trajectory. Instead of asking how confident the model sounds right now, it asks whether the sequence of all messages, all tool calls, and all state changes looks healthy or broken.

the object it moves  =  evaluation window (single message to full trajectory)
The hidden quantity

Trajectory risk: the hidden quantity

measured quantity  =  Trajectory risk score

Trajectory risk is a single number from 0 to 100 that measures how likely the entire conversation is about to break. It is not just the model's confidence in one answer; it is a full reading of whether the path the agent is taking still makes sense.

The paper estimates trajectory risk by sampling four signals from the conversation: (1) content-aware surprisal (how unexpected are the words), (2) situational-awareness (is the agent still tracking the original goal), (3) semantic and lexical repetition (are we looping), and (4) tool-grounded coherence (do the function calls match the claimed plan). Each signal is a number. The final risk score is calculated by taking the maximum (worst-case) of these signals across the last few steps, not averaging them — because one really bad moment signals imminent failure.

Why it works

Why it works: reading the whole path

A single bad signal is often noise, but multiple coordinated signals across several steps are a real warning. When an agent is looping, it will show high semantic repetition (saying the same thing), high tool incoherence (calling the tool again even though it failed), and maybe some unusual words (surprisal spike). A single one might be a glitch; all three together is a trajectory failure pattern.

By scanning the full sequence instead of just the last message, TRACER sees the context that makes each signal matter. It also focuses on the worst moment (the tail, or maximum) rather than the average. If 19 out of 20 steps look fine but one step is extremely bad, the average would hide it. The max-composite (take the worst) surfaces exactly those anomalies that predict failure.

inputEntire conversation: all messages, all tool calls, all state changes
stepExtract four signals from each turn: word surprise, goal alignment, repetition patterns, tool correctness

Math after the picture

The trajectory risk equation

First in words:

The final trajectory risk is the maximum of four component risks, each measured across the conversation history. Take the worst-case signal (not the average), weight them, and threshold to decide whether the agent is safe.

Then the compact form:

R_trajectory = MAX(alpha * MAX(surprisal_t, ..., surprisal_t-k), beta * MAX(repetition_t, ..., repetition_t-k), gamma * MAX(coherence-gap_t, ..., coherence-gap_t-k), delta * MAX(situational-drift_t, ..., situational-drift_t-k))

Every symbol:

R_trajectoryfinal risk score (0 to 1 or 0 to 100)
surprisal_tword-prediction surprise at time step t (how unexpected the words are)
repetition_tsemantic or lexical repetition score at step t (how much the message repeats earlier content)
coherence-gap_tmismatch between stated goal and tool calls at step t
situational-drift_thow far the current state is from the original user request at step t
t-kthe last k steps (a lookback window, e.g., last 5 steps)
alpha, beta, gamma, deltaweights that control how much each signal matters
MAXtake the maximum (worst case) across the window, not the average
A tiny worked example
Conversation at steps 1-5: agent asks user a clarifying question, calls tool-A, gets result, calls tool-A again, says nothing changed.
Surprisal at step 5: 0.3 (words are normal).
Repetition at step 5: 0.8 (tool-A called twice; semantic content very similar).
Coherence gap at step 5: 0.9 (user asked to fetch data once; calling same tool twice is incoherent).
Situational drift at step 5: 0.4 (still on topic but stalled).
Using weights alpha=0.2, beta=0.3, gamma=0.4, delta=0.1 (coherence matters most):
R_trajectory = MAX(0.2*0.3, 0.3*0.8, 0.4*0.9, 0.1*0.4) = MAX(0.06, 0.24, 0.36, 0.04) = 0.36.
Score 0.36 out of 1.0 is moderate risk. Baseline (surprisal only) would give 0.06 (missed the problem).

By taking the max of multiple signals and weighting coherence heavily, TRACER catches tool-use failures that look locally confident.

What can go wrong

What can go wrong

Short conversations look risk-free. If the agent has only taken two steps, there is no history to see patterns in. A looping agent with deep repetition needs at least three identical or near-identical steps to register.
Legitimate repetition is hard to distinguish from looping. Sometimes an agent must call the same tool twice (to refetch data, or to call it with a different setting). The paper uses semantic similarity to filter, but an agent that calls tool-A with a slight variation might be legitimately exploring, not broken.
Tool-use coherence requires knowing the original goal. If the user changes their mind mid-conversation, or the goal is ambiguous, measuring coherence-gap becomes noisy. The paper assumes a stable goal; it may miss graceful pivots.
Done right: human-in-the-loop. TRACER is a heuristic for when to pause the agent and ask the user for input, not a hard cutoff. An agent with high trajectory risk should ask the user to confirm the next action instead of proceeding blindly.
What a runnable demo should prove

What a runnable demo should prove

Build a simple conversation simulator where a user asks an agent to fetch data (e.g., retrieve a paper, then summarize it, then extract a figure). Introduce three failure modes: (1) the agent loops by calling the same tool twice; (2) the agent uses the wrong tool (calls search instead of fetch); (3) the agent drifts (starts answering a different question). Run each scenario and measure whether TRACER assigns high trajectory risk to looping and wrong-tool cases (true positives) and low risk to normal conversations (true negatives).

AUROC = area under the receiver operating characteristic curve; plot trajectory-risk score (x-axis) against failure-or-not (y-axis); TRACER should reach 80%+ AUROC on distinguishing healthy from broken trajectories

The key observation: trajectory risk must spike at the moment of breakdown or just before (steps 2-3 of a 5-step conversation), while single-message confidence remains high throughout. This difference is impossible to miss if the demo runs the same conversations through both methods side by side.
