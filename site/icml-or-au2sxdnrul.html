Beyond Euclidean Summaries: Online Change Point Detection for Distribution-Valued Data

When detecting sudden shifts in streaming data, working directly with full distributions instead of flattened summaries catches complex changes that numbers-based methods miss.

Paper explainersAll themesTime Series & Sequential

Online change-point detection watches a stream of data and spots the exact moment something shifts. Today's methods boil each chunk of data down to a few summary numbers: the average, the spread, maybe a few percentiles. But those summaries can hide real changes—like when data that was tightly clustered suddenly spreads out, or when the pattern of how often different values appear changes drastically. This paper treats entire patterns of data as geometric objects and detects when they change by measuring distances in a special space built for comparing patterns.

Zero assumption version

Today's methods flatten patterns into summary numbers

Every online change-point detector today works the same way: take a batch of incoming data, compute a few summary numbers from it (average, variance, a few quantiles), and watch whether those numbers jump. A beginner would do exactly this—it's intuitive and fast.

But it fails silently. Imagine data points that were clustered in a tight ball suddenly spray out in a wide cloud: the average might barely move, but the distribution has fundamentally changed. Or picture two groups of points—say, five near 0 and five near 100—flip to five near 25 and five near 75: the average stays the same, but the shape is completely different. Moment-based summaries (average, variance) can miss both of these. The moment the change is detected, the delayed reaction means you've already processed changed data with the old model.

In one sentence. The paper detects distributional changes by treating entire distributions as points in a curved space and measuring their distances directly, rather than collapsing them into summary numbers first.

The algorithm as a flow

What it actually does

Incoming data: a batch each time step

One batch of data points arrives. Instead of averaging it, keep the whole batch as a distribution.

Compute reference: the Fréchet mean

Before the supposed change, compute the center distribution (called Fréchet barycenter) of all past batches—it is the most-representative distribution from before the change.

Map to tangent space: linearize the curved world

Each new distribution is a point in a geometric space. Rather than measure curved distances, map it to a flat plane anchored at the reference distribution—like unfolding a curved surface onto a table.

Apply standard sequential tests

On the flat plane, use classical change-detection statistics (like cumulative sums) that are designed for flat spaces with simple coordinate axes.

Signal the change moment

The statistic crosses a threshold when the new distribution is far enough from the reference in shape or spread; output the change time.

What the paper changes

The single thing that changes

The paper changes how the detector represents each incoming batch: instead of flattening it into two or three numbers (average, variance, maybe skew), it preserves the entire observed pattern of data as a high-dimensional object and embeds it in a space designed for comparing patterns. The object is the representation itself.

the object it moves  =  distribution representation
The hidden quantity

The hidden quantity: distance in Wasserstein space

measured quantity  =  distributional drift from the baseline

The paper measures a quantity: how far each new distribution sits from the pre-change reference distribution. This distance is not measured in Euclidean space (which would just be a formula like square root of sum of squared differences). Instead, it is measured in Wasserstein space, a geometric framework built specifically for comparing probability distributions. The Wasserstein distance between two distributions asks: what is the minimum total cost to reshape one distribution into the other by moving probability mass? Low distance means the distributions are similar in shape and position; high distance means they differ.

The paper does not compute the raw Wasserstein distance directly in the detector—that would be too slow for streaming. Instead, it maps each distribution to a flat tangent space using the reference distribution as the anchor point. In this flat space, classical detection formulas like cumulative sums can work directly on coordinates without expensive distance re-computations at each step.

Why it works

Why it works: preserving shape to catch all changes

Here is the core insight: a summary number like an average is insensitive to certain real changes. For example, if half your data moves left and half moves right—canceling out the average—the summary does not flag anything, even though the pattern is wildly different. A variance or standard deviation is slightly better because it captures spread, but it still collapses a multidimensional shape into a single number, so offsetting changes in different directions can cancel out and hide true pattern shifts.

By working with entire patterns of data, the paper captures all the structure. A pattern is a high-dimensional fingerprint of the data. When it changes—whether the average shifts, the spread widens, the shape warps, or anything else—that change is baked into the pattern itself.

The trick is doing this efficiently. The Wasserstein space has curves and valleys, not a flat plane. If you computed the full Wasserstein distance at every step, it would be too slow. Instead, the paper flattens the curved space locally, using the pre-change reference pattern as an anchor point. It computes a tangent space—like unfolding a curved surface onto a table—where the reference sits at the origin. Within this flat region, each new pattern becomes a list of coordinates. These coordinates directly encode how the new pattern deviates from the reference. Classical change-detection statistics (cumulative sums, which add up deviations over time) can then run directly on these coordinates, fast and simple. When the cumulative sum exceeds a threshold, change is declared.

Why does this work better? Because the coordinates are built to preserve all aspects of the pattern—mean, variance, shape, tails—not just one or two. A multi-dimensional signal is less likely to be accidentally canceled out by offsetting changes. And because the coordinates live in a space mathematically built for comparing patterns, the detection rule is more likely to catch real changes and less likely to trigger on noise.

Math after the picture

The equation and a worked example

First in words:

The detector accumulates a score from the tangent-space coordinates of each new distribution. The score grows when a new distribution is far from the reference. When the cumulative score exceeds a threshold, change is declared.

Then the compact form:

S_t = max(0, S_{t-1} + (||z_t|| - threshold_offset))

Every symbol:

S_tcumulative detection statistic at time t
S_{t-1}statistic from the previous time step
z_ttangent-space coordinates of the new distribution at time t
||z_t||length of the coordinate vector (how far from reference)
threshold_offsettuning parameter: how much drift is allowed before firing
A tiny worked example
Assume threshold_offset = 1.0 and we start with S_0 = 0.
Time 1: new batch maps to z_1 with ||z_1|| = 0.5 (close to reference). S_1 = max(0, 0 + (0.5 - 1.0)) = max(0, -0.5) = 0.
Time 2: next batch maps to z_2 with ||z_2|| = 0.6 (still close). S_2 = max(0, 0 + (0.6 - 1.0)) = 0.
Time 3: after change, batch maps to z_3 with ||z_3|| = 2.5 (far from reference). S_3 = max(0, 0 + (2.5 - 1.0)) = 1.5.
Time 4: next batch z_4 has ||z_4|| = 2.3 (still far). S_4 = max(0, 1.5 + (2.3 - 1.0)) = 2.8.
Time 5: next batch z_5 has ||z_5|| = 2.4. S_5 = max(0, 2.8 + (2.4 - 1.0)) = 4.2.
If threshold is 3.5, change is declared at time 5 because S_5 = 4.2 > 3.5.

The statistic accumulates deviations as a running total; only when distance from the reference grows consistently does the alarm fire.

What can go wrong

What can go wrong

High-dimensional data with small samples. If each batch contains few data points and the true distribution is high-dimensional, the measured distribution (the estimate from the batch) is noisy. The tangent-space coordinates will wiggle even without a real change. This inflates false alarms.
Pre-change reference period is too short. The reference distribution is supposed to capture what 'normal' looks like. If the training data before the change is brief or unrepresentative, the reference is fuzzy, and true changes are harder to spot.
Slow gradual drift is hard to separate from noise. If the distribution changes very slowly over many batches (rather than one sharp jump), the cumulative statistic might not accumulate fast enough to cross the threshold before the data has already drifted far.
Done right: batch size and threshold chosen carefully. With enough data per batch, a well-tuned reference distribution, and a threshold set to balance false alarms and missed detections, the method is reliable.
What a runnable demo should prove

What a runnable demo should prove

Build a synthetic streaming dataset where the pattern changes at a known time. Generate batches of data from one pattern (say, a narrow cluster), then at time T switch to a second pattern (e.g., a wide cluster or a bimodal pattern). Run both a naive moment-based detector and this paper's tangent-space detector. Measure: (1) detection latency—how many batches after time T does each method flag the change? (2) false-alarm rate—how many false positives in a stable pre-change period? (3) whether the paper's method catches shape changes that the naive method misses?
