General Covariant Action Modeling

Robots learn actions by separating the spatial path from how fast it is traveled, so they can reuse learned skills at any speed.

Paper explainersAll themesRobotics & Control

Robots trained on a few examples of moving an object tend to copy the exact speed and motion style they saw, and fail if asked to move slower or faster, because their learned models encode both the path shape and the specific speed as a single inseparable bundle. This paper builds action representations that separate two independent ideas: what path to take (the shape of the motion) and how fast to travel it (the speed). Once separated, the same learned path can be reused at any speed or execution style.

Why robot learning gets stuck to one speed

A robot learns by watching a few examples of a task—say, moving an object from point A to point B along a smooth path at a particular speed. The naive approach is to train the robot to directly predict the exact position and velocity at each moment, as if those numbers are the fundamental things to remember.

This breaks when the task is the same but the speed is different. The robot memorizes not just the spatial path but the exact timing rhythm. If a human asks it to do the same motion slower or faster, the learned model fails, because the numbers it memorized no longer match. The root problem is deeper: the model conflates two independent ideas—the pure shape of the path and the rate at which you traverse it—into a single rigid bundle. This violates a principle called general covariance: the idea that what truly matters about a motion (the shape of the path itself) should not depend on how fast you move along it.

In one sentence. The paper separates the spatial shape of an action from the timing of its execution, so learned skills work at any speed.

What the paper changes

What the paper changes

The paper changes how the robot encodes actions: instead of storing sequences of absolute positions and velocities (which depend on speed), it stores the pure spatial path shape, separate from the temporal pacing.

the object it moves  =  action representation (position/timing factorization)
The hidden quantity

The hidden quantity the paper measures is how much of the learned action is pure path shape (the trajectory) versus how much is tied to a specific timing or speed. Pure path shape is invariant—it looks the same no matter how fast you traverse it. Timing-dependent information is variant—it changes when speed changes.

The paper estimates this by parameterizing trajectories by arc length (distance along the path) instead of elapsed time. In this reparameterized space, motions at different speeds produce identical representations if their paths are the same. Any difference between two trajectories in this space reveals speed-dependent variation (affine modulation), which the method then learns to factor out separately.

Why it works

Why separating path shape from speed works

A robot is given a few examples of an action—a hand moving from A to B. Each example is a sequence of (position, velocity) pairs recorded at regular time intervals. The naive model directly learns to predict the next position and velocity from the current state. This works for the exact speed in the training examples, because it memorizes that speed as part of the pattern.

Position and velocity are not independent of your choice of how to measure time. If you use arc length (actual distance along the path) instead of elapsed time as your parameter, the shape of the path becomes separated from the speed. Now the learned model can focus on learning the pure spatial shape, which is universal across all speeds.

Once the path shape is isolated, the method uses schema-affine factorization: it learns which parts of the variation are pure path shape (the 'schema'—the essential shape) and which parts are affine modulations (scaling, rotation, style changes that adjust the base path for different contexts). The modulations are learned separately, so they don't mix with the learned path shape.

The result is a learned action that is genuinely reusable. Changing the speed parameter or the execution style only affects the affine part; the core path shape remains valid. This is why the robot can generalize to new speeds and styles without retraining.

The arc-length reparameterization

First in words:

The position along the path parameterized by arc length (distance traveled) instead of time. As the robot moves, it records its position as a function of arc length, not elapsed time. This removes speed dependence.

Then the compact form:

p(s) = position as a function of arc length s; speed = d(arc_length) / d(time); geometry invariant under speed changes

Every symbol:

A tiny worked example
Suppose a robot moves along a circular path of radius 1 meter, starting at angle 0.
Naive method: record position at regular time intervals (e.g., every 0.1 seconds). If the robot moved faster or slower, the time-indexed sequence would be completely different.
Arc-length method: record position at regular distance intervals (e.g., every 0.1 meters along the circumference). The arc-length-indexed sequence is identical regardless of speed. A fast traversal and a slow traversal of the same circle produce the same learned representation, differing only in how the speed parameter varies over arc length.

By indexing position by distance traveled instead of time, the learned path shape becomes independent of speed, enabling transfer across different execution speeds.

What can go wrong

What can go wrong

Path is not strictly smooth. Arc-length reparameterization assumes a smooth, continuous path with a well-defined tangent direction everywhere. If the true path has sharp corners or discontinuities, computing arc length breaks down.
Speed variation is not the only source of variation. If actions vary in shape (not just timing), factorizing into pure path shape and affine modulation may fail to separate them cleanly. The method assumes that non-speed variation is small and affine (multiplicative or rotational scaling).
Training data is too sparse or biased. If examples cover only a narrow range of speeds or styles, the learned factorization may not generalize beyond that range. The method still requires enough variety to disambiguate path shape from modulation.
Done right: map trajectories to canonical coordinates. Mapping all learned actions to a standard reference frame ensures that path shape comparisons are fair regardless of local orientation or position, and affine modulations are explicit.
What a runnable demo should prove

What a runnable demo should prove

Train a robot on 3–5 examples of moving an object along a path, all recorded at a standard speed (e.g., 30 cm/s). Then test it on the same path at three speeds: the training speed, half speed (15 cm/s), and double speed (60 cm/s). Measure success (e.g., endpoint accuracy, path tracking error) for each test speed.

generalization_success = (accuracy_at_half_speed + accuracy_at_double_speed) / 2; baseline_success = same metric for a model trained on positions and velocities

The method (which decouples path shape from speed) should maintain high accuracy across all three speeds, while a naive position-velocity model should collapse at non-training speeds.
