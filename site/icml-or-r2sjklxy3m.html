Energy-based Compositional Diffusion Planning

When a robot pieces together short movement sequences into long plans, a math trick ensures the stitched path obeys real physics, not just local guesses.

This paper uses an energy-based framework to compute a full path that stays in the regions the actual motion patterns occupied in the data.

Zero assumption version

Stitching breaks physics

A robot learns movement from short sequences, maybe ten steps at a time. But a real task takes hundreds of steps. The naive approach: train a small predictor on short sequences, then chain its outputs together to make a long plan.

The problem is subtle. When you glue the predictions end-to-end, the seams do not obey the real patterns in the data. The combined path looks plausible locally but globally consists of internally valid pieces with breaks in between. The robot's model learned what comes after step 5 given step 4. But when you feed it the model's own guess at step 5, you are in a regime it never trained on.

Current methods ignore this mismatch. They just concatenate outputs and hope.

The fix in one sentence. Treat the full trajectory as minimizing an energy function (a sum of local pattern-scores) and solve for the path that keeps all the local scores high at once.

The algorithm as a flow

What it actually does

Divide the horizon

Split the long plan into overlapping short segments (40 steps each, say).

Score each segment

For each segment, compute how well it fits the learned patterns (a local energy or probability score).

Sum the scores

Add up all the local scores into one global energy function for the full trajectory.

Find the minimizer

Solve for the path that has the highest total score—this is the global optimum.

Use a fast solver

The path structure is Markovian (each step depends only on the previous one), so solve via a fast algorithm that works in linear time.

What the paper changes

What the paper changes

The paper changes how the full trajectory is computed. Instead of greedily stitching local outputs, it solves a global optimization: find the path that jointly maximizes all the local scores.

the object it moves  =  the trajectory as an energy minimizer
The hidden quantity

The boundary reaction term

measured quantity  =  boundary correction field

When you partition a long path into local segments, each segment has a starting state and an ending state. The ending state of one segment becomes the starting state of the next. This boundary is where information flows between segments.

The paper measures a quantity that naive stitching misses: the correction needed at each segment boundary to ensure the global path stays in high-probability regions. This is the boundary reaction term. It arises mathematically when you enforce that the end of one segment matches the start of the next. Naive stitching just forces this boundary to match without correcting for the probability cost; ECD solves for the correction that keeps the full path valid.

Why it works

Why global optimization works

Stitching is a local problem—each piece fits its own pattern—but the global path must fit all pieces together. Naive stitching optimizes each segment independently, then joins them. This leaves no freedom to adjust for the seams.

ECD reformulates the problem: instead of optimizing segments, optimize the full trajectory as a single entity. The trajectory's score is the sum of local segment scores. When you solve for the path that maximizes this sum, the optimizer automatically computes what each seam must be to make the whole valid. This is the boundary reaction. The math reveals that neglecting this term—as naive stitching does—leaves the path in a lower-probability region. ECD recovers it.

The solver is fast because the dependency structure is Markovian: step t depends only on step t-1. This structure means the score table has a special pattern solvable in linear time.

Math after the picture

The energy and its solution

First in words:

The global trajectory energy is the sum of local segment energies plus boundary alignment terms. The full path minimizes this sum. The solution is found by solving a block-tridiagonal linear system.

Then the compact form:

E(tau) = sum_i E_i(tau_i) + sum_i lambda_i * (tau_i^end - tau_{i+1}^start)^2

Every symbol:

E(tau)total energy of the full trajectory tau
tau_istates in segment i (a subsequence of the full path)
E_i(tau_i)energy of segment i (negative log probability from learned model)
tau_i^endfinal state of segment i
tau_{i+1}^startfirst state of segment i+1
lambda_istrength of boundary matching at seam i
A tiny worked example with 3 segments
Segment 1 energy: E_1 = -log p(path1) = -2.0 (path1 is plausible, negative energy means high prob)
Segment 2 energy: E_2 = -log p(path2) = -1.8
Segment 3 energy: E_3 = -log p(path3) = -2.2
Boundary mismatch at seam 1: (path1_end - path2_start)^2 = 0.3, penalty = lambda_1 * 0.3 = 0.15
Boundary mismatch at seam 2: (path2_end - path3_start)^2 = 0.2, penalty = lambda_2 * 0.2 = 0.10
Total energy = -2.0 + -1.8 + -2.2 + 0.15 + 0.10 = -6.75
Naive stitching (ignoring boundaries) = -6.0, leaving 0.75 in unaccounted error.
Minimizing E jointly finds the path adjustment that recovers the missing 0.75.

The solver enforces boundaries and auto-computes the correction term; naive stitching omits this step, leaving the path suboptimal.

What can go wrong

What can go wrong

Segments too short. If each segment is only 3–4 steps, there is little room to correct at boundaries, and the energy function becomes stiff. The solver may struggle to find valid paths.
Learned model is poor. If the base diffusion model does not capture the task's true patterns, the energy function will have many false minima (multiple wrong local optima). ECD finds the best of those wrong minima, but the result is still bad.
Mismatch at task boundaries. The method assumes segments overlap and that the learned patterns are smooth across the seams. If the task has hard discontinuities (a sudden mode switch), energy-based stitching may smooth over them incorrectly.
Done right. Segments are 30–50 steps, the base model is well-trained, and boundaries are smooth. The energy solver finds a high-probability path fast.
What a runnable demo should prove

What a runnable demo should prove

Build a simple robot task: navigate to a goal in a 2D grid, starting from random positions, using a diffusion model trained only on 20-step trajectories. Plan a 200-step path to the goal using three methods: (1) naive stitching, (2) simple averaging at boundaries, (3) ECD. Measure whether the robot reaches the goal without getting stuck or backtracking.

success_rate = (goals_reached) / (total_trials); plan_quality = (steps_taken) / (optimal_steps)

ECD should reach the goal reliably even on unseen start-goal pairs, while naive stitching fails when the full horizon exceeds training length.
