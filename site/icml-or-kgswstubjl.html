MultiHal: Knowledge-Graph Grounded Hallucination Evaluation

To test whether LLMs make up facts, use structured knowledge graphs instead of loose text passages, across multiple languages.

Paper explainersAll themesDatasets & Benchmarks & Evaluation

When you ask a language model a question, sometimes it answers with made-up facts. We call this hallucination. Testing if models hallucinate is hard because most test sets are in English and use loose text passages as truth. This paper proposes using structured knowledge graphs — like a filing cabinet that links entities by their real-world relationships — as the source of truth, in many languages at once.

Zero assumption version

Test sets for hallucination are fragmented and weak

Current benchmarks for measuring LLM hallucinations are mostly in English and rely on text passages as ground truth. Text passages are noisy: they have synonyms, paraphrases, and linguistic ambiguity that make it hard to decide if the model was correct or hallucinating.

A beginner might try: just compare the model's answer to the reference text word-by-word. This breaks because the model might rephrase the answer correctly but use different words, and the comparison fails.

The real problem is that these benchmarks ignore structured factual resources like knowledge graphs, which cleanly represent who is related to whom and what facts are true. Knowledge graphs are language-agnostic: the same relationship holds in English, German, or Mandarin.

In one sentence. MultiHal uses structured knowledge graphs as the ground truth to test LLM hallucinations, in multiple languages at once.

The algorithm as a flow

What it actually does

Mine paths from knowledge graphs

Extract 140k potential entity-relation-entity triples from Wikidata and DBpedia linked to questions and answers.

Link questions and answers to entities

Use a tool (Falcon 2.0) that recognizes which entities appear in the question and answer text.

Filter with an LLM judge

Use another language model to score each path: does it actually support the answer to this question?

Keep only the best paths

Curate down to 25.9k high-quality paths by removing noisy and low-confidence triples.

Test models with these paths

Feed the path context to the LLM and measure if its answers now match the graph ground truth better, because structured facts are clearer than text passages so the model makes fewer mistakes.

What the paper changes

What the paper changes: the source of truth

Instead of comparing an LLM's answer to loose text passages, this paper compares it to structured knowledge-graph paths. A path is a clean triple: an entity, a relationship, and another entity. No linguistic ambiguity. No synonyms.

the object it moves  =  source of truth: from text to graph triples
The hidden quantity

The hidden quantity: path relevance quality score

measured quantity  =  path relevance quality score

Not all mined paths are useful. Some paths are off-topic, some are outdated, and some are simply wrong. The paper needs a way to measure which paths truly support each question-answer pair. This is the quality score: a number (1-5 or similar) assigned by an LLM judge, rating whether a path is relevant to the question and whether it agrees with the correct answer.

The paper estimates this by prompting a language model (Claude or GPT-4o-mini) to read a question, an answer, and a knowledge-graph path, then output a score. They do this twice — once to select the top 10 most relevant paths from many candidates, then again to score each path individually — to reduce bias from path ordering.

Why it works

Why it works: structured facts need no linguistic translation

Text passages force every language to solve the same problem: map words to meaning. The word 'founded' in English, 'gegründet' in German, and 'फाउंड' (transcribed) in Hindi all mean the same thing, but they look different. A model trained mainly on English might not recognize the German word with confidence. Knowledge graphs sidestep this: the relationship is the same triple in every language. There is no translation ambiguity, only entity recognition.

Second, a knowledge graph path is minimal. It says exactly what is true: X founded Y. A text passage might say 'X founded Y in 1985, and later...' which is true but contains distracting details. The model must extract the core fact from noise. A graph triple has no noise.

Third, because paths are scorable by an LLM judge (using a prompt), the benchmark can filter itself. If a path is confusing or wrong, the judge's score is low and it gets removed. Text passages cannot be easily scored this way — you would have to read each one and decide by hand.

Scoring equation: path relevance

First in words:

The quality score Q for a path P given question Q and answer A is determined by prompting an LLM judge. In practice, the score is a discrete rating (e.g., 1 to 5 stars). For the benchmark, only paths with score >= threshold are kept. The threshold is chosen such that the average quality score correlates strongly with the semantic similarity between the model's prediction and the ground truth answer.

Then the compact form:

Q(P, Q, A) = LLM_judge(P, Q, A) in range [1, 5]; keep P if Q(P, Q, A) >= threshold

Every symbol:

Q(P, Q, A)quality score of path P for question Q and answer A
LLM_judgea language model prompted to rate the path
Pa knowledge-graph path (entity-relation-entity triple)
Qa question
Athe correct answer to that question
thresholdminimum quality score (e.g., 3 or 4) to include the path in the benchmark
A tiny worked example
Question: Who founded Microsoft?
Answer: Bill Gates.
Path 1 from KG: Bill Gates -> founder_of -> Microsoft. LLM judge rates this 5 (perfect match). Keep it.
Path 2 from KG: Microsoft -> has_employee -> Bill Gates. LLM judge rates this 2 (supports answer but indirect). Discard it.
Path 3 from KG: Paul Allen -> co-founder_of -> Microsoft. LLM judge rates this 1 (wrong answer; Allen, not Gates). Discard it.
Result: only Path 1 remains in the benchmark for this question. Clean, direct, scored.

The LLM judge scores each path by reading it in context of the question and answer, then discards low-scoring paths to create a high-quality benchmark.

What can go wrong

What can go wrong

Incomplete knowledge graphs. If an entity or relationship does not exist in Wikidata or DBpedia, no path can be mined. The benchmark cannot evaluate that question, because there is no structured fact to compare against. Using multiple knowledge graphs together increases coverage because different graphs contain different entities and relationships, so more paths are found overall.
LLM judge itself hallucinates. If the LLM scoring the paths makes mistakes, the quality scores are unreliable. A bad path might get a high score, or a good path might get a low score. Solution: the paper mitigates this by (1) prompting with two passes to reduce ordering bias, (2) discarding any path that the judge returns that is not an exact syntactic match in the KG, and (3) checking that the quality scores correlate with actual semantic similarity.
Multilinguality mismatch. An entity might have a different name in different languages (e.g., 'Munich' vs. 'München'). If the entity linking tool (Falcon 2.0) fails to recognize the name in one language, the path is missed. Solution: the paper uses three entity-linking methods for redundancy (Top-3 candidates, DBpedia, Wikipedia).
Done right. MultiHal addresses these by filtering aggressively (25.9k from 140k mined paths), using a trusted LLM judge with structured prompts, and validating that quality scores correlate with real semantic similarity before publishing the benchmark.
What a runnable demo should prove

What a runnable demo should prove

Build a simple hallucination detector: (1) Take a question and a candidate answer from an LLM. (2) Extract the entities from both using Falcon 2.0 or a similar tool. (3) Retrieve knowledge-graph paths linking those entities from Wikidata. (4) Score each path by asking an LLM judge: does this path support the answer? (5) If high-scoring paths support the answer, the answer is factually grounded. If no high-scoring paths exist, the answer is likely hallucinated. (6) Measure accuracy by comparing the detector's judgment against MultiHal's ground truth for 100 questions in English, German, and Arabic. (7) Repeat the same measurement with vanilla text-based comparison (instead of graph paths) and show that graph-based detection is cleaner and more consistent across languages.

Hallucination detection accuracy = (correct detections on graph paths) / (total questions); Cross-language consistency = min semantic similarity score across languages / max semantic similarity score across languages (higher is more consistent)

The demo should make it impossible to miss: graph-grounded evaluation is cleaner than text-based, and the same benchmark works reliably across languages.
