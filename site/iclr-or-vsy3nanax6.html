BOLT: Decision-Aligned Distillation for Constrained Multimodal QA

Train a smaller model to match a big model's actual multiple-choice decisions, not its word-by-word guesses, then use cheap signals to decide when to ask for a better answer.

Paper explainersAll themesRobotics & Control

Robots answering questions with pictures need a fast, memory-light brain. Big language models are accurate but too slow and heavy for a robot's onboard chip. BOLT teaches a tiny model to copy the big model's actual decisions, not its training signals, then adds a smart router that knows when to run extra checks.

Why tiny robots cannot just copy the big model

A robot on a job site receives pictures and questions: 'Is that a safe grip?' Answering this needs a large language model that understands both images and words. A big model like LLaVA works well but weighs 13 billion numbers. A robot's onboard computer has maybe 3 gigabytes of memory and runs on battery. The big model hogs 27 gigabytes, drains the battery in minutes, and answers too slowly for real work.

A naive fix is to just shrink the model to 2 billion numbers. It gets smaller and faster, but now it guesses wrong 71% of the time instead of 63%, because the tiny model has fewer numbers to store the patterns it learned from training examples. With fewer learned patterns, it makes more mistakes on new questions.

The next idea: teach the tiny model to copy the big model's word-by-word predictions during training. You feed the big model a question, it produces a stream of words, and you train the tiny model to produce the same words. This technique is called distillation. It helps, but the tiny model still gets confused because the big model's intermediate words are not always what matters. The tiny model wastes learning capacity memorizing every word choice, when all the robot really cares about is: which option is correct?

The actual problem. A tiny model trained to copy word-by-word predictions still fails too often because it is learning the wrong thing. The robot needs the right answer, not the right words.

The algorithm as a flow

What it actually does

Train decision-first

Show tiny model question + picture. Record which option the big model chose. Train tiny to pick that same option, ignoring the big model's word steps.

Learn to spot doubt

Measure when the tiny model is uncertain: very high confidence, small gap between top two options, jumbled answer pattern.

Trigger expensive steps only when unsure

If tiny is confident, answer now. If uncertain, send the question to the big model or break it into simpler parts.

Check the answer against facts

Look up similar past questions and answers. If the tiny model disagrees with what retrieval says, ask for a redo.

Return a transparent answer

Tell the robot: here is the answer, here is how confident we are, here is the evidence we found, here is how we broke down the question.

What the paper changes

What the paper changes

BOLT changes the training target. Instead of training the tiny model to copy the big model's word stream (what each word should come next), it trains the tiny model to copy the big model's final multiple-choice decision (which option is correct). This is a fundamental shift in what the tiny model learns.

the object it moves  =  the training target
The hidden quantity

Model confidence and when to trust it

measured quantity  =  five-signal uncertainty measure

The tiny model assigns a confidence number to each answer, but a single confidence is often wrong—the model can sound sure but be mistaken, or doubtful but right. BOLT solves this by combining five independent measurements to predict whether the tiny model should ask for help. These five signals are: how sure the top option is, the gap between first and second choice, how spread out the probabilities are (entropy), whether a quick database lookup agrees, and whether breaking the question into pieces gives the same answer. When these five signals disagree, the tiny model is likely to be wrong and should ask for help, because disagreement between independent checks is a sign that the model is confused or at a boundary case where expert analysis would change the answer.

Darker: the tiny model's answer is at risk. Lighter: the answer is trustworthy.

Plain reading. Before BOLT, the model just produced an answer. BOLT adds: measure five different signals about whether that answer is risky. When signals warn of risk, run a better process, because the cheaper signals are not always right but they are fast, so you only pay the cost of the expensive better process when the cheap signals suggest you might be wrong.
Paper reading. The paper frames this as calibration: do the model's confidence numbers match the real probability it is right? BOLT directly optimizes this match by observing: when do cheap augmentations actually change the answer?
Why it works

Why aligning on decisions works better than aligning on words

When you train a tiny model to match a big model's word stream, the tiny model has to memorize many arbitrary word choices. The big model might say 'Option A is the safest grip because the angle is 47 degrees and the surface is textured.' The tiny model trains on this exact word sequence. But a different way of saying the same answer — 'The textured angle works best, option A' — is treated as a different, wrong target. The tiny model wastes capacity learning stylistic choices, not understanding.

When you train on decisions only (just 'A' or 'B'), you remove the noise. The tiny model learns a direct path: given this picture and question, map to the right option. All the big model's explanatory words are gone, so the tiny model cannot copy them. Instead, it must develop its own internal logic for why A is right. Often this logic is simpler than the big model's explanation and makes fewer mistakes when it is wrong. The tiny model also becomes better calibrated: it learned exactly what matters, so when it is confident, it is more often right, because the training signal only rewarded picking the right option, not producing the right explanation, so confidence now aligns with correctness rather than with how fluent the model is at producing words.

When the finished tiny model answers a question (this phase is called inference), BOLT pairs it with a router. The router checks five signals: Is the tiny model sure? Do retrieval examples agree? Would breaking the question into pieces give the same answer? These signals are fast to compute. Only when signals warn does the router call the big model or run question decomposition. This keeps the average time to answer low while preserving accuracy.

Math after the picture

The decision loss equation

First in words:

loss = negative log probability of the correct option + weighting term times regularization

Then the compact form:

L = -log(P(correct_option | image, question)) + alpha * KL_divergence(student, teacher)

Every symbol:

Lthe training loss (what to minimize)
P(correct_option | image, question)the probability the model assigns to the right answer
alphahow much to penalize the student if it drifts from the teacher
KL_divergencea measure of how different two probability distributions are
A tiny worked example
Say the tiny model assigns probabilities: option A = 0.6, option B = 0.3, option C = 0.1.
The correct answer is A. The loss for this example is: -log(0.6) = 0.51.
The teacher model assigns: A = 0.8, B = 0.15, C = 0.05. The KL divergence is 0.12.
Total loss = 0.51 + 0.5 * 0.12 = 0.51 + 0.06 = 0.57.
The model learns: assign higher probability to A (closer to 0.8), and match the pattern of how likely the teacher thinks each option is.

Unlike word-by-word distillation which forces the tiny model to match every word the big model outputs, this loss only cares about the option probabilities. The tiny model is free to think differently, as long as it lands on the right answer.

What can go wrong

What can go wrong

The big model itself is wrong. BOLT copies the big model's decisions during training. If the big model makes a mistake, the tiny model learns the same mistake. The fix: curate the training data to remove cases where the big model is overconfident but wrong.
The router's signals do not predict when the tiny model is actually wrong. If the five signals (confidence, margin, entropy, retrieval, decomposition) do not correlate with error, the router will waste time running expensive checks on easy questions and miss hard ones. The fix: validate the signals on a held-out dataset before deploying.
The tiny model overfits to one type of question. If training data is imbalanced (many robot-grip questions, few obstacle-detection questions), the tiny model will be confident but wrong on rare types. The fix: ensure the training set covers all question types the robot will face.
Done right, BOLT is transparent. BOLT constrains outputs to valid options (no hallucinated answers), exposes retrieval evidence, and shows question decomposition traces. A human can audit why the robot chose its answer.
What a runnable demo should prove

What a runnable demo should prove

Build a demo that trains a small vision-language model on a set of multiple-choice visual questions about objects, scenes, or safety. Use decision-aligned distillation: instead of matching word streams, train the tiny model to pick the same option as a larger teacher model. Measure accuracy before and after. Then add the router: for each test question, compute the five signals (the tiny model's confidence, margin, entropy, agreement with a small retrieval index, consistency of a simplified question). Plot: for questions where all five signals are confident, report accuracy; for questions where signals warn, run a more expensive process (retrying with the big model) and report the improved accuracy. Show that the router's signal-based decision to ask for help actually improves the answer because when the five independent signals disagree, the tiny model is nearly always in an error-prone zone, so routing to the big model recovers accuracy much more often than it wastes compute on already-correct answers.

decision_accuracy = fraction of multiple-choice questions where tiny model picks the same option as big model during training, then test_accuracy_high_signal = accuracy when router says all signals green, test_accuracy_routed = accuracy when router runs expensive fallback

A working demo makes impossible to miss: the tiny model alone misses 50% of questions, but paired with a cheap signal-based router, it reaches 70% or higher by knowing when to think harder. The router's decision to ask for help actually improves accuracy because the five signals together are better at predicting error than any single model's confidence, so triggering the expensive check when signals warn recovers most of the accuracy gap without running the big model on every question.
