OneTwoVLA: Unified Reasoning and Acting

A single robot model learns to think deeply when it matters and act quickly the rest of the time.

Paper explainersAll themesRobotics & Control

Robots that do complex tasks need to both reason about what to do and physically move their arms. Most robot systems split this into two separate pieces: a thinking system and a doing system. But keeping two systems in sync is slow and they often misunderstand each other. OneTwoVLA is one unified model that decides when to reason carefully and when to just act.

Zero assumption version

Why one system is not enough, but two systems are too slow

A robot making hotpot needs to both understand the world and grab things. Understanding comes from looking at the scene, reading the recipe, planning steps. Grabbing comes from moving arms precisely. A naive approach: train one model to take a picture and output the arm movement directly. This breaks when the task is long and complex, when the robot makes a mistake, or when objects look different than in training.

The old solution: use two separate systems. A thinking system (a language model trained on internet text) reads the scene and makes a plan. An acting system (trained on robot videos) takes that plan and moves the arms. The problem: these two systems run separately, with delays between thinking and acting. The thinking system does not know how the robot will actually move. The acting system does not know the full plan. They waste time handing information back and forth, and the robot gets stuck.

The core question. Can one model learn when to think, and when to just do?

What the paper changes

The one thing the model learns to change

OneTwoVLA learns to switch between two modes: a reasoning mode (write natural language descriptions and plans) and an acting mode (output robot arm movements). The model does not reason every step; it reasons only at moments marked as critical: when completing a subtask, detecting an error, needing human clarification, or changing strategies.

The hidden quantity

The hidden quantity: Task criticality

measured quantity  =  Which moments need explicit reasoning

Every moment in a robot task sits on a spectrum: some moments need the model to stop and think hard (when the robot notices something went wrong, or when a subtask finishes), other moments just need quick action (reaching for a nearby object that was just described). This spectrum is the hidden quantity the model learns to estimate.

OneTwoVLA infers task criticality by learning which situations demand reasoning: error states (grasping failed, object not found), task transitions (subtask completed, next phase begins), human input needed. The model was trained on diverse examples where human annotators marked which reasoning points mattered, so it learned the pattern.

Why it works

Why one unified model with adaptive switching works

When reasoning and acting are in the same model, the model naturally shares what it learns about the world. If reasoning identifies that the tomato is in the top shelf, that knowledge instantly flows into the action head because they live in the same neural network. There is no delay.

But reasoning is expensive: it writes words one by one, and that takes time. If the model reasoned on every step, the robot would move once per second instead of ten times per second. During training, the model gets a loss signal that penalizes both slow operation (inference, meaning when the finished model answers a new scene) and wrong answers. The model learns that skipping reasoning on routine moments shrinks the loss: the robot moves fast and still gets actions right because those moments follow the plan. So the model learns a decision head that looks at the current situation and predicts whether this is a critical moment—because that trade-off (fast on most steps, slow only when needed) minimizes overall loss. On critical moments (error, task transition, new instruction), the model writes out its reasoning. On routine moments (continuing a known action), it skips reasoning and jumps straight to action. This keeps the robot fast while keeping it smart.

Here is what makes this work: the model never truly forgets the reasoning, even on action-only steps. The reasoning is baked into the weights from co-training (mixing robot videos with language-annotated reasoning examples). So when the model acts, it is acting as though it had just reasoned, without paying the time cost.

How the model learns to act without always reasoning

First in words:

reasoning_loss + action_loss + co_training_weight × vision_language_loss

Then the compact form:

L_total = L_reason + L_action + λ · L_vl

Every symbol:

L_reasoncross-entropy loss on reasoning text tokens during critical moments
L_actionflow-matching loss on continuous arm motion outputs
L_vllanguage-vision loss on synthetic question-answer reasoning pairs
λthe weight controlling how much synthetic reasoning data helps
A tiny worked example
Suppose robot sees a hidden object and needs to reason (L_reason = 2.5). It should open the door, so the text head penalizes wrong predictions heavily.
On the action step, the arm moves 15 degrees; the flow-matching loss says that move fits well (L_action = 0.3).
The model was also trained on language examples where humans explained reasoning. That loss L_vl = 1.8, and λ = 0.5.
Total: 2.5 + 0.3 + 0.5 × 1.8 = 3.4. The model learns that good reasoning + language data drives down total loss, so it reasons at critical moments.

Mixing reasoning loss, action loss, and language-vision loss teaches the model to decide adaptively, without paying the time cost on every step.

What can go wrong

What can go wrong

Reasoning always is too slow. If the decision head was broken and always chose to reason, the robot would move slowly because text generation is serial (one token at a time). This defeats the purpose. OneTwoVLA avoids this by learning to reason only at key moments.
Acting always loses understanding. If the model learned to act without reasoning on complex tasks, it falls back to memorized patterns and fails when the scene changes or new objects appear. The co-training with language data prevents this by encoding (storing) semantic understanding into the weights, so the model carries real world knowledge even on action-only steps.
Decision boundary is brittle. If the decision head learns a sharp rule like always reasoning when x=red, it will fail when red appears in unexpected contexts. OneTwoVLA mitigates this by training on diverse reasoning scenarios so the decision head learns nuanced patterns.
Done right. The model learns a soft decision function tuned on thousands of diverse examples, reads the decision back from the data at test time, and shares learned world knowledge between reasoning and acting heads via the shared encoder.
What a runnable demo should prove

What a runnable demo should prove

Build a minimal robot simulator with three objects (a plate, a tomato, a hidden cola in a fridge). The task is complex: fetch the cola (requires reasoning to remember it is in the fridge), place it on the plate, then fetch the plate. Simulate the model as a neural network with a decision head, a reasoning head (language generation), and an action head (motion). Train the decision head to predict reason-or-act on 100 labeled examples. At test time, measure two things: (1) How many steps did the model reason vs act? (2) What was the success rate?

reasoning_efficiency = (actions_taken / total_steps) × 100; success = (tasks_solved / test_episodes) × 100

The demo must show that with adaptive reasoning, the model acts on 70% of steps yet solves 85%+ of complex tasks, whereas pure acting solves only 40% and pure reasoning solves 80% but is 4x slower.
