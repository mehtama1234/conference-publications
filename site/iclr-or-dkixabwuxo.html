Earth-Agent: Unlocking the Full Landscape of Earth Observation with Agents

Give an Earth observation agent access to domain tools across image types so it can answer scientific questions that require several measured steps, not just one visual guess.

Paper explainersAll themesAgents & Tool Use

Earth observation work rarely ends with one image caption. Scientists need to compare dates, combine sensor types, extract measured quantities, and call specialist tools that know how to turn raw satellite data into usable estimates. General vision-language systems are weak at this because they usually focus on visible-color images and short responses. Earth-Agent builds an agent framework for this domain. It combines visible-color and spectral data inside one tool ecosystem and evaluates the whole process with a benchmark that checks both the reasoning path and the final answer. The goal is not only to describe what an image shows, but to answer real scientific questions by invoking the right tools in sequence.

Why ordinary vision agents are too shallow for Earth observation

A remote-sensing question may ask for crop stress over time, water change across regions, or a physical quantity derived from multiple sensor bands. A standard image agent often answers from one picture and one pass of text generation. That is too shallow for scientific use because the question may require comparing several dates, calling a retrieval tool, applying a domain model, and checking units before answering.

There is also a modality gap. Earth data does not come only as visible-color images. It includes spectral measurements and derived products whose meaning depends on domain-specific processing. An agent that only reads ordinary pictures cannot use much of the evidence scientists rely on.

The paper's move in one sentence. Unify visible-color imagery, spectral data, and specialist Earth tools in one agent loop so multi-step scientific questions can be solved through tool use.

The hidden quantity

The hidden quantity: scientific reach

measured quantity  =  How much of a real Earth workflow the agent can execute

The important quantity is scientific reach: the fraction of domain work the agent can carry out before a human must take over. A system with low reach may answer basic visible-color questions but fail as soon as the task needs spectral analysis, measured outputs, or multi-date comparison.

Earth-Agent raises this quantity by extending the tool and data space. The benchmark makes that visible by including tasks over visible-color imagery, spectral inputs, and derived products, then scoring both the action path and the final answer. That matters because a final answer can look plausible even when the intermediate tool use was wrong.

Why it works

Why the tool ecosystem matters more than one stronger captioning model

A stronger captioning model can describe imagery more fluently, but that alone does not produce quantitative Earth analysis because scientific tasks need explicit operations: retrieve the right scene, compute a domain quantity, align time points, compare locations, and check the result. Earth-Agent gives the model a way to call those operations directly.

This changes the system from a one-shot predictor into a workflow controller. The answer improves because each step can use the right data type and the right specialist tool. Visible-color inputs can support broad scene understanding, while spectral inputs and derived products support measured conclusions. The benchmark's trajectory scoring is important because it rewards correct scientific process, not just a plausible sentence at the end.

The evaluation idea

First in words:

Score both whether the final answer is right and whether the intermediate tool sequence followed a sound scientific path.

Then the compact form:

overall_score = path_score + answer_score

Every symbol:

path_scorecredit for using a sensible sequence of domain tools and intermediate steps
answer_scorecredit for the final task answer
overall_scorecombined evaluation across process and outcome
A tiny worked example
A task asks for a quantity change between two dates.
The agent retrieves both scenes, runs the needed domain tool, and compares the resulting values.
Suppose the tool path is mostly correct, so path_score = 0.8.
Suppose the final numeric answer is also correct, so answer_score = 1.0.
Then overall_score = 0.8 + 1.0 = 1.8.
If the final answer had looked plausible but the tool sequence was unsound, path_score would fall, exposing the weakness.

Dual-level scoring matters because scientific credibility depends on process as well as outcome.

What can go wrong

What can go wrong

The wrong tool is selected. If the agent chooses a tool for the wrong sensor type or quantity, the rest of the workflow can stay internally neat but still answer the wrong question.
Intermediate measurements are not carried forward correctly. Multi-step Earth tasks depend on earlier outputs. If one value is dropped or misread, later comparison steps can fail even when the right tools were called.
Evaluation over-rewards final wording. A scientific answer can sound reasonable while resting on a flawed process. That is why the benchmark scores the path as well as the endpoint.
Done right. When the agent selects the right modality, calls the right domain tools, and preserves intermediate results, it can solve harder Earth tasks because the workflow mirrors how domain experts actually work.
