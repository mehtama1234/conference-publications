Disentangled Representation Learning for Parametric Partial Differential Equations

Learn what hidden physical factors were baked into a trained equation-solver's weights by building a translator that turns those weights back into interpretable numbers.

Paper explainersAll themesAI for Science

A neural operator is a trained network that solves physics equations (like heat flow or fluid dynamics) by learning patterns in data instead of doing math step by step. The problem: once trained, it is a black box — you cannot see which parts of its weights correspond to physical properties like viscosity or stiffness. DisentangO reverses this. It builds a secondary network that takes a trained operator's weights as input, unpacks them back into clean, separate numbers that represent the actual physics underneath.

The black-box problem in equation solvers

A neural operator is trained to take an input (like a starting temperature map) and predict the output (like the heat after time t). It learns the mapping by fitting to examples. The network works well — it predicts correctly. But its weights are tangled. You cannot point to any part of the weights and say 'that piece encodes viscosity of 0.5'. The operator has internalized the physics, but the physics is scattered across millions of numbers.

A beginner's first try: look at which weights change the most when the physics changes. It does not work, because many weights shift together in ways that reflect the network's shape, not the physics. You get noise.

In one sentence. DisentangO decodes a trained operator's weights back into separate, clean numbers that name the physical properties it learned.

The algorithm as a flow

What it actually does

Train the forward operator

Build and fit a neural operator on the PDE data for many physics scenarios (different viscosities, stiffnesses, etc.). Each scenario gets its own set of weights.

Extract the task-specific weights

For each scenario (task), the operator's first layer has weights that adapt to the physics. These are the keys we need to decode.

Feed weights into the hypernetwork

A secondary network (the hypernetwork) takes those weights as raw input and processes them like data, not like static settings.

Compress through a bottleneck

A variational autoencoder (a compression tool that forces data into a small set of independent numbers) squeezes the weights into a list of clean, named physics factors.

Validate against labeled physics

If you have a few examples where the true physics is known, train the system to match those as well. The network learns to extract real, interpretable numbers.

The hidden quantity

The hidden quantity: disentangled physics factors

measured quantity  =  Clean physics factors extracted from weights

When a neural operator learns to solve a PDE with many possible physical scenarios, it bakes the scenario into its weights. For example, if viscosity changes, the weights shift in a particular way. But the shift is tangled with other numerical side effects. A disentangled factor list is a short list of numbers — like [viscosity 0.51, stiffness 2.1, damping 0.8] — that has been extracted and cleaned so that each number means one physical property and one only.

The paper estimates this by building a bottleneck in the middle of the hypernetwork. The compression forces the network to discard noise and keep only the interpretable, separable parts, because the network must fit the data using only the small bottleneck information — anything not essential gets squeezed out. If the paper has access to labeled examples (semi-supervised), it adds an extra loss term that pulls those factors toward the true physics values, making the extraction more accurate, because the network now has a direct signal: 'you extracted the wrong number, the true viscosity is 0.5, not 0.6'.

Why it works

Why it works: the hypernetwork chain

The core insight is that a neural operator's weights are a deterministic function of the underlying physics. If you train on many scenarios, each scenario stamps a different weight pattern. Those patterns are real — they are not random. A secondary network can learn to reverse-engineer the mapping: given weights, predict the physics.

Why the bottleneck (variational autoencoder) helps: if you tried to directly decode weights, the network could memorize useless noise — maybe one particular weight always happens to encode some irrelevant detail about how the optimizer initialized things, because there is no cost to fitting those details if you have enough capacity. A bottleneck forces the network to compress. It has to squeeze the weight information through a narrow channel of K clean numbers (e.g., between 5 and 10). To do that, it must throw away noise and keep only the structure, because the small bottleneck cannot hold both the noise and the real physics at once — it acts as a filter. The factors on the other side of the bottleneck are forced to be independent (by a constraint called KL divergence), so each factor encodes a different axis of variation in the physics, because overlapping factors would be redundant and the constraint penalizes redundancy.

Math after the picture

The equation: reconstructing weights from factors

First in words:

Total loss equals: data prediction loss (how well does the operator solve the PDE) plus weight reconstruction loss (can we rebuild the weights from the compressed factors) plus KL regularization (are the factors independent and centered) plus optional semi-supervised loss (if we know some true physics, pull the factors toward it).

Then the compact form:

L_total = beta_d * L_data + L_recon + beta_KL * L_KL + beta_semi * L_semi

Every symbol:

L_dataprediction error: how far the operator's output is from the correct PDE solution
L_reconreconstruction error: difference between original weights theta and reconstructed weights from the bottleneck
L_KLKL divergence: distance between the learned factor distribution and a standard normal distribution, encouraging independence
L_semisupervised loss: only present if some true physics labels are available; pulls extracted factors toward known values
beta_dweight on data loss (usually 1.0)
beta_KLweight on disentanglement (higher pushes factors to be more independent)
beta_semiweight on semi-supervised constraint (only used when labels exist)
A tiny worked example
Suppose an operator is trained on a viscosity-stiffness grid. For viscosity=0.5, stiffness=2.0: the operator's first-layer weights are [0.12, -0.08, 0.15, 0.03, ...].
The VAE encoder compresses these to a bottleneck: z = [0.1, -0.05] (only 2 dimensions).
The VAE decoder reconstructs: theta_hat = [0.119, -0.078, 0.152, 0.031, ...] — very close to the original.
Reconstruction loss = mean squared difference = 0.0001 (very small, good reconstruction).
The decoder also outputs: viscosity_pred=0.498, stiffness_pred=1.998 (very close to truth).
Semi-supervised loss (if labels given) = (0.498-0.5)^2 + (1.998-2.0)^2 = 0.000004 (negligible).
Total loss = 1.0*0.0005 (data) + 0.0001 (recon) + 0.01*0.002 (KL) + 0.1*0.000004 (semi) = 0.000602. The factors are extracted correctly because reconstruction pulled them tight.

The key is that the bottleneck z is much smaller than the weight vector, so the reconstruction loss forces z to capture only the essential, varying structure. Each factor in z learns to represent one axis of physical variation.

What can go wrong

What can go wrong

Bottleneck too narrow. If the compression is too aggressive, the network throws away real physics information and the extracted factors become meaningless. The system must balance compression with fidelity.
Lack of labeled physics. Without ground truth labels on at least some scenarios, the system can extract factors that are statistically independent but do not correspond to real physics. Semi-supervision fixes this.
Operator not actually parametric. If the underlying PDE does not actually change across scenarios (no real physical variation), there is nothing to extract. The method assumes the operator learned a true mapping from physics to weights.
Hypernetwork sensitivity. The extracted factors can be sensitive to hyperparameter choices (the weights beta_d, beta_KL, beta_semi). Tuning requires validation data or held-out labeled examples.
Done right. Collect diverse scenarios covering the physics space, train both the forward operator and the extraction network together, validate with a small labeled set, then use extracted factors confidently as physical interpretations.
What a runnable demo should prove

What a runnable demo should prove

Build a tiny PDE dataset with 3 controllable physical parameters (e.g., viscosity in [0.1, 1.0], stiffness in [1.0, 10.0], damping in [0.01, 0.5]). Train a neural operator on a grid of these scenarios. Then train DisentangO on the same scenarios. On a held-out test case (e.g., viscosity=0.3, stiffness=5.5, damping=0.25), feed the trained operator's weights through the extraction network and print the predicted parameters.

Factor recovery error = mean absolute error of (extracted_factor - true_factor) / true_factor. Should be < 5% for well-disentangled factors.

The demo succeeds when you can print 'true physics: viscosity=0.3, stiffness=5.5, damping=0.25' and 'extracted physics: viscosity=0.301, stiffness=5.48, damping=0.251' — the numbers line up because the operator's weights are now readable.
