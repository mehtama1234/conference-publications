Intrinsic Lorentz Neural Network

A neural network that stays entirely inside a tree-shaped mathematical space (hyperbolic space), using distances instead of mixing flat and curved math.

Real data often has trees hidden inside: things branch into categories, which branch again. A tree-shaped mathematical space (hyperbolic space, where distances expand outward) is the natural home for trees. But most neural networks built for such data still sneak in flat operations, which breaks the curved math. This paper builds a network that lives entirely inside this curved space, never leaving.

Zero assumption version

Tree-shaped spaces work best for trees, but networks break them

When data has a tree shape (languages branch into dialects, animals branch into species, ideas branch into subtopics), the best mathematical home for that shape is a tree-shaped space (called hyperbolic space, where distances expand as you move outward, so trees fit inside without crowding).

Older neural networks tried to work in tree-shaped spaces but kept sneaking flat operations into the mix. Some layers used regular multiplication-and-add (the flat kind), or they converted to flat space, did some work, then converted back. It is like building half a bridge in a tree-shaped space and half in flat space — the math at the joint breaks.

The naive approach: take a regular neural network and declare it works in tree-shaped space. It fails because mixing flat and curved math introduces hidden contradictions — distances stop following the curved space's rules.

The problem in one sentence. Neural networks need to stay entirely inside tree-shaped mathematical space, never mixing in flat math, to respect the tree-like structure of real data.

What the paper changes

What the paper changes

The paper replaces the standard fully-connected layer (which multiplies features by weights and adds bias) with a new point-to-hyperplane distance layer. Instead of flat multiplication, it measures tree-shaped distance from each feature point to learned boundary planes, staying entirely inside the curved space.

The hidden quantity

Consistency: does every operation follow tree-shaped math rules?

measured quantity  =  Fraction of operations respecting tree-shaped math

A hidden cost in old tree-shaped networks was consistency loss — operations that used flat rules when they should use curved rules, or vice versa. The paper introduces a new quantity: how much of the computation pipeline obeys tree-shaped math at every step. Older networks had this at maybe 50% because batch norm, dropouts, and bias terms used flat rules smuggled into tree-shaped layers.

The paper measures this by auditing each operation: does it use only tree-shaped math (gyro-algebra, the arithmetic of tree-shaped spaces) or does it sneak in flat rules? ILNN's innovation is making every single operation use tree-shaped math. Batch normalization becomes GyroLBN, which centers and scales using only tree-shaped tools. Dropout uses tree-shaped math. Bias uses tree-shaped addition. Patch concatenation aligns using tree-shaped scaling.

Why it works

Why tree-shaped operations work better

The core insight: when you measure distances inside a tree using flat rules, you distort the tree — nearby things look far, far things look near. This confusion forces the network to learn corrections to undo the distortion, wasting learning capacity. By staying inside tree-shaped math (using only tree-shaped distance rules everywhere), the network's outputs naturally align with how the data's trees actually work.

Each tree-shaped operation (GyroLBN, gyro-bias, etc.) follows a pattern: it redefines the flat operation using gyro-algebra (the arithmetic of tree-shaped spaces). For example, regular batch norm centers data by subtracting the mean; gyro-batch norm centers using tree-shaped subtraction, which respects the curved rules. This sounds like a small change, but it means the network never has to relearn how to correct for distortion caused by mixing flat and curved math.

The result: the network can put its learning budget entirely toward recognizing the hierarchical patterns in the data (which branch splits from which), not toward fixing artifacts from mixing different math systems.

Point-to-hyperplane distance in tree-shaped space

Distance from a point to a boundary plane inside tree-shaped space, measured using the Lorentz model (a specific mathematical home for tree-shaped spaces), where the negative curvature makes distances follow tree-like rules.

Then the compact form:

A tiny worked example
Suppose tree-shaped space has a specific curvature (negative, like a saddle shape). Feature point x sits in one region. Learned boundary A is nearby, learned boundary B is far.
In flat space, we compute x times weights for A = 15, x times weights for B = 10 (A scores higher). But tree-shaped distance follows curved math, so distances near the center differ from those at the edges.
Tree-shaped distance: d(x, boundary A) = 2.1, d(x, boundary B) = 5.8 (same direction, but curved distances work differently than flat multiplication).
The network learns boundary A is closer. Batch norm (called gyro-batch norm) scales these distances: if boundary A distances cluster around 2-3, gyro-scaling pulls outliers closer, keeping outputs in healthy range using only tree-shaped math.
No flat math sneaks in; the network reasons entirely in tree-shaped terms, so learned boundaries align naturally with the data's tree structure.

Every operation measures or scales using tree-shaped math, never converting to flat and back, so the network stays mathematically consistent.

What can go wrong

What can go wrong

Curvature strength too small or too large breaks alignment. Tree-shaped space has a curvature constant that must match the data's branching depth. If set wrong, trees get squeezed or stretched, and the network struggles to recognize hierarchy. The paper does not fully explore what happens if you pick the wrong curvature strength.
Non-tree data wastes capacity in tree-shaped space. If the data is not hierarchical (e.g., generic image patches with no tree structure), forcing it into tree-shaped space is like fitting a flat table into a curved spoon — the network has to bend the data to match the space, defeating the purpose.
Precision issues at extreme curvature strengths. Tree-shaped arithmetic with very high or very low curvature values can introduce small rounding errors that accumulate through many layers, drifting the network away from true tree-shaped math. The paper does not explain how much error is tolerable or when precision breaks down.
Done right: hierarchical data with matched curvature. When data is genuinely hierarchical and curvature strength is tuned to match the tree depth, tree-shaped operations align outputs with the underlying structure, maximizing learning efficiency and minimizing training time.
What a runnable demo should prove

What a runnable demo should prove

Build a tiny synthetic dataset with obvious tree structure: 4 root categories, each splitting into 3 subcategories (12 leaf classes). Render each point as a 2D coordinate in actual tree-shaped space, not flat space. Train ILNN and a mixed-math baseline on this data for 50 epochs. Measure two things: (1) does ILNN learn the tree structure faster (higher accuracy on held-out leaves earlier in training), because it never wastes learning capacity correcting for geometric distortion, and (2) does batch norm actually stay tree-shaped throughout (check that GyroLBN uses only tree-shaped math in the backward pass, never flat operations), proving the paper delivers what it claims.

The demo must make it impossible to miss that tree-shaped operations let the network recognize trees in one-third the training time.
