GTM: General Time-series Model for Representation Learning

A time-series model that learns to see patterns at different time-scales by paying attention to frequency information and by practicing both predicting ahead and filling in blanks.

Paper explainersAll themesTime Series & Sequential

Time-series data (temperature readings, stock prices, sensor streams) has patterns that happen at different speeds. Some patterns repeat every day, others every year. Most time-series models miss these speed differences. GTM fixes this by attending to frequency information — which rhythms are fast, which are slow — and by training on two tasks at once: predicting future values and reconstructing masked (hidden) past values.

Zero assumption version

Time patterns hide their own speed

Time-series data has patterns at many different scales. A building's temperature changes fast (hour to hour) but also slow (winter to summer). Most models treat time as a flat line: time step 1, 2, 3, 4, 5... They do not know which patterns are hourly hums and which are seasonal shifts.

A beginner's first guess: just use a big neural network on the raw numbers. But the network will ignore that some patterns repeat every 24 time steps and others every 365. It cannot separate the fast signal from the slow signal, so it muddles both together.

The method in one sentence. GTM learns what speed each time pattern runs at by analyzing frequency (which oscillations appear in the data) and by practicing two prediction tasks simultaneously: guessing future values and filling in randomly hidden middle sections.

What it actually does

Analyze frequency content.

Transform raw time values into frequency space (which rhythms are present and how strong).

Attend by frequency.

Use attention that is aware of time-scale: fast features attend to fast, slow to slow.

Hide sections randomly.

Predict ahead too.

Learn both kinds of patterns.

What the paper changes

The single thing that changes: attention weights

Standard attention in time-series models learns what to focus on, but it does not know that some patterns are fast and others slow. GTM changes the attention mechanism so that it explicitly attends to frequency information: how fast is this feature oscillating. The model learns, for each feature, what frequency (speed) it should listen to.

the object it moves  =  attention weights in frequency domain
The hidden quantity

Time-granularity importance: which speed matters for which feature

measured quantity  =  frequency-aware importance

Every feature (a learned number that helps predict the time series) tends to specialize: some features pick up on fast changes (hour to hour) and ignore slow drifts, while others do the opposite. This happens because during training, a feature that focuses on one speed gets reinforced by tasks that need that speed, and it gets confused by tasks needing a different speed. The paper introduces a hidden quantity: for each feature, how important are patterns at each frequency. Call it frequency-aware importance. This matters because if a feature is specialized in fast patterns, it should use fast attention weights, and if it is specialized in slow patterns, it should use slow attention weights. Mixing them wastes the feature's capacity.

GTM estimates this by analyzing what happens in the model's attention layer when it processes different speeds of change. Features that grab attention when processing fast oscillations get high importance at high frequencies; features that activate during slow trends get high importance at low frequencies.

Why it works

Why frequency attention and dual training work

The core problem: a time series is a mix of signals at different speeds, all packed into one number at each time step. A model trained only to predict the next value will learn an average of all those speeds — the fast noise drowns out the slow trend, or the slow trend drowns out the fast noise.

Frequency attention separates the speeds. By explicitly representing each speed (fast frequency, slow frequency) and letting the model learn which internal features care about which speeds, the model builds two separate neural pathways: one for hourly patterns, one for yearly patterns. The model no longer has to jam both into one compressed number.

The dual training (predicting ahead AND filling blanks) forces the model to hold onto both kinds of understanding. If the model cheats and forgets the slow patterns to focus on fast prediction, the reconstruction task (filling blanks) fails — because blanks span both fast and slow scales, and the model must guess correctly at both frequencies.

Math after the picture

The hybrid loss function that trains on both tasks

First in words:

total loss = prediction loss + reconstruction loss. prediction loss = mean square error between guessed next value and true next value. reconstruction loss = mean square error between guessed blanked values and true blanked values.

Then the compact form:

L_total = L_pred + L_recon = mean((y_next - yhat_next)^2) + mean((y_blanked - yhat_blanked)^2)

Every symbol:

y_nextthe true value that comes after the sequence
yhat_nextthe model's guess for the next value
y_blankedthe true values that were randomly hidden during training
yhat_blankedthe model's guess for what those blanked values were
L_predpenalty for getting the prediction wrong
L_reconpenalty for getting the reconstruction wrong
L_totalthe combined penalty that training tries to minimize
A tiny worked example with three time steps
Say we have a time series: 10, 12, 11, 13. We hide step 3 (the 11). Model guesses next value is 12.5 (true is 13). Model guesses hidden step is 10.8 (true is 11).
Prediction error: (13 - 12.5)^2 = 0.25. Reconstruction error: (11 - 10.8)^2 = 0.04. Total loss: 0.25 + 0.04 = 0.29.
The model is punished for both mistakes equally. It cannot ignore the reconstruction task to perfect the prediction; both matter. This forces it to learn both kinds of patterns.

The model sees that some mistakes come from missing the fast wiggles (prediction task catches those) and others from missing the slow drifts (reconstruction task catches those), so it learns both.

What can go wrong

What can go wrong

Blanking too much erases the signal. If you hide too many consecutive time steps (e.g., hiding steps 10-40 all at once), the model cannot guess what goes in that gap because it is too far from the surrounding context. The reconstruction task becomes impossible, and training fails.
Frequency mismatch: data without clear rhythms. If the time series is pure random noise (no actual patterns at any frequency), frequency-aware attention cannot find anything to specialize in. The model will not fail catastrophically but will gain less advantage from the frequency mechanism than on real, patterned data.
Balancing two objectives is tricky. If prediction and reconstruction losses are not roughly equal in magnitude, the model will focus on whichever loss is larger and ignore the other task. Practitioners need to check that both losses are shrinking during training.
Done right. Tune the span length for blanking (e.g., hide 10-30% of steps in chunks of 5-10 steps), ensure your data has real patterns at multiple time scales, and monitor both prediction and reconstruction losses to confirm the model is learning both skills.
What a runnable demo should prove

What a runnable demo should prove

Build a toy time series from scratch: a sine wave with period 50 steps (slow) plus a sine wave with period 5 steps (high-frequency) added together. Train GTM (frequency-aware attention plus dual masking) and a simple baseline (vanilla attention plus prediction-only) on this data. Test on three tasks: predict the next 10 values, fill in 20 randomly blanked values, and classify whether the trend over the last 50 steps was up or down.

success_rate = (prediction_correct + reconstruction_correct + classification_correct) / 3

GTM should beat the baseline on all three tasks, especially reconstruction (since the baseline never trained on that), proving that dual training and frequency attention build a more complete picture of the time series.
