Zero assumption version

Why round clouds fail on curved ground

Imagine sorting people by body shape. A naive approach: measure them on a flat 2D plane (height and shoulder width) and assume each group — tall sprinters, stocky wrestlers — spreads out in a round blob. That works on a plane.

But real body shapes live on a sphere, because you can rotate a person in 3D space. Rotate a cluster, and it looks the same — but measure it on the flat plane after spinning, and the blob changes shape. Worse: a tall-and-narrow cluster (one group is all long limbs) stays long and narrow even if you spin it. Round-blob math misses that.

The problem. Existing methods assume all clusters spread out identically and symmetrically, failing to capture groups that are stretched in specific directions on curved spaces.

What the paper changes

What the method changes

Instead of one universal round-blob formula for how each cluster spreads, this method lets each cluster have a directional shape: an ellipse (or ellipsoid in 3D), stretched differently along different curves through the curved space. The shape lives and breathes on the curved surface itself.

the object it moves  =  cluster spread direction
The hidden quantity

The directional stretch of each cluster

measured quantity  =  anisotropy per cluster

Anisotropy means uneven stretch — some directions compressed, others spread wide. Each cluster has its own anisotropy: the pattern of which directions are squeezed and which are loose.

The paper estimates anisotropy by measuring how far points in each cluster deviate along different directions on the curve, using a method called a geodesic factor model: it breaks the overall scatter into a core spread (the centroid's neighborhood) plus directional stretch patterns.

Why it works

Why stretched shapes fix the problem

On a curved surface, a truly round cluster is rare. Real clusters align with natural patterns. One group of brain shapes might be uniformly tall (big variation along one anatomical direction, small along others). The old method forced roundness, inflating the small-variation directions to compensate, and mislabeled points near the cluster edge.

By letting each cluster be stretched differently, the method matches the actual data shape. A tall-and-thin cluster is modeled as tall-and-thin. A round cluster is modeled as round. When a model matches reality, points in the true cluster score much higher under their correct cluster than under false ones, because the real shape is tight and consistent. The old round-blob model wastes information on dimensions that are not actually spread, so many points near cluster boundaries tie or flip to the wrong cluster. More data helps because each new point sampled from a cluster lands in predictable places along that cluster's true stretch directions. With 10 points, noise can hide the stretch. With 1000 points, the stretch pattern is undeniable and the algorithm finds it reliably.

The scoring formula

First in words:

For each cluster, score a point by how far it sits from the cluster center along each direction, weighted by the stretch in that direction. Add these up and subtract from a constant to get a likelihood.

Then the compact form:

log p(x|k) = const - 0.5 * sum_j (residual_j^2 / stretch_j) - 0.5 * log(det(Sigma_k))

Every symbol:

p(x|k)probability that point x belongs to cluster k
residual_jhow far the point sits from center along direction j, measured on the curve
stretch_jhow much variance is allowed along direction j (the j-th eigenvalue)
Sigma_kthe covariance matrix for cluster k, living on the manifold
det(Sigma_k)a volume term that scales with cluster size
A tiny worked example
Cluster A: center at (north pole), stretch [8, 2, 1].
Point x nearby at distance 1.0 from center.
Residuals along three directions: [0.3, 0.5, 0.2].
Score: -0.5*(0.3²/8 + 0.5²/2 + 0.2²/1) - log volume
= -0.5*(0.036 + 0.125 + 0.04) ≈ -0.1
If stretched as [1, 1, 1] instead (round): -0.5*(0.09 + 0.25 + 0.04) ≈ -0.19.
Correct stretch gives higher score: -0.1 > -0.19, so point stays in A.

The smaller the residuals and the larger the allowed stretch, the higher the score — a good fit. Clusters with natural anisotropy (one direction fat, others thin) fit real data without forcing roundness.

What can go wrong

What can go wrong

Data doesn't actually live on the claimed curve. If your data is really Euclidean (like pixel values in an image) but you measure it on a sphere, the method will overfit and learn spurious stretches.
Not enough data to estimate cluster stretches. With few points per cluster, the anisotropy estimates are noisy. You may overfit individual noise bumps as real cluster structure.
The curve itself is misspecified. If the manifold is wrong (e.g., you think it is a sphere but it is a torus), cluster shapes will be distorted, and boundaries will not line up correctly.
Real shapes captured. When data truly does live on a known curved space and the number of clusters and dimensionality are reasonable, the method recovers the true cluster structure.

Cluster 2 is stretched along the north-south axis (fat north-to-south, thin east-west). Cluster 3 is randomly scattered. Run the old round-blob method and the new geodesic factor method.
