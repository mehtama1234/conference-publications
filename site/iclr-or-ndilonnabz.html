AnyTouch 2: General Optical Tactile Representation Learning For Dynamic Tactile Perception

A robot can feel fine-grained forces and deformations if you teach it on a large dataset pairing camera images of touch with actual force measurements.

Paper explainersAll themesRobotics & Control

A robot manipulating an object needs to sense what it is touching—not just the shape of the thing, but how much force it is applying, how the surface is deforming, and whether it might slip. This paper builds AnyTouch 2, a system that learns these tactile feelings from a large dataset of optical tactile sensors (cameras pointed at rubber pads that deform when touched) paired with force measurements. The system learns to read those deformations and predict forces across different sensors and real-world manipulation tasks.

Zero assumption version

Robots cannot feel subtle touch without a teacher

A robot arm moving a block around a table is blind. It has joint angles and motor currents, but it cannot feel the texture of the block, whether it is slipping, or how much squishing force it is applying to the surface. A human in the same situation would feel all of this instantly through fingertips.

Optical tactile sensors solve this: a soft rubber pad sits on the robot's gripper, and a camera inside the pad watches how the rubber deforms when touched. If the robot presses the pad against sandpaper, the rubber bulges in a particular way; against glass, a different way. But for the robot to understand these images—to turn a picture of deformed rubber into knowledge about forces and textures—it needs millions of training examples showing the link between deformation pictures and actual force measurements.

Old tactile datasets skipped the hard part. They collected images of static objects (rough, smooth, hard, soft), but ignored the temporal dynamics—the fast changes in pressure and deformation as the robot moves. Teaching a robot only on static touch is like teaching a person to drive while watching statues.

The paper's one-sentence fix. Collect a large tactile dataset (ToucHD) that includes temporal sequences of touch images paired with force measurements, then train a unified model (AnyTouch 2) to predict forces and deformations across multiple sensors.

What the paper changes

The thing the paper changes

Most prior tactile models learn only static properties (roughness, hardness). AnyTouch 2 shifts what the model learns to include dynamic quantities: how deformations unfold over time, how forces evolve, and how these relate to manipulation actions.

the object it moves  =  learned representations of temporal deformations and forces
The hidden quantity

The hidden quantity: force dynamics over time

measured quantity  =  Deformation trajectory and force magnitude

At any moment, when the robot's gripper touches an object, three things go unmeasured without a camera: how much the rubber is bulging (deformation), how quickly it is changing (temporal dynamics), and how much force the robot is applying (force magnitude). This paper names and measures these together: the temporal sequence of camera images from the optical sensor encodes all three.

The model estimates force magnitude by watching the deformation pattern in each image and how that pattern changes from frame to frame. A sudden bulge means impact; a sustained bulge means sustained pressure; a shrinking bulge means releasing. The training data pairs thousands of these image sequences with simultaneous force sensor readings, so the model learns to read the camera and predict the force because it has seen concrete examples of which visual changes match which force numbers.

Why it works

Why it works: learning from paired data

The robot's gripper has two streams of information: the camera watching the rubber deform, and a force sensor directly measuring pressure. Before AnyTouch 2, most systems treated these as separate—the camera branch learned shapes and textures independently, while the force sensor was ignored or used only as a label for static properties.

AnyTouch 2 trains the camera branch to predict the force sensor readings directly. When the camera sees the rubber bulge in a particular pattern, the model must output a number matching what the force sensor says. Over millions of examples, this works because the model cannot cheat by memorizing shapes; it must extract the actual causal link—how material properties and movement patterns map to force. The visual signature of a 2 Newton squeeze is physically different from a 5 Newton squeeze, and the model learns to read the difference.

Because the same physics holds across different gripper designs (different rubber, different cameras), a model trained on one sensor can often generalize to another. The representation learned is not "this particular rubber pad" but "how deformation patterns encode force."

The prediction equation

First in words:

force estimate = weighted sum of deformation features plus force history plus action context

Then the compact form:

F_t = w1 * pixel_features_t + w2 * temporal_change_t + w3 * action_embedding + b

Every symbol:

F_tpredicted force at time t (in Newtons)
pixel_features_tlearned summary of camera image at time t
temporal_change_thow fast the deformation is changing
action_embeddingcompact representation of the gripper action
w1, w2, w3learned weights (importance of each input)
blearned offset (baseline force)
A tiny worked example
At frame 1: pixel_features = 0.6 (moderate bulge), temporal_change = 0.2 (slight increase), action_embedding = [push], w1=2.0, w2=1.5, w3=1.0, b=0.1.
Compute: F_1 = 2.0 * 0.6 + 1.5 * 0.2 + 1.0 * 1.0 + 0.1 = 1.2 + 0.3 + 1.0 + 0.1 = 2.6 N (plausible for a light push).
At frame 10: pixel_features = 0.9 (strong bulge), temporal_change = -0.1 (starting to shrink), F_10 = 2.0 * 0.9 + 1.5 * (-0.1) + 1.0 + 0.1 = 1.8 - 0.15 + 1.0 + 0.1 = 2.75 N.
The model learned that seeing a bigger bulge means higher force; seeing the bulge shrink means force is dropping.

The model weights how much each visual detail matters; training forces it to up-weight the details that truly correlate with force.

What can go wrong

What can go wrong

New sensor, new optics. If a different gripper design has a different camera angle or different rubber material, the pixel appearance changes drastically. The model must retrain or adapt, or performance drops.
Fast impacts beyond training. If the robot impacts an object faster than any example in the training data, the deformation pattern might be outside the learned range, because the model has never seen what visual signals correspond to those extreme forces. Extrapolating beyond the training data is risky.
Sensor noise and synchronization drift. If the camera and force sensor get out of sync (timing mismatch), the model learns a corrupted link between images and forces. Careful data collection is mandatory.
Done right. With large hierarchical data, careful sensor synchronization, and evaluation on held-out sensors, the model learns generalizable tactile intuition.
What a runnable demo should prove

What a runnable demo should prove

Collect a small sequence of optical tactile images as a robot presses an object. Run the trained model on those images without access to the force sensor. Compare the model's predicted force with the actual force sensor. Plot both curves over time. If the model tracks the ground truth closely (within 0.5 N for a 5 N range), it has learned the mapping.

force prediction error = mean of (predicted_force_t - actual_force_t)^2 over all frames, in Newtons squared

If the curves track each other closely, the model has learned the visual language of force, because it is making frame-by-frame predictions with no access to the force sensor—only the camera.
