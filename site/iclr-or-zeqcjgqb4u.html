Trading Visual Uncertainties in Multi-Agent Bandit Systems

Treat each agent's uncertainty as a tradable asset in a decentralized market, so the system automatically routes tasks to the cheapest confident agent instead of using heuristics.

Paper explainersAll themesLLMs & Foundation Models

When you use multiple vision-language models together, you need them to divide the work. Existing systems use simple rules (like asking for consensus) which ignore how much each model costs and what they are uncertain about. Agora instead measures each model's specific doubts (three kinds: seeing, understanding, and reasoning) and uses these measurements to decide which model should answer—the cheapest one that is confident enough for the task. This works because a market-like decision rule that optimizes for cost is more efficient than a heuristic rule that does not account for price.

Zero assumption version

Why multi-agent VLM coordination becomes expensive

To answer a hard visual question, you might run five different vision-language models—each sees the image slightly differently, and each costs money to run. The naive approach is to run all five on every question and use voting or averaging to pick the answer. But this wastes money on cases where three models already agree with high confidence—you do not need the other two.

Existing smart systems like Mixture-of-Agents try to route tasks only to the models you need, but they decide based on simple guesses like 'do most models agree?' They ignore two real facts: (1) they do not measure how truly confident each model is (they just look at the surface answer), and (2) they do not track what each model actually costs to run. So they often route a task to an expensive model when a cheap one was already certain enough.

In one sentence. Agora treats each agent's uncertainty about its answer as a tradable asset that the system can exchange in a market, so the cheapest confident agent always ends up with the task.

The algorithm as a flow

What it actually does

Step 1: Measure uncertainty

Each model is asked the same question; the system measures three kinds of doubt: perceptual (does the model see the image clearly), semantic (does it understand what to look for), inferential (does it make the logical leap).

Step 2: Set a market price

The broker (a special router based on Thompson Sampling) looks at all five models' confidences and costs, and sets a price: how much it costs to buy enough certainty from the cheapest source.

Step 3: Agents bid to trade

Each model can offer to help the others by sharing its strengths. A model strong at perception can lend that to a model weak at perception, because the combined pair now covers both perceptual and inferential tasks.

Step 4: Pick the cheapest confident pair

The system ranks all possible single-model or two-model assignments by their cost, picks the one with the lowest cost that still reaches the confidence target, and assigns the task to that pair.

Step 5: Route the task

The final assignment goes to the model (or pair) that can answer with the needed confidence for the lowest cost.

What the paper changes

What the paper changes

Existing systems route tasks based on surface signals (agreement, semantic similarity) and do not account for cost. Agora changes the routing decision: instead of a heuristic rule, the decision is now made by a cost-minimization market that values each model's actual certainty.

The hidden quantity

The hidden quantity: epistemic uncertainty

measured quantity  =  epistemic uncertainty

Epistemic uncertainty means 'how much the model doubts its own answer'—not just confidence, but broken into three named parts: perceptual (is the image clear enough to see what we need), semantic (does the model understand the task), and inferential (can the model make the logical leap). The paper measures this by having each model produce step-by-step reasoning, then rating each step.

The paper measures uncertainty by asking each model to explain its reasoning in detail, then scoring how well each stage (seeing, understanding, reasoning) is supported by evidence. A model that says 'I see the red ball' but the image shows blue is high in perceptual uncertainty. One that sees clearly but cannot connect the dots is high in inferential uncertainty. The system uses these three scores separately to decide how much of the answer to trust from each model.

Why it works

Why it works: the market-based routing

The mechanism has two parts. First: turn uncertainty into a tradable asset. When a model is highly confident on one dimension (perceptual, it sees the image clearly) but uncertain on another (inferential, it cannot make the logical leap), that model can sell its perceptual confidence to another model that struggles with perception. This trade matters because the second model might be very good at logic and just needs help seeing the image. The system records this trade and decides who ends up with the task.

Second: use economic rationality to pick the winner. The broker extends Thompson Sampling (a classic algorithm for learning which option is best by trying different choices and learning from the results) to ask: which assignment of this task to a model or pair of models will cost the least and still reach the accuracy we need? It greedily picks the trade that reduces cost most rapidly. Unlike heuristic routers that ignore cost, Agora directly minimizes the cost-per-unit-accuracy. If two trades both achieve 90 percent accuracy, Agora picks the cheaper one because paying less money for the same answer means you have more budget to answer more questions correctly overall.

The reason this beats naive voting is structural. Naive voting runs all models because it does not measure confidence granularly—it just looks at whether they agree. Agora measures confidence in detail (three separate dimensions) and uses a cost-aware broker, so it confidently drops expensive models as soon as a cheap one is certain enough. The market discipline forces the system to be ruthlessly efficient because it cannot hide cost behind a heuristic rule anymore.

Math after the picture

The cost-minimization equation

First in words:

The total cost is the sum of what we pay each model we use, and we want to find the set of models and the uncertainty trades that minimize this cost while keeping the final confidence above a threshold.

Then the compact form:

min_trade sum_i c_i * x_i + lambda * (target_conf - achieved_conf(trade))^2

Every symbol:

c_ithe cost per call to model i
x_i1 if model i is used, 0 if not
target_confthe minimum confidence we need for the answer (set by the system)
achieved_confthe confidence we actually achieve after the trade
lambdahow much we penalize falling short of the target (a knob the system adjusts)
A tiny worked example
Setup: five models, costs are c1=1.0, c2=0.5, c3=2.0, c4=0.3, c5=1.5 dollars.
Baseline (run all five): sum=1.0+0.5+2.0+0.3+1.5=5.3 dollars, achieved_conf=0.95.
Agora trade option 1: use models 4+2 (cheapest two, with different strengths). Cost=0.3+0.5=0.8, achieved_conf=0.88.
Since 0.88 < 0.95, lambda penalty = 1.0*(0.95-0.88)^2 = 0.0049, total=0.8+0.0049=0.8049.
Agora wins: 0.8049 (with one traded pair) vs 5.3 (naive), saving 84% of cost.

The equation says: pay for each model you use, but if you do not reach the target confidence, add a penalty. Agora finds the set of models and the trade that minimizes this sum.

What can go wrong

What can go wrong

Uncertainty measurement is wrong. If step-by-step reasoning does not actually tell you how confident the model is (e.g., a model is confidently wrong), Agora will route the task to a false winner. The system must validate uncertainty estimates separately before deploying.
Cost estimates are stale. If the cost to run model i changes (e.g., the API price drops), Agora will not notice immediately and will keep overpaying. The broker needs to periodically re-sample costs in the real world, not just rely on fixed estimates.
The target confidence is set wrong. If you set target_conf too high (e.g., 0.99 when 0.85 is enough), the system will use more models than needed and waste money. If you set it too low, it will drop models too early and give wrong answers. The system needs a way to tune this per task or use a learning algorithm.
Done right. The paper shows Agora works best when the three uncertainty dimensions (perceptual, semantic, inferential) are estimated independently, when costs are real and measured, and when the target confidence is validated on a held-out test set before deployment.
What a runnable demo should prove

What a runnable demo should prove

Build a toy system with three vision-language models (e.g., a small model, a medium model, a large model) with different costs (small=0.1 dollar per call, medium=0.5, large=1.5) and different strengths. Create a test set of 50 images with visual questions that each model answers differently (some with high confidence, some with low). For each question, run the baseline (vote across all three) and Agora (trade and route). Measure the cost per correct answer for each.

cost_efficiency = total_cost_spent / number_of_correct_answers. Lower is better. Agora should achieve the same accuracy as baseline at 60-75% of the cost.

The demo must make impossible to miss: Agora does not just pick one model at random; it systematically picks the cheapest model that is confident enough, and it proves this by showing the cost drop while accuracy stays level or improves.
