DiLA: Disentangled Latent Action World Models

Split video into what moves (structure) and what looks the same (content), so the model learns clean abstract actions without sacrificing photo-realistic generation.

Paper explainersAll themesReinforcement Learning

Video is two things happening at once: spatial arrangements shift (a hand moves forward, the horizon rises) and appearance stays mostly the same (the wall texture, the skin tone). DiLA separates these into two channels. The structure channel learns abstract actions—the skeleton of motion. The content channel stores visual details for crisp video generation. By splitting the labor, DiLA learns interpretable actions from raw video without needing human-labeled moves or two separate models.

The video-to-action puzzle

Imagine you watch a robot pick up a cup in one video, then walk across a room in another. The robot's movements are different, but both videos show something changing in space (where things are) and something staying the same (colors, textures, shadows). If you want a machine to learn abstract actions—move forward, grasp, rotate—you need to ignore the visual noise and focus on what moves and where.

Existing approaches face a hard trade-off: either learn clean abstract actions (but the generated videos look blurry and fake), or generate crisp, realistic videos (but the learned actions are tangled up with appearance details and do not transfer to new scenes). Most workarounds glue two separate models together or limit what they can predict.

The core problem. Video changes in two independent ways at once (spatial layout and visual appearance), but older models confuse the two, forcing a painful choice between abstract actions and realistic generation.

The algorithm as a flow

What it actually does

Extract video features

Freeze a vision model (DINOv2) to extract dense feature lists (vectors: just lists of numbers) from every frame.

Split into two pathways

Structure encoder learns a compressed blueprint of spatial layout. Content encoder/memory learns visual appearance.

Learn abstract actions

Inverse dynamics module predicts abstract actions (hidden numbers that summarize how the spatial layout changes) from consecutive structure states. A bottleneck constraint forces actions to be clean.

Predict next layout

Forward dynamics module (Mamba recurrent) rolls the structure state forward by one frame given the abstract action (the hidden numbers from the previous step).

Fuse and generate

Fusion decoder (using cross-attention: the model focuses on which parts of the content are relevant to each part of the structure) merges predicted structure and stored content, rendering a realistic video frame.

What the paper changes

What the paper changes

DiLA rewires how video features flow through the model. Instead of mixing spatial and appearance information throughout, it routes them into separate pathways. The structure pathway stays minimal—only what is needed to predict the next spatial layout. The content pathway (a memory buffer built with a Mamba recurrent module) stores texture, lighting, and fine details, accessed only when generating a frame.

The hidden quantity

The content-invariant abstract action

measured quantity  =  Disentanglement success score

DiLA measures whether actions it learns are truly abstract, meaning they work the same way no matter what the scene looks like. A content-invariant abstract action is one where the same learned action (a hidden number that summarizes motion) produces the same spatial change in a different video with different lighting, colors, or textures. For example, the action move-forward should shift the horizon the same amount whether the sky is blue or overcast.

The paper estimates this by applying learned actions from one video to a different video, then checking whether the spatial layout changes correctly (ignoring appearance). A high score means actions transferred well.

Why it works

Why separating channels works

Here is the causal chain. A video frame contains two kinds of information: spatial relationships (where is the cup relative to the hand?) and visual appearance (what color is the cup?). These are independent—the cup stays the same color whether it moves left or right. If you force a single neural pathway to encode both, the model learns to bind them together. Actions become tangled with appearance.

DiLA uses a bottleneck constraint: the structure encoder is deliberately made small, so it cannot pass appearance information forward. This forces it to communicate only spatial layout to the latent action module. The content encoder captures what the bottleneck discards—the texture, lighting, color. When you fuse the two later, you get spatial information (which way did things move?) and visual information (what do they look like?) kept separate, so the generation is crisp but the actions remain pure.

In the fusion stage, a cross-attention Transformer re-combines structure (predicted next spatial layout) and content (the stored visual memory). Because the structure has already been decoupled from appearance, the model can attend to the right appearance details for rendering without corrupting the action signal. This is why the actions can transfer: they encode only how things move in space, which is the same whether the background is painted blue or green.

Math after the picture

The prediction-plus-disentanglement equation

First in words:

total loss = video generation loss + structure prediction loss + action consistency loss + disentanglement regularizer

Then the compact form:

L_total = L_recon + alpha * L_struct + beta * L_action_consist + gamma * (L_latent_norm + L_latent_var)

Every symbol:

L_reconhow well the fused output matches the actual video frame
L_structhow close the predicted spatial layout is to the next frame's layout
L_action_consistpenalty if the same action applied to different content gives different actions back (enforces purity)
L_latent_normregularizer keeping action magnitudes reasonable
L_latent_varregularizer keeping action variance stable
alpha, beta, gammaweights balancing each loss term
A tiny worked example
Suppose the model predicts the next frame, and it matches the actual frame in 95% of pixels: L_recon = 0.05.
The structure prediction is close but shifts objects 2 pixels too much in total: L_struct = 0.08.
The action consistency loss checks: I applied action A to frame 1 (blue background) and got latent vector z_1. I apply the same action A to frame 2 (red background). I get z_2. If z_1 ≈ z_2, that is good (actions are appearance-invariant). Penalty is L_action_consist = 0.02.
The norm and variance regularizers are small: L_latent_norm = 0.01, L_latent_var = 0.01.
With alpha=1, beta=2, gamma=0.5: L_total = 0.05 + 1*0.08 + 2*0.02 + 0.5*(0.01+0.01) = 0.05 + 0.08 + 0.04 + 0.01 = 0.18.

The bottleneck and dual pathways make this work: structure cannot carry appearance because it is too small to transmit that information forward, so the model is forced to learn clean actions despite being trained end-to-end on video. The information has to go somewhere—appearance is shunted to content—leaving actions pure.

What can go wrong

What can go wrong

Bottleneck too tight. If the structure encoder is too small, it discards useful spatial information, and predictions become vague. The model needs just enough capacity to encode layout without appearance.
Appearance leaks into actions. If the action consistency loss is weighted too low or the bottleneck is not enforced, the model can still bind actions to appearance (e.g., action means move-in-blue-scenes). Actions fail to transfer.
Content memory runs out. The Mamba memory module must hold enough historical appearance information to reconstruct textures. In long videos, memory can become stale or corrupt if the capacity is insufficient.
Done right. When the bottleneck is calibrated and all four loss terms are weighted fairly, structure encodes only how things move, actions remain pure, and videos are crisp because content is tracked independently.
What a runnable demo should prove

What a runnable demo should prove

Train DiLA on a dataset of robot videos (e.g., a mobile manipulator moving and grasping). Extract latent actions for a few sequences. Then take a learned action from Video A (blue wall background) and apply it to the structure state from Video B (red wall background). Generate the video output. If the robot moves the same way despite the background color change, but the generated video looks realistic, the demo works.
