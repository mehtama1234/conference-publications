GARLIC: Graph Attention for Irregular ICU Time Series

GARLIC predicts patient outcomes from messy hospital sensor readings by learning which sensors matter most and how they interact, all visible inside the model.

Why hospital sensor data is hard

Hospital ICUs (Intensive Care Units) record dozens of sensors every minute—heart rate, oxygen levels, blood pressure, lab test results. But the readings don't arrive on a regular schedule. A blood test might happen every 8 hours; heart rate is recorded every second. Many values go missing. A doctor faces a puzzle: given all this chaotic, incomplete data, will this patient get worse in the next week? And when the model says yes, why did it say that?

Doctors need both accuracy and explanation. A black-box predictor that just outputs a number is not useful in the ICU—a clinician has to trust the reasoning. Old methods either are accurate but opaque, or interpretable but miss patterns. No method has done both well while handling the messy timing and missing values.

The challenge in one sentence: Learn to predict patient outcomes from irregular, incomplete sensor time series while showing doctors exactly which measurements and which sensors mattered for each prediction.

The algorithm as a flow

What it actually does

Ingest irregular data

Read all sensor values, tag what is observed vs missing.

Exponential decay fill

Estimate missing values using recent history; older history counts less.

Build time-lagged graphs

For recent history, learn which sensors correlate, store as edges.

Message passing

Pass sensor values along graph edges; each sensor absorbs its neighbors' info.

Sensor importance scoring

At each time step, learn a weight for each sensor; sum weighted signals.

Time importance scoring

Learn which time steps matter; average the signal-weighted values over time.

Predict and explain

Output risk score; return learned importance weights and graph as explanations.

What the paper changes

What the paper changes

The paper learns three things jointly: (1) how to fill in missing sensor values, (2) the graph of which sensors depend on each other, and (3) the weights that say which sensor is important at which time.

the object it moves  =  learned importance weights and sensor graph
The hidden quantity

Signal importance: which sensor matters now

measured quantity  =  Signal importance weight

At any given moment, not all sensors are equally important for predicting the outcome. The paper learns an importance weight for each sensor at each time step. A weight of 0 means ignore this sensor; a weight of 1 means trust it fully. These weights are the model's way of saying which signals were the key drivers of the prediction.

The paper estimates these weights by learning attention: a small neural network that takes the sensor reading and outputs a number between 0 and 1. Unlike typical machine learning models where importance is hidden, these weights are baked into the model's structure and come out directly as explanations.

Why it works

Why it works: three pieces talking

Standard neural networks are black boxes. GARLIC trades some flexibility for transparency by building explanation directly into the architecture.

The trick is structure. Instead of a dense black-box network, GARLIC has three layers of explicit design: (1) when a value is missing, predict it from recent history (exponential decay), so the input is always complete. (2) Build a sensor-to-sensor connection graph by looking at temporal correlations; update the graph end-to-end as the model trains. (3) At each time step, apply attention: score each sensor (the learned weights), then score each time step. The output of each attention layer is a set of numbers (the weights themselves), which are your explanation.

The magic is that attention weights serve double duty: they compute the prediction (weighted sum of inputs), and they are also the explanation (which inputs were used). No external explanation method needed. As the model trains to predict outcomes, it automatically learns which sensors to trust.

Math after the picture

The core equation: attention-weighted prediction

First in words:

The prediction is a sum of signal contributions, where each signal is weighted by its learned importance, and the importance comes from applying a learned attention function to the sensor reading. The final output sums over time steps, weighting recent and urgent time steps more.

Then the compact form:

output = sum_t { alpha_time(t) * sum_k { alpha_signal(k, t) * embedding(k, t) } }

Every symbol:

alpha_signal(k, t)attention weight for sensor k at time step t (ranges from 0 to 1)
alpha_time(t)attention weight for time step t (ranges from 0 to 1)
embedding(k, t)the imputed or observed value of sensor k at time step t, after passing through the graph
outputthe predicted risk score (0 to 1, where 1 means high risk of bad outcome)
A tiny worked example
Suppose we have 3 sensors (heart rate, oxygen, blood pressure) at 2 time steps.
Time step 1: heart_rate=92, oxygen=98, pressure=120. Learned weights: 0.8, 0.1, 0.3. Weighted sum = 0.8*92 + 0.1*98 + 0.3*120 = 73.6 + 9.8 + 36 = 119.4.
Time step 2: heart_rate=105, oxygen=95, pressure=115. Learned weights: 0.9, 0.05, 0.2. Weighted sum = 0.9*105 + 0.05*95 + 0.2*115 = 94.5 + 4.75 + 23 = 122.25.
Temporal weights: time 1 gets 0.3, time 2 gets 0.7 (recent moments weighted more). Final output = 0.3*119.4 + 0.7*122.25 = 35.82 + 85.58 = 121.4. Normalized to a 0-1 risk: approximately 0.78 risk.

The model learns all these weights end-to-end from patient data, so the attention numbers capture real clinical patterns in which sensors predict death or infection.

What can go wrong

What can go wrong

The graph can be wrong. If the training data has a spurious correlation (two sensors that happen to correlate by coincidence), the model will learn a fake edge in the sensor graph. A spurious edge can pull the model toward the wrong sensor at test time.
Attention weights can overfit. On a small dataset, the model may learn to weight one sensor extremely high (weight 0.99, others near 0) to fit the training patients, then fail on new patients where that sensor is less predictive.
Exponential decay assumes gradual change. If a patient's condition changes suddenly (a sensor suddenly drops), the exponential decay will still guess a smooth value. For a time step with missing blood pressure right after a sudden bleed, the imputed value may be dangerously optimistic.
Done right. Use L1 regularization to keep the attention weights from getting too extreme (force some signals to have small weight). Use feature-removal trials to verify that high-weight sensors truly predict outcomes. Validate on held-out patients from different hospitals.
What a runnable demo should prove

What a runnable demo should prove

Take a standard ICU dataset (MIMIC-III or PhysioNet). Train GARLIC and a naive baseline on 80 percent of the patients. On the remaining 20 percent, compute: (1) prediction accuracy (how many mortality predictions were correct), (2) remove the top 50 percent of high-importance sensors and run the model on new patient data, check that accuracy drops; remove a random 50 percent, check that it barely drops. This proves the model really learned which sensors matter. (3) For a few individual patients where the model predicted high risk, show the patient's sensor time series with importance weights painted on—confirm that high-weight sensors match the clinical events (e.g., high weight on heart rate during tachycardia, high weight on respiratory rate during respiratory failure).

Feature importance fidelity = accuracy_full - accuracy_top50_removed (large drop) minus accuracy_random50_removed (small drop).

The demo must show that removing high-attention sensors hurts predictions, removing random sensors barely hurts, and attention weights align with real clinical deterioration events.
