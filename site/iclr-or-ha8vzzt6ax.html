Break the Trade-off Between Watermark Strength and Speculative Sampling Efficiency

Watermarked language models can prove their origin and run fast at the same time, by making draft tokens deterministic functions of random seeds.

Paper explainersAll themesLLMs & Foundation Models

Language models need two things: a way to prove their output came from the real model (not a fake copy), and fast inference (answering questions quickly to save money). A watermark marks the output as authentic, but it crashes the fast inference trick. This paper shows the crash is not necessary—you can have both by making draft words (tokens are one word at a time from the model) depend on random numbers in exactly the right way.

Why watermarks and speed don't mix

A watermark is a hidden mark in the model's outputs that proves they came from the authentic model, not a copy or a jailbroken version. Watermarks are embedded directly into how the model picks tokens (one word at a time)—they tilt the model's choices toward certain tokens and away from others. This is like asking a musician to always slightly favor certain notes: you can detect it, but it changes the sound.

Speculative sampling is a trick that speeds up inference, because the draft model is much simpler and faster to run, so if it guesses right you skip the expensive real model entirely. Instead of waiting for the real model to pick a token (which is slow), you ask a tiny fast draft model to guess what the real model will pick. Most of the time it guesses right, so you skip the slow work and just use the draft's answer. But a watermark breaks this trick: the watermark makes the real model's choices narrower and more predictable, so the fast draft model guesses wrong more often. The draft's wrong guesses waste time correcting them, destroying the speedup. A naive engineer might say: use a weak watermark so the draft still guesses right. But then the watermark is too faint to detect.

The result is a trap: strong watermarks kill speed. Fast inference kills detectability. You pick one.

The paper's move in one sentence. Make the watermark's token choices deterministic functions of secret random numbers, so the draft model can accept or reject based on those same numbers—the watermark is hidden in the randomness, not in the probabilities.

What the paper changes

What the paper changes

The paper changes how the watermark lives inside the model. Instead of tilting the probabilities (making certain tokens more or less likely), the watermark is now a deterministic rule: given a secret seed, output a specific token every time. This is not a probability anymore; it is a fixed function.

the object it moves  =  token choice: from probability to deterministic function
The hidden quantity

The hidden quantity: Watermark strength

measured quantity  =  Watermark strength (detectability power)

Watermark strength is a number that measures how easy it is for a detector to prove the text is authentic. If the watermark is weak, the detector needs to read many tokens to be sure. If the watermark is strong, the detector is confident after reading just a few tokens. The paper defines strength as the KL divergence (how far apart two probability lists are) between the watermarked token distribution and the original model's token distribution—bigger distance means stronger watermark, because when two probability lists are far apart a detector can tell them apart with fewer samples, like spotting a color difference that stands out immediately.

The paper measures strength by asking: if I generate one token from the watermarked distribution and one from the original, how different are they on average? When tokens are deterministic functions of pseudorandom seeds, this distance is maximized: the watermark is as strong as it can possibly be.

Why it works

Why it works: The three-part chain

The paper proves three things that work together. First: watermark strength is maximized when each token is a deterministic function of a random seed. If you let probabilities vary, you weaken the watermark. Second: speculative sampling works by having the draft model guess the real model's distribution. If the draft and real models see the same random seed and use it the same way, they will always agree. No guessing, no rejection, no wasted work. Third: you can embed a detector that recovers the seeds from the watermarked text and confirms authenticity without ever knowing the actual token probabilities—the seed sequence itself is the proof.

Put together, these mean you can embed the watermark entirely into the randomness. The real model and draft model share a secret; they use it to pick tokens together. The detector reads the text and reconstructs the secret. No trade-off, because the watermark is not written in probabilities at all.

The equation: Watermark strength as KL divergence

First in words:

Watermark strength D equals the expected value of KL divergence between the watermarked distribution and the original distribution, computed over all random seeds.

Then the compact form:

D = E_zeta [ KL(P_zeta || P) ]

Every symbol:

Dwatermark strength (detectability power)
E_zeta [ ... ]average over all possible random seeds
P_zetathe watermarked token distribution for seed zeta
Pthe original model's token distribution
KL(A || B)how different distribution A is from distribution B
A tiny worked example
Suppose the original model picks between three tokens: A (40%), B (35%), C (25%).
A weak watermark makes it: A (45%), B (30%), C (25%). The KL divergence is small, say 0.08.
A strong watermark with pseudorandom seeds makes it: seed 1 -> always A, seed 2 -> always B, seed 3 -> always C. The KL divergence jumps to 1.1.
Same average probabilities, but watermark strength increased 14x by using randomness instead of probability shifts.

The stronger the watermark is hidden in randomness instead of probability, the easier the detector can spot it, because the seeds are farther from random noise; and it interferes less with speculative sampling, because the draft model can see the same seed and make the same choice.

What can go wrong

What can go wrong

The secret seed is leaked. If an attacker sees the seed or reconstructs it from the watermarked text, they can forge authentic-looking outputs. The detector must ensure the seed-recovery algorithm is hard to invert.
The draft model is not synchronized with the real model on seed interpretation. If the draft and real models use the same seed differently (for example, if one sorts the vocabulary alphabetically and the other does not), they will pick different tokens. Speculative sampling fails and efficiency collapses.
The detector overfits to one watermarking scheme. Different watermarking algorithms may hide the seeds differently. A detector trained on one scheme may not detect another. The paper shows this requires separate detection training per watermark type.
Done right: seeds are truly independent and unpredictable. If the seed generator is cryptographically strong (uniform random, no patterns), then neither an attacker nor a detector can predict future tokens from past ones, and both efficiency and security are maximized.
What a runnable demo should prove

What a runnable demo should prove

Build a simple language model (a small neural network, or even a lookup table of token probabilities). Implement two watermarking schemes: one that shifts probabilities (old way), one that uses pseudorandom seeds to pick deterministic tokens (new way). Attach a speculative sampling decoder that draws draft words from a simpler model. Measure both the acceptance rate (how often draft and real agree) and the watermark strength (how easy it is for a detector to classify 100 watermarked words as authentic using a simple likelihood-ratio test). Run both schemes side by side and plot the trade-off curve.

Efficiency = acceptance_rate. Strength = KL_divergence between watermarked and original distributions. Trade-off broken if both are simultaneously high (>85%).

The demo must show that pseudorandom watermarks achieve high acceptance rate AND high KL divergence, while probability-shifted watermarks suffer a clear trade-off.
