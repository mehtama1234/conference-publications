Continual Learning Under Data Poisoning: A Game-Theoretic Defense

When a model learns new tasks sequentially and an attacker silently corrupts some of them, this paper proves which defenses can work and which cannot, using game theory to find the boundary.

Paper explainersAll themesLearning Theory

Continual learning (the practice of training a model on a sequence of tasks one after another) is spreading rapidly in big language models and image recognition, but it has a critical weakness: an attacker can slip corrupted data into a task and make the model forget everything or produce garbage. This paper builds a mathematical game where the attacker and defender take turns choosing strategies, and it discovers which attacks are unstoppable and which defenses actually work.

Zero assumption version

Sequential learning is fragile when someone poisons the data

A continual-learning system trains on task 1, then task 2, then task 3, and so on. The naive approach learns each task independently, which is fast. But a single poisoned task — one where the attacker has flipped labels or injected noise — can flip the entire model's behavior and make it forget task 1 completely.

To fight this, researchers add a regularization term (a penalty that resists changing the weights that mattered for old tasks). A beginner might think: if I penalize moving those weights, the attacker cannot corrupt them no matter what data it injects. But this assumes the attacker has limited power. What if the attacker poisons many tasks? The paper asks: at what point does the attacker win no matter what penalty you add?

The core finding. If an attacker can poison a linear fraction of tasks (say, one task out of every five), no penalty-based defense can prevent catastrophic forgetting. But if attacks are rare or bounded in strength, specific defenses can provably win.

What the paper changes

The paper changes: the defense strategy

Instead of using a fixed penalty that applies to every weight equally, the paper proposes two new defenses: a verification step that detects poisoned tasks before they damage the model, and a adaptive penalty that is tuned for bounded noise rather than worst-case unbounded attacks.

The hidden quantity

The hidden quantity: cumulative bias from poisoned tasks

measured quantity  =  cumulative poisoning bias

Every poisoned task injects a false signal into the model. Over time, these false signals pile up — the model's predictions drift further and further from the truth. This paper calls this pile-up the cumulative bias. It is the difference between what the model should have learned and what it actually learned after seeing all the poisoned tasks.

The paper measures cumulative bias by tracking the model's error on the old tasks as each new poisoned task arrives. If a poisoned task injects a bias of magnitude 0.1, and the next poisoned task injects another 0.1 in the same direction, the cumulative bias grows to 0.2, then 0.3. The defense's job is to stop this pile-up.

Why it works

Why the defense works when attacks are rare or weak

A poisoned task injects a false gradient — it points the model in the wrong direction. If only one task out of ten is poisoned, the detection mechanism compares the task's loss curve to the baseline. A poisoned task's error will look anomalous (it will suddenly spike or oscillate strangely), and a simple statistical test flags it. Once flagged, the model skips that task entirely, so the false gradient never touches the weights.

If the poison is weak (bounded, like adding Gaussian noise with a known maximum strength), a stronger penalty works instead, because a strong penalty makes the weights very sticky — they resist moving. A weak poison signal cannot overcome a strong resistance, so the weights stay anchored to their old, correct values. Think of it like a weight on a scale that is glued down — you can push it with a small force, but it does not budge. The paper derives the exact penalty strength needed to guarantee convergence even under bounded noise.

Math after the picture

The strong-penalty defense equation

First in words:

penalty term equals the (importance of each weight) times (how far that weight moved) squared, summed over all weights and scaled by a tuned strength factor.

Then the compact form:

L_total = L_new + lambda * sum_i F_i * (theta_i - theta_i_old)^2

Every symbol:

L_totaltotal loss the model tries to minimize
L_newloss on the new poisoned task
lambdahow strong the penalty is (tuned for poison strength)
F_ihow important weight i is for old tasks (derived from game theory)
theta_ithe current value of weight i
theta_i_oldthe saved value of weight i after the last clean task
A tiny worked example with two weights
Weight w1: importance F=12 (very important for old tasks), moved from 0.5 to 0.6, change is 0.1.
Weight w2: importance F=1 (barely used), moved from 0.3 to 0.8, change is 0.5.
Penalty for w1: 12 * 0.1^2 = 12 * 0.01 = 0.12.
Penalty for w2: 1 * 0.5^2 = 1 * 0.25 = 0.25.
Total penalty: 0.12 + 0.25 = 0.37. Same movement, but w1 is penalized way harder (0.12 vs 0.25), so the model leaves w1 alone and only moves w2.

The penalty is strongest on weights that matter most to old tasks, so poison cannot trick the model into changing those weights.

What can go wrong

What can go wrong

Attacker poisons a majority of tasks. No penalty or detector works. The paper proves this mathematically: if an attacker can control half or more of the task stream, the game is unwinnable. The model will diverge no matter what the defender chooses.
Poison is subtle and pervasive (small changes to many tasks). The detector might miss small anomalies, and the optimal penalty is tuned for a specific noise level. If poison is much stronger than expected, the defense fails, because the penalty strength was set assuming a smaller attack — a bigger attack nudges the weights farther than the penalty can resist.
Attacker adapts: poisons tasks to look clean. If the attacker knows the detection mechanism and can craft poison that matches the clean-task distribution, the detector fails. The paper assumes the attacker cannot do this, which is a limitation.
Done right: sparse poison + known noise bound. If poison is rare (a few tasks per hundred) or bounded (attacker adds noise up to a known magnitude), the defense provably converges.
What a runnable demo should prove

What a runnable demo should prove

Build a continual-learning loop: train on 20 synthetic tasks (each a regression or classification task), then introduce poison into 30% of tasks (by flipping labels or adding noise). Run three defenses: (1) no defense, (2) fixed penalty, (3) the paper's tuned penalty with a detector. Measure and plot old-task accuracy, new-task accuracy, and cumulative bias after each poisoned task. The demo proves that the detector catches poisoned tasks and the tuned penalty keeps old-task performance high even when new tasks are poisoned.

forgetting = old_task_acc_before_poison - old_task_acc_after_poison

When poison is rare or predictable, you can defend using task verification and a mathematically optimized penalty. When poison is arbitrary and common, defense is mathematically impossible.
