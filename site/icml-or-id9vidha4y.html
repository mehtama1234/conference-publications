Obliviate: Efficient Unlearning in Recommender Systems

To remove a user's influence from a recommender without full retraining, push a small low-rank adapter in the direction that most changes the forgotten interactions, then calibrate it so ranking quality stays intact elsewhere.

Paper explainersAll themesOther

Recommendation systems are trained on user clicks, purchases, ratings, and watch history. Privacy rules can later require a system to forget some of that data. Full retraining from scratch is expensive, but cheap deletion tricks often leave traces of the removed user in the model's trainable weights, meaning the numbers the model uses to make recommendations. Obliviate takes a middle path. It does not rewrite the whole model. Instead it attaches a Low-Rank Unlearning Adapter, meaning a compact trainable module that changes the model through a small factored update, and steers that adapter with a Hessian proxy, meaning an approximation to how sharply the loss curves around current trainable weights. Then it runs a second stage called Locality-Aware Calibration to restore recommendation quality near the affected region while keeping the forgotten interactions suppressed. The result is targeted forgetting with much less computation than full retraining.

Zero assumption version

Unlearning in recommenders is harder than deleting records

A recommender model does not store one user's interactions in a neat box. Training spreads that influence through many shared trainable weights. If one user watched a niche movie and many similar users later inherit that signal, removing the raw row from the database does not remove its downstream effect from the trained model.

Full retraining can remove that effect, but it is costly because large recommenders are trained over huge interaction graphs and item catalogs. Lighter methods often overcorrect or undercorrect. They may erase too little, leaving measurable influence from the deleted data, or erase too much, damaging recommendation quality for nearby users and items.

The method in one sentence. Confine the unlearning update to a compact low-rank adapter, shape that update with local curvature information, then recalibrate the adapter so forgetting remains strong while ranking quality recovers.

What the paper changes

What the paper changes

The paper changes where unlearning happens and how it is controlled. Instead of editing the full model uniformly, it routes the change through a compact adapter and shapes that change with curvature information so the forget update is concentrated where it matters most.

the object it moves  =  unlearning update path inside a recommender
The hidden quantity

Influence concentration

measured quantity  =  influence concentration (how much of the deleted data's effect sits in a small set of sensitive update directions)

Obliviate relies on the fact that not every trainable-weight direction matters equally. Near the current solution, some directions strongly affect the forgotten interactions while others mainly add noise. The Hessian proxy estimates this local curvature, where curvature means how quickly the loss changes when you move in a given direction.

If deleted influence is concentrated in a few strong directions, a low-rank adapter can target those directions directly. That is why the method can forget with fewer trainable numbers. The calibration stage then protects local ranking behavior, because it fine-tunes the same adapter using ranking-based supervision and knowledge distillation, where knowledge distillation means matching the old model on data that should remain unchanged.

Why it works

Why the two-stage adapter approach can forget without wrecking ranking

The first stage, LUA, aims directly at the unwanted signal. A low-rank adapter represents the update as two small matrices whose product changes the model in a restricted subspace, where subspace means a limited set of allowable update directions. That restriction matters because it prevents the forget operation from drifting through every trainable weight and disturbing unrelated preferences.

The curvature proxy makes the restricted update sharper. If the loss surface changes steeply in one direction and barely changes in another, equal-size edits should not be treated the same. Curvature-aware training puts more focus on directions where the forgotten data leaves a larger local footprint, because moving there changes the target behavior faster.

The second stage, LAC, repairs collateral damage. Forgetting can distort rankings among similar items or neighboring users. LAC uses ranking objectives to re-separate good and bad recommendations in the affected neighborhood, and it uses distillation to keep untouched regions close to the original model. This improves utility because the method spends its recovery capacity only where forgetting created instability.

Math after the picture

The adapter update

First in words:

the model is changed by adding a low-rank adapter update, and the unlearning objective combines forgetting pressure with a curvature-weighted penalty and a calibration term

Then the compact form:

W_new = W + A B, L_total = L_forget + lambda * L_curvature + mu * L_calibration

Every symbol:

Wthe original recommender parameter block
A Bthe low-rank adapter product that changes that block
W_newthe parameter block after applying the adapter
L_forgetthe loss that suppresses the forgotten interactions
L_curvaturethe curvature-aware term that weights update directions by local sensitivity
L_calibrationthe refinement loss that restores ranking quality and preserves unaffected behavior
lambdathe weight on the curvature-aware term
muthe weight on the calibration term
A tiny worked example
Suppose one trainable-weight block is updated only through a rank-1 adapter, so A is a column and B is a row.
If the forget loss is 0.9, the curvature term is 0.3, and the calibration term is 0.2, with lambda = 2 and mu = 1.5, then total loss is 0.9 + 2 * 0.3 + 1.5 * 0.2 = 1.8.
A different adapter choice gives forget loss 0.8, curvature term 0.6, and calibration term 0.4, so total loss is 0.8 + 2 * 0.6 + 1.5 * 0.4 = 2.6.
The first choice wins even though its raw forget loss is slightly worse, because it removes the signal with less harmful movement and less ranking damage.

The loss balances forgetting against collateral damage, which is why the second stage is necessary instead of optimizing only deletion pressure.

What can go wrong

What can go wrong

The deleted signal is not low-rank enough. If the influence of the forgotten data is spread broadly across many unrelated directions, a small adapter cannot capture it. Unlearning will then be incomplete because the restricted update family is too narrow.
The curvature proxy is inaccurate. A rough local approximation can misidentify which directions matter. The adapter then spends capacity in the wrong place, which weakens forgetting or causes extra ranking damage.
Calibration restores too much old behavior. If the distillation or ranking weights are set too high, the second stage can pull the model back toward the original recommender and partially revive the deleted influence.
Done right. Choose adapter rank based on how concentrated the deleted influence is, validate the curvature proxy on held-out forget requests, and tune the calibration weights against both forgetting and ranking metrics.
What a runnable demo should prove

What a runnable demo should prove

Use a small factorization recommender, meaning a model that represents users and items with short lists of numbers, or use a small sequential recommender on a public interaction dataset. Train the base model, select a subset of user-item interactions to forget, and compare four systems: no unlearning, full retraining without the deleted data, a cheap adapter without curvature guidance, and Obliviate.

Measure two things at the same time: how much the deleted interactions still affect scores, and how well recommendation quality survives for untouched users. Then inspect the adapter rank and the calibration stage separately so you can see which part removes influence and which part restores ranking order.

forget_score = 1 - residual influence on deleted interactions, utility = top-k quality on retained data

A convincing demo should show that the adapter-plus-calibration path approaches retraining quality because it concentrates the update where the deleted signal actually lives.
