EGG-SR: Embedding Symbolic Equivalence

Symbolic regression finds physical laws from data faster by recognizing when two different-looking formulas are really the same function.

Paper explainersAll themesAI for Science

Symbolic regression tries to discover real equations from experimental measurements. But searching through all possible formulas is like looking through an infinite filing cabinet. Here's the catch: many formulas that look different are actually identical—for example, the log of x times y squared and log of (x times y squared) evaluate to the same thing. Most methods treat these as separate possibilities and waste time exploring redundant paths. This paper shows how to recognize these equivalences on the fly and skip the wasted work.

Zero assumption version

The search-space explosion

Symbolic regression starts with raw data and tries to reverse-engineer the physical law—the hidden equation that generated it. A naive approach builds expressions step by step, like assembling formulas from building blocks.

The trouble: even a tiny space of blocks explodes into an astronomical number of possible formulas. And worse, many of those formulas do the same job. The model wastes time exploring log of x-squared times log of y-cubed when it has already checked the log of the product x-squared times y-cubed and learned they both fit equally well—because they are the same function. That redundancy explodes the search time.

In one sentence. The same function can be written many different ways, and most symbolic regression methods explore each form separately, wasting computational work because they discover the same equation multiple times in different notational clothes.

The algorithm as a flow

What it actually does

Step 1: Build an equality graph

When the model proposes a sequence of rule applications, construct a graph that stores all equivalent expressions compactly.

Step 2: Deduplicate the search tree

In tree search, when expanding a node, skip sub-branches that the graph says are equivalent to already-explored ones.

Step 3: Pool rewards across equivalents

In reinforcement learning, collect rewards from all equivalent forms and share that success signal.

Step 4: Strengthen the learning signal

In language model methods, show the model multiple equivalent formulas so it learns the pattern faster.

Step 5: Extract the best one

After search, sample from the equivalence classes to pick the simplest or most interpretable formula.

What the paper changes

What the paper changes

The paper introduces one new data structure: an equality graph, a compact representation of equivalent expressions. Whenever the search algorithm generates a formula, the paper wraps it in this graph instead of treating it as a raw string.

the object it moves  =  Expression representation
The hidden quantity

The hidden quantity: Redundancy in the search tree

measured quantity  =  Equivalent expressions per formula

At any point in the search, a single correct formula can be written in many syntactically different ways. For example, x-squared plus x-squared and two times x-squared are the same. The paper measures this by counting how many distinct expression strings encode the same function.

An equality graph encodes this: it groups expressions into equivalence classes. If the model has explored one member of a class, the graph knows not to re-explore its twins. The paper estimates this by tracking how many branches in the search tree would be redundant.

Why it works

Why recognizing equivalence speeds up learning

Normally, a learning algorithm treats each candidate formula as independent. If it has tested one form of an equation and learned it fits the data perfectly, it has no idea that a different notational form of the same equation is identical and would also fit perfectly. So it explores both, wasting effort.

The equality graph changes this: when two formulas are marked as equivalent, the learner assigns them the same goodness score immediately. In tree search, this means skipping redundant subtree expansion. In reinforcement learning, a reward earned by one form automatically boosts all equivalent forms, because the learning algorithm now understands that discovering how well one notation fits automatically tells it how well all equivalent notations fit. The model learns faster because it does not repeat the same discovery multiple times in different notational clothes.

Math after the picture

The equation: Aggregated reward across equivalents

First in words:

For a sequence of rules that the model generated, build its equality graph and extract all equivalent sequences. Sum the rewards of all members and divide by the count. Use this pooled reward to update the model's parameters.

Then the compact form:

update_gradient = gradient_log_prob(sequence) * (sum of rewards / count of equivalent sequences)

Every symbol:

update_gradientthe nudge direction and size for the model's internal numbers
gradient_log_prob(sequence)how much the sequence likelihood changes if the model shifts
sum of rewardshow well each form of the formula fits the data, added together
count of equivalent sequenceshow many syntactically-different forms exist
A tiny worked example
Model generates rules for formula form A: a logarithmic expression. The equality graph finds this is equivalent to form B, a different notational way of writing the same thing.
Reward for form A (fit to data): 0.85. Reward for form B (same formula, measured independently): 0.85.
Pooled reward = (0.85 plus 0.85) divided by 2 equals 0.85. No change, because they are identical.
But if the system mistakenly merged a truly different form C (reward 0.60) into the equivalence class, the pooled reward would become (0.85 plus 0.85 plus 0.60) divided by 3 equals 0.77—incorrectly boosting form C.
The paper's graph ensures only true equivalences are pooled, validated on test data, so learning gets honest, unduplicated feedback.

Pooling rewards stops the model from learning the same lesson twice: once when it finds form A, again when it rediscovers form B.

What can go wrong

What can go wrong

Equivalence graph construction is expensive. Building and maintaining the equality graph for every candidate formula consumes CPU. The paper shows the overhead is small compared to coefficient fitting and neural network updates, but if your formulas are huge, the graph can become a bottleneck.
The graph must correctly encode all transformations. If the graph fails to recognize a true equivalence (e.g., misses that x + x equals 2*x), the method falls back to the naive redundancy. If it incorrectly merges two non-equivalent forms, learning receives false credit.
Grammar-based only. EGG-SR works for symbolic expressions with a defined grammar (like mathematical formulas). It does not apply to other symbolic spaces like Lisp code or image-generation prompts without adaptation.
Done right. The paper implements the graph in pure Python following the published e-graph literature, validates equivalences on test data, and tests on multiple symbolic regression frameworks (MCTS, DRL, LLM)—so false merges are caught by comparing predicted equivalences against actual experimental results.

What a runnable demo should prove

Log how many candidate formulas are explored, how many unique functionally-different formulas are discovered, and the best formula accuracy at fixed wall-clock time.

speedup = (formulas explored without EGG) / (formulas explored with EGG); accuracy_gain = best_accuracy_with_EGG - best_accuracy_without_EGG

The demo must show that the same computational budget discovers more accurate formulas when redundancy is pruned—because pruning stops wasting searches on notational twins, freeing time to explore genuinely different equations. Without pruning, most effort evaporates on redundant exploration; with it, the searcher has resources left to try new forms. That is not magic—just effective use of budget.
