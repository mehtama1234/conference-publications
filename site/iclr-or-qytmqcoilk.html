Why Discrete Curvature Fails to Detect Over-squashing in GNNs

Discrete curvature alone cannot reliably detect when graph bottlenecks squeeze information, but a new measure called Weighted Augmented Forman-3 Curvature fixes this.

Paper explainersAll themesGraph & Geometric Learning

Graph neural networks fail to send messages through narrow bottlenecks in large graphs—a problem called over-squashing. The traditional fix is to measure the shape of the graph using a number called discrete curvature: curves with strong negative curvature were thought to be the culprits. This paper proves that assumption wrong: some edges squeeze information even when the shape looks flat, and traditional curvature misses 30 to 40 percent of these bottlenecks.

Zero assumption version

Information drowning in narrow graph corridors

Graph neural networks are models that learn from connected data—social networks, molecules, road maps. They work by passing messages along the edges: each node receives information from its neighbors, adds its own observation, and passes it forward. The problem arises when the graph has bottlenecks: long chains or narrow corridors where many nodes funnel their signals through just a few edges.

When this happens, the messages get squeezed. Imagine a busy shopping district: if all shoppers try to cross a single narrow alley, they pile up, their identities blur together, and none emerges with a clear sense of who they met. This is over-squashing. The naive fix: measure the shape of the graph using a math tool called discrete curvature. If an edge has strong negative curvature, the conventional wisdom says, it will be a bottleneck. But this assumption cracks under pressure.

The problem. Graph bottlenecks squeeze messages until their details vanish, and traditional shape-measurement tools miss most of them.

What the paper changes

What the paper changes

The paper replaces the curvature formula used to detect graph bottlenecks. Instead of relying solely on Ollivier-Ricci curvature, it introduces Weighted Augmented Forman-3 Curvature, which accounts for edge weights and neighbor structures that the old measure ignores.

The hidden quantity

The hidden quantity: bottleneck severity

measured quantity  =  how much information squeezed at each edge

The paper is really measuring one thing: which edges are choke points where lots of signals collide. This quantity is not directly observable—you cannot see messages pile up without running a graph neural network and watching information flow—but it matters because squashed information means the network cannot learn long-range patterns.

The paper estimates this by analyzing the local structure around each edge: how many neighbors feed into it, how far away those neighbors are, and how the paths route through the edge. The new Weighted Augmented Forman-3 Curvature captures this structure better than the old discrete curvature because it includes neighbor distance and flow weight—two things the old method ignored.

Why it works

Why the new measure catches bottlenecks

The old Ollivier-Ricci curvature measures only the shape of the graph as if all edges and paths had equal weight. It assumes the distance between neighbors is the same everywhere, ignoring how many times messages really travel each path. In tightly connected regions, this ignorance misses real congestion because the traffic pattern—not just the shape—determines whether an edge becomes a bottleneck.

The new Weighted Augmented Forman-3 Curvature adds three fixes. First: it counts how many neighbors sit close by and far away (the Forman-3 term), because neighbors at different distances contribute differently to congestion. Second: it weights the paths by how often messages actually flow through them (the Weighted term), because a path used by many signals is more likely to squash information. Third: it includes neighbor-of-neighbor structure (the Augmented term), because these distant-once-removed nodes matter when traffic funnels through an edge. Together, these three pieces catch the real bottleneck: an edge is a chokepoint because the graph's flow pattern funnels many signals through it, not just because of its shape.

Math after the picture

The new curvature formula

First in words:

Weighted Augmented Forman-3 Curvature of edge e equals a weighted combination of how many first-order neighbors sit on each side of the edge, adjusted by how far away those neighbors sit, plus a weighted term for second-order neighbors.

Then the compact form:

WAF3(e) = sum over neighbors on each side of (weight_ij * distance_penalty_ij) + augmentation_term for second_order_neighbors

Every symbol:

WAF3(e)Weighted Augmented Forman-3 Curvature score for edge e
weight_ijhow much of the message flow passes between neighbors i and j
distance_penalty_ija number that grows when neighbors are far apart
augmentation_termadditional score from counting second-order neighbors (neighbors of neighbors)
A tiny worked example
Edge connects node A to node B.
Node A has 5 neighbors nearby (distance 1), contributing 5 × 1.0 = 5 to the score.
Node A has 2 neighbors far away (distance 3), contributing 2 × 0.3 = 0.6 to the score.
Node B has 3 neighbors nearby (distance 1), contributing 3 × 1.0 = 3 to the score.
Node B has 4 neighbors at medium distance (distance 2), contributing 4 × 0.6 = 2.4 to the score.
Augmentation term from shared neighbors of A and B: 0.5.
Total WAF3 score: 5 + 0.6 + 3 + 2.4 + 0.5 = 11.5 (a tight bottleneck).
Same edge under old curvature: score 4.0 (missed as a problem). New measure catches it.

The score rises when many neighbors cluster on both sides of an edge—the signature of a bottleneck.

What can go wrong

What can go wrong

Weighted curvature requires knowing message flow. The new measure performs best when the weights reflect the true communication patterns. If the weights are wrong or out of date, the curvature will be misleading.
Computation grows with graph size and density. The new algorithm is 133 times faster because it uses a clever local approximation instead of global path enumeration; however, it still takes longer on very large or very dense graphs because it must examine more neighbors and edges at each step.
Curvature is a local measure. It only looks at edges and their immediate neighbors. Global bottlenecks that span long paths may not be fully captured by any local curvature.
Done right. Use Weighted Augmented Forman-3 Curvature as a preprocessing step to identify bottleneck edges, then use it to guide training (e.g., add extra connections at high-curvature edges or weight the loss differently).
What a runnable demo should prove

What a runnable demo should prove

Build a small synthetic graph with a known bottleneck (e.g., a chain graph with a very narrow middle section). Run both Ollivier-Ricci curvature and Weighted Augmented Forman-3 Curvature on it. Measure how many edges each method correctly identifies as problematic. Then train a graph neural network on a simple node-classification task and show that when you use the new curvature to guide training (e.g., by adding edges at high-curvature nodes), the network learns long-range patterns better than if you use the old curvature.

accuracy_improvement = (accuracy with WAF3 guided training) minus (accuracy with old curvature guided training)

The demo should show that WAF3 catches bottlenecks the old method misses, and using it in training helps the network learn better because the model can focus its learning effort on the edges that actually choke information flow.
