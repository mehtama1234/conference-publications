Efficient Prediction of Large Protein Complexes via Subunit-Guided Hierarchical Refinement

Split big protein complexes into smaller pieces, predict each piece separately with smart boundaries, then glue them back together to dodge memory limits.

Paper explainersAll themesAI for Science

When you predict the shape of a big protein complex using a neural network, the memory use grows by a square (if the complex doubles in size, memory grows four times). This makes it impossible to predict complexes bigger than about 4,000 building blocks. HierAFold breaks this limit by treating large complexes as puzzles of smaller subunits—predicting subunits and their interfaces separately, then reassembling them with confidence scores.

Zero assumption version

Why big protein complexes break the predictor

Modern neural networks that predict protein 3D shapes (like AlphaFold3) use a trick called attention—each piece of the protein looks at every other piece to figure out where to go. When a protein has N building blocks, this means N times N connections need to be held in the graphics card's memory. For a 4,000-block complex, that is 16 million connections. Double the size to 8,000 blocks and you need 64 million connections.

A beginner might try predicting the whole complex at once. It crashes when the graphics card runs out of memory. You could predict smaller chunks and stitch them together, but the boundaries are arbitrary—you cut right through connections the model needs to see, so the prediction quality falls by half.

The core problem. End-to-end prediction runs out of memory; chopping it up blindly ruins the answer.

What the paper changes

What the paper changes

Instead of forcing the whole complex through one forward pass, HierAFold reorganizes the prediction into layers: subunits first, then interfaces, then assembly. The neural network sees smaller problems at each step, so each attention matrix is tiny. The object is the prediction strategy—not a new model, but a smarter way to route inputs.

The hidden quantity

The PAE signal: contact confidence

measured quantity  =  Predicted Aligned Error (PAE)

PAE is a grid of numbers—one for each pair of building blocks in the complex. A low PAE value means the model is confident those two blocks are close (touching, bonded). A high value means it is uncertain (far apart, or no bond). When PAE is low between two subunits, they interact; when PAE is high across a boundary, that boundary is a good place to cut the complex.

The paper uses PAE not to predict final positions (that is the job of the full model) but to identify safe decomposition boundaries. Low PAE regions (bonds) stay together; high PAE regions (sparse spaces) are cut. This lets the algorithm chop the complex without severing tight bonds.

Why it works

Why splitting by PAE and refining in pairs works

Splitting breaks quadratic memory growth. If you predict 5 subunits solo, each sees N/5 building blocks, so each attention matrix shrinks from N² to (N/5)². Memory drops 25-fold. Solo predictions lose multi-body information though—some subunits only grip in a triad, a pair, a quintet. That is what the interface-refinement step fixes.

Predicting pairs (subunit A + subunit B together, or A + C, or A + B + C) keeps the critical handshakes visible. If pair A-B was predicted at low resolution in the solo step, the joint prediction refines it. Each pair is small, so even 10 pairs still fit in memory. Finally, confidence-weighted assembly picks the best parts of each prediction—subunits stay as solo-predicted (fast, usually good), interfaces come from pair predictions (slow, fixes grip errors), and regions where confidence drops are re-predicted or flagged for human review.

The confidence-weighted assembly formula

First in words:

For each spatial coordinate (position in 3D space), the final prediction is the average position, weighted by how confident each prediction method was about that region.

Then the compact form:

position_final = sum_method ( confidence_method * position_method ) / sum_method( confidence_method )

Every symbol:

position_finalthe final 3D coordinate in the assembled complex
position_methodthe coordinate predicted by one prediction method (solo subunit or pair prediction)
confidence_methodthe model's confidence score for that prediction region
A tiny worked example
Say subunit 1 predicts an atom at (1.5, 2.0, 3.1) with confidence 0.90.
The pair prediction (subunit 1 + 2) predicts the same atom at (1.6, 2.1, 3.0) with confidence 0.85.
final_x = (0.90 * 1.5 + 0.85 * 1.6) / (0.90 + 0.85) = (1.35 + 1.36) / 1.75 = 2.71 / 1.75 = 1.55
The solo prediction pulled harder (higher confidence), so the final answer leans toward 1.5. If the pair had confidence 0.95, the final x would drift toward 1.6 instead.

Confidence acts as a weight—the model's most certain predictions dominate the final assembly.

What can go wrong

What can go wrong

PAE boundaries are wrong. If PAE is genuinely uncertain (e.g. a very loose or transient complex), the algorithm might cut in the middle of a weak bond. The interface-refinement step sometimes rescues this, but if confidence stays low, the final assembly is unreliable.
Interface predictions fail for tight trimers. Some complexes only fold correctly when three or more subunits are present. Pairwise refinement misses the three-body grip. The algorithm predicts pairs, and the trio folds wrong—a fundamental limit of the hierarchy.
Confidence scores are overconfident. The model might assign high confidence to a wrong prediction. Weighted assembly will favor the wrong part. Humans must spot-check complexes with high overall confidence but low accuracy.
It works well. For most biological complexes (which are naturally modular), HierAFold matches AlphaFold3 accuracy at a fraction of the memory and time cost. The 25 GB memory savings make complexes with 5,000+ building blocks tractable.
What a runnable demo should prove

What a runnable demo should prove

Build a tiny test: take a known protein complex (say, a 1,200-token dimer of two identical proteins), run it through HierAFold (solo subunit predictions + pair refinement), and compare the output structure to the real crystal structure in the Protein Data Bank. Compute the RMSD (a distance measure—0 is perfect, 2 Angstroms is acceptable). Then try the same complex with AlphaFold3 on the same GPU. Compare memory usage and prediction time. Finally, artificially double the complex size (add a copy of each subunit, making a 2,400-token complex), run both methods, and measure which one still fits in memory.

rmsd_error = sqrt( (1/N) * sum_i ( (x_predicted_i - x_true_i)^2 + (y_predicted_i - y_true_i)^2 + (z_predicted_i - z_true_i)^2 ) )

Memory savings must be real (at least 25 GB for a 4,000-token target), and RMSD should stay under 2 Angstroms—proof that the hierarchy does not sacrifice accuracy.
