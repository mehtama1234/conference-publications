From Gradient Volume to Shapley Fairness: Fair Multi-Task Learning

When training a model on multiple tasks at once, some tasks pull gradients in opposite directions; SVFair uses Shapley values to measure each task's deviation and rebalance updates so all tasks improve fairly.

Paper explainersAll themesAlignment, Safety & Fairness

When you train one model to handle many tasks, their learning signals often collide. Task A pulls weights in one direction, Task B pulls in the opposite way. One task wins, the other loses, and overall performance drops. SVFair fixes this by measuring how much each task deviates from the group average update direction (the gradient is the nudge that adjusts weights), then rebalancing updates so every task gets a fair say.

Zero assumption version

Gradient conflicts kill multi-task learning

When you train a single neural network on multiple tasks, their training signals pull weights in different directions. A beginner might try to average the gradients (the nudges that update weights) equally, but this fails: if Task A wants weight W to go up and Task B wants it to go down, averaging cancels both signals out, and neither task learns well.

The root problem: some tasks genuinely have antagonistic goals. A model trained to recognize cats and dogs might learn features that help one but hurt the other, because a feature useful for detecting a cat shape (pointy ears) might be useless or misleading for dogs (floppy ears). Averaging drowns out the important signal each task has. The result is that one or both tasks perform worse than if trained separately, a phenomenon called negative transfer.

The problem in one sentence. Gradient conflicts in multi-task learning cause unfair optimization where tasks with competing signals cancel each other out, degrading performance.

The algorithm as a flow

What it actually does

Collect gradients

Compute the gradient vector (direction and magnitude of the nudge) for each task separately.

Compute conflict volume

Measure how far each task's gradient direction deviates from the average—using a geometric volume metric called VolDet, which captures how much the gradients spread out.

Apply Shapley fairness

Assign each task a Shapley value (a fair share of credit) proportional to how much it deviates from the group average.

Reweight and aggregate

Multiply each task's gradient by its Shapley weight, then average them back together.

Update model once

Apply the weighted-average gradient to the model weights once per step, ensuring all tasks contribute fairly.

What the paper changes

The thing that changes

SVFair modifies how gradients are combined. Instead of averaging all task gradients equally, it weights each task's gradient by its Shapley value, which measures how much that task deviates from the group direction.

the object it moves  =  gradient weights
The hidden quantity

The hidden quantity: Gradient deviation fairness

measured quantity  =  Shapley-weighted gradient fairness

SVFair introduces a hidden quantity: each task's Shapley value, which represents its fair share of the aggregated update. A Shapley value is a number that distributes credit fairly among players (in this case, tasks) based on how much each one contributes to the whole. For gradients, the contribution is measured by how far a task's direction deviates from the group average.

The paper estimates this using two geometric metrics. VolDet computes the volume (determinant) of the Gram matrix formed by stacking all task gradients—larger volume means gradients point in more different directions. VolDetPro extends this by distinguishing antagonistic (directly opposite) gradients from merely different ones, because pulling in exact opposite directions is a worse conflict than pulling perpendicular.

Plain reading. Shapley values are a way to fairly split credit among a team. If Task A's gradient points far from the group average, it did something unique that the group needs, so it gets a higher Shapley value and a stronger influence on the update.
Paper reading. The paper computes Shapley values by analyzing the geometric volume (via VolDet and VolDetPro metrics) of the gradient cone formed by all tasks, assigning each task a value proportional to how much it would reduce that volume if removed.
Why it works

Why it works: Fairness through unique directions

The core insight is that when gradients conflict, simply averaging them loses information. Each task has a valid learning signal, but averaging treats conflicting tasks symmetrically—it penalizes both equally. SVFair inverts this: it rewards tasks that deviate from the group.

Here's the chain: High-deviation tasks have gradients that point in unique directions. These unique directions carry information the model would otherwise ignore. By giving high-deviation tasks higher Shapley weights, the update leans into the unique signal. Low-deviation tasks (those that align with the group) already influence the final update through the group average, so they need less weight. The result is that every task's learning signal reaches the model in a balanced way, and negative transfer disappears because no task is drowned out.

The Shapley value mechanism matters because it is the unique fair way to distribute credit. It is not just a heuristic reweighting; it satisfies mathematical fairness axioms: a task cannot be harmed by adding another task, and if two tasks are redundant, they share credit equally. This mathematical grounding ensures the fairness is not arbitrary.

Math after the picture

The equation: Weighted fairness aggregation

First in words:

The final aggregated gradient is the weighted average of each task's gradient, where each task's weight is its Shapley value computed from the geometric volume of the gradient cone.

Then the compact form:

g_agg = sum_i phi_i * g_i, where phi_i = Shapley value for task i, g_i = gradient for task i

Every symbol:

g_aggthe final aggregated gradient that updates the model
phi_iShapley value (fairness weight) for task i, computed from VolDet or VolDetPro
g_ithe gradient vector computed for task i on this step
sum_iadd across all tasks
A tiny worked example
Suppose three tasks have update nudges (gradients). Task 1's nudge is very different from the others (high deviation), so phi_1 = 0.5. Tasks 2 and 3 point in similar directions (low deviation), so phi_2 = 0.25, phi_3 = 0.25.
If g_1 = [2, 0], g_2 = [1, 0], g_3 = [1, 0], then g_agg = 0.5*[2,0] + 0.25*[1,0] + 0.25*[1,0] = [1.5, 0].
Task 1 (the deviant) has twice the influence of each other task, so its unique signal is preserved. Equal weights would give g_avg = [1.33, 0], drowning Task 1 in the group—but Shapley fairness amplifies it because it is unique.

Shapley weights recover the unique signal each task carries. High-deviation tasks pull harder, low-deviation tasks rely on the group average, and nothing cancels out.

What can go wrong

What can go wrong

Shapley computation is expensive for many tasks. Computing Shapley values exactly requires evaluating many subsets of tasks, which scales exponentially. The paper addresses this with approximations (VolDetPro), but if you have hundreds of tasks, the cost can become prohibitive. The paper's controllable complexity setting helps by capping how many subsets you check, but trading off cost for speed means the Shapley approximation becomes less precise and may not capture the full fairness guarantee that the exact formula would provide.
If all tasks genuinely have the same goal, extra reweighting can hurt. When gradients already point in the same direction, adding fairness reweighting is unnecessary. SVFair may still reweight them slightly based on minor deviations, potentially introducing noise. This is rare but can happen in well-aligned multi-task settings.
Task importance weights must be chosen carefully. SVFair assumes all tasks should contribute fairly, but in practice some tasks may be more important than others. If you pre-weight tasks, the Shapley computation changes. Mixing user-defined importance with Shapley fairness can lead to unexpected interactions.
Done right: measure gradient conflict first. Before applying SVFair, check if your tasks actually have conflicting gradients. If they align naturally, plain averaging is simpler. SVFair shines when VolDet or VolDetPro shows high conflict volume—that is when reweighting by Shapley values recovers the most improvement.
What a runnable demo should prove

What a runnable demo should prove

Write a simple multi-task learning setup with two tasks that have antagonistic gradients (e.g., one task wants to maximize a feature, the other wants to minimize it, like learning to classify cats vs. dogs on a dataset where the features anti-correlate). Train the model three ways: Task A only, Task B only, and both tasks together using SVFair. Measure accuracy on each task and the combined loss.

fairness_gain = (accuracy_A_svfair + accuracy_B_svfair) - (accuracy_A_avg + accuracy_B_avg), where _avg is naive equal-weight averaging and _svfair uses Shapley reweighting

The demo must show that SVFair keeps both task accuracies high even when their gradients conflict, whereas naive averaging degrades at least one task. That is the core proof: fairness through geometric conflict measurement actually works.
