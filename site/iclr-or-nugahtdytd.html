Scalable In-Context Q-Learning

Teach a transformer to learn new tasks from raw experience using value functions, not just by copying old examples.

Paper explainersAll themesReinforcement Learning

A language model is great at learning from examples without retraining. But in reinforcement learning (learning to control things by trial and error), learning from raw experience is harder than copying. This paper adds a value function (a score for how good each state is). When the value score is high, the model trains strongly to repeat the action that led there; when it is low, the model weakly trains. Over time, the model learns to seek high-value states and avoid low-value ones—an improvement over just copying what was done before.

Zero assumption version

Language models learn by copying, not by improving

A language model can read past examples and predict what to do next without being retrained. But when a robot learns by trial and error, just copying old actions is not enough. A naive approach trains the model to predict the actions that were actually taken in the past data, even if those actions were mediocre.

The trouble: if your training data contains bad attempts, the model learns to repeat them. It cannot tell which actions were wise and which were lucky accidents. Raw supervised learning treats every action equally, so it cannot reassemble suboptimal pieces—a path made of mostly-bad steps gets learned as-is, while a path that combines the best step from one attempt and the best step from another never gets explicitly shown.

The paper's move in one sentence: Add a value function (a scoring system for how good each state is) to the model so it can upweight good actions and downweight bad ones, teaching it to improve rather than just imitate.

What the paper changes

What the paper changes

Instead of a single output head that predicts actions, the paper adds a dual-head architecture. One head predicts the policy (which action to take), the other predicts the value function (how good is this state). The policy head then learns to maximize actions that are associated with high-value states.

the object it moves  =  Transformer heads (add value head)
The hidden quantity

The hidden quantity: state value

measured quantity  =  Value of a state

The value of a state is a single number measuring how good it is—roughly, the total reward you expect to earn from that point onward. Unlike the raw data (which may contain accidents and dead ends), the value function isolates the signal: high-value states are on the path to success.

The paper computes this by training the value head on returns actually observed in past data, weighted by how well the policy predicts each action. Then, during policy training, high-value states pull the policy toward their actions, and low-value states push it away.

The transformer distills this into the policy via advantage-weighted regression: policy actions in high-advantage (high quality, low baseline) states get upweighted in the supervised learning loss.
Why it works

Why it works: dynamic programming meets in-context learning

Classical reinforcement learning uses dynamic programming: compute the value of each state by summing future rewards, then use those values to train the policy. The paper's innovation is doing this inside a transformer that also works in-context (learns a new task from a few examples without retraining). The mechanism has two parts.

First, a world model (the context encoder and dynamics decoder) reads recent history and predicts what happens next. This lightweight model lets the transformer forget long-term memory and focus only on task-relevant details. Second, the value head learns which states are worth pursuing by looking at actual returns in the offline data. Then the policy head trains to imitate actions leading to high-value states and avoid actions leading to low-value states. This overcomes the key problem: data usually contains suboptimal actions, but by weighting actions by their outcome value, the model learns to filter out the mediocre ones and amplify the good ones. Over many tasks, the transformer learns a general rule: seek high-value states, and do so fast without retraining.

The weight in the advantage-weighted loss acts as a volume knob. Actions from high-value states get a loud training signal; actions from low-value states get a quiet one. Over time, the policy learns the shape of good behavior across diverse tasks without ever being retrained.

Math after the picture

The learning rule: weight actions by their values

First in words:

policy_loss = negative sum over (transitions) of weight * log( probability of observed action ), where weight is the value score of the state.

Then the compact form:

L_policy = sum_t [ Q(s_t, a_t) - V_baseline(s_t) ] * log(π(a_t|s_t))

Every symbol:

Q(s_t, a_t)Expected reward if you take action a_t in state s_t
V_baseline(s_t)Expected reward from any random action in state s_t
Q(...) - V_baseline(...)Advantage: how much better this action is than average
log(π(a_t|s_t))Log probability the policy assigns to the observed action
sum_tAdd up the loss for all steps in all trajectories
Tiny worked example: two robot paths
Path A, step 1: state value 8, robot moved right (prob 0.6). Baseline value 3. Advantage = 8 - 3 = 5. Loss term = 5 * log(0.6) = 5 * (-0.51) = -2.55 (strong push to repeat).
Path A, step 2: state value 2, robot moved left (prob 0.3). Baseline value 3. Advantage = 2 - 3 = -1. Loss term = -1 * log(0.3) = -1 * (-1.20) = +1.20 (gentle push to avoid).
Path B, step 1: state value 8, robot moved right (prob 0.4). Advantage = 5. Loss term = 5 * log(0.4) = -4.05. Same high value, different probability: steeper slope upward, more aggressive retraining.
Total loss for A and B combined: -2.55 + 1.20 - 4.05 = -5.4. Optimizer nudges weights to raise the right-action probability in high-value states.

The weight (advantage) amplifies the training signal for good states and dampens it for bad ones, so the transformer learns to stitch together the best pieces of suboptimal data.

What can go wrong

What can go wrong

Value function is poorly trained. If the value head overfits to one task's data, it will assign high scores to arbitrary states on new tasks. The policy will then learn meaningless patterns. Fix: train the value head on diverse tasks and gently steer its predictions toward sensible ranges.
Context encoder loses information. If the lightweight task summary throws away important details (like goal position), the policy cannot distinguish one task from another. Both value and policy heads will be confused. Fix: validate that the encoder captures the most informative k steps.
Advantage computation is unstable. If the baseline value (the denominator in advantage) is inaccurate, every single action weight becomes wrong. The policy learns garbage. Fix: use gentle steering to keep baseline values in a sensible range and test across diverse tasks.
Done right. When the value head is well-trained on diverse data, the policy learns to seek high-value states reliably. On new tasks, it adapts fast because it already knows the pattern.
What a runnable demo should prove

What a runnable demo should prove

Train a model on offline data from multiple robot tasks, where each task has some suboptimal trajectories. Split the tasks: train on easy versions (low rewards), test on harder versions (higher rewards). Measure how well the new task succeeds.

Success = (reward_on_new_task - baseline_supervised_reward) / (oracle_best_reward - baseline_supervised_reward)

If the value-weighted policy beats pure supervised imitation on harder test tasks, the demo proves the mechanism: the value-weight scheme is filtering—high-value states push the policy to repeat their actions, low-value states push back. Because the model is trained across many tasks, it learns the general pattern that high-value states are worth imitating, a rule that applies to any new task with the same reward structure.
