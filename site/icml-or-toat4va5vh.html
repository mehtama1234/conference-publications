Adaptive Node Feature Selection for Graph Neural Networks

A graph neural network learns which node features actually matter by testing what happens when you scramble each feature and watching the validation score change.

Paper explainersAll themesGraph & Geometric Learning

When training models on graph data (networks of connected things), you have many features (measurements) on each node. Some features help the model; others are just noise. Classical methods for picking important features don't work on graphs because graphs have complex internal structure. This paper proposes a simple test: during training, pick a random feature, scramble its values, and measure how much the validation score drops. Big drops mean that feature matters; tiny drops mean it is useless. The method is agnostic to the model type and the specific task.

Zero assumption version

Classical feature importance breaks on graphs

A graph neural network (GNN) is a model that learns on a network — a set of things (nodes) with relationships (edges) between them. Each node has a list of measurements called features. A beginner might try classical feature importance: compute a score for each feature (like how much removing it hurts), then rank them. But classical methods assume features are independent. On graphs they are not: a feature's importance depends on the graph structure and on which other nodes it is connected to.

So you get nonsense rankings. A feature that is useless in isolation might actually help because of how the graph connects things. A feature that looks important might only matter for a few rare graph shapes. You need a way to measure what is actually working in your specific graph and your specific task, during training.

In one sentence. Measure feature importance by scrambling each feature one at a time during training and watching how the validation score changes.

The algorithm as a flow

What it actually does

Measure each feature

During training, for each feature in turn, scramble its values and recompute the validation score.

Calculate the drop

The difference between the normal score and the scrambled score is the feature's importance.

Repeat often

Do this test many times during training because feature importance can change as the model learns.

Rank and filter

Rank features by how much they hurt the validation when scrambled, drop the low-scoring ones.

Retrain if needed

Optionally retrain the final model on only the selected features for a cleaner result.

What the paper changes

What changes

The paper changes which node features are included in the model. Features that pass the importance test are kept; features that have no impact when scrambled are dropped.

The hidden quantity

The importance score

measured quantity  =  feature importance via permutation

The hidden quantity is a single number for each feature: how much the validation score drops when that feature is scrambled. This is the feature's importance score. High score means the feature is essential; low score means it is noise. Unlike classical importance metrics (which assume independence), this one is measured directly on your exact graph and your exact task.

The paper measures it by a simple algorithm: compute validation score normally, then flip/shuffle all values of one feature, recompute, and subtract. The bigger the drop, the more that feature contributed. Early in training, before the model has learned anything, this score is unreliable. As training progresses, it stabilizes and becomes usable for filtering.

Why it works

Why it works

The core insight is indirect measurement. You cannot ask the model 'why did you choose this feature'; that is hard to answer in any learning system. Instead, you ask the graph a behavioral question: 'what happens if this feature stops working?' If the answer is 'the validation score barely changes', then that feature was not important in the first place. If the answer is 'the validation score drops 15 percentage points', then that feature was critical.

This works because graphs have many interlocking connections. A feature that looks useless in isolation might be used only for a specific node type or edge pattern. By testing on the full graph during training, you capture those dependencies automatically. The model has already learned which features to focus on by the time you run the importance test, so the importance scores reflect what the model actually uses, not what classical statistics say should matter.

The importance formula

First in words:

importance of feature j equals validation score before minus validation score after scrambling feature j

Then the compact form:

importance_j = val_score_normal - val_score_scrambled_j

Every symbol:

val_score_normalthe validation accuracy on the true graph
val_score_scrambled_jthe validation accuracy when all values of feature j are shuffled
importance_jhow much feature j helps the model
A tiny worked example
Feature 1: validation score without scrambling = 92%, with scrambling = 85%, importance = 92% - 85% = 7%
Feature 2: validation score without scrambling = 92%, with scrambling = 91%, importance = 92% - 91% = 1%
Feature 1 has 7x higher importance, so feature 2 can be dropped.

The importance is a simple difference in validation accuracy. Features that cause big drops are kept; features that barely hurt are removed.

What can go wrong

What can go wrong

Testing too early in training. If you measure importance when the model is still untrained, the scores are random noise. Wait until the model has learned something first, then the test is reliable.
Features that are correlated. If two features are always together (e.g., both measure size), scrambling one might not hurt because the model can rely on the other. You might keep both when one is redundant.
Rare graph patterns. A feature might matter only for nodes that appear once in the graph. The importance test averages over the whole graph, so rare patterns can be missed.
Done right. Measure importance after the model has converged (because early training scores are noise), on a held-out validation set (because test set results are unreliable for feature selection), and be aware that a feature might not appear important in your current task but could help on other tasks because what matters depends on the specific graph structure and labels you are working with.
What a runnable demo should prove

What a runnable demo should prove

Build a simple graph neural network on a graph dataset (e.g., a citation network, a social network, or a molecular graph). Train the model normally and also with this feature selection method. Track the validation accuracy on the held-out test set and the model size (number of parameters) over training steps.

payoff = (test_accuracy_selected / test_accuracy_all) - (model_size_selected / model_size_all), so bigger is better

The demo should show that using fewer features improves accuracy (because the model stops chasing noise) and shrinks the model size (because you compute fewer inputs), proving that the selected features are doing the work and the dropped features were noise.
