Revisiting the Past: Data Unlearning with Model State History

Use saved model snapshots from training to erase the influence of specific data on an LLM without retraining from scratch.

Paper explainersAll themesLLMs & Foundation Models

Large language models learn from billions of web pages, some containing private information, copyrighted text, or factually wrong content. Completely retraining the model to exclude these datapoints would take months and cost millions. This paper proposes MSA: a method that saves model snapshots during pretraining, then uses arithmetic on those snapshots to surgically remove the influence of harmful data from an already-trained model, because the difference between two saved states reveals exactly what one batch of data changed.

Zero assumption version

The retraining trap

An LLM's training is set in stone once it finishes. If later you discover that some of the training data was private (an employee's email leaked into the corpus) or copyrighted (a book you should have licensed) or just wrong (outdated medical advice), there is no surgical way to remove it. The model's millions of weights have locked in knowledge of every sentence it read.

A beginner's first idea: just retrain the model from scratch, leaving out the bad data. But pretraining a large language model takes weeks or months on thousands of graphics cards, costing $5-20 million. You cannot afford to retrain it every time you discover one bad datapoint.

The problem in one sentence. Once trained, an LLM cannot unlearn data without starting over, which is prohibitively expensive.

The algorithm as a flow

What it actually does

Save checkpoint snapshots

During pretraining, regularly save complete model states at different points (before the bad data, at the bad data, after it).

Identify the target data

Mark which datapoints need to be unlearned (the private information, copyrighted text, or factual errors).

Measure the influence

The difference between checkpoint-before and checkpoint-after shows exactly what weights changed due to that data.

Compute the unlearning update

Subtract the influence from the current model: flip the sign of the shift and add it back.

Verify the erasure

Test that the model no longer knows the bad data and still answers other questions correctly.

What the paper changes

What the paper changes

MSA does not retrain the model or change its architecture. It directly adjusts the millions of numerical weights (the parameters that hold the model's knowledge) by subtracting off the influence of specific datapoints.

the object it moves  =  the model's weights
The hidden quantity

The datapoint influence: how much each piece of data changed the model

measured quantity  =  Influence of a single datapoint

When a model trains, each datapoint (sentence, book excerpt, webpage) nudges the weights slightly. The influence is how much a single datapoint moved those weights, measured as the numerical difference between the model state before and after that data was seen.

MSA estimates this influence by comparing two saved checkpoints: one taken just before the model saw the bad data, and one after. The difference in weights is the influence. By subtracting it away, the method reverses what that data did.

Why it works

Why removing the influence actually works

Training a model means nudging the weights in tiny steps, each step directed by the error on a batch of data. If you save the model at two consecutive training steps—before a piece of bad data and after it—the difference in weights is exactly what that bad data caused.

Model weights are additive: you can save a model state (millions of numbers), run training, and later subtract one saved state from another to isolate what changed. By subtracting the influence of the bad data away from the current model, you undo the effect of that training step, leaving the rest of the learning untouched.

This works because at small scales, training steps roughly add together: the weight changes from different datapoints combine without interfering. So if you know what shift the bad data caused, you can reverse it surgically without touching the shifts caused by good data.

Math after the picture

The equation and a worked example

First in words:

Unlearned weights equals current weights minus the influence of the bad data, where influence is computed from checkpoint arithmetic.

Then the compact form:

theta_unlearned = theta_current - (theta_after - theta_before)

Every symbol:

theta_currentall the model's weights right now
theta_afterweights saved after seeing the bad data
theta_beforeweights saved before seeing the bad data
theta_unlearnedweights after removing the bad data's influence
A tiny worked example
Suppose one weight in the model has value 0.85 now. Before seeing bad data it was 0.80, and after it was 0.82.
Influence = 0.82 - 0.80 = 0.02 (the bad data moved this weight by 0.02).
Unlearned weight = 0.85 - 0.02 = 0.83 (we undo that shift).
If the same weight was only 0.81 after the bad data (the bad data barely touched it), influence = 0.01, unlearned = 0.84. Weights barely affected are barely changed.

The subtraction reverses the influence of one bad training step, surgical and cost-free.

What can go wrong

What can go wrong

Checkpoints must exist for the exact data you want to forget. If you only saved checkpoints every 10,000 training steps, but the bad data appeared at step 5,000, you cannot pinpoint its influence. The method needs dense checkpoints.
Noise and interference from other data. If many datapoints were learned between the two checkpoints (not just the bad data), the arithmetic captures all of them mixed together. You cannot surgically isolate a single bad sentence in a batch of 1,000 sentences.
Nonlinearity breaks the assumption. Training is not perfectly additive at large scales. Very far away checkpoints or large influence values may not subtract cleanly because the model's behavior has shifted.
Done right. Use dense, frequent checkpoints. Unlearn data in large groups (batches) where the arithmetic is most accurate. Verify by testing that the model actually forgets the bad data and retains good-data knowledge.
What a runnable demo should prove

What a runnable demo should prove

Train a small language model (a miniature version, maybe 10 million parameters instead of 7 billion) on a small dataset. Deliberately include a few sentences of private or copyrighted text. Save checkpoints before and after those sentences are seen. Then apply MSA: subtract the influence and test whether the model still knows the bad sentences (it should not) but still answers normal questions correctly (it should).

Unlearning success = (accuracy on bad data before) minus (accuracy on bad data after) = should be high; Retention = (accuracy on good data before) minus (accuracy on good data after) = should be low (we barely forgot good data)

The demo must show that you can erase specific data from a trained model in seconds, without retraining, and without breaking the model's performance on normal questions.
