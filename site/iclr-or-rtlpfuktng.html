Model Predictive Adversarial Imitation Learning

A robot learns a reward function and a planner together from watching a human perform a task, instead of learning them in two separate stages.

Paper explainersAll themesRobotics & Control

A robot sees a human perform a task once and needs to copy it. Today's best approach learns what the human valued (the reward) in one step, then separately learns how to plan using that reward. This paper merges these into one process: the robot learns the reward and improves its plan at the same time, using actual trial-and-error with the planner, because when they train together, the discriminator feedback keeps both from drifting apart. The result: fewer failed attempts needed, and the learned reward stays honest even when the planner tries weird shortcuts.

Zero assumption version

Two separate learning steps don't talk to each other

Imagine a robot watches a human navigate a kitchen. The human avoids obstacles and reaches a shelf. Today's approach works in two isolated stages: first, learn what rewards (the numeric scores for each action) would make a human take those steps; second, once you have a reward, learn a planner (a procedure that looks ahead and picks the best sequence of moves). The trouble: the reward learned in stage one might be easy to game—the planner in stage two might find weird loopholes the human never took, because they were trained on different kinds of mistakes.

A beginner trying to copy this naively might hand-craft a reward (like 'reach the goal, avoid walls'), then train a planner. But a hand-crafted reward is brittle: it might score some unnatural shortcut higher than the real path, and the planner will take it instead.

The fix in one sentence. Train the reward and the planner together in a single loop, so the planner's real-world mistakes teach the reward what it got wrong.

The algorithm as a flow

What it actually does

Collect demo

Store the human's states and movements (observation-only).

Run current planner

Let the robot plan actions and execute them; record what the planner tried versus what the human did.

Train discriminator

Teach a judge to tell apart human moves from robot moves.

Update reward

Shift the reward function so it gives high scores to moves the judge thought looked human.

Improve planner

Retrain the planner on the updated reward; now moves that match the human will score higher.

What the paper changes

What the paper changes

Most learning methods train a reward function, then separately deploy a planner. This paper trains both at the same time, feeding the planner's real-world experience back into the reward learning loop.

The hidden quantity

The reward discrepancy

measured quantity  =  How often the robot's planned moves differ from the human's moves.

The paper measures something called the discriminator signal: how well a trained judge can tell a robot's move from a human's move. When the judge says 'this looks human,' the robot and human are aligned; when it says 'this looks robotic,' they diverged. This is a number between 0 and 1, where 0.5 means the judge is completely confused (the robot looks just like the human).

The paper uses this signal to update the reward function: if the judge easily spots a robot move, the reward was wrong, so the paper adjusts it. If the judge is stumped, the reward is doing well. The planner keeps improving because it is trained on the rewards coming from this feedback loop.

Why it works

Why merging the learning steps works better

Here is the chain: a robot learns a reward function and a planner together instead of separately. When the planner runs in simulation or the real world and makes a move, the discriminator checks if that move looks human. If it does not, the reward function is adjusted to make that move score higher. The planner is then retrained on the updated reward, so the next actions it generates are closer to human moves. This loop repeats.

This approach is better because a planner will find ANY path that scores high on the reward, even weird shortcuts that score well but look nothing like the human's path. If the reward is learned in isolation, it might score those shortcuts high because it was not trained on what the planner would actually try. By training the reward and planner together in a loop, the reward learns what counts as natural behavior specifically for this planner—the discriminator flags when the planner's moves look fake, so the reward adjusts. The planner then learns to operate under a reward that was tuned to match human behavior because that reward is updated after each trial. In contrast, a planner trained separately on a static reward has no feedback loop to correct its shortcuts, so it keeps taking them.

Math after the picture

The adversarial learning formula

First in words:

Maximize over the planner (minimize expected log-discriminator error on robot moves plus maximize expected log-discriminator error on expert moves), balanced against a KL divergence cost that keeps the planner from drifting too far from its previous version.

Then the compact form:

min_π max_D E_π[log(D(s,s'))] + E_πE[log(1−D(s,s'))] − λ·KL(π || π_prev)

Every symbol:

πthe planner (a way to pick actions that minimizes expected cost)
D(s,s')the discriminator (outputs 1 if it thinks the move is human, 0 if robotic)
E_πexpected value under the planner's current distribution of moves
E_πEexpected value under the expert's observed moves
λhow strongly to penalize big changes from the previous planner
KL(π || π_prev)divergence distance between current and previous planner (stays small and stable)
A tiny worked example
Suppose the discriminator says: 5 of 10 robot moves look human (D=0.5 on those), and 8 of 10 expert moves look human (D=0.8 on those).
Planner term: log(0.5) ≈ −0.69, ten moves: 10 × (−0.69) = −6.9. Expert term: log(1−0.8) = log(0.2) ≈ −1.61, ten moves: 10 × (−1.61) = −16.1.
Total: −6.9 − 16.1 = −23.0. If the new planner is very different from the old one, KL might add +8.0, giving −23.0 + 8.0 = −15.0 (worse). The update keeps planner change small and useful.
Intuition: minimize the gap between how often the discriminator marks robot vs expert moves as human. A small KL term prevents thrashing.

The formula pulls the planner and reward to align, because the discriminator signal tells the reward when the planner is drifting, and the KL term keeps the planner stable enough to learn from the updated reward.

What can go wrong

What can go wrong

Insufficient exploration. If the planner gets stuck in a local optimum early (e.g., circling the goal without reaching it), the discriminator never sees the human's true behaviors, and the reward stays wrong. The paper addresses this by using a planner that samples many diverse action sequences before picking, but it can still fail if the goal region is far away.
Noisy or ambiguous demos. If the human demo is short or contains sensor noise, the learned reward becomes brittle. The paper handles single-observation demos, but the learned behavior may generalize poorly if the demo is not representative.
Model mismatch. If the simulator's model of dynamics does not match the real robot, the planner trained in simulation may make moves that are unsafe or ineffective in the real world. The paper tests zero-shot sim-to-real but does not guarantee success.
Done right. Pair the unified learning with a planner that samples many action sequences and picks the best (Model Predictive Path Integral control), use multiple expert rollouts if available, and validate the learned reward on held-out expert data before deployment.
What a runnable demo should prove

What a runnable demo should prove

Build a simple 2D navigation task (e.g., a room with obstacles, a goal to reach). Collect one or two expert trajectories (human paths). Implement the unified learning loop: (1) run a random planner, (2) train a discriminator to tell expert from robot moves, (3) update the reward function, (4) retrain the planner. Run this for 5-10 iterations. Plot the discriminator accuracy over time and the robot's path each iteration.

discriminator_accuracy_on_test = (true_positives_on_expert + true_negatives_on_robot) / total_moves

As learning progresses, the discriminator should become more confused (accuracy drops toward 50%), which means the planner and expert are converging. The robot's path should visibly shift toward the expert's path by iteration 5.
