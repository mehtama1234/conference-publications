ShifTS: Tackling Time-Series Forecasting via Concept Drift

When forecasting the future of data that changes over time, ignore false patterns caused by shifting contexts, and latch onto real patterns that stay true across contexts.

Paper explainersAll themesTime Series & Sequential

A time-series forecasting model (a model that predicts future values given past data) works well on today's data. But real-world data changes: customer behavior shifts, weather patterns evolve, market trends turn. The model trained on old data makes worse predictions as time goes on, because the actual rule of the world has changed. ShifTS teaches a model to spot patterns that work across many different contexts, so it stays accurate even as the underlying rules shift.

Zero assumption version

Why forecasts go stale

A store has three years of sales data. It trains a forecasting model to predict tomorrow's sales. The model finds a pattern: 'When the weather is cold, people buy hot drinks.' But six months ago, a coffee shop opened next door. Now that pattern is broken — cold weather no longer predicts sales, because customers go to the coffee shop instead. The model keeps using the old pattern and makes wrong predictions.

Data scientists call this problem 'concept drift': the underlying pattern that the model learned has changed. There is also a related problem called 'temporal shift': the overall distribution of values shifts (sales were 1000 dollars per day on average, now 800 dollars per day on average). Most existing methods focus on temporal shift and ignore concept drift, leaving the model blind to the real problem.

The core issue. A model learns rules from past data, but those rules stop working when the world changes. Most methods only fix the overall number shift, not the broken rule itself.

The algorithm as a flow

What it actually does

Step 1: Identify both kinds of shift

Separate the problem into two pieces: temporal shift (the overall average changed) and concept drift (the rule changed).

Step 2: Fix temporal shift first

Normalize values so the average and spread stay the same across time periods. This prevents the model from learning 'the forecast is just half the old average' — a rule that breaks the moment the average changes.

Step 3: Find patterns that appear in both past and future

Use soft attention (a mechanism that learns which parts of the input matter most) to extract patterns that work across many different time windows.

Step 4: Upweight invariant features

Give more importance to features that stay predictive even as contexts change, and downweight features that were only useful in the old world.

Step 5: Retrain on both shifts handled

Train the model with these filtered features, so it learns rules that work everywhere instead of correlations that break when the world changes.

What the paper changes

The one thing that changes

ShifTS changes which features (input variables) the model gives more importance to when making a prediction. Attention means how much a model focuses on each part of the input; by changing attention, ShifTS teaches the model to focus on features that predict the output in multiple different time periods, and ignore features that only worked in one historical era.

the object it moves  =  Attention weights to input features
The hidden quantity

Invariance: patterns that stay true across contexts

measured quantity  =  Invariance of a feature

A feature is 'invariant' if it reliably predicts the output across many different time periods and contexts, not just in one era. For example, 'time of day' might predict whether a store is busy everywhere and always. But 'store layout' predicts sales only in the layout's current configuration — once you rearrange shelves, that feature stops working.

ShifTS measures invariance by checking: does this feature predict the target value in the lookback window (the past data we train on) AND in the horizon window (the future data we want to predict)? If yes, it is invariant. The soft attention mechanism assigns a high weight to invariant features and a low weight to context-dependent ones.

Why it works

Why tracking invariance fixes the drift problem

When the world changes, some of the features a model learned to trust become useless. A feature that worked perfectly in the past (like 'store layout') cannot predict the future if the layout changes. But other features are truly causal and work everywhere (like 'day of the week'). By measuring which features stayed predictive across multiple time windows, ShifTS identifies the truly causal features and downweights the brittle correlations.

The mechanism works in stages. First, the model normalizes away temporal shift (the overall level change), so it can focus on the rules. Then, soft attention looks at which input features have high correlation with the target in the past, and which ones have high correlation in a future window. Features that correlate well in both windows are invariant and get high attention weight. Features that only correlated well in the past lose weight. When the model trains with high-weight invariant features, it cannot learn the now-broken rule. Instead, it learns rules that generalize to the new context.

Math after the picture

The soft attention formula

First in words:

For each feature, compute how much it correlates with the target in the past window. Then compute how much it correlates in the future window. Raise these correlations to a power (temperature parameter). Combine them, then normalize so all feature weights sum to one. The result is an attention weight for each feature: high weight if it correlates in both windows, low weight if it only correlates in one.

Then the compact form:

attention_j = exp(temperature * (corr_past_j + corr_future_j)) / sum_i exp(temperature * (corr_past_i + corr_future_i))

Every symbol:

jindex of one feature
corr_past_jhow much feature j correlates with the target in past data
corr_future_jhow much feature j correlates with the target in future data
temperaturea parameter that controls how sharp the attention is (higher = more extreme)
attention_jfinal weight given to feature j, between 0 and 1
A tiny worked example
Suppose feature 1 (day of week) correlates 0.8 with target in past, 0.75 in future. Sum: 1.55.
Feature 2 (store layout) correlates 0.9 in past, 0.2 in future. Sum: 1.1.
Feature 3 (temperature outside) correlates 0.6 in past, 0.65 in future. Sum: 1.25.
With temperature=1, compute exp(1.55)=4.7, exp(1.1)=3.0, exp(1.25)=3.5.
Normalize: 4.7/(4.7+3.0+3.5) = 0.45 for feature 1; 3.0/11.2 = 0.27 for feature 2; 3.5/11.2 = 0.31 for feature 3.
Feature 1 (invariant) gets 45% weight. Feature 2 (drifted) gets only 27%. Model learns to trust invariant features.

Higher weight on invariant features means the model learns rules that work across contexts, not brittle correlations that break when the world changes.

What can go wrong

What can go wrong

Temporal shift dominates the problem. If the main issue is that the overall level changed (temporal shift) rather than the underlying rule (concept drift), then temporal shift normalization alone solves it. Soft attention has little to do, because there is no broken rule to ignore. In such cases, ShifTS performs similarly to simpler baselines. The extra cost of attention computation and feature selection yields no benefit when drift does not exist.
No stationary invariant features exist. If the data is changing so dramatically that no features stay predictive across contexts, then there is nothing invariant to find. The method requires at least some causal features that do not drift. If everything drifts, soft attention cannot rescue the forecast.
The future is truly unpredictable. ShifTS finds features that worked in the past and future training windows. If the actual test future is completely different from both, then the features identified as invariant may not actually be predictive. The method relies on the assumption that some patterns repeat; if the future is chaotic, no method will forecast well.
Done right. When concept drift is present, features that stayed predictive across multiple eras truly work everywhere. Upweighting them teaches the model to ignore correlations that break and learn rules that generalize.
What a runnable demo should prove

What a runnable demo should prove

Build a synthetic time series where (1) there is a true causal rule that never changes (e.g., feature A times 2 plus feature B always equals the target), and (2) there is a spurious correlation that drifts (e.g., feature C correlates with the target in year 1 but not in year 2, because the world changed). Train a naive model on year 1 data, a baseline method on year 1 data, and ShifTS on year 1 data. Then test all three on year 2 and year 3 data. The naive model and baseline should break down (they learned the spurious rule). ShifTS should stay accurate (it only trusted the invariant rule).

Generalization error ratio = (error on future / error on past), lower is better

The demo must show that ShifTS keeps forecasting accurate even as the world changes, because it learned only the rules that generalize across contexts.
