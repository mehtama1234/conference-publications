DualTimesField: Rethinking Time Series as Continuous-Time Trends and Events

Instead of forcing all time series data into one fixed grid or one mathematical form, DualTimesField splits the signal into two separate invisible pieces — smooth trends and sharp jumps — and learns them independently.

Paper explainersAll themesTime Series & Sequential

Time series data (stock prices, temperature, sensor readings over time) doesn't fit neatly into a single pattern. Some parts move smoothly, while others jump suddenly. Existing methods either lock the data to a rigid time grid or use one flexible formula for everything, and both hit limits. DualTimesField fixes this by treating the data as a mix of two different kinds of invisible patterns: one that bends smoothly and one that captures sudden changes. Learning them separately improves accuracy because each pattern requires different mathematical constraints to learn correctly, and it handles ragged data (readings that don't arrive on schedule) by working with continuous time instead of a fixed grid.

Why one recipe breaks down

Time series data is just numbers recorded at different times — a sensor reading every second, a stock price every minute, or rainfall every day. The naive approach locks these to a fixed time grid: you pick whether to sample every 1 second or 10 seconds, and fit everything to that schedule. If readings arrive at irregular times (a sensor hiccups and skips 30 seconds), you either discard them or guess their values. This throws away real information.

A newer trick uses a single mathematical formula (what researchers call an implicit neural representation — one flexible function that outputs the value at any time you ask). This works better than the grid, but it has a hidden flaw: when one formula tries to learn both smooth patterns and sharp jumps, the training process cannot determine which parts of the data deserve attention. The formula gets pulled in two directions — it must simultaneously smooth out the noise and sharpen up sudden changes — and the conflict means it treats high-frequency noise as real signal (a problem called spectral bias) instead of ignoring it, because the formula has no way to know that some frequencies are just measurement error.

The problem in one sentence. Both the rigid grid and the single-formula method fail because they force one solution onto two different types of patterns in the data: smooth trends and sudden events.

What the paper changes

DualTimesField changes what goes into the neural field — instead of one flexible formula trying to learn everything, it splits into two co-working formulas that each specialize in one job.

The hidden quantity

The hidden quantities being measured

measured quantity  =  Trend-event decomposition

The paper measures two things simultaneously: (1) How much smooth, low-frequency pattern lives in the data (the trend component), and (2) how many sharp, high-frequency blips occur (the event component). This decomposition is the key to accuracy — if you model trends and events separately, you can calibrate each one independently. The paper estimates this split using two different neural field formulas running in parallel, each producing its own piece of the reconstructed signal.

The continuous-time field (which learns trends) is constrained to use only a limited range of frequencies (bandwidth limitation), which naturally blocks it from chasing noise. The discrete geometric field (which learns events) uses Gabor atoms — mathematical bumps that are naturally sparse and localized in time — so it only turns on when a sharp change occurs. This mutual specialization is what makes the decomposition work.

DualTimesField decomposes the continuous-time implicit neural representation into two components: a bandwidth-limited Continuous Time Field (CTF) that captures smooth spectral content and a Discrete Geometric Field (DGF) using learnable Gabor atoms with gated sparsity to model transient events.
Why it works

Why this split works

The core insight is that smooth trends and sharp events are fundamentally different patterns, and forcing one formula to learn both creates a conflict: the formula cannot decide whether to chase high-frequency noise or stay smooth. By splitting into two formulas, each with its own rules, the conflict disappears.

The continuous-time field learns trends by restricting itself to a limited set of frequencies (bandwidth limitation). When you limit which frequencies a formula can produce, it physically cannot generate high-frequency squeaks or wiggles, so it naturally ignores noise and learns only the smooth, big-picture shape. The discrete geometric field learns events using Gabor atoms (short, localized bumps in time). Each Gabor atom turns on briefly when a sharp change happens, then turns off. Because these bumps are sparse (only a few turn on at once), the formula avoids wasting capacity on background noise. The coarse-to-fine scale annealing means the model first learns which times have events, then refines the exact shape of each event.

The reconstruction equation

First in words:

Total signal equals the trend field output plus the event field output. The trend field produces a smooth curve using only low frequencies. The event field produces a sparse sum of short bumps, each centered at a time where an event occurs. Training minimizes the error between the combined reconstruction and the real data.

Then the compact form:

y_reconstructed(t) = f_trend(t) + f_event(t) where f_trend uses bandwidth-limited frequencies and f_event = sum_k w_k * Gabor_k(t) with gating mask

Every symbol:

y_reconstructed(t)the predicted value at time t
f_trend(t)output of the continuous time field (smooth trends)
f_event(t)output of the discrete geometric field (events)
w_kthe learned strength of the k-th Gabor atom
Gabor_k(t)a short, localized bump centered near event time k
A tiny worked example
Suppose the real signal at time t=5 is y(5)=10. The trend field outputs 9.5, and one Gabor event atom contributes 0.6.
Reconstruction: f_trend(5) + f_event(5) = 9.5 + 0.6 = 10.1. Error = |10 - 10.1| = 0.1.
Now suppose at t=7 the trend predicts 8.0 and an event spike should add 1.5, so y(7) should be 9.5.
Reconstruction: 8.0 + 1.5 = 9.5. Error = |9.5 - 9.5| = 0. By separating trends and events, each part learns its job independently.

The equation says the full signal is the sum of one smooth pattern plus one sparse pattern, each learned by its own formula with its own constraints.

What can go wrong

What can go wrong

Trend field learns too much noise. If the bandwidth limit is set too wide, the trend field still captures high-frequency jitter. Fix: use a principled bandwidth choice (e.g., based on Nyquist frequency of known sensor limitations).
Event field ignores real signals. If sparsity is enforced too strictly, the Gabor atoms cannot activate for small but real changes. Fix: adjust the sparsity control (the gating threshold) so it blocks noise but keeps genuine events.
No separation happens; fields interfere. If the two fields are not properly regularized, both may try to learn trends or both try to learn events. Fix: add a regularizer that encourages trend field to use only low frequencies and event field to stay sparse.
Everything works right. When both fields respect their constraints and neither blocks the other, the decomposition succeeds and fidelity improves because the trend field has no way to capture event spikes (it only outputs smooth curves) and the event field has no way to drift smoothly (it only outputs sparse bumps), so each gets exactly the signal it should learn.
What a runnable demo should prove

What a runnable demo should prove

Build a simple time series: a smooth sine wave (the trend) plus a few sudden spikes at random times (the events). Train DualTimesField on this synthetic data. The demo should visualize: (1) the ground-truth trend overlaid with the model's learned trend field output (they should match almost perfectly), (2) the ground-truth events (the spike locations) overlaid with the sparse Gabor bumps (they should align), and (3) the combined reconstruction versus the original signal (error should be tiny, maybe 5% MSE).

MSE = mean((y_real - y_reconstructed)^2); trend_alignment = correlation(y_real - events, f_trend); event_alignment = number_of_correctly_detected_spike_times / total_events

The demo makes the separation impossible to miss: a split picture showing that trends and events are learned in completely different ways, and combining them gives a clean, high-fidelity signal.
