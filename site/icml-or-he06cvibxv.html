OmniVideo-R1: Reinforcing Audio-visual Reasoning

OmniVideo-R1 improves video reasoning by learning which parts of a question need audio, which need video, and how strongly each modality should influence the answer.

Paper explainersAll themesMultimodal

Video understanding is harder than image understanding because the answer may depend on synchronized evidence across sound and motion. A question about whether a person is calling for help, playing an instrument, or operating a machine cannot be solved by video frames alone or audio alone in many cases because one stream may show the action while the other stream confirms what event is actually happening. OmniVideo-R1 treats multimodal reasoning as two linked decisions: identify what the question is asking for, then assign more weight to the modalities that contain that evidence.

Zero assumption version

Mixed-modality questions fail when the model does not know which evidence source matters most

Omnivideo tasks mix several evidence types: visual actions over time, spoken words, background sounds, and their alignment. Existing systems often fuse these streams in a fixed way, which means they apply similar weight to audio and video across many questions even when the question strongly favors one modality.

That fixed treatment creates two failures. First, the model may look at the wrong source. A question about what sound occurred can be overwhelmed by visual motion. Second, the model may fail to combine the sources when both are needed. For example, identifying whether a visible instrument is actually being played requires both the motion and the sound. Good reasoning therefore needs query-dependent grounding and query-dependent fusion.

The problem: A multimodal video model needs to know not only what is in the streams, but which stream should dominate for this question and when the streams must be combined.

The algorithm as a flow

What it actually does

Encode audio, video, and question

The system starts with representations of the sound track, the visual frames, and the query.

Infer query intention

It estimates whether the question mainly depends on audio, mainly on video, or on joint evidence.

Ground the query in each modality

Self-supervised training teaches the model to align the query with informative regions or time segments without requiring full manual labels, where self-supervised means the training signal is built from the data itself rather than from hand-written answers at every step.

Fuse modalities with learned weights

Contrastive learning teaches the model to bring matching audio-video-query triples closer and separate mismatched ones, where contrastive learning means learning by comparing matching examples against non-matching examples.

Answer with reinforced multimodal reasoning

Reinforcement favors answer trajectories that use the right modality balance for the question.

What the paper changes

What the paper changes

The paper changes multimodal fusion from fixed combination to question-conditioned combination. It also trains an explicit query-grounding stage before fusion. Together, these changes make the model decide what kind of evidence the question requires before it decides how much each modality should contribute.

the object it moves  =  query-conditioned modality weighting
The hidden quantity

The hidden quantity: modality relevance

measured quantity  =  modality relevance

Modality relevance measures how useful each stream is for the current question. A question about a spoken phrase should assign high relevance to audio. A question about hand movement should assign high relevance to video. A question about whether the visible action matches the sound should assign high relevance to both.

This quantity matters because fusion is only correct if it matches the evidence demand. If audio and video are averaged in the same way for every question, one stream can dilute the informative one. OmniVideo-R1 therefore learns to estimate relevance first and use it to control fusion later.

Why it works

Why query intention and modality weighting improve audio-visual reasoning

The first mechanism is query-intensive grounding. The model learns to align the question with informative segments in each modality before final fusion. This helps because the system does not treat every frame and every sound segment equally; it narrows focus to the parts that could answer the query.

The second mechanism is modality-attentive fusion. Instead of using a fixed merge, the model estimates how much audio and video should contribute for this question. That improves answers because the more relevant stream is amplified and the less relevant stream is restrained, so noisy or distracting evidence has less influence on the final reasoning state.

The third mechanism is reinforcement over mixed-modality reasoning. Reinforcement trains from answer outcomes on sampled reasoning trajectories. If the model answers correctly by assigning strong weight to audio on sound-centric questions and joint weight on alignment questions, those patterns receive more credit. Over time, the policy learns a stable mapping from query intention to modality weighting.

Math after the picture

A plain fusion rule

First in words:

The final reasoning state is a weighted sum of audio and video evidence, where the weights depend on the question.

Then the compact form:

final_state = audio_weight * audio_evidence + video_weight * video_evidence

Every symbol:

final_statethe combined representation used to answer the question
audio_weighthow much the audio stream should influence the answer for this query
audio_evidencethe grounded information extracted from sound
video_weighthow much the video stream should influence the answer for this query
video_evidencethe grounded information extracted from frames
A tiny worked example
Question: Is the person playing the piano or only sitting near it?
Suppose the query grounding finds strong piano sound and visible hand motion on the keys.
Set audio_weight = 0.6 and video_weight = 0.4 because sound is slightly more decisive here.
If audio_evidence = 8 and video_evidence = 6, then final_state = 0.6 * 8 + 0.4 * 6 = 7.2.
If the question were only 'What instrument is visible?', the weights would shift toward video because the evidence demand changed.

The key idea is that the weights are not fixed properties of the model; they are outputs conditioned on the current query.

What can go wrong

What can go wrong

Query intention is misread. If the model decides a question is video-heavy when the answer depends on sound, fusion will amplify the wrong stream and the later stages cannot fully repair that mistake.
Grounding is temporally misaligned. If the audio segment and video segment selected for the question do not correspond to the same event, the fused state mixes unrelated evidence and produces unstable answers.
Contrastive training uses weak negatives. If mismatched examples are too easy to separate, the model may not learn fine distinctions about which modality pairing truly supports the query.
Done right: The model first identifies the evidence demand, then grounds each stream, then fuses them with query-dependent weights that reflect that demand.
What a runnable demo should prove

What a runnable demo should prove

Build a toy video dataset with three question types: audio-only, video-only, and joint audio-video alignment. For each clip, provide one correct audio track and optionally a mismatched track. Train one model with fixed fusion and another with learned query-conditioned weights. Measure answer accuracy by question type, whether the dominant modality weight matches the question type, and whether alignment questions fail when audio and video are intentionally mismatched.
