MRAD: Memory-Retrieval Anomaly Detection

Instead of training a classifier to recognize broken things, store real broken and normal examples in memory and directly look them up.

Paper explainersAll themesComputer Vision

Anomaly detection (spotting broken products or weird medical images) usually trains a model to learn what normal looks like, then flags anything different. But training can waste data and overfits. MRAD flips this: freeze the vision model, build a filing cabinet of real normal and abnormal examples, and at test time just ask the cabinet which real examples the new image looks most like.

Why training fails at anomaly detection

Anomaly detection means spotting the broken factory part or the weird medical scan when most of your examples are normal. A naive approach: train a classifier to recognize normal, and anything it scores low is anomalous.

But training a classifier needs good normal examples and good abnormal examples. In real factory floors, abnormal things are rare, expensive to label, and highly varied. Training a model on this unbalanced data causes overfitting—the model memorizes the specific broken parts it saw, but fails on new kinds of breaks from different factories or different angles. Also, each domain (medical imaging, electronics manufacturing, fabric defects) needs its own trained model.

The core trap. Training a model to fit the pattern of what is normal wastes data, overfits to the specific examples you label, and breaks on new domains.

The algorithm as a flow

What it actually does

Freeze the vision model

Use a pretrained image encoder (CLIP) that already understands images; do not retrain it.

Extract and store features

Feed normal and abnormal training images through the frozen encoder; save the numeric descriptions (features) plus labels.

Build a two-level filing cabinet

Store both global features (whole-image level) and local features (patch level, i.e. small regions).

At test time, compare and retrieve

Encode the test image, then measure similarity to all stored examples using weighted averaging that emphasizes the most similar ones.

Declare anomaly by vote

If the most similar stored examples are mostly abnormal, predict abnormal; else normal.

What the paper changes

What the paper changes

Instead of using a trained classifier (a set of weights that compress the pattern of normal), MRAD stores the raw features and labels of actual normal and abnormal examples in memory, and retrieves from this memory at test time.

the object it moves  =  A trained model replaced with memory lookup
The hidden quantity

The hidden quantity: similarity score

measured quantity  =  Feature-to-example similarity

The hidden quantity is the numeric score that measures how close the test image's feature is to each stored example. It is not a probability from a trained model, but a direct measurement of distance in the feature space: how far apart are two lists of numbers when you treat them as points in space.

The paper measures this as weighted similarity using a temperature-scaled scoring rule: examples that are close in the feature space get high weight, examples that are far away get low weight. This is not learned from training data—it is computed on the fly directly from the positions of the stored examples in the feature space.

Paper reading. The anomaly score sanom is a temperature-scaled weighted average that puts high weight on stored abnormal examples when they are similar to the query feature q, and low weight when they are far away. The weighting rule converts raw dot-product similarities into a set of fractions that sum to 1, so each stored example gets a fair share of the vote.
Why it works

Why memory retrieval works better than training

Training a classifier tries to compress the pattern of normal and abnormal into a single set of weights. This compression loses information: the weights must summarize thousands of images into a few numbers. But anomalies are rare and varied—a single pattern does not capture all the ways something can break.

Memory retrieval avoids compression: it keeps the raw data. At test time, it directly compares the test image to all real examples in storage. If the test image is similar to stored abnormal examples, it is declared abnormal. If similar to stored normal examples, it is normal. This makes the decision transparent (you can see which examples it matched) and avoids overfitting to the specific abnormal examples used in training, because the retrieval just looks for geometric closeness in the feature space.

Math after the picture

The retrieval similarity equation

First in words:

anomaly_score = softmax-weighted fraction of similar examples labeled abnormal

Then the compact form:

s_anom(q) = [softmax(q * K^T / tau) * V]_a

Every symbol:

qfeatures of the test image
Kstored features from training (normal and abnormal)
Vbinary labels (1 if abnormal, 0 if normal)
tautemperature parameter (higher = softer weighting)
[...]_aselects the abnormal channel (sum of weights for abnormal examples)
A tiny worked example
Suppose the test image q has features [0.5, -0.3]. There are 4 stored examples: K1=[0.4, -0.2] (normal), K2=[0.6, -0.4] (abnormal), K3=[0.5, -0.1] (normal), K4=[0.7, -0.5] (abnormal).
Compute dot products (q dot each K): q·K1=0.26, q·K2=0.42, q·K3=0.27, q·K4=0.50. (These measure raw similarity; higher = more aligned.)
Divide by temperature tau=0.5: scores become 0.52, 0.84, 0.54, 1.00. Apply softmax: roughly [0.1, 0.25, 0.1, 0.55]. (Softmax turns raw scores into fractions that sum to 1; higher original score gets higher fraction.)
Select abnormal weights: K2 gets 0.25, K4 gets 0.55, total = 0.8. So s_anom(q) = 0.80. (The anomaly score is the fraction of total weight assigned to abnormal examples.)
Conclusion: The test image most resembles the abnormal examples, so the model predicts anomaly with confidence 0.80.

Softmax weighting ensures that dissimilar examples contribute little to the final vote, so only the truly nearby examples in the filing cabinet matter.

What can go wrong

What can go wrong

Frozen feature space does not capture domain detail. If the pretrained CLIP encoder has not seen examples similar to your factory or medical domain, the feature space may not separate normal from abnormal well. MRAD still needs a pretrained model that has some overlap with your domain.
Memory is large and retrieval is slow. Storing thousands or millions of example features takes disk space and computing similarity to all of them at test time is slow. MRAD trades training cost for test-time cost: no training needed, but each test query must compare to the entire filing cabinet.
Imbalanced abnormal examples. If your stored abnormal examples are all similar to each other (e.g. only scratches, no dents), then a new kind of break that does not look like any stored example will be missed, because retrieval only finds examples that are geometrically close.
Lightweight fine-tuning if needed. If retrieval alone is not discriminative enough, MRAD-FT adds just two linear layers to learn a better similarity metric without retraining the backbone, because adjusting how the similarity is computed (by changing a small piece of the pipeline) can boost how well the top-k examples separate into normal vs. abnormal without throwing away the frozen pretrained model.
What a runnable demo should prove

What a runnable demo should prove

Build a memory-retrieval anomaly detector: (1) Pick a pretrained vision model (CLIP or similar). (2) Collect or download a small set of normal and abnormal images (e.g. a defect dataset like MVTEC-AD or a medical image dataset). (3) Extract features for all examples without retraining anything. (4) At test time, encode a new image and compute softmax-weighted similarity to all stored features. (5) Measure how many of the top-k most similar examples are abnormal; that fraction is your anomaly score.

accuracy = (true_positives + true_negatives) / total; false_positive_rate = false_positives / (false_positives + true_negatives)

The demo must show that retrieval achieves high accuracy on the training domain without any training (because the pretrained encoder already understands what is normal and abnormal), and generalizes far better to new domains than a trained classifier does, because the frozen feature space captures universal properties of normal vs. abnormal rather than domain-specific patterns.
