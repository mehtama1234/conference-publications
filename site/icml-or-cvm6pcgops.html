Fixing Vision-Language Models for Compressed Images

When images are squashed to save bandwidth, vision-language models fail not because of lost detail, but because they never learned to handle squashed images—and you can fix that part with a lightweight adapter.

Paper explainersAll themesComputer Vision

Vision-language models (systems that read text and images together) work great on pristine, full-size images. But in the real world, images get compressed to save bandwidth. A compressed image loses detail irreversibly, but it also looks distorted in ways the model has never seen during training. This paper asks: which part of the failure can we fix?

Zero assumption version

Vision-language models hit two walls with compressed images

A vision-language model reads an image and text together to answer questions or describe what it sees. It learns on clean, high-quality images. In the real world, images get compressed to fit through internet pipes. Compression reduces file size by throwing away detail and introducing visible artifacts—blurry edges, color banding, blocky patterns.

When you show a compressed image to a model trained on clean images, two things go wrong. First: the model truly cannot see details that were deleted by compression. Second: the compression artifacts (the blotchy patterns) look like nothing in the model's training data, so the model is confused and makes bad guesses even where detail still exists—because its internal weights were tuned by millions of examples of clean images, so when it encounters a new pattern (blocky JPEG artifacts), its computations produce confidence scores in the wrong places. A beginner might think: train on more detail-preserving compression codecs. But the real wall is that the model has no experience with any distorted images at all.

In one sentence. Add a lightweight adapter that teaches the model which codec and bitrate created each compressed image, so it can compensate for that specific distortion pattern.

The algorithm as a flow

What it actually does

Identify the codec

Use one-hot encoding to label which compression method and bitrate level created the image.

Embed the codec signal

Convert the codec label into a list of numbers via an embedding layer (a small lookup table that turns categories into lists of numbers), same as how text is converted to numbers.

Merge with the image

Add the codec numbers to the image's feature representation so the vision transformer sees both the image and its compression history.

Train with distillation

Use the clean-image features as a target, training the adapter to make the distorted features predict the same answer as if the image were pristine.

Test on unseen codecs

Apply the adapter to images compressed with different codecs and bitrates; it generalizes because it learned the pattern of compensation, not memorized specific artifacts.

What the paper changes

What the paper changes

The paper adds a small adapter module between the image and the vision transformer. The adapter takes two inputs: the compressed image and metadata (which codec, what bitrate). It outputs a modified version of the image's feature representation—the numbers the vision transformer reads—tuned to reduce the effect of compression artifacts.

the object it moves  =  image features (numbers representing what the model sees)
The hidden quantity

The generalization gap—what the adapter measures

measured quantity  =  Generalization gap (how much the model fails due to unfamiliar distortion)

When a compressed image is shown to a model trained on clean images, performance drops. The paper separates this drop into two parts. The information gap is the loss that can never be recovered—detail was deleted by compression, it is gone forever. The generalization gap is the extra loss caused because the model's vision encoder has never seen this type of distortion. Only the generalization gap can be fixed.

The paper estimates which gap is which by comparing the model's behavior on compressed images to its behavior on clean images, using multiple compression codecs. The hidden quantity is a simple subtraction: how much worse does the model perform on compressed images compared to clean, minus the amount of visual detail that was actually lost. That remainder is the generalization gap—the model's unfamiliarity with the distortion pattern. The adapter targets this gap by conditioning the encoder on the codec identity, so the features it produces are normalized for that specific type of squashing.

Why it works

Why the adapter works—the compensation loop

The vision transformer is a neural network that processes image features (lists of numbers representing each region). Compression artifacts distort these features in recognizable ways depending on the codec. JPEG produces blocky patterns. Modern learned codecs produce different kinds of blur. When the transformer sees these distorted features, it makes wrong predictions because its weights were optimized for clean features.

The adapter works by injecting codec metadata (which compression method, how aggressive) as additional input features. This tells the transformer: I am showing you a JPEG at bitrate 2, so here is a map of what JPEG distortions look like at bitrate 2. The transformer can then reweight its own computations to ignore or reinterpret the compromised regions. The transformer learns to say: I know this blotch is JPEG compression, not a real object boundary, so I will treat it differently. The training uses features from clean images as a target, so the adapter learns to make compressed-image features look like clean-image features after accounting for the codec.

Why does this generalize to unseen codecs? The adapter learns the general principle of codec compensation—that different compression methods create distortions in predictable ways—rather than memorizing specific artifacts. When it meets a new codec at test time, the embedding layer generalizes because it has learned a shared representation space where codecs with similar distortion profiles (e.g., similar blockiness) activate similar compensation circuits.

The distillation loss: teaching the encoder to forget the distortion

First in words:

Mean squared error between compressed-image features and clean-image features, weighted by codec condition embedding.

Then the compact form:

L_d = MSE(f_compressed_with_adapter, f_clean)

Every symbol:

f_compressed_with_adapterthe feature vector from the compressed image after the adapter modifies it
f_cleanthe feature vector from the clean version of the same image (the truth)
MSEmean squared error—average of squared differences between the two vectors
L_ddistillation loss—the penalty for diverging from clean features
Tiny numeric example
Clean image JPEG test: encoder outputs features [0.8, 0.6, 0.9, 0.7].
Same image compressed as JPEG bitrate 2: encoder outputs [0.5, 0.2, 0.4, 0.3] (confused by artifacts).
Adapter adds codec signal (JPEG + bitrate 2 embedding), reweighting to [0.75, 0.55, 0.85, 0.65].
MSE = (0.75-0.8)^2 + (0.55-0.6)^2 + (0.85-0.9)^2 + (0.65-0.7)^2 = 0.0025 + 0.0025 + 0.0025 + 0.0025 = 0.01.
Training reduces the penalty by learning weights that push compressed features closer to clean features.

The adapter learns to rotate and scale the compressed features so they sit in the same feature space as clean images, conditioned on the codec identity.

What can go wrong

What can go wrong

Overfitting to training codecs. If the adapter is trained on only JPEG and ELIC, it may not generalize to StableCodec or future codecs. The paper addresses this by testing on held-out codecs and using distillation (not just memorizing artifact patterns).
Codec metadata is unavailable at test time. In real applications, you may not know which codec was used or the bitrate. The adapter assumes this metadata is known; without it, you cannot invoke the right compensation. A fallback would be to auto-detect codec and bitrate from the image artifacts (possible but adds latency).
Some codecs have genuinely irreversible losses. Extreme compression (bitrate 0.1 bits per pixel) destroys information completely. No adapter can recover what was never transmitted. The generalization gap shrinks as information loss grows.
Done right: multi-codec training. Training on diverse codecs and bitrates, using distillation against clean features, teaches the adapter to learn general compensation principles rather than codec-specific artifacts. Testing on unseen codecs validates the generalization.
What a runnable demo should prove

What a runnable demo should prove

Download a small dataset (e.g., 100 images from COCO). Compress each image using three codecs (JPEG at multiple bitrates, ELIC at multiple bitrates, StableCodec at multiple bitrates). Run a pretrained vision-language model (Qwen-VL or InternVL3) on the compressed images and record accuracy on a simple visual question (e.g., object classification). Then train the codec-aware adapter on half the images (knowing the codec and bitrate), and evaluate on held-out test images with codecs not seen during adapter training. The demo must show two things: (1) baseline accuracy drops when images are compressed, and (2) the adapter recovery is larger than would be explained by random noise, and (3) the adapter works on unseen codecs (generalization is real).

Recovered accuracy = accuracy_with_adapter - accuracy_baseline_compressed. Generalization = 1 - (accuracy_on_unseen_codec / accuracy_on_seen_codec).

The decisive moment: run the adapter on a codec it never saw during training, and show that it still recovers 8+ accuracy points. That proves it learned compensation principles, not artifact memorization.
