An Information-Theoretic Criterion for Efficient Data Synthesis

Synthetic training data helps only when the generation loop receives new task-relevant information from outside the current model, and it generalizes best when that outside signal is coarse but correct.

Paper explainersAll themesSynthetic data generation

This paper asks a basic question: when does synthetic data actually teach a model something new? Its answer is strict. If a model keeps training on its own outputs without any outside check, the useful task information can only stay the same or shrink because the training loop is reprocessing what the model already knew. Synthetic data becomes valuable only when the loop is information-open, meaning an external judge (a verifier, environment, rubric, or other source of ground truth) inserts new evidence about what counts as a correct answer. The paper then argues that among those open loops, the most transferable supervision is often the coarsest one, such as a binary correct-or-incorrect signal, because that signal rewards the underlying requirement for success rather than one domain-specific wording or format.

Zero assumption version

Why synthetic data often helps once, then starts hurting

A model can produce unlimited new training examples, so it is tempting to keep sampling from the model, train on those samples, and expect steady improvement. That expectation fails because new text alone is not new information. If the next training round only sees outputs derived from the current model, then the next round cannot recover task facts that the current model already missed.

The paper separates two cases. In an information-closed loop, the model generates data and the same model family trains on it without any outside correction. In an information-open loop, some outside source checks the output or supplies a target, so the next round receives evidence the current model did not already contain. The difference matters because collapse is predicted in the closed case, while improvement is possible in the open case.

The core claim. Synthetic data is useful only when the training loop gains new task information from outside the current model, because otherwise the loop can only recycle or discard what it already knows.

What the paper changes

What the paper changes

The paper changes the criterion for judging a synthetic-data pipeline. Instead of asking only whether generated examples look plausible, it asks whether the loop introduces new task-relevant information and what level of supervision that information lives at.

the object it moves  =  the criterion that separates informative synthetic-data pipelines from self-copying ones
The hidden quantity

The hidden quantity: task-relevant information entering the loop

measured quantity  =  task-relevant information entering each training round

The central quantity is not the raw number of synthetic examples. It is how much new evidence those examples carry about the task. A million generated answers that merely restate the model's current habits add almost nothing, while a small batch of outputs checked by an external verifier can add a lot because the verifier marks which outputs satisfy the task and which do not.

The paper uses information theory, which is a way to measure how much uncertainty about the task is removed by an observation. If the only observation available to the next model is the old model's output, the next model cannot gain more task information than the old model already exposed. If an external correctness signal is attached, the next model can gain more because that signal distinguishes acceptable and unacceptable outputs in ways the old model may not.

Why it works

Why it works: improvement needs an external correction channel

The first mechanism is negative: a closed loop cannot manufacture new task knowledge because the next training set is a processed version of the current model's behavior. Any errors, omissions, or blind spots in that behavior are either preserved or amplified. The data processing inequality formalizes this because it says that once information passes through a channel, later processing cannot increase the information about the original target.

The second mechanism is positive: an open loop can improve because the external signal separates successful outputs from unsuccessful ones. That separation changes the mix of examples the next model trains on. The next model is no longer asked merely to imitate earlier text; it is asked to imitate text conditioned on survival under a correctness test. The paper then adds a second layer to the argument: coarse supervision often transfers better because it groups all acceptable outputs together. A binary correctness label does not care whether the answer used one domain's favorite wording, which means the model is pushed toward the underlying requirement for success. Fine-grained supervision can still help when the exact structure matters, but it also ties the learned behavior more tightly to the domain and format that produced the labels because the label now rewards one specific structure rather than the broader success condition.

The final mechanism explains reward hacking. Learning preferentially follows the easiest signal component that predicts reward because optimization keeps increasing whatever feature yields consistent objective gains. If the easiest feature is the intended one, training accelerates. If the easiest feature is a shortcut, the model locks onto the shortcut instead.

The equation: new training signal must pass through an outside channel

First in words:

The useful information in the next round is bounded by the information available in the current model's outputs unless an external supervision variable adds more.

Then the compact form:

task_info_next <= task_info_from_current_output + external_signal_info

Every symbol:

task_info_nexttask-relevant information available to the next training round
task_info_from_current_outputtask information already exposed by the current model's generated outputs
external_signal_infoadditional task information supplied by a verifier, environment, rubric, or other outside source
A tiny worked example
Suppose a math model answers 100 problems and gets 60 right.
Closed loop: train a new model on those 100 raw answers with no labels. The new model sees style, formatting, and many wrong answers, but it never sees which 60 were correct.
Open loop: attach a binary correctness label to each answer. Now the new model sees 100 outputs plus 100 bits of outside evidence about success.
If another domain uses different wording but the same success test, the binary labels still transfer because both domains share the same correctness rule.

The inequality is the paper's guiding rule: without an outside correction channel, the loop cannot gain fresh task signal.

What can go wrong

What can go wrong

The verifier can be wrong. An open loop still fails if the external judge attaches noisy or biased labels, because the model will faithfully learn the wrong criterion.
Coarse supervision can hide needed structure. A binary success signal may be too weak when the task requires a specific procedure or explanation, because many partially wrong outputs can share the same final outcome label.
The easiest feature may be the wrong one. Reward hacking appears when a shortcut predicts the supervision more cheaply than the intended skill, because optimization reinforces whichever feature earns reward with the least effort.
Done right. Use a reliable external judge, choose the coarsest supervision that still preserves the needed structure, and check whether the model improves on domains that do not share surface form because transfer under a wording shift is evidence that the model learned the success condition rather than one format.
What a runnable demo should prove

What a runnable demo should prove

Build two small synthetic-data loops for the same task, such as equation solving or code unit-test passing. In the closed loop, sample solutions from the current model and train the next model directly on those solutions. In the open loop, attach an external correctness label from a solver or test suite and train on the same solutions plus that label.

Run several training rounds and track accuracy on a held-out set plus a shifted set with different wording or format. The point is to show that the closed loop plateaus or declines because it never gains fresh task evidence, while the open loop improves because the verifier keeps injecting information about what actually counts as success.

open_loop_gain = heldout_accuracy_open / heldout_accuracy_closed ; transfer_gain = shifted_accuracy_open / shifted_accuracy_closed

The decisive result is improvement that survives a wording shift, because that shows the model learned the success criterion rather than only the generator's surface habits.
