IterResearch: Markovian State Reconstruction for Long-Horizon Agents

Instead of shoving everything into one growing memory, split the research task into repeated steps, each starting fresh with a condensed report from the last step.

Paper explainersAll themesAgents & Tool Use

Deep-research agents need to explore many sources and reasons over long chains of questions. Today they cram every fact and search result into a single, ever-growing text window until it becomes so cluttered that new information drowns in noise. IterResearch cuts this knot by treating research as a game with clear rounds: at each round, the agent condenses what it has learned into a tidy report, then uses that clean summary to plan the next round. This way, even after 2048 interactions, the agent's working memory stays clear.

Why one growing window breaks on long research

Imagine you are answering a hard question—say, how do solar panels fail in arctic climates? You start by searching for papers on ice buildup, then cold-stress failure, then salt fog, then materials science. Each search result lands in a single file. After 50 searches, the file is thick. After 200 searches, it is incoherent: early facts about ice are buried, new search results talk past old ones, and the agent cannot remember whether it already checked salt corrosion. The agent's thinking gets slower and more wrong.

Humans would do something smarter: every hour, stop and write a summary—what we know so far, what gaps remain—then throw out the raw notes and continue from the summary. This keeps the mind clear.

The core problem. A single memory that grows without reset fills with noise and contradictions, making reasoning worse the longer the task runs.

The algorithm as a flow

What it actually does

Step 1: Explore and collect

Agent searches for facts and sources, storing raw results, because new information must be gathered before it can be condensed.

Step 2: Synthesize into a report

Stop and condense raw findings into a clean summary of key insights and open questions.

Step 3: Discard raw details

Drop the messy notes. The report becomes the new memory.

Step 4: Plan the next round

Based on the summary, decide which questions to explore next.

Step 5: Repeat until done

Each new round starts with a clean summary, enabling reasoning at any depth.

What the paper changes

What the paper changes

IterResearch changes how an agent organizes its memory. Instead of one endless list, it cycles between collecting raw facts and writing a condensed report that becomes the new starting point.

The hidden quantity

The hidden quantity: clear reasoning span

measured quantity  =  reasoning span

The hidden quantity is the reasoning span—how many steps the agent can think through before confusion sets in. In a mono-contextual system (one window that grows forever), the span shrinks as the window fills with noise. In IterResearch, the span stays constant because each cycle resets to a clean report. The paper measures this implicitly: the jump from 3.5% to 42.5% accuracy at 2048 interactions shows that reasoning span was preserved even after hundreds of cycles.

The paper does not name or measure this quantity directly, but the mechanism depends on it. Each periodic synthesis is an active decision to reset the span—to throw away noise and start fresh.

Why it works

Why the cycle works

The key is that summaries compress. A report that says 'ice buildup is the primary failure mode in arctic, but thermal stress also matters' is far shorter than the raw text of ten papers. A short summary keeps the agent's working memory low-overhead, so new search results stand out instead of drowning in noise.

Second, periodic synthesis forces reflection. Before writing a summary, the agent must ask itself: what do I actually know? What gaps matter? This reflection directs the next round of exploration. Without periodic checkpoints, the agent wanders—searching for whatever looks interesting in the clutter rather than pursuing a coherent line of reasoning.

Third, reformulating as a Markov Decision Process means each round is independent: the agent's decision about what to explore next depends only on the current report (the state), not the entire history. This independence unlocks scaling. After 2048 interactions, the agent is still solving a fresh decision problem based on a clear state, not drowning in thousands of words of tangled history.

The Markov Decision Process formulation

First in words:

At each step t, the state is the current report, the agent chooses an action (which question to explore next), receives a reward based on progress, and transitions to a new report in step t+1. The key insight is that the transition depends only on the current report and action, not the full history.

Then the compact form:

P(report_t+1 | report_t, action_t) = synthesize(collect(action_t))

Every symbol:

report_tthe summary at step t (the state)
action_twhich query or source to explore next
collect(action_t)raw results from executing the action
synthesize(...)compress collected results into a short report
P(...)probability of reaching the next state
A tiny worked example with two cycles
Cycle 1: Agent explores 'arctic solar failures'. Raw results: 8 papers, ~30 pages of text.
Synthesis: Compress into report, ~2 pages: 'Ice buildup is primary; thermal stress secondary; materials data sparse.'
Cycle 2: Based on report, agent explores 'materials science arctic materials'. Without reset, raw state would be ~30 + ~30 = ~60 pages + clutter.
With reset: state is just the ~2-page report + new ~30 pages = ~32 pages, clear signal.
Result: Agent can focus on the new question instead of re-reading old facts or losing the thread.

Each cycle resets the state to a compressed report, so the agent's working memory stays bounded even after many cycles.

What can go wrong

What can go wrong

Poor synthesis loses important details. If the summary is too terse or misses key distinctions, the agent will make worse decisions in later cycles. Example: summarizing 'ice and thermal stress both matter' as just 'ice matters' sends the agent down a tunnel.
Synthesis itself is expensive. Writing a good summary requires reading and reasoning over all the raw facts—a cost. If you reset too often, you spend more time summarizing than exploring. The paper addresses this with a learned policy that knows when to reset.
Timing synthesis too late gives no benefit. If you wait until the context is already huge before synthesizing, you have already lost clarity. The timing of when to reset must match the task—reset too soon and you waste effort, too late and you have already drowned in noise.
Done right: continuous synthesis cycle. The paper learns when to synthesize using a reinforcement learning framework (EAPO) that rewards efficient exploration. This automates the timing decision.
What a runnable demo should prove

What a runnable demo should prove

A demo should show that periodic synthesis preserves clarity across cycles. Run a deep-research task that requires many steps: e.g., answering a complex multi-part question like 'what are the key trade-offs in arctic solar power deployment?' Set it to run with and without periodic synthesis. Measure reasoning accuracy (or a proxy: does the final answer address all parts of the question?). The demo should show that accuracy stays high in the IterResearch version even as step count climbs, while it decays in the mono-contextual baseline.

accuracy_loss = (accuracy at step 10) - (accuracy at step 100)

If IterResearch is working, the accuracy loss should be small (agent reasons just as well at step 100 as at step 10), while mono-contextual systems show large loss (accuracy falls as steps accumulate).
