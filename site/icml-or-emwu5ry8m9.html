NOMAD: Lifelong Trajectory Planning via Memory-Adaptive Diffusion Experts

A self-driving system remembers how it solved past scenarios and learns from new rare situations without forgetting what worked before.

Paper explainersAll themesRobotics & Control

Self-driving cars face a hard trade-off: they must adapt to unexpected scenarios they have never seen before, but they also must not forget how to drive safely in normal traffic. NOMAD solves this by storing memories of past driving decisions, growing new expert skills as rare scenarios arrive, and replaying old memories to keep learned behaviors from eroding.

The stability-plasticity dilemma in autonomous driving

A self-driving car trained on normal highway scenes can navigate bumper-to-bumper traffic with learned reflexes. But when it encounters a rare edge case—a traffic jam caused by a broken traffic light, a school bus stopping unexpectedly, a flooded underpass—it freezes because it has never seen that pattern before. If you retrain the car on the new scenario to teach it how to handle such cases, something worse happens: its old driving knowledge erodes, and it now drives badly in normal traffic. This is the stability-plasticity trade-off: you cannot have both constant learning and stable memory.

A naive approach: collect every edge case into one giant dataset and train a single model on everything. This fails because the rare cases are drowned out by the overwhelming volume of normal driving examples. The model optimizes for the common cases and forgets what the rare ones look like. Alternatively, you could freeze the old model and add a separate new model for each edge case, but this explodes memory cost and makes real-time decisions slow—you would need to run dozens of models at once, which is not practical on a car.

What the method does in one sentence. NOMAD stores past driving decisions as memories, routes new driving situations to the right learned expert, and replays old memories while learning new ones so old skills do not fade.

The algorithm as a flow

What it actually does

Encode the scene

Convert current traffic snapshot (positions, speeds, road layout) into a numerical description.

Match to nearest memory cluster

Find which past scenario type this scene resembles most; if no cluster is close enough, create a new one.

Activate the right expert

The diffusion model uses the matched cluster as a label and generates trajectory choices trained on similar past scenes.

Retrain with replay

Simultaneously, regenerate examples from old memory clusters and retrain on them, preventing erosion of old skills.

Choose the trajectory

Rank the diffusion outputs by safety and efficiency, pick the best one, and execute the drive.

What the paper changes

The single thing the method changes

NOMAD changes how the trajectory expert is organized. Instead of a single massive model, or a collection of separate rigid rule-based controllers, the method grows a set of diffusion-based experts. Each expert is trained by examples from a specific cluster of scenarios (e.g., one expert for normal highway flow, one for gridlock, one for rain-slick roads). When a new driving situation arrives, the method routes it to the expert whose training examples most closely resemble it, or creates a new expert if none fit well enough.

The hidden quantity

The hidden quantity: memory cluster similarity

measured quantity  =  Scene-cluster distance

The core hidden quantity is how close the current driving scene is to each stored memory cluster. This is not a distance you directly observe in the raw data; instead, it is computed by measuring how much the scene's numerical description overlaps with the stored prototype for each past scenario type. A small distance means the new scene is 'like' a past situation, so the expert trained on that past situation will do well.

NOMAD estimates this distance using Bayesian probability: it assigns each new scene to the cluster most likely to match it, and if no cluster is probable enough, the system creates a new cluster. This is a key move because the distance directs the entire learning: if the same scene keeps appearing, it stays in the same cluster and the expert grows more confident. If a wholly new scene arrives, it spawns a fresh cluster and expert.

Why it works

Why it works: the causal chain

The stability-plasticity trade-off happens because learning from new rare scenarios inevitably overwrites the weights that were good for common scenarios. NOMAD breaks this cycle by separating the experts. When a new edge case arrives, instead of retraining the old global model (which would unlearn normal driving), the system either finds an existing cluster that resembles the edge case or creates a new cluster, then trains an expert specialized for that cluster. The old expert for normal highway driving stays untouched.

But separation alone is not enough; the system would still lose old knowledge over time if those old experts never see new data. NOMAD adds generative replay: while training the new expert on the edge case, the method simultaneously reconstructs pseudo-examples from the memory clusters trained on normal driving and retrains the old experts on those reconstructed examples. This is the mechanism that prevents the old skills from eroding. Because the old examples are 'replayed' alongside new learning, the old experts see constant reinforcement, and their learned decisions persist.

Finally, the Bayesian memory routing ensures that each new scene is answered by an expert that has seen similar scenes before. If the scene is a known type (gridlock, heavy rain), the distance is small, and the matching expert fires immediately. If the scene is anomalous, the distance is large to all clusters, so a new cluster is created, and a fresh expert is trained on just the new behavior. This ensures low-dimensional focus: each expert does not have to memorize the entire diversity of driving, only the slice it specializes in.

Math after the picture

The core equation: weighted learning with memory

First in words:

For each scene, the method assigns it to the cluster with highest probability, then trains the cluster's expert while simultaneously replaying old examples weighted by their cluster probability.

Then the compact form:

loss = L_new(theta_k, D_new) + alpha * sum_m p(C_m | scene) * L_old(theta_m, D_replay_m)

Every symbol:

losstotal error for this learning step
L_new(theta_k, D_new)error of expert k on new scenario data D_new
theta_kweights of the expert assigned to cluster k
alphahow much weight to give to replayed old examples, typically 0.3 to 0.7
sum_msum over all m old clusters
p(C_m | scene)probability that the current scene belongs to cluster m
L_old(theta_m, D_replay_m)error of expert m on replayed pseudo-examples from cluster m
D_replay_msynthetic old examples regenerated from cluster m's distribution
A tiny worked example
Suppose we see a gridlock scene. Cluster 1 (normal highway) has probability 0.1. Cluster 2 (gridlock) has probability 0.8. Cluster 3 (rain) has probability 0.05.
Loss on new gridlock data: L_new(theta_2, D_gridlock) = 0.5 (the expert for gridlock learns this new gridlock well, error is low).
Replay loss: for highway, L_old(theta_1, D_replay_highway) = 0.3 (replayed highway examples are reasonably predicted). For rain, L_old(theta_3, D_replay_rain) = 0.4.
Total loss = 0.5 + 0.5 * (0.1 * 0.3 + 0.8 * 0.05 + 0.05 * 0.4) = 0.5 + 0.5 * (0.03 + 0.04 + 0.02) = 0.5 + 0.045 = 0.545.
The gridlock expert (cluster 2) gets a strong training signal because p(C_2 | scene) is high (0.8). The highway expert (cluster 1) also gets a small refresh via replay weighted by p(C_1 | scene) = 0.1, preserving its old skill.

The equation shows the balance: train the matched expert hard on new data (first term), and retrain all old experts softly on their remembered examples (second term weighted by cluster probability).

What can go wrong

What can go wrong

Cluster boundaries are wrong If the Bayesian distance metric is poor, a new scene might be assigned to the wrong cluster, and the old expert for that cluster will receive contradictory training signals. Result: the wrong expert tries to adapt, and both old and new performances drop.
Generative replay reconstructs false memories If the pseudo-examples created during replay do not actually resemble the real old scenarios, retraining on them teaches the old expert garbage, erasing old knowledge anyway. This is especially likely if the memory clusters are poorly separated.
Too many clusters blow up cost If the system creates a new cluster for every slightly different scene, the memory grows without bound, and real-time decision time becomes too slow because the method must evaluate every expert in sequence.
Done right Use careful settings in the Bayesian clustering so that genuinely new scenarios spawn fresh clusters, but similar variations merge into existing ones. Monitor the generative replay to ensure reconstructed examples are faithful to past behavior. Cap the number of active experts by merging the smallest, least-visited clusters periodically.
What a runnable demo should prove

What a runnable demo should prove

Build a simulation with three driving scenarios: (1) normal highway flow, (2) gridlock, (3) rain-slick roads with reduced traction. Start by training a single expert on normal highway. Then, without any replay mechanism, introduce gridlock data and retrain. Measure the performance on all three scenarios before and after. You will see highway performance drop because the weights that worked for highway get overwritten. Next, repeat the experiment with NOMAD: train the highway expert, then introduce gridlock while activating generative replay. Measure all three scenarios again. The key demo result: highway performance stays high (or improves because replayed highway examples give the highway expert fresh training signals alongside the new gridlock expert), gridlock performance is strong, and rain performance does not degrade because no expert was forced to unlearn.

backward_transfer = (normal_perf_after_training_on_new - normal_perf_before) / normal_perf_before. A positive value means learning the new task improved the old one.

The demo must show that continual learning on a new scenario does NOT erase old skills; in fact, it can reinforce them.
