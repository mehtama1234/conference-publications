Multimodal Time Series Anomaly Detection with Semantic Alignment

Catch anomalies in sensor data by reading the numbers together with the text descriptions that explain what is happening.

Paper explainersAll themesTime Series & Sequential

Real-world systems like power grids or manufacturing equipment produce time series—streams of numbers recorded over time—but they also come with text descriptions: log files, notes from operators, maintenance records. Today's anomaly detection (finding when something has gone wrong) only looks at the numbers, ignoring the text entirely. This paper proposes MindTS, a model that reads both the numbers and the text at once, aligns their meanings, and learns which signals matter by filtering out the noise in the text. The result is more reliable anomaly detection because the model now understands the context in which readings occur—it can tell whether an unusual number is explained by something benign (scheduled maintenance) or is truly an alarm.

Zero assumption version

Anomaly detection on numbers alone misses the context

A power plant records thousands of sensor readings every minute—temperature, pressure, flow rate. An anomaly detector (a model trained to recognize when something is wrong) looks at these numbers and learns what normal looks like, then flags readings that are very different. But the plant also keeps text logs: operator notes, equipment maintenance records, weather alerts. These logs often explain WHY a reading is the way it is.

The naive approach reads only the numbers, so it cannot distinguish between a reading that is odd but explained (a sensor gave a weird value because it was recalibrated this morning) and a reading that is truly dangerous (the same weird value with no explanation). The model wastes effort on false alarms and misses real problems that happen to have text clues in the logs.

The core problem. A single stream of numbers cannot capture the full story when text descriptions are available.

The algorithm as a flow

What it actually does

Read the numbers and text together

For each time step, both the sensor reading and the corresponding text description enter the model.

Align the semantics

The model learns to match concepts from the text with patterns in the numbers—e.g., the text mentions maintenance, the numbers show expected drift.

Condense the text

A content condenser throws away text that does not help explain the numbers, keeping only the informative parts, because including irrelevant text would confuse the anomaly detector and raise false-alarm rates.

Fuse the two streams

The filtered text modality and the numbers are merged via cross-modal reconstruction, so the model learns from both at once, because jointly training on both signals lets them correct each other—numbers constrain text interpretation, and text guides number interpretation.

Detect anomalies

The combined signal is scored: high scores flag readings the model thinks are anomalous.

What the paper changes

What changes: the alignment bridge

Normally, anomaly detection looks at numbers only. MindTS adds a second path: it reads the text and learns to say which parts of the text explain which parts of the number stream. It then uses this alignment to decide which text signals to keep and which to discard, so the fusion of numbers and text is based on real explanation, not noise.

the object it moves  =  alignment between text and numbers
The hidden quantity

The hidden quantity: semantic coherence

measured quantity  =  semantic coherence (how well text explains the numbers)

The paper measures a hidden quantity: for each time step, how coherent is the text with the number readings? A high coherence score means the text provides a good explanation for what the numbers show. Low coherence means the text is noise or irrelevant.

The model learns this by training a cross-modal alignment mechanism: it compares the text embeddings (a list of numbers representing the meaning of the text) with patterns in the sensor readings, scoring their agreement. This score is then used by the content condenser to keep only the high-coherence text signals when fusing the two modalities.

Why it works

Why it works: two modalities correcting each other

The trick is that numbers and text have different strengths. A number stream can capture what is happening (a pressure spike) but not why. Text can capture the context (a filter was replaced today) but is sparse and might miss fine timing. By measuring how well the text semantically aligns with the numbers, the model learns to use text as a guide to interpret the numbers and to ignore text that does not align—cutting out noise.

When text has high coherence with the numbers, the model learns to trust it and let it influence the anomaly score. When text is incoherent (the log says pressure is steady but the number spikes), the model learns to suppress it. Cross-modal reconstruction forces the two streams to co-adapt: the numbers learn to be explained by the text, and the text learns which details matter to the numbers. The result is a richer signal: anomalies are easier to spot because the model now knows the context in which they occur.

Math after the picture

The formula for semantic alignment and filtering

First in words:

The anomaly score is the sum of the weighted number readings plus the cross-modal term. The weight for each text signal is based on how well it aligns with the number stream; low-alignment signals are suppressed. When text and numbers agree, the fusion term amplifies the signal; when they disagree, it dampens it.

Then the compact form:

anomaly_score = sum_i (x_i) + lambda * sum_j (align_j * text_j * x_j)

Every symbol:

x_ithe value of sensor i at this time step
align_jsemantic alignment score for text signal j (higher means text explains the numbers better)
text_jthe content of text signal j (encoded as a number)
lambdastrength of the cross-modal term; higher means text influences the decision more
A tiny worked example
Time step t: sensor readings x1=2.5 (temp), x2=3.1 (pressure).
Text: Pump serviced. Alignment score align_j=0.8 (text explains the readings well).
Base anomaly score: 2.5 + 3.1 = 5.6 (moderately high).
Cross-modal term: lambda=0.5, text_j=1.2, so 0.5 * 0.8 * 1.2 * 2.5 = 1.2 boost.
With alignment: 5.6 + 1.2 = 6.8. But if align_j=0.1 (text does not explain readings): 5.6 + 0.5 * 0.1 * 1.2 * 2.5 = 5.75 (almost no change). Low-alignment text is filtered out.

The alignment score acts as a gate: only text that semantically explains the numbers gets to influence the final anomaly decision.

What can go wrong

What can go wrong

Misaligned text dominates. If the alignment mechanism is poorly trained, it might give high coherence scores to text that does not actually explain the numbers. The model then trusts the wrong signals, and anomaly detection gets worse. Fix: train the alignment module with a clear objective that measures how well text and numbers actually correlate.
Sparse or missing text. If the text logs are sparse (many time steps with no text, or just generic notes), the model has little to align with the numbers. The cross-modal term vanishes, and performance reverts to the baseline. The method works best when text is dense and informative.
The content condenser throws away useful signals. If the condenser is too aggressive (filters out too much text), the fusion loses valuable information. If it is too lenient (keeps all text), the model is back to reading noisy text. The balance depends on how much text is actually related to anomalies in this dataset.
Done right: text and numbers improve each other. Train the alignment module end-to-end so it learns which text signals correlate with number patterns. Validate the condenser by measuring how many true anomalies are explained by the retained text. Tune lambda so that text has the right strength—neither overwhelming the numbers nor disappearing into the background. Test on data where text is dense and relevant.
What a runnable demo should prove

What a runnable demo should prove

Build a synthetic multimodal dataset: time series (e.g., 3-4 sensor streams) and paired text descriptions for a fraction of the time steps. Embed the text (using a standard text encoder like BERT, which turns words into numbers), train MindTS end-to-end, and compare its anomaly scores against a baseline that reads only the numbers. Run the content condenser to show which text signals are kept and which are filtered out. Plot the kept signals against the sensor anomalies to visually verify that semantic alignment is working: text that is kept should correlate with anomalies.

precision = correct_anomalies / (correct_anomalies + false_alarms); recall = correct_anomalies / (correct_anomalies + missed_anomalies); F1 = 2 * (precision * recall) / (precision + recall)

The demo must show that (1) semantic alignment successfully separates useful text from noise, (2) the fused model's F1 score beats the number-only baseline, and (3) the patterns of kept text make intuitive sense (e.g., maintenance notes align with pressure readings).
