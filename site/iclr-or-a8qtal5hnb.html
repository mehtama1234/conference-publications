When Style Breaks Safety: Defending LLMs Against Superficial Style Alignment

LLMs forget their safety training when prompted with certain formatting styles, even if those styles have nothing to do with the harmful request, and the paper shows how to fix this by training on style-matched safety examples.

Paper explainersAll themesAlignment, Safety & Fairness

A language model trained to refuse harmful requests can be tricked by simply changing how the request is formatted (like asking for a list instead of a paragraph). This happens because the model learns to associate certain styles with the instruction-following data it saw during training, making it more willing to follow instructions in those styles—even unsafe ones. SafeStyle fixes this by adding safety training examples in the same format mix (lists, prose, etc.) that the model was originally trained on.

Zero assumption version

Safety training misses a blind spot: formatting style

When you train a language model to refuse harmful requests, you teach it through examples: here is a harmful request, here is the safe refusal. But those examples have a formatting style—they might be written as paragraphs, or lists, or Q&A pairs. During this safety training, the model learns not just to refuse harmful content, but also learns that this particular style is trustworthy instruction-following data.

Here is the problem: the model also learned its original general ability from instruction-following data that had its own dominant styles (certain teams use lists more often, others use prose). When someone later tries to jailbreak the model, they can exploit this by asking the harmful question in the style the model saw most often during its original training. The model sees that familiar style and trusts it more, even though the actual request is the same malicious one it was trained to refuse.

In one sentence. Models can be jailbroken by changing the formatting style of a harmful request to match the format mix (lists, prose, etc.) they saw most often during their original instruction training, bypassing safety training.

The algorithm as a flow

What it actually does

Measure style inflation

Run jailbreak attacks on models, counting how often reformatting the request increases success.

Find which formats appear most

Look at the model's original instruction-training data, see which formats (lists, paragraphs, etc.) appear most.

Observe the overlap

Find that safety inflation happens most in the styles that appeared most in instruction training.

Create matched safety examples

Take safety-training examples (refusals) and rewrite some in each format to match how often each format appeared in original training.

Fine-tune with the matched data

Train the model on these new style-balanced safety examples, anchoring refusal across all formats.

What the paper changes

The one thing the paper changes

The paper changes the composition of the safety-training data: instead of safety examples in mixed styles, it creates safety examples whose format mix (lists, prose, tables, etc.) exactly matches the format mix in the original instruction-training data. This way, when the model learns to refuse, it learns to refuse across all the styles it considers familiar.

the object it moves  =  safety-training data composition
The hidden quantity

The hidden quantity: attack success rate inflation from style

measured quantity  =  ASR inflation from style patterns

The paper introduces a specific quantity it measures: attack success rate (ASR) inflation, which is how much more often an attack succeeds simply by changing the formatting style of the same harmful request. For example, if a harmful request fails 20% of the time normally but succeeds 60% of the time when formatted as a list, the inflation is 40 percentage points. This inflation reveals which style patterns are holes in a model's safety alignment.

The paper estimates this by running jailbreak benchmarks on 32 models and noting which style changes move the success rate up. It then looks at the model's instruction-training data to find that the styles with the biggest inflation are exactly the styles that appeared most in the original training. This finding shows the real problem: the model learned to trust those styles during its initial instruction training, and safety training failed to override that trust.

Why it works

Why it works: learning safety across the full style space

The core reason SafeStyle works is this: when a model sees safety examples, it learns two things at once—what to refuse (the semantic content) and in what style context that refusal is valid. If all the safety examples are in one style (like mostly prose), the model learns that refusal applies in prose contexts. But when an attacker changes the style to match the format mix the model originally trusted during instruction training, the model has never seen a refusal example in that style, so it falls back to its original instruction-following instinct.

SafeStyle fixes this by creating refusal examples in all the styles the model was originally trained to trust. Now when the attacker reformats the request, the model has already seen refusals in that style and knows how to respond safely. The style patterns no longer secretly give the attacker an advantage.

Math after the picture

The balance equation: matching the format mix

First in words:

For each style S in the original instruction-training data with frequency P(S), create or augment safety-training data to match that frequency. The goal is to minimize the divergence between the style distribution of the safety data and the style distribution the model learned to trust.

Then the compact form:

D_KL(P_instruction_styles || P_safety_styles) → 0

Every symbol:

P_instruction_stylesthe probability distribution of style patterns in the original instruction data
P_safety_stylesthe probability distribution of style patterns in the safety-training data
D_KL(...)a measure of how different two distributions are (if they match, this is zero)
A tiny worked example
Original instruction data: 60% lists, 30% prose, 10% tables.
First safety data: 20% lists, 70% prose, 10% tables.
Distribution mismatch: the model learned to trust lists but safety barely used them.
SafeStyle augmentation: rewrite some prose examples as lists until we have 55% lists, 35% prose, 10% tables.
Now the divergence is much smaller—the model sees refusals in the styles it was trained to trust.
Attack that reformats as list: model has seen many refusals as lists, refuses safely.

The equation is an information-theoretic way of saying: make the safety data look like the data the model originally trusted.

What can go wrong

What can go wrong

Instruction data is not uniform. If the instruction-training data's format mix is hard to measure or changes across different training phases, matching it perfectly becomes impossible. The paper assumes you can measure or approximate this format mix.
New styles outside the original training appear. If an attacker uses a style format the model never saw during instruction training (e.g., an emoji-based prompt format the model has never encountered), SafeStyle cannot defend against it because it only matches the styles the model was originally trained on.
Rewriting breaks semantic meaning. When you rewrite a safety example to match a different style, there is a risk of changing the meaning slightly, making the refusal less clear or the harmful request more persuasive in that new style.
Done right. The paper shows SafeStyle works across three different models and six different style settings, and consistently outperforms baselines, because when safety examples are written in all the formats the model trusts, the attacker has no secret format advantage to exploit.
What a runnable demo should prove

What a runnable demo should prove

Build a small language model (or use a prompt in a larger one) trained on instruction-following data where 70% of examples are formatted as lists and 30% as prose. Create a set of harmful requests and their refusals. First, train the model to refuse using safety examples that are 90% prose (the mismatch). Then run jailbreak attacks by reformatting requests as lists and measure attack success. Second, retrain with SafeStyle using 70% list and 30% prose refusals. Run the same attacks again and measure the drop in success rate. The demo should make it impossible to miss that a format-mix mismatch is a real safety hole, and matching the formats closes it.

safety_gain = (attack_success_before - attack_success_after) / attack_success_before

When the safety examples match the format mix the model learned to trust, the attacker no longer gains an advantage by reformatting.
