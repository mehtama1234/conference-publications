RAG4DMC: Retrieval-Augmented Generation for Missing Modality Completion

When a dataset has images without text or text without images, use retrieval to find similar complete examples from other data, then let the generative model learn from those examples to fill in the blanks.

Paper explainersAll themesGenerative Models & Diffusion

A multi-modal dataset is one where each item has multiple pieces of information—an image and a text caption, for example. In the real world, these datasets are messy: sometimes the image is there but the text is missing, or vice versa. Directly asking a generative model (a neural network trained to create new data) to guess the missing piece often fails, especially when the dataset is small or the model's API is restricted. RAG4DMC solves this by retrieving similar complete examples from a knowledge base before asking the generative model to complete the missing piece.

The incomplete data problem

Multi-modal datasets need multiple types of information—an image and a caption, for instance. In practice, data is messy: some images have no captions, some captions have no images. A naive solution is to feed the incomplete data directly to a generative model (a neural network trained to create things like images or text) and hope it guesses well. But this fails for two reasons: first, the model may have only seen complete examples during training, so it has no experience with the broken pattern. Second, fine-tuning the model on your specific broken dataset requires either lots of labeled repair examples, unrestricted access to a high-quality model, or paying expensive API costs.

Without any similar complete examples nearby, the generative model is flying blind.

A naive approach is to either fine-tune (retraining) the model on your small broken dataset, or pay an expensive API for access to a strong generative model and hope it is smart enough. Both fail.

The core problem. A generative model asked to repair missing data without seeing similar complete examples will produce inaccurate, incoherent results.

The algorithm as a flow

What it actually does

Build the knowledge base

Collect complete multi-modal examples from your dataset and from public datasets; align their features (images and text in the same space) and filter out outliers.

Encode the broken item

Convert the incomplete data (the image with no text, or text with no image) into a list of numbers that represents its meaning.

Retrieve neighbors

Search the knowledge base for complete examples most similar to the broken item; retrieve both the available modality and the missing modality from each neighbor.

Combine retrieval results

Fuse the retrieved complete examples using their cross-modal connections, creating a multi-faceted context for the generative model.

Generate and select

Let the generative model propose candidates for the missing modality; rank them by coherence and semantic fit, and return the best one.

What the paper changes

What the paper changes

The paper changes how a generative model is prompted. Instead of asking it to repair data in isolation, RAG4DMC first retrieves similar complete examples from a knowledge base and feeds them as context to the model. This one change—adding retrieved examples as input—is the entire mechanism.

the object it moves  =  the input context to the generative model
The hidden quantity

The hidden quantity: Semantic alignment

measured quantity  =  How well the retrieved examples match the broken item

The critical quantity RAG4DMC must measure is semantic alignment: how much do the retrieved complete examples actually resemble the broken item in meaning, not just superficial appearance? If you retrieve similar-looking but unrelated examples, the generative model will be misled. Semantic alignment lives in the shared feature space—a mathematical encoding where both images and text can be compared fairly.

RAG4DMC estimates this alignment by first converting images and text into a shared numerical representation (feature alignment), then measuring distance: closer neighbors in that space are more semantically similar. The paper then filters outliers (examples that look unrelated even if numerically close) using clustering, so only the most coherent neighbors survive.

Why it works

Why it works

A generative model learns to copy patterns from training data. If it has never seen an example of "image without text being completed," it has no pattern to copy, so it hallucinates. But if you show it five real examples of complete data that are similar to the broken item, the model can extract the pattern: "ah, these images with captions look like this; this broken image is similar, so its caption should follow the same style." The retrieval step supplies that critical pattern.

The mechanism works in three layers. First, feature alignment ensures images and text live in the same mathematical space, so distance measures distance in meaning, not just pixels or words. Second, clustering-based filtering removes misleading outliers—examples that happen to be numerically close but thematically unrelated. Third, multi-modal fusion retrieval combines signals from both modalities: instead of retrieving only images that look similar, it also considers what captions accompany similar images, reinforcing the retrieved context. Because the generative model now sees the relationship between images and their captions in the retrieved neighbors, it can mimic that relationship when completing the missing piece, producing more coherent output.

The scoring equation

First in words:

The retrieval score for each candidate neighbor is a weighted sum: the similarity between the broken item and the neighbor (how close they are in feature space), plus a bonus for multi-modal coverage (how complete the neighbor is), minus a penalty for outlier status (how often this neighbor gets filtered by clustering). The higher the score, the more useful the retrieval.

Then the compact form:

score_k = sim(x_broken, x_k) + alpha * coverage_k - beta * outlier_penalty_k

Every symbol:

score_khow useful neighbor k is for retrieval
sim(x_broken, x_k)similarity: distance between broken item and neighbor k in feature space
coverage_kmodality completeness: 1 if both image and text present, 0.5 if partial
outlier_penalty_khow often this neighbor is filtered; 0 if never filtered
alphaweight on modality coverage (chosen by tuning)
betaweight on outlier penalty (chosen by tuning)
Tiny worked example
Suppose we compare broken item (image, no caption) to three candidate neighbors.
Neighbor A: similarity=0.95 (very close), coverage=1.0 (complete), outlier_penalty=0 (always kept). Assume alpha=0.5, beta=0.3. Score = 0.95 + 0.5*1.0 - 0.3*0 = 1.45.
Neighbor B: similarity=0.80, coverage=1.0, outlier_penalty=0.4 (filtered half the time). Score = 0.80 + 0.5*1.0 - 0.3*0.4 = 1.22.
Neighbor C: similarity=0.85, coverage=0.5 (only text, no image), outlier_penalty=0.2. Score = 0.85 + 0.5*0.5 - 0.3*0.2 = 1.29.
Rank: Neighbor A (1.45) > C (1.29) > B (1.22). Retrieve A as the primary context for generation.

Neighbors with high similarity, complete modalities, and low outlier status become the most useful guides for the generative model.

What can go wrong

What can go wrong

Knowledge base is too small. If your in-dataset complete examples are sparse (few full items), there may be no truly relevant neighbors to retrieve. The method then falls back to remote public data, which may not fit your domain well.
Feature alignment is poor. If images and text are not properly aligned in the shared space (e.g., image numerical representations and text numerical representations are on different scales), distance measures will be misleading, and retrieval will grab irrelevant examples.
Outlier filtering is too aggressive. If clustering removes too many neighbors, the retrieval set shrinks to a few poor candidates that happen to be un-filtered. The generative model then learns from bad examples.
Done right. Build a large, diverse knowledge base of complete examples; carefully tune feature alignment using a validation set; and calibrate the outlier threshold so you keep enough neighbors but not noisy ones. Test the retrieval quality (do neighbors look relevant to humans?) before running generation.
What a runnable demo should prove

What a runnable demo should prove

A concrete demo would take a multi-modal dataset with some items missing captions (e.g., a subset of MS-COCO with captions held out), build a knowledge base from complete training data, run RAG4DMC to generate captions for the held-out images, and measure both accuracy (do the generated captions match the ground truth in meaning?) and speed (how much slower is retrieval than naive generation?).

accuracy = (number of generated captions matching ground truth in meaning) / (total held-out images); coherence = (human raters score 1-5 on semantic relevance); speedup = (time with retrieval) / (time without retrieval)

The demo must show that retrieved examples make the model's completions measurably more accurate and coherent because the model learns from real examples, not guesswork. The retrieval lookup adds a few seconds per item, but results improve: downstream tasks like image captioning and retrieval see 20-40% higher accuracy because the generated captions now semantically match the images, a result that would be much harder to achieve without guidance from real examples.
