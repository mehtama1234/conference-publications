Memory is Reconstructed, Not Retrieved: Graph Memory for LLM Agents

MRAgent stores long-horizon experience as a cue-tag-content graph and rebuilds the needed path actively, so that memory access can adapt as evidence accumulates.

Paper explainersAll themesAgents & Tool Use

A long interaction history contains too much material to scan from start to finish every time an agent needs context. Many memory systems therefore fetch a fixed set of past items first and reason over them afterward. That rigid split is limiting because the agent often discovers halfway through the reasoning process that it needs a different branch of memory. MRAgent changes memory access from one fixed lookup into an active reconstruction process. It stores experience as a graph linking cues, tags, and full content, then expands or prunes memory paths as new evidence appears. This improves long-horizon reasoning because the memory path can change with the current question instead of being frozen at the start.

Zero assumption version

Why fixed memory lookup is too rigid

An agent facing a long history usually needs only a small fraction of it, but the useful fraction is often unclear at the beginning. A static lookup step chooses memory before the reasoning process has uncovered what evidence actually matters.

That creates a mismatch. The right memory path may only become obvious after the agent has already seen some intermediate clues. The paper asks how to let memory access evolve during reasoning instead of forcing all memory choices up front.

The paper's move in one sentence. Represent memory as a cue-tag-content graph and let the agent expand or prune graph paths during reasoning, so that memory access keeps adapting as evidence accumulates.

The algorithm as a flow

What it actually does

Step 1: Break memory into cues, tags, and content

Store experience in linked pieces so that later access can move through intermediate associations.

Step 2: Start from the current cue

Open an initial graph path from the present question because some starting point is still needed.

Step 3: Use current evidence to expand or prune paths

Revise the active memory path as reasoning develops so that the graph follows the most promising branch.

Step 4: Gather content from the surviving path

Assemble the relevant memory content only after the path has been refined by current evidence.

Step 5: Answer with the rebuilt memory view

Produce the final answer using the reconstructed memory path because that path reflects the reasoning process.

The hidden quantity

The hidden quantity: path relevance

measured quantity  =  how well the currently active memory path matches the evidence uncovered so far

The important quantity is path relevance. A memory system is helpful only when the path it follows keeps matching the clues that the agent has uncovered up to the current point.

MRAgent improves path relevance by letting graph paths change during reasoning. That matters because later clues can reveal that an early branch was weak and a different branch should be followed instead.

Why it works

Why it works

The cue-tag-content graph is useful because it exposes intermediate associations between the current question and deeper memory content. Those associations give the agent handles for revising the path later.

Active expansion and pruning are the core operations because they let the system incorporate newly found evidence. A fixed lookup cannot recover from an early wrong branch, but an adaptive path can.

Controlled expansion matters because long histories can explode into too many possible branches. Pruning keeps the search focused so that the agent gains flexibility without losing tractability.

A compact reconstruction objective

First in words:

Maintain the memory path that best matches the current evidence while limiting unnecessary branch growth.

Then the compact form:

J = path_match(current_path, evidence) - alpha * branch_cost(current_path)

Every symbol:

Jthe memory reconstruction objective
path_match(current_path, evidence)how well the current graph path explains the clues gathered so far
branch_cost(current_path)cost of exploring too many branches while rebuilding memory
current_paththe active cue-tag-content path under consideration
alphaweight on branch cost
A tiny worked example
A question asks who promised a follow-up after a long meeting history.
The first cue opens two branches, one about scheduling and one about action items.
A later clue mentions a delayed report, so the action-item branch gains support while the scheduling branch loses support.
The system prunes the weak branch and follows the action-item branch to the stored content that names the person.
The final answer improves because the memory path was revised after the new clue appeared.

The objective captures the paper's main balance: adapt the memory path to new evidence, but control branch growth so that reasoning stays manageable.

What can go wrong

What can go wrong

Cue and tag links may be weak. If the graph links are noisy, path updates can drift because the agent follows poor associations between clues and content.
Pruning may remove a useful branch too early. An aggressive pruning rule can hurt later reasoning because a branch that looks weak early may become important after another clue appears.
Expansion may still grow too fast. If too many branches survive, cost rises quickly because the graph search begins to approach the long-history problem it was meant to avoid.
Done right. The approach works when graph links are informative and branch control is balanced, because then the memory path can adapt without becoming unwieldy.
What a runnable demo should prove

What a runnable demo should prove

Build a long-history question-answer benchmark where the right answer depends on combining clues revealed at different times. Compare a fixed first-lookup memory system with a graph-based system that can revise its active path after each new clue.

The demo should show higher answer quality with lower memory access cost for the graph system because it follows evidence-aware paths and prunes weak branches as the task unfolds.
