Uncertainty-Aware Clarification in LLM Agents with Information Gain

Ask clarification questions only when they sharply reduce uncertainty about the user's goal, so the agent avoids wrong tool actions with very little extra interaction.

Paper explainersAll themesAgents & Tool Use

When a user's request is underspecified, an agent can either guess and risk acting on the wrong goal or ask a follow-up question. This paper gives the agent a principled way to decide which question is worth asking. The core idea is to reward a clarification if the answer would reduce uncertainty about the user's true goal because the best clarification is the one that changes the agent's decision the most while adding the fewest extra turns.

Zero assumption version

Why guessing from vague instructions fails

A user often gives a request that leaves out key details such as destination, date, urgency, or acceptable tradeoffs. If the agent guesses those details, it may choose the wrong tool action and complete the wrong task. Always asking more questions is also costly because many requests are already clear enough.

The paper therefore treats clarification as a decision problem. A question is useful only if the likely answer would reduce uncertainty enough to improve task completion because a question that does not change the agent's plan merely adds friction.

The paper's move in one sentence. Train the agent to ask the follow-up question that most reduces uncertainty about the user's actual goal.

The algorithm as a flow

What it actually does

Represent uncertainty over goals

Keep several plausible user goals instead of locking onto one guess too early.

Score candidate questions

Estimate how much each possible clarification would reduce uncertainty because not all questions are equally useful.

Ask the best question

Choose the question with the largest expected reduction in uncertainty relative to its interaction cost.

Update the goal estimate

Use the user's answer to narrow the set of likely goals.

Proceed with tool actions

Act after clarification so that the chosen tool call is better aligned with the user's actual intent.

What the paper changes

What the paper changes

The paper changes the policy for when and how an agent asks for clarification. The agent is not rewarded for asking many questions. It is rewarded for asking useful ones.

The hidden quantity

The hidden quantity

measured quantity  =  Uncertainty over the user's goal

The hidden quantity is the spread of plausible user goals before the agent has enough detail to act confidently. The request text does not reveal that spread directly, but the agent must reason about it because different tool actions fit different goals.

The paper evaluates a question by how much it shrinks this uncertainty. A clarification is worthwhile because the user's answer can change the goal estimate enough to improve the later action.

Why it works

Why this works: a question is valuable only if it changes the decision

Clarification helps only when the answer changes which action the agent should take, because that change is what turns an extra question into a better later action. If the agent would make the same tool call either way, the question adds delay without benefit. Information gain is useful because it measures whether the answer will sharply narrow the goal space.

The paper also shows that the gain can be high even with very little extra dialogue. One targeted question may eliminate most of the dangerous ambiguity, which is why the reported success increases while average interaction length rises only slightly.

Math after the picture

Information gain from one question

First in words:

The value of a clarification question is the uncertainty before the question minus the uncertainty after the user's answer. A larger drop is better because the agent becomes more certain about the user's true goal.

Then the compact form:

gain(question) = uncertainty_before - uncertainty_after

Every symbol:

gain(question)how much useful uncertainty the clarification removes
uncertainty_beforecurrent uncertainty over the user's goal before asking
uncertainty_afterremaining uncertainty after using the user's answer
A tiny worked example
Before asking, the agent gives three possible destinations weights of 0.4, 0.35, and 0.25.
After asking 'Which city are you flying to?', the answer leaves weights of 0.9, 0.05, and 0.05.
Uncertainty drops sharply, so the question has high gain because the next tool action is now much clearer.
A weaker question such as 'Do you prefer direct flights?' might leave the destination ambiguity untouched, so its gain would be low.

The paper uses a Bayesian belief update inside the environment, but the core idea is simply to reward questions that reduce goal uncertainty.

What can go wrong

What can go wrong

The goal model can miss the true option. If the agent never considers the user's actual goal, no clarification policy can recover it because every update happens inside the wrong set of possibilities.
Users may answer vaguely again. A follow-up question can fail to help because the reply may still be incomplete, so uncertainty remains high even after the extra turn.
Low uncertainty does not guarantee correctness. The agent can become confidently wrong if its initial goal options were biased, because the update may narrow onto the wrong interpretation.
Done right. The contribution is useful because it gives clarification a direct optimization target tied to better actions, not only to more conversation.
What a runnable demo should prove

What a runnable demo should prove

Create a small tool-use environment with underspecified user requests, such as booking, scheduling, or shopping tasks. For each task, define several plausible hidden goals and mark the correct one. Compare an agent that guesses immediately with an agent that can ask one clarification question chosen by expected uncertainty reduction.

The demo should show more correct tool actions with only a tiny increase in dialogue length because the chosen question should target the most decision-relevant ambiguity.
