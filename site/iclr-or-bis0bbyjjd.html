Is In-Context Learning Learning?

In-context learning does not truly encode observations like learning does; instead, it reads patterns from prompt structure and fails on out-of-distribution tasks.

Paper explainersAll themesLearning Theory

When a language model solves a task by reading a few examples in the prompt (called in-context learning, or ICL), we might think it has just learned that task, like you learn by studying examples. But the paper shows this is not quite right. Traditional learning means storing information inside your own memory—the model's weights (the numbers that define what it does); once you have stored it, you can solve new problems reliably. ICL instead only reads the prompt structure itself, without storing anything inside the model's weights. Because nothing is stored internally, when a test case looks different from the examples shown, the model fails completely.

Zero assumption version

The confusion: ICL looks like learning but isn't encoded

In traditional learning, you study examples, update your memory (your brain's weights, the numbers that encode what you know), and then you can solve new problems. The learning is stored inside you. But when a language model does in-context learning, it doesn't update its weights at all—it just reads the examples from the prompt each time, like re-reading the study sheet every time you solve a problem.

The naive claim: if a model solves a new task from a few prompt examples, it must have learned that task, just like you learn from studying. But the paper tests this and finds it is false. Instead, ICL reads patterns from the prompt's structure itself (how the examples are phrased, ordered, balanced), without truly encoding the task inside the model.

In one sentence. ICL is not learning because the model does not encode observations into its weights; it only deduces patterns from prompt structure, and fails when test cases look different from training.

What the paper changes

What the paper changes

The paper ablates (removes or changes) three things during testing: the distribution of examples in the prompt (balanced or imbalanced), the style and phrasing of the prompt (formal, casual, chain-of-thought), and whether the test cases come from the same distribution as the training examples (in-distribution) or a shifted one (out-of-distribution). By changing each one independently, it shows what the model actually depends on.

the object it moves  =  Prompt structure (phrasing, label balance, distribution)
The hidden quantity

The hidden quantity: how much accuracy depends on prompt patterns

measured quantity  =  Accuracy sensitivity to distribution shift

Accuracy sensitivity to distribution shift answers: does the model's accuracy stay high when the test case looks different from the training examples? Real learning stays accurate (you can learn arithmetic and solve new problems with different numbers). ICL does not (if the prompt's statistical patterns change, the model breaks because it was reading the pattern, not storing knowledge).

The paper measures this by creating test sets that are progressively more different from the training examples—first identical (in-distribution), then slightly shifted, then very shifted. It measures accuracy at each level. If accuracy drops sharply when the distribution shifts, the model was not actually learning; it was pattern-matching on prompt structure.

Why it works

Why this happens: reading the prompt is not encoding

Real learning works like this: you observe examples, you update your memory (weights in a neural network), and then you can recognize the pattern no matter how it is phrased. Your learned knowledge is inside you, not in the examples.

ICL works differently: the model never updates its weights. Instead, it reads the current prompt as a piece of text. It patterns-matches: if the prompt has five examples followed by a question, it predicts the next word based on the statistical regularities in the prompt itself. When the test case's numbers or phrasing match the prompt's style, the pattern-matching works. When the test case looks different (out-of-distribution), the pattern no longer matches, and accuracy collapses.

This difference is fundamental. Real learning has two separate steps: encode knowledge into memory, then retrieve it to solve new problems. ICL conflates them—it tries to infer from a moving target (the prompt structure), not from stored encoded knowledge.

Math after the picture

The equation: how to measure what ICL can and cannot do

First in words:

Accuracy is bounded by how different the test distribution is from the training distribution. In the limit (many examples), ICL stops improving because the model has encoded nothing and can only read the prompt.

Then the compact form:

Accuracy(Q) = Pr[error(f, D_Q) ≤ epsilon], where D_Q are samples from test distribution Q, epsilon is a threshold, and error(f, D_Q) measures mismatches. If ||P - Q||_inf (the distance between train and test distributions) is large, Accuracy(Q) drops sharply.

Every symbol:

Accuracy(Q)the fraction of correct predictions on test set Q
error(f, D_Q)the fraction of wrong predictions on samples from Q
epsilonthe accuracy threshold (e.g., 0.1 means 10% error)
Pthe distribution of training examples
Qthe distribution of test examples
||P - Q||_infthe maximum difference between P and Q (distance metric)
A tiny worked example
Task: parity (is a number even or odd?). Training examples: [2,4,6,8] all even, [1,3,5,7] all odd. Accuracy on in-distribution test [10,12,14]: 100%. Model reads the training pattern (all even = one class, all odd = other).
Now shift the distribution. Test set [101,103,105,107]: numbers are larger, same parity pattern. Accuracy still high: 95%. Model's pattern-matching holds.
Shift more. Test set with rare numbers [2,3,5,7,11,13]: primes. The prompt's 'even vs odd' pattern is obscured. Accuracy drops to 40% because the distribution distance grew and pattern-matching fails.

The equation says: ICL's accuracy depends on test distribution, not just on the number of examples. More examples do not help if they are out-of-distribution, because the model never encoded anything.

What can go wrong

What can go wrong

Out-of-distribution test cases kill accuracy. ICL relies on the test distribution matching the training distribution. If the test numbers are larger, rarer, or phrased differently, accuracy collapses—sometimes from 90% to 30%. Real learning would handle this gracefully.
Chain-of-thought prompts are especially brittle. When the model is asked to reason step-by-step (chain-of-thought), it deduces patterns from the reasoning steps, not from the task itself. If the reasoning format changes, or the test case does not fit the format, the model fails worse than standard prompting.
More examples do not guarantee generalization. In real learning, more data helps you generalize better, because you encode the underlying task structure into your memory—more examples let you build a more complete understanding. In ICL, beyond a certain point (when you have many examples), adding more does not help if the test distribution is different, because the model has no internal storage to build—it can only pattern-match the current prompt, and pattern-matching still breaks when the prompt's statistical structure changes.
Done right: test in-distribution. ICL works best (as advertised) when test cases match the training distribution exactly. Use ICL for tasks where you control the test environment or know it will match training. Do not expect ICL to learn a new task that looks different from your prompt examples—it will fail because it has no internal encoding to fall back on.
What a runnable demo should prove

What a runnable demo should prove

Build a simple task (e.g., parity or Hamiltonian-cycle checking). Create a language model prompt with five in-distribution training examples, then test on: (1) five in-distribution test cases (same format, same number magnitudes as training), and (2) five out-of-distribution test cases (different number magnitudes, different formatting, or rare cases). Measure accuracy on both. The demo must show that accuracy stays high on in-distribution (90% or higher) but drops sharply on out-of-distribution (below 50%).

Brittleness ratio = Accuracy(in-distribution) / Accuracy(out-of-distribution). High ratio (> 1.5) proves that ICL is not robust learning.

The demo must make it impossible to miss that ICL is fundamentally fragile: it works on clean test cases but breaks when reality changes, which is the opposite of true learning.
