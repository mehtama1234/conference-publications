Mind-Omni: A Unified Multi-Task Framework for Brain-Vision-Language Modeling via Discrete Diffusion

Mind-Omni turns continuous brain recordings into discrete symbols so one model can map between brain activity, images, text, and answers across several tasks instead of training a separate model for each task.

Paper explainersAll themesMultimodal

Brain-computer interface systems usually split the work into separate tasks: one model decodes brain signals into text, another predicts images from brain activity, another answers questions about neural recordings, and so on. That fragmentation wastes shared structure because the same recording often contains information about what a person saw, what category they recognized, and what they could report in words. Mind-Omni tries to put those tasks into one system. Its central move is a Brain Tokenizer, meaning a module that converts continuous brain measurements into a sequence of discrete symbols, where each symbol is a chosen code from a finite codebook. Once brain signals live in the same symbol-based format as text and image representations, the model can train one generator that moves between modalities with discrete diffusion, meaning an iterative process that starts from corrupted symbols and repeatedly predicts cleaner ones. The paper matters because it treats brain decoding as a general translation problem across several targets instead of as seven unrelated pipelines.

Zero assumption version

Why single-task brain models hit a ceiling

Brain recordings are continuous, noisy, and heterogeneous, meaning different datasets use different sensors, rates, and signal ranges. A model built only for one output task usually learns the narrow mapping needed for that benchmark and throws away structure that would help elsewhere because the training signal rewards only one output path. For example, the signal pattern that supports image reconstruction can also support question answering about what was seen, but separate models do not share that internal organization.

The second problem is representation mismatch. Text models consume sequences of discrete symbols, image generators often operate on learned image codes, and brain signals arrive as real-valued time series. If every pair of modalities needs its own custom adapter, the system does not scale. Mind-Omni asks for one intermediate format that brain data can enter so any task can reuse it.

The paper's move in one sentence. Convert brain recordings into discrete symbols, then train one discrete diffusion model that can map those symbols to and from images, language, and question-answer pairs.

The algorithm as a flow

What it actually does

Encode the brain recording

Read the continuous neural signal and map local patterns to discrete symbols through the Brain Tokenizer.

Represent the target modality in symbols too

Use text symbols for language tasks and learned image codes for visual tasks so both sides have the same basic format.

Corrupt target symbols during training

Replace or mask part of the target sequence so the model must recover the clean sequence from context. This works by forcing it to learn dependencies among symbols instead of only memorizing fixed outputs.

Condition on one or more source modalities

Give the model brain symbols alone or brain symbols plus other context, depending on the task.

Iteratively denoise the sequence

Predict cleaner symbols over several steps until the sequence becomes a caption, an answer, or an image code sequence.

What the paper changes

What the paper changes

The paper changes the representation used for brain data. Instead of leaving neural activity as only continuous numbers and building a custom model around each task, it converts the activity into discrete symbols that can be handled by the same generative machinery used across modalities.

The hidden quantity

The hidden quantity

measured quantity  =  task-shared brain symbols

The hidden quantity is the sequence of brain symbols that best captures the information in the recording while staying reusable across tasks. Those symbols are not observed directly. The model has to learn code assignments that preserve what matters for decoding and generation instead of merely reconstructing the raw waveform.

This matters because a poor symbolization would fragment the tasks again. If the codes only preserve signal details useful for one benchmark, the shared model gains nothing. If the codes preserve semantics, meaning the content implied by the recording such as object identity, scene category, or answer-relevant attributes, then the same code sequence can support multiple outputs.

Why it works

Why a unified symbol space helps

A shared model only becomes practical if all tasks can speak the same internal format. Discrete symbols provide that format because they turn an irregular continuous recording into a finite sequence of choices. Once the brain data is in that form, the model can learn transition rules over symbol sequences instead of separate numeric mappings for each task.

Discrete diffusion then gives a training rule that works for many task directions. The model repeatedly learns to repair a corrupted symbol sequence while using the conditioning inputs to decide which repairs are plausible. That matters because denoising forces the system to model dependencies among symbols, not just direct one-step prediction. The same denoising process can produce text, image codes, or answers because each output is ultimately a clean symbol sequence.

Multi-task training can improve the representation because every task pressures the brain symbols in a different way. Image reconstruction pushes them to retain visual structure. Captioning pushes them to retain reportable semantics. Brain question answering pushes them to retain information that supports reasoning over the recording. If one task leaves ambiguity, another task can reduce it because all tasks update the same shared components.

The training objective

First in words:

The model learns to recover clean target symbols from corrupted ones while using source modalities as conditioning information, and it learns the tokenizer so the chosen brain symbols stay informative across tasks.

Then the compact form:

L = L_tokenizer + E_t[ CE(clean_target_symbols, denoise_model(corrupted_symbols_t, condition_symbols, t)) ]

Every symbol:

Lthe full training loss
L_tokenizerthe part that trains the Brain Tokenizer to produce useful discrete brain symbols
CEcross-entropy loss on the target symbol at each position
clean_target_symbolsthe correct symbol sequence for the task output
corrupted_symbols_tthe target sequence after corruption at step t
condition_symbolsbrain symbols and any extra source symbols provided to the model
tthe current denoising step
A tiny worked example
Suppose the brain recording corresponds to a viewed cat image.
The tokenizer converts the recording into brain symbols that preserve category and rough visual layout.
For a captioning task, the target text symbols are corrupted by masking several positions.
The denoising model sees the corrupted text symbols plus the brain symbols and predicts the missing symbols for 'a cat on a sofa.'
For an image reconstruction task, the same brain symbols condition denoising over image codes instead of text symbols.
Because both tasks depend on the same brain symbols, mistakes in one task can reveal missing information in the shared representation.

The equation emphasizes that the model is trained as a conditional denoiser over discrete sequences rather than as a separate decoder for each task.

What can go wrong

What can go wrong

The tokenizer can discard task-critical detail. If the codebook is too small or the encoder is too aggressive, the brain symbols may lose information that no later denoising step can recover because the missing detail never reaches the shared model.
Tasks can compete for capacity. If one task dominates the training data, the shared components may drift toward that task because its update signals arrive more often, leaving weaker tasks underfit.
Cross-subject variation can break the shared space. Brain recordings differ across people and devices, so symbol assignments learned on one data pattern may transfer poorly unless normalization and subject adaptation are handled carefully.
Done right. The approach is strongest when several tasks truly share latent content, meaning hidden but recoverable semantic content, and the tokenizer preserves that content instead of overfitting sensor-specific quirks.
What a runnable demo should prove

What a runnable demo should prove

Use a small paired dataset where each neural recording is aligned with an image and a short caption. Build a Brain Tokenizer that converts the recording into discrete symbols, then train one discrete denoiser for two tasks: brain-to-caption and brain-to-image-code reconstruction. Compare that unified system with two separate task-specific models that do not share a tokenizer.

Show the learned brain symbols, the denoising trajectory, and the effect of removing one task from training. The demo should prove that shared training improves both tasks because the common representation becomes more informative, not because one task simply has an easier decoder.

multi_task_gain = average_task_score_unified - average_task_score_separate
