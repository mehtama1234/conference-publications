RDT2: Scaling UMI Data for Zero-Shot Robot Generalization

RDT2 trains a 7 billion number vision-language-action robot on 10,000 hours of diverse manipulation data via three discrete-then-continuous stages to generalize to new robots, objects, and instructions without retraining.

Paper explainersAll themesRobotics & Control

A vision-language-action model (VLA) is a system that reads an image and text instruction and predicts what a robot should do. The challenge: robot data is scarce, and robots look different (different arms, grippers, sizes). RDT2 solves this by collecting massive diverse demonstration data and training in three stages—discretizing actions first, then learning continuous refinements, then compressing for speed—so the model works on robot hardware it has never seen before.

Zero assumption version

Why robot learning fails at scale

Robots today are mostly trained on small amounts of data from a single robot type. A robot learns to pick objects on one arm, but the same program will not work on a different arm—the distances and movements are all wrong. The naive approach is to collect more data from every robot you care about, but that is impossibly expensive: each robot type needs thousands of hours of human demonstrations, and you would run out of time and money long before covering all the combinations that matter.

A second problem: most methods use diffusion models (a technique where you gradually add noise to an action, then learn to clean it up). Diffusion converges slowly and wastes training compute. It also speaks the language of continuous numbers (3.45, 2.89, etc.), but the vision-language model (a pre-trained system that already understands images and text) was built to output discrete tokens—categorical predictions like 'left', 'up', 'grasp'. Forcing the two languages together creates friction and slows learning.

In one sentence. Train a single robot model on diverse hardware data in three stages—discrete-then-continuous—so it works on new robots without retraining.

The algorithm as a flow

What it actually does

Encode actions as discrete tokens

Convert continuous motion vectors into categorical buckets using residual vector quantization (a compression technique that maps numbers to nearest named categories). This is fast because the pre-trained vision-language model already knows how to predict categories.

Train vision-language backbone on discrete tokens

Teach the frozen pre-trained vision-language model to predict these categorical actions from images and instructions, using cross-entropy loss (a penalty that shrinks when predictions match observed actions). This works fast because the model was originally trained on text and image categories, so predicting action categories is natural to it.

Train action expert network for continuous accuracy

Build a separate continuous refiner that reads the vision-language backbone's features and learns to output smooth, precise motions via flow-matching (a technique that gradually transforms random motion into realistic actions).

Distill expert into single-step predictor

Compress the iterative expert (which runs multiple steps) into a fast one-step generator by regression. This is possible because the expert learned enough about good actions that a simpler predictor can mimic it in one shot, and this speeds up prediction so the robot can respond without delay.

Deploy on new robots without retraining

The embodiment-agnostic dataset (recorded with hardware-neutral interfaces) allows transfer because all robots are recorded at the same spatial coordinates and movement axes. The model never learns arm-specific details, only task-relevant decisions like 'pick at this height', so it adapts to any robot shape.

What the paper changes

What the paper changes

The paper changes the action representation pipeline—how the model converts images and instructions into robot commands. Instead of learning directly in continuous space (which diffusion does badly with pre-trained models), it first learns discrete token predictions (which aligns with how the vision-language model was originally trained), then adds a continuous expert on top, then distills that expert for speed. This three-stage design replaces the naive single-stage diffusion approach.

The hidden quantity

The hidden quantity: embodiment mismatch

measured quantity  =  Hardware generalization gap

The core hidden measurement is how much the learned behavior works on a robot shape the model never trained on. This is invisible in standard benchmarks (which test on the same hardware), but it is the crux of the paper's claim: that massive diverse data plus embodiment-agnostic interfaces (a physical design that treats all robots the same) lets the model predict actions that transfer across different robot geometries. The paper measures this by testing on robots with different arm lengths, joint ranges, and gripper designs.

The hidden mechanism: embodiment-agnostic data (recorded using a hardware-neutral manipulation interface) strips away robot-specific quirks. When the model learns 'grasp at this height and angle' from many robots at once, it learns the task in terms of what moves matter (reach point, grip force, approach direction), not the specific joint angles each robot needs. Pre-training on a large vision-language model amplifies this—the model already knows about objects and spatial relationships, so it can reason about how to adapt actions to new hardware.

Why it works

Why the three-stage design works

The root problem is a language mismatch: the pre-trained vision-language model predicts discrete categories (token IDs: 0, 1, 2, ...), but robot actions are continuous (smooth floats: 2.34, 0.87, 5.12). Diffusion solves this by adding noise and gradually denoising—but that takes many steps (slow) and creates a domain gap (the model's original training never involved noise, so it is uncomfortable with diffusion's assumptions).

The paper's solution: three stages that bridge the gap step by step. Stage 1 converts continuous actions into discrete tokens via residual vector quantization (a lossless compression that maps every action to its nearest named bucket). This lets the vision-language model train with cross-entropy loss—the same loss it was originally built for. The model converges quickly because it is in its native language. Stage 2 then trains a separate continuous expert that has seen the discrete tokens and learned what they mean; the expert uses flow-matching to generate smooth continuous actions. Stage 3 distills the expert into a one-step predictor, eliminating the multi-step loop.

Why this transfers to new robots: the embodiment-agnostic dataset (collected with hardware-neutral Universal Manipulation Interface hardware) treats all robot morphologies uniformly—it records tasks in terms of world coordinates and physics, not motor angles specific to one arm. When the model learns 'pick this object' from hundreds of diverse robots doing the same task, it discovers what moves work on the task (reach height, approach angle, grip force) rather than specific joint commands for one robot body. The pre-trained vision-language model amplifies this: its image understanding and spatial reasoning are already robot-agnostic, so combining that with embodiment-neutral data gives the model a general task understanding that any robot morphology can execute.

Math after the picture

The three-stage loss functions

First in words:

Stage 1: cross-entropy loss for discretizing and training on tokens. Stage 2: flow-matching loss for continuous action expert. Stage 3: regression loss to distill the expert into one step.

Then the compact form:

L_stage1 = -log P(token_t | image, instruction); L_stage2 = ||v(τ, A_τ, VLA(image)) - u(A_τ|A)||^2; L_stage3 = ||G(VLA(image)) - Expert(VLA(image))||^2

Every symbol:

P(token_t | ...)probability of the correct action token given image and instruction
v(τ, A_τ, VLA)denoising network that predicts action at time step τ, using VLA features
A_τthe action at noise level τ (0 is pure noise, 1 is the real action)
u(A_τ|A)the ground truth velocity of the action
G(VLA(image))single-step generator output from distilled model
Expert(...)multi-step expert network output
τcontinuous time variable from 0 to 1 (0.2 means 5 integration steps in practice)
A tiny worked example
Stage 1: A motion vector [1.5, 2.3, 0.8] gets quantized to token 42 (the nearest bucket). Training loss is -log(P(42|image)), measuring how confidently the VLM predicts the right token. P(42|image) = 0.7 → loss = -log(0.7) = 0.36.
Stage 2: At noise level τ=0.5, the expert network tries to denoise toward the true action [1.5, 2.3, 0.8]. It predicts [1.4, 2.2, 0.9]. Ground truth velocity is u([1.5, 2.3, 0.8]) = [1.5, 2.3, 0.8]. Loss = ||[1.4, 2.2, 0.9] - [1.5, 2.3, 0.8]||^2 = 0.01 + 0.01 + 0.01 = 0.03.
Stage 3: The distilled one-step generator predicts [1.55, 2.25, 0.75]. The expert predicts [1.5, 2.3, 0.8]. Distillation loss = ||[1.55, 2.25, 0.75] - [1.5, 2.3, 0.8]||^2 = 0.0025 + 0.0025 + 0.0025 = 0.0075. Lower is better (generator matches expert).

The three stages progressively refine the action: discrete tokens are fast but lossy, the continuous expert adds precision, and distillation trades a little precision for speed so the final model runs in real time on robots.

What can go wrong

What can go wrong

Quantization loses precision at stage 1. If the discrete buckets are too coarse (not enough token types), the model cannot represent fine-grained actions. The fix is to use enough residual vector quantization codebook entries so every distinct action has a bucket close enough to round-trip without losing critical detail.
Stage 2 expert overfits if trained on too little data. The continuous expert sees only the stage 1 tokenized actions, which already throw away some information. If the expert memorizes rather than generalizing, it will not transfer to new robots. Collecting massive diverse demonstrations (10,000 hours across many morphologies) is the antidote.
Distillation can compress away critical behavior. If the one-step generator is too small, it may not have capacity to mimic the multi-step expert. The model collapses to simple averages and fails on dynamic tasks (like table tennis). The paper uses on-the-fly distillation and sufficient capacity to keep this from happening.
Done right: embodiment-agnostic data + large VLM backbone. When data is diverse (many robot types, tasks, scenes), recorded with hardware-neutral interfaces, and the backbone is a large pre-trained vision-language model with 7 billion numbers to tune, the learned representations generalize. The model learns task-relevant moves (grasp height, approach angle) that work on any robot shape, not the specific quirks of one arm.
What a runnable demo should prove

What a runnable demo should prove

The demo should train a tiny version of RDT2 on a small embodiment-agnostic dataset (e.g., 100 demonstration clips of pick-and-place from multiple robot morphologies), run the three stages, and then test zero-shot transfer. Collect success rates on a test robot whose morphology was held out of training. Compare to a baseline that trains only Stage 1 (discrete only, no continuous expert) or only Stage 2 (direct diffusion). The metric should show that Stage 1 speeds up training (lower loss curves after 1 epoch) because discrete predictions converge faster. Stages 2+3 unlock transfer to held-out morphologies because the continuous expert learns to refine rough discrete predictions into smooth, generalizable motions that the embodiment-agnostic training data taught it work on new shapes.

Transfer success = (tasks_succeeded_on_new_robot / total_test_tasks) × 100%; Training speedup = (loss_after_stage1_epoch_N / loss_after_naive_diffusion_epoch_N)

The demo must make it impossible to miss: starting from Stage 1's discrete alignment, the model learns a robot-agnostic task model that the continuous expert can deploy instantly on hardware it has never seen.
