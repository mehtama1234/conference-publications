Demystifying Action Space Design for Robotic Manipulation

Changing how a robot describes its movements—whether it says absolute positions or relative nudges—dramatically shapes how easily it learns from demonstrations.

This paper tests 500+ trained models on real robots to uncover which choices actually work and why.

Zero assumption version

How does a robot even describe what it is doing?

When you teach a robot to pick up a cup by showing it videos of a human doing it, the robot learns a deep neural network—a mathematical model with thousands of numbers. That model ingests an image and outputs a command: how the robot's arm should move. But what should that command be? Should it say 'move the hand to a specific spot in space, like the coordinates for the cup'? Or 'nudge the hand 2 centimeters forward and 1 centimeter left from where it is right now'? Both describe motion, but they ask the model to solve different problems.

Today, engineers pick this choice by gut feeling or copy old projects. A beginner trying the wrong choice builds a robot that flails, fails to grasp objects, or works so badly nobody bothers tuning it. The problem is nobody had measured which choice actually matters or why.

In one sentence. This paper tests whether robots learn faster when they predict absolute hand positions or relative nudges—the choice matters because delta actions create simpler training problems, so models find good solutions faster.

What the paper changes

The thing the paper changes

The robot's action space—the vocabulary it uses to describe its own moves. Instead of letting each robot project choose arbitrarily, the paper tests two core designs: whether the model predicts absolute hand coordinates in the world, or relative displacements from the hand's current position.

the object it moves  =  action space representation
The hidden quantity

Learnability: how quickly the model figures out the task

measured quantity  =  task convergence speed

Learnability is the simplest question: given a fixed amount of training data (say, 100 human demonstrations), how many training steps does the model need before it consistently grasps the cup? A model trained on delta actions tends to converge in fewer steps than one trained on absolute positions, because predicting small nudges is a simpler problem mathematically. The paper measures this by counting how many gradient updates (adjustments to the model's weights) are needed to reach 80% success on held-out test rollouts.

The paper estimates this by training each model variant and recording at what training step performance plateaued. Faster convergence means the model learned the task's core structure earlier, because when a model reaches 80% success in fewer steps, it has found the essential relationship between images and movements more efficiently.

Why it works

Why delta actions work better: the math of small changes

Imagine the robot's hand is currently at position (0.5, 0.3, 0.8) in 3D space. If the model must predict the absolute target position, it must learn to output a specific coordinate. But that coordinate changes depending on where the hand started. In one demo the hand started at (0.4, 0.25, 0.75), in another at (0.6, 0.35, 0.85). The model sees different starting positions and must predict different targets—the relationship between input and output is entangled with irrelevant details like where the hand happens to begin.

Delta actions cut through this. Instead of learning absolute positions, the model learns nudges: 'forward 0.1 meters, left 0.05 meters'. These nudges are the same regardless of starting position. The model learns a simpler, more generalizable rule. The error surfaces become simpler and smoother—fewer jittery directions, fewer ways for gradient descent (the process that tunes the model's weights) to get stuck in local dead-ends. A simpler error surface means fewer training steps to find good weights.

Joint-space vs. task-space is orthogonal. Joint-space means predicting how much each motor should rotate; task-space means predicting hand position or pose in Cartesian coordinates. Joint-space is closer to the hardware physics, so small errors in the model's predictions translate directly to small errors in the actual motion—the system is stable because the hardware naturally dampens noise. Task-space actions are more intuitive to learn from (humans naturally demonstrate in hand-space), so the model generalizes to new scenarios better, because the relationship between image and hand position is simpler than the relationship between image and motor angles, which depends on the arm's current pose. The paper finds both matter, in different ways.

Predicting the next move

First in words:

The model outputs a movement command. With absolute actions, that is a 3D target position. With delta actions, it is a 3D displacement. The loss—the error the model tries to minimize—is the squared distance between the predicted move and the observed human move.

Then the compact form:

loss = (prediction - observation)^2

Every symbol:

predictionwhat the model outputs (absolute position or relative nudge)
observationwhat the human actually did in the demonstration
losserror to minimize during training
A tiny worked example
Human demo: hand moves from (0.50, 0.30) to (0.52, 0.31).
Observation (delta) = (+0.02, +0.01).
Model prediction (delta) = (+0.021, +0.008).
Error per axis: 0.001 and 0.002.
Loss = 0.001^2 + 0.002^2 = 0.000001 + 0.000004 = 0.000005.
Small error, smooth gradient: the model learns cleanly.
Now with absolute actions:
Same demo: hand at (0.50, 0.30) sees target (0.52, 0.31).
Different scene: hand at (0.60, 0.40) must reach nearby relative point (0.62, 0.41).
Model sees: input (0.50, 0.30) -> output (0.52, 0.31); input (0.60, 0.40) -> output (0.62, 0.41).
Two different input-output pairs: the model learns a more complex mapping, needs more data.

Delta actions keep errors small and consistent across different starting positions, so the gradient signal guides the model efficiently.

What can go wrong

What can go wrong

Stacking errors: predicting one nudge at a time can drift. If the model makes a small mistake in the first nudge, the hand ends up slightly off. The next prediction assumes the hand is in the right spot, leading to cascading error. This matters over long trajectories (many steps). Absolute actions are immune because each command specifies the exact target, not relative to the previous position.
Joint-space actions work only with known kinematics. Predicting motor rotations assumes the exact robot hardware is known (arm length, joint limits). If the hardware varies slightly between units or degrades over time, the action fails. Task-space avoids this by working in hand coordinates, not motor space.
Task-space actions can over-generalize. Predicting hand position in 3D space works well on new scenarios with the same arm, but if the task involves rotating the wrist or precise orientation, hand position alone is not enough. A task-space action should include rotation or orientation to handle complex manipulation.
Done right: use delta task-space actions for speed, joint-space for stability. The paper shows delta + task-space learns fastest and generalizes. For tasks requiring tight control, add a joint-space stabilizing layer on top.
What a runnable demo should prove

What a runnable demo should prove

Build a simulated robot arm (using a physics simulator like PyBullet). Collect 50 human demonstrations of reaching for an object. Train two models on the same data: one predicting absolute hand positions, one predicting delta movements. Record training loss and test success rate (does the robot reach the object?) over 500 training steps. Plot both curves on the same graph.

convergence_speed = step at which success >= 80% for the first time

The delta model should reach 80% success in roughly half the training steps compared to absolute positions, even though both see the same demonstrations and start from random weights.
