VideoAgentTrek: Computer-Use Pretraining from Unlabeled Videos

Mine training data for computer-control agents automatically from YouTube videos instead of paying humans to label mouse clicks and keystrokes.

Paper explainersAll themesAgents & Tool Use

Teaching a computer-control agent to use a mouse and keyboard requires tens of thousands of labeled examples: video frames paired with the click coordinates, text typed, or button pressed at each step. Paying humans to annotate these is slow and expensive. This paper extracts that training data automatically from YouTube tutorial videos, where people already perform these actions on screen. No human labels needed.

Why computer-control agents are stuck today

To train a computer-control agent—a system that looks at a desktop screen and decides to click a button or type text—you need concrete examples: a video frame paired with the actual mouse click, the coordinates of that click, and when it happened. Thousands of these pairs.

Humans can label these. A person watches a 10-minute tutorial video and marks every action: when the user clicked the File menu, the coordinates of that click, when they typed a password. But this is tedious and slow. A team of humans can label only a few hundred hours of video per month. To train a strong agent on hundreds of thousands of hours, the cost is prohibitive.

The problem is that the video alone is not enough. Raw YouTube videos show actions happening, but the video does not tell you the exact pixel coordinates of each click or what text was typed. Those details are buried in the operating system's internal logs, which the video does not capture. So humans must watch and manually extract them.

The bottleneck. Humans are doing the work to label videos, and paying them to label millions of actions is too expensive.

The algorithm as a flow

What it actually does

Find the action

A grounding model watches the video and pinpoints where each action starts and stops.

Extract the action

For each detected action, a recognizer pulls out the concrete parameters: the pixel coordinates of the click, the text typed, the key pressed.

Pair frame to action

Align each video frame with the action that happened just after it, creating a training example.

Collect at scale

Run this pipeline on 39,000 tutorial videos to generate 1.52 million labeled examples.

Train the agent

Feed these labeled examples to an agent model, which learns to predict the right action given a screenshot.

What the paper changes

What the paper changes

The paper replaces expensive manual human annotation with automatic extraction: an inverse dynamics module (a network that learns to predict the action that caused a visible change) watches raw videos and produces the action labels directly. Instead of hiring humans, you run code.

The hidden quantity

The hidden quantity: action localization precision

measured quantity  =  action localization precision

The paper measures a quantity that the raw video does not explicitly show: the precise temporal boundary of each action. When does a click happen? When does typing start? When does a drag end? The grounding model predicts these boundaries by learning from visual cues—the cursor moves, the screen updates, text appears—and must pinpoint the exact frame where the action occurs.

This precision matters because a misaligned action label teaches the agent the wrong thing. If the frame is labeled with a click that actually happened one frame later, the agent learns to click when the screen is in the wrong state. The Video2Action module estimates localization precision by comparing predicted action boundaries against unlabeled video structure (scene transitions, text insertion patterns) and refining its predictions iteratively.

Why it works

Why automatic extraction works

A human watching a tutorial video can infer actions because they see correlations: when the cursor moves to the top-left corner and clicks, the File menu opens. The grounding model learns the same correlations from unlabeled video pairs. For each consecutive pair of frames, it learns: if I see the cursor here and the screen changed that way, then a specific action happened between the frames.

The action-content recognizer goes further. It learns that certain visual patterns—a rectangular text box with a cursor blinking, then text appearing letter by letter—correspond to typing. A pattern where the cursor moves in an arc and the screen updates corresponds to a click. By training on enough videos, these patterns become predictable.

Because tutorial videos are abundant and consistent in their visual structure (tutorials show the same actions repeatedly), the model can train itself without human labels. It learns the visual language of actions and can then extract actions from new videos automatically. Each video frame pair already contains all the information needed: the before state and the after state. The model just has to learn to infer what caused the change.

The core formula

First in words:

For each video frame, predict the action that happened right after it by minimizing how wrong the prediction is. The total loss is the sum of grounding error (did we find the action at the right time?) plus recognition error (did we extract the right coordinates and text?).

Then the compact form:

L = L_ground + L_recognize = sum_i ||t_pred_i - t_true_i||^2 + sum_j ||params_pred_j - params_true_j||^2

Every symbol:

Ltotal loss (how wrong the predictions are)
L_grounderror in action timing (did we pinpoint the right frame?)
L_recognizeerror in action parameters (did we extract the right click coordinate or text?)
t_pred_ipredicted time when action i occurred
t_true_iactual time (inferred from visible changes in the video)
params_pred_jpredicted click coordinates or text for action j
params_true_jtrue coordinates or text (extracted from visual alignment)
A tiny worked example
Frame 0->1: cursor at (200, 150) in frame 0, moves to (210, 155) in frame 1. Prediction: click at (210, 155).
Grounding: predicted time=frame 1, true time=frame 1. Error: (1-1)^2 = 0 (correct).
Recognition: predicted coords=(210, 155), true coords=(212, 156) from visual alignment. Error: (210-212)^2 + (155-156)^2 = 4 + 1 = 5.
Another frame: cursor at (300, 200), text box appears with 'a' in it. Predicted text='a', true text='a'. Recognition error: 0.
Total error for this video: sum of all frame errors. Training reduces this error, so the model learns better predictions.

The model trains on unlabeled video by using visible changes as ground truth, so it learns to invert the chain: if the screen changed this way, the action must have been that.

What can go wrong

What can go wrong

Wrong action detected. The grounding model might mistake a mouse hover for a click, or miss a rapid double-click. This happens when the visual pattern is ambiguous. The fix: train on videos with clear, deliberate actions (tutorials tend to be clear).
Missed parameters. The recognizer might extract the wrong click coordinate if the text box moved between frames. Screen layouts that shift mid-action confuse the model.
Noisy labels propagate. When the grounding model is wrong, its mistake becomes a training label that the agent learns from. A single mislabeled action can teach the agent bad habits, especially if the mistake is systematic (e.g., always off by 5 pixels).
Handled right: verify and filter. The paper can reduce noise by keeping only high-confidence predictions from Video2Action (it already outputs confidence scores) and discarding low-confidence labels before training the agent. This trades quantity for quality.
What a runnable demo should prove

What a runnable demo should prove

Build a small pipeline: (1) download a few YouTube tutorial videos (e.g., someone opening Gmail and composing an email). (2) Run Video2Action on each video to extract actions. (3) Verify the extracted actions by spot-checking: for a few random extracted actions, does the predicted coordinate actually point to the cursor in that frame? Does the extracted text match what appears on screen? (4) Measure accuracy: count how many extracted actions you can manually verify as correct.

action_extraction_accuracy = (number of correct extracted actions) / (total number of extracted actions)

The demo should show that automatic extraction can find most actions with high accuracy, making it viable to train an agent on mined data instead of hiring humans to annotate.
