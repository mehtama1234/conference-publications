Test-Time Accuracy-Cost Control in Neural Simulators via Recurrent-Depth

Let a neural simulator user decide at test time how many loop iterations to run, trading speed for accuracy without retraining the model.

Paper explainersAll themesAI for Science

Science needs simulations that can be fast when you are exploring, and slow but accurate when you need a real answer. Classical simulations offer this trade-off naturally: run more iterations, get more accuracy. Neural simulators (models trained to predict the next state of a fluid or material) have not, because they are hard-wired at training time. RecurrSim fixes this by building a simulator that loops over itself K times at test time. Set K high, get accuracy; set K low, get speed. No retraining needed.

Zero assumption version

Simulators without knobs

In science, a simulator (a model predicting what happens to a fluid, a protein, or a climate system over time) must trade off speed for accuracy. A classical simulator—like finite-difference methods solving equations step by step—lets you choose how many steps to take: more steps, more accuracy, higher cost. You run it fast for what-if questions, slow and careful for papers.

Neural simulators (trained ML models that predict the next state in one or a few forward passes) broke this trade-off. Once trained, they are fixed: they predict at a certain accuracy level, full stop. If you trained it to be fast, it is inaccurate. If you trained it to be accurate, it is slow. A scientist cannot say, 'for this exploratory run, give me a rough answer in 100ms; for this critical calculation, take 2 seconds.' The model does not listen.

The knob is missing. RecurrSim adds a knob: set the number of recurrent iterations K at test time, and the simulator trades off speed versus accuracy on the fly.

What the paper changes

What the model learns to do

RecurrSim trains a neural model to take a current guess at the next state and refine it. Instead of predicting the final answer directly, it predicts a correction: how to adjust the current state to be more accurate. This works because a small refinement is much easier for a neural network to learn than a full solution—the refinement only has to learn what is wrong and fix it, not solve the whole problem from scratch. When looped K times, each iteration nudges the prediction closer to truth.

the object it moves  =  Intermediate refinement, not direct prediction
The hidden quantity

The error-to-fix quantity

measured quantity  =  Residual error (how far the current guess is from the true answer)

A residual is the gap between what the model currently believes and what is actually correct. In classical solvers, each iteration shrinks the residual. RecurrSim trains a neural model to do the same: at each loop iteration, the model computes how wrong the current state is (the residual) and nudges it in the right direction.

The paper measures this implicitly: as K increases, errors on standard benchmarks (Burgers' equation, fluid-dynamics PDEs) drop. The model is learning to estimate and reduce the residual at each pass.

Why it works

Why looping refines the simulation

Classical iterative solvers work by a simple principle: take a guess, compute what is wrong, nudge the guess toward truth. Repeat until correct. A single neural forward pass cannot do all of that; it is either predicting the full answer (hard to get right) or predicting a small refinement (easy, but needs repeating).

RecurrSim trains the model to predict a refinement. Give it a state (even a wrong one), it outputs a nudge. Feed the nudged state back in, it outputs another nudge. After K passes, the nudges compound, and the state converges to a physically correct answer. Training the model to refine one step at a time is simpler than training it to solve the whole problem in one shot: a small correction is easier for the model to learn than a full solution. Looping K times gives the user the knob to dial accuracy up or down at test time without retraining.

Math after the picture

The refinement equation

First in words:

state at iteration k plus one equals state at iteration k plus the model's predicted nudge

Then the compact form:

x_{k+1} = x_k + M(x_k)

Every symbol:

x_kthe simulated state at iteration k
x_{k+1}the state after one refinement step
M(x_k)the neural model's predicted nudge (the refinement to apply)
Kuser-chosen number of iterations at test time
A tiny worked example
Start: x_0 = [0.5, 0.3] (wrong initial guess for fluid velocity).
Iteration 1: M(x_0) = [0.15, 0.25] -> x_1 = [0.5 + 0.15, 0.3 + 0.25] = [0.65, 0.55].
Iteration 2: M(x_1) = [0.10, 0.12] -> x_2 = [0.65 + 0.10, 0.55 + 0.12] = [0.75, 0.67].
Iteration 3: M(x_2) = [0.05, 0.08] -> x_3 = [0.75 + 0.05, 0.67 + 0.08] = [0.80, 0.75].
True answer: [0.80, 0.75]. After K=3 iterations, we have converged. K=1 would give [0.65, 0.55] (rough). K=10 would give [0.80, 0.75] (accurate).

Each loop refines the state by adding the model's predicted correction, and K controls how many corrections to apply.

What can go wrong

What can go wrong

Oscillation instead of convergence. If the model's nudge overshoots (swings past the true answer), later iterations may bounce back and forth instead of settling down. Training must teach the model to nudge conservatively.
K is not enough to converge. Some problems need 20 iterations to reach high accuracy. If a user sets K to 2 and expects high-precision results, they will be disappointed. The model cannot refine faster than its training allows, because each iteration applies only the correction the model learned to make in one step—it cannot make 20 steps of progress in a single forward pass.
Drift in long simulations. In fluid simulations that run for many time steps, small errors compound. A model trained on short horizons may fail to stay stable over long simulations, no matter how high K is.
Done right. The paper shows that RecurrSim converges smoothly on benchmark PDEs (Burgers, KdV, Kuramoto-Sivashinsky). Error bars drop with K, and the model maintains physical fidelity even at low K.
What a runnable demo should prove

What a runnable demo should prove

Build a neural simulator on a simple PDE (Burgers' equation: how a 1D advection-diffusion wave evolves). Train it to refine. At test time, evaluate accuracy and speed for K values of 1, 2, 4, 8. Plot the error versus wall-clock time. Show that one model can deliver the speed-accuracy trade-off without retraining.

trade_off_quality = (accuracy_at_high_K - accuracy_at_low_K) / (time_at_high_K - time_at_low_K)

The demo must make it clear that K is the only lever the user pulls at test time, and changing K alone trades speed for accuracy without any model redesign or retraining.
