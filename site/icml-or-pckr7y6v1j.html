Pushing Forward Pareto Frontiers of Proactive Agents with Behavioral Agentic Optimization

Train proactive agents to ask, plan, and act more usefully while also discouraging wasteful interaction, so task completion and user satisfaction improve together.

Paper explainersAll themesAgents & Tool Use

A proactive agent should do more than wait for the next instruction. It should ask useful questions, gather missing facts, and push a task forward across several turns. But there is a trade-off: an agent that stays passive may miss user intent, while an agent that talks too much can waste time and annoy the user. This paper studies that trade-off and proposes a training method that rewards helpful initiative while suppressing unnecessary turns.

Zero assumption version

Why proactive behavior can help or hurt

In a multi-turn task, the agent often needs information the user did not state directly. A passive system may fail because it never asks for the missing detail or never checks whether its plan still matches the user's real goal.

But more interaction is not automatically good. Extra questions, repeated confirmations, or unnecessary planning steps can lower user satisfaction because the task feels slower and more burdensome. The paper asks how to train an agent that is active when action helps and quiet when extra turns add little value, because the best policy depends on whether the next turn will change the outcome enough to justify its cost.

The paper's move in one sentence. Use reinforcement learning with two behavioral pressures at once: one pressure encourages useful initiative and information gathering, while the other pressure discourages redundant or misaligned interaction.

The algorithm as a flow

What it actually does

Collect multi-turn interaction traces

Observe tasks where the agent can ask questions, plan, and act across several turns because proactive behavior only appears in extended interaction.

Reward helpful initiative

Increase reward for actions that gather missing facts or move the task forward because those behaviors reduce failure from passivity.

Discourage low-value interaction

Penalize redundant or misaligned turns because excessive initiative can hurt user satisfaction.

Train the agentic policy

Update the policy so that it balances task completion against interaction quality under the combined reward.

Evaluate the full trade-off

Compare task success and user-facing interaction quality together because improving one at the expense of the other does not solve the real problem.

What the paper changes

What the paper changes

The paper changes the reward design for proactive agents. It does not only reward finishing the task. It also shapes how the task is pursued by encouraging useful initiative and discouraging turns that consume user focus, which is the limited effort a person can spend on the interaction, without helping.

the object it moves  =  the behavior the reward signal encourages during a multi-turn task
The hidden quantity

The hidden quantity

measured quantity  =  the value of one more proactive action

The key hidden quantity is marginal interaction value: whether one more question, one more plan step, or one more action will improve the outcome enough to justify the added turn, because every extra turn carries a user cost. That value changes from moment to moment.

BAO tries to expose that quantity with two reward pressures. Helpful initiative earns reward when it uncovers missing intent or useful information. Wasteful initiative loses reward when it repeats known facts or adds delay without new value.

Why it works

Why this works: reward initiative only when it earns its place

A purely task-focused reward can teach the wrong lesson. If one agent succeeds by asking many low-value questions, that behavior may be reinforced even though users dislike it. A purely interaction-light reward has the opposite problem because it can teach the agent to stay quiet when action is needed.

BAO works by splitting the training pressure. One part says to gather information and plan when those moves improve task success. The other part says to avoid redundant interaction because user focus is limited. That combination can move the trade-off curve outward because the agent learns to be active where the expected value is high and restrained where the expected value is low.

Math after the picture

Combine task reward and interaction penalties

First in words:

A simple summary is that the training objective adds reward for task progress and useful initiative, then subtracts a cost for redundant or misaligned interaction.

Then the compact form:

total_reward = task_reward + proactive_gain - interaction_cost

Every symbol:

task_rewardreward for completing the task well
proactive_gainextra reward for initiative that uncovers useful information or advances the task
interaction_costpenalty for redundant, unnecessary, or user-misaligned turns
total_rewardcombined signal used to update the policy
A tiny worked example
Suppose an agent asks one clarifying question that reveals a missing delivery address.
That question adds 4 points of proactive gain because it unlocks the right task path.
The same run includes two extra confirmation turns that add no new information, so the interaction cost is 2.
If the task reward is 8, the total reward is 8 + 4 - 2 = 10.
A passive run that never asks the clarifying question may avoid the interaction cost, but it can still score lower because the task reward drops when the address remains unknown.

The main point is that one more turn is not judged by its existence alone. It is judged by whether it created enough task value to outweigh its burden.

What can go wrong

What can go wrong

The reward can misjudge user burden. If the penalty term misses what users truly dislike, the agent may still learn awkward interaction because the penalty is aimed at the wrong behavior.
Task reward can dominate the balance. If success reward is much larger than interaction cost, the agent may still overtalk because extra turns keep paying off under the current scale.
Useful initiative can depend on domain context. A question that is helpful in one task may be wasteful in another, which means reward design must match the structure of the target workload.
Done right. The method is strongest when user burden is measured carefully and task reward is scaled to it, because then the agent learns that initiative is valuable only when it changes the outcome enough to justify the turn.

What a runnable demo should prove

Build a multi-turn assistant task where some goals are underspecified, such as booking, shopping, or form completion. Compare a passive baseline, a task-only reinforcement-learning baseline, and a BAO-style system with both initiative reward and interaction penalties.

Track task completion, number of turns, and a user-burden score based on redundant questions or confirmations. The BAO-style system should land at a stronger trade-off point because it asks when a missing fact blocks progress and stays quiet when one more turn would add little value.
