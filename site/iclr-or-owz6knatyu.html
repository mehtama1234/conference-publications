Graph Homophily Booster: Creating feature nodes to fix broken graphs

Add invisible nodes that collect similar nodes together, turning a broken graph where neighbors are different into one where neighbors are alike.

Paper explainersAll themesGraph & Geometric Learning

Graph neural networks read the pattern of how nodes connect to predict labels or features. But in real data, connected nodes often have opposite labels (a friendship between rival fans, a link in a biology network that breaks a function). When you run a normal graph neural network on such data, it fails worse than just ignoring the graph and guessing from features alone. This paper fixes it by physically rewiring the graph: add new invisible nodes that pull together all the nodes with similar features, so the graph now matches the assumption that neighbors should be alike.

Zero assumption version

When connected nodes are opposites

A graph neural network works by letting each node ask its neighbors about their features, then mixing those neighbor answers into its own prediction. This only works well if neighbors are similar. But real graphs are messy: friends disagree; biological proteins that interact serve opposite roles; web pages that link to each other have opposite viewpoints.

If you try a normal graph neural network on this broken kind of graph, it gets confused. The network learns that neighbors are bad signals for prediction—which contradicts its whole design. Experiments show 23 recent graph networks do worse than a simple model that never even looks at the graph structure, just guesses from the node's own features alone. The graph is actually hurting performance.

The fix. Add invisible nodes that act as gathering points for similar nodes, so the graph gets rewired to connect alike neighbors instead of opposite ones.

The algorithm as a flow

What it actually does

Find feature clusters

Group all nodes that share the same or similar feature patterns.

Add a collection node per cluster

Create one invisible node for each group of similar-feature nodes.

Wire the collectors to their group

Connect each cluster node to every node in its group via edges.

Keep original graph edges

Do not delete real connections; add the new collector layer alongside them.

Run graph neural network on the new graph

The network now sees neighbors as allies, not enemies, and learns properly.

What the paper changes

The thing that changes

The method rewires the graph structure itself by adding new invisible nodes (called feature nodes) and connecting them to all nodes with matching features.

the object it moves  =  Graph edges (via new feature nodes)
The hidden quantity

Graph homophily: when neighbors are allies

measured quantity  =  Homophily fraction

Homophily is a single number between 0 and 1 that measures: of all edges in the graph, what fraction connects nodes with the same label or similar features? A homophily of 1 means every neighbor has exactly your label; 0 means no edge ever connects similar nodes. Most graph neural networks assume homophily is high (neighbors are alike).

This paper measures homophily before and after adding feature nodes. The metric is: (number of edges connecting same-label nodes) / (total edges). On real heterophilic datasets, this fraction starts low (0.1 to 0.3), so the network is broken. After adding feature nodes, homophily increases to 0.6–0.8, and the network suddenly works.

Why it works

Why adding invisible collection nodes fixes the problem

A graph neural network predicts a node's label by asking: what do my neighbors know? If neighbors have opposite labels, this question is sabotaged. The network learns to ignore neighbors entirely.

The paper's insight is that you do not need to change the network itself. Instead, rewire the graph so neighbors become allies. Create a new invisible node for every distinct feature value or feature cluster. Connect this collector to all nodes that have that feature. Now a node's neighborhood includes (1) its original neighbors (still diverse) but also (2) collector nodes that serve as aggregation points for nodes with matching features. When the network asks its neighbors, it now hears both the original noisy edges and these new feature-based connections. The feature-based paths are clean signals, while the original edges are downweighted or ignored. The network now learns what neighbors tell it, instead of learning to ignore them.

Because the new nodes are invisible to the label prediction task and only serve as signal carriers, the method works even on architectures designed for homophilic graphs. The addition improves the input (the graph), not the model, which means any graph network—whether old or new, simple or complex—benefits immediately because it now receives a graph where neighbors are naturally similar.

The homophily formula

First in words:

Homophily is the count of edges between same-label nodes, divided by the total edge count.

Then the compact form:

H = (edges where label[u] == label[v]) / (total edges)

Every symbol:

Hhomophily fraction, from 0 to 1
u, vtwo nodes at the ends of an edge
label[u]the true class label of node u
label[v]the true class label of node v
total edgesthe count of all edges in the full graph
Concrete example: counting homophilic edges
Suppose a graph has 10 edges total.
Edges 1,3,4,8,11 connect nodes with the same label (5 edges).
Edges 2,5,6,7,9,10,12 connect nodes with different labels (7 edges).
Homophily = 5 / 10 = 0.5 (half the edges connect similar nodes).
After adding feature nodes, 8 of the 15 new edges are homophilic.
New total edges = 10 + 15 = 25, homophilic = 5 + 8 = 13.
New homophily = 13 / 25 = 0.52, slightly higher, enough for the network to learn from neighbors again.

The homophily fraction measures whether the graph structure already matches the network's assumption that neighbors have similar labels.

What can go wrong

What can go wrong

Too many feature nodes added. If the graph has thousands of distinct feature values, the collection layer becomes huge, adding computational cost and memory. The method scales best when feature clusters are coarse or discrete.
High homophily graphs get worse. If the original graph is already homophilic (neighbors already similar), adding feature nodes introduces noise. The method is designed for heterophilic graphs; applying it to good data is wasteful.
Feature nodes must match the true structure. If the features you use to cluster do not align with the prediction task (e.g., clustering by color in a gender-prediction task), the new edges mislead the network. The method requires that similar features are actually predictive.
Done right. Choose features that correlate with the prediction target, run on genuinely heterophilic data, and accept the added edges as long as total graph size remains reasonable.
What a runnable demo should prove

What a runnable demo should prove

Build a small heterophilic graph where nodes with opposite labels are connected (e.g., pairs of nodes: label A-to-B, label B-to-A, forming a bipartite pattern). Train a standard graph neural network and record accuracy on a test set. Then apply GRAPHITE: create feature cluster nodes (e.g., one for all label-A features, one for all label-B features) and add edges from each node to the cluster node matching its label. Retrain the same graph network on the augmented graph. Record accuracy again.

improvement = (accuracy with GRAPHITE) - (accuracy without)

The demo succeeds if accuracy jumps substantially (e.g., from 40% to 75%) because the network can now rely on neighbors as signal instead of noise.
