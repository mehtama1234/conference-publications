ABBA-Adapters: Efficient and Expressive Fine-Tuning

ABBA decouples fine-tuning updates from the pretrained model by multiplying two independent low-rank learnable matrices, giving more expressivity than LoRA in the same space.

Paper explainersAll themesLLMs & Foundation Models

When you adapt a large language model to a new task, you do not want to retrain all its weights—that costs too much memory and time. LoRA solves this by learning two small matrices that, when multiplied together, approximate the weight updates needed. But LoRA's expressivity (how varied its updates can be) is limited by the rank chosen. ABBA breaks this bottleneck by using two independent low-rank matrices multiplied element-wise—a Hadamard product—rather than a single low-rank outer product, freeing both matrices to learn any shapes they need.

Zero assumption version

LoRA is cheaper than full retraining, but too rigid

Large language models have billions of weights. Retraining all of them on a new task would require storing the model twice over (the original weights plus the updates), which exhausts memory on most hardware. LoRA solved this by learning only two small matrices: if you want to change a weight matrix W, instead of storing a full update matrix (which is huge), you store A and B—much smaller—and compute the update as A multiplied by B. The result sits in the same shape as W.

The catch: the rank (the size of A and B) sets a hard ceiling on how much variety the update can express. If you need to change weights in ways that do not fit a low-rank pattern, LoRA cannot capture it, no matter how much training happens. It is forced into a mathematical straitjacket.

In one sentence. ABBA learns two independent low-rank matrices and multiplies them element-by-element, not as outer products, so both can learn freely instead of being locked into a rank-constrained shape.

The algorithm as a flow

What it actually does

Load the pretrained model

Keep all original weights frozen; add two small learnable matrices.

Multiply matrices element-wise

For each position in the weight, multiply the corresponding values from matrix A and matrix B.

Add the update to the original

The element-wise product becomes the actual weight change when the model answers questions.

Train on the new task

Training only changes A and B, never the frozen weights; the element-wise product learns task-specific patterns.

Use the fine-tuned model

Run the model with frozen weights plus the learned element-wise updates, at a tiny memory overhead.

What the paper changes

What the paper changes

ABBA changes how the weight update is built. Instead of learning a single low-rank outer product (as LoRA does), ABBA learns two independent low-rank matrices and computes their element-wise product—called a Hadamard product. This single change unleashes both matrices to adopt any shape the task requires, rather than forcing them into a rank-constrained bottleneck.

The hidden quantity

Expressivity: the width of shapes the update can learn

measured quantity  =  Expressivity score (the span of learnable patterns)

Expressivity is a measure of how many different weight-change patterns the fine-tuning method can represent. LoRA's outer-product structure means that only patterns with a specific rank can be learned; shapes that do not align with that rank are invisible to training, no matter how hard it tries. ABBA, by using an element-wise product of two independent matrices, can represent patterns that LoRA cannot—it is not confined to a rank-limited subspace.

The paper estimates expressivity by running matrix reconstruction experiments: given a target weight update, how well can LoRA reconstruct it versus ABBA? ABBA wins because its element-wise product is not constrained by rank in the same way. The hidden quantity is essentially how much of the true update the method can capture, and ABBA captures more without storing more trainable values.

Why it works

Why element-wise multiplication frees both matrices

LoRA learns two matrices A and B and multiplies them together (called an outer product). This factorization forces A and B to cooperate: if A is size 10 by 2 and B is size 2 by 100, their product must always be a rank-2 matrix (a geometric term for how 'flat' the result is). No amount of training can escape that ceiling because matrix multiplication itself is what creates the bottleneck.

ABBA breaks this by computing A times B element-wise (multiplying each position separately, not as a matrix product). Element-wise multiplication does not flatten the result in the same way. If A is size 10 by 100 and B is also size 10 by 100, their position-by-position product can take any shape, because at each spot the value is simply A's value times B's value. Neither matrix constrains the other. Both can learn independently to capture task-specific patterns. The update is no longer imprisoned in a low-rank subspace; it lives in the full space but is stored compactly because each of A and B is itself low-rank.

Math after the picture

The update equation

First in words:

The weight update is the element-wise product of two learnable low-rank matrices A and B. For each weight at position i-j, the change is A at i-j times B at i-j.

Then the compact form:

W_new = W_orig + (A ⊙ B), where ⊙ is element-wise (Hadamard) product, A ∈ ℝ^(d_in × r), B ∈ ℝ^(d_in × r), r is rank

Every symbol:

W_origthe frozen pretrained weight matrix
Afirst learnable low-rank matrix, d_in rows and r columns (r is small)
Bsecond learnable low-rank matrix, same shape as A, also rank-constrained
A ⊙ Belement-wise product: multiply each A[i,j] by B[i,j] to get the update
rrank: the number of columns (how much of each matrix's 'basis' is stored); same r as LoRA
d_indimension of the weight; the number of rows in A and B
A tiny worked example
Suppose A and B are 3 by 2 (rank 2). Each has 6 learnable values. LoRA also uses 3 by 2, so same count of trainable values so far.
A = [[2, 0.5], [1, 1], [0, 2]] and B = [[1, 2], [3, 0], [2, 1]] (arbitrary example).
Element-wise product A ⊙ B at position (0,0): A[0,0]=2, B[0,0]=1, so product=2*1=2.
At position (0,1): A[0,1]=0.5, B[0,1]=2, so product=0.5*2=1.
At position (1,0): A[1,0]=1, B[1,0]=3, so product=1*3=3.
Full product is [[2,1], [3,0], [0,2]]. This is the weight update; each position is independent, so the pattern can be any shape, not confined to rank 2.

LoRA would compute A @ B (matrix multiplication), which forces the result to be exactly rank 2; ABBA's element-wise product lifts that constraint.

What can go wrong

What can go wrong

If rank is set too low, the two matrices still cannot compensate for each other. Unlike LoRA, ABBA's two matrices are independent, so if r is very small (say r=1), each matrix individually must be low-rank. The gain comes when rank is moderate; at rank 1, both methods collapse similarly.
The element-wise product is not a magic amplifier—it only helps when patterns resist low-rank structure. If the true weight update happens to decompose neatly as an outer product (a high-structure pattern), LoRA and ABBA will perform similarly. ABBA excels when updates are idiosyncratic and do not align with any single low-rank plane.
Computational cost per forward pass slightly increases. LoRA computes a matrix product. ABBA computes an element-wise product, which costs about the same, but storing two full-size matrices (instead of one small one times one large one in LoRA's case) uses more memory cache. In practice the overhead is small.
Done right. Choose rank 4 to 8 to balance expressivity and memory. Validate on a held-out task before deployment. ABBA shines on tasks requiring rich, non-compressible updates, such as arithmetic and reasoning.
What a runnable demo should prove

What a runnable demo should prove

Build a small language model (say 124 million trainable values) and fine-tune it on a reasoning task (e.g., math word problems or commonsense QA) using LoRA and ABBA side by side with the same rank (size 8). Measure accuracy on a held-out test set. Run a matrix reconstruction experiment: given the true weight deltas (computed via full fine-tuning), how well does each method approximate them? Plot the reconstruction error as rank increases. This will show that ABBA reconstructs the true updates more faithfully, especially at moderate ranks, proving the expressivity claim.

Reconstruction error = mean squared difference between true weight update and the learned approximation

At rank 4 and rank 8, ABBA's reconstruction error should be visibly lower, and final task accuracy should be higher, without storing any more trainable values than LoRA.
