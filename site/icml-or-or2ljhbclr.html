Eating for a Sustainable Planet: Personalized Sustainable Diet Recommendation via Constraint-Aware Decision-Making Modeling

The paper recommends meals by treating sustainability as explicit constraints and personal taste as the thing to optimize inside those limits, so better planetary choices do not depend on pretending people directly prefer them.

Paper explainersAll themesOther

Diet recommendation is not a one-number problem. A meal plan should satisfy nutrition, cost, cultural fit, and environmental impact at the same time. Population-level studies can say what a sustainable diet should look like on average, but an individual recommender must still respect what a person is willing to eat. This paper separates those roles. It treats personal preference as the objective to maximize, while sustainability enters as learnable constraints that define which choices are acceptable. That lets the system search for meals a person is likely to adopt without abandoning the broader sustainability requirements.

Zero assumption version

Why sustainable diet advice is hard at the individual level

A sustainable diet must satisfy several requirements at once. The meals should nourish the person, stay affordable, fit their habits, and reduce environmental burden. Many recommendation systems treat all of those concerns as if they were just more user preferences. That is risky because a person may prefer meals that violate nutrition or sustainability limits.

The paper argues that sustainability should not be modeled only as a taste signal. Instead, sustainability should define what is allowed, while the recommender uses personal preference to choose among the allowed options.

The central design choice. Do not ask the model to guess that users secretly prefer sustainability. Put sustainability into the decision constraints and optimize preference inside those bounds.

What it actually does

Build a broad recipe set.

Use the SusDiet collection so the system has recipes with measured nutrition, cost, culture-related properties, and environmental indicators.

Estimate user preference.

Learn which meals each person is more likely to accept from interaction history or preference signals.

Learn sustainability constraints.

Represent the four sustainability pillars as constraints whose strength can be learned from data, because different settings may require different tradeoffs.

Filter to feasible meals.

Keep only recommendations that satisfy the learned constraint set.

Rank feasible meals by preference.

Among the acceptable options, recommend the meals the user is most likely to choose.

What the paper changes

What the paper changes

The paper changes the decision rule from preference-only ranking to constrained decision making, where personal taste is optimized inside a sustainability-feasible set.

the object it moves  =  the rule that turns user preference and meal attributes into final recommendations
The hidden quantity

The hidden quantity

measured quantity  =  the feasible region where a meal is both sustainable enough and personally acceptable

The hidden quantity is the feasible region of meals that satisfy the sustainability requirements while still remaining plausible choices for the individual. A recommendation is only useful if it falls inside that region. Too strict a constraint set can remove nearly everything the user will accept, while too loose a set lets unsustainable options through.

The paper learns this region instead of fixing it by hand. That matters because the practical decision is not to maximize sustainability alone or preference alone. It is to choose the best meal from the set that respects both.

Why it works

Why constraints help more than pretending sustainability is a preference

If the system treats sustainability as just another taste feature, it can decide that a user's immediate preference outweighs the diet requirements. That gives high click or acceptance scores but poor real-world sustainability. Constraint-aware decision making avoids that failure because the model first determines which meals are acceptable under the sustainability pillars.

The learned constraints matter because real settings differ in how tight each pillar should be. Once the feasible set is formed, preference ranking becomes useful again because it chooses the option the user is most likely to adopt among the meals that already satisfy the broader requirements.

Math after the picture

Maximize preference subject to sustainability limits

First in words:

Choose the meal with the highest predicted user preference among those that satisfy the learned nutrition, affordability, cultural, and environmental constraints.

Then the compact form:

meal^* = argmax_m pref(user, m) subject to c_k(m) <= tau_k for all k

Every symbol:

meal^*the final recommended meal
ma candidate meal or recipe
pref(user, m)the predicted preference score of the user for meal m
c_k(m)the value of meal m on sustainability requirement k
tau_kthe learned allowable limit for sustainability requirement k
kone of the four sustainability pillars
A tiny worked example
Suppose Meal A has preference score 9 but fails the environmental limit.
Meal B has preference score 8 and satisfies all four limits.
Meal C has preference score 7 and also satisfies all four limits.
Meal A is removed because it violates a constraint.
Meal B is chosen because it is the most preferred option inside the feasible set.

The paper's learned constraints can be more flexible than fixed thresholds, but the decision structure is exactly this: optimize taste inside a sustainability-feasible set.

What can go wrong

What can go wrong

The learned constraints can be miscalibrated. If the constraint strengths are set too loosely, unsustainable meals slip through, and if they are set too tightly, the system may recommend meals that users reject because the feasible set is too narrow.
Preference signals may reflect short-term habit only. If the model learns from very narrow past choices, it can underestimate meals the user would accept after small guidance because it only sees current habit.
Dataset coverage may be uneven. If some cuisines or affordability bands are underrepresented, the recommender may struggle to find feasible meals for those groups because the candidate pool itself is biased.
Done right. The method works when the recipe pool is broad and the sustainability limits are well learned, because then the model can offer realistic meals that satisfy the full decision problem.
What a runnable demo should prove

What a runnable demo should prove

Build a small meal recommendation sandbox with recipes labeled by calories, nutrient balance, cost, cuisine tag, and carbon estimate. Simulate a few users with different taste profiles. Compare an unconstrained ranking model with a constraint-aware recommender that first filters by sustainability rules and then ranks by preference.

The demo should show higher sustainability compliance with only limited loss in acceptance because the constraint-aware system recommends the best meal inside a feasible set instead of recommending the overall favorite regardless of impact.

feasible_acceptance = accepted_recommendations_that_meet_all_constraints / total_recommendations

The decisive result is more accepted recommendations that satisfy all four pillars, because that is the practical definition of a sustainable personalized diet system.
