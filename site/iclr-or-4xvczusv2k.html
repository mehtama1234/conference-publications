Diverse and Sparse Mixture-of-Experts for Graph OOD Learning

Train a team of specialized graph experts that each learn different causal patterns, and let a learned gate pick the right expert for each new graph.

Paper explainersAll themesGraph & Geometric Learning

Real-world graphs come with hidden causal rules that differ from graph to graph. A single model struggles to learn one rule well when different inputs follow different causal rules. This paper trains multiple experts (think specialized branches of the model) that each learn a distinct causal rule, then uses a learned gate (a decision maker) to pick the right expert for each new graph, without needing to know which rule applies.

Zero assumption version

Why one model breaks on varied causal rules

Graphs in the real world are not all the same. A social network graph might encode friendship rules (your friends tend to be your friends), while a molecule graph encodes chemical rules (atoms bond based on valence and energy). When you train a single model to predict node labels (like predicting a user's interests or an atom's reactivity), the model has to learn rules that work for all graphs at once. But each graph follows its own causal rule, and one rule that works for graphs like the training set often fails badly on graphs that follow a different causal rule. This is called out-of-distribution (OOD) failure.

A naive approach tries to fix this with data augmentation (drawing extra copies of the graph by adding noise or removing edges), but this backfires: tweaking a social network might destroy the actual friendship structure, or tweaking a molecule might change what element it is. A smarter naive approach assumes there is one true causal rule hiding inside all graphs, and tries to find it by penalizing the model to ignore confusing edge patterns. But this assumption is often wrong. Some graphs really do follow different causal logics.

The problem in one sentence. A single model cannot learn different causal rules for different graphs without either breaking the graphs or making false assumptions about what is causal.

The algorithm as a flow

What it actually does

Train multiple experts

Build several copies of the graph model, each with different random weights. Let them train on all graphs.

Enforce that experts disagree

Add a penalty that rewards each expert for learning a different causal pattern (diversity loss). Prevents all experts from collapsing to the same rule.

Train a gate (learned router)

Build a small network that reads a graph and outputs a score for each expert. Higher score means more trust in that expert for that graph.

Use sparse weights

Force the gate to give high weight to only a few experts per graph (sparse routing). Each graph trusts one or two experts, not all of them.

Mix the experts

Each graph gets a weighted blend of expert predictions, with weights set by the gate. The blend adapts to which experts the gate trusts for that graph.

What the paper changes

What the paper changes

The paper changes the routing weights (how much each graph trusts each expert). Instead of every graph using every expert equally, the gate learns to assign sparse, unequal weights. For graph A it might say: 90% trust Expert 1, 10% trust Expert 3, 0% the others. For graph B it assigns different weights.

the object it moves  =  routing weights
The hidden quantity

Semantic diversity: how different are the experts?

measured quantity  =  semantic diversity

Semantic diversity is a measure of how much the experts' learned causal rules differ from each other. If all experts learn the same rule, diversity is zero and you have wasted training time. If each expert learns a different rule, diversity is high. The paper measures diversity by checking: when two experts see the same graph, how different are their predictions? Experts that output very different predictions for the same input have learned different causal rules.

The paper uses semantic diversity as a loss term during training. It adds a penalty that rewards experts for disagreeing. This prevents the classic failure mode of mixture-of-experts: all experts collapse to the same solution because it is the easiest path.

Paper reading. Semantic diversity is operationalized as a differentiable penalty on the divergence (or pairwise disagreement) of expert outputs. This drives the optimization to find diverse expert solutions.
Why it works

Why sparse diverse experts fix the OOD problem

The core mechanism has two pieces. First, training multiple experts with a diversity penalty ensures that each expert learns a different causal rule. Expert A becomes the friendship expert, Expert B becomes the chemistry expert. They learn by seeing all training graphs, but each one specializes because the diversity loss rewards disagreement.

Second, the sparse gate learns to route each graph to the experts that know its causal rule. When the gate sees a graph from distribution A (like friendship networks), it learns to give high weight to Expert A. When it sees distribution B, it weights Expert B higher. Because the gate has access to the graph structure during training, it can learn which graph properties indicate which causal rule. On a new graph at test time, the gate reads the same properties and routes to the right expert again, even if that test graph is from a distribution never seen before. This works because the gate is learning to match graph properties to causal rules, not memorizing specific graphs.

Sparsity (giving high weight to only a few experts per graph) matters because it prevents all experts from contributing equally. If every expert contributed to every prediction, the diverse rules would blur together and you lose the benefit of specialization. Sparse weights force each prediction to come from a small team of experts that specialize in that graph's causal rule.

Math after the picture

The routing and loss equation

First in words:

Total loss is the prediction error on labeled graphs plus a diversity penalty plus a sparsity penalty. Routing weights come from applying softmax to expert scores output by the gate, then zeroing out all but the top K scores.

Then the compact form:

L_total = L_pred + lambda_div * L_div + lambda_sparse * L_sparse, where routing weights w_i = (softmax(g(x)))_i, and w_i set to zero unless in top-k

Every symbol:

L_predprediction error (how wrong the final answer is on the labeled training graphs)
L_divdiversity loss (penalty that grows when experts agree, shrinks when they disagree)
L_sparsesparsity loss (penalty that encourages most weights to be zero)
lambda_divhow strong the diversity push is (a tuning knob)
lambda_sparsehow strong the sparsity push is (another tuning knob)
g(x)the gate network function (a small neural network that reads the graph x)
softmaxconvert raw scores into fractions that add up to 1 (so weights are probabilities)
top-kkeep only the k highest scoring experts, zero out the rest
A tiny worked example with two experts and three graphs
Graph A comes in. Gate outputs raw scores [5.0, 2.0] for experts [E1, E2].
Softmax converts to weights [0.73, 0.27] (roughly 73% E1, 27% E2).
Sparsity (k=1) zeros out E2: weights become [1.0, 0.0]. Only E1 predicts.
E1 outputs pred=8, E2 outputs pred=3. Final blended answer = 1.0*8 + 0.0*3 = 8.
Graph B comes in. Gate scores [2.5, 4.0]. Softmax gives [0.27, 0.73].
Sparsity forces to [0.0, 1.0]. E2 alone predicts. E2 outputs pred=5.
Diversity loss checks: E1 said 8 on A, E2 said 3. On B: E1 would say ~7, E2 says 5. High disagreement = low penalty = good.
Prediction loss checks: Graph A true label is 8 (E1 got it right). Graph B true label is 5 (E2 got it right). Both losses are small.

The gate learns to pick the right expert for each graph by minimizing prediction loss; diversity loss ensures experts learned different rules in the first place.

What can go wrong

What can go wrong

All experts collapse to one rule anyway. If the diversity penalty is too weak, experts ignore the disagreement reward and all learn the same rule to minimize prediction loss. Solution: tune the diversity weight lambda_div higher.
Gate learns to ignore graph structure. The gate might learn a shallow pattern (like routing by graph size alone) that works on training but fails on a new OOD graph with different size distribution. Solution: validate the gate's routing on a held-out distribution during training, or use domain-informed graph features.
Sparsity is too aggressive. If you force k=1 (only one expert per graph) and that expert is slightly off, there is no backup. A graph from a hybrid causal rule might need two experts. Solution: tune k (the sparsity level) per dataset.
Done right. When experts are truly diverse, the gate learns which graph patterns signal which causal rule, and k is tuned for the data, the sparse MoE routes each graph to its matching experts and accuracy stays high even on graphs with new causal rules.
What a runnable demo should prove

What a runnable demo should prove

Build a small graph dataset with two clear causal rules: a friendship rule (predict users with similar friends) and a hobby rule (predict users with similar hobbies, ignoring edges). Train a single model, a diverse MoE, and a mixed baseline (multiple experts but no diversity penalty) on a mix of both rule types. Then test on a new graph set that is 80% friendship, 20% hobby (a distribution shift away from the balanced training set). Measure accuracy for each method.

OOD accuracy = (correct predictions on new distribution) / (total graphs on new distribution)

The diverse sparse expert model should maintain high accuracy on the distribution shift, while the single model and non-diverse MoE should drop. This proves that diversity (not just multiple experts) and sparse routing (not uniform blending) are both necessary to handle different causal rules.
