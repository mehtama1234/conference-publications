Hallucination Begins Where Saliency Drops

Hallucinations occur when a model forgets its prior outputs; catch them by watching when the gradient flow from context weakens.

Paper explainersAll themesInterpretability

Vision-language models (models that read pictures and text together) sometimes invent details that were never in the image. The paper shows this happens at a precise moment: when an output word has lost its connection to what came before, measured by combining two signals (attention weights and the slope of how much each weight matters) into one score called saliency. Armed with this insight, the paper presents two fixes: one that silently rejects bad words before they enter the sequence, and another that forces the model to stay glued to its recent outputs.

Zero assumption version

Attention alone is blind to hallucinations

When a vision-language model generates captions or answers questions about images, it builds the answer word by word. At each step, it reads all previous words and the image, and picks the next word. A naive approach is to look at which previous words the model is paying attention to—a thing called an attention map. But here is the catch: attention maps look almost identical whether the model is about to say something true or invent a detail.

The real problem is that attention weights tell you where the model is looking, not whether it understood what it saw. A word can have high attention to prior outputs but still be disconnected from their meaning—like glancing at a name tag without reading it. The model needs a deeper signal: one that shows not just where it is looking, but how strongly that prior context is influencing the decision to output the next word.

The fix in one sentence. Fuse attention weights with their gradients (a number showing how much each weight matters to the final answer) to measure whether prior outputs are truly grounding the next prediction, then reject words that fail this test.

The algorithm as a flow

What it actually does

Compute saliency for every candidate word

Before accepting a word, score how much previous outputs influence it (attention times gradient).

Compare to a threshold

If saliency is high enough, accept the word; if too low, skip it and try the next best option.

Fallback to best available

If all candidates fail the threshold, pick the one with highest saliency to avoid getting stuck.

Boost attention to recent words

After each new word is chosen, amplify model's attention to the last few outputs.

Generate with grounding

Repeat for each new word, maintaining constant pressure to stay connected to prior output.

What the paper changes

What the paper changes

The paper modifies one thing when the model is answering a question (the decoding process): which words pass the quality gate. Instead of accepting every top candidate, it now filters by a new measure (saliency), and amplifies attention weights (via a multiplier called gamma) in the self-attention layer to reinforce recent-output dependencies. The actual model weights are not trained or changed; only the decision-time choices and temporary attention modifications shift.

the object it moves  =  Word filtering and attention amplification
The hidden quantity

The hidden quantity: saliency, or grounding strength

measured quantity  =  Saliency (gradient-weighted attention)

Saliency is a number for each word in the output sequence that tells you how tightly that word is connected to the prior context. It is computed as a product: attention weight times the gradient of that weight with respect to the loss function (the model's error). The attention weight tells you the model is looking; the gradient tells you how much that look matters. Multiplying them together reveals which words truly depend on prior context versus which are running on autopilot.

The paper estimates saliency by running a single backward pass (a gradient computation, the same operation used during training) and fusing it with the forward-pass attention. This is why the method is called gradient-aware: it requires computing gradients to expose hallucinations, unlike older methods that only look at attention maps. The saliency is highest when a word both attends heavily to previous outputs and when that attention is critical to the model's confidence in the answer.

Why it works

Why it works: catching disconnection at its source

Hallucinations happen because the model's state (a list of numbers representing what it has seen and generated) can decay or lose information mid-sequence. When this happens, a new output word is generated with weak dependence on prior context. Attention weights alone cannot reveal this decay because the model can attend to prior words without actually understanding them—like a tourist reading a menu in a foreign language without comprehension.

By adding gradients to the signal, the paper exposes the true dependency: it asks, 'if this attention weight changed, how much would the error change?' High gradient means the weight is doing real work; low gradient means changing it would barely matter. A token that attends to prior outputs but has low gradient saliency is a warning: the model is glancing but not understanding. Rejection sampling blocks low-saliency tokens before they corrupt the sequence, because a word with weak connection to prior context will break coherence if accepted—it signals the model has lost its thread and should try a different candidate. Local coherence reinforcement (LocoRE) amplifies the attention weights to recent tokens using a distance-aware multiplier (giving stronger boost to the nearest prior words), forcing the model to keep close contact with its recent output history, because the decay in context happens gradually during generation and boosting attention to just-generated words prevents the state from drifting in the first place. Together, they transform hallucination detection from a passive observation into active prevention.

The saliency equation

First in words:

Saliency = Attention weight times its gradient, normalized per layer

Then the compact form:

S(l,h)_ij = A(l,h)_ij * (∂L/∂A(l,h)_ij), then average across heads and apply length normalization

Every symbol:

A(l,h)_ijattention weight from position i to j at layer l, attention head h
∂L/∂A(l,h)_ijgradient of loss with respect to that weight (how much the weight contributes to error)
S(l,h)_ijsaliency for that position pair (product of the two above)
Lthe loss (error) of the model on this sequence
βgain parameter for LocoRE (how much to amplify attention to recent tokens)
w_swindow size (how many recent tokens to reinforce)
A tiny worked example
Token 5, attending to Token 3: Attention weight = 0.8 (paying attention), Gradient = 2.4 (matters a lot to error), Saliency = 0.8 × 2.4 = 1.92 (high, grounded).
Token 7, attending to Token 2: Attention weight = 0.6 (some attention), Gradient = 0.1 (barely matters to error), Saliency = 0.6 × 0.1 = 0.06 (low, hallucinating).
Token 7 with saliency 0.06 is below the threshold (say 0.5), so it is rejected; next candidate is tested.
For the accepted token, LocoRE boosts attention to Tokens 5–6 by factor 1 + 0.3 = 1.3, making the model lean into recent output history.

Saliency fuses where the model is looking with how much that look matters, catching hallucinations by exposing context decay.

What can go wrong

What can go wrong

Threshold is too high. If the saliency threshold is set too conservatively, even coherent tokens are rejected and the model gets stuck generating fallback choices or repeating phrases.
Recent-output window is too narrow. If the window of previous outputs that LocoRE amplifies is tiny, the model may still lose track of context from a few steps ago, allowing mid-sequence hallucinations.
Gradient computation is expensive. Running a backward pass for every candidate token during decoding is slow; the method trades speed for hallucination safety, making it costly for real-time applications.
Done right. Set the threshold adaptively based on the model's confidence levels for the task, tune the window size by testing per model size, and use gradient checkpointing or batch processing to spread the backward-pass cost across multiple words.
What a runnable demo should prove

What a runnable demo should prove

Build a small demo that takes a vision-language model, generates a caption for an image, and logs the saliency score for each output token. Then feed the image with an instruction to hallucinate (e.g., 'describe the celebrity in the image' when there is none). Without the saliency filter, the model invents a name. With rejection sampling (SGRS), that invented token fails the threshold and is rejected, replaced by a generic fallback. Plot saliency over token position; the spike should occur right before the hallucinated phrase and drop sharply within it.

Hallucination rate = (hallucinated tokens before filtering) / (hallucinated tokens after SGRS + LocoRE)

The demo must make it impossible to miss the moment when saliency plummets and the hallucination begins—that is the paper's core insight made visible.
