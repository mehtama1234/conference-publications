Hallucination Begins Where Saliency Drops

Hallucinated words in vision-language models appear when recent outputs stop influencing the next prediction, and adding that influence back stops the hallucination.

Paper explainersAll themesInterpretability

Vision-language models sometimes output words that do not match what they see in the image — they hallucinate. Current methods try to catch hallucinations by watching where the model is looking (attention), but that only tells half the story. This paper adds a missing piece: tracking which parts of the model prediction chain actually matter for the next step, using gradient signals (which way the model would need to adjust). The finding: hallucinations happen when the most recent outputs stop influencing what comes next, breaking the chain of thought. The fix: when answering, reject words that break that chain, and add a lightweight reinforcement module to keep recent words mattering.

The World Before: Attention Alone Is Not Enough

Vision-language models (systems that read images and answer questions about them) sometimes generate words that are completely wrong or nonsensical — words that do not match what the image actually shows. When this happens, we say the model is hallucinating. A beginner might try to stop this by watching the model's attention (the parts of the image it is looking at when it writes each word). But looking at the image is not the only part of generation: the model also reads the words it just wrote to decide what comes next. Current methods ignore this second part.

Without tracking how much the previous words are influencing the next step, you cannot tell the difference between a deliberate choice and a derailed thought. The model might be looking at the right part of the image but not actually using what it said before — a broken chain of thought. So the previous word-based attention methods miss the real cause of hallucinations.

In one sentence. The paper measures which previous tokens actually steer the next prediction by combining where the model looks (attention) with how much that looking matters for the decision (gradients).

What the paper changes

What the Paper Changes

The paper modifies how the model decides which word to generate next. Instead of relying only on forward-pass attention (where the model looks), it adds a gradient-based signal (how much that location steers the decision). This fused signal is called saliency. The paper also adds a lightweight module when the model is answering that explicitly strengthens attention to recent outputs.

the object it moves  =  generation-time filtering and attention reinforcement
The hidden quantity

The Hidden Quantity: Saliency

measured quantity  =  saliency (fused attention and gradient signal)

Saliency is a number (or a set of numbers) that measures how much each previous output word influences the decision to generate the next word. It is calculated by taking the attention weight (how much the model is looking at that word) and multiplying it by the gradient (which way the model would need to nudge to change its score for that word). When saliency is high, changing that word slightly would change the next prediction a lot — the word matters. When saliency is low, the word is being attended to, but the model does not actually use it; the chain is broken.

The paper estimates saliency by running the forward pass (generating predictions) and the backward pass (computing how each word shifts the score for the next word). This fused signal reveals the true causal influence, which forward-pass attention alone cannot.

Why it works

Why It Works: Two Mechanisms

Vision-language models generate one word at a time. Before writing each new word, the model reads both the image and the words it has already written. The question is: how much do those recent words actually influence the choice of the next word? Saliency answers that. When saliency drops on recent outputs, it means the model has stopped listening to its own chain of thought — a sign the next word will not follow logically from what came before.

The fix has two parts. First, rejection sampling: when the model proposes a candidate word, we check its saliency first. If the saliency is below a learned threshold (set per prompt to adapt to context), we reject the word and try another, because a rejected word would break the chain and hallucinations happen when the chain breaks. Second, the reinforcement module: we add a lightweight layer that directly boosts attention from the current position to the most recent words, which keeps recent words in the model's mind during generation, because when recent words fade from attention the model loses track of context and hallucinates. Together, these keep the chain intact: the first mechanism blocks low-saliency words, and the second makes sure recent words stay highly salient, so hallucinations cannot form.

The Equation: Fusing Attention and Gradient

First in words:

Saliency for token i is the attention weight to token i multiplied by the gradient of the next token logit with respect to the activation for token i.

Then the compact form:

saliency_i = attention_i * gradient_i

Every symbol:

saliency_iHow much token i influences the next prediction (0 to 1, higher is stronger influence)
attention_iThe attention weight: fraction of focus on token i (0 to 1)
gradient_iThe gradient: how much the prediction logit changes if we nudge token i (computed via backprop)
A tiny worked example
Token A (recent output): attention = 0.8, gradient = 0.9 -> saliency = 0.8 * 0.9 = 0.72 (strong influence)
Token B (recent output): attention = 0.6, gradient = 0.1 -> saliency = 0.6 * 0.1 = 0.06 (weak influence despite high attention)
Token C (earlier): attention = 0.1, gradient = 0.5 -> saliency = 0.1 * 0.5 = 0.05 (minimal influence)
Rejection threshold = 0.10: Token A passes (0.72 > 0.10). Token B and C fail and are rejected during decoding. Next token inherits from a strong chain, no hallucination.

Saliency catches the case where the model attends to a word but does not actually use it — the broken chain that causes hallucination.

What can go wrong

What can go wrong

Threshold set too high. If the saliency threshold is too strict, even correct, coherent tokens get rejected, and the model becomes overly cautious and generates incoherent short sequences.
Gradient computation is expensive. Computing gradients at every decoding step adds computation. On very long sequences or resource-constrained devices, this overhead may be prohibitive.
The reinforcement module may over-correct. If the local coherence module is too strong, it can force the model to repeat or dwell on recent tokens instead of moving the story forward naturally.
Done right: adaptive thresholds and lightweight module. Learning a per-prompt threshold that adapts to context and keeping the reinforcement module small keeps both mechanisms balanced and effective.
What a runnable demo should prove

What a runnable demo should prove

Build a tiny vision-language model (or use a small pre-trained one) and have it describe a simple image with a known correct caption. Instrument it to log saliency for each token pair. Generate the caption twice: once with the baseline model and once with rejection sampling and the reinforcement module. Measure saliency for the baseline at the point where hallucination begins; measure it again with both fixes applied. Show that saliency stays high throughout with the fixes applied, and that the caption matches the image content.

hallucination_rate = (count of factually incorrect tokens) / (total tokens generated); target: show hallucination_rate baseline > hallucination_rate with_fixes
