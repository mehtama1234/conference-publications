AdaMEM: Test-Time Adaptive Memory for Language Agents

AdaMEM lets an agent update its working guidance during a long task by combining a stored history of past runs with short fresh strategy notes written during the current run.

Paper explainersAll themesAgents & Tool Use

Many agents can look up past experience, but they often do it only once at the start of an episode. After that first lookup, the retrieved advice stays fixed even as the task changes shape. That is a poor fit for long jobs such as web navigation or household planning, where early assumptions can become wrong halfway through the run. AdaMEM addresses this by splitting memory into two parts. A long-term store keeps earlier trajectories collected offline. A short-term store writes fresh strategy notes during the current run. The agent repeatedly updates those short notes as new evidence arrives. This gives the system a way to stay efficient and adaptive without changing model weights online.

Zero assumption version

Why one-shot memory retrieval is too rigid

An agent that starts a long task with one retrieved memory may look competent at first and then drift later. The reason is simple: the task unfolds, new facts appear, and the old advice may stop matching the current state. If the agent cannot revise its guidance, it keeps using stale plans.

Purely dynamic reasoning is not a complete answer either because recomputing everything at every step is expensive. The paper therefore asks how to keep the low-cost benefit of stored experience while still allowing the agent to adapt its guidance during the run.

The move. Keep a long-term store of past trajectories, but also write and refresh short strategy notes during the current task so the agent can adapt as the situation changes.

The algorithm as a flow

What it actually does

Store long-term experience.

Keep raw trajectories from earlier runs because those traces contain examples of what worked and what failed.

Retrieve relevant past runs.

Select earlier trajectories that resemble the current task so the agent begins from concrete experience instead of an empty context.

Write a short current strategy note.

Summarize the useful lesson from the retrieved runs in a compact form because a small guidance note is cheaper to reuse repeatedly than replaying full trajectories.

Refresh the note during the run.

Rewrite the short strategy note when new observations arrive so that the agent's guidance stays aligned with the latest task state.

Train the policy to use refreshed notes.

Use Step-MFT so the agent learns how to produce and follow high-quality strategy notes at each step.

What the paper changes

What the paper changes

The paper changes agent memory from a fixed pre-episode lookup into a two-level system with persistent trajectory storage and dynamically refreshed step-level strategy notes.

the object it moves  =  memory used during the run, not only before it
The hidden quantity

The hidden quantity: guidance freshness

measured quantity  =  how well the current strategy note matches the agent's latest situation

The key quantity is guidance freshness. Retrieved experience is only helpful if the advice still matches the state that the agent is currently facing. A note that was good ten steps ago can become harmful after the environment changes.

AdaMEM keeps freshness high by rewriting the short-term note during the episode. The long-term store supplies raw material, but the short note is what the agent actually consults repeatedly. That separation matters because the short note can stay compact while still reflecting the newest observations.

Why it works

Why it works

Long-term memory is useful because earlier trajectories contain concrete experience. Short-term memory is useful because long tasks change over time. AdaMEM gets both benefits by using the long-term store as a library and the short-term store as the current control panel.

The short note improves adaptation because it can be rewritten after each task-changing observation. That means the agent does not have to carry all past experience in full detail at every step. It carries only the currently useful lesson extracted from that experience.

Step-MFT strengthens the whole system because it teaches the policy to produce better strategy notes step by step. The benefit is not only better retrieval, because the agent also learns how to convert retrieved traces into compact guidance that is useful for the next action.

Math after the picture

The adaptation objective

First in words:

At each step, choose the short strategy note that best matches the latest state while staying grounded in useful past experience.

Then the compact form:

note_t* = argmax_n utility(state_t, n, retrieved_history_t)

Every symbol:

note_t*the short strategy note chosen at step t
state_tthe agent's latest task state at step t
retrieved_history_tthe past trajectories retrieved as support at step t
utility(state_t, n, retrieved_history_t)how useful note n is for the current state given the retrieved experience
A tiny worked example
Suppose an online shopping agent begins with the note 'sort by price and buy the cheapest item.'
Later it discovers that only in-stock items can ship today.
A refreshed note such as 'filter to in-stock items first, then sort by price' has higher utility because it matches the latest state.
The long-term history still matters because earlier trajectories may show how to use the stock filter correctly.
AdaMEM updates the note instead of keeping the stale first plan, so the next action matches the current task.

The equation expresses the paper's main idea: current guidance should be chosen for the present state, not frozen from the episode start.

What can go wrong

What can go wrong

Bad retrieval poisons the short note. If irrelevant past runs are retrieved, the strategy note can be refreshed in the wrong direction because its source material is weak.
Too much rewriting can create instability. If the note is rewritten on every minor change, the agent may overreact because it never keeps a stable enough plan to finish a subtask.
Weak note-writing skill limits the method. The memory system helps only when the policy can convert retrieved experience into useful short guidance, so poor note writing can block the gains because the agent may retrieve the right history yet still fail to turn it into a usable current plan.
Done right. The method works when retrieved trajectories are relevant and the short note is refreshed only when the latest state changes the best plan, because that keeps guidance both current and stable.
What a runnable demo should prove

What a runnable demo should prove

Build an agent task with a clear mid-run change, such as shopping where stock status and delivery constraints appear after several steps, or a household task where the required tool is discovered late. Compare three systems: no memory, one-shot memory retrieval at episode start, and AdaMEM with refreshed short notes. Track whether the agent changes course appropriately after new evidence appears. The demo should show that refreshed strategy notes improve late-task decisions because they keep guidance aligned with the current state.

adapt_success = tasks_with_correct_midrun_replan / tasks_with_midrun_change

A convincing demo must show that the agent adapts after the world changes, not only that it remembers the start, because AdaMEM is designed to keep guidance fresh during the run.
