Zero assumption version

One number per second, two kinds of invisible anomalies

A univariate time series is a sequence of single numbers arriving over time—temperature of a server, memory usage, request count. When something breaks, the number changes in a way that should stand out. But two kinds of anomalies hide: a small spike that lasts one or two seconds (gets buried in random noise), or a slow creep (rises 1% per hour, barely visible among the seasonal ups and downs of business hours). Older methods predict the next number and flag when reality misses the prediction—but on single numbers, there is barely enough information in any one moment to make a strong prediction.

A beginner might try: Just learn to predict the next value, and flag big gaps. This fails because the model has almost nothing to work with. Single numbers have no depth, no channels, no different features to cross-reference. If the model has seen only the past three numbers, it might see a pattern like (100, 105, 110) and guess 115—but if the season is 'morning peak traffic,' the real pattern repeats daily, not every second. The model misses the slow seasonal rhythm and gets fooled by random jitter or the creep of time.

The core challenge: Single-value time series lack enough detail per timestamp, so models cannot tell seasonal patterns from anomalies.

The algorithm as a flow

What it actually does

Step 1: Decompose noise

Strip out anomalies from the raw signal so seasonal patterns emerge clearly.

Step 2: Learn seasonal branch

A neural memory reads repeating patterns (morning is high, night is low).

Step 3: Learn local branch

A second neural memory reads short-term drifts (is it trending up today?).

Step 4: Predict normal value

Combine seasonal estimate plus local trend to forecast what normal should be.

Step 5: Flag gaps

If actual value is far from normal, raise an alert.

What the paper changes

What the paper changes: the loss function

The paper changes how the model learns. Instead of treating anomalies like random noise (and learning them anyway), the model first estimates and removes them, then learns only from clean normal data. This resets the training goal: fit a probabilistic (the model outputs uncertainty too, not just a guess) prediction of the true normal value, learned only from the scrubbed data.

The hidden quantity

The noise signal: what does not belong

measured quantity  =  Decomposed anomaly noise

The hidden quantity the paper tracks is the noise component that gets peeled away. Real time series contain seasonal patterns (repeating cycles), local trends (gradual changes), and anomalies (sudden breaks). The paper estimates which part of each value is 'anomalous noise' and which part is legitimate trend. This decomposition is not given by labels; the model infers it because the actual observations include anomalies but the seasonal and local branches' predictions should only reflect normal values.

During training, the paper uses anomaly masks (guesses about which timestamps are broken) to separate the signal. The loss function then computes prediction error only on timestamps the model thinks are normal, creating a feedback loop: if the noise estimate is right, fitting to the 'clean' subset trains both branches strongly on true patterns. The noise estimate is implicitly optimized to maximize this fit.

Why it works

Why splitting into seasonal and local lets you catch hidden anomalies

Here is the chain of cause-and-effect. On univariate data, a single predicted value carries very little information; the model cannot be confident. But if the model separates its task into two experts, each with a different memory of the past, each can find a different pattern. The seasonal branch reads the full history and asks, 'What time of day is it? What month? What is the typical value for this phase of the cycle?' It returns an estimate (e.g., 103 degrees for 2 PM). The local branch reads the recent short-term trend and asks, 'Are we warming or cooling right now? How fast?' It returns a delta (e.g., plus 2 degrees). Together, they predict 105 degrees (the sum of 103 and 2) in normal conditions.

The clever part: during training, the model also produces a guess for which timestamps are likely anomalies (by looking at how badly the two-branch prediction misses). It then retrains using only the 'normal' subset, refining both branch predictions on purely normal data. This breaks the anomaly's grip: a false alarm at 3 PM teaches the local branch to expect a warm afternoon, and the model learns the real seasonal rhythm instead of overfitting to the anomaly. Small spikes get ignored (they do not match any seasonal pattern and do not align with local trends, so they are marked noise), and slow creeps get caught (the local branch notices the daily trend is inching upward, and when a day hits its seasonal norm but the local branch says 'cooler than yesterday,' the combined prediction still does not match a true creep).

By cleaning the training signal, both branches learn the truth. When a new anomaly arrives (a value that hits neither seasonal pattern nor local trend), the prediction gap is large and obvious.

Math after the picture

The noise-decomposed loss function

First in words:

total loss = weighted seasonal prediction error + weighted local prediction error, where weights zero out anomalous timestamps

Then the compact form:

L = E[ w_i * (yhat_seasonal_i + yhat_local_i - y_i)^2 ], where w_i = 0 if timestamp i is anomalous, 1 if normal

Every symbol:

y_iactual value at timestamp i
yhat_seasonal_iseasonal branch prediction for timestamp i
yhat_local_ilocal branch prediction (delta) for timestamp i
w_iweight: 0 if anomaly detected, 1 if normal
Eaverage over time
A tiny worked example
Timestamp 1 (normal): actual=103, seasonal=100, local=2, combined_pred=102, error=(102-103)^2=1.0, weight=1.0, loss contribution=1.0
Timestamp 2 (spike): actual=150, seasonal=100, local=2, combined_pred=102, error=(102-150)^2=2304, weight=0 (anomalous), loss contribution=0
Timestamp 3 (normal): actual=104, seasonal=100, local=3, combined_pred=103, error=(103-104)^2=1.0, weight=1.0, loss contribution=1.0
Total loss = 1.0 + 0 + 1.0 = 2.0. The spike is ignored; only normal timestamps guide learning.

The weight mask is the key: by zeroing the loss for flagged anomalies, the model learns clean patterns and simultaneously refines which timestamps are truly anomalous.

What can go wrong

What can go wrong

Seasonal branch fails if the pattern does not actually repeat. If the data has no day-long or year-long rhythm (truly random walks), the seasonal branch learns nothing and both branches collapse to the same guess. The decomposition assumes a repeating cycle exists.
Noise mask mistakes cascade. If the model guesses wrong about which timestamps are anomalies (e.g., it marks a true slow creep as 'normal' early on), both branches learn the creep as trend and the model never flags it. The feedback loop can entrench errors.
Local branch captures anomalies, not trends. On short lookback windows, the local branch can overfit to recent anomalies if the noise mask is imperfect. If it learns 'yesterday spiked to 150, so today should be 140,' it has learned the anomaly's shadow, not the true local trend.
Done right: use domain knowledge. For best results, initialize the seasonal branch with known cycle lengths (hourly/daily/weekly), and tune the threshold for marking anomalies on a validation set from the same system. This anchors the decomposition in reality.
What a runnable demo should prove

What a runnable demo should prove

Build a univariate time series generator that produces (1) a strong seasonal cycle (e.g., daily warmth cycle: 20 degrees at midnight, 30 at noon, back to 20 at midnight), (2) a short-term trend (e.g., each day is 0.2 degrees warmer than the last), and (3) injected anomalies (random spikes or slow creeps at known times). Train a two-branch model (one reading full history, one reading recent history) to jointly minimize prediction error on 'normal' timestamps (given by a noisy mask). Record which anomaly timestamps the model flags. Compare against a single-branch baseline that has the same total model capacity but no semantic split.

Detection rate = (anomalies correctly flagged) / (total injected anomalies); False alarm rate = (normal points wrongly flagged) / (total normal points); Goal: detection rate > 80%, false alarm rate < 5%

The demo must make it impossible to miss: the two-branch model's prediction on clean data hugs the true seasonal + trend signal, while the single-branch baseline's prediction is a blur, because it tries to fit to anomalies and true patterns at once.
