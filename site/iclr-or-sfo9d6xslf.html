Actions as Language: Fine-Tuning VLMs into VLAs Without Catastrophic Forgetting

Represent robot actions as natural language commands instead of special tokens, so fine-tuning stays inside the language model's trained world and avoids wiping out its reasoning.

Paper explainersAll themesRobotics & Control

When you teach a language model to control a robot, it usually forgets how to reason and understand images. VLM2VLA fixes this by describing robot actions in plain English (like 'move down 5 centimeters and right 2 centimeters') instead of inventing new action codes. This keeps the fine-tuning data close to what the model learned on the internet, so a simple weight adjustment (LoRA) is enough—no need to rebuild the whole model.

The forgetting trap: learning actions breaks reasoning

A vision-language model (a model trained on internet images and text to answer questions and describe things) can be taught to control a robot by fine-tuning on teleoperation data (recordings of a human driving the robot). The problem: learning to predict robot actions wipes out the model's foundational skills. It stops understanding images well, stops following complex instructions, and fails on tasks with objects or words it never saw during robot training.

The naive approach adds special action tokens (new codes for 'move left', 'grasp', etc.) and trains the whole model on robot data. This works for actions, but the model forgets how to reason about the world because the robot data (arm movements, gripper angles) looks nothing like the internet text and images the model was built on. The distribution mismatch—internet scale images plus natural language versus a few thousand robot videos—causes the model to overfit and abandon its earlier knowledge.

The core move: Write low-level robot actions as natural language sentences, so the fine-tuning data stays close to what the model learned on the internet.

The algorithm as a flow

What it actually does

Convert actions to language

Take each robot action (gripper angle 45 degrees, arm height 12 cm) and describe it as English text ('move up 12 centimeters and rotate gripper to 45 degrees').

Align with pretraining

The model already knows numbers and spatial words from the internet, so this description feels familiar, not alien.

Apply LoRA (a tiny weight update)

Instead of retraining the whole model, adjust a small set of extra weights layered on top. The original weights barely move.

Generate multi-stage output

Model first generates a high-level subtask in English ('pick up the eggplant'), then a mid-level plan ('move down and left'), then the final action command.

Preserve both skills

The model stays grounded in reasoning (old internet skills) while learning robot control. Zero-shot transfer to new objects and languages follows.

What the paper changes

What the paper changes

The paper changes the representation of actions from discrete tokens (new codes invented for each robot command) to natural language descriptions (everyday English sentences that name numbers, directions, and movements). This single change—using words the model already knows instead of new symbols—is what keeps the pretraining distribution intact.

The hidden quantity

The hidden quantity: distribution alignment

measured quantity  =  Distance from pretraining

Every fine-tuning step nudges the model away from what it learned on the internet. The more the new data looks different from internet data, the bigger the nudge has to be, and the more the model forgets. The paper measures this indirectly: how well does LoRA work? LoRA is a weak update method—it only works if the new task is close to pretraining. So by comparing LoRA (works well here) to full retraining (needed when data is far), the paper shows it found a way to bring the robot data close to the internet distribution.

The paper validates this by showing that actions-as-language achieves both goals at once: the model's core reasoning abilities stay sharp (tested on Visual Question Answering), and robot control works as well as methods that co-train on internet-scale datasets. That dual success is the proof that the distribution mismatch was truly resolved.

Why it works

Why it works: the causal chain

When a model is pretrained on billions of internet examples, it learns the structure of natural language and visual concepts. Its weights are set to predict words in that world. Fine-tuning repoints those weights toward a new task. If the new task looks totally different (raw robot actions, arm angles), the model has to change drastically. LoRA, a parameter-efficient method, makes only small local changes to a few weights—it can only succeed if the new data is close to pretraining.

By representing robot actions in natural language (which the model saw during pretraining), the gap shrinks. The model sees sentences like 'move down 5 centimeters and rotate gripper clockwise'. These words—numbers, directions, objects, verbs—already exist in its pretraining knowledge. So a light touch (LoRA) is enough. The model learns the new action associations while its foundational weights stay stable. This is why reasoning abilities survive and the model can handle unseen tasks: its old skills are still there to ground the reasoning.

The equation: balancing stability and adaptation

First in words:

Loss is equal to action prediction error plus a small regularization term that steers the model to stay close to its original language-understanding weights.

Then the compact form:

L = L_action + lambda * sum_i ||W_lora_i||^2

Every symbol:

Lthe total training penalty
L_actionhow badly the model predicts the robot action
lambdahow strongly we protect the original knowledge
W_lora_ithe small weight adjustments for layer i
sum_iadd up across all layers
A tiny worked example
Suppose a layer's action loss is 0.5 (predicting the wrong action slightly).
The LoRA weights in that layer have magnitude 0.3 (small changes so far).
With lambda = 0.1: penalty is 0.5 + 0.1 * 0.3^2 = 0.5 + 0.009 = 0.509.
If we tried without actions-as-language, the raw angles would have high action loss (say 2.0) and bigger LoRA weights (say 0.8).
Then penalty would be 2.0 + 0.1 * 0.8^2 = 2.0 + 0.064 = 2.064—the model is forced to change much more.
Actions-as-language keeps the loss small and the weight changes gentle.

The equation shows that LoRA works only when the action prediction error is small. Natural language actions keep that error small because the model already understands the words.

What can go wrong

What can go wrong

Action description is vague. If the language description of the action is imprecise (e.g., 'move the gripper a bit'), the model cannot ground the words in actual numbers. Performance degrades because the mapping from English to joint angles becomes fuzzy.
The robot's action space is exotic. If the robot does things outside what the model learned from internet text (bizarre arm geometries, continuous morphing tools), no amount of English description helps—there is no pretraining knowledge to anchor to, because the model cannot understand what those motions mean. The words have no grounding.
LoRA rank is too small. LoRA adds only a tiny adjustment layer. If the rank (the capacity of that layer) is too small, even staying close to pretraining is not enough—the model simply cannot express new robot skills.
Done right. Use precise, numerical language for actions ('move 2.3 centimeters downward, rotate gripper 15 degrees clockwise'). Write out all dimensions the model has seen numbers for during pretraining. Use chain-of-thought (high-level plan first, then action) so the model reasons through the task before outputting actions, which slows down planning but makes it more accurate by grounding the action in the model's language understanding. Test on reasoning tasks to confirm skills survived.
What a runnable demo should prove

What a runnable demo should prove

Build a simple robot task: grasp a new object (one not in the training data) placed in a new location. Fine-tune a language model on 100 teleoperation examples using the standard method (special action tokens) and also using VLM2VLA (actions as language). Measure two things: (1) Does the model control the robot on the new object? (2) Does it still answer questions about images it was trained on? The demo succeeds when actions-as-language wins on both counts—the baseline picks one or the other.
