Rapid Training of Hamiltonian Graph Networks Using Random Features

Replace slow gradient-based training of physics-aware neural networks with instant random parameter construction, keeping accuracy intact.

Paper explainersAll themesAI for Science

Neural networks can learn to predict how particles move and interact, but only if they respect physical rules like symmetry. A network trained on real particles should give the same answer when you relabel which particle is particle-1, or rotate the whole scene. The problem: teaching these physics-aware networks via traditional gradient descent (nudging numbers tiny bit by tiny bit, thousands of iterations) takes forever, especially for large systems with thousands of particles. This paper shows you can build the entire set of network parameters randomly at the start — no iterative training at all — and still get accurate predictions, 150 to 600 times faster, because random basis functions drawn from a continuous smooth pool naturally align with the constrained structure of physical systems.

Zero assumption version

Gradient descent is the bottleneck for physics-aware networks

When you want a neural network to predict how a system of particles behaves — balls bouncing, molecules in a box, stars orbiting — you need it to be symmetric: if you swap two particle labels, the answer should stay the same; if you rotate the whole scene, distances don't change so predictions shouldn't either. Graph neural networks handle this natively by respecting these symmetries in their architecture.

Today, you train these networks the traditional way: start with random parameters (weights), run some particles through the network, compare the prediction to real data, calculate an error, then nudge all the parameters a tiny bit in the direction that shrinks the error. Repeat thousands or tens of thousands of times. For large systems (thousands of particles), this is glacially slow.

The core problem: Iterative training (Adam, SGD, LBFGS) takes thousands of gradient steps; for big physics problems, this is impractical.

The hidden quantity

The hidden quantity: feature representation quality

measured quantity  =  how well random features capture the physics

The paper implicitly measures whether random basis functions, even though never trained, are expressive enough to span the space of accurate physics predictions. This is not a learned quantity — it is a property of the random feature space itself.

Hamiltonian systems (where energy is conserved) obey hidden constraints. A random basis drawn from a continuous smooth distribution naturally has enough diversity to capture those constraints without any gradient-based learning. The paper validates this by solving for output weights only, then checking that predictions match real particle dynamics.

Why it works

Why it works: random features need no gradient steps

Gradient descent works by trial-and-error: nudge weights, check error, repeat. For a complex physics-aware network, this trial-and-error is expensive because every change to weights ripples through all the layers. Random features flip this: instead of designing the features via learning, you draw them from a fixed random distribution and only fit the final layer.

Why does this work? Hamiltonian systems obey conservation laws (energy, momentum). Those laws constrain the possible dynamics to a limited space. Random features drawn from a smooth pool (Gaussian) are diverse enough to cover that space. You do not need to learn custom features; you just need a big enough random pool. The final layer (a simple least-squares solve, a standard linear algebra operation that finds the best-fit weights by solving one equation) then selects and weights the useful random features.

The speed gain: a least-squares solve is one inversion operation (a standard linear algebra calculation), milliseconds. Gradient descent on the same network is thousands of multiply-and-add cycles per step, times thousands of steps. The accuracy is comparable because the random features, despite being generic, still respect the graph symmetries and can express the constrained dynamics.

Math after the picture

The random feature least-squares solve

First in words:

The predicted output is a weighted sum of random basis functions applied to the input; the weights are found by least-squares fitting to training data.

Then the compact form:

y_predicted = sum_j w_j * phi_j(x) where w = argmin_w || y_true - sum_j w_j phi_j(x) ||^2

Every symbol:

y_predictedthe network output (predicted next state)
w_jweight on random feature j (learned by least-squares)
phi_j(x)the j-th random feature applied to input x (never trained)
y_truereal observed next state from data
xparticle positions and velocities
Tiny worked example: 3 random features, 2 training points
Say random features are: phi_1(x)=1.5, phi_2(x)=0.8, phi_3(x)=2.1 for a given input.
Training points: (y_true_1 = 5.0) and (y_true_2 = 3.0).
Least-squares fit finds weights w = [w_1, w_2, w_3] that minimize error over both points.
Example solution: w_1=1.0, w_2=0.5, w_3=0.3 -> y_pred_1 = 1.0*1.5 + 0.5*0.8 + 0.3*2.1 = 3.13 (close to 5.0).
One matrix solve, done. Total time: a few milliseconds, not hours.

The least-squares solve is fast linear algebra, not iterative gradient descent, so training is nearly instantaneous.

What can go wrong

What can go wrong

Random feature pool too small If the Gaussian random basis does not have enough diversity, it may miss some dynamics. For very-high-dimensional systems or exotic Hamiltonians, a larger random pool (more features) is needed.
Symmetry breakdown in the random features The random features must be applied consistently to respect permutation, rotation, and translation. If the feature construction ignores graph structure, accuracy drops below gradient-trained baselines.
Least-squares overfitting on small data If training data is sparse, the least-squares fit can lock onto noise. Regularization (adding a penalty term) may be needed.
Done right When random features respect the graph structure and the pool is large enough for the system size, accuracy matches gradient descent with no training time.
What a runnable demo should prove

What a runnable demo should prove

Build a small N-body system (e.g., 20 particles in 2D with spring forces). Train a Hamiltonian graph network two ways: (1) gradient descent with Adam over 1000 steps, and (2) random features with a least-squares solve. Time both. Measure error on held-out test trajectories. The demo should show that random features finish in seconds while gradient descent takes minutes, with comparable accuracy, because one linear solve (a standard algebra operation) is cheaper than thousands of gradient updates.

speedup = training_time_gradient_descent / training_time_random_features; accuracy_parity = (test_mae_gradient - test_mae_random) / test_mae_gradient < 5 percent

The demo must make it impossible to miss: random features are faster because one least-squares fit beats thousands of gradient updates, and the accuracy is the same because random features are diverse enough to express the constrained physics.
