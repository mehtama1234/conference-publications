Rapid Training of Hamiltonian Graph Networks Using Random Features

Instead of tweaking weights one step at a time during training, draw random weights and solve for the output layer in one shot.

Paper explainersAll themesAI for Science

Simulating how particles move together (N-body systems) requires a model that respects physical laws like rotation and translation invariance. Graph neural networks can learn these systems accurately, but training them the standard way—nudging weights one tiny step at a time to shrink the prediction error—is painfully slow. This paper replaces the slow iterative tweaking with a two-step recipe: randomly initialize the hidden layers once, then solve directly for the output layer using linear algebra. The result trains 150–600 times faster because it replaces millions of iterative steps with a single linear solve that has a closed-form solution.

Why step-by-step weight tuning gets stuck on large physics systems

Simulating molecules or planets requires a neural network that respects symmetries: if you rotate all particles, or shift them all right, the prediction should rotate or shift the same way. Graph neural networks can build these symmetries in, and they work well.

But training them is slow. The standard recipe is gradient descent: compute the error, measure which direction shrinks it, take a tiny step, repeat. On large systems with thousands of particles, each step involves computing gradients through a thousand decisions, and you need millions of steps. On a lattice system with just 9 particles, Adam optimizer takes over 6 seconds. On 32 particles it explodes to 32 seconds.

A beginner might try better optimizers (RMSProp, LBFGS, AdamW) — and the paper tests 15 of them — but even the best ones still grind through hundreds of thousands of iterations, each one a full forward-backward pass through the network. They remain fundamentally iterative because no closed-form solution exists for the weights: the error surface is nonlinear and bumpy, so you must guess, check, nudge, and repeat hundreds of thousands of times until the error stops shrinking.

The method in one sentence. Draw random weights for the hidden layers once, then solve a linear system to find the output layer, all at once.

The algorithm as a flow

What it actually does

Encode the particles

Convert the input positions and momenta into rotation-and-translation-invariant numbers the network can use.

Draw random hidden weights

Sample all the weights in the middle layers randomly from a bell curve, once. No learning happens here.

Run particles through random layers

Feed the encoded positions through the randomly initialized network layers, transforming them into hidden representations.

Collect the output

Stack all the hidden representations into a table (rows are hidden units, columns are examples).

Solve the linear system

Find the output-layer weights that make the hidden representations predict the target (the true forces or energy gradients) as accurately as possible, all in one shot.

What the paper changes

What the paper changes

The object is the training algorithm itself. Instead of iteratively updating weights via gradient descent, the paper proposes a two-stage recipe: (1) sample the dense layers randomly once, (2) solve for the output layer. The hidden layers never change during training; only the output layer is learned.

the object it moves  =  training algorithm
The hidden quantity

The hidden quantity: residual (how far off the prediction is)

measured quantity  =  prediction error on the training set

Every training method tries to shrink some kind of error. In gradient descent, you compute it step by step. In this method, the hidden quantity is the residual: how far the randomly-initialized network's predictions deviate from the true labels (the correct forces or energy), measured across all training examples as a single table. This residual is what the linear solver minimizes when it finds the output-layer weights.

The paper estimates this residual implicitly by solving a least-squares problem: given the hidden representations, find output weights that make the training predictions as close to true labels as possible. The solver computes this directly without ever going through a step-by-step weight-tuning loop.

Why it works

Why random features work instead of gradient descent

Gradient descent (nudging weights one tiny step at a time to shrink error) is slow because it is iterative: compute the error, nudge the weights, recompute, nudge again, repeat for hours. Each nudge is tiny because if you move too far you overshoot and the error gets worse. On large systems the error terrain has many jagged, noisy bumps, making each step smaller and slower.

Random features flip this upside down. The hidden layers don't have to be perfect — they just have to transform the input in useful ways. A random transformation is surprisingly good at this: random tables of numbers are almost orthogonal (they spread the signal in different directions without collapsing it). So even with random weights, the hidden layer produces rich, diverse feature patterns.

Once the hidden representations exist, finding the output weights is a linear algebra problem: least-squares regression. This problem has a closed-form solution (the normal equations) that a linear solver can compute in one shot. No guessing, no iteration, no overshooting — just direct algebra. That is why the method is 150–600 times faster: it replaces millions of nudging steps with one linear solve.

The equation: least-squares solution

First in words:

output_weights = inverse(H_transpose · H) · H_transpose · targets, where H is the matrix of hidden representations and targets are the true labels

Then the compact form:

W_out = (H^T H)^(-1) H^T y

Every symbol:

Hmatrix of hidden representations (one row per hidden unit, one column per training example)
H^Tthe transpose of H (flip rows and columns)
yvector of true targets (forces, energy gradients, or accelerations)
W_outthe output-layer weights we are solving for
(H^T H)^(-1) H^Tthe pseudoinverse of H
A tiny worked example
Suppose we trained on 4 particles and the hidden layer gives us H = [[0.2, 0.8, 0.5, 0.3], [0.7, 0.1, 0.6, 0.9]]. (Two hidden units, four training examples.)
True targets y = [1.0, 2.5, 1.8, 2.2] (the correct forces for each particle).
H · H^T = [[0.2^2+0.8^2+0.5^2+0.3^2, 0.2·0.7+0.8·0.1+0.5·0.6+0.3·0.9], [..., ...]] ≈ [[1.14, 0.61], [0.61, 1.27]]
Solve (H^T H)^(-1) · H^T · y using a linear solver (e.g., QR decomposition) to get W_out ≈ [0.85, 1.42].
These weights W_out now map the hidden representations to predictions. No gradient descent, no iteration.

The normal equations say: find the weights that make the table times the output weights as close as possible to the true targets, measured as the sum of squared errors.

What can go wrong

What can go wrong

Random weights too extreme. If the random bell curve is poorly chosen (e.g., very large or very small), the hidden layer might saturate or explode. The paper uses standard Gaussian random sampling, which avoids this by keeping values in a reasonable range.
Linear solver fails on ill-conditioned systems. If the table of hidden representations is almost singular (its rows are nearly linearly dependent), inverting it amplifies tiny errors. In practice, this happens rarely with random tables, which tend to be well-conditioned, but it can occur on very small training sets.
Hidden layer too small for the problem. If there are too few random hidden units, the random features cannot represent the system dynamics well enough. The linear solver will then be solving with incomplete information. Choosing the hidden dimension is a hyperparameter.
Done right: architecture matches the symmetry. The paper ensures the graph network respects physical invariances (permutation, rotation, translation) by construction, before training. The random features preserve these symmetries because they operate on the invariant-encoded input, not the raw particles.
What a runnable demo should prove

What a runnable demo should prove

A minimal demo: pick a small N-body system (e.g., 8-16 particles in a lattice or spring configuration). Generate synthetic trajectories by simulating the true physics. Split into train (90%) and test (10%). Train a Hamiltonian Graph Network on the train set using (1) standard gradient descent (Adam or LBFGS, 10,000 steps), and (2) random features plus least-squares. Measure wall-clock time and test-set accuracy (position and momentum errors) for both. Run both on a 32-particle system to show gradient descent slowdown. Finally, train only on the 8-particle system with random features and test generalization zero-shot on 32 and 64 particles.

speedup = time_adam / time_random_features; test_mse_error = mean((predicted - true)^2 on test set)

The demo must show that random features train at least 50x faster than Adam (because one linear solve beats thousands of backward passes), achieve comparable test accuracy within 10% (because random features still extract useful signal), and generalize to unseen system sizes without retraining (because the graph network respects symmetries inherently).
