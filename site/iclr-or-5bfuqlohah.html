Efficient Autoregressive Inference for Transformer Probabilistic Models

Produce coherent joint predictions without re-encoding the whole context at every step by caching the fixed context once and growing a small causal buffer for the targets.

Paper explainersAll themesOther

Many set-based probabilistic models are good at answering one target at a time, but many applications need a full joint data pattern over several targets so that the predictions agree with each other. The usual way to get that agreement is costly because the model must repeatedly re-encode the conditioning set after each newly generated target. This paper keeps the context encoding fixed and adds a causal target buffer, which lets the model generate target values one by one while still respecting earlier target choices.

Zero assumption version

Joint prediction is expensive when the model keeps rereading the same context

Suppose you observe some context points from an unknown function and want predictions at several new inputs. A marginal predictor can answer each new input separately. But a joint predictor must also preserve the dependencies among those answers, because the values at nearby inputs should move together rather than independently.

Set-based models handle context well because they can condition on an unordered set. The cost appears when you generate targets one at a time. After choosing the first target value, the standard method adds that target back into the conditioning set and re-encodes the whole set before choosing the second target. Doing this at every step repeats almost the same work many times.

The problem. Joint generation is slow because each new target usually forces a full re-encoding of the context set even though the original context has not changed.

The algorithm as a flow

What it actually does

Step 1: Encode the context set once.

Read the observed context inputs and outputs into a cached state that stays fixed for the entire target-generation run.

Step 2: Create an empty target buffer.

Start a causal buffer, which means a left-to-right memory where each target can read only earlier targets.

Step 3: Generate the next target value.

Each target position reads the cached context and the earlier target states stored in the buffer.

Step 4: Append that target to the buffer.

Store the new target state so later targets can depend on it without forcing the model to rebuild the context state.

Step 5: Repeat until all target values are produced.

The context cache is reused each time, so cost grows mainly with the new target work rather than with repeated context passes.

What the paper changes

What the paper changes

The paper changes where step-by-step prediction state lives. Instead of treating the full conditioning set as something that must be rebuilt after every target value, it keeps the old context fixed and lets only the target side grow.

the object it moves  =  the state updated during joint generation
The hidden quantity

The hidden quantity: repeated context work

measured quantity  =  context re-encoding count

The main hidden cost is how many times the model rereads the same context points during one joint sample. That number can be large even when the context itself never changes.

The causal buffer lowers that count to one context encoding per run. Later steps still depend on earlier targets, but they get that dependence from the buffer rather than from a full rebuild of the whole conditioning set.

Why it works

Why the buffer keeps coherence without repeated full passes

Joint prediction needs two information sources: the fixed context and the already generated targets. The context does not change, so caching it is safe. The targets do change, so they need an updating memory.

The causal buffer provides that updating memory. Each new target reads the cached context for global conditioning and the earlier buffer entries for target-to-target dependence. This works because the model separates what is fixed from what is growing. The fixed part is reused, and the changing part is updated in a small structure whose size tracks only the targets.

Math after the picture

The equation: one context cache plus growing target buffer

First in words:

Joint target probability is factorized into a product of one-step probabilities, where each step conditions on the fixed context cache and the earlier generated targets.

Then the compact form:

joint_probability = product over t of p(target_t | cached_context, earlier_targets)

Every symbol:

target_tthe target value generated at step t
cached_contextthe one-time encoded state of the observed context set
earlier_targetsall target values generated before step t and stored in the causal buffer
joint_probabilitythe probability assigned to the full target set
A tiny worked example
Suppose there are 3 targets to generate.
Step 1 uses the cached context and predicts target 1 with probability 0.8.
Step 2 uses the same cached context plus target 1 and predicts target 2 with probability 0.7.
Step 3 uses the same cached context plus targets 1 and 2 and predicts target 3 with probability 0.9.
Joint probability is 0.8 times 0.7 times 0.9, which is 0.504.
The context was encoded once, but target dependence was still preserved at each step.

The factorization is standard step-by-step prediction modeling; the paper's contribution is to make the conditioning structure efficient for set-based probabilistic models.

What can go wrong

What can go wrong

Context that should not be treated as fixed. If later targets truly change what the context representation should be, a frozen cache can miss those feedback effects.
Long target chains. If the target list is very long, the buffer itself can become expensive because each new target must still read many earlier targets.
Poor target ordering. Step-by-step generation depends on order. A bad target order can make early uncertain choices harm many later ones.
Done right. Use the cache when the context is truly fixed and choose a target order that matches the dependence structure of the task.
What a runnable demo should prove

What a runnable demo should prove

Train a set-conditioned predictor on a toy function-regression task. Then compare two joint-generation modes on the same target sets: one that re-encodes the entire context after each generated target, and one that caches the context once and uses a causal buffer for the targets.

Measure both wall-clock time and joint log-likelihood, because the paper claims the new method saves time without giving up coherent joint prediction.

speedup = time for full re-encoding baseline / time for cached-context buffer method

A convincing demo shows that speedup rises while joint log-likelihood stays close, because the method removes repeated context computation rather than removing target dependence.
