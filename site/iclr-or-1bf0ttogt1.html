Diversity-Enhanced Reasoning for Subjective Questions

A model learns to answer questions with many valid answers by training it to think from different stakeholder perspectives and generate varied reasoning paths.

Paper explainersAll themesAlignment, Safety & Fairness

Large reasoning models trained with reinforcement learning excel at math and coding, where there is one right answer. But they fail at questions that have multiple correct answers depending on your viewpoint or role. This paper trains reasoning models to think from different perspectives and generates diverse reasoning chains, so the model learns that many answers can be equally right because the training reward signal now values both correctness and variety.

Zero assumption version

Why trained reasoning models get stuck on open questions

When you train a large reasoning model on math problems or coding, you can check if the answer is right or wrong. This lets you give the model a clear reward signal: penalize wrong answers, reward right ones. Over many training runs, the model learns to find that one correct path.

But many real questions do not have a single right answer. A doctor and a patient have different valid perspectives on a treatment. A city planner and a business owner have different valid perspectives on zoning. When you force a model trained on single-answer problems to answer these open questions, it collapses to one perspective, missing the richness of other valid viewpoints.

A beginner might try this: train the model with reinforcement learning on all valid answers equally. But the model still sees each answer as separate and does not learn to reason about why different perspectives reach different valid conclusions.

The method in one sentence. Train the model to think through multiple real-world perspectives and generate many different reasoning chains for the same question, using a reward signal that values diversity alongside correctness.

The algorithm as a flow

What it actually does

Step 1: Identify roles for the question

Prompt the model to name relevant perspectives (e.g. doctor, patient, ethicist).

Step 2: Generate reasoning chains from each role

Ask the model to think through the same question from each perspective independently.

Step 3: Combine chains into one training example

Stitch all the perspective chains together into one training example.

Step 4: Train with group relative reward

Use reinforcement learning that rewards answers based on diversity across the group, not just individual correctness.

Step 5: Verify on both subjective and objective questions

Test that the model now answers open questions from multiple angles and still solves math correctly.

What the paper changes

The one thing the paper changes

The paper adds a new training data construction pipeline: instead of feeding the model individual reasoning chains, it creates combined reasoning chains that incorporate multiple role perspectives into a single trace, then trains on those diverse paths using a reinforcement learning method that rewards both correctness and variation.

the object it moves  =  Multi-perspective reasoning chains
The hidden quantity

The hidden quantity: Reasoning path diversity

measured quantity  =  Path diversity score

The paper measures how many different reasoning paths the model generates for the same question. In a single-answer model, all paths collapse to one correct solution. In this paper's model, the same input produces many different but valid reasoning chains because the model learned to reason from multiple perspectives.

The paper measures this by counting how many distinct reasoning paths appear when you sample from the model multiple times on the same question, then checking if each path is correct. Higher diversity means more valid alternatives; lower diversity means the model has collapsed back to one answer.

Plain reading. Think of it like a student learning to solve a problem from multiple viewpoints. A single-perspective student solves it one way every time. Paper reading. The paper operationalizes diversity via Group Relative Policy Optimization (GRPO), which compares the reward of a trajectory to the average reward of other trajectories in the same batch. If your reasoning is the only one in the batch and gets high reward, you get no advantage. If your reasoning is one of many high-reward paths, you all get credit. This mechanism penalizes collapse to a single path.
Why it works

Why training from multiple perspectives fixes the problem

Single-answer training fails because the model learns to predict one correct output. During training, each time the model generates a wrong answer, the model's numbers get nudged in a direction that would produce the right answer instead. Over many training runs, the model converges to generating that one target. When you switch to open questions, the model has no learned ability to reason about alternatives because nothing in training encouraged it to explore other paths.

Multi-role training fixes this by changing what the model observes during training. Instead of seeing one correct answer per question, it sees the same question answered correctly from multiple angles. When the model reads a reasoning chain that starts with 'As a doctor, I would think...' followed by a doctor's logic, then reads the same question answered as 'As a patient, I would think...' with different logic, it learns that both are valid. Over many training steps, the model internalizes that multiple paths can be correct simultaneously.

The reward signal amplifies this. Standard reinforcement learning gives a high reward to any correct answer and trains the model to maximize expected reward. But this still incentivizes finding one high-reward path. The paper uses Group Relative Policy Optimization, which compares each reasoning path to other paths in the batch. If you generate a reasoning path that is unique and correct, you get higher reward than if everyone generates the same correct path. This directly incentivizes the model to generate different answers, not duplicate a single answer.

The reward equation with perspective bonuses

First in words:

For each reasoning path, the model gets a correctness reward if the answer is right, plus a diversity bonus if the path is different from other correct paths in the batch. Paths that are unique and correct score higher than paths that duplicate another path, even if both are correct.

Then the compact form:

R(trajectory) = R_correct(trajectory) + lambda * (reward_trajectory - mean_reward_batch)

Every symbol:

trajectoryone complete reasoning chain from input to answer
R_correctthe base reward, 1 if the answer is correct, 0 otherwise
reward_trajectorythe cumulative score assigned to this path
mean_reward_batchthe average score of all paths for this question in this batch
lambdathe weight on diversity; how much to reward being different
A tiny worked example
Batch of 4 paths for one subjective question: doctor path, patient path, ethicist path, duplicate doctor path.
Correctness scores: doctor=1.0, patient=1.0, ethicist=0.8, duplicate-doctor=1.0 (all plausible answers or correct).
Batch mean = (1.0+1.0+0.8+1.0)/4 = 0.95.
Doctor path gets: 1.0 + 1.0*(1.0-0.95) = 1.0 + 0.05 = 1.05.
Patient path gets: 1.0 + 1.0*(1.0-0.95) = 1.05.
Ethicist path gets: 0.8 + 1.0*(0.8-0.95) = 0.8 - 0.15 = 0.65.
Duplicate doctor path gets: 1.0 + 1.0*(1.0-0.95) = 1.05.
Result: being unique and correct (doctor, patient) beats being duplicate (second doctor). Being incorrect (ethicist) gets penalized. Model learns to generate different correct answers.

The second term is the core mechanism: when your path's reward is higher than the batch average, you win bonus points. When it is lower, you lose points. This penalizes collapse to a single path and encourages the model to explore and land on different correct answers.

What can go wrong

What can go wrong

Role identification fails. If you cannot name relevant perspectives for a question, or if the roles you choose are not actually distinct, the model sees fake diversity and learns to hallucinate differences rather than genuine alternative viewpoints. Example: asking a model to reason as a 'physicist' and a 'realistic physicist' is not two perspectives, it is noise.
Diversity collapses back to one answer over time. If the diversity bonus lambda is set too low, or if the batch size is small, the group relative reward signal is weak. The model may revert to finding the single highest-confidence answer and ignoring alternatives, especially if one role's answer reliably scores higher.
Word-level diversity degrades answer quality. If the model only cares about generating different words from different perspectives, it can produce grammatical but nonsensical reasoning. The paper requires diversity to stay within the correctness threshold to avoid this.
Done right. Choose roles that reflect real stakeholder groups relevant to the domain. Tune lambda so diversity is rewarded but never at the expense of correctness. Sample a large batch so the group relative reward signal is steady and clear.
What a runnable demo should prove

What a runnable demo should prove

Build a simple web interface: give it a subjective question, e.g. 'Should we build a dam here?'. The interface calls a model trained on MultiRole-R1 and samples the model's output 8 times. Display all 8 reasoning chains side by side. A good demo shows 4-6 genuinely different chains (e.g. one emphasizing economic growth, one emphasizing environmental harm, one emphasizing community consent), each correct but from a different angle. A bad demo shows all 8 chains saying the same thing with different wording.

diversity_score = (number of distinct correct reasoning chains) / (total samples) ; correctness_score = (number of samples with correct final answer) / (total samples) ; combined = diversity_score * correctness_score

The demo succeeds if users can see at least 3-4 genuinely different reasoning paths, each internally consistent, each arriving at a different valid conclusion for the same question.
