Plain Transformers are Surprisingly Powerful Link Predictors

A simple Transformer trained on sampled local neighborhoods can predict graph links better than hand-engineered graph-specific models.

Paper explainersAll themesGraph & Geometric Learning

Predicting which two people in a social network will connect, or which proteins interact in a biological network, is hard because you need to understand the structure around each pair of nodes. The standard way to do this uses graph-specialized models with lots of custom features baked in. This paper shows that a plain Transformer—just fed the local neighborhood of nodes—learns richer patterns and outperforms those fancier models, because it discovers complex co-occurrence patterns directly from data instead of relying on manually-chosen features, while needing far fewer learned numbers to store because it does not maintain a unique list of numbers describing every node.

Why predicting links is hard

In a network of nodes (people, proteins, webpages), you often want to guess if two unconnected nodes will link. The hard part: the answer depends on the structure around them. Are they both friends of the same people? Do they sit in a dense cluster? Do they bridge two groups? The current best approach builds special graph-aware models with hand-tuned features for hops, triangles, and other patterns, but these models either don't generalize to new kinds of networks or they need to store an embedding (a list of learned numbers) for every single node, which explodes the memory on billion-node graphs.

A beginner might try: just take the two node IDs and predict. But that fails because the model has no context about who they're connected to or how similar their neighborhoods are. The standard fix is to engineer lots of hand-crafted network-topology features and stuff them into a specialized graph model. This works okay, but it means you hardcode your assumptions about what patterns matter, and it breaks down when you switch to a different kind of graph.

The core move. PENCIL feeds a plain Transformer just the local neighborhood around each pair of nodes—no hand-crafted features, no per-node stored embeddings—and lets it discover what structure matters by looking at patterns automatically.

The algorithm as a flow

What it actually does

Extract local neighborhoods

For each pair of candidate nodes, grab all nodes within 1 or 2 hops and their edges.

Convert to Transformer input

Turn the subgraph structure into a sequence the Transformer can read (e.g., edge list or adjacency patterns).

Run Transformer with pattern learning

Standard Transformer processes this sequence; each specialized detector learns which structural patterns correlate with real links.

Predict the link

A learned scorer (the decoder head) takes Transformer outputs and outputs a probability: will these two nodes connect?

No stored node embeddings

Unlike other models, PENCIL never stores unique numbers per node; it recomputes the Transformer output for each new prediction.

Why it works

Why a plain Transformer works on graphs

The core insight is that graph structure, when restricted to a small local neighborhood around two nodes, can be represented as a sequence that Transformer attention can process. Attention is pattern-matching: each head learns to spot certain co-occurrence patterns in the neighborhood and upweight them if they predict links. Because Transformer attention is permutation-invariant (it treats each position as comparable to all others with individual pairwise comparisons), it naturally handles the fact that graph neighborhoods have no fixed order.

For example: if the two candidate nodes both connect to the same intermediate node, that common neighbor sits in the same subgraph. Attention learns to notice when both candidates have high attention to the same neighbor and upweight that co-occurrence, because it correlates with real links. A triangle (three mutually connected nodes) is another pattern—if one candidate is part of a tight local cluster, attention learns to notice that. The Transformer never sees a hand-coded feature called 'triangles'; it learns from data that triangle membership matters.

Scaling works because PENCIL does not store a unique embedding for each node. Traditional graph models embed all one billion nodes and then index them by node ID. PENCIL only computes embeddings for the nodes in each local sample, then throws them away. This is memory-efficient, because it only holds as many embeddings as the sample size at any moment, and enables batch processing across different graphs or dynamic graphs where node IDs change, because the model computes fresh outputs for each local neighborhood on the fly without needing to look up pre-stored per-node embeddings.

Scoring a link from local subgraph attention

First in words:

For each candidate node pair, the score is the average of multiple Transformer output tokens, passed through a learned scorer. The scorer is a small neural network that learns which combinations of subgraph patterns (discovered by attention) predict links.

Then the compact form:

link_score = MLP( mean( Attention_output_tokens ) ), where Attention_output_tokens = Transformer( sampled_subgraph )

Every symbol:

Attention_output_tokensthe Transformer output list; each position is a learned vector encoding one neighborhood pattern
mean(...)average the Transformer outputs to get one vector per candidate pair
MLP(...)a two-layer neural network that maps the averaged output to a single yes/no prediction
sampled_subgraphthe local neighborhood (edges and node types) around each candidate pair
A tiny worked example
Suppose we sample a 6-node local neighborhood around candidate pair (A, B).
Transformer processes all edges and produces 6 output lists of numbers (each list represents what the model learned about one position).
Attention head 1 (learned): spots that A and B both connect to node X → upweights X position.
Attention head 2 (learned): spots that A is in a 4-node cluster; B is not → downweights cluster features.
We average the 6 output vectors: [0.8, 0.3, 0.7, 0.2, 0.6, 0.4]_mean = 0.50.
MLP takes 0.50 and outputs 0.72 → model predicts 72% chance of link (calibrated from training data).
Another pair with a different subgraph might yield mean=0.15 → MLP outputs 0.21 → low confidence link probability.

The MLP learns which combinations of subgraph patterns (encoded by Transformer output) correlate with real links; no hand-coded features are needed.

What can go wrong

What can go wrong

Subgraph too small or unbalanced. If the sampled neighborhood is tiny or dominated by one high-degree node, the model may miss important structure. Solution: sample multiple neighborhood sizes and aggregate.
Computational cost of attention on large subgraphs. Attention requires comparing every position to every other, which scales as neighborhood-size squared. Sampling small neighborhoods mitigates this, but very dense neighborhoods become slow. Solution: adaptive sampling or hierarchical subgraph selection.
Permutation equivariance issues. Graph neighborhoods have no canonical order. Early versions may not properly shuffle node orderings during training, making the model brittle to different input orderings. Solution: ensure training subgraphs are shuffled and test-time sampling is random.
Works well when community structure and local patterns matter. PENCIL excels on link prediction where the neighborhood (triangles, common neighbors, clusters) is predictive. On graphs where links depend on global properties (e.g., bipartite matching or hierarchical structure far away), PENCIL may plateau unless it learns to aggregate distant signals.
What a runnable demo should prove

What a runnable demo should prove

Build a small graph (100–1000 nodes, synthetic or real). Split links into train (70%), validation (15%), test (15%). Hide test links. Train PENCIL (or implement from scratch): sample local neighborhoods around candidate node pairs, encode as Transformer input, train the link-score MLP end-to-end. Measure accuracy (fraction of correct predictions), parameter count (should be <100k parameters even for 1000 nodes), and generalization (train on one graph, test on a structurally different one with different node counts). Compare to a hand-crafted feature baseline (common neighbors, path length, clustering coefficient). The demo succeeds if PENCIL's accuracy is competitive or better, because a single learned detector can capture more nuanced patterns than pre-decided features, and its parameter count is orders of magnitude smaller, because it does not embed all nodes upfront, proving that learning from data beats manual feature engineering.

link_prediction_accuracy = (correct_predictions / total_test_pairs) * 100%; generalization_gap = train_accuracy - test_accuracy_on_different_graph; parameter_efficiency = params_PENCIL / params_baseline_GNN

The core takeaway: a plain, unspecialized Transformer trained on sampled neighborhoods discovers richer structure than hand-coded graph features and does so without storing embeddings for every node.
