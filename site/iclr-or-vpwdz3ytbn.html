OmniField: Neural Fields for Messy Real-World Sensor Data

A neural model learns continuous sensor fields by combining partial information from multiple sensor types, each telling a different story at different places and times.

Paper explainersAll themesAI for Science

Imagine you have a weather station that measures temperature at 3pm and wind speed at 4pm, but never both at once. Or a lab experiment where one detector captures data at point A but not point B. The naive approach: throw away all the partial data. OmniField instead learns a continuous field (like a temperature map) by fusing all the available sensor signals together, even when they measure different things at different places. It builds a unified picture from fragments.

Zero assumption version

Messy sensor data beats standard approaches

Real science produces a mess: one measurement is noisy, another is sparse (only at certain times), and a third comes from a different instrument entirely. A weather station might log temperature every minute and pressure every 10 minutes, offset by delays. A particle detector records energy deposits AND tracks separately. A material sample is stressed while strain is measured at only a few points.

The standard fix: create a fake complete grid. Smooth the data onto a regular lattice, interpolate the missing pieces, and pretend the gaps do not exist. But this introduces smoothing bias (the extremes get softened, high-frequency details disappear) and uncertainty collapse (the model forgets that the interpolated values were guesses, not ground truth). Another strategy: throw away all the partial data and use only complete records. This shrinks the training set drastically.

A beginner tries: train a standard neural network on the clean subset. It learns poorly because most of the data is discarded. Or try feeding each sensor type separately to its own model, then combine the predictions. This breaks because the sensors give different views of the same physical field and need to cross-reference each other to disambiguate noise.

In one sentence. Learn a continuous field from fragmented, noisy, multimodal sensor streams without preprocessing tricks.

What the paper changes

What the paper changes

The paper adds two architectural pieces to a standard neural field. First, a multimodal crosstalk block that lets each sensor type communicate with others during processing. Second, an iterative refinement loop that runs the fusion multiple times, letting signals propagate and align. The core object: the way per-modality (per-sensor) information flows through the network, from isolation to repeated cross-checking.

the object it moves  =  the information-fusion pathway
The hidden quantity

The hidden quantity: per-sensor alignment

measured quantity  =  alignment signal between sensor pairs

Each pair of sensors has an alignment signal: how well they agree about what the underlying field is doing at a given space-time point. Where temperature rises sharply, pressure should too (they measure the same air). Where they disagree, one is likely noisy or out of calibration. OmniField learns to detect and exploit this alignment.

The paper estimates alignment by comparing the gradients (the direction of change) in each sensor's learned representation. If two sensors point in the same direction, they agree; if they conflict, the model learns to downweight the noisier one. This happens implicitly inside the multimodal crosstalk block, where each sensor type sees a global code summarizing all sensors and can adjust its own output accordingly.

Why it works

Why it works: iterative alignment

Here is the causal chain. When you have one noisy temperature reading and one noisy pressure reading at the same location, neither alone tells you the truth. But temperature and pressure are physically coupled (both depend on the air density). If you average the two readings naively, you dilute the signal. If you train them together, the loss function (the training target) penalizes conflicting predictions equally. The model has no way to learn which sensor is trustworthy.

OmniField breaks this tie by making the sensors argue. In the multimodal crosstalk block, each sensor summarizes its observation into a list of numbers. Then, a global feature z is computed as a weighted summary of all sensor summaries. Finally, each sensor processor refines its own representation using both its raw summary and this global code z. On the first iteration, the global code is just an average, so it pulls both sensors toward the middle. But on the second iteration, whichever sensor did better at explaining the data in the first pass learns that the global code reflects its higher quality, so it leans into that signal. The other sensor, seeing that the global code is drifting away from its noisy reading, backs off. After several iterations, the model converges to a configuration where high-quality sensors dominate the global signal and low-quality ones recede—without any explicit labeling of which is which.

This is more efficient than training separate models for each sensor, because each sensor can use the others as implicit ground truth anchors. And it is more faithful to the data than gridding or imputation, because the model never pretends the gapped measurements were real—it treats gaps as missing information to be handled when answering queries.

The core equation

First in words:

For each processor step, fuse multimodal embeddings via a global code, then refine each modality using the global signal

Then the compact form:

z = sum_m alpha_m * E_m(U_in^m) h_m^(step) = Processor_m( gamma(x), eta(t), E_m(U_in^m) + z ) output(x,t) = Decoder(h_1, h_2, ..., h_M)

Every symbol:

zglobal multimodal code (one vector summarizing all sensor types)
alpha_mlearned importance weight for sensor m (0 to 1)
E_m(U_in^m)embedding of sensor m observations (list of numbers)
gamma(x)position encoding (sine/cosine functions of x and y)
eta(t)time encoding (sine/cosine functions of t)
Processor_mone neural network layer refining sensor m using z
Decoderfinal layer combining all refined modalities into predictions
Tiny worked example
Suppose z (global code) = [0.6, 0.4] (0.6 from temp, 0.4 from pressure).
Sensor temperature embedding: [0.8, 0.2]. Sensor pressure embedding: [0.3, 0.7].
Alpha for temperature: 0.7 (model learned temp is reliable). Alpha for pressure: 0.3.
Global code: 0.7 * [0.8, 0.2] + 0.3 * [0.3, 0.7] = [0.56, 0.14] + [0.09, 0.21] = [0.65, 0.35].
This global code is fed back to both sensors. Temperature sees [0.65, 0.35], which is close to its original [0.8, 0.2], so it stays confident. Pressure sees the same code, which is far from its [0.3, 0.7], so the processor adapts, moving closer to the global signal.
On the next iteration, temperature dominates the new global code even more, and pressure adapts further.

The iterative loop allows high-quality sensors to gradually separate from noisy ones because the global code gets pulled toward whichever sensor makes better predictions, and then each sensor sees that pull in the next iteration and either leans in (if it is accurate) or backs off (if it is noisy), converging without external labels.

What can go wrong

What can go wrong

All sensors are equally noisy. If every sensor type is corrupted or biased in the same way (e.g., all measuring the same wrong thing), the model will learn the wrong field faithfully. Cross-modal alignment cannot detect a systematic shared error.
One modality dominates too much. If one sensor is much higher quality than others, the global code can become a copy of that one modality's signal, and the other sensors learn to simply output a low-quality copy. The model loses diversity and fails if the dominant sensor goes offline.
Insufficient iterations. If you run the iterative refinement loop too few times, sensors do not reach alignment. The model converges to a loose, high-loss solution. Running too many iterations is safe but slower.
Done right. When sensors have uncorrelated noise and complementary coverage (each measures something the others miss, or at least from a different angle), the iterative fusion finds a stable, lower-error reconstruction than any single sensor alone.
What a runnable demo should prove

What a runnable demo should prove

Build a toy experiment with synthetic sensor data. Create a smooth underlying field (e.g., a 2D Gaussian bump). Sample it at random (x, y, t) locations, assigning half the points to temperature and half to pressure. Add independent random noise to each modality. Train OmniField on the scattered, noisy, partially-labeled data. At test time, query a dense grid and measure reconstruction error on the full field (both temperature and pressure at every point). Compare against: (1) training separate neural fields for each modality, and (2) gridding + interpolation. OmniField should win, especially as noise increases.

reconstruction_error = mean( |predicted_field - true_field| ), measured on clean test grid

As noise level rises, separate models degrade linearly; gridding gets worse due to blurring; OmniField barely budges because sensors cross-reference each other.
