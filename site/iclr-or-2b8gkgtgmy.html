CMT: Mid-Training for Efficient Learning of Consistency, Mean Flow, and Flow-Map Models

A lightweight training stage between diffusion pre-training and flow-map post-training stabilizes fast image generation by teaching the model to cut straight along solver paths.

Fast image generation requires learning to jump directly to the final picture instead of taking many tiny steps. But training this shortcut is unstable and expensive. Mid-training inserts a simple intermediate stage that teaches the model to follow the existing solver paths smoothly, creating a stable starting point for the final training without heuristics or extra data.

Zero assumption version

Fast image generation needs a shortcut

Diffusion models generate images by starting with noise and taking many tiny steps to gradually clean it up, like following a winding path. To speed this up, researchers want to train a model to make big jumps directly to the clean image instead of climbing the whole path.

Naively, if you start from scratch and train this jump model on random weights, it is unstable and breaks easily. If you start from a pre-trained diffusion model, the model at least knows something about images, but converting its slow step-by-step knowledge into one big jump remains brittle and costly—the training wobbles, requires careful tuning, and eats enormous amounts of GPU time.

The problem in one sentence. Training a model to cut a long, winding path into one big jump is unstable without a strong, trajectory-consistent starting point.

What the paper changes

What changes

The paper adds a new training stage called mid-training, positioned between the existing diffusion pre-training and the final flow-map post-training. This stage inserts one compact training run that teaches the model to follow the trajectories created by the pre-trained diffusion solver.

the object it moves  =  the initialization of jump-model weights
The hidden quantity

Trajectory consistency: how well the model follows the path

measured quantity  =  trajectory consistency

Trajectory consistency means: does the model map points along the diffusion solver's path in a way that makes geometric sense? A consistent trajectory is one where the model learns to approximate the actual diffusion process's route, not some random shortcut.

The paper estimates this by training on the solver's own steps—samples taken from the pre-trained diffusion model—and measuring how well the mid-training model reproduces those same solutions. A high-consistency initialization means the model has learned the shape of the diffusion space and can now jump reliably within it.

Why it works

Why the two-stage approach stabilizes the jump

A flow-map model must learn to make big jumps in a very high-dimensional space (thousands or millions of numbers). If weights start random, the model has no compass—it will thrash and produce garbage. If weights come from the pre-trained diffusion model as-is, they are tuned for tiny steps, not big jumps, so the learning is confused about which direction to go and wobbles.

Mid-training solves this by giving weights a clear intermediate job: learn to interpolate along paths you already know. The diffusion solver creates trajectories by starting with noise and asking the model to predict the next clean state at each step. In mid-training, the new model learns to map intermediate noise samples directly to their clean targets using the solver's own path. This teaches the weights the shape—what makes a 'good' intermediate state, which features matter, how noise and clean image are related spatially.

Once weights have learned this structure, post-training can teach the big jump. The weights now have a clear bias toward the right directions and a well-formed surface. Training converges fast because the model is not fighting against random initialization or fighting against tiny-step tuning. The jump instruction is now aligned with the learned shape.

Math after the picture

The mid-training objective

First in words:

Loss equals the squared distance between the model's predicted clean image and the actual clean image, averaged over all trajectory points.

Then the compact form:

L_mid = E_t [ ||f(x_t) - x_0||^2 ]

Every symbol:

f(x_t)the model's prediction when shown noise sample x_t
x_tan intermediate noisy state from the solver trajectory
x_0the final clean target image
E_taverage loss across all time steps t in the trajectory
||·||^2squared Euclidean distance (sum of squared pixel differences)
A tiny worked example
Trajectory has 3 intermediate steps: x_0.25 (very noisy), x_0.5 (medium), x_0.75 (mostly clean).
True clean image x_0 is the target for all three.
Step 1: model predicts 'cat-like', error ||prediction - x_0||^2 = 240. Loss = 240.
Step 2: model predicts 'better cat', error = 85. Loss = 85.
Step 3: model predicts 'sharp cat', error = 12. Loss = 12.
Average mid-training loss = (240 + 85 + 12) / 3 = 112.3. This is what training minimizes.
After mid-training, the model has learned to map the trajectory smoothly, so post-training's jump objective has a cleaner surface to navigate.

The loss teaches the model to follow the diffusion path's shape by predicting the true clean image from any point along the journey.

What can go wrong

What can go wrong

Mid-training on wrong solver paths. If the trajectories you train on do not match the solver your post-training will use, the initialization is misaligned and post-training will still be unstable. The mid-training and post-training solvers must use compatible step schedules.
Over-fitting mid-training to solver details. If mid-training overfits to the specific solver noise schedule, the model may memorize solutions for that schedule and fail to generalize to the big jump task. Mid-training must stay general enough to transfer.
Ignoring the low-noise region. If mid-training skips hard examples near the clean image, it learns an incomplete picture of the trajectory. The model must see steps across the full range to build reliable shape.
Done right. Train mid-training on the full trajectory with the same solver, then use those weights to initialize post-training. Convergence becomes fast and artifacts are rare.
What a runnable demo should prove

What a runnable demo should prove

Build a tiny image generation pipeline: (1) load a pre-trained diffusion model on CIFAR-10; (2) run mid-training for 5 epochs on solver trajectories; (3) run post-training for 10 epochs starting from mid-training weights; (4) generate two-step images and measure FID. Repeat with random initialization for post-training. The CMT version should converge faster, produce lower FID, and show smooth training curves without divergence.

FID difference = FID(random init post-training) - FID(CMT post-training); trajectory-consistency score = mean squared error on held-out solver trajectories.

The demo's core proof: mid-training weights enable post-training to converge in half the steps with half the GPU time and better final image quality.
