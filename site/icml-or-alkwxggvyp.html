Graph Alignment for Benchmarking GNNs and Learning Positional Encodings

A graph alignment task reveals which neural networks truly understand graph structure by ranking them on a self-supervised problem with tunable difficulty.

Paper explainersAll themesGraph & Geometric Learning

Most tests of graph neural networks (models that learn from networks of connected nodes) use standard prediction tasks like classifying nodes or predicting links. But these tasks do not always tell you which model truly understands the shape of the graph itself. This paper introduces a new test: can a model align two shuffled versions of the same graph that is, figure out which nodes in one graph correspond to which nodes in the other? By tuning how hard the graphs are to align, you can fairly rank different models and discover that the learned node representations can even teach a large language model (a model trained to predict text one word at a time) about graph structure.

Zero assumption version

Why benchmarking graph neural networks is stuck

Today, graph neural networks (models trained on networks where each point is connected to others) are tested on tasks like predicting a missing node label or guessing which nodes are linked. But these tasks do not isolate graph structure itself: a model might get lucky by memorizing node features, or it might succeed because the task is too easy to reveal what the model actually learned. There is no standard way to tune how hard a test is, so comparing different model designs becomes unreliable.

A naive first attempt: give each model a graph and ask it to classify the nodes. But this only tests whether the model can predict labels not whether it understands the graph's layout or connectivity. Two completely different models might both get 95% accuracy, but you still cannot tell which one truly grasps the underlying structure.

The one thing missing. A test that isolates and measures graph structure understanding, with a difficulty knob to make fair comparisons.

The algorithm as a flow

What it actually does

Start with a graph

A network of nodes and edges (nodes are points, edges are connections between them).

Shuffle and copy it

Create a second version with nodes renumbered but the same connections.

Add noise to both

Randomly flip edges (disconnect some, add false ones) to control difficulty.

Run the model

Each model tries to match nodes in copy A to nodes in copy B, solving the alignment puzzle.

Measure success

Count how many node matches the model got right; rank models by how well they handle each noise level.

What the paper changes

What the paper changes

The paper introduces a new standard test task: graph alignment (aligning two shuffled copies of the same graph instead of predicting labels or links). This task directly measures whether a model understands the graph's structure, because the only way to match nodes correctly is to use the connectivity pattern.

the object it moves  =  the benchmark task itself
The hidden quantity

The hidden quantity: noise tolerance

measured quantity  =  alignment accuracy at each noise level

The paper measures one key quantity: how many node matches the model gets right when the graphs contain varying amounts of random edge noise. This reveals which models truly understand structure versus which ones are brittle. Isotropic models (treating all directions equally) hit a cliff and fail as noise rises; anisotropic models (learning directional features) stay accurate longer. The paper does not just report one accuracy number it plots how accuracy falls as noise increases, which shows the true ranking.

The paper generates graph alignment datasets with a noise dial: the percentage of edges flipped controls the puzzle difficulty. When noise is too low, all models stay near 100% accuracy and you cannot see any difference. When noise is too high, all models collapse to zero and you cannot see any difference either. At the middle range (the sweet spot), good models still score 70-90% while bad ones drop to 20-50%, making differences statistically clear and measurable.

Why it works

Why this benchmark reveals true structural understanding

Predicting node labels or links is too easy a model can cheat by remembering node features or surface patterns. Graph alignment strips away that cheat: the only signal is the connectivity pattern itself. To solve alignment well, a model must learn which local neighborhoods are unique and how they fit together. When noise is present, a model that truly understands structure can still match nodes because it has learned patterns that hold up despite the noise, whereas a model that memorized surface features fails immediately.

Anisotropic models (ones that learn different weights in different directions around each node) stay accurate because they capture patterns in the graph where some neighborhoods are strong (densely connected) and some are weak (sparse). Isotropic models treat all neighbors equally and rely on global symmetry, so they hit a wall as noise breaks those symmetries. By varying noise, the benchmark forces models to prove their understanding at different difficulty levels. The sweet spot noise level is where model differences are clearest, creating a ranking where the difference between good and bad models is statistically clear.

Measuring alignment accuracy

First in words:

correctness equals the number of nodes the model matched right, divided by the total number of nodes, measured at each noise level separately

Then the compact form:

accuracy_k = (number of correct node matches at noise level k) / (total nodes)

Every symbol:

accuracy_kthe alignment accuracy when k percent of edges are randomly flipped
noise level kthe percentage of edges that are randomly changed (swapped or deleted) in both graphs
node matcha prediction that node i in graph A corresponds to node j in graph B
correct matchthe model's prediction was right: node i and node j are truly the same node
A tiny worked example
Graph has 10 nodes. At 0% noise (no edge flips), model matches all 10 correctly. Accuracy = 10 / 10 = 100%.
Same 10-node graph at 20% noise (20% of edges randomly flipped). Model matches 8 out of 10 correctly. Accuracy = 8 / 10 = 80%.
Same 10-node graph at 40% noise. Model matches only 5 out of 10. Accuracy = 5 / 10 = 50%.
Plotting accuracy on the y-axis and noise on the x-axis shows each model's learning curve. Steep drop shows the model fails when graphs are altered. Gradual drop shows the model stays accurate despite changes.

The accuracy curve reveals whether a model truly learned graph structure or just memorized shallow patterns; models with real structure understanding stay accurate longer as noise rises.

What can go wrong

What can go wrong

Random graphs are too easy or too hard. If the generated graphs are pure noise (just random edges with no patterns), then no model can solve alignment, and ranking is impossible. If they are too rigid (like grids or trees with obvious structure), even weak models succeed and differences vanish. The paper solves this by tuning graph properties (density, diameter, modularity) to find the middle ground where differences matter.
The noise level misses all model differences. If you pick too high or too low a noise level, all models look the same. The paper's key finding: there is an optimal noise band where model differences are statistically clear. Outside that band, the ranking is useless.
Learned embeddings are just random. If the model solves alignment by accident (not by truly learning structure), the node embeddings it learned will not transfer to other tasks. The paper tests this: they use the learned embeddings as features for a transformer on a different graph task. If embeddings are meaningless, transfer fails. But 98% reconstruction accuracy proves they captured real structure.
Done right, alignment benchmarks fairly. When graph properties and noise are tuned correctly, alignment ranking is statistically reproducible and the learned embeddings transfer to new tasks. This proves the benchmark measures real structural understanding.
What a runnable demo should prove

What a runnable demo should prove

Build a simple implementation: create a 50-node graph (e.g., random with 200 edges), shuffle node labels to create a second copy, then sweep noise from 0% to 50% (flip that percent of edges). For three simple models (random matching baseline, graph edit distance matching, one small graph neural network), compute alignment accuracy at each noise level and plot the curves. The key observation: the random baseline drops to 0% immediately, the edit-distance model plateaus at ~50%, and the neural network stays above 80% even at 30% noise.
