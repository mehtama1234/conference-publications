Anchored Supervised Fine-Tuning

When teaching a language model to write better, add a leash that ties it to what it already knows, so it learns from good examples without drifting into gibberish.

Paper explainersAll themesLLMs & Foundation Models

After a language model learns to read, we teach it to write better by showing it good examples. But this runs into a fork in the road: copying examples closely is fast and safe but leads to mindless mimicry, while learning deeper strategies takes twice as much computing power. Anchored Supervised Fine-Tuning finds a middle way by watching the model's moment-to-moment confidence and attaching a leash that keeps the model tethered to its starting point, so it learns faster strategies without spinning out of control.

Zero assumption version

The fork in the road after pre-training

After a language model is trained on raw internet text, it can read and answer questions in broad strokes, but it makes mistakes and waffles. To fix this, we need to teach it better behavior, because raw internet text contains misinformation, lazy thinking, and edge cases the model learned to mimic. There are two classic paths.

Path one: Supervised Fine-Tuning (SFT) shows the model thousands of high-quality examples of correct answers and lets it memorize patterns from them. This is fast because we just replay the examples; no talking back to the model. But the model tends to learn surface tricks—when the problem changes slightly, it breaks.

Path two: Reinforcement Learning (RL) teaches the model by reward and penalty, like training a dog. The model tries answers, we score each one, and the model nudges itself toward higher scores. This teaches real strategy, not mimicry. The catch: we have to let the model generate millions of trial answers and score each one, which costs ten times more computing power.

The naive fallback—just copy examples verbatim—fails when the test case is anything the model hasn't literally seen before. What we need is a way to inherit RL's strategic learning without RL's monstrous cost.

The paper in one sentence. Add a lightweight leash—a penalty that pushes the model back toward its starting weights—and it learns fast strategies while staying stable.

The algorithm as a flow

What it actually does

Step 1: Collect expert examples

We gather a dataset of correct problem-solution pairs (math proofs, medical diagnoses, code snippets).

Step 2: Watch the model's confidence word by word

As the model writes each word, measure how sure it is of each choice.

Step 3: Reweight each example by confidence

Examples where the model is confident get bigger training steps; uncertain ones get smaller steps.

Step 4: Add a tether to starting weights

Attach a penalty that pulls any weight change back toward its original value, proportional to distance moved.

Step 5: Train until convergence

The model learns strategic patterns (like RL) without drifting, at one-third the cost of reinforcement learning.

What the paper changes

The one thing the method changes

The paper rewrites the loss function (the scoring rule that guides training). The traditional SFT loss treats all words equally. The paper's method upweights words where the model is already somewhat confident and adds a penalty for any weight that strays far from its starting value.

the object it moves  =  Loss function
The hidden quantity

The drift penalty: how far weights have wandered

measured quantity  =  KL divergence from the start

As the model trains, its weights shift. The hidden quantity here is distributional divergence: a measurement of how far the trained model has drifted away from where it started. Think of it as the sum of all tiny distances each weight has moved. Large movements trigger a penalty.

The paper measures this by computing a KL divergence term (a mathematical distance between probability distributions). Each time a weight strays, the penalty grows, pulling the weight back toward its original value. The penalty is lightweight—just enough to prevent drift, not enough to freeze learning.

Why it works

Why the tether works

Here is the core mechanism. Standard SFT asks: fit the examples perfectly. But the examples are a snapshot of human knowledge, not the whole universe of correct answers. The model learns to mimic the surface patterns (memorization) because there is no penalty for overfitting.

Dynamic Fine-Tuning (DFT) tries to fix this by reweighting: confident predictions get rewarded more. This is closer to RL's principle—learn strategies, not templates. But reweighting alone is dangerous. Imagine a model that sees one tricky example and becomes extremely confident about a wrong pattern. That confidence feeds itself: the more confidently wrong it gets, the bigger the training step it takes toward that wrongness, until it has drifted into nonsense.

Anchored SFT solves this by adding a tether. Every weight movement costs a tiny penalty proportional to how far it has moved from the start. The model still learns strategies (via reweighting), but it cannot wander far without paying a price. The penalty is light—just strong enough to keep the distribution anchored—so learning stays fast and stable.

Math after the picture

The equation: loss plus anchor

First in words:

total_loss equals the negative log of model probability on good examples, weighted by confidence, plus a regularization term that penalizes weights for moving away from their starting values.

Then the compact form:

L = -E_x,y* [ (model_score(y*) / base_model_score(y*)) * log(model_prob(y*|x)) ] + lambda * KL(model_distribution || base_distribution)

Every symbol:

model_prob(y*|x)how sure the current model is about the correct answer y*
base_model_score(y*)how sure the starting model was about this same answer
log(model_prob(y*|x))how much the model is rewarded for getting this answer right
lambdathe strength of the tether (a small number; bigger lambda means pull harder to stay near start)
KL(model_distribution || base_distribution)a distance measurement: how far the new model has drifted from the old one
E_x,y*take the average over all training examples
A tiny worked example
Example: weight w1 starts at value 5.0, gets adjusted to 5.4 during training (moved 0.4).
Example: model confidence on a math answer is 0.9, base model confidence was 0.6, ratio = 0.9/0.6 = 1.5.
Training step for this example: -1.5 * log(0.9) = -1.5 * (-0.105) = 0.158 (reward for getting it right, boosted by confidence).
Anchor cost: lambda * (moved_distance)^2 = 0.1 * (0.4)^2 = 0.016 (penalty for straying from home).
Net: 0.158 + 0.016 = 0.174 total loss increment from this example.
Same movement (0.4), but the anchor cost is tiny compared to the learning gain, so the model updates but stays tethered.

The ratio of confidences upweights examples the model is already good at; the KL term glues the weights to their starting values.

What can go wrong

What can go wrong

Lambda too large If the tether is too tight (lambda too high), the model barely moves at all. It does not learn new behavior; it just repeats the base model. The penalty crushes learning.
No good starting model The method anchors the model to where it began. If the starting model is broken or biased, the tether drags the new model back to those mistakes.
Misleading examples If an example in the training set is wrong or unrepresentative, reweighting by model confidence can amplify the mistake. The model gets confident it is right and drifts toward that error.
Done right Choose lambda by cross-validation on a held-out validation set. Use a base model that is already reasonably good. Audit the example dataset for quality before training. Monitor the distance the weights move and dial lambda to keep drifts small but learning fast.
What a runnable demo should prove

What a runnable demo should prove

Build a toy language model (a few million adjustable numbers, small vocabulary), initialize it by reading raw text. Collect 100 ground-truth examples of correct reasoning (e.g., simple arithmetic, matching patterns to rules). Split: 80 train, 20 test. Run three training runs: (1) standard SFT, (2) Dynamic Fine-Tuning (DFT) alone, (3) ASFT with a reasonable lambda. Measure accuracy on both the training examples and a separate held-out test set.

accuracy_on_train = (correct_answers) / (total_train_examples); accuracy_on_test = (correct_answers) / (total_test_examples); forgetting = accuracy_on_train_before - accuracy_on_train_after (should be zero or near zero for ASFT)

The key test: ASFT should match or beat DFT on the training set AND have much higher accuracy on the test set, because the tether prevents wild moves that look good on training but break on new data. SFT will memorize train but fail test because it has no mechanism to learn generalizable strategy. DFT will learn better but may thrash (oscillate and become unstable) because unanchored reweighting can create feedback loops where confident mistakes amplify themselves. ASFT should be steady.
