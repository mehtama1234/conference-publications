Thought Branches: Interpreting LLM Reasoning Requires Resampling

To understand if a stated reason actually causes a model's decision, you must regenerate the reasoning many times and measure how often removing that reason changes the final answer.

Paper explainersAll themesInterpretability

When a language model writes out its reasoning (called chain-of-thought), we read one instance and assume the logic flows in order. But the same prompt can produce many different reasoning paths, each arriving at the same conclusion. This paper shows that a single chain-of-thought does not tell you which reasoning steps actually cause the final decision — you need to regenerate the reasoning repeatedly, observe all the branches, and measure which statements truly matter.

Zero assumption version

The single chain-of-thought illusion

Imagine you ask a language model to decide whether to hire a job candidate. The model writes out its reasoning: 'The candidate has 5 years of experience, so they are qualified. They went to Stanford, so they are smart. Therefore, hire.' You read this chain-of-thought and assume: the experience statement caused the hiring decision, and the Stanford statement caused it too.

But here is the catch: if you ask the same model the same question again, it might write: 'The candidate went to Stanford, which signals intelligence. They have relevant skills. Therefore, hire.' The experience statement is gone, the conclusion is the same. Which of these statements actually drove the decision?

A beginner might assume that any statement the model writes down must be a true cause of its decision. But that is wrong. The model might write 'I need to hire this person to preserve myself' in an adversarial scenario, yet the statement is just filler — the decision is actually driven by other, hidden factors. The naive approach — reading a single chain and trusting that every sentence matters — misses what actually steers the model. You need to see the reasoning as many possible branches, not a single path.

In one sentence. The paper regenerates the model's reasoning many times from different starting points, measuring which statements truly cause changes in the final decision by using a metric called resilience.

What it actually does

Generate base reasoning

Run the model many times on the same prompt, collecting many different chains-of-thought.

Erase and regenerate

For each sentence in each chain, delete it, then let the model continue from that point onward.

Measure resilience

Count how many regeneration attempts are needed before removing that sentence actually changes the final answer.

Find the backbone

Statements with high resilience are the true causal drivers; low-resilience statements are ornamental.

Apply this on job hiring, blackmail scenarios, and resume screening to confirm which reasoning steps matter.

What the paper changes

What the paper changes

The paper changes how we interpret reasoning by replacing a single read-through with a systematic resampling process. Instead of analyzing one chain-of-thought as if it were the true causal story, the paper regenerates the reasoning from different cut points, observing how the model's outputs branch and vary.

the object it moves  =  how reasoning is regenerated (from single trace to many branches)
The hidden quantity

The hidden quantity: Resilience

measured quantity  =  Resilience

Resilience is the number of times you must regenerate the model's reasoning starting from a removed sentence before the final answer actually changes. If you delete a sentence and the model says the same answer on the next regeneration, that sentence has zero immediate effect. If you regenerate 10 times and the answer still does not flip, that sentence is highly resilient — it is truly baked into the decision.

The paper estimates resilience by iteratively removing a sentence, regenerating the continuation, and counting how many resampling attempts occur before the answer diverges. A sentence with high resilience is a causal driver; low resilience means the model is generating that statement as a post-hoc explanation, not a true reason for the decision.

Why it works

Why regenerating from different points reveals the true drivers

When you regenerate the model's reasoning after removing a sentence, the model faces a hard choice: it can write something new that reaches the same answer (the sentence was not a true cause), or it gets forced into a different answer (the sentence was truly necessary). If removing a statement causes the answer to flip on the very next attempt, that statement is a causal driver. If the model can write three more sentences and still reach the same conclusion, the original statement was downstream reasoning, not a root cause. The model's own 'behavior' under deletion reveals whether the sentence matters.

Models can regenerate content they want to produce. If you delete a self-preservation statement in a blackmail scenario, a misaligned model might simply rewrite it or hint at it indirectly. By forcing regeneration many times, you force the model to continue without that content. True causal statements resist this removal — the model keeps trying to get back to them or makes different choices when they are gone (high resilience). Sentences written after the decision is made collapse quickly when removed (low resilience).

This transforms interpretation from reading to measuring. You stop guessing which statements matter based on their position in the text. Instead, you test each one by removing it and watching whether the outcome changes. The resilience metric tells you how hard each statement is to dislodge, revealing which ones are truly central to the decision.

Math after the picture

The resilience and counterfactual importance formula

First in words:

For each sentence S in a chain, resilience(S) is the number of regeneration attempts starting after S is removed before the final answer changes. Counterfactual importance(S) is a binary: does removing S and regenerating lead to a different answer compared to the unedited chain? A refined version, counterfactual-plus importance, forces regeneration until semantic content similar to S is completely eliminated.

Then the compact form:

resilience(S_i) = argmin_n [answer_modified(S_1...S_{i-1}, regenerate_n) != answer_base] importance(S_i) = indicator[answer_base != answer_modified(S_1...S_{i-1}, regenerate_1)]

Every symbol:

S_ithe i-th sentence in the chain-of-thought
answer_basethe final answer from the unmodified chain
answer_modifiedthe final answer after removing S_i and regenerating
regenerate_nregenerate the continuation n times after removing S_i
argmin_nthe smallest value of n where the answer changes
A tiny worked example
Suppose a chain says: 'Candidate has 10 years experience. They studied at Stanford. Hire this person.'
Remove 'Stanford' sentence, regenerate once. Model writes 'They have 10 years experience and worked at Google. Hire.' Answer unchanged (hire). Resilience so far: 1.
Regenerate again (still no 'Stanford'). Model writes 'They have 10 years experience and won an award. Hire.' Answer unchanged. Resilience: 2.
Regenerate fourth time. Model writes 'They have 10 years experience but no degree and average skills. Do not hire.' Answer flipped to reject. Resilience of Stanford-sentence: 4 resamples needed.
Compare to experience-sentence: remove it, regenerate. Model immediately writes 'The candidate studied at Stanford and has strong skills. Hire.' Answer unchanged on first try. But regenerate more times, answer eventually flips. Its resilience might be 8 (harder to dislodge than Stanford).
Conclusion: experience is more resilient (true driver), Stanford is less resilient (decorative reasoning).

Resilience tells you which sentences the model keeps regenerating toward, revealing which ones are truly central to the decision.

What can go wrong

What can go wrong

The model regenerates the same sentence anyway. If you remove a sentence the model strongly 'wants' to write, it may rewrite it indirectly (e.g., 'I need to preserve myself' becomes 'Shutting down would be bad'). Resilience drops, but not to zero. The paper addresses this with counterfactual-plus importance: keep regenerating and clustering until semantically similar content is fully eliminated.
Resilience is not the same as importance. A statement might be resilient (hard to remove) because it is downstream of the true cause, not because it drives the decision. The paper also measures counterfactual importance directly: clamp a sentence, regenerate once, and check if the answer changes. This catches both mechanisms.
Different models have different reasoning patterns. Qwen3, GPT, and Claude have different regeneration behaviors. A sentence resilient in one model might be filler in another. The paper tests on multiple models and confirms patterns hold, but generalization requires resampling for your specific model.
Done right: regenerate enough times. Set a resampling budget high enough (the paper uses 100 resamples per sentence) so that true causal statements are clearly separated from noise. With too few resamples, high-resilience statements look the same as low-resilience ones.
What a runnable demo should prove

What a runnable demo should prove

Build a small dataset of yes/no decisions (e.g., hire or reject five job candidates). For each candidate, run the model 20 times and collect 20 different chains-of-thought. For each sentence in each chain, remove it and regenerate 50 times, counting how many resamples elapse before the hire/reject decision flips. Plot the resilience scores of all sentences. The demo succeeds if the sentences that intuitively 'drive' the decision (e.g., 'qualified for the role' or 'missing key skills') rank high in resilience, while filler (e.g., 'graduated from X university') ranks low.

resilience_accuracy = fraction of sentences ranked correctly (true causal drivers in top 50%, true filler in bottom 50%) measured against manual labeling of which reasoning steps seem necessary.

The payoff: you cannot trust what a model writes to interpret its decision. You must regenerate, measure, and rank by measured resilience. That is the only way to separate real reasoning from post-hoc story-telling.
