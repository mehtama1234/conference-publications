Larger Datasets Can Be Repeated More

When training on repeated data, bigger datasets allow more repeats before the benefit stops growing—the paper proves exactly how many.

Paper explainersAll themesLearning Theory

Training a language model on the same data twice is called multi-epoch training. Repeating helps the first few times, because each pass still refines the model's understanding of rare patterns in the data. But how many times can you repeat before it stops helping? It depends on dataset size: larger datasets contain more rare patterns, so they sustain useful repeating for more epochs. This paper proves a scaling law quantifying this tradeoff.

Zero assumption version

The dataset reuse question

A language model needs data to learn from. If you have collected 500 million words, you can train in one pass (read each word once) or multi-epoch training (read the same words over and over, K times). Multi-epoch training costs less compute than collecting fresh data, so it is tempting.

The naive approach: treat every epoch the same. Train for 4 epochs on the same data, expect 4 times the learning. This breaks in practice: after a few epochs, each new pass through the data teaches less and less. By epoch 10, rereading adds almost nothing. The reason is that the model has already learned the common patterns; later passes only refine rare examples. Small datasets run out of new patterns quickly, so they hit this wall fast. Large datasets have more rare patterns, so they can sustain more epochs before hitting the wall.

The method in one sentence. The paper defines the effective reuse rate: the factor by which a fresh dataset must grow under one-pass training to match the performance of K-epoch training on the smaller dataset.

The algorithm as a flow

What it actually does

Ask the reuse question

Can repeating a dataset of size N match fresh data? Yes, but how much fresh data is needed?

Define the reuse rate

Measure how many times bigger a fresh dataset must be to achieve equal loss, under one-pass training.

Analyze bias and variance

In gradient descent on linear regression, each training step has two types of error: directional error from incomplete data, and random noise.

Measure how each evolves

Repeating data: the model sees the same patterns, so directional error stays large (it has memorized main ideas, refinements come slowly). Fresh data at each step shrinks directional error fast, because each batch contains new information.

Solve for the tradeoff

The paper proves: when repeats are few, the rate grows linearly (each repeat is nearly as good as fresh data). Beyond a dataset-size threshold, rate stops growing (repeats teach nothing new).

What the paper changes

What the paper changes

The paper changes the dataset size required for one-pass training to match multi-epoch training. Concretely, it measures the effective dataset size (how many fresh samples you would need) as a function of the number of epochs K and original dataset size N.

the object it moves  =  Effective dataset size
The hidden quantity

The effective reuse rate

measured quantity  =  E(K, N): how much larger a one-pass dataset must be

The effective reuse rate E(K, N) is a number that answers: if I train once on N prime fresh samples, how big must N prime be to match the accuracy of training K times on N repeated samples? It is a ratio—a pure number, like 1.5 or 3.2. The paper estimates it by running actual training experiments and measuring when the losses match across both setups.

The hidden insight: E(K, N) is not fixed. It changes depending on how many epochs you plan and how many samples you started with. The paper proves two regimes using math: when K is small (K much smaller than log N), the rate is linear in K. When K is large (much bigger than log N), the rate stops growing—it saturates. This saturation is the key: bigger datasets saturate at a higher plateau.

Why it works

Why repeating data hits a wall

Training works by squashing two types of error: directional error (you are nudging weights in slightly the wrong direction because your sample is not perfectly representative) and random noise (your sample is small, so fluctuations drown out signal). Fresh data at each step fixes the directional error quickly—each batch has new information. Repeated data in epoch 2, epoch 3, etc., only fixes random noise from previous epochs. The model has already learned the main patterns.

When your dataset is large, the model learned almost nothing about the tail patterns (rare examples) by the end of epoch 1. Epoch 2 teaches it more about the tail. Epoch 3 still has unseen tail patterns. So repeating a large dataset yields high-value information for several epochs. But when your dataset is small, epoch 1 exhausts almost all the information it contains. Epoch 2 teaches very little, because the model has already memorized the main ideas and most rare combinations. The point where repeating stops helping scales with the size of the dataset: it is roughly logarithmic in N. So if you double your starting dataset, you can afford maybe one more epoch before hitting diminishing returns.

Learning rate decay matters, too. The paper uses a learning rate that shrinks slightly over time. This affects how quickly bias and variance decay with each epoch, which changes the exact break-even point, but not the regime shape.

Math after the picture

The effective reuse equation

First in words:

Excess risk equals log of total steps divided by total steps, until K exceeds log N, then excess risk depends only on batch size, not epochs.

Then the compact form:

For K < log(N): R_bar(K,N) = Θ(log(K·N) / (K·N)) = Θ(log(T) / T), where T = K·N total steps. For K > log(N): R_bar(K,N) = Θ(1/N), independent of K.

Every symbol:

R_bar(K,N)expected error after K epochs on N samples (minus irreducible noise)
Knumber of epochs (how many times you read the same data)
Nnumber of original samples (dataset size)
Ttotal training steps (T = K times N)
log(T)logarithm of T; grows slowly
Θ( )'of order', meaning the formula shape (the key parts; constants omitted)
Tiny worked example
Suppose N = 1,000 samples, K = 4 epochs. Then T = 4,000 total steps.
Since 4 < log(1000) ≈ 7, we are in the linear regime.
Excess risk is proportional to log(4000) / 4000 ≈ 8.3 / 4000 ≈ 0.002.
To match this loss one-pass (K=1), we need T' such that log(T') / T' = 0.002.
Solving: T' ≈ 4 × 1000 = 4,000 total steps = E(4,1000) × 1000.
So E(4,1000) ≈ 4 (linear in K, as predicted for small K).
Now suppose K = 64 epochs on the same 1,000 samples. T = 64,000.
Since 64 > log(1000), we enter the plateau regime.
Excess risk becomes proportional to 1 / 1000 = 0.001 (independent of K now).
To match this one-pass: we need T' ≈ 1 / 0.001 = 1,000 fresh samples one-pass.
So E(64,1000) ≈ 1 (no gain from the extra epochs; rate saturates).

The pivot is at the logarithm of N epochs: below it, every epoch yields linear gains; above it, the reuse rate stops growing.

What can go wrong

What can go wrong

Ignoring dataset size. If you assume the reuse rate is constant across all dataset sizes, you will miss the central finding: big datasets allow more repeats because they contain more rare patterns that the model is still learning in later epochs; small datasets have fewer rare patterns, so they exhaust their teaching value fast.
Assuming all epochs help equally. The first repeat always helps because the model is still refining its understanding of common patterns. But once you exceed a threshold (roughly the logarithm of dataset size), each new repeat teaches almost nothing, because rare patterns have been exhausted. The paper shows exactly where this threshold lies for any dataset size.
Changing the learning rate schedule. The math assumes a specific learning rate setup (shrinking over time in a certain way). Different schedules will shift the threshold point, and the logarithmic factor may not hold exactly.
Applied correctly. Measure your dataset size, decide how many epochs you want to run, and use the paper's formula to predict the reuse rate. If you are below the threshold, repeating is worth it. Above the threshold, collect more data instead.
What a runnable demo should prove

What a runnable demo should prove

Build a simple linear regression model on a synthetic dataset with sizes 100, 1000, and 10000 samples. Run gradient descent for 1, 2, 4, 8, and 16 epochs on the same data. Separately, run gradient descent one-pass on fresh data until the loss matches each repeated-data run. For each dataset size and epoch count, measure how many fresh samples were needed. Plot the reuse rate (fresh needed divided by original) versus epoch count for each dataset size. You should see three patterns: when epoch count is small, the rate is roughly linear; when epoch count is large, the rate stops growing (plateau); and the plateau level rises with dataset size.

Reuse rate is the ratio of fresh data needed (one-pass) divided by original data (K epochs), where both achieve the same loss

The demo will make it impossible to ignore the core finding: bigger datasets can be repeated more times before each new repeat stops helping. The repeated dataset size sets the limit.
