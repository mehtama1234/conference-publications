FreeRet: MLLMs as Training-Free Retrievers

The paper turns an off-the-shelf multimodal language model into a retriever without extra training by extracting semantically faithful embeddings for search and then using the same model to rerank candidates.

Paper explainersAll themesMultimodal

Retrieval systems usually rely on encoders trained specifically to place matching items close together in a shared representation space. Multimodal large language models already understand text, images, and other modalities, but they are not typically exposed as retrievers out of the box. A common response is to train extra contrastive heads on millions of labeled pairs. This paper asks whether that extra stage is necessary. The answer is yes if one uses the model naively, but often no if one reads the right internal features and applies the model in two stages. FreeRet first extracts embeddings, which are fixed-length lists of numbers used for similarity search, directly from the multimodal model in a way that avoids parts of the network tuned mainly for predicting the next generated unit of text. It then uses the model's full reasoning ability to rerank a short candidate list. The result is a training-free retrieval pipeline that keeps the model's generative ability while also serving as the search engine.

Zero assumption version

General multimodal models do not become retrievers automatically

A retriever must do two things well. It must scan a large collection quickly, and it must rank the truly relevant items above distractors. Off-the-shelf multimodal language models contain broad semantic knowledge, but their default interfaces are designed for generation, dialogue, and instruction following. Those interfaces do not automatically produce representations that are ideal for nearest-neighbor search.

The mismatch has two parts. First, the model may expose features that reflect prompt framing or lexical habits rather than deep cross-modal meaning, which hurts fast search. Second, even if the model can compare a query with a candidate accurately when asked directly, using that reasoning for every item in a large corpus is too expensive. The paper builds a two-stage pipeline that separates the cheap search step from the expensive reasoning step while keeping both inside the same pretrained model.

The problem: Multimodal language models know a lot, but their default outputs are not automatically shaped for scalable retrieval.

The algorithm as a flow

What it actually does

Form a retrieval prompt

Condition the multimodal model with an explicit prior about the retrieval task so the produced representation emphasizes query intent.

Extract search embeddings

Read internal features chosen to preserve semantic content for similarity search instead of relying on a standard lexical alignment layer.

Search the corpus quickly

Use those embeddings to retrieve a short candidate list with nearest-neighbor search.

Rerank with detailed reasoning

Ask the same model to compare the query with each candidate more carefully, using neutral framing so answer order does not bias the choice.

Return evidence or feed RAG

Use the reranked results directly or pass them into retrieval-augmented generation inside the same model.

What the paper changes

What the paper changes

The paper changes how a pretrained multimodal model is read and deployed. It does not add retrieval training. Instead, it extracts search-oriented internal features, adds prompt-level priors, which means prompt instructions that tell the model which retrieval cues to emphasize, during representation generation, and uses a second reasoning stage to refine the shortlist.

The hidden quantity

Hidden quantity: semantic faithfulness of the embedding

measured quantity  =  semantic faithfulness

The critical hidden quantity is whether the embedding preserves the meaning needed for retrieval rather than artifacts of the model's generation interface. Two representations can have the same dimension and still differ sharply in retrieval value. One may track wording style or prompt format. Another may track the actual cross-modal content that determines relevance.

FreeRet tries to raise semantic faithfulness in three ways. It bypasses an alignment layer that can inject lexical shortcuts. It conditions representation generation with explicit retrieval priors so the model knows what kind of meaning to emphasize because the prompt states the retrieval role of the representation instead of leaving the model in its default generation mode. It then uses a neutral comparison format during reranking so the final decision depends less on presentation order and more on actual relevance.

Why it works

Why training-free retrieval can work

The method works because pretrained multimodal models already contain the knowledge needed for relevance judgments. The main difficulty is exposure, not absence. One must expose that knowledge in a form usable for search, then reserve the expensive detailed comparison for a much smaller set of candidates.

The first stage matters because nearest-neighbor search over the whole corpus is cheap only when each item has a compact fixed representation. By reading internal features that better preserve semantic content, FreeRet makes this stage strong enough to avoid throwing away the right answer early. The second stage matters because exact relevance often depends on subtle details such as role ordering, visual attributes, or cross-modal consistency, which the model can judge more accurately when it reasons over a small list.

Neutral framing in the reranker matters because generative models are sensitive to how options are presented. Removing positional bias makes the comparison more about content, which is why reranking can correct first-stage misses without introducing a new training pipeline.

A tiny worked example
A text query asks for an image of a red bus beside a bridge.
The first-stage embedding search returns ten images whose representations are close to the query representation.
One candidate shows a red bus alone, another shows a bridge with no bus, and another shows both objects together.
The second stage asks the model to compare the query against those top candidates directly.
Because reranking examines the object relation rather than only coarse topic overlap, the image containing both the bus and the bridge can move to the top.

The first stage must be good enough to keep relevant items in the shortlist. The second stage cannot recover an item that was never retrieved.

What can go wrong

What can go wrong

A weak shortlist limits the whole system. If the first-stage embeddings miss the relevant item, reranking cannot recover it because the candidate never enters the second stage.
Prompt design may matter more than expected. The retrieval prior and reranking frame can alter the internal features the model emits, so poorly chosen prompts can reduce semantic faithfulness.
Very specialized domains may still need training. If the corpus uses concepts or modalities the base model barely understands, a training-free pipeline may not create a strong enough search space structure.
Done right: Validate the first-stage recall carefully, use prompt templates that reduce framing bias, and treat the training-free setup as strongest when the base model already has solid cross-modal knowledge.
What a runnable demo should prove

What a runnable demo should prove

Build a demo with a mixed-modality corpus and a set of queries whose correct answers depend on semantic detail rather than exact wording. Show the first-stage nearest neighbors, then show how reranking changes the order.

The demo should establish three points. First, internal features chosen by FreeRet retrieve a stronger shortlist than a naive feature choice because they preserve cross-modal meaning more directly during nearest-neighbor search. Second, reranking corrects errors caused by coarse similarity. Third, the same model can use the retrieved items immediately in a generation step, which demonstrates the practical value of unifying search and response inside one system.
