Making big models smaller and faster

Papers on compressing models and running them efficiently using low-rank updates, mixing specialized experts, or removing unnecessary parameters.

All themesField mapMathematicsAll explainers
What this is

Modern machine learning models can have billions of parameters — numbers that the model uses to make predictions. A model that big can process information and pick up subtle patterns, but it requires massive computing power to run. If you want a model to work on a phone, in a car, or on a tiny device in a factory, you need to shrink it. The key question is how to find and remove the parameters that do not contribute much to predictions, so the model stays smart without getting bloated — because every parameter you remove saves memory and computing time.

The hard part is that the large model's power comes from its size. Every parameter contributes something to the prediction. If you simply delete parameters, the model gets worse. But often, parameters are redundant — many of them are doing almost the same thing, or their contribution is tiny. You need to find which parameters matter and which ones are passengers. Even when you identify the important ones, you have to retrain the model so the remaining parameters adapt and compensate for the ones that are gone.

Researchers use several strategies. Some compress the model by representing it in a more efficient way — for example, using low-rank factorization, which represents large matrices as products of smaller matrices, the way you might factor a big number into smaller primes. Some use sparse updates, where each specialized mini-model (called an expert) handles one kind of input, so only some of the model's parameters activate for each prediction, which saves computation. Some round numbers to fewer bits (the way images on a computer use fewer colors than in real life yet still look right), making the model lighter to store and faster to run because fewer numbers mean less data to process. Some combine these approaches together, which makes the savings multiply — so the resulting model is small, runs fast, and works well because each technique removes a different kind of waste.

How the work breaks down

Making large models practical splits into five directions: learning from larger teachers to shrink them, removing unnecessary weights (the numbers that do the computing) and experts, representing numbers with fewer bits, combining specialized models efficiently, and mixing experts that each handle specific kinds of inputs.

Learning from larger teachers

When you want a smaller model to work as well as a giant one, you can teach the small model to copy the big one's answers. The big model acts like a teacher, showing the small model which predictions are correct. But a plain copy often leaves the small model worse off than just training from scratch, because the teacher and student have different architectures and different ways of thinking.

Knowledge Distillation as Decontamination revisits a worry about this technique: if the big model learned from data that ended up in the test set, does teaching a smaller model just pass along that leak? The paper shows this is rare and much smaller than directly using contaminated data. So distillation actually protects the small model from leaks the big model picked up.

Knowledge Distillation for Large Language Models through Residual Learning takes a different angle. Instead of forcing the student to match the teacher exactly, it lets the student build on top of the teacher's knowledge. When you have a mixture-of-experts teacher (a model with many specialized sub-models), the student can learn which expert to listen to. When the teacher and student even use different word-piece systems, a cross-model attention mechanism lets them still transfer knowledge. This approach means the student can actually improve beyond what the teacher knows, because the student learns its own improvements on top of the teacher's base, rather than being capped by copying the teacher.

AMiD (Knowledge Distillation with Alpha-Mixture) adds another layer: it uses a broader, mathematically grounded approach to mix the different styles teachers produce their answers in, so training is more stable (meaning it doesn't collapse or wobble) and the student learns better. Large Language Model Teaches Visual Students (LaViD) goes cross-domain: a language model teaches a vision model about fine-grained concepts, yet does it without any images—which works because language descriptions encode visual details well enough that the vision student improves beyond models that saw both images and text. The language model describes visual details so well that the vision student learns better than methods trained on both images and text together. These papers show distillation is not just copying — it is building better small models by teaching them how to think.

Removing waste: pruning and sparsity

A trained model has billions of parameters, but many of them do almost nothing. Pruning means cutting away the ones that matter least. Sparsity means only some parts activate for each input — like having experts, where each expert wakes up for certain kinds of data. The challenge is identifying what to prune without breaking the model, and retraining efficiently so the rest compensates.

Composable Sparse Subnetworks via a Maximum-Information Principle builds subnetworks, each specialized for one task or group of tasks. Using a mathematical principle that balances capturing what matters without capturing noise, the paper finds which connections matter most to each task. When you combine subnetworks, they often recover performance across many tasks together, and you can see which functions each subnetwork handles — not a black box.

GradPruner (Gradient-guided Layer Pruning) takes a different route: instead of finding individual parameters to remove, it looks at which entire layers to drop. By watching gradients during fine-tuning, it finds layers that change very little and can go. It cuts 40% of parameters while losing only 0.99% accuracy across medical, finance, and general tasks. Revisiting Weight Regularization for Low-Rank Continual Learning combines two ideas: pruning and low-rank learning on continual tasks. As you learn new tasks over time, it keeps a steady memory footprint by learning changes to weights that are sparse and low-rank — meaning you can represent the updates with fewer numbers.

SALAAD (Sparse And Low-Rank Adaptation via ADMM) uses sparse and low-rank changes to run language models on small devices. A single training run creates a whole spectrum of model sizes — from tiny to nearly full — so you can pick the right size for your hardware without retraining. These four papers differ in what they remove (parameters, layers, connections) but share a goal: find the waste, cut it out, retrain the rest to adapt.

Fewer bits: quantization

Every number in a model takes up space and processing time. If you store numbers with fewer bits — the way a phone image uses fewer colors than real life but still looks right — the model shrinks and runs faster because fewer bits mean less data to move around. The hard part is losing as little accuracy as possible when you reduce precision.

MicroMix (Efficient Mixed-Precision Quantization) takes the idea further: different parts of language models need different precision. Layers that are sensitive lose accuracy if you cut bits too far, but other layers can go very low. MicroMix uses a microscaling format that lets each layer have its own precision level. The result: Llama and Qwen models run 2-3 times faster while staying nearly as accurate as full 16-bit models, even at just 5 bits on average, so each layer keeps only as many bits as it needs to stay accurate.

SoftBinary Coding shifts the angle: instead of rounding numbers to fewer bits, it treats them as drawn from a probability model. Using a mathematical foundation about what makes compression possible, it finds the best way to compress by simulating how well a smaller model can reconstruct what the large one does. The paper shows discrete binary structures can reach the theoretical limits of compression — the best possible trade-off between model size and accuracy.

Synchronizing Probabilities in Model-Driven Lossless Compression adds a practical layer. It applies probabilistic models to compression, and even when predictions go wrong (the model mismatch problem), it stays correct and outperforms standard tools like zip and gzip because it corrects for the mismatch rather than letting prediction errors pile up. These three papers show quantization is not just crude rounding: it is mathematically principled compression that preserves what the model does well.

Merging models and adapting across tasks

You often have multiple models: one trained for task A, another for task B. Merging them into one model that does both saves space and computation compared to running them separately, because one model takes less memory and only one set of computations run. But merging breaks easily — the two models fight each other, and performance plummets. The challenge is merging without losing the strengths each model learned.

DisTaC (Conditioning Task-Specific Updates via Distillation) solves the problem of merging models that would normally fail. When you distill knowledge from one model into the merged model, it glues the pieces together so they work. Gradient-Sign Masking for Task-Specific Update Transport looks at how to move updates from one model to another model with a different architecture. By tracking the sign (direction) of weight changes, not their size, you can transfer knowledge across models of different widths. Transporting Task-Specific Updates across Different Architectures adds a training-free option: you can move task-specific changes across heterogeneous-width models without any retraining, yet still gain performance.

Ensemble Prediction of Task Affinity works before you merge: it predicts whether tasks will help or hurt each other when combined. If you know this upfront, you group tasks smartly so compatible ones merge together, and multi-task learning gains go up because you avoid toxic combinations. From Memorization to Parameter Interference explains why merging fails: when you overtrain experts before merging, they memorize dataset details and their parameters clash when combined. Early stopping fixes this — stop training experts sooner, and merging works better across vision and language models because you avoid the memorization that causes parameter conflicts when models combine.

These five papers cover the merge pipeline: predicting which tasks go together, detecting when training has gone too far, moving task-specific changes across architectures, and finally ensuring merged models actually work. Together they show merging is not a simple average — it is careful coordination of when to train, how to predict compatibility, and how to move knowledge across different model shapes.

Specialized experts for efficiency

A mixture-of-experts model has many small specialized sub-models (experts) and a gating function that picks which ones to activate. Instead of every parameter firing for every input, only relevant experts turn on. This saves computation because you only pay for the experts you use, not the whole model.

CogMoE (Signal-Quality–Guided Multimodal MoE) applies this to cognitive load prediction from brain signals. Not all signal types are equally reliable, so the gate learns which experts to trust based on signal quality. It also balances two goals: getting good predictions and making sure experts are actually used (so they don't go idle). Combination-of-Experts with Knowledge Sharing (CoEKS) handles vehicle routing — a combinatorial problem with many constraints. By sharing knowledge across experts, each expert gets smarter, so the combined model handles new constraints much better than if each expert learned alone. Both papers show that when experts specialize and talk to each other, you get both speed (fewer active experts per input) and accuracy (experts learn from peers).
