LS-Merge: Merging Language Models in Latent Space

Merge different-sized language models by encoding their weights into a smooth shared space, blending there, then decoding back.

Paper explainersAll themesEfficiency & Systems

When you have two trained language models and want to combine their knowledge, the simplest idea is to just average their weights — but this only works if the models are identical in architecture and size. If one model is bigger or shaped differently, averaging fails because the weight positions do not line up. This paper solves that by treating model weights like data: compress them into a shared abstract space using a learned compressor, blend them safely in that space, then decompress back to weights.

Zero assumption version

Merging models fails across different sizes

Suppose you train a small language model on customer-service conversations and a separate small model on technical documents. You now have two pools of knowledge. The naive move: average their weights together. This works only if both models have the exact same architecture, size, and weight layout.

But in practice you often want to merge a small model with a large one, or merge models trained with different design choices. When you try to average weights from a model with 7 billion numbers against a model with 13 billion numbers, the weight arrays have different lengths — there is no obvious alignment. Averaging fails because you are adding numbers from completely different positions together, which is like trying to overlay two photographs of different sizes without scaling one first.

The fix. Encode both models into a smooth learned space where the dimensions match, merge there, then decode back to weights.

The algorithm as a flow

What it actually does

Train a weight compressor

Learn an encoder that squeezes any language model's weights into a compact latent code.

Train a weight decompressor

Learn a decoder that reconstructs weights from latent codes with minimal loss.

Encode both source models

Run each of the two models you want to merge through the encoder to get its latent code.

Interpolate in latent space

Blend the two latent codes in any ratio (50/50, 40/60, etc.) to form a target code.

Decode the merged model

Run the blended latent code through the decoder to reconstruct a new merged model.

What the paper changes

What the paper changes

The paper changes where merging happens: instead of blending weights directly, it blends abstract learned representations of those weights in a shared compressed space (called a latent space — a learned abstract representation of the weights).

the object it moves  =  where models blend
The hidden quantity

The hidden quantity: weight fidelity

measured quantity  =  how well the decoder reconstructs weights

When you compress a model's weights into a compact latent code and then decompress, you lose some information — like when you compress a photo and the result is slightly blurry. The paper tracks fidelity: how closely the decompressed weights match the originals. High fidelity means the compressor and decoder preserve the model's knowledge; low fidelity means important detail is lost, and the merged model will not work well.

The paper measures fidelity by comparing the original weights to the weights reconstructed from the latent code, using standard reconstruction loss. A two-stage training process improves fidelity: first the decoder learns to reconstruct accurately, then it is distilled into a smaller code. This works because the decoder first memorizes how to reverse the encoding perfectly, building up an understanding of weight structure, and only then is that knowledge compressed — so the smaller final code is a refined summary, not a rushed approximation.

Why it works

Why blending in latent space works better than blending weights

When you average two models' weights directly, you are treating weights as independent numbers. But they are not: weight values are entangled — the model's actual behavior depends on the precise relationships between weights. Averaging can break those relationships. For example, if model A sets weight 5 to 0.8 and weight 6 to 0.2 because they need to stay in a certain ratio to work together, averaging them with model B (which sets both to 0.5) destroys that ratio and the merged model's behavior falls apart.

Encoding weights into a latent space first works better because the encoder learns to capture the structure and relationships between weights, not just their raw values. The latent code represents the model as a semantic concept — something like: this is a customer-service model with a certain style. When you blend two latent codes (say 70 percent customer-service, 30 percent technical), the decoder reconstructs weights that respect the relationships learned within each code, rather than blindly averaging unrelated numbers. The result is a coherent model, not a broken average.

A secondary benefit: heterogeneous merging. When models have different sizes, their weight arrays are different lengths. In latent space, both get compressed to the same fixed-size code, so blending is geometrically straightforward. A simple learned projection aligns the codes before interpolating, allowing you to merge a 7-billion and a 13-billion model smoothly.

The reconstruction loss and fidelity trade-off

First in words:

reconstruction loss plus a penalty for code size, minimized during training

Then the compact form:

L = ||W_reconstructed - W_original||^2 + beta * ||latent_code||^2

Every symbol:

W_originalthe model's true weights
W_reconstructedweights decoded from the latent code
||...||^2sum of squared differences (how wrong the reconstruction is)
latent_codethe compressed abstract representation
betahow much we penalize large codes (higher beta = smaller code)
A tiny worked example
Suppose model A has 4 weights: [0.8, 0.3, 0.2, 0.6]. Encode to latent code [5, -2].
Decode that code back: reconstructed weights [0.78, 0.32, 0.19, 0.61].
Reconstruction error: (0.8-0.78)^2 + (0.3-0.32)^2 + (0.2-0.19)^2 + (0.6-0.61)^2 = 0.0004 + 0.0004 + 0.0001 + 0.0001 = 0.001 (tiny: good fidelity).
Code size penalty: 5^2 + (-2)^2 = 25 + 4 = 29 (if beta=0.01, penalty = 0.29).
Total loss: 0.001 + 0.29 = 0.291. Training adjusts encoder and decoder to minimize this.

The model trades off exact reconstruction against code compactness; beta controls the balance.

What can go wrong

What can go wrong

Encoder overfits to seen models. If the encoder is trained only on a handful of models, it learns their specific quirks rather than general weight patterns. When you try to merge a model the encoder has never seen, compression fidelity drops and the merged result is weak. The paper addresses this with a two-stage curriculum and layer-aware chunking: the curriculum forces the encoder to learn rough structure first (on many models), then fine detail, so it generalizes to unseen weights; layer-aware chunking groups related weights together, making the encoder see the same structural patterns across different model sizes.
Code size forces information loss. Making the latent code very compact (to speed up merging) risks losing important detail about the models, because information is like water in a container — squeeze it too small and it starts to overflow and spill. If the code is too small relative to model complexity, both encoded models compress poorly and their distinct knowledge leaks away. The paper uses adaptive compression ratios and careful distillation to find the sweet spot.
Projection mismatch across heterogeneous sizes. When models have very different sizes (a 3B and a 50B model), the learned projection that aligns their latent codes may not generalize well. Merging a small model's knowledge into a huge model can flatten the small model's contribution to insignificance.
Done right. Train the encoder on a diverse set of model sizes and architectures, use a graduated compression curriculum so the encoder learns to capture fine details first, then compress carefully, and test the merged model on downstream tasks to confirm knowledge from both sources is preserved.
What a runnable demo should prove

What a runnable demo should prove

Build a toy merging pipeline: train a small autoencoder on the weights of three small language models (each trained on a different task: say, sentiment classification, named-entity recognition, and paraphrase detection). Merge the weights of two models in latent space and decode the result. Fine-tune the merged model on a held-out test task and measure whether it retains skills from both source models.

retained_knowledge = min(accuracy_source1_after_merge, accuracy_source2_after_merge) - baseline_random

The demo must show that latent-space merging preserves both models' original capabilities better than naive weight averaging does, because averaging breaks weight relationships while latent blending preserves semantic structure.
