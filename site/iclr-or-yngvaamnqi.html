From Seeing to Doing: Bridging Reasoning and Decision for Robotic Manipulation

A robot learns to manipulate objects by first teaching itself to reason about where things are and where to move, then using that spatial reasoning to guide physical actions.

Paper explainersAll themesRobotics & Control

Robots struggle to pick and move objects they have never seen before, because robot training data is limited and messy — different robots, different camera angles, different object types. This paper proposes FSD: a model that learns step-by-step spatial reasoning (where is this part? where should it go? what path connects them?) as an intermediate layer, then uses that reasoning to guide the robot's physical moves. By separating the reasoning about space from the actual robot movements, the same reasoning can work for many different robots and tasks.

Zero assumption version

Why robots fail on new objects and tasks

A robot today is trained on thousands of videos of people or robots picking up and moving objects. If you show it a new object in a new scene, it often freezes or moves the gripper wildly. The core problem: robot videos are expensive and rare — far fewer than the billions of internet images used to train vision models. The data also mixes different robots, cameras, and lighting, making it hard to learn clean patterns.

A naive approach: take a vision model trained on internet images (it understands what things look like) and directly attach instructions to it (pick up the blue cup). But this fails because the model has never learned to think step-by-step about where things are in space, or how to plan a path from here to there. It just tries to guess actions from raw pixels, which fails when the robot faces a scene it has never trained on.

In one sentence. FSD teaches the model to reason aloud about spatial relationships (where is the cup? where should the gripper go? what path connects them?) before committing to a physical action.

The algorithm as a flow

What it actually does

Image encoder

Vision model (CLIP) reads camera image, recognizes objects and layout as patterns.

Spatial chain-of-thought

Model outputs step-by-step reasoning: identify key object, find target location, trace path through intermediate points.

Generate visual trace

Model predicts pixel coordinates of a smooth path from start to goal, marking affordances (where grasp happens, where release happens).

Planner converts to motion

Simple code turns pixel coordinates into arm joint angles, respecting robot kinematics and safety bounds.

Execute

Robot moves along the planned path and completes the task.

What the paper changes

What the paper changes

The paper modifies the vision-language model to output intermediate spatial reasoning steps and visual traces — pixel coordinates of where the gripper should move — before outputting final actions. Instead of trying to guess actions directly, the model must first explain its spatial reasoning aloud.

the object it moves  =  Spatial reasoning intermediate outputs
The hidden quantity

The named hidden quantity: Spatial affordance understanding

measured quantity  =  Spatial affordance score

The paper measures something invisible: how well the model understands spatial relationships in each image — which parts of the scene are graspable, which are obstacles, which is the goal. This is not a single number per image, but rather a set of coordinates and confidence scores for key locations.

FSD estimates this by training the model on a progressively harder series of spatial reasoning tasks: first, labeling where objects are; then, predicting the path to a goal; finally, generating detailed visual traces that show pixel-by-pixel movement. Each task refines the model's ability to pinpoint spatial structure. The paper calls this weak-to-strong learning — starting with coarse labels, advancing to fine-grained trajectory prediction.

Why it works

Why intermediate spatial reasoning fixes the problem

When the model outputs spatial reasoning steps before acting, it creates a checkpoint for error correction. If the spatial reasoning is wrong, you can catch it before the robot moves. If it is right, the planner has a clear roadmap instead of guessing. This works because reasoning forces the model to factor out the common patterns in space (where things are, how to reach them) from the incidental details (which specific gripper model, which specific table). A vision model trained on billions of internet images already understands visual structure; this method teaches it to express that understanding as spatial coordinates, which any robot can use.

The paper trains on mixed data: both internet-scale spatial reasoning tasks (draw a path between two points, segment objects) and robot manipulation videos. The internet tasks teach general spatial skills; the robot tasks teach what grasping looks like. By combining them, the model learns spatial reasoning that works across different robot types and scenarios — because the spatial reasoning part is grounded in patterns seen across billions of internet images, not just in the limited robot videos.

Math after the picture

The spatial trace equation

First in words:

Visual trace loss = averaged squared distance between predicted pixel path and ground-truth pixel path, plus a term penalizing unrealistic curvature in the path.

Then the compact form:

L_trace = (1/N) * sum_i ||predicted_path_i - actual_path_i||^2 + lambda * path_smoothness_penalty

Every symbol:

L_tracethe training loss for visual trajectory prediction
predicted_path_ithe pixel coordinate the model predicts at step i
actual_path_ithe ground-truth pixel coordinate at step i (from human labeling)
Nthe total number of coordinate steps in the path
lambdahow much to penalize jerky, unrealistic paths
A tiny worked example
Suppose the model predicts path coordinates for 5 steps: step 1 at pixel (100, 50) when truth is (102, 48).
Distance = sqrt((100-102)^2 + (50-48)^2) = sqrt(4+4) = 2.8 pixels.
Squared: 2.8^2 = 7.84. Repeat for all 5 steps, average to get ~6.0 (just the coordinate error).
If the predicted path zigzags wildly (curvature term high), add a penalty. Final loss = 6.0 + 0.5 * 2.0 = 7.0.
Training reduces this: model learns to predict smoother, closer paths. After iterations, loss drops to 1.5 (much better predictions).

The model learns to output smooth, accurate pixel paths by comparing predictions to labeled robot videos and refining until the visual traces match reality.

What can go wrong

What can go wrong

Spatial reasoning is wrong. If the model misidentifies which part of the scene is the object (confuses a shadow for the goal, or misses an obstacle), the entire plan fails. The paper addresses this by training on diverse internet-scale data, but new visual illusions can still fool the model.
Real world is messier than training. The model was trained on videos with clear lighting, known objects, and ideal camera angles. Real robots encounter poor lighting, reflections, occluded objects, and clutter. Spatial traces can be misaligned with actual pixel locations.
Planner assumes the spatial trace is correct. Once the model outputs coordinates, the planner converts them rigidly to robot motions. There is no error checking. If one coordinate is off, the gripper overshoots or crashes.
Done right. When trained on sufficient data diversity and tested on similar scenes, FSD outputs spatial traces that are close enough to guide successful manipulation, even on objects the model has never seen before and robot arms with different shapes and sizes.
What a runnable demo should prove

What a runnable demo should prove

Build a simple manipulation task: a simulated robot arm in a 3D scene with one object (a block, a cylinder, or a cup) placed at a random position. The robot starts at a random pose. Your goal: show that a model trained on spatial traces can guide the arm to grasp and move the object to a target location, even when the object type or position is changed between training and test.

Success rate = (number of trials where gripper reaches object AND moves it to goal) / (total trials)

If the model can output reasonable spatial traces for objects it has never trained on and the planner converts them to successful robot motions, you have proven that separating spatial reasoning from action selection improves generalization. This works because the spatial reasoning part learned patterns from billions of internet images, not just the limited robot videos.
