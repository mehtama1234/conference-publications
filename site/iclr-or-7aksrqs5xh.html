Correlations in Data Drive Feature Geometry

When an autoencoder compresses text patterns, repeated co-activations arrange features into semantic clusters and circles without needing explicit design.

Paper explainersAll themesInterpretability

Inside language models, features (the model's learned concepts) are arranged in organized patterns—semantic clusters, ordered circles for months. Where do these patterns come from? This paper shows they emerge naturally when an autoencoder compresses sparse patterns from real text, purely to fit information through a narrow bottleneck.

Zero assumption version

Toy models don't match real models

Early theories (using toy models—tiny, artificial setups) predicted that features would arrange themselves into regular geometric shapes like small dice or crystals. But real language models show something different: semantic clusters (words with related meanings grouped together) and ordered patterns (months arranged in sequence).

Researchers asked: where do these organized patterns come from? Current theories could not explain them. The naive guess was that the model must be learning these patterns because they help solve downstream tasks (for instance, keeping related animal words near each other might help the model answer questions about animals faster). But nobody had shown how compression alone, without any downstream task pressure, could create such organized arrangements.

The question. Can compression alone create the organized feature patterns we see in real language models?

What the paper changes

What the paper changes

The paper rearranges feature representation (the list of numbers each feature gets) by tuning how tightly the autoencoder squeezes information through the bottleneck and whether training uses weight decay (a light penalty on large numbers). These changes cause features that co-activate in the data to end up in similar geometric regions.

the object it moves  =  feature arrangement in compressed space
The hidden quantity

The co-firing structure (features that activate together)

measured quantity  =  Co-activation correlation (which features fire together)

The paper measures a hidden quantity: co-activation correlation—which features tend to activate (become non-zero) at the same time in the data. Words like dog and cat co-activate often; dog and arithmetic rarely do.

The paper estimates this from the text directly: count how often each pair of words appears together. This co-activation structure in the data is then mirrored in where features end up—features with high co-activation end up physically near each other in the learned representation.

Why it works

How compression creates organized patterns

The autoencoder has three layers: input (sparse word vectors), bottleneck (narrow compressed layer), and output (reconstruction). The bottleneck acts like a narrow door: only the most important patterns fit through. When two features co-activate, squeezing them through the same narrow space physically pushes their compressed codes to overlap or sit near each other. Over training, the network exploits this: it puts co-activating features in adjacent positions to save space, because similar locations require similar stored information.

The mechanism is purely spatial: imagine packing suitcases into a tiny closet. Items you use together get stacked near each other because it saves space. No one told the network to cluster dog and cat; the bottleneck did it automatically by choosing the most efficient spatial arrangement.

Math after the picture

The compression formula

First in words:

reconstruction error plus weight penalty, sum over all training samples

Then the compact form:

loss = mean_square_error(input, reconstruction) + lambda * sum(weights^2)

Every symbol:

inputthe sparse word vector (which words appear in this text)
reconstructionwhat the autoencoder outputs (its guess at the original)
mean_square_erroraverage of squared differences between input and output
weightsall the numbers in the network that get learned
lambdastrength of the penalty: how much to discourage large numbers
A tiny worked example
Imagine a bottleneck of width 3 and two co-activating features (dog and cat).
Without penalty: network encodes dog at [0.8, 0.6, 0.1] and cat at [0.75, 0.65, 0.05], a bit overlapped.
With weight penalty (lambda=0.1): large numbers are discouraged, so the network pushes both closer together: dog=[0.5, 0.4, 0.0], cat=[0.5, 0.4, 0.0]. Identical positions save space.
High co-activation and bottleneck pressure force features to share geometric neighborhoods, creating clusters.

The weight penalty (regularization) acts like gravity pulling the numbers toward zero, so the network uses space more efficiently by bunching similar features together.

What can go wrong

What can go wrong

Bottleneck too wide. If the compressed layer is too large, features have plenty of space and no pressure to cluster. Arrangements remain scattered and random.
No weight penalty. Without the penalty on large numbers, the network wastes space on redundant features and doesn't force efficient packing. Clusters blur and disappear.
Mismatched co-occurrence data. If the training data has different word patterns than the language model being studied (e.g., training on finance text when studying a general model), the patterns won't match.
Done right: tight bottleneck + penalty. With pressure to compress and a dataset matching the model's training patterns, features arrange into semantic clusters and coherent spatial patterns.
What a runnable demo should prove

What a runnable demo should prove

Train a small sparse autoencoder on co-occurrence statistics extracted from a text corpus (e.g., the 1000 most common words from Wikipedia). Use a narrow bottleneck (e.g., 20-dimensional compressed space for 1000 words) and include a weight penalty. After training, extract the learned feature vectors and visualize them in 2D (using a technique like t-SNE). The demo must show semantic clustering (animal words cluster together, food words cluster nearby, etc.) and if training long enough, ordered patterns (numbers 1–10 arranged in a line).

cluster_purity = fraction_of_same_semantic_neighbors / total_neighbors_examined

The demo must make it impossible to miss: compression alone, without any explicit instruction, produces the organized patterns observed in real language model internals.
