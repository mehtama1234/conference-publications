SteinsGate: Causality in Long Video via Path Integral

Video models generate short clips; to build long videos, you must teach them which actions cause which next actions, then generate one scene at a time in order.

Paper explainersAll themesGenerative Models & Diffusion

Video models today can generate a few seconds of film. To create long narratives with multiple actions playing out naturally, the model needs to understand causality: which action naturally leads to the next one, because actions in the real world do not jump randomly from one pose to the next—they flow. SteinsGate decomposes a long video story into named actions in time order, estimates how long each action lasts, then generates video one action at a time, using physics-like path constraints to ensure each new frame flows naturally from the last.

Zero assumption version

Why short clips fail at long stories

Today's video generation models are trained to fill in frames over a short time window, like 2 to 4 seconds. If you ask one to generate 30 seconds, it either slows down, repeats actions, or invents frame-to-frame contradictions because the model never learned how one frame's action naturally flows into the next frame's action.

A naive attempt is to paste short clips end-to-end by overlapping a few frames at the seams. This fails because the model has no idea which action from clip 1 makes sense to continue into clip 2. The seam often shows jerky jumps or the wrong character doing the wrong thing.

The core problem. Models trained on short windows do not learn action causality—which action naturally leads to the next—because they never see an action start from where another ended. So long video either degrades into loops or contradictions, or seams between clips feel like edit cuts because the model has no reason to make action 2 begin where action 1 ended, instead of elsewhere.

The algorithm as a flow

What it actually does

Parse the story

A multimodal language model reads a text story and lists each action with predicted duration.

Anchor to the last frame

Before generating a new action, the model sees the final frame of the previous action.

Generate via diffusion

A video diffusion model (trained on short clips) fills in frames from the predicted start.

Enforce path causality

A path integral constraint (from physics) ensures the next action does not jerk away from the previous one.

Repeat for the full narrative

Each action extends the video naturally; the full story emerges as a chain of causally-linked scenes.

What the paper changes

What the paper changes

The paper rewires how the diffusion model works: instead of generating any 4 seconds in isolation, it now generates the next action given the endpoint of the previous action and a constraint that says how this action must start.

the object it moves  =  video generation from isolated to causal-chain
The hidden quantity

The action causality signal

measured quantity  =  action-to-action continuity cost

Every time a new action begins, there is a mismatch: the final frame of the old action and the first frame the model wants to generate for the new action do not match perfectly. This mismatch is measured as a cost (how far apart they are). The paper calls this a path integral—a physics concept meaning the cumulative 'cost' of traveling from one state to another.

Without this signal, the model treats each action as a fresh start. With it, the model learns to generate the first frames of a new action such that they blend smoothly into the tail of the old one, not jerk away.

Plain reading. Imagine two dancers on a stage. Dancer 1 ends in a lunge. Dancer 2 must start their opening move from that lunge position, not from center stage. The cost measures how awkwardly Dancer 2 would begin if they ignored where Dancer 1 ended. The model learns to open Dancer 2's routine from the lunge to avoid that awkwardness.
Paper reading. The path integral is the integral of the loss between frame-level representations across the action boundary. It quantifies the continuity cost. The model learns to minimize this boundary cost during training, so actions link causally when the model runs on new videos (the time after training when the model answers a real question).
Why it works

Why constraining action seams produces natural long video

The core insight: short video models are actually good at what they were trained for—generating 4 seconds of coherent motion. The problem is they have no reason to care what comes before or after. By breaking a long story into actions, naming them, and feeding the model the endpoint of the previous action, you tell the model: your next 4-second clip must start here, not anywhere. The path integral cost penalizes any mismatch between where action 1 ends and where action 2 begins. During training, the model learns to begin new actions smoothly from wherever the last one ended. At inference, this constraint becomes automatic—the model generates action 2 in a way that flows from action 1 because its weights were shaped by millions of examples rewarding that flow.

Why does this work? Diffusion models work by gradually removing noise from random pixels to reveal a coherent image (or video frame). If you give the model a starting point—the last frame of the previous action—it does not have to invent where to start from. It just refines from that point. The path integral makes that refinement compute the boundary cost—a signal telling the model when the transition is smooth or jerky—so the model learns to refine in a way that blends, not clashes, because high boundary cost during training is painful and the model avoids it.

Math after the picture

The boundary continuity equation

First in words:

path integral loss = integral over action-transition of (distance from prev-action-end to current-frame)^2 dt

Then the compact form:

L_boundary = integral_t ||f_t(s_prev_end, a_next) - f_t(s_next_start)||^2 dt

Every symbol:

f_t(s, a)the video frame at time t given scene state s and action a
s_prev_endthe final scene state of the previous action
s_next_startthe starting scene state of the next action (what model must generate)
||...||^2the squared distance (how far apart two frames are)
integral_tsum this cost over all time steps at the boundary
A tiny worked example
Previous action ends: actor's arm at position (100, 50).
Next action should start: same actor's arm at position (98, 52).
Model's first generated frame puts the arm at (110, 40) — a jerk.
Distance squared: (110-100)^2 + (40-50)^2 = 100 + 100 = 200.
This high cost penalizes the jerk during training.
Model learns to start the next action from (100, 50) and smoothly transition, reducing the boundary cost to near 0.

The path integral is the total 'travel distance' through scene space at the action boundary; minimizing it teaches the model to start each new action where the last one ended.

What can go wrong

What can go wrong

Action duration misprediction. If the language model guesses an action lasts 10 seconds but the model only generates 8, the next action will start too early and collide with the previous one. The path integral does not fix bad predictions; it only smooths valid ones.
Scene state is ambiguous. If two actions are described in text but their physical states (position, pose, lighting) are not clearly constrained, the model may drift. The path integral enforces frame-to-frame continuity but not high-level semantic consistency across minutes.
Expensive at inference. Evaluating the path integral for every frame at every action boundary adds computation. For very long videos (hours), this becomes slow unless approximated.
Done right. With clear action labels, realistic duration predictions, and a well-trained diffusion model, the path integral naturally produces long, coherent, causally-linked videos that feel like a single unified narrative instead of edited clips.
What a runnable demo should prove

What a runnable demo should prove

Build a simple multi-action video generator: (1) manually write a 3-action story (e.g., person walks, person sits, person drinks), (2) use a pretrained language model to parse it into actions and durations, (3) generate each action in sequence, anchoring the start frame to the previous action's end frame, (4) compute the boundary-mismatch cost between actions, (5) compare the result (smooth, continuous narrative) against a baseline that ignores the previous action's endpoint (jerky transitions).

narrative smoothness = 1 - (boundary_jerk_distance / max_possible_distance)

The demo must make impossible to miss: with causality, the transitions between actions are smooth and natural; without it, they jerk or contradict. This is because the path integral constraint teaches the model to respect the physics of scene state continuity.
