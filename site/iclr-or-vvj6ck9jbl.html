Aurora: Multimodal Time Series Forecasting with Domain Guidance

Use text and image context alongside numbers to predict future trends across different domains and scenarios.

Paper explainersAll themesTime Series & Sequential

Predicting what happens next in a stream of numbers (like stock prices or weather) breaks when you move from one domain to another — the pattern that worked for oil prices does not work for electricity demand. Aurora solves this by feeding the model text and images that explain what the numbers mean, then using those words and pictures to steer how the model processes the numbers themselves. This lets one model forecast accurately across completely different scenarios without retraining.

Zero assumption version

Cross-domain forecasting is stuck

Time series forecasting — predicting the next values in a stream of numbers — works fine when you have lots of examples from the scenario you care about. But when you move to a new domain (say, from predicting stock prices to predicting weather), the old model fails, because the patterns are different.

A naive fix is to retrain the model on the new domain, but that requires lots of new labeled examples and takes time. A better approach would be a model that could work on a new domain without retraining, if only it could read text and images describing what the domain is. When a model understands what it is looking at through words and pictures, it can recognize which parts of the data to trust and which to ignore, because it can match the incoming numbers against the domain description (a stock-market model ignores weather signals that would matter in an agriculture model). This works much like a person would reason. But existing text-only forecasters ignore images entirely, and models that do use both text and images require full retraining for each new scenario.

The move. Inject text and image context directly into the model's attention (how it weighs each number in the sequence) so the model steers itself toward domain-relevant patterns. This works because when the model knows what to look for, it can upweight the time steps that actually matter and downweight the noise, just as a weatherologist would ignore stock gossip and focus on atmospheric data.

What it actually does

Encode each modality

Convert numbers, words, and pixel patterns into lists of scores that capture their meaning.

Inject guidance via attention

Use the text and image scores to reweight how much each number influences the model's predictions.

Learn prototype representations

Distill the domain context into a small set of canonical patterns the model uses for forecasting.

Generate probabilistic forecasts

Use those prototypes as constraints when sampling future values, making predictions that match domain behavior.

What the paper changes

What changes

The model's attention layer (the part that decides which numbers in the sequence to pay most attention to) gets reweighted by scores derived from the text and image inputs. In standard time series models, attention weights come solely from the numbers themselves. Here, they are bent toward domain-relevant features.

the object it moves  =  attention weights in self-attention
The hidden quantity

Domain relevance: which numbers matter in this context

measured quantity  =  domain-relevance scores

A domain-relevance score is a number between 0 and 1 that says how important each position in the time series is for forecasting in a particular domain. In stock markets, recent prices matter most; in weather, seasonal cycles matter more. The paper does not explicitly state a formula for this score, but it is implicitly estimated by encoding the text and images and using those to gate which numbers get high attention.

The model measures this by passing text descriptions through a text encoder, pixel patterns through an image encoder, and then using those to scale the attention weights. Domains with clear textual markers (like 'high volatility in energy markets') will produce high scores on time steps that exhibit that volatility. Domains with visual cues (like seasonal weather maps) will do the same for seasonal time steps.

Why it works

Why domain context steers forecasting

A time series model makes predictions by building a mental picture of patterns: 'when I see pattern A, the next value is usually B.' That mental picture depends on which parts of the history the model actually looks at. If the model pays equal attention to all time steps, it conflates noise with signal. If it can be told 'in energy markets, ignore weather noise and focus on demand shocks,' it will build a better mental picture, because the model will learn the true causal rule ('demand drives prices') instead of spurious correlations ('this particular weather sensor predicts prices').

Aurora achieves this by encoding the text descriptions (e.g., 'electricity demand in summer') and visual cues (e.g., a photo of a power plant at full capacity) into a single domain guidance signal (a list of numbers, one for each time step). It then multiplies the attention weights by this signal. Time steps that match the domain guidance get higher attention; mismatched ones get lower attention. The result: the model automatically aligns its pattern-building to the domain's actual causal structure.

In the generative phase, Aurora goes further. Instead of predicting single future values, it samples from a distribution of plausible futures, using learned prototypes (canonical examples from the domain) as constraints. This ensures generated forecasts stay within realistic bounds for that domain — no predicting negative stock prices or 200-degree weather.

Math after the picture

Modality-guided attention with prototype flow matching

First in words:

modality-guided-attention = softmax( (Q · K^T + g_domain) / sqrt(d) ) · V, where g_domain scales each position by how well it matches the text and image guidance. Flow-matching loss steers generated tokens toward prototype-anchored distributions.

Then the compact form:

attention_score_ij = softmax( (Q_i · K_j^T + g_j) / sqrt(d) ) ; forecast_t ~ N(prototype_mu + delta_t, sigma_t) where delta_t is learned flow

Every symbol:

Q_iquery vector at time i
K_jkey vector at time j
g_jdomain guidance weight for position j (from text/image encoding)
ddimension of vectors
Vvalue vectors being weighted
prototype_mulearned mean pattern for this domain
delta_tflow-matching deviation at step t
sigma_tuncertainty in the forecast at step t
A tiny worked example
Suppose the time series has 4 points: [100, 102, 101, 103] and text says 'stock market.'
Attention on point 4 (value 103) computes: raw_score = Q_4 · K_all = [0.5, 0.6, 0.5, 0.8].
Domain guidance says 'recent prices matter in stocks' so g = [0.1, 0.3, 0.5, 1.0].
Scaled score = raw_score + g = [0.6, 0.9, 1.0, 1.8] (before converting to weights).
Convert to weights that add to 1: [0.10, 0.16, 0.18, 0.56].
Without guidance, the weights would be [0.21, 0.26, 0.21, 0.32].
The guidance boosted attention to the most recent point from 0.32 to 0.56, aligning the model with stock-market logic.

The guidance signal g is not magic; it comes from encoding the text and image inputs through neural encoders trained on the multimodal corpus.

What can go wrong

What can go wrong

Text or images do not match reality. If the text description says 'high demand' but the time series shows stable demand, the model receives conflicting signals and may ignore both the text and the numbers. Garbage guidance in means garbage forecasts out.
Domain guidance is too weak. If the text or image encoders are not trained well enough, the guidance signal will be noisy, and attention will not be reweighted correctly. The model will ignore the guidance and fall back to acting like a numbers-only baseline.
Prototype learning overfits. If the learned prototypes memorize training domains too tightly, they will not generalize to new domains. The model needs diverse multimodal pretraining to learn broadly applicable prototypes.
Done right. A well-trained Aurora model will extract domain patterns from text and images, align its attention appropriately, and generate forecasts that respect both the historical data and the domain-specific constraints learned from the multimodal corpus.
What a runnable demo should prove

What a runnable demo should prove

Build a tiny time series forecasting task: two domains with different patterns (e.g., synthetic 'exponential' and 'cyclic' series). Train Aurora on a mix of time series, text labels ('this is an exponential series' or 'this is cyclic'), and simple diagrams. Then test: (1) accuracy when trained and tested on domain A (should be high, because the model has seen many examples), (2) accuracy on domain B zero-shot should improve compared to a numbers-only baseline, because the model can read the text label and adjust its pattern-recognition accordingly, (3) inspect the attention weights to confirm they align with the domain labels (exponential reads high-weight to recent steps, cyclic reads high-weight to regular intervals), and (4) inspect generated samples to confirm they respect domain prototypes (e.g., exponential never decreases, cyclic stays bounded).

zero_shot_improvement = (Aurora_accuracy_on_B_zero_shot - unimodal_accuracy_on_B_zero_shot) / unimodal_accuracy_on_B_zero_shot

The demo must show that multimodal guidance lifts zero-shot forecasting accuracy, not just that Aurora trains well on seen data.
