Aurora: Multimodal Time Series with Text and Image Guidance

A time series forecaster that uses text descriptions and images to understand each domain and predict the future.

Paper explainersAll themesTime Series & Sequential

Predicting what happens next in a time series (like stock prices or traffic flow) is hard because each domain has its own hidden rules. Aurora learns to read text hints ("stock prices are volatile now") and image clues (past patterns shown as charts) alongside the numbers themselves, then uses that guidance to forecast what comes next. It works across many different domains without retraining.

Zero assumption version

Time series forecasting ignores domain knowledge

Predicting future values in a time series — like next week's traffic or tomorrow's temperature — is hard because the numbers alone do not tell you the full story. A naive forecaster reads only the numbers and assumes all time series behave the same way.

In reality, stock prices jump based on news (text knowledge), traffic patterns repeat by hour-of-day (visual patterns), and weather follows seasonal cycles (images of historical data). When you try to forecast without that context, you miss what matters. A stock model trained on one company fails when moved to a different stock because it never learned what makes that company unique.

The paper's move in one sentence. Read text descriptions and images alongside the time series numbers, use them to guide which numbers to focus on, and forecast without retraining on new domains.

The algorithm as a flow

What it actually does

Read three sources

Time series numbers, text description, and image (chart) go into separate encoders.

Extract key pieces

Break each modality into chunks (tokenize) and distill to remove noise and keep domain knowledge.

Guide the attention

Let text and image features adjust which numbers the model focuses on.

Fuse multimodal features

Combine the guided time-series features with text and image representations (learned number lists).

Generate futures probabilistically

Use flow matching (a generative method) to produce next values, conditioned on the fused features and prototype patterns.

What the paper changes

The one thing the paper changes

Instead of reading only time series numbers, Aurora reads text descriptions and images too, and uses them to guide which numbers the model focuses on. The mechanism is this: text and image hints are fed into how the model weights each number, so it learns to focus on the numbers that matter for that specific domain.

the object it moves  =  attention weights (guided by text and image)
The hidden quantity

The guidance signal

measured quantity  =  Domain-specific feature importance

Aurora measures which parts of the time series are most important for forecasting by looking at what the text and image encoders highlight. For example, if the text says 'stock price is volatile' and the image shows a sharply rising trend, those clues tell the model: pay close attention to rapid changes and overall direction, less to small daily noise.

The paper estimates this importance by running the text and image through pretrained encoders (BERT for text, ViT for images), then using cross-attention to see which time-series tokens align with the key parts of the text and image. The features that light up in that cross-attention are the ones the model learns to trust.

Why it works

Why it works: four layers of learning

Aurora works because it uses three different encoders, each trained on billions of data points. BERT has read countless text descriptions of real-world events. ViT (Vision Transformer — a model that reads images as a grid of small patches) has seen millions of images and learned to recognize visual patterns. The time-series backbone has seen trillions of historical values. By tapping into all three, Aurora does not start from scratch on a new domain — it borrows knowledge from billions of examples.

When Aurora encounters a new domain (say, a new stock it has never seen), the text encoder already knows what 'volatile' means. The image encoder already knows what an uptrend looks like. The time-series encoder already recognizes weekly and seasonal patterns. The text and image features act as a translator: they tell the time-series part which of its learned patterns are relevant. This cross-domain transfer happens without retraining because the encoders are frozen pretrained weights — only the attention mechanism learns to wire them together.

In the decoder, Aurora generates future values one or a few at a time using flow matching (a generative method that starts from random noise and refines it to resemble real futures). The text and image features guide this generation by seeding 'prototype' patterns (like 'expect an uptrend with high volatility'). The model then samples futures that match these prototypes, so the outputs respect the domain-specific hints.

Math after the picture

The guidance equation

First in words:

To compute attention between time series and text/image, use the time series as queries, text/image as keys and values, and add a correlation term that emphasizes matches. This produces attention scores that weight the time series features.

Then the compact form:

S = (Q·K_T + Corr) / sqrt(d), O = Softmax(S)·V, X_time = LayerNorm(FFN(O) + O)

Every symbol:

QQuery: time-series tokens (what we are asking)
KKey: text/image features (what we are matching against)
VValue: text/image features (what we extract)
CorrCorrelation matrix between time series and text/image
dFeature dimension (how many numbers per embedding)
Softmax(S)Turn scores into fractions (one sums to 1)
OWeighted mix of text/image values, aligned with time series
X_timeFinal time-series features, updated by the guidance
Tiny worked example
Say time series has 3 tokens (numbers at times t1, t2, t3) and text has 2 key words ("volatile", "rally").
Query matrix Q (from time series) = [[2, 3], [1, 4], [3, 2]] (3 tokens, 2 dimensions each).
Key matrix K (from text) = [[3, 1], [2, 4]] (2 words, 2 dimensions each).
Q·K_T = [[2×3+3×2, 2×1+3×4], [1×3+4×2, 1×1+4×4], [3×3+2×2, 3×1+2×4]] = [[12, 14], [11, 17], [13, 11]].
Add correlation bonus where token t2 aligns with "rally": [[12, 14], [11, 20], [13, 11]].
Softmax each row to get attention weights (fractions summing to 1). Token t2 now focuses heavily on "rally" (weight ~0.9) and less on "volatile" (weight ~0.1).
This tells the time-series model: t2 is a rally moment, learn from that label.

The math wires text and image clues into how the time-series model weights each number, so it learns which numbers matter most for each domain — because the text and image features tell it which numbers are correlated with the key patterns.

What can go wrong

What can go wrong

Text or image mismatch. If the text description is wrong ('stock is stable' but it is crashing) or the image does not match the time series domain, the guidance misleads the model and forecast gets worse. The text encoder believed the wrong label.
Pretrained encoders do not fit the domain. BERT and ViT were trained on public web text and images. If the domain uses highly technical jargon or specialized charts (e.g. medical sensor data with domain-specific symbols), the pretrained encoders may miss the meaning.
Noisy text guidance at test time. During deployment, the text might come from user input or automated summaries. If summaries hallucinate or are vague, the attention mechanism gets confused and forecast accuracy drops.
Done right: hand-curated text, accurate images, and alignment checks. If text descriptions are human-written and reviewed, images match the time-series domain, and the cross-attention (how well text/image match the time series) is monitored to catch misalignment, the guidance signal is clean and improves forecasts reliably — because reliable hints lead the model to trust the right numbers.
What a runnable demo should prove

What a runnable demo should prove

Build a forecaster that works on two time-series domains: one seen during pretraining and one completely new. The demo should show that (1) when you include text hints and images, the new domain's accuracy stays high; (2) when you remove the text and images, accuracy on the new domain drops sharply; (3) visualizing the attention weights shows the model learned to weight the important numbers differently based on the domain hints.

Cross-domain generalization = (new_domain_accuracy_with_guidance) - (new_domain_accuracy_without_guidance)

The demo must make it impossible to miss: text and image guidance are not luxuries, they are the reason the model can forecast on unseen domains.
