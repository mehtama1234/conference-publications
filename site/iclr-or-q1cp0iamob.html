H3DP: Triply Hierarchical Diffusion Policy

Match visual features at each depth layer to action refinement steps: coarse features guide early action shape, fine features refine precise motion.

Paper explainersAll themesRobotics & Control

A robot learns to move by watching images and predicting hand motions. The problem: existing methods treat the camera feed as one flat image and generate the entire motion at once, missing how visual detail naturally connects to motion refinement. H3DP organizes the visual input by depth (near pixels in one layer, far pixels in another) and generates actions in stages, so each visual layer guides the matching stage of motion refinement.

Zero assumption version

Distance cues matter, but existing methods ignore them

A robot's camera sees both nearby and distant objects in one image. Distance matters: a close gripper finger must move with millimeter precision, while a distant arm can move broadly. But when a standard policy (a trained decision-maker) looks at the flattened image, it has no explicit signal about which pixels are near and which are far.

A naive approach: feed the image directly to the model, ask it to generate the full motion at once. The problem: the model cannot easily separate coarse global motion from fine detail refinement. It must guess which parts of the image are near, which are far, and how each scales to motion magnitude. The result: wasted computation and lower success rate.

In one sentence. The paper splits the camera input by depth and refines actions in stages, so each visual scale guides the matching motion stage.

The algorithm as a flow

What it actually does

Depth-aware layering

Partition the camera image into N separate layers by depth: layer 0 holds pixels that are closest, layer N holds far pixels.

Encode each layer

Each depth layer is run through an image encoder to produce visual feature maps at K different resolutions (coarse to fine).

Refine motion in stages

The action (hand position and orientation) is generated by a diffusion process that runs denoising steps iteratively, starting from noise.

Align stages to visual scales

Early denoising steps are conditioned on coarse visual features (overall scene layout), later steps on fine features (precise hand placement).

Train end-to-end

All components (depth layering, encoders, feature refiners, denoising) are trained together to minimize prediction error.

What the paper changes

What the paper changes

Instead of feeding one flat camera image to the action generator, H3DP splits the image into depth-aware layers and conditions each motion-refinement step on the matching visual scale. The connection is explicit: shallow pixels guide coarse motion, deep pixels guide precise details.

The hidden quantity

The hidden quantity: depth-to-action alignment

measured quantity  =  Stage-appropriate visual guidance

The paper measures an implicit quantity: how well each denoising step (each stage of action refinement) is guided by the correct visual scale. Early steps should use only coarse features (the overall scene), later steps should use fine features (precise hand details). Misalignment wastes the model's capacity.

H3DP estimates this by design: it assigns depth-layer features to denoising steps automatically. Coarse visual features (from near-distant layer splits) condition early denoising steps; fine multi-scale features condition later steps. The paper validates this by removing each component: drop depth layering, drop hierarchical action conditioning, drop multi-scale encoding — each hurts success rate on real tasks.

Why it works

Why it works: matching visual scales to motion refinement stages

A diffusion policy works by starting with random noise and refining it into an action (hand position, angle, grasp force) through repeated denoising steps. Early steps remove coarse noise (is the hand moving left or right at all?), later steps remove fine noise (is the finger at 127 mm or 128 mm?). If you feed the wrong visual scale at the wrong step, the model wastes capacity—because fine details at step 1 provide information the model cannot use yet (it is still deciding direction, not millimeter precision), and coarse features at step 100 do not constrain what the model actually needs to decide at that stage (the finger's exact angle).

H3DP solves this by organizing the camera input by depth. Pixels at depth 0 to 0.5m (near the gripper) contain fine detail, encoded at full resolution. Pixels at depth 2 to 5m (background) are coarse, encoded at low resolution. At early denoising steps, the model looks only at the coarse background features (which direction should the arm go?). At later steps, it looks at fine gripper-scale features (where exactly should the finger point?). Each step gets the visual signal it actually needs, so the model learns faster—because it can focus its gradient updates on the decision that matters at that stage—and predicts more accurately—because the relevant visual information is at the right spatial resolution for that stage's decision.

The paper uses a three-level hierarchy: depth-aware layering (split by distance), multi-scale encoding (each layer encoded at multiple resolutions), and hierarchical action conditioning (early steps use step 0–1 features, later steps use step 2–3 features). Because each component targets a real geometric constraint, removing any one of them degrades performance. The full system exploits the natural structure of the task.

Math after the picture

The training objective equation

First in words:

Total loss equals the diffusion prediction error plus a consistency penalty on the visual features, weighted equally.

Then the compact form:

L = L_diffusion + L_consistency = E[ ||epsilon - epsilon_theta(a_t, f_K, q)||^2 ] + lambda * sum_m,k ||f_hat(m,k) - recon(quantize(f(m,k)))||^2

Every symbol:

epsilontrue random noise added to the action
epsilon_theta(a_t, f_K, q)the model's predicted noise given action a_t at step t, final feature f_K, and robot pose q
f_Kthe finest multi-scale visual feature (used to guide all denoising steps)
qthe current robot joint angles (pose)
f(m,k)the original multi-scale feature for depth layer m at resolution scale k
f_hat(m,k)the reconstructed feature after quantization and refinement
lambdaweight balancing the two losses (set to 1.0 in experiments)
A tiny worked example
Suppose diffusion loss at one step is 0.5 (predicting the noise reasonably well).
Consistency loss across all 3 depth layers and 4 scales: layer 0 scale 0 = 0.01, layer 0 scale 1 = 0.02, layer 0 scale 2 = 0.03, others similar, sum = 0.4.
Total: L = 0.5 + 1.0 * 0.4 = 0.9. If consistency loss were ignored, the visual features would become noisy through the encoding and reconstruction process, and later refinement steps would receive distorted guidance. Both losses matter equally.

The loss keeps diffusion prediction accurate while ensuring each depth layer's visual features remain sharp through the encoding and reconstruction process, so motion guidance is clear at every stage.

What can go wrong

What can go wrong

Poor depth sensing breaks layering. If the depth sensor is noisy or missing data (cluttered scenes, reflective surfaces, far objects), the layer assignment becomes arbitrary. Pixels get misassigned to the wrong depth layer, so the wrong visual features guide the wrong motion stages. The paper notes that point-cloud methods require precise depth and fine segmentation to work in real clutter.
Slow prediction from repeated refinement steps. Diffusion policies refine actions by repeating refinement steps, which is slower than end-to-end prediction (when the model outputs the motion in one shot). H3DP adds layers and multi-scale features, increasing memory use. The paper addresses this by running the next refinement step while the robot executes the previous motion, but not all robots can do this safely.
Hyperparameter sensitivity: number of depth layers. The choice of N (how many depth layers to split into) is critical. Too few layers lose geometric structure, too many layers fragment the image and dilute each layer's information. The paper tests different N values but does not fully explain the trade-off.
Done right: hierarchy matches the task. When depth sensing is reliable, layer count is tuned to the scene (enough layers to separate gripper from background), and the robot can handle overlapping prediction steps, H3DP excels. The paper shows this in 4 carefully designed real-world tasks and 44 simulation benchmarks.
What a runnable demo should prove

What a runnable demo should prove

Build a simple manipulation task: a robot arm must pick an object from a clutter scene. Render the scene as RGB-D (color image plus depth map). Train three models: (1) baseline diffusion policy on the RGB image alone, (2) diffusion policy with RGB-D concatenated, (3) H3DP with depth layering and multi-scale encoding. The key is to measure success rate (did the gripper grasp the object?) and prediction accuracy (how close is the predicted hand pose to the true ground truth?). Use the same number of training steps for all three so computation is held constant.

success_rate = (number of successful grasps) / (total attempts); accuracy = mean_absolute_error(predicted_pose, true_pose_after_action)

H3DP should show both higher success rate and lower pose error than the baselines, proving that organizing visual input by depth and aligning it to action refinement stages is necessary for the model to learn manipulation.
