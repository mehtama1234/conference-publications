Generating and transforming graphs

Papers on creating new graphs or modifying existing ones using generative models and optimization techniques to solve graph-based problems.

All themesField mapMathematicsAll explainers
What this is

Most graph learning papers predict things about existing graphs. But sometimes you want to generate new graphs—design new molecules, create synthetic social networks for simulation, find better graph structures by optimization—because you need new examples or solutions. This requires a different kind of model: one that can produce structured data, respecting the constraints (molecules have valid bonds, social networks have realistic patterns), since random graphs won't work.

The hard part is the combinatorial explosion. A molecule's atoms can bond in countless ways, most of which are chemically impossible. A graph with N nodes can have up to N squared possible edges. You can't enumerate all possibilities. Also, the order in which you generate things matters: if you add an atom first, then try to add a bond to it, you might back yourself into a corner. You need a way to generate step-by-step while respecting global constraints.

Papers use generative models: diffusion (start with noise, gradually refine it into a valid graph), flow matching (learn to transform from one distribution to another), and autoregressive approaches (predict one thing at a time, conditioning on what you've already generated). They tackle combinatorial optimization: given a graph, find a better version by modifying it, using learned models or optimization algorithms. They use graph augmentation—adding or removing edges—as a way to generate training data for other tasks. Some incorporate chemical knowledge (atoms have valence limits) or social knowledge (realistic networks follow patterns like preferential attachment) to guide generation toward realistic outputs.

How the work breaks down

Graph generation splits into three directions: diffusion and flow-based methods that learn to gradually build valid graphs from noise, optimization-based approaches that modify existing graphs to improve them, and augmentation techniques that strengthen learning by generating training variations. The split reflects different goals: creating entirely new graphs (so you have new examples to work with), refining existing ones (to solve design problems), or using generation as a tool for better models (because diverse training data makes models learn more generalizable patterns).

Diffusion models for graph generation

Diffusion models start with random noise and gradually refine it step by step into a valid graph. The challenge is making sure each step respects the graph's constraints—atoms can only bond in certain ways, edges must form valid structures, the order of generation matters. Three papers tackle different versions of this problem.

CheckMate focuses on a different angle: how do you verify that a generated graph really came from your model, even if someone has tampered with it? It watermarks graph diffusion models so you can detect if edges have been added or removed or if the graph has been slightly rearranged. The innovation is doing this verification in polynomial time—fast enough to be practical—while the watermark survives realistic attacks. GLAD takes a complementary approach to generation: it starts with a partial graph (just the structure, without attributes like node features) and fills in both the missing edges and the missing attributes jointly. By treating the structure and attributes as a coupled problem, it gets more realistic outputs than older methods that handled them separately. NetDiff extends diffusion to a real application: designing mobile network topologies. It generates entirely new network structures that meet practical constraints, and also handles the harder problem of modifying an existing network by adding or removing infrastructure. It reaches over 95% of target performance with constant-time inference, meaning it stays fast even as the network grows.

All three use diffusion's step-by-step refinement, but they push the boundary in different directions: verification and tamper-detection, joint structure-attribute modeling, and real-world optimization.

Graph augmentation and training stability

Graph augmentation—randomly modifying edges—is an effective way to create training variations that make models learn more stable and generalizable features. But augmentation can hurt if it's too aggressive or mismatched to the model's architecture. These papers make augmentation principled and effective.

From Moments to Models uses mixup augmentation for graphs: it blends two graphs together in a controlled way based on learned graph mixture models, creating diverse intermediate examples. This works for both supervised learning (where labels come with graphs) and contrastive learning (where you learn from unlabeled pairs). The method outperforms existing baselines on six out of seven standard benchmarks because it creates interpolated graphs that sit between real examples, helping the model learn smoother decision boundaries. RADE takes a simpler but more fundamental approach: it randomly adds and removes edges during training, but does this consistently—the same random changes that happen during training also happen during inference. This consistency is key because it prevents a common failure mode where the model learns to exploit training-time augmentation in ways that don't work at test time. As a bonus, RADE also fixes another graph neural network problem called over-squashing, where information gets bottlenecked as it flows through deep networks.

Both papers make augmentation work by being precise: From Moments to Models blends graphs carefully using learned mixture models, while RADE aligns training and inference so the model learns stable patterns instead of gaming the augmentation.

Hypergraph generation and complex structures

Most graph papers handle simple graphs where edges connect two nodes. But many real systems have hyperedges—a single edge can connect three, four, or many nodes at once. This creates a harder generation problem because you need to generate both which nodes form a hyperedge and what attributes those hyperedges have.

ReLaSH generates synthetic hypergraphs by explicitly modeling the hypergraph structure and the attributes of hyperedges together. Instead of treating hyperedges as a collection of pairwise edges, it reconstructs the true hyperedge structure, which is closer to how real hypergraphs actually work. This produces more realistic synthetic data. SuperHype takes a different decomposition approach: it breaks a hypergraph into layers of regular graphs (treating the hypergraph as a sum of overlapping graph layers), generates each layer separately, and then recombines them. This works because many hypergraphs have a hidden layered structure. By generating the layers independently, SuperHype can learn local connectivity patterns (which nodes link to which) and global patterns (how the layers fit together) more accurately than methods that don't use this decomposition.

Both tackle the same problem—generating realistic hypergraphs—but use different structural insights: ReLaSH explicitly models attributes, SuperHype uses hidden layering.

ReLaSH: Reconstructing Joint Latent Spaces for Efficient Generation of Synthetic Hypergraphs with Hyperlink Attributes

Reproduces local and global connectivity patterns with superior fidelity compared to state-of-the-art hypergraph generation baselines across five datasets.

Merging and editing graphs

Sometimes you don't start from scratch. You have multiple graphs trained on different datasets, or you want to compute the similarity between two graphs by finding the best way to transform one into the other. These papers address graph modification and comparison as generation problems.

Out-of-Distribution Graph Models Merging tackles a practical challenge: you have graph models trained on different distributions (say, social networks from different regions), and you want to combine them into one model that works on all distributions. The framework works without needing access to the original data, only the trained models themselves. This is important because in the real world you often have pretrained models from others but can't access their training data. Towards Generative Graph Matching solves a different transformation problem: given two graphs, compute how different they are by finding the minimum edits needed to turn one into the other. Instead of checking all possible edits—which is combinatorially explosive—it generates a diverse set of promising edit sequences and picks the best one. The result is nearly as accurate as exhaustive methods but much faster because sampling a good subset of edits beats exploring every combination.

Both reframe graph modification as a generation task: one generates a merged model across domains, the other generates candidate edit sequences to measure graph similarity.
