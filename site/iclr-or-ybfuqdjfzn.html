ScaleCUA: Scaling Open-Source Computer Use Agents with Cross-Platform Data

Build a stronger computer-use agent by collecting a much larger cross-platform action dataset and training one model to operate across operating systems instead of within one narrow interface.

Paper explainersAll themesAgents & Tool Use

Computer-use agents act on real graphical interfaces: they read screens, choose where to click, type text, and move through multi-step tasks. Progress has been slowed by a simple bottleneck: open training data is small, narrow, and usually tied to one platform. ScaleCUA attacks that bottleneck directly. It builds a large dataset that spans six operating systems and several task domains, using a closed-loop data pipeline in which automated agents produce candidate traces and human experts review or refine them. Training on this wider dataset produces an agent that transfers better across platforms because the model sees the same user goals expressed through more layouts, menus, and action sequences. The central claim is straightforward: if you want a general computer-use agent, you need large-scale action data that covers the variety of screens and workflows such an agent will actually face.

Zero assumption version

Why computer-use agents stay narrow

A computer-use agent must deal with many interface layouts, button styles, window systems, and task types. A model trained on one website or one operating system often learns shortcuts tied to that setting instead of learning reusable screen-action skills.

The main limitation is data. Open datasets for this area are much smaller than the diversity of real computer use. Without broad examples of how people complete tasks across platforms, the agent struggles when menus move, icons change, or the same task requires a different sequence of actions on another system.

The paper's move in one sentence. Scale up computer-use training data across operating systems and domains, then train one model on that shared action corpus so it learns broader screen-to-action behavior.

The algorithm as a flow

What it actually does

Collect candidate action traces.

Use automated agents to attempt tasks across several operating systems and task domains, so data collection scales beyond fully manual recording.

Review and refine the traces.

Have human experts check or correct the candidate trajectories, because quality control is needed before the traces become training data.

Assemble one shared dataset.

Store screens, actions, and task progress from all supported platforms in one large corpus.

Train a cross-platform computer-use agent.

Fit one model on the combined dataset, so it learns action patterns that recur across different interface styles.

Evaluate on held-out benchmarks.

Test the model on several computer-use suites to see whether broader data improves cross-platform task completion because those benchmarks expose whether the learned skills survive interface changes.

The hidden quantity

The hidden quantity: interface diversity coverage

measured quantity  =  How much of the real variation in screens and workflows is represented in the training data

A computer-use model only generalizes to layouts and workflows it has learned how to interpret. The hidden quantity is coverage of interface diversity: how many different operating systems, layouts, and task patterns appear in the training set.

ScaleCUA raises that coverage directly by collecting data across six operating systems and multiple domains. This helps because a model that has seen broader variation is less likely to confuse a task when the same intent is expressed through a different interface structure.

Why it works

Why more varied action data helps

The method works because many computer-use failures are data failures. A narrow training set teaches the model to depend on accidental details of one interface, such as one menu position or one button style. Wider data breaks that shortcut because the same task appears under different layouts and across different systems.

The closed-loop collection process matters as well. Automated agents provide scale, while human review raises trace quality. Performance improves because the model gets both more examples and more reliable examples, and those examples cover a broader set of screen-action patterns than earlier open datasets.

The scaling idea

First in words:

Average success over many benchmarks after training on the larger cross-platform corpus, so gains reflect whether broader data improves task completion across systems.

Then the compact form:

mean_success = successful_tasks / attempted_tasks

Every symbol:

successful_taskshow many benchmark tasks the agent completed correctly
attempted_taskshow many benchmark tasks were attempted
mean_successthe task completion rate used to compare agents
A tiny worked example
Suppose one agent is trained on a narrow single-platform dataset and another is trained on the ScaleCUA corpus.
On a held-out benchmark, the narrow-data agent finishes 38 of 100 tasks.
Its mean success is 0.38.
The broader-data agent finishes 53 of 100 tasks.
Its mean success is 0.53.
The higher score is useful because the only major change was broader cross-platform training data.

This comparison is useful because the paper's central claim is about data scale and data breadth, not about a specialized test-time trick.

What can go wrong

What can go wrong

The dataset can still miss rare workflows. Even a much larger corpus may underrepresent unusual enterprise tools or uncommon system dialogs, so transfer to those cases can remain weak.
Human review may not scale perfectly. If review quality drops as the dataset grows, incorrect action traces can enter training and teach the wrong behavior.
The model may still learn visual shortcuts. Broader data reduces narrow shortcuts, but it does not eliminate them entirely because frequent layouts can still dominate the corpus.
Done right. When the collected traces are broad and accurate, the agent handles new platforms better because it has already learned the common screen-to-action patterns that persist across systems.
What a runnable demo should prove

What a runnable demo should prove

Build two open computer-use agents with the same model family. Train one on a narrow single-platform corpus and the other on a ScaleCUA-style cross-platform corpus gathered through agent drafts plus human review. Evaluate both on held-out tasks from several operating systems. The demo should show higher completion rates for the broad-data agent because broader training coverage teaches more reusable interface skills.

completion_rate = completed_tasks / total_tasks

The point of the demo is to isolate the value of broader data coverage for general computer-use behavior.
