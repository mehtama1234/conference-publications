Scaling Laws for Precision in High-Dimensional Linear Regression

When training models with low-precision numbers, multiplicative and additive rounding hurt the model differently—multiplicative rounding wastes your dataset, while additive rounding wastes your model capacity.

Paper explainersAll themesLearning Theory

Real hardware stores numbers using fewer bits to save energy and time. This rounding introduces errors. The paper measures exactly how those errors spread through the tradeoff between model size, dataset size, and accuracy. It finds something surprising: two kinds of rounding—one that scales with the signal, one that does not—degrade the model in completely different ways.

Zero assumption version

Why precision matters in training

Training a machine-learning model means finding the right numbers (called weights) by running data through the model many times and nudging those weights a tiny bit each pass. Each nudge is computed using floating-point arithmetic—the standard way computers represent decimal numbers.

But floating-point arithmetic uses many bits. Modern hardware can run the same calculation with fewer bits much faster and cheaper, because fewer bits means less data to move between memory and the chip, and simpler logic circuits to do the arithmetic. The catch: fewer bits means rounding errors. When you round a number, you lose precision. The question is: how much does that loss hurt the final model, and how do you make up for it by changing the model size or dataset size?

The problem. Rounding during training introduces error, but we don't know whether to add more data, make the model bigger, or use more bits to fix it.

What the paper changes

The numbers being stored

The paper changes how numbers are rounded during training. Instead of storing full-precision numbers, the computer rounds them to fewer bits. The paper compares two kinds of rounding: multiplicative (where the rounding error scales with how big the number is) and additive (where the rounding error is always roughly the same size).

the object it moves  =  Rounding method for storing numbers
The hidden quantity

The hidden quantity: effective capacity

measured quantity  =  Effective capacity

Effective capacity is the number of patterns the model can actually learn when rounding is happening. With perfect precision, a model with M weights (the numbers that get tuned during training) can learn M independent pieces of information from M data points. But with rounding, some of that learning is drowned out by noise. The effective capacity is lower.

The paper estimates this by working backward from the test error: given a fixed accuracy goal, how many parameters and data points do you actually need when rounding is present? That is the effective capacity—the noise has eaten away at it. Multiplicative rounding reduces effective data capacity (you need way more examples to learn), while additive rounding reduces effective model capacity (you need more parameters to absorb the noise).

Why it works

Why each quantization type hurts differently

Multiplicative rounding is when the error is proportional to the number being rounded. A big weight rounds to a big weight, with error size matching. A tiny weight rounds to a tiny weight. This means the relative error is roughly constant across all weights. During training, when data comes in, the true signal gets rounded, but the rounding error acts like signal-dependent noise. The model can still learn the direction of the signal—that is why it preserves effective model size—but it needs many more examples to average out that noise and find the true direction. It is like hearing someone whisper in a room full of people: the whisper is there but you need to listen many times to know what they said.

Additive rounding is when the error is the same size everywhere—a constant amount of noise added to every number. This is like static on a radio: the background hum is there regardless of what you are hearing. The model's weights get corrupted equally by the same noise floor. The problem is that small weights are now buried in the noise (a weight of 0.01 with a noise floor of 0.1 becomes indistinguishable from zero; the model cannot even use that weight anymore), so the model loses access to fine detail. It needs many more weights to compensate—to have enough weights that are bigger than the noise floor—so that the signal is not completely lost. This is why additive quantization reduces model size, not data size.

Math after the picture

The scaling law equation

First in words:

Error equals a base term plus terms that depend on how many parameters you have and how much data you trained on, scaled by how bad the quantization is.

Then the compact form:

error = C1 / n + C2 * quantization_cost / m + C3 * quantization_cost

Every symbol:

errortest accuracy loss
nnumber of training data points
mnumber of model parameters
quantization_costhow bad the rounding is (related to bit-precision)
C1, C2, C3constants that depend on the problem
A tiny worked example
Suppose full precision gives error = 0.10.
With 1000 data points: base error term = 0.01 / 1000 = 0.01.
With 100 parameters: model term = 0.01 * 100 = 1.0.
Multiplicative quantization (cost = 0.1): adds 0.1 * 0.1 / 1000 = 0.00001 per data point.
To keep total error at 0.02, you need n = 0.01 / 0.02 = 500 data points WITHOUT quantization.
With quantization, you need n = 0.01 / (0.02 - 0.1 * 0.1 / 100) ≈ 526 data points (minimal harm).
But if quantization cost jumps to 1.0, you need n ≈ 1000+ data points (data size doubles or worse).
Additive quantization instead hurts model: need m = 200 to absorb the noise-floor, but full-precision only needed m = 100.

The equation splits the problem into data-driven error and model-driven error; quantization pushes on them differently.

What can go wrong

What can go wrong

Mixing precision levels mid-training. If some layers use low precision and others use full, the analysis breaks down. The paper assumes all-or-nothing quantization for the worst-case bound.
Non-linear models. The paper analyzes linear regression. Neural networks have nonlinearity, which creates different interactions with quantization noise. The scaling laws might not transfer directly.
Stale estimates of quantization cost. The rounding-cost value (how bad the rounding is) depends on the bit-width. In real hardware, it also depends on how overflow is handled—some chips clamp overflows to the max value, some wrap around, some saturate—each choice creates different error patterns and thus different actual costs. The paper derives worst-case bounds by assuming no safeguards; your real hardware may achieve a lower cost if its overflow handling is more careful, or match the worst case if it does not protect against overflow.
Done right. Use the paper's scaling law to predict: given a hardware constraint (fixed bit-width), should I add more data or use a bigger model to keep accuracy high? The answer depends on which quantization type dominates your hardware.
What a runnable demo should prove

What a runnable demo should prove

Build a synthetic high-dimensional linear regression task (100+ dimensions, 1000+ samples). Train using full precision, then retrain using multiplicative quantization (e.g., round to 4 bits in a way that scales with magnitude) and additive quantization (round to 4 bits with uniform noise). Measure test error for different model sizes (50, 100, 200 parameters) and different dataset sizes (500, 1000, 2000 examples). Plot error vs. model size and error vs. dataset size separately for each quantization type.

error_mult = test_loss_multiplicative - test_loss_full_precision; error_add = test_loss_additive - test_loss_full_precision; show that increasing dataset size helps multiplicative more than additive; increasing model size helps additive more than multiplicative.

The demo makes it obvious that the two quantization types are not interchangeable: multiplicative quantization is fixed by adding data, additive by growing the model.
