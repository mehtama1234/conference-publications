Multi-Negative Importance Sampling for Multimodal Alignment

Show the model multiple different mistakes at once so it learns to handle all of them, not just one.

Paper explainersAll themesMultimodal

Vision-language models (models trained to understand both images and text together) learn from feedback. Today's methods show the model a picture it got right and one it got wrong, but that single wrong picture only teaches it to avoid ONE specific error. This paper's insight: if you show the model three or five different kinds of wrong pictures at the same time, it learns to navigate all of them at once and makes fewer hallucinations (inventing details that are not in the image).

Zero assumption version

The single-negative bottleneck

Today, vision-language models learn from human feedback in pairs: a picture the human liked and one they did not like. The model sees the positive image with its correct description and one negative image (usually a slightly corrupted or randomly chosen bad one). But there are many different ways to get an image wrong. A model might caption "a red apple" when it is green, or say "apple" when it is an orange, or describe the right object in the wrong room. A single negative image teaches the model to avoid ONE of these errors.

Because the model only sees one kind of mistake at a time, it cannot learn how to handle the trade-offs between different error types. If the negative happens to be a green apple when the problem is color, the model does not learn what to do if it encounters a different mistake—say, an apple in the wrong place. The model memorizes narrow fixes instead of learning the broader principle: be faithful to the image.

The fix in one sentence. Give the model multiple different negative images per training step so it learns to fix multiple kinds of mistakes at once.

The algorithm as a flow

What it actually does

Embed and compare

Convert the image and text prompt into lists of numbers (embeddings) using CLIP, a standard model that understands both images and words.

Find the differences

Compare the positive image with each negative candidate to find how they differ in their embeddings—what makes each wrong answer wrong.

Decompose into factors

Use a sparse autoencoder (a compressed representation) to break each difference into interpretable parts—color, object type, location, lighting.

Select diverse negatives

Pick multiple negatives that cover different error types; skip any that just repeat the same mistake in a slightly different form.

Train with ranking

Use a ranking loss that forces the model to rank the right image above all the chosen wrong ones simultaneously, learning multiple constraints at once.

What the paper changes

What changes: the negative pool

The paper changes from picking one negative image per training example to picking multiple negatives—typically three to five per positive. But not just any negatives: the negatives must be semantically different from each other, each representing a distinct type of error the model could make.

the object it moves  =  negative image selection
The hidden quantity

The hidden quantity: semantic deviation

measured quantity  =  semantic deviation from positive

Semantic deviation is how different a negative image is from the positive one in the embedding space (the space of all possible meanings), measured by comparing their CLIP encodings. A small deviation means the negative is almost identical to the positive and teaches little. A large deviation means it is a genuinely different picture and shows a real error the model should learn to avoid.

The paper estimates this using a sparse autoencoder that decomposes the embedding difference into factors like color, object, and layout. An image that differs only in color has a different deviation number than one that differs in the entire scene. By measuring and comparing these deviation numbers, the method selects negatives that each represent a different kind of mistake.

Paper reading. The sparse autoencoder breaks the CLIP embedding difference into separate, interpretable factors, surfacing orthogonal semantic variations. Each negative is scored by how hard it is to reconstruct and by mutual diversity, ensuring negatives probe distinct failure modes.
Why it works

Why multiple negatives work: ranking under constraint

The model learns by comparing a right answer to a wrong answer and asking: how much more does the wrong one look like a better match than the right one? With a single negative, there is only one constraint: beat this one. The model can win by just moving slightly away from the single negative in a narrow direction.

With three different negatives, the model has three simultaneous constraints: move away from the red apple, move away from the orange, and move away from the blurry photo—all at once. These constraints pull in different directions (color versus object type versus clarity). The only way to satisfy all three is to learn something deeper: what features actually define the right image. The model cannot cheat by moving in one narrow direction; it must move in a space that respects all the error types it sees.

Math after the picture

The ranking equation

First in words:

The model is trained to maximize the log probability that the positive image is preferred over all negatives, weighted by how informative each negative is according to a sparse autoencoder score.

Then the compact form:

L_MN-DPO = -E[log(sigmoid(beta * (log(p_pos) - log(sum of exponentials of negative scores))))]

Every symbol:

p_poshow confident the model is that the positive image matches the prompt
p_neg_ihow confident the model is that the i-th negative image matches the prompt
betaa scaling factor that controls how hard the model should try
sigmoida smooth function that turns any number into a probability between 0 and 1
Nnumber of negatives shown in this training step (usually 3-5)
A tiny worked example
Suppose the model scores the positive image 0.90 (quite confident) and scores three negatives at 0.30, 0.35, and 0.25 (less confident).
The log probabilities are roughly: positive = log(0.90) ≈ -0.11, negatives = log(0.30) ≈ -1.2, log(0.35) ≈ -1.05, log(0.25) ≈ -1.39.
The ranking loss penalizes the model when negatives score too high. If all three negatives averaged 0.50 instead, the loss would be much larger.
By training many steps, the model learns that when it sees a green apple it should give it a lower score, and same for scene changes and color errors—simultaneously.

The Plackett-Luce ranking model treats the positive as beating all negatives in a single ranking, not just one pairwise comparison.

What can go wrong

What can go wrong

Redundant negatives are wasted. If two negatives are too similar to each other (both slightly cropped versions of the positive, for example), they do not provide independent constraints. The model is not learning multiple things, just the same thing twice.
Negatives that are too different confuse the model. If a negative is so different from the positive that it represents an entirely different subject (e.g., a car instead of an apple), it is not teaching the model what went wrong with the apple—it is just noise.
Importance weighting is fragile. The sparse autoencoder scores that weight each negative must be reliable. If the scores are noisy or misleading, the model might give too much weight to unhelpful negatives or ignore the most informative ones.
Done right: diversity is key. The method selects negatives that differ in orthogonal factors—one changes color, one changes the object, one changes the scene. These independent error types ensure the model learns multiple, non-overlapping constraints.
What a runnable demo should prove

What a runnable demo should prove

Build a small multimodal dataset: 20 images with correct captions and 60 plausible but wrong captions. For each positive caption, generate three negatives by manipulating the image (crop, color shift, blur) and measure how many hallucinations the model makes before and after training with single negatives versus multi-negatives. A good demo trains a small vision-language model for 10 epochs on both methods and compares the hallucination counts and caption diversity (does it describe different aspects of the image, not just the same detail repeatedly).

hallucination_rate = (captions mentioning objects not in image) / (total captions generated)

The multi-negative method should produce fewer made-up details and more varied, image-faithful captions—all from the same model architecture, changed only by how you pick the negatives during training.
