SketchThinker-R1: Efficient Sketch-Style Reasoning

Train a multimodal model to solve problems with sketchy, goal-directed reasoning instead of exhaustive step-by-step thinking, cutting token costs in half.

Paper explainersAll themesMultimodal

When you solve a hard problem, you usually think step by step—but you skip the tedious parts and jump straight to what matters. SketchThinker-R1 teaches a multimodal model (one that looks at images and text together) to reason the same way: in quick, focused bursts that nail the essential insights without the overhead. The result is reasoning that uses half the tokens—the raw numbers the model outputs—and answers just as correctly.

Zero assumption version

Long reasoning drains resources

Today's best multimodal models reason by generating long chains of thinking—step after step, often dozens of steps for a hard problem. Each step costs tokens, the basic units of text the model produces. More tokens mean slower responses and higher computational bills.

A naive fix is to just tell the model to be brief: Answer in three sentences. But that often fails. The model skips necessary logical jumps, and accuracy plummets. You save tokens but break correctness.

The tension: Long reasoning is accurate but expensive. Brief reasoning is cheap but wrong.

The algorithm as a flow

What it actually does

Stage 1: Cold start

Take long reasoning examples and rewrite them shorter, keeping only essential steps. Fine-tune the model on these converted pairs.

Stage 2: Train a reward model

Build a separate model that scores reasoning: 1 for concise-and-correct, 0 for long or wrong.

Stage 3: Reinforce the behavior

Run reinforcement learning (reward-based training) where the model gets nudged toward higher scores from the reward model.

Adaptive weighting

Early in training, strongly reward brevity to shift the model's style. Late in training, weight correctness more, to nail accuracy.

Result

Model outputs reasoning that is roughly half as long but equally accurate.

What the paper changes

What the paper changes

The paper changes how the model generates reasoning: from long, comprehensive step-by-step chains to focused, goal-directed sketches that preserve correctness while dropping unnecessary elaboration.

The hidden quantity

The hidden quantity: Sketch quality

measured quantity  =  Conciseness with correctness preserved

The paper measures something that is not obvious: how much reasoning can be removed without breaking the answer. A long reasoning chain has redundant steps—explanations of things already clear, detours that do not lead anywhere. A sketch-style chain keeps only the steps that matter for reaching the right answer.

The paper estimates this by training a reward model that explicitly scores reasoning on two dimensions: how short it is (favoring brevity) and whether the final answer is correct (favoring accuracy). The model then learns which information is truly essential.

Why it works

Why it works: teaching the model what to keep

Long reasoning is not inherently good—it is just what the model learned to do by default because training data had lots of it. Most of a long reasoning chain is scaffolding: intermediate explanations, double-checks, restating things. The essential reasoning—the core logical jumps—is buried in there.

The paper uses three mechanisms to expose and preserve the essential parts. First, it manually rewrites long examples into short, correct ones (cold start), showing the model what brevity looks like. Second, it trains a separate reward model that learns to recognize concise-and-correct reasoning by contrast with long-and-correct reasoning, assigning scores that track the difference. Third, reinforcement learning uses those scores to nudge the model toward high-scoring outputs during training. By the end, the model has internalized what essential reasoning looks like and generates it directly.

The training equation

First in words:

The reinforcement learning loss combines a reward term (how good the reasoning is) and a penalty term (how far the new model has drifted from the starting model). The reward itself is a weighted mix: early training heavily weights sketch brevity, late training heavily weights correctness.

Then the compact form:

Loss = -(reward_brevity + reward_accuracy) + beta * KL_divergence_from_baseline

Every symbol:

reward_brevityscore from the reward model for how concise the reasoning is
reward_accuracyscore from the reward model for whether the answer is correct
betaa fixed constant controlling how much we penalize drift from the starting model
KL_divergence_from_baselinea measure of how different the new model's outputs are from the old model's outputs
A tiny worked example
Example reasoning A: Long but correct. Reward model gives brevity score 0, accuracy score 1.0. Total reward = 0 + 1.0 = 1.0.
Example reasoning B: Short and correct. Reward model gives brevity score 1, accuracy score 1.0. Total reward = 1 + 1.0 = 2.0.
Reasoning B scores twice as high, so RL training nudges the model toward outputs like B. Over many examples, the model learns the pattern.

The loss function penalizes brevity early (by weighting reward_brevity high initially) and penalizes wrongness late (by weighting reward_accuracy high finally), so the model first learns to be concise, then refines accuracy.

What can go wrong

What can go wrong

Reward model is wrong. If the reward model assigns high scores to reasoning that looks brief but is actually incomplete, the model will learn to sound concise while skipping critical logic. This is detected by testing accuracy: if it drops, retrain the reward model with better examples.
Early weighting is too aggressive. If brevity is rewarded too heavily in early training, the model sacrifices correctness before accuracy is in the mix. The paper gradually reduces the brevity weight and increases the accuracy weight to avoid this.
Out-of-domain problems are harder. A model trained on a specific dataset learns to sketch in the style of that dataset. When given a problem type it has never seen, it may sketch in ways that were safe on training data but fail on the new problem.
Done right. Train the reward model on diverse, human-verified pairs of long and short reasoning. Use the weight schedule to balance brevity and correctness. Test on out-of-domain benchmarks to catch generalization gaps early.
What a runnable demo should prove

What a runnable demo should prove

Build a simple visual task with images (e.g., a comparison puzzle or a basic visual reasoning question) that requires logical steps to solve. Train the model on long reasoning examples. Then run the three-stage pipeline: cold start, reward model, and RL. Measure two things: the total token count of the reasoning and the accuracy of the final answer.

Efficiency of Thinking = (Final Accuracy) / (Average Reasoning Tokens). Higher is better.

The demo must show that reasoning tokens drop to about half while accuracy stays stable, proving the model learned to identify and keep only essential steps—because if it were just truncating blindly, accuracy would fall.
