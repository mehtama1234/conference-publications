Risk-Sensitive Agent Compositions

The paper chooses agent workflows by minimizing bad-tail outcomes, because high average success is not enough when rare failures violate safety, fairness, or privacy requirements.

Paper explainersAll themesAgents & Tool Use

Modern AI systems often solve a large task by chaining specialized agents: one plans, one writes code, one verifies results, and one interacts with tools. Looking only at average success is dangerous in that setting. A workflow can look strong on average while still producing rare but unacceptable failures, such as unsafe actions or privacy leaks. This paper formalizes the workflow as a directed acyclic graph of possible agent choices and asks a stricter question: which full path through that graph has the lowest tail risk? The method targets value-at-risk and conditional value-at-risk, then uses dynamic programming to find a near-optimal composition efficiently.

Zero assumption version

Average performance hides dangerous rare failures

A composed agent system is a chain of decisions. One component may be good at planning, another at execution, and another at checking. Even if each part has high mean performance, their combined workflow can still have a bad tail: rare runs with very large loss.

Those rare runs matter because deployment constraints often focus on safety, fairness, and privacy. A single severe violation can be unacceptable even when most runs succeed. That makes average reward the wrong objective for selecting among candidate workflows.

The paper therefore treats workflow design as a risk-sensitive optimization problem. Instead of asking which composition has the best expected return, it asks which composition keeps the worst-case tail small enough to be usable.

The key shift: Select the workflow with the safest loss tail, because operational risk is often driven by rare large failures rather than average behavior.

The algorithm as a flow

What it actually does

Represent the workflow space as a graph

Nodes define stages and edges define available agents because a complete path through the graph is one feasible composition.

Assign a loss profile to each agent choice

Each component contributes uncertainty in safety, fairness, privacy, or task loss so that the full path has a combined pattern of possible losses.

Approximate value-at-risk along the graph

The dynamic program uses a union-bound-based approximation because exact tail computation over all compositions can be too expensive.

Recover near-optimal compositions

The algorithm traverses the graph and keeps the best risk estimates so that low-tail-loss paths survive while riskier paths are discarded.

Estimate conditional value-at-risk as well

The same procedure yields an approximation to the average of the worst tail outcomes, which helps because conditional value-at-risk is stricter than value-at-risk.

What the paper changes

What the paper changes

The paper changes the objective for choosing an agent composition. Instead of optimizing expected success, it optimizes a tail-risk criterion over the set of feasible paths in an agent graph.

the object it moves  =  Objective used to pick a multi-agent workflow
The hidden quantity

The hidden quantity: tail loss of a composition

measured quantity  =  Pattern of possible losses in the worst-probability region of a workflow

The average loss of a workflow is visible after enough runs, but the decisive quantity for deployment can be the tail: the small slice of runs where very bad outcomes happen. That quantity is hidden during ordinary evaluation because average scores wash it out.

The paper focuses on two tail summaries. Value-at-risk asks how bad the loss becomes at a chosen probability level. Conditional value-at-risk goes further and asks for the average loss inside that worst tail. These metrics matter because a workflow with a slightly lower mean loss can still be much less safe if its worst failures are extreme.

By optimizing over this hidden tail quantity, the paper aims to select workflows that remain acceptable under rare but important bad cases.

Why it works

Why graph search with tail-risk summaries can find safer workflows

The method starts from a simple observation: a workflow is a path through a finite directed acyclic graph, so the search for a composition can be phrased as path optimization. The challenge is that the path cost is not an ordinary additive mean. It is a tail-risk statistic of the full loss pattern.

The paper addresses that challenge by approximating the value-at-risk with a dynamic program that exploits a union bound. This gives an efficiently computable upper estimate of tail behavior along partial paths. That estimate is useful because it lets the algorithm compare incomplete compositions without expanding every possible workflow to the end.

The asymptotic near-optimality result matters because approximation is unavoidable here. Exact risk computation over many compositions would be too expensive for large workflow graphs. The proof shows that the approximation is not arbitrary; it approaches the right decision under a broad class of practical loss functions.

Math after the picture

The risk objective

First in words:

Choose the composition whose loss has the smallest value-at-risk at probability level alpha.

Then the compact form:

c^* = argmin_{c in C} VaR_alpha(L_c)

Every symbol:

cone feasible agent composition path
Cthe set of all feasible compositions in the agent graph
L_closs random variable for composition c
alphatail probability level, such as 0.95
VaR_alpha(L_c)the smallest threshold l such that the loss is at most l with probability alpha
A tiny worked example
Suppose workflow A and workflow B both solve the task about 90 percent of the time.
Workflow A usually has loss 1, but 5 percent of runs have loss 20 because it sometimes triggers a severe failure.
Workflow B usually has loss 2, and 5 percent of runs have loss 8.
The average loss of A may look better, but its value-at-risk at alpha = 0.95 is worse because the cutoff near the bad tail is larger.
A risk-sensitive selector picks B because its rare failures are less severe.

The exact numerical definition of value-at-risk can vary by convention, but the paper's idea is to optimize the loss threshold in the bad tail.

What can go wrong

What can go wrong

Loss models may be misspecified. If the estimated loss profiles for component agents are wrong, the chosen workflow may look safe on paper while still carrying hidden tail risk.
The union-bound approximation may be loose. A loose bound can overestimate risk for some paths, which may push the algorithm away from a genuinely good composition.
Acyclic structure is a limitation. The current formulation assumes a directed acyclic graph, so workflows with loops or repeated tool use may require extra modeling before the method can be applied.
Done right: the workflow becomes safer under rare failures. When the loss model is credible and the graph captures the real composition choices, the method helps because it directly targets the low-probability events that matter in deployment.
What a runnable demo should prove

What a runnable demo should prove

Build a small workflow graph with several planning, execution, and checking agents. Give each edge a simulated loss profile that includes rare large failures for some components. Then compare a mean-optimized path with the paper's risk-sensitive path on many rollouts. The demo should show that the risk-sensitive path produces fewer severe failures because it was chosen using tail-aware criteria instead of average success alone.

tail_failure_rate = runs_with_loss_above_threshold / total_runs

The decisive result is a lower rate of severe failures, because that is what tail-risk optimization is supposed to control.
