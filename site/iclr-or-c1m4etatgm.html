Self-Rewarding Vision-Language Model via Reasoning Decomposition

A VLM learns to see and describe images well by rewarding itself when it can answer questions from its own descriptions without looking back at the picture.

Paper explainersAll themesMultimodal

Vision-language models (tools that read images and answer questions about them) often cheat by ignoring the picture and relying only on text. We fix this by having the model describe what it sees first, then checking if that description alone is enough to answer the question. If it is, we reward the model for seeing clearly. This creates a self-checking loop that teaches visual perception.

Zero assumption version

Models that talk without looking

A vision-language model is supposed to read an image and answer a question about it. But often the model does not really look at the picture; instead, it guesses based on language patterns it learned from text. If you ask it to describe a scene with a red car and a blue car, it might answer 'blue car' because text in its training data often mentions blue cars first, even if the image shows red first.

Why does this happen? Because in training, people only check if the final answer is right. They do not watch whether the model actually looked at the picture. So the model learns a shortcut: skip the image, guess from text habits, get the answer right by luck often enough. This works because if the text habit happens to match the right answer, the model gets a reward signal with no way to know that it did not actually see the image.

The fix. Make the model describe what it sees, then check if that description alone is enough to answer the question. Reward the model only when it can describe what it sees clearly enough to reason without looking back.

The algorithm as a flow

What it actually does

Prompt for perception

Show the model an image and a question, ask it to describe the image in detail.

Validate the description

Hide the image, show only the model's description plus the question, ask it to answer based on the description alone.

Check if description is sufficient

If the answer matches the right answer, the description was clear enough. That earns a reward.

Also check the final answer

Train the model to get the answer right on the original image too.

Update weights with both rewards

Adjust the model's numbers to strengthen paths that make good descriptions and right answers at once.

What the paper changes

What the paper changes

The paper changes where the model looks for guidance during training. Normally, humans supervise only the final answer. This paper adds supervision in the middle: the visual description step. By rewarding clear descriptions, it tells the model which parts of the image matter and how to describe them, without needing human annotations.

The hidden quantity

The hidden quantity: description completeness

measured quantity  =  How much information the description holds

The paper measures a new quantity: does the model's description of the image contain enough information to answer the question without seeing the image again? Call this 'description completeness.' A complete description is one where the model can read it and answer correctly. An incomplete description forces the model to guess.

The paper estimates completeness by re-running the model on the description alone. If the model answers correctly with only the description as input, completeness is high. If it fails, the description was vague or missing details.

Why it works

Why it works: the self-checking loop

The key is that the model now has two ways to make a mistake. In the old setup, if the model skipped the image and guessed right by luck, it got rewarded anyway. In this paper's setup, if the model skips the image when describing, the description is vague and lacks the concrete details that are actually in the picture. When the model then tries to answer from only that vague description, it fails the self-check test. The reason: answering questions requires specific details. For example, to answer 'what color is the car,' you must know the color from the description. A vague description that just says 'there is a car' has no color information, so no answer can be correct.

So when vision is sloppy, the description is vague. When the description is vague, the self-check fails. When the self-check fails, the model gets no reward. Training works by adjusting the model to make paths that earn rewards more likely and paths that earn no reward less likely. Since the lazy shortcut (skip the image) leads to no reward, the model will try other paths. One path is to look at the image and describe it carefully. This path produces clear descriptions. Clear descriptions contain the details needed to answer questions, so they pass the self-check and earn reward. The reward signal tells the model: this path works. The model adjusts its numbers to repeat this successful path (the same way your brain learns to repeat an action that led to a good outcome). Over time, this creates a reliable learning signal. This is better than human annotations because the model itself is checking, so the signal adapts automatically. When the model improves at seeing, it writes more detailed and accurate descriptions. More detailed descriptions contain answers to a wider variety of questions, so they will pass self-checks for harder, more specific questions.

Math after the picture

The training signal

First in words:

total_reward = reward_for_good_description + reward_for_correct_answer

Then the compact form:

L = -log_p_vision * r_vision - log_p_answer * r_answer + KL_penalty

Every symbol:

Lthe total loss (how wrong the model is)
log_p_visionthe log probability of the description the model wrote
r_visionreward for description completeness (1 if self-check passed, 0 if not)
log_p_answerthe log probability of the answer the model gave
r_answerreward for final answer correctness (1 if right, 0 if wrong)
KL_penaltya gentle brake to keep the model from changing too fast
A tiny worked example
Suppose the model writes a description, and the self-check passes (r_vision=1) and the final answer is right (r_answer=1).
Both log probabilities are negative (around -0.5 each for this example); the loss is -(-0.5)*1 + -(-0.5)*1 + 0.1 = 0.5 + 0.5 + 0.1 = 1.1.
Now suppose the description fails self-check (r_vision=0) but the answer is lucky correct (r_answer=1).
The loss is -(-0.5)*0 + -(-0.5)*1 + 0.1 = 0 + 0.5 + 0.1 = 0.6.
The first path (honest description + right answer) is punished more, so training favors it. This is the point: do not reward lucky answers if the reasoning was sloppy.

The vision reward and answer reward act as two separate signals; the model learns to make descriptions that pass the self-check, not just answers that happen to be right.

What can go wrong

What can go wrong

Lazy descriptions. If the model learns to write descriptions that are generic or vague but happen to work for common questions, the self-check does not catch it. The fix is to use diverse questions and verify that descriptions are truly image-specific, not template answers.
Description-answer mismatch. The model might describe the image correctly but then misread its own description when answering. This means the penalty for failing the self-check does not connect to real vision improvements. Mitigation: train the model's reading comprehension on descriptions too, not just vision.
Train and test questions are different. If the kinds of questions asked during training differ from those at test time, the model might write descriptions focused on the wrong properties. For example, the model describes colors well during training because training questions ask about colors, but test questions ask about object positions. The self-check thinks the descriptions are good because they pass on the training questions, but fail on the test ones.
Done right. Use a held-out diverse question set during training so the self-check covers many different topics. This forces the model to describe the whole image, not just common question topics, because questions can ask about anything. Then verify by testing on a new set of questions from the target domain—if the descriptions were broad and detailed, they will work for those new questions too.
What a runnable demo should prove

What a runnable demo should prove

Build a small vision-language model on a dataset of images and questions (e.g. a visual question-answering benchmark). Train it with the standard method (supervise only the final answer) on one half, and train it with Vision-SR1 (add the self-check stage) on the other half. Generate descriptions for both and measure: (1) Can a human rater tell if the description is faithful to the image, without seeing the image? (2) Does the description-only model answer the question correctly from the description alone, without the image? (3) Does the final-answer accuracy on the image improve when the model has learned through self-checking, because better vision means better answers? (4) Do fewer hallucinations (false details) appear in the descriptions of the Vision-SR1 model, because hallucinations only come from guessing when the model does not see clearly?

clarity_gain = (vision_sr1_description_clarity - baseline_description_clarity) / baseline_description_clarity * 100

The demo must show that self-checking descriptions teaches the model to see, not just to answer. Description clarity and hallucination reduction are the proof, not final-answer accuracy alone.
