DECOR: Learning to Decompose and Collaborate in Deep Search via Multi-Agent Reinforcement Learning

Split deep search into planning, evidence filtering, and answer writing, then train the three roles together so that each role improves the final answer by doing only its own job well.

Paper explainersAll themesAgents & Tool Use

Deep search systems often fail because one model must plan the search, judge noisy evidence, and write the final answer all at once. DECOR separates those jobs into Planner, Filter, and Answerer, then trains them together with shared outcome rewards plus role-specific feedback so that the team learns coordination instead of relying on a fixed hand-written workflow.

Zero assumption version

Why one deep-search agent breaks down

A deep-search agent must choose where to look, decide which retrieved material is useful, and combine the surviving evidence into an answer. Those decisions interfere with each other because a bad retrieval plan floods the answer stage with weak material, while a weak filter hides facts that the answer stage needs.

Many multi-agent systems still use fixed role prompts with no learning. That limits them because repeated collaboration mistakes do not change future behavior. DECOR treats the whole search workflow as a learning problem so that each role can improve from success and failure.

The paper's move in one sentence. Train specialized search roles jointly so that planning, evidence selection, and answer synthesis improve together because the team reward ties each role to the final outcome.

The algorithm as a flow

What it actually does

Planner chooses search actions

The Planner decides which query, branch, or source to explore next so that the system spends effort on promising directions.

Filter builds a reduced memory

The Filter removes low-value material and keeps the evidence that is most useful for answering because a smaller, cleaner context lowers confusion in the final stage.

Answerer writes from the curated memory

The Answerer produces the final response using the filtered evidence so that the answer depends on material already screened for usefulness.

Compute role-specific feedback

Each role receives feedback tied to its own job so that the Planner is judged on search quality, the Filter on memory quality, and the Answerer on answer quality.

Add a shared team signal

All roles also receive a team-level outcome signal because the system must optimize the final answer, not only isolated stage scores.

The hidden quantity

The hidden quantity

measured quantity  =  How much each role is helping or hurting the final answer

When the final answer is weak, you can see the bad outcome but not the exact internal cause. The problem might be poor branching by the Planner, noisy memory chosen by the Filter, or weak synthesis by the Answerer.

DECOR makes those internal responsibilities more visible by separating roles and assigning role-specific rewards. That matters because learning works better when a role can connect outcome changes to its own decisions.

Why it works

Why this works: specialize the jobs, then align the team

Functional decomposition helps because search planning, evidence curation, and answer writing require different decision rules. A single policy must carry all those responsibilities in one state, which makes learning noisy and can hide which skill needs improvement.

Joint training matters because specialization alone is not enough. If each role optimizes only its own local target, the roles can drift apart. DECOR adds a shared outcome reward so that specialization remains tied to final answer quality.

Combine local and team rewards

First in words:

A simple summary is that each role maximizes its own local score plus a shared team outcome score. That combination matters because local rewards teach role skills while the shared reward keeps the roles working toward the same final answer.

Then the compact form:

total_reward(role) = role_reward(role) + team_reward

Every symbol:

total_reward(role)the training signal for one role
role_reward(role)feedback for doing that role's own job well
team_rewardfeedback tied to the final search outcome shared across roles
A tiny worked example
Suppose a question needs three search steps.
Planner chooses a strong route and earns role reward 4.
Filter keeps mostly useful evidence and earns role reward 3.
Answerer writes a correct supported answer and the team reward is 5.
Planner total = 4 + 5 = 9, Filter total = 3 + 5 = 8, so both roles learn from their own decisions and from the shared outcome.

The real training rule is more detailed, but this summary captures the paper's central idea that role skill and team success must be optimized together.

What can go wrong

What can go wrong

Role boundaries can be chosen badly. If the decomposition does not match the real structure of the task, specialization may hurt because one role can become a bottleneck while another role gets too little useful work.
Local rewards can mislead training. A badly designed role reward can push a role toward behavior that looks good locally but harms the final answer, so reward design matters because local and team incentives must agree.
Coordination can be data-hungry. Training multiple roles jointly may require many episodes because the system must learn both individual skills and cross-role timing.
Done right. The paper is useful because it turns deep-search collaboration into a learnable system instead of a fixed orchestration script.
What a runnable demo should prove

What a runnable demo should prove

Build a search benchmark with a question, a document store, and a verifiable final answer. Implement three roles: Planner proposes the next retrieval action, Filter keeps or drops retrieved passages, and Answerer writes the final response. Train one version with only team reward and another with team reward plus role feedback.

The demo should show that the mixed reward version reaches better answer quality with cleaner retained evidence because the Filter learns to reduce noise and the Planner learns to search more selectively. Log per-role rewards and retained passages so that you can see which stage improved.
