VIRTUE: Visual-Interactive Text-Image Universal Embedder

Add the ability to point at a part of an image so the model can ground its meaning in that specific region, not just the whole picture.

Paper explainersAll themesMultimodal

Models that turn images and text into lists of numbers make it easy to find matching pairs. But they work only on whole images and text. VIRTUE adds visual pointing: you can draw a bounding box or point at an object in the image, and the model learns to understand what that specific region means in context. This creates a new kind of search: retrieve captions that describe not just "this image" but "this particular thing in this image."

Zero assumption version

Whole-image matching breaks on ambiguity

Today's embedding models work like this: convert an image to a list of numbers, convert text to a list of numbers, then find which image-numbers are close to which text-numbers. This is excellent for broad matching, but it fails the moment you care about parts. If an image has a dog and a cat, and you ask the model to find captions about the dog, the model cannot point at the dog. It sees the whole image at once. A beginner might try converting the visual point (click, bounding box, mask) into text first—write out what the user selected in English—but the model was never trained with spatially grounded text like this, so the conversion often breaks.

Real systems need to isolate: retrieve captions that describe a specific object in a specific scene, not everything that might match any piece of the picture.

In one sentence. VIRTUE extends an embedding model to accept visual prompts so it can ground its meaning in user-selected image regions and retrieve captions for specific objects in their scene context.

The algorithm as a flow

What it actually does

User provides a visual prompt

Click, bounding box, or mask on the object the user cares about.

Segmentation model processes the prompt

Prompt encoder reads what region was selected; image encoder reads the whole image.

Entity feature map is created

Mask decoder combines prompt and image to output a small feature map with entity-level detail.

Two embeddings are produced

Entity-level embedding from segmentation; global embedding from vision-language model.

Joint embedding grounds in region and scene

Both embeddings feed into the language model to create one unified list of numbers aware of both the object and the wider picture.

What the paper changes

The thing being changed: entity-level information

Previous models produced one embedding per image: a single list of numbers representing the entire picture. VIRTUE produces two: an entity-level embedding (the specific region the user selected) and a global embedding (the whole scene). Both feed into the language model to create a single joint embedding that understands both the local detail and the global context. The key move is adding visual prompting, because the prompt encoder learns to focus on the selected region—when trained on many examples of bounding boxes paired with entity descriptions, the encoder's weights get tuned to encode spatial location into the feature map.

the object it moves  =  entity-level embeddings
The hidden quantity

The hidden quantity: region-aware alignment

measured quantity  =  how tightly the entity embedding and text align given a visual prompt

Every embedding model measures how close image-numbers are to text-numbers. VIRTUE adds a new measurement: how well does the entity-level embedding (computed from a user's selected region) align with text that describes that entity? This is different from global alignment. A caption like 'a dog sitting on grass' should align strongly with the entity embedding of the dog but weakly with the entity embedding of the grass. The paper measures this via contrastive learning: pairs of entity-region and matching text should be close; non-matching pairs should be far apart.

The paper infers region-aware alignment by training on the new SCaR benchmark, which has 1 million image-region-text triples. It observes that models trained with visual prompts naturally learn to ground meaning in the specified region, not the whole image.

Why it works

Why it works: dual-path grounding

Without visual prompts, an embedding model sees the entire image all at once. When text says 'dog,' the model matches it to image-numbers that may encode both the dog and the cat. With visual prompts, the model learns two separate pathways: one for the entity (the thing the user selected) and one for the global scene. During training, the model sees triples: an image, a visual prompt (e.g., a bounding box around the dog), and a caption about the dog. The segmentation model's prompt encoder learns what the bounding box means—it focuses the entity pathway on just the dog. The global pathway still sees the whole image; this preserves scene information because both pathways together encode 'the dog' and 'the surrounding grass and outdoor context,' which tells the model which dog caption is correct when multiple dog breeds appear in a scene. When both pathways feed into the language model, they create a joint embedding that knows 'this is a dog in this particular scene.' During retrieval, the same dual pathways activate, so captions describing the dog in the scene context rank highest.

The mechanism is essentially: adding spatial grounding makes the model's internal representation richer. Instead of one blurry image-number, you get entity-level and global-level numbers that can be balanced. This is why the model stops confusing the dog and cat—they now have separate entity embeddings. The contrastive loss ensures matching triples (image-prompt-caption) have close embeddings, and mismatches stay far apart.

Math after the picture

The learning rule: contrastive alignment with dual embeddings

First in words:

For each training triple, compute an entity embedding e_entity and a global embedding e_global from the image and prompt, compute a text embedding t from the caption, concatenate or combine the embeddings, then measure how close the combined embedding is to the text embedding using a contrastive loss—matching pairs should be close, non-matching pairs should be far.

Then the compact form:

loss = -log(exp(sim(combined_embedding, matching_caption) / tau) / sum_j exp(sim(combined_embedding, caption_j) / tau))

Every symbol:

combined_embeddingthe fused entity + global image embedding
matching_captionthe true text for this image-prompt pair
caption_jany text caption in the batch
sim(a, b)cosine similarity between two lists of numbers
tautemperature: how sharply the model distinguishes good from bad matches
expexponential: grows fast for high similarity
A tiny worked example
Suppose the combined embedding for 'dog in field' has similarity 0.92 to the true caption 'a golden retriever in a meadow'.
And similarity 0.45 to a false caption 'a tabby cat on a rug'.
The model computes: exp(0.92/0.07) ≈ 7e5 (the true caption's score grows huge).
And exp(0.45/0.07) ≈ 19 (the false caption gets a tiny score).
The loss becomes -log(7e5 / (7e5 + 19)) ≈ -log(0.99994) ≈ 0.00006 (near zero, good).
For a bad embedding (both similarities low), loss climbs. Training nudges embeddings to maximize the true caption's score.

This loss pushes the combined embedding close to matching text and far from non-matching text—exactly what is needed for retrieval.

What can go wrong

What can go wrong

Ambiguous or missing prompt. If the user's bounding box is too small (just a pixel) or overlaps multiple objects, the prompt encoder receives conflicting signals. The entity embedding becomes muddled. The model may revert to global-only matching.
Prompt encoder memorizes patterns from training data. If the training set uses only bounding boxes (no points or masks), the prompt encoder may not handle new prompt types. User clicks that were rare in training may be ignored.
Scene context swallows entity detail. If the global embedding dominates during fusion, the model may still confuse objects. Strong weighting toward global features can undo the spatial grounding.
Done right. When the prompt encoder and segmentation model are kept frozen (pretrained weights used as-is) and only the segmentation-language connector is trained, the entity pathway keeps its learned detail and the dual-path mechanism works as designed.
What a runnable demo should prove

What a runnable demo should prove

Build a simple interactive web app: load an image, let the user draw a bounding box or click a region, show the top-5 captions retrieved by VIRTUE and by an old model (e.g., CLIP without prompts). Manually curate 10 images with multiple clear objects (e.g., a dog and cat, a lamp and table, a person and building). For each, have a human judge rate whether the top caption matches the selected object or the whole image. Count the number of times VIRTUE's top caption correctly describes the selected object, versus the baseline.

entity_accuracy = (number of times top caption matches the selected object) / (total user prompts)

The demo must make it impossible to miss: when the user points at the dog, VIRTUE retrieves dog captions; when they point at the cat, cat captions; old models retrieve mixtures of both.
