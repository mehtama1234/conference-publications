Real-time efficiency and deployment

Papers making vision-language and robot policies fast enough to run on real robots in real time, using techniques like token pruning, model compression, and efficient inference.

What this is

Modern robot policies are often built from large neural networks trained on internet-scale data. A model might have hundreds of millions of adjustable internal weights—the values that the network uses to make predictions. Running this model on a real robot is a problem. The robot has onboard compute—a small GPU or CPU, not a data center. A large model might take five seconds to produce an action, but the robot needs to react in 100 milliseconds. Also, the model might not fit in memory. And if it takes too much power to run, the robot's battery runs out in an hour instead of a day. So the challenge is: how do you keep the intelligence and capability of large models while making them fast and small enough to run on a robot?

The difficulty is that scaling down a model usually means losing capability. If you shrink the network, remove layers, or quantize weights (represent them with fewer bits), the model becomes faster because it does less computation, but less accurate because it has fewer internal adjustable values to store the patterns it learned. Where is the sweet spot? Also, different robots have different compute budgets. A research robot in a lab might have a high-end GPU. A delivery robot has a small embedded processor. A surgical robot needs absolute reliability and cannot retrain in the field. So efficiency is not a one-size-fits-all problem. It depends on the robot, the task, and the environment.

Papers address this through model compression—techniques to make models smaller and faster without losing too much accuracy, because smaller models have fewer parameters to compute and fewer values to move through memory. Some prune tokens: instead of processing every detail in the image, the model learns which parts of the image are important for the task and skips processing the others, saving computation. Some use distillation: train a small model to imitate a large one. Some quantize weights or use mixed precision—use fewer bits for some weights and normal precision for others. Others optimize the model for specific hardware, rewriting the model to use the instruction set and memory layout of a specific GPU, which makes it faster on that particular hardware because the memory access patterns match the hardware design. The central insight is that real deployment requires thinking about compute from the start, not as an afterthought.

How the work breaks down

Making big neural networks work on real robots requires different strategies. Some papers shrink the model itself through distillation and compression. Others skip unnecessary computation by pruning pieces of the input (parts of the image, for example) that do not matter for the task. Some target the specific hardware the robot runs on to squeeze out speed. Still others rethink how the robot learns and plans, to reduce the amount of computation needed in the first place.

Model distillation for onboard deployment

The core challenge: large vision-language models like LLaVA are too big and slow to run on a robot. A robot has limited memory and needs to answer a question or perceive a task in milliseconds, not seconds. Shrinking a model naively by just deleting layers loses the knowledge it learned from training.

BOLT takes a different path. It trains a much smaller student model to mimic a large teacher model (LLaVA-1.5-13B) on a specific robot task: multimodal question answering under memory constraints. The trick is decision-aligned distillation—the student learns not just to match the teacher's internal features, but to make the same final decisions as the teacher, which is what actually matters for the robot. The result: the student model (Robo2VLM-1) cuts memory from 26 gigabytes to just 3 gigabytes (89% reduction), meaning it fits on a robot's onboard computer, and accuracy jumps from 28% to 50% because the training focuses on getting the decisions right, not mimicking every internal layer. Budget-aware routing on top of this lets the model skip computation when the task is simple.

BOLT: Decision‑Aligned Distillation and Budget-Aware Routing for Constrained Multimodal QA on Robots
Robo2VLM-1 student distilled from LLaVA-1.5-13B improves accuracy from 28.66 to 50.50 with lower calibration error and 89% memory reduction (26,878 to 3,035 MB).

Pruning unnecessary pieces to skip computation

Vision-language-action models process images piece by piece—each piece represents a small patch of information. But not every patch matters. A robot manipulating a cup on a table does not need to process every pixel of the background wall. Processing pieces the robot does not need wastes computation time and battery.

SP-VLA attacks this by learning which pieces are critical for the task and which can be skipped. The model identifies temporal redundancy (the same information across consecutive video frames) and spatial redundancy (parts of an image the robot does not care about). By pruning—simply not processing—redundant pieces, the model stays fast and focused on the visual information and critical action decisions that actually matter. This keeps accuracy high because the model still sees what matters, but cuts computation roughly in half by not wasting time on the rest.

SP-VLA: A Joint Model Scheduling and Token Pruning Approach for VLA Model Acceleration
Reduces temporal and spatial redundancy in VLA models, achieving effective acceleration while maintaining focus on critical actions and salient visual information.

Hardware-aware acceleration for edge devices

Robots run on different hardware: high-end GPUs in lab robots, low-power edge processors (NPUs) in delivery robots, tiny chips in surgical robots. The same model compiled for one device might run 2x slower on another, even if the hardware specifications look comparable, because how the model accesses memory does not match the device's memory architecture.

The VLA-across-XPUs paper measures vision-language-action models on many different hardware platforms and shows how to accelerate them for each one. Optimizing for a GPU can deliver a 2.9x speedup. Optimizing for an edge NPU (neural processing unit) can deliver 6x faster inference with almost no loss in accuracy—the paper shows edge devices can outperform flagship GPUs because rewriting the model to match each device's actual design makes it run much faster. By recompiling the model for a specific device's memory layout and instruction set, a roboticist can use cheaper, lower-power hardware and still get fast enough inference to deploy on a real robot, which shrinks weight and battery load.

Characterizing Vision-Language-Action Models across XPUs: Constraints and Acceleration for On-Robot Deployment
Achieves up to 2.9x speedup on GPUs and 6x on edge NPUs with only marginal degradation, showing edge devices can be more efficient than flagship GPUs.

Efficient learning and action generation

Sometimes the bottleneck is not the model but the learning process itself. Behavioral cloning (where a robot learns by copying a human's actions) is simple but data-hungry: the robot needs many, many human demonstrations and does not learn efficiently from them. Similarly, robots that generate actions one small step at a time waste computation cycles on unnecessary decision points when the action could naturally flow in chunks.

The Constrained Demonstrators paper flips the learning problem: instead of assuming the human demonstrator is optimal, it learns from demonstrators who may be constrained (a smaller robot copying a larger robot's motions, for example). This forces the learning algorithm to be smarter: it cannot just copy—it must adapt. The result is 10 times faster task completion on a WidowX arm robot and better sample efficiency, because the model learns the underlying task intent, not just surface-level imitation. Learning High-Frequency Action Chunks uses a different approach: instead of predicting one action at a time, the model predicts sequences of actions in chunks, which it can execute continuously without pauses. Running the model fewer times—once per chunk instead of once per tiny action step—directly saves computation because each model invocation costs energy and time, and this reduces that cost by roughly one order of magnitude.

When a Robot is More Capable than a Human: Learning from Constrained Demonstrators
Outperforms behavioral cloning in sample efficiency and task completion; on WidowX arm, achieves 11-second task completion, 10x faster than behavioral cloning.

Efficient vision and planning primitives

Robotic tasks often involve visual tracking across long sequences (a robot following an object) or long-horizon planning (a manipulation task with many steps). Running a full deep model on every frame or every planning step becomes expensive. Specialized efficient primitives can handle these without retraining.

FastVGGT accelerates visual tracking by 4 times on long image sequences without retraining the model, by pruning redundant computations across frames and reducing the number of calculations needed to track movement. Efficient Differentiable Contact Model enables complex behaviors involving touch and pushing—like reaching through a cluttered table or rolling an object—by discovering control signals directly from simple starting guesses. It does this efficiently by using the mathematical structure of contact physics, so the robot does not have to simulate every possible trajectory, which would take forever. SNR-Aware Power Distributions rethinks long-horizon robotic planning as a sampling problem: instead of generating all possible future paths equally, the model learns to sample actions with probabilities that weight important decisions more heavily, so it spends computation budget on the decisions that matter and less on decisions that do not. These three papers show that efficiency often comes from understanding the task structure—visual tracking, contact physics, long-horizon planning—and building that structure into the algorithm rather than brute-forcing computation.

Efficient Differentiable Contact Model with Long-range Influence
Enables discovery of complex contact-rich control signals from simple initializations for locomotion and manipulation tasks.
FastVGGT: Fast Visual Geometry Transformer
Achieves 4x speedup on 1000-image sequences while mitigating error accumulation without retraining.
