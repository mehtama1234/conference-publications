Checking If Models Understand Across Languages and Time

Papers test whether models work in multiple languages, understand time-series patterns, handle long conversations, and maintain knowledge across different contexts and sequences.

All themesField mapMathematicsAll explainers
What this is

A model trained mostly on English text might be great at English but terrible at Chinese or Arabic. A model trained on text from 2020 might not understand events or slang from 2024. A model tested on single questions might fail when you ask it a series of questions that build on each other—holding context across a long conversation. This subtheme is about building benchmarks that test whether models work across languages, time periods, and long sequences.

The difficulty is that language and knowledge change. The same word means different things in different languages and contexts. Knowledge becomes outdated: facts true in 2020 might be false in 2024. Long conversations are hard because models have finite memory and processing capacity, and they have to track who said what, what was decided, what still matters. Building tests for these challenges means creating benchmarks in many languages, testing on recent events and evolving language use, and creating long-form conversational tasks where context actually matters.

Researchers approach this in several ways. Some build multilingual benchmarks: the same task in many languages to see whether a model works equally well across language families. Others create temporal benchmarks: tests that require knowing when an event happened or what the current date context is. Still others build conversation-based benchmarks where a model has to maintain context over many turns, or time-series benchmarks where a model has to predict or understand sequential patterns. The goal is to measure how well models work across the dimensions that matter most in real-world use: language, time, and long-form reasoning.

How the work breaks down

Work in this subtheme splits along four natural directions: testing whether models work equally well across different languages while spotting false answers, handling long back-and-forth conversations where context matters, understanding and predicting patterns in time-series data, and measuring how different groups of people prefer different models. Each direction tests how well models perform when conditions change.

Multilingual Knowledge and Hallucination

Testing a model on one language is not enough—a model might excel at English but fail spectacularly at Mandarin or Arabic. The challenge is that when a model hallucinates (makes up false information), it often hallucinates differently depending on the language because some languages have more training data or different cultural references than others. Knowledge-graph retrieval can help reduce false answers by letting a model look up facts instead of guessing, but does it work equally well across languages? This matters because if knowledge-graph retrieval helps English but not Arabic, then the fix itself is incomplete. Measuring this requires benchmarks that test the same knowledge-grounded task in many languages to see where models break down.

The MultiHal paper builds exactly this: a benchmark in multiple languages where a model must answer questions grounded in a knowledge graph—a structured database of facts like "Einstein won the Nobel Prize in 1921." Without the knowledge graph, models hallucinate freely. With it, they can fetch facts instead of guessing. The paper shows that adding knowledge-graph retrieval helps across all languages, but the gains vary—some languages improve by 0.16 points while others by 0.36 because translation quality and language-specific training data quality differ. This variation matters because it means you cannot assume a single fix works universally. The HUMAINE paper takes a different angle: it evaluates 17 large models and asks hundreds of human raters which model they prefer on tasks like "write a poem." The key finding is that preferences are not universal—different age groups prefer different models for different reasons because people of different ages value different qualities (say, humor vs. accuracy), with 65% of comparisons showing a tie between top models. This means a one-size-fits-all ranking fails; a benchmark must account for demographic heterogeneity to be fair.

Both papers reveal a central problem: benchmarks often assume all users and all languages are the same. In reality, what works for English users aged 25-35 might not work for Arabic speakers aged 50+. These papers push benchmarks toward being more contextual and inclusive.

Long Conversations and Interactive Tasks

A single question is easy—ask a model to define "photosynthesis" and it responds. But in the real world, conversations go back and forth. A customer says "I want to buy a blue shirt," then later "Make it a size large," then "Can you gift wrap it?" The model must track all three constraints and apply them to the right product. The problem is hard because models must follow complex domain rules, interpret ambiguous requests, and handle follow-up questions that refer to things said earlier.

Mix-Ecom builds a benchmark for e-commerce conversation: it has dialogues where a customer places orders with multiple constraints and asks follow-up questions, and the benchmark tracks whether the model correctly applies all rules. The paper shows current models fail often because they miss constraints or confuse which rule applies to which situation. BIRD-INTERACT tackles a different kind of interactive task: it's a benchmark where a user asks a model to convert natural language to database queries ("give me the sales for June"). The key twist is that the user can ask follow-ups like "Wait, show me only high-value customers" and the model must generate a refined query—not just the first answer. The paper shows 600 tasks where the model must handle ambiguity and iterate with the user.

Evaluating Language Models in Realistic Conversational Contexts builds a framework that measures conversational quality better than existing automatic metrics because it combines multiple scoring signals rather than trusting any single one. The problem is that existing automatic metrics often disagree with what humans think is good because automated systems miss subtle flaws (like a response that is technically correct but cold) that humans notice. The paper proposes Mixture-of-Judges: instead of using a single LLM to score, use an ensemble of scoring methods (some automatic, some LLM-based, some human-inspired) and combine their votes. This improves correlation with human judgment by ~30% over picking any single scorer because diversity in scoring methods catches more aspects of quality. Together, these three papers identify a core challenge: single-turn evaluation misses what real users need. Long conversations demand tracking context, refining answers based on follow-ups, and applying rules consistently over many turns.

Time Series: Description, Prediction, and Value

Time-series data is everywhere: stock prices, sensor readings from machines, weather patterns, patient vital signs. Models must describe what time-series data represents ("prices rose sharply in Q2"), predict what comes next ("temperature will drop tonight"), or evaluate which data points are most valuable for a task. The difficulty is that time-series is a specialized data type—it has temporal order, patterns repeat at different scales, and the same model architecture that works for language might fail for sequences.

BEDTime evaluates models at a fundamental task: given a time series (say, daily rainfall for a month), describe it in words. The benchmark tests 17 models including dedicated time-series models, vision-language models, and language-only models. The surprising finding is that vision-language models perform better than specialized time-series models—meaning a model trained to describe images can describe a graph better than a model trained specifically on time sequences. Language-only models fail hardest because they have no way to see the data visually. However, all approaches break when conditions shift: change the scale of the y-axis or add noise and accuracy plummets. Beyond Model Ranking: Predictability-Aligned Evaluation for Time Series Forecasting addresses a meta-problem: how do we fairly evaluate forecasting models? Existing metrics (like mean squared error) treat all prediction errors as equally bad, but in forecasting, some time periods are inherently harder to predict (e.g., during market shocks vs. stable periods). The paper proposes a metric that aligns with forecasting difficulty—tasks with high inherent unpredictability get a lower bar. This reveals that different forecasting architectures have complementary strengths: one model excels at short-term prediction, another at long-term. ConTSG-Bench tackles conditional time-series generation: given some control signals ("generate 100 days of synthetic stock prices with rising trend"), can a model produce realistic output? The benchmark shows current models generate data that looks plausible but fails basic sanity checks—for example, generated prices might violate market constraints you specified. Terminal Dimension Reduction for Time Series proposes a mathematical tool: instead of storing a full time series (1000 data points), compress it to a small set of representative points (10-20) that preserve enough information for clustering. This is useful when memory is scarce but you still want to group similar time series. TimeLAVA solves a practical problem: given a large time-series dataset, which examples are most important to keep and which can be discarded? The paper proposes a scoring method that identifies which data points matter most for anomaly detection or preventing label errors. This matters because collecting time-series data is expensive, and most of it might be noise.

These five papers show time-series benchmarking is fragile: models trained on clean, noiseless data often collapse on real data; metrics that treat all errors equally miss domain-specific difficulty; and generation tasks have hidden constraints that models ignore. The field needs benchmarks that measure how models handle shifts in data quality and account for real-world complexity.
