Cold-Start Personalization via Bayesian Adaptive Questioning

CAPE learns population-level preference structure offline, then asks a small number of adaptive questions online to infer a new user's preferences without retraining.

Paper explainersAll themesOther

Cold-start personalization begins with almost no user-specific data. A system must decide what this user wants after only a few interactions, even though preference space is broad and users rarely state their full criteria directly. CAPE handles that by splitting the problem into two stages. Offline, it learns a world model of how preferences co-occur across a population. Online, it uses Bayesian updating to infer a new user's likely preferences from a short sequence of adaptive questions. The paper argues that this decomposition is more sample-efficient than end-to-end reinforcement learning for early personalization.

Why cold-start personalization is difficult

When a new user arrives, the system has no personal history to lean on. Yet it must quickly tailor explanations, examples, or answer styles after only a few interactions. If it asks too many questions, the user leaves. If it guesses too early, it may lock into the wrong style.

The preference space is large because users differ along many dimensions at once: detail level, appetite for examples, directness, caution, and more. But those dimensions are not independent. Some preferences tend to appear together across the population.

The paper's claim is that population structure should be learned offline and reused online. That way, the online system does not start from a blank slate. It starts from a prior, which means an initial set of probabilities over plausible user preference profiles before any personal evidence arrives.

The paper in one sentence. Learn how preferences correlate across many users first, then use that learned prior to ask a new user the most informative next question and update beliefs after each answer.

The algorithm as a flow

What it actually does

Learn a population prior offline

Fit a structured belief model on past users so the system captures which preferences tend to co-occur.

Represent a new user with hidden variables

Treat the user's underlying preference profile as latent variables, which means hidden factors that explain their answers and choices.

Choose the next question adaptively

Ask the query expected to reduce uncertainty the most under the current belief state.

Update the belief after each answer

Use Bayesian inference, which means revising probabilities by combining prior belief with the new evidence from the user's response.

Act from the current belief

Personalize output using the highest-value action under the updated belief rather than retraining the whole system.

What the paper changes

The paper separates cold-start personalization into two modules: learn shared preference structure offline, then run online belief updating and question selection at use time.

The hidden quantity

The hidden quantity: user preference profile

measured quantity  =  the user's unobserved preference profile

The system never observes a full preference profile directly. It only sees answers to questions or reactions to outputs. The real target is the user's hidden profile across several preference dimensions.

CAPE tracks a probability spread over that hidden profile. That matters because early answers are noisy and incomplete. A belief spread can represent uncertainty directly, while a single guessed profile can become overconfident after very little evidence.

Why it works

Why the decomposition beats end-to-end trial and error

End-to-end reinforcement learning must discover both preference structure and question strategy from interaction alone. In a cold-start regime, that is a poor information setting because each new user provides only a handful of steps. The learner spends many interactions relearning broad population regularities that could have been estimated offline.

CAPE avoids that waste by moving shared structure offline. The prior already encodes which answers tend to predict other preferences, so one response can update several preference dimensions at once. That coupling is the main source of sample efficiency.

Adaptive questioning adds another gain. The system does not ask a fixed survey. It chooses the next question based on the current uncertainty, which means each interaction is used to resolve the most decision-relevant ambiguity that remains.

Bayesian updating is important because it maintains calibrated uncertainty. When evidence is weak, the belief remains broad, so the system can keep asking or choose safer actions. When evidence is strong, the belief concentrates, so the system can personalize more aggressively without retraining.

The belief update

First in words:

After each answer, update the probability of each user preference profile by combining the prior with the likelihood of the observed answer under that profile.

Then the compact form:

posterior(z | a_{1:t}) proportional to likelihood(a_t | z, q_t) * posterior(z | a_{1:t-1})

Every symbol:

zhidden user preference profile
a_{1:t}answers observed up to round t
q_tquestion asked at round t
likelihood(a_t | z, q_t)probability of the observed answer if the user profile were z
posterior(z | a_{1:t-1})belief before seeing the newest answer
A tiny worked example
Suppose the prior says users who want detailed answers often also want worked examples.
The system asks whether the user prefers brief or detailed explanations.
The user picks detailed.
The updated belief shifts toward profiles that favor detail and, because of the learned correlation, also raises belief that worked examples are welcome.
The next question can then focus on a remaining uncertainty, such as tone or caution level, instead of asking independently about every trait.

The paper's point is that one answer should update many beliefs when population structure is learned well.

What can go wrong

What can go wrong

The prior may reflect the wrong population. If the new users differ sharply from the users used to learn the prior, the belief updates can start from the wrong region and stay biased for too long.
Question quality determines information gain. Adaptive questioning only helps if the candidate questions are genuinely discriminative, because a poor menu of questions cannot reduce uncertainty efficiently.
A simple belief model may miss nonlinear preference structure. The abstract notes that even linear regression works well here, but richer user populations may contain interactions that a simple model cannot express, which means some correlations will be misestimated.
Where the design is strongest. The method is strongest when interaction budgets are very small, because that is when reuse of population structure matters most.
What a runnable demo should prove

What a runnable demo should prove

Build a personalization simulator in which each user has a hidden preference profile over answer detail, examples, tone, and caution. Train the prior on a synthetic population with realistic correlations, then compare CAPE against a fixed questionnaire and an end-to-end trial-and-error baseline.

The demo should show the updated belief after each question, the expected value of each candidate next question, and alignment with the user's true profile after one, two, three, and five interactions. That matters because the main claim is not just that Bayesian updating works, but that offline correlation structure makes each early answer more informative.
