Bilinear Bandits with Partially Observable Features

When you can only see some features of users and items, augment what you see with shadow dimensions so you can learn the hidden parts.

Paper explainersAll themesTime Series & Sequential

In online recommendation, you see some things about each user (age, region) and each item (category, length), but many important things stay hidden (taste subtleties, subtle appeal). A naive algorithm that only uses visible features will give worse recommendations, missing patterns in the hidden parts. This paper shows how to directly reason about the bilinear relationship (user times item) while filling in the gaps left by missing features.

Zero assumption version

The mismatch when features are hidden on both sides

In online learning, a system repeatedly chooses pairs (a user and an item), observes whether the choice was good or bad, and tries to get better by updating its predictions based on what happened. But it never sees all the facts. You see the user age and the item category, but not the hidden taste quirks or appeal factors that truly drive the reward.

A beginner would ignore the hidden parts and only learn from visible features. The result is guaranteed to be wrong: the learned model will systematically mispredict whenever the hidden parts matter. Another common trick is to convert the bilinear problem (user times item multiplied together) into a simple linear problem by flattening all features into one long list. But flattening wastes the structure: the system no longer knows that some features belong to users and some to items, so it needs many more features to learn the same pattern, and learning becomes slower.

In one sentence. BiRoLF augments visible features with invented shadow dimensions to capture hidden structure, then uses a careful estimation trick to learn the bilinear model.

What the paper changes

What the paper moves

The paper changes how the system approaches missing features. Instead of ignoring them or collapsing everything into a flat list, it directly builds the bilinear relationship (user feature times item feature) while accounting for hidden dimensions.

The hidden quantity

The effective hidden dimension: how much gap remains

measured quantity  =  effective hidden dimension (dh)

The effective hidden dimension measures how much structure lives in the parts you cannot see. It is the number of true hidden patterns that the visible features do not already capture. If users and items have very subtle hidden traits, dh is large. If visible features already explain most of the reward, dh is small.

BiRoLF estimates dh implicitly by how much the augmented shadow space helps; during training, shadow dimensions that capture true hidden patterns become important and get large values, while useless shadow dimensions stay small. The algorithm does not need to know dh beforehand; it learns how much shadow space is truly useful via its doubly stable estimation step, adapting to whatever hidden structure exists by letting the data guide which shadow dimensions matter.

But real attraction has hidden layers: 'shares my weird humor,' 'wants the same life pace.' These invisible patterns (the hidden dimension) are what good recommendations really depend on. BiRoLF invents shadow dimensions to let the learning algorithm at least try to capture these patterns without knowing them by name.
Paper reading. In the formal setup, the observed features span a subspace of ℝ^d (true feature space). Unobserved features lie in the orthogonal complement. BiRoLF augments the observable basis with an orthonormal basis from that orthogonal complement. The effective hidden dimension dh counts how many of these shadow basis vectors actually carry signal in the bilinear model—a data-dependent quantity that can be far smaller than the full orthogonal-complement dimension.
Why it works

Why it works: the real causal chain

The mechanism has three steps. First, add shadow space. The algorithm builds an orthonormal basis orthogonal to the observed feature space. These shadow vectors never existed in the data, but they form a complete set of directions perpendicular to what you know. Appending them to the feature lists gives the learning algorithm a chance to fit hidden patterns.

Second, estimate what you cannot see. When you choose a user-item pair, you observe one reward (good or bad). But there is a reward contribution from the hidden part you did not witness. Doubly stable estimation creates two independent guesses at this unobserved part and averages them. The reason this works: if one guess has a systematic bias, the other often does not, so averaging cancels error. Even when hidden features exist, the doubly stable trick keeps the estimate trustworthy.

Third, fit the bilinear model directly. With augmented features and imputed missing rewards, the learning step operates on the full feature space (visible plus shadow), enabling the system to learn the true bilinear user-item relationship without flattening or losing structure. Flattening would require quadratically more numbers to adjust; the bilinear form learns the same patterns with far fewer adjustable values.

The bilinear model with augmented features

First in words:

reward = (observed_user_features + shadow_user_features) times (parameter_matrix) times (observed_item_features + shadow_item_features) transposed, plus estimation correction for unobserved parts

Then the compact form:

reward_hat = [x_obs; x_aug]^T * Theta * [y_obs; y_aug] + correction

Every symbol:

A tiny worked example
Suppose the true user feature is [1.0, 0.0, 0.5] (observed: [1.0, 0.0]; hidden in third coordinate: 0.5).
Suppose the true item feature is [0.5, 1.0, 0.2] (observed: [0.5, 1.0]; hidden: 0.2).
True bilinear reward: 1.0 times 0.5 plus 0.0 times 1.0 plus 0.5 times 0.2 equals 0.5 plus 0.0 plus 0.1 equals 0.6.
Naive algorithm sees only [1.0, 0.0] and [0.5, 1.0], predicts 1.0 times 0.5 plus 0.0 times 1.0 equals 0.5 (misses the 0.1 from hidden parts).
BiRoLF augments: user becomes [1.0, 0.0, 0.0, 1.0] (adds shadow orthogonal dims), item becomes [0.5, 1.0, 1.0, 0.0].
With doubly stable correction, the algorithm imputes the unobserved 0.1 and learns that the shadow dimensions matter.
Next time, BiRoLF predicts close to 0.6, the true reward, because it learned to use the shadow space.

The key point: augmentation trades invisible parameters (the hidden feature dimensions) for visible ones (the shadow basis), so the learning algorithm can fit them even though the true hidden features never appear in the data.

What can go wrong

What can go wrong

Shadow space too small. If the orthogonal complement basis is too low-rank, it cannot represent all hidden patterns. The algorithm needs enough shadow dimensions to span the true hidden feature space.
Doubly stable estimation fails when data is biased. If the data strongly favors certain user-item pairs over others, the doubly stable method's two estimates may both inherit the same bias, and averaging does not cancel it. The algorithm needs diversity in observed pairs.
Learning is slow when hidden structure is large. If hidden features dominate (dh is large), even BiRoLF needs many rounds to disambiguate visible from shadow dimensions. The learning curve is slower than if all features were visible.
Done right. When shadow space is large enough and data is diverse, BiRoLF recovers the bilinear structure and achieves sublinear regret that does not depend on the number of possible user-item pairs, only on effective hidden dimensionality.
What a runnable demo should prove

What a runnable demo should prove

Build a small recommendation simulator: 20 users, 10 items, each with 3 visible features and 2 hidden features. Generate rewards via a true bilinear model that depends on both visible and hidden. Run three algorithms side by side for 500 rounds: (1) a naive bandit that ignores hidden features and learns only from visible ones, (2) a flattened-feature approach (Kronecker product, treating all features as one long list), and (3) BiRoLF with shadow augmentation. Measure cumulative regret (sum of optimal_reward - predicted_reward each round) for each.

regret = sum over all rounds of (best_possible_reward - actual_predicted_reward)

BiRoLF regret should be visibly lower than both baselines, and should remain low even as hidden feature importance grows.
