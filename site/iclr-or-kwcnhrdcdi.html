Natural Language PDDL for Open-world Goal-oriented Commonsense Planning

Bridge symbolic planning and natural language to let robots plan in partially-observed worlds without exhaustively checking every object and action.

Paper explainersAll themesRobotics & Control

Robots must plan in messy, incomplete worlds where they do not know everything upfront and must decide what to look at. Symbolic planning (PDDL) is logically correct but assumes a complete model; language models are flexible but hallucinate. This paper fuses them: NL-PDDL lets robots state goals and actions in plain English, reason about what information they need to sense, and plan over long horizons without checking every possible state.

Zero assumption version

Two broken paths to robot planning

Symbolic planners (like PDDL) work step by step: they list every object, every possible action, and every state the world can be in. They reason perfectly inside their model. But the moment the world has gaps—a robot does not see all the objects, or an action description does not quite match reality—the planner gets stuck. It cannot generalize across different rooms full of different objects without rebuilding the entire model from scratch.

Language models bend the other way: a robot can tell GPT its goal in English, and GPT dreams up a plausible plan. But over a 10-step horizon, GPT starts inventing false steps or forgetting earlier constraints. It never explicitly checks whether the plan actually works or what the robot needs to perceive first.

A robot needs both: the rock-solid logical chain of symbolic planning AND the flexibility of natural language to handle a world that is never fully known in advance.

The dilemma. Symbolic planning is correct but rigid; language models are flexible but unreliable. Neither one decides what the robot must sense before acting.

The algorithm as a flow

What it actually does

Write goal and actions in plain English

Robot receives: goal = 'eat the bread' and actions 'toast the bread', 'retrieve from cupboard'.

Recognize misalignment

NL-PDDL notes that 'eat' and 'toast' are not the same action, but both apply to bread — commonsense fills the gap.

Apply regression planning

Start from goal, work backward: to eat bread, bread must be edible; to make it edible, toast it; to toast it, retrieve it first.

Ask what must be sensed

For each step, method asks: does the robot already know where the bread is? If not, add a 'look for bread' sensing action.

Generate lifted plan

Return a sequence that avoids checking all objects: check for bread, retrieve, toast, eat. Works in different kitchens without respecifying.

What the paper changes

What the paper changes

Instead of a rigid logical model with every object and state pre-written in symbols, the paper lets you write the goal and each action as an English sentence or phrase. The planner then interprets those sentences, fills in common-sense gaps between goal and action, and builds a plan without enumerating all possibilities.

The hidden quantity

Sensing decisions: what the robot must observe

measured quantity  =  Sensing obligations per step

At each step of the plan, the robot faces a choice: proceed with what it already knows, or stop and look at something new? The paper introduces a hidden quantity: for every action, what must be true about the world before the action can succeed? If the robot does not know it is true, the action fails or hallucinates.

The method estimates this by asking: given the current goal and the candidate next action, what properties of objects or environment state does commonsense reasoning say must hold? If the robot has not sensed them yet, add a sensing step. This turns an invisible problem—the robot acting blindly—into explicit decisions: sense before you act.

Why it works

Why it works: three interlocking moves

The method fixes three pieces of the puzzle. First, it represents the goal and actions in natural language, not symbols. This lets non-experts write plans and lets the same action description work in text and vision—a robot can learn 'toast the bread' from a video or a sentence. Second, it uses commonsense reasoning to bridge the gap between what the human asked for ('eat the bread') and what the robot can do ('toast the bread'). Instead of a hard mismatch, the method says: these two are related via commonsense; proceeding is sound. Third, it applies regression planning (work backward from the goal) to figure out what must be sensed. At each step, the method asks: given the world as observed so far, can this action run safely? If a precondition is unknown, add a sensing step. This way, the plan never assumes facts that have not been verified, and it avoids exhaustively checking all objects and states.

Why does it avoid explosion? Classical PDDL must ground every object and state upfront: if there are 100 objects, the planner constructs 100^k state combinations. NL-PDDL works on lifted (abstract) plans: 'get bread from cupboard' stays abstract until execution, so the planner never builds 100-object-sized models. It checks relevance only when needed. This shrinks the search space from exponential in object count to polynomial in plan length.

Math after the picture

The regression-planning equation

First in words:

For each action A and goal G, the plan is valid if all of A's preconditions P_A are either known or can be sensed first. If not known, add sensing step before A.

Then the compact form:

Valid(A, G) = All(p in P_A : observed(p) OR can_sense(p))

Every symbol:

Acandidate next action (e.g. 'toast the bread')
Gthe goal the robot is trying to achieve
P_Alist of preconditions for action A to succeed
observed(p)true if the robot has already sensed fact p
can_sense(p)true if the robot can perceive p (e.g. via camera or touch)
Valid(A, G)true if action A can safely run given observed facts
A tiny worked example: getting toast
Goal: eat the bread. Current observed facts: {robot_in_kitchen, toaster_exists}.
Action A1: 'toast the bread'. Preconditions P_A1 = {bread_location_known, toaster_working}.
Check: observed(bread_location_known)? NO. Call can_sense(bread_location_known)? YES, look in cupboard.
Add sensing step: 'look for bread in cupboard'. Observed facts now: {robot_in_kitchen, toaster_exists, bread_location_known}.
Re-check A1: observed(bread_location_known)? YES. observed(toaster_working)? YES (from earlier observation).
Valid(A1, Goal) = true. Plan proceeds to 'toast the bread'.

The formula encodes the core insight: do not act on a precondition unless you have verified it. If not verified, sense it first.

What can go wrong

What can go wrong

Commonsense knowledge incomplete. If the commonsense KB does not know that 'toast' makes bread 'edible', the method cannot bridge goal and action. The plan fails or the wrong action is chosen.
Sensing action fails or returns unexpected data. Robot tries to look for bread but the camera is dirty, or the cupboard is locked. The method assumes sensing will succeed; if it does not, the plan breaks.
Goal or action descriptions are ambiguous. If 'toast' could mean 'make toast' or 'make a toast (a speech)', the planner might pick the wrong interpretation. NL parsing errors cascade.
Done right: sensing checks are explicit and early. When the method asks 'what must be sensed?' upfront, it catches missing information before the robot fails mid-execution. Long plans remain stable because preconditions are verified as they arise.
What a runnable demo should prove

What a runnable demo should prove

Build a simple robot task in two environments (e.g., a text-based blocksworld where the robot stacks blocks, and ALFWorld, a simulated household with rooms and objects). Write a goal in English: 'make a sandwich'. Write action descriptions: 'get bread from cupboard', 'spread butter', 'put on plate'. Have NL-PDDL generate the plan and measure: (1) does the plan succeed over a longer horizon (8–10 steps) than a baseline language model? (2) when sensing information is missing, does NL-PDDL add a sensing step automatically? (3) does the plan transfer to a new environment (different kitchen layout) without respecifying actions?

Long-horizon success rate = (plans_succeeding_8plus_steps) / (total_8plus_plans)

The demo must show that explicit sensing decisions let the robot act on partial knowledge without hallucinating, and that abstract action descriptions generalize across embodiments (text and vision).
