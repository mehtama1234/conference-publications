Domain Expansion: Multi-Task Learning Without Collapse

Train one network on multiple tasks by giving each task its own separate hallway in the latent space, so they never get tangled together.

Paper explainersAll themesRepresentation & Self-Supervised Learning

When you ask a single neural network to solve multiple tasks at the same time—like identifying what object a photo shows and estimating its 3D pose—the network gets pulled in conflicting directions. The gradients (adjustment signals) for each task fight each other, and the network settles into a compromised middle ground that is weak at both tasks. This paper prevents that collapse by restructuring the latent space itself: each task gets its own separate, perpendicular axis, so their signals never interfere.

What breaks when one network learns multiple tasks

Imagine you build a single neural network to do two things: identify a dog in a photo, and estimate its height. The network learns a shared internal representation (a list of numbers encoding what the image contains). Each task pulls this representation in a different direction during training. The gradients (adjustment signals that nudge the numbers to reduce error for each task) collide, because nudging for task 1 points upward but nudging for task 2 points downward.

The network cannot satisfy both simultaneously, so it gets stuck in the middle: a representation that is mediocre at both tasks. This is called latent representation collapse. Existing methods try to fix this by reweighting task losses or rotating gradients at the time of training, but they do not change the latent space itself—they just adjust how hard to pull each way on an entangled tangle of numbers.

The method in one sentence: Assign each task to its own perpendicular subspace in the latent representation, so gradients for different tasks never collide.

What the paper changes

The one thing the paper changes

The paper restructures the latent space—the list of numbers the encoder creates—from a single muddy tangle into a set of separate, perpendicular subspaces. Each task's gradient updates now affect only its own subspace, leaving the others untouched.

The hidden quantity

The orthogonal axis assignment

measured quantity  =  orthogonality of latent subspaces

The hidden quantity is the degree to which each task's preferred direction in the latent space is perpendicular to all others. In plain terms: if you imagine the latent space as a multidimensional filing cabinet, orthogonality means each task gets its own separate drawer, so pulling out drawer 1 does not disturb drawer 2. The paper measures this by computing eigenvectors (the most important directions) for each task's gradients, then ensuring they are perpendicular to each other.

To estimate orthogonality, the method computes the covariance matrix (a table showing how much each number in the latent representation varies with each other) at each training epoch, extracts its eigenvectors, and assigns tasks to those directions. The Hungarian algorithm (a standard optimization tool) finds the best one-to-one matching between tasks and axes, so no two tasks share a direction.

Why it works

Why it works: the causal chain

Here is the mechanical reason this prevents collapse. During multi-task training, each task's gradient points in a direction that would improve that task's loss by reducing its error. If both tasks share the same latent numbers, their gradients are in different directions—task 1 needs one shape of the representation, task 2 needs a different shape—and they cancel each other out, like two people pulling a rope in opposite directions. The network settles in the middle—suboptimal for both, because it satisfies neither.

The paper breaks this deadlock by measuring the latent space's covariance (how the numbers naturally vary) and extracting its principal axes (the directions along which the most variation happens). Then it assigns each task to a different axis. Because these axes are orthogonal (perpendicular), a gradient update along one axis does not affect the others. Task 1's gradients slide along its axis, Task 2's slide along its own, and they never collide. The latent space becomes internally partitioned.

Why does this partition exist? Because during training, the covariance of the latent features naturally develops directions that are task-specific: the angles and directions that matter most for pose estimation are different from those for classification. The paper simply extracts those natural directions and makes them explicit by routing each task's computation through its own subspace. No task-specific architecture tweaks needed; it is all in the latent space structure.

Math after the picture

The equation

First in words:

For each task m, compute the projection of latent features onto eigenvector v_m, then apply the task's loss to only that projection.

Then the compact form:

L_total = sum over m of L_m(Dec_m(v_m dot F))

Every symbol:

L_mloss function for task m (how wrong the prediction is)
Dec_mdecoder for task m (converts latent features to the output for that task)
v_meigenvector (principal axis assigned to task m)
Fthe latent features (the shared representation from the encoder)
v_m dot Fprojection of F onto the direction v_m (extracting just that task's component)
A tiny worked example
Latent features F = [8, 3, 5, 7] (four numbers encoding the image).
Task 1 (classification) eigenvector v_1 = [1, 0, 0, 0] (focuses on first number).
Task 2 (pose) eigenvector v_2 = [0, 1, 0, 0] (focuses on second number, orthogonal to first).
Projection for task 1: v_1 dot F = 1*8 + 0*3 + 0*5 + 0*7 = 8.
Projection for task 2: v_2 dot F = 0*8 + 1*3 + 0*5 + 0*7 = 3.
Task 1 decoder operates on 8, task 2 decoder operates on 3.
When task 1's gradient nudges component 1, task 2's decoder sees no change because it only reads component 2.

The key is that each task's loss sees only its own projected number, so gradients for different tasks never interfere.

What can go wrong

What can go wrong

Covariance estimation is noisy with tiny batches. If you sample only a few images, the covariance matrix (the estimate of how features vary) becomes unreliable, and eigenvectors jump around. Use large batches or compute over the entire training set periodically.
Adding many tasks uses up the latent space. If your latent dimension is 64 and you have 100 tasks, you run out of orthogonal axes. The latent space must be at least as large as the number of tasks you plan to support.
Eigenvectors can flip direction without warning. An eigenvector for task 1 at epoch 10 might point opposite at epoch 11 (still valid, just flipped). The method uses the Hungarian algorithm to re-align task assignments, but sudden flips can confuse interpretation. The paper measures this using alignment scores (how similar consecutive-epoch directions are) to detect instability.
Done right. Recompute eigenvectors and task assignments dynamically during training, use large enough batches, monitor covariance stability (the paper measures directional alignment between consecutive-epoch eigenvectors to detect flips), and ensure your latent dimension exceeds your task count.
What a runnable demo should prove

What a runnable demo should prove

Build a simple encoder-decoder network trained on two tasks: classifying object type (cat, dog, car) and regressing object rotation angle, both on small images (32x32). Train without orthogonal pooling first, measure the final accuracy on both tasks. Then add orthogonal pooling as the paper describes: at each epoch, compute the covariance of latent features, extract eigenvectors, assign tasks, and project. Run again and measure.
