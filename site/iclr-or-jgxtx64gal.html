FERD: Fairness-Enhanced Data-Free Adversarial Robustness Distillation

When teaching a student model to resist attacks without any real training data, some classes become fragile. FERD fixes this by balancing which classes get more practice and ensuring attacks aim at all classes equally.

Paper explainersAll themesOther

You have a teacher model that resists adversarial attacks (small perturbed images that fool it). You want to teach a smaller student model the same toughness, but you do not have access to the original training data. Existing methods generate fake data to teach the student, but the student ends up fragile on certain classes while strong on others. FERD solves this by adjusting the balance of fake data and the way attack examples are constructed, so every class learns equally strong defenses.

Zero assumption version

Classes learn to resist attacks unevenly

A teacher model trained to withstand attacks (small crafty image tweaks that fool it) is a precious asset. But you cannot ship the teacher itself—it is slow and large. So you want to give a smaller student model the same defense skill. The problem: the original training data is gone or secret. How do you teach the student without it?

A naive approach: generate fake data that matches what the original data might have looked like, then use that to train the student. But this runs into a fairness trap. Suppose the real data had ten classes of animals. If your fake data generator produces data unevenly—more dogs, fewer cats—then the student gets more practice resisting attacks on dogs. When you test the student on cats under attack, it crumbles. The worst-class accuracy (the accuracy on the class that performs worst) plummets. The student becomes a specialist in defending dogs but fragile everywhere else.

The problem. Data-free defense distillation makes some classes strong against attacks and leaves others fragile, because fake data is unbalanced and attacks target vulnerable classes preferentially.

The algorithm as a flow

What it actually does

Step 1: Measure which classes are weak.

Run the fake data generator and student in a loop, checking which classes resist attacks worst.

Step 2: Reweight the generator's output.

Make the generator produce more samples for classes that are still fragile, fewer for strong ones.

Step 3: Generate Fairness-Aware Examples.

Create fake benign images using a uniformity constraint that spreads feature patterns evenly across all classes.

Step 4: Build uniform-target adversarial examples.

When making adversarial attack examples, force each attack to aim at a different target class, not clustering on the weak ones.

Step 5: Train the student on both.

The student practices resisting attacks on rebalanced, diversely-targeted data, learning to defend evenly against attacks.

What the paper changes

What the paper changes

FERD adjusts two things: the amount of synthetic data generated for each class, and how the adversarial attacks are aimed. Instead of treating all classes identically during fake-data generation, FERD feeds back which classes are still fragile and makes the generator spend more effort on them. When building attack examples, instead of letting attacks cluster on easy targets, FERD forces a constraint that spreads attacks uniformly across all classes.

the object it moves  =  Synthetic data balance and attack target spread
The hidden quantity

The hidden quantity: Fragile features per class

measured quantity  =  Class-wise fragile feature activity

A fragile feature is a pattern in the input that the model relies on to make predictions, but an adversary can flip by tiny tweaks. Unlike solid features, which are tied to real physical properties (texture, shape), fragile features are brittle shortcuts. Certain classes tend to rely on fragile features more than others. If a fragile feature is very active in class cats but rare in dogs, then attacks on cats will exploit it easily, leaving cats defenseless.

FERD measures how concentrated fragile features are in each class by enforcing a uniformity constraint on feature-level predictions: it pushes the model so that predictions from fragile features do not cluster in just a few classes. When predictions are spread evenly across all classes, no single class becomes a soft target.

Why it works

Why rebalancing synthetic data and attacks stops fragile classes

Here is the causal chain. When you generate synthetic data uniformly (same number per class), but attacks are not uniform, the model gets more practice resisting attacks that tend toward certain classes. Those classes become strong. Other classes, attacked less often, stay weak. FERD breaks this feedback loop in two places.

First, reweighting: after testing, FERD measures which classes defend worst and tells the data generator to make more samples for those classes. More samples means more attack attempts on those weak classes during training, so they get extra practice.

Second, uniform-target attacks: instead of letting the attacker pick whichever class is easiest to fool, FERD constrains the attack to cycle through all classes as targets equally. This removes the attacker's ability to cherry-pick the weakest class. Now every class faces attacks aimed deliberately at it.

Together, these two changes mean every class gets both balanced training data and balanced attack pressure. The weaker classes, which used to be attacked disproportionately, now get the extra practice data and also face more attacks aimed directly at them, which trains them harder. The result is that all classes converge to similar defense levels.

Math after the picture

The reweighting equation

First in words:

For each class, compute the defense loss under adversarial attacks, weight the loss by inverse defense strength so that weaker classes get more samples, and add a uniformity term that penalizes concentration of fragile predictions.

Then the compact form:

L_fairness = sum_c w_c * L_defense_c + lambda * KL(P_fragile, Uniform)

Every symbol:

w_cweight for class c, higher if class c is weak
L_defense_chow much adversarial loss class c experiences
lambdaa strength dial for the uniformity penalty
P_fragilepattern of how fragile predictions spread across classes
Uniformthe flat pattern (each class equally likely)
KL(..., ...)a measure of how different two patterns are
A tiny worked example
Suppose 3 classes: dogs, cats, birds.
Dogs have defense loss 0.2 (strong). Cats loss 0.6 (weak). Birds loss 0.5 (medium).
Inverse defense: dogs w=1/0.2=5.0, cats w=1/0.6=1.67, birds w=1/0.5=2.0.
Cats now get weight 1.67, highest, so generator makes most samples for cats.
Uniform term checks: fragile predictions should not be e.g. 50% dogs, 10% cats, 40% birds.
If they are, KL penalty pushes them toward 33%, 33%, 33% instead.
Result: cats get extra data and attacks; defense strength equalizes.

The weights and uniformity term work together: reweighting ensures weak classes see more data and attacks, while the uniformity constraint ensures that fragile features are spread evenly so no class becomes a preferred fallback for adversarial tweaks.

What can go wrong

What can go wrong

Reweighting goes too far. If you make weak classes dominant in synthetic data (all dogs, barely any cats), the student stops learning cats and the fairness goal flips—now cats are vulnerable. The reweighting must be modulated, not extreme.
Uniformity constraint is too loose. If the penalty for concentrating fragile predictions is too weak, the constraint does not bite and classes still cluster. The lambda dial must be set so that spreading features across classes actually costs the generator.
Uniform-target attacks become predictable. If the generator learns that attacks will always cycle through classes in order, it might overfit the order and prepare disproportionately for the first class in the cycle. The attack target constraint must be randomized, not mechanical.
Done right. When reweighting is gentle, uniformity is enforced firmly, and attacks are truly randomized, all classes learn toughness proportionally and worst-class defense stays high.
What a runnable demo should prove

What a runnable demo should prove

Implement a tiny image classifier (e.g., three-class MNIST subset: 0, 1, 2) with a teacher that defends against attacks and a student. Build a data-free generator. Train the student on uniform fake data with no class reweighting and random attack targets (baseline). Measure the test accuracy under adversarial attack for each class and report the worst-class accuracy. Then train a second student with FERD: reweight the generator to favor whatever class underperforms in step 1, and force attack targets to cover all classes. Measure again. The demo must show that worst-class accuracy rises by a large amount, even if overall average dips slightly.

worst_class_accuracy = min(accuracy_class_0, accuracy_class_1, accuracy_class_2) under FGSM attack

The demo must make clear that FERD trades off a tiny bit of average defense to buy much larger gains in the class that would otherwise fail completely.
