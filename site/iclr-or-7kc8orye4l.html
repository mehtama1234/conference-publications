Risk-Sensitive RL for LLM Exploration

A method that rewards hard math problems more than easy ones, making language models explore diverse reasoning paths instead of repeating the same solution over and over.

Paper explainersAll themesLLMs & Foundation Models

Language models trained with reward feedback (where a human labels right vs wrong answers) face a trap: they get very good at one solution style but stop trying new approaches. This paper flips the reward signal to favor hard problems, forcing the model to keep exploring and finding multiple ways to solve the same question. Hard problems have no known solution path, so solving them requires the model to invent new strategies—and it keeps those strategies even for easy problems.

The exploration trap in LLM training

When you train a language model using rewards (a score saying if an answer is right or wrong), the model quickly learns its pre-trained style of answering. It finds one solution path that works and sticks to it. If you ask the model for five different solutions to the same math problem, it tends to give you five almost-identical attempts with tiny variations.

A naive approach would be: train the model so it is really good at finding a single correct answer fast. But this backfires. When you ask for multiple solutions (pass@k: what fraction of your top-k tries are correct), the model fails because it only knows one route. The model is trapped in a local peak: very good at pass@1 (single answer), terrible at pass@k (multiple answers).

The dilemma: Standard reward-based training teaches the model one solution path and builds a wall around it; the model stops exploring because the peak-finding forces all probability mass onto the same strategy.

What it actually does

Identify the problem difficulty

For each math problem, measure how many model attempts fail.

Adjust the reward by difficulty

Reward gets higher when the problem is hard (many attempts fail).

Bias training toward hard problems

Model learns to spend effort on questions that challenge it.

Because hard problems require new strategies, model discovers alternatives.

What the paper changes

What the paper changes

The paper moves the reward signal itself: instead of giving equal credit for solving any problem, it gives higher credit for solving hard ones. This is not changing the numbers inside the model; it is changing which examples the training focuses on.

the object it moves  =  Reward weighting by problem difficulty
The hidden quantity

Exploration diversity

measured quantity  =  Solution path diversity

The hidden quantity the paper tracks is how many different strategies the model is using to solve problems. When the model only knows one solution path, this number is 1. When it learns five different ways to solve math, it is 5 or higher.

The paper measures this by looking at multi-answer performance (pass@k) and comparing it to single-answer performance (pass@1). A big gap between pass@1 and pass@5 means the model is only using one strategy; a small gap means it found many.

Why it works

Why the method works

The model's behavior is fundamentally shaped by what it is rewarded for. When every correct answer gets the same reward (1 point), the model's training algorithm (gradient descent) says: push all probability toward whichever path succeeds first. It is a race to the bottom for the single fastest route.

When you flip the reward so hard problems pay more, the training algorithm now says: spend energy on examples that are still failing. Hard problems are failing more often (the model has not yet learned a reliable strategy for them), so training pulls the model toward those examples. Solving a hard problem requires a new strategy, because the old one does not work there. Gradually the model learns multiple solution paths, one for easy problems (the original path) and others for hard ones.

The paper carefully balances this: it weights rewards high enough to drive exploration but not so high that the original solution disappears. Because the model holds onto all its learned strategies, pass@1 stays strong (the original path is still there) and pass@k improves (the new paths work too).

The equation

First in words:

Risk-seeking objective = (1 - alpha) * average-reward + alpha * maximum-reward, where alpha is how much to favor the hardest problems.

Then the compact form:

RS-obj = (1 - alpha) * E[R] + alpha * max(R)

Every symbol:

RS-objThe risk-seeking objective (reward including the bonus for hard problems)
alphaA number between 0 and 1 that controls how much to favor hard problems (high alpha means explore more)
E[R]Average reward across all problems (treat easy and hard the same)
max(R)Maximum reward possible (focus on the hardest problems only)
alpha = 0Standard training, all problems equally valued
alpha = 1Only hardest problems matter
A tiny worked example
Six problems: [easy, easy, medium, medium, hard, hard].
Rewards: [1.0, 1.0, 0.8, 0.8, 0.5, 0.5]. (Hard problems fail more, lower reward.)
Standard training: average = (1+1+0.8+0.8+0.5+0.5)/6 = 0.783.
Hard problems get zero gradient push because they are below average.
With risk-seeking (alpha=0.5): RS-obj = 0.5*0.783 + 0.5*1.0 = 0.892.
Now the objective pulls toward BOTH average (0.783) AND the max (1.0, the easy problems).
But hard problems have room to improve (0.5 is far from 1.0), so training focuses there first.
After learning a new hard-problem strategy: rewards become [1.0, 1.0, 1.0, 1.0, 0.9, 0.9].
New average = 0.967. Pass@5 is now higher (more diverse solutions work). Pass@1 stays 1.0.

The risk-seeking blend pulls training toward examples that are not yet solved, which forces the model to invent new strategies.

What can go wrong

What can go wrong

Alpha too high breaks single-answer performance. If you weight hard problems too heavily, the model forgets its original good strategy in pursuit of new ones. Pass@1 collapses. The fix is carefully tuning alpha, usually 0.3 to 0.7.
Difficulty estimate is wrong. If you label a problem hard when the model actually solves it easily, or easy when it is genuinely hard, the method gives the wrong reward. Incorrect labels make training noisy.
Problem set has no hard examples. If all problems are easy, there is nothing to explore into. The method only works when the benchmark has a range of difficulties.
Done right. Measure problem difficulty from the base model before training starts, tune alpha by testing on a small validation set, and confirm pass@1 does not drop before shipping.
What a runnable demo should prove

What a runnable demo should prove

Build a small language model (e.g., a 125-million-parameter transformer) and train it on a subset of 200 arithmetic problems (50 single-digit, 50 two-digit, 50 three-digit, 50 very hard multi-step). First, train with standard rewards for 1000 steps and record pass@1, pass@5, pass@10. Then, reset and train the same model with risk-seeking rewards (alpha=0.5), measuring difficulty from how often the base model fails. Plot the two learning curves on the same graph. The demo succeeds if pass@5 and pass@10 are notably higher in the risk-seeking version with no loss in pass@1.

diversity-gain = (pass@5-risk - pass@5-standard) / pass@5-standard * 100 percent, keeping pass@1-risk > 0.95 * pass@1-standard

The graph makes it impossible to miss: one line (standard reward) has pass@5 stuck low while pass@1 is high, because the model only knows one path. The other (risk-seeking) has pass@5 and pass@1 both strong, because the model kept all its original paths and added new ones learned from hard problems.
