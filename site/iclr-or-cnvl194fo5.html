Local Cross-Variate Modeling for Time Series

Instead of looking at all variables at once (slow), just look at nearby variables at each moment (fast), and you get better accuracy.

Paper explainersAll themesTime Series & Sequential

When you have many measurements changing together — like wind speed, temperature, and pressure at a weather station — you need to predict what comes next. Old methods look at every variable paired with every other variable, which gets impossibly slow as the number of variables grows. This paper uses a new model that looks only at nearby variables, skipping distant ones entirely, and achieves better accuracy in 100 times less compute because local patterns are simpler than global ones.

Zero assumption version

Old methods check every pair of variables, which is slow

With many measurements (variates), old methods use attention (a technique that learns which measurements matter for each other at each moment) to compare every variable to every other variable at each moment in time. With 300 variables, that is 90,000 pairs to check at each moment. Do this 1,000 times a day for a year, and your computer must perform trillions of operations. Many real-world systems have hundreds or thousands of variables, making the method impractical.

For instance, a weather prediction system with 300 variables would need to compute 90,000 scores (one for each pair) many times over. As you add more variables, this cost explodes: 1000 variables would require checking 1 million pairs at each step. The compute cost grows quadratically — doubling the variables makes the work four times harder.

The method. VPNet avoids checking every pair by rearranging variables and time into a 2D grid, then using sliding-window filters that only touch nearby grid cells. This cuts the compute cost from growing quadratically to growing linearly.

The algorithm as a flow

What it actually does

Chop time into patches

Break each variable's history into overlapping chunks (e.g., 7-day windows).

Compress each patch

An autoencoder squeezes each 7-day chunk into a dense code (a list of numbers).

Arrange into a grid

Stack all variables' codes into a 2D table: rows are variables, columns are time patches.

Slide local filters

Convolutional layers sweep 3x3 windows across this grid, each window seeing a few variables and a few time steps.

Predict future patches

Each variable's row predicts the next time patch, then an autoencoder decoder expands it back into the full time domain.

What the paper changes

What the paper changes

The paper replaces the attention mechanism (which looks at all pairs) with a 2D convolution (which looks at small rectangles in a grid of variables and time).

The hidden quantity

The hidden quantity: local dependency rank

measured quantity  =  Local dependency rank

The paper measures how many distinct neighboring variables actually matter for predicting each variable. In a weather station, predicting wind speed probably depends on temperature and pressure nearby, but not on humidity three buildings away. This number — how many nearby neighbors you truly need — is the hidden quantity.

VPNet estimates this by checking: when you train only on local patches (3x3 windows), do predictions stay as accurate as looking globally? If yes, the rank is small, and local modeling wins. The paper finds this rank is small for most real-world datasets.

Why it works

Why looking only at neighbors works better and runs faster

In most real systems, what happens to one measurement is driven by measurements nearby in the list, not by distant ones. For example, wind speed depends on air pressure and temperature right around it, not on humidity far away in the variable order. By restricting each variable to look at only its neighbors, you shrink the number of pairs from 90,000 down to maybe 300. The paper proves empirically that this restriction does not hurt accuracy; in fact, it often improves it because the model focuses on the true causes and ignores noise from distant variables.

Second, the paper rearranges variables and time patches into a 2D grid, then uses sliding-window filters (called convolutions in machine learning) to sweep across this grid. Sliding-window operations are a basic primitive that graphics processors (GPUs) were specifically designed to optimize. Checking every pair, by contrast, requires custom hand-written code with no shortcuts. So even if the local approach checked the same number of pairs, it would still be faster because GPUs have built-in fast paths for sliding-window operations. Together, these two factors — fewer pairs plus hardware optimization — deliver 100x speedup.

The efficiency gain

First in words:

For a grid of M variates and T time patches, global attention costs M squared times T squared operations. Local convolution with window size W costs about M times T times W squared operations.

Then the compact form:

Attention: O(M^2 * T^2); Local Conv: O(M * T * W^2), where W ~ 3 or 5

Every symbol:

Mnumber of variables (variates)
Tnumber of time patches
Wconvolution window width (e.g., 3 or 5)
O(...)how the cost grows as M, T, W change
A concrete example
Suppose 100 variables (M=100) and 1000 time patches (T=1000), window size W=3.
Attention cost: 100^2 × 1000^2 = 10 billion operations.
Local convolution cost: 100 × 1000 × 3^2 = 900,000 operations.
The convolution is about 10,000 times faster on this system.

Scaling linearly with variables (M) instead of quadratically makes the method practical for real systems with hundreds or thousands of measurements.

What can go wrong

What can go wrong

Variables that depend on distant neighbors. If variable A's behavior is driven by variable Z on the other side of the system, local attention misses this. The paper assumes most dependencies are local, which is not true everywhere.
Patch size tuning. If patches are too short, you lose long-term patterns. Too long, and you waste computation. The method requires picking the right size, which varies by dataset.
Boundary effects. Variables at the edge of the variate ordering see different neighbors than those in the middle, which can create bias.
Works well on local systems. For datasets where dependencies truly cluster nearby (weather, sensors, power grids), VPNet wins on speed and accuracy both.
What a runnable demo should prove

What a runnable demo should prove

Build a simple experiment: generate a synthetic time series with 20 variables where each depends only on its 3 nearest neighbors (e.g., variable 5 depends on 4, 5, 6). Train attention and VPNet. Measure accuracy and runtime. Then scale to 200 variables and repeat. The demo should show that attention's runtime grows dramatically while VPNet's barely changes.
