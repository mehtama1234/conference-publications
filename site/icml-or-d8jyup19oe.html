Topological Active Inference for Task Disambiguation

When a user's instructions are unclear, ask fewer, smarter clarifying questions by seeing the real semantic intent clusters hiding among many possible interpretations.

Paper explainersAll themesAgents & Tool Use

Natural language instructions are often vague — a single request can mean many different things. Large language models (LLMs) are good at generating text, but when they need to ask a human clarifying questions to pin down what you actually want, they often ask the wrong ones: they distinguish between trivial rewording (same intent, different words) rather than the real intent forks (different things). This paper proposes a geometric method to see which intent clusters are truly distinct, then asks only the questions that separate them.

Zero assumption version

Asking the wrong clarifying questions

A user says to a large language model: generate code for a data filter. That instruction maps to dozens of valid programs: filter by date, filter by category, filter rows vs columns, use loops vs built-in functions. Each is correct for some intent.

The naive approach: the model samples all plausible interpretations and asks the user to pick. But it often asks useless questions. It might ask, Should I use a for-loop or list comprehension? when the user's real intent fork is whether to filter rows or columns. These are different things: one asks about style (both mean the same thing), the other asks about meaning (they mean different things). The model conflates them.

The paper's move in one sentence. Identify the true semantic clusters (the distinct intents) from many sampled solutions, then ask only questions that separate those clusters.

The algorithm as a flow

What it actually does

Sample solutions

Generate many possible programs or outputs that match the vague instruction.

Find semantic clusters

Use a topology method (persistent homology) to detect which solutions are truly alike in meaning, grouping them into intent clusters.

Plan clarifying questions

Synthesize questions that separate the clusters — questions whose answers would push the user toward one cluster vs another.

Score questions by information gain

Rank questions by how much they shrink the space of possible intents; pick the one that cuts most evenly.

Iterate with user feedback

User answers one question, intent space shrinks; repeat until one cluster remains and intent is clear.

What the paper changes

What the paper changes

The paper changes how clarifying questions are chosen. Instead of picking questions that distinguish individual sampled solutions, it picks questions that separate intent clusters — the distinct, persistent semantic meanings hiding in the batch of solutions.

the object it moves  =  clarifying question selection method
The hidden quantity

The hidden quantity: intent-cluster separation

measured quantity  =  Semantic cluster boundary sharpness

The paper measures something that does not exist until you look: which sampled solutions truly cluster together (same intent, different words) versus which ones sit at the boundary between intents (different meanings). It detects this using persistent homology, a topology method that looks at how solutions cluster as you gradually tighten the distance threshold. If two solutions stay in the same cluster across a range of thresholds, that cluster is persistent — it is a real intent. If they only touch at one threshold, the boundary is noise.

The paper uses this hidden quantity in two ways: (1) to measure how well a clarifying question separates the clusters (does it split persistent clusters cleanly, or just rearrange noise?), and (2) to measure when the user has clarified enough (when only one persistent cluster remains).

Paper reading. Persistent homology tracks how the topology (the connectivity structure) of the solution space changes as distance threshold varies. A cluster is persistent if its homology class survives across a wide range of thresholds. Intent clusters are exactly these persistent structures; they remain unchanged by small shifts in how you measure similarity.
Why it works

Why asking about intent clusters is smarter

Clarification reduces uncertainty. Each yes-or-no question the user answers cuts the space of possible intents roughly in half. If you ask about things that do not split the space (for-loop vs list comprehension when both mean the same thing), you waste a turn and learn nothing about which intent the user wants.

The paper's move: instead of asking random distinguishing questions, ask only about cluster boundaries. A boundary question is one where yes-answers lean toward cluster-A and no-answers lean toward cluster-B. When you ask such a question, every user answer strictly reduces the set of live intent clusters. There is no wasted turn. This converts many confused turns into logarithmic scaling (roughly log-base-2 of the cluster count).

Math after the picture

The information-gain equation

First in words:

Topological Expected Information Gain (TEIG) measures how much a question reduces the entropy (uncertainty) over the K intent clusters. A question gets a high TEIG if its answer strongly correlates with which cluster the user is in.

Then the compact form:

TEIG = sum_c p(c) * sum_a p(a|c) * log(p(c|a) / p(c))

Every symbol:

cone of the K intent clusters
aan answer to the clarifying question (yes or no)
p(c)probability the user is in cluster c (before the question)
p(a|c)probability the answer is a given cluster c
p(c|a)probability cluster c given answer a (after the question)
log(...)information (in bits)
A tiny worked example
Two clusters: cluster-1 has 40 percent chance, cluster-2 has 60 percent chance.
Question: Do you want rows (R) or columns (C)?
In cluster-1: 90% say R, 10% say C. In cluster-2: 5% say R, 95% say C.
If user says R: posterior p(cluster-1|R) = 0.9 * 0.40 / (0.9 * 0.40 + 0.05 * 0.60) = 0.36 / 0.39 = 92%.
If user says C: posterior p(cluster-2|C) = 0.95 * 0.60 / (0.10 * 0.40 + 0.95 * 0.60) = 0.57 / 0.61 = 93%.
Both answers sharply split the clusters; this question has high TEIG.
Contrast with for-loop vs list comp (both in cluster-1): either answer leaves you still in cluster-1; TEIG = 0.

The formula says: a good question is one where knowing the answer tells you which cluster you are in; a bad question is one where both answers are possible in all clusters.

What can go wrong

What can go wrong

The model cannot synthesize good clarifying questions. Persistent homology tells you where to cut, but the model still has to write the actual question. If the model's language generation is weak, even a geometrically perfect question selection will fail. The question might be nonsensical or not actually separate the clusters in practice.
Intent clusters are not well separated. If multiple intents overlap heavily or the sampled solutions do not cover the intent space densely, persistent homology may fail to detect the true clusters. The method assumes the intent clusters have some geometric separation in the solution space.
User feedback is noisy or adversarial. The method assumes user answers honestly signal which cluster they are in. If users answer randomly, misunderstand the question, or the feedback channel is noisy, the probability distribution over clusters (which cluster the user is in) may not narrow correctly.
Done right: cluster boundaries are clear, questions are well-phrased, and user answers are honest. Under these conditions, each question cuts the intent space roughly in half, reaching single-cluster certainty in logarithmic turns.
What a runnable demo should prove

What a runnable demo should prove

A concrete demo should: (1) Start with a vague instruction (e.g., generate code to filter data). (2) Use the method to sample 10-20 candidate programs. (3) Compute the persistent homology and identify, say, 3-4 intent clusters (filter rows vs columns, loop-style vs functional, csv vs database). (4) Generate a clarifying question that separates two of the clusters. (5) Simulate a user answer; shrink the intent space. (6) Repeat for 2-3 rounds until one cluster dominates. (7) Output the final program and measure: How many questions did it take? How many false clusters were eliminated per turn?

turns_to_single_intent = count of clarifying questions asked before posterior probability of one cluster exceeds 90%

The demo must make it impossible to miss the core truth: asking about cluster boundaries cuts the confusion space sharply, while asking within-cluster questions wastes turns.
