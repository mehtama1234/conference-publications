Cross-ControlNet: Fusing Multiple Conditions

Merge multiple spatial conditions in image generation without retraining, by fusing features based on how strong each condition signal is.

Paper explainersAll themesGenerative Models & Diffusion

Text-to-image models like DALL-E and Stable Diffusion let you give a picture two instructions at once: a sketch here, a pose there. But telling the model to obey both at once usually fails — it rewrites the weights by hand for hours or trains the whole thing from scratch. Cross-ControlNet fixes this without any retraining, by learning to blend the condition signals together based on how loud each one is.

The multi-condition trap

A text-to-image diffusion model is a machine that draws pictures from words. You feed it a description (sketch + pose + lighting), and it fills in the details. But here is the trap: the model was trained on pairs of (words, finished pictures). It does not know how to balance multiple spatial constraints at the same time.

A naive attempt: crank the strength knob for the sketch condition to 10 and the pose condition to 10. The result is usually a garbage picture that satisfies neither — the model flails, contradicts itself, erases details. The second approach is worse: hire engineers to manually tweak the weights of the condition branches until the picture looks right. This takes hours and only works for ONE combination of conditions.

In one sentence. The model gets confused when you force it to obey two spatial instructions at once, because it has no way to measure how strong each signal really is.

The algorithm as a flow

What it actually does

Measure strength

For each condition branch, compute how much the feature values vary across pixels and channels.

Smooth the strength map

Blur the strength signal with a soft Gaussian filter to ignore early noisy stages.

Fuse pixel by pixel

At each pixel, weight the condition features by their measured strength and blend them.

Fuse channel by channel

For each channel in parallel, use a consistency ratio gate to decide whether to keep it or discard outliers.

Inject aligned focus masks

Use text-derived focus masks (learned look-up patterns) to separate foreground and background key-value pairs so conditions do not interfere.

What the paper changes

What the paper changes

The paper changes how intermediate learned numbers (called features) from different condition branches are combined together. Instead of treating all condition branches as equally important, it learns to weight each one by how confident its signal is.

the object it moves  =  Feature fusion strategy
The hidden quantity

The signal strength: variance as a confidence measure

measured quantity  =  Condition signal strength

Cross-ControlNet measures the strength of each condition by computing the variance (how spread out the numbers are) in each learned number list (a feature). A condition that produces very similar values everywhere is weak or noisy. A condition that produces wildly different values at different pixels is strong and confident.

The paper uses two types of variance: spatial variance (how much features differ across pixels in the image) and channel variance (how much features differ across the individual number dimensions). This tells the model which part of its learned output is actually focused on the condition and which part is just random noise.

Why it works

Why it works: three fusion layers

Each condition branch produces a set of feature vectors — intermediate activations (learned numbers) that encode what the condition is trying to communicate. When two branches produce features at the same location in the image, they might agree, disagree, or one might be shouting while the other whispers.

Cross-ControlNet fuses them layer by layer. First, PixFusion blends features pixel by pixel, using the smoothed variance map as a weight: high variance means confident, so lean hard into that feature; low variance means noise, so average it down. Second, ChannelFusion goes into each learned number dimension separately and uses a consistency gate: if the two branches agree on that dimension, keep it; if they fight, dampen the conflict. Third, KV-Injection separates key-value lookup patterns for foreground and background using masks derived from the text prompt, so a sketch condition does not accidentally overwrite the pose condition's focus patterns. The result is three independent decisions about how to blend, each preventing a different kind of collision.

Math after the picture

One real equation for pixel-level fusion

First in words:

The fused feature value at a pixel is the first condition's feature times its smoothed strength, plus the second condition's feature times its smoothed strength, all divided by the sum of the strengths so they add up fairly.

Then the compact form:

F_fused = (s1 * F1 + s2 * F2) / (s1 + s2)

Every symbol:

F_fusedthe blended feature value at this pixel
F1the feature value from the first condition (e.g. sketch)
F2the feature value from the second condition (e.g. pose)
s1the smoothed variance (strength) of the first condition, Gaussian-blurred
s2the smoothed variance (strength) of the second condition, Gaussian-blurred
A tiny worked example at one pixel
Suppose the sketch condition produces feature value F1 = 80 at this pixel, and its smoothed variance is s1 = 0.8 (high confidence).
The pose condition produces feature value F2 = 20 at this pixel, and its smoothed variance is s2 = 0.2 (low confidence).
Fused = (0.8 × 80 + 0.2 × 20) / (0.8 + 0.2) = (64 + 4) / 1.0 = 68.
The fused value 68 is close to 80 because the sketch signal is stronger. The pose did contribute (pulled it down from 80 to 68), but not equally.

The smoothed variance acts as a confidence dial; higher variance means the model is more sure about this condition, so it leans harder into that branch's feature.

What can go wrong

What can go wrong

Two equally loud conditions that truly contradict. If the sketch asks for a shoe shape and the pose asks for a completely different shoe, and both produce high variance, the fusion will average them into an ugly in-between. The framework cannot read intent; it only reads signal strength.
Noisy conditions fool the variance measurement. If a weak condition produces random noise with accidental high variance, the framework will trust it too much. This is rare but possible if the model was poorly trained on that condition.
Early-stage noise. The first few steps of diffusion generation are pure noise. Measuring variance on raw early features is unreliable. That is why the Gaussian smoothing is critical — it ignores early stages.
Done right. If conditions are complementary (sketch and lighting, not shape and anti-shape) and the fusion correctly measures their strength, the method works with no retraining.
What a runnable demo should prove

What a runnable demo should prove

Build a text-to-image diffusion pipeline (e.g. Stable Diffusion 1.5 with ControlNet branches). Add one sketch condition and one pose condition. Without Cross-ControlNet, sample 10 images with both conditions enabled at equal strength. Measure how often the final image actually respects both constraints (e.g. a human rates if the pose is correct and the sketch shapes match). Then apply Cross-ControlNet fusion and repeat. The demo proves that variance-guided fusion saves the image quality when conditions compete, because it stops the model from averaging conflicting signals into garbage — instead it trusts whichever condition is sending a stronger, more confident signal.

Condition compliance = (images where sketch is honored) / (total images) × 100%. Repeat for pose and compute average.

The key moment is sampling a single image with two conflicting conditions applied at equal strength: before Cross-ControlNet it looks broken, after it looks coherent and follows both.
