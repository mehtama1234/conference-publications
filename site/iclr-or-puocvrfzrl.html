DyGRASP: Temporal Reasoning on Evolving Graphs with Text

A method that pairs fast recent-text memory with slow long-term semantic change to reason over graphs where nodes and their labels evolve over time.

Paper explainersAll themesGraph & Geometric Learning

Graphs in the real world change: social networks grow, text descriptions shift. Existing methods read graphs as frozen pictures or apply language models to billions of words inefficiently. This paper splits the task into two jobs: keep a recent window of the last few text interactions (fast), and separately infer how a node's overall character drifts over months (slow). Combining both lets the model answer questions like which person or product a new interaction should reach.

Zero assumption version

The graph won't stop changing, and text keeps piling up

Real-world graphs are alive: people connect and reconnect, products get new reviews, emails pile up in a thread. Each edge comes with text—a message, a reason, a comment. A naive approach treats the graph as a still photo and runs a graph neural network (a model that learns by passing messages between neighbors). This breaks because it ignores time: it cannot tell the difference between something that happened yesterday and something from a year ago. A second naive approach reads all the text with a large language model (a machine that understands English and can reason). This breaks because there is too much text: a node with thousands of interactions generates millions of words, and reading them all is too slow.

The problem is a squeeze: treat time as irrelevant and you lose the story; treat every word equally and you drown in computation.

The paper's move: Split the thinking: use a small sliding window to catch recent, fresh interactions (fast), and separately measure how a node has evolved (slow), then merge both signals.

The algorithm as a flow

What it actually does

Keep a recent window

Extract the last N interactions' text for each node; ignore older history.

Read recent text fast

Use a lightweight encoder (graph neural network) to summarize this window into a vector (a list of numbers).

Measure long-term drift

Run a separate reasoning pass with prompts asking how this node's semantics have evolved; encode the answer into a vector.

Fuse both signals

Combine recent vector and drift vector via a learned merge layer; the model learns when to trust short-term or long-term.

Predict the link

Score which destination node fits best given the merged representation.

What the paper changes

What the paper changes

The paper changes how a graph neural network decides what information to read from text. Instead of looking at all text equally, it routes only the recent window through the fast path and separates long-term semantic drift into a side channel.

the object it moves  =  Text routing: recent vs. global
The hidden quantity

Temporal semantic drift: how much a node's meaning has shifted

measured quantity  =  Semantic drift (node-level character evolution)

Every node has a meaning that can shift: a person's role on Twitter changes from follower to creator to advertiser, or a product's character evolves from niche to mainstream to legacy. The paper names and measures this as semantic drift: the distance between who or what this node was and who it is now.

The paper estimates drift by running an explicit reasoning step: it prompts a language model to describe the node's role or meaning at past time steps, then at the present, then measures how much the description changed. By computing drift in a separate path, the model can learn to weight it differently across the graph: nodes with stable roles might get low drift weight, while nodes that changed function might get high drift weight, because only the path that computes drift can recognize and adjust for these differences.

Why it works

Why splitting recent and global works

The core idea is a division of labor: recent interactions carry noise but signal; old interactions carry signal but are buried in volume. By using a small sliding window (recent path), the model sees the freshest context without reading millions of words. By running explicit reasoning (global path), the model captures how the node's fundamental character or topic has drifted, which is a signal that does not fade even if no interaction happened today.

Consider a product node that was technical (old buyers asked about specs). Now it is mainstream (new buyers ask about price and availability). The recent window will naturally fill with price-related messages. The global reasoning path separately infers the drift from technical to mainstream. When these are merged, the model learns that this node's semantic shift is as important as the immediate text. This saves computation because the language model processes the drift once per node per update cycle instead of re-inferring it from every recent message: fewer words to read means faster answers, so the model becomes practical for real-time systems.

Math after the picture

The merging equation

First in words:

final_representation equals short-term_vector times short_weight plus long_term_vector times long_weight, where the weights are learned numbers that the model adjusts during training

Then the compact form:

rep_final = w_s * vec_recent + w_l * vec_drift

Every symbol:

rep_finalthe merged representation, a vector used for prediction
vec_recentthe short-term vector from the sliding window and graph neural network
vec_driftthe long-term vector from explicit semantic reasoning
w_sthe learned weight for short-term signal (how much to trust recent interactions)
w_lthe learned weight for long-term signal (how much to trust drift inference)
A tiny worked example
Suppose vec_recent = [0.8, 0.3] (high recent activity in one feature, low in another).
Suppose vec_drift = [0.2, 0.9] (high long-term shift in the second feature, low in the first).
Training learns w_s = 0.6 (trust recent moderately) and w_l = 0.4 (trust drift somewhat).
rep_final = 0.6 * [0.8, 0.3] + 0.4 * [0.2, 0.9] = [0.48, 0.18] + [0.08, 0.36] = [0.56, 0.54].
Result: both features end up moderate, neither path dominates alone.

The equation is learned, not fixed; the model adjusts the short-term weight and long-term weight so the merge weights each signal fairly.

What can go wrong

What can go wrong

Window too small. If the sliding window is too short, the model misses important recent context. Choosing the right window size depends on how often nodes interact.
Drift reasoning uses stale LLM. If the language model running the explicit reasoning is old or miscalibrated, it will infer wrong drift. The global path is only as good as the prompts and the LLM quality.
Merge layer overfits to the training graph's pattern. The learned weights for short-term and long-term are tuned to the training graph. If the test graph has a very different pattern of recent-vs-global changes, the merge may weight the wrong signal.
Done right: adapt window size to dataset. Choose the window size experimentally for each graph type; check that both recent and drift paths actually change the final prediction score.
What a runnable demo should prove

What a runnable demo should prove

Build a small dataset: a graph with 100 nodes, each with 20 time steps and 3 text messages per step. Implement a simplified DyGRASP: extract the recent window (last 2 messages), encode it with a small graph neural network, separately compute a hand-crafted drift score (e.g. vocabulary difference between old and recent text), merge the two, and predict the next node. Compare against a baseline that reads all text equally. Show that the window-based method is faster because it avoids processing thousands of old messages, and more accurate because the separate drift computation captures semantic shift that individual messages do not expose.

accuracy = number_of_correct_predictions / total_predictions

The demo must make clear that splitting recent (fast, noisy) from global (slow, stable) is faster because it avoids re-reading old messages and cleaner because each path is optimized for its own time scale.
