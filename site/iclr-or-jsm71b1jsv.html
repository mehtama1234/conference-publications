CH-BatteryGen: Real-World EV Battery Fault Diagnosis Dataset

A large-scale dataset of real electric vehicle battery data with automatically-generated fault labels enables machines to learn which operational patterns signal real faults.

Paper explainersAll themesDatasets & Benchmarks & Evaluation

Electric vehicles rely on batteries that can fail in ways that hurt safety and performance. Today, detecting battery faults depends on manual inspection and lab tests—slow and expensive. This paper builds a dataset of 1000 real vehicles' charging and discharging patterns, labels which ones show faults (low charge capacity, high internal resistance, self-discharge), and uses machine learning to automatically spot the pattern. The trick: it mixes truly measured data from vehicles with synthetic data (generated by a physics-based model) to get enough examples of rare fault types.

Zero assumption version

Why existing battery data falls short

An electric vehicle battery is safe or dangerous depending on its internal state: how much charge it can hold, how much resistance slows the current, whether it slowly drains even when parked. Today, engineers measure these states rarely—at the dealership or lab—using expensive equipment. In the real world, thousands of charge cycles happen, and faults can hide for a long time before symptoms become obvious.

The naive approach: collect data from vehicles in the field and label faults by hand. This hits two walls. First, real faults are rare—most batteries are fine, so raw data is mostly boring examples of normal operation. Second, severe faults break vehicles before enough failures accumulate to train on, so dangerous fault types stay poorly represented. A machine learning model trained on such imbalanced data will be blind to the rare but critical faults.

The real insight. Mix real measured vehicle data (which is trustworthy but scarce) with synthetic data generated by physics rules (which guarantees the rare fault types exist in balanced quantities).

The algorithm as a flow

What it actually does

Collect real data

Download measured charging/discharging logs from 1000 electric vehicles over normal road use.

Extract time-series features

From each charge cycle, compute voltage curves, current patterns, temperature, and derived quantities (capacity loss, resistance rise, leakage rate).

Generate synthetic faults

Use a physics model (battery chemistry rules) to simulate what happens during each fault type under different operating conditions, creating thousands more examples.

Label everything

Mark each cycle as normal or one of four faults, plus a severity score (1, 2, or 3) showing how severe the fault is.

Benchmark with standard models

Train random forest, SVM, LSTM, and CNN on the mixed dataset and report accuracy, precision, and F1-score so future researchers have a yardstick.

What the paper changes

The single thing the paper changes

Instead of handing practitioners a sparse, imbalanced collection of rare real fault examples, this paper provides a curated mix: authentic measured data from vehicles plus synthetic data generated by physics rules. This is the object the paper manipulates—the ratio and composition of training data.

the object it moves  =  dataset composition
The hidden quantity

The hidden quantity: data imbalance ratio

measured quantity  =  fault-class representation

In raw field data, maybe 95% of cycles show a normal battery and only 5% show faults. Among those faults, dangerous ones like low-capacity are rarer still. A machine learning model seeing 95:5 imbalance will learn to predict 'normal' all the time and score well by accident—it never learns what faults look like. The hidden quantity is how balanced the classes are: the ratio of normal examples to each fault type.

This paper measures class balance by counting how many examples of each label exist in the dataset before and after synthetic generation. By adding synthetic faults, it pushes the ratio closer to equal (maybe 30:20:20:20:10 for four fault types plus normal, instead of 95:1:1:1:2). The paper then shows that CNN trained on balanced data beats CNN trained on imbalanced data in blind tests.

Why it works

Why balancing training data works

The deep reason is simple: a neural network updates its parameters based on prediction errors. If 95% of examples are correct by default (the 'always predict normal' rule), the network's gradients (signals about which way to nudge the weights) are dominated by the rare correct predictions on fault examples. But those rare signals are too weak and inconsistent to teach the network useful fault patterns. Worse, the cost function (the penalty the network minimizes) can shrink just by ignoring faults entirely.

When you balance the classes, each fault type now contributes equally to the error signals. A misclassified self-discharge example generates a large, consistent gradient that steers the network toward the genuine features of self-discharge. The network stops ignoring faults and starts learning their true signatures: the specific voltage curves, temperature dips, and current traces that belong to each failure mode.

Math after the picture

The weighting rule

First in words:

weighted_loss = sum of (class_weight times cross_entropy_error for each example), where class_weight is inversely proportional to how often that class appears in the training set

Then the compact form:

L_weighted = sum_i w_c(i) * cross_entropy(pred_i, label_i)

Every symbol:

L_weightedthe total penalty the network minimizes
w_c(i)the weight for example i, based on its class c
cross_entropy(pred_i, label_i)how wrong the prediction is (0 if correct, large if wrong)
pred_iwhat the network predicted for example i
label_ithe true fault label for example i
A tiny worked example
Suppose real data has 1000 normal examples and 50 self-discharge examples.
Class weight for normal = 1 / 1000 = 0.001. Class weight for self-discharge = 1 / 50 = 0.02.
A misclassified normal example contributes 0.001 × 2.0 (large error) = 0.002 to the total loss.
A misclassified self-discharge example contributes 0.02 × 2.0 = 0.04 to the total loss.
Same prediction error, but rare self-discharge gets 20× weight, so the network learns to treat it seriously.

Reweighting errors makes rare fault classes pull on the network's learning signals as hard as common ones, so the network learns both equally well.

What can go wrong

What can go wrong

Synthetic data that breaks physics. If the generative model does not respect battery chemistry rules (e.g., it generates impossible voltage-current pairs), the CNN learns fake patterns that do not match real faults. Validation: compare synthetic examples to measured lab data and check that the patterns overlap.
Over-balancing hides real-world prevalence. A perfectly balanced dataset means the model sees each fault 25% of the time, but in reality, low-capacity is rare and self-discharge common. Deploy the model with a recalibrated decision threshold to match actual fault rates in the wild, or it will cry wolf.
Feature leakage from generation process. If the synthetic data generation accidentally tags examples with a signal that marks them as synthetic (e.g., slightly smoother curves), the model learns to exploit that instead of learning the true fault signature. Result: high validation accuracy but failures in the field.
Done right. Validate synthetic examples on human-labeled test data from real vehicles. Check that the model generalizes to a holdout set of truly measured field data, not just synthetic validation data.
What a runnable demo should prove

What a runnable demo should prove

Build a minimal battery fault detector on a toy imbalanced dataset (say, 95% normal, 5% faults), train a CNN, and record F1-score on each class. Then retrain on the same data but with synthetic examples added to balance the classes. Show side-by-side that the second model catches faults that the first model misses, even though both see the same raw real data.

F1_fault = 2 * (precision_fault * recall_fault) / (precision_fault + recall_fault), where precision_fault = (true positives) / (true positives + false positives) and recall_fault = (true positives) / (true positives + false negatives)

The goal is to show that adding synthetic, physics-balanced fault examples makes the detector stop ignoring rare failures and actually learn their signatures—measured as F1-score jumping from 0.4 to 0.9 on each fault class.
