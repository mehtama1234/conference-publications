U-MARVEL: Universal Multimodal Retrieval with MLLM Embeddings

A systematic study of how to turn a language model into a multimodal search engine by learning shared embedding spaces where queries and documents from mixed media types can be compared fairly.

Paper explainersAll themesMultimodal

Today's best language models can read images and text together, but they are built to generate one word at a time, not to understand an entire query or document all at once. U-MARVEL discovers the right way to adapt these models into search engines that can find matching images, text, and videos from a mixed database using a shared measurement space. The key is progressive training stages, careful selection of hard negative examples, and distilling a separate ranking model into the search engine.

Zero assumption version

Language models are built to write, not to search across mixed media

A large language model (a program trained to predict and generate text) processes input one word at a time from left to right, with each new word depending only on what came before. This is perfect for writing, but it is the wrong structure for searching. In a search engine, you want to read an entire query (maybe an image plus text) and produce a single measurement that says how similar it is to each document in your database. When the model is trained only to generate words, it has not learned how to produce stable, comparable measurements for this job.

Naive approach: just take the last hidden layer number (the vector representing the model at its final step) and use it as a measurement. This breaks because the model was never trained to make this number reliable. It worked fine as an intermediate step toward generating text, but as a final answer it is unreliable. Different inputs that should match do not, and the ranking is poor.

The fix in one sentence. Retrain the model with a bidirectional reading process and a loss function that pulls similar queries and documents close together in the measurement space, then refine it through a pipeline of training stages on different data types.

The algorithm as a flow

What it actually does

Adapt the model to bidirectional reading

Change the model from left-to-right generation (causal) to full-text reading (bidirectional) so it sees the complete input at once.

Progressive training stages

First train on text-only retrieval, then add text-and-image pairs from a public dataset to align the text and image readers together.

Extract a balanced measurement

Use mean pooling (average all token measurements together) instead of taking just the final token, creating a stable embedding.

Contrastive training with hard examples

Train using InfoNCE loss: pull matching pairs together and push mismatching pairs apart. Hard negatives (items that almost match but do not) are more informative than random mismatches.

Distill from a ranking expert

A separate reranking model examines top candidates and ranks them correctly. Teaching the embedding model to mimic the reranker's judgments improves accuracy because the reranker sees more context (full document content) than the embedding model had during training.

What the paper changes

What the paper changes: the embedding extraction and training recipe

The paper does not invent a new model architecture. Instead, it changes (1) how embeddings are extracted from the model (bidirectional attention plus mean pooling instead of left-to-right plus last-token), (2) the order and data types used during training (text-only first, then text-image pairs), and (3) the loss function details (batch size, learning rate, temperature, and the strategy for choosing negative examples all matter).

The hidden quantity

The hidden quantity: embedding quality in shared space

measured quantity  =  stability and alignment of embeddings

An embedding is a measurement: a list of numbers that represent a query or document. The hidden quantity the paper measures is whether this embedding is stable (the same input always produces the same measurement) and aligned (queries and documents with the same meaning have similar measurements, even if they are in different modalities like text or image). The paper does not give this quantity a single name, but it drives everything.

The paper estimates this by measuring retrieval accuracy on benchmark datasets: when you search for a text query, does the model rank the correct image first? When you search with an image, does it find the right text? Aligned embeddings mean the similarity score between a query and its true match is higher than for false matches, which makes the model rank the correct result first.

Why it works

Why it works: the causal chain from recipe to retrieval

A language model trained to generate text produces hidden measurements (embeddings) that are optimized for predicting the next word, not for comparing whole documents. The first fix is architectural: switch from left-to-right reading (causal) to reading the entire input all at once (bidirectional). Why? Because when the model reads left-to-right, the last token has already been committed before seeing the end of the sentence—it cannot revise its understanding. Bidirectional reading lets every token see the full context, so the measurement reflects the whole input's meaning.

The second fix is pooling: instead of taking the last token's number (which happens to be the end of the sequence), average all tokens together (mean pooling). Why? The last token's measurement was tuned for continuation (predicting what comes next), not for representing the full query. Averaging dilutes that bias and captures meaning across the input.

Third, progressive training: start with text-only retrieval (teaching the model to match text queries to text documents), then add text-image pairs. Why? The model was originally trained only on text. Switching immediately to bidirectional attention on images breaks the text encoder alignment. Gradual exposure to image-text pairs lets the text and image readers learn to speak the same language step-by-step.

Fourth, contrastive loss with hard negatives: pull matching pairs close together in the measurement space, push mismatches apart. Why? The loss function creates a force field: similar items are attracted, dissimilar items repelled. Hard negatives (items that almost match but are actually wrong) teach the model to discriminate between subtle confusions—they are far more informative than random mismatches.

Finally, distillation from a reranker: a separate model reads the top candidate documents from the embedding-based search and produces a refined ranking. The reranker sees the full document text and makes finer distinctions than the embedding model alone. When the embedding model is trained to mimic the reranker's judgments, it learns to produce embeddings that capture these distinctions. Over time, the embedding model becomes accurate enough to replace the reranker entirely, giving the same ranking quality without the extra computation.

Math after the picture

The training equation: contrastive loss brings matches together

First in words:

Loss equals the negative log of a softmax over matching pairs. For a query and its matching document, the softmax numerator is the exponential of their embedding similarity, and the denominator sums over the query paired with all documents (matches plus hard negatives). The temperature parameter controls how sharp this distribution is.

Then the compact form:

L = -log[ exp(sim(q,d+) / tau) / (exp(sim(q,d+) / tau) + sum_i exp(sim(q,d_i-) / tau)) ]

Every symbol:

sim(q,d+)embedding similarity between query q and its true matching document d+
sim(q,d_i-)similarity between q and a negative example d_i- (mismatching document)
tautemperature: higher spreads the softmax, lower sharpens it
Lloss: minimize this to improve retrieval
A tiny worked example
Suppose a query embedding is [1.0, 2.0] and a matching document embedding is [1.1, 2.1], so sim = 0.98. A mismatching document is [5.0, 5.0], so sim = 10.0 (very different). Use temperature tau = 0.07.
exp(0.98 / 0.07) = exp(14.0) = 1,200,000. exp(10.0 / 0.07) = exp(143) = huge number. But wait—use a smaller temperature like 10 to keep numbers reasonable for teaching: exp(0.98 / 10) = exp(0.098) = 1.1. exp(10.0 / 10) = exp(1.0) = 2.7.
Softmax numerator: 1.1. Softmax denominator: 1.1 + 2.7 = 3.8. Softmax output: 1.1 / 3.8 = 0.29. Loss = -log(0.29) = 1.24.
Now suppose we train and the embeddings move: matching document becomes [1.05, 2.05], sim = 0.995 (closer). Mismatching doc unchanged. exp(0.995 / 10) = 1.105. Softmax = 1.105 / 3.805 = 0.29. Loss = 1.23 (slightly lower). Training pulled the match closer, reducing loss.

The temperature controls the sharpness of the discrimination: too high (tau large) and the model does not care which is the match, too low and it overconfidently separates even similar items.

What can go wrong

What can go wrong

Switching too fast to bidirectional attention without progressive training. If you flip the model to bidirectional reading immediately and train on mixed modalities, the text and image encoders become misaligned (the text encoder forgets what it learned during pretraining). Gradual exposure through progressive stages is essential.
Using only random negatives in contrastive training. Random mismatches are easy to distinguish from matches. Hard negatives (items that almost match but are actually wrong) force the model to learn subtle discriminations. Without them, the embeddings do not refine well and zero-shot transfer breaks.
Mismatched batch size, learning rate, or temperature. The paper reveals that these hyperparameters interact. A large batch size requires a higher learning rate and a lower temperature to converge properly. Tuning one in isolation fails; they must be tuned together.
Done right: use bidirectional + mean pooling, progressive stages, hard negatives, and reranker distillation. The full recipe aligns text and image encoders, shapes the embedding space to reflect similarity, and refines retrieval through expert feedback. The embeddings become stable and transferable to new retrieval tasks without retraining.
What a runnable demo should prove

What a runnable demo should prove

Build a small multimodal retrieval system: (1) collect a few hundred text descriptions and images of common objects (dogs, chairs, food, etc.). (2) Implement the embedding extraction: take a pretrained MLLM, switch to bidirectional attention, and extract embeddings using mean pooling. (3) Train using the InfoNCE loss with a small batch (say 32), selecting hard negatives by ranking all negatives by similarity and taking the hardest. (4) Measure retrieval accuracy: for each text query, rank all images by similarity and see if the correct image is in the top 5. Repeat for image queries on text documents. (5) Ablate each component: remove progressive training, remove hard negatives, remove distillation, and watch accuracy drop. Each removal directly breaks one part of the causal chain, showing the viewer exactly why each piece is necessary.

Retrieval recall at k = (number of correct items in top k results) / (total queries)

The demo must show that bidirectional attention + mean pooling + progressive training + hard negatives + distillation together produce embeddings where text and images are truly comparable, even on new retrieval tasks the model was never trained on.
