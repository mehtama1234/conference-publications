Policy-Grounded Synergy of LLM Reward Shaping and Exploration

Give robots both a smarter reward signal from an LLM and a structured way to explore, then let them improve together.

Paper explainersAll themesRobotics & Control

Robots learn skills via reinforcement learning (RL), which means they improve by trying actions and getting a reward signal that tells them which attempts worked. A large language model (LLM) can read a task description and write a reward function from scratch, but LLM-written rewards often point so directly at the goal that the robot gets stuck trying the same failed approach rather than exploring. This paper proposes PoRSE: an LLM writes a goal-focused reward that guides learning, and at the same time, an affordance space (a list of movement types the robot can do, customized for the task) generates bonuses for trying those movements. The robot trains on both signals together, and then both the reward and affordance space are regenerated based on what the robot learned. This creates a feedback loop—because the LLM sees what the robot tried and can now write rewards that encourage partial progress toward the goal, and the affordance space can drop movements that did not help and highlight ones that did—so both the goal signal and exploration bonus improve together.

Zero assumption version

The robot gets stuck because the reward signal is incomplete

When you want a robot to solve a task, you must give it a reward signal—a number that tells it how well each attempt went. For simple tasks, you can hand-write this signal (for example, -1 for each move and +100 when the object reaches the goal). But for real-world tasks with many steps and variations, hand-writing is tedious and error-prone.

A large language model can help by reading the task in words and writing a reward function for you, because language models are good at understanding what humans want. But LLM-written rewards have a problem: they focus narrowly on the final goal. The robot learns to optimize that signal directly, which sounds good but often fails. Because the reward signal is sparse (only nonzero near the goal), the robot gets stuck exploring the same region, trying slight variations of the same failed approach, and never discovers the detours or creative movements needed to reach the goal.

The problem in one sentence. LLM rewards tell robots where to go but not how to explore the space of possible movements to get there.

The algorithm as a flow

What it actually does

Parse the task

An LLM reads the robot task and writes a reward function.

Build an affordance space

Identify types of movements the robot's body can do (reach up, rotate wrist, move forward).

Mix the signals

The robot's total reward at each step is the LLM's goal score plus a bonus for trying un-explored affordances.

Train the robot

The robot learns a policy by improving the mixed reward signal.

Refine both

As the robot makes progress, re-generate the reward and affordance space to stay relevant.

What the paper changes

What the paper changes

The paper changes two things at once: the reward function that guides the robot, and the set of movements it is encouraged to explore.

The hidden quantity

Task-aware affordance relevance

measured quantity  =  Affordance-task alignment

An affordance is a type of movement or capability a robot has—reach forward, rotate elbow, slide gripper, etc. The paper introduces an affordance space: the set of movement types that are relevant for this specific task. For example, picking up a high object rewards 'reach up' but not 'move sideways'.

The paper measures task-aware affordance relevance by checking whether the bonus rewards align with what the LLM thinks the task needs. As the robot learns and makes progress, the affordance space is re-generated to focus bonuses on movements that the LLM now expects to matter. This keeps the exploration bonus efficient—the robot spends compute budget on movements that could actually work, not random flailing.

Why it works

Why the two parts reinforce each other

The core insight is that the LLM's reward and the exploration bonus are not fixed—they both adapt as the robot learns. Here is the loop: The LLM writes a goal-focused reward. That reward guides the robot's first attempts. Some attempts succeed; some fail. The robot's learned policy reflects what it has discovered so far. Then, the paper re-runs the LLM on the current policy (sharing what works and what doesn't), so the LLM can refine the reward function to be more specific. Meanwhile, the affordance space is also re-generated, focusing the exploration bonus on movements that the LLM now thinks are important given what the robot has learned. The robot trains on the new mixed signal, makes progress, and the loop repeats.

Why does this work? Because the LLM's reward starts too narrow (goal-only) but becomes more realistic as it sees the robot's attempts—the LLM can now suggest rewards for intermediate steps it observes the robot taking. The affordance space starts too broad but becomes more task-focused—the LLM names only movements that proved useful in the previous iteration. The robot makes faster progress because it gets both a better reward signal that acknowledges partial progress and smarter exploration that skips useless movements, both improving at the same time. Without this feedback, the affordance space and reward would stay misaligned—the robot would explore the wrong movements or optimize a reward that does not actually solve the task.

Math after the picture

The combined reward signal

First in words:

Total reward per step equals the LLM reward plus a bonus that is high when the robot tries an action that matches a relevant affordance and low otherwise.

Then the compact form:

R_total(s,a) = R_LLM(s,a) + beta * sum_i A_i(a) * I_i(t)

Every symbol:

R_total(s,a)the total reward signal for trying action a in state s
R_LLM(s,a)the reward written by the LLM for this state-action pair
betaa weight that controls how much to care about exploration versus goal
A_i(a)a function that is 1 if action a belongs to affordance type i, else 0
I_i(t)how important affordance i is at this stage of learning (task-relevance)
sum_iadd up the bonuses across all affordance types
A tiny worked example
The robot is reaching for an object. Current state: arm at mid-height. Three affordances: reach-up, rotate-wrist, grip-harder.
The LLM says reach-up is very important now, so I_reach=1.0, I_rotate=0.3, I_grip=0.1.
Action: reach up 5cm. This belongs to reach-up affordance, so A_reach=1, others 0.
R_LLM(reach up) = +2 (LLM encourages this). beta=0.5.
Bonus = 0.5 * (1.0 * 1 + 0.3 * 0 + 0.1 * 0) = 0.5 * 1.0 = 0.5.
R_total = 2 + 0.5 = 2.5.
Now try grip-harder (A_grip=1, others 0). R_LLM(grip) = +0.1 (neutral). Bonus = 0.5 * 0.1 = 0.05. R_total = 0.15.
Reach-up gets higher total reward, so the policy learns to favor reach-up now, because the bonus makes that movement rewarding while the LLM reward stays neutral on grip alone.

As the policy learns, the importance values are re-computed by the LLM, so the exploration bonus stays aligned with what actually matters for the task.

What can go wrong

What can go wrong

Affordance space is too vague. If the LLM identifies affordances that do not actually help the task (for example, listing 'move backwards' as equally important as 'reach forward'), the robot wastes compute exploring irrelevant movements, because the exploration bonus gives high reward for movements that never lead to success. Fix: the affordance space must be grounded in the task structure, not generic.
LLM reward ignores feasibility. An LLM might write a reward that gives credit for states the robot's body cannot actually reach. When this happens, the affordance bonus steers exploration toward movements that will never work, because the LLM never identified feasible affordances for this task. Fix: the LLM must be prompted to consider the robot's physical limits.
Refresh cycle is too slow or too fast. If the LLM re-generates the reward and affordances too often, the robot never settles on a signal long enough to make progress. If too rarely, the signal becomes outdated as the robot learns. Fix: the paper must tune the re-generation frequency to match the task's learning speed.
Done right. The method works best when the LLM is given clear task descriptions, the affordance space is task-specific and physically grounded, and the refresh cycle is tuned to the learning curve. Under these conditions, the robot makes steady progress on both easy and hard tasks.
What a runnable demo should prove

What a runnable demo should prove

Build a simple robot simulation: a 2D arm with a shoulder joint and an elbow joint, trying to reach a target ball on a shelf. Implement three affordances: reach-forward (extend both joints), reach-up (raise the arm), and fine-rotate (adjust wrist angle). Write two reward functions by hand: one goal-only (distance to ball), one mixed (goal plus bonus for reach-up and reach-forward). Train a policy on each, recording success rate and average steps to success.

Improvement = (success rate with PoRSE) minus (success rate with LLM only)

The demo must show that adding the task-aware exploration bonus raises the success rate on the hard reach, and the mixed reward reaches the goal in fewer steps on average.
