Think Less, Act Early: Reinforced Latent Reasoning with Early Exit in Vision-Language-Action Models

Replace long written reasoning with a hidden state sequence and stop early when the state is already confident enough to act.

Paper explainersAll themesAgents & Tool Use

Vision-language-action models often reason by writing many intermediate text steps before choosing an action. That can be slow, and each extra step creates another chance to drift off course. This paper keeps the reasoning inside a hidden state sequence instead of forcing it into text, trains that sequence with task-level reward so that useful internal paths are favored, and adds an early-stop rule so the model can act as soon as the state looks confident enough.

Zero assumption version

Why explicit long-form reasoning can slow embodied control

A vision-language-action model must turn camera input and instructions into actions. One common strategy is to write many intermediate reasoning steps in text before acting. That can help, but it also raises cost because every extra written step takes time and can introduce a fresh mistake.

The problem becomes sharper in long tasks. If an early written step drifts away from the useful plan, later steps inherit that drift. So the model needs a way to think through the task without paying for long visible reasoning, because a shorter internal path may already support a good action.

The main move. Keep reasoning in hidden states and stop when confidence is high enough, because acting early avoids unnecessary computation and reduces opportunities for step-by-step drift.

The algorithm as a flow

What the method actually does

Read visual input and instruction

Start from the current observation and task request so that the action depends on the scene and goal together.

Roll the hidden reasoning state forward

Update an internal state sequence instead of writing visible reasoning, because the model can plan without producing extra text.

Train with task reward

Use reinforcement learning to favor internal paths that lead to successful actions so that useful state progress is reinforced.

Estimate confidence after each step

Check whether the current state already supports a stable action because more reasoning is only worth the cost when it changes the decision.

Stop early or continue

Act immediately when confidence is high, or keep updating the state when uncertainty remains.

The hidden quantity

The hidden quantity

measured quantity  =  action confidence along the hidden reasoning path

The important hidden quantity is action confidence at each internal step. Confidence matters because the model should stop only when the current state already supports a good action. If the state is still unstable, early stopping would lock in a weak decision.

The method estimates this confidence from the current hidden state and uses it to decide whether another reasoning step is worth the extra cost. That balance matters because the best number of internal steps changes from one scene to another.

Why it works

Why hidden reasoning plus early stop helps

Keeping reasoning inside hidden states removes the need to spell out every intermediate thought. That lowers answering time because visible text generation is skipped. It also avoids some error accumulation because a long written chain can introduce mistakes that later steps then copy.

The reward-driven training matters because not every hidden path is useful. By rewarding paths that lead to successful actions, the method shapes the internal updates toward states that support good control. Early stopping then uses the confidence estimate to quit when more updates are unlikely to help, because easy cases often reach a stable decision sooner while hard ones still need extra internal processing.

Stop when confidence passes the threshold

First in words:

At each internal step, compare the action confidence to a stopping threshold. If confidence is high enough, act; otherwise keep updating the hidden state.

Then the compact form:

stop_at_step_t if confidence_t >= tau

Every symbol:

stop_at_step_tthe decision to end reasoning at step t
confidence_tthe model's confidence in the current action at internal step t
tauthe stopping threshold that determines whether more reasoning is needed
tone internal reasoning step
A tiny worked example
Suppose the threshold tau is 0.8.
After step 1, confidence is 0.55, so the model continues.
After step 2, confidence is 0.74, so it still continues.
After step 3, confidence is 0.86, so it stops and acts.
If another scene reaches 0.82 at step 1, the model can act immediately because extra internal steps are not needed.

The paper's full training rule is more detailed, but this threshold view captures the main operational idea: spend internal computation only until the state is good enough to act.

What can go wrong

What can go wrong

Confidence can be miscalibrated. If the model feels sure too early, then early stopping will lock in bad actions because the stopping rule trusts a misleading score.
Hidden reasoning is harder to inspect. When a failure happens, it can be harder to diagnose than a visible reasoning chain because the internal path is not written out for direct inspection.
Reward shaping can favor shortcuts. If the reward overemphasizes speed, the model may stop too soon because acting early becomes more attractive than finishing careful reasoning on hard scenes.
Done right. The method works when the confidence score is calibrated and the reward balances success with speed, because then early stopping saves time without sacrificing control.
What a runnable demo should prove

What a runnable demo should prove

Build a small embodied control task, such as moving to one of several visible targets under language instructions. Compare a model that always writes full reasoning against one that keeps reasoning internal and uses an early-stop threshold.

Record task success and average internal reasoning length. The demo should show that easy scenes terminate earlier while hard scenes still use more internal steps, because the method's promise is adaptive computation rather than one fixed budget.

A convincing demo must show faster acting without a collapse in task success, because the paper's main claim is that some reasoning can be skipped safely.
