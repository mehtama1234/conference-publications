MaRS: Memory-Adaptive Routing for Continual Learning

A frozen pre-trained model learns new tasks by routing each new example to its own dedicated memory slot, expanding the roster of slots only when the data truly demands it.

Paper explainersAll themesRepresentation & Self-Supervised Learning

Large pre-trained models (like GPT or CLIP) have learned patterns across millions of examples, but when you try to teach one new tasks without changing its core weights, two forces fight: you need to remember what you learned before, but you also need to absorb the new information. MaRS solves this by keeping the model frozen and instead growing a memory router—a routing network that learns to steer each new example toward its best-fitting memory slot, expanding the roster only when statistical evidence says you need it.

Zero assumption version

Frozen models face a memory-learning trade-off

When you have a large pre-trained model (like CLIP or a big language model), you do not want to change its core weights, because those weights have learned useful patterns across millions of examples. But when a new task arrives, you need the model to remember it without forgetting the old one.

A beginner might try: train a small adapter (a lightweight add-on layer) on top of the frozen model to solve the new task. But adapters face the stability-plasticity dilemma: if you make the adapter strong enough to learn the new task well, it forgets the old knowledge. If you keep it weak to preserve memory, it fails on the new task. You cannot have both.

The core problem. How do you keep teaching a frozen model new tasks without losing old ones?

The algorithm as a flow

What it actually does

Freeze the backbone

The pre-trained model's weights never change during continual learning.

Route each example

A lightweight router network reads the frozen model's features and outputs a score for each slot (memory compartment).

Update the winning slot

The slot with the highest score adapts via contrastive learning and distillation to learn the new example while retaining old knowledge.

Decide if a new slot is needed

A statistical test checks whether examples are piling up in existing slots or consistently pointing to a genuinely new category. Only create a slot if the signal is real.

Repeat for the next example

As new tasks arrive, the router grows only as needed, keeping total memory linear, not exponential.

What the paper changes

What the paper changes

The paper moves from a single shared adapter to a roster of task-specific memory slots, each fine-tuned independently. The key object is the slot allocation: where to route each new example, and when to create a new slot.

The hidden quantity

The hidden quantity: slot occupancy and detection power

measured quantity  =  detection-power signal-to-noise ratio

The paper measures a hidden quantity that drives its expansion rule: how strong is the signal that a truly new task is arriving, versus random noise in existing slots? It formulates this as a statistical decision problem. In everyday terms: if a new example lands in slot-1, is that because slot-1 is the right place (signal), or just random chance (noise)? The paper counts misses (examples you could have caught earlier if you had a slot-3 ready) and false alarms (times you created a slot-3 when slot-1 would have done fine).

The paper uses a standard statistical test (CUSUM, or a similar sequential detection rule) to estimate this quantity. Before deciding to spawn slot-4, the method asks: how many examples have to pile up in the uncertain zone before we are confident this is a new pattern, not just noise? It chooses that threshold automatically from the data stream.

Why it works

Why it works: routing isolates, expansion stays honest

The core idea is isolation. Each memory slot is a lightweight adapter that sees only the examples routed to it. When slot-1 adapts to cat images, it does not touch slot-2 (which learned cars). Because each slot is trained independently, old knowledge stays put—there is no catastrophic forgetting.

The second secret is controlled expansion. A naive system might create a new slot every time an outlier arrives, ballooning memory use. MaRS avoids this by asking: is this a real new pattern, or just noise in an existing slot? It counts up the uncertain examples until statistical evidence is strong enough. This is why it has guarantees. The paper does not just hope expansion stays reasonable; it proves that the false-alarm rate (creating a slot you did not need) stays below a user-set threshold, and that you detect a real new task within a bounded number of examples.

The third secret is knowledge preservation. When a new slot adapts, it does not use raw replay (storing old examples and playing them back). Instead, it uses contrastive learning (learning to pull the new slot's outputs close to the frozen backbone's embeddings for the new task) and knowledge distillation (a soft penalty that keeps the new slot's predictions aligned with the old slot's outputs on old examples). This means old knowledge is not erased; it is baked into the loss function.

Math after the picture

The expansion decision rule

First in words:

Number of uncertain examples in detection window exceeds threshold derived from desired false-alarm probability

Then the compact form:

S(n) = max(0, S(n-1) + log(rho_n / lambda) - log(threshold)) ; expand when S(n) > h

Every symbol:

S(n)accumulated log-likelihood of a new pattern at step n
rho_nscore the router gives to the best slot for example n
lambdascore the router gives to the second-best slot for example n
thresholda constant you set (higher = require more confidence before expanding)
hdetection boundary; when S(n) crosses h, spawn a new slot
A tiny worked example
Example 1: best slot scores 0.8, second-best scores 0.3. Ratio is 0.8/0.3 = 2.67. Log-ratio = 0.98. Accumulated S = 0 + 0.98 = 0.98.
Example 2: best slot scores 0.75, second-best scores 0.72. Ratio is 0.75/0.72 = 1.04. Log-ratio = 0.04. Accumulated S = 0.98 + 0.04 = 1.02.
Example 3: best slot scores 0.6, second-best scores 0.59. Ratio is 0.6/0.59 = 1.02. Log-ratio = 0.02. Accumulated S = 1.02 + 0.02 = 1.04.
If threshold is 0.5 and h=2.5, we have not yet crossed h. The paper watches: if examples keep scoring high confidence for existing slots, S plateaus, and no new slot is born. But if a new task arrives and the router oscillates (best vs second-best very close), S grows slowly, and once it crosses h, we expand.

The test is sequential: you do not wait for 100 examples to decide. You accumulate evidence one at a time, and the moment S crosses h, a new slot is born.

What can go wrong

What can go wrong

Expansion threshold set too low. If you make it easy to spawn a new slot (low h), the roster grows too fast. Memory balloons, and the router becomes confused deciding which slot to use, because many slots produce similar scores—a higher choice cost when routing each new example. This forces you to choose: create many slots and learn each task quickly but use lots of memory, or create few slots and save memory but risk the router conflating old and new tasks.
Router does not see the signal. If the frozen backbone's features are poor (it was not pre-trained well on tasks like yours), the router cannot tell new tasks apart. Slot scores collapse to noise, expansion stalls, and the method fails. The frozen model must be a strong, general foundation.
Contrastive learning misleads old slots. When a new task arrives, the new slot is trained via contrastive learning to be close to the frozen backbone's features. If the frozen backbone was biased on the old task, this can pull the new slot in a biased direction, hurting generalization.
Done right. When the pre-trained model is strong, the expansion threshold is tuned to your memory budget, and the frozen backbone's biases are small, MaRS learns new tasks quickly and keeps old knowledge intact.
What a runnable demo should prove

What a runnable demo should prove

Build a mini continual learning loop: take a pre-trained vision model (like a ResNet), freeze it, then feed it examples from 5 different image categories one at a time (e.g., cats, then cars, then dogs, then planes, then birds). For each new category, measure two metrics: (1) How many new slots were created? (2) What is the accuracy on the old categories after you finished training on the new ones? Run the same loop with a single shared adapter as a baseline. The demo should show that MaRS creates only 4-5 slots (one per true category) while the naive adapter forgets 30-40% of the old categories.

forgetting = accuracy_old_task_before - accuracy_old_task_after_new_training

The proof is in the numbers: MaRS stops forgetting because each slot is isolated, and expansion is honest because the statistical test prevents slot bloat.
