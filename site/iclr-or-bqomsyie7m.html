Efficient Credal Prediction through Decalibration

A usual classifier returns one probability per class. This paper returns an interval for each class instead, so the system can express uncertainty about the probabilities without retraining an ensemble of models.

Paper explainersAll themesOther

In high-stakes settings, a single probability table can be too confident. A model might say a class has probability 0.82, but the real uncertainty about that value may be wide because the model is unsure about what it has not seen. Credal prediction addresses this by returning a set of plausible probability tables rather than one fixed table. The difficulty is cost. Existing credal methods often need multiple models or retraining, which makes them impractical for large systems. This paper proposes decalibration, a light-weight procedure that turns one classifier's output into class-wise probability intervals.

Why one probability table can hide uncertainty

A classifier often returns one probability for each class and then stops. That is fine when the model is well informed. It is less fine when the input is unusual or the evidence is weak.

In those cases, a single probability table may look more certain than it should. The model might assign class A a value of 0.70, but there may be many nearby plausible worlds where the right value is much lower or higher.

Existing credal predictors represent that uncertainty with a set of plausible probability tables, but they often rely on ensembles or retraining. That makes them costly for large pretrained systems.

Core move. The paper starts from one trained classifier and expands each class probability into a lower and upper bound, so the output can express uncertainty without building many new models.

Use its ordinary class probabilities as the baseline prediction.

Estimate plausible expansion around each class value.

Apply decalibration.

The collection of class-wise bounds defines a set of plausible probability tables.

Evaluate coverage and efficiency.

Check whether the intervals contain the truth often enough while staying narrow enough to remain useful.

What the paper changes

What the paper changes

The paper changes the output layer of uncertainty estimation. Instead of returning one calibrated point probability table, it returns interval-valued class probabilities built from a single existing predictor.

the object it moves  =  the predictive output from a single probability table to class-wise intervals
The hidden quantity

The hidden quantity

measured quantity  =  how much confidence should be removed from the original class probabilities

The hidden quantity is confidence removal. If a model is overconfident, the right uncertainty output should widen around its class probabilities. If it is already well calibrated, the widening should stay modest.

Decalibration estimates that widening directly. The method is useful only when the interval width tracks true uncertainty rather than adding slack everywhere.

Why it works

Why interval outputs can be built from one predictor

A single classifier already contains information about which classes it finds plausible and which it rejects. The paper uses that information as a starting point instead of training many separate models. It asks how far each class probability can move while remaining plausible under a relative-likelihood criterion.

That works because uncertainty is represented as a range rather than a single point. Once each class gets a lower and upper bound, the output can express caution directly. This is why the method can scale to systems such as CLIP and TabPFN: it reuses the base model instead of duplicating it many times.

From point probabilities to intervals

First in words:

For each class, the method computes a lower bound and an upper bound around the original predicted probability. The set of all probability tables consistent with those bounds is the credal output.

Then the compact form:

A tiny worked example
Suppose a classifier outputs class A = 0.70, class B = 0.20, class C = 0.10.
Decalibration may widen these to A = 0.58 to 0.79, B = 0.14 to 0.27, and C = 0.06 to 0.16.
The winning class is still A, but the model now admits that the exact probability is uncertain.
If the input is more unusual, the intervals may widen further because the base prediction deserves less confidence.

The details of the widening rule come from the paper's relative-likelihood construction, but the visible output is simple: one interval per class.

What can go wrong

What can go wrong

Intervals can become too wide. If the widening rule is too conservative, the output covers many possibilities but becomes less useful for decisions because nearly every class remains plausible.
The base classifier can still be deeply wrong. Intervals built from one model cannot recover information the model never had, so the method may still miss uncertainty patterns that only a richer model family would reveal.
Coverage and efficiency pull in opposite directions. Very wide intervals raise coverage, but that can happen for the wrong reason because the method is simply saying less. Useful credal prediction needs both coverage and reasonably tight bounds.
Done right. The method works when the widening tracks real epistemic uncertainty, because then intervals grow on doubtful cases while staying narrow on ordinary ones.
What a runnable demo should prove

What a runnable demo should prove

Take one trained classifier and compare three outputs: raw point probabilities, temperature-style calibration, and the paper's interval output. Use both in-domain and more unusual inputs. Measure interval coverage, average interval width, and decision abstention behavior.

The demo should show that decalibration produces wider intervals exactly where uncertainty is real, because that is how it justifies using a single model instead of an ensemble.

coverage = fraction_of_examples_where_true_class_probability_lies_inside_the_reported_interval

The convincing result is high coverage without exploding width, because the paper's contribution is efficient uncertainty expression, not uncertainty inflation for its own sake.
