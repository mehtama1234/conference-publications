Reading Images Like Texts: Sequential Image Understanding in Vision-Language Models

Vision-language models process images in two stages: first picking out colors and shapes, then naming what objects they belong to.

Paper explainersAll themesInterpretability

Today's vision-language models (systems that read both images and text) process images by flattening them into lists of numbers, very different from how human eyes work. This makes them opaque — nobody fully knows how they turn pixels into understanding, because the internal steps are hidden. This paper opens the model like a textbook, showing how visual understanding unfolds layer by layer inside the network, first identifying raw features, then assigning them to object categories. Seeing this structure allows us to make the model faster (by skipping unnecessary work) and smarter at spatial reasoning (by tuning how it tracks positions).

Zero assumption version

The opacity problem

Vision-language models work by shrinking images into long lists of numbers, then feeding those into a text-reading engine. But this approach hides what the model is actually doing. A beginner's naive idea: just watch the numbers as they flow through. But which numbers matter? When does the model decide a blur is a dog vs a rock? These questions have no clear answers because the internal machinery is a tangled mass of thousands of tiny numerical steps.

This opacity matters because it blocks two things: deeper understanding of how these systems work, and smarter design of future ones. Without seeing how the layers build up from features to object names, you cannot know which layers to focus on or which parts to tune without breaking something else.

The paper's move in one sentence. By analyzing the model layer by layer, it reveals that visual understanding unfolds in two distinct phases: first recognizing raw features like color and shape, then assigning those features to specific object categories.

The algorithm as a flow

What it actually does

Record each layer's output

Cut the model at layer 1, layer 5, layer 10, etc. Pass an image through each truncated version and capture what comes out.

Convert outputs to words via the language model's scoring layer

Take each layer's numbers, pass them through the language model's final scoring layer (which turns numbers into word choices), and decode to text words like bear, rock, red, smooth.

Track when attributes peak

Count how often attribute words appear (color, texture) at each layer. The peak shows where the model is identifying raw features.

Track when object names peak

Count how often object category words appear (fox, rock, tree). The peak shows where the model assigns those features to named objects.

Apply the findings to optimize

Use the roadmap to strip redundant image tokens after layer 18 (saving compute) and tune position encoding in early layers (sharpening where-is-it reasoning).

The hidden quantity

The hidden quantity: attribute emergence rate

measured quantity  =  when features become names

As you go deeper into a vision-language model, the model gradually shifts from describing low-level features (smooth, red, bumpy) to naming high-level objects (fox, table, sky). The paper measures this shift by counting how often attribute words appear at each layer. Early layers rarely mention attributes. At layer 15, attribute words are everywhere. By layer 20, object names dominate and attribute words drop. This curve reveals the hidden progression.

The paper estimates this by running images through the model, cutting it at each layer, then converting the layer's outputs to text via the language model's word-scoring layer. Then it counts what fraction of the words are attributes vs objects. That fraction creates the emergence curve.

Why it works

Why the paper's approach works

The core insight is that a neural network does not build understanding all at once. Instead, it refines progressively. Each layer takes the outputs of earlier layers and reorganizes the information. Early layers are rough tools — they detect whether a pixel is red or smooth. Middle layers combine those raw signals into linked patterns (a bunch of red pixels that feel rough suggests a rough red material like brick). Deep layers use those patterns to answer the hard question: what object has this material? A fox or a rock?

By slicing the model and measuring word emergence at each layer, the paper makes that invisible process visible. It shows that the model first collects evidence (attributes), then uses that evidence to reach a conclusion (the object name). Because the model has already decided the object category by layer 18, tokens after that layer contain mostly redundant information. Discarding those tokens saves computation time because the remaining layers do not need to process them — a smaller pile of numbers flows through fewer calculation steps. Similarly, position encoding (how the model tracks where each part is) only needs to be sharp in early layers where spatial precision still matters. In later layers, the model already knows what the object is, so exact position matters less. Tuning position encoding early means spatial reasoning is accurate where it counts most.

The emergence rate equation

First in words:

For each layer, count how many words in its decoded output are attributes (color, texture) vs objects (fox, tree). The emergence rate at layer L is: (count of attribute words at layer L) divided by (count of attribute words at deepest layer).

Then the compact form:

emergence_rate_L = sum_i (word_i at layer L is attribute) / sum_i (word_i at layer 24 is attribute)

Every symbol:

emergence_rate_Lthe fraction of attribute words at layer L compared to the deepest layer
word_i at layer Lthe i-th word decoded from layer L's output
attributea word describing features: color, texture, shape
layer Lone of 24 layers in the visual encoder
A tiny worked example
Suppose at layer 5, decoding outputs 10 words total: red, smooth, round, object, is (5 attributes, 5 non-attributes).
Suppose at layer 24, decoding outputs 20 words total: fox, sits, on, rock, red, smooth (2 attributes, 18 non-attributes).
Emergence rate at layer 5 = 5 / 2 = 2.5 (still detecting raw features).
Emergence rate at layer 24 = 2 / 2 = 1.0 (baseline, mostly object names now).
A ratio > 1 means that layer emphasizes attributes more than the final layer; < 1 means it has shifted to object naming.

What can go wrong

What can go wrong

Treating all images the same. The emergence pattern varies by image complexity. A simple photo of a single object will have its attributes peak earlier than a cluttered scene with many objects. The analysis must account for image-level variation.
Compressing too aggressively. Discarding tokens early (right after layer 15) can save time but may trash spatial precision if the image requires fine-grained positional detail. The trade-off between speed and accuracy is real.
Assuming RoPE scaling fixes all spatial bugs. Position encoding is just one source of spatial reasoning errors. Architectural limitations (attention head patterns, uneven token weighting) can persist even after scaling is tuned.
Applied correctly. Use the emergence curve as a diagnostic, not a law. Measure performance on your actual task after each optimization. Compress selectively, and validate spatial accuracy on spatial tasks (visual question answering about positions, scene graphs).
What a runnable demo should prove

What a runnable demo should prove

A demo should train a small vision-language model on a labeled image dataset, then layer-by-layer show how attribute words emerge and then fade as object names rise. Visualize the emergence curve. Then build a compressed version by discarding tokens after layer 18, measure how much faster it runs and whether it answers spatial questions (e.g., which object is on top) correctly. The speed improves because fewer tokens flow through the remaining layers; accuracy stays high because the model already knows which object it is dealing with by that point.

spatial_accuracy_loss = (accuracy_before_compression - accuracy_after_compression); speedup = (inference_time_before / inference_time_after)

The core proof is the emergence curve: attributes peak early, objects peak later, and this pattern repeats across different images and models, revealing a consistent two-stage progression in visual understanding.
