Manifold-Aligned Guided Integrated Gradients for Reliable Feature Attribution

Feature explanations become more reliable by keeping the path toward the input inside realistic-data space instead of wandering through noise.

Paper explainersAll themesInterpretability

When you want to know why a neural network made a prediction, you trace gradients backward from the output to the input. But the path you take matters: if you wander through regions where the model has never seen real data, the gradients are noisy and misleading. This paper routes attribution paths through plausible data-space instead, using a trained generative model as a guide.

Zero assumption version

Noisy gradients when attribution ventures off realistic-data space

A neural network is a black box: you feed it an image and it outputs a prediction, but you do not know which pixels mattered. The standard solution is Integrated Gradients: trace a straight line from a baseline (blank image) to the real input, and measure the gradient at each step along that line. Larger gradients mean that pixel or feature had more influence on the final answer.

But here is the catch: the path between baseline and input cuts through many regions the model has never seen in training. In those strange in-between zones where no real image lives, the gradients are erratic and unreliable. You end up attributing importance to the wrong features, or giving fake high scores to features that barely mattered.

The problem in one sentence. Straight-line attribution paths wander through implausible data regions and pick up false gradient signals.

The algorithm as a flow

What it actually does

Step 1: Compress target and baseline into latent codes

Run both images through a pre-trained VAE encoder to get compact representations.

Step 2: Interpolate in latent space

Draw a line between the baseline code and target code, sample points along it.

Step 3: Decode and measure gradients

Decode each sampled latent point back to pixel space; measure the gradient at each step.

Step 4: Aggregate by proximity

Weight each gradient by how close it sits to the real input in pixel space.

Step 5: Assign importance scores

Sum weighted gradients to get a final attribution score per feature.

What the paper changes

The one thing that changes

Instead of integrating along a straight line in pixel space, the method constructs the integration path in the latent (compressed) space of a variational autoencoder (a generative model that learns the structure of real data). Intermediate states are then decoded back to pixels, keeping the path inside realistic-data space.

The hidden quantity

The hidden quantity: Manifold proximity

measured quantity  =  Off-manifold gradient noise

Off-manifold gradient noise measures how much spurious signal leaks in when you evaluate the model in regions far from real data. In plain terms: the further you wander from realistic images, the more the model's gradients become random and unreliable.

The paper estimates this by comparing gradient stability along different paths. A latent-space path, when decoded, stays close to realistic images (the shape and structure the VAE learned from real data), so it encounters less noisy gradient terrain.

Why it works

Why it works: staying on the rails

A VAE learns a map of plausible data: it compresses real images into a smaller latent space (fewer numbers), then decompresses them back. The decoder has learned to output realistic images from anywhere in that latent space. When you interpolate in latent space and decode, you stay inside realistic-data space by design.

By contrast, a straight-line path in pixel space will cut through unreal combinations (e.g. a tree fused with a face), where the model has no training data. The gradients in those regions are noisy guesses. By using the latent path, you avoid those dead zones entirely. The model's gradients remain stable and honest because they are always being computed on something resembling real data.

The final step — weighting gradients by how close the decoded image sits to the real input — ensures you trust gradients only when they come from the most realistic interpolations. This is the reason MA-GIG produces more faithful explanations than simpler alternatives.

Math after the picture

The equation: weighted gradient integral

First in words:

Attribution equals the integral over the interpolation path of the model's gradient, weighted by how realistic each intermediate image is (measured by distance to the real input).

Then the compact form:

attr = integral from 0 to 1 of gradient(f(decode(z_t))) * w(decode(z_t)) dt, where z_t = (1-t)*z_baseline + t*z_target

Every symbol:

f(x)the model's prediction function (what we are explaining)
z_tthe latent code at interpolation step t, ranging from 0 (baseline) to 1 (target)
decode(z_t)the VAE decoder that converts latent code to pixel image
gradient(...)the vector of partial derivatives showing which pixels most influence the prediction
w(...)weight function: how much to trust this gradient (high for realistic images, low for unrealistic ones)
integralthe sum of all gradient signals along the entire path
A tiny worked example
Suppose we sample 3 points along the latent path: t = 0 (baseline), t = 0.5 (middle), t = 1 (target).
At t=0: gradient is [0.1, 0.05, 0.02], decoded image is very different from target, weight w = 0.2 -> contribution = 0.2 * [0.1, 0.05, 0.02] = [0.02, 0.01, 0.004]
At t=0.5: gradient is [0.8, 0.7, 0.3], decoded image is fairly realistic, weight w = 0.8 -> contribution = 0.8 * [0.8, 0.7, 0.3] = [0.64, 0.56, 0.24]
At t=1: gradient is [0.9, 0.85, 0.4], decoded image matches target perfectly, weight w = 1.0 -> contribution = 1.0 * [0.9, 0.85, 0.4] = [0.9, 0.85, 0.4]
Sum: [0.02, 0.01, 0.004] + [0.64, 0.56, 0.24] + [0.9, 0.85, 0.4] = [1.56, 1.42, 0.644]. The first feature gets the highest attribution because its gradients were large and trusted throughout.

The weighting ensures that only clean, realistic parts of the path contribute heavily to the final attribution.

What can go wrong

What can go wrong

VAE quality collapse. If the VAE itself is poorly trained or has not seen certain data regions, it will encode and decode inaccurate images. The path will then move through an incorrect manifold, and gradients will still be unreliable.
Bottleneck loss. The latent code is a compression of the real image. Fine details may be lost in encoding, so the decoded intermediate images may blur out small features that were important to the original prediction.
Baseline mismatch. If the baseline image (e.g. a blank image) is far outside the data the VAE trained on, the encoding may be unstable or the latent code may sit in a region the VAE has not learned well. The latent path will then veer into uncharted territory, defeating the whole point of staying on the manifold.
Done right. Use a well-trained VAE on the same data the classifier was trained on, choose a realistic baseline image (e.g. an average or blurred version of the input), and verify that the latent path produces plausible decoded images by eye.
What a runnable demo should prove

What a runnable demo should prove

Build a simple classifier on a toy dataset (e.g. CIFAR-10: a standard image test set of 32x32 photos of animals, vehicles, and objects). Train a VAE on the same data. Then run both straight-path Integrated Gradients and MA-GIG on the same image and compare the feature rankings they produce.

Faithfulness = correlation between importance scores and the impact of removing each pixel from the image (high correlation means the explanation ranks features the same way the model does when pixels are actually deleted).

MA-GIG's attribution ranking should remain stable and correlate with actual pixel importance even for complex features, while the straight-path method should rank many irrelevant off-manifold artifacts as highly important.
