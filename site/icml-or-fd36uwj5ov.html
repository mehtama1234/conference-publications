Hyperparameter Transfer with Mixture-of-Expert Layers

A scaling rule lets you tune one small model and confidently apply those settings to much bigger models without re-searching.

Paper explainersAll themesOptimization

Building very large neural networks is expensive. One trick to make them cheaper: split the decision work across multiple smaller components called experts, so each input only activates a few of them. But this creates a nightmare: tuning the settings (hyperparameters) for the routing mechanism and expert count becomes a moving target as you scale the model. This paper shows you can lock in the tuning on a tiny model and reliably carry it forward to 40x larger models.

Zero assumption version

Scaling without a map

A normal neural network is a web of connected numbers (weights) that learns to predict things. To make it predict better, you make it bigger: more weights, more layers, because more numbers mean more adjustable knobs to tweak during learning—the model can memorize finer details and express more complex patterns. But bigger models cost more to train, because each training step is slower. Mixture-of-Experts (MoE) solves this by saying: instead of every weight caring about every input, use a router (a small sub-model) to send each input to only a chosen few weights. This way, you get a bigger model without every input touching every weight, so each step stays fast.

The problem: bigger models need tuned settings (learning rate, expert count, router strength). The standard way is to train a tiny model, find good settings, then train a bigger model with those same settings. But it does not work. A router-learning-rate that was perfect at 51 million weights produces garbage at 2 billion weights. You are forced to search again, burning money on failed experiments.

In one sentence. Find a scaling rule so one tuning sweep at small size carries forward to all larger sizes without guessing.

What the paper changes

What the paper changes

The paper introduces a scaling parameterization: a formula that predicts how to adjust tuning settings (learning rate, expert count, expert size) when you increase model width, depth, number of experts, and expert hidden dimension. Instead of searching blindly at each size, you measure the relationship at small scale and extrapolate.

the object it moves  =  tuning dials
The hidden quantity

The hidden quantity: expert load balance

measured quantity  =  load balance

The paper tracks one invisible but important measure: how evenly work spreads across experts. Every input sentence piece (called a token—a small chunk of text the model processes) needs to pick which experts to route to. If the router sends all pieces to expert 1, that expert overheats and the others sit idle. If pieces spread evenly, every expert contributes and training is smooth.

The paper measures this using dynamical mean-field theory (a physics-inspired math tool that models how one token's behavior affects the whole crowd). It measures the average activation rate per expert—the fraction of tokens sent to each expert—as the model scales. When you keep this activation rate constant across all model sizes, tuning transfers automatically, because the router's algorithm for picking experts works the same way at every size.

Why it works

Why the scaling rule works

The mechanism is this: when you scale up a model, two things happen. First, the model has more capacity, so if you keep the same tuning dials, it over-fits to the routing bias you inherited from the smaller model—the model picks up on tiny quirks that helped the small version but hurt the big one. Second, the sheer number of possible routes explodes: at 51M parameters, the router has maybe thousands of valid choice combinations; at 2B, it has trillions. With more options, the router needs a higher learning rate to find a good choice before time runs out, because each training step sees a smaller fraction of the possible space. These two pressures push the tuning dial in opposite directions.

The paper's solution measures where the balance sits using mean-field theory. It shows that if you scale the router's learning rate and the number of experts together in a specific ratio tied to the model's width and depth, the router's average behavior stays identical across all sizes. This is not magic—it is because the router learns the same decision surface at every scale; you are just expressing it in a proportionally scaled space.

Math after the picture

The scaling formula

First in words:

learning rate of router is scaled by the total model width and depth in a power-law ratio; expert count and expert size follow the same scaling principle.

Then the compact form:

lr_scaled = lr_base * (width * depth)^alpha; expert_count = base_experts * (width)^beta; expert_size = base_size * (width)^gamma

Every symbol:

lr_scaledthe tuning dial for router learning rate at a new size
lr_basethe dial found by sweeping a small model
widththe size of the model's main weight layers
depththe number of layers in the model
alphaa power from mean-field theory (typically ~0.5 to ~1.0)
base_expertsnumber of experts found at small scale
betapower for expert count scaling
base_sizeexpert hidden layer size at small scale
gammapower for expert size scaling
A tiny worked example
Suppose at 51M parameters (width=768, depth=12): you tune and find lr_base = 0.001, base_experts = 8, base_size = 3072.
Now scale to 2B parameters (width=1536, depth=24): width is now 2x, depth is now 2x.
Using alpha=0.5: lr_scaled = 0.001 * (1536 * 24)^0.5 / (768 * 12)^0.5 = 0.001 * sqrt(2) ≈ 0.0014.
Using beta=0.5: expert_count = 8 * (1536/768)^0.5 = 8 * sqrt(2) ≈ 11 experts.
Result: train the 2B model with router learning rate 0.0014 and 11 experts. No search needed.

The exponents alpha, beta, gamma are derived from mean-field theory and ensure expert activation stays balanced as scale grows.

What can go wrong

What can go wrong

Exponents do not match theory. If the mean-field theory assumptions fail (e.g., the router decision is highly non-linear or experts are tightly coupled), the exponents alpha, beta, gamma may not hold across a wide range of scales. The formula breaks.
Expert initialization sabotage. The formula assumes expert initializations are similar at every scale. If large models use different initialization schemes, load balance will drift even with scaled dials.
Overly-long training schedules. The paper transfers from short-horizon small models to long-horizon large models. If the long-horizon training induces different dynamics (late-stage instability, loss drift), the old tuning dials may misfire.
Done right. Run small sweeps at multiple sizes (51M, 256M, 1B) to validate the exponents before committing to a huge training run. If they hold across three checkpoints, the formula is trustworthy.
What a runnable demo should prove

What a runnable demo should prove

A convincing demo trains three models: (1) a 128M parameter model with a hyperparameter grid sweep (for example, 4 values of router learning rate times 3 expert counts gives 12 training runs) to find the best tuning; (2) a 512M parameter model using the same tuning (naive transfer) to show it fails; (3) a 512M model with tuning scaled by the formula. The demo measures expert load balance (what fraction of tokens route to each expert) and training loss. It proves that the formula keeps load balance constant across sizes.

load_balance_variance = variance(tokens_per_expert); smaller variance = more balanced. Show that naive transfer has high variance; scaled transfer has low variance.

The single unmissable proof: plot expert activation rate (fraction of tokens) for each expert at 128M, 256M, and 512M, all using the same tuning dials. The bars at 128M are scattered; at 256M and 512M they collapse into a flat line. That flat line is the scaling rule working.
