One Model for All Crystal Symmetries

A single neural network learns to recognize any crystal's symmetry by encoding symmetry constraints directly into its weights.

Paper explainersAll themesGraph & Geometric Learning

Crystal materials (salt, diamonds, silicon) all have hidden patterns called symmetries — directions where the atoms look identical. Different crystals have different sets of symmetries, and most machine learning models need a separate design for each one. This paper builds one model that automatically adapts to work with any of the 230 symmetries that appear in real crystals, using a mathematical trick called Fourier bases.

Zero assumption version

Why one model per symmetry breaks

If you want a machine learning model to understand that a crystal looks the same when rotated by 90 degrees, you have to build that assumption into the model's design — the code, the connections between neurons, all of it. A different crystal has a different set of symmetries (maybe it only looks the same when rotated by 60 degrees), so you need a completely different model design.

With 230 different symmetry groups in real crystals, you would need 230 hand-built models. This wastes computation because you build 230 separate systems instead of one; it makes knowledge transfer hard because patterns learned for one symmetry's neural network do not apply to another symmetry's completely different design; and it requires an expert because each new symmetry demands human design work. A beginner might naively just run the same generic model on all crystals and ignore symmetry altogether — that works, but the model wastes training time re-learning patterns it already knows (atoms are arranged the same way after a 90-degree rotation, yet it learns this twice), and it predicts slower and less accurately because it does not use the symmetry to simplify the task.

The move. Instead of redesigning the model for each symmetry, encode all 230 symmetries' rules into one model's numbers, and let the model activate the right rules for each crystal.

What the paper changes

What the paper changes

The paper changes how the model's numbers (called weights) are constructed. Normally, weights are stored as whatever values the training process picks. Here, the model encodes the symmetry rules directly into how weights are allowed to be set — only certain combinations of numbers are legal, and the weight values must respect those constraints.

The hidden quantity

The Fourier basis: the hidden quantity

measured quantity  =  Valid Fourier patterns per symmetry

A Fourier basis is a set of wave patterns (up-and-down waves like sound ripples) that respect a symmetry. When a crystal has a 90-degree rotation symmetry, only certain wave patterns fit that rule — others violate it. The paper computes these valid patterns mathematically for all 230 symmetries.

The model uses this list of valid patterns as a constraint: it only allows weights to be built from allowed patterns. This works because if a weight is built from a pattern that respects 90-degree rotation, then the weight itself must respect 90-degree rotation — the math is automatic. This is how the model knows that rotating the input by 90 degrees must give the same output: it is baked into the allowed numbers. The paper estimates which patterns are needed by analyzing the symmetry group's mathematical definition, solving the equations that describe what happens when you rotate atoms.

Why it works

Why it works: the causal chain

The key idea: a symmetry is a rule about which inputs give the same output. Instead of making the model figure out this rule during training (which wastes time and data), the paper encodes the rule into the weights before training even starts. If a crystal has 90-degree rotation symmetry, the model's numbers are constructed so that rotating the input is mathematically impossible to ignore — the output will be the same whether you rotate first or not.

This works because symmetries are pure mathematics: a rotation is a precise operation, and you can write down exactly which Fourier patterns preserve it. Once you list these patterns, you can build a neural network layer where weights are only allowed to be sums of these patterns. That layer then automatically respects the symmetry.

Weight sharing happens because many symmetry groups are related — 60-degree and 120-degree rotations share common patterns. When the model trains on one symmetry, it learns which patterns in the shared basis are useful; training on another related symmetry reinforces those patterns. This is why the model generalizes to symmetries it has never seen (zero-shot): the patterns it learned on similar symmetries apply.

Math after the picture

The mathematical foundation

First in words:

The weight matrix is constructed as a sum of scaled Fourier basis functions, where each basis function respects the symmetry constraints. Only allowed patterns contribute to the final weights.

Then the compact form:

W = sum_k alpha_k * B_k(g)

Every symbol:

Wthe weight matrix the model learns
alpha_kthe scalar (single number) the model adjusts during training for pattern k
B_k(g)the k-th basis function for symmetry group g
gthe symmetry group label (which of 230 space groups)
sum_kadd up all the allowed basis functions
Tiny worked example
Suppose a 4x4 table of weights must respect 90-degree rotation symmetry.
Valid Fourier basis function B_1 for this symmetry: a symmetric pattern like [[1, 2, 2, 1], [2, 3, 3, 2], [2, 3, 3, 2], [1, 2, 2, 1]].
Valid basis function B_2: another pattern, say [[1, 0, 0, 1], [0, 2, 2, 0], [0, 2, 2, 0], [1, 0, 0, 1]].
The model sets alpha_1 = 0.5 and alpha_2 = 0.3.
Final weight: W = 0.5 * B_1 + 0.3 * B_2 = [[0.8, 1, 1, 0.8], [1, 1.6, 1.6, 1], [1, 1.6, 1.6, 1], [0.8, 1, 1, 0.8]].
This matrix is guaranteed to respect 90-degree rotation: rotating it gives the same matrix.

The model only controls alpha values; the basis functions are fixed by the symmetry group's mathematics, so symmetry is automatic.

What can go wrong

What can go wrong

Basis incompleteness. If the Fourier basis is not carefully constructed, it may miss important patterns for the symmetry. The paper requires exact mathematical derivation of the basis from the symmetry group definition — errors here break everything.
Symmetry label errors. If you tell the model the crystal has the wrong symmetry, it enforces the wrong rules. The crystal's true symmetry must be known or correctly inferred beforehand.
Limited data per symmetry. If one symmetry group has very few training crystals, the model may still struggle, even with weight sharing. Shared patterns help (because the model learns useful features from related symmetries) but do not replace real data (the model still needs examples from the specific symmetry to tune its alpha values correctly).
Done right. Accurate symmetry group identification, careful basis construction from group theory, and enough diversity in training crystals make the approach work reliably.
What a runnable demo should prove

What a runnable demo should prove

Build a small dataset of 3-4 synthetic crystals with different space group symmetries (e.g., cubic, hexagonal, monoclinic). Train the model on crystals from 2 symmetries, then test on a third symmetry the model has never seen. Measure how accurately the model predicts a simple property (e.g., density or stability score) on the unseen symmetry. Compare to a generic model that ignores symmetry entirely.

Zero-shot accuracy = correct predictions on unseen symmetry / total predictions on unseen symmetry

The demo proves zero-shot works: the model handles unseen symmetries because shared Fourier patterns from related symmetries apply, and enforced rules in the weights automatically prevent symmetry violations.
