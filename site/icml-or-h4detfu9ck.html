Hi-Time: Hierarchical Latent Prediction for Multivariate Time Series Classification

Break time series into hierarchical layers of patterns, let an LLM predict them step by step from coarse to fine, and read off the label.

Paper explainersAll themesTime Series & Sequential

When you feed a large language model raw time series data, it struggles because the reasoning steps are not clear — unlike language where we naturally read left to right, time series have no obvious way to build up a decision step by step. Hi-Time solves this by automatically finding a hierarchy of patterns hidden in the temporal data, turning those patterns into a coarse-to-fine prediction roadmap that the LLM can follow naturally.

Zero assumption version

Time series reasoning is murky

Large language models excel at language because text has a clear serial structure: read word by word, accumulate meaning, decide. But time series data is just a raw list of numbers over time. If you give an LLM raw numbers, it has no natural way to build reasoning step by step — the decision process stays a black box.

A beginner might try to write detailed instructions: "First detect if the trend is rising in the first quarter, then check variance in the middle, then look at the tail." But this requires hand-crafted rules for each new time series dataset, and datasets vary wildly. One financial dataset may need different prompts than medical sensor data. You cannot scale this approach.

The core problem: LLMs need a clear step-by-step reasoning path through the data, but raw time series offer none, and hand-writing reasoning steps for each dataset is brittle and does not scale.

What the paper changes

What changes: the prediction path

Instead of giving the LLM raw numbers or a single hand-written prompt, Hi-Time automatically constructs a hierarchy of discrete codes — each code is a named pattern in the time series — and arranges them into layers. The LLM predicts these codes step by step rather than jumping straight to a label.

the object it moves  =  prediction hierarchy
The hidden quantity

Hierarchical temporal semantic codes

measured quantity  =  the hierarchy depth and granularity

A semantic code is a discrete label for a recognized pattern in time. For example, code 3 might mean 'a rising trend in this time window' or 'high variance detected'. Hi-Time groups these codes into layers: Layer 1 captures the broadest patterns (is the signal trending up or down?), Layer 2 refines it (how sharp is the turn?), Layer 3 captures fine details (are there small repeating bumps?). The depth and fineness of this hierarchy is the hidden quantity the paper measures — it directly controls how much reasoning the LLM has to do and how structured that reasoning becomes.

The paper estimates this hierarchy by learning temporal representations (lists of numbers that capture the data patterns) via combining different ways of looking at time — raw values, rate of change, smoothed trends — merged into one representation. It then rounds these representations into discrete codes and arranges them hierarchically. Datasets with complex, multi-scale structure naturally produce deeper hierarchies; simpler datasets produce shallower ones.

Why it works

Why hierarchical codes let the LLM reason clearly

The core insight: if you give an LLM a clear sequence of prediction targets arranged from simple to complex, it can answer them in order, building up confidence and structure. Raw time series do not offer this sequence naturally, so Hi-Time manufactures it automatically. Here is the mechanical chain. Start with raw multivariate time series — possibly dozens of measurements at each time step. Learn an embedding (a list of numbers that summarizes what is interesting in a chunk of data) using a neural network trained on multiple views of the same data. This multi-view training forces the embedding to capture real structure, not just one arbitrary slice. Next, convert these continuous embeddings into discrete codes by clustering or rounding them — now each code is a category name for a pattern. Arrange these codes in a hierarchy: the top layer has the broadest categories (e.g., trending vs. flat), the middle layers have mid-level detail (e.g., how volatile), the bottom layers have fine specifics. This hierarchy is the structure the LLM will reason over.

Now the LLM's job is simple: given the raw data, predict the codes layer by layer. At each step, the LLM sees the current information and the codes it has predicted so far, and it predicts the next layer's codes. Because each layer is more detailed than the last, the LLM's reasoning is scaffolded — it cannot jump to a conclusion about fine details without first reasoning about the coarse patterns. This is called coarse-to-fine supervision: the data naturally teaches the model to think hierarchically. Finally, after predicting all layers, the LLM reads off the class label (is this a normal heartbeat pattern, an anomaly, a trend reversal, etc.). Because the LLM has reasoned through a structured hierarchy tailored to the specific dataset's patterns, it outputs cleaner, more interpretable decisions than if it guessed the label from raw data.

Math after the picture

Hierarchical prediction loss

First in words:

total loss equals supervised prediction error at each layer, summed across all layers, weighted by layer importance

Then the compact form:

L = sum_l w_l * cross_entropy(pred_l, target_l)

Every symbol:

lthe layer index (1 = coarse, L = fine)
pred_lthe LLM's predicted codes at layer l
target_lthe ground-truth codes at layer l
w_lthe weight on layer l (how much it matters)
cross_entropya standard measure of prediction error
A tiny worked example
Layer 1 (coarse): LLM predicts 'trending up', target is 'trending up', error = 0.0, weighted error = 1.0 * 0.0 = 0.0
Layer 2 (mid): LLM predicts 'medium steepness', target is 'high steepness', error = 0.5, weighted error = 0.8 * 0.5 = 0.4
Layer 3 (fine): LLM predicts 'some noise', target is 'some noise', error = 0.0, weighted error = 0.6 * 0.0 = 0.0
Total loss = 0.0 + 0.4 + 0.0 = 0.4. The LLM is guided to match the hierarchy at every level.

The loss penalizes the LLM for mispredicting at any layer, so it learns to reason hierarchically or pay a cost.

What can go wrong

What can go wrong

Hierarchy is too shallow. If the learned hierarchy does not have enough layers, the LLM still faces a big reasoning jump. The coarse-to-fine benefit is lost, and the model may overfit to surface-level patterns.
Codes are noisy or redundant. If rounding the representations into discrete codes loses too much detail, the LLM cannot reason accurately. Or if many codes represent the same pattern, the hierarchy becomes confusing rather than clarifying.
Multi-view fusion is misaligned. If the multiple views (different ways of looking at the time series) do not actually measure the same underlying truth, the embeddings are confused and the hierarchy reflects noise, not real structure.
Done right. When the hierarchy is deep enough, codes are crisp and diverse, and the views are well-chosen, the LLM follows a clear reasoning path and generalizes to new datasets without retuning the prompts.
What a runnable demo should prove

What a runnable demo should prove

Write a small experiment on two datasets (e.g., a finance time series and a medical sensor series). Train Hi-Time's embedding and code hierarchy on each. Show that the learned hierarchies are different — the finance one emphasizes volatility layers, the medical one emphasizes periodicity layers. Then compare: (1) zero-shot LLM prompt accuracy on both datasets (will be low and require manual retuning), (2) Hi-Time's LLM accuracy after the automatic hierarchy is injected (should be high for both, without rewriting prompts). The demo proves that the automatic hierarchy generalizes where hand-written reasoning does not.

generalization_gain = (hi_time_accuracy - baseline_accuracy) / baseline_accuracy * 100 percent

When the generalization gain is consistently positive across both datasets without prompt retuning, you have proven that the hierarchy automatically adapts to dataset structure rather than requiring human redirection.
