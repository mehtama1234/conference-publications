QWHA: Walsh-Hadamard Adapters for Quantized LLMs

Reduce quantization errors in compressed language models by placing adapter parameters where the errors bite hardest, using a fast integer-friendly transform.

Paper explainersAll themesEfficiency & Systems

When you shrink a language model to save memory and speed, you round its internal weights down. That rounding noise breaks the model's accuracy. This paper adds a small learnable adjustment layer (an adapter) that runs in a special fast number-space called Walsh-Hadamard. The adapter learns which parts of the model got hurt by rounding and fixes them first.

Zero assumption version

Shrunk models are broken, but adapters have weak muscles

When you ship a language model to run on someone's phone, you shrink the internal numbers. Instead of storing weights as precise decimals, you store them as integers (like 4 bits each). This cuts memory in half because integers take less space than decimals, and it speeds up the math because integer multiplication is faster on the hardware. But the rounding introduces noise—small random errors in every calculation.

A beginner's first fix: add a small adapter (a learnable layer). Low-rank adapters are cheap to train but too weak; they can only make rank-2 or rank-4 adjustments, missing most of the damage. Fourier-based adapters (using a special transform) have more muscle, but they waste computation when integrated into shrunk models, and they fail to target the places where rounding hurts most.

The paper's move: Allocate adapter parameters only to the weight channels (slices of the model) that got the biggest rounding errors, using a fast integer-friendly transform.

What the paper changes

What the method changes

The paper changes where and how an adapter allocates its learnable parameters inside a shrunk (low-precision) model. Instead of spreading them uniformly or choosing them randomly, it places them in high-error zones and carefully sets their initial values to directly counteract the rounding noise.

the object it moves  =  Adapter parameter allocation
The hidden quantity

The hidden quantity: Quantization error per channel

measured quantity  =  Channel-wise error magnitude

When weights are rounded to integers, each layer's output channel gets a different amount of damage. This paper names and measures that channel-wise error: for every output neuron, it computes the squared distance between the quantized output and the true output.

The paper estimates this quantity by running a forward pass through the pre-trained model on a sample batch, recording the layer outputs before and after quantization, and computing the per-channel sum of squared differences. It then uses this measurement to decide where to put adapter parameters.

Why it works

Why it works: Target the damage, fix it fast

When you quantize a model, you lose precision everywhere. But some neurons (channels) lose much more than others. A naive low-rank adapter spreads its learnable parameters uniformly—it has to fix everything with the same weak tool.

QWHA's move: (1) It measures where quantization hurt the model most (which channels have the biggest output errors). (2) It allocates more adapter parameters to those high-error channels and fewer to already-okay channels. (3) For each channel, it solves a tiny optimization problem (using Walsh-Hadamard, which is fast) to pick the exact values those parameters should have. The result is that the adapter immediately starts from a good place (error-reducing initialization) and has enough capacity to actually fix the noise, not just smooth it.

The Walsh-Hadamard Transform itself is key: it's a fast integer-friendly change of basis. It lets you reformulate the error-reduction problem so it splits cleanly by channel and can be solved in microseconds instead of milliseconds.

Math after the picture

The channel-wise error minimization

First in words:

For each output channel i, choose which p_i adapter parameters to activate and what values they should have to minimize the sum of squared differences between the quantized layer output and the true output.

Then the compact form:

minimize (over c, E): sum_i ||Delta_WQ_i @ H @ F_i - 0||_2^2, where F_i = Scatter(c_i, E_i) and |E_i| = p_i

Every symbol:

Delta_WQ_iThe quantization error matrix for output channel i
HThe Walsh-Hadamard Transform matrix (pre-computed, reused across layers)
F_iThe adapter matrix for channel i, built from selected parameter locations E_i and their values c_i
Scatter(c_i, E_i)A function that places the values c_i at the index positions E_i and leaves all other entries zero
p_iThe parameter budget (count) for channel i, allocated higher if channel i has large quantization error
A tiny worked example (one channel, 3 parameters out of 8 budget)
Quantization error for channel i: ΔW_Q_i has squared norm 16.0 (large damage).
Transform to Walsh-Hadamard: [spectral coeff] = [2.0, 0.5, 1.5, 0.8, 2.2, 0.3, 1.1, 0.6].
Select parameters: Pick top 2 by magnitude [2.2, 2.0] and 1 random [0.8], total p_i = 3.
Solve for values: Regression gives c_i = [0.15, 0.22, -0.08].
Apply correction: F_i @ X reconstructs the true output; squared error drops from 16.0 to 2.1.

The Walsh-Hadamard Transform turns a dense optimization into independent per-channel problems, so you can solve them in parallel and get good numerical stability.

What can go wrong

What can go wrong

Sample batch is unrepresentative. If the batch you use to measure quantization errors does not cover the actual data distribution, the adapter will over-fix some channels and under-fix others. The fix: use a calibration set that spans the domain.
Parameter budget per channel is too tight. If you allocate only 1-2 parameters to a high-error channel, it may not have enough degrees of freedom to model the damage. The fix: increase the total budget or use adaptive rank allocation.
Quantization scheme changes post-training. If you calibrate for 4-bit quantization but later switch to 8-bit or use a different rounding rule, the adapter values may not transfer well. The fix: re-calibrate the adapter initialization.
Done right. Use a representative calibration set, ensure each high-error channel gets at least a few parameters, and verify the adapter initialization on the validation set before fine-tuning on task data.
What a runnable demo should prove

What a runnable demo should prove

Build a tiny demo: (1) Load a small 4-bit quantized model (e.g., LLaMA 1B). (2) Run a sample batch forward, compute per-channel quantization error. (3) Use the QWHA initialization algorithm (or a simplified greedy version) to allocate adapter parameters to high-error channels. (4) Train the adapter on a small task (e.g., sentiment classification on 100 examples). (5) Measure accuracy before adapter, after initialization, and after fine-tuning.

Error reduction = (error_after_init - error_after_quantization) / error_after_quantization; Training speedup = time_naive_adapter / time_QWHA

The demo must make it visible that the adapter's initialized state already cuts the shrinking error by 50%+ because it solves for parameter values that directly cancel the measured rounding noise, and that fine-tuning converges 2-3x faster than random initialization because it starts much closer to the final answer.
