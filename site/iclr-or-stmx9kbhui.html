Towards Improved Sentence Representations using Token Graphs

When pooling tokens into a sentence summary, connect them first, then listen to what each token says about the others.

Paper explainersAll themesRepresentation & Self-Supervised Learning

Models like GPT read text as individual tokens (pieces of words), and produce a number list for each token. To get a single summary of the whole sentence, you pick one token or blend them all equally. But tokens actually point to each other in systematic ways during reading; throwing that away loses information. GLOT recovers that structure using a simple graph: it connects each token to its neighbors, learns what the good connections say, and builds the summary from those refined tokens.

Zero assumption version

Tokens are connected, but pooling ignores it

When a large language model reads a sentence, it builds a number list for each word piece (called a token). These lists capture what each token means in context. To classify the whole sentence or compare it to others, you need a single number list, so you either pick the first token's list, or you blend all the tokens equally by averaging.

But a model's internal layers show that tokens are connected: each token learns to focus on nearby tokens to understand itself better, because reading is all about context—a word's meaning shifts depending on what comes before and after. (The model learns to score how relevant each other token is to the current token; high scores mean it learns to focus on those tokens.) Those connections get thrown away when you average. Important signal is diluted by unimportant tokens, and unimportant tokens get equal weight. A sentence full of rare noise tokens (like random words injected mid-sentence) breaks the averaging method entirely, because noise drowns out the signal like someone shouting random words during a conversation.

The problem in one sentence. Pooling methods that ignore token connections lose the relational signal and drown useful information in noise.

The algorithm as a flow

What it actually does

Step 1: Build a graph

Compare each token's number-list to every other token's list; connect nearby tokens.

Step 2: Message-passing

For each token, let its neighbors send messages (refined insights) along the edges.

Step 3: Fuse the view

Each token blends its own number-list with the messages it received.

Step 4: Pool smartly

Assign a weight to each token showing how much it matters to the summary.

Step 5: Make the summary

Blend the refined token-lists using the learned weights into one sentence summary.

What the paper changes

What the paper changes

Instead of averaging tokens equally (or picking one), the paper learns a weighted blend guided by a graph of token connections.

the object it moves  =  pooling method
The hidden quantity

Token importance in the graph

measured quantity  =  token relevance to sentence meaning

The paper does not measure a single number per token, but rather a set of learned weights over the graph edges (connections) and a readout weight per token. The readout weight shows how much that token matters to the final summary. In plain terms: which tokens carry the sentence's meaning, and which are noise or filler?

GLOT learns this by routing messages through the graph. Tokens that receive consistent signals from their neighbors get higher readout weights; tokens that are isolated or noisy get lower weights. The paper never explicitly defines a single named 'importance score' per token, but the learned graph structure and readout layer jointly assign importance.

Why it works

How token graphs preserve meaning

The core insight is that a sentence's meaning lives in the connections between tokens, not the tokens alone. When you average all tokens equally, you give a vote to every token—including distractors. GLOT instead asks: which tokens agree with their neighbors? A real token about the sentence's topic will receive consistent signals from nearby tokens that reinforce its meaning, because those neighbors also care about that token. A noise token will stand out as isolated or contradictory, because it does not fit the pattern the neighbors are building.

The graph neural network amplifies these patterns. Tokens that sit in a cluster of similar neighbors (their number-lists are close together) receive stronger refined representations, because the messages they get reinforce each other. Tokens that are outliers get weaker ones, because their neighbors send contradictory or weak signals. The readout layer then learns which refined tokens to include in the summary. The result: the summary captures the consensus of the token network, not a poll of every voter equally.

This works well because a few key tokens can carry the full meaning, and the graph learns which ones those are through message-passing. Noise becomes background chatter that gets filtered out by consensus. This is why GLOT holds up under a stress test: 90% random distractors fail to fool a system that listens to what the remaining 10% say to each other, because the 10% real tokens will form a coherent cluster while the noise tokens are spread out and isolated.

Math after the picture

The pooling equation

First in words:

sentence-summary = sum over tokens of (readout-weight for this token) times (refined-representation of this token)

Then the compact form:

s = sum_i w_i * r_i, where r_i = TokenTokenFusion(token_i, neighbors_via_graph)

Every symbol:

sthe final sentence summary (a list of numbers)
w_ilearned weight showing how much token i matters
r_irefined representation of token i after hearing neighbors
TokenTokenFusionthe graph neural network step that fuses a token's own list with messages from neighbors
A tiny worked example
Suppose a 4-token sentence: token_1, token_2, token_3, token_4.
After graph GNN and readout learning, suppose weights are: w_1 = 0.05, w_2 = 0.40, w_3 = 0.30, w_4 = 0.25.
token_1 is noise (weight 0.05). token_2 and token_3 matter most (0.40 and 0.30). token_4 is medium (0.25).
If each refined token-list has 768 numbers (like BERT), the summary s is: 0.05 * r_1 + 0.40 * r_2 + 0.30 * r_3 + 0.25 * r_4.
Compare to naive pooling: 0.25 * r_1 + 0.25 * r_2 + 0.25 * r_3 + 0.25 * r_4. The noise token loses 80% of its influence.

The readout weights are learned during training to make the summary useful for downstream tasks; the graph GNN learns to make the refined tokens informative.

What can go wrong

What can go wrong

Very long sentences break graph learning. If a sentence is too long (hundreds of tokens), computing similarity between every pair and running GNN grows too slow. The method assumes tokens can see their neighbors; in very long contexts the graph might get sparse or noisy.
Poor token representations ruin the graph. If the model's token-lists (the number-lists that encode what each token means) are of low quality or misaligned, the graph will connect the wrong tokens. GLOT is only as good as the frozen language model it wraps.
Fine-tuning on a small dataset can overfit. The readout layer and GNN are new learnable numbers (parameters, or weights to be trained). If the downstream task has very few labeled examples, these new layers might memorize random noise rather than learn the real token structure.
Done right: tuned on realistic benchmarks. On standard sentence tasks (GLUE, MTEB), the paper is competitive with methods that fine-tune the whole model, but using far fewer trainable parameters and wall-clock time.
What a runnable demo should prove

What a runnable demo should prove

Build a simple sentence classifier (e.g., sentiment or topic). Freeze a pretrained model like BERT or sentence-BERT, add GLOT pooling on top. Compare against baseline pooling (mean, max) on the same frozen model. Deliberately inject random noise tokens (garbage words) into test sentences at increasing rates (0%, 25%, 50%, 75%, 90%). Measure accuracy as noise increases.

robustness = accuracy on clean examples minus accuracy on noisy examples

The demo should make clear that GLOT stays accurate as noise floods in, while baseline pooling collapses—because GLOT listens to what tokens say to each other, not to every voice equally.
