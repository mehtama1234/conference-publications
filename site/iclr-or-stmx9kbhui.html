Towards Improved Sentence Representations using Token Graphs

Instead of averaging tokens equally, GLOT learns which tokens matter and which are noise by treating them as a connected graph.

Paper explainersAll themesRepresentation & Self-Supervised Learning

When you ask a large language model a question, it outputs a hidden state (just a list of numbers) for every single unit of input (a word or punctuation mark), including filler words like the. To get one sentence-level answer, you normally average all these unit numbers together. But that treats garbage and gold equally. GLOT fixes this by first building a graph of which units are similar to each other based on patterns the model learned, then uses that graph to learn which units actually contain the signal.

Zero assumption version

The averaging problem: noise drowns out signal

A large language model processes text token by token (each token is a word or punctuation mark). For every token, the model outputs a vector of numbers representing what it learned about that token's meaning and role. When you need a single sentence-level representation, the standard trick is to average all these token vectors together, treating them equally.

But text is messy. A sentence contains filler words (the, a, is), punctuation, padding tokens added by the model, and sometimes tokens added as random noise during training. Averaging treats the padding and the key word identically. It is signal dilution: useful information gets buried under noise, so the final answer is watered down and less accurate than it should be.

A beginner might try: Just average all token vectors together, or take the [CLS] token. But this weights noise equally with meaning.

The algorithm as a flow

What it actually does

Start with frozen model outputs

Take the hidden states (the lists of numbers) for each token.

Build a similarity graph

Compute which tokens are similar; connect them if similarity is high.

Refine with relational learning

A graph neural network (a small network trained only on this task) learns to sharpen important tokens and blur the noise.

Compute importance scores

For each refined token, a small neural network outputs a number saying how much that token matters.

Weighted sum

Multiply each token vector by its importance score and add them up; the result is one sentence-level vector.

What the paper changes

The one thing that changes: token importance weights

Standard pooling assigns the same weight to every token: either equal (mean), or fixed (take only the [CLS] token). GLOT computes a learned, learnable importance score for each token. The graph tells the neural network which tokens are noise; it responds by giving them tiny weights.

the object it moves  =  Token importance weights
The hidden quantity

The hidden quantity: token graph centrality

measured quantity  =  Token centrality in the similarity graph

A graph is a collection of nodes (tokens) and edges (connections). When two tokens are similar, the graph connects them. A token that is similar to many others is central in that graph; a token that connects to few others is peripheral. Peripheral tokens are likely noise or filler.

GLOT does not explicitly measure centrality, but it learns it implicitly. The graph neural network receives the graph structure as input and adjusts each token's representation. Central tokens (those with many high-similarity connections) end up with larger importance scores because the network learns that similarity to many other tokens is a sign of signal. Peripheral tokens fade.

Plain reading. A token that matches the meaning or role of many nearby tokens is probably real; a token that is isolated is probably noise.
Paper reading. Tokens are refined by passing them through multiple layers of a small neural network trained specifically for this task. Each layer updates a token's vector by blending information from its neighbors in the graph. A token connected to many others receives information from many neighbors; the more neighbors, the larger the total adjustment, so central tokens shift more than isolated ones. This is why central tokens end up with stronger, more refined representations.
Why it works

Why learning a graph works: structure reveals substance

A large language model already knows which tokens matter. It learns this through self-attention: the model computes a similarity score between every pair of tokens, and in those scores, real tokens tend to attend to each other. Real tokens also have consistent meaning across contexts; noise does not.

GLOT exploits this by asking: if we build a graph where tokens are connected by the model's own learned similarities, can we use that structure to identify which tokens are truly important? The answer is yes, because signal in language is relational. A noun relates to adjectives that describe it, verbs that act on it, and arguments that fill its roles. Noise (padding, random distractors) does not participate in these relationships. When you run a graph neural network on this structure, it learns to amplify tokens with strong relational signatures and suppress isolated noise.

The weighted pooling equation

First in words:

For each token i, a score network outputs a number m_i. Softmax converts these into weights that sum to 1. The final representation is the weighted sum of refined token vectors.

Then the compact form:

z = sum_i [ (softmax(m_i)) * u_i ]

Every symbol:

zFinal sentence-level representation (the output)
u_iRefined representation of token i after GNN
m_iImportance score for token i (before normalization)
softmax(m_i)Normalized weight for token i; all weights sum to 1
A tiny worked example
Suppose 5 tokens: vectors u1, u2, u3, u4, u5; scores m1=5.0, m2=2.0, m3=0.5, m4=4.0, m5=1.0.
Softmax: exp(5.0)=148, exp(2.0)=7.4, exp(0.5)=1.6, exp(4.0)=55, exp(1.0)=2.7; sum=215.
Weights: w1=148/215=0.69, w2=7.4/215=0.03, w3=1.6/215=0.01, w4=55/215=0.26, w5=2.7/215=0.01.
Tokens 1 and 4 (the important ones) get 69% and 26%; noise tokens get 1% each.
Final z = 0.69*u1 + 0.03*u2 + 0.01*u3 + 0.26*u4 + 0.01*u5 (mostly signal, little noise).

Softmax automatically converts any real-number scores into fractions that sum to 1, so high-scoring tokens dominate the average.

What can go wrong

What can go wrong

The token-similarity graph is unreliable if tokens are poorly represented. If the frozen LLM's hidden states do not capture real token relationships well, the graph will have false edges and the GNN will learn wrong importance scores. This is rare with modern LLMs but possible with very small or poorly trained ones.
Threshold tuning: setting the edge threshold too high or low changes which tokens connect. If the threshold (the minimum similarity needed to connect two tokens) is too strict, real-token relationships disappear. If too loose, noise tokens form false clusters. The paper uses 0.1 to 0.6 and searches over this range.
Only works on frozen models. GLOT fine-tunes only the pooling head, not the LLM backbone. If the backbone is too small or poorly initialized, the hidden states are weak to begin with; GLOT cannot manufacture good signal out of bad input, so the best it can do is extract what little signal is already there without adding more noise.
Done right: careful hyperparameter search. The paper validates that learning rates, graph layers, and the similarity threshold matter; searching over the right range (learning rate 1e-3 to 2e-5, GNN layers 2 to 4, threshold 0.1 to 0.6) consistently beats baselines.
What a runnable demo should prove

What a runnable demo should prove

Build a small experiment: take a frozen LLM (e.g. BERT or Mistral), generate sentence embeddings for a classification task (e.g. sentiment), and compare mean pooling vs GLOT. Then add random noise tokens to 30%, 50%, 70%, 90% of the input and re-measure. Plot accuracy for each pooling method. GLOT should stay flat; mean pooling should crash.

Robustness = accuracy_with_noise / accuracy_without_noise (higher is better; 100% means immune to noise)

When 90% of the input is garbage, mean pooling collapses to random guessing; GLOT should still hit 95%+ accuracy.
