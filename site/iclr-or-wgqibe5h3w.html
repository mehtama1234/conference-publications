ResCP: Reservoir Conformal Prediction for Time Series

A training-free method that uses a simple fixed network and similarity scores to build honest prediction intervals for forecasts that automatically adapt as data changes.

Paper explainersAll themesTime Series & Sequential

When you forecast the next value in a time series (like tomorrow's stock price), you want a confidence band around your guess, not just a single number. Conformal prediction is a mathematical tool for building these bands so that they are honest: they cover the true answer with a guaranteed probability. But for time-series data, existing methods either need a lot of examples or must be expensively retrained when the world shifts. This paper introduces ResCP, which skips the expensive training and instead uses a simple, fixed network to spot when the current moment is similar to past moments, then reweights the error estimates accordingly.

Zero assumption version

Why honest forecasts are hard to build fast

Suppose you build a time-series forecaster that predicts tomorrow's sales. It guesses 105 units. You want to say: I am 90% sure the true sales will fall between 95 and 115. But how do you know? You need to measure how often your forecast is wrong, and by how much.

Conformal prediction is the mathematical way to do this. You keep a list of past prediction errors, then at each new step, you ask: what error would be big enough to be in the top 10% of all past errors? That error becomes your confidence band width. This guarantees coverage mathematically, with no assumptions about whether your data is normal or strange.

The problem: when you forecast time series, the pattern of errors changes over time. Sales spike in December; they drop in July. When errors are bigger, you want wider bands; when they are small, you want narrower bands. If you naively use all past errors equally, your bands will be too wide when things are calm and too narrow when they are volatile. So existing methods fit a complex model to learn which time steps have which error patterns (a neural network or Gaussian process) so that errors can be reweighted based on the time of year. But this is expensive: it needs many examples to fit well, and when the true data pattern shifts, you must retrain everything.

The core challenge. How to build honest confidence bands for forecasts on time series without fitting an expensive model and without needing to retrain when conditions change?

The algorithm as a flow

What it actually does

Feed the time series into a reservoir

A reservoir (just a fixed, random network that does not learn) converts the history into a compact list of numbers that summarizes what it has seen so far.

Compute similarity to all past states

Measure how close the current reservoir state is to each past state: same pattern, or different?

Reweight past errors by similarity

Errors from recent states that look like now get higher weight; dissimilar states get lower weight.

Find the confidence threshold

Sort the reweighted errors and pick the percentile that guarantees your desired coverage (e.g. top 10% for 90% confidence).

Output forecast with band

Report the prediction plus-or-minus the threshold width as the honest interval.

What the paper changes

What the paper changes

The paper changes how past prediction errors are weighted when building confidence bands. Instead of fitting an expensive model to learn the weights, it uses a pre-set, untrained network (the reservoir) to compute similarity scores, then reweights each past error by how similar its context was to now.

the object it moves  =  error weighting scheme
The hidden quantity

The hidden quantity: temporal similarity

measured quantity  =  Similarity between reservoir states

The paper measures something implicit but critical: how similar is the current moment to each past moment? It does this by running both through a reservoir (a random, fixed network that you never train) and measuring the closeness of the resulting lists of numbers that the network produces.

The paper uses this similarity score to reweight past errors. If a past error came from a moment very similar to now, that error is weighted high. If it came from a very different moment, it is weighted low. This ensures that the set of errors the paper uses to build confidence bands reflects only the moments that looked like now, making the bands honest and tight for the current context.

Why it works

Why it works: the causal chain

The core insight is that time series have structure: moments that look alike tend to have similar patterns of errors. By weighting past errors according to similarity, ResCP uses only the errors that are relevant to right now, rather than all past errors equally.

Why does a frozen, untrained network suffice? Reservoir computing works because a random, high-dimensional network can separate different input patterns into distinct regions, even without training. You do not need it to be perfect at prediction—you only need it to group similar moments together. This grouping naturally works for many time series without any task-specific learning, because randomness itself is a form of dimensionality: adding enough random features makes it almost certain that different patterns will land in different places.

Because the reservoir is never trained, there are no numbers to update when the data pattern shifts. The confidence bands adapt automatically because the reweighting is recalculated fresh at each step from scratch. When a new moment arrives, its similarity to past moments is computed instantly, errors are reweighted instantly, and the band is set instantly. This means no training cost (fast) and automatic adaptation (adaptive): the bands reshape themselves at each step, always using the current similarity scores, with zero overhead.

Math after the picture

The equation: reweighted quantile

First in words:

The confidence band at time t is set by taking the weighted percentile of past errors, where each error is weighted by how similar its moment was to now.

Then the compact form:

q_alpha(t) = arg min_{q} sum_i w_i(t) * I(|residual_i| <= q), where w_i(t) = exp(-beta * d(h_t, h_i))

Every symbol:

q_alpha(t)the confidence band width (prediction interval half-width) for time t
w_i(t)weight of past error i at time t
d(h_t, h_i)distance (dissimilarity) between reservoir state at time t and past time i
h_treservoir state vector at time t
residual_ithe observed error at past time i
betatemperature parameter controlling how fast similarity decays with distance
I(·)indicator: 1 if true, 0 if false
alphatarget miscoverage rate (e.g. 0.1 for 90% coverage)
A tiny worked example
Suppose you forecast at time 50. The reservoir state at time 50 has Euclidean distance 0.2 from time 45 and distance 2.0 from time 10.
With beta = 2, the weight for error_45 is exp(-2 * 0.2) = exp(-0.4) = 0.67, and weight for error_10 is exp(-2 * 2.0) = exp(-4) = 0.018.
If error_45 was 5 units and error_10 was 4 units, the weighted percentile heavily favors error_45 (weight 0.67) over error_10 (weight 0.018).
This means the confidence band reflects the recent, similar errors, not distant history.

The formula says: for each time step, reweight all past errors by how similar their context was to now, then pick the threshold that covers your target fraction.

What can go wrong

What can go wrong

Reservoir does not separate dissimilar patterns. If all past moments look equally similar to the reservoir, similarity weighting has no effect. This happens if the time series has no repeating structure, or if the reservoir is configured too coarsely. The method then degrades to equal weighting, covering correctly but not adapting.
Extreme nonstationarity defeats similarity matching. If the data pattern changes so drastically that nothing in the past resembles now (e.g., a sudden market crash where volatility jumps 10-fold), similarity scores cannot rescue you because there are no similar past moments to learn from. You need at least some past errors that came from moments similar enough to the present.
Reservoir initialization is random. The quality of similarity matching depends on which random network you draw. Different random seeds may cause some similar moments to land far apart in the state space and different moments to land close together. Running a few different random reservoirs and averaging their results can smooth this out, because a majority of random reservoirs will separate patterns correctly; this trades a small increase in computation for stability.
Done right: asymptotic guarantees hold. The paper proves that under mild assumptions (exchangeability within temporal contexts), ResCP's coverage approaches your target level as more data arrives. It does not require the reservoir to be perfect, only good enough to group similar moments.
What a runnable demo should prove

What a runnable demo should prove

Build a simple time series with a known, repeating pattern (e.g. daily seasonality: high in morning, low at night, with random noise). Then build a naive forecaster (e.g. last value, or simple exponential smoothing). Apply ResCP to generate 90% prediction intervals. Compare the interval width and coverage rate across three time windows: (1) a calm period with low noise, (2) a volatile period with high noise, (3) a period where the pattern shifts slightly (e.g. the peak time moves). Measure how ResCP's interval width and true coverage rate change across these windows.

coverage_rate = (number of true values inside interval) / (total forecasts), interval_width = average of (upper_bound - lower_bound)

The demo must show that ResCP adapts its interval width to match local volatility: wide bands when noise is high, narrow bands when it is calm, without any retraining.
