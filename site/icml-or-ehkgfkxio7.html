PosterAgent: Iterative Design via Agentic Reinforcement Learning

A poster-making system learns to draft and then refine designs through trial and error, with different learning rules for each stage.

Paper explainersAll themesAgents & Tool Use

Posters demand two competing skills: visual beauty and clear, readable text—neither of which text-to-image models handle well. This paper treats poster design as an agentic workflow: first draft a layout, then refine it step by step, guided by feedback. It uses a new learning method (Stage-Aware RL) that trains drafting and refinement as separate goals, because the two tasks require opposite skills: drafting needs risk-taking and exploration, while refinement needs precision and caution.

Zero assumption version

Why one-shot design fails

Today's text-to-image models (systems that generate pictures from descriptions) can create beautiful images, but they cannot be edited afterward—if the text is unreadable or the layout is off-balance, you cannot fix it. They also consistently render text poorly: letters blur or distort.

Layout-generation methods (algorithms that arrange elements on a page) handle readable text and clear structure better than text-to-image models do, because they are designed to place text as separate objects instead of painting it. But they predict the entire design in one pass and stop. They have no loop to look at their own work and then make targeted improvements. This is a hard constraint because their architecture makes all decisions at once—they have no second chance, so if the initial prediction is imbalanced or unreadable, there is no way to improve it. A designer working on paper can sketch, judge, erase, and sketch again; these methods cannot.

The core problem. Current methods are either beautiful but unfixable, or editable but static. Neither learns to iterate.

The algorithm as a flow

What it actually does

Step 1: The agent drafts a full layout

Starting from a brief and content list, generate an initial poster with text placement and element sizes.

Step 2: Score the draft against design rubrics

Measure readability, visual balance, and hierarchy; assign a score reflecting how close it is to professional.

Step 3: Extract what failed

From the score and design rules, identify which text is too small, which blocks clash, which layout principles were violated.

Step 4: Execute targeted refinements

Adjust element sizes, reposition text and images, tweak spacing—each move targets a specific failure.

Step 5: Repeat feedback-and-refine until done

Loop steps 2–4 until the score plateaus or reaches a professional threshold.

What the paper changes

What the agent learns to move

The agent controls two kinds of actions: placing and sizing elements during drafting (boxes, text height, images), and making small adjustments during refinement (nudging positions, changing font size, rebalancing padding). The trick is that these two action sets require different learning strategies: drafting rewards risk and exploration (try new layouts), while refinement rewards precision (fix one problem without breaking others).

the object it moves  =  design actions (layout positions and element sizes)
The hidden quantity

Credit: which action fixed which mistake

measured quantity  =  credit assignment (which action caused which score improvement)

Reinforcement learning works by trial and error: try a move, see if it improved the outcome, and if so, do it more often. To do that reliably, the system must link each move to the part of the outcome it caused—otherwise it cannot tell which moves are good and which are harmful. If it drafts a messy layout and then refines it twice, with scores going 40 to 80, the question arises: did the first refinement move do most of the work, or the second, or were both equally important? Without a clear answer, the system cannot learn which kinds of refinements actually work in the future because it is trying to learn from a blurry signal—the learning algorithm cannot tell whether the score improved because the draft was good (meaning refinement had easy work) or because the refinements were skillful (meaning they had to fix a bad draft). This matters because the system's next draft will be influenced by whichever action it thinks was responsible.

The paper introduces stage-aware credit assignment: instead of treating all actions as equivalent, it learns separate value functions (scoring rules) for drafting and refinement. A drafting action is judged by the question: 'did this initial move leave room for refinement to succeed later?' A refinement action is judged by: 'did this tweak fix a specific problem without breaking something else?' By splitting credit this way, each kind of action gets a clear signal: draft actions see whether their layout is refinable, and refinement actions see whether their fix actually worked. The learning becomes focused instead of confused because now each value function has a single, unambiguous signal to learn from.

Why it works

Why stage-aware learning works

In standard reinforcement learning, the system sees a sequence of actions (draft, then refine, refine, refine) and a final score. It must assign credit backward: which action caused which part of the score? This is ambiguous when actions serve very different purposes.

The paper's insight: drafting and refinement are two distinct jobs. A good draft is not a beautiful design—it is a sketch that leaves room for refinement to work. A good refinement is a small targeted fix that improves one aspect without breaking others, because large changes risk cascading breakage and undo earlier fixes. These are opposite skills: drafting rewards exploration and openness, refinement rewards precision and caution. By learning two separate value functions (one asking 'is this draft refinable?' and one asking 'does this tweak improve things?'), the system avoids ambiguity because each value function sees a clear, single goal. Draft actions get signal on whether the layout is improvable; refinement actions get signal on whether each fix actually worked. This focused learning is faster and more reliable because the system is not trying to optimize two contradictory signals at once.

Math after the picture

Stage-Aware RL loss

First in words:

Loss for drafting actions plus loss for refinement actions. Drafting loss rewards states that leave room to improve. Refinement loss rewards moves that actually improve the score. Total loss is the weighted sum of both.

Then the compact form:

L_total = lambda_d * L_draft + lambda_r * L_refine, where L_draft = (V_draft(s_t) - (gamma * V_draft(s_t+1) + r_draft_t))^2 and L_refine = (V_refine(s_t) - (gamma * V_refine(s_t+1) + r_refine_t))^2

Every symbol:

V_draft(s_t)how good is this draft state for setting up refinement
V_refine(s_t)how much improvement can a refinement move make from here
r_draft_treward for drafting (potential for future improvement)
r_refine_treward for refinement (actual score improvement)
gammahow much we value future score improvements versus immediate ones
lambda_d, lambda_rweights balancing how much drafting and refinement matter in training
A tiny worked example
Start: empty poster, V_draft = 0 (no structure yet).
Draft action: place text box and title. Reward is whether this draft looks refinable (e.g., text is placed but wrong size). V_draft goes to 50 (moderately refinable).
Refinement action 1: enlarge title text. Score jumps from 30 to 55. V_refine earns +25 reward for this move.
Refinement action 2: rebalance padding. Score jumps from 55 to 78. V_refine earns +23 reward.
Each stage's value function sees its own clear signal: drafting saw 'this setup is refinable' (V_draft improved), refinement saw 'this tweak worked' (score improved). No ambiguity about which action caused which gain.

Splitting the value function by stage means drafting is judged on setup potential, not final beauty, while refinement is judged on actual fixes—removing the confusion that arises when one training signal must cover both jobs.

What can go wrong

What can go wrong

Drafting too timid. If the learning heavily penalizes risky drafts, the agent learns to place everything in the safest, most boring arrangement, where refinement cannot do much. Stage-aware RL avoids this by rewarding draft-potential, not final score, but if tuned wrong it can still happen.
Refinement becomes surface-level. If refinement actions are tiny nudges (shift by 2 pixels, shrink by 1 point), the system cannot make deep fixes, so large improvements become impossible. Credit assignment might be correct, but the action space does not allow big-enough changes because the system cannot nudge far enough to change the core mistakes—if text is placed in the wrong area, moving it by 2 pixels will not fix it. The system learns precise movements but cannot fix core design mistakes.
Stage boundaries are strict. The paper treats drafting and refinement as distinct. If the optimal strategy is to interleave small drafts with instant feedback, the two-stage separation may not discover that.
Done right. When stage-aware credit and a sufficiently varied action space are balanced, the system learns to sketch bold, explorable layouts and then execute precise, targeted fixes. Drafting learns to place elements in ways that give refinement room to work, and refinement learns which kinds of adjustments actually fix things.
What a runnable demo should prove

What a runnable demo should prove

Build a simple poster-design arena: given a random brief (headline, 3 bullet points, one image), the agent drafts a layout, scores it on three rubrics (text readable, elements balanced, hierarchy clear), then refines twice and shows the before-and-after. Train the agent on 100 random briefs using standard RL (one value function) and stage-aware RL (two value functions) in parallel. Measure: (1) average score after all refinement loops, (2) how much each stage contributes to quality improvement (draft refinability score plus refinement improvement score), (3) how many refinement loops before the score stops rising.

final_score = baseline_score + sum_refine_i (score_i - score_i-1), where each refinement is a distinct contribution

The demo must show that stage-aware RL learns designs that are refinable (good draft setup) and actually improve under refinement (good adjustment skill), because separating the credit signal lets each stage specialize. Whereas single-value-function RL tends to learn either scared drafts (unrefined but safe, because exploration looks risky) or wasteful refinements (fine-tuning without foundation, because safe baseline looks better than risky setup).
