SeRI: Gradient-Free Sensitive Region Identification

SeRI finds which pixels matter most for fooling a neural network by testing tiny image regions, without access to the network's internal workings.

Paper explainersAll themesAlignment, Safety & Fairness

Deep neural networks can be tricked into making mistakes by adding tiny changes to images — but figuring out which pixels to change is hard when you can only see the final guess, not the network's confidence. SeRI solves this by recursively testing small image regions and measuring how much each pixel contributes to the mistake.

Zero assumption version

Why finding sensitive pixels is stuck

A neural network's guess changes when you alter an image, but not all pixels matter equally — some regions are sensitive (changing them flips the prediction), while others barely affect the output. A beginner might try: nudge each pixel one at a time and check if the network's answer changes. But if you only see the top-1 label (yes, it flipped; no, it didn't), this is blind work — you learn nothing about how much each pixel contributed, only whether it broke the prediction. With a strict limit on how many times you can query the network (say, 1000), this one-at-a-time approach is wasteful and gives you only binary answers (flip / no flip), not a ranking of importance.

The real problem: you have no gradient (no internal access to the network), no confidence scores (only the winning class label), and a tight query budget. How do you build a map of pixel importance without burning queries on thousands of individual tests?

In one sentence. SeRI tests image regions by nudging them up and down, then compares the network's decision boundary to score each pixel's sensitivity, all with queries only.

The algorithm as a flow

What it actually does

Partition coarsely

Divide the image into large grid cells.

Generate perturbations

For a selected region, create two versions: pixels scaled up (stronger) and down (weaker), because comparing both directions reveals whether the region straddles the decision boundary.

Query and compare boundaries

Feed both perturbations to the network; if predictions differ, the region is sensitive.

Score the region

Use the comparison result to assign a continuous sensitivity score, not just binary.

Recurse and refine

Split sensitive regions into finer sub-regions and repeat, building a detailed map.

What the paper changes

What the paper changes

SeRI assigns a continuous sensitivity score to each pixel. Prior methods either picked important regions as binary selections (sensitive or not) or required confidence scores (which are unavailable in this setting). SeRI instead compares decision boundaries to generate a smooth ranking without them.

the object it moves  =  Pixel sensitivity scores
The hidden quantity

Pixel sensitivity: how much each pixel matters

measured quantity  =  Pixel sensitivity

Pixel sensitivity is a number measuring how much changing a single pixel (or a small region) affects the network's prediction. In most machine learning, you can measure sensitivity using gradients (which way does the output move if I nudge this weight). But in a black-box setting with only labels, gradients are invisible. SeRI instead measures sensitivity indirectly: it perturbs regions, observes whether the prediction flipped, and uses those boundary crossings to infer each pixel's importance.

If boosting a region changes the prediction at a different scale than shrinking it does, then that region straddles the decision boundary and is sensitive. SeRI captures this as a continuous score by comparing the up and down perturbations.

Why it works

Why the boundary-comparison trick works

A neural network's decision boundary is the invisible line separating examples it classifies as one class from examples it classifies as another. If you perturb a region and the network's output flips (from panda to bird), you crossed that boundary. If you perturb in two directions (boost and shrink) and only one flips the output, then the region is close to the boundary and sensitive, because the asymmetry in which direction triggers the flip reveals that the region's effect straddles the boundary.

SeRI exploits this: for each region, it generates a boosted version (stronger signal) and a shrunk version (weaker signal), then queries both. The way the predictions differ tells you whether that region straddles the boundary, because an asymmetric response (one flips, one does not) is a signature of boundary proximity. By comparing these two queries, SeRI infers a sensitivity score without ever seeing confidence scores or gradients. It then recursively refines, splitting sensitive regions into finer cells and repeating the test, zooming into the true sensitive areas with surgical precision.

Math after the picture

The sensitivity equation

First in words:

Score a region's sensitivity by comparing the boundary crossings from boosted and shrunk perturbations. If the scaled-up version flips the prediction and the scaled-down version does not (or vice versa), the region is at or near the decision boundary.

Then the compact form:

S_region = I(pred(img_boosted) != orig_label) - I(pred(img_shrunk) != orig_label)

Every symbol:

S_regionSensitivity score for this region (continuous, ranges 0 to 1)
pred(img)The network's predicted class for a given image
orig_labelThe original, correct class label
img_boostedThe image with this region's pixels scaled up (multiplied by factor > 1)
img_shrunkThe image with this region's pixels scaled down (multiplied by factor < 1)
I(...)Indicator function: 1 if true, 0 if false
A tiny worked example
Region A (panda's eye): boosted predicts 'bird' (flipped, indicator = 1), shrunk predicts 'panda' (no flip, indicator = 0). S_A = 1 - 0 = 1 (highly sensitive).
Region B (background): boosted predicts 'panda' (no flip, indicator = 0), shrunk predicts 'panda' (no flip, indicator = 0). S_B = 0 - 0 = 0 (not sensitive).
Region C (nose): boosted predicts 'bird' (flipped, indicator = 1), shrunk predicts 'bird' (also flipped, indicator = 1). S_C = 1 - 1 = 0? No — C is so sensitive it flips both ways; SeRI uses a refinement: if both flip, recurse into finer granularity.

SeRI scores regions by asking: does one direction (boost or shrink) flip the prediction while the other doesn't? That asymmetry means the region straddles the boundary.

What can go wrong

What can go wrong

Regions at the hard boundary are ambiguous. If a region is far inside the decision boundary (clearly belongs to one class), boosting and shrinking both keep the same prediction — SeRI cannot score it well. Recurse into finer granularity helps because subdividing exposes pixels that lie closer to the boundary, but very shallow regions near the boundary may still be underestimated if the perturbation scale is too coarse.
Scaling direction matters. If you scale a region up by 1.5x and down by 0.5x, but the perturbation is so small that neither crosses the boundary, you learn nothing. The paper requires choosing scaling factors wisely; wrong choices waste queries.
Recursive depth trades off precision and queries. Refining too deeply burns queries on tiny sub-regions; stopping too early misses fine structure. The paper does not fully specify how to choose stopping depth in advance.
Done right. SeRI works best on images where sensitive regions are spatially clustered (e.g., faces) and the perturbation scale is tuned per image. On cluttered or multi-scale content, the method degrades gracefully but queries rise.
What a runnable demo should prove

What a runnable demo should prove

Build SeRI on a small image (say, thirty-two by thirty-two or sixty-four by sixty-four pixels) and a simple trained classifier. Generate an adversarial example (a small perturbation that tricks the network into guessing the wrong class). Run SeRI to score each pixel. Visualize the sensitivity heatmap and measure how well it ranks the true perturbation's pixels as high-sensitivity. Compare to a baseline (uniform random importance or one-at-a-time guessing) on the same query budget.
