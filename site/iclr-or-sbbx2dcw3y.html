Multi-Scale Hypergraph Meets LLMs: Aligning for Time Series

Connect an LLM to time series by matching multi-scale patterns in both, using hypergraphs to group related time steps and prompts that explain the context.

Paper explainersAll themesTime Series & Sequential

Large language models (LLMs, like the kind that writes essays) can now help analyze time series data (sequences of numbers over time) because they can learn patterns from data just as they learn language structure. The trick is translating between language and numbers so the LLM understands. But real time series have patterns at many scales — a few hours, a day, a week, a month. Real language also works across scales. This paper shows how to align an LLM to time series by honoring both at every scale, not just at one size.

Zero assumption version

Why simple alignment fails

When you feed a time series to an LLM, you must first turn the numbers into words or tokens (small text fragments that the LLM reads). A naive approach: convert each time step into a token and send them all in. But this misses the real structure of time data. A naive split into chunks of 24 hours works for daily patterns but misses weekly or monthly trends. Another chunk size fits monthly patterns but blinds you to hourly changes. The LLM sees only one scale at a time.

Also, real language is inherently multi-scale: a sentence can discuss a trend in the data, then drill down to a specific hour, then zoom back out. A time series query has the same depth. If the LLM only sees one scale, it cannot answer questions that naturally span scales. A beginner's fix: send all chunks at once. The LLM chokes on too much input and loses track of priorities — hourly noise drowns out weekly signals.

The fix in one sentence. Build a multi-scale graph that connects time steps at different zoom levels, then align the LLM to reason at every scale at once.

The algorithm as a flow

What it actually does

Hyperedge construction

Group time steps into a graph where each node is a time step and edges connect steps at the same scale (hourly together, daily groups together).

Multi-scale encoding

For each time step, compute a small list of numbers that captures its meaning at each scale independently.

Cross-modality alignment

Map the encoded time series patterns into the LLM's internal number space (embeddings are lists of numbers) so the LLM recognizes the patterns as similar to ideas in natural language.

Scale-aware prompts

For each query, select which scales matter and feed the LLM a prompt that explains the context at those scales.

LLM reasoning

The LLM reads the aligned scales and the contextual prompt, then answers questions about trends, anomalies, or forecasts.

What the paper changes

What the paper changes

The paper modifies two things: first, how time series is encoded so that each scale is explicit (hourly, daily, weekly); second, which prompts are sent to the LLM so the model is told what scale to reason about.

the object it moves  =  time series encoding and prompts
The hidden quantity

Multi-scale alignment score

measured quantity  =  alignment score per scale

The hidden quantity is how well the time series patterns at each scale match the LLM's understanding at that scale. It is a single number for each scale (0 to 1), where 1 means the LLM correctly recognizes the pattern and 0 means the LLM is confused.

The paper estimates it by: first, converting the time series at that scale into tokens (small chunks); second, asking the LLM to predict the next token given the history; third, measuring how often the LLM's prediction matches the true next token. High accuracy means high alignment at that scale.

Why it works

Why matching scales at once makes predictions better

Real time series have structure at every zoom level. Hourly data wiggles randomly but follows a daily cycle (colder at night). Daily data looks choppy but a weekly pattern (less demand on weekends) is clear. Weekly data is noisy but a seasonal trend (summer vs. winter) shapes it. An LLM trained on language knows this multi-scale reasoning: a sentence discusses an idea, paragraphs develop it, chapters organize ideas into arcs. When you show an LLM time series encoded at only one scale, it cannot use its natural strength — reasoning across levels of detail.

This paper's move: encode each time step as a 'multi-scale token' that says what happens at the hourly level, the daily level, the weekly level, and so on. Then, craft prompts that name the scales explicitly, e.g. 'At the hourly scale, the value is rising. At the daily scale, it is steady.' The LLM reads all scales at once, so it can weigh them. When the hourly scale says one thing but the daily scale says another, the LLM learns to trust context (e.g. trust daily for long-term forecasts, hourly for detecting glitches), because the LLM's training on language already taught it to reason across multiple levels of time. This alignment — encoding multi-scale + prompting multi-scale — means the LLM's predictions improve because each scale gives the model extra clues; patterns at the daily level guide hourly predictions toward plausible ranges, and weekly patterns anchor all forecasts to long-term trends.

The alignment formula

First in words:

The total prediction loss is the sum of losses at each scale, weighted by how important that scale is for the task.

Then the compact form:

L_total = sum_s (w_s * L_s(predicted_s, actual_s))

Every symbol:

sa specific scale (hourly, daily, weekly)
L_s(predicted_s, actual_s)prediction error at scale s: how far the LLM's guess is from the true next value
w_simportance weight for scale s (learned during training)
sum_sadd up across all scales
A tiny worked example
Suppose we have 3 scales: hourly, daily, weekly.
Hourly scale: LLM predicts value 23, true value is 25. Error = 2.
Daily scale: LLM predicts value 20, true value is 20. Error = 0.
Weekly scale: LLM predicts value 18, true value is 22. Error = 4.
Weights learned: hourly = 0.3, daily = 0.5, weekly = 0.2.
Total loss = 0.3 * 2 + 0.5 * 0 + 0.2 * 4 = 0.6 + 0 + 0.8 = 1.4.
The model is forced to fix the weekly error (highest impact) and the hourly error, but the daily error matters less. Training emphasizes the scales where the model struggles most.

The paper learns these weights automatically, so the LLM automatically learns to care most about scales where it makes big mistakes.

What can go wrong

What can go wrong

Choosing the wrong scales. If you pick hourly, daily, and weekly scales but the true pattern is every 6 hours, the hyperedge misses it. The fix: run exploratory analysis to find the dominant periodicities in the data before encoding.
Too many scales at once. If you encode 10 scales simultaneously, the prompt becomes huge, the LLM's token budget is exhausted, and reasoning slows to a crawl. The fix: select only scales with significant patterns (filter by signal strength).
Prompts that contradict the data. If the prompt says 'the daily pattern is steady' but the data shows wild daily swings, the LLM gets whiplash and makes poor predictions. The fix: generate prompts automatically from the data, not by hand.
Done right. Automatically detect dominant scales, encode and align each, and compose prompts that reflect the data's true multi-scale structure. The LLM then reasons naturally across all levels of detail.
What a runnable demo should prove

What a runnable demo should prove

Build a toy time series with clear patterns at three different scales: a sine wave at 24-hour frequency (daily cycle), a second sine wave at 168-hour frequency (weekly cycle), and white noise (randomness). Encode this at all three scales. Ask an LLM-based model to forecast the next 48 hours. Measure the forecast error. Then, strip away all but the hourly scale (single-scale baseline) and measure the error again. The demo must show that multi-scale encoding produces a lower error because the LLM can see both the daily and weekly structure.

improvement = (single_scale_error - multi_scale_error) / single_scale_error

The demo must make it impossible to miss: the multi-scale model uses each scale to catch patterns the single-scale model cannot see.
