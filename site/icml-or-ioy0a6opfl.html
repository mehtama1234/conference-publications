MemCast: Memory-Driven Time Series Forecasting with Experience-Conditioned Reasoning

A time series forecaster that learns from past attempts and stores lessons as memory guides to improve future predictions.

Paper explainersAll themesTime Series & Sequential

Large language models can now predict what happens next in a sequence of numbers (stock prices, sensor readings, weather patterns). But they start from scratch each time: no memory of what worked before, no lessons from past failures. MemCast changes this by storing experiences as structured memory — historical patterns that guided past successes, reasoning wisdom from how the model explored different ideas, and general laws learned from the data — then using that memory to guide new forecasts.

Zero assumption version

Forecasters without memory repeat mistakes

A time series is a sequence of numbers over time: daily stock prices, hourly temperatures, minute-by-minute traffic counts. Predicting the next value in that sequence is hard because past patterns matter. Large language models are good at pattern recognition, so they can be trained to do this forecasting.

But today's LLM-based forecasters do not store lessons from their mistakes. When asked to forecast a new sequence, a model starts with no memory of what worked on similar sequences before. If it tried to predict a holiday spike and failed on one sequence, it repeats the same failed reasoning on the next holiday spike. The model has no systematic way to learn from its own experience across many forecasts.

In one sentence. MemCast organizes forecasting experience into memory — patterns from past successes, reasoning steps that worked, and general rules extracted from data — and uses this memory to guide future predictions.

The algorithm as a flow

What it actually does

Step 1: Learn experience from training data

Train the model on past sequences, capturing outcomes, reasoning steps, and feature patterns.

Step 2: Organize into three-layer memory

Build hierarchical storage: historical patterns (outcomes that happened), reasoning wisdom (good reasoning paths), general laws (rules that held across data).

Step 3: Guide new predictions with patterns

When forecasting a new sequence, retrieve similar historical patterns and use them to steer the model's initial reasoning.

Step 4: Refine with wisdom and laws

Use reasoning wisdom to pick better exploration paths, because stored steps that worked before are more likely to lead to good forecasts than random tries. Use general laws as sanity checks and iterate to stay consistent, because forecasts violating known rules are wrong by definition.

Step 5: Adapt confidence safely

Update confidence in each memory entry based on new forecasts, but never let the model see the actual answer on test data.

What the paper changes

What the paper changes: memory state

MemCast adds a new object to forecasting: structured memory. Before, the model only had its learned weights (the parameters trained once on the training set). Now, MemCast introduces a second learnable object — a hierarchical memory bank that grows and adapts as the model forecasts.

the object it moves  =  Hierarchical memory state
The hidden quantity

Confidence in memory entries

measured quantity  =  Memory entry confidence (how much to trust each stored lesson)

As the model forecasts on new sequences, it learns whether each stored lesson is actually useful. A confidence score (a number from low to high) for each memory entry tells the model how much to trust that pattern or rule.

MemCast measures confidence by tracking: when a memory entry is retrieved, does the forecast succeed or fail? If retrieved patterns led to good forecasts, confidence increases. If they led to errors, confidence decreases. The paper's key challenge is updating these scores without accidentally learning from the test set itself — the trick is to only update based on patterns the model itself generated, not from seeing the correct answer.

Why it works

Why storing and refining memory helps

The mechanism is a learning loop. A standard forecaster trains once, then predicts the same way forever — it cannot improve from experience. MemCast breaks this by making experience learnable.

When the model forecasts on a new sequence, three things happen in order: First, it retrieves similar patterns from memory and uses them to guide which reasoning path to explore (this avoids re-exploring dead ends). Second, it uses stored reasoning wisdom — the steps that worked before — to steer how it explores. Third, after proposing a forecast, it checks that proposal against stored general laws; if it violates a rule, the model re-thinks and tries again. Each time this works, the confidence in that memory entry goes up. Each time it fails, confidence goes down. Over many forecasts, memory entries become increasingly tuned to what actually helps because the model reinforces entries that lead to success and suppresses ones that lead to failure — a form of learning that never stops, even during deployment.

Why does this work? Because patterns that kept failing in training never built high confidence; they stay dormant. Patterns that consistently led to correct predictions accumulate high confidence and guide more future forecasts. The hierarchical structure has three levels: specific patterns stored from past sequences, reasoning wisdom that captures good exploration strategies, and general laws that hold broadly across the data. This layering means the model has both concrete lessons from similar past sequences and abstract rules to fall back on.

Math after the picture

The confidence update rule

First in words:

New confidence equals old confidence plus a small adjustment based on how well this forecasting step matched the memory entry's advice.

Then the compact form:

confidence_new(m) = confidence_old(m) + alpha * match_score(m, forecast_step)

Every symbol:

confidence_new(m)confidence value for memory entry m after this forecast
confidence_old(m)confidence value before this forecast
alphahow much each forecast result shifts confidence (a small number, like 0.01)
match_score(m, forecast_step)how well the memory entry matched what the model actually did (1 if it matched, 0 if it did not match, between 0 and 1 if it partially matched)
A tiny worked example
Scenario: Pattern_1 stored a rule about holiday spikes. On a new forecast with a holiday, the model uses Pattern_1 to guide reasoning.
Before: Pattern_1 confidence = 0.60
Match score: Does the forecast match what Pattern_1 predicted? Yes, fully. match_score = 1.0
Alpha (learning rate) = 0.05
confidence_new = 0.60 + 0.05 * 1.0 = 0.65
If instead the forecast had disagreed with Pattern_1, match_score = 0 and confidence_new = 0.60 + 0.05 * 0 = 0.60 (no change)

Each memory entry's confidence grows when it guides successful forecasts, because the model tracks whether reasoning steps it used actually matched what it decided to forecast, and shrinks when it leads to errors, using the same internal matching signal. This works without ever seeing the ground truth because the update only looks at the model's own choices, not at correct answers.

What can go wrong

What can go wrong

Memory contamination: updating confidence using ground truth If the model peeks at the actual next value (the ground truth), it can game its confidence scores to match any data. The paper's fix: only update based on reasoning steps the model generates, not from seeing the correct answer. This is the core constraint of dynamic confidence adaptation.
Noisy memory: storing failed patterns at high confidence Early forecasts might build wrong patterns that seem to work by luck. If confidence updates too aggressively, these bad patterns stick around and mislead later forecasts. The fix is a slow learning rate (alpha stays small) so confidence changes gradually.
Catastrophic forgetting: adapting memory breaks old lessons If confidence updates too freely, high-confidence entries might suddenly flip based on one bad forecast from a very different sequence type. The hierarchical structure mitigates this because specific patterns adapt quickly (they apply only to similar sequences, so one mismatch is expected noise) while general laws adapt slowly (they apply everywhere, so they need many mismatches to flip), so abstract lessons persist even when specific patterns are wrong.
Done right: three-layer design Organizing memory into patterns (specific outcomes), wisdom (reasoning strategies), and laws (general rules) creates natural resistance to noise. Specific lessons can adapt quickly; abstract rules resist one-off noise and stay stable. Confidence updates only from internally-generated reasoning steps, never from seeing answers.
What a runnable demo should prove

What a runnable demo should prove

Build a simple forecaster on a small time series dataset (e.g., a toy monthly sales sequence with seasonal spikes). First, train a baseline LLM-based forecaster on the first 60 percent of the data. Then, without retraining, deploy it on the remaining 40 percent while MemCast's memory adapts. Track the forecast error for each new sequence. Measure how much memory-guided forecasts improve over the purely-trained baseline, because accumulated memory allows later forecasts to benefit from what earlier ones learned.

Improvement = (error_baseline - error_memcast) / error_baseline, measured as the average across all test sequences

The demo must show that memory improves forecasts on sequences the model never saw in training because patterns that predicted well accumulate high confidence while ones that fail drop in confidence, and the high-confidence patterns guide new forecasts to better answers.
