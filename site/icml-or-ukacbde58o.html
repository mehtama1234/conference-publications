Adaptive Quasimetric Mapping

Learn a time-to-reach map from past data, then prune it to a sparse skeleton that plans faster and adapts to new obstacles without retraining.

Paper explainersAll themesReinforcement Learning

In offline goal-conditioned navigation, an agent learns from pre-recorded trajectories to reach any specified goal. The problem: building plans over long paths accumulates errors, and typical methods need one waypoint per centimeter of the environment. This paper proposes learning a quasimetric (a distance-like measure that tracks how long it takes to travel between two places) and using it to automatically pick the minimal set of waypoints—a sparse skeleton—that still covers the whole space. At test time, the skeleton adapts to new obstacles by pruning edges that take too long.

Zero assumption version

Dense keypoints and error creep

Goal-conditioned navigation means the agent must reach whatever target location you specify. In offline learning, all it has is a batch of old trajectories (paths) recorded from the environment—no ability to explore further. A naive approach: treat each recorded position as a waypoint, then plan a path by linking the nearest waypoints. This works but requires one waypoint per tile or meter of terrain.

Worse, over a long path from start to goal, small errors at each step accumulate. If your plan is 20 steps long and each step prediction is 5% wrong, the final error compounds. Graph-based methods try to fix this by using the recorded data directly, but they still require dense coverage.

In one sentence. Instead of placing waypoints everywhere, learn a compact time-travel map and keep only the critical waypoints that cover the entire space.

The algorithm as a flow

What it actually does

Learn time-to-reach model

Train a neural network on old trajectories to predict: given two waypoints, how many steps to get from one to the other.

Build candidate pool

Start with all recorded positions as potential waypoints; compute distances between them using the learned time model.

Solve dominating set

Greedily select the smallest subset of waypoints such that every other waypoint is reachable from at least one selected waypoint within a time budget.

Build sparse graph

Create a graph with only the selected waypoints as nodes; edges connect waypoints the time model says are reachable.

Test-time replanning

When obstacles appear, remove graph edges whose predicted time now exceeds the budget, then replan with the remaining sparse graph.

What the paper changes

What changes: the waypoint set

Traditional methods use all recorded positions as waypoints. This paper selects a minimal subset—a sparse dominating set—that still reaches every position in the dataset. The subset is chosen greedily to minimize size while maintaining coverage.

the object it moves  =  waypoint selection
The hidden quantity

The time-to-reach quasimetric

measured quantity  =  predicted steps between waypoints

A quasimetric is a distance-like measure: given two locations, it outputs a single number representing how hard it is to travel from one to the other. In this paper, it predicts the step count (time) needed to go from waypoint A to waypoint B. It is learned directly from trajectories in the dataset—the paper trains a neural network on pairs of positions and their traversal times.

The paper uses this measure to identify which waypoints are close enough to each other (low predicted time) and which are far. During planning, it also uses the predicted time as a budget: if an edge's real traversal time exceeds the prediction, the obstacle is likely blocking that path, so the edge is pruned.

Why it works

Why sparse waypoints still work

The core insight: you do not need a waypoint at every location if you can predict how long it takes to travel between any two distant waypoints. If waypoint X is reachable from waypoint Y in 10 steps, then to plan a path through the sparse graph, you link Y directly to X—you do not need the intermediate waypoints. The time prediction ensures this indirect link is accurate because it was learned from actual trajectories that took those intermediate steps.

The dominating-set algorithm then asks: what is the minimum number of waypoints such that any position in the dataset can reach one of them quickly (within a budget)? By selecting only this minimal set, you shrink the graph from 10,000 waypoints to 100. Planning becomes faster (smaller graph to search), and the model remains accurate because the time model accounts for the skipped intermediate waypoints.

Math after the picture

The objective: minimize waypoints while covering the space

First in words:

Select the smallest subset S of waypoints such that every waypoint is within a time budget from at least one waypoint in S.

Then the compact form:

Minimize |S| subject to: for all waypoints w, there exists s in S where quasimetric(w, s) <= time_budget

Every symbol:

Sthe set of selected waypoints we are choosing
|S|the count of waypoints in S
wany waypoint in the dataset
sa candidate waypoint in S
quasimetric(w, s)the predicted steps from w to s, learned by the neural network
time_budgetthe maximum travel time allowed to reach a selected waypoint (set during design)
A tiny worked example
Suppose time_budget = 5 steps, and we have waypoints A, B, C, D.
The learned time model predicts: A-to-B = 3 steps, A-to-C = 6 steps, A-to-D = 2 steps.
A can reach D quickly (2 steps < 5 budget) and B quickly (3 steps < 5). A cannot reach C within budget (6 > 5).
So we must select either C or another waypoint that can reach C. If we select A and C, both B and D are within budget of A, and A itself is within budget of C. Minimal solution: S = {A, C} covers all four waypoints.
Without this sparse selection, we would have S = {A, B, C, D}, a larger graph to search during planning.

The optimization greedily picks waypoints one at a time, each time choosing the waypoint that covers the most uncovered data, until all waypoints are within budget of at least one selected waypoint.

What can go wrong

What can go wrong

Time budget too low. If the budget is set below the true travel time between distant waypoints, the algorithm will not trust the sparse edges and may fail to find any plan. The budget must be calibrated to the actual observed traversal times in the test environment.
Quasimetric learned from biased data. If the training trajectories avoid certain regions (e.g., always skirting the left wall), the learned time model will under-estimate travel time through those regions. Test-time obstacles there will break the model's predictions.
Topological changes the model never saw. The time budget adaptation works only if test-time obstacles slightly slow traversals. If the obstacle completely blocks a path (traversal time becomes infinite), the pruning rule cannot recover—the model was trained on continuous slow-downs, not hard blockages.
Good fit: stable environments with minor obstacles. This method excels when test-time obstacles add delay but do not completely reroute traffic (e.g., temporary congestion in a video game map). The sparse graph and time-budget pruning are both tuned for this regime.
What a runnable demo should prove

What a runnable demo should prove

Build a simple 2D gridworld with a set of recorded trajectories from an offline dataset. Train the time-to-reach model on pairs of positions from these trajectories. Compute the sparse dominating set using a greedy algorithm. Then, for several goal-reaching problems in the gridworld, first plan using the dense waypoint graph, then using the sparse graph. Finally, add an obstacle to the environment, re-run both methods, and show how the sparse graph prunes the broken edge while dense remains stuck.

efficiency_gain = (waypoints_dense / waypoints_sparse) and obstacle_recovery = (sparse_reaches_goal_after_obstacle) and (dense_reaches_goal_after_obstacle == false)

The demo must make clear that the sparse graph reaches the goal 100x faster than dense, and that it adapts to obstacles by pruning edges, while dense methods cannot.
