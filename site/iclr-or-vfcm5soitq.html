OptimSyn: Influence-Guided Rubrics Optimization for Synthetic Data

Measure how much each synthetic training example actually helps the target model, then optimize the rubric that generates those examples to maximize measured impact.

Paper explainersAll themesLLMs & Foundation Models

To train a large language model on rare topics (medicine, law, finance), experts must write thousands of fine-tuning examples. That is slow and expensive. Instead, researchers use a teacher model to generate synthetic examples, but they guide it with handmade rubrics (lists of rules for what counts as a good example). These rubrics are fragile: they work in one domain but fail in another, and no one can predict which rules matter most. This paper proposes a radical shift: stop guessing at rubrics. Instead, measure each synthetic example's actual impact on the target model's learning, then use those measurements to automatically adjust the rubric generation process.

Zero assumption version

The rubric design loop is stuck

Building a language model for specialized domains (medicine, law, social sciences) requires fine-tuning data: tens of thousands of examples showing the model how to reason about domain-specific problems. Expert humans can write this data, but it costs a fortune and takes months. So researchers use a cheaper shortcut: a teacher model (like GPT-4 or a large open model) generates synthetic examples—this is cheaper because the teacher model runs automatically without expert labor—conditioned on domain documents and a rubric, a hand-written list of criteria for what makes a good example (for example, 'examples should cite sources', 'answers should be concise', 'reasoning should mention background knowledge').

The problem: rubric design is an art, not a science. Domain experts spend days writing rubrics. Even when a rubric works brilliantly in one domain (e.g., medical), it fails in another (e.g., history essays). No one knows which of the ten rules actually mattered. When the synthetic data quality is poor, teams guess at fixes: tweak the wording, add a new rule, remove an old one, regenerate examples, retrain the model, inspect the results, and guess again. This feedback loop is slow and unreliable.

A naive approach tries to evaluate synthetic examples directly: check if they look 'correct' by scoring them against a standard (a classifier, a rubric, or comparing numerical representations to real examples). But numerical closeness is deceiving. A synthetic example that resembles a real one in word choice may still be useless for training. Two examples can look nearly identical but differ wildly in how much they teach the target model.

The core insight: Stop designing rubrics by hand. Measure each synthetic example's causal impact on the target model's learning, then adjust the rubric generator to produce examples with higher impact.

The algorithm as a flow

What it actually does

Seed with domain documents

Start with raw text in your target domain (medical papers, legal cases, historical documents).

Generate rubric candidates

A rubric-specialized model reads a domain document and writes a rubric (specific criteria).

Synthesize examples using the rubric

A teacher model conditions on the rubric and generates synthetic question-answer pairs.

Compute influence scores

For each synthetic pair, compute how much the target model's loss would change if trained on it.

Update the rubric generator

Use the influence scores as rewards. Reinforcement learning adjusts the rubric generator to produce higher-impact examples in the next round.

What the paper changes

What the paper changes

The paper changes how rubrics are created: from hand-written static lists to automatically updated rules conditioned on target-model feedback. Instead of a human designer typing rubrics once and hoping they work, a specialized generator model writes new rubrics, and a reinforcement-learning algorithm adjusts the generator's behavior based on measured impact.

The hidden quantity

The hidden quantity: influence score

measured quantity  =  Influence on target model learning

The key hidden quantity is the influence score: a number that estimates how much a single synthetic example will improve the target model's ability to solve tasks, measured via the first-order gradient information (the direction the model's weights want to move to reduce error on that example). High influence means the example teaches something the model does not yet know, because it nudges the model's weights in a direction that matters for the validation tasks. Low influence means the example is already well-understood or unhelpful.

The paper estimates influence using a classic technique from machine learning research (influence functions). The idea: if you remove an example from the training set, how much would the model's final performance on a validation set change? That change is the influence. Computing the exact answer is slow, so the paper uses a gradient-based approximation: the influence is approximately the inner product (dot product) of two gradients—the gradient of the loss on that example, and the gradient of the loss on the validation set. This approximation is fast enough to compute for every synthetic example in every batch.

Plain reading. Influence is how much an example teaches the model something new. High-influence examples correct gaps in the model's knowledge or reasoning. Low-influence examples are already well-known or wrong in ways the model does not encounter on test problems.
Paper reading. Influence is the first-order gradient approximation of the change in held-out validation loss if the example is included in training. The computation involves three pieces: the gradient showing how the example nudges each weight, the signal from the validation set showing which weight movements matter for test performance, and the learning rate controlling step size.
Why it works

Why it works: closing the feedback loop

The core mechanism is feedback. Before this paper, synthetic data generation was one-directional: write a rubric, generate data, train, inspect, guess. The new approach closes the loop by inserting a measurement step between generation and training. Here is the causal chain.

First, influence functions reveal a critical gap: numerical closeness does not mean teaching value. A synthetic example can be textually similar to real training data yet teach the target model almost nothing (low influence), because it duplicates knowledge the model already has. Conversely, an example that is concrete and well-reasoned can move the model's weights substantially (high influence) even if it does not resemble any real example. This finding demolishes the old assumption that 'fake data close to real data is good data.'

Second, the paper uses influence scores as a reinforcement-learning reward. A specialized rubric generator (a language model fine-tuned to write rubrics) produces candidate rubrics. For each rubric, synthetic data is generated, influence scores are computed, and those scores become rewards. An RL algorithm (GRPO) updates the rubric generator's weights to maximize expected influence. Over iterations, the generator learns which criteria produce high-impact examples: specific instructions, never-before-seen reasoning paths, clarity in the logic, or examples grounded in domain sources—whatever actually teaches the target model.

The influence approximation

First in words:

influence = negative learning_rate times the dot product of two gradients: one for the training example loss, one for the validation loss.

Then the compact form:

influence(z) = -η * (∇_θ ℓ(z; θ) · Γ_val(θ))

Every symbol:

za single synthetic example
θthe target model's weights
ℓ(z; θ)the loss (prediction error) on example z
∇_θ ℓ(z; θ)how much to nudge each weight to reduce error on z (the gradient)
Γ_val(θ)the combined gradient signal from the validation set, weighted by importance
ηthe learning rate (step size in training)
-η * (· · )the negative dot product scales the total impact
A tiny worked example
Suppose a synthetic example has gradient [0.5, -0.3, 0.8] (nudges each of three weight groups).
The validation signal is [0.6, -0.4, 0.9] (tells us which weights matter for test performance).
Dot product: 0.5×0.6 + (-0.3)×(-0.4) + 0.8×0.9 = 0.3 + 0.12 + 0.72 = 1.14.
With learning rate η = 0.01, influence = -0.01 × 1.14 = -0.0114.
Negative means training on this example nudges weights in the direction the validation set wants, so it is high-value (true influence is positive; the math convention inverts the sign to show 'reducing validation loss').
Compare to a low-influence example with dot product 0.05: influence only -0.0005 per example, 20× weaker.

The influence score estimates how much training on this example reduces error on held-out validation tasks; high scores indicate examples the model desperately needs.

What can go wrong

What can go wrong

Influence approximation can be stale. The gradient-based influence assumes the model's weight gradients do not change much during training. In early training, when the model is shifting fast, the approximation becomes less accurate. Influence estimates computed on the initial model may not predict final performance as well.
Validation set must represent test tasks. The influence score depends on which validation tasks you use. If the validation set is poorly chosen (e.g., it measures the wrong skills), then high influence on that set does not mean high impact on the final test set. The method amplifies whatever signal the validation set provides.
High-stakes domains require additional safeguards. In medicine or law, synthetic examples optimized only for influence can produce confident-sounding but misleading advice. The optimization loop does not know about safety or domain regulations. Human review is still essential before deploying synthetic data in critical applications.
Done right: validation-aligned approach. Ground the validation set in your true downstream task. Use influence scores alongside other checks (consistency, factuality, format) to build a reliable data generation pipeline, not as the sole decision criterion.
What a runnable demo should prove

What a runnable demo should prove

Build a simple end-to-end pipeline on a small dataset (e.g., a few thousand examples from medical or history domains). Use a small target model (e.g., a 1 billion or 8 billion weight model) to keep compute tractable. Generate synthetic examples using two competing rubrics: one static (hand-written), one optimized via influence scores. Measure the influence score for each synthetic example in both batches. Train the target model separately on data from each rubric, holding all else equal. Compare final accuracy on a held-out test set of real examples.

gain = (influence_optimized_test_accuracy - static_rubric_test_accuracy)

The demo succeeds if influence-optimized rubrics consistently produce higher test accuracy, and if the pattern of influence scores in the optimized batch is noticeably shifted higher than in the static batch.
