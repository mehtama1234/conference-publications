FedRGL: Robust Federated Graph Learning under Label Noise

When multiple organizations share graph data over a network but labels are messy, use local structure and global agreement to spot which labels are wrong, then fix them.

Why federated graph learning breaks with bad labels

Organizations often have sensitive graph data—networks of people, transactions, or relationships—that they cannot share directly. So they use federated learning: each site trains a local model and sends only the weight updates to a central server, which combines them into one shared model. A naive approach trains on whatever labels each site has, even if some are wrong.

This fails because wrong labels contradict each other across sites and pull the shared model in conflicting directions. The global model ends up confused, and accuracy drops. Existing methods to handle label noise were built for computer vision—images with labels—not graphs, where the structure itself (who is connected to whom) carries signal. Applying those methods directly misses the graph information entirely.

In one sentence. Spot which labels are wrong using both the graph structure and the global model's agreement, then relabel those nodes correctly.

The algorithm as a flow

What it actually does

Compute local opinions

On each site, use the local model and local graph structure to score which category each node should be.

Get global opinion

Collect all local model updates on the server; aggregate them into a global model. Run predictions.

Find mismatches

Compare: where does local graph structure strongly vote one way, but the global model predicts something else? Those nodes are likely mislabeled.

Relabel with high confidence

Use graph augmentation—small random changes to edges—to build multiple noisy-but-related views of each suspicious node. Take the majority vote as the new label.

Train on cleaned labels

Feed the cleaned labels back to the next training round. Server also tracks model uncertainty to weight high-certainty updates more heavily.

What the paper changes

What the paper changes

The paper changes the labels themselves. Instead of blindly training on whatever labels the original data came with, it identifies which labels are wrong and replaces them with better ones inferred from graph structure and global model agreement. It does this because wrong labels act as contradictory signals that pull the global model in conflicting directions, and fixing them up-front lets the model train clearly.

the object it moves  =  labels
The hidden quantity

The hidden quantity: Dual-perspective consistency

measured quantity  =  consistency score between local and global

The paper measures a score for each node: how much do the node's local neighbors agree with the global model's prediction? A high score means the label is trustworthy; a low score flags noise. This is the core signal—it rides on two perspectives at once: what the local graph structure suggests (which neighbors connect to this node and what are they?) and what the trained global model predicts (after seeing all sites' evidence).

The paper estimates this by taking predictions from both angles—one from local subgraph information, one from the aggregated global model—and checking alignment. If they disagree strongly, the label is likely wrong.

Why it works

Why it works: The three-part fix

The method works because it uses graph structure where vision-only methods cannot. Graph data carries signal in edges: if node A connects to node B, they are often the same category. When a node's label disagrees with both its neighbors and the global model, the label is almost certainly wrong. By measuring this dual consistency—local structure AND global agreement—the paper catches noise that a single view would miss.

Second, the paper fixes mislabeled nodes using graph augmentation: it creates multiple noisy copies of the graph (randomly dropping a few edges), re-computes predictions on each, and takes the majority vote. This works better than trusting the original label because the majority vote leans on graph patterns that stay consistent even when edges are randomly dropped. The original label does not adapt to the graph; the structure-based vote does.

Third, on the server side, the paper tracks model uncertainty—how confident is the global model on each node?—and weights aggregation accordingly. High-uncertainty nodes contribute less to the next round, dampening disagreement. This adaptive aggregation keeps the global model from being dragged off-track by low-confidence local updates.

The noise detection equation

First in words:

A node is flagged as noisy if the consistency score—how often the global model and local neighbors agree—falls below a class-specific threshold.

Then the compact form:

flag_node_i = 1 if consistency_score_i < threshold_class(y_i) else 0

Every symbol:

consistency_score_iagreement between local neighbors' votes and global model's prediction for node i
threshold_class(y_i)threshold set per category (class) of node i; higher for confident classes
flag_node_i1 if node i is flagged as noisy, 0 if trustworthy
y_ithe original label of node i
A tiny worked example
Node 1 has label 'Cat'. Its neighbors and global model both predict 'Cat' with high agreement: score = 0.92. Threshold for 'Cat' = 0.75. 0.92 > 0.75, so Node 1 is trustworthy.
Node 2 has label 'Dog'. Its neighbors predict 'Cat' (they are mostly connected to cats), but global model hedges. Score = 0.35. Threshold for 'Dog' = 0.70. 0.35 < 0.70, so Node 2 is flagged as noisy.
Node 2 gets relabeled: augmented graph samples all vote 'Cat'. New label = 'Cat'. Next round trains on that.

A node is trustworthy if both its neighbors and the global model agree. A low score flags noise. The threshold adapts per category so rare classes are more strictly vetted.

What can go wrong

What can go wrong

Consensus can mislead on minority classes. If a rare category has few examples, local neighbors may not agree strongly just by chance. The paper sets adaptive thresholds per class, but if thresholds are too strict, rare-class nodes are over-flagged as noisy. If thresholds are too loose, the method misses real noise.
Graph structure itself can be noisy. The method assumes the edges (connections) are correct and only labels are wrong. If some edges are also mislabeled or missing, the local consensus becomes unreliable and the whole approach falters.
Aggregation can average out signal. If one site has clean data and another has many noisy labels, averaging their model updates muddles the clean signal. Weighted aggregation by model uncertainty dampens low-confidence updates, which reduces the damage—high-uncertainty noisy models get smaller voice—but cannot fully undo the harm if noise is severe.
Done right: diversity helps. If sites have different graph structures or different mixes of categories, the dual-perspective approach becomes stronger because local consensus and global agreement measure independent signals. When sources disagree in different ways, the mismatch is clearer, so the paper spots noise more reliably.
What a runnable demo should prove

What a runnable demo should prove

Build a small federated graph learning setup: split a real graph (e.g., citation network: papers as nodes, citations as edges, paper topic as label) across three simulated organizations. Inject label noise into 20% of nodes at each site. Train a naive federated model and measure accuracy. Then run FedRGL: apply dual-consistency filtering per round, relabel noisy nodes, and re-train. Track how accuracy recovers as noisy labels are corrected.

accuracy_gain = accuracy_after_cleaning - accuracy_before_cleaning

The demo must show that finding and relabeling just the noisy nodes—without touching the data or communication cost—recovers most of the accuracy loss from noise.
