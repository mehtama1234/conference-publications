Unlocking Long-Horizon Agentic Search with Large-Scale End-to-End RL

ASearcher trains one open search agent with reinforcement learning so it can keep searching, checking conflicts, and revising its answer across very long tool-use runs.

Paper explainersAll themesAgents & Tool Use

Search tasks become hard when a system must keep track of many partial facts across many tool calls, not just answer after one lookup. This paper builds ASearcher, a single open model that learns that long search behavior directly with reinforcement learning. Two pieces matter most: first, it creates training questions that force multi-step evidence gathering; second, it trains with runs as long as 128 actions so the agent gets practice finishing a full research loop instead of quitting early.

Zero assumption version

Why open search agents stop too early

A search agent does more than issue one query. It has to decide what to look up first, compare sources, notice missing facts, and keep going until the answer is settled. Open agents usually break on that longer job because they were not trained to carry credit across many steps. They often learn short habits such as search once, read one page, and answer.

That weakness comes from the training setup. If the reward mostly arrives on short tasks, the agent has little reason to pay the cost of extra checking. A long search plan looks worse during training because each extra action risks wasted time unless the system has seen enough examples where the late actions changed the final answer. The result is a tool user that knows how to search, but not how to keep searching when the easy path is not enough.

The paper's move. Train on questions that require long evidence gathering, then let the agent take many actions during reinforcement learning so that late corrections can still earn reward.

The algorithm as a flow

What it actually does

Create hard search questions

Use a two-stage process to make question-answer pairs where the answer needs several searches and cross-checks.

Start from an open base model

Begin with a model that already reasons fairly well, so reinforcement learning can focus on search behavior rather than basic language use.

Run long training episodes

Allow up to 128 actions in one run because the agent needs enough room to search, read, compare, and revise before the reward arrives.

Reward complete answers

Score the whole run by answer quality, so the agent keeps actions that help the final answer and drops actions that waste steps because only actions that improve the finished answer receive positive credit.

Add tools at test time

After training, the same agent can use extra tools or several parallel runs, because the core policy already knows how to manage long evidence chains.

What the paper changes

What the paper changes

The paper changes the training horizon. Instead of teaching a search agent on short tasks or imitation traces from a stronger closed model, it trains one open model end to end on long tool-use runs because long runs preserve credit for late verification steps.

the object it moves  =  training horizon for search behavior
The hidden quantity

The hidden quantity: delayed value of later actions

measured quantity  =  how much a late search step changes the final answer

In a long search run, the useful action is often not the first query. A late action can reveal a contradiction, surface the missing source, or show that two pages disagree. That means the training signal has to preserve credit for actions far from the final reward.

This paper succeeds when reinforcement learning can hold onto that delayed value. If the training run is too short, the agent never sees the payoff from late checking, so it learns to stop early. If the run is long enough, a search, follow-up search, and verification step can all earn credit because together they produce the right answer.

Why it works

Why it works

The two-stage data process gives the agent tasks where shallow behavior fails. That matters because reinforcement learning only improves behavior that changes reward. If one quick search already solves most training questions, the policy will not learn to inspect disagreements or chase a weak lead. Harder question construction fixes that because the final answer depends on gathering several pieces of evidence.

Long episodes matter for the same reason. A long search run is only worth doing if later actions can still influence training. By allowing up to 128 actions, the method gives the policy room to search, compare, and correct itself before the reward is assigned. That lets the policy keep behaviors such as uncertainty analysis and conflict checking, because those extra steps now pay off in the final score.

The result is not just more searching. It is better search organization, because the agent learns which extra actions are worth the cost and which ones are not. The policy becomes willing to spend steps on verification when verification changes answer quality, and to stop when additional searching no longer helps because those extra actions stop improving the finished answer.

Math after the picture

The training objective

First in words:

Increase the chance of action sequences that lead to high final answer reward, while summing that pressure across the whole search run.

Then the compact form:

J = E[ sum_t log p(a_t | history_t) * A ]

Every symbol:

Jthe score the training process tries to increase
a_tthe action chosen at step t, such as a search or read action
history_teverything the agent has seen so far in the run
Athe advantage, meaning how much better this finished run was than the expected baseline
sum_tadd the contribution from every action in the run
E[ ]average across many training runs
A tiny worked example
Run 1 stops after 3 actions and answers early. Final reward is low because the answer misses a conflicting source.
Run 2 spends 2 extra actions on verification. Final reward is high because the later source fixes the answer.
Training raises the chance of the action sequence in Run 2 because its advantage is positive.
That positive advantage is attached to all useful actions in the run, including the late verification step.
Over many runs, the policy becomes more willing to keep searching when the answer is still uncertain.

The equation is simple but the key choice is the long run length, because that is what lets late actions receive useful credit.

What can go wrong

What can go wrong

Training questions are too easy. If the synthetic question process produces shallow tasks, long-horizon reinforcement learning will still collapse into short search habits because extra actions will not change the reward.
Long runs drift off topic. A large action budget can hurt performance if the agent fills it with weak searches, because more steps only help when they gather evidence that changes the final answer.
Reward only checks the final answer. If reward misses citation quality or factual support, the policy may learn lucky answer patterns because a correct string can still earn credit even when the search trace was sloppy.
Done right. The method works when the question set really requires long evidence gathering and the reward reflects whether that evidence improved the final answer.
What a runnable demo should prove

What a runnable demo should prove

Build a small search environment with questions that need two to five linked lookups. Train one agent with a short action budget and one with a long action budget. Record how often each agent launches follow-up searches after it finds conflicting evidence, and how often those extra searches change the final answer. The long-budget agent should win because it has learned that late verification steps matter.

late_step_gain = correct_after_verification - correct_before_verification; answer_accuracy = correct_answers / total_questions

The demo should make clear that the gain comes from keeping useful later actions, not from taking more actions blindly.
