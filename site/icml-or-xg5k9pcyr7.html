DyGRO-VLA: Cross-Task Scaling of Vision-Language-Action Models

A two-stage framework that makes robot-control models learn shared skills across many tasks instead of overfitting to each one separately.

Paper explainersAll themesRobotics & Control

Robot-control models can watch human demonstrations and learn from practice in the real world. But when trained on many different tasks, they often become specialists that work well on seen tasks and fail on new ones. DyGRO-VLA fixes this by first extracting what tasks have in common, then refining the learning process to balance learning new task-specific skills without forgetting the shared knowledge.

Zero assumption version

Task-specific learning breaks cross-task skill sharing

A robot learns to perform tasks in two ways: watching humans do them, and practicing in the real world with rewards that mark good outcomes. When given many tasks at once, the learning system that works best for task A often works poorly for task B. The reason is that the model learns different, task-specific strategies instead of finding the common structure beneath all tasks.

A beginner might try to just train one learning system on all tasks equally. This fails because the tasks have different reward signals and different strategies. The learning process bounces back and forth between them, and the model ends up mediocre at everything. Without a way to identify what is shared across tasks, the model overfits — it memorizes task-specific details instead of learning general skills.

The core problem. Robot models learn to specialize rather than generalize across tasks because the learning system has no way to separate task-specific noise from shared knowledge.

The algorithm as a flow

What it actually does

Stage 1: Extract shared knowledge

Analyze all tasks together to find the patterns they hold in common using information-theoretic principles.

Stage 2: Build mixture of residuals

Create small task-specific adjustments that sit on top of the shared base, not replacing it.

Dynamic refinement

During learning, the system watches for when task-specific learning starts hurting shared knowledge and reduces it.

Mitigate interference

Prevent the learning process from having one task erase what another task taught.

Evaluate on new tasks

Test on tasks the model never trained on to confirm the shared knowledge actually transfers.

What the paper changes

What the paper changes

The paper changes how the learning system distributes its efforts across tasks. Instead of updating all the model's weights the same way for each task, it splits the update into two pieces: one shared piece that all tasks learn together, and many small task-specific pieces that adapt the shared piece without erasing it.

The hidden quantity

The hidden quantity: Cross-task information shared

measured quantity  =  Cross-task information content

The paper measures how much information the model can extract that is true across all tasks, not just for one task. This is measured using information-theoretic principles, which quantify how much randomness or uncertainty is reduced when the model knows something. Higher information means the model has found patterns that genuinely help on many tasks, because real shared knowledge compresses what many tasks have in common into fewer numbers, while noise and task-specific details remain separate.

The paper estimates this by training the shared representation and measuring how much it improves performance on held-out tasks. If the shared representation helps on new tasks the model never saw during training, it contains real cross-task information, because the improvements come from patterns the tasks genuinely share rather than memorized task-specific details.

Why it works

Why it works: The two-stage design

The method works by solving two separate problems. First, it identifies what is common across all tasks using information-theoretic principles. It analyzes all tasks together and extracts the patterns that matter for multiple tasks, separate from the details unique to each one. By building a representation that captures only cross-task commonality, the model constructs knowledge that transfers to new tasks.

Second, it builds learning as a sum: shared knowledge plus a small task-specific adjustment (called a residual). This matters because it forces the learning process to work in two layers. The shared layer learns what matters for all tasks. The adjustment layer learns only what is unique. Because the adjustment is small and sits on top, a task cannot accidentally erase what the shared layer learned. The learning system measures when tasks start interfering with each other and automatically reduces the task-specific adjustments when that happens — the 'dynamic' part of the name.

inputDemonstrations and rewards from all tasks
stepExtract shared representation using information theory
stepCreate small residual adjustments for each task
stepTrain shared and residual layers simultaneously
stepDetect when task-specific learning interferes with sharing
stepReduce task-specific adjustments to preserve shared knowledge
outputOne model that works on old and new tasks
Math after the picture

The equation: Mixture of residuals

First in words:

The total weight update is the shared update plus a small residual adjustment per task, scaled down when task interference is detected.

Then the compact form:

weight_final = shared_weight + sum_task( mask_task * residual_task )

Every symbol:

weight_finalthe weight the model uses after updating
shared_weightthe part all tasks learned together
residual_taskthe small task-specific adjustment for this task
mask_taska number between 0 and 1 that scales down residuals when interference is high
A tiny worked example
Shared weight for 'grasping motion': 0.5
Task 1 (grasp) residual: +0.1, mask: 1.0 -> contribution: 0.1 * 1.0 = 0.1
Task 2 (push) residual: +0.05, mask: 0.8 -> contribution: 0.05 * 0.8 = 0.04
Final weight: 0.5 + 0.1 + 0.04 = 0.64
If Task 2 started erasing Task 1's learning, its mask drops to 0.3: 0.5 + 0.1 + 0.015 = 0.615 instead.

The mask is a number that scales down task-specific adjustments when they threaten the shared knowledge.

What can go wrong

What can go wrong

If shared representation is too weak. If the information-theoretic extraction fails to find genuine commonality, the shared weight becomes noise, and residuals must carry everything — you lose generalization.
If residual scale is set too high. Large task-specific adjustments can override the shared knowledge. The mask threshold must be tuned; if it never triggers, interference still happens.
If tasks are unrelated. If four tasks genuinely share nothing in common (e.g., picking, math, navigation, cooking), forcing a shared representation makes all of them worse. Cross-task structure is a prerequisite.
Done right. Extract shared knowledge carefully, keep residuals small, monitor for interference during training, and validate on held-out new tasks.
What a runnable demo should prove

What a runnable demo should prove

Build a simulation with three robot tasks (grasp, push, move) trained together for many iterations. Hold out one task as 'new' and keep it unseen during training. After training the shared model, test it on the held-out new task. Measure success rate on all tasks, old and new. Then disable the dynamic mask (force all residuals to be full-strength) and run the same test — it should fail on new tasks because the interference will be unchecked.

generalization = (accuracy on new tasks with dynamic mask) / (accuracy on new tasks without mask)

If the ratio is >1.5, the mask is genuinely preventing interference and preserving shared knowledge.
