Controlling complex hands and manipulation

Papers tackling the hardest robotics problem: controlling many-jointed robotic hands and arms to perform precise, coordinated manipulation tasks—bridging the gap between simulation and real robots.

All themesField mapMathematicsAll explainers
What this is

Picking up a coffee cup is one of the hardest manipulation tasks in robotics. A human hand has 27 degrees of freedom—27 different joints that can move. Even a simplified robotic hand has 10 to 20. Controlling all of those joints to grasp and manipulate objects requires solving a puzzle: what should each finger do, in what order, with what force? If one finger is too stiff, the cup breaks. If it is too loose, the cup drops. The fingers have to move in coordination—thumb and pinky cannot work against each other. And the robot has to feel what is happening; it cannot just execute a pre-planned motion because the object is never in exactly the same place or orientation.

The difficulty has two parts. First, the control problem itself is hard—many degrees of freedom, many constraints, and the need for real-time feedback. Second, collecting training data is expensive. You can simulate a hand in a computer, but the simulation is not perfect—friction works differently, object properties are guessed, sensor noise is not realistic. When you train a policy in simulation and move it to a real hand, it often fails. Getting enough real-world data to train on requires either hand-crafting thousands of demonstrations or running the real robot for weeks, trying different approaches. This is slow and costly.

Papers in this area work to bridge simulation and reality. Some use domain randomization—they train the policy in simulation on many slightly different versions of the task (different materials, object shapes, friction values) so that when it sees the real world, it feels like just another random simulation. Others use real demonstrations as a seed, teaching the robot from human examples first, then refining through practice. Some use tactile feedback—the robot's fingers have force and touch sensors, and the learning algorithm uses these signals to adjust grip strength in real time. A few try to learn a model of the real world dynamics from a small amount of real robot data, then use that model to train the policy more safely.

How the work breaks down

Work on controlling complex robot hands splits into five directions: learning from limited real-world data by importing demonstrations from humans, bridging the gap between simulation and reality through domain randomization and learned dynamics models, using touch and force feedback to sense what the hand is actually doing, learning abstract skills that compose together, and building world models that predict what will happen next.

Learning from human demonstrations

One core challenge is that collecting training data on real robots is slow and expensive—each test of the hand might damage it or waste an object. So researchers use human demonstrations as a starting point, because watching a human move teaches the robot to imitate that motion without breaking things. The robot then practices and refines using those learned starting behaviors as a foundation, so fewer real attempts are needed. This direction tackles the question: how can we teach a hand to grasp and manipulate objects starting from a small number of human examples?

Learning to Grasp Anything By Playing with Random Toys (5) shows that you don't need a perfect dataset of carefully arranged objects. Train the hand to grasp anything in simulation with random object shapes and sizes, then test it on 100 real objects the robot has never seen. It achieves 67% success right away, without any real-world training. This works because random simulation data is diverse enough that real objects just look like slightly different versions of things the hand has already practiced on. DemoGrasp (14) goes further: it learns from a single human-shown grasp and generalizes to grasping hundreds of different objects and even works on different robot hands with different numbers of fingers. UniHM (32) also learns dexterous hand manipulation from human data alone—no massive robot demonstrations needed—and handles unseen objects and trajectories by understanding physics constraints.

Across these papers, the pattern is the same: the hand does not need to see the exact object type to learn. Show it enough variety in simulation, or show it how one grasp works and let it extrapolate to similar objects, and it generalizes. These papers build a bridge from a small human signal to broad robot capability.

Bridging simulation and reality through learned models

Even with simulation, there is a gap between training a hand in a computer and running it on a real robot. The simulation is not exact—friction behaves differently, objects bend slightly, sensor noise is missing. Papers in this group solve this by learning a model of the real world from actual robot data, then using that model to train policies more accurately. The goal is: how can we learn what the real world looks like, and then use that knowledge to train a hand without having to run thousands of expensive real-world trials?

D-REX: Differentiable Real-to-Sim-to-Real Engine for Learning Dexterous Grasping (3) identifies exactly which properties of objects matter most: their mass and shape. It learns these properties from a few real-world grasp attempts and feeds them back into the simulator to match reality better, because when the simulator knows the true mass, it can predict how the hand's motion will affect the object. Then the policy trains in that corrected simulation, which cuts the gap between simulation and reality dramatically, so the hand grasps real objects with higher success. DexNDM: Closing the Reality Gap for Dexterous In-Hand Rotation via Joint-Wise Neural Dynamics Model (4) learns a model of how each joint of the hand actually behaves in the real world—how fast it can move, how it responds to commands—and trains the policy to respect those real constraints. A single policy trained this way generalizes to real objects of all shapes and sizes without needing more real-world data. Manipulation as in Simulation (6) takes a different approach: it trains purely in simulation without any real-world noise or tweaking, and finds that if the simulation accurately captures object shape and the policy learns to work on many object sizes and shapes, it just works on real robots—even on tricky objects like thin silverware. Ctrl-World (10) builds a generative world model—a video generator that predicts what will happen next when the hand moves—so you can simulate long robot behaviors without running the real robot, and rank policies by how well they will perform before trying them on the real hand.

These papers share a philosophy: learn or build an accurate model of how the real world works, then use that model to train the policy, which saves money and prevents damage because you run fewer real-world experiments. They avoid the brute-force approach of just running millions of real-world trials.

Touch and force sensing for closed-loop control

A robot hand holding a fragile coffee cup cannot just close its fingers a fixed amount—it has to feel the cup, sense when it is gripping firmly enough, and ease off if the pressure gets too high. Tactile sensors—touch and force sensors on the fingers—give the hand this sense of feel. Papers in this group learn to use these signals to adjust how the hand is moving in real time. The question is: how can we teach a hand to feel its way through a task, using touch signals to decide what to do next?

Cross-Tactile Sensor Representation Learning (2) solves a practical problem: different robots have different sensors in their fingers, and models trained on one sensor do not work on another. By learning a shared representation that works across many sensor types, it makes policies portable between different robot hands. DexMove: Learning Tactile-Guided Non-Prehensile Manipulation with Dexterous Hands (17) uses touch feedback to push and slide objects—not just grasping, but sliding things across a surface. The tactile signal tells the hand when it is about to lose grip, so it adjusts finger pressure in real time. Success rate jumps from 41% to 78% when you add touch sensing. DECO: Decoupled Multimodal Diffusion Transformer for Bimanual Dexterous Manipulation with a Plugin Tactile Adapter (11) learns to coordinate two hands and a tactile sensor adapter, improving success rate by 10% on tasks where touch contact matters—like inserting a peg into a hole or folding cloth. Tabero: Learning Gentle Manipulation with Closed-Loop Force Feedback from Vision, Touch, and Language (30) goes one step further: it uses force feedback to learn how gently to hold objects—responding to spoken instructions like 'gentle' by actually reducing grip force by 70%, while keeping task success high.

The common thread is that touch is not just a signal to record—it is a real-time steering wheel. Let the hand feel what is happening and adjust grip strength in the moment, and it succeeds more often and does not break things, because the hand can respond if the object starts to slip.

Multi-task learning and skill composition

Training a hand to do one task is hard. Training it to do ten tasks, or a hundred, seems even harder because the tasks have different goals and require different movement patterns. Papers here tackle the challenge: how can we make a single hand that learns many manipulation tasks, and then compose skills—combine learned behaviors—to do new tasks? This is about building scalable, general-purpose hand control.

Abstracting Robot Manipulation Skills via Mixture-of-Experts Diffusion Policies (1) learns a compact set of manipulation 'experts'—each expert is a small policy specialized for one type of motion—and gates them with a router that picks which expert to use at each step. This gives the speed of a small model with the capability of a large one, and it works on real dual-arm robots. RoboOmni: Proactive Robot Manipulation in Omni-modal Context (7) learns hand control from speech, text, and video instructions at once by understanding what the person intends, which means the hand can begin moving before the person finishes speaking because it is already predicting the goal, so it can proactively prepare to help. Decompose and Recompose: Reasoning New Skills from Existing Abilities for Cross-Task Robotic Manipulation (13) learns manipulation as reusable blocks: a reaching skill, a grasping skill, a pushing skill. Then, for a new task the hand has never seen, combine those blocks—compose them in a new sequence—and it works zero-shot, without retraining. Genie Envisioner (20) goes for full generality: trained on over one million episodes, it learns to do both short manipulation tasks and long planning sequences, on many different robot embodiments, with no fine-tuning needed.

These papers share the insight that not every skill needs to be learned from scratch. Break down manipulation into reusable parts, or learn a policy so general that it works across tasks and bodies.

Generalizing across cameras and robot bodies

A manipulation policy trained on one type of camera, with one arm configuration, sometimes fails when you move the robot or change the camera angle. Papers here ask: how can we make policies work across these variations—different viewing angles, different robot bodies, different object properties—so they are actually usable in the real world?

When would Vision-Proprioception Policies Fail in Robotic Manipulation? (8) directly addresses this: it identifies the failure modes where vision and proprioception (the sense of joint position) conflict, and shows how to build policies that work even when they do conflict, which ensures the policy works in both simulated and real-world settings. EquAct: An SE(3)-Equivariant Multi-Task Transformer for 3D Robotic Manipulation (18) learns to understand that rotating an object or moving it in space transforms the required hand motion in predictable ways—and uses that principle to generalize across 18 different tasks and to handle scene rotations and shifts, because the hand motion rule stays the same even if the scene is rotated. This outperforms just feeding pixels to a neural network because it understands how the world transforms, not just static pixel patterns. GeoMoLa learns abstract movement patterns that work across object shapes, so a grasping skill learned on one shape works on all similar shapes, even in cluttered real-world settings, because it understands which shape properties matter. RoboTwin 2.0 (27) builds a huge synthetic dataset using domain randomization—changing materials, friction, object shapes—so that when the policy sees real robots, real objects look like just another random variation it has already seen in training, which is why the model transfers 3.6 times better to real robots and generalizes zero-shot across 50 different dual-arm tasks.

The key principle is that vision alone breaks when the camera angle changes or objects look new. Combine it with geometric understanding, proprioception, or massive synthetic diversity, and the hand keeps working when the world changes.
