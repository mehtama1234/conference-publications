Cosmos Policy: Video Models for Robot Control

Teach a pretrained video model to control a robot by encoding actions directly into the video diffusion process, with no new architecture parts.

Paper explainersAll themesRobotics & Control

Video generation models (the AI that creates videos frame by frame) have learned patterns from millions of real videos: how things move, how gravity pulls, how objects collide. This paper steals that knowledge for robot control. Instead of building a separate robot controller, it feeds the pretrained video model robot demonstrations and teaches it to predict actions the same way it predicts video frames. The trick: encode the actions as hidden numbers inside the diffusion process, side by side with future images.

Zero assumption version

The robot control bottleneck

To make robots useful, you need to teach them to move in response to what they see. Most robot-control papers train a small, custom-built neural network from scratch on robot videos. This works, but throws away one huge advantage: billions of dollars have gone into training video models on internet videos. Those models have learned how the world moves.

A naive first attempt: just download a pretrained video model and fine-tune it directly on robot videos. The problem: video models predict pixel images frame by frame. A robot needs to predict actions (joint angles, motor commands). So earlier work grafted a separate action predictor onto the video model, or trained it in multiple stages. Each extra part adds complexity and loses some of the knowledge the video model learned.

The paper's move in one sentence. Encode actions directly inside the video model's denoising process (the loop that cleans up blurry image predictions) so a single fine-tuning stage teaches the model to output actions without adding new parts.

The algorithm as a flow

What it actually does

Start with pretrained video model

Download a model trained on internet videos to predict future frames.

Encode modalities as tokens

Convert robot images, actions, proprioception (joint angles), and value (expected total reward) into the same compressed token space as the video model uses.

Mix them into one sequence

Build a sequence: current observation, then action, then future image, then future proprioception, then value. Treat them all as video frames to denoise.

Fine-tune with mixed loss

Adjust weights by learning (iteratively nudge them to reduce error) on robot demonstrations. Loss covers action accuracy, future image accuracy, proprioception accuracy, value accuracy. Allocate 90 percent to world model and value, 10 percent to policy.

Use for planning

At test time, condition on the current observation and iteratively denoise the action and future frames. Chain predictions: denoise action one step, take it, observe, denoise next action. Or use value predictions to pick the best action chain.

What the paper changes

What the paper moves

The core change: instead of separate policy and world-model components, encode robot actions as latent tokens (compressed numbers) inside the video model's denoising process. The model learns to jointly generate actions, future images, and value estimates all at once, with no new architecture parts.

The hidden quantity

The hidden quantity: action readiness at each noise level

measured quantity  =  Denoising signal for action prediction

The video model works by starting with pure noise and gradually removing it, revealing the image underneath. At each noise level (the model calls this sigma), the denoiser network learns what the clean image looks like. Cosmos Policy hooks into this same denoising loop for actions: at each noise level, the denoiser learns to predict what the next robot action should be.

The paper measures this implicitly through training loss: how well does the denoiser predict the action, given the current observation and noise level? The model learns a map from (observation, noise level) to (action, future image, value). Noisier predictions are noisy; cleaner predictions are sharp and actionable.

Why it works

Why this works: reuse beats custom parts

The core insight: a video model has already learned to denoise images and predict motion. When you add actions to the same denoising loop, the model's existing motion-prediction machinery helps predict action sequences too, because the same weights that learned to recognize hand motion in videos also learn to recognize hand commands from observations. The model has patterns for hands accelerating, fingers curling, objects being grasped—all baked into its priors from videos. Decoding actions from those same priors means you get physics reasoning for free, because the learned patterns already link cause (an action) to effect (motion in the video).

Why avoid separate modules? Each extra component adds learnable weights that must be trained. Those weights start random, so they don't know anything. The pretrained video model's weights already know physics. By keeping one architecture and one fine-tuning pass, every weight adjustment improves the action prediction while preserving the motion understanding already encoded.

The denoising loss equation

First in words:

Loss equals the average squared difference between predicted and true action, plus the same for future images and values, weighted by importance.

Then the compact form:

L_total = sum over batch of ( L_action(action_pred, action_true) + L_future_state + L_value + L_proprioception )

Every symbol:

L_actionsquared difference (L1 norm) between predicted and ground-truth robot action
action_predaction the model predicted at this denoising step
action_trueactual action taken by the robot in the demonstration
L_future_statesquared difference for predicted next robot joint angles
L_valuesquared difference for predicted expected total reward
L_proprioceptionsquared difference for predicted robot body state
A tiny worked example
Action prediction error: predicted [0.5, -0.2], true [0.6, -0.1]. Squared differences: 0.01 + 0.01 = 0.02.
Future image latent error: predicted [1.2, 0.8, 0.3], true [1.1, 0.9, 0.2]. Squared error sum: 0.01 + 0.01 + 0.01 = 0.03.
Value error: predicted 0.7, true 0.8. Squared: 0.01.
Total loss for this step: 0.02 + 0.03 + 0.01 + 0.005 (proprioception) = 0.065. Gradient descent nudges all weights to shrink this.

The loss is zero when the model perfectly predicts the action, future state, and value from each observation. The denoiser learns to solve all three tasks at once.

What can go wrong

What can go wrong

Noise schedule mismatch. The base video model was tuned for clean internet videos, not robot data. If you use the original noise levels (how much blur to add at each step) without adjustment, the model's denoising at high noise levels predicts blurry actions. The paper reorders the latent sequence and adjusts how it samples noise levels.
Task imbalance in loss. If you weight action loss too low (say 1%) compared to future images, the model learns to predict vivid future frames but forgets to output good actions. The 10/90 split is calibrated by trial.
Limited demonstration diversity. The model inherits video priors, but if robot demos only show one gripper strategy, the model cannot generalize to a different gripper or new object.
Done right. Adjust noise levels carefully for robot data. Weight losses to prioritize action learning. Collect diverse robot demonstrations. Use the model for planning (chain predictions) to correct compounding errors.
What a runnable demo should prove

What a runnable demo should prove

Build a tiny manipulation environment: a 2D arm, a block, and a goal position. Collect 50 robot demonstrations (human teleoperation or scripted policy). Fine-tune the video model on this data for 1,000 gradient steps. Test without planning: feed the current observation and ask the model to predict one action. Test with planning: iteratively denoise the action, take it, observe, repeat.

success_rate = (number of trials reaching goal) / (total trials); planning_success - direct_success shows the value of chaining predictions

The demo must show that chaining future-image and value predictions improves success rate over single-step action prediction. This proves the world model and value function help the policy plan, because the model corrects its own prediction errors: after each action, it observes the new scene and re-predicts, adjusting for any gap between predicted and actual outcome.
