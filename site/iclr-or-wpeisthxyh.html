Cosmos Policy: Teaching Video Models to Control Robots

A robot learns to act by teaching a large video model to generate action frames, so it uses the knowledge of physics already baked into that model.

Paper explainersAll themesRobotics & Control

Video generation models have learned the physics of the real world just by watching countless videos. Robots could use this knowledge to plan actions, but wiring them together usually requires rebuilding the model with custom pieces. Cosmos Policy shows a cleaner way: take the existing video model and teach it to produce robot actions as a special kind of frame, all in one step, no custom parts.

Zero assumption version

Video knowledge is locked in the model

Video generation models have learned physics from watching millions of videos. They understand gravity, collisions, how things move over time. A robot that could use this physics knowledge would learn faster—because it doesn't have to figure out from scratch which moves are legal and which cause crashes—and plan safer actions, because the model already knows which arm configurations are physically possible.

Robots are usually trained from scratch on demonstration videos of someone (or another robot) doing a task. A naive approach would be to throw away the video model and train a fresh robot policy. But that wastes all the physics knowledge already learned. So researchers tried to adapt the video model into a robot policy, grafting on new pieces: an extra stage of training after the first one, custom layers to generate actions, special decoding steps. This patchwork works, but it breaks the beauty of the base model and makes everything harder to tune.

The core stuck question: how do you take a finished video model and repurpose it for robot control without rewriting it?

In one sentence. Can a robot take a pretrained video model and learn actions directly from it in a single training pass, with no custom modifications?

What the paper changes

What the paper changes

Most robot policies are trained from scratch or require multiple stages of adaptation. Cosmos Policy changes one core thing: it treats actions as if they are just another kind of latent frame (compressed numbers inside the video model), and teaches the existing model to generate them in a single training pass. No custom action layers. No separate decoder. The action is just encoded the same way the video generator encodes pixels internally.

the object it moves  =  how actions are encoded
The hidden quantity

Value prediction: what will reward us

measured quantity  =  future cumulative reward

The paper introduces a named hidden quantity: the value, meaning the total reward the robot will collect from this moment forward if it executes well. It is not the immediate reward for this one action; it is the sum of all rewards over the whole trajectory ahead. At each step, the model learns to estimate this quantity as it generates actions and states.

The paper estimates value by training the model to output a value frame alongside the action and state frames. During training, the true total rewards come from the demonstrations (a robot that completes the task gets high value; one that fails gets low value). At test time, the model's value prediction guides planning: the robot samples many possible action sequences and picks the path with the highest predicted total reward.

Paper reading. The policy learns to simultaneously generate latent action frames, latent state frames (predictions), and value frames, all conditioned on the history. Value is estimated from the ground-truth cumulative rewards in the training demonstrations.
Why it works

Why one training pass is enough

A video generation model has already learned the physics of how objects move, how gravity works, how collisions happen. That knowledge lives inside its weights: the numbers that were tuned during all the hours training on videos. When you add a robot demonstration to that model, the model does not have to learn physics from scratch; it already knows it. A single finetuning pass teaches the model only the small gap: which arm movements are legal, what commands the gripper responds to, how to predict value from this specific robot's state.

Encoding actions as latent frames (instead of training a separate action head) means the same learning machinery that predicted the next video frame now predicts the next action. The diffusion process (the model's core algorithm for generating frames) does not change; you just shift what counts as a frame. This keeps everything in one pass because there is no extra piece that needs its own separate training loop.

During test-time planning, the robot generates multiple possible action sequences from the current state using the model's existing sampling machinery. Each sample comes with a value prediction. Picking the trajectory with the highest value means the robot chooses actions that the model learned lead to task completion in the training data. This is planning without retraining.

Math after the picture

Planning score: pick actions with highest expected reward

First in words:

For each sampled action sequence, compute the sum of its predicted values at each step, and pick the sequence with the maximum sum.

Then the compact form:

a_best = argmax_{a_seq} sum_t gamma^t * V(s_t | a_seq)

Every symbol:

a_bestthe best action sequence to pick
a_seqone possible sequence of actions the model samples
V(s_t | a_seq)predicted value at step t if we take actions a_seq
gamma^tdiscount factor (future rewards matter less than immediate ones)
argmaxpick the sequence that gives the highest total
A tiny worked example
Sequence A: sample gripper-open (V=10) then move-right (V=8) -> total 10 + 0.99*8 = 17.92
Sequence B: sample gripper-open (V=10) then move-left (V=2) -> total 10 + 0.99*2 = 11.98
Sequence C: sample gripper-close (V=-5) then move-up (V=3) -> total -5 + 0.99*3 = -2.03
Pick Sequence A (highest total of 17.92). This is planning: choosing the path the model predicts will succeed.

The paper encodes actions, states, and values all as latent frames, and uses the model's diffusion process to sample them together.

What can go wrong

What can go wrong

Value estimate overconfidence. If the model is trained on only successful demonstrations, it has never seen failure, so it may overestimate the value of risky actions. The robot attempts moves that seemed good in training but fail on the real hardware.
Distribution shift: robot platform difference. If the training robot has different gripper strength or arm reach than the deployment robot, the learned physics will not transfer. Actions that worked in simulation fail on different hardware.
Long-horizon planning breaks down. Predicting state and value many steps ahead is harder than one step. The model's predictions drift, and value estimates get noisier. Very long trajectories become unreliable.
Done right. Finetune on the target robot platform with diverse demonstrations (successes and safe failures), use ensemble sampling (pick the mode of many trajectories, not just the single greedy best), and limit planning horizon to steps where value predictions are reliable.
What a runnable demo should prove

What a runnable demo should prove

Build a minimal demo: take a pretrained video diffusion model (or a small proxy like a frame-diffusion model), finetune it on 10-20 short robot demonstration clips where a simulated arm picks an object. The demo should show that (1) a single finetuning run teaches the model to output actions, (2) sampling action sequences from the model beats a random policy, (3) using the model's value prediction to pick trajectories beats always sampling the same action.

success_rate = (number of trajectories that reach the goal) / (total sampled trajectories)

The demo must make clear that the model did not memorize the demonstrations (test it on new object poses never seen before) and learned a generalizable picker policy. Also show that value-guided planning picks trajectories with higher success rate than random action sampling, proving the value prediction carries real signal.
