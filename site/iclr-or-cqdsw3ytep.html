ERA: Entropy Regularizing Activation

ERA boosts model performance across math, control, and vision by transforming output activations to guarantee minimum entropy.

Paper explainersAll themesReinforcement Learning

Large language models, robot controllers, and image classifiers often have a problem: they give overconfident answers to uncertain questions. ERA is a simple trick that fixes this by changing the last layer of the model. It forces the model to keep some uncertainty by applying a transformation to the raw output numbers before they become probabilities. In tests, because models stay uncertain during training, they explore more and find better solutions: math scores jump 37%, robot control improves 30%, and image recognition gains 0.69%, all for 7% more computation time.

Zero assumption version

Overconfident outputs trap models

Neural networks (systems that learn patterns from examples) create output numbers for every possible answer. In a math problem, that might be numbers for each choice A, B, C, D. In robot control, numbers for how hard to push each joint. These raw numbers get converted to probabilities (fractions between 0 and 1 that add up to 1) via a calculation that spreads the numbers proportionally based on their size. The problem: a trained model often makes one output much bigger than the others, leaving the others tiny. When this huge gap gets converted into fractions, one fraction becomes almost-certain (0.97 for choice A) while the others shrink to nearly 0.

Why is overconfidence bad? In math (like AIME, a competition test), being slightly unsure about a hard problem is honest. In robot control, wild confidence in the wrong direction kills the task. In image recognition, a tiny 0.69% drop in top-1 accuracy costs real money at scale. The naive fix is to add noise or explicitly tell the network to spread its outputs more evenly. But these workarounds either hurt what the model learned or require tuning many new controls.

The method in one sentence. ERA changes the activation function (the output layer of the network) so that no single output can grow much larger than the others, forcing the model to keep genuine uncertainty.

What the paper changes

What the paper changes

ERA modifies the activation function at the output layer — the final step that turns raw numbers into answers. Instead of a standard activation (like ReLU or identity), ERA applies a clamping function that keeps all outputs within a bounded range. This is a tiny surgical change to the last layer; everything else stays the same.

the object it moves  =  output activation function
The hidden quantity

Entropy: the hidden quantity that measures spread

measured quantity  =  entropy of the output probabilities

Entropy is a single number that measures how spread-out a probability distribution is. If the model is nearly certain (0.97 for choice A, 0.01 for the others), entropy is low. If the model is uncertain (0.25 for each of four choices), entropy is high. Mathematically, entropy counts how many equally-probable outcomes fit; in plain terms, it measures how much the model is hedging its bets.

ERA measures entropy over all possible outputs at each step. The activation function is designed so that no matter how the network trains, the entropy of the final probabilities cannot drop below a threshold. The paper does not report raw entropy numbers but proves mathematically that the constraint is enforced by the activation shape.

Why it works

Why constraining outputs fixes overconfidence

A standard conversion takes any list of numbers and turns them into probabilities (fractions that add to 1). When you start with a big gap in sizes (e.g., 100 vs 1 vs 1 vs 1), the conversion squashes the biggest number into almost 1.0 and the others near 0. When the starting numbers are close in size (e.g., 50 vs 48 vs 49 vs 50), the conversion spreads the probabilities across them more evenly. The bigger the gaps in the original numbers, the more certain (winner-take-all) the result.

ERA exploits this by clamping each raw output into a narrow band, say 0 to 10 instead of allowing 0 to 1000. When the network tries to make one output much larger to signal confidence, the cap stops it. All outputs are forced to stay similar in size, so the conversion cannot collapse the probabilities onto a single answer. The network must express what it learned by the detailed pattern across multiple outputs, not just one dominating signal.

This helps because in hard problems (math, complex robot moves), multiple answers are genuinely plausible. When the model keeps enough uncertainty, it explores more options during training instead of locking onto one wrong answer early. It tries different strategies in robot control longer, finding richer solutions. The cap acts as a constraint that keeps the model flexible and learning longer.

The clamping equation

First in words:

Each output gets clamped to a min and max. If x is the raw output, the clamped version is max(min_bound, min(x, max_bound)). All outputs stay within this narrow range. Softmax then runs on these bounded outputs instead of unbounded ones.

Then the compact form:

clamp(x, a, b) = max(a, min(x, b)); p_i = exp(clamp(z_i, a, b)) / sum_j exp(clamp(z_j, a, b))

Every symbol:

x or z_iraw output number from the network for choice i
alower bound of the clamp (e.g., 0)
bupper bound of the clamp (e.g., 10)
clamp(x, a, b)bounded version of x: if x < a return a; if x > b return b; else return x
p_ifinal probability for choice i
exp()exponential function (e to the power of)
A tiny worked example
Say the network outputs: [102, 5, 8, 3]. Without clamping, the conversion sees a huge gap and makes [0.999, 0.0003, 0.0008, 0.0002].
Now clamp to [0, 10]: [102, 5, 8, 3] becomes [10, 5, 8, 3] (the 102 hits the cap).
Convert [10, 5, 8, 3]: each exp(x) divided by sum gives 0.87, 0.006, 0.12, 0.001 respectively.
Much more balanced: [0.87, 0.006, 0.12, 0.001] vs [0.999, 0.0003, 0.0008, 0.0002]. The cap forced uncertainty.

The clamping function is simple: just a floor and ceiling. The conversion does all the probability work, but now it cannot amplify a single large output into near-certainty.

What can go wrong

What can go wrong

Clamping bounds set too tight. If the min and max are too close (e.g., 0.1 to 0.2), outputs cannot express learned differences. The model is strangled. This is a tuning failure; the bounds must be wide enough for the task.
Bounds set too loose. If the bounds are very wide (e.g., 0 to 1000), the clamping does nothing; overconfidence returns. The constraint only works if the range is narrower than the network's natural output range.
Wrong domain for the task. Some tasks actually need high confidence. A self-driving car should be nearly certain before braking hard. ERA forces uncertainty, which is wrong for safety-critical decisions that demand confidence.
Done right. Bounds are chosen per task (via a validation set). The clamp is small enough to prevent overconfidence but large enough to let the network express what it learned. The 7% compute overhead is negligible.
What a runnable demo should prove

What a runnable demo should prove

Build a small neural network (e.g., a 3-layer image classifier on CIFAR-10 or a simple robot controller on a toy task). Train one copy normally. Train an identical copy with ERA's clamping on the output layer. Record the entropy (how spread the probabilities are) and final accuracy. The demo should show: (1) the normal model reaches very low entropy because one answer dominates, (2) the ERA model keeps entropy higher because clamping keeps all outputs similar, (3) ERA model learns faster, because it keeps trying alternatives longer instead of locking onto a wrong answer.
