Difference-Aware Retrieval Policies for Imitation Learning

Instead of learning one global action rule, DARP predicts actions by looking at the few closest expert examples and measuring how far the current state differs from them.

Paper explainersAll themesRobotics & Control

When a robot learns by copying expert demonstrations, it tends to fail when it lands in a state the expert never showed it. The robot has no practice recovering. DARP solves this by rewiring imitation learning: instead of training a single policy that maps any state to an action, it trains a model that looks up the handful of most similar expert examples, sees what actions those experts took, and predicts actions based on how the current state sits relative to those neighbors. This local view makes the robot recover gracefully when it meets unfamiliar states without requiring new expert data.

Zero assumption version

Behavior cloning breaks when the robot sees an unfamiliar state

Behavior cloning is the simplest way to teach a robot: show it expert demonstrations (states paired with the correct actions to take), and train a neural network to predict actions from states. It works well when the robot stays in the training regime, but fails as soon as the robot lands in a state the expert never demonstrated. The robot has no learned response, so it guesses wrongly, takes a bad action, and ends up in an even stranger state. Each mistake compounds the next.

A naive attempt: just collect more demonstrations to cover every possible state. This doesn't scale. There are infinitely many possible states, and hiring an expert to demonstrate every one is infeasible.

The core problem: A single learned policy must memorize a direct state-to-action mapping; any state outside that memory gets a wrong guess.

The algorithm as a flow

What it actually does

Step 1: Store the expert buffer

Keep every state and action the expert demonstrated; do not forget them.

Step 2: At inference, find neighbors

Given a new state, compute distance to all expert states; pick the k closest.

Step 3: Calculate neighbor offsets

For each neighbor, measure how far the new state is from it in each dimension (the relative position).

Step 4: Assemble the feature list

Concatenate the neighbor states, their actions, and the offsets into one long list of numbers.

Step 5: Predict the action

Feed the assembled list through a learned neural network to predict the next action.

What the paper changes

What the paper changes: from direct mapping to neighborhood reasoning

Standard behavior cloning trains a model to answer the question: given state, what action? DARP rewires the question entirely: given a state, find its k nearest neighbors in the expert buffer, and predict the action using information about those neighbors and how far away you are from each. The network no longer directly maps state to action; instead, it learns to reason about the local structure around the query state.

the object it moves  =  Imitation policy representation
The hidden quantity

The hidden quantity: how close neighbors are and how they arrange around the query

measured quantity  =  Local neighborhood relevance

Every query state sits surrounded by expert demonstrations. DARP measures a new hidden quantity: how close are the expert neighbors, and how do they arrange around the query state (the relative difference vectors). This quantity captures something behavior cloning never explicitly uses—the structure of the expert's demonstrations (which are near, which are far, and in what pattern they surround the current state). When neighbors are nearby and varied, the robot has multiple nearby examples to learn from. When the query falls far from any expert state, the distances signal that the robot is in uncharted territory.

The paper estimates this by precomputing distances from the query state to all stored expert states, sorting by distance, and keeping the k nearest. The relative vectors (query minus each neighbor) become explicit features fed to the prediction model.

Plain reading. Imagine you are lost in a city and ask someone for directions. If you spot three locals nearby who walk a familiar route, you can infer your own route by seeing where they go and measuring how far away you are from each one. Local examples teach you more than a single memorized map.
Paper reading. The k-nearest neighbors and their corresponding action labels, plus the relative distance vectors between the query state and each neighbor, compose the input feature set. The model learns to weight and combine these signals to predict actions.
Why it works

Why it works: neighbors carry the expert's know-how for similar situations

Behavior cloning trains a single policy to memorize a direct mapping from every state to the correct action across the entire training dataset. When a new state arrives that sits far outside that memorized space, the network must extrapolate blindly—and fails. DARP sidesteps this by querying the expert buffer directly. If a new state lands between two expert demonstrations, the k-nearest neighbors in that local region encode the expert's behavior for similar situations. The difference vectors make explicit how far the new state deviates from each neighbor, so the prediction model can reason: the query is 0.3 units away from neighbor A (which took action 2.5) and 0.5 units from neighbor B (which took action 2.3), so a safe action here is something in between and slightly adjusted.

This works because the expert demonstrations already sample the decision space. A new state near that sample inherits the expert's knowledge; a state far from all samples clearly signals low confidence (all neighbors are distant). The model learns to interpolate and adjust rather than blindly extrapolate. The difference vectors turn this fuzzy intuition into concrete features the network can learn from.

Math after the picture

The equation: combining neighbor actions with distance-weighted reasoning

First in words:

predicted action = neural network applied to (concatenated neighbor states, neighbor actions, distance vectors)

Then the compact form:

a_pred = f_theta([s_neighbors; a_neighbors; (s_query - s_neighbors)])

Every symbol:

a_predthe action the model predicts
f_thetathe learned neural network with parameters theta
s_neighborsthe k closest expert states (stacked into a vector)
a_neighborsthe k expert actions corresponding to those neighbors
s_querythe current state the robot is in
s_query - s_neighborsthe difference vectors (how far the query is from each neighbor)
Tiny worked example: robotic reaching with k=2 neighbors
Expert buffer: neighbor-1 at position (0, 0) took action reach-right-2, neighbor-2 at (0.5, 0.2) took action reach-right-1.8.
Current query state: robot arm at (0.3, 0.1).
Distances and differences: neighbor-1 is 0.36 units away (diff = 0.3, 0.1); neighbor-2 is 0.22 units away (diff = -0.2, -0.1).
Feature vector fed to network: [0, 0, 0.5, 0.2, reach-right-2, reach-right-1.8, 0.3, 0.1, -0.2, -0.1].
Network learns: neighbor-2 is closer and more relevant; predict action closer to reach-right-1.8, adjusted for the -0.2, -0.1 offset. Output: reach-right-1.75.

The network does not just average the neighbors; it learns to weight them by their relevance (distance) and the specifics of the difference vectors, which encode how the query sits relative to each neighbor.

What can go wrong

What can go wrong

Expert buffer is sparse or poorly distributed. If the expert demonstrations cluster in only part of the state space, unfamiliar queries far from any cluster still have distant neighbors with weak guidance. The robot still fails in unexplored regions.
Neighbors are in high-dimensional spaces where distance breaks down. In very high-dimensional state spaces (e.g., raw images), Euclidean distance becomes unreliable—all points are roughly equally far apart. Neighbors stop being semantically similar. A learned distance metric or representation is needed.
Computational cost grows with expert buffer size. Finding k nearest neighbors at every inference step requires computing distances to all stored expert states. For large datasets, this is slow. Approximate nearest-neighbor methods (hashing, trees) help because they skip far-away points instead of checking every one; however, they trade computation for being slightly less accurate.
Done right: choose expert data that densely covers the deployment region. If the expert demonstrates across a representative spread of states and the deployment states stay within that region, neighbors are close and guidance is strong.
What a runnable demo should prove

What a runnable demo should prove

Build a simple continuous control task (e.g., 2D ball-reaching or a cartpole swing-up). Collect 50 expert demonstrations. Train standard behavior cloning on them. Then train DARP using the same 50 demonstrations without collecting any new data. Evaluate both on a held-out test set that includes states outside the training distribution (e.g., by perturbing the goal position or initial state in a region the expert did not cover). Measure success rate on on-distribution vs out-of-distribution states separately.

robustness gain = out-of-distribution success rate (DARP) - out-of-distribution success rate (behavior cloning)

The demo must show that DARP recovers gracefully on unfamiliar states while behavior cloning fails, proving that neighborhood structure is a stronger foundation than direct state-to-action memorization because neighbors encode how experts handle similar situations, not a brittle global rule.
