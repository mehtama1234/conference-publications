Difference-Aware Retrieval Policies for Imitation Learning

Instead of one giant model, predict actions by looking at nearby expert examples and how far away you are from them.

Paper explainersAll themesRobotics & Control

When a robot learns from watching an expert, it memorizes expert moves but fails on situations the expert never showed. DARP solves this by keeping all the expert examples and retrieving them at decision time, then predicting actions based on how different the current situation is from nearby examples.

Zero assumption version

Why memorized rules fail on new situations

Behavior cloning trains a single model on expert state-action pairs (what the expert did in each situation). At test time, the robot only has this one model and nothing else. When it encounters a situation unlike any the expert showed, the model guesses and often guesses wrong. Those wrong guesses compound: a small error in one step cascades into bigger errors in the next step, and the robot drifts farther and farther from what the expert would do.

A beginner might try teaching the model to be more confident or to memorize harder. But that fails because the problem is not weak memory—it is that no single model can reliably generalize (make correct predictions on new cases) to situations it never trained on.

In one sentence. DARP keeps the expert examples and at decision time retrieves nearby ones, then predicts actions based on how the current situation differs from each neighbor.

The algorithm as a flow

What it actually does

Store expert data

Keep all expert state-action pairs in memory.

Retrieve neighbors

Find the k closest expert states to the current query state.

Compute differences

Calculate how far the query state is from each neighbor (a list of position differences).

Condition on neighborhoods

Feed the model tuples of (neighbor state, neighbor action, position difference).

Predict refined action

Model learns to adjust the neighbor actions based on how different the query is.

What the paper changes

What the paper changes

Instead of a model learning state to action directly, DARP changes the architecture so the model learns to adjust expert actions based on how different the current state is from neighbors in the training data. This works because adjusting a nearby expert move is easier than predicting a move for an unseen situation—the model only needs to learn local corrections, not a global rule.

the object it moves  =  model architecture: from learning one rule for all states to learning to adjust nearby expert actions.
The hidden quantity

Implicit neighborhood smoothness

measured quantity  =  How much the action should change when the state moves.

The hidden quantity is the local smoothness: when a robot state changes slightly, the action should change only slightly too, because the world is usually smooth—small changes in position lead to small changes in the right move. The paper calls this implicit manifold regularization (iMRIL).

DARP measures this implicitly by comparing the query state to all stored neighbors. If the query is close to many similar expert states, those neighbors must all agree roughly on the action, which forces the model to predict an action consistent with the local neighborhood structure. The paper does not compute an explicit smoothness score; instead, it builds neighborhood aggregation into the model architecture itself, so smoothness emerges naturally.

Why it works

Why this rescues generalization

Behavior cloning fails because it asks one model to predict a correct action for the entire world—including situations it never saw. DARP changes the question: instead of ask the model to predict the action directly, ask it to predict how each neighbor's action should be adjusted given the differences. This works because adjusting nearby actions is an easier problem than predicting from scratch.

When the query state is close to a neighbor, the adjustment is small, and the model learns a small correction. When it is far from all neighbors (a truly new situation), the model still has to answer, but now it is adjusting actions from similar-enough cases, not guessing from nothing. The neighbors ground the prediction in observed behavior.

The equation: implicit manifold regularization

First in words:

The model predicts an action by averaging predictions at each neighbor state, weighted by how far that neighbor is from the query.

Then the compact form:

action_pred = sum_i w_i * f(neighbor_state_i, action_i, difference_i) / sum_i w_i

Every symbol:

action_predthe model's predicted action for the query state
w_iweight of neighbor i (higher if closer, lower if farther)
f(...)the learned model function
neighbor_state_ithe i-th closest expert state from the training data
action_ithe action the expert took in neighbor_state_i
difference_ithe difference vector: (query_state - neighbor_state_i)
A tiny worked example
Query state: a robot at (5.0, 3.0). Three neighbors: state A at (5.2, 3.1) [distance 0.22], state B at (4.8, 2.9) [distance 0.22], state C at (4.0, 2.0) [distance 1.41].
Weights (inverse distance): w_A = 1/0.22 ≈ 4.5, w_B = 1/0.22 ≈ 4.5, w_C = 1/1.41 ≈ 0.7. (Normalized by sum = 9.7.)
Expert actions: A did move 0.8, B did move 0.7, C did move 0.2. The model learns small adjustments: +0.05 for close neighbors (slightly different situations), +0.00 for distant neighbor.
Predicted action = (4.5 * 0.85 + 4.5 * 0.75 + 0.7 * 0.2) / 9.7 ≈ (3.83 + 3.38 + 0.14) / 9.7 ≈ 0.76. Close neighbors dominate; distant neighbor barely influences the result.

The equation shows that neighbors close to the query state have much higher weight, so the prediction stays consistent with observed behavior in the local region of the state space.

What can go wrong

What can go wrong

Retrieval is slow on large datasets. Finding k neighbors requires searching the entire training set, which is expensive if the expert demonstrated millions of situations. In robotics with limited compute, this is a real constraint.
Neighbors must be in the right space. Retrieval finds neighbors in whatever representation is used (raw pixels, feature vectors, etc.). If the representation is wrong, neighbors are meaningless, and the method fails. The paper tests multiple representations but does not solve representation learning.
Extrapolation beyond all neighbors still guesses. When the query state is genuinely far from all expert examples, the method must still predict something. It picks the least-bad neighbor adjustment, but that adjustment is still a guess.
Done right, it works across domains. The paper shows consistent improvements on continuous control tasks and robotic manipulation across different visual representations, suggesting the method is general.
What a runnable demo should prove

What a runnable demo should prove

Build a simple robot control task: a 2D point moving from start to goal, with obstacles. Collect 50 expert demonstrations (state-action pairs showing how an expert navigates). Split into train and test. Compare behavior cloning alone versus DARP (behavior cloning plus retrieval). On test cases that match training: both should succeed. On test cases with unseen obstacles or start positions: behavior cloning should fail, DARP should stay close to expert paths by retrieving and adjusting neighboring strategies.

success_rate = (count of reached goals without collision) / (count of test runs)

DARP should show 15-20% higher success on unseen situations than behavior cloning, because neighbors constrain the prediction to stay in the manifold of expert behavior.
