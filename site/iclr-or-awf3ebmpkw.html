Expert Merging: Layer-wise coefficient learning for domain-specialized models

Combine multiple specialized LLMs into one by learning what fraction of each expert to use at each layer, guided by how important that layer is.

Paper explainersAll themesLLMs & Foundation Models

You have several large language models trained for different jobs: one writes math, one writes code, one answers questions. Instead of running all three at once (expensive) or picking one (limited), you can stitch them together into a single merged model. This paper shows how to pick the right balance of each expert at each layer using just a handful of unlabeled examples, and allocate more mixing choices to the layers that matter most.

Zero assumption version

Merging experts the hard way

When you have multiple specialized models (one for math, one for code, one for chat), you face a dilemma: serving all three costs a fortune in GPU memory and latency. You could simply add their outputs together, but without carefully tuning how much of each expert to use, you get interference: the math expert nudges individual words one way, the code expert another, and the merged result becomes confused.

Simple approaches that hand-tune a single number per layer ignore the fact that not all layers are equally important to the final answer. The lowest layers build basic patterns that all experts share; the highest layers do the specialized reasoning. Treating them all the same wastes capacity on layers that do not need fine-tuning.

The problem in one sentence. You need to learn how much of each expert to blend at each layer, and give more blending control to layers that actually matter.

The algorithm as a flow

What it actually does

Grab a few unlabeled examples

Pull 5-10 random sentences that have nothing to do with your task.

Make a merged model

Start with a base model, then add a fraction of each expert's changes at each layer.

Measure hidden-state mismatch

Run your examples through the merged model and each expert. Measure how different the layers' intermediate outputs are.

Learn what fraction of each expert to use

Tweak the blend fractions to shrink that mismatch. Only a few hundred optimization steps on unlabeled data.

Rank layer importance and reallocate control

Count which layers moved the most and handle the most weights. Give those layers more independent blending knobs.

What the paper changes

The single thing the paper changes

The paper learns a set of layer-wise blending coefficients. Instead of hand-tuning them, it treats each coefficient as a learnable number that can be tuned on unlabeled data. In Expert Merging++, it goes further: high-importance layers get multiple independent coefficients (one chunk of coefficients per section of the layer), while low-importance layers stay simple.

the object it moves  =  Layer-wise blending coefficients
The hidden quantity

The hidden quantity: layer importance

measured quantity  =  Layer importance score

Layer importance is a single score per layer that measures how much that layer actually contributes to the final prediction. Layers that do heavy lifting get a high score; layers that just shuffle data around get a low score.

The paper computes it from three signals: how much the layer's expert changes moved (the magnitude of change each expert made), how many weights (numbers inside the model) the layer has, and what the learned blending coefficients turned out to be. Layers that need big coefficient adjustments to match expert behavior, that have large expert changes, and that have many weights all score high. This score then determines how many independent blending knobs that layer gets in Expert Merging++.

Paper reading. Layer importance combines three things: the strength of the learned blend coefficients, the size of each expert's weight changes at that layer, and how many weights that layer contains. Divide by the total importance across all layers to get a normalized score from 0 to 1.
Why it works

Why it works: alignment before task training

The core insight is to align the merged model's intermediate outputs (the hidden states inside each layer) to each expert's hidden states before you ever try the final task. Think of it like tuning an instrument: you make sure each string resonates correctly before you play the song. When the merged model's layer 5 output matches what the Code expert's layer 5 would have produced, then blending is working right at that point.

The paper measures this mismatch using two alignment losses: one on the hidden states at each layer, and one on the final logits (the raw scores before the model picks an answer). By minimizing these two, you learn how much of each expert's weight changes to copy at each layer. Then, to avoid overfitting on those few calibration examples, you add a penalty term that keeps coefficients small and stable.

Expert Merging++ goes further: after you learn the coefficients, you compute which layers are doing the real work (layer importance) and split those layers into chunks. Each chunk of an important layer gets its own coefficient, giving fine-grained control where it matters. Low-importance layers stay simple with a single coefficient.

Math after the picture

The equation: layer-wise alignment loss

First in words:

For each layer, the penalty is the sum of the mismatch between the merged model's hidden state and each expert's hidden state, plus the mismatch in the final logits, plus a small penalty for using large coefficients.

Then the compact form:

Loss = sum_layer (mse(h_merged, h_expert) + mse(z_merged, z_expert)) + lambda * sum_layer sum_expert |alpha|

Every symbol:

h_mergedthe hidden state output of the merged model at that layer
h_expertthe hidden state output of each expert model at that layer
z_mergedthe final logits (raw answer scores) from the merged model
z_expertthe final logits from each expert model
alphathe learned coefficient for blending that expert at that layer
lambdahow much to penalize large coefficients (keep them small)
mse(A, B)mean squared error: the average squared difference between A and B
A tiny worked example
Suppose layer 5 has Math expert, Code expert, and Chat expert.
The merged model's layer 5 output is [0.2, -0.1, 0.5].
Math expert's layer 5 output is [0.3, 0.0, 0.4].
Code expert's layer 5 output is [0.1, -0.2, 0.6].
Chat expert's layer 5 output is [0.2, -0.1, 0.5].
Mismatch with Math: (0.2-0.3)^2 + (-0.1-0.0)^2 + (0.5-0.4)^2 = 0.01 + 0.01 + 0.01 = 0.03.
Mismatch with Code: (0.2-0.1)^2 + (-0.1-(-0.2))^2 + (0.5-0.6)^2 = 0.01 + 0.01 + 0.01 = 0.03.
Mismatch with Chat: (0.2-0.2)^2 + (-0.1-(-0.1))^2 + (0.5-0.5)^2 = 0.00.
Layer 5 alignment loss is 0.03 + 0.03 + 0.00 = 0.06. The optimization algorithm pushes the coefficients to move the merged output closer to the experts.

The alignment loss directly measures how well the merged model at each layer behaves like each expert at that layer.

What can go wrong

What can go wrong

Calibration data is too task-specific. If your 5-10 unlabeled examples happen to be all math problems when you are merging a chat and math expert, the alignment will overfit to math. Use diverse, truly random data.
Experts are too different. If one expert was trained on entirely different data from the others, their hidden states may have completely different scales or meanings. Alignment will fight to match incompatible representations.
You ignore the layer-importance score. If you give equal control to all layers (vanilla Expert Merging), you are wasting capacity on layers that do not need tuning. Expert Merging++ fixes this, but only if you actually compute and use importance.
Done right. Use diverse calibration data, ensure experts are trained on similar base models, and apply importance-guided chunking to layers that actually matter.
What a runnable demo should prove

What a runnable demo should prove

Build a toy model with two expert branches (or use a small open-source LLM with two fine-tuned variants). Implement layer-wise coefficient learning: forward-pass both experts and the merged model on 5 random sentences, compute the hidden-state and logit mismatch, run a few optimization steps to tweak the coefficients, then measure accuracy on held-out task-specific examples. Compare against equal blending and a hand-tuned baseline.

Task accuracy improvement = accuracy_with_learned_coefficients - accuracy_with_equal_blend

The demo must make it obvious that learning coefficients from hidden-state alignment (without task labels) beats guessing or manual tuning.
