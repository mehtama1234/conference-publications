Personalized Policy Learning through Discrete Experimentation

Learn a personalized continuous treatment rule from discrete randomized experiments by estimating how each user's outcome changes across treatment levels and then optimizing that fitted response curve.

Paper explainersAll themesOther

A large online platform often wants to choose a continuous policy variable such as a price, incentive, or payment level for each user. Standard randomized controlled trials usually test only a few discrete levels. That tells us which tested level did better on average, but it does not directly tell us which untested value would be best for a particular user because the optimum may lie between the tested arms and may differ across users. This paper proposes Deep Learning for Policy Targeting, or DLPT, which uses high-dimensional user features to learn how outcomes vary with treatment level and then chooses a personalized continuous action from that learned relationship. The main challenge is to extrapolate from discrete experimental arms without inventing arbitrary behavior between them.

Zero assumption version

Why discrete A/B tests are not enough for continuous decisions

A platform can run an experiment with treatment levels such as low, medium, and high incentive. Randomization makes the causal comparison trustworthy at those tested levels. But if the real decision space is continuous, the platform still does not know what would happen at the many untested values between them or beyond them.

Personalization makes the gap wider. Different users may respond differently to the same incentive. A global best arm can leave substantial value on the table if one user should receive slightly more and another slightly less. The learning problem is therefore to infer an individualized response curve from sparse randomized data.

The paper's move. Fit a user-specific treatment-response function from discrete randomized arms, then optimize that function over a continuous action range because the best personalized decision may lie between the levels that were directly tested.

The algorithm as a flow

What it actually does

Collect randomized data

Run an experiment with several discrete treatment levels and record outcomes together with high-dimensional user features.

Estimate the response surface

Train a model that predicts outcome as a function of both user features and treatment level, so the method can interpolate across the tested arms.

Recover user-specific effects

Use the fitted model to estimate how each individual user's outcome changes when the treatment moves up or down.

Optimize treatment continuously

Search over the allowable treatment range and choose the value with the highest predicted reward for that user.

Evaluate regret

Measure how much value is lost relative to the best possible personalized policy, because that shows whether the learned rule converges toward the correct decision.

What the paper changes

What the paper changes

The paper changes how experiment data is used after an A/B test. Instead of selecting among the tested arms only, it turns the experiment into a continuous personalized decision problem.

the object it moves  =  the policy mapping from user features to treatment level
The hidden quantity

The hidden quantity

measured quantity  =  the user-specific response curve over treatment values

The hidden quantity is the full treatment-response curve for each user. The experiment reveals only a few points on that curve because each user is assigned one discrete arm. The rest of the curve must be learned from patterns shared across users with similar features.

DLPT estimates that curve by combining experimental randomization with a flexible predictive model. Randomization matters because it separates treatment choice from user characteristics in the observed data. The predictive model matters because it borrows strength across users to infer how the outcome changes between the observed treatment levels.

Why it works

Why discrete experiments can support continuous personalization

Randomized experiments provide reliable outcome comparisons at the treatment levels that were tested. That is the hard causal part. The remaining task is statistical: use those trustworthy anchor points to fit a response function that varies with both treatment and user features.

The learned function creates personalization because users with different feature patterns can receive different predicted curves. A creator who responds strongly to moderate incentives may have a peak at one value, while another creator may require a larger payment before outcomes improve, because their outcome sensitivity to treatment is not the same. Once those curves are estimated, policy selection becomes an optimization problem rather than a fixed-arm comparison.

The paper's theoretical contribution matters because interpolation between arms can be dangerous if it introduces systematic bias. By proving unbiasedness, consistency, and regret guarantees under their setup, the authors argue that the fitted policy converges toward the correct personalized rule rather than merely overfitting the finite experiment sample.

Math after the picture

Choose the treatment that maximizes predicted reward

First in words:

For each user, estimate the expected outcome at every allowed treatment level and choose the treatment with the highest predicted value. The prediction model is trained from randomized experimental data, so the fitted curve is anchored at observed treatment arms.

Then the compact form:

policy(user) = treatment value that maximizes predicted_outcome(user, treatment)

Every symbol:

userone individual with observed features
predicted_outcome(user, treatment)the model's estimate of that user's expected outcome at a chosen treatment value
policy(user)the personalized treatment level selected for that user
treatment value that maximizesthe optimization step that searches across the continuous action range
A tiny worked example
Suppose a trial tested incentives of 0, 5, and 10 units.
For one user, the fitted response model predicts outcomes of 2.0 at 0, 3.8 at 5, 4.1 at 7, and 3.9 at 10.
The best tested arm is 10 only if we restrict ourselves to trial arms, but the fitted continuous peak is 7.
DLPT therefore assigns 7 units to that user.
Another user could still receive 3 or 10 if their predicted curve peaks elsewhere.

The important change is that the chosen action does not need to match one of the original experiment arms once the response function has been estimated.

What can go wrong

What can go wrong

The tested treatment range may be too narrow. A model can interpolate more safely than it can extrapolate. If the best personalized value lies far outside the tested arms, predictions there may be unreliable because the trial offers little direct evidence.
Sparse arms can leave the response shape weakly identified. With only a few treatment levels, several smooth curves can fit the observed points. If the model class is too flexible, it may infer the wrong peak location between arms.
Feature shift after deployment can break personalization. The policy is learned from historical users in the experiment. If future users differ substantially, the fitted response model may assign treatments based on patterns that no longer hold.
Done right. The approach is strongest when the experiment spans the relevant treatment region and the platform has enough feature coverage to estimate how response curves differ across users.
