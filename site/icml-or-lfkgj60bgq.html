How can embedding models bind concepts?

Study why image-text embedding models can recognize the parts of a scene yet still fail to represent which properties belong to which object, then show that low-complexity binding can emerge in controlled training.

Paper explainersAll themesMultimodal

Concept binding is the problem of attaching the right attributes to the right object in a multi-object scene. A model should know that the red shape is the square and the blue shape is the circle, not merely that red, blue, square, and circle all appear somewhere. This paper studies why contrastive embedding models, meaning models that place matching images and texts near each other in a shared feature space, such as CLIP often fail at that distinction. It finds that the scene embedding can still contain recoverable object information, yet the mapping from object concepts to the final shared embedding is too complex to generalize well across unseen combinations. The paper then shows that this limitation is not inevitable by training controlled transformer models, meaning sequence models built from repeated focus-weighting blocks, from scratch and observing when simpler binding behavior appears.

Zero assumption version

Why recognizing concepts is not enough

A retrieval-oriented embedding model maps images and texts into a shared vector space, meaning a space where each example becomes a list of numbers. Similar image-text pairs should land near each other. That objective is good at detecting which concepts are present overall, but it does not force the model to represent how those concepts are grouped into objects.

As a result, the model can behave as a bag-of-concepts system. It can know that a scene contains a red thing and a blue thing, plus a square and a circle, while still failing to know which color belongs to which shape. This is a binding failure because the model has concept presence without concept assignment.

The paper's move in one sentence. Analyze the binding function from object concepts to scene embeddings, show why CLIP-like models learn a high-complexity mapping, and demonstrate that simpler multiplicative binding can generalize when training coverage is sufficient.

Treat a scene as a set of object concepts and ask how those concepts are mapped into one image or text embedding.

Probe existing embedding models

The hidden quantity

The hidden quantity

measured quantity  =  Binding-function complexity

The key hidden quantity is the complexity of the function that maps object concepts into one scene embedding. Complexity here means how intricate the rule must be in order to assign concepts to objects correctly across many possible combinations.

This quantity matters because two models can both store object information, yet only the model with a simpler reusable binding rule will generalize to unseen pairings. The paper argues that CLIP-like models often rely on a high-complexity binding function, so image and text encoders do not converge on one shared rule that transfers systematically.

Why it works

Why this works: additive storage is not the same as relational binding

The paper finds a tension that is easy to miss. A scene embedding can decompose additively into object-related pieces, meaning the final vector can be approximated as a sum of contributions from different objects. That explains why probes can recover object information from image embeddings or text embeddings separately. The information is there.

But additive storage alone does not guarantee correct binding across modalities. To answer whether the red attribute belongs to the square or the circle, the model needs a consistent assignment rule. If that rule is highly complex, then the image encoder and text encoder may each fit the training combinations without agreeing on one low-complexity shared mechanism. Generalization then fails because unseen combinations require rule reuse rather than memorized co-occurrence.

The controlled transformer experiments show that binding can emerge when data coverage is sufficient and the model learns multiplicative interactions, meaning terms where two concept signals combine rather than simply add. Those interactions can express who-goes-with-whom more directly because they encode pair-specific relations rather than only separate concept presence, so the resulting binding function is simpler and transfers better to new concept compositions.

A simplified binding decomposition

First in words:

The paper's main structural claim is that a scene embedding can be written as a sum of object terms, while successful generalization needs additional interaction terms that encode which concepts belong together.

Then the compact form:

e_scene = sum_j e_object_j + sum_jk g(concept_j, concept_k)

Every symbol:

e_scenethe final scene embedding
e_object_jthe contribution from object j
g(concept_j, concept_k)an interaction term that captures concept binding between paired attributes
sum_jthe additive object contributions
sum_jkthe extra interaction terms needed for binding relationships
A tiny worked example
Suppose a scene has a red square and a blue circle.
An additive model can store red, blue, square, and circle as separate object-related parts.
If it lacks a strong interaction term, swapping the pairings to red circle and blue square may leave the scene embedding too similar.
Adding explicit interaction terms for red with square and blue with circle separates the two scenes and supports correct binding.

The exact analysis in the paper is more formal, but this summary captures the difference between storing concepts and storing assignments.

What can go wrong

What can go wrong

Probe success can be misread as binding success. Recovering object information from embeddings does not prove that the model bound attributes correctly, because a probe can exploit stored concept pieces without revealing how those pieces are assigned.
Controlled settings may oversimplify natural scenes. A clean synthetic task may reveal the mechanism clearly, but real images contain clutter and ambiguity that can require richer binding rules.
Coverage demands may be large. The paper shows that better binding emerges with sufficient training coverage, but that requirement may become expensive as the number of possible concept combinations grows because covering enough pairings can require a rapidly expanding dataset.
Done right. The method is most informative when the evaluation separates concept detection from concept assignment and when data coverage is varied carefully enough to expose the transition from memorization to rule-based binding.
What a runnable demo should prove

What a runnable demo should prove

Create a synthetic dataset of scenes with two objects, each defined by color and shape. Train one contrastive image-text embedding model on limited combinations and another on broader coverage. Then evaluate four things separately: concept presence detection, object probe recovery, cross-modal retrieval, and binding generalization on unseen pairings.

The demo should include an analysis of scene embeddings as additive object parts plus interaction terms. It should show that a model can score well on retrieval and still fail binding, while broader coverage encourages a simpler relation-aware rule that transfers to new combinations.

binding_gap = concept_presence_score - binding_generalization_score

A convincing demo must separate stored ingredients from correct assignment of ingredients to objects.
