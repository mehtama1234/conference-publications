Selling Data as a Digital Good with Scaling Valuations

Treat data as a copyable good whose value rises with dataset size but with diminishing returns, then design allocation and production rules around that shape.

Paper explainersAll themesOther

Ordinary auction theory is built around scarce goods: if one buyer gets the item, another buyer cannot. Data is different because the seller can copy the same dataset for many buyers after paying to collect it once. The hard part is not exclusivity. The hard part is deciding how much data to produce and how much of that data each buyer should receive when value follows a scaling law. Early units of data can raise model quality a lot, while later units add less. This paper builds mechanism design around that fact. In the offline case it shows that optimal allocations pool buyers on a shared produced amount because production cost depends on the largest delivered dataset, not on how many copies are sent. In the online case it shows that the seller must combine an initial production plan with later expansion because purely myopic selling can miss profitable demand that appears later.

Zero assumption version

Data markets are not ordinary single-item auctions

If a seller is offering one physical item, the allocation is binary: a buyer wins or loses. If a seller is offering training data, the allocation is continuous because a buyer can receive ten thousand examples, one million examples, or any amount in between. The same produced data can also be copied to several buyers.

That changes the objective. The seller chooses production volume and allocations jointly. One more unit of data may still be worth making if several buyers all benefit from that same expansion. But the buyer side has diminishing returns because scaling laws say each extra unit usually adds less model value than the previous one.

The paper's move. Model data as a copyable good with concave buyer value in dataset size, then solve pricing and production together instead of pretending the seller is only assigning winners.

The algorithm as a flow

What it actually does

Write buyer value as a scaling law

Model each buyer's utility from data quantity with diminishing returns because later data units contribute less than early ones.

Solve the offline benchmark

Assume all buyer types are known at once and derive the profit-maximizing truthful mechanism using virtual values adapted to continuous allocations.

Show the pooling structure

Allocate the same produced quantity to all buyers with positive adjusted value because the production cost depends on the maximum produced amount.

Move to sequential arrivals

Let buyers appear over time and force the seller to make irreversible production decisions under uncertainty.

Use two-stage production

Produce an initial amount from prior demand estimates, where prior means the demand beliefs available before arrivals are observed, then expand adaptively because fixed plans and purely myopic plans can both perform badly.

What the paper changes

What the paper changes

The paper changes the good being sold from a winner-take-all object into a produced quantity that can be copied. Once that change is made, the mechanism must optimize over a shared data volume rather than only over who wins.

the object it moves  =  the allocation variable: from binary winning to continuous shared data volume
The hidden quantity

Aggregate marginal value of one more unit

measured quantity  =  aggregate marginal value (how much total buyer value is created by expanding the produced dataset slightly)

The seller needs to know whether one more unit of production is justified. That answer is hidden because it depends on all active buyers at once, not on one posted price alone. The next unit is worth producing only if the sum of extra value across served buyers exceeds the marginal production cost.

Diminishing returns make this quantity move downward as production grows. Early expansion may be profitable because many buyers gain a lot from the first extra units. Later expansion may stop being profitable because each buyer's extra gain has already flattened out.

Why it works

Why pooling and expansion are the right structure

Pooling appears in the offline solution because one produced dataset can be copied. If the seller has already paid to produce a certain amount, giving that same amount to another buyer with positive virtual value adds revenue without increasing production cost. That is why the mechanism often serves all positive-virtual-value buyers at a common quantity instead of tailoring a separate production level for each one.

The online difficulty is different because the seller does not yet know future demand. A myopic rule that produces only enough for the current buyer can underinvest because later buyers could have shared the same produced data. A fixed plan can also fail because it ignores realized demand. The two-stage rule works because it captures both forces: it secures some scale early from priors, then expands only when realized arrivals justify it.

The bilateral trading part fits the same logic. When both buyer value and seller cost are private, the mechanism must recover truthful reports while still respecting the scaling shape of data value. Exact optimal rules become complicated, but simple mechanisms still capture a constant fraction of the best possible gain because the scaling law limits how much welfare is concentrated in the last marginal units.

Math after the picture

Choose production where marginal gain meets marginal cost

First in words:

pick a common production quantity by comparing the summed adjusted marginal values of served buyers against the linear cost of producing more data

Then the compact form:

produce_more if sum_i positive_virtual_marginal_value_i(q) >= marginal_cost

Every symbol:

positive_virtual_marginal_value_i(q)buyer i's adjusted value from one more unit when current produced quantity is q, clipped at zero if serving that buyer is not worthwhile
marginal_costthe seller's cost of producing one more unit of data
qthe current common produced quantity
A tiny worked example
Suppose the next block of data costs 10 to produce.
Buyer A gains 6 from that block and buyer B gains 7, after the mechanism's truthfulness adjustment.
The total adjusted marginal value is 13, so expansion is worthwhile.
After more data has already been produced, the same next block may be worth only 4 to A and 3 to B.
The total is then 7, so production should stop.

The paper develops this rule formally with virtual values and truthful constraints, but the first-principles condition is the same: continue only while shared marginal value covers cost.

What can go wrong

What can go wrong

The scaling law is badly misspecified. If buyer value does not actually flatten in the assumed way, the production threshold can be wrong because the mechanism is comparing cost to the wrong marginal gains.
Buyer types are not independent of future market events. If arrivals are strategically correlated or demand shocks change value distributions, meaning the weighted spread of possible buyer values, sharply, prior-based initial production can be too low or too high.
Production is not truly linear. If marginal collection cost rises or falls strongly with scale, the clean pooling rule changes because the seller no longer faces one constant slope.
Done right. The analysis is most informative when data can be copied freely and collection cost is close to linear, because those assumptions isolate the market-design effect of scaling valuations.
What a runnable demo should prove

What a runnable demo should prove

Build a simulator with three buyers whose values follow concave curves in data quantity and one seller with linear production cost. First solve the offline case by computing the shared quantity that maximizes seller profit under truthful reporting. Then simulate sequential arrivals and compare three online rules: myopic production, fixed upfront production, and the two-stage expand-if-needed policy.

The demo should show that pooling creates value because the same produced dataset serves several buyers, and it should show that a two-stage policy beats the naive online rules because it preserves the option to expand after demand is observed.

A convincing demo makes the copyable nature of data visible and shows that production timing matters as much as pricing.
