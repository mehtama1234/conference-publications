Cross-Embodiment Robot Foundation World Models with Latent Actions

A robot learns to predict what will happen next by translating different robot bodies' action commands into a shared hidden language, so the model works better when adapted to new robots.

Paper explainersAll themesRobotics & Control

Different robots have different hands and arms, so they speak different action languages. This paper introduces a world model that learns one shared hidden action language across all the different robot embodiments it sees during training. Because all robots now feed the model their actions in the same hidden code, the model can learn patterns that transfer better when adapted to a brand-new robot it has never seen before.

Why robots cannot share what they learn

A world model is software that predicts the next video frame or the robot's position after an action. It learns by watching thousands of videos of the robot moving, then asks itself: given where I am and what action I take, where do I end up? The more embodiments (different robot designs) it learns from, the better its predictions should be, because more data and more diverse examples help the model spot patterns that apply broadly rather than overfitting to one robot's quirks.

But here is what breaks: a robot arm with three fingers and a robot arm with five fingers have completely different action vocabularies. When you tell the three-finger robot "spread your fingers," that command is meaningless to the five-finger robot — it already has two more fingers. So the model remembers: action A goes with three-finger body, and action B goes with five-finger body, because the explicit labels are simply different words from different manufacturers and nothing connects them. These actions stay locked to their original robot. When the model then sees a six-finger robot it has never met, it has no good guess for what "spread fingers" even means on this new body, because the model never learned any hand-independent concept of spreading — it only memorized three-finger and five-finger spreads as separate, unrelated commands.

The naive approach breaks because each robot stays trapped in its own action language. The paper teaches all robots to speak one shared hidden language for actions, so patterns learned from many robots transfer to new ones.

Predict using the hidden code

Adapt to a new robot

Measure prediction accuracy and downstream task performance on the new robot.

What the paper changes

What the paper changes

The paper changes how the world model receives action commands. Instead of receiving explicit motion labels (the names the robot manufacturer gave to each move), the model receives a latent action vector — a hidden list of numbers that encodes the action in a unified way across all robots.

the object it moves  =  action representation
The hidden quantity

The hidden quantity: action alignment

measured quantity  =  action alignment

Action alignment is how well a single hidden action code can represent moves from many different robots without getting tangled up. It is the opposite of what happens with explicit labels, where a robot manufacturer's "grasp" command means different things on different hands.

The paper estimates alignment by comparing two setups: the latent-action version (LAC-WM, where all robots speak one hidden language) and the explicit-action version (EAC-WM, where each robot keeps its own label language). It measures alignment indirectly: if alignment is high, the model will predict better when adapted to a new robot because it learned generalizable patterns from multiple robots speaking the same code; if alignment is low, adding more training robots will confuse the model and hurt performance because the model keeps separate vocabularies for each robot and cannot cross-reference patterns.

Why it works

Why learning a shared hidden language makes models transfer better

The reason is simple: a world model learns by spotting patterns. If the model sees only three-finger robots, it learns patterns about three-finger motion: how soft fingers bend, how they touch objects, how momentum flows through them. When a five-finger robot shows up, the model has no three-finger patterns to borrow, so it has to learn five-finger motion from scratch.

But if both robots first translate their actions into a shared hidden code, the model sees the same pattern from both: how close fingers are to the object or how much force is being used. These are not robot-specific; they apply to any hand. So the model learns once, from both robots together, because the shared code forces them to encode the same aspects of motion, giving the model twice as many examples of each physical principle; and when the six-finger robot adapts, it only needs to teach the model how to count to six — the model already knows how to predict when fingers are close or force is high, because it has learned those concepts from many robots already.

The latent action space works because it forces all robots to agree on what matters: which actions are similar, which are opposite, which are gentle and which are forceful, so the model builds patterns around these shared dimensions. Explicit labels, by contrast, let each robot speak its own dialect, so the model never builds a unified understanding, because it has no way to know that three-finger gentle and five-finger gentle are the same thing — they have completely different names.

The hidden action encoding equation

First in words:

For each robot, its specific action labels are encoded into a latent vector using a learned encoder network. The world model then uses only the latent vectors to predict the next state, not the original labels.

Then the compact form:

z_action = Encoder_robot(action_label); next_state = WorldModel(current_state, z_action)

Every symbol:

z_actionthe hidden action vector (list of numbers)
Encoder_robota learned neural network trained separately for each robot
action_labelthe original action command from this robot's manufacturer
WorldModelthe shared prediction network trained on all robots
current_statewhat the robot sees now (position, velocity, etc.)
next_statewhere the robot ends up after taking the action
A tiny worked example
Three-finger robot says: 'Action 5' (its own label).
Three-finger encoder converts Action 5 to latent vector [0.8, 0.2, 0.1] (the shared hidden code).
Five-finger robot says: 'Action 12' (a similar gentle grasp on its labels).
Five-finger encoder converts Action 12 to latent vector [0.8, 0.2, 0.1] (same shared code).
World model receives [0.8, 0.2, 0.1] from both robots, so it learns: this vector means gentle grasp.
New six-finger robot encodes its own 'gentle grasp' label to [0.8, 0.2, 0.1], and the model already knows what to predict.

The hidden action code is the bridge: it forces robots to agree on what actions mean, so the shared model learns once and works everywhere.

What can go wrong

What can go wrong

The encoders may collapse to the same code for all actions. If the encoders are not trained carefully, they might assign identical hidden vectors to very different actions (a grasp and a poke). The world model then cannot distinguish them, so predictions fail.
The shared code may not fit all robots' action spaces. If one robot has very exotic moves (e.g., a snake-like robot that moves in ways the others cannot), forcing it into a shared code with rigid robots may lose information. The hidden vector might be too small to capture the snake's motions.
Adapting to a very different new robot requires careful encoder tuning. A new robot with a completely different embodiment (e.g., a mobile base vs. a manipulator) might not have a clear mapping to the shared code. The tiny adapter encoder may fail to learn the right translation.
Done right: the shared code captures task-relevant aspects. If the code learns to encode force, position, and speed — things that matter for prediction — then any robot can translate its actions into those dimensions and transfer knowledge from the pre-trained model.
What a runnable demo should prove

What a runnable demo should prove

Build a simulator with three robot embodiments (e.g., a three-fingered hand, a five-fingered hand, and a two-finger gripper). Train a world model to predict the next camera frame and the object position after each action. Compare two versions: (1) the model that receives explicit action labels, one set per robot; (2) the model that receives latent action codes learned from a shared encoder. Train both on 80% of the videos from all three robots. Then freeze the world models and adapt each to a fourth robot (a new hand design not seen during pretraining). Measure prediction accuracy on held-out videos of the fourth robot.

transfer_performance = (next_frame_prediction_error_new_robot_explicit - next_frame_prediction_error_new_robot_latent) / next_frame_prediction_error_new_robot_explicit

The demo must show that latent-action adaptation improves prediction accuracy by at least 10–20% compared to explicit-action adaptation on the completely new robot, because the shared code lets the model reuse patterns learned from the training robots, while explicit labels force the new robot to learn from scratch.
