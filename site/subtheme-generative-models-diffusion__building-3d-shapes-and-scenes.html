Building 3D shapes and scenes

Papers on creating three-dimensional objects and complete scenes, including techniques to generate parts, preserve identity, and build detailed 3D environments from descriptions.

All themesField mapMathematicsAll explainers
What this is

Generating 3D objects and scenes is harder than generating images for a fundamental reason: images are 2D grids and relatively simple to represent, but 3D is much more complex. A 3D object has to be valid from every angle—a car viewed from the front has to have wheels if you walk around to the side. A scene has to have spatial coherence: objects can't float in mid-air unless there's a reason, and all the perspective has to be geometrically consistent. Generating something that looks good in a static 2D render is easy compared to generating something that would actually hold up as a real 3D model.

The technical challenges are immense. How do you even represent 3D? As a grid of voxels (3D pixels)? As a point cloud (a scatter of 3D points)? As a mesh (triangles forming a surface)? As a signed distance function (a mathematical description of where surfaces are)? Each representation has tradeoffs, and none captures detail as naturally as 2D images do. How do you ensure the outputs are geometrically valid—no self-intersecting surfaces, no floating-point errors that destroy the model? How do you generate from a text description ('a wooden chair') when the model has seen millions of images but far fewer 3D assets? How do you handle identity—if asked to generate a person sitting in a chair, can you make sure the person and chair are consistent across multiple generations, not randomly different people and chairs?

Research here uses several strategies. Some papers generate 3D by treating it as multiple 2D views—generate several images of an object from different angles, then use those to reconstruct 3D. Others use intermediate geometric representations: first generate a coarse skeleton or shape, then refine it. Still others condition generation on 2D images: if you show the model a photo, it can try to generate a 3D model consistent with that photo. Papers on scene generation often focus on specific domains: rooms, outdoor environments with sky and trees, and enclosed spaces where there are clear conventions about how things arrange and relate. The work is less mature than image or video generation, and many papers are still exploring what the right approach is.

How the work breaks down

Building 3D scenes and objects splits into four main directions: making generation fast enough to be practical, ensuring the outputs are physically valid and can actually be used, handling the leap from 2D images to 3D (where a single image can be ambiguous), and creating 3D assets that fit together as modular pieces.

Fast scene generation from images and text

The first challenge is speed. Generating high-quality 3D scenes from a single image or text takes minutes in prior work, which makes it impractical for interactive applications because users need to wait too long for results. Three papers attack this directly.

FlashWorld generates complete 3D scenes from a single image or text description and does it in seconds—10 to 100 times faster than previous methods because it uses a more efficient generation process. It maintains high rendering quality and 3D consistency, meaning the scene looks valid from any angle. HIVE-3D also tackles high-resolution scene generation from a single scene image and outperforms prior methods in quality because hierarchical voxel enhancement refines the 3D representation in stages from coarse to fine, which means details emerge gradually and higher-resolution results become achievable. Sat3DGen takes a different input: it generates complete street-level 3D scenes directly from satellite images. The method improves geometric accuracy (reducing error from 6.76m to 5.20m) and visual quality (cutting a quality metric from ~40 to 19), which opens the door to 3D scene understanding from aerial data because satellite views can now produce reliable 3D reconstructions. All three solve the same bottleneck—turning a single 2D input (image, text, or satellite view) into a full 3D scene quickly enough to actually use.

Physics-aware 3D generation for simulation

A second direction focuses on making generated 3D content physically valid. Early 3D generation papers produce models that look good in renders but break when you try to simulate them: parts might intersect, balance might be impossible, or movement constraints might be ignored. This blocks applications like robotic manipulation, game design, and interactive virtual worlds.

PAT3D (Physics-Augmented Text-to-3D Scene Generation) generates scenes from text descriptions while enforcing physical plausibility. It outperforms prior work in both how realistic the physics is and how well it matches the semantic content (a table is actually a table, not a different object) because it constrains generation to satisfy physical laws. Uniquely, it produces simulation-ready scenes that can be edited and used directly in robotics applications, which means robots can actually manipulate the objects. PhysForge generates individual 3D assets that are functionally plausible and ready for simulation, using a large database of 150,000 real assets with physical annotations at four levels of detail. It provides a data engine that lets creators build interactive 3D worlds where objects actually behave correctly because the physical properties are tracked. These two papers address the same problem from different scales: one ensures physical validity in scene generation, the other ensures it in individual asset creation. Both enable downstream use cases (editing, simulation, robotics) that inconsistent models cannot support because those applications require predictable, physically accurate behavior.

Generating 3D shapes with structure and editing

A third direction focuses on generating individual 3D shapes—not full scenes, but single objects—while maintaining structural coherence and support for editing afterward. The key difficulty is that 3D shapes can be represented many ways (voxels, point clouds, meshes), and each representation trades off fidelity for computational cost. When users want to edit a generated shape (say, make a chair taller), the representation has to support that without breaking.

Rethinking 3D Shape Generation uses superquadrics (mathematical shapes that can be combined and deformed) as an intermediate representation, then generates point clouds directly from that without extracting an isosurface—a step that usually introduces artifacts. This is fast (0.6 seconds per shape) and supports part-level editing and constraint-based design, meaning users can ask for specific properties and the model tries to satisfy them. LATO (3D Mesh Flow Matching with Structured Topology Preserving Latents) generates complex 3D meshes while preserving well-formed topology—the connectivity and structure of how surfaces connect—which is hard because bad topology makes shapes unsalvageable. It outperforms prior diffusion-based and sequence-based approaches by encoding structure directly in the latent representation (the compressed internal code that the model uses to represent a shape). Interp3D addresses the morphing problem: given two 3D shapes, generate smooth transitions between them while preserving texture and plausibility. It uses correspondence-aware interpolation, which means it tracks which part of shape A should connect to which part of shape B so the transition is coherent, not tangled. These three papers all care about preserving and manipulating shape structure in ways raw pixel diffusion cannot.

Generating parts and complete objects

A fourth direction tackles specific sub-problems within 3D object generation: how to generate modular assets that fit together, how to ensure consistency when generating a single object like a head, and how to edit 3D objects after generation.

AssetFormer uses a sequence-generation model (a neural network that produces outputs step-by-step, each one building on the last) to generate modular 3D assets piece by piece, streamlining creation for game developers and content creators who need flexible components that snap together. This approach works because if you generate parts sequentially (one after the other), each part can condition on the previous ones, ensuring they fit together correctly. Condition Matters in Full-head 3D GANs addresses a specific case: generating 3D heads (faces) from all angles simultaneously. Prior work conditioned the generator on viewing angle, which created biases—heads looked different depending on which angle you were viewing from, which is geometrically impossible. The paper removes this directional bias and accelerates training by conditioning differently, producing globally coherent heads. Nano3D addresses a frustrating problem: editing 3D objects requires masks to specify which part you want to change, but creating masks is tedious. Nano3D does 3D-consistent editing without needing them. It also introduces a dataset of 100,000 high-quality 3D editing pairs so the community has benchmarks. These three papers each solve a practical friction point: modular asset creation, view consistency, and editing workflows.

Multimodal and hybrid 3D generation

A fifth direction explores using large language models and multimodal approaches for 3D generation. CG-MLLM (Captioning and Generating 3D content via Multi-modal Large Language Models) allows the same model to both caption existing 3D content and generate new 3D objects from text descriptions, which means one system handles both understanding and creating. It produces higher-quality 3D objects than other multimodal language models because it benefits from the language understanding already built into large models. This matters because LLMs already excel at understanding language, so using them for 3D opens a direct path from text instructions to 3D models without needing separate specialized systems.
