Smart token management for long context

These papers reduce the memory explosion when models process very long documents by deciding which tokens matter most and keeping only those, or using clever ways to summarize.

All themesField mapMathematicsAll explainers
What this is

Attention in transformers has a quadratic cost: if a document has 100 tokens, attention is 100 squared, which equals 10,000 operations. At 1 million tokens (a very long book), attention alone is a trillion operations. For long documents, memory explodes because you have to store all those attention scores. But not all tokens matter equally. Early in a document, the model might not need to see every single word — it could focus on key sentences. Later, when making a specific decision, only a few previous tokens matter (the ones already seen). Why load and process every token when you can be smart about which ones to keep?

These papers tackle smart token selection in several ways. One approach is pruning: as you process the document, mark tokens as important or not, and drop the unimportant ones from memory. Another is summarization: condense the already-processed part of the document into a shorter summary, then process new tokens with attention to just the summary plus a recent sliding window. A third is routing: only certain tokens get full attention, others get reduced attention, based on what the model predicts will matter. These techniques can shrink the effective length of the document from a million tokens to maybe 10,000 or 100,000, making processing tractable.

The hard part is deciding which tokens to keep without losing important information. If you drop a token that turns out to be critical, the model's answer gets worse. Researchers use multiple signals: frequency (common words might matter less), position (first and last tokens in a passage matter more), or learned importance scores. Some papers use auxiliary networks that predict which tokens will be important, adding a bit of overhead now to save huge overhead later. The goal is to handle multi-million-token documents in reasonable time without degrading the quality of the model's output.

How the work breaks down

Work in this subtheme splits into four main directions: reducing visual pieces in image and video models where you can drop pixels without losing understanding; learning to prune or merge text pieces based on what actually matters; redesigning how the model's focus mechanism works to handle long sequences faster; and changing how models are trained or deployed so they can work with fewer pieces in the first place.

Pruning Visual Pieces from Images and Video

When models process images and video, they usually convert each pixel region into a piece (a unit of data), creating thousands of pieces per image. But not every visual piece carries equally important information. A patch of uniform blue sky background matters far less than the face of a person in the foreground. The hard part is figuring out which pieces to drop without the model missing something important for understanding the image.

FlashVID shows that video language models can throw away 90% of visual pieces from video frames—keeping just 10%—and still preserve 99.1% of performance on understanding what the video shows. The reason is that pixels change slowly across video frames, so most frames are redundant; by being smart about which frames and which patches within frames matter most, the model can process ten times more video frames with the same computational budget, leading to better understanding because more context was seen. LearnPruner tackles the same problem for static images with a different approach: it learns which vision pieces will be most important for the specific task at hand, not just which pieces look important in isolation. By keeping only 5.5% of vision pieces, it accelerates inference three times over while preserving 95% of the original performance—a huge speedup that matters in real-world deployment. The iLLaVA paper pushes this further: images can be reduced to fewer than one-third of their original piece count, yet larger models using fewer pieces become faster and more accurate than smaller models using the full piece count. This works because with intelligent pruning, the model processes less noise and focuses on what matters. LiteLVLM (the CLIP Tricks paper) shows that you don't even need to train the model; by analyzing which visual regions correspond to what things mean using vision features from CLIP, a pre-trained model, you can identify important pieces at test time without retraining. The result: 22% speedup with 90% of the original performance, and it works across different piece budgets. Together, these papers show that most visual pieces are unnecessary—the real information is concentrated in a small fraction—and identifying those pieces either through learning or through analysis gives you massive efficiency wins.

Intelligent Piece Selection and Merging

For text documents and multi-modal contexts, deciding which pieces to keep is harder than for images because every word might matter later. A name mentioned on page 1 might be important for understanding a decision made on page 100. The challenge is selecting or summarizing pieces during processing so that downstream decisions remain accurate, even when you've compressed the context.

CoMem tackles long-context tasks by decoupling the model into separate components: one that processes the most recent pieces with full focus, and another that works with a compressed summary of already-processed content. This design gives 1.4x faster latency on real-world software engineering tasks while keeping accuracy the same. Task-Aware Structured Memory takes a similar idea but makes the compression adapt to the specific task being solved; when different tasks care about different information, you compress differently, which means you can use very high compression ratios (dropping 80-90% of pieces) while preserving information that matters for the task. MMTok applies this to vision-language models by asking: which visual patches actually help answer the current question? Some questions need faces, others need hands, others need scene context. By selecting patches based on task relevance, the model achieves 1.87x speedup while retaining 98.7% of performance, and it can even answer questions using just four visual pieces when a compact representation suffices. SPLIT-VLM uses a different signal: it looks at how similar nearby visual pieces are in meaning, and if two pieces represent the same object (like two parts of the same face), it keeps only one. This approach preserves over 99% accuracy with far fewer pieces. Statistically Calibrated Scaling addresses a subtle problem: when you merge or drop pieces, you change the statistics of the data flowing through the model (the distribution shifts). This paper derives the correct mathematical adjustments so that merged pieces behave as if the full pieces were there, improving both accuracy and how well the model works across different situations. These five papers converge on the same principle: pieces aren't interchangeable. By identifying which pieces are truly important—either through learning, through task adaptation, or through statistical reasoning—you can compress context dramatically without losing information.

Efficient Focus Through Sparsity and Routing

The quadratic cost of focus is the fundamental problem: if you have N pieces, computing focus between all pairs costs N-squared operations. For very long documents, this becomes prohibitive. One way to break the quadratic barrier is to have the model pay full attention to some pieces and reduced or no attention to others—sparsity means you don't compute attention between every pair, only between carefully chosen pairs.

Less Is More demonstrates that models can maintain or even improve accuracy while attending to far fewer pieces through cross-head unified sparse attention—because redundant focus heads are asking the same questions anyway, so computing those questions once and reusing the results for all heads wastes no information while saving huge computation. Different focus heads (parallel computation paths within the model) often attend to similar sets of pieces—they're redundant, asking the same questions about the same parts of the input. You can unify them by having all heads pay attention to the same subset, which means instead of computing N-squared interactions for each head separately, you compute it once and reuse it. This cuts the number of computations dramatically, and with optimized GPU code that exploits this structure, the result is a 1.6x speedup end-to-end. Step applies this idea to mixture-of-experts models: at the piece level, you identify which pieces are critical for routing decisions (deciding which expert processes each piece). Those critical pieces need full processing; others use a lighter computation path because they don't affect the routing decision. This means the model does expensive work only where it matters, and on a 30 billion-weight model at 50% sparsity, it achieves a 1.5x throughput improvement while reducing memory by 50%. DND (Dynamic Nested Depth) takes a different approach: instead of deciding which pieces to skip, it decides which pieces need deep processing and which can use shallow processing. Some pieces get processed through all layers (deep processing) because they carry important information; others skip layers and use only a shallow path because they're less central to the decision. By routing pieces conditional on their importance, each piece gets as much processing as it needs, not more. This works because the model learns to invest computation where it pays off—on dense models, this improves accuracy by 1.9-2.6%, and on large mixture-of-experts models by 0.87%, with minimal added overhead. Together, these papers show that focus doesn't have to be dense and uniform. By routing pieces to different processing paths or restricting attention to important subsets, you break the quadratic cost barrier because you're not computing all pairs—you're computing only the pairs that matter.

Efficiency in Training and Context Parallelism

Efficiency isn't just about inference (running a model to make predictions). Training large models on long contexts is also a bottleneck. During training, the model updates its weights using backpropagation, which requires storing intermediate computations for every piece—this memory explosion can be as bad as inference. When training and deploying across multiple GPUs, you also need to handle how to split the workload.

Piece-Level Importance-Aware Training solves the training bottleneck by recognizing that during backpropagation, not all pieces contribute equally to updating the model's weights. Some pieces cause small changes to weight updates; spending computation on those updates is wasteful. By computing importance scores for each piece and skipping backpropagation for unimportant pieces, this method saves 42.9% of memory while keeping training speed the same or faster. OmniFit addresses the inference challenge for omnimodal models (models that handle multiple types of input simultaneously—text, image, audio, etc.). When a model receives inputs of different types, some inputs take more pieces than others. OmniFit learns layer-specific compression: each layer drops pieces that it determines are least useful for downstream computation. This achieves 2.31x end-to-end speedup and 2.5x VRAM savings while retaining 98% of performance across multiple model sizes and benchmarks. Untied Ulysses solves a different problem: when training on very long sequences across multiple GPUs, you have to split the context between GPUs, but each GPU wastes memory on intermediate computations. By chunking the context at the level of focus heads (the smallest parallelizable unit) and carefully scheduling computation, this method reduces peak memory by 82.5% for a 70-billion-weight model and enables training with 5 million piece sequences on a single eight-GPU node. These three papers show that piece efficiency matters throughout the entire model lifecycle, not just at inference time.
