Memory-Augmented Selective Prediction

A vision-language model can refuse low-confidence predictions by looking up similar examples in memory, then tuning its confidence score using contrastive comparison.

Paper explainersAll themesAlignment, Safety & Fairness

When a vision-language model (a system trained to understand both images and text) makes a prediction, it is not always right. This paper gives such a model a power: to say no instead of guessing. The trick is memory: look up similar image-text pairs in a stored database, average their embeddings (the internal numbers the model computes), and then use contrastive scores (comparing the image to a retrieved text, then contrasting it against other options) to calibrate how confident that prediction should be.

Zero assumption version

Vision-language models struggle to know when to quit

Large vision-language models (systems that read both images and text at the same time) work well on many tasks but fail confidently. They sometimes answer wrong with high confidence: an image of a husky is labeled a wolf, or a chaotic image gets a detailed description even though it is corrupted. When the model is wrong, you want it to say I do not know instead of guessing.

The naive approach: score the prediction's confidence by measuring how aligned the image and its predicted text are, using an external model like CLIP (a standard vision-language reference). But CLIP embeddings (the internal numbers CLIP computes for images and text) are noisy and fragile—a small change to the image gives a wildly different number. And CLIP's similarity scores are not properly calibrated (the score does not honestly reflect how likely that prediction is to be right).

The method in one sentence. Store a large dataset of image-text pairs in memory, retrieve the most similar ones, average their embeddings to smooth out noise, and use contrastive scoring (comparing one option against others) to calibrate confidence.

The algorithm as a flow

What it actually does

Encode the image

Run the image through a pre-trained encoder to get its embedding numbers.

Retrieve neighbors

Search a stored dataset for K images most similar to the query image.

Average embeddings

Blend the embeddings of those K neighbors using a weighted average (heavier weight on closer matches).

Score with contrast

Measure how aligned the image is to both the predicted text and several wrong texts, then normalize by dividing by the sum of all similarities.

Set rejection threshold

If the contrastive score falls below a learned threshold, reject and return no answer.

What the paper changes

What the paper changes

The paper changes how a model estimates its confidence in a prediction. Instead of using CLIP's direct similarity score (which is noisy and uncalibrated), it uses a smoothed, contrastive-normalized score computed from retrieved neighbors in a memory database.

the object it moves  =  confidence score estimation
The hidden quantity

The hidden quantity: representation stability

measured quantity  =  embedding variance

CLIP embeddings (the internal numbers a vision-language model computes for images and text) are inherently noisy: the same image gives different lists of numbers depending on tiny details. This high variance makes direct similarity scores unreliable. The paper measures this as the deviation of a single embedding from the average of its nearest neighbors' embeddings.

The paper tackles this by averaging retrieved embeddings (a proxy embedding). When you average K similar embeddings, random noise cancels out, leaving only the true signal. This is the core insight: membership in a stable neighborhood reduces variance more than any training-based tuning could.

Why it works

Why it works: two problems, two fixes

CLIP embeddings are unstable: the same image can have quite different embedding numbers when encoded at different times or with minor image changes. This means a direct similarity score (how aligned an image and text are) bounces around unreliably. If you reject predictions with low direct scores, you reject some correct ones and accept some wrong ones by chance.

The paper fixes this by replacing a single noisy embedding with a weighted average of K neighbors' embeddings. Since the neighbors were chosen because they are similar to the query, averaging their embeddings cancels out random noise—the outliers balance out. You end up with a stable, representative number. Because it is stable, a threshold on the score becomes reliable: low scores now genuinely mean misalignment, not just bad luck.

The second problem is miscalibration: CLIP's similarity scores do not honestly reflect the actual chance the prediction is correct. A score of 0.8 might mean 50% accuracy, not 80%. The paper fixes this using contrastive normalization: instead of scoring the image against only the predicted text, score it against both the predicted text and multiple distractor (wrong) texts, then normalize using the ratio. This forces the model to show why this text is better than the alternatives, not just whether the image-text alignment is high. The contrastive score is calibrated because it measures relative strength, which aligns with the model's actual decision-making: it picks the best option, not the option above some absolute threshold.

The contrastive score formula

First in words:

Proxy embedding = weighted sum of neighbor embeddings. Weight = proximity score (how similar each neighbor is). Contrastive score = similarity to predicted text, divided by (1 plus sum of similarities to distractor texts).

Then the compact form:

proxy_txt(q) = sum over K neighbors of (weight_i * embedding_i) / sum of all weights contrastive_score = sim(img, predicted) / (1 + sum of sim(img, distractors))

Every symbol:

qthe query image
weight_iproximity score between query and neighbor i (higher if more similar)
embedding_ithe text embedding of neighbor i's caption
proxy_txt(q)the smoothed text embedding representing the query
sim(a,b)cosine similarity between embeddings a and b (ranges 0 to 1)
imgthe query image's embedding
predictedthe text embedding of the predicted caption
distractorsembeddings of several wrong captions (negatives)
Tiny example: averaging and contrasting
Query image has direct CLIP embedding [10, 5, 3] (vector of three numbers). Noisy!
Retrieve 2 neighbors: neighbor embeddings [10.2, 4.8, 3.1] and [9.9, 5.2, 2.9].
Weights based on similarity: 0.5 and 0.5 (equally close).
Proxy embedding = 0.5 * [10.2, 4.8, 3.1] + 0.5 * [9.9, 5.2, 2.9] = [10.05, 5.0, 3.0]. Less noise!
Similarity: proxy vs. predicted text = 0.82. Predicted text is the obvious choice.
Similarity: proxy vs. distractor A = 0.30. Distractor B = 0.25.
Contrastive score = 0.82 / (1.0 + 0.30 + 0.25) = 0.82 / 1.55 = 0.53. This honest ratio reflects that the predicted text is better, but not overwhelmingly.
If the threshold is 0.60, reject. If 0.40, accept.

The contrastive score is a ratio: how much does the image prefer the predicted text over the alternatives? High ratio means yes; low ratio means unclear.

What can go wrong

What can go wrong

Retrieval dataset is out-of-domain. If the memory database is from a different type of image or text than the test data, neighbors will not be truly similar. When you average embeddings that do not match the test domain, you are averaging noise from a different world—the averaged embedding does not represent the query image well in its own domain. Contrastive scores built from such poor proxies remain unreliable and noisy. The paper's experiments show that in-domain retrieval (neighbors from the same task or dataset) produces much better calibrated scores than out-of-domain retrieval, because the neighbors are actually representative of what the model is trying to predict.
Threshold is set wrong. Choosing a rejection threshold requires ground truth on a validation set. If the threshold is too high, the model rejects too much (wastes opportunity). If too low, it accepts confidently wrong answers (defeats the purpose).
Retrieval is expensive. Looking up K nearest neighbors in a large database requires a fast search index. If the database is huge or the index is slow, the time to answer each query slows down. The method trades answer latency for safety.
Done right. Use a well-chosen, curated retrieval dataset that overlaps the test domain, set the threshold on a held-out validation split, and invest in efficient retrieval (FAISS or similar index). The paper demonstrates this works across three different task types: image captioning, image-text matching, and fine-grained classification.
What a runnable demo should prove

What a runnable demo should prove

Build a toy image captioning system: take 100 images with captions, split 80-20 into retrieval and test sets. Encode all images and captions with CLIP. For each test image, predict a caption using a simple baseline (e.g., retrieve the most similar caption from the retrieval set, or use a small pretrained captioning model). Compute the CLIP similarity between image and predicted caption (direct score). Then, retrieve 5 nearest neighbors of the test image from the retrieval set, average their caption embeddings (proxy), and compute the contrastive score using the predicted caption and 3 random distractors from the dataset. Measure the accuracy on predictions you accept (contrastive score > 0.50), and count how many correct captions you wrongly rejected (false reject rate). Compare this to the direct-score baseline.

acceptance_accuracy = (number of accepted predictions that are correct) / (number of accepted predictions); false_reject_rate = (number of correct predictions rejected) / (number of all correct predictions)

The core point the demo must make clear: averaging K neighbors' embeddings makes the score stable (the same image gives the same score even with slight changes), and contrasting against wrong answers makes the score honest (a high score really means the model is confident, not just that the image-text pair happens to align numerically).
