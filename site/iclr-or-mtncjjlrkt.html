WebWeaver: Structuring Web-Scale Evidence with Dynamic Outlines for Open-Ended Deep Research

WebWeaver treats research as an outline that keeps changing while evidence arrives, then writes each section from only the cited evidence it truly needs.

Paper explainersAll themesAgents & Tool Use

Open-ended research is harder than ordinary question answering because the system has to decide what the report should cover before it knows what the web will reveal. Static plans fail because the outline becomes stale as soon as new evidence appears. Monolithic writing fails because one giant prompt mixes useful sources with irrelevant ones. WebWeaver fixes both problems with a planner that keeps updating the outline as evidence arrives and a writer that drafts one section at a time from the exact cited evidence for that section.

Zero assumption version

Why deep research reports fall apart

A deep research report is not just one answer. It is a structured document with sections, evidence, and citations that must stay consistent from start to finish. Many systems plan once at the start, gather pages later, and then write the whole report in one large pass. That creates two problems. The plan does not adapt when the evidence turns out to be different from what the system expected, and the writer sees too much mixed evidence at once.

When that happens, section boundaries blur. A useful source for one section leaks into another. Weak sources get cited because they were present in the large context window. Missing evidence goes unnoticed because the writer has no explicit link between outline entries and the source bank. The final report may read smoothly, but the support under each claim is thin.

The paper's move. Keep the outline alive while gathering evidence, then write section by section from the exact cited evidence linked to that section.

The algorithm as a flow

What it actually does

Start with a rough outline

Create an initial report structure from the user request.

Search and store evidence

Gather web evidence and save it in a memory bank with notes and source links.

Revise the outline

Update sections and subsections whenever the evidence shows a better structure or a missing area, because new sources can reveal that one heading should be split, merged, or added.

Write one section at a time

For each section, fetch only the cited evidence linked to that section instead of dumping the whole memory bank into one prompt.

Assemble the report

Merge the drafted sections into one report whose citations trace back to stored evidence.

What the paper changes

The paper changes the planning object from a fixed outline into a dynamic outline tied to a memory bank of evidence. That link matters because every section can now be revised when the evidence changes.

The hidden quantity

The hidden quantity: section evidence coverage

measured quantity  =  how well each section is supported by the evidence bank

A report section is only trustworthy when it has enough relevant evidence and little irrelevant evidence. WebWeaver keeps that support visible by linking each outline item to notes and citations in the memory bank.

That makes section evidence coverage the key hidden quantity. Low coverage means a section is missing facts or is built from weak support. High coverage means the writer can draft that section from a compact set of directly relevant sources. The method works because planning and writing both read that same coverage signal.

Why it works

Why it works

Static plans fail because they separate planning from evidence gathering. WebWeaver keeps them coupled. When the planner finds new evidence, it can split a broad section into two narrower ones, drop an unsupported branch, or add a section that the original plan missed. The outline therefore becomes a summary of what the evidence can actually support, not just what the system guessed at the start.

The section writer then benefits from that structure. Instead of reading the whole memory bank, it reads only the evidence linked to the current section. That reduces citation mistakes because irrelevant pages are absent, and it improves section coherence because the writer is solving one local problem at a time.

The two-agent split matters because each side has a clear job. The planner decides what the report should contain and which evidence belongs under each heading. The writer turns that bounded evidence into prose. The report is better because each section is grounded in a small, deliberate evidence set rather than a giant mixed pile.

Math after the picture

The planning objective

First in words:

Choose the outline that gives high section coverage and citation precision while penalizing evidence that does not belong in the section.

Then the compact form:

score(outline) = sum_s [ coverage(s) + precision(s) - noise(s) ]

Every symbol:

sone section of the report
coverage(s)how much of the needed evidence for section s is present in the memory bank
precision(s)how much of the retrieved evidence for section s is actually relevant
noise(s)irrelevant material attached to section s
sum_sadd the score across all sections in the outline
score(outline)overall quality score for the current outline
A tiny worked example
Suppose a report has two sections: market history and safety concerns.
For market history, the planner has strong notes and clean citations, so coverage is high and noise is low.
For safety concerns, the planner only has one weak source, so coverage is low.
The outline score stays low until the planner searches again and adds stronger safety evidence.
After that update, the safety section score rises and the writer can draft it without guessing.

The real system is more detailed, but this captures the core pressure: keep the outline aligned with the evidence it can truly support.

What can go wrong

What can go wrong

Outline churn never settles. If the planner keeps rewriting the outline after every weak clue, the report may never stabilize because the structure changes faster than evidence quality improves.
Memory bank notes are poor. If stored notes miss key facts or mix claims from different sources, the writer will inherit those errors because section retrieval depends on the note bank.
Section links are wrong. A clean writer cannot save a bad link. If a section points to the wrong evidence, the prose may stay fluent but the citations will not support the claim.
Done right. The method works when the planner updates the outline only when evidence support truly changes and when each section keeps a tight citation link to its own evidence.
What a runnable demo should prove

What a runnable demo should prove

Take a broad topic with several subtopics, such as the regulation, market history, and safety issues of one technology area. Build one system with a fixed outline and one with an outline that updates as evidence arrives. For both systems, store sources in a small memory bank and generate a final report. Then measure how often each section has at least two supporting citations and how often reviewers judge a citation to be relevant to the sentence it supports.

section_support_rate = supported_sections / total_sections; citation_precision = relevant_citations / checked_citations

The demo should show that the gain comes from better section support and tighter citation links, because those two measures show whether each section is grounded rather than merely longer.
