FS-KAN: Permutation Equivariant Kolmogorov-Arnold Networks

A new type of neural network layer that learns from data where rows can be reordered without changing the answer, using a simpler form of a recent better-than-MLP architecture.

Paper explainersAll themesGraph & Geometric Learning

Kolmogorov-Arnold Networks are a new kind of model layer that decompose functions into univariate basis functions and sum them. Because each basis function is univariate (operates on a single number), the total computation is lower than older MLP layers that use dense grid-of-numbers multiplications, and it is easier to see what each basis function learned. But they have not yet been systematized for data with permutation symmetry — datasets where reordering rows does not change what the answer should be, like point clouds, molecular atom lists, or set-based problems. FS-KAN fills this gap by extending Kolmogorov-Arnold layers to work correctly on permutation-symmetric data while preserving their interpretability and learning efficiency.

Zero assumption version

The gap: KANs are good but do not handle permutation symmetry yet

Kolmogorov-Arnold Networks (a newer architecture that decomposes functions into simpler univariate functions then sums them) have shown better data efficiency and interpretability than standard MLPs (dense layers of weights). However, when data has a permutation symmetry — meaning that reordering rows should not change the prediction — the published KAN layers do not know how to enforce that symmetry.

A beginner would just train a standard KAN on set-like data and hope it learns the symmetry from examples alone. This fails in low-data regimes because the model wastes capacity learning the same function separately for each row position, instead of learning once and reusing that knowledge.

In one sentence. The paper reuses the same learned basis functions across all rows of data, which forces the model to treat every row the same way, making it automatically handle permutation-symmetric data without wasting capacity learning separate functions for each position.

The algorithm as a flow

What it actually does

1. Decompose the input

Break each row's numbers into univariate basis functions applied separately.

2. Aggregate across rows

Sum or pool the outputs of the basis functions, so the result does not depend on row order.

3. Reuse basis functions between rows

All rows use the same learned basis functions; no separate weights per position.

4. Compose outputs

Combine the aggregated basis responses into the final layer output.

5. Verify symmetry

Reordering inputs automatically gives the same output, by construction.

What the paper changes

The one thing that changes: how basis functions are deployed

Standard KANs learn a separate set of basis functions (univariate learnable functions) for each input position and neuron. FS-KAN instead shares a single learned basis-function library across all input rows, and aggregates their outputs, so the network becomes equivariant to row permutations.

the object it moves  =  basis-function deployment and sharing
The hidden quantity

The hidden quantity: symmetry burden

measured quantity  =  symmetry burden (wasted capacity)

Most standard networks on permutation-symmetric data carry a hidden burden: they must learn the same function multiple times, once for each row position, because they have no mechanism to share. This redundancy is the symmetry burden — the fraction of model capacity wasted on learning position-specific copies of the same concept.

FS-KAN estimates and removes this burden by construction: parameter sharing forces all rows through the same learned basis functions. The paper measures this implicitly via data efficiency — fewer examples needed to reach target accuracy is a sign that symmetry is no longer a learning burden.

Why it works

Why it works: forced sharing prevents position-bias from ever forming

The mechanism is straightforward: if all rows are forced through the same learned basis functions before aggregation, the network cannot learn position-specific patterns, even if it wanted to. The aggregation step (summing or pooling row outputs) automatically makes the result invariant to reordering.

This is more data-efficient than learning from symmetry via examples alone, because the model starts with the symmetry constraint baked in. It does not have to stumble through billions of weight configurations to find the symmetric solution; symmetric solutions are the only ones possible by design. On low-data problems, this saves training time and example count because the model searches a smaller, more constrained solution space where every solution is already symmetric, so it converges faster.

The equation: shared basis plus aggregation

First in words:

output equals the sum over all rows of the shared basis functions applied to each row's input

Then the compact form:

y = sum_i f_shared(x_i) where f_shared is the learned basis-function layer and aggregation is sum or max-pool

Every symbol:

ythe network output
sum_iaggregation over all rows i (sum, max, or mean)
f_sharedthe shared basis-function layer learned from data
x_ithe numbers in row i
A tiny worked example
Row 1 input: [2, 3] → apply shared basis → outputs [0.8, 0.5]
Row 2 input: [1, 4] → apply shared basis → outputs [0.6, 0.4]
Row 3 input: [3, 2] → apply shared basis → outputs [0.7, 0.5]
Aggregation (sum): [0.8+0.6+0.7, 0.5+0.4+0.5] = [2.1, 1.4]
If rows are reordered, same basis applied in different order, sum stays identical.

Because all rows use the same f_shared and results are summed, reordering rows changes nothing.

What can go wrong

What can go wrong

Data without symmetry If the data does not actually have permutation symmetry (each row's position matters for the answer), FS-KAN's forced sharing becomes a constraint that hurts accuracy.
Basis function capacity If the learned basis functions are too simple to capture the true task, no amount of sharing will help, because all rows are forced through the same shared basis functions, so if those functions cannot express the pattern, neither can the model. The architecture still depends on choosing a suitable Kolmogorov-Arnold layer width.
Large, imbalanced sets If the input sets are very large or have rows of vastly different importance, simple aggregation (sum or pool) may miss subtle per-row differences that matter.
Done right FS-KAN succeeds on set-like problems (point clouds, molecular atom lists, permutation-invariant classification) where the symmetry is real and the task is genuinely set-based.
What a runnable demo should prove

What a runnable demo should prove

Build a small set-classification task: generate random point clouds (sets of 2D coordinates) and assign labels based only on the set's centroid or spread, not the point order. Train both a standard KAN and FS-KAN on the same small dataset (100–200 examples). Measure accuracy and verify that FS-KAN reaches target accuracy faster in fewer epochs or examples than the standard KAN, because FS-KAN's forced symmetry eliminates the capacity spent on learning separate row-position functions. Shuffle point order in test examples and verify that FS-KAN's predictions are unchanged while standard KAN's may drift.

data_efficiency_gain = (examples_for_std_KAN - examples_for_FS_KAN) / examples_for_std_KAN × 100%; invariance_check = 1 if accuracy_same_before_and_after_shuffle else 0

The demo must make it impossible to miss: FS-KAN learns the symmetry instantly (by design), while standard KAN struggles to find it from data alone.
