Full-Graph vs. Mini-Batch Training: Comprehensive Analysis from a Batch Size and Fan-Out Size Perspective

When training a graph neural network, loading the entire graph at once is not always faster or more accurate than training on subsets, because batch size and fan-out size (how many neighbors each node sees) have opposing effects on learning and overfitting.

Paper explainersAll themesGraph & Geometric Learning

Graph neural networks (models that learn from data arranged as networks of connected nodes) can be trained two ways: load the whole graph at once (full-graph) or process it in small chunks (mini-batch). This paper proves which is actually better by showing that the answer depends on two invisible levers called batch size (how many examples train together) and fan-out size (how many neighbors a node learns from). These two levers push in opposite directions: big batches make updates stable but slow, while wide fan-outs add signal but also noise. The paper provides mathematical proof and practical recipes for choosing the right combination.

The GNN training puzzle

When you train a graph neural network, you face a choice: feed the whole network into memory at once, or break it into small chunks and train on each chunk separately. Feeding the whole graph means every node's update is based on the same set of other nodes, so all nudges point in stable directions—but it uses enormous memory.

But this is expensive. Graphs can have millions of nodes. A naive approach would fail: it either runs out of memory or takes forever. So engineers invented mini-batch training for graphs: instead of using all nodes, grab a small subset (say 100 nodes) and train on those. To prevent the model from forgetting what it learned from other subsets, you also choose how many neighbors each node learns about—the fan-out.

The real puzzle: does full-graph always win? And how do batch size and fan-out interact? Previous research never gave a clear, mathematical answer.

In one sentence. This paper proves that full-graph training and mini-batch training are only comparable through two levers—batch size and fan-out size—and full-graph often loses.

What the paper changes

What the paper changes

The paper does not change the model itself. Instead, it changes how you think about choosing between full-graph and mini-batch training. It introduces a unified view: both modes are just positions on a dial of batch size and fan-out size. This reframing lets you pick the best combination for your hardware and data.

The hidden quantity

The hidden quantity: convergence rate

measured quantity  =  How fast the model learns

Every machine learning model improves by tiny steps, because each nudge to its internal weights (the numbers that define what it does) moves the next prediction slightly closer to the truth. How big those nudges are, and whether they point in a consistent direction, determines convergence rate—the speed at which the model stops making mistakes and reaches good performance.

This paper measures convergence rate using a mathematical formula (the Wasserstein distance, a way to measure the gap between the training examples and test examples seen by the model) that captures how much a single batch update affects the model's trajectory. A batch that sees all nodes converges differently than a batch that sees 100 randomly chosen nodes, because the all-nodes batch reduces randomness in each update. The fan-out (how many neighbors each node in the batch learns from) also changes this rate—more neighbors means more signal but also more variance (random fluctuations).

Why it works

Why batch size and fan-out size pull apart

Here is the core mechanism: when you train a neural network, each update is a small nudge in the direction of lower error. The size and consistency of that nudge depends on how many different examples you see together (batch size) and how much information about neighbors you integrate (fan-out).

Larger batches (including all nodes in full-graph) make each nudge stable because random noise from individual examples averages out—you see the true signal. But this stability comes at a cost: with all nodes in one batch, you can only make one nudge per epoch. A single nudge per epoch is slow exploration because you cannot course-correct if that one nudge went the wrong direction, whereas multiple small nudges per epoch (from mini-batch) let you adjust course continuously as mistakes reveal themselves.

Wider fan-out (learning from more neighbors) adds signal: each node sees a richer picture of the graph. But it also adds variance because neighbor information may contradict or overwhelm the node's own signal. This variance in nudge direction makes training noisier.

The paper proves mathematically that these two effects have opposite signs in convergence time: batch size enters as an inverse cubic term (big batch, slow convergence), while fan-out enters as a direct cubic term (wide fan-out, noisy convergence). This means there is no single winner. A well-tuned mini-batch (medium batch, controlled fan-out) can converge faster than full-graph because it makes multiple nimble updates per epoch that each correct mistakes faster than one stable but slow full-graph update. It also generalizes better because controlled fan-out prevents the model from overweighting random noise in the graph.

Math after the picture

The convergence bound

First in words:

Convergence time for mini-batch is roughly: number of training examples cubed times (log of training examples) divided by learning rate, batch size, graph degree cubed, and a polynomial in the squared model parameters.

Then the compact form:

T_mini = O( n_train^3 * log(n_train) / (batch_size * alpha^2 * beta^3 * h^2) )

Every symbol:

T_ministeps needed for mini-batch training to converge
n_traintotal training examples in the full graph
batch_sizenumber of nodes trained per step (1 to n_train)
betafan-out size, how many neighbors per node
alphalearning rate (step size)
hmodel width (number of hidden units)
A tiny worked example
Suppose full-graph training has 1000 training nodes and degree of 10.
Full-graph convergence time ~ 1000^3 / (degree^5/2) = 1,000,000,000 / 1000 = 1,000,000 steps.
Mini-batch with batch_size=64, fan-out=4: convergence time ~ 1000^3 * log(1000) / (64 * 4^3) ≈ 10,000,000,000 / 4096 ≈ 2,400,000 steps.
But mini-batch updates 1000/64 ≈ 16 times per epoch, so wall-clock time is actually faster and memory usage is 16x lower.

Batch size and fan-out have inverse power laws in convergence time, so tuning them carefully lets mini-batch beat full-graph on real hardware.

What can go wrong

What can go wrong

Tiny batch size without wide fan-out. If you use batch_size=1 and fan_out=1, each update is nearly random noise. The model learns nothing.
Fan-out larger than graph diameter. If you set fan-out to 1000 but the graph has diameter 5, you are pulling in irrelevant distant nodes, adding noise with no signal.
Full-graph training on million-node graphs. Full-graph training may run out of memory or be so slow that a tuned mini-batch (which can use multi-GPU parallelism) finishes first.
Done right. Run a small hyperparameter sweep: try batch_size in (32, 64, 128) and fan_out in (2, 4, 8), measure validation accuracy and wall-clock time on your target hardware, and pick the best.
