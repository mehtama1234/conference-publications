SAGE-3D: Physically Executable 3D Gaussian for Navigation

Add object labels and collision shapes to photorealistic 3D Gaussian scenes so robots can understand what things are and navigate without crashing.

Paper explainersAll themesRobotics & Control

3D Gaussian Splatting renders photorealistic scenes in real time, but a robot navigating inside sees only pretty pictures with no understanding of objects or physics. SAGE-3D fixes this by overlaying semantic labels (this is a chair, that is a door) and collision shapes (invisible physics barriers) onto the Gaussians, transforming a visual-only model into an executable environment where agents can reason about the world and move safely.

Zero assumption version

A robot sees the photo but does not understand the world

When a robot navigates an indoor space, it needs to know two things: what things are, and where it can move. Traditional 3D scene models (like depth meshes) answer both—a robot reads the shape of the room and walls and sees labels on objects. But 3D Gaussian Splatting (a new way to represent scenes using millions of small colored blobs called Gaussians) renders a photorealistic image instantly. The catch: it only stores color and the positions of those blobs. There is no semantic layer—no labels saying this is a table or a door. And there is no physics layer—no collision boundaries to stop a robot from walking through a wall.

A naive solution is to bolt a separate segmentation model on top of the Gaussians to predict what objects are in each pixel. This breaks for two reasons. First, pixel-level predictions are noisy and conflict; the model cannot reason about which objects are which when they overlap. Second, there is still no physics—the robot has nowhere to ground its movement commands in actual collision shapes.

In one sentence. Add object labels and collision shapes directly into the 3D Gaussian scene.

What the paper changes

What the paper changes

Standard 3D Gaussian Splatting is a pure rendering engine: it stores the position, color, and opacity of millions of tiny spheres and blends them to make a photorealistic image. The paper adds two new layers. First, a semantic layer: each Gaussian cluster (a group of primitives that form one object like a chair) gets a label and category tag. Second, a physics layer: invisible collision bodies surround each object, computed via convex hull decomposition (a standard technique that wraps the smallest watertight cage around the spatial points of an object). Both layers sit alongside the Gaussians; the scene is no longer just appearance.

The hidden quantity

The hidden quantity: object-level semantic coherence

measured quantity  =  Semantic coherence of annotated objects

The paper introduces a quantity that standard 3D Gaussian Splatting does not measure: object-level semantic coherence. This is how well the spatial structure of the Gaussians aligns with object boundaries, and how clearly each object is labeled with a unique identity and category. Standard Gaussians have no concept of identity or purpose—they are just colored blobs placed in space. The paper estimates this by annotating every 3D Gaussian cluster with its object ID and category from the scene data, then validating that trajectories respect those objects.

The paper measures coherence through SAGE-Bench, a new benchmark that evaluates whether agents can follow instructions that reference specific objects (e.g., go to the water bottle). High coherence means the Gaussians align with objects; low coherence means the segmentation is fuzzy.

Why it works

Why it works: from beautiful pixels to executable worlds

The core insight is that a 3D Gaussian scene is a spatial data structure. The Gaussians already encode position and shape implicitly (their centers and covariances define where objects are). The paper simply reads that spatial structure, assigns human labels to the clusters, and adds collision boundaries. Because the Gaussians are already spatially coherent (nearby Gaussians render nearby pixels), labeling those clusters automatically gives object-level grounding.

Here is the causal chain. (1) Gaussian clustering naturally groups blobs that belong to the same object, because they are learned together during scene reconstruction. (2) Adding a semantic label to that cluster lets the agent reason about it by name. (3) Computing a convex hull around the cluster's spatial points produces a collision boundary that faithfully represents the object's footprint, because the hull wraps the Gaussian centers. (4) Binding the collision shape to the scene means the physics engine sees the same boundaries the rendering engine uses. As a result, commands like go to the table translate into path planning on a 2D semantic map derived from those labels and collision shapes, and movement respects physics collisions.

The physics layer solves a critical problem invisible in rendering: a robot that executes motion must know where it cannot go. Convex hull decomposition from the 3D scene's spatial layout provides this without requiring a separate physics annotation step—the spatial structure is already captured in the 3D Gaussian training data.

Given a chair in the 3D Gaussian scene: G_chair = 150 Gaussians within a 0.5 meter radius

The formula is direct because the Gaussians already capture where things are in space; semantics and physics are overlays on top.

What can go wrong

What can go wrong

Manual annotation is expensive. Labeling 1K scenes with 554k objects by hand is labor-intensive. Mistakes in annotation propagate to navigation. Automating the labeling (e.g., using a pre-trained object detector) trades annotation cost for detection noise.
Convex hulls can be too loose or too tight. Complex shapes like tables with curved legs do not decompose perfectly into convex pieces. A loose hull lets the robot think it can walk through a chair leg; a tight hull blocks valid paths. The trade-off depends on the decomposition parameters (settings that control how strictly the hull fits the spatial points).
Semantic mismatch between rendering and physics. If the Gaussian cluster does not align perfectly with the collision hull, the robot sees an object in one place but collides as if it were elsewhere. This happens when Gaussians are trained on noisy image data.
Done right. When annotation, hull extraction, and alignment are careful, the 3DGS scene becomes a true simulator: the robot trains on semantically understood, physically correct worlds and transfers to real robots.
What a runnable demo should prove

What a runnable demo should prove

Build a simple indoor scene (e.g., a kitchen with a table, chairs, sink). Reconstruct it as a 3D Gaussian scene from images. Manually label the objects (table=furniture, sink=fixture, chairs=furniture). Extract collision hulls for each. Then run two navigation tasks: (1) Follow a language instruction like go to the sink and retrieve a glass. The agent must route through the semantically annotated 2D map to the sink, and collide correctly if it tries to walk through a chair. (2) Train a navigation policy on mesh-based data versus 3DGS-based data with SAGE-3D annotations, and test both on a new unseen scene. The 3DGS policy should converge slower but transfer better because the semantic labels teach it what kinds of objects to expect in any kitchen, not just this kitchen.

success_rate = (tasks_reached_correct_object AND no_collision) / total_tasks

The demo must make it impossible to miss that semantic labels and collision physics, grounded in the 3D Gaussian spatial structure, let robots understand and move through photorealistic worlds.
