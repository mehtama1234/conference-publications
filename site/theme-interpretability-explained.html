Interpretability

How can we look inside a neural network and understand what it is actually computing?

← All themes explainedField mapMathematicsAll explainers
What this whole area is about

Modern AI models — especially large language models and image classifiers — make decisions by running computations through millions or billions of adjustable numbers, called parameters (the specific numerical values that determine how the model transforms input). But we can't see how they work. When a model predicts the next word in a sentence, or decides that an image contains a cat, the answer emerges from a maze of matrix multiplications and nonlinear transformations. This is the core problem: the most capable models today are black boxes. We can observe what goes in and what comes out, but the middle is opaque.

Understanding what's happening inside these models is hard because the computation is distributed across vast numbers of dimensions. A language model doesn't store information in a few variables we can inspect — it spreads knowledge across thousands of hidden units, layered dozens or hundreds of times deep. Even if we could freeze the computation at one point and look at the numbers, they are meaningless to us. The raw values don't read as English words or concepts. A single neuron might respond to a dozen unrelated patterns. The information is tangled: to extract 'the model thinks this sentence is sarcastic,' we'd have to untangle thousands of overlapping signals.

Researchers have built multiple approaches to look inside. Some hunt for small, interpretable parts — a sparse subset of neurons or directions in the hidden space that cleanly represent one concept. Others trace the flow of information step-by-step, finding which neurons feed into which and what each stage computes. Some follow a specific question backward: given a prediction, which parts of the input actually caused it? Others use language models themselves to read out the model's internal state in English. Each approach trades off between simplicity and completeness, and each brings a different part of the model into focus.

Why does this matter? When an AI system is deployed in the real world — in medicine, criminal justice, hiring, autonomous vehicles — we need to know when to trust it. If a model hallucinates or relies on spurious patterns, interpretability can catch that. It helps engineers spot bugs and improve architectures because seeing what the model actually computes reveals design flaws that test scores alone would miss. It helps researchers understand what their models actually learned, separate from what they intended, so they can detect when a model has learned to cheat or exploit the data in unintended ways. And it's a foundation for building models we can align with human values because you can't align what you can't understand.

Subtheme

Finding hidden features in neural networks

Neural networks store information in compressed form. A language model might encode 'this word means cat' not in one neuron but in a pattern spread across hundreds of them, like a code written in a high-dimensional space. Researchers want to find the 'atoms' of this code — the minimal set of directions in that space where each one stands for one clear concept. If they can do that, the model becomes much easier to understand: instead of millions of adjustable numbers, they focus on a few interpretable features.

The challenge is that finding these features is like recovering the original message from heavily scrambled data. The model's learned representation might mix multiple concepts in subtle ways. A direction might matter only in certain contexts. And some features might be quirks of the training process, not real patterns the model should use. These papers use dictionary learning and sparse autoencoders — techniques that find a small set of direction vectors (directions in the high-dimensional space) that can reconstruct the model's hidden states while staying interpretable. The goal is to decompose the model into a 'parts list' that a human can reason about.

Subtheme

Tracing how models compute step by step

A large language model processes text in layers. The first layer might extract simple patterns like 'this token is a noun.' A middle layer might combine patterns: 'this noun is the subject.' Deep layers might encode abstract reasoning. But how do these stages connect? Which earlier computations feed into which later ones? Can we find modular circuits — small groups of neurons that collaborate to solve one sub-problem? This line of research treats the model as an actual circuit: neurons are nodes, connections have weights, and information flows from input to output.

The difficulty is scale and entanglement. Even a small model has millions of connections. Most neurons participate in multiple tasks. A single neuron might fire for dozens of unrelated reasons. Researchers use techniques like activation patterns, attention weight analysis, and causal intervention — toggling parts of the model to see what breaks — to trace these circuits. The payoff is a mechanistic model: a picture of how the model actually computes, not just a statistical description. When you understand the circuit, you can predict failure modes and sometimes redesign it.

Subtheme

How language and meaning flow through the model

Language models process text token by token — one chunk at a time — and each token is first converted into a numerical vector called an embedding (a list of numbers that represents the token in a way the model can work with). As the token flows through layers, this vector is transformed, mixed with information from surrounding tokens, and gradually becomes something richer. By the final layers, the same token's representation has absorbed context: 'bank' in 'river bank' is represented differently from 'bank' in 'the bank is closed.' This research asks: where and how does this transformation happen? At what layer does the model separate the surface form (spelling, word order) from the meaning?

The core challenge is that language has layers of structure: sound, syntax (grammar), and semantics (meaning). A model has to build all three and coordinate them. Do early layers extract syntax while later layers add meaning? Or does it happen all at once? Some research uses probing classifiers — attaching a small auxiliary model to read out hidden states and asking, 'if I measure at this layer, can I predict the part of speech?' Others track how specific token positions influence each other through attention. By building this map, researchers understand how language gets parsed and reassembled inside the model, which matters for spotting errors or biases introduced during that processing.

Subtheme

Explaining what a model's prediction came from

When a model makes a prediction, we want to know why. If a language model generates the word 'happy' as the next token, which parts of the input influenced that choice? Was it a specific adjective two sentences back? A pattern in the overall sentiment? These papers compute importance scores: a number for each input element (word, pixel, etc.) telling how much that element contributed to the final answer. This is called attribution or explainability — the goal is to justify the prediction in terms of the input.

Attribution is tricky because causality in neural networks is tangled. Removing one input word changes many neurons, which affect many other computations downstream. Does the importance score measure the direct effect or the total effect? Different methods give different answers. Some use gradient-based methods: how much does the output change if we nudge the input slightly? Others use perturbation: mask inputs and see what breaks. The papers in this area refine these techniques and study when they work and when they fail. The use case is critical: in medicine or law, you need to explain decisions, and a model that points to the relevant evidence is more trustworthy than one that stays silent.

Subtheme

Testing whether explanations are trustworthy

Imagine a model that's good at predicting but gives explanations that sound plausible but are wrong. It might point to random parts of the input and claim they caused the output. To a human reader, the explanation might sound convincing, but it's false. This is a real danger: if we rely on interpretability methods that are themselves unreliable, we gain false confidence in a broken model. These papers ask a hard question: how do we know an explanation actually captures what the model is doing?

One approach is adversarial testing: design cases where you know the true explanation and see if the method finds it. Another is mechanistic verification: trace through the computation step-by-step to see if the highlighted inputs actually cause the output via the paths the explanation claims. A third is consistency: do different explanation methods agree? These papers also benchmark explanations against simpler proxy models. If the explanation helps a simple model achieve similar accuracy, that's evidence the explanation captures real structure, because a simpler model that learns from the same explanations will also need those explanations to be true in order to match the complex model's behavior. The goal is to move interpretation from an art (that sounds reasonable) to a science (that provably works).

Subtheme

Catching when models hallucinate or go wrong

Language models sometimes generate text that is false, nonsensical, or based on patterns that don't generalize. When asked 'What is 2 plus 2?', a model might answer '5' with high confidence. This is called hallucination. The model isn't reasoning; it's matching patterns in its training data. These papers try to detect when a model is uncertain, contradicting itself, or leaning on spurious correlations — surface-level patterns that happen to be true in the training set but don't reflect real reasoning.

Detection methods look for red flags inside the model. High uncertainty in the internal states might signal doubt. Incoherence — when different parts of the model disagree — might mean the model is guessing. Some papers check whether the model's explanation of a prediction actually holds up under scrutiny: if you ask the model to justify its answer and the justification doesn't logically follow, it's probably hallucinating. Others measure whether the model is truly using the features it claims to use or just pattern-matching shallow correlations. The aim is to catch failures before they reach the user, so the system can fall back to a human, ask for clarification, or refuse to answer.

Subtheme

Reading out what models secretly think

Inside a model's computation, information is encoded in a numerical format that computers can process but humans cannot read. The numbers in a hidden layer don't look like English words or ideas. But they must encode something — patterns the model noticed, knowledge it extracted from training data, hypotheses about the input. Some researchers use other neural networks to translate this internal code into human language. You can take a specific internal state, pass it to a separate decoder network (a small model trained to output descriptions), and ask it to generate a sentence describing what that state represents.

This is helpful because it lets a language model help us understand another language model. But it's also risky: the decoder itself might hallucinate. It might describe features that don't really exist or get the meaning subtly wrong. Researchers validate by checking whether the decoded descriptions actually predict the original model's behavior: if the decoded description is accurate, the original model should act consistently with it. Some papers also use prompting: activating the model to 'think aloud' about what it's computing at each step. The challenge is making sure the translation is faithful, not just plausible-sounding.

Subtheme

Understanding reasoning inside the model

Some models are trained to reason step-by-step, generating intermediate thoughts before arriving at a final answer. This happens in chain-of-thought prompting, where a language model outputs working memory — 'Let me think about this...' — before answering. These papers ask: when a model does step-by-step reasoning, is it actually reasoning or just mimicking the style? Inside the model, do the intermediate steps represent genuine problem-solving, or are they cosmetic? And when reasoning fails, where does it break — at the setup, the arithmetic, the logic?

Understanding internal reasoning is hard because the steps the model computes might not match the text it outputs. The model might be doing correct reasoning but expressing it poorly, or it might be writing convincing-looking reasoning while the computation is actually guessing. Researchers measure whether intermediate states contain information needed for later steps. They intervene: corrupt an intermediate step and see if it breaks the final answer, proving that step was actually used. Some papers use mechanistic analysis to show that specific parts of the model are solving the sub-problem at each step. The goal is to build confidence that when a model reasons, it's actually thinking through the problem, not just pattern-matching.
