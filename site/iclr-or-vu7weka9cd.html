Membership Privacy Risks of Sharpness Aware Minimization

Seeking flatter loss valleys improves accuracy but reduces confidence variance, which makes it easier to tell if a person's data was in the training set.

Paper explainersAll themesAlignment, Safety & Fairness

Sharpness-Aware Minimization (SAM) is an optimization method that trains models to sit in broad, gentle plateaus in the error function (the curve that shows how wrong the model is at each possible weight setting), where small changes to the weights produce only small changes in error. This helps the model generalize better to new data, because small random shifts during training don't throw the model off course. But this paper reveals a dark tradeoff: SAM-trained models are paradoxically MORE vulnerable to membership inference attacks—attempts to guess whether a person's data was part of the training set—despite their better accuracy. The reason is that flatness forces the model to produce more uniform, predictable confidence scores, and an attacker can exploit that predictability.

Zero assumption version

The flatness trap

A machine learning model learns by finding a spot in weight-space where the error is small. But not all low-error spots are equal. Some are in sharp valleys: nudge the weights even slightly and error jumps. Others sit in broad, flat plateaus: nudge the weights a lot and error barely moves. Flatter spots tend to generalize better to new data, because small random shifts due to variance in the training process don't throw the model off.

Sharpness-Aware Minimization (SAM) deliberately seeks flat spots. It does this by adding a penalty term: when a weight is updated, SAM looks for the worst-case error in a small ball around the current weights, then minimizes that worst-case error. This is brilliant for accuracy—the paper shows SAM achieves lower test error than classical SGD. But flat minima have a hidden consequence: the model's predictions become more consistent, less jittery. A naive hope would be that any improvement in accuracy is purely good news. But membership inference attacks exploit inconsistency. A member's data point is seen at train time, so the model overfits it slightly—the model becomes particularly sensitive to small variations of that person's data, because it memorized their exact training example. A non-member's data point was never seen at train time. The model was never incentivized to fit that data tightly, so it often gives different confidence values on slight variations of that data. The attacker looks for this tell-tale pattern: steady confidence means likely member, jittery confidence means likely non-member. Flatter models are smoother, less overfitting-prone, so this member-vs-nonmember difference should vanish. But paradoxically, the flatness creates a new signal: even flatter models show members with tighter confidence than non-members.

The method in one sentence. SAM trains to flat valleys so predictions become uniform; this kills the tell-tale inconsistency that membership attacks exploit—but not in a good way for privacy.

The algorithm as a flow

What it actually does

SAM optimizes for flatness

During training, SAM looks ahead: if we move weights in any direction, how bad could the loss get in a small ball around the new location? Minimize that worst-case loss.

Flatness reduces variance

Flat regions mean all small perturbations to weights produce similar prediction outputs, because the flat plateau has no steep slopes to amplify tiny weight changes into big prediction changes. So if you ask the model the same question many times with tiny variations, it gives similar answers each time rather than wildly different ones. This means the model's confidence on any input becomes steady rather than jittery.

Both members and non-members get uniform scores

Data seen during training and data never seen both now receive steady, predictable confidence values from the model, because the model sits in a flat region where nudging weights slightly does not change predictions much.

Attacker compares score histograms

A membership attacker trains on reference data and then observes: does this query data point's confidence scores fluctuate wildly or stay tight? Tight clusters look like training data.

Privacy paradox emerges

SAM's uniform predictions kill the tell-tale jitter that signals overfitting. But here is the paradox: flatness reduces how much the model varies on ANY input, including both member and non-member data. However, member data shows even LOWER variance than non-member data does. So instead of looking for jitter patterns, an attacker looks at absolute variance levels—and SAM makes those levels so much lower overall that the difference between member and non-member becomes MORE visible, not less. Result: accuracy up, privacy down.

What the paper changes

What the paper changes

SAM changes the target of optimization: instead of minimizing loss at the current weight location, it minimizes the maximum loss in a ball around those weights. This causes the model's predictions to become less volatile when weights are perturbed slightly.

the object it moves  =  prediction variance during training
The hidden quantity

Confidence variance: the tell-tale signal

measured quantity  =  output confidence variance

When a model makes a prediction on a new input, it outputs a confidence score (how sure it is). If you ask the model the same question many times with slightly different versions of the input, a sharp model gives wildly different confidence values; a flat model gives very similar values. This variance in outputs is the hidden quantity SAM manipulates.

The paper measures this by collecting confidence scores across multiple test samples and checking their scatter. For data the model saw during training (members), the confidence scores are tighter—lower variance. For data the model never saw (non-members), because SAM places the model in a flat region, the scores are also tight, but the paper shows member data produces measurably less scatter. The attacker uses this signal: if the confidence variance is unusually low for a sample, it probably was in the training set.

Paper reading. The paper proves that in a perfectly interpolating linear regime (where the model fits all training data exactly), SAM reduces output variance as a mathematical consequence of the flatness penalty. When confidence values form tighter clusters, the attacker can more easily separate members from non-members by looking at how varied the model's answers are. The ranges of answers become more distinct: member answers cluster tightly in one range, non-member answers in a slightly wider range. This sharper boundary makes membership attacks far more accurate because the attacker now has a clear gap between the two clusters—easy to build a threshold or classifier to split them.
Why it works

Why flatness leaks privacy

SAM modifies the loss function to penalize sharp minima. At each training step, instead of just minimizing loss at the current weights, SAM looks around: within a ball of radius rho, what is the maximum loss? Then it minimizes that maximum. This forces the model into a flat region.

A flat region has a key property: if you push the weights in any direction, the loss only climbs gently. Mathematically, the gradient (direction of steepest ascent) is small in all directions. For predictions, this means: nudge the weights and the model's output barely changes. So confidence scores become stable, less volatile.

Standard SGD can overshoot into sharp valleys because there is no penalty for sharpness. Sharp valleys mean the model's predictions are sensitive to tiny weight changes—which means they vary a lot. This variation is an accidental signal of overfitting, because the model has memorized specific training examples and is now fragile to noise.

Membership attacks exploit this: they measure how variable a model's confidence is. If confidence is steady, the model probably saw that data at train time and fit it tightly (even though the fit is now smooth). The attacker notices members produce lower-variance confidence. SAM makes this signal STRONGER because SAM explicitly enforces low variance across all predictions. With SGD, the overfitting jitter creates a tell-tale difference: members give jittery answers, non-members give steady answers. But with SAM, everyone gets steady answers, so the attacker must look at absolute values of confidence, not jitter—and SAM's uniformity makes that easier to exploit.

Math after the picture

The flatness penalty

First in words:

SAM loss = standard loss + penalty for maximum loss in a nearby ball. penalty = lambda times the difference between max loss near current weights and current loss

Then the compact form:

L_SAM(w) = L(w) + lambda * max_{||u|| <= rho} L(w + u) - L(w)

Every symbol:

L(w)standard training error for weights w
L_SAM(w)SAM's modified loss with flatness penalty
lambdastrength of the flatness penalty
rhoradius of the ball to look inside
uperturbation to the weights
max_{||u|| <= rho}worst-case loss direction within radius rho
A tiny worked example
Suppose weights are at w0, and standard loss is 0.5.
SAM looks in a ball of radius 0.1. It finds the worst direction: if we move +0.1 in direction v1, loss rises to 0.8. The max loss in the ball is 0.8.
Penalty = lambda * (0.8 - 0.5) = lambda * 0.3.
If lambda = 10, penalty = 3.0, so total SAM loss = 0.5 + 3.0 = 3.5.
Training will nudge weights away from direction v1 to flatten the valley. After training, worst-case loss in the ball is only 0.55, so penalty drops to 10 * (0.55 - 0.5) = 0.5, and model sits in a flat region.

Flatness penalty pushes weights toward regions where nudging weights in any direction only slightly changes the loss. Mathematically, this forces the model's outputs to stay similar under small weight perturbations. Ironically, this stabilizes predictions for all data, including non-members, but it does so more aggressively on member data—making that contrast detectible to an attacker.

What can go wrong

What can go wrong

Only works on models that fit their training data tightly. SAM's privacy leak relies on the model overfitting slightly at train time so flatness makes that overfitting obvious. On very hard problems where the model is already underfitting, SAM's benefit to privacy is unclear. The paper tests on standard vision and language benchmarks; atypical domains may differ.
Assumes attacker has reference data. Membership attacks need labeled examples of non-training data to set a threshold. If the attacker has access only to the model itself and no reference dataset, some attack variants weaken. The paper assumes the standard threat model: attacker has some unlabeled data and can partition it into train/test.
Variance reduction is not the only privacy mechanism. The paper proves variance reduction amplifies membership leakage, but it is possible that other properties of SAM (e.g., reduced reliance on outliers, or memorization patterns) also contribute. The paper measures memorization scores and confirms SAM does memorize atypical samples more, but disentangling causes is hard.
Differential privacy patches can still work. Adding noise during training (differential privacy) reduces membership leakage regardless of whether the model is trained with SAM or SGD. The privacy-accuracy tradeoff is orthogonal.
What a runnable demo should prove

What a runnable demo should prove

A demo should train two models on the same dataset—one with SAM, one with SGD—and then run membership inference attacks on both. Measure: (1) test accuracy for both models, verifying SAM achieves higher accuracy because its flat region is more stable. (2) Collect confidence scores on many variations of the same test sample, computing the variance—show that SAM produces tighter, less spread-out scores because small weight changes cause only small prediction changes. (3) Run a membership attack (threshold-based: flag high-confidence as member, low-confidence as non-member; or ML-based: train a classifier on reference data) on both models and report attack accuracy—show that SAM's attack succeeds more often because the member-variance-vs-nonmember-variance gap is wider. Use a small dataset like CIFAR-10 and a small model like ResNet-18 so the demo runs in minutes on a CPU.

membership_attack_accuracy = (true_positives_on_members + true_negatives_on_nonmembers) / (total_members + total_nonmembers)

The demo must make vivid that SAM achieves lower test error AND higher membership attack accuracy simultaneously. Better accuracy and worse privacy emerge from the same flatness property: flatness lowers overall prediction variance (everyone gives tighter answers), but member data sits in an even-flatter sub-region (because training optimized there), so member variance is noticeably lower than non-member variance. This gap is the attacker's signal. One property, two opposite consequences.
