Optimizing Visual Generative Models via Distribution-wise Rewards

Instead of rewarding individual images, reward the whole batch as a group to prevent collapse where all samples become identical.

Paper explainersAll themesGenerative Models & Diffusion

When training image generators with reinforcement learning (a method where you nudge a model toward better results), a common trap is sampling-wise rewards. Each image gets scored individually, so every image independently chases the highest score, because the training updates nudge each image toward higher individual rewards. The result: all images drift toward the same mode. This paper changes the scoring rule: score the entire batch together as a group, measuring how varied they are. This stops collapse because now the model only gets a high score when the batch is both good and diverse.

Zero assumption version

Why individual rewards fail

Image generators create pictures by learning patterns from data. When you train them with reinforcement learning, you score each image and nudge the model to make higher-scoring images. The trap: if every image is scored separately, every image tries to maximize its own score, pulling all samples toward the same single mode that gets the highest reward. This is called mode collapse.

A beginner would try scoring each image individually. This backfires because the model has no reason to keep samples diverse—they all chase the same peak.

In one sentence. Reward the entire batch of samples as a group, not each sample alone.

What the paper changes

The score applied to training

The paper changes what gets scored during reinforcement learning. Instead of giving each generated image its own reward score, the method scores the entire batch of images together, looking at how different they are from each other.

the object it moves  =  batch reward signal
The hidden quantity

Distribution structure—the invisible force

measured quantity  =  batch diversity penalty

The paper introduces an invisible quantity that measures how spread out the generated samples are. Each reward not only rates quality but also penalizes the batch if all samples cluster too close together. This force keeps the batch diverse. The paper estimates this penalty by looking at how much the samples vary—if they are all nearly identical, the penalty is large; if they span different modes, the penalty is small.

Why it works

How batch rewards stop collapse

Here is the causal chain. When you score each image alone, the gradient (the arrow pointing to better solutions) for each image points the same way—toward the highest-scoring image type. Every image chases that same target, so they converge to identical pixels. When you score the batch as a whole, the reward now depends on both quality and variance. If all images become too similar, the batch reward drops, the gradient reverses, and the model learns to produce different images. The diversity requirement is built into the reward itself, not added as a separate penalty afterward.

Math after the picture

The batch reward formula

First in words:

batch reward equals quality score minus a coefficient times the negative variance, adjusted by a merge weight

Then the compact form:

R_batch = quality(samples) - lambda * (1 - variance(samples)) + alpha * (merge_coeff - base_coeff)^2

Every symbol:

R_batchthe reward for the entire batch
quality(samples)how good the generated batch looks on average
variance(samples)how different the samples are from each other
lambdathe strength of the diversity requirement
merge_coeffthe weight used to blend the improved model with the base
alphapenalty for deviating from the pretrained weight
A tiny worked example
Suppose 5 images have quality=0.8 and variance=0.5.
Batch reward (with lambda=0.3, alpha=0.1, merge_coeff=0.6): 0.8 - 0.3 * (1 - 0.5) + 0.1 * (0.6 - 0.5)^2
= 0.8 - 0.3 * 0.5 + 0.1 * 0.01 = 0.8 - 0.15 + 0.001 = 0.651
If the same batch collapses to variance=0.1: 0.8 - 0.3 * (1 - 0.1) = 0.8 - 0.27 = 0.53
Lower reward for identical samples pushes model away from collapse.

The variance term in the reward directly penalizes collapse because when samples become identical, variance drops to zero and the penalty term grows, lowering the batch reward, so the model learns it must keep samples diverse to earn high reward while still chasing quality.

What can go wrong

What can go wrong

Over-weighting diversity. If the diversity penalty (lambda) is too strong, the model values spread over quality, generating low-quality images that happen to look different from each other.
Batch size sensitivity. Small batches have high natural variance, so the diversity signal is weak. Large batches are costly to reward-estimate.
Subset replacement noise. Using only a small subset to estimate rewards can introduce instability if the subset is not representative.
Done right. Tuning lambda to balance quality and diversity, using a representative subset size, and monitoring both metrics throughout training.
What a runnable demo should prove

What a runnable demo should prove

Build a simple image generator (e.g., a small diffusion model) on a toy dataset (e.g., 100 diverse images). Train it with sample-wise rewards, then with distribution-wise rewards. Track diversity by measuring variance across a batch of generated images, and track quality by a simple classifier score. The diversity metric should increase under distribution-wise rewards while quality stays competitive.

diversity_improvement = variance_distribution_wise - variance_sample_wise; quality_drop = quality_sample_wise - quality_distribution_wise

The demo must show that distribution-wise rewards raise diversity without collapsing quality below the sample-wise baseline.
