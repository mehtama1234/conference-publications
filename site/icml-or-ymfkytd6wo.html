Layer Pruning Breaks the Scaling Paradox in Time Series Models

When you add layers to a time series model, some layers do useful work and others distract; remove the distracting ones and the model becomes both faster and more accurate.

Paper explainersAll themesTime Series & Sequential

Time series models are huge nowadays — with 1.7 billion numbers to learn. You might think a bigger model would always be better, but researchers found something strange: sometimes a larger model performs worse than a smaller one, because most layers do redundant work and contradict each other during learning. By automatically finding and keeping only the working layers (about 21% of the original), you can make the model run nearly 3 times faster (fewer layers means fewer calculations), and the predictions become up to 12% more accurate (because the remaining layers work together cleanly without distraction).

Zero assumption version

Bigger is not always better

For decades, larger models have reliably beaten smaller ones. In language and vision, doubling the number of learned numbers (called parameters) almost always means better results, because there is more capacity to memorize patterns. So engineers keep building bigger time series models — models with billions of numbers that get tuned during training.

But here is the puzzle: on many time series forecasting tasks (predicting the next value in a sequence of numbers, like stock prices or temperature readings), adding more layers actually makes the model perform worse. The accuracy drops. This is the scaling paradox.

A beginner might guess the model is overfitting — memorizing details of the training set instead of learning general rules. But the real culprit is different: when you stack layer after layer, the later layers start doing redundant work. They amplify noise instead of refining predictions. The gradient signals (the nudges that guide learning) get tangled, and training never finds a good solution.

The method in one sentence: Identify which layers in a model are actually doing useful work, and delete the rest.

What the paper changes

What the paper changes

The paper removes entire layers (blocks of learned numbers and operations) from the model. It does not change the training data, the learning algorithm, or the task itself — just which layers stay and which get deleted.

the object it moves  =  which layers to keep
The hidden quantity

Layer importance: which layers actually matter

measured quantity  =  Layer importance score

Most layers in a model pass along the prediction without changing it much. A few layers make big changes. The paper introduces a way to measure how much each layer actually influences the final answer — call this the layer importance score. Higher score means that removing the layer would hurt the prediction more.

The paper estimates this by looking at the partial derivatives (small changes to the layer's output) and seeing how sensitive the final error is to those changes. Layers with high sensitivity are important; layers with low sensitivity can be pruned without much damage.

Why it works

Why removing redundant layers makes the model better

When you train a large model with many layers, each layer learns to transform the numbers a little. In theory, each transformation should be useful. In practice, later layers often do redundant work: they copy what earlier layers already said, or they amplify random noise in the data instead of refining the actual signal.

When you force the model to train with redundant layers, the training algorithm has to solve a harder puzzle. The gradients (the learning signals) bounce around contradictorily — some layers want to move in one direction, others in the opposite. The model gets stuck in a bad local solution.

By pruning the redundant layers, you simplify the puzzle. The training algorithm has fewer competing signals to coordinate, so it finds a better solution faster, because each gradient signal now points in a consistent direction. Fewer layers also means fewer calculations per prediction, so the model runs nearly 3 times faster. Fewer calculations consume less electricity and GPU memory, so each server handles more forecasts per second without slowing, letting you run the same system with one-third the machines and one-third the cost.

How to score and prune layers

First in words:

For each layer, compute the sum of absolute gradients with respect to the final loss. Rank layers by this score. Keep the top N percent (approximately 21 percent) and delete the rest.

Then the compact form:

importance_i = sum_j |d(loss) / d(layer_i_output_j)|

Every symbol:

importance_iTotal importance score for layer i
lossThe prediction error on time series data
layer_i_output_jThe output value j from layer i
d(loss) / d(layer_i_output_j)How much the loss would change if we nudged that output slightly (the gradient)
A tiny worked example
Suppose Layer 1 has 100 output values and the average gradient magnitude is 0.8 per value. Total importance: 100 * 0.8 = 80.
Layer 2 also has 100 outputs, but average gradient magnitude is 0.05 per value. Total importance: 100 * 0.05 = 5.
Layer 3: 100 outputs, average gradient 0.6 per value. Total importance: 100 * 0.6 = 60.
Rankings: Layer 1 (80), Layer 3 (60), Layer 2 (5). If we keep the top 33%, we keep only Layer 1. If we keep the top 67%, we keep Layers 1 and 3.

This score measures sensitivity: a high score means the final error depends heavily on that layer, so removing it would hurt badly.

What can go wrong

What can go wrong

Importance score is task-specific. A layer might be important for one time series dataset but useless for another. The method must be run separately for each application.
Too aggressive pruning loses signal. If you prune more than 80% of layers, the remaining model may be too small to hold the patterns needed for accurate forecasting. There is a practical limit.
Fine-tuning is still necessary. After pruning, the model needs a brief retraining phase on the new data to re-optimize the remaining layers. Without this step, accuracy will still drop.
Done right: measure, prune carefully, fine-tune. Use the importance scores as a guide, prune a modest fraction (70 to 80 percent), and always re-train the pruned model on the original task.
What a runnable demo should prove

What a runnable demo should prove

Build a small time series forecasting model (e.g., predicting the next 10 values in a stock price or weather sequence) on a public dataset like ETTh1 or traffic data. Train a 200-layer model and measure its accuracy and speed (how long it takes to make one prediction). Then apply the layer importance scoring: compute gradients and rank each layer. Prune the bottom 80% of layers, retrain briefly, and measure accuracy and prediction time again.

speedup = baseline_inference_time / pruned_inference_time; accuracy_gain = pruned_accuracy - baseline_accuracy

The demo should make it impossible to miss: a much larger model ran slow and performed badly, while a model 5 times smaller (after pruning) ran fast and more accurately.
