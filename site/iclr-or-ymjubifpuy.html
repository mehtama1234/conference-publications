AutoMetrics: Build a Scoring System from Scraps

Instead of hiring humans to score every output, AutoMetrics learns to blend simple metrics and AI judges so a few hundred human ratings can guide millions.

Paper explainersAll themesDatasets & Benchmarks & Evaluation

Every AI chatbot or travel planner needs a way to know when it is working well. Humans score outputs by hand, but that is expensive and slow. AutoMetrics solves this by learning to mix simple scoring rules and LLM-as-a-Judge into a single automatic scorer that matches human judgment — and it does this with fewer than 100 human labels.

Zero assumption version

Human judgment is the only true measure, but it is too slow

When you build a chatbot or a travel planner, you need to know: is the output good or bad? A human can tell by reading and rating each answer. But humans are slow and expensive. You need hundreds or thousands of ratings to train a system. If you want to improve the system and test your changes, you need even more human ratings, because every tweak requires validation — your budget for human judgment runs dry quickly.

A naive attempt is to use one fixed automatic scorer — count the right keywords, measure how long the answer is, or ask an LLM to rate it. But a fixed scorer does not know what humans actually value. It might reward long answers when humans want short ones. It might count keywords that do not matter.

The gap. Humans are the ground truth, but they are expensive. Fixed automatic scorers are fast but wrong. AutoMetrics learns to blend simple metrics and LLM judges so that a small human signal (fewer than 100 ratings) can guide millions of automatic scores.

The algorithm as a flow

What it actually does

Start with MetricBank

A shelf of 48 pre-built metrics (keywords, length, syntax checks, LLM ratings).

Generate new judges

Prompt an LLM: For this task, what makes a good answer? Get domain-specific criteria.

Collect minimal human signal

Have humans rate a few hundred outputs (thumbs up/down, or a score).

Learn the blend

Regression: which metrics + judges predict human ratings? Weight each one.

Deploy the scorer

Use the learned blend to score new outputs automatically, instantly.

What the paper changes

What the paper changes

AutoMetrics changes how an automatic scorer is built. Normally, you either hand-craft a single formula (e.g., count specific words) or you use a black-box LLM judge. AutoMetrics instead creates a learned formula that mixes both kinds of signals — simple metrics and LLM judgment — so the mixture is tailored to what your humans actually care about.

the object it moves  =  the scorer formula
The hidden quantity

The hidden quantity: How well does the automatic scorer match human judgment?

measured quantity  =  correlation with human ratings

The paper measures one central quantity: the correlation, a number from 0 to 1 that says how closely the automatic scorer's outputs match human ratings. If humans rate an output as excellent and the automatic scorer also scores it high, the correlation is high. If they disagree often, the correlation is low.

AutoMetrics estimates this correlation from a small set of human ratings (fewer than 100). It then tunes the blend of metrics and judges to maximize this correlation, so the final formula becomes a faithful proxy for human judgment.

Why it works

Why mixing simple metrics with LLM judges works

No single scorer is universally true. A keyword counter works for some tasks (e.g., extractive summarization) but misses nuance in others (e.g., creative writing). An LLM judge is flexible but expensive and can hallucinate. Combining them lets you cover more ground.

A small human signal (fewer than 100 ratings) acts as a compass. It shows which of your candidate scorers (metrics and LLM judges) actually track human judgment. Regression is the glue: it learns a weight for each candidate scorer, so the weighted average becomes a faithful proxy. The human labels are scarce but trustworthy; the candidate scorers are abundant but noisy. Regression finds the mix that lets the noisy scorers track the truth.

This works because the candidate scorers are diverse. A metric might catch one aspect of quality (e.g., length); an LLM judge might catch another (e.g., coherence). In combination, they cover more of what humans care about.

The blending formula

First in words:

final_score = weight_1 * metric_1 + weight_2 * metric_2 + ... + weight_N * metric_N

Then the compact form:

score = sum_i w_i * m_i(output)

Every symbol:

scorethe final automatic rating of the output, 0 to 1
w_ithe learned weight for metric or judge criterion i
m_i(output)the score (0 to 1) of the output from metric or criterion i
sum_iadd them all up
A tiny worked example
Suppose you have 4 scorers: keyword-match, answer-length, LLM-judge-1, LLM-judge-2.
Regression on 100 human ratings learns: w1=0.3, w2=0.1, w3=0.4, w4=0.2.
A new output scores: keyword=0.6, length=0.7, LLM-1=0.8, LLM-2=0.5.
Final score = 0.3*0.6 + 0.1*0.7 + 0.4*0.8 + 0.2*0.5 = 0.18 + 0.07 + 0.32 + 0.1 = 0.67.
The LLM judges (weights 0.4 and 0.2) dominate the blend, so they drive the final score.

Regression finds the weights that make the weighted blend match human ratings as closely as possible.

What can go wrong

What can go wrong

Biased human labels. If the 100 human raters all prefer long answers, the regression will weight any metric that correlates with length, even if real human diversity wants short answers. Fix: use diverse human raters, or sample from real usage.
LLM judges hallucinate. An LLM prompted to judge might invent criteria that sound good but do not match human values. Fix: validate LLM-generated criteria against human feedback; filter out criteria that diverge.
Metrics are not independent. If two metrics measure nearly the same thing (e.g., two length-based metrics), regression will arbitrarily split the weight between them instead of combining their signal cleanly. Fix: pre-filter metrics for diversity, or gently steer weights away from overtuning to noise (e.g., add a penalty for extreme weights).
Done right. Use enough diversity in human raters, test LLM-generated criteria against real human ratings to make sure they align, and choose a diverse set of candidate metrics. With 100+ human labels and diverse signals, AutoMetrics becomes a trustworthy automatic scorer.
What a runnable demo should prove

What a runnable demo should prove

Build a tiny demo: pick one open-ended task (e.g., generate a travel recommendation, summarize a news article, answer a trivia question). Collect outputs from your system (or off-the-shelf). Have 50 humans rate each output on a 1-5 scale. Curate 5 simple metrics (e.g., answer length, keyword overlap with a reference, LLM yes/no judgment on a criterion). Generate 3 more LLM judgment criteria. Use AutoMetrics to learn the blend from 40 human ratings, and measure correlation on the held-out 10 ratings. Then compare how much the learned blend outperforms any single metric or LLM judge — the blend should rank outputs more similarly to humans because it can weight whichever signals actually matter for that task.

improvement = correlation_with_AutoMetrics - max_correlation_with_any_single_scorer

The demo makes it clear: one fixed scorer is predictable and brittle because it applies the same formula to every task; a learned blend is adaptive because it re-weights the signals for each new domain, so it stays faithful to human judgment wherever it changes.
