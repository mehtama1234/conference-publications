Alignment across Trees on Heterogeneous Hyperbolic Manifolds

Instead of matching one picture feature to many text features, build feature trees for both sides and align them in curved spaces built to model hierarchies.

Paper explainersAll themesMultimodal

Vision-language models (models trained on both images and text) need to wire images and text together so the model can answer questions about pictures, because the model must know which image parts match which text words at each level of meaning. Today, image encoders pull out a single blob of a feature, while text encoders naturally pull out many levels—coarse categories first, then finer details. This mismatch breaks alignment. This paper builds hierarchical feature trees for images too, using a guided query-and-lookup mechanism between text and image features, then aligns the trees by placing them in bent mathematical spaces whose bend models how deep the hierarchy is.

Zero assumption version

The asymmetry breaks alignment

Today's vision-language models have a wiring problem. When you show an image, the model extracts one summary blob—call it a single feature vector (a list of numbers describing what the image contains). But when you give it text like 'a bird species,' the encoder naturally reads it as a hierarchy: first the broad category (animal), then the mid-level type (bird), then the fine detail (species). One side outputs one feature, the other outputs many. It is like trying to match a single address to a list of addresses at different zoom levels.

A beginner might try forcing the image to be hierarchical by cutting it into pieces—crop the face, crop the body, crop the wings. But the image encoder does not know these chunks should form a hierarchy. You end up with unrelated scraps, not a sensible tree.

The move: Use the intermediate layers inside the image encoder itself—they already capture coarse-to-fine features—and stitch them into a tree with text guidance.

The algorithm as a flow

What it actually does

Extract visual hierarchy

Pull class tokens (summaries) from intermediate layers (e.g., layer 4 and 7); each layer has caught different levels of detail.

Guide with text

Text features at each hierarchy level act as questions; use a query-lookup mechanism to ask which image-layer features are relevant.

Build two trees

Collect the guided image features into a coarse-to-fine tree matching the text tree structure.

Embed in bent spaces

Map each tree into a hyperbolic manifold (a bent space where hierarchy fits naturally without distortion) with a bend-rate learned from the data.

Align via intermediate manifold

Learn an intermediate curved space between the two; move both trees toward it to minimize distance.

What the paper changes

What changes

The paper changes the visual feature extraction from a single blob into a tree of features with coarse-to-fine hierarchy, guided by text.

The hidden quantity

Manifold curvature: how much hierarchy lives in this space

measured quantity  =  manifold curvature per modality

A manifold is a bent mathematical space. A sphere is one; a flat plane is one too. Hyperbolic space is a special kind of bend (like saddle shape everywhere) that naturally encodes tree-like hierarchies—the deeper the hierarchy, the stronger the bend. This paper measures the optimal bend-rate for each modality's feature tree, because text and images may have different depths.

The paper learns these bend-rates directly from the data, making them adjustable per dataset. A stronger bend means the space can fit a deeper hierarchy without squishing branches together, because in a strongly-bent space, farther-out regions have exponentially more room—so you can spread coarse branches far apart and still fit fine branches close together near the center without collision.

Why it works

Why this works: hierarchy wants curved space

Flat space treats all relationships equally—a distance of 1 unit is the same anywhere. But hierarchies are not equal: going from animal to bird is a big semantic jump; going from bird to songbird is smaller. A bent space naturally fans out the center, so coarse branches take up much more room than fine branches, mimicking a tree shape. Flat alignment forces image and text features to match in a space that does not fit either one well; bent alignment lets each set find a space whose bend matches its own hierarchy shape.

The query-lookup step ensures image layers are harvested at the right level of detail. Early layers capture broad shapes (is it an animal?); text's coarse level queries them. Late layers capture fine details (what species?); text's fine level queries them. This prevents random mismatches.

The intermediate space is the marriage. Instead of forcing both trees into one bent space (whose bend might suit only one), the method learns a middle ground. Both trees move toward this intermediate space, meeting halfway, so alignment is fair to both hierarchies.

The alignment loss: balance curvatures

First in words:

Total loss equals the matching loss between tree features plus the entailment losses for each tree in its own space plus the cost of aligning across different curvatures.

Then the compact form:

J(theta, c1, c2) = J_proj(Te, Ve) + alpha * [J_Tent(T_c1) + J_Vent(V_c2) + J_ent(V_c*3, T_c*3)]

Every symbol:

c1curvature of image tree manifold (learned)
c2curvature of text tree manifold (learned)
J_projdistance between aligned image and text trees
J_Tenthow well text features fit their hyperbolic space
J_Venthow well image features fit their hyperbolic space
J_entdistance between trees in the intermediate space (curvature c*)

Te, Vetext and image feature trees

V_c*3, T_c*3trees embedded in the intermediate alignment manifold
A tiny worked example
Say text tree has curvature c1 = 0.5, image tree has c2 = 0.3 (text is deeper).
To align them, find intermediate c* = 0.4 (halfway). The loss for embedding text in 0.5 space: J_Tent = 2.1. The loss for embedding image in 0.3: J_Vent = 1.4.
Re-embedding both in c* = 0.4 costs J_ent = 0.8. Matching loss J_proj = 1.2.
Total (alpha=1): 1.2 + (2.1 + 1.4 + 0.8) = 5.5. Lowering alpha reduces hierarchy pressure; raising it tightens alignment to match structure.

Higher curvature pinches the space tighter, fitting deeper trees; the loss forces each tree's curvature to suit its actual semantic depth, then middle-grounds them for alignment.

What can go wrong

What can go wrong

Choosing the wrong intermediate layers. If layers 4 and 7 do not split coarse and fine correctly for a new architecture, the visual hierarchy collapses into noise. The method assumes intermediate layers encode increasing detail, which is true for standard image-reading models built with stacked blocks but may not hold for custom designs.
Curvature overfitting. If the dataset is small, learned curvatures c1 and c2 may overfit to that particular hierarchy structure and fail on new data with different depth. Few-shot settings are at risk here.
Intermediate manifold does not exist or is unstable. If the two hierarchies are radically different (one very deep, one very flat), the intermediate curvature c* may not smoothly bridge them, and the alignment loss oscillates without converging.
Done right. Validate layer choice on your architecture by trying layers 4, 5, 6, 7 and picking the best. Gently steer bend-rates to stay within a reasonable range. Monitor convergence; if it is erratic, the intermediate space math may be ill-conditioned—consider pre-conditioning the optimization.
What a runnable demo should prove

What a runnable demo should prove

Implement the query-lookup module: given a fixed image from a standard dataset (e.g., CIFAR-100), extract class tokens from layers 4 and 7 of a pretrained image-reading model. Use a text encoder to phrase category labels (e.g., 'bird', 'songbird', 'sparrow') at each hierarchy level. Run query-lookup where text levels query image-layer tokens. Visualize: do layer-4 features activate on coarse visual patterns (shape, size) while layer-7 features activate on fine details (feather texture, beak shape)? Next, place both the constructed visual tree and the text tree into bent spaces with different learned bend-rates. Compute the distance before and after alignment to the intermediate space. The metric is: how much does distance shrink from separate-bend-rate to intermediate-space placement?

alignment_gain = KL_before - KL_after; where KL_before = KL(image_in_c1 || text_in_c2) and KL_after = KL(image_in_c* || text_in_c*)

A successful demo shows that the intermediate space bend-rate truly bridges the two hierarchies—distance drops by half or more—and that the query-lookup genuinely extracts hierarchical visual features (layer 4 fires on coarse objects, layer 7 on fine details).
