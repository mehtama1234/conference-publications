Knowing When to Ask: Teaching Multi-Agent Systems to Defer to Humans

A multi-agent system learns to recognize when it has hit a knowledge boundary and ask a human for help, then absorbs that feedback to get smarter.

Paper explainersAll themesAgents & Tool Use

Large language models trained on a fixed dataset can only answer questions if the answer is hiding somewhere in their training data. When a question ventures into truly new territory, the agent fails silently rather than admitting it is stuck. This paper teaches a team of AI agents to recognize the edge of their knowledge, defer to a human expert at exactly the right moment, and then learn from what the human teaches them—making the system both more honest about its limits and progressively less dependent on human help because each deferral becomes a training example that strengthens the agent's internal reasoning.

Zero assumption version

Multi-agent systems are brittle beyond their training data

A team of AI agents can sometimes solve harder problems than one agent alone, because different agents can verify each other's work and spot errors. But when a problem requires knowledge that was never in the training data, all agents fail equally—they cannot invent facts they have never learned. If all agents learned the same training data, they have the same blind spots.

A naive fix would be to have agents always ask a human whenever they are unsure. This works but wastes human time; a human expert should only step in when it truly matters. The opposite mistake is to never ask, suffering a cascade of wrong answers built on a wrong foundation.

In one sentence. Agents learn a decision rule: try alone first, recognize when you have hit the boundary of your training knowledge, and defer to a human only when necessary.

The algorithm as a flow

What it actually does

Step 1: Autonomous attempt

All agents try to solve the problem using only what they learned in training.

Step 2: Metacognitive assessment

Agents examine the conversation so far and score their own confidence on this specific question.

Step 3: Deferral decision

If confidence is low and the cost of asking a human is less than the cost of a wrong answer, the system asks the human, because getting the right answer from an expert is cheaper than propagating a mistake through downstream tasks.

Step 4: Expert feedback absorption

The human provides the correct answer. The system treats this as a supervised training example.

Step 5: Continual learning

The agent updates its weights based on human feedback, incorporating new knowledge permanently into its behavior.

What the paper changes

What the paper changes

The paper adds a new decision gate inside each agent: a learned policy (a set of numbers that control behavior) that decides when to ask for help. This policy is trained to predict, for each new problem, whether the agent's current knowledge is sufficient or whether a human should be consulted, because learning when to defer is like learning when to stop improvising and ask for directions—a skill that compounds over time as the agent recognizes more patterns.

the object it moves  =  the deferral policy
The hidden quantity

The metacognitive confidence score

measured quantity  =  how uncertain the agent is

Before attempting a solution, each agent computes a single confidence number from the problem description and its own reasoning so far. This number is not a guess—it is computed from concrete signals like: Does the question mention concepts the model has never seen in training? Do my internal reasoning attempts get stuck or loop? Are the agents disagreeing sharply (a sign they are thrashing)? These signals are combined into one score between 0 and 1.

The paper shows how this score is used inside the training algorithm: if the score is low and a human is available, the inner training loop (the part that optimizes deferral decisions) learns to predict this low-confidence situation and emit a 'defer' action. If the human then provides feedback, the outer loop captures that and updates the agent's reasoning weights.

Why it works

Why it works: two learning loops

The trick is to use two separate learning loops. The inner loop trains the deferral decision very quickly on examples where a human just helped. It asks: 'When did I defer? Was that the right call?' If the human confirmed the problem was hard and the help worked, the inner loop reinforces the deferral decision, because that example shows the deferral criterion was accurate. If the agent should have solved it alone, the inner loop learns to avoid false alarms, because wasted deferrals consume human time without producing new knowledge.

The outer loop is slower and deeper. Whenever a human provides an answer, that answer is treated as ground truth. The system updates its reasoning weights so that on the next similar problem, it will not need to defer—it will have absorbed the expert's knowledge. This is the growth phase. Over time, the system becomes less dependent on humans because it has learned from them.

By separating these two jobs—immediate deferral decisions (inner loop) from capability growth (outer loop)—the system avoids a trap: it does not waste training on fixing its current mistakes; instead it trains itself to recognize when mistakes are likely and ask for help before they happen.

Math after the picture

The learning equation

First in words:

Total loss is the immediate reward from deferral decisions plus the learning signal from human feedback, weighted by how often we defer.

Then the compact form:

L_total = E[ L_inner + lambda_sft * Indicator(action=defer) * L_sft ]

Every symbol:

L_innerthe GRPO loss that optimizes whether to defer (inner loop)
L_sftthe supervised learning loss trained on human feedback (outer loop)
lambda_sftthe weight balancing immediate decisions vs. long-term learning (a dial the researchers tune)
Indicator(action=defer)a switch that is 1 if we deferred, 0 otherwise
E[...]average over all problems in a batch
A tiny worked example
Scenario A: Agent defers on a math problem, human gives answer.
L_inner = 50 (reward for the deferral was correct)
L_sft = 30 (training on this human feedback)
Indicator = 1 (we did defer)
lambda_sft = 0.5
L_total = 50 + 0.5 * 1 * 30 = 50 + 15 = 65
Scenario B: Agent does NOT defer, solves it alone correctly.
L_inner = 40 (reward for solving alone was correct)
L_sft = 0 (no human feedback to learn from)
Indicator = 0 (we did not defer)
lambda_sft = 0.5
L_total = 40 + 0.5 * 0 * 0 = 40 + 0 = 40
The system balances: sometimes deferring costs effort but leads to learning; sometimes solving alone is faster but the agent stays the same. Over time, as the agent learns more, L_sft shrinks (fewer deferrals needed) and L_inner optimizes for speed.

The equation shows that learning from human feedback only counts when we actually defer, forcing the system to decide deferral wisely.

What can go wrong

What can go wrong

False alarms: over-deferring. If the confidence threshold is set too low, the agent asks for help on every tricky problem, wasting human time and missing a chance to learn from struggle, because solving hard problems on your own is how reasoning skills sharpen. The inner loop must learn the right calibration.
False confidence: under-deferring. If the agent overestimates its knowledge, it will confidently give wrong answers and the outer loop will reinforce the mistake. The metacognitive assessment must be honest.
Feedback quality: learning the wrong lesson. If a human expert is tired or mistaken, the outer loop absorbs incorrect knowledge. The system becomes confidently wrong in a new way.
Done right: virtuous cycle. When confidence assessment is accurate and feedback is sound, the inner loop saves human time by deferring only when necessary, and the outer loop gradually shifts the agent toward independence.
What a runnable demo should prove

What a runnable demo should prove

Build a small multi-agent system (two to three agents) solving a set of problems where some are in-distribution (can be solved from training) and some are out-of-distribution (require new information). Let the system run with the metacognitive policy disabled (baseline): watch it fail on out-of-distribution problems and waste effort on in-distribution ones. Then enable the Dual-Loop Optimization and give it a human oracle that answers deferred questions, treating each answer as a supervised training example. Measure: (1) how many times the system asks for help, which should be low for in-distribution problems (because the agent has already learned them) and high for out-of-distribution ones (where knowledge must come from somewhere), (2) how often the human needs to step in, which should decline over episodes as the outer loop learns and incorporates feedback, and (3) final accuracy on a held-out test set never seen in training.

learn_efficiency = (correct_answers_on_hard_problems - deferrals_wasted) / total_deferrals; improvement = accuracy_with_HILA - accuracy_baseline

The demo succeeds when the system learns to ask only when it matters, and then visibly stops asking as the outer loop embeds human feedback into its permanent knowledge.
