Random Controlled Differential Equations

Train only a single linear layer atop a giant randomly frozen time model, avoiding the cost of updating millions of weights.

Paper explainersAll themesTime Series & Sequential

Predicting future values in a time series (stock prices, weather, sensor readings) usually means training a huge model with millions of weight updates. This paper freezes a randomly built model and trains only one small linear layer on top, keeping it fast and simple while capturing complex temporal patterns through random features and differential equations.

Zero assumption version

Training large time models is slow

Every time you train a sequence model (a neural network that processes a stream of numbers), you run gradient descent: compute an error, nudge each of millions of weights in the direction that shrinks it, repeat hundreds of times. This is expensive — it requires many forward and backward passes, and storing all the intermediate values in memory. For real-time applications or edge devices, you cannot afford this cost.

A beginner might try training a tiny model instead, but tiny models do not see enough past context to make good predictions. You need a model that remembers thousands of past values, but training it is prohibitively slow.

The paper's move, in one sentence: Freeze a randomly initialized model and train only the final single linear layer that reads off the output, avoiding the cost of updating the frozen weights.

The algorithm as a flow

What it actually does

Initialize a large random model

Create a controlled differential equation (a system that evolves continuously over time) with random weights, never changed.

Lift inputs with random features

Transform each input using random Fourier features (random waves at different frequencies and phases), creating a richer representation.

Run inputs through the frozen model

Feed the lifted inputs into the random differential equation, which evolves over time and outputs complex patterns.

Collect the output representations

Store all the values the frozen model produces across the time series.

Train the linear readout

Fit a single linear layer on top to predict the target (next value, classification, or other label) from the frozen representations.

The hidden quantity

The representation: path signature

measured quantity  =  path signature (higher-order temporal features)

A path signature is a mathematical summary of a path (a stream of values over time) that captures not just the values themselves but the order and sequence of changes. It is similar to a fingerprint: two completely different time series can produce the same sequence of points, but the signature tells them apart because it records how the path moved through space.

This paper estimates the path signature implicitly: instead of computing it directly, the random differential equation model automatically produces features that span the space of all possible path signatures. The random features and the continuous-time dynamics together mean the frozen model outputs representations that encode these higher-order temporal patterns without explicit computation.

Why it works

Why freezing works: random features already capture what matters

When you randomly initialize a large neural network and freeze it, the network's weights are a fixed 'basis' — like an unchangeable coordinate system. Adding more random features (sine waves at random frequencies) expands this basis, so the frozen network can express more patterns without ever changing its weights.

The reason this works for time series: random features at many different frequencies can approximate any smooth function of the input. The continuous-time differential equation (which evolves smoothly) then composes these features over time, automatically producing representations that encode the full history of the input path. Training only the readout layer finds which combination of these frozen representations best predicts the target. You skip the expensive part (updating millions of weights) and keep the cheap part (fitting a single linear layer to pre-computed features).

Math after the picture

The core equation

First in words:

The output is a linear combination of the frozen model's representations. Each representation is produced by passing lifted features through the differential equation.

Then the compact form:

output = W * h_frozen(t) + b

Every symbol:

outputthe prediction (next value or class)
Wthe linear readout weights (trained)
h_frozen(t)the frozen model's hidden state at time t
bthe readout bias (trained)
A tiny worked example
Suppose the frozen model outputs a 3-element representation at each time step: h = [2.1, 0.5, 1.8].
The readout weights are W = [0.4, 0.3, 0.2].
Prediction = 0.4 * 2.1 + 0.3 * 0.5 + 0.2 * 1.8 = 0.84 + 0.15 + 0.36 = 1.35.
To improve the prediction, training nudges W slightly: perhaps W becomes [0.45, 0.25, 0.25].
New prediction = 0.45 * 2.1 + 0.25 * 0.5 + 0.25 * 1.8 = 0.945 + 0.125 + 0.45 = 1.52.
No weight in the frozen model moves; only W and b change — fast, because there are only 3 numbers to train.

The entire complexity lives in h_frozen, which is computed once and never retrained. Only the linear combination of these frozen values is learned.

What can go wrong

What can go wrong

The frozen model is too small. If the random model does not have enough capacity, even the best readout layer cannot extract good features from it. The random features and differential equation must be large enough to span the space of patterns you need.
Random features are poorly matched to the data. If the Fourier frequencies are chosen badly (all too high or all too low), the lifted input loses important structure before the frozen model even sees it. The choice of random frequencies is a design decision that affects performance.
The linear readout bottleneck. A single linear layer cannot capture arbitrarily complex nonlinear relationships in the frozen features. If the target depends on complex interactions the readout cannot express, performance will plateau.
Done right: scale the random model and verify on a validation set. Use a large frozen model, tune the Fourier feature frequencies and magnitudes, and measure accuracy on held-out data. A slightly smaller frozen model trained on random features often beats a smaller trainable model.
What a runnable demo should prove

What a runnable demo should prove

Implement a random CDE on a standard time-series benchmark (e.g., a currency exchange rate, stock price, or sensor signal). Split the data into train and test. On the training set, freeze the random differential equation and train only the linear readout using linear regression or gradient descent. Measure the mean squared error on the test set and compare it to training a full model with the same architecture using the same time budget. Plot both the prediction and the true signal side by side to see where they diverge.

The frozen model with a trained readout should reach competitive accuracy in a fraction of the training time of a full model.
