From Seeing to Experiencing: Navigation via Pretrained Video and Real-World Refinement

A robot learns to navigate by first watching millions of hours of real-world video, then fine-tunes on interactive simulation so it reacts safely to obstacles and people.

Paper explainersAll themesRobotics & Control

Navigation models trained on internet video alone can generalize across cities and robots, but they do not learn what happens when they actually move—they only predict camera angles from other camera angles. This paper adds reinforcement learning (where the robot learns by trial and failure in simulation) to teach the same model to think about consequences and react to dangers, without forgetting the broad knowledge it learned from watching video.

Zero assumption version

Video teaches you to watch. It does not teach you to move.

A robot trained on millions of hours of real-world video can predict what a street looks like from different angles. It learns general patterns: how trees look, how cars move, how crowds flow. The model can handle cities it has never seen before.

But video is passive watching. When you train a model only on video, you teach it to say what comes next in a recording, not what happens when the robot actually takes a step. A naive beginner robot would move forward confidently into an obstacle, because it has no experience feeling the consequence of that mistake. It learned to see, not to navigate—no counterfactual reasoning, no 'if I do this, that bad thing happens.'

Real urban navigation requires safety: avoiding obstacles, reacting to pedestrians, handling surprise. Video alone cannot teach this—you need practice in an interactive world where mistakes cost something.

The method. Train on video first to learn what the world looks like, then fine-tune through reinforcement learning in simulation to learn what your actions do, without forgetting the video knowledge.

The algorithm as a flow

What it actually does

Phase 1: Learn from video

Model watches real-world street videos, learns patterns of how scenes change as viewpoint shifts.

Phase 2: Anchor-guided learning

Pretraining stabilized by grounding predictions on anchor frames, so model learns diverse motion patterns reliably without drifting.

Phase 3: Residual gating layer

New trainable layer that adjusts which parts of the video knowledge to use, trained only through RL.

Phase 4: RL in simulation

Robot tries moves in a fake photorealistic world, gets reward for reaching goals and penalty for collisions.

Phase 5: Transfer

Fine-tuned model, which now knows both video generalization and interactive safety, deployed to real robots.

What the paper changes

What the paper changes

The object being changed is the navigation model's ability to adjust which parts of its learned video knowledge matter for action—specifically, learned numbers (called gates) that multiply each visual feature learned from video to adjust how much it influences the robot's movement decisions.

the object it moves  =  residual gating of learned features
The hidden quantity

The hidden quantity: Action consequence awareness

measured quantity  =  reward signal per action

In video-only training, the model is optimized on a very simple task: predict the next camera angle. There is no quantity measuring whether the model understands that its movement choices lead to different outcomes. Reinforcement learning introduces a hidden quantity: the gradient of reward with respect to the action the robot chooses. This tells you how much each motor command affects the likelihood of success or failure.

The paper keeps this quantity hidden by not letting it overwrite the video knowledge. Instead, the residual gating layer learns a small adjustment factor for each learned feature, proportional to how much that feature matters for predicting safe vs. unsafe actions. High-consequence features (like 'is there a person here?') get boosted; low-consequence features stay quiet.

Why it works

Why it works: Protecting knowledge while learning safety

The core problem: if you naively train a video-pretrained model with RL, the RL signal will overwrite everything—the model will unlearn the generalization that took millions of hours of video to build. You end up with a model that only knows the simulation it trained in, fragile on real robots.

S2E solves this by adding a bottleneck: instead of letting RL rewire the entire video-trained model, it trains only a small residual layer. This layer is a set of learned numbers that multiply the video features before they feed into the action choice. Each number is a fraction (like 0.8 or 1.2), so the RL can make important visual patterns matter more or make less important ones matter less, but it cannot completely erase them. The video-learned features stay in the model. The RL learns to adjust which video features matter most, not to reinvent the model.

Why this works mechanically: video features already encode what the world looks like (trees, pedestrians, road boundaries). The RL does not need to rediscover this; it only needs to learn which of these pre-existing features predict safety. By gating existing features with learned multiplier numbers, the model keeps its broad generalization and gains reactive safety in one training cycle.

Math after the picture

The formula: Gated video knowledge

First in words:

learned video features multiplied by RL-tuned scalars, then fed to the action choice

Then the compact form:

action = argmax( sum_i g_i * f_i(video) )

Every symbol:

actionthe movement command the robot sends
f_i(video)the i-th video-learned feature (what the model sees)
g_ithe learned scalar gate for feature i (trained by RL, initially near 1.0)
sum_iadd up all the gated features
argmaxpick the action direction with the highest score
A tiny worked example
Feature 1 (person ahead): learned value 8.0, RL gate 1.5 -> contribution 12.0
Feature 2 (clear road): learned value 6.0, RL gate 0.9 -> contribution 5.4
Feature 3 (distant tree): learned value 4.0, RL gate 0.3 -> contribution 1.2
Total score for forward: 12.0 + 5.4 + 1.2 = 18.6
RL discovered that people matter most (gate 1.5), distant trees matter least (gate 0.3), so the robot stops.

Each RL gate is a small multiplier; video features determine what the model sees, gates determine how much each sight influences the action.

What can go wrong

What can go wrong

RL overwrites video knowledge. If you do not use a gating bottleneck and instead let RL fine-tune the whole model, the safety signal drowns out the broad patterns. The model becomes brittle: high accuracy in the training simulation, crashes on real robots.
Simulation is too simple. If the simulation does not capture real-world physics—collisions feel different, lighting is fake, pedestrians behave differently—the RL trains on phantom lessons. The robot's safety intuitions do not transfer.
Anchor frames are poorly chosen. If the anchor frames in the pretraining phase do not represent diverse navigation scenarios (sunny, rainy, crowded, empty), the model fails to learn stable motion representations. RL then starts from a weak foundation.
Done right. Anchor-guided pretraining learns stable video features, residual gates preserve them, RL teaches selective use, sim-to-real transfer is modest but reliable.
What a runnable demo should prove

What a runnable demo should prove

Build a small robot navigation task: a photorealistic simulation (Gaussian Splatting reconstruction of a real scene, or a photorealistic game engine) with random obstacles, moving people, and a goal flag. Train a baseline video model on video-only data (pre-recorded navigation traces). Then add RL post-training via residual attention gating and show side-by-side: baseline crashes into obstacles or ignores them; S2E stops, reroutes, and reaches the goal.

safety = 1 - (collisions this episode / total steps); generalization = accuracy on unseen cities; overall = safety * generalization

The demo proves that gated attention lets RL teach safety without the model forgetting its video-learned world knowledge.
