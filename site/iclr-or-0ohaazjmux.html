LeSTD: LLM Compression via Learning-based Sparse Tensor Decomposition

Break the dense core tensor bottleneck in model compression by learning which core weights are truly important, then pruning the rest.

Paper explainersAll themesEfficiency & Systems

Large language models have billions of weights, making them expensive to store and run. One way to shrink them is tensor decomposition: split the weight matrices into simpler pieces that take up less space. But the trick has a fatal flaw: when you split them, you create a new dense core tensor that grows huge and cancels out your savings. LeSTD fixes this by first finding a smart shared basis, then learning which pieces of the core are worth keeping and which can be thrown away.

Zero assumption version

The dense core trap

Large language models are huge: a model like GPT has 70 billion numbers (called weights) that must be stored in memory. To make them smaller, researchers use tensor decomposition, which splits each rectangular table of weights into three smaller rectangular tables that multiply back together. This works in principle: three small tables take less space than one big one.

But there is a hidden cost. When you split a 2D table of weights into three tables using decomposition, the middle table (called the core tensor) has to capture everything that does not fit into the outer tables. When you choose to use more of these 'basis' directions (essentially, more columns in the outer tables), the core grows as the square (or cube) of that number. A core that was compressed 2x can become the new bottleneck, making the whole method pointless.

The problem in one sentence. Standard tensor decomposition trades a big table of weights for a dense core tensor that grows polynomially, cancelling out the compression gain.

The algorithm as a flow

What it actually does

Step 1: Find a shared basis

Run an algorithm that finds one set of basis directions that works well for all attention heads together, minimizing the information lost.

Step 2: Build the core tensor

Express all attention heads in terms of this basis. The core tensor holds the coefficients that mix the basis pieces for each head.

Step 3: Score each core element

Rank every number in the core by importance: which elements does the model rely on to keep accuracy, and which are barely used?

Step 4: Prune ruthlessly

Delete the least important elements, replacing them with zero. The model now stores only the core's non-zero pieces.

Step 5: Refit the remaining core

Adjust the surviving core elements slightly (because removing a weight creates a gap, refitting fills it back in to recover lost accuracy).

What the paper changes

The single thing the paper changes

This paper changes the core tensor: instead of a dense table full of stored values, it becomes a sparse table with mostly zeros. The basis directions stay the same; only the core is redesigned.

the object it moves  =  Core tensor sparsity
The hidden quantity

Importance score for each core element

measured quantity  =  Importance score (per element)

The paper measures how much each number in the core tensor contributes to the model's correct predictions. This is the 'importance': if removing a value and retraining drops accuracy a lot, that value is important. If removing it barely matters, it is unimportant.

LeSTD estimates importance by computing how sensitive the model's output is to changes in each core element. Elements with low sensitivity can be pruned away. After pruning, the remaining elements are adjusted slightly to keep predictions accurate.

Why it works

Why decoupling basis from sparsification works

Here is what makes this approach different: the dense core problem comes from trying to do two jobs at once. Standard methods choose the basis (to capture as much information as possible) AND keep the core dense (because pruning it was not part of the design). LeSTD splits these into two separate jobs.

First, it finds the best basis without worrying about the core's size. The basis is shared across all attention heads, so it can be optimized carefully: which directions capture the most information for all heads together? This basis is usually small (rank 16 or 32), so it is efficient.

Second, it prunes the core directly. Now that the basis is fixed, the paper asks a simpler question: which core elements are actually used by the model? The core can be pruned to extreme sparsity (90%+ zeros) because the basis has already done the hard work of capturing important directions. The pruning is guided by an importance score: a measure of how much each core value affects the final predictions.

This separation works because a sparse core with a good basis can be far smaller than a dense core, even if that core has fewer basis directions. By decoupling the two jobs, LeSTD breaks the polynomial bottleneck.

Reconstructing a head from basis and sparse core

First in words:

Each attention head is reconstructed by multiplying the basis matrix, the sparse core matrix, and the basis matrix transposed. Only the nonzero core elements contribute to the final result.

Then the compact form:

Head_i = Basis × Core_sparse_i × Basis^T

Every symbol:

Head_iThe reconstructed weight matrix for attention head i
BasisThe shared set of basis vectors (same for all heads)
Core_sparse_iThe sparse core tensor for head i (mostly zeros)
Basis^TThe basis transposed (multiplied on the right)
A tiny worked example
Suppose Basis is 4×2, Core_sparse_1 is 2×2, so Basis^T is 2×4.
Original dense head matrix would be 4×4 = 16 values.
After decomposition: Basis stores 8 values, Core_sparse_1 stores 4 values but 3 are zero (1 nonzero), Basis^T stores 8 values.
Total: 8 + 1 + 8 = 17 values. But wait — Basis and Basis^T are the same storage (one shared copy), so really 8 + 1 = 9 values for this head.
If there are 8 heads and all share Basis: 8 (Basis) + 8 heads × 1 (sparse core) = 16 values vs. 8 × 16 = 128 in the dense case. Compression: 8×.
Actual LeSTD achieves much higher compression by using even sparser cores and wider bases across all MHA blocks.

The sparse core uses almost no memory because most of its entries are zero; only the nonzero entries are stored.

What can go wrong

What can go wrong

Pruning too aggressively. If you remove core elements that are actually important but not yet detected, accuracy will drop. The importance score must be calibrated carefully to avoid over-pruning.
Basis does not capture all heads. If the shared basis is chosen poorly, some attention heads will be poorly represented in that basis, and pruning will hurt them more. The basis optimization step determines whether the whole method works.
Refitting is not thorough enough. After pruning, the remaining core values must be adjusted to compensate. If this step is skipped or rushed, accuracy will drop.
Done right. LeSTD works because it scores importance carefully, chooses a good basis first, and refits the core after pruning. This three-stage design avoids the pitfalls above.
What a runnable demo should prove

What a runnable demo should prove

Build a small language model with 12 attention heads (like a toy GPT). Compress one multi-head attention layer using LeSTD with a rank-4 basis and target 90% core sparsity (meaning 90% of core elements become zero). Measure: (1) Storage in bytes for the original head, the dense decomposition, and the sparse decomposition. (2) Accuracy on a small test set before and after compression. (3) Time to run the finished model on both the original and compressed versions on 100 test examples.

compression_ratio = storage_original / storage_compressed; accuracy_loss = accuracy_before - accuracy_after

The demo must show that LeSTD compresses 3–5x while keeping accuracy loss under 2%, and runs faster than the original because it has fewer stored numbers and can use sparse operations.
