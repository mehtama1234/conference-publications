OmniCT: Towards a Unified Slice-Volume LVLM for Comprehensive CT Analysis

Build one CT model that can read both single slices and full volumes, so it can answer local detail questions and 3D spatial questions without switching architectures.

Paper explainersAll themesMultimodal

CT interpretation needs two levels of understanding at the same time. A radiologist may need to inspect a tiny lesion boundary on one slice, but also reason about how that lesion spreads across many slices and how it sits relative to nearby organs. Existing large vision-language models usually choose one side. Slice-based systems are sharp on local detail but weak on cross-slice consistency. Volume-based systems preserve 3D structure but often blur away fine detail and do not accept ordinary slice inputs gracefully. OmniCT tries to unify both modes in one model by making slice inputs carry volume cues and by injecting explicit organ-level alignment signals.

Zero assumption version

Why CT understanding breaks when slice detail and 3D structure are split apart

A single CT slice can show very small findings, but that slice alone does not reveal where the finding sits in the full body structure. A full CT volume preserves those body-wide relations, but direct volume models often downsample heavily because 3D data is large. That reduces sensitivity to small lesions, vessel edges, and other subtle boundaries.

The result is a false choice. If you train for slice questions only, the model may answer a local detection question but contradict itself across adjacent slices because it lacks volumetric consistency. If you train for volume inputs only, the model may understand gross anatomy while missing the exact local evidence that supports a diagnosis.

The paper's move. Encode slices so they retain where they sit inside the volume, add organ and region alignment signals, and use one projection module that can adapt between slice and volume inputs.

The algorithm as a flow

What it actually does

Compose neighboring slices

Group slices so the model sees a slice together with nearby slices, because local findings often extend across adjacent positions and isolated slices lose that continuity.

Add tri-axial position encoding

Attach explicit coordinates for all three scan axes so each feature knows where it lies in the volume.

Project with a hybrid module

Use a mixture-of-experts projection, which is a routing layer that sends inputs through specialized submodules, to adapt slice and volume features into a shared language-model space.

Inject organ-level supervision

Use segmentation masks and region-of-interest labels so the model learns which anatomical structure each visual pattern belongs to, because similar intensities can come from different organs.

Evaluate on unified tasks

Test one model on slice-driven detail tasks and volume-driven spatial reasoning tasks with the same evaluation framework.

What the paper changes

What the paper changes

The paper changes the visual input pipeline of a CT vision-language model. Instead of treating slices and volumes as incompatible input types, it builds a shared representation where slice features carry explicit volumetric position and organ identity. The language model then reads those enriched features through one adaptation layer.

the object it moves  =  Unified slice-volume representation with organ-aware supervision
The hidden quantity

The hidden quantity: spatial consistency across dimensions

measured quantity  =  Whether local evidence and 3D location tell the same story

The hidden quantity is cross-dimensional consistency. A model may correctly notice a lesion boundary on one slice, but if it cannot place that boundary at the right depth and relative organ position, its answer is only half correct. Likewise, a model may know the rough organ layout of the volume, but if its local evidence comes from the wrong slice, the reasoning chain breaks.

OmniCT estimates this consistency by carrying slice composition and tri-axial position into the features themselves, then reinforcing them with organ masks and region labels. That matters because the model can no longer treat similar-looking patches from different body regions as interchangeable. Their coordinates and organ context separate them.

Why it works

Why this works: preserve detail while preventing location drift

The method works because it does not let detail and structure be learned in isolation. Slice-based models are often accurate on what appears in a frame but weak on where that frame sits in the scan. OmniCT fixes that by attaching explicit three-axis position to slice-derived features. Now when the model sees a texture pattern, it also sees whether that pattern lies high or low in the scan and which lateral region it occupies.

The organ-level supervision matters because anatomical semantics are not obvious from raw intensity values alone. A bright region could belong to different tissues depending on location. Segmentation masks and region-of-interest labels tell the model which organ or lesion region a feature belongs to, so the model can tie visual evidence to anatomy rather than only to appearance. That reduces cross-organ confusion because two similar patches in different organs no longer share identical context.

The hybrid projection layer matters because slice inputs and volume-aware inputs do not need exactly the same transformation before they enter the language model. A mixture-of-experts projection lets the model route different input styles through specialized submodules, then map them into a shared space. That avoids forcing one compromise mapping for all cases, which would either blur local detail or discard volume structure.

Math after the picture

A simple view of the training objective

First in words:

The full objective combines task loss, spatial consistency loss, and organ alignment loss. One term teaches the final answer. One keeps features consistent across slices and volume coordinates. One aligns those features with anatomy.

Then the compact form:

L_total = L_task + alpha * L_spatial + beta * L_organ

Every symbol:

L_totaloverall training loss
L_taskloss for question answering or report-style task targets
L_spatialpenalty when slice features disagree with their volumetric positions
L_organpenalty when features fail to align with organ or region labels
alpha, betaweights that balance the auxiliary terms
A tiny worked example
Suppose the model correctly detects a liver lesion on one slice, but places it near the lung region in its internal representation. Task loss may stay low because the label is right, but spatial and organ losses rise because the location story is wrong.
If task loss is 0.5, spatial loss is 0.3, organ loss is 0.2, alpha is 2, and beta is 1.5, then total loss is 0.5 + 2 times 0.3 + 1.5 times 0.2 = 1.4.
Training lowers that total by keeping the lesion evidence sharp while moving it into the correct organ and volume position.

The paper uses concrete module-level losses, but this captures the design logic: answer the task while preserving 3D consistency and anatomy alignment.

What can go wrong

What can go wrong

Segmentation labels can be noisy. If organ masks are wrong or inconsistent across scanners, the model may learn false anatomical anchors because its supervision says a feature belongs to the wrong structure.
Position encoding can be mismatched across preprocessing pipelines. If slice ordering or orientation changes are not normalized correctly, tri-axial coordinates can point to the wrong body location, which breaks the spatial consistency signal.
Expert routing can collapse. A mixture-of-experts layer only helps if different experts actually specialize, because the layer is meant to give different input types different transformations. If one expert handles nearly all inputs, the adaptation layer turns back into a single bottleneck.
Done right. Standardize scan orientation, validate segmentation quality, and monitor expert usage so slice detail, 3D position, and anatomy labels remain mutually consistent.
What a runnable demo should prove

What a runnable demo should prove

Build a benchmark with paired slice questions and volume questions on the same CT studies. Train a slice-only baseline, a volume-only baseline, and OmniCT. Keep the language model backbone fixed so the comparison isolates the representation change.

The demo should include questions that require tiny local evidence, such as boundary or small lesion identification, and questions that require 3D relations, such as whether a mass crosses organ boundaries. The paper's claim holds if one model handles both sets well without a large drop on either side, because that would show slice detail and volume structure can be unified instead of traded off.

unified_score = local_task_score + global_task_score - inconsistency_penalty

The important result is not only a higher average benchmark score. It is the removal of the old split between seeing small evidence and understanding full-scan anatomy.
