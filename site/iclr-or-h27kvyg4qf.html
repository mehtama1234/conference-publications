When Foundation Models are One-Liners: Time Series Anomaly Detection

Large time-series models fail to beat simple one-liner formulas because anomalies are not harder to forecast or reconstruct.

Paper explainersAll themesTime Series & Sequential

Foundation models (large trained models that work across many tasks) promise to be good at detecting anomalies in time series (weird points in a stream of numbers over time). But researchers tested five popular time-series models and found something shocking: they perform no better than a two-line formula like moving-window variance (just how wiggly the numbers are right now). The reason is that anomalies are not actually harder to forecast or reconstruct for these models, so the whole approach is backwards.

Zero assumption version

The broken promise of bigger models

Everyone believes that if you train a model on millions of time-series examples, it learns some deep pattern about what normal looks like, and then spotting anomalies becomes easy. For anomaly detection, the common approach is: feed the model some recent history of numbers, ask it to reconstruct (predict what those same numbers should be) or forecast (predict what comes next), and measure the error. A big error means anomaly.

A beginner trying this would assume: the model has learned normal so well that it predicts normal sequences accurately, but stumbles on weird ones. Bigger models should be even better at this because they have seen more examples and learned tighter patterns. But the paper tests five popular foundation models at this task and finds they fail.

The problem. Large time-series models do not actually reconstruct or forecast anomalies worse than normal points, so error-based detection fails.

What the paper changes

What the paper changes

The paper does not propose a new model or a better formula. Instead, it rejects the entire assumption that error-based detection (reconstruction error or forecasting error) works for large models, because large models are too flexible to fail predictably on anomalies. It asks: why do we believe error should rise on anomalies? And the answer is: we should not believe it for models that generalize.

the object it moves  =  The detection assumption
The hidden quantity

The hidden quantity: reconstruction and forecast error

measured quantity  =  Prediction error magnitude

Prediction error is just the difference between what the model predicted and what actually happened. For reconstruction, it is the squared difference between input and re-predicted input. For forecasting, it is the squared difference between predicted future and actual future. The paper measures: does this error grow when the input contains an anomaly?

The paper estimates this by simply running each of the five models on thousands of normal and anomalous time series from standard benchmark datasets, recording the error in each case, and comparing the results. If error on anomalies were consistently higher, the detection would work.

Why it works

Why the error approach fails

Foundation models are trained on massive amounts of time-series data to forecast or reconstruct well on average. But average does not mean they learn a tight model of normal. Instead, they learn a smooth, flexible model that can absorb small disturbances without jumping error. When you introduce an anomaly (an outlier), the model does not necessarily predict it worse because the model is flexible enough to have learned that some sequences have outliers in them, or it learned patterns broad enough to not care.

The core mechanism is: if a large model has seen enough variation in training, it generalizes well to anomalies too. That is not a strength here. A tight, brittle model would fail on anomalies and reveal them via error. But a flexible model just adapts and says, sure, this is plausible. Meanwhile, the moving-window variance formula does not generalize; it simply measures how much the numbers are bouncing around right now. An anomaly (a sudden spike or dip) immediately looks abnormal by that local metric, because it violates the recent history.

Math after the picture

The detection equation

First in words:

Anomaly score equals the squared difference between what the model predicted and what actually happened.

Then the compact form:

error = (predicted - actual)^2

Every symbol:

predictedthe number the model guessed
actualthe true value that occurred
errorhow far the guess missed (squared so bigger misses count more)
A tiny worked example
Model predicts next value is 10.0.
Actual value is 10.5 (small normal variation).
Error = (10.0 - 10.5)^2 = 0.25.
Model predicts 10.0 again.
Actual value is 25.0 (a spike anomaly).
Error = (10.0 - 25.0)^2 = 225.
BUT if the model learned that spikes sometimes happen, it might predict 18 instead.
Then error = (18 - 25)^2 = 49, not much higher than normal.
The foundation model adapts; the one-liner variance just measures how much 25.0 differs from the recent average.

The equation is simple, but it only works if the model fails hard on anomalies. Here, the model does not.

What can go wrong

What can go wrong

Model has seen similar anomalies in training. If the foundation model trained on datasets that already included the type of anomaly, it learned them as plausible variations, not errors.
The anomaly is gradual, not sharp. A slow drift looks like a trend, not a spike. The model might learn trends from training, so error stays low.
Context window is too short. If the model only sees the anomaly point in isolation without recent normal history, it has no reference to compare against.
Done right: use local statistics. One-liners work because they measure local oddness (variance, differences) without assuming what normal should look like globally.
What a runnable demo should prove

What a runnable demo should prove

Build a dataset of time series with labeled anomalies. Run a pre-trained time-series model (e.g. Chronos) on each sequence and measure reconstruction or forecasting error. Sort sequences by error. Check: do anomalies cluster in the high-error tail? Also compute moving-window variance for each sequence. Compare the two methods by measuring true positive rate (fraction of real anomalies caught) and false positive rate (fraction of normal sequences wrongly flagged).

True positive rate = (anomalies detected) / (total anomalies); False positive rate = (normal wrongly flagged) / (total normal)

The demo makes clear that the foundation model error and the one-liner error have similar power to detect anomalies because large models generalize too well to separate normal from anomalous prediction errors, disproving the idea that bigger models learn better error thresholds.
