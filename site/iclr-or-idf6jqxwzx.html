Stronger-MAS: Multi-Agent RL for Collaborative LLMs

Teach teams of language models to work together by training them with reward signals that properly account for each agent's role and turn in the conversation.

Paper explainersAll themesAgents & Tool Use

A language model (a program that guesses the next word) can handle many tasks alone, but dividing jobs among specialized agents — one for planning, one for coding, one for logic — works better. The challenge: teaching these agents to improve together using rewards (numerical scores for good answers), because the standard training trick fails when each agent sees different starting information and takes turns.

Zero assumption version

Why training multi-agent teams is stuck

A single language model can try to do everything: write code, plan trips, solve math problems. But specialists work better — a model trained only on code writes cleaner code because its weights have learned patterns specific to code (variable names, syntax, structure); a planning model knows how to break big tasks into steps because its training included many examples of good plans. The dream: a team where the code expert and planning expert each do what they know best, then pass the result along.

To make a lone model better at a task, researchers use a technique called reinforcement learning: run the model, give it a score based on whether the answer is correct, then nudge it toward behaviors that got high scores. This works well for a single agent because the model always starts from the same starting point (the raw problem) and is always being scored on the same thing (the final answer). But in a team, each agent sees a different starting point (the earlier agents' work) and knows its role (I am the planner, I am the coder). Standard reinforcement learning assumes all agents see the same setup and start fresh — that assumption breaks in teams, because comparing the planner's performance to the coder's when they started from completely different information is like comparing a painter's work to a poet's work by one global standard.

The problem in one sentence. Standard reinforcement learning training assumes all agents face the same situation, but in teams, each agent has a different role and sees what earlier agents wrote.

The algorithm as a flow

What it actually does

Run the team of agents on a task

Planner writes a plan, coder executes it, math agent checks results.

Score each agent separately

Did the plan make sense? Was the code correct? Did math check out?

Group rewards by agent and turn

Collect all the planning-turn scores together, all coding-turn scores together, separately.

Measure how much better this run was than typical

For the planner, measure: this plan's score minus the average plan score this agent has made.

Nudge each agent toward its better runs

Retrain the planning model on planning runs that beat its own average, the coder on coding runs that beat its own average.

What the paper changes

The single thing the paper changes

The paper changes how rewards are grouped during training. Instead of lumping all agent turns together and comparing them to one global average, it creates separate reward groups: one for the planner's turns, one for the coder's turns, one for each agent. This way, each agent only competes with itself.

the object it moves  =  reward grouping scheme
The hidden quantity

The hidden quantity: relative advantage by role

measured quantity  =  turn-wise relative advantage

The paper measures a quantity called the relative advantage: the difference between this run's score and the average score when agent X took turn T before. This difference matters because it tells you whether the agent did better or worse than it usually does on that specific role, which is the key to fair training. The relative advantage is calculated by subtracting the agent's historical average from this run's score: if the agent usually scores 70 but this time scored 75, the relative advantage is positive 5; if it scored 65, the relative advantage is negative 5. A positive value means the agent found a particularly strong way to do its job, which the training system should reinforce by nudging the agent toward this behavior. A negative value means the agent's behavior was below its own typical quality, which the training system should discourage.

Standard reinforcement learning computes one global average (averaged across all agents and turns), which conflates different roles. AT-GRPO computes separate averages for each (agent, turn) pair, which isolates each agent's performance. When the planner's first turn scores 80 and its historical average is 70, the planner's relative advantage is +10. Meanwhile, the coder's first turn scores 60 with a historical average of 55, so the coder's relative advantage is +5. Standard training would wash these out because the global average might be 65, making both agents look mediocre; AT-GRPO keeps them separate so each agent sees a fair comparison against only its own past.

Why it works

Why separate-group training fixes the problem

In a team, each agent starts in a radically different state. The planner sees the raw problem; the coder sees the plan and must write code for it; the math agent sees the code output and must verify it. If you mix all their turns together and compute one average, you are averaging apples and oranges: the planner's raw-problem turns (often hard) with the coder's plan-to-code turns (often easier because the plan is clear). When an agent is below the global average only because its turn is inherently hard, the training system wrongly treats it as bad and nudges it away from that behavior.

AT-GRPO fixes this by grouping: compute one average for all planner turns, one for all coder turns, one for all math-agent turns. Now the planner competes only with itself, the coder only with itself. If the planner's turn is inherently harder, that is baked into the planner's own average, and a planner that beats its own average still gets rewarded. Each agent receives fair feedback based only on whether it did better than usual for that role, which means the training signal is honest — if the planner improved, it will be told so, rather than being unfairly downweighted because the planning role happens to be harder than coding.

Math after the picture

The equation behind the fairness

First in words:

The training update for each agent is proportional to the sum over all turns the agent took of (this turn's score minus the baseline score for that agent and turn), scaled by a learning speed constant.

Then the compact form:

update_agent = learning_rate * sum_over_turns( score_t - baseline_agent_t )

Every symbol:

score_tthe score (correctness measure) for turn t of this agent
baseline_agent_tthe historical average score for this agent on turn t
learning_ratehow much to nudge the weights; a small number like 0.01
update_agentthe change to make to this agent's weights
A tiny worked example
Planner turn: score is 75, baseline for planner-turns is 65, relative advantage is 75 - 65 = 10.
Coder turn: score is 82, baseline for coder-turns is 80, relative advantage is 82 - 80 = 2.
Math turn: score is 88, baseline for math-turns is 85, relative advantage is 88 - 85 = 3.
Total advantage sum: 10 + 2 + 3 = 15. With learning_rate 0.01, update magnitude is 0.01 * 15 = 0.15.
If the global average were 78 (mixing all three), the planner would look slightly bad (75 < 78) and the coder slightly good, contradicting reality. Separate baselines reveal the truth: planner beats its own bar, so it gets rewarded.

Each agent is rewarded only when it beats the baseline for its own role, ensuring fair training even when roles have different inherent difficulties.

What can go wrong

What can go wrong

Mismatched turn lengths. If one agent's turn produces much longer output (more tokens, i.e., words/subwords) than another, it may accumulate more errors just from length, because longer text has more chances for a word to be wrong. AT-GRPO helps by ensuring each agent is only compared to its own historical turns (not to agents with different inherent difficulties), but does not fix an underlying imbalance in the reward itself — for instance, if a 100-word plan loses 1 point per mistake while a 20-word code snippet loses 5 points per mistake, the grouping ensures each agent trains fairly within its group, but the task has built-in preference for longer-output agents.
Baseline drift. If the baseline average (historical score for that agent and turn) is computed from too few examples early in training, it may be unrepresentative. The grouping then provides false confidence. Baselines must be updated frequently and from enough data.
Reward signal design. AT-GRPO assumes the reward signal (the score for correctness) actually measures what each role should do. If the reward is noisy or does not match what each agent is supposed to improve, fair grouping will not help, because fair grouping only ensures each agent is compared to itself — it does not fix a reward that is measuring the wrong thing.
Done right: test on multi-domain tasks. Apply AT-GRPO to tasks where multiple agents with different roles take turns. Measure each role's accuracy separately to verify fair improvement — if the planner and coder improve at roughly the same rate, you are grouping fairly. Recompute baselines regularly as agents improve, because a baseline computed from early bad runs will mislead you once the agent has learned.
What a runnable demo should prove

What a runnable demo should prove

Build a simple multi-agent loop: a planning agent (given a goal, writes a step-by-step plan in plain text), a reasoning agent (given the plan, makes a logical argument or deduction), and an answer agent (given the reasoning, writes a final answer). Run this team 100 times on a mix of questions (math, logic puzzles, planning riddles). Assign a reward: 1.0 if the final answer is correct, 0.0 if not. Train both a naive baseline (one global average) and AT-GRPO (separate (agent, turn) baselines) for equal numbers of steps. After training, measure the accuracy of the planning turns only (did the plan make sense?), reasoning turns only, and answer turns only, separately. The demo must show that under AT-GRPO each agent improves its own role, whereas the naive baseline shows one agent dragging the others down due to unfair grouping.

Improvement_agent = accuracy_after_agent - accuracy_before_agent (measured separately for planning, reasoning, and answer turns)

If AT-GRPO is working, each agent's role-specific accuracy should rise, whereas naive training will show uneven gains because some roles are being unfairly penalized by the global average.
