The Fairness Hierarchy: A viewpoint from causal inference

Define fairness by deciding which causal paths from sensitive attributes may influence the prediction, then generate predictions from the corresponding counterfactual world.

Paper explainersAll themesOther

Many fairness methods add constraints to training loss or to group statistics and then call the result fair. This paper moves the definition earlier. It asks a semantic question first: when a sensitive attribute changes, through which causal paths should that change be allowed to affect the prediction, and through which paths should it be blocked? Once that choice is made, the prediction is computed from a structural causal model under the matching path-specific intervention. Different allowed path sets produce a hierarchy of fairness notions rather than a single rule.

Zero assumption version

Why fairness metrics keep colliding

Fair prediction usually starts with an observed sensitive attribute, such as race or gender, and an outcome to predict. Standard fairness criteria often disagree because they summarize different patterns in the data. One metric asks for equal error rates, another asks for equal positive rates, and another asks whether the prediction would change under a counterfactual change in the sensitive attribute.

Those disagreements usually reflect a missing causal statement. Sensitive information can affect the target through many routes. Some routes may encode discrimination that should be blocked. Other routes may reflect information the system is explicitly allowed to use. Without naming the routes, a fairness rule cannot say which influence is legitimate.

The paper therefore defines fairness through path-specific counterfactual interventions. Instead of asking only whether the prediction changes when a sensitive attribute changes, it asks which downstream edges are permitted to carry that change.

The paper in one sentence. Fairness is defined by causal path permissions: specify which effects of a sensitive attribute may pass through the graph, then predict from the counterfactual outcome pattern produced by that choice.

The algorithm as a flow

What it actually does

Specify a causal graph

Write down variables and direct causal arrows so the system can distinguish different routes from a sensitive attribute to the outcome.

Choose a fairness level

Decide which paths from each sensitive source are allowed and which are blocked, because fairness is defined through that choice.

Instantiate a structural causal model

Use structural equations, which means explicit rules for how each variable is generated from its parents, to define the full data-generating system.

Apply path-specific interventions

For blocked paths, replace the sensitive influence with a reference value while leaving allowed paths untouched.

Predict from the resulting outcome pattern

Compute the outcome pattern under that modified causal world, because the prediction itself must satisfy the chosen fairness semantics.

What the paper changes

What the paper changes

The paper changes fairness from a training constraint into a prediction semantics. The central question becomes which causal effects are allowed to enter the prediction rather than which numerical parity condition the outputs should satisfy afterward.

The hidden quantity

The hidden quantity: path-specific influence

measured quantity  =  how much each sensitive path contributes to the prediction

A sensitive attribute may affect the final prediction through several intermediate variables, and those routes can have different normative status. The important hidden quantity is therefore not the total effect alone. It is the contribution carried by each individual path or path set.

The framework recovers those contributions through counterfactual interventions that alter some paths and preserve others. Comparing predictions across those modified worlds reveals which part of the sensitive effect remains under each fairness level.

Why it works

Why a hierarchy appears naturally

Once fairness is defined at the level of paths, there is no reason to expect a single universal notion. Blocking all influence from a sensitive attribute is one extreme. Allowing all influence is the opposite extreme. Between them lie many intermediate choices that preserve some routes and suppress others.

That is why the paper describes a hierarchy. Each level corresponds to a different policy about permissible influence. A predictor built for one level can differ from a predictor built for another even if both use the same data and the same causal graph, because their interventions alter different parts of the structural equations.

This approach also clarifies why metric-based fairness criteria conflict. Two metrics may disagree simply because they are implicitly endorsing different path permissions. The causal framework makes those permissions explicit and then derives the prediction that matches them.

The mechanism only works if prediction is generated from the structural causal model itself. If one merely adds a fairness penalty after training, the system may still rely on blocked paths internally. Path-specific counterfactual prediction avoids that mismatch because the blocked effects are removed in the generative procedure that produces the prediction.

The prediction target

First in words:

The fair prediction is the expected outcome under a path-specific intervention that keeps allowed paths factual and blocks forbidden paths.

Then the compact form:

fair_pred(x) = E[Y_{pi}(s_allowed = s, s_blocked = s_ref) | X = x]

A tiny worked example
Suppose hiring score Y depends on interview score and school prestige.
Sensitive attribute S affects school prestige through historical access and also affects an interviewer bias variable directly.
A fairness rule may allow the path through school prestige but block the path through interviewer bias.
The path-specific prediction keeps S factual on the allowed school path and replaces S with a reference value on the bias path.
The resulting predicted score answers a precise question: what would the outcome be if only the allowed sensitive effects were active?

Different choices of allowed and blocked paths produce different fairness levels, which is why the paper frames fairness as a hierarchy.

What can go wrong

What can go wrong

The causal graph may be disputed. If the graph omits an important variable or draws the wrong direction for an effect, the chosen path permissions may not correspond to the real sources of unfairness.
Reference values can encode normative choices. Blocked paths need a reference intervention value, and different references can change the resulting prediction because they define the counterfactual world differently.
Some path sets may be hard to identify from data. Even with the right graph, the data may not support precise estimation of every path-specific effect, which means the semantic definition can be cleaner than the estimable procedure.
Where the design is strongest. The framework is strongest when stakeholders can articulate which causal routes are acceptable, because the method turns that policy statement directly into the prediction rule.
What a runnable demo should prove

What a runnable demo should prove

Build a small causal-graph editor for a decision problem such as lending or hiring. Let the user specify sensitive nodes, intermediate variables, and an outcome. Then let the user click each outgoing path from the sensitive nodes to mark it as allowed or blocked.

The demo should show three outputs side by side: the factual prediction, the counterfactual prediction under the chosen fairness level, and the contribution removed by blocked paths. It should also let the user compare several fairness levels on the same case. That matters because the paper's main contribution is not one fairness score; it is the claim that fairness notions form an ordered family defined by path permissions.

removed_influence = factual_prediction - fair_prediction

The demo must make clear that fairness changes when the allowed path set changes, because the prediction semantics itself changes.
