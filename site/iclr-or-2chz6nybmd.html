Helix: Evolutionary Reinforcement Learning for Open-Ended Problem Solving

When an LLM tries to solve hard open-ended problems, feed it not one answer to improve, but a diverse crowd of solutions—pick the best and most different ones each round, then push the model to find better ones.

Paper explainersAll themesLLMs & Foundation Models

Large language models can reason through complex problems, but exploring huge solution spaces is slow and models tend to repeat the same kinds of wrong answers. This paper combines evolutionary algorithms (a classic technique: keep the best, add variety, evolve forward) with reinforcement learning (teaching a model to improve through reward signals). The method maintains a crowd of diverse candidate solutions and teaches the model to generate better ones by rewarding it when its solutions make the cut, producing answers that beat GPT-4o on real benchmarks.

Why open-ended problem solving is stuck

Open-ended scientific problems—like packing circles tightly, or finding the lowest point in a complex curve—have huge solution spaces. Naive approaches either get stuck in one groove (fine-tuning a model on past solutions teaches it to repeat familiar ideas) or take forever to explore.

If you ask a model to solve one problem and then nudge it to improve, it explores slowly because the model only learns from attempts on that one problem. It tends to try variations on the same failed approach, like someone lost in a forest always turning left, never backtracking to try a completely different path. The model gets good at small tweaks to one idea but never discovers that a completely different strategy works better, because it only sees the space around one starting point.

In one sentence. The model explores like a single lost hiker, not like a scout team fanning out to find what works.

The algorithm as a flow

What it actually does

Sample a batch

Ask the model to generate many candidate solutions to the current problem.

Score each solution

Run each solution; measure reward (does it work?) and compute how different it is from all others.

Pareto filtering

Use NSGA-II algorithm: keep solutions that rank high on reward or that rank high on difference from others. Discard boring failures.

Show the crowd to the model

Feed the model the diverse set of solutions plus their scores as context for next round.

Reinforce better generation

Use RL (reinforcement learning) signal to push model to generate higher-reward solutions in future.

What the paper changes

The one thing the paper changes

Instead of polishing one solution, the paper maintains a diverse pool and teaches the model to generate from that pool rather than starting from scratch.

the object it moves  =  the candidate pool composition
The hidden quantity

Distance from neighbors

measured quantity  =  solution isolation score

The paper measures how far each solution sits from all other solutions. Not just structurally different code, but semantically different: solutions that solve the problem in fundamentally different ways sit far apart in the space of all possible solutions.

To compute this, the paper first encodes each solution into an embedding (a list of numbers that captures its meaning, produced by a pre-trained language model). Then it checks the K-Nearest Neighbors: is this solution sitting close to many others, or is it isolated? Isolated solutions earn high scores because they represent unexplored territory.

Why it works

Why feeding the model a diverse crowd works

The model learns from examples. If you show it ten different ways people tried and failed, it learns what NOT to do. If you show it the best attempt plus nine different bad attempts, it learns the shape of the problem—the regions that work and those that don't. With only one solution to learn from, the model sees too little and generalizes poorly.

The evolutionary part enforces diversity: if two solutions are too similar and both are mediocre, drop one. This prevents the model from learning that 'try the same thing nine times' is the strategy. Instead, the model sees: good solutions are rewarded, isolated solutions are kept even if imperfect, and copying a neighbor gets your solution deleted next round because NSGA-II replaces copies with unique attempts.

Reinforcement learning then nudges the model: every time it generates a solution, check if it made the cut into the diverse pool. If yes, increase the probability of that kind of generation. If no, decrease it. Over many rounds, the model specializes in generating solutions that are both rewarding and isolated, because the selection rule favors both qualities.

Math after the picture

The selection rule

First in words:

A solution is kept if no other solution beats it (is both more rewarding AND more novel). This is Pareto dominance: solution A dominates B if reward of A is at least as high as B AND diversity of A is at least as high as B, with at least one being strictly higher.

Then the compact form:

A dominates B if R(A) >= R(B) and Div(A) >= Div(B) with at least one strict

Every symbol:

R(s)reward score: how well solution s solves the problem (higher is better)
Div(s)isolation score: how far solution s sits from others in the embedding space (higher means more isolated, better)
dominatessolution A survives if no other solution is simultaneously better on both rewards and isolation
Tiny worked example
Solution A: reward 85, isolation 60. Solution B: reward 80, isolation 65.
Does A dominate B? A has higher reward (85 > 80) but lower isolation (60 < 65). No dominance.
Does B dominate A? B has higher isolation (65 > 60) but lower reward (80 < 85). No dominance.
Conclusion: both A and B survive the cut. You keep the high-reward one and the isolated one. Next round the RL signal reinforces both patterns because both made it through selection.

NSGA-II's Pareto front captures the frontier of solutions that are best-in-class on at least one objective, preventing the method from collapsing to a single type of solution.

What can go wrong

Isolation measure is only as good as the embedding model. If the pre-trained embedding model is weak, it mislabels truly different solutions as similar to existing ones. The method then throws away unique ideas by mistake because the isolation score wrongly says they sit close to neighbors.
Computational cost scales with population size. Keeping hundreds of solutions and scoring all of them each round is expensive. If the compute budget is tiny, the population cannot stay large enough to explore many paths, so you collapse back to a few variations on the same idea.
Reward function must be well-defined. For circle packing, you can measure how many circles fit. For fuzzy problems (design a molecule for a property you can barely test), defining what counts as better is hard because good and bad attempts look similar. When the reward signal is weak or noisy, the RL reinforces solutions that scored high by random chance; the model then copies those patterns because the reward looked good, even though it was just luck—this is called overfitting to noise.
Done right. Use a strong embedding model, allocate compute for a large population, and carefully define rewards for your problem class with signal that clearly distinguishes good attempts from bad ones.
What a runnable demo should prove

What a runnable demo should prove

Implement circle packing: place circles inside a square to maximize the sum of their radii without overlap. Write a reward function (sum of radii). Generate random circle configurations, encode them into embeddings, run NSGA-II selection, and collect the top solutions. Use an LLM to generate new configurations, train it with RL to favor selected ones. Run for 50 rounds, track the reward and diversity of the population each round.

improvement = (final_reward - initial_reward) / initial_reward; population_diversity = average pairwise embedding distance

If the demo works, you will see reward climb and diversity plateau (not collapse to repetition). The crowd of solutions will grow more rewarding while staying diverse.
