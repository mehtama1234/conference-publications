GNN Explanations that do not Explain

Some graph neural networks can achieve perfect accuracy while producing explanations totally unrelated to their actual reasoning, and most existing audits miss this.

Paper explainersAll themesInterpretability

A graph neural network is a model that reads a network of connected things (like a social network or molecular structure) and makes predictions about them. Many researchers have built versions that promise to explain their reasoning: they point to which connections mattered most. But this work shows a devastating flaw: a network can be right about the answer while pointing to completely wrong reasons for that answer, and the tools designed to catch this lie often miss it.

Zero assumption version

Why you cannot trust explanations from a graph neural network

A graph neural network reads a network of things and their connections, then makes a prediction. For example, it might read a social network and predict whether a user is trustworthy, or read a molecule's atoms and their bonds and predict whether it will dissolve in water.

Engineers wanted to understand how the network decided. So they built self-explainable versions that not only predict but also highlight which connections they say mattered most. If a network predicts a user is trustworthy and points to connections to verified accounts, we feel confidence. But a naive builder might hope: if the model is accurate, its explanation must be honest.

This hope breaks. A network can be completely right about the answer—getting 99% correct—while pointing to connections that have nothing to do with how it actually decided. It is like a doctor diagnosing your illness correctly but citing a symptom you do not have. The diagnosis is right; the reasoning is fiction.

The problem in one sentence. Graph neural networks can produce perfect predictions while their explanations are completely unrelated to their actual reasoning.

What it actually does

Self-explainable networks promise two things

A prediction and a ranked list of which connections mattered.

The core flaw: they can decouple

The network learns to predict correctly using one set of connections but points to a different set in its explanation.

This is not just poor calibration

Even when the network is absolutely accurate, the explanation can be completely false.

Existing faithfulness metrics miss this

They check whether the explanation helps the model predict by testing if accuracy drops when you remove highlighted connections. But a network that already solved the task another way passes this test even though its explanation is false.

The paper proposes a better audit

A new metric that catches degenerate explanations by directly testing whether the network relies on what it highlights.

What the paper changes

The one thing that changes

The paper introduces a new faithfulness metric: a way to audit whether a network's explanation is truthful. Most existing metrics treat an explanation as good if removing those connections hurts the network's accuracy. But a degenerate explanation passes that test while being false. The new metric directly tests whether the network's internal computations actually depend on the highlighted connections, not just whether the explanation correlates with the output.

the object it moves  =  faithfulness metric
The hidden quantity

The hidden quantity: genuine dependence

measured quantity  =  whether the network actually uses highlighted connections

The paper names a quantity that previous audits ignored: whether the network's internal reasoning actually depends on the connections it highlights. This is different from asking whether the explanation is useful for prediction. A network could highlight useless connections, and those connections could be removed without hurting accuracy, if the network already solved the task some other way.

The paper measures this by checking whether the network's actual computations change when you remove the highlighted connections. If the computation stays the same, the explanation was fiction. If it changes dramatically, the network relied on what it said it relied on.

Why it works

Why the metric works: catching degenerate explanations

A degenerate explanation is one where the network points to connection X as important but secretly solved the problem without X. The old audits ask: if we delete X, does accuracy drop? A degenerate network says no, so it passes. But the new metric asks a deeper question: when we remove X, does the network's reasoning change?

The mechanism is this: the network has internal layers of representations—intermediate computations that transform the input toward the final answer. If the network truly used connection X, removing it will change those internal representations. If the network is lying and X was never used, the representations stay the same. By comparing the representations before and after removal, the metric catches the lie. It is like asking a person to explain their reasoning, then checking whether that reasoning actually changed their answer, not just whether the answer remains right when you take away one piece.

Math after the picture

The faithfulness equation

First in words:

faithfulness equals one minus the similarity between original representations and representations after removing the highlighted connections, averaged over all data points

Then the compact form:

F = 1 - mean(sim(h_orig, h_removed)) where h_orig is the network's internal representation before removal and h_removed is after removal

Every symbol:

Ffaithfulness score, from 0 to 1; high means the explanation is real
h_origthe network's internal representation (a vector of numbers encoding what it learned) when the connections are present
h_removedthe same representation recomputed after removing the highlighted connections
simsimilarity between two vectors, like asking how much they point in the same direction
meanaverage over all examples in the dataset
A tiny worked example
Example 1: Original representation is [0.8, 0.9, 0.7]. After removing highlighted connections: [0.1, 0.2, 0.1]. Similarity = 0.1 (they point in very different directions). Faithfulness = 1 - 0.1 = 0.9 (the explanation was real).
Example 2: Original representation is [0.8, 0.9, 0.7]. After removing highlighted connections: [0.79, 0.88, 0.71]. Similarity = 0.999 (almost identical). Faithfulness = 1 - 0.999 = 0.001 (the explanation was a lie; removing those connections barely changed anything).
High faithfulness means the network truly depended on what it claimed to depend on. Low faithfulness means the explanation was degenerate.

The metric tests whether the network's actual reasoning process depended on the connections it highlighted, by checking if internal representations change when those connections are removed.

What can go wrong

What can go wrong

Malicious attack. An attacker can intentionally build a network that hides its use of sensitive information. It predicts correctly using a person's race, but its explanation points to irrelevant features, hiding discrimination. The new metric catches this by showing the explanation is unfaithful.
Natural degenerate explanations. Even without an attacker, a network trained on a benign dataset can stumble into this trap: it finds a shortcut to the right answer but learns a bogus explanation. The paper shows this happens often in practice.
Metric requires access to internal representations. Unlike simpler audits, this metric needs to peek inside the network at its intermediate layers. If you only have a black-box prediction, you cannot use it.
Metric is designed precisely for this flaw. Once you know to look for degenerate explanations and you have a metric that catches them, you can audit networks reliably, making deception much harder.
What a runnable demo should prove

What a runnable demo should prove

Build a small graph neural network on a synthetic or real dataset (like citation networks or molecular graphs). Train a self-explainable version. Then create a malicious variant: train it to solve the task correctly but force it to highlight the wrong connections. Run both the old faithfulness metric and the new one. The demo must show that the old metric thinks both networks are equally faithful, while the new metric catches the malicious one and rates it as unfaithful, because when you remove the highlighted connections from the malicious network, its internal representations barely change, proving it never used those connections to decide.

faithfulness = 1 - mean(cosine_similarity(original_repr, removed_repr)) where lower similarity = higher faithfulness (explanation was real)

The demo must make it impossible to miss: a network can be right and lying at the same time, and only the new metric catches the lie.
