GNN Explanations that do not Explain

Self-explaining graph neural networks can output relevance scores that are completely unrelated to how they actually predict, fooling standard auditing tests.

Paper explainersAll themesInterpretability

Graph neural networks that claim to explain themselves by highlighting important nodes (via relevance scores or attention weights, which are weights that decide how much each node influences the result) are used everywhere for high-stakes decisions. But this paper shows a shocking failure: the explanations can be unambiguously unrelated to how the model actually infers its predictions. The attack is simple: an attacker can train the model to produce fake explanations while keeping the prediction accuracy perfect. Standard faithfulness tests fail to catch this lie. The paper introduces a new audit method that reliably detects when explanations are degenerate.

Zero assumption version

Explanations can lie while predictions stay right

A graph neural network (a model that reads networks of connected nodes) can be trained to output relevance scores — which nodes matter for a given prediction. These are treated as explanations: if node 5 gets score 0.9, we say the model relied on node 5. In sensitive applications (medicine, hiring, credit), regulators and engineers assume these scores are truthful: they reflect how the model actually reasons.

A beginner's intuition: if I train a model to predict accurately AND to output high scores for the nodes it uses, the scores must reflect the real reasoning. But this is wrong. It is possible to train a model that predicts perfectly while assigning high scores to completely irrelevant nodes. The model can even achieve optimal loss (zero error) while its explanations are unambiguously unrelated to how it infers. The standard auditing tests (faithfulness metrics) fail to detect this.

In one sentence. A graph neural network can achieve perfect accuracy while its explanations (relevance scores) point to nodes it never actually uses.

What the paper changes

The object: explanation fidelity

The paper does not change the model weights or how predictions are computed. It changes what we measure: not just whether explanations are sparse, but whether they are honest. It shifts the audit target from explanations that exist to explanations that matter.

the object it moves  =  faithfulness auditing
The hidden quantity

The hidden quantity: explanation-prediction coupling

measured quantity  =  whether explanations control predictions

Standard metrics ask: are the explanations sparse or do they highlight important features? They miss the real question: does the model actually use the highlighted nodes for its prediction? If you mask the high-scoring nodes and the prediction changes, the explanation is honest. If you mask them and the prediction stays the same (or changes the wrong way), the explanation is a lie. The paper measures this coupling via a new metric called EST (Explanation Sufficiency Test): given a proposed explanation (which nodes matter), an attacker tries to predict the class using ONLY those nodes, without access to the model's internal reasoning. If the attacker fails, the explanation is real (the model actually uses those nodes). If the attacker succeeds, the model was hiding something else.

EST works by quantifying rejection ratios: for each explanation, it checks if a surrogate model trained only on the highlighted nodes can achieve high accuracy. If the surrogate fails while the original model succeeds, the original explanation is degenerate.

Why it works

Why degenerate explanations can emerge and persist

A graph neural network learns by adjusting its weights to minimize a loss (an error measure). If trained with TWO losses simultaneously — one for classification accuracy and one for matching a fake explanation — the model faces two conflicting signals. In principle, it should fail at both. But here is the trap: the model has many paths through its weights. Because the model is a composition of layers (each layer reads the previous layer's output and transforms it), the early layers can compute one representation of the graph, and later layers can independently extract a different representation. One representation can feed into the actual prediction circuit; another can feed into the explanation-output circuit. The two paths share the same weights initially, but during training each learns to ignore the other path's information, because the losses do not require them to be connected. The original training objective allows this split because neither loss alone requires the explanation to be based on the prediction—they are scored independently.

Faithfulness metrics like SUFF (Sufficiency) ask: if I remove the high-scoring nodes from the input graph, does the model's prediction change? But this test is incomplete, because the model learned to ignore the explanation during prediction. An attacker can binarize the scores aggressively (threshold at 0.9 for true, 0.1 for false), penalizing uncertain scores, and still fool SUFF. The model outputs confident scores for its fake explanation while achieving zero loss because the prediction circuit never relied on the explanation in the first place. SUFF passes the fake explanation because masking the high-scoring nodes does not hurt the prediction—the prediction was never using them. SUFF interprets this passively: it sees confident scores and concludes they must be relevant. But in fact it is evidence of betrayal. The gap is semantic: SUFF measures whether the explanation looks important, but it should measure whether the model actually used it. A split pathway means the model is lying—it outputs confident scores for nodes it never routes through.

Math after the picture

The training objective that creates the split

First in words:

total loss equals classification loss plus lambda times explanation loss; explanation loss penalizes relevance scores that deviate from the fake target; thresholds binarize uncertain scores

Then the compact form:

L_total = L_classification + lambda * L_explanation; L_explanation = sum over nodes of (binarize(score, class) - target_class(node))^2

Every symbol:

L_classificationloss from wrong predictions (e.g., cross-entropy)
L_explanationloss from explanation scores not matching the attacker's fake target
lambdaweight: how strongly to enforce the fake explanation during training
scorethe model's output relevance score for a node, range 0 to 1
binarize(score, class)threshold score: 0.9 for nodes supposed to matter, 0.1 for nodes supposed to be irrelevant
target_class(node)the attacker's fake explanation: 1 if this node should be highlighted for this class, 0 otherwise
A tiny worked example
Node A: belongs to fake explanation (target = 1). Model outputs score 0.95. Binarized to 1. Loss = (1-1)^2 = 0.
Node B: not in fake explanation (target = 0). Model outputs score 0.08. Binarized to 0. Loss = (0-0)^2 = 0.
Node C: not in fake explanation but model outputs score 0.55 (uncertain). Binarized to 0. Loss = (0-0)^2 = 0.
Node D: in fake explanation but model outputs score 0.12 (uncertain). Binarized to 0. Loss = (0-1)^2 = 1. Strong penalty.
With lambda = 0.5, total explanation loss penalty = 0 + 0 + 0 + 0.5*1 = 0.5. Model is nudged to flip Node D's score above 0.9.

The objective does not require the model to actually use the explanation for prediction—only to output high-confidence scores that match the attacker's target. The model learns to satisfy both losses by splitting its reasoning: one hidden path for correct predictions, one visible path for fake explanations.

What can go wrong

What can go wrong

Attacks can hide sensitive attributes. An attacker can train a model that appears to avoid a sensitive feature (e.g., gender) in its explanation while secretly using it for prediction. This is especially dangerous in domains like hiring or lending where regulators assume explanations are honest.
Degenerate explanations emerge naturally without malice. Even without an attacker, standard training can produce unintentionally degenerate explanations if the model finds a shortcut path that achieves high accuracy while the explanation component learns something else.
EST requires access to the model's learned representations. EST trains a surrogate model on the highlighted nodes. If the original model's representation is not accessible (e.g., a black box), this approach may require additional data or architectural assumptions.
Done right: audits combined. Use EST alongside other tests. Check both sparsity (are there few high scores?), sufficiency (does masking hurt?), and the new coupling test (can a surrogate model trained on only those nodes match the prediction?). Together they form a more complete audit.
What a runnable demo should prove

What a runnable demo should prove

Train a graph neural network on a simple classification task (e.g., predicting if a molecule is toxic based on its atoms and bonds). First, train it normally and compute its explanation scores for each atom. Then, on the same data, train a second version with an adversarial loss that pushes the explanation scores toward a different set of atoms (the attacker's fake target). Measure both versions with the old SUFF metric and EST. The honest model should pass both; the degenerate model should pass SUFF but fail EST. This proves that EST catches failures the old metrics miss.

rejection ratio (EST) = fraction of test inputs where a surrogate model trained on highlighted nodes fails to match original prediction; faithfulness = 1 - rejection ratio

A degenerate explanation should yield rejection ratio close to 1 (surrogate fails on most inputs), proving the original model was not actually using the highlighted nodes for its predictions.
