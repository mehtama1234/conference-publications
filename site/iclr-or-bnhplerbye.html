Score-based Greedy Search for Structure Identification of Partially Observed Linear Causal Models

When some causes are hidden, ordinary causal search methods can break after one wrong test. This paper replaces that chain of tests with a scored greedy search over graph classes that can include unobserved causes.

Paper explainersAll themesOther

Causal discovery tries to recover which variables directly affect which others. The hard case is partial observation: some causes are hidden and never measured. Many existing methods use long chains of conditional-independence tests. That can fail because one mistaken test early in the chain can distort many later decisions. This paper takes a score-based route instead. It defines a model family that can include hidden causes and then builds a greedy search procedure, LGES, that moves through equivalence classes of graphs using well-defined local operators.

Zero assumption version

Why hidden causes make structure recovery hard

Suppose ice cream sales and sunburn both rise together. A naive system might say ice cream causes sunburn. The real cause is temperature, which may be hidden from the data. Partial observation creates exactly this problem: some important variables are missing.

Constraint-based methods try to solve it by asking many conditional-independence questions. But each question is a statistical test with noise. One error can trigger a bad edge decision, and later steps may build on that mistake.

A score-based search could be more stable because it compares whole candidate structures instead of making many one-off decisions. The obstacle is that hidden causes make the search space harder to define and search.

Core move. The paper defines a graph family that can represent hidden causes and then searches that space greedily with a score, so decisions are judged by overall fit instead of a fragile chain of tests.

The algorithm as a flow

What it actually does

Choose a graph family with hidden causes.

Use the paper's generalized factor-style model so partially observed linear systems can still be represented.

Assign a score to each candidate class.

The score rewards structures that explain the observed data well while accounting for model size.

Start from an initial graph class.

LGES begins from a simple candidate and evaluates legal local moves.

Apply the best local move.

At each step, add, remove, or redirect an edge pattern when that move improves the score, because the search treats higher-scoring nearby graph classes as more plausible explanations of the data.

Stop when no move helps.

The final result is a high-scoring equivalence class that represents the recovered causal structure up to unavoidable ambiguity.

What the paper changes

What the paper changes

The paper changes the search strategy for partially observed linear causal discovery. Instead of relying on chains of tests, it introduces the first greedy score-based search with identifiability guarantees for this setting.

the object it moves  =  the search procedure for causal structure with hidden causes
The hidden quantity

The hidden quantity

measured quantity  =  the score gap between the true graph class and nearby wrong graph classes

The hidden quantity is the score gap. If the true graph class scores only barely higher than a wrong nearby class, greedy search can get confused by finite-sample noise. If the gap is larger, the right local moves become easier to identify.

This matters because LGES does not inspect every possible graph. It depends on local score comparisons. The theory says that, under the model assumptions and enough data, the true graph class wins those comparisons consistently.

Why it works

Why score-based greedy search can beat long test chains

A long chain of tests makes many brittle yes-or-no decisions. Each test uses only a narrow slice of evidence. If one test is wrong, later steps may inherit the damage. A score-based search reduces that exposure because each move is judged by a fuller fit to the data.

LGES still uses local steps, but those steps are tied to a graph family with proven identifiability properties. That matters because the score is not wandering blindly through arbitrary graphs. It moves through a space where local improvements line up with the true structure under the paper's assumptions.

Search for the highest-scoring equivalence class

First in words:

Each candidate graph class receives a score from the observed data. LGES repeatedly chooses a legal local move that raises the score until no improving move remains.

Then the compact form:

current_class <- argmax over legal_neighbor_classes of score(neighbor_class), repeated until score cannot increase

Every symbol:

current_classthe graph class currently under consideration
legal_neighbor_classesthe graph classes reachable by one allowed local move
scorethe model-selection score computed from the observed data
argmaxchoose the option with the highest score
A tiny worked example
Suppose the current class scores 120.
Adding one edge gives a new class with score 126.
Redirecting an edge gives score 123.
Deleting an edge gives score 118.
LGES takes the edge addition because 126 is the best local improvement, then repeats from there.

The real method uses graph-class operators tailored to hidden-variable structure, but the search idea is exactly this local score ascent.

What can go wrong

What can go wrong

The model assumptions may be wrong. If the data are far from the paper's partially observed linear setting, the score may favor the wrong class because the search is only as good as the model family it assumes.
The sample size may be too small. With little data, local score differences can be noisy, so a greedy step may choose the wrong neighbor because the true score gap is hidden by estimation error.
Greedy search can still face flat regions. If many neighboring classes receive nearly equal scores, the method may stop at a local plateau because no single move looks clearly superior.
Done right. The method works when the model family is appropriate and the score gap is clear enough, because then local improvements consistently point toward the true graph class.
What a runnable demo should prove

What a runnable demo should prove

Generate linear causal data with a few hidden causes and compare LGES against a constraint-based baseline. Increase the sample size and record how often each method recovers the correct equivalence class or its adjacency pattern.

The demo should also track how often an early mistaken test in the baseline leads to later edge errors, because the paper's claim is that score-based search reduces this propagation failure.

recovery_rate = correct_runs / total_runs

The main result should be higher recovery as data grow, together with fewer cascaded mistakes from single local errors, because that is the practical reason to use score-based search here.
