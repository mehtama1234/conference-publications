Making models smaller and faster

These papers shrink neural networks and reduce computation by removing unneeded weights, simplifying math, or using lower precision numbers while keeping the model smart.

All themesField mapMathematicsAll explainers
What this is

The straightforward idea: not all weights matter equally. A neural network with one million weights might be able to throw away half of them and barely lose any accuracy. These papers figure out which weights are least important, then remove them. Some look at which weights are closest to zero. Others measure how much each weight actually changes the output. Once you remove them, the network is smaller, uses less memory, and runs faster — because there is literally less math to do.

The tricky part is that removing weights is not smooth. If you just cut out the weak ones, you often get big gaps in accuracy. So researchers do this gradually, or they retrain the network a little bit after pruning to let the remaining weights learn to compensate. Another angle is quantization: instead of using full-precision numbers (which take lots of memory), use smaller numbers — fewer bits — that take less space. An 8-bit number is half the size of a 16-bit number, which cuts memory in half. The catch is that smaller numbers cannot hold as much detail, so you have to be clever about which layers get the aggressive cuts.

A third direction combines both: start with a large network, train it, prune it, quantize it, and sometimes add clever tricks like knowledge distillation — having a smaller network learn from a larger one to capture its knowledge without the bulk. The papers in this subtheme measure speed and accuracy against each other, finding the right tradeoffs for different devices and tasks.

How the work breaks down

Making models smaller and faster splits into five main directions because different parts of the model have different structure. Pruning strategies remove unneeded weights and the patterns that decide which inputs connect to which outputs—this works because not all weights contribute equally to the answer. Approaches that use fewer bits to store numbers (so a weight takes 4 bits instead of 32) work because most values are clustered near a few common numbers. Methods where smaller models learn from larger ones compress structure that's already been learned. Specialized designs for running models quickly like efficient ways to store cached data and generate one output step at a time work because much of the cached data repeats or doesn't affect the final answer. Combinations that mix pruning with bit-reduction achieve maximum shrinking because they address complementary inefficiencies in how models are organized.

Structured pruning for language models

Large language models contain billions of weights, most of which do little work. Structured pruning removes entire groups of weights at once, like cutting out whole rows or columns rather than scattered individual weights. This matters because if you remove weights scattered randomly, the machine can't speed up execution—it still has to check every position. But if you remove them in blocks, the machine can skip whole sections of math.

ARMOR (“ARMOR: High-Performance Semi-Structured Pruning via Adaptive”) tackles the 2:4 pruning pattern used in new GPUs: for every 4 weights in a group, exactly 2 must be kept. Unlike most pruning methods that just keep weights with the largest absolute values, ARMOR breaks down the weight structure into simpler parts (factorization), then removes weights based on that simpler structure. Breaking structure into parts helps because some small weights only appear small due to numerical cancellation—they actually matter for the model's logic. MaskPro (“MaskPro: Linear-Space Probabilistic Learning for Strict”) uses probabilistic learning to assign which weights in each block should be removed, with good scalability and holds performance well because it adapts to each block's data rather than using one rule for all. Reassessing Layer Pruning (“Reassessing Layer Pruning in LLMs: New”) found that existing layer-pruning methods don't always compare fairly—the paper proposes better methods that exceed previous best results by 5–17% on Llama models by fixing the comparison methodology. Learning Semi-Structured Sparsity (“Learning Semi-Structured Sparsity for LLMs via”) uses a special network that learns which pattern of sparse weights works best based on the input, outperforming fixed patterns like 2:4 because the optimal pattern varies by model and task. Prune Redundancy, Preserve Essence (“Prune Redundancy, Preserve Essence: Vision Token”) removes vision tokens in multimodal models by combining importance scoring with diversity—keeping tokens that both matter and represent different information so the model doesn't collapse to one repeated token. Chain-of-Thought Reconstruction (“Reasoning Models Can be Accurately Pruned”) works on reasoning models by reconstructing the intermediate thinking steps during pruning, not just the final output, which is harder but more accurate because reasoning requires preserving the chain of logic. SubspacePath Pruner (“SubspacePath Pruner: Inference-time Pruning via Probe-based”) specializes at running time: instead of pruning once during training, it adapts which weights to use based on the input, achieving both speedup and better accuracy on diverse tasks because different inputs need different weights.

These papers represent a shift from one-size-fits-all pruning toward methods that adapt to model structure (factorization), to hardware patterns (2:4 spacing), to context (via hypernetworks), and even to the task at hand (runtime-adaptive pruning). The pattern holds because different inputs and different model regions have different pruning needs, so methods that learn what to prune where outperform fixed decisions.

Bit-reduction for fast running

Quantization shrinks numbers: instead of storing weights as full-precision floats (32 bits), store them in 4, 2, or even 1 bit. This cuts memory by 8x or 16x, and lets newer GPUs with special hardware for low-bit math run models much faster because the hardware can process these narrow numbers in parallel. The challenge is that fewer bits means less precision—you can't store as many different values, so you have to be clever about which values matter most to avoid losing accuracy.

LogART (“LogART: Pushing the Limit of Efficient”) uses logarithmic scales for bit-reduction: instead of evenly spaced numbers from -1 to 1, use powers of 2 (like 1, 2, 4, 8). This matches how real neuron outputs actually spread across neural networks, improving accuracy at ultra-low bitwidths because most values cluster near a few powers rather than spreading uniformly. WSVD (“WSVD: Weighted Low-Rank Approximation for Fast”) bit-reduces vision-language models by first breaking down the weight structure into simpler parts (singular value decomposition), then reduces bits on those simpler parts because simple parts have less variation and tolerate fewer bits. Why Low-Precision Transformer Training Fails (“Why Low-Precision Transformer Training Fails: An”) identifies a specific bug: when you train with fewer bits, rounding errors pile up unevenly in the connection-pattern layer (the part that decides which earlier outputs feed into later ones) because those weights multiply and amplify small errors. The fix is a tiny bias correction that stabilizes training by preventing runaway error accumulation. Attn-QAT (“Attn-QAT: 4-Bit Attention With Quantization-Aware Training”) reduces connection-pattern weight bits to 4 using awareness-trained bit-reduction, where you simulate the bit-reduction during training so the weights learn to work better with fewer bits because they adapt their values to be bit-reduction-friendly. Channel-Aware Mixed-Precision (“Channel-Aware Mixed-Precision Quantization for Efficient Long-Context”) uses different bit-widths for different channels: some channels get 8 bits, others get 4, based on how sensitive they are to bit-reduction because some channels amplify small errors more than others. FPTQuant (“FPTQuant: Function-Preserving Transforms for LLM Quantization”) avoids custom machine code entirely, using a mathematical transformation called function-preserving to enable 4-bit reduction with 3.9x speedup in standard hardware by ensuring the transformation doesn't change the function computed. Improving Block-Wise LLM Quantization (“Improving Block-Wise LLM Quantization by 4-bit”) proposes BOF4—a block-wise format that reduces bit-reduction error compared to older NF4 formats while keeping mixed-bit strategies efficient because different blocks need different number representations. SHARP-Q (“SHARP-Q: Spectral Hessian Alignment and Rectification”) aligns the reduced model's curvature (via Hessian) to the original model's, enabling uniform bit-scales to outperform non-uniform designs even at 2-bit precision because curvature alignment prevents sharp regions from losing too much information. TwinQuant (“TwinQuant: Learnable Subspace Decomposition for 4-Bit”) splits weights into multiple simpler low-rank spaces, then reduces bits on each independently—this flexibility helps preserve information at 4 bits because each space can be quantized in the way it needs. WaterSIC (“WaterSIC: Information-Theoretically (Near) Optimal \\Linear Layer”) uses information theory to set bit-reduction thresholds optimally, staying near the theoretical limit of what's possible at each bit-width because information theory tells us the minimum loss for any bit-reduction scheme.

The progression moves from simple bit-reduction to designs that match how numbers actually spread (logarithmic, mixed-bit) to training that anticipates bit-reduction (awareness-trained) to designs that respect different parts of the model (channel, layer-wise, subspace) to theory-guided (information-optimal). Each adds a layer of sophistication to handle the fundamental tradeoff between memory and accuracy.

Knowledge distillation and model compression

Knowledge distillation teaches a small model to mimic a large one. The small model learns not just to produce the right answers, but to reproduce the large model's internal confidence patterns—the shape of its output distributions across possible answers. This sounds inefficient (why not just train small from scratch?), but it works: the large model has already learned structure that the small model can reuse, compressing years of training into months.

DTO-KD (“DTO-KD: Dynamic Trade-off Optimization for Effective”) improves the core distillation loss by dynamically adjusting how much to focus on hard examples vs. easy ones during training, outperforming fixed weighting schemes because different stages of training benefit from different balances between easy and hard. Distillation of Large Language Models via Concrete Score Matching (“Distillation of Large Language Models via”) replaces the usual KL divergence loss with score matching—a technique from diffusion models that compares probability distributions differently, gaining both accuracy and diversity in the distilled model because score matching better captures distribution shape than KL. Boomerang Distillation (“Boomerang Distillation Enables Zero-Shot Model Size”) enables zero-shot model interpolation: after distilling a student from a teacher, you can generate intermediate-sized model families that scale smoothly between them, often matching independently trained models because the distilled student spans a space that the teacher already covers. Cross-Tokenizer Likelihood Scoring (“Cross-Tokenizer Likelihood Scoring Algorithms for Language”) handles a real problem: different tokenizers break text differently, so a distilled model trained on one tokenizer might fail on another; this method distills across tokenizer boundaries by accounting for the mismatch. From Per-Image Low-Rank to Encoding Mismatch (“From Per-Image Low-Rank to Encoding Mismatch”) revives feature-level distillation for vision transformers by fixing the feature matching loss, improving DeiT-Tiny accuracy from 74.86% to 77.53% because the correct matching prevents the student from learning misaligned features. NanoFLUX (“NanoFLUX: Distillation-Driven Compression of Large Text-to-Image”) distills the massive FLUX text-to-image model into a mobile-size version that generates 512x512 images in 2.5 seconds on phones by capturing FLUX's image generation knowledge at smaller scale. Reasoning-Preserved Efficient Distillation (“Reasoning-preserved Efficient Distillation of Large Language”) distills reasoning models by initializing the student based on which neurons the teacher fires most, preserving the reasoning chain because this initialization embeds the teacher's reasoning structure into the student. Towards Resource-Efficient LLMs (“Towards Resource-Efficient LLMs: End-to-End Energy Accounting”) measures the full energy cost of distillation—including the teacher's compute—and derives practical rules for choosing distillation methods under energy constraints because the teacher's cost can outweigh the student's savings.

Distillation works best when you compress structured knowledge: answer distributions for classification (DTO-KD), probabilistic structure (score matching), feature patterns in vision (low-rank), or reasoning chains. Generic distillation is slow; targeted distillation that preserves task-specific structure is fast.

KV cache compression and efficient decoding

When language models generate text, they cache key-value pairs (KV) from all previous tokens. For long text, this cache grows huge—a 70B model generating 512 tokens can need 100+ GB of memory for the cache alone. KV cache compression removes or quantizes this cache to fit in available memory, which lets models run on consumer GPUs.

DynamicInfer (“DynamicInfer: Runtime-Aware Sparse Offloading for LLMs”) notices that most weights can be computed on CPU (slow) while keeping only critical parts on GPU (fast). It uses runtime sparsity profiling to skip weights that contribute little to the output, achieving 253% speedup over existing methods. A3 (“A3: an Analytical Low-Rank Approximation Framework”) approximates the attention matrix using low-rank decomposition—mathematically, breaking it into simpler factors that are smaller to store. This works because much of the attention pattern is redundant. CriticalKV (“CriticalKV: Optimizing KV Cache Eviction from”) prunes KV cache by measuring how much each token's cache affects the final output, removing tokens that change outputs little. FASA (“FASA: FREQUENCY-AWARE SPARSE ATTENTION”) keeps only tokens that matter for frequency-domain patterns in the data, achieving 2.56x speedup with 18.9% of the original cache. GSRQ (“GSRQ: Gain-Shape Residual Quantization for Sub-1-bit”) quantizes the KV cache to 1 bit per value (binary), improving performance from 11.34 to 33.54 on long-context tasks. OBCache (“OBCache: Optimal Brain KV Cache Pruning”) uses output-aware signals—measuring actual errors caused by removed cache—rather than heuristic importance scores. PatternKV (“PatternKV: Flattening KV Representation Expands Quantization”) flattens the KV representation before quantization, expanding the range of numbers and giving quantization more room to work, improving 2-bit and 4-bit accuracy. STAR-KV (“STAR-KV: Low-Rank KV Cache Compression via”) uses soft thresholding to adaptively reduce the rank of the KV cache, combining low-rank approximation with quantization for up to 75% cache compression and 6.9x attention speedup. ThinKV (“ThinKV: Thought-Adaptive KV Cache Compression for”) compresses the KV cache based on the thinking (reasoning) depth of the model—models that think more need less cache reduction. RL-Guided KV Cache Compression (“Which Heads Matter for Reasoning? RL-Guided”) uses reinforcement learning to learn which heads are worth caching, achieving 60% cache reduction with near-zero accuracy loss.

KV cache compression moves from simple rules (size of values, age of tokens) through principled approaches (rank reduction, bit-reduction, information theory) to learned methods (reinforcement learning guidance, neural selection). The central pattern: the cache contains lots of duplication—most of it can be removed without hurting the final answer.

Mixture-of-experts pruning and quantization

Mixture-of-Experts (MoE) models use sparse routing: each token is sent to only a few specialized sub-networks (experts) rather than through all weights. This allows building very large models (trillions of weights) with reasonable computation, so that only the weights needed for that token run. But routing overhead and repeated expert work waste resources—pruning and bit-reducing MoE models requires different techniques than dense models because removing an expert entirely breaks the routing graph.

MoNE (“MoNE: Replacing Redundant Experts with Lightweight”) replaces redundant experts with lightweight novices: instead of pruning expert weights, it compresses whole experts using low-rank approximation and then trains routing to use these compressed versions, outperforming baselines by up to 2.72% at 25% expert pruning because compression targets whole experts instead of scattering weight removal. Attribution-Guided and Coverage-Maximized Pruning (“Attribution-Guided and Coverage-Maximized Pruning for Structural”) scores experts by how much they contribute to the outputs (attribution) and ensures coverage across different input types, achieving 5.27x memory reduction because removing redundant experts while maintaining coverage across diverse inputs prevents performance collapse. CodeQuant (“CodeQuant: Unified Clustering and Quantization for”) clusters experts using KV-means, then quantizes clusters together—this keeps related experts in the same bit-reduction range, achieving 4.15x speedup because similar experts share similar value distributions and can use the same bit-reduction scheme. Efficient Quantization of Mixture-of-Experts (“Efficient Quantization of Mixture-of-Experts with Theoretical”) assigns bit-widths to experts based on their importance, using theory to guarantee the quantization doesn't hurt accuracy because the math bounds how much information is lost. GEMQ (“GEMQ: Global Expert-Level Mixed-Precision Quantization for”) uses mixed-precision quantization where different experts get different bit-widths based on sensitivity because sensitive experts need more bits to preserve accuracy. KBVQ-MoE (“KBVQ-MoE: KLT-guided SVD with Bias-Corrected Vector”) uses singular value decomposition guided by KLT (a rotation technique) to quantize expert weights at extremely low bits because decomposition reduces variance and makes low-bit quantization possible. PADD (“PADD: Path-Aligned Decompression Distillation for Non-Router”) distills dense teacher networks into MoE students via path-aligned decompression, letting students outperform teachers at the same running cost because path-aligned distillation transfers the teacher's decision paths into the sparse MoE structure. SCHUR-A* (“SCHUR-A*: Layer-wise Optimal Expert Pruning for”) searches for the optimal expert-pruning pattern using Schur complements—a mathematical tool that evaluates pruning impacts globally rather than greedily because global evaluation avoids local traps that greedy methods fall into. TileQ (“TileQ: Efficient Low-Rank Quantization of Mixture-of-Experts”) uses 2D tiling (blocked structure) in low-rank quantization of experts, cutting memory by 10x because the blocked structure exposes repeated patterns that compress well.

MoE compression differs from dense because it must respect routing structure: you can't just prune random weights. Instead, successful methods either (1) compress entire experts together (MoNE, clustering), (2) assign mixed-precision by expert sensitivity (GEMQ, KBVQ), or (3) optimize globally using mathematical tools (SCHUR-A*). The key is preserving the routing graph while shrinking each expert.
