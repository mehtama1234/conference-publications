Agent World Model: Infinity Synthetic Environments for Agentic Reinforcement Learning

Train tool-using agents in many executable synthetic worlds so they can practice broadly without depending on one narrow benchmark environment.

Paper explainersAll themesAgents & Tool Use

Training an agent needs many episodes, many task types, and reliable feedback. Real environments are expensive to build and slow to run. Fully language-simulated worlds can be fast, but their state changes may be inconsistent because the world update itself is just another generated response. This paper builds a large collection of code-driven synthetic environments backed by databases so that agents can practice across many tasks while still getting stable state transitions and dependable reward signals.

Zero assumption version

Agent training stalls when environments are too few, too slow, or too inconsistent

A strong tool-using agent needs practice across many tasks, not just one benchmark setting. But collecting that practice from real or highly detailed environments is expensive, and fully generated environments may produce unstable world updates that weaken the reward signal.

The result is a scaling problem. Training cannot expand smoothly if every new environment is costly to author, costly to run, or too inconsistent to trust. The paper asks whether a large bank of executable synthetic worlds can provide diversity, speed, and stable feedback at the same time.

The paper's move in one sentence. Generate many code-driven synthetic environments with database-backed state so agents can train broadly because executable worlds make transitions and reward easier to trust.

The algorithm as a flow

What it actually does

Generate many environments

Create a large set of everyday synthetic worlds with tasks, tools, and observations so that agent training is not tied to one benchmark.

Back each world with executable state

Use code and databases to update the world because explicit state transitions are easier to trust than free-form simulation text.

Train agents across the world bank

Run multi-turn reinforcement learning episodes over many synthetic tasks so that the policy sees broader interaction patterns.

Design dependable rewards

Use direct access to world state when scoring episodes so that reward reflects actual task progress instead of uncertain textual interpretation.

Evaluate outside the training worlds

Test on separate benchmarks so that the result shows whether synthetic practice transfers beyond the generated environment bank.

What the paper changes

What the paper changes

The paper changes the source of agent experience. Instead of learning mainly from benchmark-specific worlds, the policy learns from a large reusable library of synthetic executable environments.

The hidden quantity

The hidden quantity

measured quantity  =  how much useful general practice the agent gets per unit of environment cost

The hidden quantity is not just the number of training episodes. It is the amount of useful, trustworthy, diverse practice the agent receives for the environment-building cost paid.

A world bank is valuable only if those episodes teach skills that transfer outward. Code-driven state and database-backed records help because they make transitions and rewards stable, while large world variety helps because repeated exposure to different task structures discourages narrow benchmark habits.

Why it works

Why executable synthetic worlds can train useful policies

Synthetic worlds can scale because they are cheaper to create and run than many fully realistic environments. That alone is not enough, though. If world transitions are inconsistent, the policy learns from noise. The paper's code-driven design matters because the next state follows explicit program logic and stored data rather than an unconstrained textual guess.

The environment bank also helps transfer because the agent sees many combinations of tasks, tools, and observations. That variety reduces overfitting to one benchmark path and encourages general problem-solving habits that can be reused elsewhere.

Math after the picture

A compact training-resource view

First in words:

Useful training supply can be viewed as environment variety times state reliability, because many episodes help only when those episodes come from worlds whose updates can be trusted.

Then the compact form:

training_supply = world_variety * state_reliability

Every symbol:

training_supplyamount of broadly useful agent practice available for learning
world_varietyrange of different tasks, tools, and situations covered by the world bank
state_reliabilityhow consistently world updates and rewards reflect the true task state
A tiny worked example
Suppose one world bank covers many task types, giving world variety 8.
Suppose its executable updates are highly consistent, giving state reliability 9.
Then training supply is 72 by this simple product view.
A second bank with the same variety but unreliable updates might score only 40.
That lower value reflects a practical truth: broad practice loses value when the world itself cannot be trusted.

The paper's full setup is larger than this summary, but the equation captures the main scaling claim about diversity and reliability together.

What can go wrong

What can go wrong

Synthetic worlds can still miss real deployment quirks. Even a large world bank may omit important real-world irregularities, so transfer can stall because the training data mix still leaves out decisive edge cases.
Generated environments can become formulaic. If many worlds are built from similar templates, the agent may learn the template rather than the broader skill because superficial variety hides structural repetition.
Reward design can still be narrow. Direct state access helps scoring, but a poorly chosen reward can still teach the wrong lesson because reliable measurement does not guarantee the right objective.
Done right. The approach is strongest when the world bank is both varied and executable, because that combination gives reinforcement learning many trustworthy practice episodes.
What a runnable demo should prove

What a runnable demo should prove

Build a small bank of executable household task environments with stored state and tool interfaces. Train one agent only on a single benchmark environment and another on the synthetic bank. Keep the reward tied to true world state rather than text-only judgments.

The demo should then evaluate both agents on held-out environments with related but not identical tasks. The synthetic-bank agent should transfer better because it has already practiced across a wider range of situations.

transfer_gain = heldout_success_bank - heldout_success_single ; supply_gain = training_supply_bank - training_supply_single

The point of the demo is to show that many executable synthetic worlds help because they supply diverse and dependable practice at training time.
