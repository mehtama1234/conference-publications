Latent Geometry-Driven Network Automata for Network Dismantling

A method that breaks networks efficiently by using simple local rules to find which nodes matter most, guided by the hidden geometric shape of the network.

Paper explainersAll themesGraph & Geometric Learning

When a virus spreads through a contact network or a power grid fails, knowing which nodes to remove first can save lives or prevent catastrophe. Most methods that find these critical nodes either require knowing the entire network structure at once (slow for giant networks) or use complex machine learning that ignores the hidden geometric structure of real-world networks. This paper shows how simple local rules can find the most critical nodes by sensing the geometric shape of the network, and proves it works on thousands of real networks.

Zero assumption version

Finding critical nodes the hard way

A network is just a set of things connected together: airports linked by flights, people linked by friendships, or neurons linked by synapses. Breaking a network means removing some of its nodes (the things) to fragment it into disconnected pieces.

Existing methods for finding which nodes to remove face a problem: they either must see the entire network at once before deciding which node to remove (slow and impossible for networks with billions of nodes), or they ignore a hidden structure that determines how networks actually behave. Real networks are not random; they sit on a curved surface where nearby nodes interact more than distant ones. Most nodes cluster together in groups, and these groups have a shape (how they bend in space). Existing methods throw this cluster-shape information away.

The challenge. Find the nodes that matter most without seeing the whole network first, and use how the nodes cluster in groups and the shape of those groups.

What it actually does

Start with neighbors only

Each node counts how many friends it shares with its immediate neighbors.

Automata rules spread information

Simple rules (like common neighbor counts) propagate through local connections, building a picture of the network shape.

Estimate effective distances

The spreading pattern reveals which nodes are actually close together on the network's hidden geometric surface, even if they are far apart in steps.

Rank nodes by importance

Nodes that bridge many geometric clusters or sit at high-traffic junctions get high scores.

Delete the highest-scoring node, recalculate scores for the remaining network, and repeat until fragmented.

What the paper changes

What the paper moves

The paper changes how a node's importance score is computed. Instead of using global network knowledge (which is slow) or ignoring how nodes cluster and their clusters bend in space (which is inaccurate), it uses simple local automata rules to estimate a node's centrality (its role in holding the network together) based on the effective link distances it reveals through local signal propagation.

the object it moves  =  Node importance scores
The hidden quantity

Effective link distance: how nodes actually relate

measured quantity  =  Effective link distance between nodes

Real networks have clusters and these clusters have shapes (they bend in space). Two nodes might be many steps apart through the network but close in their cluster, or vice versa. Most algorithms ignore this clustering shape. This paper's hidden quantity is the effective link distance: the true distance between two nodes as measured through the network's cluster structure and bending, inferred from how information spreads through local automata rules.

The paper estimates effective link distances by running simple automata rules (like counting common neighbors) locally at each node, then seeing how these local patterns combine to reveal the network's cluster shapes and bending. Nodes that sit where multiple clusters meet or inside densely packed regions get flagged as critical.

Why it works

Why local automata rules reveal cluster shapes

Simple local rules, run repeatedly across a network, naturally expose how the nodes cluster and how these clusters bend in space. When you ask each node to count common neighbors with its immediate contacts and propagate this count forward, the pattern that emerges is not random: it reflects how the clusters are shaped. Nodes sitting at bridges between clusters see different neighbor-count patterns than nodes sitting inside one solid cluster.

By aggregating these local automata signals, the method estimates which nodes are truly critical for holding the clusters together. Removing these nodes tears apart the clusters, fragmenting the network faster than removing randomly chosen nodes. The local rules work because they do not require global knowledge (you do not need to see the whole network upfront) and they naturally encode cluster-shape information (the pattern of local neighborhoods reveals the global cluster structure).

Math after the picture

The importance score formula

First in words:

A node's importance score is the sum of how many neighbors it has, weighted by a measure of how central each neighbor is in the local automata pattern. Neighbors with high common-neighbor counts get more weight.

Then the compact form:

importance_i = sum_j (neighbors_of_i) [common_neighbors(i,j) * weight_j]

Every symbol:

importance_iscore for node i (higher = remove first)
neighbors_of_iall nodes directly connected to node i
common_neighbors(i,j)count of nodes connected to both i and j
weight_jhow central node j is (from automata rule)
A tiny worked example
Node A has three neighbors: B (3 common), C (2 common), D (4 common).
Node B's automata weight is 0.5 (low centrality). Node C is 1.0 (high). Node D is 0.8.
importance_A = (3 * 0.5) + (2 * 1.0) + (4 * 0.8) = 1.5 + 2 + 3.2 = 6.7
A neighbor that shares many connections and is itself central contributes more to the score.

Nodes with many well-connected neighbors rank high; removing them tears apart the network's clusters.

What can go wrong

What can go wrong

Highly regular or grid-like networks. If the network has no cluster structure (e.g., a perfect grid or random graph), the automata rules see no useful signal. The method falls back to basic degree centrality.
Very small neighborhoods. If nodes have few direct neighbors, common-neighbor counts drop near zero and are drowned out by noise. The method needs enough local density to see clusters clearly.
Dynamic networks. Real networks change over time (new friendships form, neurons rewire). The method estimates cluster shapes based on a snapshot. If the network evolves while you remove nodes, scores become stale.
Networks with clear clusters. When the network has distinct clusters that bend in clear ways (hierarchical organization, small-world structure), local automata rules perfectly capture the cluster shapes. Scores stay accurate even in large networks.
What a runnable demo should prove

What a runnable demo should prove

Build a small social network (e.g., 100 nodes, edges representing friendships). Run the local automata rules: have each node count common neighbors with its immediate contacts. Compute importance scores. Remove nodes in order of decreasing score. After each removal, measure the size of the largest connected component (the number of nodes still able to reach each other). A good demo proves that removing nodes by local cluster-shape scores fragments the network faster than removing random nodes or using a simple degree-based heuristic, because nodes with high cluster-bridge scores sit where multiple clusters meet, so their removal severs more connections at once.

Fragmentation speed = number of node removals needed to reduce the largest component below 50% of original size

The demo must show that a node with high local automata score breaks the network faster than a random node, even though the method never sees the whole network, because local neighbor patterns encode cluster-bridge information.
