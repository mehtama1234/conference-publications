HEDP: A Hybrid Energy-Distance Prompt-based Framework for Domain Incremental Learning

HEDP learns to stay stable across new data domains by measuring how spread-out and well-separated each domain's learned patterns are, then uses that signal to update itself smartly.

Paper explainersAll themesRepresentation & Self-Supervised Learning

Models trained on one kind of data often break when you give them a new kind of data. This is called domain shift. HEDP prevents that by using two signals to understand each new domain: how spread out the learned patterns are (energy), and how far apart they sit from each other (distance). The model learns which signal to trust for each situation, allowing it to adapt to new domains without forgetting old ones.

Zero assumption version

Why models break on new data

Imagine you train a model to recognize cats by showing it thousands of cat photos from your phone. It learns patterns: ear shapes, whisker layouts, fur colors. Now you show it cat photos from a different camera, taken outdoors with different lighting. The model struggles—it has never seen that lighting before. This is domain shift: the data changed, but you did not retrain.

A beginner might say: just train on both old and new data together. But that causes catastrophic forgetting—the model rewrites the old patterns to fit the new data, and suddenly fails on the old data. You wanted to learn continuously, not erase.

In one sentence. HEDP learns which patterns need to stay stable and which need to change by measuring how well-separated each domain's representations are.

The algorithm as a flow

What it actually does

Step 1: Measure domain spread

Calculate how spread-out the learned patterns are for the current domain.

Step 2: Measure domain separation

Calculate how far apart this domain sits from all previous domains.

Step 3: Blend the two signals

Combine spread and separation into one quality score, with a learnable weight for each.

Step 4: Apply protection penalty

Penalize changes to patterns that were important in old domains.

Step 5: Train on new data with protection

Learn new patterns while the penalty system holds the old ones stable.

What the paper changes

What the paper changes

HEDP changes how the model weights new information against old. Instead of a fixed rule, it learns domain-specific blend weights that decide whether to trust energy (spread) or distance (separation) as a signal for what to protect.

the object it moves  =  domain-selection weights
The hidden quantity

The hidden quantity: representation spread

measured quantity  =  Energy-based representation spread

This is a number that measures how spread-out and well-separated the learned patterns are for each domain. Think of it like a crowd: if people are tightly clustered, the spread is low; if they are fanned out across the floor, spread is high. In machine learning, well-separated patterns mean the model can tell different things apart confidently.

HEDP calculates this energy directly from the learned patterns and uses it to decide which old patterns to protect when learning new domains. A high-spread domain is already well-organized, so the model locks it down. A low-spread domain is messy, so it has more room to change.

Why it works

Why it works: the causal chain

The problem is that training on new data alone rewrites old patterns. The paper's move is to measure two things: (1) how organized the patterns are (energy), and (2) how far they sit from other domains (distance). Combining these two signals tells the model which patterns matter most.

When the model learns from new data, a regularization penalty slows down changes to the high-energy patterns—the ones that are already well-organized and important. But patterns that are disorganized or redundant are free to change. This way, the model adapts to new domains while keeping the old knowledge intact. The hybrid weighting (energy + distance) lets the model learn which signal is most reliable for each domain, so it does not apply the same rigid strategy everywhere.

Math after the picture

The equation: hybrid regularization

First in words:

penalty equals alpha times energy term plus beta times distance term, applied to how much each pattern changed, weighted by a hybrid score that the model learns

Then the compact form:

L_reg = lambda * [ (alpha * E_i + beta * D_i) * (theta_i - theta_i_old)^2 ]

Every symbol:

L_regregularization penalty that slows down parameter changes
lambdahow strong the overall protection is
alphalearned weight: trust energy or not
betalearned weight: trust distance or not
E_ienergy (spread) of pattern i
D_idistance from old domains for pattern i
theta_icurrent value of pattern i
theta_i_oldsaved value before this domain
A tiny worked example
Pattern A: spread E_A=8, distance D_A=6, changed 0.4 from old value.
Model learns alpha=0.7, beta=0.3 (trust spread more).
Hybrid score = 0.7*8 + 0.3*6 = 5.6 + 1.8 = 7.4.
Penalty = 1.0 * 7.4 * 0.4^2 = 7.4 * 0.16 = 1.184.
Pattern B: spread E_B=2, distance D_B=1, changed 0.4.
Hybrid score = 0.7*2 + 0.3*1 = 1.4 + 0.3 = 1.7.
Penalty = 1.0 * 1.7 * 0.4^2 = 1.7 * 0.16 = 0.272.
Pattern A is penalized 4.3x more, so training leaves it alone while letting Pattern B adapt.

The hybrid score lets the model decide whether to trust spread or distance for each pattern, so the protection is not one-size-fits-all.

What can go wrong

What can go wrong

Energy signal is wrong for this domain. If the new domain's patterns naturally have low spread, energy regularization might refuse to let them change, even though they need to. The model will underfit on the new domain.
Distance metric does not work across domain types. If two domains are fundamentally different (e.g. photos vs. sketches), a simple distance measure may not catch that difference. The hybrid weighting can partly recover, but only if the domains share some structure.
Learning alpha and beta requires careful tuning. If alpha and beta are learned badly, the model might trust the wrong signal and protect the wrong patterns. Unstable training can cause it to flip between trusting energy and distance.
Done right. When energy and distance are well-calibrated and the model has seen enough data to tune alpha and beta, HEDP locks down high-value patterns while letting low-value ones adapt freely.
What a runnable demo should prove

What a runnable demo should prove

Build a simple model that learns on domain A, then trains on domain B. Measure three things: (1) accuracy on domain A after domain B training, (2) accuracy on domain B, and (3) the pattern change size. Compare naive retraining (always forgets), standard regularization (fixed protection), and HEDP (learned hybrid protection). HEDP should keep domain A accuracy high while getting domain B accuracy close to naive training, because it learned which patterns can change and which must stay locked.

Forgetting = accuracy_A_before - accuracy_A_after | New domain accuracy = accuracy_B_after | Stability = how many old patterns stayed close to their original values

A good demo makes it impossible to miss that HEDP keeps both old and new domains accurate, because it learned which patterns each domain needs to protect.
