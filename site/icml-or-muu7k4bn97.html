Optimizing Agentic Reasoning with Retrieval via Synthetic Semantic Information Gain Reward

Give retrieval actions a dense reward based on how much the agent's answer uncertainty shrinks after each fetch so that the agent learns to seek useful information before finishing the answer.

Paper explainersAll themesAgents & Tool Use

Reasoning agents often know whether the final answer was right, but they receive little guidance about whether each intermediate retrieval step was useful. That makes training hard because the agent must guess which search actions actually improved its understanding. InfoReasoner adds a dense reward based on semantic information gain: a retrieval step is rewarded when it narrows the set of plausible final answers in a clear semantic way, because a good fetch should reduce uncertainty before the final answer is written.

Zero assumption version

Why retrieval actions are hard to train with final-answer reward alone

When an agent solves a question with retrieval, many intermediate actions happen before the final answer appears. The agent decides what to search for, which source to open, and when to stop searching. If training only rewards the final answer, those earlier choices receive a weak signal because the agent does not know which retrieval step actually helped.

Manual labels for every useful retrieval step would be expensive and narrow. The paper instead asks whether a fetch reduced the uncertainty of the agent's belief over answers. If uncertainty shrinks in a clear semantic way, that fetch was useful even before the final answer is scored.

The paper's move in one sentence. Define a dense reward for retrieval steps by measuring how much each step narrows the set of semantically plausible answers, then use that reward inside group-relative policy optimization.

What the paper changes

What the paper changes

The paper changes what counts as a useful intermediate retrieval step during training. Instead of relying only on final correctness, it gives explicit credit when a fetch reduces semantic uncertainty in the answer space.

the object it moves  =  the reward signal attached to intermediate retrieval actions during agent training
The hidden quantity

The hidden quantity

measured quantity  =  how much a retrieval step actually reduces uncertainty over plausible final answers

A retrieval step may look active without being helpful. The hidden part is whether that step truly changed the answer belief state. If the agent fetches a document but still cannot rule out wrong answers, the fetch did not add much value.

InfoReasoner tries to estimate that hidden value directly. It groups answer candidates by semantic meaning and checks whether a new fetch makes the answer spread smaller. That helps because useful retrieval is defined by what it does to the answer space, not by how impressive the fetched document looks.

Why it works

Why this works: reward the fetch when it changes the answer space

Final-answer reward is sparse because many retrieval steps happen before the outcome is known. A dense intermediate signal helps if it correlates with the eventual answer. Semantic information gain does that by asking whether the fetch ruled out wrong answer groups and concentrated belief on better ones.

The semantic grouping matters because answer strings can differ in wording even when they mean the same thing. Measuring raw string change would miss that. Grouping answers by meaning gives a cleaner signal, so the reward reflects whether the fetch changed what the agent believes rather than only how the final text is phrased.

Math after the picture

Reward uncertainty reduction from one retrieval step to the next

First in words:

A compact summary is to define the reward of one retrieval step as the drop in semantic uncertainty over plausible answers after the new evidence is added.

Then the compact form:

gain(step) = uncertainty(before_step) - uncertainty(after_step)

Every symbol:

gain(step)reward assigned to one retrieval step
uncertainty(before_step)how spread out the answer belief state is before the fetch
uncertainty(after_step)how spread out the answer belief state is after the fetch
before_step, after_stepthe answer belief state on the two sides of the retrieval action
A tiny worked example
Before retrieval, the agent sees three answer groups as plausible.
After opening one document, two of those groups mostly disappear.
The uncertainty after the step is smaller than before the step.
That step receives positive reward because the fetch removed wrong possibilities.
A fetch that leaves all three groups equally plausible would receive little or no reward.

The full paper defines the reward more carefully and uses semantic grouping of answer outputs, but this equation captures the key idea that a useful fetch makes the answer belief state more concentrated.

What can go wrong

What can go wrong

Semantic grouping can be noisy. If the answer groups are formed poorly, the reward may overvalue or undervalue a fetch because the uncertainty estimate itself is wrong.
A fetch can narrow the wrong answer set. The agent may become more certain about an incorrect answer if it reads misleading evidence, so uncertainty reduction alone is not enough without final correctness checks.
Dense reward can bias behavior toward easy gains. The policy may chase quickly rewarding fetches rather than the globally best search plan if short-term reward is easier to collect.
Done right. The method matters because it gives retrieval actions credit for changing the answer belief state before the final answer is known.

What a runnable demo should prove

Build a retrieval question-answering setup where an agent can search a document collection before answering. Compare final-answer-only training against an InfoReasoner-style reward that measures uncertainty reduction after each fetch. Log the answer belief state after each retrieval step so the reward can be inspected directly.

The demo should show at least one example where a useful document sharply narrows the answer space and one example where a distracting document does not. The reward should separate those cases because the paper's main claim is that useful retrieval can be identified before the final answer arrives.
