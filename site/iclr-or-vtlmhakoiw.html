AutoDA-Timeseries: Automated Data Augmentation for Time Series

Automatically tune which time-series modifications to use and how strong to make them, so the model learns better on tasks like forecasting and anomaly detection.

Paper explainersAll themesTime Series & Sequential

When you train a model on time-series data—stock prices, weather patterns, sensor readings—you want to feed it many different versions of the same underlying signal so it learns patterns that still work when the real-world input is slightly different. Image models have automated data augmentation: a system that tries different picture distortions and learns which ones help, because showing the model distorted examples teaches it that minor visual changes do not change what an object is. But that approach does not work for time series, where the right modifications are entirely different because distortions that help one task (like random drift for anomaly detection) actively break another (like forecasting where magnitude matters). AutoDA-Timeseries is the first automated system to learn which time-series-specific transformations to use and how intense to apply them, tailored to each forecasting, classification, or anomaly detection task.

Why existing data augmentation does not work for time series

Image models use a two-step process: first, you train a model to recognize images by showing it many distorted versions (rotations, crops, color shifts) so it learns the core content independent of small visual changes. Then, you fine-tune that pre-trained model on your actual task. This works well because distortions that preserve object identity (a rotated dog is still a dog) are clear and help generalization—the model learns invariance rather than memorizing pixels. But time series are different. A small rotation in a stock-price chart means something totally different than a small rotation of a dog photo—it misrepresents the underlying signal and teaches the model wrong invariances. The distortions that help an anomaly detector (sudden spikes, drifting baselines) are the opposite of those that help a forecasting model (smooth trends, seasonal patterns), because anomaly detection aims to recognize deviations while forecasting aims to project smooth continuation.

A beginner might try to use image augmentation directly on time series, applying the same playbook: shift pixels, blur, rotate. But these distortions wreck time series. A blur of a sensor reading destroys the fine-grained signal. A rotation of a temperature sequence makes no physical sense. Existing automated augmentation frameworks for images are built on image-specific tricks (random crops preserve object context), so they fail silently on time series—they either apply useless transformations or destroy the task-relevant information.

In one sentence. AutoDA-Timeseries learns which time-series-specific augmentations to apply (e.g. scaling, time warping, rotation) and how strong to make them, automatically optimizing both for your specific task in one go.

The algorithm as a flow

What it actually does

1. Define the augmentation pool

Collect time-series-specific operations: jittering (add small random noise), scaling (multiply by a random factor), time warping (stretch or compress the sequence), rotation (apply a linear transformation), drift (add a slow ramp), magnitude warping (non-linear scaling).

2. Set up the policy

For each augmentation, assign two learnable numbers: a probability (use this 30% of the time) and intensity (how strong). Initialize them as guesses.

3. Inner loop: evaluate augmentations

Sample augmentation settings from the policy, apply them to training examples, train the model for a few steps, and measure performance on a hold-out validation set.

4. Outer loop: update the policy

Use the validation performance to nudge the probabilities and intensities. Augmentations that improved accuracy get stronger and more frequent because good performance signals they are teaching the model useful invariances; those that hurt get weaker because they introduce noise or break the signal.

5. Deploy

The learned policy is now your augmentation recipe. Use it on the full train set to train your final model.

What the paper changes

What the paper changes

AutoDA-Timeseries changes the augmentation policy—the set of operations and their parameters—from manually chosen constants to automatically learned values. Instead of a human saying 'use jittering at 0.1 strength and scaling at 0.5 strength', the system measures task performance and adjusts both the probability and intensity of each augmentation operation end-to-end in a single pass, without the two-stage representation learning approach that image models use.

The hidden quantity

The hidden quantity: task-specific augmentation utility

measured quantity  =  How much each augmentation helps this specific task

Task-specific augmentation utility measures how much each transformation (jittering, scaling, warping, etc.) actually improves accuracy on your particular job. For a forecasting model, strong scaling might hurt because it distorts the magnitude scale and teaches the model to ignore true price levels; but time warping might help because it teaches the model to recognize trends at different speeds. For anomaly detection, the opposite may be true because anomalies often are detected via magnitude spikes. The utility is hidden because you never observe it directly; you only see the model's final accuracy on examples trained with a particular augmentation.

AutoDA-Timeseries estimates utility by running tiny experiments: apply an augmentation to a batch, train briefly, and measure validation accuracy. Augmentations with higher utility get a higher probability and intensity score in the learned policy. The system explicitly optimizes these two numbers together (probability and intensity) rather than treating them as fixed hyperparameters, making augmentation selection automatic and task-aware.

Why it works

Why it works: task-aware trial and feedback

The core difference is that the right augmentations depend entirely on your specific task. A classification model on weather data needs different augmentations than a forecasting model on the same data. Traditional approaches fix augmentations before training (a human choice) or learn them only for representation learning (a two-stage setup). AutoDA-Timeseries closes the loop: it continuously measures how each augmentation affects accuracy on your actual task and adjusts the policy in response.

Here is the mechanism. The system maintains a vector of probabilities and intensities (one pair per augmentation type). During training, it randomly samples from this policy to decide which augmentations to apply and how strong. Those augmented examples are fed to the model for a few gradient steps. Then, the system measures validation accuracy—the true signal of whether this augmentation helps, because only examples that actually make the model answer correctly matter. If accuracy went up, the probability and intensity of that augmentation are nudged higher because it is teaching something the model needs; if they went down, they are nudged lower because it is introducing noise or wrong patterns. This happens repeatedly over many iterations, so the policy converges toward the augmentations that genuinely improve performance on your task because each update reinforces useful augmentations and suppresses harmful ones, creating a feedback loop. The one-stage, end-to-end optimization (no separate representation learning step) means the augmentations are tuned directly for your downstream objective, not a generic one, so the policy learns task-specific utility.

The policy optimization equation

First in words:

Policy gradient update: increase probability and intensity of augmentations in proportion to how much they improved validation accuracy

Then the compact form:

p_i := p_i + alpha * dL/dp_i, s_i := s_i + alpha * dL/ds_i

Every symbol:

p_iProbability of using augmentation i (how often to apply it)
s_iStrength or intensity of augmentation i (how much to modify the signal)
alphaLearning rate (how fast to adjust probabilities and intensities)
dL/dp_iGradient: how much validation loss (error) changes if we use augmentation i more often
dL/ds_iGradient: how much validation loss changes if we make augmentation i stronger
A tiny worked example
Start: jittering probability 0.5, intensity 0.1 (default guess).
Try jittering: train model on jittered examples, validate, get accuracy 75%.
Compare to baseline without jittering: accuracy was 70%.
Improvement: 75% - 70% = 5 percentage points. This is good feedback.
Gradient dL/dp_jitter = -5 (negative because lower loss is better). Nudge: p_jitter := 0.5 + 0.01 * 5 = 0.55.
Similarly, try intensity 0.2 instead of 0.1, revalidate, see 76% (better). Nudge s_jitter := 0.1 + 0.01 * 6 = 0.16.
Repeat for scaling, warping, etc. After many iterations, the policy converges to high probabilities and strong intensities for augmentations that help.

Each augmentation's probability and intensity are adjusted proportionally to the validation improvement it produced, so the policy learns which operations are genuinely task-relevant.

What can go wrong

What can go wrong

Validation set too small. If your hold-out validation set is tiny, the accuracy signal is noisy. The policy may learn to rely on augmentations that helped by random chance, not true generalization. Larger validation sets stabilize the gradient estimates.
Overfitting the augmentation policy. If the learning rate (alpha) is too high or training runs too long, the policy may specialize to your specific validation set. It learns augmentations that accidentally match the validation data's quirks rather than true invariances, hurting performance on new data.
Augmentation pool does not fit the domain. If your time series is medical (heart rate) but the augmentation pool includes operations that destroy clinical meaning (random drift, sharp rotation), the system may learn to use them and wreck accuracy. The pool must respect domain semantics.
Done right. With a reasonable validation set, moderate learning rate, and domain-aware augmentation pool, AutoDA-Timeseries converges to a policy that works across all five tasks—classification, forecasting, regression, anomaly detection, and others—yielding consistent accuracy gains without manual tuning.

What a runnable demo should prove

A demo loads three time-series datasets (e.g. UCR classification, electricity demand forecasting, machine anomaly detection). For each, it runs AutoDA-Timeseries to learn the augmentation policy, then trains a model using the learned policy and compares accuracy to a baseline model trained without augmentation and to a model trained with fixed hand-tuned augmentation. The demo should visualize the learned policy—a bar chart showing the final probability and intensity of each augmentation type—and show that these profiles are different across the three tasks, proving the system adapted. Output one metric per task: accuracy improvement as a percentage. Code should be under 300 lines: load dataset, initialize policy, run policy optimization loop (50–100 iterations of inner training and outer policy update), train final model with learned policy, and report accuracy.

accuracy_improvement = (accuracy_with_autoda - accuracy_baseline) / accuracy_baseline * 100%

A successful demo proves that learned policies outperform both no augmentation and fixed augmentation on every task because they are tailored to each job's true requirements, and that the policies are visibly different across tasks—confirming the system adapted to the specific objective rather than memorizing a generic recipe.
