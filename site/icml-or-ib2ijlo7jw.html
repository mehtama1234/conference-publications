Adaptive Recurrent Message Passing for Test Time Computing on Graphs

A graph model that adjusts how many thinking steps to take for each new task at test time, without retraining.

Paper explainersAll themesGraph & Geometric Learning

Graph foundation models—trained once on generic tasks—get deployed on wildly different real graphs: social networks, molecules, traffic networks. A naive approach runs the same fixed number of steps on all of them, which wastes compute on simple graphs and underanalyzes hard ones. This paper shows how to make the model itself decide, at test time, how many steps it needs for each specific task and graph, stopping early when it has enough information.

Zero assumption version

Fixed models meet variable graphs

A foundation model for graphs works like this: you train a neural network once on many sample graphs and many different prediction tasks. After training, you ship it. Then it hits the real world, where every new graph is different—a social network has millions of nodes, a molecule has 20, some tasks need global reasoning, some local. The model has no idea.

The naive approach: run the same fixed computation (say, 5 update rounds) on every graph and task. Simple graphs waste cycles: they converge in 2 rounds but you run 5. Hard problems get shortcuts: they need 7 rounds but you stop at 5. No one asked the model what it actually needs.

In one sentence. AdaR makes the model itself decide at test time how many update rounds each graph needs, by encoding task clues into the update rule and stopping when representations stabilize.

The algorithm as a flow

What it actually does

At test time, encode the step number

Feed the current step count (1, 2, 3, ...) as numbers into the update rule so the model knows where it is, because the neural network was trained to interpret this number and adjust its behavior accordingly—early steps can be exploratory with large nudges, late steps can be conservative with small refinements.

Encode the target signal

Also feed in a signal showing the direction toward correct answers for this task. The model was trained to watch this signal shrink as it converges, so it learns to recognize "small signal = close to answer" and "big signal = far away" through the training examples it saw.

Update node representations

Use the recurrent rule to nudge all node values closer to their task-specific targets, informed by both step count and the target signal (which shows the direction of improvement).

Check convergence

Monitor whether node values are stabilizing (getting closer to a fixed point). When they stop moving much, the model is ready.

Stop adaptively

Exit early if representations are stable, or run more steps if they are still changing. Different graphs, different numbers of steps.

What the paper changes

The thing the paper changes

The paper makes the model decide when to stop, instead of running a hard-coded number of steps. It does this by adding two pieces of information to the recurrent update: the step counter (which step are we on right now) and a target signal (how far are we from the task's correct answer, measured by the direction of steepest improvement).

the object it moves  =  Stop condition
The hidden quantity

Representation stability

measured quantity  =  Stability of node values

During recurrent updates, each node's value (its learned representation) inches toward a task-specific target. Initially it moves a lot. Eventually it plateaus—the changes shrink to nearly zero. This settling is called convergence. The paper measures it by checking how much each node value changes from one step to the next, and by reading off the gradient signals themselves (which encode how far from correct the current representations are).

The gradient signals show how far representations are from correct. Big gradients mean "still far from the target, keep going." Small gradients mean "close to correct, you can stop soon."

Why it works

Why encoding step info and gradients enables adaptive stopping

Here is the causal chain. A graph foundation model, trained once, has learned generic update rules. Those rules do not know what task you are solving right now or how many steps this particular graph needs. By the time you freeze the model and deploy it, you have thrown away the ability to tune anything.

AdaR fixes this at test time by feeding two new pieces of information into every recurrent update: (1) the current step number (1, 2, 3, ...), encoded as numbers, and (2) the gradient—the direction toward correct answers for this task. During training, these signals were always fed into the model, so it learned to read them and condition its updates on them; this is why it works at test time. Now, with these signals, the update rule can be conditioned on the task and progress. Early in the recurrence (steps 1-3), the gradient signals are large because representations are far from correct. The model receives these strong signals and continues exploring. As steps accumulate and representations approach their targets, gradients shrink. The model receives weak signals and knows it is converging. Because the update rule was trained to be adaptive (conditioned on step count and gradient), it naturally produces smaller, more refinement-like updates as it progresses. Representations stop changing much because the update function itself has learned to output smaller nudges when signals weaken. The model can then output "stop" when it detects this stability, rather than blindly running more steps. Different graphs have different convergence speeds—a small graph has tight neighborhoods so it converges faster—so different graphs naturally stop at different step counts, exactly what adaptive test-time computing means.

By encoding the step number and how-far-from-target, you give the model context to decide when it is done, rather than having a human hard-code a step limit upfront. The model learned during training to stop when these signals converge.

Math after the picture

The recurrent update rule

First in words:

New node value equals old node value plus (learning rate times the update step, which depends on the current step number and a gradient-based target signal). The update step is computed by the neural network conditioned on step count and gradient.

Then the compact form:

h_v^(t+1) = h_v^t + lr * f(t, grad_v^t, neighbors(v), theta)

Every symbol:

h_v^(t+1)node v's learned representation after step t+1
h_v^tnode v's representation at step t
lrlearning rate (step size, a small number like 0.01)
f(t, grad_v^t, neighbors(v), theta)the neural network update function, which takes step count t, the gradient-based target signal for node v, the values of v's neighboring nodes, and the model's weights theta
grad_v^tgradient indicating how far node v is from its task target
tthe current step number (1, 2, 3, ...)
thetathe model's weights (trained once, not changed at test time)
A tiny worked example
Suppose node v starts at h_v^0 = 0.5, and its task target direction (gradient) is grad_v^0 = 0.8 (far from target).
Step 1: The function f reads t=1 and grad=0.8 (large), decides to take a big step. Computes an update = 0.3. New value: h_v^1 = 0.5 + 0.01 * 0.3 = 0.503.
Step 3: After a few rounds, h_v^3 = 0.78, and grad_v^3 = 0.05 (small, close to target). The function f reads t=3 and grad=0.05 (small), decides to refine, computes update = 0.02. New value: h_v^4 = 0.78 + 0.01 * 0.02 = 0.7802.
Step 4 onward: Gradients remain tiny (0.02, 0.01, ...). Updates stay small. Eventually the model outputs stop.

The key is that f was trained to reduce its update size as the gradient signal shrinks, so later steps refine rather than overshoot.

What can go wrong

What can go wrong

Gradient signal wrong for the task. If the target gradient was computed poorly or is not actually pointing toward the right answer, the model will refine toward the wrong value. Adaptive stopping will still work, but it will converge to a bad answer. The fix: ensure the task-specific loss or gradient is well-calibrated.
Model was not trained to be adaptive. AdaR requires the model to have seen step counts and gradient signals during training. If training used fixed steps and no gradient encoding, deploying AdaR at test time will fail because the model never learned to read these signals. The fix: retrain with adaptive supervision.
Stopping condition is too conservative. If you stop the moment gradients dip below a threshold, you might stop too early on harder graphs. The node values have not fully converged. The fix: tune the threshold or use a more careful convergence check, such as verifying that gradients stay small for multiple steps in a row.
Done right. The model was trained with step-count and gradient supervision, so it learned to read these signals. Target gradients are accurate for the task, so the stopping signals are honest. The stopping threshold is calibrated: large graphs have slowly-shrinking gradients so they run longer; small graphs shrink fast so they stop early. This trade-off delivers speed (fewer wasted steps on easy graphs) and accuracy (enough steps on hard graphs).
What a runnable demo should prove

What a runnable demo should prove

Build a small graph dataset with two types of tasks: (1) simple prediction tasks on small graphs (10-50 nodes), and (2) harder reasoning tasks on larger graphs (500-1000 nodes). Train a base graph neural network with the adaptive supervision: at each training step, inject the step number and a gradient-based target signal. Deploy it with AdaR's adaptive stopping. Measure: (a) accuracy on both task types, (b) average number of steps used per task, (c) compute (steps times model size). Compare against a fixed-step baseline that always uses the same number of recurrent rounds.

Adaptive benefit = (fixed-step-steps * model-flops) - (adaptive-steps * model-flops); Accuracy gap = adaptive-accuracy - fixed-accuracy

The demo must show that on easy graphs AdaR uses fewer steps without losing accuracy, and on hard graphs it uses more steps to gain accuracy—proving the model itself learned to calibrate when to stop.
