Learning to Remember, Learn, and Forget in Attention-Based Models

Palimpsa adds a smart plasticity controller to attention models so they can remember important examples without drowning in interference when new information arrives.

Paper explainersAll themesLLMs & Foundation Models

When a language model reads a new conversation or document, it needs to remember key facts from earlier in the text — but not too well, because new facts will come in and the old ones will matter less. Palimpsa solves this by giving each attention weight (the part of the model that decides which earlier facts to blend together) its own importance meter. The model learns which attention states matter most (using a technique called Bayesian metaplasticity, where a starting belief about what matters gets refined by data) and gently protects those while letting less important ones learn afresh. This turns the problem of remembering into a stability-plasticity dilemma — the eternal tension between holding onto what you know and being ready to learn something new.

Zero assumption version

Attention runs out of room when sequences grow long

A language model uses a technique called attention to look backward in a conversation or document, finding facts that are relevant right now. Each time a new token (word or symbol) arrives, the attention mechanism scores how much each earlier fact matters, then builds a memory by storing a blend of the important ones. For short texts this works well — the model can hold everything it needs in mind.

But as the text gets longer, something breaks. With gated linear attention (a faster, leaner version that uses multiplication gates to filter what gets remembered), the memory has a fixed size, because it stores information in a compressed state that cannot grow — adding more would make the model much slower. New facts push out old ones, and facts can also interfere with each other — like trying to remember two phone numbers that rhyme. A beginner might think the answer is to add more memory, but that makes the model slower and heavier. The real problem is that the model has no way to tell which facts are actually important and worth protecting.

The core problem. Attention models forget important facts when long texts arrive, because memory is fixed-size and facts interfere with each other.

What the paper changes

The attention plasticity gate

Palimpsa changes the plasticity (ability to learn and change) of each attention weight. Instead of every weight learning at the same speed, the model learns an importance score for each attention state and uses it to control how much that weight can shift when new data arrives. A weight with high importance barely moves when a new token comes in. A weight with low importance can change freely.

the object it moves  =  attention plasticity gate
The hidden quantity

Importance state: how much does this memory slot matter?

measured quantity  =  importance state per attention slot

Importance state is a number (or distribution) attached to each attention memory slot that measures how much that slot has contributed to correct predictions so far. It is not the attention score itself — which weights facts right now. It is a running tally: does this memory slot generally help the model make good predictions? Palimpsa estimates it using a Bayesian model, which means the model maintains a probability distribution over how important each slot really is. This distribution starts with a base belief built from all past examples, then gets refined by each new token's evidence.

The paper measures this importance using accumulated gradients — the more a weight contributes to shrinking prediction error, the higher its importance rises. In Bayesian terms, the importance state acts like that starting belief that gets refined by evidence — it anchors the plasticity gate, encoding the model's accumulated confidence about what matters.

Why it works

Why gating plasticity solves the stability-plasticity trap

The core problem is: if you make all attention weights change quickly (high plasticity), they learn fast but forget old facts. If you lock them down (low plasticity), they hold old facts but cannot learn new ones. Palimpsa solves this by measuring which facts matter and varying the plasticity per weight.

Here is the causal chain. When the model reads examples, it learns which attention slots have been useful — these accumulate high importance scores. When a new token arrives, the plasticity gate (controlled by importance) determines how much each weight can shift. High-importance slots barely move, because they hold facts the model has learned to rely on. Low-importance slots change freely, because they are not baked into the model's decision-making yet. The result: new facts fill up the low-importance slots (which act as scratch space), while old high-importance facts are preserved. The memory feels larger, because the model uses it more efficiently — not every slot has to compete equally.

Math after the picture

The metaplasticity equation

First in words:

the update to an attention weight is gated by its importance. the updated weight equals the old weight plus (learning step size) times (importance gate) times (the direction to improve). importance gate = high for slots that helped predictions, low for slots that were silent.

Then the compact form:

w_t+1 = w_t + alpha * importance_t * gradient_t

Every symbol:

w_tthe attention weight at time step t
alphathe learning step size (how much to change at once)
importance_tthe importance state of this weight, 0 to 1
gradient_tthe direction to adjust the weight to reduce error
w_t+1the weight after the update
A tiny worked example
Slot A: importance 0.9, gradient 0.1, learning rate 0.1 -> update = 0.1 * 0.9 * 0.1 = 0.009 (barely moves)
Slot B: importance 0.2, gradient 0.1, learning rate 0.1 -> update = 0.1 * 0.2 * 0.1 = 0.002 (moves freely)
Slot C: importance 0.05, gradient 0.15, learning rate 0.1 -> update = 0.1 * 0.05 * 0.15 = 0.00075 (new data easily fits)
Same gradient size, but high-importance slots resist change 18x harder. This protects facts the model relies on.

The importance gate acts like a brake: high importance locks the weight in place; low importance lets gradients flow through freely.

What can go wrong

What can go wrong

Stale importance scores. If a weight was important in an old task but is useless now, its importance score stays high and the weight cannot update. The prior distribution must decay or reset, or performance stalls on new domains.
Weak prior. If the prior distribution does not capture real accumulated knowledge, importance scores are random noise. The plasticity gate has no signal, and the method reduces to baseline gated attention.
Gradient noise early on. In the first few tokens, gradients are tiny and noisy. Importance estimates are unreliable. The model may lock in bad early decisions because they look important.
Done right: warm-start or adaptive decay. Initialize the prior from a related task, or let importance decay over time as new contexts arrive. The model then balances old knowledge with flexibility to learn new tasks.
What a runnable demo should prove

What a runnable demo should prove

Build a simple synthetic task: a sequence where the first half tests whether the model remembers fact A (e.g., 'Alice is tall'), the second half tests whether it learned fact B (e.g., 'Bob is short'). A standard model with a fixed learning rate either forgets A when it learns B, or fails to learn B because it is too locked in by A. Palimpsa should keep both facts — A is marked important because the model used it to score the first half correctly, B is learned into low-importance slots because they are free for new information.

recall = (correct_fact_A_at_step_N + correct_fact_B_at_step_N) / 2

Baseline recall drops below 60 percent because it chooses between remembering and learning. Palimpsa reaches above 90 percent because it does both.
