Reflex: Real-Time Vision-Language-Action Control through Streaming Inference

A robot learns to act from camera images by making a flow-matching model stream actions one at a time without re-doing math each step.

Paper explainersAll themesRobotics & Control

Vision-Language-Action models let robots learn precise continuous control by reading camera images and writing movement commands. The standard way these models work uses a denoising process that starts with random noise and iteratively refines it into a clean action. But this process has a fatal flaw for real-time robots: each step changes a hidden state called a timestep, which breaks a speed trick (KV-cache reuse) that lets the model answer faster. Reflex fixes this by realizing the parts that read the camera are independent of the parts that denoise, so you can cache the camera work and only redo the denoising.

Zero assumption version

Why denoising breaks real-time robots

A Vision-Language-Action model reads a camera image and outputs a robot movement command. To learn, it uses a denoising process: start with pure noise, then run the model over and over, each time subtracting a tiny bit of noise until you have a clean action. This works great for learning.

But each denoising step gets a global signal: which step of the denoising loop are we in? The model uses this to adjust how much noise to subtract each time. A speed trick, called KV-cache reuse, remembers the camera encoding from the previous step so the model does not have to re-read the camera each time—this works because the same camera frame is used over all denoising steps. The catch: the global step number breaks this trick. If the step number changes, the math that was cached becomes wrong, because the model tuned the math for step 1 but now we are at step 2; so the model either re-reads the camera every time (slow quadratic arithmetic—work grows as step-count squared) or reuses the cached math anyway (wrong answers).

The core problem. Global timestep injection breaks KV-cache reuse, forcing a choice between slow recomputation or mathematically incorrect cache reuse.

The algorithm as a flow

What it actually does

One: recognize independence

The encoder that reads the camera does not use the global step number, so its output can be reused.

Two: split the memory context

Partition the cache into static (encoder output, never changes), sliding (a memory window that shifts), and dynamic (recomputed each denoising step). The parts of the cache that are always used must be kept frozen; parts that change with the denoising step must be recomputed.

Three: incremental updates

When the denoising step changes, only update the dynamic and sliding parts; static stays unchanged in memory.

Four: stabilize numerics

Add AdaRMSNorm, a layer that prevents precision loss by gating (turning on and off) based on the denoising phase.

Five: run in parallel

Decouple camera reading from action generation in separate threads; fuse multiple low-level operations into one.

What the paper changes

What the paper changes

Reflex changes how the model stores and updates its internal cache when the robot runs the model in real time. Normally, the entire cache becomes invalid when the timestep changes. Reflex partitions the cache into three zones: parts that never change (cached), parts that slide (move through a window), and parts that are recomputed each step. This splits the problem so the model can reuse the camera encoding without lying about the math, because the camera-dependent parts are separated from the timestep-dependent parts and each is handled correctly.

The hidden quantity

The hidden quantity: cache reuse depth

measured quantity  =  Fraction of cached computation reused across denoising steps

The paper measures how much of the cached math can be safely reused when the timestep changes. Without Reflex, zero percent of the cache is valid (it all breaks). With Reflex, the static portion (encoder output) stays valid, plus the sliding window is updated in place without re-reading the entire context. This fraction directly determines how fast the model runs when the robot uses it in real time.

The paper estimates this by analyzing how the model decides which parts to use (the decision mechanism). It observes that the encoder layer does not read the timestep number at all—only the denoising layers do. So the encoder output is invariant (stays the same regardless of timestep). Reflex then tracks which parts of the model's decision context depend on the encoder (static or sliding) versus only on the denoising step (dynamic), and caches accordingly.

Why it works

Why partitioning the cache solves the problem

The core mechanism is recognizing that the model has two independent jobs: reading the camera, and refining actions. The camera encoder runs once and produces a fixed output (a list of numbers representing what the camera saw). The denoising loop then uses this fixed output to decide how much noise to subtract at each step. The global timestep number is only used by the denoising loop, not the encoder.

This means you can cache the encoder output and reuse it across all denoising steps. The encoder never sees the timestep, so its output is true at step 1, step 2, and step 50—no recalculation needed. Meanwhile, the denoising loop runs the part of the model that does use the timestep (the dynamic layers), but it only needs to recompute this small part. This splits a problem that seemed unsolvable (cache is either 100% wrong or 100% right) into a solvable one (cache part of the work, recompute only the timestep-dependent parts).

AdaRMSNorm adds stability. When you reuse cached numbers over 50 rapid steps, floating-point errors (tiny rounding mistakes) add up. AdaRMSNorm gently scales the numbers to stay in a safe range, preventing the 16-bit floating-point format (BFloat16) from losing precision and crashing. The async pipeline runs the camera reading on one thread and denoising on another, so while one thread waits for the camera frame, the other finishes denoising the last frame. Operator fusion squashes multiple low-level operations into one, reducing scheduling overhead.

Math after the picture

The cache reuse equation

First in words:

Total inference cost is the cost to encode the camera once, plus the cost to run the denoising loop on the static-cached encoder output.

Then the compact form:

total_cost = encode_cost + denoising_steps * (update_sliding + recompute_dynamic) where encode_cost is paid only once and cached

Every symbol:

total_costarithmetic cost for one action (camera + denoising)
encode_costcost to read camera and build the encoder output
denoising_stepshow many refinement steps in the loop (typically 4-10)
update_slidingcost to shift and update the sliding window of context
recompute_dynamiccost to recompute the layers that use the timestep
A tiny worked example
Suppose encode_cost = 100 units, denoising_steps = 5, update_sliding = 5 units, recompute_dynamic = 10 units.
Without Reflex: recompute entire attention for all steps = 5 * (100 + 5 + 10) = 575 units.
With Reflex: encode once, then only update/recompute = 100 + 5 * (5 + 10) = 100 + 75 = 175 units.
Speedup: 575 / 175 = 3.3x, matching the observed 2.58x speedup on real models (difference due to overhead).

Reflex beats the naive loop by paying the camera encoding cost once and amortizing it across all denoising steps.

What can go wrong

What can go wrong

Numerics collapse under high frequency. If you run 50 denoising steps at 50Hz without normalization, floating-point errors accumulate and the 16-bit format loses precision, producing garbage actions. AdaRMSNorm prevents this by detecting when numbers drift out of range and gently rescaling them.
Timestep signals baked into the cache invalidate it. If the timestep number is mixed into the encoder output (built into the static cache), then changing the timestep breaks the assumption that the cache is invariant. Reflex requires strict separation: encoder output must not include any timestep signal.
Sliding window misalignment causes attention errors. The sliding window (context that shifts as you step through denoising) must be updated precisely. If the shift is off-by-one or the boundary is wrong, the model attends to the wrong part of the context and produces incorrect refinement.
Done right: measure cache reuse by observation. Validate that the encoder output is truly invariant by running the model with and without caching and checking that the attention weights match when the timestep changes.
What a runnable demo should prove

What a runnable demo should prove

A demo should start with a real Vision-Language-Action model (e.g., trained on LIBERO robot manipulation tasks) and run a single action loop repeatedly. For each camera frame, measure the time to run the encoder with and without caching. Then, over 5 denoising steps, measure the time to update the sliding/dynamic parts only (Reflex) versus re-running the full encoder each step (naive). Record latency and throughput at 50Hz. The demo should also log the cache hit rate (percentage of the model output that was reused without recomputation) and show that it stays above 80% over sustained high-frequency running.

speedup = naive_total_latency / reflex_total_latency, sustained_throughput = actions_per_second at 50Hz target

The demo must show sustained 50Hz inference (one action per 20ms) without numerical collapse, proving that cache reuse plus adaptive normalization enable real-time robot control, because the speed comes from not re-reading the camera and the stability comes from preventing floating-point errors from accumulating.
