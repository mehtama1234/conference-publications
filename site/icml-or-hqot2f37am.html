CAOS: Conformal Aggregation of One-Shot Predictors

CAOS combines multiple one-shot predictors with smart weighting to give honest confidence bands instead of pretending uncertainty does not exist.

Paper explainersAll themesLearning Theory

One-shot learning lets pretrained models adapt to new tasks using just one labeled example. But the model has no way to say how confident it is in its answer, which can be dangerous. CAOS solves this by aggregating multiple one-shot predictions and using a clever leave-one-out calibration method to build prediction sets with mathematically proven coverage guarantees even when standard assumptions break down.

Zero assumption version

One-shot adaptation lacks honest uncertainty

Pretrained models are highly capable but unprepared for new tasks. With just one labeled example, a model can learn quickly — but it has no way to express how much uncertainty it carries. If it guesses wrong, nothing stops it.

A beginner might try splitting the one example into a training set and a test set to measure confidence. But splitting one example gives you nothing on both sides. Or you might train on the one example, then on held-out data, measure error, and assume the new task has the same error rate. That assumption is often false — the new task is genuinely different.

The problem. One-shot learners adapt fast but have no way to bound how wrong they could be.

The algorithm as a flow

What it actually does

Take the one labeled example.

Feed it and the pretrained model into the system.

Train multiple one-shot copies.

Each learner adapts the model differently to the single example.

Leave-one-out calibration.

For each held-out predictor, see how much the others disagree with it.

Weight by disagreement.

Predictors that often disagree get lower weight in the final set.

Output confidence bands.

Return a set of possible answers with proven coverage on new data.

What the paper changes

What the paper changes

Instead of one predictor or a naive split, CAOS builds an adaptive aggregation (a weighted voting scheme) that uses all the information from the single labeled example. By leaving out each predictor in turn, the method measures how reliable each one is on unseen data.

The hidden quantity

Conformal rank: the hidden quantity

measured quantity  =  conformal rank (how often predictors agree)

Conformal rank is a score that measures how much a prediction disagrees with others on held-out data. It is not a number the model assigns; it emerges from leave-one-out validation — hold back one predictor, feed it the example, see where its answer falls in the rank ordering of predictions from the others.

The paper estimates this rank by repeatedly training the model with one example held out, then using those ranks to decide which predictions are safe enough to include in the final confidence set. High rank means the predictor is an outlier; low rank means it agrees with most others.

Why it works

Why the voting scheme gives honest confidence

The core move is simple: train many one-shot models and use their disagreement as a signal of unreliability. When you train a model on one example, different random initializations or fitting procedures lead to different answers. If all of them agree, you have a reason to trust the result. If they scatter wildly, you know you should output a wide range.

Leave-one-out validation lets you measure disagreement without wasting the single example. Hold back predictor i, train all the others, ask where predictor i's guess would rank in their distribution. If it always ranks high (is an outlier), exclude it. If it usually ranks in the middle (agrees with the crowd), include it. The math proves that even though you violate the usual exchangeability assumption (your data is tiny and non-random), a monotonicity argument ensures valid coverage: the true answer lands in your confidence set at least as often as you promise.

Math after the picture

The confidence set equation

First in words:

The prediction set is the union of answers from all predictors whose leave-one-out rank is at most the quantile threshold, where the threshold is set so that coverage is guaranteed.

Then the compact form:

C(x) = {y : rank_i(x, y) <= ceil((k+1)(1-alpha) / k)} for a subset of trained predictors i, where rank_i is the quantile of predictor i under the others.

Every symbol:

C(x)the prediction set (all possible answers)
rank_i(x, y)how often predictor i's output on example x, answer y, would rank among others
kthe number of one-shot predictors trained
alphathe target error rate, e.g., 0.1 for 90 percent coverage
ceil(...)round up to the nearest integer
A tiny worked example
Example: k = 4 one-shot models trained, alpha = 0.1 (we want 90 percent coverage).
Threshold = ceil((4+1) * (1 - 0.1) / 4) = ceil(5 * 0.9 / 4) = ceil(1.125) = 2.
Predictor 1 ranks 1 in leave-one-out (central), ranks 2 in leave-one-out (central) — both <= 2, include both.
Predictor 2 ranks 4 in leave-one-out (outlier) — rank > 2, exclude.
Predictors 1 and 3 form the confidence set; their range is smaller and more honest than trusting all four equally.

The threshold is a data-dependent quantile that ensures the final set will cover the true answer most of the time, even though the one example is not random.

What can go wrong

What can go wrong

The one example is not representative. If the single labeled example is from a very different distribution than test examples, the calibration is meaningless. CAOS will still give mathematically valid coverage, but the set will be so wide it is useless.
Too few one-shot models. If you train very few one-shot copies (k too small), leave-one-out ranks fluctuate wildly, and the coverage guarantee is valid but the set is very conservative (very wide).
Model class does not adapt well. If the pretrained model is poorly suited to the new task, all k one-shot learners fail, and CAOS outputs a wide set. The math still holds; the input was just bad.
Done right: data-dependent intervals. CAOS works when you have a pretrained model that can plausibly adapt to the task in one example, and when the one example is at least somewhat typical of the test distribution.
What a runnable demo should prove

What a runnable demo should prove

Build a simple one-shot learning task: take a pretrained image classifier, remove its final layer, and adapt it to a new small dataset using only one labeled example per class. Train between 5 and 20 one-shot copies with different random seeds. For each test example, measure the width of the CAOS confidence set and the actual coverage (whether the true answer is in the set). Compare against split conformal using only half the example. Measure the trade-off: CAOS should give narrower sets, because aggregating all predictors gives more data for calibration than a split, while maintaining the same or better coverage, because the leave-one-out ranks measure disagreement directly.

tightness_gain = (split_conformal_width - CAOS_width) / split_conformal_width, coverage_delta = CAOS_coverage - split_conformal_coverage

The demo must show that CAOS narrows confidence sets without sacrificing mathematical guarantees, the core appeal of the method.
