CollabBench: Benchmarking and Unleashing Collaborative Ability of LLMs with Diverse Players via Proactive Engagement

Test and train agents for cooperation with different kinds of partners by putting them in shared game tasks where communication style and action choices both matter.

Paper explainersAll themesAgents & Tool Use

Many agent benchmarks ask whether one model can finish a task alone. This paper asks a harder question: can an agent work well with a partner whose habits, needs, and emotional reactions are not all the same. CollabBench builds cooperative game settings with varied player profiles and trains agents to balance task progress with partner-aware behavior because good collaboration depends on both.

Zero assumption version

Why single-agent success does not guarantee good collaboration

A model can be good at solving a task by itself and still be a poor teammate. Collaboration requires noticing what the partner knows, when the partner needs a message, and whether a fast action will confuse or frustrate the other player.

Most older evaluations miss this because they focus on isolated task success. They do not force the agent to coordinate with a partner whose behavior changes from one run to another, so they do not reveal whether the agent can adapt its communication and timing.

The paper's move in one sentence. Create cooperative multi-player benchmarks with varied partner profiles and train the agent on rollouts that reward both task progress and partner-aware interaction.

The algorithm as a flow

What it actually does

Simulate diverse players

Create partner profiles with different habits and reactions so that the benchmark tests adaptation rather than one fixed script.

Extend cooperative environments

Use multiplayer versions of game tasks so that action choices and communication both affect the outcome.

Generate collaborative rollouts

Let the agent reason, talk, and act during joint play so that training sees whole cooperation traces.

Score efficiency and partner response

Combine task speed with affective quality because a teammate that reaches the goal while damaging coordination is still weak.

Train from those outcomes

Update the agent toward rollouts that finish the task and maintain stronger interaction with varied partners because those rollouts preserve cooperation while making progress.

What the paper changes

What the paper changes

The paper changes the target from solo problem solving to partner-aware coordination. It treats communication timing and tone as part of the task because those choices shape whether joint action succeeds.

the object it moves  =  the policy that chooses when to communicate, how to communicate, and when to act in a shared task
The hidden quantity

The hidden quantity

measured quantity  =  the partner state that the agent must infer from behavior

The key hidden quantity is the partner's current state: what the partner understands, what the partner expects next, and how the partner is reacting to the exchange. The agent does not receive that state directly.

It has to infer the state from actions and messages. That reading matters because the next best move depends on it. A reminder can slow one partner if that partner already understands the plan, and a direct command can hurt coordination if the partner expects discussion first.

Why it works

Why this works: make adaptation part of the reward

An agent will not learn real collaboration if success is defined only as finishing the game. In that case it can ignore the partner whenever direct action is enough. CollabBench changes the pressure by adding a second requirement: the agent must also interact in a way that fits the partner and supports coordination.

That combination matters because efficiency and partner response can conflict on some turns. By training on whole collaboration traces, the agent sees when a short message or a brief pause helps the partner understand the plan, and those choices receive credit because they improve the shared result.

Math after the picture

Score a collaboration trace by task progress and partner fit

First in words:

A compact summary is to give each shared-task trace one score that combines how efficiently the team finishes and how well the agent adjusts to the partner. Higher total score means better collaboration.

Then the compact form:

collab_score(trace) = efficiency(trace) + alpha * partner_fit(trace)

Every symbol:

collab_score(trace)overall value of one collaboration trace
efficiency(trace)how well and how quickly the team completes the task
partner_fit(trace)how well the agent's messages and actions suit the current partner
alphaweight on the partner-fit part of the score
A tiny worked example
Trace A finishes quickly but gives abrupt messages that confuse the partner.
Its efficiency is 8 and its partner-fit value is 1, so with alpha equal to 1 the total score is 9.
Trace B finishes slightly later but keeps the partner aligned.
Its efficiency is 7 and its partner-fit value is 4, so the total score is 11.
Training prefers Trace B because the team outcome is stronger when coordination stays intact.

The paper uses a fuller training rule, but this equation captures the main design choice: the agent is rewarded for being a better teammate because coordination quality affects whether the team can finish together.

What can go wrong

What can go wrong

Simulated partners can still be simpler than real people. A profile generator may miss rare or contradictory behaviors, so an agent that performs well here can still struggle with messy human interaction.
The affective score can oversimplify interaction quality. If the score reduces social response to a small set of markers, the agent may learn a narrow style that earns points without supporting deeper coordination.
Game tasks may not cover workplace collaboration. Cooperative games are useful because they expose shared planning, but workplace settings can involve longer memory, external tools, and more ambiguous goals.
Done right. The benchmark matters because it treats collaboration as a measurable skill with partner variation rather than assuming one ideal teammate.
What a runnable demo should prove

What a runnable demo should prove

Build a two-player grid task with three partner profiles: cautious, hurried, and easily confused. Give the agent a shared objective that requires both movement and messaging. Log completion time, message timing, and whether the partner follows the plan.

The demo should show that the trained agent changes its behavior across profiles because one interaction style is not best for every teammate. For example, it may send earlier clarifying messages to a confused partner so that later actions line up better.

coordination_gain = success_rate_trained - success_rate_base ; partner_alignment = followed_joint_plan / total_turns

The result should make visible that cooperative skill depends on adaptation to the partner, not only on task competence.
