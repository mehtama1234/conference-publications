TESS: Bridging Modality Gap with Temporal Evolution Semantic Space

TESS extracts simple numerical meaning from text about upcoming events, then uses those numbers to improve time-series forecasts.

Paper explainersAll themesTime Series & Sequential

When you try to forecast future values in a changing dataset (stock prices, traffic, demand), text descriptions of upcoming events can help—because events change patterns that raw numbers alone cannot predict. But text and numbers speak different languages. Text says things qualitatively (a new competitor will shake things up), while forecasting models need exact quantities. TESS bridges this gap by having a large language model convert text descriptions into four concrete numerical signals about what is coming: whether patterns will shift, whether swings will get bigger, whether trends will change shape, and how far back to look.

Zero assumption version

Text and numbers don't align in forecasting

Forecasters have learned that text about the future—news articles, event calendars, expert analysis—can make their predictions better, because events change which patterns to expect. But there is a mismatch: a text description is vague and qualitative (competitors are entering, regulations are tightening), while a forecasting model needs precise numerical inputs (the mean will shift by 5%, volatility will double by Tuesday).

A beginner might try to feed the text directly into the model alongside the historical numbers, hoping the model learns to extract meaning itself. But in practice, the model wastes its energy on irrelevant words—headline pronouns, repeated phrasing, common nouns—and fails to reliably translate abstract claims into actionable numbers. The gap stays open.

In one sentence. TESS has an LLM translate event descriptions into four named numerical signals (shift, volatility, shape, lag), filtered by confidence, and passes those to the forecaster.

The algorithm as a flow

What it actually does

1. Text arrives

Event description (news, calendar, analysis) enters the pipeline.

2. LLM reads and extracts

Structured prompting asks the LLM for four signals: is the mean shifting, will swings grow, is the trend shape changing, how many steps ahead does this matter.

3. Confidence scoring

The LLM also outputs a confidence number for each signal (how sure it is), used to gate weak meanings before they corrupt the forecast.

4. Numerical signals feed the forecaster

The four high-confidence numbers become explicit inputs to the time-series model alongside historical data.

5. Forecast improves

The model now has actionable numerical context and avoids the noise that derailed naive text fusion.

What the paper changes

What the paper changes

TESS changes how text is converted into inputs for the forecaster. Instead of feeding raw text tokens or learned embeddings (lists of numbers automatically learned from data), TESS uses an LLM with explicit prompting to emit four interpretable numerical meanings: distribution shift, volatility scaling, shape change, and forecast lag. These numbers are human-readable and were designed to match what a forecaster actually needs.

the object it moves  =  Text-to-number conversion via structured prompting
The hidden quantity

The confidence score: which meanings to trust

measured quantity  =  Confidence score for each semantic signal

The paper introduces an explicit confidence score: for each of the four numerical meanings the LLM extracts from text, it also outputs how sure it is (0 to 1). A low confidence score means the LLM saw conflicting signals in the text or matched only weak patterns.

TESS filters signals through confidence-aware gating: only meanings above a threshold enter the forecaster, preventing the model from wasting power on half-believable claims. This is the hidden mechanism that actually matters—without it, weak signals would blend together and bury the strong ones, just like the original naive approach.

Why it works

Why filtering confident signals fixes the modality gap

The root problem is that text and numbers have different jobs. A sentence like 'competitor entering this quarter' is abstract—it does not say the mean will rise 12% on Tuesday. A forecasting model trained on historical data cannot reliably learn to convert abstract text into the specific number it needs.

TESS sidesteps this learning problem by having an LLM (which already understands language deeply) do the conversion upfront and explicitly. The LLM outputs not a hidden embedding (learned representation), but four concrete, named numbers that align with how time-series forecasting works: does the mean shift, do swings grow, does the shape change, and how many days ahead. The LLM also outputs confidence because it knows it cannot always be certain—a vague sentence might hint at multiple interpretations.

The forecasting model then receives these four explicit signals, not raw text or learned embeddings. It can use them directly without learning the hard implicit conversion itself. And because only high-confidence signals enter, the model avoids chasing weak or contradictory clues. The gap closes: text meaning now arrives as the precise numerical language forecasting needs.

The confidence-gated signal

First in words:

The forecast model receives four signal types, each with a confidence weight. Only signals above confidence threshold are used. The weighted input is: sum over signal types of (signal value times confidence gate), where gate is 1 if confidence exceeds threshold, 0 otherwise.

Then the compact form:

input_used = sum_j (signal_j * gate_j), where gate_j = 1 if confidence_j > threshold, else 0

Every symbol:

signal_jThe jth numerical meaning extracted by LLM (shift, volatility, shape, or lag)
confidence_jThe LLM's confidence score for that signal (0 to 1)
thresholdCutoff below which signals are discarded
gate_jBinary: 1 if confidence_j exceeds threshold, 0 otherwise
input_usedThe filtered signal passed to the forecaster
A tiny worked example
Signal 1 (shift): LLM says +8% change, confidence 0.92. Threshold is 0.75. Gate = 1. Contributes: 8.0
Signal 2 (volatility): LLM says ×2.3 growth, confidence 0.61. Threshold is 0.75. Gate = 0. Contributes: 0.0
Signal 3 (shape): LLM says steeper trend, confidence 0.88. Threshold is 0.75. Gate = 1. Contributes: steeper
Signal 4 (lag): LLM says 4 days, confidence 0.79. Threshold is 0.75. Gate = 1. Contributes: 4 days
Result: forecaster uses signals 1, 3, 4. Signal 2 is suppressed because LLM was uncertain.

Confidence gating acts as a clean switch: either a signal is strong enough to matter (gate=1) or weak enough to ignore (gate=0), preventing weak signals from averaging down the strong ones.

What can go wrong

What can go wrong

LLM hallucinates or misinterprets. If the text is ambiguous or the LLM misreads it, the extracted numbers can be wrong. Confidence gating helps but does not catch all errors—an LLM might be confidently wrong, especially if the domain is unfamiliar or the text contains subtle implications the LLM fails to parse, because high confidence reflects internal consistency in the LLM, not correctness against reality.
Four signals are not enough. Not every text claim maps to shift, volatility, shape, or lag. Important context about seasonality, holidays, or domain-specific factors might not fit the four primitives, leaving information on the table.
Threshold tuning is brittle. If the confidence threshold is set too low, weak signals slip through and corrupt the forecast. If set too high, real signals are thrown away. The right threshold depends on the dataset and the LLM's calibration.
Done right. TESS works when text genuinely contains signal (news that predicts changes), the LLM is reliable on the domain, and the four semantic types cover the shifts that matter in the data.
What a runnable demo should prove

What a runnable demo should prove

Build a simple time-series forecaster on one real dataset (e.g., a stock price or demand series with known events). Collect 20-30 event descriptions (one-sentence summaries of news or announcements that actually occurred before your data points). Run the forecaster three ways: (1) using only historical numbers, (2) using historical numbers plus raw text fed directly into the model, (3) using TESS—text converted to four numerical signals via a structured LLM prompt, with confidence gating. Measure forecast error on the test set for each.

forecasting_error = mean absolute percentage error on held-out time steps

TESS should show lower error than both baselines—proving that explicit signal extraction and confidence filtering beat both ignoring text and naively fusing it.
