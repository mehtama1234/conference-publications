Adaptive Social Learning via Mode Policy Optimization

Teach a language agent to reason fast or slow depending on what the social situation demands, instead of thinking the same amount every time.

Paper explainersAll themesAgents & Tool Use

Language agents today use the same reasoning depth for every social interaction — they either skip reasoning entirely or write out long chains of thought no matter how simple the task is. This wastes computation and makes their behavior rigid. This paper teaches agents to pick the right reasoning mode for the moment: a quick gut-check for obvious moves, deeper deliberation when the stakes are high. It does this by having the agent first pick which mode to use, then reasoning within that mode, rewarded by how well it reaches its social goals.

Zero assumption version

Why agents reason wrong today

Language agents in social tasks — negotiation, collaboration, conversation — face a painful choice: respond instantly with no thought (cheap but often wrong), or write out long step-by-step reasoning every single time (expensive but only sometimes necessary). If you negotiate a house price with a friend, you do not need to write down your reasoning. But if you are being lied to, you do.

A beginner trying to fix this might say: turn on reasoning for hard tasks, turn it off for easy ones. The problem is the agent does not know in advance how hard a task is. A social negotiation might look simple until you read the human's hidden intentions. The model has to commit to a reasoning mode before it has enough context to know if that mode was the right choice. Most methods either use one fixed mode always, or switch modes in ad-hoc ways with no learning signal.

In one sentence. The paper trains an agent to pick the right reasoning depth for each social moment, learning which moments need thought and which do not.

What the paper changes

What the paper changes

The paper changes how the agent decides between reasoning modes. Instead of committing to one fixed mode or switching at random, it learns a policy — a learned function that takes the social context and outputs the probability of picking each reasoning mode. This policy gets trained by reward signals from real social interaction outcomes.

the object it moves  =  the reasoning mode policy
The hidden quantity

The hidden quantity: mode-level advantage

measured quantity  =  mode-level advantage signal

The paper measures something called the mode-level advantage, which is the average reward the agent gets when using a particular reasoning mode, compared to what it got on average across all modes. This tells the training algorithm which modes are actually working.

Without this, the algorithm would just look at each sample in isolation: did this one response work or not? But many responses work fine regardless of mode — the slow thinking was not needed. The mode-level advantage picks out the samples where the mode choice mattered. A fast mode that worked well, or a slow mode that was wasteful, stands out in the statistics.

Why it works

Why it works: the real chain of cause and effect

A social context arrives — say, a negotiation where the human is hiding their true reservation price. The agent's policy network takes in that context and outputs scores for each reasoning mode. Higher score means the policy thinks that mode is a good bet right now. The policy is initially random, so it picks modes all over the place.

When the agent picks a mode and responds, a reward model (a separate trained evaluator) scores the outcome: did the agent reach its social goal? The score is honest — maybe it succeeded, maybe it failed. Over many interactions, the algorithm collects data: this mode won here, that mode lost there.

The key move is two-level advantage estimation. At the sample level, each response gets a reward signal, just like normal. But the algorithm also pools the rewards by mode across many samples. If intuitive mode won 60% of the time and step-by-step mode won 80% of the time, the algorithm sees that step-by-step is ahead by 20 percentage points on average. This mode-level signal matters because it filters out noise: a single fast response might luck into success, but if fast mode consistently underperforms slow mode on hard social contexts, the algorithm finds the pattern.

The policy is trained to maximize this dual-level advantage: pick modes that both (1) succeeded on this specific sample and (2) tend to succeed for this reasoning mode in this kind of context. Over time, the policy learns: when the social context has high stakes or hidden information, favor the deep modes; when the request is straightforward, pick the fast mode. This saves tokens because it stops wasting deep reasoning on easy cases, and it improves accuracy because hard cases get the thinking they need.

Math after the picture

The equation: dual-level advantage objective

First in words:

advantage from this sample plus advantage from this reasoning mode

Then the compact form:

L_AMPO = E [ (advantage_sample + alpha * advantage_mode) * log(pi(mode|context)) ]

Every symbol:

pi(mode|context)the probability the policy gives to picking this mode in this context
advantage_samplehow much better this response did than a baseline (e.g., average reward)
advantage_modehow much better this reasoning mode performs on average in this kind of context
alphaa weight balancing the two advantages (e.g., 0.5 or 1.0)
A tiny worked example
Context: negotiation about salary. Agent picks step-by-step mode.
Sample reward: 0.8 (succeeded in reaching goal; baseline average is 0.6).
Sample advantage: 0.8 - 0.6 = 0.2.
Mode stats: step-by-step mode averaged 0.75 across all contexts; intuitive mode averaged 0.55.
Mode advantage for step-by-step: 0.75 - 0.55 = 0.20.
Dual advantage: 0.2 + 0.5 * 0.20 = 0.3.
Policy update: raise the probability of step-by-step in salary negotiations by 0.3 * alpha_lr (learning rate), making it more likely next time.

The policy learns to pick modes that both won this time and tend to win for this type of problem.

What can go wrong

What can go wrong

The reward model is biased. If the evaluator (reward model) systematically scores one reasoning style higher just because it looks more professional or formal, the agent will learn to always use that style, not because it works better but because the grading is unfair. The paper notes that different evaluators have different tendencies; this can pollute the mode-level statistics.
Mode choices become context-agnostic. If the policy network does not truly see the context deeply, or if modes are too coarse-grained, the agent falls back to picking one mode most of the time, defeating the purpose. The agent needs detailed representations of social state (dialogue history, goals, stakes) to pick modes that fit the situation.
Feedback is delayed or sparse. In real social interaction, the reward may not arrive until many turns later (e.g., did the negotiation succeed?). If the training data is sparse or the reward signal is weak, the mode-level statistics become unreliable, and the policy has no clear signal.
Done right: mode choice is trained end-to-end. When the reward model is honest, the context is rich, and the training data is dense, the policy learns interpretable mode switching: fast mode for simple requests, deep mode for layered social situations.
What a runnable demo should prove

What a runnable demo should prove

Build a small social task where the agent negotiates or collaborates with a human or simulated partner. Include scenarios where fast thinking suffices (easy requests, clear information) and scenarios where deep reasoning is needed (conflicting goals, hidden information). Train the agent with the AMPO algorithm and observe two things: (1) the policy learns to pick fast mode on easy scenarios and deep mode on hard ones, because the mode-level advantage signal trains it to favor modes that succeed in each type of context; (2) the total token usage drops compared to always using deep reasoning, while the success rate on hard scenarios stays the same or improves, because the mode-level statistics guide the policy to reserve deep thinking only for tasks where it actually helps.

total_tokens_used / baseline_tokens + (success_rate_hard - baseline_success_hard)

The demo must show that mode choices become context-sensitive: the same agent reuses its policy and adjusts reasoning depth on the fly, proving it learned to think harder when it matters.
