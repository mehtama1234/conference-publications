Verifier-free Test-Time Sampling for Vision Language Action Models

A robot learns to pick its best action by measuring how uncertain the model is about each one, using the model's own internal uncertainty without needing an external verifier.

Paper explainersAll themesRobotics & Control

Robot models trained on demonstrations can answer a single action at a time, but to handle precision tasks like precise grasping they need to try multiple candidates and pick the best one. External verifiers that score actions need extra training and do not generalize to new situations. This paper uses the model's own internal uncertainty to score candidates: masking out the current state and instructions from the same model gives a view of the model's uncertainty, and comparing that to the model's actual prediction measures confidence. No extra training on the new task, and the same method works everywhere.

Zero assumption version

Robot models are precise, but fragile on hard tasks

A robot trained on human demonstrations learns to predict the next action: given a camera image and an instruction like pick up the cube, it outputs one action command. This works when the robot sees familiar objects and situations. But when precision matters—like picking up a fragile object where the grasp angle is critical—one prediction fails about half the time. A human doing the same task would try an action, watch closely, and if it does not feel right, try a slightly different angle. A trained robot cannot do that. If you ask it to generate multiple guesses and pick the best one, you need a separate scorer: a verifier module. But building and training a verifier costs time, money, and GPU time. And when the verifier sees a new object shape or lighting it has not seen in training, it confidently gives the wrong score.

A beginner might try to rate each action by how 'activated' or 'hot' the model got when predicting it. But activation strength tells you nothing reliable about correctness—a wrong answer can be high-confidence.

The paper's move: Measure confidence by comparing what the model predicts for the real state and instruction against what it predicts for a blank state and instruction. Big difference means the model is confident in its choice. Small difference means it is confused and guessing.

The algorithm as a flow

What it actually does

At training time (once)

Train the robot model with both normal inputs and with the state and instructions randomly masked out, using dropout. The model learns two distributions: one conditional on seeing everything, one when things are hidden.

At test time (every action)

Get the actual prediction: run the model with real camera image and instruction. Get the uncertain prediction: run the same model with the image and instruction blanked out. Measure the distance between them.

Score multiple candidates

Generate several candidate actions (using beam search or sampling). For each one, measure how different it is from the masked prediction. Large difference means the model is using the state and instruction strongly.

Pick the confident one

Choose the action with the largest difference. It is the one the model trusts most given what it sees.

Execute and repeat

The robot takes that action, gets new feedback from the camera, and repeats for the next step.

What the paper changes

The thing it changes: action scoring at test time

Before: the model makes one action prediction, and you trust it. Or you use an external verifier trained separately. After: you generate a few action candidates and rank them by measuring the model's own internal confidence, without external modules. The object being changed is the decision rule at test time—how you pick which action to execute from multiple guesses.

The hidden quantity

The hidden quantity: action-specific confidence

measured quantity  =  action confidence score

Confidence here means: how much did the model rely on the actual state and language instruction to make this prediction, versus how much is it just guessing? If you hide the instruction and image, does the model still predict the same action, or does it drift? A score of zero means the model's prediction is identical whether or not it can see the state and instruction—so it does not trust the input. A high score means the model's prediction changes a lot when you remove the context—the model was leaning on what it saw.

The paper measures this using KL divergence (a tool that measures how different two probability distributions are). The reference distribution comes from the same model run with masked inputs. The confidence is the divergence from reference to predicted—how far the real prediction drifts from the masked one.

Why it works

Why it works: uncertainty from hiding the inputs

The core insight is that a trained model is brittle: it was built to work best when it can see the camera and instructions. If you delete the instructions and black out the image, the model falls back to generic guessing—it predicts with low confidence because it is missing the information it was trained to use. When the real state and instruction are present, the model uses them to refine its prediction. The bigger the refinement, the more the model relied on those inputs, and thus the more confident it should be.

But confidence is not the same as correctness. The paper's second move is training the model with this uncertainty baked in. During training, you teach the model to learn the masked distribution—what it predicts when inputs are hidden—at the same time as learning the normal task. This way, when you compare them at test time, the masked version is not a hack, it is a trained approximation of the model's own inherent uncertainty. The joint training with dropout makes the reference distribution task-aligned: it is still predicting actions, but without being biased by the specific state or instruction.

Math after the picture

The equation: KL divergence as confidence

First in words:

The confidence score for an action at time step i is the KL divergence from the reference distribution to the predicted distribution. Reference comes from the model run on masked state and instruction. Predicted comes from the model run normally.

Then the compact form:

C_i = KL(Q_i || P_i) = sum_a Q_i(a) * log(Q_i(a) / P_i(a))

Every symbol:

C_iconfidence score at action step i
Q_iprobability distribution over actions when state and instruction are masked
P_iprobability distribution over actions with full state and instruction
sum_asum over all possible actions
loglogarithm (how much to scale the ratio)
A tiny worked example with two actions
Suppose at step i there are two possible actions: grasp-angle-45 and grasp-angle-50.
With masked input (Q_i): the model guesses 60% angle-45, 40% angle-50. Uniform-ish, uncertain.
With real input (P_i): the model predicts 92% angle-45, 8% angle-50. Confident in angle-45.
For angle-45: Q(45)*log(Q(45)/P(45)) = 0.60*log(0.60/0.92) = 0.60*log(0.652) = 0.60*(-0.427) = -0.256
For angle-50: Q(50)*log(Q(50)/P(50)) = 0.40*log(0.40/0.08) = 0.40*log(5.0) = 0.40*1.609 = 0.644
Sum: -0.256 + 0.644 = 0.388. This is the confidence score.
Interpretation: the model refined its belief from 60-40 to 92-8. That large shift is what the KL divergence measures. A confident prediction where the model is sure would score higher.

The KL divergence measures how much the model changed its prediction when given full information versus none, so larger scores mean stronger confidence in the choice, because a model that relies heavily on the inputs it sees will predict very differently when those inputs are hidden.

What can go wrong

Masked prediction is not trustworthy early in training If you just blank out inputs without teaching the model to handle it, the masked predictions are random noise, not a real confidence signal. The joint training with dropout during training is essential.
Masking must preserve task structure The confidence signal only works if masked predictions are plausible but uninformed. If dropout is too strong and the masked model predicts garbage, the comparison to the real prediction becomes meaningless. The dropout strength must be tuned carefully so masked predictions stay within the valid action space, just without using the specific state or instruction details.
Computational cost of beam search Scoring K candidate actions means running the model K times. If K is large or the model is huge, test-time latency grows. The paper shows optimized implementations can keep latency acceptable.
Works best with joint training The method improves base models even without retraining on new tasks, but gains are amplified if you do a small retraining step with dropout on the target task dataset, because learning the masked distribution specifically on the new task data makes the reference predictions task-aligned and more reliable than using a distribution learned only on generic data.
What a runnable demo should prove

What a runnable demo should prove

Build a simple pick-and-place task in simulation where precise grasp angle matters (e.g. grasping a thin object versus a thick cube). Train a small robot model on 30 demonstrations. At test time, generate multiple action candidates via beam search. Score each using MG-Select: run the model once normally, then again with state and instruction masked via dropout. Execute the highest-confidence action. Measure success rate.

improvement = (success_with_MG_Select - success_base) / success_base * 100%

The demo must make clear that the model, when blindfolded, genuinely predicts differently than when it can see—and that the difference tracks real task difficulty, not random noise.
