DAMR: Efficient and Adaptive Context-Aware Knowledge Graph Question Answering with LLM-Guided MCTS

Search through possible relation paths with tree search, use a language model to expand promising options, and train a lightweight scorer to judge partial paths better over time.

Paper explainersAll themesAgents & Tool Use

Knowledge-graph question answering asks a system to map a question onto a path through a structured graph of entities and relations. A common failure is either searching too rigidly with fixed candidate paths or searching too expensively with too many large-model calls. This paper proposes DAMR, which uses Monte Carlo Tree Search to explore reasoning paths, a language model to suggest promising next relations, and a smaller learned scorer to judge partial paths in context. The key idea is to spend large-model effort only where it helps trim the search space, then let a cheaper scorer adapt during search so that path evaluation improves as new partial reasoning traces are discovered.

Zero assumption version

Why graph question answering needs both search and judgment

A knowledge graph stores facts as entities connected by named relations. To answer a question, the system often needs to follow several relations in sequence from a starting entity to the correct answer entity.

The difficulty is that there may be many possible relation sequences. A fixed candidate extractor can miss the right path because it does not adapt to the exact question. A free-form large-model search can adapt better, but it becomes expensive because it repeatedly calls the model while exploring many branches. The system therefore needs a way to search selectively and to evaluate partial paths accurately.

The paper's move in one sentence. Use tree search to explore candidate relation paths, ask the language model which expansions look most relevant, and train a smaller scorer to judge partial paths as the search proceeds.

The algorithm as a flow

What it actually does

Initialize the search tree.

The system starts from the question and one or more anchor entities in the graph.

Expand with guided relation choices.

At each step, the language model proposes the most relevant next relations so that the tree grows in promising directions.

Score partial paths.

A learned scorer evaluates how plausible each partial relation sequence is for the current question.

Back up the search values.

Tree search uses those path scores to decide which branches deserve more exploration.

Refine the scorer over time.

Partial paths discovered during search are reused as new training signal so that the scorer improves on the kinds of traces the search is actually visiting.

What the paper changes

What the paper changes

The paper changes path reasoning from a one-shot retrieve-then-rank step into a closed search loop. The main object is now a partial relation path whose value can be updated as search discovers more evidence.

the object it moves  =  partial graph paths evaluated inside an adaptive tree search
The hidden quantity

The hidden quantity: path plausibility

measured quantity  =  how likely a partial relation path is to lead to the correct answer for this question

The system does not know the full answer path at the start. It must estimate whether a partial path is worth extending. That estimate is the hidden quantity that controls search efficiency.

If the estimate is poor, the tree search wastes effort on branches that look acceptable locally but do not answer the question. If the estimate is strong, the search can spend most of its budget on branches that stay semantically aligned with the question. DAMR tries to improve this estimate during search by training on the partial traces it actually encounters.

Why it works

Why tree search plus a learned scorer can save compute

Tree search gives a disciplined way to choose which branches to explore next. That alone is not enough, because the search still needs a good signal about which partial paths deserve more budget.

The language model helps at expansion time by proposing a small set of relevant next relations, which narrows the branching factor. The learned scorer then helps at evaluation time by rating partial paths more cheaply than repeated large-model calls. Search becomes more effective because one component trims the candidate set and the other component ranks the surviving candidates in context.

Math after the picture

A compact statement of branch choice

First in words:

Choose the next search branch by combining its current value estimate with a bonus for less-visited branches, then update the value estimate using the path scorer.

Then the compact form:

branch_score(path) = path_value(path) + c * explore_bonus(path)

Every symbol:

path_value(path)the current estimate of how promising the partial path is for answering the question
explore_bonus(path)extra credit for branches that have been explored less often
cthe weight that balances exploitation against exploration
branch_score(path)the score used to decide which branch tree search expands next
A tiny worked example
Suppose one partial path has path_value = 0.7 and explore_bonus = 0.1.
A second path has path_value = 0.6 and explore_bonus = 0.3.
Let c = 1.
Then the first branch gets branch_score = 0.8.
The second branch gets branch_score = 0.9.
Tree search expands the second branch next because it is slightly weaker on current value but more underexplored.
After expansion, the scorer updates path_value based on the new partial path evidence.

The important part is that path_value improves over time, because the scorer keeps learning from the partial traces the search process uncovers.

What can go wrong

What can go wrong

The guided expansions miss the right relation. If the language model fails to surface the correct next relation early, tree search may never explore the answer path at all.
The path scorer learns from noisy partial traces. Search-generated supervision can be helpful, but it can also reinforce bad paths if the training signal from those traces is weak.
The graph requires very long reasoning chains. Long paths increase both branching and uncertainty, so even a guided tree search may still struggle when many hops are needed before useful evidence appears.
Done right. The method works when guided expansion keeps the right relations in play and the scorer learns quickly enough to focus tree search on paths that stay aligned with the question.
