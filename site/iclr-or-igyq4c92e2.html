DRBench: Enterprise Deep Research

A benchmark that tests whether AI agents can answer complex multi-step business questions by sifting through both public web pages and private company documents to find and cite the right facts.

Paper explainersAll themesAgents & Tool Use

When a company needs an AI agent to answer a strategic question like 'What should we change in our product roadmap to stay compliant with this regulation?', the agent must search across many sources—emails, files, web pages, chat logs—find the relevant nuggets, and tie them together into a clear written answer. DRBench is a test suite of 100 real business questions across 10 domains (sales, security, compliance) that measures whether agents can do this well.

Zero assumption version

The search problem: too many sources, too easy to miss things

Today, AI agents can search the web and pull back pages. But a real business question often hides the answer across many places. A compliance question might need insights from a regulation website, a company email chain, a file in the file system, and a team chat. One search is not enough.

A beginner agent tries: type the question, search once, summarize the top result. This breaks because most business questions require reading across many documents to find the pieces that matter. One search finds one source. The agent writes a shallow answer, cites a source that does not actually support the claim, or misses the most important insight buried in a private email. The real world is messier than a single web query can handle.

The method in one sentence. DRBench gives agents a set of 100 realistic business questions to answer by iteratively searching, retrieving documents from both web and company files, and producing a final report grounded in the evidence they found.

The algorithm as a flow

What it actually does

Plan sub-questions

Break the big question into smaller sub-questions that guide which documents to search for.

Search and retrieve

Issue queries to web search, company file system, email, chat. Collect candidate documents.

Extract insights

Read retrieved documents and pull out the concrete facts that answer each sub-question.

Verify and deduplicate

Check that each insight is cited, relevant, and not contradicted by other sources.

Write grounded report

Synthesize verified insights into a clear narrative, with citations to the original sources.

What the paper changes

What the benchmark changes

DRBench does not propose a new agent algorithm. Instead, it changes the evaluation target: instead of measuring whether agents can search the web or summarize one document, DRBench measures whether agents can handle multi-step, multi-source enterprise research. This forces agent builders to design systems that iterate, that verify facts against evidence, and that cite sources honestly.

The hidden quantity

The hidden quantity: insight recall

measured quantity  =  fraction of high-value insights found and cited

The paper introduces a new hidden quantity called 'insight recall'. This is the fraction of the truly important facts that an agent actually retrieves and cites in its final report. A high-value insight is one that directly answers part of the business question. Missing insights means the agent's answer is incomplete or misleading. Citing distractors (facts that sound relevant but do not actually support the claim) is also failure.

The paper measures this by having humans first read all the documents and mark which insights are essential. Then it checks whether each agent-generated report cites those same insights. This is not just 'did the agent retrieve a document'—it is 'did the agent extract and cite the exact insight that matters'.

Why it works

Why deep research requires iteration and verification

The mechanism is straightforward: a single search query cannot cover the territory. A compliance question needs insights from three places: a public regulation website, an internal email exchange, and a filed company decision. The first search might hit the regulation page. But searching for the email and the decision requires different queries, or searching across a different source (the company file system instead of the web). No one query finds all three.

This is why the agent must iterate. After each retrieval round, it extracts what it learned and asks: what else do I need to know to answer this question? Then it issues a new search to cover the gap. Over 5–10 iterations, it weaves together insights from different sources. But iteration alone is not enough. If the agent cites facts that do not actually appear in the retrieved documents, or cites distractors that sound relevant but are not, the report is still wrong. So the agent must verify each insight against the original source before including it. The mechanism is: search, then extract, then verify, then if still incomplete, loop back. An agent that skips verification may cite a distractor. An agent that searches only once misses high-value insights.

Math after the picture

The scoring formula

First in words:

insight_recall = (number of marked insights cited by agent) divided by (total number of marked insights). distractor_penalty = (number of cited insights not in marked set) divided by (total cited).

Then the compact form:

final_score = 0.6 * insight_recall + 0.3 * (1.0 - distractor_penalty) + 0.1 * report_coherence

Every symbol:

insight_recallfraction of important facts the agent found and cited (0 to 1)
distractor_penaltyfraction of cited facts that sound relevant but do not matter (0 to 1)
report_coherenceLLM-judged score of how clear and well-structured the final report is (0 to 1)
final_scoreweighted average: recall is most important, distractors hurt, coherence is a tiebreaker
A tiny worked example
Suppose the question has 10 marked high-value insights. The agent retrieves documents, extracts 8 of those 10, but also cites 2 distractor facts. insight_recall = 8 / 10 = 0.8. distractor_penalty = 2 / (8 + 2) = 0.2. Assuming coherence = 0.9, final_score = 0.6 * 0.8 + 0.3 * (1.0 - 0.2) + 0.1 * 0.9 = 0.48 + 0.24 + 0.09 = 0.81.
If the agent cites all 10 insights and no distractors, insight_recall = 1.0, distractor_penalty = 0.0, final_score = 0.6 * 1.0 + 0.3 * 1.0 + 0.1 * 0.9 = 0.99.
If the agent cites only 3 insights and 5 distractors, insight_recall = 0.3, distractor_penalty = 5 / 8 = 0.625, final_score = 0.6 * 0.3 + 0.3 * 0.375 + 0.1 * 0.9 = 0.18 + 0.1125 + 0.09 = 0.3825. Missing insights and citing wrong facts both hurt.

The scoring formula rewards agents that find important facts, penalizes distractors, and requires coherent writing—which forces real multi-step reasoning, not just search-and-paste.

What can go wrong

What can go wrong

One-shot search agents miss high-value insights. If the agent searches once and summarizes the top result, it will miss facts in emails, internal PDFs, or less-indexed documents. The score drops because insight_recall is low. The agent may sound confident but is incomplete.
Distractor hallucination inflates report length. An agent may fabricate supporting facts if it has not retrieved a document that confirms them. Or it may cite a real document but misinterpret it, claiming a fact is there when it is not. This raises the distractor_penalty and lowers the final score. Verification catches some of this but not all if the agent is sloppy.
Iteration without stopping criteria wastes time. If an agent loops forever, searching for facts it has already found, it gains nothing. DRBench includes a maximum iteration limit (e.g., 15 loops) to prevent this, but an agent that does not learn to detect convergence will consume resources on diminishing returns.
Done right: multi-loop + verification + clear synthesis. An agent that plans sub-questions, iterates with varied search queries, verifies each insight, and stops when new searches yield no new marked insights will score well across insight_recall, distractor_penalty, and coherence.
What a runnable demo should prove

What a runnable demo should prove

Take a realistic business question (e.g., 'What are the regulatory requirements our product must meet in the EU?'). Provide the agent with access to a company file system (10–20 documents: PDFs, emails, chat logs), a web search tool, and a URL list of relevant regulations. Run the agent, collect its final report. Manually mark which insights in those documents are truly essential to answering the question. Score the agent on how many marked insights it found and cited.

deep_research_score = 0.6 * (found_insights / total_marked_insights) + 0.3 * (1.0 - distractor_fraction) + 0.1 * coherence_score

The demo must make it impossible to ignore that agents which search only once will score much lower than agents that iterate, and that citing distractor facts is a major failure—not a detail.
