OVSeg3R: Learn Open-vocabulary Instance Segmentation from 2D via 3D Reconstruction

Use 2D object masks from videos and 3D scene reconstruction to teach a 3D model which objects are which, even for objects it has never seen before.

Paper explainersAll themesRobotics & Control

Humans learn to recognize objects by seeing them from many angles in 3D space. But 3D object recognition models are expensive to train because they need hand-labeled 3D scenes. This paper asks: what if we borrowed the free 2D labeling (a trained 2D model that recognizes any object in a photo) and used 3D reconstruction to lift those labels into 3D? The trick is stitching 2D answers across views and keeping blurry 3D point clouds from merging nearby objects together.

Zero assumption version

The cost of 3D labels

Right now, 3D object models learn from hand-labeled 3D scans. A human sits and marks each object in a 3D scene, which is slow and expensive. We have great tools for 2D images: you can take any photo and a trained model will find and label every object in it, and it works on objects it has never seen in training. But moving those 2D answers to 3D is not straightforward. The 3D model has to reason about the full 3D shape, not just a single view, and rough 3D reconstruction often blurs out the boundaries between nearby objects.

A beginner would try: run 3D reconstruction on videos to get a 3D point cloud (a cloud of 3D coordinates), then use the 2D model to label the points. But this breaks because: 1) the same part of an object appears in many frames as many different 2D predictions, and there is noise; 2) 3D reconstruction blurs the shape information, so nearby objects merge together; 3) you never know if a small difference is a real boundary or just reconstruction error.

The core problem. We have free 2D object labels but no cheap way to turn them into reliable 3D labels.

The algorithm as a flow

What it actually does

Step 1: Record videos

Capture a 3D scene from many camera positions as it stays still.

Step 2: Reconstruct 3D

Feed the video frames into a 3D builder to extract a point cloud and camera positions.

Step 3: 2D predictions per frame

Run the 2D object model on each frame, getting a mask for every object it sees.

Step 4: Partition into views

For each 3D point, find which 2D masks claim it belongs to. Assign it only to its own camera frame's masks (do not mix predictions across views).

Step 5: Boundary-aware clustering

Group 3D points into clusters (super-points) using their position, but stop clusters at 2D object boundaries so no cluster contains pieces of two different labeled objects.

What the paper changes

What the paper changes

OVSeg3R changes how 3D points get their object labels. Instead of the model guessing from point positions alone, it takes in both a 3D point cloud and the corresponding 2D masks from video frames, then uses the 2D masks as a constraint on position-based clustering.

The hidden quantity

The hidden quantity: Instance boundary fidelity

measured quantity  =  Boundary fidelity between 2D and 3D

The paper measures whether 3D object clusters actually respect the 2D mask boundaries. When 3D reconstruction is fuzzy, a cluster might accidentally include pixels from two different 2D objects. The paper introduces a hidden quantity: how well do the final 3D clusters match the boundaries drawn in 2D masks? Clusters with high fidelity stay within one 2D object's region; clusters with low fidelity leak across the boundary into another object.

The paper estimates boundary fidelity by checking: after clustering, does every 3D point in a cluster belong to the same 2D object mask across all camera views that see it? A cluster is clean if yes, polluted if a point claims membership in two different object labels. The paper's method uses 2D masks as hard constraints during clustering, so high fidelity is enforced by design.

Why it works

Why the method works

The core insight is that 3D reconstruction produces blurry point clouds but 2D masks from photos are sharp. So the method uses 2D as a teacher for 3D. First, it projects the sharp 2D object masks onto the 3D point cloud using the known camera positions. This tells every 3D point which object it belongs to, viewed through each camera. Then, when clustering nearby 3D points into groups (super-points), the method enforces that no cluster can contain points that belong to different objects in any 2D view. This is like saying: do not draw a line across a 2D object boundary when you are building 3D groups. The result: even if the 3D points are ambiguous, the clusters respect object identity because they are constrained by 2D. Finally, the method only uses clusters from single camera views for training (a technique called view-wise partition), so it avoids mixing conflicting predictions across views. This gives the model clean, unambiguous supervision.

Math after the picture

The boundary constraint in math

First in words:

For each 3D point p in cluster C, require that all camera views that see p label it the same object class.

Then the compact form:

forall p in C, forall views v1, v2 that see p: label_v1(p) == label_v2(p)

Every symbol:

pa 3D point coordinate
Ca cluster of nearby 3D points
va camera view (frame)
label_v(p)the object label that view v assigns to point p
A tiny worked example
Point P1 is visible in camera view 1 (Camera1) and camera view 2 (Camera2).
Camera1's 2D model says P1 is on a mug. Camera2 agrees.
Point P2 is also nearby. Camera1 says P2 is mug. Camera2 says P2 is table.
Candidate cluster: P1 + P2. Check the constraint:
P1: Camera1=mug, Camera2=mug. Consistent. OK.
P2: Camera1=mug, Camera2=table. NOT consistent. Reject.
Result: P1 and P2 cannot be in the same cluster, even if they are spatially close.
Only points that all cameras agree on can cluster together.

This constraint acts like a hard wall: point position alone cannot pull points together if 2D masks say they are different objects.

What can go wrong

What can go wrong

3D point cloud too damaged. If 3D reconstruction completely mangles the scene (missing big pieces, twisted shapes), projecting 2D masks onto the cloud may miss or misalign. The method works only on points the 3D builder outputs, so if a region is missing, the 2D labels cannot reach it since there are no 3D points to label.
2D model is wrong. If the 2D object recognizer misidentifies an object, it will teach the 3D model the wrong label. The method has no way to catch this; it trusts the 2D source.
Fast camera motion. If the camera moves so quickly between frames that there is no overlap in what each frame sees, the reconstruction is fragile. Few 3D points get constraints from multiple views, so the boundary fidelity check fails.
Done right. When the video is captured steadily, the 3D reconstruction is reasonable, and the 2D model is accurate, the method produces clean clusters that match both point positions and object identity.
What a runnable demo should prove

What a runnable demo should prove

Record a short video of a desk with a few objects (mug, pen, phone, notebook). Run standard 3D reconstruction (COLMAP or similar) to get a point cloud. Run a 2D vision model (like a foundation model that knows any object) on each frame to get masks. Implement the boundary-aware clustering: for each potential group of nearby 3D points, check whether all points agree on their object label across all cameras. Count how many objects the 3D model recognizes both in training data and outside of it. Plot accuracy on seen versus unseen classes.

Accuracy on unseen objects = correct labels on novel objects / total points on novel objects

The critical evidence: the model should label never-before-seen objects just as well as familiar ones, because it learned object identity from the 2D model rather than memorizing training data.
