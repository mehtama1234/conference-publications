DistMatch: Adaptive Binning via Distribution Matching

When predicting the next value in a time series, partition old prediction errors into groups where each group stays stable, so you can make locally honest confidence intervals that don't break when the data shifts.

Zero assumption version

Time series break the rules that uncertainty methods depend on

When you predict the next value in a time series (stock price, temperature, sales), you want to know not just your best guess, but also how confident you should be. A naive approach: fit a model, measure how wrong it was in the past, and assume it will be just as wrong in the future. But this breaks when the series changes over time.

Real time series have temporal dependencies (today affects tomorrow) and distributional shifts (the noise level or pattern changes). A model trained on the first year of stock data may work well on year two, then suddenly fail on year three when the market regime shifts. The error pattern changes, so last year's confidence intervals are no longer honest.

The blind spot. Standard methods assume past observations are independent and unrelated, but in time series each time step builds directly on what came before.

The algorithm as a flow

What it actually does

Collect prediction errors

Run your time series model and record how wrong each prediction was.

Test each split for stability

Use a statistical test (Kolmogorov-Smirnov) to check if two groups of errors have the same distribution.

Build a decision tree of stable groups

Recursively split errors in half, and keep splitting only where the test detects a real change.

Fit a confidence model per group

Within each final group, estimate how wrong predictions typically are (quantile regression).

Update online as new data arrives

Immediately recalibrate confidence for each group as the time series extends.

What the paper changes

What the paper changes

The paper changes how you partition the time series when building uncertainty estimates. Instead of treating all past errors as one group, it recursively divides them into separate subgroups. Each subgroup is chosen so that within it, the error pattern stays the same (is exchangeable, meaning the past and future have the same statistical properties).

the object it moves  =  Error partitions
The hidden quantity

The hidden quantity: distributional stability

measured quantity  =  Error distribution stability

The paper measures whether a group of prediction errors actually has a stable statistical shape. Stable means: if you drew randomly from the first half of a group, it would look the same as drawing from the second half. Unstable means: something changed, so older errors follow a different pattern than newer ones.

The paper uses the Kolmogorov-Smirnov statistic to measure this. Sort all the errors from the first half of the group from smallest to largest, and do the same for the second half. Then compare: at each position in the sorted list, how far apart are the values? A small difference means the group is stable and can be treated as one unit. A large difference means you need to split it.

Plain reading. Stability is how much the error pattern changes when you move forward in time. Measure it by comparing sorted error lists from two halves of the time series.
Paper reading. The Kolmogorov-Smirnov statistic is the largest vertical gap between two sorted cumulative distributions. Large gap means the distributions differ; small gap means they are approximately the same.
Why it works

Why partitioning into stable groups fixes the problem

Confidence intervals work by asking: given the errors I saw before, what range should I predict for the next one? This only works if the past is truly representative of the future—if the error distribution does not change. When it does change, your confidence interval becomes dishonest: it is too tight when volatility rises, too loose when it falls.

By partitioning errors into subgroups where the distribution is truly stable within each group, you restore that assumption locally. Now each subgroup is exchangeable (the sorted order of errors in the past half looks like the sorted order in the future half), so you can build honest confidence intervals for each. When you make a new prediction and it lands in a high-volatility regime, you use the wider confidence interval from that regime, not the narrow one from calm periods.

Math after the picture

The partitioning rule

First in words:

For each group of errors, compute how different the first half looks from the second half using the Kolmogorov-Smirnov test. If the test says they differ significantly (test statistic exceeds a threshold), split the group in half and repeat on each piece. If not, keep the group and build a quantile regression model inside it.

Then the compact form:

KS(F_first_half, F_second_half) > threshold ? split : keep_group

Every symbol:

KS(F1, F2)Kolmogorov-Smirnov test comparing two distributions F1 and F2
F_first_halfcumulative sorted list of errors in the first half of the group
F_second_halfcumulative sorted list of errors in the second half of the group
thresholdsignificance level (typically 0.05) — if test statistic exceeds this, distributions are too different
A tiny worked example
Suppose you have 100 prediction errors from a time series.
First 50 errors: mostly in the range -0.5 to +0.5 (calm market).
Last 50 errors: spread over -2.0 to +2.0 (volatile market).
Sorted list of first 50: [-0.48, -0.45, ..., +0.50] (tight cluster).
Sorted list of last 50: [-1.95, -1.88, ..., +2.05] (wide spread).
KS test: at every percentile, the gap between the two cumulative curves is large (e.g., the 50th percentile is at 0.01 for the first half and 0.40 for the second).
Conclusion: KS statistic is large, exceeds threshold. Split the group into two subgroups.
Now build a narrow confidence model for first 50 (market is calm) and a wider one for last 50 (market is volatile).

The KS test is not about the mean or variance—it checks if the entire sorted shape is the same. This catches all kinds of changes (shifts in center, changes in spread, outliers appearing).

What can go wrong

What can go wrong

Too many splits create overfitted groups. If you split too aggressively, each leaf has few errors, so your confidence estimates become noisy. The cure: use a higher significance threshold (make it harder to justify a split), or require a minimum group size before splitting.
The KS test is sensitive to the sample size. With many errors, the KS test can reject a match even if the distributions are close enough for practical purposes. With few errors, it may accept a mismatch out of sheer noise.
Future distributional shifts you have not seen yet. DistMatch adapts to shifts in the training data, but if a brand-new regime arrives (a black-swan event), your confidence intervals may still be too tight until the model retrains.
Done right. When you update online (recompute partitions as new data arrives) and tune the split threshold carefully for your domain, DistMatch builds confidence intervals that stay honest through real-world distributional shifts.
What a runnable demo should prove

What a runnable demo should prove

Write a simple time series prediction task: e.g., predict the next month's temperature given the previous 12 months, using a linear or neural network model. Introduce a controlled shift in the middle (increase the noise level, or shift the mean). Fit the naive method (one confidence interval for all) and DistMatch on the training data. On the test data, measure how many true future values fall inside each method's predicted confidence interval.

Coverage = (number of true test values within predicted interval) / (total test values)

DistMatch should maintain 90% coverage throughout (including during the shift), while the naive method drops to 40-50% coverage during the high-noise period.
