ComMem: Brain-Inspired Dual-Memory Test-Time Adaptation

VLMs learn better on new data by running two memory systems together—a fast cache that captures detail and a slow store that holds concepts—just like your brain's hippocampus and cortex.

Paper explainersAll themesRepresentation & Self-Supervised Learning

Vision-language models like CLIP start strong on new tasks but struggle when real test data drifts away from their training data. ComMem solves this by teaching the model to adapt on-the-fly, using two memory systems: a fast-changing detailed cache that grabs what is unusual and different, and a slow-changing concept store that keeps the model's core knowledge safe. These two systems update each other continuously through a consistency penalty that pulls their predictions into alignment, so the model gets better without forgetting because the fast cache can chase new patterns while the slow store anchors back to pre-training every time it resists, keeping the ship steady.

Zero assumption version

Models drift when test data looks different

Vision-language models (large models trained to match images to text captions) are pre-trained on millions of internet images and work brilliantly at first. But in the real world, test images often drift: lighting changes, camera angles shift, or entirely new types of images arrive. The model's accuracy drops.

A naive fix is to tweak the model's weights on each test image to make it more confident about its guess. But this is risky. The model can overfit to noise in single images (chasing a false pattern in one corrupted photo), or keep changing itself so much it forgets what it learned before (every new update erases traces of old learning). Early test-time adaptation methods adapt each image in isolation, so the model never accumulates or consolidates lessons—it is amnesic, like waking with no memory each time, because there is no system that slowly remembers what is reliably true across multiple examples.

The core problem. Models need to learn from streaming test data without forgetting pre-training and without overconfident self-training on noisy individual samples.

What the paper changes

What the paper changes

ComMem changes how the model's internal feature representations (the numbers encoding what the image looks like) are updated during test-time adaptation. Instead of one monolithic adaptation process, the paper runs two parallel feature pipelines—a detailed cache that updates on every sample and an abstract store that learns slowly—and couples them through a consistency penalty so they agree.

the object it moves  =  Two coupled memory feature representations
The hidden quantity

Cross-modal consistency: how well the two systems agree

measured quantity  =  Consistency between fast and slow memory

ComMem works by keeping two different internal memories of what the image means: one that is flexible and updates instantly (the hippocampal cache), and one that is stable and changes slowly (the neocortical store). A key hidden quantity is how consistent these two views are. If the fast cache and slow store give the same prediction for the same test image, the update is safe and reliable. If they disagree sharply, the model is uncertain and should hold back.

The paper estimates this consistency by computing the distance (in the space of features and predictions) between what the detailed cache produces and what the abstract store produces, then uses this as a soft constraint (a penalty term called Lconsistency) that pulls the two systems into alignment.

Why it works

Why two systems beat one

Test-time adaptation has a fundamental tension: learn from new data quickly (plasticity), but do not overfit or forget old knowledge (stability). A single system cannot do both well at the same time. ComMem breaks the deadlock by running two specialized systems in parallel.

The detailed cache (inspired by the hippocampus) updates on every sample and captures what is unusual or fresh about each image. It is fast and plastic, so it reacts immediately to domain shift. The abstract store (inspired by the neocortex) consolidates semantic knowledge and changes slowly, so it resists overfitting and preserves pre-training.

A single consistency loss couples them: when both systems predict the same class, the model is confident and makes a big update; when they disagree, the model is uncertain and updates less or pauses. This feedback loop prevents the fast system from overfitting (because the slow system pulls it back) and prevents the slow system from being blind to real drift (because the fast system flags new patterns).

The paper also uses sample selection (entropy-based confidence thresholding) to feed only trustworthy samples into training, further reducing self-training noise.

Math after the picture

The joint learning equation

First in words:

Total loss equals prediction entropy loss plus consistency penalty plus sparsity regularization; we minimize this jointly for both cache and abstract store.

Then the compact form:

L_total = L_entropy(cache) + L_entropy(store) + lambda_c * L_consistency(cache, store) + lambda_s * L_sparsity

Every symbol:

L_entropy(memory)Entropy-based loss: encourages confident, peaked predictions
L_consistency(cache, store)Distance between cache and store embeddings: keeps them aligned
lambda_cWeight on how strong the consistency pull is
lambda_sWeight on sparsity regularization
L_sparsityPenalty on unused features to keep representations compact
A tiny worked example
Suppose on one test image: cache entropy = 0.8, abstract entropy = 1.2 (low confidence), consistency distance = 0.3 (they agree reasonably), sparsity = 0.1.
With lambda_c = 0.5 and lambda_s = 0.01: L_total = 0.8 + 1.2 + 0.5*0.3 + 0.01*0.1 = 2.00 + 0.15 + 0.001 = 2.151.
If entropy gets better (cache = 0.4, abstract = 0.6) but consistency worsens (distance = 0.8): L_total = 0.4 + 0.6 + 0.5*0.8 + 0.001 = 1.00 + 0.40 + 0.001 = 1.401, which is better overall.
The model trades off: lower entropy (more confident guessing) is good, but if it makes the two systems disagree, the consistency penalty pushes back and prevents unstable overfitting.

The consistency penalty is the key: it stops either memory from drifting too far from the other, enforcing a balance between fast adaptation and knowledge stability.

What can go wrong

What can go wrong

Both systems overfit together. If entropy or confidence thresholding is too loose, both cache and store can overfit to noisy samples in tandem, defeating the benefit of two independent views. Fix: tune entropy thresholds and confidence weighting carefully.
Consistency penalty is too strong. If lambda_c is too high, the cache is forced to match the slow store so closely it cannot detect real distribution drift quickly. Fix: balance consistency weight against entropy loss.
Abstract store learns stale concepts. If the consolidation from cache to store is too slow, the abstract memory lags and becomes obsolete when the test distribution shifts dramatically. Fix: adapt consolidation rate to shift magnitude.
Done right. Entropy thresholding selects only high-confidence samples because low information spread means the model is certain about its guess, so the update is likely correct and not chasing noise; consistency allows quick reaction because when both cache and store agree on a class, a fast weight update is safe and will not cause either system to overfit; slow consolidation preserves pre-training because abstract store changes only in small, gradual increments, so old learned patterns survive and are not erased by a single test sample; fast cache adapts because it updates instantly on every sample and reacts immediately to real new patterns; the balance makes ComMem work under gradual drift (slow system prevents forgetting) and sudden shifts (fast system detects and adapts).
What a runnable demo should prove

What a runnable demo should prove

Build a simple test-time adaptation experiment: take a pre-trained CLIP model, load a vision-language dataset like ImageNet-C (which has corrupted versions of ImageNet: blur, fog, frost, rain, etc.), and run two competing methods—a single-adapter baseline and ComMem—on a stream of corrupted test samples arriving sequentially. Measure accuracy on the original classes and the consistency between the two internal memory predictions (cache vs. abstract store) as samples arrive.

Accuracy = count(correct predictions) / total test samples; Consistency = 1 - mean(distance between cache and store embeddings)

The key observation: ComMem's consistency metric should stay high (close to 1) throughout the stream, while the single-adapter baseline's internal agreement should degrade as it overfits or forgets. High consistency should correlate with high accuracy retention.
