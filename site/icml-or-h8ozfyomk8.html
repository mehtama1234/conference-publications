Learning Permutation from Structure Without Supervision

When teaching a model to uncover a hidden ordering, give each position its own temperature dial instead of one global knob, so confident positions lock in while uncertain ones keep exploring.

Paper explainersAll themesOptimization

Many real problems hide an ordering inside unordered data—like sorting an array by value, or assembling a scrambled jigsaw puzzle from its shape and colors. A model can learn this hidden ordering without being shown the answer by just checking if the reordered data looks right. The catch: different positions in the ordering become clear at different speeds, but old methods force all of them to sharpen or blur at the same rate, causing the training to wobble and fail at scale. This paper's move is to give each position its own temperature dial, so confident positions freeze early while uncertain ones keep exploring.

Zero assumption version

The ordering is hidden, but not all positions agree

Imagine you want to sort an array of numbers, but the model has never seen a sorted array before. It only knows the rule: if the array is sorted, it will feel right. So it reorders the data over and over and checks if each reordering satisfies the rule. The catch is that some reorderings are clearly wrong (putting large numbers before small ones fails badly), while others are almost correct but ambiguous—maybe several orderings look equally right.

A naive approach uses one global confidence dial for the entire permutation. The dial starts loose (the model can try many orderings) and tightens gradually (eventually it locks in). The problem: a position that is clearly correct is forced to stay wiggling until other positions catch up. This causes instability—the training jumps around, and on large problems it breaks entirely.

The fix in one sentence. Use a local uncertainty-adaptive temperature that adjusts each position's confidence dial based on how sure the model already is about that position, rather than forcing all positions to sharpen at the same rate.

The algorithm as a flow

What it actually does

Compute soft assignment

The model produces scores for each possible position, then soft-assigns pieces using a reversible transformation that approximates choosing one position.

Measure confidence per position

For each position, compute how spread-out the soft assignment is. A concentrated distribution means high confidence; a flat distribution means high uncertainty.

Adjust each position's dial

For confident positions, tighten the dial so they lock in quickly, because the model already knows what belongs there. For uncertain positions, keep the dial loose, because ambiguous alternatives still deserve exploration and the model needs room to find which one is actually correct.

Recompute permutation with local dials

Apply the position-specific dials and recompute the soft assignment, so each position now has its own sharpening rate.

Check structure and adjust

Reorder the data using the new soft assignment and test if it satisfies the goal (is it sorted, does the jigsaw look coherent). Measure how much the result falls short, and use that measurement to nudge the scoring function toward better predictions, because a bigger error signal points to which scores need to move.

What the paper changes

What the paper changes

The paper modifies a standard relaxation method called Gumbel–Sinkhorn, which normally uses a single global temperature to gradually sharpen soft assignments into discrete choices. Instead of one temperature for the entire permutation matrix, the paper introduces local temperature fields—one for each row and column—that vary based on how confident the soft assignment already is at that position.

the object it moves  =  the temperature setting, making it local and adaptive
The hidden quantity

Assignment entropy: how uncertain is each position

measured quantity  =  Per-position assignment entropy

When the model produces soft assignments (probabilities spread over possible positions), the entropy measures how concentrated or diffuse that distribution is. High entropy means the model is unsure—it spreads probability across many positions equally. Low entropy means the model is sure—it puts most probability on one position.

The paper computes this entropy separately for each row and column of the assignment matrix. Confident rows and columns have low entropy; ambiguous ones have high entropy. The paper then uses this entropy value to adjust that position's temperature dial: high entropy gets a lower temperature (staying loose), low entropy gets a high temperature (tightening to discretize).

Plain reading. Entropy is just how spread-out a probability distribution is. If the model assigns 99% confidence to one position and 1% to others, entropy is low. If it assigns 50% to one and 50% to another, entropy is high.
Paper reading. The paper defines entropy as the sum of negative probabilities times their logarithms, computed per row and column. It then passes this through a scaling function to compute the per-position temperature adjustment, ensuring confident assignments sharpen while uncertain ones stay diffuse.
Why it works

Why local entropy control beats a global temperature

Here is the core reason the method works. In a typical assignment problem, some rows and columns of the assignment matrix naturally become confident early—the model quickly learns that certain pieces must go in certain positions. Other rows and columns remain ambiguous because multiple orderings satisfy the goal equally well, like a jigsaw puzzle rotated 90 degrees looking just as coherent.

With a single global temperature, the training dial is either loose (all assignments stay soft and explore) or tight (all assignments push toward discrete choices). This creates a mismatch: confident positions that are ready to lock in cannot, because the dial is still loose. When the dial finally tightens, ambiguous positions are forced to commit prematurely and jump around, destabilizing the entire system.

The adaptive local temperature solves this by letting each position use its own dial. Confident positions see a high effective temperature (strong push toward discretization) and lock in early, anchoring that part of the solution. Ambiguous positions see a low effective temperature (gentle push, room for exploration) and continue exploring, finding the right answer at their own pace. This heterogeneous sharpening removes the bottleneck: the training no longer waits for the slowest position, and the model reaches a stable, discrete permutation much more reliably.

Math after the picture

The temperature adjustment formula

First in words:

For each row and column, the local inverse temperature is the base inverse temperature divided by one plus a scaling function applied to the entropy at that position. This causes high-entropy positions to get lower effective temperatures and low-entropy positions to get higher effective temperatures.

Then the compact form:

beta_row_i = beta_0 / (1 + b(H_row_i)) , beta_col_j = beta_0 / (1 + b(H_col_j))

Every symbol:

beta_row_ilocal inverse temperature for row i (higher means sharper, more discrete)
beta_0base inverse temperature at training step (annealed over time)
H_row_ientropy of the soft assignment in row i (high entropy = uncertain, low entropy = confident)
b(H)a scaling function that maps entropy to a positive adjustment (higher entropy gives higher value)
beta_col_jsame adjustment applied per column j
A tiny worked example with five positions
Suppose base beta_0 = 10, and at this training step we compute row entropies:
Row 1 entropy: 0.1 (very confident) -> b(0.1) = 0.2 -> beta_row_1 = 10 / (1 + 0.2) = 8.3
Row 3 entropy: 1.2 (very uncertain) -> b(1.2) = 4.0 -> beta_row_3 = 10 / (1 + 4.0) = 2.0
Row 1 sees effective temperature 8.3 (tight, sharpen fast). Row 3 sees temperature 2.0 (loose, explore).
After Sinkhorn normalization with these local temperatures, Row 1 assignments are nearly deterministic (close to 0 or 1), while Row 3 assignments stay soft (spread across values like 0.4, 0.3, 0.2).

The division in this formula is the core mechanism: high uncertainty increases the denominator, lowering the effective temperature and keeping that position soft and exploring; low uncertainty decreases the denominator, raising the effective temperature and making that position discretize.

What can go wrong

What can go wrong

Entropy function is noisy early in training. In the first few training steps, the soft assignments are nearly uniform, so all entropies are high and all local temperatures are low. The method does not sharpen anything and training stalls. Fix: use a warm-up phase with a fixed global temperature before switching to adaptive control, or bias the entropy measurement toward the model's strongest scores.
The scaling function b(H) must be chosen carefully. If b(H) is too aggressive (grows too fast with entropy), uncertain positions stay so soft they never converge. If b(H) is too weak, it reverts to near-global behavior and the stability gains disappear. The paper uses a learned or heuristic function; the right choice depends on the problem.
Blocking feedback is critical. The paper blocks the learning signal from flowing backward through the entropy-based controller when computing entropy, so the entropy measurement stays stable and does not get caught in a feedback loop. Without this blocking, the entropy signal becomes circular: it adjusts temperature, which changes the assignment, which changes entropy, which reinforces the adjustment. This reinforcing cycle can cause the assignments to oscillate and destabilize.
Done right, the method converges reliably. When entropy is computed cleanly, the scaling function is well-calibrated, and stop-gradient is applied, the local dials self-adjust smoothly: confident positions discretize and anchor the solution, while uncertain positions explore and eventually converge to the right answer.
What a runnable demo should prove

What a runnable demo should prove

Build a simple jigsaw-puzzle solver that scrambles a 10-by-10 image into 100 random tiles, then trains the model to reassemble it. Use a smoothness objective: adjacent tiles in the reordered image should have similar colors, so discontinuous boundaries are penalized. Train two models side by side: one using fixed global temperature, one using adaptive uncertainty-based local temperatures. Plot the stability metric (how much the assignment oscillates between steps) and the final reconstruction quality (how many adjacent pairs have low-color-distance) for both over 500 training steps. The adaptive model should show lower oscillation early on because confident positions lock in and stay locked, anchoring the solution and reducing thrashing, while still achieving better final quality because uncertain positions explore longer and find genuinely better answers.

stability = mean absolute change in assignment matrix between step t and step t+1; quality = fraction of adjacent tile pairs with color difference less than 30 in RGB space

The demo must show that the adaptive model locks in confident positions early and keeps them locked (stabilizes faster because no more energy is wasted on positions that are already solved), while uncertain positions continue exploring and improve (final quality is higher because exploration time is spent only where it helps), whereas the fixed temperature model wobbles unpredictably as it tries to force all positions to sharpen together, wasting training on positions already solved and shortchanging positions that need exploration.
