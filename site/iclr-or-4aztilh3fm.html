TableDART: Dynamic Adaptive Multi-Modal Routing for Table Understanding

Instead of forcing every table through both text and image pathways, use a lightweight decision network to pick the best single path for each specific table.

Paper explainersAll themesMultimodal

Tables are tricky because they have two sides: words convey precise meanings, while pictures preserve structure. Existing methods cram both into one model, creating redundancy and confusion. TableDART picks the right view for each table without expensive retraining, using a tiny decision gate of 2.59 million tunable weights that routes work to text-only, image-only, or fused answers.

Zero assumption version

Tables lose information either way

Tables have two natural views. If you flatten them into words, a language model reads them like text, but the grid structure vanishes — you lose where things sit relative to each other. If you convert them to pictures, the structure stays visible, but the words become fuzzy pixels, and the model can no longer read exact numbers or labels crisply.

A beginner tries to fix this by shoving both views into a single large model at once. The model now has redundant information (the same facts twice), and when the text says one thing and the image shows another, the model has no clean way to choose. It pays a heavy training cost and often cannot adapt to new tables without expensive retraining.

The problem in one sentence. Existing methods force both text and image into every table, wasting computation and creating conflicts between the two views.

The algorithm as a flow

What it actually does

Encode the question

Convert the query into a list of numbers that represents its meaning.

Encode the table in all three ways

One model reads the table as words, another as pixels; compute their outputs side by side.

Score each path

A small network sees the question and both outputs, then predicts which answer is likely to be correct.

Pick and execute

Route only to the winner path, or run all three and fuse if the gate scored fusion highest.

Synthesize if fusing

If the gate chose fusion, a language model reasons over both outputs and picks or combines the best parts.

What the paper changes

What the paper changes

TableDART adds a routing mechanism — a lightweight network that looks at each table and decides which modality path (text, image, or both) to use for that specific case. The large base models stay completely frozen; only the routing network gets trained.

the object it moves  =  routing path selection
The hidden quantity

Correctness signal for each path

measured quantity  =  path correctness scores

The paper measures a hidden quantity: for each table-query pair during training, does the text-only path produce the correct answer? Does the image-only path? Does fusion? This is a list of three yes-or-no flags, one per path.

The gating network learns by seeing these correctness signals: it learns that some tables are best handled by text (e.g., a table of precise numbers), others by image (e.g., a table with strong visual structure), and some need fusion (when text and image have equal but complementary strengths). The network is trained to predict which path will be correct, then route accordingly.

Plain reading. For each table, the paper records which of the three paths (text, image, or fusion) gave the right answer. This tells the gate what to learn.
Paper reading. The method pre-computes a binary score list where each entry is 1 if that path produces a correct answer, 0 otherwise. The gate is trained by minimizing the difference between its predicted routing scores and these ground-truth scores, measured using KL divergence (a measure of how far apart two lists of probabilities are).
Why it works

Why routing fixes the problem

When a table is full of numbers and labels, the text path reads cleanly. When a table has complex visual structure — borders, shading, alignment — the image path sees it better. By routing each table to the path most likely to be right, the model never wastes computation on redundant processes and never confuses itself with conflicting cues.

A tiny gate can learn to predict correctness. During training, the gate watches which path succeeded on each table, then learns to score paths by looking at the question and the table's features together. At test time, it picks the highest-scoring path. If no single path is confident, it can run all three and ask a reasoning agent to synthesize the best answer. This costs computation only when genuinely needed.

Math after the picture

Training the router

First in words:

minimize the difference between where the gate sends a table and which path actually succeeded

Then the compact form:

loss = KL(s || p) + lambda * cost(selected_path)

Every symbol:

sground-truth binary vector (1 if path succeeded, 0 if not)
pgate's predicted routing scores (soft probabilities)
KL(s || p)how far the gate's guess is from the true answer
cost(selected_path)computational cost of running the chosen path
lambdaweight that trades off accuracy for efficiency
A tiny worked example
Table A: text succeeds (s=[1,0,0]), gate predicts p=[0.8, 0.1, 0.1].
KL divergence: 0.8 * log(0.8/1) + 0.1 * log(0.1/0) ≈ 0.22 (low cost, gate was right).
Table B: fusion succeeds (s=[0,0,1]), gate predicts p=[0.6, 0.2, 0.2].
KL divergence: 0.6 * log(0.6/0) + 0.2 * log(0.2/0) ≈ 1.8 (high cost, gate was wrong).
Training adjusts the gate's weights to predict s more often. Lambda weight on cost discourages running expensive fusion unless genuinely needed.

The gate learns to match where it routes with where success actually lies, while keeping expensive fusion rare.

What can go wrong

What can go wrong

The gate gets overconfident on training tables. If the gate learns the training data too well, it may route correctly in training but pick the wrong path on new tables. A regularizer on the routing costs (the lambda weight) helps by gently pushing the gate to use simpler paths more often, because running fewer paths means lower costs and less memorizing of the specific training examples it saw.
Text and image paths give opposite answers. Sometimes the text model and image model disagree. If both are confident but wrong in different ways, the gate may pick the slightly-less-wrong one, but neither is right. Fusion can help by reasoning over both outputs to spot contradictions and synthesize a better answer, but if both base models are fundamentally bad at a task, fusion will inherit that weakness.
The gate sees the question but not the table itself. The routing decision depends on question representations (lists of numbers that encode what the question means) and the outputs from text and image models, but the gate cannot see all the fine-grained table details directly. A truly unusual table format may confuse it.
Done right. When the gate has enough training data showing which path works for which table shape, it learns to route accurately. Fusion acts as a fallback for ambiguous cases, and the efficiency gain from routing keeps computation reasonable.
What a runnable demo should prove

What a runnable demo should prove

Build a demo with three tables: one dense with numbers (text-heavy), one with visual structure (image-heavy), and one balanced. Train the gate on a few hundred table-query pairs and show that it learns to route text-heavy queries to the text path, image-heavy to image, and balanced to fusion. Measure both accuracy and the cost (how many times each path was run). The gate should pick different paths for different tables, prove that the right path succeeds more often, and show that selective fusion (only on hard cases) beats always-fusing.

routing_accuracy = fraction_of_correct_predictions_where_gate_routed_optimally / total_pairs; efficiency_gain = (cost_naive_fusion - cost_routed) / cost_naive_fusion * 100%

The demo must show that different tables need different paths because each path has different strengths; that the gate learns to pick correctly by observing which path succeeded on each training table; and that routing saves computation because the gate avoids running expensive fusion when a single path is already confident.
