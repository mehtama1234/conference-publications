PolyILR: Tree-Structured Coordinates for Compositional Data

A method that turns hierarchical data (like taxonomies) into independent axes that respect how proportions actually measure distance.

When you measure compositions—things made up of parts that sum to a whole, like the microbes in a sample or cell types in tissue—distance matters. This paper shows how to build coordinates that honor both the tree structure of your categories and how proportions actually measure closeness, so downstream models can learn cleanly.

Zero assumption version

Hierarchies in proportions are invisible

Compositional data—measurements where each sample is a list of parts that add to one (100% of something)—show up everywhere: microbiome abundance (what fraction of bacteria are each species), cell types in tissue, geochemical composition. In these measurements, distance between samples has a special meaning: two compositions are close if their log-ratios are close, not just if the raw fractions are similar. This property is called the Aitchison metric.

Often these parts come organized in a tree: bacteria might be grouped by phylum, then genus, then species; cells might be grouped by cell type, then subtype. A naive approach throws away the tree and treats each leaf the same. A traditional method forces binary trees (each parent has exactly two children) even when you have ten children. Either way, you lose information about the hierarchy.

The challenge. Build coordinates from a tree hierarchy that respect the Aitchison metric, work with any tree shape, and let you analyze data at multiple levels of the tree.

What the paper changes

The tree of coordinates

PolyILR changes one thing: the coordinates (axes) used to represent proportion data. Instead of one independent axis per leaf (species), it constructs axes anchored to tree nodes. Each axis encodes contrasts (comparisons) between subtree branches, aligned to the hierarchy.

the object it moves  =  coordinate system (basis)
The hidden quantity

Branching contrast strength at each node

measured quantity  =  Branching contrast strength

At each internal node (e.g., a family containing three genera), the paper measures how the branches split the total mass. This is a branching contrast—how different the sibling groups are, when you zoom in to just that node and ignore the rest of the tree. If one genus is 80% and another is 10%, the contrast is strong; if they split 45%-45%, the contrast is weak.

The paper estimates this from the data by looking at how much each subtree typically contributes. Larger subtrees get more weight in the contrast calculation. This tells the model where in the hierarchy to focus during learning.

Why it works

Why PolyILR captures hierarchy and distance together

The trick is to build axes that sit perpendicular to one another (no redundancy) while each one corresponds to a real tree location. At each internal node, you define a local contrast: the weighted difference between subtree proportions. In ordinary space this would be messy; with the Aitchison metric (which measures how far apart two proportions really are), you have a natural way to make all these contrasts independent. PolyILR uses this metric to orthogonalize all the node-level contrasts into a single global basis.

Why does this help? Because now a model training on microbiome data has axes that mean something: one axis might capture the ratio of Bacteroidetes to Firmicutes (a phylum-level split), another might capture Clostridium to Faecalibacterium (a genus-level split). The model can learn which splits matter and at what resolution. Predictions are stable because the axes are independent; interpretability is built in because each axis ties to the tree.

Math after the picture

The independent-axis decomposition

First in words:

For each internal tree node, define a contrast that encodes the weighted difference between sibling branches, then make all contrasts independent (perpendicular) using the Aitchison distance; transform data by projecting onto this set of axes.

Then the compact form:

x_PolyILR = V_tree^T * log_ratio(x)

Every symbol:

xoriginal proportion vector (adds to 1.0)
log_ratio(x)log-ratio form: takes proportions into the Aitchison distance space
V_treematrix built from tree structure where each column is a contrast at a tree node
V_tree^T * log_ratio(x)projection: the new coordinates
A small worked example
Sample proportions: Phylum A 60 percent, Phylum B 40 percent.
First contrast at root: log(0.6) minus log(0.4) gives 0.405.
Within Phylum A, Genus 1 is 70 percent of A, Genus 2 is 30 percent of A.
Second contrast at A node: weighted by A being 60 percent total, magnitude 0.601.
Make independent: both contrasts become perpendicular axes, dot product is zero.
Transformed data: coordinates 0.405, 0.601, and so on in PolyILR axes.

Each coordinate axis aligns with one tree node's branching pattern, and they are independent so models see no redundancy.

What can go wrong

What can go wrong

Unbalanced trees are bad input. If one branch is huge and another tiny, the contrast at that node becomes degenerate. The paper handles this via weighting, but extreme imbalance will still cause numerical instability. Fix: ensure tree has reasonable branching ratios or trim rare categories before building axes.
Missing categories sink the coordinates. If a leaf category is present in the training tree but absent in a new sample, the proportion is zero and its log-ratio blows up (log of zero is undefined). The method requires nonzero counts everywhere (or pseudocounts). Fix: add a small pseudocount (e.g. 0.5 reads per category) before taking log-ratios.
Tree mismatch breaks everything. If you train on one taxonomic tree but evaluate on a different one (e.g., outdated taxonomy, different reference database), the coordinates no longer align. Fix: lock the tree at training time and reuse it at inference.
Done right: stable and interpretable. With a sensible tree, nonzero counts, and consistent preprocessing, PolyILR gives axes that are independent, tied to biology, and stable across samples.
What a runnable demo should prove

What a runnable demo should prove

Build a synthetic microbiome dataset: 100 samples, a known tree with 3 phyla, 3 genera per phylum, 4 species per genus (36 leaf categories total). Assign true abundances with known hierarchical structure (e.g., Phylum A dominates samples 1-50, Phylum B dominates 51-100). Apply PolyILR to extract axes. Train a simple classifier (logistic regression) to predict sample group from the axes. Measure accuracy and compare to a flat method (treating each species as an independent axis). Also visualize: do the axes separate the two groups? Do the tree-level axes (phylum contrasts) alone achieve reasonable separation, or do you need genus-level detail?

accuracy is correctly classified samples divided by total samples; interpretability is whether phylum-level axes alone separate the groups

The demo proves that PolyILR axes are both more predictive and hierarchically interpretable than flat methods.
