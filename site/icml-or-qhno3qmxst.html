Dune: Directed Unitary Graph Networks

Graph networks that handle directed edges with arrows and side labels without the learning signals weakening as networks get deeper.

Paper explainersAll themesGraph & Geometric Learning

Most graph neural networks treat all edges as bidirectional and equivalent. Real networks have directional arrows: bacteria infects host, one airport connects to another only one way, a Twitter user follows someone but is not followed back. When you try to add this directionality to existing graph networks, the learned signals wash out after just a few layers, making deep networks useless. Dune fixes this by using unitary math (a special kind of rotation that preserves information) to keep signals alive through 100+ layers.

Zero assumption version

Why directed graphs broke existing methods

A graph is a picture of relationships: dots (nodes) connected by lines (edges). A graph neural network (a model that learns from graphs) works by having each dot talk to its neighbors repeatedly, gradually building up a richer picture of the network. In an undirected graph, edges go both ways: if Alice talks to Bob, then Bob also talks to Alice. Most graph networks assume this.

Real networks are directed: bacteria can infect a host, but the host does not infect the bacteria the same way. Airport A has a flight to airport B, but maybe B has no flight back to A. A Mastodon user follows someone but is not followed back. When you try to adapt an undirected graph network naively to directed edges, two bad things happen: the learned signals get weaker and weaker with each layer (oversmoothing), and the gradient signals used during training become chaotic (gradient pathologies). After just a few layers, the model stops learning and is stuck at shallow depth.

The core problem. Directed graph networks cannot go deep because signals fade and training breaks down.

The algorithm as a flow

What it actually does

Read the directed edges

Treat arrows as one-way: A->B means A sends to B, not backwards.

Extract edge features

Each arrow carries a label (weight, type, distance). Use it.

Apply unitary rotation

Rotate each message using math that never shrinks the numbers.

Repeat deeply

Stack 50, 100, or more layers without signals fading.

Read the final representations

Each node now has a complete list of numbers built from the entire directed graph.

What the paper changes

What the paper changes

Dune changes how each edge transmits a message: it uses a unitary operator (a mathematical rotation) instead of a simple multiply-and-add, and it scales that rotation based on the edge's own features (weight, type, etc.).

the object it moves  =  message transmission on directed edges
The hidden quantity

The hidden quantity: gradient norm magnitude

measured quantity  =  gradient norm magnitude

When a model learns, it computes a gradient: a number that says how much to nudge each learned number to shrink the error. If gradients become huge, training becomes unstable and chaotic. If gradients become tiny, training stops. Dune keeps the magnitude (the size) of these gradients bounded at every layer by design, because unitary operators preserve the length of vectors (lists of numbers). Existing directed GNNs cannot make this guarantee, so their gradients explode or vanish as you add layers.

The paper measures this by comparing how stable training stays across many layers. A stable training means the gradient sizes stay reasonable from layer 1 to layer 100. An unstable training means gradients blow up, then collapse.

Why it works

Why unitary math works for deep directed graphs

Unitary operators are special rotations in math: they spin a list of numbers without changing its length. A list of numbers has a length (the square root of the sum of squares). A unitary operator rotates that list but does not make it longer or shorter. When you apply it once, then again, then again, the list length stays the same forever. Oversmoothing happens because normal multiply-and-add operations shrink signals with each layer. Dune's unitary rotation never shrinks, only rotates, so the signal stays alive through 100 layers.

For directed edges with labels, Dune scales the rotation by the edge feature. A strong edge (label is 2.0) rotates more than a weak edge (label is 0.5), so edge directionality and strength actually steer how information moves. The gradient signals used in training also stay bounded by the same property: if you differentiate a unitary rotation, you get another unitary rotation, preserving length up the chain. This is why training stays stable at depth.

Math after the picture

The rotation operator

First in words:

For each directed edge with feature label w, compute the message as: unitary_matrix(w) times the input vector. The unitary matrix is a rotation parameterized by the edge label. The output has the same length as the input, always.

Then the compact form:

h_v^(l+1) = sigma( sum_{u in parents(v)} U(w_{u,v}) * h_u^(l) )

Every symbol:

h_v^(l+1)the new representation for node v at layer l+1
h_u^(l)the representation of neighbor u at layer l
U(w)a unitary rotation parameterized by edge weight w
w_{u,v}the feature (weight, type) of the directed edge from u to v
sigmaan activation function (e.g. relu: turns negatives to 0)
sum_{u in parents(v)}add up messages from all nodes that point into v
parents(v)all nodes u that have an edge pointing to v
A tiny worked example
Node A receives messages from 2 parents: X and Y.
X sends representation [4.0, 0.0]. Edge weight w_X,A = 1.0.
U(1.0) is a unitary rotation by 45 degrees: [[0.707, -0.707], [0.707, 0.707]].
Rotated message: [[0.707, -0.707], [0.707, 0.707]] * [4.0, 0.0] = [2.828, 2.828]. Length stays sqrt(4^2 + 0^2) = 4.0.
Y sends [0.0, 3.0]. Edge weight w_Y,A = 2.0.
U(2.0) is a rotation by 90 degrees: [[0, -1], [1, 0]].
Rotated message: [[0, -1], [1, 0]] * [0.0, 3.0] = [−3.0, 0.0]. Length stays 3.0.
h_A^(l+1) = activation([2.828, 2.828] + [−3.0, 0.0]) = activation([−0.172, 2.828]). Signals preserved through both rotations.

Unitary operators rotate without shrinking, so gradients and signals stay alive no matter how deep the network.

What can go wrong

What can go wrong

Very dense graphs with many edges. If a node has 10,000 incoming edges, summing all rotated messages becomes expensive. Unitary math does not shrink complexity; each edge still costs work.
Edge features that are all the same. If all edges have the same label, the rotation angles are identical for all incoming messages, losing the power of directionality. The method works best when edge labels actually differ and carry signal.
Learning which rotation angles to use for each edge weight. The model must learn how to map edge weights to rotation angles. If this mapping is not chosen carefully, the model may get stuck learning bad angles and never recover.
Done right: graphs where edge labels matter. On realistic directed networks (social graphs, knowledge bases, protein interactions) where edges carry real labels that differ, Dune trains stably because gradients stay bounded, and deep networks outperform shallow ones because they can combine signals from more distant nodes in the graph.
What a runnable demo should prove

What a runnable demo should prove

Build a small directed graph (e.g., a citation network where papers cite other papers, or a social graph where users follow users). Add edge features (citation strength, follow recency, trust weight). Train a Dune network with 50 layers and a baseline directed GNN with 3 layers on a node classification task (predict a label for each node). Measure accuracy and the size of gradients at each layer.

layer_gradient_norm_stability = (max gradient norm) / (min gradient norm); lower is more stable. layer_accuracy_gain = accuracy_50_layers - accuracy_3_layers.

The demo should show that Dune's 50-layer model has stable gradient norms (ratio close to 1.0) because unitary math preserves norm, and higher accuracy than the shallow baseline because deeper layers can access more distant information in the graph, proving that depth is now useful.
