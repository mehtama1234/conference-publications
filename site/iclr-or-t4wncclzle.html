DADA: Dual Averaging with Distance Adaptation

An optimization algorithm that needs no manual tuning: it tunes its own learning speed by watching both the gradients it sees and how far it has traveled from the start.

Paper explainersAll themesOptimization

Most optimization algorithms need you to pick a learning rate (how big a step to take) and other settings tailored to each problem. DADA is different: it automatically picks its step size on the fly by looking at what has already happened—the gradient signals it has seen and how much distance it has covered. It works across different problem types because the step size adapts to real-time measurements (distance and gradient strength) that naturally encode problem difficulty, making tuning unnecessary.

Zero assumption version

Every algorithm needs tuning, but every problem is different

Most gradient-based optimizers require you to set a learning rate—the size of each step downhill toward the best solution. Pick it too small and training crawls. Pick it too big and the algorithm bounces wildly and never converges. Worse, the right rate depends on the problem itself: smooth functions (where the gradient changes gently) need bigger steps than bumpy functions (where the gradient changes abruptly). Real problems also vary hugely: some are linear and predictable, others have wild curvature (high-order structure), and some are constrained (you can only explore certain regions). A learning rate that works for one class of problem fails for another.

A beginner would pick a single learning rate and hope it works everywhere. It does not. The algorithm either crawls or crashes. The core problem: the algorithm is blind to the actual structure of the problem it is solving.

The paper's move. Watch the gradients and distance traveled, then use both to automatically pick how big each step should be, adapting in real time.

The algorithm as a flow

What it actually does

Start at an arbitrary point

Set a counter to zero; remember your starting location.

Compute the gradient

Measure which way is downhill at the current point.

Track the distance traveled

Keep a running sum of all the steps taken so far from the start.

Tune the step size

Divide distance traveled by the average gradient magnitude. This is the new step size.

Take a step

Move in the negative gradient direction by this adaptive step size; repeat.

What the paper changes

What the paper changes

The paper changes how the step size (the size of each downhill move) is computed. Instead of using a fixed number picked beforehand, DADA computes it on the fly using two pieces of information available right now: how far the algorithm has traveled from the start, and how strong the gradient signals have been on average. This feedback loop makes the algorithm self-tuning.

The hidden quantity

The hidden quantity: Effective learning rate

measured quantity  =  Adaptive step scaling

DADA tracks an internal quantity that decides how much to scale down the gradient when moving. This quantity is computed from two measurements: the total distance covered from the starting point, and the accumulated magnitude of all gradients seen. The paper calls this the adaptive coefficient, and it is the secret to handling many problem types without human tuning.

The paper estimates this coefficient using cumulative information: after N steps, the coefficient equals (total distance traveled) divided by (typical gradient size observed). This ratio grows when the algorithm is exploring far but slows down when gradients become weak, and shrinks when the algorithm is close to the start or gradients are strong.

Why it works

Why it works: automatic tuning without knowing the problem

The core insight is that you can infer problem difficulty from your own exploration. When you move far from the start but gradients stay weak, the problem is probably smooth (you can safely take bigger steps). When you move a tiny distance but gradients are huge, the problem is bumpy (you need small steps). DADA uses this self-generated evidence to scale its step size.

Here is the causal chain: (1) DADA accumulates two measurements as it explores: how far it has gone and what gradient sizes it has felt. (2) It divides distance by gradient magnitude to get a step size. (3) This division acts as an automatic brake: if gradients are huge, the fraction becomes small and steps shrink. If gradients are tiny, the fraction is large and steps grow. (4) The algorithm thus self-tunes—no hand-picked learning rate needed. (5) This strategy works across problem types because the adaptation is purely empirical: it is based on what the algorithm actually observes, not on any assumed structure of the problem.

Math after the picture

The equation: step size from history

First in words:

step_size = total_distance_from_start ÷ average_gradient_magnitude

Then the compact form:

alpha_t = D_t ÷ (G_1 + G_2 + ... + G_t) / t

Every symbol:

alpha_tthe step size (learning rate) at iteration t
D_ttotal Euclidean distance traveled from the starting point up to step t
G_ithe magnitude (length) of the gradient at step i
tthe current iteration number
A tiny worked example
Iteration 1: Distance from start = 0.5. Gradient magnitude = 2.0. Step size = 0.5 ÷ 2.0 = 0.25.
Iteration 2: Distance from start = 0.5 + 0.3 = 0.8. Gradient magnitudes: [2.0, 1.5]. Average = 1.75. Step size = 0.8 ÷ 1.75 = 0.46.
Iteration 3: Distance from start = 0.8 + 0.4 = 1.2. Gradient magnitudes: [2.0, 1.5, 1.0]. Average = 1.5. Step size = 1.2 ÷ 1.5 = 0.80.
Notice: step size grew because we moved farther and gradients weakened, so the algorithm takes bigger steps.

The fraction grows as you explore farther but shrinks when gradients stay large, automatically matching the problem's difficulty.

What can go wrong

What can go wrong

Step size can grow too large if you wander far but hit a steep cliff. If the algorithm moves far from the start but then enters a region with tiny gradients (nearly flat), the step size equation gives a huge step, and the next gradient jump can be enormous, causing divergence. This happens in unusual shapes with sudden drops or hidden cliffs.
Unbounded domain and constrained problems need care. If the domain (the space you can explore) is very large or has no natural boundary, distance can grow without bound, and the algorithm's step size might not shrink when needed. The paper addresses this, but only for problem classes where you can prove the function value stays bounded.
Starting point matters more than usual. Since distance is measured from the starting location, an unlucky starting point far from the solution means distance starts large, which can cause overshooting early on until gradients are observed.
Works reliably if problem class is known. If you can verify your problem belongs to one of the supported classes (smooth, bumpy, high-order structure, quasi-self-concordant), DADA's adaptive tuning proves convergence. The self-tuning fails only if the problem violates its assumed bounds.

What a runnable demo should prove

Build a small demo that compares DADA to a standard gradient descent algorithm with a fixed learning rate. Set up three toy problems: (1) a smooth bowl-shaped function (quadratic), (2) a bumpy function with many ripples, and (3) a constrained function that lives in a box. For each problem, run both DADA and gradient descent with several fixed learning rates. Measure how many steps each takes to reach near the minimum, where accuracy means staying within 1% of the true minimum value.

convergence_steps: number of iterations until the objective value is within 1% of the minimum

The demo should show that DADA reaches the goal in roughly the same number of steps regardless of the problem type, while fixed learning rates either crawl (too small) or diverge (too big).
