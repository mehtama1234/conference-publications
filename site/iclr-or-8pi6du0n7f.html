Autoencoding-Free Context Compression for LLMs via Semantic Anchors

Stop compressing contexts by reconstructing them; instead, grab the important tokens directly and let them see the whole conversation.

Paper explainersAll themesLLMs & Foundation Models

Large language models slow down when given very long contexts (long emails, articles, documents). A common fix is context compression: take the 10,000-word input and shrink it to 100 words without losing the answers. Old methods use a trick called autoencoding (the compression system learns by guessing what was deleted, like solving a puzzle with missing pieces). This paper asks: why force the compression system to be a puzzle-solver if what we really need is a task-solver? It shows that directly picking the important words from the original text and letting them see the whole context is faster and better, because anchor selection avoids wasting compression capacity on reconstruction details and focuses entirely on task-critical information.

Zero assumption version

Why old compression breaks

Long contexts make models slow. A 10,000-word document gets encoded (turned into numbers) all the way through, which takes time. Compressing that down to 100 key words should help, because the model then has to process and store only the 100 compressed representations instead of 10,000, cutting compute time roughly proportionally.

Old compression methods train a compressor by making it solve a reconstruction puzzle: remove some words from a document (tokens are just the individual words), then train the compressor to guess them back. The idea is, if the compressor can rebuild the missing pieces, it must have learned something important. But the puzzle it solves (reconstructing exactly what was deleted) is not the same puzzle the model needs to solve (answering a question about the document). So the compressor learns useless details—words that matter for reconstruction but not for the actual task.

The mismatch. The old way trains compression systems to be good at reconstruction puzzles, not at keeping the information that answers actual questions.

The algorithm as a flow

What it actually does

Identify anchor tokens

A small learned network (anchor embeddings) scores each token in the context, picking the most important ones.

Let anchors see the whole context

Normally, models read left-to-right (causal attention). Here, we allow anchor tokens to look backward and forward (bidirectional attention), so they gather information from the entire document.

Grab their representations

The key-value pairs (the internal numbers the model uses to remember each token) from the anchor tokens become the compressed representation.

Decoder uses compressed form

The main model reads the compressed representation as if it were the original context, answering questions normally.

Skip the reconstruction puzzle

No autoencoding loss, no puzzle training. Train only on actual tasks: language modeling and question-answering.

What the paper changes

The one thing that changes

Instead of training a compression system to guess deleted tokens (autoencoding), the paper selects certain tokens directly from the original context and uses their internal representations as the compressed form. The tokens are chosen via a learned scoring mechanism (anchor embeddings), and they are allowed to look backward and forward through the context (bidirectional visibility) before their values are locked in as the compression.

the object it moves  =  anchor tokens and their key-value pairs
The hidden quantity

Anchor importance: which tokens matter most

measured quantity  =  anchor embedding scores

The hidden quantity is a score for each token that says how useful it is for the final task. Not a number that appears in the final answer, but a score the compression system learns during training.

The paper estimates this by training a small learned network (anchor embeddings) on actual downstream tasks (question-answering, language modeling). Tokens that get high scores are kept; low-scoring tokens are dropped. Unlike the old method, this score is trained on real-world tasks, not on reconstructing deleted words.

Why it works

Why anchor selection plus bidirectional attention works better

Autoencoding forces the compressor to remember all kinds of details so it can reconstruct every token. That means useful-for-questions and useless-for-questions details get tangled together. When you shrink the representation, some task-critical information gets thrown away along with the puzzle-specific noise.

SAC works because it extracts tokens directly from the original context. Those anchor tokens already contain the right information (the model already uses them to understand the original text). By letting anchor tokens attend to the whole context (bidirectional attention), we make sure they absorb information from tokens that came before and after them, so they stand alone well. Then we lock in their internal state as the compressed form. No reconstruction puzzle, no mismatch—what the compressor keeps is exactly what the downstream task needs.

Scoring and selecting anchors

First in words:

For each token in context, compute its anchor score. Select top-K tokens. Aggregate their key-value representations. Loss = language_modeling_loss + question_answering_loss (no autoencoding term).

Then the compact form:

score_i = AnchorEmbed(token_i); selected = topK(scores); compressed = aggregate(KV[selected]); loss = L_LM + L_QA

Every symbol:

score_ihow important token i is (learned by the model)
AnchorEmbedsmall neural network that rates tokens
topKkeep the K highest-scoring tokens
KV[selected]the internal key-value pair from each selected anchor token
aggregatestack or pool the representations together
L_LMloss on the language modeling task (predicting next word)
L_QAloss on the question-answering task
Kthe compression ratio (e.g., K=100 means keep 100 tokens from 10,000)
A tiny worked example
Context has 1,000 tokens. Target compression ratio is 10:1, so K = 100.
Anchor embeddings score each token. Top 100 scores: token 5 (score 0.95), token 12 (0.92), token 89 (0.91), ... token 876 (0.71).
We extract the internal number-lists (key-value pairs) from those 100 anchor tokens.
The decoder receives a compressed form with 100 number-lists instead of 1,000, running 10x faster.
During training, we compute L_LM (did the model predict the next word?) and L_QA (did it answer the question correctly?). No reconstruction loss. Learning signals flow back to AnchorEmbed, training it to rank task-useful tokens high.

The key difference: old loss includes a reconstruction term forcing exact guessing; this loss has only task-aligned terms, so the model learns to rank tokens by usefulness, not by how easy they are to reconstruct, because gradients now flow only from objectives that matter (answering questions), not from a puzzle objective (rebuilding deleted words).

What can go wrong

What can go wrong

Anchor embeddings are miscalibrated. If the scoring network is weak or undertrained, it may rank unimportant tokens high and drop important ones. The compressor can only keep what the anchor embeddings identify; garbage scores lead to garbage compression.
Bidirectional attention breaks downstream decoder. The decoder (the main LLM) uses causal (left-to-right) attention. If anchor tokens attended bidirectionally but the decoder still reads left-to-right, there is a mismatch in how context flows. The fix: make sure anchors aggregate info correctly so the decoder can use it.
Very high compression ratios starve the decoder. If you compress 10,000 tokens down to 50, even perfect anchor selection may lose rare but critical information. There is a hard limit below which no anchor method works.
Done right. Train anchor embeddings on real downstream tasks, keep compression ratios reasonable, and verify that the model still understands edge cases and rare facts.
What a runnable demo should prove

What a runnable demo should prove

Build a small question-answering system. Feed it a document (e.g., a news article or a book chapter), ask it a question, and record the accuracy. Compress the document to different ratios (5x, 10x, 20x) using SAC. For each compressed version, run the same question and record accuracy. Plot accuracy vs. compression ratio and compare it to a baseline (autoencoding-based compression or naive truncation).

accuracy_drop = accuracy_original - accuracy_at_compression_ratio; smaller drop = better compression

SAC should hold accuracy flat even at 10x compression, while autoencoding-based methods should show steep accuracy cliffs.
