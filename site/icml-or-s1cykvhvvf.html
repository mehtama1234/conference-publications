Coherent Coordinate Descent: Reusing Old Gradients as Stable Nudges

When you can't compute gradients directly, reuse stale old gradients to stay stable and efficient.

Paper explainersAll themesOptimization

In many real problems — like on-device learning or black-box optimization — you can't compute gradients the normal way. The paper introduces Coherent Coordinate Descent (CoCD), a method that turns old, stale gradients from previous steps into computational assets. Recycling those historical gradients with the right coordination keeps the optimization stable and only needs to ask the model one more time per step.

Zero assumption version

Gradients are expensive or forbidden

In normal machine learning training, you compute gradients (the direction and size of weight nudges) by running the model forwards, then backwards through every layer to see which weights matter most. But in many real situations this is impossible: your phone has no memory for the backwards pass, or the model is a black box and you can only ask it 'what is the answer to this input' with no insight into how it works inside.

When you can't compute gradients directly, standard workarounds are broken. You could estimate a gradient by running the model twice — once with a weight slightly higher, once slightly lower — but that costs two queries instead of one, so it is sample-inefficient. Or you could randomize which weights you check, which lowers the cost but makes the gradient estimates noisy and unpredictable, so learning zigzags and fails to converge smoothly.

In one sentence. CoCD treats old gradients from earlier steps as a stable, reusable resource instead of garbage.

The algorithm as a flow

What it actually does

Keep old gradients

Don't throw away gradient estimates from the last few steps.

Rotate coordinates

Each iteration, pick a different one to adjust based on a stale gradient.

Bigger step sizes

Use a slightly larger finite-difference step (the distance you wiggle the weight).

Implicit smoothing

Counterintuitively, the larger step reduces how choppy the loss surface feels, making descent stable.

One query per step

Get the same descent direction as a full gradient with one forward pass.

What the paper changes

What the paper changes

Instead of computing a fresh gradient estimate every step (expensive or noisy), CoCD keeps a rolling window of stale gradient estimates and rotates which one it uses. At step t, it applies an update based on the gradient from step t minus some fixed block size. This is called 'recycling' or 'coordinate cycling'.

The hidden quantity

Gradient coherence: a measure of how well old directions still point downhill

measured quantity  =  Gradient coherence

The paper names a new quantity: gradient coherence. It measures how much an old gradient estimate (from step t minus k) still points in a useful direction at the current step t. If the loss surface is smooth, an old gradient direction is still mostly correct. If the surface is choppy, old gradients quickly become stale junk. Coherence quantifies the angle between the old estimate and what a fresh gradient would be.

The paper proves that when you use old gradients in a coordinated, cyclic pattern — always rotating through the same block of coordinates — the coherence stays high enough to guarantee convergence. This is the main theoretical insight.

Why it works

Why recycling old gradients with the right pattern keeps you converging

Here is the causal chain. In zeroth-order optimization, you estimate a gradient by perturbing a weight and measuring the change in loss. This estimate is cheap (one query) but stale after one step — the model has been updated, so the estimate no longer describes the current state. The naive approach: keep re-computing fresh estimates (expensive) or add randomness (unstable).

CoCD's move: instead of discarding old estimates, reuse them in a cyclic pattern. At step t, you apply an update based on the gradient estimate from step t minus B (where B is a block size). This works because: (1) if the loss surface has smooth, rolling hills rather than sharp cliffs, the old gradient direction is still roughly correct; (2) the cyclic pattern ensures that you eventually touch every coordinate, so every weight gets updated; (3) the implicit smoothing effect (larger finite-difference step sizes reduce how sensitive the surface is to small changes) means the gradient estimates are even more coherent across steps.

The result is a descent algorithm that only needs one query per step, maintains a stable (coherent) descent direction, and converges provably because the coordinate cycling guarantees progress on every weight.

Math after the picture

The update rule

First in words:

new weight equals old weight minus step size times the old gradient, with smoothness scaling

Then the compact form:

theta_t = theta_t-1 - alpha_t * g_t-B

Every symbol:

theta_tweight value at step t
theta_t-1weight value at step t minus 1
alpha_tstep size at step t (can be scaled by smoothness estimate)
g_t-Bgradient estimate from B steps ago
Bblock size: how many steps back to reuse
A tiny worked example
Start: weight = 0.5, old gradients in memory: [0.2 (from 2 steps ago), 0.15 (from 1 step ago)].
Step 1: select first old gradient, g = 0.2. Update: 0.5 - 0.1 * 0.2 = 0.48.
Step 2: select second old gradient, g = 0.15. Update: 0.48 - 0.1 * 0.15 = 0.465.
Step 3: compute new gradient, g_fresh = 0.12. Store it, rotate block. Update: 0.465 - 0.1 * 0.2 = 0.445.
Each step only asked the model once. No randomness. Converges steadily downhill.

The key is the cyclic pattern: you always pick from a fixed block of old gradients, never the newest, so you only need one fresh query per step.

What can go wrong

What can go wrong

Choppy loss surface. If the loss surface has sharp, unpredictable changes, old gradients become incoherent fast. CoCD relies on smoothness; if the surface is jagged with cliffs, recycling fails.
Block size too large. If you wait too many steps before reusing a gradient, it becomes very stale. Choosing B (block size) is a hyperparameter; wrong choice reduces coherence.
Finite-difference step size too aggressive. Larger steps help smoothing because they average over a wider region of the surface, but they can also miss fine details if the true loss surface has bumps smaller than your step size. The implicit smoothing benefit works best in a sweet spot where you smooth enough to stay coherent but not so much that you skip over important structure.
Done right. When the loss surface is reasonably smooth (true for most neural nets because training dynamics favor gentle slopes over sharp cliffs), block size is tuned to the problem, and step size is set to balance smoothing, CoCD converges faster than standard finite differences with fewer queries because the recycled gradients remain coherent and deterministic progress is more stable than randomized sampling.
What a runnable demo should prove

What a runnable demo should prove

Build a simple neural network (5-layer MLP on MNIST or a toy dataset). Lock away the backwards pass (only allow forward passes) by removing access to gradient computation, simulating a black-box scenario. Run three optimizers in parallel: (1) standard finite differences (two queries per step), (2) random subspace (one query, random coordinate), and (3) CoCD (one query, cyclic coordinate with a block of old gradients). Train each for 100 steps on the same 1000-sample batch. Record loss and final accuracy after training.

convergence_speed = initial_loss - final_loss; final_accuracy = correct_predictions / total_samples

CoCD should reach the lowest final loss in 100 steps and highest accuracy with only one query per step, visibly outperforming both standard finite-differences (two queries, not one) and random subspace (noisy, zigzagging).
