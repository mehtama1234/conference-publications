Same Graph Cross-Task Transfer in GNNs: Protocols and Predictors

When you have a graph with many tasks, reusing learned patterns from one task to another can help or hurt depending on whether you measure transfer correctly and which direction you go.

Paper explainersAll themesGraph & Geometric Learning

Real-world graphs often have many questions to answer from the same structure. A graph neural network (a machine-learning model that reads graphs by passing messages between connected nodes) can learn one task well, then reuse that learning on another. But when researchers test transfer, they use different setups, making their findings unreliable. This paper fixes the test protocol and discovers that transfer direction matters sharply: moving from node classification to link prediction works reliably, but the reverse often breaks the model.

Zero assumption version

The measurement trap

Suppose you have a social network graph — nodes are people, edges are friendships. You want to solve two jobs from this one graph: (1) predict whether a person should be labeled "influencer" or "regular" (called node classification), and (2) predict whether a future friendship edge will form between two people (called link prediction). A smart approach would be to train on one task, then reuse the learned patterns for the other. But researchers testing this idea all used different ways to split the graph, different assumptions about what data the model has access to, and different rules for picking negative examples (people who won't be connected). This means published findings contradict each other.

A beginner tries to train a graph neural network on node classification, then immediately run it on link prediction with no changes. Or the reverse. But because the tests were incompatible, nobody knew if transfer actually worked or if the studies just disagreed by accident.

In one sentence. Design one honest test protocol for transferring a graph model from one task to another, run it fairly, and reveal which directions help and which hurt, because different test rules have contradicted each other for years.

What the paper changes

The thing the paper moves

The paper changes how researchers set up and run cross-task transfer tests. It fixes three concrete things: which node and edge splits are used for training and testing, what data the message-passing graph has access to, and which pairs of nodes count as negative examples in link prediction (people who are not friends).

The hidden quantity

The hidden quantity: transfer direction

measured quantity  =  transfer directional asymmetry

Transfer is not symmetric. Consider a graph where students are nodes and friendships are edges. If friends tend to be in the same grade (homophilic), then the node classification model learns the rule: nodes with similar neighbors should get similar labels. When you switch to link prediction, this pattern directly helps — predict that similar nodes are more likely connected, because the model learned which nodes cluster together. But reverse transfer is fragile. The link prediction model only learns which connected node pairs are similar; it never learns about isolated nodes or unlabeled nodes. When you switch to node classification, the model must suddenly predict labels for every node, including disconnected ones, using only edge-structure patterns that tell you nothing about those isolated nodes.

The paper measures this asymmetry by running both transfer directions and checking if accuracy drops. It also measures homophily (how much friends are similar) to predict which direction will work.

Why it works

Why transfer direction matters

Node classification and link prediction require different learned patterns. Node classification answers: are these nodes similar enough to get the same label? Link prediction answers: are these nodes connected? On homophilic graphs (where friends are similar), these are almost the same question, so node-to-link transfer passes useful patterns straight through. The model learns that similar nodes should cluster, and it uses that clustering to predict edges.

Link-to-node transfer is fragile because link prediction only cares about edges that exist, not about unlabeled nodes. A link prediction model learns which connected pairs are similar, but it never learns about node labels for disconnected nodes or isolated nodes. When you switch to node classification, the model must suddenly predict labels for every node, including isolated ones, using learned patterns built only from edge structure. If the graph has sparse edges or isolated nodes, those patterns fail.

The paper finds that transfer backward works only when the link prediction task is easy (the graph has obvious structure) but node classification is hard (nodes lack obvious labels). In that case, link prediction acts like structural pretraining — it forces the model to learn the graph backbone, which node classification then builds on.

Measuring transfer

First in words:

transfer gain is the difference in accuracy when a model trained on task A is tested on task B versus training task B from scratch

Then the compact form:

gain_AB = acc_B_with_A_pretraining - acc_B_from_scratch

Every symbol:

gain_ABhow much accuracy improved by using task A for pretraining
acc_B_with_A_pretrainingaccuracy on task B after training on task A
acc_B_from_scratchaccuracy on task B trained without any other task
Asource task (e.g., node classification)
Btarget task (e.g., link prediction)
A tiny worked example
Example: NC→LP on a homophilic graph.
acc_LP_from_scratch = 72% (training on link prediction alone).
acc_LP_with_NC_pretraining = 84% (trained on node classification first).
gain_NC_to_LP = 84 - 72 = +12 percentage points (transfer works).
Now reverse: LP→NC.
acc_NC_from_scratch = 71% (training on node classification alone).
acc_NC_with_LP_pretraining = 68% (trained on link prediction first).
gain_LP_to_NC = 68 - 71 = −3 percentage points (transfer hurt).

Transfer asymmetry appears in the numbers: the same graph and model give positive gain one direction, negative the other.

What can go wrong

What can go wrong

Using different splits for each task. If node classification uses different train/test splits than link prediction, you cannot tell whether transfer helps or whether results differ only because the tasks use different data, not because of transfer.
Leaky negatives in link prediction. If the negative pairs (non-edges you train on) include edges that exist in the test graph, the model memorizes those specific pairs instead of learning general structure.
Forgetting to ignore edges during message passing. If the graph message-passing layer includes edges you are testing, the model peeks at the answer and inflates its performance. Information leaks because the model sees which nodes will be connected before it tries to predict, so it can just memorize the answer instead of learning a general pattern, making transfer look better than it would be if those edges were truly hidden.
Transferring backward blindly. Link prediction pretraining helps node classification only when graph structure is the main hurdle and node labels are sparse. If labels are clear and structure is noisy, backward transfer crashes accuracy because edge patterns contradict the label signal.
Done right: fixed protocol, fixed negatives, no information leaks. Lock down all three sources of unfairness; measure transfer both directions; check homophily to predict which way works.
What a runnable demo should prove

What a runnable demo should prove

Build a synthetic graph with two kinds of nodes (group A and group B). Color edges so friends are always the same type (homophilic). Train a small graph neural network on node classification (predict group), then test on link prediction (predict whether an edge exists). Record the accuracy before and after transfer. Then reverse: train on link prediction, test on node classification. Plot the two transfer gains side by side. The node-to-link gain should be large and positive because the clustering learned from labels predicts edges; the link-to-node gain should be small or negative because edge patterns tell nothing about isolated nodes. Then swap the graph to a heterophilic one (friends are opposite types) and rerun. Now even node-to-link should be weaker because clustering no longer predicts edges, and link-to-node should crash further because edge patterns now contradict the label signal. Finally, compute CoTask Score for a balanced model and show that homophily predicts whether the joint score will be high or low.

gain_AB = accuracy_B_with_A_pretrain - accuracy_B_from_scratch

The demo must show that the same model transfers differently in different directions on the same graph, and that graph structure (homophily) predicts which direction wins.
