Keeping knowledge as data changes over time

Papers tackle continual learning and domain adaptation by building models that learn from new data without forgetting old knowledge, important for real-world systems that must evolve.

All themesField mapMathematicsAll explainers
What this is

In the real world, data arrives continuously. A factory's production process shifts, social media trends change, new species of plants appear in ecology datasets. When a model is trained once and deployed, it sees data it was never trained on, and its performance decays — a phenomenon called distribution shift or domain adaptation. Simply retraining the model from scratch on new data is expensive and often causes catastrophic forgetting: the model forgets everything it learned before and has to relearn it all. The goal is to learn from new data without erasing old knowledge.

This is genuinely hard because neural networks are prone to interference: fitting new patterns can mechanically overwrite the weights that encoded old patterns. Continual learning researchers explore several strategies: maintain a buffer of past data and mix it with new data when training, learn in a way that is less destructive to old knowledge (like constraining weight changes), develop architectures that isolate new tasks in dedicated pathways, or learn features that are more stable across domains. The tradeoff is always the same: if you are too conservative with old knowledge, you learn slowly from new data; if you are too aggressive, you forget. Finding that balance is the core research question.

Across 57 papers, researchers tackle continual learning, domain adaptation, and few-shot learning (learning from very few examples of a new domain). Some papers ask what the theoretical limits are: is it possible to never forget? Others build practical systems: test-time adaptation methods that adjust the model slightly as it encounters new data, or meta-learning approaches that train the model to learn quickly from new examples. The applications are critical: robots deployed in the real world need to adapt, medical AI systems need to handle new patient populations, and recommendation systems need to track evolving user preferences.

How the work breaks down

The work splits into five directions: adapting models at the moment they see new data (test-time adaptation), preserving old knowledge by replaying examples from the past (experience replay), physically isolating new learning in separate network pathways (task isolation), learning representations that stay stable across new domains (representation learning), and bridging gaps between training and deployment domains (domain adaptation). These directions coexist because the core problem is hard—fitting new data tends to overwrite old weights—and different solutions trade off between speed, memory, and how well they generalize.

Test-Time Adaptation at Deployment

In the real world, a model's job doesn't end when it ships. Once deployed, it encounters data it never saw in training: new lighting conditions, new camera angles, new user groups. The model's accuracy drops. Test-time adaptation asks: can we adjust the model slightly, using only what it sees now, without going back to old data? This is hard because you have no ground truth labels (the model is already deployed), and tiny tweaks can break performance on what the model saw in training.

FedPAT uses stable prototype relationships—key learned patterns—to adapt even in federated settings (where data sits on different machines and never meets). Long-tailed Test-Time Adaptation handles an imbalance where some classes appear far more often than others, a common real-world problem. ADTE uses Tsallis entropy (a way to measure how spread-out the data is) to detect when the data has shifted and adapt automatically without manual tuning. Bilateral Information-aware Test-Time Adaptation prevents a subtle failure: in vision-language models (models that see pictures and text together), blind adaptation can memorize spurious details instead of learning real patterns. Learning to Memorize uses both associative memory (when you see a cat, remember that cats are furry) and attributive memory (remember the specific orange cat you saw), building a two-part memory system that handles data drift. SaTeen learns structural alignment—how to match the shape of learned features to the shape of new data without breaking the network's foundation. These methods let models adapt to deployment, but they assume the network's core weights stay mostly frozen, so they work only for small shifts in what the data looks like.

All six papers tackle adaptation without access to historical training data, but they split on the mechanism: prototypes and memory systems work by storing key patterns, entropy-based methods detect and respond to shift, and structural approaches preserve relationships. Together they show that even without explicit labels, a model can partially adapt by tracking how its own learned patterns behave on new data.

Replay and Isolation via Separate Pathways

Two strategies address forgetting directly. First is replay: keep a small buffer of past data and mix it with new data when training. Second is isolation: create separate pathways for new tasks so they don't overwrite old weights. Idempotent Experience Replay (IDER) discovers that replayed data should be processed the same way every time—idempotent means doing it twice gives the same result as doing it once. Avoid Catastrophic Forgetting with Rank-1 Fisher uses diffusion models (generative models that slowly add noise) to conjure synthetic old data that preserves the model's behavior on past tasks. A Brain-Inspired Geometric Memory (BTSP-CAM) is inspired by how fruit fly brains store memories in spatial patterns; it can work without storing real examples, just spatial patterns.

Detect, Decide, Unlearn (DEDUCE) detects which neurons are involved in past tasks and decides which to modify for new tasks, so new learning avoids key old pathways. Fly-CL uses decorrelation (making neurons more independent) inspired by the fruit fly brain, and does it efficiently so training stays fast. Task-Driven Subspace Decomposition (LoDA) splits the weight space into shared (used by all tasks) and task-specific parts, then routes information to the right place. Together, replay and isolation show that forgetting is not inevitable when you understand what the model is remembering and where it lives.

Efficient Adaptation via Low-Rank Methods

Low-rank adapters and efficient routing methods scale continual learning to large models. HEDP (Hybrid Energy-Distance Prompt) uses energy scores (a physics-inspired measure) and distance metrics to keep prompts that work on old data while adapting to new domains, preserving what was learned. Cross-View Lewis Weight Fusion weights which examples matter most using insights from information theory, so you replay the most important past data. Factor-Wise Homogeneity detects when slots (individual neurons or pathways) in an object-centric model align, which is the mechanism preventing forgetting. Forgetting Whenever You Want builds a decentralized system where different machines learn different tasks and can unlearn any task on demand.

Gradient-Recycling LoRA (GR-LoRA) recycles gradients across tasks—when a new task's gradient points in the same direction as an old task's gradient, reusing that direction saves memory and preserves old knowledge. JANUS-LoRA balances stability (holding onto old knowledge) and plasticity (learning new things) by allocating different low-rank weights to different tasks. These methods are computationally efficient because they add only small learned matrices rather than retraining full models, and they work at scale when tasks are many and data is distributed.

Stable Representations and Model Merging

Instead of protecting weights, you can learn representations—internal features—that stay stable as data changes. CoMem uses a concept graph (a learned map of ideas and how they relate) to store memory in terms of concepts rather than raw pixels, making it easier to adapt vision-language models because concepts stay consistent across domains. MoCL (Metabolic Optimization for Curvature) tracks how the learned feature space curves (the shape of features the network uses) and adapts while preserving that shape so the network's learned structure stays intact. Personalized Feature Translation learns a mapping in feature space (the internal representation layer) that adapts to a new domain without regenerating images, saving computation. Continual Learning of Domain-Invariant Representations directly learns features that work across many domains by training on mixed domain data, so the same features apply everywhere.

When features are stable, you can merge models from different tasks. HypCL adapts CLIP (a vision-language model) in hyperbolic space (a special space where distance grows with hierarchy) to keep class structure during continual learning. Learn to Merge trains a meta-learner to decide how to merge models so the merged model works on new unseen tasks. When representations capture domain-invariant patterns (the core structure), adapting requires only translating or routing those features rather than retraining from scratch, and merging works because the shared foundation allows task-specific changes to coexist.

Domain Adaptation and Conflict Resolution

The broadest direction asks: how do you learn when training and test data come from different domains? When domains shift, models must understand what changed and what stayed the same. RC-FCL (Retrospective Calibration) handles asynchronous concept drift (where different machines see data changing at different speeds), which is hard because each learns at its own pace. Decoupling Primitive with Experts (EVA) separates attributes (appearance) from primitives (identity) in zero-shot learning, so new combinations can be assembled from known parts. Demystifying Mergeability studies whether task-specific adaptations can merge together, finding gradient alignment predicts success because similar weight changes can compose.

SABER (Representation Conflict Management) detects and fixes conflicts between how tasks represent features, preventing interference where both try to use neurons differently. Unbiased, Unconfounding Causal Framework (U3CF) uses causal reasoning to block spurious patterns and preserve true patterns when adapting to new domains, since correlations in training data may not cause outcomes in new domains. Unlearning During Training uses gradient ascent to push away from old patterns, making generalization better by learning what to avoid. These papers show domain adaptation requires understanding cause and effect, not just correlation. By identifying truly causal features versus spurious ones, and managing representational conflicts across domains, models can generalize reliably to new data.
