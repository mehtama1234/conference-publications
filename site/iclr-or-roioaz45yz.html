Confidence-Weighted Preference Optimization

Train a tiny referee to spot high-confidence preferences, then use those grades to teach a large model much faster with far fewer human labels.

Paper explainersAll themesLLMs & Foundation Models

Teaching an LLM to follow human values normally means hiring humans to grade thousands of answers. This paper finds a shortcut: a smaller weak LLM can grade answers just as well, but only when it is confident. By trusting only the grades where a weak LLM is sure, you need far fewer human examples to train the large model. Surprisingly, using 20 percent human labels plus a weak referee beats using 100 percent human labels alone.

Zero assumption version

The label shortage problem

An LLM learns what to say by comparing pairs of answers: a good one and a bad one. A human labels each pair. But hiring humans to grade thousands of answer-pairs is slow and expensive.

A beginner's first try is to use a cheaper API model to grade all the pairs. That works, but API calls are still costly and slow because you pay per call, and the trained model often becomes a copy of the API model rather than learning its own style.

The method. Train a tiny LLM as a grader on a small set of human labels. Let it grade the rest of the data. But trust only the grades where it is very sure. Use those confident grades to train the main model.

The algorithm as a flow

What it actually does

Build a referee

Train the tiny model to score pairs of answers using a few hundred human labels.

Grade all data

Run the tiny model on all unlabeled answer-pairs, computing a confidence score for each.

Trust the confident ones

Keep only the pairs where the tiny model is highly sure of its judgment.

Teach the big model

Feed the selected confident pairs to the main model's training, reweighting by confidence.

Check quality

Measure how well the final model follows human values using a reward model.

What the paper changes

What the paper changes

Standard preference training uses all labeled pairs equally. CW-PO instead re-weights each pair by how confident the weak annotator was in its judgment. High-confidence grades pull training harder; low-confidence ones barely move the model.

the object it moves  =  training weights per example
The hidden quantity

Annotator confidence as a compass

measured quantity  =  confidence score from weak model

The hidden quantity is the weak model's confidence: how sure is the tiny LLM that one answer is better than the other? It is measured by the absolute difference in the model's scores for the two answers, because a model that is certain about its choice will give very different scores to the two answers, whereas a confused model gives nearly the same score to both. A large gap means high confidence; a small gap means uncertain.

The paper then uses this confidence to decide which labeled pairs are worth learning from. High-confidence pairs get full weight in training; low-confidence pairs get downweighted or dropped.

Why it works

Why selecting by confidence works

When a weak model is very confident about a pair, it means the two answers are clearly different to it. Those clear-cut cases teach the big model faster, because every learning step is a clean signal: one answer is obviously better. Unclear pairs muddied by randomness or nuance do not help the big model find the right direction, because the training signal is buried in noise and pulls the model toward average between conflicting opinions rather than toward a coherent principle.

By throwing away the low-confidence pairs, you pay a cost in volume but gain huge returns in clarity. Training on 500 clear examples teaches more than training on 5000 noisy ones. The big model learns a principle faster than it would by averaging over contradictions.

The re-weighting does one more thing: it makes the training stable. Pairs where the weak model is very sure become strong anchors that do not shift. Pairs where it waffles get ignored. This prevents the big model from being dragged in conflicting directions by weak evidence.

The reweighting formula

First in words:

For each answer pair, compute a confidence weight as the absolute difference between the weak model's scores for the two answers. Multiply that weight by the standard preference loss to get the final loss per pair. Sum over all pairs.

Then the compact form:

L_CW = sum_i w_i * L_PO(y_i^+, y_i^-) where w_i = |π_w(x, y_i^+) − π_w(x, y_i^-)|

Every symbol:

L_CWtotal loss for reweighted training
w_iconfidence weight for pair i, ranges from 0 to 1
L_POstandard preference optimization loss (how wrong one pair is)
y_i^+the preferred answer in pair i
y_i^−the dispreferred answer in pair i
π_w(x, y)weak model's score for an answer
xthe prompt or question
A tiny worked example
Pair A: weak model scores preferred answer 0.8, dispreferred 0.3. Confidence gap = 0.8 - 0.3 = 0.5.
Pair B: weak model scores preferred 0.55, dispreferred 0.50. Confidence gap = 0.55 - 0.50 = 0.05.
If standard loss per pair is 2.0, Pair A contributes 0.5 * 2.0 = 1.0 to the total loss.
Pair B contributes 0.05 * 2.0 = 0.1 to the total loss.
Training pulls 10x harder on Pair A because the weak model was much more confident. Clear signal wins.

The confidence weight amplifies strong opinions and mutes weak ones, so training focuses on examples the weak referee understood best.

What can go wrong

What can go wrong

Weak model is just wrong. If the tiny referee is trained on biased or incorrect human labels, its confidence will be confidently wrong. High confidence does not mean correct; it means the weak model is sure. Train it well.
Threshold tuning is tricky. You must decide how confident is confident enough. Too strict and you throw away useful data. Too loose and you include noise. The paper explores this but there is no one perfect number.
Domain shift breaks it. If the unlabeled data is very different from the labeled data the tiny model saw, its confidence scores may not mean what they did before. Confidence on a new kind of problem is unreliable.
Done right: iterate. The paper shows that a weak model trained on even 100 labeled pairs can grade the rest well if you filter by confidence. Start small, measure, tune the confidence threshold.
What a runnable demo should prove

What a runnable demo should prove

Build a tiny LLM (even one with 50 million numbers to adjust) and train it to grade answer-pairs using 100 human labels. On a few hundred unlabeled pairs, have it score each pair and output its confidence. Manually filter to the top 30 percent by confidence. Train a larger model using only those confident pairs, reweighting by the weak model's confidence score. Measure final model quality on a held-out reward model or human preference test.

alignment_quality = reward_model_score_aligned − reward_model_score_base

The demo must show that a model trained on 30 percent filtered labels beats a model trained on 100 percent unfiltered labels, because the filtered data is cleaner and higher-signal.
