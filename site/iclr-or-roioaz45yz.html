Weak LLM Confidence for Preference Alignment

A weak language model can align a larger model better than humans if you only use its most confident answers and weight training by that confidence.

Paper explainersAll themesLLMs & Foundation Models

Normally, teaching a language model to match human values requires paying humans to rate thousands of model outputs. This paper discovers that a smaller, weaker language model can do the rating instead — and if you only use its answers it feels certain about, the smaller model actually outperforms human raters, because weak models make fewer mistakes on cases they feel confident about, and filtering for high-confidence cuts away the noise. The trick is confidence weighting: training harder on samples the weak model feels sure about.

Zero assumption version

Why humans are expensive, and why you cannot just ask another model

Building a language model that behaves like humans want it to requires a two-step dance. First, you train the base model on text from the internet. Second, you teach it to prefer some outputs over others — the ones humans actually like.

The second step is expensive. It means showing humans pairs of model outputs and asking each one: which output do you prefer? Fixing the model's behavior needs thousands of such pairs, because one comparison only pins down a single tiny preference — each human judgment takes minutes of careful reading and thinking — so paying for thousands becomes thousands of dollars or more, so the model can learn what people prefer directly from their choices.

A natural shortcut: instead of paying humans, ask another language model. This weaker model acts as a rater, comparing outputs and picking the better one, because models can run automatically at scale. But here is the trap: when a weak model makes a judgment call, it is often wrong. It confidently picks the worse answer. Training a strong model to copy the weak model's mistaken choices makes the strong model worse, not better, because the strong model learns false lessons about which kinds of outputs are good.

In one sentence. Only use the weak model's answers when it feels confident, and during training, lean harder on those certainty signals.

The algorithm as a flow

What it actually does

1. Weak model rates outputs

A smaller language model compares pairs of outputs and picks the better one, standing in for a human judge because collecting real human labels for every pair is far too slow and costly.

2. Extract confidence

The weak model calculates how certain it is about each judgment call.

3. Filter by confidence

Keep only the judgments where the weak model's confidence is high; throw away the rest.

4. Train with weighted samples

During training, make the loss function stronger on high-confidence samples, weaker on borderline cases, because confident comparisons carry a clearer signal about which output people actually prefer.

5. Alignment emerges

The larger model learns reliable judgment rules from the cleaner, high-confidence signal.

What the paper changes

What the paper changes

The paper changes two things about how training samples are selected and weighted. First, it only uses a subset of the weak model's judgments — the ones where the weak model outputs a high probability (feels confident). Second, during training, it tells the learning algorithm to care more about those high-confidence samples and less about borderline ones.

the object it moves  =  Sample weighting and filtering
The hidden quantity

The hidden quantity: Confidence score

measured quantity  =  Confidence (the model's belief in its own judgment)

When a language model picks between two outputs, it does not just output one label. Behind the scenes, it assigns a probability to each choice — say 52% for one output and 48% for the other — so a near-even split flags a genuinely hard call while a lopsided one flags an easy, reliable preference. This probability is the confidence score. These probabilities matter because they let the training weight clear preferences more heavily than near-coin-flip ones.

The paper uses this score in two ways. First, it filters: only keep judgments where the weak model reports 70% or higher confidence (the exact threshold varies). Second, it weights: during training, each sample's importance is set proportional to the confidence score. A sample where the model was 90% sure contributes twice as much to learning as one where it was 75% sure.

Why it works

Why filtering and weighting work

A weak model makes mistakes. Sometimes it picks the wrong output and feels 80% sure about it. If you train on this sample, the strong model learns a false lesson. But the weak model also gets some calls right, often with high confidence. This separates the good from the bad.

Filtering throws away the uncertain calls — the borderline cases where the weak model was leaning 55% one way and 45% the other. These are exactly the cases the weak model is likely to get wrong. Discarding them removes noise. What remains is a set of samples the weak model nailed with real conviction.

Weighting adds a second layer. Among the high-confidence samples you kept, some are 95% confident and some are 75% confident. During training, the 95% samples get more say in how the weights adjust. The learning algorithm treats them as more reliable ground truth. This tilts the learning toward the weak model's clearest signals, because a high-confidence judgment is more likely to match what a human would have said.

The combination works because weak models and strong models agree most often when the weak model is sure. In cases of disagreement, the weak model's confidence is low. So by filtering and weighting by confidence, you are essentially saying: use the weak model's judgment, but only where it overlaps with likely-correct decisions.

Math after the picture

The training update formula

First in words:

loss equals the average weighted sample loss, where each sample's weight is the weak model's confidence score

Then the compact form:

L_total = mean(c_i * L_i) where c_i is confidence and L_i is the preference loss for sample i

Every symbol:

c_iThe confidence score of the weak model on sample i (a number from 0 to 1)
L_iThe preference loss for sample i (the learning signal, showing how wrong the prediction is)
L_totalThe total loss the training algorithm tries to minimize
meanAverage across all selected samples
A tiny worked example
Suppose we have three high-confidence samples, each with loss 2.0.
Sample 1: confidence 0.9, so weighted loss = 0.9 * 2.0 = 1.8
Sample 2: confidence 0.8, so weighted loss = 0.8 * 2.0 = 1.6
Sample 3: confidence 0.7, so weighted loss = 0.7 * 2.0 = 1.4
Total loss = mean(1.8, 1.6, 1.4) = 1.6
Without weighting, total loss would be 2.0. Weighting by confidence lowers the overall loss signal, telling the algorithm to focus on the clearest calls.

Weighting by confidence means the training algorithm listens more to the samples the weak model was surest about.

What can go wrong

What can go wrong

The weak model is confidently wrong. If the weak model has a systematic bias — say it always prefers verbose answers — it will be highly confident about that wrong preference. Filtering does not catch this. The result: the strong model learns the bias too.
Confidence threshold set too high. If you only keep samples where confidence exceeds 95%, you throw away so much data that the strong model does not learn enough. The model improves in a narrow way but misses the broader range of behaviors humans want, because the judge only rewards the specific qualities it was trained to compare and ignores the rest.
Confidence score miscalibrated. Some models claim high confidence even when uncertain. If the weak model's reported confidence does not match its actual accuracy, the weighting goes wrong.
Done right: weak model is diverse and honest. If the weak model is built well, trained on varied data, and its confidence reflects real uncertainty, filtering and weighting gives a clean learning signal.
What a runnable demo should prove

What a runnable demo should prove

Build a simple preference alignment experiment: take a pre-trained language model (even a tiny one); have it generate output pairs for a task like question-answering. Then use a second, weaker model to rate the pairs and assign confidence. Train a third model using three different methods: (A) all weak model judgments unweighted, (B) high-confidence judgments only (filtered), and (C) high-confidence judgments weighted by confidence (CW-PO). Measure the accuracy of each trained model on a held-out set of human judgments.

Alignment accuracy = fraction of human-held-out pairs the trained model ranks the same way as humans

CW-PO should match or beat the unweighted version using far fewer training samples — ideally, 50% of the samples.
