BiCrossNet with Decoupled Dual Generators: A Parameter-Efficient and Generalizable Few-Shot Custom Gesture Recognition Framework

Recognize custom gestures from very few inertial-sensor examples by combining a compact two-branch recognizer with two generators that create additional variation in motion change and feature space.

Paper explainersAll themesOther

Custom gesture recognition from IMU data is hard because each user may define new motions, but collecting many examples of every gesture is inconvenient and often impossible on small devices. A deployable system needs to learn from a few recordings while keeping the model compact. This paper proposes BiCrossNet, an IMU-based recognizer, together with two augmentation generators. One generator creates new delta patterns, meaning changes between sensor readings over time. The other generator creates new embedding samples (an embedding is a learned internal representation, and a feature vector is a list of numbers that summarizes a whole gesture). The two generators are decoupled, so they expand the training set at two different levels instead of forcing one model to invent all variation at once.

Zero assumption version

Why few-shot gesture recognition is awkward on real devices

An IMU gesture system reads accelerometer and gyroscope streams and must map them to gesture labels. The target gestures may be user-defined, which means there may be only a handful of examples for each class. A large model may fit those few examples, but it is hard to deploy on lightweight hardware.

Data scarcity creates a second problem beyond raw accuracy. The model must generalize across differences in speed, amplitude, and style even when it has seen only a small number of recordings. If those variations are not represented in training, the recognizer learns a brittle boundary that matches the recorded samples too closely and fails when a user performs the same gesture slightly differently.

The paper's move. Use a compact recognizer plus two separate data generators, one for motion deltas and one for learned feature embeddings, because variation enters the problem both before and after feature extraction.

What the paper changes

What the paper changes

The paper changes both the recognizer design and the way few-shot training data is expanded. Instead of relying on a single model to compensate for scarce examples, it adds targeted synthetic variation at the raw-change level and at the learned-feature level.

The hidden quantity

The hidden quantity

measured quantity  =  within-class variation that the few-shot set failed to capture

The hidden quantity is the full range of ways a person could perform the same gesture even though the training set contains only a few recorded examples. That missing variation includes timing shifts, amplitude changes, and small stylistic differences.

The method tries to reconstruct that missing variation in two stages. The delta-generator expands how local motion changes can look over time, while the embedding-generator expands where class members can lie in the learned feature space. Those two generators target different parts of the data pipeline, which matters because not every useful variation is easy to create directly in raw sensor coordinates.

Why it works

Why decoupling the generators helps

A gesture recognizer fails in few-shot settings when it sees too little class variation during training. One possible fix is to generate more raw sequences, but that asks one generator to learn every source of variation at once. This paper splits the job. The delta-generator focuses on local temporal changes in the sensor stream, which directly affects how the motion unfolds across time. That helps the model tolerate differences in speed and transition shape because the classifier is trained on more than one valid way for the same gesture to evolve over time.

The embedding-generator works later in the pipeline. After BiCrossNet extracts a compact feature representation for a gesture, the embedding-generator expands that representation with new synthetic points from the same class. This matters because the learned feature space has already compressed away some nuisance details, so generating there can fill class coverage more directly than generating only at the raw input level.

The recognizer also stays compact because the main network does not need to grow very large to memorize scarce data. Instead, the richer support set created by the generators gives the classifier a broader picture of each class. That is why the method can improve recognition while still reducing model size compared with heavier baselines.

A simple training objective view

First in words:

The recognizer can be trained on the union of real examples and generated examples. The goal is to reduce classification error across both sets so that the learned class boundary reflects more than the few recorded traces.

Then the compact form:

training_set = real_samples plus delta_generated_samples plus embedding_generated_samples ; loss = average classification error over training_set

Every symbol:

real_samplesthe original labeled IMU gesture recordings
delta_generated_samplessynthetic samples created from motion-delta variation
embedding_generated_samplessynthetic feature examples created in embedding space
training_setall examples used to train the recognizer
lossthe average classification error the model tries to reduce
A tiny worked example
Suppose each of four gesture classes has only 5 real recordings, for 20 real samples total.
The delta-generator adds 3 temporal variants per real recording, producing 60 extra sequence-level samples.
The embedding-generator adds 2 feature-level variants per real recording, producing 40 extra feature examples.
The recognizer now trains against an effective support set of 120 examples instead of 20.
Those extra examples matter only if they stay class-consistent, because otherwise the larger set would add confusion rather than coverage.

The exact losses in the paper are more detailed, but the core training logic is simple: improve the classifier by supplementing scarce real data with carefully targeted synthetic variation.

What can go wrong

What can go wrong

Generated samples may drift off class. If either generator creates motion or feature variants that no longer correspond to the intended gesture, the recognizer will learn a blurred class boundary and accuracy can fall instead of rise.
The few real examples may be too narrow to guide generation. A generator can only extrapolate from what it has seen. If the seed examples all come from one user style, the synthetic variants may stay trapped near that style and fail to cover true deployment variation.
Compactness can still cap representation quality. Reducing model size helps deployment, but a model that is too small may discard distinctions between similar gestures before the generators can help, because the feature extractor itself becomes the bottleneck.
Done right. The approach works best when the compact recognizer preserves the essential gesture structure and the generators add valid variation rather than arbitrary noise.
What a runnable demo should prove

What a runnable demo should prove

Collect a small IMU gesture dataset with a few custom classes and only a few recordings per class. Train four systems: the base compact recognizer, recognizer plus delta generation only, recognizer plus embedding generation only, and the full BiCrossNet framework. Test on held-out users who perform the same gestures with different speeds and styles.

The demo should show that the full system recognizes more gestures correctly because it expands class coverage at two complementary stages. It should also report parameter count (a parameter is one learned numeric setting inside the model) so the tradeoff between device suitability and recognition quality stays visible.

few_shot_gain = accuracy_full_system minus accuracy_base_compact_model ; size_ratio = model_parameters_full_system divided by model_parameters_baseline

The important proof is that the extra generated support helps the model generalize to new performances without giving up the compact model size needed for on-device use, because the added class variation reduces overfitting while the recognizer itself stays small.
