BaseReward: Building a Multimodal Preference Judge

A systematic study of what makes a multimodal model accurately score whether a vision-language model's answer matches human taste.

Paper explainersAll themesMultimodal

A multimodal model (one that reads images and text together) must learn to guess what humans think of its answers. A reward model is a separate model trained to score answers: high score means humans would like it, low score means they would not. This paper tests every choice — from the shape of the scoring brain to which data to train on — to build the most accurate reward model. The discovery: a specific recipe (a Qwen2.5-VL backbone, a two-layer scoring head, and a careful mix of multimodal and text-only examples) consistently outperforms all others because each piece solves a part of the puzzle: a strong backbone understands how images and text relate to each other, two layers strike a balance between expressiveness and avoiding overfitting, and mixed data teaches the model the full spectrum of human preference.

Zero assumption version

Scoring vision-language answers is hard

A vision-language model (a model that reads pictures and text) can generate many possible answers to the same question. A human evaluator can say which ones are good and which ones are bad. But you cannot ask a human to score every answer your model produces — that would be too slow and expensive.

A naive approach: train a simple classifier to mimic human judgments. But the classifier might focus on the wrong clues (e.g., answer length instead of correctness) or generalize poorly to new questions or image types. Different choices in how you build the scoring model (which backbone to use, how many scoring layers, which training data to include) lead to wildly different accuracy. Without a systematic guide, practitioners guess.

In one sentence. The paper tests every design choice in building a reward model and publishes the winning recipe.

What the paper changes

The recipe: backbone, head, and data

The paper changes three things at once: which base vision-language model to use (the backbone), how many layers in the scoring head (the final small network that outputs a score), and which datasets to train on (text-only preference data plus multimodal preference data, in a specific ratio). Each choice cascades: a weaker backbone might need a fancier head to compensate, but that fancier head might not train well on all data. The paper's insight is that certain combinations work together.

the object it moves  =  Backbone, scoring head, training data mixture
The hidden quantity

The hidden quantity: preference prediction error

measured quantity  =  How often the reward model disagrees with humans

The paper must measure whether the trained reward model is actually good. The core question: given two answers, does the reward model rank them in the same order as humans would? Preference prediction error is the fraction of pairs where the model gets the ranking backwards.

The paper estimates this by testing on held-out preference datasets (collections of answers that humans have already ranked). For each pair of answers, the reward model predicts which is better, and the tester checks whether it matches the human ranking. Lower error is better, because an error means the reward model will steer the vision-language model to learn the wrong preference during reinforcement learning.

Why it works

Why this recipe works: the three pillars

The Qwen2.5-VL backbone already understands how to read images, text, and how they relate to each other, so the reward head does not have to learn vision from scratch. Starting from a model that already works means the reward head only needs to adjust the final layers to learn what humans prefer.

A two-layer scoring head (not one, not three) strikes a balance: one layer is too simple to capture nuanced preference judgments (e.g., answer A is factually correct but rude, answer B is friendly but vague; the model needs to weigh those trade-offs). Three or more layers risk overfitting to the training data and failing on new preference patterns. Two layers give enough expressive power without going too deep.

The data mixture (multimodal examples plus text-only examples) teaches the model to judge along two dimensions: it learns from images-plus-answers (multimodal examples) how humans rate visual reasoning, and from text-only examples how humans judge language fluency, factuality, and style. Training on only one type narrows the model's sense of preference; mixing both teaches it to recognize that good answers need both visual reasoning and clear language.

Math after the picture

The scoring equation

First in words:

score equals the output of a small two-layer network that takes the base model embedding and produces a single number between zero and one

Then the compact form:

score = sigmoid(W2 * relu(W1 * embedding + b1) + b2)

Every symbol:

embeddingthe feature list from the Qwen2.5-VL model
W1, b1weights and bias of layer one
W2, b2weights and bias of layer two
relua simple nonlinearity: pass positive numbers through, zero out negatives
sigmoida function that squashes any number into a score between zero and one
scorethe final preference prediction: close to one means humans like this answer
A tiny worked example
Say the Qwen embedding is a list of ten numbers: [0.2, -0.1, 0.5, 0.3, -0.2, 0.4, 0.1, -0.3, 0.6, 0.25].
Layer 1 transforms this via relu: multiply by W1, add b1, then zero out any negatives. Result: [0.18, 0, 0.45, 0.27, 0, 0.36, 0.09, 0, 0.54, 0.22] (example numbers).
Layer 2 collapses this to a single score: multiply by W2, add b2, apply sigmoid. Result: 0.78 (a probability).
Interpretation: the model predicts humans would rate this answer 78 out of 100. If the true human rating is also high, the score was correct.

The actual reward model uses a pretrained Qwen2.5-VL embedding, so W1 operates on thousands of features; the two-layer head is tiny, just steering those features toward preference prediction.

What can go wrong

What can go wrong

Using too deep a head. A three or four layer scoring head memorizes the training data and fails on new preference patterns, because it has too many degrees of freedom. The model becomes brittle.
Training only on text-only data. The model learns to judge text fluency and factuality but ignores visual reasoning failures, because it never saw image-plus-answer pairs in training. It scores visual answers poorly.
Starting from a weak backbone. An older or smaller vision-language model has weaker image understanding, so even a two-layer head cannot extract the right features. The final accuracy ceiling is lower.
Done right. With the BaseReward recipe (Qwen2.5-VL, two-layer head, mixed data), the model generalizes across visual and language preference types and remains stable as new tasks arrive.
What a runnable demo should prove

What a runnable demo should prove

Build a toy pipeline to test if BaseReward learns genuine preference, because comparing its scores to human judgments on new examples reveals whether it learned the real pattern or only memorized: (1) Generate two answers to a question about an image (e.g., from a weaker model and a stronger model). (2) Use BaseReward to score both answers. (3) Check which answer is better by asking a human or using an oracle rule (e.g., the stronger model's answer is better, because it tends to align with human preference). (4) Record whether BaseReward ranked them the same way. Repeat on a few diverse images and questions. Count the fraction of correct rankings.

accuracy = (number of preference pairs BaseReward ranked correctly) / (total number of pairs)

If BaseReward achieves over 75% accuracy on a diverse set of held-out image-question-answer triples, it is learning genuine human preference, not memorizing the training set.
