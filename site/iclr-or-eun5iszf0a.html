BaseReward: Building Multimodal Reward Models

A systematic recipe for building strong multimodal reward models by carefully choosing and combining existing components.

Paper explainersAll themesMultimodal

A reward model is a tool that scores how well an AI model's answer matches what a human would prefer. The paper shows there is no official recipe for building these models for multimodal systems (models that handle both text and images). Instead of inventing a new technique, the authors test every knob—the shape of the scoring head, the training method, which datasets to use, which backbone model, and how to blend different models together—and publish the recipe that works best.

Zero assumption version

No blueprint exists for building strong multimodal reward models

Multimodal large language models (models that understand both images and text) are getting better, but steering them toward human preferences is hard, because the main model has no built-in sense of what humans actually want—it just predicts the next word based on patterns in its training data. A reward model is the tool that does the steering—it scores an answer as good or bad so the main model can learn from feedback.

Today, every company and lab builds reward models differently. One might use a simple linear scoring head, another might ask the model to explain its reasoning first, then score it. Nobody knows which choices matter and which do not. A beginner would try random combinations and hope one works.

The paper's move in one sentence. Test every decision in reward model design on real multimodal datasets, then publish the exact combination that works best.

The algorithm as a flow

What it actually does

Pick a pretrained multimodal backbone

Start with a finished model (Qwen2.5-VL) that already understands images and text.

Attach a simple scoring head

Add a two-layer neural network that reads the model's hidden reasoning and outputs one number: the score.

Gather preference pairs

Collect examples where humans said one answer is better than another (across text-only and multimodal tasks), because the model learns by seeing patterns in these comparisons—more data types teach it to judge across more situations.

Train to predict preferences

Adjust the scoring head so it assigns higher scores to the better answers and lower scores to worse ones.

Use it to guide the main model

When training the main model, use the reward scores as learning signals so it learns to produce preferred answers.

What the paper changes

What the paper changes: the reward head

The paper does not invent a new scoring method. Instead, it systematically picks the best existing piece for each role. The main object it examines is the reward head—the neural network that reads the model's internal reasoning and outputs a score. The paper tests whether this should be a simple one-layer network (fast but limited), a two-layer network (balanced), or a three-layer network (richer but slower).

The hidden quantity

The hidden quantity: preference alignment error

measured quantity  =  How often the model scores human preferences backward

The hidden quantity is how well the reward model learns to agree with human preference judgments. On every test pair—one answer humans liked, one they disliked—the reward model either gets it right (higher score for the preferred answer) or wrong (lower score for the preferred answer). Preference alignment error is the fraction of pairs it gets wrong. Lower is better, because if the reward model scores preferences backward, it teaches the main model to produce worse answers.

The paper measures this by testing on four domains: Chat (conversations), Safety (harmful vs. safe answers), Code (programming tasks), and Math (mathematical reasoning). For each domain, it counts how many preference pairs the model scores in the correct order.

Why it works

Why each choice matters: the causal chain

A reward model is a tool to guide learning. Its job is to read an answer (from an image and text) and output a single number that means how good that answer is, according to human preference. If the reward model is wrong, the main model learns the wrong lesson.

The paper shows why certain pieces work better than others. A two-layer reward head outperforms a single layer because a single layer has to compress all its judgment into one step—like trying to understand a photograph by looking at only the reddest pixel. Two layers allow the model to build intermediate reasoning: the first layer can pick out relevant details, and the second layer can weigh them. Three layers do not help further, because the gain stops (the bottleneck moves upstream to the backbone, not the head).

Likewise, training on a mixture of multimodal and text-only data beats using only multimodal data. Text-only data teaches the model to judge writing quality, reasoning, and factuality in pure language—skills that transfer to multimodal answers too. A backbone that was pretrained to understand both images and text (like Qwen2.5-VL) handles both modalities better than a text-only backbone, because it has already learned the visual patterns.

Combining many trained models (ensemble) works because each model makes independent mistakes. A voting system that averages their scores catches errors that any single model would miss—similar to a jury being more reliable than a single judge, because when ten people make random errors, most votes still go toward the truth, whereas one person's mistake can point the wrong way.

The preference training equation

First in words:

Loss equals negative log of the sigmoid of the difference between the score for the preferred answer and the score for the non-preferred answer.

Then the compact form:

Loss = -log(sigmoid(R(y_w) - R(y_l)))

Every symbol:

R(y_w)The score the model gives to the answer humans preferred
R(y_l)The score the model gives to the answer humans disliked
sigmoidA curve that squashes any number into a probability between 0 and 1
LossThe error we minimize; lower means the model learns to rank answers correctly
A tiny worked example
Suppose the model scores a good answer (y_w) with 5.0 and a bad answer (y_l) with 2.0.
The difference is 5.0 - 2.0 = 3.0.
sigmoid(3.0) is approximately 0.95 (very close to 1, correct ranking).
-log(0.95) is approximately 0.05 (tiny loss, this is good).
Now suppose it ranks them backward: good answer scores 2.0, bad answer scores 5.0.
The difference is 2.0 - 5.0 = -3.0.
sigmoid(-3.0) is approximately 0.05 (close to 0, wrong ranking).
-log(0.05) is approximately 3.0 (large loss, training will fix this).

The loss is smallest when the model ranks the preferred answer higher, and grows as the ranking gets more wrong, so training naturally pulls the model toward human judgment.

What can go wrong

What can go wrong

Adding layers without improving the backbone. If the backbone model is weak, adding more layers to the reward head cannot make up for it. The limitation is upstream. You must start with a strong multimodal model.
Training only on one type of data. A model trained only on text cannot judge multimodal answers well, and one trained only on images cannot reason about language. The model must see both during training.
Trusting ensemble too much. An ensemble averages mistakes only if the models are independent. If all models are trained the same way on the same data, they will make the same errors together, and voting does not help, because unanimous wrong votes are still wrong.
Done right. Start with a strong multimodal backbone already pretrained on both images and text (because it already understands both modalities), add a two-layer scoring head (because it balances expressiveness and efficiency), train on a careful mix of real preference data across domains (because diversity teaches the model to judge across situations), and optionally ensemble independent models for a final boost (because independent voting catches more errors).
What a runnable demo should prove

What a runnable demo should prove

Build a small multimodal reward model: take a pretrained model like Qwen2.5-VL, attach a two-layer scoring head, and train it on a subset of preference pairs from the paper's datasets. Then test it on held-out preference pairs to measure how often it scores the better answer higher than the worse one, because that is the direct test of whether the model has learned human preference patterns. The metric is preference accuracy (fraction of pairs ranked correctly).

Preference accuracy = (number of pairs scored in the correct order) / (total number of test pairs)

The demo should show that a two-layer reward head on a strong backbone, trained on mixed data, achieves higher preference accuracy than either a single-layer head or training on only one data type.
