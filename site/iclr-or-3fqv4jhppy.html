Expanding Reasoning Potential by Learning Diverse Chains of Thought Patterns

To teach a reasoning model harder problems, pick the training examples that unfold the most useful thinking patterns, measured by how many independent attempts the model needs per problem.

Paper explainersAll themesOther

Reasoning models (AI systems that think step by step through math problems) get better when trained on examples that show HOW to think, not just answers, because seeing the reasoning path teaches the model to follow similar paths on new problems. But training on all available thinking-examples is wasteful — many repeat the same reasoning move. This paper says: measure how hard a problem truly is by counting how many independent tries a model needs to solve it, then select training examples that contain the atomic thinking patterns hidden in successful solutions, so training teaches the model the most versatile reasoning building blocks.

Zero assumption version

The data selection trap

Reasoning models learn to solve hard math problems by training on examples that show step-by-step thinking. Currently, teams just grab every available thinking-example and throw it at the model. But not all examples are equally valuable: some show the same reasoning move over and over, while others reveal new patterns the model has never seen.

A beginner would try: train on all available data. But this buries rare, valuable reasoning patterns in a sea of repetitive ones. The model spends training capacity learning the same move dozens of times instead of learning diverse thinking patterns it actually needs.

The question: Which examples truly expand what the model can think? Pick training examples by measuring problem difficulty (how many tries a model needs) and selecting for the hidden reasoning patterns they contain.

The algorithm as a flow

What it actually does

Measure problem difficulty

Count how many independent attempts a model needs to solve each problem (call this the reasoning potential).

Extract reasoning patterns

Break down each thinking-example into atomic reasoning moves (substitution, grouping, testing bounds).

Find a core reference

Build a small set of examples that together contain the most common AND rare reasoning patterns.

Score all data

For each training example, score how well its reasoning patterns match the core reference, plus how coherent its thinking is (via entropy of word probabilities).

Select and train

Train on only the top-scoring examples, which pack rare patterns into each step. This achieves the same or better results with 10 times less data because each training example teaches more new reasoning moves.

What the paper changes

The thing the paper changes

Instead of training on ALL thinking-examples equally, the paper changes which EXAMPLES get selected for training. It filters the raw data to keep examples that contain valuable reasoning patterns and drops redundant ones.

The hidden quantity

Reasoning potential: the hidden quantity

measured quantity  =  Reasoning potential

This is the paper's key measurement: the number of independent random attempts a model needs to solve a problem by just guessing (before it learns the pattern). A problem that requires 5 tries on average has reasoning potential 5. A trivial problem that succeeds on the first try has reasoning potential 1.

The paper measures this by repeatedly running the model on the same problem with fresh random seeds and counting successes. A problem with high reasoning potential is genuinely hard — it stretches what the model can learn. A problem with low reasoning potential is either solved by luck or by a pattern the model already knows.

Why it works

Why picking rare patterns makes models reason better

When you train a model on EVERY thinking-example indiscriminately, you waste training time on redundant examples. If 50 of 100 examples show the same reasoning move (e.g., factoring), the model learns that move perfectly but never learns a rarer move (e.g., testing boundary conditions) that appears in only 5 examples and gets buried.

The paper extracts atomic reasoning patterns from each thinking-example and builds a core reference set: a small collection of examples that together covers the full range of reasoning moves the data contains. Then it scores each example by how much its patterns align with this reference, weighted by how rare or unusual those patterns are. Finally, it trains only on high-scoring examples.

This works because the model's reasoning ability is bottlenecked by the rarest, most unusual patterns. If training touches those patterns, the model learns to use them flexibly. If training ignores them (because they're buried in noise), the model never gains that capability. By selecting for pattern diversity, the paper guarantees the training process hits all the important reasoning modes, so the model learns to reason more deeply.

Math after the picture

How to score an example

First in words:

score of example = (how well its reasoning patterns match the reference set) times (how coherent its thinking is)

Then the compact form:

score_e = (sum of pattern_match_i for each pattern i) times exp(-entropy_of_tokens)

Every symbol:

score_ehow valuable this example is for training (higher is better)
pattern_match_ihow strongly example e contains the reasoning pattern i (scaled 0 to 1)
entropy_of_tokensthe randomness of word choices in the thinking sequence; low entropy means the thinking is clear and follows a consistent path
exp(-)makes the score smaller if the thinking is muddled (high entropy), bigger if thinking is clear
Tiny worked example
Example A contains patterns: grouping (match 0.9), substitution (match 0.8), testing (match 0.3). Sum = 2.0. Entropy = 0.5. Score = 2.0 * exp(-0.5) = 2.0 * 0.6065 = 1.21.
Example B contains patterns: grouping (match 0.3), substitution (match 0.2), testing (match 0.1). Sum = 0.6. Entropy = 0.5. Score = 0.6 * exp(-0.5) = 0.6 * 0.6065 = 0.36.
Example A scores 1.21, Example B scores 0.36. Example A covers more reasoning patterns and gets higher score. Training picks A first.

An example that touches many reasoning patterns and expresses them clearly scores high and gets selected for training.

What can go wrong

What can go wrong

Reference set is too small. If the core reference set misses rare patterns, the selection algorithm will never find examples containing those patterns. The model learns only the common moves.
Patterns are not truly atomic. If the extracted patterns are too large (e.g., entire problem-solving strategies instead of individual reasoning moves), the selection becomes coarse and misses fine-grained diversity.
Entropy threshold is wrong. If the entropy weight is too strong, the algorithm penalizes examples with exploratory thinking and selects only safe, conventional patterns. If too weak, incoherent or garbled reasoning gets picked.
Done right. The reference set is built by careful analysis of a representative sample, patterns are extracted at the right level of detail (individual reasoning moves like substitute, group, test), and entropy is tuned so clear, unconventional reasoning is still selected.
What a runnable demo should prove

What a runnable demo should prove

Build a small math reasoning task (e.g., solving quadratic equations or factoring polynomials). Collect 1000 thinking-examples from a model solving these problems. Extract reasoning patterns (e.g., recognize standard form, apply quadratic formula, check discriminant). Build a reference set of 50 diverse examples. Score all 1000 examples by pattern coverage and entropy. Train two models: one on all 1000 examples, one on the top 100 selected examples. Measure their performance on a held-out test set of new problems.

performance_gain = (accuracy_selected / accuracy_all)

If the paper's idea works, the model trained on selected high-value data should match or beat the model trained on all data, using 90% less training data.
