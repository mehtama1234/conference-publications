Breaking the SFT Plateau: Multimodal Structured Reinforcement Learning for Chart-to-Code Generation

When training a model to turn charts into code, adding more data eventually stops helping, but pairing textual code-correctness checks with visual chart-shape checks breaks through that wall.

Paper explainersAll themesMultimodal

Imagine teaching a student to copy a chart into working Python code. At first, more examples help a lot, because the student is still discovering the main rules: how to structure code, where to read data, how to map colors to the chart. But after thousands of examples, the student stops improving even with new data; this is the SFT plateau, where the model has learned the easy patterns and just repeats them. A new paper shows a way to break through it: use two kinds of feedback at once. One judge checks if the code is syntactically correct and pulls the right values from the chart. Another judge renders the code and compares the output picture to the original chart. Together, these two feedback sources wake up the model in ways that more data alone cannot.

Zero assumption version

More data hits a wall

Chart-to-code is hard. You have a colorful chart: bars, lines, scatter points, maybe dozens of data series stacked together. You need to write code that recreates it. The model must understand the numbers inside the chart, the colors, the labels, and turn all that into working Python.

Supervised fine-tuning (SFT) is the straightforward approach: give the model thousands of chart-code pairs, and it learns to copy the pattern. It works, at first. But experiments show it hits a performance plateau: after a few million training examples, adding more examples barely helps, because the model has already learned the most common patterns and simply repeats them; rare variations do not appear in enough data to sink in. The curve flattens. The model seems stuck.

In one sentence. MSRL splits the feedback: one checker verifies the code works and reads the data correctly, while another checker looks at the rendered picture and grades how well it matches the original chart.

The algorithm as a flow

What it actually does

Stage 1: textual reward

Train the model using feedback that grades code syntax, rule compliance, and whether extracted values match the chart data.

Stage 2: visual reward

Continue training with a second judge that renders the code and compares the rendered picture pixel-by-pixel to the original.

Curriculum order

Do text-only training first until it converges, then layer in the visual judge; reversing this order weakens the gain.

Data curation

Use only high-quality training examples (real charts from arXiv papers + code generated by strong models), filtered to avoid noise.

Result

The model breaks through the SFT plateau and reaches new performance levels on standard benchmarks.

What the paper changes

What the method changes

The method changes the feedback signal during training. Instead of using only one kind of loss (the distance between predicted code and ground-truth code), it switches to two-sided grading during reinforcement learning: a textual judge that checks code correctness, and a visual judge that checks picture likeness.

the object it moves  =  feedback signal: from one kind to two kinds
The hidden quantity

The hidden quantity: structural alignment

measured quantity  =  visual-semantic gap

SFT only measures one thing: whether the model's code matches the ground-truth code string. But two different code strings can render the same picture (different variable names, different loop structures, equivalent operations). The paper names a hidden quantity: structural alignment, measured as how close the rendered output picture looks to the target. This is invisible to text-only training but absolutely needed for real correctness.

The paper estimates it using a visual reward model: a separate trained model that compares two rendered charts and scores how similar they are. A high visual score means the code creates the intended picture, regardless of the exact code string.

Plain reading. The model's hidden problem: it can write code strings that sound right but render wrong pictures. Adding more code examples does not teach it to render correctly because the text-only loss ignores how the picture looks.
Paper reading. The paper introduces a visual reward as a model-based evaluator that scores structural similarity between the rendered code output and the ground-truth chart. This reveals whether the model is learning to produce visually correct outputs, not just syntactically valid code.
Why it works

Why two judges wake up the model

The model is stuck because SFT only gives one signal: match the code string. But code strings are lossy descriptions of pictures. Two different strings render the same thing. So the model converges to a shallow pattern: memorize the most common code forms, ignoring nuance, because the text signal cannot tell the model that variant forms are equally valid—the model only sees that one form appears in the training data and copies it.

Introducing a visual judge adds a new channel of truth. Now the model gets feedback not just on string-matching but on picture correctness. This is harder to game. The model must genuinely understand which colors, values, and shapes to place where. Because the visual signal is independent of the code string, it pulls the model to richer, more accurate internal reasoning.

The two-stage curriculum matters: train with textual feedback first so the model learns syntax and data extraction in a stable way, because textual rules are clear and unambiguous—they give clear signals about which way to nudge the weights. Only then layer in visual feedback. If you mix them from the start, the model oscillates and struggles to converge, because the textual and visual signals pull in slightly different directions and the model cannot balance them. Training in stages is like learning to write first, then learning to make beautiful handwriting.

The reward equation

First in words:

The total training signal is a weighted sum of three components: textual reward (for code correctness), visual reward (for picture similarity), and a regularization term to prevent the model from drifting too far from its starting point.

Then the compact form:

R_total = w_text * R_text + w_visual * R_visual + beta * R_regularization

Every symbol:

R_totalthe combined reward signal guiding training
R_textscore from textual judge (0-1, higher means code is correct)
R_visualscore from visual judge (0-1, higher means rendered chart matches)
R_regularizationpenalty for moving model weights too far from start
w_texthow much to weight the textual feedback
w_visualhow much to weight the visual feedback
betahow strongly to enforce stability
A tiny worked example
Suppose a generated code receives R_text = 0.8 (code is mostly correct but one variable is wrong) and R_visual = 0.6 (chart shape is close but one bar is the wrong color).
With w_text = 0.6, w_visual = 0.4, beta = 0.01, R_regularization = 1.0: R_total = 0.6 * 0.8 + 0.4 * 0.6 + 0.01 * 1.0 = 0.48 + 0.24 + 0.01 = 0.73
The model learns that this code is pretty good (0.73 is high) but not perfect. In the next iteration, it tweaks both the variable and the color.
A second generated code gets R_text = 0.9 and R_visual = 0.9 (both judges agree this is excellent): R_total = 0.6 * 0.9 + 0.4 * 0.9 + 0.01 * 1.0 = 0.54 + 0.36 + 0.01 = 0.91.
The model strongly prefers the second code, so it learns to aim for dual correctness.

In words: the training signal combines textual correctness and visual fidelity, weighting each, so the model learns to write code that both parses and renders correctly, because high rewards encourage the model to explore code variations that satisfy both judges simultaneously.

What can go wrong

What can go wrong

Reward hacking on textual judge alone. If you only optimize textual rewards (Stage 1 only), the model learns superficially: it writes syntactically correct code that passes basic checks but does not truly understand the chart. The visual judge catches this.
Mixing stages hurts convergence. If you train with both textual and visual rewards from the start, gradients point in conflicting directions: text wants one kind of simplicity, visuals want another. The model oscillates and converges slowly. The paper shows this empirically; training in order (text first, then visual) is essential.
Visual judge mislabels niche charts. The visual reward model is trained on common charts. On rare or exotic chart types (uncommon combinations of stacked bars, rotated axes, unusual color schemes), it can give misleading scores. High-quality curation helps, because filtering examples to only the cleanest, most representative charts teaches both the main model and the visual reward model on the kinds of charts they will actually see.
Done right. Use real-world data for training (not synthetic), filter for high-quality examples, train stages in order, and pair both judges. The method works well across 24 different chart types.
What a runnable demo should prove

What a runnable demo should prove

Build a small demo with a few real chart-code pairs. Train a simple model on them using only textual rewards until it plateaus (a few hundred iterations). Record the final accuracy (e.g., 65%). Then continue training with visual rewards for the same number of iterations. Plot the accuracy curves side-by-side. The visual-reward curve should climb above the textual plateau.
