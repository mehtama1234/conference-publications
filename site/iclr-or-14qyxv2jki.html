Breaking the SFT Plateau: Multimodal Structured Reinforcement Learning for Chart-to-Code

When teaching a model to turn charts into code, supervised learning hits a wall; using rewards that check both the code and the visual output breaks through it.

Paper explainersAll themesMultimodal

Imagine teaching a person to turn a bar chart into spreadsheet code. You can show them many examples, and they improve at first because each example teaches them a new pattern they have not seen before. But eventually, all the easy patterns are memorized, and new examples show only rare edge cases and tiny variations — the learning slows to a halt. This paper shows that adding a reward system that grades the code two ways (does the code work? does it draw the right picture?) lets the model jump over that wall and keep improving.

Zero assumption version

The supervised learning plateau

Chart-to-code is hard because the model has to see a visual image, understand what it shows (which rows, which bars, which colors matter), and then write code that makes the exact same picture when it runs. It is not enough to write code that is syntactically correct; the code has to draw the right thing.

When you train with supervised learning (showing examples and correcting the code word-by-word), the model learns quickly at first. But after eating millions of examples, each new example teaches the model less and less. Researchers call this the plateau: more data stops helping.

In one sentence. Supervised fine-tuning alone runs out of steam; the model plateaus because it has no way to learn from its own mistakes.

The algorithm as a flow

What it actually does

Start with supervised learning

Train the model on chart-code pairs until it hits the plateau.

Grade the code

Check each line of generated code for syntax and chart-specific rules.

Grade the visual output

Run the code, render the chart, compare pixels to the ground truth.

Give two rewards

Score progress on code quality and visual match separately.

Optimize with both

Train the model to maximize both scores, pushing past the plateau.

What the paper changes

What the paper changes

Instead of just correcting the model word-by-word from examples, the paper adds a second kind of teaching: rewards. These rewards do not come from human annotation; they are computed automatically by running the code and checking if the picture looks right.

the object it moves  =  Rewards from visual feedback
The hidden quantity

The hidden quantity: visual alignment score

measured quantity  =  How well the rendered code matches the chart

This is the paper's new measurement. It is not just syntax or correctness; it is the visual distance between what the model's code draws and what the real chart looks like. A model-based reward system reads the generated code, runs it, captures the picture, and measures the pixel-level similarity to the ground truth.

The paper uses this hidden score to steer training. As the model learns to write code, it does not just try to match example solutions word-for-word; it also learns to make pictures that look like the target.

Why it works

Why breaking two rewards breaks the plateau

Supervised learning hits a wall because the model sees examples but only learns one kind of feedback: whether each word matches the reference code. After millions of examples, there is no new pattern left to find; the model has memorized the correspondences it will ever see.

The paper adds a second channel: visual rewards. These are not based on matching words; they are based on checking if the rendered picture looks right. This gives the model a completely new learning signal. When the model tweaks the code in a way that makes the picture closer to the target — even if those tweaks are not in any training example — the visual reward still catches it and says so. The model learns to maximize picture-similarity, not just word-similarity. This is a new direction to optimize, so training can escape the plateau.

The two-stage curriculum is the second move. First, the model optimizes using only code-level rewards (syntax, chart-specific rules). This teaches it to write valid code. Then, visual rewards are turned on, and the model learns to make pretty pictures. By staging them, early training focuses on correctness, and late training focuses on visual polish. Together, these two changes let the model go from stuck to progressing again.

Math after the picture

The reward equation

First in words:

total_reward = alpha times code_reward plus beta times visual_reward

Then the compact form:

R_total = α * R_code + β * R_visual

Every symbol:

R_totalcombined reward score for the generated code
R_codescore from rule-based code checks: 0 to 100
R_visualscore from comparing rendered chart to target: 0 to 100
αweight on code quality, typically 1.0
βweight on visual match, typically 1.0
A tiny worked example
Generated code has one syntax error and draws almost the right picture.
Code reward: 40 out of 100 (broken syntax is penalized).
Visual reward: 85 out of 100 (the bars are right, axis labels are off by a few pixels).
R_total = 1.0 * 40 + 1.0 * 85 = 125 total points.
Because both rewards matter equally, the model learns to fix both the syntax and the visual details.

The model optimizes both rewards together, so training can progress even when the code-only signal saturates.

What can go wrong

What can go wrong

Visual rewards are noisy. If the rendering engine is slow or unreliable, the visual feedback is garbled, and the model learns nonsense. The paper mitigates this by using a fast, deterministic renderer.
Two conflicting rewards. If code quality and visual match point in opposite directions (make the picture perfect, or make the code clean?), the model has no clear direction. The paper stages the training so code comes first, then visual polish. By weighting them separately (let us call them w_code and w_visual), the paper can raise one weight, train, then raise the other.
Overfitting to the reward function. If the visual reward checks only pixel-level similarity, the model might learn to fake nearby pixels (adversarial perturbations) rather than writing good code. The paper uses multiple reward signals to make this harder.
Reward weighting must be tuned. If you set the code-reward weight or the visual-reward weight badly, the model ignores one reward and optimizes the other. The paper uses ablation studies to find good values, but tuning is still required for new datasets.
What a runnable demo should prove

What a runnable demo should prove

Build a small benchmark of 100 chart-code pairs. Train a model on 80 pairs until supervised learning plateaus (accuracy stops improving). Then apply reinforcement learning with code + visual rewards. Measure accuracy again.

improvement = accuracy_with_RL - accuracy_with_SFT_only

The demo must show a measurable jump in accuracy (at least 3–5 points) after turning on reinforcement learning, proving that visual rewards unlock learning past the supervised ceiling.
