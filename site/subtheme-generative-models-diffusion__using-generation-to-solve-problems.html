Using generation to solve problems

Papers that use generative models to answer difficult questions or fix broken data, including solving math problems, restoring damaged images, and improving data quality.

What this is

Beyond creating pretty outputs for their own sake, generative models can solve hard problems. If you have a model that learned the structure of valid solutions (images, proteins, code, proofs), you can use it as a tool: point it at a broken or incomplete thing, and have it imagine what should go there. Inpainting is the simplest example—'I have a photo with someone's face blurred; generate what that face should look like.' Image restoration means 'this photo is noisy or corrupted; clean it up.' Molecule design means 'generate new molecules that would bind to this protein' (critical for drug discovery). Mathematical reasoning means using generation to search through possible proofs of a theorem.

The challenge is that these aren't straightforward generation tasks. When you inpaint a blurred face, you can't just generate any face—it has to match the context, the lighting, the angle, the person's actual appearance if visible elsewhere. The model has to navigate a constrained space: 'generate something that looks realistic AND fits the context AND solves the problem.' For molecules, the model has to generate structures that actually follow chemistry rules and have the desired properties. For proofs, it has to generate steps that are logically valid.

Researchers handle these constraints in several ways. Conditional generation means feeding extra information (the image context, the target properties) into the model to guide it. Iterative refinement means generating a rough solution, checking if it works, and then refining it. Some papers use a generative model as one part of a larger system—it generates candidates, and a separate tool checks if they're valid or useful. For molecules, researchers combine generative models with chemical constraints and simulators that check if a generated molecule would actually work. The key is treating the generative model as part of a problem-solving pipeline, not a standalone system.

How the work breaks down

When generative models solve real problems, they face five distinct challenges: making sure the output fits strict constraints (images that look real and match context, molecules that follow chemistry rules), tuning the model to match what humans actually want, generating solutions step-by-step rather than all at once, combining generation with other tools to check if answers work, and handling multiple types of damaged inputs with the same method.

Restoring damaged images with guided generation

Images get corrupted or damaged in many ways: blur, noise, missing pieces, or multiple types of damage all at once. The hard part is that when you generate the missing pieces, they have to match the surrounding image perfectly—the lighting, the colors, the angles of the shapes, everything. A diffusion model learned what real images look like, but it needs guidance to focus only on fixing what is broken while keeping the good parts intact.

Image Restoration via Diffusion Models with Dynamic Resolution improves on older methods by adjusting how detailed the generation is based on what type of damage you are fixing, which means faster, clearer results. TPGDiff uses three separate guides—one for the overall structure, one for textures, one for details—so it can fix images whether they are missing pieces, too noisy, too blurry, or a mix of all three. Unifying Heterogeneous Degradations takes this further and does all kinds of repairs (blur, noise, compression, missing pieces) with a single model, so you do not need separate tools for each damage type.

These three papers build on each other by making the repair process more flexible and faster. They all use the same core idea: run the diffusion model in reverse while pointing it at what is broken, then guide it to fill in only the missing or damaged parts.

Generating images that match your preferences

Text-to-image models generate images from descriptions, but they often miss details you care about or produce pictures that don't look as good as you want. The problem is that you need to teach the model what you actually prefer—crisp text, certain colors, a style—without retraining the whole thing from scratch or changing how the model normally works. These papers tackle how to fine-tune or steer generation so the images match your preferences exactly.

FAIL: Flow Matching Adversarial Imitation Learning takes a fast flow-based image generator and fine-tunes it on just 13,000 examples of images you like, which is much smaller than the millions of images it was originally trained on. This lets you adapt a general model to your specific taste quickly. Optimizing Visual Generative Models via Distribution-wise Rewards (evaluating how good a batch of images is as a whole, not scoring each one separately) improves the quality score by training the model to maximize what humans rate as beautiful and well-composed, not just making images that look vaguely like the description. Value Matching does the same reward optimization but uses much less computer memory and is faster, which means you can tune models even on smaller machines because it stores only what is necessary rather than tracking all intermediate gradients. Follow-Your-Preference combines multiple reward models (each trained on different human preferences) to avoid the problem where one reward model has its own biases, so the final image balances different preferences at once.

All four papers agree on the same strategy: start with a working pre-trained generator, then nudge it toward images that score higher on what you care about. They differ in how fast and memory-efficient they are and how well they avoid copying one rater's weird preferences.

Generating valid solutions to hard constraints

In real-world problems, generation is not free—the output has to obey hard rules. In drug discovery, a generated molecule has to actually follow chemistry. In physics simulation, a generated solution has to satisfy the laws of thermodynamics. A raw generative model does not know these rules, so it often creates things that look good but are physically or chemically impossible. You need to combine the model with a verifier or constraint checker that makes sure outputs are valid.

Flow Expansion via Verifier-Constrained Noised State Space Exploration expands what a flow model can generate by trying out new solutions and checking each one with a validator (a separate model that knows if a molecule is chemically real). If a solution is invalid, the method adjusts and tries again. Physics-Constrained Fine-Tuning of Flow-Matching Models teaches the model the physics rules directly during training, so it learns to generate solutions that naturally satisfy equations like heat flow or wave motion. Score Correction enables a pre-trained image diffusion model to generate pictures that satisfy fairness rules or other hard constraints without needing to retrain it; instead, it corrects the model's decisions at generation time by applying a penalty if the output would violate a rule.

These three papers show different ways to add constraints: run generation and validate afterward, bake constraints into training, or fix violations during generation. All three work because they treat the generative model as one part of a larger system that checks answers.

Image editing with fine control over multiple requirements

When you edit an image, you want to change one part but keep everything else the same. If you ask for a new style, you want that new style in the right place while the subject stays recognizable. If you want to customize an object, you want it to be that specific object but also match your text description. The challenge is that these goals can conflict—pushing toward one might break the other—so the system has to balance them.

BideDPO: Conditional Image Generation with Simultaneous Text and Condition Alignment solves this by letting you choose how much you care about each goal in each case. It does not try to find one single best balance; instead, it lets you dial each requirement up or down depending on what you are editing. OmniText is a training-free tool that rewires an existing image model to handle many different editing tasks—fill in missing parts, change colors, add objects, blur faces—without being trained on each one separately. ViPO: Visual Preference Optimization at Scale tunes image models by learning which edits humans prefer, so when the system generates multiple versions, it picks the one that looks best.

All three papers attack the same core issue: image editing is a multi-goal problem where you need to steer the model toward several targets at once. They solve it by either letting humans choose the tradeoffs case-by-case, designing one editing system that works for many tasks, or learning from human preferences which version is cleanest.

Generating and checking solutions for reasoning tasks

When generative models solve logic problems or math problems, they need to produce sequences of steps that are correct, not just sequences that sound correct. A language model can hallucinate—make up facts that sound plausible but are wrong. A model generating code might produce syntax that looks right but crashes. You need a way to generate many candidate solutions and then check each one to see if it actually works.

Generative Universal Verifier as Multimodal Meta-Reasoner acts as a checker that looks at generated solutions and grades them across three dimensions: does this solve the problem, are the steps logically sound, and does the answer match the question. GuidedSampling improves the generation step itself by steering the model away from dead ends during inference, so it produces more valid candidate solutions in the first place—when you generate 50 candidates, more of them work. Test-Time Reinforcement Learning for Flow Matching improves text-to-image accuracy by generating multiple images and then using reinforcement learning to pick the one that best matches the prompt, without retraining the base model.

These three papers split the work: one checks if generated solutions are valid, one steers generation to produce more valid candidates upfront, and one scores final outputs to pick the best. Together they show that generation plus verification is often better than trying to make the generator perfect by itself because checking answers after the fact is much faster than retraining the model to never make a mistake in the first place.
