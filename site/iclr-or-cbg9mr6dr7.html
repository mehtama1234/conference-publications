Reinforcement Finetuning for Transformer Agents

Mixing reward-based and supervised finetuning makes Transformer agents better at adapting to new tasks with very few examples.

Paper explainersAll themesReinforcement Learning

Large multi-task models are trained once on massive amounts of data, then applied to many different tasks (a model that can answer questions, summarize text, or write code). When they face a new task, they need to adapt. Current methods just show the model the right answers (supervised copying). This paper asks: what if we instead let the model practice by trying the new task and getting reward feedback, the way AlphaGo learned chess? The answer is that mixing both approaches works better than either alone, because examples warm up the weights to a good starting point, and rewards then refine them without the blind exploration that would waste time if starting cold.

Zero assumption version

The wrong tool for the job

A multi-task model (a large neural network trained to handle many different tasks at once) needs to adapt when it encounters a new task. Today, people teach it by showing examples: feed it pairs of (situation, correct answer) until it mimics the pattern. This is called supervised finetuning, or SFT.

But this approach has a blind spot. The model learns what the correct answer looks like, but it never learns by trying and failing. It does not discover which moves lead to reward, which paths are dead-ends, or how risk-taking pays off. It is like learning to drive by watching videos instead of getting behind the wheel. A beginner would naively think: just show more examples. The trap is that more examples do not teach exploration or reward-seeking — they only teach imitation.

Meanwhile, in other domains (like game-playing and robotics reasoning models), a different approach has taken off: reinforcement finetuning, or RFT. The model practices the task by trying actions and receiving rewards for good performance. Over many attempts, it learns not just what experts do, but why they do it and when alternatives work. Yet almost no one applies RFT to Transformer agents that handle multiple tasks. The reason is unclear — the paper investigates why this gap exists.

In one sentence. Transformer agents adapt to new tasks via supervised copying, but never learn by reward-based practice like specialized learning models do.

The algorithm as a flow

What it actually does

Start with a pretrained Transformer agent

The model already knows patterns from learning on many tasks before any adaptation starts.

Feed in supervised examples first

Show the model a small number of correct (situation, answer) pairs for the new task.

Warm up the weights via copying

The model adjusts itself to mimic the pattern in those examples — this is fast and stable.

Then practice with rewards

The model tries actions on its own, receives a score for how good each try is, and learns which moves earn high rewards.

Hybrid weights adapt faster

Because the weights started warm (from examples), reward-based practice builds on solid ground instead of wandering aimlessly.

What the paper changes

The single change

The paper changes the finetuning strategy: instead of using only supervised copying or only reward-based learning, it runs them in sequence. First adapt via supervised examples, then continue adapting via reward feedback.

the object it moves  =  finetuning strategy
The hidden quantity

The adaptation velocity

measured quantity  =  how many examples or signals needed to reach full skill

Adaptation velocity is how quickly the agent's performance climbs when it starts learning a new task. If it reaches 80 percent accuracy after 100 examples, that is faster than reaching it after 1000 examples, because the fewer examples needed, the sooner the agent is ready to use.

The paper measures adaptation velocity by running finetuning on many new tasks (in a meta-RL environment: an environment designed to teach the agent to learn other environments) and counting how many examples or reward signals are needed before performance stops improving. Fewer signals needed means the agent learns the new task with less wasted time and fewer failed tries.

Why it works

Why the hybrid approach works

Supervised finetuning (examples alone) is fast but shallow. The model sees a few correct answers and learns their surface pattern. But the pattern is fragile because the model never tests it against reality. It does not know if a slightly different choice works just as well, or if the strategy fails in edge cases. Reward-based finetuning (practice alone) is thorough but slow. The model must try thousands of random actions, receive scores, and slowly figure out which moves lead to points. If it starts from scratch on a new task, it explores blindly for a long time before finding any high-scoring path.

The hybrid method splits the work: supervised finetuning gets the model to a warm, credible starting point (it has seen the right direction), then reward-based finetuning tunes it further by letting it practice and find nuances. This is faster than pure reward learning because the model does not start lost. It is deeper than pure supervised learning because the model still refines its strategy through trial, feedback, and reward-seeking. The velocity advantage comes from starting the race halfway through instead of at the line.

In meta-RL environments (where the agent must learn to learn new tasks quickly), this advantage is dramatic. The agent that started warm via examples adapts to task 5 in 50 examples plus 100 reward signals; the agent that started cold via rewards alone needs 500 signals. The agent that only copied examples never learned to seek rewards at all.

Math after the picture

The hybrid loss function

First in words:

Total training cost is supervised loss plus reward loss, weighted by how far through training we are. Early on, supervised loss dominates. Later, reward loss takes over.

Then the compact form:

loss_total = (1 - alpha_t) * loss_SFT + alpha_t * loss_reward, where alpha_t rises from 0 to 1 over time

Every symbol:

loss_SFTcost of the model's answers differing from the correct examples given to it
loss_rewardcost assigned by the reward function: lower for actions that score high, higher for actions that score low
alpha_ta fraction that grows over time (0 at the start, 1 at the end)
loss_totalthe combined cost the training procedure tries to shrink
A tiny worked example
Step 1 (early, alpha_t = 0.2): loss_total = 0.8 * 5.0 + 0.2 * 20.0 = 4.0 + 4.0 = 8.0. Supervised loss is still the main cost.
Step 100 (mid, alpha_t = 0.5): loss_total = 0.5 * 3.0 + 0.5 * 12.0 = 1.5 + 6.0 = 7.5. The two losses are balanced.
Step 1000 (late, alpha_t = 0.9): loss_total = 0.1 * 1.0 + 0.9 * 8.0 = 0.1 + 7.2 = 7.3. Reward loss dominates now, refining the warm start.

The schedule slides from copying examples to reward-seeking, keeping both active but shifting emphasis, because if rewards took over too fast the model would abandon the good habits learned from examples and start exploring blindly again.

What can go wrong

What can go wrong

Supervised loss drowns out reward learning. If the schedule does not shift toward reward loss fast enough, the model keeps imitating examples and never learns to seek rewards, because the copying signal is strong and the reward signal is faint — the model optimizes the louder objective and ignores the quiet one. The warm start helps the model reach good performance fast, but it can become a cage if the transition is slow, because the model then refuses to try actions that differ from the examples even when rewards would be higher.
The examples are misleading. If the few supervised examples shown to the model are non-representative (e.g., they show a strategy that works in 10 percent of cases), the warm start points the wrong direction. Reward learning then refines the wrong pattern instead of correcting it.
Task shift is too large. If the new task is radically different from the tasks in the examples, the warm weights are not just unhelpful — they actively misguide exploration. The model spends reward signals un-learning the wrong assumptions instead of learning the new task.
Balanced transition from examples to rewards. When the schedule is tuned right, supervised finetuning guides the model to a credible starting point, and reward signals polish it. The warm start accelerates learning without creating a cage.
What a runnable demo should prove

What a runnable demo should prove

Build a simple meta-RL environment: a grid world where an agent must reach a goal, but the goal location changes per task. Pretrain a small Transformer agent on 10 tasks. Then measure how fast it adapts to a new 11th task using three strategies: (1) supervised only (show 5 correct (state, move) pairs), (2) reward only (give the agent a score after each action, no examples), (3) hybrid (give it the 5 examples first, then let it practice for reward). Track how many steps it takes each strategy to reach 80 percent goal success on the new task.

adaptation_steps = number of examples + number of reward signals until goal success rate hits 80 percent

The hybrid approach should reach 80 percent in roughly 55 steps (5 examples plus 50 signals), while pure reward alone needs 300 signals and pure supervised never learns to optimize.
