FIRST PRINCIPLE

An Approach Is A Controlled Change

A paper's method usually changes one of five things: what the model remembers, where the model is allowed to move, which examples count as evidence, what checker decides success, or which internal form makes the object easier to handle. The basic question is always the same: what changes, what must stay the same, and why should the changed object be closer to the target?

This is why superficially different papers can share one argument. A robot action rule, a reasoning trace, a cause graph, a sample-making path, a smaller network, and a benchmark judge all become easier to compare once the method is written as a controlled change with a protected quantity and a known failure boundary.

PATTERNS

Twenty Reusable Method Moves

state

Keep enough notes for the next step

Problem. The model is asked to act from a view that hides facts needed for the next step.

Approach. Add traces, memory, tool output, video evidence, robot subgoals, or hidden working state until the next decision can be made from what is currently saved.

Need: P(next | history, action) ~= P(next | state, action)

Why it works. Once the saved state contains the relevant past, the action rule does not need to guess missing causes from surface clues. Markov enough is the name used later for a saved state that makes the full history almost unnecessary. RAGEN-2, Skill-Pro, HDFlow, VideoKR, EntroKV, ThinkV, and Mamba Markov ICL all use this move in different forms.

measurement

Turn vague success into a real instrument

Problem. A score or benchmark label is too thin to prove the actual skill being claimed.

Approach. Build judges, executable tests, rubrics, process traces, disagreement audits, or artifact-native checks.

Observed score = target signal + bias + noise + gaming pressure

Why it works. A better instrument watches the place where the real failure would appear and separates signal from noise, bias, and gaming pressure. What must stay the same is the skill or property being measured. What may change is the question, judge, or artifact view. Name used later: variance for how much readings spread.

constraint

Search only where valid answers can live

Problem. Penalizing invalid outputs after generation does not stop the search from spending effort outside the valid region.

Approach. Define constraints, snap outputs back to a valid set, decode only legal objects, or optimize with explicit safety and route conditions.

choose x in C to optimize utility, not choose x anywhere and regret violations

Why it works. If the true answer must lie in an allowed region, searching outside it wastes probability and can create false confidence. What must stay the same is the real validity boundary. What may change is the candidate chosen inside it. Name used later: feasible set.

distribution

Change where the evidence comes from

Problem. Training or evaluation examples come from the wrong parts of the task.

Approach. Reweight, curate, stress-sample, bridge curricula, use rare-event proposals, or generate synthetic coverage for missing cases.

risk_target(f) = E_target loss(f,x), but data arrive from source

Why it works. A learner can only reduce error where it receives usable evidence. What must stay the same is the target task. What may change is the mix of examples or possible cases used to teach or test it. Name used later: distribution.

geometry

Measure movement by what it can damage

Problem. A small-looking update can be large in the directions that change loss, safety, or capability.

Approach. Use trust regions, bend-aware data selection, natural gradients, low-rank adapters, optimizer movement rules, or merge constraints.

harm ~= delta^T H delta, not only ||delta||^2

Why it works. The relevant size of a move depends on which directions are fragile. What must stay the same is protected behavior. What may change is the update direction and ruler used to judge it. Names used later: curvature for sharp bending and representation for the coordinate system.

quotient

Group versions that should count as the same object

Problem. The data contain changes that alter the file or view but not the object the task cares about.

Approach. Use same-object rules: quotient spaces, graph relabeling, camera-aware coordinates, molecular symmetries, or canonical routes.

model object on X/G when transformations in G should not change the target

Why it works. Removing fake differences reduces the amount of evidence needed and prevents the model from memorizing accidents. What must stay the same is the target answer. What may change is the wrapper, pose, label order, or camera view. Name used later: quotient.

transport

Move a cloud of possibilities by a controlled path

Problem. The model must generate or adapt from one mix of possibilities to another without losing rare cases or accumulating error.

Approach. Learn flows, bridges, samplers, diffusion paths, reward-shaped sample clouds, or phase curricula.

move p0 to p1 through path p_t while controlling path error

Why it works. A path breaks a hard global change into local changes whose error can be checked. What must stay the same is the important mass in the cloud of possibilities. What may change is the route used to move the cloud. Name used later: transport.

tail

Look for the bad case ordinary sampling will miss

Problem. The important failure is rare under benign sampling but costly under deployment pressure.

Approach. Define the bad event, sample toward it, estimate how often it happens, and control how noisy that estimate is.

P(failure) = E[1{X in bad set}], but bad set is rarely sampled

Why it works. Risk is not the same as average score. What must stay the same is the harmful event being measured. What may change is how hard the test looks near that event. Name used later: tail.

spectrum

Find the directions where signal is visible

Problem. Large models have many possible directions, but only some carry target signal rather than noise or memorized variation.

Approach. Study repeated visible directions, low-rank score structure, which input changes get amplified, kernel alignment, or phase transitions.

target is learnable when signal aligns with stable leading directions

Why it works. A direction helps only if it is stable enough to recover and actually carries the target. What must stay the same is the real signal. What may change is the sample noise around it. Name used later: spectrum.

identification

Say only what the evidence really proves

Problem. Data can support several cause stories, graphs, routes, or response rules, not always one answer.

Approach. State what is being changed, which background facts are held fixed, what instrument or environment separates stories, and which alternatives still remain possible.

claim is identifiable if all models matching observations give the same target

Why it works. The claim is earned only when every rival story still allowed by the evidence gives the same target answer. What must stay the same is that answer. What may change is the hidden story behind the observations. Name used later: identification.

mechanism

Model how other actors respond

Problem. A policy, auction, benchmark, or multi-agent system changes what people or agents have reason to do.

Approach. Write who can act, what they know, what they gain, what rules bind them, and when no one wants to change their move.

chosen behavior is a response to incentives, not a fixed sample

Why it works. Strategic systems fail when the environment adapts. What must stay the same is the rule, information, and payoff structure. What may change is each actor's response. Names used later: mechanism and equilibrium.

hidden control

Change the internal handle that already tracks the variable

Problem. Prompts and labels are indirect controls over what happens inside the model.

Approach. Locate internal directions, routes, norms, modality channels, or brain tokens, then change or decode that handle.

change behavior by moving latent z, while auditing side effects on other variables

Why it works. If a hidden coordinate tracks the target behavior, a direct internal change can be cleaner than more text. What must stay the same is the intended behavior and nearby protected behavior. What may change is the hidden code or internal number pattern. Names used later: latent and activation.

decomposition

Break an artifact into checks that depend on each other

Problem. Papers, software, proofs, medical workflows, and web apps cannot be judged by one local score.

Approach. Represent the artifact as claims, code, citations, tests, files, or clinical steps, plus which pieces support which other pieces.

valid artifact requires local correctness plus satisfied dependencies

Why it works. A support map reveals failures hidden by local pass rates. What must stay the same is the dependency between parts of the artifact. What may change is which local piece is checked. Name used later: dependency graph.

approximation

Make it smaller while preserving the job

Problem. Memory, precision, or latency limits force a cheaper version of the model or context.

Approach. Quantize, prune, cache, route conditionally, distill, or select a compact memory that keeps the facts needed later.

approximation is acceptable when task loss and behavior drift stay bounded

Why it works. Compression is not about fewer bits alone; it is about preserving the function under deployment inputs. What must stay the same is the job users rely on. What may change is the cheaper representation. Name used later: approximation.

frontier

Keep the tradeoff menu visible

Problem. One score hides conflicts among accuracy, cost, safety, privacy, fairness, and latency.

Approach. Estimate non-wasteful tradeoff menus, constrained best choices, subgroup curves, or threshold tradeoffs before choosing an operating point.

x is efficient if no objective improves without another worsening

Why it works. Many failures are hidden tradeoffs, not simple bugs. What must stay visible is what one goal costs another. What may change is the operating point chosen later. Name used later: Pareto frontier.

certificate

Attach the claim to evidence a checker can inspect

Problem. A generated answer can look right without giving enough evidence to check it.

Approach. Require executable tests, proofs, citations, watched work paths, retrieved evidence, formal logs, or reproducible scripts.

claim is useful when verifier(claim, witness) accepts the thing that matters

Why it works. A witness moves trust from surface fluency to checkable structure. What must stay the same is the claim being made. What may change is the evidence artifact attached to it. Name used later: certificate.

curriculum

Choose when evidence enters training

Problem. The same data can help or fail depending on what the model currently knows and how much it can still move.

Approach. Insert bridge data, lengthen tasks gradually, tune decay schedules, or select late data by whether its training push still points somewhere useful.

effect of data depends on time: delta theta_t = optimizer(theta_t, batch_t)

Why it works. Training is like teaching lessons in an order the student can use. An example helps when its push is still aimed at the skill being learned instead of undoing useful behavior. What must stay the same is retained useful behavior. What may change is when and where an example pushes the model. Name used later: gradient alignment for a training push that points in a useful direction.

modality

Give credit to the evidence channel that changed the answer

Problem. Multimodal systems can answer from text habits while appearing to use images, audio, video, or physiology.

Approach. Swap evidence channels, remove routes, force missing-channel calibration, or test channel-specific before-and-after examples.

credit channel m if intervention on m changes answer while controls do not

Why it works. Attribution needs a change test, not decoration. What must stay the same is the target question. What may change is one evidence channel. Name used later: counterfactual.

native structure

Use the object's own working coordinates

Problem. Generic sequence prediction ignores physical, molecular, spatial, temporal, or relational structure.

Approach. Model constraints in coordinate systems, molecular hierarchy, robot action graphs, neural operators, or structured paths.

choose representation where valid local moves preserve object structure

Why it works. The right coordinates make invalid moves harder and useful neighborhoods smoother. What must stay the same is the object's own rule system. What may change is the coordinate format used to model it. Name used later: native structure.

uncertainty

Report uncertainty before ranking systems

Problem. Benchmarks, discoveries, and certificates are often built from too few samples for the claim being made.

Approach. Use confidence intervals, bootstrap checks, finite-test certification, held-out environments, or multiplicity control.

difference is meaningful only when estimation error is smaller than the claimed gap

Why it works. Finite samples can reverse rankings and produce false discoveries. Micro-Benchmarking Reliability, finite-test certification, ATLAS, UFEval, Neural Effect Search, and benchmark audit papers make uncertainty part of the result.

USE

How To Apply This To Each Paper

For every remaining paper card, the next expansion should name the everyday move before adding formal prose. A useful entry says: this paper changes the saved state, movement ruler, evidence mix, checker, hidden code, or allowed region; it preserves this property; it should work because this condition becomes easier; and it fails when this assumption breaks.

That keeps the atlas from becoming a catalog. The reader should see the common problem underneath the papers: how to make AI systems reason, generate, adapt, and verify under limited information, limited compute, strategic pressure, and imperfect measurements.
