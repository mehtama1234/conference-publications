Assumptions and limits

What has to be true for the math to help

This page adds the failure-boundary layer to the atlas. A method helps only after it quietly says what must stay true. It may assume the kept notes are enough, the checker sees the real failure, the removed difference does not matter, the cause story has enough evidence, or the test pressure matches deployment. The failure boundary is the place where that promise stops being true.

FIRST PRINCIPLE

Every Method Buys Something By Assuming Something

The clean way to read a paper is not to ask whether it "solves" reasoning, safety, generation, compression, or science. Ask what it is allowed to ignore. A checker assumes the thing it checks is the thing that matters. A same-object model assumes two different-looking inputs should count as the same. A causal method assumes the evidence rules out rival cause stories. A compression method assumes the dropped details would not change the future answer.

The remaining failure is usually the opposite of that assumption. If the checker watches the wrong artifact, the system learns to pass the wrong test. If the same-object assumption is false, the method erases real signal. If missing variables drive the cause story, a clean-looking effect may be unsupported. If a memory budget drops rare evidence, the smaller model becomes confidently blind.

BOUNDARY 01

Kept State

RAGEN-2, HDFlow, IRNO, Mamba Markov ICL

Assumption. The saved middle state still contains the facts needed for the next step.

Why it works. A system cannot carry every past detail. It works when the kept notes are enough: a reasoning trace can continue, a robot can refine motion, a physics solver can reduce leftover error, and a recurrent model can keep the hidden process it needs. What must stay the same is the next decision the full history would support. What may change is the smaller note used to make that decision. Name used later: sufficient state.

Failure outside. If the saved state drops a rare event, contact fact, sharp physical error, or hidden process variable, later steps cannot recover it without seeing new evidence.

success requires P(next decision | retained state) close to P(next decision | full history)
BOUNDARY 02

Trace Dependence

OpenThoughts, h1, T3, CE-Graph, TRACE Effort

Assumption. The middle steps are doing work the final answer depends on.

Why it works. A long explanation is useful only if changing a step changes the later answer for the right reason. Trace data, gradually longer tasks, partial-path scoring, and graph checks make progress visible before the final answer. What must stay the same is the task-relevant path from middle work to final answer. What may change is one step in that path. Name used later: intervention for deliberately changing part of the trace to see whether it mattered.

Failure outside. If traces are after-the-fact style, teacher habits, or checker-gaming scripts, optimizing them can make the model look more careful while weakening task-dependent reasoning.

trace is evidence only if intervention(trace) changes outcome for task-relevant reasons
BOUNDARY 03

Checker Fit

CyberGym, VERINA, OmniVerifier, WebDevJudge

Assumption. The checker looks at the artifact where correctness or failure actually lives.

Why it works. Running code, checking a proof, rendering a page, or inspecting a visual output turns a claim into something that can fail in public. What must stay the same is the real property being claimed. What may change is the artifact attempt being inspected. Name used later: verifier for that checker.

Failure outside. If the checker is incomplete, brittle, or watches a substitute artifact, agents can pass the checker while missing the real outcome. This is not a small implementation issue; it changes what the system is optimizing.

optimize V(artifact) only when V is a valid measurement of target property
BOUNDARY 04

Benchmark Reading

ATLAS, FRABench, UFEval, Micro-Benchmarking, MADQA

Assumption. The questions, rubrics, judges, and sampling rules really read the skill being claimed.

Why it works. A benchmark score is like an instrument reading. Adaptive questions spend more tests where they remove doubt; split rubrics show which part failed; uncertainty reports stop tiny noisy gaps from becoming false rankings. What must stay the same is the skill being measured, even though the skill cannot be read directly. What may change is the question, rubric, or judge sample. Name used later: latent ability, meaning the hidden skill inferred from visible answers.

Failure outside. A benchmark can be reliable for the wrong skill. It may rank models precisely while measuring shortcut use, judge preference, task-mixture fit, or tolerance for missing evidence.

score = ability signal + sampling noise + judge bias + design artifact
BOUNDARY 05

Rare Bad Cases

Rare Event Analysis, Jailbreak Foundry, VALUEFLOW, FlowGuard

Assumption. The test pressure reaches the uncommon region where real deployment failure lives.

Why it works. Average prompts can miss the cases that matter. Rare-event estimates, attack harnesses, value-pressure probes, and path monitors move measurement toward boundary behavior. What must stay the same is the bad outcome being measured. What may change is how the test puts pressure on the system. Name used later: tail for the far edge of the outcome set.

Failure outside. A new adversary, hidden context, monitor-aware model, or deployment loop can create a different rare-failure region. Safety evidence is only about the pressure that was tested.

risk claim is about event E under tested pressure Q, not all possible pressure
BOUNDARY 06

Allowed Region

Copyright-Bench, Pi-net, Fair OT, CSPO, PACT

Assumption. The written rule describes what is actually allowed: lawful source use, physically possible numbers, fair matching, safe action, or bounded robot correction.

Why it works. Searching inside the allowed region prevents the model from spending effort on outputs that cannot be used. What must stay the same is the real boundary from law, physics, fairness, safety, or robot motion. What may change is the chosen output inside that boundary. Name used later: feasible set for that allowed region.

Failure outside. If the allowed region is too narrow, it blocks valid solutions. If it is too broad or leaves out a hidden rule, training can still find invalid actions that look legal to the written rule.

C must be close to the real allowed set, not only easy to repair against
BOUNDARY 07

Same-Object Rules

Quotient Diffusion, Camera-Aware MLLM, GraphGlue, Protein Generation

Assumption. The difference removed by the model truly does not matter for the task: rotation, translation, relabeling, viewpoint, or file format.

Why it works. If two versions should count as the same object, the model should not waste examples learning them separately. What must stay the same is the task answer. What may change is the coordinate wrapper, label order, viewpoint, or file format. Names used later: symmetry for a target-preserving change and quotienting for grouping same-object versions together.

Failure outside. Some differences matter only in certain tasks. A camera angle may affect action, chirality may affect chemistry, and graph labels may encode roles. Removing the wrong difference erases signal.

x ~ g*x only when target(x) = target(g*x)
BOUNDARY 08

Sample Paths

DMPO, FALCON, Safety-Guided Flow, GWF, Cauchy Bridges

Assumption. The route used to make samples preserves the probability weight, rare kinds, safety rules, or reward emphasis the task cares about.

Why it works. A sample is not only an endpoint. The route can decide whether rare cases are visited, unsafe regions are crossed, or numerical error piles up. What must stay the same is the target cloud of possible outputs and its important rare parts. What may change is the path used to move through that cloud. Names used later: flow, diffusion, bridge, and Wasserstein views for different ways of describing sample-making routes.

Failure outside. If the path overweights easy kinds, accumulates numerical error, crosses unsafe regions, or chases the wrong reward-shaped target, filtering at the end cannot fully repair the sample cloud.

sample path matters when rules and probabilities depend on the route
BOUNDARY 09

Update Movement

Adam Degeneracy, DiReCT, LoRA Theory, Trust-Region LLM RL

Assumption. The method's movement ruler matches the directions where useful behavior is fragile.

Why it works. Training changes a model by moving it. Some directions are cheap, some are stiff, some are protected, and some are small but important. What must stay the same is protected behavior outside the target update. What may change is the model's movement toward the new training target. Names used later: metric for the ruler, curvature for flat-or-steep bending, rank for a smaller movement family, and trust region for an allowed movement boundary.

Failure outside. If unmeasured behavior lives outside the protected movement family or the ruler misses deployment-sensitive behavior, an update can improve the target score while damaging capability elsewhere.

safe update requires useful movement and protected behavior under the same movement ruler
BOUNDARY 10

Smaller State

FlashVID, InfoTok, EntroKV, LiftQuant, FOCUS/RePAIR

Assumption. The removed tokens, bits, layers, channels, or cache entries would not change the future decision or generated path.

Why it works. Compression helps when the smaller system still does the same job. It should protect high-value state and spend error where the task will not notice. What must stay the same is the answer or path the full system would have produced. What may change is which detail gets dropped. Name used later: conditional irrelevance for a dropped detail that adds no useful answer once the kept state is known.

Failure outside. Rare evidence, outlier channels, long-range dependencies, and loop-stability facts can look small until removed. Uniform compression fails because not all approximation error has equal consequence.

discard d only if target is conditionally independent of d given retained state
BOUNDARY 11

Data Value

Sequential Data Values, DiReCT, Midtraining Bridges, Common Corpus, OPUS

Assumption. The data score matches the current model, chosen examples, training moment, target behavior, and governance rules.

Why it works. An example is not valuable by itself. It helps only if it can still teach this model something now. What must stay the same is the model and training moment being judged. What may change is whether this example is inserted into the learning path. Name used later: intervention on the learning path.

Failure outside. Data scores go stale when the target behavior changes, the learning rate closes the learning window, source records are wrong, or examples interact in ways the added-value score did not account for.

value(example) is conditional, not intrinsic
BOUNDARY 12

Cause Evidence

Local Covariate Selection, BRCD, OU Identifiability, Latent Hawkes Discovery

Assumption. The graph, timing, environments, interventions, or event pattern gives enough evidence to rule out rival cause stories.

Why it works. The methods name the smaller cause claim the evidence can support: which background facts to match, which repair point is likely, which drift can be recovered, or which events trigger later events. What must stay the same is the target cause answer across every rival story still allowed by the evidence. What may change is the hidden story behind the observations. Name used later: identification.

Failure outside. Hidden causes, wrong time scale, weak interventions, or graphs that fit the same observations can leave the cause story undecided even when prediction is strong.

identified claim = invariant across alternatives allowed by assumptions
BOUNDARY 13

Modality Credit

MoCA, VGS, VISUALSWAP, Causal Route Gating, MINT

Assumption. The test isolates the route by which image, text, audio, memory, or prior evidence changes the answer.

Why it works. The model can be repaired only when the failing channel is known. The method separates "it did not see the evidence" from "it saw it but reasoned badly" from "it ignored the evidence and used a prior." What must stay the same is the answer target and task difficulty. What may change is one evidence route. Name used later: credit assignment for deciding which route earned the answer.

Failure outside. If channels are too tangled, internal edits create unnatural states, or a changed example changes more than one cause, the route diagnosis can become misleading.

grounding requires causal contribution, not co-occurring modality tokens
BOUNDARY 14

Hidden Interface

PRISM, Mind-Omni, LatentLM, Linear Causal Representation Learning

Assumption. The hidden code exposes variables the next operation can read, change, or test.

Why it works. A good hidden space turns messy evidence into handles: brain signals become object-attribute-relation clues, media becomes editable working state, and cause features become variables that can be recovered. What must stay the same is the concept, control, or cause variable the next operation needs. What may change is the compact internal code that carries it. Name used later: latent code, meaning the hidden working record that keeps the needed concept or control handle available.

Failure outside. A compact embedding can preserve similarity while hiding the variable that matters. If the hidden code is not aligned with action, decoding, or cause testing, it is storage rather than an interface.

z is useful only relative to operation O: decode, control, retrieve, identify, or verify
BOUNDARY 15

Reaction Rules

AdvGame, Accuracy Auctions, Data Market Pricing, Fair OT, OMAC

Assumption. The model includes the actors, information, rewards, and constraints that determine how people or agents respond after deployment.

Why it works. Once others react, the rule itself changes behavior. Attackers adapt, sellers shade information, users value errors differently, agents coordinate, and fairness constraints shape matches. What must stay the same is the action space, information available, and shared limits. What may change is each actor's response. Names used later: mechanism for the rule of the setting and equilibrium for a stable pattern after actors respond.

Failure outside. If actors have missing actions, hidden information, collusion, shifted data, or incentives outside the model, the predicted stable behavior may not match deployment.

mechanism claims are conditional on the action space and information structure
BOUNDARY 16

Scientific Claims

Neural Effect Search, HypoSpace, RefineStat, MedAgentGym, Bitween

Assumption. A generated claim can be turned into something that could visibly fail: an experiment, program, reduction, workflow, or testable effect.

Why it works. Scientific language helps only when it can be checked against evidence that might reject it. A lab claim should face a randomized test, a statistics program should tell a coherent random-data story, an agent workflow should run, and a reduction should preserve the problem it claims to reduce. What must stay the same is the claim being tested. What may change is the proposed artifact or experiment. Names used later: hypothesis for a claim that evidence can weaken, and statistical semantics for the meaning of a random-data story.

Failure outside. If the claim cannot fail, the system can produce plausible science-shaped text without increasing knowledge. The missing object is not intelligence; it is a rejection channel.

hypothesis h is scientific only when some evidence e can lower belief in h
PAPER ROWS

Paper-Specific Multimodal Boundaries

Mind-Omni / PRISM

Assumption. The bridge from brain signal to tokens keeps the concepts that were actually present in the measurement.

Why it works. Raw fMRI or perception data is not the concept itself. The method inserts a middle code that is closer to objects, attributes, and relations than voxels or pixels are. What must stay the same is the concept actually supported by the measurement. What may change is the code that carries it into tokens. Names used later: representation for that middle code and mutual information for how much it reveals about the concept.

Failure outside. Subject variation, timing mismatch, scanner noise, low-level perceptual detail, or hard tokenization can remove doubt the downstream model should have kept.

Evidence needed. Cross-subject stress tests, tests that remove the interface variable, uncertainty calibration by concept class, and checks that the same token still predicts under changed irrelevant visual factors.

useful z requires I(concept; z) high and I(noise; z) controlled

Hibiki-Zero / VibeVoice / TTSDS2

Assumption. The system can keep what was said and how it sounded together while streaming or generating speech.

Why it works. Speech is not text plus decoration. A sentence can have the right words and still fail because the speaker changed, the pause came too late, the tone contradicted the meaning, or the audio became unnatural. What must stay the same is meaning, timing, speaker identity, emphasis, and uncertainty. What may change is the waveform, streaming delay, or generated continuation. Names used later: semantic state for word meaning and acoustic state for sound shape over time.

Failure outside. The transcript can be right while prosody, speaker continuity, turn timing, or naturalness is wrong. Low latency can also force a premature decision before the audio evidence has settled the utterance.

Evidence needed. Audio-native scores, streaming-delay sweeps, speaker and prosody consistency checks, and human plus automatic multi-aspect evaluation rather than transcript accuracy alone.

speech success depends on P(words, prosody, speaker | acoustic history)

MoCA / VGS / VISUALSWAP / Causal Route Gating / MINT

Assumption. A test can change the image, text, memory, or prior route without changing the hidden difficulty of the question.

Why it works. The repair target is different depending on what failed. If the model saw the image but ignored it, the fix is different from a model that never extracted the visual fact. What must stay the same is the question difficulty and non-target evidence. What may change is the image evidence route being tested. Name used later: counterfactual image edit.

Failure outside. An image edit may change more than the intended fact. A hidden route may be spread across the model. A shortcut can disappear in one layer and reappear through another internal code.

Evidence needed. Paired evidence changes, tests that remove or block one route, hidden-state patching, controlled image edits, and tests where the same fact is moved across modalities.

route claim requires do(channel=c) changes answer through that channel alone

FlashVID / InfoTok / VideoFlexTok / OmniFit / LST

Assumption. The kept video or context pieces are enough for the future question or action under the memory and latency budget.

Why it works. Token selection is a lossy note-taking system. It helps only when the notes keep the moments that will later change an answer. What must stay the same is the answer the full evidence would support for the query. What may change is the smaller kept record. Name used later: sufficient statistic, meaning the shortest kept notes that still contain every fact needed for the later question.

Failure outside. A rare decisive event can be discarded because it has low average salience. A later query may ask for a detail that looked irrelevant earlier. Cross-channel redundancy may be overestimated when both channels share the same blind spot.

Evidence needed. Deletion and insertion tests, rare-event benchmarks, query-conditioned retention evaluation, and latency-memory curves tied to task loss rather than token count alone.

compress x to r only if P(y | r, q) approximates P(y | x, q)

SAW-Bench / MomaGraph / EgoTactile / HDFlow / PACT / JoSE / RodriNet

Assumption. The state contains the body and world facts that decide which actions are possible.

Why it works. A robot action is not valid because it sounds like a good plan. Contact, pose, available object actions, subgoals, joint movement, and correction limits define the allowed region. What must stay the same is physical possibility in the current world. What may change is the chosen action or movement surface. Names used later: affordance for an action the environment makes possible and manifold for a smaller allowed movement surface.

Failure outside. The scene graph can be stale, touch readings can be miscalibrated, a hierarchy can choose the wrong subgoal, a learned movement surface can exclude recovery actions, or body math can omit the contact fact that decides success.

Evidence needed. Contact, timing, and occlusion stress tests, new-object action tests, intervention on constraint variables, and recovery trials after partial failure.

valid action a must lie in C(body, object, contact, time)

VideoKR / Visual Attribution Streaming / DLMR / RFCMH / WETR / AGREE

Assumption. Source history stays attached to observations, derived memories, retrieved knowledge, modality agreement, and weak labels.

Why it works. The central object is not memory size; it is evidence lineage. A system can revise beliefs only if it knows whether a statement came from direct observation, a previous inference, retrieval, a weak label, or agreement among correlated channels.

Failure outside. A belief can be mistaken for evidence. Agreement across modalities can come from a shared prior rather than independent support. Reliability weights can amplify easy or frequent labels while underweighting rare but decisive observations.

Evidence needed. Source-label audits, memory-write tests, checks that separate direct observation from stored belief, weak-label calibration, and temporal checks that old beliefs are corrected when new evidence arrives.

belief update needs source(e), time(e), reliability(e), and dependence(e)

NextStep-1 / EditVerse / LatentLM / UALM / FlashWorld / VIST3A / TideGS / RadioGS / Omni-Reward / UniPercept / MetamerGen

Assumption. A shared generation interface keeps the rules each medium needs after decoding, scoring, or checking.

Why it works. Text, images, video, speech, fields, and perceptual matches each have different rules. A shared hidden code helps only if it keeps scene layout, timing, texture, field structure, and perceived sameness where needed. What must stay the same is each medium's native validity rule. What may change is the shared code and generated artifact. Names used later: latent for the shared hidden code and verifier for the checker that reads the artifact.

Failure outside. A shared hidden code can erase texture, timing, or spatial layout. Repeated edits can drift from the target. A reward can ignore the view where artifacts appear. A field basis can miss boundaries even when average reconstruction looks strong.

Evidence needed. Edit-stability tests, artifact-native checkers, world and view consistency checks, basis stress tests, and tests that remove or change reward parts to expose which output-space rules are actually enforced.

shared z is valid only if decoder_m(z) preserves constraints C_m for each medium m
PAPER ROWS

Paper-Specific Physical And Generative Boundaries

Quotient-Space Diffusion / Chamaileon / Complexa

Assumption. Different coordinate files can describe the same physical object, and grouping them does not remove a binding-relevant fact.

Why it works. The model should not treat the same molecule as new just because it was rotated or shifted. What must stay the same is the physical object and its target behavior. What may change is the coordinate wrapper. Name used later: quotient space for grouping same-object copies together.

Failure outside. A same-object rule can be false for the task. Docking orientation, handedness, solvent exposure, local flexibility, distant shape changes, or one-sided measurement conditions can make a removed coordinate physically meaningful.

Evidence needed. Tests that rotate and shift the same molecule, handedness and pocket stress cases, tests that remove or change binding state, experimental multimer validation, and checks that generated variation remains chemically distinct rather than pose-distinct.

valid identity requires target(x) = target(g*x) for every removed transform g

DeCoDe / mCLM / ReaSyn / MORetro*

Assumption. Binding, conformation, building blocks, and synthesis route can be represented as coupled but separable variables.

Why it works. The problem is not just to sample a molecule with a high score. It is to sample an object plus a path by which the object can exist. Decomposing binding position from conformation reduces entanglement, and route-aware generation turns feasibility into state rather than a filter after generation.

Failure outside. The factorization can split variables that chemistry keeps coupled. A route can be valid on paper but unavailable under real reaction conditions, toxic, low-yield, too expensive, or incompatible with the selected binding pose.

Evidence needed. Route reconstruction tests, reaction-condition checks, Pareto-front audits over yield/cost/toxicity, and paired tests where the same scaffold is evaluated with and without route constraints.

design state = molecule + conformation + route + constraints

FIDIA / SRMC / FALCON

Assumption. The sampler reaches the part of the possible-output cloud that the downstream scientific quantity reads: uncommon output kinds, balance of probability, or the best candidate from a finite batch.

Why it works. Generation is being used to estimate something. FIDIA cares about the best sample under a budget, SRMC cares about missed output kinds, and FALCON tracks how probability changes as samples move. What must stay the same is the target cloud and the downstream quantity read from it. What may change is the sample route or batch. Names used later: distribution for the cloud of possible outputs and density for how much probability sits near a point.

Failure outside. Best-candidate training can overfit a partial score. Visual variety can miss the region that contributes most to the answer. A precise probability-near-a-point estimate can still describe the wrong family of sample paths.

Evidence needed. Best-of-N calibration, held-out tests for uncommon output kinds, reports of how many genuinely useful samples were obtained, checks against known systems for probability balance, and remove-one-measure tests showing which downstream quantity improves.

sampler quality depends on F(P), where F may be mean, tail, density, or max_N

Safety-Guided Flow / Cauchy-Driven Diffusion Bridges / GWF

Assumption. The sample-making path can be shaped without destroying the variables the final task needs.

Why it works. A sampler is a path, not only a final draw. Safety-guided flows push away from unsafe regions before unsafe samples appear. Heavy-tailed bridges allow bigger jumps when that matches the process. What must stay the same is the target sample cloud and its task-relevant variables. What may change is how the cloud moves. Names used later: Wasserstein and flow for describing movement of the whole probability cloud.

Failure outside. If the unsafe set is wrong, the model steers away from measured harm while entering unmeasured harm. If big jumps are not real structure, the model explains ordinary error as abrupt events. If transport over-smooths modes, final samples can satisfy local rules while losing global mass.

Evidence needed. Boundary misspecification tests, path diagnostics, rare-event replay, mode-preservation audits, and comparisons against end-only rejection to prove the path change matters.

controlled sampling modifies dP_t/dt, so path evidence matters

TideGS / RadioGS / LoRFS / Modified SINNs / IRNO

Assumption. The chosen building blocks, leftover-error measure, and physical rules match the field being modeled.

Why it works. A continuous field becomes learnable when the coordinates expose smoothness, nearby dependence, sensor layout, repeated signal, or leftover equation error. What must stay the same is the physical rule and boundary condition. What may change is the set of building blocks used to describe the field. Names used later: basis for the building blocks and residual for the leftover mismatch after applying the physical rule.

Failure outside. A basis can hide sharp boundaries, jumps, far-apart coupling, high-frequency leftover error, or sensor artifacts. A correction can appear to settle under the wrong error measure while violating the real boundary condition.

Evidence needed. Boundary-condition sweeps, high-frequency leftover-error plots, basis stress tests, tests that remove or change the sensor rule, and rollouts that show error shrinking under the task-relevant measuring rule.

field claim needs observation = M(basis state) and residual -> 0 in the right norm

FlashWorld / VectorWorld / Stable Video Infinity / dWorldEval / Control Consistency

Assumption. The hidden world state contains the facts changed by action and keeps them through time.

Why it works. A generated world is more than plausible frames. It needs actors, layout, action effects, and accumulated changes. What must stay the same is the world state that actions are supposed to modify. What may change is the next state after an action. Name used later: transition model for the rule that moves from one world state to the next.

Failure outside. A world state can omit intent, contact, occlusion, stale layout, or physical constraints. Video can look locally plausible while drifting away from the action that should have shaped it.

Evidence needed. Action-change tests, long-horizon drift curves, topology and occlusion stress cases, transition consistency checks, and checkers that inspect state variables rather than frame appearance alone.

world model requires s_t + action -> s_{t+1}, not prompt -> plausible frames

MetamerGen / OmniVerifier / VideoKR / Seizure-Semiology-Suite

Assumption. The checker observes the view of the artifact where failure can happen.

Why it works. Physical and scientific outputs can fail in many views: perceived sameness, instruction satisfaction, time order, clinical state, meaning, or domain rules. Multiple checkers help when each one measures a different view of the same hidden object. What must stay the same is the richer object being claimed correct. What may change is which view the checker reads. Formal name sometimes used: projection, meaning a single-view reading of a richer object.

Failure outside. A model can pass an image score while failing clinical meaning, pass a knowledge check while failing temporal evidence, or fool one perception route while breaking another. Verification cannot protect a variable it never measures.

Evidence needed. Tests that remove one artifact-native checker at a time, expert-label audits, cross-view disagreement reports, adversarial score tests, and examples where a single checker passes but the combined check rejects.

certificate is valid only for measured view phi(object)
PAPER ROWS

Paper-Specific Theory And Optimization Boundaries

Adam Degeneracy / Non-Euclidean EoS / Trust-Region LLM RL

Assumption. The movement ruler in the argument is the movement ruler used by the real update.

Why it works. A training rule changes which directions are large, small, cheap, or forbidden. Adaptive scaling, normalized updates, and trust regions help only if the proof describes the actual training loop. What must stay the same is the real update rule. What may change is the ruler used to measure movement. Names used later: metric for the movement ruler and KL or policy distance for measuring how far behavior moved from the checked base behavior.

Failure outside. Stale training-rule memory, clipping, mixed precision, implementation-specific normalization, or reward channels outside the theorem can change the effective movement while leaving the written training target unchanged.

Evidence needed. Update-size traces, behavior-distance curves, training-rule state audits, precision sweeps, and behavior checks on capabilities not named in the reward.

theorem movement ruler must match the realized model update

LoRA Theory / LoRA-Pre / Low-Rank LM Logits / FlexRank

Assumption. The useful task change can be made with a small coordinated set of knobs, and the training data can reveal which knobs matter.

Why it works. Fine-tuning every parameter is like letting a repair person adjust every screw in a machine. That may be powerful, but it is expensive and easy to disturb old behavior. If the new task mainly needs a few coordinated adjustments, a smaller adapter can make the needed change while leaving the rest alone. What must stay the same is protected old behavior. What may change is the limited update handle. Names used later: low rank for a small coordinated update shape, and subspace for the smaller family of allowed movements.

Failure outside. A task can need broader movement, multiple adapters can interfere, adapter size can be selected on the wrong validation slice, or compressed training-rule memory can discard directions that become useful later.

Evidence needed. Adapter-size sweeps, held-out domain checks, adapter composition tests, reports of how much movement each adapter direction carries, and tests comparing full movement to constrained movement.

low-rank helps only if useful delta theta is close to rank-r subspace

Alignment-Sensitive Minimax / Single-Head Attention / Jacobian Spectra / BBP Transitions

Assumption. The useful signal is visible in directions that can be separated from noise with finite evidence.

Why it works. A learner can follow a pattern only after the pattern rises above background confusion. What must stay the same is the real relationship between input and answer. What may change is the noise, sample size, or prompt mix around it. Names used later: spectral directions for repeated visible patterns, and Jacobian spectra for the input changes the function amplifies or suppresses.

Failure outside. The visible pattern can be a dataset artifact, deployment can shift the internal ruler, rare behavior can sit in weak directions, or finite samples can make noise look like signal.

Evidence needed. Stability of the visible directions across datasets, noise-floor estimates, held-out alignment tests, perturbation probes along weak and strong directions, and finite-sample confidence on recovered components.

generalization depends on the target signal rising above the noise floor

Transformer Clustering Circuits / Softmax Turing / Exact GNN Algorithms / Language Generation In The Limit

Assumption. Having the parts to run a procedure, learning that procedure from examples, and actually running it at deployment are separate claims unless evidence connects them.

Why it works. A calculator with enough buttons can do long division, but that does not mean a student learned long division or used it on the test. These results matter because they show which procedures the architecture could carry under stated depth, width, precision, or sequence conditions. What must stay the same is the intended step-by-step rule. What may change is whether finite data, training, or runtime constraints find and preserve that rule. Name used later: expressivity for the "has enough parts" claim.

Failure outside. A model can represent an algorithm without learning it. It can learn a shortcut that passes finite tests. A runtime can break the algorithm through limited context, finite precision, memory layout, or changed execution order.

Evidence needed. Algorithmic probes, length extrapolation, finite-precision tests, training-path diagnostics, and adversarial examples that distinguish the real algorithm from a shortcut.

can represent f does not imply trained system implements f

Finite Test Certification / UFEval / Micro-Benchmarking / Benchmarking At The Edge

Assumption. A limited test sample can support a broader claim only for a named population, distance from deployment, and noise level.

Why it works. A bridge inspection does not prove every bridge is safe; it proves a named bridge was checked under named conditions. A test set works the same way. What must stay fixed is the population, judge setup, model version, and allowed distance to deployment. What may change is the sampled item. Name used later: certificate for that bounded evidence receipt.

Failure outside. Leaderboards fail when the test mix is treated as universal ability. Adaptive benchmark exposure, rubric drift, judge bias, hidden tool differences, or model-version changes can invalidate the finite-test certificate.

Evidence needed. Confidence intervals, item-family audits, judge calibration, model-version locks, bootstrap or hierarchical uncertainty, and explicit distribution-distance assumptions.

score supports claim only with population, uncertainty, and system identity named

Gaussian Certified Unlearning / Exact RL Unlearning / High-Dimensional Gaussian Mechanism / PRISM

Assumption. Privacy, deletion, or influence removal covers every place the data could still remain.

Why it works. Deletion matters only if the system after deletion behaves like one that never saw the record. What must stay the same is what an allowed observer can inspect. What may change is which training history actually happened. Name used later: indistinguishability for two histories that are too similar for that observer to separate. In RL, the covered history must include action rules shaped by past paths, not just labels.

Failure outside. Checkpoints, logs, caches, adapters, retrieval stores, evaluation traces, or downstream models can retain information outside the guarantee. An attacker with side information can test a different distinction than the theorem protects.

unlearning claim covers state S only; data outside S is outside the theorem

Catch-22 / Spherical Watermark / Ellipse Signatures / WaterSIC / Floating-Point Neural Networks / TetraJet

Assumption. The source mark or numerical behavior survives the transformations used in deployment.

Why it works. A source mark helps only if normal edits do not erase it and innocent text is not accused too often. Cheaper arithmetic helps only if changed numbers still compute the same behavior. What must stay the same is the detectable source signal or task function. What may change is paraphrasing, formatting, kernels, or number precision. Name used later: hypothesis testing for deciding between marked and unmarked worlds while controlling false alarms.

Failure outside. Paraphrase, translation, truncation, editing, platform formatting, kernel differences, accumulation order, calibration outliers, or mixed precision can erase the signal or change the computed function.

Paper-Specific Evaluation And Safety Boundaries

ATLAS / FRABench / UFEval / Micro-Benchmarking

Assumption. The questions, rubrics, judges, and sampling rules reveal the hidden capability being claimed.

Why it works. Evaluation is measurement, not a scoreboard by itself. A good question is useful when its answer removes real doubt about the skill, the way a well-placed thermometer reading tells more than another reading from the same spot. What must stay the same is the skill being estimated. What may change is which question gets asked next. Name used later: Fisher information for how much one question can reduce doubt by separating skill levels that are still plausible.

Failure outside. The test can precisely measure the wrong thing: benchmark familiarity, judge preference, task-mixture fit, prompt format, or shortcut use. More items do not fix a wrong measurement model.

Evidence needed. Item-family audits, inter-judge calibration, uncertainty intervals, adversarial item variants, and reporting of what population the score estimates.

observed score = latent ability + item noise + judge bias + design artifact

MADQA / CounselBench / WebDevJudge / Seizure-Semiology-Suite

Assumption. The evaluator observes the domain variable that determines success: evidence access, professional boundary, rendered behavior, or clinical temporal state.

Why it works. High-stakes evaluation needs the right observation channel. Document QA separates oracle access from agent weakness; counseling needs expert risk judgment; web tasks need rendered interaction; seizure video needs laterality, symptom sequence, and timing rather than generic video labels.

Failure outside. A model can answer correctly for the wrong reason, sound safe while missing escalation, pass source checks while failing UI behavior, or name symptoms without preserving clinical order.

Evidence needed. Oracle-gap decomposition, expert adjudication, rendered artifact tests, temporal-label audits, and examples where surface correctness is separated from domain correctness.

valid score must observe phi_domain(output, evidence), not only text(output)

Rare Event Analysis / Tail Risks / CVaR MDPs / UP-OCP / ROCP

Assumption. The tested sample cloud or doubt set reaches the rare region where deployment loss lives.

Why it works. Average accuracy can look fine while rare failures carry most of the harm. The method deliberately looks harder where the bad cases live, then corrects for that harder looking. What must stay the same is the definition of the dangerous region. What may change is how often the test visits that region. Names used later: importance sampling for over-visiting dangerous cases with correction, and CVaR for averaging only the bad slice.

Failure outside. The true rare region may be created by a new user population, repeated interaction, adversarial search, tool side effect, or feedback loop absent from the estimator. A calibrated average can still hide platform-scale harm.

Evidence needed. Event definitions, tail confidence intervals, pressure-distribution reports, sequential coverage checks, stress prompts, and sensitivity to the chosen uncertainty set.

safety claim is about P(loss in E under Q), not mean loss under ordinary P

Jailbreak Foundry / AdvGame / SecFid / SandboxEscapeBench / CSPO

Assumption. The evaluation pressure matches how a real boundary is attacked, traded off, or approached.

Why it works. Safety is clearest when it names the boundary: a forbidden state, an adaptive attacker, a security-fidelity frontier, or a signed distance to constraint violation. These papers move testing from static examples toward reachable failure regions.

Failure outside. A defense can pass known attacks while failing adaptive combinations. A sandbox can be safe in one configuration and exposed in another. A frontier can omit usability, latency, or hidden side effects that decide deployment viability.

Evidence needed. Reproducible attack harnesses, adaptive red-team rounds, boundary-distance traces, sandbox configuration sweeps, and separate reporting of security and task-fidelity losses.

boundary evidence requires reachable unsafe state plus pressure process

CyberGym / CIRBench / DRPBench / WZ-LLM / VERINA / AlgoVeri / Weak-Strong Verification

Assumption. The certificate checks the artifact whose correctness is being claimed.

Why it works. Executable evaluation removes ambiguity because the output must run, exploit, compile, prove, or fail in a place the checker can inspect. What must stay the same is the environment and rule system the claim depends on. What may change is the attempted artifact. Name used later: certificate for evidence a checker can inspect.

Failure outside. A certificate can be too narrow. The environment, compiler flags, concurrency schedule, proof library version, or weak-checker calibration may differ from deployment. Passing one checker can still miss relevant behavior.

Evidence needed. Environment manifests, before-and-after checks, same-meaning tests, schedule exploration, proof-kernel logs, checker calibration curves, and defer-rate reporting.

claim valid only over artifacts and environments inspected by verifier V

Gaussian Certified Unlearning / Exact RL Unlearning / Catch-22 / Spherical Watermark / LM Memorization / PRISM

Assumption. The test for telling two origins apart matches the attacker, output channel, and deployed artifacts people will actually face.

Why it works. Privacy and source-history proof ask opposite questions. For unlearning, the released model should look the same whether the deleted record was used and removed or never used at all. For watermarking, marked and unmarked outputs should look different enough for an authorized detector after ordinary edits. For memorization, the question is how much training material can still be recovered. What must stay the same is what the observer is allowed to inspect. What may change is the hidden training or source history. Name used later: hypothesis test for deciding which origin story the evidence supports, with false alarms and missed detections counted.

Failure outside. Side information, caches, logs, checkpoints, downstream copies, paraphrase, fine-tuning, quantization, or platform transformations can change the test. A guarantee over the model parameters may not cover the full deployed system.

Evidence needed. Artifact inventories, attack-model statements, membership and extraction tests, robustness curves after transformations, false-positive and false-negative rates, and deletion checks across logs and adapters.

privacy/source-history claim = error rates of a specified origin test

VALUEFLOW / SafeDPO / Accuracy Auctions / Fair OT / Data Market Pricing / Omni-Reward

Assumption. The rule includes the people, stakes, groups, sellers, and artifacts the system claims to serve.

Why it works. A shared decision is not just one score. One user may value speed, another safety, another fairness, another legal use, and a seller may have reason to exaggerate data value. What must stay the same is the social promise being made. What may change is the weight, report, price, group match, or artifact inspected. These methods help by replacing one hidden reward with a visible decision rule that says whose values count and how conflicts are handled. Names used later: preference model for guessed user wants, incentive model for how people may game the rule, and aggregation rule for combining many views into one decision.

Failure outside. Values can be unstable, group labels can be incomplete, users can misreport stakes, sellers can collude, and reward models can miss artifact-native evidence. A clean tradeoff curve can still be wrong for the population it serves.

Evidence needed. Reports showing different user groups separately, subgroup calibration, tests where sellers or users benefit from lying, fairness-tradeoff audits, artifact-native reward checks, and sensitivity to the rule that combines many views.

governance score is valid only relative to named actors, values, and aggregation rule

Paper-Specific Data And Systems Boundaries

LR Decay / Midtraining Bridges / PRISM / Procedural Pretraining / OpenThoughts

Assumption. The example arrives while the model can still move in the direction the example is meant to teach.

Why it works. A lesson helps only if it arrives while the student can still change that habit. Late in training, some examples still push toward the wanted behavior; others push against retained skills or arrive after the step size is too small. What must stay the same is the skill the model should keep. What may change is the timing, mix, and source of the new example. Name used later: useful-push alignment for whether an example's training push points in a useful direction.

Failure outside. Specialized data can arrive too late, too early, or in the wrong mixture. Reasoning traces can encode teacher bias. Procedural data can overfit operators that do not transfer. The path can improve a target benchmark while closing off later movement.

Evidence needed. Learning-rate and mixture tests, checkpoint-time insertion tests, forgetting audits, trace-source metadata, and capability retention measured before and after the bridge.

data value at time t = update_size(t) * useful_push_alignment(t)

Sequential Data Values / NASH / OPUS / HOBIT / ATLAS Multilingual Transfer

Assumption. An example's value is judged relative to what has already been chosen, what the current model still needs to learn, how the training rule would move the model, and which transfer target is being served.

Why it works. Data value is conditional. Like adding one more ingredient after tasting the bowl, an example helps only if it adds something not already covered. Sequential valuation asks what new information an example adds after previous choices; OPUS asks how the example would move the current model; hard-negative batching values contrasts only while they remain uncovered; transfer matrices expose which language data helps which target. What must stay the same is the target behavior. What may change is the selected set, model checkpoint, training rule, or language mix.

Failure outside. A value score can go stale after the model changes. Marginal estimators can miss interactions among examples. Transfer benefits can be one-way or disappear under a new tokenizer, training target, or domain mix.

Evidence needed. Re-estimation across checkpoints, held-out language-to-language transfer tables, tests that separate repeated examples from examples that add new coverage, batch-composition sweeps, and direct measurement of the model movement each example causes.

value of an example depends on selected set, current model, and training target

Common Corpus / Data Market Pricing / Bayesian Truthful Valuation / Hubble / LM Memorization Capacity

Assumption. The data's origin, permission, incentive structure, and private-information exposure are part of the scientific object.

Why it works. A dataset is more like a recipe box with receipts than a pile of text. The source, license, duplicates, seller incentives, and memorized private details decide whether the dataset can support the claim. What must stay visible is where examples came from and what rights or risks travel with them. What may change is the mix of examples used for training or valuation. Name used later: distribution for the mix of examples.

Failure outside. Hidden scraping, broken license metadata, seller collusion, duplicated near-copies, downstream caches, or untracked derived data can invalidate the governance claim even when model quality improves.

Evidence needed. Source manifests, license audits, duplicate and near-duplicate checks, seller-honesty stress tests, memorization probes, and downstream artifact inventories.

dataset claim requires sample values plus source, permission, incentives, and leakage state

LIMSSR / Robust Contextual Optimization / Synthetic Data Selection / FAC Synthesis / COMPACT

Assumption. Missing facts, synthetic coverage, and missing skill directions are kept visible instead of silently guessed.

Why it works. If a form has blank fields, pretending one guessed fill-in is true can make the decision overconfident. These methods keep the blankness visible, add examples where coverage is missing, or repair missing skill directions. What must stay the same is honest uncertainty about absent evidence. What may change is which plausible completion, synthetic example, or skill patch is considered. Name used later: covariance for which facts tend to move together.

Failure outside. Masks can become shortcuts. Synthetic samples can match simple statistics while missing real dependencies. Robust sets can be too narrow to contain deployment missingness or too broad to support action.

Evidence needed. Missing-modality stress tests, synthetic-real checks for facts that should move together, internal-coverage reports, robust-set sensitivity, and tests showing that added samples cover previously failing directions.

unknown variable should remain uncertainty set U, not guessed fact x_hat

DHSA / ThinKV / STAR-KV / EntroKV / TileLang / ThunderAgent / ADP

Assumption. The kept memory and serving schedule preserve the information needed by future tokens, tool calls, or retrieved actions.

Why it works. Long context and agents are limited by the cost of carrying notes forward. A smaller cache helps only if it keeps the note that will change a later answer, tool call, or branch choice. What must stay the same is the future decision the full state would support. What may change is which notes are kept, reused, tiled, or speculated. Name used later: entropy for remaining uncertainty about what will matter next.

Failure outside. A cache can drop a rare but decisive token. A speculative action can precompute the wrong branch. A faster kernel implementation can change numerical behavior. A trace schema can omit the state variable that explains failure.

Evidence needed. Long-context retrieval tests, rare-token deletion checks, latency-memory curves, kernel parity tests, speculative rejection rates, and trace completeness audits.

serving state r is valid only if P(next action | r) approximates P(next action | full state)

Assumption. The cheaper model's errors stay small in the directions that determine behavior over time.

Why it works. Compression is not just making the file smaller; it replaces a working procedure with a cheaper one. That helps only if the important decisions still follow the same path, especially when small mistakes can build across many steps. What must stay the same is task behavior under long or fragile use. What may change is bit width, pruned layers, early exits, sparse execution, or diffusion timesteps. Name used later: trajectory for the path of states through time.

Assumption. Adaptation moves through a small handle that can change the target behavior without corrupting retained capabilities.

Why it works. A small adjustment knob is useful when it changes the thing you intend and leaves the rest of the machine alone. These methods limit where adaptation can move: a task vector, support set, object slot, reset rule, or skill token. What must stay the same is protected old behavior. What may change is the target behavior for the current task. Name used later: subspace for the smaller allowed family of movement directions.

Paper-Specific Causality And Scientific Discovery Boundaries

Local Covariate Selection / TRECA / Unpaired Causal IV / Fair Causal Bandits

Assumption. The local effect or action rule has enough matched background facts, environment variation, instrument evidence, or fairness structure to be supported.

Why it works. These papers do not need the whole cause graph before acting. They ask the smaller decision question: which facts must be matched, when should the system refuse to decide, which environment change acts like a fair test, and whether changing a protected condition would wrongly change the action. What must stay the same is the decision's validity under the plausible stories. What may change is the treatment, environment, or sensitive condition being imagined. Name used later: counterfactual policy for an action rule evaluated under a deliberately changed situation.

Failure outside. Hidden causes, weak instruments, violated monotonicity, selection bias, or missing fairness variables can make the local certificate look valid while the intervention claim remains undecided.

Evidence needed. Adjustment-set sensitivity, negative controls, environment holdouts, abstention audits, instrument strength checks, and counterfactual fairness stress tests.

effect claim is valid only if alternatives allowed by assumptions agree on target effect

Structure Learning CI / Distributional Equivalence / DiCoLa / PSAHS / RULE

Assumption. The tests can distinguish the graph story from other graph stories that would produce the same observations.

Why it works. Graph discovery is evidence accounting. If two diagrams predict the same records, the data has not earned the right to choose one. What must stay the same is the set of observed relationships after relevant background facts are held fixed. What may change is the graph story that explains them. Name used later: indistinguishable graph group, meaning the set of graph stories the evidence still cannot separate.

Failure outside. Hidden variables, cycles, small samples, noisy attributes, shifted data, or unmodeled matching errors can produce a precise graph that the evidence did not really identify.

Evidence needed. Calibration for held-fixed relationship tests, same-evidence graph reporting, hidden-variable stress cases, graph perturbation checks, structure/attribute disagreement reports, and sample-size sensitivity.

graph output should be class G_evidence, not one DAG when many DAGs fit

BRCD / CausalGame / MAP / Production Agent Studies

Assumption. Work logs contain enough cause-relevant variables to rank repairs or diagnose workflow failure.

Why it works. Root cause is not the loudest abnormal metric. It is the repair point most likely to change the failure if fixed. What must stay visible is the remaining doubt over possible causes. What may change is which repair is imagined or tried. Name used later: posterior, meaning revised doubt after evidence.

Failure outside. Logs can omit the actual cause, interventions can change the system while measuring it, human handoffs can be invisible, and sampled graphs can exclude the true operational dependency.

Evidence needed. Trace completeness audits, intervention replay, calibration of revised cause beliefs, pre/post incident checks, human-handoff annotations, and ranking quality under known injected failures.

root cause claim is updated belief over interventions, not highest anomaly score

Latent Hawkes Discovery / OU Identifiability / Power-Law Causal Discovery / Linear Recurrent Memory

Assumption. Time order, summary statistics, kept memory, or repeated visible patterns preserve the rule that caused the sequence.

Why it works. Temporal causality needs more than "this came before that." One alarm ringing before another may mean it triggered the second, or both may be driven by an unseen schedule. What must stay the same is the next-step rule that actually moves the system. What may change is the observation window, intervention, noise, or memory summary. Names used later: Hawkes structure for event-triggering, OU moments for summaries of noisy drift, spectral features for repeated time patterns, and recurrent memory for a running state kept across time.

Failure outside. Wrong time scale, changing regimes, hidden subprocesses, aliasing, too few interventions, or memory that drops the real hidden variable can make time dependence look causal.

Evidence needed. Time-scale sweeps, stationarity checks, intervention moment tests, simulations with unseen subprocesses, tests that remove kept memory state, and forecasts under controlled mechanism changes.

temporal mechanism requires stable transition, not only predictive lag

Neural Effect Search / HypoSpace / Bitween / Consequence-Based Utility

Assumption. A generated idea can be placed in a claim space where wrong claims can be rejected or lose value through checked consequences.

Why it works. Scientific generation helps only when proposals become testable objects. Neural features become hypotheses after randomized evidence; HypoSpace measures which possible explanations were covered; reductions must be verified; consequence utility values claims by checked downstream effects.

Failure outside. A hypothesis can be fluent but non-rejectable, duplicated under different names, selected after peeking, or supported only by consequences that are easier to fake than the original claim.

Evidence needed. Pre-registered claim spaces, multiplicity correction, uniqueness metrics, randomized tests, checker-backed reductions, and downstream consequence checks with held-out tasks.

scientific proposal h helps only if some evidence e can reduce belief in h

RefineStat / MedAgentGym / PaperBench / WZ-LLM / VERINA

Assumption. The scientific artifact can be run, checked, or rejected by a workflow that exposes the way it failed.

Why it works. A scientific answer is not only a paragraph. It can be code, a statistical model, a proof, an analysis notebook, or a paper artifact that must survive inspection. What must stay the same is the claim being checked and the rules of the domain. What may change is the attempted program, repair, proof step, or analysis route. RefineStat checks whether a probabilistic program says a meaningful random-data story; MedAgentGym runs biomedical analyses; PaperBench checks assembled research work; WZ-LLM and VERINA use proof or artifact checkers that reject invalid steps. Names used later: statistical semantics for the meaning of the random-data story, and formal proof system for a checker that accepts only valid derivations.

Assumption. Internal edits stay inside states the model can naturally use and isolate a cause route rather than a nearby correlate.

Why it works. A dashboard light is not a cause just because it moves before the engine fails.
