ICML and ICLR differ by mathematical habit

FIRST PRINCIPLE

The Difference Is Where Each Conference Puts The Missing Variable

Both conferences are moving away from isolated prediction. The difference is where they usually place the hidden variable that explains behavior. ICML tends to put it inside the learning or inference mechanism: curvature, constraint distance, hidden-state norm, tail probability, denoising error, spectral span, low-rank update, or verifier signal. ICLR tends to put it around the model: agent world, public data recipe, benchmark environment, multimodal interface, quotient sample space, retrieval setting, or executable task.

That distinction is useful because it explains why similar papers feel different. ICML often asks: what variable can we measure and control so the method becomes reliable? ICLR often asks: what system form must exist before the behavior is meaningful? The shared end state is the same: an AI system whose state, evidence, constraints, and failure boundaries are visible.

ICML habit: expose control variable c. ICLR habit: build observation system E. Both ask whether c or E identifies the target.

DIFFERENCE 01

Reasoning: Control Signal Versus Process Substrate

ICML habit

Make the reasoning control variable measurable

RAGEN-2 makes trace-input dependence the object. The Tell-Tale Norm turns hidden-state magnitude into a recursion or steering signal. h1 makes horizon length a curriculum variable. Thinking in Flow treats the reasoning path as a dynamical system that needs bounded correction.

Why it works mathematically. Reasoning can fail even when the final token sequence is fluent. ICML-style work often tries to find a statistic that predicts whether extra computation, steering, or curriculum movement will improve the latent reasoning state.

use statistic s(trace, hidden state) to allocate compute or detect collapse
ICLR habit

Build the substrate where process evidence exists

OpenThoughts makes reasoning data recipes public. Verifying Chain-of-Thought turns traces into dependency graphs. TRACE Effort tests whether a verifier can be satisfied with shallow work. LongWriter-Zero and ThinkV make long reasoning and cache retention operational.

Why it works mathematically. ICLR-style work often creates the environment where process variables can be observed: trace data, graph checks, long-output settings, cache interventions, and verifier stress tests.

construct process artifact A so V(A, answer) tests the reasoning path
DIFFERENCE 02

Agents: Boundary Control Versus World Construction

ICML habit

Define what the agent must not cross

SandboxEscapeBench makes protected host state a forbidden reachable set. Copyright-Bench makes lawful source choice a feasible workflow set. DRPBench makes concurrent execution schedules the hidden object behind a code answer. ParetoPO makes tool use a cost-quality frontier.

Why it works mathematically. Agent behavior is a path through state. If the allowed region, forbidden region, or cost frontier is explicit, the benchmark can reject action sequences that sound reasonable but violate the real state constraint.

agent succeeds when trajectory stays in C and reaches task state G under cost budget
ICLR habit

Create worlds where agent behavior can be seen

CyberGym executes proof-of-concept exploits. GAIA2 introduces dynamic and asynchronous environments. OpenApps varies UI states. ASTABench and MedAgentGym turn scientific work into reproducible task environments. SwingArena puts code agents inside issue, retrieval, patch, and review loops.

Why it works mathematically. The missing variable is the environment transition. ICLR-style agent work often builds a state machine where action consequences are observable instead of inferred from text.

environment E maps action a_t to observation o_{t+1}, state s_{t+1}, and verifier output
DIFFERENCE 03

Safety: Tail Geometry Versus Pressure Harness

ICML habit

Name the safety functional

Rare Event Analysis and Tail Risks estimate low-probability harmful events. CSPO uses signed distance and constraint sensitivity. VALUEFLOW measures value intensity. Catch-22 names the watermark tradeoff among detectability, stealth, and robustness.

Why it works mathematically. Safety is not the mean score. It is a probability, frontier, distance, or hypothesis test over the part of behavior where loss concentrates.

safety claim = tail probability, boundary distance, or distinguishability frontier
ICLR habit

Generate the pressure that exposes the boundary

Jailbreak-style environments, malicious-finetuning studies, safety-guided generation, counsel benchmarks, deepfake detectors, and CyberGym-like tasks make pressure executable. The focus is not only the metric but the process that discovers the failure mode.

Why it works mathematically. A boundary cannot be estimated if the sample distribution never approaches it. ICLR-style safety work often constructs the adversary, benchmark, or artifact generator that moves probability mass toward risk.

risk estimate depends on pressure distribution Q, not only ordinary sample distribution P
DIFFERENCE 04

Generation: Path Control Versus Native Sample Space

ICML habit

Control the path through probability space

DMPO adapts RL to diffusion language-model trajectories. Error-propagation work models cumulative quantization error in denoising. HDFlow separates global subgoal exploration from local trajectory generation. FALCON and SRMC treat sampling as estimation of a downstream functional.

Why it works mathematically. The final sample is produced by a path. Reward, safety, likelihood, rare-mode coverage, and numerical error are path-dependent, so the transition rule matters.

distribution_t -> controlled update -> distribution_{t+1}; path error changes final law
ICLR habit

Choose the space where samples are meaningful

Quotient-Space Diffusion removes rigid-pose nuisance variables. FlashWorld builds fast inspectable 3D worlds. TRACE uses diffusion attention as instance-boundary evidence. VibeVoice, LatentLM, and structured video work choose interfaces suited to audio, media, and long generation.

Why it works mathematically. A generator cannot be better than its sample space. Removing fake variation and adding native structure makes the target distribution easier to represent and evaluate.

sample x in object space X / nuisance, then lift only when coordinates are needed
DIFFERENCE 05

Data: Update Timing Versus Public Recipe Infrastructure

ICML habit

Treat data as an optimizer-time control input

DiReCT selects late data by curvature-aware movement. Midtraining Bridges times specialized data between pretraining and posttraining. LR-decay and annealing work ask whether valuable examples arrive while the model can still move. Sequential data-value work makes marginal utility conditional on the selected set.

Why it works mathematically. An example has value only relative to model state, optimizer state, already-seen evidence, and downstream validation geometry.

value(example) = expected target movement given theta_t, optimizer_t, and current dataset
ICLR habit

Make data generation and provenance reproducible

Common Corpus makes legal public pretraining data an auditable object. OpenThoughts publishes reasoning recipes. Retrieval and multimodal data papers build supervision from documents, media, and public workflows. Data governance papers make source constraints part of the dataset.

Why it works mathematically. Reproducibility changes the evidence model. A data recipe is not a static set; it is a procedure for sampling, filtering, weighting, and auditing the distribution that trains behavior.

dataset D is produced by recipe R with provenance, filters, mixture weights, and audit trail
DIFFERENCE 06

Systems: Behavioral Approximation Versus Deployable Form

ICML habit

Ask what approximation preserves behavior

LiftQuant makes precision a tunable approximation geometry. TetraJet models low-precision error modes. FOCUS and RePAIR show pruning can create repetition-loop dynamics. Diffusion quantization work tracks how local numerical errors accumulate across denoising.

Why it works mathematically. Compression is a map from one computation to another. It is safe only if the map preserves the function, state transition, or distributional path that the task reads.

compressed system C(f) is valid when task functional T(C(f)) stays close to T(f)
ICLR habit

Build the system form that makes the method usable

Mamba-3 explores state-space sequence modeling. FlashVID and InfoTok allocate video tokens. TileLang exposes kernel structure. Probabilistic Angle Kernels speed similarity search. Low-precision failure work studies when hardware-friendly arithmetic breaks training.

Why it works mathematically. The model's available state is limited by memory, latency, kernels, and precision. ICLR-style systems papers often turn those limits into representation choices or execution models.

usable method = model state + memory layout + precision + latency budget + verifier path
DIFFERENCE 07

Theory: Guarantee Boundary Versus Expressive System Model

ICML habit

State the condition under which the recipe works

Alignment-Sensitive Minimax Rates names target-kernel spectral alignment. Transformer Circuits Can Realize Clustering Algorithms maps architecture to Lloyd-style updates. Language Generation in the Limit separates computability from feasible samples. Jacobian-spectra work connects learned directions to dynamics.

Why it works mathematically. The theory is valuable when it draws the boundary: this class, this spectrum, this sample budget, this algorithmic primitive, this failure outside the assumption.

guarantee holds when signal lies in recoverable directions under finite evidence
ICLR habit

Explain what computation or geometry the system can express

Softmax Transformers Are Turing-Complete studies computational envelope. HATSolver uses hierarchical attention for Groebner bases. Temporal Superposition describes feature packing in recurrent memory. GraphGlue aligns graph domains through shared geometric structure. Taming Momentum studies optimizer-state rank.

Why it works mathematically. The theory names the system's computational form: automaton, algebraic solver, memory packing, graph manifold, low-rank state. That makes architectural behavior intelligible.

architecture matters through the computation or geometry it makes efficient
DIFFERENCE 08

Measurement: Estimator Validity Versus Artifact-Native Observation

ICML habit

Ask whether the score estimates the claimed variable

ATLAS chooses items by Fisher information. Micro-Benchmarking Reliability tests ranking confidence. Rare-event work estimates low-probability failures. Value and watermark papers expose tradeoff frontiers rather than reporting a single number.

Why it works mathematically. The score is an estimator with variance, bias, coverage limits, and hidden alternatives. ICML-style evaluation often makes those error terms explicit.

score S is evidence for target theta only with uncertainty and measurement assumptions
ICLR habit

Observe the artifact where correctness lives

WebDevJudge scores rendered websites. CyberGym runs exploit artifacts. OpenApps varies UI state. MINT patches multimodal hidden states. Visual and scientific benchmarks inspect the native object: image, video, proof, code, world, or workflow.

Why it works mathematically. Measurement fails when it observes the wrong projection. ICLR-style evaluation often strengthens the observation channel by making the artifact or environment first-class.

valid observation O should preserve the variable that determines task loss
SYNTHESIS

How To Read The Conferences Together

ICML Gives Control Knobs

When an ICML paper is strongest, it usually names a variable that can be measured, optimized, bounded, or used for intervention: trace dependence, constraint distance, curvature alignment, spectral span, precision error, tail probability, or distinguishability.

ICLR Gives System Forms

When an ICLR paper is strongest, it usually builds the setting where the behavior becomes real: an agent environment, public recipe, sample space, multimodal interface, executable verifier, retrieval loop, or deployment-shaped benchmark.

The Shared Problem Is Identification Under Action

Both conferences ask whether the system's observed behavior identifies the intended target after the system acts, learns, compresses, samples, or adapts. The methods differ, but the mathematical standard is shared: preserve the right information, remove fake variation, name the constraints, and show what evidence rules out shortcuts.
