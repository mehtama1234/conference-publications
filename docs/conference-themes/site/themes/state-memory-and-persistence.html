State, memory, and persistence

Memory is useful when it preserves state that changes future decisions. It is harmful when it preserves stale, private, false, or over-specific state that should no longer control behavior. The central question is not how to remember more. It is what should persist, what should expire, and what future action the remembered state is allowed to influence.

CORE

Memory is not storage. Memory is future control.

A fact matters as memory only if it changes what the system should do later.

It is tempting to treat memory as a bigger context window or a larger database. That misses the main issue. Memory is a control surface over future behavior. If a model remembers a user's preference, that preference can shape later answers. If an agent remembers a tool result, it may avoid repeating work. If a code assistant remembers a design decision, it may keep future edits consistent. If a medical model remembers medication history, it may interpret a new lab differently. If a robot remembers object identity, it can act coherently after occlusion.

The same mechanism can also hurt. A stale tool result can mislead an agent. A temporary user instruction can become an unwanted permanent preference. A wrong diagnosis can keep biasing care. A private fact can leak into another context. An outdated repository summary can cause a bad edit. A repeated reasoning trace can become a template. A long context can preserve irrelevant detail while burying the one fact that matters. More memory is not automatically better; more uncontrolled influence is often worse.

The right question is therefore: what state should survive across time, at what granularity, for how long, under what identity, and with what authority over future decisions? Memory needs a scope. It needs an expiration condition. It needs provenance. It needs uncertainty. It needs deletion when the world, user, policy, or task says the state should no longer control behavior.

First-principles line
Memory is useful when it preserves state that changes future decisions; memory is harmful when stale, private, false, or over-specific state keeps controlling behavior after it should not.
ANATOMY

The concrete object is persistent state

A memory paper is about the state that survives into a later decision: task state, context evidence, episodic trace, object identity, temporal trajectory, user state, learned skill, replay buffer, governed record, or compressed cache.

What must stay fixed is the authority of that state. A working memory should influence only the current task. A user preference should apply only to the right user and scope. A patient history should preserve timing, source, and uncertainty. A long-context cache should preserve decisive evidence. A governed memory should preserve deletion, consent, and provenance boundaries. If state crosses scopes, memory becomes contamination.

What may change is the representation and lifetime: summary, trace, skill, vector, cache entry, episodic record, adapter, replay example, audit log, or deletion marker. The method works when the persistent state improves future decisions while remaining fresh, scoped, inspectable, and removable. The failure boundary is uncontrolled influence: stale, private, wrong, or over-specific state keeps steering later behavior after the evidence no longer justifies it.

FAILURE MODES

How memory becomes contamination

Memory fails when persistent state keeps influencing future behavior after its scope, freshness, authority, or consent has expired.

Stale state

An old tool result, diagnosis, repository summary, user request, or world state keeps steering decisions after conditions changed.

Scope leak

Temporary task state becomes a durable preference, or one user's private fact influences another user, task, or context.

Provenance loss

The system remembers a claim without source, timestamp, uncertainty, permission, or deletion status.

Compression loss

A summary, vector, cache, or skill preserves the surface but drops the exact evidence needed for a later decision.

Overgeneralized trace

A past workflow is reused where its activation conditions do not hold, turning a useful episode into a brittle habit.

Governance failure

Deletion, consent, privacy scope, source rights, or audit boundaries no longer control what memory can influence.

TOPIC 01

Working memory: keeping the current task alive

An agent needs to know what it is doing now, what it already tried, what failed, and what remains open.

Working memory is the short-lived state of a task. It includes the goal, constraints, selected tools, observations, intermediate results, failed attempts, verification output, and next step. Without it, the system repeats tool calls, forgets constraints, repairs the wrong file, loses track of a proof obligation, or answers without using the latest evidence. Working memory is not meant to become permanent; it is meant to keep a task coherent while it is active.

Agent papers make this visible. CyberGym requires the agent to inspect state, act, patch, and validate across a workflow. Gaia2 turns write actions into verifier-scored steps. ParetoPO prices tool calls, so the agent must remember whether another call is worth it. Process diagnostic papers ask whether reasoning remains tied to the current input rather than falling into a generic trace. In each case, failure is not only a bad final answer. It is loss of task state.

The repair is to store active state in a form that guides the next action: what has been established, what remains uncertain, what tool output is trusted, what action is blocked, what verifier failed, and what success condition remains. The danger is letting temporary working state leak into durable memory. A failed hypothesis during a task should not become a permanent belief about the user, codebase, or patient.

Memory principle
Working memory should persist until the task is resolved, then either become audited evidence, reusable skill, or expire.
TOPIC 02

Context memory: remembering evidence without drowning in it

Long context is valuable only when the needed evidence remains reachable and usable at the decision point.

A long context window can hold more text, but it does not guarantee memory. Important facts can be buried, contradicted, duplicated, or compressed away. Retrieval can surface relevant passages or distract with near matches. KV-cache compression can save compute or delete rare clues. A conversation summary can preserve intent while losing exact strings. A codebase summary can keep architecture while losing the line that breaks the test.

This connects directly to the retrieval and long-context pages. The issue is not only capacity. It is access. Which fact reaches the model when it needs to decide? Does the memory preserve provenance? Can the model distinguish current from stale? Does compression preserve rare but decisive evidence? ThinKV-style work asks which cache entries are sufficient. Context-compression course materials frame rare-clue retention as the important failure mode.

The best context memory is selective and accountable. It keeps exact values when exactness matters, summaries when abstraction is enough, provenance when trust matters, and expiration when evidence ages. A model should not treat a retrieved chunk, a memory summary, a user assertion, and a verified source as equal authority.

Memory principle
Context memory should preserve the evidence that can change the answer, with enough provenance and freshness to decide whether it should still be trusted.
TOPIC 03

Episodic memory: turning past traces into reusable skill

A trace is useful memory only if the system knows when it applies and when it does not.

Agents generate traces: tool calls, observations, edits, proof attempts, navigation paths, and repair sequences. Raw traces are expensive and brittle. A good memory system turns some traces into reusable skills: what condition activates the skill, what steps it performs, what evidence it needs, what success looks like, and when it should stop. That is different from simply storing the transcript.

Skill-Pro is the central example: episodic agent traces become reusable executable skills with activation, execution, and termination conditions. LALP selects teacher traces by transferable local step transitions. These papers treat process memory as an operator library, not as a pile of past text. The lesson generalizes to code repair, web workflows, security tasks, math proofs, and data analysis.

Episodic memory fails when it overgeneralizes. A workflow that worked in one repository may break another. A security exploit path may depend on a specific configuration. A teaching intervention may fit one student and confuse another. Reuse needs a match test. The memory should say why it applies, not only that it worked before.

Memory principle
Reusable memory should store the condition under which a past trace is valid, not only the steps that happened to work once.
TOPIC 04

Identity memory: knowing what is still the same thing

Many long tasks depend on preserving identity across harmless change.

Identity memory says that this object, person, variable, graph node, patient, disease, code symbol, proof term, or action phase is still the same entity across steps. Without it, a video model loses track after occlusion, a medical model treats visits as unrelated, a graph model ignores role continuity, a code model renames the wrong variable, and an agent forgets which file or issue it was working on.

This connects to representation units. The unit must persist if future decisions depend on it. In medicine, Risk Hypergraphs represents disease interaction structure rather than flat labels. Graph-learning papers preserve node and neighborhood structure. VERINA separates code, specification, and proof objects so identity can be checked across formal steps. Object-centric memory papers in continual learning ask how new concepts can be stored without overwriting old ones.

Identity memory should survive harmless surface change but break when evidence says the identity changed. A patient state may evolve. A variable may be shadowed. A graph node may change role under new edges. An object may split, merge, or leave the scene. The memory system needs update rules, not only persistence.

Memory principle
Preserve identity when future decisions depend on the same entity, but allow identity links to be revised when the world, graph, code, patient, or scene actually changes.
TOPIC 05

Temporal state: memory that changes with time

Some memory is not a fact. It is a trajectory.

A lab value means different things depending on baseline and trend. A safety policy matters differently before, during, and after violation. A physical surrogate error can accumulate even if one step looks fine. A text event can shift a future forecast. A student misconception can persist, weaken, or change form. A robot pose and object relation evolve after each action. Temporal state is memory with direction.

IRNO focuses on iterative residual correction because physical surrogate failure accumulates over inference steps. TESS maps temporal text events into forecasting primitives. CSPO evaluates recovery near safety boundaries through time-to-safety, violation frequency, and reward preservation. Hawkes models represent events that trigger future events. h1 makes long-horizon reasoning learnable by composing dependency chains. These papers all treat time as part of the object, not as a timestamp beside it.

Temporal memory fails when old state is treated as current, when trends are collapsed into averages, when recovery path is hidden behind final success, or when a future prediction ignores uncertainty. The memory system should know what state was true, when it was true, how it changed, and what future decision it affects.

Memory principle
Temporal memory should preserve the variables whose change over time affects future prediction, recovery, control, diagnosis, or reasoning.
TOPIC 06

User and patient state: persistent facts with high cost

Personal memory is powerful because it improves future decisions. It is risky for the same reason.

A tutor benefits from remembering a student's misconceptions, mastery, pace, and prior explanations. A medical assistant benefits from remembering symptoms, medications, allergies, visits, labs, baselines, and clinical context. A preference model benefits from remembering values and style. But personal state has high cost. It may be sensitive, outdated, wrong, or context-bound. It may help one task and harm another if reused without permission.

Healthcare and education agent pages make this a domain problem. A clinical assistant cannot treat a patient as a bag of isolated facts; patient state unfolds over time. Education agents need student or group belief states rather than one answer. P-GenRM shows alignment can be user-specific through adaptive personas and scoring rubrics. VALUEFLOW measures value intensity rather than generic preference wins. These are all memory problems because future behavior depends on persistent state about a person.

The right memory is scoped. A user preference about writing style should not become a medical belief. A past symptom should not remain current without date and uncertainty. A student's misconception should be updated after learning. A sensitive fact should have consent, privacy boundary, and deletion path. Persistent personal state needs governance, not only better retrieval.

Memory principle
Personal memory should improve future decisions only within the scope where the remembered fact is current, consented, relevant, and safe to reuse.
TOPIC 07

Learned memory: when the model itself changes

Some memory is not retrieved into context. It is absorbed into parameters, adapters, fast weights, or behavior policies.

Adaptation turns experience into model change. That change can be temporary, local, adapter-based, federated, merged, or permanent. It can help if the new state captures a durable regularity. It can hurt if it overfits a temporary context, erases old behavior, memorizes private data, or changes the reasoning format. Learned memory is powerful because it reduces future effort; it is dangerous because the stored state becomes less visible.

The adaptation page covers this directly. In-Place TTT uses current context as local signal for fast-weight adaptation. SDFT uses demonstration-conditioned in-context behavior as a self-teacher to reduce forgetting. PRISM and midtraining papers show that training stages prepare models for later reward pressure. Continual learning papers ask how to add new concepts without overwriting old ones. Model merging and adapters decide where learned memory lives.

The important distinction is between task-local memory and durable model memory. A temporary support set should not always become a permanent update. A user preference may belong in a profile, not the base model. A domain adaptation may belong in an adapter. A safety correction may need a verifier and audit trail. Learned memory should be inspectable through behavior tests.

Memory principle
Let the model change only when the new state should affect future behavior beyond the current task, and place that change where it can be bounded, audited, or removed.
TOPIC 08

Forgetting: the other half of memory

A good memory system needs deletion, expiration, and overwrite rules, not only retention.

Forgetting is not always failure. Forgetting stale facts prevents bad decisions. Forgetting private facts enforces privacy. Forgetting temporary task state prevents contamination. Forgetting over-specific repair examples prevents overfitting. Forgetting outdated policies prevents wrong compliance behavior. The hard problem is to forget the right thing without damaging what still matters.

Privacy, unlearning, and governance papers sit here. Certified deletion and unlearning work ask how to remove data influence, not only hide records. Copyright-Bench and data governance pages make provenance and source rights part of the memory question. Continual learning papers frame the opposite problem: keep useful old capabilities while learning new ones. Retention-plasticity is the balance between remembering and changing.

Forgetting needs evidence. Did the model stop using the deleted data? Did old general skill remain? Did the system remove a private record from retrieval and summaries? Did an adapter still carry the information? Did audit logs show where the memory lived? A deletion claim is weak unless the memory path is known.

Memory principle
Forgetting is controlled removal of influence: delete what should no longer control behavior while preserving what still has legitimate future use.
TOPIC 09

Compressed memory: keeping the sufficient state

When memory is expensive, the question is what can be discarded without changing future decisions.

Every memory system compresses. Context windows are finite. KV caches are expensive. Retrieval indices choose chunks. Summaries omit detail. Model parameters distribute facts. Edge devices limit storage and compute. Compression is useful if it removes harmless detail and harmful if it deletes rare but decisive evidence.

ThinKV, LiftQuant, Cross-Domain OT Compression, and Hallucination Rate-Distortion all connect here. ThinKV asks which cache information can be discarded without losing rare clues. Cross-Domain OT Compression ties compression to target-domain decision value. Hallucination Rate-Distortion explains factual hallucination as lossy storage of sparse membership facts. LiftQuant and related systems papers show that numerical compression can preserve broad metrics while changing behavior.

The sufficient memory depends on use case. A legal system may need exact source and clause. A medical system may need timestamped thresholds. A code system may need exact identifier and test result. A robot may need current pose and object relation. A tutor may need misconception state, not every prior word. Compression should be evaluated by future action cost, not by average reconstruction quality alone.

Memory principle
Compressed memory is good when it preserves the smallest state that can still support the future decision the system must make.
TOPIC 10

Memory tests: proving persistence is correct

A memory claim needs tests for recall, freshness, identity, deletion, transfer, and harm.

It is not enough to say a system has memory. We need to test what the memory does. Can it recall the exact fact when exactness matters? Can it ignore a stale fact after correction? Can it preserve object or patient identity over time? Can it reuse a skill only when its activation condition matches? Can it forget private or deleted information? Can it avoid letting irrelevant history bias a new task? Can it show provenance for a remembered claim?

The evidence page gives the proof logic. Memory tests should be external to the memory claim. For agents, test repeated tool use and recovery. For code, test whether earlier design decisions remain consistent without overriding new requirements. For medicine, test trajectories and dated facts. For education, test whether student state updates after learning. For robotics, test occlusion and action continuity. For unlearning, test influence removal. For compression, test rare-clue retention.

The deeper pattern is that memory should be evaluated by future behavior. A memory system is not good because it stores many facts. It is good when the right facts control the right later decisions, and the wrong facts do not.

Closing line
A memory system is correct when it preserves the state needed for future action, updates that state when the world changes, and removes its influence when it no longer belongs.

CONCEPT BRIDGES

Where to read the larger pattern

Long context is memory design

Memory is the state future decisions can still use. Storage becomes memory only when it controls the right later action and expires when it no longer belongs.

Privacy and unlearning are recoverability claims

Forgetting is a claim about what information can still be recovered. A memory system is not governed until deletion changes future behavior, not only stored records.

Human-facing AI estimates hidden state

Human-facing systems store beliefs about people and must update them carefully. The risk is not memory itself, but stale or private state steering future decisions.
