Problem

Scientific ML cannot ignore numerical implementation. A theorem over real numbers may fail in floating point, a PDE solver may violate time causality, and a model too expensive for hardware may never be used.

Approaches

The papers redesign PINNs, neural operators, Hamiltonian maps, reversible solvers, graph operators, number tokens, quantization, neuromorphic inference, and mechanistic simulators around real computational constraints.

Connecting read

This theme sits where algorithms meet machines: physics supplies structure, hardware supplies limits, and numerical design decides whether learning respects both.

FIRST PRINCIPLES

The core problem

Scientific computing is not just prediction. It is the controlled approximation of a process. The approximation must preserve causality, invariants, arithmetic meaning, stability, and hardware feasibility. If those constraints are lost, the model can be accurate on a benchmark while being unusable as a scientific tool.

The papers in this theme share a simple engineering stance: expose the real constraint and build around it. Time-dependent equations need causal temporal solvers. Molecular dynamics needs phase-space structure. Low-latency hardware needs event-driven propagation. Large models need low-bit conversion. Neural theory has to account for floating-point execution rather than ideal arithmetic.

TOPIC 01

An approximation is a scientific promise

A learned solver is useful only if the shortcut preserves the thing the original scientific problem was trying to protect.

Every paper here changes the computational route. Frozen-PINN changes how a PDE solution is represented. IRNO changes one-shot neural-operator inference into repeated correction. Rex changes ordinary integration into a reversible exponential form. Hamiltonian Flow Maps changes trajectory learning into phase-space map learning. CAT-Q changes high-precision weights into ternary weights. These changes are allowed only because some deeper object is supposed to stay fixed: the PDE, the residual target, reversibility, Hamiltonian structure, numerical behavior, or deployed model capability.

That is the simplest way to read scientific ML papers. Ask what is being approximated, then ask what the approximation is not allowed to destroy. If the answer is unclear, the method may be an engineering trick rather than a scientific computing contribution.

TOPIC 02

Physics gives constraints before it gives data

Physical structure is not just another feature. It defines which outputs are legal.

For time-dependent equations, the future should depend on the current state in the way the dynamics specify, not on information leaked from later time points. For molecular dynamics, the phase-space variables are not arbitrary coordinates; they carry conserved or structured relationships that make a trajectory physical. For neurostimulation, the model is not simply predicting a recording; it is inferring parameters inside a biophysical simulator that has mechanistic meaning.

This is why the evidence has to test more than average error. A method can fit observed states while violating causality, drifting away from valid dynamics, or losing the mechanism needed for intervention. Scientific computing cares about the path by which the answer is produced because that path encodes the scientific assumptions.

TOPIC 03

The machine changes the mathematics

A model implemented with finite numbers is not the same object as a theorem over exact real arithmetic.

Floating-Point Neural Networks makes this point directly. Expressivity claims can change when operations are rounded, clipped, or restricted to representable values. BitTokens makes the same point from the language-model side: if the tokenization breaks the structure of machine numbers, the model has to reconstruct arithmetic through an awkward interface. CAT-Q makes it operational: once weights are ternary, the model is not just compressed; it is executing a different numerical object.

The first-principles lesson is that representation and arithmetic are part of the algorithm. If the number system changes, the computation changes. Good evidence has to show that the behavior survives the number system actually used at deployment time.

TOPIC 04

Hardware is a constraint on what intelligence can be used

A method that is too slow, too dense, or too memory-hungry may be scientifically elegant but practically unavailable.

ETTFS shows this in neuromorphic inference. If the hardware works through spike timing, then ordinary dense layer-by-layer evaluation does not respect the machine. The useful computation is causal propagation from incoming events to early decisions. Sparse timing is not a decoration; it is the reason the hardware can offer low latency.

The same idea appears in large-model conversion and numerical solvers. A quantized model that can be produced within practical GPU budgets changes what can be deployed. A reversible solver can make memory or backward reconstruction practical. A graph operator with fewer parameters can make physical-domain inference cheaper. Hardware constraints do not merely reduce cost after the method is designed. They select which methods can exist at scale.

OBJECT

The scientific object is the approximation

The concrete object is an approximation that must run: a PDE solution path, a neural operator refinement loop, a reversible integrator, a Hamiltonian phase-space map, a biophysical simulator, a graph operator, a number representation, a quantized model, or an event-driven inference schedule.

What must stay fixed is the scientific meaning of the problem. A time-dependent differential equation must keep temporal causality. A molecular dynamics method must preserve the phase-space structure that makes trajectories physical. A biophysical model must stay tied to the mechanism being inferred, not only fit recordings. A graph solver must preserve the relations that carry long-range physical information. A numerical-representation paper must preserve the arithmetic operation being tested. A hardware paper must preserve the latency, precision, or event structure that motivated the design.

What may change is the computational route: frozen spatial features, residual refinement, reversible algebraic form, learned flow map, differentiable simulator, spectral graph mixing, bit-level tokenization, ternary conversion, or spike-time propagation. These methods work only if the new route changes cost, stability, or generalization while leaving the scientific object recognizable.

EVIDENCE

What would prove the approximation is faithful

The proof depends on the object: solver evidence for solvers, physical evidence for physics, arithmetic evidence for number systems, and timing evidence for hardware.

Long rollout stability

PDE and dynamical-system methods should remain stable beyond short one-step prediction, where causal and invariant errors start compounding.

Structure preservation

Hamiltonian, reversible, graph, and biophysical methods should preserve the state variables or mechanisms that make the domain meaningful.

Finite-precision audit

Claims about expressivity, arithmetic, or compression should be checked under the floating-point, token, or low-bit format actually used.

Hardware-real timing

Neuromorphic or GPU-oriented methods should show latency, memory, or throughput gains under the intended computation schedule.

Generalization under changed conditions

Scientific approximations should survive new boundary conditions, stimulation patterns, sparsity structures, graph regimes, or molecule states.

Cost with meaning intact

Cheaper computation counts only when the scientific object remains recognizable: same equation, same mechanism, same arithmetic, or same deployed behavior.

FAILURE MODES

Where scientific computing claims break

A scientific ML method fails when the learned shortcut no longer preserves the thing that made the scientific object meaningful.

Accurate but non-causal

A solver can match short trajectories while violating temporal direction, boundary conditions, or the coupling that controls long rollouts.

Iterative but non-contracting

Residual refinement is only useful if each step reduces the right error. Extra iterations can also amplify artifacts or chase distribution-specific noise.

Physical-looking drift

A molecular or Hamiltonian method can produce plausible paths while slowly leaving the valid phase-space structure that makes the dynamics physical.

Mechanism replaced by fit

A biophysical model can predict recordings while losing interpretable parameters, so it no longer explains what stimulation or physiology changed.

Arithmetic theorem mismatch

A claim proven over real numbers can fail under floating-point, tokenized numbers, or low-bit weights because the implemented operation is a different object.

Hardware-only theater

A method can look fast in simulation but lose the latency, sparsity, precision, or energy property once it runs on the intended hardware schedule.

SYNTHESIS

Four ways computation is made physical

1. Scientific solvers must preserve time, causality, and invariants

physical solvers

This cluster treats learned solvers as numerical methods. The hard part is not only fitting observed solutions, but preserving the structure that makes simulation reliable when steps get longer or conditions change.

ICLR 2026Frozen-PINN
Frozen-PINN uses frozen random spatial features and solves time coefficients with ODE machinery instead of optimizing a full PINN loss by gradient descent. Its second evidence row emphasizes separation of space and time, temporal causality, and decoupled PDE, boundary, and initial-condition losses. Together, the paper reframes PINNs as structured causal solvers rather than monolithic neural regressors.
ICML 2026IRNO
IRNO recasts neural-operator inference as iterative residual refinement with contraction-style convergence and fixed-point regularization. It treats inference itself as a solver. The model repeatedly corrects residual error, so the operator is judged by whether its refinement dynamics converge, not only by one forward pass accuracy.
ICML 2026Solving Time-Dependent Differential Equations with Physical Dynamical Systems
Solving Time-Dependent Differential Equations with Physical Dynamical Systems uses dynamical-system machines with state-aware nonlinearity and hierarchical temporal integration. The paper asks whether hardware-like dynamical processes can solve TDDEs faster by matching the temporal structure of the equation. Computation is organized as physical evolution.
ICML 2026Rex
Rex converts explicit ODE and SDE Runge-Kutta schemes into algebraically reversible exponential solvers for exact inversion. Reversibility matters when the solver must move backward without accumulating reconstruction error. The method makes a numerical property, exact inversion, part of the solver design rather than an afterthought.
ICML 2026Hamiltonian Flow Maps
Hamiltonian Flow Maps trains on independent machine-learned force-field phase-space samples without future states and supports larger integration timesteps. Molecular dynamics is governed by phase-space structure, not arbitrary trajectories. The method learns maps that respect that structure enough to step farther while staying physically meaningful.

2. Mechanistic models and graph operators carry domain structure

structured scientific models

Scientific domains often already contain strong structure: neural biophysics, meshes, graphs, and long-range relations. These papers use learning to parameterize that structure, not erase it.

ICML 2026Learning Biophysical Models for Neurostimulation
Learning Biophysical Models for Neurostimulation uses differentiable Hodgkin-Huxley simulation and simulation-based inference to infer biophysical parameters from scalable extracellular recordings. The model remains tied to retinal stimulation physics. That gives predictions a mechanistic route to generalize to unseen stimulation patterns.
ICML 2026S3GNN
S3GNN reports gains across long-range graph benchmarks, knowledge-graph question answering, and mesh-based fluid dynamics with fewer parameters. Its role here is showing why scientific graphs need both local message passing and global spectral mixing. Physical meshes can require long-range coordination that ordinary local GNNs compress poorly.

3. Machine arithmetic changes what models can represent

numbers and precision

The third cluster asks what happens when ideal mathematical models meet actual number systems. Tokens, floating-point operations, and low-bit weights are not implementation details; they define the computations the model can perform.

ICML 2026Floating-Point Neural Networks
Floating-Point Neural Networks shows that exact-arithmetic expressivity results do not directly transfer to implemented floating-point ReLU networks. That is a foundational warning. A network theorem over real numbers may overstate what the deployed model can compute under finite precision, rounding, and representable values.
ICML 2026BitTokens
BitTokens shows small language models can learn arithmetic nearly perfectly when numeric tokens preserve computational structure. Instead of scattering a number across subword pieces, it represents machine numbers directly. Arithmetic improves when the token interface matches the number system the model must reason over.
ICML 2026CAT-Q
CAT-Q reports ternary conversion for very large language models within practical GPU budgets. The importance is deployment pressure: if low-bit conversion can be done quickly and cheaply enough, compression becomes an operational tool rather than a research-only artifact. The question is how far precision can fall before useful behavior breaks.

4. Hardware-aware inference changes the computation schedule

event-driven hardware

The final cluster focuses on matching inference to hardware timing. Low-latency systems do not always want layer-by-layer dense evaluation; they may want sparse causal propagation driven by events.

ICML 2026ETTFS
ETTFS targets causal step-by-step time-to-first-spike propagation for low-latency neuromorphic hardware rather than ordinary layer-by-layer inference. The paper treats time as the computation carrier. If spikes arrive sparsely and causally, the hardware should propagate useful events immediately instead of waiting for dense synchronous layers.
FIELD READ

What this theme says about ICML and ICLR

The scientific-computing signal is that implementation is part of the theory. Causality, finite precision, reversibility, low-bit weights, event timing, and physical invariants all change what the model means.

That matters for the larger conference synthesis because many ML claims only become real when they survive the machine. This theme is the reminder that the benchmark object is not just the model; it is the model plus solver, arithmetic, hardware, and the scientific structure it is supposed to preserve.
