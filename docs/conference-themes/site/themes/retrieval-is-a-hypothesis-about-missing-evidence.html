CORE

The query is a theory of what is absent

A retriever should return evidence that the model could not safely infer from its current state.

If retrieval returns fluent neighbors, familiar language, or preferred source languages instead of answer-changing evidence, it can make a system more confident and less grounded. The first-principles object is the evidence gap: what fact, procedure step, modality, comparison, or source is missing?

Q-RAG learns sequential evidence selection for huge contexts. Revela trains retrieval without query-document labels by asking whether documents improve language prediction. TG-RAG retrieves procedure-step guidance. BlitzRank ranks candidates under comparison budgets. Linguistic Nepotism shows citation choice can prefer language over relevance. MC-Search makes multimodal search chains inspectable step by step.

Core rule
Retrieval is useful only when the returned object changes the answer for a reason that can be checked.
FIRST PRINCIPLE

Retrieval begins with an absence

A system should retrieve only when its current state is missing something needed for the task.

The mistake is to treat retrieval as a way to make answers look documented. The first question is not “what can I cite?” The first question is “what can I not know from the current state?” The missing object may be a fact, a procedure step, a counterexample, a current document, an image region, a precedent, or a verification trace.

Once the absence is named, retrieval becomes a hypothesis: this outside source may contain the missing evidence. That hypothesis can be wrong. The source may be related but not decisive. It may be popular but stale. It may be in a favored language. It may be retrieved because of surface overlap rather than use. A serious retrieval system must therefore test not only whether it found something nearby, but whether the answer changed because the missing evidence was filled.

First-principles test
Remove the retrieved source, replace it with a near miss, and check whether the answer changes exactly where the evidence should matter.

PAPER MAP

The papers separate access from evidence

Sequential search

Q-RAG treats retrieval as a multi-step policy, not a single nearest-neighbor lookup.

Pair-free learning

Revela trains retrievers from language-model prediction when labeled query-document pairs are missing.

Procedure state

TG-RAG retrieves according to the current step in an expert procedure graph.

Comparison budget

Citation bias

Linguistic Nepotism controls relevance to reveal language preference in RAG citations.

Multimodal chains

MC-Search stores subquestions, retrieved evidence, intermediate answers, and verification.

METHOD

Why nearest neighbor is not enough

Similarity is only a guess about evidence.

A nearest document may share words with the question while missing the fact that decides the answer. A useful document may use different words because it belongs to a procedure graph, an image chain, another language, or a later step in reasoning. This is why the retrieval papers keep moving away from one-shot surface matching: they add sequential policies, training signals, tournament ranking, bias controls, and stepwise verification.

The method lesson is to make retrieval conditional on need. Ask what is missing, choose a source that could fill it, and then test whether it did. If the answer would be the same without the source, the retrieval was decorative. If the source changes the answer but cannot be verified, it may be contamination. If ranking cost blocks the right source, retrieval has become an efficiency problem.

Good retrieval is therefore selective twice: selective about when to search, and selective about when to let the found source change the answer.

FAILURE MAP

How retrieval misleads

Topical neighbor

The source is about the same subject but does not contain the decisive evidence.

Citation theater

The final answer cites sources that were not used to form the answer.

Language bias

Preferred-language sources win even when equally relevant sources in another language are better.

Greedy path

An early retrieval choice blocks a later source that would have answered the real gap.

Procedure mismatch

The system retrieves general guidance instead of the next step needed now.

Unverified chain

Intermediate retrieved facts are never checked before they become the final answer.

CONNECTION

Why this idea cuts across the atlas

Retrieval is the external-evidence form of memory.

Long-context design asks what past information should remain inside the model state. Retrieval asks when the state is not enough and outside evidence must be brought back. Grounding then asks whether that evidence controlled the answer. Evaluation asks whether the retrieval step itself can be judged as part of the task.

This also explains why retrieval and generation cannot be evaluated separately. A perfect retriever is not useful if the generator ignores the evidence. A strong generator is not trustworthy if the retriever feeds it biased or irrelevant sources. The unit of analysis is the whole path from missing evidence to selected source to changed answer.

The deeper point is that retrieval is not a search feature. It is a decision to admit that the current state is incomplete and to spend work on a specific missing object.
