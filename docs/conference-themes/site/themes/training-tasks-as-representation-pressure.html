A representation is shaped by the task that trains it. Masking, contrast, reconstruction, prediction, teacher targets, bottlenecks, rewards, and behavior tests do not merely reduce loss. They decide what information survives, what can be compressed away, and what later systems can use.

ANATOMY

The concrete object is the training pressure

A training-task paper is about the pressure applied to representation: masking, reconstruction, contrast, prediction, distillation, compression, reward, verifier feedback, or process supervision.

What must stay fixed is the downstream distinction the representation must preserve. A code task must preserve executable semantics. A medical task must preserve thresholds and patient state. A video task must preserve time and object identity. A reasoning task must preserve useful intermediate state. A reward task must preserve the behavior users actually care about rather than a proxy that is easy to optimize.

What may change is the task format, hidden part, negative set, teacher signal, bottleneck, reward, verifier, or credit-assignment rule. The method works when the changed pressure makes the right information survive compression and transfer. The failure boundary is shortcut learning: the model satisfies the loss while ignoring the unit, state, mechanism, or consequence the deployment task needed.

FAILURE MODES

How a training task preserves the wrong thing

A task fails when the model can satisfy the loss without learning the unit, distinction, state, mechanism, or consequence the downstream system needs.

Shortcut cue

The loss can be solved from style, frequency, local texture, answer format, or dataset artifact instead of the intended structure.

Unit erasure

Training compresses away exact characters, symbols, objects, frames, measurements, or code semantics that later decisions require.

Bad negative

Contrastive pressure separates things that should remain close, or treats contradictory/noisy examples as useful boundaries.

Teacher bias

Distillation preserves the teacher's blind spots, confidence errors, style preferences, or missing domain knowledge.

Reward proxy

Verifier or reward pressure makes the model optimize a checkable surface while ignoring the human-relevant behavior.

Transfer illusion

The representation works under the training task but fails when modality, domain, interface, or deployment consequence changes.

TOPIC 01

Training as pressure

A training task is a pressure field. It makes some information useful, makes other information cheap to ignore, and teaches the model what kind of mistake is allowed.

The same data can produce different representations under different tasks. A sentence trained with next-token prediction learns continuations and local distributional cues. The same sentence trained with contrastive retrieval learns which texts should be close or far. The same sentence trained with instruction following learns what kind of response satisfies a user. The same sentence trained with a verifier learns what can be checked. The raw characters did not change; the pressure did.

This is the training-side version of unit choice. A unit is not kept because it exists in the input. It is kept because the loss makes it matter. If one character changes a drug name and the training task never punishes that mistake, the exact character may not survive. If a video task only rewards caption style, the model may not preserve the action phase. If a vision task rewards patch similarity but never object persistence, object identity may be weak. If an agent task rewards final answers but not tool quality, the model may learn to hide bad intermediate actions.

The first question is therefore not "what objective is popular?" It is "what difference must the later system use?" A code model needs exact syntax and executable semantics. A medical model needs thresholds, trends, patient state, and uncertainty. A vision model may need objects, relations, or pixel boundaries depending on the task. A reasoning model needs useful intermediate state, not only a fluent explanation. A representation is good when the training task has made the answer-changing differences hard to lose.

Survival

What information must remain available after compression, abstraction, and transfer?

Cheap variation

What can safely change without changing the answer: lighting, wording, pose, file layout, or harmless style?

Penalty

Which mistake does the training task actually punish, and which mistake can pass unnoticed?

Credit

Does the task reward the exact useful step, or only the final answer after many hidden choices?

Shortcut

What easier cue can satisfy the loss without learning the intended structure?

Transfer

Will the learned unit still be useful when the domain, modality, interface, or use case changes?

First-principles line
Training is pressure before evaluation is evidence: the task decides what the model must keep, what it may ignore, and what structure becomes easy to use later.
TOPIC 02

Masking and reconstruction

Masking asks the model to infer what is missing. Reconstruction asks it to keep enough detail to rebuild. Both teach by creating absence.

The useful pressure in masking is not that something was hidden. It is that the hidden part can only be recovered if the model preserves the right context. If a masked word can be guessed from local grammar, the task may teach syntax. If it requires a long-range fact, it may teach document memory. If a masked image patch requires neighboring texture, the model may learn local appearance. If it requires object identity, pose, or scene layout, the model must represent more than pixels. The same masking format can be shallow or deep depending on what evidence is needed to fill the blank.

Reconstruction has the opposite danger. It can force too much detail to survive. A model that must reconstruct every pixel or signal sample may spend capacity on noise that does not matter for the downstream decision. But reconstruction is powerful when the details are meaningful: fMRI-to-image reconstruction, sleep-signal captioning, video restoration, code repair, table structure, or geometry reconstruction. The question is whether the rebuilt detail is evidence or decoration.

1. Masking teaches context only when context is necessary

masking

Masked diffusion language models and learned unmasking policies make generation order itself trainable. MDM Reasoning shows that masked diffusion can support reasoning-like computation rather than simple fill-in-the-blank behavior. Learning Unmasking Policies treats the choice of which token to reveal next as a policy, which matters because filling one blank changes the evidence available for the rest. Mind-Omni uses task-specific masking over brain, vision, and language tasks, making masking a bridge across modalities rather than a text-only trick.

The conceptual lesson is that masking creates a dependency test. If the model can recover the missing unit using a cheap local cue, the pressure is shallow. If recovery requires object state, action phase, exact symbol, physiological event, or cross-modal alignment, the same training format becomes much deeper.

2. Reconstruction teaches detail, but not every detail deserves survival

rebuild

PRISM projects fMRI into object-attribute-relation text before reconstructing visual stimuli, which makes the reconstruction less about raw voxel copying and more about preserving supported concepts. SleepLM aligns physiological signals with captions, retrieval, event localization, and reconstruction-like tasks so sleep traces become language-grounded evidence. CLEAR uses self-supervised occlusion priors for video restoration, where the hidden area must be rebuilt without relying on an explicit mask at inference.

The first-principles distinction is between reconstructing the surface and reconstructing the state. Surface reconstruction asks whether the output looks like the input. State reconstruction asks whether the rebuilt artifact preserves the object, event, measurement, or domain fact that later decisions need.

3. Reconstruction can become a bridge between modalities

bridge

BioX-Bridge aligns intermediate biosignal foundation-model representations through bridge networks, reducing trainable parameters while transferring across physiological modalities. Mind-Omni uses discrete brain tokens and diffusion across brain-vision-language tasks. These papers treat reconstruction and translation as a way to test whether a middle representation carries the same measured state across different instruments.

A good bridge is not a generic embedding. It is a promise that the downstream modality can still recover the relevant event. A bad bridge may produce fluent captions or plausible images while erasing uncertainty, subject variation, timing, or clinically meaningful thresholds.

First-principles line
Masking and reconstruction are useful when the missing or rebuilt unit forces the model to preserve the state that later behavior depends on, not merely the surface that is easiest to imitate.
TOPIC 03

Contrast and identity

Contrastive training teaches identity by comparison: pull together what should count as the same, push apart what should count as different.

Contrast is powerful because many concepts are relational. A model may not know what matters in an image until it sees a near-miss where only one cue changes. It may not know what makes a document relevant until it sees a hard negative. It may not know how speech, sleep, image, graph, or text align until the task forces matching across views. Contrast tells the representation what distinctions must remain sharp.

But contrast can also teach the wrong identity. If positives and negatives are chosen badly, the model may separate examples by background, language, shortcut style, patient site, camera, or annotation artifact. If the objective overemphasizes uniformity, it may flatten hierarchy. If hard examples are too hard or contradictory, they can damage unsupervised learning. Contrast is therefore not automatically deep. It is deep only when the contrast changes the answer for the same reason the deployment task changes the answer.

1. Contrast identifies the deciding cue

grounding

VC-STaR builds contrastive visual reasoning examples that force precise evidence identification. The target is a common VLM failure: a model can answer correctly for the wrong visual reason. By changing the visual cue that controls the answer, the training or evaluation pressure asks whether the model grounded the answer in the right place.

This generalizes beyond vision. In law, the contrast may be two similar clauses. In medicine, two drug names or threshold-crossing lab values. In code, two snippets that differ by one semantic condition. In retrieval, a relevant source and a near-duplicate distractor. Good contrast makes the answer-changing difference visible.

2. Contrast can flatten structure if the objective is crude

failure

Difficult Examples Hurt Unsupervised Contrastive Learning shows that examples considered useful in one setting can hurt contrastive generalization in another. HyperDepth identifies semantic flattening in hypergraph contrastive learning and balances local uniformity with global hierarchy. InfoNCE Gaussian gives an analytic lens on contrastive representations, showing that the geometry produced by contrast has measurable structure rather than being a black box.

The underlying issue is that contrastive pressure asks the model to organize a space. If the pressure only says "spread everything apart," hierarchy can disappear. If it only says "make views similar," important differences can blur. The contrast has to match the domain's real identity boundaries.

3. Cross-modal contrast decides what the views share

alignment

SleepLM aligns polysomnography with natural language through contrastive alignment, captioning, and signal reconstruction. BioX-Bridge uses physiological correlations to transfer across biosignal modalities when labels are scarce. VGS decomposes VLM distillation into language-prior and visual-grounding components, finding that the grounding subspace needs separate treatment.

Cross-modal contrast is a choice about shared identity. Are sleep signals and captions the same because they describe the same event? Are image and text the same because both support the same answer? Are brain signal and visual object the same because one measured the perception of the other? The representation improves when the contrast preserves the real shared state instead of forcing all modalities into a shallow common style.

First-principles line
Contrastive training is identity pressure: it works when positives and negatives are chosen around the distinction the later system must actually use.
TOPIC 04

Prediction and future state

Prediction pressure teaches the model what present information matters because it will change a future state.

A predictive task is deeper than a fill-in task when the answer cannot be recovered from surface regularity alone. The model has to preserve variables that control what happens next: object motion, patient trajectory, physical state, route stability, tool consequences, future observations, or long-context evidence. The unit of representation becomes future-relevant state, not just a token, patch, frame, or table row.

This is why prediction is central across modalities. In language, next-token prediction can teach syntax, style, and factual continuation, but it may not teach which evidence should control a later decision unless the task makes that dependence necessary. In video, predicting the next frame is shallow if it only smooths pixels, but deeper if it preserves object identity and action phase. In robotics, prediction matters when the latent state supports control. In science, prediction matters when the representation preserves a mechanism, not only a curve.

1. Future prediction turns representation into state

state

TD-JEPA and Koopman representation work both learn latent dynamics meant to support downstream control or prediction. The important move is that the latent space is judged by whether it can carry the future-relevant variables forward. MERLIN learns observation functionals with near-linear progression and memory terms for reduced-order Koopman forecasts, which is the scientific version of the same idea: a compressed state is good only if future evolution remains stable.

A state is not just a hidden vector. It is a compact record of what will matter later. If the future requires exact identity, the state must preserve identity. If the future requires physical constraints, the state must preserve constraints. If the future requires a diagnosis trend, the state must preserve timing, baseline, and uncertainty.

2. Prediction across action teaches consequences

action

LaST0 models future visual dynamics, 3D structure, and proprioception in latent reasoning space for vision-language-action control. WestWorld uses morphology-aware trajectory world models. Latent Action Supervision shows that discrete latent action-token supervision can train VLA models effectively, while also finding that different latent formulations help different task types. These papers make the same point: actions need representations that predict consequences, not just labels that describe the current frame.

For agents, this pressure is the difference between a tool call that sounds relevant and a tool call that changes the next state usefully. For robots, it is the difference between recognizing a scene and knowing what movement will do. For code, it is the difference between generating a patch and anticipating the tests, proof obligations, or runtime behavior that follow.

3. Prediction can be operational, not only statistical

decision

dWorldEval couples future observation generation with progress-as-text indicators for learned robot policy ranking. ROCP treats prediction sets as operational decision objects, balancing coverage with downstream minimax decision risk. TESS maps temporal text events into forecasting primitives, asking whether language changes a future numeric trajectory in structured ways. These are prediction tasks where success means supporting a later decision.

The first-principles lesson is that forecasting pressure should preserve the variables that a later action will use. Prediction is weak when it only matches the next surface. It is strong when it creates a state that remains useful for control, diagnosis, planning, risk, or scientific explanation.

First-principles line
Prediction pressure is useful when it forces the present representation to keep the facts that will control future behavior, not merely the surface pattern that comes next.
TOPIC 05

Teacher-student targets

Teacher-student training transfers pressure from one system to another. The student does not only learn outputs; it learns what the teacher's signal makes worth preserving.

A teacher can provide labels, logits, traces, intermediate states, preferences, activations, visual grounding gradients, or curricula. That is powerful because the teacher can expose structure that sparse final labels do not contain. But it is also risky. The teacher may pass along style, bias, blind spots, overconfidence, wrong rationales, or a representation that was useful for the teacher but mismatched to the student's use case.

The key question is not whether distillation is cheaper than training from scratch. It is what kind of knowledge is being distilled. A final answer distills outcome behavior. A reasoning trace distills path shape. A local transition distills a reusable operation. A context-conditioned distribution distills how evidence should update a model. A visual-grounding gradient distills which modality should control the answer. Each target creates a different representation.

1. Teachers can give paths, not only labels

trace

OpenThoughts scales a teacher-generated reasoning pipeline across math, code, and science. LALP selects teacher traces from diverse pools by transferable local step transitions, which is a sharper target than whole-response correctness. SOAR uses asymmetric teacher-student meta-RL to generate learnable curricula for hard tasks with sparse binary rewards, rewarding teachers by actual student improvement.

The deeper principle is that a useful teacher signal should identify the move that helps the student learn. If the student copies long traces without learning reusable transitions, the representation becomes style-heavy. If the teacher signal highlights local steps that transfer, the student learns operations it can use in new problems.

2. Distillation targets can conflict with the task

conflict

DTO-KD dynamically balances task and distillation gradients because the teacher can pull against the downstream objective. VGS decomposes vision-language distillation into language-prior and visual-grounding gradients, then prioritizes grounding updates when language shortcuts dominate. DGS-Net uses distillation-guided gradient decomposition to preserve transferable CLIP priors while fine-tuning for synthetic-image detection.

This shows why "learn from the teacher" is not precise enough. The teacher may know useful structure, but the student still needs gradient arbitration. The update should preserve the teacher's transferable signal while refusing the parts that would erase task-specific evidence, grounding, robustness, or domain distinctions.

3. Teachers can protect continuity during adaptation

continuity

DiSC distills teacher and student distributions conditioned on different context segments, updating parametric knowledge while preserving instruction-following, reasoning, and factual skills. RealUID distills matching models into faster generators using real-data supervision. TRACE extracts hidden diffusion attention boundary cues and distills them into a fast edge decoder. These papers use teacher signals to preserve useful behavior while changing the student interface, speed, or domain.

The first-principles risk is inheritance without understanding. The student may inherit the teacher's confidence without its evidence, its style without its mechanism, or its broad behavior while losing rare exact details. Good teacher-student training asks what must remain the same across the transfer and what the student is allowed to change.

First-principles line
Teacher-student training is inherited pressure: the student learns whatever the teacher target makes visible, so the target must expose the structure the student will need later.
TOPIC 06

Bottlenecks and compression

A bottleneck is a forced choice about what survives. It can create useful abstraction, or it can erase the exact fact that later behavior needed.

Compression is not automatically intelligence. A smaller vocabulary, sparse dimension set, latent patch, concept bottleneck, low-rank adapter, compressed context, binary code, or hidden reasoning state only helps if the training task punishes the loss of important information. Otherwise the model may become efficient by throwing away rare details, exact names, boundary cues, time order, medical thresholds, source authority, or recovery history.

The first-principles question is: what is the bottleneck for? Some bottlenecks remove noise. Some reduce compute. Some force interpretability. Some protect privacy. Some separate structure from content. Some make a model deployable on smaller hardware. Some make a long context usable. The right bottleneck keeps the answer-changing variables and discards variation the use case can tolerate.

1. Compression must preserve the unit of use

unit

TACO compresses in-context tabular training data into latent rows or tokens, making memory and latency practical for tabular foundation models. LST compresses raw speech tokens into latent patches better aligned with text. dnaHNet uses tokenizer-free latent chunking for long sequences. Each case changes the unit the model carries forward: rows, speech patches, chunks, or learned latent units instead of raw input atoms.

The danger is misaligned compression. If a tabular compressor loses the rare row that controls prediction, speed is bought by wrong evidence. If speech patches erase a phonetic cue, alignment looks efficient but fails on exact content. If latent chunks cross meaningful code, math, or medical boundaries, the model may never recover the distinction.

2. Bottlenecks can make concepts functional

concepts

M-CBE generalizes concept bottleneck models by learning multiple concept-to-task expert expressions. CompSLOT adds object-centric slots and concept-similarity distillation for continual vision learning. DiSCo/Table-GLS separates table layout structure from semantic content for multimodal table reasoning. These papers use bottlenecks to name reusable intermediate objects rather than only shrink vectors.

A concept bottleneck is valuable when the named concept actually controls behavior. It is weak when concepts are decorative labels that do not affect the decision. The useful compression is not just fewer dimensions; it is a better handle on the thing the system must compare, compose, remember, or explain.

3. Capacity bottlenecks decide where effort can go

capacity

FlexRank treats low-rank capacity as an adaptive resource. PonderLM-2 and MDM Reasoning ask where reasoning computation can happen when not every step is public text. Tool-Augmented SSMs and hybrid sequence-model work ask which memory roles require attention, state, or external tools. Nevo-CRL evolves task-specific activation masks over a fixed policy network to prevent forgetting and reuse prior skills.

These are all capacity-allocation questions. Which dimensions stay active? Which reasoning steps stay visible? Which memory lives in parameters, context, state, or tools? Which old skill is frozen, reused, or pruned? The bottleneck is successful only if the training task makes the loss of useful behavior visible.

First-principles line
A bottleneck is intelligent only when it removes what the use case can ignore while preserving the exact units, concepts, evidence, and future state that later behavior needs.
TOPIC 07

Reward and verifier pressure

Reward training asks the model to preserve whatever helps it score. Verifier training asks it to preserve whatever can survive a check.

This is different from ordinary prediction. A predictive task asks what is likely. A reward or verifier task asks what is acceptable, useful, safe, executable, preferred, or worth doing. That change matters because many AI systems are not only producing continuations. They are solving math, writing code, using tools, acting in environments, refusing unsafe requests, following preferences, and deciding when to stop.

The risk is that reward pressure can teach shortcuts. If the reward model likes long reasoning, the model may become verbose. If the verifier is weak, the model may learn to pass the weak check. If the final answer is rewarded but intermediate actions are invisible, the model may hide bad process. If the preference target is underspecified, the model may learn style instead of substance. Reward is not magic pressure; it is pressure toward whatever the scoring system can see.

1. Verifiers turn process into trainable evidence

verifier

Gaia2 uses action-level verifiers in dynamic environments, so an agent is not judged only by the final response. Write actions become checkable units and therefore possible reward signals. THOR adds tool feedback at intermediate math steps. VERINA separates code, specification, and proof obligations. CE-Graph uses counterexample pools and Propose-and-Verify graph edits to improve workflows.

The shared principle is that the training task should expose the step that matters. If a proof step fails, that should be visible. If a write action changes state incorrectly, that should be visible. If a workflow fails on a counterexample, the failure should become data for repair. Verifiers make hidden process into pressure.

2. RL changes what existing mechanisms are used for

rl

Base Models Know How to Reason reports that hybrids recover much more of RL-trained gaps than SFT-distilled gaps, suggesting that RL can teach when to use mechanisms that may already exist. Trust-Region LLM RL improves reasoning and code training while constraining updates so useful inference behavior is not destroyed. DMPO adapts policy optimization to diffusion LMs by matching a reward-tilted distribution and correcting small-batch mode-coverage errors.

This makes reward pressure a routing problem inside the model. The model may already contain partial skills, but the reward decides when those skills are activated, how much compute is spent, and which candidate path becomes preferred. Bad reward pressure can activate the wrong style of reasoning; good reward pressure makes the useful mechanism easier to use.

3. Reward must price cost, diversity, and failure

tradeoff

HERO shapes reward comparison inside verifier-defined groups. DECS separates useful exploratory reasoning tokens from redundant length. SOAR rewards teachers by actual student improvement, avoiding proxy-driven instability and diversity collapse. Stable-GFN uses pairwise comparison, noisy-reward masking, and fluency stabilization to find diverse effective LLM attacks. These papers show that reward design often fails by rewarding only one axis.

The representation learns what reward makes valuable. If cost is invisible, the model may overthink. If diversity is invisible, samples collapse. If failure mode is invisible, the model optimizes a proxy. If student improvement is invisible, a teacher can produce tasks that look hard but do not teach. Reward pressure should name the real tradeoff.

First-principles line
Reward and verifier pressure shape behavior by deciding what counts as progress; they work only when the scoring signal sees the process, cost, failure, and consequence the use case actually cares about.
TOPIC 08

Collapse prevention

Collapse is what happens when many useful possibilities become one cheap answer, one dominant style, one inactive dimension set, or one repeated loop.

Training pressure can collapse representations in many ways. Contrastive objectives can flatten hierarchy. Sparse systems can route too many tokens to the same experts. Reasoning models can repeat long but redundant traces. Generators can lose mode coverage. Pruned models can keep accuracy while becoming unstable in generation. Continual learners can overwrite old concepts. RL policies can stop exploring. Collapse is not one bug; it is a family of failures where the model stops preserving meaningful alternatives.

Preventing collapse means making the lost alternative visible to the training task. If dimensions go unused, the task needs pressure for balanced representation. If outputs repeat, the task needs token-level diagnostics. If exploration becomes redundant, the reward must distinguish useful exploration from length. If contrastive learning flattens hierarchy, the objective must preserve local and global structure. If continual learning overwrites old skills, memory units need boundaries.

1. Representation collapse hides before accuracy drops

hidden

FOCUS & RePAIR shows that pruning can amplify repetition loops even when perplexity and task accuracy remain largely unchanged. It decomposes repetition into loop-entry risk and loop-persistence risk, then targets escape mass around plausible alternatives. LM Geometry Diagnostics warns that rank-like measures can reflect training hyperparameters more than downstream performance, so collapse metrics need behavioral grounding. Isotropic Gaussian RL reduces neuron dormancy and representation collapse by encouraging balanced use of dimensions.

The lesson is that aggregate accuracy is too coarse. A model can still pass familiar tasks while losing generation diversity, rare-token control, dimensional health, or robustness under long outputs. Collapse prevention needs diagnostics at the unit where the failure lives.

2. Diversity must be useful, not decorative

diversity

DECS separates exploratory reasoning tokens from redundant reasoning tokens because a blunt length penalty can punish useful search and reward shallow brevity. Stable-GFN stabilizes red-team generation so the system finds diverse effective attacks rather than one repeated mode. SOAR rewards teacher models by student improvement, not by superficial task variety. DMPO's mode-coverage correction addresses a diffusion-RL case where poor batch coverage can push updates in the wrong direction.

Useful diversity means the alternatives cover different assumptions, paths, cues, failures, or modes. Decorative diversity is the same answer with different wording. A training task prevents collapse when it rewards alternatives that change what the model can learn or do.

3. Memory collapse is a forgetting problem

memory

CompSLOT protects concept-compositional memory through object-centric slots and concept-similarity distillation. Nevo-CRL evolves task-specific activation masks over a fixed policy network to prevent forgetting and reuse prior skills. DiSC updates parametric knowledge from adaptation corpora while preserving instruction following, reasoning, and factual skills. These are collapse-prevention methods over time: the model must change without turning old useful structure into noise.

Continual learning makes the collapse problem obvious, but the same issue appears in every training setup. If new pressure overwrites old evidence, the representation becomes narrower. A good task does not only improve the current metric; it preserves the useful alternatives the future system still needs.

First-principles line
Collapse prevention asks what useful distinction, dimension, mode, path, or memory would disappear under ordinary training, then adds pressure that makes that loss visible.
TOPIC 09

Units across modalities

Training pressure always acts on some unit: token, patch, object, frame, clip, dimension, concept, action, proof step, lab value, or patient state.

The unit is not decided by the data type alone. Text can be characters, subwords, tokens, spans, claims, intents, retrieval chunks, or proof obligations. Vision can be pixels, patches, regions, objects, parts, relations, or scenes. Video can be frames, clips, tracks, actions, phases, events, or goals. Code can be characters, tokens, AST nodes, types, tests, patches, runtime traces, or proofs. Medicine can be measurements, visits, symptoms, medications, diagnoses, trajectories, or latent patient state. The training task decides which level becomes useful.

A unit is chosen well when the training pressure matches the later use case. If exact names matter, subword compression cannot erase spelling. If object boundaries matter, patch training must preserve boundaries. If action timing matters, frame-level supervision may be too short or too static. If table reasoning matters, layout and content may need separate units. If a robot must act, the unit may need to be a latent action token rather than an image caption.

1. Tokens, subwords, chunks, and exact strings

language

TokSuite controls tokenizer choice across matched pretrained models, showing that tokenization is not a harmless preprocessing detail. Incremental BPE asks for stable subword boundaries in streaming settings before the full future is visible. dnaHNet uses tokenizer-free latent chunking, letting the model discover chunks rather than inherit them from a tokenizer. Skill Neologisms adds compact tokens for procedural capabilities.

The first-principles issue is exactness. Code symbols, math vocabulary, drug names, legal terms, and person names can change meaning with small surface changes. A training task can compress strings only if exact distinctions survive somewhere recoverable.

2. Patches, objects, scenes, and relations

vision

VC-STaR uses contrastive visual evidence so the decisive cue must survive. CompSLOT uses object-centric slots and concept primitives for continual vision learning. PRISM projects brain signals into object-attribute-relation text before visual reconstruction. DiSCo/Table-GLS separates table structure from content. These papers show that pixels or patches are often the wrong final unit when the task depends on object identity, relation, or layout.

Patch-level training is useful when local visual evidence matters. Object-level training is useful when identity, part-whole structure, occlusion, or relations matter. Scene-level training is useful when global layout or physical plausibility matters. The unit should be where the answer-changing boundary lives.

3. Frames, clips, actions, and embodied state

time

Latent Action Supervision shows that discrete latent action-token supervision trains VLA models and that image-based versus action-based latents help different tasks. LaST0 models future visual dynamics, 3D structure, and proprioception in latent reasoning space. dWorldEval ranks robot policies through generated future observations and progress indicators. SleepLM treats physiological traces as long signals tied to events, captions, retrieval, and localization.

A frame is too small when the task is an action phase. A clip is too small when the task is a goal. A caption is too coarse when the task depends on timing. A latent action is useful when it carries the control bottleneck. Time-sensitive training should choose the shortest unit that preserves the event and the longest unit needed to explain its consequence.

4. Sparse dimensions, concepts, and exact domain units

domain

M-CBE uses concept bottleneck experts. Isotropic Gaussian RL pressures balanced dimension use. FlexRank changes low-rank capacity by deployment need. VERINA separates code, specification, and proof. ROCP treats prediction sets as decision objects. Medical and physiological papers such as SleepLM, Mind-Omni, BioX-Bridge, and PhenoBrain operate on measured states rather than generic labels.

The same rule applies across domains: choose the unit that the later decision will respect. A code unit may be a proof obligation. A medical unit may be a thresholded trend. A safety unit may be a policy behavior under pressure. A scientific unit may be a conserved state or feasible object. Dense vectors are useful only if the exact domain units remain recoverable when they matter.

First-principles line
The right training unit is the level where the use case's answer-changing distinction lives: exact string, object, action phase, concept, sparse dimension, proof step, measurement, or state.
TOPIC 10

Depth of task signal

A training task is deep when the easiest way to do well is to preserve the structure the later use case really needs.

A shallow task can be solved through surface co-occurrence, style, local texture, broad category labels, or memorized benchmark format. A deep task forces the model to keep mechanism, relation, evidence, action consequence, exact syntax, or domain state. The difference is not the name of the objective. Masking can be shallow or deep. Contrast can be shallow or deep. Reconstruction can be shallow or deep. Reward can be shallow or deep. What matters is whether the task makes the intended variable necessary.

Depth is therefore a question about dependency. If the target can be predicted without reading the decisive source, the representation may not learn evidence use. If a visual answer can be guessed from language priors, the model may not learn grounding. If a code answer can pass a weak test without satisfying the invariant, the model may not learn semantics. If a medical label can be predicted from site artifacts, the model may not learn patient state. A deep task removes the shortcut or makes the shortcut fail.

1. Surface tasks teach association

surface

Surface pressure is not useless. Next-token prediction teaches language regularities. Patch reconstruction teaches visual texture. Captioning teaches a useful interface. But these tasks become misleading when the later system needs exact evidence, mechanism, or action. A model can speak the right style, name the right object class, or complete a familiar pattern while failing the decision that matters.

TokSuite, Incremental BPE, and dnaHNet show that even the surface unit matters because token boundaries shape what the model can learn. FOCUS & RePAIR shows that surface metrics can miss generation dynamics. LM Geometry Diagnostics warns that internal-looking numbers can still fail to predict downstream behavior. Shallow signals are useful only when we keep their claim narrow.

2. Structural tasks teach relations and constraints

structure

Structural pressure asks the model to preserve how parts fit together. VC-STaR forces a visual cue to control the answer. CompSLOT protects object-centric concepts for continual learning. DiSCo/Table-GLS separates table layout from content. HyperDepth balances local contrast with global hierarchy. Protein Autoregressive Modeling uses hierarchical protein structure to guide next-scale prediction.

A structural task is deeper than a surface task because it makes isolated labels insufficient. The model must keep relations: object-to-attribute, row-to-column, part-to-whole, local-to-global hierarchy, symbol-to-definition, or state-to-action. The representation becomes useful because the task punishes breaking the relation.

3. Mechanistic tasks teach consequences

mechanism

Mechanistic pressure asks whether the representation supports an operation that can be checked. VERINA compares code, specification, and proof. THOR gives tool feedback at intermediate math steps. Gaia2 uses action-level verifiers. CE-Graph repairs agent workflows from counterexamples. MERLIN and Koopman-style work ask whether compressed scientific state evolves correctly.

This is the deepest common form because the model cannot merely describe the world. It must preserve the rule that changes the world. Code must run or prove. A tool action must update state. A physical model must forecast. A workflow must recover from counterexamples. A mechanistic task trains representations that carry causal, executable, or procedural structure.

4. Domain-state tasks teach the real object

domain

SleepLM, Mind-Omni, BioX-Bridge, PRISM, PhenoBrain, ROCP, TESS, and LaST0 all point toward domain-state pressure. The useful representation is not a generic embedding. It is a sleep event tied to physiological evidence, a brain signal tied to perceived concepts, a patient or phenotype state, a risk-sensitive prediction set, a time-series event effect, or an embodied latent state for control.

Domain-state pressure is deep because the answer is defined by the field. Medicine cares about thresholds, uncertainty, timing, and harm. Robotics cares about body-world consequences. Science cares about mechanisms and feasible states. Tables care about structure and semantics. The training task should make the domain's native state hard to erase.

First-principles line
The depth of a training task is measured by the weakest shortcut that can pass it; the deeper task makes surface shortcuts fail and makes the real structure necessary.
TOPIC 11

Behavior tests

A behavior test asks whether the representation learned the operation it was supposed to learn, not merely whether the loss went down.

Training creates pressure, but pressure is only useful if we can later test what it created. A masked model should recover the missing unit for the right reason. A contrastive model should separate examples by the deciding cue. A reconstruction model should rebuild domain state, not only surface detail. A teacher-student model should transfer useful mechanism, not style. A bottleneck should preserve the answer-changing variable. A reward-trained model should optimize the real behavior, not the scoring loophole.

The right behavior test changes the evidence and watches whether behavior changes in the right way. Remove the decisive source. Flip the visual cue. Change one token in a drug name. Swap the object boundary. Break the proof obligation. Add a distractor chain. Change the interface while preserving the task. Shift the patient threshold. If the model's answer does not move with the controlling evidence, the representation probably learned a shortcut.

1. Grounding tests ask what evidence controlled the answer

grounding

VC-STaR tests visual grounding by using contrastive examples where one cue changes the answer. LoongRL tests long-context grounding through UUID chains, true-question identification, retrieval, and rechecking amid distractors. CRAMF tests formal vocabulary grounding by requiring the right Mathlib4 definitions. MetaphorVU and UALM-R1 show that the deciding evidence may be relational video structure or audio-text information rather than text alone.

A grounding test proves more than correctness. It asks whether the model used the source, cue, definition, modality, or relation that should have controlled the answer. This is the behavior-test version of contrastive training.

2. Verification tests ask whether the claim survives a stronger check

verification

VERINA exposes the gap between code correctness and proof success. THOR makes intermediate math steps accountable through tool feedback. Gaia2 turns write actions into verifier-scored units. CyberGym, SandboxEscapeBench, and CVE-Factory in the evaluation theme show the security version: a vulnerability claim must become executable behavior against vulnerable and patched code.

The point is scope. A unit test can prove one behavior. A proof can prove a stronger invariant. A runtime check can show one consequence. A verifier can accept one action. Behavior tests should say exactly what the check proves and refuse to promote weak evidence into a stronger claim.

3. Recovery tests ask whether failure changes the next state

recovery

T3 learns from useful prefixes inside failed trajectories. CE-Graph uses counterexample-guided edits to improve workflow robustness. CRV repairs faulty reasoning through attribution-graph analysis and targeted feature interventions. AutoEP uses search diagnostics to adapt strategy. These papers are behavior tests for learning from failure.

A recovery test should not ask only whether the second answer is better. It should ask whether the system kept the useful part, identified the failed part, changed strategy, and avoided repeating the same mistake. If failure does not update state, the training pressure did not create real recovery.

4. Collapse tests ask whether alternatives still exist

collapse

FOCUS & RePAIR tests repetition at token-level loop entry and loop persistence. DECS separates useful exploration from redundant reasoning length. Stable-GFN tests whether red-team generation keeps diverse effective modes. CompSLOT and Nevo-CRL test whether old concepts or skills remain usable after new learning. These tests expose failures that average accuracy can miss.

A collapse test asks whether the model still has the alternatives that the use case needs: alternate modes, dimensions, concepts, memories, sources, paths, or plans. If they disappeared, the representation may look compact but it has become brittle.

First-principles line
A behavior test proves the learned representation by changing the controlling evidence and checking whether the model changes for the right reason.

The whole theme in one pass

synthesis

Masking asks what can be recovered from context. Reconstruction asks what detail must survive. Contrast asks what identity boundary matters. Prediction asks what present state controls the future. Teacher-student training asks what target is inherited. Bottlenecks ask what can be compressed away. Reward and verifiers ask what behavior counts as progress. Collapse prevention asks which alternatives would disappear. Behavior tests ask whether the learned representation actually performs the intended operation.

Together, these are not a list of losses. They are ways of putting pressure on information. The page's core claim is that representation learning is use-case-specific because every training task makes a promise about what the later system should still be able to compare, copy, predict, explain, verify, or act on.

First-principles line
Training tasks create representations by pressure: they decide which units survive, which shortcuts fail, which structure becomes usable, and which behavior can later prove that learning was real.
