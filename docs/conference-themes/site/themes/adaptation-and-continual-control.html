Problem

Full retraining is too slow for many adaptation needs. The model may need to infer a task, personalize a reward, update fast weights, or improve prompts while it is already deployed.

Approaches

The papers use test-time training, support-example graph inference, hyperparameter-conditioned paths, bandit task inference, task-vector projection, natural-language reflection, and preference transfer.

Connecting read

This is a control theme: adaptation is useful only when the system knows what to change, what to preserve, and how much evidence is enough.

FIRST PRINCIPLES

The core problem

A deployed model sees new evidence after training: a user's preferences, a support set, a task trajectory, a new hyperparameter setting, or a failed prompt. The adaptation question is how to turn that evidence into behavior change without overwriting the base system.

The papers here make adaptation local. Some adapt at inference time without parameter updates. Some alter fast weights or output distributions. Some preserve reasoning format while merging instructions. Some use reflection and search to improve prompts. The common shape is bounded change under limited evidence.

TOPIC 01

Adaptation starts with evidence, not desire

A model should change because a specific evidence source justifies the change.

The evidence may be a support set, a bandit trajectory, a current context, a user preference trace, a failed rollout, or a hyperparameter setting. Each source has a different authority. A few graph support examples can justify a local prediction adjustment. A user-neighbor set can justify cautious personalization. A failed prompt trajectory can justify prompt search. None of those automatically justify moving the whole model.

This is the first-principles contract of the page: name the evidence, name the allowed behavior change, and name the behavior that must stay fixed. Without that contract, adaptation becomes a vague promise to improve.

TOPIC 02

The smallest useful surface should move

Controlled adaptation is not about changing everything quickly. It is about changing the narrowest surface that can absorb the new condition.

MF-GIA changes the inference rule from support examples without reopening raw modalities or updating weights. HTI changes the output-distribution path across hyperparameter settings. In-Place TTT changes final-projection fast weights temporarily. RAIN-Merging changes a projected task vector while protecting reasoning-related features. These are all different answers to the same design question: where should plasticity live?

The smaller the surface, the easier it is to reason about what stayed fixed. That does not mean small changes are always enough. It means the method should justify why this surface is the right one for the evidence it receives.

TOPIC 03

Temporary evidence should not become permanent knowledge

Some adaptation should expire when the context, support set, or task episode ends.

In-Place TTT is useful because the current context can reveal local structure that was not available during pretraining. But that local structure may be accidental, adversarial, or irrelevant to the next document. If temporary evidence writes permanent behavior, the model starts learning the wrong lesson from a narrow case.

OpTI-BFM has the control version of the same boundary. Exploration can identify the current task, but costly actions cannot be treated as free information. Adaptation under uncertainty must account for regret while it learns. The model should ask not only "what can I learn from this evidence?" but also "what damage can the learning action cause?"

TOPIC 04

Personalization must preserve disagreement

A user-specific model should not confuse nearby-user similarity with the user's actual rubric.

P-GenRM transfers preference structure from similar users and adapts scoring at test time. That is practical because every user cannot train a full reward model from scratch. But the risk is preference averaging: users can look similar on surface examples while disagreeing on the criterion that matters.

So the fixed object is the individual's scoring meaning. Borrowed structure is allowed only insofar as it helps estimate that meaning. If the method smooths away real disagreement, it is no longer personalization. It is population-level approximation wearing a personal label.

TOPIC 05

Search improvements need causal failure stories

Reflection and lineage metrics are useful only when they identify what made behavior improve.

GEPA improves prompts through trajectory reflection and Pareto search. The reflection is valuable if it points to a reusable cause of failure: the prompt omitted a constraint, encouraged the wrong tool order, or failed to preserve evidence. It is weak if it merely tells a plausible story after the rollout.

Huxley-Goedel Machine pushes the same issue across generations of coding agents. A descendant metric should reward durable capability improvement, not artifacts of a development lineage. In both papers, adaptation becomes search over future behavior. The proof has to show that the search signal tracks real capability, not cosmetic progress.

ANATOMY

Four surfaces where adaptation can live

The papers differ because they do not all adapt the same thing. Each one chooses a narrow surface where new evidence can change behavior while the rest of the system remains anchored.

WHY IT WORKS

Local adaptation works when the evidence is local

The first-principles bet is that many deployment shifts do not require rewriting the whole model. They require changing the interface through which the model interprets the current situation.

OpTI-BFM treats the current task as something to infer through action, so adaptation is exploration under regret rather than blind policy replacement. MF-GIA treats a few support examples as enough to align a pre-encoded graph domain, so the system adapts the prediction rule instead of reopening raw modalities or retraining weights. In-Place TTT uses the current context to update fast weights temporarily, which is appropriate when the relevant structure lives inside the current document or sequence.

The preservation papers make the same point from the opposite direction. RAIN-Merging says instruction skill is useful only if the long-reasoning format survives the merge. P-GenRM says personalization is useful only if transferred preference structure still respects the individual user's scoring rule. GEPA says reflection is useful only if the language description identifies a causal failure pattern, not just a plausible story after the fact. Huxley-Goedel Machine says agent self-improvement should be judged by descendant capability, not by local edits that look clever today.

EVIDENCE

What would prove controlled adaptation

Bounded change

The adapted system should improve on the new task while measurable old capabilities, formats, or constraints remain intact.

Evidence efficiency

The method should use the promised small evidence source: support examples, context chunks, user neighbors, reflections, or bandit feedback.

Reversibility

Temporary adaptation should be removable or scoped. A context-specific fast-weight update should not become permanent model drift.

Real task signal

Search and reflection methods should improve external rollout or benchmark behavior, not only generate more convincing explanations.

Preserved format

Reasoning-aware merging should keep the thinking or proof format that made the long-reasoning model useful.

Calibration under uncertainty

Bandit or preference methods should know when local evidence is too weak and avoid overconfident personalization or exploration.

FAILURE MODES

How adaptation becomes damage

The danger is not only failure to adapt. The danger is adapting to the wrong thing and treating that change as knowledge.

Prompt overfitting

GEPA-style reflection finds a prompt that wins the sampled rollouts but does not capture a reusable failure cause.

Preference averaging

P-GenRM transfers from similar users whose surface behavior hides a different rubric, so personalization becomes demographic smoothing.

Reasoning erosion

RAIN-Merging adds instruction behavior while quietly removing the feature subspace that supports long reasoning format.

Context contamination

In-Place TTT adapts fast weights to misleading local context and worsens the next chunk instead of helping it.

Expensive exploration

OpTI-BFM gathers task information through actions whose regret is too high for the deployment setting.

Lineage gaming

Huxley-Goedel Machine optimizes a descendant metric that rewards artifacts of the development process rather than durable coding-agent capability.

SYNTHESIS

Three adaptation patterns

1. Inference-time adaptation turns local evidence into temporary behavior

test-time control

These papers avoid full retraining by using support examples, task inference, fast weights, or hyperparameter-conditioned paths at inference time.

ICLR 2026OpTI-BFM
OpTI-BFM connects behavior foundation model task inference to upper-confidence linear-bandit algorithms with regret bounds. It treats task identification as exploration under uncertainty. The model should try actions that identify the task while still controlling regret, rather than assuming the task is known from the prompt.
ICLR 2026MF-GIA
MF-GIA performs inference-time graph prediction from support examples without raw modality access or parameter updates. The important constraint is deployment realism: the system may only receive pre-encoded features and labels. Adaptation has to align support evidence on the fly without opening the original modalities or changing weights.
ICLR 2026HTI
HTI learns conditional output-distribution paths across hyperparameter settings to adapt models without retraining. It turns hyperparameter movement into a learned map through output space. That gives adaptation a continuous control surface instead of a new training job for every setting.
ICLR 2026In-Place TTT
In-Place TTT adapts final-projection fast weights at inference time with a next-token-prediction-aligned objective. It uses the current context as training signal while the model is running. The change is temporary and local, which is exactly why it can help long contexts without committing to a permanent fine-tune.

2. Continual control must preserve the behavior format that still works

preservation

Adaptation can damage useful behavior. These papers explicitly preserve reasoning formats, preference schemes, or future-agent improvement paths while allowing change.

ICLR 2026RAIN-Merging
RAIN-Merging projects instruction-tuned task vectors away from thinking-token feature subspaces to preserve long-reasoning model format. The problem is that instruction adaptation can accidentally destroy the internal or textual format that reasoning relies on. Projection makes preservation part of the merge rule.
ICLR 2026P-GenRM
P-GenRM transfers preferences from similar users and scales individual scoring schemes at test time. Personalization cannot wait for full new reward-model training for every user. The paper treats preference adaptation as borrowing structure from nearby users while keeping the scoring scheme individual.
ICLR 2026Huxley-Goedel Machine
Huxley-Goedel Machine uses a clade-inspired CMP metric to guide coding-agent development toward stronger future descendants. It frames continual agent improvement as lineage control. The question is not only whether today's agent is strong, but whether the development path creates descendants with better capabilities.

3. Reflection and search can improve behavior without gradient training

trajectory search

The final pattern treats adaptation as a search process over prompts or behaviors, using natural-language reflections as the evidence that guides the next attempt.

ICLR 2026GEPA
GEPA uses natural-language trajectory reflection and Genetic-Pareto search to improve prompts with fewer rollouts than GRPO. It turns failures into textual search guidance. Instead of gradient-updating a policy, the system edits the prompt population toward better tradeoffs using reflective evidence from trajectories.
FIELD READ

What this theme says about ICLR

The theme says adaptation is becoming lighter, more local, and more controlled. Models are expected to shift behavior from context, support examples, task traces, and user preference without erasing the base capabilities that made them useful.

For agent evaluation, this matters because agents should not only be evaluated after static training. A useful benchmark may need to measure whether the agent can adapt from its own trajectory, learn a user's scoring rule, or preserve reasoning format while improving task behavior.
