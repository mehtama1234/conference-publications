Adaptation and continual learning as controlled change

Adaptation is useful only when change has boundaries. A model should improve on the new condition without erasing old structure, overfitting the moment, leaking private data, accepting unsafe updates, or moving farther than the evidence supports.

TOPIC 01

What should change, what should stay fixed

The first adaptation question is not how to update. It is where change is allowed to live.

A model has many possible control surfaces: all weights, low-rank adapters, final-projection fast weights, prompts, retrieval memory, user profiles, soft skill tokens, concept slots, activation masks, client-specific parameters, bridge networks, or only the output distribution. Each surface makes a promise. If change lives in fast weights, it can be temporary. If it lives in adapters, it can be modular. If it lives in memory, it can be auditable. If it lives in the full model, it can be powerful but destructive. If it lives in a user profile, it can personalize without forcing global behavior to move.

The controlled-change principle is simple: move the smallest surface that can absorb the new evidence while preserving the old behavior that still matters. RAIN-Merging preserves reasoning format while merging instruction-tuned task vectors. Skill Neologisms adds procedural skills through new soft tokens without changing frozen LLM weights. CompSLOT preserves reusable visual concepts. Nevo-CRL freezes useful neurons and evolves task-specific masks. These are all answers to the same question: what should change, and what must stay fixed?

First-principles line
Adaptation is controlled change: choose the narrowest update surface that can learn the new condition without damaging the behavior that still has authority.
ANATOMY

The concrete object is the update surface

An adaptation paper is about where change is allowed to live: fast weights, adapters, masks, slots, soft tokens, retrieval memory, client parameters, bridge networks, output distributions, or full model weights.

What must stay fixed is the behavior that still has authority. Test-time adaptation must preserve the boundary between local evidence and permanent knowledge. Continual learning must preserve old concepts, skills, safety behavior, and future plasticity. Adapters must preserve base-model behavior and privacy boundaries. Domain transfer must preserve only the structure that remains true in the target domain. Personalization must preserve the difference between one user's preference and global policy.

What may change is the chosen surface and its radius: temporary support alignment, fast-weight update, concept slot, low-rank rank, mask, client adapter, pseudo-label, merge rule, or bridge. The method works when the changed surface absorbs new evidence without spreading damage into unrelated capabilities. The failure boundary is uncontrolled plasticity: the model adapts, but it forgets, leaks, overfits, collapses old skills, or treats temporary local evidence as a durable fact.

CONTRACT

The controlled-change contract

Every adaptation method is making a contract: this part of the system may move, these other meanings must survive, and this evidence will tell us whether the move was justified.

FAILURE MODES

Adaptation fails when change loses its boundary

The danger is not that a model changes. The danger is that the system cannot say what changed, why it changed, who authorized it, and what evidence shows the old commitments survived.

Forgetting

The new update overwrites old concepts, old skills, formats, safety behavior, or future learnability.

Confirmation bias

Source-free adaptation trusts its own wrong pseudo-labels and turns initial error into training signal.

Stale memory

A system remembers feedback, user state, or retrieval evidence after its authority has expired.

Privacy leakage

Local or federated updates expose client information, user preference, or deleted data influence.

Unsafe personalization

A local preference becomes a global policy shift, or malicious context steers future behavior.

Off-support control

A robot, policy, or test-time controller adapts outside the evidence region where its actions were validated.

TOPIC 02

Test-time adaptation

Test-time adaptation uses the current case as evidence, but it must remain local because the evidence is narrow and sometimes misleading.

At test time, the model may see a support set, a long context, a task trajectory, a new hyperparameter setting, an unlabeled shifted batch, or one scientific problem. The attraction is obvious: do not wait for full retraining. The danger is equally obvious: the model may overfit the current context, chase spurious unlabeled structure, or make a temporary change that should not become permanent.

In-Place TTT adapts final-projection fast weights with a next-token-prediction-aligned objective, using the current context as local signal. MF-GIA performs graph prediction from support examples without raw modality access or parameter updates. OpTI-BFM frames behavior-foundation-model task inference as a bandit problem with regret control. HTI learns output-distribution paths across hyperparameter settings. TTT-Discover applies reinforcement learning during test-time search for one scientific or engineering problem. These papers make test-time adaptation a bounded evidence-to-behavior controller.

Local evidence

Support examples, current context, unlabeled shift, trajectory feedback, or one problem instance.

Local change

Fast weights, output path, search policy, support alignment, or temporary control signal.

Local risk

Overfitting, spurious pseudo-labels, bad task inference, or permanent learning from temporary evidence.

First-principles line
Test-time adaptation should change behavior only at the scale justified by the current evidence.
TOPIC 03

Continual learning

Continual learning asks how a model can keep learning over time without turning old capabilities into accidental casualties.

The problem is not only forgetting old labels. A long-lived system can forget concepts, skills, formats, safety behavior, user preferences, source authority, action affordances, and future learnability. It may also become rigid: it keeps old behavior but loses plasticity. Good continual learning therefore needs memory units and update boundaries. Some knowledge should be reusable. Some should be client-specific. Some should be pruned. Some should be frozen. Some should be converted into a compact interface.

CompSLOT uses object-centric slots and concept-similarity distillation so visual learners remember reusable concepts rather than only current class contrasts. FIRE restores plasticity through Frobenius-isometry reinitialization while minimizing weight drift. Skill Neologisms adds trainable soft tokens for procedural skills while keeping base LLM weights frozen. Nevo-CRL evolves activation masks, freezes useful neurons, reuses similar skills, and prunes inactive connections for continual policies and robots. MemoryBench evaluates whether LLM systems can learn from accumulated simulated user feedback over time.

First-principles line
Continual learning works when new capability is added through a memory boundary that keeps old useful structure available and future learning possible.
TOPIC 04

Retention versus plasticity

Retention without plasticity creates a frozen model. Plasticity without retention creates a model that cannot be trusted over time.

Every adaptation method must decide how far to move. Too little movement means the model ignores new evidence. Too much movement means it overwrites capabilities, shifts style, breaks safety behavior, or moves into a brittle local solution. The hard part is that the right amount of movement depends on the evidence source and the risk of being wrong. A support set can justify local behavior. A high-quality midtraining phase can justify broader change. A user preference can justify personalization, not global policy drift. A deletion request can justify removing information, not degrading unrelated performance.

FIRE makes this explicit by balancing stability and plasticity through weight-drift and isometry objectives. DiSC updates parametric knowledge from adaptation corpora while preserving instruction following, reasoning, and factual skills. PRISM midtraining improves reasoning while retaining general ability and stabilizing later RL. Trust-Region LLM RL improves reasoning and code while constraining behavior drift. Local Redundancy defines plasticity through information-theoretic redundancy of local gradient-direction model families. The shared object is update radius: enough movement to learn, not enough to destroy.

First-principles line
The right adaptation step is the smallest reliable move that changes the target behavior while preserving the capabilities, formats, and safety properties still in force.
TOPIC 05

Adapters and low-rank change

Adapters make change modular. Low-rank updates make change cheap. Neither is safe by default.

A low-rank adapter is a bet that the needed behavioral change lives in a small subspace. That can be true for many deployment needs, but it creates new questions. What rank is enough? Which subspace should move? Do client updates collide? Does privacy noise behave correctly under the adapter factorization? Do task and distillation gradients fight? Does a fixed rank waste capacity on easy cases and underfit hard ones?

FlexRank extracts importance-ordered low-rank components so one training run can deploy different submodels at different cost-capability points. LoRA Gradient Descent gives convergence analysis for original LoRA updates rather than treating adapters as pure engineering. DTO-KD balances task and distillation gradients when the teacher pulls against the downstream task. PRISM's gauge-invariant DP LoRA adds intrinsic tangent-space privacy noise so low-rank factorization does not amplify privacy cost. FedPissa selectively aggregates LoRA components and decorrelates subspaces to reduce heterogeneous-client interference. SmartFed routes adapter capacity by input semantics and resource budgets.

First-principles line
Adapter adaptation is controlled subspace movement: choose which low-dimensional directions may change, which must stay private or local, and how much capacity the task deserves.
TOPIC 06

Domain adaptation and source-free transfer

Domain adaptation is useful when the new domain shares structure with the old one. It is dangerous when transfer imports the old domain's shortcuts.

The adaptation question changes when raw source data is unavailable, target labels are scarce, or modalities differ. Then the system must infer what can be reused from support examples, pseudo-labels, density structure, source subsets, or representation bridges. The problem is not only performance. The problem is choosing which old invariances remain valid and which old assumptions must be dropped.

BioX-Bridge aligns intermediate biosignal foundation-model representations through lightweight bridge networks for unsupervised cross-modal transfer. Source Screening selects source subsets that help shared subspace estimation, showing that discarding data can improve transfer. DDG-SFDA Regression refines pseudo-labels under shift through perturbation-robust density structure. Self-Soupervision adapts on unlabeled shifted data and merges model ingredients to improve corrupted-distribution robustness. MF-GIA adapts graph prediction from support examples without raw modality access. These methods adapt by finding a reusable structure under constraints.

First-principles line
Transfer should move only the structure that remains true in the target domain, while refusing source-specific shortcuts that no longer have authority.
TOPIC 07

Personalization and federation

Personalization asks how a system can adapt to one user, client, device, or organization without forcing that local preference into everyone else's model.

The shared model/local model split is central. Some facts are global: language, code syntax, visual concepts, safety constraints, general reasoning. Some facts are local: user preference, client data distribution, device budget, institution policy, private examples, graph structure, or reward scale. A good personalized system shares what is genuinely common and keeps local structure local.

P-GenRM transfers preferences from similar users and scales individual scoring schemes at test time. FlatLand embeds clients in tailored Lorentz spaces, separating client-specific and shared parameters. FedARC aligns federated clients with semantic anchors while preserving local/global fusion. Cost-aware FedOpt prices communication strategies in non-convex federated optimization. SmartFed routes adapter capacity by input semantics and resource budgets. FedPissa reduces client interference by selectively aggregating LoRA components. These papers treat personalization as structured partial sharing, not as one global average.

First-principles line
Personalized adaptation works when shared structure is shared, local structure stays local, and the aggregation rule does not erase either one.
TOPIC 08

Model merging and checkpoint paths

Merging is adaptation by combination: the system tries to inherit capabilities from different model states without destructive interference.

A checkpoint is not just a saved file. It is a point on a training path with its own capabilities, formats, and failure modes. A task vector is not just a direction. It may move useful behavior and damage something else. Merging methods ask how to combine states or directions while preserving what matters: reasoning format, instruction-following, general ability, safety, or specialized skill.

RAIN-Merging projects task vectors away from thinking-token feature subspaces to preserve long-reasoning format. WSM interprets learning-rate decay through checkpoint averaging and finds that the aggregation window controls decay-free pretraining gains. DiSC transfers context-segment knowledge while preserving existing skills. Neural Thickets frames pretrained weights as surrounded by nearby specialist variants, making fine-tuning a local navigation problem. Train-before-Test shows evaluation rankings can change after controlled adaptation, reminding us that the checkpoint path is part of the capability claim.

First-principles line
Merging is safe only when the combination rule knows which capability each model state carries and which interference would invalidate the result.
TOPIC 09

Safety and governance of adaptation

Adaptation is also an attack surface. The ability to change a model is useful only if the change is authorized, auditable, private, and reversible where needed.

Fine-tuning can smuggle harmful behavior. Personalization can leak private data. Federated aggregation can expose clients or erase minority behavior. Adaptation corpora can contain copyrighted or unlicensed material. Unlearning can degrade unrelated predictions. Test-time adaptation can learn from malicious context. Adapter reuse can carry hidden unsafe directions. Governance is therefore not documentation after the fact; it is part of the update rule.

Gaussian certified unlearning introduces a high-dimensional certification view and measures prediction-level degradation after deletion. PRISM's private LoRA work designs noise in the correct low-rank geometry. FedPissa, SmartFed, FlatLand, and Cost-aware FedOpt make federated adaptation respect heterogeneity, privacy, and resource cost. Trojan-Speak shows adversarial fine-tuning can preserve reasoning while evading classifiers. Surgery uses sink-divergence regularization to reduce harmful pattern learning during fine-tuning. Common Corpus makes legal usability a pretraining constraint. These papers define the governance boundary around controlled change.

First-principles line
An adaptation method is incomplete until it says who authorized the change, what data justified it, what privacy or legal boundary applies, and how unrelated behavior was protected.
EVIDENCE

What would prove controlled change

The evidence must show both movement and retention: the target condition improves, and the behavior that still has authority survives.

Target gain

The adapted system should improve on the new task, user, domain, support set, client, safety request, or deletion requirement.

Retention test

Old concepts, skills, formats, calibration, safety behavior, and general ability should be measured after adaptation, not assumed intact.

Surface ablation

Fast weights, adapters, masks, memory, slots, pseudo-labels, or merge rules should be ablated to show where the useful change actually lives.

Boundary stress

Shifted target batches, malicious context, client heterogeneity, off-support actions, and stale memory should test whether the update leaks outside its intended radius.

Privacy and deletion proof

Private, federated, or unlearning methods need certificates, accounting, or distinguishability tests showing the protected information stayed protected.

Future plasticity

A continual method should prove the model can still learn later tasks, not only that it preserved yesterday's benchmark.

CONCEPT BRIDGES

Where to read the larger pattern

Privacy and unlearning are recoverability claims

Controlled change includes controlled removal. A model has not forgotten if deleted information can still steer answers, embeddings, or behavior.

Data is training pressure

Adaptation depends on which evidence moves the model, when it arrives, and what old behavior must remain stable after the update.

Spectra, rank, and subspaces are working objects

Adapters, rank limits, task vectors, and local subspaces define where change is allowed to happen without rewriting the whole model.
