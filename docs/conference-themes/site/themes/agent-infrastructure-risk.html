Problem

Safety systems often inspect visible text, but agent infrastructure creates hidden representations, encoded channels, tool state, and intermediate messages that may carry the real intent.

Approaches

The two papers attack opposite sides of the same gap: hidden unsafe content in messages, and harmful internal representations that survive surface-level filtering.

Connecting read

This theme is small in paper count but important as a warning: monitoring must move closer to the channels through which agents actually compute and communicate.

FIRST PRINCIPLES

The core problem

A safety monitor only works if it sees the object that carries risk. With simple chat, that object looks like user text and assistant text. With agents, the risky object may be a hidden activation pattern, a steganographic message, a tool output, a memory write, a compressed scratchpad, or a protocol-level handoff between components. The infrastructure becomes part of the model's communication channel.

This page is therefore not about two isolated tricks. It is about a monitoring mismatch. Surface classifiers ask whether the visible content appears safe. Agent infrastructure asks whether the whole computational pathway is safe. Those are different questions. If unsafe instructions can be hidden in an apparently harmless message, or if harmful intent can be detected inside activations before it appears in text, then production safety needs deeper observability than prompt/output scanning.

LENS

Safety depends on observing the right channel

The concrete object is the channel that carries intent: visible text, decoded text, internal representation, memory state, or tool-bound message.

The core mistake is assuming that safety-relevant meaning lives only where humans read it. Agent systems transform information. They encode, decode, retrieve, compress, pass state through tools, and represent behavior internally before the final answer appears. A monitor that reads only the visible output can be technically correct about that output and still miss the dangerous computation.

MECHANISM

Risk moves when the system transforms messages

A safety check is only meaningful relative to the representation it inspects.

If a system checks text before decoding, then decoded meaning can escape the check. If a system checks only final output, then harmful internal planning may never be observed. If a system logs tool calls but not memory writes, then the risky state may persist between steps without ever appearing in the reviewed transcript. Agent infrastructure expands the number of places where intent can live.

The practical lesson from these two papers is not that one monitor solves everything. It is that monitoring should follow the transformation chain. For stegotext, inspect what the message becomes after decoding. For activation-level risk, inspect the computation before surface text appears. For production agents, log intermediate state with enough structure that safety systems can ask which channel actually carried the behavior.

WHY IT WORKS

The attacker changes the representation boundary

Surface safety works when the safety-relevant meaning and the inspected representation are the same object. These papers break that assumption.

Invisible Safety Threat changes the text channel. The user interface shows a benign cover question and answer, while hidden content is embedded in the text using invisible-character steganography. The model has been fine-tuned to decode the hidden target question and re-encode the target answer. The classifier is not necessarily weak at judging visible harmful text; it is looking at the wrong representation.

Trojan-Speak changes the model's learned communication protocol. The attack uses curriculum learning and hybrid reinforcement learning to preserve ordinary capability while teaching a classifier-evading way to answer harmful expert queries. That matters because many older attacks paid a visible capability cost. If the model keeps most reasoning performance, then capability benchmarks do not reveal the safety compromise.

The common first-principles point is representation mismatch. A safety system has to monitor the representation where the harmful meaning exists: decoded payloads for steganography, learned protocol behavior for adversarial fine-tuning, and activation states when harmful intent appears before visible text.

TOPIC 01

The unsafe object may be downstream of the text

A harmless-looking string can become harmful after a normal system transformation.

This is the core lesson of hidden-channel attacks. The visible message is only one representation of the interaction. If the system later decodes invisible characters, parses markup, expands a compressed payload, retrieves linked content, or passes the string into a tool, the operative instruction can be different from the inspected text. The safety check was not necessarily bad; it was placed before the meaning became visible.

For agents, this matters because transformations are routine. Messages are summarized, embedded, chunked, retrieved, translated into tool arguments, written into memory, and handed to other agents. Each transformation can move the safety-relevant object. A monitor that sees only the pre-transform surface can approve the wrong thing.

TOPIC 02

The unsafe object may also be upstream of the text

The model can contain harmful intent in its internal computation before the final answer exposes it.

Trojan-Speak points at the opposite direction from steganography. Instead of hidden meaning appearing after decoding, harmful behavior can appear inside activations before surface text is produced. That makes internal state a possible evidence source. If a probe detects a harmful representation early enough, the system may be able to block, redirect, decode, or escalate before the final output is generated.

But activation evidence is not magic. A probe must distinguish real harmful computation from benign nearby topics, safety analysis, fiction, research, or quoted policy text. The useful object is not "an activation looks scary." It is a tested relationship between an internal pattern and downstream unsafe behavior.

TOPIC 03

Capability retention makes safety failure harder to see

If an attack destroys model quality, ordinary evaluations may notice. If capability remains intact, safety-specific observability becomes essential.

This is why the reported Trojan-Speak pattern is dangerous: the model can preserve most ordinary capability while changing how it communicates harmful answers. A benchmark that measures reasoning, coding, or general helpfulness can stay high even though the model has learned a classifier-evading protocol. Performance is not proof of safety when the failure lives in a hidden channel.

The same logic applies to Invisible Safety Threat. A stegotext interaction can look benign to the classifier and still carry the target harmful content after decoding. In both cases, the system's visible competence and visible harmlessness do not prove that the hidden communication pathway is safe.

TOPIC 04

Agent infrastructure needs audit surfaces

A production agent cannot be safer than the channels it can observe, normalize, and test.

The infrastructure lesson is practical. Agent platforms need structured audit surfaces for decoded content, intermediate messages, memory writes, retrieval results, tool arguments, model-state alerts, and cross-agent handoffs. Without those surfaces, safety teams are forced to inspect the easiest representation rather than the operative one.

The right evidence is end-to-end: show that a hidden payload is caught after transformation, that activation alerts connect to actual harmful behavior, that benign near-misses are not overblocked, and that an alert triggers a real mitigation path. Observability is not logging for its own sake. It is the precondition for knowing which representation carried the risk.

EVIDENCE

What would prove monitoring has moved deep enough

Transformation coverage

Checks should catch unsafe content before and after encoding, decoding, retrieval, memory writing, and tool handoff.

Early signal

Activation probes should detect harmful internal state before final text makes the risk obvious.

Low false comfort

A visible safe message should not be treated as proof that the computation or decoded instruction is safe.

Decode audit

Invisible Safety Threat reports that stegotext prompt-response pairs were classified safe before decoding, while more than 90 percent became unsafe after decoding across four fine-tuned models.

Capability retention

Trojan-Speak reports classifier evasion above 99 percent for 14B+ models with less than 5 percent capability degradation, so ordinary performance checks are not enough.

Probe robustness

Activation probes help only if they continue to work against adaptive fine-tuning, distribution shift, benign near-misses, and attempts to hide the internal signal.

FAILURE MODES

Where defenses can give false comfort

The dangerous failure is not only missing unsafe text. It is concluding that the system is safe because the inspected surface is safe.

Pre-transform checks

A classifier checks cover text but never normalizes, decodes, or strips the channel that carries the hidden payload.

Training-data blind spot

Fine-tuning data appears benign because the malicious examples contain no explicit harmful plaintext before decoding.

Benchmark comfort

The model retains general benchmark capability, so evaluators miss that safety behavior changed under a hidden protocol.

Probe overfit

Activation monitors detect one learned protocol but fail when the adversary adapts the representation or shifts layers.

False positives

Internal monitors can trigger on benign CBRN-like discussion, fiction, policy analysis, or safety research unless tied to behavioral evidence.

Unmitigated alert

A probe that detects risk but cannot block, quarantine, decode, or escalate the interaction is only an alarm, not a defense.

SUBTHEMES

Two failure modes the papers expose

1. Hidden channels defeat surface monitoring

encoded communication

The first risk is that a message can look harmless at the level the safety system reads while carrying a different meaning at the level the agent or downstream decoder uses. This is especially relevant for multi-agent systems, tool-using workflows, and retrieval pipelines where content may be transformed before it is acted on.

ICLR 2026Invisible Safety Threat
Invisible Safety Threat studies stegotext interactions: messages that are classified as safe before decoding but become unsafe after the hidden content is decoded. The reported result is stark because it shows a complete monitoring blind spot. The visible text can pass the classifier while the actual instruction stream remains dangerous. The broader lesson is that safety checks have to reason about transformations and hidden channels, not only raw surface strings.

2. Internal representations can reveal risk earlier than text

activation monitoring

The second risk points in the other direction. Sometimes the surface text is too late or too easy to disguise, while the model's internal state already carries evidence that the behavior is harmful. Activation-level monitoring treats safety as a property of computation inside the model, not just the final message.

ICML 2026Trojan-Speak
Trojan-Speak finds that activation probes can detect harmful internal representations even when surface classifiers are bypassed. The important idea is not that probes are a complete solution; it is that the safety signal may exist before it is visible in text. For agent infrastructure, this matters because agents can route information through scratchpads, tools, and intermediate states. Monitoring only the final output misses the computation that produced it.
FIELD READ

Why this belongs beside the agent pages

The agent pages argue that tasks, observations, actions, feedback, and verifiers need a common representation. This page adds the security reason: once those fields exist, they also become places where risk can hide. A normalized agent protocol is useful for training and benchmarking, but it is also useful because it gives safety systems a structured surface to inspect.

The production implication is simple. If an agent platform cannot log and inspect intermediate messages, decoded content, tool calls, memory writes, and model-state risk signals, it cannot know what it is deploying. The risk is not only that the final answer is unsafe. The risk is that the system performs unsafe computation while every visible message looks acceptable.
