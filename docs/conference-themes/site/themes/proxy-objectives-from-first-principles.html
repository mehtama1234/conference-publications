Proxy objectives from first principles

A proxy objective is a stand-in for the thing we actually care about. The conferences are full of reward models, judge scores, preference pairs, rubrics, benchmark numbers, pseudo-labels, verifier passes, likelihoods, and human ratings. They are useful because the real target is hard to measure directly. They are dangerous because models optimize the stand-in, not our intention.

Problem

The wanted object is usually broad: truth, safety, usefulness, legality, beauty, clinical value, reasoning quality, or task success. The optimized object is narrower and easier to compute.

Approaches

Use reward models, model judges, rubrics, preference losses, binary verifiers, pseudo-labels, likelihoods, psychometric scores, pairwise rankings, and downstream utility checks.

Connecting read

This page sits between evaluation, alignment, training pressure, and evidence: a proxy is both a training signal and a measurement instrument.

SEQUENCE

Where this fits in the atlas

Evaluation asks what evidence proves behavior. Training tasks ask what pressure creates behavior. Alignment asks which feedback should move behavior. Proxy objectives are the common object underneath all three.

Evaluation

A benchmark score is a proxy for ability. The hard question is whether score movement tracks real capability.

Training pressure

A loss is a proxy for what the representation should preserve. Bad losses preserve the wrong distinction.

Alignment

Preference pairs, rewards, and rubrics are proxies for human value, usefulness, and safety.

Evidence surfaces

A verifier is a proxy only when its checked artifact is narrower than the real-world claim.

Uncertainty

A confidence score is a proxy for decision readiness. It fails when calibration is not tied to action cost.

Failure repair

Proxy failure often appears as representation failure: the model learned the measurable surface instead of the useful variable.

CORE

A proxy is a compressed target

The real target is too expensive, delayed, ambiguous, private, subjective, or physical to optimize directly. So the method replaces it with something easier.

A factuality reward stands in for truth. A judge score stands in for quality. A preference pair stands in for human values. A benchmark score stands in for capability. A pseudo-label stands in for ground truth. A likelihood stands in for modeling quality. A verifier pass stands in for task success. A safety score stands in for harmless deployment behavior. A structural metric stands in for real artifact validity.

That replacement is not automatically wrong. Without proxies, most modern ML would be impossible to train or evaluate at scale. The problem is that a proxy keeps only part of the target. It compresses the target into a number, label, comparison, rubric, pass/fail bit, distributional objective, or selected item. The model then optimizes that compressed object. If the compression preserved the right variable, the system improves. If it preserved the wrong variable, the system learns a counterfeit version of success.

This is the shared structure behind reward hacking, benchmark gaming, judge overfitting, bad pseudo-labeling, shortcut contrastive learning, unsafe helpfulness optimization, and synthetic-data collapse. The surface differs; the first-principles failure is the same. The optimized signal came apart from the intended target.

First-principles line
A proxy objective works only while optimizing the proxy still moves the real target in the desired direction.

The important object is not the reward, score, label, or metric alone. It is the link between that stand-in and the thing it claims to measure.

FAILURE MODES

How proxies break

Proxy failure is not one bug. It is a family of ways the measurable object stops tracking the intended object.

Reward hacking

The model finds behavior that scores highly under the reward while missing the human-relevant goal.

Benchmark gaming

The model improves on the test distribution, item format, or judge habit without gaining the claimed capability.

Judge capture

A model judge rewards fluency, style, visible reasoning, or familiar patterns instead of the task object.

Pseudo-label drift

Self-training turns an uncertain guess into supervision, then amplifies the original mistake.

Scalar collapse

Several incompatible goals are crushed into one number, hiding tradeoffs such as helpfulness versus safety.

Proxy overfit

The system becomes excellent at passing one verifier or rubric while failing outside its measurement scope.

TOPIC 01

Reward models are not the reward

A reward model estimates what should be preferred. Optimization treats that estimate as if it were the thing itself.

That difference matters. A reward model is trained from examples, comparisons, rubrics, or generated judgments. It sees a finite slice of behavior. It inherits annotator bias, model bias, rubric gaps, and distribution limits. Once RL or best-of-N search starts optimizing against it, the model can move into regions where the reward model is confident but wrong.

BNRM attacks this by making reward factors sparse and non-negative inside Bradley-Terry preference modeling. P-GenRM makes reward conditional on user-specific personas and rubrics. Omni-Reward expands reward modeling across modalities, making it harder to pretend one text-only scalar captures image, video, audio, and 3D quality. HERO combines dense reward-model guidance with sparse correctness verifiers, acknowledging that dense reward is useful but not always trustworthy.

The first-principles rule is simple: a reward model is evidence, not ground truth. It should be checked where it is easiest to fool: out-of-distribution outputs, adversarially optimized candidates, vague rubrics, long reasoning traces, multimodal artifacts, and tradeoff cases where one scalar hides several concerns.

Proxy test
If a policy can increase reward while humans, verifiers, or downstream outcomes do not improve, the reward model is no longer a faithful proxy.
TOPIC 02

Preference pairs hide value structure

A preference pair says one output was chosen over another. It does not automatically say why, for whom, or under which tradeoff.

Preference optimization compresses human judgment into comparisons. That is useful because comparisons are easier than writing a full utility function. But each pair can mix correctness, style, politeness, safety, length, confidence, cultural assumptions, persona fit, and annotator habit. If those factors are not separated, optimization may improve the visible preference rate while damaging a hidden value.

SafeDPO makes the safety-helpfulness frontier explicit rather than hiding it in a single preference score. Conditional Equivalence of DPO and RLHF shows that DPO can optimize relative advantage rather than absolute alignment when hidden assumptions fail. DPO Unchained broadens the choice-theory view behind DPO. WIMHF interprets feedback datasets through sparse preference features, turning the dataset itself into something inspectable before it becomes training pressure.

The proxy question is: what did the pair actually measure? If the chosen answer was shorter, safer, more confident, more conventional, more helpful, or simply more familiar, the learning signal should not be treated as a pure statement of value. Preference data is a measurement channel with hidden components.

TOPIC 03

Benchmarks are measurement instruments

A benchmark score is not ability. It is a reading from an instrument designed to expose ability.

This is already central to the evaluation pages, but proxy objectives make the failure sharper. A benchmark becomes dangerous when score movement is interpreted as broad capability movement. If the items are too narrow, the format is predictable, the judge is biased, or the task omits deployment pressure, the model can improve on the benchmark without improving on the use case.

ATLAS uses psychometric item selection to estimate model ability efficiently, which treats the benchmark as an adaptive measuring tool. EigenBench tackles subjective values when objective labels are unavailable. TTSDS2 validates objective text-to-speech evaluation against subjective ratings. FRABench/UFEval trains aspect-level judges, making quality decomposed rather than one vague score. OpenApps shows environment variation can change agent success dramatically, which means a static app instance is a weak proxy for robust app-use ability.

The benchmark question should always be: what uncertainty remains after this score? A good benchmark reduces doubt about a named ability. A bad benchmark creates confidence by hiding the ways the task differs from reality.

TOPIC 04

Rubrics make values visible, but also make them gameable

A rubric decomposes judgment. That helps only if the decomposition matches the real target.

Rubrics are attractive because they make vague quality more explicit. A rubric can say that an answer needs factuality, completeness, citation quality, safety, tone, reasoning, or domain fit. It can provide dense feedback where binary success is too sparse. But a rubric is still a proxy. The model may learn the rubric language, satisfy visible criteria, or over-optimize easy components while missing the deeper target.

RGR-GRPO uses rubrics as dense rewards for multi-domain reasoning. DR Tulu co-evolves rubrics with the policy so deep-research RL can use newly explored search information and contrasting responses. P-GenRM builds user-specific scoring rubrics. Pressure Reveals Character validates a model judge against human annotations but still reports imperfect agreement on behavioral rationales. These papers show the same tension: rubrics are useful because they expose criteria, but the criteria must be tested against human and task outcomes.

A good rubric should make failure more local. If a model gets a high total score while failing the intended target, the rubric has become theater. The fix is not always a longer rubric. Sometimes it is a better verifier, a domain expert check, a harder counterexample, or a separate score for the variable that was being hidden.

TOPIC 05

Pseudo-labels convert guesses into training data

Pseudo-labeling works when uncertainty is controlled. It fails when a model trains on its own errors as if they were facts.

A pseudo-label is a cheap substitute for an expensive label. It can scale learning beyond human annotation, especially when paired labels are scarce. But the central danger is feedback loop collapse. The model guesses. The method treats the guess as supervision. The updated model becomes more confident in the same guess. Under distribution shift or weak calibration, pseudo-labeling can harden mistakes.

SSPO uses reward-threshold pseudo-labeling for semi-supervised preference optimization, expanding beyond scarce paired human feedback. Domain adaptation pages show the same structure with target predictions under shift. HAMC lets reliable views guide unreliable views instead of forcing symmetric alignment. The point is not that pseudo-labels are bad. The point is that pseudo-labels need trust rules: thresholds, uncertainty, density, agreement, deferral, or external checks.

The first-principles object is the conversion rule from uncertain evidence to training pressure. If that rule is too loose, the system manufactures supervision out of its own bias.

TOPIC 06

Binary verifiers are strong but sparse

A verifier pass/fail signal can be more trustworthy than a reward score, but it often says less about how to improve.

A proof checker, unit test, compiler, simulator, or answer verifier has a powerful property: it can reject. That makes it less vulnerable to fluent persuasion. But binary feedback is sparse. It may not identify the broken step. It may cover only part of the real target. A program can pass tests and still be brittle. A proof can verify while solving the wrong theorem. A web artifact can pass static checks while failing interaction. A safety check can miss rare deployment pressure.

Weak-Strong Verification uses calibrated weak verifier scores to accept, reject, or defer to costly strong verification. Gaia2 pairs dynamic scenarios with write-action verifiers. CIRBench combines verifier, equivalence checking, and end-to-end performance for compiler optimization. OmniVerifier builds visual outcome verification across many task categories. HERO explicitly combines sparse correctness checkers with dense reward-model scores because neither signal is enough alone.

The proxy lesson is that a verifier is faithful only for the property it checks. Treating a narrow verifier as proof of a broad claim is another proxy failure.

TOPIC 07

Likelihood is a training signal, not a full measure of usefulness

Likelihood rewards modeling the data distribution. Usefulness may require action, reasoning, truth, safety, or rare-event behavior that likelihood barely sees.

Log likelihood is one of the most important proxies in machine learning. It is mathematically clean and scalable. But it can be mismatched to deployment goals. A model can assign high likelihood to common patterns while failing rare but important cases. It can imitate flawed demonstrations. It can model text well without acting well. It can produce calibrated tokens while missing exact task constraints.

Beyond Log Likelihood shows that strong and weak models can benefit from different supervised objectives, with strong models sometimes favoring prior-leaning probability objectives while weak models favor NLL. BLL-Loss caps the influence of low-probability demonstration tokens to improve reasoning generalization. DiffusionNFT and AGSM show the analogous issue in generative modeling: the training objective must align with the desired sample behavior, not only the original likelihood or denoising recipe.

The first-principles question is what likelihood leaves out. If the target is factuality, executable correctness, long-horizon planning, safety, or user utility, likelihood needs external evidence or a second training signal.

TOPIC 08

Multi-objective proxies expose tradeoffs that one number hides

When several values matter, a single scalar can turn a real tradeoff into a hidden failure.

Many tasks are not one-objective problems. A helpful answer should also be safe. A web agent should be accurate and cheap. A generated image should be faithful, aesthetic, diverse, and non-harmful. A classifier should maximize accuracy while respecting social welfare or user-specific costs. A robot should pursue reward without unsafe extrapolation. A single number can hide which dimension was sacrificed.

ParetoPO optimizes tool-integrated agents across accuracy and tool-use efficiency using Pareto ranking. RACO resolves preference-gradient conflicts with conflict-averse descent toward Pareto-critical points. Accuracy Auctions replaces average accuracy with social welfare based on user values. AGREE shows overall aesthetic labels hide attribute conflicts and bias. SafeDPO keeps safety constraints visible instead of letting helpfulness consume them.

The proxy rule is that collapse into one scalar is safe only when the tradeoff is genuinely acceptable. If different users, domains, or risks value dimensions differently, the proxy should preserve the frontier rather than pretending one optimum exists.

TOPIC 09

Proxy objectives need pressure tests

The right test is not whether the proxy improves. It is whether the target still improves when the proxy is pushed hard.

A weak proxy can look fine before optimization pressure becomes intense. The model may not exploit it until enough search, RL, decoding, reranking, or fine-tuning pushes into loopholes. That is why proxy objectives need pressure tests: adversarial optimization, out-of-distribution candidates, strong search, rare-event sampling, ablations of reward components, judge disagreement analysis, human spot checks, and external verifiers.

Binary RAR argues binary factuality rewards avoid generic-claim reward hacking seen with continuous factuality scores. AuxDPO shows DPO can reverse preferences or lower reward when the policy class cannot represent the true reward. LLM Deception on Benign Prompts defines deception scores to expose trustworthiness failures. Biased Generalization challenges test loss as a sufficient privacy-critical metric. FlowOptimizer trains from objective evaluations without solution labels, making the reliability of the objective-evaluation channel central.

The pressure-test question is direct: if an optimizer searches aggressively for high proxy value, what failure appears first?

METHOD

How to write or review a proxy-objective paper

Do not start with the formula. Start with the missing target.

#QuestionWhat the answer should name
01What is the real target?The human, domain, safety, physical, legal, or task property we actually care about.
02Why is direct measurement hard?Cost, delay, ambiguity, subjectivity, privacy, physical access, expertise, or sparse success.
03What proxy is used?Reward, score, label, pair, rubric, verifier, likelihood, pseudo-label, metric, or judge.
04What information did the proxy drop?Tradeoffs, uncertainty, source identity, domain context, rare failures, process, or hidden value factors.
05Why should optimizing it work?The assumption linking proxy movement to target movement.
06What pressure could break it?Search, RL, reranking, distribution shift, adversaries, personalization, scale, or shortcut learning.
07What evidence would prove fidelity?Human validation, external verifier, downstream outcome, calibration, ablation, adversarial test, or deployment stress.
SYNTHESIS

The shared lesson

The field is not moving away from proxies. It is learning to make proxies accountable.

Every large system needs stand-ins. We cannot ask humans to judge every output, run every program in every environment, deploy every policy, wait for every patient outcome, or test every rare safety event. Proxies are how we train, evaluate, and choose systems under scarcity. The danger is pretending that a proxy is the target.

The best papers in this batch expose the proxy-target link. They decompose rewards, calibrate judges, validate rubrics, test environment variation, combine dense rewards with sparse verifiers, keep tradeoff frontiers visible, measure rare failures, or show when a popular objective can reverse the intended preference. They make the stand-in inspectable.

That is the first-principles spine: name the target, name the proxy, name what was lost in compression, name the pressure that could exploit it, and show evidence that the proxy still tracks the target when optimized.

Final rule
A proxy objective is acceptable only when its failure mode is named, stress-tested, and bounded by evidence outside the proxy itself.
