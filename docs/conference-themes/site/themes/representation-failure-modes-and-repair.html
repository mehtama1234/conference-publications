Representation failure modes and repair

A representation fails when it preserves the wrong differences, removes the right differences, or cannot compose small facts into the larger thing the task needs. The papers under this theme are not all solving the same benchmark. They are solving the same deeper problem: how to notice what broke in the learned representation and apply the right repair pressure.

Problem

Models often fail because the representation kept the wrong object, blurred a needed boundary, reacted to harmless variation, or lost the structure needed for later action.

Approaches

Change the unit, add contrast, add invariance, reconstruct missing detail, predict future state, force composition, add domain constraints, change the curriculum, use teachers, or prevent collapse.

Connecting read

This page follows evaluation, training pressure, data curriculum, and adaptation: it asks what to do once those mechanisms still produce the wrong internal structure.

CORE

What it means for a representation to break

A broken representation is not simply a low score. The score is evidence. The failure is the mismatch between what the model kept internally and what the use case needed it to keep.

A model can fail even when the input is clean, the architecture is strong, and the training loss went down. It can represent the wrong unit: a subword when the task needs a full name, a patch when the task needs an object boundary, a frame when the task needs an action phase, a diagnosis label when the task needs a hidden patient state. It can learn the wrong invariance: treating two legal clauses, two drugs, two diseases, two objects, or two code paths as interchangeable because they look similar. It can learn the wrong sensitivity: changing its answer when lighting, paraphrase, file formatting, scanner type, or camera angle changes even though the decision should remain stable.

The important move is to stop saying only "the model failed" and start naming the representation failure. Did it merge two things that needed to stay separate? Did it separate two harmless variants that should have stayed together? Did it keep surface evidence but lose the state? Did it know local pieces but fail to compose them? Did it collapse into a generic reasoning trace, repeated generation loop, dead dimension, or dominant shortcut? Each failure implies a different repair.

This is why this topic naturally follows the previous pages. Evaluation discovers the behavioral symptom. Training tasks explain which pressure created the internal structure. Data curriculum explains which examples were available to shape it. Adaptation explains how the model changes later. Failure-and-repair ties these together by asking what internal promise was broken and what pressure can repair it without damaging what still works.

First-principles line
A representation breaks when the model keeps the wrong differences, throws away the right differences, or cannot build the larger object that the downstream task actually uses.
MAP

The failure-to-repair table

The repair should match the break. Better data alone is not enough if the unit is wrong. A bigger model is not enough if the evaluation lets a shortcut pass. A stronger teacher is not enough if the teacher preserves the same mistake.

TOPIC 01

Wrong unit: repair starts by changing the object

If the unit is wrong, the model is asked to preserve the wrong thing from the start.

A model can be given the right data but the wrong unit. In language, a token or subword may be convenient for pretraining but unsafe for exact names, drug strings, code identifiers, math expressions, and rare morphology. In vision, patches may be convenient for a transformer but weak for object boundaries, table cells, lesions, faces, street signs, or part-whole relations. In video, single frames can preserve appearance while missing action phase. In medicine, individual lab values can miss the patient state that only appears across visits, symptoms, medications, and thresholds. In graphs, a node label can miss the local structure that gives the node its role.

The repair is not simply to make the representation bigger. The repair is to choose a unit that matches the use case. Sometimes that means going smaller: characters for exact strings, pixels for masks, short temporal windows for falls, fine-grained events for clinical timelines. Sometimes it means going larger: claims instead of sentences, objects instead of patches, clips instead of frames, visits instead of labs, graph neighborhoods instead of isolated nodes. Often it means keeping more than one level alive at once.

The papers in the repo give several versions of this. TokSuite and Incremental BPE make token boundaries visible as an object of study rather than treating vocabulary as a preprocessing detail. Mind-Omni gives fMRI a discrete brain-token interface before it joins image and language tasks. Protein Autoregressive Modeling uses multiscale biological structure rather than flat coordinate prediction. Risk Hypergraphs represents medical risk through interacting disease subsets instead of independent labels. VERINA separates code, specification, and proof so executable correctness is not collapsed into code-shaped text.

Repair principle
Change the unit when the current representation cannot preserve the answer-changing boundary: exact string, object, event, graph role, proof object, patient state, molecule part, or action phase.
TOPIC 02

Wrong contrast: repair by making the boundary visible

Contrast repairs confusion. It teaches the model which two things must stay different even if they look similar.

Many failures are not caused by missing information. They are caused by information being too close together internally. Two drug names look similar. Two legal clauses share surface wording but imply different obligations. Two images share background and color but contain different objects. Two code snippets look nearly identical but one has a race condition. Two patients share symptoms but have different risk because of age, medication, or history. A representation fails when it does not reserve space for the distinction.

The repair is to add contrast at the point of confusion. Hard negatives are useful because they make cheap cues fail. Pairwise ranking is useful because it asks which candidate is better, not whether one candidate sounds plausible. Adversarial examples are useful when they change exactly the feature the model was ignoring. Retrieval distractors are useful because they force the model to separate related from relevant. Contrastive grounding is useful when it ties the answer to the evidence that should control it.

The repo already has this pattern. VC-STaR uses contrastive visual reasoning examples to force attention to deciding visual evidence. HyperDepth repairs semantic flattening in hypergraph contrastive learning by balancing local uniformity with global hierarchy. Difficult Examples Hurt Unsupervised Contrastive Learning warns that hard examples are not automatically good; if the hard example changes the wrong property, it can damage the representation. MF-GIA aligns graph support evidence under realistic access constraints. UniImb protects minority graph structure from being washed out by majority patterns. VALUEFLOW and AdAEM show the alignment version: value differences need probes and intensity measures, not only broad preference labels.

Repair principle
Add contrast when the model merges things that deployment needs to keep separate; choose the contrast around the reason the answer changes, not around superficial difference.
TOPIC 03

Wrong invariance: repair by saying what may safely vary

A useful representation is not sensitive to every difference in the input. It is sensitive to differences that change the answer.

Wrong invariance has two sides. The model may fail to ignore harmless changes: lighting, paraphrase, scanner type, camera angle, file format, UI layout, speech accent, or background texture. Or it may ignore harmful changes: a small token difference in a medication, a changed operator in code, a new edge in a graph, a shifted threshold in a lab value, or a one-frame event in a safety video. The repair is to define what should stay the same across change and what must remain different.

Data augmentation can teach invariance when the augmentation matches harmless variation. Consistency training can keep predictions stable across views. Teacher-student targets can preserve stable behavior while the student sees noisy inputs. Cross-modal bridges can make different instruments agree on the same hidden state. Source-free adaptation can adjust to a shifted domain without needing the original source data. But each repair depends on choosing the allowed variation carefully. A random augmentation is not a principle; it is a bet that the change is harmless.

BioX-Bridge is a good anchor because it aligns physiological representations across biosignal modalities through lightweight bridges. Self-Soupervision and DDG-SFDA Regression address shifted distributions and pseudo-label refinement. Source Screening shows that discarding sources can improve shared subspace estimation when the source does not support the target invariance. LIMSSR handles incomplete multimodal action-quality evidence while calibrating hallucination risk. Together these papers say that invariance is a domain promise, not a generic smoothing trick.

Repair principle
Add invariance when harmless surface changes are distracting the model, but keep exact distinctions alive wherever a small change changes the decision.
TOPIC 04

Lost detail: repair with reconstruction and decision-aware compression

Compression is only useful if the compressed representation keeps the details the later system will need.

A model can fail because it compressed away the evidence. This is common in exact domains. OCR needs exact letters, not just document topic. Code needs syntax and execution behavior, not just intent. Math needs variable identity and proof steps, not just a plausible answer. Medicine needs lab thresholds and patient-specific baselines, not just broad diagnosis names. Vision segmentation needs boundaries. Retrieval may need a specific clause, not the surrounding page theme. Compression can look successful while quietly deleting the detail that determines the action.

Reconstruction is one repair, but it has to reconstruct the right thing. Pixel-perfect rebuilding may waste capacity if the task is classification under harmless lighting variation. But exact field reconstruction matters for forms, table cells, names, medical values, code snippets, and legal documents. Rate-distortion thinking is useful because it forces the question: under a fixed budget, which errors are acceptable and which are unacceptable? A representation should spend capacity on costly mistakes, not on every surface detail equally.

The repo has several anchors. Cross-Domain OT Compression makes compression answer to target-domain decision value rather than only source reconstruction. Hallucination Rate-Distortion frames random factual hallucination as lossy storage and retrieval of sparse facts. Error Propagation in Quantized Diffusion Models shows that small per-step numerical errors accumulate along the denoising path. ThinKV asks which key-value cache information can be discarded without losing rare clues. LiftQuant, TetraJet, and FOCUS/RePAIR show the systems version: low-bit or pruned models can preserve ordinary metrics while damaging stability, repetition, or reasoning quality.

Repair principle
Use reconstruction or compression constraints when the representation loses details whose action cost is high: exact strings, syntax, thresholds, boundaries, rare facts, or target-domain decision evidence.
TOPIC 05

Missing dynamics: repair by predicting what comes next

A representation of the present is weak if it does not preserve the variables that control the future.

Static recognition is often not enough. A video model can classify frames but miss the transition from standing to falling. A patient model can read visits but miss disease progression. A robot can recognize objects but fail to predict the consequence of motion. A reasoning model can produce a plausible current step but drift over a long chain. A physical surrogate can match one state but accumulate high-frequency error over many iterations. In these cases the missing object is state over time.

The repair is prediction pressure. Future-frame, next-state, trajectory, event, and world-model objectives force the representation to keep what matters later. But prediction is only deep when the future target requires real structure. Predicting a blurred next frame may not teach object persistence. Predicting the next token may not teach causal evidence. Predicting the next patient code may not preserve uncertainty or treatment effects. The task has to expose the future dependency that the use case will rely on.

IRNO treats neural operators as learned fixed-point solvers with iterative residual correction, directly addressing accumulated surrogate error. HDFlow splits robot planning into high-level latent subgoals and low-level trajectories. Hawkes Representer Theorem turns temporal triggering into a finite inference problem. h1 composes short tasks into longer dependency chains so long-horizon reasoning gets a learnable path. Thinking in Flow treats reasoning as a trajectory that can drift and needs selective correction. dWorldEval, ROCP, TESS, LaST0, and WestWorld all make prediction operational: the representation is judged by the later decision or action it supports.

Repair principle
Add prediction pressure when the model sees the current evidence but loses the variables that determine future action, risk, motion, event timing, or reasoning stability.
TOPIC 06

Missing composition: repair by teaching how parts become wholes

A model can know the pieces and still fail because it does not know how the pieces make a larger object.

Composition failure appears everywhere. A language model may know words but not claims. A retrieval system may know passages but not evidence chains. A code model may know syntax but not program behavior. A vision model may know patches but not objects and relations. A video model may know frames but not events. A theorem model may know local proof moves but not the proof strategy. A medical model may know symptoms and lab values but not a disease pathway. In each case the representation lacks the rule for building the larger thing.

The repair is to add structure that makes composition learnable. Hierarchical models keep multiple levels alive. Graph models represent relations directly. Step supervision makes intermediate moves visible. Program execution and proof checking make composition accountable. Curriculum can start with small compositions and move toward longer dependency chains. Object-relation modeling can bind parts into scenes. Domain constraints can stop invalid wholes from passing as plausible.

h1 is a clear example: it bootstraps long-horizon reasoning by composing short tasks into dependency chains. Power Law Compositional Reasoning explains how frequent compositions can support rarer ones. Grammar Substructure analyzes language-modeling loss through reusable grammar parts. Transformer Circuits Can Realize Clustering Algorithms maps transformer components onto assignment, aggregation, update, and iteration. Protein Autoregressive Modeling builds biological structure through coarse-to-fine generation. VERINA and THOR show the code/math version: local steps have to survive executable or tool-backed checks.

Repair principle
Add composition pressure when local units are correct but the larger claim, scene, event, proof, program, molecule, plan, or patient trajectory is wrong.
TOPIC 07

Invalid domain state: repair with constraints and external checks

A representation can be statistically plausible and still invalid in the world where it will be used.

Some failures are not visible from surface similarity. A generated program can look reasonable and fail tests. A legal answer can sound confident and ignore jurisdiction or source eligibility. A medical recommendation can follow a pattern and miss a contraindication. A physical model can produce smooth outputs that violate conservation, symmetry, or boundary conditions. A robot plan can look coherent in language and be impossible under contact or kinematics. In these settings the representation must respect a domain state, not merely a distribution of examples.

The repair is to add an external check or domain constraint. Executable tests, simulators, verifiers, ontologies, symbolic rules, constrained decoding, and decision-aware prediction sets all change the pressure. They say that plausible is not enough. The output has to pass the condition that defines validity in the domain. This is why evaluation and repair are tightly linked: once the benchmark is artifact-native, the repair has a target that is closer to real use.

CyberGym, SandboxEscapeBench, DRPBench, and Copyright-Bench make this vivid. CyberGym evaluates whether security agents can exploit, patch, or validate state changes rather than describe vulnerabilities. SandboxEscapeBench makes sandbox escape a reachability problem. DRPBench tests concurrent-code semantics through data-race prediction. Copyright-Bench tests legal compliance as workflow behavior under user pressure. ROCP and CRC treat prediction sets as decision objects rather than coverage statistics alone. These papers repair shallow representation by tying success to the world condition the user cares about.

Repair principle
Add constraints when fluent, plausible, or high-scoring behavior can still violate the domain object: executable correctness, physical validity, legal eligibility, clinical safety, or decision robustness.
TOPIC 08

Bad curriculum: repair by changing which evidence arrives when

Some representations break because the right evidence was missing, mistimed, overpowered, or surrounded by examples that taught a shortcut.

Data is not a pile. It is a sequence of pressures. An example can be useful before the representation settles and useless afterward. A rare case can be ignored if common examples dominate. A hard example can teach the right boundary or inject noise depending on when it arrives and what the model already knows. Repair data can fix a failure mode or overfit the model to the failure set. Curriculum is therefore a repair mechanism, not only a training convenience.

The repair is to choose data by effect, not by static desirability. Hard-example mining helps when the hard case exposes a real boundary. Coverage balancing helps when the model misses rare distinctions. Sequential selection helps when the value of one example depends on what has already been selected. Midtraining helps when the model needs an intermediate state before reward or specialization can land. Replay helps when new updates would erase old structure. Source screening helps when some sources harm the shared target subspace.

Sequential Data Values formalizes the value of examples under sequence. OPUS scores documents by effective update direction relative to a target. DiReCT selects late-training data through curvature-aware gradient alignment. Midtraining Bridges and PRISM show that the training stage itself changes whether later RL is stable. LR Decay Wastes Your Best Data shows that late high-quality data can be underweighted by standard schedules. Source Screening shows that dropping unhelpful sources can improve transfer. The deeper message is that a representation can break because the training path gave it the wrong pressures in the wrong order.

Repair principle
Change curriculum when the model has the capacity to learn the right distinction but the training path failed to expose, repeat, time, or protect that distinction.
TOPIC 09

Unstable targets: repair with teachers, verifiers, and decomposed feedback

A model only learns what the target signal can express. If the target is noisy, sparse, or misspecified, the representation inherits that weakness.

Teacher-student training is not just compression from a large model to a small one. It is a choice about what the student should inherit. A teacher can provide labels, traces, preferences, dense rewards, step-level judgments, grounded checks, or behavior anchors. That can stabilize learning when raw labels are noisy or sparse. But a teacher can also transfer bias, overconfidence, shallow reasoning style, or domain mistakes. The repair only works if the teacher signal exposes the structure the student needs.

Verifier-guided learning gives a stronger target when the domain has checkable consequences. Process rewards give credit to intermediate steps. Preference decomposition can make hidden values visible. Self-teaching can reduce forgetting by anchoring behavior the model already demonstrates. Ensembles can smooth noise, but they can also hide systematic errors if all teachers share the same shortcut. The question is always: what does the target make easy to preserve?

HERO combines sparse correctness checkers with dense reward-model scores for reasoning post-training. MoCA separates perception verification and structured verbal checks in multimodal reasoning. LALP selects teacher traces by transferable local step transitions. SDFT uses demonstration-conditioned in-context behavior as a self-teacher to reduce forgetting. BNRM makes reward factors more interpretable. VALUEFLOW measures value intensity. SVGT separates normative value representations from general generation through bridge tokens. These papers all treat the target as a representation-shaping object, not a passive label.

Repair principle
Use teacher or verifier targets when raw supervision cannot express the needed behavior, but inspect what the target itself preserves, hides, or encourages the student to exploit.
TOPIC 10

Collapse: repair by keeping useful diversity alive

Collapse happens when the representation becomes too uniform: the model still produces outputs, but the outputs carry less task-specific information.

Collapse is dangerous because ordinary metrics can miss it. A model may keep similar accuracy while becoming repetitive. A reasoning model may produce long fluent traces that no longer depend on the input. A sparse code may stop using dimensions. A cluster model may create dead clusters. A reward-driven generator may find one attack pattern and repeat it. A pruned model may preserve perplexity while increasing loop-entry or loop-persistence risk. Collapse means the representation has lost useful distinctions even if the surface remains acceptable.

The repair is to keep useful diversity, not random variation. Entropy can help when the model needs exploration, but too much entropy can block convergence. Variance and decorrelation can keep dimensions active, but internal geometry must still connect to behavior. Negative samples can keep examples apart, but wrong negatives can damage structure. Balanced clustering can avoid dead clusters, but only if clusters map to useful states. Loop repair can add escape probability, but it should preserve fluent generation. The objective is not diversity for its own sake. It is diversity that preserves possible correct behaviors.

RAGEN-2 names template collapse in multi-turn agent RL and uses a mutual-information proxy to check whether reasoning remains input-dependent. FOCUS & RePAIR decomposes pruning-induced repetition into loop-entry and loop-persistence risk. Stable-GFN reduces mode collapse in reward-driven red-team generation. RLVepsR separates convergence slowdown from collapse in reasoning modes. Entropy Control switches between entropy maximization and minimization depending on positive-negative divergence. Isotropic Gaussian RL reduces neuron dormancy and representation collapse by encouraging balanced dimension use. These papers make collapse measurable and repairable rather than mysterious.

Repair principle
Prevent collapse when the model's internal or behavioral variety is shrinking in a way that removes task information, rare modes, active dimensions, or input-dependent reasoning.

SYNTHESIS

How to decide the repair

The right repair is chosen by the failure, not by the modality. The same repair family appears in language, vision, video, graphs, code, medicine, science, robotics, and agents because the same conceptual breaks repeat.

If the model confuses two near-neighbor cases, add contrast. If it changes under harmless variation, add invariance. If it loses exact information, add reconstruction or decision-aware compression. If it cannot act over time, add prediction. If it knows pieces but not the whole, add composition pressure. If it sounds plausible but violates the world, add external checks. If the right examples were absent or mistimed, repair the curriculum. If the target is weak, repair the teacher or verifier signal. If the internal state becomes too uniform, add collapse prevention. If none of these work, revisit the unit.

This gives a useful writing structure for every paper under the theme. Start with the behavioral symptom, then identify the representation failure, then explain the repair pressure. A paper summary becomes much deeper when it says: this method repairs lost exactness, this one repairs temporal state, this one repairs value-boundary confusion, this one repairs shortcut evaluation, this one repairs collapse under reward pressure. The point is not to force all papers into one vocabulary. The point is to make their common engineering logic visible.

Closing line
A repair is good when it makes the model preserve exactly the information whose absence caused the failure, while leaving harmless variation cheap and already-useful behavior intact.
