CORE

The useful object is the constraint

A theory paper should be read by asking what it makes impossible, expensive, identifiable, or stable.

Some results name a sample bottleneck. Language Generation in the Limit separates computable generation from feasible learning: a class can be possible in principle and still require too many examples. Alignment-Sensitive Minimax Rates names an information bottleneck: risk depends on how target signal lines up with observed directions. Matroid Algorithms names a cost bottleneck hidden by an oracle model: a large query is not the same as a small query.

Other results name memory, privacy, or parameterization bottlenecks. Secret Memory Lower Bounds shows privacy can force extra streaming space. Single-Head Attention in High Dimensions ties generalization to spectral recovery in query-key matrices. LoRA Gradient Descent asks whether the low-rank parameterization used in practice can actually converge. In each case, the theorem is valuable because it names the object that blocks an easy story.

Core rule
Read theory by naming the bottleneck first: data, dimension, spectrum, memory, privacy, oracle cost, or optimization geometry.
FIRST PRINCIPLE

A theorem is useful when it explains what must be paid

Theory matters when it names a constraint that methods cannot wish away.

A result can be elegant and still not guide practice. The useful question is what the theorem makes visible: a sample cost, memory cost, privacy cost, dimension boundary, oracle cost, spectral recovery condition, alignment condition, or optimization barrier. Once that object is named, method design becomes clearer because the paper says what has to be measured or paid for.

The first-principles difference is between abstraction that clarifies and abstraction that hides. A clean oracle model can hide real query size. A formal learnability result can hide impossible sample demand. A convergence proof can hide the fact that the parameterization used in deployment is different. A good theory paper states its world and tells us what bottleneck survives inside that world.

First-principles test
Ask what scarce object the theorem isolates, which assumption creates the boundary, and what design choice changes because of it.

METHOD

Why assumptions are part of the result

A theorem is not a slogan once its assumptions are removed.

The result lives inside a model of the world. That model may simplify data, computation, privacy, oracle access, optimization, or architecture. The simplification is not a flaw by itself. It becomes a flaw when the conclusion is exported without the boundary. Useful theory makes the boundary readable.

The method for reading these papers is to translate the proof into a practical sentence: if this assumption holds, this resource must scale this way, because this mechanism blocks an easier route. That sentence lets the atlas connect theory to systems, compression, privacy, low-rank adaptation, and evaluation.

FAILURE MAP

How theory becomes decorative

Boundary erased

A narrow theorem is quoted as if it covered deployment.

Cost model fantasy

The proof charges for an abstraction that hides real work.

Rate without object

The result gives a bound but not the mechanism causing it.

Wrong parameterization

The proof studies a clean model instead of the update rule actually used.

Privacy free lunch

The guarantee ignores the memory or sample cost needed to make it true.

Geometry slogan

Spectral language is used without tying modes to behavior.

CONNECTION

Why this idea cuts across the atlas

Theory gives the atlas its hard edges.

Spectra and rank show where geometry becomes a bottleneck. Privacy and unlearning need formal bounds because recovery claims are hard to prove by examples alone. Efficiency needs theory when resource models decide which computation exists. Compression needs limits on what can be removed.

It also keeps first-principles writing honest. If a theme page claims a method works because of alignment, rank, privacy, samples, memory, or optimization, the theory page asks what those words cost in a real bound or failure mode.

A good reading question for any theory paper is: what would a practitioner stop doing, start measuring, or pay for differently after understanding the theorem? If nothing changes, the result may be mathematically valid but it has not yet become an atlas concept.

The deeper point is that good theory does not float above practice. It names the thing practice cannot escape.
