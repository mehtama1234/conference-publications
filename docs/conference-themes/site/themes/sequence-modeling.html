Problem

Sequence models often pass short benchmarks while failing when length, state, or grammar changes. The real question is whether the architecture learned an algorithm or only a finite pattern.

Approaches

The papers analyze masked diffusion reasoning, relative positional encodings, rational recurrence, output reachability, state-space recurrence, and quantitative length-generalization bounds.

Connecting read

This page connects architecture to computational power: order, recurrence, position, and state determine which sequence problems a model can solve efficiently.

READ

The Big Picture

Sequence modeling is not just predicting the next token. A sequence model is a machine that must store state, update that state, retrieve older information, and generalize from short examples to longer ones. The difficulty is that many architectures can imitate a finite training length without learning the underlying rule. This matters for language, code, planning, and reasoning because the test case often differs from the training case by length, nesting depth, or required memory.

The papers here ask what architectural ingredients change that story. Relative position can expand what softmax chain-of-thought transformers can compute. Rational recurrence can close regular-language gaps while preserving parallel training. Masked diffusion can reason faster than chain-of-thought transformers on some regular-language classes because it does not have to reveal every intermediate step serially. State-space models can be designed around inference-first state tracking. The shared point is that sequence modeling quality depends on the computation path, not only on loss.

CORE

Order is not the same as state

A sequence gives the model an order. A sequence task gives the model a state update problem.

This distinction is the simplest way to read the papers. The tokens arrive in some order, but the answer often depends on a hidden variable that must be updated as the sequence unfolds: a stack depth, finite-automaton state, retrieval target, parity bit, counter, latent memory, or set of unresolved constraints. A model can fit many short examples by memorizing local patterns in the ordered tokens. It has learned the task more deeply only when it has learned the state transition that should repeat at new lengths.

That is why length generalization is not just "testing on longer strings." It is a test of whether the internal computation is reusable. If the model's state after 50 tokens can be simulated from the state after 10 tokens by applying the same rule, the task has a chance to extrapolate. If the model depends on positions, examples, or attention patterns that only existed inside the training length, longer tests reveal that the rule was never learned.

TOPIC 01

State is the thing the future depends on

A sequence model does not need to remember everything. It needs to preserve exactly the information that changes what should happen next.

This is the first-principles object behind the page. In a finite automaton, the state is the small label that tells you which transitions are legal next. In retrieval, the state is the unresolved query and the evidence already seen. In code or formal language tasks, the state may be a nesting depth, a symbol table, or a pending obligation. In long generation, the state is the constraint that must survive while many tokens are emitted.

The architectural question is therefore not "does the model have a long context?" but "where does the relevant state live, how is it updated, and what makes it survive?" Attention can look back at many tokens, but it may recompute the wrong summary. A state-space model compresses history into a recurrent state, but that compression can drop the decisive token. A chain-of-thought transformer can externalize state into generated tokens, but then reasoning cost grows with the written path. A masked diffusion model can update many positions together, but then hidden states must coordinate without a serial public trace.

TOPIC 02

Position can be a computational resource

Position is not only a label for where a token appears. It can supply the model with the coordinate system needed to run an algorithm.

Softmax Turing is important because it treats relative position as part of the machine, not as formatting. If a model must recognize a language, simulate a repeated transition, or move information across a sequence, it needs to know relations such as "the previous symbol," "the matching symbol," "the next step in the trace," or "the same offset at a larger length." Absolute position can let a model memorize that something happens near index 17. Relative position helps describe a reusable move that can be applied at index 17, 170, or 1700.

This also explains why length extrapolation is fragile. A model can achieve low loss by tying behavior to the training coordinate range. It sees enough examples to act correctly inside that range, but it has not learned a position-independent transition. The useful evidence is not a slightly longer benchmark alone. It is evidence that the same positional rule controls the computation after the training positions have been left behind.

TOPIC 03

Recurrence is a promise about what history becomes

A recurrent model turns the past into a compact state. The promise is efficiency; the danger is irreversible loss.

Rational Transductors and Mamba-3 sit on this tradeoff. A recurrence can implement repeated state transitions cleanly, which is exactly what regular languages, streaming retrieval, and long traces often require. It can also be trained or executed efficiently because the model is not always attending to the full visible history in the same way. But the compression is only useful if the right information survives. If the state merges two histories that require different future actions, the model has already lost the task.

That gives a simple test for recurrent sequence methods. Ask which histories the model treats as equivalent. If two histories lead to the same compressed state, then the model is claiming that no future continuation will need to distinguish them. This is fine when the merged histories really are equivalent under the task rule. It is a failure when the merged histories differ by the one old fact that a future token will ask for.

TOPIC 04

Parallel reasoning changes the bottleneck

Chain-of-thought makes hidden work visible, but it also forces reasoning through a serial text channel.

MDM Reasoning is useful because it asks when a masked diffusion process can solve a sequence problem by refining many unknown positions at once. The contrast is not simply "diffusion versus transformer." It is serial public computation versus parallel hidden refinement. A chain-of-thought model writes one reasoning token after another, so some computations pay for every intermediate step in the output stream. A masked diffusion model can update multiple positions in the same refinement round, which can be a better match for tasks where constraints propagate across the sequence in parallel.

The failure boundary is coordination. Parallel updates are powerful only if local changes settle into a globally valid sequence. If different positions update using incompatible partial beliefs, the final output can look coherent locally while violating the language rule. So the evidence has to measure both speed and correctness under rules that require global consistency.

TOPIC 05

Reachability is different from intelligence

A model may have enough compute to continue generating while still being unable to reach the required kind of output from the prompt.

Transformer Outputs makes this limitation explicit. The question is not whether generation can continue indefinitely in a mechanical sense. The question is which output lengths and structures are accessible from the information in the prompt under the model's generation process. If accessible length grows only linearly with prompt length, then unbounded compute does not remove the dependency on the initial prompt. More sampling steps cannot create arbitrary reachable structure if the generation process itself restricts what can be reached.

This matters for long-form writing, code generation, planning traces, and video or action sequences. A long output is not evidence that the model controlled a long-horizon object. The model has to preserve the original constraint, keep producing compatible pieces, and avoid drifting into a region that is merely fluent. Evidence should therefore ask what outputs are reachable, not just how many tokens can be emitted.

EVIDENCE

What would prove a sequence method learned the rule

The proof signal is not a single benchmark score. It is stress evidence that separates reusable state updates from memorized finite traces.

Length stress

Test much longer sequences than training and check whether the same rule holds rather than whether the output remains locally plausible.

Position stress

Move the decisive dependency to unseen positions and verify that relative structure, not absolute index memorization, controls the result.

State separation

Construct histories that look similar locally but require different future actions; a valid state representation must keep them apart.

Reachability analysis

Measure which lengths and structures can actually be reached from a prompt instead of assuming more compute removes the limit.

Computation path

Compare serial chain-of-thought, recurrent state, attention, and parallel refinement on tasks where the required algorithm is known.

Global consistency

For parallel generation, check that local refinements converge to a sequence satisfying the whole grammar or constraint system.

FAILURE MODES

Where sequence models overclaim

A good short-sequence score can hide several different failures.

The model may know the training length but not the rule. It may use absolute positions where the task requires relative movement. It may store a blurred summary when the task requires an exact finite state. It may generate plausible intermediate reasoning that is slower than a parallel update would be. It may pass examples where the decisive token is nearby while failing when the same dependency is moved far away. It may produce a long output while slowly drifting from the constraint that made the output correct.

The evidence that matters is therefore stress evidence: longer strings, changed positions, held-out grammars, larger retrieval gaps, tasks where accessible output length is measured directly, and comparisons between serial, recurrent, and parallel computation paths. The core question is not whether the model can continue a sequence. It is whether the continuation is controlled by the same state rule that controlled the shorter examples.

CLUSTERS

The Main Research Moves

1. Length generalization is a computational property

Length Generalization Bounds asks when long-sequence behavior can be simulated from shorter examples and turns that into quantitative training-length requirements. Transformer Outputs gives a complementary limit by showing accessible sequence length grows only linearly with prompt length even if compute is unbounded. Softmax Turing shows relative positional encoding expands softmax chain-of-thought universality from letter-bounded languages to arbitrary languages. Together these papers separate memorizing finite traces from having a mechanism that scales with length.

2. Recurrence and parallelism change the reasoning cost

Rational Transductors injects weighted-finite-automata-derived matrix recurrence into attention, closing regular-language gaps while retaining efficient parallel training. Mamba-3 moves in the state-space direction, combining richer recurrence, complex state updates, and MIMO structure for retrieval and state tracking. MDM Reasoning identifies regular-language classes where masked diffusion parallelism can reason faster than chain-of-thought transformers. These papers make clear that the same sequence task can be easy or hard depending on whether the architecture uses serial token emission, recurrent state, or parallel refinement.

CONCEPT BRIDGES

Where to read the larger pattern

Long context is memory design

Sequence models are memory systems over ordered symbols. The method must say what state is carried forward and what can be forgotten.

Theory names the bottleneck

Length generalization, automata limits, and transducer capacity matter when they identify what a sequence model cannot represent from short evidence alone.

Test-time compute is a policy

Long reasoning and generation depend on how much computation is spent after the prompt: recurrence, search, decoding, verification, and stopping.
