First-principles concept

Compression preserves or destroys capability

Compression is not just making something smaller. It is a claim about what information can be removed while the needed behavior remains possible.

CORE

The smaller object has to keep the right distinctions

A compressed model state is useful only if the task-critical information survived.

Many papers save something: bits, tokens, memory, context, latent dimensions, visual frames, cached state, or stored facts. The saving is valuable only under a preservation claim. Which comparisons still fit? Which visual cue remains? Which cross-modal relation survives? Which factual membership can still be recovered? Which numerical value keeps enough precision?

Embedding Collapse makes the point sharply: reducing dimension can make contrastive triplet relations impossible to represent. LiftQuant asks how low-bit deployment can fit hardware without wasting accuracy. FlashVID and OmniFit reduce multimodal tokens while trying to keep the evidence that long video or streaming inputs need. Hallucination Rate-Distortion treats factual error as what can happen when sparse facts are stored under limited capacity.

Core rule
Compression is valid only relative to a named behavior and a test that the behavior still works after information is removed.
FIRST PRINCIPLE

Compression is a preservation claim under a budget

Making a model smaller is useful only when the right information still survives.

Compression always has two objects. The first is the thing being reduced: bits, tokens, dimensions, layers, memory, video frames, cache entries, or stored facts. The second is the thing that must remain possible: a comparison, a visual judgment, a long-range dependency, a factual distinction, a stable numerical operation, or an action. Many failures come from reporting the first object while leaving the second vague.

The reason this is first-principles is that information cannot be removed for free. Sometimes the removed part was redundant. Sometimes it carried a rare clue. Sometimes it held geometry that only mattered under hard comparisons. Sometimes it preserved enough precision for a numerical path not to flip. A good compression paper therefore has to say what is being discarded, what distinction is protected, what budget forces the discard, and where the discard starts to break behavior.

First-principles test
State the budget, state the protected distinction, then stress the compressed system exactly where that distinction is easiest to lose.

PAPER MAP

Several kinds of smaller state

Geometry

Embedding Collapse shows that too few dimensions can force wrong comparisons even when the desired triplets are realizable in a larger space.

Bits

LiftQuant treats fractional bit width as a deployment object, trying to fit large models into real GPU memory without crude rounding.

Video tokens

FlashVID merges redundant visual tokens so long-video understanding can use more frames under fixed compute.

Modality budgets

OmniFit changes token budgets by layer and modality, with the preservation claim centered on cross-modal alignment.

Facts

Hallucination Rate-Distortion explains that limited factual storage can create false positives even without dirty data.

Reasoning tokens

ThinkV sits in the same family when visual reasoning must decide which visual tokens deserve continued attention.

METHOD

Why average accuracy is the wrong proof

Compression usually fails first at the boundary cases.

If most examples are easy, a compressed model can look healthy while losing the exact information that matters in rare, long, precise, or ambiguous cases. Average accuracy rewards the common path. Compression risk often lives in the uncommon path: a small object in a video, a rare fact in memory, a near-tie in embedding space, a long dependency in context, or a low-precision activation that flips a downstream decision.

A serious compression method therefore needs stress tests that match the claimed preservation. Geometry compression needs near-neighbor and triplet checks. Video compression needs temporal and small-cue checks. Quantization needs layer and value sensitivity. Factual compression needs false-positive and false-negative analysis. Long-context compression needs questions whose answer depends on the discarded-looking middle.

FAILURES

What cheapness can hide

Compression can fail quietly. Average task scores may stay high while rare facts are lost, small visual cues disappear, minority modes collapse, proof-critical tokens vanish, or long-range dependencies become unreachable. The model looks efficient because the evaluation did not ask for the information that was removed.

The first-principles warning is simple: the saved resource and the preserved object are different things. Saving tokens is not preserving video evidence. Saving bits is not preserving numerical behavior. Saving context is not preserving memory. Saving dimensions is not preserving geometry.

FAILURE MAP

The common ways smaller becomes worse

Rare clue loss

The removed token or frame looked redundant on average but carried the hard-case evidence.

Geometry collapse

Too few dimensions force relations that should stay separate to overlap.

Bit instability

Low precision changes a value enough to flip a later decision.

Token bottleneck

The model keeps a summary that sounds right but lacks the detail needed for the next step.

Cross-modal loss

Compression preserves each modality alone while breaking the relation between modalities.

Factual false positive

Limited storage makes the model treat an unseen or wrong fact as if it belonged.

Final rule
Never ask only how much was removed. Ask what had to remain true after the removal.
CONNECTION

Why this idea cuts across the atlas

Compression is the budget side of memory, grounding, and deployment.

Long-context memory asks what past information must remain available. Grounding asks whether the evidence path survived. Efficiency asks whether the resource limit changed the method itself. Spectral and rank views ask which subspaces carry useful distinctions and which can be removed.

The deeper unity is simple: every AI system works with a smaller internal state than the world it describes. The hard question is not whether it is smaller. The hard question is whether the right differences still fit inside it.
