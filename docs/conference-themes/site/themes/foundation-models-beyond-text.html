Problem

Outside text, the model has to bridge between domain structure and language-like interaction. A sleep signal is temporal physiology; a table is typed, relational data. Neither is naturally a chat transcript.

Approaches

The evidence covers a large sleep-text dataset for captioning and retrieval, plus inference acceleration and memory reduction for tabular foundation-model workloads.

Connecting read

This theme is about making foundation models useful where the bottleneck is not only scale, but the translation between domain-specific structure and flexible model behavior.

READ

The Big Picture

Text foundation models became powerful because text gave them a universal interface: instructions, explanations, examples, retrieval targets, and evaluations could all be written as sequences. Other domains do not come with that convenience. Sleep recordings are long physiological signals with events, rhythms, and clinical interpretation layered on top. Tables are compact structured objects where columns carry types, distributions, and relationships. Extending foundation models beyond text therefore means solving two problems at once: how to represent the domain, and how to expose useful tasks over that representation.

SleepLM addresses the representation-and-interface problem by building a sleep-text dataset over more than 100K hours and supporting captioning, retrieval, event localization, and insight generation. The point is that sleep signals become something a model can describe, search, and reason over. TACO addresses the cost side for tabular foundation models, reporting much faster inference and large memory savings on TabArena-style workloads. Together, the papers show that "foundation model beyond text" is not one trick. In some domains the missing piece is paired data that gives the model words for the signal; in others the missing piece is making the foundation-model workflow cheap enough to run at all.

CORE

Beyond text means preserving the native object first

A domain foundation model fails if it turns a sleep trace or table into generic tokens while losing the structure that made the domain useful.

Sleep recordings are measurements of hidden body states over time. The useful object is not only the waveform; it is the sleep event, timing, transition, artifact, and clinical interpretation supported by the signal. Tables are organized records. The useful object is not only a sequence of cells; it is rows, columns, types, keys, missing values, distributions, and the operations a task may require.

That is why SleepLM and TACO belong together even though they look different. SleepLM builds a language-facing interface for physiological evidence. TACO compresses tabular context while trying to preserve the operations tabular prediction needs. Both papers ask how to make non-text structure usable by foundation-model machinery without flattening away the thing that matters.

TOPIC 01

The native object comes before the model interface

A beyond-text foundation model starts by deciding what the domain object is.

For SleepLM, the object is not a paragraph about sleep. It is a long physiological recording with channels, rhythms, events, artifacts, and subject variation. For TACO, the object is not a prompt full of cell strings. It is a table with rows, columns, types, missingness, target relations, and examples that may change the prediction. The model interface is useful only if it preserves that object.

This is the core difference from ordinary text modeling. Text is already a human-facing interface. Sleep signals and tables are not. The model has to build an interface before it can behave like a foundation model.

TOPIC 02

Language is useful only when grounded in the signal

A sleep caption is not proven by sounding clinical. It is proven by pointing back to the physiological evidence.

SleepLM makes sleep data searchable and describable through captioning, retrieval, event localization, and insight generation. That is powerful because language can turn raw signals into objects people can query and inspect. But it creates a failure mode: fluent summaries can detach from the recording. A model can describe apnea-like events, sleep stages, or anomalies in confident language while missing the exact timing or channel evidence.

The first-principles rule is that language should expose the signal, not replace it. Every useful sentence should remain accountable to event timing, channel measurements, subject context, and uncertainty in the underlying physiological state.

TOPIC 03

Tabular compression must preserve decisions, not cells

The goal is not to remember every table token. The goal is to keep the information that could change the prediction.

TACO addresses a practical bottleneck in tabular foundation models: in-context examples can make inference expensive because the model carries many rows through attention. Compression is attractive, but a table is not a bag of tokens. A rare row, a missing value pattern, a column type, or a comparison between examples can be decisive.

So the proof of compression is not only speed or memory saving. The compressed latent has to preserve the row-column relations the downstream task uses. If the compressed context gives the same prediction for the right reason, the interface worked. If it works only on average while deleting rare decisive examples, it changed the task.

TOPIC 04

A token is a promise about what survives

Tokenization is not just chopping input into chunks. It decides what unit the model is allowed to reason over.

A sleep token may promise an event, a channel pattern, or a temporal segment. A table token may promise a row, column, feature type, or target relation. A video token may promise motion or object identity. A brain token may promise enough neural state to support encoding and decoding. The promise matters because the model can only reason with what the interface preserved.

This is why beyond-text work is really representation design. The model inherits the successes and failures of the chosen unit. If the unit loses timing, type, geometry, or state, the later model can be large and still answer the wrong question.

TOPIC 05

Domain-native proof is the real benchmark

A non-text model should be judged by whether the domain evidence still controls the output.

For SleepLM, that means captioning, retrieval, event localization, reconstruction, and insight generation should remain tied to sleep-signal evidence. For TACO, it means speed and memory savings should come without losing tabular decision information. Nearby beyond-text papers make the same point for video, audio, brain signals, multimodal latents, and domain judges.

The deeper principle is that foundation-model flexibility is not enough. Outside text, the benchmark has to test the native object: physiological event, table relation, video motion, audio grounding, brain state, or evaluation aspect. Otherwise the model may only be a fluent wrapper around lost evidence.

METHOD

Two routes beyond text

The first route builds a language bridge for a measured signal. The second route compresses structured context while keeping the task-relevant operations alive.

SleepLM is a measurement-interface paper. It uses sleep-text data so physiological traces can support captioning, retrieval, event localization, and insight generation. The language layer is useful only if it remains accountable to the signal. A sleep caption should point back to real timing and channel evidence, not merely sound clinically plausible.

TACO is an information-bottleneck paper. In-context tabular prediction can become expensive because the model carries many training rows through attention. Compressing those rows helps only if the compressed representation is sufficient for the later prediction. The question is not "how many tokens did we save?" It is "which row, column, type, or relation did the prediction still need?"

EVIDENCE

What would prove the interface is faithful

The proof standard is domain-native. SleepLM should be checked against sleep evidence, and TACO should be checked against tabular decision evidence.

Temporal grounding

Sleep captions and insights should point to the right event timing rather than producing generic clinical descriptions.

Retrieval fidelity

Sleep retrieval should find signal segments because the physiological evidence matches the query, not because metadata or common wording leaks the answer.

Localization

Event localization should show that language-facing tasks still preserve where in the recording the evidence lives.

Compression ablation

TACO should reveal which compression rates preserve prediction and where row/column information starts to disappear.

Rare-row retention

Tabular compression should preserve uncommon but decisive rows instead of only the average pattern.

End-to-end budget

Reported speed and memory savings should survive the full TabArena-style workload, not just a compressed subroutine.

FAILURE MODES

How beyond-text models become fluent wrappers

The danger is that the model gains a convenient interface while the domain evidence stops controlling the answer.

Physiology hallucination

SleepLM produces a plausible caption or insight that is not supported by the signal timing or channel evidence.

Event smearing

A long sleep recording is summarized correctly at a high level while the exact event location is lost.

Subject flattening

The model learns average sleep-language patterns but misses individual variation that matters clinically.

Row erasure

TACO compresses context by removing the row that would have changed the prediction.

Type confusion

Compressed table latents blur categorical, numerical, missing, and target-related fields into one generic vector.

Benchmark-only speed

The method reports large speedups but depends on assumptions about table size, batching, or preprocessing that do not hold in deployment.

INSIGHT

The interface decides the capability

A foundation model beyond text is only as good as the interface that connects the domain object to the model's working space.

For sleep, the interface must preserve a noisy physiological state and make it readable. For tables, the interface must preserve structured operations and make them cheap. In both cases, failure can hide behind fluent outputs or impressive speedups. The real test is whether the domain-native evidence still controls the answer.

PRINCIPLE

A token is a contract, not just a chunk

The easiest mistake is to treat every modality as if it only needs a tokenizer. The harder question is what promise that token makes about the world.

A word token promises a rough unit of language. A sleep token may need to preserve a physiological event. A table token may need to preserve a row, column type, missing value, or target relation. A video token may need to preserve motion, geometry, object identity, or a future state. A brain token may need to preserve enough neural signal to support both encoding and decoding tasks. If the token breaks that promise, the model can still be fluent, fast, or visually impressive while no longer answering the domain question.

This is why beyond-text foundation models connect directly to evaluation. The right test is not whether the model can produce an output in the new modality. It is whether the output remains controlled by the domain object: the event in the signal, the relation in the table, the aspect in the judge rubric, the geometry in the video, or the hidden state in the physiological measurement.

CLUSTERS

The Main Research Moves

Give non-text signals a language-facing task layer

SleepLM treats physiological traces as objects that can support captioning, retrieval, localization, and insight generation. That matters because the raw waveform is not the user-facing artifact. The useful artifact is an interpretation tied back to signal evidence, so the dataset and model have to connect continuous measurements to textual descriptions without erasing the underlying temporal structure.

Make structured-data foundation models practical enough to use

TACO is about the other half of the beyond-text problem: even when the task interface exists, the model has to run under realistic memory and latency budgets. Tabular workloads are often operational rather than theatrical; a method that saves memory and speeds inference can change whether a foundation-model approach is usable in routine structured-data settings.

CONCEPT BRIDGES

Where to read the larger pattern

Multimodal models need modality contracts

Sleep signals, tables, images, motion, and text do not carry evidence the same way. A foundation model beyond text must respect each modality's contract.

Grounding preserves evidence

Cross-domain models are useful when their outputs stay tied to the measured signal, table field, physical state, or source evidence that made the answer valid.

Efficiency changes the algorithm

Beyond-text models often become usable only when inference cost, memory, tokenization, and serving constraints are part of the method itself.
