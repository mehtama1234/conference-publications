Long-context and long-horizon generation as state management over time

The central problem is not merely fitting more tokens into a window. Long-horizon systems must decide what to remember, when to retrieve, when to overwrite, when to use tools, and when more raw context becomes noise.

Problem

Long tasks fail when the model carries the wrong state forward. It may forget early evidence, over-attend to irrelevant context, drift from the plan, or generate long outputs without maintaining structure.

Approaches

The papers use test-time updates, overwrite memory, retrieval policies, tool-augmented SSMs, RL for long writing, synthetic long-context tasks, multimodal regulatory models, and long-video generation systems.

Connecting read

This theme is about control over state: the model's internal state, external memory, retrieval path, repeated data exposure, and generated artifact over time.

FIRST PRINCIPLES

The core problem

A long-horizon model has to survive accumulation. Every new segment, retrieved document, generated paragraph, or video frame changes the state the next step depends on. The system needs rules for memory update and access, otherwise length becomes a liability.

The papers split the problem into two choices. First, what should be stored internally through context, test-time updates, or learned memory? Second, what should be externalized through retrieval, tools, repeated data passes, or structured conditioning? The useful pattern is selective state, not maximal state.

SYNTHESIS

Three ways the papers extend horizon

1. Long context needs active memory updates

internal state

This cluster asks how a model should update itself or its memory as it reads. The goal is not simply storing everything, but turning a stream into useful state.

ICLR 2026In-Place TTT
In-Place TTT uses chunk-wise test-time updates to improve tasks with contexts up to 128K. The method treats reading as adaptation: each chunk can update fast weights so the model becomes better suited to the current document. That is different from passively attending over a fixed context.
ICLR 2026MemAgent
MemAgent processes documents segment by segment and learns overwrite-based memory updates for contexts far beyond training length. Its key idea is that memory is finite and must be edited. The model learns what to overwrite, which is the central operation in long-horizon state management.
ICLR 2026Intrinsic Entropy
Intrinsic Entropy explains long-context gains and harms through irreducible uncertainty conditioned on available context. It gives a reason why more context can hurt: if added context does not reduce uncertainty, it may add distraction or conflict. Context value should be judged by information, not length.
ICLR 2026Multi-Epoch Scaling
Multi-Epoch Scaling shows that larger datasets can be repeated more times before reuse benefits plateau. This belongs in long-horizon learning because repeated exposure is a memory-forming process. The question is when another pass still teaches the model and when reuse stops adding useful information.

2. Long tasks need learned access paths, retrieval, and tools

external state

Some horizons are too long for fixed memory. These papers teach the model to retrieve, recheck, and call external tools so it can solve tasks whose required state outlives its native architecture.

ICLR 2026LoongRL
LoongRL uses KeyChain synthetic tasks to train plan-retrieve-reason-recheck behavior that generalizes from 16K to 128K contexts. The important behavior is procedural: the model learns a loop for managing evidence over distance. Planning and rechecking keep retrieval from becoming a one-shot lookup.
ICLR 2026Q-RAG
Q-RAG achieves strong results on long-context benchmarks by learning multi-step access policies. Retrieval is framed as a policy, not a static top-k search. The model chooses which evidence to access over multiple steps, which is closer to how long tasks are actually solved.
ICLR 2026Tool-Augmented SSMs
Tool-Augmented SSMs shows that fixed-memory state-space models need interactive external tools for arbitrary-length tractable tasks. This is a boundary result: compressed internal memory alone cannot solve every long problem. Tools extend the state space by letting the model externalize storage and computation.

3. Long generation must preserve structure across the artifact

output horizon

Long generation is not only long input reading. The output itself can be a long document, video, or biological sequence model where consistency must persist over many steps.

ICLR 2026LongWriter-Zero
LongWriter-Zero uses reinforcement learning from a base model to induce long-form writing without synthetic long-output supervised data. It treats long writing as a behavior that can be shaped by reward. The model must learn length control, structure, and coherence rather than imitating a handcrafted long-output corpus.
ICLR 2026Stable Video Infinity
Stable Video Infinity supports non-looping long video with prompt, audio, skeleton, and text conditioning without extra inference cost. Long video stresses temporal consistency: frames must evolve without collapsing into loops or drift. Multiple conditioning channels give the generator anchors over time.
ICLR 2026Prism
Prism finds that proper multimodal regulatory modeling can outperform simply using longer DNA sequence windows. This is the cleanest warning against length worship. In biology, the right regulatory state can matter more than extending the raw sequence window, because mechanism is not always local token span.
FIELD READ

What this theme says about ICLR

The theme says long-horizon capability is a systems problem around state. Some state is internal, some external, some retrieved, some generated, and some should be discarded.

That matters directly for agent gyms. A long browser or coding task is not won by context length alone. The agent needs a memory policy, retrieval policy, tool policy, and verifier loop that keep the right facts alive over many steps.
