Data curriculum and selection as learning path

Data is not just material for training. It is a sequence of pressures. The same example can help, do nothing, or hurt depending on when it arrives, what the model already knows, what other examples surround it, and what future capability the training run is supposed to create.

Problem

Dataset size alone does not say whether training will improve. Data value depends on timing, current model state, redundancy, target behavior, and the update rule.

CORE

Data value is conditional

An example is not valuable in isolation. It is valuable if its training push moves the current model toward the target behavior without damaging something else that still matters.

The same example can mean different things at different stages. Early in training, it may teach a basic pattern. Later, it may be redundant. Too early, it may be too specialized for the model to use. Too late, the learning rate or representation may be too settled for it to move the model. In another batch, it may be a useful contrast. Next to the wrong examples, it may become noise. Data value is therefore relational: example, model state, selected set, update rule, and target behavior all matter.

Sequential Data Values makes this explicit by treating selection as a dynamic programming problem: the value of an item depends on what has already been selected and what remains possible. OPUS adds the optimizer-shaped view by scoring documents through their effective update direction relative to a target. Source Screening shows the source-level version: discarding data can improve shared representation learning if the discarded sources are uninformative for the target subspace.

First-principles line
Data value is the value of a training push at a particular moment, not a permanent property of an example.
ORDER

Order matters

A curriculum is a claim about when the model can use a lesson. Good ordering lets local updates accumulate into a capability path.

The old view treats a dataset as a bag. The learning-path view treats it as a sequence. If basic examples build the representation needed for harder examples, order helps. If hard examples arrive before the model has the right handles, they may teach noise or be ignored. If high-quality examples arrive after learning-rate decay has made updates weak, their quality is wasted. If midtraining bridges create an intermediate state before reinforcement learning, later reward pressure can become more stable.

LR Decay Wastes Your Best Data is the clean schedule example: ascending-quality curricula can lose their benefit when late high-quality data is underweighted by standard decay. PRISM midtraining shows a stage view: a compact high-quality middle phase can improve reasoning while preserving general ability, and RL after that midtraining can be more stable than direct RL from the base. Power Law Compositional Reasoning gives a distributional curriculum story: frequent compositions can be learned first and support rarer compositions later.

Too early

The model lacks the primitives needed to use the example, so the signal becomes noise.

Too late

The optimizer can no longer move enough, or the representation has already settled around another solution.

Right bridge

Intermediate data creates a state where later specialized or reward-based training can land.

Wrong bridge

The curriculum creates an attractive path toward a behavior that is not the target behavior.

First-principles line
Ordering helps when earlier examples create the representation that later examples need in order to matter.
COVERAGE

Coverage versus redundancy

More data helps only when it adds useful coverage, useful reinforcement, or useful contrast. Repetition without new pressure can waste compute or narrow behavior.

Coverage means the selected data spans the distinctions the target behavior needs: languages, modalities, domains, edge cases, tools, reasoning forms, failure modes, and exact units. Redundancy is not automatically bad; repeated exposure can stabilize common patterns. But redundancy becomes harmful when it crowds out rare distinctions, amplifies shortcuts, or spends update budget on what the model already knows.

HOBIT chooses hard, informative, non-contradictory in-batch negatives for contrastive learning, which is coverage at the batch level. OpenThoughts treats reasoning data as an engineered supply chain, where coverage across math, code, science, trace styles, and problem types becomes part of capability. CoCo removes graph redundancy and noise while preserving intrinsic structure. Universal Redundancies in TSFMs shows that redundancy itself can be measured in model components, which matters because data redundancy and model redundancy interact.

First-principles line
Coverage is useful pressure over missing distinctions; redundancy is useful only while it reinforces behavior the model has not yet made stable.
HARDNESS

Hard examples can help or hurt

Hard data is useful when it teaches a real boundary. It is harmful when it is hard because of noise, contradiction, bad labels, or a distinction the model is not ready to learn.

A hard negative can force precise identity. A boundary case can widen a robust decision margin. A rare example can expose a failure hidden by averages. But hard examples are not sacred. If the contrast is impossible, mislabeled, or beyond the current representation, training may overfit noise or distort the geometry. The question is why the example is hard and what pressure it applies.

Difficult Examples Hurt Unsupervised Contrastive Learning is the caution: examples that look useful can worsen contrastive generalization. HOBIT is the constructive version: hard negatives should be informative and non-contradictory. C2R prioritizes smallest-margin adversaries during dataset distillation and uses class-balanced contrastive robustness loss, making boundary cases useful for robust behavior rather than just difficult for difficulty's sake.

First-principles line
Hard examples are good when they expose the boundary the deployment task needs, and bad when they only inject unstable pressure.
REPAIR

Data as repair

Some data is valuable because it repairs a known failure: a counterexample, a useful failed prefix, a missing modality, a weak workflow, or a stale representation.

Repair data is different from general coverage. It starts from a diagnosis. The model repeats a bad reasoning pattern. A workflow fails on certain signatures. A modality is missing. A verifier catches an action-level error. A long rollout contains useful early work but a bad ending. The training set then adds examples targeted at that failure. This is data selection as debugging, not only sampling.

T3 preserves useful prefixes from failed trajectories, turning failed rollouts into partial credit instead of garbage. CE-Graph uses counterexample pools and Propose-and-Verify edits to improve math, code, and QA workflows. LALP selects teacher traces by transferable local step transitions, which treats process data as reusable repair operators. LIMSSR handles missing modalities through prompt-guided imputation and mask-aware uncertainty, showing the data-level repair problem when the training set itself is incomplete.

First-principles line
Repair data is selected because it targets a known broken transition between state, evidence, action, and outcome.
TRANSFER

Cross-domain and cross-modal transfer

Transfer data helps when it carries a structure the target domain can use. It hurts when it imports the wrong invariances, shortcuts, or unit boundaries.

A source domain is useful when its examples teach a representation that the target task can reuse: physiological correlations, shared subspaces, reasoning traces, table structures, visual grounding, multilingual token behavior, or domain-independent proof steps. But transfer can fail asymmetrically. One language may help another while the reverse is weak. One biosignal may bridge to another only through a shared latent state. A source subset may look large but contain little information for the target representation.

BioX-Bridge uses physiological correlations to transfer knowledge across biosignal modalities when labels are scarce. Source Screening formalizes source subset selection for shared subspace estimation, showing that the right source set can beat using everything. TokSuite tests tokenizer effects across multilingual perturbations, making tokenization itself part of cross-domain transfer. DiSC distills context-segment knowledge while preserving instruction-following, reasoning, and factual skills, which is transfer with retention constraints.

First-principles line
Transfer data is useful when the source teaches a structure the target must preserve, not when it merely increases training volume.
GOVERNANCE

Data governance as training constraint

Data that cannot be legally, privately, or reproducibly used is not a stable foundation, even if it would improve a benchmark.

Governance is not separate from training. Provenance decides whether data can be audited. Licensing decides whether models can be reused. Privacy decides whether an update is allowed. Filtering decides what patterns are visible. Documentation decides whether another lab can reproduce the recipe. Governance constraints therefore shape what the model is permitted to learn from and what claims builders can make afterward.

Common Corpus is the anchor because it assembles roughly two trillion tokens of uncopyrighted or permissively licensed multilingual and code data, with provenance, filtering, and curation details. Its point is not just dataset size; it makes legal usability a technical training constraint. PRISM's gauge-invariant DP LoRA work shows the privacy-adaptation version: update geometry and privacy noise have to be designed together. Train-before-Test reminds us that evaluation protocol and adaptation data are entangled; rankings after controlled fine-tuning depend on what data the model is allowed to see.

First-principles line
Governance is part of the data curriculum because allowed, auditable, private, and reproducible data determines which learning paths are legitimate.
