First-principles concept

Data as training pressure

Data is not a pile of examples. In training, data becomes pressure on the model: what it sees, when it sees it, how often it sees it, and what the optimizer can still change when it arrives.

CORE

The example matters only through the change it can cause

A training example has value when it moves the model toward a behavior that matters and does not damage behavior that must remain.

The same example can be useful early and nearly useless late. A hard negative can sharpen a boundary or corrupt it. A reasoning trace can teach process or teach imitation. A specialized corpus can bridge pretraining and posttraining or arrive too late for the optimizer to absorb it. Data value is therefore not a fixed property of the file. It depends on model state, training time, batch context, optimizer movement, and the target behavior.

This is why the grouped data papers treat selection, order, recipe, and filtering as method design. OpenThoughts makes reasoning traces and recipes inspectable. HOBIT chooses hard but non-contradictory contrastive batches. Sequential Data Values turns selection order into a planning problem. OPUS scores token usefulness online. LR Decay Wastes Your Best Data shows high-quality data can be underused when learning-rate decay leaves too little movement.

Core rule
Ask what movement the data causes at this point in training, not whether the data looks valuable in isolation.
FIRST PRINCIPLE

Examples are forces, not trophies

A dataset matters through the change it produces in the model.

It is easy to talk about data as if it were a collection of valuable objects: clean examples, hard examples, expert examples, rare examples, synthetic examples, reasoning traces. Training changes the question. Once an example is used, it becomes a force applied to a model in a particular state. The same example can sharpen a behavior, do nothing, or damage a neighboring behavior depending on when and how it is applied.

This is why data work cannot be separated from optimization. An example does not carry a fixed amount of value in its text. Its value depends on the model’s current errors, the learning rate, the batch it appears in, the curriculum around it, the loss that turns it into pressure, and the evaluation that says whether the pressure moved the right behavior. Data quality is therefore not just inspection before training. It is measured by effect during and after training.

First-principles test
Name the behavior the data should move, then measure whether that behavior moved because of this data under this training recipe.

METHOD

Why data selection is part of the training algorithm

Choosing data is choosing which errors the optimizer is allowed to see.

A training run does not optimize against the world. It optimizes against the examples that arrive, in the order they arrive, with the weights they receive. That means data selection is not a support task outside the method. It decides the gradient stream. If the stream over-represents easy cases, the model learns comfort. If it over-represents hard but noisy cases, the model learns confusion. If it hides rare failures, the model learns average behavior and fails at the boundary.

A first-principles data method therefore has to say five things: the behavior being targeted, the current model state, the arrival schedule, the batch relation, and the stop condition for adding more of that kind of pressure. This is why static dataset descriptions are not enough. We need effect curves, ablations, order comparisons, and tests for collateral damage.

FAILURES

How data work goes wrong

Data work fails when it counts examples instead of measuring their effect. More data can repeat what the model already knows. Cleaner data can arrive too late. Hard data can teach a false boundary. Reasoning traces can train format without process. A bridge corpus can over-specialize if the mixture weight is wrong. A token selector can chase a cheap score that is not the target behavior.

The fix is not a single better dataset. The fix is to state the pressure: what behavior should move, what should stay fixed, when the pressure is applied, and what evidence shows the movement happened.

FAILURE MAP

The common false stories about data

Volume worship

More examples are treated as more learning even when they repeat known behavior.

Late value

High-quality data arrives after the optimizer has too little movement left.

Hard-negative damage

Hard examples are selected without checking whether they create useful contrast or false conflict.

Recipe opacity

The dataset is released, but the teacher, filters, ordering, and loss are unclear.

Static scoring

A token or document score is treated as permanent even though model state has changed.

Bridge overfit

Intermediate data helps one downstream recipe but narrows the model too early.

CONNECTION

Why this idea cuts across the atlas

Data pressure is the hidden cause behind many visible behaviors.

Feedback signals are data after judgment has been attached. Synthetic data is training pressure whose source may or may not preserve evidence. Compression can decide which examples still fit into a training or inference budget. Representation repair often begins by changing the pressure that shaped the representation.

The deeper point is that data is one of the few levers that reaches into the model before behavior appears. To understand a trained system, we have to ask what pressure formed it, not only what it can do after the fact.
