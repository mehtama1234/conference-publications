Problem

Continual learning is the stability-plasticity problem: the model must absorb new tasks, skills, or data streams while preserving old behavior and reusable structure.

Approaches

The papers add concept-compositional memory, restore plastic weight geometry through isometric reinitialization, and package new LLM skills as trainable soft tokens instead of full weight updates.

Connecting read

The common move is to stop treating adaptation as unconstrained fine-tuning. Each paper picks a smaller control surface where learning can happen with less forgetting.

FIRST PRINCIPLES

The core problem

A deployed model lives in time. New classes appear, new domains arrive, users ask for new skills, and agents accumulate experience. The naive solution is to update the model on the new data. The failure is that the same parameters that absorb the new behavior also carry the old behavior, so learning can overwrite memory.

The important question is therefore not only how to learn the next task. It is where the change should live. If the change can be expressed as a reusable concept, a geometric reset that restores plasticity, or a compact learned token, then the model can adapt without pushing every parameter through the same destructive update. The three papers here are small in count but sharp in pattern: each turns continual learning into a problem of choosing the right interface for change.

LENS

Continual learning is controlled change

The concrete object is the part of the model allowed to change while earlier capability remains anchored.

The stability-plasticity problem is easy to say and hard to solve because the same update can be both useful and destructive. A new skill should enter the system. An old skill should not vanish. A model should regain plasticity when it becomes rigid, but not wipe out what it already learned. These papers are valuable because each picks a smaller change surface: concept slots, weight geometry, or soft skill tokens.

WHY IT WORKS

Forgetting is an update-location problem

A continual learner fails when new evidence is written into a place that also stores old authority.

CompSLOT responds by moving memory into reusable visual concepts. Instead of forcing each new class boundary to carry all the knowledge, it tries to preserve object-centric parts that can support many future classifications. FIRE responds at the geometry level. It says the model may need a reset, but the reset should be constrained: stay near past weights for stability while restoring isometry for plasticity. Skill Neologisms responds at the language-interface level. It adds a new learned word-like handle for a procedure while freezing the rest of the model.

These are not three unrelated tricks. They are three answers to the same question: where can new capability live without destroying old capability? In vision, the answer can be concept slots. In training dynamics, it can be a carefully chosen reinitialization point. In LLMs, it can be a soft token that composes inside prompts. The method works when the update surface is narrow enough to avoid global damage but expressive enough to absorb the new skill.

TOPIC 01

Stability and plasticity pull in opposite directions

A useful long-lived model must be able to change and remain itself.

Stability means old capability survives. Plasticity means the model can still absorb new capability. Continual learning is hard because ordinary updates use the same parameters for both. Push too hard toward the new task and old behavior disappears. Protect old behavior too strongly and the model becomes rigid. The problem is not simply "avoid forgetting"; it is choose where learning is allowed to happen.

The three papers solve this tension by changing the update surface. CompSLOT lets new classes lean on reusable concept memory. FIRE moves the model to a weight state that is close to the past but easier to learn from. Skill Neologisms adds new skill handles while freezing the base model. Each method defines a different boundary between old authority and new movement.

TOPIC 02

Concept memory stores parts that future tasks can reuse

For vision, the stable object may be a concept rather than a class label.

A class label is task-specific. Today the model distinguishes birds from cars; tomorrow it distinguishes bird species; later it may need beaks, wings, wheels, or textures. If the model only stores class boundaries, each new task can overwrite the old organization. Concept slots offer a more reusable unit: object-centric parts or semantic primitives that can support many future labels.

CompSLOT works when those slots are functional memory, not just pretty explanations. The evidence has to show that concept primitives help later classification, that sample-wise concept similarity supports retention, and that the module improves diverse continual learners rather than one cherry-picked stream.

TOPIC 03

A reset can preserve memory if it preserves the right geometry

Reinitialization is usually blunt. FIRE treats it as constrained movement.

A model that has learned many tasks can become hard to train further. Some weights may sit in a geometry that protects past performance but resists new learning. Resetting weights can restore plasticity, but a naive reset throws away hard-won knowledge. FIRE frames this as a two-objective problem: stay close enough to previous weights to preserve useful behavior, while restoring isometry to make future learning easier.

The first-principles object is the reinitialization point. It is not "old weights" and not "fresh random weights." It is a state chosen to balance memory and learnability. The method is convincing only if that geometric proxy predicts actual future learning and retention across settings.

TOPIC 04

A skill token is a small interface to a procedure

For language models, a new capability can sometimes be packaged as a learned handle rather than a model-wide update.

Skill Neologisms uses soft tokens as procedural handles. The base model remains frozen; the new token embedding is trained to call up a behavior. This is a different kind of continual learning. Instead of rewriting the whole model for each new procedure, the system adds a small vocabulary-like object that can be inserted into prompts and composed with other skills.

The hard test is composition. A token that works only in one narrow prompt is a patch. A token that combines with independently learned skills is closer to a reusable interface. The paper matters because it asks whether continual skill acquisition can look more like adding words to a language than repeatedly fine-tuning a whole model.

TOPIC 05

The update boundary must match the thing being learned

The right controlled-change object depends on whether the new information is a concept, a geometry problem, or a procedure.

This is the deeper synthesis. If the new information is a reusable visual part, concept memory is a natural place to store it. If the model's problem is lost plasticity, the update object is the weight geometry. If the new information is a procedure a language model should invoke, a skill token may be enough. Continual learning fails when it writes a new capability into the wrong kind of object.

That gives a practical reading rule for future papers: identify the object that changes, the behavior that must stay fixed, and the evidence that proves both. Without all three, a method may simply move forgetting somewhere harder to notice.

EVIDENCE

What would prove controlled change

Retention

Old tasks or concepts should remain usable after learning the new task, not merely remembered in a frozen feature visualization.

Plasticity

The model should still learn future tasks after the update; a stable but rigid model has not solved continual learning.

Composability

New concepts or skill tokens should combine with existing knowledge instead of acting as isolated patches.

Cross-method gains

CompSLOT should improve diverse continual learners, not only one hand-tuned backbone or task stream.

Cross-domain reset

FIRE's SFE/DfI tradeoff should help beyond one setting, as reported for visual learning, language modeling, and reinforcement learning.

Zero-shot composition

Skill Neologisms should compose independently learned skill tokens without retraining the full model for each combination.

FAILURE MODES

How controlled change breaks

Each update surface has its own failure boundary. The point is not to avoid change; it is to make the wrong change visible.

Concept theater

Slots look interpretable but do not preserve accuracy, retention, or useful sample-wise similarity.

Object mismatch

Object-centric assumptions fail in domains where classes are texture, style, relation, or scene-context driven.

Over-reset

FIRE restores plastic geometry but moves too far from prior weights, damaging old knowledge.

Under-reset

The reset preserves stability but does not recover enough plasticity for future learning.

Token bottleneck

A soft skill token cannot store the procedure, or it stores it only for one narrow benchmark form.

Composition illusion

Skill tokens work alone but interfere when combined, so the model has acquired patches rather than composable skills.

SYNTHESIS

Three control surfaces for learning over time

1. Remember through concepts instead of class labels

concept memory

A classifier that only compares classes can be brittle when tasks arrive sequentially. If a new task has few classes, the model may overfit the current contrast and forget how older visual concepts were organized. Concept-level structure gives the learner a more stable unit of memory than the current task label set.

ICLR 2026CompSLOT
CompSLOT adds a plug-and-play concept module for foundation-model continual vision learners. It uses object-centric slots to parse semantically meaningful image parts, selects and aggregates concept primitives, and distills sample-wise concept similarity into the classifier. The first-principles move is to make memory compositional. A model that remembers reusable concepts can classify future examples by recombining stable parts, rather than relearning brittle class comparisons each time the task stream changes. That is why the paper also connects to interpretability: the concepts are not just explanations after the fact, they become functional supports for retention.

2. Restore plasticity without throwing away the past

weight geometry

A model can become too rigid after learning previous tasks. Reinitializing weights can recover plasticity, but ordinary resets are hard to tune: too small and the model remains stuck, too large and it loses useful knowledge. This line of work asks whether the reset itself can be chosen by a principled geometric condition.

ICLR 2026FIRE
FIRE, Frobenius-Isometry Reinitialization, formalizes stability and plasticity as two measurable objectives. Stability is proximity to past weights, measured by squared Frobenius error; plasticity is restored by enforcing isometric geometry, measured through deviation from isometry. The reinitialization target minimizes drift from the old weights while restoring the geometry associated with learnability. This matters because it turns the vague instruction "reset enough but not too much" into a constrained optimization problem, and the local notes report use across continual visual learning, language modeling, and reinforcement learning.

3. Add skills through vocabulary, not model-wide updates

skill interface

For language models, full fine-tuning can be too blunt for continual skill acquisition. Prompting avoids weight updates but is limited by context and expressiveness. A smaller option is to add a learned handle for a skill and let the frozen model compose that handle with what it already knows.

ICML 2026Skill Neologisms
Skill Neologisms introduces trainable soft tokens integrated into the model vocabulary. The base LLM weights stay frozen; the new token embeddings are optimized for a specific procedural skill and then used inside prompts as if the model had learned a new word for that skill. The deeper idea is that a skill can be packaged as a composable interface instead of a global parameter change. The paper's local note emphasizes zero-shot composition of independently learned skill tokens, which is exactly the continual-learning pressure: acquire new capabilities without forgetting and without blocking later composition.
FIELD READ

What this theme says about ICML and ICLR

The big picture is that continual learning is moving away from monolithic retraining and toward controlled interfaces. Concepts, slots, spectra, masks, soft tokens, replay buffers, and memory systems are all attempts to decide what should change and what should stay anchored.

That matters for long-lived AI systems because a benchmark or deployment test that runs only once misses a central problem: real systems accumulate user feedback, learn tool affordances, adapt to domains, and still need to behave consistently. The page's three named papers show the mechanism-level version of that problem. CompSLOT protects reusable visual concepts, FIRE restores future learnability without discarding prior weights, and Skill Neologisms adds procedural capability through compact tokens. Together they say that long-lived systems need update mechanisms with boundaries.
