Optimization and training dynamics as controlling when updates should move

The central problem is that training is a path, not a single objective. The same data, gradient, adapter, or search step can help or hurt depending on timing, local geometry, and the update rule around it.

Problem

Optimization failures often come from mismatch: late data meets a decayed learning rate, distillation gradients fight task gradients, adapters are too rigid, or exploration stays trapped near known samples.

Approaches

The papers use learning-rate repair, trust regions, gradient balancing, low-rank convergence theory, landscape analysis, route aggregation, smooth measure comparison, and novelty-guided sampling.

Connecting read

The theme is about steering the update process itself: how much to move, which subspace to use, when to average, and when to protect the current policy.

FIRST PRINCIPLES

The core problem

An optimizer only sees local signals: gradients, losses, sampled candidates, current parameters, and schedules. But the desired outcome is global: a model that becomes more capable without forgetting, collapsing, overfitting, or wasting the best data. Training dynamics research is the attempt to make local updates respect that larger trajectory.

That is why the papers here are diverse. Some repair pretraining schedules. Some prove convergence for low-rank adapters. Some balance distillation and task gradients. Some use trust regions so RL does not destroy inference behavior. Some guide search into new high-performing regions. All are asking when an update is actually useful.

OBJECT

What is being controlled?

The concrete object is the update path: the ordered sequence of parameter states, gradients, data batches, learning rates, adapter ranks, search proposals, and policy constraints that move a model from one behavior to another.

The fixed part is the intended training contract. A curriculum paper must keep the same data quality claim. A LoRA theory paper must keep the same objective and low-rank parameterization. A distillation paper must keep the teacher and task signals interpretable as separate pressures. A trust-region RL paper must keep the base model's useful inference behavior inside the allowed movement region. If those fixed parts are changed, the method may still improve a number, but it no longer proves the paper's claim.

What may change is the local control variable: learning-rate decay, checkpoint weighting, active rank, gradient mixing, trust-region size, route aggregation, measure comparison, or novelty pressure. These methods work when changing that variable changes the training path without secretly changing the problem. The evidence is therefore path evidence, not only final score evidence: curves, ablations, stability diagnostics, convergence guarantees, retained base behavior, and comparisons showing the claimed control caused the improvement.

PRINCIPLE

Optimization papers are about path dependence

The same gradient can mean different things depending on when it appears, what state surrounds it, and which movement the optimizer is allowed to make.

This is the deeper commonality across the page. Late high-quality data is not useful if the schedule has made the model nearly immovable. A low-rank adapter is not useful if the needed change lies outside the allowed subspace. A distillation gradient is not useful if it cancels the task gradient. A trust-region update is not useful if the region is so wide that it destroys base behavior or so narrow that it cannot learn. A novelty search is not useful if it leaves the training set by exploiting the evaluator rather than discovering a valid better candidate.

So the evidence should be read as trajectory evidence. A final score is only the end of the story. The paper has to show the controlled variable actually changed the path: the schedule kept learning alive, the rank budget bought capability, the gradient arbitration reduced conflict, the trust region preserved behavior, or the search pressure found valid new regions.

TOPIC 01

Training is an ordered process

A dataset is not just a pile of examples. During training, examples arrive at particular moments when the model is more or less able to move.

LR Decay Wastes Your Best Data is easy to understand from this angle. If high-quality examples arrive after the learning rate has decayed too far, the optimizer sees them but cannot respond strongly. The data is valuable, yet the update path has made the model stiff. The fix is not only "use better data" or "use a better schedule." It is to make data order and learning-rate motion agree with each other.

Neural Thickets adds the local-geometry version of the same idea. A pretrained model may sit inside a dense region of nearby useful specializations. Fine-tuning is then not a blind search across all parameters. It is navigation through a neighborhood created by pretraining. The optimizer's job is to move enough to specialize while staying close enough to preserve the structure pretraining built.

TOPIC 02

An update subspace is a permission boundary

Parameter-efficient training works by saying: only this part of the model is allowed to move.

Low-rank adaptation is not merely a cheaper implementation detail. It is a restriction on the directions available to training. FlexRank asks how much low-rank capacity to activate; LoRA Gradient Descent asks when descent in that restricted space has legitimate convergence behavior. The fixed object is the base model and task objective. The movable object is a small low-rank surface laid over the model.

This restriction is useful when the needed behavior can be reached inside the subspace. It fails when the required change lies outside it. That is why evidence for adapter methods should include both cost and reach: how much movement was saved, what capability was recovered, and where the low-rank boundary starts to block learning.

TOPIC 03

Gradients can disagree about what the student should become

A training signal is not automatically helpful just because it comes from a teacher or a task label.

DTO-KD makes a common hidden conflict explicit. The distillation objective may ask the student to imitate the teacher, while the downstream task objective asks it to specialize. Sometimes those directions agree. Sometimes they compete. If one gradient dominates, the model may copy the teacher while underperforming on the task, or chase the task while losing useful teacher structure.

The first-principles object is the combined update direction. Gradient balancing works only if it changes that direction in a way that preserves both pressures. The evidence should show less conflict, not just a better end score: the task signal remains alive, the teacher signal remains useful, and neither one silently becomes decorative.

TOPIC 04

A trust region is a controlled-change contract

RL post-training is powerful because it can push behavior directly, but dangerous because reward pressure can move the model too far.

Trust-Region LLM RL belongs here because it treats the base model's existing behavior as something to preserve while optimizing reward. That is different from treating RL as a pure maximization problem. The model already has useful inference behavior, language behavior, and code behavior. The update should improve the target tasks without making the rest of the model drift unpredictably.

A trust region is therefore a permission boundary around the current policy. If it is too tight, learning cannot happen. If it is too loose, reward optimization can break the model. The method works when it finds a movement scale that gives task gains while keeping the original behavior close enough to remain useful.

TOPIC 05

Search must distinguish discovery from loopholes

Leaving known data is useful only when the new region is genuinely better, not when it merely tricks the evaluator.

AutoEP, L2Seg, and PCD all deal with controlled exploration. AutoEP changes a metaheuristic by reading evidence from the landscape. L2Seg compresses stable route segments so search can focus on uncertain parts. PCD guides samples toward novel high-performing regions beyond static training data. Each method changes where the optimizer spends effort.

The hard line is validity. Exploration is valuable when it finds candidates, routes, or samples that perform under held-out checks and preserve the problem definition. It is not valuable when novelty pressure discovers artifacts of the evaluator, aggregates a route segment that should have stayed flexible, or tunes a search recipe to a narrow benchmark surface.

EVIDENCE

What would prove the update path is controlled

The proof signal has to show that the claimed control variable caused the better trajectory.

Path ablations

Change the schedule, rank, gradient arbitration, trust region, or novelty pressure while holding the rest of the training setup fixed.

Trajectory diagnostics

Show curves, gradient conflicts, checkpoint behavior, search movement, or policy deviation, not only the final benchmark number.

Invariant preservation

Verify that the method kept the task, base behavior, objective, data claim, candidate validity, or low-rank contract intact.

Stability evidence

Check whether gains survive seeds, learning-rate choices, ranks, horizons, teacher strengths, and evaluation settings.

Theory-to-practice match

For convergence or landscape claims, empirical behavior should reflect the assumptions and limits of the theory.

Held-out validity

For search and novelty methods, new candidates should remain valid under checks not used to guide the search.

FAILURE MODES

Where training-dynamics papers overclaim

An optimization result can look clean while the mechanism that supposedly caused it is unproven.

The most common failure is confounding the path. A schedule method may improve because it used more effective compute. A data-order method may improve because the data changed, not because timing mattered. A low-rank method may look efficient because the task was easy enough that the restricted subspace never got stressed. A distillation method may report a final gain while one gradient simply drowned out the other. A trust-region method may improve reward while drifting in unmeasured behaviors.

The second failure is mistaking final score for process evidence. Training dynamics is about how the model moved. If the paper cannot show the update path, the controlled variable, and the invariant that stayed fixed, then the final number does not explain why the method worked. Good evidence makes the movement visible.

SYNTHESIS

Three controls over training dynamics

1. Schedules and checkpoints decide whether data can still matter

training path

This cluster treats the training run as a temporal object. The model's ability to learn from data depends on learning-rate decay, checkpoint averaging, and the surrounding pretrained parameter landscape.

ICLR 2026LR Decay Wastes Your Best Data
LR Decay Wastes Your Best Data shows that curriculum gains can disappear when high-quality examples arrive after the learning rate has decayed too far. Its repair, moderate decay plus weighted final-checkpoint averaging, is conceptually important because it treats schedule and data order as coupled. Better data is only useful if the optimizer can still respond to it.
ICML 2026Neural Thickets
Neural Thickets reframes pretrained weights as surrounded by many nearby task-specialist parameter vectors in large, well-pretrained models. The idea is that pretraining creates a dense region of reachable specializations. Fine-tuning is then less about finding one distant optimum and more about navigating a local thicket of useful variants.
ICLR 2026DMS
DMS replaces histogram discounting with a smooth model that distinguishes similar high-dimensional measures. It belongs in training dynamics because many optimization systems compare evolving distributions. A smoother measure comparison can detect meaningful differences without crude binning artifacts.

2. Parameter-efficient updates need subspace and gradient control

adaptation geometry

Adapters and distillation are attractive because they are cheap, but cheap updates can conflict or underfit. These papers ask how to choose rank, balance gradients, and prove the adapter update is not just a heuristic.

ICML 2026FlexRank
FlexRank selectively activates nested low-rank components to trade cost for capability across LLMs and vision transformers. It treats rank as an adaptive resource instead of a fixed hyperparameter. The model can spend more low-rank capacity on harder settings and less when cheap adaptation is enough.
ICML 2026LoRA Gradient Descent
LoRA Gradient Descent reformulates stacked adapter outer products and controls step size to obtain stationary-point convergence guarantees. The paper matters because LoRA is widely used as engineering practice, but its optimization behavior needs theory. It asks when low-rank adapter descent is a legitimate optimization method rather than an uncontrolled approximation.
ICLR 2026DTO-KD
DTO-KD dynamically balances task and distillation gradients to avoid conflict and dominance. Distillation is not always aligned with the downstream task; the teacher can pull against task loss. The method makes gradient arbitration explicit so neither objective silently overwhelms the other.

3. Search and RL need guardrails that still allow discovery

controlled exploration

The final cluster focuses on optimizers that explore: metaheuristics, routing solvers, sample generation, and RL post-training. The core tension is between stability and movement into new useful regions.

ICLR 2026AutoEP
AutoEP combines online exploratory landscape analysis with multi-LLM reasoning to adapt metaheuristic hyperparameters. It treats search configuration as a live decision problem. Instead of using one static optimizer recipe, the system reads the landscape and changes the search behavior as evidence accumulates.
ICLR 2026L2Seg
L2Seg predicts stable and unstable route segments so iterative solvers can aggregate stable portions into hypernodes. The idea is to reuse certainty. If part of a route is stable across iterations, the solver can compress it and spend future computation on the uncertain regions.
ICLR 2026PCD
PCD guides samples toward novel high-performing regions beyond static training data. It addresses a familiar limitation: learned generators often stay close to observed samples. The method uses optimization pressure to leave the training manifold only when doing so plausibly improves performance.
ICLR 2026Trust-Region LLM RL
Trust-Region LLM RL improves reasoning and code-generation training speed, stability, and success while preserving inference behavior. The trust region is the guardrail: RL can improve the model, but not by taking updates that break the useful behavior already present. That makes reinforcement learning a controlled post-training instrument rather than a high-variance shove.
FIELD READ

What this theme says about ICML and ICLR

The optimization papers are not just about faster convergence. They show that modern ML needs update policies: when to learn, how far to move, which subspace to use, when to preserve behavior, and when to search past existing data.

That connects back to agents and benchmarks because benchmark success depends on training dynamics too. If an agent improves in an interactive environment, we need to know whether the improvement came from better data, better exploration, safer updates, or a schedule that finally allowed the relevant signal to matter.

CONCEPT BRIDGES

Where to read the larger pattern

Data is training pressure

Training changes because examples arrive with timing, direction, difficulty, and curvature. The data matters through the update it causes.

Spectra, rank, and subspaces are working objects

Low-rank adapters, gradient subspaces, and measure geometry are not side details. They define the part of the model that is allowed to move.

Theory names the bottleneck

A training-dynamics claim is strongest when it identifies the limiting factor and shows why the proposed update removes that specific limit.
