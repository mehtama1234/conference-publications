Problem

Reasoning systems must decide what to think about, what evidence to fetch, when to use an external tool, when to stop, and how to recover when an intermediate step is wrong.

Approaches

The papers attack that problem through data pipelines, latent computation, tool use, search, retrieval, formal verification, and explicit controls on overthinking.

Connecting read

The unifying move is to treat reasoning as a resource allocation problem: useful thought is computation that changes the reachable solution, not text that merely looks careful.

FIRST PRINCIPLES

The core problem

A reasoning model is useful only if its intermediate work changes what it can correctly do. That sounds simple, but it breaks into several hard choices. The model may need to decompose a problem, inspect a visual cue, call a theorem prover, run code, retrieve a buried fact, explore partial solutions, or ask a clarifying question. Each action costs tokens, latency, money, or error exposure. The conference papers in this theme are about turning that messy process into something trainable and measurable.

The older view treated reasoning as a written explanation appended before an answer. This theme treats reasoning as an internal control loop. A good loop gathers information, keeps useful branches alive, suppresses wasteful loops, and connects intermediate artifacts to the final answer. That is why the papers range from math tool calls to latent thought, visual planning, diffusion search, reward normalization, and formal proof. They are different surfaces of the same underlying problem: how should a model spend limited computation in order to reduce uncertainty and produce a consequence that can be checked?

WORK PROGRAM

The full treatment should explain agents and reasoning systems from the inside out: what loop they run, what state they keep, how they choose tools, how they know when to think or act, how they recover from errors, and how the papers each pressure a different part of that loop.

TOPIC 01

What an agent is really for

An agent is useful when the system has to do more than answer once. It must keep track of a goal, choose actions, observe the effects, and keep going while the situation changes.

The simplest way to misunderstand agents is to define them by their tools. A model with a calculator, browser, code runner, theorem prover, retriever, or planner is not automatically an agent. Those tools matter only if the system knows when to use them, what result to trust, what changed after the call, and what to do next. The deeper object is the loop that connects state, action, consequence, and update.

This is why the theme belongs next to long context, representation, and training tasks. An agent needs memory because the next action depends on prior observations and failed attempts. It needs a useful representation because the raw transcript is too messy to act from directly. It needs training pressure because the model will only preserve the information that the task rewards. It needs evaluation because a fluent plan is cheap; a plan that survives contact with tools, evidence, constraints, and time is harder.

The first-principles question is: what must stay true across the loop? If the task is math, the agent must preserve the problem constraints and make intermediate operations checkable. If the task is code, it must preserve file state, symbols, tests, errors, and edits. If the task is a browser workflow, it must preserve page state, user intent, permissions, and completed steps. If the task is medicine or law, it must preserve exact evidence, uncertainty, and authority. If the task is video or robotics, it must preserve spatial state, temporal order, and physical consequences.

1. The agent begins when output becomes action

action

A normal answer can be judged mostly after it is written. An agent action changes what will happen next. It may run code, retrieve a document, ask a question, choose an experiment, generate a proof attempt, alter a file, sample a plan, or call an external system. Once output becomes action, the model is no longer only producing language. It is making a move inside a task environment.

That changes the standard for reasoning. The system must ask whether the action is relevant, allowed, timely, and checkable. A long explanation that does not change the reachable solution is wasted compute. A short tool call that reveals the decisive missing fact may be valuable. This is the common ground between Rational Agents, THOR, AutoEP, VERINA, CRAMF, LoongRL, and Actions Speak Louder than Prompts: each paper gives the model a way to make reasoning touch something outside plain text.

2. The real object is the loop, not the single model call

loop

A single model call sees an input and emits an output. An agent loop has to preserve continuity across steps. It observes a state, selects an action, receives a result, updates its state, and decides whether the goal is closer, farther away, blocked, or complete. If this loop is weak, the system can look intelligent at each individual step while still failing the task as a whole.

Several papers can be read as loop repairs. T3 asks how to learn from useful prefixes instead of throwing away an entire failed trajectory. Reasoning with Sampling keeps multiple paths alive because the first path may be wrong. ASAG and DECS ask when the loop should stop spending visible tokens. HERO asks how feedback should be normalized so reward pressure compares the right things. PonderLM-2 and MDM Reasoning ask whether part of the loop can happen in hidden or iterative computation rather than public text.

3. State is the agent's working truth

state

An agent does not need to remember every token equally. It needs to know what is currently true enough to act. The useful state includes the goal, active constraints, available tools, open uncertainty, completed actions, failed attempts, retrieved evidence, verifier feedback, and any world change caused by the last action. This state is smaller than the transcript but more important than the transcript.

State errors create agent failures that are easy to miss in final-answer benchmarks. The model may repeat a failed command, ignore a tool result, use stale retrieved evidence, keep obeying an old plan after conditions changed, or assume a proof step succeeded when the checker rejected it. LoongRL ties retrieval to answer reasoning because the state must point at the right evidence. Rational Agents formalizes the value of asking a question because state should be updated by the answer that most reduces uncertainty. AutoEP feeds search diagnostics back into the loop because the state should reflect observed algorithm behavior, not just the model's story about the algorithm.

4. Tools are useful because they impose consequences

tools

A tool is not just extra capability. It is a stricter interface. Code runs or fails. A proof checker accepts or rejects. Retrieval returns a specific source. A graph operation exposes structure that prose may hide. A visual intermediate plan preserves spatial constraints. These consequences give the model feedback that plain text often cannot provide.

THOR uses tool-call success and final answer reward so math reasoning is shaped by executable intermediate steps. VERINA shows that passing code tests and satisfying proof obligations are not the same level of evidence. CRAMF retrieves Mathlib4 definitions because formal mathematics depends on the exact object in the library, not a loose paraphrase. Actions Speak Louder than Prompts argues that code can be a better reasoning interface for graph-like structure. Visual Planning makes the intermediate artifact an image sequence because some constraints are spatial before they are verbal.

5. Planning is controlled commitment, not a list of nice steps

planning

A plan is useful only when it narrows future action without locking the system into a bad path. Too little planning makes the agent reactive and locally greedy. Too much planning makes it brittle when the environment changes. Good planning chooses enough structure to guide action, then checks each step against the world.

NEXCO is a clean example because it treats partial solutions as objects that must remain feasible. CDGS adds population search and pruning inside diffusion generation because a plan needs selection pressure, not just proposal. L2T learns latent programs from observations because a compact rule can support future action better than a surface prediction. Visual Planning uses image sequences when the plan itself is spatial. These papers share a principle: planning is the management of possible futures under constraints.

6. Verification closes the loop

checking

An agent that cannot check consequences is forced to trust its own text. That is dangerous because fluent intermediate reasoning can be wrong. Verification gives the loop a way to distinguish progress from motion. The check may be an executable result, proof success, source match, reward signal, visual contrast, attribution graph, or human review.

The papers use different checks because different domains expose truth differently. VC-STaR uses contrastive visual evidence so the model must attend to the cue that changes the answer. CRV uses attribution-graph analysis and feature intervention to repair faulty internal reasoning. HERO shapes reward comparisons inside verifier-defined groups. VERINA exposes the gap between code that seems correct and code that satisfies a formal proof. In each case, verification is not an afterthought; it is what tells the agent whether the current state should be trusted.

7. The same loop appears across modalities and domains

domains

The surface unit changes, but the loop stays recognizable. In text, the action may be retrieving or citing evidence. In code, it may be editing and running tests. In math, it may be calling a solver or proof checker. In video, it may be choosing a visual plan or tracking an event. In audio, it may be preserving acoustic evidence that text misses. In science, it may be selecting the next experiment or checking a generated hypothesis against measurements.

UALM-R1 matters here because it treats audio and text as reasoning material, not just input and caption. MetaphorVU matters because high-order video understanding may need relational knowledge beyond object labels. Tool-Augmented SSMs matters because the backbone itself affects whether the loop can carry state efficiently. OpenThoughts matters because the training supply chain shapes the kinds of intermediate work the model learns to imitate. The page should read these papers as parts of one field question: what loop lets a model act usefully in this kind of world?

TOPIC 02

The agent loop

The agent loop is the smallest useful picture of action: observe the situation, represent what matters, choose a move, execute it, read the result, update state, and decide whether to continue.

This loop sounds ordinary, but it explains why agent papers look so different from each other. A paper may improve observation, state, action choice, tool execution, feedback, recovery, or stopping. Those are not separate hobbies. They are different places where the loop can fail. If the observation is wrong, the agent acts on the wrong world. If the state is vague, it cannot choose the right next move. If action choice is weak, it wastes calls. If feedback is ignored, it repeats mistakes. If stopping is weak, it spends computation after the answer is already settled.

The important point is that a loop creates dependency between steps. A tool call is only useful if the result changes the next state. A retrieval is only useful if it changes what evidence the answer is built from. A proof failure is only useful if the next attempt repairs the failed obligation. A visual plan is only useful if later reasoning respects the spatial state it exposed. Agent design is therefore not only about giving the model more capabilities. It is about making sure each capability changes the next decision in the right way.

1. Observe: decide what world the agent is in

observation

Observation is not passive intake. The agent has to decide which pieces of the environment are relevant to the current goal. In text tasks, this may mean finding the clause, claim, or missing fact. In code, it may mean reading the right file, test, error, or dependency. In video, it may mean identifying the object, action phase, or visual cue. In math, it may mean noticing the exact constraint that limits the solution.

LoongRL fits here because long-context retrieval is not just more reading; it is observation control under distractors. Rational Agents also fits because asking a question is active observation: the agent chooses which missing answer would reduce uncertainty most. VC-STaR fits because visual reasoning fails when the model observes the wrong cue and still gets the answer by shortcut. The first loop failure is simple: the agent cannot act correctly if it is looking at the wrong evidence.

2. Represent state: turn raw context into what is currently true

state

After observation, the agent needs a compact working state. Raw context may include old messages, irrelevant tokens, partial traces, previous failed attempts, retrieved text, tool logs, and tentative plans. The state must separate what is still active from what is merely historical. It should keep the goal, constraints, known facts, uncertain facts, available tools, current plan, and checked results.

Tool-Augmented SSMs belongs here because the backbone has to carry useful state efficiently across long reasoning. PonderLM-2 and MDM Reasoning belong here because some state update may happen inside hidden or iterative computation rather than visible chain-of-thought. UALM-R1 broadens the point across modalities: if audio carries timing or acoustic cues, state cannot be reduced to text alone. State is the agent's working truth, and the loop is only as good as that truth.

3. Choose an action: spend the next move where it changes the answer

choice

The next action may be to think, sample, retrieve, ask, run code, search, formalize, inspect a visual plan, or stop. The agent should choose the action whose expected value is worth its cost. The hard part is that the value is often hidden until after the action is taken. A retrieval may return nothing. A code run may reveal the bug. A proof attempt may fail but expose the missing invariant. A sample may find a path the first attempt missed.

Rational Agents makes this action-choice problem explicit through expected information gain. Reasoning with Sampling treats candidate reasoning paths as choices to explore before committing. ASAG and DECS ask when continuing visible reasoning is worth the extra tokens and when it is only length. NEXCO and CDGS treat planning as action selection inside constrained search spaces. A good agent is not one that always does more; it is one that spends the next move on the uncertainty or constraint that controls the outcome.

4. Execute: make the action touch a stricter object

execution

Execution is where the agent leaves speculation. Code can run. A theorem prover can reject a statement. Retrieval can produce a source. A graph operation can compute a property. A search algorithm can return diagnostics. A generated visual plan can show whether the spatial arrangement is coherent. The action becomes useful because it creates an external result the agent cannot simply wish into correctness.

THOR is directly about this step because mathematical reasoning is trained with tool calls and step-level feedback. Actions Speak Louder than Prompts argues that executable code can be the right interface for graph-like and long-text structures. CRAMF retrieves the formal handles needed for Lean, because a proof environment cares about exact definitions. VERINA shows why execution is not one thing: tests can pass while proof obligations still fail. Execution gives the loop evidence, but the strength of that evidence depends on what the tool actually checks.

5. Read the result: distinguish signal from noise

feedback

A tool result is not automatically understood. The agent has to read it, decide whether it is trustworthy, and extract the part that matters. A compiler error may point near the real issue but not at the root cause. A retrieval result may be similar but not decisive. A reward score may be meaningful only inside a comparable group. A visual cue may be present but not the reason the answer should change.

HERO fits this step because reward-model scores need local meaning before they can guide optimization. AutoEP fits because real-time search diagnostics tell the model whether its optimization strategy is working. VC-STaR uses contrastive examples to make visual evidence reading sharper. CRV looks at internal attribution graphs because a reasoning failure may be visible inside the mechanism, not just at the output. Reading feedback is where the loop learns whether the last action produced progress or only more text.

6. Update: change the working state without losing the useful past

update

After feedback, the agent must update its state. This is where many failures become persistent. If the agent ignores a failed proof, it may repeat the same invalid step. If it over-trusts a retrieved passage, it may answer from the wrong source. If it forgets a useful prefix from a failed trajectory, it loses partial progress. If it treats every old observation as equally live, stale state can control the next action.

T3 is important here because it preserves useful prefixes from trajectories that did not end in full success. LoongRL matters because answer reasoning has to stay linked to the retrieved chain of evidence. CRV matters because update can include targeted repair of internal features, not only prompt changes. OpenThoughts matters because teacher-generated reasoning traces teach the model what kinds of intermediate updates a successful problem-solving path tends to contain. Updating is not appending to a transcript; it is revising what the agent will now treat as true, useful, uncertain, or discarded.

7. Continue or stop: decide whether more work is still useful

stopping

The final decision in each loop is whether to continue. Continuing is not automatically better. More reasoning can find missing evidence, repair a failed step, or explore a better plan. It can also waste tokens, overfit to a bad branch, invent rationales, or create new errors after the answer was already determined. Stopping is therefore a reasoning skill, not only a cost setting.

ASAG is about improving accuracy while reducing generated tokens. DECS separates redundant-token penalties from useful exploration. Reasoning with Sampling shows why diversity across attempts can be valuable, but also why collapse is a real risk. PonderLM-2 asks whether extra computation can be spent internally before emitting tokens. The loop should continue when the next step can change the outcome; it should stop when further motion is unlikely to add checked value.

SYNTHESIS

Six ways the field is attacking it

1. Build stronger reasoning traces

data and training

One approach is to improve the raw material that models learn from. Instead of hoping a base model discovers good multi-step behavior from generic text, these papers create or preserve traces that contain useful intermediate structure. The key distinction is between traces that are merely long and traces that carry credit: the model must learn which prefixes, examples, or hidden computations actually make success more likely.

ICLR 2026OpenThoughts
OpenThoughts is a scaling paper about reasoning data. It uses a teacher-generated pipeline, based on QwQ-32B, to produce roughly 1.2 million examples across math, code, and science. The important idea is not just that the dataset is large; it is that reasoning supervision is being treated as an engineered supply chain. If reasoning depends on multi-step traces, then the quality, diversity, and coverage of those traces become part of the model architecture in practice.
ICLR 2026T3
T3 focuses on credit assignment inside reasoning traces. Many failed rollouts contain useful early moves, but standard training tends to discard the whole trajectory because the final answer was wrong. T3 preserves informative prefixes, which lets the model learn from partial progress instead of treating success as all-or-nothing. This matters because long-horizon reasoning is usually built from locally useful moves, and a training method that can recognize those moves can improve accuracy while reducing wasted rollout tokens.
ICLR 2026Reasoning with Sampling
Reasoning with Sampling asks whether some gains attributed to reinforcement learning can be recovered through inference-time sampling without collapsing diversity. The deeper issue is exploration. A reasoning system needs several candidate paths because the first plausible path may be wrong, but training can make outputs converge to a narrow style. This paper matters because it separates the value of searching over possibilities from the value of permanently changing the model with RL.

2. Spend computation without wasting it

latent thought and stopping

Another group treats reasoning as a compute budget. The model should think longer when extra computation changes the answer, but stop when extra tokens are ornamental. The practical question is how to add internal work, adaptive generation, or reward pressure without teaching the model to produce bloated explanations.

ICML 2026PonderLM-2
PonderLM-2 adds hidden-state thought steps before token prediction. The first-principles motivation is that not every useful computation should be exposed as text. A model may need extra internal updates to settle an answer, but forcing those updates into emitted chain-of-thought creates cost, privacy, and faithfulness problems. The paper sits in the line of work trying to scale per-token computation while keeping the visible answer compact.
ICML 2026ASAG
ASAG is about adaptive generation control. It tries to improve reasoning accuracy while reducing generated tokens, without requiring a new training run. The underlying failure mode is overthinking: a model continues to elaborate after the useful computation has already happened, or explores irrelevant branches because the decoding process rewards more text. ASAG matters because inference control is becoming a direct capability lever, not just a cost optimization.
ICLR 2026DECS
DECS separates penalties for redundant tokens from the value of exploratory reasoning. That distinction is important because short answers are not always better; sometimes the model needs to explore. The target is not minimal reasoning but non-wasteful reasoning. By decoupling the reward signals, the method tries to discourage empty length while preserving the exploratory steps that actually help solve hard problems.
ICLR 2026MDM Reasoning
MDM Reasoning studies masked diffusion language models as reasoning systems, showing that they can match chain-of-thought transformer reasoning power through an equivalence to padded looped transformers. The conceptual point is that reasoning does not have to be a left-to-right stream of public tokens. If iterative refinement can provide the same computational shape, then the field has more than one architecture for spending thought.
ICLR 2026Tool-Augmented SSMs
Tool-Augmented SSMs asks whether state space models can serve as efficient agent backbones when they have the right tools and training data. This is a systems-level version of the compute question. Transformers are not the only possible substrate for long reasoning, but alternative sequence models must still handle arithmetic, code, and length generalization. The paper matters because agent capability depends on the backbone's memory and control properties, not only on the external tool wrapper.

3. Turn tools into part of the reasoning loop

code, proof, math

Tool use changes reasoning from text prediction into interaction with a stricter object. Code can execute, a prover can reject a proof, and a graph algorithm can expose whether a proposed plan respects structure. These papers show that tools are useful not because they decorate an agent, but because they convert vague intermediate claims into artifacts with consequences.

ICLR 2026THOR
THOR trains mathematical reasoning with tool calls, combining episode-level answer reward with step-level feedback about code or tool-call success. The key idea is that a math agent should not be rewarded only at the final answer; it should also learn whether the intermediate operations it chooses are executable and relevant. This is a bridge between chain-of-thought and programmatic verification.
ICLR 2026Actions Speak Louder than Prompts
Actions Speak Louder than Prompts argues that executable code can be a better interface than prompt-only interaction for long-text and high-degree graph settings. The deeper point is representational: some structures are awkward to reason about as prose but natural to manipulate as code. When the task has graph structure, the model can offload part of reasoning into executable operations instead of holding everything in fragile context text.
ICLR 2026CRAMF
CRAMF tackles autoformalization by retrieving Mathlib4 definitions for the core concepts needed to translate informal mathematics into Lean. The failure mode is not merely that the model lacks mathematical intuition; it may use the wrong formal object. Retrieval grounds the translation in the library's actual vocabulary, which makes the reasoning task less like free-form paraphrase and more like choosing the correct formal handles.
ICLR 2026VERINA
VERINA compares code correctness with proof success in verifiable programming tasks and finds a large gap. That gap matters because code can often pass tests while the proof obligation demands a stronger, more general argument. The paper is useful for this theme because it shows that tool use has levels: execution checks one kind of consequence, while formal proof checks whether the model can state and justify the invariant behind the code.
ICLR 2026AutoEP
AutoEP uses real-time search-dynamics feedback to reduce hallucinated optimization strategies. The problem is that an LLM asked to control an algorithm can invent plausible but ungrounded moves. By feeding quantitative diagnostics back into the loop, the system makes the model's planning depend on observed algorithm behavior rather than rhetoric about what should work.

4. Retrieve, ask, and update under uncertainty

information control

Reasoning often fails because the model acts before it has the right information. These papers view question asking, retrieval, and reward calibration as parts of the same problem: the model must decide which missing information is worth acquiring and how much trust to place in partial feedback.

ICLR 2026Rational Agents
Rational Agents applies Bayesian experimental design to language-model agents. It improves question asking and action selection through Monte Carlo expected-information-gain inference. In simple terms, the agent should ask the question whose answer will most reduce uncertainty about what to do next. This matters because many agent failures are not caused by weak language alone; they come from taking action while still missing the decisive fact.
ICLR 2026LoongRL
LoongRL couples retrieval and reasoning in long contexts. Its tasks require tracing UUID chains, finding the true question, retrieving the right facts, and rechecking answers amid distractors. The first-principles challenge is attention control: the model must not merely fit a long context window, it must route attention through the pieces that form the answer path. This connects long-context work directly to agent planning.
ICLR 2026HERO
HERO uses stratified reward normalization, bounding reward-model scores inside verifier-defined groups and emphasizing prompts where dense feedback matters. The practical issue is that reward scores can be hard to compare across different prompt types. HERO makes the feedback more locally meaningful, so optimization pressure is focused where it can actually distinguish better reasoning from worse reasoning.

5. Search over constrained worlds

planning and feasibility

Planning is not just listing steps. The plan has to obey constraints, fit together across time, and remain feasible as decisions accumulate. These papers use candidate sets, feasibility projection, population search, diffusion denoising, and latent programs to make planning less like verbal intention and more like structured construction.

ICLR 2026NEXCO
NEXCO generates feasible partial solutions for combinatorial problems using confidence-guided candidate sets and feasibility projection. The core problem is that a locally plausible choice can make the remaining problem impossible. By keeping candidate sets constrained and projecting toward feasibility, the method treats planning as controlled expansion through a solution space rather than unconstrained sequence generation.
ICLR 2026CDGS
CDGS embeds population search, likelihood pruning, and overlap resampling inside diffusion denoising. The conceptual move is to combine generative modeling with explicit search pressure. Diffusion can propose compositional plans, but planning needs a way to prune weak branches and reconcile overlapping parts. CDGS is part of the broader shift from one-shot generation to guided construction.
ICML 2026L2T
L2T learns latent programs as explanations for non-textual observations. Instead of predicting future frames directly, it tries to infer an executable theory that accounts for what was observed. This matters because a theory can support planning and counterfactual reasoning in a way a surface prediction cannot. It is the same reason program induction keeps returning in agent work: a compact rule can guide action outside the exact examples seen.
ICLR 2026Visual Planning
Visual Planning uses image sequences as intermediate plans for spatial and geometric reasoning. Some tasks are hard to solve through words because the important state is spatial. A visual trajectory can preserve layout, motion, and geometric constraints directly. The paper broadens the idea of chain-of-thought: the useful intermediate representation may be a sequence of images rather than a sequence of sentences.

6. Ground reasoning in perception and internal mechanisms

multimodal and repair

The last group asks how reasoning connects to the signals underneath it. A model may need to identify the visual evidence that matters, reason across audio and text, use metaphor as a structured bridge between domains, or intervene on internal circuits when a reasoning path goes wrong. These papers make reasoning less text-centric and more grounded in the representations that feed the answer.

ICLR 2026VC-STaR
VC-STaR builds VisCoR-55K with contrastive examples that force precise visual evidence identification. The problem is that a vision-language model can answer correctly for the wrong visual reason, which makes its reasoning brittle. By using contrast, the dataset pressures the model to notice the exact cue that distinguishes one answer from another. This is grounding as an anti-shortcut device.
ICLR 2026UALM-R1
UALM-R1 uses both text and audio in intermediate thinking steps for complex generation tasks. Its importance is that reasoning is not confined to written language once the task itself is multimodal. If sound carries timing, speaker, or acoustic information that text misses, then a useful reasoning trace has to preserve and transform that information instead of translating everything into a lossy text-only channel.
ICML 2026MetaphorVU
MetaphorVU uses a metaphor knowledge graph at inference time to improve high-order video understanding. The paper treats metaphor not as decoration but as a mapping device between domains. That matters for reasoning because hard video understanding often requires recognizing an abstract relation, not just an object. A structured metaphor graph gives the model a way to transfer relational patterns across situations.
ICLR 2026CRV
CRV uses attribution-graph analysis to target transcoder-feature interventions that repair faulty reasoning. Instead of only changing prompts or examples, it looks for internal features involved in a reasoning failure and intervenes there. This is important because it treats reasoning errors as mechanistic phenomena inside the model, not only as bad outputs. If successful, that kind of repair could make model debugging more surgical.
FIELD READ

What this theme says about ICML and ICLR

The big picture is that reasoning is becoming less of a prompt style and more of an engineering object. The papers do not agree on one mechanism. Some add better traces, some hide thought inside latent computation, some use executable tools, some add retrieval and Bayesian information gathering, some search over constrained worlds, and some repair internal circuits. But they agree on the same pressure: a capable model must control its own intermediate work.

That is why this theme sits next to evaluation, agents, software reliability, and multimodal systems. Once models are asked to do real tasks, the important unit is not the final string. It is the path from observation to intermediate state to action to checked consequence. Reasoning, planning, and tool use are the machinery that makes that path work.
