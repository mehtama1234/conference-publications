Theory follows deployment needs

The central problem is that clean theoretical assumptions often break exactly where systems are deployed. Real models run in floating point, call expensive oracles, face bounded human verification, need privacy guarantees in finite regimes, and optimize post-training objectives that may no longer match the pretrained model.

Problem

Deployment exposes assumptions that were harmless on paper: exact arithmetic, free oracle calls, unlimited human judgment, asymptotic privacy, perfectly aligned losses, and unbounded trust in predictions.

Approaches

The papers redefine the theoretical object around the deployed constraint: finite-regime privacy, hypothesis-testing unlearning, realistic oracle costs, bounded verification games, and prediction-use budgets.

Connecting read

This is theory becoming more honest about the environment in which models run. The goal is not to weaken rigor, but to aim rigor at the real bottleneck.

READ

The Big Picture

A deployment constraint is not an implementation detail if it changes what the guarantee means. If an algorithm assumes oracle calls are constant time but the natural oracle query costs scale with set size, the complexity theorem is pointed at the wrong machine. If a neural network proof assumes exact real arithmetic, it may not describe the model that runs on hardware. If unlearning is certified by a definition that does not match Gaussian noise in high-dimensional regimes, the certificate may be mathematically valid but operationally weak. This theme collects papers where the theory is pulled toward the actual conditions of use.

The same shift appears in evaluation and alignment. Humans cannot verify arbitrary model outputs globally, so benchmarking becomes a game where humans check local claims. Direct oracle verification may be unavailable, so downstream utility becomes evidence. Prediction advice can improve online algorithms, but only if the algorithm budgets how much it trusts the prediction and preserves worst-case guarantees. Post-training losses can become mismatched with strong pretrained models because low-probability supervision tokens may be noisy. The larger message is that theory becomes more useful when it models the messy interface where systems meet cost, hardware, humans, and incentives.

ANATOMY

The concrete object is the deployed guarantee

A deployment-aware theory paper is about a guarantee after real constraints are included: privacy noise, verifier limits, oracle cost, online prediction trust, finite precision, watermark distinguishability, or post-training objective mismatch.

What must stay fixed is the operational meaning of the guarantee. An unlearning certificate must answer the attacker question the deployment faces. A matroid oracle theorem must charge the query the machine actually pays. A floating-point expressivity result must describe finite arithmetic rather than ideal reals. A learning-augmented algorithm must preserve worst-case behavior while using predictions. A benchmark theory must preserve the fact that humans can only verify local claims.

What may change is the mathematical model: privacy definition, noise family, verification game, utility proxy, cost model, regularized objective, hypothesis test, or finite-precision representation. The method works when the revised theory predicts the behavior of the deployed system more honestly than the cleaner abstraction. The failure boundary is decorative theory: the theorem is correct, but the object it proves does not match the system people actually run.

TOPIC 01

The theorem should model the deployed bottleneck

A theoretical result is useful when the expensive part of the proof object is the same expensive part the deployed system pays for.

Matroid Algorithms is the cleanest example. In the older abstraction, an oracle query can be treated as a unit-cost operation. That is mathematically tidy, but it can hide the real cost of the algorithm. For natural matroids such as graphic matroids, the query cost can scale with the size of the set being queried. Once that is true, an algorithm that looks efficient under unit-cost oracle access may be inefficient on the actual object.

The first-principles lesson is simple: complexity is not only about the number of steps. It is about the price of the primitive operation. If the primitive operation changes, the algorithmic story changes. Deployment-facing theory therefore starts by asking what the system really pays for: oracle calls, memory movement, floating-point operations, human checks, privacy noise, labels, feedback, or verification time.

TOPIC 02

Human verification is a bounded resource

A benchmark is not only a task distribution. It is also a theory of what a human can check.

Benchmarking at the Edge of Comprehension matters because it does not pretend that people can globally verify every hard model output. When an answer is near the boundary of human understanding, the human may not be able to decide whether the whole solution is correct. But the human may still verify a local claim, a smaller step, or a challenge inside an adversarial game. That changes the benchmark from "can the human grade the answer?" to "what pieces can the human reliably inspect?"

This is a deep shift for AI evaluation. If models become strong enough to produce long arguments, scientific proposals, code patches, or mathematical derivations that exceed a reviewer's attention, evaluation must become structured around bounded verification. The fixed object is not human authority in the abstract. It is the local checking capacity of the human in a concrete protocol.

TOPIC 03

Privacy and unlearning are attacker-facing claims

A privacy certificate is only as meaningful as the attack question it answers.

Gaussian certified unlearning in high dimensions and High-Dimensional Gaussian Mechanism both point at the same problem: privacy guarantees can become misleading when their asymptotic or mechanism assumptions do not match the deployed regime. If the system uses Gaussian noise in a high-dimensional proportional setting, the certificate should describe that regime. If a low-dimensional finite setting favors another noise family, the theory should not keep Gaussian mechanisms only because the standard abstraction is familiar.

The unlearning paper's hypothesis-testing view is especially useful for first principles. Unlearning is not a feeling that a model has "forgotten" a datum. It is a claim about what an attacker can distinguish after the removal procedure. What must stay fixed is the adversarial question. What may change is the privacy definition or mechanism used to answer it. Evidence would come from showing that the certificate tracks distinguishability in the regime where the deployed model actually runs.

TOPIC 04

Prediction help must come with a trust budget

Learning-augmented algorithms are useful only if they say how much damage bad predictions can cause.

Learning-Augmented Paging captures a pattern that shows up across modern ML systems. A predictor can help an online algorithm make better choices, but the predictor is not a proof. It can be wrong under shift, adversarial inputs, or ordinary statistical error. The algorithm therefore has to budget its dependence on the prediction while preserving a worst-case guarantee.

This is the theory version of a practical engineering rule: use the model where it helps, but keep a fallback invariant. The fixed object is the worst-case bound or recovery behavior. The thing that may change is how aggressively the algorithm follows the model's advice. The method works when good predictions improve performance and bad predictions cannot destroy the guarantee.

TOPIC 05

The objective has to match the decision people care about

A clean loss can be the wrong theory if deployment uses the model for a different kind of decision.

Beyond Log Likelihood argues that negative log likelihood can become prior-averse during post-training because it places heavy weight on low-probability supervision tokens. That matters when those tokens are noisy and the pretrained model is already strong. Axiomatic Value of Regularization makes a neighboring point from preference optimization: the choice of regularized objective changes what kind of winner or preference rule the system is actually optimizing. Catch-22 does the same for watermarking by tying distinguishability to KL-based hypothesis testing.

The common lesson is that the mathematical objective is not neutral. It chooses what errors matter, what evidence counts, and what tradeoff is treated as legitimate. A deployment-aware theory paper earns its keep by naming the real decision boundary: which answer wins, which text is distinguishable, which model update is trusted, which consequence is preferred, or which supervision token should be allowed to reshape the model.

EVIDENCE

What would prove the theory is aimed at the right object

The evidence is not just that the theorem is correct. It is that the theorem's object matches the deployed constraint it claims to clarify.

Matched primitive

The charged operation is the one the system really pays for: oracle query size, finite precision, memory, verification, or privacy noise.

Matched adversary

The privacy, watermarking, safety, or unlearning claim answers the distinguishability question the deployment actually exposes.

Matched verifier

The evaluation protocol reflects what humans, tools, or downstream consequences can check, not an imaginary perfect oracle.

Preserved fallback

When predictions help an algorithm, the proof still states what happens when the predictions are wrong.

Objective audit

The loss or preference rule is justified against the real deployment decision rather than treated as a harmless surrogate.

Regime test

The mechanism is evaluated in the finite, high-dimensional, noisy, or hardware-constrained regime where the guarantee will be used.

FAILURE MODES

How deployment theory becomes decorative

A deployment-facing theorem fails as guidance when its object no longer matches the system boundary it claims to explain.

Wrong attacker

Privacy, unlearning, or safety guarantees answer a weaker adversary than the deployed access pattern creates.

Wrong cost

The theorem charges oracle queries, arithmetic, verification, memory, or communication differently from the machine or workflow.

Ideal arithmetic

A result assumes real-valued computation while finite precision, rounding, overflow, or hardware kernels change behavior.

Proxy utility

The guarantee protects a clean mathematical objective that does not match the deployment decision or user risk.

Protocol mismatch

Benchmark, verifier, or human-review assumptions differ from the way the system is actually evaluated.

Prediction dependence

A learning-augmented guarantee hides how badly the method behaves when predictions fail or shift.

CLUSTERS

The Main Research Moves

1. Certification has to match the deployed privacy mechanism

Gaussian certified unlearning in high dimensions appears twice in the evidence because it makes two linked moves. First, it develops a certification notion better matched to Gaussian-noise mechanisms in proportional high-dimensional regimes. Second, it defines unlearning privacy as a hypothesis-testing problem and names the resulting Gaussian guarantee (phi, epsilon)-GPAR. The practical point is that a certificate is only useful if it reflects the actual noise, dimension, and adversarial question faced by the deployed system. High-Dimensional Gaussian Mechanism makes a neighboring move by introducing Spherical Generalized Gamma mechanisms that can outperform Gaussian and l2 mechanisms in finite low-dimensional settings, where asymptotic intuitions may choose the wrong privacy mechanism.

2. Verification is bounded by humans, oracles, and consequences

Benchmarking at the Edge of Comprehension treats humans as local claim verifiers in an adversarial benchmark game, which is closer to how hard outputs are actually checked. Consequence-Based Utility uses transferable method-level consequences to rank candidate solutions when direct oracle verification is unavailable, replacing impossible direct checking with downstream evidence. Matroid Algorithms revises constant-time oracle assumptions by charging query costs according to set size in natural matroids such as graphic matroids. These papers share a sober view: verification is not free, and theory should model the verifier's actual cost and reach.

3. Alignment and safety guarantees must model the operational objective

Beyond Log Likelihood argues that negative log likelihood can become prior-averse in post-training because it heavily weights low-probability supervision tokens that may be noisy for strong pretrained models. Axiomatic Value of Regularization argues that regularized von Neumann winner objectives have better axiomatic properties than regularized Borda-style standard RLHF, changing the normative object being optimized. Catch-22 uses KL-based hypothesis testing to characterize when watermarked and unwatermarked text become distinguishable. Learning-Augmented Paging shows that ML predictions should be trusted with an explicit budget so online algorithms retain worst-case guarantees. In all four cases, the guarantee has to describe the operational decision, not a cleaner surrogate.

4. Hardware and numeric representation are part of the model

Floating-Point Neural Networks studies minimum depth and width under floating-point parameters and operations rather than exact real arithmetic. That sounds narrow, but it captures the central pressure of the theme: the deployed model is the finite-precision object that runs, not the real-valued object in a proof. Once the numeric representation changes, expressivity and approximation claims can change with it. This is the same reason privacy, oracle cost, and verification limits matter: implementation details become theoretical details when they determine what the system can actually guarantee.
