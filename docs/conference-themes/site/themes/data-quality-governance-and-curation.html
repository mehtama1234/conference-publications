Problem

Data quality is not a single score. A sample can be legally unusable, statistically harmful, missing key covariates, poorly timed in training, or valuable only because its gradient points toward a target behavior.

Approaches

The papers use licensed-corpus construction, gradient and Hessian geometry, midtraining gap analysis, missingness-aware optimization, prompt-guided imputation, and contrastive graph theory.

Connecting read

This page is the focused companion to the broader data governance page: it isolates the narrow mechanics of evidence quality.

FIRST PRINCIPLES

The core problem

A dataset only looks like a clean table from far away. Up close, each row has a status: it may be licensed or not, complete or missing, easy or harmful, early or late, aligned or off-target. The optimizer does not know those statuses unless the training process encodes them. Data quality work is the attempt to make those hidden statuses explicit enough to act on.

The six papers here cover the minimum set of failure modes. Common Corpus asks whether the data can be used at all. DiReCT asks whether the data moves the late-pretraining optimizer in the desired direction. Midtraining Bridges asks where data should sit between broad pretraining and narrow posttraining. LIMSSR and Robust Contextual Optimization ask what to do when the observed row is incomplete. Difficult Examples Hurt Unsupervised Contrastive Learning asks when hard data becomes anti-signal rather than useful challenge.

CORE

Data quality means fit for a specific job

There is no universal property called "good data." A row is good only relative to what the system is allowed to do with it and what learning or decision problem it must support.

A legally clean web document may be useless for a medical task. A hard contrastive example may look informative but distort the similarity graph. A specialized reasoning sample may help during midtraining and hurt if introduced too late. A missing modality may be harmless for one prediction and decisive for another. A covariate may be blank in exactly the cases where the decision is riskiest.

The first-principles question is therefore: what status does this piece of evidence have right now? Is it allowed, complete, timed correctly, aligned with the target update, compatible with the objective, and honest about what it does not know?

METHOD

Why the method has to match the data failure

Bad data handling often comes from using the wrong repair for the wrong failure.

If the problem is legal provenance, gradient selection cannot fix it. If the problem is a late-training brittle direction, a license audit cannot tell whether the sample will damage capability. If the problem is missing evidence, filling one guessed value into the blank field can create false certainty. If the problem is a contrastive objective, "harder" examples can harm the learned geometry instead of improving it.

That is the shared lesson of the six papers. Data governance is not one filter. It is a routing problem: send each data failure to the check that can actually see it.

TOPIC 01

Permission is a learning constraint

A corpus cannot be a foundation if the model builder cannot say where it came from or whether it can be used.

Common Corpus is important because it treats legal usability and provenance as part of the technical object. A training set is not only a distribution over tokens. It is a set of source documents with rights, filtering history, language coverage, code coverage, deduplication choices, and reproducibility claims. If those facts are missing, then the model may train successfully while the scientific claim remains weak: other researchers cannot inspect the source mixture, reproduce the curation path, or reason about what rights the model inherited.

The first-principles point is that permission is upstream of optimization. A sample may contain useful signal, but if it cannot enter the training process under the intended governance rules, it is not valid evidence for that model. What must stay fixed is the source-status record. What may change is the mixture and filtering policy. The method works when source rights and provenance remain visible enough that downstream model claims can be audited rather than guessed.

TOPIC 02

The same example has different value at different training phases

Data quality depends on when the model sees the data, not only on what the data contains.

Midtraining Bridges Pretraining and Posttraining makes this intuitive. Broad pretraining teaches general support. Posttraining pushes the model toward narrower task behavior. If the gap between those two stages is large, a bridge mixture can help the model specialize without shocking it away from useful base capabilities. The example is valuable because of its position in the training path, not because it carries a universal high-quality label.

This teaches a more general rule for curriculum. The model's current state decides what an example can do. Early in training, a sample may help build broad representations. Late in training, the same sample may be too weak, too disruptive, or too specialized. What must stay fixed is the target capability and the base behavior that should survive. What may change is the phase, mixture weight, and curriculum placement.

TOPIC 03

A data point is an update direction

Late in training, the useful question is not only what domain a sample belongs to. It is what update the sample would induce.

DiReCT turns data selection into an optimization-geometry problem. A sample carries a gradient. Near the current model state, that gradient points in some direction through a curved loss landscape. Some directions improve the target behavior without damaging fragile old capabilities. Others look relevant by domain label but push through brittle curvature or interfere with what the model already learned.

This is why naive filtering can fail. "Looks like math data" or "looks like code data" is only a proxy. The stronger object is the sample's effect on the model. What must stay fixed is the validation target and the capabilities that should not be damaged. What may change is which samples are selected and how they are weighted. Evidence would show that gradient and Hessian information causes better late-training movement than simpler domain labels.

TOPIC 04

Hard examples are useful only if they preserve the intended relation

Difficulty is not automatically signal. In contrastive learning, hard examples can corrupt the graph the objective is trying to learn.

Difficult Examples Hurt Unsupervised Contrastive Learning is a useful correction to a common intuition. People often assume harder data makes stronger models. That can be true when difficulty sharpens the right distinction. But contrastive learning depends on neighborhood structure: which examples should be pulled together, which should be pushed apart, and how similarity should be represented. A hard example that creates misleading positives or negatives can damage that geometry.

The concrete object is not "a difficult sample." It is a difficult sample inside a similarity graph and objective. What must stay fixed is the representation relation the objective is meant to learn. What may change is removal, margin, temperature, or hard-example policy. The method works when the intervention repairs the learned geometry rather than merely making the training set easier.

TOPIC 05

Missing data must stay visible after repair

Imputation is dangerous when it turns absence into fake certainty.

LIMSSR and Robust Contextual Optimization with Missing Covariates both start from the same uncomfortable fact: the learner may not see all the evidence it needs. A modality may be missing. A covariate may be blank. Worse, missingness may be correlated with the target or the decision risk. A system that fills in a single guessed value and then treats it as observed fact has hidden the most important part of the problem.

The first-principles object is therefore a partial record plus uncertainty about plausible completions. For prediction, the model should keep track of what was observed, what was imputed, and how confident the imputation is. For decisions, the optimizer should choose actions that remain reasonable across plausible missing-covariate completions. What must stay fixed is the distinction between fact and reconstruction. What may change is the imputation path, mask, ambiguity set, or robust objective.

EVIDENCE

What would prove a data-quality claim

Each data-quality claim needs a different proof. A single benchmark score cannot prove legal usability, optimization value, and missingness safety at the same time.

Provenance audit

Common Corpus should expose enough source, license, filtering, and mixture information for independent reuse and inspection.

Phase ablation

Midtraining Bridges should show that the same specialized data has different value depending on when it enters the training path.

Directional causality

DiReCT should show that gradient and Hessian selection causes the late-training gain, not merely that selected data has a familiar domain label.

Objective-specific repair

Difficult-example interventions should improve the contrastive representation because they fix graph relations, not because they make the task easier in general.

Missingness calibration

LIMSSR should keep separate what was observed, what was imputed, and how uncertain the imputation remains.

Decision robustness

Robust contextual optimization should improve decisions across plausible covariate completions without becoming vacuous or over-conservative.

FAILURE MODES

How data quality becomes a slogan

The danger is treating "high quality data" as a universal label instead of asking what specific evidence status was proven.

Clean but unusable

A corpus looks curated but lacks rights, provenance, or reproducibility strong enough for open training claims.

Late but immovable

High-quality examples arrive after the optimizer or model state can no longer absorb them usefully.

Domain-label proxy

Data is selected because it looks in-domain, while its actual gradient direction damages the target capability.

Hard-example mythology

Difficult examples are assumed to help, but they distort the contrastive similarity graph.

Imputed certainty

A missing channel is filled in and then treated as observed fact, erasing the uncertainty the model should preserve.

Robustness theater

The ambiguity set is either too narrow to contain real missingness or so broad that the decision no longer carries useful information.

SYNTHESIS

Three pressure points in data quality

1. A corpus has to be usable before it can be useful

rights and provenance

The first quality gate is not statistical. It is whether the data can legally and operationally enter training, and whether future users can understand where it came from.

ICLR 2026Common Corpus
Common Corpus assembles roughly two trillion tokens of uncopyrighted or permissively licensed multilingual and code data, with provenance, filtering, and curation details. Its first-principles contribution is to treat legal usability as a technical constraint on pretraining, not an after-the-fact policy note. A corpus that cannot be audited, attributed, or reused safely is not a stable foundation for open model development.

2. Data quality depends on the training phase and optimizer state

optimization control

The same example can be good or bad depending on where the model is in training. These papers make data choice conditional on gradients, curvature, and the gap between general pretraining and specialized posttraining targets.

ICML 2026DiReCT
DiReCT recasts late-pretraining data choice as constrained sample selection using per-sample gradients and Hessian spectral geometry. The important move is to stop treating domain filtering as a proxy for usefulness. Late in training, the useful sample is the one whose update is compatible with the target direction and the local curvature of the model.
ICML 2026Midtraining Bridges Pretraining and Posttraining
Midtraining Bridges Pretraining and Posttraining shows that midtraining helps most when specialized data bridges a large distributional gap between broad pretraining and posttraining targets. The paper gives a concrete role to midtraining: it is not just extra data, but a transition layer. The best bridge data reduces the shock of specialization while preserving enough base-model support for posttraining to work.
ICLR 2026Difficult Examples Hurt Unsupervised Contrastive Learning
Difficult Examples Hurt Unsupervised Contrastive Learning models difficult examples through similarity graphs and shows why removal, margin tuning, or temperature scaling can improve bounds. The key lesson is that hard examples are not automatically good curriculum. In contrastive learning, some difficult samples create misleading neighborhood structure, so the data-quality rule has to depend on the objective.

3. Missing data is part of the problem, not a preprocessing nuisance

missingness

Missing covariates and missing modalities change what the learner can know. These papers treat incompleteness as uncertainty that must remain visible through prediction or decision-making.

ICML 2026LIMSSR
LIMSSR defines the training set itself as incomplete and uses prompt-guided imputation plus mask-aware uncertainty calibration. The conceptual point is that a missing modality is not just a blank input slot. The model needs to reason about what is absent, estimate what can be filled in, and keep uncertainty attached to the imputed signal.
ICML 2026Robust Contextual Optimization with Missing Covariates
Robust Contextual Optimization with Missing Covariates treats the missingness mechanism as part of the optimization model and preserves observation uncertainty through decisions. The paper matters because imputation alone can create false confidence. A decision system should know whether it is optimizing from observed facts or from uncertain reconstructed context.
FIELD READ

What this small theme adds

The larger data governance theme says data is a supply chain. This smaller page says quality is local and conditional. The usable corpus, the late-pretraining sample, the bridge dataset, the hard contrastive example, and the missing-covariate row each require a different quality test.

That is the practical takeaway: do not ask whether data is simply high quality. Ask high quality for which objective, at which training stage, under which rights, with which missing fields, and with what uncertainty carried forward.

In simple terms: a dataset is not trusted because it is large, clean-looking, or hard. It is trusted when the right evidence-status checks have been applied before the model or decision rule is allowed to use it.

CONCEPT BRIDGES

Where to read the larger pattern

Data is training pressure

Selection, ordering, and filtering matter through the model movement they cause. A data point is valuable when its update helps the intended behavior.

Synthetic data is evidence or contamination

Generated data either adds controlled evidence or feeds model bias back into training. The difference depends on source, check, mixture, and failure boundary.

Privacy and unlearning are recoverability claims

Data governance must include what remains recoverable after training. Rights and deletion claims matter only if they bound later model behavior.
