FIRST PRINCIPLE

Data And Compute Are Control Variables

A dataset is not a timeless pile of examples. It is closer to a sequence of pushes on a model that is changing while it learns. An example has source receipts, missing facts, duplicates, license limits, seller incentives, and value that depends on what the model has already seen. A serving system is not an implementation afterthought. It is the physical route through memory, cache, bandwidth, number precision, kernel layout, and latency.

The papers in this lane work when they make that substrate explicit. They ask which example should arrive while the model can still learn from it, which cache entry still affects future tokens, which smaller number format preserves the same behavior, which small update space can change safely, and which data source is lawful or strategically reliable.

FORMULA PASS

Paper-Specific Math Boxes

LR Decay Wastes Your Best Data

Object. An example's value as the actual model movement it can still cause at that training moment.

Why it works. An example can contain the right lesson and still arrive too late. If the step size has become tiny, the model sees the information but cannot move much from it. What must stay the same is the target behavior the lesson should improve. What may change is when the lesson arrives and how large a training step remains. Names used later: gradient for the example's push, and learning rate for the multiplier on that push.

effective value(x,t) = eta_t * <grad loss_x(theta_t), useful direction_t>

Evidence check. Compare the same high-value data at different training times, measure retained capability, and separate data quality from remaining model plasticity.

Midtraining Bridges And PRISM

Object. Like using stepping stones between a wide road and a narrow trail, the object is a transition data mix that helps the model move toward a narrower skill without a harsh jump.

Why it works. A model can lose old useful behavior if specialized data arrives as a sudden replacement. Bridge data makes the next mix close enough that the model can adapt while still keeping broad capability. What must stay the same is retained broad skill. What may change is the mix of examples used during the transition. Name used later: distribution for the recipe of examples in a stage.

choose D_mid so distance(P_pre, D_mid) + distance(D_mid, P_post) is easier than distance(P_pre, P_post)

Evidence check. Sweep insertion time, mixture weight, and data scale; measure downstream gains beside retained broad capability.

BLL-Loss, LALP, And OpenThoughts

Object. Reasoning traces as paths with local validity, not teacher strings to copy exactly.

Why it works. A trace can differ token-by-token from the teacher and still solve the problem. Outcome-aware or premise-local losses give credit to valid moves so the model learns transition structure rather than surface imitation.

trace score rewards valid transition s_i -> s_{i+1}, not only equality to teacher token y_i

Evidence check. Audit alternate correct traces, local premise accuracy, teacher-bias artifacts, and whether public trace recipes reproduce gains.

Sequential Data Values And NASH

Object. The value of the next example after accounting for what the selected set already covers.

Why it works. Two examples can repeat the same lesson, or one can unlock the value of another. So value is not just a score attached to each item alone. What must stay the same is the target utility. What may change is the already-selected set and the score pieces used for credit. Names used later: marginal contribution and utility factoring.

value(x | S) = U(S union {x}) - U(S); credit is stable when U decomposes into coherent parts

Evidence check. Report order sensitivity, redundancy effects, semivalue variance, and utility-component ablations.

OPUS, DiReCT, And HOBIT

Object. Like choosing practice problems by the habit they change, the object is the movement an example or batch would cause in the current model.

Why it works. Useful data should push the model toward the target, avoid delicate places where small changes hurt validation, and add contrasts the batch does not already contain. What must stay the same is target behavior without damaging retained skill. What may change is the selected example or batch. Names used later: gradient for the push, curvature for how delicate a direction is, and Hessian for the map that finds directions where small pushes change held-out behavior sharply.

select x when the example's push helps the target and avoids fragile directions

Evidence check. Compare metadata selection to push-based selection, track fragile-direction energy, and test batch diversity after hard-negative selection.

LIMSSR And Robust Missing-Covariate Optimization

Object. Decisions made while some background facts are visibly missing.

Why it works. Missing information should remain uncertain instead of being silently filled in as fact. The decision should work across the plausible completions still consistent with what was observed. What must stay visible is doubt from missing fields. What may change is which completion is true. Names used later: ambiguity set and covariates.

choose action a minimizing worst-case loss over x_missing in ambiguity set A(mask, observed x)

Evidence check. Vary missingness mechanisms, compare imputation-only baselines, report uncertainty calibration, and test whether hallucinated modalities change decisions.

Common Corpus, Hubble, And LM Memorization Capacity

Object. A dataset with source receipts plus tests for whether sensitive examples can be extracted later.

Why it works. Provenance makes the sample space auditable: where each example came from, what license applies, and what filtering happened. Controlled insertions make memorization observable. The data system can then separate lawful traceable evidence from hidden private-information exposure.

training distribution = samples with provenance constraints; leakage test estimates I(secret; model output)

Evidence check. Report source composition, license filters, duplicate rates, controlled canary extraction, and bits stored per parameter.

DHSA, TileLang, And einx

Object. Like planning a warehouse route for boxes, the object is where numbers sit, how they are grouped, and how far they must move before the computation can finish.

Why it works. A model can have enough context length on paper and still fail on a real machine if memory traffic dominates. What must stay the same is the intended tensor meaning and model behavior. What may change is tiling, layout, vectorization, and scheduling. Explicit layout makes the real bottleneck visible enough to improve without confusing shape transformations. Name used later: computation schedule.

runtime cost = FLOPs + bytes_moved / bandwidth + synchronization; capability needs feasible schedule

Evidence check. Report memory traffic, wall-clock latency, shape-correctness tests, kernel portability, and long-context behavior at the claimed scale.

ThinKV, STAR-KV, And EntroKV

Object. A shorter attention cache that still keeps the past evidence needed for future tokens.

Why it works. Cache entries are not equally important. Some past tokens still decide the next answer; others are repeated background. What must stay the same is the future answer behavior that depends on the past. What may change is which cache entries, ranks, or number precision are kept. Name used later: KL, a measure of how much the next-token odds change after compression.

keep cache r such that KL(P(next | full cache) || P(next | r)) stays small under memory budget B

Evidence check. Test long-range retrieval, multi-hop dependencies, rare-token evidence, latency/memory savings, and degradation versus context length.

ThunderAgent, Speculative Actions, And ADP

Object. Like preparing likely next steps in a kitchen while keeping unapproved dishes off the serving counter, the object is the agent's branches, tool state, checks, and reusable work records.

Why it works. Agent latency is often dominated by external work, not text generation. What must stay the same is verified world state: no guessed branch should change the task unless the checker accepts it. What may change is which likely branch is prepared early and which trace format stores the work. Speculation helps only when prepared branches can be checked before use; reusable traces help only when they preserve the variables needed for the next task. Name used later: agent execution graph.

speedup = saved tool/model time - wasted speculative branches - verifier overhead

Evidence check. Measure accepted speculation rate, side-effect safety, stale-state failures, trace transfer, and end-to-end task latency rather than token speed alone.

LiftQuant, TetraJet-v2, And Quantized Diffusion

Object. Like rounding every measurement in a long recipe, the object is the cheaper number path and the errors it carries forward.

Why it works. Low precision is safe only when the carried error stays too small to change behavior. What must stay the same is the training update or generated sample the full-number system would have produced. What may change is the number code, reset rule, outlier handling, or denoising step. These methods track repeated error instead of pretending each rounded number is an isolated accident. Name used later: compression map.

compressed state C(x) is valid when accumulated error ||Phi_T(C(x)) - Phi_T(x)|| stays below task tolerance

Evidence check. Track per-step error, outlier-channel damage, timestep sensitivity, training stability, and behavior changes at the same memory budget.

FOCUS And RePAIR

Object. The chance that generation enters a repetition loop and the chance it can escape once there.

Why it works. Pruning can preserve average score while changing the step-by-step behavior of generation. A model may still look good on short tests but become more likely to repeat itself in long output. Markov-like dynamics means the next token depends on the current prefix state; repair helps when it restores escape routes from repetitive states.

control degeneration by lowering P(enter loop) and raising P(exit loop | loop prefix)

Evidence check. Measure repetition loops, long-generation behavior, escape probability, perplexity tradeoffs, and failures hidden by short benchmark averages.

RAIN-Merging, FlexRank, And LoRA Gradient Descent

Object. Adaptation as allowed movement inside a small family of update directions.

Why it works. Merging and adapters are safe when the useful task change fits inside controllable directions and avoids directions that carry reasoning format or retained capability. What must stay the same is retained useful behavior. What may change is the size and direction family of the adapter movement. Names used later: rank and subspace.

Delta theta = P_safe(Delta task) with rank(Delta W) <= r and fragile subspace energy bounded

Evidence check. Report rank-energy curves, task-vector projections, retained reasoning behavior, and ablations that remove fragile-direction filtering.

Continual VLA, Skill Neologisms, GEPA, And DTO-KD

Object. Adding new behavior while keeping old behavior available.

Why it works. New behavior must be added without erasing old behavior or letting teacher objectives overpower the real task. Replay preserves representative old states, soft tokens localize skill access, Pareto search keeps several useful prompt tradeoffs alive, and dynamic distillation balances competing training pushes. What must stay the same is old skill access. What may change is the new skill or prompt tradeoff. Name used later: stability-plasticity.

update should improve new task while constraining old-task loss and teacher/task push conflict

Evidence check. Measure forgetting, replay coverage, skill-token locality, tradeoff-frontier movement, and push-conflict changes during distillation.

OBJECT 01

Training Path

LR Decay Wastes Your Best Data

Problem. High-quality examples can arrive after the learning rate has become too small to use them.

Object. Like giving the best lesson after class is almost over, the object is whether an example arrives while the model can still change from it.

Why it works. An example creates a push, but the step size decides whether that push changes the model. What must stay the same is the target behavior the example should improve. What may change is training time and remaining step size. Name used later: gradient for the training push caused by the example.

Connection. This is the training analog of test-time compute allocation.

Midtraining Bridges

Problem. Specialized data can help or damage a model depending on when it enters between pretraining and post-training.

Object. Like taking a ramp between a highway and a narrow side road, the object is a middle data mix that makes the training transition less abrupt.

Why it works. The bridge reduces the jump between broad pretraining and narrow downstream objectives while the model can still adapt. What must stay the same is retained broad ability. What may change is timing and mixture. Name used later: distribution for the recipe of examples used at that stage.

Connection. It is stepwise movement through training space.

PRISM

Problem. Reasoning specialization can overwrite general capabilities if the transition is too abrupt.

Object. Like adding a focused workshop without replacing the whole school curriculum, the object is a compact midtraining set that teaches harder operations while protecting broad skill.

Why it works. What must stay the same is general capability already learned. What may change is the added reasoning skill and the small data mix used to teach it. The specialized data acts as a controlled nudge rather than a new pretraining universe. Name used later: controlled perturbation for a limited change to the training path.

Connection. It is retention-aware curriculum design.

Procedural Pretraining

Problem. Later meaning-rich data may not teach step-by-step operators if the model never sees procedure early.

Object. Like practicing long division before word problems, the object is early examples that repeatedly show a reusable procedure.

Why it works. What must stay the same is the operation that later tasks need. What may change is the subject matter where the operation appears. Early procedural examples make reusable operations easier to form, so later language, code, and math data can reuse those operations instead of discovering them from scratch. Name used later: representation for the internal way the model stores those reusable operations.

Connection. It matches architecture-as-computation from the theory page.

OpenThoughts

Problem. Reasoning traces are generated artifacts with teacher and filtering bias.

Object. Like publishing the lab recipe instead of only the final dish, the object is the public process that created the reasoning paths: sources, teachers, filters, domains, and trace shapes.

Why it works. What must stay the same is trace usefulness for later reasoning. What may change is the source, teacher, filter, or domain mix. Inspectable pipelines let researchers compare which traces transfer and which only encode a private recipe. Names used later: distribution for the mix of traces and trajectory for the recorded reasoning path.

Connection. It supplies the data counterpart to RAGEN-2's trace diagnostics.

BLL-Loss And LALP

Problem. Exact imitation of a teacher sequence can punish alternative correct reasoning or hide local trace quality.

Object. Like grading each proof step for whether it follows, not whether it uses the teacher's exact wording, the object is feedback on useful local reasoning moves.

Why it works. What must stay the same is the validity of the step and the final outcome. What may change is the wording or route. The loss rewards moves that keep the reasoning path correct even when the full sequence differs from the teacher. Name used later: premise-local supervision.

Connection. It is credit assignment inside the training score for reasoning data: the model should learn which step helped, not only which final string matched.

OBJECT 02

Data Value

Sequential Data Values

Problem. Scoring each example independently misses repetition and useful complementarity.

Object. What the next example adds after the current selected set.

Why it works. Dynamic selection asks what new information an example adds after previous choices. What must stay the same is the dataset goal. What may change is the already-selected set. Name used later: marginal contribution.

Connection. It is fair-share credit for large data; Shapley-style methods are the formal family behind that idea.

NASH

Problem. Data valuation becomes noisy when one utility score mixes unrelated effects.

Object. A utility score split into coherent parts before assigning credit.

Why it works. Credit improves when the target is separated into pieces that mean something: accuracy, coverage, safety, format, or another specific effect. What must stay the same is the contribution being credited. What may change is the selected set used for comparison. Name used later: semivalue.

Connection. This matches aspect factoring in evaluation.

Data Market Pricing And Bayesian Truthful Valuation

Problem. Data sellers can exaggerate value, hide flaws, or respond strategically to payment rules.

Object. Like paying weather stations for useful reports, the payment rule should make honest useful information more rewarding than exaggeration or strategic hiding.

Why it works. What may change is the buyer, seller, price, and uncertainty about usefulness. What must stay the same is that better evidence is rewarded because it is better evidence, not because it is louder or easier to sell. Bayesian means beliefs about value are updated from evidence; mechanism means the rule that makes honest reporting the better move.

Connection. Data governance and market design are the same problem here.

OPUS

Problem. Metadata quality does not necessarily predict whether a document moves the model in the desired direction.

Object. The training movement an example would cause, checked against a target direction.

Why it works. The selector looks at parameter movement, not only surface features. Data is chosen by its effect on the training path. Curvature logic means it also cares whether that movement enters fragile directions.

Connection. It is DiReCT's fragile-direction logic applied to selection.

HOBIT

Problem. Contrastive learning depends on which examples share a batch.

Object. A batch that adds missing contrasts without repeating or contradicting what is already present.

Why it works. A negative example is valuable when it teaches a contrast the batch does not yet contain. Its value drops once that contrast is already covered. What must stay the same is coverage of useful contrasts. What may change is the next batch item. Name used later: submodular.

Connection. The batch is a temporary dataset with its own coverage needs.

ATLAS Multilingual Transfer

Problem. Equal language sampling ignores which languages help each other.

Object. A table of how training on one language changes performance on another.

Why it works. The table estimates cross-lingual added benefit, so data and compute can go where they buy coverage instead of following token counts alone. What must stay the same is target-language improvement. What may change is the source language used for training. Name used later: transfer matrix.

Connection. It is data value across language distributions.

OBJECT 03

Provenance And Missingness

Common Corpus

Problem. Hidden scraping and unclear licenses make a training dataset scientifically unstable.

Object. A corpus with explicit origin, permission, filtering, and multilingual/code composition.

Why it works. Like ingredient labels on food, source receipts make the sampled data auditable. What must stay the same is the right to know where examples came from and whether they were allowed into training. What may change is language, code mix, filter, or source. Name used later: provenance for source receipts.

Connection. It is provenance as dataset structure.

LIMSSR

Problem. Deployment may lack modalities that were present during training.

Object. Like grading a performance when one camera angle or sensor stream is missing, the object is a score based only on observed evidence while missing channels remain marked as unknown.

Why it works. What must stay the same is the decision's dependence on evidence actually present. What may change is which channels are missing. The model keeps missingness visible through masks and uncertainty instead of hallucinating a complete input. Name used later: partial observability.

Connection. It links data missingness to partial-observation agents.

Robust Contextual Optimization With Missing Covariates

Problem. Filling unknown background facts can turn ignorance into false certainty.

Object. A set of plausible completions left open by the missingness pattern.

Why it works. Decisions are chosen to work across plausible completions, so missingness remains part of the decision problem. What must stay visible is the set of still-possible worlds. What may change is the missing background fact. Names used later: ambiguity set and covariates.

Connection. This is robust evaluation uncertainty inside data systems.

Synthetic Data Selection

Problem. Synthetic examples can match the average case while missing important combinations or variation.

Object. Generated samples chosen to fill missing directions in the data.

Why it works. The selector looks for synthetic samples that add missing structure rather than redundant volume. More generated data helps only if it changes the right relationships among features. What must stay the same is the relationship the downstream task uses. What may change is which generated samples are added. Name used later: covariance.

Connection. It is coverage repair for training data.

FAC Synthesis And COMPACT

Problem. Instruction and visual datasets may leave capability holes hidden under aggregate coverage.

Object. A map of missing internal features or missing combinations of small skills.

Why it works. Synthetic data targets missing features or skill combinations instead of randomly increasing count. What must stay the same is coverage of the capability hole. What may change is the generated example used to trigger it. Name used later: feature activation.

Connection. It connects data design to benchmark aspect coverage.

Hubble And LM Memorization Capacity

Problem. Memorization risk is hard to measure when sensitive exposure is unknown.

Object. Known sensitive insertions and a measure of how many bits the model can store.

Why it works. Known insertions make private-information exposure observable; capacity estimates separate possible storage from ordinary pattern learning. Generalization means learning a reusable pattern, while leakage means reproducing a sensitive record.

Connection. It ties data governance to distinguishability tests.

OBJECT 04

Memory Movement

DHSA

Problem. Long context is irrelevant if memory traffic makes it impossible to run.

Object. Like dividing a huge table into pieces that fit on a workbench, the object is attention scheduled around the memory the GPU can actually hold.

Why it works. What must stay the same is the attention result the model needs. What may change is the order and size of the chunks moved through memory. The method changes data movement so 100K-token context can fit on commodity hardware. Name used later: tiling.

Connection. It is systems as information transport.

ThinKV And STAR-KV

Problem. KV caches dominate long-generation memory and latency.

Object. Like keeping only the notes that future sentences will still need, the object is a smaller cache that preserves generation behavior.

Why it works. What must stay the same is the next-token behavior that depends on past evidence. What may change is which slots are reused or which repeated cache patterns are compressed. ThinKV avoids expensive compaction by reusing slots; STAR-KV compresses repeated structure while keeping the evidence future tokens still need. Name used later: low rank for describing many cache values with fewer shared directions.

Connection. It is long-context state selection at serving time.

EntroKV

Problem. Uniform cache compression discards some states that still matter and preserves others that do not.

Object. Like keeping extra notes where the story could still go several ways, the object is a signal for which attention heads still carry unresolved future evidence.

Why it works. Heads with many still-plausible next-token outcomes are compressed less because they may still affect future decisions. What must stay the same is the future evidence needed by the answer. What may change is how much each head is compressed. Name used later: entropy for remaining uncertainty about what comes next.

Connection. It is the systems form of uncertainty-aware reasoning.

TileLang And einx

Problem. Tensor and kernel code can hide memory placement, scheduling, and shape meaning.

Object. Like putting labels and arrows on every box in a warehouse move, the object is an explicit record of data movement, vectorization, and tensor transformations.

Why it works. What must stay the same is the intended shape meaning and computed result. What may change is the layout or schedule used to run faster. Making the layout visible lets developers optimize the real bottleneck and avoid silent shape mistakes. Name used later: tensor layout notation.

Connection. It is proof pressure for systems code.

ThunderAgent And Speculative Actions

Problem. Agent latency often comes from external tools and stateful workflows, not only token generation.

Object. Like preparing likely next steps while waiting for a slow approval, the object is the work that can be safely done early and later accepted or rejected.

Why it works. What must stay the same is the real workflow state and the rule for accepting a speculative result. What may change is which model calls, tools, caches, or likely future actions are run ahead of time. Scheduling uses workflow structure to overlap or precompute actions whose acceptance can be checked. Name used later: resource graph for the map of calls, tools, states, and dependencies.

Connection. It links systems scheduling to controlled inference.

ADP And CRAMF

Problem. Agent traces and formal-math retrieval are not reusable if every benchmark encodes actions differently.

Object. Like using the same forms for work logs across teams, the object is a shared way to record actions, observations, retrieved definitions, and task state.

Why it works. What must stay the same is the meaning of each recorded action and evidence item. What may change is the task or domain. Consistent records let process data transfer across tasks and let retrieval find the exact definitions a proof needs. Names used later: interoperable trace schema and domain retrieval handle.

Connection. It is data standardization for agent state.

OBJECT 05

Approximation Maps

LiftQuant

Problem. Integer bit-widths create coarse compression choices that may not match a real memory budget.

Object. A code that gives more usable precision levels than ordinary bit-width choices.

Why it works. Lifting gives more choices than simply picking 2, 3, 4, or 8 bits. Compression becomes a tunable approximation, not a staircase of crude options. Effective precision means the behavior acts like a finer number format than the raw code suggests.

Connection. It is precision as a controlled budget.

TetraJet-v2

Problem. Low-precision training fails when rounding error becomes a repeated pattern rather than harmless noise.

Object. Like a scale that is always a little biased in the same direction, the object is the pattern of number errors that keeps pushing training off course.

Why it works. What must stay the same is the function the full-precision model was learning. What may change is the cheaper number format and the reset or outlier handling used during training. Double-block quantization, resets, and outlier handling reduce errors that keep accumulating in important directions. Names used later: oscillation, bias, and outlier channels.

Connection. It explains how cheaper training numbers can stay useful only when repeated error is tracked and controlled.

Error Propagation In Quantized Diffusion Models

Problem. Diffusion quantization errors accumulate across denoising steps.

Object. Like a recipe where a tiny measurement mistake repeats at every step, the object is how rounding error grows or shrinks through the whole denoising path.

Why it works. What must stay the same is the final sample behavior the full-precision model would have produced. What may change is the cheaper number format at each step. Compression is adjusted according to where errors build up through the sampler rather than judging one denoising step alone. Name used later: timestep-indexed error trajectory.

Connection. It connects systems compression to sample-path control.

FOCUS And RePAIR

Problem. Pruning can trigger repetition loops even when aggregate metrics look acceptable.

Object. Like a conversation getting stuck repeating the same sentence, the object is the chance of entering a loop and the chance of escaping once the loop starts.

Why it works. What must stay the same is stable long-form generation. What may change is which weights or channels remain after pruning. The methods identify where the model gets trapped and restore nearby alternatives that let generation move on. Name used later: token transition dynamics, meaning the next-word path created by each prefix.

Connection. It is degeneration as behavior over time, not only a one-shot score drop.

Layer Pruning Reassessment And MoE Compression

Problem. Removing layers or experts can preserve visible scores while damaging hidden capabilities.

Object. Like shrinking a repair crew while still needing the right specialist for each job, the object is a smaller structure that still routes the right cases to the right computation.

Why it works. What must stay the same is the behavior the full model produced on broad and rare cases. What may change is layer count, expert storage, or routing. The papers ask which layers or experts carry function under broad tests, not which parameters look redundant locally. Name used later: conditional computation.

Connection. Function preservation beats parameter-count reduction.

TabSwift, FFCC, IO-Aware GNNs, And SparseRL

Problem. Inference cost depends on confidence, activation cost, memory locality, and executable sparse layout.

Object. Like letting easy support calls end early while hard cases go to a specialist, the object is a rule for spending computation only where it can change the answer.

Why it works. What must stay the same is user-visible behavior. What may change is whether the system exits early, rewrites expensive activations, moves less data, or uses sparse kernels. The math is not just "make it smaller"; it is "skip work only when the skipped work would not have changed the result." Name used later: conditional computation under hardware cost.

Connection. Efficiency is a constrained decision policy.

OBJECT 06

Adaptation Subspaces

In-Place TTT

Problem. Deployment contexts can contain useful training signal, but full updates are too expensive and risky.

Object. Like taking quick notes during a meeting without rewriting the whole handbook, the object is a small set of temporary weights that can adjust to the current context.

Why it works. What must stay the same is the base model's broad behavior. What may change is a small output-facing interface for the current input stream. The method uses next-token prediction as a local practice signal, so the model adapts at inference time without reopening every parameter. Name used later: final-projection fast weights.

Connection. It is test-time learning as controlled state update.

RAIN-Merging

Problem. Merging instruction-tuned task vectors can damage thinking format or reasoning behavior.

Object. A merge that avoids fragile internal directions.

Why it works. The merge removes movement along directions likely to harm reasoning format. What must stay the same is retained reasoning behavior. What may change is which part of the task-vector movement is kept. Name used later: projection.

Connection. It is DiReCT's fragile-direction avoidance applied to model merging.

OpTI-BFM

Problem. Behavior foundation models must infer which task they are in while acting.

Object. A rule for trying uncertain tasks while using what is already known.

Why it works. Like choosing between a familiar route and a promising unknown shortcut, the model balances known value against useful uncertainty. What must stay the same is progress on the task. What may change is which action is explored. Name used later: upper-confidence linear bandit.

Connection. It links agents, bandits, and deployment-time control.

MF-GIA

Problem. A graph system may receive support examples without raw modalities or permission to update parameters.

Object. Like solving a new worksheet by looking at a few worked examples in the margin, the object is temporary task context built from support examples.

Why it works. What must stay the same is the stored model. What may change is the prediction for the current graph task after seeing the support set. The method treats examples as evidence available at inference time rather than as new training data, so adaptation happens through context instead of permanent weight changes. Name used later: support-set adaptation.

Connection. It is in-context learning for graph domains.

HTI

Problem. Hyperparameter changes produce behavior paths that are expensive to sample with full training runs.

Object. Like testing a few oven knobs instead of rebuilding the oven each time, the method learns how changing settings changes the finished result.

Why it works. What must stay the same is that predicted behavior changes match real training runs. What may change is the setting: learning rate, batch shape, data mix, or other training choices. The method helps when nearby settings produce a surface smooth enough to learn from fewer full runs. Name used later: manifold.

Connection. It connects systems tuning to behavior geometry.

P-GenRM

Problem. Reward evaluation is user-dependent, but training a separate reward model for every user is impractical.

Object. Like learning a new editor's taste by comparing it with editors whose preferences are already known, the object is a scoring rule that can borrow shared structure while keeping user differences visible.

Why it works. What must stay the same is the user's own preference evidence. What may change is which similar users or scoring rubric help interpret sparse feedback. The system works when shared patterns reduce data needs without flattening everyone into one average taste. Name used later: personalized reward model.

Connection. It links data systems to values and governance.

OBJECT 07

Continual State

CompSLOT

Problem. New visual concepts can overwrite old concepts if they spread through the full model.

Object. Like giving each new object its own labeled drawer, the method stores a new visual concept where it will not spill into unrelated concepts.

Why it works. What may change is the added concept. What must stay the same is access to old concepts that users still need. Localizing new knowledge reduces accidental overwriting because the model has a place to put the new feature instead of smearing it across everything. Name used later: concept slot.

Connection. It is MoE-style specialization for concepts.

FIRE

Problem. Reinitialization must make the model able to learn again without destroying useful old behavior.

Object. A measurement of how much a reset changes the old function's internal shape.

Why it works. A reset should loosen stuck parts without smashing the working parts. What must stay the same is the old useful function. What may change is the internal layout that opens room for new learning. Name used later: Frobenius-isometry deviation.

Connection. Continual learning is restart with a preservation check.

Continual VLA Forgetting

Problem. Embodied policies forget old robot skills while adapting to new tasks.

Object. Like keeping a few practice drills for old skills while learning a new one, the object is the saved experience that prevents useful behavior from disappearing.

Why it works. What must stay the same is the old skill behavior that deployment still needs. What may change is the new task and the small set of old examples replayed during adaptation. Replay helps only if it covers the skill states that would otherwise be overwritten. Name used later: replay buffer as a preservation constraint.

Connection. It is memory selection for behavior, not tokens.

Skill Neologisms

Problem. Adding a skill through full fine-tuning can be too broad and destructive.

Object. Like adding a new button that calls a procedure instead of rewiring the whole machine, the object is a small learned symbol that triggers the new skill.

Why it works. What must stay the same is the base model's existing behavior. What may change is the meaning attached to the new symbol. The model learns how to use that symbol as a handle for a procedure, so skill access is localized rather than spread across all parameters. Name used later: trainable soft token.

Connection. It matches Skill-Pro's executable procedural memory.

GEPA

Problem. Agent prompt improvement can require many expensive rollouts.

Object. Like reviewing a failed work session to write a better instruction, the object is the run record and the prompt variants it suggests.

Why it works. What must stay visible is the useful menu of tradeoffs: one prompt may be faster, another safer, another more accurate. What may change is which prompt variant is chosen. The method learns more from each rollout by turning failures into evidence for the next variant, while keeping options that are best for different goals. Name used later: Pareto search.

Connection. It is rollout-efficient search over agent policies.

Huxley-Goedel Machine

Problem. Coding agents need improvement paths, not only one-shot benchmark gains.

Object. Like tracking which code changes create better future versions, the score asks whether an agent change helps its descendants keep improving, not only whether it wins one benchmark once.

Why it works. What may change is the child agent, its tools, and its search behavior. What must stay visible is the inherited improvement path. The metric rewards changes that make later improvements easier or more reliable, so selection happens over families of agent versions rather than isolated edits. Name used later: lineage metric.

Connection. It is governance of recursive adaptation.

OBJECT 08

Movement Rulers

DiReCT

Problem. A late-training sample can move the model through helpful directions or fragile directions.

Object. The training push from one example, checked against places where small changes are forgiving or dangerous.

Why it works. Near the end of training, a lesson can still help or damage. What must stay the same is broad useful behavior. What may change is which examples are selected. The method asks where an example would push the model before using it. Names used later: gradient for the push, curvature for local fragility, and Hessian for the direction-by-direction map showing where small pushes cause large validation changes.

Connection. It is the center of the data/systems lane because it treats data as a controlled movement, not as a static pile.

Neural Thickets

Problem. Pretraining may create many nearby specialists, but ordinary evaluation sees one checkpoint.

Object. Like checking which small adjustments around a tuned instrument can play different songs, the method asks which nearby model changes produce useful specialists.

Why it works. What may change is the task behavior. What must stay the same is that the base model does not need a full rewrite. Pretraining can create a region where small movements reach many related skills cheaply. Name used later: local parameter neighborhood.

Connection. It explains why small adapters and task vectors can work.

FlexRank And LoRA Gradient Descent

Problem. Low-rank adaptation saves cost, but rank limits what behavior can change.

Object. A stack of small update families whose size can grow when the task needs it.

Why it works. FlexRank spends more movement capacity only when the task needs it; LoRA theory studies the actual path taken by the factorized adapter. What must stay the same is useful base behavior. What may change is the number of independent update directions. Name used later: rank.

Connection. It is compression and adaptation under one movement budget.

DTO-KD

Problem. Teacher training pushes can conflict with downstream task pushes.

Object. Like listening to a tutor while still solving the actual assignment, the object is a balance between teacher pressure and task pressure.

Why it works. What must stay the same is downstream task progress. What may change is how much the teacher is followed at each point. The method prevents one push from dominating when it would damage the other goal. Name used later: multi-objective optimization, meaning training with more than one goal at once and checking when those goals ask for opposite moves.

Connection. It is conflict-aware training data.

Trust-Region LLM RL

Problem. RL post-training can chase verifiable reward while breaking useful base-model behavior.

Object. Like letting a driver improve a route without leaving familiar roads, the update can improve reward only while behavior remains close to the trusted model.

Why it works. What may change is the response pattern that earns better reward. What must stay the same is the base behavior users still rely on. The boundary keeps reward training from making one large jump into behavior that scores well but breaks hidden capability. Name used later: trust region.

Connection. It is deployment safety as bounded movement.

L2Seg And PCD

Problem. Search and generation waste effort if solved substructures are repeatedly reconsidered or if generators stay too close to existing data.

Object. Like saving a solved stretch of a route on a map, then exploring beyond the familiar neighborhood, the object is reusable path pieces plus movement toward useful new regions.

Why it works. What must stay the same is the final solution quality. What may change is whether the search reuses a solved segment or pushes a generated sample away from overfamiliar examples. L2Seg avoids re-solving known subpaths; PCD spends sampling effort where novelty still has value. Name used later: route-segment compression and positive contrastive divergence.

Connection. It links solver systems with generative discovery.

SYNTHESIS

The Cross-Paper Shape

Example To Push To Movement

LR Decay, Midtraining Bridges, DiReCT, OPUS, Sequential Data Values, HOBIT, BLL-Loss, and LALP all say that data matters through the update it creates. The useful question is not "is this example high quality?" but "what movement does this example cause given the current model, target behavior, and training moment?" What must stay the same is the target behavior. What may change is the example and training moment. Name used later: gradient for the direction one example pushes the model.

State To Cache To Latency

DHSA, ThinKV, STAR-KV, EntroKV, ThunderAgent, Speculative Actions, ADP, TileLang, and einx treat systems as information movement. Long context, tools, and retrieval work only when decision-relevant state stays available and physically affordable.

Compression To Preservation To Governance

LiftQuant, TetraJet, FOCUS/RePAIR, Layer Pruning, MoE Compression, Common Corpus, Hubble, PRISM, SlaClip, and source-signature work all ask what survives transformation. A model is trained, compressed, adapted, served, audited, and sometimes deleted. What must stay true through those changes is the preserved behavior, source rule, privacy promise, or evidence trail. Name used later: invariant.

FOCUSED CHAIN

Training-Path Value: From Example To Movement

The deep object in data selection is not the example by itself. It is the movement the example causes at a particular moment in training, under a particular update rule, after a particular selected set. A dataset is therefore a control sequence: each example is an intervention on a model that has already been changed by earlier examples.

LR Decay And Midtraining Bridges: Time Changes Value

Plain object. Like giving a lesson while the student is still able to use it, an example's value depends on when it arrives and how much the model can still move.

Why it matters. What must stay the same is useful movement toward the target without erasing retained skills. What may change is training phase, learning rate, and data mix. Name used later: gradient for the example's push.

Remaining failure. Timing can improve the target skill while eroding retained capabilities. The bridge must be evaluated as a path, not only as a final checkpoint.

effective value = learning_rate(t) * alignment(gradient_x, useful direction)

Sequential Data Values And NASH: Value Is Conditional On The Set

Plain object. Like adding one more ingredient after seeing what is already in the bowl, an example is useful only if it adds something not already covered.

Why it matters. What must stay the same is the target behavior being improved. What may change is the selected set that came before. Splitting utility reduces attribution noise, so the selector can distinguish repeated examples from complementary ones. Name used later: marginal contribution.

Remaining failure. Added value can become unstable after the model changes or when examples interact through long-range curriculum effects not visible in the local utility estimate.

marginal_value(x) = utility(S union {x}) - utility(S)

OPUS, DiReCT, And HOBIT: Choose Data By The Update It Induces

Plain object. Like choosing practice problems by what habit they change, these methods value an example by the push it gives the current model.

Why it matters. What must stay the same is movement toward the target without damaging fragile behavior. What may change is the example, batch, or contrast. OPUS and DiReCT ask whether the example pushes useful directions; HOBIT adds that value can live in the batch relation. Name used later: curvature, meaning the shape of places where small movement becomes risky.

Remaining failure. Directional selection can overfit the validation slice or miss brittle deployment behavior living outside the measured target direction.

select x when the example's push helps the target and avoids fragile movement

BLL-Loss, LALP, And OpenThoughts: Reasoning Data Needs Local Credit

Plain object. Like grading each step of a proof for whether it follows, reasoning data should reward useful moves, not just matching the teacher's exact wording.

Why it matters. Reasoning traces are paths. What must stay the same is the valid transition from one step to the next. What may change is the route if it still reaches the right answer. Public trace recipes make the path auditable. Name used later: local credit.

Remaining failure. Trace data can encode teacher shortcuts or filtering artifacts. Local credit must still be connected to final task success.

trace loss should reward valid transition, not only teacher-token match

The Training-Path Chain

Shared object. A control path through data mixes, selected examples, batches, losses, movement rulers, and checkpoints.

First-principles read. Data is not fuel. It is a sequence of interventions on a moving system. The right question is what state the model is in, what direction the example pushes, what capability should stay the same, and what later movement remains possible.

model_t + selected data_t + optimizer_t -> model_{t+1}
FOCUSED CHAIN

Serving-State Preservation: From Context To Affordable Memory

Systems papers become conceptually important when they change what information remains available at inference time. Long context, KV caches, kernel layout, retrieval handles, speculative actions, and trace schemas are all different ways of preserving state under physical limits.

DHSA, TileLang, And einx: Make Movement Visible

Plain object. Like organizing a kitchen so ingredients are already near the stove when needed, the system names where numbers sit, how they move through memory, and what shape each operation expects.

Why it matters. A model's theoretical context length is irrelevant if the memory path cannot execute. What must stay the same is the intended calculation. What may change is the layout and order of movement. Explicit tiling and tensor notation make hidden cost visible enough to improve and audit.

Remaining failure. A faster kernel can still change numerical behavior, hide shape assumptions, or tune the wrong bottleneck for production workloads.

runtime capability depends on computation plus memory schedule

ThinKV, STAR-KV, And EntroKV: Cache State Is A Kept-Evidence Problem

Plain object. Like keeping only the notes that might change tomorrow's answer, a compressed cache should preserve old facts that future tokens still need.

Why it matters. KV entries are not equally useful. What must stay the same is the future decision that full context would have supported. What may change is how much past state is stored. Slot reuse, low-rank cache structure, mixed precision, and uncertainty-aware retention work when they preserve the past information that future tokens still need. Name used later: sufficient statistic, meaning a smaller cache record that still keeps the old facts needed by future tokens.

Remaining failure. Rare evidence can have low average salience, and a compressed cache can pass short tests while failing long-range retrieval or multi-hop dependency tasks.

retain r so P(next token | r) stays close to P(next token | full cache)

ThunderAgent, Speculative Actions, And ADP: Agent Systems Preserve Workflow State

Plain object. Like prepping likely ingredients before the final order is confirmed, the system can prepare likely future actions only if a later check accepts or rejects the branch before it affects the real task.

Why it matters. Agent latency is not only token latency. Tool calls and environment transitions dominate. What must stay the same is the workflow state seen by the real user or environment. What may change is which likely branch is prepared early. Speculation helps only when guessed work has checker gates.

Remaining failure. Speculation can precompute the wrong branch, hide side effects, or create stale state. A trace schema can normalize away exactly the failure variable needed for debugging.

agent speedup requires predicted branch + verifier, not blind pre-execution

LiftQuant, TetraJet, And FOCUS/RePAIR: Compression Must Preserve Dynamics

Plain object. Like replacing precise gears with cheaper parts and then checking whether the machine still runs through the whole cycle, compression must be judged over repeated behavior, not only one output.

Why it matters. A low-bit or pruned model is not merely smaller. It is a system with different step-by-step behavior. What must stay the same is the function users rely on over time. What may change is number precision, removed layers, or sparse execution. Quantization error can accumulate; pruning can alter token transition loops.

Remaining failure. Aggregate metrics can miss repetition loops, outlier-channel damage, long-horizon drift, or hardware-specific differences between test and deployment.

compression is safe only when error trajectory stays below behavior threshold

The Serving-State Chain

Shared object. A physically constrained state channel: context, cache, tensor layout, tool state, trace state, and compressed function all compete for memory, latency, and fidelity.

First-principles read. Systems work changes capability because it changes which state survives to the next decision. The key invariant is not model size. It is whether the future decision remains conditionable on the evidence that matters.

full state -> affordable retained state -> next decision -> verifier
