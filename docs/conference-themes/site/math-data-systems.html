FIRST PRINCIPLE

Data And Compute Are Control Variables

A dataset is not a timeless pile of examples. It has order, provenance, missingness, redundancy, licensing, source incentives, and marginal value under a training objective. A serving system is not an implementation afterthought. It is a physical channel with memory traffic, cache state, bandwidth, precision, kernel layout, and latency.

The papers in this lane work when they make that substrate explicit. They ask which example should arrive while the optimizer can still move, which cache entry still affects future tokens, which bit-width preserves function, which adapter subspace can change safely, and which data source is lawful or strategically reliable.

OBJECT 01

Training Path

LR Decay Wastes Your Best Data

Problem. High-quality examples can arrive after the learning rate has become too small to use them.

Object. Data value as a function of optimizer time.

Why it works. An example creates a gradient, but the step size decides whether that gradient changes the model. Curriculum quality is therefore path-dependent, not an intrinsic property of the example.

Connection. This is the training analog of test-time compute allocation.

Midtraining Bridges

Problem. Specialized data can help or damage a model depending on when it enters between pretraining and post-training.

Object. A bridge distribution over a parameter trajectory.

Why it works. The bridge reduces the jump between broad pretraining and narrow downstream objectives while plasticity remains. Timing and mixture become variables in the optimization path.

Connection. It is distributional transport in training space.

PRISM

Problem. Reasoning specialization can overwrite general capabilities if the transition is too abrupt.

Object. Compact high-quality midtraining that preserves broad state while adding harder operators.

Why it works. The model receives targeted movement without a full distribution replacement. The specialized data acts as a controlled perturbation rather than a new pretraining universe.

Connection. It is retention-aware curriculum design.

Procedural Pretraining

Problem. Later semantic data may not teach algorithmic operators if the model never sees procedural structure early.

Object. A warm-start distribution over compact procedures.

Why it works. Early procedural examples bias the representation toward reusable operations. Later language, code, and math data can reuse those operators instead of discovering them from scratch.

Connection. It matches architecture-as-computation from the theory page.

OpenThoughts

Problem. Reasoning traces are generated artifacts with teacher and filtering bias.

Object. A public distribution over reasoning trajectories plus recipe metadata.

Why it works. Inspectable pipelines let researchers compare which traces transfer. Reasoning data becomes experimental infrastructure rather than private folklore.

Connection. It supplies the data counterpart to RAGEN-2's trace diagnostics.

BLL-Loss And LALP

Problem. Exact imitation of a teacher sequence can punish alternative correct reasoning or hide local trace quality.

Object. Outcome-aware and premise-local supervision over reasoning paths.

Why it works. The loss is aligned with logical or local validity rather than teacher-token identity. Useful intermediate moves remain learnable even when the full sequence differs.

Connection. It is credit assignment inside the data objective.

OBJECT 02

Data Value

Sequential Data Values

Problem. Scoring each example independently misses redundancy and complementarity.

Object. Marginal contribution conditioned on the already selected set.

Why it works. Dynamic selection asks what new information an example adds after previous choices. Value is sequential because the dataset being built changes the utility of the next item.

Connection. It is Shapley-style credit made operational for large data.

NASH

Problem. Data valuation can become noisy when the utility function mixes unrelated effects.

Object. Decomposed utility components for more reliable semivalue credit.

Why it works. Credit assignment improves when the target utility is factored into coherent parts. The method reduces variance in the attribution object rather than only changing the estimator.

Connection. This matches aspect factoring in evaluation.

Data Market Pricing And Bayesian Truthful Valuation

Problem. Data sources can be strategic, and reusable data is not consumed when sold.

Object. A mechanism over non-rival information goods.

Why it works. Pricing and truthfulness conditions shape seller behavior so useful evidence reaches buyers without rewarding distortion. Data quality depends on equilibrium incentives.

Connection. Data governance and mechanism design are the same problem here.

OPUS

Problem. Metadata quality does not necessarily predict whether a document moves the model in the desired direction.

Object. Optimizer-shaped effective update projected onto a target direction.

Why it works. The selector looks at the parameter movement an example would induce, not only at surface features. Data is chosen by its causal effect on the training path.

Connection. It is DiReCT's curvature logic applied to selection.

HOBIT

Problem. Contrastive learning depends on which examples share a batch.

Object. A submodular batching objective over hard, informative, non-contradictory negatives.

Why it works. A negative example has high value when it covers a missing contrast and lower value after that contrast is already represented. Batch construction becomes structured optimization.

Connection. The batch is a temporary dataset with its own geometry.

ATLAS Multilingual Transfer

Problem. Equal language sampling ignores which languages help each other.

Object. A transfer matrix over language pairs.

Why it works. The matrix estimates cross-lingual marginal benefit, so data and compute can be allocated where they buy coverage instead of following token counts alone.

Connection. It is data value across distribution families.

OBJECT 03

Provenance And Missingness

Common Corpus

Problem. Hidden scraping and unclear licenses make a training distribution scientifically unstable.

Object. A corpus with explicit origin, permission, filtering, and multilingual/code composition.

Why it works. The empirical distribution becomes auditable. Reproducibility and legality are constraints on the sample space, not paperwork after training.

Connection. It is provenance as dataset geometry.

LIMSSR

Problem. Deployment may lack modalities that were present during training.

Object. Conditional sequence-to-score reasoning under missing observations.

Why it works. The model keeps missingness visible through masks and uncertainty instead of hallucinating a complete input. The score conditions on what is actually observed.

Connection. It links data missingness to partial observability in agents.

Robust Contextual Optimization With Missing Covariates

Problem. Imputation can turn unknown covariates into false certainty.

Object. An ambiguity set induced by the missingness mechanism.

Why it works. Decisions are optimized across plausible completions, so missingness remains part of the feasible decision problem. The optimizer cannot silently trust guessed values.

Connection. This is robust evaluation uncertainty inside data systems.

Synthetic Data Selection

Problem. Synthetic examples can match mean behavior while missing covariance structure.

Object. Distribution design under high-dimensional covariance constraints.

Why it works. The selector looks for synthetic samples that supply missing geometric directions rather than redundant volume. More generated data helps only if it changes the right distributional moments.

Connection. It is mode coverage for training data.

FAC Synthesis And COMPACT

Problem. Instruction and visual datasets may leave capability holes hidden under aggregate coverage.

Object. Feature-activation coverage and composed atomic skill space.

Why it works. Synthetic data targets missing features or skill combinations instead of randomly increasing count. The generation objective is coverage repair.

Connection. It connects data design to benchmark aspect coverage.

Hubble And LM Memorization Capacity

Problem. Memorization risk is hard to measure when sensitive exposure is unknown.

Object. Controlled sensitive insertions and bits stored per parameter.

Why it works. Known insertions make leakage observable; capacity estimates separate possible storage from ordinary generalization. Privacy risk becomes quantitative.

Connection. It ties data governance to distinguishability tests.

OBJECT 04

Memory Movement

DHSA

Problem. Long context is irrelevant if memory traffic makes it impossible to run.

Object. Attention tiled around GPU memory limits.

Why it works. The method changes data movement so 100K-token context can fit on commodity hardware. Capability becomes a property of the memory path, not only model architecture.

Connection. It is systems as information transport.

ThinKV And STAR-KV

Problem. KV caches dominate long-generation memory and latency.

Object. Cache slots, low-rank cache structure, mixed precision, and kernel layout.

Why it works. ThinKV avoids expensive compaction by reusing slots; STAR-KV compresses structure while preserving generation behavior. Both treat cached state as an optimizable representation.

Connection. It is long-context state selection at serving time.

EntroKV

Problem. Uniform cache compression discards some states that still matter and preserves others that do not.

Object. Attention-head entropy as a proxy for unresolved future information.

Why it works. High-entropy heads are compressed less because they may still affect future decisions. Compression follows expected information value rather than a fixed budget.

Connection. It is the systems form of uncertainty-aware reasoning.

TileLang And einx

Problem. Tensor and kernel code can hide memory placement, scheduling, and shape semantics.

Object. Explicit notation for data movement, vectorization, and tensor transformations.

Why it works. Making the computation's layout visible lets developers optimize the real bottleneck and avoid shape mistakes. The language becomes part of the correctness and performance model.

Connection. It is proof pressure for systems code.

ThunderAgent And Speculative Actions

Problem. Agent latency often comes from external tools and stateful workflows, not only token generation.

Object. A resource graph over model calls, tools, KV caches, states, and likely future actions.

Why it works. Scheduling uses workflow structure to overlap or precompute actions whose acceptance can be checked. Wall-clock time becomes an optimization variable over the agent loop.

Connection. It links systems scheduling to controlled inference.

ADP And CRAMF

Problem. Agent traces and formal-math retrieval are not reusable if every benchmark encodes actions differently.

Object. Interoperable trace schemas and domain retrieval handles.

Why it works. Consistent actions, observations, and retrieved definitions let process data transfer across tasks. Infrastructure defines what experience can be reused.

Connection. It is data standardization for agent state.

OBJECT 05

Approximation Maps

LiftQuant

Problem. Integer bit-widths create coarse compression choices that may not match a real memory budget.

Object. A lifted binary code that projects to quasi-continuous effective precision.

Why it works. Lifting gives more representational choices than raw bit-width selection. Compression becomes a tunable approximation map, not a staircase of crude options.

Connection. It is precision as geometry.

TetraJet-v2

Problem. Low-precision training fails when quantization error becomes structured rather than harmless noise.

Object. Error modes from oscillation, bias, and outlier channels.

Why it works. Double-block quantization, resets, and outlier handling reduce persistent error in high-leverage directions. The method preserves function by modeling error dynamics.

Connection. It is error propagation theory inside hardware-efficient training.

Error Propagation In Quantized Diffusion Models

Problem. Diffusion quantization errors accumulate across denoising steps.

Object. A timestep-indexed error trajectory.

Why it works. Compression is adjusted according to how approximation errors flow through the sampler. The method respects dynamics instead of judging one denoising step in isolation.

Connection. It connects systems compression to sample-path control.

FOCUS And RePAIR

Problem. Pruning can trigger repetition loops even when aggregate metrics look acceptable.

Object. Loop-entry risk and loop-persistence risk in token transition dynamics.

Why it works. The methods identify where probability mass traps generation and increase escape mass near plausible alternatives. Compression is judged by behavior over time.

Connection. It is degeneration as dynamical-system failure.

Layer Pruning Reassessment And MoE Compression

Problem. Removing layers or experts can preserve visible scores while damaging latent capabilities.

Object. Structural approximation of conditional computation.

Why it works. The papers ask which layers or experts carry function under broad tests, not which parameters look redundant locally. Expert sparsity lowers active cost but leaves storage and routing structure to compress.

Connection. Function preservation beats parameter-count reduction.

TabSwift, FFCC, IO-Aware GNNs, And SparseRL

Problem. Inference cost depends on confidence, activation cost, memory locality, and executable sparse layout.

Object. Conditional computation under hardware-specific cost.

Why it works. Early exits avoid full computation on easy cases; FFCC changes expensive activations; IO-aware GNNs reduce traffic; SparseRL optimizes sparse CUDA behavior directly. Each method compresses work where it does not change the result.

Connection. Efficiency is a constrained decision policy.

OBJECT 06

Adaptation Subspaces

In-Place TTT

Problem. Deployment contexts can contain useful training signal, but full updates are too expensive and risky.

Object. Final-projection fast weights adapted by next-token-prediction-aligned loss.

Why it works. The update is localized to a small interface where current context can adjust behavior without rewriting the base model. Adaptation becomes bounded inference-time movement.

Connection. It is test-time learning as controlled state update.

RAIN-Merging

Problem. Merging instruction-tuned task vectors can damage thinking-token or reasoning subspaces.

Object. Projection away from fragile internal feature subspaces.

Why it works. The merge removes movement along directions likely to harm reasoning format. Task-vector arithmetic becomes safer when it respects representation geometry.

Connection. It is DiReCT's stiff-direction avoidance applied to model merging.

OpTI-BFM

Problem. Behavior foundation models must infer which task they are in while acting.

Object. Task inference as an upper-confidence linear-bandit problem.

Why it works. The model balances exploration and exploitation over possible tasks. Adaptation is framed as uncertainty reduction, not prompt parsing.

Connection. It links agents, bandits, and deployment-time control.

MF-GIA

Problem. A graph system may receive support examples without raw modalities or permission to update parameters.

Object. Inference-time support-set adaptation.

Why it works. The method uses examples as temporary context that changes predictions without changing the stored model. This is adaptation through observed task state.

Connection. It is in-context learning for graph domains.

HTI

Problem. Hyperparameter changes produce behavior paths that are expensive to sample with full training runs.

Object. Conditional output-distribution trajectories over hyperparameter settings.

Why it works. The model learns how behavior moves as settings change. Hyperparameters become coordinates in a learned behavior manifold.

Connection. It connects systems tuning to representation geometry.

P-GenRM

Problem. Reward evaluation is user-dependent, but per-user reward-model training is impractical.

Object. Preference transfer across similar users and adaptive scoring rubrics.

Why it works. The system borrows structure from nearby users while preserving individual scoring differences. Personalization becomes fast adaptation over a preference space.

Connection. It links data systems to values and governance.

OBJECT 07

Continual State

CompSLOT

Problem. New visual concepts can overwrite old representations if they diffuse through the full model.

Object. Object-centric concept slots.

Why it works. New knowledge is localized into semantic modules, reducing interference with unrelated concepts. Continual learning becomes controlled allocation of representational space.

Connection. It is MoE-style specialization for concepts.

FIRE

Problem. Reinitialization must add plasticity without destroying useful geometry.

Object. Frobenius-isometry deviation as a stability-plasticity measurement.

Why it works. The reset is tuned by how much it perturbs representation geometry. Old function is preserved while opening space for new learning.

Connection. Continual learning is geometry-aware restart.

Continual VLA Forgetting

Problem. Embodied policies forget old robot skills while adapting to new tasks.

Object. Replay buffer content as a preservation constraint.

Why it works. Small replay buffers can preserve or recover prior capabilities if they cover the right skill states. What is replayed controls the stability-plasticity tradeoff.

Connection. It is memory selection for behavior, not tokens.

Skill Neologisms

Problem. Adding a skill through full fine-tuning can be too broad and destructive.

Object. Trainable soft tokens as compact procedural handles.

Why it works. A new token localizes skill access while freezing the base model. The model learns a callable control symbol instead of rewriting all parameters.

Connection. It matches Skill-Pro's executable procedural memory.

GEPA

Problem. Agent prompt improvement can require many expensive rollouts.

Object. Trajectory reflection plus Genetic-Pareto search.

Why it works. Failures become structured text evidence for future prompt variants, and Pareto search preserves multiple useful tradeoffs. Adaptation spends rollouts where they improve the frontier.

Connection. It is data-efficient evolution over agent policies.

Huxley-Goedel Machine

Problem. Coding agents need improvement paths, not only one-shot benchmark gains.

Object. A clade-inspired lineage metric over agent descendants.

Why it works. The metric values changes that improve future search and inheritance. Continual improvement becomes selection over lineages rather than isolated edits.

Connection. It is governance of recursive adaptation.

OBJECT 08

Optimizer Geometry

DiReCT

Problem. A late-training sample can move the model along helpful flat directions or harmful stiff directions.

Object. Gradient alignment with validation-Hessian eigendirections.

Why it works. Curvature tells which parameter directions can absorb movement. Data selection becomes a constrained optimizer update.

Connection. It is the mathematical center of the data/systems lane.

Neural Thickets

Problem. Pretraining may create many nearby specialists, but ordinary evaluation sees one checkpoint.

Object. A local neighborhood of task-specialist vectors around pretrained weights.

Why it works. Adaptation searches a dense reachable region rather than all parameter space. Pretraining creates local geometry that later systems can exploit cheaply.

Connection. It explains why small adapters and task vectors can work.

FlexRank And LoRA Gradient Descent

Problem. Low-rank adaptation saves cost, but rank limits what behavior can change.

Object. Nested low-rank components and factorized adapter dynamics.

Why it works. FlexRank spends rank only when the task needs more capacity; LoRA theory studies the actual factorized path. Rank becomes a controllable movement budget.

Connection. It is compression and adaptation in one geometry.

DTO-KD

Problem. Distillation gradients can conflict with downstream task gradients.

Object. A dynamic balance between teacher loss and task loss directions.

Why it works. The method prevents one gradient from dominating when it would damage the other objective. Teacher knowledge is useful only when its direction is aligned with the task.

Connection. It is multi-objective optimization for training data.

Trust-Region LLM RL

Problem. RL post-training can chase verifiable reward while breaking useful model behavior.

Object. A bounded policy movement region.

Why it works. The trust region constrains updates so reward improvement does not leave the neighborhood where the base model's behavior remains coherent.

Connection. It is deployment safety as optimizer geometry.

L2Seg And PCD

Problem. Search and generation waste effort if stable substructures are repeatedly reconsidered or if generators remain trapped near existing data.

Object. Stable route segments and novelty-directed sample movement.

Why it works. L2Seg compresses solved subpaths into hypernodes; PCD pushes samples toward new high-value regions. Both control the path of optimization rather than only scoring endpoints.

Connection. It links solver systems with generative discovery.

SYNTHESIS

The Cross-Paper Shape

Example To Gradient To Movement

LR Decay, Midtraining Bridges, DiReCT, OPUS, Sequential Data Values, HOBIT, BLL-Loss, and LALP all say that data matters through the update it creates. The useful question is not "is this example high quality?" but "what movement does this example cause given the current model, objective, and optimizer state?"

State To Cache To Latency

DHSA, ThinKV, STAR-KV, EntroKV, ThunderAgent, Speculative Actions, ADP, TileLang, and einx treat systems as information movement. Long context, tools, and retrieval work only when decision-relevant state stays available and physically affordable.

Compression To Preservation To Governance

LiftQuant, TetraJet, FOCUS/RePAIR, Layer Pruning, MoE Compression, Common Corpus, Hubble, PRISM, SlaClip, and provenance-signature work all ask what survives transformation. A model is trained, compressed, adapted, served, audited, and sometimes deleted; the math is the invariant that remains true across those transformations.

FOCUSED CHAIN

Training-Path Value: From Example To Movement

The deep object in data selection is not the example by itself. It is the parameter movement the example causes at a particular moment in training, under a particular optimizer, after a particular selected set. A dataset is therefore a control sequence.

LR Decay And Midtraining Bridges: Time Changes Value

Mathematical object. A time-indexed gradient effect along the optimizer path.

Why it matters. An example can contain the right information and still arrive when the model can no longer move. Midtraining bridge data works when it enters before the plasticity window closes and reduces the distributional jump into specialized post-training.

Remaining failure. Timing can improve the target skill while eroding retained capabilities. The bridge must be evaluated as a path, not only as a final checkpoint.

effective value = learning_rate(t) * alignment(gradient_x, useful direction)

Sequential Data Values And NASH: Value Is Conditional On The Set

Mathematical object. Marginal contribution after previously selected examples and utility decomposition.

Why it matters. The next example is valuable if it adds information not already covered. Decomposing utility reduces attribution noise, so the selector can distinguish redundant examples from complementary ones.

Remaining failure. Marginal value can be unstable after the model changes or when examples interact through long-range curriculum effects not visible in the local utility estimate.

marginal_value(x) = utility(S union {x}) - utility(S)

OPUS, DiReCT, And HOBIT: Choose Data By The Update It Induces

Mathematical object. Gradient direction relative to target movement, curvature, and contrastive batch coverage.

Why it matters. OPUS and DiReCT make data selection causal: the example matters because it moves parameters along useful directions and avoids stiff harmful directions. HOBIT adds that value can live in the batch relation, not only the single example.

Remaining failure. Directional selection can overfit the validation slice or miss brittle deployment behavior living outside the measured target direction.

select x when gradient_x aligns with target and avoids fragile curvature

BLL-Loss, LALP, And OpenThoughts: Reasoning Data Needs Local Credit

Mathematical object. Supervision over trajectory segments, local premises, and outcome-compatible alternatives.

Why it matters. Reasoning traces are paths. Token imitation can punish correct alternate routes, while outcome-aware and premise-local objectives preserve useful intermediate moves. Public trace recipes make the path auditable.

Remaining failure. Trace data can encode teacher shortcuts or filtering artifacts. Local credit must still be connected to final task success.

trace loss should reward valid transition, not only teacher-token match

The Training-Path Chain

Shared object. A control path through distributions, selected examples, batches, losses, optimizer geometry, and checkpoints.

First-principles read. Data is not fuel. It is a sequence of interventions on a moving system. The right question is what state the model is in, what direction the example pushes, what capability should stay invariant, and what later movement remains possible.

model_t + selected data_t + optimizer_t -> model_{t+1}
FOCUSED CHAIN

Serving-State Preservation: From Context To Affordable Memory

Systems papers become conceptually important when they change what information remains available at inference time. Long context, KV caches, kernel layout, retrieval handles, speculative actions, and trace schemas are all different ways of preserving state under physical limits.

DHSA, TileLang, And einx: Make Movement Visible

Mathematical object. A computation schedule over memory layout, tensor shape, and data movement.

Why it matters. A model's theoretical context length is irrelevant if the memory path cannot execute. Explicit tiling and tensor notation make the hidden cost surface visible enough to optimize and audit.

Remaining failure. A faster kernel can still change numerical behavior, hide shape assumptions, or optimize the wrong bottleneck for production workloads.

runtime capability depends on computation plus memory schedule

ThinKV, STAR-KV, And EntroKV: Cache State Is A Sufficient-Statistic Problem

Mathematical object. A retained cache representation whose entries differ in future decision value.

Why it matters. KV entries are not equally useful. Slot reuse, low-rank cache structure, mixed precision, and entropy-aware retention work when they preserve the past information that future tokens still need.

Remaining failure. Rare evidence can have low average salience, and a compressed cache can pass short tests while failing long-range retrieval or multi-hop dependency tasks.

retain r so P(next token | r) stays close to P(next token | full cache)

ThunderAgent, Speculative Actions, And ADP: Agent Systems Preserve Workflow State

Mathematical object. A stateful execution graph over likely actions, verifier checks, tools, and normalized traces.

Why it matters. Agent latency is not only token latency. Tool calls and environment transitions dominate. Speculation helps when likely future actions can be prepared and then accepted or rejected by a verifier; trace schemas help when past actions can be reused across tasks.

Remaining failure. Speculation can precompute the wrong branch, hide side effects, or create stale state. A trace schema can normalize away exactly the failure variable needed for debugging.

agent speedup requires predicted branch + verifier, not blind pre-execution

LiftQuant, TetraJet, And FOCUS/RePAIR: Compression Must Preserve Dynamics

Mathematical object. An approximation map whose error evolves across generation or training time.

Why it matters. A low-bit or pruned model is not merely smaller. It is a different dynamical system. Quantization error can accumulate; pruning can alter token transition loops; sparse execution can change which behavior remains stable.

Remaining failure. Aggregate metrics can miss repetition loops, outlier-channel damage, long-horizon drift, or hardware-specific differences between test and deployment.

compression is safe only when error trajectory stays below behavior threshold

The Serving-State Chain

Shared object. A physically constrained state channel: context, cache, tensor layout, tool state, trace state, and compressed function all compete for memory, latency, and fidelity.

First-principles read. Systems work changes capability because it changes which state survives to the next decision. The key invariant is not model size. It is whether the future decision remains conditionable on the evidence that matters.

full state -> affordable retained state -> next decision -> verifier
