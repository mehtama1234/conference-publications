Research lane

Agents and reasoning as control over state

A model becomes an agent when its output changes what it will observe next. The ICML and ICLR papers in this lane are about that loop: a system observes state, spends computation, chooses a tool or action, changes an environment, checks the result, and decides whether to continue, recover, or stop.

FIRST PRINCIPLE

The Unit Is the Loop

A static model answer can be judged after it is written. An agent cannot be understood that way because the important object is the loop. The model sees an observation, carries some internal state, decides what action or tool call to make, receives a new observation, and then has to decide whether the world now looks better, worse, or merely different. Failure can happen at any point: the state can be incomplete, the plan can be impossible, the tool call can be malformed, the verifier can be gamed, the memory can be polluted, or the model can keep working after useful computation has stopped.

That is why this lane connects reasoning, browser agents, coding agents, long context, test-time compute, multi-agent coordination, and sandbox risk. These are not separate stories. They are different ways of asking how a learned model should control state under uncertainty. The deep shift is from "can the model say the answer?" to "can the system make progress while its own actions keep changing the problem?"

FIELD SHAPE

The Agent Control Stack

The papers form a stack of control surfaces. At the bottom is state: context windows, memories, files, browsers, terminals, simulators, repositories, and sandboxes. Above that is action: text, code, tool calls, UI clicks, proof steps, questions, search branches, and peer messages. Above that is feedback: executable tests, verifiers, reward models, human or LLM judges, trace diagnostics, and monitor alarms. Above that is policy: how much compute to spend, when to ask, when to defer, when to stop, and how to recover when the previous step made the state worse.

State
What the system can see and carry forward: prompt context, retrieved facts, memory, browser state, repository files, terminal output, hidden activations, or shared multi-agent history.
Action
What the system can change: answer tokens, tool calls, code edits, shell commands, UI operations, proof terms, questions to users, or messages to other agents.
Feedback
What tells the system whether the action helped: tests, compilers, proof kernels, reward signals, judges, visual checks, trace monitors, and adversarial probes.
Control
The policy that allocates thought and risk: sample more, retrieve, ask, search, steer activations, call a stronger verifier, coordinate peers, or stop before extra work becomes noise.

SUBTHEME 01

Reasoning and Planning

The basic problem is not producing a chain of thought; it is choosing useful intermediate work.

Long reasoning is valuable only when the intermediate computation changes the answer or makes the next action better. These papers attack that problem through better trace data, hidden-state thought, constrained planning, visual plans, latent programs, and sampling over candidate paths. The shared question is how a model decides which branch of work is worth keeping alive.

ICLR 2026

OpenThoughts

Builds a large teacher-generated reasoning-data pipeline across math, code, and science. The important idea is that reasoning supervision becomes an engineered input supply chain: the model is learning from traces whose diversity, correctness, and intermediate structure shape what it later treats as legitimate thought.

ICLR 2026

T3

Preserves useful prefixes from failed reasoning trajectories instead of discarding the whole rollout. That matters because long-horizon reasoning is built from partial moves; a final wrong answer can still contain a local step that should receive credit.

ICML 2026

PonderLM-2

Adds hidden-state thought steps before token prediction. The paper separates useful internal computation from visible explanation, which is crucial when extra reasoning should improve an answer without forcing the system to emit long, costly, or unfaithful prose.

ICLR 2026

NEXCO

Generates feasible partial solutions for combinatorial problems using confidence-guided candidate sets and feasibility projection. Planning becomes controlled expansion through a constrained solution space rather than a fluent list of steps.

ICLR 2026

Visual Planning

Uses image sequences as intermediate plans for spatial and geometric reasoning. It broadens chain-of-thought beyond text: when the relevant state is spatial, a useful plan may need to preserve geometry directly.

ICML 2026

L2T

Learns latent programs as explanations for non-textual observations. The paper is about inferring an executable theory of the observed world, which can support planning and counterfactual reasoning more robustly than surface prediction.

SUBTHEME 02

Tool Use and Agent Scaffolds

A tool is useful when it converts vague reasoning into a stricter artifact.

Tool use is not an accessory around a model. It changes the epistemology of the task. Code can execute, a prover can reject a proof, a browser can expose whether the right page state was reached, and retrieval can change the facts available for the next step. These papers ask how agents should call tools, learn from tool feedback, and build environments where tool behavior is measurable.

ICLR 2026

THOR

Trains math reasoning with tool calls, combining answer-level reward with step-level feedback about tool success. It treats a tool call as part of the proof process rather than a decorative side channel.

ICLR 2026

Actions Speak Louder than Prompts

Uses executable code as the interface for long-text and graph reasoning. The deeper claim is representational: some structures are easier to inspect and manipulate as programs than as prompt text.

ICLR 2026

CRAMF

Retrieves Mathlib4 definitions for autoformalization into Lean. The agentic issue is grounding: the model must pick the library object the proof assistant actually understands, not merely write a plausible mathematical paraphrase.

ICML 2026

MEnvAgent

Automates executable software-engineering environments across ten programming languages. The work matters because a benchmark task is only useful if the environment, dependency state, execution path, and verifier can be built reliably.

ICML 2026

TerminalTraj

Curates Docker images and verified terminal trajectories across domains. The object being evaluated is the command-line process itself: observations, commands, state changes, and checks.

ICLR 2026

ADP

Unifies browsing, coding, tool-use, and research trajectories across agent datasets. Its value is comparability: heterogeneous action traces become analyzable as the same kind of object instead of remaining isolated benchmark formats.

ICML 2026

Skill-Pro

Converts episodic traces into reusable executable skills with activation, execution, and termination conditions. The first-principles move is to stop treating experience as a transcript and start treating it as procedural knowledge that can be invoked when the current state matches the skill's preconditions.

ICLR 2026

AgentFlow

Coordinates planner, executor, verifier, and generator modules through evolving memory during live tool use. It makes explicit what many agent stacks leave implicit: failure can come from the handoff between modules even when each module is locally competent.

ICLR 2026

GEPA

Learns high-level rules from reasoning, tool calls, and tool outputs across whole system trajectories. The paper treats prompt improvement as system-level learning: the update should come from how the compound workflow behaved, not from isolated final-answer examples.

ICML 2026

ParetoPO

Optimizes tool-integrated agents across accuracy and tool-use efficiency. It makes the cost of tools visible: a tool call is valuable when it changes the reachable result, but wasteful calls create latency and expense without adding evidence.

SUBTHEME 03

Process Diagnostics

For agents, final success is too little evidence.

An agent can pass by luck, by exploiting a verifier, by following a brittle template, or by doing unnecessary work that happens not to break the task. Process diagnostics treat the trace as evidence. They ask whether the agent's effort, intermediate artifacts, recovery choices, and failure signatures are consistent with genuine task progress.

ICML 2026

RAGEN-2

Studies agentic reasoning traces and failure modes after reinforcement learning. The important object is not only whether the final answer improves, but whether the model learns a process that transfers rather than a brittle pattern that satisfies the training verifier.

ICML 2026

TRACE Effort

Measures low-effort verifier passing and process quality in reasoning traces. It targets the failure where a model learns to produce just enough surface work to pass, while the underlying search or checking behavior remains shallow.

ICML 2026

CE-Graph

Models workflows through failure signatures and edits workflow graphs using counterexample pools. The diagnostic signal is structural: which counterexamples reveal where a math, code, or QA workflow breaks.

ICML 2026

LLMs Get Lost

Examines how agents lose their place in long or complex processes. It is a state-tracking diagnosis: the agent may know individual facts but fail to preserve where it is in the task.

ICML 2026

RoTS

Studies robustness of task-solving agents under trace or state variation. The question is whether success survives changes in intermediate context, not only whether a clean demonstration works once.

ICLR 2026

WebDevJudge

Evaluates judges for web implementation comparisons. It belongs in diagnostics because web correctness includes layout, interaction, responsiveness, and behavior that source-only or text-only evaluation can miss.

ICML 2026

Hierarchical Thinking

Models chain-of-thought as transitions among latent cognitive states. The diagnostic value is that reasoning traces can have structure beyond token order; a successful trace may move through different abstract states than a failed trace even when both look verbose.

ICML 2026

Complex Reasoning/TRM

Represents reasoning traces as DAGs and evaluates macro and micro efficiency through preferences. The trace becomes a graph of dependency and reuse, which is closer to how real problem solving works than a single linear explanation.

ICML 2026

T2PO

Triggers reasoning interventions when marginal uncertainty change falls below a threshold. It treats being stuck as a measurable process state: if more thinking no longer changes uncertainty, the agent should change strategy rather than continue the same loop.

ICML 2026

MAP

Studies deployed agents through case studies and practitioner interviews. Its role is to keep diagnostics grounded in production reality: teams observe failures that benchmark-only research can miss, especially around handoffs, monitoring, latency, and user trust.

SUBTHEME 04

Test-Time Scaling and Verifier Loops

Inference compute is becoming a policy choice.

A model can sample multiple solutions, recurse, call a verifier, defer to a stronger checker, or stop early. The central issue is allocation: extra compute helps only if it is routed toward uncertainty and checked against a meaningful signal. These papers turn inference from a fixed decoding step into a budgeted control problem.

ICML 2026

ASAG

Controls reasoning length at inference time without retraining. The target is overthinking: extra generated tokens can become cost and noise unless the system has a way to stop when additional work no longer changes the answer.

ICLR 2026

Reasoning with Sampling

Separates the value of exploring several candidate paths from the value of permanently changing the model through reinforcement learning. It asks how much reasoning gain can come from search at inference time.

ICML 2026

Weak-Strong Verification

Uses calibrated weak verifier scores to accept, reject, or defer outputs to stronger costly verification. The mechanism is triage: spend expensive checking only when the cheap verifier is uncertain or risk is high.

ICML 2026

Global Resolution

Uses global consistency pressure during inference to reduce fragmented or locally plausible reasoning. It treats the answer as a structure whose parts must agree, not just a sequence of tokens that each looked likely.

ICML 2026

NAD

Fits into the verifier-loop story by making inference-time refinement depend on disagreement or deficiency signals. The key idea is that the system should allocate extra work where the current state reveals a specific weakness.

ICML 2026

ECHO

Uses repeated or reflective inference to improve long-horizon behavior. The important question is whether repetition creates new evidence and correction, or only restates the first answer in a more confident form.

SUBTHEME 05

Coding and Software Agents

Code agents are useful only when their artifacts survive execution and context.

Software work is a natural testbed for agents because the state is concrete and the verifier is often executable. A patch must respect surrounding code, pass tests, preserve semantics, avoid new vulnerabilities, and sometimes produce a proof. These papers move from code completion toward real software work: editing, optimization, repair, security, and verification.

ICLR 2026

EditBench

Evaluates instructed code edits with highlighted spans, cursor context, and natural editing requests. It measures the practical contract of a coding assistant: change the requested part while preserving the project around it.

ICML 2026

CIRBench

Evaluates LLVM IR optimization through verifier checks, equivalence checking, and runtime measurement. The answer must preserve semantics and improve performance, which makes the benchmark stronger than code-style judging.

ICML 2026

CVE-Factory

Builds executable environments for code-security agents and live vulnerability evaluation. It matters because security capability cannot be measured only through stale textual examples; the exploit or fix has to interact with real code state.

ICLR 2026

VERINA

Evaluates code, specification, and proof generation in Lean. It exposes the gap between code that appears correct and proof artifacts that certify the relevant invariant.

ICLR 2026

RefineStat

Repairs probabilistic programs by enforcing semantic constraints and resampling priors or likelihoods when diagnostics fail. Statistical code is treated as an executable scientific artifact, not a final string.

ICLR 2026

SwingArena

Pairs patch-generating submitters with test-writing reviewers over real GitHub issues and CI. The benchmark evaluates the software loop: retrieval, patching, tests, review, and integration.

SUBTHEME 06

Multi-Agent Coordination

Multiple agents create signal, but also strategic distortion.

When agents debate, collaborate, or share an environment, behavior is no longer explained by one model's local policy. Coordination can expose uncertainty and improve search, but it can also amplify confident errors, hide incentives, or create equilibria that satisfy formal constraints while failing practical goals. These papers make disagreement and interaction structure part of the measurement object.

ICML 2026

Value of Variance

Penalizes self-contradiction, peer conflict, and low-confidence outputs in multi-agent debate. Disagreement becomes a calibration signal rather than only an obstacle to consensus.

ICML 2026

OMAC

Fits the test-time coordination story by asking how multiple agents or candidates should be organized under compute and outcome constraints. The important issue is not more agents by default, but whether additional interaction creates independent evidence.

ICLR 2026

Rational Agents

Uses expected information gain to choose questions and actions. In multi-agent settings, the same principle explains why an agent should seek the message or observation that most reduces uncertainty about the next move.

ICML 2026

Nash Equilibria with Coupling Constraints

Studies equilibria when agents' feasible choices are linked by shared constraints. It matters for agent systems because local optimality can be misleading when the environment imposes coupled resource, safety, or coordination limits.

ICML 2026

MASPOB

Represents the branch where multi-agent search and preference optimization meet. The control question is how collective sampling should be scored when agents provide different, noisy views of the same problem.

ICML 2026

LatentMAS

Lets agents exchange last-layer hidden thoughts through shared latent working memory. The paper asks whether collaboration has to be textual: compressed internal state may coordinate agents without forcing every useful signal into natural language.

ICML 2026

DLM

Uses supervised finetuning plus GRPO to improve robustness and zero-shot generalization in multi-agent decisions. It sits on the training side of coordination, asking whether interaction policies can be learned rather than entirely hand-designed.

ICML 2026

Unsupervised Partner Design

Generates training partners on the fly and selects them by learnability for ad-hoc teamwork. The core problem is partner overfitting: agents that only train with familiar collaborators can fail when paired with new agents or humans.

ICML 2026

What Preferences Can and Cannot Predict

Introduces leaklessness as a payoff-based condition for stability beyond ordinal preference graphs. It matters because multi-agent systems are governed by incentives and information flow, not only by each agent's stated preference ranking.

SUBTHEME 07

Long Context and Memory

Long context is not memory unless the right information remains usable.

A longer window can make an agent worse if important facts are diluted, position encodings drift, retrieval adds distractors, or memory stores stale state. These papers treat context as an active control resource: what should be retained, retrieved, compressed, forgotten, or re-read before action?

ICLR 2026

LoongRL

Couples retrieval and reasoning in long contexts with distractors and chained facts. The task is not merely fitting more tokens; it is routing attention through the facts that form the answer path.

ICLR 2026

MemAgent

Studies memory as an explicit component of long-horizon agent behavior. The key problem is deciding what state should persist across turns so the agent does not start each step from a fragile reconstruction.

ICML 2026

MemoryBench

Evaluates whether memory systems retain useful task state rather than merely logging more text. It matters because memory can become noise unless the system can retrieve the right past fact at the right time.

ICML 2026

TG-RAG

Connects retrieval to graph or trajectory structure, making information access depend on relationships rather than raw text similarity alone. For agents, retrieval quality determines what world state is visible before action.

ICML 2026

Robust Filter Attention

Studies attention under long-context noise and filtering pressure. The agent reading is direct: an action system must suppress irrelevant context without dropping the small fact that controls the next step.

ICML 2026

Focus and Dilution

Names the core long-context failure: adding more context can dilute the model's ability to focus on decisive evidence. Long context is therefore a control problem, not just a capacity number.

ICLR 2026

In-Place TTT

Uses chunk-wise test-time updates on very long contexts. The agent reading is that reading can itself be adaptation: as each chunk arrives, fast weights can specialize the model to the current document rather than forcing every fact through a fixed hidden state.

ICLR 2026

Q-RAG

Learns multi-step access policies for long-context retrieval. Retrieval becomes an action policy rather than a static top-k operation: the system chooses which evidence to inspect next based on what it has already learned.

SUBTHEME 08

Browser, UI, and Embodied Action

In interface worlds, the action space is visible state plus hidden consequences.

Browser, app, mobile, home, and embodied agents act through interfaces that were designed for humans. A click may reveal new state, a form may reject input, a page may hide a prompt injection, and a simulated home may require spatial or temporal reasoning. These papers make the environment part of the task rather than a prompt wrapper.

ICML 2026

OpenApps

Benchmarks agents in app-like environments where UI state and action sequencing matter. The agent must read the interface, choose operations, and recover when the visible state changes.

ICML 2026

BIRD-INTERACT

Turns data interaction into an agent task rather than a static question-answer task. It captures a common workflow: inspect, query, observe the changed state, and refine the next action.

ICML 2026

SimuHome

Evaluates agents in a home-like simulated environment. The key issue is grounded state: the agent's plan must respect objects, locations, temporal order, and consequences.

ICML 2026

Gaia2

Extends general-assistant evaluation into richer agentic tasks. It belongs here because the work tests multi-step interaction, not only static knowledge recall.

ICML 2026

AstaBench

Evaluates assistants on tasks that require multi-step state management and tool behavior. It exposes whether the system can keep a workflow coherent across observations.

ICML 2026

VenusBench-Mobile

Targets mobile-agent behavior, where success depends on understanding screen state and operating through constrained UI actions. Mobile tasks are useful because they expose small interaction errors that text benchmarks hide.

ICLR 2026

ScaleCUA

Builds a large open GUI-agent dataset across operating systems and task domains. The point is coverage under interface variation: an agent that works only on one visual style may have learned the look of a platform rather than the operation behind it.

ICML 2026

MiniAppBench

Uses agentic exploratory testing to assess open-ended interactive artifacts. The agent is not just solving a predefined task; it is probing an artifact whose valid behaviors may be numerous and whose failures have to be discovered.

ICML 2026

Vision2Web

Combines GUI agent verification and vision-language judging for website-development tasks. It sits at the boundary between building and evaluating: the agent must create an interface, and the evaluator must decide whether the visual and functional result matches the intent.

ICML 2026

tau2-bench

Places the user and AI inside a shared telecom decision process where both can use tools to change state. Conversation becomes a state-changing protocol, so success depends on coordination, tool effects, and policy compliance rather than answer fluency.

ICLR 2026

MedAgentGym

Creates a sandboxed biomedical coding environment with feedback, ground truth, and trajectories. It shows why domain agents need controlled environments: biomedical mistakes need executable or expert-grounded checks, not only plausible explanations.

SUBTHEME 09

Inference-Time Steering and Control

Some controls act on the model while it is generating, not before training.

Inference-time control separates the task prompt from the behavior control signal. The system may steer activations, adjust decoding, change unmasking policies, or use lightweight reward pressure while the model is already solving the task. This matters for agents because deployment often requires behavior changes faster than full retraining can provide.

ICLR 2026

Steer Like the LLM

Studies activation steering as a practical control mechanism. The paper asks how internal directions can shape behavior while preserving the model's ability to solve the underlying task.

ICML 2026

Assistant Axis

Identifies an activation-space direction associated with assistant persona drift and uses it to constrain behavior. The agent reading is that persona stability becomes an operational safety control, not only a prompt-writing problem.

ICML 2026

Learning Unmasking Policies

Controls the order in which masked diffusion language models reveal tokens. It turns generation into a policy over which uncertainty to resolve next.

ICML 2026

AdaBlock-dLLM

Adjusts computation inside diffusion language models. The practical concern is adaptive effort: hard parts should receive more computation than easy parts.

ICML 2026

PLAINTAIN

Represents the class of methods that modify inference behavior through explicit control signals. Its importance in this lane is the separation between what the user asks and how the model's internal process is guided.

ICML 2026

JitRL

Applies reinforcement-learning pressure close to the moment of use. The broader idea is just-in-time adaptation: the model's behavior can be updated around the task distribution rather than frozen at deployment.

SUBTHEME 10

Infrastructure Risk and Monitoring

Tools create capability, and capability creates new boundaries to defend.

Once agents browse, run code, call tools, write files, and operate inside sandboxes, safety cannot be only a refusal policy. The infrastructure becomes part of the threat model. These papers ask whether hidden channels, sandbox escapes, prompt injections, covert coordination, and monitor blind spots appear when agents are given realistic action surfaces.

ICML 2026

SandboxEscapeBench

Measures whether agents can escape nested VM and container sandboxes to reach protected host evidence. The benchmark makes the security boundary itself the object under test.

ICML 2026

CyberGym

Validates generated vulnerability proof-of-concept tests against pre-patch and post-patch code. It asks for executable security evidence rather than a convincing vulnerability description.

ICLR 2026

RedTeamCUA

Builds a hybrid VM and Docker setup for indirect prompt injection against computer-use agents. The attack surface is the GUI environment itself, not just the text prompt.

ICML 2026

Monitoring Monitorability

Measures when chain-of-thought traces make agent misbehavior more visible than action-only monitoring. It treats monitor compute and follow-up reasoning as oversight resources.

ICLR 2026

Invisible Safety Threat

Studies hidden safety bypasses in agent infrastructure. The lesson is that an agent can route around visible policy checks if the tool or environment layer carries an unmonitored channel.

ICLR 2026

Trojan-Speak

Examines covert or compromised communication patterns in agent systems. It matters because multi-agent and tool-using systems can fail through hidden protocols, not only explicit malicious instructions.

ICLR 2026

Weak-to-Strong Monitoring

Combines hierarchical and sequential monitors so weaker systems can supervise stronger agents with targeted escalation. The oversight problem is asymmetric: the monitor may need to notice when it is outmatched and route the case to a stronger checker or human.

ICLR 2026

PLAGUE

Shows that multi-turn attack planning can reach high attack success with efficient query use. The infrastructure lesson is temporal: attacks can optimize across conversation state, so a defense that only filters one turn can miss the plan forming over several turns.

FIELD READ

What This Lane Says About ICML and ICLR

The big picture is that reasoning is being pulled out of the model's answer and into the system's control loop. The papers do not agree on one mechanism. Some build better traces, some hide thought in latent computation, some use tools, some control decoding, some inspect traces, some make code executable, some coordinate multiple agents, and some harden sandboxes. But they are all working on the same object: a learned system that must repeatedly decide what state matters and what action should come next.

That makes this lane the natural sequel to the completed safety and evaluation lane. Measurement asks what evidence counts. Agents ask what process produces that evidence. A serious conference atlas needs both: the system that acts, and the instruments that prove whether its actions were real progress.
