READ FIRST

The Core Mathematical Shift

The old mental model was supervised learning: choose model knobs that lower error on examples. The conference map is broader. Many papers still lower an error score, but the real object is often a changing process: an agent's work session, a checker, a causal story, a generation path, a physical world state, a set of possible explanations, or a compute budget.

That is why the same ideas appear across very different domains. A browser gym, a protein generator, a safe RL algorithm, a federated optimizer, and a root-cause system all ask versions of the same question: what is the right state, what doubt remains, what surface changes should not matter, what actions are allowed, and what evidence proves success?

The most important reading move is to stop asking only which model architecture a paper uses. Ask what the paper makes measurable. Some papers measure the work path. Some make a checker executable. Some show how much doubt remains in a benchmark. Some make source history, compute budget, or hidden causal state part of the problem. Once that object is clear, papers from different themes become comparable.

FIRST PRINCIPLES

Why Mathematics Enters At All

The role of mathematics in these papers is not to decorate a method after it works. It is to decide what has to be preserved while the system changes. Every strong paper here identifies a quantity that cannot be guessed from the surface output alone.

What is the state?

If the state is wrong, the problem is already broken. In agents, the state includes tool observations, file changes, memory, and verifier output. In robots, it includes subgoals, contact, and dynamics. In long-context models, it includes which past tokens still affect future decisions. RAGEN-2, HDFlow, Mamba-3, EntroKV, ThinkV, GAIA2, and tau2-bench work because they enlarge the state until it contains the information needed for the next decision.

Why it works. A decision can only use facts that are still in the working record. If the record omits the missing tool result, hidden contact, or past clue, the system treats an unknown as if it were settled. What must stay the same is the information needed for the next decision; what may change is how that information is stored.

What should stay the same?

Some changes should not matter. A molecule rotated in space is the same molecule. A graph relabeled by node names may have the same relational structure. A web task should survive harmless UI variation. A proof step should remain valid when written in a different surface form. Quotient diffusion, GraphGlue, OpenApps, CRAMF, and transformer-circuit work all improve behavior by separating the object from its accidental encoding.

Why it works. If fake variation is treated as real variation, the model wastes effort learning camera angle, naming style, or wrapper format. What must stay the same is the real object or task relation. What may change is the description that should not affect the answer.

What actions are allowed?

Many papers work because they stop searching over impossible or unacceptable outputs. Copyright-Bench restricts agent action by law. LSFlow maps continuous samples through a solver into combinatorial actions. Pi-net projects neural outputs into hard constraints. Fair optimal transport constrains the matching. CSPO keeps policy movement near a safety boundary.

Why it works. If a kitchen recipe cannot use peanuts, the cook should not invent peanut dishes and throw them away at the end. The allowed menu should shape the search from the start. What must stay the same is legality, safety, physics, or fairness. What may change is which allowed answer is chosen.

What doubt remains?

Incomplete channels, missing variables, rare events, small benchmarks, noisy judges, and weak checkers all leave doubt that cannot be wished away. LIMSSR keeps missing-channel doubt visible. Robust contextual optimization keeps several possible completions alive in the decision. Rare Event Analysis estimates rare bad-case probability directly. Micro-benchmarking studies whether ranks are stable. RLVepsR makes checker noise part of training.

Why it works. If a blank form field is filled in with a guess, later steps treat that guess as fact. These methods keep the doubt visible until there is enough evidence to act. What must stay the same is honest uncertainty; what may change is which plausible completion, rare case, judge, or checker result is considered.

What may the update change?

Post-training, pruning, quantization, LoRA, federated merging, and trust-region RL all change a trained model. The hard question is what can move without destroying useful behavior. DiReCT controls data-induced movement through fragile and forgiving directions. Trust regions bound policy drift. LoRA theory constrains updates to small factorized moves. TetraJet controls numerical error. RAIN-Merging moves away from reasoning features that should not be disturbed.

Why it works. Updating a model is like repairing a running machine. A small turn in one place may help; the same-sized turn elsewhere may break a hidden part. What must stay the same is useful behavior the system still needs. What may change is the step size, allowed direction, number format, or adapter handle.

What counts as evidence?

A final answer is weak evidence when the system could have reached it by shortcut. Verifying chain-of-thought uses dependency graphs. CyberGym uses executable proof-of-concept behavior. ATLAS uses questions that separate remaining ability guesses. WebDevJudge asks whether a judge sees web functionality. MINT changes hidden states to test which internal route caused the output.

Why it works. Evidence helps when it rules out a rival story. A trace, execution result, internal patch, or adaptive question matters because it shows something a final score cannot show: which work was done, which artifact changed, which ability remains uncertain, or which route caused the answer.

Concepts to Publications

Allowed-Set Search

The first-principles problem is choosing an action when not every high-scoring action is allowed. The object is a score plus the set of actions that are legal, safe, physically possible, or fair. What must stay the same is the boundary rule. What may change is which allowed answer wins.

choose the best allowed action, not the best action anywhere
Pi-netForces a neural output back into the allowed region before it is used.
CSPOChanges safe-RL updates by how near they are to a safety boundary and how fragile that nearby behavior is.
Robust Contextual Optimization with Missing CovariatesBuilds robust decision sets from partial observations instead of filling missing facts with guesses.

Moving A Cloud Of Possibilities

The problem is not only predicting one point, but moving a cloud of possible outputs toward the target while keeping rare valid cases, likelihood, or safety rules. This is the language of diffusion, flow, RL post-training, and generative decision-making.

move generated possibilities toward target possibilities without losing valid cases
Enhancing Reasoning for Diffusion LLMs via DMPOMoves a diffusion LM policy toward outputs rewarded by the task.
Latent Spherical Flow PolicyUses flow matching to sample structured actions that solvers map into valid decisions.
FALCONTrains flows with accurate likelihoods for molecular equilibrium estimation.

Same Object, Different Description

The problem is that raw coordinates often contain details that only come from the observer. A molecule rotated in space is the same molecule. The model should sample the object, not the coordinate accident.

group coordinate descriptions that name the same physical object
Quotient-Space Diffusion ModelRuns diffusion after same-molecule coordinate copies are grouped together.
Protein Autoregressive ModelingUses hierarchy in protein structure to generate coarse-to-fine backbones.
Camera-Aware MLLMUses camera parameters so spatial understanding is not confused with viewpoint artifacts.

Cause Stories And Deliberate Changes

The problem is directional explanation: what would change if we deliberately changed one thing? Seeing two things together is not enough when the task is root cause, fair comparison, or scientific discovery. What must stay the same is the fair comparison. What may change is the tested action, repair point, or cause story.

estimate effects or causes while keeping track of which cause stories still fit the evidence
BRCDRanks repair points when several cause maps still fit the microservice logs.
Local Covariate SelectionFinds the background variables needed for one fair cause comparison.
Latent Hawkes Causal DiscoveryStudies cause influences in partly observed time-event systems.

Checking The Thing That Must Work

The problem is separating a plausible answer from a correct outcome. A checker observes the world state, trace, or generated object. Strong evaluations make that check executable.

CyberGymChecks generated proof-of-concept exploits on pre-patch and post-patch code.
OmniVerifierBuilds visual outcome checking for iterative generation and editing.

Information And Remaining Doubt

The problem is deciding with incomplete evidence. The question is how much an observation changes what we know and how the remaining doubt should affect actions, rankings, or guarantees.

new evidence should reduce decision-relevant doubt enough to be worth using

Rare Event Analysis of LLMsEstimates low-probability deployment behaviors with explicit probability methods.

Training Movement And Visible Directions

The problem is that training is a path, not only a final score. Some pushes help, some break fragile behavior, and some point toward patterns the data cannot clearly show. What must stay the same is useful behavior. What may change is the update direction, step size, checkpoint, or data timing.

study which update directions help, which are fragile, and which signal directions finite data can see
DiReCTSelects late-training data by whether it pushes forgiving useful directions instead of fragile harmful ones.

Compute Allocation

The problem is deciding where computation should go: which tokens, experts, clients, layers, timesteps, or precision levels deserve budget. Capability becomes an allocation problem.

Changing-State Systems

The problem is predicting or controlling systems that evolve. The relevant object is not one frozen example; it is the rule that carries the system from the current situation to the next one. What must stay the same is the physical, time, memory, or control rule. What may change is the action, noise, correction, or learned approximation.

next state = rule(current state, action, uncertainty)

Hidden Working Notes As Interfaces

The problem is choosing the internal note where the task becomes easier. A good note keeps the structure the later task needs while dropping noise, scanner quirks, surface wording, or irrelevant detail. What must stay the same is the task-relevant structure. What may change is the raw signal, sensor, wording, or internal code.

learn an internal code that keeps the structure the later task needs
CompSLOTStores new object concepts in localized slots so old concepts are less likely to be overwritten.
PRISMTurns fMRI into object-attribute-relation text before visual reconstruction.

Work Paths And Process Evidence

The problem is that a final answer can hide the work that produced it. For agents, post-training, code repair, rare-event sampling, and control, the path is often the evidence. The object is the ordered record of situations, actions, intermediate artifacts, checker calls, and recovery steps. Formal label if needed: trajectory.

work path = situation -> action -> observation -> next situation, checked by process and outcome
RAGEN-2Measures reasoning collapse by asking whether the trace actually depends on the input.
tau2-benchFrames service agents as shared-state interaction processes with user and agent actions.
Control Consistency LossesTreats rare-event simulation as an online control-learning path.

Benchmarks As Measuring Devices

The problem is that a benchmark is not neutral. It has a task mix, a scoring rule, sampling noise, judge error, coverage limits, and shortcut paths. Many evaluation papers are really about designing the measuring device, not only ranking models.

Systems Where Others React

The problem is that many systems contain more than one actor trying to improve its own outcome. A model, user, adversary, checker, platform, or group of agents can react to the others. The object becomes a game, debate, or constrained interaction rather than a single loss minimization.

each actor chooses a policy while seeing constraints, information, and responses from others

Constrained EquilibriaAnalyzes multi-agent behavior when optimality must respect shared constraints.
LLM Debate VarianceUses disagreement between agents as evidence about answer reliability.

Data Source Receipts And Governance

The problem is that data is not just examples. It has origin, legality, ordering, missing values, duplication, consent, contamination, and value for the current training target. Several papers make the dataset itself the object to build, audit, or govern.

dataset has source receipts, weights, order, constraints, missingness, and later value

OBJECT GRAMMAR

The Reusable Mathematical Objects

A long-term atlas needs a grammar: a small set of objects that reappear across papers. These are the objects to track while expanding every theme and subtheme.

State Transition

Plain object. Something observes a state, takes an action or update, and lands in a new state.

Where it appears. GAIA2, tau2-bench, HDFlow, IRNO, Mamba-3, differentiable MPC, Delayed-Observation RL, Thinking in Flow.

Why it matters. If the transition is not modeled, errors look like isolated mistakes. Once transition is explicit, the method can ask whether each step preserves enough information for the next step.

Feasible Set

Plain object. The subset of actions, outputs, policies, or couplings that are allowed.

Where it appears. Copyright-Bench, CSPO, Pi-net, LSFlow, Fair OT, robust contextual optimization, constrained diffusion, Nash equilibria with coupling constraints.

Why it matters. Feasibility must be part of search. If invalid outputs are only filtered afterward, the model still spends probability and training signal on regions it can never use.

Quotient Space

Plain object. A space where different coordinate descriptions of the same object are treated as one object.

Where it appears. Quotient-Space Diffusion, protein generation, graph gluing, camera-aware spatial reasoning, molecule/protein samplers.

Why it matters. Removing irrelevant variation lowers the burden on learning. The model no longer has to relearn that rotations, translations, labels, or viewpoints are not new underlying objects.

Hidden Cause Or Hidden Skill

Plain object. A quantity the model cannot directly see but must infer from visible clues, like skill from answers or mood from tone and context.

Where it appears. ATLAS ability, VALUEFLOW value intensity, MINT fusion bands, Mind-Omni brain tokens, Linear Causal Representation Learning, EigenBench, HAMC.

Why it matters. The method works when it estimates the hidden thing that actually controls behavior, instead of chasing noisy surface labels that mix several causes.

Verifier

Plain object. A function that checks whether a trace, artifact, proof, output, or action satisfies a condition.

Where it appears. CyberGym, VERINA, CRAMF, Verifying Chain-of-Thought, OmniVerifier, WebDevJudge, SandboxEscapeBench, DRPBench.

Why it matters. A verifier turns plausibility into evidence. The more directly it observes the relevant state, the harder it is for fluent but wrong behavior to pass.

Still-Possible Worlds

Plain object. The worlds, completions, or model behaviors that incomplete evidence has not ruled out.

Where it appears. Robust contextual optimization, missing-covariate decisions, loss-aware OT-DRO, finite test certification, feasible payoffs, Gaussian unlearning, MADQA oracle gaps.

Why it matters. Like leaving several possible addresses open when the street number is missing, the method keeps uncertainty alive until the decision point. That prevents the training or decision rule from treating guessed missing values or under-sampled risks as facts.

Tail Event

Plain object. A low-probability behavior that matters because deployment repeats the system many times.

Where it appears. Rare Event Analysis, tail-risk estimation, Control Consistency Losses, TRECA, jailbreak evaluation, prompt-injection benchmarks, watermark detection.

Why it matters. Average sampling is weak in the tail. Tail methods work by changing the sampling or estimation procedure so the rare region becomes measurable.

Tradeoff Frontier

Plain object. A boundary showing which combinations of goals are possible together.

Where it appears. ParetoPO, SecFid, Catch-22, SafeDPO, Accuracy Auctions, Fair OT, LiftQuant, FlexRank, compute-capability scaling.

Why it matters. Many goals cannot be maximized at once. A frontier exposes the cost of moving one goal, instead of hiding the cost inside a single weighted score.

Strong And Weak Directions

Plain object. A sorted list of the main ways something can vary, from strongest to weakest.

Where it appears. Alignment-Sensitive Minimax Rates, DiReCT, Jacobian spectra, SVD interpretability, spectral-sphere training, Neural Ricci Flow, low-rank optimizer state.

Why it matters. Imagine listening to a song and separating the loud bass, the voice, and the faint background hiss. This sorting says which directions are strong enough to trust, which are weak, and which are mostly noise. What must stay the same is the real pattern the task depends on. What may change is the coordinate system used to describe it. Methods work when they put learning effort into the directions that actually carry the pattern and avoid overreacting to tiny noisy directions.

Rules Where Others React

Plain object. Multiple decision-makers whose incentives or actions affect one another.

Where it appears. AdvGame, data market pricing, accuracy auctions, Bayesian truthful valuation, constrained equilibria, fair causal bandits, multi-agent collaboration, weak-to-strong monitoring.

Why it matters. A single-decision view fails when other actors adapt. If a payment rule rewards exaggeration, sellers exaggerate. If a leaderboard rewards hiding hard cases, teams hide hard cases. These papers work by treating response to the rule as part of the system. Formal labels if needed: game or mechanism.

Trajectory

Plain object. A path through states, thoughts, tool calls, parameters, samples, or physical configurations.

Where it appears. RAGEN-2, OpenThoughts, h1, Skill-Pro, TerminalTraj, DiReCT, WSM, HDFlow, diffusion samplers.

Why it matters. The path can contain the evidence that the endpoint hides. Trajectory methods work by scoring or reusing intermediate movement, not only final outputs.

Sample Path

Plain object. The route a generator or simulator follows from uncertain start to finished output.

Where it appears. DMPO, Safety-Guided Flow, quotient diffusion, FALCON, Control Consistency Losses, diffusion quantization, Phased DMD.

Why it matters. If errors accumulate along the path, one-step quality is not enough. Path-aware methods control the middle states so final samples inherit the right structure instead of merely looking good at the end.

THEME EXPANSION 01

Agents And Reasoning: The Mathematics Of The Loop

An agent is like a worker who sees only part of the desk, chooses a move, gets a new clue, and must decide again. What must stay the same is the task goal and the real state of the work. What may change is the next action, the tools used, the notes kept, and the amount of thinking spent. These papers work when they make that loop visible enough to check: what the agent knew, what it did, what changed, and whether the change helped.

Reasoning and Planning

Object. The work path, not just the final answer.

Why it works. In a hard puzzle, the final answer does not show which step mattered. OpenThoughts, h1, RAGEN-2, PonderLM-2, T3, Visual Planning, and Verifying Chain-of-Thought keep the intermediate work visible. What must stay the same is the connection between the original problem and each step. What may change is the length of the path, the smaller problems used, and the checks along the way. This works because a system can learn from steps only when it can tell which steps removed doubt or made the next move possible. Formal label if needed: credit assignment, meaning deciding which step in the work path should receive responsibility for the result.

Connection. RAGEN-2 checks whether the path actually depends on the input; h1 teaches short links before long chains; OpenThoughts supplies path data; graph verification checks whether each step follows a valid rule.

Tool Use and Scaffolds

Object. Like asking someone to open a file, run a test, or click a page instead of guessing from memory, the object is an action that changes the outside work state and brings back evidence.

Why it works. THOR, CRAMF, Skill-Pro, ParetoPO, TerminalTraj, MEnvAgent, ADP, AgentFlow, and GEPA work because tool calls turn uncertain internal reasoning into checked work. What must stay the same is the task goal and the real state of the file, proof, browser, or environment. What may change is which tool is used, how much it costs, and what evidence comes back. A theorem prover rejects invalid syntax, a shell command changes files, a browser click changes page state, and a test suite returns a concrete result. Formal label if needed: external state for the world outside the model that tools can inspect or change.

Connection. ParetoPO adds the missing cost dimension: tools are valuable only when the evidence gained is worth the latency, risk, and budget.

Process Diagnostics

Object. The pattern of work that led to success or failure.

Why it works. A student can get the right answer by understanding, guessing, copying, or luck. Models have the same problem. TRACE Effort, CE-Graph, LLMs Get Lost, RoTS, MADQA, CausalGame, Hierarchical Thinking, and MAP ask whether the route to the answer has the right shape. What must stay the same is the link between the task and the work. What may change is the amount of effort, the examples tested, and the checks used. This works because repeated signs in the path reveal failures that a final score hides: losing the state, passing a weak checker with little effort, looping, using the wrong cause, or recovering only in narrow cases.

Connection. These papers judge how the answer was produced, not only whether the answer string looked right.

Test-Time Scaling

Object. Like deciding whether to spend another minute checking a hard answer, the object is extra thinking time treated as something that must earn its cost.

Why it works. ASAG, The Tell-Tale Norm, Weak-Strong Verification, Reasoning with Sampling, Global Resolution, ECHO, and ThinkV all decide where extra compute should go. What must stay the same is the final decision standard. What may change is whether the model samples another path, asks a stronger checker, zooms into a hard region, keeps more memory, or stops. More inference helps only when it reduces doubt that could change the answer. Formal label if needed: budgeted decision variable for a resource the system spends only when its expected value is high enough.

Connection. The link to evaluation is direct: test-time compute is useful when it buys evidence, not length.

Coding and Software Agents

Object. Like repairing a machine and then turning it on, the object is the changed program plus the behavior it must still produce.

Why it works. EditBench, CIRBench, CVE-Factory, VERINA, RefineStat, SwingArena, DRPBench, SparseRL, and BRCD work because software can be checked where it actually runs. What must stay the same is the intended behavior, security property, proof rule, or user-facing result. What may change is the patch, proof step, file layout, or generated code. Pi-net, FFOLayer, Constrained Transformers, SC-MILP, MORetro*, RECM, Weight-Space Expressivity, DISCO, Local Covariate Selection, Structure Learning CI, Distributional Equivalence, Linear Causal Representation Learning, LC-PB-SCM, and DiCoLa all make the rule part of the computation. What must stay the same is validity: allowed outputs, checked evidence, fair comparisons, or solver consistency. What may change is the model's first proposal or internal route. The model may need to move an invalid first answer back inside the allowed region, and a checker may need inspectable evidence that the rule was obeyed.

Connection. This connects theory to scientific and embodied systems: valid behavior is not whatever lowers the score; it is whatever remains inside the structure of the problem.

THEME EXPANSION 06

Causality And Scientific Discovery: The Mathematics Of What Would Change

Prediction asks what usually appears together. Causality asks what would change if we deliberately changed one thing. What must stay the same is the comparison being made: like with like, same background, same target outcome. What may change is the chosen cause, treatment, repair point, environment, or experiment. These papers work when they separate a story that merely fits the data from a claim the evidence can actually support.

Local Effects Instead Of Whole Worlds

Object. One cause-and-outcome comparison plus the background facts needed to make it fair.

Why it works. If we ask whether a medicine helped one outcome, we do not need to explain the whole hospital. Local Covariate Selection is useful because it keeps the question local. What must stay the same is everything that would make the comparison unfair if it differed. What may change is the treatment or cause being studied. This works by finding which observed variables must be held steady so the comparison is like with like. Formal label if needed: adjustment set.

Connection. A causal estimate is a claim with a receipt. The receipt is not a high prediction score; it is the argument for why this comparison is valid.

Graph Recovery As Statistical Testing

Object. Which cause-and-effect drawings the data can rule out.

Why it works. A graph is a story about what can directly affect what. Structure Learning CI, DiCoLa, and Distributional Equivalence ask which stories survive the evidence. What must stay the same is the observed pattern of data. What may change is the direction or presence of arrows in the graph. The key test is whether two quantities stop being related once the right background facts are known. If several drawings still fit after those tests, the honest output is the whole still-possible group, not one favorite drawing.

Connection. A discovered edge is a measurement result with doubt attached, not a plausible drawing.

Root Cause Under Partial Structure

Object. Like diagnosing an outage where many alarms ring after one upstream service fails, the object is a ranked list of repair points that might actually change the failure.

Why it works. Many services can look broken because one earlier break spreads. BRCD asks which repair would most likely change the outcome, while admitting that the exact cause graph may still be uncertain. What must stay the same is the evidence from the incident. What may change is the still-possible cause story and the repair point tried first. The updated doubt is the repair notebook after logs are seen: some causes become less likely, some remain plausible, and the next fix should spend effort where it is most likely to stop the failure.

Connection. This turns causality into an operational agent task: intervene first where a fix is most likely to change the outcome.

Temporal And Stochastic Mechanisms

Object. Like watching alarms, weather, or symptoms over time and asking which hidden rule keeps making the next event more likely, the object is the time-changing cause story.

Why it works. Latent Hawkes Causal Discovery, OU Identifiability, Robust Causal Discovery with Power-Laws, Linear Causal Representation Learning, LC-PB-SCM, Unpaired Causal IV, Evolutionary Selection, and LDM all ask which cause story can be separated from imperfect time or environment evidence. What must stay the same is the rule that would keep producing observations after conditions change. What may change is the noise, observation window, environment, or hidden subprocess. A hidden state is a not-directly-seen condition that helps explain later events. An event-triggering rule asks whether one event temporarily raises the chance of another. Evidence is strong enough only when rival time rules no longer make the same predictions.

Connection. A hidden state is useful only if it preserves the rule that would keep producing observations after the environment changes.

Scientific Discovery As Hypothesis Search

Object. Like turning a suspicious lab pattern into a claim that can be tested, the object is a proposed effect plus the evidence that could prove it wrong.

Why it works. Neural Effect Search turns learned model features into candidate units for treatment-effect discovery. What must stay the same is the treatment question being tested. What may change is which learned feature becomes the candidate explanation. The method helps because a feature is not accepted just because it looks interpretable; it becomes a hypothesis only after it is tied to randomized treatment evidence and checked against the risk of finding a pattern by chance. Formal labels if needed: statistical error control and multiplicity pressure.

Connection. This links interpretability to causality. A feature matters scientifically when it supports a testable effect, not just when humans can name it.

Executable Scientific Workflows

Object. Like a lab bench with the dataset, code, instruments, expected readings, and failure logs all present, the object is the whole scientific work session.

Why it works. MedAgentGym and RefineStat both reject one-shot scientific text generation. What must stay the same is the scientific claim being checked. What may change is the code path, repair step, model choice, or analysis action. MedAgentGym checks biomedical data-science work by running actions in a sandbox. RefineStat checks probabilistic programs by inspecting priors, likelihoods, parameters, diagnostics, and repairable components. The method works because scientific validity is checked by execution and domain meaning, not by fluent prose. Formal label if needed: verifiable trajectory.

Connection. This is the bridge to agent gyms: a scientific benchmark should preserve the object being manipulated, the allowed operations, and the verifier that proves whether the result is meaningful.

Fairness And Policy As Counterfactual Constraints

Object. Like asking whether the same person would have received the same decision if one sensitive fact were different, the object is the allowed decision under a what-if rule.

Why it works. Fair Causal Bandits, TRECA, DISCO, Fair Posthoc Control, and robust contextual optimization papers show that some rules cannot be checked from observed accuracy alone. What must stay the same is the fairness or treatment promise. What may change is the protected attribute, treatment, abstention choice, or operating threshold. The method works by making the what-if assumption part of the decision rule and tracking harm or uncertainty directly. Formal label if needed: counterfactual constraint.

Connection. Governance becomes causal when the relevant claim is not "what did the model predict?" but "would this decision remain justified under the change we care about?"

Identification Boundaries

Object. Like admitting that two plumbing layouts could produce the same readings, the object is the set of claims the evidence can truly separate from rival stories.

Why it works. Distributional Equivalence, Local Covariate Selection, Latent Hawkes Causal Discovery, OU Identifiability, Structure Learning CI, and Linear Causal Representation Learning all share one discipline: state what cannot be uniquely known. What must stay the same is the data plus the assumptions the method is allowed to use. What may change is the still-possible cause story, graph, hidden mechanism, or transformation. Sometimes the honest output is an effect with a local adjustment receipt; sometimes it is a set of graphs the evidence cannot tell apart; sometimes it is updated doubt over root causes, not a single cause. Formal label if needed: identification for the point where evidence and assumptions force the claim.

Connection. This is the deepest connection to first principles across the atlas: good methods preserve the boundary between identified knowledge and plausible story.

THEME EXPANSION 07

Multimodal And Embodied AI: The Mathematics Of Grounded State

Multimodal and embodied papers are solving a state problem. Text can hide missing structure behind fluent description. A grounded system cannot. It must preserve where things are, what happened over time, which evidence channel saw what, what a body can physically do, what changed after an action, which moments were kept, which human signal was measured, and which checker can verify the result. The central object is a joint state: not image plus text plus action as separate files, but one working record whose parts constrain one another.

Spatial Coordinate State

Object. Like taking several photos of the same room, the object is the room behind the photos: where things are, how far away they are, which views show the same object, and how the camera moved.

Why it works. Camera-Aware MLLM, DepthLM, Depth Anything 3, 3ViewSense, Vid-LLM, SAW-Bench, VGGT-Motion, Holi-Spatial, TideGS, RadioGS, WAFT, SplAttN, FutureCAD, and SpatioLM all fix the same problem: a flat image loses distance and viewpoint. What must stay the same is the underlying scene and the action possibilities it creates. What may change is the camera position, crop, sensor, rendered view, or coordinate system. Spatial methods work when they keep object identity, distance, camera settings, camera pose, and same-point matches across views while letting viewpoint-only details change.

Connection. This is the perception version of ignoring fake changes from viewpoint while preserving real changes in object and scene structure.

World Models As Transition State

Object. Like tracking pieces on a board game after each move, the object is the record of what changed in the scene and what could happen next.

Why it works. DreamDojo, VectorWorld, GLANCE, LPWM, HDFlow, dWorldEval, Stable Video Infinity, FlashWorld, SceneSmith, Motive, VideoFlexTok, InfoTok, and Control Consistency Losses all treat video as evidence about possible futures. What must stay the same is the real state behind the images: objects, positions, actions, timing, and physical consequences. What may change is the next frame, action, or compressed memory. The model improves when it predicts not only what the next image might look like, but what state change would have produced it. The hidden world record matters because the camera may not show every object or constraint that controls the next state.

Connection. This is the multimodal version of agent reasoning: the system needs a trace whose intermediate states remain tied to the task.

Action Shape And Embodiment

Object. Like choosing a safe movement for a particular body in a particular room, the object is the allowed family of actions after body shape, joint rules, contact, self-sensing, timing, and skill phase are known.

Why it works. BehaviorVLA, XR-1, Latent Action Supervision, LaST0, RodriNet, ScaleMoE, OXE-AugE, RoboMME, MomaGraph, SCALE, PACT, VPRL, JoSE, Posterior Behavioral Cloning, VOTP, TimeRewarder, HALO, Continual VLA Forgetting, MSP, and EcoVLA work because robot actions are not text tokens. What must stay the same is a physically valid world change. What may change is the action code, body state, memory, contact evidence, or latency budget. The likely-action menu must stay inside what the body can actually do, rather than treating every command number as equally possible.

Connection. Embodiment turns every abstract claim into a physical constraint: wrong uncertainty becomes risky motion, wrong memory becomes repeated action, wrong timing becomes control failure.

Modality Credit Assignment

Object. Like asking which witness changed the verdict, the object is the route from image, text, audio, time, body signal, or prior habit to the final answer.

Why it works. MoCA, VGS, Causal Route Gating, VISUALSWAP, Visual Symbolic Mechanisms, DOUBT, MINT, DLMR, RFCMH, LIMSSR, WETR, AGREE, DAVE, Visual Attribution Streaming, and FlowGuard all ask which signal caused the answer. What must stay the same is the claim about which evidence the model used. What may change is the image, text, audio, hidden state, label reliability, or failure route being tested. The method works by exposing whether the answer came from the claimed evidence or from a shortcut. Formal label if needed: modality credit assignment.

Connection. The question is not only whether the output is correct, but which evidence channel made it correct or wrong.

Token Budgets As Information Bottlenecks

Object. Like taking notes from a long meeting when only some moments will matter later, the object is the kept pieces of video, audio, speech, table, text, or cache.

Why it works. FlashVID, InfoTok, VideoFlexTok, OmniFit, LST, COMPACT, LiME, Beyond LM, MetaEmbed, TACO, ThinKV, EntroKV, and ThinkV all work because multimodal streams are too large for uniform processing. What must stay the same is the evidence needed for the later answer or action. What may change is how many tokens each region receives, which cache entries are kept, or which layer gets budget. A piece matters only if removing it can change the future decision. Formal label if needed: information bottleneck.

Connection. This is compression as state selection. Efficiency is safe only when the discarded tokens are not the evidence the task needed.

Unified Generation Across Modalities

Object. Like one editing desk that can handle script, storyboard, sound, 3D scene, and revision notes without turning them all into plain captions, the object is a shared workspace for different media.

Why it works. NextStep-1, EditVerse, LatentLM, UALM, VibeVoice, TTSDS2, FlashWorld, VIST3A, TideGS, RadioGS, IDCD, RelaxFlow, Omni-Reward, UniPercept, and MetamerGen all try to make generation cross media without losing what each medium needs. What must stay the same is each medium's native evidence: visual detail, timing, audio texture, 3D consistency, or edit state. What may change is the token, hidden code, rendering, or reward signal used to connect them. The method works when media constrain one another instead of being flattened into captions. Formal label if needed: shared generative interface.

Connection. Sampling is not enough; the sample must remain editable, grounded, and verifiable in the modality where it will be used.

Non-Text Human Signals

Object. Like judging whether someone is tired, upset, joking, having a seizure, or speaking naturally, the object is evidence carried by timing, tone, body signal, culture, and domain vocabulary.

Why it works. Hibiki-Zero, EmotionThinker, EEmo-Logic, WAVE, TokSuite, ATLAS, Seizure-Semiology-Suite, Active Mind Avatars, MetaphorVU, SleepLM, BioX-Bridge, PRISM, Mind-Omni, and LST all widen grounding beyond image labels. What must stay the same is the event or human state the evidence points to. What may change is language, accent, clip, sensor, or cultural setting. These approaches work by building a task layer that matches how the domain is measured and used. Formal label if needed: representation for the internal record of the signal.

Connection. This is the human-data version of scientific structure: the model must preserve the signal's measurement grammar before it can reason over it.

Outcome-Level Evaluation And Safety

Object. Like checking the cooked dish rather than the recipe description, the object is the produced image, video, audio, robot action, scene state, or human judgment.

Why it works. FRABench/UFEval, VideoKR, DeceptionDecoded, FlowGuard, VJA, Visual Attribution Streaming, DAVE, MetamerGen, OmniVerifier, Agent0-VL, VC-STaR, Seizure-Semiology-Suite, DGS-Net, TTSDS2, and HALO all refuse to let fluent text be the only evidence. What must stay the same is the real outcome being claimed. What may change is the explanation string, edit path, generated sample, or correction step. These evaluations work when the checker observes the artifact where failure can happen, not a detached explanation. Formal label if needed: verifier over grounded artifacts.

Connection. This ties the lane back to benchmark design: a multimodal benchmark must preserve the world state and evidence path, not only the final answer string.

PAPER DETAIL

Per-Paper Mathematical Read

The useful question for each paper is not "what trick did it use?" The useful question is: what problem did the paper make precise, what did it measure, change, preserve, or check, and what approach follows once that object is chosen?

RAGEN-2

Problem. Agent RL can reward traces that look thoughtful while becoming almost independent of the input. The model has learned a habit, not a task-conditioned process.

Object. Information flow from input to reasoning trace. Entropy measures variation within one input; mutual information asks whether traces differ across inputs in a way that preserves task information.

Approach. Diagnose template collapse with mutual-information proxies and filter prompts by reward variance so training batches contain enough signal to push reasoning away from generic templates.

The Tell-Tale Norm

Problem. Test-time reasoning needs a cheap internal signal for when the model is doing important work and when extra recursion is waste.

Object. The object is the size of the model's hidden working numbers while it answers. That size is not the reasoning itself; it is more like a dashboard gauge that may rise when the model is using reasoning machinery.

Approach. Use sparse-autoencoder evidence and deliberate internal changes to connect high-gauge states to reasoning steps, then route recursion, steering, or answer selection with that signal.

Steer Like the LLM

Problem. A prompt can change behavior by changing the model's internal working numbers, but a hand-built steering knob may push the wrong thing.

Object. Like adjusting different mixing-board sliders for different moments in a song, the object is the inside change a prompt would have caused for this token and this context.

Approach. What must stay the same is the intended prompt effect and a natural working state for the model. What may change is where and how strongly the internal adjustment is applied. The method trains replacement steering models from the current internal numbers instead of applying one fixed shove everywhere.

DMPO for Diffusion LLMs

Problem. Diffusion language models revise a whole noisy text state, so training them as if they choose one next word at a time uses the wrong story.

Object. Like judging finished drafts and making future drafting paths more likely to end in the better drafts, the object is the cloud of completed texts after reward has favored some outputs.

Approach. What must stay the same is the denoising process the model actually uses. What may change is how likely each completed text becomes after reward is applied. The method matches the model's drafting process to the reward-favored output cloud, while controlling for noisy estimates from small batches.

OpenThoughts

Problem. Reasoning-model progress depends on the quality and reproducibility of trace generation, not only on the base model or final answer labels.

Object. A data recipe for producing reasoning trajectories. The dataset is a process with sources, filters, teachers, domains, and trace shapes.

Approach. Build public reasoning data pipelines so the field can inspect how intermediate supervision is created and why it transfers.

Verifying Chain-of-Thought via Computational Graph

Problem. A chain of thought can be fluent without implementing a valid computation.

Object. Like checking a receipt line by line, each step must show which earlier fact or operation paid for it.

Approach. What must stay the same is support: a later claim should depend only on earlier claims that actually justify it. What may change is the wording of the explanation. The method turns reasoning into a checkable dependency map instead of grading the prose as one persuasive block. Formal label if needed: computational graph.

SandboxEscapeBench

Problem. Tool-using agents create a safety risk when they interact with containers, shells, runtimes, and host systems.

Object. Like locking a worker inside a test room, the object is whether anything outside that room can still be touched.

Approach. What must stay the same is the protected outside state. What may change is the route the agent tries: configuration mistakes, privileges, runtimes, orchestration, or host interfaces. The benchmark works by running real escape attempts and checking whether the boundary was crossed. Formal label if needed: reachability across a security boundary.

CyberGym

Problem. Cybersecurity ability cannot be measured by static vulnerability questions; the exploit or test must interact with real code.

Object. An executable software environment with pre-patch and post-patch behavior. Correctness is a behavioral difference under code execution.

Approach. Ask agents to generate proof-of-concept tests and run them against controlled versions so evaluation becomes an operational artifact.

DRPBench

Problem. Concurrent-code errors depend on possible interleavings, so a model can understand syntax and still miss the race.

Object. Like two people editing the same form at the same time, the object is who can read or write the same place before the other person is finished.

Approach. What must stay the same is safe ordering around shared memory. What may change is the schedule in which operations happen. The benchmark works by isolating variable sharing, synchronization, and possible orderings so the model must reason about the execution, not just the code text. Formal label if needed: partial order constraints.

CSPO

Problem. Safe RL needs more than high return with occasional constraint satisfaction. Deployment cares about recovery near the boundary.

Object. Like driving near a guardrail, the object is how far the agent is from crossing the line and which steering moves make that distance shrink fastest.

Approach. What must stay the same is the safety line. What may change is the policy update and the recovery action near that line. The method works by teaching the agent not only to avoid violations on average, but to know which moves pull it back when it is close. Formal labels if needed: signed distance and local sensitivity.

Safety-Guided Flow

Problem. Generators can drift into unsafe regions even when the base model is good at realism.

Object. Like guiding a drawing hand away from a forbidden part of the page while it still follows the prompt, the object is the step-by-step direction used to make the sample.

Approach. What must stay the same is prompt-relevant quality and the safety boundary. What may change is the direction of each generation step. The method works by adding a push away from unsafe outputs instead of only pulling toward realistic ones. Formal label if needed: sampling vector field.

Rare Event Analysis of LLMs

Problem. A behavior can be invisible in ordinary testing and still occur often enough to matter at deployment scale.

Object. Like checking how often a factory has the one dangerous fault that happens once in many runs, the object is the named bad event and how much probability sits on it.

Approach. What must stay the same is the definition of the event being measured. What may change is how samples are searched or steered toward that event. The method works by spending test effort where ordinary random testing almost never looks, while keeping explicit doubt around the estimate. Formal label if needed: tail probability.

VALUEFLOW

Problem. Values are not binary labels. A model can express a value weakly, strongly, inconsistently, or in conflict with another value.

Object. Like comparing how strongly several people care about honesty, privacy, kindness, and directness in the same answer, the object is a measured strength for each value.

Approach. What must stay the same is the relative value signal people gave. What may change is the answer, user group, or value being steered. The method works by turning rankings into value-strength estimates, so conflicts are visible instead of hidden inside one reward number. Formal label if needed: value-intensity profile.

Quotient-Space Diffusion

Problem. Molecules and proteins should not become different examples just because their coordinate frame rotated or translated.

Object. Like recognizing the same chair after someone turns it around, the model needs one record for the object itself and a separate record for harmless viewing changes.

Approach. What must stay the same is molecular or protein identity. What may change is rotation, translation, or another wrapper coordinate that should not affect the target. Formal label if needed: quotient space for the grouped-together versions of the same object.

Protein Autoregressive Modeling

Problem. Protein backbones have nested structure, so independent coordinate prediction ignores the hierarchy that makes a molecule valid.

Object. Like sketching the main beams of a bridge before placing every bolt, the model first keeps the broad fold and then fills in finer atom positions.

Approach. What must stay the same is biological plausibility across both large shape and local shape. What may change is the order and scale at which pieces are predicted. Step-by-step generation helps because each new detail is checked against the structure already built.

HDFlow

Problem. Long-horizon robot planning needs exploration over subgoals and fast generation of dense motion.

Object. Like deciding first which table to reach and only then how the arm should move, the plan has a coarse aim and a detailed body path.

Approach. What must stay the same is feasible progress toward the task. What may change is which high-level aim is sampled and which smooth motion path realizes it. The hidden aim says what broad world change should happen; the body path says how the robot moves through time to make it happen.

IRNO

Problem. Neural operators can accumulate leftover error over a physical prediction horizon, especially in fast-changing details.

Object. Like repeatedly adjusting a blurry forecast until the remaining mismatch gets smaller, prediction is treated as correction toward a stable solution rather than one guess.

Approach. What must stay the same is the physical rule being predicted. What may change is the correction applied at each refinement step. Formal labels if needed: residual for the leftover mismatch, and fixed point for a solution that no longer changes under the correction rule.

DiReCT

Problem. Late-training data can help or harm depending on where it pushes a model that has already learned many habits.

Object. Each example is a small proposed push. Some pushes move through forgiving places where behavior improves; others touch fragile places where a tiny change breaks already-learned behavior.

Approach. Choose examples whose push helps validation behavior while avoiding fragile directions. The key background is simple: the same-sized training step can be safe in one direction and damaging in another, so data should be judged by the move it causes, not only by whether the example looks high quality.

Midtraining Bridges

Problem. Specialized data is useful only if it arrives when the model can still absorb it without losing broad capability.

Object. Like adding advanced lessons after the basics but before final exam drilling, the bridge is the order and mix of examples that changes what the model is ready to learn.

Approach. What must stay the same is broad capability that should not be overwritten. What may change is when specialty examples appear and how much of them are mixed in. The lesson mix matters because it decides which examples the model practices from at each stage.

Mamba-3

Problem. Long sequences need memory that scales better than comparing every token to every other token.

Object. Like keeping a running notebook while reading a long book, the model carries a compact state forward instead of reopening every earlier page.

Approach. What must stay the same is the history that can still change the next prediction. What may change is the size and update rule of the carried state. Formal label if needed: state-space recurrence for a repeated memory update through time.

FlashVID and InfoTok

Problem. Long video has more frames than a fixed model budget can afford, and not every region of the video is equally useful.

Object. Like taking detailed notes when the ball changes hands and shorter notes when nothing changes, the model marks which video pieces could affect the later answer.

Approach. What must stay the same is the event, order, or visual fact needed later. What may change is how many tokens each region receives. Formal label if needed: information density for how much a video piece can change the decision.

Transformer Circuits Can Realize Clustering Algorithms

Problem. Architecture descriptions do not explain what algorithm a transformer may be implementing.

Object. An algorithmic circuit: assignment, aggregation, update, and iteration steps mapped onto attention and feed-forward blocks.

Approach. Show how Lloyd-style clustering can be represented by transformer components, then compare learned behavior to the classical algorithm.

Softmax Transformers Are Turing-Complete

Problem. A model can fail for two different reasons: the machine may be unable to run the needed procedure, or training may fail to find that procedure. Those are not the same failure.

Object. Like asking whether a calculator has enough buttons and memory to carry out a recipe, the object is the procedure the architecture can represent.

Approach. What must stay the same is the memory-and-symbol routine being represented. What may change is whether finite data, finite time, or the optimizer can discover it. The result shows that softmax-attention components can simulate very broad computation under stated conditions, while keeping the boundary explicit: possible inside the architecture does not mean easy to learn. Formal label if needed: computational expressivity.

Alignment-Sensitive Minimax Rates

Problem. Generalization cannot be explained only by model size or kernel complexity; it also depends on whether the useful pattern is visible to the features the model has learned.

Object. Like trying to hear a melody in a noisy room, the question is whether the target signal sits in directions that rise above noise and can be estimated from finite data.

Approach. What must stay the same is the target pattern. What may change is the learned feature view or the amount of sample noise. The method works because data cannot reliably teach every faint direction; it teaches the directions that show up strongly and repeatedly enough to be heard.

ACROSS PAPERS

How The Concepts Connect

Trace, State, And Evidence

RAGEN-2, Verifying Chain-of-Thought, TRACE Effort, CyberGym, DRPBench, and GAIA2 all reject final-answer scoring as the whole story. Their shared problem is evidence loss. If only the final output is measured, the benchmark cannot tell whether the system solved the task, exploited a shortcut, got lucky, or performed dangerous intermediate actions. The shared approach is to expose the trace as inspectable evidence: a sequence, graph, execution log, or state-transition history that shows what happened before the answer.

Boundary Behavior

CSPO, SandboxEscapeBench, Safety-Guided Flow, Catch-22, Rare Event Analysis, and VALUEFLOW all study boundaries. Some boundaries are physical or formal, such as a container wall or a required rule. Some are statistical, such as a rare bad event or watermark detection threshold. Some are social, such as value strength under pressure. The common move is to stop asking whether the system is safe in the average case and instead ask how close it is to a boundary and what pushes it across.

Right Sample Space Before Better Sampling

Quotient-Space Diffusion, Protein Autoregressive Modeling, HDFlow, Safety-Guided Flow, FALCON, FlashWorld, and constrained diffusion papers all say the same thing in different domains: sampling is only meaningful after the sample space is correct. The wrong coordinates create fake variation. The wrong hierarchy creates invalid outputs. The wrong constraint handling creates plausible but unusable samples. These papers improve generation by changing what a valid draw means.

Training As A Path, Not A Pile

DiReCT, Midtraining Bridges, OpenThoughts, Common Corpus, LiftQuant, TetraJet, and low-precision training work all treat training as a path through constraints. Data order, source receipts, fragile update directions, number precision, and hardware budget are not secondary implementation details. They determine which example pushes are seen, which movement directions are stable, what legal evidence can be used, and which capabilities survive compression.

Internal State As Interface

The Tell-Tale Norm, Steer Like the LLM, MINT, Temporal Superposition, ThinkV, and representation-learning papers all make hidden state useful by turning it into an interface. The model's internal working numbers are not only explanations after the fact. They can trigger extra reasoning, steer generation, locate where image and text evidence meet, decide which cache notes to keep, or reveal how memory is packed.

Theory As Object Selection

Transformer Circuits, Softmax Turing completeness, Alignment-Sensitive Minimax Rates, Language Generation in the Limit, HATSolver, and Jacobian-spectra work are not separate from the applied papers. They answer the same first question: what is the object? It may be a working procedure, a set of grouping steps, the directions where signal is visible above noise, a language rule, an algebra workspace, or a strong internal direction. Once the object is named in this plain way, the paper can state what is possible, what is learnable, and where the recipe should fail.

SUBTHEME SPINE

The Mathematical Problem Across Theme Families

Across the atlas, each theme family is solving one version of the same problem: turn an underspecified behavior into a measurable object, then choose an update rule, verifier, sampler, or representation that respects that object.

Agents and Reasoning

Problem. A model's answer is only the last state of a longer process. The hidden failure is that the process can stop depending on the task, use tools wastefully, forget state, or satisfy a verifier without solving the problem.

Plain object. The work log: what the agent saw, what it remembered, what it tried, what changed outside the model, what checks came back, and why it stopped.

Why the approaches work. Think about a repair technician. The final note "fixed" is not enough; you need to know which part was tested, which tool was used, what reading changed, and why the technician stopped. Agent papers use the same idea. What must stay the same is the real task state and the goal. What may change is the reasoning path, tool calls, amount of compute, and stopping rule. RAGEN-2 checks whether the work still depends on the question, Tell-Tale Norm checks whether an internal gauge predicts when extra work is needed, Skill-Pro saves reusable routines, ParetoPO asks when tool cost is worth paying, and graph verification checks whether each step actually supports the next. Formal label if needed: trajectory.

Evaluation and Diagnostics

Problem. A score is a noisy observation of capability, not capability itself. It can be distorted by lucky samples, judge bias, task mixture, hidden shortcuts, and repeated tuning to the same benchmark.

Plain object. A measuring setup: which questions are asked, who or what judges them, what rule turns answers into numbers, and how much doubt remains.

Why the approaches work. A bathroom scale can be wrong because the scale is broken, the floor is uneven, or you measured only once. Model evaluation has the same problem. What must stay the same is the ability being claimed. What may change is the question mix, judge, sample size, rubric, and artifact being inspected. ATLAS chooses the next question because it should reduce a specific doubt. UFEval and FRABench split one score into separate abilities. Micro-benchmark reliability asks whether a ranking survives limited evidence. WebDevJudge and OmniVerifier inspect the thing users actually see or use. Formal label if needed: measurement instrument.

Safety and Governance

Problem. Bad behavior often appears under pressure, at low probability, after adaptation, or through a hidden channel. Average-case testing misses exactly the part that matters.

Plain object. The edge of what is allowed, plus the hard-to-see cases near or beyond that edge.

Why the approaches work. A guardrail is not tested by driving down the center of the lane forever. You test near the edge, in bad weather, and with someone trying to defeat the rule. What must stay the same is the safety or governance requirement. What may change is the attack, user pressure, watermark edit, privacy test, or helpfulness tradeoff. CSPO watches whether learning steps move toward a forbidden line. Rare Event Analysis deliberately visits uncommon failures. Catch-22 shows what a watermark must survive and what it must hide from attackers. Gaussian unlearning asks whether removed data still leaves a detectable trace. SecFid separates blocking attacks from preserving benign instructions. VALUEFLOW measures which values are strong, weak, or in conflict. Formal labels if needed: boundary, tail event, tradeoff frontier.

Data and Systems

Problem. Data and compute are not passive resources. Their order, source receipts, precision, memory layout, communication cost, and hardware representation change the model that is actually trained or served.

Plain object. The route by which examples and numbers move through training and serving under real budgets.

Why the approaches work. A lesson has different value before and after the student has learned the basics. A note has different value if it will or will not be needed later. A rounded number is harmless in one place and damaging in another. What must stay the same is the behavior the system must preserve. What may change is which data arrives when, which examples are trusted, how precise the stored numbers are, and which memory is kept. DiReCT chooses late data by whether its training push helps without moving through fragile directions. Midtraining Bridges chooses a gentler route from general data to specialty data. Common Corpus attaches source and permission receipts. LiftQuant and TetraJet control where low-precision error lands. EntroKV and ThinkV keep cache entries that can still change future answers. Formal label if needed: constrained training path.

Physical and Generative Models

Problem. Generic arrays do not encode the real object. Molecules have rotations that should not change identity, proteins have parts inside larger parts, robots have contact and time, videos have motion, and physical simulators have rules that repeat step after step.

Plain object. The real thing being generated or predicted, described in the coordinates that matter for that thing.

Why the approaches work. A chair is still the same chair when viewed from another angle; a robot plan is invalid if the hand cannot physically reach; a weather-like simulation is wrong if tiny errors grow at every step. What must stay the same is the physical or structural fact the task depends on. What may change is viewpoint, scale, subgoal, sampling route, or correction step. Quotient diffusion ignores changes that do not create a new molecule. PAR builds proteins from coarse parts to fine parts. HDFlow separates the intended subgoal from the body path that must reach it. IRNO corrects a physical prediction by repeatedly fixing the remaining error. Safety-Guided Flow changes the generation route while keeping the final object valid. Formal labels if needed: state space for the working record, quotient for grouping fake coordinate changes, flow for a directed sample route, and fixed point for a correction rule that settles when the remaining error is gone.

Theory and Optimization

Problem. Practical recipes can work for reasons that are invisible if the only language is "bigger model, lower loss." Theory has to name the smaller piece that controls success.

Plain object. The part of the machine or learning process that can be described exactly enough to make a promise about it.

Why the approaches work. If a machine succeeds, one explanation is "it is big." A better explanation is "this gear carries this motion." Theory papers look for those gears. What must stay the same is the claim being explained: what can be computed, learned, preserved, or bounded. What may change is the model size, coordinates, movement rule, or data sample. Transformer Circuits maps attention parts to clustering steps. Alignment-sensitive rates ask whether the target signal lies in directions the learner can see. LoRA theory studies the small adapter shape people actually train. Trust regions limit how far reward training can move at once. HATSolver builds attention around the algebra steps the task already needs. The recurring pieces are working procedures, visible signal directions, small allowed move families, and the movement ruler used during training.

WHY IT WORKS

Mechanisms Behind Representative Papers

ATLAS

Why it works. A fixed benchmark wastes questions that cannot change what the evaluator believes. If a question is far too easy, far too hard, or repeats what earlier questions already proved, it adds little. ATLAS works like a careful examiner: ask the next question near the place where the model's ability is still uncertain. What must stay the same is the skill being measured. What may change is which question is asked next. A useful question is one that separates skill levels that are still plausible; it reduces doubt because different skill levels would answer it differently.

FRABench and UFEval

Why it works. A report card is clearer than one final grade when a student is strong in writing and weak in arithmetic. These benchmarks do the same for models. What must stay separate is each ability that can fail; what may change is how a user weights those abilities. Formal label if needed: aspect taxonomy.

Micro-Benchmarking Reliability

Why it works. One race does not prove which runner is faster. A small benchmark has the same problem. What must stay the same is the claim that one model is really ahead on the named task population. What may change is the sampled item set. Formal label if needed: finite-sample ranking uncertainty.

Copyright-Bench

Why it works. A helpful answer is not acceptable if it uses a forbidden source, just as a shortcut through a locked room is not a valid route. What must stay the same is the legal source rule. What may change is the user's pressure, source choice, and artifact. Formal label if needed: feasible workflow set.

SecFid

Why it works. A mail sorter should block poison notes without throwing away every useful letter. SecFid works by keeping two jobs visible: stop malicious instructions and preserve benign content. What must stay the same is both security and task fidelity; what may change is the defense strength. Formal label if needed: tradeoff frontier.

Catch-22

Why it works. A watermark must survive ordinary edits, but if it is too obvious an attacker can find and remove it. What must stay the same is authorized detectability. What may change is editing, attack pressure, and detector threshold. Formal label if needed: watermark hypothesis test.

Gaussian Certified Unlearning

Why it works. Deletion should mean an auditor cannot tell whether the removed record was ever used. What must stay the same is the model's useful behavior after deletion. What may change is whether the deleted example was in the original training history. Formal label if needed: indistinguishability certificate.

Robust Contextual Optimization with Missing Covariates

Why it works. If a form is missing an important field, filling in one guess can make the decision look more certain than it is. This method keeps several plausible completions alive. What must stay the same is decision safety under missing facts; what may change is which completion is true. The decision must survive the remaining possible cases because the missing fields did not settle them.

Fair Optimal Transport

Why it works. Matching riders to drivers by lowest cost alone can create unfair patterns. Fair transport writes the fairness rule into the matching table before choosing cheap pairings. What must stay the same is the group constraint; what may change is which individual pairings are used. Formal label if needed: coupling.

Common Corpus

Why it works. A recipe without ingredient sources cannot be checked or repeated. A corpus is the model's recipe. What must stay visible is where the data came from, what was filtered, and what is legally usable. What may change is the data mix. The inspected mix of real examples is the evidence the model is allowed to learn from.

Sequential Data Values

Why it works. The first map of a city helps; the tenth copy adds little. Data value depends on what has already been chosen. What must stay the same is the target behavior being improved. What may change is the current selected set. Formal label if needed: marginal contribution.

HOBIT

Why it works. A practice set teaches more when it includes contrasts the learner has not seen yet. Once the same contrast is already covered, another copy is less useful. What must stay the same is useful contrast coverage; what may change is the batch composition. Formal label if needed: submodular value.

LiftQuant

Why it works. Hardware often offers rough storage choices, like rulers with only a few tick marks. LiftQuant creates a richer set of effective values from cheaper codes. What must stay the same is the model behavior users rely on; what may change is the stored number format. Formal label if needed: lifted codebook.

TetraJet-v2

Why it works. Rounding errors are harmless only when they do not keep landing in the same damaging places. TetraJet shapes where low-precision error is allowed to land. What must stay the same is stable training behavior; what may change is the cheaper arithmetic. Formal label if needed: structured quantization error.

FOCUS and RePAIR

Why it works. Repetition is like getting stuck in a rut: the problem is both entering the rut and failing to climb out. These methods separate those two moments. What must stay the same is long-run generation stability; what may change is local probability around escape words. Formal label if needed: loop dynamics.

EntroKV and ThinkV

Why it works. A note is worth keeping only if it can still change a later answer. Cache compression follows the same rule. What must stay the same is future decision evidence; what may change is cache size and detail. Formal label if needed: entropy for remaining uncertainty.

MINT

Why it works. If a model sees the image but the visual fact never reaches the words, the bridge failed. MINT changes that bridge and watches the answer. What must stay the same is the image and question; what may change is the internal bridge state. Formal label if needed: hidden-state patching.

Visual-Symbolic Mechanisms

Why it works. Naming objects is not the same as understanding how they relate. The test asks whether the model can reuse pieces like "left of," "same as," or "inside" in new combinations. What must stay the same is the relation; what may change is the image instance. Formal label if needed: compositional variable.

Temporal Superposition

Why it works. A small notebook can track many threads only if the notes do not overwrite each other. Recurrent memory has the same problem. What must stay recoverable is each future-relevant feature; what may change is how features share internal space. Formal label if needed: superposition.

GraphGlue

Why it works. Two subway maps can use different station names while sharing transfer patterns. GraphGlue tries to preserve those patterns across domains. What must stay the same is neighborhood and relation structure; what may change is node identity and domain-specific detail. Formal label if needed: graph alignment.

HATSolver

Why it works. Some problems are easier when small pieces are solved and then combined. HATSolver gives the model that layered workspace instead of a flat token list. What must stay the same is the algebraic step structure; what may change is the local expression being processed. Formal label if needed: hierarchical attention.

Language Generation in the Limit

Why it works. A rule may exist, but a learner may need too many examples to find it. This paper keeps those claims separate. What must stay the same is the target language rule; what may change is the amount of evidence available. Formal label if needed: sample complexity.

Softmax Transformers Are Turing-Complete

Why it works. A machine may have enough parts to run a procedure even if training never discovers how. This result proves capacity, not automatic learning. What must stay the same is the memory-and-symbol routine being represented; what may change is whether finite data can find it. Formal label if needed: computational expressivity.

LoRA Gradient Descent

Why it works. Instead of turning every knob in a huge model, LoRA adds a small adapter with a limited set of moves. What must stay the same is useful base behavior. What may change is the small task-specific movement. Formal label if needed: low-rank update.

Trust-Region LLM RL

Why it works. Reward training can make a model chase a score and forget behavior users still need. A trust rule says improve, but stay near the checked model. What must stay the same is trusted base behavior; what may change is reward-seeking behavior inside the boundary. Formal label if needed: trust region.

Alignment-Sensitive Minimax Rates

Why it works. A faint melody can be learned only if it rises above static often enough. A representation helps when the target pattern sits in directions the data can see clearly. What must stay the same is the target signal; what may change is the representation. Formal labels if needed: effective span dimension and spectrum.

CONNECTIONS

The Big Picture Problem These Papers Are Solving

From Prediction To State Control

The old problem was to map input to output. The new problem is to watch what changes over time and decide whether the next change helps. RAGEN-2 watches reasoning work, CSPO watches distance from a safety line, HDFlow watches a robot body path, IRNO watches leftover solver error, and Mamba-3 watches sequence memory. What must stay the same is the goal of the process. What may change is the next internal state, action, correction, or memory update. Formal label if needed: state-space movement.

From Scores To Instruments

Evaluation papers are solving the problem of measurement error. A score is not a property of the model alone; it is produced by a task mix, judge, rubric, sampling plan, and stopping rule. ATLAS, FRABench, UFEval, WebDevJudge, Micro-Benchmarking Reliability, and MADQA work because they redesign the measuring instrument. They ask what hidden skill the score is trying to measure, where the judge can fail, how much doubt remains, and when one combined number hides several different abilities.

From Data To The Teaching Menu

Data papers are solving a simple problem: the examples a model sees are chosen by people and pipelines, not handed down by nature. A class learns differently if the teacher changes the order of lessons, repeats old drills, removes illegal material, or adds worked examples. OpenThoughts constructs reasoning traces. Common Corpus builds legally usable pretraining data with source records. DiReCT asks which examples push the model in useful directions. Midtraining Bridges chooses when specialized data should enter. Sequential Data Values asks whether the next example still adds anything after earlier examples. The key object is the mix of cases the model learns from or claims to cover.

From Outputs To Allowed Outputs

Many failures come from generating something that looks plausible but is not allowed. A contract answer may use forbidden sources, a route may break fairness rules, a molecule may be impossible, and a physical design may violate the rules of the system. Copyright-Bench, Pi-net, LSFlow, Quotient Diffusion, Fair OT, robust contextual optimization, and constrained diffusion work by saying which outputs pass the domain rules before chasing a high score.

From Architecture To Actual Work

Theory papers are solving a naming problem. "Transformer," "RNN," "MoE," or "flow" is not enough. The question is what work the machine actually carries out. Transformer Circuits names grouping steps. Softmax Turing names memory and symbol updates. HATSolver names layered algebra work. Temporal Superposition names memory packing. Jacobian-spectra work asks which internal directions are strong enough to be recovered from data. Once the work is named, design choices become testable: does the architecture keep the quantities that work needs?

From Average Safety To Pressure Response

Safety papers are solving the problem that deployed systems are judged at their weakest boundary, not at their average behavior. Rare Event Analysis, Pressure Reveals Character, Invisible Safety Threat, Trojan-Speak, SecFid, Catch-22, and VALUEFLOW all ask what happens under pressure, hiding, adaptation, or low-probability events. The useful move is to test the region ordinary sampling barely visits: the place where deployment risk is highest and the average score says least.

DEEP MECHANISMS

First-Principles Mechanisms Across Subthemes

Reasoning Control: Keep The Work Tied To The Question

The failure is not simply that the model writes too few or too many tokens. The failure is that the written reasoning stops depending on the actual question. Like scratch work on an exam, the trace matters only if the answer would change when the important step changes. RAGEN-2 measures whether the work path still carries information from the input. The Tell-Tale Norm adds an internal sign: when the model is really using reasoning machinery, certain hidden numbers grow or shrink in a way that marks effort. Steer Like the LLM adds a control layer: instead of hoping prompt words indirectly create the right inner push, learn a more direct internal push.

Why it works. These approaches succeed when the controlled signal is closer to answer-making than surface text is. What must stay the same is that the work is caused by the question. What may change is the trace, hidden signal, or steering method. The checks ask how much the work still tells us about the question, how strong the hidden effort signal is, and what happens when internal model numbers are deliberately changed.

Long-Horizon RL: Keep Reward From Vanishing

In long tasks, the final reward arrives after many decisions. A robot may fail at the end because of one bad early move, but the training signal arrives late and has to guess which move caused the failure. h1 grows shorter tasks into longer chains so early learning still gets useful feedback. Polychromic objectives keep several strategies alive instead of letting training collapse to the first loophole. Trust-region RL limits how far the model's action rule can move at once so reward improvement does not erase useful base behavior.

Why it works. The methods reshape the learning signal. Curricula keep early feedback close to the action that caused success or failure. Diversity rewards keep different workable strategies available. Trust regions act like a speed limit on model updates. What must stay the same is useful task behavior; what may change is task length, strategy mix, or update size.

Tool Agents: Turn Language Into Checked State Changes

Tool-use papers work when they replace an unverifiable sentence with an artifact that can be checked. CyberGym checks code behavior. SandboxEscapeBench checks boundary reachability. DRPBench checks possible race conditions. Copyright-Bench checks legal source choice. ParetoPO checks whether tool use paid for itself.

Why it works. A tool action changes the state of the world. That state change can be observed by tests, filesystem effects, browser state, or policy constraints. The benchmark becomes stronger because it measures consequences, not claims about consequences.

Evaluation: Measure The Hidden Skill, Not A Leaderboard Number

ATLAS, FRABench, UFEval, CounselBench, WebDevJudge, MADQA, Micro-Benchmarking Reliability, and Prescriptive Scaling all ask what the score is really trying to measure. The hidden skill might be reasoning ability, safety under pressure, clinical judgment, web-building quality, document recovery, or capability under extra compute.

Why it works. Once evaluation is treated as measurement, the design choices become concrete: choose examples that reveal the skill, reduce judge bias, report remaining doubt, split apart different abilities, and avoid comparing models when the error range is wider than the claimed gap. What must stay the same is the skill being claimed. What may change is the visible test evidence. The skill or quality is inferred from visible answers because it cannot be read directly.

Safety: Test Where Ordinary Sampling Is Weakest

Rare Event Analysis, Tail Risk estimation, Pressure Reveals Character, Invisible Safety Threat, Trojan-Speak, Obfuscation Atlas, Weak-to-Strong Monitoring, and RedTeamCUA focus on behavior that ordinary testing rarely sees. Some failures are rare, some are hidden inside the model's working state, some appear only under pressure, and some appear when the model knows it is monitored.

Why it works. These papers change where they look and what they can observe. Rare-event methods deliberately test low-frequency but high-cost cases. Pressure scenarios push toward boundary cases. Internal probes watch model numbers before final text appears. Monitor benchmarks vary what the agent and monitor know. What must stay the same is the safety rule. What may change is where and how the test applies pressure. The hard cases are the bad edge of outcomes and the tests where attacker and defender react to each other.

Preference and Values: Replace One Reward With A Structured Object

VALUEFLOW, Omni-Reward, SafeDPO, P-GenRM, MNPO, AGREE, Accuracy Auctions, and value-ranking papers all reject the idea that one scalar preference captures the target. Human judgments can be multidimensional, user-dependent, conflict-prone, intensity-valued, or tied to social welfare rather than mean accuracy.

Why it works. Like a restaurant review that separates taste, price, allergy safety, service, and noise, the method helps by refusing to average everything too early. What must stay the same is the value evidence people actually gave. What may change is how that evidence is split by user, value, ranking, or welfare weight. Formal label if needed: factorization for separating one blended score into parts that can be inspected.

Physical Generation: Remove Fake Choices

Quotient-Space Diffusion, Protein Autoregressive Modeling, HDFlow, FlashWorld, FALCON, Autoregressive Boltzmann Generators, constrained diffusion, and Safety-Guided Flow all work by changing what choices the generator is allowed to treat as different. A molecule rotated in space is the same molecule. A robot path that violates body limits is not a valid path. A protein part has to fit the whole structure.

Why it works. A sampler is only as good as the menu it samples from. If the menu includes duplicate versions of the same object, impossible options, or pieces in the wrong hierarchy, the generator wastes effort and probability on meaningless choices. What must stay the same is the physical object or rule. What may change is coordinate system, generation order, or sampling path. The key is the ruler that says which moves or differences matter for the real object.

Scientific Dynamics: Watch Repeated Error

IRNO, Frozen-PINN, REX, Hamiltonian flow maps, differentiable MPC, and time-series papers treat prediction as a repeated process. The important quantity is not only one output. It is what happens when the solver, controller, or time rule is applied again and again.

Why it works. A tiny one-step error can grow after many steps. Fixed-point correction reduces leftover error step by step. Reversible or structure-preserving solvers keep numerical movement closer to the physical rule. MPC repeatedly replans from the observed state instead of trusting one brittle plan made at the beginning. What must stay the same is the system rule over repeated steps; what may change is the step size, correction, or replanning window. Formal label if needed: dynamics for the rule describing how the state changes over time.

Compression: Preserve Behavior, Not Every Number

LiftQuant, TetraJet-v2, FOCUS/RePAIR, Layer Pruning Reassessment, MoE Compression, TabSwift, FlashVID, EntroKV, ThinkV, and STAR-KV all ask which parts of the model or input still matter for behavior. Compression fails when it removes a rare but important clue.

Why it works. Like packing a smaller emergency kit, the goal is not to keep every item; it is to keep the items that can change the outcome. What must stay the same is the answer or action the full system would have produced on the cases that matter. What may change is the number grid, cache size, layer count, or stored channels. Formal labels if needed: expressivity for what the smaller form can still represent, entropy for unresolved clues worth keeping, and outlier channel for a rarely used but high-impact part.

Update Movement: Changes Have Shape

DiReCT, LoRA Gradient Descent, FIRE, Polar Express, Beyond Muon, WSM, Non-Euclidean Edge of Stability, RACO, DTO-KD, and Neural Thickets all study how model updates move. The method works or fails depending on which changes are allowed and which useful behavior must stay fixed.

Why it works. Updating a model is like repairing a machine while it is running: a small turn in one screw can be harmless, while the same-sized turn in another place can break the whole system. What must stay the same is the useful behavior being protected. What may change is the direction, size, and ruler used for the update. The training push, the fragile places where tiny moves cause large changes, and the ruler for move size all have to be visible.

Causality: Separate Seeing From Changing

BRCD, local covariate selection, latent Hawkes causal discovery, CausalGame, Linear Causal Representation Learning, Divergent Causal Interventions, and MINT all separate "these things appear together" from "changing this thing would change that thing." A model can predict the next observation and still misunderstand what would happen after a deliberate change.

Why it works. Think of wet sidewalks and umbrellas. Seeing umbrellas helps predict wet sidewalks, but opening an umbrella does not make the sidewalk wet. What must stay the same is the fair comparison: the background facts that would otherwise confuse the change being tested. What may change is the chosen action, variable, graph story, or internal state patch. Formal labels if needed: intervention for the deliberate change, adjustment set for the background facts held steady, and mechanism for the route by which the change affects the outcome.

Formal Computation: Name The Algorithm Inside The Network

Transformer Circuits, Softmax Turing completeness, HATSolver, WZ-LLM, CRAMF, VERINA, Language Generation in the Limit, and program verification papers ask what computation the model represents or whether an outside checker can verify it.

Why it works. Like inspecting the gears instead of only watching the clock face, these papers ask what steps are actually being carried out. What must stay the same is the claimed procedure or proof rule. What may change is the network part, proof text, or training sample used to express it. A proof assistant rejects invalid steps; a dependency map exposes unsupported claims; a circuit proof maps components to algorithmic operations; a sample-complexity result warns when possible computation still needs too much evidence to learn. Formal label if needed: formal computation.

PAPER CHAINS

How Papers Explain Each Other

RAGEN-2 -> OpenThoughts -> h1 -> TRACE Effort

RAGEN-2 says a reasoning trace must depend on the input. OpenThoughts says the training traces must be generated and filtered as infrastructure. h1 says the horizon must be grown so reward remains learnable. TRACE Effort says the verifier can be gamed by low-effort traces. Together they define reasoning training as four concrete duties: preserve question-specific information, construct good trace data, keep feedback close enough to the step that caused success or failure, and test whether verifier success reflects real work.

SandboxEscapeBench -> CyberGym -> SecFid -> Weak-to-Strong Monitoring

SandboxEscapeBench defines a boundary the agent should not cross. CyberGym defines executable security capability. SecFid defines the tradeoff between blocking attacks and preserving benign instructions. Weak-to-Strong Monitoring defines oversight as a game between agent capability and monitor capability. Together they show why agent safety is not a classifier problem. It is a controlled interaction problem with reachability, execution, tradeoffs, and supervision limits.

Quotient Diffusion -> PAR -> HDFlow -> IRNO

Quotient diffusion removes irrelevant symmetry. PAR adds biological hierarchy. HDFlow separates long-horizon planning into subgoals and local motion. IRNO turns physical prediction into iterative fixed-point refinement. Together they say scientific and physical AI works when the representation matches the object before learning starts: symmetry for molecules, hierarchy for proteins, temporal decomposition for robots, residual correction for PDE-like operators.

DiReCT -> Midtraining Bridges -> Common Corpus -> Sequential Data Values

DiReCT looks at which examples push the model through directions where useful behavior can still improve without breaking old behavior. Midtraining Bridges asks when a new data mix should arrive. Common Corpus asks whether that mix has checkable source records and legal status. Sequential Data Values asks whether the next example adds information after previous selections. Together they turn data from a pile of examples into a governed control over the training path.

LiftQuant -> TetraJet -> FOCUS/RePAIR -> EntroKV

LiftQuant addresses memory budgets through continuous effective bit-width. TetraJet studies low-precision training error modes. FOCUS/RePAIR catches behavioral degeneration from pruning. EntroKV compresses cache by information. Together they show why efficiency is a preservation problem: each compression choice changes the working machine, and the change matters only through its effect on behavior, repeated state changes, and future uncertainty.

Transformer Circuits -> HATSolver -> Softmax Turing -> Language Generation In The Limit

Transformer Circuits maps attention to clustering operations. HATSolver maps hierarchical attention to algebraic computation. Softmax Turing asks what procedures the machine can represent at all. Language Generation in the Limit warns that representable does not mean learnable from realistic evidence. Together they give the cleanest theory story: first ask whether the architecture can carry the procedure; then ask whether data and optimization can actually find it.

DENSE ATLAS

More Per-Paper Mathematical Mechanisms

This section is intentionally compact, but each card still has to do real explanatory work: start with the thing being measured, changed, preserved, or checked; explain why that thing matters; then name the math only when the name helps connect papers.

Prescriptive Scaling

Object. Like asking what the best students can do after the same course and exam rules, the object is the reachable high-end capability at a given compute budget.

Why it works. Average scores can hide whether extra compute creates genuinely harder reachable ability or only lifts easy cases. What must stay the same is the post-training recipe and test rule. What may change is pretraining compute. Formal label if needed: frontier for the boundary of reachable capability.

Beyond First-Order Asymptotics

Object. Like stopping a medical test after enough evidence arrives, the object is the time needed to stop plus the remaining wobble around that time.

Why it works. Two tests can look the same in the long run but behave differently with the amount of evidence actually available. What must stay the same is the decision rule. What may change is sample noise and stopping time. Formal label if needed: fluctuation term for the extra uncertainty hidden by the rough average.

Finite Test Certification

Object. Like a bridge inspection report that names which bridge, load, and weather were checked, the object is a bounded evidence receipt for a task family.

Why it works. Passing sampled tasks supports a claim about the sampled population; it does not prove every possible task. What must stay the same is the named task family and sampling rule. What may change is the individual test item. Formal label if needed: certificate for the claim plus checkable evidence.

HypoSpace

Object. Like listing all recipes that could have made the same soup, the object is the set of possible explanations the evidence has not ruled out.

Why it works. Scientific reasoning is not just giving one plausible answer. What must stay the same is consistency with the evidence. What may change is which explanation is proposed. Formal label if needed: hypothesis space for the set of candidate explanations.

MADQA

Object. Like separating "the file does not contain the answer" from "the answer is there but the agent could not find it," the object is document QA split by where the work failed.

Why it works. What must stay the same is the question and document collection. What may change is whether a human, oracle, or agent gets access to each work step. TAKEAWAY

The Unifying Problem

The core is not one theorem. It is the repeated need to choose the right thing before improving it. If the thing is a crowd of possible outputs, match the crowd. If it is a physical structure, ignore wrapper changes that do not change the structure. If it is an agent, score the path and the verifier outcome. If it is a causal system, reason over deliberate changes and remaining graph doubt. If it is deployment, include compute, privacy, missingness, and safety limits in the working description.

That is the deep connection between the themes and the actual publications: the best papers are not only proposing a new model. They are choosing the right thing to measure, change, preserve, or check so the method is solving the real problem.
