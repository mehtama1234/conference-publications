FIRST PRINCIPLE

A Failure Mode Is A Broken Assumption

A method fails when it protects the wrong thing. The benchmark may measure an easy visible score instead of the real skill. The model may treat a change as irrelevant even though the task needs it. The cache may keep common notes and drop the rare clue needed later. The checker may inspect a stand-in artifact instead of the real artifact. The sampler may visit attractive outputs and miss dangerous or scientifically important outputs.

Treating failure modes as objects makes future work concrete. For each paper, ask which assumption breaks first and what evidence would reveal the break before deployment.

Stand-in score driftThe score, reward, or checker keeps pointing at the real target after the model learns to chase it.The training push improves the measured score while the real behavior gets worse or stays flat. Formal labels if needed: stand-in drift, checker drift, and training-push disagreement.RLVepsR, TRACE Effort, JudgeBench, WebDevJudge, Omni-Reward.Disagreement audits, stand-in versus real-target checks, reward hacking examples, truncated-process tests.Model the measuring channel and require evidence that the stand-in score keeps matching the target after training pressure.
False same-object ruleThe change treated as irrelevant really does preserve the target.The method groups together cases that the task actually needs to keep separate. Formal labels if needed: harmless-change rule, same-object grouping, and same-object class.Quotient-Space Diffusion, Camera-Aware MLLM, GraphGlue, protein and molecule models.Transformed-input consistency plus task cases where orientation, labels, or viewpoint should matter.State which changes are allowed to be ignored and test where that promise stops being true.
Missing enough-stateThe shortened memory contains every fact needed later.Performance holds on common cases but fails when a delayed, rare, or dependency-heavy clue was dropped. Formal labels if needed: enough state, sufficient statistic, and running summary.ThinKV, STAR-KV, EntroKV, Skill-Pro, DLMR, VideoKR, Mamba Markov ICL.Rare-fact retention, long-horizon perturbations, full-history comparisons, stale-memory tests.Define the future tasks the state must support and test against delayed evidence.
Wrong allowed setThe paper's allowed boundary matches the real valid boundary.Valid outputs are blocked or invalid outputs remain reachable. Formal labels if needed: allowed set and rule set.CSPO, Pi-net, Copyright-Bench, ReaSyn, MORetro*, Fair OT, PACT.Boundary cases, violation rates, valid-object recall, false refusals, route-validity tests.Audit both sides of the boundary: false positives and false negatives.
Rare-case blindnessOrdinary samples reveal the risk that matters.Mean score improves while rare harmful cases remain unmeasured. Formal labels if needed: tail risk and rare-event probability.Rare Event Analysis, Tail Risks, Jailbreak Foundry, SandboxEscapeBench, FlowGuard, SRMC.Doubt ranges for rare events, proposal coverage, near-boundary examples, adaptive attacks.Define harmful event sets explicitly and use stress sampling with stability checks.
Visible-direction mirageThe biggest visible directions are stable and tied to the target.Large directions explain variation in the data but not task behavior. Formal labels if needed: visible signal direction, strongest table direction, and variance.Alignment-Sensitive Rates, BBP Transitions, Low-Rank LM Logits, SVD Interpretability, Jacobian Spectra.Resampling stability, target alignment, perturbation sensitivity, held-out behavior preservation.Separate variation explanation from causal or predictive signal.
Wrong movement rulerThe movement ruler used in analysis matches the trainer and deployment behavior.An update looks small by one ruler but damages stiff or hidden behavior directions. Formal labels if needed: update movement, movement ruler, and fragile bend.Adam Degeneracy, DiReCT, LoRA Theory, Trust-Region RL, Beyond Muon, RAIN-Merging.Movement energy, off-target capability loss, trimmed-update comparisons, trainer-rule removal tests.Report movement under the ruler that actually governs loss and safety.
Sample path coverage missThe sampler visits every important kind of output.Generated artifacts look plausible but omit rare, unsafe, or scientifically important regions. Formal labels if needed: path support and output-mix support.FALCON, SRMC, Cauchy Bridges, Safety-Guided Flow, DMPO, Quantized Diffusion.Mode recall, likelihood calibration, effective sample size, proposal stress, guidance bias.Audit coverage and step-path error, not only final sample quality.
Cause overclaimThe data and assumptions force one effect, graph, route, or cause story.The output is more specific than the evidence supports: it gives one story when several stories still fit the same observations.Distributional Equivalence, Local Covariate Selection, Structure Learning CI, DiCoLa, BRCD.Still-possible story sets, examples where evidence is not strong enough, relation-test strength, hidden-cause stress tests.Return the set of claims still compatible with evidence and state which assumptions narrow it.
Checker mismatchThe checker sees the artifact where correctness actually lives.Generated output passes a checker that is not checking the real claim. Formal labels if needed: verifier mismatch and certificate mismatch.CyberGym, VERINA, WZ-LLM, PaperBench, WebDevJudge, OmniVerifier.Checker scope, false positives, execution traces, formal failure logs, human disagreement.Bind the checker to the native artifact and state the unchecked region.
Reacting-actor gapOther actors do not change behavior in ways outside the model.The rule works when everyone is static but fails when people adapt, attack, collude, or misreport. Formal labels if needed: incentive rule, settled joint behavior, and strategic response.AdvGame, Accuracy Auctions, Data Market Pricing, OMAC, Constrained Nash, Fair Causal Bandits.Adaptive attacks, truthful-report tests, settled-behavior distance, payoff sensitivity, collusion checks.Model actor response and test incentives under changed payoff assumptions.
Tangled hidden handleThe internal handle isolates the intended variable.Steering, decoding, or a deliberate internal change moves unintended behavior along with the target behavior. Formal labels if needed: hidden interface and internal-number direction.Steer Like The LLM, The Tell-Tale Norm, MINT, Causal Route Gating, PRISM, Mind-Omni.Off-target audits, layer removal tests, what-if swaps, transfer tests, route changes.Measure locality: what else changes when the hidden control is moved?
Tradeoff hidingOne number faithfully represents several goals.Improvement hides loss on safety, cost, fairness, detection, or subgroup value. Formal labels if needed: single-number goal and tradeoff frontier.ParetoPO, SecFid, Catch-22, SafeDPO, VALUEFLOW, Fair OT, LiftQuant.Tradeoff curves, weight sensitivity, subgroup reversals, false-positive cost, utility loss.Report the tradeoff menu before choosing one operating point.
Finite-evidence overconfidenceThe sample supports the broader claim.Rankings, proof tokens, or discoveries reverse under resampling or new environments. Formal labels if needed: sample-limited certificate and case-mix-level claim.Micro-Benchmarking Reliability, Finite Test Certification, ATLAS, Neural Effect Search, UFEval.Resampling intervals, held-out environments, many-searches correction, confidence targets.State evidence amount and remaining doubt beside the claim.
Finite-machine mismatchThe theorem describes the number format and hardware actually used.The guarantee holds with ideal numbers or ideal memory but fails under low-bit math, layout, or latency. Formal labels if needed: quantization and finite arithmetic.Floating-Point Neural Networks, QAT Scaling, TetraJet, TileLang, IO-Aware GNN, Quantized Diffusion.Hardware traces, numerical sensitivity, memory bandwidth, step error, precision removal tests.Include machine assumptions in the claim.
Broken artifact graphParts can be checked independently without losing the dependencies between them.A proof, paper, codebase, or web artifact has passing parts but a broken whole. Formal label if needed: artifact decomposition error.PaperBench, Bitween, RefineStat, MedAgentGym, WebDevJudge, VERINA.Dependency graph failures, reproduction gaps, invalid citations, component interaction tests.Verify the artifact dependency graph, not only local pieces.
Evidence-channel credit failureThe intended evidence channel caused the answer.The answer survives when the intended evidence is swapped out, or changes because of the wrong channel. Formal labels if needed: channel credit and cause route.VISUALSWAP, MoCA, MINT, Causal Route Gating, Visual Attribution Streaming, LIMSSR.Swap tests, route removal tests, text-prior controls, missing-channel calibration.Use cause tests over evidence channels, not only attention heatmaps.
Learning-window missThe model can still learn from the data or curriculum when it arrives.Helpful data does nothing or damages general ability because it arrives in the wrong training phase. The plain issue is whether the data's training push still points in a useful direction over time.Midtraining Bridges, LR Decay, Procedural Pretraining, h1, OpenThoughts, DiReCT.Phase removal tests, useful-push checks over time, representation drift, retained general capability.Treat training as a path and evaluate when the same evidence has value.
BIG PICTURE

How This Guides The Next Pass

Future paper expansions should not only add more names. They should ask which failure mode the paper is trying to prevent and whether the evidence actually detects that failure. A safety paper without rare-case evidence, a benchmark paper without remaining doubt, a compression paper without behavior-drift checks, or a causal paper without still-possible story sets is still incomplete at the first-principles level.

The atlas now has a loop: object, proof sketch, equation, evidence, and failure. That loop is the standard for making each remaining paper explain what is being claimed and how the claim could break.
