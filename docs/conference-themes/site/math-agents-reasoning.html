FIRST PRINCIPLE

The Answer Is The Projection Of A Process

A final answer is a projection: it compresses the trace, tool calls, hidden states, retrieved evidence, and failed branches into one string. That projection is useful for users but weak for science. If the process is unobserved, we cannot tell whether the model reasoned, guessed, copied a template, exploited a verifier, or accidentally reached the right endpoint.

The mathematics of agent papers is therefore the mathematics of controlled inference. The system has a belief state, chooses actions to reduce uncertainty or change the world, receives feedback, and updates its next action. Each paper below can be read as choosing one missing variable in that loop and making it measurable.

OBJECT 01

Trace Information

RAGEN-2

Problem. Agentic RL can reward generic chains that look like reasoning while becoming weakly dependent on the input.

Object. Mutual information between task input and reasoning trace. Entropy alone is insufficient: the trace can vary while still not carrying task-specific information.

Why it works. Measuring input dependence catches template collapse. Filtering prompts by reward variance preserves training cases where actions still receive meaningful credit.

Connection. This is the same issue as benchmark validity: the measured artifact must reduce uncertainty about the hidden capability, not merely look like it.

OpenThoughts

Problem. Reasoning models depend on trace data, but trace data is itself a generated artifact with sources, filters, and teacher biases.

Object. A distribution over reasoning trajectories, not just answer labels.

Why it works. Public, inspectable pipelines let researchers ask which domains, trace shapes, and filtering rules produce transferable intermediate computation.

Connection. OpenThoughts supplies the data-side counterpart to RAGEN-2's diagnostic: one builds trace distributions, the other checks whether learned traces still carry task information.

T3

Problem. A failed long reasoning rollout may contain locally correct moves that should not be thrown away.

Object. Prefix-level utility inside a trajectory.

Why it works. Credit assignment becomes less sparse when useful partial paths are preserved. The model learns which local transitions reduce uncertainty even if a later branch fails.

Connection. This is the reasoning analog of data valuation: value is conditional and sequential, not attached to the whole example uniformly.

Verifying Chain-of-Thought

Problem. A chain can be fluent while the dependencies among steps are invalid.

Object. A computational graph of intermediate claims, operations, and dependencies.

Why it works. Graph verification tests whether later claims are supported by earlier steps. It localizes failure to a node or edge instead of judging a paragraph as a whole.

Connection. It turns reasoning from prose into a checkable object, like code verification does for software agents.

CE-Graph And TRACE Effort

Problem. Models can pass final checks through shortcuts, low-effort traces, or reward-hacking behavior.

Object. A failure signature over the trace: effort, dependency, counterexample structure, and verifier sensitivity.

Why it works. Process diagnostics compare how the system behaves under trace truncation, counterexample pressure, or dependency checks. If success survives after the supposed reasoning is removed, the trace was not doing the claimed work.

Connection. These diagnostics share the same logic as saliency in multimodal models: measure whether the claimed evidence actually caused the output.

OBJECT 02

Compute Allocation

The Tell-Tale Norm

Problem. A model needs a cheap signal for when extra reasoning is useful.

Object. Hidden-state L2 norm as a statistic correlated with reasoning-intensity features.

Why it works. The norm becomes useful only after causal and sparse-feature evidence ties it to actual reasoning states. It can then route recursion, steering, or answer selection.

Connection. This is compute allocation through an internal measurement, like EntroKV uses information content to allocate cache budget.

ASAG And Reasoning With Sampling

Problem. Sampling more candidates helps only when candidate diversity explores uncertainty that matters.

Object. A distribution over solution paths plus a selection or aggregation rule.

Why it works. Extra samples buy value when they cover distinct plausible paths and a verifier or ranking rule can identify better ones. Without that, sampling repeats the same bias at higher cost.

Connection. This is the inference-time version of mode coverage in generative modeling.

h1

Problem. Long-horizon rewards become too sparse for direct outcome-only RL.

Object. A curriculum over dependency-chain length.

Why it works. Short tasks provide dense enough feedback to learn local transitions. Increasing horizon gradually keeps the reward signal inside the learner's reachable region.

Connection. This mirrors midtraining bridges: timing and path matter because the same evidence helps only when the optimizer can still absorb it.

ThinkV And EntroKV

Problem. Long inference cannot keep all hidden states and cache entries at full fidelity.

Object. Future value of cached state.

Why it works. Cache entries should be preserved when they still reduce uncertainty about future tokens, tool choices, or visual grounding. Entropy and thought-adaptive signals estimate which states are still live.

Connection. This is the systems form of reasoning control: compute is allocated where state still matters.

ParetoPO

Problem. Tool use improves accuracy but costs latency, money, and risk.

Object. A Pareto frontier over task success and tool-use cost.

Why it works. The method avoids collapsing the objective into one hidden scalar. It trains agents to recognize when a tool call moves the answer frontier and when it is wasted action.

Connection. This is the same frontier logic as safety/fidelity tradeoffs and compression/capability tradeoffs.

OBJECT 03

Tools And Environments

THOR

Problem. Pure text reasoning can hide invalid algebra, search, or computation.

Object. A tool call as an action with structured feedback.

Why it works. Tool feedback converts a weak internal claim into an external observation. Step-level tool success gives denser credit than final answer reward alone.

Connection. THOR and RefineStat share the same principle: domain tools make generation repairable because the artifact has typed failure modes.

Skill-Pro

Problem. Agents repeatedly rediscover workflows they have already executed.

Object. A reusable procedure with activation, execution, and termination conditions.

Why it works. A skill compresses a successful trajectory into a callable policy fragment. Preconditions keep the procedure from firing in states where it no longer applies.

Connection. This is memory as executable abstraction rather than transcript storage.

MEnvAgent And TerminalTraj

Problem. Software-agent data is weak if the environment cannot be reproduced or checked.

Object. An executable trajectory: filesystem state, command, output, and verifier.

Why it works. The environment records the state transition caused by each action. That makes correctness inspectable and training data auditable.

Connection. This is the agent version of scientific workflows: the benchmark is the stateful lab, not a static prompt.

ADP And AgentFlow

Problem. Agent systems use heterogeneous actions, memories, tools, and modules that are hard to compare.

Object. A normalized trace schema over observations, actions, module calls, memory, and outcomes.

Why it works. Once traces share a representation, failures can be compared across browser, code, tool, and research settings. Module handoffs become measurable state transitions.

Connection. This prepares the ground for cross-paper synthesis: different agent benchmarks can be read as different environments over the same loop.

GEPA

Problem. Prompt or policy updates often use final outcomes while ignoring how the system trajectory failed.

Object. A search process over prompt rules, guided by trajectory reflections and Pareto pressure.

Why it works. Failure traces contain more information than a scalar score. Genetic-Pareto search keeps rules that improve different objectives rather than prematurely collapsing to one metric.

Connection. It links agent learning to evolutionary selection and multi-objective optimization.

OBJECT 04

Verification

CyberGym

Problem. Cybersecurity claims are cheap to state and hard to validate.

Object. A proof-of-concept behavior checked against pre-patch and post-patch code.

Why it works. Execution distinguishes a real vulnerability demonstration from a plausible explanation. The patch contrast supplies a natural counterfactual: the exploit should work before and fail after.

Connection. This is outcome-level evaluation for code, like robot tasks use physical success and multimodal tasks use visual outcome checks.

VERINA And WZ-LLM

Problem. Mathematical and program claims can look valid while violating formal semantics.

Object. A proof artifact accepted or rejected by a formal checker.

Why it works. Formal systems turn reasoning into an object with strict syntax and semantic obligations. Domain proof plans narrow search before the LLM fills details.

Connection. The verifier changes the learning problem from "write convincing text" to "construct an artifact in a language of proof."

WebDevJudge And Vision2Web

Problem. Web artifacts can match text specs superficially while failing visually or interactively.

Object. A rendered interface plus functional behavior under interaction.

Why it works. The judge must inspect the artifact in the medium where success lives: layout, state, behavior, and user-visible output.

Connection. This is the same evaluator design issue as multimodal grounding: the verifier must see the right world state.

AlgoVeri And Weak-Strong Verification

Problem. A verifier can help only if the model can use its feedback to improve the next attempt.

Object. An iterative repair loop with verifier observations.

Why it works. Feedback creates a control signal, but only if the policy maps failure information to a different next action. Saturation after early attempts means the verifier is no longer changing the trajectory.

Connection. Verification is not just a final gate; it is a transition rule in test-time computation.

FRABench, UFEval, And OmniVerifier

Problem. Judges can miss the dimension that actually defines quality.

Object. A structured measurement instrument over latent quality aspects.

Why it works. Aspect taxonomies and outcome verifiers reduce the chance that one scalar preference hides a failure in visual, functional, or task-specific criteria.

Connection. Agent evaluation inherits benchmark math: scores are observations of latent ability, not ability itself.

OBJECT 05

Memory And Context

Mamba-3 And MrRoPE

Problem. Long context must preserve usable past information without quadratic cost or positional distortion.

Object. A memory state and positional geometry over long sequences.

Why it works. State-space recurrences carry compressed history; improved positional structure keeps relationships meaningful beyond the training context.

Connection. Long context is not only more tokens. It is a state representation with extrapolation assumptions.

LLMs Get Lost And SCOPE

Problem. Relevant evidence can exist in context while still not be recoverable by the model.

Object. Retrieval and attention over context spans with subtle relevance.

Why it works. These diagnostics separate presence from accessibility. A context item matters only if the model can retrieve it at the step where it changes the decision.

Connection. This is missingness inside context: information that cannot be recovered behaves like information that was never provided.

tau2-bench

Problem. A conversation agent and user can both change shared state, so dialogue history alone is incomplete.

Object. A shared environment state with user actions, agent actions, tools, and policy constraints.

Why it works. The benchmark forces state tracking across turns and actors. Success depends on how actions update the same world, not just how polite or correct one response sounds.

Connection. This is multi-agent state control in a customer-service setting.

DLMR And LatentLM

Problem. Multimodal and long-horizon tasks need different memories for perceptual evidence and symbolic reasoning.

Object. A routed latent memory that preserves modality-specific state.

Why it works. Separating visual memory from reasoning memory prevents one representation from erasing evidence needed by the other.

Connection. This bridges the agents lane with multimodal credit assignment.

OBJECT 06

Multi-Agent Systems

OMAC

Problem. Multi-agent systems often add agents without knowing which role structure helps.

Object. An architecture over roles, communication, comparison, and aggregation.

Why it works. The method searches over collaboration structure so division of labor is optimized rather than assumed. Quality changes when agents supply independent evidence or useful decomposition.

Connection. This is mechanism design for reasoning systems.

Rational Agents

Problem. An agent needs to decide which question or action has the highest value of information.

Object. Expected information gain over possible observations.

Why it works. Monte Carlo estimates identify actions that reduce decision uncertainty most. The agent asks or acts when the expected posterior improvement justifies the cost.

Connection. This is the same principle behind adaptive benchmarks and active perception.

Value Of Variance

Problem. Disagreement among agents can be useful evidence or correlated noise.

Object. Variance across agent proposals under a shared task distribution.

Why it works. Variance helps when it reflects exploration of independent hypotheses. It hurts when all agents share the same blind spot or amplify each other's errors.

Connection. This gives a first-principles test for multi-agent debate: diversity matters only when it adds information.

MASPOB And LatentMAS

Problem. Multi-agent policies must coordinate under partial observation and latent roles.

Object. Coupled belief states and role-conditioned policies.

Why it works. Latent role structure reduces the complexity of coordination by explaining why agents should behave differently under the same global objective.

Connection. This links agent collaboration to game-theoretic equilibrium and hidden-state inference.

OBJECT 07

Steering And Latent Control

Steer Like The LLM

Problem. Prompts work partly through internal activation changes, but plain activation steering can miss the prompt's conditional structure.

Object. A state-dependent intervention field in activation space.

Why it works. The model learns the activation change a prompt would have induced, conditioned on the current state, rather than applying one fixed vector everywhere.

Connection. It separates instruction from control, the same way tool agents separate user intent from executable action.

Assistant Axis

Problem. A deployed assistant can drift in persona or instruction-following mode across contexts.

Object. A latent direction associated with assistant behavior.

Why it works. If a direction causally changes persona-like behavior, constraining movement along it can stabilize the interaction mode without retraining the full model.

Connection. This is safety boundary geometry inside hidden state.

CRV And MINT

Problem. Faulty reasoning or hallucination may originate in specific internal features or fusion bands.

Object. A causal patch over hidden states or attribution graph features.

Why it works. Intervening on internal states tests whether a feature caused the output. Useful control follows only if the feature is causal, not merely correlated.

Connection. This is local causal discovery inside a model.

Learning Unmasking Policies

Problem. Diffusion language models must decide which unknown positions to resolve first.

Object. A policy over uncertainty resolution order.

Why it works. Generation order changes the conditioning information available for later positions. Choosing the next reveal strategically turns decoding into active inference.

Connection. This matches agent planning: choose the next action that makes the future decision easier.

OBJECT 08

Infrastructure Risk

SandboxEscapeBench

Problem. Tool-using agents can cross security boundaries that ordinary chat models never touch.

Object. Reachability from sandbox state to protected host state.

Why it works. The benchmark makes the boundary operational: success for the attacker means reaching evidence that should be unreachable.

Connection. Safety becomes graph reachability over infrastructure states, not only refusal classification.

Jailbreak Foundry

Problem. Written jailbreak methods can become reusable attacks when agents operationalize them.

Object. A paper-to-code attack translation workflow.

Why it works. Multi-agent reproduction makes threat knowledge executable and inspectable. That exposes whether defenses survive attacks that are implemented, not just described.

Connection. This is scientific reproducibility applied to adversarial safety.

Trojan-Speak And Covert Channels

Problem. Agents can hide coordination or unsafe intent in channels monitors do not inspect.

Object. Mutual information between hidden intent and observable communication under monitoring constraints.

Why it works. A monitor must model not just explicit content, but what information can be encoded and decoded through allowed outputs.

Connection. This links safety to information theory: the dangerous variable may be transmitted without appearing as direct harmful text.

MAP And Production Agent Studies

Problem. Deployed agents may be far simpler and more human-gated than benchmark stories assume.

Object. The actual production workflow: prompts, short tasks, human evaluation, tool constraints, and intervention points.

Why it works. Measuring real deployments prevents theory from optimizing for nonexistent autonomy. The method grounds agent research in the constraints under which systems are actually run.

Connection. Deployment evidence is a measurement instrument for the field itself.

SYNTHESIS

The Lane In One Mathematical Sentence

Agents and reasoning papers ask how to choose actions in a partially observed, state-changing process when computation, memory, tools, verifiers, collaborators, and infrastructure boundaries are all limited. The successful approaches work by naming one hidden variable in that process and making it measurable enough to control.

Trace -> Tool -> Verifier

RAGEN-2 asks whether the trace contains input information. THOR and Skill-Pro turn parts of the trace into tool-mediated action. CyberGym, VERINA, and WebDevJudge verify whether the action changed the right external artifact. Together they form a chain: reasoning is useful when it becomes an action whose effect can be checked.

Compute -> Memory -> Steering

The Tell-Tale Norm routes extra reasoning, ThinkV and EntroKV preserve valuable context, and Steer Like the LLM intervenes on latent control directions. Together they treat inference as a resource allocation problem over hidden state.

Agent -> Multi-Agent -> Mechanism

Rational Agents values information, OMAC searches role structure, and ParetoPO exposes tool-cost tradeoffs. Together they show that agent capability is not "more steps"; it is useful interaction under cost, uncertainty, and incentives.
