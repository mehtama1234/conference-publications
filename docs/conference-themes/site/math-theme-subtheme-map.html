FIRST PRINCIPLE

A Theme Is A Repeated Mathematical Problem

The theme names are not labels for topic areas. They are repeated failure patterns. Reasoning is about preserving task information through a trace. Evaluation is about measuring a hidden target through a noisy channel. Data is about moving parameters with evidence at the right time. Generation is about sampling in the right native state space. Theory is about naming the budget or threshold. Causality is about what evidence identifies. Multimodal work is about assigning credit across channels.

The map below keeps each subtheme in the same shape: problem, mathematical object, approach, representative papers, and cross-theme connection.

THEME 02

Evaluation And Safety

The thing being tested is usually hidden.

A benchmark is a measuring device, not the ability itself. The ability is a latent property: can the system reason from the evidence, use the right modality, obey a boundary, execute an artifact, or avoid a rare harmful state? The score is only an observation produced by prompts, tasks, judges, verifiers, users, and sampling rules. Evaluation works mathematically when that observation still carries enough information about the hidden property to separate real capability from noise, shortcuts, memorization, judge preference, and lucky samples.

The hard part is that models are not passive objects. Once a score becomes a training target, a leaderboard target, or a selection rule, the model can move toward patterns that raise the observed score without improving the hidden property. That is why the useful papers in this lane build sharper instruments: adaptive tests that spend questions where uncertainty is high, domain rubrics that observe the correct state, executable verifiers that test the artifact itself, tail estimators that look where average sampling rarely goes, and constrained policies that measure distance to forbidden behavior.

Pressure boundariesA model can look safe at ordinary prompts because the test never approaches the boundary. Under persuasion, role-play, tool access, obfuscation, or multi-step execution, the same policy may cross into a forbidden set.A feasible set with a boundary: allowed behavior is inside, harmful or disallowed behavior is outside, and the relevant number is distance to crossing under adaptive pressure.Constrained policies penalize movement toward the boundary; jailbreak and sandbox tasks search for paths that cross it; game-style evaluations let the attack adapt so safety is tested as a boundary under response, not as a static checklist.CSPO, SecFid, SandboxEscapeBench, CyberGym, Jailbreak Foundry, AdvGame.Connects safety to optimization geometry and games: the claim is not "safe on average" but "hard to move outside the feasible region under the allowed pressure."
Tail riskAverage benchmarks mostly sample ordinary behavior. Low-probability failures can dominate real harm because cost is asymmetric: one rare unsafe trajectory can matter more than many harmless successes.A tail probability or tail loss over trajectories: not average score alone, but probability mass and cost beyond a threshold, often under distribution shift or adversarial selection.Rare-event methods change the sampling distribution so dangerous regions become visible; worst-slice objectives give credit according to the hardest or most harmful cases; flow and control losses track whether safety constraints remain true along the path, not only at the final sample.Rare Event Analysis, Tail Risks, Reward Redistribution for CVaR MDPs, Control Consistency Losses, FlowGuard.Matches generative sampling: proposal choice decides what the evaluator can see. If the sampling rule almost never visits the failure region, the benchmark cannot prove the region is small.
Executable verifiersText can describe a proof, website, exploit, spreadsheet, or experiment that does not actually work. The final sentence is cheap; the artifact state is where correctness lives.A verifier over the native artifact, trace, proof, rendered state, or execution state. The verifier is a function that maps the produced object to pass/fail, partial credit, or a structured error.Run the code, render the page, check the proof step, execute the terminal trace, inspect the workflow dependency, or compare the generated artifact against observable task constraints.CyberGym, TerminalTraj, WebDevJudge, VERINA, OmniVerifier, PaperBench, RefineStat.Connects evaluation to certificates: a claim becomes stronger when the checked object is closer to the object that must work in deployment.
Proxy and reward pressureA learned judge or reward model is also a measurement channel. If it has systematic errors, optimization will amplify the errors because the policy moves toward high measured reward, not necessarily high real value.A proxy objective gap: true value minus measured reward. The danger is directional: small biased errors can become large behavior changes when the optimizer repeatedly follows them.Use decomposed rewards, weak-strong verifier training, uncertainty-aware verifier selection, cross-modal reward checks, and counterfactual swaps to test whether the reward depends on the evidence it is supposed to measure.RLVepsR, Weak-Strong Verification, Omni-Reward, VISUALSWAP, FlowGuard, JudgeBench.Connects evaluation to data and RL: once measurement becomes an update direction, validity is no longer only statistical; it becomes a control problem.

BIG PICTURE

What The Map Adds

The subthemes show that the atlas is not a list of isolated papers. Each subtheme is a transformation problem with a preserved quantity: a trace must preserve task information, a benchmark must preserve measurement validity, a dataset must preserve useful gradient movement, a generator must preserve native-state validity, a theorem must preserve assumptions under deployment, a causal method must preserve identification boundaries, and a multimodal system must preserve evidence credit.

That is the practical first-principles reading of the conferences: before asking which method wins, ask which object the paper protects while the system changes.
